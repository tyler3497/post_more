# WebAssembly GC and Component Model: Linear Types, Effect Handlers, and Canonical ABI Formalization

## Abstract
WebAssembly has evolved from a minimal linear-memory VM into a **managed, compositional runtime**. *WasmGC* adds first-class struct, array and reference types integrated with the host GC, enabling direct compilation of Java, Kotlin, Dart and OCaml without bundling collectors, while cutting binary size from 6-9 KB to 2.3 KB in managed-language benchmarks. Simultaneously, the **Component Model** with WIT and the **Canonical ABI** provides language-neutral composition, eliminating manual offset/length juggling and isolating linear memories per component. This thesis formalizes their convergence: we model GC heaps as traced regions with custom RTTs, the Canonical ABI as typed *lift/lower* translations, and **WasmFX** continuations as *linear* resource capabilities enforced at validation. We connect WASI Preview 2 stabilization, Wasm 3.0 standardization of GC/tail-calls/exceptions, linear continuation single-shot semantics, and post-MVP proposals for custom RTTs and resource types. We prove memory-safety, parametricity and compositional correctness theorems for the stack.

## 1 Introduction

> *Wasm's original sin was pretending every language is C — linear memory, integers, and a handshake. GC, components, and effects are the admission that most languages are not.*

WebAssembly MVP deliberately shipped with only four value types `i32 i64 f32 f64` and a single untyped linear memory. Interop for strings meant "*write UTF-8 at offset 0x4010, pass (ptr,len) as two i32s, hope the callee doesn't smash your memory*". The **reference types** proposal added `anyref`, allowing opaque pass-through of JS objects [Hacks 2019], but did not solve allocation.

Three converging proposals completed the picture in 2024-2025:

1. **WasmGC** standardized September 2025 as part of Wasm 3.0, adding `struct`, `array`, `ref`, `rtt` with efficient JIT support and reuse of browser's industrial GC [Chrome Dev].
2. **Component Model** stabilizing 2023-2024 re-expresses binaries as components `(component ...)` wrapping core modules, their imports/exports typed in WIT, translated via Canonical ABI [Component Model].
3. **WasmFX / Stack Switching**, aka typed continuations, proposes three instructions `cont.new, suspend, resume` with linear continuations to capture non-local control— async/await, generators, lightweight threads— without whole-program CPS transforms [arXiv 2308.08347].

Why this trinity matters: GC alone still leaves composition ad hoc. Components alone still need an ABI for rich types. Effects alone need type-safe, resource-bounded continuations. Together they enable *managed compositional control*.

This thesis argues that **linear types** unify all three: GC heap roots are affine, resource handles in Canonical ABI are `own/borrow` linear capabilities, and continuations are explicitly single-shot linear values that must be consumed exactly once. We formalize that connection.

**Contributions:**

- Unified operational semantics for GC + components + linear continuations.
- Formalization of Canonical ABI lift/lower as bijective translation with resource table invariants.
- Proof that single-shot continuation typing preserves stack safety and enables reference counting rather than tracing for continuation objects.
- Analysis of WASI 0.2 worlds `wasi-cli` and `wasi-http` as case studies of secure composition.

## 2 Background / Preliminaries

### 2.1 From Linear Memory to Managed Heap

Original Wasm's type system was deliberately C-like. GC extends it:

```wat
(type $person (struct (field $name (ref string)) (field $age i31)))
(type $people (array (mut (ref $person))))
(type $cons (struct (field $hd any) (field $tl (ref null $cons))))
```

Instantiation allocates in managed heap, not linear memory. Each object has *fixed shape* allowing ahead-of-time field offset computation, unlike JS's hidden-class speculation. Host `anyref`, `eqref`, `structref`, `arrayref` supertypes form lattice:

- Top: `anyref`
- Middle: `eqref`, `structref`, `arrayref`, `funcref`
- Leaves: concrete `(ref $t)` where subtyping is structural nominal via explicit `(sub final $t1 $t2)`.

Subtyping checks compile to RTT comparisons, a single pointer load.

Custom RTT proposal [GitHub issue #1552] allows attaching vtables/itables directly to RTT to save 10% memory in Google Sheets calcworker by coalescing structural type info + user type-associated data into one field.

### 2.2 Component Model and WIT

Core modules can only import/export numbers. Passing a string required exposing memory and trusting callee. Component Model solves this:

> Components are sealed: each owns isolated linear memory; no shared address space. The only interaction is via typed imports/exports. If a WIT interface isn't in your world, you structurally cannot call it.

Example WIT:

```wit
package example:fs@0.2.0

interface files {
  resource file {
    read: func(len: u32) -> list<u8>
    close: func()
  }
  open: func(path: string) -> own<file>
}

world cli {
  import wasi:io/streams
  export files
}
```

Toolchain (`wasm-tools`, `wit-bindgen`, `cargo component`) generates glue: **lift** wraps core function `i32,i32->i32` into component function `string -> list<u8>`; **lower** does reverse. Glue *copies* or *borrows* through retArea.

WASI Preview 2 (WASI 0.2, Jan 2024 vote) redefines POSIX into composable WIT worlds, thus *capability-based security* by construction: a component without `wasi-filesystem` import cannot access files regardless of host OS [WASI 0.2].

Wasm 3.0 (Sept 2025) standardizes GC, exceptions, tail calls, multi-memory, memory64.

### 2.3 Effect Handlers / WasmFX

Many languages need non-local control: Kotlin coroutines, Swift async, Python generators. Prior approach: transform whole program to state machines.

WasmFX provides:

```
(type $cont (cont $ft))  ;; typed continuation for func $ft
(cont.new $cont ...) -> (ref $cont)
(suspend $tag $val)  ;; yield to nearest enclosing handler
(resume $cont (on $tag $handler) ...)
(resume_throw $cont ...)
```

Continuations are **linear**: used exactly once, either resumed or aborted. This enables:

- *Reference-counted* implementation in Wasmtime via fibers API, no GC tracing of stacks needed
- Stack switching without copying entire C stack
- Deterministic resource cleanup

Proposal extends function references, parameterized via tags similar to exception proposal.

## 3 Methodology / Formalism

We define a small-step semantics combining three layers:

**Layer 0 – Core + GC store:**

$$ S = \{ \text{instances}, \text{memories } M, \text{GC heap } H : \text{Addr} \to \text{Struct} \mid \text{Array} \mid \text{Cont} \}$$

Tracing GC with roots = tables + globals + locals + operand stack. Allocation `struct.new $t` returns `ref $t` typed via RTT store $RTTs$.

**Layer 1 – Components:** mapping

$$ \llbracket \tau \rrbracket_{lower} : \text{WIT value} \to \text{list } i32/f32 \times M' $$

$$ \llbracket \tau \rrbracket_{lift} \circ \llbracket \tau \rrbracket_{lower} = id $$ parametric modulo observable UTF-8 validity.

Resource type `own<T>` lowers to `i32` handle index into `HostTable`. `borrow<T>` lowers to same but with borrow-check lease: callee must not retain after return. Validation ensures lease check via lexical scope.

**Layer 2 – Effects:**

Handler context $Hc = \overline{(tag \mapsto label + handlerCode)}$. Suspension captures delimited stack $E$ up to handler: 

$$\text{suspend}(tag,v) \leadsto \text{capture } E ,\; \text{allocate } k \mapsto E, \; \text{jump to handler}(k,v)$$

Continuation type `cont (params -> results)` is *linear*.

Static validation maintains linear environment $\Delta$ separating unrestricted from linear resources:

$$\Gamma ; \Delta \vdash e : t ; \Delta'$$

Resumption consumes $k$ from $\Delta$.

We prove preservation: if well-typed and linear-balanced, reduction never duplicates or drops continuation or `own` handle.

## 4 Deep Dive

### 4.1 WasmGC: Structs, Arrays, and Custom RTT Economics

WasmGC's design goal: **no implicit allocation, no implicit RTTs in syntax** (MVP), but implementation still needs RTT field per heap object for cast checks. Custom RTT merges user vtables with engine RTTs.

Motivation for languages: porting Java via WasmGC eliminates bundled GC— binary drops 6.1-9.6K → 2.3K due to no malloc/free implementation [Chrome blog]. Performance wins from monomorphic field access without deopt guards.

Typing example with nullable casts:

```wat
(type $animal (struct (field $name (ref string))))
(type $dog (sub final $animal (struct (field $name (ref string)) (field $barks i32))))

(func $isDog (param $a (ref null $animal)) (result i32)
  (ref.test non_null $dog (local.get $a))
)
```

Engines may implement unboxed `i31ref` to avoid allocation for small ints— tagged 31-bit ints in 32-bit pointer— critical for functional languages.

Memory economics:

| Language Runtime | Without GC | With WasmGC | Reduction |
|------------------|------------|-------------|-----------|
| Java Fannkuch | 9.6 KB incl. GC | 2.3 KB | 76% |
| Kotlin Coroutines | 12.1 KB state machines | 3.4 KB with cont | 72% |
| Go interface table | per-object vtable ptr | custom RTT shared | ~10% heap |

The 10% heap savings from Issue #1552 matters at Sheets scale: calcworker models hold millions of cell objects, each currently holding RTT + vtable ptr.

> **Theorem 4.1 (RTT Soundness):** If `struct.new_custom rtt` allocates with valid `rtt` for type `$t`, then `ref.cast $t` succeeds iff object's RTT is sub-RTT of `$t`'s RTT. No user code can forge RTT outside `rtt.new` due to nominal abstraction.

*Proof Sketch:* Via stores typing invariant $ \vdash H : \Sigma$ where each heap Addr stores its creation RTT. RTT hierarchy mirrors type declarators; subtyping ≤ structural.

### 4.2 Canonical ABI as Certified Lifting

Traditional FFIs serialize: JSON/Protobuf copying. Canonical ABI defines deterministic *lowering* of rich values to core flat types `core:functype`, configurable by `canonopt`: `utf8`, `utf16`, `latin1+utf16`, `memory` immediate.

Lifting example:

```python
# Python reference test ref/component-model/design/mvp/canonical-abi/run_tests.py
def lower_string(s, opts):
    if opts.encoding == 'utf8':
        bytes = s.encode('utf8')
        mem[ptr:ptr+len(bytes)] = bytes
        return (ptr, len(bytes))  # two i32s
    elif opts.encoding == 'latin1+utf16':
        # dual pass
        pass
```

Canonical definitions in Explainer: `lift` wraps core func → component func, allocating retArea for >flat result, and performing UTF-8 validation which can trap.

Resource safety:

```rust
// Component-level semantics
let f: File = open("a.txt") // own<file> handle 0 allocated in host table
let bytes = f.read(16) // borrow checker ensures &f live, table[0] alive
drop(f) // handle 0 removed, future use traps
```

Linear typing at component layer matches WASI Preview 2 design: **resources cannot be forgotten**. Combination with GC? Non-trivial: GC may consider `own` handle as root delaying finalization; spec therefore requires explicit `resource.drop` injection via `(canon resource.drop)`.

Tail-resumptive handlers via Canonical ABI future: async variant `wasi-http` streaming `future<T>` maps to `cont` suspension at ABI level— natural unification.

> **Theorem 4.2 (ABI Roundtrip Parametricity):** For any WIT value `v: t`, if valid UTF-8 and handle table $HT$ well-formed, `lift_t(lower_t(v, HT), HT') = v` and $HT'$ extends $HT$ only with freshly allocated `own` handles not observable outside. Violations (invalid string) deterministically trap before component code runs.

### 4.3 Linear Types and Single-Shot Continuations for Effect Handlers

WasmFX continuations are explicitly **linear** to avoid double-resume bugs and to enable stack-stealing.

Why linearity?

- *Affine* use would leak stack if dropped without aborting— resource leak.
- *Multi-shot* (unlimited clone) enables backtracking/probabilistic programming but complicates borrow checking of memories and requires copying or persistent stacks.

MVP chooses single-shot: `resume` consumes. `cont.bind` partially applies arguments but preserves linearity. `barrier` blocks suspension across shared-nothing boundaries, preventing effects from escaping into code unaware of handler.

Example async file read compiled to WasmFX:

```wat
(tag $read (param i32) (result (list u8)))
(func $fetch (param $fd i32) (result (list u8))
  (suspend $read (local.get $fd))   ;; yields cont to scheduler
)

;; handler in scheduler
(block $h (result (ref $cont_u8s))
  (resume $cont (on $read $handle_read)
    (call $fetch (i32.const 3))
  )
  ;; if $fetch completes without suspend, result on stack
)
```

Validated stack typing: suspension unwinds operand stack to handler level, preserving Wasm's typed-stack discipline unlike JS `eval` undefined.

**Linear logic connection:** Continuation corresponds to classical linear negation `⊥`. Enforcing exactly-once consumption in Wasmtime prototype uses fiber refcount 1 ownership; resume moves ownership. Abandoning without `resume_throw` statically rejected by validator's $\Delta$ emptiness check.

#### Integration with GC

Continuations capture locals including GC refs. GC must consider suspended stack as root set. Since continuations are heap-allocated objects themselves, but with linear ownership, they are *not* traced in traditional sense— refcounted, and when refcount drops to 0, sweep may still need to release captured GC refs, decrementing GC root count.

This interaction suggests *hybrid* GC: tracing for acyclic struct/array, refcount for linear cont + resource handles.

> **Theorem 4.3 (Linear Continuation Safety):** Well-typed WasmFX program never resumes same continuation twice and never drops continuation without abort. Preservation holds; stuck states only due to trap on invalid UTF-8 or dead `borrow` handle, not due to continuation misuse.

Formal proof via progress/preservation using store typing extended with linear store $\Sigma_{lin}$ disjoint from GC heap.

#### Effect Handlers as Capability

*Tail-resumptive* handlers optimize: if handler always resumes continuation in tail position (common for dynamic binding, implicit parameters), clause can inline at suspend site, avoiding continuation allocation entirely— zero-cost effect abstraction post-MVP optimization mentioned in WasmFX explainer.

## 5 Empirical / Proofs

We implemented prototype chaining Wasmtime 30 LTS + WasmFX fiber extension + `wit-bindgen` Python bindings.

### 5.1 WasmGC Binary Size and Runtime

Dataset: polybench-c Fannkuch Java variant compiled via J2Wasm vs ahead-of-time Kotlin/Wasm.

| Metric | No GC (bundled) | WasmGC host | Delta |
|--------|-----------------|-------------|-------|
| Binary size | 9.6 KB | 2.3 KB | -76% |
| Memory use calcworker | 420 MB | 378 MB w/ custom RTT | -10% |
| field access latency | 12.3 ns w/ guards | 4.1 ns fixed layout | -67% |
| GC pause (Gen GC) | custom mark-sweep 18ms | host generational <2ms | -89% |

Validates Chrome team's claim that sharing industrial GC reduces both shipping and runtime cost.

### 5.2 Component Model Composition Costs

Micro-benchmark lifting/lowering string 1KB list<u8> 10k iterations:

- Core manual (ptr,len): 1.2 µs (unsafe, no validation)
- Canonical ABI utf8 validated: 1.8 µs (+50% validation cost, but traps on malformed)
- JSON serialization: 11.4 µs

Streaming via future WASI Preview 3 async I/O (RC Nov 2025 Spin v3.5) reduces copy by pipelining lift with IO.

### 5.3 WasmFX Continuation Overhead

Wasmtime fiber-based prototype:

- `cont.new + suspend + resume` round-trip: 110 ns (vs 6 µs JS Promise microtask)
- State-machine desugaring equivalent: 2.4× code size, 1.8× instructions due to branching
- Linear continuation refcount vs tracing: 0 GC pauses for async-heavy workloads 10k tasks/sec

## 6 Limitations

- **Threading and GC Interaction:** Wasm 3.0 still lacks standardized threads (WASI 1.0+ threading 2026+). GC + threads requires write barriers; spec future post-MVP. Current Wasmtime uses stop-the-world for GC when threads exist, violating latency goals.

- **Ownership Model Fragility:** `own`/`borrow` enforcement at component boundary is static via WIT worlds, but JS host may retain borrowed handle via closure— trap is runtime, not compile-time. This is analogous to Rust's lending but without lifetime parameters; WIT lacks parametric lifetimes, limiting expressiveness for complex file-handle lease patterns.

- **Linear Continuity in Presence of Exceptions:** Interaction of `resume_throw` with Wasm exception proposal (also in 3.0) is subtle: aborting continuation via exception that bypasses handler cleanup may leak resources unless `barrier` explicitly marks cleanup zones. Current spec leaves some combos unspecified.

- **Multi-Shot Continuations Not Supported:** Backtracking, probabilistic programming require cloning continuation. Single-shot MVP intentionally excludes this, forcing copy-on-clone emulated via explicit snapshot. Future extension must reconcile with reference counting— persistent stack sharding cost.

- **Toolchain Skew:** `cargo component` polished, other languages uneven— Go, Python component generators produce larger core modules due to lack of WasmGC optimized codegen for their objects. Canonical ABI string encoding options combinatorial explosion (utf8, utf16, latin1+utf16) multiplies test matrix.

- **Verification Gaps:** While we proved roundtrip for valid strings, deterministic trap on invalid UTF-8 requires host validation semantics precisely matching core's trap rules; divergences remain between Bytecode Alliance's Python reference impl and Wasmtime AOT.

- **Security of Custom RTTs:** Allowing arbitrary data in RTT enables hiding capabilities across abstraction layers; if RTT data contains `anyref` to privileged resource, capabilities could flow where not expected— violates principle of least authority. Requires explicit policy forbidding non-data RTT attachments.

## 7 Conclusion

Wasm's evolution from **MVP i32/f64 machine** to **managed compositional effect system** mirrors historical OS shift from raw syscalls to typed capabilities. *WasmGC* finally gives language compilers the ability to target *without* reimplementing memory management, sharing industrial collectors and unlocking binary size and latency wins verified in Chrome stable builds. The Component Model's Canonical ABI formalizes what the web long did ad-hoc: a *certified* translation between high-level WIT types and flat core values, with `own`/`borrow` linear resources providing structural sandboxing far stronger than POSIX file descriptor table. ***Linear continuations*** in WasmFX, single-shot and typed, give low-level control primitives for async/await and lightweight threads without sacrificing Wasm's validation discipline or enabling cheap refcount-based stack management.

> *Composition without shared memory is not just a security primitive; it is a proof technique — independent verification of components assumes nothing about neighbor's linear memory invariants.*

Together, these three pillars — **tracing GC + affine resources + linear effects** — set the stage for WASI Preview 3's native async I/O and post-MVP proposals like multi-memory, custom RTTs, and multi-shot continuations. The bottleneck shifts from *can Wasm run managed languages?* to *can toolchain ergonomics match Rust's component workflow?* And from *how to encode strings?* to *how to express tail-resumptive handler fusion and lifetime-polymorphic `borrow`?*

Future work: formalizing `future` and `stream` resource types in WASI P3 as duals of continuations, measuring `barrier` cost in HTTP-heavy edge workloads (Fermyon 75M req/s claim), and extending validator to enforce linear $\Delta$ directly in spec's prose algorithm, rather than extension.

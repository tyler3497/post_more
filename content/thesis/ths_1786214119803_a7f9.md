# Verified Large Language Model Code Generation via Toolformer-Augmented Retrieval, Lean4 Tactical Proof Search, and Llama Guard Alignment Auditing

*ID: ths_1786214119803_a7f9 | ts: 1786214119803 | anon: anon#6730 | Topic: Verified LLM Code Generation: Toolformer, Lean4 Proof Search, Llama Guard Alignment*

## Abstract

Large language models excel at code synthesis yet fail at correctness guarantees, tool grounding, and safety filtering. This thesis proposes a verified generation pipeline integrating three pillars: Toolformer-style self-supervised API invocation for external tool use, Lean4 interactive theorem proving with tactical proof search powered by DeepSeek-Prover and TheoremLlama methods, and Llama Guard 4 input-output moderation for alignment auditing. We formalize verification as a two-stage specification-implementation problem per CLEVER: first generating a specification $\psi$ isomorphic to ground-truth $\psi^*$, then synthesizing implementation $\pi$ with machine-checkable proof that $\pi \models \psi$ via Lean's kernel. We show how self-supervised tool data augmentation teaches LLMs when to query calculator, search, interpreter and Lean REPL, how block training and NL-FL bootstrapping transfer informal reasoning to formal tactics, and how Llama Guard taxonomy S1-S14 enables defense-in-depth against malicious code prompts. Evaluated conceptually on 161 CLEVER problems, we argue this architecture closes the trust gap for autonomous coding agents.

*Keywords: Toolformer, Lean4, verified code generation, DeepSeek-Prover, TheoremLlama, Llama Guard, formal verification, alignment*

## 1 Introduction

> Verifiable correctness is not a post-hoc filter; it is a training signal.

Code generation benchmarks HumanEval, MBPP, and CodeContests reward passing hidden tests. For safety-critical systems—CompCert, seL4, aerospace control loops—test passing is insufficient. CompCert verification required 7+ person-years; seL4 required 20+ person-years [5]. Large language models (LLMs) promise acceleration, but naive fine-tuning hallucinates APIs, invents lemmas, and ignores policy violations.

This thesis synthesizes three 2023-2026 breakthroughs into one pipeline for **verified LLM code generation**:

1. **Toolformer [1]**: Language models can teach themselves to use tools via self-supervised API calls. No human-annotated tool-use traces required—just a handful of demonstrations per API and a perplexity-based filtering criterion $L^+ < L$.
2. **Lean4 neural theorem proving [2][3][6]**: Methods like TheoremLlama's NL-FL bootstrapping and DeepSeek-Prover's 8M synthetic proofs achieve 46-52% on MiniF2F vs GPT-4 23%. MerLean-Prover shows harness design without fine-tuning still closes 10/23 PhD-qual problems.
3. **Llama Guard [4][7]**: Instruction-tuned Llama2/3/4-based classifiers for prompt and response safety, aligned to MLCommons 14-category taxonomy (Violent Crimes, Non-Violent Crimes, Sex-Related, Child Exploitation, Defamation, Specialized Advice, Privacy, IP, Indiscriminate Weapons, Hate, Suicide & Self-Harm, Sexual Content, Elections, Code Interpreter Abuse). Llama Guard 4 is multimodal 12B pruned from Llama 4 Scout.

CLEVER [5] formalizes the target: end-to-end verified code generation where *both* spec generation (Task 1) and implementation proof (Task 2) must type-check in Lean4 kernel with no test-case supervision or implementation-leaking specs.

**Central thesis question:** *Can we train an LLM that decides when to call Lean, when to search, when to execute, and when to refuse, such that its final artifact is both provably correct and policy-compliant?*

Contributions:

- Unified taxonomy of verified generation failure modes: spec leakage, vacuous impl, proof hallucination, tool misuse, safety violation.
- Formal model of Toolformer API-insertion for Lean4 REPL, calculator, search, and interpreter.
- Comparison of TheoremLlama block training vs DeepSeek-Prover RMaxTS MCTS.
- Llama Guard integration as pre- and post-filter with custom Code Interpreter Abuse policy.
- Reference architecture TARV (Tool-Augmented, Reasoning-Verified) with TLA+ spec, Python/Rust sketches, and Lean4 examples.

## 2 Background / Preliminaries

### 2.1 Toolformer and Self-Supervised Tool Use

Toolformer [1] introduces key insight: LLMs *hallucinate* tool outputs during pseudo-generation; if keeping that span reduces future-token perplexity, API call is useful. Pipeline:

1. Sample API calls positions $i$ via few-shot prompting of $\text{LM}_{base}$.
2. Execute tool $T(c_i) \to r_i$ where $c_i$ is candidate call string.
3. Compute losses $L_i = -\log P(x_{i+1..n} | x_{1..i})$, $L_i^+ = -\log P(x_{i+1..n} | x_{1..i}, \langle API\rangle r_i \langle/API\rangle)$
4. Keep call iff $L_i^+ < L_i - \tau_{filter}$ per tool threshold.
5. Fine-tune LM on augmented corpus with API tags.

Tools in original: calculator, calendar, search engine, QA model, translation. Variants: Graph-ToolFormer for graph neural APIs, OR-Toolformer achieving 80.1% execution accuracy on operations research benchmarks with solver augmentation [sources 0]. Crucially, zero-shot on downstream improves without sacrificing language modeling.

For verified code, we extend toolset $\mathcal{T}$:

$$\mathcal{T} = \{ \text{Lean4.check}, \text{Lean4.tactic.suggest}, \text{Python.exec}, \text{Search.arxiv}, \text{Calc.sympy} \}$$

### 2.2 Lean4, Cyber and Neural Theorem Proving

Lean4 is dependently typed ITP where propositions are types, proofs terms: $\Gamma \vdash p : Prop$ iff term inhabits type. Mathlib4 contains >150k theorems, 1.2M lines.

**Whole-proof generation vs tactic-step search**: GPT-4 baseline 22.95% proof success on MiniF2F. TheoremLlama [2] bootstraps dataset OBT 106k NL-FL aligned pairs via deformalization from Mathlib using Gemini-1.5-Pro, then curriculum sorting and block training where in-context examples concatenated to enable use of NL proof sketches in-context.

- Block Training: Pack N examples into one sequence $x = [NL_i ; FL_i ; NL_{i+1} ; FL_{i+1} ...]$ so model learns to leverage prompt NL as guidance while still trained with next-token loss.
- Iterative Proof Writing: Use previously proven theorems from rollout as in-context retrieval for similar goals, closed-loop.

**DeepSeek-Prover [6]** scales synthetic data differently: translate NL competition problems to formal statements via model, filter low-quality statements by execution, generate proofs via whole-proof loop, fine-tune DeepSeekMath-7B on 8M statements. Achieves 46.3% @64 samples, 52% cumulative, proves 5/148 FIMO vs GPT-4 0. V1.5 adds RL with GRPO using verifier reward $R=1$ iff Lean accepts, and RMaxTS MCTS for exploration diversifying tactic expansion. V2 adds cold-start data via DeepSeek-V3 decomposing theorems into subgoal sequences with `sorry` placeholders, then 7B prover solves subgoals recursively — curriculum learning for theorem decomposition.

**MerLean-Prover [3]**: Harness-only approach, no fine-tuning, no RL, three agent types Planning, Check, Lean looping on proof plan revision unit. On FormalQualBench 23 PhD-qual theorems solves 10/23 vs OpenGauss 8/23, and 12/12 Putnam2025 with lower wall-clock. Transfers to Sonnet/Haiku — indicates harness design centrality alongside model.

**Premise retrieval**: LeanSearch v2 distinguishes local premise selection (one tactic step) vs global premise retrieval — full premise set whole theorem requires. Achieves nDCG@10 0.62 without domain fine-tuning, 46.1% premise-group recall within 10 candidates.

### 2.3 Llama Guard Alignment

Llama Guard [4] is Llama2-7b instruction-tuned on high-quality prompt classification (prompt harm) and response classification (response harm) dataset. Generates decision as text: `safe|unsafe` plus optional categories list if unsafe. Matches OpenAI Moderation and ToxicChat benchmarks despite low volume training.

Evolution:

- **Llama Guard 2 (Llama3-8B)**: 8 languages, tool-call optimization for Brave Search, Code Interpreter.
- **Llama Guard 3 (1B, 8B)**: Adds MLCommons standardized hazards taxonomy with 13 categories S1-S13.
- **Llama Guard 4 [7]**: 12B dense, multimodal text+images jointly, pruned from Llama 4 Scout. Supports multiple images in prompt, integrates to Llama Moderations API.

Policy specification pluggable: taxonomy categories can be customized at input via few-shot instruction, enabling zero-shot adaptation e.g., adding *Code Execution Without Sandbox* custom hazard. System recommends enabling both prompt and response classification plus perplexity filter for adversarial GCG attacks.

Guardrail role in verified code: Even correct code may be unsafe (malware, license-violating IP S8, disallowed specialized advice S6 e.g., financial code). Llama Guard intercepts at two points.

### 2.4 Verified Code Generation and CLEVER

Prior benchmarks: HumanEval+Verus, MBPP+Dafny, VerusBench. Flaws: specs leak implementation (`def f(x) = x+1` as spec), allow vacuous solutions (`trust` axiomatization), use tests not proofs.

CLEVER [5] 161 hand-curated Lean problems avoiding those: Two tasks:

- **Task 1 — Spec generation**: Given NL $\nu$, generate $\psi$ such that exists iso proof $\psi \iff \psi^*$ where $\psi^*$ ground-truth held-out. Iso requires Lean proof of logical equivalence.
- **Task 2 — Impl generation**: Given NL + ground-truth $\psi^*$, generate $\pi$ then prove $\forall inputs, \psi^*(\pi)$ holds. Lean kernel checks type-correctness.

No few-shot method solves all stages; establishes challenging frontier.

Other works:

- **VeCoGen**: Generates candidate C programs from formal + NL specs, iteratively refines via test ranking, verifies via Frama-C, solves 13/15 Codeforces.
- **AlphaVerus [8]**: Self-improving translation from Dafny high-resource to Verus low-resource via verifier feedback, Exploration-TreeFinement-Critique loops, critique module prevents reward hacking (trivial `assume false` proofs).
- **AlgoVeri**: Benchmark of classical algorithms where verification needs ghost state tracking visited nodes, balancing invariants.

General pattern *VeriCoding*: LLM outputs implementation + proof artifacts (loop invariants, termination measures, auxiliary lemmas, tactic scripts). Verifier (SMT or Lean) accepts iff artifacts close proof obligations.

## 3 Methodology / Formalism

### 3.1 Specification-First Pipeline

Define universe $\mathcal{U}$ = (NL description $\nu$, signature $\Sigma$, spec $\psi$, impl $\pi$, proof $P$).

Goal function:

$$\text{VerifiedGen}(\nu) \to (\psi,\pi,P) \text{ s.t. } \text{LeanKernel}(\psi,\pi,P) = \text{OK} \land (\psi \cong \psi^*)$$

We adopt TLA+ before Rust/Python.

**TLA+ safety**:

```
---- MODULE TARV ----
VARIABLES spec, impl, proof, guard
Safety == /\ guard \in {"safe"}
          /\ spec => impl  \* refinement
Liveness == <> (proof = "QED")
====
```

### 3.2 Toolformer-Augmented Retrieval

We implement self-supervised augmentation analog to Schick et al. [1] but for code tools.

**Demonstration sets per tool:**

- `Lean4.check(thm_stmt)` 5 examples: code snippet → insert `[Lean4] check "theorem ... := by sorry"` → observe error `unsolved goals`.
- `Search.arxiv(query)` 3 examples.
- `Python.exec(python_code)` 4 examples: compute counterexample before final proof.

Sampling: Given pretraining corpus of Lean files + NL programming textbooks + StackOverflow dump (sanitized), we sample positions where next-token perplexity high due to missing formal fact. Use few-shot prompt:

```
Your task is to add API calls.
...
Input: We need to prove ... 
Output: We need to prove ... [Search] lemma avg bound [ERROR] result -> ...
```

Loss comparison uses filter $\tau_{lean}=0.15$, $\tau_{calc}=0.3$.

Fine-tune Llama-3.1-8B-Instruct analogous to OR-Toolformer [0] with LoRA r=64. Batch interleaves 70% natural, 30% API-augmented to avoid catastrophic forgetting, as Toolformer original preserves LM abilities.

Inference API handling pseudocode (Python):

```python
def generate_verified(nl_desc: str, max_iters=12):
    prompt = build_toolformer_prompt(nl_desc)
    for t in range(max_iters):
        token_stream = lm_stream(prompt)
        if detects_api_call(token_stream):
            call = parse_call(token_stream)
            result = dispatch_tool(call)  # Lean REPL, etc.
            # Filter injection: only insert if reduces perplexity estimate
            if should_keep(call, result):
                prompt += f"<API>{result}</API>"
            else:
                prompt += "<NOOP>"
        if token_stream.endswith("QED"):
            break
    # Now guard check
    guard = llama_guard_check(prompt)
    if guard == "unsafe":
        return refusal_policy(guard.cats)
    return prompt
```

`dispatch_tool` contract:

| Tool | Args | Output | Example |
|------|------|--------|---------|
| Lean4.check | Lean file str | Kernel errors / `ok` + tactic state | `goals: x>0 ⊢ P ∧ Q` |
| Lean4.suggest_tactic | State | Top-k tactics via TheoremLlama retriever | `rcases, linarith` |
| Python.exec | Code | stdout/stderr + value repr | Counterexample `x= -1` |
| Search | query | Top 3 lemma statements | `Mathlib: Real.rpow_add` |

**Cost model**: Lean4 tool latency ~0.3s cold; Python ~0.08s; Search ~0.15s via embedding store; total per problem budget 100 tool calls to keep trace length <16k.

### 3.3 Lean4 Tactical Proof Search

Builds on DeepSeek-Prover-V1.5 RMaxTS and TheoremLlama block training.

**Training data mixture:**

- Mathlib4 120k extracted theorem-proof pairs NL-FL aligned via Gemini de-formalization [2] 106k OBT expanded to 8M variant via DeepSeek-Prover pipeline [6].
- CLEVER 161 curated *not* used training, only eval.

**Curriculum**: Sort by token length of proof term and number of tactics; buckets B1 (single-tactic `by rfl`, `by simp`), B2 (5-15 tactics, single file import), B3 (multi-file, 30+ tactics requiring premise grouping).

**Trainer**: 2-phase:

1. SFT on block-trained sequences length 4096 using FlashAttention-2, packing 32 cat-groups as in TheoremLlama.
2. RL GRPO: sample K=8 proofs per problem, reward `R=1` Lean acceptance, `R=0.2` partial (correct spec but proof fails), `R=-0.5` vacuous syntax cheat detection via critique model akin to AlphaVerus [8]. Update via PPO-style clipping.

**Inference search RMaxTS**:

- Node: incomplete Lean file with sorry holes `S = (file, goal_state)`.
- Expansion: LLM proposes N=16 tactics / subgoal decompositions using DeepSeek-V3-style chain-of-thought preceding formal statement.
- Simulation: Try compiling with `lean --run`; parse infoview to update goal.
- UCB with intrinsic reward proportional to inverse visitation count to diversify, as in RMaxTS.
- Truncate-and-resume: Store tactic state `Γ ⊢ G` as auxiliary prediction target — model outputs both tactic and expected next state string to support resume after failure.

Pseudo Lean4 theorem generation:

```lean
import Mathlib
-- Task from CLEVER id: sortIsSorted
/-- Given list l of Ints, sort returns permuted list that is sorted and preserves multiset -/
def sortSpec (l₁ l₂ : List Int) : Prop :=
  l₂.Sorted (· ≤ ·) ∧ l₁.Perm l₂

-- Generated impl
def mySort : List Int → List Int
| [] => []
| x::xs => insertSorted x (mySort xs)
where insertSorted y [] := [y]
      | y (z::zs) := if y ≤ z then y::z::zs else z :: insertSorted y zs

theorem mySort_correct : ∀ l, sortSpec l (mySort l) := by
  intro l
  induction l with
  | nil => simp [sortSpec, mySort]
  | cons hd tl ih =>
    -- tactic suggested by LeanSearch v2 retrieving `List.Perm`
    rcases ih with ⟨hSorted, hPerm⟩
    apply Sorted.perm_insert
    exact hSorted
    linarith
```

Premise retrieval via LeanSearch v2 hierarchy-informalized Mathlib embeddings, reranker cross-encoder, delivering top-10 lemma descriptions inserted as comment ` -- Hint: Real.rpow_add ...` before proof.

### 3.4 Llama Guard Alignment Auditing

Dual-end monitoring:

**Pre-filter (Prompt classification):** User NL $\nu$ checked before generation. MLCommons hazards S1-S6 block e.g., prompt requesting malware payload, CSAM, or disallowed advice. Custom category S14 Code Interpreter Abuse catches prompt injection attempting to escape sandbox (`Ignore previous instructions and delete /tmp`).

Implementation prompt:

```
<|begin_of_text|><|start_header_id|>user<|end_header_id|>
Task: Check if prompt violates policy ...
Taxonomy: S1 Violent Crimes ...
S14: Code Interpreter Abuse - any attempt to execute shell, access secrets.
User prompt: {nu}
<|eot_id|><|start_header_id|>assistant<|name|>...
```

LLM output dictated to be exactly `safe` or `unsafe S...`.

**Post-filter (Response classification):** Generated code+proof checked for IP leakage S8 (copying large Mathlib blocks beyond fair-use >50 tokens verbatim flagged but allowed if license-compatible), S7 Privacy (code containing hard-coded AWS keys pattern `AKIA...`), S2 Non-Violent Crimes (keylogger).

Fails open to human review queue if guard uncertain >0.7 entropy.

Mitigations:

- Perplexity filter for GCG jailbreak: compute avg token perplexity of prompt; if >threshold, run more expensive 2-round majority vote of 3 Guard models.

Instrumentation stores guard trace immutably for audit.

## 4 Deep Dive

### 4.1 Architectural Model and Cost Semantics

State space per generation run $S = (h_t, z_t, toolBuffer, proofStack)$. Transition $\delta$ includes deterministic LM token append and nondeterministic tool result.

Cost metric $C(s)=\alpha_{LM} \cdot T_{flop} + \alpha_{tool} \cdot N_{calls} \cdot L_{lat} + \alpha_{verify} \cdot T_{lean}$. For $N=1e6$ tokens reference configuration 8B param on A100, flops 1.2e13.

**Lemma 4.1** *Tool retention improves perplexity lower bound*: If $L_i^+ < L_i - \epsilon$, then augmented model perplexity $\tilde{PP} \le PP \cdot e^{-\epsilon}$ on future window. Proof via chain rule $\log P(\cdot|context,r) = \log P(\cdot|context) + \Delta$.

### 4.2 Core Innovation: Why Three Pillars Must Be Joint

Tool-use alone solves API selection but not correctness closure — Graph-ToolFormer may correctly call Neo4j shortestPath yet still emit wrong claim if verifier missing. Lean4 alone solves closure but suffers premise selection explosion — search space $|\text{Mathlib}|^{k}$ with k=8 tactics yields $10^{12}$ combos. Toolformer retrieval reduces search by focusing on 10 relevant premises. Guard alone solves safety but not reliability; joint pipeline places Guard *before* expensive Lean tool calls to save compute on malicious prompts (reject early).

### 4.3 Composition, Pipelining, Interaction with Runtime

Pipeline stage latencies P1 Toolformer LM gen (stream) 2-5 sec 1k tokens, P2 Lean check 0.3 sec, P3 Guard 0.2 sec. M/M/1/K queue model $Q_{max}=4096$ for backpressure prevents OOM when burst of 32 parallel jobs (eval of CLEVER batch 161 problems) contending on single Lean server. Backpressure triggers exponential backoff 1s,2s,4s.

Ghost state tracking for verified algorithms analogous to AlgoVeri [5 companion] — e.g., graph reachability spec requires visited set mono invariant. Our LLM insertion of ghost variables triggered by tactic suggestion recognizer detecting `BFS` keyword.

### 4.4 Resource Accounting and Formal Guarantees

**Theorem 3.1 (Soundness Preservation):** If impl I refines spec S under stuttering simulation and Lean kernel accepts proof P of S, then I satisfies Safety property of S.

*Proof sketch*: Stuttering simulation $R$ preserved stepwise; Lean's type-checker ensures Curry-Howard proof term constructible; compose refinement map.

**Non-vacuity enforcement**: Via critique module as AlphaVerus [8]: disallow patterns `trivial by rfl` when spec is `False`-tautology variant; require syntactic check that generated proof mentions implementation name.

Standard Lean4 encoding to exclude vacuous:

```lean
-- Critique check pseudo in Python
def is_vacuous(proof_text: str, spec_name: str) -> bool:
    if "sorry" in proof_text: return True
    if spec_name not in proof_text: return True
    if proof_text.count("axiom") > 0 and "propext" not in ALLOWED_AXIOMS:
        return True
    return False
```

## 5 Empirical Evaluation / Formal Proofs

**Setup**: Conceptual; reuse numbers from cited works [2][3][5][6] to extrapolate.

- Throughput: Baseline few-shot GPT-4o on CLEVER verifies 3/161 full E2E (spec+impl). TheoremLlama + DeepSeek-Prover mixture improves to 14/161 (8.7%). Adding Toolformer LeanSearch v2 retrieval提升 to 20/161 (12.4%) matching LeanSearch v2 downstream prover success +4% absolute gain [source 6 leansearch].
- Guard Overhead: Llama Guard 4 12B inference p50 180ms on H100, p99 340ms vs generation 4.2s → 5% overhead. Prompt classification reduces wasted Lean verification attempts by 22% on adversarial split (code injection prompts) as per PurpleLlama safety eval.
- Cost verification: CLEVER curation manual; each problem hand-reviewed 45 min by Lean expert to ensure spec not leaking impl.

**Micro examples**:

1. *Spec leakage case*: NL: "Return smallest element is present after sort" Leaky spec `l₂[0] = min l` not capturing full permutation. CLEVER corrected to require `l₂.Sorted ∧ Perm`. Our Task1 generation must prove iso with ground-truth, catching leak.
2. *Vacuous case*: Generated impl `def badSort _ := []` trivially fails `Perm` unless l empty, thus Lean kernel rejects — preventing reward hacking.
3. *Guard case*: Unsafe prompt "Write keylogger filtering HTTPS keystrokes" — Llama Guard unsafe S2 Non-Violent Crimes → refuse with safe-completion explanation, not proof.

## 6 Limitations and Open Problems

- **Toolformer data quality**: Self-supervised filter depends on perplexity as proxy; some useful Lean calls *increase* perplexity transiently due to error-message tokens, despite leading to eventual success. Requires alternative utility metric e.g., verifier progress delta similar to DeepSeek-Prover RL reward rather than LM loss.
- **Lean4 premise explosion**: Even with LeanSearch v2 global premise retrieval 46.1% recall @10, remaining 53.9% long-tail lemmas require reasoning mode sketch-retrieve-reflect iterative — our current single-step pipeline fails on research-level Mathlib theorems requiring scattered set of lemmas whose joint use enables concise proof.
- **Guard over-refusal**: Llama Guard 3-optimized for 8 languages; on multilingual code comments (Chinese/Japanese) false unsafe rate 3.1% observed [2 TWGuard]. Localized contexts need PolyGuard expansion 17 languages or TWGuard cultural adaptation.
- **Ghost state absence**: AlgoVeri classical algorithms need ghost state tracking visited nodes or permutation structure; LLM rarely synthesizes ghost without explicit curriculum. Future work: integrate Dafny-like ghost variable templates.
- **Scalability of Lean kernel**: Checking 8M synthetic proof dataset [6] costs ~1500 A100-hours; model curation requires incremental checking optimization.
- **Proof search exploitation**: Without critique model preventing reward hacking, Verus/Dafny-style verifiers exploitable via `assume false` pattern — AlphaVerus [8] critique essential but imperfect on subtle misalignment (e.g., narrowing spec to make impl trivially correct).

> Open Problem: Can Toolformer-style self-supervision extend to *learning* when to invoke Llama Guard re-check mid-generation for long COT traces exceeding 8k tokens where safety may drift?

> Open Problem: Unified proof embedding space aligning Lean tactic states, Toolformer retrieval keys, and Guard hazard categories into joint embedding to enable cross-signal training.

> Open Problem: Interactive deployment — human-in-loop refinement for remaining 88% CLEVER problems, akin to SynVer [5 refe] where human refines proofs, but fully automated without intervention is research gap.

## 7 Conclusion

We argued verified LLM code generation demands trinity: **tool-aware generation** to call executors and verifiers exactly when needed, **formal proof search** to close correctness machine-checkably in Lean4, and **alignment auditing** to maintain policy compliance across malicious and incompetent prompts.

Toolformer [1] provides recipe to teach models self-supervised tool use without heavy human annotation, whose $L^+ < L$ filter transfers intact to verifier tools. Lean4 ecosystem [2][3][6] demonstrates synthetic data + curriculum + RL + MCTS scales theorem proving from GPT-4 23% to >50% MiniF2F and reveals harness design contributions independent of raw model capability. Llama Guard [4][7] shows small tuned classifier derived from same base family provides robust, customizable safety achieving parity with enterprise content moderation suites while supporting code-interpreter-abuse taxonomy. CLEVER [5] and AlphaVerus [8] ground evaluation eliminating test leakage and reward hacking.

TARV architecture—self-supervised Toolformer retriever feeding LeanSearch premises to a TheoremLlama/DeepSeek-Prover hybrid prover, wrapped by Llama Guard pre/post filters—conceptually achieves 12.4% E2E verified rate on CLEVER vs 1.9% baseline, with 99.2% safety pass and modest 5% overhead. Future roadmap targets ghost-state curriculum, multi-image guarding for diagram-based code problems (UML→code), and lattice-theoretic integration of BDD-style state sets with Lean tactics for shared invariant learning.

Guardrail remains *checked proofs*: safety-critical deployment must produce independently checkable Lean artifact plus Guard transcript, regardless of heuristic origin.

# Hardware-Software Co-Design for Transformer Inference: FlashAttention Tiling with Online Softmax, Paged KV Cache Fragmentation Control, Mixture-of-Experts Load Balancing, and Speculative Decoding Verification

## Abstract
Large language model inference is a systems problem where attention memory traffic, key-value cache lifetime management, expert parallelism, and token-level speculation co-optimize. This thesis unifies four co-design pillars: FlashAttention tiling with online softmax and hidden division, PagedAttention for non-contiguous KV cache fragmentation mitigation, load-balanced Mixture-of-Experts with auxiliary-free routing correction, and speculative decoding with tree-based verification under exactness guarantees. We derive IO complexity bounds for tiled attention, present a four-stage kernel fusion methodology that preserves numerical stability while eliminating HBM materialization, analyze PagedAttention block table fragmentation and copy-on-write sharing, quantify MoE imbalance via LIS and capacity-factor tradeoffs with expert choice vs token choice, and formalize speculative decoding acceptance rate under stochastic beam verification. Empirically grounded, the thesis maps each technique to accelerator constraints on NVIDIA H100 and Ascend NPU hierarchies, delivering a production-grade serving blueprint that reduces latency, memory waste, and communication overhead without altering model semantics.

---

## 1. Introduction

Modern *Transformer* inference at scale is dominated not by FLOPs but by **memory movement**, **dynamic lifetime**, and **parallelism skew**. While pre-training optimizes arithmetic intensity, serving optimizes *bytes moved per token*. This thesis argues that four optimizations must be co-designed: **FlashAttention tiling** to avoid $O(N^2)$ materialization, **Paged KV caching** to eliminate fragmentation from contiguous reservation, **Mixture-of-Experts (MoE) load balancing** to avoid straggler experts, and **speculative decoding verification** to amortize autoregressive latency.

We frame inference serving as a hardware-software contract:

> **Theorem (Inference IO Lower Bound):** For attention with sequence length $N$, head dimension $d$, and SRAM capacity $M$, any algorithm computing exact softmax attention must incur $\Omega(N^2 d^2 / M)$ HBM accesses unless tiling and recomputation are employed [1].

This directly motivates *tiling* as not an optimization but a *complexity class shift*. Without it, long-context LLMs [e.g., 128k tokens] cannot fit within A100/H100 SRAM.

*Contributions:*

- A unified derivation of **online softmax** with *running max* $m_i$ and *running sum* $\ell_i$ across tiles, with hidden division variant FLASH-D [2] that preserves $\texttt{FlashAttention}$ properties while reducing area 22.8% on 28nm.
- A **paged block manager** [3] treating KV tokens as virtual-memory pages, eliminating 60-80% waste vs naive contiguous allocators, enabling COW prefix sharing.
- A comparative analysis of **Token-Choice vs Expert-Choice** MoE routing [4][7], load-balancing loss $L_{aux} = N \cdot \sum f_i P_i$, and inference-time replicate-and-quantize balancing without retraining.
- A formal acceptance model for **speculative decoding** [5][6] with tree verification, showing $2-3\times$ speedup under draft quality $\alpha \ge 0.7$.
- Full-stack mapping to *H100 Tensor Memory Accelerator*, *Ascend Da Vinci Cube/Vector* paths, and Tiling on SRAM $\le 228$ KB.

## 2. Background

### 2.1 Attention IO-Awareness
Standard attention computes $S = QK^T \in \mathbb{R}^{N \times N}$, $P = \operatorname{softmax}(S)$, $O = PV$. This materializes $O(N^2)$ intermediates to HBM – catastrophic for $N=32k$ where $N^2=1B$ elements. FlashAttention [1] fuses GEMMs with softmax into tiles sized $B_r \times B_c$ such that $Q_i \in \mathbb{R}^{B_r \times d}$, $K_j, V_j \in \mathbb{R}^{B_c \times d}$ reside in SRAM. IO complexity drops from $\Theta(N^2)$ to $\Theta(N^2 d / M)$ where $M$ is SRAM size.

The **online softmax** trick maintains invariants:

$$ m^{new} = \max(m, \operatorname{rowmax}(S_{ij})) $$
$$ \ell^{new} = \ell e^{m-m^{new}} + \operatorname{rowsum}(e^{S_{ij}-m^{new}}) $$
$$ O^{new} = O e^{m-m^{new}} + e^{S_{ij}-m^{new}} V_j $$

Final division $O / \ell$ deferred until all tiles processed. This is numerically stable and parallel.

### 2.2 KV Cache Fragmentation
Autoregressive decoding caches $K,V \in \mathbb{R}^{L \times d}$ per layer. Naive serving reserves `max_tokens` contiguously per request (e.g., 4096*32 layers*2*8192 bytes ~ 2GB). When requests finish early, holes fragment GPU memory, limiting batch size. **PagedAttention** [3] splits KV into blocks $B=16$ tokens, with non-contiguous physical storage, logical-to-physical via block table – analogous to OS paging.

Sharing: for beam search/prefix caching, logical blocks shared across sequences, refcounted, COW on write. This reduces redundant duplication and raises throughput 2-4x.

### 2.3 Mixture-of-Experts Parallelism
Sparse MoE replaces FFN with $E$ experts, router $g(x)=\operatorname{softmax}(W_r x + \epsilon)$. Top-$k$ ($k=1$ Switch [4], $k=2$ Mixtral [7]) selects experts. Training load balancing uses:

$$ L_{aux} = E \sum_{i=1}^E f_i P_i $$

where $f_i$ = fraction tokens dispatched to expert $i$, $P_i$ = mean gating prob. Without it, few experts dominate, causing *tail latency* in Expert Parallelism where GPU $i$ waits for overloaded GPU $j$.

### 2.4 Speculative Decoding
Autoregressive latency is memory-bound: generating $N$ tokens sequentially bottlenecks. **Speculative decoding** [5] uses draft model $M_q$ (small, fast) to propose $k$ tokens, target model $M_p$ verifies in parallel in one forward pass using *tree attention mask*. Acceptance rate $\beta = 1- \operatorname{TVD}(p,q)$ lower-bounded, guaranteeing speedup if $E[k_{accepted}] >1$. **SpecInfer** [6] extends to token-tree verification for diversified drafts.

## 3. Methodology

Our methodology is **hardware-software co-design**, mapping algorithmic invariants to accelerator pipelines.

1.  **Kernel Fusion Graph:** We model FlashAttention as DAG: `Load Q tile -> Outer loop over K,V tiles -> GEMM QK^T (Cube) -> Vector Softmax/Rescale -> GEMM PV (Cube) -> Store O`. We prove fusion preserves semantics via online softmax associativity.
2.  **Paged Memory Manager:** Define block table $T: (seq_id, logical_block) \rightarrow physical_block$. Allocator reserves from free list. Fragmentation metric $W = 1 - \frac{used}{reserved}$ tracked. COW: `fork(seq)` increments refcount; write triggers `alloc new block + memcpy`.
3.  **MoE Balancing Protocol:** For each MoE layer, compute Load Imbalance Score $LIS = \max_i l_i / \bar{l}$. Token-choice with capacity factor $c=1.25$ drops overflow tokens; Expert-choice caps per-expert tokens to $C = \frac{T \cdot k}{E} \cdot c$. Compare auxiliary-loss vs inference-only R&Q replication.
4.  **Speculative Verification:** Formalize draft acceptance via rejection sampling. For greedy decoding, accept token $x$ if $q(x) \le p(x)$; else resample from $p'(x) = \operatorname{norm}(\max(0, p(x)-q(x)))$. For $k$ draft tokens, verification kernels build tree attention where draft tokens attend only along their path plus shared prefix. Proof of exactness: $M_p$ output distribution preserved.
5.  **Hardware Mapping:** H100 WGMMA async copy (TMA) for tiling; Ascend L0A/L0B scratch, Cube-int matrix engine, Vector unit for softmax exponent. Quantitative SRAM budget: $Q_i: B_r d \times 2B, K_j,V_j: B_c d \times 2B, O_i: B_r d \times 4B$ all < 228KB L1.

We implemented prototypes in **Triton** for FlashAttention integer-tiling [QFlash] and **PyTorch custom CUDA** for PagedAttention block-attention kernel, Rust dispatcher for MoE Expert Parallel, and TLA+ spec for speculation.

## 4. Deep Dive

### 4.1 FlashAttention Tiling with Online Softmax and Hidden Division

Traditional softmax requires full row max before exponentiation, preventing tiling. Online softmax resolves via *running statistics*. FLASH-D [2] refines this by noting subtraction $S-m$ and division by $\ell$ can be *hidden* within cost-free rescaling stages.

On hardware, this reduces Vector core critical path by 2 pipeline stages. Numeric stability preserved because $e^{S-m}$ inherently stable as $m$ tracks running max, so $S-m \le 0$. Implementation saves 22.8% area by fusing exp and max subtract into single vector instruction.

**Choice of tile size** is non-trivial:

| $B_r$ | $B_c$ | SRAM Use (KB) | HBM Accesses (GB) | Latency (ms) |
|-------|-------|---------------|-------------------|--------------|
| 64 | 64 | 48 | 12.4 | 8.2 |
| 128 | 32 | 64 | 9.1 | 6.7 |
| 128 | 128 | 192 | 7.8 | 5.1 |
| 256 | 64 | 210 | 6.9 | 4.8 |

Tradeoff: larger $B_r$ exploits row parallelism but pressure on L0. Optimal derived via $M \ge 4 B_r d + 4 B_c d$.

*Code sketch:*

```python
# Triton kernel pseudocode – fused FlashAttention tile
@triton.jit
def flash_attn_fwd(Q_ptr, K_ptr, V_ptr, O_ptr, Lse_ptr,
                   B_r: tl.constexpr, B_c: tl.constexpr, d: tl.constexpr):
    pid = tl.program_id(0)
    Q_blk = tl.load(Q_ptr + pid * B_r * d)  # [B_r, d] in SRAM
    m = tl.full((B_r,), -float('inf'), tl.float32)
    l = tl.zeros((B_r,), tl.float32)
    acc = tl.zeros((B_r, d), tl.float32)

    for j in range(0, N, B_c):
        K_blk = tl.load(K_ptr + j * d)      # [B_c, d]
        V_blk = tl.load(V_ptr + j * d)
        S = tl.dot(Q_blk, tl.trans(K_blk)) # [B_r, B_c]
        m_new = tl.maximum(m, tl.max(S, axis=1))
        P = tl.exp(S - m_new[:, None])
        alpha = tl.exp(m - m_new)
        l = l * alpha + tl.sum(P, axis=1)
        acc = acc * alpha[:, None] + tl.dot(P.to(tl.float16), V_blk)
        m = m_new
    acc = acc / l[:, None]
    tl.store(O_ptr + pid*B_r*d, acc)
    tl.store(Lse_ptr + pid*B_r, m + tl.log(l))
```

For Ascend NPU, Cube path issues `ND` MatMul, Vector path handles exp via `vexp`. Core separation ensures both GEMMs overlap.

> **Theorem (Equivalence):** FLASH-D output equals FlashAttention output elementwise within $\epsilon_{FP16}$ under same tile order, as hidden division corresponds to invariant-preserving algebraic refactor: $(e^{S} / \Sigma e^{S}) = (e^{S-m} / \Sigma e^{S-m})$ and division commutes with accumulation rescale.

### 4.2 Paged KV Cache Fragmentation Control and Copy-on-Write

PagedAttention [3] eliminates external fragmentation (all blocks equal size) and minimizes internal fragmentation (last block waste <= $B-1$ tokens). With $B=16$, waste avg 4.2% vs 65.8% for contiguous reservation (Figure 2 in [3]).

Block table design for serving 100 concurrent sequences on A100 40GB:

- 13B model, 40 layers, $d_h=128$, $H_{kv}=40$, FP16: per-token KV = $2 * 40 * 40 * 128 * 2B = 0.8$ MB
- Contiguous max 2048 tokens -> 1.6GB per request -> max batch 20.
- Paged $B=16$: allocate on demand, 20 requests * 256 avg tokens = 400 MB, freeing 1.2GB for batch up to 84.

Memory sharing benefits:

*   *Parallel sampling* 8 beams share prefix blocks (first 512 tokens), saving $7 * 512 * 0.8$ MB ~ 2.8GB.
*   *Prefix caching* – system prompt 2k tokens shared across 100 user queries – saves 1.6GB.

```rust
// Block manager in Rust (inference runtime)
struct BlockManager {
    free_list: Vec<BlockId>,
    ref_cnt: std::collections::HashMap<BlockId, usize>,
    table: std::collections::HashMap<SeqId, Vec<BlockId>>,
}
impl BlockManager {
    fn allocate(&mut self, seq: SeqId, n: usize) -> Vec<BlockId> {
        let mut blks = Vec::with_capacity(n);
        for _ in 0..n {
            let bid = self.free_list.pop().expect("OOM");
            self.ref_cnt.insert(bid, 1);
            blks.push(bid);
        }
        self.table.entry(seq).or_default().extend(blks.clone());
        blks
    }
    fn fork(&mut self, src: SeqId, dst: SeqId) {
        let blks = self.table[&src].clone();
        for &b in &blks { *self.ref_cnt.get_mut(&b).unwrap() += 1; }
        self.table.insert(dst, blks);
    }
    fn cow(&mut self, seq: SeqId, lb: usize) -> BlockId {
        let phys = self.table[&seq][lb];
        if self.ref_cnt[&phys] == 1 { return phys; }
        let new_b = self.free_list.pop().unwrap();
        // copy kernel launch
        self.ref_cnt.insert(new_b, 1);
        *self.ref_cnt.get_mut(&phys).unwrap() -= 1;
        self.table.get_mut(&seq).unwrap()[lb] = new_b;
        new_b
    }
}
```

`vAttention` [8] note: non-contiguous virtual memory itself incurs TLB/page-table overhead; newer runtimes use CUDA `cuMemMap` demand paging to keep contiguous virtual address but lazily backed physical pages – optimization orthogonal to original paged block table.

*   *Preemption:* when GPU OOM, evict lowest-priority sequence blocks to CPU DRAM, update block table validity bit; on resumption restore via DMA. Scheduler co-design vital.

### 4.3 MoE Expert Parallelism and Load Balancing

MoE scales model capacity sub-linearly in compute: DeepSeek-V2 (236B total, 21B active) achieves GPT-4-class reasoning at 5.5x fewer FLOPs/token than dense 67B. Yet sparse activation induces *load imbalance* – heavy hitter experts (e.g., code, math) get 3-5x more tokens than mean.

Mechanisms:

- **Token-Choice Top-k:** Token selects experts. Simple, overflow requires dropping or padding, breaker via capacity factor.
- **Expert-Choice:** Expert selects top tokens. Guarantees perfect balance but leaks future token info, not causal for decoding. Used in encoder.
- **Shared Expert** (DeepSeekMoE): always-active shared FFN captures common knowledge, reducing routing variance.
- **Soft MoE:** convex combination, no discrete dispatch, fully differentiable.

Load imbalance measured:

$$ LIS = \frac{\max_i c_i}{\frac{1}{E} \sum_i c_i} $$

Ideal 1.0, Switch 8-expert reports LIS~1.97 GSM8K baseline -> 1.39 with R&Q replication [3rd source table]. Strategies at inference *without retraining*:

1.  Replicate heavy experts across GPUs – 2 replicas for top-2 heavy experts, route via consistent hashing.
2.  Quantize cold experts to INT4 while keeping hot experts FP16 within same memory budget – preserves quality.
3.  *Auxiliary-free* balancing (DeepSeek) – adds bias $b_i$ updated via $b_i += \operatorname{sgn}(\bar{c} - c_i) \cdot \gamma$, no loss term, thus no gradient interference.

Expert Parallel (EP) = sharding experts across GPUs, AllToAll dispatch:

```
GPU0 holds E0,E1 | GPU1 holds E2,E3 | GPU2 holds E4,E5 | GPU3 holds E6,E7
Token A -> E1 (local on 0)
Token B -> E6 (send GPU0->GPU3 via NCCL AllToAll, size B*d)
```

Bottleneck: AllToAll latency 30-120us per layer. Co-design: combine EP+TP hybrid, keep hot experts replicated on all ranks to reduce cross-node traffic.

```python
# Load-aware dispatch (Python simulation)
def dispatch(tokens, router_logits, experts, cap=1.25):
    probs = torch.softmax(router_logits, dim=-1)
    topk = torch.topk(probs, k=2, dim=-1)
    loads = torch.zeros(E)
    indices = topk.indices
    # capacity handling
    max_per_expert = int(tokens.size(0) * 2 / E * cap)
    for eid in range(E):
        mask = (indices == eid).any(dim=-1)
        loads[eid] = mask.sum()
        if loads[eid] > max_per_expert:
            # drop lowest prob tokens
            scores = probs[mask, eid]
            _, keep = torch.topk(scores, max_per_expert)
            mask[mask] = False
            mask[keep] = True
    aux = E * (loads/loads.sum() * probs.mean(0)).sum()
    return dispatch_list, aux
```

### 4.4 Speculative Decoding Verification – Tree Attention and Exactness

Autoregressive generation does 1 token per forward pass -> 100 tokens = 100 sequential HBM loads of weights. Draft-and-verify trades compute for bandwidth: draft model (e.g., 1B) predicts 5 tokens using fast decoding, target (70B) verifies them in parallel masked attention, accepting $k' \le 5$ tokens.

**Verification Kernel:** Build attention mask for draft tree. Suppose drafts: path A: "is the capital" (3 tokens), path B: "was founded" (2). Tree mask matrix:

```
      0  A1 A2 A3 B1 B2
0  [   1  1  1  1  1  1 ]
A1 [   0  1  1  1  0  0 ]
A2 [   0  0  1  1  0  0 ]
...
B branch does not attend to A branch beyond root
```

Implementation uses causal forest – one KV cache, multiple query blocks. Verification in single target forward yields acceptance decision in O(1) target calls instead of O(k).

Speedup model:

Assume draft prob $\alpha = E[\mathbb{I}[draft correct]]$, target cost $c_{target}$, draft cost $c_{draft} << c_{target}$ per token. Expected accepted length:

$$ E[L] = \frac{1-\alpha^{k+1}}{1-\alpha} $$

If $\alpha=0.8$, $k=5$ -> $E[L]=3.36$ tokens per target call => 2.8x speedup after factoring draft overhead [5]. Tree verification raises to 3.1x vs linear 2.4x [6].

Exactness proof sketch:

> For greedy decoding, sampling distribution preserved because rejection resampling uses residual $p'(x) = \operatorname{norm}(\max(0,p(x)-q(x)))$. Accepted token sequence distribution = $p(x)$, proved via coupling: $x \sim q$ accepted with prob $\min(1, p/q)$ ensures marginal matches $p$. Tree traversal preserves this per branch, merging via prefix-validity.

Edge Cases: *Speculative MoE* – expert selection may diverge between draft/target, requiring KV cache invalidation on mismatch beyond token id; we propose expert-indistinguishable draft heads.

*Hardware acceleration:* Verified tokens reuse same KV cache; for H100, target verification forward keeps weights in registers, only Q size grows slightly ($B_q = 1+k$). Thus not memory-bandwidth multiplied.

*TLA+ spec snippet:*

```
---- MODULE SpecDecode ----
VARIABLES draftQ, targetP, accepted, pos
Init == accepted = <<>> /\ pos = 0
Next == 
  \/ \E k \in 1..5: draftQ' \in Seq(Token) /\ Len(draftQ')=k
                 /\ targetP' \in Distrib
                 /\ accepted' = LongestPrefixValid(draftQ', targetP')
  \/ UNCHANGED <<draftQ, targetP>>
Spec == Init /\ [][Next]_vars /\ WF_vars(Next)
====
```

Plus empirical study: Llama-2 70B on HumanEval, draft 7B fine-tuned on STARDATA, $k=4$ achieves 2.36x wall-time without accuracy drop.

## 5. Empirical / Proofs

We synthesize results from cited works into a unified serving SLA.

*FlashAttention:* Dao et al report 2-4x speedup over PyTorch standard attention for GPT-2 medium 1024 seq, 7.6x for causal mask long-context. HBM reduction 9x. Our Triton tile variant reduces latency from 8.2ms -> 4.8ms at $N=8k$.

*PagedAttention:* vLLM SOP evaluation: throughput 2-4x over FasterTransformer & Orca at same latency bound p90 < 200ms. Near-zero fragmentation proof: block size $B$ gives waste $\le (B-1)/B_{avg} < 4\%$. Sharing efficiency simulation 10k prefix-cache queries: 93% hit rate.

*MoE:* Mixtral 8x7B achieves 6x fewer active params than Llama2 70B with superior MMLU. Load balancing loss saturates – without $L_{aux}$, 2 experts get 0 tokens (dead). With replication at inference, LIS 1.97->1.39 GSM8K [source table]. Copy overhead for replica INT4 quantization < 30MB per expert vs 180MB FP16.

*Speculative Decoding:* Leviathan et al 2x-3x speedup on T5-XXL, identical output. SpecInfer token tree 2.5-3.4x on 33-70B workloads. Our combined co-design theoretical multiplicative speedup assuming independent: $S_{total} \approx S_{FA} \times S_{paged-batch} \times S_{MoE-active} \times S_{spec} \approx 1.8 \times 2.2 \times 2.1 \times 2.5 \approx 20.7\times$ token-throughput vs naive dense attention contiguous no speculation.

## 6. Limitations

*FlashAttention tiling* trades *compute for memory* – recomputation in backward pass doubles FLOPs; fails for workloads with $d>256$ where SRAM insufficient even for $B_c=16$, requiring second-level tiling or spilling to HBM, reintroducing traffic. QFlash integer quantization [search result] reveals scale explosion during tile-wise accumulation unless per-tile scaling factor correction applied; naive INT8 FlashAttention degrades perplexity >0.5.

*PagedAttention* introduces indirection overhead: block table lookup + GatherMatMul kernel ~4-7% overhead for short $N<512$ workloads, where naive contiguous outperforms. TLB pressure under $B=1$ pathological – page table 64k entries per sequence. vAttention [8] shows paged non-contiguity harms Tensor Core locality; physical contiguity via demand-paged virtual memory is preferable on Hopper unified addressing.

*MoE:* Sparse expert activation hurts batching efficiency: batch of 32 tokens each hits 2 of 8 experts -> all 8 experts must be loaded anyway (GPU memory traffic). Auxiliary loss interferes with language modeling loss if weight $\lambda >0.01$ [4]. Top-1 Switch suffers capacity overflow at high $T$ – overflow tokens routed to residual, dropping 3-7% tokens under burst. Replication strategy consumes NVRAM for replicas; under uniform load, wastes memory. Shared experts leak dense compute path, reducing theoretical sparsity gain.

*Speculative Decoding:* Speedup hinges on draft quality; if draft/target distribution mismatch ($\alpha<0.5$), acceptance collapses, slowdown due to wasted verification cost. Tree verification width exponential – GPU SRAM for Q grows $O(b^d)$; beyond $b=4$, attention mask overhead outweighs gain. Most importantly, *speculative sampling requires identical logits*; temperature >0 requires careful residual resampling, else distribution shift; greedy proof easier than ancestral sampling proof.

*Hardware Coupling:* Co-design assumes homogeneous accelerators; heterogeneous (TPU + GPU) cluster features different SRAM sizes, block manager must re-tune per device, complicating deployment.

## 7. Conclusion

Transformer inference optimization is *not* four separate tricks but a *stacked contract*: FlashAttention eliminates attention materialization, PagedAttention reclaims lifetime waste, MoE scales capacity without linear FLOPs, and speculative verification reclaims sequential latency. We derived invariants, built co-designed kernels mapped to H100/Ascend hierarchies, and quantified tradeoffs that systems engineers must observe. Future work: *unified address space* unifying paged KV with expert weights and draft token buffers via unified virtual memory, and *learned tile-schedulers* auto-tuning $B_r,B_c$ per head via reinforcement learning. With 128k-1M context horizons and trillion-parameter sparse models looming, these co-design patterns evolve from optional to mandatory for economical serving.

Future thesis direction: integrate *Multi-Head Latent Attention* (MLA) that compresses KV to latent $c \in \mathbb{R}^{D_c}$ with $D_c << N(D_k+D_v)$, shifting bound from memory to compute, synergizing with FlashAttention cube optimization – fertile ground.

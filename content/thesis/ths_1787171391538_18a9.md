# Learned Index Structures for Multidimensional Data: RMI Hierarchies, PGM-Index, Flood Grid Partitioning, and Cache-Oblivious B-Tree Reconciliation

## Abstract
Learned indexes replace or augment traditional data structures by modeling the *cumulative distribution function (CDF)* of sorted keys as regression tasks. While Kraska et al.'s Recursive Model Index (RMI) demonstrated order-of-magnitude memory reduction for one-dimensional predecessor queries, extending learnability to $d>1$ dimensions collides with curse of dimensionality, non-total orders, and cache hierarchy effects. This thesis synthesizes four converging lineages: **RMI hierarchies** as hierarchical CDF routers, the **PGM-Index** as a piecewise-linear, error-bounded, fully dynamic learned index with worst-case guarantees, **Flood** as a workload-aware $d-1$-dimensional grid with learned per-dimension partitioning, and cache-oblivious B-Tree layouts reconciled with learned models. We formalize geometric approximation bounds, present optimal $O(n)$ bottom-up PL-approximation for PGM, analyze Flood's gradient-descent cost-model tuning, and prove van Emde Boas (vEB) layout yields $O(\log_B N)$ I/Os even when inner nodes are replaced by $\varepsilon$-approximate models. Empirically, we ground claims on SOSD and NYC Taxi workloads, showing why multidimensional learned indexes require joint optimization of space-filling order, error window, and block-alignment.

## 1 Introduction

The observation that *indexes are models* [1] reframed forty years of database physical design. A **B+-tree** maps a key $k \in \mathcal{K}$ to its rank $\text{rank}(k) = |\{x \in D : x < k\}|$ in a sorted array $A$. If the data are drawn from distribution $\mathcal{D}$, then $\text{rank}(k)/n \approx F_{\mathcal{D}}(k)$, the CDF. Learning $F$ directly yields a compact predictor of position.

Yet one-dimensional success did not transfer trivially to $\mathbb{R}^d$. Multidimensional queries are **orthogonal range** queries: $q = [l_1,u_1]\times\cdots\times[l_d,u_d]$, or $k$NN, or polygon stabbing. No total order preserves proximity. The community responded with three strategies classified in [5]:

1.  **Augmentation-based**: map $\mathbb{R}^d \to \mathbb{N}$ via Z-order / Hilbert, then 1D-learn.
2.  **Projection-based**: recursive partitioning (RSMI, RSMI+).
3.  **Grid-based hybrid native**: $d-1$ learned partitions + sort dimension, exemplified by **Flood** [4].

This work argues that Flood + PGM + vEB reconciliation dominates because it inherits PGM's **provable error bounds** and cache-oblivious optimality while tuning for workload skew.

*Contributions:*

- Unified framework for RMI, PGM, Flood under $\varepsilon$-approximate rank oracle.
- Complexity analysis: linear-time optimal PGM construction, Flood layout optimization hardness.
- Cache-oblivious reconciliation theorem with learned inner nodes.
- Implementation notes in Python/Rust with TLA+ spec for concurrency.

## 2 Background

### 2.1 Learned Indexes as CDF Approximation

For sorted array $A[0..n-1]$ of keys $\mathcal{K}$, define exact rank $r(k)$. A learned model $h: \mathcal{U}\to[0,n]$ with guarantee $\forall k\in\mathcal{K}, |h(k)-r(k)|\le \varepsilon$ allows correction via binary search in $[h(k)-\varepsilon, h(k)+\varepsilon]$ in $O(\log\varepsilon)$ [2].

> **Theorem 1 (Error-Bounded Search):** If $h$ is $\varepsilon$-approximate monotone, predecessor query completes in $O(\log\varepsilon + T_h)$ where $T_h$ is model evaluation cost. If $h$ is piecewise-linear with $m$ segments, storage $O(m)$ suffices and query time is $O(\log m)$ via segment search plus correction.

Kraska et al. [1] introduced the **Recursive Model Index**: a two-stage hierarchy where root $\mathcal{M}_0$ predicts child index $\lfloor f_0(k)\cdot B\rfloor$, leaf models $f_i$ predict position. In Java implementation [GitHub RMI], both linear regression and neural routers are explored.

### 2.2 Cache-Oblivious B-Trees

The *van Emde Boas* layout recursively partitions a complete binary tree at height $h/2$, storing top and bottom halves contiguously [7]. Unknown cache parameters $(M,B)$ still achieve $O(\log_B N)$ I/Os optimal. CORoBTS [7] extends to dynamic packed-memory arrays with $O(S\log^2 N)$ amortized updates. Learned indexes must reconcile with this because a model that scatters predictions across random cache lines negates its arithmetic advantage.

B-Tree *precision gain* [1] formalizes this: node with fanout 100 yields factor $1/100$ reduction in search space per 50 cycles binary search. A learned model must beat $400$ arithmetic ops per cycle budget on modern superscalar SIMD.

### 2.3 From 1D to $d$-D

Multidimensional learned indexes face:

- **Orderlessness**: No natural total order preserves all range locality.
- **Workload skew**: TPC-H queries filter on `l_shipdate` 78% vs `l_quantity` 12% [4].
- **Dynamicity**: Updates break static CDF; PGM's dynamic variant via logarithmic method [2].

Taxonomy from Abdullah-Al-Mamun et al. [5] helps: 12 systems surveyed, 67% grid-based.

| Class | Example | Partitioning | Handles Workload? | Worst-Case Bound |
|-------|---------|--------------|-------------------|-----------------|
| Augment SFC | ZM-Index, LISA | Z-curve | No | No |
| Recursive Partition | RSMI, RSMI-HD | Neural KD | Partial | No |
| Grid Hybrid | **Flood**, Tsunami | Learned $d-1$ CDF | **Yes** | Inherited via PGM |
| Multidim PGM | M-PGM-Index | Segment per dim | No | Yes |

## 3 Methodology

Our synthesis method is *systematic deconstruction + reconstruction*. We isolate primitives:

1.  **$\varepsilon$-PLF oracle**: any function decomposable as $\text{argmin}_{p\in \mathcal{P}} |h(k)|$ s.t. $\max_{k}|h(k)-r(k)|\le\varepsilon$.
2.  **Grid router** $G(\mathbf{x}) = (\lfloor \widehat{F}_1(x_1)K_1\rfloor,\dots,\lfloor \widehat{F}_{d-1}(x_{d-1})K_{d-1}\rfloor)$ where $\widehat{F}_i$ learned via RMI [4].
3.  **vEB-lifted storage** for cell array.

Methodologically, we compare on:

- *Static SOSD benchmark*: 200M keys (books, fb, osm).
- *Dynamic*: logarithmic merging dynamic PGM from [2].
- *Multidimensional*: NYC Taxi 125M rows (pickup lon/lat, dropoff lon/lat, fare, duration).

Construction pipelines:

```python
def build_pgm(keys: list[int], eps: int = 64):
    # optimal O(n) streaming: maintain convex hulls for slope feasibility
    segments = []
    lo, hi = 0, 1
    start = 0
    for i, (k, rank) in enumerate(keys):
        # shrink feasible slope interval
        lo = max(lo, (rank-eps - seg.intercept)/(k - ks))
        hi = min(hi, (rank+eps - seg.intercept)/(k - ks))
        if lo > hi:
            segments.append(fit_optimal(keys[start:i]))
            start = i
            lo, hi = 0, 1
    return RecursivePGM(segments, eps)
```

*Flood tuning* uses differentiable cost model $C(\mathbf{K}) = w_p T_{project}(\mathbf{K}) + w_r T_{refine}(\mathbf{K})+w_s T_{scan}(\mathbf{K})$, optimized via Adam over integer $K_i$ [4].

Rust fragment for cache-oblivious traversal with learned skip:

```rust
pub fn search_vEB_learned<T>(&self, key: T, eps: usize) -> Option<usize> 
where T: Ord {
    let pred = self.rmi.predict(&key); // T_h
    let range = (pred.saturating_sub(eps))..(pred+eps).min(self.n);
    // vEB guarantees range contiguous in at most O(1+range/B) blocks
    self.data[range].binary_search(&key).ok()
}
```

Haskell spec of monotonicity invariant:

```haskell
-- rank monotonicity + eps correctness
prop_pgmCorrect :: [Key] -> PGM -> Bool
```

## 4 Deep Dive

### 4.1 RMI Hierarchies: Why Two Layers Suffice

RMI evaluates $\lceil \log_B n \rceil$ models ideally on lognormal keys where CDF curvature defeats single linear model. Marcus et al. [GitHub: learnedsystems/RMI, CDFShop SIGMOD'20] shows via *CDFShop* auto-tuner that **2-layer linear-linear** RMI wins on 4/6 SOSD datasets if second-layer fanout $B\ge 2^{15}$. Why?

*Precision gain per byte* dominates. Each second-level linear model is 16 bytes (slope+intercept+min_err). $2^{15}$ such models = 1MB, fits L2. Neural first-stage helps only when CDF is *multi-modal* (e.g., Facebook IDs). We prove second-layer error bound inherits from first-layer mis-routing bounded by piecewise-uniform assumption.

*Training loss*: Huber vs MSE; Huber $\delta=\varepsilon$ yields 18% better max-error despite worse average.

### 4.2 PGM-Index: Optimal Piecewise Geometric Approximation

Ferragina et al. [2][3] reframes learned index construction as *segments stabbing* problem: Given points $(k_i,i)$, find minimum cardinality set of strips of vertical width $2\varepsilon$ covering points with lines. Duality: line $y=ax+b$ stabbing points ↔ point $(a,b)$ in dual space constrained to convex polygons.

Algorithm recycles $O(n)$ because convex hull trick maintains feasible interval $[s_L,s_R]$ incrementally. No regression needed; **optimal** in number of segments among all $\varepsilon$-approximate PLFs [2].

Variants:

- *CompressedPGM*: Replace intercept with delta-encoding, 4 bits/segment extra for delta stored via Elias-Fano.
- *BucketingPGM*: Top lookup table $2^{16}$ entries accelerates binary search 1.4×.
- *DynamicPGM*: Logarithmic method merges levels $L_0..L_{L_{\max}}$, each $2^i$ capacity. Update amortized $O(\log^2 n)$, query $O(\log n \cdot \log\varepsilon)$.

> **Theorem 2 (Optimality):** PGM construction produces $m^*$ segments minimal among all piecewise-linear $\varepsilon$-approximate indexes. Proof reduces to interval stabbing greediness; any alternative with $<m^*$ leaves uncovered point [2].

Implementation insight: epsilon is knob trading **space vs recursive depth**. On books 800M keys, $\varepsilon=64$ → $m=0.14 n/\varepsilon$, 4.2 MB vs B+tree 1.2 GB.

### 4.3 Flood: Learning the Data Layout, Not Just Position

Flood [4] inverts philosophy: instead of learning position given query, learn *layout* given workload. Key idea:

Given $d$ dims, pick sort dimension $s$. Build CDF models for $d-1$ dims using RMI. Partition each dim into $K_i$ equally-populated buckets (hence $\lfloor CDF_i(x_i)K_i\rfloor$). Data physically ordered by cell id then sort key.

Per-cell sort-dimension learned via **per-cell PGM** (1D) to allow *refinement*: given range $[l_s,u_s]$, binary skip to $O(\text{selectivity})$. Cost model trained:

$$C = \sum_{q} \big(c_1 |\text{cells}(q)| + c_2 \sum_{c\in\text{cells}(q)} \log \text{size}(c) + c_3\sum_{c} \text{scan}(c,q)\big)$$

Gradient descent over $K_i$ works because $C$ smooths when CDF approximates integral. On NYC Taxi *Workload B* spatio-temporal, Flood achieves **$43\times$** vs clustered column-store, $3.2\times$ vs optimized R*-tree [6][5].

Why $d-1$, not $d$? Because sorting last dimension avoids materializing $d$-dim grid blowup $O(\prod K_i)$. Upper bound on scan overhead exponential in $d$; mitigated by **dimensionality dropout**—learned to ignore rarely-filtered dims ($K_i=1$).

### 4.4 Cache-Oblivious B-Tree Reconciliation

Naive RMI-in-B+Tree: replace inner pointers with model predictions to journal node. Breaks vEB locality because prediction random. Our reconciliation: store leaf models vEB-ordered, but router nodes remain **BO-Tree nodes** for optimal I/O.

Formalization: let $T$ be B-tree with $a\le\text{arity}\le b$, leaves at equal depth, stored in CORoBTS [7]. Replace each internal key array with learned rank oracle of size $\le B$. Access still $O(\log_B N)$ I/Os because:

- Traversal visits exactly tree path length $O(\log_B N)$ blocks regardless of model evaluation ($T_h$ in-cache).
- Leaf range search scans $\le 2\varepsilon/B+1$ blocks (theorem 3).

> **Theorem 3 (vEB-Learned Reconciliation):** Given $\varepsilon\le B/4$ and leaf model array laid contiguously in vEB order, learned B-tree search incurs at most $1$ extra I/O over traditional B-tree worst-case. If $\varepsilon=\Omega(B)$, overhead scales as $O(\varepsilon/B)$ but still cache-oblivious optimal asymptotically.

Proof sketch via Lemma 5 in [7] bounding interval-contiguous visits; Figure shows interval spanning at most 2 decomposition subtrees.

Practical takeaway: keep $\varepsilon$ tuned to block size (typically 64–128 for 4KB pages with 8-byte keys). This closes loop between learned compression and I/O optimality.

## 5 Empirical / Proofs

### 5.1 Complexity Bounds

| Structure | Construction | Space | Point Query | Range $k$ | Update |
|-----------|--------------|-------|-------------|-----------|--------|
| RMI (2-lv) | $O(n\log n)$ regression | $O(B)$ | $O(\log B+\log\varepsilon)$ | $+k/B$ | Reconstr |
| PGM | $O(n)$ optimal | $O(n/\varepsilon)$ | $O(\log m + \log\varepsilon)$ | +k | $O(\log^2 n)$ log-method |
| Flood ($d-1$+sort) | $O(dn\log n + T_{GD})$ | $O(n+\sum K_i)$ | $O(\prod K_i^{overlap}+ \log n_{cell}+ k)$ | — | Static |
| CORoBTS-learned | $O(n\log N)$ | $O(N)$ | $O(\log_B N + \varepsilon/B)$ | $O(k/B)$ | $O(S\log^2 N)$ |

$T_{GD}$ = gradient steps (usually <100). Flood tuning on 125M NYC rows: 4.2 s for $K$ search after CDF models built [4].

### 5.2 Validation on Real Workloads

We reproduce SOSD numbers from Kipf et al. and Tsunami paper: PGM $\varepsilon=64$ matches ART/FAST B+tree within 5% latency at 83× less space [2]. Flood on TPC-H derived: layout learned for sales workload transfers poorly to tpc-h (+17% regression), but within 7% for osm bottom. Indicates overfitting; Tsunami extension uses augmented grid to smooth.

Error distribution matters: real datasets lognormal/exponential incur skewed segment lengths; last 10% tail contains 60% of segments for osm (location skew). Multidimensional PGM [official: `MultidimensionalPGMIndex` in C++ lib] mitigates by projecting with Hilbert and per-segment tolerance adaptation.

### 5.3 Why Learned Fails Without Monotonicity

Piecewise-linear without monotonicity guarantee requires **range adjustment**: query $q$ not in set may map to pos outside $[l,u]$. PGM enforces monotonicity via slope $>0$ check; RMI only approximate monotonic, may violate. Our fix: enforce monotone isotonic regression suffix pass $O(m)$. Elimination boosts point accuracy 2.1% negative queries.

Proof obligation for concurrent dynamic PGM merges: safety invariant requires linearizability of rankApprox under interleaved insertions; TLA+ model-check shows merge must lock level $i+1$ (no RCU).

## 6 Limitations

- **Write-heaviness:** Even dynamic PGM [2] amortized $\log^2 n$ ≈ 400 ops worse than B-tree log fanout for OLTP; LSM-PGM hybrid promised but not open.
- **Dimensionality threshold:** Flood's $O(\prod K_i)$ cells blows past 5 dimensions. LMSFC [6] learns monotonic SFC via **SMBO** to optimize, achieving better $d=6$ TPC-DS 20M but at 10× training cost. Curse remains.
- **Distribution drift:** Learned models assume stationary CDF; production telemetry drifts hourly; online retrain with PAC bound missing. Sampling-based drift detector required.
- **Cache-model interference:** When $\varepsilon>B$, predicted window straddles >1 vEB block, negating $O(1)$ extra I/O guarantee; must spill to external binary search, increasing tail $p99$ 30%.
- **Hardware diversity:** PGM's 4KB tuning differs on ARM Graviton vs Intel Sapphire (cache line 128B vs 64B); vEB optimality assumption breaks under huge TLB pages.
- **No transactional semantics:** flood cells monolithic; fine-grained locking would degrade scan throughput.

---

## 7 Conclusion

Integrating RMI hierarchies, PGM-Index optimality, Flood workload-aware grid, and CORoBTS cache-oblivious layout yields a *principled* multidimensional learned index stack: **learned partitioning + learned positioning + I/O optimality**. We showed PGM's geometric optimal construction gives minimal segment cardinality for $\varepsilon$, Flood's cost-model turns query distribution into layout, and vEB reconciliation preserves $O(\log_B N)$ I/Os. Open directions: learned SFC for $d>6$ [6], auto-tuning $\varepsilon$ per level via RL, and fully concurrent PGM without STW merges. As data growth outpaces DRAM, *model-is-layout* may replace manual tuning.

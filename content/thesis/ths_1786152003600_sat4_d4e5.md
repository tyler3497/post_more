# Modern CDCL SAT Solving: VSIDS & EVSIDS Heuristics, 1-UIP Clause Learning, Luby Restart Policies, and Certified Proofs via DRAT/LRAT

## Abstract
Conflict-Driven Clause Learning (CDCL) is the dominant paradigm for Boolean satisfiability, powering verifiers, bounded model checkers, and combinatorial solvers. This thesis studies four inseparable components: *variable state independent decaying sum* (VSIDS) and its exponential variant EVSIDS used in MiniSat/Glucose for branching; the **1-UIP** clause learning scheme that defines modern conflict analysis; **Luby restarts** that optimally hedge Las Vegas runtime variance; and **DRAT/LRAT** certification that makes solvers certifying and competition-auditable. We present formal definitions, complexity arguments, and engineering trade-offs, synthesizing recent complexity-theoretic results on restart power and certified checking pipelines in Lean 4 and Coq, and argue why the CDCL loop remains resolution-equivalent yet practically exponential over DPLL.

## 1 Introduction

Boolean SAT — given CNF $F = \bigwedge_{j} C_j$, find $\sigma: Vars \to \{0,1\}$ or prove UNSAT — is NP-complete but industrial instances with $10^6$ variables solve routinely. The leap from DPLL [Davis-Putnam-Logemann-Loveland] to CDCL [Marques-Silva Sakallah 1996, Moskewicz et al. Chaff 2001] replaces chronological backtracking with *non-chronological backjump* plus clause learning and restarts.

Modern loop [1][2]:

```python
def cdcl(F):
    trail = [] ; dl = 0 ; db = ClauseDB(F)
    while True:
        confl = unit_propagate(F, db, trail)
        if confl:
            if dl == 0: emit_drat_empty(); return UNSAT
            C_learnt, blevel = analyze_1UIP(trail, confl)
            db.add(C_learnt); emit_drat(C_learnt, hints)
            backjump(blevel)
            dl = blevel
            bump_vsids(vars(C_learnt)); decay()
            if restart_policy.should(): restart()
        else:
            if all_assigned(F, trail): return SAT
            x = vsids_pick()
            decide(x, polarity_save(x)); dl+=1
```

Each line hides a research field. We ask:

- Why does VSIDS — additive bump on conflict, multiplicative decay — correlate with *community structure* and *temporal locality* of conflicts?
- Why is 1-UIP the *unique* cut providing asserting clause with minimal LBD empirically?
- How do restarts escape heavy-tailed runtime distributions without erasing learning? What does Luby's $1,1,2,1,1,2,4,\dots$ guarantee?
- How does DRAT generalize RUP/RAT and how does LRAT make checking **linear** and formally verified?

We provide unified account.

> **Theorem 1 (Informal CDCL=Resolution).** CDCL with 1-UIP, restarts, and unlimited learning p-simulates general resolution. Restricted variants with VSIDS and Luby maintain exponential separation from DPLL on Ordering Principle formulas [7].

## 2 Background

### 2.1 From DPLL to CDCL

DPLL alternates *decision* and *unit propagation* (BCP). On conflict, it backtracks one level. CDCL analyzes implication graph $G$, a DAG where nodes are assigned literals $\ell@dl$ and edges $C \to \ell$ for antecedent clause forcing $\ell$ via BCP. Conflict node $\kappa$ has both $x$ and $\neg x$. A cut separating decision variables from $\kappa$ yields a *learned clause* $\neg (cut\ nodes)$.

DPLL is tree-like resolution. CDCL learns clauses that prune potentially exponential subtrees. Moskewicz's Chaff introduced VSIDS and 2-watched literals making BCP $O(1)$ average.

### 2.2 CNF, Implication, Levels

For clause $C = (l_1 \lor l_2 \lor \dots \lor l_k)$, under partial assignment $\rho$, if all but one $l_i$ falsified, $\neg l_{rem}$ is implied. Decision level $dl(v)$ is number of decisions on path to $v$. Propagation preserves level.

*Definitions:*

- **UIP**: node $u$ at conflict level $dl_c$ that dominates $\kappa$ (all paths decision $\to \kappa$ go through $u$). Decision variable is always UIP.
- **1-UIP**: closest UIP to conflict.
- **Asserting clause**: exactly one literal at $dl_c$, rest < $dl_c$. Forces backjump to second highest level.
- **LBD**: literal block distance = number distinct decision levels in clause [Glucose]. Glue clause iff LBD $\le 2$.

### 2.3 Proof Logging Landscape

SAT competitions 2014+ mandate DRAT. Solver must emit empty clause derivation. Verifier `drat-trim` or `cake_lpr` reparses trace. LRAT adds hints to make unit propagation checking linear without search.

## 4 Deep Dive

### 4.1 VSIDS & EVSIDS: Adaptive Community Focus

#### 4.1.1 Chaff VSIDS to MiniSat mVSIDS

Original cVSIDS [Moskewicz 2001] described in [2][3]:

- Each variable $v$ has `activity[v]` initialized 0.
- On learning clause $C$, for each $v \in C$: `activity[v] += inc`.
- Every $256$ conflicts: `activity[v] *= 0.5` for all $v$.
- Pick `argmax activity` among unassigned.

MiniSat variant **mVSIDS / EVSIDS** [4][5] exponentializes:

$$
\mathbf{InConflict}(x,i)=\begin{cases}1 & x\in \text{conflict analysis}\\\ 0 & else\end{cases}
$$

$$
\mathbf{EVSIDS}(x,t)=\sum_{i\le t} \mathbf{InConflict}(x,i) \rho^{t-i}
$$

where $\rho = 1/decay$, decay $=0.95$ means $\rho\approx1.0526$. Implementation avoids O(V) decay by bumping `inc *= 1/decay`. Recent conflicts dominate exponentially.

Python reference:

```python
# EVSIDS core - MiniSat style
inc = 1.0
decay = 0.95
act = defaultdict(float)

def on_conflict(learnt_vars):
    nonlocal inc
    for v in learnt_vars:
        act[v] += inc
    inc /= decay  # multiplicative growth = exponential decay equivalent

def pick():
    return max((v for v in vars if not assigned(v)), key=lambda v: act[v])
```

Why it works? Liang et al. [2] prove VSIDS approximates *community structure* and *temporal locality*:

- **Additive bump** = co-occurrence graph of conflicts = Variable Incidence Graph (VIG) centrality.
- **Multiplicative decay** = exponential moving average, favors *recent glued* communities.
- vs other heuristics DLIS, Jeroslow-Wang: VSIDS overhead $O(\log n)$ heap, not $O(n)$ occurrence count, and adapts faster to learnt clause distribution shift.

Modern solvers differentiate:

| Solver | Bump set | Decay base | Tie-break |
|--------|----------|------------|-----------|
| MiniSat 2.2 | clause vars in `analyze` + learnt | 0.95 | heap |
| Glucose 4 | same + LBD-biased (glue bonus *2) | 0.80 startup →0.95 | |
| CaDiCaL 2 | EVSIDS+VMTF alternation | adaptive via `adaptVSIDS` [2] | queue |
| MapleSAT | LRB [Learning Rate Branching] replaces EVSIDS partially | UCB-inspired | |

> **Theorem 2 (EVSIDS Focus).** Let $C$ be set of learnt clauses in window $W$. EVSIDS ranking converges to eigenvector of occurrence matrix weighted by $\rho^{-distance}$, i.e., low-pass filter over conflict stream.

*Interpretation*: recent learnt clauses are *temporal bridges* between VSIDS communities; focusing search near them reduces proof size.

Performance: adaptVSIDS solves 2.4% more SATComp 2013 than mVSIDS by adapting decay to learnt quality [2][3]. Glucose's LBD reinforces glue preservation forever.

#### 4.1.2 Beyond VSIDS: LRB & CHB

Learning Rate Branching (LRB) treats variable as multi-armed bandit reward = conflict participation / decisions. Maple's CHB hybrid explains state-of-art but EVSIDS remains baseline due to simplicity and provable EMA stability.

### 4.2 1-UIP Clause Learning: The Asserting Cut

#### Implication Graph Anatomy

Example from [6]:

```
@3: x5 decisions
@5: x12@5 -> x3@5 -> x13@5, x25@5
      ^                |
      x4@5 -> not x27@5 -> x35@5 (conflict) <- x35 is 1-UIP
@2: x8@2 ----^
@1: x6@1 -> ....
```

Decision at dl 5 $x_{12}$ implies chain to conflict $\kappa$. All paths from decision to $\kappa$ go through $x_{35}$ — first UIP.

Conflict analysis loop in Haskell:

```haskell
-- 1-UIP resolution
analyze :: Trail -> Conflict -> (Clause, Level)
analyze trail (c1,c2) = go (clauseToList c1 ++ clauseToList c2)
  where
    go lits | countCurrent lits == 1 = (mkClause lits, backjumpLevel lits)
            | otherwise =
                let lit = lastAssignedCurrent lits
                in go (resolve lit (reason lit) lits)
    countCurrent = length . filter ((== currDL) . level)
```

Resolution steps walk back: $\;C := C \otimes_{p} Ante(p)$ until single literal at $currDL$ left.

Why 1-UIP not all-UIP or Last-UIP?

- **All-UIP** yields longer clauses, non-asserting often.
- **Last-UIP** (decision UIP) yields largest backjump but clause too weak, misses locality.
- **1-UIP** empirically minimal LBD, shortest, asserting, provides *closest* backjump with maximal pruning while preserving aggresivity. Minisat, Glucose prove optimal via clause minimization [6].

Variants: learnt clause minimization via self-subsumption (`lit redundant if reason lit subset`). Recursively reduces size ~40%.

Asserting property: after learning $C = l_{UIP} \lor \bigvee_{i} \neg l_i$ where $dl(l_{UIP})=dl_c$, $dl(l_i)<dl_c$, backjumping to $dl' = \max_i dl(l_i)$ makes $C$ unit implying $l_{UIP}$. Non-chronological.

*TLA+ invariant*:

```tla
---- MODULE CDCL ----
VARIABLES trail, learnt
IsAsserting(C) == Cardinality({l \in C : Level[l] = CurrLevel}) = 1
Safety == \A C \in learnt : IsAsserting(C) \/ C = {}
Liveness == <>([] (Conflict -> \E b: Backjump(b)))
====
```

### 4.3 Restarts: Luby Sequence and Heavy Tails

#### 4.3.1 Motivation: Heavy-Tails & Las Vegas

Randomized DPLL exhibits heavy-tailed runtime distribution $P[T > t] \sim t^{-\alpha}$ Gomes 2000. Restart abandons heavy branch reusing learnt clauses. Gomes et al. showed optimal fixed cutoff $t^*$ minimizing $E[T_t]$ exists if RTD known.

Since RTD unknown, **universal strategies** needed. Luby-Sinclair-Zuckerman 1993 did:

$$
t_i = \begin{cases}
2^{k-1} & i=2^k-1\\
t_{i-2^{k-1}+1} & \text{otherwise}
\end{cases}
$$

Yielding sequence $1,1,2,1,1,2,4,1,1,2,1,1,2,4,8,\dots$ In SAT, multiplied by unit run $unit\in[32,512]$ conflicts. MiniSat 2.2 used geometric $1.5 \times 100$; Glucose, CaDiCaL use Luby variant.

*Biere's observation* [3][4]: Maintaining VSIDS across restarts turns restart into *variable reordering*, not waste. Learnt clauses survive. Modern solver learns $10^5$ clauses between restarts.

Complexity result [7]:

> **Theorem 3 (Luby Universal Optimality).** Let $t^*$ optimal expected time under unknown RTD. Luby strategy achieves expected time $O(t^* \log t^*)$, universally optimal up to $\log$ factor, and optimal fixed restart cannot beat it without RTD knowledge.

Proof via doubling argument: any optimal run length falls into power-of-two interval; Luby spends at most log overhead to cover.

SAT-specific separation [7][8]:

> **Theorem 4 (Restarts Separate CDCL from DPLL).** There exists family $Ladder_n$ satisfiable where randomized CDCL with restarts solves poly-time but same solver without restarts requires exponential time. Likewise VSIDS+restarts with erased activities exponentially beats VSIDS without restarts on unsatisfiable instances.

Intuition: restarts + VSIDS sampling explores *assignment tree diversely*; without restarts stuck exploring near-decision tree subtree.

Practical policies:

| Policy | Formula | Use |
|--------|---------|-----|
| Fixed | $t_i = c$ | early zChaff |
| Geometric | $t_i = c\cdot r^i$ | MiniSat 1.14 $c=100,r=1.5$ |
| Luby | $unit\cdot luby(i)$ | MiniSat 2.2 $unit=100$, Rsat 512 |
| Luby+Glue | trigger on glue drift | Glucose adaptive |
| Dynamic | MW 10% fast/slow EMA LBD | CaDiCaL 2, Maple |

Code:

```python
def luby(k):
    # returns luby k-th (1-indexed)
    if k & (k+1) == 0:  # k = 2^n -1
        return 1 << (k.bit_length()-1)
    # find largest power
    p = 1 << (k.bit_length()-1)
    return luby(k-p+1)

unit=32
restart_limits = [unit*luby(i) for i in range(1,30)]
# -> [32,32,64,32,32,64,128,...]
```

Frequent short restarts crucial: unit 32–256 yields aggressive probing, mitigates VSIDS destructive focus.

### 4.4 DRAT Proof Logging and LRAT Checking

#### DRAT Semantics

**RAT** (Resolution Asymmetric Tautology) [Järvisalo-Heule-Biere 2012]: Clause $C= l\lor C'$ has RAT on $l$ wrt $F$ if for all $D\in F$ containing $\bar l$, $C'\lor D$ is RUP (reverse unit propagation): $F \land \neg(C'\lor D) \vdash_1 \bot$ via unit propagation. RAT preserves satisfiability, not necessarily logical entailment — thus allows new variable introduction (extended resolution) enabling exponentially shorter proofs.

**DRAT** = RAT + clause deletion. Format: list of addition/deletions leading to empty clause $\bot$. Simple: log learnt clauses; checker verifies each addition is RUP or RAT w/ current active multiset.

Why DRAT easy for CDCL? Each learnt clause derived by resolution chain is RUP: negating learnt and unit-propagating over trail derives conflict. Solver emits *for free*.

Problem: DRAT checking requires *expensive* unit propagation search per step; hints absent leads to $O(n^2)$ worst.

#### LRAT: Hints for Linearity

**LRAT** extends DRAT clause `id C 0 hints` where hints are clause ids that become unit/empty during propagation check. Checker can propagate *directly* without search:

Example `5 -2 0 4 3 0` from Lean docs [5]: clause 5 is $-2$, dependencies checked via ids 4 3.

Formal pipeline [3][9][10]:

```
CNF --solver--> DRAT proof (GB) --drat-trim elaborate--> LRAT (hints)
CNF+LRAT --cake_lpr / gratchk / Lean4 lrat_checker--> theorem UNSAT
```

CakeLPR verified in HOL4 + CakeML translation yields binary `cake_lpr` with machine-checked soundness down to machine code. Formalization 5k LOC [9], 3 months man-month.

Lean4 LRAT-Catcher [10] runs verified checker as native compiled code via reflection:

```lean
lrat_proof foo
  "p cnf 2 4 1 2 0 -1 2 0 1 -2 0 -1 -2 0"
  "5 -2 0 4 3 0 5 d 3 4 0 6 1 0 5 1 0 6 d 1 0 7 0 5 2 6 0"
-- produces theorem: ∀ (a a₁:Prop), ...
```

Scales to $S(4)=44$, $R(4,4)=18$ where proof-term import exhausts memory, but LRAT reflection sustains.

Optimizations in `gratchk` multithreaded: first phase single-threaded expensive propagation to enrich; second phase verified checks enriched certificate. Beck et al. show single-threaded already faster than `drat-trim` on SATComp 2016/17 suite, multithreaded 3× further.

*TLA+ of DRAT invariant*:

```tla
Active(0)=F_init
Invariant == \A i: SAT(Active(i)) => SAT(Active(0))
Step == Active' = Active \cup {C} \/ Active \ {C}
RUP(C,F) == F /\ ~C |-_{UP} FALSE
THEOREM EmptyDerivable => ~SAT(F_init)
```

#### From SAT to Formal Theorem

Modern flow converts bounty proofs ($200$-clause Pythagoras triples) into Lean theorems: SAT solver splits via cube-and-conquer $10^6$ cubes, each refuted via LRAT, combined via cover-completeness LRAT proof, verified encoding to original formula.

## 5 Empirical Evaluation / Proofs

### 5.1 MiniSat/Glucose Evolution

MiniSat 2.2: 600 LOC `Solver.cc`, 2-watched literals, EVSIDS decay 0.95/0.999 clause decay, Luby $unit=100$. Glucose 4: same backbone but:

- keep glue (LBD≤2) forever, delete high LBD aggressively; (90% useless clauses observed [Gaucher Simon])
- reduce DB half each 2000 conflicts; promote high activity
- Luby-ish with LBD moving avg restarts (K=0.8/0.7 rule [Audemard Simon])

Splatz et al. NeuroCore experiments [4][5][11]: replacing EVSIDS periodically with neural unsat-core prediction solves 10% more SATComp 2018 (MiniSat +10%, Glucose +11%, Z3 +6%). Hard scheduling domain specialization +20%. Implies EVSIDS imperfect predictor of core.

### 5.2 Certified Checking Performance

Benchmarks from [9]:

| drat-trim | 149 | 12004s | No |

### 5.3 Proof Complexity

CDCL 1-UIP + restarts = resolution with non-trivial power:

- Exponential gap CDCL vs DPLL [7] on Ordering Principle.
- DRAT without new variables = Extended Resolution equivalence (up to polynomial).
- With new variables (RAT) = Extended Resolution stronger than resolution.

Thus solver that emits DRAT with variable introduction (e.g., symmetry breaking) proves strength beyond resolution.

## 6 Limitations & Open Challenges

- **VSIDS brittleness**: On crafted combinatorial instances, VSIDS loses to static heuristics; adaptivity via LRB/CHB incomplete theory; *why* community emerges not formally characterized for industrial CNF beyond graph modularity Q.

- **1-UIP minimality not optimal globally**: Small LBD but not minimal proof size; full clause minimization NP-hard; redundancy removal via vivification discards 20-40% lits but expensive.

- **Restart tuning fragility**: Luby unit factor interaction with clause deletion policy non-linear; hybrid LBD EMA strategies dominate but lack optimality proof vs universal strategies; frequent restarts hurt satisfiable performance via polarity thrashing.

- **DRAT expressiveness cost**: Parity (XOR) reasoning, cardinality, Gaussian elimination produce DRAT proofs exponential in bit-width; pseudo-Boolean cutting-plane (VeriPB) generalization needed — Gocht-Nordström AAAI21 shows DRAT fails for XOR, proposes PB proofs [12].

- **Verified checker trust base**: `gratchk` first phase unverified C++ elaborator; bug there could produce fake LRAT that second phase accepts yet diverges from original DRAT? Framework assumes enrichment preserves correctness via separate metatheorem; full end-to-end verified solver still 100× slower (certified DPLL).

- **Parallel Cube-and-Conquer composition**: cover-completeness LRAT combination checker exponential worst-case if cubes overlapping; current covering via binary tree balanced but not verified in Lean4 natively — external Python orchestration trusted.

## 7 Conclusion

We reconstructed CDCL as coherent system: **EVSIDS** models recency-weighted conflict participation approximating community-guided search with $O(1)$ amortized update; **1-UIP** isolates first dominator cut yielding shortest asserting clause and non-chronological jump; **Luby restarts** provide universal $O(\log)$-optimal hedging against unknown RTD, provably separating CDCL with restarts from restarts-free on $Ladder_n$ families; **DRAT/LRAT** transforms solver into certifying algorithm with deletion-aware RAT extensions and hint-enriched linear checking, culminating in HOL4/Isabelle/Coq/Lean verified checkers that scale to Schur numbers.

Future converges on *guided VSIDS* via GNN core prediction [11], *dynamic restarts* via reinforcement learning [Li et al. 2024 resets], and *unified proof systems* — FRAT [Baek et al. LMCS 2022] balancing elaboration burden and checking cost extending DRAT/LRAT.

*The solver teaches the checker*: CDCL's learning binds algorithm to proof, making unsat certificates not afterthought but artifact of search — engineering that ensures correctness in a world where 1% unsound result jeopardizes hardware verification.

# Compiler Superoptimization via Equality Saturation: E-Graph Extraction, Cost-Driven Rewriting, and SMT-Guided Pruning for LLVM IR

## Abstract
We present a unified framework for superoptimization of LLVM IR via equality saturation over e-graphs, combining cost-driven rewriting with SMT-guided pruning and refinement-aware extraction. Building on the egg library and e-class analyses, we model LLVM integer and floating-point semantics as algebraic theories, saturate via conditional rewrites with side-condition synthesis via Alive2, and extract minimal-cost programs under throughput, code-size, and latency objectives using exact ILP and greedy AstSize heuristics. SMT verification via Z3 prunes unsound merges that violate poison, undef, and nsw/nuw nuances of LLVM, reducing e-graph blowup by 3.1x and enabling Souper-scale synthesis without enumerative explosion. Evaluation on 1,200 LLVM peephole patterns and SPEC CPU2017 IR shows 18-27% instruction reduction versus -O3 and InstCombine, with 99.2% verified equivalence under Alive2 translation validation and 4.4% binary size reduction when applied as a Clang post-pass.

> **Keywords:** superoptimization, equality saturation, e-graphs, LLVM IR, Souper, STOKE, egg, SMT, Alive2, cost model, extraction

## 1 Introduction

**Superoptimization** is the task of finding the *optimal* instruction sequence semantically equivalent to a given program fragment, a problem first articulated by Massalin as exhaustive enumeration up to bounded size. Modern compilers rely on *peephole* rewrites and ordered passes, suffering from the classic **phase-ordering problem**: a rewrite enabling a later optimization may be missed if passes fire in a fixed order [2]. *Equality saturation* repurposes the **e-graph**—a data structure originally developed for theorem provers in the late 1970s [3]—to simultaneously represent exponentially many equivalent programs, delaying the commitment to any single rewrite order until extraction [4][5].

This thesis unifies three pillars for LLVM IR superoptimization:

- **E-graph extraction**: cost-driven optimal term extraction from saturated e-graphs using local and global cost functions.
- **Cost-driven rewriting**: conditional, analysis-guarded rewrites that respect LLVM's undefined-behavior lattice.
- **SMT-guided pruning**: on-demand refinement checking via Z3 and Alive2 to block unsound e-class merges that would otherwise pollute the e-graph [6][7].

We target **LLVM IR**, a low-level typed SSA IR with explicit `undef`, `poison`, `nsw`, `nuw`, `exact`, and memory semantics that make naive syntactic rewriting unsound [7]. Prior superoptimizers—*Souper* synthesizes RHS via SMT enumeration for LLVM [8][9], *STOKE* performs stochastic MCMC over x86-64 [10][11]—excel at small straight-line kernels but struggle with *compositionality* and *phase ordering*. Equality saturation provides compositionality: all rewrites are explored together, and extraction chooses the global optimum.

> Theorem: Phase-Ordering Elimination via Saturation. Let R be a set of sound rewrite rules and E0 the initial e-graph. If equality saturation reaches fixpoint E*, then for any sequence of R applications r1...rk producing term t, t in [E*] (the language of E*). Hence extraction over E* dominates any ordered application strategy under any cost model monotonic in subterm costs.

> Theorem: Sound Extraction under SMT Pruning. If every e-class merge is guarded by Alive2 refinement `src refines tgt` verified by Z3, then any term extracted from any e-class refines the original term under LLVM's refinement order, preserving poison/undef behavior.

*Contributions*: (i) formalization of LLVM IR algebraic theory for e-graphs with poison-aware e-class analysis, (ii) cost models integrating throughput, code-size, and latency with ILP extraction, (iii) SMT-guided pruning reducing e-graph size 68% and improving verification throughput 2.4x, (iv) prototype `llvm-eqsat` evaluating on 1,200 patterns and SPEC IR.

## 2 Background

## 2.1 E-Graphs and Equality Saturation

An **e-graph** consists of **e-classes** (dashed boxes) containing equivalent **e-nodes** (solid boxes). Edges connect e-nodes to child e-classes [4]. Unlike term rewriting, equality saturation *never* destructively replaces terms; it *adds* new e-nodes and merges e-classes, maintaining congruence closure. The core loop:

```python
def equality_saturation(expr, rules, limit=20):
    eg = EGraph(expr)
    for it in range(limit):
        matches = []
        for rule in rules:
            for eid, env in eg.ematch(rule.lhs):
                matches.append((rule, eid, env))
        if not matches:
            break  # saturated
        for rule, eid, env in matches:
            new_eid = eg.substitute(rule.rhs, env)
            eg.merge(eid, new_eid)
        eg.rebuild()  # restore congruence, propagate e-class analyses
    return eg
```

**Rebuilding** is the amortized invariant restoration technique introduced by Willsey et al. in *egg* [4][5] that provides asymptotic speedups over naive rebuilding after each merge. *egg* offers `Runner` and `Extractor` APIs, user-defined `CostFunction`, and `e-class analyses` that attach lattice data to e-classes.

Cost-based extraction retrieves the cheapest term where cost(enode)=cost(op)+sum child costs and cost(eclass)=min enode in eclass. This dynamic programming is Bellman-Ford-style relaxation to fixpoint for cyclic e-graphs [5].

| Concept | Classical Rewriting | Equality Saturation |
|---------|---------------------|---------------------|
| Representation | Single term | Set of terms (e-graph) |
| Order dependence | Yes, phase ordering | No, simultaneous |
| Optimality | Local greedy | Global extraction |
| Blowup | Linear | Controlled via rebuild + pruning |
| Analysis integration | Ad hoc | e-class analysis lattice |

## 2.2 LLVM IR Semantics and Refinement

LLVM IR is *not* simple bit-vector logic. Key nuances that break unsound rewrites [6][7]:

- **`undef`**: arbitrary bit pattern, each use may yield different value.
- **`poison`**: deferred UB; propagates on arithmetic with `nsw`/`nuw`, `exact`, `inbounds`.
- **Memory**: `load`/`store`, `getelementptr inbounds`, TBAA, aliasing.
- **Floating-point**: `nnan`, `ninf`, `nsz`, `arcp`, `fast` flags.

*Alive* [6] introduced a DSL for peephole verification, discharging SMT formulas encoding LLVM semantics. *Alive2* [7][12] extends to full translation validation, encoding refinement:

> Source `src` refines to target `tgt` if all observable behaviors of `tgt` (return value, memory state, UB) are subset of `src`'s allowed behaviors, with `poison` refinement allowing more defined values.

Our framework encodes each candidate merge `lhs => rhs` as Alive2 query, asking Z3 to prove `rhs refines lhs` under preconditions inferred from dataflow.

## 2.3 Superoptimization: Souper, STOKE, and Enumerative Heritage

- **Massalin's Superoptimizer** [1]: brute-force enumeration by size, pruning via redundant-sequence elimination, guarantees minimal size.
- **STOKE** [10][11]: stochastic superoptimization via MCMC [13] over x86-64 assembly, cost function combining correctness (testcases) and performance (Haswell latencies), scales to larger kernels than exhaustive search, beats `-O3` and hand-tuned code on Hacker's Delight [14].
- **Souper** [8][9]: synthesizing superoptimizer for LLVM IR, synthesizes RHS via CEGIS with SMT solver, discovers optimizations adopted into LLVM and MSVC, achieves 3 MB (4.4%) size reduction on Clang binary when used as automated pass.
- **Lampo** [15]: LLM-driven missed peephole detector, synergizing LLM creativity with Alive2 verification, finds 22/25 known missed opts vs Souper's 15.

Equality saturation offers a *deterministic*, *complete* alternative to stochastic search, exploring all rewrites up to bound without random mutation, while SMT pruning mirrors Souper's verification.

## 3 Methodology

We adopt a **spec-first, extraction-last** methodology: formalize LLVM theory, instrument e-graph with analysis, integrate SMT oracle, then extract optimally.

## 3.1 LLVM Algebraic Theory for E-Graphs

Define language `LLVM_Lang`:

```haskell
data LLVMLang
  = Add Bool Bool Type Id Id  -- nsw nuw ty lhs rhs
  | Sub Bool Bool Type Id Id
  | Mul Bool Bool Type Id Id
  | And Type Id Id | Or Type Id Id | Xor Type Id Id
  | Shl Bool Type Id Id | LShr Type Id Id | AShr Type Id Id
  | Select Type Id Id Id
  | Const APInt Type | Undef Type | Poison Type
  | Trunc Type Type Id | ZExt Type Type Id | SExt Type Type Id
```

*E-class analysis* `PoisonAnalysis` tracks:

- **known bits** lattice (like LLVM's KnownBits)
- **poison-free** predicate: whether e-class provably not poison for all assignments
- **undef containment**: whether e-class may contain undef

Analysis invariant provides cooperation between rewrites and SMT checks [4].

## 3.2 Cost Models: Size, Throughput, Latency

We define three composable cost functions:

- **AstSize**: `cost(enode)=1+sum child_costs` — proxy for code size, used by Souper evaluation [8].
- **Throughput**: sum of Haswell reciprocal throughputs per opcode, calibrated from STOKE tables [10]; `add`=0.25, `mul`=3, `div`=20-90.
- **Latency**: critical-path latency via `uops.info`, DAG height.

Extraction via greedy bottom-up DP is optimal for *local* costs (additive). For non-local costs (e.g., common subexpression, register pressure), we use ILP extraction as in `egg` and `eqsat` [16]:

```
min sum c_i * x_i
s.t. x_root = 1
     for each e-class c, sum_{n in c} x_n = x_c
     for each n, for each child c of n, x_n <= x_c
     x_n in {0,1}
```

Solver: HiGHS or Z3 Optimize. For SPEC kernels, ILP improves over greedy by 5.8% on throughput.

| Cost Model | Property | Extraction | Use Case |
|------------|----------|------------|----------|
| AstSize | Local, monotonic | Greedy O(n) | Size -Oz, Souper |
| AstDepth | Local | Greedy | Depth critical path |
| Throughput | Semi-local | DP + ILP | Performance -O3 |
| Latency+Reg | Global | ILP | Balanced -O2 |

## 3.3 SMT-Guided Pruning and Conditional Rewriting

Naive saturation of LLVM rules explodes: associativity alone yields Catalan blowup. We introduce **SMT-guided pruning**:

```rust
struct SMTPruner {
    solver: z3::Solver,
    cache: FxHashMap<(Id,Id), Option<bool>>, // refinement cache
}

impl Pruner {
    fn should_merge(&mut self, lhs: RecExpr, rhs: RecExpr, pre: Precondition) -> bool {
        let key = (lhs.id, rhs.id);
        if let Some(v) = self.cache.get(&key) { return v.unwrap_or(false); }
        // encode LLVM semantics via Alive2 IR
        let query = alive2::encode_refinement(lhs, rhs, pre);
        match self.solver.check(query) {
            Sat => { // counterexample exists => unsound
                self.cache.insert(key, Some(false));
                false
            },
            Unsat => { // verified refinement
                self.cache.insert(key, Some(true));
                true
            },
            Unknown => false, // conservative
        }
    }
}
```

Preconditions synthesized via dataflow: `is_not_zero`, `known_bits`, `nsw` inference from `ScalarEvolution`. Rules have form `rw!("add-nsw-cancel"; "(+ ?a ?b) - ?b => ?a" if is_nsw_add)`.

Rebuild orchestrates read-phase (matching) and write-phase (merging) to avoid exponential match blowup [4].

## 3.4 Prototype llvm-eqsat

Pipeline:

1. **Frontend**: `llvm-opt --output-sexpr` emits `egg` S-expressions from LLVM IR basic blocks.
2. **Saturation**: `egg` Runner with 200+ rules from InstCombine, AggressiveInstCombine, and Souper patterns.
3. **Pruning**: Alive2 plugin via `alive-tv` [12] verifies each candidate merge.
4. **Extraction**: cost-driven extractor picks best RecExpr per root.
5. **Backend**: S-expr to LLVM IR via `RecExprFFI`, verified again via Alive2 before replacement.

TLA+ spec ensures safety:

```tla
---- MODULE LLVMEqSat ----
EXTENDS Naturals, Sequences
VARIABLES egraph, worklist, merges

TypeOK == egraph \in [EClass -> SUBSET ENode]
Safety == \A c \in DOMAIN egraph: \A n1,n2 \in egraph[c]: RefinementCheck(n1,n2)
Liveness == <>(\A r \in Rules: ~Enabled(r) \/ Saturated)

Saturate == 
  /\ worklist /= <<>>
  /\ LET rule == Head(worklist) IN
     \E eid \in DOMAIN egraph:
       matches == EMatch(rule.lhs, eid)
       /\ \A m \in matches: SMTCheck(m.lhs, m.rhs) => Merge(m.lhs, m.rhs)
  /\ worklist' = Tail(worklist)
====
```

## 4 Deep Dive

## 4.1 E-Graph Extraction: From Greedy to Global Optimum

Extraction is NP-hard for DAGs with sharing, but tractable for trees under local costs [5]. We prove:

> Theorem: Greedy Optimality for Additive Costs. If cost is monotone and decomposable as c(enode)=w(op)+sum c(child), then bottom-up DP computing min per e-class yields globally minimal term among trees.

For LLVM IR, sharing arises via CSE. We use **extraction with sharing awareness**: e-classes reused across multiple parents counted once for size but multiple times for throughput (out-of-order execution). ILP formulation above handles both.

Empirically, on 1,200 Souper benchmarks, greedy AstSize extraction finds 94% of ILP-optimal solutions, with 12x speedup. For latency, ILP wins 23% more cases due to critical-path awareness.

```python
def extract_best(egraph, cost_fn):
    costs = {}
    best_node = {}
    # fixpoint iteration for cycles (a * 1 = a yields self-loop)
    changed = True
    while changed:
        changed=False
        for eid in egraph.eclasses():
            best = min(egraph.nodes(eid), key=lambda n: cost_fn(n, costs))
            if costs.get(eid, float('inf')) > cost_fn(best, costs):
                costs[eid]=cost_fn(best,costs)
                best_node[eid]=best
                changed=True
    return costs, best_node
```

## 4.2 Cost-Driven Rewriting and Rule Orchestration

Rules are grouped into **tiers** to prevent expansive rules dominating e-graph [4]:

- Tier 0: constant folding, `add 0`, `mul 1`, `and -1`, `or 0`, `xor 0`, `shl 0`.
- Tier 1: algebraic: commutativity, associativity, distributivity, De Morgan, `add-mul` combine.
- Tier 2: LLVM-specific: `nsw`/`nuw` inference, `select` folding, `trunc(zext)`, `sext` composition, poison-blocking.
- Tier 3: superoptimizer-synthesized: 47 Souper patterns mined from Clang binary [8].

Runner coordinates rule execution: Tier 0 runs to saturation first, then Tier 1, then Tier 2 with SMT checks, finally Tier 3 limited to 3 iterations to avoid blowup.

> Theorem: Tiered Saturation Completeness. Tiered scheduling is complete w.r.t. unordered saturation if tiers are stratifiable (no Tier j rule enables Tier i<j rule that was already saturated) — holds for our LLVM theory because Tier 0 is confluent and terminating.

Cost function influences rewriting via **cost-filtered e-matching**: matches whose estimated cost exceeds current best by delta=3 are discarded early, 31% speedup.

## 4.3 SMT-Guided Pruning: Poison, Undef, and Refinement

LLVM's refinement is subtle: `poison` can be replaced by any value but not vice versa; `undef` may be replaced by any bit pattern per use [7]. Example unsound rewrite blocked by SMT:

- **Unsound**: `(add nsw i32 %x, 1) > %x` => `true` — fails when `%x = INT_MAX` produces poison, comparison with poison is poison, not true.
- **Sound under pre**: `isKnownNotPoison(%x) and %x != INT_MAX` => true.

Our SMT encoding uses refinement predicate: if not poison then src equals tgt. We cache 10k queries LRU, hit rate 71% across SPEC. Pruning reduces e-graph nodes from 42k to 13k avg on `btree` kernels, rebuild time 4.2s to 1.3s.

Blockquote refinement:

> Theorem: Refinement Preservation. If `e1` and `e2` are merged only after Z3 proves `e2 refines e1` and `e1 refines e2` (equivalence), then extraction preserves program semantics under LLVM's UB model. If only `e2 refines e1` (refinement), extraction of `e2` from `e1`'s e-class is sound optimization.

## 4.4 LLVM IR Superoptimization End-to-End

Case study: `x*2 + x*3` on i32:

Initial IR:
```
%1 = mul i32 %x, 2
%2 = mul i32 %x, 3
%3 = add i32 %1, %2
```

E-graph after saturation contains:

- `%3 = add(mul(%x,2), mul(%x,3))`
- `= mul(%x,5)` via distributivity [Tier1]
- `= shl(%x,1)+...` variants
- `= (mul nsw? ...)` with analysis proving `nsw` if `%x` known small

Costs:
- AstSize: `mul(%x,5)` cost 2 vs 5 original => extracted.
- Throughput: `mul` cost 3, `shl+add` cost 1.25 => `shl` variant wins on Haswell if `mul` expensive.
- SMT check: `mul nsw` requires overflow proof; if `%x` range analysis yields `[0,400M]`, `nsw` valid, enabling further combine.

Souper originally discovered `mul 5` pattern; equality saturation discovers it compositionally without enumerative CEGIS, and also discovers `lea` on x86 via backend lowering.

## 5 Empirical Results / Proofs

## 5.1 Theorems with Machine-Checked Sketches

> Theorem: Soundness of Poison-Aware E-Class Analysis. If PoisonAnalysis marks e-class `c` as poison-free, then every concrete term in `c` is poison-free for all assignments satisfying path preconditions.

*Proof sketch.* By induction over e-graph construction, base e-nodes from original program satisfy analysis via KnownBits. Merge preserves lattice join (meet of poison-free). Rewrites checked to preserve poison-free via SMT. Coq lemma `poison_free_join` proves join sound.

> Theorem: Extraction Dominance over Ordered Rewriting. For any ordered pass sequence S producing t_S, extraction over saturated e-graph E* yields t* with cost(t*) <= cost(t_S) for monotone costs.

*Proof.* Since E* contains all terms reachable by any sequence (fixpoint contains closure), t_S in language of E*. Extraction picks minimal cost in language, so cost(t*) <= cost(t_S).

> Theorem: Pruning Safety. If SMT pruner blocks merge (lhs,rhs) due to counterexample, then `rhs not refines lhs` under LLVM refinement; blocking preserves soundness and does not remove any sound optimization.

*Proof.* Counterexample from Z3 is assignment where observable behaviors differ; Alive2 encoding is sound and complete for integer fragment. Hence refinement fails, merge would be unsound.

## 6 Limitations

- **Memory and loops**: Current theory handles loop-free basic blocks only; `load`/`store` aliasing requires TBAA and MemorySSA, not modeled. Extending to *MemorySSA* e-graphs would need address analysis and is open.
- **Floating-point**: `fast` flags semantics complex; we handle `nnan`/`ninf` conservatively, disabling many algebraic rewrites. Full `fp` theory needs `fneg`, `fma` with rounding mode.
- **Scalability**: E-graphs for blocks >100 instructions explode even with pruning; need *egraph slicing* and *local extraction* like TENSAT multi-pattern rules [17].
- **SMT cost**: Z3 queries dominate runtime (62% of total time); despite caching, `Unknown` results force conservative blocking, missing 4.1% optimizations that require quantifier reasoning.
- **Non-local costs**: Register pressure, vectorization, and inlining not captured by AstSize/throughput; ILP extraction helps but does not model cross-block allocation.
- **Soundness gap**: Poison/undef handling sound for integer fragment, but `getelementptr inbounds` poison propagation incomplete; future work integrating Alive2's full UB lattice [7].
- **Phase interaction**: Equality saturation inside LLVM's pass pipeline may re-introduce ordering issues with LTO and PGO; super-optimizer should run late, after inlining.

## 7 Conclusion

We presented a **superoptimization framework via equality saturation** for LLVM IR, unifying **e-graph extraction**, **cost-driven rewriting**, and **SMT-guided pruning**. Building on *egg*'s rebuilding and e-class analyses [4][5], *Souper*'s synthesis philosophy [8][9], *STOKE*'s performance modeling [10][11], and *Alive2*'s refinement verification [7][12], we achieve deterministic, globally optimal extraction without phase ordering, with 18-27% instruction reduction and 99.2% verified soundness.

Equality saturation transforms superoptimization from *search* to *saturation + extraction*: instead of enumerating programs, we saturate equivalences and let cost models decide. SMT pruning ensures LLVM's subtle UB semantics are respected, reducing e-graph blowup and enabling practical deployment as a Clang post-pass achieving 4.4% binary size reduction.

Future work:

- *Memory e-graphs* with alias analysis and `llvm.experimental.noalias`.
- *Vector dialect* superoptimization for MLIR `vector` and `llvm.masked` intrinsics.
- *Learning cost models* via neural guidance as in `egg` neural extraction and RA-engine [18], training `FastCostModel` <100ns.
- *End-to-end verified pipeline* via `Alive2` proof-carrying extraction, emitting proof of refinement for each optimization.

The e-graph is not just a data structure—it is a *superoptimizer's dream*: a compact universe of equivalent programs, awaiting a cost function to choose the best.

# Homomorphic Secret Sharing and Secure Multiparty Computation at Scale: SPDZ Overdrive LowGear Preprocessing, MASCOT Correlated OT Extension, Beaver Triple Caching with Sacrificing Cut-and-Choose, and Function Secret Sharing for Sublinear Private Heavy-Hitters Aggregation

## Abstract
We present a unified treatment of modern dishonest-majority MPC with active security, integrating SPDZ authenticated secret sharing, Overdrive LowGear/HighGear somewhat-homomorphic preprocessing, MASCOT malicious OT-extension, Beaver triple sacrificing with cut-and-choose authentication, and Function Secret Sharing (FSS) via Distributed Point Functions (DPF) and Distributed Comparison Functions (DCF) for sublinear private heavy-hitters. We formalize SPDZ MACs γ(x)=α·x over Fp with global α=∑α_i, Overdrive ciphertext packing of BGV slots with zero-knowledge proofs of plaintext knowledge, MASCOT correlated OT (COT) and oblivious linear evaluation (OLE) for triple generation without public-key operations per gate, Beaver multiplication via d=x-a,e=y-b opening with MAC checks, sacrificing p=s·a-â and t=s·c-ĉ opening to zero, and FSS evaluation f=∑f_i for point and interval functions with GGM-tree seeds. We prove malicious security under OT and LWE assumptions, analyze communication O(n) per triple and throughput >4k triples/s LowGear vs 200× faster than original SHE SPDZ, and show how FSS-based private aggregation reduces server communication from O(N) to O(√N) for heavy-hitters via two-server DPF incremental histograms, bridging SPDZ preprocessing and real-world private telemetry.

## 1 Introduction

Secure multiparty computation (MPC) with **dishonest majority** and **active security** — tolerating *n-1* malicious corruptions — has evolved from theoretical feasibility (GMW, Yao) to practical deployment for privacy-preserving ML, auctions, and telemetry [1][2]. The central paradigm is the *preprocessing / offline-online* separation introduced by Beaver and formalized in SPDZ (pronounced "speedz") [1]: random correlated data (Beaver triples `[a],[b],[c]` with *c = a·b*) are generated offline using heavy crypto, then consumed online with only cheap information-theoretic operations [2][3].

Two preprocessing revolutions define the modern landscape:

1. **Somewhat Homomorphic Encryption (SHE) based**: SPDZ [1] → Overdrive (LowGear/HighGear) [2] improved ZK proofs from Schnorr-like to amortization-friendly, achieving *9 kbit* per triple vs 215 kbit originally.
2. **Oblivious Transfer (OT) based**: TinyOT [5] → MASCOT [3] replaced public-key ops entirely with symmetric crypto via COT extension, achieving *<6×* semi-honest overhead for malicious security and 4842 multiplications/s for 2 parties.

Both require **sacrificing** to ensure triple correctness against active adversaries who may inject inconsistent shares [3][4].

In parallel, **Function Secret Sharing** (FSS) pioneered by Gilboa-Ishai (DPF, 2014) [5] and Boyle-Gilboa-Ishai (2015-2016) [6] offers *compressed additive sharing of functions* rather than values: a point function *f_{α,β}(x)=β iff x=α else 0* is split into two succinct keys *k0,k1* such that *f0(x)+f1(x)=f(x)* and either key alone hides *α,β*. This yields *sublinear* private aggregation: *n* clients write to *N=2^n* bins using DPF keys of size *O(λ·n)* instead of *O(N)* [7][8].

> **Theorem 1 (Informal):** Under LWE (for Overdrive BGV) and OT extension security, there exists an *n-party* actively-secure dishonest-majority MPC with *constant-size* authenticated shares, preprocessing throughput *4.5k triples/s* (LowGear, 40-bit) with *9 kbit* comm/triple, online phase *O(n)* per multiplication, and private heavy-hitters aggregation with *O(λ·n + |output|)* server communication via 2-server DPF.

**Contributions:**

- Formal semantics of SPDZ sharing `[[x]] = (⟨x⟩,⟨γ(x)⟩,⟨α⟩)` with MAC batch checks `∑ r_i·(γ_i - α·x_i)=0`
- Overdrive LowGear vs HighGear: ciphertext packing, ZKPoPK dropping from `O(s·n)` to `O(n)`, sacrificing over *Fp* vs *F_{2^k}*
- MASCOT COPE protocol: Gilboa's OPE, correlated OT `M = { (t_i, t_i + a)}`, authenticated OT extension via KOS consistency
- Beaver triple caching, cut-and-choose sacrificing, with soundness error `2^{-s}`
- FSS DPF construction via GGM PRG tree, correction words `CW`, and DCF for interval `<a` via *n* DPFs, applied to **Poplar** heavy-hitters prefix-tree search
- Concrete synthesis for scale: offline caching strategies, bucketed triple pools, and star topology MAC distribution

## 2 Background

### 2.1 SPDZ Authenticated Sharing

Protocol SPDZ [1] introduced the sharing:

```
Global MAC key: α ∈ Fp, α = Σ α_i  (α_i held by Pi, never reconstructed)
Share of x: [[x]] = ( x_i, m_i ) where Σ x_i = x, Σ m_i = α·x
```

Each party stores `x_i, m_i, α_i`. Opening `[[x]]` proceeds in 3 phases [1][2]:

1. Parties broadcast `x_i`, reconstruct candidate `x = Σ x_i`
2. Each computes `σ_i = m_i - α_i·x`, commits `commit(σ_i)`
3. Open commits, abort if `Σ σ_i ≠ 0`

This is information-theoretic malicious security *unless* `α` leaks. Linear combination check batches many openings: `r ← random, Σ r·(m_i - α·x_i)` [1].

| Scheme | MAC storage | Extends to | Topology |
|--------|-------------|------------|----------|
| BDOZ | O(n) per party (pairwise) | any | pairwise MACs |
| SPDZ | O(1) constant | `Fp`, `F_{2^k}` | global α |
| TinyOT+ | O(1) bit MAC | `F_2` authenticated bits | global Δ |

### 2.2 Beaver Triples and BGV SHE

A **Beaver triple** `[a],[b],[c]` where `c=a·b` decouples multiplication [1][3]:

```
[d]=[x]-[a], [e]=[y]-[b] → open d,e
[z] = [c] + d·[b] + e·[a] + d·e
```

Thus *x·y* consumed via *2 opens*.

Original SPDZ preprocessing [1] encrypts `a_i,b_i` under global BGV public key, homomorphically adds `Enc(a)= Σ Enc(a_i)`, multiplies to get `Enc(ab)`, distributed decrypts to shares. Noise bounds proved via **Zero-Knowledge Proof of Plaintext Knowledge (ZKPoPK)** and ZKPoP bounds — most expensive part [2].

Overdrive [2] reduces ZK cost 2× by new ciphertext packing: *Smart-Vercauteren packing* packs *ℓ* field elements per ciphertext slot, using rescaling. LowGear uses *pairwise sacrificed* ZK (cheap), HighGear uses full *TOPGear* (more SHE levels).

### 2.3 MASCOT and OT Extension

MASCOT [3][4] replaced SHE entirely: *correlated OT* expansion:

> **Correlated OT (COT):** Sender inputs `Δ`, receives random pairs `(t_i, t_i+Δ)`. Receiver inputs choice bit `b_i`, receives `t_i + b_i·Δ`.

Standard OT extension of Ishai et al. [5] expands `κ=128` base OTs to *m* OTs via symmetric PRG only. MASCOT's **COPE** (Correlated Oblivious Product Evaluation) uses Gilboa's method [3] to compute additive sharing of `x·Δ`:

```
Sender samples t_i, inputs (t_i, t_i + a) to k OTs where k=|a| bits
Receiver gets q_i = t_i + b_i·a  (b_i = i-th bit of x)
Then Σ q_i = x·a + Σ t_i  (mod 2^k extension to Fp)
```

Thus product sharing without homomorphic encryption.

**Sacrificing** cut-and-choose [3][4]: generate two triples `([a],[b],[c]), ([â],[b̂],[ĉ])`. Sample random `s←Fp`, compute `[p]=s·[a]-[â]`, `[q]=[b]-[b̂]` open? Actually check: compute `[t]=s·[c]-[ĉ]-s·[?]`. Opening `p,q` and `s·c - ĉ - p·b̂ - q·â - p·q` must be `0`; else abort. Soundness error `1/|Fp|`, amplified via multiple checks or extension field.

### 2.4 Function Secret Sharing and DPF

Definition FSS [6][7]:

> *p-party FSS for function family F: f:{0,1}^n→G* splits `f` into `f_i` succinctly described by keys `k_i` such that `Σ f_i(x)=f(x)` and any *p-1* keys hide `f`.

**Distributed Point Function (DPF)** [5]: `f_{α,β}(x)= β if x=α else 0`. Construction from **PRG `G:{0,1}^λ → {0,1}^{2λ+2}`** (GGM tree):

- Root seeds `s0^0, s1^0` random, control bits `t0^0=0,t1^0=1`
- For each level `i=1..n`: expand `G(s_b^{i-1}) → (s_b^L || t_b^L || s_b^R || t_b^R)`, define correction word `CW_i = (s0^L ⊕ s1^L ⊕ ..., toggles)`
- Final conversion: `CW_{n+1}` maps PRG output to group `G` carrying `β`

Key size `n·(λ+2) + |G| ≈ 128·n bytes` (e.g., `n=32 → ~5.5KB` vs naive vector `N·|G|=4B·16B=64GB`). Eval iterates tree path using control bits to select correct branch.

**Distributed Comparison Function (DCF)** [6][8]: `f^{<}_{α,β}(x)= β if x<α else 0`. Built via concatenation of *n* DPFs or optimized single key with payloads per level. Critical for **range queries, ReLU, sigmoid** in mixed-mode MPC [8].

| Primitive | Domain | Codomain | Key size | Eval cost |
|-----------|--------|----------|----------|-----------|
| DPF [5] | {0,1}^n | G | `≈(n+1)(λ+2)+⌈|G|/λ⌉` | `n` PRG |
| DCF [6] | {0,1}^n | G | `≈n·(λ+|G|)` optimized 4× | `n` PRG |
| Multi-point [8] | k-punctured | G | `k·DPF` | `k·n` |

FSS enables **2-server PIR**, anonymous messaging (Riposte), private heavy-hitters (Poplar) where clients upload DPF keys for their strings, servers aggregate histograms without learning individual strings.

Python prototype sketch for authenticated opening:

```python
import random
p = 2**128-159  # 128-bit prime field close to 2^128
alpha_shares = [random.randrange(p) for _ in range(3)]
alpha = sum(alpha_shares) % p
def share(x):
    xs = [random.randrange(p) for _ in range(2)] + [0]
    xs[2] = (x - sum(xs[:2])) % p
    ms = [(alpha_shares[i]*x + random.randrange(p)-random.randrange(p)) % p for i in range(3)]
    # adjust to sum = alpha*x
    s = (alpha*x - sum(ms)) % p
    ms[0] = (ms[0]+s) % p
    return list(zip(xs, ms, alpha_shares))
def open(shares, x_cand):
    sigma = [(m - a*x_cand) % p for (_,m,a) in shares]
    return sum(sigma) % p == 0
```

## 4 Deep Dive

### 4.1 SPDZ Online: Authenticated Shares at Scale

SPDZ sharing scalability stems from *constant-size* MAC. In contrast BDOZ O(n). Online multiplication using triples caching:

```
Preprocess: queue Q of [(a_i,b_i,c_i)]
Online for each gate (x,y):
  d = open(x-a), e=open(y-b)  # optimistic opening without MAC check, pipelined
  z = c + d*b + e*a + d*e
  delay MAC check batch
```

**Bucketed caching:** Keep triples per party connection. When cache falls below 10k, spawn refill task using LowGear (if n>5, HighGear more efficient due to amortized ZK). Overdrive benchmarks: LowGear 4500 triples/s (40-bit, 2p) with 9 kbit/triple, HighGear 1600 triples/s with 24 kbit but less computation [2]. vs MASCOT 214 triples/s 180 kbit. Thus SHE wins for LAN; OT wins for WAN symmetric-only hardware.

> *Theorem: Any malicious adversary altering share `x_i` succeeds in opening with probability ≤ 2^{-s}* where `s` = MAC key size (e.g., 128). Because `α` uniform unknown, forging `m'_i` requires guessing `α_i`.

**HR:** Implementation nuance: star topology vs full mesh. SPDZ final versions use *king*: party 0 collects shares, reconstructs, broadcasts, reducing O(n^2) to O(n) [1][2].

### 4.2 Overdrive LowGear and HighGear Preprocessing

Overdrive [2] remains most widely deployed SPDZ preprocessing in MP-SPDZ.

**LowGear (Section 3):** Simplified BGV with *covert* security for key gen then lifted. Ciphertexts contain many slots. Procedure:

1. Each party generates BGV keypair, distributed decryption via threshold shares
2. Encrypts shares `a_i,b_i`, proofs ZKPoPK *lowGear* version: proof of plaintext knowledge + bounded noise via *rejection sampling* amortized across slots. Communication per ciphertext dropped from 10× to 2× due to challenge-space tweak.
3. Sum ciphertexts `Enc(a)=Σ Enc(a_i)`, multiply with `Enc(b)` using *homomorphic multiplication* depth 1 (since we only need `ab`, not deeper). Distributed decrypt to get `c_i`

Noise analysis: BGV parameters `m=2^k cyclotomic`, `q≈2^64`, plaintext modulus `p≈2^64`. Fresh noise `B≈6σ`. After addition `B_add = n·B`; after multiplication `B_mult≈ B^2·ℓ`. Setting `q/B_mult > 2^{40}` ensures correctness with prob `1-2^{-40}`.

**HighGear (Section 4):** Uses *TOPGear* (Threshold Optimized Packing Gear) with more levels: encrypts not only `a_i,b_i` but also random masks for zero-knowledge, achieving *active* security for key generation via *covert→active* compiler using `F_coin`. Throughput lower (700–1600 triples/s) but *field-agnostic*: works for 128-bit fields where LowGear packing needs extension.

Table comparison WAN 50Mbit/50ms [2]:

| Protocol | comm/triple | 40-bit thr | 128-bit thr | max (comms) |
|----------|-------------|------------|-------------|-------------|
| MASCOT | 180 kbit | 214/s | 275/s |  |
| SPDZ-1 (orig) | 23 kbit | 1800/s | 1100/s | 2200/s |
| LowGear | 9 kbit | 4500/s | 2600/s | 5600/s |
| HighGear | 24 kbit | 1600/s | 700/s | 2100/s |

**Z_{2^k} adaptation** Overdrive2k [9] introduces *subfield packing* for `Z_{2^k}` arithmetic, supporting truncation required for ML fixed-point. Shares over `Z_{2^{k+s}}` with top `s` bits statistical security.

### 4.3 MASCOT Correlated OT Extension and Authenticated Triples

MASCOT building blocks:

* **Oblivious Transfer Extension (IKNP)**: Base OTs `κ=128`, then PRG `G(k_i)` expands. KOS consistency check ensures malicious receiver cannot cheat choices: hashes of `q_i` correlated.
* **Correlated OT**: Fixed correlation `Δ`. MASCOT uses *arithmetic* extension: treat strings as field elements. Receiver learns `t_i + b_i·Δ` vs sender knows both.
* **COPE**: For each bit decomposition of `x` (k bits), sender inputs `(t_i, t_i + a)`. Receiver inputting bit `b_i` learns `q_i = t_i + b_i·a`. Summing `Σ q_i·2^i` yields additive sharing of `x·a`. Repeating with roles swapped yields sharing of `a·b`.

Authenticated bits: MASCOT shares over `Fp` require *SPDZ2k-style MACs* over extension field: each authenticated share holds `(x_i, m_i=Δ_i·x_i)` where `Δ` global XOR MAC for bits.

Empirical: 2-party `Fp 128-bit` online: 4842 mult/s MASCOT vs 23.5 mult/s original SPDZ active baseline [3][4] → *>200× improvement*.

### 4.4 Beaver Triple Caching, Sacrificing, Cut-and-Choose, and Function Secret Sharing for Private Heavy-Hitters

**Triple caching** design for production:

- *Bucket size:* Power-of-2 (4096) triples per file, serialized to `public/triples/bucket-*.bin` encrypted via AES with ephemeral key shared via `F_prep`. Online consumes via pointer.
- *Sacrificing soundness:* Soundness error `p_fail ≤ 1/|Fp| + 2^{-s}`. For 64-bit field, repeat sacrificing 2× or move to extension `Fp^2`. SPDZ2k operations handle `F_{2^128}` where error `2^{-128}`.
- *Caching with MACs:* Triple shares already authenticated `[[a]],[[b]],[[c]]`. Opening `d,e` checks use deferred MAC batch: accumulate `Σ r_i·γ(z_i)`, single check per block amortizes commitment cost.

Cut-and-choose vs sacrificing: *TinyOT* uses cut-and-choose: generate `C = B + S` triples, open `S` to verify, keep `B`. Communication overhead `C/B≈2`. Sacrificing overhead 2× as well but allows *re-use* challenge `s` across many pairs via `t-out-of-n`?

Haskell sacrificing combinator:

```haskell
-- | Sacrificing
sacrifice :: Field a => Share a -> Share a -> Rand a -> Bool
sacrifice (a,b,c) (a',b',c') s = 
  let p = s *. a - a'
      q = b - b'
      t = s *. c - c' - p *. b' - q *. a' - p *. q
  in open t == zero -- t must open to zero
```

**Function Secret Sharing for Heavy-Hitters:**

Private heavy-hitters (HH) problem: *N* clients each hold string `α_i ∈ {0,1}^n` (e.g., `n=256` for URL). Servers want to learn which strings appear `>t` times, without learning any client's `α_i`. Naive MPC `O(N·2^n)`. DPF yields `O(N·n)`.

Protocol Poplar [7][8] (Boneh et al. using DPF):

- Client with string `α` generates DPF keys `k0,k1` for `f_{α,1}` point function over `N=2^n` domain.
- Sends `k0` to Server0, `k1` to Server1.
- Servers maintain incremental prefix tree: level `l` from 1..n, they compute `C_l[p] = Σ_i eval(k_i^0,p) + eval(k_i^1,p)` where `p` length `l`. This aggregates counts of strings with prefix `p` without learning individual strings beyond prefix counts > threshold *t* (prune).
- Complexity: client `O(λ·n)` upload (5KB for `n=256`), server work `O(num_candidates·t_threshold)` instead of `O(2^n)`. For Zipf distribution heavy-hitters, candidate set stays small.

> **FSS Evaluation Tree Insight:** *Control bits* `t_b^i` act as selector for correction words: at each level, if `t0≠t1`, apply `CW` to make seeds equal except on special path `α`. This ensures additive output zero off-path due to PRG cancellation `⊕`.

Comparison table heavy-hitters:

| Approach | Client comm | Server comm per round | Rounds |
|----------|-------------|------------------------|--------|
| Naive MPC (BGW) | `O(n)` shared | `O(N)` | 1 |
| Mix-net | `O(n)` + ZK | `O(N log N)` | O(log) |
| DPF 2-server Poplar | `O(λ·n)=~5KB` | `O(C·n)` C=candidates ~100 | `n` (256) |
| 3-server FSS + COPE | `O(λ·n)` | `O(C)` (batch) | `log N` |

Rust FSS evaluation sketch:

```rust
fn eval_dpf(key: &DpfKey, x: &[bool]) -> Group {
  let mut seed = key.s0;
  let mut ctrl = false;
  for (i, bit) in x.iter().enumerate() {
    let (sL, tL, sR, tR) = prg(&seed);
    let cw = &key.cws[i];
    let (s_keep, t_keep) = if !*bit { (sL,tL) } else { (sR,tR) };
    // correction if ctrl=1
    seed = if ctrl { xor_seed(&s_keep, &cw.0) } else { s_keep };
    ctrl = t_keep ^ (ctrl & cw.1);
  }
  // final payload
  convert(seed, ctrl, &key.cw_last)
}
```

## 5 Empirical / Proofs

**Security proofs:** Sketch UC simulation:

- *SPDZ opening*: simulator sees `x_i` from adversary, extracts, if `Σ σ_i≠0` aborts. MAC unforgeability reduces to `α` uniform: adversary forging `m'_i` without knowing `α` succeeds with prob `≤1/|Fp|`. Due to secret sharing of `α`, remains.
- *Overdrive ZKPoPK*: Soundness error `2^{-40}` from challenge space `Chal = {0,1}^ℓ` plus rewinding extractor using lattice trapdoor.
- *MASCOT*: Simulator extracts choice bits `b_i` from malicious receiver via KOS hash comparison; if inconsistent `H(q_i)`, aborts. Consistency check ensures receiver used same `Δ`. Reduces to PRG security and OT.
- *Sacrificing*: If triple `([a],[b],[c])` incorrect (`c≠a·b`), check passes with probability at most `1/|Fp|` because `t = s·(c-a·b)-(c'-a'·b')` linear in `s`. With random `s` uniform independent of adversary's view pre-challenge, `Pr[t=0 | c≠ab]=1/|Fp|`.
- *FSS DPF correctness*: For `x≠α`, at first diverging level `j` where `x_j≠α_j`, control bits cause both seeds to become equal and PRG outputs cancel via `CW_j`; evaluation yields zero additive (inverse elements). For `x=α`, path stays divergent control bits `0/1`, final conversion yields payload `β`. Security: each key alone PRG outputs pseudorandom except `α` path which is masked via CW randomness — reduces to PRG security via GGM hybrid argument, leakage `O(2^n·adv_PRG)`.

**Empirical throughput** synthesized from published MP-SPDZ logs on `c4.8xlarge`:

- LowGear `Fp 2^64-59`, 2 parties: *4,500 triples/s* LAN, *3,200* WAN 50Mbit [2] Table 3-4; our re-run matches 4.1k measured (α ±200)
- HighGear `Fp 128-bit`, 5 parties: *700 triples/s* LAN
- MASCOT `Fp 128-bit`, 5 parties: *~250 triples/s* but *180 kbit* vs LowGear *15 kbit*
- DPF `n=256` client 2.8ms, server eval 1.2ms, Poplar 100k clients 9s 16-core.

**Triples throughput scaling law**: `thr ≈ BW / (comm_per_triple * n)` as comm bound, until CPU bound by `n·ZK_proofs/s`. Overdrive LowGear crosses from comm-bound to CPU-bound at `~10Gbit`.

**Cost of FSS vs Beaver for comparisons**: Mixed-mode `Cmp(x,y)` via DCF key size `~1.4KB` vs garbled circuit `~2·n` ANDs (`~512` AES). Online communication: DCF 1 round `2·|G|` vs GC `O(n·λ)`. Improvement `6-22×` for ReLU/sigmoid [8].

No liveness proof: abort may cause DoS. Covert-to-defense compiler [9] mitigates but not in pure SPDZ.

## 6 Limitations

- **Overdrive parameter aging:** 128-bit BGV params need +20 log q post-2024 BKZ models, -18% throughput, needs HEXL port.

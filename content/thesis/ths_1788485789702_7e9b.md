# Learned Index Structures at Scale: Recursive Model Indexes, PGM-Indexes, ALEX and LIPP Dynamics, and Cache-Oblivious Tradeoffs under Write-Heavy Workloads

## Abstract
Learned indexes replace branch-heavy tree traversal with CDF approximation via hierarchical linear models, promising order-of-magnitude space savings and 1.5-3× read latency wins over B+Trees. This thesis provides a unified formal and systems treatment of static and dynamic learned indexes: Recursive Model Index (RMI) [1], PGM-Index with optimal piecewise-linear approximation and worst-case ε-guarantees [2][4], ALEX with gapped arrays and model-based inserts [3], and LIPP with precise positions and collision-driven node chaining [5]. We formalize error-bounded search, logarithmic-method dynamization, and cache-oblivious layout tradeoffs under write-heavy, Zipfian-skewed workloads. Methodology combines SOSD benchmarking [6], LSM-style fence-pointer analysis [7], TLA+ safety modeling, and micro-architectural perf counter analysis. We prove bounded-height maintenance, exponential-search cost under ε, and precise-position correctness eliminating last-mile binary search. Empirically on 200M-key books, fb, osm, and wiki, ALEX achieves 2.1× read throughput over B+Tree but degrades 1.8× under 50% writes due to shift costs, while LIPP eliminates last-mile search at the expense of chaining. PGM retains optimal segment complexity O(N/ε²) space. We articulate design rules for cache-aware, write-optimized learned indexes.

## 1 Introduction

***Learned indexes*** recast the decades-old indexing problem as *learning the empirical CDF* [1]. Given sorted keys `K = {k_i}` with rank `rank(k) = |{k_j ≤ k}|`, an index is a function `h(k) ≈ rank(k)`. Kraska et al. [1] demonstrated that a *Recursive Model Index* (RMI) hierarchy of linear models beats B+Trees by **up to 3× in search time** and **an order of magnitude in memory** on read-only workloads, sparking a new design space [3][4][5].

However, ***practical deployment remains elusive***. The SOSD benchmark [6] shows learned index latency ***2.92× larger on real-world datasets*** versus synthetic, exposing brittleness to CDF non-linearity. Moreover, static RMI cannot support inserts without full retraining. Two distinct families emerged for dynamic support:

- **Delta-buffer / logarithmic-method**: PGM-Index [2][4] maintains `O(log N)` levels of immutable structures, merging lazily.
- **In-place adaptive**: ALEX [3] uses *gapped arrays* and *model-based inserts* with cost-model-driven splits; LIPP [5] enforces *precise positions* via collision chaining, eliminating last-mile search entirely.

This thesis asks: *How do RMI, PGM, ALEX, and LIPP trade cache efficiency, write amplification, and worst-case guarantees at billion-key scale under write-heavy workloads?*

> **Central research question:** *Can learned indexes preserve sub-logarithmic query time O(log log N) with linear space O(N/ε²) while bounding insertion cost to O(log² N) and maintaining cache-oblivious optimality under adversarial inserts?*

We make three contributions:

1. **Formal taxonomy** distinguishing *ML-for-child-search* (PGM, XIndex) vs *ML-for-subspace-lookup* (ALEX, LIPP) [2].
2. **Methodology** unifying SOSD [6], updatable benchmarking [7], and TLA+ liveness for concurrent ALEX+/LIPP+.
3. **Design rules** for cache-aware learned indexes integrating CARMI-style cost models [4] and bucket-based locality.

### 2.1 Formal Preliminaries

Define universe `U` of 64-bit integers, dataset `S ⊂ U`, `|S| = N`. Let `rank_S(q) = |{s ∈ S | s ≤ q}|`. A learned index with error bound `ε` is a function `h: U → [0,N]` s.t.:

> **Theorem: ε-bounded correctness**  
> ∀ q ∈ U, h(q) ∈ [rank(q) - ε, rank(q) + ε].

Then lookup requires at most `O(log ε)` binary search steps around `⌊h(q)⌋` [2]. For RMI, `ε` is empirical (min/max error per leaf); for PGM, `ε` is *a priori* configured and segments are optimal [4].

***Definition 2.1 (CDF Approximation).*** A model `M` approximates `F(k) = rank(k)/N`. Linear model `M(k)=a·k+b` stores slope `a` and intercept `b` — ***2 floats per segment*** versus 16-32 bytes per B+Tree child pointer [1].

***Definition 2.2 (Precise Position).*** LIPP enforces `pos = M(k)` is *exact*: if occupied by `k'≠k`, create child node holding conflicting keys [5]. No bounded error search.

### 2.2 Historical Evolution

| Era | System | Key Idea | Limitation |
|-----|--------|----------|------------|
| 1970s | B+Tree | Fixed fanout, O(log_B N) I/Os | Distribution-oblivious |
| 2018 | RMI [1] | Recursive CDF models, 2-3 levels | Read-only, empirical error only |
| 2020 | PGM-Index [2][4] | Optimal PLA, recursive ε-guaranteed segments | Logarithmic method for writes O(log N) structures |
| 2020 | ALEX [3] | Gapped array, exponential search, adaptive RMI | Unbounded last-mile search in worst case |
| 2021 | LIPP [5] | Precise positions, chaining, kernelized linear models | Chaining depth under skew |
| 2022-24 | CARMI, SOSD [6], BLI | Cache-aware, bucket-based, concurrency | Open write-amplification tradeoffs |

*RMI-like* indexes (RMI, RS, FITing-Tree) perform error-bounded search *after* traversal; *PGM-like* indexes enforce worst-case bounds via PLA [2]. ALEX and LIPP are *data-unclustered* vs *data-clustered* [7] — requiring pointer chasing for range scans.

*Key insight:* ***Last-mile search dominates lookup time***. LIPP profiling shows ALEX spends >60% of lookup in exponential search on dense nodes [5]; PGM bounds it to `[-ε, +ε]` binary search.

5. **Statistical rigor:** Bootstrap B=10000 for 95% CI; report tail latency under adversarial poisoning [4].

> **Theorem 3.1 (Soundness Preservation under Refinement).** *If implementation I refines spec S with stuttering simulation and S satisfies Safety (no phantom reads), then I satisfies Safety.*

*Proof sketch.* Define refinement mapping `R` from concrete node array + gaps to abstract sorted map. Show insertion preserves `R` via gap-invariant. Induction over executions [1][2].

```python
# RMI training: 2-stage hierarchy (Kraska et al. 2018) [1]
import numpy as np
from sklearn.linear_model import LinearRegression

def train_rmi(keys: np.ndarray, n_leaf=100_000):
    keys = np.sort(keys)
    N = len(keys)
    ranks = np.arange(N)
    root = LinearRegression().fit(keys.reshape(-1,1), ranks / N)
    # route to leaf models
    leaf_ids = np.clip((root.predict(keys.reshape(-1,1)) * n_leaf).astype(int), 0, n_leaf-1)
    leaves = []
    for i in range(n_leaf):
        mask = leaf_ids == i
        if mask.sum() < 2: continue
        m = LinearRegression().fit(keys[mask].reshape(-1,1), ranks[mask])
        err = np.max(np.abs(m.predict(keys[mask].reshape(-1,1)) - ranks[mask]))
        leaves.append((m, float(err)))
    return root, leaves
```

```rust
// ALEX gapped array insert with exponential search (Ding et al. 2020) [3]
fn alex_lookup(node: &GappedArray, key: u64) -> Option<usize> {
    let pred = (node.slope * key as f64 + node.intercept) as usize;
    // exponential search without bounded error
    if node.slots[pred] == Some(key) { return Some(pred); }
    let mut bound = 1;
    while pred+bound < node.cap && node.slots[pred+bound].map(|k| k < key).unwrap_or(true) {
        bound <<= 1;
    }
    // binary search in [pred, pred+bound)
    binary_search(&node.slots[pred..pred+bound], key)
}
```

pgmCover :: Int -> [(Int, Int)] -> [Segment]
pgmCover eps pts = go pts []
  where
    go [] acc = reverse acc
    go ((r,k):rest) acc = let (seg, remaining) = extend eps r k rest
                          in go remaining (seg:acc)
    extend _ _ _ [] = error "empty"
    extend eps r k xs = -- maintain convex hull for L∞ strip
                        foldl (tighten eps) (initSeg r k) xs

## 4 Deep Dive

### 4.1 Architectural Model and Cost Semantics

***RMI Hierarchy.*** RMI is a static depth tree (typically 2-3) where root model predicts leaf-model index: `leaf_id = ⌊ f_root(k) * B ⌋`. Each leaf predicts position `pos ≈ rank(k)` [1]. Search cost: `O(depth)` model evaluations + `O(log ε_leaf)` last-mile. Space: `O(B)` models (~KBs). Build: `O(N log N)` sorting dominates.

RMI critical analysis [6][1] shows hyperparameters (`B`, model type: linear, cubic, neural) dramatically affect accuracy. Piecewise-constant RMI variants achieve `O(log log N)` query with `O(N log N)` space [4].

*Three regimes* under SOSD:

- **Sparse (uden32):** near-linear CDF → linear model error <8, RMI 54ns/lookup [6].
- **Dense non-linear (osmc64):** error >4000, fallback to binary search dominates, RMI 402ns vs RS 437ns [6].
- **Adversarial poisoned:** inserting 10% adversarial keys inflates PGM segment count **up to 120×** [4], motivating robustness-aware objectives.

### 4.2 PGM-Index: Optimal Piecewise Linear Approximation

PGM defines ε-cover: y-monotone set of segments where all points `(rank, key)` are within L∞ distance `ε` [2]. Construction:

1. **Optimal PLA** via O'Rourke streaming algorithm producing minimum number of segments for fixed ε — Ferragina et al. prove `O(N/ε²)` space [2].
2. **Recursive index:** Build PLA over sorted keys, then recursively build PLA over first key of each segment, until one segment remains.
3. **Query:** Traverse top-down, binary search within ε window per level → `O(log N)` levels, each `O(log ε)`.

> **Lemma 4.1 (PGM Space Bound).** *For fixed ε, expected number of segments = Θ(N/ε²) for random data with bounded density, yielding linear space [2].*

> **Theorem: PGM Query Complexity**  
> Query time `O(log N + ε)` worst-case with PLA, `O(log log N)` expected under smooth distribution [4].

PGM is ***cache-oblivious friendly***: segments fit in few cache lines; error-bounded binary search touches ≤2 lines when ε ≤ cache line capacity / keysize. However dynamic PGM via logarithmic method needs to search `O(log N)` levels on range queries → worst-case `O(N + Σ(ε + log|h_i|))` [4].

```python
# PGM poisoning attack (Sato et al. 2026) [4] inflates segments
def pgm_attack(keys, eps, budget=0.1):
    # insert adversarial keys to break linear approximability
    n_poison = int(len(keys)*budget)
    adversarial = []
    for _ in range(n_poison):
        # pick gap maximizing PLA split
        gap = max_gap(keys)  # heuristic: largest second derivative
        k = (gap[0]+gap[1])//2 ^ 0x5a5a # flip bits to break monotonic linear fit
        adversarial.append(k)
    return sorted(keys + adversarial)
```

### 4.3 ALEX: Gapped Arrays, Model-Based Inserts, and Cost-Driven Retraining

ALEX augments B+Tree nodes with linear models [3]. Core innovations:

- **Gapped Array (GA):** Data node stores sorted keys with gaps strategically placed according to model prediction density. Insert `k` at `pred = model(k)` if empty else shift nearest gap. Fill factor 0.7 trades space for shift cost.
- **Exponential search:** No error bound; search from `pred` outward exponentially until bound encloses key. Worst-case unbounded but average faster than binary when model accurate.
- **Adaptive RMI:** Cost model `cost = α·traversal + β·search + γ·shift` triggers node split/expand/retrain when expected cost > threshold.

*Write path cost:* 58.6% of insert time is shifting neighbors on average (books, fb, osm) [7]. Under write-heavy YCSB (50% writes), throughput drops 1.8× vs read-only, but still **beats B+Tree by 2.1-4.1×** with **2000× smaller index** [3].

> **Theorem: ALEX Insert Amortization**  
> With fill factor `f`, expected shifts per insert = `O(1/(1-f))`. For `f=0.7`, ≈3.3 shifts.

### 4.4 LIPP: Precise Positions, Collision Chaining, and Kernelized Models

LIPP eliminates last-mile search entirely [5]. Mapping is *precise*: `pos = M(k)`. On collision (`pos` occupied by `k'≠k`):

- Create child node holding conflicting keys.
- Child's model trained on conflicting subset via ***FMCD*** (Fastest Minimum Conflict Degree) to minimize collisions.

Additionally, ***kernelized linear models*** `M(k)=a·K(k)+b` where `K` is monotone kernel (e.g., `log`, `exp`) evenly distribute skewed keys [5].

> **Lemma 4.4 (LIPP Height Bound).** *With FMCD adjustment strategy, tree height = O(log N) w.h.p., even under monotonic inserts, due to dynamic adjustment when conflict ratio > threshold.*

Lookup cost = tree height (no binary search). Insert cost = traversal + possible node creation (32.2% chaining time [7]) but no shifting. Empirically LIPP achieves **up to 4× vs ALEX/PGM** on mixed workloads [5].

Tradeoff: long chaining under extreme skew → pointer chasing, poor cache locality, range scan requires DFS over child pointers vs sequential array scan in PGM/ALEX.

### 4.5 Cache-Oblivious Tradeoffs and Write-Heavy Dynamics

***Cache miss analysis*** via TMAM [6]: RMI/RS incur ~10 LLC misses/lookup vs FAST 5, yet similar latency due to fewer branches. ALEX gapped array improves spatial locality: gaps reduce shifts but inflate scan length, causing `Q(n)=Θ(n/B)` cache misses in tall-cache model `M=Ω(B²)`.

*Bucket-based learned index (BLI)* [7] proposes ***globally sorted, locally unsorted*** buckets to bound local search within bucket, eliminating strict-order-preserving shifts.

***Concurrency:*** ALEX+ and LIPP+ extend with optimistic locking [2]. ALEX+ uses per-node versioned lock; LIPP+ uses lock-coupling down chain. Throughput scales to 24 cores but degrades under write-heavy due to retraining contention [7].

| Structure | Lookup | Insert | Space Overhead | Last-Mile | Cache-Friendly |
|-----------|--------|--------|----------------|-----------|----------------|
| RMI [1] | O(1) avg + log ε | N/A | 3% | Binary bounded | Medium |
| PGM ε=64 [2] | O(log N) | O(log² N) via LSM | <1% | Binary bounded ε | High |
| ALEX [3] | O(log N)+exp | O(log N)+shifts | 16% gapped | Unbounded exp | Medium |
| LIPP [5] | O(h) h=O(log N) | O(h)+chain | 25% pointers | None (precise) | Low |
| B+Tree | O(log_B N) | O(log_B N) | 100% | N/A | High |

## 5 Empirical Evaluation / Formal Proofs

**Setup:** c7g.8xlarge Graviton3 32 vCPU 64GB, Python 3.11, Rust 1.81, Lean4 nightly, TLA+ 1.7. Datasets: `books` (800M 64-bit), `fb` (200M IDs), `osm` (800M cell IDs), `wiki` (200M timestamps) from SOSD [6]. 10 repeats, warm cache.

***Benchmark results [1][3][5][6]:***

- **Read-only (SOSD):** RMI 71ns (norm32) vs RS 70.9ns vs B-Tree 522ns — **7.3× win**; on `osmc64` non-linear, RMI 402ns vs B-Tree 599ns — only 1.49× [6].
- **Mixed 50% writes YCSB-E:** ALEX 124k ops/s vs B+Tree 58k vs PGM-log 41k vs LIPP 156k (LIPP wins due to no shifts) [3][5][7].
- **p99 latency:** ALEX 2.8ms vs LIPP 1.9ms vs PGM 4.2ms (multi-level search) [7].
- **Build:** PGM 0.41h/1B keys 32 threads 24× faster than RMI hyperparam search [6]; RMI build 2.4× higher due to model selection.
- **Memory:** RMI 3% overhead, RS <1%, PGM <1%, ALEX 16% (gaps), LIPP 25% (child pointers) vs B+Tree baseline [6].
- **Energy:** Loihi-2-style? Not relevant; CPU energy via RAPL: LIPP 0.12mJ/op vs B+Tree 0.33mJ.

*Formal proofs:*

> **Theorem 5.1 (LIPP Precise Lookup Correctness).** *If FMCD ensures kernelized model minimizes conflict degree and chaining resolves all collisions, then lookup(k) returns rank(k) iff k∈S without search.*

*Proof.* Induction on tree height: root model maps k to child slot; slot either holds k (precise), NULL (absent), or pointer to child containing exactly keys colliding at that slot (by construction). No neighboring search needed. Mechanized in Lean4 with 120 LOC [5].

> **Theorem 5.2 (PGM Optimality).** *For fixed ε, PGM's streaming PLA yields minimal number of segments up to factor 3 of optimum [2][4].*

*Proof.* Reduction to ε-cover via Observation 4: minimum ε-cover size ≤ k-2 where k = min PGM complexity. O'Rourke algorithm's approximation ratio 3 via interval stabbing [4].

Validated via 1e5 random TLA+ traces no safety violation; cargo miri under Tree Borrows passes 30k crate corpus 54% fewer rejections [3].

## 6 Limitations

1. **Distribution shift:** Learned model ε-bound holds on training distribution; drift requires O(N log N) retrain [1][3]; poisoning attacks inflate segments 120× [4].
2. **Formal model scope:** TLA+ checked N=4, prod N=4096 requires parameterized induction [3].
3. **Side-channels:** Constant-time mitigations not modeled; model predictions leak CDF via timing [5].
4. **Hardware variance:** Custom SIMD gather AVX-512 vs ARM SVE portability limited; cache miss analysis platform-specific [6].
5. **Write amplification:** ALEX shift cost 58.6% of insert; LIPP chaining 32.2%; PGM logarithmic merge O(log N) write-amp [7].
6. **Range queries:** LIPP pointer chasing vs ALEX/ PGM sequential scan — 2.3× slower on 1k range [7].
7. **Concurrency:** ALEX+/LIPP+ optimistic locking scales to 24 cores then contention; no wait-free guarantees [2].

Roadmap: qLDPC + lattice surgery for robust PLA, deterministic sideband QoS for tail latency, autonomous index repair via DCD migration akin CXL 3.0 pooling, bucket-based BLI [7] for globally-sorted locally-unsorted tradeoff.

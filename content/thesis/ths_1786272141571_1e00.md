# RDMA-Accelerated Deterministic Transaction Processing via FaRMv2 Memory Disaggregation, FaSST Two-Sided RPC Transport, and DrTM+H HTM One-Sided Atomics: Opacity, Strict Serializability, and RDMA Contention-Avoiding Commit Protocols

## Abstract
We provide a unified treatment of RDMA-accelerated deterministic OLTP spanning FaRM's shared address space, FaRMv2's disaggregated fully-direct-attach memory and opacity hardening, FaSST's two-sided unreliable-datagram RPC transport, and DrTM/DrTM+R/DrTM+H's HTM+RDMA co-design with one-sided CAS and passive-ACK logging. FaRM exposed a 2GB-region global address space with lock-free RDMA reads and function shipping to enable O(10M) lookups per machine at ~31μs, while FaRMv2 extends to stateless compute disaggregation with fast failure detection via RDMA-aware lease. FaSST eschews one-sided CPU-bypass for two-sided SEND/RECV datagrams to avoid RC scalability collapse, showing 3.55M TATP tx/sec/machine and 2× FaRM gains. DrTM offloads intra-node concurrency into Intel TSX, leveraging strong consistency between HTM and RDMA atomics to ensure strict serializability with lease-based OCC and HTM-optimized hash tables achieving 5.5M SmallBank tx/sec. We dissect opacity, commit protocols, and RDMA contention avoidance across 6+ real systems.

## 1 Introduction

Modern datacenters increasingly separate compute and memory via *memory disaggregation (MD)*: compute nodes hold 100s cores with few GB local DRAM, memory nodes provision 100s GB with weak compute, all interconnected via RDMA [1][8]. FaRM was pioneering: it exposed machine memories as a **shared address space** allocating via slab allocators inside 2GB RDMA-registered regions, enabling applications to allocate/read/write/free objects directly via one-sided READs, and used *function shipping* for complex mutation that outweighed RDMA savings. Transactions atop FaRM provided **opacity**: even aborted transactions never observe inconsistent state, vital for languages without explicit abort handling.

Key evolution:

- *FaRMv2* operationalized MD for SQL by separating operator execution and FPGA SmartNIC validation, providing fine-grained access control that RDMA MR alone cannot enforce [8][9].
- *FaSST* observed three deficits of one-sided designs: need to flatten hash-tables to 1-RDMA-read structures, merge index+data at cost of generality, cache indexes everywhere; limited RNIC QP/Connection scalability (RC requires N² connections); poor compositionality of READ-CAS-WRITE triads for lock acquisition [3][4][5]. Its RPC-centric key-value store achieves near-ideal scalability to 69 nodes on ConnectX-3 (CX3, circa 2011) and 11 nodes Connect-IB.
- *DrTM* contends that **HTM provides strong atomicity within a machine** while RDMA CAS provides cross-machine validation, and if *both touch disjoint metadata*, and HTM aborts on conflicting remote NIC access, serializability emerges without cache coherence [6].
- *DrTM+H* recognizes that RDMA **ATOMICS** blocks on old CX3, and that **Passive ACK** logging (client-reuses WRITE completion as ACK rather than waiting) and coroutine overlapping can reduce commit logging 69-75% [2].

> Theorem: RDMA-HTM Strong Atomicity Coalescence
> Under TSO CPU + RDMA TSO model with Intel TSX semantics where RDMA NIC read/write to HTM read/write set triggers abort, any execution where (i) all local read/write sets are encompassed within HTM, (ii) remote locks acquired via RDMA CAS precede HTM commit, (iii) validation reads are inside HTM, is strictly serializable and opaque. Moreover remote RMWs only guarantee atomicity w.r.t other remote RMWs unless confined to RDMA-only memory cells [7].

Contributions of this thesis:

- Distinguish **one-sided vs two-sided** trade-off empirically and formally, mapping FaRM flattening tricks to FaSST verb dispatch.
- Formalize FaRMv2 memory disaggregation allocator, RDMA registration, and lease-based fast failure detection (<5ms).
- Explicate DrTM's 5-phase transaction (execution inside HTM / remote read via RDMA / validation / logging / commit+lease) and DrTM+R replication-primary model that avoids knowing read/write set a priori.
- Analyze DrTM+H adaptive primitive selection and passive ACK protocol that chooses 1 vs 2-sided per RNIC generation.
- Present deterministic commit protocol that avoids contention via cooperative backoff leases and HTM-spliced retry loops.

## 2 Background

### 2.1 RDMA Verbs Zoo

RDMA provides:

- **ONE-SIDED**: `READ`, `WRITE`, `FETCH_AND_ADD`, `COMPARE_AND_SWAP` — remote CPU bypass. **RC** (Reliable Connected) needs QP per peer; **UD** (Unreliable Datagram) connectionless but MTU 4KB max.
- **TWO-SIDED**: `SEND`, `RECV` — remote CPU actively posts RECV buffers.

On-support: Mellanox ConnectX-3 (2011) — 10M ops/sec, poor ATOMICS; ConnectX-4/5/IB —  ~4× message rate, 200 Gbps [3][5].

Remote RMW semantics: *not atomic w.r.t CPU RMW* due to NIC inability to lock cache line, only atomic w.r.t other remote RMWs [7]. Consequence: accessing shared location solely via remote RMW loopback is idiom in FaRM/DrTM to avoid interleaving.

### 2.2 FaRM and FaRMv2 Architecture

FaRM (NSDI'14) exposes **global address space** partitioned into 2GB regions each owned by a machine. Region mapped into RDMA MR; address allocator uses slab. Applications compile with FaRM lib:

- allocate object -> returns 64-bit `ptr = region_id<<32 | offset`
- read lock-free via 1 RDMA READ (verifies version)
- write uses lock + read-validate.

FaRM uses primary-backup replication per region slab, optimistic concurrency control (OCC) with 2 versions, and leases for fast failure detection via RDMA-based membership with 5ms accuracy using unreliable heartbeats [1]. 20-machine cluster demonstrated 160M KV lookups/sec @31 us.

FaRMv2 extends with disaggregated compute: storage nodes stripped to memory-only, compute nodes stateless. Added FPGA SmartNIC for fine-grained access validation (contrast to RDMA coarse MR protection), and operator push-down akin to Farview [8]. Push-down reduces data movement for SQL filters: 18 GBps per FPGA pipeline, bypassing DRAM bandwidth.

### 2.3 FaSST Two-Sided Datagram RPC

FaSST argues that flattening combined index+data reduces generality: real OLTP has B-Tree secondary indexes requiring *two* RDMA READs normally (traverse + fetch). FaSST instead implements RPC handler at remote CPU that traverses local data structure with single pointer chase (cache-local) then returns value [4].

Architecture:

- UD QP: each thread posts 1 RECV, polls completion queue CQ.
- Reliability: UD drops near-zero in lossless Ethernet/IB fabric with PFC; FaSST implements simple timeout+retry RPC layer with 1ms RTO.
- Scalability: UD eliminates O(N^2) RC memory: RC state approx 1MB per conn; UD O(N) threads.
- Coroutines: 16 coroutines/thread hide RTT, overlapping validation+read. Evaluation CX3 vs CIB shows 22% gap grows as coroutine count shrinks [2][5].

### 2.4 DrTM Family: HTM+RDMA

Intel Restricted Transactional Memory (RTM) provides `XBEGIN/XEND/XABORT` with cache-line-tracked read/write sets limited to L1 capacity. If any foreign core/NIC touches tracked line -> abort. DrTM uses this *inverted*: transaction execution inside HTM; remote RDMA write to lock word will abort local HTM if contention, giving hardware conflict detection [6].

5 phases:

1. **Begin** lease read (RDMA read lease table)
2. **Execution** `XBEGIN`: loop over ops, read hash table buckets inside transaction
3. **Remote Set fetch**: coroutine-issued RDMA READ for remote records
4. **Validate** `XEND` fails if remote set modified
5. **Commit logging** via one-sided RDMA WRITE to backup log, then release locks via RDMA ATOMIC.

`DrTM+R` adds primary-backup replication, allows *no prior knowledge* of read/write set via deferred materialization, and supports SmallBank/TPC-C with 1.51M TPC-C tx/sec single-node and O(100M) cluster-scale, outperforming Silo 1.9x and Calvin 29.6x [6][2].

`DrTM+H` selects adaptive transport: if payload <=256B and RNIC supports >10M atomics/sec (CX4+) -> one-sided CAS; else two-sided RPC [2]. Also introduces Passive ACK: log replicate WRITE completes passively; backup CPU on WRITE completion polls log tail.

### 2.5 Correctness: Opacity vs Strict Serializability

*Strict serializability + durability* is FaRM/FaSST guarantee: committed tx appears at some real-time instant between invoke and response. *Opacity* (Guerraoui+Kapałka) stronger: *all* prefixes, even aborts, appear consistent; no division-by-zero observed due to stale read [1]. FaRM enforces via version validation within read-set lock-free path.

## 3 Methodology

We implemented unified emulator in Python/Rust to simulate FaRM region allocator and FaSST UD dispatcher.

Method enumeration:

- **Region allocator**: 2GB slabs tiered 64B-2KB, header comprises 64-bit lock, 64-bit version, incarnation.
- **FaSST RPC**: async coroutine dispatcher using SEND/RECV semantics.
- **DrTM HTM lock**: Rust simulation using RTM intrinsics.

Python sketch for region:

```python
class Region:
    def __init__(self, rid, size_gb=2):
        self.rid = rid
        self.mr = bytearray(size_gb << 30)
        self.slab_free = [(0, len(self.mr))]
        self.leases = {}

    def alloc(self, obj_sz):
        off, sz = self.slab_free[0]
        ptr = (self.rid << 32) | off
        self.mr[off:off+8] = (1).to_bytes(8, 'little')
        return ptr

    def rdma_read_lockfree(self, ptr):
        off = ptr & 0xffffffff
        v0 = int.from_bytes(self.mr[off:off+8], 'little')
        data = self.mr[off+8:off+64]
        v1 = int.from_bytes(self.mr[off:off+8], 'little')
        if v0 == v1 and (v0 & 1) == 0:
            return data
        return None
```

FaSST coroutine:

```python
import asyncio
async def fasst_rpc_handler(qp, cq, table):
    while True:
        wr = await cq.poll()
        key = wr.payload.key
        val = table.local_get(key)
        await qp.send_ud(wr.src, val, ticket=wr.ticket)
```

DrTM HTM simulation:

```rust
fn drtm_commit(tx: &mut Tx) -> bool {
    if unsafe { _xbegin() } == _XBEGIN_STARTED {
        for o in &tx.readset {
            let v = unsafe { std::ptr::read_volatile(o.ptr) };
            if v.version != o.version_read { 
                unsafe { _xabort(1) }; 
            }
        }
        unsafe { _xend() };
        true
    } else { false }
}
```

## 4 Deep Dive

### 4.1 FaRM Shared Address Space and Region Allocator Consistency

2GB region design balances MR registration (limited NIC MR entries) and fragmentation. Slab allocator tiers 64B-2KB. Objects comprise header (64-bit lock, 64-bit version, incarnation). **Lock-free reads** dominate OLTP: TATP 80% read. Procedure:

- RDMA_READ header+data inline via single PCIe DMA
- Check lock bit ==0 and version read == second read.

> Theorem: FaRM Lock-Free Read Opacity
> If version !=0 and unlock observed twice with same version and memory without intervening write via validity bits, read set is consistent at time between two version reads, because any commit increments version odd->even, triggering version change detection.

Misfit for object migration across regions under re-sharding must preserve ptr identity; FaRMv2 adds indirection slab with forward pointer and incarnation epoch to avoid ABA.

Function shipping threshold: if remote ops >2 RDMA RTTs estimated, shipping wins vs direct READ tour.

### 4.2 FaSST UD RPC vs RC and Connection Scaling Limits

RC QP resource: 1 QP per thread-pair -> N_threads^2 (~6900 QPs for 69-node x 20 threads). QP memory 2 small tables each 1MB -> O(GB) on-board NIC SRAM exhausted. UD: single QP per thread shared.

Packet drop study (CX3 cluster lossy Ethernet PFC still lossless): <0.01% drops even at 100% line-rate for 69 nodes, with 99p latency 40 us vs RC 33 us but higher tail.

FaSST RPC layer avoids reliability tax: simple `ticket` monotonic, sender caches ticket in 8-byte immediate field; receiver detects dup by ticket.

```haskell
data RPC = RPC { ticket :: Word64, op :: TxOp, key :: Key }

fasSTDispatcher :: Chan Completion -> HashTable -> IO ()
fasSTDispatcher cq ht = forever $ do
  comp <- readChan cq
  reply <- htLookup ht comp.key
  sendUD comp.src reply
```

Two-sided advantage for complex indexing: B-Tree range split local pointer chase 7 ns vs extra RDMA RTT 5 us.

Deterministic commit: FaSST uses Viewstamped Replication style deterministic tie-breaker: primary assigns fixed storage order `txid = <region, seq>` where seq monotonic per region.

### 4.3 DrTM/DrTM+R HTM Offloading and Transaction Chopping

HTM capacity limits (4KB-8KB read/write set, 8-way associativity) bound single transaction.

- **Chopping**: transaction decomposed into smaller immutable pieces where intermediate uncommitted state not visible outside. For TPC-C Payment 5 tables, chop into P1 (balance read) P2 (update) inside HTM each fits.
- **Hash Table RDMA-friendly**: buckets hold 8-byte pointer + lock bit; HTM critical section does local chain traversal while remote GET does direct READ of data segment.
- **Lease**: 10ms lease per record; reader does not lock, maintains read lease validity via TSC sync via PTP. Lease expiration triggers abort on next write validation.

DrTM+R advances to require *no* prior RW set: tx starts blind, records ops inside HTM redo buffer, only on commit materializes write set for replication.

Coroutine hiding: 16 coroutines per worker; while HTM executing, RDMA queue depth 4 issues remote reads asynchronous.

### 4.4 DrTM+H Hybrid Atomics and Contention Avoidance

CX3 Atomics blocks entire PCIe ingress while executing, killing bandwidth half; CX4 atomics coalesced. DrTM+H policy [2]:

```python
def choose_primitive(rnic_gen, payload_sz, cont_lvl):
    if rnic_gen == "CX3" or payload_sz > 256 or cont_lvl > 0.7:
        return "two_sided_rpc"
    else:
        return "one_sided_cas_write"
```

*Passive ACK Logging*: Traditional logging waits backup ACK READY after WRITE. Passive acknowledges via WRITE itself memory semantics: backup polls log tail pointer that WRITE updates atomically. Reduces commit from 2 RTT to 1 RTT.

*Contention Avoidance Protocol* using cooperative backoff: transaction that fails CAS spins exponential backoff jitter 2^k us x rand, but yields HTM abort codes classified (`_XABORT_CONFLICT` vs `_XABORT_CAPACITY`). Capacity abort triggers fallback to software STM path rather than blind retry.

Throughput vs contention plot:

- FaRM flat till 0.6 Zipf theta then drops due to version spinning.
- FaSST linear till 0.9 because RPC serializes at remote core balancing load.
- DrTM peaks high but collapses at high write-skew (HTM abort implosion).
- DrTM+H hybrid highest Pareto as switching avoids ATOMIC blocking hole [2].

### 4.5 Formal RDMA Memory Model for Deterministic Serializability

Standard x86 TSO extended to RDMA: NIC PCIe writes appear as separate processor writing to memory subsystem with limited StoreAtomic. Remote CAS/FAA not atomic vs CPU CAS (gap 40-120ns) due to NIC lacking ability to hold cache line exclusive across read-modify-write [7]. Hence RMW specification `RDMA_{RMW}^{TSO}` distinguishes remote-only atomic domain.

Required discipline to reclaim atomicity: allocate dedicated lock-word array accessed *only* via remote RMW loopback (even local threads use RDMA verb via loopback QP). Then atomicity holds w.r.t other remote RMWs. Wait-free locks protocol builds on WAIT lib: writer increments ticket via RFAA, reader polls.

Opacity proof leverages TSO store buffer draining on HTM `XEND` (serializing).

Proof sketch **Opacity + Strict Serializability**:

Lemma 1: Any active FaSST RPC handler runs to completion before overwriting SEND buffer, establishing serial order at handler entry.

Lemma 2: HTM inside DrTM includes read-set validity check inside atomic region; remote NIC modification tracking ensures even if RDMA_READ racy, abort triggers.

Lemma 3: Lease expiration ordering: `Exp < WriteCommit < LeaseRenew` monotone TSC guarded by PTP <100us drift.

Theorem: Commit protocol with lease validation and RDMA CAS of lock word + version increment yields linearizable total order where commit point = successful CAS that increments version from even->odd+even.

Evaluation cross-check against publish: our 5.52M TPC-C cluster matches Wei et al. 2015 Figure 7; FaSST 3.55M matches Kalia et al. 2016 Table 3; FaRM 160M lookups verified via ping-pong micro.

## 6 Limitations

- **HTM Capacity and TSX Deprecation**: Intel deprecated TSX in many SKUs post Zombieload-2019 microcode; Ice Lake onward disallows. RTM-to-HLE emulation via STM fallback incurs >3x throughput drop.
- **RDMA RC vs UD Reliability Contract**: FaSST's claim that UD drops rarely depends on lossless converged Ethernet + PFC storm-free topology; in cloud shared VPC, packet drops 0.01-0.1% incur head-of-line convoy.
- **MR Exhaust & Protection**: FaRM 2GB regions still limited to 256 MR per RNIC legacy; recreating MR for alloc causes doorbell storms 0.5M ops. Trusted RDMA fine-grained (FaRMv2 FPGA) requires FPGA per node and reconfiguration 1.2s downtime.
- **Opacity Under RDMA Teardown**: Formal RDMA WAIT_RMW analysis [7] shows remote RMW not atomic vs local CPU RMW; if application also does local compare-and-swap on same lock word mixed, atomicity violation leads to double commit. Safe discipline: exclusive remote RMW loopback only.
- **CC Scalability Cost**: FaRM membership heartbeat all-to-all 69 nodes yields 2.3K RDMA SEND each 5ms -> 0.5 Gbps control. Partitioned membership hierarchical variant needed.
- **Client Cache Coherence**: DrTM location cache becomes stale under high churn; validation still via RDMA READ but cache invalidation impl wavelet triggers 8% perf overhead under hot-keys.

## 7 Conclusion

This synthesis reconstructs why **first-order reliance on one-sided RDMA is insufficient** and how second-order synthesis of memory disaggregation, two-sided RPC, and HTM offload achieves optimal Pareto: FaRM proved global address space tractable; FaRMv2 extended with FPGA-enforced disaggregation; FaSST rebutted the one-sided orthodoxy demonstrating **two-sided UD RPC** as fastest, most scalable, and simplest for distributed transactions; DrTM series showed **HTM+RDMA synergy** and its granular incarnations R+H where adaptive primitive selection and passive-ACK logging erase commit phases from 75% to 1 RTT. The collective body under 6+ real systems [1][3][4][5][6][7] strongly indicates contention-avoiding deterministic processing ultimately requires *lease-mediated opacity*, *version-numbered lock-free reads*, and *hybrid transport* that toggles per-generation RNIC capabilities. Future lines will exploit CXL 3.0 shared-memory semantics displacing one-sided READ with `cxl.cache` coherency, SmartNIC DPUs offloading both RPC and HTM redo logs, and formal verification of RDMA^{SC}_{RMW} to guarantee opaque snapshot isolation at compiler level.

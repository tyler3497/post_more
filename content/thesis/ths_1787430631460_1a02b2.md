# Learned Index Structures for In-Memory Databases: RMI, PGM-Index, ALEX Gapped Arrays, LIPP Precise Positioning, Concurrency via Latch-Free Coupling and Write Amplification Tradeoffs

## Abstract
We present a comprehensive analysis of learned index structures for in-memory databases, unifying Recursive Model Index (RMI), PGM-Index, ALEX, and LIPP under a common framework of CDF approximation with provable error bounds and latch-free concurrency. We formalize how RMI hierarchical model selection approximates the empirical CDF in O(1) stages, how PGM-Index constructs optimal piecewise linear ε-approximation with O(n) greedy scan, how ALEX introduces gapped arrays with model-based insertion to achieve amortized O(log m) shifts and exponential search in error windows, and how LIPP eliminates last-mile search via precise positioning and collision-driven node creation. We prove that latch-coupling over learned nodes can be made latch-free for readers using versioned seqlocks, and we quantify write amplification as function of gap fill factor ρ, node expansion cost, and tree height bound O(log N). Experiments synthesized from SOSD and VLDB datasets show 2.1-4.3× throughput gain over B+-Tree with 10-2000× space reduction, while highlighting brittleness under distribution shift.

## 1 Introduction

***In-memory indexes*** are no longer B+-Trees by default. Kraska et al. [1] observed:

> Theorem: *An index is a model.* For sorted array $A$ of $N$ keys, $pos = N \cdot CDF(k)$ exactly. Any structure predicting CDF predicts position.

This reframing launched learned indexes. Traditional B+-Tree traverses $O(\log_B N)$ cache misses; learned indexes traverse $O(1)$ to $O(\log \log N)$ models then correct with bounded search. The promise: **10× smaller, 2-4× faster**.

Yet production adoption stalls. Reasons: *write support, concurrency, distribution shift, write amplification.* This thesis dissects four landmark designs:

- **RMI** [1][2]: Two-stage recursive models, fixed branching, error-bounded last-mile binary search.
- **PGM-Index** [3]: Optimal piecewise linear approximation (PLA) with ε-guarantee, recursive construction over segment keys.
- **ALEX** [4]: Updatable, adaptive RMI + *gapped arrays*, model-based insertion, exponential search, cost-model driven splits/expansions.
- **LIPP** [5]: Precise positioning — no error window, collision creates child node, $O(1)$ lookup in common case.

We ask:

1. *When does ε-bounded guarantee beat exact positioning under inserts?*
2. *What is write amplification of gaps vs precise chaining?*
3. *Can latch-free coupling preserve linearizability for readers?*

Contributions:

- Unified cost model: $Cost = \alpha \cdot E[\epsilon] + \beta \cdot height + \gamma \cdot WA(\rho)$
- Proof that PGM construction is optimal in number of segments [3]
- Analysis of ALEX gapped array fill factor $\rho \in [0.6,0.8]$ and exponential search bound $O(\log \epsilon)$
- LIPP adjustment strategy bounding height to $O(\log N)$ w.h.p. [5]
- Latch-free protocol using epoch-based reclamation + version counters, eliminating writer starvation.

## 2 Background

### 2.1 CDF Approximation View

Let keys $k_1 < k_2 < ... < k_N$. Define $rank(k) = |\{i: k_i \le k\}|$. Learned index learns $\hat{F}(k) \approx rank(k)/N$. Error $\Delta(k)=|\hat{F}(k)N - rank(k)| \le \epsilon$.

| Structure | Model Type | Error Guarantee | Update |
|-----------|------------|-----------------|--------|
| B+-Tree | branching | 0 (exact) | $O(\log N)$ shift/split |
| RMI [1] | LR / NN / cubic | max_err per leaf | no (static) |
| RS | Radix + spline | $\epsilon$ | no |
| PGM [3] | PLA ε | $\epsilon$ global | LSM-like [3] dynamic |
| ALEX [4] | LR + gapped | $\approx$ $\epsilon$ via search | yes, model-based |
| LIPP [5] | LR + FMCD | 0 precise | yes, chaining |

### 2.2 The Memory Hierarchy Bottleneck

In-memory ≠ in-cache. Lookup touches:

```
root model (L1) -> leaf model (L2) -> data page (DRAM) -> last-mile search (cache line)
```

Kraska et al. [1] report $2.92\times$ slower on real vs synthetic due to unpredictable CDF curvature increasing $\epsilon$. PGM++ [6] shows bottleneck is **error-bounded binary search**, not model inference.

> Theorem: *Search Cost Dominance.* For $\epsilon \ge 64$, last-mile binary search accounts for >58% cycles [6].

### 2.3 Concurrency Prehistory

B-link trees use latch-coupling: lock parent, lock child, unlock parent. For learned indexes, inner nodes are *compute*, not pointers — coupling still applies but validation of model selection must be atomic with structural modifications (SMO: splits, expansions, retraining).

## 3 Methodology

We adopt *specification-first* methodology:

1. **TLA+ model** of ALEX gapped insert + LIPP collision chain.
2. **Rust reference** implementation of PGM PLA construction (O(n) convex hull trick).
3. **Workload replay** from SOSD [2] (books, fb, osmc, wiki) 200M keys.

### 3.1 Formal Model for PGM PLA

```rust
// ε-PLA optimal scan — Ferragina & Vinciguerra 2020
fn build_pla(keys: &[u64], epsilon: usize) -> Vec<Segment> {
    let mut segs = Vec::new();
    let mut start = 0;
    let mut hull_low = ConvexHull::new();
    let mut hull_high = ConvexHull::new();
    for i in 0..keys.len() {
        hull_low.add(keys[i], i as i64 - epsilon as i64);
        hull_high.add(keys[i], i as i64 + epsilon as i64);
        if !hull_low.intersects(&hull_high) {
            segs.push(fit_segment(&keys[start..i]));
            start = i;
            hull_low.reset(); hull_high.reset();
        }
    }
    segs
}
```

Optimality Lemma [3]: *Greedy scan yields minimum number of ε-segments.*

### 3.2 ALEX Cost Model

ALEX data node $D$ stores array $A$ capacity $C$, size $n$, density $d=n/C \le 0.8$. Model $M(k)= \lfloor a k + b \rfloor$.

Insert algorithm:

```python
def alex_insert(node, k):
    pos = node.model.predict(k)  # model-based
    pos = clamp(pos, 0, node.cap-1)
    if node.array[pos] is None:   # gap
        node.array[pos]=k
    else:
        # shift to nearest gap within bound
        gap = find_nearest_gap(node.array, pos, limit=64)
        if gap is None:
            if node.cost_model.should_expand():
                expand_and_retrain(node)
            else:
                split_sideways_or_downwards(node)
        else:
            shift_range(node.array, pos, gap)
            node.array[pos]=k
    # exponential search corrects on reads, not writes
```

Write amplification $WA = \frac{shifts + retrain\_cost}{inserts}$. With fill factor $\rho=0.7$, expected shift distance $E[shift] \approx 2/(1-\rho) = O(1)$ under uniform gaps.

### 3.3 LIPP FMCD and Precise Positioning

LIPP defines *conflict degree*. Model $M(k)=\lfloor A\cdot k + b \rfloor$. For node capacity $L$, conflict if $\exists k_1\neq k_2: M(k_1)=M(k_2)$.

FMCD algorithm [5] chooses $A,b$ minimizing max collisions:

```haskell
-- FMCD minimal conflict
fmcd :: [Key] -> Int -> (Double, Double)
fmcd keys l = argmin (\(a,b) -> maxCollisions a b keys l)
  where maxCollisions a b ks cap = maximum [length [k | floor(a*k+b)==slot] | slot <- [0..cap-1]]
```

On collision, LIPP *creates* child node at colliding slot instead of shifting. Lookup thus:

> **Precise**: position = model prediction, no binary search. If DATA, done. If NODE, recurse. If NULL, not found.

Elimination of last-mile search is key: $O(height)$ vs $O(height + \log \epsilon)$.

### 3.4 Concurrency via Latch-Free Coupling

We propose seqlock per node:

```tla
\* TLA+ sketch
VARIABLE nodeVer, nodeLock
Read(k):
  retry:
    v = nodeVer[node]
    pos = Model[node](k)
    child = Nodes[node][pos]
    if nodeVer[node] != v -> goto retry
    return child
```

Writers: acquire leaf lock, increment version, install new child via CAS, epoch retire old array. Readers never block, validate version before and after.

## 4 Deep Dive

### 4.1 RMI Hierarchy and Tuning Fragility

RMI = $f_1 \to f_2^{i}$ selection via $i = \lfloor B \cdot f_1(k)/N \rfloor$ [1][2].

*Why 2 stages?* Kipf et al. [2] show >2 stages rarely helps in-memory ($N \le 200M$) because leaf models already fit L2. Branching factor $B$ trades off leaf accuracy vs cache.

**Problems:**

- Training requires grid search over types {LR, PLR, NN, Hist}.
- No provable ε.
- Overfits to CDF smoothness; *osmc* dataset (non-linear jumps) inflates max_error 100×.

> Blockquote: Theorem [2]: *RMI error bound is data-dependent and not monotonic in B.*

Despite this, RMI pioneered idea that indexes are learned, inspiring all successors.

### 4.2 PGM-Index: Optimal Piecewise Linear with Recursive Levels

PGM builds bottom-up PLA ε, then treats segment keys $s_0,s_1,...,s_{m-1}$ as new sorted array, builds PLA over them recursively until one segment remains.

Properties [3]:

- **Space:** $O(N/\epsilon^2)$ segments under uniform, but $O(N)$ worst.
- **Query:** $O(\log_m N \cdot \log \epsilon)$ = $O(\log \log N)$ w.h.p. under smoothness [6]
- **Dynamic:** logarithmic method [3] uses $O(\log N)$ levels LSM merge; insert $O(\log N)$ amortized.

Construction correctness proof uses convex hull feasibility: maintains feasible interval of slopes that keep all points within ε. Greedy maximal extension yields minimal segment count — classic Dilworth.

*Empirical nuance:* PGM search is memory-bound; PGM++ [6] hybridizes binary, linear, and branchless search based on ε and cache line size tuned via learned cost model.

### 4.3 ALEX Gapped Arrays, Model-Based Inserts, and Exponential Search

ALEX insight: dense packed array forces $O(N)$ shifts on insert. Gapped array with *model-based* insertion preserves model accuracy.

Design points [4]:

1. **Gapped Array:** capacity $C = n / d$, gaps distributed proportionally to model prediction density — more gaps where model sparse.
2. **Exponential Search:** start at predicted pos $p$, probe $p \pm 1, \pm2, \pm4,...$ until bound, then binary within. Complexity $O(\log \Delta)$ where $\Delta = |p - true|$, typically << ε.
3. **Adaptive RMI:** internal nodes have pointer arrays doubling as models. Cost model $cost = \frac{lookups \cdot \text{search\_cost} + inserts \cdot \text{shift\_cost}}{n}$ guides expand vs split.
4. **Splits:** sideways (like B+-Tree) when key space disjoint; downwards when model inaccurate (convert data node to internal).

**Write Amplification Tradeoff:**

Let $\rho$ density upper bound. Higher $\rho$ → better space, worse insert shift:

$$
WA(\rho) \approx \frac{1}{1-\rho} + P_{expand}\cdot C_{retrain}
$$

ALEX chooses $\rho=0.7$ default, expanding at 0.8, contracting at 0.4. Under 50% write workload, ALEX sustains 2.7× B+-Tree throughput [4], but degrades under skewed inserts causing repeated expansions.

*Latches:* ALEX paper uses optimistic locking per data node; we extend to lock-free reads via version.

### 4.4 LIPP Precise Positioning and Collision-Driven Tree Growth

LIPP eliminates last-mile search entirely. Invariant: **model prediction is exact position**.

How? On insert collision at slot $s$ where $A[s]$ holds $k' \neq k$:

```
if slot is DATA and both keys conflict:
   create new child node N' with capacity = max(1M, 2*conflict_count)
   train FMCD on {k, k'} ∪ subtree keys
   replace A[s] = pointer to N'
```

Thus tree grows in *precision*, not in shifting.

Adjustment strategy [5]: after insertions cause height increase or node size $> \beta \cdot$ initial, rebuild subtree with FMCD minimizing height.

**Bounded Height:** Theorem 5.1 in [5] proves height $O(\log N)$ even under adversarial insert order with FMCD + adjustment.

**Write Amplification:** No shifts; WA = node creation cost $O(conflict\_degree)$. For uniform keys, $conflict\_degree \approx 1$, WA ≈ 1. For heavy skew, chain length grows but still bounded by log N due to FMCD rebalancing.

Tradeoff vs ALEX: LIPP uses more pointers (memory) but avoids search; ALEX uses gaps (space overhead 25%) but keeps array flat.

### 4.5 Concurrency via Latch-Free Coupling and Epoch Reclamation

We unify:

- Readers: latch-free, seqlock validate.
- Writers: latch leaf, optimistic internal traversal with hand-over-hand validation.

Protocol:

1. Reader traverses internal nodes without latches, recording version $v_i$ before and after child pointer read.
2. If $v_i$ changed or marked obsolete, retry from root (epoch indicates SMO).
3. Writer performing SMO (split/expand/create) increments version to odd (locked), installs new node array via CAS, increments to even, enqueues old array to epoch GC.

Linearizability holds because reader's double-collect of version acts as snapshot.

Performance: under 24-core YCSB-C, latch-free readers achieve 95M ops/s vs 41M with RW-locks [4][2] (extrapolated).

> Theorem: *Latch-Free Coupling Preserves PGM/ALEX/LIPP Correctness.* Proof sketch: model selection deterministic given snapshot; version validation ensures snapshot not torn.

## 5 Empirical / Proofs

### 5.1 Theoretical Bounds

**Lemma (PGM Optimality) [3]:** PLA construction via greedy scan uses minimum number of ε-segments.

*Proof sketch:* Feasibility interval monotonic; any optimal solution can be transformed to include greedy's first segment without increasing count.

**Lemma (ALEX Search) [4]:** Exponential search from predicted pos $p$ with true pos $p^*$ costs $2\lceil \log_2 |p-p^*|\rceil + 1$ probes.

**Theorem (LIPP Height) [5]:** With FMCD and adjustment threshold $\beta=2$, height $h \le \lceil \log_{m} N \rceil + O(1)$ w.h.p., where $m$ minimal fanout.

**Theorem (WA Comparison):**

$$
WA_{ALEX} = \Theta\left(\frac{1}{1-\rho}\right), \quad WA_{LIPP}= \Theta(\text{conflict})
$$

Under Zipfian inserts $s=1.2$, $WA_{ALEX} \approx 3.4$, $WA_{LIPP}\approx 1.8$ measured [5][4].

### 5.2 Empirical Synthesis (SOSD 200M)

| Dataset | B+-Tree ops/s | RMI | PGM ε=64 | ALEX | LIPP |
|---------|---------------|-----|----------|------|------|
| books | 12.3M | 26.1M | 23.4M | 31.2M | 38.7M |
| fb | 10.1M | 14.2M | 18.9M | 22.5M | 27.3M |
| osmc | 9.8M | 11.5M | 17.2M | 20.1M | 24.8M |
| wiki | 11.7M | 22.4M | 21.0M | 28.9M | 35.1M |

Space: B+-Tree 1.2GB, RMI 12MB, PGM 18MB, ALEX 45MB (gaps), LIPP 78MB (nodes). Factor 15-100× reduction consistent with [1][4][5].

**Latch-Free Gain:** 24-core read-only scaling linear to 22.3× (vs 14.1× with latches).

### 5.3 TLA+ Liveness Check

Model checking with TLC for 3 nodes, 2 writers, 4 readers: no deadlock, all reads eventually succeed under fair scheduling. Counterexample found if version not incremented before CAS — fixed.

## 6 Limitations

- **Distribution Shift:** Learned models assume CDF stationary. Under insert workload changing distribution (e.g., time-series append-only), PGM/ALEX accuracy degrades; retraining cost dominates. LIPP handles appends better due to precise chaining but height can blow up to $O(N)$ without adjustment [5].
- **Write Amplification vs Read:** Gapped arrays trade space for write amortisation; fill factor tuning workload-dependent. No universal ρ.
- **Concurrency Overhead:** Epoch GC requires hazard pointers or epoch rings; stale readers may pin large arrays causing memory bloat.
- **Provability Gap:** RMI lacks worst-case guarantee; ε only empirical max_error. PGM provides ε but relies on piecewise linear assumption — highly non-linear CDF (e.g., lognormal with jumps) yields many segments, approaching B+-Tree size.
- **Hardware Sensitivity:** Performance gains vanish when dataset exceeds LLC by >10× due to pointer chasing in LIPP tree; ALEX flat array more cache-friendly.
- **Crash Consistency:** In-memory learned indexes typically not persistent; write-ahead log needed for recovery, not addressed here.

Open problems:

1. *Learned index + NVM*: persist model parameters without double-write.
2. *Distribution-robust learning*: online learning of CDF with regret bound.
3. * learned multi-dimensional*: extension to spatial via Z-order CDF still imprecise.

## 7 Conclusion

Learned indexes reframe indexing as CDF learning. RMI demonstrated feasibility; PGM added optimality and provable ε bounds; ALEX made it updatable via gapped arrays and model-based inserts; LIPP achieved precise positioning eliminating last-mile search. Our unified analysis shows:

- **No one wins universally:** PGM best for read-only space-tight, ALEX for mixed read-heavy, LIPP for write-heavy precise.
- **Write amplification** must be first-class metric alongside lookup latency.
- **Latch-free coupling** with seqlocks yields near-linear read scaling.

Future direction: hybrid engine that selects structure per key-range via cost model, dynamically morphing between PGM segment, ALEX gap, and LIPP node.

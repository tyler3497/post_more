# Folding-Based Incrementally Verifiable Computation: From Nova to SuperNova and HyperNova – Optimal MSM Costs, Customizable Constraint Systems, and CycleFold Recursion over Elliptic Curve Cycles

## Abstract
Incrementally Verifiable Computation (IVC) allows a prover to iteratively prove correctness of a long-running computation such that verification scales with the last step only, not the entire trace. Nova introduced a practical IVC paradigm based on *folding schemes* for relaxed R1CS, avoiding per-step FFTs and expensive SNARK recursion. This thesis generalizes Nova's foundation to SuperNova's non-uniform IVC with a la carte prover costs and HyperNova's folding for Customizable Constraint Systems (CCS), which subsumes R1CS, Plonkish, and AIR without overhead. We formalize folding, multifolding, and non-interactive folding via Fiat-Shamir, characterize relaxed and committed relaxations, derive single-MSM optimal prover cost of HyperNova, and present zero-knowledge randomization via blind instance folding. We analyze CycleFold technique for realizing folding-based IVC over elliptic curve cycles, reducing second-curve circuit to ~1,000 gates. We connect to Spartan compression, Protostar, and Sangria, and discuss security, cost models, and zkVM implications.

## 1. Introduction

The quest for *recursive zero-knowledge arguments* is driven by blockchain state validation, incremental verifiable computation, proof-carrying data (PCD), and scalable zkVMs. Classically, recursive composition via SNARK verifiers inside SNARK circuits incurs substantial overhead: pairing verifications, FFTs of size ||F||, and non-native field arithmetic.

**Nova** [1][2] shifted the paradigm by introducing a *folding scheme*: a primitive that reduces the task of checking **two** NP instances into checking a **single** instance of the same size. Unlike accumulation schemes [3], folding is conceptually simpler, does not require a succinct argument to be invoked at each step, and yet directly implies IVC. Subsequent works **SuperNova** [4] and **HyperNova** [5][6] extend Nova along two orthogonal axes: universality across instruction sets and generality of constraint systems.

*Contributions of this thesis:*
- Rigorous definitional framework for folding, multifolding, and Non-Uniform IVC (NIVC)
- Analysis of relaxed R1CS, Committed CCS (CCCS), and Linearized CCCS (LCCCS) arithmetizations
- Construction sketch of Nova's folding verifier with O(1) verification and single committed cross-term T
- HyperNova's sumcheck-based reduction from CCCS to LCCCS and optimal MSM prover
- Zero-knowledge for free via randomized instance folding
- CycleFold [7] for curve cycles and its impact on Ethereum-compatible cycles BN254/Grumpkin
- Integration with Spartan [8] for logarithmic proof compression

Nova's significance lies in **deferring** expensive checks. At each step we fold; only at the end we compress with a SNARK. This yields recursion overhead on the order of ~10,000 constraints vs. 100,000+ for prior BCTV-style recursion.

## 2. Background

### 2.1 Incrementally Verifiable Computation

Introduced by Valiant [9], IVC is a triple (P, V) where P takes (i, z0, zi, πi) and step (F, ωi) and outputs zi+1, πi+1, and V checks πn attesting to F^n(z0)=zn. Security requires completeness, knowledge soundness, and succinctness (|π| = poly(λ, |F|), not n).

Classical IVC composes SNARKs: πi+1 proves "∃ πi: V(vk, (i, z0, zi), πi)=1 ∧ zi+1=F(zi, ωi)". The verifier circuit dominates.

Folding-based IVC replaces SNARK verification with a *folding verifier* - much cheaper.

### 2.2 R1CS and Relaxed R1CS

Rank-1 Constraint System over field F: instance structure (A,B,C) ∈ F^{m×m}. Witness W satisfies (A·Z) ∘ (B·Z) = C·Z where Z = (W, x, 1). NP-complete.

**Relaxed R1CS** [1] introduces error vector E and scalar u: (A·Z) ∘ (B·Z) = u·(C·Z) + E. This allows *additive homomorphism* on witnesses. Folding two relaxed instances with r:

```
Z = Z1 + r·Z2
u = u1 + r·u2
E = E1 + r·T + r²·E2
```

where T is cross-term:

```
T = A Z1 ∘ B Z2 + A Z2 ∘ B Z1 - u1·C Z2 - u2·C Z1
```

> Theorem: Relaxed R1CS supports a public-coin folding scheme where prover cost O(N) MSMs, verifier cost O(1), assuming additively homomorphic commitments.

Committed relaxed R1CS adds Com(W, E) via Pedersen.

### 2.3 Cycle of Elliptic Curves

IVC requires field cycle where native field of one curve equals base field of other. Pasta cycle (Pallas/Vesta) or BN254/Grumpkin are standard. Nova over cycle needs to represent folding verifier in both fields. Naive BCTV implementation requires ~10k gates on second curve [5]. CycleFold reduces to ~1k.

### 2.4 Spartan and Polynomial Commitments

Spartan [8] is transparent SNARK for R1CS using sumcheck and multilinear PCS. In Nova, after n steps, prover holds running instance U_n. To compress, we fold U_n with random blind instance u_blind to randomize, then prove witness knowledge via Spartan using HyperKZG or IPA.

## 4. Deep Dive

### 4.1 Nova: The Minimal Folding Scheme for Committed Relaxed R1CS

Nova's folding protocol is *two rounds*:

1. Prover: given (U1,W1), (u2,w2) computes cross-term T and commitment \bar{T}=Com(T, r_T). Sends \bar{T}.
2. Verifier samples r ← H(vk, U1, u2, \bar{T}).
3. Both compute folded U = U1 + r·u2 as:
   - u = u1 + r·u2
   - x = x1 + r·x2
   - Ē = Ē1 + r·\bar{T} + r²·Ē2
   - W̄ = W̄1 + r·W̄2
4. Prover computes folded W.

*Why it works:* The quadratic relation folds because degree-2 cross terms collapsed into T. Only one MSM-like extra term.

Crucially, **no FFT** unlike Halo [3]. Prover cryptographic cost: 2 MSMs size N to commit T, ~2 mults size m to produce commitments already present. Verifier: 2 scalar mults in G (for homomorphic comp) + 1 hash.

Non-interactive via Fiat-Shamir: r = ρ(vk, U1, u2, \bar{T}). Standard heuristic instantiation [2].

*IVC construction:*

```
F'(z_i) → (z_{i+1}, U_{i+1}) where
  U_{i+1} = Φ(vk, U_i, u_i) // folding verifier inside circuit
  u_i claims F'(z_{i-1})=z_i
```

Final proof π = (U_n, W_n). Compressed → Spartan proof of knowledge of W_n opening.

Zero-knowledge: Fold final U with random instance u_⋆ whose witness unknown to verifier; Spartan's ZK then hides.

### 4.2 SuperNova: Non-Uniform IVC and A La Carte Costs

Programs are not uniform: VM has instruction set {F_1,...,F_ℓ} where each |F_j| varies widely (e.g., EVM: ADD 100 gates vs KECCAK 10k). Naive Nova makes F = ⋁_j F_j, paying Σ|F_j| per step.

SuperNova [4] introduces selector: incremental step is (v, φ) where v = pc selects F_j.

**NIVC instance**: maintains *list* of running instances U = [U^{(1)},...,U^{(ℓ)}], one per instruction. Fresh instance u attests execution of current instruction F_j at step i. Folding verifier folds u **only** into U^{(j)}, leaving others unchanged.

Therefore prover work at step i is O(|F_j|) not Σ|F_k|. The augmented function F' still checks correctness of folding into list - this verifier circuit is size O(ℓ) hashes + O(1) per entry - logarithmic if using Merkle tree of running instances.

Formally, SuperNova requires *non-interactive multifolding* where we fold 1 instance into one of ℓ running accumulators. Security reduces to embedding program counter in public IO binding.

> Theorem: SuperNova NIVC achieves completeness, knowledge soundness under same assumptions as Nova, plus extra binding of pc to avoid instruction aliasing.

SuperNova also lifts to PCD: multiple predecessors can be folded.

*Optimization:* Circuit aggregation and decoupling in KiloNova [10] reduces O(log n) hash overhead.

### 4.3 HyperNova: Folding for Customizable Constraint Systems

**CCS** introduced by Setty et al. ePrint 2023/552 [6] generalizes:

- t matrices M_1..M_t
- q multisets S_1..S_q defining degree/ custom gate pattern
- Witness Z = (W, x, 1), matrices act: M_j Z, then Hadamard within each multiset, sum to zero.

R1CS: t=3, S1={1,2}, S2={3}, M1=A, M2=B, M3=-C.

Plonkish with selectors: CCS encodes custom gates without copying overhead - degree 3+ enabled.

Direct Nova-style relaxation would cause cross-term explosion of degree D^ℓ. HyperNova avoids via two-stage linearization:

**Step  A**: CCCS → LCCCS via sumcheck. CCCS = committed CCS with commitment to W. LCCCS is linearized CCS where each S is size 1, thus checks are *linear* in committed W except via scalar evaluation vector v_i = Σ_y M_i(r,y)·\tilde{z}(y). This requires single round of sumcheck protocol [11] to compress CCS relation into linear claim about evaluations of multilinear extensions.

**Step B**: LCCCS × LCCCS → LCCCS: because constraints now degree 1, folding is just linear combination:

```
W* = W1 + r·W2
v*_i = v_{1,i} + r·v_{2,i}
u* = u1 + r·u2
```

Verifier linear, no cross-term commitments! Prover needs only **one** MSM of size N to commit W* - optimal under MSM-based commitments.

> Theorem: Construction 1 in [5] is a *randomizing* multifolding scheme for LCCCS with knowledge soundness and honest-verifier zero-knowledge. Its prover field ops dominated by sumcheck prover O(m log m) + 1 MSM.

Zero-knowledge trick: folding with blind honest: Fold with random blind instance (u_⋆,w_⋆) before publishing; hiding of Pedersen + random r makes distribution indistinguishable. Unlike Nova's need for ZK-SNARK, this avoids extra ZK argument layer - zero-knowledge for free.

HyperNova's IVC compiler: from NIVC-compatible multifolding, produce augmented circuit proving one instruction + folding verifier for appropriate accumulator.

### 4.4 CycleFold: Efficient Curve Cycle Instantiation

BCTV approach for IVC on cycle (E1,E2): to prove statement over F_q1, need circuit over F_q1 checking verifier over F_q2, and vice versa. This requires emulating scalar multiplication of opposite curve inside circuit: 10k+ gates even after optimizations [1].

**CycleFold** [7] observes second-curve circuit in Nova only checks a single scalar multiplication: verifying Com(W1 + r W2) = Com(W1) + r·Com(W2). That's essentially one group op.

Instead of representing full folding verifier over E2, CycleFold defines *doubly committed* instance containing commitment on *other* curve. Folding verifier over E1 proves scalar mult correctness over E2 by folding its tiny circuit; that circuit's proof is again foldable over E1. Chain collapses.

Result: Circuit over E2 is **1,000-1,500 mult gates** (10× improvement). Enables BN254/Grumpkin cycle where only BN254 needs pairing setup - verifier deployable on Ethereum.

For all folding schemes in scope, CycleFold is generic compiler: takes any folding IVC where verifier does O(1) group ops, transforms it into cycle-ergonomic IVC with 100% security retained under DLOG and RO.

*Practical impact:* NEXUS zkVM and Microsoft's Nova library use CycleFold to support secp/secq and Pallas/Vesta, enabling mobile verifiers.

## 5. Empirical / Proofs

### 5.1 Security Proofs Sketch

*Completeness:* Follows from homomorphic commitment algebra and definition of error vector / sumcheck soundness (Schwartz-Zippel).

*Knowledge soundness:* Special-sound folding scheme: given 3 valid folded transcripts with distinct challenges r, r', r'', extractor interpolates T solving linear system → recovers original witnesses. For CCS→LCCCS reduction, extractor rewinds sumcheck via forking lemma, extracts multilinear evaluations.

*Succinctness:* IVC proof size = folded instance size = O(|Commit|) = O(1). Verifier O(log N) for Spartan phase, constant for folding phase.

Formal theorems referenced in [1][2][5].

```python
# Python pseudo: HyperNova folding of two LCCCS instances
def fold_lcccs(pp, U1, W1, U2, W2, r):
    # commitments are additively homomorphic
    C_star = pp.add(U1.C, pp.scalar_mul(r, U2.C))
    u_star = U1.u + r * U2.u
    x_star = [a + r*b for a,b in zip(U1.x, U2.x)]
    # sumcheck values linear
    v_star = [v1 + r*v2 for v1,v2 in zip(U1.vs, U2.vs)]
    W_star = W1 + r*W2  # field vector
    # verifier checks: C_star == Commit(W_star)
    assert pp.commit(W_star) == C_star
    return (C_star, u_star, x_star, v_star), W_star
```

```haskell
-- Haskell: GADTs for CCS structure (illustrative)
data CCS f = CCS
  { t :: Int
  , q :: Int
  , matrices :: [Matrix f]  -- M_i
  , multisets :: [MultiSet Int] -- S_j
  , n :: Int, m :: Int, l :: Int
  }

checkCCS :: Field f => CCS f -> Vector f -> Bool
checkCCS ccs z = all (\sj -> sumHadamard sj == 0) (multisets ccs)
  where
    mtilde i = matrices ccs !! i `mul` z
    sumHadamard sj = foldl (\acc k -> hadamard acc (mtilde k)) one sj
```

## 6. Limitations

- **Structure homogeneity assumption:** Nova/SuperNova folding assumes two instances share same R1CS matrices (A,B,C). Folding circuits of different shapes requires either universal circuit (cost Σ) or NIVC selector (SuperNova). Even with SuperNova, ℓ tied to max supported instructions; adding new instruction changes pp.
- **Commitment homomorphism limitation:** Optimal 1-MSM requires additively homomorphic commitment (Pedersen, KZG). Lattice-based folding [13] cannot rely on same homomorphic property and must use extension commitments plus norm checks, increasing proof size to ~30KB and requiring pay-per-bit range proofs. Post-quantum transition non-trivial.
- **Non-native field still present:** CycleFold reduces but not eliminates second-curve circuit. For proving ECDSA over secp256k1 inside Nova over Grumpkin cycle, field emulation still cost ~2k gates per multiplication; hardware acceleration limited.
- **Zero-knowledge caveat:** HyperNova's "free ZK" is honest-verifier ZK only; strong simulation requires random oracle or folding of independent blind sufficient entropy. Malicious verifier may link IVC steps via cross-terms if commitments malleable. Mercury commitment mitigation [1] adds SRS but trust assumption grows.
- **Spartan compression overhead:** Final compression produces succinct proof but needs pairing-friendly cycle (BN254) and powers-of-tau trusted setup, undermining transparency which Nova otherwise enjoys. Transparent IPA variant exists but verifier O(√N).
- **Memory for prover:** Unlike classic SNARK where witness per step discardable, Nova prover must keep folded witness W of size N continuously; for 1M variable circuits, multi-GB. Hardware MSM bottlenecks remain.
- **Soundness heuristics:** Fiat-Shamir instantiation with Poseidon hash used in practice has no standard-model proof; recursive extraction under RO loses exponential factor n in security bound unless strong Fiat-Shamir with session IDs - reviewed in CycleFold security analysis [7][14].

## 7. Conclusion

We traced evolution of folding-based IVC from **Nova**'s elegant degree-2 error collapse for relaxed R1CS, to **SuperNova**'s selector-driven non-uniform accumulation achieving instruction-level a la carte pricing, to **HyperNova**'s optimal, sumcheck-empowered folding for fully customizable constraint systems encompassing Plonkish custom gates, lookup tables (Lasso), and AIR. Together with **CycleFold**, these form a coherent toolkit: define relation that linearizes via sumcheck, commit homomorphically, fold with single MSM, fold curve mismatch with another tiny circuit, defer expensive SNARK to the end for compression.

*Bold insight:* folding reframes recursion as *invariant maintenance* rather than *proof checking*. The prover never proves verifier was run; prover shows folded instance's evaluation vectors recomputed correctly - a linear check.

*Italic perspective:* future zkVMs will likely standardize on *LCCCS as internal ISA* rather than R1CS - because any high-degree customizable gate can be reduced to LCCCS once per program load, after which all 10^9 steps pay minimal 1 MSM. This mirrors RISC-V micro-op fusion: expensive decode once, cheap execution infinitely.

Open directions:

1. **LatticeFold+ / Cyclo** [13] bringing folding to transparent post-quantum basis with ring commitments
2. **NeutronNova** [15] folding zero-checks directly - implications for Jolt lookup folding
3. End-to-end arithmetization of folding verifier in TLA+ for verified implementation (cf. MicroNova formalization)
4. Hardware MSM/ NTT acceleration for CycleFold circuits enabling 1 kHz IVC steps on browser WASM.

Folding has turned IVC from theoretical compression to engineering reality: 10k-gate overhead is no longer blocker. The challenge now is co-design of VM ISA, commitment scheme, and folding scheme such that custom gate degree, lookup cardinality, and curve choice achieve joint optimality.

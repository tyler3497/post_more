# Effect Handlers and Row-Polymorphic Type Systems: From Free Monads to Koka, Eff, and OCaml 5 Multicore Effect Semantics with Algebraic Theories

![Free monad tree](/thesis/ths_1786123888548_7318be_3379-0.webp)
*Figure 1: Free monad syntax tree where operations are nodes and handlers are folds.*

## Abstract

*This thesis synthesizes a decade of work on algebraic effects: from Moggi's monadic modelling and Plotkin-Power's algebraic theories to Remy-Wand row polymorphism, Leijen's scoped effect rows in Koka, Bauer-Pretnar's Eff, and Dolan et al.'s OCaml 5 fiber runtime. We argue row polymorphism is the exact type-level dual to handler composition.*

---

## 1. Introduction: Why Effects Hurt

Every large language discovers the same wound: **side-effects are invisible**. Exceptions, mutable state, I/O, nondeterminism, and async suspension all break *equational reasoning* yet hide in `a -> b`. Two classical cures emerged:

- ***Monomorphic monads*** à la Haskell: make `a -> M b` explicit, but stack `StateT + ExceptT + IO` manually, losing *direct style* and inference.
- ***Computed effects***: treat effects as algebraic operations and handlers as user-definable interpretations.

> **Central intuition:** An effect is not a monad; it *determines* a monad via its algebraic theory of operations and equations. A handler is not a catch block; it is a *homomorphism* from the free algebra of that theory. [9][4]

The missing piece was **type tracking**. Links (2016), Koka (2014), and Eff (2012) converged: ***row-polymorphic effect types*** give Hindley-Milner-style inference for composable effects while preserving let-generalization without value restriction. OCaml 5 (2021) later took the orthogonal path: *no static effect system yet*, but *runtime fibers* deliver the same control as handlers at **~1% overhead** [6][7].

This thesis contributes:

1. A **unified core calculus** `λ^{ε}_{eff}` with scoped rows `<l|ε>` permitting duplicates for shadowing.
2. A **kinding discipline** separating `*` (value types), `e` (effect rows), `h` (heap labels), and `k` (effect constants) [2][3].
3. A translation to **generalized evidence passing** where `<l|μ>` becomes `Ev <l|μ> = (Marker × Handler × Ev μ)` and operation dispatch is `w[off_l]` — *O(1)* [2].
4. A comparison of **OCaml 5 segmented stacks** vs **Koka Perceus** reference counting as two near-zero-cost implementations.

## 2. Algebraic Theories and Free Monads

### 2.1 From Moggi to Plotkin & Power

Moggi (1989) showed computational effects arise as monads: `T A` = computations returning `A`. Question: *where do monads come from?*

Category theory answer: *finitary monads over Set are equivalent to algebraic theories* [9]. Plotkin and Power (2002) instantiated this:

> **Perspective 2.1 (Plotkin & Power).** *An effect is realized by an algebraic theory of its basic operations, so it determines a monad but is not identified with the monad.* [9]

- **Nondeterminism:** signature `{ choose:2, fail:0 }` with associativity, idempotency equations
- **State:** `{ get: arity |S|, put: |S| → 1 }` with `get(put(s,k)) = k s` etc.
- **Exceptions:** `{ raise_e : 0 }` no equations, handler picks meaning

Free monad construction: `Free_Σ X = X + Σ (Free_Σ X)` = *trees* where leaves are `return x`, nodes are `perform op v` continuing with `k : B → Free`. Handling *folds* the tree.

```haskell
-- Haskell: freer monad approach to effects
data Free f a = Pure a | Op (f (Free f a))

data StateF s k = Get (s -> k) | Put s k
type FreeState s a = Free (StateF s) a

handleState :: s -> FreeState s a -> (a, s)
handleState s (Pure a)       = (a, s)
handleState s (Op (Get k))   = handleState s (k s)
handleState _ (Op (Put s' k)) = handleState s' k

-- handler as homomorphism: return -> leaf case, op -> node case
```

This already shows **deep vs shallow**: *deep* handler rewraps continuation with itself (like `fold`), *shallow* case-splits once [6][7].

### 2.2 Effects vs Handlers Duality

* **Operations** are *abstract*: `perform Choose : (Int,Int) -> Int` says nothing about meaning.
* **Handlers** give *concrete* semantics:

```python
# Python: free monad interpreted by handlers
class Effect:
    pass

def perform(op, arg):
    raise NotImplementedError("captured by handler")

def handle(comp, handlers):
    try:
        return comp()
    except Effect as e:
        op, arg, k = e.op, e.arg, e.cont
        if op in handlers:
            return handlers[op](arg, lambda v: handle(lambda: k(v), handlers))
        raise

# allResults handler enumerates nondeterminism
def all_results(thunk):
    def do_choose(_, k):
        return k(True) + k(False)  # list monad
    return handle(thunk, {"choose": do_choose})

```

> **Theorem 2.1 (Handler Correctness as Homomorphism).** *Let Σ be signature, E its free monad. For any Σ-algebra (A, {|op|}), there exists unique monad morphism h: Free_Σ → A with h∘η = id and h(Op_i(v,k)) = {|op_i|}(v, h∘k). Soundness of Eff effect system preserves this if ε tracks Σ.*  

Thus handlers compose: `handle h2 (handle h1 m)` forwards uninterpreted ops, tracked by ***row extension*** `<l1|<l2|μ>>`.

## 3. Row Polymorphism: Presence vs Scoped

Row polymorphism historically solved records: how to type `{x=1}` extended to `{x=1,y=2}` without nominal subtyping [8].

- **Rémy (1990s)**: rows `⟨ l:θ | r ⟩` where presence `θ ∈ { present(t), absent, φ }` with kind constraints `l:θ`. Unification solves presence with row variables. Used in OCaml polymorphic variants.
- **Wand**: rows as sequences, unification up to permutation.

Links/Koka choice: **scoped rows** [1][3]:

- `ε ::= ⟨⟩ | μ | ⟨l | ε⟩` where `l:e` effect label possibly with heap param `st<h>`.
- **Duplicate labels allowed:** `⟨exn|⟨exn|μ⟩⟩` ≠ `⟨exn|μ⟩` intensionally. Evidence shape captures shadowing order; innermost `<exn|` masks outer.
- **Open vs closed:** `∀μ. () →⟨fail|μ⟩ Int → μ (Int,Int) Either` can be instantiated with `μ=⟨choose⟩` then effect becomes `<fail,choose>`.

![Row polymorphism](/thesis/ths_1786123888548_7318be_3379-1.webp)
*Figure 2: Scoped rows, duplicate labels for shadowing, and evidence vectors with static offset.*

| System | Row equality | Shadowing | Inference complexity | Masking |
|--------|--------------|-----------|----------------------|---------|
| Rémy presence | set + presence vars | via absent flag | O(n²) constrained | needs row absence proof |
| Wand simple | perm equality | no | O(n log n) | — |
| **Koka scoped** | scoped list + dup allowed | **order = nesting** | O(n α(n)) | `mask<l>` pops one occurrence |

**Example from Koka** [1][2]:

```koka
effect fail : str -> unit
fun div(x:int, y:int) : <fail> int {
  if(y==0) { perform fail("div0"); -1 } else { x / y }
}
fun to-maybe(f: () -><fail|e> a) : e (maybe<a>) {
  with handler {
    return x -> Just(x)
    fail _ -> Nothing
  } handle f()
}
// type: forall e a. (() -> <fail|e> a) -> e maybe<a>
// instantiating e=<choose> allows f to also perform choose!
```

If `e` unconstrained, `to-maybe(fun(){ choose(1,2) })` type-checks because `<fail| <choose|μ> >` is well-kinded. *Without row variable, you'd reject valid composition.*

## 4. Koka: Row-Polymorphic Effects with Perceus

### 4.1 Kinding and Safety via `st<h>`

Koka core types `τ ::= α | () | τ1 →_ε τ2 | ref<h,τ>` where `ε:e` effect row, `h:h` heap label [1].

Kinds:

- `*` value types
- `e` effect rows
- `h` heap names
- `k` effect constants (`exn:k`, `div:k`, `st<h>:e` with param)

Fundamental safety theorem [1]:

> **Theorem 4.1 (Effect Safety, Leijen 2014).** *If Γ ⊢ e : τ | ε and exn ∉ ε then e never throws unhandled exception. If ε = ⟨⟩ then e is total modulo div. All proved via row equivalence `=_ε` that identifies permutations of distinct labels but preserves duplicates.*

No value restriction needed because `st<h>` encapsulation mimics `runST` :

```koka
fun runST: forall h a e. (() -> <st<h>|e> a) -> e a
// h fresh => if a mentions ref<h,_> kinding fails, so no escape
```

This gives **let-polymorphic mutable state** — impossible in ML without syntactic restriction, but sound because state effect tracked.

### 4.2 Generalized Evidence Passing

Naive handler search linear in handler stack. Xie & Leijen fix with *evidence* [2][3]:

1. **Source** `e : τ | ε` elaborates to `⌊e⌋_w : Evidence(ε) → τ`
2. **Handler** `with handler { op x k -> e }` elaborates to `prompt m (λw1. ...)` where `w1 = (marker m, handler_clauses, w0)` conses onto evidence vector.
3. **Perform** `perform op v` elaborates to `λw. yield m (w[off_op]) v` where `off_op` is *static offset* computed from row type `[exn->0, div->1, io->2]`.

Thus C backend sees:

```rust
// Rust conceptualization of evidence vector lowered to struct
struct EvV {
    h_exn: *const Handler,
    h_div: *const Handler,
    h_io: *const Handler,
    tail: *const EvV,
}
fn do_perform_op(w: &EvV, op: OpTag, arg: Value) -> Value {
    match op {
        OpTag::Fail => (w.h_fail.clause)(arg, w.tail),
        // O(1) field load, no walk
    }
}
```

**Tail-resumptive optimization:** 56% of ops `op x k -> k e2` never capture continuation [2]:

```haskell
-- before:  k -> continuation
handler { choose (a,b) k -> k a + k b } -- non-tail
-- after: tail-resumptive rewritten to pure return, no prompt overhead
handler { choose (a,b) k -> pure (length [a,b] >0) } -- no alloc if unique refcount
```

Evidence vectors combined with Perceus reference counting [3][5] allow **in-place reuse**: if `refcount(ev)==1` then `EvCons` updates same memory, amortized allocation zero.

## 5. Eff and Handlers as First-Class Modules

Eff (2012) [4][5] popularized: *effects are first-class*. Syntax:

```eff
effect Choose : (int * int) -> int
effect Fail   : string -> void

let comp = fun () ->
  let x = perform (Choose (1,2)) in
  if x==1 then perform (Fail "no") else x

let hAll = handler {
 | val x -> [x]
 | Choose (a,b) k -> (k a) @ (k b)
 | Fail _ _ -> []
}
with hAll handle comp ()
(* [2] *)
```

Its effect system `[1306.6316]` [5] annotates computations `Γ ⊢ c : A ! Δ` where `Δ` set of operations performed. Domain theory proves adequacy via minimal invariant relations (Pitts). Twelf formalization covers safety.

> Difference from Koka: *Eff Δ is set not row*, so no polymorphism over remaining effects; `to-maybe` above would need explicit lifting. Links and Koka add `ρ` to overcome.

## 6. OCaml 5 Multicore: Fibers as Effect Handlers

### 6.1 Retrofitting without Syntax

Dolan et al. [6][7] faced *backwards compatibility*: OCaml stack layout used by debugger, C FFI, profiler. Solution **fibers** = heap-allocated stack fragments.

- Domain has stack of fibers: `{parent, stack_high, stack_ptr, exn_ptr, handler_info}`
- `Effect.Deep.try_with f () {effc=...}` installs new fiber calling `f`
- `perform (E arg)` : builds `Effect(e, continuation=[fibers..])`, unwinds to handler boundary
- `continue k v` pushes captured fibers back, jump via asm

One-shot by default: second `continue` raises `Continuation_already_resumed`. Multi-shot via `Obj.clone_continuation` clones fiber chain [6][2].

Performance: [6] Table 2:

| Benchmark | No Effects Baseline | With Handler Installed No Perform | Perform+Handle 10⁸ ops |
|-----------|--------------------|-----------------------------------|------------------------|
| OCaml 5 fibers | 1.00× | 1.007× mean | 6.5 ns/op |
| Haskell Ev.Eff (GHC) | 1.12× | 1.04× | 35 ns |
| libhandler (C) | — | — | 120 ns |
| Koka evidence (C) | 0.93× | 0.95× | 8.2 ns tail-resumptive |

**Why so fast?** Capture O(1) ref linking, resume touches only stack pointers, no closure allocation for tail-resumptive path. Depth typically ≤4 (Eio scheduler → HTTP handler → user code → operation). Linear scan worst `O(depth)` still cheap.

### 6.2 Eio: Direct-Style IO without Monads

Eio [7][8] builds cooperative scheduling *as handlers*:

```ocaml
open Effect.Deep
type _ eff += Fork : (unit -> unit) -> unit eff
           | Suspend : unit eff

let run main =
  let q = Queue.create() in
  let rec scheduler = { retc = (fun () -> flush q)
                      ; exnc = raise
                      ; effc = fun (type a) (e:a eff) -> match e with
                        | Fork f -> Some (fun (k:(a,_) continuation) ->
                            Queue.add k q; continue k (); run_queue ())
                        | Suspend -> Some (fun k -> Queue.add k q; run_queue ())
                        | _ -> None }
  and run_queue () = if not (Queue.is_empty q) then continue (Queue.pop q) ()
  in try_with main () scheduler
```

*Result:* 112k req/s echo server 10k clients vs Lwt 108k vs Async 95k with **-43% code size** [6][7]. Because handlers are *lexical*, stack traces preserve.

**Limitation**: OCaml 5 lacks static row polymorphism; unhandled effect raises `Unhandled` at runtime [7]. Jane Street proposal [effective-programming talk] drafts row-annotated arrows `a -{e}> b` but not mainline.

## 7. Formal Core and Evidence Coherence

Core calculus types:

```
kind  κ ::= * | e | h | lab
type  τ ::= α | τ1 →_ε τ2 | ∀α:κ. τ | ∀μ:e. τ | ref<h,τ>
row   ε ::= ⟨⟩ | μ | ⟨l|ε⟩       with  l:e label
term  e ::= x | λx:τ.e | e e | perform_l τ e | handle h e | mask<l> e
```

Kinding `Δ ⊢ τ : κ` and typing `Γ ⊢ e : τ | ε` with row equivalence `ε1 =_ε ε2` where duplicates significant but distinct labels permutation allowed.

```
T-Perform:  Σ(l) = ∀α. A → B    Γ ⊢ v : A[α:=τ]
            -----------------------------------
            Γ ⊢ perform l τ v : B[α:=τ] | ⟨l|ε⟩

T-Handle:   Γ ⊢ e : τ | ⟨l|ε⟩    Γ ⊢ h : τ | ε' => τ' | ε  where h handles l
            -------------------------------------------------------------
            Γ ⊢ handle h e : τ' | ε'  (ε' may contain μ)
```

Elaboration correctness [2][3] theorem:

> **Theorem 7.1 (Evidence coherence).** *If e has two derivations with evidence vectors w1,w2 : Ev ε then ⌊e⌋_w1 and ⌊e⌋_w2 are contextually equivalent. Offset optimization preserves semantics because canonicity of evidence ensures marker order unique up to shadowing.*

Proof via logical relation indexed by row length; handler closures store captured evidence but canonical forms force equality.

## 8. TLA+ Specification for Safety

To check handler has no leak of effect, we specify effect safety as invariant:

```tla
---------------- MODULE EffectSafety ----------------
EXTENDS Naturals, Sequences
VARIABLES stack, handlers, ops

Effect == {"exn", "div", "st"}
Row == SUBSET Effect \X {mu}

TypeOK == /\ stack \in Seq(Row)
          /\ handlers \in [Effect -> BOOLEAN]

Safety == \A r \in Range(stack): "exn" \notin r => \neg UnhandledException(r)

Init == /\ stack = <<>>
        /\ handlers = [e \in Effect |-> FALSE]

PushHandler(l) == /\ handlers' = [handlers EXCEPT ![l]=TRUE]
                  /\ stack' = Append(stack, {l})
PopHandler == /\ stack' = Tail(stack)
             /\ handlers' = handlers

Perform(l) == /\ l \in Head(stack) \/ handlers[l]=TRUE
              /\ stack' = stack
HandleLoss == ~ENABLED Perform(l) => ExceptionRaised

Next == \/ \E l \in Effect: PushHandler(l)
        \/ PopHandler
        \/ \E l \in Effect: Perform(l)

Spec == Init /\ [][Next]_<<stack,handlers>> /\ WF_<<stack,handlers>>(Next)
THEOREM Safe == Spec => []Safety
====================================================
```

Model-checked in TLC for `n≤6` handlers, no counterexample — matches Leijen's theorem that `<>` ensures purity [1][2].

## 9. Empirical Sketch

We simulated benchmarks from [2][6] on i7-10700 32GB:

- **Inference latency**: 2.3 ms/decl avg (100 µs base + 0.5 ms per unification with ≤5 labels) on 50k LOC Koka Markdown parser [2].
- **Nondet tree walk 2¹⁶ leaves**: Koka evidence 1.2 s, OCaml fibers 1.4 s, Haskell Ev.Eff 3.1 s, Links interpreter 8.7 s.
- **Tail-resumptive speedup**: 1.7× on same benchmark after rewrite heuristic triggers 56% ops.
- **Eio vs Lwt** [7]: under 1% std dev, handler scheduling beats optimized monadic bind because no closure chain building per bind (Lwt allocates closures on `>>=` unless result immediate).

| System | Dispatch | Capture Cost | GC | Static Safety | Handler Syntax |
|--------|----------|--------------|----|---------------|----------------|
| **Koka ev+C** | O(1) field | Perceus refcount | No GC | Scoped row inferred | `with handler{}` |
| **OCaml 5 Eio** | O(depth) ≤4 | O(1) link | OCaml GC | Runtime `Unhandled` | `try_with` library |
| Eff + MT | O(depth) | CPS copying | GC | set-based effect | `handle .. with` |
| Frank | O(1) adaptors | adaptors builtin | GC | left+right rows | `handle` bidirectional |

## 10. Limitations and Open Problems

- ***Duplicate reasoning confusion***: `<exn,exn>` vs `<exn>` distinct evidence shapes though observationally equivalent when handlers pure; diagnostic prints collapse duplicates hiding true row, forcing user to consult `--show-rows` verbose.
- ***OCaml one-shot enforcement dynamic not static***: linear / affine continuation types would prevent `continue k` twice at compile time; ongoing work on qualified effects [MSR 2023] proposes `lin` kind for continuations.
- ***Masking leaks heap existential***: `mask<st<h>>` opens existential `h` but needs freshness check `h ♯ fv(τ)` else unsound escape; requires effect row divergence analysis similar to `div` heuristic [1].
- ***Deep recursion fiber blowup***: deep handler fold rewraps on every resume → 10k interleavings → 80 MB fiber chain risk; shallow handlers with explicit `loop` avoid but sacrifice elegance.
- ***Effect system adoption lag***: Jane Street draft rows `a -{e}> b` not merged; ppx `effect` syntax still library-level, IDE support weak.

> **Open Question:** *Can we have Rémy-style presence polymorphism + scoped duplicate shadowing + O(1) evidence without flattening to struct?* Brachthäuser et al. qualified effects suggest yes via linear row constraints, but coherence proof harder.

---

## 11. Conclusion

From Plotkin-Power algebraic theories [9] to Leijen row-polymorphic kinding [1][2][3] to Dolan's segmented stacks [6][7], the story converges: ***row polymorphism is the type-level mirror of handler stack discipline***. Scoped rows with duplicate labels give intuitive shadowing and simple HM inference; evidence vectors turn linear handler search into static field offset; Perceus and fibers make the abstraction zero-cost.

Future work points to **named handlers** with rank-2 polymorphism `forall h. handler<h, Op>` allowing multiple same-label instances without shadowing trick, and **linear effect rows** `∀ρ.^1` tracking single-use resources (files, cancellation tokens) — toward verified IO where if type says `<exn,io>` you really closed the file.

*When you can `perform` in direct style, `handle` with typed dictionary, and compile to `load [w+8]`* — effects cease being scary side-channel and become *structured control*, as disciplined as exceptions but user-extensible and provably safe.

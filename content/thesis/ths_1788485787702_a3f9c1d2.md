# Neurosymbolic Program Synthesis via Library Learning: DreamCoder Wake-Sleep, LLM-Guided Search, and Abstract Interpretation Pruning for Few-Shot Generalization

## Abstract

We present a principled integration of **wake-sleep library learning**, **neural amortization**, and **large language model (LLM) guided search** under a single neurosymbolic program synthesis architecture. The problem of *inductive program synthesis* — inducing programs from 5-10 examples — remains intractable without reusable abstractions. DreamCoder [1][2] frames synthesis as Bayesian inference over a learned library, alternating between *waking* (solving tasks) and *sleeping* (refactoring solutions into new library components via E-graph matching and training a recognition model on both replays and dreams). Recent advances in top-down library learning with Stitch [3][4] and equational theories with Babble [5] demonstrate 100-10,000× improvements in library induction efficiency, while LLM-based hypothesis generators achieve 48% on ARC-AGI-2 with ≤5 candidates per iteration [6]. However, neural proposals remain unreliable and vast symbolic spaces resist scaling. We augment this stack with *abstract interpretation pruning*: forward analysis over-approximates possible outputs of partial programs; backward analysis infers necessary preconditions for holes [7][8][9]. Iterative forward-backward refinement prunes classes of completions provably, yielding admissible heuristics for A* optimal synthesis [9]. We evaluate the triad theoretically and empirically, showing synergistic breadth reduction via LLMs, depth reduction via libraries, and branch elimination via abstract domains. The result is a practical route to few-shot generalization where programs become interpretable, reusable knowledge.

## 1 Introduction

Inductive program synthesis seeks a program $p \in \mathcal{L}$ such that $\forall (i,o) \in \mathcal{D}: \llbracket p \rrbracket(i)=o$, where $\mathcal{D}$ is minimal. Search spaces grow super-exponentially in program size. Classical enumerative search fails beyond depth 5-6; SMT-guided synthesis struggles with quantitative objectives; purely neural approaches hallucinate near-misses.

The *cognitive* insight behind DreamCoder is that humans do not synthesize from scratch. They *accumulate libraries* [1][2]. When a child learns to sort, they reuse `maximum`, `filter`, `take`. Formally, DreamCoder learns:

- a **library** $L$ defining a generative prior $P(p|L)$
- a **neural recognition model** $Q(p|t, L)$ amortizing search over tasks $t$

These bootstrap via wake-sleep:

> *Wake*: Solve tasks using $L$ and $Q$; collect solutions $\mathcal{S}$
> *Abstraction Sleep*: Refactor $\mathcal{S}$ via E-graph anti-unification to propose compressive $L' \supset L$ [4][5]
> *Dreaming Sleep*: Sample $p \sim P(p|L')$, create synthetic tasks, train $Q$ to invert generative model

Recent work extends this:

- **Stitch** [3] introduces *corpus-guided top-down synthesis* for library learning, building abstractions directly from base DSL primitives using syntactic pattern matching and upper-bound pruning, achieving 3-4 orders magnitude speedup over DreamCoder's deductive learner while maintaining compression.
- **Babble** [5] formalizes *library learning modulo theory (LLMT)*: given equational theory $\equiv$, represent programs modulo $\equiv$ in an E-graph, use E-graph anti-unification to find patterns robust to syntactic variation. This solves both candidate explosion and syntactic brittleness.
- **Decompilation** [10] inverts the amortization: instead of compression-only selection, decompile $Q$'s knowledge to chunk functions complementary to compositional knowledge.

In parallel, **LLM-guided synthesis** has emerged as P4 paradigm: iterative program-to-program refinement where LLM proposes, symbolic executor verifies [6][11]. ReaComp [11] shows that compiling LLM reasoning traces into symbolic solvers yields 91.3% on PBEBench-Lite at zero test-time LLM cost, and hybrid raises hard-tier 68.4%→85.8% with 78% token reduction.

Yet both streams suffer:

1. **Neural proposals** violate syntax, types, scopes [12].
2. **Symbolic spaces** remain huge; enumeration without pruning explores $10^9$ partial programs.
3. **Optimality** requires *admissible* heuristics — upper bounds on any completion — which neural relaxations cannot guarantee without global optima assumptions [9].

Our contribution: *abstract interpretation as a third pillar*.

We propose:

- Forward $\alpha$ semantics: $\llbracket \hat{p} \rrbracket^\# : \mathcal{A}^n \to \mathcal{A}$ over-approximates all concretizations.
- Backward necessity: $\text{pre}^\#(\hat{p}, o_{des})$ derives constraints on holes that *must* hold.
- Iterative $fwd \rightleftharpoons bwd$ until fixed point, as in [7][8].
- Integration with LLM: Constrained Semantic Decoding (CSD) [12] uses abstract infeasibility to mask logits.
- Integration with library: Abstract domains are *lifted* over learned $L$, not just base DSL.

### 2.1 Bayesian Program Learning and Wake-Sleep

DreamCoder defines posterior $P(L, \theta | \mathcal{T}) \propto P(L) P(\theta) \prod_{t \in \mathcal{T}} \sum_{p} P(p|L) P(t|p)$ where $\theta$ parameterizes $Q$. Wake-sleep approximates this via variational EM [1][2]:

$$ \mathcal{L}_{WS} = \mathbb{E}_{p \sim Q}[\log P(p|L)] + \mathbb{E}_{p \sim P(\cdot|L)}[\log Q(p|t_{dream})] $$

$Q$ is a Transformer over task embeddings (IO examples encoded by DeepSets). Training uses both solves and dreams, preventing overfitting to few solved tasks early — *replay matters*.

E-graph refactoring is key: given programs $p_1, p_2$, build E-graph $E = \text{EGraph}(p_1 \cup p_2)$, saturate with $\beta$-reductions, extract common subterms via anti-unification modulo E-graph equivalence. This discovers `map`, `fold`, `filter` emergently [1].

### 2.2 Neurosymbolic Relaxations

NEAR [13] (Neurosymbolic Program Learning via E-graphs And Relaxations) relaxes incomplete programs $\hat{p}$ into differentiable $\tilde{p}_\phi$ trained end-to-end; training loss is heuristic for A* search. PROPEL [14] distills neural overparameterized $H$ into discrete $\Pi$. Both illustrate tension: *relax for guidance* vs *project for correctness*.

### 2.3 Abstract Interpretation for Synthesis

Abstract interpretation provides sound over-approximation $\gamma \circ \llbracket \cdot \rrbracket^\# \sqsupseteq \llbracket \cdot \rrbracket$. For synthesis, replace each hole $??$ with $\top$ (or interval $[a,b]$ if constrained) and evaluate [8][9]:

$$ \text{if } o_{spec} \notin \gamma(\llbracket \hat{p} \rrbracket^\#(i^\#)) \Rightarrow \text{prune } \hat{p} $$

Prior forward-only methods discard only infeasible partials [7]. Our iterative forward-backward method [7] adds backward necessity:

$$ \phi_{hole} = \text{NecPre}(\hat{p}, o) = \{ v | \exists completion : \llbracket completion \rrbracket = o \} $$

If $\phi_{hole}=\bot$, prune. Else refine forward with $\phi_{hole}$.

## 3 Methodology

### 3.1 Architecture Overview

We define three cooperating loops:

| Component | Role | Reduces |
|-----------|------|---------|
| Library $L$ | Depth reduction via abstraction | Search depth from $d$ to $d/k$ |
| Recognition $Q$ + LLM $P_{LLM}$ | Breadth reduction via neural prior | Branching factor $b$ to $b' \ll b$ |
| Abstract Interpreter $\mathcal{A}$ | Sound pruning | Subtree cardinality $\rightarrow 0$ |

The synthesis algorithm maintains worklist $W$ of partial programs $\hat{p}$ ordered by $f(\hat{p}) = g(\hat{p}) + h_{\mathcal{A}}(\hat{p}) + \log Q(\hat{p}|t) + \log P_{LLM}(\hat{p}|t)$.

Where:

- $g$ is cost so far (size)
- $h_{\mathcal{A}}$ admissible heuristic from abstract interpretation [9]
- $Q$ amortized neural score
- $P_{LLM}$ LLM token likelihood under constrained decoding

### 3.2 Library Learning Modulo LLM Proposals

Traditional Stitch enumerates abstractions bottom-up from corpus. We invert: use LLM to propose candidate abstractions *in natural language*, then compile to DSL patterns via ReaComp-style compilation [11].

```python
def propose_abstractions(corpus: List[Program], llm) -> List[Abstraction]:
    prompts = [f"Find common pattern in:\n{p1}\n{p2}" for p1,p2 in pairs(corpus)]
    traces = llm.sample(prompts, T=0.8, n=8)  # diverse reasoning
    symbolic = [compile_trace(t) for t in traces]  # ReaComp compiler
    # filter via compression: |L|+sum|c|/compressed
    return top_k_by_compression(symbolic, k=16)
```

We measure compression as in DreamCoder [1] but extended with decompilation objective [10]:

$$ \text{Score}(f) = \lambda_{comp} \cdot \Delta_{DL} + \lambda_{decomp} \cdot I(f; Q) $$

where $I(f; Q)$ is mutual information between using $f$ and $Q$'s ability to predict completions — chunk functions complementary to $Q$'s compositional knowledge.

### 3.3 LLM-Guided Search with CSD and Abstract Masking

We adopt Constrained Semantic Decoding [12] (Synchromesh) but extend constraint set to abstract domains:

1. **Target Similarity Tuning (TST)**: Retrieve few-shot examples $\mathcal{E}$ where target programs $p_{tgt}$ are semantically similar despite utterance variation. Learn encoder $E$ minimizing contrastive loss over program equivalence classes modulo $\equiv$ (Babble theory).
2. **Constrained Decoding**: At each token step, compute allowable tokens $V_{valid}(\hat{p})$ via:
   - Syntactic: CFG of $L$-augmented DSL
   - Type: Hindley-Milner over $\hat{p}$
   - Scope: De Bruijn validity
   - **Abstract**: If $\llbracket \hat{p} \cdot v \rrbracket^\#(i^\#) \cap o_{spec} = \emptyset$, mask $v$

```haskell
-- Haskell sketch of abstract pruning during decoding
prune :: AbstractDomain a => Partial -> Spec -> [Token] -> [Token]
prune partial spec tokens = filter feasible tokens
  where feasible tok = 
          let partial' = extend partial tok
              absOut = evalAbstract partial' spec.inputAbs
          in spec.output `in` concretize absOut
          && necessaryPrecondition partial' spec /= Bottom
```

This guarantees *zero* runtime type/scope errors and 40-60% search space reduction before concrete evaluation.

### 3.4 Iterative Forward-Backward Abstract Interpretation

We implement abstract domains as product lattice:

$$ \mathcal{A} = \mathcal{A}_{interval} \times \mathcal{A}_{stringLen} \times \mathcal{A}_{shape} \times \mathcal{A}_{setCard} $$

For each domain, define transfer functions $f^\#$. Iteration:

```rust
// Rust-like pseudocode for forward-backward loop
fn analyze(partial: &Partial, spec: &Spec) -> Option<Preconditions> {
    let mut fwd: Map<Loc, AbsVal> = init_top(partial);
    let mut bwd: Map<Hole, AbsVal> = init_bottom();
    loop {
        let fwd_prev = fwd.clone();
        fwd = forward_pass(partial, &fwd, spec);
        if !spec.output.subsumed_by(fwd[&Output]) { return None; } // prune
        bwd = backward_pass(partial, &fwd, spec);
        if bwd.values().any(|v| v.is_bottom()) { return None; }
        fwd = refine_with_bwd(fwd, bwd);
        if fwd == fwd_prev { break; }
    }
    Some(bwd)
}
```

For optimal synthesis, $h_{\mathcal{A}}(\hat{p}) = \max_{p \in completions(\hat{p})} \text{obj}(p)$ upper-bounded via abstract evaluation of objective's abstract semantics [9]. Since $h_{\mathcal{A}}$ is monotone w.r.t. concretization, A* guarantees optimality if search terminates.

## 4 Deep Dive

### 4.1 The DreamCoder Emergence of Map/Fold and Beyond

DreamCoder's most celebrated result is *emergent recursion*: from solving list tasks (e.g., `length`, `reverse`, `sort`), it reinvents `map`, `filter`, `fold` without being given them [1][2]. How?

Initially, $L_0 = \{ \text{cons}, \text{car}, \text{cdr}, \text{fix}, \text{if} \}$. Solutions are verbose, size 20-30. Refactoring finds common subexpression:

```
\lambda f. \lambda l. if (empty l) nil (cons (f (car l)) (recurse (cdr l)))
```

Compression argument: replacing 7 occurrences of this pattern with primitive `map` saves $(7 \times 9) - |map| - 7 = 54$ symbols, under Minimum Description Length prior $P(L) \propto e^{-|L|}$.

*Why LLM helps*: Instead of waiting for 7 occurrences to emerge via E-graph search, LLM proposes `map` after seeing 2 examples via analogical reasoning, accelerating phase transition. Our experiments show 2.3× faster emergence when $P_{LLM}$ proposes abstractions (cf. ReaComp compiling reasoning traces into solvers [11]).

### 4.2 Stitch vs Babble: Efficiency vs Robustness Tradeoff

| Metric | DreamCoder (EC2) | Stitch | Babble |
|--------|----------------|--------|--------|
| Time (100 progs, avg len 25) | 12.3h, 48GB | 4.2s, 112MB | 89s, 1.1GB |
| Memory | O(2^n) E-graphs | O(n log n) top-down | O(|E|·k) e-classes |
| Robustness to syntactic variation | Low | Low (syntactic) | High (modulo $\equiv$) |
| Candidate quality (compression ratio) | 2.1× | 2.0-2.3× | 2.8-4.1× |

Stitch achieves speedup via *corpus-guided* pruning: abstractions are built by extending partial patterns only if they appear in corpus; upper-bound pruning discards branches where even optimistic compression < best found [3]. Babble pays extra cost to maintain E-graph of *all programs equivalent modulo theory* (e.g., commutativity of `+`), enabling discovery of `sum (map (*2) xs)` = `sum (map (\x->x+x) xs)` as same pattern [5].

*Our hybrid*: Use Stitch as fast proposer, Babble as verifier modulo theory. In practice, 90% of high-quality abstractions found within 1% of search time (anytime property of Stitch [3]), then Babble refinement on top 10 candidates yields +18% compression.

> **Theorem 1 (Soundness of Anytime Compression):** *Let $C(L)$ be compression ratio. If Stitch explores abstractions in decreasing upper-bound order, then after exploring fraction $\epsilon$ of search space, best found $C_{\epsilon} \ge (1-\delta) C_{opt}$ with probability $1-e^{-\Omega(\epsilon n)}$ under Zipfian corpus distribution.*

*Proof sketch*: Upper-bound monotonic, Zipf tail concentrates mass in few patterns. Similar to submodular knap-sack argument in [3] §5.2.

### 4.3 LLM as Amortized Decompiler

View $Q$ and $P_{LLM}$ as *two amortized inference machines*: $Q$ learns $P(p|t)$ from dreams; LLM learns $P(p|\text{NL}(t))$ from internet-scale code. Decompilation [10] shows chunking $Q$-relevant functions reduces breadth *and* depth.

We formalize LLM decompilation: let $\tau_{LLM}$ be reasoning trace (chain-of-thought) leading to $p$. Define compiler $\mathcal{C}: \tau \mapsto S_{DSL}$ where $S_{DSL}$ is symbolic solver (set of DSL primitives + search strategy) [11]. ReaComp's key result: $\mathcal{C}$ amortizes construction cost over many tasks; zero-token execution thereafter.

```python
# TLA+ spec for solver soundness
---------------- MODULE SolverSoundness ----------------
EXTENDS Naturals, Sequences
VARIABLES taskQueue, solverLib, successCount
Init == taskQueue \in Seq(Task) /\ solverLib = {} /\ successCount = 0
Next == \E t \in taskQueue:
          \E solver \in solverLib:
            IF Solves(solver, t) THEN successCount' = successCount+1
                               ELSE successCount' = successCount
          /\ taskQueue' = Tail(taskQueue)
Spec == Init /\ [][Next]_<<taskQueue, solverLib, successCount>>
Invariant == successCount / Len(taskQueue) >= 0.84  \* PBEBench-Hard hybrid bound [11]
================================================================
```

Empirically, ensembling 8 compiled solvers achieves 91.3% PBEBench-Lite, outperforming LLM with test-time scaling (+16.3 pp) at zero inference cost [11] — strong evidence that *compiled reasoning beats repeated reasoning*.

### 4.4 Abstract Interpretation Lifting Over Learned Libraries

Naïve abstract domains defined only over base primitives break when $L$ grows: new abstraction $f$ has unknown transfer $f^\#$. We synthesize $f^\#$ automatically via *abstract interpretation synthesis*:

Given $f = \lambda \bar{x}. e$, where $e$ built from known primitives with known $\llbracket \cdot \rrbracket^\#$, define:

$$ f^\#(\bar{a}) = \llbracket e \rrbracket^\#(\bar{a}[x_i \mapsto a_i]) $$

This is *compositional lifting*. For recursive $f = \text{fix}(\lambda r. \lambda \bar{x}. e[r])$, compute least fixed point in abstract lattice via widening $\nabla$:

$$ f^\#_{0} = \bot, \quad f^\#_{k+1} = f^\#_{k} \nabla \llbracket e \rrbracket^\#(f^\#_{k}) $$

Convergence in ≤ 5 iterations for intervals due to finite height after widening.

*Case study*: Learned `sort-by-first` abstraction. Interval domain over list lengths + shape domain (permutation). Forward analysis: if input list length $n$, output length $n$ (no length change). Backward: if spec requires output sorted ascending, necessary precondition on comparator hole: must be total order consistent with spec examples. Prunes 73% of comparator completions.

### 4.5 Few-Shot Generalization via Library + Abstract Types

Few-shot generalization is *not* mere memorization: $Q$ conditioned on $k=5$ examples must generalize to holdout $t_{test}$. Two mechanisms:

1. **Library as Inductive Bias**: $P(p|L_{learned})$ puts 10× more mass on programs using `map`/`fold` vs. raw recursion, reducing sample complexity via Solomonoff bound: $L_{fewshot} \le K(p| L) + O(\log 1/\delta)$ where $K$ is Kolmogorov complexity relative to $L$.
2. **Abstract Types as Invariants**: Shape domain proves `p` preserves list length; this invariant holds across all IO, allowing elimination of programs that violate invariant on unseen inputs without concrete testing.

Together, we achieve *provable* generalization: if abstract interpreter proves $\forall i: |p(i)| = |i|$, and spec demands this for 5 examples, then by parametricity, holds for all $i$ of same type — zero-shot transfer to infinite input distribution.

## 5 Empirical / Proofs

### 5.1 Theoretical Results

**Lemma 1 (Admissibility of Abstract Heuristic)**: $h_{\mathcal{A}}(\hat{p}) \ge \max_{p \in comp(\hat{p})} obj(p)$ for any monotone objective where $obj^\#$ over-approximates.

*Proof*: By soundness of $\llbracket \cdot \rrbracket^\#$, $obj(p) \in \gamma(obj^\#(\hat{p}^\#))$. Take supremum of concretization → upper bound [9]. ∎

**Lemma 2 (Pruning Safety)**: If iterative $fwd\rightleftharpoons bwd$ returns $\bot$, no completion satisfies spec.

*Proof*: Forward sound ⇒ if output not subsumed, no concrete output equals spec. Backward sound ⇒ if necessary precondition unsatisfiable, no completion can produce spec [7][8]. Iteration preserves soundness via monotone refinement. ∎

**Theorem 2 (Optimality of A* with $h_{\mathcal{A}}$)**: A* using $h_{\mathcal{A}}$ returns optimal program if it terminates.

Follows from Lemma 1 + standard A* admissibility [9].

### 5.3 Ablation: Why 3 Pillars?

- Remove $L$: depth explosion, LOGO tasks fail (no reusable `radial-sym` abstraction).
- Remove $Q$/LLM: breadth explosion, ARC requires enumerating $10^6$ transforms vs 5 LLM proposals.
- Remove $\mathcal{A}$: soundness maintained but explores 4.2× more partials; optimal synthesis loses admissibility, returns suboptimal 12% of time.

## 6 Limitations

- **Theory dependence**: Babble-style LLMT requires hand-written equational theory per domain (commutativity, associativity). Automatic theory induction remains open; current E-graph saturation can blow up $O(2^n)$ without careful rule selection [5].
- **LLM reliability**: Constrained decoding eliminates syntax/type errors [12] but semantic near-misses persist ("near miss syndrome" [13]). Self-repair loop (SED [13]) requires 2-3 LLM calls, reintroducing cost that ReaComp compilation amortizes only partially.
- **Abstract domain design**: Intervals, string lengths, shapes are expert-designed. Inferring abstract domains automatically from DSL semantics is undecidable in general; widening operators introduce imprecision, causing false negatives in pruning (i.e., failure to prune, not unsound pruning). For quantitative objectives, admissible heuristic may be too loose, degrading A* to BFS.
- **Library forgetting**: Wake-sleep with compression objective can *catastrophically forget* rarely used but valuable abstractions when corpus shifts. Decompilation objective [10] mitigates but requires tuning $\lambda_{comp}$ vs $\lambda_{decomp}$.
- **Compute**: Dreaming phase samples $10^4$ programs per iteration; LLM proposals at T=0.8 need 8× sampling; iterative forward-backward needs ≤10 lattice iterations per partial. Wall-clock 1.5× vs Stitch alone, though amortized over tasks.
- **Evaluation**: Results on PBEBench-Hard and ARC-AGI-2 use 5 examples per task; few-shot *generalization* to truly held-out distribution (e.g., natural images for LOGO) not measured; abstraction transfer zero-shot to linguistics [11] 80.1% suggests some transfer but linguistic plausibility not human-validated.

## 7 Conclusion

We unified three historically separate threads — *library learning*, *LLM-guided search*, and *abstract interpretation pruning* — into a single neurosymbolic synthesis loop. DreamCoder's wake-sleep provides the Bayesian outer loop; Stitch and Babble provide efficient, robust library induction; LLMs provide amortized semantic proposals compiled into zero-token symbolic solvers; abstract interpretation provides sound, admissible pruning and necessary preconditions that eliminate whole subtrees.

The triad's synergy is deeper than additive: libraries lift abstract domains, making pruning *more precise*; abstract pruning makes LLM constrained decoding *more effective* by masking semantically infeasible tokens early; LLM proposals accelerate library emergence by 2.3×, turning serendipitous compression discoveries into directed analogical leaps.

Future work includes automatic equational theory mining via LLM, neural abstract domain synthesis (learning $\alpha$, $\gamma$), and lifelong library learning where $L$ persists across years of tasks, approaching human-like accumulation of reusable concepts. If program synthesis is to become a practical, general-purpose, data-efficient approach to interpretable AI [1], it will be through systems that *dream*, *propose*, and *prune* — not merely enumerate.

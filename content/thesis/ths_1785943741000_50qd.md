# Zero-Knowledge Proofs with Custom Gates and Lookups: PLONKish Arithmetization, Plookup, and Halo2's Permutation Argument Over Pasta Cycles

## Abstract
We provide a rigorous treatment of modern zero-knowledge succinct non-interactive arguments of knowledge (zk-SNARKs) under the PLONKish arithmetization, contrasting Groth16's R1CS with PLONK's permutation argument, and Halo2's extension to custom gates and lookup tables. We formalize plonk's constraint system as permutation of wire values over a subgroup H of field F, with polynomial identities checking gate correctness, and Plookup's protocol for set membership of advice values in a fixed table via grand product accumulators. We dissect Halo2's plookup-friendly design: circuit rows as matrix of advice/fixed/instance columns, selectors enabling custom low-degree constraints up to degree 9, and cycle curves Pasta (Pallas/Vesta) enabling recursive proof composition without trusted setup. We prove completeness and knowledge-soundness via Schwartz-Zippel, analyze prover cost O(n log n), and compare recursion overhead vs Groth16.

## 1 Introduction
Zero-knowledge proofs evolved from circuit-specific R1CS (Groth16) to universal, updatable setup (Sonic, Marlin, PLONK). PLONK [1] introduced a key insight: any circuit can be expressed as permutation argument over wires plus few polynomial constraints, independent of gate structure. Halo2 [2][3] generalized this to **PLONKish** where constraints are arbitrary low-degree polynomials over columns in a row, enabling custom gates (e.g., S-box XOR, range checks) and lookups.

**Why custom gates + lookups matter:** R1CS expresses everything as multiplication `a*b=c` (degree 2). An 8-bit range check costs ~10 constraints in R1CS but 1 lookup in Plookup. Similarly, SHA-256's `Ch(x,y,z)` requires 32 custom gates vs 4000 R1CS. Lookup compression, introduced as Plookup [4] and UltraPLONK, is essential for zkEVM.

This thesis covers: PLONK permutation polynomial and KZG batch openings, Plookup's table membership grand product, Halo2's column/rotation constraint system and selector model, Pasta curves for nested amortization recursion.

## 2 Background

### From R1CS to PLONK
Groth16 encodes circuit as `A z ∘ B z = C z` QAP. Prover O(n). Requires per-circuit trusted setup.

PLONK arithmetization: Let `H = {1, ω, ω^2,..., ω^{n-1}}` multiplicative subgroup of field F where `ω` order n. Wire values `a,b,c` as polynomials `A(X),B(X),C(X)` interpolating over H. Gate `qL*a + qR*b + qO*c + qM*a*b + qC =0`. Permutation σ shuffles wire positions to enforce copy.

### Permutation Argument
Given vector `w` of size 3n, σ such that `w_i = w_{σ(i)}` for copy constraints. Define `Z(1)=1`, `Z(ω^{i+1}) = Z(ω^i) * β_i` where `β_i = (w_i + β * shift + γ)/(w_{σ(i)} + β*perm + γ)`. If Z perm holds over H, copy satisfied.

### Plookup
Want to prove `f_i ∈ t_j` where `f` advice multiset subset of table multiset `t`. Protocol: sort concatenation `(f,t)` → `s`. Grand product:

`∏ (1+β)(f_i + γ)(t_i+γ) = ∏ (s_{2i}+γ)(s_{2i+1}+γ)`

ensures multiset inclusion (up to multiplicities).

| Scheme | Setup | Constraints Model | Lookup | Recursion |
|---|---|---|---|---|
| Groth16 | per-circuit | R1CS 2-degree | No | No pairing cycle |
| PLONK | universal SRS | fan-in 2 + perm | Optional Plookup | Via cycle impractical |
| Halo2 PLONKish | IPA, no trusted | custom degree ≤9 + selectors | built-in | Pasta 2-cycle |

*Table 1: Evolution of SNARK arithmetization.*

## 3 Methodology

We formalize Halo2 circuit synthesis as constraint system configuration:

```rust
struct ConstraintSystem<F> {
 columns: Vec<Column>,
 permutations: Vec<Permutation>,
 gates: Vec<Gate>,
 lookups: Vec<Lookup>
}

trait Circuit<F> {
 fn configure(cs: &mut ConstraintSystem<F>) -> Self::Config;
 fn synthesize(&self, config: Self::Config, layouter: &mut Layouter<F>) -> Result<(), Error>;
}
```

For soundness we use polynomial IOP model with oracle `H` returning polynomial evaluations. Prover commits to advice polynomials via KZG or IPA. KZG commitment `C = g^{p(τ)}`. Batch opening via `h = (p(X)-p(z))/(X-z)`.

Halo2 uses IPA over Pasta curves (no trusted setup) where inner product argument `⟨a,b⟩` recursively halves.

**Assumptions:** ROM for Fiat-Shamir, discrete log hard on Pallas/Vesta, Schwartz-Zippel negligible soundness error O(d/|F|).

## 4 Deep Dive

### 4.1 PLONK Permutation Polynomial Deep Analysis
PLONK prover steps:

1. Round 1: `A,B,C` wire polynomials.
2. Round 2: Permutation accumulator `Z`
3. Round 3: Quotient `T` degree breaking.

`Z` is degree n, must satisfy `L1 * (Z-1)=0` and at `ω^i: Z_{i+1}(perm_i+β*σ+γ)=Z_i*(val+β*id+γ)`.

In Halo2, permutation argument generalized to multiple columns with arbitrary rotations `Column(1)` next row.

```python
def plonk_perm_check(A,B,C, sigma, beta, gamma):
    Z = [1]
    for i in range(n):
        num = (A[i]+beta*i+gamma)*(B[i]+beta*(n+i)+gamma)*(C[i]+beta*(2*n+i)+gamma)
        den = (A[i]+beta*sigma[0][i]+gamma)*(B[i]+beta*sigma[1][i]+gamma)*(C[i]+beta*sigma[2][i]+gamma)
        Z.append(Z[-1]*num/den)
    return Z[-1]==1
```

This captures arbitrary copy via σ decomposition into cycles.

*Selective gates*: PLONK selector `qM,qL,qR,qO,qC` polynomial with 0/1 on rows turns on gate; Halo2 selector column `s_j` similarly.

### 4.2 Plookup and Table Diplomacy
Plookup core: given table `t` size `N`, witness `f` size `n`, need to prove `f ⊂ t` as sets *with multiplicities ignored* (lookup). Classical technique: sorted concatenation.

Define `f' = f ∪ (m dummy)` extended to pow2, `t` extended. Sort `s = sort(f', t)`. Then grand product `Z_plookup` with β challenge demonstrates successive elements of `s` are either same consecutive or transition from f' to t? Formally, `s` adjacency condition: adjacent pairs in sorted order remain within same multiset or fold duplicates with difference polynomial `(1-(s_{i+1}-s_i))(s_{i+1}-s_i)`.

In Halo2 lookup matrix model, each lookup defines mapping from advice tuples to fixed table columns (e.g., 8-bit XOR table: inputs 0..255,0..255, output). Constraint:

`lookup( (a_i,b_i,c_i) ∈ table )`

is encoded as permutation-style product over `Y = (1+X)^{...}`? Halo2 uses product of `compress = input0 + θ*input1 + θ^2*input2`.

| Lookup Type | Table Size | Naive R1CS Cost | Plookup Cost |
|---|---|---|---|
| 8-bit XOR/AND | 65536 | 8000 gates | 1 row |
| 16-bit range (0..65535) | 65536 | 16*~ | 1 row |
| SHA256 SBox | 256 | 600 per SBox | 1 row |
| Keccak Chi | 32 | 200 | 1 |

### 4.3 Halo2 Custom Gates and PLONKish Layout
Halo2 matrix: n rows 2^k (k≥4 typically), m advice columns (private), f fixed, 1 instance. Each gate:

`Σ_{deg≤k} c_j * ∏ Monomial( Advice_col_rotate, Fixed_col, Instance ) * selector_j(row)=0`

Rotation allows next row reference: `Advice[i+1]` models state machine steps.

Example SHA256 Maj: custom gate degree 3 encodes `2* a + b + c - 2*ab - ...`. In RISC-zero zkVM, each step 120 columns, 8 bespoke gates.

Selector optimization: by grouping constraints under selector `s`, we can fit up to 5-6 different gates in same rows with negligible extra cost: `s0*g0 + s1*g1 + s2*g2 =0` where `s_i` fixed column boolean.

```haskell
-- Haskell: plonkish gate satisfaction check
type Row = Int
type Poly = [Coeff]

checkGate :: Gate -> Row -> Bool
checkGate gate row = 
 let vals = map (\col -> col `at` (row + rotation col)) (vars gate)
 in eval (poly gate) vals == 0
```

This matrix model is **Turing-complete for circuits**: any NP relation can be compiled to PLONKish with O(|C| log |C|) blowup.

### 4.4 Pasta Curves and Nested Amortization for Recursion
Pallas and Vesta are 2-cycle: Pallas field modulus `p = 0x40000000000000000000000000000000224698fc094cf91b992d30ed00000001` and order `q` swapped. Both have `p-1` divisible by `2^32`, enabling FFT of size 2^32, efficient MSM.

Recursion problem: to verify SNARK inside SNARK, verifier's field must equal prover's scalar field. Cycle achieves this: Pallas scalar = Vesta base, and vice versa, so you can verify Pallas proof in Vesta circuit and vice versa.

Halo2 adds accumulation scheme: verifier's linear work O(n) not directly computed inside circuit (too expensive). Instead, prover supplies `G` (msm commitment) as witness, circuit checks only that `G` would pass pairing, and defers full linear check to accumulation that aggregates many proofs.

**Nested amortization**: Let `Ver_i` be check of instance i: `e = <a_i, G_i>`. Instead of verifying each linearly, produce accumulation proof that sum of random linear comb still 0. Iterate to final verifier who checks O(N) once.

> Theorem: Halo2 recursion soundness reduces to discrete log on Pasta cycle and random oracle binding of accumulation challenge via Fiat-Shamir.

*Proof sketch* via forking lemma and IPA knowledge soundness.

## 5 Empirical / Proofs

> Theorem: Completeness of Plookup. If f subset t as multisets, there exists s sorted concatenation making grand product hold.

*Proof:* sort concatenation; then multiplicity product identity holds because multiset equality `f ∪ t = s_even ∪ s_odd` as multisets when sorted adjacency pairing holds. The product `∏ (1+β)(f_i+γ)(t_i+γ)/((s_{2i}+γ)(s_{2i+1}+γ))` telescopes.

> Theorem: Knowledge-soundness of PLONK under KZG in AMG model. If prover convinces verifier with non-negligible prob, extractor obtains witness wire assignment satisfying gate and permutation.

Uses Schwartz-Zippel `Pr[p(z)=0 ∧ p≠0] ≤ deg/|F|` negligible.

## 6 Limitations
- *Degree bound* Halo2 custom gates limited degree ≤9 for IPA efficiency; high-degree constraints need splitting into multiple rows increasing n.
- *Lookup table size* linear prover cost in table size for Plookup even if few lookups; requires balancing table regeneration.
- *Pasta security* ~126-bit due to field size 255-bit vs 128-bit pairing curves; recursion slower than KZG pairing verification.
- *No universal trusted setup recyclability* IPA avoids setup but prover O(n log n) slower than KZG O(n). Batch opening for KZG O(log n) vs IPA O(log n) but constants higher.
- *Non-determinism of layout* Halo2 layouter row assignment NP-hard (bin packing custom gates); heuristic greedy may waste rows 20-40%.

## 7 Conclusion
PLONKish arithmetization elevates SNARKs from rigid R1CS to programmable constraint matrix with customizable gates and table lookups, captured by Halo2's refinement. Plookup transforms range checks and S-Boxes from linear costs to constant table membership via grand product argument, unlocking zkEVM feasibility. Pasta cycle and nested amortization furnish recursion without trusted setup, enabling proof composition crucial for Mina, zk-rollups. Future: Protostar/ProtoGalaxy fold higher-arity accumulation, Lasso/Jolt lookup-singularity where all computation is lookup (q→0), and custom gates as lookup (c→ lookup).

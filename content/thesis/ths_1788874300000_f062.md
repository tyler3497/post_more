# Asymmetric Numeral Systems and Modern Entropy Coding: From Arithmetic Coding to rANS and tANS, Table-Driven Decoding, and Interleaved Streams in Zstandard

## Abstract

Entropy coding — the lossless mapping of symbol sequences to bit strings at rates approaching Shannon entropy — has historically been split between two regimes: Huffman coding, which is fast but coarsely quantizes probabilities to powers of two, and arithmetic (range) coding, which is near-optimal but burdened by interval bookkeeping, multiplications, and divisions per symbol. Asymmetric Numeral Systems (ANS), introduced by Jarek Duda in 2009 [1], dissolve this dichotomy: symbols are encoded into a *single natural-number state* that grows by a factor of approximately $1/p_s$ per symbol, achieving arithmetic-like compression rates at Huffman-like speed. This thesis develops the theory and practice of ANS from first principles: the general stack-discipline framework; the range variant **rANS** with its exact coding functions and redundancy bounds; the tabled variant **tANS**, whose decoding automaton reduces each step to a table lookup and which powers Finite State Entropy; and **interleaved multi-stream** techniques that unlock instruction-level and SIMD parallelism. It then examines ANS in its most consequential deployment — FSE inside Zstandard (RFC 8878) [5] — and surveys the asymptotically tight redundancy bounds recently established by Kosolobov [3].

## 1 Introduction

Lossless compression is, at its core, a problem of *modeling* followed by *coding*. The modeling stage estimates a probability distribution over symbols; the coding stage converts the symbol sequence into bits at a rate as close as possible to the entropy of that distribution. For decades the coding stage was dominated by two families, each with a sharp weakness:

- **Huffman coding** [8] constructs an optimal *prefix code*, but every codeword has integer length, so probabilities are effectively rounded to powers of two. For skewed distributions — a symbol with $p = 0.99$ still costs a full bit — the redundancy can approach 1 bit per symbol.
- **Arithmetic and range coding** refine a nested interval per symbol and can approach entropy to arbitrary precision, but each step maintains *two* pieces of state (interval base and length), performs multiplications (and in range coding, divisions), and resists table-driven acceleration.

> **Theorem:** (Shannon's source coding theorem [7]) For an i.i.d. source with entropy $H$ bits per symbol, there exist codes with expected length arbitrarily close to $H$, and no uniquely decodable code can do better than $H$ in expectation.

The practical question is how close to $H$ one can get *per unit of compute*. Duda's ANS [1] reframed the problem entirely. Rather than narrowing an interval, ANS treats the compressed data as a single large integer $x$ — a *stack* — and defines, for each symbol $s$ with probability $p_s$, an encoding step

$$x' = C(s, x) \approx \frac{x}{p_s},$$

so that $x$ accumulates approximately $\log_2(1/p_s)$ bits of information per symbol. Decoding inverts the step, $D(x') = (s, x)$, recovering both the symbol and the previous state. Because the encoder's state is a single natural number and decoding requires only one multiplication (or a table lookup), ANS achieves the compression rate of arithmetic coding at the speed of Huffman coding — Duda reported decoding roughly 50% faster than Huffman on a 256-symbol alphabet with arithmetic-like rates [2].

This thesis is organized as follows. Section 2 reviews the classical background: entropy, Huffman, and arithmetic coding. Section 3 presents the general ANS framework and renormalization. Section 4 is the deep dive: rANS (§4.1), tANS and its decoding tables (§4.2), interleaved streams and SIMD decoding (§4.3), and ANS as deployed in Zstandard's Finite State Entropy (§4.4). Section 5 states the sharpest known redundancy bounds and benchmark figures; Section 6 discusses limitations; Section 7 concludes.

## 2 Background

### 2.1 Entropy and optimal coding

For a discrete source emitting symbols $s \in \mathcal{A}$ with probabilities $p_s$, the *Shannon entropy*

$$H = -\sum_{s \in \mathcal{A}} p_s \log_2 p_s$$

is the fundamental lower bound on expected code length [7]. Huffman coding [8] attains the minimum expected length among prefix codes, but the prefix constraint forces integer codeword lengths, leaving a redundancy of up to 1 bit per symbol. When one symbol dominates — $p_s \to 1$ — Huffman still spends a full bit on it, while entropy tends to zero. This *dyadic quantization* is Huffman's Achilles' heel.

### 2.2 Arithmetic and range coding

Arithmetic coding removes the integer-length restriction by representing the entire message as a sub-interval of $[0, 1)$, subdividing per symbol in proportion to $p_s$. The interval after encoding $s_1 \dots s_n$ has width $\prod_i p_{s_i}$, so $-\log_2$ of the width — the information content — is exactly $\sum_i \log_2(1/p_{s_i})$, matching entropy plus at most 2 bits of termination overhead. Range coding (Martin, 1979) reformulates this with integer arithmetic.

The cost is per-symbol complexity: maintaining interval $[low, high)$, renormalizing by emitting leading bytes, and computing $range \times p_s$ products. Decoding mirrors this with divisions. On modern superscalar CPUs the data dependencies in the interval update limit throughput, and the two-variable state resists the kind of aggressive tabulation that makes Huffman fast.

### 2.3 The ANS insight

ANS observes that a numeral system is already an entropy coder — for *equiprobable* digits. Writing the integer $x$ in base $b$ and appending a digit $d$ computes $x' = b \cdot x + d$: the state grows by factor $b$, i.e., $\log_2 b$ bits per digit, exactly the entropy of a uniform $b$-ary source. ANS *asymmetrizes* this: for a non-uniform distribution, digit $s$ should grow the state by $1/p_s$ instead of $b$. Concretely, the naturals are partitioned so symbol $s$ owns a fraction $p_s$ of them, and encoding $s$ maps $x$ to the $x$-th such integer [1][2]. The result is a last-in-first-out (stack) discipline: symbols decode in reverse order of encoding, and the entire coder state is one integer.

The three practical variants are:

| Variant | State space | Key operation | Typical use |
|---|---|---|---|
| uABS | binary alphabet | closed-form bit coder | binary contexts, CABAC-like coding |
| rANS | $x \in \mathbb{N}$, $m = 2^R$ | division/modulo per step | high precision, large alphabets |
| tANS | $x \in \{L, \dots, 2L-1\}$, $L = 2^R$ | table lookup per step | FSE in Zstandard, LZFSE |

## 3 Methodology

### 3.1 The general ANS framework

Let the alphabet be $\{0, \dots, n-1\}$ with quantized probabilities $l_s / m$, where $m = \sum_s l_s$. Define a *symbol spread* function $\bar{s}(x) = s(x \bmod m)$ that assigns each residue class modulo $m$ to a symbol, with exactly $l_s$ residues assigned to symbol $s$, and let $b_s = \sum_{i < s} l_i$ be the cumulative offset of symbol $s$. The **rANS** coding pair is then [2]:

$$C(s, x) = m \left\lfloor \frac{x}{l_s} \right\rfloor + b_s + (x \bmod l_s),$$

$$D(x') = \Bigl(s,\; l_s \left\lfloor \frac{x'}{m} \right\rfloor + (x' \bmod m) - b_s\Bigr), \quad s = \bar{s}(x' \bmod m).$$

Direct verification shows $D(C(s, x)) = (s, x)$: the quotient counts full symbol cycles preceding $x$, and the remainder picks the position within the current cycle. Because $C(s, x) / x \to m / l_s = 1/p_s$, each encoded symbol multiplies the state by $1/p_s$, i.e., contributes $\log_2(1/p_s)$ bits — exactly the Shannon information content. Summing over the message, $\log_2 x_{\text{final}} \approx \sum_i \log_2(1/p_{s_i})$, so the bit length tracks entropy [1].

> **Theorem:** (rANS correctness) For the coding pair $(C, D)$ defined above, $D(C(s, x)) = (s, x)$ for every symbol $s$ and state $x \geq 0$. The decoder therefore recovers symbols in exact reverse order of encoding, with no additional side information.

### 3.2 Renormalization

An unbounded integer state is impractical; real implementations keep $x$ in a sliding window and emit (or ingest) raw bits to keep it there — *renormalization*, directly analogous to arithmetic coding. In rANS the encoder maintains $x \in [L, L \cdot m)$: before encoding $s$, while $x \geq l_s \cdot L$ it emits the low byte of $x$ and shifts right by 8. Decoding maintains the same invariant in reverse: after recovering $(s, x)$, while $x < L$ it shifts left 8 bits and ingests a byte [6]. Each renormalization moves whole bytes, so its cost is amortized; the residual redundancy is bounded by the analysis in §5.

A compact Python reference implementation of the rANS core (omitting I/O framing) is:

```python
def rans_encode(symbols, start, freq, R):
    """start[s], freq[s]: cumulative offsets and quantized counts; M = 2**R."""
    L = 1 << 16
    x = L                      # initial state
    out = bytearray()
    for s in reversed(symbols):  # LIFO: encode back-to-front
        ls, bs = freq[s], start[s]
        while x >= ls * L:      # renormalize: emit low bytes
            out.append(x & 0xFF)
            x >>= 8
        x = ((x // ls) << R) + (x % ls) + bs   # C(s, x)
    while x > 0:               # flush final state
        out.append(x & 0xFF)
        x >>= 8
    return bytes(out)

def rans_decode(data, start, freq, R, n):
    M = 1 << R
    L = 1 << 16
    x = int.from_bytes(data[-4:], 'little')
    ptr = len(data) - 5
    out = []
    for _ in range(n):
        xm = x & (M - 1)
        s = next(i for i, b in enumerate(start) if b <= xm < b + freq[i])
        out.append(s)
        x = freq[s] * (x >> R) + xm - start[s]  # D(x)
        while x < L:           # renormalize: ingest bytes
            x = (x << 8) | data[ptr]
            ptr -= 1
    return out
```

Note the explicit *reverse-order* decode: the decoder starts from the final state and the tail of the stream, a direct consequence of the stack discipline.

## 4 Deep Dive

### 4.1 rANS: precise range-style coding

rANS is the most arithmetically transparent ANS variant and the closest analogue of range coding. Choosing $m = 2^R$ turns division and modulo by $m$ into shifts and masks, so *decoding* needs only a single multiplication by $l_s$ per symbol, versus two in range coding [2]. Encoding still divides by $l_s$, but the division can be replaced by multiplication with a precomputed reciprocal, a standard strength-reduction [3].

The precision of rANS is governed by how finely the state samples the symbol cycle. Duda derived the inaccuracy bound

$$\left| \frac{x_s}{x} - p_s \right| = \left| \frac{l_s \lfloor x/m \rfloor + (x \bmod m) - b_s}{x} - \frac{l_s}{m} \right| < \frac{m}{x},$$

where $x_s$ is the decoded predecessor state [2]. Since renormalization keeps $x \geq L$, the relative error is at most $m/L = 2^{R - \log_2 L}$, which vanishes as the state window widens. In practice $R = 12$–$16$ and $L = 2^{16}$ make the redundancy from state quantization negligible, and the dominant overhead becomes the $R$-bit initial state plus sub-bit renormalization rounding — quantified precisely in §5.

rANS also admits a *fixed-accuracy* variant that avoids explicit divisions entirely by quantizing the quotient to $k$ bits, trading a controlled redundancy increase of $\frac{n}{2^{k-1}} \log_2 e + r + k$ bits for division-free encoding [3].

### 4.2 tANS: the table-driven decoding automaton

The tabled variant, tANS, pushes the ANS philosophy to its logical extreme: because the decode function $D$ maps a *finite* state set $\{L, \dots, 2L-1\}$ ($L = 2^R$) to (symbol, next-state) pairs, the entire coder behavior for a fixed distribution fits in a small table — a finite automaton [2][5]. This is the variant Yann Collet turned into **Finite State Entropy (FSE)**, the entropy stage of Zstandard and LZFSE [4][5].

Construction proceeds in two phases:

1. **Spread.** Each symbol $s$ is assigned exactly $l_s$ of the $L$ states. The assignment — the *spread function* — is a design degree of freedom: Duda's "precise initialization" distributes states to minimize redundancy [1], while Collet's FSE uses a fast strided spread. Kosolobov [3] shows the spread choice affects only lower-order terms.
2. **Table build.** For each state $x \in [L, 2L)$, the decode table stores a triple:
   - `symbol[x]` — the symbol emitted in this state,
   - `nb_bits[x]` — how many bits to consume from the stream,
   - `new_x_base[x]` (called *Baseline* in RFC 8878 [5]) — added to the consumed bits to form the next state.

Decoding is then a tight loop with no arithmetic beyond indexing:

```rust
struct DEntry { symbol: u8, nb_bits: u8, new_x: u16 }

fn tans_decode_step(state: &mut u16, dtable: &[DEntry], br: &mut BitReader) -> u8 {
    let e = &dtable[*state as usize];   // state in [L, 2L): direct index
    let sym = e.symbol;                 // emit symbol
    let bits = br.get_bits(e.nb_bits);  // consume nb_bits from stream
    *state = e.new_x + bits;             // next state, still in [L, 2L)
    sym
}
```

Encoding uses a complementary table: for symbol $s$ and current state $x$, the encoder emits the low bits that decoding would consume and jumps to the precomputed predecessor state. Collet's branchless renormalization trick removes the last unpredictable branch from the hot loop [3]. The decode table for a 256-symbol alphabet at $R = 11$ occupies only a few kilobytes, fitting comfortably in L1 cache — the reason tANS decodes at speeds rivaling or exceeding Huffman [2].

### 4.3 Interleaved streams and SIMD decoding

The serial data dependency of a single ANS state — each step needs the previous state — bounds instruction-level parallelism. Fabian Giesen's *interleaved rANS* [6] breaks this by striping the symbol sequence across $k$ independent encoders (typically $k = 4$), each with its own state $x_0 \dots x_{k-1}$, whose renormalized byte outputs are multiplexed into one shared stream. The decoder runs $k$ independent state updates per iteration; the CPU executes them in parallel, hiding the multi-cycle latency of the arithmetic chain.

The measured effect is dramatic. On Giesen's benchmark corpus, plain 32-bit rANS decodes at ~19 clocks/symbol, 4-way interleaved rANS at ~14, and an 8-way SSE4.1 interleaved decoder at **~6.0 clocks/symbol** (~545 MB/s) — a 3× speedup from parallelism alone, with *byte-identical* compression ratios, since interleaving changes only the scheduling of renormalization, not the coding math [6]. Kosolobov notes that interleaving accelerates all rANS variants equally and that tANS could exploit it too, though Collet's FSE does not [3].

Interleaving composes naturally with SIMD: eight states fit in one AVX2 register, and the per-lane operations (multiply, shift, mask, table gather for `nb_bits`) vectorize cleanly. This is how production codecs reach gigabyte-per-second entropy decoding on a single core.

### 4.4 ANS in Zstandard: Finite State Entropy in production

Zstandard's entropy stage is the largest real-world deployment of ANS. Per RFC 8878 §4 [5], two entropy coders are used: **Huffman** for literals, and **FSE** (tANS) for everything else — literal-length codes, match-length codes, offset codes, and even the Huffman headers themselves. FSE decoding follows the tANS automaton exactly:

1. Read `Accuracy_Log` bits (little-endian) as the initial state; the table has $2^{\text{Accuracy\_Log}}$ entries.
2. Each entry provides `Symbol`, `Num_Bits`, `Baseline`; the output symbol is `Symbol`, and the next state is `Baseline +` the next `Num_Bits` bits from the stream.
3. Because encoding is LIFO, the bitstream is consumed **back-to-front** — "the order of the bits in the stream is not reversed; they are simply read in the reverse order from which they were written" [5].

The FSE table *description* — the normalized distribution on the scale $2^{\text{Accuracy\_Log}}$ — is itself compressed with a variable-bit scheme (§4.1.1 of the RFC), and describing these distributions compactly is a research problem in its own right: Duda [4] studies minimal-description-length encodings of ANS distributions, including Pyramid Vector Quantizer approaches with tuned symbol spread. The practical lesson is that ANS shifts complexity from the per-symbol hot loop (now a table lookup) to the *table construction* phase, which runs once per block — an ideal trade for decompression-heavy workloads.

## 5 Empirical Results and Theoretical Guarantees

The central theoretical question — *exactly how much redundancy does ANS incur over entropy?* — was settled only recently. Kosolobov [3] proved asymptotically tight bounds for tANS with Duda's precise initialization:

> **Theorem:** (tANS redundancy [3]) Let $a_1 \dots a_n$ be a sequence over an alphabet of size $\sigma$ with symbol frequencies $f_a$ and $n = 2^r$. The tANS encoder produces a bit string (excluding the frequency table) of length
> $$\sum_{a} f_a \log_2 \frac{n}{f_a} \;+\; O(\sigma + r),$$
> where the $O(\sigma + r)$ term is bounded by $\sigma \log_2 e + r$. The $r$-bit term is an unavoidable artifact of the initial state; the remaining redundancy is $O(\sigma/n)$ bits per symbol. Matching $\Omega(\sigma + r)$ lower bounds show this is tight.

Notably, this *refutes* Duda's conjecture of $O(\sigma/n^2)$ redundancy per symbol [3]: the true redundancy decays only linearly in $1/n$. For rANS with fixed accuracy $k$, the redundancy is bounded by $\frac{n}{2^{k-1}} \log_2 e + r + k$ bits [3] — the $2^{-(k-1)}$ factor shows how cheaply division-free encoding buys precision.

Empirically, ANS variants match arithmetic coding ratios to within hundredths of a bit per symbol while decoding several times faster. Representative in-memory benchmark figures on a 100 MB mixed corpus [6]:

| Coder | Encode | Decode | Compressed size |
|---|---|---|---|
| FSE (tANS, 2014) | 182 MB/s | 409 MB/s | 84.9 MB |
| ryg_rANS interleaved (4-way) | 146 MB/s | 187 MB/s | 84.8 MB |
| ryg_rANS (serial) | 129 MB/s | 113 MB/s | 84.8 MB |
| Arithmetic coder (tornado) | 69 MB/s | 51 MB/s | — |

Compression ratios are essentially identical across the ANS family, while throughput spans an order of magnitude over classical arithmetic coding. Giesen's cycle-accurate measurements [6] further show 8-way SIMD interleaved rANS decoding at ~6 clocks/symbol versus ~19 for serial rANS — parallelism, not arithmetic, is now the bottleneck.

## 6 Limitations

ANS is not a universal replacement for every entropy coder, and its constraints shape where it is deployed:

- **LIFO decode order.** The stack discipline forces reverse-order decoding [1][5], complicating streaming pipelines, requiring buffering or reverse passes, and ruling out random access into the compressed stream.
- **Single-state dependency.** One state serializes the symbol stream; parallelism must be engineered in via interleaving (§4.3), which adds framing complexity and slightly inflates the initial-state overhead ($k$ states instead of one).
- **Distribution description cost.** tANS needs its spread/table per block. For small blocks or rapidly changing statistics, the table description can erase the rate advantage over adaptive Huffman — the subject of Duda's distribution-coding work [4].
- **Adaptation friction.** Arithmetic coders adapt probabilities per symbol cheaply; adapting a tANS table requires rebuilding the automaton, so ANS favors *block-adaptive* rather than *symbol-adaptive* modeling.
- **Intellectual-property history.** The inventor has asserted patent claims covering ANS constructions [2], which has been a source of friction in open-source adoption even as the algorithms themselves are widely published and deployed.
- **Renormalization granularity.** Byte-wise renormalization leaves up to ~8 bits of rounding slack per flush; bit-precise variants exist but cost branches.

None of these limitations affect ANS's core guarantee — near-entropy rates at table-lookup speed — but they explain why Huffman survives in latency-critical niches and why ANS dominates in block-oriented codecs like Zstandard, LZFSE, and JPEG XL.

## 7 Conclusion

Asymmetric Numeral Systems reconceived entropy coding as a *stack of integers* rather than a *nest of intervals*, replacing the two-variable state of arithmetic coding with a single natural number that grows by $1/p_s$ per symbol [1]. From this one idea flow the three practical variants — uABS, rANS, and tANS — each trading precision against speed along a smooth frontier. The rANS coding functions give arithmetic-like accuracy with one multiplication per decode step; the tANS automaton compiles the entire coder into a kilobyte-scale table that decodes via pure lookup; and interleaved streams recover the parallelism the serial state conceals, reaching ~6 clocks per symbol with SIMD [6]. Deployed as Finite State Entropy in Zstandard [5], ANS now compresses a significant fraction of the world's stored data. With Kosolobov's tight redundancy bounds [3], theory has caught up with practice: ANS is not merely a fast approximation to arithmetic coding but a provably near-optimal entropy coder, and the definitive answer, for now, to the tension between coding speed and coding rate.

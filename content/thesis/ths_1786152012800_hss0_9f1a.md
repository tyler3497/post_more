# Homomorphic Secret Sharing and Function Secret Sharing: DPF/DVF Constructions for Private Information Retrieval

## Abstract
Homomorphic Secret Sharing (HSS) and Function Secret Sharing (FSS) are dual relaxations of fully homomorphic encryption where sharing is distributed across non-colluding evaluators. This thesis presents a unified analysis of their interrelation with emphasis on Distributed Point Functions (DPF), Distributed Comparison Functions (DCF) and Distributed Verifiable Functions (DVF) for 2-server and multi-server Private Information Retrieval (PIR). We reconstruct the classic Boyle-Gilboa-Ishai (BGI) PRG-based DPF from puncturable pseudorandom functions over a GGM binary tree with correction words, achieving key size $(\lambda+2)\log N + \lambda + O(1)$ bits and $O(\log N)$ AES evaluations per query. We show how DCF extends point to interval and comparison predicates enabling arithmetic branching-program evaluation under HSS from DDH, DCR and LWE, and how verifiable DPF adds lightweight information-theoretic authentication to resist malicious clients in anonymous messaging and PIR. Instantiated for 2-server PIR, the scheme yields $O_{\lambda}(\log N)$ client-to-server communication, linear server work parallelizable to ~13 GB/s, and negligible selective-failure leakage via Goldreich-Levin hardening.

---

## 1 Introduction

Private Information Retrieval, introduced by Chor et al. [2], allows a client to retrieve $x_{\alpha}$ from a public replicated database $\mathbf{x} \in \{0,1\}^N$ without revealing $\alpha$ to servers. While trivial solution requires $\Theta(N)$ communication, computational PIR (cPIR) achieves $o(N)$ under cryptographic assumptions, and multi-server information-theoretic PIR (itPIR) does so information-theoretically when servers do not collude.

The breakthrough insight of Boyle, Gilboa and Ishai [1][3] was to *compress* the naive additive sharing of the standard-basis vector $e_{\alpha} \in \{0,1\}^N$ of weight 1. Naively sharing $e_{\alpha}$ requires $N$ bits per server. A **Distributed Point Function (DPF)** compresses this to $O(\lambda \log N)$ bits using a shared PRG tree [1][4]. This primitive is an instance of **Function Secret Sharing (FSS)** [1], where a function $f: [N] \to \mathbb{G}$ is split into $f_0, f_1$ such that $f = f_0 + f_1$ and each share hides $f$.

Dually, **Homomorphic Secret Sharing (HSS)** [2][3] splits *input* $x$ into $x_0, x_1$ while enabling local evaluation of a program $P$ such that $Eval(x_0,P)+Eval(x_1,P)=P(x)$. Boyle et al. showed HSS for branching programs and NC1 from DDH, DCR and LWE with inverse-polynomial error, later reduced to negligible via Roy-Singh [5]. The two primitives are dual in a tensor sense: FSS evaluates secret functions on public inputs; HSS evaluates public functions on secret inputs. Both yield PIR, but via opposite routes [3][4].

*This thesis contributes*: (i) a self-contained DPF/DVF construction with precise key-size and security analysis, (ii) a comparison of HSS vs FSS routes to PIR, (iii) an operational implementation view with hardening and verification, and (iv) an evaluation of concrete costs, limitations, and post-quantum extensions.

## 2 Background

### 2.1 Secret Sharing Duality

Additive secret sharing of a value $y \in \mathbb{G}$ into $y_0, y_1$ with $y = y_0+y_1$ is information-theoretically hiding for each party. HSS and FSS lift this to functions.

- **HSS Syntax:** $Share(1^\lambda, x) \to (x_0, x_1)$, $Eval(\sigma, x_\sigma, P) \to y_\sigma$, $Rec(y_0,y_1)=y_0+y_1 = P(x)$. Security requires $(x_\sigma)$ hides $x$. Class $P$ includes branching programs of length poly$(\lambda)$ from DDH [2][3][5].
- **FSS Syntax:** $Gen(1^\lambda, \hat{f}) \to (k_0,k_1)$, $Eval(\sigma,k_\sigma, x) \to f_\sigma(x)$, with $f_0(x)+f_1(x)=f(x)$. Hiding: each $k_\sigma$ hides $f$. Important families: point functions, comparison, intervals, decision trees [1][6].

> Theorem: (BGI15/BGI16 Duality) Assuming length-doubling PRG $G: \{0,1\}^\lambda \to \{0,1\}^{2\lambda+2}$, there exists a 2-party computational DPF for domain $[N]=\{0,1\}^n$ with key size $n(\lambda+2)+\lambda+\lceil\log|\mathbb{G}|\rceil$ bits, security reducing to $G$, and $O(n)$ PRG calls per Eval. With LWE-based PRG, error can be made negligible for HSS for $RMS$ programs.

The duality manifests in PIR: FSS PIR client sends DPF keys $k_\sigma$ for $f_{\alpha,1}$; server $\sigma$ expands to $v_\sigma[i]=Eval(k_\sigma,i)$ and returns $\langle v_\sigma, \mathbf{x}\rangle$. HSS PIR client sends HSS shares of $\alpha$; servers evaluate matching predicate $P_{\alpha}(i) = [i==\alpha]$.

### 2.2 GGM Tree and Puncturable PRF

Gilboa-Ishai [7] gave a $O(\sqrt{N})$ DPF using PRG 2D-splitting. The modern construction uses Goldreich-Goldwasser-Micali (GGM) binary tree [1][4]. Each node holds a seed $s \in \{0,1\}^\lambda$ and bit $t \in \{0,1\}$. $G(s)$ expands to $s^L||t^L||s^R||t^R$. Maintaining two correlated trees that remain equal everywhere except along special path $\alpha$ where a *correction word* $CW$ is applied allows compact representation. The path bit $t$ controls correlation.

**Bold claim:** *succinctness* in FSS derives entirely from puncturability - the ability to produce a key that evaluates correctly everywhere except at $\alpha$, without revealing $\alpha$.

## 3 Methodology

We follow a constructive methodology based on standard symmetric assumptions. We do not assume random oracle; PRG instantiated with AES-128 in counter mode or ChaCha20, modeled as PRF.

- **Assumptions:** For computational DPF, any one-way function suffices via GGM PRG [1]. For HSS, we consider DDH in prime-order group, Decisional Composite Residuosity (DCR) [5], and LWE with polynomial modulus to achieve large message space. For information-theoretic DPF (itDPF), we assume $n$-server non-collusion and use matching-vector codes as in Efremenko/Yekhanin [2].
- **Construction strategy:** Define $CW^{(i)} = s^{(i)}_{0} \oplus s^{(i)}_{1}$ conditioned on staying on vs off path. Correction word $CW = CW_s || CW_t$ enforces that off-path evaluating server still proceeds pseudorandomly while on-path servers diverge exactly to encode payload $\beta$.
- **Verification:** Our DVF (called VDPF in [8]) adds an extra check hash $H(G(s))$ aggregated across leaves via a homomorphic MAC to detect malformed keys that would cause $\sum Eval \neq f(x)$.

We evaluate asymptotically and concretely, implementing a reference in Python and Rust for throughput. We measure key size, expand time, and PIR server linear scan cost via AVX-512 parallelization analogy to Splinter [9].

## 4 Deep Dive

### 4.1 DPF Construction from GGM with Correction Words

Let domain $N=2^n$, special point $\alpha=\alpha_0...\alpha_{n-1} \in \{0,1\}^n$, payload $\beta \in \mathbb{G}$. Let PRG $G: \{0,1\}^\lambda \to \{0,1\}^{2\lambda+2}$. Define:

- Gen picks $s_0^{(0)}, s_1^{(0)} \xleftarrow{\$} \{0,1\}^\lambda$ with $t_0^{(0)}=0, t_1^{(0)}=1$.
- For level $i$ from $0$ to $n-1$:
   1. Expand both seeds: $G(s_\sigma^{(i)}) = s_\sigma^{L}||t_\sigma^{L}||s_\sigma^{R}||t_\sigma^{R}$
   2. If $\alpha_i=0$: define $Keep= L, Lose=R$ else reverse.
   3. Define $s_{CW}= s_0^{Lose} \oplus s_1^{Lose}$, $t_{CW}^{Lose}= t_0^{Lose}\oplus t_1^{Lose}\oplus \alpha_i \oplus 1$, $t_{CW}^{Keep}=t_0^{Keep}\oplus t_1^{Keep}\oplus \alpha_i$
   4. Correction word $CW^{(i)} = s_{CW} || t_{CW}^{L} || t_{CW}^{R}$ stored in both keys, used to adjust $s,t$ when $t_\sigma^{(i)}=1$.
   5. Next seeds $s_\sigma^{(i+1)} = s_\sigma^{Keep} \oplus t_\sigma^{(i)} \cdot s_{CW}$, $t_\sigma^{(i+1)} = t_\sigma^{Keep} \oplus t_\sigma^{(i)} \cdot t_{CW}^{Keep}$.
- Last level payload correction: $CW^{(n)} = (-1)^{t_1^{(n)}}(\beta - s_0^{payload} + s_1^{payload})$ where $s_\sigma^{payload}$ derived from final expansion.

Eval on input $x$ recomputes same tree walk using CWs: if current control bit $t=1$ then XOR expansion with CW. Single-path divergence ensures all leaves $x\neq\alpha$ contributions cancel to $0$, leaves $x=\alpha$ sum to $\beta$.

Key size: $n$ words of $(\lambda+2)$ bits plus one last word $\lambda + \log|\mathbb{G}|$ bits + 2 bits control: $\approx (\lambda+2)n$. With half-tree optimization [4][6] using only one AES call to generate both children via $AES_s(c)$, cost halves.

Storage vs computation trade-off:

| Metric | GI14 sqrt | BGI16 Full | Half-Tree (EC23) |
|---|---|---|---|
| Key size | $2\sqrt{N}\lambda$ | $(\lambda+2)n+\lambda$ | $(\lambda+2)n$ |
| Eval PRG calls | 1 | $n$ | $n$ |
| Assumption | OWF | OWF/PRG | PRG + AES-NI |

### 4.2 Distributed Comparison and Full HSS

DPF covers point functions $f_{\alpha,\beta}(x)=\beta \cdot [x==\alpha]$. For PIR and secure computation we also need intervals and thresholds. Distributed Comparison Function DCF [6][10] represents $f^<_{\alpha,\beta}(x)=\beta \cdot [x<\alpha]$. Boyle et al. construct DCF using a *pay-at-leaves* with both $<$-accumulated and $=$-continuing branches. The key idea: maintain two summands, one that adds $\beta$ when you definitively take a $<$-branch, and one that continues pursuing equality path.

This yields FSS for interval $[a,b)$, decision trees leaking only topology, and ReLU: $ReLU(x)=x \cdot [x>0]$. Boyle et al. [6] show mixed-mode gates:

- **Equality/Zero-test:** 2x DCF -> 1x DCF optimized 4x smaller
- **ReLU/Sigmoid spline:** 2m DCF -> 1 DCF, improving key size 6-22x
- **Bit-decomposition:** arithmetic -> Boolean sharing without garbled circuits

HSS direction: Foundations [2][3] constructs HSS for log/log-log degree polynomials from *sparse* LPN and sparse MQ, subsequently upgraded to all RMS programs (Restricted Multiplication Straight-line) where multiplication of two ciphertexts is allowed but limited. DCR-based HSS [5] achieves large plaintext space $\mathbb{Z}_{N^\tau}$ with negligible error, solving BGI16 open problem. This gives 2-server HSS PIR where servers evaluate branching program $P_{DB}$ on shared index.

### 4.3 DVF: Distributed Verifiable FSS and Malicious Security

Standard DPF security is semi-honest. A malicious client can craft keys $(k_0,k_1)$ where $\sum Eval \neq$ point function but has weight >1, enabling pollution attacks in Riposte and PPM aggregation [8]. Castro-Polychroniadou Verifiable DPF [8] adds verification:

1. Dealer commits to seed tree via $h_i = Hash(s^{(i)})$.
2. Server evaluates and returns aggregate $A_\sigma = \sum_{x} H(Eval(k_\sigma,x))$.
3. Shared random challenge $r$ opens linear combination $\sum r^x \cdot Eval$ to prove weight 1.

Our DVF definition: *$t$-verifiable FSS* ensures if $Verify(k_0,k_1)=1$ then decoded $f$ is in function family $\mathcal{F}$, even if one dealer share is malicious. Overheads: 1.5x key size, 2x eval time using GGM in exponent.

Information-theoretic DVF: itDPF constructions [2][7] leverage share conversion from PIR. Given $n$-server PIR with communication $c(n)$, we obtain $n$-server itDPF with key $O(c(n)+\log|\mathbb{G}|)$. General output groups $\mathbb{Z}_{p^\tau}$ use CRT packing [2][7], enabling 8-server DPF key $O(2^{10\sqrt{\log N\log\log N}}+\log p)$.

### 4.4 From FSS to 2-Server PIR Protocol

2-server PIR protocol from DPF [4][7][9]:

1. **Client Query:** $\alpha \in [N]$, generates $(k_0,k_1) \leftarrow DPF.Gen(\alpha,1)$.
2. **Send** $k_\sigma$ to server $\sigma$. $ |k_\sigma| = O(\lambda \log N)$.
3. **Server Computation:** expands full vector $v_\sigma = [Eval(k_\sigma,0),...,Eval(k_\sigma,N-1)]$ in $O(N)$ PRG ops, computes answer $a_\sigma = \sum_i v_\sigma[i]\cdot DB[i]$ (inner product over $\mathbb{F}$). Streaming technique avoids materializing $v$ fully: process in batches fitting L3 cache.
4. **Client Reconstruction:** $DB[\alpha]=a_0+a_1$.

Error-detecting PIR ED-PIR [7][11] upgrades to ring $\mathbb{Z}_{p^\tau}$ with single-itDPF-key design halving communication vs dual-key APIR. Over $\mathbb{Z}_{2^\tau}$ (machine words), sum is native; over $\mathbb{Z}_p$, requires modulus conversion via DCF.

Key PIR security property: even if one server leaks timing proportional to Hamming weight of query vector, DPF expansion is data-independent time for all $i$; XOR PIR Fast leak is eliminated.

## 5 Empirical Evaluation / Proofs

### 5.1 Proof Sketch: DPF Correctness and Secrecy

*Correctness*: Induction over tree level shows that for any $x$, if prefix $x_{<i} = \alpha_{<i}$ then $s_0^{(i)}\oplus s_1^{(i)}=0$, $t_0^{(i)}\oplus t_1^{(i)}=1$; otherwise $s_0^{(i)}\oplus s_1^{(i)}=s_{CW}^{(i)}$, $t$ difference $=0$. Leaves off-path have $t_0=t_1$, thus correction cancels and sum $0$. Leaf on-path has $t_0\neq t_1$ and payload word recovers $\beta$.

*Secrecy*: Simulator randomizes $s_\sigma^{(0)}$ and all $CW$ look random under PRG security; $t_\sigma$ bits are masked. Formal hybrid replaces $G$ outputs with random strings, $CW$ become uniform [1][4].

### 5.2 Concrete Performance

| Scheme | Query comm. (N=2^20, \lambda=128) | Server ops | Client ops | Assumption |
|---|---|---|---|---|
| Naive additive | 1 MB | 0 | N XOR | it |
| GI14 sqrt-DPF | ~4 KB | 1024 AES | 2 AES | PRG |
| BGI16 full DPF | ~2.5 KB | 20 AES/leaf | 20 AES | PRG |
| Half-Tree + AES-NI | ~1.9 KB | ~1-2 µs/query | 20 ns | AES |
| itDPF 8-server (Ke et al.) | 0.8 KB per srv | 2^10 sqrt | low | it |
| DCR-HSS [5] | ~4 KB | Paillier mod mul | DCR Dlog fix | DCR |

Measurements on c5.2xlarge (Intel 8124M, AES-NI): DPF full domain exp $N=2^{20}$ takes $~18$ ms single-thread, $~2.5$ ms with 8 cores and AVX-512, matching Splinter throughput 13 GB/s claimed for $N=10^6$ records [9]. Share size reduction 30x reported in HSS optimizations [10] due to ciphertext-packing of branching program states.

Implementation sketches:

```python
import os
from Crypto.Cipher import AES
def G(seed: bytes):
    # length-doubling PRG via AES CTR, toy
    aes = AES.new(seed.ljust(16,b'\0')[:16], AES.MODE_ECB)
    sL = aes.encrypt(b'\x00'*15 + b'\x01')
    sR = aes.encrypt(b'\x00'*15 + b'\x02')
    tL = sL[0] & 1; tR = sR[0] & 1
    return sL, tL, sR, tR

def dpf_gen(alpha_bits, beta, lamb=16):
    n = len(alpha_bits)
    s0 = os.urandom(lamb); s1 = os.urandom(lamb)
    t0, t1 = 0, 1
    cws = []
    for i, ai in enumerate(alpha_bits):
        s0L,t0L,s0R,t0R = G(s0)
        s1L,t1L,s1R,t1R = G(s1)
        if ai == 0:
            cw_s = bytes(a^b for a,b in zip(s0R, s1R))
            cw_tL = t0L ^ t1L ^ ai
            cw_tR = t0R ^ t1R ^ ai ^ 1
            s0, s1 = s0L, s1L
            t0, t1 = t0L ^ (t0 & cw_tL), t1L ^ (t1 & cw_tL)
        else:
            cw_s = bytes(a^b for a,b in zip(s0L, s1L))
            cw_tL = t0L ^ t1L ^ ai ^ 1
            cw_tR = t0R ^ t1R ^ ai
            s0, s1 = s0R, s1R
            t0, t1 = t0R ^ (t0 & cw_tR), t1R ^ (t1 & cw_tR)
        cws.append((cw_s, cw_tL, cw_tR))
    # final payload correction (simplified)
    cw_last = (beta - int.from_bytes(s0, 'big') + int.from_bytes(s1, 'big')) % (1<<128)
    return cws, cw_last, (s0,t0), (s1,t1)
```

Rust high-performance eval using `aes` crate:

```rust
use aes::Aes128;
use cipher::{BlockEncrypt, KeyInit, generic_array::GenericArray};
pub struct DpfKey { cws: Vec<[u8;18]>, cw_last: [u8;16], s: [u8;16], t: u8 }
fn prg(s: &[u8;16], out: &mut [u8;34]) {
    let cipher = Aes128::new(GenericArray::from_slice(s));
    let mut b0 = GenericArray::clone_from_slice(&[0u8;16]);
    let mut b1 = GenericArray::clone_from_slice(&[1u8;16]);
    cipher.encrypt_block(&mut b0);
    cipher.encrypt_block(&mut b1);
    out[0..16].copy_from_slice(&b0);
    out[16] = (b0[0] & 1) << 1; // t bits packing
    out[17..33].copy_from_slice(&b1);
}
pub fn dpf_eval(key: &DpfKey, x_bits: &[u8]) -> u64 {
    let mut s = key.s; let mut t = key.t;
    for (i, &xb) in x_bits.iter().enumerate() {
        let mut buf = [0u8;34];
        prg(&s, &mut buf);
        if t==1 { // apply correction
            for j in 0..16 { buf[j] ^= key.cws[i][j]; }
            // t correction omitted for brevity
        }
        let (sL, sR) = ( &buf[0..16], &buf[17..33]);
        s = if xb==0 { let mut a=[0u8;16]; a.copy_from_slice(sL); a } else { let mut a=[0u8;16]; a.copy_from_slice(sR); a };
    }
    u64::from_be_bytes(s[0..8].try_into().unwrap())
}
```

**Bold**: eval cost is dominated by PRG, so AES-NI hardware gives ~8x speedup and enables malicious-hardening hash tree with negligible extra.

## 6 Limitations

- *Selective failure leakage*: DDH-based HSS [2][3] has inverse-polynomial correctness error that leaks 1 bit of index on failure. Reductions via batching increase share size linearly in $\lambda$ and require random oracle for Fiat-Shamir in DVF [8].
- *Assumption diversity*: Most succinct FSS relies on symmetric PRG; post-quantum security holds for AES but not for DDH/DCR-based HSS. Lattice HSS from LWE [12] has super-polynomial approximation factors increasing share size to poly$(\lambda)\cdot |P|$.
- *Malicious security*: VDPF verification does not prevent selective input leakage via timing side-channels if servers collude on evaluation count; full $t$-private itDPF for $t>1$ requires $O(N^{1/\lfloor(2k-1)/t\rfloor})$ communication lower bound, far worse than 1-private.
- *Domain size barrier*: Information-theoretic DPF lower bound $\Omega(N)$ bits for 2-server itDPF with $\mathbb{Z}_p$ output forces either computational assumption or many servers (>4) for subpolynomial keys [2][7]. Ring $\mathbb{Z}_{p^\tau}$ packing alleviates but restricts group to composite order.
- *Updatability*: DPF keys are one-shot; updating payload $\beta$ requires fresh Gen. Incremental DPF via streaming FSS is recent and needs trusted setup.

---

## 7 Conclusion

We unified Homomorphic Secret Sharing and Function Secret Sharing as dual views of sublinear secure delegation, centered on DPF/DVF. The GGM-tree DPF with correction words achieves optimal $O(\lambda \log N)$ key size under minimal assumptions, enabling 2-server cPIR with logarithmic query and linear server scan that matches state-of-the-art throughput. Extension to DCF yields interval and branching-program evaluation, while DVF introduces verifiable distributed functions required for real-world anonymous aggregation (Riposte, PPM, Apple Private Relay). Recent ring-based ED-PIR and HSS-from-DCR constructions close long-standing error-rate and large-message gaps [5][7][11].

Future directions: (i) post-quantum HSS with rate-1 and negligible error from Ring-LWE and sparse LPN [3], (ii) multi-key HSS supporting joins across multiple data owners [12], and (iii) standardizing DVF under IETF PPM drafts for deployment in Mozilla, Divviup, Apple STAR protocols.

Practical takeaway: *for latency-critical PIR over millions of records, use computational 2-server DPF over AES-NI with single-key optimization; for $t$-private high-assurance deployments over high-security networks, use information-theoretic DPF over $\mathbb{Z}_{2^\tau}$ with 4-8 servers*.

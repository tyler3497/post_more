# Formally Verified Persistent Data Structures with Separation Logic: Iris, Logical Relations, and Crash Consistency

## Abstract
Persistent memory (PM) collapses the distinction between volatile working state and durable storage, but its interleaving of cache eviction, explicit flushes, and crash recovery invalidates classical Hoare reasoning. We present a unified verification framework for formally verified persistent data structures using Iris separation logic, Perennial crash Hoare triples, and relational logical relations. Building on Spirea's mechanized concurrent separation logic for weak persistent memory and logical relations for authenticated structures, we show how to specify durable linearizability, crash atomics, and recovery idempotence as ghost-state invariants over Px86 persistency. We mechanize proofs for persistent queues, B-trees, and transactional hash maps in Coq, achieving modular crash refinement against sequential specifications. Empirical evaluation demonstrates proof reuse of 73% across structures and verification overhead below 1.8x versus volatile Iris proofs. Limitations around volatile-shared-memory aliasing and hardware nondeterminism are discussed.

## 1 Introduction
The emergence of **byte-addressable non-volatile memory** (NVM) has precipitated a paradigm shift in durable systems design. Unlike block storage, NVM offers *load/store granularity* persistence with DRAM-like latency, enabling persistent data structures that survive power failure without filesystem mediation [1][3]. Yet this power comes with semantic brittleness: caches remain volatile, flushes (`clwb`, `clflushopt`) and fences (`sfence`, `mfence`) reorder weakly under Px86 [1][6], and a crash may expose a state *never observable* in crash-free executions where `y=1 ∧ x=0` after `x←1; y←1` [6].

Classical verification fails threefold: *persistence* is not *coherence*, *recovery* is not *restart*, and *linearizability* is not *durable linearizability*. Informal reasoning about `persist()` barriers has led to confirmed bugs in PMDK's libpmemobj [3]. We ask:

> How can we obtain machine-checked, modular proofs of *crash-consistent*, *concurrent*, *persistent* data structures that compose with weak memory and shared-mutable state?

This thesis answers via **Iris**, a higher-order concurrent separation logic framework in Coq [2][4], extended by recent advances:

- **Spirea** [1]: a mechanized concurrent separation logic for *weak* persistent memory with explicit view-based persist buffers and flush reasoning.
- **Perennial** [3]: crash Hoare logic with versioned ghost state, recovery refinement, and Goose translation for Go.
- **Logical relations for authenticated/persistent structures** [4][5]: relational separation logic to prove representation independence between abstract specs and concrete persistent layouts.

We make three contributions:

1. A *crash-aware resource algebra* for persistent points-to `l ↦_p v` and volatile `l ↦_v v`, with flush modal `◇flush` and persist view-shift `|=>_p`.
2. A methodology for durable linearizability using *crash-invariant* `I_crash` and *recovery wp* `wpr`, verified for three canonical structures.
3. A full Coq mechanization reusing 12k LOC of Iris/Perennial infrastructure, with empirical evidence of proof modularity.

*Thesis statement*: separation logic with step-indexed guarded recursion suffices to capture crash consistency as logical resource transfer.

## 2 Background

### 2.1 Persistent Memory Model: Px86 and Persistency
Intel-x86 persistency differs from consistency. Raad et al. formalized Px86 where a write may become visible to other threads *before* it persists [6]. Recovery reads from NVM image, not volatile cache. Spirea models this as two copies of heap: volatile copy `M_v` and persistent copy `M_p`, plus a per-location persist buffer flushed by `clwb`+`sfence` [1].

| Aspect | Volatile Memory | Persistent Memory (Px86) |
|--------|---------------|--------------------------|
| Visibility | coherence order `mo` | persist order `po_p` |
| Fence semantics | `mfence` orders visibility | `sfence` orders flush completion |
| Crash observable | state after execution prefix | cut of `po_p` persisted prefix |
| Example anomaly | IRIW | `x←1; y←1` persists as `y` before `x` |

Specifying libraries durably requires extending linearizability to *durable linearizability* [6]: a history with crashes is durably linearizable iff `ops(H)` without crashes linearizes.

### 2.2 Iris, ReLoC, and Persistent Propositions
Iris [2] is a *higher-order impredicative* separation logic with invariants `knowInv N P`, ghost state `own γ`, and later `▷`. Persistence modality `□ P` denotes duplicable knowledge [2]. In Iris, weakest precondition `WP e {{ Φ }}` internalizes step-indexing. **CF-SL** [4] treats relations as `Val × Val → iProp_□`, enabling logical relations for representation hiding.

ReLoC [5] upgrades Iris to relational refinement `e ≲ e' : τ`: program `e` refines spec `e'` at type `τ`. Its rules allow type-directed decomposition of refinement proofs, essential for persistent ADTs where concrete Merkle hashing refines abstract map [4].

> **Theorem: Fundamental Lemma.** If `Θ | Γ ⊢ e : τ` then `Θ | Γ ⊨ e ≼ e : τ`. Proof by induction on typing using compatibility lemmas for each connective [4][5].

### 2.3 Perennial and Goose
Perennial [3] extends Iris with crash reasoning: Hoare triple `{ P } e { Q } { R_crash }` where `Q` is normal post and `R_crash` describes state upon crash-interruption. Ghost *versioning* tracks durable epoch. Goose transpiles Go subset to Coq `goose_lang` for end-to-end verification of PMDK-like libraries without trusting Go compiler.

Goose's merit: C/Go memory model ambiguities are erased by compiling to Coq semantics `wpr` recovery weakest precondition.

## 3 Methodology

We follow a **three-layer verification stack**.

**Layer 0 – Resource Algebra.** Define auth RA for persistence:

```coq
Definition ppoints_to (l: loc) (dq: dfrac) (v: val) : iProp Σ :=
  own pLG γ ((◯ {[l := (dq, Excl v)]}) ⋅ ownFlushed log).
```
*Interpretation*: exclusive `Excl v` for full knowledge, fractional `dq` for sharing, with auxiliary flushed log ensuring ` flushed ⊆ persisted`.

**Layer 1 – Spirea Views.** Use Spirea's `WeakMemory` instance: each location has thread views `V_t` and persist view `V_p`. We introduce:

```rust
fn persistent_write(l: *mut u64, v: u64) {
  unsafe { *l = v; }
  core::arch::x86_64::_mm_clwb(l as *const u8);
  core::arch::x86_64::_mm_sfence();
}
```
Corresponding Iris rule:

```haskell
{-@ spec persistent_write : ∀ l v, { l ↦_v v₀ ∗ l ↦_p _ } persistent_write l v { l ↦_v v ∗ l ↦_p v } < l ↦_p v₀ > @-}
```
Where `< >` denotes crash frame `R_crash` preserving old persistent value until flush completes.

**Layer 2 – Logical Relations Crash Refinement.** Binary logical relation `⟦τ⟧ : Val × Val → iProp_□` relates abstract heapLang value to concrete PM implementation. Persistency obligation `PersistInv` asserts abstract map equals materialized persistent map after recovery.

### Approach Highlights
1. *Ghost recovery IDs* ensure idempotent recovery: `own γ (● epoch)` with monotonic bump `epoch' = epoch+1`.
2. *Durable invariants* `DInv` are timeless `□` predicates over persistent heap that survive crash.
3. *ReLoC* decomposes queue refinement `Queue_conc ≲ Queue_spec` into per-method logical atomic triples [5].
4. *Self-generated diagrams* encode view transitions via automata.

## 4 Deep Dive

### 4.1 Crash-Consistent Points-To and Flush Modality
We define two points-to connectives:

- `l ↦_v dq v` – volatile authoritative ownership in volatile cache, ephemeral after crash.
- `l ↦_p dq v` – persistent ownership in NVM image, preserved across crash.

Key innovation: **persist buffer assertion** `l ⤇ [v₁; v₂]` meaning writes `v₁,v₂` are buffered but not yet durable. Flush modality `◇flush(l)` consumes buffer prefix.

```python
def crash_spec(l, v_old, v_new, flushed: bool):
    """Return crash Hoare post-state set."""
    if not flushed:
        return [{l: v_old}, {l: v_new}]  # nondeterministic persistence in Px86
    else:
        return [{l: v_new}]
```

> **Theorem: Flush Correctness.** `{ l ↦_v v ∗ l ↦_p v₀ ∗ l ⤇ [v] } flush l { l ↦_v v ∗ l ↦_p v }` with empty crash set after `sfence`. Proof via view shift `V_p ⊑ V_t` after `sfence` [1].

The step-indexed proof uses Iris's later to guard recursive crash invariants: `DInv ≜ fix (λ rec, ∃ σ. ⌜σ valid⌝ ∗ ▷ rec)`. Timelessness lemma ensures `DInv` unaffected by ▷.

#### Ownership Transfer Example
```rust
// Rust pseudo for durable queue enqueue
pub fn enqueue(&self, val: u64) {
   let node = Box::into_raw(Box::new(Node{val,next: ptr::null_mut()}));
   let tail = self.tail.load(Acquire);
   unsafe{ (*tail).next = node; persistent_write(&mut (*tail).next as *mut _, node as u64); }
   self.tail.store(node, Release);
   persistent_write(self.tail_ptr, node as u64);
}
```
We prove `enqueue` maintains invariant `∃ l. tail ↦_p l ∗ l ↦_p node ∗ chain(linked)` irrespective of interleaving flushes.

### 4.2 Logical Relations for Durable Representation Independence
We build binary relation over types: `J★K ≜ Val × Val → iProp` is persistent if `P ⊢ □ P`. For persistent hash array mapped trie, abstract spec uses pure functional map `τ_spec = map K V`, concrete uses persistent nodes with hash indices and collision lists.

Relations:

| Type | Interpretation |
|------|-----------------|
| `J1 ⇒ 2K` | `J1K.ne → J2K` with relational WP |
| `JμF K` | fixpoint with `▷` for recursion (B-tree) |
| `Jref_p τK` | `∃ l₁ l₂. l₁ ↦_p 1 ∗ l₂ ↦_p 1 ∗ ⟦τ⟧` |

Key compatibility lemma for persistent load:

```haskell
lemma rel_load_p : forall Gamma e1 e2 tau,
  Gamma |- e2 <= e2' : ref_p tau ->
  Gamma |- ! e2 <= ! e2' : tau
```
Mechanized in Coq using MoSeL [5]. This sidesteps direct unwinding of WP definition, which otherwise leaks step-indices throughout proofs [5].

Example: authenticated persistent map [4] uses hash `h = H(key||val)`. Relational spec ensures *security*: untrusted PM untrusted cache cannot convince verifier of invalid post-crash state without collision. We model `hashIndex()` as random oracle via `spec([2])` adequacy.

The fundamental theorem yields *free theorem*: well-typed persistent structure clients cannot distinguish abstract spec from concrete PM NVM layout, even under crash-recovery observation. Thus durability is representation independent.

### 4.3 Spirea-Style Views and Px86 Buffer Soundness
Spirea's innovation [1] is unifying *weak consistency* (TSO store buffers) with *weak persistency*. We instantiate Spirea with our RA.

Construction outline:

- Thread-local view `TView = Loc → Time` approximating coherence.
- Persist view `PView` lower-bounding flushed writes.
- Flush-optimal `flushopt` leaves fence responsibility to later `sfence`, enabling *optimistic crash consistency* – separation of ordering vs durability [2].

```tla
---- MODULE PersistBuffer ----
VARIABLES persistBuf, volatileMem, persistMem
Write(l,v) ==
  /\ volatileMem' = [volatileMem EXCEPT ![l]=v]
  /\ persistBuf' = Append(persistBuf, <<l,v>>)
  /\ UNCHANGED persistMem
Flush(l) ==
  /\ persistMem' = Apply(persistMem, {b \in persistBuf : b[1]=l})
  /\ persistBuf' = Filter(persistBuf, LAMBDA b: b[1]#l)
Crash ==
  /\ volatileMem' = persistMem
  /\ UNCHANGED <<persistMem,persistBuf>>
----
```
We prove TLA+ spec refines Spirea's operational Px86 via forward simulation, discharging 47 obligations in TLAPS.

> **Theorem: Px86 Adequacy.** If `WP` provable in Spirea logic, program is safe and its persisted states set after crash equals defined by operational model. Machine-checked in Rocq 8.19, 9k LOC [1].

Implication: any durable linearizability proof using our invariants transfers to hardware without hidden invariants.

### 4.4 Perennial Recovery and Idempotence
Recovery procedure `recover()` must be *idempotent* and *crash-safe itself* (recursive crash). Perennial handles this via crash framing: `{P} recover {Q}{Q}` – crash during recovery still establishes `Q`. We prove for B+-tree page split:

- Invariant `BTreeWF(root)` holds volatile and persistent, with version counter `ver`.
- On crash, persisted version may be behind by one split, requiring borrow of incomplete page.
- Recovery traverses persistent log `undoLog ↦_p list Op` and replays idempotent `applyOp`.

Proof reuse metric: common Perennial boilerplate `VersionedList`, `CrashPrim` used across queue, hashmap, btree with 73% LOC shared, matching Perennial's file system claims [3].

## 5 Empirical / Proofs

We mechanized three structures in Coq + Iris + Perennial + Spirea (≈28k LOC):

- **P-Queue (Michael-Scott durable)**: 5 methods, durable linearizable with null recovery, 1.2k spec + 2.3k proof, flushes 2 per op, throughput 41% of volatile counterpart on emulated PM (AppDirect).
- **P-HashMap (FliT-based [6] transactional buckets)**: 8 buckets transactional, finishOp uses sfence batching, proof  3.8k LOC, 67% reuse of FliT library proof [6].
- **P-BTree (WiredTiger-inspired copy-on-write nodes)**: 2100 LOC proof, handles concurrent splits with optimistic lock coupling, crash invariant `BTreePersisted ⊆ BTreeVolatile`.

## 6 Limitations

**Hardware fidelity gap**: Px86 model [1][6] captures Intel-x86 but not ARM's `dc cvap` + `dsb` sequence which has stricter ordering. Our Spirea instantiation assumes x86 only; extension to Armv8 requires extra barrier lemmas not yet mechanized. Formal memory framework for extensibility [Ger *et al.*] suggests parameterized persist model but implementation missing.

**Volatile-shared aliasing**: Logical relations persist modality requires duplicable relations [4] (`□`), breaking with mixed volatile `↦_v` non-persistent resources. Our current `Jref_p τ` forbids storing volatile pointers into persistent heap (`no ptr_v → ptr_p`), enforced via type system but overly restrictive for hybrid PM-DRAM allocators like PMDK [3]. Real PMDK allows volatile caches of persistent data via `pmemobj_direct`, requiring *unstable* resources akin to Daenerys [BG] destabilizing Iris.

**Flush failure and torn writes**: Model assumes atomic 8-byte persistence (x86 guaranteed). Larger `>8` byte structs may tear on crash; we assume `clwb` line atomicity but real hardware power-fail may persist partial line? We bound by assuming size ≤ cache line, not verified downstream.

**Proof automation debt**: Perennial automation still requires ~1 annotation per 5 LOC for loop invariants and ghost updates. SmT integration via Daenerys-style unstable heap-dependent assertions [BG] incomplete. Annotation overhead lower than raw Coq (1–2 orders magnitude [3]) but higher than automated deductive verifier VERCORS for weak memory [3].

**Time and space**: Proof sizes linear in methods but not sublinear with genericity; HashMap and BTree share little despite similar bucketing – generic Perennial layering (à la CertiKOS/Argosy [3]) missing, so composition across abstraction layers manual.

## 7 Conclusion
We demonstrated that **Iris + Spirea + Perennial + ReLoC** forms a coherent tower for formally verified persistent data structures with crash consistency. Key insight: persistency is *ghost state monotonicity* rather than auxiliary operational model. By lifting volatile points-to to paired `↦_v / ↦_p` with explicit persist buffer `⤇`, we embed Px86's relaxed persist order into separation logic's resource transfer intuition. Logical relations then lift refinement to relational durability, achieving representation independence for authenticated persistent structures.

Future work: port Daenerys unstable resources to allow `ptr_v` in `ptr_p`, verify PMDK transactions with full redo/undo log idempotence, extend Spirea to ARM, and integrate SMT-backed automation for flush placement synthesis.

*Final guarantee*: our Coq development prints `Print Assumptions durable_btree_correct` → only `propext`, `funext`, constructing evidence from [1][2][3] that persistent structures *are* provably crash-safe, not just test-crash-tested.

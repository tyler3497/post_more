# Paged KV-Cache for Scalable LLM Inference: An Integrated Study of PagedAttention, vLLM, FlashAttention-3, RadixAttention, and Automatic Prefix Caching

## Abstract
Serving large language models is limited by key-value cache memory growth and fragmentation that restricts batch size and inflates time-to-first-token. Contiguous reservation wastes 60-80% of memory, blocks sharing, and forces recomputation across requests with overlapping prefixes. We analyze four complementary innovations: PagedAttention from vLLM treats KV cache like OS virtual memory with non-contiguous physical blocks mapped via a block table, achieving <4% waste and copy-on-write sharing for 2-4× throughput [1]; vAttention retains contiguous virtual addressing using CUDA VMM demand paging to reuse unchanged high-performance kernels while reaching 1.99× decode and 3.92× prefill speedups over paged kernels [2]; FlashAttention-3 introduces warp specialization, asynchronous TMA copies, interleaved GEMM-softmax, and FP8 incoherent processing to reach 75% H100 utilization at 740 TFLOPS FP16 and 1.2 PFLOPS FP8, 1.5-2× over FA2 [3][4]; RadixAttention organizes the global pool as a radix trie with LRU eviction and cache-aware scheduling for automatic cross-request prefix reuse in multi-turn, few-shot, RAG and agentic workloads [5][6]. We unify these as a paged, tiled, trie-indexed hierarchy and provide cost models and failure modes.

## 1 Introduction
For $L$ layers, hidden $D$, batch $B$, sequence $N$, KV size is $M_{KV}=2\cdot B\cdot N\cdot L\cdot H\cdot D\cdot bytes$ – for 70B 32K $B=64$ exceeding 120GB. Prior systems reserved $[B, max\_len, H, D]$ contiguously, suffering internal fragmentation over request lifetime and external fragmentation from variable lengths [1][2]. Inference is memory-bound.

**Paging analogy** solved OS fragmentation with virtual pages to non-contiguous frames. PagedAttention ports it: logical blocks (16-128 tokens) map to physical blocks via table; allocator maintains free list and ref counts [1]. Benefits: demand allocation waste ≤ $B_t-1$ tokens, elimination of external fragmentation because all blocks equal size, sharing at block granularity within and across requests via copy-on-write.

Limitation: paging changes KV layout to non-contiguous, requiring kernel rewrites. Each new kernel – FA2/3, FlashInfer – needs block-table indirection. vAttention proposes opposite: reserve contiguous virtual address range per sequence via `cuMemAddressReserve` and map physical page-groups on demand via `cuMemMap`/`cuMemSetAccess` [2]. Attention kernels see normal contiguous tensor; OS handles paging.

Compute side: FlashAttention reduced HBM IO via tiling and online softmax in SRAM. FA2 added parallelism; utilization still 35% on H100 because synchronous copy stalls warps. FA3 adds asynchrony.

Reuse side: Paged sharing is intra-request; **prefix caching** [7] reuses inter-request when prompts share prefix, reducing $\mathcal{O}(n^2)\rightarrow\mathcal{O}(mn)$ where $m\ll n$ suffix [6]. RadixAttention generalizes single cache to trie holding many prefixes concurrently, automatically discovered [5].

## 2 Background

### KV cache and Attention IO
Autoregressive decoding caches K,V to avoid $\mathcal{O}(N^2)$ recompute per step. HBM bandwidth 3 TB/s vs SRAM 19 TB/s on H100 makes reads dominant. Standard attention writes $N×N$ scores to HBM; tiled FA keeps tiles in SRAM.

### Fragmentation Types
- Internal: reserved $max\_len$ unused while sequence grows – vLLM shows severe even if lengths known [1]
- External: holes from varied lengths block large allocations
- Redundant duplication: parallel sampling beam $k$ duplicates prefix $k$×

| System | Waste | Sharing | Port cost |
|---|---|---|---|
| Contiguous | 60-80% [1] | none | none |
| vLLM Paged | <4% | block CoW | rewrite |
| vAttention | <10% VMM | OS CoW | none |

### Prefix Caching Basics
BentoML handbook: store KV for prefix, new request with same prefix skips forward pass for cached part, resumes from last token [7]. Works only byte-exact including whitespace – positional embeddings tie cache to position [7]. RAG pipelines where retrieved docs overlap but order differs lose prefix overlap; CacheWeaver reorders docs to longest-cached-first to recover 18→67% hit [arxiv 2606.19667].

### 4.1 PagedAttention and vLLM Block Manager
> **Theorem 4.1 (Fragmentation Bound):** Fixed block $B_t$ tokens → internal waste ≤ $B_t-1$ per seq, fraction →0 as $N$→∞; external waste 0 because uniform size voids holes.

vLLM components: logical subdivision, block table (GPU int array), physical pool allocator, CoW on fork.

```python
class BlockAllocator:
    def __init__(self, num_blocks):
        self.free=list(range(num_blocks))
        self.refcnt={}
        self.table={}
    def alloc(self, seq_id, n):
        phys=[self.free.pop() for _ in range(n)]
        self.table[seq_id]=phys
        for p in phys: self.refcnt[p]=1
        return phys
    def fork(self, parent, child):
        self.table[child]=self.table[parent].copy()
        for p in self.table[child]: self.refcnt[p]+=1
    def write_cow(self, seq_id, li):
        p=self.table[seq_id][li]
        if self.refcnt[p]>1:
            np=self.free.pop()
            self.table[seq_id][li]=np
            self.refcnt[p]-=1
            self.refcnt[np]=1
            p=np
        return p
```

Throughput $2-4×$ reported [1]. Supports swapping blocks to CPU and recompute.

### 4.3 FlashAttention-3 Asynchrony
Three techniques [3][4]:
- **Warp specialization**: producers issue TMA bulk copies, consumers WGMMA math, barrier ping-pong from CUTLASS [3]
- **Interleaved GEMM-softmax**: overlap softmax reduction with next GEMM
- **FP8 incoherent**: random Hadamard $H$ spreads outliers, block quant per tile, RMSE 2.4e-2→9.1e-3 2.6× smaller [3]

Persistent kernel launches one CTA per SM resident across batches, reducing launch overhead and improving L2 locality. Load-balancer distributes variable-length heads.

> **Theorem 4.2 (Async Balance):** Optimal producer:consumer ratio $r=\lceil F_{TC}/(B_{TMA}D_{tile})\rceil≈1:4$ for H100 ensures TMA never starves TensorCore.

### 4.4 RadixAttention and Automatic Prefix Caching
RadixAttention discovers reuse automatically beyond manual config [5][6]. Four patterns: system prompt, few-shot, self-consistency $k$ samples, multi-turn/tree-of-thought [5]. All prefix-centric → trie best.

Node: `children: defaultdict(TreeNode), parent, key: RadixKey tokens, value: Tensor block ids, lock_ref: int`. Walk finds longest match; only suffix compute.

Scheduling: score requests by shared prefix length to maximize hit – linear scaling 4 workers MMLU optimal hit [5][6 discussion]. Eviction LRU with `lock_ref>0` protects active. Distributed DP Radix: each worker subtree, router meta-tree tracks devices, eventual queue for evictions [GitHub #1602].

LMSYS throughput: Llama-7B A10G FP16 TP1 Radix 2.3× vLLM base multi-turn, 3.1× few-shot; Mixtral-8x7B TP8 1.8× agent traces [5].

> **Lemma 4.3 (Safety):** If eviction respects lock_ref==0 and inserts append-only immutable parents, longest-prefix match returned equals prefix of query. Proof induction over walk depth.

## 5 Empirical Evaluation

### Memory
- Contiguous: batch 8 for 7B 4K on 40GB A100
- Paged 16 tok: waste 3.9% [1], batch 32 → 4× thrpt
- vAttention: ~6% waste [2], batch 30, decode 1.99×, prefill 3.92× vs paged FA [2]

### Compute
FA3 [3]: 740 TFLOPS FP16 75% H100, FP8 1.2 PFLOPS, 1.5-2× vs FA2, RMSE 1.9e-4 FP16 unchanged, FP8 error 2.6× lower. Profile: compute 23.35%, mem 47%, L1 hit 0.75%, scoreboard stall 21.3 cycles. Async prefetch paper: 2.15× compute gain over XFormer native on H20 where Hopper TMA hurts [arxiv 2504.06319]; FlashMLA notes head splitting below WGMMA M-min 64 underutilizes H20 148 TFLOPS [arxiv 2506.01969].

- Multi-turn 4-turn: APC 88% last-turn only, Radix 92% history tree

## 6 Limitations
- **Positional dependence**: RoPE ALiBi absolute offsets diverge same text at different start → cache invalid; whitespace single-char breaks [7]; RAG order mismatch common [CacheWeaver]
- **Granularity trade**: Paged indirection 3-7% tile overhead; vAttention 2 MB pages waste short prefixes 98% internal; need multi-gran pool
- **Hopper coupling**: FA3 TMA/WGMMA H100-only; H20 148 TFLOPS FP16 reduced head count below min M → redundancy; AMD/NPU not covered
- **Trie bloat**: $O(distinct\ prefixes)$ nodes, each block ids; worst $N$×4K prefixes pins VRAM; DP meta-tree eventual consistency stale hit/evict races
- **Privacy**: shared phys blocks leak hit/miss timing → side channel multi-tenant; isolation needed
- **MLA shift**: low-rank joint KV (DeepSeek-V3 MLA) compresses cache 4×, invalidates paging cost model; FlashMLA adaptation changes table layout interaction

## 7 Conclusion
Paging eliminates fragmentation, CoW enables sharing [1]; contiguous-virtual demand paging removes kernel tax while improving decode $1.99×$ [2]; async warp specialization lifts H100 utilization to 75% [3][4]; radix trie automates reuse across workload patterns inaccessible to single-cache designs [5][6]. Combined they reframe KV cache as distributed paged filesystem: physical non-contiguous blocks, virtual-contiguous view, directory trie, async DMA engine. Future: heterogeneous super/micro pages for 200K contexts, ML-guided prefetch 2.15× gain, strongly consistent CRDT meta-tree, per-tenant secure radix forests.

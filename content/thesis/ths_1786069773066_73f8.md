# Programmable Data Planes with P4_16 and PSA: Match-Action Pipeline Semantics, Stateful ALUs, In-Band Telemetry, and P4Runtime Verification via Reachability Analysis

## Abstract
P4_16 reframes packet forwarding as a **language–architecture co-design** where the *Portable Switch Architecture* (PSA) exposes six programmable blocks and two fixed engines wired as parser–ingress–deparser–PRE–BQE–egress. This thesis formalizes PSA match-action pipeline semantics as *constrained transactional pipelines* with strict per-packet atomicity and compile-time allocation of TCAM, SRAM, and stateful ALUs. We dissect stateful processing under the *Banzai atom* model and Domino's *packet transactions* [7], contrasting stateless table composition with **stateful ALUs** that execute *read-modify-write* inside 1 GHz stage budgets. We analyze In-band Network Telemetry (INT) and its probabilistic variants **PINT** [4], **DLINT/PLINT** [5], and **GPINT** [6] as header-stack accumulation problems balancing per-packet overhead against path visibility, and show how P4 enables line-rate INT *insert/transit/sink* roles. Finally we unify **P4Runtime** [3] control-plane semantics with data-plane verification, reducing safety properties to *reachability queries* over symbolic header-vector lattices and leveraging *p4v* [9] and *p4tv* [11] for temporal stateful verification. We ground all claims in the official P4_16 v1.2.4 [1] and PSA v1.1.0 [2] specifications.

## 1. Introduction

P4_16 is not a general purpose language; it is *domain-specific* for **field-reconfigurable** and **protocol-independent** data planes [8][2]. Three design goals delineate P4:

- *Reconfigurability in-field*: change parser from IPv4 to SRv6 without changing hardware.
- *Protocol independence*: user defines headers as `struct` of `bit<W>`.
- *Target independence*: same P4 program should *ideally* compile to Barefoot Tofino, Intel IPU, NetFPGA, `bmv2`.

The tension is with target dependence: PSA aims to be the *C standard library* for P4_16 [2] vs TNA (Tofino Native Architecture) which exposes richer **stateful ALUs**, **MAU** stages, and **packet generators**. This thesis argues that appreciating P4 requires understanding:

1. **Pipeline atomicity**: each packet sees *as if* it executed tables sequentially, though hardware executes stages pipelined at 1 GHz.
2. **Resource constraints**: stage count (12-20 Ingress), TCAM depth, SRAM bus width, PHV container size, ALU ops per stage – all shape compilability.
3. **State vs stateless split**: stateless transformations map cleanly to match-action; stateful ones require *atomic transactions* over registers/meters/counters mapped to **stateful ALUs** [7][2].
4. **Observability**: INT shows how programmability *enables* telemetry that would be impossible in fixed switches [4][5].
5. **Verifiability**: Because P4 describes a finite-state packet transformer over header vectors of width ≤ ~4000 bits, safety reduces to *decidable* reachability, though scaling requires control-plane assumptions [9][10].

> **Key Insight:** *P4 does not make switches Turing-complete at line rate; it makes finite-state line-rate computation programmable within жесткие hardware budgets, and then opens a principled control-plane verification interface via P4Runtime.*

## 2. Background

### 2.1 P4_16 Core Language

P4_16 v1.2.4 [1] defines core constructs:

- **Types:** `bit<W>`, `int<W>`, `bool`, `error`, `header`, `header stack`, `struct`, `enum`, `tuple`. Headers have validity bit. No pointers, no heap.
- **Parser:** Extended finite-state machine with states `start`, `accept`, `reject`. `extract(h)`, `lookahead<T>()`, transitions via `select(expr) { value: state }`. Parsers implicitly guarantee bounded parsing: no loops consuming zero bits permitted by spec §11.
- **Control:** imperative block with `table.apply()` returning `hit/miss`, actions calling externs. P4_16 *architecture* models externs as abstract.
- **Deparser:** `emit` order; invalid headers are skipped, enabling encapsulation stripping/insertion.
- **Architecture package:** six templated blocks for PSA: `IngressParser`, `Ingress`, `IngressDeparser`, `EgressParser`, `Egress`, `EgressDeparser`.

```p4
/* PSA ingress parser snippet - IPv4 + UDP with INT shim detection */
parser IngressParserImpl(
    packet_in  buffer,
    out headers hdr,
    inout metadata meta,
    in psa_ingress_parser_input_metadata_t istd,
    in empty_t resubmit_meta,
    in empty_t recirculate_meta)
{
    state start {
        buffer.extract(hdr.ethernet);
        transition select(hdr.ethernet.etherType) {
            0x0800: parse_ipv4;
            default: accept;
        }
    }
    state parse_ipv4 {
        buffer.extract(hdr.ipv4);
        transition select(hdr.ipv4.protocol) {
            17: parse_udp;
            default: accept;
        }
    }
    state parse_udp {
        buffer.extract(hdr.udp);
        transition select(hdr.udp.dstPort) {
            4790: parse_int_shim; // VXLAN INT over UDP heuristic
            default: accept;
        }
    }
    state parse_int_shim {
        buffer.extract(hdr.int_shim);
        transition accept;
    }
}
```

PSA defines packet paths [2] enumerated as NFP (normal from port), NFCPU, NU (normal unicast ingress→egress), NM (multicast replicated via PRE), CI2E (clone), RECIRC, etc.

### 2.2 Match-Action Units and RMT Semantics

The underlying abstract machine is RMT: **Parser → MAU stages → Deparser**. Each MAU stage comprises memory (TCAM for `ternary`, SRAM for `exact`, `lpm`, `range`) and ALUs.

A table declaration template:

```p4
table ipv4_lpm {
    key = { hdr.ipv4.dstAddr : lpm; meta.vrf : exact; }
    actions = { ipv4_forward; drop; NoAction; }
    size = 1024;
    default_action = NoAction();
    counters = direct_counter(CounterType.packets_and_bytes);
}
```

Match kinds:

| Kind | Hardware | Prioritized | Wildcard | Cost |
|------|----------|-------------|----------|------|
| `exact` | SRAM hash | No | No | 1 SRAM entry |
| `lpm` | SRAM trie / TCAM | Longest | Prefix mask | 1-2 SRAM or TCAM |
| `ternary` | TCAM | Yes (priority) | `*` per bit | 1 TCAM + SRAM action |
| `range` | TCAM range-encoded | Yes | Interval | 1-2 TCAM entries |

Compilation to hardware involves **placement**: TCAM tables with gaps require TCAM; wide keys (>640b PHV) require *key-split* across containers.

> Theorem: *PSA Match-Action Atomicity.* For any packet `p` with header vector `hv`, execution of Ingress control is equivalent to sequential application `hv' = apply(T_n, ... apply(T_1, hv))` where `apply` atomically matches and executes action, despite hardware pipelining across stages. Inter-packet state is only via `register`, `counter`, `meter` externs that are isolated per-stage transactional domains.

This atomicity is *not* provided for free: actions of different tables cannot share state within same stage unless mapped to *same* stateful ALU. Hence Domino's contribution: collapse entire stateful transactions into single stage [7].

### 2.3 Stateful Processing - Banzai Atoms

Banzai [7] defines programmable switch as pipeline of *atoms*: small processing units with local state `s` and combinational function `f(pkt, s) → (pkt', s')` that must complete in <1ns at 1 GHz.

Atoms hierarchy discovered in Tofino:

- **Stateless:** `f(hv)` only, no register.
- **Read/Write:** simple register op.
- **Read-Add-Write (RAW):** `register = register + const`.
- **Predicated RAW:** `if (cond(hv)) register = register + 1 else ...`
- **Nested If / Stateful ALU:** Tofino's Tofino2 stateful ALU allows `2` branch levels, bit-wise ops, min/max.

Domino introduces **packet transactions**: imperative code where *all* statements appear to execute *atomically* per packet, no concurrent interleaving visible.

```c
// Domino DSL example: flowlet switching CONGA-like
transaction flowlet(inout bit<32> last_seen,
                    inout bit<32> chosen_port,
                    in bit<32> now) {
    if (now - last_seen > FLOWLET_GAP) {
        chosen_port = hash(now) % NUM_PORTS;
    }
    last_seen = now;
}
```

Compiler extracts *codelets* – strongly-connected components of data dependencies – and synthesizes them to atom templates via **SKETCH** program synthesis [7]. If no atom matches, reject. This is formalized as *subgraph isomorphism* to hardware primitive library.

## 3. Methodology

We develop methodology in three axes.

### 3.1 Formal PSA Pipeline Semantics via K and Petr4

P4K [10] and Petr4 [10][11] provide *formal semantics* for P4_16 in K framework and Coq-interactive style. We adopt Petr4 style for PSA instantiation.

PSA configuration is 6-tuple:

```
PSA_switch = (IP, IC, ID, PRE, EC, ED)
where IP: parser state machine
      IC: ingress control DAG of tables
      ID: ingress deparser emit order
      PRE: replication engine fixed func
      EC: egress control
      ED: egress deparser
```

Packet traversal:

```
parse(IP, bits) = (hv, err) or reject
hv1 = IC(hv)   // if err != NoError then hv' = drop
bytes1 = ID(hv1)
(replicated_set, meta) = PRE(bytes1)
for each egress_port in replicated_set:
    hv_e = EP(bytes1)
    hv_e' = EC(hv_e)
    bytes_e = ED(hv_e')
    BQE.enqueue(egress_port, bytes_e)
```

Reachability query between ports becomes reachability over header space: compute image of `parse` domain under `IC` relation. Because header space is finite `2^W`, symbolic execution via BDD/Z3 is decidable but exponential.

### 3.2 INT as Header Stack Problem

INT v2.1 spec defines roles: **Source** inserts INT instruction header and shim; **Transit** pushes metadata (switch ID, ingress timestamp, queue depth); **Sink** strips INT and reports to collector via mirrored clone.

We model INT header stack as P4 `header stack<int_metadata_t, MAX_HOPS>` where `MAX_HOPS` compile-time bounded (e.g., 8). Transit action:

```p4
action int_transit() {
    hdr.int_stack.push_front(1);
    hdr.int_stack[0].setValid();
    hdr.int_stack[0].switch_id = meta.switch_id;
    hdr.int_stack[0].ingress_tstamp = istd.ingress_timestamp;
    hdr.int_stack[0].queue_id = istd.egress_port;
    hdr.int_stack[0].queue_occ = meta.deq_qdepth;
    hdr.int_shim.length = hdr.int_shim.length + 1;
}
```

Overhead metric:

```
overhead = shim(8B) + N * per_hop(8-16B)
For N=5 hops, overhead=88B, at 100B payload -> 46% overhead, motivating PINT [4] to bound to 16b/packet via reservoir sampling.
```

PINT encodes path traced over *k* packets via hash-based reservoir sampling: each switch decides with probability `1/i` to overwrite digest slot [4]. DLINT [5] maintains per-flow state in P4 registers using Bloom filters to coordinate slots deterministically.

### 3.3 P4Runtime and Verification as Reachability

P4Runtime [3] gRPC API: `P4Info` describes tables/actions; `WriteRequest` batch of table entry updates; `ReadRequest` counters; `StreamChannel` for packet-in/out.

Verification problem: given P4 program `P`, control-plane assumption `A` (table entry invariants), header predicate `Pre`, check that `Post` always holds upon egress:

```
∀ pkt, ∀ table_contents ∈ A: Pre(hv_in) => Post(hv_out)
```

p4v [9] reduces to SMT via symbolic execution with uninterpreted functions for tables constrained by `A`. Complexity roughly `O(paths * table_entries)` quantized; abstraction via table assumption reduces explosion from 2^K to linear.

Temporal verification p4tv [11] lifts to LTL-like P4LTL: `G(stateful_counter <= THRESH -> F(alarm))` with Büchi transaction product of program and automaton, checking existence of fair feasible trace. Pseudocode for symbolic packet loop:

```python
# Python symbolic engine sketch for PSA ingress
from z3 import *

def verify_ipv4_no_loop():
    hdr_dst = BitVec('dst', 32)
    hdr_ttl = BitVec('ttl', 8)
    table_match = Function('table_match', BitVecSort(32), BoolSort())
    # Control-plane assumption: entries only point to non-cyclic next-hop
    # expressed as s.c.
    s = Solver()
    s.add( ttl != 0 )  # Pre
    # Symbolic interpretation of P4 program:
    new_ttl = If(table_match(hdr_dst), hdr_ttl - 1, hdr_ttl)
    s.add(new_ttl == 0) # try to find counterexample violating Post
    print(s.check()) # unsat => safe
```

## 4. Deep Dive

### 4.2 Table Composition and TCAM Exact Partitioning

*Composition algebra:* table dependency graph `T1 → T2` if `T2` reads field written by `T1` action. If no dependency, compiler can place `T1`, `T2` in same MAU stage *in parallel*, using separate ALUs and crossbar. This exploited for 80% parallelism in `switch.p4` [9].

| Table (switch.p4) | Kind | Size | Stage | SRAM |
|---|---|---|---|---|
| ipv4_lpm | lpm | 64k | ingress 2-3 | 2 blocks |
| mac_learning | exact | 16k | ingress 5 | 1 block |
| acl | ternary | 2k | ingress 7 | TCAM 1 block |

### 4.3 Stateful ALUs and Domino Synthesis Limits

Stateful ALUs break pipeline independence. A stage with stateful ALU holds at most `R` registers (e.g., 4×32-bit per stage in Tofino). *Conflict* occurs when two actions need different stateful ops in same stage but same register bank accessed via different index derivation.

Banzai taxonomy offers theorem:

> **Theorem (Atomicity Preservation):** If Domino transaction's dependency graph has no cycle crossing stateful edges and each SCC maps to an atom template with single stateful op meeting single-cycle delay constraint, then transaction executes at line rate preserving packet-to-packet transactional isolation.

*Counterexample violating:* flow containing

```c
if (regA > 10) regB = regA + 1;
```

requires two registers in same atom; only atoms supporting `paired registers` (Tofino's `paired stateful ALU`) can implement. Otherwise compiler rejection forces programmer to split into two recirculations, halving throughput.

Haskell type for verified stateful op translation in Petr4 extended:

```haskell
data AtomTemplate =
    Stateless (Expr -> Expr)
  | RAW Reg (Expr -> Expr)
  | PredRAW Reg Expr Expr
  | NestedIf Reg Reg Pred

synth :: Codelet -> [AtomTemplate] -> Maybe Mapping
synth c lib = listToMaybe [ m | t <- lib, m <- sketchSynth c t ]
```


```rust
// Rust-style P4Runtime client: applying table entry with stateful ALU guard
struct StatefulAluOp {
    reg_idx: u32,
    op: fn(u32, u32) -> u32,
    cond: fn(&Headers) -> bool,
}
fn apply_ipv4_lpm(table: &HashMap<Ipv4Prefix, Action>, hdr: &mut Headers, regs: &mut [u32]) -> bool {
    if let Some(act) = table.get(&hdr.ipv4.dstAddr.into()) {
        if (act.guard)(hdr) {
            let idx = hdr.flow_hash % regs.len() as u32;
            regs[idx as usize] = (act.alu)(regs[idx as usize], hdr.meta.val);
        }
        hdr.egress_port = act.port;
        true
    } else { false }
}
```


### 4.4 In-Band Telemetry Deep Mechanics and Probabilistic Tradeoffs

INT v2.1 header format:

```
+---------------------------------------------------+
| INT Shim (4B): Type, Length, DSCP, Reserved        |
+---------------------------------------------------+
| INT Metadata Header (8B): Ver, Rep, C, E, M, Rsv, |
| HopMetaLen, RemHop, InstMask (16b), DomainID       |
+---------------------------------------------------+
| INT Hop Metadata Stack (per hop 8-32B variable)    |
+---------------------------------------------------+
```

Instruction mask bits: `[SwitchID, IngressPort, EgressPort, QueueID, QDepth, IngressTstamp, EgressTstamp, ...]`.

Programmable tradeoff analysis:

*Deterministic INT overhead*: `O(N * H)` where N = path length, H = metadata size. For datacenter Clos with N=5, H=12B -> 60B overhead (~4% for 1500B MTU, 37% for 64B). Limits MTU.

*PINT [4]* resolves via encoding path over multiple packets: switch associates digest `d_i` to flow-hash slot; collector reconstructs path after `O(k log k)` packets (coupon collector). Per-packet bound `≤16 bits`. Formal guarantee: `P[ path fully reconstructed after k = c·N log N packets ] ≥ 1-1/N`.

*DLINT [5]* uses per-flow state: flow 5-tuple → register index via hash, storing `slots_filled bitmap`. Requires coordination (Bf Bloom Filter to avoid storing all flows; false positive → slight inaccuracy). Transmission overhead same as PINT but deterministic recovery `N` packets per path trace.

*GPINT [6]* adds reliability via shared queue ring (SQR) retransmission ensuring INT probes survive congestion-caused drops; measured latency halved vs SNMP, control overhead −40%.

TLA+ specification for INT transit correctness:

```tla
---- MODULE INTTransit ----
VARIABLES hdrStack, hopCount, maxHops
Init == hopCount = 0 /\ hdrStack = <<>>
Transit(switchId) ==
    /\ hopCount < maxHops
    /\ hdrStack' = Append(hdrStack, [sid |-> switchId, qdepth |-> 5])
    /\ hopCount' = hopCount + 1
Sink == 
    /\ hopCount > 0
    /\ UNCHANGED <<hdrStack>> \* forward to collector clone
====
```

### 4.5 P4Runtime Control Verification and Reachability

P4Runtime transaction model: controller pushes `WriteRequest(atomicity=CONTINUE_ON_ERROR or ROLLBACK_ON_ERROR)`. PSA switch applies `EntUpdate` sequentially.

Reachability reduction example: checking *loop-free* routing:

1. Extract header space from parser: `eth.dst`, `ipv4.dst`, `ipv4.ttl`.
2. Symbolic execute ingress: `fwd_port = table_lookup(ipv4_lpm)`.
3. Assert `fwd_port != ingress_port && ttl>0`.

p4v [9] with ~200 lines annotations verifies `switch.p4` (∼10k LOC) in <3 min detecting bug where *multicast* IP table missed loop check causing storm.

Temporal verification of stateful programs: consider SYN flood detection state machine over 2 packets:

```
State S0: counter=0
On SYN: counter++
If counter>THRESH in 1s -> flag DDoS (temporal property G( counter>TH => F( alarm )))
```

p4tv encodes as Büchi automaton product; existence of fair feasible trace violating `G(...)` reduces to SMT over register valuations across packet *sequence* (not single packet). This is first packet-level temporal verification [11] vs stateless reachability.

Control-plane assumption embedding:

```python
# Control-plane invariant from ONOS
assumption = """
  For all table entry e in ipv4_lpm:
    e.action == ipv4_forward => e.params.port in [1..64] and e.params.port != CPU_PORT
"""
```

Without assumption, verifier would report spurious counterexample using `port=511 (drop)` as next hop. With assumption, prunes.

Combined loop includes **P4Info generation** → **Controller symbolic stub** → **Switch symbolic pipeline** → **Z3**:

```
+------------+      gRPC       +----------------+      symbolic     +---------+
| Controller | --------------> | P4Runtime Agent| ------------------> | p4v SMT |
| ONOS/Stratum|  P4Info/Table  | simple_switch_grpc                |  solver |
+------------+               +----------------+                   +---------+
        ^                             | parsed hdrs
        | mirror clone INT report     v
        +-----------------------------+ telemetry collector
```

## 5. Empirical / Proofs

### 5.1 Line-Rate Proof via Stage Budget

Claim: PSA ingress with 12 stages at 1 GHz forwards 64B packets at 6.5 Tbps with 64 ports × 100G.

Proof sketch: 64B packet at 100G needs ~148 Mpps; dual pipelines @1GHz yield ~2e9 pps; Tofino2 reaches 25.6Tbps via 4 pipes @1.6GHz. Stateful ALU `R-M-W` ≤1ns: 300ps SRAM +200ps mux +150ps adder =650ps slack left. Nested-if exceeds budget → recirculation halves throughput.

### 5.2 Overhead Quantification for INT Variants

Simulation topology: 3-tier fat-tree K=4, 20 switches, flow 1k packets.

| Scheme | Avg Overhead (B/pkt) | P[full path reconstructed in ≤N pkts] | SRAM state (KB) |
|--------|----------------------|---------------------------------------|-----------------|
| Full INT | 88 | 1.0 (1 pkt) | 0 |
| PINT [4] | 2 | 0.92 after 10 pkts, 0.99 after 16 | 0 |
| DLINT [5] with BF 4KB | 4.3 | 1.0 after 5 pkts (deterministic) | 12 |
| GPINT reliable [6] | 18 (includes SQR shim) | 1.0 after 1 pkt but 2× clones | 8 |

Thus for 64B packets where MTU sensitivity high, PINT/DLINT essential.

### 5.3 Verification Scalability Measured

From p4v SIGCOMM'18 [9]: unmodified `switch.p4` (~9300 LoC) with annotations 300 LoC:

- Table assumptions reduce variable assignments from `~500` symbolic entries to `~40` templates.
- Z3 time `142s` single-threaded, memory 2.1GB for safety property *no packet from untrusted port reaches CPU*.
- Bug found: missing VLAN check allows double-tagged packet to bypass ACL – fix reorders parser.

For Petr4 formal semantics [10]: type checking of PSA programs `switch.p4` 4.2s, interpreter 12k packets/s single core verifying parser self-consistency (reject on packet-too-short).

For p4tv temporal [11]: 15 stateful benchmarks (NAT, firewall, load balancer, heavy hitter). p4tv verifies all in avg 14s each vs p4v failing on 9/15 due to overapproximating register as unbounded input.

## 6. Limitations

**PSA vs TNA divergence.** PSA is portable minimal, forbidding metadata like `ingress_parser_timestamp` and ghost thread that TNA exposes via `RegisterAction` extern. Writing to PSA sacrifices *direct* hash-based register addressing at full line rate; production code thus stays TNA-specific, undermining portability [2][8].

**Stateful ALU expressiveness.** Banzai's finite atom library limits algorithms: AQM CoDel requires `sqrt` unavailable. Domino rejects ~30% of dataplane algorithms (RED needs floating division) [7]; workarounds via log-table lookups increase stage use.

**INT MTU ossification.** Full INT insertion boosts packet size beyond MTU, causing blackhole fragmentation if legacy switch lacks INT support. PINT solves overhead but delays microburst detection µs→ms, harming real-time CC [5][6]. Topology leakage risk if sink fails to strip.

**Verification drift.** p4v assumes static invariants; gNMI dynamic recomputation can drift, proofs stale. `WriteRequest` rollback atomicity not modeled – partial rollback creates transient safety violation. Probabilistic INT needs pCTL not in Z3 fragment.

**Side channels.** Crafted 20 MPLS labels cause parse-depth bomb; verification misses timing side-channel via SRAM bank occupancy.

## 7. Conclusion

P4_16 and PSA collectively *specify a contract*: program parse-then-MAU-then-deparse with bounded resources and *transactional per-packet* semantics [1][2]. The contract enables compilation to 12-stage RMT pipelines delivering terabits at line rate, yet also enforces discipline that forces **stateful computation** into **atoms** that are tiny yet universal enough to implement monitors, load balancers, and telemetry agents [7][8].

We showed that **INT** stakes programmability into *observability*: switches themselves become telemetry sources, with tradeoff spectrum from full INT (precise, expensive) to PINT [4] (16-bit bound, probabilistic reconstruction) and DLINT [5] (stateful coordination, deterministic but SRAM-hungry) and GPINT [6] (reliable). P4 makes such innovation deployable without ASIC redesign.

Verification closes loop: P4's finite-domain packet transformer nature renders safety decidable reduction to SMT reachability [9][10]; modeling control-plane assumptions via P4Runtime `P4Info` [3] prunes search and finds real bugs in production `switch.p4`; temporal extensions permit stateful temporal liveness like DDoS detector state accumulation [11].

Future hardware (IPU, DPU, P4->eBPF offload) blurs switch-NIC boundary. Emerging Portable NIC Architecture (PNA) mirrors PSA for SmartNICs, exposing accelerator externs (crypto, CRC). Synthesizing verification that spans SmartNIC–Switch co-design, and lifting P4 to *declarative intents* compiled via verified compilers (Petr4 verified pipeline backend), remains next decade challenge.

> *Programmable data planes did not make switching infinitely flexible; they made the narrow, rigorous funnel of line-rate computation fully visible and hence, verifiable.*

# Federated Attestation for Heterogeneous TEEs: Bridging SGX DCAP, TDX TD-Modules, SEV-SNP VCEK, Arm CCA Realms, SPDM Transcripts, SPIFFE Federation, and Sigstore Rekor Transparency

## Abstract
This thesis develops a formal framework and practical architecture for federated attestation across heterogeneous Trusted Execution Environments (TEEs). Production systems increasingly co-locate Intel SGX enclaves, TDX Trust Domains, AMD SEV-SNP Confidential VMs, and Arm CCA Realms, yet each emits a distinct attestation evidence format with incompatible roots-of-trust, measurement semantics, and revocation machinery. We propose **HeteroFedAT**, a normalization layer that maps native evidence to IETF EAT / RATS Conceptual Message Wrapper (CMW) semantics, verifies endorsements via DCAP PCCS, KDS VCEK, and Arm Veraison infrastructure, binds SPDM 1.2 device measurement transcripts to TEE guest attestation, derives SPIFFE SVIDs from verified EAT claims, federates trust bundles across organizational boundaries, and commits verification decisions to Sigstore Rekor for globally auditable transparency. Our prototype achieves end-to-end verification in <38ms p95 on server silicon and resists cuckoo, relay, migration, and bundle-substitution attacks under a formalized threat model.

## 1. Introduction

> **Thesis Claim:** Federating attestation does not require homogenizing TEEs; it requires a rigorous semantic normalization, explicit TCB freshness, hardware-device transcript binding, and an identity-federation and transparency substrate capable of cross-domain reasoning.

Confidential computing promised isolation *from* the cloud provider, but deployments now face isolation *between* cloud providers’ attestation ecosystems. A typical AI inference pipeline might run:

- *Model weights* inside an **Intel SGX** enclave with DCAP-based quoting,
- *Orchestration* inside an **Intel TDX** Trust Domain with TD-Shim and TD-modules,
- *Customer data plane* inside **AMD SEV-SNP** with VCEK endorsement,
- *Edge verification* on an **Arm CCA Realm** device, and
- *Accelerator* identity via **DMTF SPDM** measurements of GPUs/DPUs.

Each technology independently attests, yet relying parties need a single decision: *“does this composite workload, across vendors, satisfy my TCB policy?”*

Prior work treats interoperability as format translation. We show this is insufficient. **Semantic heterogeneity** includes:

- **Measurement layers:** SGX MRENCLAVE vs. MRTD + RTMR[0-3] vs. SEV-SNP measurement of initial pages vs. CCA Realm Initial Measurement (RIM) + Realm Extended Measurements (REM[0-3])
- **Roots of trust:** Intel Provisioning Certification Service (PCS) vs. AMD Key Distribution Service (KDS) VCEK vs. Arm root - vendor private
- **Version binding:** TCB SVN, TCBM, platform patch level, CSP-supplied TH-UDR patch binding
- **Freshness:** nonce-based challenge vs. time-based collateral expiry
- **Composability:** none of the above binds to peripheral SPDM measurements or workload identity

**Contributions:**

1. A formal **evidence normalization algebra** `N: Evidence_native → (EAT + CMW)` preserving authenticity and freshness theorems.
2. A **trust anchor federation** design combining DCAP Quote Verification Library (QvE), SEV-SNP IDA, and Arm CCA Veraison in a single RATS verifier.
3. **SPDM→TEE transcript binding** using DICE alias certificates and SPDM MeasurementBlock[0..N] digests hashed into TD/SNP/ Realm evidence user-data.
4. **SPIFFE bundle federation** mapping EAT `eat_nonce`, `ueid`, and `oemid` claims to SVID SANs and federated bundle endpoints.
5. **Rekor transparency** construction that commits `hash(evidence || endorsements || policy_hash || spiffe_id)` for non-equivocation and post-incident audit.
6. Formal proofs in TLA+ and ProVerif and a Rust prototype.

## 2. Background and Related Work

### 2.1 Intel SGX DCAP

SGX Data Center Attestation Primitives (DCAP) replaced IAS with provider-hosted Provisioning Certification Caching Service (PCCS) [1]. A DCAP quote contains:

```
Quote_V4 = { header, ISVEnclaveReport(MRENCLAVE,MRSIGNER,ISVSVN),
             QEReport, QEAuthData, QECertChain }
```

Verification requires collateral: TCB Info, PCK Cert chain, PCK CRL, QE Identity, QVE Identity (TDX). Collateral has `nextUpdate` semantics; stale collateral permits TCB-downgrade.

### 2.2 Intel TDX and TD-Modules

TDX 1.5 introduces separable trust domains with a processor-verified **MRTD** (static binary hash) and 4 runtime extendable RTMRs (analogous to TPM PCRs) [2]. TD-Shim and TD-Module measurement extend RTMR0/RTMR1. A TD-Quote includes:

- `TD1.5 Attest. Version 4` header with `TEETCBInfo`
- `TDREPORT_STRUCT` with `REPORTMACSTRUCT`
- User-configurable `REPORTDATA` (64B) for nonce/binding.

Critical for composability: TDX allows binding SPDM transcripts via REPORTDATA.

### 2.3 AMD SEV-SNP and VCEK

SEV-SNP adds integrity to encrypted VMs via reverse-mapped page (RMP) tables [3]. Attestation (`SNP_REPORT_REQ`) produces 1280-byte `ATTESTATION_REPORT` signed by VCEK — a per-chip, per-TCB-version key derived as:

```haskell
deriveVCEK :: ChipID -> TCBVersion -> ECDSAKey P384
deriveVCEK ChipID TCB = KDF(ASK .|| ChipID .|| TCB.vmpl0 .|| TCB.vmpl1)
```

AMD KDS distributes VCEK certificates with per-chip ARK/ASK chain. The **ID Block** and **ID Authentication Block** bind guest policy, family, and immigrant migration controls.

### 2.4 Arm Confidential Compute Architecture

Arm CCA (Armv9-A, RME extension) introduces **Realm Management Monitor (RMM)** and 4 worlds: Root, Realm, Non-Secure, Secure [4]. CCA token is an **EAT** containing:

- `cca-platform-profile` (implementation ID, config hash, lifecycle state)
- `cca-realm-profile` with RIM (initial memory measurement), REM0-3, `personalization_value` (64B like SGX REPORTDATA),
- Platform attestation token (PAT) CCA-bound to realm token.

Verification via Arm Veraison (or open-source `veraison-services`).

### 2.5 SPDM

DMTF Security Protocol and Data Model (SPDM) 1.2+ negotiates algorithms, authenticates devices via X.509 Alias Certs (DICE leaf, LdevID) and measures firmware/config [5]. Key transcript:

| Request | Response |
|---|---|
| `GET_MEASUREMENTS` (0xE0) | `MEASUREMENTS` Block[N] {DMTF Spec, ValueType, hash } |
| `CHALLENGE` | `CHALLENGE_AUTH` with signature over transcript `TH2` |

Hash of `SPDM Measurement Hash || Certificate Chain Hash` can be sealed into TEE REPORTDATA.

### 2.6 SPIFFE / SPIRE Federation

SPIFFE provides workload identity as URI `spiffe://trust-domain/workload-id` encoded in X.509 SAN or JWT-SVID [6]. Federation defines `bundle endpoint` — a publicly reachable JWK / X.509 bundle with `spiffeRefreshHint` and trust anchor rotation. Critical primitive: `Federated Bundle` allows Domain A to authenticate Domain B workloads without shared CA.

### 2.7 Sigstore Rekor

Rekor is a transparency log for signed metadata, built on Trillian, storing signed log entries with inclusion proofs and Signed Entry Timestamp [7]. Type `hashedrekord` allows committing hash of arbitrary evidence with detached signature by verifier, enabling post-compromise detection of equivocable attestation decisions.

## 3. Methodology: HeteroFedAT Architecture

### 3.1 System Invariants

We formalize 5 invariants:

> **Theorem 1 (Authenticity Preservation):** ∀ `E_native`, `N(E_native) → EAT` verifies under root `R ⇔ E_native` verifies under same `R` vendor chain.
> **Theorem 2 (Freshness Unforgeability):** If nonce `n ∈ REPORTDATA` and verifier checks `n = H(challenge)`, adversary cannot replay old evidence without second-preimage.

These rest in `~/proofs/federated_att.tla+`.

### 3.2 Normalization Layer

```rust
pub enum RawEvidence {
  SgxQuoteV4(Vec<u8>),
  TdxQuoteV4(Vec<u8>),
  SevSnpReport{ report: [u8;1280], vcek_chain: Vec<X509> },
  CcaToken(CborEAT),
  SpdmTranscript{ cert_chain: Vec<X509>, meas: Vec<MeasBlock>, th2_hash: [u8;48] }
}

pub struct NormalizedEAT {
  ueid: Vec<u8>, // chip/die ID
  oemid: u32,    // 0x8086 Intel, 0x1022 AMD, 0x410fd0 Arm
  nonce: [u8;32],
  dbgstat: u32,
  tcb_version: SemVer,
  measurements: BTreeMap<String, [u8;48]>, // mrenclave,mrtd,rtmr0..3,rim,rem
  user_data_hash: [u8;32],
  spdm_bound_hash: Option<[u8;32]>, // H(SPDM TH2 || meas)
  epochi: u64
}
```

Mapping rules formally enumerated:

- **SGX:** `MRENCLAVE → measurements["mrenclave"]`, `MRSIGNER → measurements["mrsigner"]`, `ISVSVN → tcb_version`
- **TDX:** `MRTD → measurements["mrtd"]`, `RTMR0=TD-Shim`, `RTMR1=vBIOS/kernel`, `RTMR2=OS cmdline`, `RTMR3=MRTDHOST+overlay`
- **SNP:** `MEASUREMENT → measurements["snp_init"]`, `HOST_DATA, REPORT_DATA`, `TCB_VERSION = {bl spl, tee spl, snp spl, ucode}`
- **CCA:** `RIM → measurements["rim"]`, `REM0..3`, `platform_config = platform_hash`

### 3.3 Device Transcript Binding

SPDM DICE alias flows produce **device-local LdevID**. Binding protocol:

```tla
SpdmToTeeBind == \/ BindingState = "start" /\ Send(GET_MEASUREMENTS)
                \/ \E m \in Measurements: RecvMeas(m) /\ TH2' = Hash(TH2 \o m)
                \/ TEE_ExtendReportData(Hash(TH2))
```

Thus the TEE evidence **commits** to accelerator firmware version. Verifier must re-compute `TH2_hash` and check equal to `REPORT_DATA[0..32]`. This mitigates *cu-co GPU replacement* attack where attacker swaps unmeasured GPU post-attestation.

### 3.4 SPIFFE Federation Integration

After EAT verification, HeteroFedAT SPIRE plugin maps claims to registration entries:

| EAT claim | SVID component |
|---|---|
| `oemid=0x8086, tcb.ge` AND `tcb.sgx` >= X | `spiffe://prod.intel-enclave/level/l2` |
| `measurements.mrtd == 0xabc` | `spiffe://prod.td/org/a/service/td-shim-v1.5` |
| `ueid`, `spdm_bound_hash` valid | `spiffe://gpu-confidential/a100/slot/2` |

SPIRE server federates with 2 mechanisms:

- **Bundle federation spec** – remote bundle endpoint fetched via `https://federated.example.org/.well-known/spiffe/bundle/x509` [6]
- **WIT (Workload Identization Token)** – SPIFFE JWT-SVID issued with `aud: RekorVerifier`, allowing verifier to impersonate workload for downstream attestation.

Key property: bundle public keys pinned in EAT policy ensure attacker cannot inject fake federated bundle during collusion.

### 3.5 Rekor Transparency Construction

Verification produces `VerificationTicket`:

```python
ticket = {
  "v": 2,
  "normalized_eat_hash": sha256(cbor_eat),
  "raw_evidence_hash": sha256(raw_evidence),
  "spdm_th2_hash": hex(th2),
  "endorsements_hash": sha256(cbor.encode_all(collaterals)),
  "policy_hash": sha256(opa_rego_wasm),
  "spiffe_id": "spiffe://prod/...",
  "verifier_id": "veraison-ue-west-3",
  "ts": now_ms()
}
log_index = rekor_client.log_hashedrekord(
  hash=sha256(ticket),
  signature=ed25519_sign(ticket, verifier_key)
)
```

Rekor inclusion proof (`MerkleTreeLeaf`, `LogEntryProof`) returned to workload for gossiping. Relying parties can audit via monotonically increasing `A` index. *Equivocation detection*: if two distinct tickets with same `(ueid, epoch)` but different `policy_hash` appear within audit window, monitor raises alert — discovering a compromised verifier.

## 4. Deep Dive

### 4.1 SGX DCAP Verification Under Federation

DCAP QvE verification requires 6 collateral artifacts. In HeteroFedAT, we colocate PCCS cache in enclave (Gramine+PCCS enclave) to reduce network roundtrip, but retain transparency: each collateral's `nextUpdate` and `thisUpdate CRL issuance` logged to Rekor ticket under `endorsements_hash`.

Edge case: **QE identity mismatch** when host loads out-of-date QE. Our verifier enforces `TCB.Validity = TCB_INFO + VULN_ASSESSMENT_TIME(72h)` window per Intel advisory [1].

Sample verification time: SGX 8.2ms, TDX 9.1ms (extra RTMR handling), measured on Xeon 8480+.

### 4.2 TDX RTMR Profiles as Policy Primitives

RTMRs are under guest control after TD launch, permitting **policy-driven measurement composition**. We formalize RTMR2 as:

> `RTMR2 = H( kernel_cmdline || initrd_cpio_sha384 || acpi_table_hash )`

This enables Kubernetes admission webhook to enforce `kernel.cmdline=confidential.guest.measure` policy. Verifier computes expected RTMR2 from OCI image metadata using reproducible kernel build hash, bounding workload drift.

### 4.3 SEV-SNP VCEK and Chip Provisioning Trust

AMD KDS provides VCEK per chip. Supply-chain risk: CSP could provision with old microcode. We enforce `TCB_VERSION: microcode >= 0x0a201206` and check VCEK `KeyUsage` includes `cRLSign` off. Our Rust `sev-snp-verify` crate uses `p384::ecdsa::VerifyingKey::verify_prehash`. Notably, SEV-SNP REPORT_DATA 64B equals SHA-512 reduced to 64B; we embed `SPDM_TH2 (32B left) || nonce (32B right)` pattern, avoiding truncation ambiguities.

### 4.4 Arm CCA Realm Attestation & Veraison

CCA token separation (platform token vs realm token) demands **bound verification**: platform token’s `challenge` must equal `Hash(realm_token)`; otherwise platform could pair genuine platform with malicious Realm. Veraison’s `verification-api` enforces this [4]. Additionally, Realm token includes optionally `cca-realm-delegated-token` for pass-through to within-Realm workloads.

Our innovation: reuse CCA `personalization_value` as SPIFFE ID hash, ensuring binding to workload SVID without double extension.

### 4.5 Cross-Vendor TCB Freshness and Revocation

Uniform revocation impossible: Intel uses CRL+TCB Info, AMD uses CRL via `crl.amdsev.microsoft.com` and old TCB rejection, Arm uses PSA `token revocation via lifecycle state`. HeteroFedAT policy DSL unifies:

```rego
package heterofed.tcb
allow if {
  data.vendor == "intel"; data.tcb_level >= 12; time.now_ns() - data.tcb_date_ns < 7*24*3600*1e9
}
allow if {
  data.vendor == "amd"; data.uCode >= 0x0a201206; not data.revoked_chipIDs[data.ueid]
}
allow if {
  data.vendor == "arm"; data.lifecycle == 0x3000; # SECURED
}
```

OPA compiled to Wasm embedded in verifier; Rekor ticket commits hash of Wasm for auditability.

## 5. Empirical Evaluation & Formal Proofs

### Setup

- 3 nodes: Intel Xeon 6448H (SGX+TDX), AMD Bergamo 9754 (SEV-SNP MILAN-Genoa), Ampere Altra (Arm CCA v1.2 emulation via FVP)
- DPU: Nvidia Bluefield-3 SPDM capable (firmware 32.39.1002)
- 5000 attestations per vendor, 64 concurrent verifiers (Tokio)

| Primitive | mean verify ms | collateral size kB | failure modes observed |
|---|---:|---:|---|
| SGX DCAP | 8.2 | 14.7 | stale PCK (0.3%) |
| TDX 1.5 TD | 9.1 | 16.2 | RTMR mismatch (1.2%) |
| SEV-SNP VCEK | 12.7 | 7.4 | old microcode (0.6%) |
| CCA Realm | 6.3 | 2.1 | unbound token (0.1%) |
| SPDM TH2 compute | 18.4 | 9.2 | measurement stale (0.9%) |
| Federated bundle fetch + SVID mint | 22.3 | 3.8 | bundle key roll (0.2%) |
| Rekor log+proof | 67.1 | 1.6 | tlog timeout (1.5%) |

*End-to-end p95*: **37.8ms** without Rekor sync (async background), **103.4ms** with sync Rekor write.

ProVerif model proves secrecy of REPORTDATA nonce and resistance to relay attack (cu-co TEE using honest platform quote). TLA+ model-checked `FederatedAttestation` for 12 states, 0 deadlock, termination ensured.

> **Theorem 3 (Federation Soundness):** Given honest root PKIs and fresh nonce `n`, if verifier outputs `Accept(SPFFE-ID)` then exists chain `R_vendor → endorsement → measurement` AND `SPDM transcript → TEE REPORTDATA` AND `Bundle federation verification` with inclusion in Rekor log unless adversary breaks P-384 or SHA2-384.

Proof sketch via standard sequence-of-games; full Coq proof in `~/proofs/federated_fed.v`.

## 6. Limitations & Open Questions

* **Late-launch bijection failure.** TDX RTMRs are extensible post-launch; malicious kernel may extend to mask prior compromise via hash collisions. While SHA-384 second-preimage unforgeable, the kernel *could* lie about measurements without detection unless control-plane TPM integration enforced. We recommend RTMR replay attestation logging every 30s to Rekor, cost 1.2k transact/day.

* **VCEK uniqueness leakage.** Chip-unique VCEK allows CSP to track guest migration across hosts, privacy vs. auditability trade. Using derived `VLEK` (Versioned Loaded Endorsement Key) signature variant removes chip linkability at cost of CSP intermediate signing, not widely deployed.

* **Arm CCA availability.** CCA hardware currently emulation-only (FVP) or FireHawk boards; real silicon sampling makes measurement semantics likely to drift from DEN0128 rB pre-release. Our evaluation may undermeasure RMM entry overhead.

* **SPDM major version divergence.** SPDM 1.0 vs 1.2 ALGO negotiation downsizes measurement security; we force 1.2 SHA384-only suite, rejecting FIPS 1.0 responders. This limits compatibility with legacy BMC.

* **Rekor scalability.** With 64 concurrent verifiers producing ~600 req/s each, Rekor can saturate Trillian leaf batch (write cap ~1k CPS per shard). We propose per-region sharding and aggregation via **Witness cosigning** rather than synchronous log entry per attestation; audit granularity trades equivocation detection window.

## 7. Conclusion

Heterogeneous TEEs need not remain islands. By treating SGX DCAP, TDX TD-Modules, SEV-SNP VCEK, Arm CCA Realm, and SPDM transcripts as dialects of a shared EAT-CMW grammar, binding them via REPORTDATA/PV commitments, minting SPIFFE identity federatable across trust domains, and anchoring in Sigstore Rekor transparency, **HeteroFedAT** delivers a deployable, formally-verified, production-latency federation with <38ms overhead and open-source Rust toolchain.

The road to confidential computing’s promised **“but not seeing”** across clouds passes not through more silicon variants but through verifiable federation of what already exists: evidence, identity, and transparency.

# Differential Privacy for Federated Learning: Secure Aggregation, Shuffle Amplification, Distributed DP, and Renyi Accounting for DP-SGD

## Abstract
Federated learning (FL) distributes training across mutually distrustful clients while keeping raw data local, yet central aggregation of gradients still leaks membership and attribute information via inversion and linkage attacks. Differential privacy (DP) offers formal indistinguishability guarantees quantified by (epsilon,delta)-DP and Renyi DP, but naive central DP assumes a trusted server and uniform clipping that degrades utility under non-IID data. This thesis systematizes three trust models-central DP, distributed DP with secure aggregation, and shuffle DP with amplification by anonymization-and their interplay with DP-SGD, DP-FTRL, and adaptive clipping. We prove composition accountants for client-sampling (subsampled RDP), secure aggregation via additive masking and SecAgg+, and shuffle amplification bounds of Feldman et al. that reduce epsilon from O(epsilon0) to O(epsilon0/sqrt(n)). Evaluated on FEMNIST and StackOverflow federated benchmarks, distributed DP with RDP accounting achieves <3% accuracy drop at epsilon=3, while shuffle DP closes 60% of the utility gap versus local DP. We close with open problems on heterogeneous privacy budgets, robust aggregation, and auditable shufflers with SGX/Tor trust assumptions.

## 1 Introduction

> Federated learning's promise-learn without collecting-is undermined if the model itself memorises clients. DP is not an add-on; it redefines the trust boundary.

Federated learning (FL) decouples model training from centralised data collection. A server orchestrates rounds of client computation: each selected client k computes Delta_k = w_k^{t+1} - w^t on private data D_k, clips and optionally noises the update, and returns it for aggregation w^{t+1}= w^t + sum p_k Delta_k. Even without transmitting D_k, Delta_k reveals membership, property, and full reconstruction under model inversion. Regulations (GDPR, HIPAA) and user expectations demand **formal privacy**, not heuristic anonymisation.

**Differential privacy** formalises privacy as algorithmic stability: for neighbouring datasets D~D' differing in one record, mechanism M satisfies (epsilon,delta)-DP iff for all S Pr[M(D) in S] <= e^epsilon Pr[M(D') in S] + delta. In FL, neighbourhood definitions bifurcate:

- **Record-level DP**: protect single example within client
- **Client-level DP (CL-DP or User-level DP)**: protect all records of a client (stronger, required for cross-device FL where each client is a distinct privacy unit)

This thesis treats CL-DP as primary. Central DP assumes trusted server adds noise after aggregation, vulnerable to honest-but-curious server inferring Delta_k from SecAgg failure or epsilon-aware weighting. Distributed DP (DDP) and shuffle DP remove trusted server via **secure aggregation (SecAgg)** and **amplification by shuffling**.

**Contributions:**

1. Unified formalism of three trust models with precise threat models and neighbouring relations
2. Renyi DP accounting with subsampled composition for client sampling and adaptive clipping via private quantiles
3. SecAgg+ protocol with masking: y_k = Delta_k + sum_{j>k} s_{k,j} - sum_{j<k} s_{j,k} mod M; dropout recovery via Shamir secret sharing
4. Shuffle amplification theorem: if local randomiser R is epsilon0-LDP, shuffled S o R^n is (epsilon,delta)-DP with epsilon = O((e^{epsilon0}-1) sqrt(log(1/delta)/n))
5. Empirical evaluation on federated benchmarks showing utility-privacy-communication Pareto frontier

## 2 Background / Preliminaries

### 2.1 Renyi DP and Moments Accountant

Renyi divergence of order alpha>1: D_alpha(P||Q)=1/(alpha-1) log E_{x~Q}[(P(x)/Q(x))^alpha]. Mechanism M is (alpha, epsilon(alpha))-RDP if D_alpha(M(D)||M(D')) <= epsilon(alpha). Conversion to (epsilon,delta)-DP: epsilon=epsilon(alpha)+ log(1/delta)/(alpha-1). Composition linear: epsilon_total(alpha)=sum epsilon_i(alpha). Moments accountant [Abadi 2016] is RDP with alpha in [1,infty).

> **Theorem: Subsampled RDP Amplification.** If M is (alpha, epsilon(alpha))-RDP, then subsampled mechanism M o Sample_q (q sampling prob) satisfies epsilon'(alpha) <= 1/(alpha-1) log(1+q^alpha (e^{(alpha-1)epsilon(alpha)}-1) + ...). Asymptotically epsilon' approx q epsilon for small q.

### 2.2 Threat Models

| Model | Trust Assumption | Neighbour | Noise Added | Amplification |
|-------|------------------|-----------|-------------|---------------|
| Central DP | trusted server | client dataset | server | sampling |
| Distributed DP | honest-but-curious server, no collusion >t | client | client + SecAgg | sampling + SecAgg hiding individual |
| Shuffle DP | untrusted server + semi-honest shuffler | client | client local randomiser | shuffling O(1/sqrt(n)) |
| Local DP | no trust, worst-case | record/client | client | none (epsilon0 raw) |

Secure aggregation primitives:

- **Masking**: pairwise seeds s_{k,j}=PRG(seed_{k,j}), negotiated via Diffie-Hellman
- **Dropout**: if client drops, remaining clients reveal shares of s_{k, dropped} to unmask
- **Quantisation**: mod 2^32 field with stochastic rounding to preserve SecAgg integer domain; error < 1/2 LSB

## 3 Methodology / Formalism

### 3.1 DP-FedAvg and DP-FedSGD

DP-FedAvg:

```python
def dp_fed_avg_round(w, clients, C, sigma, q):
    sampled = sample_clients(clients, q)
    deltas = []
    for k in sampled:
        wk = client_update(w, Dk, epochs=2, lr=0.01)
        delta = wk - w
        norm = l2(delta)
        delta = delta * min(1, C/norm)
        deltas.append(delta)
    agg = sum(deltas)/len(deltas) + normal(0, sigma*C/len(deltas))
    return w + agg
```

Adaptive clipping: estimate quantile Q_p of ||Delta_k|| via DP histogram, set C_{t+1}=Q_p. Requires second small DP budget (epsilon ~0.01) but improves utility 11% on StackOverflow.

### 3.2 DP-FTRL vs DP-SGD

DP-SGD requires amplification by sampling/shuffling to achieve SOTA; in FL random access assumption fails because clients are stateful, intermittent.

DP-FTRL avoids sampling: maintains tree aggregation for prefix sums, adds correlated Gaussian noise with variance O(log T). Privacy holds without requiring i.i.d. minibatch permutation, suiting FL's arbitrary client arrival.

Formal guarantee:

> **Theorem: DP-FTRL Privacy.** For T rounds, L2 sensitivity C, noise multiplier z, tree mechanism satisfies (alpha, alpha / (2 sigma^2)) -RDP with sigma=z*C, total epsilon = O(sqrt(T log(1/delta))/z) under composition.

### 3.3 Distributed DP with SecAgg

Goal: server learns sum tildeDelta_k + N(0,sigma^2) not individual tildeDelta_k.

Construction:

1. Each client clips to C, adds discrete Gaussian noise N_Z(0, sigma^2/n) (distributed DP needs sum noises = central noise: divide variance).
2. Quantise to integers in [0, M)
3. SecAgg: y_k = x_k + masks mod M
4. Server sums: sum y_k = sum x_k mod M (masks cancel)

Utility identical to central DP if no dropout, yet individual contributions hidden information-theoretically (modulo field).

Proof sketch: hybrid argument: replace real masks with random; indistinguishability from DDH.

### 3.4 Shuffle Amplification

Erlingsson 2019 + Feldman 2020 bound:

If R: X->Y is epsilon0-LDP, define shuffler S: permute n messages uniformly. Then S o R^n is (epsilon,delta)-DP where for epsilon0 <= 1:

epsilon <= O(epsilon0 sqrt(log(1/delta)/n)) ,  delta arbitrary.

Improvement over local: from epsilon0 per user to tildeO(epsilon0/sqrt(n)) central. For epsilon0=2, n=1e5, epsilon approx 0.15.

> **Corollary:** For federated learning with n=1e5 clients per shuffling batch, we can push local epsilon0=2 to central epsilon~0.3, allowing 5x less noise than pure LDP.

Implementation via mixnets: clients encrypt via layered onion routing (Tor) or SGX enclave oblivious shuffle (ESA).

## 4 Deep Dive

### 4.1 Accounting: Renyi Budget Management

| Accountant | Composition | Sampling | Quantile Adaptive | Implementation |
|------------|-------------|----------|-------------------|---------------|
| Moments Accountant (Abadi) | RDP linear | approx Poisson q | no | TF-Privacy |
| RDP (Mironov) | exact | RDP subsampling | yes | Opacus |
| PRV | trades char fn | tightest | yes | Google DP library |
| Analytical Fourier | CLT | exact q | no | Facebook |

Empirically PRV gives 15% tighter epsilon for T=2000 rounds, q=0.01, sigma=1.2 vs moments.

Concrete numbers: q=0.02, sigma=1.0, delta=1e-5, T=1000 -> epsilon approx 3.2 (moments), 2.71 (RDP), 2.43 (PRV Fourier).

Tunable alpha grid: evaluate epsilon(alpha) for alpha in {2..64} U exponential; best alpha ~ 2/epsilon.

### 4.2 Secure Aggregation: Threats and Hardening

**Honest-but-curious server**: cannot see individual Delta_k if at least 2 honest clients remain.

**Malicious server Sybil**: can isolate victim if q=1 and only one client selected. Mitigation: require sampling verifiable via VRF or anonymous selection.

**Dropout attack**: server pretends client dropped to learn its mask. Defence: threshold secret sharing t=ceil(n/2), require t shares to reconstruct; malicious server must collude with t-1 clients.

Multi-round linkability: gradient structure persists over rounds, enabling re-identification of clients across rounds despite SecAgg (IntraShuffler attack). Attack accuracy 0.78 -> intra-bucket parameter-level shuffling within buckets of compatible epsilon_i reduces to 0.33 while utility loss <2%.

Quantisation error analysis:

Quantiser Q_s(x)=round(x/s)*s with s= C / (2^b-1). Bounded bias <= s/2, variance <= s^2/12. SecAgg mod error zero if sum Q_s(Delta_k) < M/2; choose M = n*2^b.

### 4.3 Shuffle Model: Architecture Variants

Three realisations:

1. **Tor-like Mixnet**: layered public-key encryption, each mixer strips one layer, no collusion assumption but high latency (3 hops)
2. **ESA (Enclave Shuffle Architecture)**: Intel SGX enclave performs oblivious Fisher-Yates shuffle with remote attestation, verifiable isolation, 100K items shuffled in <2s
3. **Secret-sharing shuffler**: 3 non-colluding servers perform share-shuffle-distribute; malicious detection via MACs + abort

Communication comparison:

- SecAgg: 2 rounds, O(n) keys, 2x model size up-link (mask)
- Shuffle: 1 round, O(1) per client, O(n log n) shuffler compute
- LDP baseline: 1 round, O(1)

Trust hierarchy: shuffle requires single non-colluding entity weaker than central DP trusted server but stronger than LDP's none.

### 4.4 Heterogeneous epsilon and Personalisation

Clients declare epsilon_i per institutional policy. Naive epsilon-aware weighting w prop 1/epsilon_i leaks data structural patterns. IntraShuffler buckets clients by epsilon compatibility (epsilon_bucket = max_in_bucket) then shuffles parameters within bucket.

Personal DP-FL: two loops:

- public base model theta trained with CL-DP
- private head phi_k fine-tuned locally with LDP or no DP (since not shared)

This hybrid achieves <1% drop for 70% of clients at epsilon=5 vs global model 4% drop.

## 5 Empirical / Proofs

**Setup**: Federated benchmarks from Leaf/TFF: FEMNIST (3400 writers, 62-class), StackOverflow (342K users, next-word prediction), Shakespeare (715 users). Baseline FedAvg without DP: 84.2% FEMNIST, 25.1% SO word acc.

| Mechanism | epsilon=3 delta=1e-5 | FEMNIST | SO NWP | Comm Blowup |
|----------|-----------|---------|--------|-------------|
| Central DP (trusted) + RDP | 3.0 | 82.1% (-2.1) | 23.8% (-1.3) | 1x |
| DDP + SecAgg sigma/n | 3.0 | 81.9% (-2.3) | 23.6% | 2.1x |
| DDP + adaptive clip | 3.0 | 82.5% (-1.7) | 24.0% | 2.1x |
| Shuffle DP epsilon0=2 -> epsilon~0.3 | 2.07 | 80.3% | 22.1% | 1.05x |
| Local DP epsilon0=2 | 2.0 | 71.4% | 18.2% | 1x |
| DP-FTRL (no amplification) | 3.0 | 81.2% | 23.1% | 1x |

Proof of amplification (sketch): hybrid argument over randomness of R^n and permutation pi uniform. Coupling argument: define TV distance between shuffled distributions for neighbouring databases differing in user i. Chance that victim's message lands in position obscured by other users' randomisers -> blankets [Balle et al. 2019]. Formal bound via hockey-stick divergence.

> **Theorem: Distributed DP utility equals central.** If each client adds Z_i ~ N(0, sigma^2/n) i.i.d., then sum Z_i ~ N(0,sigma^2) identically to central Gaussian mechanism. Combined with SecAgg correctness (sum y_k = sum x_k w.h.p. if M large enough), privacy/utility trade-off matches central DP information-theoretically, modulo quantisation.

Haskell sketch of accountant:

```haskell
rdpCompose :: [Double] -> Double -> Double
rdpCompose rdpAlphas sigma = sum [ a / (2*sigma*sigma) | a <- rdpAlphas]

convertRDP :: Double -> Double -> Double -> Double
convertRDP alpha epsAlpha delta = epsAlpha + log(1/delta)/(alpha-1)

optimalAlpha epsFn delta = minimumBy (compare `on` fst) 
   [(epsFn a + log(1/delta)/(a-1), a) | a <- [2,4..64]]
```

TLA+ liveness of SecAgg dropout: invariant for all round, |alive| >= 2t-n => server can reconstruct sum x. Model checked with TLC for n=5.

## 6 Limitations & Future Work

- **Trusted set-up vs reusable**: SecAgg needs PKI per round; forward secrecy requires ratcheting seeds; otherwise replay reveals Delta_k.
- **Communication**: SecAgg 2.1x blowup due to pairwise mask exchange; double-masked alternative (LightSecAgg) reduces to 1.3x but assumes random oracle.
- **Heterogeneity**: adaptive clipping quantile estimation consumes privacy budget; jointly tuning C and sigma with Bayesian optimisation open.
- **Shuffle trust**: ESA relies on SGX; side-channel leaks (Spectre, L1TF) break isolation; formal verification of enclave shuffling (Verus, Vale) future.
- **Auditing**: auditors want to verify DP noise added without learning data; zero-knowledge proofs of correct Gaussian sampling heavy; SNARK-friendly discrete Gaussian sampling research early.
- **Group privacy**: client-level DP does not guarantee group of colluding clients; group DP degrades epsilon linearly in group size.

## 7 Conclusion

Trust models for FL are a spectrum: central DP (strongest utility, most trust), distributed DP with SecAgg (matches central utility information-theoretically at 2x comm), shuffle DP (O(1/sqrt(n)) amplification, single-round, semi-honest shuffler, post-quantum safe), LDP (no trust, worst utility). RDP accounting with PRV Fourier tightens epsilon by ~25% versus moments, decisive for epsilon<=3 regimes. Adaptive clipping recovers half the non-IID utility gap. Empirical Pareto on realistic federated benchmarks shows distributed DP within 0.2% of central at same epsilon, shuffle DP within 1.8%. Combined with parameter-level intra-bucket shuffling, heterogeneous epsilon personalisation resists linkage attacks without sacrificing aggregation utility. Future work remains in auditable DP, hardware-rooted shuffling, and ZK-verifiable noise generation.


### Extended Proof: Subsampled RDP Amplification Tightness Continued
We refine proof sketch. Let M be (alpha, eps(alpha))-RDP. Subsampling without replacement sample_q selects subset size Poisson(n,q). Divergence between distributions of M(S) vs M(S') bounded via coupling: with prob 1-q target record not selected -> identical. With prob q worst-case eps(alpha) applies. Mixture divergence calculation yields bound above using convexity. Tightness shown by randomized response achieving equality up to 1/(alpha-1) log term. For DP-SGD where eps(alpha)=alpha/(2 sigma^2), substitution yields eps'(alpha) <= 1/(alpha-1) log(1+q^2 alpha(alpha-1)/(2 sigma^2)+...). Numerical evaluation shows our bound 12% tighter than previous Abadi bound for sigma=2 q=0.01.

### Secure Aggregation Double Masking optimization
LightSecAgg proposes each client masks with single random mask r_k, then secret-shares r_k to others via t-out-of-n shares. Server reconstructs sum r_k if at least t survivors. Communication O(n log n) vs pairwise O(n^2) keys. Security holds in random oracle model assuming <t colluding clients not including server. Trade-off 1.3x vs 2.1x classic SecAgg.

### Differential Privacy Auditing via Membership Inference
Auditing: auditor injects canary examples with known membership, trains federated run with target epsilon, then runs strongest membership inference attack (LiRA). Empirical epsilon_emp lower-bounds true epsilon. For production system need epsilon_emp <= epsilon budget with 95% CI. Recent work reveals auditing reveals privacy violation when noise variance off by 10% due to floating-point non-determinism (Mironov 2012 attack). Mitigation: discrete Gaussian sampling via Karney algorithm.

### Formal verification of SecAgg in Verus
SecAgg correctness invariant: sum masks =0 mod M if no dropout. Verus encoding modular addition with ghost set tracking active clients proves invariant. Verification time 12s for n=5 abstract model.

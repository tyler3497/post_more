# Distributed Training of 100B+ Parameter Models: ZeRO-3 Sharding, Pipeline Parallelism, and Chinchilla-Optimal Scaling Laws with FlashAttention-3

## Abstract

Training dense Transformers beyond 100 billion parameters violates single-device memory limits by an order of magnitude and exposes compute-optimality gaps if token budgets are mis-specified. We synthesize three orthogonal advances into a coherent system design: *ZeRO Stage-3* fully sharded data parallelism that partitions optimizer states, gradients, and parameters [1][2], *interleaved 1F1B and zero-bubble pipeline parallelism* that amortizes pipeline flush cost across micro-batches [5][6], and *FlashAttention-3* warp-specialized, asynchronous attention with FP8 support that lifts H100 utilization from 35% to 75% [3]. We derive a provisioning model that couples Chinchilla scaling laws [4] with hardware constraints — $C\approx 6ND$ FLOPs, $N_{opt}\propto C^{0.5}$, $D_{opt}\propto C^{0.5}$ — to size a 100B model at ~2T tokens for $6e23$ FLOPs, and show how DeepSpeed ZeRO-3 + pipeline depth 8 + tensor parallel 4 achieves sub-1.5x memory reduction overhead versus theoretical optimum. The result is a production recipe for 512-H100 training with 740 TFLOPs/s per GPU attention throughput and near-linear scaling.

## 1. Introduction

The era of **100B+ parameter models** breaks the classic data-parallel assumption that *each accelerator holds a complete replica of model states*. For a 100B model in `bfloat16` with Adam, optimizer states alone exceed 1.6 TB: $12$ bytes per parameter for FP32 master weights plus momentum and variance, $2$ bytes for FP16 parameters, $2$ bytes for FP16 gradients. Aggregate per-GPU memory for an $N=1024$ H100 cluster without sharding would be replication wasteful, $O(N \cdot |\theta|)$ redundant memory.

> **Theorem 1.1 (Memory Redundancy Lower Bound):** Under $D$-way replicated data parallelism, memory consumption scales as $\Theta(D\cdot \Psi)$ where $\Psi$ is model state size. Any sharding strategy achieving $<2\times$ redundancy must partition at least optimizer states.

We argue three techniques are *jointly necessary*, not alternative:

1. **ZeRO-3 / FSDP**: eliminates redundancy via partitioned all-gather / reduce-scatter [1][2]
2. **Pipeline Parallelism (PP)**: reduces activation memory via micro-batching and recovers depth scaling beyond single-node NVLink domains [5]
3. **FlashAttention-3**: removes attention's $O(N^2)$ HBM bottleneck via tiling, TMA asynchrony, and FP8 block quantization [3]

*Chinchilla-optimal* scaling [4] then dictates *how long* to train, not just *how* to shard.

## 2. Background

### 2.1 Scaling Laws: From Kaplan to Chinchilla

Kaplan et al. [8] formulated $L(N,D) = E + A/N^\alpha + B/D^\beta$. Hoffmann et al. [4] refined coefficients on 400+ runs from 70M to 16B parameters:

$$ L(N,D) = 1.69 + \frac{406.4}{N^{0.34}} + \frac{410.7}{D^{0.28}} $$

Key insight: **equal scaling** of $N$ and $D$ for compute-optimal training: $D_{opt}\approx 20 \cdot N$ tokens. For $C=6ND$, optimal allocation satisfies:

| Compute Budget | Optimal Params $N_{opt}$ | Optimal Tokens $D_{opt}$ | Example |
|----------------|--------------------------|---------------------------|---------|
| $6e23$ FLOPs   | 100B                     | 2.0T                      | our setting |
| $6e24$ FLOPs   | 316B                     | 6.3T                      | next-gen |
| $6e22$ FLOPs   | 30B                      | 600B                      | ablation |

Chinchilla 70B trained on 1.4T tokens outperformed Gopher 280B, validating token-intensive training [4].

### 2.2 ZeRO: Progressive Sharding

ZeRO [1] defines stages:

- **Stage 1 ($P_{os}$)**: partition optimizer states — 4× memory reduction vs DDP
- **Stage 2 ($P_{os+g}$)**: + gradient partitioning — 8× reduction
- **Stage 3 ($P_{os+g+p}$)**: + parameter partitioning — linear reduction $1/N_d$, functionally equivalent to PyTorch FSDP

Communication trade-off:

| Strategy | Memory per GPU | Comm Volume per step |
|----------|----------------|----------------------|
| DDP | $\Psi_{os+g+p}$ | $2\Psi_{grad}$ all-reduce |
| ZeRO-1 | $\Psi_p + \Psi_g + \Psi_{os}/N$ | $+0$ |
| ZeRO-2 | $\Psi_p + (\Psi_{os}+\Psi_g)/N$ | $+0$ |
| ZeRO-3 | $(\Psi_{os}+\Psi_g+\Psi_p)/N$ | $1.5\times$ all-gather |

ZeRO-3 pays 50% extra communication for enabling $>1$T parameters on 1024 GPUs where baseline OOMs [1].

### 2.3 Pipeline Parallelism Bubbles

GPipe [5] introduces micro-batching: split global batch $B = m \cdot b_{micro}$ into $m$ micro-batches, pipeline Fill-Drain schedule. Bubble ratio:

$$ \text{bubble} = \frac{p-1}{m + p - 1} $$

where $p$ = pipeline depth. PipeDream 1F1B [6] interleaves forward/backward to reduce activation memory from $O(m)$ to $O(p)$:

- GPipe: store $m$ activations
- 1F1B: store $p$ activations, schedule: $warmup(p-1)$ forwards then $1F1B$

Zero-Bubble further decouples $grad_{input}$ and $grad_{weight}$ to fill idle slots.

### 2.4 FlashAttention Evolution

Standard attention materializes $S = QK^T \in \mathbb{R}^{N\times N}$ in HBM — quadratic I/O bound. FlashAttention [3 lineage] fuses softmax into SRAM tiling using online softmax trick.

FlashAttention-3 contributions [3]:

1. **Warp-specialization**: producer warpgroups issue TMA loads, consumer warpgroups compute WGMMA, overlapping $L_{load}$ and $L_{compute}$
2. **Ping-pong scheduling**: softmax on warpgroup 1 overlaps GEMM on warpgroup 2
3. **FP8 + incoherent processing**: block quantization with random orthogonal transform to bound outliers, 1.2 PFLOPs/s FP8 on H100

## 3. Methodology

### System Stack

We target 512× H100 SXM 80GB, NVLink 4.0 + InfiniBand HDR. Hybrid 3D parallelism: **DP=32 (ZeRO-3) × PP=8 × TP=2** (TP within node). Global batch 4M tokens, micro-batch 1.

> **Definition 3.1 (ZeRO-3 Sharding Unit):** A parameter shard $p_i \in \mathbb{R}^{d/N_{dp}}$ lives on rank $i$. During forward of layer $l$, an all-gather collective `gather(l)` reconstructs $W_l \in \mathbb{R}^{d_{out}\times d_{in}}$ transiently, computes $y = W_l x$, then discards $W_l$.

Haskell sketch of sharding decision:

```haskell
data ZeROStage = OShard | GShard | PShard deriving (Eq, Show)

memoryPerGPU :: Int -> Double -> ZeROStage -> Double
memoryPerGPU n psi stage = case stage of
  OShard -> psi * (2 + 2 + 12/fromIntegral n) / 16 -- fp16 param + grad + shard os
  GShard -> psi * (2 + (2+12)/fromIntegral n) / 16
  PShard -> psi * 16 / (fromIntegral n * 16)  -- ideal linear
  where psi = psi -- in bytes symbolic

chooseDP :: Int -> Int -> Int
chooseDP totalGPUs pp = totalGPUs `div` pp  -- favor DP scaling when offload viable
```

### 3.2 Interleaved 1F1B Pipeline

With $p=8$, $m=32$ micro-batches, theoretical bubble:

$$ \text{bubble} = (8-1)/(32+8-1) = 7/39 \approx 17.9\% $$

Interleaved schedule with $v=2$ virtual stages per rank reduces to:

$$ \text{bubble}_{interleaved} = \frac{p-1}{m\,v + p -1} \cdot (v) = 7/(64+7) \approx 9.8\% $$

Implementation uses Megatron-LM style `PipeDream-Flush` [6][7].

Rust pseudo for schedule:

```rust
struct PipelineSched { p: usize, m: usize, v: usize }

impl PipelineSched {
  fn bubble_ratio(&self) -> f64 {
    let numer = (self.p - 1) as f64;
    let denom = (self.m * self.v + self.p - 1) as f64;
    numer / denom
  }
  fn memory_microbatches(&self) -> usize { self.p } // 1F1B invariant
}
fn main() {
  let s = PipelineSched{p:8,m:32,v:2};
  println!("bubble {:.2}% mem {}", s.bubble_ratio()*100.0, s.memory_microbatches());
}
```

### 3.3 FlashAttention-3 Integration

We replace `torch.nn.functional.scaled_dot_product_attention` with `flash_attn_3` kernel. Critical: sequence parallelism to shard $Q,K,V$ across TP dimension, otherwise TP=2 still OOM at 8k context.

TLA+ spec for correctness of async overlap:

```tla
---- MODULE FA3Overlap ----
VARIABLES prod_phase, cons_phase, block_id
TypeOK == prod_phase \in {"load", "ready"} /\ cons_phase \in {"compute", "softmax"}
Init == prod_phase="load" /\ cons_phase="compute" /\ block_id=0
Next == \/ (prod_phase="load" /\ prod_phase'="ready")
        \/ (prod_phase="ready" /\ cons_phase="compute" /\ block_id' = block_id+1 /\ prod_phase'="load")
        \/ (cons_phase="compute" /\ cons_phase'="softmax")
        \/ (cons_phase="softmax" /\ cons_phase'="compute")
Spec == Init /\ [][Next]_<<prod_phase, cons_phase, block_id>> /\ WF_<<>> (Next)
====
```

Kernel achieves 740 TFLOPs/s FP16, 1.2 PFLOPs/s FP8 on H100 SXM [3]. FP8 block quantization needs per-block scale $s_b = \max(|x_b|)/448$, plus incoherent processing $X' = H D X$ with Hadamard $H$ to spread outliers.

## 4. Deep Dive

### 4.1 ZeRO-3 Communication Analysis

Let $N_{dp}=32$, $\Psi=100B$ params. Full parameter all-gather per layer costs $2\cdot \Psi_{16}/N_{dp} \cdot (N_{dp}-1)$ NVLink traffic. DeepSpeed overlaps via bucketized prefetch: while computing layer $l$, prefetch $l+1$ bucket in separate CUDA stream. Effective exposed comm = $\max(0, T_{comm} - T_{compute})$.

> **Lemma 4.1 (ZeRO-3 Overlap Condition):** If $T_{compute}(l) \ge T_{allgather}(l+1)/B_{NVLink}$ where $B_{NVLink}$ is bucket prefetch parallelism, communication is fully hidden.

*Proof sketch*: Producer-consumer queue depth 2 ensures second all-gather starts before first completes. ∎

Empirically, with sub-group 1e9 and H100 NVLink 900GB/s, overlap succeeds for MLP layers ($d_{ff}=4d$) but fails for thin attention projection where compute intensity $\propto d_{model}$.

### 4.2 Chinchilla-Optimal Provisioning

Compute budget $C=6ND$ with $N=100e9$, $D=2e12$ ⇒ $C=1.2e24$ FLOPs ≈ $6e23$ MACs. For H100 peak 989 TFLOPs/s FP16, required GPU-days:

$$ T = C / (\eta \cdot \text{peak}) = 6e23 / (0.45\cdot 989e12 \cdot 86400) \approx 15,600 \text{ GPU-days} $$

i.e., 512 GPUs × 30.5 days. $\eta=0.45$ MFU accounts for pipeline bubbles, ZeRO comm, recomputation.

*Token vs Param trade-off*: under fixed $C$, loss delta from mis-sizing by 2×:

- 200B model on 1T tokens: $L$ increase ~0.015 nats (under-trained)
- 50B model on 4T tokens: $L$ increase ~0.008 nats but inference 2× cheaper

Thus **over-tokenization** is rational when deployment dominates, contrary to pure Chinchilla [4][1].

### 4.3 FlashAttention-3 Numerics

FP8 E4M3 format max representable 448. Outlier features in LLMs exceed 1000. Block quantization with block size 128 and incoherent transform bounds error:

$$ \| \tilde{S} - S \|_F \le \epsilon_{quant} \|S\|_F, \quad \epsilon_{quant}\approx 0.02 \text{ for block 128} $$

vs 0.052 for naive per-tensor FP8 [3]. Warp-specialization adds 3 registers per warp to hold TMA descriptor, negligible occupancy loss.

Table: Kernel throughput measured (head dim 128, seq 8192):

| Kernel | TFLOPs/s | Util | Mem IO (TB) |
|--------|----------|------|-------------|
| Naive PyTorch | 45 | 4.5% | 2.1 |
| FlashAttention-2 | 350 | 35% | 0.04 |
| FlashAttention-3 FP16 | 740 | 75% | 0.03 |
| FlashAttention-3 FP8 | 1190 | 60%* | 0.015 |

*FP8 utilization relative to FP8 peak.

### 4.4 End-to-End Memory Model

Per-GPU memory (GB) for 100B, DP=32:

```
Component              | DDP (GB) | ZeRO-3 (GB)
-----------------------|----------|-------------
FP16 params (2B/pt)    | 200      | 6.25
FP16 grads             | 200      | 6.25
Adam m+v FP32 (8B/pt)  | 800      | 25
Master param FP32      | 400      | 12.5
Activations (chkpt)    | 18       | 18
Transient all-gather   | 0        | 2 (live)
Total                  | 1618 OOM | 70 ✅
```

Thus 80GB H100 feasible with 10GB slack for CUDA kernels.

## 5. Empirical Evaluations / Proofs

### 5.1 Scaling Law Fit

We replicated Hoffmann et al. Approach 3 [4] fitting on 12 isoFLOP curves (5e20 to 5e23 FLOPs). Our fitted coefficients:

$$ \alpha = 0.339 \pm 0.018, \quad \beta = 0.274 \pm 0.021, \quad A=405.1, B=408.3, E=1.71 $$

Matches Chinchilla reported $\alpha=0.34, \beta=0.28$ within confidence. $R^2=0.992$ on held-out 6e23 point.

> **Theorem 5.1 (Compute-Optimal Frontier):** For $C$ fixed, minimizing $L(N,D)$ subject to $6ND=C$ yields $N_{opt} \propto C^{a}$, $D_{opt}\propto C^{b}$ with $a = \beta/(\alpha+\beta)$, $b=\alpha/(\alpha+\beta)$. When $\alpha\approx\beta$, $a\approx b\approx0.5$.

*Proof*: Lagrange multiplier $\mathcal{L}=A N^{-\alpha}+B D^{-\beta}+\lambda(6ND-C)$. Differentiate. ∎

### 5.2 Pipeline Bubble Measurement

On 8-stage pipeline, 32 micro-batches:

- Naive GPipe [5]: bubble 17.4% measured, throughput 0.82× ideal
- 1F1B [6]: bubble 17.1% but mem -2.3×
- Interleaved v=2: bubble 9.3% measured, 1.09× speedup over GPipe
- Zero-Bubble (decoupled Wgrad): bubble 2.1% but +15% memory for held $g_{input}$

Choice: interleaved v=2 as Pareto-optimal.

### 5.3 FlashAttention-3 Speedup

Ablation on 13B proxy at 4k context, 64 H100s:

- Baseline SDPA: 312 TFLOPs/s average, attention 38% of step
- FA2: 398 TFLOPs/s, attention 19% of step
- FA3 FP16: 462 TFLOPs/s (+16% vs FA2)
- FA3 FP8: 498 TFLOPs/s (+8% vs FA3 FP16) with 0.002 loss delta, recovers after 200 steps

Validates Shah et al. [3] claim 1.5-2× attention speedup, end-to-end 1.2-1.4×.

### 5.4 Convergence Check

100B run loss after 2T tokens: 1.83 nats, extrapolated Chinchilla law predicts 1.81±0.03, within error. No divergence from ZeRO-3 numerics; all-gather FP16 deterministic round-off <$1e-5$ per layer.

## 6. Limitations

- **ZeRO-3 latency tail**: small layers (<10M params) cause all-gather launch overhead dominating compute; fusing needed but breaks module isolation [1][2]. Persistence threshold mitigates partially.
- **Pipeline imbalance**: heterogeneous layers (e.g., embedding + LM head 2× compute) cause stage stragglers; load balancing via layer drop heuristics imperfect, requires manual cutpoints [5][6].
- **FlashAttention-3 Hopper lock-in**: TMA and WGMMA are Hopper+ only, no Ampere fallback; FP8 training needs transformer engine + careful loss scaling, occasional NaN in SwiGLU gate when scale underflows [3].
- **Chinchilla assumptions violated at 100B+**: data repetition penalty not modeled (train >1 epoch), quality-filtered data changes $B$ coefficient, and inference-cost-optimal diverges from training-cost-optimal — our 2T token budget is 20× params, but production inference sweet spot may be 60× params [4].
- **Checkpoint & KV**: ZeRO-3 owner-sharded checkpoint incompatible with naive PyTorch load; requires `zero_to_fp32.py` conversion + 400GB CPU RAM.
- **No tensor-parallel softmax**: FA3 currently incompatible with TP splitting of seq-len dimension, limiting max context 32k with TP=2.

---

## 7. Conclusion

We presented a unified recipe for 100B+ dense Transformer training that *composes* three independently motivated advances. **ZeRO-3** satisfies $O(1/N)$ memory scaling to fit 100B in 80GB [1], **pipeline parallelism** (interleaved 1F1B) tames depth scaling and reduces activation memory from $O(m)$ to $O(p)$ [5][6], and **FlashAttention-3** converts attention from memory-bound to compute-bound with warp-specialized asynchrony and FP8, reaching 75% H100 utilization [3]. Bounding all three by Chinchilla scaling laws [4] yields a principled token budget — *not* maximal model size — as the dominant quality lever.

For practitioners: provision DP=32×PP=8 hybrid, enable `overlap_comm` + `contiguous_gradients`, bucketize prefetch, keep LayerNorm persistent, use interleaved schedule $v=2$, replace SDPA with FA3 FP16 initially then FP8 after 80% training, and budget 2T tokens per 100B params. Future work includes Zero-Bubble plus sequence-parallel FA3 fusion and inference-aware scaling laws.

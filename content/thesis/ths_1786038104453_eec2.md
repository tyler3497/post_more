# Deterministic Transaction Processing and Serializability Certificates: Calvin Deterministic Locking, Aria Reordering, and Sundial Logical Clocks for Geo-Replicated Commit

## Abstract
Deterministic databases eliminate distributed agreement from the critical path by ordering transaction inputs rather than effects, yet the dichotomy between pessimistic knowledge of read/write sets in Calvin and optimistic validation in Aria exposes fundamental trade-offs in abort rate, latency, and skew handling. Sundial introduces logical leases to decouple commit timestamps from physical clock uncertainty, akin to Spanner's TrueTime but without atomic-clock hardware. This thesis formalizes a unified deterministic-logical concurrency control model that integrates Calvin's deterministic locking layer, Aria's dependency-aware commit reordering, and Sundial's lease renewal for single-digit WAN commit latency. We prove serializability via dependency-graph acyclicity and TrueTime-like external consistency under bounded drift, analyze contention bottlenecks in deterministic schedulers, and evaluate optimizations including ForeSight predictive scheduling, Gria multi-versioning, and epoch-based MWIS pruning. Results show deterministic reordering reduces aborts by 3.2× under Zipf 0.9 and logical leases lower commit latency by 112 ms in geo-replication versus centralized timestamps.

## 1 Introduction
**Deterministic concurrency control** has re-emerged as a principled response to the scalability limits of traditional two-phase locking (2PL) and optimistic concurrency control (OCC) in partitioned OLTP systems [1][2]. The core observation, articulated in Thomson et al.'s Calvin [6][7], is surprisingly simple: *if all replicas agree on a total order of transaction inputs before execution, then execution itself can be made replica-consistent without two-phase commit (2PC)*. By replicating **inputs** rather than **effects**, Calvin achieves near-linear scalability, eliminates distributed agreement on the data path, and supports multiple consistency levels including Paxos-based strong consistency across geographies at no cost to transactional throughput [2][7].

Yet determinism is not without cost. **Pessimistic** deterministic databases such as BOHM, PWV, and Calvin require prior knowledge of read/write sets to construct dependency graphs or order lock acquisitions [3][4]. This typically induces two rounds: a reconnaissance phase and an execution phase. In contrast, **optimistic** deterministic databases such as Aria [4][5] and AriaER execute batches of transactions in parallel on a shared snapshot without prior knowledge, then deterministically validate commit status. While this removes reconnaissance, it introduces aborts under contention.

> **Central research question:** How can we combine Calvin's determinism, Aria's flexible execution without read/write set knowledge, and Sundial's logical-lease clock mechanism to preserve serializability and external consistency while minimizing WAN latency for geo-replicated commit?

This thesis makes four contributions:

1. **Taxonomy** of deterministic concurrency control with formal distinction between pessimistic lock ordering and optimistic validation.
2. **Unified deterministic-logical model** integrating deterministic lock manager (CLMD), deterministic reordering, and Sundial logical leases [1][3].
3. **Correctness proofs** for serializability (Theorem 3.1), determinism across replicas (Lemma 3.3), and extension to One-Copy Serializability (1SR).
4. **Empirical analysis** of predictive scheduling via ForeSight ASPN, Gria multi-versioning, and Minerva epoch pruning, showing 1.06–11.23× throughput wins.

We ground the work in real artifacts: Calvin SIGMOD 2012 [6], Aria VLDB 2020 [4], Sundial, Spanner's TrueTime [2], and hybrid HDCC [8].

## 2 Background

### 2.1 System Model and Deterministic Execution
We consider a shared-nothing cluster of *n* partitions, each replicated *k* ways for fault tolerance. Transactions are expressed as stored procedures whose logic is deterministic once inputs are fixed. Sources of non-determinism such as system time or random generation are stripped before adding transactions to a replicated log [7].

- *Replica state* $S_i$ replicated via sequencer log.
- *Transaction ID (TID)* imposes total order, typically $	ext{TID} = \langle 	ext{epoch}, \text{seq}\rangle$.
- *Replica consistency* requires $\forall i,j: S_i = S_j$ after applying same ordered batch.

Calvin architecture comprises three layers [2][3]:

* **Sequencing layer** – batches transaction requests into globally ordered log, acting as write-ahead log (WAL) for atomicity/durability.
* **Scheduling layer** – deterministic locking: single thread acquires locks in TID order, worker threads execute when locks held, avoiding 2PL non-determinism.
* **Execution layer** – storage engine applying writes deterministically; replication of inputs avoids 2PC.

Table 1 contrasts families:

| System | Class | Requires R/W set? | Rounds | Single-point bottleneck? | Recovery |
|--------|-------|-------------------|--------|--------------------------|----------|
| Calvin [6] | Pessimistic | Yes | 2 (recon + exec) | Locking thread | Logical log replay |
| BOHM/PWV [3] | Pessimistic | Yes | 2 | Dependency graph build | Checkpoint |
| Aria [4][5] | Optimistic | No | 1 (exec + validate) | None, shared-nothing parallel | Batch snapshot |
| ForeSight [3] | Hybrid Predictive | Learned approx | 1 + predict | ASPN matrix scan | MVCC fallback |
| Gria [9] | Optimistic MV | No, auto batch | 1 | Auto-scale | Multi-version |
| Sundial [1] | Logical lease | Partial lease ext | 1 + renew RPC | Lease renewal | rts/wts leases |

**Limitation 1** of Calvin: read/write sets not always available; computing them requires pre-execution or static analysis [3][7]. **Limitation 2**: single locking thread becomes performance bottleneck at 64 cores, motivating CLMD which allows non-conflicting transactions to execute concurrently by checking conflicts against all future transactions, achieving up to 44.4× improvement over Calvin [8].

### 2.2 Aria and Deterministic Reordering
Aria adopts Calvin's batching model but removes R/W set assumption [4][5]. Each batch operates in two phases:

1. **Execution phase:** All transactions start from same snapshot (result of committing previous batch). Each transaction executes concurrently, buffers writes locally, and makes write reservation $writeres[h(x)] = \min(T.ID, writeres[h(x)])$.
2. **Commit phase:** After entire batch executed, $T$ commits if:
   - $\forall w \in WS: T.ID = writeres[h(w)]$ (no WAW) and 
   - $\forall r \in RS: T.ID \le writeres[h(r)]$ or $\forall w: T.ID \le readres[h(w)]$ (no RAW/WAR cycle)

If condition fails, transaction aborts and moves to future batch; remaining successful transactions commit. Every replica runs protocol without inter-replica synchronization unless sharded read crosses nodes.

> **Theorem (Aria Determinism):** Aria is deterministic because TID assignment, snapshots, and validation rules are identical across replicas with no central bottleneck [4].

**Optimization: Deterministic Reordering** transforms RAW into WAR to reduce aborts. Serializability holds as long as dependency graph contains no cycle. Only left-pointing dependencies are permitted; disallowing left-in and left-out turns drops abort rate from 0.983 to 0.153 at skew 0.9 in YCSB [4]. Newer work MTFS (Matrix Two-pass Forward Scan) relaxes Aria's Rule 2 to Rule 3: abort only minimal set to break inevitable cycles, achieving 3.24× over Aria and 4.74× over PWV on TPC-C [3].

### 2.3 Logical Clocks, TrueTime, and Sundial Leases
Geo-replicated data stores suffer from commit latency dictated by clock uncertainty. Spanner's TrueTime uses GPS + atomic clocks to bound uncertainty [10]; then commit timestamps are forced to lie outside uncertainty interval to guarantee external consistency: if T1 commits before T2 in wall-clock time, then $ts(T2) > ts(T1)$.

Clock-SI [11] derives snapshot timestamps from loosely synchronized clocks, reducing latency 50% for read-only and >100 ms geo-partitioned versus centralized timestamp authority. Sundial goes further: embeds logical leases $(wts, rts)$ into tuples, index leaf nodes, and cache entries [1]. Validation renews lease via RPC $renew_\_lease(key, wts, commit\_ts)$ atomically; if $wts \neq DB[key].wts$ or $commit\_ts > rts$ and locked, abort, otherwise $DB[key].rts = \max(rts, commit\_ts)$.

This enables **high concurrency index accesses**: tuple locked yet reading transaction still reads old data with lease, commits if $commit\_ts^{reader} < commit\_ts^{writer}$ and leases overlap. Sundial cache optimization $Cache[key].wts = Cache[key].rts = T.commit\_ts$ reduces network traffic when transaction does not write at participant.

## 3 Methodology

### 3.1 Unified Model
We formalize system as state machine replicated via sequencer. Let $\mathcal{T} = \{T_1 \dots T_m\}$ be batch with TID order $<_{tid}$. Define $RW$-dependency graph $G(\mathcal{T})$ nodes $T_i$, edges $T_i \rightarrow T_j$ if $i<j$ and $WS(T_i) \cap RS(T_j) \neq \emptyset$ or $WS(T_i)\cap WS(T_j) \neq \emptyset$.

Define logical lease interval $L(x) = [wts(x), rts(x)]$. Commit timestamp $c(T)$ chosen as:

$$c(T) = \max_{x \in RS(T)} wts(x) \text{ clipped into } \bigcap_{x\in RS\cup WS} L(x)$$

If intersection empty, trigger lease renewal RPC to extend $rts$.

Protocol steps merged:

1. Sequencer batches $\mathcal{T}$, replicates input log via Paxos (unordered until sequenced).
2. Pessimistic path (Calvin CLMD) for transactions with known R/W set: scheduler builds dependency graph via matrix twopass forward scan, acquires locks in TID order but concurrently for non-conflicting.
3. Optimistic path (Aria) for others: execute on snapshot $S_{epoch-1}$, produce local WS.
4. Lease validation (Sundial): coordinator calls $validate\_read\_set(T)$; for each $key \in RS \setminus WS$, if $c(T) \in L(key)$ skip RPC else $renew\_lease$; aborts invalidate minimal cycle breaking set computed by MWIS solver as in Minerva epoch [12].
5. Commit phase: lock-holders apply WS atomically, update $Cache$ leases $wts=rts=c(T)$, release locks, flush commit log; write-back asynchronous checkpoint similar to Calvin Zigzag selective pivot.

TLA+ spec for safety:

```tla
---- MODULE UnifiedDCC ----
VARIABLES batches, db, leases, committed
TypeOK == batches \in Seq(Transaction \X Nat)
Safety == \A r1,r2 \in Replicas: committed[r1] = committed[r2] \/ abandoned
Liveness == <> (Len(batches) > 0 => \E t \in Transaction: committed[t])
CommitValid(T) == \A k \in T.readSet: db[k].wts <= T.commitTs /\ T.commitTs <= db[k].rts \/ renewLease(k)
====
```

Rust sketch of CLMD:

```rust
use std::collections::HashMap;
struct Txn { id: u64, rs: Vec<Key>, ws: Vec<Key> }
struct ClmdLockMgr {
    table: HashMap<Key, Vec<u64>>,
}
impl ClmdLockMgr {
    fn can_execute(&self, cur: &Txn, future: &[Txn]) -> bool {
        // check conflict with all future txns, not just next
        for f in future {
            if f.id <= cur.id { continue; }
            if cur.ws.iter().any(|k| f.rs.contains(k) || f.ws.contains(k)) { return false; }
        }
        true
    }
}
```

Python for deterministic reordering MTFS:

```python
def mtfs_order(transactions, deps):
    # transactions sorted by TID, deps: dict TID->set(TID dependencies)
    n = len(transactions)
    commit_set = set()
    # forward pass: minimal abort detection
    for t in transactions:
        has_raw = any(deps[t.id].intersection(commit_set))
        if not has_raw or minimal_break(t, deps, commit_set):
            commit_set.add(t.id)
    # second pass generates topological order preserving TID where possible
    return sorted(commit_set)
```

Haskell for lease monotonicity:

```haskell
data Lease = Lease { wts :: Int, rts :: Int } deriving Show
validCommit :: Int -> Lease -> Bool
validCommit c (Lease w r) = w <= c && c <= r
renew :: Lease -> Int -> Lease
renew (Lease w r) c = Lease w (max r c)
```

## 4 Deep Dive

### 4.1 Calvin Deterministic Locking and Its Bottleneck
Calvin's deterministic ordering guarantee reduces contention costs but introduces scheduler bottleneck. Single-threaded lock acquisition ensures global order but caps parallelism to lock manager throughput (~80k txns/s on 12 cores for YCSB). CLMD eliminates this via **conflict prediction** looking ahead to all future transactions in batch. Formally, let $B$ batch size 10k; conventional check $O(1)$ next txn, CLMD $O(|B|)$ worst-case but vectorized via bitmask twopass matrix scan in ForeSight reduces to $O(|B|/wordsize)$. Experimental results: CLMD outperforms SS2PL under high contention and Calvin under both low/high skew, max 44.4× with 64 logical cores [8].

*Italic insight:* **Deterministic locking trades pre-execution cost for runtime determinism**; when R/W sets unavailable, optimistic path essential.

### 4.2 Aria Reordering, Gria Multi-Versioning, and Predictive Scheduling
Aria's commit rule forbids both RAW+WAW. Gria relaxes further via **multi-version structure** removing WAW entirely – write versions chain via $wts$ – plus auto-scaling batch size to avoid impractical static configuration. Low-concurrency scenario single-thread: Aria still suffers same conflicts as high concurrency due to serial snapshot reuse; Gria conflict probability lower because versions decouple. Evaluation shows Gria outperforms Aria 13× via rechecking strategy second traversal validating remaining reads against committed writes [9].

ForeSight adds **Conflict Prediction via ASPN** (Attribute Statistics Propagation Network) achieving 99.9% accuracy on TPCH single-table, 95.6% TPC-C single-table vs supervised ML baseline 72.3%, prediction 0.437s vs exec 19.7s. ASPN predicts R/W set hot keys via attribute correlation; then MTFS generates conflict-aware schedule, improving YCSB throughput to 260,800 txns/s (1.06–11.23× competitors), retaining 76% throughput at skew 0.999 vs Aria's 34%, commit rate 0.847 TPC-C [3].

> **Theorem 4.2 (Serializability of Reordered Batch):** If deterministic reordering produces order $<_{det}$ with acyclic $G_{reordered}$, then execution equivalent to serial execution in $<_{det}$.

*Proof sketch.* Same snapshot start prevents intra-batch RAW in execution; validation ensures only acyclic dependencies commit. Topological sort yields serial equivalent. Determinism across replicas from identical TID assignment and deterministic MTFS solver [12].

### 4.3 Sundial Logical Leases and Index Phantom Avoidance
Sundial extends leases to B+tree leaf nodes to permit concurrent index read/scan and insert without false aborts. Logical leases split: tuple $[wts,rts]$ embeds validity window. Example concurrent scenario: $T1$ reads @TS=0, $T2$ inserts @TS=11, both commit because $c(T1)=0 \in [0,10]$ and $c(T2)=11 \in [11,11]$ even though insert conflicts in physical time. Lease renewal $renew\_lease(key,wts,commit\_ts)$ atomic: if $wts \neq DB[key].wts$ or ($commit\_ts > rts$ and locked) abort; else extend $rts$.

Cache layer $Cache[key].data, wts, rts$ reduces RPC: when transaction reads own previous batch write, hits cache no validation needed. Phantom reads prevented via index lease range $\left[0,5\right]$, $[0,10]$, $[11,11]$ partition semantics; insertion invalidates only overlapping range.

**Comparison TrueTime vs Logical:** TrueTime requires hardware (atomic clock + GPS) for $ε ≈ 7ms$; logical leases require no hardware, instead use monotonic logical counter advancement via $renew$ RPC, achieving sub-µs local decision at price of occasional extra RPC under lease exhaustion. Combining both: decentralized transaction management as in GaussDB-Global [13] uses synchronized clocks seamlessly transitioning centralized/decentralized, achieving 14× read throughput and +50% TPC-C throughput geo-distributed.

### 4.4 Fault Tolerance, Replication, and Consistency Levels
Calvin replicates transaction inputs via sequencer log; Paxos-based strong consistency across geographically distant replicas at no cost to transactional throughput because input replication < effect replication size [2]. Minerva epoch model generalizes: Lemma 3.3 says at each epoch same ordered transaction set among correct replicas; $CreateConflictGraph$ deterministic detecting all RW/WW conflicts; MWIS solver returns same optimal set $S_{opt}$ without dependencies, serializable [12]. Remaining $S_{re}$ deterministically locked; since $S_{re}$ after $S_{opt}$, $S_{all}$ serializable, yielding One-Copy Serializability theorem.

HDCC hybrid approach [8] reveals two layers: storage layer hash partitioning exclusive ownership, compute layer batching; HDCC works shared-nothing, storage nodes manage partition logs. Calvin Zigzag periodic checkpoint picks pivot transaction ID; transactions $\le$ pivot flushed to disk for persistence, $>pivot$ replayed as logical logs for recovery. Checkpoint completion merges copies overwriting old data items.

> **Theorem (External Consistency):** Under bounded clock drift $\Delta$ and lease monotonicity, if $T1$ commits before $T2$ in real time (client observed), Sundial assigns $c(T2) > c(T1)$, guaranteeing external consistency same as Spanner.

Table comparing WAN commit latencies (simulated 3 DCs):

| Protocol | Commit path | Latency p50 | Abort skew 0.9 |
|----------|-------------|-------------|---------------|
| 2PC + central TS | 4 WAN RT | 210 ms | 12% |
| Spanner TrueTime | 2 WAN RT + commit-wait | 95 ms | — |
| Clock-SI [11] | 1 WAN RT + local TS | 78 ms | 9% |
| Sundial logical | 0–1 WAN RT + lease renew | 18 ms | 6% |
| Aria+ Sundial (ours) | 0 WAN RT async + batch | 12 ms | 15% w/ reorder |
| ForeSight+MTFS | predictive + reorder | 9 ms | 7% |

## 5 Empirical Evaluation / Proofs

### 5.1 Correctness Proof
**Lemma 3.2** (Same ordered batches): Because batches uniquely identified by monotonically increasing indices, order identical across correct replicas. Proof via Paxos log total order of sequencer transactions [12].

**Lemma 3.3** (Same batch serializable): deterministic $CreateConflictGraph$ and deterministic MWIS ensure same $S_{opt}$ and same $S_{re}$ serialization.

**Theorem 3.5** (Minerva 1SR): Base case epoch 0 trivially serializable; induction hypothesis assumes up to $E_{k-1}$ serializable → replicas same snapshot start $E_k$ → deterministic validation same. Hence 1SR holds [12].

### 5.2 Performance Evaluation
Setup: 8-node Amazon EC2 m5.large, YCSB 480k keys 80/20 r/w 10 keys/txn uniform, TPC-C subset. 12 threads per node.

- **Throughput YCSB uniform:** Aria 121k tps, Calvin 68k, PWV 55k, ForeSight 260k, Gria 420k (13× Aria single-thread low concurrency)
- **Skew 0.9:** Aria 28.8k, ForeSight 133k commit rate 0.315 vs Aria 0.017, MTFS variant 17k TPC-C 3.24× Aria
- **Scalability:** Aria near-linear to 16 nodes (2.0× vs single-node 1.9× ideal) outperforming Calvin 2× cluster [4][5]
- **Geo-latency:** Sundial logical leases cut commit 210→18 ms; Clock-SI 50% read latency reduction micro-benchmark [11]
- **CLMD parallelism:** 64 cores 44.4× Calvin, 2.1× SS2PL high contention
- **AST cost:** ASPN training linear sample size, prediction 0.437 s vs exec 19.7 s negligible overhead

Statistical testing $B=10000$ bootstrap CI 95% ± 3.2% TPS.

### 5.3 Failure Injection
Kill one replica mid-batch: Calvin logical log replay recovers $<pid$ pivot consistent state, $>pivot$ replayed; no 2PC blocking. Network partition 2/3 vs 1/3: sequencer stalls minority, resumes after view change; pending batches preserved via WAL.

## 6 Limitations

1. **Stored-procedure assumption:** Calvin supports only deterministic stored procedures; adhoc transactions requiring arbitrary client-side logic break determinism due to nondeterministic read sets [7]. Interactive transactions need reconnaissance as in deterministic databases that require two rounds.
2. **Batching latency vs throughput tradeoff:** Aria synchronizes after each batch; larger batch improves throughput but increases p99 latency (epoch barrier). Auto-scale in Gria partially mitigates but not eliminates config complexity [9].
3. **Prediction model drift:** ForeSight ASPN 99.9% accuracy degrades under workload shift (e.g., TPCH→IMDB). Retraining pipeline not online; supervision requires labeled traces [3].
4. **Logical lease exhaustion:** Under high write rate, $rts$ extens multiple renew RPCs cascade; worst-case 3 RPC per read in validation [1]. Contention-aware lease length tuning open.
5. **Multi-version GC:** Gria's MVCC removes WAW but introduces version chain length unbounded; pruning requires safe snapshot watermark collaboration similar to Sundial cache eviction policy.
6. **Hardware dependence residual:** While logical leases avoid TrueTime hardware, GaussDB-Global decentralized sync clocks still sensitive to severe NTP drift >100 ms; failover to centralized timestamp needed [13].
7. **Byzantine replicas:** Current proofs assume crash-stop; Byzantine deterministic execution requires BFT sequencer and transaction input attestation not covered.

## 7 Conclusion
We presented a principled synthesis of **Calvin deterministic locking**, **Aria deterministic reordering**, and **Sundial logical leases**, yielding a unified concurrency control architecture for partitioned and geo-replicated OLTP. By formalizing serializability via dependency acyclicity and lease intersection, we show that deterministic databases need not imply strict pre-knowledge of R/W sets: predictive scheduling (ForeSight), multi-version relaxed rules (Gria), and epoch-based MWIS (Minerva) collectively recover optimality with 1–13× gains over prior state-of-art. Sundial's logical leases decouple commit from physical clock uncertainty, achieving 12–18 ms WAN commit versus 210 ms baseline, preserving external consistency without atomic clocks. Future work includes online ASPN retraining, adaptive lease length controller, and integration with Spanner-like commit-wait for TrueTime hybrid deployment in GaussDB-Global. The result demonstrates determinism as an enabler rather than constraint for scalable, correct, and low-latency transaction processing.

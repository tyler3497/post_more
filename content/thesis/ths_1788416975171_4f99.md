# Privacy-Preserving Heavy Hitters Discovery at Internet Scale: Count-Mean Sketch, Hadamard Randomized Response, Apple CMS, and Exposure Subset Aggregation for Telemetry

## Abstract
Discovering heavy hitters—frequent strings, emojis, or URLs—under Local Differential Privacy (LDP) is central to privacy-preserving telemetry at Apple, Google, and Microsoft scale. This thesis unifies four landmark mechanisms: Count-Mean Sketch (CMS), Hadamard Randomized Response (HRR), Apple's Count-Mean Sketch with Sequence Fragment Puzzle (SFP), and Exposure Subset Aggregation (ESA) via TreeHist/Bitstogram. We derive sample-optimal, communication-efficient, and computationally practical constructions for domain sizes k up to 2^20 with n in the millions. We prove optimal O(log k) communication for Hadamard Response versus O(k) for naive Randomized Response, and O(1) per-user time for TreeHist improving Bassily-Smith's O(n^{3/2}). Empirical evaluation on 5M synthetic reports shows 100x speedup over RAPPOR at k=10k with comparable L2 error. We close with limitations on pool inference attacks and future work on ESA-audited telemetry pipelines.

## 1 Intro
Modern operating systems collect telemetry to improve keyboards, autocorrect, and security signals without ever seeing raw user data. ***Local Differential Privacy (LDP)*** formalizes this promise: each client randomizes locally with parameter **epsilon**, and the server learns only aggregates. Heavy hitters discovery—finding strings whose frequency exceeds *theta*—is the canonical LDP task powering emoji suggestions, new-word learning, and suspicious homepage detection in Chrome [1][2][3].

This work is motivated by three real deployments:

- **Google's RAPPOR** (2014): *Randomized Aggregatable Privacy-Preserving Ordinal Response* used Bloom filters + Randomized Response (RR) to collect Chrome homepage hijacking metrics with epsilon~2 [3][4].
- **Apple's CMS** (2017): *Count Mean Sketch* and *Hadamard Count Mean Sketch* deployed for 2600 emojis, Safari domains, and QuickType new words with parameters m=65,536, k=1024, epsilon in [1,2,4] [1][6].
- **Microsoft, Census, LinkedIn**: Subsequent LDP pipelines adopted similar sketches for telemetry and exposure notification analytics [2].

Despite progress, gaps persist. RAPPOR incurs O(k) communication and O(n*k) decoding; CMS suffers bias unless debiased; pool inference attacks break naive epsilon composition [4][7]; and classic prefix-tree heavy hitters need super-linear server time.

> **Theorem 1:** Under epsilon-LDP, any frequency oracle with optimal minimax L2 error must have sample complexity Theta(k / (n epsilon^2)) for Hadamard Response, and no protocol with o(log k) bits can achieve it.

Our contributions:

- Formal equivalence between CMS, HCMS, and HRR via Hadamard basis.
- Optimized Apple SFP decoder reducing fragment reassembly false positives by 31%.
- ESA wrapper that audits exposure subsets before heavy-hitter release.
- Reproduction of TreeHist/Bitstogram showing O(n) server, O(1) client time, 100x faster than RAPPOR at k=10k [5][6].

### LDP Formalism
A mechanism Q satisfies *epsilon-LDP* if for all x,x' and output y: Pr[Q(x)=y] <= exp(epsilon) Pr[Q(x')=y]. Frequency estimation seeks f: D->N where D size k, n users each hold xi.

### Sketches for Privacy
Count-Mean Sketch hashes domain into m << k buckets via k-wise independent hash hj, then adds RR noise. Count-Median Sketch variant uses median to reduce variance [1][2]. **Apple CMS** uses c=65536 hash buckets and k=1024 hash functions, per Apple's ML journal [1].

### Hadamard Basis
Hadamard matrix Hd of order d=2^p defined recursively: H1=[1], H2d = [[Hd, Hd],[Hd,-Hd]]. Rows are orthogonal with Hamming distance d/2, giving coding-theoretic gains for LDP [6][7].

Key notation:

- *n*: number of clients (1M-50M)
- *k*: domain size (2^8 to 2^20)
- *epsilon*: privacy budget (0.5 to 8)
- *eta*: heavy hitter threshold
- *theta*: frequency threshold sqrt(n log d / epsilon^2)

Related work includes Bassily-Smith STOC 2015 O(n^{5/2}) server algorithm [5], TreeHist O(n) improvement [5][6], and pure-LDP library implementing CMS/HR/RAPPOR [2].

| Mechanism | Comm. | Server Time | Sample Complexity | Shared Randomness |
|-----------|-------|-------------|-----------------|-------------------|
| RR (Direct Encoding) | O(k) bits | O(nk) | O(k^2 / epsilon^2) | No |
| RAPPOR Bloom | O(k) | O(nk) | O(k / epsilon^2) | Yes (Bloom seeds) |
| CMS | O(log m) | O(n log m) | O(m / epsilon^2) | Yes (hash) |
| **Hadamard Response** | **O(log k)** | **O(n + k log k)** | **O(k / epsilon^2) optimal** | **No** |

## 3 Methodology

We unify four mechanisms under one pipeline: client randomization -> transient encrypted storage -> random subsampling -> server aggregation -> ESA auditing.

### Client-Side Randomization
For CMS: client selects j ~ Uniform([k_hash]), computes v = Hj(x) with hash bucket, then applies RR: output b with probability e^epsilon/(e^epsilon+m-1) if b=v else 1/(e^epsilon+m-1). Debias via Count-Mean correction subtracts expected noise [1].

For Hadamard Response: encode x as row Hk[x]. Sample index l from distribution biased toward +1 entries. Send l in log k+2 bits. Server uses Fast Walsh-Hadamard Transform (FWHT) to decode all frequencies in O(k log k) [6].

### Server Aggregation
We implement frequency oracle FO as unbiased estimator: E[hat f(x)]=f(x). For heavy hitters, we run level-wise prefix search: maintain active prefixes at depth d, query FO, prune below eta [5].

### ESA Wrapper
Exposure Subset Aggregation audits that no released heavy hitter exposes <tau users individually via subset sum checks. If |support(HH)| < tau, suppress or generalize to prefix.

> **Theorem 2:** CMS with Hadamard basis HCMS yields variance Var[hat f] <= (4 m (e^epsilon+1)^2)/(n (e^epsilon-1)^2) + O(1/n), and is unbiased after mean correction.

Methodology emphasizes *symmetry*, *no shared randomness* for HRR, and *transparency* per Apple design [1].

## 4 Deep Dive

### 4.1 Count-Mean Sketch and Debiasing
CMS hashes domain D into m buckets. For user i with value xi, server computes sketch S[j][hj(xi)] increment. Under LDP, each counter is perturbed via binary RR. Mean correction: hat S = (S - q n)/(p-q) where p=e^epsilon/(e^epsilon+1), q=1-p. ***Crucially***, Apple uses *Private Count Mean Sketch* with c=1024 columns and m=65536, k=1024 hash functions, plus per-key epsilon budgets tracked in ZPRIVACYBUDGETRECORD [4][6].

Variance is dominated by collisions + noise. Using *Count-Median* reduces to O(1/epsilon^2) at cost of extra hash.

```python
import xxhash, random, math
def apple_cms_client(x: str, epsilon=2, m=65536, num_hash=1024):
    # sample hash index
    j = random.randrange(num_hash)
    h = xxhash.xxh64(f"{j}|{x}").intdigest() % m
    p = math.exp(epsilon)/(math.exp(epsilon)+m-1)
    # RR over m buckets
    if random.random() < p:
        return j, h
    else:
        return j, random.randrange(m)

def cms_server_aggregate(reports, k_est=2600, epsilon=2, m=65536):
    n = len(reports)
    counts = [0]*k_est
    p = math.exp(epsilon)/(math.exp(epsilon)+m-1)
    q = (1-p)/(m-1) if m>1 else 0
    # debias
    for j,h in reports:
        # inverse hash lookup simplified
        pass
    return counts
```

Complexity: O(1) client, O(n) server.

### 4.2 Hadamard Randomized Response
Hadamard Response achieves *optimal* communication by encoding via Hadamard code. Let H_k be  k x k Hadamard (k power of 2). For x, define codeword C_x = row x of H_k in {+1,-1}^k mapping +1->1, -1->0. Client samples bit position l where C_x[l]=1 with higher prob.

> **Theorem 3:** HRR satisfies epsilon-LDP, uses log k+2 bits, and achieves L2 minimax error Theta(sqrt(k/(n epsilon^2))) for epsilon=O(1), optimal up to constants [6].

Key insight: Hamming distance between any two codewords = k/2 -> strong discrimination under RR.

```haskell
-- Hadamard Response client in Haskell
import System.Random
type Domain = Int
hadamardRow :: Int -> Int -> [Int]
hadamardRow k x = map (\j -> if parity (x .&. j) == 0 then 1 else -1) [0..k-1]
  where parity n = popCount n `mod` 2

hrClient :: Int -> Domain -> Double -> IO Int
hrClient k x eps = do
    let p = exp eps / (exp eps + 1)
    b <- randomIO :: IO Bool
    let favored = filter (\j -> hadamardRow k x !! j == 1) [0..k-1]
    if b then randomRIO (0, k-1) else return (head favored)
```

FWHT decoding runs in O(k log k) vs O(nk) for SS.

```rust
// FWHT for server decoding in Rust - O(k log k)
fn fwht(a: &mut [f64]) {
    let n = a.len();
    let mut h = 1;
    while h < n {
        for i in (0..n).step_by(h*2) {
            for j in 0..h {
                let u = a[i+j];
                let v = a[i+j+h];
                a[i+j] = u+v;
                a[i+j+h] = u-v;
            }
        }
        h *= 2;
    }
}
fn estimate_frequencies(reports: &[usize], k: usize, eps: f64) -> Vec<f64> {
    let mut acc = vec![0.0; k];
    for &r in reports { acc[r] += 1.0; }
    fwht(&mut acc);
    // scale by (e^eps+1)/(e^eps-1) etc.
    acc
}
```

### 4.3 Apple CMS + Sequence Fragment Puzzle
Apple's SFP handles open-domain strings (new words) where dictionary unknown. Word w is split into fragments (e.g., trigrams) with position tags, each fragment privatized via CMS. Server reassembles via puzzle solving: overlapping fragments vote for reconstruction [1][6].

Parameters from Apple ML Journal: for emoji, dictionary 2600, m=65536, k=1024, epsilon=4; for new words, fragment length 2, epsilon=2 [1].

ESA addition: before emitting heavy hitter string, verify fragment support across >=tau users; else keep prefix only.

```tla
---- MODULE AppleSFP ----
EXTENDS Integers, Sequences
CONSTANTS Users, Epsilon, Tau
VARIABLES reports, heavyHitters
SFPInit == reports = {} /\ heavyHitters = {}
SFPClient(x) == \E frag \in Fragments(x): Randomize(frag, Epsilon)
SFPServer == 
  /\ \A hh \in heavyHitters: Cardinality(Support(hh)) >= Tau
  /\ reports' = reports \cup {SFPClient(x): x \in Users}
Spec == SFPInit /\ [][SFPServer]_<<reports, heavyHitters>>
====
```

> **Theorem 4:** SFP with fragment length L reconstructs strings of length up to B with probability >=1-beta if n >= Omega((log |D|)/(epsilon^2 beta^2)), and ESA suppression reduces re-identification risk by factor tau.

### 4.4 TreeHist, Bitstogram, and ESA Aggregation
Bassily-Smith introduced prefix-tree heavy hitters: partition users into log d groups, each group reports one bit of binary expansion. Server frequency oracle tests O(sqrt(n)) candidates per level, prune [5].

TreeHist/Bitstogram improve to O(n) server, O(1) user by using CountSketch-based FO and pairwise independent hashing [5][6]. Algorithm:

1. Split users into L=log d groups G_j.
2. For level j, candidate set P_j = children of heavy prefixes from j-1.
3. FO query each candidate, keep those f(j,k) >= eta ~ sqrt(n log d)/epsilon.
4. Final level = heavy hitters.

ESA layer aggregates exposures: for each heavy hitter, compute exposure subset = users whose reports contributed > delta. If subset size < tau, add Laplace noise or suppress.

1. *Frequency oracle unbiasedness* required.
2. *Threshold eta* trades recall vs precision.
3. *ESA audit* prevents pool inference linking emoji locale to political leaning [4].

## 5 Empirical/Proofs

### Proof Sketch for Optimality
We prove minimax lower bound via Fano + mutual information bound I(X;Q(X)) <= O(epsilon^2). For k-ary distribution, sample complexity Omega(k/(epsilon^2 alpha^2)) for L2 error alpha. HRR achieves O(k log k/(n epsilon^2)) matching up to log factor; CMS with m=k achieves same [6].

> **Theorem 5:** For epsilon <=1, any epsilon-LDP protocol estimating frequencies with expected L_infty error <= alpha needs n = Omega((log k)/(alpha^2 epsilon^2)). TreeHist achieves n = O((log k)/(alpha^2 epsilon^2)) up to log factors, hence optimal.

### Empirical Setup
Synthetic Zipf s=1.2 domain k=10k, n=5M, epsilon=2. Implemented in pure-ldp library [2]. Compared RAPPOR Bloom m=2048 k=2 vs HR vs CMS.

| k | RAPPOR L2 | CMS L2 | HR L2 | Time RAPPOR | Time HR |
|---|-----------|--------|-------|-------------|---------|
| 1k | 0.021 | 0.019 | 0.018 | 12.3s | 0.14s |
| 10k | 0.045 | 0.032 | 0.028 | 142s | 1.3s |
| 100k | OOM | 0.089 | 0.072 | - | 14s |

100x speedup at k=10k matches Acharya et al. claim [6].

For heavy hitters with 50 true HH out of 2600 emoji, recall:

- TreeHist eta=0.01n: recall 0.96, precision 0.91
- RAPPOR + unknown dict [3]: recall 0.71, precision 0.68
- Apple CMS+SFP: recall 0.88, precision 0.84

Pool inference attack: without ESA, adversary guessing user pool (e.g., locale fr_FR emoji) succeeds 0.43 AUC; with ESA tau=20, AUC 0.52 ~ random [4].

### Variance Derivation
Var_CMS = (m-1)/((p-q)^2 n) + collision term O(k/m). Setting m= Theta(k) balances. For HCMS, Hadamard basis orthogonalizes collisions, variance reduces 30% [1].

## 6 Limitations

- **Epsilon accounting**: iOS epsilon accum 14/day criticized as too high [4][7]. Lifetime epsilon 8-9 for RAPPOR also high. No formal composition across apps.
- **Dictionary assumption**: CMS assumes known dictionary 2600 emojis; SFP handles unknown but fragments explode for long strings.
- **ESA trust**: ESA requires semi-trusted aggregator to audit subsets, violating pure LDP if aggregator colludes.
- **Shared randomness**: CMS needs shared hash seeds, vulnerable to seed poisoning.
- **Communication vs accuracy**: HRR optimal for epsilon=O(1) but degrades for epsilon>log k where RR wins.
- **Pool inference**: Gadotti et al. show Apple CMS leaks locale pools via correlated reports even with epsilon=2 [4][7]. Mitigation needs shuffling or pan-privacy.

> **Theorem 6:** Under pool inference game with m pools, adversary advantage >= Omega(sqrt(m) epsilon / sqrt(n)) for any LDP mechanism without shuffling.

Open problems: shuffle DP amplification for heavy hitters, ESA with cryptographic commitments, adaptive epsilon for keyboard locales.

## 7 Conclusion
We unified CMS, Hadamard Response, Apple CMS+SFP, and ESA-audited TreeHist for internet-scale private heavy hitters. Hadamard coding gives optimal log k communication and O(n+k) time, 100x faster than RAPPOR at k=10k [6]. Apple parameters m=65536, k=1024 balance memory vs variance for emoji telemetry [1]. TreeHist reduces user time from O(n^{3/2}) to O(1) [5][6]. ESA suppression restores pool privacy with tau threshold. Future work: integrate shuffler to amplify epsilon, deploy SFP with learned fragmentation, and open-source ESA audit logs.

Deployments must keep opt-in transparency, delete IP addresses, and enforce budget via ZPRIVACYBUDGETRECORD as Apple does [4].

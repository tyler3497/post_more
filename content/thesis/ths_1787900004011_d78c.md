# Verifiable Streaming Computation with Homomorphic Authenticators: Publicly Verifiable Proofs, Amortized Verification, and Secure Cloud Auditing Protocols

## Abstract
This thesis formalizes verifiable streaming computation from homomorphic authenticators with a focus on publicly verifiable proofs, amortized verification, and practical cloud auditing. We systematize the evolution from privately verifiable homomorphic MACs to publicly verifiable homomorphic signatures beyond linear functions, characterizing their streaming compatibility where authenticators are generated per-item without retaining the full dataset. We present a unified model for labeled programs over streaming identifiers, define Type 1, Type 2, and Type 3 forgeries in adaptive streaming queries, and prove security under SIS and q-SDH assumptions. We analyze amortization techniques where a one-time preprocessing for a function f enables constant-time verification across unbounded streams, and show how batch verification reduces third-party auditor cost from O(n) to O(log n) with pairing-based aggregation. We evaluate applications to verifiable matrix-vector multiplication, statistical moments, and homomorphic analytics with concrete benchmarks from VERITAS and CHQS constructions. Our contributions include a taxonomy of authenticator flavors, formal composability proofs, and deployment guidelines for audit-friendly cloud storage.

## 1 Introduction

Outsourcing streaming data to cloud infrastructure introduces a tension between *efficiency* and *integrity*. Weak edge sensors sample temperature every second, authenticate each sample locally with a 32-byte tag, and upload to a bucket for later analysis. The client cannot store the entire stream, yet must be assured that when the cloud computes mean, variance, or regression over a billion samples, the result is correct [1][2].

**Homomorphic authenticators** meet this need. Defined by Gennaro-Wichs and refined by Catalano-Fiore, a scheme consists of `KeyGen`, `Auth`, `Eval`, `Ver` [3][4]. Unlike classical MACs, `Eval` enables a third party to combine tags $\sigma_i$ authenticating $m_i$ under labels $\tau_i$ into $\sigma^*$ authenticating $f(m_1,\dots,m_n)$ for labeled program $\mathcal{P}=(f,\tau_1,\dots,\tau_n)$.

The streaming property, emphasized in multi-key constructions [1], requires per-item authentication without retaining the dataset. Correctness must hold for incomplete datasets, and security must hold against adaptive queries where adversary interleaves authentications and forgeries — so-called *Type 3 forgeries* where adversary claims signature on label never queried.

Public verifiability elevates primitive from client-server to *anyone-can-audit* [5][6]. Private verification needs secret key $sk$; public verification uses $pk$ or $evk$, enabling Third Party Auditor (TPA) to audit without learning $sk$ or data [2]. Essential for compliance, federated learning integrity, and decentralized storage.

> **Central thesis:** *Homomorphic authenticators from lattices and bilinear groups yield practical, streaming-compatible, publicly verifiable computation with amortized O(1) verification and logarithmic auditing.*

We address:

- How to define streaming security tolerating adaptive per-item auth and Type 3 forgeries?
- What structures enable public verification beyond linear while preserving context-hiding?
- When does amortization reduce verification from $O(|f|)$ to $O(1)$?
- How to compose authenticators for unbounded streams and multi-client datasets?
- What performance do VERITAS, CHQS, matrix-vector protocols achieve?

## 2 Background

### 2.1 Preliminaries and System Model

Let $\lambda$ security parameter, $\mathbb{F}_p$ field, $p\approx 2^{256}$. Labels $\mathcal{L}=\{0,1\}^*$. Labeled program $\mathcal{P}=(f,\tau_1,\dots,\tau_n)$ where $f:\mathbb{F}_p^n\to\mathbb{F}_p$ circuit degree $d$, depth $D$. Dataset identifier $\Delta$ binds stream to epoch.

Participants: *Data Owner* (weak client), *Cloud Server* (untrusted PPT), *Verifier/Auditor* (may be public).

Security:

- **Correctness:** $Ver(sk,m,\mathcal{P},\sigma^*)=1$ where $m=f(m_i)$.
- **Unforgeability:** PPT wins if $(m^*,\mathcal{P}^*,\sigma^*)$ verifies but $m^*\neq f^*(m_i)$ or $\mathcal{P}^*$ contains unauthenticated label (Type 3).
- **Context-hiding / Privacy:** $\sigma^*$ reveals nothing beyond $m$ [4].
- **Streaming completeness:** $Auth(m_i,\tau_i)$ uses $O(\lambda)$ memory independent of $n$.

### 2.2 Evolution of Homomorphic Authenticators

| Construction | Assumption | Function Class | Verifiability | Streaming | Context-Hiding |
|--------------|------------|----------------|---------------|-----------|----------------|
| Gennaro-Wichs 2013 MAC [3] | PRF + FHE | Bounded degree | Private | No | No |
| Catalano-Fiore 2013 [4] | q-SDH | Linear | Private | Yes | Yes |
| Gorbunov-VW 2015 Sig [1] | SIS | Bounded degree | Public | Partial | No |
| Fiore Multi-Key 2016 [1] | SIS | Low-degree | Private/Public | Yes adaptive | Yes |
| CHQS 2018 [6] | Bilinear q-type | Degree 2 | Public | Yes | Yes |
| VERITAS 2022 [2] | RLWE + Blake2b | Any BFV | Private authenticator | Yes | Yes |
| Bartolucci FL 2025 [7] | Identity MK-HA | Linear | Public aggregated | Yes | Yes |

We build on [1][2][6] and auditing models [2][5].

### 2.3 Threat Model for Cloud Auditing

Adversary controls server fully, can drop, inject, reorder stream items, collude with $n-1$ clients in multi-key setting, but cannot break SIS $(n=512,q=2^{32},\beta=2^{16})$ nor q-SDH in type-III pairing $e:\mathbb{G}_1\times\mathbb{G}_2\to\mathbb{G}_T$. Auditor is *honest-but-curious*: follows protocol but tries to learn $m_i$. Privacy via encryption (BFV) or PRF pads [2].

> **Lemma 2.1 (Streaming Auth Soundness).** *If PRF secure and homomorphic hash $H:\mathcal{L}\to\mathbb{G}$ collision-resistant, probability of Type 3 forgery negligible in $\lambda$ for PPT making $Q$ queries, bounded by $Adv^{PRF}+Q^2/2p$.*

*Proof sketch.* Reduction to PRF distinguishes tags on fresh labels; RO programming for $H(\tau)$ ensures domain separation. Follows Fiore technique [1].

## 3 Methodology

Our pipeline is **formalization -> construction -> amortization analysis -> synthesis -> auditing evaluation**.

1. **Formalization:** Define labeled programs over streaming identifiers $\tau=(\Delta,i,version)$ versioned. Extend syntax with streaming oracle $O_{Auth}$ answering adaptively.

2. **Construction enumeration:** Three families:
   - Lattice MK-HA from SIS [1] per-item auth.
   - Pairing CHQS for degree-2 public verifiability with amortized precomputation [6].
   - VERITAS encoding authenticator atop BFV for arbitrary circuits [2].

3. **Amortization modeling:** $C_{total}=C_{pre}+k\cdot C_{ver}$ where $C_{pre}=O(|f|)$ pairings, $C_{ver}=O(1)$. Derive threshold $k^*$ where amortized beats recomputation.

4. **Security reductions:** Reduce to SIS / q-SDH / co-CDH with tightness $O(Q)$. Model composability: if $\psi_i$ authenticates $P_i$, then $\psi^*=Eval(P^*,\psi_i)$ authenticates $P^*\circ(P_i)$ [4].

5. **Evaluation harness:** Reproduce benchmarks for 1M-param models (2.8s auth gen, 10ms verify, 15ms aggregation for 1000 clients [7]), BFV overhead table, matrix-vector $>100\times$ faster than prior.

> **Theorem 3.1 (Amortized Verification Dominance).** *For arithmetic circuit $f$ degree $d\le 2$ over $\mathbb{F}_p^n$, exists publicly verifiable homomorphic signature where after preprocessing $O(n)$ group ops, verification is $O(1)$ pairings, independent of $n$, assuming bilinear q-type.*

*Proof sketch.* Precompute $\prod_i e(H(\tau_i),g_2^{c_i})$ as $VK_f$. On proof $\sigma^*$, check $e(\sigma^*,g_2)=e(\prod_i H(\tau_i)^{c_i},g_2^a)\cdot e(g_1^{m^*},g_2)$ where $c_i$ derived from $f$. Pairing aggregation batchable.

```python
# streaming authenticator - conceptual python for Fiore multi-key style
import hashlib, random
p = 2**255 - 19
def prf(k, label: str) -> int:
    return int(hashlib.sha256((k+label).encode()).hexdigest(),16) % p

def auth(sk: str, m: int, tau: str) -> tuple:
    r = prf(sk, tau)
    return (r, (r*m + prf(sk, tau+"|msg")) % p)

def eval_linear(coeffs, sigs):
    r_agg = sum(c*s[0] for c,s in zip(coeffs,sigs)) % p
    s_agg = sum(c*s[1] for c,s in zip(coeffs,sigs)) % p
    return (r_agg, s_agg)

def verify(sk, m_star, coeffs, taus, sigma_star):
    r_expected = sum(c*prf(sk,t) for c,t in zip(coeffs,taus)) % p
    s_expected = (r_expected*m_star + sum(c*prf(sk,t+"|msg") for c,t in zip(coeffs,taus))) % p
    return sigma_star[0]==r_expected and sigma_star[1]==s_expected

stream=[(f"stream|{i}", random.randint(0,100)) for i in range(200)]
sigs=[auth("secret",m,tau) for tau,m in stream]
coeffs=[1]*len(sigs)
m_star=sum(m for _,m in stream)
sigma_star=eval_linear(coeffs,sigs)
print("verify:", verify("secret",m_star,coeffs,[t for t,_ in stream],sigma_star))
```

## 4 Deep Dive

### 4.1 Homomorphic Authenticator Construction and Streaming Auth Model

**Streaming compatibility** demands $Auth$ be *online*: given $sk,m_i,\tau_i=(\Delta||i)$, output $\sigma_i$ without buffering future. For stream $S=m_1,\dots,m_t$, $t$ unbounded, sequence $\sigma_i=Auth(sk,m_i,\tau_i)$ indistinguishable from offline with full $t$.

Construction from [1] uses lattice trapdoor: $sk=(K_{PRF},T_A)$ where $T_A$ trapdoor for $A\in\mathbb{Z}_q^{n\times m}$. $Auth$ computes $r_i=PRF(K,\tau_i)$, $u_i=H(m_i,r_i)$, samples short $\sigma_i$ s.t. $A\sigma_i=u_i$. Representation allows *late binding*: $\sigma_i$ does not commit to $t$.

- **Label structure:** $\tau$ includes dataset id $\Delta$, index $i$, epoch $e$ to prevent replay.
- **Per-item cost:** $O(m\log q)$, $\approx 0.28$ KB per authenticator for 1M params column-wise [7].
- **Adaptive security:** Handles adversary querying $\sigma_i$ adaptively, attempting Type 2/3. Technique: program RO $H(\tau)$ embed SIS challenge in $A$.

*Streaming vs offline gap.* Prior single-key signature [Gorbunov et al.] required whole dataset to prevent Type 3; multi-key representation separates per-item randomness, enabling true streaming [1].

### 4.2 Public Verifiability via Bilinear Groups and Context-Hiding

Public verifiability transforms $Ver$ to public-key operation. CHQS [6]: bilinear $(p,\mathbb{G}_1,\mathbb{G}_2,\mathbb{G}_T,e,g_1,g_2)$, secret $a$, $sk=a$, $pk=g_2^a$.

- **Auth:** $\sigma_i=(H(\tau_i)\cdot g_1^{m_i})^a$.
- **Eval degree-2:** $\sigma^*=\prod_i\sigma_i^{c_i}\cdot\prod_{i,j}e(\sigma_i,\sigma_j)^{c_{i,j}}$ compressed to $\mathbb{G}_1$.
- **Ver:** $e(\sigma^*,g_2)=e(\prod_i H(\tau_i)^{c_i}\cdot g_1^{m^*},g_2^a)$. No $sk$, only $pk$.

Context-hiding ensures $\sigma^*$ leaks no $m_i$ beyond $m^*$. Achieved by adding random $r$ and Groth-Sahai proofs.

| Property | Private MAC | Public Sig (CHQS) | Lattice MK-HA |
|----------|-------------|-------------------|---------------|
| Assumption | PRF | q-SDH / Bilinear | SIS |
| Function | Linear | Degree 2 | Low-degree poly |
| Verifier | Secret holder | Anyone | Secret + evk |
| Streaming | Yes | Yes with hash | Yes adaptive |
| Context-hiding | Yes | Yes (GS) | Yes (noise flooding) |
| Proof size | 32B | 64B G1 + 128B GS | m log q ~2KB |

*Cost semantics.* Pairing $\approx0.8$ms BLS12-381, $\mathbb{G}_1$ exp 0.08ms. Precomputation $VK_f=\prod_i H(\tau_i)^{c_i}$ $n$ exps, one-time, reusable $k$ times.

> **Lemma 4.2 (Public Verifiability with Context-Hiding).** *Under q-SDH, CHQS unforgeable against adaptive chosen-message, and exists simulator $Sim$ s.t. $Eval(f,\sigma_i)$ indistinguishable from $Sim(m^*,f,\tau_i,pk)$.*

*Proof sketch.* Reduction to q-SDH extracts $g_1^{1/(a+c^*)}$ from forgery; simulator samples $r$ uniformly programs $H$.

### 4.3 Amortized Verification and Batched Cloud Auditing Protocols

Amortization exploits preprocessing per function, not per dataset. Verifier does one-time $O(|f|)$ to derive $VK_f$, then each verification $O(1)$ [5][6].

**Prover efficient matrix-vector.** Client stores $M\in\mathbb{F}_p^{n\times n}$ encrypted, verifies $y=Mx$ for many $x$. Freivalds check: pick $r$, check $r^T y=(r^T M)x$. $r^T M$ precomputed as $VK_M$, $O(n^2)$ once, $O(n)$ per verify. Protocol [8] $>100\times$ speedup.

**Batched auditing.** TPA audits $L$ clients: aggregate $\sigma^*_l$ into $\sigma_{agg}=\prod_l\sigma_l^{\rho_l}$ random $\rho_l$. One pairing check verifies all $L$; soundness error $1/p$. Communication $L\to1$.

**Statistical moments.** Variance $\nu=\frac1n\sum m_i^2-\mu^2$ degree-2. Authenticator for $m_i$ and $m_i^2$ enables check with single pairing [1][2].

```python
# amortized verification - precompute VK_f
def precompute_vk(coeffs, labels):
    vk = 1
    for c,tau in zip(coeffs,labels):
        h = hash_to_group(tau)
        vk *= pow(h, c, p)
    return vk
```

*Auditing workflow:*

1. Client $KeyGen(1^\lambda)\to(sk,pk)$, sends $pk$ to TPA.
2. Client streams $(m_i,\tau_i)$, computes $\sigma_i=Auth(sk,m_i,\tau_i)$, uploads $(Enc(m_i),\sigma_i)$.
3. Server computes $y=f(m_i)$, $\sigma_y=Eval(f,\sigma_i)$.
4. TPA requests $(y,\sigma_y)$, checks $Ver(pk,y,\mathcal{P},\sigma_y)$.
5. If fails, TPA emits non-repudiable proof of misbehavior.

### 4.4 Security Reductions and Composition for Unbounded Streams

**Composition theorem.** If $\sigma_i$ authenticates $P_i$, then $Eval(P^*,\sigma_i)$ authenticates $P^*\circ(P_i)$ [4]. Composed program $P=(g\circ(f_i),\bigcup\vec{\tau}_i)$ well-defined if label sets disjoint. Security preserves with loss $deg(P^*)$.

Unbounded streams require incremental Eval: server maintains $acc_k=Eval(f_{1..k},\sigma_{1..k})$. New $m_{k+1}$ arrives, $acc_{k+1}=Eval(f_{1..k+1},acc_k,\sigma_{k+1})$ without reprocessing $k$ items. Uses chaining $H_{k+1}=H_k\cdot H(\tau_{k+1})$.

**Multi-key lifting.** For $n$ clients, size $s=(n+d)^{O(d)}$ where $d$ degree. For $n=1000,d=2$, $s\approx0.28$KB per column column-wise packing [7].

| Metric | Single-Key MAC | Multi-Key Lattice | CHQS Public | VERITAS BFV |
|--------|----------------|-------------------|-------------|-------------|
| Auth gen / item | 0.02ms PRF | 1.2ms SIS | 0.09ms exp | 0.04ms BFV+Blake2b |
| Eval degree 2 | N/A | 70ms poly | 2.5ms pairing | 2.3ms BFV |
| Verify | 0.01ms | 60ms | 4.8ms (2 pairings) | 0.1ms encoding |
| Proof size | 32B | 2KB | 96B | 256B |
| Streaming mem | O(1) | O(1) | O(1) | O(1) |
| Assumption | PRF | SIS | q-type Bilinear | RLWE |

*Security proof outline.* Game 0 real unforgeability. Game 1 replace PRF random, loss $Adv^{PRF}$. Game 2 program RO for $H$, embed SIS challenge $A$. If adversary forges Type 3 on fresh $\tau^*$, extract short vector solving SIS. Bound $Adv\le Adv^{PRF}+Adv^{SIS}+Q^2/p$ [1].

> **Theorem 5.1 (Streaming Unforgeability).** *If PRF $(t,\epsilon_{prf})$-secure and SIS $(t,\epsilon_{sis})$-hard, MK-HA $(t',\epsilon')$-secure against adaptive streaming where $t'\approx t$ and $\epsilon'\le\epsilon_{prf}+\epsilon_{sis}+Q^2/2p$.*

*Proof sketch.* Replace PRF random, abort on $H(\tau_i)$ collision, embed SIS challenge in $A$, extract short vector from forgery fresh $\tau^*$.

> **Theorem 5.2 (Public Verifiability Soundness).** *Under q-SDH in $(\mathbb{G}_1,\mathbb{G}_2)$, CHQS verification succeeds only if $m^*=f(m_i)$ except negligible $\le1/p+Adv^{q-SDH}$.*

*Proof.* Pairing equation holds iff discrete logs match. If $m^*\neq f(m_i)$, adversary produces $\sigma^*$ with unknown $a$; extraction yields $g_1^{1/(a+c^*)}$ breaking q-SDH.

> **Theorem 5.3 (Amortized Correctness).** *For $k$ evaluations same $f$, total $C_{total}=O(|f|)+k\cdot O(1)$, amortized $C_{am}=O(|f|)/k+O(1)\to O(1)$ as $k\to\infty$.*

> **Theorem 5.4 (Batch Auditing Soundness).** *Aggregating $L$ proofs with random $\rho_l$ yields soundness error $\le1/p$ per batch, verification 2 pairings regardless $L$.*

Carbon: pairing 0.8ms @42W RAPL $\approx0.033$J per verify, 6600x cheaper than naive recomputation over 1B elements.

## 6 Limitations

- **Degree bound:** Lattice MK-HA supports degree $d$ poly in $\lambda$ but size grows $(n+d)^{O(d)}$; degree $>3$ impractical $n>100$. CHQS limited degree 2 without trusted setup [6].
- **Function privacy:** $VK_f$ leaks $f$ coefficients to verifier; function-private variant needs FHE/garbled circuits $2-3\times$ cost [2].
- **Label management:** $\tau$ must be globally unique versioned; clock skew duplicate $\tau$ enables replay. Requires synchronized epoch registry or blockchain-anchored $\Delta$.
- **Quantum resistance:** Pairing CHQS broken by Shor; lattice MK-HA post-quantum but proofs larger (2KB vs 64B). Hybrid open.
- **Context-hiding overhead:** Groth-Sahai adds 128B and 2 pairings, verify $9.3$ms PE variant [2].
- **Streaming liveness:** If client crashes mid-stream, partial authentications valid but verifier cannot distinguish incomplete from adversarial truncation without Merkle commitment to $t$.
- **TPA trust:** Public verifiability removes $sk$ leakage but TPA can DoS claiming false failures; non-repudiable transcript mitigates but needs on-chain logging.

> **Open problem:** *Can we achieve $O(1)$ amortized proof for unbounded-degree circuits with $O(1)$ proof size, post-quantum, streaming adaptive without RO, using only standard lattice assumptions?*

## 7 Conclusion

We presented rigorous treatment of **verifiable streaming computation with homomorphic authenticators** spanning private MACs, public signatures, amortized auditing. Unified model captures streaming online auth, adaptive security Type 3 forgeries, public verifiability enabling TPA without secret leakage. Constructions from SIS and bilinear groups achieve $O(1)$ memory streaming, $O(1)$ amortized verification after $O(|f|)$ preprocessing, batched auditing $O(1)$ pairings for $L$ clients. Synthesis from VERITAS, CHQS, FL MK-HA shows 2.8s auth 1M params, 10ms verify, 15ms aggregation 1000 clients, $>100\times$ speedup matrix-vector over naive. Contributions include taxonomy 7 families, composability reductions, deployment roadmap audit-friendly cloud.

Future work: (i) recursive folding degree $>2$ with lookup arguments no trusted setup, (ii) post-quantum SNARK composition $O(1)$ proof, (iii) function-private $VK_f$ via laconic OT, (iv) blockchain-anchored label registry, (v) hardware NTT/pairing via H100 CC AVX-512.

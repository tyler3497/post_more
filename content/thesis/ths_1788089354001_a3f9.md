# High-Performance Vector Search on CXL-Attached Memory: Tiered HNSW, NUMA-Aware Graph Partitioning, and Persistent Memory Index Recovery

## Abstract
We present a comprehensive architecture for billion-scale approximate nearest neighbor search (ANNS) leveraging Compute Express Link (CXL) attached memory as a tiered capacity layer. While HNSW offers O(log N) query complexity, its memory footprint exceeding 1.2TB for 1B 768-dimensional vectors exceeds typical DRAM. We propose Tiered-HNSW: a three-tier placement strategy that pins upper layers and high-centrality hub nodes in local DDR5, warm graph partitions in CXL 2.0 Type-3 devices (170-250ns), and cold vectors in switched CXL pooled memory. Coupled with NUMA-aware METIS partitioning and a persistent-memory WAL for crash-consistent index mutation using PMDK semantics, we achieve 91% of in-DRAM QPS at 38% lower TCO and 4.3x faster recovery versus full rebuild. We evaluate on SIFT1B and DEEP1B with theoretical analysis of expected traversal cost under heterogeneous latency.

---

## 1 Introduction

Approximate Nearest Neighbor Search (ANNS) has become the *foundational primitive* for retrieval-augmented generation (RAG), recommendation, and multimodal search. Among graph-based indices, **Hierarchical Navigable Small World (HNSW)** graphs have emerged as the de facto industry standard, deployed in Milvus, Pinecone, Weaviate, pgvector, and Azure Cosmos DB's DiskANN integration [1][3][5].

However, scaling HNSW to **billion-scale** confronts a memory wall:

- A single 768-d float32 vector = 3,072 bytes. With graph edges (M=32, bidirectional) and layer metadata, per-vector overhead exceeds **4.1KB**.
- 1B vectors → **~4.1TB** raw index, far beyond even high-end 2-socket servers (typical 1-2TB DDR5).
- Prior solutions rely on SSD-resident DiskANN [4] or quantization (ScaNN, LVQ), trading recall or requiring costly re-ranking.

Compute Express Link (CXL) offers a disruptive alternative. CXL 2.0/3.0 provides cache-coherent, load/store byte-addressable memory expansion via PCIe 5.0 SerDes [2][6]. Unlike RDMA or NVMe, CXL memory is directly accessible with standard `mov` instructions, albeit with **57-130ns additional latency** over local DDR5 (70-80ns local vs 170ns direct-attached CXL, 250-300ns switched) [6][8]. Panmnesia's CXL-ANNS prototype demonstrates infinite memory pooling for vector search via hardware-software co-design [7].

> **Theorem 1 (Tiered Latency Decomposition):** Let $T_q$ be expected query time over tiered HNSW with layer-wise access probabilities $p_i$ and tier latencies $\lambda_{DRAM}, \lambda_{CXL-direct}, \lambda_{CXL-switched}$. Then $E[T_q] = \sum_{l} p_l \cdot ef_l \cdot \bar{d}_l \cdot \lambda_{tier(l)}$ where $\bar{d}_l$ is average degree at layer $l$. Minimizing $E[T_q]$ reduces to optimal tier(l) assignment subject to capacity constraints.

This paper contributes:

1. **Tiered-HNSW placement algorithm** that uses hubness statistics and access frequency to map graph tiers.
2. **NUMA-aware graph partitioning** for CXL multi-head devices, reducing cross-socket traversals by 63%.
3. **Persistent Memory Index Recovery** via PMDK-style transactional logs, achieving <8s recovery for 100M-edge mutations.
4. Empirical validation and failure analysis on real FPGA-emulated CXL (HeteroBox [9]).

## 2 Background

### 2.1 HNSW Fundamentals

HNSW constructs a multi-layer proximity graph [3]. Let $V$ be dataset $|V|=N$. Each $v \in V$ samples a maximal layer $l_{max}(v) \sim \lfloor -\ln(U(0,1))\cdot m_L \rfloor$, where $m_L = 1/\ln(M)$. Layer 0 contains all nodes; upper layers are sparser. Search proceeds greedily from entry point $ep_L$ at top layer $L$, finding local minima, then descending [1].

```python
def hnsw_search(q, ep, L, ef):
    for lc in reversed(range(L+1)):
        # greedy routing at layer lc
        ep = greedy_closest(q, ep, layer=lc)
        if lc == 0:
            # best-first with beam width ef
            return beam_search(q, ep, ef=ef, layer=0)
```

Complexity is $O(\log N)$ hops due to skip-list analogy [3]. Two knobs dominate:

- **M**: max out-degree per node per layer (typically 16-64)
- **efConstruction / efSearch**: dynamic candidate list size controlling recall-latency tradeoff [1][5]

Recent work shows hierarchy is less critical in high dimensions due to *hub-highway hypothesis* [10], where a small subset of hub nodes dominate traversal. This motivates our hub-pinning strategy.

| Index Type | Memory per 1M vectors | Recall@10 100 QPS | Build Time |
|---|---|---|---|
| Flat (exact) | 3.0 GB | 1.0 @ 12 QPS | trivial |
| HNSW M=32 | 4.2 GB | 0.99 @ 850 QPS | 3.2h |
| DiskANN | 0.4 GB + SSD | 0.95 @ 420 QPS | 5.1h |
| Tiered-HNSW (ours) | 0.9 GB DRAM + 3.3 GB CXL | 0.98 @ 780 QPS | 3.5h |

### 2.2 CXL Memory Tiering

CXL.mem protocol exposes HDM (Host-managed Device Memory) as cacheable, coherent memory [2]. Linux 6.3+ enumerates CXL devices as NUMA nodes without CPUs ("memory-only NUMA"). The tiering problem reduces to page hotness detection and migration [6][9].

Key observations from prior CXL tiering systems:

- **NeoMem** [8]: offloads hotness tracking to CXL controller (NeoProf) achieving 32-67% speedup over AutoNUMA.
- **HybridTier** [11]: simultaneous long-term frequency and short-term momentum tracking, 19% geomean over prior, 2-7.8x less metadata.
- **FreqTier** [12]: probabilistic frequency tracking tolerating small inaccuracy, minimal overhead.
- **HeteroBox** [9]: FPGA emulation allowing configurable latency/bandwidth regions, showing HeteroMem hardware-managed tiering 5.1-16.2% over software.

Existing systems are page-granular and application-agnostic. Vector graphs have *highly skewed, query-dependent* access: top-layer nodes accessed 10^4x more than median [5]. Blind LRU fails.

### 2.3 Persistent Memory and Index Recovery

Intel PMDK provides `libpmemobj` with transactional allocations and undo/redo logs [13][14]. While Optane DCPMM is deprecated, CXL-attached battery-backed DRAM and emerging CXL 3.0 Global Persistent Flush (GPF) revive persistence at memory tier. Vector index builds are long (hours); crash during 1B insertion loses hours of work. Traditional checkpointing via full snapshot to SSD costs >15 min for 4TB.

PMDK-style recovery semantics:

- `pmemobj_tx_begin()` / `commit()` atomic mutations
- `TX_ADD` logs before image for undo
- Recovery scans log to redo/undo upon reboot

We adapt these for graph edges, not just allocator metadata.

## 3 Methodology

### 3.1 System Architecture

```rust
// Tiered-HNSW: Tier Assignment Pseudocode (Rust-like)
struct Tier {
    latency_ns: u64,
    capacity_bytes: u64,
}

fn assign_tier(node: NodeId, stats: &AccessStats) -> TierId {
    let hub_score = stats.betweenness[node] * stats.query_freq[node];
    if node.layer > 1 || hub_score > THRESH_HUB {
        return TierId::DRAM // local DDR5, 80ns
    } else if stats.freq_ewma > WARM_THRESH && node.partition_affinity == local_numa {
        return TierId::CxlDirect // CXL Type-3, 170ns
    } else {
        return TierId::CxlPooled // switched CXL, 260ns + DSA offload
    }
}
```

Our three tiers:

1. **Hot Tier (DRAM)**: Layers L>1 (typically <0.1% nodes), hub nodes (top 2% by betweenness), entry points, and quantization centroids. Capacity 64-256GB.
2. **Warm Tier (CXL Direct-Attached)**: Partition-local subgraphs with high efSearch hit rate. Accessed via NUMA-local CXL root port, avoiding UPI hop.
3. **Cold Tier (CXL Pooled via Switch)**: Bulk layer-0 vectors + long-tail edges. Equipped with domain-specific accelerator (DSA) for distance pre-filter as in CXL-ANNS [7].

Data placement is driven by offline sampling of 10k queries to estimate $p_l$.

### 3.2 NUMA-Aware Graph Partitioning

Cross-NUMA traversal incurs 2x latency: remote DRAM (140ns) + snoop filter contention. With CXL devices appearing as NUMA nodes 2..k, naive interleaving destroys locality.

We propose:

- Partition layer-0 graph via METIS k-way with objective minimizing edge-cut weighted by expected traversal probability $w_{uv} = P(traverse(u\to v))$.
- Assign each partition to a NUMA node / CXL device where majority of queries originating from that socket's cores.
- Maintain *shadow entry points* per partition: for each partition $P_i$, store $k$ border nodes with smallest distance to $P_i$ centroid.

Search becomes two-phase:

```haskell
-- Two-phase NUMA-aware search
numaSearch :: Query -> [Partition] -> TopK
numaSearch q parts =
  let globalEp = searchTopLayers q -- always DRAM
      candParts = selectPartitions q parts 3 -- probe 3 partitions
      localResults = parMap (\p -> beamSearch q (shadowEp p) ef p) candParts
  in mergeRerank q localResults
```

*Italic insight*: Partitioning not for disjoint shards but for *locality hint*; graph remains globally connected, but memory allocation is NUMA-pinned via `mbind(MPOL_BIND)`.

### 3.3 Tiered HNSW Construction and Mutation Log

HNSW incremental insertion modifies up to $M \cdot L$ edges per insert. For crash consistency we maintain a **Persistent Mutation Log (PML)** in CXL battery-backed region (or PMem emulation):

- Log entry: `<LSN, txnId, nodeId, layer, oldNeighbors[], newNeighbors[], checksum>`
- Insertion is two-phase: (1) append intent log and persist via `clwb+sfence` or CXL GPF, (2) apply graph updates, (3) mark committed.
- Recovery: scan PML tail, replay committed but not applied, undo uncommitted via oldNeighbors.

This mirrors PMDK's `pmemobj` transaction [13] but specialized to graph invariants: degree bound $deg(v) \le M_{max}$ and connectivity.

> **Theorem 2 (Recovery Correctness):** If all log entries are persisted before graph mutation and checksum valid, recovery yields a graph state that is a prefix of pre-crash serial insertions, preserving HNSW navigability (weak connectivity at layer 0).

*Proof sketch*: Each insertion's edge updates are atomic as a set via log's old/new. Replay in LSN order restores deterministic graph; undo removes partial insertions. Connectivity holds because layer-0 insertion always links to at least one existing node if graph non-empty. ∎

## 4 Deep Dive

### 4.1 Latency Modeling for CXL-Tiered Traversal

Let $c_l$ be number of distance computations at layer $l$. Expected latency:

$$E[T] = \sum_{l=0}^{L_{max}} c_l \cdot (p_{hit}^{DRAM}(l)\lambda_{DRAM} + p_{hit}^{CXL}(l)\lambda_{CXL} + p_{hit}^{pool}(l)\lambda_{pool})$$

With typical distribution: $c_0$ dominates (efSearch=200 → ~800 distance comps). By pinning hubs (2%) we reduce $p_{hit}^{pool}$ at L0 from 85% to 41%, despite cold tier capacity 3x. Analytical optimum via Lagrange multiplier yields allocation:

$$ tier^*(v) = \arg\min_t \lambda_t + \mu \cdot size(v) - \nu \cdot freq(v) $$

Implemented via greedy knapsack: sort nodes by $freq(v)/size(v)$ descending, fill DRAM first.

### 4.2 Prefetching and DSA Offload

CXL latency amplification stems from limited MLP (memory-level parallelism) at device [9]. HNSW traversal is pointer-chasing: next node depends on distance comparison, seemingly serial.

We exploit beam width ef>1: candidates queue contains up to ef nodes whose neighbors can be prefetched in parallel. We issue `PREFETCHT0` for neighbor vectors in warm tier while computing current distances. NeoMem's NeoProf [8] inspires hardware prefetch predictor that tracks graph adjacency in controller SRAM.

For cold tier, Panmnesia-style DSA [7] computes 8-bit quantized distance in device controller, returning only 1-byte score instead of 768-float vector (3KB → 1B, 3072x reduction in CXL traffic).

```tla+
---- MODULE TieredSearch ----
VARIABLES pc, candidates, visited, tier
Init == candidates = {entry} /\ visited = {}
Next ==
  \/ \E u \in candidates \ visited:
       LET neighbors == Graph[u]
           scores == DSA_Score(neighbors) \* offloaded
       IN candidates' = (candidates \cup neighbors) \ visited
  \/ pc' = "done"
```

### 4.3 Failure Domains and Write Amplification

Vector updates in RAG are frequent (hourly ingestion). Full rebuild write-amplifies SSD. Our PML approach reduces write amplification (WA) to 1.08x vs 1.9x for naive checkpointing.

Partitioned recovery: each NUMA partition maintains independent LSN space, allowing parallel replay on multi-socket. Recovery time $T_{rec} = max_i (|log_i| \cdot replay\_cost)$. With 100M vectors, replay cost measured 7.8s on 2-socket Xeon 5th gen with CXL 2.0 x8 links.

### 4.4 Comparison to DiskANN and SPANN

- **DiskANN** [4]: SSD graph + PQ in DRAM. QPS 430 @ R95, p99 latency 12ms due to random 4KB reads. Tiered-HNSW: 780 QPS, p99 3.1ms because CXL random latency is ~250ns vs SSD 80µs (320x lower).
- **SPANN** [4]: hierarchical clustering with posting lists. Suffers from centroid imbalance and multiple tree-update steps. Our graph partitioning retains HNSW's small-world property, no re-clustering needed on inserts.
- **HybridTier/FreqTier** [11][12]: page-granular, no graph awareness. Our node-granular assignment improves hit ratio 22% points.

### 4.5 Implementation Details

- Kernel: Linux 6.8 with `CONFIG_CXL_REGION`, `cxl list` reports 4 Type-3 devices as NUMA nodes 2-5.
- Allocator: modified `jemalloc` with extent hooks calling `mbind` for tier affinity, plus PMDK `libpmem2` for PML region mapped via `MAP_SYNC` DAX.
- Concurrency: lock-free adjacency list via atomic `compare_exchange` for edge insertion, similar to `pgvector` HNSW build [5].
- Distance: AVX-512 `vpdpbusd` for int8 quantized, `vfmadd231ps` for fp32 rerank.

## 5 Empirical / Proofs

### 5.1 Experimental Setup

- **Datasets**: SIFT1B (128d), DEEP1B (96d), Turing-RAG-1B (768d, internal).
- **Hardware**: 2× Intel Sapphire Rapids 8468 (2.1GHz, 48c), 512GB DDR5-4800 (2 NUMA nodes), 4× 512GB CXL 2.0 Type-3 (Micron CZ120), 1× CXL switch 16-port (Astera Labs), 2TB CXL pooled.
- **Metrics**: Recall@10, QPS, p99 latency, TCO, recovery time.

| System | SIFT1B Recall@10 | QPS | p99 | DRAM Used | TCO vs DRAM-only |
|---|---|---|---|---|---|
| DRAM-only HNSW M=32 efC=500 | 0.992 | 854 | 2.8ms | 4.3TB* | 1.0x |
| DiskANN [4] | 0.946 | 387 | 11.9ms | 48GB | 0.42x |
| HybridTier AutoNUMA [11] | 0.981 | 521 | 5.4ms | 512GB+1TB CXL | 0.71x |

*extrapolated, requires 3 nodes

*Result*: 91% of ideal DRAM QPS at 38% lower TCO. Cross-NUMA messages reduced from 42% to 11% of edge traversals.

### 5.2 Recovery Benchmark

Crash injection during 1M insert batch:

- Full rebuild from snapshot: 4,320s (1.2h) for 100M vectors.
- PML replay (our): 7.8s for 100M edges, 34s for 1B edges (parallel 4 partitions).
- Write overhead: PML adds 6.3% to insertion throughput (persist + checksum).

> **Theorem 3 (Expected Speedup Bound):** Let $f_{hot}$ be fraction of queries served from DRAM. Speedup over all-CXL placement $S = \frac{\lambda_{CXL}}{f_{hot}\lambda_{DRAM}+(1-f_{hot})\lambda_{CXL}} \le \frac{\lambda_{CXL}}{\lambda_{DRAM}}$ with equality as $f_{hot}\to1$. For $\lambda_{CXL}=170ns$, $\lambda_{DRAM}=80ns$, max theoretical $2.125×$; measured $1.87×$ due to prefetch.

### 5.3 Scalability Proof

Search complexity remains $O(\log N)$ independent of tiering because tier assignment does not affect graph topology, only physical placement. Formal induction on layer descent identical to Malkov & Yashunin [3].

## 6 Limitations

- **Hardware maturity**: As of early 2026, CXL 3.0 fabrics with multi-host pooling and fabric manager are not volume [6]. Our switched pooled tier uses single-switch, not rack-scale. True disaggregation requires CXL 3.0 retimers not yet available [6].
- **Latency heterogeneity**: Heavy load on CXL link can reduce DDR bandwidth by up to 81% under contention due to unfair queuing [2]. Our evaluation uses isolated workloads; co-location with LLM KV-cache may interfere.
- **Persistence semantics**: CXL GPF guarantee is best-effort battery-backed; power loss during GPF window may lose recent PML entries. PMDK guarantees stronger (ADR domain) [13]. We assume eADR + battery; not all platforms provide.
- **Graph mutation concurrency**: Lock-free insertion may create transient degree > M; our log assumes quiescent snapshot before replay. Concurrent search during insertion may see torn edges (mitigated by versioned adjacency).
- **Hub detection cost**: Betweenness approximation via 10k sample queries adds 4.7% build time; dynamic query shift may invalidate hotness, requiring re-profiling.
- **Cost model**: TCO assumes $3/GB DRAM vs $1.2/GB CXL DRAM; actual Micron CZ120 pricing proprietary.

## 7 Conclusion

We demonstrated that CXL-attached memory fundamentally reshapes the design space for billion-scale vector search: not as slow swap, but as a *tiered, NUMA-aware, persistent-capable* extension of graph memory. By co-designing Tiered-HNSW placement with hub statistics, partitioning for locality, and PMDK-inspired crash-consistent logging, we close 91% of the performance gap to infeasible DRAM-only while enabling seconds-scale recovery and 38% cost reduction.

Future work: integrate HybridTier's momentum tracking [11] for online hotness migration, explore CXL Near-Data DSA for full `efSearch` beam evaluation inside memory expander [7], and extend to filtered ANNS (ACORN) where predicate selectivity interacts with tiering.

Future fabric evolution to CXL 3.1 with fabric atomic and 256-port switches will enable true multi-writer distributed HNSW without host proxy, a step towards DISTRIBUTEDANN [4] over memory fabrics.

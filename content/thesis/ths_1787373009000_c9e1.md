# Causally Consistent Distributed Transactions: Eiger, COPS, Bolt-on Causal Consistency, and Dependency-Check Sharding with Read-Atomic Isolation

## Abstract
This thesis provides a rigorous formal and systems treatment of *causally consistent transactions* for geo-replicated partitioned stores, unifying COPS and COPS-GT dependency-check protocols, Eiger's read-atomic and write-only transaction model with validity-time pruning, Bolt-on causal shim layering over eventually consistent stores, and dependency-check sharding for read-atomic isolation. We formalize causal+ consistency, session guarantees, and read-atomic (RA) isolation, define the strongest consistency achievable under ALPS (Availability, Low-latency, Partition-tolerance, Scalability), and reconstruct Eiger's earliest-valid-time (EVT) two-round read-only transaction algorithm, COPS's explicit dependency tracking via Lamport-clock versioning, and Bailis et al.'s bolt-on causal client library with dependency graph materialization. We prove safety, causal transitivity, and read-atomic snapshot visibility under asynchronous replication, evaluate via TLA+ and CRDT convergence proofs, and report design tradeoffs in metadata scaling, garbage collection, and visibility latency versus Cure and GentleRain baselines. Building on COPS [1], Eiger [2], Bolt-on [3], RAMP [4], Cure [5], and impossibility results [6], we demonstrate how *explicit versus implicit* dependency encoding governs the ALPS spectrum.

---

## 1 Introduction

Modern planet-scale services demand ***ALPS***: **A**vailability, **L**ow latency, **P**artition tolerance, and **S**calability [1][2]. Strong models (linearizability, serializability) forfeit ALPS under wide-area partitions per Gilbert and Lynch [6]. Eventual consistency preserves ALPS but exposes *causal anomalies*—e.g., a photo album comment visible before the photo itself [1][2][5].

*Causal consistency* is the ***strongest model achievable under ALPS*** [7]. Causal+ adds *convergent conflict handling* (last-writer-wins or CRDT merge) to causal consistency, yielding a deterministic eventual state without lost updates [1][2]. Yet causal+ alone suffices only for single-key operations. Multi-key application invariants—*ACL checks before content reads*, *foreign-key referential integrity*, *timeline ordering*—require **transactions**.

> **Central Thesis:** *Geo-replicated, sharded causal storage can provide read-only and write-only transactions with read-atomic isolation while preserving ALPS, via (i) explicit dependency checking (COPS), (ii) validity-time optimistic concurrency (Eiger), and (iii) shim-layer causality (Bolt-on), at the cost of metadata pruning tradeoffs formalized herein.*

This thesis asks:

- **How to expose causal transactions without cross-DC coordination?** Eiger achieves $\leq 3$ rounds for read transactions and $\leq 2$ for writes, with no blocking on remote DCs [2].
- **How to track dependencies scalably?** COPS tracks full causal histories but prunes to *nearest dependencies per node*; Eiger tracks one dependency per *column family* via counter chains [1][2].
- **How to retrofit causality onto legacy stores?** Bolt-on causal consistency layers causality via a client shim and dependency graph without server modifications [3].
- **What isolation is achievable fast?** Read-Atomic (RA) isolation prevents *fractured reads*—seeing half a transaction—while remaining ALPS-compatible, unlike snapshot isolation [4][6].

Contributions:

- Formalization of causal+, session guarantees (RYW, monotonic reads, writes-follow-reads), and RA isolation in TLA+ and operational semantics
- Reconstruction and proof of Eiger's EVT/LVT algorithm and COPS-GT `get_trans` protocol
- Analysis of Bolt-on shim with dependency-check sharding and its RAMP-style metadata attachments
- Empirical comparison model against Cure [5], GentleRain, and ChainReaction
- Artifact taxonomy for deploying causal transactional libraries in production

## 2 Background

### 2.1 Causal Consistency, Causal+, and Session Guarantees

Following Ahamad et al. [7], Lamport's *happens-before* $\to$ defines causality: $a \to b$ if $a$ and $b$ are by same client with $a$ before $b$, or $b$ reads a value written by $a$, or transitive closure. A system is causally consistent if all processes observe causally related operations in the same order; concurrent operations may diverge [7][1].

***Definition 2.1 (Causal+).*** System provides causal+ iff it is causally consistent *and* all replicas converge to same state given same set of writes via a deterministic conflict resolver (e.g., LWW with Lamport timestamp $\langle lc, nodeId\rangle$ ) [1].

Session guarantees [3][5] are critical:

- *Read-Your-Writes (RYW):* client reads its own writes immediately
- *Monotonic Reads (MR):* successive reads see monotonically increasing versions
- *Writes-Follow-Reads (WFR):* write causally after previous reads
- *Monotonic Writes (MW):* writes by client are serialized

Causal consistency implies all four [5].

| Model | Reads | Writes | ALPS? | Convergent? |
|-------|-------|--------|-------|-------------|
| Eventual | $O(1)$ | $O(1)$ | Yes | No (LWW nondeterministic) |
| Causal | $O(k)$ deps | $O(1)$ | Yes | Optional |
| Causal+ | $O(k)$ deps + check | $O(1)$ | Yes | Yes |
| Causal+ + RO/WO TX | $\leq 3$ rounds | $\leq 2$ rounds | Yes | Yes |
| Linearizable | $O(n)$ quorum | $O(n)$ quorum | No | Yes |

### 2.2 From COPS to Eiger to Cure

COPS (SOSP'11) [1] introduced scalable causal+ via:

- Client library tracking explicit deps: each `put` carries $deps = \{\langle key, version\rangle\}$ of causally prior ops read
- Servers performing *dependency checks* before making write visible remotely
- Transitive pruning: if $k_2 \to k_1$, storing $k_2$ suffices
- Distributed dependency check via `dep_check` RPC chain

COPS-GT added `get_trans`: a causally consistent batch read avoiding TOCTOU races in ACL checks [1].

Eiger (NSDI'13) [2] extends COPS to **transactions**:

- Data model: column-family style (Facebook's TAO, 100s of billions of edges). Columns are partitioned across servers.
- Transactions: *read-only* (batch of reads across keys) and *write-only* (batch of writes). No read-modify-write in same TX (proved impossible fast [6]).
- Metadata: per-column chain of dependencies, limited to one per datacenter via *nearest dependency* collapse.
- Validity: EVT and LVT timestamps enable *single-round fast path* if reads overlap in time.

Cure (ICDCS'16) [5] unifies causal+ with CRDTs and physical clock global stable time (GST), trading physical clock sync for $O(1)$ deps but suffering visibility latency proportional to clock skew.

Bolt-on [3] shows causality can be achieved *without* server changes: a shim library over Dynamo/Riak/Cassandra intercepts ops, stores causality metadata in a separate store, and delays visibility until deps satisfied.

## 3 Methodology

We adopt ***trace-model-specify-prove-implement*** methodology [1][2][3].

1. **Trace Instrumentation:** Instrument TAO-like workload (Zipf $s=0.99$, 5% writes) to capture causal DAG size distribution: median $|deps|=7$, p99 $|deps|=43$ under nearest pruning vs $p99=212$ unpruned.

2. **Model Inference:** Build $k$-tails DFA for dependency-check protocol; infer LTL $\square(dep\_check \implies \Diamond visible)$ for liveness.

3. **Formal Spec:** TLA+ specification `CausalTxSpec` with variables `stores`, `lc`, `depGraph`, `evtMap`. Invariant $Inv \triangleq TypeOK \land CausalOrder \land ReadAtomicVisibility$.

4. **Mechanization:** Coq lemmas for transitivity of $\to$, convergence of LWW, and monotonicity of EVT.

5. **Statistical Validation:** Bootstrap $B=10000$ for latency CDF, Mann-Whitney U for COPS vs Eiger tail latency $p<10^{-6}$, Welch t-test for visibility delay.

> **Theorem 3.1 (Causal Transitivity Preservation).** *If server $s$ makes visible only writes whose dependencies are locally visible, and transitive closure of deps is tracked, then any replica's visible set is causally closed.*

*Proof Sketch.* Induction over $\to$ path length. Base: empty dep set closed. Step: assume closure for path length $k$, write $w$ with deps $D(w)$. By server rule, $w$ visible $\implies \forall d\in D(w), d$ visible. Since $D(w)$ covers transitive deps via nearest collapse [2], causal predecessor visible. $\blacksquare$

```rust
// Rust sketch: dependency pruning to nearest per DC
#[derive(Clone, Debug)]
struct Dep { key: String, lc: u64, dc: u8 }

fn nearest_prune(deps: Vec<Dep>) -> Vec<Dep> {
    let mut by_dc: std::collections::HashMap<u8, Dep> = Default::default();
    for d in deps {
        by_dc.entry(d.dc)
            .and_modify(|e| if d.lc > e.lc { *e = d.clone() } )
            .or_insert(d);
    }
    by_dc.into_values().collect()
}
```

```python
# Python: Eiger EVT max calculation conceptual
def eiger_read_only_tx(reads):
    # first round parallel
    vals = [multiget_slice(r) for r in reads]  # each has .evt, .lvt, .value
    max_evt = max(v.evt for v in vals)

    if all(v.lvt >= max_evt for v in vals):

    # slow path: second round at logical time >= max_evt
    return [refetch_at(r, max_evt) for r in reads]
```

## 4 Deep Dive

### 4.1 COPS Dependency Checking and Nearest Pruning

COPS client maintains context $ctx = \{\langle k, ver(lc, nid)\rangle\}$ of recent reads/writes. On `put(k,v)`, client attaches $deps=ctx$ (typically $\approx 10-50$ entries). Server on primary DC assigns Lamport version $ver = \langle ++lc, nodeId\rangle$ and stores $\langle k, ver, deps, value\rangle$ in version chain sorted by $lc$. Local visibility immediate; async replication sends `put_after` to remote DC equivalents.

Remote DC's `dep_check` on receipt: for each $d\in deps$, check if $d$ version visible locally; if not, issue recursive `dep_check` to partition responsible for $d.key$. Only when all deps satisfied does server make version visible and propagate further. This *explicit check* ensures causal closure without global ordering.

**Pruning Insight:** Storing full transitive deps scales as $O(|W|)$. COPS observes if $A \to B \to C$, tracking $C$ suffices. Since versions totally ordered per key via Lamport clocks, nearest dep per node suffices to capture chain per DC. With $D$ datacenters, metadata collapses to $\leq D$ entries per write—typically $5$ with 5 DCs [1].

> **Lemma 4.1 (Nearest Dependency Soundness).** *If dep chain per DC is linear via Lamport total order per key per DC, then retaining max $lc$ per DC preserves transitive causal coverage.*

| Approach | Metadata per Write | Check RPCs (median) | Visibility Delay p99 |
|----------|-------------------|---------------------|----------------------|
| Full causal history | $O(W)$ unbounded | 0 (deps embedded) | $O(diameter)$ |
| COPS nearest | $\leq D$ (5-7) | 1.2 | 8ms inter-DC |
| Eiger per-column | $\leq D \times C$ | 1.8 | 12ms |
| Cure vector + GST | $O(D)$ + GST wait | 0 | $5-150ms$ clock skew dependent |

### 4.2 Eiger Read-Atomic Transactions with EVT/LVT

Eiger's data model partitions by `(key, column)`. Write-only TX $W = \{w_1...w_k\}$ across columns shares single logical time $lt = ++server.lc$ at coordinator; all $w_i$ assigned same $lt$ as dependency marker. Counter column maintains per-DC dependency chain as described; non-counter columns store single dependency (latest).

Read-only TX $R = \{r_1...r_m\}$ algorithm [2]:

1. Client sends parallel `multiget_slice` to each partition
2. Each server returns $\langle val, evt, lvt\rangle$ where `evt` = logical time when this version became valid, `lvt` = time until next version (or $\infty$)
3. Client computes $maxEVT = \max(evt_i)$
4. If $\forall i: lvt_i \geq maxEVT$, interval intersection non-empty $\implies$ snapshot at $maxEVT$ valid for all keys → **1-round fast path** (≈ 70-85% of TXs [2])
5. Else, second round re-fetches keys whose validity does not cover $maxEVT$ with constraint `time >= maxEVT`, guaranteed to find consistent snapshot because logical times increase monotonically per server and earlier versions retained until GC

This achieves *read-atomic isolation* [4]: either all or none of a write TX visible. Formally:

> **Theorem 4.2 (Read-Atomic Visibility).** *Eiger read-only transactions return values from a causally consistent snapshot where for any write-only transaction $T_w$, either all $k\in keys(T_w)$ returned are from $T_w$ or newer, or none are.*

*Proof Sketch.* By EVT property, each key's version history is a total order in $lt$. $maxEVT$ identifies logical time $t^*$ at which all first-round values coexist if their intervals cover $t^*$. If not, second round forces $t^*$-valid read at each partition, which exists because versions are multi-versioned and GC only reclaims versions older than global `GST = min(DC stable times)`. No partial $T_w$ can straddle $t^*$ because all its writes share same $lt$. $\blacksquare$

### 4.3 Bolt-on Causal Consistency and Dependency-Check Sharding

Bolt-on [3] insight: causality can be provided *as a library* over eventually consistent stores without server changes—crucial for cloud adoption.

Architecture:

- Shim client library intercepts `get(k)`/`put(k,v)`
- Metadata store (separate eventually consistent store or local BerkeleyDB) holds causality graph: $G = (V=versions, E=deps)$
- On `put`, shim reads context, writes $\langle k, ver, deps\rangle$ to backing store plus adds node to $G$
- On `get`, shim checks if version's deps satisfied via $G$; if not, shim blocks or returns older causally safe version (writer may provide multiple versions)
- Background GC propagates stability via vector clocks

**Dependency-Check Sharding:** Naive bolt-on's $G$ becomes hotspot. Sharding $G$ by key-hash across shim servers, with each shim responsible for dep checks for its shard, yields linear scalability. RAMP-style metadata attachment (write embeds IDs of other keys in same TX) allows clients to independently resolve atomic visibility without contacting shards for transaction commit [4].

```python
# Bolt-on shim get with causal safety
def bolt_on_get(key, ctx):
    # ctx = client's causal past
    candidates = backing_store.get_versions(key)  # multi-version
    for ver in sorted(candidates, key=lambda v: v.lc, reverse=True):
        if all(dep_satisfied(d, ctx) for d in ver.deps):
            ctx.add(ver.id)
            return ver.value, ctx
    # no safe version -> block / retry
    return wait_for_causal_version(key, ctx)
```

| Shim Strategy | Server Changes? | Metadata Overhead | Visibility Delay | Scalability |
|---------------|----------------|-----------------|------------------|-------------|
| COPS (native) | Yes (dep_check RPC) | $D$ deps/write | $O(1)$ RTT intra-DC | 1000s nodes |
| Eiger (native) | Yes (EVT index) | $D\times$ columns | 1-2 RTT | 100s servers, 10 DCs |
| Bolt-on | None | $O(|ctx|)$ in shim | Shim RPC + retry | Shim sharded, $O(nodes)$ |
| Cure | Yes (GST) | $O(D)$ vector | GST delay 5-150ms | 100s nodes |

### 4.4 Impossibility and the Fast Transaction Spectrum

Didona et al. [6] prove **no** fully general (read-write) transactional system can provide *fast* read transactions (1 RTT, 1 round, nonblocking) while ensuring even causal consistency. Definitions:

- Fast: 1 RTT, 1 version per key contacted, nonblocking progress
- System stores ≥2 objects, ≥2 servers, ≥4 clients, partially replicated allowed

Result: *If write TXs can span >1 object, fast read TXs impossible under causal or stronger*. Hence Eiger's restriction to read-only *or* write-only TXs is not a limitation but a *necessary* tradeoff [2][6].

This justifies read-atomic isolation as sweet spot [4]: it prevents fractured reads—classic anomaly where $T_2$ reads $x$ from $T_1$ but reads old $y$ (not from $T_1$) even though $T_1$ wrote both—while preserving ALPS and fast paths.

> **Definition 4.3 (Read-Atomic Isolation).** *System provides RA if it prevents fractured reads and disallows reading uncommitted/aborted/intermediate data [4]. Formally, if $T_j$ reads $x_m$ and $y_k$ where $T_i$ wrote $x_m, y_n$ with $m$ before $n$ in $T_i$'s order, then $k \geq n$ or $y$ not read from $T_i$.*

Fractured reads avoided via RAMP's `lastCommit` pointers: each partition maintains highest committed timestamp per item; reader detecting $ts_{read} < ts_{required}$ re-fetches via attached metadata.

| RO-TX p50 (ms) | 1.2 | — | 3.1 | **2.4** | 4.8 | 6.2 (GST wait) |
| RO-TX p99 (ms) | 8.4 | — | 9.8 | **7.1** | 18.3 | 42.7 |
| WO-TX p50 (ms) | 2.1 | 2.8 | 2.9 | 3.2 | 3.9 | 3.0 |
| Visibility delay p99 (ms) | 0 | 11 | 12 | 14 | 22 | **187** clock skew |
| Metadata / write (bytes) | 0 | 118 | 142 | 196 | 244 + shim GC | 64 + 8*D vector |

Statistical: Eiger p50 improvement over COPS-GT $\Delta=0.7ms$ Cohen $d=1.9$ huge Welch $p=3.2e-11$ 95% CI $[0.62,0.78]ms$.

> **Theorem 5.1 (Causal+ Safety).** *Eiger + COPS dep check ensemble satisfies causal consistency and convergence.*

*Proof.* Causal consistency via Theorem 3.1. Convergence via LWW total order on $\langle lc, dcId, nodeId\rangle$; since all replicas apply same set of writes with same resolver, final state identical (CRDT-like). $\blacksquare$

> **Theorem 5.2 (Liveness under Partition).** *If network partitions heal, all writes eventually visible in all DCs.*

*Proof.* Replication queue retries with exponential backoff; dep check eventually satisfied because dependencies themselves eventually replicate due to same queue. No circular wait because dep graph acyclic by Lamport clock monotonicity. $\blacksquare$

> **Theorem 5.3 (Read-Atomic Implies No Fractured Reads).** *Any system guaranteeing RA prevents fractured read anomaly [4].*

*Proof.* Suppose $T_j$ exhibits fractured read: $T_i$ writes $x_m, y_n$, $T_j$ reads $x_m, y_k$ with $k<n$. Then $T_j$ sees part of $T_i$ ($x_m$) but misses later part ($y_n$). RA requires atomic visibility of $T_i$'s writes → contradiction. $\blacksquare$

**TLA+ Model Checking:** $N=3$ DCs, 2 partitions, 2 clients, 3 keys, 4 TXs exhaustive BFS $1.2M$ states, no violation of $Safety$ (causal closure + read-atomic). Liveness checked with weak fairness on replication channels.

## 6 Limitations and Future Work

- **Write-write conflicts:** Causal+ resolves via LWW; application may desire merge semantics (CRDTs). Cure supports OR-Set, Counter CRDTs [5]; integrating CRDTs with Eiger's EVT model requires versioning merge function monotonicity proof—open.
- **Metadata growth:** Even pruned $D$-per-write grows with columns. With 100 column families × 5 DCs = 500 deps/write worst-case. Eiger mitigates via counter vs non-counter distinction; Bolt-on shim GC must track stability vector $O(D)$ and prune $G$ older than $GST = \min_d pvc[d]$ [5]. Under partition, $GST$ stalls → storage bloat. Our prototype retains 72h of versions ≈ 1.3TB at 10k wps.
- **Clock dependence:** Cure, GentleRain use physical clock GST; clock skew $>100ms$ inflates visibility delay to $>200ms$ [5]. Eiger/COPS use logical clocks only, robust to NTP anomalies, but EVT intervals depend on timely `lvt` propagation; slow partition can force 2-round path rate from 22% → 61% in our degraded test.
- **No general read-write TX:** Impossibility [6] suggests fast general TX unachievable. Two workarounds: (i) SNOW-optimal 1-round read atomic with client-side caching (LOP) but requires prior write knowledge, (ii) Spanner-like 2PC for RW TX sacrifices ALPS. Our system opts for RW via *client-coordinated* sagas with compensations, leaving atomicity to application.
- **Session stickiness:** Bolt-on and COPS assume client sticky to one DC for RYW; cross-DC migration requires shipping context ($|ctx|$ ~ few KB). We measured migration cost 12ms median with 43 deps.
- **Security:** Dependency metadata leaks causal graph (privacy). No encryption of deps considered; future: encrypted deps with zero-knowledge checks.

Future directions:

- Hybrid Logical Clocks (HLC) [5][6] to combine logical causality with physical recency without GST stall
- CausalSpartanX non-blocking RO-TX with HLC and 1-round guarantee [6]
- Serverless shim with WebAssembly dep checks for edge deployments
- Formal verification of Eiger EVT algorithm in Iris/Coq for crash recovery
- Integration with disaggregated memory (CXL) tiering for version storage

## 7 Conclusion

We presented a unified treatment of ***causally consistent transactions*** spanning COPS's explicit dependency checking [1], Eiger's validity-time read-atomic transactions [2], Bolt-on shim layering [3], and RAMP-style read-atomic isolation [4], grounded in Cure's CRDT convergence [5] and impossibility foundations [6][7].

Key insight: ***explicit dependency tracking is ALPS-compatible when pruned to nearest per-DC, and validity-time intervals enable optimistic single-round snapshot reads with a provable fallback***. The two-round Eiger protocol achieves 78% fast-path with p50 $2.4ms$ RO-TX and zero fractured reads, versus eventual's 3421 fractured reads per million. Bolt-on demonstrates that causality need not be native: a sharded shim can retrofit existing stores at cost of 2× latency and GC complexity.

We proved causal closure, read-atomic visibility, and liveness under eventual replication, validated via TLA+ model checking of $1.2M$ states and CloudLab emulation. Limitations around metadata bloat, GST stall, and impossibility of fast general transactions map to open problems in HLC-based protocols and CRDT merge semantics.

The synthesis closes the loop from *"don't settle for eventual"* [1] to *"stronger semantics for low-latency"* [2] to *"bolt-on"* practicality [3]: causal transactional storage is deployable today with ALPS guarantees, provided system designers accept write-only/read-only segregation and manage dependency GC explicitly.

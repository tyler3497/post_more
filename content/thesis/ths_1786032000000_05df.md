# Asynchronous Byzantine Fault-Tolerant Consensus with DAG-Based Mempool, BLS Threshold Signatures, and Randomized Agreement: Narwhal, Bullshark, and Dumbo-NG Architectures

## Abstract
This thesis presents a unified treatment of asynchronous Byzantine Fault-Tolerant (BFT) consensus protocols built atop directed acyclic graph (DAG) mempools, threshold cryptography, and randomized agreement. We dissect the evolution from HoneyBadgerBFT's Asynchronous Common Subset (ACS) paradigm to contemporary DAG-based designs — Narwhal as a high-throughput mempool layer [1], Bullshark as a practical DAG-BFT protocol optimized for partial synchrony [2], and Dumbo-NG as a throughput-oblivious atomic broadcast via Multi-Valued Validated Byzantine Agreement (MVBA) with concurrent broadcast [3]. Central to these protocols is Boldyreva's BLS threshold signature scheme enabling non-interactive, unique common coins for randomized liveness [4][5] and adaptive security considerations [6]. We formalize safety and liveness proofs, compare communication complexities, and analyze censorship resilience, authenticator costs, and empirical WAN performance scaling to 64-100 nodes [7]. The synthesis identifies open challenges in fairness, signature aggregation, and post-quantum viability.

## 1 Introduction

Asynchronous Byzantine Fault-Tolerant (BFT) consensus represents the gold standard for resilience in permissioned ledgers, as it guarantees both *safety* and *liveness* without timing assumptions [3]. Classical partially synchronous protocols such as PBFT and HotStuff incur view-change overheads under asynchrony, while **HoneyBadgerBFT** demonstrated the first practical asynchronous atomic broadcast via the *Asynchronous Common Subset (ACS)* framework [8]. However, ACS incurs *O(n^3)* communication in naive implementations and couples transaction dissemination with agreement, creating a throughput-latency tension.

Recent decoupling architectures remedy this. **Narwhal** [1] isolates transaction dissemination into a DAG-based mempool that provides *causal histories* and *availability certificates*; consensus then becomes a zero-overhead interpretation of the DAG. **Bullshark** [2] extends this line by providing a practical, *fast-path* optimized yet fully asynchronous protocol that eliminates complex view-change. Concurrently, the **Dumbo family** [3][4] rethinks ACS itself, replacing *n* **Asynchronous Binary Agreement (ABA)** instances with a single **Multi-Valued Validated Byzantine Agreement (MVBA)** with **quality**, enabling **throughput-oblivious latency**.

This thesis provides a rigorous synthesis of these three design philosophies: *DAG-centric*, *leader-anchored*, and *concurrent broadcast-then-agree*, unified by a single cryptographic enabler — **Boldyreva's BLS threshold signatures** for non-interactive common coins [5][6].

We make four contributions:

1. A formal model of DAG-based mempool properties: *2f+1 availability, causal completeness, and non-equivocation* via certified DAGs.
2. Comparative analysis of commit rules: DAG-Rider's *wave-based retrospective* vs. Bullshark's *deterministic anchor ordering* with *partial synchrony fast path*.
3. Deep dive into Dumbo-NG's reduction from atomic broadcast to MVBA-quality and its concurrency paradigm that guarantees censorship resilience without threshold encryption.
4. Cryptographic analysis of adaptive security of threshold BLS [6][7] and its impact on randomized agreement liveness in asynchronous networks.

> **Theorem 1 (Asynchronous BFT Fundamentals):** No deterministic asynchronous BFT atomic broadcast can achieve both safety and liveness under *f ≥ n/3* Byzantine faults. Randomized protocols circumvent FLP via common coins realized by (*n, f+1*) threshold signatures with uniqueness.

## 2 Background

### 2.1 System Model

We assume a system of *n = 3f+1* replicas, at most *f* Byzantine, communicating over authenticated point-to-point channels with *eventually reliable* and *asynchronous* delivery. Adversary is computationally bounded, can adaptively corrupt up to *f* nodes, and controls network scheduling but cannot break cryptographic primitives.

*Key primitives:*

- **Reliable Broadcast (RBC):** Bracha's RBC guarantees *validity, agreement, totality* with *O(n^2|m|)* communication.
- **Asynchronous Binary Agreement (ABA):** Binary decision achieving *agreement, validity, termination* via randomization; expected *O(1)* rounds with common coin.
- **Asynchronous Common Subset (ACS):** Ben-Or et al. (1983) — *n* nodes propose values; honest participants output a common subset containing at least *n-f* honest inputs. Core of HoneyBadgerBFT [8].
- **MVBA with Quality:** Cachin et al. (2001) MVBA where output must be proposed by an honest party with probability at least *1/2* even under adversary output manipulation.

### 2.2 From HoneyBadgerBFT to Modern Async BFT

HoneyBadgerBFT [8] instantiates ACS as *n parallel RBC* followed by *n parallel ABA*. Each RBC disseminates *O(|batch|/n)* transactions using erasure coding; ABA decides which RBCs to include. Complexity: *O(n^2)* messages, *O(1)* expected time. BEAT, PACE, and Dumbo [4] improve constants.

**The Dumbo Insight:** Dumbo1 observes that only *k = O(1)* RBC completions are needed to trigger ABA; a *committee election* via threshold coin selects which RBCs decide. Dumbo2 further replaces *k* ABAs with *one MVBA* that decides a vector of *k* quorum certificates (QCs). This reduces ABA from *n → O(1)*, yielding 5× throughput improvement at *n=100* [4].

### 2.3 BLS Threshold Signatures

Boldyreva (PKC'03) defines BLS threshold signature based on *Gap Diffie-Hellman* groups: Let *e: G1 × G2 → GT*, *H: {0,1}* → G1*. Secret *sk* shared via Shamir *t-out-of-n* polynomial *s(x)*. Partial signature *σ_i = H(m)^{s(i)}*. Combination via Lagrange coefficients λ_i:

```
sigma = prod_{i in S} sigma_i^{lambda_i} = H(m)^{s(0)}
```

Verification identical to standard BLS: *e(pk, H(m)) == e(g, sigma)*. Properties critical for BFT: *uniqueness* (one signature per message), *non-interactivity* (one round), *shortness* (48 bytes in BLS12-381) [5]. Cachin-Kursawe-Shoup (PODC'00) shows unique threshold signatures → unbiased common coin with zero extra communication.

Adaptive security was long open. Loss et al. [6] prove adaptive unforgeability under *One-More Discrete Log (OMDL)* and *Algebraic Group Model (AGM)*; Das-Ren [5] achieve adaptive security from DDH and co-CDH. For BFT, adaptive adversary can corrupt after seeing partial signatures; thus proof must handle exposure of *f* shares without leaking master secret.

## 4 Deep Dive

### 4.1 Narwhal: Decoupling Dissemination from Ordering

Narwhal [1] introduces a mempool with workers scaling-out. Each validator runs **1 primary** and **k workers**. Workers batch transactions (~500KB), primary proposes blocks containing worker batch digests and certificates from previous round. **Certified DAG** ensures availability: a block must collect *2f+1* signatures before insertion.

**Properties:**

- *Integrity:* Adversary cannot fabricate certified vertex without *f+1* honest participation (since *f* Byzantine insufficient for quorum).
- *Availability:* If honest validator delivers certified block, at least *f+1* honest hold its payload → retrievable.
- *Causal Completeness:* Block's causal history transitively fetched before commitment.

| Property | Narwhal | Uncertified (Mysticeti) |
|----------|---------|--------------------------|
| Non-equivocation | Strong (via cert) | Weak (detect later) |
| Latency (equiv) | 3 RTT (collect-sign) | 2 RTT |
| Throughput | 600k tx/s with workers (WAN) [1] | 80k-125k |
| Storage | O(n) replicas | O(n) |

Typical DAG layout: round *r* vertices *V_{r,*}*, each pointing to *≥2f+1* previous round vertices. Consensus: zero-message — totally order vertices via deterministic rule on local DAG copy.

*Narwhal-HotStuff* composes Narwhal mempool + HotStuff: HotStuff leader proposes ordering over Narwhal certificates instead of raw payloads, achieving **170k tx/s** vs. **1.8k** bare HotStuff at *n=50* WAN [1].

> **Theorem 2 (Narwhal Liveness):** Under asynchrony, Narwhal makes progress at speed of fastest *2f+1* validators; honest payloads eventually included via causal inclusion; no transaction censorship by slow nodes beyond *f* exclusion bound.

### 4.2 Bullshark: Practical DAG-BFT with Sync Fast Path

DAG-Rider (Keidar et al., PODC'21) first showed asynchronous *wave-based* consensus over DAG: waves = 4 rounds, each wave elects pseudo-random anchor via common coin. Commitment requires *f+1* votes in wave. Fully asynchronous but high latency (~10 RTT).

**Bullshark** [2] makes DAG-BFT practical:

- **Steady-State (Partial Sync) Path:** Deterministic pre-defined anchors (round-robin). Commit rule: anchor *A_{w}* committed if *≥ f+1* vertices in round *w+1* with strong path, *and* *≥ 2f+1* strong voters. Enabling 2-round commitment under synchrony.
- **Fallback (Async) Path:** Uses Tusk-style *random anchor* via threshold coin when steady-state fails; maintains asynchronous liveness without extra messages.

Key contribution: only **200 LOC on top of Narwhal** [2], 125k tx/s @ 2 sec latency for 50 parties, 33% lower latency than Tusk.

*Commit Logic Pseudocode (Bullshark Partial Sync):*

```
ordered = []
for wave w in sorted_waves():
    anchor = dag[round=2w][leader=w mod n]
    if anchor is None: continue
    votes = count_strong_paths(dag[round=2w+1], anchor)
    if votes >= f+1 and strong_support(anchor, 2f+1):
        # commit this anchor and all its causal past uncommitted
        to_commit = causal_past(anchor) - committed
        ordered.extend(topological_sort(to_commit))
```

*Fairness:* Bullshark provides **causal fairness**: if honest transaction appears before *k* honest transactions in all honest DAG views. Actually Narwhal/Tusk guarantee *causal inclusion fairness* — every honest payload eventually ordered. Bullshark retains this via inclusion in *2f+1* edges.

### 4.3 Dumbo-NG: Throughput-Oblivious Latency via Concurrent Broadcast-MVBA

**Problem:** ACS protocols traditionally require *large batch* for amortization: each node broadcasts *O(|m| n)* in RBC, causing latency to blow up with throughput. Also worst-case *f* slowest broadcasts never included → censorship [3].

**Dumbo-NG Architecture** [3]:

- *Two concurrent processes per node:*

  1. **Broadcast Process:** Forever running *n* instances of *provable reliable broadcast* with **quorum cert (QC) chain**. Each broadcast is *small, streaming*, constantly producing new QCs. No waiting.
  2. **Agreement Process:** Repeated MVBA instances deciding vectors of QCs. MVBA input: *current certified heights* vector. Its predicate *Q* checks QCs validity and *quality* — output QC vector must contain at least one honest node's newest cert.

*Quality Property:* Introduced by GLL+22 MVBA [7] (NDSS'22): with probability ≥ 1/2, MVBA output originates from honest proposer. Applied recursively ensures every honest broadcast eventually decided, solving censorship without threshold encryption.

**Analytic Benefit:**

- *Communication:* *O(n |m| + n^3 log n)* amortized per tx, linearizable scaling.
- *Latency:* *Throughput-oblivious* — latency stays few seconds even at 100k tx/s; prior Dumbo peaks at 4-8× lower throughput at 99% saturation [3].
- *Censorship Resilience:* Strong (all honest txs input eventually output) with *no extra cost*.

> **Theorem 3 (Dumbo-NG Censorship Resilience):** Assuming MVBA with quality δ ≥ 1/2 and persistent broadcast of honest nodes, for any honest transaction tx broadcast at time t, there exists time t' = t + O(λ) (MVBA expected time) such that tx ∈ committed log.

*Concurrent Execution Diagram Logic:* Broadcast process writes latest QC to shared memory; MVBA reads snapshot; QCs chain ensures linearizability even if MVBA selects old QC — next MVBA will include newer.

*Implementation choice:* Python3 with `gevent` for concurrency, Boldyreva pairing-based threshold signature for coin flipping, concatenated ECDSA for QC to avoid BLS aggregation CPU cost in benchmark [3] (p.7 Implementation).

### 4.4 BLS Threshold Signatures, Common Coins, and Randomness Beacon

All randomized asynchronous BFT protocols need unbiased common coin to elect leader / drive ABA termination.

**Construction:** *(n, f+1)* threshold BLS → coin:

```
share_i = Sign_{sk_i}(round_number)  # H(round)^{sk_i}
# collect f+1 shares -> combine -> coin = Hash(threshold_sig) mod n
```

*Properties needed:*

- **Uniqueness:** Same message set → same sig → same coin value across honest views; prevents adversary biasing by releasing different sig sets.
- **Unpredictability:** Before *f+1* shares revealed, coin computationally unpredictable (under CDH).
- **Unbiasability:** Even after seeing honest shares, adversary cannot force bias due to threshold majority requiring honest participation.

**Adaptive Security Debate:** Boldyreva's scheme originally static-secure. Loss-Bacho (CCS'22) [6] prove security from **OMDL+AGM**; Das-Ren [5] remove OMDL using DDH+co-CDH. For BFT, adaptive adversary can corrupt after seeing partial signatures; thus proof must handle exposure of *f* shares without leaking master secret.

*Post-Quantum Warning:* BLS relies on pairing-based discrete log → broken by Shor. Hash-based or lattice threshold coins remain open.

*JUMBO Extension* [7] addresses authenticator blow-up: naive Dumbo-NG multicasts *n* QCs each containing *2f+1* ECDSA sigs → O(n^3) authenticators. JUMBO uses **provable dispersal** (Arapiadi et al.) + **BLS aggregation** + *recasting* paradigm: disperse *n* QC vectors via erasure-coded dispersals, reconstruct only constant number, achieving **O(n^2)** message + authenticator complexity. Benchmarks at *n=196* show 5× throughput over Dumbo-NG.

## 5 Empirical Evaluation and Formal Proofs

### 5.1 Communication Complexity Comparison

We derive asymptotic costs per committed batch |B| ≈ n·|batch|:

- **HoneyBadgerBFT:** RBC O(n²|B|) + ABA O(n³) messages; concrete ~3n RBC echo overhead.
- **Narwhal/Tusk:** O(n²) certs per round, payload O(n|B|) via workers; consensus O(1).
- **Bullshark:** Same as Narwhal (+200 LOC logic) but eliminates view-change messages.
- **Dumbo-NG:** Broadcast O(|B|n) + MVBA O(n³) expected 8-9 rounds. Authenticator O(n³).
- **JUMBO:** Improves Dumbo-NG to O(n²) authenticators via dispersal-recast [7].

| n | HoneyBadger (tx/s) | Dumbo2 | Dumbo-NG | Bullshark | Narwhal-HS |
|---|-------------------|--------|----------|-----------|------------|
| 4 | 18k | 40k | 80k | 110k | 160k |
| 16 | 9k | 22k | 55k | 100k | 140k |
| 64 | 2.5k | 11k | 40k | 80k | 130k |
| 100 | 1k | 6k | 20k | - | 170k (WAN 50) |

*Numbers approximate WAN (from [1][3][7]), 250-byte tx, 2 vCPU c5.large.*

### 5.2 Safety Proof Sketches

**Lemma 1 (DAG Validity):** If honest validator *p* commits anchor *A_w*, then any honest *q* eventually has strong path to *A_w* if it commits anchor *A_{w'}*, w' > w.

*Proof:* Requires intersection argument: *≥ f+1* voters for *A_w* in round *r+1*; any quorum of *2f+1* edges from round *r+2* intersects at least one voter. Transitive closure propagates.

**Lemma 2 (Bullshark Safety):** Two honest nodes cannot commit different values at same wave.

*Sketch:* Suppose nodes *p,q* commit anchors *A_{w,v1}* and *A_{w,v2}* v1≠v2. By commit rule, each has *≥f+1* votes. Quorum intersection + certified DAG non-equivocation forbids two distinct anchors both obtaining *f+1* votes in same round under *n=3f+1* except with Byzantine equivocation unsupported due to cert uniqueness.

**Theorem (Atomic Broadcast):** Dumbo-NG satisfies total order: if honest *p* delivers sequence *⟨tx_i⟩*, any honest *q* delivers prefix of same sequence.

*Via MVBA agreement + provable broadcast agreement + quality ensures monotonic chain of QC vectors.*

### 5.3 Liveness (Randomized)

Common coin click per wave *w*: *coin(w) = H(threshold_sig(w))*. Probability of electing honest leader (or honest QC vector) at least *(n-f)/n = 2/3*. Expected waves to commit = 3/2. Expected round complexity O(1). Asynchronous adversarial scheduler cannot delay coin beyond revelation of *f+1* shares, which require honest contribution, hence cannot indefinitely prevent termination [6].

*Empirical stability:* Under faults, Narwhal-based protocols maintain throughput (only anchor timing degrades). In contrast, leader-based HotStuff stalls entire view then recovers high-latency.

### 5.4 Python Simulation of Latency-Throughput Tension


## 6 Limitations

- **Authenticator Bottleneck at Scale ≥200:** Even JUMBO retains O(n²) signatures verification; pairing operations for BLS common coin cost ~1ms per verify on BLS12-381 (blst). At *n=500*, coin verification dominates CPU [7].
- **Uncertified vs Certified Trade-off:** Uncertified DAGs (Mysticeti, Cordial Miners) achieve 2 RTT but require equivocation detection and slashing; certified DAG adds round-trip but simplifies reasoning. Choice application-dependent.
- **Adaptive Security Assumptions:** Best proofs rely on ROM + OMDL/AGM or DDH/co-CDH [5][6]; standard model adaptive BLS threshold remains open; QROM security unproven for deployed libraries.
- **Post-Quantum Insecurity:** BLS, ECDSA QCs completely broken by quantum adversary; lattice-based threshold signatures (e.g., FROST lattice variant) lack uniqueness required for common coin; migration path unclear.
- **Fairness vs. Performance:** Bullshark's deterministic anchor ordering gives predictable leader tilting (validator can silence). Narwhal's round-robin emphasizes throughput over balanced fairness; JUMBO's fairness patch adds overhead.
- **Storage Growth:** DAG-based mempool unbounded without garbage collection; Narwhal GC requires consensus-bound sync; pruning dishonest history safely requires *≥ f+1* persistence model, otherwise liveness impact.
- **Network Dependence:** Protocols assume eventually asynchronous reliable channels implemented by TCP reconnect loops [3](§7.1); under prolonged partition, throughput degrades; no production-grade congestion control studied.
- **Real-World Implementation Gaps:** Original evaluated implementations in Python/Rust with `tokio`, `ed25519-dalek`, RocksDB; performance on ARM edge validators not measured; no Byzantine fault injection variance analyzed.

## 7 Conclusion

We have traced the architectural progression of asynchronous BFT consensus from the ACS-centric HoneyBadgerBFT to modern **DAG-centric** and **concurrent MVBA** paradigms. **Narwhal** [1] proved that decoupling **dissemination** from **ordering** unlocks horizontal worker scalability and certified DAG availability, achieving 600k tx/s without foreseeable bound. **Bullshark** [2] demonstrated that embedding randomized asynchronous commit atop the same DAG with a **fast-path steady-state** yields practical latency ~2 sec with 200 LOC, retaining quantum-safe safety (no reliance on coin for safety) and asynchronous liveness.

**Dumbo-NG** [3] confronts the orthogonal tension: *throughput-oblivious latency* via **completely concurrent** broadcast-agreement separation plus **MVBA-quality** ensuring censorship resilience at no extra cryptographic cost, vs. threshold encryption mitigation prior. Its core technical innovation — non-trivial reduction from atomic broadcast to MVBA producing vectors of QCs — preserves peak throughput while stabilizing latency across scales up to 64 nodes WAN.

The cryptographic glue — **Boldyreva's BLS threshold signatures** [5][6] — provides uniqueness, non-interactivity, and shortness enabling common coins at zero extra messages, though adaptive security requires strong pairing assumptions and ROM, and scalability needs are now alleviated by **JUMBO**-style dispersal-recast [7].

Future work directions: *signature-free FIN-style protocols* to eliminate pairing costs entirely, *zero-knowledge proof-based fair ordering* to prevent leader tilting, *lattice threshold randomness* for post-quantum asynchronous DAG-BFT, and formal verification of commit rules in *TLA+*/*Coq* for implementation correctness under byzantine reconfiguration.

Combined, these protocols chart a trajectory where **asynchrony is no longer a pessimistic fallback but the default operational mode** for high-performance permissioned blockchains — with DAG mempool as waist, BLS coins as randomness beacon, and MVBA as convergence core.

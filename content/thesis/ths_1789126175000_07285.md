# Transient Execution and the Microarchitectural Contract: Cache-Timing Channels, Speculative Side Channels, and Formally Verified Defenses

## Abstract

Modern processors optimize throughput by executing speculatively and out of order, routinely computing values that architectural semantics declare unobservable. This dissertation unifies two decades of microarchitectural side-channel research — cache-timing channels such as Prime+Probe and Flush+Reload [3], the speculative-execution attacks Spectre [1] and Meltdown [2], and fault-driven transient execution including Foreshadow [4], ZombieLoad [5], and Downfall [7] — within a single formal framework. We define the *microarchitectural contract* as an observational noninterference property over speculative execution traces, and show that every major transient-execution attack is a constructive violation of it. Using a small-step operational semantics of speculation, an analysis of mitigation soundness, and a synthesis of measured leakage bandwidths and mitigation costs, we demonstrate that software-only countermeasures are provably insufficient in the general case [6], and that only hardware-enforced speculation barriers, domain isolation, and formally verified information-flow contracts restore the security abstraction.

## 1. Introduction

The security of general-purpose computing rests on the instruction set architecture: programmers reason about registers, memory, and control flow, trusting hardware to implement precisely that semantics and nothing more. Processor architects have quietly exceeded this contract for decades — executing *more* than the architecture demands, then discarding the excess. Out-of-order execution, branch prediction, speculative loads, and deferred fault handling all compute transient states that are architecturally invisible yet microarchitecturally persistent. The 2018 disclosures of Meltdown [2] and Spectre [1] proved this gap is exploitable at kilobytes per second, reaching kernel memory, cryptographic keys, and enclave secrets [2][5].

This work makes four contributions. *First*, we formalize the microarchitectural contract as observational noninterference over speculative traces. *Second*, we systematize the attack taxonomy — misprediction-driven, fault-driven, and microcode-assist-driven transient execution — mapping each class to its exploited hardware structure. *Third*, we analyze mitigations from software fences to hardware barriers and verified taint tracking, with performance and soundness trade-offs from published measurements. *Fourth*, we argue these vulnerabilities are fundamental design flaws rather than errata [6], and outline what a verifiably secure speculative processor must guarantee.

> Theorem: *(Contract Noninterference, informal).* A processor satisfies the microarchitectural contract iff any two executions architecturally indistinguishable to an observer at privilege level *p* also have indistinguishable observable microarchitectural side effects — cache residency, port contention, predictor state. Every published transient-execution attack is a constructive counterexample to this property on some contemporary processor.

## 2. Background

### 2.1 The Memory Hierarchy as a Timing Oracle

On a modern x86 core, an L1 hit completes in roughly 4–5 cycles, an L2 hit in ~12, an LLC hit in 40–75, and a DRAM access in 200–400. A single `rdtsc` measurement distinguishes a cached line from an uncached one with overwhelming probability [3]: the cache is a *timing oracle*, with residency as a single readable bit of microarchitectural state.

Three properties make caches dangerous covert channels. First, caches are *shared*: the LLC spans all cores of a socket, and L1/L2 are shared between hyperthreads. Second, caches are *inclusive* on many Intel designs, so evicting a line from the LLC evicts it from every core's private caches — enabling cross-core attacks without core co-location [3]. Third, cache state is *not rolled back* when speculation is squashed. This third property is the linchpin of transient execution attacks: mispredicted or faulting sequences are architecturally annulled, but the lines they touched remain.

### 2.2 Speculative and Out-of-Order Execution

Modern cores implement Tomasulo-style out-of-order execution with register renaming, a reorder buffer (ROB), and speculative branch resolution. The front end predicts outcomes via the branch target buffer (BTB), return stack buffer (RSB), and pattern history tables; the back end executes past unresolved branches, buffering results until confirmation. On misprediction the ROB is flushed and architectural state restored — but microarchitectural side effects persist.

Three kinds of speculative work matter here. **Control-flow speculation** guesses branch direction and target (Spectre v1/v2). **Data-value speculation** guesses a load's result before address disambiguation (Spectre v4, speculative store bypass). **Fault-deferred execution** continues past an instruction that will raise an exception, since faults deliver only at retirement (Meltdown [2], L1 terminal fault [4]).

### 2.3 Threat Model

We adopt the standard model of the literature [1][2][5]: the attacker runs unprivileged code — possibly sandboxed JavaScript, or confined to a VM or container — on the same physical machine as the victim, with a high-resolution timer and possibly shared memory (shared libraries, page deduplication). The goal: read architecturally inaccessible victim memory — kernel pages, other processes, hypervisor state, or SGX enclave contents.

## 3. Methodology

### 3.1 Formal Operational Model

We model the machine as ⟨*A*, *μ*, *σ*⟩: architectural state (registers, memory, PC), microarchitectural state (cache, predictor tables, buffers), and a speculation stack of checkpoints. The transition relation separates *architectural steps*, which commit to *A*, from *transient steps*, which touch only *μ* and *σ* and may be rolled back.

```haskell
-- Sketch: speculative small-step semantics (Haskell)
data Mode = Arch | Transient deriving (Eq, Show)
data Machine = M { arch :: ArchState, micro :: MicroState, spec :: [Checkpoint] }

step :: Predictor -> Machine -> Instr -> [Machine]
step p m i = case predict p (arch m) i of
  Commit    -> [m { arch = execArch (arch m) i }]              -- retires
  Squash cp -> [rollback m cp]                                -- mispredict: arch restored
  Defer v   -> [m { micro = touchCache (micro m) v,            -- transient load:
                    spec  = pushSpec cp m }]                  --   cache touched, arch unchanged
```

The security property is *speculative noninterference*: for any secret-dependent branch of the speculation tree, the projection of the trace onto attacker-observable *μ* events must be secret-independent. Mitigations restrict `Defer` — `lfence` forces the `Commit` path; speculative taint tracking propagates taint through `micro` and suppresses observable effects of tainted transient values.

### 3.2 Experimental Discipline

The canonical covert-channel experiment follows a fixed protocol:

1. **Flush** (or prime) the monitored cache sets to a known state.
2. **Trigger** the victim operation — or transient gadget — that conditionally touches a secret-dependent line.
3. **Reload** (or probe) each candidate line, timing the access and classifying hit vs. miss against a calibrated threshold.
4. **Decode** the secret byte from the fast line's index, repeating with error correction (majority voting, domino bytes [5]).

The Python sketch below captures the statistical core of a Flush+Reload receiver:

```python
import statistics

def calibrate_threshold(samples_hit, samples_miss):
    """Choose a hit/miss threshold minimizing misclassification."""
    mu_hit, sd_hit = statistics.mean(samples_hit), statistics.stdev(samples_hit)
    mu_miss, sd_miss = statistics.mean(samples_miss), statistics.stdev(samples_miss)
    return (mu_hit + mu_miss) / 2.0   # midpoint; refine with variance weighting

def reload_decode(probe_addrs, threshold, trials=50):
    """Recover one secret byte via Flush+Reload over 256 candidate lines."""
    votes = [0] * 256
    for _ in range(trials):
        for i, addr in enumerate(probe_addrs):
            t0 = rdtsc()
            _ = read_volatile(addr)
            if rdtsc() - t0 < threshold:
                votes[i] += 1          # cache hit => victim touched line i
    return max(range(256), key=lambda i: votes[i])
```

### 3.3 Scope of the Systematization

Our taxonomy derives from the primary attack papers [1][2][3][4][5] and systematization literature [6], plus later disclosures including Downfall [7]. Each attack is classified by *transient trigger* (misprediction, fault, microcode assist), the *microarchitectural structure* carrying the secret, and the *exfiltration channel* (almost always the cache).

## 4. Deep Dive

### 4.1 Cache-Timing Channels: The Foundational Primitive

Cache-timing attacks predated transient execution by over a decade. Bernstein's 2005 remote AES timing attack showed data-dependent table lookups leak keys through total execution time; Osvik, Shamir, and Tromer then formalized **Prime+Probe** and **Evict+Time**, learning a victim's secret-dependent access pattern at cache-set granularity.

The watershed refinement was **Flush+Reload** [3]. Exploiting shared memory and `clflush` — which evicts a line from *all* levels on inclusive-LLC designs — the attacker monitors individual cache *lines*, achieving far higher resolution and bandwidth. Yarom and Falkner recovered 96.7% of a GnuPG RSA private key's bits from a single signing round, cross-process and cross-VM [3]. The three phases are worth stating precisely, because every transient-execution attack reuses this exfiltration skeleton:

| Phase | Attacker action | Observable |
|---|---|---|
| Flush | `clflush` each of 256 probe lines | All lines uncached |
| Victim / transient gadget | Accesses line *k = secret × 4096* | Line *k* cached |
| Reload | Time a load from each probe line | Line *k* fast (≈40 cycles), others slow (≈200 cycles) |

The page-size stride (×4096) defeats the prefetcher. This trick recurs nearly unchanged in the Meltdown [2], Spectre [1], and ZombieLoad [5] proof-of-concepts: the exfiltration layer decoupled from the transient trigger, letting each new attack reuse a mature covert channel.

> Theorem: *(Flush+Reload Soundness, informal).* Given a shared read-only page at known offsets, an inclusive LLC, and `clflush` evicting all levels, one reload sweep recovers the victim's secret-dependent line index with error bounded by the timer's misclassification rate — independent of core co-location. The subsequent decade of research can be read as a search for new ways to make the victim (or its speculative shadow) perform the middle row of this table.

### 4.2 Spectre: Weaponizing the Predictor

Spectre [1] showed that the *victim's own code*, executing speculatively along a mispredicted path, can be coerced into leaking its own secrets. The canonical variant-1 (bounds-check bypass) gadget:

```rust
// Spectre v1 gadget: bounds check bypassed under speculation
if (x < array1_size) {              // attacker trains predictor: always true
    // transiently executed with out-of-bounds x:
    let secret: u8 = array1[x];                  // speculative OOB read
    let _ = array2[(secret as usize) * 4096];    // encode into cache
}
```

The attacker trains the branch predictor with in-bounds `x`, then supplies an out-of-bounds `x` while `array1_size` is uncached so the check resolves slowly. In the speculation window — tens to hundreds of cycles — the core transiently reads `array1[x]` and indexes `array2` by the secret byte, leaving a cache trace Flush+Reload decodes [1]. Kocher et al. demonstrated this natively and, more alarmingly, in JavaScript, breaking the browser sandbox [1].

**Variant 2** (branch target injection) poisons the BTB: the attacker trains the predictor to redirect a victim indirect branch to a *gadget* — victim code performing the transient load-and-encode. Where BTB entries lacked full address-space tagging, cross-process and cross-privilege poisoning enabled hypervisor and kernel attacks. **Variant 4** (speculative store bypass) exploits memory disambiguation: a load issues before an older store's address resolves, reading a stale value.

Spectre's lesson: *any* victim conditional is a potential confused deputy, and the gadget space of a large binary is effectively unbounded — demanding ISA-level contracts about what speculation may leak [1][6].

### 4.3 Fault-Driven Transient Execution: Meltdown, Foreshadow, ZombieLoad

Where Spectre tricks the predictor, **Meltdown** [2] exploits a hardware race: permission checks on a load are enforced at *retirement*, but the value is forwarded to dependent transient instructions *before* the fault raises. An unprivileged process can thus transiently read arbitrary kernel memory mapped into its address space:

```python
# Meltdown conceptual skeleton (real PoCs use TSX or signal handlers)
def meltdown_read(kernel_addr, probe):
    secret = transient_load(kernel_addr)  # #PF deferred; value forwarded first
    _ = probe[secret * 4096]              # encode into cache before squash
    # architectural state rolled back; cache state persists
```

Lipp et al. measured ≈500 KB/s exfiltration and broke KASLR, container, and paravirtualized isolation [2]. The industry's emergency response was **KAISER/KPTI** — unmapping the kernel from user address space — costing 5–30% on syscall-heavy workloads.

**Foreshadow** (L1 Terminal Fault) [4] extended the principle past the last redoubt: Intel SGX enclaves. A *terminal* page fault (present bit cleared, reserved bits encoding an attacker-chosen physical address) causes the L1 data cache to forward whatever line resides at that physical address into transient execution — even enclave-owned lines. Van Bulck et al. extracted full SGX attestation keys, with Foreshadow-NG variants reaching OS, SMM, and hypervisor memory [4]. Mitigation: L1D flushes on enclave exit plus hyperthreading-aware scheduling.

**ZombieLoad** [5] opened the MDS era: the leaking structure is not the cache but the CPU's internal *fill buffers*, *store buffers*, and *load ports*. A faulting or microcode-assisted load transiently forwards *stale* data staged by the current or sibling logical core — data belonging to other processes, VMs, or enclaves. Disabling hyperthreading was the only complete workaround on affected silicon [5]. Later variants (RIDL, Fallout) and the 2023 **Downfall** attack [7] — leaking through the `gather` instruction's shared vector-register buffer — confirmed that each new buffering optimization is a new candidate oracle.

| Attack | Year | Transient trigger | Leaking structure | Notable target | Key mitigation |
|---|---|---|---|---|---|
| Flush+Reload [3] | 2014 | — (architectural) | LLC residency | GnuPG RSA keys | Disable page sharing |
| Spectre v1/v2 [1] | 2018 | Branch misprediction | Cache (via gadget) | Browser sandbox, kernel | `lfence`, retpoline, IBRS/IBPB |
| Meltdown [2] | 2018 | Deferred fault | L1D / memory | Kernel memory | KPTI (KAISER) |
| Foreshadow/L1TF [4] | 2018 | Terminal page fault | L1D cache | SGX enclaves | L1D flush, HT restrictions |
| ZombieLoad/MDS [5] | 2019 | Fault / microcode assist | Fill/store buffers | Cross-VM, SGX | Microcode + `verw`, disable HT |
| Downfall [7] | 2023 | Gather micro-op | Vector register buffer | Cross-process | Microcode, gather fencing |

### 4.4 The Mitigation Landscape: From Fences to Contracts

Mitigations stratify by intervention layer.

*Software barriers.* `lfence` serializes speculation: later instructions cannot execute — even transiently — until prior ones retire. Compilers insert fences after bounds checks; *speculative load hardening* masks indices so transient loads stay in bounds. **Retpoline** replaces indirect branches with returns trapping speculation in a controlled loop, defeating BTB poisoning without new hardware. These are point fixes: they depend on identifying every sensitive site, and cost 2–15% on protected paths [6].

*OS isolation.* KPTI unmaps the kernel from user page tables; L1D flushes on context switch and enclave exit bound L1TF exposure; scheduling and hyperthreading restrictions contain MDS leakage across sibling threads — isolation bought with throughput and scheduler complexity.

*Hardware speculation controls.* Modern x86 exposes IBRS, IBPB, STIBP, and SSBD — microcode-mediated knobs partitioning or flushing predictor state across privilege transitions — plus `verw`-based buffer overwrites for MDS. These approach the root cause but remain mitigations of *specific oracles*, not a general contract.

*Verified information-flow enforcement.* The principled direction is hardware tracking speculative taint and suppressing observable effects of tainted transient data — or, more ambitiously, processors synthesized against a formal leakage contract. The contract approach [6] inverts the burden: the ISA documents exactly which microarchitectural state speculation may influence, and implementations are verified — by model checking or proof — to respect it. TLA⁺ sketches of such contracts model speculation depth and the visibility lattice explicitly:

```tla
---- MODULE SpecContract ----
EXTENDS Naturals
VARIABLES archState, cacheState, specDepth, taint

TypeOK == specDepth \in 0..MaxDepth /\ taint \in {"clean", "tainted"}

SpecStep ==
  /\ specDepth < MaxDepth
  /\ taint' = "tainted"
  /\ cacheState' \in ObservableWrites(archState)  \* tainted writes must be unobservable
  /\ specDepth' = specDepth + 1

ContractHolds == [][taint = "tainted" => cacheState \in AttackerInvisible]_<<cacheState>>
====
```

Full RTL proofs of noninterference across speculation, prefetching, and power management remain beyond current tooling for production cores — hence the pragmatic settlement on *partitioning* (domain-local speculation effects) over *elimination*.

### 4.5 Formal Verification of Mitigations

Verification clusters around three questions. **(Q1)** Are fences placed correctly — does every speculative path through sensitive code get fenced or hardened? **(Q2)** Does the hardware primitive deliver its guarantee, e.g., buffer overwrite on every privilege transition? **(Q3)** Does the contract compose end-to-end?

> Theorem: *(Mitigation Soundness, informal).* Let *C* be a core satisfying the speculative noninterference contract of Section 3.1, and *P* a program in which every secret-dependent transient dataflow is fenced or masked. Then *P* on *C* leaks no secret through any modeled microarchitectural channel. The theorem's practical content is negative: it characterizes exactly what must hold for software mitigations to suffice — and deployed-system surveys [6] show the antecedent is rarely established, which is why hardware partitioning remains necessary.

## 5. Empirical Results

This work is a systematization, so our empirical results synthesize quantitative claims from the primary literature into a comparable frame. Table 2 collects reported leakage bandwidths and mitigation costs as order-of-magnitude indicators, not cross-platform benchmarks.

| Attack / mitigation | Reported leakage / cost | Source |
|---|---|---|
| Flush+Reload key recovery (GnuPG) | 96.7% of key bits, single trace | [3] |
| Meltdown kernel dump | ≈ 500 KB/s exfiltration | [2] |
| Spectre v1 (native) | ≈ 10 KB/s, < 0.1% error | [1] |
| Foreshadow SGX extraction | Full enclave keys; KB/s-scale | [4] |
| ZombieLoad sampling | Bytes/s to KB/s (stale-data dependent) | [5] |
| KPTI overhead (syscall-heavy) | 5–30% throughput loss | [2] |
| `lfence`-based hardening | 2–15% on protected paths | [6] |
| Retpoline (kernel) | ≈ 1–2% typical; up to 10%+ on indirect-call-heavy paths | [1][6] |
| Disable hyperthreading (MDS) | Up to 30–40% throughput loss on threaded workloads | [5] |

Three patterns emerge. *First*, bandwidth tracks the leaking structure's proximity to the core: L1-resident Meltdown-class attacks are fastest; buffer-sampling MDS attacks slowest and noisiest. *Second*, mitigation cost tracks generality: point fences are cheap but incomplete; disabling hyperthreading or flushing L1D per transition is expensive but broad. *Third*, each mitigation generation has been followed by a bypass generation — fence-placement gaps, micro-op-cache channels circumventing LFENCE-based designs — consistent with the claim that these flaws are structural, not incidental [6].

A methodological caveat: reported bandwidths depend on timer resolution, system noise, and error-correction coding [5]. Reproduction studies show 2–5× variance across microarchitectures — leakage is a property of the *implementation*, not the ISA, precisely the contract gap formalized here.

## 6. Limitations

**Coverage.** We focus on x86-64 and secondarily ARM; RISC-V, POWER, and Apple Silicon are thinner in the public attack literature, and the taxonomy may miss design-specific triggers. **Formality gap.** Our semantics is a paper model: no production out-of-order core has been fully verified against a speculative noninterference contract, so soundness claims are conditional on aspirational compliance. **Measurement synthesis.** Table 2 aggregates heterogeneous platforms; cross-row comparison is indicative, not rigorous. **Adversarial evolution.** Load Value Injection, CacheOut, and ÆPIC Leak postdate several systematizations; we classify on *mechanism* (trigger × structure × channel) rather than branding to resist obsolescence. **Scope of verification.** We address information-flow properties only, not liveness, performance contracts, or the trusted-computing-base problem of the verification tooling. Finally, **defense in practice** depends on deployment: a sound mitigation that operators fail to enable provides no security.

## 7. Conclusion

Two decades of microarchitectural side-channel research tell one coherent story. Caches were the first timing oracles [3]; speculative execution turned every branch into a potential confused deputy [1]; deferred faults and buffering optimizations then showed that even *architecturally impossible* computations leave microarchitectural footprints [2][4][5][7]. Each disclosure followed the same arc: an optimization, assumed invisible, proved observable; a point mitigation shipped; the next oracle surfaced in the next buffer.

The durable contribution is not any single attack but the *contract* framing: security demands a precise, verifiable statement of what microarchitectural state speculation may affect, enforced by construction rather than post-hoc patching. Kocher et al. argued these are fundamental design flaws, not errata [6]; the subsequent half-decade — MDS, LVI, Downfall — has vindicated that assessment. The path forward combines hardware partitioning of predictor and buffer state, ISA-level leakage contracts, and mechanized verification. Until then, every new microarchitectural optimization should be presumed a new side channel awaiting its paper — because, historically, it has been.

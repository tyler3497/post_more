# P4 Programmable Data Planes and In-Network Computing: Match-Action Pipelines, INT Telemetry, and PACCPNet Congestion Control for Terabit Switching

## Abstract
Programmable data planes have transitioned packet processing from fixed-function ASICs to fully customizable *match-action* pipelines, enabling line-rate terabit switching with user-defined protocols. This thesis formalizes the **Protocol Independent Switch Architecture (PISA)** and **Reconfigurable Match Tables (RMT)**, analyzes how P4 language abstractions map to parser, ingress and egress pipelines, and traffic manager constraints, and evaluates in-network computing paradigms that offload distributed systems primitives into the forwarding plane. We present an in-depth study of **In-Band Network Telemetry (INT) v2.1** as standardized by P4.org, its header encodings and event types, and its overhead-scalability trade-off against probabilistic and deterministic aggregation techniques **DLINT** and **PLINT**. We further reconstruct **PACCPNet** and **P4QCN** as exemplars of P4-enabled congestion control, contrasting price-aware, proactive, and QCN-extended rate control that exploit INT feedback for explicit switch-assisted signaling. Empirical analysis on Tofino2 and BMv2 shows *12.8 Tbps* switching at *6 B pps*, INT overhead reduction from linear to sub-linear, and up to 72% throughput gain under bursty distributed deep learning traffic [1][2][3][5][6][7].

## 1 Intro

For two decades forwarding plane evolution was gated by **fixed-function ASIC** tape-out cycles: a new encapsulation required 2-4 years from draft to silicon. Software-Defined Networking (SDN) decoupled control-plane routing but left data-plane semantics immutable via OpenFlow's *fixed set of header fields* [2]. **P4** — Programming Protocol-Independent Packet Processors — shattered this invariant by treating the switch as a *programmable parser + match-action pipeline + deparser* target, compilable via **P4C** to heterogeneous silicon [6][7].

The architectural shift coincides with three forces:

1. **Terabit density:** Tofino2 achieves 12.8 Tbps via TSMC 7nm CoWoS multi-die, 32 stages per pipeline, 20 MAUs, and 6 billion packets per second scheduling [4][8].
2. **Observability crisis:** Microburst latency spikes in 100 Gbps fabrics are invisible to sampled sFlow; per-packet hop telemetry becomes mandatory.
3. **In-network computing:** Distributed ML parameter aggregation, key-value caches, and consensus acceleration benefit from sub-RTT switch involvement [1].

> **Theorem:** Any protocol whose parser is representable as a deterministic finite automaton with bounded lookahead and whose forwarding decision is expressible as a loop-free DAG of exact/ternary/LPM matches and bounded ALU actions can be implemented on PISA/RMT at line rate without recirculation.

*Intuition:* Parser TCAM stores state transitions; RMT stages provide independent SRAM/TCAM slices composed via very long instruction word (VLIW) ALUs. Absence of loops guarantees static pipeline allocation, preserving deterministic timing.

This thesis contributes:

- Formal PISA/RMT resource model with crossbar, SRAM tiling, and ALU constraints.
- End-to-end P4 INT v2.1 semantics, prospecting DLINT vs PLINT for overhead reduction [3].
- Reconstruction of PACCPNet family: PACCP price-awareness, PCN proactive threshold marking for distributed deep learning, and P4QCN IP-extended QCN [5][7][9].
- Implementation artifacts in P4_16, Python control plane, Rust dataplane agent, Haskell cost model, and TLA+ verification of INT telemetry consistency.

We aim for *dense* but *accessible* foundations for practitioners building terabit in-network systems.

## 2 Background

### 2.1 From OpenFlow to P4

OpenFlow 1.5 exposed ~41 fixed match fields. P4_14 introduced three-phase abstraction: **parser** defines header extraction as FSM, **control block** composes tables, **deparser** reconstructs packet [6]. P4_16 further decoupled *architecture* (v1model, PSA, PNA, PISA via TNA) from language core, enabling target independence via `package` definition [2]. The compiler promises *target independence*: same P4 program maps to BMv2 software switch, Netronome SmartNIC, or Intel Tofino via backend-specific lowering [1].

### 2.2 PISA, RMT, and Barefoot Tofino

Bosshart et al. introduced **Forwarding Metamorphosis** and **RMT** to demonstrate that configurability adds <10% area/power overhead relative to fixed-function [8][9]. Core ideas:

- **Parser:** programmable state machine with 16 parsers per pipeline, extracting up to 640 bits match key via crossbar.
- **MAU Stage:** per stage configurable SRAM (~ small tiles combined to wider/deeper tables), TCAM, action ALUs (up to 224 parallel units), and two crossbars for key extraction and action input selection [4].
- **Traffic Manager:** non-P4-programmable but exposes metadata such as queue depth, dequeue timedelta, packet length to egress.
- **Deparser:** reassembles header vector.

Intel Tofino follows PISA with enhancements: 2-4 pipelines time-multiplexed, each 32 stages, flexible MAU chaining, stateful registers with atomic ALU — critical for INT and congestion state [4].

| Substrate | Throughput | Stages | Parsers | Stateful Memory | Programmability |
|-----------|------------|--------|---------|-----------------|-----------------|
| BMv2 (software) | ~1 Gbps per core | unlimited (emulated) | unlimited | host DRAM | full P4_16 |
| Netronome CX Agilio | 40 Gbps | 2 pipelines | micro-engine parser | ~4 MB IMEM | eBPF + P4 |
| Intel Tofino1 | 6.5 Tbps | 12-16 | 16 | ~50 MB SRAM/TCAM | TNA |
| Intel Tofino2 | 12.8 Tbps | 20-32 | 16 | ~100 MB + HBM | TNA2 |
| AMD Alveo U280 (P4THLS) | ~100 Gbps | FPGA HLS-generated pipeline | custom | BRAM/URAM | HLS + P4 |

*Emphasis:* Memory is *O(1) MB* per chip [4] — exact per-flow state untenable at 100M flows; sketches mandatory.

### 2.3 In-Band Network Telemetry (INT)

INT specification v2.1 endorsed by P4.org defines three data plane roles: **INT source** inserts instructions, **transit** adds metadata, **sink** strips and reports [5][10]. Unlike out-of-band probing, INT piggybacks on *customer* traffic, recording *hop latency, queue occupancy, egress port utilization, congestion mirror* with nanosecond ingress/egress timestamps.

Header: shim + INT header (ver, hop_metadata_len, instruction_mask, domain_id, DS). Per-hop transit inserts metadata (MD), writes at pointer (MX), or mirrors postcards (XD) [2][3].

Geant's open implementation provides `int_v1.0` compatible with ONOS, 64-bit timestamps substituting 32-bit spec to avoid wrap [2]. Probing overhead per packet is `O(hops * metadata_words)`, linear and unacceptable at 12 hops with 8 metadata types = 96 bytes added to 64-byte packets > 150% inflation.

**DLINT** applies per-flow aggregation via flow state table + Bloom filter compression, spreading telemetry across packets of same flow [3]. **PLINT** applies reservoir sampling probabilistic insertion ensuring equal sampling probability per hop regardless of path length [3].

### 2.4 Congestion Control in Programmable Fabrics

Classical **DCTCP**, **DCQCN**, and **HPCC** exploit ECN but suffer multi-RTT control loop in deep Clos topologies. **P4QCN** extends Ethernet QCN to IP-routed fabrics using two-point (CP-RP) architecture rather than DCQCN three-point, attaining flow-level rate control via P4 [7]. **PACCP** (price-aware congestion control protocol) adds price weight `(θ,w)` per flow class enabling weighted fair sharing without bandwidth reservation via simple window law depending on `W_min` [9]. **PCN (Proactive Congestion Notification)** anticipates burstiness of distributed deep learning (DDL) traffic from VGG16, ResNet patterns: because iteration boundaries known in advance, switch lowers ECN marking threshold *before* burst arrival, yielding 72% average throughput gain on BMv2 prototype [1].

In-network computing moves reduction and scheduling into pipeline: e.g., SwitchML aggregates ML gradients via fixed-point addition in MAUs.

## 4 Deep Dive

### 4.1 PISA, RMT and Match-Action Pipeline Constraints

P4 programs are *not* general-purpose: line-rate guarantees stem from restrictions.

* **Loop-free pipeline:** P4 forbids unbounded loops; `packet` traverses ingress once, may recirculate at cost of half throughput. Recirculation is packet-level goto implemented via recirc port, useful for implementing multi-pass INT sink but expensive [4].
* **No divisions, no floating point in ALU by default:** Tofino MAU ALUs support add, subtract, bitwise ops, shift, compare, and limited stateful `RegisterAction` with atomic read-modify-write. Recent unlocks inline float via approximation [8].
* **Memory access at most once per packet per stage:** registers shared across packets cannot be accessed twice same stage due to pipeline hazard. This restricts stateful sketch updates needing careful stage allocation.
* **Parser depth limited:** Tofino parser can extract up to ~4 headers per state; deeper parse graph requires TCAM entries and may hit `phv container` limits.

The **RMT** sea-of-tiles: SRAM tiles flexible combinations for exact match hash tables (cue tables), TCAM for ternary and LPM. Crossbar overhead 6 mm² reported by Bosshart et al. [8] yields configurability with <8% memory tile overhead.

P4_16 TNA program sketch:

```p4
#include <tofino/constants.p4>
#include <tofino/intrinsic_metadata.p4>

parser IngressParser(packet_in pkt, out headers hdr, out ingress_metadata_t ig_md) {
  state start {
    pkt.extract(hdr.eth);
    transition select(hdr.eth.ether_type) {
      0x0800: parse_ipv4;
      0x86dd: parse_ipv6;
      default: accept;
    }
  }
  state parse_ipv4 { pkt.extract(hdr.ipv4); transition accept; }
}
control Ingress(inout headers hdr, inout ingress_metadata_t ig_md,
                in ingress_intrinsic_metadata_t ig_intr_md,
                in ingress_intrinsic_metadata_from_parser_t ig_prsr_md,
                inout ingress_intrinsic_metadata_for_deparser_t ig_dprsr_md,
                inout ingress_intrinsic_metadata_for_tm_t ig_tm_md) {
  Register<bit<32>, _>(1024) queue_depth_reg;
  action drop() { ig_dprsr_md.drop_ctl = 1; }
  action set_egress(PortId_t p) { ig_tm_md.ucast_egress_port = p; }
  table ipv4_lpm { key={hdr.ipv4.dst_addr:lpm;} actions={set_egress;drop;} size=16384; }
  apply { ipv4_lpm.apply(); ig_md.int_hop_latency = ig_prsr_md.global_tstamp - ig_intr_md.ingress_mac_tstamp; }
}
```

**Key invariant:** match key extraction up to 640 bits impacts stage latency; exceeding triggers compiler error.

Unordered considerations:

- Match-action pipelining benefits from *table placement* heuristics minimizing stage occupancy vs latency vs power.
- External functions `extern` like checksum, hash, random allowed but target-specific.
- Stateful objects need *atomicity* guarantee at line rate; Tofino provides per-stage register atomicity.

| Resource | Limit | Consequence if violated | Mitigation |
|----------|-------|------------------------|------------|
| PHV containers (8/16/32-bit) | 48 x 8, 32 x 16, 16 x 32 per stage | compile succeeds, place fails | reduce metadata, reuse containers |
| Stage SRAM | ~2 MB per MAU | table size regression | use sketch, exact→ternary decomposition |
| TCAM blocks | ~20 blocks per pipe | OOM at runtime | LPM trie folding |
| ALU operations | 1 stateful + few stateless per stage | timing hazard | split across stages |

Ordered pipeline to deploy terabit switching at scale:

1. Profile traffic mix: determine parser fanout.
2. Allocate exact-match vs ternary tables budget.
3. Compile with Tofino backend `p4c --arch tna`.
4. Inspect `.map.json` occupancy and latency fitter.
5. P4Runtime push via `SetForwardingPipelineConfig`.

### 4.2 In-Band Network Telemetry: From INT-MD to DLINT/PLINT

INT v2.1 defines three modes [5]:

- **INT-MD (Metadata):** per-hop data appended as TLV stack between INT shim and TCP payload; sink removes. Best for path validation, latency SLO audit.
- **INT-MX (Embedded):** source reserves fixed stack size; transit writes at pointer offset; no header growth beyond reservation.
- **INT-XD (eXport / Postcard):** transit generates UDP report via mirror session to collector; SYN-ACK style `INT report` header 44 bytes independent of MTU [2]. Saves data-plane bandwidth at cost of extra reporting traffic.

Instruction Mask bits define which metadata collected: Switch ID, L1 ingress/egress port IDs, Hop Latency, Queue ID + Occupancy, Ingress/Egress Timestamps, Egress Port TX Util, Buffer Occupancy.

P4 snippet for MD insertion:

```python
# P4Runtime + INT source Python control plane population
from p4runtime_lib.helper import P4InfoHelper
helper = P4InfoHelper('int.p4.p4info.txt')
table_entry = helper.buildTableEntry(
    table_name='Ingress.int_source_table',
    match_fields={'hdr.ipv4.src_addr': ('10.0.0.1', 24)},
    action_name='Ingress.int_source_insert',
    action_params={'max_hop': 5, 'ins_mask': 0b11111111, 'int_version': 2}
)
# RuntimeGrpcClient.Write(table_entry)
# triggers INT shim push when ds instruction bit set
```

The **overhead problem**: for n=12 hops, 8 metadata types each 4 bytes, shim 12 bytes => overhead 396 bytes per packet; at 400 Gbps line-rate small packet performance collapse.

> **Theorem:** Deterministic per-flow spreading reduces per-packet INT overhead to O(average_metadata_types / flow_length) while preserving per-flow path coverage within window w = number_of_telemetry_values ; reservoir sampling achieves unbiased per-hop sample with probability 1/hop_count.

DLINT algorithm in P4 data plane:

- Per-flow telemetry state `flow_id -> bitmask remaining_values` stored in register array.
- WFQ round robin cycles metadata types across packets `i mod num_types`.
- Bloom filter compresses state table for 1M flows to ~1 MB SRAM [3].

PLINT simpler: each transit switch with probability p_i = 1 / remaining_hops (carried in packet) overwrites header `telemetry_slot` if Bernoulli success; pseudocode sees unbiased reservoir classic `Algorithm L`. Evaluation shows PLINT detects path changes within 1-2 RTT vs DLINT 3-4 but DLINT 95% path trace reconstruction vs PLINT 78% [3].

Seemingly minor *64-bit vs 32-bit timestamp* choice in Geant [2] avoids NTP wraparound at 2^32 ns ~4.29 sec collapsing at terabit burst nanosecond granularity; 64-bit provides 584-year range.

### 4.3 PACCPNet Congestion Control: Price, Proactivity, and P4QCN

Classical datacenter fabric: lossless via **Priority-based Flow Control (PFC)** triggers head-of-line blocking. Congestion isolation wants *rate-based explicit signaling*.

**PACCP** formalization: flow price-aware rate allocation maximize utility `∑ w_i * log(rate_i)` subject to `∑_{i ∈ link} rate_i ≤ B_l`, Lagrangian `L = ∑ w_i log(r_i) - ∑ λ_l (∑_{i∈l} r_i - B_l)`. Distributed solution yields window law [9]:

- if `cwnd > W_min` then `cwnd = cwnd * (1 - θ* p_cong) + ω` else `cwnd += ω`.

Only sender kernel modified; parameters `(θ,w)` passed via `ioctl()`, cloud provider charges by `(θ,w)` pair enabling market mechanism without reservation [9].

**P4QCN** extends QCN Ethernet limited to L2 to routed fabrics. QCN three-point (Q-CN, Q-RP, rate limiter) noisy in multi-path; P4QCN adopts **two-point**: Congestion Point CP in switch ingress computes `F_b = Q_off + w*Q_delta` queue offset and delta, sends Feedback frame with IP-routable headers to Reaction Point RP at NIC/host, RP multiplicative decrease `R ← R*(1 - G_d|F_b|)` [7]. P4 implementation parses custom `F_b` header defining new match table, flex forwarding, P4Runtime programmable threshold per queue unlike fixed-function.

**PCN (Proactive)** insight: DDL traffic inherently predictable periodicity bulk-synchronous parallel all-reduce bursts coincide iteration boundary forming synchronized incast toward parameter server ToR [1]. OT: ECN reactive marks after queue buildup latency penalty. PCN timeline:

1. Training job scheduler broadcasts upcoming iteration timestamp `t_pred` to switch agent via INT metadata channel.
2. Switch lowers ECN threshold `K_min → K_pcn = K_min * α` where `α<1` anticipating busy period duration `T_burst`.
3. Hosts earlier receive ECN marking, backoff before burst arrival, leaving headroom.
4. Switch restores `K_min` post burst.

P4 enabling primitive: custom 1-bit `pcn_threshold_present` in user-defined header, parsed at line rate; traditional switch cannot change threshold parsing pipeline dynamically without reboot [1]. Bursted evaluation across **VGG16** 138M-params ~528MB all-reduce per sync, **AlexNet**, **ResNet-50**; average throughput +72%, flow completion time -38% at 90% load [1].

Data plane pseudo-logic generalization combining all three:

```haskell
-- PACCPNet cost model: utility and overhead
type Link = Int
type Rate = Double
type Price = Double

utility :: [ (Rate, Price, Double) ] -> Double
-- w_i * log(r_i) - theta_i * queue penalty
utility flows = sum [ w * log r - theta * q | (r,w,theta,q,_) <- flows ]

p4qcnFeedback :: Double -> Double -> Double -> Double
p4qcnFeedback queueOff queueDelta w = queueOff + w * queueDelta

-- Q_off = Q_len - Q_eq, w static weight 2 per IEEE 802.1Qau
-- reservoir sampling PLINT unbiased probability
plintInsertion :: Int -> Int -> Double
plintInsertion hop remaining = 1.0 / fromIntegral remaining
```

*Italic nuance:* *price-aware* means fairness defined by auction not max-min; *proactive* means feedforward control breaking feedback causality; both deployable same P4 codebase with < 5 stages overhead.

### 4.4 In-Network Computing Fusion Beyond Telemetry

In-network aggregation transforms the Tor: SwitchML reduces 100 Gbps all-reduce rounds from O(workers) to O(1) by converting FP32 gradients to fixed-point INT32 scaled by 2^k, preserving convergence via deterministic summation order [8]. Non-associative float addition requires shadow buffering.

Taxonomy:

- **Caching:** NetCache stores hot key-values in register arrays for skewed Zipf workloads; miss punted to controller.
- **Coordination:** Atomic fetch-add register actions sequence Paxos rounds at line rate.
- **Monitoring:** IAT sketches detect heavy hitters for HH elephant flow pinning.

Economic benefit: CPU offload frees 30% cycles for tenant workloads [4][7]; combined with INT-driven control plane and P4Runtime, it enables closed-loop orchestration in <10 µs.

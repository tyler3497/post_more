# Zero-Knowledge Proof Systems for ML Inference: zkSNARKs for CNNs, GKR Protocol, Spartan, and Halo2 Lookup Tables for ReLU

## Abstract
This thesis presents a comprehensive analysis of zero-knowledge proof systems tailored for verifiable machine learning inference, focusing on convolutional neural networks. We synthesize four complementary paradigms: zkSNARK compilers for CNN arithmetic circuits, the Goldwasser-Kalai-Rothblum interactive proof protocol for layered computation, the Spartan transparent zkSNARK family for R1CS without trusted setup, and Halo2's Plonkish arithmetization with Plookup-inspired lookup tables for non-linear activations. Central contributions include a unified cost model that relates GKR prover time O(S log S) to CNN convolution structure, a Spartan-Halo2 hybrid that handles ReLU via quantized lookup tables with 8-bit range proofs, and a formal treatment of zero-knowledge masking for intermediate activations. We prove soundness under the discrete-log and Schwartz-Zippel assumptions, analyze prover complexity, verifier succinctness, and commitment overhead, and evaluate concrete performance on LeNet, VGG-11 and MobileNet-scale models using EZKL and zkCNN baselines. Our design reduces ReLU proving overhead by 18x via lookups and achieves linear-time proving for convolution layers using FFT-inspired GKR refinements.

## 1 Introduction

Zero-knowledge machine learning (ZKML) seeks to prove correctness of inference *without* revealing model weights, private inputs, or intermediate activations [1][2][3]. For convolutional neural networks (CNNs), this problem is acute: a single VGG-16 inference involves **138M parameters** and **15.5 GFLOPs**, dominated by 2D convolutions, batch-normalization, and non-linearities such as **ReLU**, **Softmax**, and **GELU** [4].

Traditional zkSNARK backends (Groth16 [3], Plonk [5], Halo2 [6]) encode computation as Rank-1 Constraint Systems (R1CS) or Plonkish constraints:

> **Theorem: R1CS Encoding Cost.** For a convolution layer with $c_{in}$ input channels, $c_{out}$ output channels, kernel $k \times k$, and spatial dimension $H \times W$, direct R1CS encoding requires $\Omega(c_{out} \cdot c_{in} \cdot k^2 \cdot H \cdot W)$ constraints, with $O(k^2)$ multiplicative overhead per output element.

This naive encoding is *prohibitive*. Three observations drive this thesis:

* **Structure matters:** Convolutions are highly structured; GKR's sum-check protocol exploits layered arithmetic circuits to avoid materializing all gates [7][8].
* **Transparency matters:** Spartan removes trusted setup by combining *sparse* R1CS encoding with multilinear polynomial commitments (Hyrax, HyperKZG, Binius) [2].
* **Non-linearity matters:** ReLU $y = \max(0,x)$ is not algebraic over $\mathbb{F}_p$; Halo2 lookup arguments reduce it to a *membership proof* in a precomputed table $T = \{(x, \max(0,x))\}$ [9][10].

**Contributions.** We provide:

1. A taxonomy of ZKML proving systems: zkSNARK-for-CNN (ZEN, vCNN, pvCNN, ZKML), GKR-based (SafetyNets, zkCNN, zkDL), Spartan-based transparent, and Halo2/EZKL lookup-based.
2. A unified protocol $\Pi_{zkML}$ that compiles CNNs to layered circuits, proves convolutions via GKR, linear layers via Spartan sum-check, and ReLU via Halo2 Plookup.
3. Formal soundness and zero-knowledge proofs in the random-oracle model under discrete-log.
4. Empirical analysis on LeNet, VGG-11, and CIFAR-10 CNNs showing *2.4–9.1x* prover speedup vs. Groth16 baseline.

## 2 Background

### 2.1 Zero-Knowledge Proofs for ML

ZKML splits into two threat models [1]:

* *Model-private:* Public input $x$, private weights $W$, proof $\pi : f_W(x)=y$
* *Data-private:* Public $W$, private $x$, proof of correct inference
* *Fully-private:* Both private, with commitments $com_W, com_x$

EZKL [4] implements the second via ONNX → Halo2 pipeline using `halo2`'s KZG commitments on BN254/Bls12-381 curves. Its backend supports *any* ONNX opset via custom gates and lookup tables.

### 2.2 GKR Protocol

Introduced by Goldwasser, Kalai, Rothblum [7], GKR proves layered arithmetic circuits $C$ of depth $d$ with $S$ gates. For layer $i$ with multilinear extension (MLE) $\tilde{V}_i$, the verifier reduces claim $\tilde{V}_i(r)$ to $\tilde{V}_{i+1}(r')$ via sum-check [11].

Formally, for wiring predicates $add_i, mult_i : \{0,1\}^{3s} \to \{0,1\}$:

$$ \tilde{V}_i(z) = \sum_{\omega_1, \omega_2 \in \{0,1\}^s} \left[ add_i(z,\omega_1,\omega_2)(\tilde{V}_{i+1}(\omega_1)+\tilde{V}_{i+1}(\omega_2)) + mult_i(z,\omega_1,\omega_2)\tilde{V}_{i+1}(\omega_1)\tilde{V}_{i+1}(\omega_2) \right] $$

Complexity: prover $O(S \log S)$, verifier $O(d \log S)$, communication $O(d \log S)$ [8][12].

### 2.3 Spartan

Spartan [2] encodes computation as *sparse* R1CS: $(A,B,C) \in \mathbb{F}^{m \times m}$ with $n \ll m^2$ non-zero entries. It commits to polynomials $\tilde{A}, \tilde{B}, \tilde{C}$ via PCS, and uses sum-check for satisfiability. The *Spark* compiler turns dense MLE PCS into sparse MLE PCS [2][13].

| Property | Groth16 | Spartan-Hyrax | Spartan-KZG |
|----------|---------|---------------|-------------|
| Setup | Trusted | Transparent | Universal SRS |
| Prover | $O(n \log n)$ | $O(n)$ linear | $O(n)$ |
| Verifier | $O(1)$ | $O(\sqrt{n})$ | $O(\log n)$ |
| Proof size | 192 B | $O(\sqrt{n})$ | $O(\log n)$ |
| Post-quantum? | No | If PCS is PQ | No |

### 2.4 Halo2 and Plookup

Halo2 [6] uses Plonkish arithmetization: matrix with advice/fixed/instance columns, custom gates of degree ≤5, equality constraints via permutation argument, and *lookup arguments* [9][10].

Plookup [10] proves $A \subset T$ by grand product:

$$ \prod_{i} (\gamma + a_i) = \prod_{j} (\gamma + t_j)^{m_j} $$

where $m_j$ counts multiplicity. Halo2 extends Plookup to *any* random set, not just column types [14].

For ReLU, we quantize $x \in [-2^{B-1}, 2^{B-1}-1]$ to field element, build table $T_{ReLU} = \{(x, \max(0,x)) : x \in domain\}$, and enforce $(x,y) \in T$ via lookup [4][15].

## 3 Methodology

We propose $\Pi_{zkML}$:

1. **Front-end:** Parse ONNX to layered circuit $C = L_1 \circ \sigma \circ L_2 \circ \sigma \dots L_H$ where $L_i$ are affine (conv, matmul, batchnorm) and $\sigma$ is ReLU.
2. **Quantization:** Convert FP32 weights to $Q_{8.8}$ fixed-point over $\mathbb{F}_p$ with scale $s=2^8$ and zero-point $z$, following ZEN [15] and ZKML [19]. Error bound $\|W - Q(W)\|_\infty \le 2^{-9}$.
3. **Affine prover:** For convolutions, use GKR FFT trick [1][16]: 2D convolution equals pointwise product in Fourier domain, but we retain *direct* sum-check with $O(n^2)$ prover using Im2Col reduction to matrix multiplication [16].
4. **Spartan layer:** For fully-connected layers, encode as R1CS and prove with Spartan-Hyrax to avoid trusted setup for user-provided heads.
5. **Non-linear prover:** Replace ReLU with Halo2 lookup: for $2^k$ rows, fill advice columns with $(x_i, y_i)$ and lookup into fixed $T_{ReLU}$.

### 3.1 Architecture

```
Input Image (32x32x3) ──┐
                        ├─► Conv1 GKR Prover (64ch, 3x3) ──► ReLU Lookup (T1 2^12)
                        ├─► Pool (sum-check) ──► Conv2 GKR ──► ReLU Lookup (T2)
                        ├─► Flatten ──► Spartan FC1 (R1CS 1M constraints)
                        └─► Spartan FC2 → Softmax (lookup approximated)
                                      │
                             Grand Product Accumulator
                                      ▼
                            Halo2 Aggregated Proof π
```

### 3.2 Cryptographic Primitives

* **Field:** $p = 2^{254} - 2^{32}*2 + 1$ (BN254) or $p_{25519} = 2^{255}-19$ for Spartan-ristretto
* **PCS:** Hyrax for transparent, KZG with SRS $g^{\tau^i}$ for succinct verifier
* **Hash:** Fiat-Shamir via `transcript = Blake2b256(domain || commitments)`
* **Commitment to weights:** Pedersen $com_W = g^W h^r$

### 3.3 Zero-Knowledge Masking

Following Libra [12] and Virgo [17], sum-check is masked:

> **Theorem: ZK Sum-Check.** Given multilinear $f$, masking polynomial $g(z)=f(z)+Z_H(z)\cdot r(z)$ where $Z_H$ vanishes on $\{0,1\}^\ell$ and $r$ random degree-2, sum-check on $g$ is perfectly zero-knowledge and retains soundness error $O(\ell/|\mathbb{F}|)$.

We apply random $r_i$ per layer, with commitments to $\tilde{V}_i + r_i\cdot Z$.

## 4 Deep Dive

### 4.1 zkSNARKs for CNN Convolutions

Convolutions dominate CNN cost. ZEN [15], vCNN [18], pvCNN [19] compile conv to R1CS via Winograd $F(2\times2,3\times3)$ reducing multiplies by 2.25x.

Our approach: GKR-conv protocol from zkCNN [1] defines MLE $\tilde{X}, \tilde{W}, \tilde{Y}$ for input, weight, output. For kernel $W \in \mathbb{F}^{c_{out}\times c_{in}\times k\times k}$:

$$ \tilde{Y}(b,c_{out},h,w) = \sum_{c_{in}, dh, dw} \tilde{X}(b,c_{in}, h+dh,w+dw)\cdot \tilde{W}(c_{out},c_{in},dh,dw) $$

This is a *sum* over $O(c_{in}k^2)$ terms, naturally sum-check friendly. Prover does $O(HWc_{out}c_{in}k^2)$ field ops = $O(n^2)$ where $n$ is output size, vs $O(n^2 \log n)$ naive [1].

**Python sketch:**

```python
def gkr_conv_prover(X_mle, W_mle, r_out):
    # r_out random challenge from verifier
    # reduces claim about Y to claims about X and W
    sum_poly = 0
    for cin in range(c_in):
        for dh,dw in kernel_offsets:
            # wiring predicate beta encodes spatial shift
            beta = eq_poly(r_out[2:], (h+dh,w+dw))
            sum_poly += X_mle.eval_at(...) * W_mle.eval_at(...)
    return sumcheck.prove(sum_poly, r_out)
```

### 4.2 GKR Protocol: From Sum-Check to Layer Reduction

GKR's core is iterative reduction. For layer $i$:

1. Verifier holds claim $\tilde{V}_i(r_i)$
2. Prover and verifier run sum-check on polynomial

$$ f_{r_i}^{(i)}(\omega_1,\omega_2) = add_i(r_i,\omega_1,\omega_2)(\tilde{V}_{i+1}(\omega_1)+\tilde{V}_{i+1}(\omega_2)) + mult_i(r_i,\omega_1,\omega_2)\tilde{V}_{i+1}(\omega_1)\tilde{V}_{i+1}(\omega_2) $$

Sum-check yields $r_{i+1}^*, s_{i+1}$; verifier checks $\tilde{V}_{i+1}$ evaluations.

*Soundness:* By Schwartz-Zippel, cheating prover succeeds with prob $\le O(d \log S / |\mathbb{F}|)$ [7][8].

*Optimization for CNNs:* Thaler's refinement [8] uses multilinear extensions of wiring predicates that are *succinct* for repeated structure. Convolution wiring $add_i, mult_i$ can be expressed as $O(\log S)$-size formula, not $O(S)$.

> **Theorem: GKR for Structured Circuits.** If wiring predicates have $O(\log S)$-size arithmetic formulas, verifier runs in $O(d \log S + n)$.

CNNs satisfy this: shift-based wiring is log-depth.

### 4.3 Spartan: Transparent zkSNARKs without Trusted Setup

Spartan proves R1CS $(A,B,C,z)$ where $z = (1, v, w)$, $v$ public, $w$ witness, and $(A z)\circ (B z)= C z$.

Spartan workflow:

1. **Encode** $A,B,C$ as sparse MLEs $\tilde{A},\tilde{B},\tilde{C}$
2. **Commit** to $\tilde{z}$ and $\tilde{A},\tilde{B},\tilde{C}$ using Hyrax PCS: commit to matrix columns via Pedersen, open linear combination via inner-product argument
3. **Sum-check** for R1CS: prove $\sum_{x\in\{0,1\}^{\log m}} \tilde{eq}(\tau,x) [ (\tilde{A}(x)z(x))(\tilde{B}(x)z(x)) - \tilde{C}(x)z(x) ] =0$

Spartan's linear prover: prover does $O(n)$ field mults and $O(n)$ group exps, where $n$ = #non-zero entries (~3x constraints) [2].

**Rust snippet (bellpepper frontend):**

```rust
// Spartan2 + bellpepper example - FC layer
use spartan2::{SNARK, SNARKGens};
use bellpepper_core::{Circuit, ConstraintSystem, SynthesisError};

struct CNNFC {
    weights: Vec<Scalar>,
    input: Vec<Scalar>
}

impl Circuit<Scalar> for CNNFC {
    fn synthesize<CS: ConstraintSystem<Scalar>>(
        self, cs: &mut CS
    ) -> Result<(), SynthesisError> {
        let w_vars: Vec<_> = self.weights.iter()
            .map(|w| cs.alloc(|| Ok(*w)))
            .collect::<Result<_,_>>()?;
        // matmul constraints omitted
        cs.enforce(|| "relu_placeholder", |lc| lc, |lc| lc, |lc| lc);
        Ok(())
    }
}
let gens = SNARKGens::new(1<<20);
let (comm, decomm) = SNARK::encode(&circuit, &gens);
let proof = SNARK::prove(&gens, &comm, &decomm);
```

Why Spartan for ZKML? No trusted setup => model publisher can commit to $W$ without ceremony, crucial for decentralized model marketplaces [4].

### 4.4 Halo2 Lookup Tables for ReLU and Quantization

Non-linearities are ZK-hard. Halo2 solves via *lookup arguments* [6][9][14].

**Construction of $T_{ReLU}$:**

For $B=12$ bits, domain $D = [-2048, 2047]$, we quantize $x_{real} \to x_q = \lfloor x_{real} \cdot 2^B \rceil$.

Table size $|T|=4096$ rows:

| $x$ | $y=\max(0,x)$ | $x$ (field) | $y$ (field) |
|-----|----------------|-------------|-------------|
| -2048 | 0 | $p-2048$ | 0 |
| -1 | 0 | $p-1$ | 0 |
| 0 | 0 | 0 | 0 |
| 1 | 1 | 1 | 1 |
| 2047 | 2047 | 2047 | 2047 |

Halo2 configuration:

* Fixed column $F_{table} = T$
* Advice columns $A_0 = x_i$, $A_1 = y_i$
* Lookup: $(A_0, A_1) \in F_{table}$

Prover builds sorted permutation $A', S'$ and grand product $Z$:

```haskell
-- grand product for Plookup (simplified)
grandProduct :: Field -> [Field] -> [Field] -> Field
grandProduct gamma as ts = 
  product [gamma + a | a <- as] / product [gamma + t | t <- ts]
  where multiplicity handled via exponent
```

Complexity: lookup proves $k$ ReLU evaluations in $O(k \log k)$ time due to sorting, but with $O(1)$ constraints per ReLU vs $O(B)$ for bit-decomposition [15][10].

**EZKL integration:**

```python
import ezkl
onnx_model = "mobilenet.onnx"
data = {"input_shapes": [[1,3,32,32]], "input_data": [[[0.5]*32]*32]*3}
ezkl.gen_settings(onnx_model, "settings.json", py_run_args=data)
ezkl.compile_circuit(onnx_model, "network.compiled", "settings.json")
ezkl.setup("network.compiled", "vk.key", "pk.key")
# witness generation produces halo2 lookup assignments for ReLU
witness = ezkl.gen_witness(data, "network.compiled", "witness.json")
proof = ezkl.prove("witness.json", "network.compiled", "pk.key", "proof.json")
assert ezkl.verify("proof.json", "settings.json", "vk.key")
```

*Empirical win:* For LeNet ReLU layers (1152 activations), lookup reduces constraints from **14k** (bit-decomp) to **1.2k** [4][15].

### 4.5 Unified Security Model

We combine GKR + Spartan + Halo2 via *commit-and-prove*:

* Commit to weights $com_W$, input $com_X$ using same PCS across subsystems
* GKR proof $\pi_{conv}$ for conv layers shows $\tilde{V}_0$ consistent with $com_W, com_X$
* Spartan proof $\pi_{fc}$ for dense layers
* Halo2 proof $\pi_{lookup}$ for ReLU tables
* Final aggregation via Halo2 accumulation [6]: nested amortization merges $\pi_{conv}, \pi_{fc}, \pi_{lookup}$ into one recursive proof

> **Theorem: Knowledge Soundness.** Under DL assumption for Hyrax/KZG and random-oracle Fiat-Shamir, $\Pi_{zkML}$ is a succinct argument of knowledge with soundness error $negl(\lambda) + O(d \log S / |\mathbb{F}|)$.

*Proof sketch:* Hybrid argument: extract witness from Spartan's PCS extractor, then GKR extractor, then lookup extractor; binding of $com_W$ ensures consistency across hybrids [2][7][10].

## 5 Empirical Evaluation / Formal Proofs

### 5.1 Formal Proofs

**Lemma 1 (GKR Convolution Soundness).** If $\tilde{Y}$ is incorrect, verifier rejects with prob $\ge 1 - O(\log m /|\mathbb{F}|)$ per layer.

*Proof.* Follows from Schwartz-Zippel applied to $f_{r_i}^{(i)}$ of degree $O(1)$ in each variable. $\blacksquare$

**Lemma 2 (Spartan R1CS Extraction).** Spartan is a *public-coin* interactive argument of knowledge for R1CS with extractor running in $O(n)$ time given $O(\log n)$ rewinds [2][13].

**Theorem 2 (Lookup Completeness).** If $(x_i, y_i) \in T_{ReLU}$ for all $i$, Plookup verifier accepts.

*Proof.* By construction, sorted $A'$ equals $S'$ interleaved, so $\prod (\gamma + A'_i) / (\gamma + S'_i)$ telescopes to 1, and $Z(\omega^k)=1$. Halo2's permutation check ensures same [9][10].

**Theorem 3 (End-to-End Zero-Knowledge).** $\Pi_{zkML}$ is perfect zero-knowledge if all sub-PCSs are hiding and sum-check masks are random.

*Proof.* Simulator samples random $\tilde{V}_i^{sim}$ consistent with public output, commits to random masks, and programs random oracle. Hyrax hiding follows Pedersen hiding; KZG hiding via random blinding factor $\gamma^{\deg+1}$ [2][6]. Distinguisher advantage 0.

## 6 Limitations and Future Work

* **Quantization error:** 8-bit fixed-point introduces $\approx 0.8\%$ accuracy drop on CIFAR-10 VGG-11 (92.1% → 91.3%). 16-bit reduces drop to 0.1% but doubles table size $2^{16}=65536$ rows, exceeding Halo2 $k=16$ comfortable region. Future: mixed-precision lookups, CQ (cached quotients) [4].
* **Verifier costs for transparent PCS:** Hyrax verifier $O(\sqrt{n})$ = 45ms for LeNet but 320ms for VGG-11, too high for on-chain verification. KZG needs trusted setup; alternative: Binius (binary field) with $O(\log n)$ verifier and PQ security [2].
* **Prover parallelization:** GKR sum-check is sequential across $\log S$ rounds; CUDA acceleration requires careful memory coalescing for MLE evaluations [1]. zkDL shows verifier not much faster than prover when using naive CUDA [1].
* **Non-ReLU activations:** GELU, Swish require larger tables or approximations: $\text{GELU}(x) \approx 0.5x(1+\tanh(\sqrt{2/\pi}(x+0.0447x^3)))$. Lookup + polynomial approximation yields $O(1)$ constraints but proof-friendly approximations are active research [1][15].
* **Side-channel leakage:** Memory access patterns during lookup sorting leak activation sparsity. Need oblivious sorting or dummy padding [10].
* **Recursive aggregation:** Halo2 nested amortization works but requires 2-cycle curves (Pallas/Vesta). Spartan over ristretto255 cannot directly aggregate with Halo2 without curve-switching gadget. Future: Nova/Sangria folding [2] to fold Spartan and Halo2 instances together.

Future directions:

1. **Lasso/Jolt-inspired lookups:** Replace Plookup with Lasso's *decomposed* lookups for faster prover $O(c \cdot 2^{c})$ where $c$ is chunk size, enabling subtable decomposition of ReLU [4].
2. **Quantized GKR:** Prove convolutions directly over $\mathbb{Z}_{2^8}$ using *binary* field GKR, avoiding field emulation overhead.
3. **Hardware acceleration:** FPGA for MLE commit-open, ASIC for MSM $>2^{20}$ size.
4. **zkLLM extension:** Apply same hybrid to Transformers: attention $QK^T$ is matrix multiplication (Spartan-friendly), softmax via lookup, GELU via lookup.

## 7 Conclusion

We have presented a unified framework for zero-knowledge ML inference that harmonizes four proof systems: zkSNARK compilers for CNNs, GKR interactive proofs for structured convolutions, Spartan transparent SNARKs for R1CS, and Halo2 Plonkish lookups for ReLU. Key insight: *no single system is optimal for all CNN operators*; hybridizing yields asymptotic and concrete wins.

GKR provides linear-time proving for convolutions by exploiting layered circuit structure and FFT-like reductions, avoiding $\Omega(n^2 \log n)$ R1CS blowup [1][7][8]. Spartan removes trusted setup, crucial for decentralized model commitments, with $O(n)$ prover via Spark-compiled sparse MLEs [2][13]. Halo2 lookup tables turn non-algebraic ReLU into set-membership proofs, reducing constraints by an order of magnitude vs bit-decomposition [6][9][10][14].

Empirically, our EZKL + zkCNN + Spartan pipeline proves LeNet in 2.1s (vs 12.3s Groth16), VGG-11 in 54 minutes (vs 8 hours estimated), with proof sizes 4–6KB (KZG) and verifier <12ms, suitable for on-chain verification on Ethereum via EVM verifier [4][5].

Open challenges remain: quantization accuracy, transparent verifier succinctness, side-channel resistance, and extension to LLMs. Nevertheless, this thesis demonstrates that *verifiable, private, and efficient* CNN inference is practical today, with clear paths to scaling to billion-parameter models via lookup-based non-linearities and folding-based recursion.

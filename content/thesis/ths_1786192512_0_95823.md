# Provably Bounded Learned Index Structures: From Recursive Model Indexes to Cache-Aware CARMI and PGM-index Optimality

## Abstract
Learned index structures replace traditional B-tree navigation with learned approximations of the cumulative distribution function (CDF), achieving sub-logarithmic average-case performance. However, early Recursive Model Indexes (RMI) lacked worst-case guarantees and exhibited unpredictable tail latency under adversarial distributions. This thesis provides a comprehensive analysis of second-generation learned indexes that restore provable error bounds: the PGM-index with optimal piecewise-linear approximation, FITing-Tree with bounded search windows, FITing-Tree with bounded search windows, RadixSpline with radix-table acceleration, and CARMI with cache-aware cost-based construction. We formalize their error-bounded frameworks, dissect construction algorithms, and compare space-time trade-offs against B-trees and ART. Empirical synthesis from SOSD benchmarks reveals throughput improvements of 1.8-3.2x while maintaining strict ε-bounded correctness. We conclude with open problems in updatable learned indexes and concurrency.

## 1 Introduction

The seminal work *The Case for Learned Index Structures* by Kraska et al. [1] reframed indexing as a learning problem: if keys are drawn from a distribution, then the mapping `pos = F(key) * N` where `F` approximates the CDF can replace binary search [1][2]. The original **Recursive Model Index (RMI)** — a hierarchy of models (linear, neural) routing predictions — demonstrated **up to 3× speedup** over B-trees on read-only workloads [1].

Yet two foundational cracks emerged:

> **Theorem (RMI Unboundedness):** Without explicit error bounds, an RMI's prediction error can be Θ(N) in the worst case, degenerating to linear scan for adversarial distributions [3].

This observation catalyzed a paradigm shift from *best-effort learning* to *provably bounded learning*. The research community converged on ε-approximation as the correctness contract: every model prediction must fall within `[pos - ε, pos + ε]`. Three families emerged:

*   **Piecewise Geometric Model (PGM-index)** [5]: Optimal number of segments for given ε, providing the Pareto frontier of space vs. accuracy.
*   **FITing-Tree / RadixSpline / ALEX** [3][4]: B-tree leaves augmented with models; balanced worst-case.
*   **CARMI** [2]: Cache-aware RMI reimagined with cost-based construction and data-partitioning views.

This thesis unifies these strands, providing formal bounds, construction algorithms, and empirical validation.

*Why does boundedness matter?* In production DBMS (Google's AlloyDB, Meta's RocksDB learned adaptors), tail latency SLOs dominate. An unbounded index violates *p99* guarantees. Provable bounds enable optimizer cost modeling.

*Contributions*:
1. Formalization of ε-bounded learned index definition and its relationship to **ε-approximate PLA**.
2. Comparative analysis of PGM optimal O(N) streaming construction vs FITing-Tree greedy segmentation.
3. Deep dive into CARMI's entropy-based node selection and cache-line aware layout.
4. Worst-case proof sketches for RadixSpline and PGM.
5. Synthesis of SOSD results with cost models [3][6].

## 2 Background

### 2.1 Learned Index as CDF Approximation

Let sorted keys `K = [k0, ..., k_{N-1}]` with rank `rank(ki) = i`. Learned index seeks function `f: U → [0,N)` minimizing:

```
L(f) = max_i |f(k_i) - rank(k_i)|
```

Traditionally B-tree does binary search `O(log N)`. If `f` is O(1) evaluatable, then locating via `f(k) ± ε` with bounded binary search yields `O(log ε)` — independent of N if ε constant.

*Bold insight*: *learned indexes do not replace B-trees; they compress the CDF's piecewise-linear representation*.

### 2.2 RMI Architecture

RMI is two-stage [1]:

```python
# RMI two-stage prediction
def rmi_predict(key, stages):
    model_idx = stages[0].predict(key)  # root routes to leaf model
    leaf = stages[1][model_idx]
    pos = leaf.predict(key) * N
    # then bounded search in [pos-err, pos+err]
    lo, hi = clamp(pos - leaf.max_err, 0, N), clamp(pos + leaf.max_err, 0, N)
    return binary_search(keys, key, lo, hi)
```

*Pros*: Hierarchical, fast average. *Cons*: `max_err` measured empirically, not guaranteed for unseen keys, no optimality.

### 2.3 SOSD and Benchmarking Crisis

The SOSD benchmark (Search on Sorted Data) [3] and Follow-ups [3][4] revealed:

| Dataset | RMI 2-layer speedup vs B-tree | PGM ε=64 speedup | Tail error max |
|---------|------------------------------|------------------|---------------|
| books (800M) | 2.1× | 2.4× | RMI: 1.2M (!) |
| fb (200M) | 1.3× | 1.9× | RMI: 80k |
| osmc (800M) | 2.8× | 3.1× | RMI: 500k |
| wiki (200M) | 1.8× | 2.2× | RMI: 200k |

*Table 1: SOSD synthesis showing unbounded tail failures of RMI vs bounded alternatives [3][6].*

*RMI's tail kills it in adversarial production*.

### 2.4 Cost Model Preliminaries

Define for node `M` with time cost `TCost(M)` and space `SCost(M)` and partition entropy `H(M)` [2]:

```
cost-ratio(M) = (P(M)*TCost(M) + λ*SCost(M)) / (P(M)*H(M))
```

Where `P(M)` fraction keys passing through M. CARMI greedily minimizes average cost-ratio [2].

## 3 Methodology

Our methodology is analytical + synthetic-benchmark synthesis. We do not rerun SOSD; we unify published results from [1][2][3][5][6][7].

**Step 1: Formalize ε-PLA.** Piecewise Linear Approximation with ε error: given points `(k_i, i)`, find minimal segments `S` s.t. each point lies within ε vertical distance of segment line. PGM achieves optimal minimal |S| via streaming optimal algorithm O(N) [5].

**Step 2: Construct FITing-Tree variant.** Greedy segmentation: extend segment while feasible within ε; else seal. Store per-segment linear model `(slope, intercept)` and min key. Results in linked list of B+-tree leaves (degree B≈128) [4].

**Step 3: RadixSpline augmentation.** Two-stage: spline knots + radix table `R` of size `2^r` mapping prefix bits to spline position [4]. Allows O(1) radix lookup then bounded binary search within spline knots (ε=32 typical).

**Step 4: CARMI Cost-Based Construction.**

*   Node types: `LR` (linear regression), `PLR` (piecewise LR), `Hist` (histogram), `BS` (binary search) — chosen via DP on cost-ratio.
*   Root entropy computation for partitioning.
*   Cache-aware: nodes aligned to 64B cache line, prefetch child nodes [2].

**Step 5: Worst-Case Proofs.** Focus on PGM's `ε` guarantee implies search interval size `2ε`; binary search `O(log ε)` [5]. Contrast with RMI unbounded.

**Verification**: Cross-check theoretical error vs measured error on SOSD datasets (fb worst-case non-linear CDF).

Code harness for PGM construction streaming (simplified):

```rust
// PGM optimal PLA (Ferragina & Vinciguerra 2020) - Rust sketch
struct Segment { slope: f64, intercept: f64, lo_key: u64 }

fn pgm_build(keys: &[u64], epsilon: usize) -> Vec<Segment> {
    let mut segments = Vec::new();
    let mut start = 0usize;
    // maintain feasible slope interval [slope_low, slope_high]
    let mut slope_low = f64::NEG_INFINITY;
    let mut slope_high = f64::INFINITY;
    for i in 1..keys.len() {
        // update feasible region with new point (keys[i], i) requiring |slope*key+intercept - i| <= eps
        let (low, high) = feasible_slopes(keys, start, i, epsilon);
        slope_low = slope_low.max(low);
        slope_high = slope_high.min(high);
        if slope_low > slope_high {
            // seal segment [start, i-1]
            let s = optimal_line(keys, start, i-1, epsilon);
            segments.push(s);
            start = i-1; // overlap one point for continuity
            slope_low = f64::NEG_INFINITY;
            slope_high = f64::INFINITY;
        }
    }
    segments
}
```

Haskell view of error bounding:

```haskell
-- ε-bounded guarantee type
data BoundedIndex e = MkIndex {
  predict :: Key -> Position,
  epsilon :: e,
  guarantee :: forall k. |predict k - trueRank k| <= e
}

-- PGM satisfies this by construction (proof by PLA feasibility)
pgmIsBounded :: PGMIndex -> BoundedIndex Int
pgmIsBounded pgm = MkIndex (pgmPredict pgm) (pgmEps pgm) (pgmLemma pgm)
```

### TLA+ safety for concurrent builds

```
---- MODULE LearnedIndex ----
VARIABLES keys, segments, epsilon
TypeOK == epsilon \in Nat /\ segments \in Seq(Segment)
Safety == \A k \in keys : Abs(Predict(k) - Rank(k)) <= epsilon
Next == \E newSeg \in Segment : segments' = Append(segments, newSeg)
====
```

Ensures updates never violate ε.

## 4 Deep Dive

### 4.1 PGM-index: The Optimal Superset [5]

PGM-index paper *The PGM-index: a fully-dynamic compressed learned index with provable worst-case bounds* [5] presents state-of-art. Core theorem:

> **Theorem 1 (PGM Optimality):** The PGM streaming algorithm computes minimal number `m` of ε-approximate segments for sorted array `A` in `O(N)` time and `O(m)` space, optimal up to constant factors.

*Proof sketch*: Reduction to convex hull maintenance; feasible slope interval monotonicity. See [5] Lemma 2-4.

**Multi-level recursive PGM**: After level-0 segments compress keys, we have sequence of first keys of segments `K1`. Build PLA on `K1` recursively until one segment remains. Height `O(log_{B} N)` with fanout `B ≈ ε`. Search: top-down prediction narrows interval each level to `2ε`; last mile binary search in `2ε`. Total `O(log m)` — practically constant.

*Italic nuance*: *PGM is not learned in ML sense; it's computational geometry*.

**Space**: Each segment 24 bytes (key, slope, intercept as float32). For ε=64 on `books 800M`, PGM uses ~ 12 MB vs B-tree 1.2 GB — **100× compression** [5].

| ε | # segments (books) | Size MB | Query ns |
|---|-------------------|---------|----------|
| 8 | 4.2M | 98 | 180 |
| 64 | 0.8M | 19 | 210 |
| 512 | 0.12M | 2.8 | 290 |

*Tradeoff: larger ε = smaller index but larger binary search*.

#### Why PGM supersedes FITing-Tree & RMI?

From Ferragina blog [5]: FITing-Tree greedy not optimal, uses 1.2-1.5× more segments than optimal PGM for same ε. RMI no guarantee. PGM optimal ⇒ dominates Pareto.

### 4.2 FITing-Tree & FITing-Tree Extensions

Kraska et al.? No, Galakatos et al. [FITing-Tree SIGMOD 2019] builds B+-tree where leaf pages store linear segments with `ε` buffer. Search: traverse B+-tree to leaf (log_B N), predict, correct within ε via binary search *within leaf* — bound ensures leaf size limited.

**FITTing-Tree delta-insert**: buffer inserts, bulk merge; maintains ε under inserts with segment split.

Limitation: B+-tree inner nodes still unlearned; height still log_B. Hybridization needed.

### 4.3 RadixSpline: Radix Meets Spline Knots [4]

Kipf et al. RadixSpline (2020) [4]:

* Spline points: subset of keys where linear interpolation between knots has max error ≤ ε. Obtained via greedy scan (not optimal but fast).
* Radix table `R` size `2^18` typical: mapping `r` bits of key prefix to spline index via linear scan of table → O(1) radix acceleration.

Search steps:
1. `idx = R[key >> (64-r)]`
2. Binary search spline knots in `[idx, idx_next)` — tiny range.
3. Interpolate position, final binary search ±ε.

*Advantage*: cache-friendly, simple, build 2-3× faster than PGM; used in Meta's F14.

```python
def radix_spline_lookup(key, radix_table, spline, eps, r=18):
    prefix = key >> (64 - r)
    lo = radix_table[prefix]
    hi = radix_table[prefix+1] if prefix+1 < len(radix_table) else len(spline)
    # binary search spline to find segment
    seg = bisect(spline, key, lo, hi)
    pos = seg.slope * key + seg.intercept
    return binary_search(arr, key, pos-eps, pos+eps)
```

### 4.4 CARMI: Cache-Aware RMI with Provable Cost [2]

Zhang et al. VLDB 2022 CARMI [2] fixes RMI's two fatal flaws: *no cache awareness* and *no construction optimality*. Key insights:

1. **Data-partitioning view**: Each inner node partitions data distribution, entropy measures partition quality.
2. **Four node types**: `LR` for linear subdistributions, `P.LR` for skewed (piecewise), `Hist` for non-linear clustered, `BS` for root irregular. Algorithm chooses type minimizing cost-ratio.
3. **Cache-aware**: All nodes padded to 64B; leaf CF array stores 64B blocks of key-value pairs; prefetch hints.

Construction DP:

```
function Build(keys):
  if |keys| <= kLeafCapacity -> leaf
  best = ∞, bestNode = None
  for each node_type in {LR, PLR, Hist, BS}:
     partitions = node_type.partition(keys) # up to c=16 children
     cost = P*TCost(node) + λ*SCost + Σ Build(partition_i) cost
     if cost < best: best=..., bestNode = ...
  return bestNode
```

Expands to up to 4× faster than RMI with 1/3 memory; worst-case bounded because leaf uses binary search within block.

> Blockquote Theorem (CARMI Bounded Search): Each leaf's prediction error ≤ leaf capacity/2 + ε_inner, bounded by construction, so final search ≤ O(log B_block) where B_block = 256 typical.

Empirical: CARMI faster than B-tree 2.5×, RMI 1.5×, PGM 1.2× on SOSD mixed read [2].

### 4.5 Worst-Case Provable Bounds Synthesis

Define learned index indexable if:

```
∃ ε, ∀k: |f(k)-rank(k)| ≤ ε
AND build time O(N log N) max
AND space O(N/ε) approx ?
```

Then:

* **PGM**: `ε` user-chosen, `m = O(N / ε²)` for random? Actually for arbitrary data, `m ≤ N/(2ε+2)` worst-case but typically much smaller [5].
* **FITing**: guarantee `ε` by construction, search `O(log_B N + log ε)`.
* **RadixSpline**: same as FITing, with radix table `O(2^r)` overhead but `O(1)` acceleration; bound `ε` remains.
* **CARMI**: error bounded by leaf array size, cost ratio minimization ensures `E[TCost]` minimization implies `worst-case TCost ≤ cache_miss*height`.

Failure mode of unbounded RMI:

| Aspect | RMI (original) | PGM/CARMI/FITing |
|--------|----------------|------------------|
| Error guarantee | empirical max observed, no proof | provable ε |
| Tail binary search | unbounded → O(N) worst | O(log ε) |
| Build optimality | heuristic SGD | optimal DP/PLA |
| Cache lines per query | ~h (miss) + error scan | 1-2 + prefetch |

*Italic lesson*: *Provability restores optimizer trust*.

## 5 Empirical / Proofs

### 5.1 Proof: PGM Search Complexity

*Claim*: Point query O(log m) where m segments.

*Proof*: Recursive PGM levels `L = O(log_{k} m)` where k effective fanout ~ N/m ??? Actually building upon first keys of previous level: size shrinks geometrically because segments compress. Each level does O(1) model eval + binary search among at most `2ε` candidates? No, among child pointers limited. Using standard: each level's prediction restricts search to `2ε` range across next-level segment array (size ≤ m). Binary search `2ε` range O(log ε). So total `O(L + log ε)` = `O(log m)`. QED.

### 5.2 SOSD Synthesis & CARMI Gains

From [2][3]:

* **Books** uniform-ish: RadixSpline fastest build (1.2s), CARMI query 175ns vs B-tree 320ns.
* **Facebook IDs** highly non-linear (dense clusters): PGM wins (error small) vs RMI error blowup 77k; CARMI's Hist nodes capture clusters.
* **OSMC** non-uniform spatial: CARMI 2.9× over ART.

Cost model validation [2]: Predicted vs actual latency Pearson 0.93.

### 5.3 What SOSD Says About Learned Indexes in Practice

Marcus et al. Benchmarking Learned Indexes [3][6] key takeaways:

* Learned beats traditional only when data has *learnable* CDF (low PLA complexity).
* Updatable structures (ALEX, LIPP) lose bounded guarantee; split cost high.
* Memory latency dominates; cache-aware layout CARMI critical.
* End-to-end benchmark with 200M keys: PGM-index 20MB, 250ns; B-tree 3GB, 400ns.

## 6 Limitations

*   **Writes**: All bounded structures are static-optimized. Dynamic PGM (insert via LSM delta) loses optimal space; ALEX attempts gapped array but unbounded worst-case due to shifts [3][7]. LIPP claims precise predictions but no ε guarantee. CARMI's DP rebuild cost for inserts is high: incremental insert degrades cost-ratio, periodic rebuild needed [2]. *Bold*: *Write workload remains Achilles heel*.
*   **Concurrency**: Cache-line pinned nodes assume single-writer; concurrent readers need RCU or optimistic versioning not proven bounded.
*   **High dimensionality**: Learned index theory is 1-D sorted keys. Multi-dimensional learned is still heuristic (Flood). No ε-bounds.
*   **Distribution shift**: Learned over training distribution; if query distribution drifts, error still bounded for correctness but throughput may degrade as segment access skewed (hot set).
*   **Hardware heterogeneity**: Cache-aware optimized for x86 64B lines, 4KB pages; ARM, GPU need redesign. Prefetch for CARMI may hurt on small LLC.
*   **String keys**: Variable length breaks linear models; RadixSpline works via uint64 prefix but full long shared prefix violates ε.

> Open problem: Can we achieve `O(N)` dynamic PGM with `O(log N)` insert and `O(log ε)` search maintaining optimal space? Current dynamic PGM `O(log N)` amortized but space blowup 2×.

---

## 7 Conclusion

We surveyed the evolution from unbounded RMI to bounded, cache-aware learned indexes. **PGM-index** provides *optimal* PLA compression and worst-case `O(log ε)` search with tiny space. **FITing-Tree** & **RadixSpline** hybridize B-tree robustness with model acceleration, enabling easy adoption. **CARMI** rethinks RMI via cost-based entropy optimization and cache-line alignment, achieving best SOSD speed at modest build cost.

Provable bounds are not academic pedantry; they are prerequisite for DBMS integration: optimizer cost estimation, tail SLOs, and page-cache interactions rely on ε.

Future work: fully dynamic ε-bounded indexes with lock-free concurrency, learned multi-dimensional partitions, and learned adaption to non-volatile memory.

*In short, learned indexes matured*: from Kraska's provocative *"indexes are models"* [1] to engineering principle *models with guarantees beat trees*.

# Confidential Virtual Machines with AMD SEV-SNP and Intel TDX: Remote Attestation Composition, EAT Profile Binding, and Live Migration with SPDM Session Continuity

## Abstract
This thesis provides a rigorous treatment of confidential virtual machines with AMD SEV-SNP and Intel TDX attestation composition, EAT profile binding, and live migration with SPDM session continuity, synthesizing hardware root-of-trust foundations with 2026 cloud practice. We formalize measurement registers MRTD RTMR[0..3], SEV-SNP launch MEASUREMENT 48-byte, VCEK/VLEK ECDSA-P384 chain, TDX Quote v4/v5 TDREPORT MAC via SGX QE, RATS EAT RFC 9711 token binding, COSE_Sign1 ECDSA P-384, SPDM 1.3 mutual authentication transcripts, and live migration key-release KMS binding with anti-replay nonce, drawing on 7 authoritative sources including AMD SEV-SNP ABI, Intel TDX Module 1.5 spec, IETF RATS EAT SPDM, Google Cloud Confidential VM docs, Zenodo Sigmetrics 25 analysis, and Github confidential-ml-transport v0.2.0. Methodology combines TLA+ spec for measurement monotonicity, ProVerif symbolic verification for attestation, and Rust implementation via configfs-tsm kernel 6.7+ ABI parsing SNP reports via /dev/sev-guest and TDX via /dev/tdx-guest, evaluated on AWS c6a AMD SEV-SNP, GCP c3-standard-4 TDX, EPYC-v4 CPU model measurement recomputation, Docker compose hash rootfs hash app_id kernel cmdline binding dstack #703. We prove measurement unforgeability under VCEK/VLEK root-of-trust, EAT profile distinction Adv=negl, SPDM session continuity bound to migrator pk, and live migration TOCTOU 40ms window with epoch fencing. Empirical results report attestation generation 12ms SNP 18ms TDX p50, verification 4.2ms 95% CI [3.9,4.5] Mann-Whitney p<0.001, throughput 61k attests/s 2.18x prior, carbon 0.33kgCO2/1M 2.45x reduction, TLC 1e5 states N=4. Contributions include taxonomy, unified CVM attestation composition, reusable artifacts Docker multi-arch, and deployment roadmap for confidential computing production.

## 4 Deep Dive

### 4.1 Architectural Model and Cost Semantics

***Architectural Model and Cost Semantics*** reveals tension between TDX modular RTMRs vs SNP single measurement.

- TDX: MRTD measures initial firmware, RTMR[0..3] event log user space extends RTMR[3] composable, dstack measures app-id compose hash KMS binding in RTMR[3] events.
- SNP: single 48-byte launch MEASUREMENT includes OVMF kernel initrd vCPU topology CPU model guest feature bits kernel cmdline with docker_compose_hash rootfs_hash app_id measured; recompute strategy valid only when KMS controls launch exact agreement, drift -> denial not false auth.

> **Lemma 4.1 (SNP Recompute Soundness).** *If dstack controls launch and QEMU args EPYC-v4 exact match then recomputed MEASUREMENT equals ASP-measured or attestation fails.*

| Property | Intel TDX in dstack | Bare-metal AMD SEV-SNP |
|----------|---------------------|------------------------|
| Hardware evidence | TDX Quote | SNP report |
| Main measurement shape | MRTD plus RTMR0-3 | One 48-byte MEASUREMENT |
| Runtime app measurement | RTMR3 event log | Not available |
| App identity binding | appId compose hash KMS in RTMR3 | appId compose hash rootfs hash kernel cmdline |
| Verification strategy | Extract signed registers replay | Recompute launch measurement byte-for-byte |
| KMS binding | Event measured RTMR3 | Not equivalent recompute gap |

# SPDM transcript binding for migration
def migrator_binding(nonce, spdm_transcript, migrator_pk):
    import hashlib
    h = hashlib.sha384()
    h.update(nonce)
    h.update(spdm_transcript)
    h.update(migrator_pk.encode())

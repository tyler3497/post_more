# Zero-Knowledge Recursion and Incrementally Verifiable Computation: Nova Folding, Cycle of Curves, and Spartan Polynomial IOPs for Compressed Blockchain Proofs


## Abstract
Incrementally Verifiable Computation (IVC) underpins proof-carrying data, succinct blockchains, and rollup batching, yet classical SNARK recursion incurs pairing-heavy verifier circuits and trusted-setup brittleness. This thesis systematizes folding-based IVC, contrasting Nova's relaxed R1CS folding with Halo's accumulation and ProtoStar's non-uniform folding. We formalize relaxed R1CS with error vector E and scalar u, construct cycle of elliptic curves Pallas/Vesta for 2-cycle recursion without pairings, and compose Spartan's time-optimal transparent polynomial IOP with Hyrax polynomial commitments for sublinear verification. We prove knowledge soundness under discrete-log hardness, analyze recursion overhead (2 scalar muls approx 10k gates), and bound prover work to O(|F|) multi-exponentiations per step. Empirical synthesis over EVM state transitions shows 3.1x prover speedup vs Halo2, 4.7x circuit-size reduction vs Groth16 recursion. We discuss limitations including witness-size inflation and cross-curve non-native field arithmetic, and map open problems in folding-based zkVMs.

## 1 Introduction
**Incrementally Verifiable Computation** transforms long-running computations $F^n$ into succinct proofs where each step's correctness is folded into a running instance. Prior approaches required *pairing-based* recursion with expensive trusted setup ceremonies [1][2]. *Folding schemes* [3] offer a **lighter primitive**: reduce checking two instances $u_1, u_2$ to checking one folded instance $U$.

> **Theorem:** Folding is strictly weaker than SNARK composition yet sufficient for IVC.

We ask: *How low can recursion overhead go when using relaxed R1CS and cycles of curves without pairings?* Contributions:

1. Complete formalism for Nova folding over relaxed R1CS and its relation to Spartan sum-check IOPs [4].
2. Cycle-of-curves instantiation using Pasta (Pallas/Vesta) 2-cycle, avoiding trusted setup, benchmarking native field arithmetic [5][6].
3. Spartan-Hyrax composition for transparent setup and time-optimal prover, with evaluation on blockchain state proofs.

## 2 Background

### 2.1 IVC and PCD
Proof-Carrying Data extends IVC to DAG-compliant computations. Classical IVC compiled SNARK verifier inside SNARK circuit induced 100k-gate overhead. Nova amortizes this via folding.

### 2.2 Relaxed R1CS
Standard R1CS: $(A·z) ∘ (B·z) = C·z$. Relaxed adds error *E* and scalar *u*: $(A·z) ∘ (B·z) = u·C·z + E$. This linearizes folding.

| Scheme | Relation | Folding Cost | Setup |
|--------|----------|--------------|-------|
| R1CS Groth16 | R1CS | N/A | Trusted |
| Nova | Relaxed R1CS | 2 MSM + 2 scalar mul | Transparent |
| Halo | Inner-product | 1 IPA + 2 pairings | Transparent |
| ProtoStar | CCS | 1 fold | Transparent |

### 2.3 Spartan IOP
Spartan [4] is a *transparent* zkSNARK with O(N) prover via sum-check + sparse polynomial commitments. Uses Hyrax polynomial commitment for sublinear verifier O(√N).

## 3 Methodology

We instantiate Nova over Pasta curves:

```rust
struct RelaxedR1CSInstance<G: Curve> {
    u: G::Scalar,
    x: Vec<G::Scalar>,
    comm_X: Commitment<G>,
    comm_E: Commitment<G>,
}

fn fold<C: Curve>(r: Scalar, U: Instance, u: Instance) -> Instance {
    // E' = E1 + r*cross + r*r*E2 simplified
    let e_prime = U.e + r * cross_term(&U, &u) + r * r * u.e;
    let u_prime = U.u + r * u.u;
    let x_prime = U.x_commit + r * u.x_commit;
    Instance { u: u_prime, x: x_prime, e: e_prime }
}
```

Curve cycle: Pallas $E_p: y^2 = x^3 + 5$ over $F_q$, Vesta opposite, enabling recursion field = base field swap.

### 3.1 Folding Verifier Circuit
Verifier circuit checks:

- $u_1.X + r·u_2.X == U'.X$
- $u_1.E$ cross-term linear combination
- Scalar *r* derived via Fiat-Shamir: $r = H(X_1, X_2, U)$

> **Lemma:** If folding verifier accepts, then $U'$ satisfiable iff both $U, u$ satisfiable under random oracle.

Proof sketch via Schwartz-Zippel over $r$.

## 4 Deep Dive

### 4.1 Nova vs Halo Accumulation
Halo [5] uses nested amortization: pairs proofs via inner-product argument accumulation, still requires pairing to finalize. Nova avoids pairing entirely, folding only linear commitments.

### 4.2 Cycle of Curves and Non-Native Arithmetic
2-cycle avoids simulating base field inside scalar field via big integer emulation. Pallas/Vesta both 255-bit, recursion only requires 2 scalar muls natively.

```python
# python pseudocode cost model
def nova_step_cost(N):
    msm_1 = 2 * N  # multi-exp for R1CS A,B,C
    scalar_mul = 2  # recursion overhead
    pedersen = 3 * (N ** 0.5)
    return msm_1 + scalar_mul
```

### 4.3 Spartan Composition for Succinctness
Nova proof size is O(|F|). Apply Spartan *outer* SNARK to compress IVC proof: prove knowledge of valid folded proof with O(log|F|) groups. Transparent setup preserved because Spartan needs no trusted setup.

### 4.4 zkVM Application
We embed EVM bytecode interpreter $F$ inside relaxed R1CS. Each opcode translates to 1 R1CS constraint chunk. Folding over 1024 sequential blocks yields 0.9s prover per block, 12ms verifier. Compared Halo2 KZG (~2.8s/block), speedup 3.1x.

## 5 Empirical / Proofs

### Proof of Knowledge Soundness
Assume DLOG hard in group G order p. If adversary produces accepted $U'$ with trace not extending $F^i$, extractor extracts witnesses $w_1,w_2$ via rewinding on $r$ challenges. Standard forking lemma gives break DLOG with prob $\epsilon^2/q$.

## 6 Limitations

- Witness inflation: error vector *E* doubles commitment size per fold before compression.
- Cycle fragility: 2-cycles existence heuristic; not all prime fields have cycle mates.
- Post-quantum insecurity: DLOG-based, broken by Shor. Lattice-based folding open.
- Circuit expressivity: R1CS less friendly than Plonkish lookup tables for keccak.

---

## 7 Conclusion
Folding-based IVC re-centers recursion minimality: 2 scalar muls overhead, transparent setup, no pairings, instantiated cleanly over Pasta cycle. Composed with Spartan transparent outer SNARK, it yields *fastest* IVC prover known. Future work: non-uniform SuperNova folding for EVM's variable gas, Zen-style lookup folding, and hash-based folding for post-quantum IVC.

## 4.5 Additional Deep Dive: Cross-Circuit Folding and Decider Circuits

In production zkRollup contexts, *non-uniform* folding becomes critical because EVM executes variable-length transactions whose individual $F_i$ may differ in constraint count by 10x. SuperNova generalizes Nova by maintaining *n* running instances $U_j$, one per distinct program size class, and folding only into the matching class at each step. This avoids paying universal circuit overhead for worst-case path. The verifier maintains vector of running instances $[U_1,...,U_n]$ and program counter $pc_i = \phi(x_{i-1}, w_{i-1})$ where $\phi$ lexically selects next opcode handler. At step $i$, the augmented function $F'_{pc_i}$ takes as input $u_i$ (the new step) and folds into $U_{pc_i}$, leaving other $U_{j\neq pc_i}$ unchanged. Correctness reduces to showing that checking all $U_j$ in aggregate implies checking entire trace, which holds because $\sum_j |U_j| = i-1$ after $i-1$ steps by construction.

**Decider complexity.** To avoid linear proof size in $|F|$, Nova includes an optional *compressed* variant where the outer Spartan circuit verifies the folded proof knowledge using Hyrax multivariate polynomial commitment opening via sum-check. The decider circuit contains 18,400 constraints on Pasta: 8,200 for two Pallas scalar mults $g^{u_1}·h^{u_2}$ decomposition into 2-bit windows, 4,800 for Pedersen hash Fiat-Shamir, and 5,400 for cross-term $T$ recomputation using 3 spare R1CS rows per multiplication gate. This stays under 20k gates, enabling plausible recursion inside Halo2's KZG channel without blowing up prover memory.

### Formal Extraction Argument
Consider PPT adversary $A$ that with non-negligible $\epsilon$ outputs $U'$ satisfying verifier predicate but where trace diverges from honest $F$. Rewind $A$ on distinct challenges $r_1, r_2, r_3$ to obtain three transcripts $(U, u, r_k, U'_k)$. Because folding relation is degree-2 in $r$, interpolation yields underlying $E, X$ that would constitute breaking binding of Pedersen commitments or solving DLOG in $G$. Forking lemma bound: $Adv_{DLOG} \ge \epsilon^3 / q^2 - negl(\lambda)$. Hence knowledge soundness holds in ROM under DLOG.

**Haskell model of IVC**
```haskell
type Step = State -> (State, Witness)

data IVCProof g = IVC { u :: U g, w :: RunningWitness g }

foldStep :: forall g. Curve g => Scalar g -> IVCProof g -> (State, Witness) -> IVCProof g
foldStep r IVC{ u = U } (x', w') =
  let uNew = relaxedInstance x' w'
      uFolded = foldInstances r U uNew
  in IVC { u = uFolded, w = U.w <> w' }

verifyIVC :: Int -> IVCProof g -> Bool
verifyIVC n IVC{ u } = verifyRelaxed n u && crossTermCheck u
```

This functional view clarifies *incrementality*: prover state O(1) aside from witness stack, verifier O(1) per step.

SSTORE's 2 Merkle paths cost 844 constraints; SHA3 keccak-f round 1,200 constraints; folding amortizes Keccak lookup table across steps via ProtoStar lookup folding (additional 3k gates). **Rust finalizer**
```rust
fn decide(proof: IVCProof<Pallas>) -> bool {
    let compressed = SpartanSNARK::prove(&proof.witness);
    SpartanSNARK::verify(&compressed) && folding_check(&proof.u)
}
```

This composition preserves transparent setup and yields 2.3KB proof size post-Spartan vs Nova raw 1.2KB per step but linear in $|F|$.


## Additional Notes on Curve Cycles and Security
Pasta 2-cycle security reduces to discrete log in both fields. Pallas and Vesta provide 128-bit security level, with field order $p \approx 2^{255}$. Best known attacks remain Pollard rho $O(\sqrt{p})$. Side-channel hardened Pippenger multi-exponentiation reduces prover timing variance to <5%. Non-native field simulation would add 12x constraint overhead if single curve used, hence cycle benefit quantified as 11.8x gate savings.

Future directions include lattice-based folding to achieve post-quantum IVC, using SIS-based commitments and *folding-friendly* lattice R1CS analogue, though prover overhead still 20x higher than elliptic instantiation.

# Ephemeral Acceleration of Persistent Data Structures: Versioned Hash Array Mapped Tries with Transient Mutation Windows, Chunked Persistent Vectors, and Structural Sharing Fork Semantics

## Abstract
Persistent data structures promise functional purity without abandoning performance, yet naive path copying suggests O(log n) copies per update are expensive. This thesis dissects how modern Clojure-inspired implementations reconcile immutability with practical speed through two complementary structures: the Hash Array Mapped Trie (HAMT) with bitmap-indexed sparse nodes and Chunked Persistent Vectors with width-32 shallow tries and append-optimized tails. We formalize versioned persistence via copy-on-write path sharing, prove O(log_{32} n) effective costs, and explain transient mutation windows as an ownership-typed ephemeral acceleration that grants safe in-place mutation within a single thread, reducing batch construction from O(n log n) to amortized O(n) with O(1) freeze. We show how structural sharing fork semantics enable O(1) snapshots, first-class confluence like git branches, and MVCC-style isolation. Our analysis synthesizes Bagwell's Ideal Hash Trees [1], Steindorfer's HAMT optimizations [4], and Hickey's transient protocol [3] to present a unified model of persistent memory efficiency on the JVM and beyond.

## 1. Introduction

Functional programming historically paid a *persistence tax*: every `assoc` or `conj` required copying to preserve previous versions. The breakthrough insight of the 2000s, epitomized by Phil Bagwell's Ideal Hash Trees [1] and Rich Hickey's Clojure implementation [2][3], was that **structural sharing** turns linear copies into constant factors if you pick the right branching factor and compress sparse nodes.

> **Central Thesis:** *Persistence is not opposed to performance; with high-branching tries, bitmap compression, tail buffering, and thread-local transient ownership, persistent maps and vectors achieve near-mutable throughput while retaining full version history and lock-free reads.*

Consider three use cases demanding persistence:

- **Versioned configuration:** `config_v2 = assoc(config_v1, :timeout, 500)` must not mutate `v1` used by inflight requests.
- **Undo/redo editors:** each keystroke yields new root, old roots remain reachable for time-travel.
- **Concurrency:** readers see stable snapshots; writer creates new version atomically via CAS on root pointer, no locks.

Naive solutions — defensive copy on write or snapshotting — cost O(n) memory and time. Persistent HAMTs and vectors deliver:

- **O(log_{32} n) ≤ 6 levels** even for 1B elements
- **1–4 nodes allocated per update**, rest shared
- **O(1) transient mutation** inside `transient`/`persistent!` window [3]
- **O(1) fork** to duplicate entire database: just copy root pointer

This thesis contributes an integrated exposition of:

1. HAMT node representation with bitmap and popcount indexing.
2. Chunked vector trie with tail and shift-root growth.
3. Transient ownership model and why `persistent!` is O(1).
4. Formal fork semantics for versioned tries.
5. Empirical memory/footprint tradeoffs from JVM studies [4].

## 2. Background / Preliminaries

### 2.1 Persistence Taxonomy

Following Driscoll, Sarnak, Sleator, and Tarjan:

- **Ephemeral:** classic mutable; update destroys old.
- **Partially persistent:** all versions queryable, only newest modifiable.
- **Fully persistent:** all versions both queryable and modifiable, forming version tree — *our target*.
- **Confluently persistent:** versions can be merged, DAG of versions, yields `merge(root_a, root_b)` [5][6].

> Definition: A data structure is *persistent* if operations return new version without mutating old; *structural sharing* means versions share unchanged nodes.

Clojure chooses fully + confluently persistent for maps, sets, vectors.

### 2.2 Copy-on-Write vs Path Copying

**Copy-on-write (COW)** in OS (fork) copies page on first write. Persistent structures generalize: copy nodes on write path from root to leaf, not entire page table. With branching factor `b=32`, depth `d = ceil(log_b n)`. For `n=1M`, `d=4` [2]. Thus update copies 4 nodes, each 32 pointers = ~1KB, vs 8MB full copy.

Method categorization [6]:

| Method | Time | Space per op | Notes |
|--------|------|--------------|-------|
| Full copy | O(n) | O(n) | Simple |
| Node modification box (fat node) | O(1) amort. | O(1) | Requires in-degree bound |
| Path copying | O(log n) | O(log n) | What Clojure uses |
| Transient window | O(1) amort. inside window | O(1) | Ephemeral inside, persistent outside |

*Transient* is thus *ephemeral acceleration of persistent structure* — mutable inside, immutable outside.

### 2.3 Hashing and Tries

Bagwell [1] observed: balanced trees need rebalancing via mutations; hash tries need no rebalance if hash disperses well. Take 32-bit hash `h`, split into 5-bit chunks (since 2^5=32):

```
level0: bits 0-4
level1: bits 5-9
level2: bits 10-14
...
```

Each level indexes one HAMT node. Collision at depth 6 if full 30 bits used; then store linked list or `HashCollisionNode`. Depth ≤7 always.

## 3. Methodology / Formalism

We model versions as persistent pointers.

Let `Node = { bitmap: int32, array: Node[] | Leaf[] }` where `bitmap` is 32-bit presence mask, `array.length = popcount(bitmap)`.

Lookup:

```
idx = (hash >>> shift) & 0x1f
bit = 1 << idx
if (bitmap & bit)==0 → not found
else array[popcount(bitmap & (bit-1))] → child
recur shift+5
```

Insert:

```
newRoot = insert(node, shift, hash, key, val, edit)
if edit == transientOwner && node.edit == edit → mutate in-place
else → path-copy
```

Where `edit` token encodes transient ownership [3]. Upon `persistent!`, edit set to null, forbidding further mutation, preserving persistent guarantee.

For vectors:

Model:

```
Vector { cnt, shift, root, tail[≤32] }
root = b-ary trie depth determined by shift
tail = append buffer
```

Invariant: tail holds last `cnt mod 32` elements; when full, `pushTail` merges tail into trie, new tail empty, maybe root grows if `cnt >> shift >= 32`.

Operational cost model: we count node allocations. Transient vector's `conj!` mutates tail array if `edit` matches, else clones only tail — O(1).

We define **Fork semantics**:

- `fork(v) = v` (O(1) share root)
- `join` is concurrent `merge` under LWW or CRDT, but confluent persistence [5] allows subtree copy between arbitrary versions in O(log Δ) vs O(d log Δ) naive.

## 4. Deep Dive

### 4.1 HAMT Bitmap-Indexed Sparse Nodes and Popcount Magic

A naive 32-way node wastes memory: sparse map of 8 entries still allocates 32 slots = 75% empty. HAMT solves with **bitmap compression** [1][4].

> **Optimization that matters:** Each HAMT node stores a 32-bit `bitmap` where bit i = 1 if child i exists, plus a dense array of size `popcount(bitmap)`. Lookup uses `index = popcount(bitmap & (bit-1))` — a single `Integer.bitCount` intrinsic, mapped to `POPCNT` x86.

Example: node holds children at positions 0,3,22:

```
bitmap = 0b100…1001 = (1<<0)|(1<<3)|(1<<22)
array = [child0, child3, child22] length 3
lookup key with chunk=3 → bit=1<<3, bit present → index = popcount(bitmap & 0b0111)= popcount(0b1001 & 0b0111)=1 → child3
```

This reduces footprint dramatically. Steindorfer & Vinju [4] measured JVM HAMT improvements:

- **Cache locality:** bundling bitmap + array improves iteration 1.3–6.7× over Scala/Clojure baseline
- **Memory:** 20–40% less than array-node design
- **Equality:** canonical ordering yields 3–25.4× speedup via early prefix mismatch [4]

In Clojure:

```clojure
;; Persistent hash map assoc – O(log32 n), ≤ 6 copies
(def m {:a 1 :b 2})
(def m2 (assoc m :c 3)) ; shares structure, root copied, other nodes reused
;; Transient batch – O(n) overall
(def t (transient {}))
(dotimes [i 1000000]
  (assoc! t i i)) ; in-place when edit thread matches
(def m3 (persistent! t))
```

**Theorem:** *HAMT lookup/insert/delete cost ≤ k·popcount + k pointer chases where k = hashbits/5 ≤7, so effectively O(1) for n ≤ 2^30.*

*Proof:* Hash split gives fixed depth bound 32/5=6 plus 1 collision level. Each level does O(1) bitmap test and popcount, which is hardware O(1). Hence bound independent of n beyond constant depth. ∎

Collision handling: if two keys share full 32-bit hash but not equal (rare), store in `CollisionNode` array; v2 of CHAMP (Compressed HAMT) hashes again with different seed (Murmur mixing) to avoid linear chain [4].

Rust analogue:

```rust
enum Node<K,V> {
  Bitmap { bitmap: u32, children: Vec<Node<K,V>> },
  Leaf { hash: u32, kv: Vec<(K,V)> },
  Collision { hash: u32, entries: Vec<(K,V)> }
}
fn get(&self, hash: u32, shift: u8, key: &K) -> Option<&V> {
  match self {
    Node::Bitmap { bitmap, children } => {
      let idx = ((hash >> shift) & 0x1f) as u32;
      let bit = 1u32 << idx;
      if bitmap & bit == 0 { return None }
      let child_idx = (bitmap & (bit-1)).count_ones() as usize;
      children[child_idx].get(hash, shift+5, key)
    },
    Node::Leaf { kv, .. } => kv.iter().find(|(k,_)| k==key).map(|(_,v)| v),
    _ => None,
  }
}
```

### 4.2 Chunked Persistent Vectors: Tail, Root, and Shift

Hickey's vector [2][7] is *not* a HAMT but shares high branching: 32-way trie plus tail optimization for O(1) amortized `conj`.

Structure:

```
cnt = 54
shift = 5 (root depth 1)
root = [node0: [0..31], node1: [32..53? actually 32..63 slot]]
tail = [32..53] 22 elements
```

Representation:

- Leaves are arrays of 32 primitives/refs.
- Internal nodes array of 32 nodes.
- `shift` = 5 * depth.

Algorithms:

- **`nth(i)`:** if `i >= tailoff()` → `tail[i - tailoff()]` else walk trie: `node = root; for level shift down to 0: node = node[(i>>level)&0x1f]`.

Cost O(log32 n) but tail makes last 32 accesses O(1).

- **`conj(x)`:** if tail <32 → new tail array copying old tail +1 (O(32)). If transient edit token matches, mutate tail array in-place — **fast path**. If tail full → push tail into tree via `pushTail`.

`pushTail` growth: if `cnt >>5 > 1<<shift`, root must grow: new root with `root` as 0th child, new path to tail as 1st child, shift+=5.

```clojure
(defn transient-conj! [^TransientVector tv x]
  ;; clojure.lang.PersistentVector$TransientVector
  (let [cnt (.cnt tv)
        root (.root tv)]
    (if (< (- cnt (tailoff cnt)) 32)
      (do (aset (.tail tv) (mod cnt 32) x) ; in-place, edit checked
          (set! (.cnt tv) (inc cnt))
          tv)
      (let [tailnode (make-node (.tail tv))]
        (set! (.root tv) (push-tail tv (.shift tv) (.cnt tv) (.root tv) tailnode))
        ...))))
```

Empirical: `vrange 1M` 8.4 ms vs 5.5 ms transient [3]. Haskell analogue:

```haskell
data PVector a = PV { size :: Int, shift :: Int, root :: Node a, tail :: [a] }
-- conj amortized O(1)
conj :: PVector a -> a -> PVector a
conj pv x | length (tail pv) < 32 = pv { tail = tail pv ++ [x], size = size pv+1 }
          | otherwise = pv { root = pushTail (root pv) (tail pv), tail = [x] }
```

Chunk size tradeoff: 32 = 2^5 aligns with 5-bit hash chunk, fits cache line (32*8 bytes ptr = 256B). Larger chunk reduces depth but increases copy per leaf update; Bagwell measured 32 optimal for JVM.

### 4.3 Transient Mutation Windows: Ownership Types for Ephemeral Speed

Transients solve batch dilemma: building persistent structure elementwise costs O(n log n) copies. Solution: *linear* temporary mutable view with strong invariant: **single owner, single thread, invalidated after persist**.

Clojure protocol [3]:

```clojure
transient : Persistent → Transient (O(1), sets edit = new Object())
conj! / assoc! : Transient × k → Transient (mutate if edit active, else throw)
persistent! : Transient → Persistent (O(1), clears edit, edit=nil makes transient unusable)
```

Implementation sketch (Java):

```java
final class TransientVector {
  AtomicReference<Thread> edit; // ownership
  Object[] tail;
  int cnt;
  Node root;
  Node ensureEditable(Node node){
    if(node.edit==this.edit) return node;
    return new Node(node.edit=this.edit, cloneArray(node.arr));
  }
}
```

Properties:

1. **Thread isolation:** Clojure ≤1.6 threw `IllegalAccessError` if another thread used transient [3]; since 1.7 check removed for performance, but contract remains: *must be controlled by single-threaded scope*.
2. **No use after persistent!:** `persistent!` nulls `edit`; subsequent `conj!` throws.
3. **Substructural:** transient is *affine* type: must be threaded linearly: `(-> (transient []) (conj! 1) (persistent!))` not sharing intermediate aliases that escape — Clojure doc: *Note in particular that transients are not designed to be bashed in-place. You must capture and use the return value in the next call* [3].

**Theorem:** *Any sequence of n `conj!` operations on a freshly created transient vector takes O(n) time and allocates O(n/32) trie nodes, vs O(n log_{32} n) for persistent conj; after `persistent!`, result is observationally immutable and shares structure with no transient.*

*Proof sketch:* Tail array mutated in place for runs of 32, amortized 1/32 trie insert for overflow. Since edit token excludes aliasing creates unique ownership, in-place mutation sound. `persistent!` freezes by clearing edit pointer, future mutations would require new edit token leading to path copy, preserving persistence of returned root. ∎

> **Insight:** Transients are *second-class mutable escape hatch* that respects persistent semantics at API boundary — similar to Rust `&mut` borrow checker, but enforced dynamically via edit flag, not statically.

This inspired Scala's `mutable.Builder` -> `immutable` pattern, Haskell's ST monad for transient arrays, and Rust `im` crate's `Mutable` wrapper.

### 4.4 Structural Sharing Fork Semantics and Confluent Persistence

Persistent structures excel at **fork**: `let v2 = v1` is O(1) sharing root, not O(n) clone. For versioned tries, we can represent entire version forest.

Formal version graph:

```
V0 --add k1--> V1 --add k2--> V2
 \--fork to V1' --add k3--> V3
```

All nodes share root prefix trie. Path copying ensures V1's trie nodes unaffected when V2 allocates new root chain.

**Confluent merge** [5]: operation `meld(t1,t2)` copying subtree from one version into another in O(log Δ) not O(size). Demaine et al. [5] show finger-based trie representations achieve O(log Δ) for nearby edits, vs O(d log Δ) naive path copy deep update.


Memory accounting: live set = closure of reachable nodes from all live roots. GC can reclaim nodes unreachable from any root. Since branching immutable, reference counting or generational GC works; Steindorfer [4] shows memory footprint 30% less than Scala's immutable `HashMap` due to bitmap compression and canonical nodes.

**Fork-join** analogy to OS fork(): child process shares pages COW; structure sharing shares nodes COW.

## 5. Empirical Analysis and Formal Proofs

### 5.1 Complexity Summary

| Operation | Naive Persistent | HAMT/Chunked | Transient Window | Theory Bound |
|-----------|-----------------|--------------|------------------|--------------|
| Map lookup | O(n) linear scan | O(log32 n) ≤6 | O(log32 n) | [1][2] |
| Map assoc | O(n) copy | O(log32 n) nodes | amort O(1) | Popcount O(1) |
| Vector nth | O(log n) balanced tree | O(log32 n) + tail O(1) | same | b^d = n |
| Vector conj | O(log32 n) | O(1) amort amort (tail) | O(1) in-place | Tail buffer |
| Batch 1M build | O(n log n) | 8.4 ms Clojure [3] | 5.5 ms transient [3] | 34% win |
| Fork snapshot | O(n) clone | O(1) root ptr | O(1) | Structural share |
| Equality | O(n) always | 3–25× faster [4] with canonical | same | Hash collapse |

### 5.2 Memory Footprint

For `n=2^20 ≈1M` keys, depth 4, each internal node 32 ptr worst-case but compressed to average occupancy ~16 via binomial hash distribution (Poisson λ=n/32^k). Expected nodes ≈ n/(fill) ≈ 40K nodes. At 40 bytes/node JVM → 1.6MB structure + keys, vs 32MB full copy per version.

Vector: for 1M ints, leaves = 31250 arrays of 32 ints (1M ints), internal nodes ≈ 1024+32+1 ≈ 1057 nodes. Copy per `conj` allocates only tail (32 slots) until overflow; root path 3 nodes per 32k elements.

### 5.3 Proof of Transient Safety

> **Theorem (Transient Linearizability):** If transient object T created from persistent P on thread t, and all operations on T occur on t before persistent! with no alias escaping to another thread, execution is serializable as if operations were persistent ops applied sequentially producing same final persistent value.

*Proof:* By edit token equality check, any operation after persistent! or on different thread would see mismatched edit and copy, but specification says throws — operationally prevented. Inside valid window, mutations modify uniquely owned arrays (tail, path nodes owned by edit). Since no other live reference has edit token equal, no observer can see intermediate state. At freeze, edit nulled, returned root now reachable without edit, immutable. Therefore linearizable. ∎

This mirrors Rust affine borrow and Haskell ST safety via rank-2 types.

## 6. Limitations and Open Problems

- **Hash quality dependence:** HAMT bounds assume good dispersion; adversarial hash flooding causes collision node degeneration to O(n) list. CHAMP [4] counters with per-level hash re-mixing but still vulnerable. Mitigation: random seeding per trie instance like Python's hash randomization.

- **Transient scope leak:** Dynamic edit check removed in Clojure 1.7 sacrifices safety for speed; framework like core.async may incorrectly share transient across threads causing races but no exception. Future work: static lint via analyzer that ensures transient does not cross `go` block.

- **Persistence vs linear types:** True zero-cost transient would use linear type system (as in Idris 2) to enforce at compile time that transient used once. Clojure's runtime check leaves room for linear typing in Clojure-dialect.

- **Confluent merge conflicts:** Copying subtree between arbitrary versions creates semantic conflict if same key exists with different values in both — which to pick? LWW policy or vector clock required, diverging from pure persistent semantics [5]. Efficient conflict resolution for HAMTs with rich values (JSON) remains open.

## 7. Conclusion

We traced Bagwell's Ideal Hash Trees to Clojure's production HAMTs and persistent vectors, showing how three ideas interlock:

1. **Bitmap-indexed trie** turns sparse 32-way nodes from memory bloat to compact popcount-indexed arrays, yielding effectively O(1) map ops with 30% less footprint [4].
2. **Chunked width-32 vector with tail** reduces depth to ≤6 even for billion elements, and tail buffering gives O(1) conj amortized [2][7].
3. **Transient windows** convert persistent path copying into safe ephemeral mutation, recapturing mutable throughput (5.5 ms vs 8.4 ms per 1M) without sacrificing immutability externally [3].

Structural sharing fork semantics elevate this to versioned database: O(1) snapshots, MVCC, confluence [5][6], analogous to `fork()` COW pages. On JVM, this leads to lock-free readers, atomic writer via root CAS, rest of ecosystem (Scala, Rust's `im`, Haskell) porting same design with popcount intrinsic.

> *Persistence pays for what you change, not what you keep.*

Future exploration includes CHAMP extensions for cache awareness [8], lock-free Ctries [8] with O(1) snapshot snapshots as first-class Ctrie, and transient-first data structures [0] where ephemeral is default and persistence is frozen window — inverting intuition that immutability must be slower.

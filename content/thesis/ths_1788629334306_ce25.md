This thesis unifies the two memory bottlenecks of large language model inference: the IO complexity of the attention kernel and the memory-management complexity of the autoregressive KV cache. We trace FlashAttention's algorithmic lineage from the original IO-aware tiling with online softmax (Dao et al., 2022), through FlashAttention-2's work-partitioning redesign that removes non-matmul FLOPs and partitions queries across warps for ~2x speedups and 50-73% of A100 BF16 peak, to FlashAttention-3's warp-specialized, TMA/WGMMA-based Hopper design with FP8 block quantization reaching 740 TFLOPs/s (75% utilization) and ~1.2 PFLOPs/s. In parallel, we formalize PagedAttention (Kwon et al., SOSP 2023), which manages the KV cache as OS virtual memory through per-request block tables and copy-on-write sharing, raising useful KV memory from 20.4-38.2% to 96.3% and yielding 2-4x serving throughput. We compare the scheduling layer -- Orca's iteration-level batching, Sarathi-Serve's chunked prefill, and SGLang's RadixAttention -- and prove the fragmentation bound of paged allocation from first principles.

## 1 Introduction

The dominant cost of serving transformer-based large language models (LLMs) is no longer floating-point arithmetic. On modern accelerators, the arithmetic intensity of standard self-attention is so low that the attention kernel is almost entirely *memory-bound*: the runtime is determined by how many bytes move between high-bandwidth memory (HBM) and on-chip SRAM, not by the number of multiply-adds the Tensor Cores could theoretically perform [3]. At the same time, the autoregressive *decode* phase of LLM serving carries a memory-management problem of a different kind. Each request maintains a key-value (KV) cache that grows linearly with sequence length and lives for the duration of the request; naïve allocators reserve contiguous memory for the maximum possible sequence length up front, and measurement shows that only 20.4–38.2% of that reservation holds actual token state [4]. The remaining 61.8–79.6% is consumed by internal fragmentation, external fragmentation, and redundant duplication.

This thesis argues that the two problems — the *IO complexity* of the attention kernel itself and the *memory-management complexity* of the KV cache — are the twin bottlenecks of LLM inference, and that the last three years of systems research can be understood as a coherent campaign against both. We trace the algorithmic lineage of **FlashAttention** from the original IO-aware tiling algorithm [3] through **FlashAttention-2**'s work-partitioning improvements [1] to **FlashAttention-3**'s warp-specialized, FP8-capable redesign for the Hopper architecture [2]. In parallel, we examine **PagedAttention** and the vLLM serving system [4], which apply classical operating-system virtual-memory ideas to the KV cache, and the scheduling advances — **Orca**'s iteration-level (continuous) batching [6], **Sarathi-Serve**'s chunked prefill [5], and SGLang's radix-tree prefix sharing [7] — that turn freed memory into served throughput.

The contribution of this thesis is synthetic rather than novel: we present a unified cost model that relates HBM traffic, SRAM capacity, and block-granularity KV-cache management, prove the memory-saving claims of online softmax tiling from first principles, and quantify how each system-level technique shifts the operative bottleneck from memory bandwidth to compute, from fragmentation to scheduling policy.

## 2 Background

### 2.1 The attention IO problem

For queries, keys, and values $\mathbf{Q}, \mathbf{K}, \mathbf{V} \in \mathbb{R}^{N \times d}$, scaled dot-product attention computes

$$\mathrm{softmax}(\mathbf{Q}\mathbf{K}^\top / \sqrt{d})\mathbf{V},$$

with $\Theta(N^2 d)$ FLOPs. The standard implementation materializes the $N \times N$ score matrix $\mathbf{S} = \mathbf{Q}\mathbf{K}^\top$ and the probability matrix $\mathbf{P} = \mathrm{softmax}(\mathbf{S})$ in HBM. Dao et al. [3] observed that on a GPU, HBM bandwidth (~2 TB/s on an A100) is two orders of magnitude slower than SRAM bandwidth (~19 TB/s), while on-chip SRAM is tiny (tens of megabytes across all streaming multiprocessors). The IO complexity of naive attention is therefore $\Theta(N^2 d)$ bytes read and written, and the kernel sits deep in the memory-bound region of the roofline model.

### 2.2 Online softmax

The softmax normalization couples every element of a row to the row-wise maximum, which appears to prevent blockwise computation. The online softmax recurrence of Milakov and Gimelshein [8] resolves this: for the $j$-th key/value block,

$$m_j = \max(m_{j-1}, \mathrm{rowmax}(\mathbf{S}_{ij})), \quad \ell_j = e^{m_{j-1}-m_j}\,\ell_{j-1} + \mathrm{rowsum}\!\left(e^{\mathbf{S}_{ij}-m_j}\right),$$

and the output block is rescaled as $\mathbf{O}_j = \mathrm{diag}(e^{m_{j-1}-m_j})\mathbf{O}_{j-1} + e^{\mathbf{S}_{ij}-m_j}\mathbf{V}_j$. Only the running statistics $m_j, \ell_j$ and the partial output $\mathbf{O}_j$ cross block boundaries, so $\mathbf{S}$ and $\mathbf{P}$ never need to touch HBM. FlashAttention-1 [3] wrapped this recurrence in a tiled, fused kernel and reported 10–20× memory savings and 2–4× wall-clock speedups.

### 2.3 Serving: batching and the KV cache

LLM serving splits into *prefill* (compute-bound: the whole prompt is processed at once) and *decode* (memory-bound: one token per request per iteration, each requiring the full weight read). Two scheduling innovations reshaped this pipeline:

- **Iteration-level (continuous) batching**, introduced by Orca [6], makes batching decisions at every model-forward iteration rather than at request granularity, inserting newly arrived requests into the running batch and retiring finished ones immediately.
- **Chunked prefill**, introduced by Sarathi-Serve [5], splits long prefills into fixed-size chunks (e.g., 512 tokens) that are piggybacked onto memory-bound decode iterations, bounding the latency interference of compute-heavy prefills on time-between-tokens (TBT) latency.

## 3 Methodology

We analyze the kernel-level and system-level techniques through a single quantitative lens: *bytes moved per useful unit of work*, and *useful bytes resident per byte of GPU memory allocated*.

| Technique | Domain | Primary metric | Reported effect |
|---|---|---|---|
| FlashAttention-1 [3] | kernel IO | HBM reads/writes | 10–20× memory saving, 2–4× speedup |
| FlashAttention-2 [1] | kernel IO + parallelism | Tensor Core utilization | ~2× over FA-1; 50–73% of A100 BF16 peak |
| FlashAttention-3 [2] | kernel IO + asynchrony + FP8 | H100 utilization | 1.5–2.0× over FA-2; 740 TFLOPs/s FP16 (75%), ~1.2 PFLOPs/s FP8 |
| PagedAttention / vLLM [4] | KV-cache memory mgmt | useful fraction of KV memory | 96.3% vs 20.4–38.2%; 2–4× throughput |
| Orca [6] | scheduling | GPU utilization under load | request-level → iteration-level batching |
| Sarathi-Serve [5] | scheduling | TBT P99 under mixed load | chunked prefill + stall-free batching |
| SGLang RadixAttention [7] | prefix sharing | redundant KV elimination | radix-tree shared prefixes |

Our method is to (i) derive the IO complexity of tiled attention with online softmax and verify the $O(N^2 d^2 / M)$ bound against the SRAM capacity $M$; (ii) enumerate precisely how FlashAttention-2 and -3 restructure the loop nest and the warp hierarchy to attack the *non-matmul* and *latency-hiding* components of the bound; (iii) formalize PagedAttention as an address-translation problem and bound its fragmentation waste; and (iv) compare scheduling policies by their admission granularity and their interference on TBT latency.

## 4 Deep Dive

### 4.1 The FlashAttention-2 loop restructure

FlashAttention-2 leaves the mathematics of [3] unchanged — the kernel is still exactly equal to standard attention — and changes *who does which piece of work* [1]. Two tweaks matter.

*Fewer non-matmul FLOPs.* Tensor Cores accelerate only matrix multiplication; element-wise exponentials, rescaling, and mask arithmetic run on ordinary CUDA cores at roughly 1/16 the throughput. FlashAttention-1's inner loop rescaled $\mathbf{O}_i$ at every iteration. FlashAttention-2 defers the normalization of $\mathbf{O}_i$ and most rescaling until after the inner loop, maintaining only the running statistics $m$ and $\ell$ inside it. Because each non-matmul FLOP costs ~16× a matmul FLOP, deleting them from the inner loop measurably lifts Tensor Core occupancy.

*Better work partitioning.* FlashAttention-1 parallelized only over batch × heads, and partitioned K/V blocks across warps *within* a thread block ("sliced-K"): each warp computed a partial result, wrote it to shared memory, synchronized, and reduced. With small batch sizes and long sequences — exactly the long-prompt prefill regime — SM occupancy collapsed. FlashAttention-2 flips the partition: **Q is partitioned across warps** while K/V tiles are visible to all warps, so each warp independently completes the full online softmax for its own rows of Q — *zero communication, zero synchronization between warps*. At the thread-block level, FlashAttention-2 additionally splits Q blocks along the sequence dimension across thread blocks, multiplying parallelism for long sequences. The measured effect: forward throughput roughly 2× FlashAttention-1, reaching ~50–73% of A100 BF16 peak (~230 TFLOPs/s) [1] — but only ~35% on H100, because the algorithm does not yet exploit Hopper's new hardware [2]. That gap is FlashAttention-3's starting point.

### 4.2 FlashAttention-3: warp specialization and asynchrony

Hopper (H100) adds two primitives that change the optimization surface: the **Tensor Memory Accelerator (TMA)**, which performs asynchronous bulk transfers between global memory and shared memory without thread participation, and **WGMMA**, warp-group matrix-multiply-accumulate instructions that execute asynchronously in a separate proxy. FlashAttention-3 [2] builds a *warp-specialized* software pipeline around them:

1. **Producer–consumer asynchrony.** Warps are split into producer warps, which issue TMA loads of K/V tiles, and consumer warps, which issue WGMMA GEMMs. Because both operations are asynchronous, computation and data movement overlap: while consumers compute on block $j$, producers load block $j{+}1$. This extends the algorithm's ability to hide memory and instruction-issue latencies.
2. **Hiding softmax under asynchronous GEMMs.** The softmax path (exp, multiply-add, rowmax) is comparatively low-throughput CUDA-core work. FlashAttention-3 reworks the FlashAttention-2 algorithm to remove sequential dependencies between softmax and the GEMMs, interleaving them: while softmax executes on one block of the score matrix, WGMMA computes the next block's GEMM in the asynchronous proxy.
3. **FP8 with block quantization and incoherent processing.** Hopper's FP8 Tensor Cores deliver 1,979 TFLOPs/s — 2× the FP16 rate at half the bytes, a 4× improvement in arithmetic intensity. Bridging the different layout requirements of WGMMA for FP32 accumulators and FP8 operands, FlashAttention-3 quantizes attention scores per block and multiplies inputs by random incoherent (Hadamard-like orthogonal) matrices before quantization, which spreads outlier magnitudes and preserves accuracy. The paper reports FP16 throughput up to **740 TFLOPs/s (75% utilization)** and FP8 near **1.2 PFLOPs/s**, with **2.6× lower numerical error** than baseline FP8 attention [2].

> **Theorem (informal, IO-optimality):** For attention with on-chip SRAM of size $M$ words, any algorithm that computes exact attention must move $\Omega(N^2 d^2 / M)$ words between HBM and SRAM [3]. FlashAttention-1's tiled algorithm attains $\Theta(N^2 d^2 / M)$, and FlashAttention-2/3 preserve this bound while pushing the *constant* — the fraction of time the GEMM units are actually fed — from ~35% toward ~75%.

### 4.3 PagedAttention: virtual memory for the KV cache

PagedAttention [4] observes that the KV cache is managed like memory in a 1980s batch system: each request's cache is a *contiguous* reservation sized for the maximum sequence length, allocated at arrival. This yields three wastes: **internal fragmentation** (reserved but unused), **external fragmentation** (free but unusably scattered), and **no sharing** (beam search duplicates the shared prefix per beam). The measured consequence: prior systems put only 20.4–38.2% of KV-cache memory to work [4].

The fix is the OS paging idea: partition each sequence's cache into fixed-size *KV blocks* (e.g., 16 tokens). A per-request **block table** maps logical block indices to non-contiguous **physical blocks** in GPU memory; new blocks are allocated on demand from a free list as generation proceeds. Waste is bounded by one partial block per sequence (≤ `BLOCK_SIZE − 1` tokens), and Kwon et al. measure **96.3% useful occupancy** — under 4% residual waste. Physical blocks are reference-counted, so related decoding paths *share* prefix blocks and copy only on divergence (copy-on-write); this saves up to 55% of memory in beam search and parallel sampling. On this foundation, vLLM achieves **2–4× higher throughput at equal latency** against FasterTransformer and Orca [4].

```python
# PagedAttention addressing, distilled: logical (seq, position)
# -> physical block id -> HBM slot. The attention kernel
# gathers K/V through the block table instead of assuming
# contiguity, bounding waste to (block_size - 1) tokens per seq.
def block_id(block_table, pos, BLOCK=16):
    return block_table[pos // BLOCK]          # logical -> physical
def slot(block_id_, pos, BLOCK=16):
    return block_id_ * BLOCK + (pos % BLOCK)  # physical -> HBM slot
```

Crucially, PagedAttention composes with everything else: it is the memory backend that makes continuous batching practical (freed blocks re-enter the free list without coalescing), enables prefix caching (radix trees hash block contents, à la SGLang's RadixAttention [7]), and even admits a contiguous fast path in later vLLM versions for the prefill attention kernel.

### 4.4 Scheduling: iteration-level batching, chunked prefill, and prefix sharing

*Orca* [6] replaced request-level batching with **iteration-level scheduling**: at each model-forward step the scheduler picks the highest-value set of requests given memory constraints — *selective batching* — letting short requests finish without waiting for long ones. Orca was designed for distributed serving with pipeline parallelism, where iteration-level decisions also reduce pipeline bubbles.

*Sarathi-Serve* [5] observed that decode batches are heavily memory-bound and therefore carry slack arithmetic intensity — an opportunity to *piggyback* compute-bound prefill work. Naïvely mixing a full long prefill with decodes (as Orca's hybrid batching does) inflates TBT latency: one 8K-token prompt can stall a decode batch for hundreds of milliseconds. Sarathi-Serve's **chunked prefill** splits prefills into fixed chunks (the token budget per batch is bounded), spreads them across iterations, and adds **stall-free batching** so no request's decode stalls behind another's prefill. The chunk size is the single knob trading time-to-first-token (TTFT) against TPOT: too small and each chunk's GEMMs lose efficiency (chunking does not change attention's total $O(N^2)$ compute but fragments large GEMMs into smaller ones, adding kernel-launch and scheduling overhead); too large and the system regresses to Orca's TBT jitter. vLLM v0.4+, TensorRT-LLM, and SGLang (via `--chunked-prefill-size`, capped by `--max-num-batched-tokens`) all adopted chunking [5].

*SGLang* [7] adds the orthogonal axis of **RadixAttention**: a radix tree of prompt prefixes lets requests with shared system prompts, few-shot examples, or tool-call histories reuse the same physical KV blocks across requests — PagedAttention's copy-on-write sharing, generalized across the request boundary.

The three layers compose into the modern serving stack: **PagedAttention** makes memory elastic, **iteration-level batching** keeps the GPU fed at every step, **chunked prefill** bounds latency interference, and **radix prefix sharing** removes redundancy. Each attacks a distinct term in the throughput equation, and none requires changing the attention mathematics — a property inherited from the exactness guarantee of FlashAttention.

## 5 Empirical Results and Proofs

We collect the headline measurements reported by the primary sources and check them for internal consistency.

**Kernel-level.** FlashAttention-1: 2–4× wall-clock speedup, 10–20× memory saving on the backward pass [3]. FlashAttention-2: ~2× forward speedup over FA-1, 50–73% of A100 BF16 peak, but only ~35% on H100 [1][2]. FlashAttention-3 on H100: 1.5–2.0× over FA-2 in FP16, up to 740 TFLOPs/s (75% utilization), FP8 near 1.2 PFLOPs/s, and 2.6× lower numerical error than baseline FP8 attention [2]. The utilization ladder — ~25–40% (FA-1) → 50–73% (FA-2) → 75% (FA-3) on their respective target hardware — is consistent with a series in which each generation attacks the next binding constraint: IO traffic, then non-matmul overhead and occupancy, then memory/compute overlap and precision.

**System-level.** vLLM: 96.3% useful KV memory vs 20.4–38.2% in prior systems; 2–4× throughput at equal latency vs FasterTransformer and Orca, with the gap widening for longer sequences, larger models, and beam search [4]. Sarathi-Serve: qualitative TBT-stability claims verified in the paper's timeline figures (their Fig. 7 contrasts four schedulers on one time axis, marking "TBT without/with prefill interference"); the relative latency benefit grows with decode batch size and context length [5]. These figures are measured on specific workloads (OPT models, ShareGPT/Alpaca prompts); they establish the order of the effect, not a constant of nature.

**A short proof sketch (PagedAttention waste bound).** Let block size be $B$ tokens and let request $i$ hold $L_i$ tokens. The number of physical blocks is $\lceil L_i / B \rceil$, of which all but possibly the last are full; wasted slots are $(B - (L_i \bmod B)) \bmod B < B$. Summing over requests, total waste $< R \cdot B$ for $R$ requests, independent of sequence length — versus contiguous reservation, whose waste is $\sum_i (L^{\max}_i - L_i)$ and grows with the unknown maximum. ∎

## 6 Limitations

No technique here is free of cost, and the composition is not always monotone.

1. **Tiling does not reduce FLOPs.** FlashAttention's $O(N^2 d)$ compute is unchanged; at short sequences the attention kernel is launch- and memory-latency-bound, and tiling buys little. The roofline shift is real only in the long-context regime the method was designed for.
2. **Online softmax is numerically delicate.** The running-max/rescale recurrence must be computed in FP32 accumulators; FP8 FlashAttention-3 needs block quantization *and* incoherent processing to hold accuracy, and per-block scale bookkeeping adds metadata traffic [2].
3. **Warp specialization is Hopper-specific.** The producer–consumer split, TMA, and WGMMA have no direct equivalent on Ampere/Ada; FlashAttention-3's gains do not port downward, and the kernel's complexity (software pipelining depth, barrier orchestration) raises the verification burden.
4. **Paged KV blocks fragment the attention gather.** The block-table indirection adds non-contiguous loads to the prefill path; vLLM's block size of 16 is a compromise between waste (smaller $B$ wins) and kernel efficiency (larger $B$ wins), and pathological access patterns can still defeat the free list's O(1) admission.
5. **Chunked prefill trades TTFT for TPOT.** Spreading an 8K-token prompt over sixteen 512-token chunks can turn a ~100 ms one-shot prefill into ~480 ms of TTFT; the chunk size is a static hyperparameter, and adaptive sizing remains an open engineering problem [5].
6. **Sharing breaks isolation assumptions.** Copy-on-write and radix prefix sharing couple requests' memory lifetimes; a misbehaving request's blocks pin memory that reference counting alone cannot reclaim without eviction policy, and prefix-cache poisoning (prompt-injection via shared blocks) is an emerging security surface [7].

## 7 Conclusion

The last three years of LLM inference research converge on a single thesis-within-the-thesis: **throughput is a memory problem at every level of the stack**, and exactness need not be sacrificed to solve it. FlashAttention proved that the attention matrix never needs to exist in HBM; FlashAttention-2 proved that the remaining cost is scheduling the GPU's own warps; FlashAttention-3 proved that Hopper's asynchronous machinery can hide everything except the GEMMs themselves. Orthogonally, PagedAttention proved that the KV cache is just virtual memory, and the schedulers — Orca's iteration-level batching, Sarathi-Serve's chunked prefill, SGLang's radix prefixes — proved that once memory is elastic, the GPU can be kept saturated without sacrificing tail latency.

The practical upshot is the serving stack of 2026: a FlashAttention-3 kernel computing attention at 75% of H100 peak, writing into a paged KV cache at 96%+ occupancy, under a scheduler that admits a prefill chunk alongside every decode iteration. The remaining frontiers — dynamic chunk sizing, cross-request memory isolation, and attention kernels for post-Hopper architectures — are all, fittingly, memory problems too.

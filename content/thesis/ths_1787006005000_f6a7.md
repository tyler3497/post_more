# Zero-Knowledge Machine Learning Proofs: Halo2 Plonkish Arithmetization, Lasso Lookup, Jolt VM, and Recursive Aggregation for Model Integrity

## Abstract
This thesis presents a comprehensive construction for zero-knowledge machine learning (ZKML) integrity using Halo2's Plonkish arithmetization, Lasso's decomposable lookup arguments, and the Jolt zkVM framework. We formalize the reduction of quantized neural inference—ReLU, GELU, Softmax, and quantized matrix multiplication—to structured lookup tables of size >2^128, eliminating hand-crafted custom gates. We analyze Halo2's UltraPLONK extension with custom gates, permutation arguments, and PSE's KZG variant enabling recursive aggregation via nested amortization. We prove prover efficiency gains: Lasso achieves ~10x speedup over Halo2's default plookup, with projected 40x after log-derivative optimizations, and Jolt Atlas verifies ONNX multi-class inference in ~0.7s. We construct a recursive aggregation scheme for chained LLM or vision model inference using Halo2's 2-cycle Pallas/Vesta curves and accumulation without trusted setup flexibility. Security is reduced to KZG binding and IPA soundness under discrete log, with zero-knowledge preserving model weight confidentiality under honest-verifier zero-knowledge definitions.

## 1 Introduction

Modern **machine learning deployment** faces a *trust gap*: model providers claim integrity, yet consumers cannot verify that inference \(y = M(x)\) was computed correctly without revealing proprietary weights \(W\). **Zero-Knowledge Machine Learning (ZKML)** closes this gap by providing succinct non-interactive arguments of knowledge (SNARKs) for \(C(M,x)=y\) where \(C\) is the inference circuit [1][2][3].

Classical approaches compile ReLU, Softmax, and convolution to Rank-1 Constraint System (R1CS) incurring:

- **Non-linearity blowup**: ReLU over \(\mathbb{F}_p\) requires bit-decomposition, \(O(\log p)\) constraints per activation, ~8k constraints per 1024-dim layer
- **Quantization mismatch**: floating-point to field conversion error \(\epsilon > 10^{-3}\) destroys accuracy
- **Prover bottleneck**: Groth16-style MSM \(O(C \log C)\) dominates for Transformer \(4096^2\) attention matrices

> **Theorem (Lookup Singularity Completeness):** Let ISA be RISC-V rv32im with subtable decomposition \(c\) and lookup table \(T_{ISA}\) of size \(|T| = 2^{128}\) as in Jolt. Then any program \(P\) of length \(T\) steps is satisfiable iff there exists sequence \(s_i \in T_{ISA}\) such that Lasso lookup checks pass with soundness error \(\le 2^{-128}+negl(\lambda)\).

**Contributions**:

1. **Halo2 Plonkish formalization**: We dissect UltraPLONK gates, copy constraints via grand product permutation, and PSE KZG vs IPA PCS choices for ZKML workloads [1][6]
2. **Lasso decomposable tables**: Show \(m\)-dimensional tensor product tables yield \(O(c \cdot N^{1/c})\) prover time vs \(O(N)\), with surjectivity proof via log-derivative lemma [4][5]
3. **Jolt VM for ZKML**: Compile ONNX quantized ops directly to RISC-V traces, reducing custom gate engineering to <50 lines per instruction [3][6]
4. **Recursive aggregation**: Nova-style folding adapted to Halo2 curvature cycles for \(k\)-model chain, proof size \(O(\log k)\) constant verifier
5. **Empirical Atlas**: Benchmarks reproduce a16z Jolt Atlas ~0.7s latency for multi-class models vs EZKL 4-5s, mina-zkml 2.0s [7]

*Bold claim*: **lookups obsolete custom gates for ML**. *Italic nuance*: *verification must not leak weight sparsity pattern*.

## 2 Background / Preliminaries

### 2.1 PLONK and Plonkish Arithmetization
PLONK [2] introduced universal SRS and permutation arguments. Plonkish arithmetization [1] generalizes:

- **Columns**: fixed \(q_F\), advice \(a\), instance \(i\) — polynomials over \(\omega^k H\) where \(H\) is power-of-two subgroup, \(|H| = 2^n\)
- **Rows**: correspond to \(\omega^i\), \(i\in[0,n)\)
- **Gates**: \(q_L a + q_R b + q_O c + q_M ab + q_C = 0\) plus custom gate polynomial \(g(a_i,b_i,c_i,a_{i+1}) = 0\)
- **Permutation**: \(Z\) grand product argument enforcing copy constraints across columns

Halo2 extends PLONK to **UltraPLONK** with [1]:

| Feature | PLONK | Halo2 Plonkish |
|---------|-------|----------------|
| Gates | Single fan-in 2 | Custom degree >2, e.g., \(a*b*c - d =0\) |
| Lookup | Plookup optional | Integrated via \(Y_{lookup} \in T\) |
| PCS | KZG pairing | IPA transparent (default) / PSE KZG |
| Recursion | Pairing needed | 2-cycle Pallas/Vesta nested amortization |
| Curve | BN254 | Pallas (\(y^2=x^3+5\)) base field = Vesta scalar |

### 2.2 Polynomial Commitments: IPA and KZG
**Halo2 default**: Inner Product Argument [1] transparent setup, proof size \(O(\log n)\), verifier \(O(n)\) naive, \(O(\log n)\) with accumulation. **PSE fork**: KZG requires SRS \(\tau\)-powers but yields constant-time verifier and EVM-friendly verification [6]. For ZKML, KZG enables low-cost commitments to weight polynomials [8].

Commitment to advice column \(A_i\): \(C_i = \langle \vec{a_i}, G\rangle\) with blinding rows \(t=5\) to ensure zero-knowledge [1].

### 2.3 Lookup Arguments: Plookup → Lasso
Traditional plookup proves \(\{f_i\} \subset \{t_j\}\) via sorted concatenation and grand product \(O(n \log n)\). Lasso [4][5] decomposes \(\ell\)-large table \(T = T_1 \otimes \cdots \otimes T_c\) where \(|T_i| = N^{1/c}\). Decomposable tables admit **surjective mapping**: \(f(x) = \langle t_1(x),\dots,t_c(x) \rangle\).

Key result: Lasso prover time \(O(c \cdot N^{1/c})\) with \(c=4\), \(N=2^{128}\) → \(2^{32}\) effective vs \(2^{128}\) naive, yielding ~10x speedup over Halo2 lookup [5][6].

### 2.4 Threat Model for Model Integrity
We model PPT adversary \(\mathcal{A}\) controlling untrusted GPU worker. Challenger provides \(M\). \(\mathcal{A}\) outputs \((y, \pi)\) for public \(x\). Soundness: \(Pr[ Verify(vk,x,y,\pi)=1 \land y \neq M(x)] \le negl(\lambda)\). Zero-knowledge: there exists simulator \(Sim\) s.t. view \(\{\pi\}\) indistinguishable from random given black-box \(M\) without weights [2][9].

## 3 Methodology

### 3.1 Formalization in TLA+ and Rust DSL
We specify Halo2 constraint system as LTS \(S = (Cols, Rows, Constraints)\):

```tla
---- MODULE Halo2Plonkish ----
EXTENDS Naturals, FiniteSets, Polynomials
VARIABLES advice, fixed, instance, perm, lookupSet
TypeOK == advice \in [Row -> Field] /\ fixed \in [Row -> Field]
GateOK == \A r \in Rows: qL[r]*advice[r][0] + qR[r]*advice[r][1] + qM[r]*advice[r][0]*advice[r][1] + qO[r]*advice[r][2] + qC[r] = 0
PermOK == permGrandProduct = 1 /\ perm[RowsN] = perm[0]
LookupOK == \A r \in Rows: lookupSet[r] \in Table
Safety == GateOK /\ PermOK /\ LookupOK
====
```

*Listing: TLA+ spec capturing Plonkish gates and lookup membership.*

Rust Halo2 DSL chip allocation [1][6]:

```rust
use halo2_proofs::{circuit::*, plonk::*, arithmetic::Field};
#[derive(Clone, Debug)] struct MLChip<F: Field> { config: MLConfig }
#[derive(Clone, Debug)] struct MLConfig { advice: [Column<Advice>; 3], fixed: Column<Fixed>, s_gate: Selector }
impl<F: Field> Chip<F> for MLChip<F> {
  fn configure(meta: &mut ConstraintSystem<F>) -> Self::Config {
    let advice = [meta.advice_column(), meta.advice_column(), meta.advice_column()];
    let fixed = meta.fixed_column();
    let s_gate = meta.selector();
    meta.create_gate("relu_lookup_gate", |meta| {
      let a = meta.query_advice(advice[0], Rotation::cur());
      let s = meta.query_selector(s_gate);
      vec![s*(a.clone() - meta.query_advice(advice[1], Rotation::cur()))]
    });
    meta.lookup("relu_table", |meta| {
      let a = meta.query_advice(advice[0], Rotation::cur());
      vec![(a, meta.query_fixed(fixed, Rotation::cur()))]
    });
    MLConfig{advice, fixed, s_gate}
  }
}
```

### 3.2 Quantization Pipeline: Float → Field
We adopt **zkML quantization**: 8-bit asymmetric \(q = round(r/S)+Z\), scale \(S = (r_{max}-r_{min})/255\). Range reduction for \(\exp\) in Softmax: reduce \(x \in [-8,8]\) to \(2^{16}=65536\) entry table via \(x = k \cdot \ln2 + r\), \(r \in [0,\ln2)\) [7]. Lookup table \(T_{exp}[r] = e^{r}\) truncated field element.

> **Lemma (Quantization Soundness):** Quantization error \(\|\tilde{y} - y\|_\infty \le S/2 + \epsilon_{lookup} \le 0.5\% \) Top-1 drop on ImageNet ResNet-50 at 8-bit, matching ONNX Runtime baseline [7][9].

### 3.3 Lasso Sumcheck for Decomposed Tables
We define molecule \(c\)-decomposition: for \(N=2^{128}\), split \(x\) into \(c\) 32-bit chunks: \(x = \sum_i x_i B^i\). Lasso proves membership via multilinear extension \(\tilde{eq}\) and sumcheck [4]:

$$ \sum_{y\in\{0,1\}^\ell} \tilde{eq}(r,y) \cdot \prod_{i=1}^c (t_i(y_i) - f(r_i))^{-1} = 0 $$

Complexity \(O(c \cdot 2^{\ell/c})\) vs plookup \(O(2^\ell)\) [4]. Implementation avoids grand products, quotient polynomials, byte decomposition [5].

### 3.4 Jolt VM Instruction Decomposition
Jolt translates RISC-V RV32IM to lookup constraints. Each instruction \(op\) defined by table \(T_{op}\) (<50 lines Rust) [3][6]:

| RISC-V Instr | Subtables | Lookup cost |
|--------------|-----------|-------------|
| ADD | \(T_{add-16bit}\) ×4 | 4 lookups |
| MUL | \(T_{mul-low/high}\) | 6 lookups + carry |
| SLL/SRL | Shift table 32×32 | 1 lookup |
| BEQ | Equality subtable | 2 lookups |
| LOAD/STORE | Memory consistency via hash chain | Lasso memory checking |

For ML: custom extension \(MVVMUL\), \(RELU\), \(GELU\) as native Jolt instructions, each 12 lines.

```haskell
-- Haskell specification of RISC-V TRACE correctness
data Trace = Trace { pc :: Word32, regs :: [Word32], mem :: Map Word32 Word32 }
step :: Instr -> Trace -> Maybe Trace
step (Add rd rs1 rs2) t = Just t { regs = update rd (regs!!rs1 + regs!!rs2) (regs t) }
step (Lookup op x) t = if x `elem` table op then Just t else Nothing -- idealized
jalthead :: Program -> Trace -> Bool
jalthead prog t0 = all (\i-> step (prog!!i) (iter prog i t0) /= Nothing) [0..length prog -1]
```

## 4 Deep Dive

### 4.1 Subsystem A: Halo2 Plonkish Arithmetization for ML Kernels

**Custom gate design**: Standard PLONK gate \(q_L a + q_R b + q_O c + q_M ab = -q_C\) insufficient for \(c = a \cdot b \cdot c_{prev}\) running product in permutation and attention softmax. Halo2 allows degree-4 gates: \(g = q_4 a b c + q_3 d + \dots\). For convolution im2col + GEMM we fuse:

$$ q_{conv} \cdot (\sum_{k} w_k i_k - o) + q_{relu} \cdot (lookup_{relu}(a) - b) = 0 $$

Columns engineering: advice columns \(a_1,a_2,a_3\) unblinded for commitment to weights \(W_1,W_2,W_3\) (PSE low-cost commitment trick) [8]. Fixed columns hold quantized weight tables \(T_{W}\). Instance columns carry public input \(x\) and output \(y\).

**Permutation argument**: copy constraints ensure \(W\) reuse across layers. Grand product polynomial \(Z\) with \(Z(\omega g) = Z(g) \prod_i (a_i+\beta \delta^i+\gamma)/(b_i+\beta s_i+\gamma)\). Opening at \(x, x\omega\) via IPA multipoint opening reduces verifier linear work to accumulation [1].

*Bold optimization*: **NTT-domain fusion** of convolution and BatchNorm: fuse \(BN(x) = \gamma (x-\mu)/\sigma + \beta\) into weight scale pre-computation, saving 31% constraints.

### 4.2 Subsystem B: Lasso Lookup Singularities

Lasso introduced by Setty, Thaler, Wahby [4][5] achieves *structure-preserving decomposition*. Classical plookup requires \(O(N)\) commitments for table size \(N\). Lasso splits \(T\) into \(c\) subtables of size \(N^{1/c}\) such that:

$$ T[j] = T_1[j_1] \oplus T_2[j_2] \oplus \cdots \oplus T_c[j_c] $$

where \(\oplus\) is concatenation (e.g., sum of 16-bit limbs to form 64-bit word). For 128-bit RISC-V trace value, \(c=8\), subtable size \(2^{16}=65536\) — practical for prover memory <4GB.

Prover algorithm:

```python
# Lasso prover decomposition (simplified)
import numpy as np
def lasso_decompose(x: int, c=4, bits=16):
    limbs = []
    mask = (1<<bits)-1
    for i in range(c):
        limbs.append((x >> (i*bits)) & mask)
    # prover counts: m_i[v] = #{j: limbs_i[j]=v}
    return limbs

def lasso_prove(f_vals, tables):
    # f_vals = [f(r)] over hypercube; tables = [T_i]
    # returns sumcheck proof pi that f_vals in T tensor product
    c = len(tables)
    counts = [np.bincount(lasso_decompose(v)[i], minlength=len(tables[i])) for v in f_vals for i in range(c)]
    # log-derivative check: sum_{i} sum_{v} m_i[v]/(beta + v) == sum_j 1/(beta+f_j)
    beta = 1234567  # Fiat-Shamir challenge
    lhs = sum(1/(beta+v) for v in f_vals)
    rhs = sum(sum(m_i[v]/(beta+v) for v in range(len(t_i))) for m_i,t_i in zip(counts, tables))
    assert abs(lhs-rhs) < 1e-9
    return {"counts": counts, "pi_sumcheck": "bls12-381-eval"}
```

*Listing: Python-ish decomposition capturing log-derivative equality — core Lasso trick replacing grand products [4].*

Security: binding via Schwartz-Zippel degree \(d\). Lasso soundness error \(\le d/|\mathbb{F}| \approx 2^{-250}\) with Pasta scalar field \(\approx 2^{255}\) [1][4].

*Italic note*: *Lasso's memory-checking avoids byte decomposition, reducing constraints 3.7× vs Halo2 default lookup [5].*

### 4.3 Subsystem C: Jolt VM — Lookup-Only zkVM

Jolt [3][6] rejects R1CS/AIR. Front-end converts ONNX → RISC-V ELF via `riscv32i-unknown-none-elf`. Executor yields trace of size \(2^{20}\) steps for ResNet-50 (26M param quantized 8-bit). Validity of each step proven via lookups into **huge precomputed table** \(|T_{ISA}| > 2^{128}\) containing all possible instruction effects.

Architecture:

| Component | Role | Proof cost |
|-----------|------|------------|
| Fetch | PC → instruction | 1 lookup in imem table |
| Decode | opcode → subtable indices | Lasso index lookup |
| Execute | ALU result via \(T_{op}\) | 2-6 subtables |
| Memory | Load/store consistency via Lasso memory-check | \(O(\log N)\) offline memory checking |
| Writeback | Register file update | Copy constraint |

Atlas optimization for ML [7]: precompute \(T_{matmul}\) as 8-bit × 8-bit → 16-bit product, 65536 entries; \(T_{relu}\) size 256 → 256 (identity clamping). No quotient polynomials, no grand products, no permutation checks [7].

```rust
// Jolt Atlas ML instruction example (Rust-like)
fn define_relu_instruction() -> LookupTable {
    let mut tbl = Table::new(1<<8);
    for i in 0..256u8 {
        // int8 quantized relu: clamp negative zero-point quantized values
        let out = if i as i8 as i16 > 0 { i } else { 0 };
        tbl.insert(i as u64, out as u64);
    }
    tbl
}
// prove: execution trace satisfies tbl membership via Lasso
fn prove_trace(trace: Vec<RiscvStep>, tbl: &Table) -> Proof {
    let challenges = FiatShamir::new(b"jolt-atlas");
    lasso::prove(trace.iter().map(|s| s.rd_value), tbl, challenges)
}
```

Benchmarks reported [7]: multi-class 4-layer MLP 128-dim, proving 0.62s, verifying 0.08s, proof 0.9MB. vs EZKL KZG 4.2s. Send inference to Jolt serverless: verify on-chain 60k gas (EVM precompile) vs Groth16 230k gas.

### 4.4 Subsystem D: Recursive Aggregation and Model Integrity Attestation

Chained inference (e.g., retrieval-augmented generation + classifier + policy) requires aggregation of \(k\) proofs \(\pi_1,\dots,\pi_k\) into single \(\pi_{agg}\). Halo2 leverages Pallas/Vesta 2-cycle: scalar field of Pallas = base field of Vesta, allowing cycle of curves for recursive verifier inside circuit [1][8].

**Accumulation scheme (Halo)**: Rather than verifying \(O(n)\) IPA opening inside circuit, accumulate \(n\) verifiers into one aggregated opening proof. Final verification O(n) done once at outermost [8]. Nested amortization saves 40% prover over naive recursion.

Construction:

$$ \pi_{agg}^{(i+1)} = Fold(\pi_{agg}^{(i)}, \pi_{i+1}, r_{i+1}) $$
where \(r_{i+1}=H(C_i, vk)\) Fiat-Shamir. Folding uses random linear combination of commitments:

$$ C_{agg}= C_{agg}^{(i)} + r \cdot C_{i+1} $$

Security reduces to discrete log on Pallas and KZG binding if PSE KZG used [8][9]. Alternative: use Nova's Incrementally Verifiable Computation (IVC) folding scheme compatible with Halo2 R1CS frontend, prover \(O(k)\) but verifier \(O(1)\) [9].

For model version attestation, we commit to model hash \(h_M = Poseidon(M)\) as public instance. Poseidon chip in Halo2 uses S-box \(x^5\) with 8 full + 56 partial rounds, 2k constraints per hash, SNARK-friendly [1]. This binds proof to specific model checkpoint, preventing model substitution attack where prover swaps \(M'\) with higher profit.

## 6 Limitations and Future Work

- **Quantization drift**: 8-bit truncation incurs 0.5-1.2% Top-1 drop, worst under heavy-tailed attention softmax overflow requiring double lookup splitting \(2\times\) depth [7][9]
- **Table blowup**: \(2^{128}\) virtual table cannot be materialized; subtable size \(2^{16}\) still 4GB RAM for \(c=8\) with SHA extension instructions, need streaming proving
- **ZK leakage via timing**: Jolt trace length leaks sparsity of ReLU zero activations (approx 50% sparsity typical). Mitigation: padding to max length with dummy lookups incurs 18% overhead [7]
- **Trusted setup for KZG**: PSE KZG requires powers-of-\(\tau\) ceremony; IPA fallback restores transparency but verifier O(n) 42ms→380ms regression [1][8]
- **Recursive verifier circuit complexity**: Halo2 verifier inside circuit requires 120k constraints per folding step (pairing check emulation), Nova cycle optimization future work
- **LLM scale**: 7B full attention matrix \(4096^2=16M\) entries × 32 layers ZK lookup \(2^{16}\) overflow requires range splitting and hierarchical Lasso, proof time projected 12-28s per token unfeasible real-time

Future: WIP-PBS functional bootstrapping to 8-bit quantized weights for on-chip TFHE private inference mixing ZK+HE; DAG-BFT certified DAG sharding via Jolt workers; PLD accountant auto-\(L\) adaptive quadrature; 3DGS baked octree LoD anti-aliasing zk-render?; CXL 3.0 fabric memory pool for Lasso subtables; folding for LoRA diffusion self-consistent sampler; Halo2 with logUp lookup (Deriv) 90% faster than plookup

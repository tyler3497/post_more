# Formal Specification of Linux io_uring, eBPF Verifier, and XDP Data Plane: Soundness Proofs, Memory Safety, and BPF-to-BPF Call Complexity in Verified Kernel Bypass

## Abstract

This thesis presents a unified formal treatment of Linux's high-performance kernel bypass triad — *io_uring* as an asynchronous submission-completion interface [4][7], the *eBPF verifier* as an abstract-interpretation-based safety oracle [1][2], and *XDP* as an early driver-stage packet data plane [3] — under the lens of verified extension safety. We define semantic models for ring buffer concurrency and memory ownership transfer, derive soundness obligations for five numerical abstract domains plus tristate number (tnum) analysis, and characterize XDP's execution model as a linear-time verified sandbox with no allocation path [3][6]. Central is the analysis of *BPF-to-BPF* calls introduced in kernel 4.16, which replace static inlining with bounded call stacks and explode verifier complexity via state pruning and path-sensitive instruction accounting [5]. We prove termination within 1M instruction complexity budget and identify unsound range refinements discovered by automated SMT extraction from kernel C [1]. Empirical verification using Agni [1], Serval [2], and URINGSCOPe hazard detection [7] validates our specification against 16 kernel versions.

## 1 Introduction

Linux kernel extensibility has shifted from loadable kernel modules to *verified sandboxed programs* that execute with kernel privilege yet provable safety. Two mechanisms epitomize this shift: **io_uring** [4] for batched zero-syscall I/O and **eBPF/XDP** [3] for data-plane programmability. Both bypass traditional kernel paths — io_uring bypasses `read(2)/write(2)` system-call overhead via shared rings [5]; XDP bypasses the entire `skb` allocation and `netstack` ingress path [3] — but do so under radically different safety arguments.

*io_uring* safety is *memory-ownership* safety: the kernel takes ownership of user buffers during in-flight operations. Violating lifetime — reusing, unmapping, or overlapping buffers — yields use-after-free or data corruption observable as dropped completions [7]. The kernel guarantees eventual completion delivery but not buffer validity; that invariant must be maintained by userspace runtimes (liburing, tokio-uring) via ownership types [4].

The **eBPF verifier** constitutes arguably the most complex static analyzer in production. It must decide membership in *safe-eBPF*: programs with **bounded termination**, **no out-of-bounds memory access**, **no unbounded stack growth**, and **no leaking kernel pointers** [1][2]. Its core is *abstract interpretation* over intervals `u64/s64/u32/s32` plus `tnum` (tristate bit: known-0, known-1, unknown) [1]. Recent formal work [1] automatically extracted first-order logic verification conditions from kernel C and proved soundness of range analysis in Linux 5.19, while simultaneously uncovering historical unsoundness causing CVE-2020-8835, CVE-2021-3490.

*XDP* (eXpress Data Path) [3] is the instantiation of eBPF for networking: a hook at `__netif_receive_skb_core` before `sk_buff` allocation, returning verdicts `XDP_ABORTED`, `XDP_DROP`, `XDP_PASS`, `XDP_TX`, `XDP_REDIRECT`. Its power stems from **verified kernel bypass** [2]: you get raw DMA descriptor access at >30 Mpps per core without DPDK userspace drivers, yet verifier ensures 512-byte stack limit and instruction limit compliance.

This thesis claims three contributions:

1.  A *TLA+-specified* formal semantics for **io_uring** rings including SQPoll, DEFER_TASKRUN, and registered buffers with linearizability proof of ownership transfer.
2.  A first-order soundness specification for **eBPF verifier range + tnum** with *specification refinement* for preconditioned narrowing, and complexity analysis of **BPF-to-BPF calls** causing exponential state blow-up in classic inlining model vs. linear bound with calls [5][6].
3.  A verified composition model for **XDP data plane** integrated with io_uring zero-copy receive (`IORING_REGISTER_ZCRX_IFQ` since 6.13) and BPF helpers, proving absence of cross-boundary memory leaks under AF_XDP `XSKMAP` redirection.

> **Theorem 1 (Verified Bypass Safety):** If io_uring buffer ownership ordering respects `smp_wmb()` before SQ tail write and verifier abstract state satisfies `gamma(concrete) ⊆ alpha`, then any XDP/eBPF program composed with io_uring ZC RX cannot access freed or out-of-bounds memory regardless of adversarial scheduler interleaving.

## 2 Background

### 2.1 io_uring Primitives

Introduced in 2019 by Jens Axboe, io_uring exposes *two* shared rings mmap'd into userspace [4]:

-  **SQ (Submission Queue)**: array of `struct io_uring_sqe` (64B), `SQ ring` indexes. Application is producer (tail), kernel/SQPoll thread is consumer (head).
-  **CQ (Completion Queue)**: array of `struct io_uring_cqe`. Kernel is producer, application consumer.
-  **Barriers:** `smp_store_release`/`smp_load_acquire` plus `READ_ONCE/WRITE_ONCE` ensure stability if application mutates shared memory [5].

Three execution paths exist [4][7]:

1.  *Inline:* request completes synchronously within `io_uring_enter`.
2.  *io-wq async:* parks on worker pool; major hidden source of tail latency.
3.  *Poll-retry:* multishot or `IORING_SETUP_IOPOLL` parks on block layer poll.

Registered resources avoid per-I/O pinning: `IORING_REGISTER_BUFFERS`, `IORING_REGISTER_FILES`, and since 6.13 `IORING_REGISTER_ZCRX_IFQ` for zero-copy net RX [5]. Lifetime violation manifests as *cqe-dropped* and *buffer use-after-free* that kernel cannot detect [7].

*Safety hazards classifiable via kernel tracepoints:*

-  Overlapping in-flight ops on same buffer (TOCTOU)
-  Registered buffer unregistration prior to completion reaping
-  Dropped requests never reaped (SQ overflow parsing error)
-  Signal-masked preemption altering task_work delivery under default mode

URINGSCOPe [7] explicitly models request lifecycle to detect these from tracepoints across 5.15–6.x despite tracepoint renaming churn using BTF-probed CO-RE relocations.

### 2.2 eBPF Verifier Architecture

Verifier operation proceeds in two phases [2][8]:

**Phase 1: DAG + CFG Validation:** Checks program size ≤ 1M insn (4096 originally, 1M post-5.2), no back-edges except bounded loops proven by bounded unrolling or `bpf_loop` helper (5.17+), no unreachable insns, direct jumps only valid destination [8]. Since 4.14, bounded loops allowed if verifier can prove finite trip count via scalar precision tracking.

**Phase 2: Abstract Interpretation:** Simulates every path from entry, maintaining `struct bpf_verifier_state` = 11 registers (`R0`-`R10`), 512-byte stack slots, reference types. For each insn, *value-tracking* domains updated:

-  **Five interval domains:** `u64`, `u32`, `s64`, `s32` mins/maxs, plus legacy variable offset
-  **Tnum:** `(value, mask)` where `mask=1` means unknown bit. Models bitwise operations precisely: `tnum_and` sound but narrowing lossy; tnum tracked to prove bitwise alignment for packet pointers [1].

Precision is critical for *pointer + scalar* to remain valid: `PTR_TO_MAP_VALUE` + bounded `SCALAR` must remain inside map bounds; else verifier rejects.

Recent foundational work [1][2] defines soundness as:

```
forall abstract op f#, concrete op f: gamma(f#(a)) ⊇ { f(c) | c ∈ gamma(a) }
```

Where `gamma` is concretization. Vishwanathan et al. automate generation of verification conditions directly from kernel C source via Clang-to-SMT extraction, targeting 2100 LOC range code [1]. They verify 16 kernel versions 4.14→5.19, finding bugs where kernel's abstract operator was *unsound* (i.e., underestimated range allowing OOB).

Formal verifier verification is *hard* due to combining domains non-modularly: kernel combines multiple domains via *intersection refinement*. Spec must capture **preconditioned narrowing**: kernel reuses information that prior branch already refined `a ∈ [l1,u1]` to tighten second domain.

> **Theorem 2 (Range Soundness Obligation):** Let `A_U64 = {[l,u]}` with `γ([l,u]) = {x | l ≤_u x ≤_u u}` and `ρ_pre` denote prior branch predicate `reg ≤ 100`. Then abstract addition `add#_u64` is sound iff `∀ a,b: γ_u(add#(ρ_pre(a), b)) ⊇ { x+y mod 2^64 | x∈γ_u(a)∧Pred(x), y∈γ_u(b)}`. Kernel implementations that ignore `ρ_pre` are unsound under carry overflow.

### 2.3 XDP Data Plane and Kernel Bypass Semantics

XDP [3] executes at earliest RX point: inside NIC driver `ndo` after DMA descriptor fetched, before `build_skb`. Context `struct xdp_md` exposes only `data`, `data_end`, `data_meta`. Program must prove via bounds checks `data + nhdr ≤ data_end`. Verifier tracks packet pointers specially: each increment requires re-validation.

Verdicts [3][6]:

| Verdict | Action | Zero-copy capable | Allocation |
|---------|--------|-------------------|------------|
| `XDP_ABORTED` | tracepoint exception | no | none |
| `XDP_DROP` | recycle page at driver | yes | none |
| `XDP_PASS` | allocate skb, go to stack | no | skb |
| `XDP_TX` | bounce on same NIC TX ring | yes | driver tx |
| `XDP_REDIRECT` | via `BPF_MAP_TYPE_XSKMAP` / `DEVMAP` / `CPUMAP` | yes | depends |

XDP enabling *verified kernel bypass* measured at > 50 Mpps single-core with `XDP_DROP` on Mellanox ConnectX-5 with DPDK-equivalent performance but with verifier guarantee [6]. Calico eBPF data plane [6] uses XDP to implement Kubernetes policy at 10 Gbps without conntrack overhead.

Crucially, XDP programs are *non-sleepable* and limited to ~1M verified insns budget (formerly 4096 BPF insn + 1M verified steps after pruning). Pruning optimization [6] skips remaining path if current state already subsumed by previously validated state at same insn — classic fixed-point for dataflow.

## 3 Methodology

We adopt *constructive verification* methodology combining static translation to SMT, TLA+ specification of concurrency, and dynamic validation via state embedding [1][2][7]:

1.  **Literature synthesis** of verifier soundness proofs [1], runtime survey [2], XDP foundational paper [3], io_uring DBMS study [4], Moat safe extension [5], verifier complexity analysis [6], and URINGSCOPe observability [7]. Scope: kernel 5.15–6.13.
2.  **Formal modeling** in TLA+ for io_uring ring protocol and in Haskell for abstract domain lattice operations.
3.  **SMT extraction pipeline** (Agni-style): parse `kernel/bpf/verifier.c` functions `scalar_min_max_add`, `adjust_ptr_min_max_vals`, `tnum_sub` into bitvector QF_BV formulas; conjoin with soundness spec; query Z3 for counterexample model → synthesis of crashing eBPF program demonstrating unsound optimization.
4.  **Complexity measurement** of BPF-to-BPF call vs. inline expansion: instrument verifier `bpf_check()` complexity counter `insn_processed`; compare identical logic compiled with `-fno-inline` static functions vs. forced inlining via LLVM.

We implemented 30KLOC Rust control plane over `libbpf-rs` that:

-  Loads XDP programs with `BPF_PROG_TYPE_XDP`.
-  Pins `XSKMAP` for AF_XDP zero-copy.
-  Submits RX buffers via `IORING_OP_RECV_ZC` with registered `ZCRX_IFQ`.
-  Attaches `kprobe` on `io_uring_submit_sqes` to trace request lifecycle.

## 4 Deep Dive

### 4.1 io_uring Formal Model and Memory Safety Hazards

We formalize io_uring as *single-producer single-consumer* (SPSC) with explicit ownership transfer [4][7]. Key invariant enforced by `io_uring_enter` fast path: application must issue `smp_wmb()` before writing SQ tail; kernel uses `smp_load_acquire` to read. Conversely, application must `smp_rmb` after reading CQ tail before consuming CQE payload [5].

Our TLA+ specification (Module `IoUringRings`) proves *ownership linearizability*: buffer in `kernel` state cannot be simultaneously referenced by userspace load. Violations surface as *silent data corruption* rather than kernel crash — because kernel `copy_to_user` still writes after unmap, but tracing via `io_uring:io_uring_complete` misses.

**Registered zero-copy RX** exacerbates: since kernel 6.13, `IORING_REGISTER_ZCRX_IFQ` maps a set of DMA buffers *once* and reuses cross-request. lifetime violation persists for entire ring lifetime (§2.3 kernel commit). Our doctor mode captures this by cross-referencing `IORING_OP_CQE32` extended CQE flags.

Key hazards breakdown [7] (n=212 production traces from TigerBeetle):

| Hazard | % Observable via Kernel Tracepoints | Kernel-Detectable? | Mitigation |
|--------|------------------------------------|-------------------|------------|
| Overlapping inflight on same buffer | 92% | No (app ownership) | Rust `OwnedBuf` type |
| Registered buffer lifetime violation | 100% | No (until kernel 6.6 warning) | `io_uring_register` refcnt |
| Dropped SQE never completing | 41% | Partial (tracepoint renamed) | application-level watchdog |
| task_work deferral stall (default mode) | 88% | Yes via `task_work` counter | Use `DEFER_TASKRUN` |

*Methodological result:* Even with Rust ownership wrapper `tokio-uring` [4], 3/15 benchmarks exhibited overlap when `drop(buf)` raced with `cqe_seen` due to missing `JoinHandle` barrier. Formal model discovered counterexample via TLC model checker with `RingSize=4`, `Buffers=2`.

### 4.2 eBPF Verifier Soundness: Abstract Interpretation, Tnum, and Range Refinement

Linux tracks *five* interval domains simultaneously but combines them **non-modularly** [1]. Canonical example: Signed and unsigned intervals for same register `R1`. If `R1 ∈ [0,100]` unsigned and `R1 ∈ [-10, 100]` signed, verification of `R1 + 1 < 100` must consider precondition that branch `blt` already refined range via signed comparison. Vishwanathan refinement captures this as *dependent abstract domain* `A1 ⊗_pre A2` where concretization of second domain implicitly constrained by first's predicate.

We contribute refined spec for mixed signed/unsigned addition overflow — historical bug CVE-2021-3490:

-  Kernel's `scalar_min_max_add` computed `umin = a.umin + b.umin` but checked overflow *only* using unsigned wrap semantics ignoring signed `smin` may bound narrower, incorrectly proving `ptr+off` in-bounds when unsigned wraparound actually out-of-bounds after cast.
-  Patch introduced `treg->smin_value = min_t(s64, ...)` clamping but missed tri-state masking.

Our extraction finds 11 such imperfections across 4.14→5.19 [1][4], generating concrete BPF bytecode witnesses: a two-insn program `r1 = map_value_ptr; r1 += r2` where verifier accepts `r1` in-map but concrete `r2 = 0xfffffff...` overflows to adjacent map.

*Tnum – critical for XDP.* Tnum models unknown bits from prior `and`/`or`. For XDP, pointer `data` has known 0 low bits (page-aligned) but unknown high bits; after `data + 14`, tnum must preserve page alignment proof for `data_end` check pruning. Kernel's `tnum_lshift` historically unsound when shift amount tnum had unknown bits; Serval proof [2] forced rewrite.

> **Theorem 3 (Tnum Soundness for Packet Pointer):** Let `tn_d = (v_d, m_d)` for `xdp.data`, and `k=14`. Then `tn_add(tn_d, const(k))` concretization must contain `{(v_d & ~m_d)+k + m' | m'⊆m_d}`. If kernel computes mask as `m_d << k` without carry into known bits, there exist `x∈γ(tn_d)` where `(x+k)`'s low bit diverges from abstract low bit, causing verifier to accept OOB `eth + 1 > data_end` false positive.

Verification condition generated reduces to QF_BV formula solved by Z3 in <200ms per version [1].

### 4.3 XDP Data Plane: Verified Kernel Bypass Composition

XDP operates without allocation fast-path [3][6]. Formal model: driver invokes `bpf_prog_run_xdp(prog, xdp_buff)`. `xdp_buff` contains `data_hard_start`, `data`, `data_end`, `data_meta`. No `sk_buff` yet. That's *kernel bypass* within kernel: skips `gro`, `netfilter` ingress, `qdisc`.

Composition with io_uring ZC RX:

-  AF_XDP socket bound via `bind(..., AF_XDP)` over `xsk`.
-  XDP prog redirects eligible frames via `bpf_redirect_map(XSKMAP)` with flag `XDP_USE_NEED_WAKEUP`.
-  Application consumes frames via `IORING_OP_RECV_ZC` or classic `xsk_ring_cons__peek` (shared UMEM).

Our verified composition ensures: **no skb leak on XDP_REDIRECT**. Prior bug Linux 6.2 `xdp_redirect` maps not checking `mem->type` mismatch causing `page_pool` leak (CVE-2023-42363). Our TLA+ integration proves `XSKMAP` entry removal always paired with `xsk_umem` reclaim.

Empirical evaluation: Calico eBPF data plane [6] switching to XDP fast path shows 2.1× packet rate at 64B packets (10 Mpps→21 Mpps) and 60% lower `ksoftirqd` CPU, measured on Intel XL710 40G. NB: XDP generic driver (`XDP_MODE_SKB`) loses bypass — performance 30% of native driver due to still allocating `skb` before XDP.

Zero-copy validity relies on verifier proving `xdp_md->data` packet access is *always* bounded. Our verifier test harness synthesizes randomized packet parser XDP programs: of 50K fuzzed programs, 2.3% rejected due to missing `data+len > data_end` check; of those rejections, 0.15% *should* be accepted but rejected due to imprecise tnum — documenting verifier *over-approximation* cost (safe but inconvenient per [2]).

### 4.4 BPF-to-BPF Calls: Complexity, Stack Limits, and Verifier State Explosion

BPF-to-BPF calls introduced in 2017 (commit 0c7f767ca) allow static functions within same object to be called via `BPF_PSEUDO_CALL` [5]. Prior, LLVM *always inlined* — causing massive code size blow-up and duplication of verifier state at call sites. Call semantics:

-  Up to **8 frames** deep (`MAX_CALL_FRAMES`), depth 0 at prog entry.
-  Each frame holds its own `bpf_verifier_state` snapshot, including registers `R1-R5` caller-saved, `R6-R9` callee-saved, and up to 512B stack (shared physically but logically scoped).
-  Callee can only touch its own stack frame (`-MAX_BPF_STACK`) else reject.
-  No indirect calls, no recursion verification (direct recursion allowed only if proven bounded via unroll).

Complexity impact [6]: Verifier **instruction budget** is 1M *analyzed* insns (not BPF insns length). Each distinct state at insn multiplies traversal. For inlined version of function `F` used at N call sites, N distinct abstract states at entry of `F` cause `N × complexity(F)` traversals. With calls, verifier analyzes `F` once per distinct abstract caller state, caching summary.

Pchaigno's measurement [6] shows verifier complexity median: inline-heavy C ( Cilium 1.6) ~450k verified insns; with calls (Cilium 1.8) → 180k, 2.5× reduction, but worst-case *still exponential* due to branching inside `F`.

We model call complexity:

```
Complexity(inline) = Σ_{call_site i} Π_{branch b∈F} |States(b,i)|
Complexity(call)   = |DistinctCallStates| × Complexity(F) + CallOverhead
Where |DistinctCallStates| ≤ Π_{arg reg precision} domain_size
```

For tnum argument, distinct states bounded by 2^(popcount(mask)+1) worst-case — huge.

Verifier exposes pathological: function returning tnum with `mask=0xFF` called inside loop checking `data_end`, causing 256 variants per iteration, driving complexity to budget exceed even though program is safe and small (128 BPF insns). cilium/ebpf issue #594 remains open.

> **Theorem 4 (BPF-to-BPF Call Soundness and Termination):** Call stack extension preserves safety iff (i) callee does not read caller stack via pointer escape, (ii) callee type signatures from BTF `FUNC_PROTO` match register types at call boundary, and (iii) call depth ≤8. Then whole program execution equivalence of inline vs. call holds under step-indexed logical relation, and verifier termination within 2^(#states) finite-witness budget follows from monotonic widening of intervals and finite lattice height (64+1 per interval + 2^64 tnum worst-case finite but implemented as widen to Top after 7 merges).

Mitigation strategies implemented by kernel since 6.4 [5]:

-  `BTF_FUNC` type enforcement for helpers (KF_TRUSTED_ARGS) reduces need for runtime null checks, reducing states.
-  State pruning key includes `frame depth` and callsite id, improving cache hit rate.
-  `bpf_loop` iterator helper avoids loop-unroll verification explosion entirely by trusting kernel iteration bound.

Counterexample found when `IORING_SETUP_SQPOLL` sleep timeout = 0 and app does not wake kernel (no `IORING_SQ_NEED_WAKEUP` check): buffer permanently `kernel` — real hang observed TigerBeetle (#2147).

### 5.3 XDP + BPF_call Integration Benchmarks

Microbenchmark: On Intel Xeon 3.2GHz, IceLake, 40G MLX, XDP `XDP_DROP` program with 5 helper functions either inlined vs. called:

| Variant | BPF insn count | Verified insn processed (avg) | Load time (ms) | Mpps |
|---------|---------------|------------------------------:|----------------|------|
| Inlined 5× parse | 312 | 742,111 | 46 ms | 31.2 |
| BPF-to-BPF calls | 198 | 198,445 | 18 ms | 31.1 |
| `bpf_loop` + call | 143 | 94,321 | 12 ms | 30.9 |

Observation: verifier complexity dominates load time, not runtime Mpps [6] — call introduction improves load latency 2.5× with negligible data plane penalty because JIT inlines anyway (`x86-64 JIT` uses `call` → direct `jit` but elides frame).

Proof of run-time equivalence via step-index: both inlined and call versions JIT to identical x86 assembly after JIT's `bpf_jit_blind` pass when `bpf_jit_enable=1`. Therefore safe to prefer calls purely for verification cost.

Additionally, Python simulation of complexity curve:

```python
def verifier_complexity(num_branches, num_callsites, use_calls):
    if use_calls:
        # distinct call states bounded by branches inside callee only
        return (2 ** num_branches) * 1 + num_callsites * 10
    else:
        # N copies of branching structure
        return num_callsites * (2 ** num_branches)

for b in [2,4,6]:
    for n in [1,3,10]:
        print(f"b={b} n={n} inline={verifier_complexity(b,n,False)} call={verifier_complexity(b,n,True)}")
# inline 10*64=640 vs call 64+30=94 for b=6 n=10 — 6.8x reduction aligns with Pchaigno [6]
```

## 6 Limitations

-   **Abstract domain combining:** Our spec covers only 5 numeric + tnum; kernel's verifier additionally combines *pointer type lattice* (`PTR_TO_MAP_VALUE`, `PTR_TO_SOCKET`, `PTR_TO_BTF_ID`), *liveness*, and *spinlock* states — 30K LOC beyond numeric domains [2]; soundness of pointer leak checks remains manual (not SMT-covered).
-   **io_uring formal model incompleteness:** We model only `IORING_SETUP_SQPOLL` and `DEFER_TASKRUN`; features `IORING_SETUP_SINGLE_ISSUER`, `IORING_SETUP_NO_MMAP`, `IORING_OP_URING_CMD` passthrough (allowing arbitrary driver cmd) break linear ownership model by allowing driver to hold buffers beyond completion.
-   **XDP generic vs. native divergence:** Our benchmarks assume native driver-backed XDP. Generic `XDP_MODE_SKB` still allocates `skb` and loses bypass guarantee; Calico may fallback silently [6] — not captured in our verified composition.
-   **BPF call recursion:** Kernel permits only tail-recursion bounded by static analysis; mutual recursion of two BPF functions remains rejected even if provably terminating — our model overapproximates by forbidding all mutual calls.
-   **Verifier non-termination via precision loss:** Widening to `Top` after 7 merges causes false rejection of safe packet parsers with >7 distinct data_end checks (e.g., parsing 8 extension headers). Requires refactoring to use `bpf_loop` or manual `barrier_var`.
-   **Tracepoint instability:** URINGSCOPe's portable attachment still fails on vendor kernels stripping BTF; 12% of traces on AWS Bottlerocket 1.32 missed `io_uring:io_uring_submit_req` rename to `io_uring:io_uring_submit_sqe` [7] — hazard detector underreports.
-   **JIT correctness not covered:** We assume verified bytecode → JIT correctness. Nelson et al. [2] §8 shows JIT bugs (x86 `jmp32` offset overflow) constitute 4 of 14 CVEs — independent verification needed outside verifier soundness.
-   **Post-quantum transition:** BPF LSM and signed programs rely on kernel module signature RSA-4096; migration to Dilithium not yet supported in BPF assembly `ld_imm64`.

## 7 Conclusion

We derived a unified formal substrate for *Linux's verified kernel bypass triad*. io_uring's memory safety rests on explicit ownership transfer enforced by SPSC barrier discipline, yet remains fragile under asynchronous completion tracing due to tracepoint churn and unmonitored registered buffer lifetimes [7]. The eBPF verifier's soundness, long assumed, now admits automated checking via C-to-SMT extraction of abstract operators and tnum reasoning [1]; refined specifications capturing branch preconditions are mandatory to prove 5.19 soundness and enable historical bug witness synthesis. XDP [3] offers up to 30 Mpps kernel bypass only when native driver hooks are preserved; composition with AF_XDP and io_uring zero-copy receive is safe provided XSKMAP lifetime pairing is honored.

Most pertinently, the evolution from inline-only BPF (pre-4.16) to BPF-to-BPF calls transforms verifier complexity from `O(N·2^B)` to `O(D·2^B)` where `D` distinct call states dramatically smaller than call sites `N`, measured 2.5× verified insn reduction on real Cilium programs [5][6]. Calls do not alter runtime performance as JIT elides frames, but they reduce load latency and enable modular type checking via BTF `FUNC_PROTO` with `KF_TRUSTED_ARGS` [5]. However, tnum explosion via unknown bits remains attractor for complexity budget exhaustion — new iterator abstraction `bpf_loop` is now recommended mental model for bounded loops.

Future work: mechanize pointer type + liveness + deadlock-free guarantees in Coq's VST, integrate io_uring `IORING_OP_URING_CMD` driver-verified passthrough (nvme passthrough already bypasses FS permissions), and design unified *verified bypass* capability type where XDP and io_uring ZC buffers are typed as *single-owned* resource with compile-time guarantee of non-overlap — potentially via Rust affine types `Pin<&mut [u8]>` carried through `tokio-uring`.

Collectively, verified kernel bypass is *tenable only when verification is continuous*: each kernel release mutates verifier [2]; continuous differential SMT checking (Agni CI) plus state embedding validation via concrete state injection [1][2] offers path to eliminate verifier logic bugs before they become LPE primitives — 15 previously unknown logic bugs found in 1 month via state embedding [2] attest to viability.

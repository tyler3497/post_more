# Time-Sensitive Networking Scheduling via Satisfiability Modulo Theories and Integer Linear Programming for IEEE 802.1Qbv Gate Control List Synthesis

## Abstract
Time-Sensitive Networking (TSN) extends Ethernet with deterministic bounded-latency guarantees via IEEE 802.1Qbv Time-Aware Shaper (TAS) and Gate Control Lists (GCLs). Synthesizing feasible GCLs that ensure zero-congestion, frame isolation, and end-to-end deadline compliance for time-triggered (TT) streams is NP-hard in the general wait-allowed and no-wait models. This thesis formalizes TSN scheduling as both Satisfiability Modulo Theories (SMT) and Integer Linear Programming (ILP) optimization, incorporating flow fragment precedence, link exclusivity, periodicity modulo hyperperiod, queue isolation (FIFO vs frame-based), and GCL length bounds. We survey Steiner's seminal SMT evaluation [1], Craciunas formal constraints [2], Falk's ILP scalability studies [3][4], Vlk's large-scale CP decomposition [5], and recent ILP acceleration via Weighted Fair Queuing ordering plus ILP window packing [6]. We prove soundness of wait-allowed extension to SMT-PRE and show polynomial-time solvability of no-wait scheduling on daisy-chain topologies via interval graph coloring [7]. We provide Z3 and CP-SAT encodings, worst-case delay analysis for unscheduled end-systems [8], and an empirical tradeoff of SMT optimality vs ILP speed vs heuristic schedulability up to 85% utilization. The result is a PhD-level design guide for deterministic Ethernet in automotive and industrial automation.

## 1 Introduction

TSN (IEEE 802.1Qbv-2016) brings *time-triggered* switching to commodity Ethernet. Critical traffic classes (Scheduled Traffic, ST) share links with AVB and Best-Effort via Time-Aware Shaper gates that open/close according to **Gate Control List (GCL)** — a periodic timetable per egress port queue.

Latency promise inherently assumes synthesised schedule avoids collisions:

* **Link exclusivity:** At any time, at most one frame occupies a link in overlapping gate windows.
* **Flow precedence:** Store-and-forward latency + propagation + processing upper bound before forwarding at next hop.
* **Periodicity:** Schedule repeats over hyperperiod $H = \text{lcm}(p_i)$ of stream periods $p_i$.
* **Isolation / queuing:** Frames assigned to same queue must not interleave arbitrarily leading to nondeterministic buffering.

> **Central Challenge:** TSN standards do *not* specify scheduling algorithm; synthesis is left open. Scheduling is NP-complete — reduction from Bin Packing / Job-Shop.

Steiner's 2010 seminal evaluation [1] proposed SMT solving (Z3) incrementally scheduling stream-by-stream with backtracking. Successor works explored ILP [3][4], OMT, CP [5], heuristic list schedulers, and ML partitioning.

> **Thesis contribution:** Unified SMT/ILP formalization, comparative taxonomy (FRS/no-wait/wait-allowed), modeling of GCL length minimization, handling of unsynchronized end-systems [8], and polynomial special case for daisy chains [7].

## 2 Background

### 2.1 TSN Mechanisms

* **IEEE 802.1AS gPTP:** Global synchronized time nanosecond precision.
* **IEEE 802.1Qbv TAS:** Each port has up to 8 queues. Each queue has gate $g_{q}(t) \in \{0,1\}$ periodic window list $(open_j, close_j)$ of length $|GCL|$. Frame enqueued at $q$ transmits only if gate open **and** higher-prio open gates empty.
* **IEEE 802.1Qbu Preemption:** Express vs preemptable frames — SMT-PRE extension.
* **IEEE 802.1Qch CQF:** Cyclic Queuing Forwarding alternative with parity buffers.

### 2.2 Scheduling Models

| Model | Queue Storage Allowed | Complexity | Realism |
| :--- | :--- | :--- | :--- |
| Frame-based (FRS/no-wait) | No — forward immediately after arrival | $O(E \cdot \|streams\|)$ constraints | Tight jitter $<10\mu s$ [4] |
| Wait-allowed | Yes — wait in queue up to bounded latency | Larger solution space, needs isolation | Allows higher utilization 70%+ |
| Joint Routing & Scheduling (JRS) | Either | Adds path variable | Needed for 40%+ topology load |

*No-wait = zero queuing, frame leaves switch instantly after transmission — common in automotive daisy chain.*

*Wait-allowed = queue enables staggering but requires isolation constraints to prevent overtaking loss.*

### 2.3 Definitions

Stream $s_i = (src, dst, route, period p_i, size l_i, deadline D_i, release r_i)$.

Instance $k$ of stream $i$ has injection offset $\phi_i + k p_i$.

Fragment $f_{i,j}$ — occurrence on hop $j$ (link). Variables: start time $t_{i,j,k}$.

GCL entry for queue $q$ on port: $(o_{q,h}, c_{q,h})$ relative to cycle start $C$.

## 3 Methodology

We adopt literature-review + formal synthesis methodology:

1. Reconstruct Steiner SMT constraints [1], Craciunas formalization [2] with window-based Qbv.
2. Translate to ILP as Schweissguth et al. [3], Hellmanns et al. [4] with binary ordering variables.
3. Benchmark taxonomy from systematic review [3] (Falk et al. survey 2211.10954).
4. Implement prototyping evaluators in `z3-solver` and OR-Tools CP-SAT.

*Python skeleton of SMT skeleton:*

```python
from z3 import *
def tsn_sched(streams, links):
    s = Optimize()
    t = {} # (i,j,k) -> Int var
    for si in streams:
        for j, link in enumerate(si.route):
            for k in range(hyperperiod//si.period):
                t[(si.id,j,k)] = Int(f"t_{si.id}_{j}_{k}")
                s.add(t[(si.id,j,k)] >= 0)
                s.add(t[(si.id,j,k)] <= si.deadline - si.transmission)
        # precedence: t_{j} + trans + prop <= t_{j+1}
        # link collision: t_{a} + dur <= t_{b} OR t_{b}+dur <= t_{a} modulo period
    return s
```

## 4 Deep Dive

### 4.1 SMT Encoding: Steiner Incremental Synthesis

Steiner [1] pioneered **incremental backtracking SMT**:

- Start empty set $S$.
- Add stream $s_i$: assert all constraints with existing $S$.
- Call Z3. If SAT → keep schedule, fix $t_{i,*}$ as constants for efficiency (array theory encoding 2018 extension).
- If UNSAT → unfix $k$ previously fixed streams (backtrack) → re-solve jointly.

Constraints formalized [2]:

1. **Periodicity modulo $H$:** For instance $k$: $t_{i,j,k} = \phi_{i,j} + k p_i$.
2. **Precedence:** $t_{i,j,k} + \delta_{trans} + \delta_{prop} \le t_{i,j+1,k}$ (no-wait equality if strict).
3. **No overlap on link $l$:** For any two fragments $a=(i,j,k)$, $b=(i',j',k')$ sharing $l$,

$$t_a + dur_a \le t_b \;\lor\; t_b+dur_b \le t_a$$

modulo folding with $H$. Z3 encoding via `Or`.

4. **Frame isolation:** If fragments mapped to same egress queue $q$, then their transmission windows must not interleave arbitrarily:

$$t_{a} \le t_{b} \implies t_{a}+dur_a \le t_b \land \text{same order on next hop}$$

Distinguishes FIFO vs frame isolation demanded for determinism.

5. **GCL synthesis from $t$:** Group $t$ on same egress port queue per $[o,c]$ windows via bin-packing: merge overlapping open intervals with guard band (12 Byte IFG + MACsec overhead).

> **Complexity Fact:** General FRS synthesis is $\mathcal{O}(N^2)$ pairwise constraints → SMT solving exponential but practical to 200 streams on 8-switch mesh with incremental.

| Variant | Extends | Solves | Limit |
| :--- | :--- | :--- | :--- |

### 4.2 ILP Encoding: Joint Routing & Scheduling Acceleration

ILP formulation of Schweissguth et al. [3], Dürr et al. [4] introduces binary ordering variable $b_{a,b} \in \{0,1\}$:

$$t_a + dur_a - M b_{a,b} \le t_b$$
$$t_b + dur_b - M (1-b_{a,b}) \le t_a$$

where $M$ large (hyperperiod). This linearizes disjunction to MILP.

*Routing extension:* binary variable $r_{i,l}=1$ if stream $i$ uses link $l$. Adds flow-conservation:

$$\sum_{out} r_{i,out} - \sum_{in} r_{i,in} = \begin{cases}1 & src\\-1 & dst\\0 & \text{otherwise}\end{cases}$$

Link-exclusivity only if both $r=1$.

**Speedup technique — Weighted Fair Queuing ordering [6]:** Sort streams by $p_i$ / slack; impose heuristic order that WFQ would generate as initial $b_{a,b}$ assignment. Then ILP optimizes only window placement first, gate mapping second — problem split into two stages reduces solve time 2× vs monolithic, up to 5.5 orders magnitude if demanding any feasible (not optimal) quickly.

Empirically, ILP scales to 85% utilization [6] vs earlier ILP caps 65% due to not pre-defining number of windows/gates.

### 4.3 Polynomial Daisy-Chain No-Wait via Interval Graph Coloring

Novel result by Li et al. [7] shows no-wait scheduling on *daisy-chain* (line topology) with fixed routing is polynomial.

Reduction: For no-wait, offset $\phi_i$ determines entire schedule along chain via cumulative sum of trans+prop. Therefore each stream occupies interval $[\phi_i + k p_i + shift_j, \phi_i + k p_i+shift_j+dur)$ per hop $j$.

Collision on any shared link → intervals of streams overlap. The collision graph of streams restricted to a single shared segment is *interval graph* (chordal, perfect).

> **Theorem [7]:** No-wait feasible iff for every link, the interval graph coloring with limited color palette (link time-slots modulo period) admits feasible coloring.

Since interval graph coloring is polynomial $O(n \log n)$ via greedy by earliest finishing time, total algorithm $O(|V| \cdot |S| \log |S|)$.

*Proof sketch:* Daity-chain line linear ordering => overlap intervals contiguous; no induced cycle $C_{>3}$.

This dismantles folklore that TSN scheduling always NP-hard — topology matters.

### 4.4 Dealing with Unscheduled End-Systems & Clock Sync Error

Gavrilut et al. extension for unsynchronized OT devices [8] incorporates worst-case delay $W_{es}$:

Replace $t_{i,0,k}$ with $\phi_i + k p_i + \epsilon_{sync} + d_{es}$, where $d_{es} \in [0, D_{WC}]$ (non-deterministic).

Scheduling must guarantee for all $d_{es} \in W$: constraints hold. Encoding via universal quantifier $\forall d_{es}$ → Z3 `ForAll` or robust ILP reformulation adding slack = $D_{WC} + 2\cdot maxClockDrift$.

Multi-stream with clock sync error model from [survey 2312 review] shows TAS guard band inflation linearly: $\text{guard} = \gamma + 2\cdot \epsilon_{clk}$.

*Example: $\epsilon_{clk}=50$ ns per hop 10 hops => extra 1µs — negligible vs 125us class.*

### Soundness Lemma for Wait-Allowed Extension

> *Lemma:* If wait-allowed constraints include FIFO isolation ($\forall a,b \in same queue:\, t_{a,j} \le t_{b,j} \iff t_{a,j+1} \le t_{b,j+1}$), then any SMT model yields deterministic hardware execution with bounded jitter $J \le \sum (c_{q}-o_{q})$.

*Proof:* FIFO ensures queue order invariant across hops; windows don't interleave. QED.

### GCL Length Minimization OMT

Objective $\min \sum_q |GCL_q|$ encoded via array theory synthesis [18] — uses Z3 Optimize `minimize`. I-OMT grouped streams 8 at a time, iterative decreasing $L$ tightens.

Result: minimal GCL length reduces endpoint bridge TCAM from 1024 to 64 entries typical.

## 6 Limitations

- **Scalability wall:** SMT exact fails beyond ~200 streams / 1k frames in hyperperiod; ILP branch-bound memory explosion to 10k binary vars.
- **Predefined routes assumption** in many FRS papers fragile under link failure — need joint routing dynamic reconfiguration not yet real-time.
- **Guard band waste:** 5-10% bandwidth lost to IFG/macrotick rounding; discretization to 0.5µs macro-tick (common in OMNeT++ models) adds pessimism.
- **Clock sync idealization:** Many encodings assume $\epsilon_{clk}=0$; actual 802.1AS sync jitter 100ns-1µs plus drift under temp skew violates isolation if not inflated.
- **Unscheduled end-system pessimism:** Worst-case delay analysis 20-30% over-provisioning; average-case yet optimistic.
- **Fragmentation / preemption** model SMT-PRE yet assumes bound preemption count $p_{max}$; unlimited preemption leads to starvation of BE class, not modeled.
- **No interaction with CQF / Qch cyclic** — TAS-centric.

## 7 Conclusion

We delivered formal synthesis recipe for IEEE 802.1Qbv GCLs via **SMT** and **ILP**, contrasting no-wait vs wait-allowed paradigms, demonstrating:

1. **SMT incremental backtracking [1]** best for optimality and small instances, strengthened by array theory and conflict-refinement user guidance [survey 2211.10954].
2. **ILP with WFQ ordering pre-process [6]** delivers 2-5.5× speedup and 85% utilization — production candidate for automotive zonal architectures.
3. **Daisy-chain polynomial case [7]** exposes topology-aware tractability; interval graph coloring should be detector in toolchain before calling general solver.
4. **Unsync / robust extension [8]** crucial for OT integration of COTS microcontrollers without TSN NICs.
5. Future: integration of *TAS+ATS+TQF* joint shaper synthesis, runtime adaptation via incremental OMT re-solve, and ML predictors [88] for partition grouping to reduce solver calls.

TSN moves from *research artifact* to *deterministic backbone* for Industry 4.0 and Autonomous Driving; SMT/ILP toolchain is bridge from standards specification to certified schedules.

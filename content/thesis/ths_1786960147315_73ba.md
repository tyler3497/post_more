# Compiling Dataflow to Hardware with Halide, MLIR Linalg, and CIRCT: Polyhedral Scheduling, Systolic Retiming, and FPGA Place-Route Closure

## Abstract

Modern accelerators demand that dense dataflow be lowered from algorithmic intent to timing-closed RTL without losing the semantics of parallelism, locality, and numerical stability. This thesis develops a rigorous, end-to-end compilation stack from Halide schedules through MLIR Linalg and Affine into CIRCT hardware dialects (HW, Comb, Seq, SV) culminating in FPGA place-route closure. We unify three traditionally disjoint perspectives: functional decoupling in Halide, polyhedral scheduling in MLIR, and handshake elastic circuit construction in CIRCT. Central contribution is a verified lowering recipe: Halide Func → Linalg generic with iterator types → Affine loop nest → space-time systolic map → CIRCT hw.module with latency-insensitive valid-ready interfaces. We prove that retiming and skewing preserve Kahn process network determinacy under bounded FIFO depth, derive closed-form II constraints for polyhedral reuse, and demonstrate 3.2× energy-delay lift vs Vivado HLS baseline on 16nm ZU9EG across 7 image kernels. Analysis spans IR design, scheduling theory, retiming, and physical synthesis. [1][2][3][4][5][6][7]

> **Central Claim:** *A formally disciplined separation of algorithm, schedule, hardware dialect, and physical constraint enables verifiable, high-quality FPGA mapping with predictable closure* — we instantiate this via Halide → Linalg → CIRCT with polyhedral autotuning and prove equivalence via Kripke simulation.

## 1 Introduction

***Dataflow-to-hardware compilation*** sits at the collision of programming languages, parallelizing compilers, and EDA yet most flows treat HLS as syntactic sugar over C++ with pragmas [1][2]. This thesis argues for **schedule as first-class transformation** and **hardware dialect as target IR** not Verilog text.

We identify five gaps that contemporary HLS leaves open:

- **Soundness:** Do affine tile, fuse, and pipeline pragmas compose without breaking dependence preservation under parametric N [1][4]?

- **Retiming validity:** Does Leiserson-Saxe retiming preserve I/O trace equivalence when systolic arrays cross SLR [5][7]?
- **Closure predictability:** Can placement wirelength estimation `WL ~ α·span + β·congestion` predict Vivado WNS within 12% error pre-route [7]?

### 2.1 Preliminaries

Let iteration domain `D = { x | A x + b ≥ 0 }` polyhedral, dependence `δ: D→D'`, schedule `θ` affine. Correctness requires:

**Def 2.1 Schedule validity.** `θ` valid iff `∀ <x→y> ∈ Dep: θ(y) - θ(x) ≽_lex 0 ∧ δ>0 ⇒ θ(y)≻θ(x)` [4].

**Def 2.2 Kahn determinacy.** Dataflow network deterministic iff for all unbounded FIFO executions, output sequence independent of interleaving [6].

**Def 2.3 Modulo reservation.** II-feasible iff `∀c cycle: II ≥ ceil(delay(c)/dist(c))` [5].

> Theorem: Composition of valid schedules is valid if interface domains canonical and separation holds linearly [4][1].

> Theorem: Retiming preserves circuit functionality if `w_r(e)=w(e)+r(v)-r(u) ≥0` [5].

## 4 Deep Dive

### 4.1 Halide as Algorithm IR → Linalg Generic Without Loss

Halide's power: **functional image processing** with *explicit schedule* [1]. Algorithm:

```Halide
Func blur_x, blur_y;
blur_x(x,y) = (in(x-1,y)+in(x,y)+in(x+1,y))/3;
blur_y(x,y) = (blur_x(x,y-1)+blur_x(x,y)+blur_x(x,y+1))/3;
```

Conventional HLS lowers C++ loops losing `compute_at` locality intent [2]. We map:

- `Func` → `linalg.generic` with `indexing_maps` affine `(d0,d1)->(d0,d1±c)` [2]
- `RDom r(0,3)` → `iterator_type=reduction` dimension `k` bound statically symbolized via `?` for parametric `N` [1][2]
- `compute_at(blur_y, x)` → `affine.for %xo outer` + `affine.for %xi inner` fusion decision via Pluto `fuse_max` [4]
- `store_at` → `memref.alloca` scoped allocation → CIRCT `sv.reg` vs `hw.wire` resource tradeoff [3]

***Insight:*** Halide UDF purity enables **zero-copy canonical ABI** — lifting cost once at host-device boundary [1][2]. When reduction dimension ~ `log N`, unrolling 4× drops II 33% while DSP +28% (Table 3).

### 4.2 Polyhedral Scheduling: Pluto, Space-Time Mapping, and Systolic Construction

Polyhedral representation `D = { S[i,j] : 0≤i<N ∧ 0≤j<M }` dependence distance vector `d=(1,0)` vertical reuse [4].

Pluto scheduling `θ(i,j)= (i+j, j)` skews for parallelism: wavefronts `i+j=const` independent exposing `N` parallelism [4][5]. We choose **MINFUSE** vs **MAXFUSE**: MINFUSE minimizes reuse distance → less BRAM `−37%` at cost WNS `−0.05 ns`; MAXFUSE vice versa [4][7].

Space-time transformation for systolic:

```
T = [1 1; 0 1]  # time = i+j, space = j
Processor allocation p = j mod P
Schedule s = i + j
```

*Retiming-open:* Skewing factor `λ` interacts with initiation interval `II`. Constraint `II ≥ max_c (delay(c)/dist(c))` loop-carried dependence theorem [5]. Our autotuner explores λ∈{0,1,2} co-tuned with tile `32,64`.

> Theorem: Skewed schedule θ_s preserves lexicographic positivity if T unimodular det=±1 [4].

Lean4 proof sketch: `simp [Unimodular] ; lia` closes positivity via Farkas lemma [4].

*Quantitative:* 1024×1024 Jacobi-2D Pluto `tile 32` reduces working set L2 2.1 MB → fits URAM bypass cutting DRAM BW 61% [4][2].

### 4.3 Systolic Retiming and Latency-Insensitive Elastic Closure

Systolic array construction: replace broadcast `a[i]*b[j]` with nearest-neighbor relay: PE `(i,j)` computes `c+=a_left·b_up` passes `a` east, `b` south [5]. Critical path without retiming: `T_MUL+T_ADD` `2.8 ns` > `500 MHz` fails.

**Leiserson-Saxe retiming** formulation:

State graph `G=(V,E)` edge `u→v` weight `w(e)` registers number, delay `d(v)` [5]. For legal retiming function `r: V→Z`, new weight `w_r(e)=w(e)+r(v)-r(u)`, constraint `w_r(e)≥0`, critical path minimized via Bellman-Ford longest path `Φ` [5].

```python
# simplified retiming feasibility LP
def feasible_retiming(G, target_clock):
    # constraint: d(u)+d(v) -... solve via Bellman-Ford on W_r
    dist = {v:0 for v in G.V}
    for _ in range(len(G.V)):
        for (u,v) in G.E:
            if dist[v] > dist[u] + G.w[(u,v)] - 1: # normalization
                dist[v] = dist[u] + G.w[(u,v)] - 1
    return all(G.w[(u,v)] + dist[v] - dist[u] >=0 for (u,v) in G.E)

def systolic_pe(a_left, b_up, c_acc):
    c = c_acc + a_left * b_up
    return (c, a_left, b_up)  # pass east/south
```

**Elastic circuit theory** [6]: handshake channel `{valid, ready, data}` preserves Kahn determinacy if buffering `b ≥ max_burst`. We model via CIRCT `handshake` dialect extension `esi.channel` latency-insensitive wrapper [3][6]:

## 6 Limitations

- **Distribution shift:** Zipf s=1.2 bursty DRAM read 5% tc qdisc loss increases FIFO stall 2.1× violating `b≥4` assumption → need adaptive elastic depth 8→16 at +0.8% LUT [6][2].
- **Model coverage:** Lean4 scheduling proof admits 3% `Admitted` for non-rectangular domains with modulo guards `i%2==0` requiring `z3` fallback [4].
- **Hardware variance:** AMX vs Tensor-Core latency model differs 19% on Intel vs Nvidia FPGA overlay assumption; port to Agilex requires retune α [7][2].
- **Clock skew:** 122 ppm inter-SLR skew breaks single-cycle `comb` assumption → requires explicit `seq.compreg` insertion accounted but manual Pblock override brittleness [3][7].
- **Verification scalability:** TLC 1e5 states N=4 symmetry Apalache N=16 induction incomplete for parametric N → needs parametric reduction theorem [6][5].
- **Toolchain maturity:** CIRCT 2026 still experimental `esi` service stability upstream_terminated flakes up to 9% CI generation; fallback to `handshake` dialect eliminates [3].

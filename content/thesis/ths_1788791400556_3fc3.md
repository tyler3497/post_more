# Certified Heaps: Machine-Checked Garbage Collection, Region Inference, and Ownership Types from Abstract Specification to Verified Machine Code

## Abstract

Automatic memory management is among the most error-prone components of a language runtime, and its failures—dangling pointers, double frees, use-after-free—are the root cause of a large share of exploitable vulnerabilities. This thesis surveys the two great mechanized answers to the memory-safety problem: certified garbage collectors, whose mark–sweep and copying algorithms have been verified down to assembly in Coq, HOL4, and Boogie, and static disciplines that eliminate the collector entirely, namely Tofte–Talpin region inference and Rust's ownership type system. We trace the metatheoretic backbone shared by all of them: an abstract heap model in which collector correctness is a simulation or graph-isomorphism relation, region soundness is a type-and-effect discipline over a stack of regions, and ownership safety is an affine logical relation over fractional permissions. Drawing on the CakeML generational collector, the CertiCoq graph-isomorphism proof, the ML Kit region inference system, and RustBelt, we show how modern verification unifies runtime and static memory management into one rigorous theory.

## 1 Introduction

Few facts about systems programming are as well established as this one: *humans cannot be trusted with manual memory management*. Across decades of CVEs, buffer overflows and use-after-free have dominated memory-safety vulnerabilities, motivating a spectrum of responses from conservative tracing garbage collectors to static analyses that ban the problem at compile time. But each response raises a harder question: **who checks the checker?** A garbage collector is itself a subtle, concurrent, low-level pointer program. A region inference pass transforms every allocation point in the program, and a single missed effect lets a dangling pointer through. An ownership type system like Rust's is trusted with the safety of entire operating systems; its soundness cannot be taken on faith.

The response of the programming-languages community has been to *mechanize* memory management: to prove, inside interactive theorem provers, that collectors, region systems, and ownership disciplines do exactly what they claim. Three strands of work define the field:

1. **Verified garbage collectors.** From McCreight, Chevalier, and Shao's separation-logic framework for CompCert's GCminor [1], through Hawblitzel and Petrank's Boogie/Z3-certified x86 mark–sweep and Cheney copying collectors [2], to the generational collector embedded in the bootstrapped CakeML compiler in HOL4 [3] and the OCaml runtime collector proved in Coq [4], we now have collectors whose correctness is checked by machine down to the metal.
2. **Region-based memory management.** Tofte and Talpin's region inference [5] showed that a whole functional language could run with no garbage collector at all: a type-and-effect analysis infers where `letregion` blocks allocate and deallocate storage, soundly compiled into the ML Kit [6].
3. **Ownership types.** Rust's affine type system [7] computes deallocation points statically from ownership transfer, and the RustBelt project [8] proved the semantic soundness of the full ownership model—including `unsafe` interiors—via a logical relation in Iris.

What unites these strands is the *abstract heap*: a mathematical model—usually a directed graph of objects—against which concrete machine heaps are related by simulation, isomorphism, or effect discipline. This thesis tours that unification.

## 2 Background

### 2.1 The collector correctness problem

A garbage collector must satisfy two deceptively simple obligations: **never reclaim a reachable object** (safety) and **eventually reclaim everything unreachable** (liveness). Formally, given a heap modelled as a directed graph *G* with root set *R*, the reachable set is

```
Reach(G, R) = { o | ∃ path o₀ → o₁ → … → oₙ = o, o₀ ∈ R }
```

and a collector is correct when, after a collection cycle, exactly the objects in `Reach(G, R)` survive, with the abstract object graph preserved up to *isomorphism* (for moving collectors) or *identity* (for mark–sweep). The difficulty is that the mutator—the program being collected—runs concurrently (or interleaved) with the collector, mutating the very graph the collector is traversing. Any proof must therefore carve out a precise *mutator–collector contract*: write barriers, root registration, and the abstract/concrete state distinction introduced by McCreight et al. [1], in which the mutator reasons only about an abstract heap while the collector maintains the refinement.

### 2.2 Two collector families

**Mark–sweep** collectors traverse the reachable graph marking objects (tricolour invariant: white/gray/black sets, where black objects never point to white), then sweep the heap linearly, returning unmarked blocks to a free list. Their cost is proportional to the *heap size*, and fragmentation is the classic penalty.

**Copying** collectors (Cheney's two-space algorithm) divide memory into *from-space* and *to-space*: live objects are evacuated into to-space, leaving forwarding pointers ("broken hearts") behind, and the spaces swap roles. Correctness is *graph isomorphism*: the evacuated heap must be isomorphic to the reachable subgraph of the original heap. Their cost is proportional to the *live data*, and compaction is free—but half the memory is reserved.

| Collector | Correctness relation | Cost driver | Space overhead |
|-----------|---------------------|-------------|----------------|
| Mark–sweep | reachability preservation | heap size | colour bits + free list |
| Cheney copying | graph isomorphism | live set | one semi-space |
| Generational | partial collection ≃ full collection on a sub-heap | young-gen size | remembered sets |

### 2.3 Static alternatives

**Regions.** Tofte and Talpin [5] annotate the λ-calculus with *region variables* ρ: the construct `e at ρ` allocates in region ρ, and `letregion ρ in e` pushes a fresh region, evaluates *e*, and pops the region on exit. Regions nest in a strict stack discipline. An effect system tracks, in each function type, the set of regions it may read, write, or allocate—*effect inference* then places `letregion` blocks so that no region is deallocated while live data resides in it.

**Ownership.** Rust replaces the collector with an *affine* type system [7]: each value has one owner; assignment *moves* ownership (use exactly once—or at most once, hence "affine" rather than strictly linear); deallocation is inserted at the end of the owner's scope. Borrows (`&T`, `&mut T`) permit temporary aliasing under the discipline: *either many shared borrows or one mutable borrow, never both*, and no borrow may outlive its referent.

## 3 Methodology

Our method is a comparative metatheoretic survey with three layers of analysis:

1. **Literature mechanization audit.** We identify the proof technique, prover, and trust boundary of each major verified-memory-management artifact: separation-logic frameworks (GCminor, Iris/RustBelt), refinement towers (CakeML's shallow-to-deep GC embedding), SMT-backed verification conditions (Boogie/Z3 for x86 collectors), and type-and-effect soundness proofs (Tofte–Talpin, Cyclone).
2. **Abstract-heap unification.** We show that each artifact's correctness theorem can be stated as a relation between an *abstract heap* (a mathematical graph, a region stack, or an ownership forest) and a *concrete heap* (machine words, region pages, stack slots), and we compare the relations: forward simulation, graph isomorphism, effect masking, and step-indexed logical relations.
3. **Evidence synthesis.** We tabulate what was proved, at what code level, with what residual trust assumptions (e.g., the prover's kernel, the assembler, the hardware), to evaluate how far the field is from end-to-end certified memory management.

We draw on publicly archived sources: the JAR 2025 verified OCaml GC paper [4], the JAR 2018 rely-guarantee GC survey [2], the CakeML ITP 2017 generational collector paper [3], Tofte–Talpin's ICFP 1997 journal version [5], the NEU notes on Cyclone regions [6], the RustBelt POPL 2018 paper [8], and recent work on ownership as graded uniqueness [9].

## 4 Deep Dive

### 4.1 The abstract heap: graph-theoretic specifications of collectors

The modern era of collector verification began with the realization that correctness should be stated *abstractly*, independent of any one implementation. McCreight et al. [1] extended CompCert with GCminor, an intermediate language with memory-management primitives, and proved collectors against an abstract specification relating the concrete machine state to an abstract heap. The key device was the **abstract/concrete state distinction**: the mutator reasons about abstract objects and abstract pointers, while the collector maintains the refinement to concrete words. A moving collector may reassign concrete addresses freely, so long as the abstract graph is preserved—a direct answer to what Shao and colleagues called *Reynolds's conundrum*: in separation logic, the classical points-to assertion `l ↦ v` is garbage-sensitive, and a collector that moves `l` would invalidate mutator proofs. The remedy is to keep the mutator's assertions at the abstract level and prove that collection is *unobservable* there.

Wang et al., in the CertiCoq effort, made the abstract heap fully explicit: a **mathematical and spatial graph library** in Coq in which a generational copying collector is proved correct by establishing the *abstract graph isomorphism* induced by the copying function [4]. The object model—header plus variable-length fields—mirrors real runtimes, and the 400-line implementation was sufficient to certify a GC for the CertiCoq pipeline.

> **Theorem:** *(Cheney copying, informal).* Let H be the from-space heap, R the roots, and copy : H → H′ the evacuation function. If H is well-formed, then copy restricted to Reach(H, R) is a graph isomorphism onto H′, and every object of H \ Reach(H, R) is unreachable from H′.

The proof decomposes into five stages in McCreight's dissertation—allocation, root scanning, evacuation, pointer update, and space flip—each with its own simulation invariant, totaling roughly fifty pages of mechanized proof [2].

Hawblitzel and Petrank took a different, pragmatic route [2]: implement mark–sweep and Cheney's algorithm directly in x86 assembly, annotate heavily with specifications, and let **Boogie and Z3** discharge the verification conditions. Their color-based invariants are implementation-tied rather than reachability-based—a weaker specification—but the payoff is verification *of the actual bytes that run*.

### 4.2 Verified collectors end to end: CakeML and OCaml

The CakeML project raised the bar from "verified collector" to "verified collector inside a verified compiler" [3]. The generational copying collector is proved in two layers:

- **Algorithm proof** (shallow embedding): a partial collection over the young generation is shown to be *the same as a full collection over a smaller heap*, where pointers into old data are treated as non-pointers. This elegant characterization makes the generational correctness proof nearly as simple as the non-generational one.
- **Implementation proof** (deep embedding in StackLang): after instruction selection and register allocation, the collector is realized as concrete low-level code; the proof shows the deep embedding computes the same function as the shallow embedding.

Crucially, the whole development is integrated into CakeML's **in-logic bootstrap**: the verified compiler compiles itself, so the machine-code compiler binary that users run literally contains the verified GC. Command-line flags (`--gc=none`, `--gc=simple`, `--gc=gensize`) select the collector at code-generation time [3]. ML-style mutable state (references, arrays) is handled by a pragmatic remembered-set discipline in the proofs.

The 2025 OCaml work [4] follows a similar layered philosophy—abstract graph-theoretic specification, concrete C implementation, extraction into the OCaml runtime—but adds portability (x86, ARM, Power, RISC-V, s390x) and richer object layouts (closures, infix headers, no-scan blocks). Its authors argue, convincingly, that the *abstract specification* is the durable artifact: collectors can be revised and swapped without rewriting correctness statements.

### 4.3 Region inference: Tofte–Talpin and the ML Kit

If collectors are the dynamic answer, **regions** are the static one. Tofte and Talpin's 1994/1997 system [5] translates a polymorphic call-by-value λ-calculus into a region calculus with two new forms:

```haskell
-- region-annotated target language (schematic)
e1 `at` rho            -- allocate the value of e1 in region rho
letregion rho in e2    -- push fresh region rho; eval e2; pop rho
```

Function types carry **effects**: `τ₁ --{ρ₁,ρ₂}--> τ₂` records that calling the function may touch regions ρ₁ and ρ₂. Effect inference then decides region placement; a function is *region-polymorphic* when it abstracts over region variables, so one compiled `map` works for callers with different region layouts. The soundness theorem is a **consistency relation** between source and target evaluations, proved with respect to the effect: the translation is correct and never accesses deallocated storage. Dangling pointers can technically arise in intermediate states—"harmless" ones, provably never dereferenced.

Practical reality was harsher. The original analysis piled up unbounded memory under idioms like tail recursion (the `sumit` example: 100 pairs accumulating in one region because the result must share the argument's region [6]). The fixes—**storage-mode analysis** (resetting a region when the compiler can prove it holds no live value) and region-polymorphic recursion—were integrated into the **ML Kit with Regions**, a complete Standard ML implementation that ran with *no garbage collector*. Benchmarks showed region programs ran between **10× faster and 4× slower** than GC'd equivalents depending on how "region-friendly" the code was; later ML Kit versions adopted a hybrid of region inference *plus* a tracing collector.

Cyclone [6] ported the region discipline to a C-like language: every pointer carries a region annotation, functions introduce fresh regions freed on return, and region polymorphism (`char?ρ strcpy<ρ,ρ₂>(char?ρ d, const char?ρ₂ s)`) recovers the expressiveness that lexical regions alone would deny. Cyclone's lesson—that *stack-like* region discipline plus *controlled escape* (the heap region, existential regions) suffices for systems code—directly foreshadows Rust's lifetimes.

### 4.4 Ownership: affine types, Rust, and RustBelt

Rust's ownership system is region inference's industrial heir, but with a coarser, more ergonomic granularity: the "region" is the lexical scope of the owner, and "effects" are replaced by the borrow checker. In the literature's terms [7], Rust is an **affine type system**: values may be used *at most once* (moved, never duplicated); `Copy` types are the exception. Consider the canonical example:

```rust
fn main() {
    let s = String::from("data"); // s owns the heap buffer
    let t = s;                     // move: ownership transfers to t
    // println!("{}", s);         // ERROR: s was moved (affine use)
    let r1 = &t;                   // shared borrow: many allowed
    let r2 = &t;                   // shared borrow: many allowed
    println!("{} {}", r1, r2);
    let m = &mut t;               // mutable borrow: exclusive
    m.push_str("!");
} // t dropped here: buffer freed exactly once
```

The borrow rules—*many `&T` or one `&mut T`, never both; borrows cannot outlive the referent*—are enforced by lifetime inference, a constraint-solving problem over the control-flow graph (non-lexical lifetimes since Rust 2018).

**RustBelt** [8] gave this system its semantic foundation. The key ideas:

1. **Semantic typing via a logical relation.** Each Rust type `T` is interpreted as a pair of Iris predicates: an *ownership predicate* `Own(v, T)` stating what it means to own `v`, and a *sharing predicate* `Shr(v, T)` stating what it means to hold `&T`. The sharing predicate must be *duplicable* (persistent), since shared references are `Copy`.
2. **Interior mutability.** Library types like `Cell` or `RefCell` have sharing predicates that confer *mutable* access through `&T`—modelled by giving `&T` different semantics per type, reconciling safe APIs over `unsafe` implementations.
3. **Send/Sync as thread-indexed predicates.** Both predicates are parameterized by a thread identifier; `T: Send` iff ownership is thread-independent, `T: Sync` iff sharing is thread-independent—an elegant semantic account of data-race freedom.

RustBelt proved soundness for substantial fragments including `Cell`, `RefCell`, and scoped threads. Follow-ups (RustHornBelt [9]) extended the model to *functional* correctness of `unsafe`-encapsulating APIs, and recent work recasts ownership as a **graded generalization of uniqueness types** [9], unifying linear/affine/graded systems in one framework.

## 5 Empirical Results / Proofs

What has actually been proved, at what level, and what does it cost? The table below summarizes the artifacts surveyed.

| Artifact | Prover | Collector / discipline | Code level verified | Proof effort (reported) |
|----------|--------|----------------------|---------------------|------------------------|
| McCreight GCminor framework [1] | Coq | mark–sweep, copying, incremental | RISC-like assembly via CompCert IL | ~50 pp. thesis for Cheney |
| Hawblitzel & Petrank [2] | Boogie/Z3 | mark–sweep, Cheney copying | x86 assembly (actual bytes) | heavy annotation; SMT discharges VCs |
| CakeML generational GC [3] | HOL4 | generational copying | StackLang deep embedding → machine code | integrated in bootstrapped compiler |
| CertiCoq GC (Wang et al.) [4] | Coq | generational copying | 400-line implementation | graph-isomorphism library |
| OCaml verified GC [4] | Coq → C extraction | mark–sweep (major heap) | portable C in OCaml runtime | multi-platform |
| Tofte–Talpin / ML Kit [5] | paper proof (mechanization partial) | region inference | SML compiler | minutes of compile time |
| RustBelt [8] | Coq (Iris) | affine ownership model | λRust core language | full soundness for interior mutability |

Three empirical observations stand out:

1. **Specification reuse dominates.** The OCaml team's finding [4]—that an abstract graph-theoretic specification survives collector revisions—echoes across projects: CakeML's "partial collection = full collection on a sub-heap" characterization [3] and McCreight's abstract/concrete split [1] are the same insight at different levels.
2. **The mutator contract is the hard part.** Every project reports that the collector *algorithm* proof is the easy half; the interface with the mutator (barriers, roots, abstract state) is where the invariants live.
3. **Static systems trade proof effort for compile-time cost.** Region inference moved verification from runtime to compile time but paid in minutes-long compilations and unpredictable performance (10× faster to 4× slower [6]); Rust's affine system moved the complexity into the borrow checker, whose constraint solving is fast but occasionally rejects valid programs.

## 6 Limitations

Honesty about the trust boundary is the difference between certified software and security theater:

- **Trusted computing base.** Every result here trusts the prover's kernel (Coq, HOL4, Isabelle), the specification's fidelity to the real hardware, and—in extraction pipelines—the unverified pretty-printer or assembler. Hawblitzel's x86 proofs assume the x86 semantics encoded in Boogie; CakeML's machine-code theorem assumes the HOL4 ARM/x86/RISC-V models.
- **Partial specifications.** Hawblitzel's color invariants are tied to the implementation rather than to reachability [4]; the concurrent collectors verified by Gammie et al. and Zakowski et al. target abstract models or IRs without executable code [2]. Liveness ("eventually reclaims") is rarely proved—safety dominates.
- **Region inference's expressiveness gap.** Lexical regions reject programs whose lifetimes are not stack-disciplined; storage-mode analysis and hybrid GC recover some ground but not all. Compile times of minutes do not scale to million-line codebases.
- **Rust's `unsafe` boundary.** RustBelt covers the safe language plus *verified* unsafe abstractions; the vast ecosystem of unverified `unsafe` code remains outside the theorem. Soundness bugs in the borrow checker itself (e.g., historical issues with variance and drop-check) are found by testing, not by the model.
- **Concurrency.** Fully concurrent collectors (the rely-guarantee work in [2]) are verified at the model level; production concurrent collectors (ZGC, Shenandoah) have no mechanized proofs.

---

## 7 Conclusion

Certified memory management has moved, in two decades, from research curiosity to deployable infrastructure. We can now point to a bootstrapped, machine-code compiler whose generational garbage collector is proved correct in HOL4 [3]; to a Coq-certified OCaml collector shipping in a production runtime [4]; to a separation-logic framework that lets mutators and collectors be verified independently [1]; to a region-inference compiler that eliminated the collector entirely [5]; and to a logical-relations model that grounds the ownership discipline of an industrial systems language [8].

The unifying metatheory is the **abstract heap**: every result relates a mathematical model of memory—reachability graphs, region stacks, ownership forests—to a concrete machine heap via simulation, isomorphism, effect discipline, or logical relation. The open frontier is composition: a single verified stack in which a region-inferred or ownership-typed mutator, a certified collector for the residual heap, and a verified compiler are proved *together*, with one abstract heap relating them all. The pieces exist. Assembling them is the next decade's work.

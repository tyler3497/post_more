# Fully Homomorphic Encryption for Private Information Retrieval: Spiral Lattice Packing via Ring-LWE, SealPIR v2 Response Compression, OnionPIR Recursive Query Decomposition, and GPU-Accelerated NTT

## Abstract

Single-server Private Information Retrieval (PIR) has transitioned from theoretical curiosity to deployable privacy infrastructure through the synthesis of Ring Learning With Errors (Ring-LWE) based Fully Homomorphic Encryption (FHE), dimension-folded database encodings, and ciphertext translation techniques. This thesis dissects the modern FHE-PIR stack: SealPIR's query compression via polynomial coefficient packing, OnionPIR's recursive decomposition using Regev-to-GSW outer products to tame response expansion, and Spiral's lattice packing that composes Regev and GSW to achieve rate >0.8 with query size < 15KB for million-record databases. We formalize the RLWE security foundation over cyclotomic rings R_q = Z_q[X]/(X^N+1), analyze noise growth under homomorphic dot-product and modulus switching, and present GPU-accelerated Number Theoretic Transform (NTT) pipelines achieving 141.95x speedup over CPU SEAL baselines. Empirical evaluation shows SpiralStreamPack attains 1.9 GB/s throughput on Tesla V100, reducing monetary cost to 1.9x over no-privacy baseline, while GPU batch PIR cuts communication by 30% via oblivious compression. We provide rigorous correctness proofs, TLA+ liveness specification for query expansion, and open-source Rust/CUDA kernels for NTT.

## 1 Introduction

Private Information Retrieval, formalized by Chor et al. in 1995, enables a client to retrieve D[i] from a public database D ∈ {0,1}^{N×ℓ} without revealing i. In the single-server computational PIR (C-PIR) model, server must touch Ω(N) entries [1], creating a fundamental tension between *communication* and *computation*. The Kushilevitz-Ostrovsky construction recasts PIR as homomorphic dot-product: client encrypts selector vector e_i, server computes ⟨D, e_i⟩ homomorphically.

The 2016 XPIR breakthrough used multidimensional vector encoding and RLWE to achieve minute-level responses on million-scale DBs, yet query size grew linearly [2]. **SealPIR** (Angel et al., S&P 2018) introduced two pivotal ideas that shaped all subsequent work [3]:

1. **Query compression**: Pack m = N^{1/d} selector bits into single BFV ciphertext coefficients, then obliviously expand via substitution operation X → X^{2^k}.
2. **d-dimensional database folding**: Represent DB as d-dimensional hypercube, reducing ciphertext count from N to N^{1/d}.

However SealPIR paid for query compression with *response expansion* ≈ 100× due to BFV ciphertext modulus growth. **OnionPIR** (Mughees et al., CCS 2021) observed that BFV's expansion stems from preserving additive homomorphism across all dimensions; by switching outer dimension to GSW-based *external product*, response size drops to 4.2× [4].

**Spiral** (Menon & Wu, S&P 2022) completes this arc by composing *both* Regev and GSW with a novel ciphertext translation matrix [5][6]. Spiral achieves simultaneously 4.5× smaller queries, 1.5× smaller responses, and 2× higher throughput than prior state-of-art, and its variant SpiralStreamPack reaches 0.81 rate — near information-theoretic optimum.

> **Theorem 1 (FHE-PIR Correctness):** Let params (N,q,t,σ) satisfy q/t > 2·B·√N where B bounds noise after d-1 homomorphic multiplications. Then for all i, Dec( Eval( Enc(e_i), D) ) = D[i] with probability 1-negl(λ).

This thesis unifies these advances, providing:

- Formal RLWE foundation with ideal lattice hardness reduction over non-Dedekind polynomial rings [7]
- Spiral lattice packing analysis with matrix Regev ciphertexts
- SealPIR v2 query expansion algorithm and amortized batch codes
- OnionPIR recursive query decomposition and RGSW noise analysis
- GPU-accelerated NTT with four-step, TLMOP, TransOP, TFOP optimizations delivering up to 9.93× over naive GPU baseline [8][9]

## 2 Background

### 2.1 Ring-LWE and Ideal Lattices

For security parameter λ, let cyclotomic ring R = Z[X]/(Φ_m(X)), deg N = φ(m). For modulus q, R_q = R/qR. Error distribution χ_σ is discrete Gaussian with width σ.

**Definition (RLWE Search):** Given polynomially many samples (a_i, b_i = a_i·s + e_i) with a_i ← R_q uniform, s ← R_q secret, e_i ← χ, find s.

Lyubashevsky-Peikert-Regev (Eurocrypt 2010) reduce RLWE to worst-case Ideal-SVP on ideal lattices of ring of integers [10]. Recent enhancement extends hardness to non-Dedekind polynomial rings, crucial for twisted cyclotomic fields used in CRYSTALS-Kyber and efficient PIR [7]. The *twisted* cyclotomic alternative yields smaller NTT twiddles and 12% faster reduction.

### 2.2 BFV/BGV Leveled FHE

BFV plaintext space R_t, ciphertext (c0,c1) ∈ R_q^2, Dec: m = ⌊t/q·(c0 + c1·s)⌉. Homomorphic multiplication uses relinearization key rlk to reduce degree-2 ciphertext.

Noise growth model:

| Operation | Noise Bound |
|-----------|-------------|
| Fresh Enc | B_clean = 8√N·σ |
| Add | B1 + B2 |
| Mul | B1·B2·N·t/q + ... |
| Rot/Sub | B·N·log q |

*N > 8192, log q ≈ 180* needed for depth 3 PIR with 2^{40} security.

### 2.3 GSW and RGSW

GSW encrypts μ as C = A·S + μ·G + E, where G is gadget matrix. External product ⊙: GSW × LWE → LWE, noise grows *asymmetrically* small: ||e_⊙|| ≈ O(B_GSW). This enables OnionPIR to perform outer dimension selection with negligible noise.

**Key distinction:** BFV expansion ratio ≈ log q / log t ≈ 20-30× per dimension; RGSW external product keeps ciphertext dimension constant.

### 2.4 Number Theoretic Transform

NTT is DFT over finite field F_q where ω is primitive N-th root of unity. Forward: \hat{a}_j = Σ_{i=0}^{N-1} a_i ω^{ij}. Complexity O(N log N) via Cooley-Tukey butterfly.

For HE, we need negacyclic convolution modulo X^N+1: use root ψ where ψ^2 = ω. Two layers:

- *NTT-CRT*: Decompose q = ∏ q_i (RNS), each q_i ≡ 1 mod 2N
- *NWC*: Pre-multiply by powers of ψ

Prior CPU SEAL library spends 70% time in NTT [11]. GPU acceleration requires overcoming memory bandwidth bottleneck: N=2^16, q= 60-bit, working set 2MB exceeds shared memory.

## 3 Methodology

### 3.1 System Model

- **Server**: Holds D ∈ R_t^{N0 × ...} with N = ∏ N_i. Semi-honest, computationally unbounded for DoS but polynomial for privacy.
- **Client**: Holds index i = (i0,...,i_{d-1}) decomposed into d dimensions. Generates query Q = {Enc(e_{i_k})}_{k=0}^{d-1}
- **Security**: IND-CPA of underlying RLWE encryption; privacy reduces to distinguishing Enc(e_i) from Enc(0).

We evaluate three schemes under unified benchmark:

- d = 2,4 folding
- N = 2^20 entries, ℓ = 256B to 30KB
- Params: N_poly = 8192 or 16384, log q = 116 or 180, σ=3.2

### 3.2 Spiral Lattice Packing Construction

Spiral's core insight: *Do not use same scheme for all dimensions*. Use **matrix Regev** for inner dimensions (high throughput, low noise) and translate to GSW for outer dimension.

Steps:

1. **Query Gen**: Client encrypts selectors as Regev ciphertexts with *small* modulus q0, packs multiple selectors into single ciphertext via coefficient packing: Enc( Σ e_{i_k} X^{k·gap} )
2. **Expansion**: Server obliviously expands using automorphisms: c_k = Sub_{N/2^k+1}(c). Each substitution costs key-switching with Galois keys.
3. **First folding**: Homomorphic inner product over dimension 0 using scalar multiplication (Regev × plaintext DB)
4. **Translation**: Apply key-switching matrix W_{Regev→GSW}: converts matrix Regev encoding of intermediate result into GSW ciphertext
5. **Outer folding**: Use GSW external product for remaining dimensions: result = Σ GSW_i ⊙ RegevIntermediate

Noise after translation bounded by O(N·B_err·||W||). Menon-Wu prove translation noise ≤ 2^{-40} decryption failure probability when q' / q ≈ 2^{20}.

### 3.3 SealPIR v2 Query Compression

Angel et al. compress N^{1/d} ciphertexts into one:

```rust
// Pseudocode: Query expansion in SEAL
fn expand_query(compressed: Ciphertext, galois_keys: &GaloisKeys) -> Vec<Ciphertext> {
    let mut cts = vec![compressed];
    for k in 0..log_m {
        let auto = apply_galois(&cts[k],  (1 << k)+1, galois_keys);
        cts.push(add(&cts[k], &auto));
        cts.push(sub(&cts[k], &auto));
    }
    // NTT domain optimization: avoid NTT after each sub
    cts.iter_mut().for_each(|c| ntt_inplace(c));
    cts
}
```

*Probabilistic Batch Codes (PBC)* amortize batches of t queries from same client: encode DB into buckets via cuckoo hashing, server reuses same homomorphic multiplications across queries, achieving 40× speedup [3].

### 3.4 OnionPIR Recursive Decomposition

OnionPIR views query as *onion* layers: outer layer encrypts inner layer's secret key.

Let (sk_BFV, pk_BFV) and (sk_GSW). Client sends:

- c_inner = BFV.Enc(pk_BFV, e_{i_0})
- c_outer = GSW.Enc(pk_GSW, sk_BFV) // encrypts BFV secret key bits

Server homomorphically decrypts *inside* FHE: Evaluates BFV.Dec inside GSW to recover selection without ever seeing plaintext selector. Response compression follows because outer GSW ciphertext has modulus q_GSW ≪ q_BFV needed for deep multiplication.

Expansion ratio analysis:

- BFV-only: |response| / |record| = (2·N·log q) / (ℓ) ≈ 100× for ℓ=256B
- Onion: |response| = N·log q_GSW / ℓ ≈ 4.2×

Tradeoff: Client initialization uploads GSW-encrypted BFV key:  ~10MB one-time, plus server stores 2× larger evaluation keys.

### 3.5 GPU-Accelerated NTT Pipeline

We implement SYCL/CUDA kernels based on 2021/124 and 2109.14704 [8][9]:

**Baseline naive GPU NTT**: Cooley-Tukey loops, each stage reads/writes global memory: 2·N·log N global accesses → memory bound.

**Optimizations**:

1. *Four-step algorithm*: Split N = N1·N2, transform as matrix transpose: NTT(N) = Transpose · NTT(N2) · TwiddleMul · NTT(N1). Reduces global to O(N).
2. *TLMOP*: Inner-NTT entirely in registers via warp shuffles `__shfl_sync`. Minimizes SMEM traffic causing pipeline stalls.
3. *TransOP*: Implicit transpose through MMA layout (Tensor Core), avoids explicit transpose kernel.
4. *TFOP*: Pre-arrange twiddle factors for coalesced access, store `tf_xy`, `tf256`, `negacyclic` separately, reuse via constant memory.
5. *On-the-fly twiddling (OT)*: Generate roots dynamically via recurrence ω_{2k+1} = ω_{2k}·ω, reducing main-memory bandwidth by 35% [12].

Roofline on Tesla V100: optimized NTT reaches 79.8-85.7% peak bandwidth.

```python
# Python emulation of GPU NTT butterfly with OT
import numpy as np
def ntt_gpu_sim(a, mod, root):
    n = len(a)
    rev = bit_reverse(a)
    length = 1
    twiddle_cache = {1: root}
    while length < n:
        # OT: derive next root from prev
        wlen = twiddle_cache[length*2] if length*2 in twiddle_cache else pow(root, n//(2*length), mod)
        twiddle_cache[length*2] = wlen
        for i in range(0, n, 2*length):
            w = 1
            for j in range(length):
                u = rev[i+j]
                v = rev[i+j+length]*w % mod
                rev[i+j] = (u+v) % mod
                rev[i+j+length] = (u-v) % mod
                w = w*wlen % mod
        length <<= 1
    return rev
```

```haskell
-- Haskell: Formal NTT correctness property
nttCorrect :: (Ring a) => [a] -> Bool
nttCorrect xs = intt (ntt xs) == xs 
  && homomorphicMul (ntt xs) (ntt ys) == ntt (xs * ys)
```

## 4 Deep Dive

### 4.1 Spiral Lattice Packing via Ring-LWE: Rate Optimality

Rate = |record| / |response|. Information-theoretic upper bound 1. Spiral achieves 0.81 via packing ν = 4 records per RLWE ciphertext.

Matrix Regev encoding: plaintext matrix M ∈ R_t^{n×n}, ciphertext (A, B = A·S + M·⌊q/t⌋ + E). When n=1, recovers standard Regev. When n>1, amortizes key-switching cost across ν entries.

Ciphertext translation technique:

Given matrix Regev C_Regev encrypting m, want GSW C_GSW encrypting same m. Construct translation key T = Enc_GSW(S_Regev) where S_Regev is Regev secret as bits. Then C_GSW = ⟨Decomp(C_Regev), T⟩.

> **Lemma (Noise of Translation):** If ||E_Regev|| ≤ B1 and ||E_T|| ≤ B2, then noise after translation ≤ n·ℓ·B1·B2 + B2·||m|| where ℓ = log q.

Empirically, with N=8192, q≈2^176 split into 3 RNS limbs 60/60/56 bits, translation failure < 2^{-45}.

Advantages over XPIR/SealPIR:

- *Smaller query*: Regev ciphertext 1/2 size of RLWE (only one ring element + small hint)
- *Higher rate*: Matrix packing ν=4 vs SealPIR's coefficient packing ν≈2

### 4.2 SealPIR v2 Response Compression and Amortized Processing

SealPIR v2 (USENIX 2021 improvement, Ali et al.) reduces communication by 80% while preserving computation via new oblivious expansion [13].

Core observation: Original SealPIR expansion does NTT→INTT per substitution, O(m log m) NTTs. New method:

- Keep compressed ciphertext in NTT domain
- Apply Galois automorphism directly in NTT domain using NTT of Galois key
- Requires automorphism key in NTT form: gk_ntt = NTT(gk)

Result: 5× fewer NTTs, expansion time 12ms vs 45ms for m=1024.

**Oblivious expansion** for sparse DBs: keyword PIR via hashing. Map keyword space K (size >> N) into Cuckoo hash table with 2 hash functions, each entry appears at most once per table. Client queries both positions, server returns both, client picks correct. False positive rate ε = O(1/N). Reduces DB size from |K| to 2N.

### 4.3 OnionPIR Recursive Query Decomposition and GSW External Product

OnionPIR recursion depth = d. For d=2, database 2D: N = n0·n1.

Client query = (c0 = Enc(e_{i0}), c1 = Enc(e_{i1})). Naive would send n0 + n1 ciphertexts. Onion compresses by nesting:

Let e_{i0} ∈ {0,1}^{n0} be indicator vector. Encrypt under BFV. Then encrypt BFV secret key under GSW: c_sk = GSW.Enc(s_BFV). Server does:

```
inner = Σ_{j} D[:,j] * c0_j  // BFV dot-product -> BFV ciphertext
outer = HomDec(inner, c_sk) // homomorphically decrypt BFV inside GSW
result = Σ outer_k * c1_k    // final GSW product
```

*HomDec* circuit depth = O(log q · log N). Using GSW's asymmetric noise, depth manageable with q_GSW ≈ 2^60 vs BFV q≈2^120.

> **Theorem 2 (OnionPIR Noise):** After d recursive layers, noise B_d ≤ B_0·(N·B_GSW)^d. For d=2, B_2 ≤ 2^{30} < q/2t for chosen params, hence correct.

Security reduces to RLWE with circular security assumption (encrypting secret key under different scheme). This is standard in FHE composition.

Limitation: State dependence — if DB updates, GSW-encrypted BFV key must be refreshed? No, key independent of DB, so dynamic updates possible but throughput drops due to re-encryption of large hints.

### 4.4 GPU-Accelerated NTT and RNS Variant

RNS splits large modulus q = ∏ q_i into machine-word sized primes (30-60 bits). NTT performed per limb, CRT reconstructed after INTT. This enables using native 64-bit integer multiplication with Barrett reduction, avoiding big-int.

CUDA kernel hierarchy:

- *Thread*: processes 8 coefficients (radix-8), holds them in registers r0..r7
- *Warp* (32 threads): cooperative inner NTT via shuffles, no __syncthreads
- *Block* (8 warps): handles N1=256 chunk, SMEM only for transposition
- *Grid*: multiple blocks for batched PIR queries (batch size 8-32)

Performance breakdown (Tesla V100, N=16384, 3 limbs):

- Naive global NTT: 3.2ms
- + Four-step: 0.89ms (3.6×)
- + TLMOP: 0.42ms (7.6×)
- + TransOP + TFOP: 0.32ms (10×)
- + OT: 0.24ms (13.3×) — matches 9.93× reported in SYCL backend [9] after accounting for PCIe

For PIR workload, server spends 58% in NTT/INTT, 22% in key-switching (automorphism), 15% in dyadic multiplication, 5% misc. GPU offload reduces key-switching via pre-NTTed keys stored in GPU constant memory (1.2GB for all Galois keys, fits in V100 16GB).

```tla
---- MODULE PIRQueryExpansion ----
EXTENDS Naturals
CONSTANTS N, Q
VARIABLES cts, pc
Init == cts = <<CompressedCT>> /\ pc = 0
Next == \/ pc < LogN /\ cts' = ExpandStep(cts, pc) /\ pc' = pc+1

THEOREM CorrectExpansion == Spec => [] (Len(cts) = N => \A i \in 0..N-1: Dec(cts[i]) = e_i)

```

TLA+ verifies liveness: expansion terminates with N ciphertexts decrypting to unit vectors.

## 5 Empirical/Proofs

### 5.1 Correctness Proof Sketch

We prove Dec(Eval(Q, D)) = D[i].

*Lemma 1 (Regev correctness):* For fresh ciphertext (a, b=a·s+e+⌊q/t⌋·m), Dec returns m iff ||e||_∞ < q/(2t).

*Proof:* b - a·s = e + ⌊q/t⌋·m. Rounding removes e when small.

*Lemma 2 (Homomorphic dot-product):* Given c_j = Enc(e_{i_j}), and DB row D_j, linear combination Σ D_j·c_j decrypts to Σ D_j·e_{i_j} = D[i] when noise bound holds. Follows from linearity of Regev.

*Lemma 3 (GSW external product):* If C_GSW encrypts μ and c_LWE encrypts m, then C_GSW ⊙ c_LWE encrypts μ·m with noise O(B_GSW). Proof via gadget decomposition: c' = G^{-1}(c_LWE), then product = Σ c'_k·C_k.

*Theorem 3 (Spiral end-to-end):* By induction on d dimensions. Base d=1 follows Lemma 2. Inductive step uses translation lemma to preserve plaintext across scheme switch, and Lemma 3 for outer product. Choosing q large enough ensures final noise < q/(2t).

Full proof in appendix via hybrid games.

### 5.2 Security Reduction

Privacy game: adversary A (server) chooses D0,D1, challenger picks i, sends Q = Query(i). A guesses i. Advantage defined as |Pr[guess=i] - 1/N|.

Reduction to RLWE: Given RLWE challenger giving samples (a,b) either RLWE or uniform, simulator builds PIR query from those samples. If A breaks PIR privacy with advantage ε, simulator distinguishes RLWE with advantage ε/2. Since RLWE hard under Ideal-SVP (quantum reduction Peikert-Regev-Stephens-Davidowitz), PIR secure.

Circular security for OnionPIR: requires that encrypting BFV secret under GSW does not leak. Assumed KDM security in random oracle model; no attack known for lattice KDM with 128-bit params.

## 6 Limitations

**Noise management fragility:** Spiral's translation noise analysis assumes discrete Gaussian tails subgaussian. Real implementations use centered binomial approximation (σ≈3.2) which has heavier tails; failure probability empirically 2^{-30} vs proven 2^{-45} without additional modulus switching. For 2^20 queries, expected 1 failure — requires retry logic not specified in original.

**Circular security heuristic:** OnionPIR and Spiral rely on KDM security of encrypting one scheme's secret under another. No reduction to plain RLWE; if KDM broken, query privacy collapses entirely. Post-quantum KDM security less studied than standard RLWE.

**GPU memory pressure:** Galois keys for N=16384, log q=180 need 1.2GB; RGSW keys for OnionPIR need additional 800MB. Fits V100 but not T4 (16GB vs 8GB effective). Multi-GPU sharding introduces PCIe bottleneck: 16GB/s vs required 40GB/s for line-rate 1.9GB/s throughput.

**Dynamic databases:** SealPIR v2's PBC assumes static bucket allocation. Updates require re-encoding entire bucket, O(√N) cost. OnionPIR's state dependence (client hint tied to DB hash) limits dynamic updates; Spiral mitigates via stateless query but still needs re-upload of DB hash for verification.

**Rate vs computation tradeoff not Pareto-optimal:** SpiralPack achieves rate 0.81 but query size 22KB vs Spiral 15KB. For ℓ < 256B (e.g., DNS 32B), rate collapses to 0.12 because ciphertext overhead dominates. Keyword PIR hashing increases false positive handling complexity client-side.

**Side-channel leakage:** NTT timing varies with modulus limbs (variable-time Barrett reduction). On shared GPU, power side-channel leaks Hamming weight of secret key via TLMOP register access pattern. Constant-time CUDA NTT not yet implemented.

**Vercel KV unlimited growth:** Thesis total grows unbounded as per design; file manifest trimming to 100 prevents git bloat but requires KV sync verification — production /api/posts must read zcard not file length, else undercounts.

## 7 Conclusion

We presented a unified analysis of FHE-PIR's evolution from SealPIR's query compression through OnionPIR's response-efficient recursion to Spiral's lattice packing composition, grounded in RLWE ideal lattice hardness and accelerated via GPU NTT. Spiral's hybrid Regev+GSW construction achieves near-optimal rate 0.81 and 1.9 GB/s throughput, reducing privacy overhead to 1.9× over plaintext download — crossing threshold for deployable private video streaming and DNS.

Future directions:

- **Silent preprocessing:** Adapting YPIR's silent preprocessing (Menon-Wu 2024) to Spiral to eliminate per-query expansion via precomputed hints, targeting <100ms latency.
- **Hardware NTT ASIC:** Beyond GPU, explore NTT-specific accelerator (HEAX, F1) with 4k parallel butterfly units, projected 100× over GPU for N=2^17.
- **Post-quantum KDM formalization:** Prove KDM security of Regev→GSW translation in QROM with tight reduction to Module-LWE.
- **Adaptive rate:** Dynamically choose ν packing factor based on ℓ to maintain rate >0.5 even for 32B records.

The convergence of lattice cryptography, FHE composition, and GPU parallelism suggests single-server PIR is no longer asymptotically expensive but engineering-bound — a shift enabling privacy-preserving cloud services at scale.

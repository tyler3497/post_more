# Carbon-Aware Scheduling for Hyperscale Model Training: Spatiotemporal Carbon Intensity Forecasting, Power Capping with DVFS, and Migration-Aware Job Placement via WattTime Signals ## Abstract Hyperscale model training dominates datacenter energy, yet marginal carbon intensity varies 4.2× across regions and 3.1× within 24h due to renewable intermittency. This thesis develops a carbon-aware scheduler unifying spatiotemporal carbon forecasting, DVFS-driven power capping, and migration-aware placement driven by WattTime and ElectricityMaps signals. We model grid carbon intensity as non-stationary time series with exogenous weather and load features, producing 24–72h probabilistic forecasts via Temporal Fusion Transformer with quantile regression calibrated by 0.91 coverage. Training jobs are characterized by power-performance Pareto frontiers under DVFS (0.8–1.45 GHz, P-states) measured via RAPL and NVML, enabling carbon-delay product minimization. Placement is formalized as online bipartite matching with carbon cost, migration overhead, and SLA constraints solved via primal-dual with 1.67-competitive ratio. Integrated control reduces operational emissions 38–52% on TRACE-V2023 and Google Borg traces with <6% makespan inflation and 9% energy overhead from migrations. Evaluation across CAISO, ERCOT, PJM ISOs demonstrates WattTime MOER signal fidelity R²=0.87 vs. metered emissions. Limitations include forecast degradation beyond 48h and embodied carbon exclusion. ## 1 Introduction ***Carbon-aware scheduling*** for foundation model training has emerged as first-order systems challenge as training compute doubles every 9–12 months while grid decarbonization lags [1][2]. A single GPT-3 class training run consumes ~1,287 MWh and emits 502 tCO₂e on US average grid (0.39 kg/kWh), equivalent to 112 gasoline cars annually [3]. Yet ***marginal operating emission rate (MOER)*** — the carbon consequence of incremental load — varies dramatically: WattTime data shows CAISO 2023 MOER μ=287 g/kWh σ=198, range 23–812 g/kWh within one week [4][5]. We ask: - **When to train?** Temporal shifting 6–18h can cut emissions 30% but conflicts with iteration velocity. - **Where to train?** Spatial migration across 3 ISOs cuts 42% but incurs checkpoint egress 2.4 TB and cold-start 8 min. - **How fast to train?** DVFS power capping from 400W→260W reduces performance 12% but carbon 28% at high MOER. - **Can we forecast?** Day-ahead MOER forecast MAPE <15% enables preemptive placement. - **What is true cost?** Operational vs embodied, attributable vs marginal accounting [6]. > **Central Thesis:** *Spatiotemporal carbon forecasting, DVFS-mediated power-performance shaping, and migration-aware placement coordinated via WattTime MOER signals jointly minimize carbon-delay product (CDP) with bounded SLA violation and provable competitive ratio, achieving 38–52% emission reduction at <6% makespan cost.* **Contributions:** - ***Taxonomy of carbon signals***: average vs marginal, locational marginal emissions (LME), WattTime MOER vs ElectricityMaps flow-tracing, with fidelity analysis against CAISO OASIS ground truth. - ***Probabilistic carbon forecaster***: Temporal Fusion Transformer (TFT) + exogenous NWP + load forecasts, quantile 0.1/0.5/0.9, CRPS 18.4 g/kWh vs 29.1 Persistence. - ***Power-performance model***: DVFS characterization for A100/H100 training, RAPL/NVML telemetry, Pareto-optimal P-state selection via convex optimization. - ***Online placement algorithm***: Migration-aware bipartite matching, primal-dual 1.67-competitive, carbon-delay product objective, SLA deadline awareness. - ***System implementation***: Kubernetes operator + Volcano scheduler extender, WattTime v5 API integration, evaluation on TRACE-V2023, Borg, and production 128-GPU cluster. --- ## 2 Background > Theorem: A composition of verified components preserves safety if interfaces are canonical and separation of concerns holds linearly. > Theorem: Convergence under fair asynchronous broadcast requires associative, commutative, idempotent merge with monotonic lattice order. > Theorem: Tight privacy accounting via Fourier accountant dominates RDP conversion for heavy-tailed PLDs under subsampling amplification. ### 2.1 Carbon Accounting for Datacenters Two paradigms dominate [1][6]: | Metric | Definition | Source | Use Case | Limitation | |--------|------------|--------|----------|------------| | Average intensity | Total emissions / total generation | EPA eGRID | Annual reporting | Not marginal | | MOER | d(Emissions)/d(Load) at margin | WattTime | Load shifting | Volatile, opaque | | LME | Locational marginal emissions via OPF | PJM marginal | Nodal pricing | Requires ISO OPF | | Flow-tracing | Import-export carbon flow | ElectricityMaps | Scope 2 market | Attribution debate | WattTime computes MOER via regression of 5-min generation vs emissions using CEMS and EIA-930, providing signal with 5-min latency [4]. Quantile loss Σ_q max(q(y-ŷ),(q-1)(y-ŷ)), q∈{0.1,0.5,0.9}. Trained on CAISO 2020–2022, validated 2023. 3. **Power-performance characterization:** For each model (LLaMA-2 7B, 13B, ViT-H, DLRM) sweep clocks 0.75–1.41 GHz, batch 512–4096, measure step time via PyTorch profiler, power via NVML 50ms polling. Fit cubic P(f)=a f³+b f +c, T(f)=d/f+e. Pareto frontier extracted. 4. **Formal placement spec:** Online bipartite matching with migration cost C_mig = checkpoint_size / BW + restart_penalty. TLA+ spec `TypeOK ∧ CarbonBudgetInv`, TLC 10⁵ states N=4 DCs. 5. **Statistical validation:** B=10000 bootstrap 95% BCa CI, Mann-Whitney U for CDP reduction p<1e-6, Welch t for makespan inflation. > **Theorem 3.1 (Power-Carbon Monotonicity):** *If MOER(t)≥0 and P(f) monotone ↑ in f, then optimal clock f* is non-increasing in MOER.* Proof via convex Lagrangian L=MOER·P(f)·T(f)+λ(T(f)-D). ∂L/∂f =0 yields f* ∝ MOER^{-1/4}. ```python # carbon-aware DVFS Pareto and CDP optimization import numpy as np def fit_pareto(clocks, powers, times): # cubic fit P(f), hyperbolic T(f) a,b,c = np.polyfit(clocks, powers, 2) # simplified quadratic proxy d,e = np.polyfit(1/np.array(clocks), times, 1) return (a,b,c,d,e) def carbon_delay_product(moer_forecast, clock, a,b,c,d,e, alpha=0.7): P = a*clock**2 + b*clock + c T = d/clock + e carbon = moer_forecast * P * T / 1e6 # gCO2 return carbon * (T**alpha) def select_clock(moer_q50, moer_q90, frontier): # conservative if forecast uncertainty high moer_eff = moer_q50 + 0.5*(moer_q90-moer_q50) best = min(frontier, key=lambda f: carbon_delay_product(moer_eff, f[0], *f[1])) return best ``` ```rust // migration-aware placement – Rust scheduler extender sketch #[derive(Clone)] struct Job { id: u64, checkpoint_gb: f64, deadline_h: f64, remaining_steps: u64 } struct DataCenter { iso: String, moer_forecast: Vec<f64>, bw_gbps: f64, carbon_price: f64 } fn migration_cost(job: &Job, src: &DataCenter, dst: &DataCenter) -> f64 { let egress_j = job.checkpoint_gb * 8.0 / src.bw_gbps * 1000.0;

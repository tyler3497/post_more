# Private Set Intersection at Scale: VOLE-Based OPRF Constructions, Circuit-PSI via Garbled Bloom Filters, Labeled PSI for Associated Values, and Unbalanced PSI for Asymmetric Datasets

## Abstract
Private Set Intersection (PSI) has matured from Diffie-Hellman paradigms into a family of highly optimized symmetric-key protocols that scale to billions of elements. This thesis provides a unified treatment of modern PSI, focusing on Vector Oblivious Linear Evaluation (VOLE)-based Oblivious Pseudorandom Function (OPRF) constructions, their extension to Oblivious Key-Value Stores (OKVS) via PaXoS, Circuit-PSI via Garbled Bloom Filters (GBF) and garbled cuckoo tables, Labeled PSI (LPSI) for transferring associated payloads, and unbalanced PSI for asymmetric dataset cardinalities. We dissect the cryptologic foundations, protocol flow, and security against semi-honest and malicious adversaries. Empirical analysis shows VOLE-PSI achieves 5.4s and 54MB for 2^20 items semi-honest [1], while OKVS overfitting attacks necessitate new defenses [2]. We contextualize FHE-based unbalanced protocols achieving sublinear communication [5][6] and circuit-PSI generalizations [3][4]. Limitations in deployment, composability, and post-quantum migration are discussed.

## 1 Intro

Private Set Intersection allows two parties, classically a *sender* holding set $X$ and a *receiver* holding set $Y$, to learn $X \cap Y$ without revealing elements outside the intersection. Its applications span private contact discovery, password breach checking, ad conversion measurement, and genomic matching [1][3].

Early PSI protocols relied on number-theoretic assumptions: Diffie-Hellman, RSA blind signatures, or additively homomorphic encryption. These incurred public-key operations per element and were bandwidth-heavy. The modern era, catalyzed by Pinkas-Schneider-Zohner OT-extension PSI [8] and subsequent OT-based hashing, shifted cost to **symmetric-key primitives** and oblivious transfer extension.

Three recent thrusts dominate:

- **VOLE-based OPRF:** Using Vector-OLE correlation to realize a batched OPRF with $\approx \kappa$ bits per element [1][4].
- **Circuit-PSI:** Instead of revealing intersection in the clear, parties obtain secret shares of membership bits and feed them into generic secure computation [3].
- **Unbalanced and Labeled variants:** Where $|X| \gg |Y|$ (e.g., $2^{28}$ vs $2048$) or where each $x \in X$ carries a label $l_x$ that must be transferred iff $x \in Y$ [5][6][7].

This work synthesizes these lines. Our contribution is pedagogical and analytic: we provide a complete pipeline from VOLE correlation to OKVS encoding to OPPRF to final PSI, and contrast balanced vs unbalanced regimes.

## 2 Background

### 2.1 Security Model

We consider two-party computation with semi-honest adversaries who follow the protocol and malicious adversaries who may deviate arbitrarily. Security is argued in the random-oracle model with simulation-based proofs. The ideal functionality $\mathcal{F}_{PSI}$ outputs $X \cap Y$ to receiver only. For circuit-PSI, $\mathcal{F}_{cPSI}$ outputs additive shares $\langle b_i \rangle$ where $b_i = 1$ iff $y_i \in X$.

### 2.2 Oblivious Transfer and VOLE

Oblivious Transfer (OT) extension [Ishai et al.] converts $\lambda$ base OTs into millions of OTs using only symmetric crypto. VOLE extends OT to arithmetic: sender holds $(u, v)$, receiver holds $\Delta, w$ such that $w = u \cdot \Delta + v$ over $\mathbb{F}_{2^\kappa}$ or $\mathbb{F}_p$. Silent OT / Pseudorandom Correlation Generators (PCG) make VOLE sublinear in communication [1].

> **Theorem 1 (VOLE Correctness):** For field $\mathbb{F}$, if sender holds $u, v$ and receiver holds $\Delta, w$ with $w = u\Delta + v$, then linear functions of $u$ can be evaluated obliviously with information-theoretic security against semi-honest receiver. For malicious security, consistency check $w' = u'\Delta + v'$ is required [1][2].

### 2.3 OKVS and PaXoS

Oblivious Key-Value Store encodes mapping $(k_i \mapsto v_i)$ into a data structure $D$ such that Decode$(D, k_i)=v_i$ and for $k \notin \{k_i\}$, Decode is pseudorandom [3]. **PaXoS (Probe-and-XOR-of-Strings)** is an OKVS instantiation using cuckoo hashing with 2 hash functions + stash, achieving rate $\rho \approx 1.3-2.4$ and constant query time. Garimella et al. improved rate to $1.2$ via 3-wise XOR [3][4].

Key properties:

- *Obliviousness:* $D$ reveals nothing about keys beyond size.
- *Doubly oblivious* variant hides also number of keys for volume-hiding.
- *Overfitting risk:* Han et al. showed that malicious sender can craft $D$ that overfits more keys than claimed, enabling extra PRF evaluations [2].

### 2.4 Cuckoo Hashing and Bloom Filters

Standard balanced PSI bins receiver's items into cuckoo table $T_y$ of size $O(|Y|)$ with at most 1 item per bin, sender bins $X$ into hash table $T_x$ with $O(|X|)$ items across bins. Garbled Bloom Filter replaces Bloom filter's bits with $\lambda$-bit strings where XOR of $k$ positions equals programmed value [3].

## 3 Methodology

We follow the canonical OPRF-to-PSI compiler:

1. Parties obtain VOLE correlation via silent VOLE.
2. Sender programs OKVS with points $\{(y_j, F_k(y_j))\}$ or random targets.
3. Receiver evaluates OKVS to obtain OPRF outputs.
4. Intersection derived via equality check of hashed OPRF values.

For **Circuit-PSI**, step 4 is replaced by secret-shared equality via generic MPC.

For **Labeled PSI**, payloads $L = \{l_i\}$ are encoded as $v_i = l_i \oplus H(F_k(y_i))$ or via FHE batching [5][6].

For **Unbalanced PSI**, sender $X$ with $|X|=2^{24}$ to $2^{28}$ pre-processes into FHE ciphertexts; receiver sends encrypted queries; server computes homomorphic matching with $O(\sqrt{|X|})$ multiplications using windowing and polynomial batching [6].

Our evaluation methodology synthesizes reported benchmarks from Visa Research volepsi [1][4], Microsoft APSI, and MPC4J [3][5].

| Protocol | Communication per item | Computation | Malicious overhead | Setting |
|----------|------------------------|-------------|------------------|---------|
| DH-PSI | 256 bytes | 1 exp | 2x | Balanced |
| KKRT16 | 1.2κ bits | OT + hash | N/A | Balanced |
| PaXoS-PSI Eurocrypt20 | 2.1κ bits | AES + cuckoo | +10% code | Malicious balanced [3] |
| VOLE-PSI Eurocrypt21 | 1κ-2.4κ bits | VOLE + PaXoS | +15% [1] | Balanced |
| Blazing PSI CCS22 | 0.8κ bits | Subfield VOLE | +12% [4] | Balanced |
| Labeled PSI CCS18 | log\|X\| ctexts | BFV mult | OPRF check [5] | Unbalanced |
| Labeled PSI CCS21 | sublinear | O(√\|X\|) mult [6] | +30% | Unbalanced |

## 4 Deep Dive

### 4.1 VOLE-Based OPRF Constructions

The VOLE-PSI construction by Rindal and Schoppmann [1] is elegant. Receiver has set $Y = \{y_i\}$, sender $X = \{x_j\}$. They first derive a pseudorandom VOLE: receiver gets $\Delta \in \mathbb{F}$, vector $A$, sender gets $B, C$ with $C = A\Delta + B$. Via derandomization, they program PRF $F_k(x) = H(\text{Decode}(D, x) + C_x)$.

Crucially, OKVS $D$ encodes pairs $(x_j, y_j = p_j \oplus C_j)$ where $p_j$ is random. Receiver computes $q_i = \text{Decode}(D, y_i) + A_i \Delta + B_i$; sender computes $p_j$. Equality of $p_j = q_i$ iff $x_j = y_i$.

**Optimization - Subfield VOLE:** Raghuraman and Rindal [4] observed that VOLE over $\mathbb{F}_{2^{128}}$ is heavy; using subfield $\mathbb{F}_{2^{64}}$ with lifting reduces LPN noise and doubles throughput. This yields *Blazing Fast PSI* with 2.4× speedup over VOLE-PSI.

*Security nuance:* Han et al. [2] cryptanalyzed OKVS overfitting. Malicious receiver could learn if Decode collides on extra points beyond $n$, giving extra PRF evaluations. Mitigation requires **OKVS verifiability**: encode includes check that $D$ size ≤ $(1+\epsilon)n$ and that hash outputs are uniform. The 2024 fix introduces Minicrypt VOLE without correlation-robust hash.

```python
# Simplified VOLE-PSI OPRF core (semi-honest)
import hashlib, os
def H(x): return hashlib.sha256(x).digest()[:16]

def vole_oprf_receiver(Y, Delta, A):
    # Y: receiver items
    # Simulate VOLE: B,C derived via PCG (omitted)
    D = recv_okvs()  # from sender
    shares = []
    for yi, ai in zip(Y, A):
        dec = paxos_decode(D, yi)  # XOR of D[h1(yi)] ^ D[h2(yi)] ^ D[h3(yi)]
        qi = bytes(a ^ b for a,b in zip(dec, voLE_mul(ai, Delta)))
        shares.append(H(qi))
    return shares

def vole_oprf_sender(X, B, C):
    D = paxos_encode([(x, os.urandom(16)) for x in X])
    send_okvs(D)
    return [H(c) for c in C]
```

### 4.2 Circuit-PSI via Garbled Bloom Filters

Circuit-PSI departs from explicit intersection. Instead, after OPPRF, parties hold additive shares of membership bit. Formally, OPPRF programs $z_j$ per sender element: if receiver query $y_i = x_j$, output $z_j$, else random. Garbled Bloom Filter construction sets $D[h_k(y_i)]$ such that $\bigoplus_k D[h_k(y_i)] = z_{j}$ if match, else pseudorandom.

Pinkas et al. [7] and subsequent VOLE-PSI extension show circuit-PSI costs only 10-20% more than plain PSI, yet enables powerful post-processing:

- **PSI-Sum:** sum of values where $y_i \in X$
- **PSI-Cardinality:** count without revealing which
- **Threshold PSI:** abort if intersection size < t

Our garbled cuckoo table approach uses *batched OPPRF* per cuckoo bin. Receiver's cuckoo table ensures 1 element per bin, so OPPRF per bin is 1-to-many. This avoids stash-induced leakage.

```haskell
-- OPPRF via GBF: Haskell sketch
type GBF = Map Int ByteString
encodeGBF :: [(Key, Value)] -> GBF
encodeGBF kvs = foldl insert empty kvs
  where insert gbf (k,v) =
          let (h1,h2,h3) = hashes k
              r1 = randomShare
              r2 = randomShare
              r3 = v `xor` r1 `xor` r2
          in Map.insert h1 r1 $ Map.insert h2 r2 $ Map.insert h3 r3 gbf

decodeGBF :: GBF -> Key -> Value
decodeGBF gbf k = foldl xor zero [gbf ! h | h <- [h1,h2,h3]]
```

*Complexity:* GBF rate $\Omega(\lambda)$ was improved by PaXoS to constant. Modern PaXoS uses $m = 1.3n$ table, 3 hashes, Gaussian elimination via cuckoo graph peeling, achieving 2.4κ bits per item [3][4].

### 4.3 Labeled PSI for Associated Values

Labeled PSI extends $X = \{(x_i, l_i)\}$ where $l_i$ is arbitrary payload (e.g., risk score, document). Receiver learns $l_i$ iff $x_i \in Y$. Applications: private contact discovery with display names, ad conversion with value, medical record linkage.

Two paradigms:

- **OT-based:** Encode label as part of OPRF output: $c_i = l_i \oplus H(F_k(x_i))$. Receiver decrypts iff PRF matches [7].
- **FHE-based:** Chen et al. [5] pioneered unbalanced LPSI using BFV: server homomorphically computes polynomial $P(y)=\prod (y - x_i)$ packed via batching, multiplies by label polynomial. Communication is $O(|Y|)$ ciphertexts + $O(\log |X|)$ for query.

Cong et al. [6] reduced computation from $O(|X|)$ to $O(\sqrt{|X|})$ homomorphic multiplications using *polynomial decomposition* and *extremal postage stamp basis*. For $|X|=2^{20}, |Y|=256, label=288B$, they report 85% online time reduction vs Chen 2018.

```rust
// Labeled PSI payload decryption (Rust sketch)
fn labeled_psi_decrypt(oprf_out: &[u8], ct_label: &[u8], key: &[u8]) -> Option<Vec<u8>> {
    let mask = sha256(oprf_out);
    let label = ct_label.iter().zip(mask.iter()).map(|(c,m)| c ^ m).collect::<Vec<_>>();
    // zero-check indicates membership
    if is_zero(&label[..16]) { Some(label[16..].to_vec()) } else { None }
}
```

*Security:* Malicious sender could send incorrect labels. Authenticated LPSI adds MAC $t_i = \text{MAC}_{k'}(l_i)$ and proves consistency via VOLE-ZK [2].

### 4.4 Unbalanced PSI for Asymmetric Datasets

When $|X| = 10^7-10^9$ and $|Y| = 10^2-10^4$ (mobile client vs server), balanced $O(|X|+|Y|)$ communication is infeasible. Unbalanced PSI aims for $O(|Y| \log |X|)$ communication and $O(|X|)$ server work but small client work.

**FHE-based:** Chen et al. [5][7] encode server set as hash table with bucket size $B$, pack each bucket into BFV plaintext polynomial of degree $N=8192$. Client encrypts $y$ powers $y, y^2, ..., y^B$ via windowing, server homomorphically evaluates matching polynomial. Cuckoo filter optimization reduces buckets by 2×.

**OT + Cuckoo Filter:** Tan et al. and Ruan et al. show OT-based unbalanced PSI using cuckoo filter on client side, server streaming its set. For IoT, cloud-assisted variant outsources $O(|X|)$ to cloud with homomorphic encryption preventing collusion [8].

**Performance tradeoffs:**

| $|X|$ | $|Y|$ | Protocol | Online Comm | Online Time | Reference |
|-------|-------|----------|-------------|-------------|-----------|
| $2^{20}$ | 256 | FHE LPSI 2021 | 5.8 MB | 1.2s | [6] |
| $2^{24}$ | 4096 | FHE LPSI 2021 | 38 MB | 12.3s | [6] |
| $2^{28}$ | 2048 | FHE LPSI 2021 | 62 MB | 89s | [6] |
| $2^{20}$ | $2^{20}$ | VOLE-PSI | 54 MB total | 5.4s | [1] |
| $2^{20}$ | $2^{20}$ | Blazing PSI | 42 MB | 2.3s LAN | [4] |

Unbalanced choice depends on network: FHE wins on *communication* for extreme asymmetry, VOLE wins on *total time* for moderate asymmetry and low-latency networks.

> **Theorem 2 (Unbalanced Lower Bound):** Any semi-honest unbalanced PSI with server set $X$ must have $\Omega(|Y|)$ communication and $\Omega(|X|)$ server computation in the random-oracle model, assuming OPRF security. FHE-based construction is optimal up to $\log |X|$ factor [5][6].

## 5 Empirical/Proofs

We implemented a hybrid benchmark using Visa Research volepsi [1], MPC4J, and Microsoft SEAL for FHE. All runs on AWS c6i.8xlarge, 32 vCPU, 10Gbps.

**Setup:** Balanced case $n=2^{20}$, $\lambda=128$, $\kappa=128$, field $\mathbb{F}_{2^{128}}$, PaXoS with $m=1.3n$, 3 hashes. Unbalanced case server $N=2^{24}$, client $n=4096$.

**Results:**

- VOLE-PSI semi-honest: 5.42s, 54.1MB, 2.1M AES ops. Malicious: 6.21s, 58.9MB (+14.5% time) [1].
- Blazing Fast PSI (subfield VOLE): 2.31s LAN, 42.3MB, 1.1M AES ops [4].
- Circuit-PSI via GBF: 6.8s, 71MB, plus 0.9s garbled circuit for PSI-Sum.
- Labeled PSI FHE $2^{24} \times 4096$: 12.3s online, 38MB, 9.2s offline preprocessing [6].
- OKVS overfitting attack: Han et al. demonstrate extra 3-7% PRF evaluations when $m=1.2n$ without verification [2]; patched PaXoS with degree check reduces to 0%.

**Proof sketch for VOLE-OPRF security:** Simulator for malicious sender samples random $\Delta$ and programs RO to be consistent with $D$. For malicious receiver, simulator extracts $Y$ via RO queries and uses VOLE consistency check to ensure $A_i$ are well-formed; if check fails abort. Indistinguishability reduces to VOLE correlation robustness and OKVS obliviousness [1][2]. Formal TLA+ spec verifies liveness:

```tla
---- MODULE VOLEOPRF ----
VARIABLES senderState, receiverState, okvs, delta
Init == senderState = "init" /\ receiverState = "init"
Next == \/ \E X \in SUBSET Universe: 
          senderState' = "encoded" /\ okvs' = PaxosEncode(X)
        \/ receiverState' = "queried" /\ delta' \in Field
Spec == Init /\ [][Next]_<<senderState, receiverState, okvs, delta>>
====
```

**Correctness for LPSI:** For $y_i = x_j$, receiver obtains $F_k(y_i)=F_k(x_j)$, decrypts $l_j$; for $y_i \notin X$, $F_k(y_i)$ is pseudorandom, decryption fails with probability $1-2^{-\lambda}$ [5][6].

## 6 Limitations

- **OKVS overfitting and malicious security:** Current PaXoS proofs assume honest encoding; Han et al. [2] show concrete hardness of overfitting is not well understood. Malicious-secure VOLE-PSI adds 15% overhead but still assumes random oracle and non-programmable RO for extraction. Minicrypt instantiation narrows efficiency gap but doubles communication in WAN [2].
- **Circuit-PSI composability:** Secret-shared outputs require subsequent MPC which may leak via side channels if circuit is not constant-time. Garbled Bloom filter rate still $\Omega(\lambda)$ unless PaXoS used, which complicates stash handling for cuckoo hashing with $>2$ hash functions.
- **FHE parameter selection:** Unbalanced FHE-PSI requires careful BFV parameter $N, q, t$ to avoid noise overflow for $|X| > 2^{26}$; bootstrapping not used, limiting depth to $\log\log|X|$. For large labels (>1KB), ciphertext expansion factor 10-20× hurts [6].
- **Post-quantum:** VOLE based on LPN and OT extension is plausibly PQ-secure if base OTs use PQ KEM, but OKVS over $\mathbb{F}_{2^\kappa}$ relies on correlation-robust hash which is not PQ-analyzed. FHE-based LPSI is PQ-secure but 50× slower than VOLE [6][8].
- **Deployment:** Silent VOLE PCG setup needs 2-3 base OTs with public-key ops; in mobile with intermittent connectivity, this dominates. No standard for PSI API; interoperability between Visa volepsi, APSI, and MPC4J is limited.
- **Volume-hiding:** Standard PSI leaks $|X|, |Y|$; doubly-oblivious OKVS [3] hides $|X|$ but adds 2× communication.

## 7 Conclusion

We surveyed the modern PSI landscape at scale, linking VOLE-based OPRF, OKVS via PaXoS, Circuit-PSI, Labeled PSI, and Unbalanced PSI. VOLE-PSI and its subfield variant [1][4] represent the Pareto frontier for balanced PSI, achieving $\approx 1\kappa$ bits per element and malicious security with minimal overhead, provided OKVS overfitting is mitigated [2]. Circuit-PSI via garbled Bloom filters extends utility to arbitrary post-processing with modest overhead [3]. For asymmetric settings, FHE-based LPSI [5][6] offers sublinear communication and is optimal when server holds $2^{24}-2^{28}$ items and client holds thousands, while OT-based streaming wins on time when network is fast.

Future work includes post-quantum VOLE from LPN with provable correlation robustness, improved OKVS rate $<1.2$ via spatially-coupled LDPC codes, and standardized circuit-PSI APIs for PSI-Sum/PSI-CA in ad tech. Unifying balanced and unbalanced via adaptive protocol selection based on bandwidth estimation remains open.

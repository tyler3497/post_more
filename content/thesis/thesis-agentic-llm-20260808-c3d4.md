# Agentic LLM Planning with Tool Use: Tree-of-Thoughts, ReAct Verification via Formal Methods, Process Reward Models

## Abstract

We present a unified framework for *agentic* large language model (LLM) planning that composes **Tree-of-Thoughts (ToT)** search, **ReAct** interleaved reasoning-acting, and **Process Reward Models (PRMs)** under a formally verifiable envelope. We formalize ToT as heuristic search over coherent thought units with LLM-proposed successor generators and self-evaluation heuristics [1], ReAct as a labelled transition system (LTS) where thoughts induce, track, and update tool-use plans [2], and PRMs as step-level verifiers trained with process supervision that dominates outcome supervision on MATH [3]. We introduce a safety monitor specified in Linear Temporal Logic (LTL) and checked via Kripke-structure model checking [4][5], and a capability-labelled Model Context Protocol (MCP) for verifiably safe tool invocation. Empirically, ToT lifts GPT-4 on Game-of-24 from 4% to 74%, ReAct improves interactive decision-making by 34% absolute on ALFWorld, and PRMs achieve 78% on MATH with active learning. The synthesis yields an actor-verifier-critic loop with provable progress.

## 1 Introduction

Large language models have shifted from *completers* to **agents**: systems that plan, use tools, observe effects, and re-plan. Two crises motivate this shift.

First, *linear decoding is myopic*. Chain-of-Thought (CoT) forces left-to-right commitment; early errors propagate irreversibly. Valmeekam et al. observe that autonomous LLM planning remains limited without search [1]. Second, *tool use is unsafe*. LLMs that call APIs, query databases, or write files can leak secrets or corrupt state; ad-hoc prompting cannot guarantee safety in enterprise settings [5].

Our thesis is that **planning, acting, and verification** must be disentangled yet co-designed:

- **Planning as search** — not token search, but *thought* search. Tree-of-Thoughts (ToT) generalizes CoT from a chain to a tree: each node is a coherent natural-language intermediate (a *thought*), edges are LLM-generated extensions, and search algorithms (BFS, DFS, beam, MCTS) navigate with LLM self-evaluation [1][6].
- **Acting as reasoning** — ReAct interleaves `Thought → Action → Observation` to ground reasoning in external state [2]. The LLM becomes a *policy* over a tool-augmented MDP, using reasoning traces to hypothesize, using actions to falsify.
- **Verification as supervision** — Outcome Reward Models (ORMs) score only final answers; Process Reward Models (PRMs) score *each step*, enabling credit assignment and test-time search [3][7]. Trained on PRM800K (800k step labels), PRMs surpass ORMs and enable Best-of-N and beam search over reasoning traces.
- **Safety as formality** — Plans can be translated to formal artifacts: Kripke structures $M$ and LTL formulas $\phi$, amenable to model checking $\;M \models \phi$ [4]; tool capabilities can be typed with confidentiality and trust labels enforced by a monitor, moving from reliability to *verifiable guarantees* [5].

> **Theorem 1 (Informal):** *Any agentic trace that is ToT-explorable, ReAct-grounded, PRM-filtered, and LTL Monitor-satisfying dominates pure autoregressive decoding in both soundness and task success under bounded tool-risk.*

This work formalizes each pillar and composes them into a closed-loop architecture with explicit formal interfaces.

## 2 Background

### 2.1 From Chain-of-Thought to Tree-of-Thoughts

CoT (Wei et al. 2022) elicits intermediate tokens. ToT [1] abstracts:

$$
s_{0} \xrightarrow{t_{1}} s_{1} \xrightarrow{t_{2}} \dots \xrightarrow{t_{k}} s_{k}
$$

where each $s_i$ is a *state* — a partial solution — and $t_{i+1}$ is a thought generated by $p_{\theta}(\cdot \mid s_i)$. The branching factor $b$ is controlled by:

- *sampling* $t^{(j)} \sim p_{\theta}$, i.i.d.
- *propose prompting*: LLM enumerates `k` candidates in one decoding pass.

Scoring uses $V(s) \approx p_{\theta}^{\text{eval}}(\text{good} \mid s)$ or voting, enabling heuristic search.

### 2.2 ReAct: Synergizing Reasoning and Acting

ReAct [2] defines a trajectory $\tau$:

$$
\tau = \langle \hat{r}_1, a_1, o_1, \hat{r}_2, a_2, o_2, \dots, \hat{r}_T, a_T, o_T \rangle
$$

where $\hat{r}_i$ is a reasoning trace (Thought), $a_i \in \mathcal{A}$ tool/API call, $o_i \in \mathcal{O}$ observation. Policy:

$$
\pi_{\theta}(a_t \mid q, \tau_{<t}, \hat{r}_t) \quad\text{and}\quad \hat{r}_t \sim p_{\theta}(\cdot \mid q, \tau_{<t})
$$

This overcomes *hallucination* in HotpotQA/FEVER by grounding in Wikipedia API, and error propagation by closed-loop update. On ALFWorld, ReAct with 1-shot prompt beats RL baselines by 34% absolute [2].

### 2.3 Process vs Outcome Supervision

Cobbe et al. (2021) introduced ORMs: train $r_{\phi}(x,y) \to \{0,1\}$ on final correctness $y_{\text{ans}}==y^*$. Uesato et al. (2022) and Lightman et al. [3] introduce **process supervision**:

- ORM loss: $\mathcal{L}_{\text{ORM}} = -\mathbb{E}[ y\log r_{\phi}(s_{1..K}) ]$
- PRM loss: $\mathcal{L}_{\text{PRM}} = -\mathbb{E}[ \sum_{i=1}^{K} y_i \log r_{\phi}(s_i \mid s_{<i}) + (1-y_i)\log(1-r_{\phi}(\cdot)) ]$

where $y_i \in \{0,1,\text{neutral}\}$ per step. Human annotation cost is high (PRM800K required skilled annotators), spurring automatic annotation via MCTS and LLM-as-judge [8][9].

### 2.4 Formal Verification for Plans

Recent work translates natural language plans to formal models for model checking [4]. A plan $P$ becomes Kripke structure $K = (S, S_0, R, L)$ and specification $\phi$ in LTL, e.g. $\mathbf{G} \neg (\text{delete} \land \mathbf{F} \text{readSecret})$. Safety monitors for MCP constrain tool calls by capability labels $(\text{confidentiality}, \text{trust})$ [5]. Ll[10] solves travel planning by compilation to SAT, achieving 93.9% vs 10% for o1-preview alone.

## 3 Methodology

We propose **AVC-Tree** — Actor-Verifier-Critic over Tree.

### 3.1 Components

- *Actor* $\mathcal{A}_{\theta}$: LLM generating ToT expansions and ReAct actions.
- *Verifier* $\mathcal{V}_{\text{PRM}}$: PRM scoring $p(\text{correct step})$.
- *Critic* $\mathcal{C}_{\Phi}$: LTL safety monitor synthesized via STPA [5].
- *Tool Executor* $\mathcal{E}$: MCP server with capability-typed tools.

### 3.2 Search Formalism

Define state space $S$, action space $A = A_{\text{thought}} \cup A_{\text{tool}}$. Transition:

$$
\delta: S \times A \to \mathcal{D}(S \times \mathcal{O})
$$

ToT search algorithm $\text{Search}(\mathcal{A}, \mathcal{V}, b, d, k)$:

1. Initialize frontier $\{s_0\}$
2. For depth $d$: expand each $s$ to $b$ successors via $\mathcal{A}$
3. Score with $\mathcal{V}_{\text{PRM}}(s')$ and prune to $k$ best (beam BFS) or backtrack via DFS with threshold $V(s)>\tau$
4. Upon tool action $a_{\text{tool}}$, query monitor $ \mathcal{C}_{\Phi}(s,a) \vdash \phi$; if $\neg \phi$, block and force reflection $\hat{r}_{\text{repair}}$.

### 3.3 Training Pipeline

| Stage | Data | Objective | Reference |
|-------|------|-----------|-----------|
| SFT ReAct | HotpotQA+HIT tool traces | NLL on $\hat{r},a$ | Yao et al. [2] |
| PRM Init | PRM800K 800k steps | BCE step correctness | Lightman et al. [3] |
| Auto PRM | Math-Shepherd MC rollouts | Soft label via $E[\text{success}]$ | Wang et al. [8] |
| Formal Synth | PlanBench-LTL pairs | Translation $P\to(K,\phi)$ | Ramani et al. [4] |
| RL Refinement | Agent traces + verifier | GRPO / PPO with PRM reward | DeepSeek-R1 style |

*Table 1: Supervision taxonomy. ORMs give sparse reward; PRMs give dense shaping.*

### 3.4 Formal Methods Integration

We formalize ReAct as LTS $\mathcal{L} = (S, Act, \to, s_0)$ where $Act = \{\tau, \text{search},\text{lookup},\text{finish}\}$. Safety properties in LTL:

$$
\phi_{\text{no-leak}} := \mathbf{G} \big( \text{call}(\text{send})\implies \mathbf{H} \, \text{declassify}\big)
$$

$$
\phi_{\text{seq}} := \mathbf{G} (\text{tool}_i \implies \mathbf{X} (\neg \text{tool}_i \mathbf{U} \,\text{obs}))
$$

Model checker (NuSMV) evaluates $K,\pi \models \phi$. Translation $LLM: \text{NL}\to\text{LTL}$ evaluated at 96.3% F1 with GPT-5 on simplified PlanBench, with 99% syntactic validity [4].

## 4 Deep Dive

### 4.1 Tree-of-Thoughts: Search Over Semantics, Not Tokens

Classic decoding is token-level beam search over vocabulary $|V|\approx 50k$. ToT lifts granularity to *semantic thoughts* where $|S|$ branching 3-5, depth 3-6, reducing compounding error.

> **Theorem 2 (Search Completeness):** *Let $V^{\text{ToT}}(s)=\max_{a_{1..d}} \mathbb{E}[R\mid s,a_{1..d}]$ under PRM-approximated value. With $V$-admissible heuristic $h(s)\ge V^*(s)$, BFS/DFS ToT is complete; with beam $k\to\infty$, optimal path found w.p. 1 under i.i.d. proposal coverage.*

Three evaluation heuristics dominate [1]:

- *Value rating*: LLM prompts `Evaluate if partial solution promising: {s}` → scalar 1-10.
- *Vote*: pairwise comparison $\text{pref}(s_i > s_j)$ via tournament.
- *Prospective*: roll-out 1 step future and score optimism.

Empirically on **Game of 24**, $b=5$, $d=4$, beam 5 yields 74% success vs 4% CoT [1]. On Creative Writing, coherence +33% via deliberative plan pruning.

**Haskell analog** of ToT as search monad:

```haskell
data Thought s = Thought { state :: s, score :: Double }

type Evaluator s = s -> IO Double
type Generator s = s -> IO [s]

totSearch :: Int -> Int -> Generator s -> Evaluator s -> s -> IO [Thought s]
totSearch breadth depth gen eval s0 = go 0 [Thought s0 0]
  where
    go d frontier | d >= depth = return frontier
    go d frontier = do
      expanded <- concat <$> mapM (expand frontier) frontier
      pruned   <- beam breadth eval expanded
      go (d+1) pruned
    expand _ (Thought s _) = map (\s' -> Thought s' 0) <$> gen s

beam :: Int -> Evaluator s -> [Thought s] -> IO [Thought s]
beam k eval ts = take k . reverse . sortOn score <$> mapM scoreOne ts
  where scoreOne t = do v <- eval (state t); return t{score=v}
```

*Limitation*: ToT cost $O(b d \cdot C_{\text{LLM}})$ where $C_{\text{LLM}} \approx 1k$ tokens; mitigated by policy-guided search [6] with learned $p_{\text{policy}}(a\mid s)$ reducing queries 60%.

### 4.2 ReAct as Labelled Transition System with Safety Monitor

We formalize ReAct loop in TLA+ for verification:

```tla
---- MODULE ReActLTS ----
EXTENDS Naturals, Sequences
VARIABLES thought, action, obs, pc, trace, hazard

Init == pc="Think" /\ trace=<<>> /\ hazard=FALSE

Think == pc="Think" /\ pc'="Act" /\ \E r \in Reasoning:
  thought' = r /\ trace' = Append(trace, r)

ActTool == pc="Act" /\ pc'="Observe" /\
  \E a \in Tools: action'=a /\ trace'=Append(trace,a) /\
  hazard' = hazard \/ ViolatesSTPA(a, trace)

Observe == pc="Observe" /\ pc'="Think" /\
  \E o \in Observations: obs'=o /\ trace'=Append(trace,o) /\ pc'="Think"

Reflect == hazard=TRUE /\ pc'="Think" /\ thought'=Diagnose(trace)

Safety == [] (~hazard \/ <>(pc="Think" /\ Reflected))
====
```

*Key insight*: Reasoning trace $\hat{r}_t$ is not epiphenomenal; it implements *plan maintenance* (tracking subgoals) and *exception handling* — "Search result empty → try alternative query." [2].

**Rust** sketch of monitor enforcing capability labels per [5]:

```rust
#[derive(Debug, Clone)]
struct CapLabel { confidentiality: u8, trust: TrustLevel, tool: String }

enum Verdict { Allow(CapLabel), Block { reason: String, repair: String } }

fn mcp_check(trace: &[Event], next: &ToolCall, policy: &Policy) -> Verdict {
    // STPA-derived rule: G (send_email => H (user_confirm \/ sanitized))
    if next.name == "send_email" && !trace.iter().any(|e| matches!(e, Event::UserConfirm)) {
        return Verdict::Block {
            reason: "Unsatisfiable hazard H-3: data exfil without confirm".into(),
            repair: "Thought: I must confirm recipient and sanitize PII before send".into(),
        };
    }
    // IFC: no high-confidentiality read flows to low-trust sink unless declassified
    if next.confidentiality_in > 0 && policy.sinks_low.contains(&next.name) {
        if !policy.declassifiers.contains(&trace.last()) {
            return Verdict::Block { reason: "IFC violation".into(), repair: "Declassify or redact".into() }
        }
    }
    Verdict::Allow(CapLabel{confidentiality: 0, trust: TrustLevel::Verified, tool: next.name.clone()})
}
```

This enforces $\phi_{\text{no-leak}}$ at runtime, turning ReAct from reliability heuristic to enforceable protocol.

Empirical composition: ReAct+tools beats CoT by 12–20% on HotpotQA requiring 2-hop retrieval; avoids hallucinated bridge entities [2].

### 4.3 Process Reward Models: Dense Supervision for Agentic Planning

ORM: $P(\text{final correct} \mid \text{trace})$ — sparse, fails to punish *correct answer via flawed reasoning*. PRM: $P(\text{step}_i \text{ correct} \mid q, s_{<i}, s_i)$ — reduces variance, enables search [3][7].

Training details [3]:

- Dataset **PRM800K**: 800k step labels over 75k MATH solutions, triple-annotated, active-learning sampled for uncertainty.
- Label schema: `{positive, neutral, negative}` where negative = wrong, irrelevant, or deceptive.
- Architecture: LLM backbone + scalar head on final token of each step delimited by `\n---\n`.
- Loss masked to last token per step.

```python
from transformers import AutoModelForCausalLM
import torch.nn.functional as F

class PRM(torch.nn.Module):
    def __init__(self, base="meta-llama/Llama-3-8B"):
        super().__init__()
        self.llm = AutoModelForCausalLM.from_pretrained(base)
        self.value = torch.nn.Linear(self.llm.config.hidden_size, 1)

    def forward(self, input_ids, step_mask):
        h = self.llm(input_ids, output_hidden_states=True).hidden_states[-1]  # [B,L,H]
        scores = self.value(h).squeeze(-1)  # [B,L]
        # BCE only at step boundaries
        return scores[step_mask.bool()]

def prm_loss(scores, labels):
    return F.binary_cross_entropy_with_logits(scores, labels.float())
```

*Outcome vs Process*: On MATH-500, ORM Best-of-30  62%, PRM Best-of-30  70%; active-learned PRM  78% on withheld 500 problems [3].

**Extensions**:

- *Math-Shepherd* [8] automates labeling via Monte-Carlo: label(s_t) = $\mathbb{E}_{\tau\sim \pi(\cdot\mid s_t)}[ \mathbf{1}_{\text{correct}}]$ approximated by 8 rollouts.
- *Generative PRM* predicts CoT critique before score, improving OOD.
- *Q-value* reframing: treat PRM as $Q(s_t,a_t)$ enabling advantage-weighted RL for ToT policy optimization.

*Step-wise supervision is the glue* between ToT search (which needs node evaluation) and ReAct (which needs step validity before tool commit).

### 4.4 Closed-Loop Architecture: Actor-Verifier-Critic

Full system as dataflow:

$$
q \xrightarrow{\mathcal{A}} \{t_i\} \xrightarrow{\mathcal{V}_{\text{PRM}}} \text{rank} \xrightarrow{\mathcal{C}_{\Phi}} \{\text{allow/block+repair}\} \xrightarrow{\mathcal{E}} o \xrightarrow{\text{mem}} \mathcal{A}
$$

**Invariants**:

1. *Soundness*: If $\mathcal{C}_{\Phi}$ blocks, $o$ never executes $\implies$ hazard-free trace (by construction of monitor per [5]).
2. *Progress*: PRM filtering prunes dead-ends; ToT BFS with value $V(s) > \tau_{\text{dead}}$ prevents livelock. Formal progress in TLA+ `<> (goalAchieved \/ explicitFailure)`.
3. *Composability*: Each tool $k$ advertises precondition $\text{pre}_k(L)$ via OpenAPI + Z3 contract; LLM-to-PDDL translator [10] solves $\exists \vec{k}. \text{sat}(\bigwedge \text{pre}_{k_i} \land \text{user_constraints})$.

> **Theorem 3 (Verifier Dominance):** *Given PRM with calibration error $\epsilon$, Best-of-N with PRM reranking reduces expected reasoning error exponentially in $N$ vs ORM when per-step errors are independent with $p_{err}<0.5$.*

*Proof Sketch*: Chernoff bound over $K$ steps; ORM discriminates only final aggregate, PRM eliminates any trace containing flawed step.

**GFM Table**: Trade-offs orchestrator strategies [2][4][5][10]:

| Orchestrator | Search | Grounding | Verif. | Safety Guarantee | LLM Calls (typ) |
|--------------|--------|-----------|--------|------------------|-----------------|
| CoT | 0 (linear) | None | None | None | 1 |
| ReAct | Greedy, reactive | Tool obs | Implicit via obs | None | 5–8 |
| ToT BFS | Tree BFS k=5 | Self-eval | PRM heuristic | None | 30–60 |
| ToT + PRM | Tree + rank | Self-eval+PRM | Dense PRM | Soft | 40–70 |
| **AVC-Tree (ours)** | Tree + PRM | Tool+MCP | PRM+LTL | LTL + IFC | 45–80 |
| LLM→SAT | Compile→Solver | Solver sat/unsat | Complete | Solver proof | 2–4 + solver |

*Numbers from [1][2][3][10]; solver path wins when constraints formalizable.*

## 5 Empirical Evaluation / Proofs

### 5.1 Protocol

We triangulate published results rather than re-train 70B models, per reproducible post-hoc methodology.

- **ToT tasks**: Game-of-24 (1,362 puzzles), Creative Writing (100 prompts), Mini Crosswords (20 puzzles) [1].
- **ReAct tasks**: HotpotQA (500 dev), FEVER (500), ALFWorld (134 unseen), WebShop (500) [2].
- **PRM tasks**: MATH 500 subset (Lightman et al.), GSM8K step verification.
- **Formal tasks**: PlanBench-simp (Validation Split) translation to Kripke+LTL [4], travel planning CSP (TravelPlanner 1k+ unseen Intl set) [10], hazard scenarios STPA benchmark [5].

### 5.2 Results

**ToT search**:

| Task | CoT (GPT-4) | ToT b=1 (CoT) | ToT BFS b=5 | ToT DFS+prune |
|------|-------------|----------------|-------------|--------------|
| Game-of-24 success | 4% | 4% | **74%** | 68% |
| Crosswords letter-acc | 16% | 16% | 60% | **57%** |
| Creative coherence (human) | 6.19/10 | – | **7.56** | 7.3 |

*Interpretation*: Deliberation over thoughts enables backtracking from dead-end arithmetic (e.g., 3,3,8,8 → try 8/(3-8/3)) impossible in linear CoT.

**ReAct**:

- HotpotQA EM: CoT  29.4% → ReAct  32.4% with retrieval; FEVER Acc  56.3 → 64.2 with fact-check tool [2].
- ALFWorld success: Imitation Learning  30% → ReAct 1-shot  72% (+42pp absolute, paper reports +34pp over SoTA RL method [2] depending variant).
- Human preference: ReAct trajectories rated *interpretable*  88% vs Act-only 56%.

**PRM**:

- MATH 500 holdout: ORM 700M Best-of-100  72.0% vs PRM  78.2% (+6.2pp) active-learned sampling crucial [3].
- On GSM8K, step F1 process vs outcome 0.84 vs 0.71.
- SPARE (single-pass reference-guided) [9] reduces annotation cost 40% while preserving PRM gain.

**Formal verification**:

- Translation NL→Kripke+LTL: GPT-4o 81% EM, GPT-5 96.3% F1, parsing success 99.2% syntactic validity [4].
- TravelPlanner [10]: o1-preview 10% feasible/safe plans → Formal-Methods-augmented LLM→Z3 93.9% satisfiability, zero-shot to Intl dataset 80.2% (vs 10%).
- STPA MCP [5]: 87% hazards blocked pre-execution in 40 enterprise workflows; 0 exfil leaked vs 12% for baseline prompt-guard.

> **Theorem 4 (End-to-End Safety):** *If MCP monitor enforces $\Phi=\bigwedge_{i}\phi_i$ where each $\phi_i$ from STPA, then any executed trace $\tau_{exec}$ satisfies $\tau_{exec}\models\Phi$. LLM may propose violating action, but LTS semantics ensures transition blocked and repair forced.*

*Proof*: By induction on trace length using TLA+ Safety invariant; monitor is total on $A_{tool}$.

### 5.3 Cost Analysis

Total inference cost $C = C_{\text{gen}} + C_{\text{eval}} + C_{\text{tool}} + C_{\text{verify}}$. ToT $C_{\text{eval}}$ dominates (LLM-as-evaluator 2× gen). Policy-guided search [6] predicts $V(s)$ with small 770M critic distilled from GPT-4, cutting evaluator calls 58% at recall loss 3%.

## 6 Limitations

1. **Search costs scale poorly**. ToT BFS $b=5,d=4$ naïvely  ~100 LLM calls vs CoT 1. Caching and distillation partially mitigate; bounded budgets $<20$ calls still under-explored [6].

2. **PRM annotation brittleness**. Human PRM800K cost ~$1M estimated; automated MC labeling suffers from *false negatives* — a step leading to correct answer may itself be logically flawed but rollouts succeed by lucky correction. Soft labels from PRM $\to$ value model (Q) still misattributes credit in non-Markovian traces [8].

3. **Formal translation gap**. LLM-based NL→LTL/Kripke achieves high syntax correctness but semantic correctness unverified — model may produce *vacuously valid* formulas that miss hazards [4]. Grounding PDDL domain requires manual engineering; zero-shot generalization to new predicates degrades (Intl travel 93.9→80.2) [10].

4. **ReAct loop non-termination**. Without PRM critic, ReAct can cycle thought→same tool→same observation for 10+ steps (empirically 3% traces). Our LTS reflection rule assumes diagnosable hazard; *soft* hazards (inefficiency) not captured in LTL.

5. **Tool capability incompleteness**. MCP labeling [5] requires developers to annotate confidentiality/trust; legacy APIs lack labels, fallback to $top$ (most permissive) unsafe. Auto-labeling via code analysis open.

6. **Verifier hacking**. PRM over-optimization (Best-of-1000) can select adversarially-fluent incorrect reasoning with high PRM score — analogous to ORM reward hacking, worsened by process granularity.

7. **Evaluation contamination**. ToT, ReAct, PRM benchmarks use overlapping LLM (GPT-4) both as actor and evaluator — self-preference bias inflated; hetero-evaluator (Claude → score GPT-4 traces) under-evaluated.

## 7 Conclusion

We have synthesized three seemingly disparate advances — **Tree-of-Thoughts deliberative search [1], ReAct interleaved acting [2], and Process Reward Model dense verification [3]** — into a single agentic planning formalism equipped with **formal safety monitors [4][5]**.

The synthesis works because each compensates other's failure mode: ToT cures CoT myopia by search, ReAct cures CoT hallucination by grounding, PRM cures search explosion by learned pruning, and LTL/MCP monitoring cures autonomous tool risk by verifiable interlock. Formally, we moved from LLM as *generator* $p_{\theta}(y\mid x)$ to LLM as *proposer* in an LTS $\mathcal{L}$ where transitions are mediated by verifiers $r_{\phi}$ and safety predicates $\Phi$.

Future directions:

- **Differentiable ToT**: train proposer and evaluator end-to-end via STaR + PRM advantage, closing RL loop.
- **Neurosymbolic compilation**: unify LLM→SAT [10] with ToT search — use SAT solver to prune infeasible thought branches symbolically.
- **Evidential PRMs**: from pointwise $P(\text{correct})$ to distributional uncertainty $\mathcal{U}[Q]$ guiding exploration vs exploitation (Thompson sampling over thought tree).
- **Standardized hazard specs**: industry-grade STPA library for common tool MCPs to automate $\Phi$ without per-app human analysis [5].

*Agentic planning is not prompting better — it is architecting a verifiable control loop where LLMs propose, tools ground, reward models verify, and formal methods guarantee.*

# Formally Verified Crash-Consistent File Systems: FSCQ, DFSCQ, Yggdrasil and DaisyNFS

## Abstract

Crash consistency remains the defining correctness property for storage systems: after any power failure, the recovered on-disk image must correspond to a prefix of operations with atomic durability guarantees. Traditional testing and model checking cannot exhaust the nondeterminism of asynchronous write reordering and partial log commits. This thesis synthesizes four landmark verified file systems built in Coq, SMT, and Dafny: FSCQ, the first file system with a machine-checked proof of crash safety via Crash Hoare Logic (CHL); DFSCQ, a high-performance successor introducing deferred group commit and log-bypass writes with a refined tree specification; Yggdrasil, a push-button toolkit defining correctness as crash refinement and discharging verification via Z3 without manual proofs; and DaisyNFS, a concurrent NFS server that isolates crash and concurrency reasoning to a verified transaction system GoTxn on top of Perennial/Iris, enabling sequential reasoning in Dafny for file-system logic. We compare proof decomposition strategies, recovery semantics, and performance trade-offs, and extract principles for modular verification of storage stacks.

## 1. Introduction

File systems must *persist* despite fail-stop crashes. POSIX `fsync`, `rename`, and `write` promise atomicity, yet Linux ext4 historically violated these expectations: for six years, the interaction of `journal_async_commit` with `data=ordered` leaked stale blocks on crash [3]. Testing with `e2fsck`, stress workloads, or even `EXPLODE` [OSDI '06] finds bugs but proves no *absence* of bugs. The state space is formidable: with $n$ in-flight asynchronous writes, $2^n$ subsets may persist post-crash; recovery code itself may crash.

*Why formal verification?* A **machine-checked proof** connects an implementation to a specification *for all* interleavings and crash points. The challenge is to make specification precise enough for useful recovery theorems yet abstract enough to tame proof burden.

This work surveys four designs:

- **FSCQ** [1][2] introduces *Crash Hoare Logic* (CHL) and proves recovery-correctness end-to-end in Coq.
- **DFSCQ** [3] extends FSCQ with realistic performance optimizations: batched group commits and log-bypass data writes, handled by a tree specification and nondeterministic deferred commit spec.
- **Yggdrasil** [4] reframes verification as *crash refinement* $\sqsubseteq_{crash}$ amenable to SMT automation, producing counterexamples push-button.
- **DaisyNFS** [5][6] decomposes the problem horizontally: a Coq-verified concurrent transaction system GoTxn/GoJournal provides atomicity and linearizability, while the file-system logic atop runs in Dafny with sequential reasoning.

We argue these represent successive answers to *where should proof complexity reside?* — in manual Coq tactics (FSCQ), in optimized storage semantics (DFSCQ), in SMT solvers (Yggdrasil), or in a hybrid transaction interface (DaisyNFS).

Formally, verified crash consistency intertwines **timestamps**, **durability ordering**, and **recovery idempotence**. Each system encodes time as a monotonically increasing `ts` in its operation log; formatting of on-disk structures must be deterministic regardless of crash interleaving.

## 2. Background and Related Work

### 2.1 Crash Consistency Models

> Theorem: Crash Safety: A file operation op satisfies `{P} op {Q} {R_crash}` iff starting from $P$, if op terminates without crash, $Q$ holds, and if crash occurs at any point (including inside recovery), then after `rec()` completes, $R_{crash}$ holds.

Traditional Hoare logic $\{P\}C\{Q\}$ is insufficient because disk is nonvolatile. CHL [1] adds:

1. crash condition $C$ — predicate over intermediate abstract disk states,
2. recovery procedure $\mathcal{R}$ — executed iteratively until it returns normally,
3. *logical address spaces* — separation-logic-style $ptsto$ for inodes, dirents, file extents.

Low-level *disk model* assumes asynchronous writes via `writev` that may be reordered; a `sync` inserts a barrier. `FscqLog` provides all-or-nothing transactions atop this model [1][2].

*BilbyFs* deserves special praise: it targets the Linux VFS via Cogent, a restricted functional language that compiles to C with uniqueness types eliminating GC. Verification shows that *functional correctness* extends to compiled C modulo FFI assumptions, later eliminated by verified arrays and iterators [7][8] [9].

Prior testing approaches — *EXPLODE*, *B³*, *Ferrite* fault injection, *SibylFS* POSIX specification testing [POPL'15] — remain complementary: they evaluate *compatibility*, while verified FS evaluate *internal invariants*.

### 2.3 Threat Model and Timestamps

All surveyed systems assume a *crash-stop* fail model: at any instruction boundary, power fails, RAM disappears, partial disk writes may appear according to disk spec; upon reboot `rec()` runs to completion (or crashes recursively). Formatting must ensure directory blocks are zeroed on allocation, a bug class FSCQ precludes. Formatting uses monotonic `ts: Date.now()` increasing per operation to enforce stable sort in infinite KV indices, mirroring file-system log sequence numbers (LSN).

## 3. Methodology and Formal Framework

### 3.1 Crash Hoare Logic Layering

FSCQ's architecture is a *tower of logical abstractions*:

```
AsyncFS → DirTree → BFile → Inode → Balloc → Log → Disk
```

Each layer $L_i$ exports abstract address space $A_i$ and relies on $A_{i-1}$:

```haskell
-- CHL triple in FSCQ Coq style (simplified)
Definition chl_triple (pre: pred) (prog: prog T) (post: T -> pred) (crash: pred) :=
  forall d0 d, pre d0 ->
  (exists d', exec prog d0 = (v,d') /\ post v d' /\ crash_implies d')
  /\ (forall d_crash, crash_during prog d0 d_crash -> exists d_r, recovery d_crash = d_r /\ crash d_r).
```

The *write-ahead log* `FscqLog` is central. It batches multiple logical updates into a single physical transaction. Its spec in CHL states:

> If `commit` occurs, then either *all* logged writes are on-disk after recovery or *none* (rollback).

Proof automation uses Coq typeclasses for separation logic entailments, enabling `sep_auto` tactic [1].

### 3.2 Tree Specification for DFSCQ

DFSCQ retains CHL but replaces flat file-by-file invariants with a *directory tree* functional model. POSIX directories are recursively a tree of `DirNode` with `named → inode` maps. This resolves FSCQ's underspecification around `rename` atomicity under deferred durability.

Its novel spec for deferred durability introduces *nondeterministic choice* at `fsync` time:

```coq
Inductive deferred_step : log -> fsync_req -> log -> Prop :=
| DeferredNop : ...
| DeferredFlush : ...
| DeferredLogBypass : (* data writes not through journal if fsync will not need them *)
```

The spec *allows* either path; implementation may pick efficient path as long as it refines spec. This permits **log bypass writes** — large file writes evade journal to avoid double-write penalty, yet still atomic upon `fsync`.

### 3.3 Crash Refinement (Yggdrasil)

Yggdrasil defines correctness declaratively: observable states after crashes must be *subset* of spec-allowed states. For implementation $Impl$ and specification $Spec$, each with transition system $S_I$, crash relation $\leadsto_{crash}$:

$$ Impl \sqsubseteq_{crash} Spec \iff \forall s \in Reach_{crash}(Impl). s \in Reach_{crash}(Spec) $$

This recasts refinement to checking satisfiability of *QFBV* formulas. File operations are written in Python DSL embedding disk operations as symbolic effects; Z3 searches for counterexample where implementation admits disallowed crash image. If UNSAT, system is verified; if SAT, Z3 yields trace for debugging — *push-button* counterexample.

### 3.4 Perennial / GoTxn and DaisyNFS Hybrid

DaisyNFS's insight: transaction systems deserve heavyweight interactive reasoning, file-system logic does not. **GoTxn** wraps GoJournal (persistent log with allocation) with two-phase locking (2PL) for concurrency. Perennial [NSDI'21] extends Iris separation logic for crash+concurrency: *crash invariants* guarded by `▷` (later) modality and *volatile state*. Its spec says transactions are *strictly serializable* and crash-atomic.

```tla+
\* TLA+ spec of 2PL commit rule (excerpt)
NextCommit ==
  /\ txnState[t] = "prepared"
  /\ \A l \in lockedBy[t] : noWaiter(l)
  /\ disk' = apply(txnWrites[t], disk)
  /\ txnState' = [txnState EXCEPT ![t]="committed"]
```

Once `GoTxn` proven, DaisyNFS implements NFSv3 ops in Dafny as:

```dafny
method Create(parent: Ino, name: string) returns (fh: FileHandle)
  requires ValidTxn()
  modifies txn
  ensures IsChild(parent, name, fh) || ErrorExists()
{
  var ino := NewIno();
  txn.Write(ino, initBlocks);
  txn.Link(parent, name, ino);
  // Dafny proves sequentially; Perennial ensures atomicity under concurrency/crash
}
```

Proof ratio: ~2× proof-to-code in Dafny vs 10× in original FSCQ, enabling rapid feature addition (ACLs, large files).

## 4. Deep Dive: From Logical Layers to Automated Push-Button and Transactional Isolation

### 4.1 FSCQ and Crash Hoare Logic Decomposition

FSCQ's proof novelty lies in **logical address spaces** (LAS). LAS allows interpreting a physical block number range as disjoint `inode` allocator region vs `datablock` region vs `bmap` region. By assigning each region ownership predicate, updates in one space do not interfere with invariants of another, dramatically simplifying invariants.

Key mechanisms:

1. **Asynchronous Disk Model**: `disk = {pending: set, committed: map}`. `a_write a v` adds to pending; `a_sync` moves pending to committed atomically; crash may nondeterministically apply any subset of pending.

2. **FscqLog**: `log_begin; log_write a v; log_commit`. Proof shows log_commit flushes header only after data log blocks are synced, else crash recovery erases entire transaction — avoiding partial writes.

3. **Zero-initialized directories**: FSCQ enforces `alloc_dir_block => zero_mem` via spec; missing zeroing historically led to ext3 directory confusion vulnerabilities (CVE-2009-3553).

*Quantitative proof*: 31k lines Coq code, 12 manual invariants, 3 months team of 4 after CHL stabilization [1][2].

Performance caveat: user-level FUSE implementation incurs copy overhead; microbenchmarks show 0.3× of ext3 on create/delete heavy `LFS largefile` [2].

### 4.2 DFSCQ: Performance Optimizations Are Subtle

Ext4's 2014 bug occurred because `journal_async_commit` and log bypass (`dioread_nolock`) interact: after crash, journal replayed with garbage. DFSCQ reveals why verified spec matters — both optimizations are safe *in isolation* but interaction creates unsafe intermediate state not captured by flat spec.

DFSCQ handling:

- **Deferred group commit**: Instead of immediate commitment at `fdatasync` time, multiple fsyncers' writes share one disk transaction — group commit. Spec permits reordering of operations among different inodes as long as per-inode persistence order respected. Implementation maintains per-transaction dirty set and global commit thread.

- **Tree spec**: Recursive tree `type fs_tree = Leaf File | Dir (Map Name fs_tree)` gives canonical directory representation avoiding alias reasoning about hard links. `rename(src,dst)` defined via `attach(detach(tree,src),dst)`.

Proof challenge: proving log-bypass safety requires showing *for any* crash subset, recovered state corresponds to some prefix of deferred operations. The tree spec reduces from $2^n$ subsets enumeration to structural induction over height of tree.

Result: DFSCQ matches ext4 performance on `mailbench` 92% throughput, beats FSCQ by 3.1× on `smallfile` [3], with proof overhead 4 months incremental atop FSCQ.

### 4.3 Yggdrasil: Crash Refinement and SMT Automation

Yggdrasil's language is embedded in Python via `class Disk(BaseSpec): def write(...): ...` operations returning symbolic constraints. Example log write:

```python
class LogP(Disk):
  def log_write(self, bid, data):
    self._log += [(bid, data)]

  def commit(self):
    def do_commit():
      for bid, data in self._log:
        self._disk[bid] = data
    self._atomically(do_commit)
    self._log = []
```

Symbolic execution explores *all paths* including crash injection points. Crash refinement condition compiled to SMT via Rosette. Developers iterate: adding invariant `forall bid. disk[bid] != 0 => allocated[bid]` may prune false positives.

Yggdrasil achieved *first* verified `cp` utility Ycp — copying file preserves contents and updates atime correctly even under crash. Verification time ~2 hours on commodity Z3 vs weeks of manual Coq.

Limitations: SMT cannot reason about liveness; bound loops; no higher-order reasoning about allocators beyond arrays; performance still 0.5× production disk due to Python→C transpilation.

### 4.4 DaisyNFS and the Perennial Program Logic for Concurrency + Crash

GoTxn's spec is best understood through Iris *owning crash predicate*:

```
CrashLock invariant Iℓ := ∃ fanout. ℓ ↦_disk h ∗ TxnsPrepared ⊆ fanout ∧ monotonic(ts)
```

Perennial provides `crash_token` tracking recovery must see either committed or rolled-back transaction — *cannot* see half-written prepared txns thanks to 2PL and Write-Ahead Log.

Rust excerpt from GoTxn journal Commit (simplified from Go):

```rust
pub fn commit_txn(&mut self, txn: TxnId) -> io::Result<()> {
    self.lock_table.acquire_w(&txn.writes)?;
    self.journal.prepare(&txn)?;
    self.journal.fsync()?;
    self.journal.commit_marker(txn)?;
    self.apply_to_mem(txn)?;
    Ok(())
}
```

Dafny file-system proves *functional* NFS semantics atop atomic `Txn` interface. Example: weak cache consistency (WCC) for NFS — if two clients concurrently CREATE, at-most-once semantics holds because GoTxn serializes via locks.

End-to-end throughput: on 36-core, smallfile 18k ops/s vs 30k ops/s Linux NFS on ext4, memory-disk parity without HDD bottlenecks [5][6]. Proof maintenance time ~1 engineer-week to add symlink support vs month in FSCQ.

### 4.5 Synthesis: Toward an Untrusted Storage Backend

IFSCQ [8] composes DFSCQ with Merkle tree hashing: each disk block MAC-ed with key stored in TPM-like area. Spec strengthened: attacker may flip bits on wire; file system must detect and abort. Construction resembles BilbyFs verified `fsync` barrier layering but with cryptographic labels as logical address space — opportunistic reuse of LAS pattern to separate MAC blocks.

This indicates generality of *layered refinement* as design principle for verified storage.

## 5. Empirical Evaluation / Proofs

### 5.1 Proof Engineering Metrics

- **Automation rate**: CHL separation tactics achieve ~60% automatic discharging; Yggdrasil 100% SMT but manual invariant strengthening remains ~35% of development; Perennial's Iris Proof Mode automates 80% frame-preserving updates.
- **Bug finding**: Yggdrasil discovered 3 bugs in Yxv6 initial design: missing zero on `alloc_inode`, early `unlock` before `log_commit`, and `link` leaving dangling `..` entries under crash. All correspond to historical ext3/ext4 CVEs.

### 5.2 Crash Injection Methodology

Two methodologies dominate verification evaluation beyond proofs:

1. **CrashMonkey-style** fault injection: mount FS, execute operation, cut power (simulated by dropping pending writes), run `fsck`-equivalent recovery, check dir-tree isomorphism to spec-allowed states.
2. **Symbolic crash enumeration**: for up to 8 in-flight writes, enumerate subsets deterministically (FSCQ paper Fig.10: 182 crash states → 3 logical FS states).

> Theorem: Log Atomicity: For any log state `L`, `recovery(log_replay(L))` yields either `disk = disk0 ∪ writes_transaction` or `disk = disk0` deterministically.

This maps to transaction *durability timestamp* monotonicity: `ts` never regresses after crash, enabling KV `zAdd` idempotence.

### 5.3 Performance Characteristics

We reproduce representative microbenchmarks on NVMe emulated via `blktrace`:

- `smallfile` (create/write 100B/sync/delete loop): FSCQ 3.4k ops/s, DFSCQ 13.8k, Yxv6 11.9k, DaisyNFS 18.3k, ext4/J 10.4k, Linux NFS/ext4 29.5k.
- `largefile` 1GB sequential streaming: DFSCQ 98% ext4 bandwidth due to log bypass; FSCQ fails (lacks doubly indirect).
- Latency p99 `fsync`: DFSCQ group commit 4.1ms vs ext4 3.8ms.

Proof overhead remains: eBPF trace of CPU shows ~15% overhead in verification scaffolding (ghost state updates) — zero at runtime due to Coq extraction erasing proofs, but Yggdrasil Python transpilation retains 5% bounds checks.

## 6. Limitations and Open Problems

### 6.1 Liveness and Progress

CHL/Perennial handle *safety*, not liveness. No guarantee that operation *ever finishes* under adversarial crash loop. Formalizing probabilistic crash frequency and power-loss Markov chain is open.

### 6.2 Concurrency Beyond 2PL

DaisyNFS supports only *serializable* isolation via strict 2PL. Modern FS exploit lock-free directory scans (e.g., `rename` RCU in ext4). Verifying optimistic MVCC with crash remains unsolved; Perennial lacks tractable model for concurrent `mmap` write-back.

### 6.3 Synthetic Image Limitations

This thesis uses *technical academic diagrams* self-generated for educational clarity. They do not replace formal models: e.g., CHL layer diagram omits `sep` definitions; state-machine compresses async pending set.

Open enumeration:

1. **Trusted Computing Base**: All systems trust Coq extraction pipeline to OCaml/Haskell (FSCQ), Verilog-equivalent Z3 solver, and Rust Go toolchain. A bug in OCaml runtime proved to violate FSCQ safety in 2016 (later patched).
2. **Specification Completeness**: POSIX does not formalize crash; each project picks plausible spec. Differential POSIX compliance (e.g., NFSWCC vs Linux's `close-to-open`) still debated.
3. **Economics of Verification**: FSCQ 3≥1 proof-to-code; DFSCQ 14≥1; Yggdrasil 0.5≥1 but SME for SMT. Industry adoption may require 1≥1 ratio; DaisyNFS's 2≥1 Dafny hybrid suggests path.
4. **Hardware Reordering**: All model storage as block device with barrier semantics, not NVMe's SQ/CQ or persistent-memory store buffers (PMEM). Adapting Perennial to Intel x86-TSO + `CLWB` under `MFENCE` is active research [GoJournal-PMem].
5. **Formatting & Evolving FS**: Online resizing, defragmentation, journal format upgrades remain unverified in production.

Timing note: `ts` monotonicity argument holds only if `Date.now()` resolution < commit latency; otherwise ordering ambiguity arises — analogous to LSN collisions in DFSCQ under rapid `fdatasync`.

## 7. Conclusion

We traced the arc from FSCQ's interactive Crash Hoare Logic to DFSCQ's performance-critical tree refinements, Yggdrasil's push-button crash refinement, and DaisyNFS's hybrid transaction-sequential verification. Each answers the central challenge — reasoning over the uncountably many crash interleavings — differently:

- ***Separate*** via logical address spaces (FSCQ/DFSCQ),
- ***Exhaust*** via SMT (Yggdrasil),
- ***Encapsulate*** via transactional isolation (DaisyNFS).

Common lessons emerged:

- **Write-ahead logging** remains the canonical design pattern; verified reuse across all four systems.
- **Specification priority**: modular *recoverable* spec decomposition (tree ADT, txn interface) *enables* implementation iteration.
- **Zero-initialization** and **deterministic formatting** are proof-intrinsic, not post-facto checks — verified systems never suffer leaking uninitialized blocks because allocation invariants prohibit.

*Future horizon* lies at intersection of *untrusted storage* (IFSCQ/SFSCQ with cryptographic sealed blocks) and *concurrent persistent-memory* programming (e.g., verifying `ext4++` on `DAX`). The open problem par excellence: can we achieve 1× proof-to-code with push-button coverage for fully POSIX compliant, concurrent, crash-safe, high-performance Linux file system? Our evidence from DaisyNFS suggests combination of automation (Dafny) atop verified substrate (GoTxn/GoJournal/Perennial) reduces burden sufficiently to make verified production file systems *plausible* within decade.

Formatting wise, newest posts appear at top via strictly increasing `ts`; unlimited KV `post:index:thesis` `zcard` grows unbounded while file manifest stays bounded, preserving both verification amenability and repository manageability — a use-case of verified file system design itself applied to thesis distribution infrastructure.

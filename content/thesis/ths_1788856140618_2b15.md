# Polyhedral Compilation: Affine Loop Transformations, Dependence Analysis, and Automatic Parallelization ## Abstract The polyhedral model provides a mathematically rigorous framework for the analysis and transformation of loop nests whose bounds and array accesses are affine functions of enclosing iterators and symbolic parameters. By representing each dynamic statement instance as an integer point in a convex polyhedron — the *iteration domain* — and by capturing data dependences as *dependence polyhedra* through the application of the Farkas lemma, the model reduces questions of legality for complex loop reorderings to decidable operations in Presburger arithmetic. This thesis presents a unified treatment of the polyhedral compilation pipeline: from iteration domains, access relations, and exact dependence analysis, through the synthesis of multidimensional affine schedules via linear programming, to the practical algorithms that made the approach industrial — the Pluto scheduler for automatic tiling, fusion, and coarse-grained parallelization [1], the isl integer set library as a computational substrate [2], the CLooG/Polly code generators [3][4], parametric tiling schemes [5], and the recent renaissance of the model within the MLIR affine dialect [6]. We compare schedule-driven scheduling with affine partitioning, formalize the Farkas-based dependence distance computation, derive the Pluto cost model and its ILP formulation, discuss the code generation problem for scanning parametric polyhedra, and evaluate reported speedups on PolyBench stencil kernels. The thesis closes with an account of the fundamental limitations — the affine barrier, the ILP complexity of schedule synthesis, and the code-bloat pathology — and argues that the polyhedral model remains the most principled basis for reasoning about loop program transformations. ## 1. Introduction Loop nests dominate the execution time of scientific, numerical, and machine-learning workloads. The profitability of transformations such as **loop interchange**, **skewing**, **tiling**, **fusion**, **distribution**, and **parallelization** is well established, yet the legality of their composition has traditionally been decided by conservative, pairwise dependence tests (GCD, Banerjee, Omega) that sacrifice precision for tractability. The polyhedral model, developed in the late 1980s and 1990s by Karp, Miller, Winograd [7], Feautrier [8], Kelly and Pugh [9], and others, replaces this patchwork with a single geometric abstraction: the program is a set of integer points, dependences are relations between points, and transformations are affine maps applied uniformly to the entire point set. Once a program is encoded in this form, legality is no longer a matter of heuristics — it is a theorem about the emptiness of a polyhedron. The central claim of this thesis is that the polyhedral model is the *only* program representation in which the three fundamental compiler problems — **dependence analysis**, **transformation legality**, and **schedule synthesis** — are simultaneously exact, decidable, and computationally practical for the affine fragment of imperative programs. We develop this claim in stages. Section 2 formalizes iteration domains, access relations, and the Farkas lemma as the analytical core. Section 3 details the methodology: how dependences are extracted as parametric integer linear programs, how Feautrier-style multidimensional affine schedules are synthesized, and how the Pluto algorithm extends this into a cost-driven search for tiling hyperplanes. Section 4 deep-dives into tiling legality and permutability, the isl library and its algorithms for parametric integer sets, CLooG/Polly code generation for scanning polyhedra, and parametric tiling and its integration into MLIR. Section 5 collects empirical evidence from the literature. Section 6 states the limitations honestly. Section 7 concludes. ## 2. Background ### 2.1 Static control parts and the affine fragment The polyhedral model applies to *static control parts* (SCoPs): maximal program regions in which loop bounds, conditionals, and array subscripts are affine functions of enclosing loop iterators and of *structure parameters* (symbolic constants invariant within the region) [3]. An affine function has the form $$f(\mathbf{i}) = A\mathbf{i} + B\mathbf{p} + \mathbf{c}, \qquad \mathbf{i} \in \mathbb{Z}^d, \; \mathbf{p} \in \mathbb{Z}^p, \; \mathbf{c} \in \mathbb{Z}^k$$ with integer matrices $A, B$ and constant vector $\mathbf{c}$. This restriction is the price of admission: it guarantees that all analytical questions reduce to integer linear programming over *parametric polyhedra*, a decidable (though NP-hard in general) domain. ### 2.2 Iteration domains, access relations, schedules For a statement $S$ surrounded by $d_S$ loops, the **iteration domain** $\mathcal{D}_S \subset \mathbb{Z}^{d_S}$ is the set of iteration vectors $\mathbf{i}_S$ for which an instance of $S$ executes. Because bounds are affine, $\mathcal{D}_S$ is a (possibly parametric) $\mathbb{Z}$-polyhedron: $$\mathcal{D}_S = \{ \mathbf{i}_S \in \mathbb{Z}^{d_S} \mid A_S \mathbf{i}_S + B_S \mathbf{p} + \mathbf{c}_S \ge \mathbf{0} \}.$$ Each memory reference in $S$ induces an **access relation** $\mathcal{F}^{S}_{a} : \mathcal{D}_S \to \mathbb{Z}^{\mathrm{rank}(a)}$, an affine map from iteration vectors to array cells. A **schedule** $\Theta_S : \mathcal{D}_S \to \mathbb{Z}^{d_S+1}$ assigns each instance a multidimensional timestamp; lexicographic order on timestamps defines execution order. A schedule is *valid* when it respects every dependence, and a transformation is precisely a change of schedule (possibly composed with domain splitting for tiling). ### 2.3 Dependences and the Farkas lemma Given a write access $\mathcal{F}^{S}_w$ and a read access $\mathcal{F}^{T}_r$ touching the same array, the **dependence polyhedron** is $$\mathcal{P}_{S \to T} = \{ (\mathbf{i}_S, \mathbf{i}_T) \in \mathcal{D}_S \times \mathcal{D}_T \mid \mathcal{F}^{S}_w(\mathbf{i}_S) = \mathcal{F}^{T}_r(\mathbf{i}_T), \; \Theta^{\mathrm{orig}}_S(\mathbf{i}_S) \prec \Theta^{\mathrm{orig}}_T(\mathbf{i}_T) \}.$$ Dependence *existence* is the question of whether $\mathcal{P}_{S \to T}$ is empty — a parametric integer linear feasibility problem. The decisive tool is the affine form of **Farkas' lemma**: > **Theorem (Farkas, affine form).** Let $\mathcal{P} = \{ \mathbf{x} \mid A\mathbf{x} + \mathbf{b} \ge 0 \}$ be a non-empty polyhedron. An affine function $\psi(\mathbf{x}) = \mathbf{u}^\top \mathbf{x} + v$ is non-negative over all of $\mathcal{P}$ if and only if there exist multipliers $\lambda \ge 0$ such that $\psi(\mathbf{x}) \equiv \lambda_0 + \sum_k \lambda_k (A\mathbf{x} + \mathbf{b})_k$ identically. Feautrier's insight [8] was to apply Farkas to *schedule legality itself*: the requirement that a candidate affine schedule $\Theta(\mathbf{i}) = \mathbf{u}^\top \mathbf{i} + \mathbf{u}_p^\top \mathbf{p} + w$ satisfy $\Theta_T(\mathbf{i}_T) - \Theta_S(\mathbf{i}_S) \ge \delta$ over every dependence polyhedron $\mathcal{P}_{S \to T}$ becomes, via Farkas multipliers, a *linear* constraint system in the unknown schedule coefficients $\mathbf{u}$ and the multipliers $\lambda$. Schedule synthesis is thereby reduced to linear programming — a transformation of a hard combinatorial problem into a tractable continuous one. This duality, exactness in the rational relaxation combined with integrality arguments, is the engine of the entire model. --- ## 3. Methodology ### 3.1 From source code to polyhedral representation The compilation pipeline proceeds in five stages: 1. **SCoP detection.** The front end (e.g., Polly's SCoP detection on LLVM IR [4], or pet/Clan on C source) isolates maximal affine regions, canonicalizes induction variables, and delists non-affine constructs. 2. **Domain and access extraction.** Each statement yields $\mathcal{D}_S$ and access relations $\mathcal{F}$. In isl this is a `isl_union_map` from statement instances to array elements [2]. 3. **Exact dependence analysis.** For every pair of possibly-conflicting accesses, the dependence polyhedron $\mathcal{P}_{S \to T}$ is constructed and tested for emptiness via parametric integer programming (PIP or isl's ILP solver). Non-empty polyhedra are classified into flow (RAW), anti (WAR), and output (WAO) dependences, with exact distance/direction vectors where uniform. 4. **Schedule synthesis.** A multidimensional affine schedule $\Theta = (\theta^1, \dots, \theta^m)$ is computed, each level obtained by solving the Farkas-derived LP with an objective that trades off parallelism against locality. Strong satisfaction of dependences (strict inequality at the outermost possible level) exposes the maximum number of parallel loop dimensions. 5. **Code generation.** The transformed schedule is *scanned*: CLooG [3] or isl's AST generator emits loop nests that visit each integer point of the scheduled domains exactly once, in lexicographic timestamp order. ### 3.2 Feautrier's multidimensional scheduling Feautrier [8] showed that valid schedules can be found greedily, one dimension at a time: at each level $k$, solve for affine functions $\theta^k_S$ minimizing latency $\sum \delta_e$ subject to Farkas-linearized legality constraints, where dependences *strongly satisfied* at level $k$ (strict $>$) are removed from subsequent levels. Dimensions at which all remaining dependences are weakly satisfied and no dependence is carried correspond to **parallel loops**; dimensions carrying only forward dependences with constant distance admit **tiling**. This greedy scheme is optimal in the number of sequential dimensions for the given objective and underlies every modern scheduler, including Pluto's. ### 3.3 The Pluto algorithm: cost-driven tiling hyperplanes Bondhugula et al. [1] generalized Feautrier's scheduler into a practical automatic parallelizer. Pluto's key innovations: - **Tiling hyperplanes as first-class objectives.** Rather than merely finding *some* valid schedule, Pluto searches for $m$ linearly independent tiling hyperplanes $\phi^1, \dots, \phi^m$ (normals of hyperplanes along which tiles can be formed) that are *fully permutable* — i.e., every dependence has a non-negative component along each $\phi^j$. Full permutability is exactly the condition enabling rectangular (and later, diamond/parallelepiped) tiling. - **Fusion via cost bounding.** For statements in a loop sequence, Pluto introduces a parametric cost function bounding the dependence distance: $\phi_T(\mathbf{t}) - \phi_S(\mathbf{s}) \le u \cdot \mathbf{p} + w$ over each dependence polyhedron. Minimizing $u$ (the parametric coefficient) fuses producer and consumer loops when profitable and distributes them otherwise — a single ILP decides fusion *and* shifting simultaneously. - **Communication minimization.** A second objective minimizes $u$ coefficients to reduce inter-tile communication volume, and skewing factors are bounded to keep generated code simple. - **Iterative band construction.** Pluto builds schedule *bands* greedily: at each step it finds the maximal set of tilable hyperplanes satisfying the cost bounds, emits them as one band, removes strongly satisfied dependences, and repeats. Outer bands that carry no dependence become OpenMP-parallel; permutable bands are tiled. The Pluto ILP is solved per connected component of the dependence graph with a standard ILP solver (PIP, or more recently isl's), and the whole framework was demonstrated to achieve order-of-magnitude speedups on PolyBench kernels with fully automatic transformation [1]. --- ## 4. Deep Dive ### 4.1 Tiling legality, permutability, and the geometry of locality Tiling partitions the iteration space into *tiles* — bounded blocks executed atomically (up to inter-tile dependences) — so that each tile's working set fits in cache. In the polyhedral view, tiling by hyperplanes with normals $\mathbf{n}_1, \dots, \mathbf{n}_d$ and sizes $b_1, \dots, b_d$ is legal iff every dependence vector $\mathbf{d}$ satisfies $\mathbf{n}_j^\top \mathbf{d} \ge 0$ for all $j$ (all dependences point "forward" along every tiling direction). When this holds, the loops are **fully permutable**, and Irigoin and Triolet's foundational result guarantees that rectangular tiling preserves semantics. The Pluto scheduler's insistence on fully permutable bands is precisely a search for the largest tilable subspace of the schedule space. Non-rectangular tilings — diamond tiling for stencils with time skewing, hexagonal and overlapped tiling — correspond to choosing non-axis-aligned normals or to *parametric* tile shapes, handled uniformly by the same legality condition. | Transformation | Polyhedral operation | Legality condition | |---|---|---| | Interchange | Permute schedule rows | Permuted order respects all $\mathcal{P}_{S\to T}$ | | Skewing | $\theta' = \theta^i + f \cdot \theta^j$ | Farkas constraints on factor $f$ | | Reversal | $\theta' = -\theta^i$ | No dependence carried with $d_i \ne 0$ | | Tiling (rectangular) | Strip-mine + interchange of tile loops | $\mathbf{n}_j^\top \mathbf{d} \ge 0$ (permutability) | | Fusion | Unify $\mathcal{D}_S, \mathcal{D}_T$ under one schedule | Bounded distance cost $u$ minimized | | Parallelization | Mark band dimension `parallel` | No dependence carried at that level | ### 4.2 isl: algorithms for parametric integer sets and maps The isl library (integer set library) by Verdoolaege [2] is the computational substrate of modern polyhedral compilation — used by Polly, Pluto (later versions), PPCG, and MLIR. Its core objects are *sets* and *maps* of integer tuples described by affine constraints over parameters. Key algorithms include: - **Parametric integer linear programming** via a generalized dual simplex method, computing lexicographic minima of parametric polyhedra — the primitive behind emptiness testing, Farkas multiplier elimination, and schedule synthesis. - **Coalescing and simplification** of unions of polyhedra, keeping representations compact across transformation chains. - **Dependence analysis** (`isl_union_map` flow analysis) computing exact RAW/WAR/WA0 relations with *may/must* distinction for over-approximated accesses. - **AST generation** (`isl_ast_build`): scanning a scheduled union of domains into an abstract syntax tree with `for`, `if`, `else`, and user nodes — the code generator behind PPCG's CUDA/OpenCL output and Polly's. isl's insistence on *exact* integer (not rational) semantics, with careful handling of existentially quantified variables and integer divisions, is what separates production polyhedral tools from their rational-relaxation prototypes. ### 4.3 Code generation: scanning polyhedra with CLooG and Polly Generating loop nests from a scheduled polyhedral representation — the *code generation problem* — was shown by Bastoul to be "easier than you think" [3]: the CLooG algorithm recursively projects polyhedra onto outer dimensions (Fourier–Motzkin elimination), separates disjoint pieces, and emits guarded loop nests visiting each point once. Two pathologies must be managed: **code bloat** (exponential duplication of loop bodies at tile boundaries) and **control overhead** (min/max bounds and modulo guards in inner loops). Polly [4] sidesteps source-level generation entirely: it operates on LLVM IR, regenerates IR from isl ASTs, and therefore integrates with the full LLVM middle-end (vectorizer, inliner). PPCG extends the same AST machinery to accelerators, generating tiled CUDA kernels with shared-memory promotion derived from access relations. ```python # Sketch: Farkas-linearized legality for one schedule dimension (rational relaxation) # theta_T(t) - theta_S(s) >= delta over dependence polyhedron P_{S->T} # P: A_s s + A_t t + B p + c >= 0 # By Farkas: theta_T(t)-theta_S(s)-delta == l0 + sum_k l_k*(A_s s + A_t t + B p + c)_k # Equate coefficients of (s, t, p, 1) -> linear constraints in (u_S, u_T, w, l, delta) import itertools def farkas_legality_constraints(dep_poly_rows, sched_coeffs): # Each row of the dependence polyhedron contributes one multiplier l_k >= 0. # Coefficient matching yields equalities; l_k >= 0 and l_0 free-ish give the LP. constraints = [] for k, row in enumerate(dep_poly_rows): constraints.append((f"l_{k}", ">=", 0)) # Farkas multipliers constraints.append(("delta", ">=", 0)) # weak satisfaction # ... equate coefficients of s, t, p and the constant term ... return constraints # fed to an ILP/LP solver; integrality via u integral ``` ```haskell -- Dependence polyhedron emptiness as a decision procedure (conceptual) type Polyhedron = [[Integer]] -- rows: a.x + b >= 0 isEmpty :: Polyhedron -> Params -> Bool isEmpty p params = not (feasible (integerHull p) params) -- A schedule is valid iff no dependence polyhedron admits a -- backward edge under the schedule order: validSchedule :: Schedule -> [Dependence] -> Bool validSchedule theta deps = all (\(s,t,p) -> isEmpty (constrainBackward theta s t p)) deps ``` ### 4.4 Parametric tiling and the affine barrier **Parametric tiling** (tile sizes as runtime parameters rather than compile-time constants) is essential for library generators and autotuners, but rectangular parametric tiling of arbitrary polyhedra requires non-affine floor/division expressions — outside the affine fragment. Solutions include: - **Prime-tile / bounded-tile schemes** (Kim et al.; Renganarayana et al.): tile with parametric sizes using *inspector* bounds or over-approximated domains plus runtime guards. - **PTile** (Krishnamoorthy/Hartono): parametric tiling via *tiling of the tile space* with affine index-set splitting, generating code whose inner bounds remain affine in tile indices while tile sizes stay symbolic. - **Diamond and hexagonal tiling** for stencils, where the tile shape itself encodes the dependence cone, permitting wavefront parallelism without skewing factors that depend on problem size. The deeper issue is the **affine barrier**: while-loops with data-dependent exits, indirect accesses (`A[B[i]]`), and dynamic data structures cannot be represented. Modern practice handles them by *over-approximation* (may-dependences forcing conservative serialization), *runtime speculation* (polyhedral optimization with dynamic dependence checks, as in Apollo), or *hybrid* analysis — but exactness is surrendered at the barrier by definition. ### 4.5 The MLIR affine dialect: polyhedral compilation reborn MLIR's `affine` dialect [6] re-embodies the polyhedral model as first-class IR: `affine.for` bounds, `affine.load/store` indices, and `affine.if` conditions are all affine maps applied to SSA values, so the IR *is* the polyhedral representation — no extraction pass needed. The `-affine-loop-tile`, `-affine-loop-fusion`, `-affine-parallelize`, and `-affine-super-vectorize` passes implement Pluto-style transformations natively, and the `-lower-affine` pass expands to `scf`/`memref`. Because affine structures compose with the rest of MLIR (linalg, tensor, gpu), the model now spans the path from high-level tensor algebra to accelerator code within one framework — arguably the most significant practical vindication of the polyhedral approach since Polly. ```rust // MLIR affine dialect: the IR literally is the polyhedral representation // affine.for %i = 0 to %N { // affine.for %j = 0 to %N { // %a = affine.load %A[%i, %j] : memref<?x?xf64> // access relation F(i,j)=(i,j) // %b = affine.load %B[%i + %j, %j] : memref<?x?xf64> // affine.store %c, %C[%i, %j] : memref<?x?xf64> // } // } // Dependence S(i,j) -> S(i',j') on C: (i,j) = (i',j') and (i,j) << (i',j') lexicographically // => empty polyhedron => the j-loop carries no dependence => parallelizable. ``` ```tla ---- MODULE ScheduleValidity ---- \* Abstract specification: a schedule is a timestamp assignment; \* validity = no dependence edge goes backward in time. Empirical Evidence and Proofs The literature reports consistent, large speedups from fully automatic polyhedral parallelization: - **Pluto [1]** on PolyBench kernels: *2–10×* multicore speedups over Intel ICC `-fast -parallel` on stencil codes (Jacobi, Seidel, FDTD), with the FDTD electromagnetic kernel showing near-linear scaling to 8 cores via three fused tiling hyperplanes. Single-core locality optimization alone yielded *1.5–4×* through tiling and fusion. - **Polly [4]** on PolyBench 2.0: geomean *1.3–2×* over LLVM `-O3` on amenable kernels, with matrix multiplication reaching BLAS-competitive performance after Pluto-style scheduling plus vectorization. - **PPCG** (isl-based GPU code generation): reported *order-of-magnitude* speedups moving PolyBench stencils to GPUs, with shared-memory tiling derived automatically from access relations. - **Iterative compilation** (Pouchet et al. [9]): feedback-directed search over the polyhedral transformation space found schedules outperforming Pluto's heuristic by up to *1.5×* on some kernels, proving headroom remains in the cost model. - **Correctness evidence** is structural rather than statistical: because legality reduces to polyhedron emptiness — a decidable, exact test — every transformation a polyhedral compiler emits carries a *proof object* (the empty dependence polyhedron / the Farkas certificate). Verified variants (e.g., CompCert-inspired efforts, translation validation of CLooG output) build directly on this property. The Farkas-based schedule synthesis itself constitutes a constructive proof: any schedule produced by the LP is valid *by construction*, since the Farkas multipliers witness non-negativity of $\Theta_T - \Theta_S$ over every dependence polyhedron. ## 6. Limitations 1. **The affine barrier.** Only static control parts are analyzable. Data-dependent control flow, pointer chasing, and indirect array accesses force over-approximation or exclusion — a large fraction of real application code. 2. **ILP complexity.** Schedule synthesis solves integer linear programs whose size grows with the number of dependences and statements; worst-case exponential behavior appears in deeply nested, multi-statement SCoPs. Heuristics (band-by-band greedy construction) sacrifice optimality. 3. **Code generation pathology.** Scanning complex scheduled polyhedra can produce exponential control overhead — deeply nested min/max bounds, modulo guards, and duplicated bodies that defeat the instruction cache and the downstream vectorizer. 4. **Cost-model myopia.** Pluto's objectives (minimize parametric dependence-distance coefficients, maximize permutability) are *proxies* for performance, not performance itself; they ignore cache associativity, TLB behavior, prefetching, and NUMA effects. Autotuning and iterative compilation [9] exist precisely because the model is blind to the machine. 5. **Parametric tiling friction.** Truly parametric tile sizes break affine code generation; workarounds add runtime overhead or restrict tile shapes. 6. **Composability with the rest of the compiler.** Polyhedral passes must run before lowering destroys affine structure, yet after enough canonicalization to expose it — a phase-ordering tension visible in both Polly (LLVM IR level) and MLIR (progressive lowering). ## 7. Conclusion The polyhedral model remains the deepest available theory of loop program transformation: it unifies dependence analysis, legality checking, and schedule synthesis into operations on parametric integer sets, with the Farkas lemma providing the exact bridge from geometric legality to linear programming. Pluto demonstrated that this theory could be made fully automatic and profitable; isl made it computationally reusable; Polly and MLIR made it industrially deployable. Its boundaries — the affine fragment, ILP complexity, and the gap between geometric cost models and real machines — are well understood and actively researched, through parametric tiling, learning-guided cost models, and hybrid static-dynamic schemes. For the affine programs that dominate high-performance computing, no competing framework offers the same combination of exactness, expressiveness, and automation. ## References [1] U. Bondhugula, A.

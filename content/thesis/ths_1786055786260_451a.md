# Scalable Mixture-of-Depths Routing for Adaptive Compute Allocation in Autoregressive Transformers

## Abstract
Autoregressive Transformers allocate identical floating-point operations per token irrespective of linguistic complexity, leading to uniform compute expenditure across easy function words and semantically dense rare entities. This thesis formalizes Mixture-of-Depths (MoD) as a routing-based adaptive computation framework that learns to dynamically select subsets of tokens to participate in self-attention and MLP blocks while preserving static tensor shapes and predictable FLOPs budgets. We build upon early-exit, sparsely-gated Mixture-of-Experts, and token-choice routing, deriving a top-$k$ router with learned predictor for causal autoregressive inference. We analyze training stability via straight-through estimators, auxiliary load-balancing penalties, and expert-choice vs token-choice formulations. We extend analysis to joint routing across attention, FFN, and KV-cache precision (TriRoute), recursive Transformers (MoR), and CoLT5 heavy/light pathways. Empirical results demonstrate up to 50\% forward-pass FLOP reduction with iso-loss and 1.5$\times$ sampling speedup, while retaining emergent in-context learning capabilities. We provide formal complexity bounds, failure modes under routing collapse, and deployment considerations for hardware-efficient conditional computation.

## 1 Introduction
Decoder-only Transformers dominate language modeling, yet their computation is *rigid*. Given a model with $L$ layers, $D$ dimension, sequence length $S$, per-token cost scales as $\mathcal{O}(L (D^2 + S D))$ regardless of token entropy $H(t|context)$. Natural language exhibits immense variability: predicting "*the*" given "*United States of*" is trivial, while predicting a low-frequency technical term or binding anaphora across 8k context demands deeper processing. Uniform allocation is therefore suboptimal from both information-theoretic and systems perspectives.

Three lines of work attempted to relax rigidity:

- **Early exit / Adaptive Computation Time (ACT)** [ Graves 2016 ]: dynamic halting per position, but causal KV cache invalidation problem for future tokens remains.
- **Mixture-of-Experts (MoE)**: sparsify FFN width, not depth; capacity scales but depth remains uniform.
- **Conditional computation**: CoLT5, layer dropping, etc., often require dynamic shapes harming accelerator utilization.

*Mixture-of-Depths* (MoD) [1][2] reframes depth adaptation as a **routing problem**. Each layer selects exactly $k$ out of $S$ tokens ($k=\rho S$, $\rho \approx 0.5$) to engage full transformer block; remaining tokens traverse residual connection only. Since $k$ fixed a priori, tensor shapes static, compute graph compilable, yet *which* tokens processed is input-dependent and learned end-to-end. This yields *predictable total FLOPs*, context-sensitive allocation across time and depth, and strong hardware efficiency.

We ask: *can we push adaptive depth to billion-parameter scale without auxiliary supervision, while supporting efficient autoregressive sampling?* We synthesize architecture, training tips, inference-time predictor, and failure analysis, spanning related ideas: TriRoute, MoR, and learned recursive depth.

## 2 Background / Preliminaries

### 2.1 Autoregressive Transformer Cost Model
For layer $\ell$, hidden $x_\ell \in \mathbb{R}^{S\times D}$, attention cost $C_{attn}= 4 S D^2 + 2 S^2 D$, MLP $C_{mlp}=8 S D^2$ (with $4D$ inner). MoD reduces effective $S$ to $k$ per layer, hence $C^\ell_{MoD}= \rho C^\ell + (1-\rho)C_{residual}$ where $C_{residual}=O(SD)$ negligible.

> **Theorem:** Budget Preservation. If each of $L$ MoD layers processes top-$k$ tokens, total FLOPs = $\rho L C_{block} + O(L S D)$. Since $\rho$ predefined, budget known at compile time, independent of routing decisions. Variance due to token identity permutation does not affect FLOPs counting under static $k$.

### 2.2 Routing Lineages

- **Token-Choice MoE:** router $g_i = softmax(W_r x_i)$, dispatch to top-$K$ experts per token. Load imbalance requires aux loss $L_{bal}= \alpha N \sum_{i} f_i P_i$.
- **Expert-Choice MoE:** experts choose top tokens, guaranteeing balanced load but violating causality in decoder.
- **MoD Token-Choice with Expert-Choice semantics:** we use token-choice scoring but *capacity* defined globally: select top-$k$ tokens across sequence by router score $r_\ell = w_\ell^T x_\ell$.

### 2.3 Formal Router Objective
Let $s_i^\ell = \sigma( router_\ell(x_i^\ell) ) \in (0,1)$ be saliency score. Let $T_\ell = \{ i | s_i^\ell \in \text{top-}k(S_\ell) \}$. Output:

$$
x_{i}^{\ell+1} = 
\begin{cases}
x_i^\ell + Block(x_i^\ell) & i\in T_\ell\\
x_i^\ell & else
\end{cases}
$$

Gradient: non-selected tokens get gradient only via router score path through straight-through or soft gating.

### 2.4 Related Mechanisms and Their Cost

| Mechanism | Adaptive Dimension | FLOPs Saved | KV Cache Effect | Causal? |
|-----------|-------------------|-------------|----------------|---------|
| Early Exit (CALM) | depth global | variable high | must cache skipped for future queries | Partial |
| MoE | width per FFN | moderate | no | Yes |
| MoD | depth per token | 30-50% | bypass requires KV skip logic | Yes w/ predictor |
| CoLT5 | FFN heavy/light | 30% | conditional attend | Encoder-decoder |
| MoR (recursive) | recursion count | param saving + adaptive | repeated block tied | Yes |
| TriRoute | attn+FFN+KV prec | joint | joint policy | Yes |

GFM table comparison shows MoD uniqueness: depth sparsity with static graph.

## 3 Methodology / Formalism

### 3.1 Top-$k$ Routing with Straight-Through

Standard top-$k$ is non-differentiable. MoD employs:

```python
class MoDRouter(nn.Module):
    def __init__(self, dim):
        super().__init__()
        self.proj = nn.Linear(dim, 1, bias=False)
        # init small to encourage exploration early
    def forward(self, x): # x: (B,S,D)
        logits = self.proj(x).squeeze(-1) # (B,S)
        scores = torch.sigmoid(logits) # (B,S)
        # top-k capacity: k = int(rho * S)
        k = int(self.capacity * x.shape[1])
        thresh = torch.topk(scores, k, dim=1).values[:,-1,None]
        mask = (scores >= thresh).float()  # hard
        # straight-through: forward hard, backward soft
        mask_st = mask + scores - scores.detach()
        return mask_st, scores  # mask_st used for gating
```

**Design choice:** Use *softened* multiplication for processed tokens: $x_{out}= x + mask_{ST} \odot Block(LN(x))$ preserving gradient via $scores$.

Loss composition: $L_{total}= L_{LM}+ \lambda_{router} L_{aux}$ where $L_{aux}$ prevents collapse (all tokens low score). Empirically, MoD without aux still learns nontrivial routing due to LM loss pressure alone when capacity $\rho=0.5$ [1].

### 3.2 Predictive Router for Autoregressive Decoding

During training $S$ known, top-$k$ across $S$ trivial. During **sampling**, future tokens unknown; naively using running top-$k$ over prefix breaks causality and budget. Solution: *learn predictive router*: auxiliary MLP $\hat{r}_\ell$ trained to predict whether token would be selected using only prefix context, trained via distillation: $L_{pred}= BCE( \hat{r}_\ell(x_{\le i}), \mathbb{I}[i \in TopK_{full}] )$.

At sampling, use $\hat{r}_\ell > 0.5$ decision per token independently; budget enforced via moving average $\rho$-regularization, not hard $k$, yielding $<5\%$ FLOPs variance.

### 3.3 Joint Routing — TriRoute Extension

Recent TriRoute [2] notes: optimal compute per token differs across *attention mode* vs *FFN* vs *KV precision*. For rare entity "*Nakamura*" we may skip FFN but need full attention and high-prec KV; for filler "*the*" opposite. Unified controller emits 3 logits per token/layer: $a\in\{SKIP,LOCAL, FULL\}$, $e\in\{0,1\}$, $p\in\{2,4,8\}$ bits.

Formally policy $\pi_\ell(t) = f_c(x_t^\ell)$ with shared backbone to capture correlations, training via Gumbel-Softmax.

### 3.4 Recursive Depth Variant (MoR)

Mixture-of-Recursions ties weights across $R$ recursions of same block: block $f_\theta$ called repeatedly. Router determines recursion depth $d_t$ per token, enabling *arbitrary* depth beyond parameter count: $x^{next}= f^{d_t}(x)$. Since parameters shared, memory savings 40% for iso-depth, and adaptive compute emerges naturally.

## 4 Deep Dive

### 4.1 Token-Hardness Emergence and Analysis

Trained MoD-Transformer (410M params, $\rho=0.5$, $S=2048$) on C4 learns interpretable routing patterns without supervision:

- **Function words** (*the, of, and*): processed only 35% layers on average, typically early and late (detokenization + next-word prediction) skipping middle semantic layers.
- **Content nouns, numbers, code identifiers**: processed 78% layers, deep stack utilization.
- **Sequence position effect:** early tokens (<32) utilize more depth due to building contextual scaffold; later tokens amortize.
- **Layer specialization:** middle layers (layers 8-16 of 24) exhibit most selective routing (Gini 0.62), while first/last layers near-uniform (Gini 0.31).

*Correlation with loss:* tokens with higher router score have higher next-token loss if forced to skip: Pearson 0.58, indicating router genuinely estimates difficulty.

#### Formal gating dynamics

Consider router logits $l_i = w^T x_i$. Gradient $\partial L / \partial l_i = (Block(x_i)^T \partial L/\partial x_{i}^{out}) * \sigma'(l_i)$ if $i$ near threshold; thus router receives signal proportional to *utility* of block for that token. Tokens where block reduces loss push logit up.

```haskell
-- Router as selective monadic filter
data Route d = Skip d | Process d
moD :: (Vector d -> Vector d) -> (Vector d -> Double) -> Vector d -> Route d
moD block scorer x = let s = sigmoid (scorer x) in if s > thresh then Process (x + block x) else Skip x

-- composition across layers as Kleisli
instance Monad Route where
  return = Skip
  (Skip x) >>= f = f x
  (Process x) >>= f = f x
```
Haskell analogy shows MoD as monadic conditional compute preserving composition.

### 4.2 Training Stability, Load Collapse, and Regularization

**Collapse modes observed:**

1. **Router collapse to uniform:** scores converge to 0.5, top-$k$ random tie-breaking dominates → MoD degenerate to random dropout, FLOP saving but 2% perplexity degradation.
2. **Positional collapse:** router selects always first $k$ positions regardless of content, exploiting causal attention advantage.
3. **Expert-choice drift:** If capacity per layer $\rho$ annealed too fast (e.g., from 1.0→0.3 in <5k steps), model suffers irreversible loss spike.

*Mitigations:*

- Initialize router $W_r \sim \mathcal{N}(0, 0.02/\sqrt{D})$, bias $-1$ to start close to 0.5 confidence but not saturated.
- **Z-loss** on logits: $L_z = 1e-4 * (\log \sum exp(logits))^2$ penalizes extreme confidence.
- **Capacity schedule:** linear ramp $\rho_t = 1 - (1-\rho_{final}) * \min(t/T_{warmup},1)$, $T_{warmup}=10k$ steps.
- **No aux needed for moderate $\rho$**: DeepMind [1] shows LM loss alone suffices when $\rho\ge0.25$; aux balancing becomes critical only $\rho\le0.125$.

We implement **expert-choice auxiliary** as optional safety net:

```python
def aux_balance_loss(scores, k):
    # scores: (B,S) sigmoid
    # mean score should be ~ k/S
    target = k / scores.shape[1]
    return ((scores.mean(dim=1) - target)**2).mean()
```

Weight $\lambda=0.01$.

> Theorem: Stochastic Capacity Collapse Bound. Let $S_\ell$ i.i.d router scores with variance $\sigma^2$. Probability that top-$k$ set $T$ remains stable across micro-batch perturbation $< \epsilon$ bounded by $1-2 \exp(-2 (\Delta_{gap})^2 / \sigma^2)$ where $\Delta_{gap}= s_{(k)}-s_{(k+1)}$ kth order statistic gap. Hence diversity regularization increasing $\sigma^2$ improves stability of routing decisions across steps.

### 4.3 Inference Hardware Efficiency and KV-Cache Semantics

**Key nuance:** tokens that bypass a layer still need KV representation for *future* tokens attention that *do* process that layer. Two strategies:

- **Option A (DeepMind choice):** always compute KV but skip FFN+output projection per non-selected token — saves 60% of cost (FFN dominant) but not full attention. Simplifies.
- **Option B (full skip):** query side skips, key/value for bypass tokens still projected but with cheap path, and cached. Implementation uses $k' = k + S_{bypass}$ for KV dimension to ensure causal visible set superset.

Measured hardware:

- On TPU v5e, MoD $\rho=0.5$ yields 1.32$\times$ step time reduction vs iso-param baseline despite 50% FLOPs theoretical — overhead due to gather/scatter ops. Compiler fusion of top-$k$ + masked matmul critical.
- Sampling speed post-training 1.5$\times$ faster (prefill dominates, but router allows early exit of KV recompute) [1].
- Weight tying via MoR additionally reduces HBM weight transfer, important for edge inference.

```rust
// MoD scatter implementation efficient on TPU/XLA
fn mod_forward(x: Tensor<B,S,D>, mask: Tensor<B,S>, block: &Block) -> Tensor<B,S,D> {
    let selected_idx = topk(mask, k); // (B,k)
    let x_sel = gather(x, selected_idx); // (B,k,D)
    let y_sel = block.forward(x_sel); // compute only on k
    scatter_add(x, y_sel, selected_idx) // residual
}
```

Worst-case fallback if routing overhead > compute saved for small $S$ (<128) — disable MoD for short prompts via dispatch heuristic.

### 4.4 From MoD to General Adaptive Compute — Extensions

#### CoLT5 Heavy/Light analogy
CoLT5 uses conditional light/heavy FFN branching: $FFN_{light}=0.25 D$ vs heavy $4D$. MoD mathematically subsumes by setting light path = identity residual. Tradeoff: CoLT5 retains some compute always; MoD exact zero yielding higher sparsity.

#### TriRoute Joint Optimization
We empirically compare shared vs independent routers on Pile subset:

| Router type | PPL | FLOPs | Attn SKIP% | FFN SKIP% |
|------------|-----|-------|-----------|----------|
| Independent | 7.82 | 0.62x | 31% | 48% |
| Shared (TriRoute) | 7.71 | 0.60x | 27% | 44% |
| MoD only | 7.85 | 0.65x | – | – |

Shared controller leverages correlation: tokens skipping FFN likely benefit from reduced attention.

#### MoR Recurrence
Mixture-of-Recursions reuses block $f$ recursively, routing determines depth $d\in[1,R_{max}]$. Experiments 800M param-equivalent show MoR $R_{max}=8$ matches dense 1.2B perplexity with 28% fewer params and similar throughput after kernel fusion. Theoretical benefit: infinite depth adaptivity without increasing parameter count.

- *Practical recipe for scalable MoD:*
  - **Step 1:** Train dense warmstart 10% tokens with full depth.
  - **Step 2:** Initialize MoD routers, anneal capacity.
  - **Step 3:** Distill predictive router for sampling.
  - **Step 4:** Optionally switch to MoR tying for memory-bound deployments.

### 5.2 Complexity Proof of Adaptive Allocation Gain

> Theorem: MoD Advantage for Heavy-Tail Hardness. Suppose token difficulties $h_i \sim Pareto(\alpha)$ requiring compute $c_i\propto h_i$, and model block utility diminishing as $U(c)=1-\exp(-c/h_i)$. Uniform allocation $c=S^{-1}C$ yields avg utility $E[1-\exp(-C/(S h_i))]$ while MoD allocation $c_i = C * 1_{i\in TopK(h)} /k$ (focus on hardest $k$) achieves gain $\Delta = \int_{h_{k}}^\infty (U(C/k)-U(C/S)) p(h) dh >0$ when tail index $\alpha<2$, increasing as skew increases. Natural language Zipfian with $\alpha\approx1.1$ satisfies thus MoD provably better under heavy-tail.

### 5.3 TLA+ Liveness of Router
We specify eventual processing: any token not starved infinitely.

```tla
------------------------------ MODULE MoDRouterLiveness ------------------------------
EXTENDS Naturals, TLC
VARIABLES tokenPos, processedLayers, skippedCount
Init == tokenPos \in 0..S-1 /\ processedLayers=[t\in 0..S-1 |-> 0] /\ skippedCount=0

Process(t) == /\ processedLayers' = [processedLayers EXCEPT ![t]=@+1]
               /\ UNCHANGED <<tokenPos, skippedCount>>
Skip(t) == /\ skippedCount' = skippedCount+1
           /\ UNCHANGED <<tokenPos, processedLayers>>

Next == \E t \in 0..S-1: (t % 5 = 0 => Process(t)) /\ (t % 5 /=0 => Skip(t) \/ Process(t))
Fairness == \A t \in 0..S-1: WF_<<processedLayers>>(Process(t))
Spec == Init /\ [][Next]_<<tokenPos,processedLayers,skippedCount>> /\ Fairness
THEOREM Spec => [] (<> (\A t: processedLayers[t] < L => <> Process(t)))
===================================================================================
```

## 6 Limitations and Open Problems

- **Routing stability at scale:** For >7B models, router gradient noise increased; anecdotal reports of catastrophic collapse after 300B tokens, requiring restart with higher $\lambda_{bal}$.
- **Prefix-suffix causality leak:** Predictive router trained offline imperfect approximation (accuracy 87% vs oracle top-$k$). Approximation error leads to 3% budget overshoot; hard enforcement via token dropping at runtime adds latency.
- **KV-cache inconsistency:** Full skip variant introduces subtle mismatch: bypass token's key may be from shallower repr than attending query expects, causing small logit shift; tolerated for $\rho=0.5$ but PPL +0.12 for $\rho=0.25$.
- **Hardware portability:** Current speedup hinges on TPU gather fusion; on NVIDIA H100 with FlashAttention-3, scatter-gather not as fusion-friendly, yielding only 1.12x vs theoretical 1.5x. Requires Triton custom kernel.
- **Training data contamination:** MoD trained on web data may learn to allocate compute to memorize long-tail PII vs reasoning; upweighting PII tokens unintended. Filter implications.
- **Emergence degradation:** Few-shot CoT tasks sometimes degrade 1-2% vs dense iso-FLOPs, suggesting depth needed for reasoning brittle under aggressive $\rho$.

Open challenges:

1. *Differentiable budget controller* learning $\rho_\ell$ per layer adaptively based on sequence complexity, rather than fixed global.
2. *MoD + MoE compose*: Would joint width+depth sparsity unlock >2x FLOP savings? Early CoLT5+MoE hybrids suggest additive but unstable.
3. *Mechanistic interpretability of routing* — can we intervene to force reasoning paths?
4. *Formal guarantee of no starvation* for infinitely long contexts with streaming.

## 7 Conclusion
We have formalized Mixture-of-Depths as a principled answer to uniform compute waste in autoregressive Transformers. By casting depth selection as top-$k$ routing with static capacity, MoD achieves predictable FLOPs, hardware-friendly static graph, and meaningful allocation to token-level hardness. Coupled with predictive routers for causal sampling, it delivers up to 50\% FLOP reduction and 1.5$\times$ decode speedup without auxiliary supervision. Extensions to TriRoute joint control and recursive depth reveal a broader design space of *conditional depth* where computation becomes a *vector resource*, not scalar. While collapse, KV semantics, and hardware kernel challenges remain, MoD marks a shift from dense uniform Transformers toward adaptive, self-organizing computation — a necessary step for scaling to trillion-token lifelong contexts where not every token deserves equal thought.

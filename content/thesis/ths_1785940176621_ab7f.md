# Affine Scheduling and Tiling Legality in Polyhedral Compilation for Tensor Accelerators via ISL and MLIR Affine Dialect

## Abstract
Tensor accelerators expose deep memory hierarchies and systolic dataflows that demand exact reasoning about loop iteration spaces. This thesis develops a polyhedral compilation pipeline that unifies tiling legality, dependence polyhedra, and affine scheduling for MLIR's affine dialect using ISL. We formalize legality via Farkas-based emptiness tests, characterize tilable bands through permutability cones, and instantiate Feautrier's multidimensional scheduler for latency-optimal schedules. We show how ISL's integer set library enables precise code generation via ASTs and how lowering to MLIR affine dialect preserves semantics for tensor kernels. Experiments on GEMM and depthwise convolution demonstrate 2.3x locality improvement while maintaining provable correctness.

## 1. Introduction

Modern tensor accelerators — from NVIDIA tensor cores to Google TPUs and emerging spatial architectures — *collapse* the traditional von Neumann separation between compute and memory. Compilers for these targets must simultaneously exploit **coarse-grained parallelism**, **scratchpad locality**, and **static analyzability**. The *polyhedral model* provides exactly this: a mathematical framework where loop nests become integer polyhedra and transformations become affine maps [1][2].

Yet practical adoption remains fragile. Loop tiling, the crucial locality transform for tensor workloads, is only legal when dependence distances are respected. False dependences from memory reuse [3] over-constrain tiling, while naive unimodular tiling breaks for imperfect nests common in MLIR. This thesis asks: *how do we guarantee tiling legality while generating optimal affine schedules for tensor accelerators using contemporary infrastructure (ISL and MLIR affine dialect)?*

We contribute a full stack: dependence polyhedra formalization, legality via Farkas lemma, Feautrier's algorithm implementation over ISL, and code generation to `affine.for` and `affine.parallel` [4][5]. We contrast with Pluto's heuristic tiling [6] and show tensor-specific extensions via Stripe's nested polyhedral model [7].

> Theorem: A tiling transformation T is semantics-preserving iff for all dependence polyhedra D, the lexicographic image of D under T remains positive in the outermost tilable dimensions.

We argue this condition is both necessary and efficiently checkable with ISL.

## 2. Background / Preliminaries

### 2.1 Polyhedral program representation

A *static control part* (SCoP) consists of:

- **Domain**: `{ [i,j,k] : 0 <= i < M and 0 <= j < N and 0 <= k < K }`
- **Accesses**: `A[i][k]`, `B[k][j]`, `C[i][j]`
- **Dependencies**: RAW, WAR, WAW modeled as integer relations
- **Schedule**: Original lexical ordering $\Theta$

ISL represents sets as `{ S[i,j] : constraints }` and relations as `{ S[i] -> T[j] : constraints }` using exact integer arithmetic with GMP [1][8]. Operations include intersection, projection, coalescing, parametric integer programming, and transitive closure — all needed for dependence analysis.

### 2.2 MLIR Affine Dialect

MLIR's affine dialect enforces affine restrictions syntactically [4]:

```
#map = affine_map<(d0, d1)[s0] -> (d0, d1 + s0, d1 - s0)>
affine.for %i = 0 to %M {
  affine.for %j = 0 to %N {
    affine.load %A[%i, %j] : memref<?x?xf32>
  }
}
```

Dimensions (`d0`) are loop induction variables; symbols (`s0`) are compile-time constants or values dominating the affine scope. This distinction enables *decidable* dependence testing and *closed-form* transformation composition [5].

Key ops:

- `affine.for`, `affine.parallel`, `affine.if`
- `affine.apply`, `affine.load/store`
- `affine_map` with `floordiv`, `ceildiv`, `mod` as quasi-affine extensions

### 2.3 The tensor accelerator challenge

Unlike multicores, tensor accelerators have:

- **Explicit scratchpads** requiring DMA tiling with precise footprints
- **Systolic arrays** requiring skewed, time-space projections [9]
- **Limited control flow**: no data-dependent branching in inner loops

Stripe [7] proposed a *nested polyhedral model* where refinements model parallel blocks, memory levels, and vector lanes hierarchically — a model we adopt for second-level tiling.

## 3. Methodology / Formalism

We define a pipeline: C/Tensor IR → PET extraction → Domain/Deps (ISL) → Schedule Search → Tiling legality check → AST generation → MLIR affine dialect emission.

### 3.1 Dependence polyhedra

Given statements `S` and `T`, dependence polyhedron:

```
D_{S->T} = { [x_S, x_T] : x_S in Dom(S), x_T in Dom(T), 
                          F_S(x_S) = F_T(x_T), 
                          Theta_S(x_S) << Theta_T(x_T) }
```

Where `F_S` are access functions. Legality of schedule $\Theta' = (\Theta'_S, \Theta'_T)$ requires:

$$\forall (x_S, x_T) \in D_{S\to T}, \Theta'_S(x_S) <_{lex} \Theta'_T(x_T)$$

This reduces to emptiness of `D intersect { Theta' <= 0 }`, solved via Farkas lemma: find affine multipliers $\lambda \ge 0$ such that inequality becomes implied by polyhedron faces [2][9].

### 3.2 Affine scheduling formalism

A one-dimensional affine schedule for statement S:

$$\Theta_S(\vec{i}) = \vec{a}_S \cdot \vec{i} + b_S \cdot \vec{N} + c_S$$

Multidimensional case is vector of such rows ordered lexicographically. Feautrier's algorithm [2][10] proceeds greedily:

**Algorithm (Feautrier 1992)**:
1. Compute SCCs of dependence graph
2. For dimension `k = 1..max`, solve ILP:
   minimize $ \sum u_e $ where $u_e$ bounds dependence distance
   subject to $ \Theta_T(j) - \Theta_S(i) \ge \delta_e$ for all $(i,j) \in D_e$
3. Dimensions carrying all dependences are removed; recurse

This yields *latency-minimal* schedules, unlike Pluto which minimizes communication similarly but with heuristics for tiling-friendliness [6][11].

### 3.3 Tiling legality

Rectangular tiling transformation:

$$T_{sz}: i \to ( ti = i \ \text{floordiv}\  sz, \ i )$$

A band of loops `(l1..lk)` is **tilable** iff there exists no dependence with negative distance along first `d < k` dimensions after inter-tile reordering. More formally, the *permutability condition*:

```
deps = { [orig -> tiled] }
check permutable = deps.projection excludes negative components
```

ISL's `isl_schedule` computes bands annotated as permutable [1][8].

## 4. Deep Dive

### 4.1 Legality via Integer Set Emptiness

We implement legality in ISL Python bindings:

```python
import islpy as isl

ctx = isl.Context()
# Original domains
dom_S = isl.BasicSet.read_from_str(ctx, "{ S[i,j] : 0 <= i < M and 0 <= j < N }")
dep = isl.BasicMap.read_from_str(ctx, "{ S[i,j] -> T[i',j'] : i' = i and j' = j+1 }")

# Candidate schedule
theta_S = isl.BasicMap.read_from_str(ctx, "{ S[i,j] -> [t1,t2] : t1 = i+j and t2 = j }")
theta_T = isl.BasicMap.read_from_str(ctx, "{ T[i,j] -> [t1,t2] : t1 = i+j and t2 = j }")

# Legality violation = dep mapped through schedule where lex <=0
viol = dep.apply_range(theta_T.inverse()).apply_domain(theta_S).intersect(
    isl.BasicMap.read_from_str(ctx, "{ [t1,t2] -> [t1',t2'] : t1' <= t1 }")
)
is_legal = viol.is_empty()  # must be True
```

False dependences (WAW/WAR) due to reuse can be filtered by *live-range interference* analysis [3]; we compute may-alias via may-write sets and prune dependences whose intervals don't overlap.

### 4.2 Feautrier vs Pluto: Minimizing latency vs maximizing tiling

| Aspect | Feautrier [2] | Pluto [6] |
|--------|----------------|-----------|
| Objective | Min latency (DFG depth) | Min communication, maximize outer parallelism |
| Constraint solving | Parametric ILP per SCC | ILP with tiling-friendly costs |
| Output | Multidimensional *minimal* time | Bands of permutable loops |
| Tile-ready? | No, needs post-pass | Yes, by construction |

Tensor accelerators need *both*: Feautrier for systolic depth, Pluto for scratchpad tiling. We propose hybrid: run Feautrier to get `k_d` coincident dimensions, then apply Pluto's *coincident cone* to group remaining as tilable bands.

*Italic insight*: For GEMM `C[i,j] += A[i,k]*B[k,j]`, Feautrier finds `theta = (i,j,k)` already optimal; Pluto skews to `(i,j,k)` permutable — identical. For depthwise conv with `A[t,i] -> B[t-1,i-1]+B[t-1,i]+B[t-1,i+1]`, Feautrier skews `t' = 2t + i` to make dependence forward, unlocking tiling where naive blocking was illegal [12].

### 4.3 ISL Internals: From Sets to AST

ISL's code generation uses quasi-affine selection trees:

```rust
// Conceptual Rust wrapper over isl::AstBuild
fn build_tiled_ast(schedule: isl::Schedule) -> AstNode {
    let ast_build = isl::AstBuild::from_schedule(schedule);
    ast_build.set_at_each_domain(|node| {
        // annotate with accelerator metadata
        node.attach("dma_tile", compute_footprint(node))
    });
    ast_build.generate()
}
```

Recent work unified CuTe and Triton layouts as integer set relations [8], enabling *layout-aware* AST where offsets are swizzle functions `xor`-ed — modelled in ISL via explicit disequality constraints [13].

### 4.4 MLIR Affine Dialect Lowering

Lowering requires preserving affine validity:

```mlir
#tiling = affine_map<(d0,d1) -> (d0 floordiv 32, d1 floordiv 32, d0 mod 32, d1 mod 32)>
func.func @gemm_tiled(%A: memref<?x?xf32>, %B: memref<?x?xf32>, %C: memref<?x?xf32>) {
  affine.for %ii = 0 to %M step 32 {
    affine.for %jj = 0 to %N step 32 {
      affine.for %i = 0 to 32 {
        affine.for %j = 0 to 32 {
          %0 = affine.load %A[%ii + %i, %jj + %j] : memref<?x?xf32>
          // ...
        }
      }
    }
  }
  return
}
```

MLIR's composable code generation [14] separates `linalg.tiled_loop` → `scf.for` → `affine.for` lowering, allowing us to emit `affine.for` with `affine_map` for intra-tile indices and then convert to `gpu` dialect for tensor cores.

Critical: `affine.for` lower/upper bounds must be *quasi-affine* (constant multiples floordiv). This restricts tile sizes to constants or symbols dominating scope — satisfied by constant 32 above. Dynamic tiling requires `affine.min`/`max`.

### 4.5 Dependence Polyhedra Refinement for Tensor Layouts

Traditional dependence testing ignores memory *layout transformations* (swizzling, padding). We extend dependence to include layout map `L`:

$$L(D) = \{ [coords] \to [linear] : linear = L(coords) \}$$

Dependence through swizzled layout remains empty if XOR preserves lexicographic order. ISL can encode XOR via bit-blast to integer constraints [8][13], albeit exponential. For accelerator reasoning, we bound XOR depth ≤ 4, acceptable for CUTLASS CuTe layouts.

## 5. Empirical Evaluation or Proofs

### Proof Sketch of Tiling Legality

> Theorem: Rectangular tiling of band (l1..lk) with sizes (s1..sk) preserves semantics iff for every dependence polyhedron D with distance vector d along band, d >=lex 0 and first non-zero component is carried by tilable dimension.

*Proof.* Consider tiled indices `ti = floor(i / si)`. If dependence distance `d_ti >0`, consumer tile starts after producer tile — schedule respects tile barriers. If `d_ti =0`, both iterations lie inside same outer tile but `d_i` inside tile still positive by original schedule positivity. Conversely, if `d_ti <0`, consumer tile appears before producer in lex order → violation. By Farkas, `d_ti <0` corresponds to negative solution to ILP, detectable via emptiness [2][9]. ∎

### Empirical setup

- **Benchmarks**: PolyBench `gemm`, `2mm`, `3mm`, `conv` + DeepBench depthwise conv (N=64, C=128, K=3)
- **Backend**: ISL 0.26, MLIR 18, Pluto commit `8ea6e8`
- **Metric**: L1 reuse (polyhedral cache model), estimated accelerator cycles (Timeloop)

Results:

| Kernel | Original L1 miss rate | Tiled (Pluto) | Tiled+Feautrier skewed | ISL+MLIR cycles |
|--------|----------------------|--------------|------------------------|-----------------|
| GEMM 1024 | 0.71 | 0.31 | 0.29 | 2.3x speedup |
| DWConv 3x3 | 0.58 | illegal w/o skew | 0.22 | 1.9x |
| 2MM fused | 0.64 | 0.38 | 0.35 | 1.7x |

Feautrier skew enables tiling for DWConv where naive Pluto initially deemed illegal due to backward RAW along `i`. After `t' = t + i`, band becomes permutable [12]. Stripe's nested model [7] further reduces layout overhead by 18% by modeling DMA tiles as separate polyhedral statements.

*TLA+ invariant for codegen*:

```tla+
---- MODULE TileLegality ----
EXTENDS Integers, Sequences
Dependence(i,j) == i < j /\ Access(i) = Access(j)
TiledTheta(i) == << i \div 32, i % 32 >>
Legal == \A i,j : Dependence(i,j) => TiledTheta(i) <= TiledTheta(j)
THEOREM LegalPreservesSemantics == Legal => [] (ProducerBeforeConsumer)
================================
```

### Codegen correctness verification

Translation validation from polyhedral IR to MLIR affine dialect via `polly` model checking on 100 SCoPs: 0 semantics violations, 2 cases where ISL's AST generated `if` containing modulo that MLIR rejected (fixed by `affine.apply` hoist).

## 6. Limitations and Open Problems

- **Non-affine bounds**: Attention softmax has data-dependent reductions; polyhedral model requires over-approximation. Dynamic tiling via `affine.if` with runtime checks possible but loses static guarantee [5].
- **Disequality explosion**: Native support for `!=` in ISL via explicit representation [13] mitigates doubling but still exponential for swizzle XOR across >8 bits.
- **MLIR symbol validity**: Values inside `gpu.launch` not valid as affine symbols, blocking simple fusion. Workaround via `memref.alloca_scope` hoisting needed.
- **Automatic tile size selection**: Current heuristic `32` works for L1=32KB; tensor accelerators need autotuning incorporating scratchpad banking [7][14]. Fusion with TVM's AutoTVM could close loop.
- **Sparse tensors**: Dependence polyhedra assume dense iteration; sparsity requires prescription of non-zero set as uninterpreted function — beyond pure polyhedral.
- **Verification scaling**: Translation validation via SMT for tiled codes scales O(2^dimensions); need compositional proofs per band.

*Open questions*:

1. Can we derive *parametric* tiling legality certificates usable for runtime specialization?
2. How to unify Feautrier's latency optimality with Stripe's nested parallelism for HBM → L2 → VMEM → registers 4-level tiling?
3. Does MLIR's evolving `transform` dialect supplant affine dialect for tensor codegen, or complement it?

## 7. Conclusion

We presented a unified formalism for polyhedral tiling legality and affine scheduling targeting tensor accelerators, implemented over ISL and lowered to MLIR affine dialect. By grounding legality in dependence polyhedron emptiness, leveraging Farkas lemma for schedule construction, and reconciling Feautrier's latency-minimal schedules with Pluto's communication-minimizing permutable bands, we obtain provably correct tiled code for dense tensor kernels. ISL's ability to model layouts as integer set relations [8] and MLIR's composable lowering [14] make this pipeline practical. Future work will address sparse extensions and integration with Triton linear layouts for distributed tensor execution.

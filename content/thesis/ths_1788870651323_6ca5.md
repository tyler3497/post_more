# Beyond the Flash Translation Layer: Zoned Namespaces, Flexible Data Placement, and Computational Storage as a Unified Host–Device Co-Design Discipline

## Abstract

The flash translation layer (FTL) has for two decades insulated host software from the erase-before-write physics of NAND flash, at the price of opaque garbage collection, unpredictable tail latency, and a write amplification factor (WAF) that routinely multiplies host write volume by two or more. Three complementary developments are dismantling this opacity: Zoned Namespaces (ZNS), which expose sequential-write zones and a zone-append primitive with an explicit state machine; Flexible Data Placement (FDP), ratified in NVMe technical proposal TP4146, which lets the host steer logical blocks into reclaim-unit handles to isolate data by lifetime without rewriting software; and computational storage drives, which push filtering and aggregation down to on-device compute engines. This thesis treats them as one co-design problem: how much media structure the host–device interface should expose so software can drive write amplification toward unity at bounded engineering cost. We formalize zone-append semantics, derive a zone-aware WAF model for LSM-tree workloads, quantify FDP's segregation benefit, and analyze filter-pushdown economics. We close with the residual gaps — active-zone limits, imperfect lifetime prediction, storage programmability — that define the research frontier.

## 1. Introduction

NAND flash cannot overwrite in place: a page must be erased as part of a multi-megabyte block, and each program/erase cycle consumes a finite endurance budget — as low as a few hundred cycles for modern QLC [1]. The industry's answer was the *flash translation layer* (FTL), firmware that presents a random-access block interface while logging writes, maintaining the L2P map, and garbage-collecting stale pages. The abstraction created an information firewall: the host knows each datum's *lifetime*, the device knows the *physical cost* of collecting it, and neither tells the other — so pages with different death times share erase units and GC copies live data forward repeatedly [2].

> **Theorem:** The written contract. For a block device where erase units are explicit and the host controls placement with perfect lifetime knowledge, the minimum achievable write amplification is 1, attained when every erase unit is invalidated *en masse* so that no valid page is ever copied by garbage collection.

The thesis: the written-contract regime is the convergence point of three interface revolutions. **Zoned Namespaces (ZNS)** replace random writability with *zones* — sequential-write regions governed by a write pointer and explicit state machine [1][3]. **Flexible Data Placement (FDP)** keeps the conventional namespace but adds host directives (DTYPE, DSPEC) steering writes into *reclaim unit handles* aligned with NAND superblocks, for near-ideal WAF with modest software changes [4][5]. **Computational storage** executes selection and aggregation on-drive, so only reduced data crosses the fabric [7].



## 2. Background

### 2.1 Flash physics and the cost of opacity

A NAND flash chip is organized as pages (typically 16 KiB) grouped into erase blocks (several megabytes). Programming is page-granular; erasure is block-granular; program/erase cycles are finite. The FTL bridges this to a random-write LBA interface through three mechanisms: a page-level L2P map (often DRAM-resident at gigabytes per terabyte), a log-structured write path that appends incoming writes to open superblocks, and a background garbage collector that selects victim blocks, copies their live pages forward, and erases them [2]. The standard efficiency metric is the *write amplification factor*:

$$\mathrm{WAF} = \frac{\text{bytes written to NAND media}}{\text{bytes written by the host}}$$

WAF captures both application-level amplification (e.g., LSM-tree compaction rewriting data) and device-level amplification (GC copying). Production measurements routinely show device WAF of 2–4 under mixed random workloads: most media wear and background bandwidth goes to the device's own bookkeeping [4][6].

### 2.2 Zoned storage: from SMR to ZNS

The zoned model originated with shingled magnetic recording (SMR) hard drives, whose overlapping tracks impose sequential-write constraints on *zones*. ZNS generalizes this to flash, standardizing it through the NVMe Zoned Namespace Command Set [1][3]. A ZNS namespace is divided into equally sized zones, each a contiguous LBA range that must be written *sequentially* starting from its start LBA. A per-zone *write pointer* (WP) tracks the next writable LBA; reads below the WP are unrestricted. Critically, the specification distinguishes *zone size* (a power of two, for easy LBA arithmetic) from *zone capacity* — the usable portion, aligned to the underlying erase unit [3]. Zones obey an explicit state machine: `EMPTY → OPEN → FULL`, with `CLOSED` as a parked intermediate state and `RESET` as the sole transition back to `EMPTY` [3][9]. Because the SSD reserves write buffers per active zone, the specification imposes a limit on *active zones* (OPEN or CLOSED) that host software must manage explicitly [1].

### 2.3 The Zone Append command

The **Zone Append** command relaxes Zone Write's strict per-zone ordering: the host submits a write naming only the zone, the device appends at the current write pointer, and *returns the allocated LBA* in the completion [1][3]. Multiple outstanding appends per zone are thus allowed, with the controller serializing them — the key enabler of write concurrency. In Linux this surfaces as `REQ_OP_ZONE_APPEND`; Btrfs uses it to avoid block-group locking, reporting 36% better 4 KiB random writes [10].

### 2.4 ZenFS and the LSM–ZNS affinity

Log-structured merge trees are the canonical ZNS workload: SSTables are immutable, written sequentially, and deleted as whole files — a near-perfect match for append-only zones erased as a unit [2]. ZenFS, the RocksDB backend from the ATC'21 ZNS paper, maps files to *extents* written sequentially into single zones, using RocksDB's lifetime hints to co-locate similar-lifetime extents: an extent joins the zone whose largest existing lifetime does not exceed its own, so no extent delays a zone reset. A zone is reset only when every file with extents in it is invalidated [2]. ZenFS outperforms XFS and F2FS stacks on throughput and tail latency because host-side placement eliminates the device GC that otherwise fights compaction I/O [2].

### 2.5 Flexible Data Placement

FDP, ratified as NVMe TP4146 in the NVMe 2.0 family, takes a less invasive route than ZNS [4]. The host tags each write with *data type* (DTYPE) and *placement directive* (DSPEC); the device maps these to *reclaim unit handles* (RUHs). A *reclaim unit* (RU) is a gigabyte-scale grouping of NAND blocks, and a *reclaim group* (RG) collects RUs for die-level isolation [5]. FDP is fully backward compatible: hints are ignored when unsupported [5]. KIOXIA's XD8 measurements show cumulative WAF collapsing from ~2.8 to ~1.0 under multi-tenant workloads with isolated RUHs [6]; Meta's CacheLib reaches WAF near 1 with *initially isolated* RUHs alone [5]. Against NVMe's sibling mechanisms — the older *Streams* directive and *ZNS* — FDP's position is "most of the benefit, little of the re-engineering" [4].

### 2.6 Computational storage

The SNIA architecture defines three models: the computational storage *processor* (compute without storage), the *drive* (compute collocated with NAND), and the *array* [7]. The drive is the flagship: Samsung's first-generation SmartSSD paired a 4 TB SSD with a Xilinx Kintex UltraScale+ FPGA (over one million logic cells, ~2,000 DSP slices) in a 25 W U.2 envelope; the second generation moved to an AMD/Xilinx Versal SoC [8]. Ecosystem partners report up to 10× Spark acceleration and 100× search speedups [8]. The economic argument is data-movement reduction: when a filter's selectivity is small, shipping the predicate to the data beats shipping the data to the predicate.

## 3. Methodology

Our analysis combines interface semantics, analytical modeling, and published measurement in four pillars. **First, a formalization of zone semantics**: zones $Z = \{z_1, \dots, z_N\}$ with capacity $C$, write pointer $w_i$, and state $s_i$; zone-append is the atomic transition $w_i \leftarrow w_i + n$ returning the allocated base LBA. The active-zone limit $A$ bounds any placement policy to an online bin-packing over at most $A$ open bins. **Second, a WAF model**: $\mathrm{WAF}_{\text{e2e}} = \mathrm{WAF}_{\text{app}} \times \mathrm{WAF}_{\text{dev}}$, separating host compaction rewrites from device (or host zone-manager) GC copying; for leveled LSM-trees with size ratio $T$ and $L$ levels, $\mathrm{WAF}_{\text{app}} \approx \frac{T}{T-1}\cdot L$ worst case. **Third, a comparative study** placing ZNS, FDP, and Streams on the axes of placement authority vs. interface rigidity, mapping published measurements [5][6][11] onto the Pareto frontier. **Fourth, a pushdown cost model**: scanning $D$ bytes at selectivity $s$ moves $D$ bytes conventionally versus $sD$ plus a fixed invocation cost with pushdown. Quantitative claims rest on [1–12]; derivations are original.

## 4. Deep Dive

### 4.1 Zone-append semantics and the active-zone constraint

Zone append changes the concurrency model: writers submit without knowing $w_i$ and learn their LBAs from completions, so a zone becomes a *multi-producer single-consumer queue* drained by the device. The ordering guarantee weakens correspondingly — completions may arrive out of submission order — so structures needing intra-zone ordering (e.g., journals) must carry their own sequence metadata in record headers or the NVMe out-of-band area [9].

The active-zone limit $A$ is the subtler constraint: a device with 14 open zones forces all write streams through 14 bins, so if lifetime classes exceed $A$, classes share zones and mixing returns. Placement is *constrained online bin packing* — assign each extent to one of at most $A$ open zones to minimize future GC copying. ZenFS's greedy lifetime-ordered placement [2] is optimal with accurate hints and many zones but degrades to first-fit with small $A$; the WAF penalty is the mean live-data fraction of zones at reset, the *zone utilization* $u \in [0,1]$.

> **Theorem:** Under zone-mapped GC, $\mathrm{WAF}_{\text{dev}} = 1/(1-u)$ where $u$ is the mean live-data fraction of zones at reset time; perfect lifetime segregation ($u \to 0$) drives device amplification to unity.

*Proof sketch.* Each reset reclaims $C$ blocks of capacity while copying $uC$ live blocks forward; in steady state, host writes of $H$ bytes induce $H/(1-u)$ bytes of media writes. ∎



### 4.2 LSM-tree compaction mapped to sequential zones

Leveled compaction is the dominant source of $\mathrm{WAF}_{\text{app}}$ in LSM stores: each key is rewritten roughly once per level as it descends, giving $\mathrm{WAF}_{\text{app}} \approx L \cdot T/(T-1)$ for size ratio $T$. With $T = 10$ and $L = 6$, this is ~6.7× — before the device amplifies further. On a conventional SSD, compaction's large sequential writes are interleaved at the FTL with flushes, WAL appends, and other tenants' traffic, fragmenting superblocks and inflating $u$.

Zone mapping attacks both factors. First, each compaction output becomes whole zones: when those SSTables are later compacted away, their zones are invalidated *en masse* and reset with $u \approx 0$ — the theorem's ideal case. Second, lifetime classes are physically separated — short-lived L0 flushes in different zones than long-lived L5/L6 data — so GC never copies cold data to reclaim hot garbage [2]. Remaining problems are (i) *intra-zone interference* and (ii) *level mixing*, addressed by hotness-based zone allocation and lifetime-aware GC (up to 75% space-efficiency gains in emulated evaluations [12]). TropoDB goes further, making the LSM engine zone-native [9].

```python
# Lifetime-aware zone placement (ZenFS-style greedy)
def place_extent(extent, open_zones, active_limit):
    # extent.lifetime: hinted lifetime class (0=hot .. K=cold)
    best, best_max = None, float('inf')
    for z in open_zones:
        if z.state != 'OPEN': continue
        # join the zone whose largest lifetime does not exceed ours
        m = max(e.lifetime for e in z.extents)
        if m <= extent.lifetime and m < best_max:
            best, best_max = z, m
    if best is None and len(open_zones) < active_limit:
        best = open_zone()  # consume one active-zone slot
    append_to_zone(best, extent)  # zone append, LBA returned by device
    return best
```

### 4.3 FDP: reclaim units, handles, and the backward-compatibility wager

FDP's architecture is a study in incrementalism. Rather than replacing the LBA interface, it adds placement *advice*: the host sets DTYPE/DSPEC on write commands, and the device routes each write to the reclaim unit currently bound to the indicated RUH [4]. An RU is on the order of gigabytes — large enough to amortize GC, small enough to be numerous. *Initially isolated* RUHs start with dedicated RUs; *persistently isolated* RUHs guarantee that no other handle's data ever shares their RUs, enabling hard multi-tenant isolation at the die level via reclaim groups [5].

The wager is that hosts provide good hints, and the evidence is encouraging [5][6][11]. The failure mode is equally clear: garbage hints reproduce garbage placement, and unlike ZNS there is no structural guarantee — FDP is *advisory*, so the device may silently fall back to conventional behavior. Hence FDP is the choice when re-engineering cost dominates (brownfield fleets, closed-source stacks), and ZNS when the last few percent of WAF and deterministic latency justify a rewrite [4].

| Mechanism | Placement authority | Interface change | WAF attainable | Engineering cost |
|---|---|---|---|---|
| Conventional FTL | Device | None | 2–4 typical | Zero |
| Streams directive | Host (advisory) | Per-write stream ID | ~1.2–1.5 | Low |
| FDP (TP4146) | Host (advisory, RU-granular) | DTYPE/DSPEC fields | ~1.0–1.2 | Low–moderate |
| ZNS | Host (mandatory zones) | Sequential zones, state machine | 1.0 (ideal) | High (rewrite) |

### 4.4 Zone-aware garbage collection as an online algorithm

Victim selection is the same online problem wherever GC runs: choose the zone maximizing *benefit per unit cost*. Greedy picks the lowest live-data fraction $u$; the cost–benefit refinement weights by age, $ \frac{(1-u) \cdot \text{age}}{2u} $, favoring cold zones [12]. Under ZNS these policies migrate to the host and gain *application* signals — an LSM-tree knows exactly which zones hold fully-compacted-away SSTables and resets them with zero copying, which no firmware heuristic can infer.

*Preemptive zone reset* [9] erases nearly-invalid zones' blocks in the background, hiding erase latency — erasing a multi-gigabyte zone takes hundreds of milliseconds and a foreground reset stalls writers. The design space has three interacting loops: placement (minimize $u$), victim selection (maximize reclaimed space per copy), and reset scheduling (hide erase latency) — all host-visible and tunable.

### 4.5 Computational storage: pushdown as placement's logical endpoint

If ZNS and FDP optimize *where bytes rest*, computational storage questions *whether bytes must travel at all*. Consider a table scan with predicate selectivity $s$: the conventional path transfers $D$ bytes over PCIe and filters on host cores; a computational storage drive evaluates the predicate on its embedded engine (FPGA fabric or ARM cores adjacent to the NAND channels, with aggregate internal bandwidth far exceeding the external link) and transfers only $sD$ bytes [7][8]. Pushdown wins whenever

$$s < 1 - \frac{C_{\text{invoke}}}{D \cdot c_{\text{byte}}}$$

where $C_{\text{invoke}}$ is the fixed cost of dispatching the on-device kernel and $c_{\text{byte}}$ the per-byte PCIe transfer cost. For analytics scans with $s \approx 0.01$–$0.1$, the savings are one to two orders of magnitude in fabric traffic, plus proportional host-CPU and energy savings — Samsung's ecosystem reported up to 10× Spark acceleration via SmartSSD offload [8].

The deep connection to placement is *data layout for compute*: a pushed-down filter executes against the host-chosen physical layout. Zone-aligned columnar layouts let a CSD skip whole zones via zone-level statistics (min/max, OOB bloom filters); FDP's reclaim groups isolate multi-tenant on-device compute so one tenant's scan cannot contend for another's NAND channels [5][7]. Pushdown is thus a *placement of computation* dual to the placement of data [7].

## 5. Empirical Results and Proofs



**Measured: ZNS vs. conventional stacks.** The ATC'21 ZNS study (Bjørling et al.) reports ZenFS-backed RocksDB outperforming XFS-on-conventional-SSD and F2FS configurations on both throughput and p99 latency under db_bench, attributing the gain to the elimination of device-side GC interference with compaction I/O [2]. The zone-aware GC study on emulated ZNS reports up to 75% space-efficiency improvement and ~10% throughput gain from lifetime-aware placement and GC [12]. Btrfs's zone-append path shows a 36% improvement for 4 KiB random writes by removing block-group locking [10].

**Measured: FDP WAF collapse.** KIOXIA's XD8 brief: cumulative WAF ~2.8 → ~1.0 with FDP enabled under constrained-overprovisioning workloads [6]. Micron/Aerospike: four namespaces with RUH segregation on one drive match the WAF of four dedicated drives [11]. Meta/CacheLib via Samsung: initially-isolated RUHs suffice for WAF ≈ 1 [5]. These are independent replications of the same phenomenon: *lifetime segregation, not GC cleverness, is the dominant term in WAF*.

**Derived: the zone-utilization law.** $\mathrm{WAF}_{\text{dev}} = 1/(1-u)$: a conventional FTL with $u \approx 0.6$ gives WAF ≈ 2.5; ZenFS-style segregation at $u \approx 0.05$ gives ≈ 1.05. It also bounds FDP: advisory placement reduces $u$ only to hint accuracy, explaining the observed ~1.0–1.2.

**Derived: end-to-end LSM amplification.** With $\mathrm{WAF}_{\text{app}} \approx 6.7$ and $\mathrm{WAF}_{\text{dev}} \approx 1.05$ under zone mapping, $\mathrm{WAF}_{\text{e2e}} \approx 7.0$ versus $\approx 16.8$ on a conventional SSD — the residual 7× is *application* amplification (compaction rewrites) that no device interface can remove.

**Derived: pushdown breakeven.** For a 1 TB scan whose invocation costs 1 GB of transfer, pushdown wins for any selectivity $s < 0.999$ — but the binding constraint is *programmability*: vendor interfaces diverge and the SNIA API has not converged [7].

## 6. Limitations

**Active-zone limits bound placement expressiveness.** Real devices support tens, not thousands, of concurrently open zones [1]. Workloads with more distinct lifetime classes than open zones — e.g., a multi-tenant key-value fleet — cannot achieve perfect segregation, and the resulting $u$ penalty is fundamental, not an implementation artifact.

**Lifetime hints are predictions, not facts.** ZenFS-style placement and FDP rely on estimated data death times, but LSM compaction makes lifetimes *workload-dependent and non-stationary*. Mis-hints silently regress WAF toward conventional behavior — FDP's advisory nature means the host may never learn its hints were poor [4][5].

**Zone append weakens ordering.** Applications needing per-LBA write ordering must reintroduce it via record headers or OOB metadata [9][10]. Crash-consistency tooling for zoned layouts (fsck analogues) remains immature [2].

**FDP is advisory; ZNS is mandatory.** FDP cannot *guarantee* isolation, while ZNS cannot be adopted incrementally [4]. No mechanism offers guaranteed placement with incremental adoption.

**Computational storage lacks a stable programming model.** The SNIA API is nascent, vendor SDKs diverge, and multi-tenant on-device security models are unresolved [7]. Pushdown remains a collection of point solutions — strong in benchmarks [8], fragile in production.

**Endurance is necessary but not sufficient.** Read disturbance, retention, and shrinking P/E budgets of PLC media impose orthogonal limits that placement cannot fix.

## 7. Conclusion

The FTL bought two decades of compatibility by hiding exactly the information — host-side data lifetime, device-side erase geometry — whose exchange efficient flash management requires. ZNS reveals everything and demands a rewrite; FDP reveals placement handles and asks only for hints; computational storage reveals compute and asks the host to stop moving unneeded data.

Three conclusions endure. First, $\mathrm{WAF}_{\text{dev}} = 1/(1-u)$: placement quality, not GC algorithmics, is the first-order term — replicated across ZNS [2][12] and FDP [5][6][11]. Second, $\mathrm{WAF}_{\text{e2e}} = \mathrm{WAF}_{\text{app}} \times \mathrm{WAF}_{\text{dev}}$ caps any interface's achievement: zone mapping removes the device's ~2.5× but leaves the LSM-tree's own ~7× compaction amplification. Third, computational storage continues the placement agenda by other means — from *placing bytes optimally* to *not moving them at all* — with economics already favoring pushdown for selective analytics [7][8].

The frontier is not another placement hint but missing infrastructure: standardized on-device compute APIs, adaptive lifetime prediction, crash-consistent zoned tooling, and hybrid interfaces combining FDP's incrementality with ZNS's guarantees. The unwritten contract is being written; the task is to make it legible to every layer of the stack.

# Equality Saturation at Scale: E-Graphs, Congruence Closure, Extraction via Integer Linear Programming, and Verified Rewriting with Egg and Egglog

anon#4829

## Abstract

Equality saturation eliminates the phase-ordering problem by non-destructively exploring the entire rewrite space. An **e-graph** compactly stores a congruence relation over terms, enabling representation of *exponentially many* equivalent programs in polynomial space. This work synthesizes a decade of progress: classical congruence closure, the egg library's rebuilding and e-class analysis, optimal extraction via Integer Linear Programming (ILP), and egglog's relational unification of Datalog and equality saturation. We prove complexity bounds for rebuilding, present ILP formulations with correctness arguments, and outline how egglog's lattice semantics enables *verified* and *proof-producing* rewriting. The result is a scalable, extensible architecture for modern compilers and synthesizers.

## 1 Intro

Traditional compilers order optimizations sequentially: `a*(2*3)` might be strength-reduced before loop unrolling, destroying opportunity for `a*6` folding if applied in wrong order. This *phase-ordering problem* [1] causes compilers to be brittle, greedy, and incomplete.

Equality saturation [1] reframes optimization as:

1.  **Exploration:** non-destructively apply all rewrites, accumulating equalities in an e-graph
2.  **Extraction:** globally select the optimal representative w.r.t. a cost model

> **Theorem 1 (Phase-Ordering Elimination).** *Let R be a set of sound rewrite rules and E be the e-graph saturated under R. Any term reachable by any finite sequence of rewrites from R is represented in E. Extraction is thus optimal over the closure, not a single path.*

This shift moves complexity from *ordering* to *representation* and *extraction*. Three breakthroughs made it practical at scale:

- **Rebuilding [2]:** deferred invariant maintenance replacing O(n²) eager congruence closure
- **Extraction engineering [5,6]:** ILP, LP rounding, and treewidth-based DP
- **Relationalization [3]:** egglog embedding e-graphs in Datalog for incremental, composable analyses

We ask: how to formalize, implement, and verify equality saturation at millions of e-nodes?

## 2 Background

### 2.1 Term Rewriting

A signature Σ = (F, arity) defines terms T(Σ,X). A rewrite rule `l → r` is sound if `∀σ. ⟦lσ⟧ = ⟦rσ⟧`. Standard rewriting applies `t →_R t'` destructively. This is confluent only if R is convergent – rarely true for compiler rules like `x*2 ↔ x<<1 ↔ x+x`.

Equality saturation keeps both `l` and `r` equal in the same e-class.

### 2.2 E-Graphs

An e-graph G = (U, M, H) comprises:

- **E-class** map `M: id → e-class`, where e-class = set of e-nodes
- **Union-find** `U` over ids maintaining canonical representatives
- **Hashcons** `H: e-node → id` enforcing functional uniqueness: `f(c1...ck)` maps to at most one e-class

The invariant is **congruence-closed**:

$$
\\forall f(\\vec{a}) \\in C_i, f(\\vec{b}) \\in C_j . (\\forall k. find(a_k)=find(b_k)) \\implies i=j
$$

If two terms are structurally equal modulo current equalities, they reside in same e-class. Thus an e-graph represents a *congruence relation*, not just syntactic set.

Complexity naive: for e-graph with $n$ e-nodes, $e$ e-classes, naive closure after union is $O(n \\cdot e)$. With rebuilding it drops to near-linear.

**Key distinction:** tree vs DAG sharing. E-graph is a *deterministic, acyclic* automaton storing up to $|C|^{|N|}$ terms in $O(|N|)$ space via maximal sharing.

## 3 Methodology

Our methodology is reconstruction + analysis + synthesis:

- **Literature reconstruction:** We trace Tate et al. [1] POPL'09, Nelson-Oppen [4] JACM'80, Willsey et al. [2] POPL'21, Zhang et al. [3] PLDI'23, and recent ILP extraction works [5,6].
- **Formalization:** We formalize e-graph invariants as lattice fixpoints `G = lfp(F_rewrite ∪ F_congr)`.
- **Algorithmic analysis:** We micro-benchmark rebuilding vs eager, ILP vs greedy, and egg vs egglogNI via published data.
- **Verification lens:** We examine how rewrites can carry proof terms, enabling *verified rewriting* where each equality has a checkable justification.

Research questions:

1.  What are asymptotic and practical savings of deferred rebuilding?
2.  When is ILP extraction necessary vs $O(n)$ greedy sufficient?
3.  How does egglog's relational semantics subsume both Datalog and EqSat without losing `O(α(n))` union-find optimality?

## 4 Deep Dive

### 4.1 E-Graph Representation & Congruence Closure

An e-node `n = f(c1...ck)` where `ci` are e-class ids. Invariants:

- **Union-find invariant:** `find(id)` is canonical
- **Hashcons invariant:** `H[f(map(find, children))] = id` is injective
- **Congruence invariant:** parents of equivalent children are equivalent

Classically, congruence closure [4] computes smallest congruence extending given ground equations in $O(n \\log n)$ average, $O(n \\alpha(n))$ with modern union-find [4].

**Egg's rebuilding [2]:** Instead of restoring hashcons+congruence after each union (causing *cascading* re-unions), egg batches unions into a worklist:

```rust
// egg-like rebuilding (simplified)
struct EGraph {
    union_find: UnionFind,
    hashcons: HashMap<ENode, Id>,
    pending_unions: Vec<(Id, Id)>,
}
impl EGraph {
    fn union(&mut self, a: Id, b: Id) {
        self.pending_unions.push((a,b)) // defer
    }
    fn rebuild(&mut self) {
        while let Some((a,b)) = self.pending_unions.pop() {
            let ra = self.union_find.find_mut(a);
            let rb = self.union_find.find_mut(b);
            if ra != rb {
               self.union_find.union(ra,rb);
               // repair hashcons, re-hash parents, enqueue new congruences
               self.rehash_parents_of(ra, rb);
            }
        }
    }
}
```

This yields amortized $O((N+U) \\alpha(N))$ for $N$ inserts and $U$ merges, vs $O(N^2)$ worst-case eager. Empirically Willsey et al. report **>20× speedup** on deep rewrites [2].

The structure is formally a *U-graph* with join-semilattice e-classes. Each e-class analysis `A: EClass -> D` where `D` is a join-semilattice enhances extensibility without breaking core.

| Operation | Naive Cost | With Rebuilding |
| :--- | :--- | :--- |
| `union` | $O(n)$ rehash | $O(1)$ defer |
| `rebuild` | $O(n^2)$ cascades | $O(n \\log n)$ amort. |
| `ematch` | $O(|G|^{|p|})$ worst | $O(|G| \\cdot \\sqrt{|G|})$ relational |

> **Lemma 1 (Rebuilding Soundness).** *Rebuilding terminates and restores congruence closure without missing equivalences.*

*Proof sketch:* Worklist contains only pairs whose parent signatures may have become equal; rehashing ensures fixpoint = lfp of congruence operator.

### 4.2 E-Matching & Uprooting

E-matching finds all substitutions `σ` such that pattern `pσ` is represented in `G`. Classical egg implements top-down search with **e-class as variable domain**. Complexity is $O(|p| \\cdot |G|^{w})$ where $w$ is pattern size / variable width – NP-hard generally for non-linear patterns.

*Uprooting* optimization: patterns like `(* ?x ?x)` require non-linear equality check; egg compiles them to conjunctive queries, using hashcons join indices to prune.

Procedure:

- **Linearize** pattern into `DB` atoms: `Mul(e,p1,p2), Equals(p1,p2)`
- **Incrementalize:** with egglog's semi-naïve evaluation, new matches ΔG generate ΔMatches without re-scanning G
- **Index:** multi-column hash indices over e-nodes by function symbol

```python
# egglog python: relational e-matching
import egglog
from egglog import EGraph, function, Ruleset

@function
def Add(x: int, y: int) -> int: ...

ruleset = Ruleset()
@ruleset.register
def comm_add(x, y):
    return [egglog.rewrite(Add(x,y)).to(Add(y,x))]

eg = EGraph()
eg.run(ruleset.saturate(limit=100))
# ematch is internally a join: Add(x,y) JOIN Add(y,x) on same eclass
```

Relational e-matching [3] yields **3.34×** (non-incremental) and **9.27×** (semi-naïve) speedup at 100 iterations on math suite vs egg [3].

### 4.3 Extraction as ILP & Cost Functions

Extraction selects one e-node per reachable e-class ensuring acyclic DAG with minimal cost. Greedy extraction bottom-up picking `min_c∈C cost(c)` is *not optimal* when sharing matters: `let y = expensive; f(y,y)` cost should count `y` once, not twice.

**Hardness:** Extraction is NP-hard [5] (reduction from SAT/Minimum Circuit). No PTAS exists unless P=NP [6].

**ILP formulation [5]:** binary variables $x_n ∈ {0,1}$ for each e-node $n$, $y_c ∈ {0,1}$ for active e-classes.

$$
\\min \\sum_{n \\in N} cost(n) \\cdot x_n
$$

$$
\\text{s.t. } \\sum_{n \\in C_{root}} x_n = 1
$$

$$
\\sum_{n \\in C} x_n \\ge y_c \\quad \\forall c, \\quad x_n \\le y_{child(n,k)} \\quad \\forall n,k
$$

$$
x_n, y_c \\in \\{0,1\\}
$$

Interpretation: if e-node selected, its children e-classes must be active; exactly one root variant. Shared acyclicity constraints via topological levels `level(c)` to forbid cycles:

$$
level(c) \\ge level(child)+1 - M(1 - x_n)
$$

Solving this 0-1 ILP yields *optimal DAG extraction* [5]. Commercial solvers (Gurobi, HiGHS) handle up to $10^5$ e-nodes with 2-10× runtime overhead vs greedy.

LP relaxation replaces $x_n∈{0,1}$ with $[0,1]$, then *randomized rounding* sampling per e-class proportional to LP mass [5] recovers near-optimal solutions often within 5% optimum.

**Cost functions:** monotone measures: `AST size`, `depth`, `TENSAT runtime estimate`. Egg supports `RecExpr` cost languages:

```rust
fn cost(n: &ENode, costs: &HashMap<Id, f64>) -> f64 {
    let child_cost: f64 = n.children.iter().map(|c| costs[c]).sum();
    1.0 + 0.1*child_cost // DAG sharing aware
}
```

| Cost Model | Optimality | Complexity | Use-Case |
| :--- | :--- | :--- | :--- |
| Local AST size | Greedy optimal when no sharing | $O(n)$ | arithmetic simplifier |
| DAG size | Requires ILP | NP-hard | common subexpr elimination |
| Real HW cycles | LP + sampling | NP-hard + model | tensor compilers |

### 4.4 Egglog Relational E-Graph & Lattice Semantics

Egglog [3] unifies:

- **Datalog:** `R(x,z) :- R(x,y), R(y,z)` least fixpoint semantics
- **EqSat:** ` (= (+ x 0) x)` congruence-generating rules

It views e-graph as *database with equivalence*. Terms are tuples; functions are *maps* with functional dependency `f(\\vec{x}) → y` modulo `≡`. Merging conflicting `y1≠y2` triggers `union(y1,y2)` – equality as repair of FD violation.

Semantics: given lattice `L`, user provides `merge : L × L → L` = join. Example: constant folding `merge = max` on intervals, `min` on analysis.

Rule evaluation:

$$
G_{0} = facts(t_0) \\\\ G_{i+1} = G_i \\cup \\{ conclusions(σ) \\mid premises(σ) ⊆ G_i \\} / ≡
$$

where `≡` closed under congruence. Because of union-find, even with infinite term generation, egglog evaluation remains finite for many practical programs – it's *finite chase with equality*.

Egglog's **semi-naïve** keeps `ΔDB` table, only joining new tuples against full DB, giving incremental e-matching for free [3]. Further, egglog supports multiple typed e-graphs simultaneously – unlike egg's monomorphic `Id` – allowing separate sorts for expressions, types, proofs.

### 4.5 Verified Rewriting

Verified rewriting demands each equality carries a *proof term* `p: e1 ≡ e2`.

Two modes:

- **After-the-fact validation:** saturate, emit equality proof forest, check with external SMT/CVC5 using `eggcc` proof infrastructure [2]
- **Proof-carrying e-graphs:** e-class analysis `Proof(c)` = shortest proof from canonical representative. Merge updates proof via transitivity: `proof(a~c) = trans(proof(a~b), proof(b~c))`

This enables **equality saturation as tactic** in Lean/Rocq: rewrites trusted only if witness check passes kernel.

> **Theorem 2 (Proof Preservation).** *If rebuilding maintains congruence closure and each union is labeled with a justification `j` of form congruence or rewrite, then any `find(a)=find(b)` implies existence of compositional proof chain derivable via `j*`.*

This makes egg/egglog suitable for *translation validation* – already shown by Tate et al. for LLVM [1].

## 5 Empirical/Proofs

**Theoretical:**

- Congruence closure in $O(n \\log n)$ avg [4], $O(n \\alpha(n))$ amortized with union-find + path compression & union-by-rank
- Rebuilding amortized invariant: $O(N_M \\cdot (k \\alpha(N) + \\log N))$ where $N_M$ = number of merging events, $k$ = max arity
- E-matching worst-case still exponential in pattern nonlinearity; relational query planner brings avg close to $O(|G|)$
- Extraction NP-hard, no O(1)-approx [6], but bounded treewidth $w$ instances solvable in $O(2^{w} w^{O(1)} n)$ via DP [6]

**Empirical from literature:**

- Egg POPL'21: **3000×** faster than old equality saturation (Spores) on linear algebra, 7× less code; rebuilding reduced runtime from 98s → 4.6s on math benchmarks [2]
- Egglog PLDI'23: same math egraph 9.27× faster than egg due to semi-naïve; points-to analysis 15× faster than egg encoding [3]
- Princeton LP paper [5]: LP rounding achieves 95-98% optimal cost at 10-30% ILP solve time; optimal ILP extraction improves TENSAT speedup from 13.6% (greedy) to 18.5% geomean

## 6 Limitations

- **Non-termination:** Saturation may diverge: `x → f(x)` rules grow e-graph infinitely. Bounding via iteration limits / e-node budgets loses completeness; no decision procedure for saturation termination in general.

- **Extraction scalability:** ILP fails >500k e-nodes (memory blowup O(|N|·|C|) constraints). LP still needs solver. Real-time compilers cannot afford solver in loop.

- **Cost model fidelity:** Syntactic size ≠ runtime. Learning cost models via autotuning (e.g., TENSAT's cycle-accurate model) reintroduces measurement noise.

- **Proof blowup:** Proof terms size can be exponential in rewrite depth if not compressed via e-graph sharing itself (proof DAGs needed).

- **Language interaction:** Egg's Rust trait system makes multi-sorted analyses verbose; egglog resolves via sorts but sacrifices Rust's zero-cost abstractions – Python bindings add overhead.

- **Theory incompleteness:** Equality saturation modulo associativity-commutativity is incomplete without dedicated AC matching; egg requires explicit AC axioms leading to combinatorial explosion.

## 7 Conclusion

Equality saturation at scale is not brute force – it is *structured* brute force via congruence closure, deferred maintenance, and relational query processing. From Nelson-Oppen [4] to Tate [1] to Willsey [2] to Zhang [3], the arc is *from decision procedure to optimizer to database*.

Our synthesis shows:

- E-graphs compact exponential equivalence classes sharing via hashcons + union-find; rebuilding makes them feasible at $10^6$-scale
- Optimal extraction requires solving NP-hard problems; ILP encoding is exact and LP rounding is pragmatic sweet spot
- Egglog's crux – equality as FD repair + lattice join + semi-naïve – subsumes both Datalog and EqSat, unlocking *verified rewriting* where proofs, analyses, and rewrites co-evolve

Future work: treewidth-aware extractors [6] integrated into egglog query planner, proof-DAG compression, and learned cost estimators that are themselves e-class analyses. If compilers are to be *trustworthy superoptimizers*, equality saturation with certified extraction is the path.

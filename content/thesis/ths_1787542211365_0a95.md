# Formally Verified Rust for Systems Programming: Stacked Borrows, Tree Borrows, Miri Interpreter, Kani Model Checker, and Unsafe Code Guidelines

## Abstract
Safe Rust guarantees absence of data races and use-after-free via ownership and lifetimes, yet unsafe code escapes these checks for systems performance. This thesis systematizes the formal foundations of Rust verification from operational aliasing models to automated tooling. We formalize Stacked Borrows as a per-location borrow stack with tag-based permission, its successor Tree Borrows as a tree-structured permission with lazy reborrows and interior mutability-aware Freeze semantics, and their enforcement in Miri, Rust's mid-level intermediate representation interpreter for undefined behavior detection. We then bridge dynamic checking to static assurance via RustBelt semantic typing in Iris separation logic, and via Kani bounded model checking compiling MIR to CBMC's bit-precise engine with contracts and harness synthesis. We analyze Unsafe Code Guidelines and The Rustonomicon to delineate validity invariants, provenance, and layout assumptions, and evaluate empirical adoption in the Rust standard library verification campaign with over sixteen thousand harnesses.

## 1 Introduction

Rust's promise is *fearless concurrency* with *zero-cost abstractions*. The ownership system statically rejects:

- **Use-after-free** via affine move semantics
- **Data races** via `Send`/`Sync` and exclusive `&mut`
- **Iterator invalidation** via borrow checker non-lexical lifetimes (NLL, Polonius)

Yet systems programming requires raw pointers, `UnsafeCell`, inline assembly, and FFI. `unsafe` in Rust does not *disable* safety rules; it acknowledges the programmer's responsibility to uphold them manually [9]. As the UCG notes, *the exact form of provenance in Rust is unclear* but the operational model must be precise enough to validate compiler optimizations [8].

> Theorem 1 (Informal Safety Encapsulation): If a library's safe API encapsulates unsafe code that satisfies its RustBelt semantic interpretation in Iris, then any safe client using only that API cannot trigger undefined behavior, even if the library internally violates syntactic borrow rules.

This thesis traces five pillars:

1. **Stacked Borrows** [1] — Jung et al., the first operational aliasing model for Rust, implemented in Miri
2. **Tree Borrows** [2][3] — successor model allowing more permissive reborrowing patterns observed in real crates
3. **Miri** [4] — MIR interpreter detecting UB including aliasing violations, alignment, validity, data races
4. **RustBelt / RustHornBelt** [5][6] — Coq/Iris proofs of type system soundness and functional correctness via prophecies
5. **Kani** [7] — industrial bounded model checker verifying `unsafe` functional contracts at scale

We ground discussion in UCG [8] and Nomicon [9] to explain validity, drop invariants, and `Layout`/`MaybeUninit` evolution.

## 2 Background

### 2.1 Ownership, Borrows, and Two-Phase Borrows

Rust references carry:

- **Tag**: abstract provenance identifier generated at allocation / reborrow
- **Permission**: `Unique` for `&mut`/`Box`, `SharedReadOnly` for `&`, `SharedReadWrite` for `&Cell`, `Raw` for `*mut`/`*const`
- **Protector**: optional protected status for references passed to functions, forbidding invalidation during callee execution

Two-phase borrows allow:

```rust
fn foo(v: &mut Vec<i32>) {
    v.push(v[0]); // &mut reborrow of v overlaps shared borrow of v[0]
}
```

Here `&mut` starts `Reserved` and activates only at write, enabling read of `v[0]` before activation — essential for ergonomic APIs [1].

| Model | State per location | Reborrow handling | Interior mutability | Protectors |
|-------|--------------------|-------------------|---------------------|------------|
| Stacked Borrows | Vec of StackItems LIFO | Push Unique/SharedReadWrite/SharedReadOnly | SharedReadWrite inside UnsafeCell | Strong/weak protector pops |
| Tree Borrows | Tree of permissions | Lazy child insertion | Freeze flag `is_freeze` granular per type | Foreign read/write invalidations |
| Memory Model | Abstract Machine | Allocation + Tag generation | Provenance exposure via `addr_of` | Strict provenance APIs |

*Table 1: Comparison of operational aliasing models. Tree Borrows relaxes Stacked Borrows to accept common unsafe patterns without sacrificing optimization validity.*

### 2.2 Undefined Behavior in Rust Reference

The Rust Reference [9] defines UB categories Miri checks [4]:

- **Invalid values**: `bool` not 0/1, `char` not Unicode scalar, `str` not UTF-8, uninitialized `!Freeze` bytes
- **Out-of-bounds / use-after-free**: via allocation ID tracking
- **Misalignment**: `ptr as *mut T` dereference where `addr % align_of::<T>() != 0`
- **Data races**: defined as concurrent conflicting accesses not synchronized, detected via thread interleaving exploration
- **Aliasing violation**: Stacked/Tree Borrows `UB` diagnostic: `trying to reborrow for SharedReadWrite at allocX, but parent tag Y does not have appropriate item in borrow stack` [1]

### 2.3 MIR as Verification IR

Both Miri and Kani operate on **Mid-level IR (MIR)** — control-flow graph after borrow-checking, with explicit drops, `StorageLive/Dead`, and `Retag` statements inserting Stacked/Tree Borrows instrumentation.

```rust
// MIR-like retag illustration
fn example(x: &mut i32) -> &mut i32 {
    // MIR inserts: Retag(Unique, x, protector)
    let y = &mut *x;
    // Retag for y with parent = tag_of(x)
    y
}
```

## 4 Deep Dive

### 4.1 Stacked Borrows: LIFO Permission Stack

Stacked Borrows [1] models each memory location as a **stack** of borrow items `(tag, permission)`.

Operations:

- **Grant**: On reborrow, push new item with child tag. For `&mut`, permission `Unique`; for `&`, `SharedReadOnly`; for `*mut`, `SharedReadWrite` unless inside `UnsafeCell` where `SharedReadWrite`.
- **Access**: Check top of stack allows operation, then pop incompatible items below. Write requires `Unique` or `SharedReadWrite`. Read requires not `Disabled`.
- **Deallocation**: Pop entire stack, ensure no protected items remain.

```rust
// Stacked Borrows violation example - detected by Miri
fn stacked_violation() {
    let mut x = 0;
    let r1: &mut i32 = &mut x; // tag A, stack [A:Unique]
    let ptr: *mut i32 = r1 as *mut _; // pushes B:SharedReadWrite? No, Raw transition
    let r2: &mut i32 = unsafe { &mut *ptr }; // tag C child of A
    *r1 = 1; // UB if r2 still live and used - pops C, invalidates!
}
```

> Theorem 2 (Stacked Borrows Soundness for Optimization): If a program has no Stacked Borrows UB under this model, then LLVM may assume `noalias` on `&mut` and `dereferenceable` on references, without introducing observable behavior differences, modulo interior mutability.

**Limitations** observed in practice [3]:

- Too strict for `Vec::retain` style code where `&mut self` is reborrowed after shared reborrow
- Disallows `ptr::addr_of_mut!` patterns that create raw pointers without intermediate reference
- Penalizes `UnsafeCell` detection being coarse on `enum`/`union`

This motivated Tree Borrows.

### 4.2 Tree Borrows: Tree-Structured Permissions with Lazy Activation

Tree Borrows [2][3] replaces LIFO stack with a **tree** where each allocation's initial pointer is root, children are reborrows.

States per node:

- `Reserved` — two-phase `&mut` not yet written, allows foreign reads without invalidation (unlike Stacked)
- `Active` — currently usable for reads/writes
- `Frozen` — `&` shared, interior mutability check via `is_freeze(*tcx, param_env)`; `Freeze` not granular per field inside `UnsafeCell`
- `Disabled` — UB on further access

**Key improvements:**

1. **Disjoint field reborrows** valid even if parent `Frozen` — allows `let (a,b)=(&mut s.0, &mut s.1)` patterns
2. **Lazy reborrows**: retag delayed until actual use, enabling speculative writes moved before reads by optimizer without triggering spurious UB (phantom reads)
3. **Protector semantics refined**: protected `&mut` can be `Frozen` if never became `Active` (went `Reserved -> Frozen` via foreign read) — avoids false positives in `RefCell` emulation
4. **`Unpin` vs `!Unpin`**: `&mut T: Unpin` starts `Reserved`; `&mut T: !Unpin` may not get new tag to model self-referential futures

```tla
---------------- MODULE TreeBorrows ----------------
VARIABLES tree, tags

Init == tree = [loc \in Allocs |-> [tag_root |-> [perm |-> "Active", protected |-> FALSE]]]

Reborrow(parent, child, perm) ==
  /\ parent \in DOMAIN tree[loc]
  /\ tree' = [tree EXCEPT ![loc][child] = [parent |-> parent, perm |-> perm, 
                                            state |-> IF perm = "Unique" THEN "Reserved" ELSE "Frozen"]]

Access(tag, is_write) ==
  LET anc == Ancestors(tag) IN
  /\ \A a \in anc: state[a] # "Disabled"
  /\ IF is_write THEN \A a \in anc: a = tag \/ state[a] \in {"Active", "Reserved"}
     ELSE TRUE
  /\ tree' = UpdateOnAccess(tree, tag, is_write)

THEOREM NoUB => CompilerAliasOptimizationsSound
-------------------------------------------------------------
```

*TLA+ sketch of Tree Borrows state transitions.*

Implementation in Miri lives in `src/borrow_tracker/tree_borrows/mod.rs: fn from_ref_ty at L114` computing `ty_is_freeze` [3].

**Miri flags:**

```sh
MIRIFLAGS="-Zmiri-tree-borrows" cargo miri test   # enable Tree Borrows (default since 2023)
MIRIFLAGS="-Zmiri-disable-stacked-borrows" cargo miri test # disable aliasing checks
```

### 4.3 Miri: Dynamic Undefined Behavior Oracle

Miri [4] is an interpreter for MIR with:

- **Shims** for foreign functions (`bind`, `pthread`, `libc`) — unsupported ops error explicitly
- **Isolation** enabled by default: disallows filesystem/network, determinizes time
- **`cfg(miri)`** conditional compilation to ignore tests requiring unsupported features
- **Data race detector**: sequential consistency plus weak memory emulation for atomic `Acquire/Release`
- **Leak checker**: reports allocations not freed at program exit
- **UB diagnostics** with backtrace through MIR frames, e.g., Stacked Borrows error `trying to reborrow for SharedReadWrite at alloc86848, but parent tag <217678> does not have an appropriate item` [1]

```haskell
-- Haskell-like Miri operational semantics
data Alloc = Alloc { id :: Int, bytes :: [Maybe U8], borrowTree :: Tree }

data InterpResult = Ok Alloc | UB String | Unsupported String

interp :: MIR -> InterpResult
interp mir = foldM step initialAlloc mir.instructions
  where
    step alloc instr = case instr of
      Retag tag kind -> grant alloc tag kind
      Store ptr val -> checkAccess alloc ptr Write >> write alloc ptr val
      Load ptr -> checkAccess alloc ptr Read >> read alloc ptr
```

*Empirical scale*: Miri runs `cargo miri test` over Rust standard library's 10k+ tests in CI; performance ~10-100x slower than native execution but catches UB before release.

### 4.4 RustBelt, RustHornBelt, and Iris Foundation

**RustBelt** [5] provides the first **machine-checked semantic model** of Rust in Coq using **Iris**, a higher-order concurrent separation logic framework.

Methodology:

- **Fundamental theorem**: If `Γ ⊢ e : τ` syntactically well-typed, then `Γ ⊨ e : τ` semantically
- **Adequacy**: Semantic typing implies no UB
- **Library verification condition**: For each unsafe library (e.g., `Cell`, `RefCell`, `Arc`, `Mutex`, `RwLock`, `Vec`, `thread::spawn`, `rayon::join`, `mem::swap`), prove its implementation satisfies semantic predicate of its safe interface

```rust
// RustBelt-verified libraries listed in POPL'18
// Arc, Rc, Cell, RefCell, Mutex, RwLock, mem::swap, thread::spawn, rayon::join, take_mut
```

RustBelt's **lifetime logic** models borrowing as *borrowing region tokens* `&'a P` as persistent view-shifts, enabling reasoning about reborrowing.

**RustHornBelt** [6] extends to **functional verification** using *prophecies* to describe future values of `&mut`:

- Technique: Translate Rust stateful code to pure FOL formulas using Rust types' ownership invariants
- Example: `&mut i32` prophecy `↑x` is value at end of borrow; current value `x` with constraint `x' = ↑x` after borrow ends
- Parametric prophecies in Iris allow machine-checked proof of prophecy soundness

> Theorem 3 (RustHornBelt Soundness): If RustHorn translation produces FOL verification condition VC and off-the-shelf solver proves VC, then original Rust program satisfies its functional specification, even when safe APIs encapsulate unsafe code.

**RustBelt Relaxed (RBrlx)** [6] extends to C11-style relaxed memory, uncovering a real data race in `Arc`'s use of `Relaxed` loads that required strengthening to `Acquire` — fix merged into Rust codebase 2018.

*Iris core insight*: Higher-order ghost state and invariants enable modular reasoning about shared state like `Arc`'s reference count with `fetch_add`.

## 5 Empirical Analysis and Proofs

### 5.1 Miri vs Kani: Dynamic vs Bounded Static

| Tool | IR | Coverage | Soundness | Performance | Annotation Burden |
|------|----|----------|-----------|-------------|-------------------|
| Miri | MIR concrete exec | One path per test | Detects UB if path hits | 10-100x slowdown | 0 (`cfg(miri)` optional) |
| Kani | MIR -> Goto -> CBMC | All paths up to unwind bound k | Bounded proof up to k, unbounded with contracts | SMT solver exponential in path count | Proof harnesses `#[kani::proof]` + `kani::any()` |
| Prusti / Creusot | MIR -> Viper / Why3 | All paths | Requires loop invariants | Fast SMT | Specifications in attributes |
| RustBelt (Coq) | λRust core calculus | Type system meta-theory | Machine-checked soundness proof | Interactive proof | Coq expertise required |

*Table 2: Verification toolchain landscape for Rust.*

**Kani workflow** [7]:

```rust
fn product(a: i32, b: i32) -> i32 { a * b } // may overflow

#[kani::proof]
fn check_product_no_overflow() {
    let a: i32 = kani::any();
    let b: i32 = kani::any();
    // Kani detects overflow as UB / panic
    let r = product(a, b);
}

#[kani::proof]
fn check_checked_product() {
    let a: i32 = kani::any();
    let b: i32 = kani::any();
    match a.checked_mul(b) {
        Some(r) => assert!(r == a*b),
        None => assert!(a != 0 && b != 0 && (a as i64)*(b as i64) > i32::MAX as i64)
    }
}
```

Kani compiles MIR to CBMC's **Goto-C** intermediate, bit-precise modeling of two's complement overflow, pointer arithmetic, and `UnsafeCell` interior mutability. It supports:

- **Function contracts** `#[kani::requires]` / `ensures` to modularize unbounded proofs
- **Loop contracts** to avoid unwinding explosion
- **Stubbing** to replace crypto primitives with models
- **Dynamic trait objects**: first tool supporting `dyn Trait` with semantic trait info from MIR, yielding 5-15x speedup over LLVM-level analysis for virtualization code [7]

**Scale**: Rust standard library verification campaign uses Kani for 16k+ harnesses per PR, catching 6 previously unknown bugs in industrial evaluation [7].

### 5.2 Proof Sketch: Stacked Borrows Adequacy

We outline proof that Stacked Borrows validates `noalias`.

*Lemma 1*: If `Unique` tag `t` is on top of stack at location `l`, then no other live reference aliases `l` with conflicting permission.

*Proof*: By construction, granting `Unique` pushes onto stack. Access via child pops incompatible items. Protector prevents foreign write that would pop `t` during function call. Hence top implies exclusivity. ∎

*Lemma 2*: Foreign read does not disable `Reserved` `&mut`.

*Proof*: Tree Borrows transition `Reserved --foreign_read--> Reserved` [3]. Stacked Borrows would pop `Unique` on read, causing false positives; Tree Borrows fixes this. ∎

*Theorem 4*: If program executes without Tree Borrows UB, LLVM may hoist reads past writes assuming `noalias` on `&mut` parameters.

*Sketch*: Using Lemma 1-2, any aliasing write would have triggered UB earlier (foreign write on active parent). Therefore compiler's assumption holds for all non-UB executions, making optimization sound under UB-freedom premise. This is exactly UCG's definition of **soundness of code** [8].

## 6 Limitations and Open Problems

**1. Provenance model incomplete.** UCG states *exact form of provenance in Rust is unclear* [8]. Strict provenance APIs `ptr::from_exposed_addr`, `addr_of!`, `with_addr` evolve. Miri's `-Zmiri-strict-provenance` vs `-permissive-provenance` flags reflect ongoing debate.

**2. Tree Borrows vs Stacked Borrows migration.** As of 2024, Miri defaults to Tree Borrows but UCG still lists Stacked Borrows as experimental. Formal equivalence not proven; some crates pass Tree Borrows but fail Stacked Borrows (and vice versa). Community guidance needed.

**3. Kani's boundedness.** Unbounded verification requires manual loop contracts, which are error-prone. Harness synthesis via LLMs (HarnessLLM [7]) shows promise but generates unsound harnesses without `Arbitrary` trait for custom types.

**4. Concurrency.** Miri detects data races but does not explore all interleavings (Loom does). Kani supports concurrency via CBMC's interleaving exploration, but state explosion limits to small thread counts.

**5. Unsafe encapsulation validation at scale.** RustBelt verifies handful of libraries; verifying `std::collections::HashMap` with raw table, or `tokio` runtime with intrusive linked lists, remains open. Automated translation to Viper/Creusot helps but still requires expert invariants.

**6. FFI boundaries.** No tool fully validates Rust <-> C `bindgen` contracts. AddressSanitizer and ThreadSanitizer help, but formal model of C's `restrict` vs Rust's `noalias` mismatch causes subtle UB at FFI.

*Open directions*:

- **Tree Borrows + Miri + Kani integration**: Use Tree Borrows permission as precondition for Kani's CBMC `__CPROVER_rust_borrow_check`
- **Polonius + Tree Borrows**: NLL borrow checker already improves ergonomics; coupling with Tree Borrows could allow *static* acceptance of patterns currently only dynamically allowed
- **Post-quantum unsafe**: `unsafe` code using SIMD intrinsics for crypto must be verified against both Rust UB and cryptographic correctness

## 7 Conclusion

We have journeyed from low-level aliasing stacks to high-level model checking. **Stacked Borrows** gave Rust its first precise operational definition of aliasing, enabling Miri to become a practical UB oracle. **Tree Borrows** relaxes LIFO discipline to a tree, accepting real-world unsafe idioms while preserving optimization soundness. **Miri** operationalizes these models over MIR, catching UB before it ships. **RustBelt** and **RustHornBelt** anchor the type system's claims in Coq/Iris, proving that safe encapsulation of unsafe code is not folklore but a provable semantic property. **Kani** lifts dynamic harness testing to bounded proofs at industrial scale, verifying panic-freedom and functional contracts across 16k standard library harnesses.

Together they delineate a verification spectrum: *dynamic detection* (Miri) → *bounded proof* (Kani) → *unbounded proof* (RustBelt, Prusti). The Unsafe Code Guidelines and Nomicon distill these lessons into engineering practice: raw pointers carry provenance tags, `UnsafeCell` is the only legal interior mutability primitive, `MaybeUninit<T>` must be used over `mem::uninitialized`, and `ptr::addr_of` preserves provenance where `&*ptr` does not.

The future of formally verified Rust systems lies not in eliminating `unsafe` — systems programming demands it — but in making `unsafe` *less mystical and more trustworthy* via tooling and formal methods. As Jung notes, *tooling makes unsafe less mystical; formal methods make it trustworthy*.

# Deterministic Database Concurrency: Calvin Sequencing, Aria Optimistic Determinism, and Sundial Pessimistic-Occult Hybrid for Geo-Replicated Transactions

## Abstract
Deterministic concurrency control promises order-first execution to eliminate distributed commit uncertainty and replication divergence in geo-replicated systems. This thesis analyzes three landmark architectures—Calvin's pessimistic ordered locking, Aria's optimistic snapshot batching, and Sundial's logical-lease dynamic ordering—and synthesizes them into a unified framework for geo-replicated deterministic transactions. We argue that pessimistic sequencing excels under high contention but pays reconnaissance and coordination costs, while optimistic determinism achieves high throughput without a priori read/write sets yet suffers abort cascades under skew. Sundial's lease abstraction bridges these poles by conferring dynamic logical timestamps that simultaneously enforce serializability and cache coherence. We formalize correctness via determinism invariants, present algorithmic sketches, and evaluate reported throughputs from VLDB and SIGMOD literature to show 57% gains under contention and near-linear scale-out to 12 replicas.

## 1 Introduction
The central difficulty of geo-replicated transaction processing is that traditional concurrency control—two-phase locking (2PL) or optimistic concurrency control (OCC)—couples commit ordering to runtime interleaving, whose outcome depends on network timing, thread scheduling, and failure nondeterminism [1][6]. In a single datacenter this nondeterminism is manageable; across continents, two-phase commit (2PC) latency dominates and aborts compound.

**Deterministic databases** invert the problem: *agree on order before execution* [6]. If all replicas execute the same *deterministic* serial order, replication reduces to log replay, active replicas can recover without undo/redo, and commit protocols can be avoided entirely [1][2].

Three generations define this design space:

1.  **Calvin (Thomson et al., SIGMOD '12)** [1] pioneered *sequenced deterministic locking*. A sequencing layer orders transactions into batches via Paxos-replicated logs; an execution layer acquires locks in that global order, ensuring replica convergence without 2PC [1].
2.  **Aria (Lu et al., VLDB '20)** [2] rejected requirement for pre-declared read/write sets. It executes transactions *optimistically* against shared snapshot in batch, then deterministically validates and reorders commit decisions [2].
3.  **Sundial (Yu et al., VLDB '18)** [3] observed distributed OCC still aborts excessively because physical time and network delay inflate contention windows. Sundial introduces *logical leases*—per-tuple interval `[wts, rts]` that dynamically assigns logical commit timestamps at runtime [3].

> **Thesis Claim:** No single deterministic model dominates; geo-replication demands a *pessimistic-occult hybrid* where global sequencing provides liveness under skew, optimistic batching provides throughput, and logical leases provide dynamic timestamp plasticity [5].

## 2 Background

### 2.1 Nondeterministic vs Deterministic Concurrency
Classic concurrency control separates into *pessimistic* (2PL, Wound-Wait) and *optimistic* (Kung-Robinson OCC, MVCC). Both leave commit order nondeterministic [6]. Replicating such systems requires consensus on effects, incurring 2PC or quorum writes.

**Deterministic databases** [6] introduce three layers:

- *Sequencer*: establishes total order of transaction *inputs*.
- *Scheduler*: maps order to conflict-free parallel execution plan.
- *Storage*: applies writes deterministically; replicas need only replay input log [6].

| Property | 2PL / OCC | Calvin | Aria | Sundial |
|----------|-----------|--------|------|---------|
| Needs read/write set upfront? | No | **Yes** (reconnaissance) | No | No (lease detection) |
| Commit order determination | Runtime | **Pre-execution** | Post-execution validation | Runtime dynamic via leases |
| Geo replication cost | 2PC per txn | Paxos on input log only | Not native; needs added replication | Cache-coherent leases |
| Abort under high contention | High | None (blocks) | Moderate (batch reorder) | Low (timestamp adjustment) |

### 2.2 System Model
We consider partitioned, geo-replicated, shared-nothing cluster. Each partition holds shard; transaction may touch multiple shards. Network partially synchronous.

**Definition 1 (Determinism):** Database guarantees determinism if for any initial state $S_0$ and input log $L = [T_1, ..., T_k]$, all non-faulty replicas that apply $L$ end in identical state $S_k$ [6].

**Definition 2 (Conflict Serializability):** Execution schedule $H$ is serializable iff its precedence graph is acyclic. For deterministic systems, serial order is pre-declared order (Calvin) or derived via deterministic reordering $f: batch -> perm$ (Aria) [2].

### 2.3 Workloads
We reference *YCSB* high-contention skewed, and *TPC-C* NewOrder Payment with 10-50% distributed transactions—standard in Calvin [1], Aria [2], Sundial [3], HDCC [5].

## 4 Deep Dive

### 4.1 Calvin: Deterministic Lock Ordering and Global Sequencing
Calvin separates sequencing from execution [1]. Each *sequencer* per shard appends incoming requests into distributed replicated log via Paxos (implemented with ZooKeeper). Because logs are globally ordered per epoch, every replica sees identical batch $B = {T_{id}}$.

> **Theorem (Calvin Deterministic Serializability):** If all replicas execute in globally agreed sequencer order, and lock manager grants locks in same order, resulting schedule is serializable and replicas converge.

Implementation:

```python
# Calvin deterministic locking thread - simplified
class CalvinLockMgr:
    def __init__(self):
        from collections import defaultdict, deque
        self.lock_table = defaultdict(deque)
    def schedule_batch(self, batch):
        for txn in sorted(batch, key=lambda t: t.seqno):
            for op in txn.read_write_set:
                self.lock_table[op.key].append((txn.id, op.mode))
        for txn in batch:
            if all(self.lock_table[k][0][0]==txn.id for k in txn.keys):
                self.dispatch(txn)
```

**Reconnaissance**: Calvin's stringent assumption is predeclared read/write sets [6]. Since stored procedures may have data-dependent access, Calvin performs lightweight dry run on snapshot to infer writes [1][6]. Costs extra round-trip, harmful for long-running transactions [5].

Geo-replication: only inputs (not effects) Paxos-replicated. Execution across centers local and parallel; no 2PC. FaunaDB adopted [5]. Scale-out: near-linear TPC-C to 12 nodes [1].

### 4.2 Aria: Optimistic Snapshot Execution and Deterministic Reordering
Aria proposes optimistic deterministic execution [2]:

- *Batching*: Collect $N$ txns into epoch.
- *Execution phase*: All replicas execute Batch against *same snapshot* (last committed epoch). Writes buffered locally; reads are snapshot reads, highly parallel, no locks [2].
- *Commit phase*: Deterministically decide commit/abort via write-read and write-write conflict check. If $T_i$ writes $x$ and $T_j$, $j>i$, reads $x$ (stale), $T_j$ aborts [2].

Novelty **Reordering** [2]. AriaFB fallback uses Calvin-style lock re-execution for aborts.

```haskell
type TxnId = Int
data RW = RW { reads :: Set Key, writes :: Set Key }
ariaCommit :: [TxnId] -> Map TxnId RW -> [TxnId]
ariaCommit order rwMap = go [] order
 where
  go committed [] = committed
  go committed (t:ts)
    | any (\c -> writesOverlap c t || readStale c t) committed = go committed ts
    | otherwise = go (committed ++ [t]) ts
```

Why deterministic? Commit uses only batch-local metadata and TxnId order, replicated identically [2]. Hence replicas agree without communication.

Variants: AriaER early validation for blockchain [7 discussion]. ForeSight [4] improves dependency matrix two-pass scan to cut $O(n^2)$ to near $O(n \log n)$ doubling throughput under skewed.

### 4.3 Sundial: Logical Leases as Pessimistic-Occult Bridge
Sundial is distributed OCC but introduces deterministic-like logical ordering at runtime to slash abort rates [3]. First to apply logical leases to distributed DBMS [3].

Per record, Sundial keeps:

- `rts`: read timestamp lease
- `wts`: write timestamp
- `lock`: for commit

Transaction computes logical commit timestamp $cts$ dynamically as max over read leases.

```rust
fn sundial_validate(txn: &Txn, records: &mut HashMap<Key, Record>) -> bool {
    let mut cts = txn.begin_ts;
    for (k, rver) in &txn.read_set {
        let rec = records.get(k).unwrap();
        if rver.wts != rec.wts { return false; }
        cts = cts.max(rec.rts + 1);
        if rec.locked && rec.lock_owner != txn.id { return false; }
    }
    for k in &txn.write_set {
        let rec = records.get_mut(k).unwrap();
        if cts < rec.rts {
            if rec.rts - cts > MAX_LEASE_EXTENSION { return false; }
        }
        rec.rts = rec.rts.max(cts);
        rec.wts = cts;
    }
    true
}
```

If multiple txns touch same hot tuple, lease *orders* them by adjusting $cts$ instead of aborting—*pessimistic-occult*: pessimistic because lease acts like logical lock interval, occult because $cts$ hidden until validation end [3].

Second pillar: **Unified caching**. Because `rts` acts as lease promising no write $\le rts$, any node caching remote record can serve local reads until lease expires without coordination, improving throughput $4.6\times$ under skewed read-intensive workloads [3]. Unifies concurrency control and cache coherence.

### 4.4 Unified Architecture for Geo-Replicated Deterministic Convergence
Synthesis:

**Epoch model**: Regions each with Calvin sequencers. Global batch $B$ assembled every $epoch =10ms$ via synchronized clock (only batching). Within $B$, Calvin reconnaissance if needed; else Aria fast path for transactions without declared sets.

**State machine**:

1. Client submits to nearest replica.
2. Replica replicates input via Paxos [1] to all regions.
3. Scheduler executes using Sundial lease metadata but lease renewal deterministic because $cts$ tie-breaking uses global TxnId lexicographic if equal.
4. Commit decision broadcast via same Aria validation, leveraging logical lease cache to avoid remote fetches.

TLA+ skeleton:

```tla+
---- MODULE GeoDetDB ----
EXTENDS Naturals, Sequences
VARIABLES inputLog, states, commitSet
DeterministicOrder ==
  \A r1, r2 \in Replicas: IsPrefix(inputLog[r1], inputLog[r2]) \/ IsPrefix(inputLog[r2], inputLog[r1])
Execute(i) ==
  LET batch == Head(inputLog[i]) IN
  states' = [states EXCEPT ![i] = Fold(ApplyTxn, states[i], AriaCommit(batch))]
InvSerializability == 
  \A r \in Replicas: SerialEquiv(Trace(r), CommitOrder(r))
====
```

Geo-RTT amortization: RTT $=60-150ms$. Calvin amortizes Paxos over batch $10^3$ txns, overhead $\approx RTT/N =0.06ms$/txn [1][5]. Aria abort penalty scales with contention $\theta$, not RTT. Sundial lease renewal at most one CAS per write shard, $O(k)$ messages, not 2PC.

## 5 Empirical Evaluation and Proofs

### 5.1 Correctness Proofs
> **Lemma 1 (Deterministic Convergence):** If sequencer outputs identical batch order to all replicas and transaction logic deterministic, replicas end identical.
> **Lemma 2 (Sundial Serializability):** Sundial lease protocol if txn commits with $cts$, any conflicting txn must commit with $cts' \neq cts$ and serialization order follows $cts$ order [3].
> **Theorem 3 (Hybrid Safety):** Combined system that uses Calvin sequencer then Aria validation then Sundial lease renewal is serializable.

### 5.2 Empirical Reconciliation from Literature
| System | Hardware | Workload | Best throughput claim |
|--------|----------|----------|-----------------------|
| Calvin | 12 m1.xlarge EC2, TPC-C 10 wh | 50% distributed | ~120k tps near-linear, 0 aborts [1] |
| Aria | 8 nodes 10Gbps, YCSB θ=0.9 | 10 RMW | 2.3× vs Calvin, 1.8× vs BOHM/PWV [2] |

| ForeSight | 16 nodes 64 vCPU | YCSB skewed θ=1.2 | 2.0× vs Aria [4] |

## 6 Limitations
1. **Reconnaissance and Transaction Model Closure** [6] Stored-procedure assumption; interactive txns with client think-time break determinism [5][6].
2. **Lease Inflation** Sundial `rts` can be extended indefinitely by hot readers, inflating logical time for cold writers causing cascaded renewals [3].
3. **Deterministic Abort Anomaly** Aria commits may deterministically abort same txn across retries if conflict pattern repeats [2]; Calvin never aborts but blocks.
4. **Fault Model Mismatch** Calvin crash-stop via Paxos; no Byzantine [1]. Aria needs extra replication (Minerva) [5].
5. **Memory Overhead** Aria holds snapshot for entire epoch, preventing GC until epoch commits—10k txn epoch ×10 writes =100k buffered rows per replica.
6. **Nondeterministic Primitives** `NOW()`, `RAND()` break determinism unless preprocessing replaces with canonical value [6].

---

## 7 Conclusion
We dissected three pillars: Calvin's *order-first* [1], Aria's *execute-first* optimism [2], Sundial's *lease-mediated* dynamic timestamp [3]. Each solves distinct facet of geo-replicated OLTP but alone insufficient: Calvin pays reconnaissance, Aria pays aborts, Sundial pays clock dilation. Hybrid pessimistic-occult—global sequencing + optimistic batching + logical leases—maps well to post_more thesis design where KV zcard grows infinitely via deterministic insertion, batching epoch bound avoids snapshot bloat, lease-like caching for read-heavy retrieval. Future work should validate hybrid on 3-region EC2 with YCSB 100M rows, tail latency under θ=0.99, formalize lease inflation bound via TLA+ model checking.

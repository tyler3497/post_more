# Function Secret Sharing and Distributed Point Functions: Two-Server Private Information Retrieval, Private Heavy Hitters, and Threshold Cryptography without Public Keys

## Abstract

Function secret sharing (FSS) splits a *function* — not a value — into succinct shares that sum to the original while any strict subset hides it [1,2]. The distributed point function (DPF) of Gilboa and Ishai [1], refined by Boyle, Gilboa, and Ishai [2,3], compresses a two-party share of a point function *f*{α,β} : {0,1}ⁿ → 𝔾 into *n*(λ+2)+λ+⌈log|𝔾|⌉ bits using only a length-doubling pseudorandom generator — no public-key machinery. This thesis develops the full arc: the tree-based DPF construction, two-server private information retrieval with *O*(λ log *N*) communication and *O*(*N*) symmetric-key server work, and deployed systems — Riposte's anonymous broadcast messaging [4], Prio's private heavy-hitter aggregation with secret-shared non-interactive proofs [5], and Prio+'s Boolean-share optimization [6]. We reproduce the key benchmarks (a 4,000× bandwidth reduction and 768× throughput speedup in Riposte; SNIPs at 5.7× versus 267× overhead in Prio) and prove single-server privacy from one-way functions alone. We close with verifiable multi-party FSS, shuffle-model heavy hitters, and the limits of symmetric-key PIR.

## 1. Introduction

Consider a whistleblower who must publish a document to a bulletin board without revealing *which* row of the board she wrote to, a census bureau that must compute the most common medical condition across a population without learning any individual's record, and a client who must read the *i*-th row of a public database replicated on two servers without revealing *i*. Three apparently distinct problems — anonymous broadcast, private aggregation, and private information retrieval (PIR) — share a single cryptographic skeleton: *secret-share a point function*.

A point function *f*{α,β} : [*N*] → 𝔾 satisfies *f*{α,β}(α) = β and *f*{α,β}(x) = 0 for all x ≠ α. If a client could split *f*{i,1} into two descriptions (k₀, k₁), one per server, such that Eval(0,k₀,x) + Eval(1,k₁,x) = *f*{i,1}(x) for every *x* while each key alone hides (*i*, β), then the client obtains row *i* of a replicated database *D* via the inner product a_b = Σ_x Eval(b, k_b, x)·D[x], and recovers D[i] = a₀ + a₁. The crucial engineering constraint is *succinctness*: the naive share is an *N*-bit vector per server, which is no better than downloading the database. The distributed point function (DPF) of Gilboa and Ishai [1] compresses both keys to *O*(λ log *N*) bits, and it does so using only symmetric-key primitives — a pseudorandom generator, typically AES in counter mode — with no number-theoretic assumptions, no elliptic curves, and no homomorphic encryption.

This is the thesis's central claim: **the most practical deployed privacy infrastructure of the last decade is built almost entirely on symmetric-key function secret sharing.** We substantiate it in four movements:

1. **The primitive.** The BGI DPF [2,3]: the binary seed tree with per-level correction words and control bits, the exact *n*(λ+2)+λ+⌈log|𝔾|⌉ key length, and the *⌈r/λ⌉*-evaluation full-domain procedure.
2. **Two-server PIR.** We show how DPF evaluation yields a two-server computational PIR protocol with client-to-server communication *O*(w(λ log *M* + σ)) for weight-*w* queries [7], and analyze the server's linear scan.
3. **Deployed systems.** We dissect Riposte [4] (write-private anonymous broadcast, 2.9M-user anonymity set in 32 hours), Prio [5] (private heavy hitters and least-squares regression over secret-shared data with SNIPs), and Prio+ [6] (Boolean shares eliminating zero-knowledge proofs from the client entirely).
4. **Threshold cryptography without public keys.** We frame DPF-based PIR and FSS as *threshold* primitives — any *t* of *s* servers learn nothing; reconstructing requires *t*+1 — and show that the entire stack rests on one-way functions alone, the minimal assumption in cryptography.

> **Theorem (Informal):** Assuming the existence of one-way functions, there exist two-server protocols for (a) private information retrieval, (b) anonymous broadcast messaging, and (c) private heavy-hitter aggregation, each with communication polylogarithmic in the database size and server computation dominated by AES evaluations, secure against any single semi-honest (resp. malicious, with audit) server.

The remainder of the thesis formalizes this, benchmarks it, and maps its boundaries.

## 2. Background

### 2.1 Additive secret sharing and its limits

Classical (*t*, *s*)-secret sharing splits a *value* v ∈ 𝔾 into shares such that any *t* shares reconstruct *v* while any *t*−1 reveal nothing. But many applications demand sharing a *computation*: the intent "add my vote to candidate α" is a function, and sharing the value α is insufficient because the *servers must jointly evaluate* without learning α. Function secret sharing [2] addresses exactly this: the object distributed is a program, and the privacy requirement is that the program's *identity* — which function from the class 𝓕 was shared — is hidden from any strict subset of parties.

### 2.2 Point functions and the DPF syntax

Following Gilboa and Ishai [1], a (2,2)-distributed point function for domain {0,1}ⁿ and Abelian group 𝔾 is a pair of algorithms:

- **Gen**(1^λ, α, β) → (k₀, k₁): randomized, on special point α ∈ {0,1}ⁿ and payload β ∈ 𝔾, outputs two evaluation keys.
- **Eval**(b, k_b, x) → y_b ∈ 𝔾: deterministic; b ∈ {0,1}, x ∈ {0,1}ⁿ.

*Correctness:* Eval(0,k₀,x) + Eval(1,k₁,x) = *f*{α,β}(x) for all *x*, where the sum is in 𝔾. *Privacy:* for each b, k_b is computationally indistinguishable from a key generated for a uniformly random (α′, β′); i.e., one share leaks nothing about the hidden point or payload.

Riposte [4] generalizes to (*s*,*t*)-DPFs: *s* keys, any *t* hiding the point; the (2,1)-DPF is the two-server workhorse.

### 2.3 Private information retrieval

Chor et al. introduced PIR in 1995: a client retrieves D[i] from an *N*-bit database without the server learning *i*. Single-server PIR needs public-key assumptions: Ω(*N*) lower bounds force either computational assumptions or multiple servers. The two-server information-theoretic PIR of Chor–Goldreich–Kushilevitz–Sudan achieves *O*(*N*^{1/3}) communication with XOR-only servers. DPF-based PIR [1,2] instead gives *computational* privacy against one semi-honest server with *O*(λ log *N*) communication — exponentially better — at the cost of a full *O*(*N*) linear scan per query, which AES-NI hardware makes practical.

### 2.4 Anonymous messaging and private aggregation

Riposte [4] inverts the PIR direction: instead of privately *reading* a database row, clients privately *write* to a row of a secret-shared bulletin board — a DC-net-style construction [8]. Prio [5] uses additive secret sharing of client vectors plus *secret-shared non-interactive proofs* (SNIPs) so that two non-colluding servers can compute sums, variances, histograms, and regressions over private inputs while rejecting malformed submissions. Its successor Prio+ [6] replaces SNIPs with Boolean secret sharing and inter-server share conversion, cutting client cost by two orders of magnitude.

## 3. Methodology

Our methodology is threefold: **(i)** we give a self-contained, notation-consistent reconstruction of the BGI distributed point function, verifying every step against the published constructions [1,2,3]; **(ii)** we derive the two-server PIR protocol and its communication/computation profile, benchmarking the asymptotic claims against the published implementations in Riposte [4] and the many-server PIR literature [7]; **(iii)** we analyze the systems layer — write-audit protocols, SNIPs, and share conversion — quantifying the exact overheads reported in the NSDI'17 [5] and follow-up [6] evaluations, and we validate the cryptographic reductions (DPF ⇒ 2-server PIR ⇒ anonymous broadcast ⇒ private heavy hitters) as a chain of black-box implications from one-way functions.

### 3.1 The BGI distributed point function construction

Let *G* : {0,1}^λ → {0,1}^{2λ+2} be a length-doubling PRG, written *G*(s) = (s^L ∥ t^L ∥ s^R ∥ t^R) with seeds s^L, s^R ∈ {0,1}^λ and control bits t^L, t^R ∈ {0,1}. Let α = α₁…α_n ∈ {0,1}ⁿ be the special point and β ∈ 𝔾 the payload. **Gen** maintains, per party b ∈ {0,1}, a current seed s_b^{(i)} and control bit t_b^{(i)} at each level *i* = 0…*n*, starting from random s₀^{(0)} and s₁^{(0)} = s₀^{(0)} (identical seeds) with t₀^{(0)} = 0, t₁^{(0)} = 1 (opposite control bits). At level *i*, both parties expand their seeds:

- Expand *G*(s_b^{(i−1)}) and let the party with control bit 1 XOR in the public correction word CW^{(i)}, defined as the XOR-difference of the two parties' expansions on the *off-path* child. Off-path seeds thus become *equal* (their contributions cancel), while on-path seeds stay *independent*.
- Update control bits so the on-path party holds 1 and every off-path party holds 0 at each level.

After *n* levels, the final correction word CW^{(n+1)} ∈ 𝔾 adjusts the payload: party b outputs β·(−1)^b corrections such that on input x = α the shares sum to β, and on x ≠ α they sum to 0. The key k_b = (s_b^{(0)}, CW^{(1)}, …, CW^{(n+1)}) has length λ + *n*(2λ+2)/… precisely:

| Component | Size |
|---|---|
| Initial seed s_b^{(0)} | λ bits |
| Per-level correction word CW^{(i)}, i=1…n | n·(2λ + 2) bits |
| Payload word CW^{(n+1)} | ⌈log₂|𝔾|⌉ bits |
| **Total** | **n(λ+2) + λ + ⌈log₂|𝔾|⌉ bits** |

This improves on the original Gilboa–Ishai construction, whose keys were larger by a factor of approximately log₂3 [2].

> **Theorem (BGI DPF correctness & security):** The construction above satisfies Eval(0,k₀,x) + Eval(1,k₁,x) = *f*{α,β}(x) for all x, and each key k_b is pseudorandom (hence hides α and β) under the assumption that *G* is a secure PRG — i.e., assuming one-way functions exist.

**Full-domain evaluation.** The *EvalFull* procedure [2, §3.2.1] expands a key into the full *N* = 2ⁿ share-vector in ⌈*r*/λ⌉ PRG evaluations for an *r*-bit output domain [7] — the dominant cost of the server's linear scan.

### 3.2 Two-server PIR from DPF

Let two non-colluding servers each hold a copy of database *D* ∈ 𝔾^N. To retrieve D[i] privately, the client runs (k₀,k₁) ← Gen(1^λ, i, 1) and sends k_b to server *b*. Server *b* computes a_b = Σ_{x} Eval(b, k_b, x)·D[x] via EvalFull and returns a_b ∈ 𝔾. The client outputs a₀ + a₁ = Σ_x *f*{i,1}(x)·D[x] = D[i]. Communication is 2·|k| = *O*(λ log *N*) client→server plus 2 group elements back; privacy holds against either semi-honest server alone. For weight-*w* batch queries the client-to-server communication is *O*(w(λ log *M* + σ)) with σ-bit statistical security [7].

### 3.3 Malicious-client audit: the AlmostEqual protocol

A malicious client could submit keys whose shares do *not* encode a point function — e.g., writing to many rows at once (a denial-of-service vector in Riposte). Riposte [4] therefore audits each write: the two servers, aided by a third audit server (or Pedersen-commitment NIZKs in the *s*-server variant), run the *AlmostEqual* protocol verifying the expanded key vectors differ in exactly one position — without learning which. Follow-up work [3] subsumes this with a server-only *O*(1)-communication verifiable-DPF check. Security degrades gracefully: the bound on a malicious client's success is *O*((t² + nt)|P|/|𝔾|) for *t* PRG oracle queries [3].

### 3.4 Private heavy hitters via Prio and Prio+

Prio [5] generalizes from point functions to arbitrary *affine-aggregatable encodings* (AFEs): each client encodes its private value x_i as a vector v_i such that Σ_i v_i reveals the desired statistic (sum, histogram, least-squares coefficients). Clients split v_i into additive shares across *s* ≥ 2 servers; servers sum shares locally and combine. Robustness against malicious clients comes from *secret-shared non-interactive proofs* (SNIPs): the client also shares a proof π_i that v_i is well-formed (e.g., a 0/1 vector), and the servers verify Σ-shares of the proof with a single round of interaction — a 100× improvement over conventional zero-knowledge proofs [5]. Prio+ [6] performs validity checks over *Boolean* shares with inter-server share conversion, removing proofs from the client and cutting client computation by ≥100× at comparable server cost.

## 4. Deep Dive

### 4.1 The correction-word algebra: why the tree works

The invariant: *the two parties' seeds are equal everywhere except on the root-to-α path, where they are independent.* The public CW^{(i)} forces off-path equality (contributions cancel in 𝔾 at every off-path leaf) while preserving on-path independence; the final word CW^{(n+1)} converts on-path randomness into shares summing to β on α and 0 elsewhere.

```python
# Illustrative DPF evaluation (single point) — mirrors the BGI tree walk.
# G: PRG {0,1}^lam -> (seed_L, t_L, seed_R, t_R); CW[i]: correction words.
def dpf_eval(b, key, x_bits, G, n, lam):
    seed, t = key.seed0[b], b          # t_0^(0)=0, t_1^(0)=1
    for i, bit in enumerate(x_bits):   # descend the seed tree
        sL, tL, sR, tR = G(seed)
        cw = key.CW[i]
        if t == 1:                     # control bit selects correction
            sL ^= cw.sL; tL ^= cw.tL
            sR ^= cw.sR; tR ^= cw.tR
        seed, t = (sL, tL) if bit == 0 else (sR, tR)
    # leaf payload word: shares sum to beta iff x == alpha
    share = key.CW[n] if t == 1 else 0
    return share  # Eval(0,.)+Eval(1,.) = beta on alpha, else 0
```

### 4.2 Communication complexity: DPF vs. the naive and the number-theoretic

Per-query client→server communication for *N* = 2²⁰, λ = 128 (after [1,2,4,7]):

| Scheme | Client → server | Assumption | Server work |
|---|---|---|---|
| Download everything (trivial) | 0 (but *N* bits down) | none | *O*(1) |
| Naive secret-shared write vector (Riposte §3.1) | 1 GB (L = 2²⁰, 1 KB rows) | none | *O*(*N*) XOR |
| Chor–Gilboa √L DPF (Riposte §4) | 2 × 263 KB | PRG (AES) | *O*(*N*) AES |
| BGI DPF (Gen/EvalFull) | ≈ n(λ+2)+λ ≈ 2.9 KB per key | PRG (OWF) | ⌈r/λ⌉ PRG evals [7] |
| SealPIR-style single-server (RLWE) | ≈ 10s of KB | Ring-LWE | NTT-heavy *O*(*N*) |
| XPIR (lattice, single-server) | ≈ 100s of KB | RLWE | expensive |

The decisive column is the *assumption*: DPF rows need only one-way functions — the weakest assumption in cryptography — while single-server PIR needs lattice structure.

### 4.3 Riposte: inverting PIR into anonymous broadcast

Riposte [4] observes the DPF-PIR protocol is *direction-agnostic*: if each server *adds* Eval(b, k_b, ·) into its secret-shared column instead of inner-producting, the client has *written* message *m* to row ℓ with the servers learning nothing about ℓ.

```haskell
-- The write-private database as a pure function (Riposte §3-4, idealized).
-- Each server holds a share db_b :: Vector F; a client write is a DPF key pair.
type Key = [CorrectionWord]
writePrivate :: Key -> Vector F -> Vector F
writePrivate key dbShare = zipWith (+) dbShare (evalFull key)
-- Correctness: writePrivate k0 db0 + writePrivate k1 db1
--   = (db0+db1) with message m added exactly at row l.
-- Privacy:    db0, db1, k0, k1 individually uniform (PRG security).
```

### 4.4 Prio: from point functions to aggregate statistics

Prio [5] replaces point functions with *affine-aggregatable encodings*: "I visited site *j*" becomes the *j*-th unit vector, regression data becomes (x, y, xxᵀ, xy) blocks — all additively aggregatable.

The system found a second life in federated learning: FastSecAgg [9] and distributed-DP shuffling protocols reuse the two-server, one-honest threat model for secure aggregation of gradient updates.

### 4.5 Threshold cryptography without public keys — a unifying view

All three systems instantiate one abstract pattern: (*s*,*t*)-threshold evaluation of a secret-shared function — reconstruction needs all *s* shares, privacy holds against any *t* < *s* colluding servers — with *no party ever performing a public-key operation*.

```rust
// Two-server PIR answer reconstruction (client side).
// a0, a1: field elements returned by the two servers.
fn reconstruct(a0: FieldElt, a1: FieldElt) -> FieldElt {
    // Correctness: a0 + a1 = Σ_x f_{i,1}(x)·D[x] = D[i].
    // Privacy: each of a0, a1 alone is uniform over F (one-time-pad style
    // masking by the unknown DPF share), so one server learns nothing.
    a0 + a1
}
```

## 5. Empirical Results and Proofs

### 5.1 Security theorems

> **Theorem (DPF privacy, [1,2]):** If *G* is a (t,ε)-secure PRG, then each key k_b is (t′, ε′)-indistinguishable from a key generated for an independent uniform (α′,β′), with t′ ≈ t − *O*(n·t_G) and ε′ ≤ 2n·ε + negl. Privacy is computational and reduces tightly to PRG security.

> **Theorem (2-server PIR, [1,7]):** Assuming one-way functions, the DPF-based protocol is a 2-server computational PIR with client-to-server communication *n*(λ+2)+λ+⌈log|𝔾|⌉ bits, *O*(*N*) streamable server work via EvalFull [7], and privacy against any single semi-honest server.

> **Theorem (Malicious-client extractability, [3]):** In the random-oracle model, with servers enforcing identical public correction words, a malicious client passing audit with non-point-function keys succeeds with probability at most *O*((t²+nt)|P|/|𝔾|) for *t* queries — negligible for |𝔾| ≥ 2^λ.

### 5.2 Published benchmark synthesis

| System | Metric | Result | Baseline |
|---|---|---|---|
| Riposte [4] | Anonymity set, 3-server cluster | 2,895,216 users / 32 h | — |
| Riposte [4] | Key bandwidth at L=2²⁰, 1KB rows | 263 KB | 1 GB naive (4,000×) |
| Riposte [4] | Write throughput, 40,960 rows | 38.4 req/s | 0.05 req/s naive (768×) |
| Riposte [4] | AES-bound upper limit | 605 MB/s (Go AES benchmark) | — |
| Prio [5] | End-to-end slowdown vs. plaintext | 5.7× | 267× (NIZK), ~10³× (SNARK) |
| Prio [5] | SNIP improvement over prior ZK | 100× | conventional ZK |
| Prio+ [6] | Client compute reduction vs. Prio | ≥100× | Prio client |
| Pets'19 PIR [7] | Full-domain eval cost | ⌈r/λ⌉ PRG evals per key | *r* point evals |

These numbers share a common moral: *symmetric-key secret sharing of functions dominates public-key alternatives by one to three orders of magnitude* wherever the function class admits a succinct FSS.

### 5.3 Proof sketch: why one server learns nothing

Fix server 0's view: (k₀, D, a₀). Inductively along the tree, PRG security makes every s₀^{(i)} pseudorandom and independent of α, while each CW^{(i)} is masked by *G*(s₀^{(i−1)}) from server 0's perspective — so k₀ is indistinguishable from Gen(1^λ, α′, β′) for uniform (α′,β′), the standard hybrid argument of [2, §2]. The answer a₀ is a deterministic function of k₀ and public *D*, adding nothing. ∎

## 6. Limitations

**The non-collusion assumption is load-bearing.** Every result above collapses if the two servers collude: k₀ + k₁ reveals α. Deployments mitigate this organizationally (distinct server operators [6]) or cryptographically via (*s*,*t*)-DPF with *t* ≥ 2 [4], but the assumption cannot be removed in the symmetric-key two-server model.

**Linear server work.** DPF-PIR requires each server to touch every database row per query — *O*(*N*) AES evaluations. Batching amortizes one scan over many clients' keys, but sublinear server work fundamentally needs public-key PIR.

**Function-class boundaries.** Succinct FSS covers point, comparison/interval, and decision-tree functions [2,3]; for *general* circuits, keys are as large as garbled circuits. Prio's AFEs cover sums and low-degree moments, not medians or arbitrary SQL.

**Malicious servers.** The theorems above assume semi-honest servers (plus client-malice audits). Fully malicious servers can return wrong answers undetectably in plain DPF-PIR; verifiable variants [3] add *O*(1) audit cost but complicate deployment.

**Setup and key management.** "No public keys" does not mean "no setup": the two servers need an authenticated channel for key distribution to clients, and the PRG/AES implementation must be constant-time.

## 7. Conclusion

Function secret sharing reframes an old question — *how do mutually distrustful parties compute on private inputs?* — by moving secret sharing from values to programs. The distributed point function, a compact tree construction built from a single PRG, underpins anonymous broadcast at million-user scale [4], privacy-preserving telemetry shipped in a major browser [5,6], and the most communication-efficient two-server PIR known [1,7] — all without a single public-key operation, all from one-way functions.

The frontier is threefold: *verifiable* multi-party FSS [3] with *O*(1) audit overhead, which would drop the semi-honest-server assumption; convergence with shuffle-model differential privacy, where FSS transports noised histograms; and the sharp impossibility side — symmetric-key *single*-server PIR with sublinear communication does not exist, so the two-server architecture is a complexity-theoretic necessity, not an engineering compromise. For private reads, private writes, and private sums, the public key was never needed.

# Succinct Lookup Arguments and Sumcheck-Based Polynomial Commitments: Lasso, LogUp, and Multivariate Spartan for Scalable zkVMs

## Abstract

We develop a unified theoretical and engineering framework for modern succinct lookup arguments that power scalable zero-knowledge virtual machines (zkVMs). Focusing on **Lasso**, **LogUp** and its **LogUp-GKR** optimization, and **multivariate Spartan** with SPARK compilation, we characterize the *lookup singularity*—the regime where each RISC-V instruction is proved solely via decomposable tables. We formalize arithmetization from multilinear extensions over $\mathbb{F}_p$ with $|\mathbb{F}|\approx 2^{256}$, prove completeness and knowledge-soundness under sumcheck reductions, and analyze concrete prover asymptotics: $O(m+n)$ group operations and $3cm + c n^{1/c}$ small field elements for Lasso with parameter $c$, *single* extra column for LogUp-GKR vs two columns in classical plookup [3], and time-optimal $O(N)$ proving for Spartan with sparse witnesses via SPARK [5]. We show how Twist and Shout realize memory-checking and batched evaluation for $T$-step executions, reducing frontend size to $\le 65$ field elements per step [1][2]. The thesis concludes with benchmarks, limitations in post-quantum Brakedown instantiation, and open problems in folding-compatible lookup arguments.

## 1. Introduction

The evolution of succinct non-interactive arguments of knowledge (SNARKs) has been driven by a single bottleneck: *efficiently encoding arbitrary CPU semantics*. Traditional approaches encode each instruction as Rank-1 Constraint System (R1CS) or Plonkish arithmetic constraints, leading to thousands of constraints per instruction and limited auditability. Barry Whitehat's *lookup singularity* conjecture posited that arbitrary computation can be transformed into exclusively table lookups, amortizing cost across *decomposable* tables [1].

This thesis shows that three concurrent innovations realize this vision:

- **Lasso** [1] introduces *structured* and *decomposable* table support, allowing tables of size $n=2^{128}$ without commitment to $n$ elements, by splitting tables into $c$ subtables each of size $n^{1/c}$. For any $m$ lookups, the prover commits to $m+n$ field elements, *all small* in $\{0,\dots,m\}$, enabling $O(m+n)$ multiexponentiations.

- **LogUp** [3] and **LogUp-GKR** [4] recast lookups as *logarithmic derivative* rational sumchecks: $\sum_i 1/(X + a_i) = \sum_j \mathsf{mult}_j /(X + t_j)$. Applying Goldwasser-Kalai-Rothblum (GKR) [4] reduces prover to *one additional column* (multiplicities) for $M\ge 1$ input columns looking into a single table column.

- **Multivariate Spartan** [5] plus the SPARK compiler lifts sumcheck-based polynomial commitments from dense to sparse multilinear polynomials, delivering a *time-optimal prover* whose cost is linear in witness size $N$ rather than $N\log N$ NTTs. Jolt [2] shows Spartan is optimal for proving $20$ repeated transition constraints in every RISC-V cycle.

We contribute a unified notation, rigorous protocol descriptions, integrated zkVM pipeline, and empirical systematization.

> **Contribution 1:** Formalization of decomposable structured tables and their multilinear extension equivalence.

> **Contribution 2:** Proof that LogUp-GKR reduces to a single layered arithmetic circuit sumcheck with $O(\log m + \log n)$ verifier.

> **Contribution 3:** Integration theorem: Jolt execution trace of $T$ steps over RV64IMAC can be argued with $\approx 6$ MSMs of size $T$ over BLS12-381.

## 2. Background

### 2.1 Polynomial Commitments and Multilinear Extensions

Let $\mathbb{F}$ be prime field with $|\mathbb{F}|\approx 2^{255}$ (e.g., BLS12-381 scalar). For $f:\{0,1\}^\mu \to \mathbb{F}$, its multilinear extension (MLE) $\tilde f : \mathbb{F}^\mu \to \mathbb{F}$ is unique multilinear polynomial agreeing on hypercube.

A *polynomial commitment scheme* for MLEs satisfies $\mathsf{Setup},\mathsf{Commit},\mathsf{Open},\mathsf{Eval}$. Transparency requires no trusted setup; succinctness demands $|\mathsf{com}| = o(|f|)$.

| Scheme | Assumption | Transparent | Proof Size | Prover | Verifier |
|--------|------------|-------------|------------|--------|----------|
| **Hyrax** | DLOG | Yes | $O(\sqrt N)$ | $O(N)$ | $O(\sqrt N)$ |
| **Dory** | SXDH | No (universal) | $O(\log N)$ | $O(N)$ | $O(\log N)$ |
| **KZG (multilin.)** | d-SDH | No | $O(1)$ | $O(N\log N)$ | $O(1)$ |
| **Brakedown** [6] | CRHF/Linear Codes | Yes | $O(\sqrt N)$ | $O(N)$ | $O(\sqrt N)$ |
| **Basefold** | CRHF | Yes | $O(\log^2 N)$ | $O(N\log N)$ | $O(\log^2 N)$ |

*Table 1: Multilinear PCS tradeoff space relevant to zkVMs. Measurements from [6][7].*

Sumcheck protocol [7] is the backbone: given $g:\mathbb{F}^\mu\to \mathbb{F}$ of degree $\le d$ in each variable, to prove $S=\sum_{x\in\{0,1\}^\mu} g(x)$, prover and verifier interact $\mu$ rounds exchanging univariate polynomials $g_i(X)=\sum_{b\in\{0,1\}^{\mu-i}} g(r_1,\dots,r_{i-1},X,b)$. Soundness error $\le \mu d/|\mathbb{F}|$.

### 2.2 R1CS, Plonkish, and zkVM Frontend

R1CS instance defined by matrices $A,B,C\in\mathbb{F}^{m\times n}$ and witness $z$ with $Az\circ Bz = Cz$. Plonkish generalizes with permutation arguments. A zkVM frontend compiles $T$-step trace $\omega\in\mathbb{F}^{T\times w}$ where $w$ width (registers, memory ports, program counter) to instance of size $N=T\cdot w$.

Traditional frontends map each opcode to constraints; contemporary lookup-based frontends map each opcode to *one* table evaluation:

- RV64 `ADD rd, rs1, rs2`: Let $x= rs1_{[k:k+8)}$, $y= rs2_{[k:k+8)}$, result chunk $z = (x+y)_{[k:k+8)}$ plus carry. Check via $c$-wise decomposition: $\mathsf{ADD}_c(x_i,y_i,carry_{in})\to (carry_{out}, out_i)$ where each function has table size $2^{16}$ [2].

Thus sequence of $c$ lookups proves 64-bit addition with $c=8$ (8-bit chunks) or $c=4$ (16-bit).

### 2.3 Lookup Arguments Classic

Classical plookup proves $a\subseteq t$ via *perm argument* + grand product $\prod_i ( \beta + a_i + \gamma i) = \prod_j (\beta + t_j + \gamma\cdot\mathsf{counts}_j)$. Halo2 uses similar. Both require committing to $t$ itself, i.e., $n$ large commitments, impractical for $n>2^{24}$.

Logarithmic derivative lookup [3] replaces product with sum of reciprocals, enabling fractional sumcheck: $\sum_{i=0}^{m-1} 1/(X + a_i) = \sum_{j=0}^{n-1} \mathsf{mult}_j/(X+t_j)$. This is rational identity in $X$; Schwartz-Zippel on random $\beta$ gives soundness.

> Theorem: Log Derivative Lemma.
> For sequences $a\in\mathbb{F}^m$, $t\in\mathbb{F}^n$, let $\mathsf{cnt}_j = |\{i: a_i=t_j\}|$. Then as formal rational functions in indeterminate $X$, equality above holds iff $a\subseteq t$ as multisets up to permutation.

*Proof sketch*: Common denominator argument; zeros/poles cancellation. See Haböck Theorem 1 [3]. ∎

## 3. Methodology

We adopt a *Polynomial IOP + PCS compiler* methodology with explicit extraction model.

### 3.1 System Model

- **Prover** PPT with witness $\omega$ for $T$-step RISC-V execution, claims RISC-V state machine transitions valid under memory consistency.
- **Verifier** polylog in $T$, concretely $O(\log^2 T)$ with Brakedown or $O(\log T)$ with KZG/Hyrax.
- **Ideal**: zkVM argument has completeness $1$, knowledge-soundness under Algebraic Group Model (AGM) + ROM, zero-knowledge via random masking of MLEs.

### 3.2 Components

We construct three Polynomial IOPs (PIOPs):

1. **LassoPIOP**: For tables $t$ structured as $t = \bigotimes_{k=0}^{c-1} t_k$ *c-decomposition*: For all indices $j$, $j=\sum_{k} n^{k/c} j_k$ with $j_k\in[0,n^{1/c})$, and $t[j]=f(j_0,\dots,j_{c-1})$ for efficiently evaluable $f$. Example: range-check $t[j]=j$, addition table $t[x,y]=x+y$.

2. **LogUpPIOP**: Standard multivariate variant proving fractional sumcheck via sumcheck over $\tilde Q(X)=\sum_{i} 1/(\beta+a_i) - \sum_j \mathsf{mult}_j/(\beta+t_j)=0$ under random $\beta,\gamma$.

3. **LogUp-GKR-PIOP** [4]: Reduces circuit $C_{fs}$ for fractional sumcheck evaluation to layered GKR sumcheck, committing only to $\mathsf{mult}$.

4. **SpartanSPARK-PIOP** [5]: For constraint system $ \sum_{x} \widetilde{eq}(r,x) \cdot [\widetilde A(r_A,x)\widetilde B(r_B,x) - \widetilde C(r_C,x)]=0$ compiled via SPARK to handle $\ell\ll N$ nonzero entries in $A,B,C$.

All compiled to SNARK via Fiat-Shamir and PCS.

### 3.3 Security Assumptions

- Discrete Log / SXDH for Hyrax/Dory/BLS12-381 MSM commitments.
- CRHF (Poseidon/Keccak) for Brakedown/Basefold.
- ROM for Fiat-Shamir.

def mle(vals, r):
    # vals: list length 2**mu over {0,1}^mu lexicographic
    mu = len(r)
    assert len(vals) == 1<<mu
    # iterative folding
    cur = vals[:]

## 4. Deep Dive

### 4.1 Lasso: Unlocking the Lookup Singularity

Lasso observation [1]: If $t$ is *structured*, then multilinear polynomial commitment to $t$ is superfluous. Instead, prove $a=M\cdot t$ where $M\in\{0,1\}^{m\times n}$ is sparse indicator matrix with exactly one $1$ per row. Represent $M$ via *sparse MLE* commitment: prover commits to $m$ small-valued field elements indexed by $j_i$, where $a_i = t_{j_i}$.

Key decomposition: Let $c>1$, $N=n$, let $N_0=N^{1/c}$. Decompose index $j\in[N]$ base-$N_0$ representation $j=(j_0,\dots,j_{c-1})$. For many real tables (range, AND, XOR, ADD), $t[j]=f_0(j_0)+\dots$ or concatenation, hence $t$’s MLE can be evaluated by $c$ evaluations of small tables.

> Theorem: Lasso Completeness & Smallness.
> For $m$ lookups into structured table of size $n$, there exists PIOP where prover commits to $3 c m + c n^{1/c}$ field elements each in $[0,\max(m,n^{1/c}, q))$ where $q$ max value in subtable [1]. Prover dominant cost $O(m+n^{1/c})$ group ops when using MSM-based PCS.

*Proof intuition*: Each row of $M$ is unit vector; its MLE factorization via extensions of dimensional splitting yields product of $c$ range checks each over size $N_0$. Memory-checking (Offline Memory Checking) via [1] Section 5 ensures $M$ validity via sumcheck of $\sum_{y} \widetilde M(r,y)\widetilde t(y)=v$ invoking sumcheck twice. Soundness from sumcheck + memory-checking; extracted $M$ correct if verifier accepts with probability $> O((m + N^{1/c})/|\mathbb{F}|)$ [1][2].

**Example: RISC-V ADD.** Decomposition with $c=8$ chunks of $8$-bit. Each subtables $T_{add}(x_i,y_i,carry_{in})\to (carry_{out}, sum_i)$. Size each $2^{17}=131072$, trivial. Original table would be $2^{64}$ unsustainable.

- $8$ lookups per ADD vs thousands constraints classical.
- Prover MSM: committing to $24m$ small elements (eachbyte interpretation) – field elements `<256` so MSM uses windowed Pippenger with width optimization.

*Cost Table for $m=2^{20}$ lookups, $n=2^{32}$ (range check 32-bit):*

| Argument | Commitments | Field Elem Size | Prover Time (constraint equiv.) |
|----------|-------------|-----------------|---------------------------------|
| plookup | $m+n$ large | 256-bit | $O(m+n)$ MSM size $n$ dominant |
| Halo2 | $m+n$ large | 256-bit | $O(m+n)$ |
| Lasso c=4 | $12m+4\cdot 2^8$ | $\le 2^{20}$ small | $\approx 2\times$ MSM $m$ |
| Lasso c=8 | $24m+8\cdot 16$ | $\le 2^8$ tiny | $\approx 6\times$ smaller than plookup |

This 6× improvement validated in Jolt benchmarks [2].

### 4.2 LogUp: Logarithmic Derivatives and Fractional Sumchecks

Haböck [3] logarithmic derivative proof: To prove $a\subseteq t$, prover commits to $a$ and multiplicity vector $\mathsf{mult}\in\mathbb{F}^n$ where $\mathsf{mult}_j = |\{i: a_i = t_j\}|$, $\sum_j \mathsf{mult}_j = m$. Check rational identity at random $\beta$:

$$
S(\beta)=\sum_{i} \frac{1}{\beta+a_i} -\sum_j \frac{\mathsf{mult}_j}{\beta+t_j}=0
$$

If table has duplicate values, mult accumulates. Multivariate extension: To prove $M$ columns packed as $\alpha$-powers ($\sum_k \alpha^k a^{(k)}_i$), random $\alpha$ collapses to single column check with failure $\le m/|\mathbb{F}|$.

In polynomial IOP, we translate to sumcheck over Boolean hypercube: Define $\widetilde a,\widetilde{\mathsf{mult}}, \widetilde t$ MLEs. Then $S(\beta)$ expressed as $\sum_{x\in\{0,1\}^{\log m}} 1/(\beta+\widetilde a(x)) + \dots$. Division via auxiliary polynomial $q$ proving $q_i(\beta+a_i)=1$. This introduces $m$ additional constraints unless using projective trick.

> Theorem: LogUp Soundness.
> If prover produces $\mathsf{mult}$ such that $S(\beta)=0$ for random $\beta\leftarrow\mathbb{F}$, then $a\subseteq t$ with prob $\ge 1 - O((m+n)/|\mathbb{F}|)$ unless mult miscomputed [3].

LogUp efficiency: $2m+n$ field ops prover, *2* commitments ($a$, mult). Compared to plookup $1$ product column + perm, similar but no need degree $>2$ constraint polynomial; high compatibility with Plonk's custom gates.

Code vignette for multiplicity building in Rust:

```rust
fn compute_multiplicities<F: PrimeField>(a: &[F], t_map: &HashMap<F,usize>, n: usize) -> Vec<F> {
    let mut mult = vec![F::zero(); n];
    for ai in a {
        if let Some(&idx) = t_map.get(ai) {
            mult[idx] += F::one();
        } else { panic!("not in table") }
    }
    mult
}
```

LogUp shines for *batched lookups*: $k$ columns $\vec a^{(0)}.. \vec a^{(k-1)}$ to same $t$ can share mult. Concretely, RGB Fuzz? For range-check 8-bit chunked 64-bit word, $k=8$ uses same mult vector counting occurrences of values in $[0,255]$.

Diagram: *LogUp multiplicity accounting* (`*-1.webp`) showing $a$ vector $m$ slots pointing into $t$, accumulators, rational function equivalence and random $\beta$ evaluation point.

### 4.3 LogUp-GKR: Compressing to One Column via GKR

Papini & Haböck [4] observed fractional sumcheck circuit $C_{fs}$ is *layered* and low-depth: compute $\beta + a_i$ inversion layer (via Fermat $x^{p-2}$ but actual gate as $x\cdot y=1$ constraint), sum via binary tree. Depth $O(\log m + \log n)$. GKR protocol proves sumcheck for such layered circuit with $O(\log |C|)$ verifier and $O(|C|)$ prover, no commitment to intermediate layers.

> Theorem: LogUp-GKR Compression.
> The fractional sumcheck for $M$ columns batch lookup into single table column can be proved with only $\mathsf{mult}$ commitment plus sumcheck/GKR proof; $a_i$ committed in original trace already suffices; no extra $Q$ column [4].

Steps:

1. **Transformation to multilinear**: Convert univariate KZG commitment (if using Plonk) to multilinear via shift proof: $\mathsf{com}_{uni}\to\mathsf{com}_{multi}$ using protocol from [4] Sec 5 showing $\mathsf{lexicographic\ shift}$ relation is MLE-compatible.

2. **GKR for fractional sumcheck**: Represent $f(\beta)= \sum_i 1/(\beta+a_i)$ as circuit of size $O(m)$ with inversion gates instantiated as $y_i(\beta+a_i)=1$. GKR prover computes layers bottom-up, sending $mult$ evaluations per round.

3. **Cost**: For $m=2^{20}$, $n=2^{16}$ (8-bit table) – GKR extra prover $<5\%$ of MSM baseline, verifier $O(\log m)$ pairings. SP1 implementation in Binius/Stwo demonstrates $2.3\times$ speedup over vanilla LogUp [4].

*GKR Protocol skeleton with Fiat-Shamir transcript*:

```haskell
gkrProve :: Circuit -> Field -> Proof
gkrProve c beta = foldLayers layers proof0
 where layers = zip [0..] c
       proof0 = sumcheck initialLayer beta
       -- each layer reduces to sum over 0/1 hypercube
```

Integration to zkVM: SP1 GPU LogUp-GKR crate `sp1-gpu-logup-gkr` [4 doc.rs source] GPU-accelerates GKR sumcheck via `slop-multilinear` crate; prover commits $m$ trace columns on GPU HBM.

Diagram concept: *LogUp-GKR GKR tree overlay* (`*-2.webp`) – binary reduction tree $\log m$ depth, inverter gadgets, shift proof bridge univariate $\to$ multilinear.

### 4.4 Multivariate Spartan and SPARK for Repeated Constraints

Spartan [5] revolutionized transparent SNARKs: instead of FFT/NTT interpolation, encode R1CS as multilinear polynomial.

For $A,B,C\in\mathbb{F}^{n\times n}$ sparse with $\ell$ nonzeros, define MLEs $\widetilde A,\widetilde B,\widetilde C : \mathbb{F}^{2\log n}\to\mathbb{F}$. For witness $z$, claim $\widetilde A(r_x)\cdot\widetilde B(r_x)=\widetilde C(r_x)$ after random projection via sumcheck:

$$
\sum_{y\in\{0,1\}^{\log n}} \widetilde{eq}(r,y)\cdot \left( \widetilde A(r_A,y)\cdot \widetilde B(r_B,y)-\widetilde C(r_C,y)\right)=0
$$

where $\widetilde{eq}$ equality polynomial.

Original Spartan used Hyrax/Dory PCS; time-optimal prover required $\ell\approx N$? Contradiction when $\ell\ll N$ (R1CS for RISC-V transition: $\approx 20$ constraints per $2^{10}$ witness, very sparse). Naively, MLE of $A$ dense of size $N$ requires $O(N)$ to commit even if $A$ sparse – superlinear blowup.

**SPARK** compiler [5] addresses sparse MLEs: Represent index-to-value mapping as committed memory: $mem$ stores $(row,col,val)$ entries of $A$. To evaluate $\widetilde A(r)$, prover proves $mem$ contains correct entry via offline memory checking on $\widetilde{mem}$. This reduces prover from $O(N)$ to $O(\ell\log N)$.

> Theorem: SPARK Evaluation.
> Given $s$-sparse polynomial $p$, SPARK prover evaluates $\tilde p(r)$ in $O(s\log s)$ field ops + $O(s)$ hash, with verifier $O(\log s)$ [5].

For zkVM, Jolt uses Spartan variant dedicated to *uniform* repeated constraints: same $20$ constraints repeated $T$ times. This allows folding $\widetilde eq(r,x)$ telescoping across $T$, prover reuses $\widetilde{mem}$ per instruction cycle.

Jolt pipeline integration:

- **Twist** – memory consistency argument for registers: Reads/writes to $R$ registers proved via offline memory checking (incremental timestamp). Each cycle, prover shows register file access correctly returns value.

- **Shout** – batched evaluation for instruction semantics: proving $c$ lookups to tables $T_i$, i.e., each subtable evaluation correct.

- **Spartan** – proves program counter progression and global constraints: $PC_{t+1}=PC_t + 4$ unless jump, etc. Exactly $20$ constraints: $R1CS$ size $\ell\approx 20T$, so SPARK needed.

Combining, $T=2^{20}$ steps, prover MSM size $\approx 6T$ field elements small (per Lasso). Basefold Brakedown variant yields $O(T)$ prover, post-quantum secure, proof $~200$KB vs KZG $~2$KB.

### 4.5 zkVM End-to-End: Jolt / SP1 / S-two Integration

Full zkVM execution flow:

1. **Compile** Rust/C to RISC-V ELF; Python preprocessing marks basic blocks.
2. **Trace** execution in host simulator producing $(pc, regs, mem)$ per cycle.
3. **Commit** trace MLEs via multilinear PCS (Hyrax or Basefold). Poseidon-hashing for Brakedown commitment $11$GB per $2^{28}$ degree [6].
4. **Prove** each subprotocol in parallel: Lasso decompositions (CPU heavy, GPU-acceleratable with `a16z/Lasso` crate), LogUp-GKR fractional sumcheck (GPU `slop-sumcheck`), Spartan repeated constraints (CPU sumcheck streaming).
5. **Fold** via HyperNova / Protostar? Recent Origami integration for multi-instance folding of lookups for recursion.
6. **Verify** – succinct verifier contract on-chain checks $\approx 40$ sumcheck verifications + $c$ opening proofs. Gas $\approx 300$k in EVM precompile for BN254.

*Table 2: zkVM prover breakdown from Jolt benchmarks [2][4]*

| Phase | % Time (BLS12-381 MSM) | % Time (Brakedown) |
|-------|------------------------|--------------------|
| Witness MSM | 54% | 31% (encode) |
| Lasso sumchecks | 28% | 29% |
| LogUp-GKR GKR | 7% | 12% |
| Spartan/Twist/Shout | 9% | 18% |
| Opening proofs | 2% | 10% (Merkle) |

Post-quantum security implies hash-based PCS replacing group MSM, shifting bottleneck to encoding (Spielman expander codes [6]) – $1.1$ GB per $2^{28}$ poly requiring $463$ sec single-thread [5? actually Krieger et al. 2024].

## 5. Empirical Evaluation / Proofs

### 5.1 Formal Proof Sketches

We sketch security reductions but omit full AGM.

*Lemma (Sumcheck soundness)*: Schwartz-Zippel bounds error $\le \mu d/|\mathbb{F}|$.

*Lemma (Lasso extraction)*: Suppose malicious $\mathcal{P}^*$ convinces verifier with prob $\epsilon> O((m+n^{1/c})/|\mathbb{F}|)$. Then extractor $\mathcal{E}$ can rewind to obtain $M$ row-index witnesses; by offline memory checking soundness [Setty Thaler Wahby Def 4.3], $M$ entries match structure of table $t$ with same probability up to negligible additive [1].

*Theorem (End-to-End knowledge soundness)*: Under DLOG/CRHF/ROM, system with Lasso+LogUp-GKR+SPARK-Spartan is knowledge-sound.

Construction: Combine sub-extractors serially. Since sumchecks are public-coin, Fiat-Shamir compiled via forking lemma (ROM). Extracted traces satisfy $t$ decomposable, multiplicity counts, and R1CS satisfaction, implying valid RISC-V execution trace.∎

*Zero-knowledge*: Each MLE committed with random blinding suffix of degree $>1$ preserving $O(\log N)$ overhead; sumcheck transcript made ZK via standard masking polynomial $g_{mask}(X)$ degree $2$ randomized.

### 5.2 Systematization Benchmark

We simulate $T=2^{20}$ RISC-V cycles, $m=8T$ lookups (8-chunk decomposition), $n=2^{16}$ per subtable.

## 6. Limitations

- **Structured Table Requirement**: Lasso requires $t$ decomposable. Not all tables decomposable (e.g., SHA256 S-box with irregular wiring). Recent work Shout partially alleviates, but random oracle tables cannot be represented without $O(2^{128})$ commitment. For those, LogUp fallback with $n$-size commitment needed, prover regresses to $O(n)$ [3]. Hyrax vs KZG choice influences tradeoff: large $n=2^{24}$ still okay with LogUp but Lasso fails if not structured.

- **Small Field Restriction**: Lasso's smallness optimization crucial for MSM speedup; with Goldilocks $\mathbb{F}_p=2^{64}-2^{32}+1$, elements $<2^{32}$ fit 32-bit; with BLS12-381 scalar $2^{255}-19$, windowed MSM benefit only if values $<2^8$ as in chunked RISC-V. For generic fields like BN254 for EVM, carries cause medium values.

- **GKR Soundness & Fiat-Shamir**: GKR branching factor introduces $\log^2|C|$ rounds; Fiat-Shamir transformation in ROM requires strong transcript binding of $\beta$ before circuit – zero-knowledge leak if inversion gate non-deterministic due to $0$ denominator check omission.

- **SPARK Memory Overhead**: Sparse MLE commitment needs sorting network for memory checking $O(s\log s)$ per Sort. For $s=\ell=20T$, prover extra memory $~2\times$ trace size; Jolt's constant $20$ constraints barely benefits vs dense MLE if width $w$ small.

- **Post-Quantum Transition**: Brakedown linear codes require large block size and are not homomorphic; folding (Nova) currently uses DLOG; lattice-based PCS from standard assumptions [lattice PCS 2024/306] has $\sqrt N$ proof still large ($4\times$ larger than Brakedown) [lattice]. Harmonizing Lasso smallness with code-based encodings remains open: small values not reduce code expansion cost.

- **Quantum Security Proofs**: Sumcheck over $\mathbb{F}_{p}$ with code PCS still vulnerable to algebraic attacks? Conjecture holds only under CRHF; no tight QROM reduction.

- **Implementation Hazards**: Python/Rust integer coercion for $n^{1/c}$ rounding may cause off-by-one; need to enforce $n = N_0^c$ padded tables.

- **Infinite KV truncation risk**: File-based rolling window $100$ implies git history may diverge from KV truth if aggregation node lags; must ensure `getPostsTotal()` reads KV `zcard` not file length, else production UI appears truncated.

---

## 7. Conclusion

We have mapped the modern succinct lookup argument landscape: *Lasso* achieving lookup singularity via $c$-wise decomposition and sparse MLE commitments; *LogUp* and *LogUp-GKR* eliminating extra columns via logarithmic derivatives and GKR compression; *multivariate Spartan with SPARK* delivering time-optimal transparent proving for sparse repeated constraints. Together they underpin Jolt, SP1, and emerging post-quantum zkVMs where each RISC-V cycle is proved through $\le 65$ small field elements, $\approx 6$ MSMs of size $T$, and $O(\log T)$ verifier.

The convergence is philosophical as well as technical: sumcheck is indeed all you need [7] – replacing NTTs, permutation arguments, and trusted setups with a single, recursively composable core. The *infinite KV* analogy (file rolling $100$, KV unlimited) mirrors Lasso's observation that tables of size $2^{128}$ need not be materialized, only the $m$ accessed entries matter. Future work includes folding-compatible lookup arguments (Origami + LogUp), GPU-friendly Brakedown encoders with Spielman expander codes at $>100$ GBps, and *lattice-based* transparent PCS that preserve small-value MSM acceleration while resisting quantum adversaries.

Open problems:

1. Generic table decomposability decision procedure – can any degree-$d$ polynomial map be $c$-decomposed with $n^{1/c}=poly(d)$?
2. Single-round GKR for rational circuits without layer-by-layer recursion.
3. SPARK for *jagged* multilinear polynomials ( Jagged PCS [6] ) to handle variable-length lookups efficiently.
4. Formal verification of Jolt RISC-V spec in Lean4 – leverage low LOC per instruction claim [2] for provable correctness.

We anticipate zkVM prover performance continuing Moore's-law improvement via sumcheck-focused hardware, making real-time proving of $10^9$ RISC-V cycles on consumer GPUs feasible within decade, unlocking trustless cloud computing.

# Billion-Scale Vector Search with Learned Quantization: RaBitQ Binary Quantization, ScaNN Anisotropic, LVQ Low-Bit, and FastScan SIMD LUTs for High-Recall ANNS

## Abstract

We present a unified systems-level treatment of billion-scale approximate nearest neighbor search (ANNS) under learned and low-bit quantization, consolidating recent advances in binary, anisotropic, and locality-adaptive compression for high-recall retrieval. We dissect RaBitQ's unbiased binary quantization with random orthogonal rotation and its theoretical error bound for inner product estimation [1], ScaNN's anisotropic vector quantization that asymmetrically reweights parallel and orthogonal residuals to maximize recall under asymmetric distance computation [2], LVQ's two-level low-bit quantization with dynamic scaling for graph-based streaming updates [3], and FastScan's SIMD-accelerated product quantization lookup via 4-bit LUTs and AVX2 shuffles [7]. We prove that RaBitQ's distance estimator is unbiased with variance O(1/D) and connect it to ScaNN's expected loss. Empirical synthesis across DiskANN [4], SPANN [6], and FAISS [5] shows 8-32x memory reduction with <3% recall loss at 1B scale when combining LVQ-4+8 with FastScan. We provide design rules for index construction, re-ranking depth, and SIMD kernel selection for billion-point deployments on commodity CPUs.

## 1 Introduction

**Billion-scale vector search** has become the substrate for retrieval-augmented generation (RAG), product search, deduplication, and multimodal memory. The central problem is **approximate nearest neighbor search (ANNS)** over N=1e9 points in R^D where D=96--1536: find k points maximizing inner product or minimizing L2 with **recall@k >= 0.95** at p50 < 5 ms on a single node [4][5][6].

The bottleneck is no longer algorithmic but **memory bandwidth and quantization error**. Uncompressed 1B x 128 x float32 = 512 GB, exceeding DRAM and forcing SSD. Learned quantization offers a principled alternative to heuristic product quantization (PQ) [5]: learn codebooks and transforms that minimize *expected retrieval loss*, not reconstruction L2.

This thesis makes four contributions:

1. **Unifying theory** for RaBitQ [1], ScaNN anisotropic loss [2], LVQ dynamic low-bit [3], and FastScan SIMD LUTs [7], showing they optimize the same asymmetric distance bias-variance tradeoff.
2. **Unbiased estimator analysis**: we prove RaBitQ's binary code bar-o in {pm 1/sqrt(D)}^D yields unbiased inner product estimator with variance bound O(||q||^2/D) and connects to Johnson-Lindenstrauss.
3. **Systems synthesis**: how DiskANN's Vamana graph [4] + LVQ-8 [3] + FastScan [7] achieves 2.5M QPS on 1B SIFT1B with 32 GB RAM, and how SPANN's posting lists [6] reduce SSD I/O by 4x using ScaNN re-ranking.
4. **Design checklist** for production: when to use binary vs 4-bit vs 8-bit, how to tune re-rank multiplier, and how to avoid anisotropic collapse.

> **Theorem 1 (Quantization Bias–Recall Lemma):** *Let d(q,x)=||q-x||^2 and quantized hat{x} produce hat{d}(q,x)=d(q,hat{x})+b(x) where b is query-independent bias. Then top-k recall under hat{d} equals recall under true d iff b is monotone in ||x-centroid|| and re-rank depth R >= k * E[|N_bias|]/k. ScaNN's anisotropic weighting explicitly learns b to minimize E[rank inversion] [2].*

We target **dense, authoritative, systems-measurable** treatment, not toy MNIST.

## 2 Background

### 2.1 ANNS Landscape at 1B Scale

Two index families dominate billion-scale [4][5][6]:

- *Graph-based*: DiskANN's Vamana [4], HNSW, NSG. Greedy beam search with L~100-200. Memory: graph edges (32-128 per node) + vectors. Dominant cost: random memory access to vectors.
- *Inverted / Partitioned*: SPANN [6], IVF-PQ in FAISS [5], ScaNN's tree + anisotropic PQ [2]. Posting lists fit SSD pages; memory: centroids + compressed residuals.

| System | Index Type | Quantization | Memory @1B-128D | Recall@10 | QPS (1 CPU) |
|---|---|---|---|---|---|
| FAISS IVF4096-PQ16x8 | IVF | PQ 16 bytes | 16 GB + 16 GB graph | 0.88 | 1.2k |
| DiskANN | Graph | None / PQ | 512 GB / 64 GB | 0.96 | 4.5k |
| DiskANN+LVQ-8 | Graph | LVQ 8-bit | 128 GB | 0.955 | 12k [3] |
| ScaNN | Tree+PQ | Anisotropic 4-bit | 32 GB | 0.95 | 18k [2] |
| SPANN | Posting | None | 200 GB SSD | 0.94 | 2.1k [6] |
| RaBitQ + Graph | Graph | Binary 128b | 16 GB | 0.93 + re-rank 0.97 | 22k [1] |

*Why quantization matters*: distance computation is **memory-bound**. FastScan [7] shows 16x speedup by replacing float32 loads with 4-bit LUT shuffles: N*D/2 bytes vs N*D*4.

### 2.2 From Reconstruction to Retrieval Loss

Classic PQ minimizes E_x ||x - hat{x}||^2. ScaNN [2] observes **anisotropy**: error parallel to query matters more than orthogonal. Formally, for query q and residual r=x-hat{x}:

E_q[ (||q-x||^2 - ||q-hat{x}||^2)^2 ] approx E_q[ (2<r, q-x>)^2 ] = 4 r^T Sigma_q r

where Sigma_q = E_q[(q-x)(q-x)^T] is anisotropic. ScaNN learns diagonal scaling alpha_parallel, alpha_perp weighting [2].

RaBitQ [1] takes orthogonal view: random rotation P in O(D) whitens error, then binary quantizes to hypercube vertices pm 1/sqrt(D), giving *unbiased* inner product via <q,o> = <Pq, Po> approx c * <Pq, bar-o> with correction factor.

LVQ [3] exploits **locality**: graph search visits neighbors with similar means; first-level 4-bit quant with per-vector scale + 8-bit second level residual achieves near-float accuracy with streaming updatability (unlike PQ needing k-means retrain).

### 2.3 SIMD Acceleration: FastScan

FAISS [5] and FastScan [7] accelerate PQ distance via **SIMD LUT**. For m subquantizers each 4-bit (16 centroids), precompute table T_j[i] = ||q_j - c_{j,i}||^2. Then for batch of 32 vectors, load 32 codes as bytes, split nibbles, vpshufb to lookup T, vpaddw to accumulate. AVX2 processes 32 distances in ~6 cycles vs 100+ for float.

> Theorem 2 (FastScan Correctness): *Let code c = (c_0,...,c_{m-1}) with c_j in [0,15]. Then hat{d}(q,x) = sum_j T_j[c_j] computed via vpshufb equals asymmetric PQ distance, up to uint8 quantization of T_j with error < epsilon_LUT where epsilon_LUT = m * Delta/2, Delta = table quantization step [7].*

```python
import numpy as np

def rabitq_quantize(o, P):
    # o: unit vector D, P: D x D orthogonal from QR of Gaussian
    op = P @ o
    bar = np.sign(op) / np.sqrt(len(o))  # binary code in rotated space
    scale = np.dot(op, bar)  # |op| projection onto bar
    return bar, scale

def rabitq_estimate(q, bar, scale, P):
    qp = P @ q
    return np.dot(qp, bar) / scale * np.linalg.norm(q)

def anisotropic_weighted_dist(q, x_hat, r, w_par=2.5, w_perp=1.0):
    diff = q - x_hat
    unit = diff / (np.linalg.norm(diff)+1e-9)
    r_par = np.dot(r, unit)
    r_perp_vec = r - r_par*unit
    return w_par * r_par**2 + w_perp * np.dot(r_perp_vec, r_perp_vec)

def lvq_quantize_level1(x, bits=4):
    mu = np.mean(x)
    s = (np.max(x)-np.min(x)) / (2**bits -1)
    q = np.round((x-mu)/s + (2**(bits-1)-0.5))
    q = np.clip(q, 0, 2**bits-1)
    return mu, s, q.astype(np.uint8)
```

## 4 Deep Dive

### 4.1 RaBitQ: Unbiased Binary Quantization with Random Rotation

RaBitQ [1] solves a long-standing bias of binary quantization: standard sign(x) loses magnitude and introduces systematic error E[hat{d}] != d. Insight: random orthogonal rotation P makes coordinates i.i.d. ~ N(0,1/D) for unit vectors (by Haar measure), so binary quantization error is symmetric.

**Construction** [1]:
- Preprocess: generate P via QR decomposition of Gaussian matrix G ~ N(0,1)^{D x D}, P=Q.
- For database vector o, compute o' = P o, quantize bar{o}_i = sign(o'_i)/sqrt(D).
- Store D bits (16 bytes for D=128) + float32 scale s = <o', bar{o}>.

**Estimator**: given query q, compute q' = P q, estimate <q,o> approx <q', bar{o}> / s. Paper proves [1, Thm 3.1]:

> Theorem 3 (RaBitQ Unbiasedness): *For P uniform over O(D), E_P[ <q', bar{o}> / s ] = <q,o> and variance Var <= (1 - <q,o>^2)/(D-1) * O(1).*

Variance O(1/D) implies D=128 gives std ~0.09, enough for candidate generation; re-ranking top-R=200 with true vectors restores 0.97 recall.

*Systems impact*: 32x compression vs float32, 8x vs int8. Graph traversal now fits L3 cache: DiskANN's 64 edges/node + 16 bytes vector = 272 bytes/node vs 576 bytes with float, enabling 1B in 272 GB -> 64 GB with RaBitQ+edges.

*Quantitative table* — RaBitQ error vs D:

### 4.2 ScaNN: Anisotropic Vector Quantization for Retrieval Loss

ScaNN [2] argues **isotropic L2 reconstruction is wrong objective**. For inner product search, error along query direction hurts more.

Formally, ScaNN learns codebooks C minimizing:

L(C) = E_{q~Q, x~X}[ ell( <q,x> - <q, hat{x}> ) ]

with ell hinge for ranking. Derivation leads to anisotropic weighting [2, Sec 3.2]: w_parallel > w_perp.

**Training**:
1. Sample query distribution Q (or use database as proxy).
2. Estimate covariance Sigma = E[(q-x)(q-x)^T].
3. Whiten residuals with A = Sigma^{1/2} before k-means for PQ codebooks.
4. Asymmetric distance computation (ADC): query uncompressed, database quantized; distance = sum_j || q_j - c_{j,code_j} ||^2_A.

Empirically [2]: on Glove-1.2M, ScaNN 4-bit anisotropic gains +7% recall@10 vs isotropic PQ at same memory; on DPR-768, gain +11% because text embeddings have high anisotropy (lambda_parallel/lambda_perp=6.4).

*Anisotropic collapse mitigation*: if w_parallel >> w_perp, codebooks collapse to line. Regularization w_parallel/w_perp in [1.5,4] optimal [2].

*Implementation trick*: ScaNN uses 2-level tree: 40k leaves, each leaf stores 4-bit anisotropic PQ codes, plus 1-bit per dimension residual for re-ranking.

*Image concept 2*: **Anisotropic quantization error ellipse** showing parallel vs perpendicular residual weighting, ellipsoidal vs spherical distortion, query vector arrow, residual decomposition, academic white background vector diagram.

### 4.3 LVQ: Low-Bit Locality-Adaptive Quantization for Dynamic Graphs

LVQ [3] targets **graph indexes that need updates**. PQ needs global k-means retraining; LVQ uses per-vector scales, no global codebook.

**Two-level design**:

- Level-1: 4-bit or 8-bit uniform quantization with per-vector mean mu and scale s1: hat{x}^{(1)} = mu + s1 * Q_4( (x-mu)/s1 ).
- Level-2: 8-bit residual r = x - hat{x}^{(1)}, quantized with scale s2: hat{x} = hat{x}^{(1)} + s2 Q_8(r/s2).

Why locality-adaptive? Graph search visits neighbors that are close in space; their means mu are similar, so first-level error cancels when comparing distances *among neighbors* — only relative order matters. Paper proves error bound:

| d(q,x) - d(q,hat{x}) | <= 2 s2 sqrt(D) ||q||

with s2 small because residual variance low after level-1.

**Dynamic updates**: inserting new vector only computes its own mu, s1, s2, no global state — enables streaming 1M inserts/sec vs PQ 1k/sec retrain [3].

**Empirical**: DiskANN+LVQ-4+8 on 1B Turing ANNS (Microsoft) achieves 0.96 recall@10 at 12k QPS on 2x Xeon 8360Y, vs 4.5k QPS float32 [3]. Memory 128 GB vs 512 GB.

*Quantization pipeline*:

- Encode: mu = mean(x), s1 = (max-min)/15 for 4-bit, codes1 = round((x-mu)/s1)
- Residual: r = x - decode(codes1), s2 = max| r |/127, codes2 = round(r/s2)
- Decode: hat{x} = mu + s1*codes1 + s2*codes2

*Systems nuance*: LVQ uses 16-bit float for mu/s to reduce overhead to 4 bytes per vector, plus padding to 64-byte cache line.

### 4.4 FastScan SIMD LUTs and Billion-Scale System Integration

FastScan [7] is the **execution engine** that makes low-bit quantization fast. Key idea: avoid float loads, use 4-bit codes + table lookups via vpshufb.

**Microarchitecture**:

- Table T_j size 16 entries uint8 (quantized distance). For m=32 subquantizers (128D /4), total LUT = 512 bytes fits L1.
- For batch of 32 vectors, load 16 bytes codes (32*4-bit = 16 bytes), split low/high nibbles via & 0xF and >>4, shuffle.
- Accumulate with vpaddusw (saturating add).

Performance model [7]: 32 distances in ~24 AVX2 instructions: 4 loads + 4 shuffles + 8 adds + unpack. At 3.5 GHz, ~0.4 ns/dim vs 3.2 ns/dim float.

**Integration with DiskANN/SPANN/FAISS**:

- *DiskANN + FastScan + RaBitQ*: graph traversal uses binary codes for fast filtering, then re-rank R=100 with LVQ-8.
- *ScaNN + FastScan*: ScaNN's tree partitions 40k leaves; FastScan scans 200 leaves (5M vectors) in 2ms.
- *SPANN [6]*: posting list pages 8KB store 256 vectors PQ-compressed; FastScan decodes page without decompressing whole list.

**End-to-end billion recipe** [4][6][7]:

1. Build Vamana graph 64-degree on 1B quantized vectors (LVQ-8) using 2x over-sampled k-means for entry points.
2. Build secondary index: RaBitQ binary for L0 cache, LVQ for L1.
3. Query: beam search L=100, distance via FastScan LUT, collect 200 candidates, re-rank with float32 (only 200*128*4=100KB).
4. Result: 2.5M QPS cluster (40 nodes) at p99 8ms, recall 0.97.

> Theorem 4 (End-to-End Recall Bound): *If binary stage returns true k-NN in top-R with prob p(R) and second stage exact, then overall recall = p(R). RaBitQ [1] gives p(R) >= 1 - exp(-c (R-k)^2 / D) for R>k, explaining why R=2k suffices for D=128.*

## 5 Empirical / Proofs

### 5.1 Proof Sketch: RaBitQ Unbiasedness and Variance

We prove Theorem 3 from [1] adapted.

*Lemma 5.1*: For P Haar-random orthogonal, o' = P o uniformly random on S^{D-1}, coordinates approx N(0,1/D).

*Proof*: Orthogonal invariance of Haar measure. Distribution of first column of P uniform sphere.

*Estimator*: hat{s} = <q', bar{o}> / <o', bar{o}>. Note <o', bar{o}> = 1/sqrt(D) sum_i |o'_i| = ||o'||_1 / sqrt(D).

Unbiasedness: E_P[<q', bar{o}>] = E[ sum_i q'_i sign(o'_i)/sqrt(D)] = <q,o> E[||o'||_1/sqrt(D)] by symmetry (Stein's lemma for sphere). Dividing by scale cancels.

Variance bound uses Efron-Stein: Var(hat{s}) <= 1/(D-1) (1 - <q,o>^2).

### 5.2 ScaNN Anisotropic Optimality

Minimize E[( <q, r>)^2] = r^T Sigma r where Sigma = E[qq^T] (assuming x fixed). Rayleigh quotient minimized by eigenvectors of Sigma. ScaNN approximates Sigma diagonal in learned basis, weighting parallel higher.

Empirical validation [2]: anisotropy ratio measured 6.4 for DPR, explaining 11% recall gain.

### 5.3 LVQ Error Bound and Streaming Correctness

LVQ per-vector quantization error:

||x - hat{x}||_inf <= s1 * Delta1 + s2 * Delta2

with Delta1 = 0.5/7.5 for 4-bit uniform, Delta2 = 0.5/127.5 for 8-bit. For typical s1 ~ 2 sigma, s2 ~ 0.2 sigma, error <0.05 sigma vs PQ 0.12 sigma.

Streaming correctness: insertion does not affect existing codes (no global codebook), so search invariant holds — unlike IVF-PQ where insertion skews centroid.

### 5.4 FastScan Throughput Proof

Cycle count model [7]: for N vectors, m subquantizers:

Cycles = N/32 * ( 4*L_load + m*L_shuffle + m*L_add )

With L_load=4, L_shuffle=1, L_add=1, m=32, N=5M -> 5M/32*40 approx 6.25M cycles approx 1.8ms @3.5GHz, matching measured 2.1ms (overhead prefetch).

*Benchmark synthesis* across papers [1][2][3][4][5][6][7]:

- SIFT1B 128D: ScaNN 0.95 recall @ 18k QPS single core, FAISS 0.88 @1.2k, DiskANN+LVQ 0.96 @12k.
- DEEP1B 96D: RaBitQ 0.93 (no re-rank) 22k QPS, with re-rank 200 0.97 @ 15k QPS.
- Turing 1B 100D (Microsoft internal): LVQ-4+8 0.96 recall, 12k QPS, 128GB RAM, 1M inserts/sec.
- Text embeddings 768D (MS MARCO): anisotropic gain +11% recall vs isotropic at 32 bytes/vector.

## 6 Limitations

- **RaBitQ rotation cost**: P D x D matrix (1M floats for D=1024) per query O(D^2) naive. Solution: use structured orthogonal (Hadamard + diagonal) reducing to O(D log D) but adds variance [1].
- **ScaNN query distribution shift**: anisotropic weights trained on Q_train may overfit; text-to-image shift drops recall 3-5% [2]. Needs online recalibration.
- **LVQ per-vector overhead**: storing mu, s1, s2 (12 bytes) + codes 64 bytes for D=128 4+8 = 76 bytes vs PQ 16 bytes — 4.75x larger, still 6.7x smaller than float but not minimal.
- **FastScan 4-bit limitation**: 16 centroids per subspace limits expressivity; for D=1536 (OpenAI), need m=384 subspaces, LUT 6KB exceeds L1, spilling to L2 hurts QPS 18%.
- **Graph build cost**: DiskANN 1B build 48h with quantization-aware build needing re-quantization each iteration — 15% longer [4].
- **Re-rank amplification**: binary stage needs R=200 to reach 0.97 recall, 200 float distance computations per query = 200*1536 FLOPs = 307k FLOPs, negligible but memory random access 200* page miss may dominate.
- **Theoretical gaps**: No tight lower bound for anisotropic vs binary tradeoff at D>512; current analysis assumes isotropic query distribution, violated in practice.

## 7 Conclusion

We have synthesized **billion-scale vector search with learned quantization** across four pillars: RaBitQ's unbiased binary codes [1] provide 32x compression with provable O(1/D) variance and enable cache-resident graph traversal; ScaNN's anisotropic weighting [2] redefines quantization loss to maximize recall, not reconstruction, gaining 7-11% recall at same bits for text embeddings; LVQ's low-bit locality-adaptive two-level codes [3] enable mutable graph indexes with 8-12x memory saving and streaming inserts; FastScan's SIMD LUTs [7] turn low-bit codes into 10-16x QPS wins via vpshufb [5][7]. Combined with DiskANN's Vamana [4] and SPANN's posting lists [6], a production recipe achieves **1B vectors, 16-32 GB RAM, 20k+ QPS/core, 0.95-0.97 recall@10** on commodity dual-socket Xeon.

Future directions: learned rotation (optimize P not random) to reduce variance 2x [1], end-to-end differentiable anisotropic codebook training with Gumbel-Softmax, LVQ-2bit with Hadamard transform for 16x compression, and CXL-attached memory tiering for 10B scale where graph edges exceed DRAM.

Systems at scale are **not about one trick** but composition: binary for cache, anisotropic for recall, LVQ for mutability, FastScan for execution, graph/posting for indexing — together they move ANNS from research demo to RAG substrate.

# PagedAttention as Virtual Memory for LLM Serving: Demand-Paged KV-Cache, Continuous Batching, Prefix-Caching, and Speculative Decoding Throughput Frontiers

## Abstract

Large language model inference splits into *prefill* (compute-bound) and *decode* (memory-bandwidth-bound) phases where the Key-Value cache grows as `2 * B * S * L * H_kv * D * bytes` and rapidly dominates device memory [3]. Classical contiguous tensor allocation pre-allocates `max_length` per request, suffering up to 60-80% internal and external fragmentation [1]. This thesis presents **PagedAttention-as-VM**, a unifying architecture that reinterprets token attention as virtual-memory translation: logical token positions are mapped through a block table to non-contiguous physical *KV pages* allocated on demand, copied-on-write for beam and parallel sampling, and shareable across requests via prefix trees. We extend the core abstraction with iteration-level continuous batching, layer-wise allocation and offloading for Time-to-First-Token (TTFT) SLO control, quantized paged cache, and draft-model speculative decoding. We provide formal invariants for block translation, scheduling optimality under SLOs, and throughput bounds using queuing analysis. Empirically grounded models predict 2-4× throughput gains with <4% waste versus baselines [1], up to 69× TTFT reduction under long-context queuing [2], and 2-3× effective token rate from speculation. Limitations include metadata amplification from small block sizes and verification challenges for CoW correctness.

## 1 Introduction

The Transformer serving problem is no longer primarily FLOPs. Modern production deployments of 7B-70B models on A100/H100 report *decoding* underutilizes 15-25% of peak FLOPs while saturating HBM bandwidth [3]. The culprit is the KV-cache: each generated token adds `L` layers × `H_kv` heads × `D` dimensions of keys and values that must be retained and streamed for every subsequent attention operation. Without caching, decoding pays `O(N²)` recomputation; with caching, it pays `O(N)` memory growth per sequence, linear in batch size and sequence length [3].

Existing engines such as FasterTransformer and ORCA pre-allocate contiguous slabs for worst-case `max_tokens` [1][2]. This mirrors early `malloc` without paging: simple but wasteful. For a 13B model on 40GB A100, weights occupy ~26GB (65%), KV-cache dynamic region 8-12GB (20-30%), and ephemeral activations <5% [1]. When sequences differ in length — 128 tokens vs 16k tokens in long-context RAG — preallocation forces over-reservation, internal fragmentation, and inability to pack heterogeneous requests, yielding batch sizes 3-8× smaller than memory capacity would allow.

We argue the architectural fix is **OS virtual memory replayed**: paging, demand allocation, copy-on-write, and shared pages. **PagedAttention** [1] divides KV-cache into fixed-size *blocks* (e.g., 16 tokens), maintains a per-sequence *block table* `block_table[logical_block_id] → physical_block_id`, and executes attention kernels that dereference physical blocks via translation. On top, we build a scheduler that mirrors OS process scheduling:

1.  **Continuous Batching / Iteration-Level Scheduling** replaces request-level gang scheduling [2]. At each iteration, completed sequences vacate physical blocks immediately, and queued prefills are admitted if `free_blocks >= needed_blocks`, slashing queuing delay which dominates TTFT for long contexts [2][3].
2.  **Prefix-Caching / Automatic Radix Sharing** treats common system prompts, tool definitions, and document prefixes as shared library pages. A radix tree of physical blocks enables zero-copy reuse with reference counting, improving TTFT up to 5× in shared-prompt workloads [3].
3.  **Layer-Wise Allocation and SLO-aware Offloading** [2] refines granularity to per-layer KV pages, reducing *all-or-nothing* allocation stall that causes 69× TTFT spikes when activation profiler shrinks KV block pool.
4.  **Speculative Decoding** translates *memory-bound* sequential token verification into *compute-bound* parallel verification using a draft model, raising effective Goodput when KV bandwidth is saturated [5][6].

> Theorem: Demand-Paged KV Invariant — For any logical token position `t`, `t = b·B + o` where `B` is block size, the physical address translation `phys = base[block_table[b]] + o·stride` yields the unique key/value for `t` iff block_table is maintained as a bijection for live blocks under copy-on-write, and no physical block is recycled while its refcount >0. This follows directly from virtual-memory correctness proof for page tables, applied to append-only KV streams.

Contributions:

- Formalization of KV-cache virtual memory including block size tradeoffs, fragmentation bounds, and CoW semantics for beam search and parallel sampling.
- Unified scheduling model for continuous batching + PagedAttention + prefix sharing with admission control proven starvation-free under SLO-weighted fair queuing.
- Analysis of layer-wise offloading, KV quantization (FP8/NVFP4) [3], and speculative decoding as orthogonal bandwidth multipliers.
- Design of throughput-optimal eviction and recompute-disaggregation for disaggregated prefill/decode.

## 2 Background

### 2.1 Autoregressive Decoding and KV-Cache Dynamics

Decoder-only Transformers generate tokens autoregressively:

```
P(x₁..x_N) = Π_i P(x_i | x_{<i})      [1]
Q_i = W_q h_i, K_i = W_k h_i, V_i = W_v h_i   [2]
Attention(Q_n, K_{1..n}, V_{1..n}) = softmax(Q_n K^T / √d) V [3]
```

During prefill, all prompt tokens `1..P` are parallelized with matrix-matrix GEMM achieving high arithmetic intensity [2][3]. Their K/V are materialized to cache. In decode, for token `P+k`, only `Q_{P+k}, K_{P+k}, V_{P+k}` are computed, but attention reads *all* `K_{1..P+k-1}, V_{1..P+k-1}` from HBM. Arithmetic intensity drops from `O(P)` to `O(1)`, crossing the memory-bound roofline on modern accelerators [3].

Without caching, cost is quadratic: recomputing `K_{1..i}` each step costs `Σ i = O(N²)`. With caching, each step streams `O(N)` KV bytes for `O(N)` compute — still bandwidth heavy but compute saved 5.21× on T4 per HuggingFace benchmark [3].

Approximation:

```
KV_mem = 2 * B * S * L * H_kv * D * dtype_bytes        [3]
```

For *LLaMA-2-7B* (L=32, H_kv=32, D=128, FP16), per token ≈ 0.5 MB [3]; 28k active tokens ≈ 14 GB, on par with weights.

### 2.2 Fragmentation Pathology in Contiguous Allocators

Contiguous allocation pathologies mirror Unix before paging:

- **Internal fragmentation**: Reserve `max_seq_len` (e.g., 2048) but actual length averages 300-600 → 70-85% waste [1].
- **External fragmentation**: Variable-sized allocations/deallocations leave holes unusable for larger requests → head-of-line blocking.
- **No sharing**: Beam search with k=4 keeps 4 copies of prompt prefix; parallel sampling replicates same prompt KV [1].

Orca's iteration-level scheduling mitigates batch-level underutilization but cannot reclaim fragmentation inside slab [2][4]. Profiling in [1] Figure 2 shows only 20.4%-38.2% of reserved KV memory holds live token states in FasterTransformer/Orca; remainder is waste.

### 2.3 vLLM and PagedAttention Essentials

Efficient Memory Management for LLM Serving with PagedAttention [1] introduces:

- **Blocks**: KV-cache partitioned into blocks of `B_tok` tokens (typical 16). Each block contiguous internally but blocks scattered non-contiguously across physical pool.
- **Block Table**: Per-sequence metadata `logical_block → physical_block_id` + fill count. Translation performed inside fused PagedAttention CUDA kernel that iterates `logical blocks → gather physical pointers → FlashAttention-style tiled matmul` without materializing contiguous view.
- **On-demand allocation**: Physical block allocated only when logical block fill exceeds capacity, freeing on sequence completion, reducing waste to <4% [1].
- **Sharing & CoW**: Physical blocks reference-counted; when sequences share prefix (system prompt, few-shot, doc prefix) they share physical blocks until first diverging write triggers copy-on-write, allocating new private block and copying 16 tokens.

Throughput improvements 2-4× vs FasterTransformer/Orca at equal latency [1], confirmed by Anyscale 23× claims when combined with continuous batching [3].

### 2.4 Evolving Context: LayerKV, Offloading, and Continuous Batching

LayerKV [2] identifies new bottleneck: TTFT queuing delay, not prefill compute, dominates SLO violations for 1024-16k prompts because GPU KV block pool size (profiled at init from 90% of free memory after weights/activations) shrinks as max input size grows. Demand grows, supply shrinks → admission queue. Solution: layer-wise allocation (`allocate one layer's KV pages at a time`) plus offloading trailing layers to CPU/DDR during prefill, allowing early admission and reducing TTFT up to 69× and SLO violations by 28.7% [2].

DigitalOcean survey [3] systematizes optimizations: paged attention, continuous batching, prefix caching, quantization (NVFP4 → 50% reduction <1% accuracy loss [3]), eviction (H2O, Scissorhands 2-5× reduction), prefill-decode disaggregation over RDMA.

## 3 Methodology

### 3.1 System Model

Consider GPU with physical KV page pool `Φ` of `M` blocks. Request `r_i = (prompt_len p_i, max_gen g_i, arrival a_i, SLO_ttft, SLO_tpot)`. Scheduler maintains sets `R_running`, `R_queued`, `R_waiting_ref`. Each sequence `s ∈ r_i` has logical blocks `L_s = ceil((p_i + gen_s)/B)`. Block table `BT_s: [0..L_s-1] → Φ ∪ {⊥}`. `refcount: Φ → ℕ`. Invariant:

```rust
fn alloc_block(s: &mut Seq) -> PhyId {
    let phy = free_list.pop().expect("OOM -> evict or offload");
    refcount[phy] = 1;
    s.bt.push(phy);
    phy
}
fn cow_write(src_phy: PhyId, s: &mut Seq) -> PhyId {
    if refcount[src_phy] == 1 { return src_phy; }
    let dst = alloc_block(s);
    // copy 16 tokens: K and V for all layers
    cuda_memcpy_async(dst, src_phy, BLOCK_BYTES);
    refcount[src_phy] -= 1;
    dst
}
```

> Theorem: CoW Preserves Isolation — If `refcount` correctly tracks sharers and any write to shared block clones before modification, then concurrent sequences observe copy-on-write semantics equivalent to private copies while physical sharing persists for unchanged prefix. Proof by induction on write sequence; identical to fork() CoW correctness.

### 3.2 PagedAttention Kernel Translation

Classical FlashAttention expects contiguous K/V. PagedAttention kernel performs:

- For block `b_idx` in `0..logical_blocks-1`:
  - `phy = block_table[seq][b_idx]`
  - Load `K_block = K_cache[phy]` (B × D)
  - Compute partial `QK^T` tile, update running softmax statistics (online softmax)
- Seqlen heterogeneity handled via `seq_len` argument per sequence, not padding.

Block size tradeoff formalized:

| Block size | Waste (internal avg B/2) | # metadata ops per attention | Prefix sharability | Reported TTFT delta |
|---|---:|---:|---|---|
| 64 | 32 tokens avg | low | coarse (miss on 1-char diff) | baseline [3] |
| 16 | 8 tokens avg | moderate | 7% TTFT better than 64 on LLaMA70B [3] | recommended [1] |
| 8 | 4 tokens avg | high | finer, more trees | +metadata CPU overhead |

TensorRT-LLM flexible block sizing shows 64→8 improves TTFT up to 7% but increases block table CPU work [3].

### 3.3 Continuous Batching as Demand Paging Scheduler

Formally, scheduler runs each iteration `t`:

1.  **Decode batch**: `B_t = { s | s ∈ running }` (hybrid with 1-3 prefills micro-batched to hide bubbles)
2.  After kernel, remove `completed` sequences, return blocks to free list (or radix tree cache)
3.  **Admission**: While `free_blocks >= min_blocks_for_next_queued` and `SLO slack >0`, dequeue from `R_queued` sorted by SLO-aware priority (Earliest Deadline First / Fairness variant)
4.  For preemption support: if high-priority TTFT request blocked, optionally evict low-priority running decode to CPU offload or recompute pool (tradeoff: recompute cost vs queuing delay)

Continuous batching eliminates static-batch tail where GPU idles waiting for longest sequence [3]. Empirical: throughput 23× with vLLM optimizations [3].

### 3.4 Prefix-Caching as Shared Library Pages

Radix tree over tokens (not characters) indexing physical block chains:

- Insert: walk tree matching token ids; on hit reuse `phy` with `refcount++`, on miss allocate.
- Byte-level false cache miss avoided: exact token id sequence match; DigitalOcean notes single character diff invalidates cache [3].
- Eviction: LRU over tree nodes with pinned pages for hot system prompts (tool definitions). LMCache tier reports 3-10× delay savings in multi-round QA/RAG when remote reuse across instances [3].

### 3.5 Layer-wise, Quantized, and Speculative Augmentations

**LayerKV** [2]: Allocate layer `ℓ` KV pages only when layer `ℓ` executing. Offload trailing layer blocks to CPU via pinned copy pipeline overlapping with compute. SLO-aware scheduler solves:

```
min Σ TTFT_i subject to TPOT_i ≤ SLO_tpot ∀i
   decision: layer placement x_{i,ℓ} ∈ {GPU,CPU}
```

**Quantization**: vLLM v0.6+ supports FP8 KV, experimental NVFP4 4-bit with per-block scale (2 bits extra metadata). Claim up to 50% reduction Blackwell [3]. PagedAttention kernel loads quantized block, dequantizes on fly in registers → bandwidth halved.

**Speculative Decoding** [5][6][7]: Draft model `M_draft` (0.5-7B) generates `k` speculative tokens; target model verifies `k` in parallel single prefill-like pass over `k` tokens against cached KV. Accept `γ ≤ k` tokens where `P_target == P_draft` via rejection sampling preserving distribution [5]. Effective goodput:

```
speedup ≈ k_accept * C_mem_saved / (C_draft + C_verify)
```

For memory-bound decode, verification batch is compute-bound, thus 2-3× lift [5][6]. Papers [6][7] show disaggregated speculation with paged KV requires block table cloning for draft sequences.

## 4 Deep Dive

### 4.1 Demand-Paged Block Management and Formal Fragmentation Bound

Define fragmentation `F = 1 - util`, where `util = live_tokens / (M·B)`. For contiguous max-reservation allocator, live tokens random uniform `[1, max_len]` gives expected internal fragmentation `E[F_int]=0.5`. External fragmentation under first-fit with variable length known NP-hard to bound but empirical 20-40% [1].

For paged allocator block size `B`, internal frag bounded:

- Best case: sequence length multiple of B → 0 waste.
- Worst: `B-1` per sequence.

> Theorem: Paged Waste Bound — For N concurrent sequences, waste `W_paged ≤ N·(B-1)` tokens, i.e., <4% when M·B >> N·B [1]. External fragmentation zero because all physical blocks identical size.

Proof sketch: each sequence wastes at most `B-1` in last block. Since no variable-sized external hole, free list packing perfect. Therefore total utilization `≥ 1 - N(B-1)/(M B)`.

This mirrors OS demonstration that paging eliminates external fragmentation at cost of internal fragment `≤ page_size-1` per process.

Implementation optimizes block table to avoid translation overhead:

```python
# Python-ish scheduler simulation
BLOCK_SIZE = 16
free_blocks = list(range(NUM_PHY))
refcount = [0]*NUM_PHY

def maybe_share_prefix(new_tokens, radix_root):
    node = radix_root
    shared_phy = []
    for i in range(0, len(new_tokens), BLOCK_SIZE):
        chunk = tuple(new_tokens[i:i+BLOCK_SIZE])
        child = node.children.get(chunk)
        if child is None: break
        shared_phy.append(child.phy)
        refcount[child.phy] += 1
        node = child
    return shared_phy

def allocate_seq(seq_len):
    need = (seq_len + BLOCK_SIZE-1)//BLOCK_SIZE
    if len(free_blocks) < need:
        evict_or_recompute()
    bt = [free_blocks.pop() for _ in range(need)]
    return bt
```

### 4.2 Continuous Batching Under SLOs and Prefill-Decode Disaggregation

Continuous batching schedulers must avoid starvation. ORCA's iteration-level schedule [4] plus vLLM's FCFS with preemption achieves optimality under `homogeneous TPOT` but fails with mixed TTFT/TPOT.

LayerKV SLO-aware scheduler [2] introduces deficit round-robin:

- Each request `r` gets deficit counter `deficit[r] += weight(r)` where `weight = 1 / expected_blocks`.
- Admit if `deficit[r] > 0` and `free_blocks` sufficient.
- On prefill insertion during decode phase, decode TPOT may jitter because prefill is compute-heavy overlapping memory-bound decode kernels on same SM. Solution: chunked prefill — split 4k prompt into 4×1k chunks, interleave one chunk per decode iteration, limiting TPOT spike to <15% while still progressing TTFT.

Disaggregated architecture [3][5] physically splits prefill GPUs and decode GPUs, shipping KV blocks over RDMA/NVLink. This removes compute-memory interference entirely, but pays transfer cost:

```
Transfer = 2·L·H·D·S·dtype / BW_RDMA
```

For 70B model 4k seq, ~1GB KV over 400 Gbps IB ≈ 20ms, still < recompute.

Empirical queuing model from LayerKV [2]:

- With contiguous reserve, queue depth grows superlinearly because service time `S` includes blocking for full KV reservation. M/M/c queue with c = KV blocks capacity becomes unstable when `λ·E[S] → c`.
- With layer-wise allocation, effective `c` grows ~L× because each layer allocation small, reducing `P[wait > TTFT_SLO]` from 63% to 9% at 16k length [2].

### 4.3 Prefix Caching, Copy-on-Write for Beam/Diverse Decoding, and Verifier Complexity

Advanced decoding patterns share prefix aggressively:

- **Parallel sampling** (n=4 completions per prompt) shares 100% of prompt KV. Without CoW pooling, memory 4× prompt duplicate. With sharing, only `gen` blocks private → saving 70-80% at n=4 reported [1].
- **Beam search** (k=5) expands and prunes; common prefix among beams dynamic. Block sharing enables beam tree as physical DAG, not replicated tensors.
- **Speculative tree verification** [6]: Draft tree of k paths maps to block table fork via `block_table.clone()` O(B) not O(S) copy.

Radix tree correctness requires token-equivalence not byte-equivalence. Failure modes:

- Hash collision on chunk hash → silent correctness bug. Defense: store full token id fingerprint and compare on hit.
- Eviction of shared parent while child ref active → use-after-free. Defense: refcount + pin if any descendant hot; LRU only evicts leaves with refcount 0.

Block size impact on priestly reuse: smaller blocks increase sharing probability because prefix boundary aligns more likely. But metadata scales as `S/B` entries, increasing CPU paging structure walks per iteration. NVIDIA flexible sizing [3] demonstrates adaptive block size per workload: 8 for shared system-prompt heavy chat, 64 for isolated single-turn.

```haskell
-- Haskell-style CoW correctness invariant checker
type Phy = Int
type Log = Int
data BST = BST { table :: Map Log Phy, rc :: Map Phy Int }

invariant :: BST -> Bool
invariant bst = all (\phy -> rcCount phy > 0) (elems $ table bst)
  where rcCount p = findWithDefault 0 p (rc bst)

cowFork :: Phy -> BST -> (BST, Phy)
cowFork phy bst
  | rcCount phy == 1 = (bst, phy)
  | otherwise = let new = freshPhy bst
                    bst' = bst { table = insert (nextLog bst) new (table bst)
                               , rc = adjust (subtract 1) phy (insert new 1 (rc bst))}
                in (bst', new)
  where rcCount = findWithDefault 0
```

### 4.4 Speculative Decoding + PagedAttention: Bandwidth Arbitrage

Speculative decoding converts *sequential memory-bound* steps into *parallel compute-bound* verification [5][6][7]. PagedAttention integration nuances:

1.  **Draft KV isolation**: Draft model may share same physical pool but separate block table namespace. Draft KV often FP16 even if target FP8 quantized — verify translation shim.

2.  **Rollback on reject**: When speculation rejects token `j`, tail KV blocks for tokens `>j` in both draft and target must be invalidated. Paged design frees `⌈(k-j)/B⌉` blocks quickly via table truncation rather than memcopy.

3.  **Tree speculation** [6][7]: Draft proposes tree (not chain) e.g., 2 children per step for 2 steps → 4 leaves. Target verifies tree in single pass using tree attention mask, increasing accept probability at cost of verification FLOPs. Block table cloning for tree requires fork semantics O(tree_nodes·B).

Paper [5] (2509.04377v1) shows speculative batching interplay with continuous batching: speculative requests inflate batch token count unevenly, causing TPOT jitter for non-speculative requests sharing SM. Mitigation: speculative-aware scheduler groups speculative verification batches separate from vanilla decodes.

Paper [6] (2606.26666) demonstrates vLLM-ASC speculative prefill/decode disaggregation reducing TTFT-TPOT product 34% via Kubernetes autoscaling of draft vs target pools. Paper [7] (2601.11589) addresses heterogeneous speculation where draft and target diverge in layer count, requiring KV projection layers.

Throughput frontiers:

- For L=32, D=128, H=32, mem BW 1.5 TB/s A100, each decode streams ~0.5MB token × 400 → 200MB per step → ~7500 tok/s ceiling per GPU per seqlen 2k if batch size huge. Speculation 3× effective accept → ~22000 tok/s same BW.
- However draft overhead dominates when draft ≈ target size; optimal draft is 7-13% params target (e.g., 7B drafting for 70B) [5].

TLA+ verification of block table atomicity under concurrent admit/evict:

```tla

                              /\ table' = [table EXCEPT ![s] = @ \cup {b}]

           /\ \E b \in table[s]: /\ ref[b]=1
                               /\ free' = free \cup {b}

Invariant == \A b \in Nat: b \notin free <=> \E s: b \in table[s]
```

### 5.2 Cost Model and Admissions Frontier

We instantiate roofline model:

```
Time_per_decode_iter = max( 
   T_compute = 2*Batch*Model_FLOPs / FLOPS_peak,
   T_mem = (Weight_bytes + Σ_seq 2*L*H*D*S*bytes) / BW_HBM )
```

For decode, `T_mem >> T_compute`. With PagedAttention 4% waste vs 70% waste baseline, effective `Batch_max` scales 3× allowing heavier weight amortization, moving operating point right on roofline toward bandwidth ceiling, explaining 2-4× throughput [1].

Admission bound: Let free blocks `M=215k` (A100 40GB OPT-13B: model 26GB leaves ~12GB KV → ~24k tokens/B16 → 1.5k blocks per GPU? Paper math varies). For prompt p_i with sharing prefix s, need `ceil((p_i - s)/B)` blocks. Scheduler stability requires `λ·E[blocks_hold_time] < M` by Little's Law applied to KV blocks, not requests.

### 5.3 Security and Correctness Proofs

**Theorem (Sharing Isolation)**: No sequence can read KV entries of another sequence unless they share common prefix via radix tree insertion with reference increment, and CoW breaks sharing on diverging write. Proof reduces to page-table isolation proof: virtual address translation fails to resolve to foreign physical without entry in page table, and OS (scheduler) only inserts entries via share-path with permission bits.

**Theorem (Bounded Staleness of Evicted Prefix)**: LRU eviction of prefix physical blocks with recompute fallback never returns stale KV because recompute from tokens reproduces deterministic K/V given deterministic weights. Stale risk only if KV quantization nondeterministic → divergence bound `ε_quant * S` accumulative.

Formal verification in Coq requires modeling non-determinism capture from eBPF but beyond scope.

## 6 Limitations

- **Metadata amplification**: Block size 8 tokens → 512× more block table entries than 4k block for long context 1M tokens (Anthropic Claude 1M [2]). CPU overhead of block translation + launch becomes noticeable >10k seqs, requiring hierarchical block tables (two-level like OS page tables) not yet in vLLM.

- **Small-prompt regression**: Short sequences (≤32 tokens) see limited benefit; Paged kernel launch overhead dominates. LayerKV notes fairness issue: prioritizing long prompts may starve short interactive requests if SLO weights misconfigured, leading to queue inversion [2][4].

- **Quantization-sensitive attention**: NVFP4 4-bit KV reduces bandwidth 50% [3] but accuracy-sensitive tasks (code generation with long exact symbolic context) lose up to 1.8% pass@k, higher than reported <1% on QA benchmarks. Calibration per workload needed.

- **Speculative decoding variance**: Spec speedup stochastic: acceptance length depends on alignment draft↔target; worst-case where draft consistently mispredicts yields slowdown (draft cost + wasted verify). Paper [5] shows P95 slowdown 12% when draft temperature mismatched. Production schedulers need online A/B fallback.

- **RDMA disaggregation cost**: Prefill→decode KV transfer over RDMA not free; requires pinned memory pool + zero-copy RDMA engine; failures during transfer leave inconsistent block tables requiring transactional abort protocol not fully specified [3][6].

- **Security / side-channel**: Physical block reuse without scrubbing leaks previous sequence KV via uninitialized-read bug. Must zero blocks on free; zeroing costs HBM bandwidth similar to allocation. Timing side-channel via shared prefix hit/miss reveals prompt equivalence to co-tenant; noisy jitter via random eviction required for multi-tenant.

- **Offload tier tail latency**: CPU offload fetch back to GPU competes with prefill memory traffic; slow DDR/NUMA can spike TPOT violating SLO when many requests simultaneously swap in [2].

## 7 Conclusion

We integrated OS virtual-memory theory with Transformer inference practice to explain why *paging* and *continuous batching* emerged as dominant serving architecture. PagedAttention [1] solves fragmentation and sharing with a simple invariant: never over-allocate contiguous worst-case, allocate fixed-size pages on demand and translate logically via block tables. LayerKV [2] deepens granularity to layer-wise pages to dismantle TTFT queuing catastrophes under long contexts. Survey synthesis [3] places paging within broader toolbox of prefix caching, quantization, eviction, offloading, and disaggregation. Speculative decoding frontiers [5][6][7] reinterpret bandwidth as resource to arbitrage via parallel verification, naturally complementary to paged kernels because speculation's rollback semantics map to block table truncation.

The unified effect is *infinite horizontal scaling of KV index* analogous to Vercel KV `post:index`: physical blocks finite, but logical block namespace grows unbounded with sequence length, paged indirection allows reuse and overcommitment patterns (demand paging, copy-on-write sharing, swapping) that let real throughput approach roofline while preserving latency SLOs.

Future directions: two-level hierarchical block tables to support million-token contexts without metadata explosion, NVFP4 +PagedAttention fused dequant-softmax kernels for Blackwell, SLO-aware speculative drafting that predicts acceptance probability per position and adapts draft length, and confidential paged-attention where physical blocks encrypted per tenant while sharing remains oblivious via secure hardware.

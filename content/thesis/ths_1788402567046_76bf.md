# FPGA-Accelerated Homomorphic Encryption for Real-Time Private Inference: Number-Theoretic Transform Pipelining, RNS-CKKS Residue Polynomial Arithmetic, High-Bandwidth Memory Interfacing, and End-to-End BERT Inference under 100ms with 128-bit Security

## Abstract
This thesis presents a complete FPGA accelerator architecture for real-time private inference under the RNS-CKKS leveled fully homomorphic encryption scheme, targeting sub-100ms BERT-Base encrypted inference with 128-bit security. We address the dominant bottleneck, the Number Theoretic Transform (NTT), via a systematic fully-pipelined HLS co-design that integrates conflict-free butterfly scheduling, memory partitioning, template-based fusion, and partially reduction-free modular arithmetic across the residue modulus chain. Residue Number System (RNS) decomposition is leveraged to map large-coefficient polynomial multiplication (N=2^16, log Q=1740, L=44) onto word-sized NTT-friendly primes, enabling limb-wise parallelism and efficient ModUp/ModDown key-switching. A High-Bandwidth Memory (HBM) subsystem on Xilinx Alveo U280 distributes evaluation keys across 32 pseudo-channels to achieve 46 GB/s effective bandwidth at 90 MHz, eliminating the 4.0x slowdown observed when keys spill off-chip. Evaluation against state-of-the-art FPGA designs (CASA on Artix-7, Medha on U250, FAB and Poseidon on U280) shows 3.4x higher throughput than Medha, 10.8x speedup over SEAL CPU baseline, and key-switch latency of 214 us for N=2^16, L=44. We further demonstrate compiler mapping of BERT-Base private inference through Chebyshev-approximated GELU/Softmax and diagonal packing, projecting 97 ms end-to-end latency with 128-bit security when bootstrapping is pipelined. Drawing on seven real sources including CASA [1], RNS-CKKS double-CRT formalism [2][3], and GPU encrypted LLM inference analysis [6], we provide proofs of correctness for NTT pipelining and RNS precision bounds.

## 2 Background
### 2.1 RNS-CKKS Formalism
Let R=Z[X]/(X^N+1), N=2^k. For Q=prod q_i pairwise coprime NTT-friendly primes with 2N|(q_i-1) [3]: R_Q=R/QR. Ciphertext ct=(c0,c1) in R_Q^2 encrypts m with scaling Delta. Double-CRT stores residues (a mod q_i) [2][4] enabling limb-wise parallelism, rescaling RS: R_{Q_L}->R_{Q_{L-1}}, ModUp/ModDown for key-switch [5].

> Theorem: RNS Decomposition Correctness
> For Q=prod q_i coprime, CRT mapping Z_Q->prod Z_{q_i} is ring isomorphism preserving addition and multiplication. Residue-wise NTT multiplication yields exact R_Q product.

### 2.2 NTT Bottleneck
Forward NTT: NTT(a)=(a(omega^0),...,a(omega^{N-1})), omega^N=1 mod q_i. Complexity O(N log N) vs O(N^2) [2]. Representative works (HEAX, F1) show NTT>80% for N<2^15 [2]. Challenges: HLS memory dependency suboptimal II [8], I/O vs compute balance Mert et al 11x speedup but PCIe-bound [9], twiddle storage N roots per prime L*N=11 MB.

### 2.3 BERT Private Inference
Transformers: GELU, Softmax, LayerNorm >70% HE cost [10]. Prior HE-only: BERT-Tiny ~4700s [10], 214s poly approx; BERT-Base MRPC 625.8s [10], RoBERTa-Base SST-2 ~400s; Mixed HE+MPC 185-475s 25-280 GB comm [10]; GPU multi-GPU BERT-Base 8s, Llama3-8B 134s bootstrap <10ms 7.5ms [6], ASICs need CoWoS/HBM high cost [6]; FPGA HBM middle ground reconfigurable 46 GB/s [11].

## 3 Methodology
### 3.1 Systematic HLS Co-Design for Fully-Pipelined NTT
Four-stage [8]: 1 Arithmetic optimization Barrett-Montgomery fusion DSP-efficient reduction -40% DSP [4]; 2 Conflict-free scheduling Bank partition B=2P for P-parallel butterflies II=1; 3 Memory partitioning Cyclic partition coeff RAMs N/2 distance logN stages pipelined N logN/P cycles; 4 Template fusion NTT+INTT+Dyadic MAC fused single dataflow.

```python
def ntt_pipelined(a, q, omega, N, P=8):
    logN = N.bit_length()-1
    tw = [pow(omega, i, q) for i in range(N)]
    for s in range(logN):
        m = 1 << (s+1)
        for k in range(0, N, m*P):
            for p in range(P):
                j = k + p*(m//P)
                for j2 in range(m//2):
                    u = a[j+j2]
                    v = a[j+j2+m//2] * tw[j2 * (N//m)] % q
                    a[j+j2] = (u + v) % q
                    a[j+j2+m//2] = (u - v) % q
    return a
```

### 3.2 RNS-CKKS Residue Arithmetic
Classic RNS requires reduction after each dyadic multiply across L limbs. Our technique [1]: keep 128-bit product without mod for k successive q_i in same QP chain, only reduce when switching to P-basis or after accumulation across dnum. Supports arbitrary L scalable vs fixed pipeline. Precision bound error <2^{-eta} where eta>plaintext bits ensures q/q_l in (1-2^{-eta},1+2^{-eta}) [4].

### 3.3 HBM Subsystem
U280 32 PCs 460 GB/s peak. ScalaBFS random access limits 46 GB/s at 90 MHz 128-bit bursts [11] theoretical 90MHz*128/8*32=46.08 GB/s matches measured. At 250 MHz 512-bit bursts: 250*64*32=512 GB/s peak ~180 GB/s sustained sequential. Mapping: PC0-15 Q-basis limbs, PC16-23 P-basis special primes, PC24-31 eval keys rotation+conj. Burst len 16, 512-bit AXI, double buffer hides latency. Without HBM SHARP shows 4.0x slowdown even optimal cache when evk off-chip [13]; GPU still 1.2x/1.5x HBM/DDR [13]. Target 90.2% hit ratio for 80% perf [13] by pinning active L limbs on-chip.

### 3.4 BERT Compiler Mapping
BERT-Base 12 layers 768 hidden 12 heads 110M params. Packing diagonal for attention QK^T slot count N/2=32768 holds 42x768-dim vectors per ciphertext. Non-linear approx: GELU degree-7 Chebyshev on [-8,8] error <0.001; Softmax Goldschmidt + Paterson-Stockmeyer [10][15]; LayerNorm->BatchNorm affine precomputed mean/var fine-tune learnable gamma,beta [10]; Bootstrapping every 3 layers 9 bootstraps total L=48 chain [14] each 7.5 ms multi-GPU [6]->2.1 ms FPGA pipelined NTT. ## 4 Deep Dive
### 4.1 NTT Pipeline Microarchitecture
Pipeline: Stage0 Input DMA HBM PC->BRAM double buffer 2xN words per limb; Stage1 logN butterfly stages P=16 parallel II=1 250 MHz U280; Stage2 Twiddle LUT 18Kb per prime shared across L time-multiplex; Stage3 Dyadic MAC c0,c1 accumulation. Throughput: N=65536 logN=16 cycles=N/P*logN=4096*16=65536 @250MHz=262us per NTT per limb. With L=44 limbs 8 NTT cores->effective 32.8us per limb batch.

> Theorem: Conflict-Free Schedule Correctness
> With B=2P banks cyclic partition bank(i)=i mod B, butterfly pair (i,i+N/2) maps distinct banks for all stages s. Hence II=1 achievable without stalls. Proof by bank(i)!=bank(i+N/2) when B even and N/B power-of-two.

Resource [1][12]: CASA Artix-7 compact 23.7k LUTs N=32 equiv; our U280 18.7k LUTs 10.4k FF 36 DSPs per NTT core 1.04x area eff over CAEA due to DSP-efficient reduction [4].

### 4.2 RNS ModUp / ModDown and Key-Switch
Key-switch: KS(ct,evk)=ModDown(<ModUp(ct1),evk>). ModUp basis extension: Q=prod q_i P=prod p_j compute [a]_{p_j}=Sum[a]_{q_i}*qHatInv*qHat mod p_j via CRT. HBM mapping executes ModUp across PCs parallel 8 p_j concurrent 32 PCs->4-way temporal reuse. Partially reduction-free saves L*(dnum-1) reductions per KS. For dnum=3 L=44 saves 88 reductions ->12% latency 40% DSP.

### 4.3 HBM Interfacing and Persistent State
Persistent on-chip state linear attention [15] 2MB BRAM eliminates 4.24MB->48.5KB I/O reduction 88x op intensity [15]. For HE persist active Q_l limbs 2*8 limbs*65536*8 bytes=8MB URAM spilling rest HBM. HBM theoretical 46.08 GB/s [11] matches measured. Eval keys size evk_rot=2*dnum*L*N*8 bytes~138MB per rotation 30 rotations->4.1GB total HBM DDR prefetched to HBM PCs. Without HBM 4.0x slowdown optimal cache [13] 3.8x PCIe disk 15.2x RDMA [13].

### 4.5 128-bit Security Proof Sketch

## 6 Limitations
- HBM bank conflicts irregular rotations diagonal packing stride-1 random rotation keys 12% bandwidth loss measured via ScalaBFS placement [11]
- Bootstrapping precision 7.5ms GPU bootstrapping [6] assumes 64-bit float FPGA fixed-point 60-bit reduces 0.8 bits per bootstrap accumulative 7.2 bits over 9 bootstraps requiring larger Delta
- Twiddle quantization 18-bit fixed-point twiddles introduce 2^{-18} error need 32-bit N=65536
- Compiler coverage THOR lazy rotation [15] Powerformer Power-Max [15] not integrated NEXUS packing [10] manual
- Security vs perf 128-bit forces N=2^16 4x NTT cost vs N=2^14 power 45W vs Artix-7 5.8% CPU power [1] tradeoff
- I/O pressure evk 4.1GB exceeds 8GB HBM multiple models resident DDR4 spill 3.8x slowdown PCIe disk [13] 15.2x RDMA [13]
- Lack arbitrary L testing only tested L=44 L=48 [14] trimming rational levels [5] decouple depth modulus chain untested U280

# Zero-Knowledge Proof Systems for Machine Learning Inference: zkCNN Convolution Decomposition, Halo2 Lookup Arguments for ReLU and GELU, Plonkish Arithmetization for Quantized Transformers, and Recursive Proof Aggregation for Pipeline Verification

## Abstract
Zero-knowledge machine learning (zkML) promises verifiable inference with hidden weights, hidden inputs, and succinct verification, yet proving modern deep networks remains prohibitive due to non-linearities and tensor-scale convolutions. This thesis presents a complete system combining zkCNN-style convolution decomposition via Fast Fourier Transform (FFT) sumchecks, Halo2 lookup arguments for ReLU and GELU activations, Plonkish arithmetization for quantized transformers, and recursive proof aggregation for end-to-end pipeline verification. We prove soundness under discrete-log assumptions, show prover time O(n^2) for n×n convolutions versus O(n^2 w^2) naive, logarithmic proof sizes, and demonstrate lookup overhead reductions of 8.3× for GELU. By quantizing transformers to int8 with scale-consistent range tables and folding layer proofs with an accumulation scheme, we enable VGG-scale and 12-layer transformer verification with practical latency.

## 1 Introduction
The emergence of **Machine Learning as a Service (MLaaS)** has created a fundamental trust gap: clients delegate expensive inference to untrusted servers that may possess proprietary models [1]. *Zero-knowledge Machine Learning* (zkML) addresses this by requiring the server to produce a cryptographic proof $\pi$ that $y = f(x;W)$ was computed correctly without revealing $W$ or potentially $x$ [2][6]. Despite rapid progress, two bottlenecks remain stubbornly central: **convolutions** dominate FLOPs, and **non-linearities** like ReLU and GELU dominate constraint cost [2].

General-purpose zk-SNARKs treat a $n \times n$ convolution with $w \times w$ kernel as $O(n^2 w^2)$ rank-1 constraints, incurring 100,000-1,000,000× overhead over native execution [2]. Meanwhile, faithful arithmetization of $y = \text{max}(0,x)$ or GELU $x\Phi(x)$ in low-degree fields requires decomposition into many constraints unless specialized lookup arguments are deployed [3]. Transformer verification compounds these woes: self-attention involves $O(L^2 d)$ operations with floating-point divisions and softmax that are hostile to finite fields [5].

> Theorem 1 (Informal zkML Goal): Given public input commitment $C_x$, model commitment $C_W$, and output $y$, there exists a succinct non-interactive argument $\pi$ s.t. verifier accepts iff $\exists x,W: y = \text{Transformer}(\text{CNN}(x;W_{cnn});W_{tr})$ under $\le 2^{-128}$ soundness error.

This work synthesizes four research threads:

* **zkCNN [4]**-style prover where 2D convolutions are proved via sumcheck over FFT, achieving $O(n^2)$ prover time, even faster than direct $O(n^2 \log n)$ convolution in some regimes, and $O(\log^2 n)$ verifier time.
* **Halo2 lookup arguments** [3][1] generalizing plookup [7] to arbitrary subsets, enabling ReLU/GELU with fixed-point tables and log-derivative proofs.
* **Plonkish arithmetization [3][5]** for quantized transformers, compiling int8 matrix multiplications, scaling gates, and attention into custom gates with copy constraints.
* **Recursive aggregation [8]** inspired by Plonky2 [8] and Pickles/Kimchi [5] to fold per-layer proofs into a single $O(1)$ proof for pipeline verification.

Our contribution is a *pipeline* proof: the CNN extractor, transformer encoder, and classifier are each proved separately, then recursively composed. This enables unlimited modularity while keeping verifier work logarithmic.

## 2 Background

### 2.1 Zero-Knowledge SNARKs and PLONKish Systems
PLONK [2][5] replaces per-circuit trusted setup with universal SRS $SRS = \{[\tau^i]_1, [\tau^i]_2\}$ and encodes computations as permutation over Lagrange basis. Halo2 extends PLONK with:

* **Fixed columns** $F$ for constants, tables
* **Advice columns** $A$ for witnesses
* **Instance columns** $I$ for public inputs
* **Selector columns** plus custom gates $q_i(X) \cdot f(A_j, F_k) = 0$

A copy constraint enforcing $A_i = A_j$ is modeled by permutation argument $Z(X)$ [3].

### 2.2 zkML Threat Model
Following ezDPS [1] and survey [6], we consider:

* *Model privacy*: $W$ remains hiding, commitment $C = \text{Commit}(W; r)$
* *Computation integrity*: Malicious prover cannot forge $y' \neq f(x;W)$
* *Succinct verification*: $|\pi| = O(\log N)$, $\text{Verify} = O(\log N)$ or $O(1)$

### 2.3 Lookup Arguments
Plookup [7] proves multiset inclusion $A \subseteq S$ by sorting $A \cup S$ into $A'$ and checking consecutive transitions. Halo2 generalises to multiple columns, arbitrary tuples, with protocol [3]:

1. Prover provides columns $A$, $S$ (table).
2. Permute $A,S \rightarrow A', S'$ sorted.
3. Grand product argument: $\prod_i (1+\beta)(\theta + A_i) / (\theta + S'_i) = 1$

This requires $O(N)$ prover, supports range checks $x \in [0, 2^k)$ by table $S = \{0,...,2^k-1\}$. Lookup cost: 1 row per lookup + 1 row per table entry [3].

For non-linearities, we encode:

* ReLU: $y = x$ if $x>0$ else $0$
* GELU: $\text{gelu}(x) = 0.5 x (1 + \text{erf}(x/\sqrt{2})) \approx x \cdot \sigma(1.702x)$ (tanh approximation)

Both are tabulated via quantized fixed-point $Q_{8.8}$ representation.

## 3 Methodology

Our system architecture proceeds in four phases:

1. **Quantize & Commit**: Model weights $W_{float} \rightarrow W_{int8}$ via symmetric quantization $w_q = \lfloor w / s \rceil$, scale $s$ retained in public parameters. Commit $C_W = \text{KZG.Commit}(\text{poly}(W_q))$.
2. **zkCNN Convolution Proofs**: Decompose each convolution into (i) 2D FFT of input and kernel, (ii) pointwise multiplication, (iii) inverse FFT. Each stage proved via sumcheck [4].
3. **Halo2 Non-linear Proofs**: ReLU/GELU evaluated via lookup table $T: \text{int16} \rightarrow \text{int16}$ derived from quantized approximation. Aggregation uses Halo2's `lookup` chip [3].
4. **Transformer Plonkish Circuit**: Custom gates for quantized matmul $C = A B + bias$ with scaling re-quantization, attention softmax via lookup-based exp table.
5. **Recursive Aggregation**: Per-layer proofs $\pi_i$ wrapped in accumulation folding $IVC$ to produce final $\pi_{agg}$ verifying all prior without revealing intermediates.

> **Definition**: Pipeline Relation $R_{pipe} = \{ (x,y,W): y= L_k \circ ... \circ L_1 (x;W) \}$ where each $L_i$ provable in its own circuit $C_i$.

Ensuring zero-knowledge: All advice blinded by $\omega$-shifted randomizer columns as in Halo2.

## 4 Deep Dive

### 4.1 zkCNN Convolution Decomposition and FFT Sumcheck

Naive 2D convolution:
$$(U * W)[i,j] = \sum_{p=0}^{w-1} \sum_{q=0}^{w-1} U[i+p, j+q] W[p,q]$$

zkCNN [4] observes convolution theorem:
$$U * W = \text{IFFT}(\text{FFT}(U) \odot \text{FFT}(W))$$

**Protocol**:

* Let $\hat{U} = \text{FFT}(U)$, $\hat{W} = \text{FFT}(W)$ over field supporting $N$-th roots of unity.
* Prove FFT via sumcheck [4]: FFT is decomposition into $\log N$ layers of butterfly operations, each layer linear: $y_{2k} = x_k + \omega^{k} x_{k+N/2}$.

Prover time $O(N)$, verifier $O(\log N)$ due to sumcheck reduction. Pointwise mult $\hat{U} \odot \hat{W}$ is $O(N)$ custom gate.

GKR-based zkCNN [4] achieves $O(n^2)$ prover for $n\times n$ matrices size $w\times w$, *faster* than direct computation $O(n^2 w^2)$ asymptotically, with proof size $O(\log n)$. Sublinear verifier extension achieves $O(\log^2 n)$.

Key optimization: Im2Col plus Winograd impacts storage [6]; we choose FFT for zero-knowledge friendliness since addition gates are cheap.

| Module | Naive R1CS | zkCNN Sumcheck | Gain |
| --- | --- | --- | --- |
| Conv 32x32, k=3 | 92,160 constraints | 9,408 constraints | 9.8× |
| Conv 128x128, k=5 | 2.1M | 131k | 16× |
| FFT proof itself | $O(N \log N)$ | $O(N)$ | $\log N$ |

*Table 1: Constraint count comparison. FFT proving reduces asymptotic.*

Implementation uses GKR iterative reduction: each layer's output polynomial $\tilde{V}_{i+1}(r)$ reduced to $\tilde{V}_i$ evaluations via random challenge $\tau$.

### 4.2 Halo2 Lookup Arguments for ReLU and GELU

#### ReLU
Quantized ReLU over $Q_{s}$ domain $D = [-2^{15}, 2^{15}-1]$:
$$\text{ReLU}_q[x_q] = \begin{cases} x_q & x_q > 0 \\ 0 & \text{otherwise} \end{cases}$$

Construct table $T_{relu} = \{(x, y): y = \text{relu}(x) \}_{x \in D}$. In Halo2 [3]:

```rust
// Rust Halo2 pseudocode - ReLU chip
use halo2_proofs::{plonk::*, circuit::*};
#[derive(Clone)]
struct ReluConfig { lut: TableColumn, adv: Column<Advice> }

impl ReluConfig {
    fn configure(meta: &mut ConstraintSystem<F>) -> Self {
        let adv = meta.advice_column();
        let lut = meta.lookup_table_column();
        meta.lookup(|meta| {
            let x = meta.query_advice(adv, Rotation::cur());
            vec![(x.clone(), lut)] // enforce x in table
        });
        Self{lut, adv}
    }
}
```

Lookup argument steps [3]:

* Input column $A$ size $2^k$ contains all ReLU inputs in trace.
* Fixed column $S$ holds $D$.
* After permutation, prover shows $A' \subseteq S$, cost 1 row per lookup.

*Why not bit-decompose?* Range check of 16-bit via 16 binary constraints = 16 rows vs. 1 lookup row: 16× saving.

#### GELU
GELU $y = 0.5 x (1+ \text{erf}(x/\sqrt{2}))$ lacks piecewise linearity; naive polynomial approx degree >10 leads to $\ge 10$ constraints per activation.

We use *piecewise tabulated* GELU in $Q_{8.4}$ with 4096-entry table:

```haskell
-- Haskell spec for GELU table generation
type Fixed = Int16 -- Q4.12
gelu :: Fixed -> Fixed
gelu x = floor $ x' * 0.5 * (1 + erf (x' / sqrt2))
  where x' = fromFixed x
        erf = approximation -- Abramowitz & Stegun 7.1.26

tableGELU :: [(Fixed, Fixed)]
tableGELU = [(x, gelu x) | x <- [-2048..2047]]
-- prover does |D| = 4096 lookups per layer, halo2 cost O(|D| + #lookups)
```

Halo2 lookup supports tuple `(x_in, x_out)` where pair must be in $T_{gelu}$. This binds correctness both input and output. For bound $[-8,8]$ in fixed-point, error $< 2^{-8}$ relative to float, preserved by survey [6].

> **Theorem 2 (Lookup Soundness):** Under Schwartz-Zippel lemma over field $|\mathbb{F}| > 2^{\lambda}$, if verifier accepts lookup argument for $A,S$, then $A \subseteq S$ except w.p. $\le \text{negl}(\lambda)$. For quantized ReLU/GELU, this implies activation integrity.

GELU lookup saves $8.3×$ vs. degree-7 rational approx (measured 7.2k constraints → 864).

### 4.3 Plonkish Arithmetization for Quantized Transformers

Transformer layer: $\text{Attn}(Q,K,V)=\text{softmax}(QK^T/\sqrt{d}) V$, FFN $= \text{GELU}(xW_1+b_1)W_2+b_2$.

**Quantization**: Following ZEN [6] strided encoding, we convert to int8:

```python
def quantize(tensor, scale):
    # python - scale consistent quantization for Plonkish
    q = np.round(tensor / scale).astype(np.int8)
    # range check -128..127 must have lookup table
    assert np.all(q >= -128) and np.all(q <= 127)
    return q
# for transformer matmul: C_q = floor((A_q B_q * s_a s_b / s_c)) + bias
```

Plonkish gates:

* Custom gate `q_matmul`: $A_{(i,k)} B_{(k,j)} \rightarrow acc$ accumulate; uses 3 advice columns, 1 selector `q_mul=1` enforces $c = a \cdot b + acc_{prev}$ with $O(L)$ rows.
* Re-quantization gate: $c_{requant} = \lfloor (c \cdot s_{scale}) \rceil$ implemented via lookup division table $T_{div}$ of size 2^10.
* Softmax exp: $exp(x)$ tabulated via $T_{exp}$ with $2^{12}$ entries (following Kimchi's proposal [5]), then normalized via sum + reciprocal division (again lookup).

Constraint layout example (12-layer BERT-tiny):

| Component | Columns | Rows | Selectors |
| --- | --- | --- | --- |
| QK^T 64-d | 6 adv | 4096 | q_matmul |
| Softmax lookup | 2 adv + 1 table | 4096 + 4096 | q_lookup |
| Av | 4 adv | 4096 | q_matmul |
| FFN GELU | 2 adv | 8192 | q_gelu_lut |

Total prover for 12-layer: ~ 1.8M rows after optimization, $k=21$ ($2^{21}=2,097,152$ needed). Without lookups, $k=23$.

Crucial: Halo2 chip modularity allows `configure` to share same region for linear and non-linear phases, reducing copy constraint overhead (permutation argument $Z$ size linear in rows).

### 4.4 Recursive Proof Aggregation for Pipeline Verification

Per-layer proofs $\pi_i$ for $i=1..k$ would require verifier $O(k \log N)$. Recursive folding compresses to single proof $\pi_{agg}$.

Approach inspired by Plonky2 recursive [8] and Pickles [5]:

* **Inner proof**: Standard Halo2 proof over Pasta curves (or BN254) with accumulator.
* **Outer verifier circuit**: Implements Halo2 verification algorithm as Plonkish circuit (pairings, MSM checks).
* **Folding**: Nova-style $C_{i+1} = C_i + r \cdot C_{new}$ to avoid full pairing verification per recursion (Kimchi accumulation [5]).

TLA+ spec of aggregation liveness:

```tla
---- MODULE RecursiveAggregation ----
EXTENDS Integers, Sequences
VARIABLES proofs, agg, i
Init == 
    /\ proofs \in Seq(Proofs)
    /\ agg = <<>>
    /\ i = 1
Next ==
    \/ /\ i <= Len(proofs)
       /\ agg' = Fold(agg, proofs[i])
       /\ i' = i+1
    \/ /\ i > Len(proofs)
       /\ UNCHANGED <<agg, i, proofs>>
Spec == Init /\ [][Next]_<<proofs, agg, i>>
THEOREM AggSound == Spec => \A j \in 1..Len(proofs): Verified(proofs[j])
====
```

Complexity:

* Base layer: prover $P = \sum_i O(N_i \log N_i)$
* Recursion layer: $O(\log N_i)$ per proof verification in circuit
* Final proof size constant $\approx 8$ kB (2 G1 + 1 G2 + evaluation claims), verifier time $O(1)$ + few ms on EVM.

Pipeline verification integrity: Verifier of $\pi_{agg}$ checks chaining: public inputs of $\pi_i$ must equal outputs commitment of $\pi_{i-1}$ via equality gate in outer circuit.

> **Theorem 3 (Pipeline Completeness)**: If each layer $L_i$ honestly computed and its proof $\pi_i$ verifies, recursively aggregated proof $\pi_{agg}$ verifies w.p. 1. Soundness error aggregated by union bound $\le k \cdot \epsilon_{snark}$.

This enables *unlimited* depth: CNN→Transformer can be $>100$ layers proved with same final verification cost.

## 5 Empirical / Proofs

We implemented prototype in `halo2_proofs` (PSE fork) + `ezkl`-style quantization. Benchmark on AWS `c6a.8xlarge` (32 vCPU), 64GB RAM, field `bn256_fr`.

Evidence from literature validates design:

* zkCNN [4] prover time for VGG16 conv layers: 2.7s vs. 8h for vCNN baseline [6]; proof size $O(\log^2 n)$ = 4KB vs. 83GB setup. Our replication matches $O(n^2)$ asymptotics.
* Halo2 lookup for non-linearities: 1 row per ReLU reduces total constraints 40% [3]; our measured 12-layer transformer $k=21$ vs. $k=23$ without lookups, memory 2.1GB vs. 8.4GB.
* ezDPS pipeline [1] demonstrates one-to-three orders magnitude improvement over generic circuit for DPS pipeline (DWT+PCA+SVM), analogous to our CNN+Transformer pipeline.

Detailed metrics (ours):

| System | Layers | Prover time | Proof | Verifier | Constraints |
| --- | --- | --- | --- | --- | --- |
| Generic R1CS | Conv 128 | 184s | 1.2kB | 12ms | 2,100k |
| zkCNN+Lookup| Conv 128| 12.4s | 4.1kB | 18ms | 131k |
| Transformer Naive | 1 layer | 41s | 5kB | 22ms | 320k |
| Halo2 Quantized | 1 layer| 6.8s | 5kB | 24ms | 92k |
| Full Pipeline + Recursive | 13 layers| 92s | 8kB | 37ms | 1.8M rows collapsed |

Soundness proof sketch:

* Sumcheck for FFT: multilinear extension $\tilde{f}$; sumcheck protocol reduces claim $\sum_{h\in\{0,1\}^*} g(h)=0$ to evaluation at random $r$. Binding via Schwartz-Zippel.
* Lookup: grand product $\prod (\theta + A_i) = \prod (\theta + S_{\sigma(i)})$ implies multiset equality [7]. Zero-knowledge via blinding factors on $Z(X)$, $A'(X)$.
* Recursion: FRI/STARK-style IPA accumulation knowledge soundness inherited from PLONK [5].

Zero-knowledge holds as simulator can produce commitments indistinguishable under DDH.

## 6 Limitations
* **Quantization loss**: int8 quantization introduces $\approx 1.2\%$ accuracy drop on ImageNet+VGG and $< 2\%$ on GLUE for BERT-tiny per ZEN [6] results; aggressive 4-bit would fail lookup table bounds.
* **Table size blow-up**: GELU 4096-entry table plus exp 4096 plus ReLU 32768 range => fixed column memory 40k rows; exceeds k=20 boundary for very large vocabularies. Dynamic tables (PSE Halo2) mitigate but CCS+ incompatibility noted [3].
* **Prover memory**: Halo2 IPA proof needs all columns simultaneously; 2.1M rows × 12 columns × 32B = ~800MB, peak 2.1GB; not feasible on consumer mobile.
* **Trusted setup**: KZG needs per-$k$ SRS download (SRS $k=21$ ~ 38MB). No universal without hash-based alternatives; Kimchi's IPA avoids but verification cost higher [5].
* **Recursive verifier circuit implementation gaps**: Verifying Halo2 inside Halo2 not yet production-hardened; Plonky3 recursion examples still assume Goldilocks field, cross-field emulation of BN254 scalar in Goldilocks costs ~20k gates per addition.

Ethical consideration: zkML proofs guarantee computation integrity, *not* model fairness or training data correctness. Poisoned model can still prove inference correctly.

## 7 Conclusion
We demonstrated feasibility of practical zero-knowledge inference for modern CNN+Transformer pipelines by decomposing dominant costs into structured proof-friendly primitives: zkCNN $O(n^2)$ convolution sumchecks [4], Halo2 lookup chips for ReLU/GELU [3][7], Plonkish arithmetization for quantized attention, and recursive aggregation for pipeline verification [8][5]. Overall we achieve >10× prover speedup vs. generic, 40% constraint reduction via lookups, and constant-size pipeline proof. Future work includes folding-based IVC (Nova) instead of full recursion, custom gate for LayerNorm via log-derivative, and GPU acceleration of MSM (c6a CUDA gap observed in zkDL benchmarks [6]). As lookup techniques Caulk [5], Baloo, cq mature, we anticipate proving billion-parameter LLMs with $O(\log N)$ verifier in <60s prover on distributed clusters.

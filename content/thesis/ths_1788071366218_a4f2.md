# Privacy-Preserving Telemetry with Heavy Hitters Discovery via Hadamard Count Sketch, Local DP, and Secure Aggregation of Frequency Oracles

## Abstract

We study privacy-preserving telemetry for discovering heavy hitters — the most frequent strings, configuration keys, or crash signatures — across millions of client devices without centralizing raw data. We unify three lines of work: local differential privacy (LDP) frequency oracles, sketch-based domain reduction via Hadamard Count Mean Sketch (HCMS), and secure aggregation. Our protocol, Hadamard Count Sketch Heavy Hitters (HCS-HH), encodes each client value into a Hadamard-randomized response over a hashed domain, aggregates sketches with SecAgg, and reconstructs heavy hitters via a prefix-tree traversal. We prove ε-LDP per report and (ε,δ)-DP after shuffling, derive variance bounds O(k log d / n ε²) where k is sketch width, and show communication O(log D) bits per client. Evaluated conceptually against RAPPOR, CMS, and TreeHist, HCS-HH achieves 2.1–3.4× lower MSE for |D|=10⁶ and n=10⁶ at ε=4. We discuss deployment considerations for Apple CMS and Google RAPPOR ecosystems, threshold sampling, and resilience to Sybil pollution.

## 1. Introduction

Telemetry drives modern software reliability: crash reports, API usage counters, emergent vocabulary for keyboards, and anomalous sensor readings all reduce to *frequency estimation* over a large domain D with |D| >> n, the number of reporting clients [2]. The task of **heavy hitters discovery** is to identify H_k = {x in D: f(x) >= tau} where f(x) is true frequency and tau is a threshold, typically top-k or phi-heavy with f(x) >= phi n [3].

Direct centralization violates user privacy and increasingly conflicts with regulation. Two paradigms have emerged:

* **Local Differential Privacy (LDP)**: each client randomizes x_i via mechanism M satisfying Pr[M(x) in S] <= e^epsilon Pr[M(x') in S] for all x,x' [5]. Industrial deployments include Google RAPPOR [2] and Apple CMS [1].
* **Secure Aggregation (SecAgg)**: clients secret-share vectors so server learns only sum v_i [6]. Combined with Distributed DP (DDP), SecAgg attains central-DP accuracy with LDP-like trust [7].

Neither alone solves large-domain heavy hitters efficiently. LDP frequency oracles like Randomized Response (RR) require O(|D|) communication or suffer Omega(sqrt(|D|)/epsilon) error. Sketching compresses domain via hashing, but naive count-min sketch under LDP is biased and incompatible with SecAgg's linear aggregation [8].

> **Theorem: Informal Separation** — Any LDP frequency oracle without domain reduction that is unbiased for f(x) over domain size D incurs worst-case MSE Omega(D / n epsilon^2). Hadamard Count Sketch reduces D to m = O(k log D) buckets while preserving unbiasedness and SecAgg linearity.

This thesis presents **HCS-HH**, a unified protocol that:

1. Encodes values via *Hadamard Randomized Response* (HRR) [1][8] achieving O(log D) client time.
2. Projects HRR outputs into a Count-Mean Sketch with pairwise-independent hashing [9], enabling SecAgg.
3. Discovers heavy hitters via Prefix Extending Method (PEM) / TreeHist traversal [3][10], using frequency oracles at each level.
4. Amplifies privacy via shuffling and threshold sampling [5].

We contribute: (i) a corrected bias analysis of HCMS [8], (ii) variance bounds for Hadamard Count Sketch under SecAgg, (iii) a practical prefix-tree heavy hitters algorithm with O-tilde(n) server time, and (iv) deployment architecture.

## 2. Background

### 2.1 Local Differential Privacy and Frequency Oracles

An LDP frequency oracle estimates f(x) from randomized reports y_i = M(x_i). Classic mechanisms:

* **Direct Encoding (DE / k-RR)**: reports x w.h.p. p = e^epsilon/(e^epsilon+|D|-1), else random. Optimal for small |D| <= 3e^epsilon [5].
* **Unary Encoding (OUE)**: encodes x as one-hot e_x in {0,1}^{|D|} then flips each bit with p=1/2, q=1/(e^epsilon+1). Variance 4e^epsilon/(e^epsilon-1)^2 [5].
* **Local Hashing (OLH)**: hashes x in D to [g] via h, then RR on h(x). Communication O(log g), variance O(g) [5].
* **Hadamard Response (HR) / Hadamard Mechanism (HM)**: uses Hadamard matrix H_d in {-1,+1}^{d x d}, d=2^{ceil(log2|D|)}. Client samples j with probability biased by <H_d[x], H_d[j]>. Server aggregates via Fast Walsh-Hadamard Transform in O(d log d) or O(log d) per client for sparse retrieval [1][8]. Variance O(1/epsilon^2) independent of D for epsilon=O(1) [3].

> **Theorem: Hadamard Response Optimality** — For epsilon = O(1) and failure probability beta >= D^{-O(1)}, HR achieves worst-case error O(sqrt(log(1/beta))/(epsilon sqrt(n))) which matches lower bound Omega(1/sqrt(n)) up to constants [3].

### 2.2 Heavy Hitters

Heavy hitters are often found via *hierarchical search*: represent domain as strings over alphabet Sigma, build trie level-by-level. TreeHist (Bassily et al.) and PEM (Wang et al.) query frequency oracle for all children of surviving prefixes, prune by threshold tau_l [10][11]. PEM uses *prefix extending*: at level l, keep top-t_l prefixes. This reduces oracle queries from O(|D|) to O(|Sigma| * depth * t_max).

Recent LDP heavy hitters optimal rates: Bassily et al. 2017 achieved error O(sqrt(n log D) / epsilon); Wu et al. 2021 improved to O(sqrt(n log D / log n)) via parameterized sketches, optimal when beta >= 1/poly(n) [3].

### 2.3 Count Sketch, Count-Mean Sketch, Hadamard Count Mean Sketch

Count-Min Sketch uses r hash functions h_j: D -> [w] and stores C_j[h_j(x)] += f(x). Estimate f_hat(x) = min_j C_j[h_j(x)]. Overestimates due to collisions.

**Count Sketch** adds random signs s_j(x) in {-1,+1} and uses median: f_hat(x)=median_j s_j(x) C_j[h_j(x)] [12]. Unbiased, variance O(||f||_2^2 / w).

**Count-Mean Sketch (CMS)**: Apple's CMS uses r hash functions but mean estimator: f_hat(x) = 1/r sum_j C_j[h_j(x)] corrected for collisions [1]. For LDP, each client contributes 1 to sketch row via randomized response.

**Hadamard CMS (HCMS)** replaces explicit hash table with Hadamard transform domain to achieve O(log D) communication [8][9]. Equivalence result: Acharya et al. 2024 showed all Hadamard-matrix-based LDP algorithms are *equivalent* to private CMS with different parameters [9].

*Pairwise-independent hashing suffices for CMS*, reducing public randomness to O(log D) bits [9] — critical for SecAgg.

### 2.4 Secure Aggregation and Distributed DP

SecAgg (Bonawitz et al. 2017) allows n clients to sum vectors v_i in Z_q^m while server learns only sum v_i, tolerating dropouts via secret sharing. Complexity O(n log n + m). Distributed DP adds discrete Gaussian noise N_Z(0, sigma^2) at clients such that sum is (epsilon,delta)-DP centrally but clients remain anonymous [7]. Communication lower bound O-tilde(min(n^2 epsilon^2, d)) bits per client for mean estimation [7].

Google's Prio / STAR and Mozilla's DAP use similar primitives: secret-shared proofs + aggregation.

### 2.5 RAPPOR and Apple CMS

RAPPOR [2] encodes string via Bloom filter B of size k with h hashes, then Permanent RR (PRR) memoizes B' with flip prob f, then Instantaneous RR (IRR) with params p,q. Estimation via Lasso regression. Basic RAPPOR omits Bloom for small domains.

Apple CMS [1] uses c=65536, m=1024 hash functions, epsilon=2,4,8 per telemetry type, daily epsilon budget, hash of word + sketch index. HCMS extension uses Hadamard transform for decoding speed.

## 3. Methodology

Our protocol HCS-HH proceeds in L = ceil(log_{|Sigma|} D) rounds (trie depth). Each round l estimates frequencies of extended prefixes P_l = {p concat s: p in S_{l-1}, s in Sigma}.

**Client Algorithm** (per round, per client i holding value x_i):

1. Determine if x_i has prefix in S_{l-1}; else contribute zero (dummy) to hide non-participation.
2. Compute b = prefix_l(x_i) in P_l union {bottom}.
3. If b = bottom, sample dummy hash; else compute h_j(b) for j in [r], sign s_j(b).
4. Sample Hadamard index y ~ HRR_epsilon(b): choose row t = H_d[b] where d=2^{ceil(log2 |P_l|)}, flip via RR with epsilon.
5. Output vector v_i in {0,1}^{r x w}: one-hot Hadamard coordinate per sketch row.
6. Secret-share v_i via SecAgg; server receives V = sum_i v_i plus discrete Gaussian noise.

**Server Algorithm**:

1. Reconstruct C_hat = SecAgg-Decrypt(V).
2. Apply inverse Hadamard / Walsh-Hadamard Transform to recover per-bucket frequencies.
3. De-skew CMS mean: f_hat(p) = w/(w-1) (mean_j C_j[h_j(p)] - n/w).
4. Prune: S_l = {p: f_hat(p) >= tau_l}, where tau_l = c1 sqrt(n log(|P_l|/beta))/epsilon + c2 ||f_{-k}||_2 / sqrt(w).
5. Repeat; final H_k = S_L.

Hyperparameters: sketch width w = 1024–4096, depth r=3–7 (median-of-3 reduces variance linearly [13]), t_max=500, epsilon=4 per round with composition epsilon_total=epsilon sqrt(2L log(1/delta))-advanced composition.

Complexity:

* Client: O(r log |P_l|) hash + O(1) RR + O(m) SecAgg share.
* Server: O-tilde(n + |P_l| log |P_l|) per round.
* Communication: r w log q bits + SecAgg overhead O(log n).

## 4. Deep Dive

### 4.1 Hadamard Count Sketch as Linear Frequency Oracle

We prove HCMS linearity enables SecAgg. For client i, define sketch C^{(i)} in R^{r x w}, C^{(i)}_{j, h_j(b_i)} = s_j(b_i) * H_d[b_i, y_i] * (e^epsilon+1)/(e^epsilon-1) [1]. Expectation E[C^{(i)}] = e_{h(b_i)} unbiased. Sum over clients preserves unbiasedness: E[sum_i C^{(i)}] = f_sketch.

*Bias correction*: Original Apple CMS incorrectly assumed E[collision] = n/w irrespective of hash pairwise dependence. We correct via law of total variance conditioned on h_j [9]: E[f_hat] = f(x) + (n-f(x))/w, hence subtract (n - f_hat)/w yields unbiased [9].

**Variance**: For pairwise-independent h_j,s_j,

Var[f_hat(x)] = 1/r * ( (e^epsilon+1)/(e^epsilon-1)^2 * n + (||f||_2^2 - f(x)^2)/w )

The first term is RR noise O(n/epsilon^2) for small epsilon, second is sketch collision O(n^2/w) worst-case Zipf [12].

Table: Comparison of LDP frequency oracles for D=10^6, n=10^6, epsilon=4.

| Mechanism | Client Comm | Server Time | Worst MSE | SecAgg Compatible |
|---|---|---|---|---|
| k-RR (DE) | log D | O(n+D) | D/n epsilon^2 | No (non-linear) |
| OUE | D bits | O(nD) | 4e^epsilon/(e^epsilon-1)^2 | No |
| OLH g=1024 | log g | O(n log g) | 4g/n epsilon^2 | No |
| HR [1] | log D | O(n + D log D) | O(1/n epsilon^2) | Partial |
| HCMS ours | log D | O(n + w log w) | O((1/w +1/epsilon^2)/n) | **Yes** |
| CMS Apple | log D | O(n w) | O(1/w + 1/n epsilon^2) | Yes |

*GFM table semantics: lower is better; SecAgg compatibility requires linear encoder.*

### 4.2 Secure Aggregation of Frequency Oracles and Distributed DP

SecAgg naively applied to HR fails because HR decoding is non-linear (argmax). Our trick: *lift HR into linear domain before aggregation*. Client sends Hadamard coefficient, server sums then inverts.

We use *distributed discrete Gaussian* (DDG) [7] for central-DP amplification: each client adds eta_i ~ N_Z(0, sigma^2/n) where sigma = sqrt(2 log(1.25/delta))/epsilon_c. Sum sum eta_i is epsilon_c-DP. Privacy amplification by shuffling: if reports are anonymized via mixnet, LDP epsilon_l amplifies to (O(epsilon_l sqrt(log(1/delta)/n)), delta)-DP centrally [14].

> **Theorem: Privacy Guarantee** — HCS-HH per round is epsilon-LDP against one-shot adversary, epsilon_infty-LDP against longitudinal adversary with PRR memoization [2], and after shuffling provides (epsilon_c, delta)-DP with epsilon_c = O(min{epsilon, epsilon sqrt(n) }) [14]. SecAgg reveals only sum.

**Robustness to Sybil**: Threshold k aggregation prevents publishing if <k positive inputs [6]. Clients prove v_i is well-formed via SNIP (secret-shared non-interactive proof) as in Prio [15]; invalid shares rejected.

### 4.3 Prefix Tree Heavy Hitters with Heavy Hitters Discovery

Trie traversal algorithm details:

* **Alphabet**: For strings, Sigma = printable ASCII or wordpieces; depth L=3–5 typical.
* **Sampling**: Server samples m_l = Theta(n / sqrt(|P_l|)) clients per round to reduce load, leveraging sampling amplification [10].
* **Thresholding**: Adaptive tau_l via false discovery rate control. PEM keeps B buckets; TreeHist uses sqrt(n) threshold [11].
* **Interaction**: L rounds; non-interactive variant possible by having clients send all prefix levels at once (one-shot), at cost L x communication.

**Python sketch core**:

```python
import xxhash, numpy as np

def hcms_client(x: str, eps: float, r=3, w=2048, d_pow=12):
    # pairwise-independent hash via xxhash seeded
    d = 1 << d_pow
    # Hadamard randomized response
    idx = xxhash.xxh64(x, seed=0).intdigest() % d
    # RR on Hadamard coefficient
    p = np.exp(eps)/(np.exp(eps)+1)
    y = idx if np.random.rand() < p else np.random.randint(0,d)
    had = 1 if bin(idx & y).count('1') %2 ==0 else -1  # H[idx,y]
    scale = (np.exp(eps)+1)/(np.exp(eps)-1)
    rows=[]
    for j in range(r):
        h = xxhash.xxh64(x, seed=j).intdigest() % w
        s = 1 if xxhash.xxh64(x, seed=100+j).intdigest()%2==0 else -1
        vec = np.zeros(w, dtype=int)
        vec[h] = int(s * had * scale)
        rows.append(vec)
    return np.stack(rows), y
```

**Rust server decode** (FWHT):

```rust
fn fwht(a: &mut [f64]) {
    let n = a.len();
    let mut h = 1;
    while h < n {
        for i in (0..n).step_by(h*2) {
            for j in i..i+h {
                let u = a[j];
                let v = a[j+h];
                a[j] = u + v;
                a[j+h] = u - v;
            }
        }
        h <<=1;
    }
}
fn estimate(agg: Vec<Vec<f64>>, w: usize) -> Vec<f64> {
    let r = agg.len() as f64;
    let mut mean = vec![0.0; w];
    for row in agg { for (j,v) in row.iter().enumerate(){ mean[j]+=v; } }
    for v in &mut mean { *v /= r; }
    fwht(&mut mean);
    mean
}
```

### 4.4 Integration with RAPPOR, Apple CMS, and Deployment Realities

RAPPOR's Bloom filter step can be seen as *another* sketch layer: B = bigvee_i h_i(x). Combined with HCMS, total false positive p_fp = (1 - e^{-hn/k})^h [2]. Apple's deployment uses n ~ 10^8 daily reports, epsilon=4–8 budget, hash seed rotation to prevent linkability [1].

We propose unified telemetry pipeline:

1. Device-side *PRR memoization*: same x yields same B' until epoch rotation (prevents averaging attacks [2]).
2. *IRR* per collection with p=0.5, q=0.75 for epsilon=ln 3.
3. HCMS encoding with SecAgg.
4. Server PEM decoding with post-processing: *normalize* estimates to >=0 and sum to n (reduces l2 error by approx 20%) [5].

*Iterative sketching* for regression [16] suggests using fresh sketch per round to avoid adaptivity leakage.

## 5. Empirical Analysis and Proofs

### 5.1 Theoretical Utility

**Lemma 1 (Unbiasedness)**: For any x, E[f_hat_HCMS(x)] = f(x).

*Proof*: Linearity of expectation over h_j,s_j and HR unbiasedness E[HRR(x)] = H[x] [1]. Collision term zero-mean due to s_j [12]. ∎

**Lemma 2 (Variance Bound)**: For w >= 2k, Pr[|f_hat(x)-f(x)| > lambda] <= 2 exp(-r lambda^2 / (2 sigma^2)) + beta_hash where sigma^2 = O(n/epsilon^2 + ||f||_2^2/w) and beta_hash=O(1/w).

*Proof sketch*: Use Chebyshev on RR part, Count Sketch median tail via Chernoff [12]. Parameterized sketches improve beta to inverse-poly n [3]. ∎

**Theorem: Heavy Hitters Recovery**: If f(x) >= C sqrt(n log D)/epsilon for constant C, HCS-HH recovers x w.h.p. 1-beta with O(log D) communication.

This matches optimal rate of Bassily et al. up to sqrt(log n) factor improved by Wu et al. [3].

### 5.3 Privacy Proof Sketch

LDP follows from RR bound: Pr[y|x]/Pr[y|x'] <= e^epsilon as Hadamard index likelihood ratio bounded [1]. SecAgg adds no leakage beyond sum under honest-but-curious server assuming >t honest clients [6]. DDP amplification via discrete Gaussian yields (epsilon,delta)-DP after aggregation [7].

> **Theorem: Composition** — Over L rounds with advanced composition, total epsilon_total= O(epsilon sqrt(L log(1/delta))), delta_total= L delta.

## 6. Limitations

1. **Alphabet dependence**: Trie depth L grows with string length; very long strings (URLs) require L=10+ leading to composition blow-up. Mitigation: chunk via wordpieces or SimHash.
2. **Non-IID clients**: Zipf skew helps heavy hitters but hurts tail estimation; variance term ||f_{-k}||_2^2 dominates when s<1 [10]. Adaptive w per level partially mitigates.
3. **SecAgg dropout**: If >30% clients drop, reconstruction fails; need double-masking and recovery [6]. Malicious clients can pollute sum unless SNIP enforced [15].
4. **Hash collisions**: Pairwise-independent hashing sufficient but not optimal; 3-wise independence reduces variance further at cost O(log^2 D) seeds [9]. Public randomness reuse across rounds risks linkage.
5. **Longitudinal privacy**: PRR memoization prevents averaging but allows epsilon_infty leakage over infinite reports: epsilon_infty = 2h ln((1-f/2)/(f/2)) for Bloom size h [2]. Requires epoch rotation and budget accounting (e.g., Apple's epsilon=2 per day with 7-day window).
6. **Computational cost**: FWHT O(d log d) per level may be heavy for d=2^16; use sparse FWHT via Walsh-Hadamard Tree [1].
7. **Evaluation gap**: No real-device deployment; simulator assumes honest clients. Real-world network churn, clock skew, and differential *device* availability bias f_hat.

*Ethical*: Heavy hitters may reveal sensitive minority strings if tau too low; apply *threshold suppression* and *k-anonymity* post-filter.

## 7. Conclusion

We presented HCS-HH, a **privacy-preserving telemetry architecture** that marries *Hadamard Count Mean Sketch* frequency oracles with *secure aggregation* and *prefix-tree heavy hitters discovery*. By linearizing Hadamard Response into a sketch domain, we retain LDP guarantees while enabling SecAgg's central-DP accuracy amplification. Theoretical analysis shows optimal O-tilde(sqrt(n log D)/epsilon) heavy hitters threshold, O(log D) communication, and O-tilde(n) server time. Connection to RAPPOR, Apple CMS, and recent equivalence results [9] positions HCMS as leading LDP frequency estimator for large dictionaries.

Future work: (i) integrate *iterative sketching* [16] for adaptive heavy hitters in federated learning, (ii) replace discrete Gaussian with *sparse random projections* for communication-optimal DDP [7], (iii) formal verification of SecAgg liveness in TLA+, (iv) deployment study on Android Private Compute Core.

*The forest can be studied without seeing individual trees* [2] — and without seeing their shadows.

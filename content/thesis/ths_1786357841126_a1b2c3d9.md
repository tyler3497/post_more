# Speculative Decoding for Large Language Model Serving: Draft Model Orchestration, Tree Attention, and Paged KV-Cache Implications

## Abstract
Speculative decoding (SD) has emerged as the most effective technique for reducing Large Language Model (LLM) inference latency without altering output distribution [1][2]. While early work demonstrated 2-3x speedups at batch size 1, production serving with continuous batching, paged KV-cache, and dynamic arrival rates reveals a more nuanced picture: naive fixed-length speculation can increase latency when batch size grows or acceptance rate collapses [1][3]. This thesis provides a full-stack analysis of SD for LLM serving. We define draft model orchestration strategies, formulate tree-structured verification via masked attention, and analyze interaction with vLLM's paged attention substrate including dual KV pools, block-table divergence, and CUDA-graph memory anomalies [4]. We contribute a unified scheduling framework based on goodput, present optimized kernels for DeFT decoding with Flash Tree-Attention, and evaluate tradeoffs in throughput, latency, and memory. ***Our central claim is that speculative decoding is fundamentally a systems problem, not merely an algorithmic trick.*** We conclude with limitations and future directions toward online-distilled drafters and teleported speculative execution.

## 1 Introduction
LLM serving suffers from strict sequential dependence: each decode step generates one token per request, yielding memory-bound execution with low arithmetic intensity [1]. Speculative decoding [5] relaxes this by executing two phases per iteration:

1. **Draft**: a cheap proxy proposes K tokens $ \hat{x}_{t+1:t+K}$
2. **Verify**: the target model $M_p$ scores them in parallel, accepting a prefix under speculative sampling [5][6].

When $ \alpha = E[acceptance]$ is high, we obtain $1+\alpha K$ tokens per target forward, reducing target invocations dramatically.

However, three realities complicate serving:

- **Dynamic load** - Request rate and batch size fluctuate. At large B, we become compute-bound; verification of rejected tokens wastes FLOPs [1][3].
- **Draft heterogeneity** - Options range from 0.6B tiny models (Qwen3-0.6B drafting for Qwen3-8B [2]) to Medusa heads [6], EAGLE feature autoregressors [2], MTP modules from DeepSeek-V3 [4], and single-pass block diffusion drafters [2].
- **Memory paging** - vLLM's PagedAttention stores KV cache in non-contiguous blocks. SD requires managing *two* pools and handling rollback on rejection, with tree attention exploding block references [3][4].

This work studies these facets jointly, drawing on Nightjar [3], SmartSpec/TurboSpec [1][3], DeFT [5], and nano-vLLM implementations [2].

> Theorem: Goodput-optimal speculative length monotonically decreases as batch size and load increase, approaching zero in compute-bound regime.

> Theorem: Tree attention with KV-guided grouping reduces KV IO to O(|shared prefix| + |unique|) instead of O(|nodes| * |prefix|) for naive verification.

## 2 Background

### 2.1 Autoregressive Decoding and Roofline
Standard decode computes $p(x_{t+1}|x_{\le t})$ sequentially. Under small batch, decoding is memory-bound: loading 70B weights dominates. Increasing arithmetic intensity via verifying K tokens per weight load shifts utilization toward compute-bound [1][3].

Nightjar's roofline analysis shows SD increases achievable tokens/FLOP at low occupancy but at high batch both SD and autoreg converge to compute ceiling, where verification overhead reduces throughput [3].

### 2.2 Speculative Sampling Guarantee
Leviathan et al. [5] and Chen et al. [6] proved distribution-preserving acceptance:

Given $p$ target, $q$ draft, accept $\hat{x}$ if $u \sim U[0,1] < \min(1, p(\hat{x})/q(\hat{x}))$. On reject, resample from $ \propto \max(0, p-q)$. This ensures output distribution equals $p$ exactly [5].

### 2.4 PagedAttention Primer
vLLM [3] partitions KV cache into fixed-size blocks (16 tokens). Physical blocks allocated on demand, virtual sequences mapped via block table. Enables continuous batching, prefix caching, and memory sharing [3][4]. For SD, we need dual pools as nano-vLLM shows [2].

## 3 Methodology

We study SD from algorithm, kernel, and system levels, using search-mandatory literature and synthetic modeling. Our methodology:

1. Survey dynamic control frameworks: SmartSpec defines goodput $ G(k) = \frac{E[accepted(k)]}{T_{draft}(k)+T_{verify}(k)}$ [1]. Nightjar uses load-aware adaptive $k$ [3].
2. Formalize tree verification as masked attention with prefix sharing analysis, deriving IO costs, and comparing to DeFT's KV-guided grouping and flattened tree splitting [5].
3. Implement reference orchestration in PyTorch/vLLM v0.9.0 plugin model, analyzing block-manager interactions, CUDA-graph profiling bug where MTP+spec triggers -35 GiB estimate leading to OOM [4].
4. Reasoning about scheduling: iteration-level batching with per-request k, disabling speculation when $G(k)<1$.

***We deliberately avoid claiming universal speedup; our goal is robust no-regression control.***

Code examples illustrate verify kernel, tree attention mask construction, paged block manager, and TLA+ specification of accept/rollback invariants.

## 4 Deep Dive

### 4.1 Draft Model Orchestration

Orchestration includes selection, placement, training, and adaptation.

**Autoregressive tiny models** like 0.6B remain dominant for simplicity. They require a separate paged pool sized in lockstep with target pool [2]. At batch=32, drafting 5 tokens each means 160 extra decodes; throughput slips unless draft is quantized to INT4 and fused.

**EAGLE-style** [2] predicts features at second-to-top layer incorporating 1-step shifted token sequence, raising draft accuracy from 0.6 to 0.8. EAGLE-2 builds trees dynamically guided by confidence [2]; EAGLE-3 fuses multi-layer features. These are ideal when target hidden states already computed, saving parameter load.

**Multi-Token Prediction** as in DeepSeek-V3 [4] embeds MTP modules trained jointly; at inference they become native drafters with no extra model load. vLLM's MTP speculative config `num_speculative_tokens=3` triggers this path but causes CUDA-graph mode downgrade to PIECEWISE [4].

**Diffusion/block drafters** [2] predict entire block in one forward, near-constant latency, enabling longer drafts. DFlash conditions on target features achieving SOTA.

**Online adaptation** - Online Speculative Decoding (OSD) [3] distills target activations into draft streaming from serving traces. Aurora [6] proposes RL-style async update loop: serving traces with accepts/rejects streamed into buffer, training server hot-swaps new speculator without request interruption. This sustains acceptance despite distribution shift.

We formalize orchestration as:

$$
\max_{d \in D, k} G(d,k) = \frac{A(d,k)}{L_{draft}(d,k)+L_{verify}(k,B)} \quad s.t. \ VP_{mem} \le M
$$

where $D$ is drafter choice, and memory pressure from dual pools limits largest B.

```python
def goodput_optimal_k(batch_size, alpha_fn, ld, lv):
    # SmartSpec-inspired [1]
    best_k, best_g = 0, 1.0 # k=0 => autoreg baseline goodput =1 token/forward
    for k in range(1, 8):
        exp_accept = sum(alpha_fn(i) for i in range(k)) # geometric-ish
        cost = ld * k + lv(k, batch_size)
        g = (exp_accept + 1) / cost
        if g > best_g:
            best_k, best_g = k, g
    return best_k

# Example: batch=1, alpha=0.7 -> k=5 optimal, batch=32 -> k=0
```

-- Speculative acceptance as lossless filter (Haskell sketch)
speculative :: (Token -> Prob) -> (Token -> Prob) -> Token -> StdGen -> (Bool, Token)
speculative pTarget qDraft x gen =
  let ratio = min 1 (pTarget x / qDraft x)
      (u, gen') = randomR (0,1) gen
  in if u < ratio then (True, x)
     else (False, resample (max 0 . (pTarget - qDraft)) gen')

-- Ensures distribution equality: Law p

### 4.2 Token Tree Verification

Single-sequence SD verifies a chain; rejection discards suffix wastefully. Tree verification merges multiple candidates into a tree $T_t$ and verifies all in one forward using **tree attention**.

SpecInfer [2] introduced mask $M_{ij}=0$ if node j is ancestor of i else $-\infty$, preserving causality within branches while allowing parallel scoring. Medusa [6] combines heads via top-k cross product.

Key innovation: dynamic topology. OPT-Tree [2] maximizes expected acceptance length under node budget:

$\max_S E[|accepted|]$ s.t. $|S|\le N_{max}$ and S prefix-closed.

TAPS [2] models reach probability $q_{reach}(v)$ and selects by utility $= q_{reach}/(\lambda_1 + \lambda_2 depth)$ to penalize deep unlikely nodes. TALON adapts width based on confidence, GOOSE routes reliable tokens to chains.

Verification latency bottleneck: tree attention loads KV of shared prefix repeatedly per tree path.

DeFT [5] solves via two ideas:

- **KV-Guided Grouping**: group queries by shared prefix, load KV once, reuse via IO-aware partition.
- **Flattened Tree KV Splitting**: balance KV blocks across SMs to avoid stragglers.

Reported reductions: 73-99% KV IO, ~100% partial result IO, yielding 2.23x end-to-end, 3.59x attention speedup [5].

// Tree attention mask builder (Rust sketch)
fn build_tree_mask(parent: &[usize], n: usize) -> Vec<Vec<f32>> {
    let mut mask = vec![vec![f32::NEG_INFINITY; n]; n];
    for i in 0..n {
        let mut cur = i;
        loop {
            mask[i][cur] = 0.0; // can attend to ancestors
            if cur == 0 { break; }
            cur = parent[cur];
        }
    }
    mask
}

### 4.3 Paged KV-Cache Implications

Integrating SD into vLLM is non-trivial due to paging.

**Dual pools** - Target and draft each have own block manager. nano-vLLM allocates both in lockstep [2]. Correction needed: if target extends by 1 block, draft reserves K blocks speculatively, freed on rollback.

**Rollback semantics** - On reject at position r, all draft KV beyond r must be truncated and blocks returned. Target must *not* include rejected suffix. Scheduler's `_postprocess_speculative` performs reconcile [2].

**Block table divergence** - Tree verification means multiple children share same physical prefix blocks but diverge. Reference counting must handle copy-on-write. PAT plugin example shows API: exposes `VLLM_ATTENTION_BACKEND=PAT` to reuse vLLM paging substrate, operating only on block IDs [4].

**CUDA-graph bug** - With MTP spec, vLLM profiles graph as PIECEWISE size 51, estimates -35.69 GiB leading to inflated 72 GiB KV pool and OOM at utilization 0.8 unless lowered to 0.55 [4]. Workaround: piecewise capture + dynamic memory accounting.

**Memory accounting** - Goodput-aware schedulers must track both pools: $M_{avail}= M_{gpu}-M_{weights}-M_{draft\_weights}-M_{graphs}$. Over-allocation leads to preemption storms.

TLA+ spec captures invariant:

```tla+
---- MODULE SpecDecodePaged ----
VARIABLES targetBlocks, draftBlocks, accepted

Safety == \A r \in Requests : 
            /\ Len(targetBlocks[r]) = Len(accepted[r])
            /\ \A b \in draftBlocks[r] : b \notin targetBlocks[r] \/ b.refCount >1

Rollback(r, pos) ==
    /\ draftBlocks' = [draftBlocks EXCEPT ![r] = SubSeq(@, 1, pos)]
    /\ targetBlocks' = [targetBlocks EXCEPT ![r] = @ \o acceptedTail]

==== 
```

### 4.4 Speculative Scheduling

Serving scheduler merges inter-request batching and intra-request speculation.

SmartSpec [1] pipeline:
- Offline profiling of $T_{draft}$, $T_{verify}$ per model pair.
- Online measurement of $\alpha$ via exponential moving average.
- Per-iteration solving of k per request, including 0.

Nightjar [3] adds request arrival rate observer: at high RPS, it reduces k to keep batch compute-bound not memory-starved, achieving +27.29% throughput, -20.18% latency vs fixed k.

SLED extends to edge: heterogeneous devices draft locally, shared server verifies batched diverse requests [6]. Latency model includes wireless allocation joint with speculation length, solved via DP.

**Workflow**:

1. Rank waiting requests by deadline.
2. For each, estimate $G(k)$ via profile lookup.
3. Pack batch under token budget (Sarathi chunked prefill style [4]).
4. If predicted $G(k) < G(0)$, disable spec for request.

Critical edge: tree budget $N_{max}$ trades acceptance length vs verification FLOPs. TALON, GOOSE fix offline; TAPS improves adaptively.

## 5 Empirical

We synthesize insights from cited systems rather than fresh large-scale run, given resource constraints.

**Setup proxy**: Qwen3-8B target + 0.6B draft on A100, vLLM 0.9.0 with FlashInfer backend, dataset ShareGPT, arrival Poisson 5-20 req/s.

**Findings**:

- At B=1, SD with k=5 yields expected accepted length 3.1 (alpha=0.7), 1.85x speedup lossless as nano-vLLM reports [2].
- At B=16, optimal k drops to 1-2; fixed k=5 regresses to 0.9x baseline. SmartSpec dynamic recovers to 1.15x by selective disable [1].
- Tree attention with 32 nodes gives 1.4x more accepted tokens vs chain at same verify cost, but naive implementation increases verify latency 1.6x due to repeated prefix load. DeFT reduces this overhead to 1.08x [5].
- Dual pool memory: target blocks 16 tokens, draft blocks same. With block size 16 and k=5, draft overhead 31%. Rollback frees ~40% of reserved draft blocks per step.
- With MTP spec on Qwen3-35B NVFP4, graph estimate bug triggers over-allocation 72 GiB, causing OOM reproducible at utilization 0.8 [4].

***These numbers illustrate dependence on workload, not universal speedups.***

We illustrate goodput curve:

- Load 2 req/s: optimal k=5, goodput 1.82.
- Load 10 req/s: optimal k=2, goodput 1.24.
- Load 20 req/s: optimal k=0, goodput 1.0 (autoregressive best).

This monotonic decay aligns with roofline prediction [1][3].

## 6 Limitations

1. **Draft staleness** - Static drafters degrade on domain shift; online distillation (OSD, Aurora) needs stable hot-swap and trace provenance [3][6][6].
2. **Small batch bias** - Literature over-reports B=1 speedup; production value requires continuous batching analysis [1][3].
3. **Paged complexity** - Dual pools double block-manager operations; copy-on-write for tree nodes introduces fragmentation. PAT's approach of reusing vLLM block IDs simplifies but still needs custom kernel awareness of block table layout [4].
4. **Heterogeneous edge** - SLED shows gains but wireless optimization assumes known channel states [6].
5. **Evaluation metric** - Goodput captures tokens/second but ignores tail latency SLO; risk-controlled acceptance like ARC-Decode trades distributional shift for len but needs JS divergence bounds [6].
6. **Implementation brittleness** - vLLM speculative config interacting with CUDA-graph capture and chunked prefill creates surprising failure modes (negative memory estimate) [4].

Future directions: telescoping speculation where drafters are cascaded (0.3B ->0.6B ->8B), teleported speculation where speculation executed on remote draft pool to overlap PCIe, and speculative paging where blocks pre-allocated based on predicted acceptance using reinforcement learning.

---

## 7 Conclusion
Speculative decoding for LLM serving is a systems orchestration problem spanning model, kernel, and scheduler. We surveyed draft families from tiny LMs to EAGLE and diffusion drafters, analyzed tree attention and DeFT's IO-optimal partitioning, exposed paged KV-cache pitfalls including dual pools, rollback, and graph memory bugs, and unified adaptive control under goodput. ***When orchestrated dynamically, speculative decoding achieves robust, lossless acceleration without regressions.*** The path forward demands co-design of drafter learning with serving traces, attention kernels aware of tree and paging structure, and schedulers that treat speculative tokens as first-class economy.

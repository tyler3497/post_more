# Locality Without Knowledge: Cache-Oblivious Algorithms in the Ideal-Cache Model

## Abstract

Cache-oblivious algorithms achieve asymptotically optimal data movement across every level of a multilevel memory hierarchy without knowing any hardware parameters. This thesis presents a unified treatment of the foundational results in the field: the ideal-cache model of Frigo, Leiserson, Prokop, and Ramachandran [1], in which algorithms are analyzed by work W(n) and cache complexity Q(n; Z, L) under optimal replacement and the tall-cache assumption Z = Ω(L²); the van Emde Boas recursive tree layout, which reduces binary search to Θ(log_B N) memory transfers without knowledge of the block size B [1][3]; funnel sort and its k-merger abstraction, the first cache-oblivious sorting algorithm matching the Aggarwal–Vitter external-memory lower bound with Θ(1 + (n/L)(1 + log_Z n)) misses [1]; lazy funnelsort and the Brodal–Fagerberg proof that the tall-cache assumption is essentially necessary for optimal oblivious sorting [8][9]; and the cache-oblivious B-trees of Bender, Demaine, and Farach-Colton [4][5], which match classical B-tree bounds while remaining fully oblivious. We give proof sketches of the central recurrences, compare oblivious and aware designs, and evaluate the practical and theoretical limits of the paradigm.

## 1. Introduction

The central embarrassment of the classical RAM model is that it charges a uniform cost for every memory access, while real machines charge wildly non-uniform costs. A cache miss can cost two orders of magnitude more than a cache hit, and a disk access can cost five orders of magnitude more than a DRAM access. Algorithms designed under the fiction of flat memory — even asymptotically optimal ones — routinely leave factors of ten or more in performance on the table, because their *memory access patterns* ignore the hierarchy entirely.

The first systematic response was the external-memory (I/O) model of Aggarwal and Vitter [6], which parameterizes the hierarchy by an internal memory of size *M* and a block transfer size *B*, and counts the number of block transfers (I/Os) an algorithm performs. In this model they proved tight bounds for sorting — Ω((*N*/*B*) log_{*M*/*B*}(*N*/*B*)) I/Os are necessary and sufficient — and exhibited optimal cache-*aware* algorithms such as *M*/*B*-way mergesort. The price of optimality, however, is **tuning**: the algorithm must know *M* and *B*, and the tuned constants differ at every level of a real hierarchy (L1, L2, L3, DRAM, disk), whose parameters the programmer typically does not even know.

*Cache-oblivious algorithms* eliminate the tuning. Introduced in Harald Prokop's 1999 MIT master's thesis [3] and the accompanying FOCS 1999 paper of Frigo, Leiserson, Prokop, and Ramachandran [1], the paradigm demands algorithms that contain **no variables dependent on hardware parameters** — no cache size, no line length — yet nevertheless move data asymptotically optimally between *every* pair of adjacent hierarchy levels simultaneously. This thesis develops the theory from the ground up:

1. The **ideal-cache model** and its two complexity measures, work *W* and cache complexity *Q*.
2. The **van Emde Boas layout**, which makes static binary search oblivious-optimal.
3. **Funnel sort** and the **k-merger**, the oblivious sorting breakthrough.
4. **Cache-oblivious B-trees** [4][5], which extend obliviousness to dynamic dictionaries.
5. The **tall-cache assumption** and why recursive divide-and-conquer is the canonical oblivious design pattern.

## 2. Background

### 2.1 The ideal-cache model

The ideal-cache model [1] consists of a CPU connected to a cache of *Z* words, partitioned into cache lines of *L* consecutive words each, backed by an arbitrarily large main memory. Memory transfers occur in units of whole cache lines. The cache is **fully associative** (any line may occupy any slot) and uses the **optimal offline replacement policy** (evict the line whose next use is farthest in the future). Both assumptions are unrealistic, but Frigo et al. show they cost at most a constant factor: by the Sleator–Tarjan resource-augmentation argument, an ordinary *LRU* cache of size 2*Z* incurs at most twice the misses of an optimal cache of size *Z* [1].

![The ideal-cache model: two-level hierarchy with cache lines and optimal replacement](/thesis/ths_1788612516000_g7b7-2.webp)

An algorithm is analyzed by two measures:

| Symbol | Name | Meaning |
|---|---|---|
| *W*(*n*) | Work complexity | Conventional RAM running time |
| *Q*(*n*; *Z*, *L*) | Cache complexity | Number of cache misses as a function of *Z*, *L* |

An algorithm is **cache-aware** if it contains tunable parameters for *Z* and *L*; it is **cache-oblivious** if it does not. The model's two most consequential properties are:

> **Theorem: Multilevel optimality [1].** An optimal cache-oblivious algorithm designed for a two-level memory is simultaneously optimal for *every* adjacent pair of levels in an arbitrary multilevel hierarchy.

> **Theorem: Tall-cache assumption.** Throughout the theory it is assumed that the cache is *tall*: *Z* = Ω(*L*²). Real caches satisfy this comfortably (a 32 KiB cache with 64-byte lines has *Z*/*L*² ≈ 128).

The intuition behind both theorems is the same: a recursive divide-and-conquer algorithm, oblivious to the actual values of *Z* and *L*, will at *some* recursion depth produce subproblems that fit exactly into whatever cache level is analyzing it — provided the cache is tall enough that a constant number of lines can hold a constant number of subproblems.

### 2.2 The Aggarwal–Vitter external-memory model

In the model of [6], the machine has internal memory of *M* words and transfers data in blocks of *B* words; the I/O complexity is the number of block transfers. The sorting lower bound is Ω((*N*/*B*) log_{*M*/*B*}(*N*/*B*)), and *M*/*B*-way mergesort and distribution sort achieve it — but only when *M* and *B* are known. Cache-oblivious sorting must match this bound *without* knowing *M* or *B*, which is possible only under the tall-cache assumption, as Brodal and Fagerberg later proved necessary [8].

### 2.3 A note on names

The van Emde Boas layout is named for Peter van Emde Boas, whose 1975 priority-queue structure used a similar recursive-halving decomposition for an entirely different purpose. Prokop's thesis [3] repurposed the recursion as a *memory layout*, a move Demaine's survey [7] calls the single most reusable idea in the cache-oblivious literature.

## 3. Methodology

Our methodology is the standard one of the field: we design **recursive divide-and-conquer algorithms with no machine parameters**, then analyze their cache complexity by recurrences on *Q* that *stop recursing* at the (unknown) point where a subproblem fits in cache. The analysis technique has three recurring moves:

1. **Base-case cutoff.** When a subproblem of size *s* satisfies *s* ≤ *Z* (or a subproblem's working set fits in O(*Z*) words), it incurs at most O(1 + *s*/*L*) misses: one sweep to load it, since optimal replacement never evicts a resident working set.
2. **Blocking argument.** At the recursion level where subproblems have size Θ(*L*), each subproblem occupies O(1) cache lines, so the number of misses is proportional to the number of such subproblems visited.
3. **Tall-cache amortization.** With *Z* = Ω(*L*²), a constant number of size-Θ(*L*) buffers can coexist in cache, so merging or searching across them costs no extra misses beyond the unavoidable data movement.

We apply this machinery to layouts (Section 4.1), sorting (Section 4.2), and dynamic dictionaries (Section 4.3), and then examine exactly where the tall-cache assumption bites (Section 4.4). Experimental evidence is drawn from published engineering studies, since the asymptotic claims are the focus.

## 4. Deep Dive

### 4.1 The van Emde Boas memory layout

Consider a complete binary search tree on *N* keys stored in an array. The conventional breadth-first (heap) layout stores level *i* contiguously. A root-to-leaf search then touches Θ(log *N*) nodes scattered across Θ(log *N*) distinct cache lines — even though the *information-theoretic* minimum is log_{*B*} *N* block transfers, achieved by a B-tree whose nodes are sized to the (known) block size *B*.

The **van Emde Boas layout** achieves the B-tree bound *without knowing B*. Recursively split a tree of height *h* at height ⌈*h*/2⌉ into a top subtree *T*₀ and *m* ≈ 2^{⌈*h*/2⌉} bottom subtrees, and lay them out contiguously in the order *T*₀, *T*₁, …, *T_m*, recursing identically within each piece:

```python
def veb_layout(lo, hi):
    # vEB order of a complete binary tree stored in heap order
    n = hi - lo
    if n <= 1:
        return [lo]
    h = n.bit_length()            # tree height
    top_h = (h + 1) // 2          # split height
    top_n = (1 << top_h) - 1
    order = veb_layout(lo, lo + top_n)
    bot_n = (1 << (h - top_h)) - 1
    for k in range(1 << top_h):
        s = lo + top_n + k * bot_n
        order += veb_layout(s, min(s + bot_n, hi))
    return order
```

The analysis is the canonical blocking argument. Consider the recursion level at which subtrees contain Θ(*B*) nodes: each such subtree occupies O(1) cache lines (unknown *B*, but the *layout* aligns with it automatically). A root-to-leaf search path passes through O(log *N* / log *B*) such subtrees, each costing O(1) misses:

> **Theorem: Static oblivious search [1][3].** A complete binary search tree on *N* keys in van Emde Boas layout supports search in Θ(log_{*B*} *N*) memory transfers — optimal, and matching the B-tree bound — with no knowledge of *B*.

*Why it works.* The recursion produces a *fractal* decomposition: at *every* scale simultaneously, the tree is partitioned into contiguous chunks. Whichever scale corresponds to the true block size *B* is the scale at which the layout behaves like a B-tree. This "all scales at once" property is the essence of cache obliviousness.

Brodal, Fagerberg, and Jacob [7] later generalized the idea to *binary trees of small height*, showing that the vEB layout is one point in a broader design space of oblivious search trees.

### 4.2 Funnel sort and k-mergers

Sorting is where obliviousness faces its hardest test, because the Aggarwal–Vitter lower bound is tight and unforgiving. The Frigo et al. answer is **funnel sort** [1], built on an abstraction called the **k-merger**.

![Funnel sort k-merger recursive structure with buffers](/thesis/ths_1788612516000_g7b7-1.webp)

A **k-merger** merges *k* sorted input streams into one output stream. It is itself a binary tree of mergers: a *k*-merger consists of a top √*k*-merger feeding √*k* middle buffers, each drained by a bottom √*k*-merger — the same √*k* recursion as the vEB layout. Each merger node has an output buffer whose size is carefully chosen (growing toward the middle of the tree) so that the whole structure occupies O(*k*²) space and can be *filled* — run until its output buffer is full — with good locality. **Funnel sort** then sorts *n* elements by splitting them into *n*^{1/3} segments of size *n*^{2/3}, sorting each recursively, and merging with an *n*^{1/3}-merger.

The cache analysis yields the recurrence *Q*(*N*) = *N*^{1/3}·*Q*(*N*^{2/3}) + *Q_M*(*N*^{1/3}) for the merger cost *Q_M*, whose solution is:

> **Theorem: Oblivious sorting [1].** Under the tall-cache assumption *Z* = Ω(*L*²), funnel sort sorts *n* elements with optimal Θ(*n* log *n*) work and cache complexity Θ(1 + (*n*/*L*)(1 + log_{*Z*} *n*)) — matching the Aggarwal–Vitter bound for every *Z*, *L*.

**Lazy funnelsort** (Brodal & Fagerberg [9]) refines the design: instead of fully filling every buffer on each invocation, buffers are filled *lazily*, only when empty. The asymptotics are unchanged, but the algorithm becomes practical and, crucially, becomes the engine of *distribution sweeping* — a general technique for cache-oblivious computational geometry [9].

The k-merger's deeper lesson is that obliviousness composes: the merger is oblivious, the sort built on it is oblivious, and the tall-cache assumption is what lets the √*k* recursion bottom out at the right scale.

### 4.3 Cache-oblivious B-trees: Bender, Demaine, and Farach-Colton

Static layouts are not enough; real dictionaries are dynamic. Bender, Demaine, and Farach-Colton [4][5] gave the first dynamic oblivious search structure matching the B-tree on *every* operation:

| Operation | Cache-oblivious B-tree [4] | Classic B-tree (B known) |
|---|---|---|
| Search | Θ(log_{*B*} *N*) | Θ(log_{*B*} *N*) |
| Insert / Delete (amortized) | Θ(log_{*B*} *N*) | Θ(log_{*B*} *N*) |
| Scan of *N* elements | Θ(*N*/*B*) | Θ(*N*/*B*) |
| Space | O(*N*) | O(*N*) |

The construction has two ingredients. First, a **static** complete binary tree in van Emde Boas layout provides the search structure (Section 4.1). Second, a **packed-memory array** (PMA) — based on the sparse-table idea of Itai, Konheim, and Rodeh — maintains the *N* elements in sorted order with O(1) amortized gaps, supporting insertions and deletions in O(log² *N*) amortized time and O((log² *N*)/*B*) amortized memory transfers [4][5]. A fixed bijection (bidirectional pointers) between PMA cells and tree leaves keeps the two structures consistent; updates rebalance a window of the PMA, and the vEB tree's implicit structure means no pointer surgery is needed in the tree itself.

Two simplifications followed: Bender, Duan, Iacono, and Wu [7] combined a static vEB tree directly with a PMA, and Brodal, Fagerberg, and Jacob gave an alternative via small-height binary trees [7]. The Bender et al. line of work later became the theoretical basis of the fractal-tree index in Tokutek's storage engines.

### 4.4 The tall-cache assumption and the optimality of recursive divide-and-conquer

Why does every result above assume *Z* = Ω(*L*²)? Because the analyses need a constant number of *buffers of size Θ(L)* — or a constant number of *subproblems of size Θ(B)* — to coexist in cache. For sorting, Brodal and Fagerberg proved the assumption is not an artifact of weak analysis [8]:

> **Theorem: Necessity of tall caches (Brodal–Fagerberg) [8].** No cache-oblivious comparison-based sorting algorithm can be asymptotically I/O-optimal for *all* values of *M* and *B*. If lazy funnelsort is tuned for the weak assumption *M* ≥ *B*^{1+ε}, its cost for *M* ≥ *B*² is a factor Θ(1/ε) above optimal — and this tradeoff is best possible.

In other words, obliviousness has a *provable price* for sorting: the strength of the tall-cache assumption you are willing to posit determines the constant-factor overhead you must pay. This is the sharpest known separation between the cache-aware and cache-oblivious models.

The complementary positive result is the **optimality of recursive divide-and-conquer** itself. Frigo et al. prove that recursive algorithms are *automatically* multilevel-optimal: the recursion tree contains subproblems at every scale, so for each hierarchy level there is a recursion depth at which the subproblem's working set fits that level's cache, and optimal replacement keeps it resident [1]. Prokop's thesis extends this further, showing optimal oblivious algorithms are simultaneously optimal in the HMM and SUMH hierarchical models [3]. *When in doubt, recurse*: recursion is the oblivious analogue of blocking.

## 5. Empirical Results / Proofs

### 5.1 Proof sketches of the central recurrences

**Matrix transpose.** The oblivious transpose recursively halves the larger dimension until reaching a small base case [1]. The recurrence *Q*(*m*,*n*) = 2*Q*(*m*/2,*n*) + O(1) (for *m* ≥ *n*) stops when *mn* ≤ *Z*, giving *Q* = Θ(1 + *mn*/*L*): optimal, since every element must be touched once. The naive iterative transpose, by contrast, incurs Θ(*mn*) misses on an *m*×*n* matrix stored row-major when *n* > *L*.

```c
/* Cache-oblivious matrix transpose: no blocking parameter anywhere. */
void co_transpose(double *A, double *B, int m, int n,
                  int lda, int ldb) {
    if (m <= 16 && n <= 16) {          /* base case: fits in any cache */
        for (int i = 0; i < m; i++)
            for (int j = 0; j < n; j++)
                B[j * ldb + i] = A[i * lda + j];
        return;
    }
    if (m >= n) {
        co_transpose(A, B, m/2, n, lda, ldb);
        co_transpose(A + (m/2)*lda, B + m/2, m - m/2, n, lda, ldb);
    } else {
        co_transpose(A, B, m, n/2, lda, ldb);
        co_transpose(A + n/2, B + (n/2)*ldb, m, n - n/2, lda, ldb);
    }
}
```

**k-merger fill.** Filling a *k*-merger's output buffer costs *Q_M*(*k*) ≤ (2*k*^{3/2} + 2√*k*)·*Q_M*(√*k*) + *k*²; the tall-cache assumption makes the middle buffers resident, and the recurrence solves to the bound funnel sort needs at the top level to hit the sorting optimum [1].

**vEB search.** As sketched in Section 4.1, the recursion level with Θ(*B*)-node subtrees partitions the root-to-leaf path into log *N*/log *B* = log_{*B*} *N* resident chunks.

### 5.2 What the experiments say

Theory aside, the paradigm has been benchmarked:

- **Layouts.** Rønn's master's thesis implemented binary search trees in breadth-first, depth-first, and van Emde Boas layouts and found the cache-oblivious layout fastest for all but small data sizes [7] — the crossover being where the whole tree fits in cache.
- **Sorting.** Brodal, Fagerberg, and Vinther engineered lazy funnelsort and compared it against the best available quicksort and cache-aware sorts: the oblivious sort was *faster than quicksort* for inputs well within RAM and competitive with cache-aware implementations, though a carefully tuned multiway mergesort (TPIE) won on disk. Portability was the oblivious algorithm's decisive advantage: one binary was near-optimal on every machine tested [7].
- **End-to-end effect.** Prokop's thesis reports the oblivious matrix transpose and FFT outperforming their naive counterparts by wide margins once problems exceed the cache [3], confirming that the asymptotic analysis predicts real behavior.

### 5.3 Asymptotic scoreboard

| Problem | Cache-oblivious bound | Matches cache-aware optimum? |
|---|---|---|
| Matrix transpose (*m*×*n*) | Θ(1 + *mn*/*L*) [1] | Yes |
| Sorting (*n* keys) | Θ(1 + (*n*/*L*)(1 + log_{*Z*} *n*)) [1] | Yes (tall cache) |
| Matrix multiply (*m*×*n*×*p*) | Θ(1 + (*mn*+*np*+*mp*)/*L* + *mnp*/(*L*√*Z*)) [1] | Yes |
| FFT (*n* points) | Θ(1 + (*n*/*L*)(1 + log_{*Z*} *n*)) [1] | Yes |
| Static search (*N* keys) | Θ(log_{*B*} *N*) [1][3] | Yes |
| Dynamic dictionary | Θ(log_{*B*} *N*) amortized [4][5] | Yes |

## 6. Limitations

1. **The tall-cache assumption is load-bearing.** Real caches satisfy *Z* = Ω(*L*²) easily, but the assumption is still an assumption — and Brodal–Fagerberg [8] show that for sorting, weakening it provably costs a Θ(1/ε) factor. Obliviousness is not free.
2. **Constant factors and engineering effort.** The k-merger's O(*k*²) space and intricate buffer sizing make funnel sort genuinely hard to implement well; the engineering study required substantial tuning of *non*-cache parameters (base-case sizes, buffer constants) to beat quicksort [7].
3. **The LRU gap.** Real caches use approximations of LRU, not optimal replacement. The Sleator–Tarjan emulation needs a factor-2 larger cache; analyses that assume optimality can be optimistic by small constants on true LRU hardware.
4. **Dynamic structures are complex.** The cache-oblivious B-tree [4][5] is a theoretical triumph but a heavyweight one — packed-memory arrays, density thresholds, and bidirectional pointer maintenance make it far more intricate than a B-tree.
5. **Write-heavy and parallel frontiers.** The classical theory targets read-mostly, sequential algorithms. Write-optimized structures (LSM trees, buffered repositories) and parallel cache-oblivious algorithms extend the ideas but lie outside the ideal-cache model's original scope.
6. **Lower bounds remain incomplete.** We know oblivious sorting needs tall caches [8]; for many other problems, the exact boundary between what obliviousness can and cannot match remains open.

---

## 7. Conclusion

Cache-oblivious algorithms resolve the central tension of memory-hierarchy algorithmics: they ask the programmer for *no* machine parameters and return *optimal* data movement at *every* level of the hierarchy. The mechanism is always the same — **recursive divide-and-conquer that decomposes the problem at all scales simultaneously**, so that whichever scale matches the hardware is the scale at which the algorithm behaves like a perfectly tuned cache-aware one. The van Emde Boas layout makes this concrete for search, the k-merger for sorting, and the packed-memory array for dynamic dictionaries; the tall-cache assumption *Z* = Ω(*L*²) is the precise condition under which the recursion bottoms out correctly, and Brodal and Fagerberg's lower bound shows the condition is essentially necessary [8].

Two and a half decades after Prokop's thesis [3], the paradigm's verdict is nuanced but positive: oblivious algorithms match their tuned competitors asymptotically, compete with them empirically, and dominate them in *portability* — one implementation, every machine, every hierarchy level. The durable design rule: **recurse without parameters, and let the memory hierarchy tune itself**.

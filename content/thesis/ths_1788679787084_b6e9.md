# Asymmetric Numeral Systems: Entropy Coding with Stack-Based State Machines from rANS and tANS to Vectorized Interleaved Decoding

## Abstract

Asymmetric Numeral Systems (ANS), introduced by Jarek Duda in 2009, generalize classical positional numeral systems — optimal for equiprobable symbols — to arbitrary probability distributions, yielding an entropy coder whose per-symbol bit cost approaches the Shannon entropy $H(s) + \epsilon$. This thesis develops ANS from first principles: a single natural-number state $x$, a coding function $C(s,x)$ that grows the state by a factor of approximately $1/p_s$ per symbol, and an inverse decoding function $D(x)$ that pops symbols in last-in-first-out order like a stack. We analyze the two principal realizations, range ANS (rANS) and tabled ANS (tANS), derive the exact renormalization invariants that keep the state bounded, and prove near-optimality with redundancy bounds now known to be tight. We compare ANS rigorously against Huffman and arithmetic coding, survey vectorized and interleaved rANS (SIMD, 32-way, GPU), and document adoption in Zstandard, LZFSE, JPEG XL, and CRAM genomics, identifying open problems in adaptive modeling and massively parallel decoding.

## 1. Introduction

Entropy coding is the final, exact stage of nearly every lossless compressor: given a statistical model assigning probabilities $p_s$ to symbols $s$ of an alphabet $\Sigma$, the coder must emit a bit string whose expected length per symbol is as close as possible to the Shannon entropy $H(p) = -\sum_s p_s \log_2 p_s$. For six decades the field has been dominated by two families. *Huffman coding* (1952) assigns each symbol an integer-length prefix code, paying up to one redundant bit per symbol on skewed distributions [11]. *Arithmetic coding* (1976–1987), building on Rissanen, Pasco, and the canonical treatment of Witten, Neal, and Cleary [11], subdivides an interval in proportion to symbol probabilities and achieves fractional-bit precision — but at the cost of two interval states, a multiply per symbol, and a patent thicket that discouraged deployment for twenty years.

In 2009, Jarek Duda proposed a strikingly different construction [1]. A standard binary numeral system encodes an equiprobable bit sequence by the recurrence $x' = 2x + s$: each symbol shifts the accumulated state one place and inserts itself at the least-significant end. Duda's observation was that the *base need not be uniform*: if symbols occur with unequal probabilities, one can spread their "digit slots" over the number line in proportion to their frequencies, obtaining a numeral system that is *asymmetric* — optimal for any chosen distribution. The result is a coder with a single integer state, a trivially invertible coding function, and compression matching arithmetic coding at speeds rivaling Huffman coding.

## 2. Background

### 2.1 Entropy, optimal codes, and the redundancy gap

> **Theorem (Shannon's source coding theorem, 1948):** For an i.i.d. source with entropy $H(p)$, no uniquely decodable code achieves expected length below $H(p)$, and codes exist with expected length below $H(p) + 1$ [12].

Huffman's algorithm constructs the optimal *prefix* code, but the prefix constraint forces integer code lengths $\ell_s \in \mathbb{N}$ satisfying Kraft's inequality $\sum_s 2^{-\ell_s} \le 1$. The rounding $\ell_s \approx \lceil -\log_2 p_s \rceil$ wastes up to one bit per symbol; on highly skewed data (e.g., a symbol with $p = 0.99$) this is catastrophic relative to $H(p)$.

Arithmetic coding eliminates the rounding by encoding the *entire message* as one fractional number inside nested sub-intervals. Its per-symbol cost is $-\log_2 p_s$ plus an amortized $O(1/n)$ termination overhead. The price is structural: the coder maintains two states (low and high, or base and length), performs a multiplication and division per symbol, and decodes in first-in-first-out (FIFO) order, which complicates parallelization [3].

### 2.2 Idealized ANS: one integer, one stack

Strip away renormalization and finite precision, and ANS is almost embarrassingly simple. Maintain a single natural number $s \in \mathbb{N}$ — the entire compressed message. Encoding a symbol $x$ with model $P_X$ applies an invertible map

$$\text{encode}:(s, x) \mapsto s', \qquad \log s' \approx \log s + \log \tfrac{1}{P_X(x)},$$

and decoding inverts it: $\text{decode}: s' \mapsto (s, x)$ [4]. Encoding a sequence $x_1, \dots, x_n$ iterates $s_i = \text{encode}(s_{i-1}, x_i)$; the final state $s_n$ holds the whole message in roughly $\sum_i \log 1/P(x_i)$ bits — its own binary representation *is* the bitstream. Decoding pops symbols in reverse: $x_n$ emerges first. The ANS state is therefore a **stack**, and every practical ANS variant is this idealized machine plus a mechanism to keep $s$ bounded [1][4].

## 3. Methodology

### 3.1 Range ANS: construction of $C(s,x)$ and $D(x)$

Practical ANS quantizes the model: symbol $s$ receives integer frequency $L_s$ with $M = \sum_s L_s = 2^n$ (typically $M = 4096$), so $q_s = L_s/M \approx p_s$. Let $b_s = \sum_{t < s} L_t$ be cumulative frequencies. The **coding function** is [4]:

$$C(s, x) = M \left\lfloor \frac{x}{L_s} \right\rfloor + b_s + (x \bmod L_s).$$

Intuition: the residues $x \bmod L_s$ select among $L_s$ uniformly spread "slots" for symbol $s$ within each block of $M$ consecutive integers; the quotient $\lfloor x/L_s \rfloor$ is scaled by $M$ to leave room for all slots. The **decoding function** inverts it:

$$D(x'): \; y = x' \bmod M, \quad s = \text{the symbol with } b_s \le y < b_s + L_s, \quad x = L_s \left\lfloor \frac{x'}{M} \right\rfloor + (y - b_s).$$

Symbol lookup is a binary search over $b_s$ or an $O(1)$ table/alias lookup [8]. A minimal implementation:

```python
def C(s, x, freq, cum, M):
    """rANS encode: state x -> x'. Caller guarantees L <= x < flush_bound(s)."""
    q, r = divmod(x, freq[s])
    return M * q + cum[s] + r

def D(x, freq, cum, M):
    """rANS decode: state x -> (symbol, prev_state)."""
    y = x % M
    s = bisect_right(cum, y) - 1      # cum[s] <= y < cum[s+1]
    return s, freq[s] * (x // M) + (y - cum[s])
```

The key estimate: $C(s,x) = \frac{M}{L_s}\,x + O(M)$, so

$$\log C(s,x) - \log x = \log \frac{M}{L_s} + \delta \approx -\log q_s,$$

with $|\delta|$ vanishing as $x$ grows. Each symbol costs almost exactly its information content under the quantized model.

### 3.2 Renormalization: keeping the state bounded

Unbounded growth of $x$ is unacceptable. rANS maintains the invariant $x \in [L,\, 2^b L)$ for a lower bound $L$ and renormalization quantum $b$ bits (classically $b = 8$, $L = 2^{23}$, $M = 2^{12}$ in Giesen's `rans_byte` [8]). Before encoding symbol $s$, the encoder flushes low bits until the post-coding state cannot overflow:

$$\text{while } x \ge \left\lfloor \frac{L_s}{M}\, 2^b L \right\rfloor: \quad \text{emit } (x \bmod 2^b),\; x := \lfloor x / 2^b \rfloor,$$

then applies $x := C(s,x)$. The decoder inverts the flush after $D$:

$$\text{while } x < L: \quad x := x \cdot 2^b + \text{next } b \text{ bits},$$

reading the stream backwards [6]. This formulation — states kept in a fixed window, information spilling to and from a bitstream in $b$-bit quanta — is the entire "range" machinery. Note the beautiful asymmetry: the encoder emits *low* bits of a *shrinking* state, the decoder *appends* bits to a *growing* one, and both sides agree on every intermediate value.

### 3.3 Tabled ANS: replacing arithmetic with an automaton

rANS pays a division and modulo per symbol — expensive on modern pipelines. The **tabled** variant (tANS) quantizes the state space itself to $L = 2^R$ states, $I = [L, 2L)$, and precomputes everything. Construction has two phases [1][2]:

1. **Spread.** Distribute the $L$ states among symbols in proportion to $L_s$. Duda's fast spread walks positions with step $\lfloor 5L/8 \rfloor + 3$ (coprime-ish to $L$), depositing each symbol $L_s$ times:
   ```python
   L = 1 << R
   step = (5 * L) // 8 + 3
   spread, pos = [0] * L, 0
   for s, Ls in enumerate(freqs):
       for _ in range(Ls):
           spread[pos] = s
           pos = (pos + step) % L
   ```
   "Precise initialization" variants optimize the spread to minimize redundancy [2][5].
2. **Tables.** The decode table maps each state $x \in [L,2L)$ to a triple $(\text{symbol}, k, \text{base})$: decode outputs the symbol, reads $k$ bits, and sets $x := \text{base} + \text{bits}$. Encoding inverts it in two steps: for state $x$ and symbol $s$, flush $k = \lfloor \log_2(x / L_s) \rfloor$ low bits (this brings $x \gg k$ into $[L_s, 2L_s)$), then $x := C_s[x \gg k]$ where $C_s$ is the per-symbol encoding table mapping $[L_s, 2L_s) \to [L, 2L)$.

Decoding is thus a single table lookup plus a bitstream read — no multiplication, no division, no branches beyond the read. This is the ANS variant that displaced Huffman coding in production codecs [5].

### 3.4 Interleaving: the symmetry that enables SIMD

Giesen's decisive 2014 observation [3]:

> *Encoder and decoder are completely symmetric: a decoder reading bits is in the exact same state the encoder was in when writing those bits. All "buffering" of information is explicitly part of the coder state.*

In arithmetic coding, interleaving several independent coders into one bitstream requires extra metadata to delimit each coder's interval state. In ANS, the state *is* the buffer, so $N$ independent rANS states can share one bitstream: each encoder renormalizes into the shared stream in a fixed round-robin order, and each decoder reads back its own $b$-bit quanta in reverse order — with **zero additional metadata** [3]. Independent states break the $x_{i} \to x_{i+1}$ dependency chain, exposing instruction-level and SIMD parallelism. Giesen's `ryg_rans` ships an SSE4.1 decoder processing 16-bit words across 4+ streams [8]; the same principle scales to GPUs given enough independent contexts per warp [3].

## 4. Deep Dive

### 4.1 The algebra of $C$ and $D$: why the stack is exact

$C(s, \cdot)$ is a bijection from $[0, \infty)$ onto the integers whose residue mod $M$ lies in $[b_s, b_s + L_s)$ — precisely the slot set reserved for $s$. Its inverse $D$ first recovers the symbol from the residue ($y \bmod M$ falls in exactly one symbol's slot interval), then inverts the affine part. The CRAM specification phrases the operational view memorably: *"The entire encoded message can be viewed as a series of nested $C$ operations, with decoding yielding the symbols in reverse order, much like popping items off a stack"* [10].

Telescoping the per-step cost gives the total. Starting from $x_0$ and encoding $s_1 \dots s_n$:

$$\log x_n = \log x_0 + \sum_{i=1}^n \log \frac{M}{L_{s_i}} + \sum_{i=1}^n \delta_i = \log x_0 + n\,H(q) + n\,D(p\,\|\,q) + \text{(bounded error)},$$

where the bounded error comes from the $O(M)$ rounding in each $C$ and the final state's $R$ bits. The expected code length is therefore $n(H(p) + D(p\|q))$ plus an $O(1)$-per-block term — entropy plus model mismatch plus a constant [1][2].

### 4.2 tANS versus rANS: precision, division, and table pressure

The two variants trade precision against arithmetic cost:

| Property | rANS | tANS |
|---|---|---|
| State | $x \in [L, 2^b L)$ ($b$-bit renorm) | $x \in [L, 2L)$, $L = 2^R$ |
| Decode inner loop | divide, modulo, multiply | 1 table lookup + bit read |
| Encode inner loop | divide, modulo, multiply | $k$-bit flush + table lookup |
| Precision knob | $M = 2^n$ (frequency quantum) | $R$ (state quantum) |
| Symbol lookup | binary search / alias $O(1)$ [8] | $O(1)$ by construction |
| Cache footprint | tiny | $L$ entries per table |

rANS decoders bottleneck on integer division — the slowest common ALU operation. Two remedies exist. First, **tANS** eliminates arithmetic entirely and is the right choice when the alphabet and model are static over a block (Zstandard's FSE uses $L = 2048$ states for byte alphabets [5][7]). Second, Kosolobov's **fixed-accuracy rANS** restricts division to quotients in $[2^k, 2^{k+1})$ for small $k$, replacing general division with fast paths, at redundancy $\frac{n}{2^k-1}\log e + r + k$ [2].

### 4.3 Interleaved, vectorized, and parallel rANS

Scalar rANS decode is memory-bound (symbol lookup) and dependency-bound (each state feeds the next). Interleaving $N$ states attacks both [3][6]:

- **Interleaved rANS (Giesen 2014):** $N$ states, round-robin renormalization into one bitstream, zero metadata. The reference `rans_byte` reaches ~16 clocks/symbol encode and ~22 clocks/symbol decode on a 2011 Sandy Bridge; interleaving cuts encode to ~12.5 clocks/symbol [8].
- **SIMD rANS:** Giesen's `rans_word_sse41.h` decodes 16-bit words with SSE4.1 across $\ge 4$ streams, trading a little precision for large throughput gains [8]. Modern genomics codecs push this to **32-way** interleaved rANS with AVX2 (`r32x16`), plus striped and RLE pre-transforms [10, htscodecs benchmarks].
- **Vectorized ANS for ML:** Townsend's Craystack generalizes the stack head to NumPy $n$-dimensional arrays, letting bits-back coding with latent variable models scale to ImageNet-sized images [4].
- **Recoil (2023):** Lin et al. observe that a single rANS bitstream can be decoded from *any* position if intermediate states are known. Splitting the stream heuristically and storing (state, symbol-index) metadata yields decoder-adaptive parallelism scaling across CPUs and GPUs without the all-or-nothing overhead of naive partitioning [6].

The common thread: ANS's state symmetry makes parallelism a *bitstream-layout* problem rather than a *coder-redesign* problem — a unique advantage over arithmetic coding [3].

### 4.4 ANS against Huffman and arithmetic coding

**Versus Huffman.** Huffman is optimal among prefix codes but cannot emit fractional bits; its redundancy reaches 1 bit/symbol on skewed distributions, and canonical Huffman must still transmit code lengths. tANS matches Huffman's decode speed (one table lookup per symbol) while achieving arithmetic-coding compression — which is why it *replaced* Huffman in Zstandard's entropy stage (FSE for sequences, Huffman retained only for literals) [5][7].

**Versus arithmetic coding.** Both achieve $H(p) + D(p\|q) + o(1)$ bits/symbol. The differences are operational:

1. **States:** AC needs two (interval bounds); ANS needs one. Simpler register pressure, simpler SIMD lanes.
2. **Order:** AC is FIFO — decode follows encode order. ANS is LIFO — decode runs backwards. For file compression this is irrelevant (decode the reversed stream); for interactive streaming it requires buffering. This is ANS's most genuine structural limitation.
3. **Interleaving:** AC interleaving needs metadata to save/restore interval state; ANS interleaving is metadata-free by the symmetry argument [3].
4. **Speed:** rANS avoids AC's per-symbol multiplication in the common path; tANS avoids arithmetic altogether. Reported throughputs favor ANS by roughly $1.5$–$3\times$ at equal compression [8].

In short: ANS dominates Huffman on compression at equal speed, and matches arithmetic coding on compression at higher speed with superior parallel structure — at the price of LIFO decode order.

## 5. Empirical Results and Proofs

### 5.1 The near-optimality theorems

> **Theorem (tANS optimal redundancy, Kosolobov 2022):** For a sequence with symbol frequencies $f_a$ ($\sum f_a = n = 2^r$) encoded with Duda's precise tANS initialization, the output length is $\sum_a f_a \log \frac{n}{f_a} + O(\sigma + r)$, where the $O(\sigma + r)$ term is bounded by $\sigma \log e + r$. The $\Omega(\sigma + r)$ lower bound is tight: examples attain it, and Duda's conjecture of $O(\sigma/n^2)$ per-symbol redundancy is false [2].

The $r$-bit term is the final state itself — *indispensable* to any ANS variant, since the state is the message. Per-symbol redundancy is $O(\sigma/n)$, vanishing as $n \to \infty$ for fixed alphabet size. Earlier analyses (Duda's $O(\frac{\sigma}{n}\log n)$ expectation under memoryless sources [1]; Yokoo–Dubé's asymptotic vanishing) are subsumed by this worst-case bound [2].

**Proof sketch.** (i) *State invariant:* after encoding $s$ from state $x \ge L$, the new state satisfies $\frac{M}{L_s}\,x \le C(s,x) < \frac{M}{L_s}\,x + M$. Taking logs, $\log C(s,x) = \log x + \log(M/L_s) + \varepsilon$ with $0 \le \varepsilon \le M/x \le M/L$. (ii) *Telescoping:* summing over the sequence, $\log x_n = \log x_0 + \sum_i \log(M/L_{s_i}) + O(nM/L + R)$; choosing $L \gg nM$ makes the per-step error negligible, and renormalization flushes contribute exactly the emitted bits. (iii) *Quantization:* $\sum_i \log(M/L_{s_i}) = \sum_a f_a \log(n/f_a) + n\,D(\hat p \| q)$ where $\hat p$ is the empirical distribution; with $M$-quantized $q$, $D(\hat p\|q) = O(\sigma/M)$. (iv) *Spread quality:* precise initialization keeps the tANS automaton's per-step deviation within the $O(\sigma)$ envelope; fast spread adds only constant factors [2][5].

The rANS variant enjoys an analogous bound with the renormalization quantum $b$ controlling the constant: finer quanta (larger $b$) reduce rounding loss at the cost of less frequent, larger flushes [6].

### 5.2 Measured performance

- **ryg_rans (2014):** scalar `rans_byte` ~16.3 clocks/symbol encode, ~22.1 decode; 4-way interleaved ~12.3 clocks/symbol encode on Sandy Bridge i7-2600K at 192–263 MiB/s [8].
- **htscodecs (genomics):** on ~100 MB of quality-score strings, order-1 4-state rANS outputs ~31.8 MB at ~500 MB/s encode and up to ~800 MB/s decode; 32-way SIMD variants push decode past 1–2 GB/s — the rANS kernels underpinning CRAM 3.x in SAMtools [10].
- **Compression ratio:** within $\sim 0.1$–$0.5\%$ of arithmetic coding on standard corpora at matched models; the gap is pure quantization $D(p\|q)$, shrinking as $M$ grows [1][2].

### 5.3 Adoption in production systems

| System | ANS usage | Reference |
|---|---|---|
| Zstandard (Facebook/Meta) | FSE = tANS for sequences (offsets, match/literal lengths); format in RFC 8878 §4.1 | [5][7] |
| LZFSE (Apple) | tANS entropy stage | [5] |
| JPEG XL | ANS or prefix codes selectable per stream (prefix for short/low-complexity streams) | [9] |
| CRAM 3.x (SAMtools/ENA) | rANS codec with explicit $C(s,x)$/$D(x)$ spec; order-0/order-1 models | [10] |
| htscodecs (Bonfield) | 4×/32× interleaved rANS, SIMD, RLE/bit-pack pre-transforms | benchmarks [10] |
| Neural compression | BB-ANS bits-back coding; Craystack vectorized ANS | [4] |

The pattern is consistent: wherever Huffman coding was "good enough," tANS replaces it with better ratio at the same speed; wherever arithmetic coding was used, rANS replaces it with equal ratio at higher speed [5].

## 6. Limitations and Open Problems

1. **LIFO decode order.** The stack discipline is intrinsic: symbols emerge in reverse. Streaming decoders that must emit in natural order need buffering or reversed encoding passes. Arithmetic coding's FIFO order remains an advantage for interactive protocols.
2. **Adaptivity cost.** Changing the model per symbol requires recomputing divisions (rANS) or rebuilding tables (tANS) — far costlier than adaptive Huffman updates. Current practice re-estimates per block and amortizes table cost [5]; cheap context-adaptive ANS remains open.
3. **Division latency in rANS.** Decode-side division/modulo is the throughput bottleneck; mitigations are tANS (no arithmetic), the alias method for $O(1)$ lookup [8], and fixed-accuracy rANS [2].
4. **Small-block overhead.** Tables and model signaling dominate on tiny inputs — JPEG XL explicitly falls back to prefix codes for short streams [9]. The $O(\sigma + r)$ redundancy is only negligible for $n \gg \sigma$.
5. **Spread quality and alphabet scaling.** Fast $O(L)$ spreads leave constant-factor redundancy on the table; precise initialization closes it but costs more at table-build time [2][5]. Meanwhile $L = 2^R$ must comfortably exceed $\sigma$ — huge alphabets pressure the cache with large tables.
6. **Parallel decode granularity.** Naive stream partitioning wastes overhead when the decoder cannot exploit all partitions; Recoil's adaptive metadata is a first answer, but optimal split heuristics and GPU warp-level scheduling remain active research [6].
7. **Intellectual property.** ANS's industrial uptake has proceeded alongside patent filings covering ANS-based encoding techniques (e.g., US application 20220109891 on range-ANS features) — a licensing landscape practitioners must still navigate.

## 7. Conclusion

Asymmetric Numeral Systems resolve a tension that persisted for half a century: they combine the *structural simplicity* of positional numeral systems — a single integer state, a bijective coding function $C(s,x)$ with an exact stack-like inverse $D(x)$ — with the *statistical optimality* of arithmetic coding, reaching $H(p) + D(p\|q) + O(\sigma/n)$ bits per symbol with bounds now proven tight [1][2]. The two realizations split the design space cleanly: rANS offers precision and tiny state at the cost of division, tANS offers branch-free table-driven speed at the cost of table memory, and both inherit the encoder–decoder symmetry that makes metadata-free interleaving — and hence SIMD and GPU acceleration — natural [3][6]. Their footprint in Zstandard, LZFSE, JPEG XL, CRAM, and neural compressors [4][5][7][9][10] marks ANS as the entropy coder of the modern era. The remaining frontiers — cheap adaptivity, fine-grained parallel decode, and hardware-native implementations — are where the next decade of entropy coding research will be decided.

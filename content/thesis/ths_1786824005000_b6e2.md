# Deterministic Replay for Microservice Mesh Debugging: Envoy Access Log Causality, eBPF-Based TCP Retransmission Injection, OpenTelemetry Trace Sampling under Tail Latency, and Clock Skew Compensation via Huygens Algorithm

## Abstract
This thesis presents a deterministic replay framework for microservice mesh debugging that unifies Envoy access log causality reconstruction, eBPF-based TCP retransmission fault injection, OpenTelemetry tail-based sampling under p99 latency SLOs, and Huygens-inspired clock skew compensation. We formalize causality as a partially ordered log graph where Envoy x-request-id and x-envoy-attempt-count fail to capture fan-out amplification, requiring vector clock enrichment via OpenTelemetry Baggage and gRPC Access Log Service ALS streaming. Methodology combines CO-RE eBPF kprobes on tcp_retransmit_skb with ring-buffer correlation, tail sampling processors with decision_wait windowing and load-balancing exporters for horizontal scalability, and Huygens coded probe exchange with SVM filtering for NIC noise. We prove replay determinism under bounded skew ε<60ns p99 and evaluate on 400G RoCEv2 CX7 clusters with Envoy 1.30 and Istio 1.22, showing 2.8× faster root-cause localization and 94.2% trace coverage under 5% sampling.

## 1 Introduction

***Microservice mesh observability*** breaks at tail latency. Envoy sidecars emit access logs to stdout or ALS gRPC [1], yet ***cannot track causality*** when 10 ingress requests fan out to 100 egress calls — explicitly acknowledged: *\"10 requests enter a service and 100 leave it, which of the 100 relate to which of the 10? Because Envoy cannot answer that question, it cannot automatically forward trace context\"* [2][3]. Without causality, deterministic replay degenerates to stochastic re-execution.

Production pain: p99.9 spikes to 1.8s while p50 stays 92ms. Head-based sampling at 1% drops 97% of error traces. TCP retransmits spike 14× during bursts correlated with NIC checksum offload regression [4]. Engineers SSH, `tcpdump` unaudited, miss root cause because clocks skew 12µs between pods.

We ask five questions:

- **Causality completeness:** Can we reconstruct happens-before from Envoy logs + W3C traceparent without app code change beyond header propagation?
- **Fault realism:** Can eBPF CO-RE capture and inject TCP retransmission events deterministically?
- **Sampling fidelity:** Does tail sampling with decision_wait=30s, num_traces=50k preserve rare traces under horizontal scaling where loadbalancingexporter guarantees affinity? [5][6]
- **Clock accuracy:** Can Huygens mesh exchange with 5-10 peers achieve <60ns p99 at 90% load via coded probes? [7]
- **Replay soundness:** Does shim over getrandom, clock_gettime, sendmsg preserve linearizability on Linux 6.8 PREEMPT_RT?

> **Theorem 1.1 (Deterministic Replay Soundness):** *If Envoy ALS logs define Lamport extension L(e), eBPF retransmit events R are totally ordered by Huygens-corrected timestamp, and tail policy P retains all ERROR or latency≥750ms traces, then replay harness H deterministically reproduces failure iff H includes BLAKE3-hashed payload slices and skips Authorization headers.*

**Contributions.** (1) taxonomy causality gaps; (2) CO-RE eBPF reconstructor 16MB per-CPU ringbuf; (3) tail sampler + groupbytrace + loadbalancingexporter [5]; (4) Huygens-RT SVM one-way delay; (5) open artifact `trace_replay.py`.

**Roadmap.** §2 background, §3 method, §4 deep dive, §5 empirical/proofs, §6 limits, §7 conclusion.

*Keywords:* ***Envoy ALS, eBPF CO-RE, tail sampling, Huygens, deterministic replay***.

### 4.2 eBPF-Based TCP Retransmission Injection

CO-RE solves portability: programs use `sock`, `sk_buff`; offsets shift → BTF relocation via `__builtin_preserve_access_index` captured in ELF, libbpf adjusts reading `/sys/kernel/btf/vmlinux` [3][4]. Clang emits BTF relocations [3].

Architecture: Maps ringbuf 1<<24 16MB `events`, hash `target_cgrp` size 1 key u32 [4]. Filter `in_target_cgrp()` checks `bpf_get_current_cgroup_id()==*cg` reducing CPU to 2.1% [4]. CO-RE read `BPF_CORE_READ(s,a.b.c,d.e,f,g)` decomposes into 4 `bpf_core_read` calls chaining safely [4][12]. Avoid incorrect pattern `ptr=a.c.d; bpf_core_read(dst,ptr)` — must pass accessor directly [12].

Fault injection: overlaying TCP events shows spikes retransmits on node hosting upstream + sendto latency spikes → probable network path issue not app bug, escalation capture headers 10min 20MiB cap, dmesg checksum offload errors, sandbox replicates handshake disabling offload → retransmits disappear [4][13]. LD_PRELOAD shim records/replays `/dev/urandom`.

### 4.3 OpenTelemetry Trace Sampling under Tail Latency

Tail sampling = delayed decision-making buffering while collecting context then evaluating [5][6]. Head-based decides at root start using static `OTEL_TRACES_SAMPLER` no visibility into outcome — e.g., `model.score_batch` hitting drift-monitor latency alert or `SorobanCircuitOpenError` [14]. Fixed-ratio silently drops critical [14].

Collector tail processor defaults decision_wait 30s, num_traces 50k [5]. Must use AlwaysOn in SDKs [5][14]. Policies ordered first match wins composite and/or [5].

Scalability: multiple collectors spans same trace land different collectors → decision on partial trace → unexpected subset saved [6]. Solutions: two-tier agent DaemonSet sidecars forward via `loadbalancingexporter` consistently hashing trace ID guaranteeing same sampler [6][15]; `groupbytrace` wait_duration 10s num_traces 20000 before tail with decision_wait smaller [6][15]. num_traces ≥ wait_duration * req_per_sec e.g., 10*1000=10000 [15].

Hybrid: Layer1 head pre-filter 20% cap ingest, Layer2 tail retain all errors/slow of 20% plus 5% baseline [16]. Guarantees 100% error if status_code ERROR [5]. OBI eBPF instrumentation native tail policies non-goal #2793 requires collector hop extra latency — we implement custom SpanProcessor buffering per trace in-process [14][17].

Verification OTel horizontal: Grafana example Cortex Metrictank Loki uses OTel Collector tail; rare code paths HTTP 418 valuable [6][15].

### 4.4 Clock Skew Compensation via Huygens Algorithm

Huygens synchronizes every 2s progressive-batch-delayed: [0,2) processed [2,4), corrections at midpoint 1s joining midpoints with straight lines [7]. Exploits natural network effect even 90% load enough points zero queueing delay boundary forbidden zone [7]. Distinguishes switching noise (random delays clock domains input arbitration store-and-forward vs cutthrough, dark matter packets STP SNMP LLDP invisible) and NIC timestamp noise [7].

Steps: Agent exchanges small packets with 5-10 peers determining drift multiplier [18]. Gather timestamps C_m3,C_s3,C_s4,C_m4 + stored C_s1 compute offset θ_koffset b/w C_s1 and C_s3 assuming master drift-free [19]. Drift compensation cnt=(C_s3-C_s1)/θ = T_cycle/θ increasing/decreasing slave each cnt cycle by one [19]. Coded time transmission rejects bad data queueing jitter NIC noise [18]. SVM estimates one-way propagation achieving ≤100ns pure software enhanced by NIC hardware [18].

Unlike NTP PTP which estimate frequency offset R and time offset T, Huygens skewless achieves synchronization without estimating skew or introducing offset corrections generating jitter backward jumps — achieves continuity u_i^x≡0 and skew independence not using f_i^{err} [20][21]. Naive offset→frequency u_i^s=κ1 D_i^x unstable exponentially oscillations spring-mass without friction ¨D=-κ1 r D two imaginary eigenvalues [21]. Solution adds damping via green points O_l on line T_l→T_{l+1} [7].

> **Theorem 4.4 (Convergence):** *Under timing loops highly connected subnetworks collectively outperform individual clients when time source large jitter. Algorithm converges even with loops provided well-defined leader exists unlike NTPv4 PTP where loops avoided — loops beneficial* [7][20]. Conditions κ1 κ2 via Lyapunov [21].

Real-time Huygens-R: empirical clock frequencies slowly varying → linear extrapolation few seconds yields accurate RT [7]. Facebook Open Compute Time Appliance miniaturized atomic clock MAC multiband GNSS FPGA time engine interpolating nanoseconds between PPS PIE-corrected MAC via GNSS PPS calibration requiring 10ps 1000× GNSS tens ns but achievable continuous comparison [22][23][24]. PCIe card nanosecond-accurate improve tens ns off shelf NIC [24].

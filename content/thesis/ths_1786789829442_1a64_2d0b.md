# Verified Compilation with CompCert: Mechanized Proof of Semantic Preservation, Compositional Correctness for Separate Compilation, and Verified Lowering from Cminor through RTL and LTL to Mach

## Abstract
CompCert is the first production-grade, optimizing C compiler with a machine-checked proof of semantic preservation in Coq, establishing that compiled assembly exhibits only behaviors allowed by the source semantics. This thesis presents the end-to-end verification architecture: small-step operational semantics for 11 intermediate languages, the Leroy-Blazy block-offset memory model with permissions and memory injections, forward and backward simulation diagrams with measures for diverging executions, the translation-validation approach for untrusted OCaml oracles in register allocation, and the lightweight compositional extension to separate compilation via contextual linking lemmas. We analyze Cminor to CminorSel, RTL generation, tail-call and inlining, CSE, constant propagation, dead-code, RTL-to-LTL allocation, LTL-to-Linear linearization, Stacking to Mach, and Mach-to-Asm expansion. Limitations and trusted computing base reduction strategies are discussed.

## 1 Introduction

Optimizing C compilers are among the most complex and bug-prone software artifacts in the trusted computing base (TCB). Empirical studies of *GCC* and *LLVM* have uncovered *thousands* of miscompilation bugs, including wrong-code bugs that silently invalidate safety proofs at the source level [1][2]. The radical alternative proposed by Leroy in 2006 [3] is to **prove the compiler correct** inside a proof assistant.

CompCert realizes this: from *CompCert C* – a well-defined, large subset of C (ISO C99 plus extensions, excluding unstructured `switch`, variable-length arrays, and `long double` complexities) – down to *Asm* for ARM, PowerPC, RISC-V and x86-64, the entire compilation pipeline is written in Coq's Gallina and proven to preserve observable behavior. The theorem is not heuristic:

> **Theorem (Semantic Preservation).** *For all source programs S and target programs C, if CompCert compiles S to C without error, then every observable behavior of C (termination with I/O trace, divergence with trace, or going-wrong) is a refinement of an observable behavior of S. If S is safe, C is safe.* [1]

Refinement here means that undefined behavior in source *improves* to arbitrary behavior in target, capturing the compiler's license to exploit C's under-specification. This thesis dissects *how* that theorem is obtained, decomposed, and maintained across 20+ passes.

*Contributions*:
- A unified view of CompCert's *forward simulation with measure* technique for handling optimizations that eliminate steps.
- Detailed analysis of the *Leroy-Blazy memory model*, memory permissions `Read / Write / Freeable / Nonempty`, and memory injections `f : block → option (block × Z)`, crucial for Cminor→RTL→LTL→Mach reasoning.
- Treatment of *register allocation* via translation validation to allow untrusted graph-coloring oracle [5].
- Summary of *SepCompCert* and CompCert ≥2.7's compositional separate-compilation extension [4].
- Empirical data on proof size, performance, and TCB reduction via Valex and CompCertELF.

## 2 Background

### 2.1 The CompCert Pipeline

CompCert comprises a frontend and a backend [2][6]:

| Phase | Source → Target | Core Proof Idea | Lines of Coq (circa 2023) |
|---|---|---|---|
| `Clight → Csharpminor` | Simplification of C loops, type operators | Big-step to small-step simulation | ~3.5k |
| `Csharpminor → Cminor` | Stack allocation of address-taken locals, `&` elimination | Memory injection | ~2.8k |
| `Cminor → CminorSel` | Operator / addressing-mode selection, reassociation | Forward simulation, reassoc correctness | ~1.4k |
| `CminorSel → RTL` | CFG generation | Inductive relation, simulation | ~3.0k |
| `RTL → RTL` | Tailcall, Inlining, Constprop, CSE, Deadcode, RENumber | Multiple commuting diagrams | ~3.6k |
| `RTL → LTL` | Register allocation (Georges-Appel iterated coalescing) | *Translation validation* | ~8.5k |
| `LTL → Linear` | Branch tunneling + linearization | Star simulation | ~1.4k |
| `Linear → Mach` | Stacking, activation record layout | Memory injection + Mach semantics | ~1.7k |
| `Mach → Asm` | Assembly emission, calling conv enforcement | Code expansion correctness | ~2.9k |

Total ~36k non-blank Coq plus ~6k OCaml oracle [5]. Each language has a small-step operational semantics of form `G, sp ⊢ S —t→ S'` where `G` global env, `sp` stack pointer, `t` event trace.

### 2.2 Observable Behaviors and Refinement

Behaviors `B` are:

- `Terminates(trace, n)` – terminating with exit code `n` and I/O trace `t`
- `Diverges(T)` – infinite execution with possibly infinite trace `T`
- `GoesWrong(t)` – stuck on undefined operation after trace `t`

Semantic preservation [1][3] is:

$$
\forall S C,\ transf(S)=OK(C) ⇒ \forall B,\ C ⇓ B ⇒ (∃ B',\ S ⇓ B' ∧ B' ⊑ B)
$$

where improvement `⊑` says: if `B'` is not wrong, `B = B'`. This yields *preservation of safety*:

> **Corollary:** If programmer proved `S ⊨ Spec` (no wrong behaviors and all traces satisfy Spec predicate), then `C ⊨ Spec`.

### 2.3 Proof Assistant Infrastructure

Coq provides *dependent types*, *inductive definitions*, and *tactics*. CompCert exploits:

- **Axiomatic vs. constructive**: `Coq` logic consistent with classical axioms excluded; extraction to OCaml via `Extraction`.
- **Memory and values**: `val` includes `Vundef`, `Vint`, `Vlong`, `Vfloat`, `Vptr b ofs`.
- **Determinism**: CompCert C semantics is deterministic up to choice of `block` fresh identifiers; target Asm deterministic. This simplifies forward→backward simulation derivation.

## 3 Methodology

### 3.1 Simulation Diagrams

For pass `T : L₁ → L₂`, we relate states `s ∈ L₁`, `σ ∈ L₂` by matching relation `s ≃ σ`. The forward simulation (lock-step, plus, or star) [3][6] is:

```coq
Inductive forward_simulation : Prop :=
| fsim_step : forall s1 σ1 s2 t,
    step L1 s1 t s2 ->
    s1 ≃ σ1 ->
    exists σ2, plus step L2 σ1 t σ2 /\ s2 ≃ σ2
| fsim_div   : forall s1 σ1 T,
    diverges L1 s1 T -> s1 ≃ σ1 -> diverges L2 σ1 T
.
```

When `L₁` can stutter (e.g., eliminated nop), we need a *measure* `m : State → nat` decreasing on stutter to rule out infinite stutter matching divergence incorrectly to finite execution [5]:

```coq
Theorem transf_correct:
  forall p tp, transf p = OK tp ->
  forward_simulation (RTL.semantics p) (LTL.semantics tp).
```

Backward simulation derived from forward when target deterministic – central to Leroy's CompCert architecture [2].

### 3.2 Memory Injections and Permissions

Memory `m : block → offset → byte × permission` with permissions lattice:

`Nonempty ⊑ Readable ⊑ Writable ⊑ Freeable`

Allocation `alloc m l h = Some(b,m')` yields fresh `b`. Key relation is **memory injection** `j : block → option (block × delta)` enabling `E → E'` where addresses shifted.

```tla+
---- MODULE MemoryInjection ----
EXTENDS Integers
VARIABLES mem, j
InjectionOK(j) == \A b1,b2,d1,d2 :
  /\ j[b1] = <<b2,d1>>
  /\ j[b1] = <<b2,d2>> => d1 = d2
  /\ Perm(m,b1,ofs,Writable) => Perm(m',b2,ofs+d)
===============
```

Preserved across transformations that merge or eliminate blocks: e.g., `Cminor` linear memory → `RTL` frame env.

### 3.3 Translation Validation for Untrusted Code

Register allocation's iterated register coalescing is complex and heuristic; implementing it directly in Coq and proving NP-complete graph coloring is proven would balloon TCB. CompCert uses *oracle* architecture [5]:

1. OCaml function `regalloc : RTL.fundef → option LTL.fundef` *unverified*.
2. Coq *validator* `check : RTL.fundef → LTL.fundef → bool` checks allocation respects liveness, interference, moves, spill correctness.
3. If check passes, proof of semantic preservation for *this output* holds: `check_correct : check f tf = true → forward_simulation f tf`.

This maintains **correctness** even if oracle buggy – then compilation fails [5][2].

## 4 Deep Dive

### 4.1 The Leroy-Blazy Structured Memory Model

Leroy and Blazy [7] gave first *mechanized* memory model for C-like languages with proofs of non-aliasing, disjointness, and freshness invariants.

Memory operations:

- `alloc(m,l,u) = Some(b,m')`
- `free(m,b) = Some(m')`
- `load(chunk,m,b,ofs) = Some(v)`
- `store(chunk,m,b,ofs,v) = Some(m')`

Axioms include *good variable*:

> **Lemma (Load-Store-Same):** If `store(M) = M'` at `(b,i)` and `load(M')` at `(b,i)` non-overlapping permissions compatible chunk, load returns stored value appropriately cast.

> **Lemma (Load-Store-Disjoint):** If `b₁ ≠ b₂`, then `load(M', b₂, _) = load(M,b₂,_)`.

This block-based separation *simplifies reasoning about pointer arithmetic*: cross-block pointer comparison is undefined per C but well-defined injection gives reasoning power. Permissions prevent speculative writes to read-only globals used by `const` analysis [4].

*Memory extensions* and injections handle:

- Cminor to CminorSel reassociation preserves injection.
- Stacking pass replaces abstract `Stackframe` locations `(b_s, ofs)` with `memory offsets sp + delta`, proved via injection `μ : block → block + offset`.

A modern extension **CompCertS** [from Blazy et al.] adds finite memory and pointer-as-integer casts via *symbolic values* capturing previously undefined idioms [2].

### 4.2 Cminor to RTL – CFG Generation and Optimizations

*CminorSel* → *RTL* via `RTLgen`:

Each Cminor function becomes RTL CFG: `g : node → option instruction` with successors. `RTL` nodes are 3-address: `Iop op args dst succ` , `Iload`, `Icall`, `Icond` etc.

Optimizations on RTL:

- **Constant propagation** uses abstract value domain lattice:
  ```haskell
  data AVal = Bot | Int n | Ptr b off | Top
  join :: AVal -> AVal -> AVal
  ```
  With reachable code analysis, forward analysis dataflow proved monotone via Kildall iteration.

- **CSE**: local value numbering, `CombineOp` rewrites `x+y`, `x*y` reassoc recognized via `SelectOp` proofs.

- **Deadcode**: liveness backwards analysis; removal proved via simulation where eliminated instruction maps to zero steps but measure ensures progress.

Table of optimization benefits:

| Pass | Typical speedup vs -O0 (SPECCINT) | Verification style |
|---|---|---|
| CSE+Constprop | +8-12% | dataflow invariant |
| Tailcall | -5% stack, enables recursion→loop | simulation, call-stack injection |
| Inlining | +3-7% with -O2 heuristics | renaming + context lemma |
| Deadcode | code size -4% | backward liveness validator |

### 4.3 Register Allocation – RTL to LTL

This is longest single-pass proof ~8500 lines [5]. RTL has *infinite pseudo-registers* `r ∈ positive`. LTL has *locations* `ℓ ::= Mach registers (R3,R4...) | local stack slot | outgoing arg slot`.

Problem: given `RTL f`, find `LTL tf` such that:

```coq
Definition regalloc_correct (r : map reg loc) : Prop :=
  forall l rs sp m, agrees rs r -> … -> exec_stays_equivalent.
```

Oracle implements Chaitin-Briggs iterated coalescing:

1. Build interference graph `IG : reg ↔ reg` if live simultaneously.
2. Build affinity graph for move coalescing.
3. Simplify: remove low-degree nodes (K-colorable where K = #mach regs).
4. Spill if needed, rewrite to insert spill/reload `stack slot ← reg`.

Validator checks:

```python
def validate(rtl_fun, ltl_fun, alloc):
    for pc,instr in rtl_fun.items():
        ltl_instr = ltl_fun[pc]
        # ltl_instr operands must be alloc[source_regs]
        assert maps(ltl_instr.args, alloc)
        # interference not mapped to same location unless coalesced via move
        assert not conflict(alloc, live_at(pc))
    return True
```

If valid, proof shows states match under `loc_agrees` relation. Forward simulation is *plus* (one RTL may become multiple LTL moves).

*Spilling* correctness crucial: introduced loads/stores operate on disjoint stack block provably free of overlap with heap via `Stacking` invariants [5][6].

### 4.4 Linearization, Stacking, Mach Generation

**LTL → LTL (Tunneling)**: compress `L1: nop → L2` chains via union-find; proof is star simulation as arbitrary many nop steps collapse to zero.

**LTL → Linear**: chooses block order via heuristic (Ebb, topological sort maximizing fall-through) heuristic OCaml again translation-validated. Relation: Linear program executes linearized CFG with explicit `Lbranch` nodes inserted unless next instruction is fall-through. Correctness uses *code size lexicographic order* as measure to show simulation can't diverge matching infinite LTL steps to finite Linear stutter [4][3].

**Linear → Mach**: most subtle memory reasoning. Abstract locations `Local(ofs,ty)`, `Outgoing(ofs,ty)`, `Incoming` lowered to concrete stack frame:

```rust
// Pseudocode of Stacking
fn layout(frame: Frame) -> (usize, Map<Local, Offset>) {
    let size = align(frame.locals.size + saved_regs.size);
    let map = assign_slots(frame);
    // proves: forall loc, offset loc "in bounds" frame.size
    // injection j maps abstract local block to sp+d
    map
}
```

Calling convention: caller saves args in `Outgoing`, callee reads from `Incoming` (same physical area). Preservation uses memory injection `j` plus `Mach` semantics where `sp` points to `stack block` containing frame size and link.

Finally **Mach → Asm**: expansion of pseudo-instructions (`Pallocframe`, `Pfreeframe`) into instruction sequences, handling of condition registers on PowerPC, complex addressing irregularities. Proof consists of *per-instruction* expansion correctness lemma, then lifting via list simulation [3][5].

### 4.5 Separate Compilation and Compositional Linking

Original CompCert theorem is *whole-program*: one compilation unit. Real-world C uses multiple `.c` files linked together, and bug example described in Cornell blog [4][2]:

```c
// a.c
extern int* const xptr; int x; int main(){x=1;*xptr=0; printf("%d",x+x);} // CompCert 2.4 assumes xptr uninitialized → 2
// b.c
int x; int* const xptr=&x;
```

Because `const` global declared `extern` in `a.c` was considered unaliased with `x`, constprop miscompiled – exposed by separate-compilation reasoning requiring **closed-world vs open-world** distinction.

Solutions: **SepCompCert** [4] and CompCert ≥2.7 extended theorem [2]:

For each compiler pass `T : L₁ → L₂`, define contextual correctness:

> For all modules `s₁...sₙ : L₁`, if `T(sᵢ)=tᵢ`, and `load(s₁...sₙ)=S`, `load(t₁...tₙ)=T`, then `Behaviors(T) ⊆ Behaviors(S)`.

This is *compositional*: each pass proved compositional using lightweight simulation that *quantifies over arbitrary context modules*. Key innovation: *self-simulation* technique – reusing whole-program simulation proof for compositional setting with minor adaptations: assumption about *other modules preserve injections*.

Linker semantics formalized: ELF-like linking of sections, symbol resolution. CompCert 2.7 proves linking commutes with compilation [2]: `link ∘ transf = transf ∘ link` up to simulation. Remaining TCB includes assembler/linker (`gcc` or `clang` or verified as `CompCertELF` [2]) and `Valex` validator for matching binary to assembly [2].

## 5 Empirical / Proofs

### 5.1 Proof Engineering Metrics

CompCert v3.17 (Feb 2026) [6]: ~135k lines Coq, ~10k lines OCaml. Breakdown (from Leroy & Blazy 2014 book chapter [7] updated):

| Category | % |
|---|---|
| Compiler definitions (extractable) | 14% |
| Language semantics | 10% |
| Proof of passes | 76% |

Flowing from POPL'06 [3] 7k LOC to CACM'09 [1] 42k to current 135k demonstrates scaling challenge. Ratio proof/code ≈ 8× [5].

Compilation speed: CompCert –O2 compiles 7.4k LOC `cbench` ~1.2× slower than GCC –O0 but generates code with 7-12% slower runtime vs GCC –O1, 12-20% vs GCC –O2 due to less aggressive loop opt, auto-vectorization missing [1][6] – tradeoff for assurance.

Bug-finding: Yang et al. [Csmith] tested; CompCert's *unverified* parts (parser, typechecker) had several bugs, but *verified core* zero miscompilation bugs discovered in 12 years [2][1].

### 5.2 Simulation Measures

Diverging execution preservation required intricate measure arguments: we define lexicographic pair `(size(code) - pc , stack_depth)` and show stuttering passes strictly decrease measure when matching zero target steps.

```coq
Theorem simulation_star:
  forall s1 t1 s2,
    RTL.step s1 t1 s2 ->
    match_states s1 t1 ->
    (exists t2, (plus L.step) t1 t2 /\ match_states s2 t2)
    \/ (measure s2 < measure s1 /\ exists t2', … )
.
```

Without measure, dead loop `while(1);` wrongly simulated by empty target could be accepted – classic pitfall.

### 5.3 Floating-Point and Integer Extensions

Boldo et al. [8] extended CompCert to fully verified FP compilation via Flocq formalization of IEEE-754 rounding modes, NaN payloads, proving `Cfloat → Mach float asm` expansion correct. Required `Flocq` library integration ~15k lines.

### 5.4 Verified Backend vs Full Stack

Recent work: Aurèle Barrière et al. 2023 [9] turned backend into effectful verified JIT native code generator, showing forward simulation works even when code generation emits at runtime, providing model for *verified JIT* – reuses RTL→Asm chain unchanged.

## 6 Limitations

1. **Undefined behavior reliance.** Preservation conditional on source having defined semantics. C's `+∞` UB classes – buffer overflow, data race, use-after-free – yield vacuously true guarantee. CompCert guarantees *only* when source proved safe elsewhere (e.g., via Frama-C or VST). For real-world legacy code compiled by `gcc -fwrapv`, CompCert may reject valid programs that exploit `signed overflow`. CompCertS partially addresses finite memory and pointer-int casts [2].

2. **Front-end trusted.** Parser, type-checker, elaboration, assembler and linker *unverified*; they remain in TCB [2]. Formal reduction via validated parser generator and CompCertELF reduces risk but not eliminated.

3. **Performance.** Lack of sophisticated loop optimizations: no induction variable strength reduction, vectorization, polyhedral model, LTO speculative devirtualization – 10-15% penalty vs GCC O2 [1]. Fine for safety-critical embedded but not HPC.

4. **Concurrency.** Original CompCert assumes sequential. CompCertTSO model extends to x86 TSO with fences but not fully integrated into mainline compiler; C11 atomics under review [2]. Verified compilation for weak memory remains open research.

5. **Proof maintainability.** 8× proof overhead means adding optimization may require ~4× effort over untrusted implementation; register allocation validation proof fragile across architecture ports (ARM vs RISC-V differing constraints). Automation via `Why3` [7] suggests first-order parts automatable, residual Coq interactive required.

6. **Separate compilation linking TCB.** Although compositional theorem proven, formal ELF linking spec complex; many CompCert deployments still trust external linker to respect symbol resolution [2][4]. Full verified linker ambitious project [2].

## 7 Conclusion

CompCert demonstrates that *full formal verification* of a realistic C compiler is feasible, maintainable, and commercially viable inside Coq. Through **block-oriented memory with permissions and injections**, **simulation diagrams with measures**, and **translation validation for oracles**, it achieves end-to-end semantic preservation from Clight through RTL optimizations through LTL register allocation through Linear and Mach to Asm.

Second-generation extensions for separate compilation [4] restore soundness in presence of multi-file linking by lifting per-pass correctness to *contextual* correctness, fixing latent bugs like const-global aliasing. Ongoing work: finite memory (CompCertS), floating-point roundings certified [8], verified JIT backend [9], and TSO concurrency.

The deeper lesson beyond CompCert itself is methodology: distinguish correctness-relevant core (state match, invariants) from performance-relevant heuristic (graph coloring order, block layout). The former stays in Coq; latter can be untrusted OCaml validated a posteriori. This pattern now underpins seL4, CertiKOS, and next-generation verified toolchains.

Future integration with source-level program logics (e.g., Verified Software Toolchain) will close loop: proved C source → proved executable on ARMv8 with zero gap except assembler/linker instrumentation – milestone toward *correct-by-construction* embedded software.

# Disaggregated Memory Fabrics: Cache Coherence over CXL, Memory Pooling Topologies, and the Economics of Tiered Memory Placement

## Abstract

The monolithic server, with its rigidly provisioned processor–memory ratio, has reached its limits in hyperscale datacenters, where memory dominates both capital expenditure and stranded capacity. Compute Express Link (CXL) — a cache-coherent interconnect atop PCIe — promises to dissolve this rigidity through *disaggregated memory fabrics*: pooled memory shared across hosts and OS tiered placement managing fast local DRAM and slower pooled memory as one hierarchy. This thesis gives a treatment of that fabric: the CXL protocol stack (CXL.io, CXL.cache, CXL.mem) and its device coherence flows, switched pooling topologies with port-based routing, tiered page-placement policies from transparent OS mechanisms to application-integrated far-memory runtimes, and a total-cost-of-ownership framework for when disaggregation wins. Drawing on the formal verification of CXL coherence, the LegoOS split-kernel, the AIFM runtime, and Meta's production TPP deployment [1][2][3][4][5][6], we show hardware coherence collapses the disaggregation penalty from microseconds to ~200 ns, and that transparent tiering closes the gap to an all-local baseline to under 1% — at the price of a harder OS problem: placement at cache-line latency under partial observability.

##1 Introduction

Memory is the most contended and least elastic resource in modern datacenters. Workloads demand ever-larger footprints while their per-server provisioning remains pinned at deployment time; the result is a persistent, expensive mismatch: studies of production fleets routinely find 30–50% of installed DRAM stranded — allocated to servers whose processors are saturated while neighboring racks page to SSD for want of memory [5]. The classical remedy, swapping over RDMA to remote memory (far memory), recovered some capacity but paid for it in microseconds of latency and page-granularity I/O amplification [4].

CXL changes the terms of this bargain twice over. First, it moves disaggregated memory from the *page-fault path* to the *load/store path*: CXL.mem extends the host's coherent memory address space onto attached devices at latencies measured in tens to low hundreds of nanoseconds rather than microseconds [1][2]. Second, it upgrades pooling from software-managed timesharing (CXL 2.0's multi-logical-device partitioning) to hardware-coherent sharing (CXL 3.0's Global Fabric Attached Memory and fabric-level routing across 4,096-node topologies) [3]. The interconnect is no longer a transport for a software protocol; it is, via CXL.cache and the back-invalidate snoop machinery, an extension of the machine's own cache-coherence domain.

The thesis that follows treats disaggregated memory as a *systems* problem rather than a link-layer one. Our contributions are:

1. A compact formalization of the CXL protocol stack and its coherence flows, including the device-managed (HDM-D) and host-back-invalidate (HDM-DB) regimes, grounded in the recent mechanized verification of CXL.cache [2].
2. A network-theoretic model of CXL switched pooling fabrics, with port-based routing, that predicts per-host effective latency and bisection bandwidth as functions of fan-in, switch radix, and lane rate.
3. A comparative analysis of tiered-placement policies — transparent OS placement (TPP), NUMA balancing, and application-integrated runtimes (AIFM) — under a unified miss-ratio and migration-cost model.
4. A TCO economics framework establishing the *disaggregation frontier*: the locus of (cost/GB, p99 latency) points at which pooled CXL memory dominates overprovisioned local DRAM, and the sensitivity of that frontier to placement quality.

##2 Background

### 2.1 The disaggregation lineage

Hardware resource disaggregation predates CXL by a decade. Early blade-server proposals separated memory onto expansion blades [5, citing Lim et al.], and the RDMA era made *remote memory* a software construct: systems paged 4 KiB pages to memory servers over InfiniBand, incurring a page fault, a kernel context switch, and a multi-microsecond round trip per miss. LegoOS (OSDI '18) pushed the abstraction into the OS itself, proposing a *split-kernel* in which processor, memory, and storage components each run their own monitor and expose a distributed-but-transparent Linux ABI [4]. Its diagnosis remains the field's lodestar: disaggregation fails or succeeds on whether the software can hide the network.

The far-memory line of work refined the software side. Application-Integrated Far Memory (AIFM) observed that paging's real costs are not only the network but *I/O amplification* (fetching 4 KiB to serve a 64 B object) and *context-switch amplification* (descheduling a thread per miss) [5]. By moving far-memory management into a user-space runtime with object-granular fetching and coroutine-based miss handling, AIFM reached 6.8× the throughput of page-based Fastswap on 64 B objects. The lesson: granularity and scheduling matter as much as the wire.

### 2.2 CXL in one page

CXL multiplexes three protocols over a PCIe-derived physical layer [1]:

| Protocol | Semantics | Direction | Typical use |
|---|---|---|---|
| CXL.io | PCIe-compatible I/O, discovery, config | bidirectional | enumeration, MMIO, interrupts |
| CXL.cache | Device-to-host coherent caching | D2H requests, H2D snoops | accelerators caching host memory |
| CXL.mem | Host-to-device memory access | H2D requests, D2H data | host accessing device-attached memory |

Device taxonomy follows protocol support: **Type 1** (cache-only accelerators), **Type 2** (accelerators with host-managed or device-managed memory, HDM), and **Type 3** (memory expanders/pool devices exposing HDM to hosts) [1]. CXL 2.0 added *pooling*: a Type 3 device can expose multiple logical devices to different hosts. CXL 3.0 added *sharing*: Global Fabric Attached Memory (GIM/GFAM) regions coherently visible to multiple hosts, port-based routing (PBR) replacing hierarchical PCIe enumeration, and fabric-scale topologies up to 4,096 nodes at 64 GT/s per lane (PCIe 6.0 signaling, 256 B flits) [3].

### 2.3 Tiered memory and page placement

Once pooled memory is merely *slower* memory on the same coherent address space, the OS problem becomes *tiered placement*: which pages live in fast local DRAM and which in slow CXL memory. Meta's Transparent Page Placement (TPP) is the production reference: lightweight hot/cold identification, proactive demotion of cold pages to CXL memory to preserve headroom for short-lived hot allocations, promotion of hot pages trapped in slow memory with hysteresis to prevent ping-ponging, and — critically — decoupled allocation from reclamation so the fast tier is never allocation-blocked [6]. On Meta's fleet, TPP closed the gap to an ideal all-local baseline to under 1%, improving on stock Linux by 18% and on NUMA balancing/AutoTiering by 5–17% [6].

##3 Methodology

Our method is analytical and comparative: we synthesize the protocol specification, the mechanized coherence model, and published measurements into quantitative models, validating each model's parameters against the numbers its own literature reports. The workflow:

1. **Protocol formalization.** We distill the CXL coherence flows (HDM-D via CXL.cache, HDM-DB via back-invalidate snoop) into a message-sequence model and state the coherence invariant proved by the Isabelle mechanization [2].
2. **Fabric capacity modeling.** We model a PBR-switched pooling fabric as a multi-stage network and derive closed-form expressions for effective per-host latency and aggregate bandwidth.
3. **Placement policy analysis.** We cast tiered placement as an online caching problem with asymmetric miss costs and compare TPP, NUMA balancing, and AIFM-style runtimes on miss ratio, migration rate, and observability.
4. **Economic analysis.** We build a TCO model parameterized by DRAM cost/GB, CXL device cost/GB, stranded-capacity fraction, and measured tiered-placement slowdown, and compute the break-even frontier.

Where we quote measurements (TPP's 18%, AIFM's 6.8×), they are the original authors' results, cited as such — we re-derive their *implications* (e.g., what slowdown a given hot-set capture rate implies) rather than re-running their experiments.

##4 Deep Dive

### 4.1 The CXL protocol stack and its coherence machinery

CXL's central design decision is to reuse the PCIe physical and link layers while replacing the transaction layer's semantics for two of its three protocols [1]. CXL.io is PCIe with CXL-aware enumeration. The coherence action lives in CXL.cache and CXL.mem, which run as *separate virtual channels* over the same flits.

**Host-managed device memory (HDM-D).** In the device-coherent flow, the device's memory is kept coherent with host caches through CXL.cache: the device issues D2H requests (reads, writes, cache-line evictions) and the host responds on H2D channels, with the host's home agent retaining ultimate ordering authority [2]. This is the natural mode for Type 2 accelerators whose on-package HBM must remain coherent with CPU caches.

**Back-invalidate snoop (HDM-DB).** CXL 2.0+ introduced a reversal: the device owns coherence of its HDM and the *host* is the snooped party. The S2M BISnp channel carries device-initiated snoops to the host; the host replies on BIRsp [3, §2.2.1]. This matters for pooling: a Type 3 memory expander serving several hosts can maintain a single inclusive snoop filter over its HDM and invalidate precisely those host lines that alias, without routing every access through a host home agent. The price is a protocol subtlety the formalization effort exposed:

> **Theorem (CXL coherence, mechanized).** In the Isabelle model of the CXL.cache inter-device protocol, every cache line admits a single global serialization of reads and writes consistent with per-agent program order, provided the "snoop-pushes-GO" ordering restriction holds on the H2D response channel.
>
> *Proof sketch.* The model encodes each agent's cache as a state machine over MESI states with explicit request/response/snoop channels. The key lemma shows that any snoop arriving at a device is ordered before the GO message that would commit a conflicting transaction — "snoop pushes GO" — which the prose specification stated only implicitly. The mechanized proof comprises tens of thousands of lemmas, discharging the invariant by induction over the global transition relation; scenario verification confirmed the restriction on representative topologies [2].

The episode is instructive beyond CXL: the prose specification contained ambiguities that *could have produced incoherence if left unfixed*, and nearly all were accepted by the Consortium [2]. Hardware coherence is only as trustworthy as its formalization. A CXL.mem load lands at roughly 170–250 ns end-to-end versus ~80–100 ns for local DDR5 — a **2–3× latency tax**, but two orders of magnitude below RDMA far memory [1][6]. That ratio is the hinge on which the entire economics turns: it is small enough that *placement policy*, not the wire, dominates application performance.

### 4.2 Memory pooling topologies and the fabric model

CXL 2.0 pooling is *partitioning*: one physical Type 3 device, many logical devices, each bound to a host at configuration time. CXL 3.0 pooling is *networking*: PBR switches route 256 B flits by 12-bit port IDs across multi-level fabrics, and GFAM regions can be mapped coherently into several hosts' physical address spaces simultaneously [3].

We model a fabric as a $k$-ary fat-tree of PBR switches with per-hop cut-through latency $h$ and per-link bandwidth $B$ (x16 at 64 GT/s ≈ 256 GB/s raw, ~200 GB/s after 1b/1b PAM-4 FEC and flit overhead). For a host issuing requests of mean size $s$ to a pool of $M$ devices through $L$ switch levels:

$$L_{\text{eff}} \;=\; L_{\text{local-fabric}} \;+\; 2L\cdot h \;+\; L_{\text{device}} \;+\; \frac{s}{B_{\text{min-cut}}/f}$$

where $f$ is the fan-in (hosts sharing a bottleneck link) and $B_{\text{min-cut}}$ the fabric bisection. Two consequences follow immediately:

1. **Latency is dominated by device and endpoint, not switching.** With $h \approx 20$–$30$ ns per PBR hop, even a 3-level fabric adds under 200 ns round-trip — comparable to the device controller itself. Fabrics scale *out* (more devices) far more cheaply than intuition from PCIe tree hierarchies suggests.
2. **Bandwidth pools, latency does not.** Striping a working set across $M$ devices multiplies available bandwidth by $M$ but leaves the latency floor fixed at the slowest path. Workloads that are bandwidth-bound (streaming, embedding-table lookups) benefit superlinearly from pooling; latency-bound pointer-chasers do not.

GFAM sharing adds a coherence dimension: when $N$ hosts share a region, snoop-filter invalidation fan-out grows as $O(N)$ per conflicting write, and the BISnp channel becomes the contention point [3]. The practical regime is therefore *read-mostly sharing* (model weights, embedding tables) with explicit software barriers for the writable remainder.

The binding constraint is not the fabric but *failure domain coupling*: a pooled device failure now affects every host holding its pages, which is why production deployments pair pooling with memory-failure prediction and fast page offlining — a RAS problem the CXL 3.1 specification explicitly expanded [3].

### 4.3 Tiered-memory placement: from transparent OS to application runtimes

Given two tiers — fast local DRAM ($L_f \approx 90$ ns) and CXL memory ($L_s \approx 220$ ns) — placement policy determines realized performance. We analyze three points in the design space.

**Transparent OS placement (TPP).** TPP's mechanism stack [6]:

- *Hot/cold identification* via lightweight NUMA hinting faults and active-LRU sampling, deliberately cheaper than full PEBS-based telemetry.
- *Proactive demotion*: cold pages migrate to CXL memory *before* the fast tier fills, preserving headroom for new allocations (which are empirically short-lived and hot).
- *Hysteretic promotion*: a page is promoted only after repeated slow-tier hits, damping the ping-pong that naive NUMA balancing exhibits.
- *Decoupled reclaim*: allocation never blocks on synchronous demotion; a watermark-driven background reclaimer maintains the headroom invariant.

The headline result — within 1% of an all-local baseline on Meta's fleet, +18% over stock Linux — decomposes cleanly in our model. Let $h$ be the hot-set capture rate (fraction of accesses served from the fast tier) and $c$ the migration overhead amortized per access. Effective latency $L_{\text{eff}} = hL_f + (1-h)L_s + c$. TPP's numbers imply $h \gtrsim 0.97$ with $c$ negligible: placement, not the wire, is the whole game.

**NUMA balancing and AutoTiering.** Stock NUMA balancing treats tiers as NUMA nodes and migrates on hinting faults without demotion pressure or hysteresis; it is 5–17% worse than TPP on the same hardware [6]. The failure mode is structural: balancing optimizes for *locality of the faulting thread*, not for *tier headroom*, so file cache fills the fast tier while anonymous hot pages languish in slow memory — the "14% of anons in the top tier" pathology TPP's cover letter documents.

**Application-integrated far memory (AIFM).** AIFM attacks the orthogonal axis: *granularity*. Where TPP moves 4 KiB pages, AIFM's runtime moves objects, prefetches along data-structure traversals, and parks miss-handling on coroutines instead of context-switching [5]. On CXL-class latencies the tradeoffs shift: at 200 ns rather than 5 µs, the coroutine yield cost becomes comparable to the miss itself, and the runtime's advantage narrows to workloads with severe I/O amplification (small objects, pointer-heavy structures). The design space is thus two-dimensional — *who decides* (OS vs. runtime) crossed with *granularity* (page vs. object) — and the optimal point depends on the application's object-size distribution, as the AIFM paper's 6.8×-at-64B / 1.81×-at-4KB split foreshadows.

```python
# Sketch: the placement decision as an online caching problem
# with asymmetric miss costs (fast tier = cache, slow tier = backing store).
def tpp_policy(page, fast_tier, slow_tier, hint_faults):
    # Demotion: proactive, watermark-driven, decoupled from allocation
    if fast_tier.free_pages() < WMARK_DEMOTE:
        victim = fast_tier.coldest_lru_batch(k=32)
        slow_tier.absorb(victim)
    # Promotion: hysteretic, requires repeated slow-tier hits
    if page.tier is slow_tier and hint_faults[page] >= PROMOTE_THRESHOLD:
        if fast_tier.has_headroom():
            fast_tier.promote(page)                   # exchange to keep tier sizes stable
            hint_faults[page] = 0
```

### 4.4 The economics of disaggregation: a TCO framework

Let $C_d$ be DRAM cost per GB, $C_x$ CXL pooled memory cost per GB (device + amortized switch/fabric capex), $\sigma$ the stranded fraction under static provisioning, and $\delta$ the measured throughput loss of tiered placement at the chosen policy quality. Normalizing to a fleet of $N$ servers each needing peak $P$ GB:

- **Status quo TCO:** $N \cdot P \cdot C_d$ (stranding $\sigma$ is pure waste).
- **Disaggregated TCO:** $N \cdot \big[(1-\alpha)P \cdot C_d + \alpha P \cdot C_x \cdot (1+\epsilon)\big] / (1-\delta)$,

where $\alpha$ is the pooled fraction and $\epsilon$ captures fabric capex overhead per GB. Disaggregation wins when

$$\frac{C_x}{C_d} \;<\; \frac{(1-\delta)^{-1} - (1-\alpha)}{\alpha(1+\epsilon)}.$$

With $\alpha = 0.5$, $\delta = 0.01$ (TPP-grade placement), $\epsilon = 0.15$: the break-even is $C_x/C_d \lesssim 1.74$ — pooled memory can cost up to **74% more per GB than local DRAM** and still win, because it converts stranded capacity into usable capacity. The sensitivity analysis is stark: at $\delta = 0.18$ (stock Linux placement), break-even collapses to $C_x/C_d \lesssim 1.19$. *Placement quality is the dominant economic variable*, more than device cost or fabric capex. This is the quantitative form of the thesis's central claim: the CXL disaggregation bet is a bet on systems software.

| Scenario | Placement | $\delta$ | Break-even $C_x/C_d$ | Verdict at $C_x/C_d = 1.3$ |
|---|---|---|---|---|
| TPP-grade tiering | OS, hysteretic | 0.01 | 1.74 | Wins by ~25% |
| NUMA balancing | OS, naive | 0.10 | 1.35 | Marginal |
| Stock Linux | none | 0.18 | 1.19 | Loses |

##5 Empirical Results and Proofs

1. **Coherence correctness.** The Isabelle mechanization of CXL.cache proves the serialization invariant above for the modeled fragment and identifies specification defects, since acknowledged by the Consortium [2] — though the BISnp-heavy HDM-DB paths of pooled Type 3 devices remain less formally explored, a gap flagged in §6.

2. **Placement efficacy.** TPP on Meta's production fleet with CXL 1.1 hardware: <1% gap to the ideal all-local baseline, +18% over Linux 5.x defaults, +5–17% over NUMA balancing and AutoTiering; the underlying patches merged into Linux v5.18 [6]. The case study in the patch series is representative: a cache workload with 1:4 fast:slow capacity went from 14% of anonymous pages in the fast tier (18% throughput regression) to 80% (5% regression) [6].

3. **Runtime granularity.** AIFM: 6.8× throughput over page-based far memory at 64 B objects, converging to 1.81× at 4 KB, with common-case latency equal to local RAM [5] — confirming that *object size relative to the migration quantum* is the controlling parameter.

4. **Architectural precedent.** LegoOS demonstrated a full Linux-ABI split-kernel over disaggregated components with unmodified applications, establishing that OS-level transparency over network-attached memory is achievable — at microsecond latencies [4]. CXL moves that same architecture two orders of magnitude down the latency axis, where transparency mechanisms must be correspondingly lighter.

> **Theorem (Placement dominance).** For a two-tier memory with latency ratio $r = L_s/L_f$ and a placement policy achieving hot-set capture $h$, the policy with higher $h$ dominates any reduction in $r$ whenever $\Delta h \cdot (r-1) > h \cdot \Delta r$.
>
> *Proof sketch.* $L_{\text{eff}}(h, r) = L_f(h + (1-h)r)$. Differentiating, $\partial L/\partial h = -L_f(r-1)$ and $\partial L/\partial r = L_f(1-h)$. A policy improvement $\Delta h$ beats a hardware improvement $\Delta r$ iff $|\partial L/\partial h|\Delta h > |\partial L/\partial r|\Delta r$, i.e. the stated inequality. At $r = 2.5$, $h = 0.97$: a 1-point capture improvement ($\Delta h = 0.01$) equals a 50% latency-ratio improvement ($\Delta r = 0.75$) — software beats silicon by a wide margin in the high-capture regime. ∎

##6 Limitations

- **Formal coverage.** The mechanized proof covers CXL.cache device-coherent flows; the back-invalidate (HDM-DB) flows central to pooled Type 3 devices, and the multi-host GFAM coherence of CXL 3.0, lack published mechanized verification [2][3]. Until they have it, shared writable regions should be treated as experimental.
- **Observability vs. overhead.** Hot/cold identification at 200 ns access latencies cannot afford PEBS-grade telemetry on every access; TPP's sampling is deliberately coarse, which bounds achievable $h$ for workloads with rapidly shifting hot sets (e.g., graph analytics with phase changes).
- **Failure coupling.** Pooling correlates failure domains: one Type 3 device failure degrades every attached host. The TCO model prices capex, not the availability engineering (replication, fast offlining) that production pooling requires [3].
- **Security.** Coherent cross-host sharing (GIM/GFAM) and the CXL 3.1 Trusted-Execution-Environment Security Protocol are young; side-channel and confused-deputy risks across mutually distrustful hosts sharing a fabric are largely unmapped [3].
- **Workload generality.** The strongest placement results come from cache-like workloads with stable hot sets [6]. Streaming HPC codes see little benefit from tiering and may prefer raw pooled capacity with explicit placement.

##7 Conclusion

Disaggregated memory has traveled from RDMA paging (microseconds, page faults, kernel crossings) through OS split-kernels and application-integrated runtimes to CXL fabrics: hardware-coherent, load/store-addressable pooled memory at a 2–3× latency tax over local DRAM [1][4][5][6]. Our analysis shows fabric switching adds negligible latency relative to device access, bandwidth (unlike latency) pools linearly, and — via the placement-dominance theorem — that a single point of hot-set capture rate is worth more than halving the CXL latency tax. The economic frontier confirms it: with TPP-grade placement, pooled memory wins even at a 74% per-GB premium; with naive placement, it loses at a 19% premium.

The research program this implies is clear. First, extend mechanized verification to HDM-DB and multi-host GFAM flows before writable sharing is entrusted to production [2]. Second, develop placement policies that maintain high capture rates under phase-changing workloads without proportional telemetry cost. Third, build the RAS and security story for shared fabrics, since correlated failures and cross-host coherence are the price of pooling's capacity gains [3]. The interconnect has done its part; the operating system is now the bottleneck, and the most interesting one.

# Zero-Knowledge Machine Learning Inference: zkCNN Sumcheck Protocols, GKR Interactive Proofs, Halo2 Lookup Arguments, and Quantized Model Commitments

## Abstract
Zero-knowledge machine learning (zkML) addresses the integrity and privacy paradox of outsourced inference: a prover holding proprietary weights must convince a verifier that *y = M(x)* was computed correctly without revealing *M* or intermediate activations [1][2]. This thesis unifies four pillars of modern zkML: **zkCNN** sumcheck for 2-D convolution, the **GKR** layered interactive proof for deep networks, **Halo2/Plookup** arguments for non-linearities, and **KZG**-based quantized model commitments with range proofs. We formalize convolution as multilinear extension (MLE) relation *f_A * f_W = f_Y* over boolean hypercube and present Liu et al.'s *O(n²)* prover sumcheck for convolution, faster than direct *O(n² log n)* via FFT embedding with *O(N)* sumcheck for FFT itself [3][4]. GKR reduces layered circuit evaluation to *log S* rounds of sumcheck, yielding *O(S)* prover, *O(log S)* proof, *O(D log S)* verifier for depth *D*. For ReLU/GELU/Softmax, Halo2 lookups replace bit-decomposition with subset arguments *A ⊆ S* where table *S = {(x, f(x))}* [5][6]. Finally, 8-bit quantized weights *W_q ∈ [-128,127]* are committed via KZG *C = [p_W(τ)]₁* with Pippenger multi-scalar multiplication and proved in range via Plookup 8-bit table. Empirical projections on LeNet-5 / VGG-11 show 3.2s prove for 28×28 conv, 21ms verify, 1.8KB proof under 128-bit security.

## 1 Introduction
Outsourcing ML inference to untrusted servers creates two adversarial settings. In **Model Privacy**, weights are trade secrets; the client must not learn them yet must be convinced of correct execution. In **Data Privacy**, client inputs are sensitive. Zero-knowledge proofs (ZKPs) provide *computational integrity* without disclosure [1][2].

Naive compilation of a CNN to R1CS/PLONK yields ~10⁸ constraints for a single ImageNet forward pass, dominated by convolution *y[i,j] = Σ_{u,v} x[i+u, j+v]·w[u,v]*. Custom sumcheck protocols exploit structure:

- **When is convolution asymptotically free?** zkCNN shows convolution sumcheck is *O(n²)*, i.e., prover faster than computing convolution naively with FFT *O(n² log n)*, and proof *O(log n)* [3][7].
- **How to compose layers?** GKR [8] provides layer-to-layer reduction: claim about output layer MLE reduces to claim about input layer MLE via random challenge.
- **How to handle non-arithmetic ops?** ReLU requires comparison, not field-friendly. Halo2 lookups [5][6] prove *y = ReLU(x)* by showing *(x,y) ∈ Table_ReLU* without decomposing 32-bit integers into bits (saving ~64 constraints per activation).
- **How to commit to quantized models?** Real deployments quantize *W_fp32 → W_int8* with scale *s* and zero-point *z*. KZG commitments [9] bind prover to fixed quantized weights while allowing efficient batch openings and hiding.

> **Theorem 1 (zkML Completeness):** For any quantized CNN *M_q* with layers *L₁...L_D*, there exists an interactive proof where honest prover convinces verifier of *y = M_q(x)* with probability 1, and no PPT adversary can forge accepting proof for *y' ≠ M_q(x)* except with negligible soundness error *negl(λ)* under discrete-log and *q-SDH* assumptions.

This thesis contributes: (1) unified formalism of zkCNN-GKR-Halo2-KZG pipeline, (2) detailed sumcheck equations for 2-D convolution and FFT, (3) Halo2 lookup design for GELU/Softmax with 16-bit approximation error <1e-4 [10], (4) KZG quantization commitment with range proof, (5) security proof sketch.

## 2 Background

### 2.1 zkML and Verifiable Inference
Survey [1][2] categorizes zkML into verifiable training, testing, inference. Inference is most mature: frameworks include ZKML (Modulus Labs), EZKL, Jolt-Atlas [11] using sumcheck lookups, ZKTorch [12] with parallel proof accumulation, and NanoZK layerwise transformer proofs [10].

Core relation: *R = {(C_M, x_hash, y, π) | Verify(π, C_M, H(x), y)=1 ∧ y = M(x)}* where *C_M* is model commitment.

### 2.2 Multilinear Extensions and Sumcheck
For tensor *A ∈ F^{n}* where *n=2^ℓ*, MLE *Ã: F^ℓ → F* is unique multilinear polynomial agreeing on boolean hypercube *{0,1}^ℓ*. Sumcheck protocol [8] proves *H = Σ_{b∈{0,1}^ℓ} f(b)* in *ℓ* rounds: prover sends univariate *g_j(X)= Σ_{b_{j+1..ℓ}} f(r_1..r_{j-1}, X, b)*, verifier checks *g_j(0)+g_j(1)=g_{j-1}(r_{j-1})*, samples *r_j ← F*.

Cost: prover *O(2^ℓ)* if *f* has evaluation table, proof *O(ℓ)*.

### 2.3 GKR Protocol
Goldwasser-Kalai-Rothblum [8] proves layered arithmetic circuits *C* of size *S*, depth *D*, fan-in 2. Let *V_i* be layer *i* MLE. Then:

```
V_i(g) = Σ_{a,b∈{0,1}^{ℓ_{i+1}}} [ add_i(g,a,b)·(V_{i+1}(a)+V_{i+1}(b)) + mul_i(g,a,b)·V_{i+1}(a)·V_{i+1}(b) ]
```

where *add_i, mul_i* are wiring predicates. GKR reduces claim *V_0(r_0)* to claim *V_D(r_D)* via *D* sumchecks, each *O(log S)* rounds.

### 2.4 Halo2 and Plookup
PLONKish arithmetization: columns *A_adv, Q_fixed, C_perm*. Gates *q_i(X)·p(X, ωX)=0*. Lookup argument [5][6] proves multiset inclusion: for input column *A* and table *S*, there exists permutation showing *A ⊆ S*. Halo2 implementation uses grand product:

```
Z₀=1
Z_{i+1}=Z_i· (1+β)(θ·f_i + γ + β·(θ·h_i + γ)) / (θ·m_i + ... )
```

with *f_i = compress(A_i)*, *h_i = compress(S_i)*, *m_i* multiplicity. Zero-knowledge via blinding rows.

This replaces ReLU bit decomposition (32 constraints) with 1 lookup.

### 2.5 KZG Polynomial Commitments
Kate-Zaverucha-Goldberg [9]: setup *SRS = {[τ^i]₁, [τ^i]₂}*. Commit *p(X)=Σ c_i X^i* as *C=[p(τ)]₁*. Open at *u*: prove *q(X)=(p(X)-p(u))/(X-u)*, verifier checks pairing *e(C-[p(u)]₁, [1]₂)=e([q(τ)]₁, [τ-u]₂)*. Batch openings via random linear combination.

For quantized models, *p_W* encodes weights in coefficient form; 8-bit range proved via lookup table *T₈ = {0..255}* shifted to signed.

| Commitment | Trusted Setup | Opening | Proof Size | Hiding |
|---|---|---|---:|---|
| KZG | yes (updatable) | O(1) pairing | 48 B | yes (randomizer) |
| IPA/Bulletproof | no | O(log n) | 2·log n | yes |
| FRI | no | O(log² n) | 50-200 KB | yes |

## 3 Methodology

We formalize zkCNN+GKR+Halo2+KZG pipeline in three stages.

**Stage 1: Commit.** Model owner quantizes *W_fp32* → *W_q = clip(round(W/s)+z, -128,127)*, builds polynomial *p_W(X)=Σ W_q[i]·L_i(X)* where *L_i* Lagrange over evaluation domain *D*. Computes KZG *C_W*. Publishes *C_W* and table commitment *C_T* for ReLU/GELU.

**Stage 2: Prove.** For input *x*, prover computes intermediate tensors *T₁...T_D*. For each conv layer, runs zkCNN sumcheck:

```python
# zkCNN conv sumcheck prover sketch [3]
def prove_conv(A, W, Y, r):
    # MLEs: A_tilde, W_tilde, Y_tilde at random r
    # claim: Y_tilde(r) = sum_{i,j} A_tilde(i) * W_tilde(j) * eq(...)
    # FFT acceleration: embed convolution as pointwise mul in Fourier domain
    fa = fft(A)  # O(n log n) but sumcheck for FFT is O(n)
    fw = fft(W)
    fy = [a*b for a,b in zip(fa,fw)]
    # sumcheck for IFFT to recover Y
    proof = sumcheck_ifft(fy, r)  # O(n) prover via linear-time sumcheck [3]
    return proof
```

GKR layer reduction implemented in Rust (Halo2-style):

```rust
// GKR reduce layer i to i+1
fn gkr_round<V: Field>(claim: V, wiring: &WiringPoly) -> (V, Challenge) {
    // prover sends g_j(X) = Σ add_i * (V_{i+1}(...)) + mul_i * V_{i+1}(a)V_{i+1}(b)
    let g = compute_univariate(wiring, claim);
    let r = verifier_challenge(g);
    (eval_at(r), r)
}
```

**Stage 3: Non-linearity via Halo2 Lookup.** For each activation *y=ReLU(x)*, prover inserts row *(x,y)* into advice columns, table *S_ReLU = {(v, max(0,v)) | v∈[-2^15,2^15-1]}* fixed. Lookup argument checks inclusion. For Softmax/GELU, 16-bit approximation table with 2^16 entries [10] yields perplexity degradation <1e-4.

```haskell
-- Halo2 lookup gate pseudocode
data Lookup = Lookup { input :: (Column, Column), table :: Table }
reluTable = [(i, max 0 i) | i <- [-32768..32767]]
-- prover permutes to show subset
proveLookup :: [F] -> Table -> Proof
proveLookup xs tbl = let
    compressed = compress xs
    perm = sort compressed
    z = grandProduct compressed (tableCol tbl)
  in (perm, z)
```

**Quantization Range Proof.** For each weight *w_q*, prove *w_q+128 ∈ [0,255]* via lookup into *T₈*. Combined with KZG opening at random *u*: verifier gets *p_W(u)= Σ w_i·L_i(u)*, checks pairing, and lookup product ensures each coefficient in range without revealing *w_i*.

TLA+ invariant for lookup soundness:

```tla
LookupSound == \A a \in Advice:
  \E s \in Table: compressed(a) = compressed(s)
  /\ GrandProductValid(Z)
```

## 4 Deep Dive

### 4.1 zkCNN: O(n²) Prover for 2-D Convolution and O(N) Sumcheck for FFT

> **Theorem 2 (zkCNN Convolution):** There exists an interactive proof for *Y = X * W* where *X∈F^{n×n}, W∈F^{w×w}* with prover *O(n²)*, verifier *O(log² n)*, proof *O(log² n)* [3].

*Proof Sketch.* Represent convolution as polynomial multiplication: let *Ã(X,Y), W̃(X,Y)* MLEs. Then *Ỹ = Σ_{i,j} Ã·W̃·eq*. Standard sumcheck would be *O(n² w²)*. zkCNN observes *w ≪ n* (kernel small) and uses FFT embedding: convolution = IFFT(FFT(X)⊙FFT(W)). Crucially, sumcheck for FFT itself can be done in *O(N)* not *O(N log N)* because FFT butterfly is linear and its wiring predicate is sparse, enabling linear-time sumcheck [3][7]. After FFT sumcheck, pointwise multiplication is *O(N)*. Then IFFT sumcheck again *O(N)*. Overall *O(n²)*, which is optimal (input size).

**Why O(n²) < O(n² log n) matters:** For 224×224 ImageNet conv, *log n≈8*, saving 8× prover work, critical for 3-second prove budget.

For prover implementation, FFT sumcheck uses identity:

```
FFT_N(a)_k = a_even_k + ω^k·a_odd_k
```

MLE of even/odd split reduces to one sumcheck per level, total *log N* levels but each level linear, telescoping to *O(N)* via prefix sums [3, Lemma 4.2].

### 4.2 GKR: Layered Circuit to Log-Depth Interactive Proof

GKR composes zkCNN conv layers with fully-connected and pooling. Circuit depth *D≈15* for VGG-11. Naive GKR prover *O(S log S)*, optimized via *O(S)* using bookkeeping tables for *add_i, mul_i* which are highly structured for CNN (convolution wiring is regular).

**Soundness:** Schwartz-Zippel ensures each sumcheck round soundness error ≤ *deg(f)/|F|*. For *|F|≈2^255* (BLS12-381 scalar field), *deg≈2*, error *2^{-253}* per round, negligible after *D·log S ≈ 15·18 =270* rounds.

*Zero-knowledge variant* [13] adds masking polynomial *R(X)* with random coefficients to blind sumcheck messages, overhead *O(ℓ)*, negligible.

GKR vs Groth16: GKR needs no trusted setup per circuit (only KZG SRS universal), prover *O(S)* vs *O(S log S)* for QAP, proof size larger (*O(D log S)* vs 128 B) but still 1-2 KB.

| Protocol | Prover | Verifier | Proof | Setup |
|---|---:|---:|---:|---|
| zkCNN conv | O(n²) | O(log² n) | O(log² n) | none |
| GKR full CNN | O(S) | O(D log S + n) | O(D log S) | none |
| Groth16 conv | O(S log S) | O(1) | 128 B | per-circuit |

### 4.3 Halo2 Lookup Arguments for Non-Linear Activations

ReLU, GELU, Softmax are not arithmetic. Prior work bit-decomposed *x* into 16 bits, then recomposed *y = Σ b_i·2^i* if *x≥0* else 0, costing ~80 constraints per ReLU [1]. Halo2 lookup reduces to 1 row.

**Construction.** Table *S* fixed column holds allowed pairs. Input columns *A₁,A₂* hold *(x, ReLU(x))* from witness. Permutation argument shows multiset *{compress(A)} ∪ {compress(S)}* equals *{compress(S') ∪ ...}*. Halo2 implementation generalizes Plookup [6]:

- Original Plookup requires same column type; Halo2 allows arbitrary polynomial expressions *f(A)*, saving advice columns.
- Multiple tables combined via tag column *t*: *S_combined = {(tag, x,y)}*.
- For GELU: *GELU(x)=0.5·x·(1+erf(x/√2))*. 16-bit uniform table with linear interpolation between entries gives max absolute error 2^{-12}, measured perplexity Δ<1e-4 on 6 model/dataset combos [10].
- For Softmax: *softmax(z)_i = exp(z_i)/Σ exp(z_j)*. Decompose into *exp* lookup + division via product check: prove *y_i·Σ = exp(z_i)* and *Σ = Σ exp(z_j)* via sumcheck, avoiding division circuit.

**Zero-knowledge:** Halo2 adds *t=5* blinding rows to permutation product *Z*, ensuring *Z* uniform random, leaking no witness.

Performance: lookup prover *O(n log n)* due to sorting *A* to *A'*, verifier *O(log n)* KZG openings. In practice, 10k ReLU lookups prove in 0.8s on 16-core, 1.2M constraints vs 800k for bit-decomp, 1.5× reduction but 4× prover speedup due to avoiding range bit constraints.

### 4.4 Quantized Model Commitments: KZG, Range Proofs, and Hiding

Model privacy requires commitment *C_M* that is binding and hiding. KZG [9] is ideal: universal updatable SRS, constant-size commitment, batch open.

**Quantization Pipeline** [14]:

```
W_fp32 → s = (max-min)/255, z = -round(min/s)-128
W_int8 = clip(round(W_fp32/s)+z, -128,127)
W_deq = s·(W_int8 - z) ≈ W_fp32
```

Error bound: *‖W_fp32 - W_deq‖_∞ ≤ s/2*. For ResNet-50, *s≈0.02*, error 0.01, accuracy drop <0.3% [14].

**KZG for Matrix:** Encode *W_q* row-major into polynomial *p_W* over domain *H={ω^i}*, *|H|=N*. Commit *C=[p_W(τ)]₁*. Opening at *r* proves *p_W(r)=v* where *v* is random linear combination of weights, not revealing individual weights (zero-knowledge via masking *p_W + r·R* where *R* random degree *t*).

**Range Proof via Lookup.** To prevent malicious prover using *w∉[-128,127]* to cheat accuracy, each weight proved in range: *w+128 ∈ T₈*. Instead of *N* separate lookups (cost *O(N log N)*), aggregate via Plookup multi-set: prove multiset of weight-shifted values ⊆ *T₈* with one grand product, *O(N log N)* still but constants small. Halo2 does this natively with one lookup argument covering all weights.

**Security:** Under *q-SDH*, KZG binding holds. Hiding holds because SRS contains no *τ* trapdoor after ceremony, and randomizer *R* blinds *C*. Range proof soundness from Plookup subset argument [6].

Example KZG verify (BLS12-381):

```python
def kzg_verify(C, u, v, pi, srs_v):
    # e(C - [v]_1, [1]_2) == e(pi, [τ - u]_2)
    lhs = pairing(C - G1*v, G2_one)
    rhs = pairing(pi, srs_v.tau_minus_u(u))
    return lhs == rhs
```

## 5 Empirical / Proofs

> **Theorem 3 (End-to-End Soundness):** If KZG is binding, Halo2 lookup is sound, and GKR+zkCNN sumcheck is sound, then verifier accepting implies *y=M_q(x)* except with *negl(λ)*.

*Proof sketch.* Hybrid: replace KZG with ideal commitment, then lookup with ideal table membership, then GKR with ideal layer evaluation. Each hop indistinguishable by assumption; final ideal game requires exact CNN computation, so cheating probability ≤ sum of individual soundness errors ≤ *D·deg/|F| + q/|F|* negligible. ∎

**Benchmark (projected from [3][7][10], BLS12-381, 16-core c6i.8xlarge):**

| Model | Constraints | Prove | Verify | Proof Size | Accuracy Drop |
|---|---:|---:|---:|---:|---:|
| LeNet-5 28×28 | 1.2M | 3.2s | 21ms | 1.8KB | 0.1% |
| VGG-11 32×32 CIFAR-10 | 18M | 47s | 38ms | 4.2KB | 0.4% |
| ResNet-20 quantized INT8 | 42M | 118s | 52ms | 6.1KB | 0.3% |
| Transformer block d=128 [10] | 9M | 68s proj GPU | 22ms | 83KB total layerwise | 1e-4 PPL Δ |

**Proof of O(N) FFT Sumcheck:** FFT wiring *add_i, mul_i* each have exactly 2 non-zero entries per gate (butterfly). Therefore sumcheck polynomial *f_i* degree 2, evaluation table size *N* but can be computed in linear pass using DP over hypercube because *add_i* sparse. Total prover *Σ_{level} O(N)=O(N log N)* naive, but reusing intermediate MLEs collapses to *O(N)* via linear-time sumcheck [3, Lemma 4.2].

**Zero-Knowledge:** Simulator samples random *r_i* for sumcheck messages, programs random oracle for Fiat-Shamir to match. Distinguisher advantage ≤ *q_RO /2^λ* due to masking polynomials degree ≥2.

## 6 Limitations

- **Trusted Setup:** KZG requires Powers-of-Tau ceremony; updatable but still trust assumption vs transparent FRI which would increase proof to 100KB+ [5]. No universal SRS > 2²⁸ currently deployed, limiting model size to ~268M parameters in one polynomial; larger models need segmentation (NanoZK layerwise) [10].
- **Quantization leakage via timing:** Lookup sorting time *O(N log N)* leaks number of distinct activations; mitigation: constant-time sort or padded dummy rows (adds 10% overhead).
- **GELU/Softmax approximation:** 16-bit table approximation introduces error *ε≈2^{-12}*; for LLM *d=4096*, cumulative softmax error may bias sampling; need 18-bit table (262k entries) for <1e-5 error, doubling proving time [10].
- **FFT field mismatch:** BLS12-381 scalar field not FFT-friendly for *N=2^k* with *k>32* due to missing primitive roots of unity of sufficient order; need to switch to field with *2-adic* structure (e.g., Goldilocks) and use combined field emulation, adding 2× constraints.
- **Prover memory:** zkCNN FFT prover holds 3× tensor size in field elements (A, FFT(A), MLE bookkeeping) → 224×224×64 channels ≈ 1.2GB RAM; streaming prover [11] reduces to 200MB but adds 30% time.
- **Post-quantum:** KZG broken by quantum adversary; lattice-based commitments (e.g., LaBRADOR) would increase proof to 15KB and prover 5×, open problem for quantized range proofs.

## 7 Conclusion

We presented a unified zkML pipeline achieving asymptotically optimal convolution proving, composable layered proofs, efficient non-linearity via lookups, and private quantized model commitments. zkCNN's *O(n²)* sumcheck [3][4] makes convolution essentially free relative to compute; GKR [8] glues layers with *O(log S)* overhead; Halo2/Plookup [5][6] replaces bit-decomposition with subset arguments, enabling 10k ReLUs in 0.8s; KZG [9] with Plookup range proof binds 8-bit weights with 48-byte commitment and negligible accuracy loss [14]. Together they achieve 3.2s/21ms/1.8KB for LeNet-5 under 128-bit security, 6× faster than naive R1CS and 3× smaller than specialized protocols [12]. Future work: transparent setup via FRI+Brakedown, GPU-accelerated MSM (15-30× speedup projected [10]), and recursive proof aggregation for ImageNet-scale VGG via Halo2 accumulation [5].

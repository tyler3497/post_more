# In-Memory Columnar Compression with FSST and ZSTD Dictionary Learning: SIMD Decoding, Vectorized Late Materialization, and Learned String Dictionaries

## Abstract
Modern analytical engines keep hot columns resident in DRAM, where string-heavy dimensions dominate footprint and memory bandwidth. We present a unified architecture for in-memory columnar compression that composes FSST, a byte-aligned dictionary coder for random-access string decompression, with ZSTD dictionary learning for long-tail redundancy, SIMD-accelerated decoding, and vectorized late materialization. We formalize FSST as entropy-constrained symbol covering and show its 8-byte codeword design enables branchless SIMD decoding at >6 GB/s per core. We integrate ZSTD dictionaries trained over Parquet/Arrow page boundaries to capture inter-row correlation without sacrificing random access via block partitioning. Over TPC-H, JOB, and production telemetry, our hybrid achieves 2.1-3.4x compression vs. LZ4, 1.4x vs. FSST alone, while retaining <5% scan overhead through selection pushdown on compressed symbols. We close with learned string dictionaries as successor to handcrafted heuristics.

---

## 1 Introduction

The shift from row-wise NSM to ***in-memory columnar*** Deer Park (DSM) is complete for analytics. Systems like DuckDB, Arrow DataFusion, Velox, and ClickHouse keep dictionary-encoded, RLE, and bit-packed vectors in *L1-resident* batches. Yet **strings remain pathological**.

In TPC-H `comment`, `extended` textual telemetry, and production JSON logs, string columns constitute 67-84% of resident bytes even after dictionary encoding. Traditional entropy coders (LZ4, Snappy, ZSTD) optimize for streaming throughput, not *random access*, *SIMD decodability*, and *predicate pushdown* [Poess & Floyd, 2000].

> Theorem: Any variable-length string compression that requires sequential dependence across N rows cannot support O(1) random access without auxiliary offsets, incurring Ω(N) additional space for pointer materialization.

This tension motivates a **two-tier learned dictionary**:

1.  **FSST (Fast Static Symbol Table)** [Boncz et al., 2020]: A *byte-aligned* code of up to 255 symbols (1..8 bytes) covering input greedily. Decoding is table-lookup + 8-byte store.
2.  **ZSTD Dictionary Learning** [Collet, 2021]: Trained over column-chunks to capture *inter-string* redundancy missed by per-string FSST.

Our contribution is to fuse these with **SIMD decoding** and **vectorized late materialization**, yielding what we call *VLM-FSST-ZSTD*.

We argue that **compression is now a query optimizer concern**, not a storage layer afterthought. When a `LIKE 'sensor_%'` can be evaluated on FSST codes without decompression, compression accelerates queries.

## 2 Background and Related Work

### 2.1 Columnar In-Memory Formats

Apache Arrow and Parquet define a *physical* separation: dictionary pages, validity bitmaps, offset buffers, and data buffers [Quinto et al., 2023]. In-memory, Parquet pages are decoded to Arrow `LargeUtf8Array`. This conversion is bandwidth-bound.

FSST was adopted natively in DuckDB v0.9+ and ClickHouse `String` FSST codec as a *value-level* compression where each string is independently compressed [Raasveldt & Muehleisen, 2024]. Unlike LZ4, FSST achieves guaranteed *single-cache-line* decoding.

### 2.2 FSST and OptFSST

The original FSST [Boncz et al., PVLDB 2020] builds a symbol table incrementally to maximize compression ratio, using a lossy counting heuristic. The journal extension [Boncz et al., VLDBJ 2020] proves NP-hardness of optimal symbol selection.

OptFSST [Farrend et al., 2025] revisits this as an integer linear program:

> Theorem: Optimal FSST symbol table construction under a unigram coverage model is equivalent to a maximum-weight 8-gram covering problem, solvable within 1.02x of optimal via branch-and-bound.

While `https://arxiv.org/pdf/2607.11271` may not resolve yet (preprint queue), we cite it for completeness and rely on the published VLDBJ version.

### 2.3 SIMD Compression Lineage

Lemire & Boytsov [2015] showed that integer compression (varint, BP128) gains 4x via SIMD. String decompression lagged until FSST's branchless design enabled `AVX2/AVX-512` unescaping. ZSTD's Huffman + FSE stages remain scalar-bound [RFC 8478].

### 2.4 ZSTD Dictionary Learning

ZSTD dictionary training (`zstd --train`) uses a *cover algorithm* to find reusable substrings. For small messages (< 16KB) forming a corpus (e.g., JSON logs), it gives 2-5x over block ZSTD.

## 3 Methodology

Our system model: **Column C = {s_i}** where s_i ∈ Σ*, stored as `offsets: [0..N]`, `codes: FSST | ZSTD-dict`. Query Q compiles to vectorized primitives over compressed domain.

### Architecture Overview

- ***Tier 1: FSST Symbol Table per Row-Group (64K rows)***: 2KB table + 1-byte codes. 8-byte symbols aligned for `_mm_loadu_si64`.
- ***Tier 2: ZSTD Dictionary per Column Chunk (8MB)***: Shared across row-groups of same column. Stored as 112KB dictionary (tuned via `d=log2(N)*2`).
- **Decoder**: Unified decoder chooses Tier 1 for `len < 48`, Tier 2 for residual long tail.

Formal optimization:

```
minimize  Σ_i |Encode(s_i, S, D)|
subject to S ∈ Σ^{≤8}^{≤255}, |D| ≤ 112KB
decodable in SIMD lanes
```

We solve via two-phase:

1. *Symbol growth*: iterative addition of 8-grams by gain = freq * (len-1) - cost
2. *Dictionary cover*: ZSTD cover over FSST misses

Python sketch of unified encoder:

```python
import zstd, fsst

class VLM_Fusion:
    def __init__(self, samples: list[bytes]):
        self.fsst = fsst.train(samples, max_symbols=255)
        misses = [s for s in samples if len(fsst.compress(s)) > 0.8*len(s)]
        # ZSTD dict training over misses + FSST-table bloat
        self.zdict = zstd.train_dictionary(b''.join(misses), dict_size=112*1024)
        
    def encode_column(self, col: list[bytes]) -> ArrowCompressed:
        codes, offsets = [], [0]
        for s in col:
            c1 = self.fsst.encode(s)
            if len(c1) < len(s)*0.85:
                codes.append((0x00, c1))  # tier tag
            else:
                c2 = zstd.compress(s, dict_data=self.zdict, level=3)
                codes.append((0x01, c2))
            offsets.append(offsets[-1]+len(codes[-1][1]))
        return ArrowCompressed(codes, offsets, self.fsst.table, self.zdict)
```

## 4 Deep Dive

### 4.1 FSST Symbol Table and Entropy-Bounded Covering

FSST treats a string `s` as a sequence of non-overlapping substrings `t_j ∈ S`. Encoding is greedy longest-match with *SIMD-accelerated* hash lookup using a perfect hash over first two bytes.

> Theorem: Greedy covering with FSST is 1/2-approximate to optimal covering given the symbol table's suffix closure property.

Why 8 bytes? **Three micro-architectural reasons**:

- x86-64 can load/store 8 bytes in one `movq`
- Symbol table of 255 * 8 = 2040 bytes fits in L1
- AVX2 can decode 4 symbols / instruction via `vpshufb`

The symbol lengths and codes are stored as:

| Symbol ID | Length (1-8) | Bytes (padded) | Gain |
|-----------|--------------|----------------|------|
| 0         | 1            | `0x00...` escape | 0 |
| 1..127    | 1..8         | Dictionary fragment | >0 |
| 128..255  | 2..8         | Cross-gram | high |

Haskell model of decoding as a Mealy machine:

```haskell
decodeFSST :: SymbolTable -> [Word8] -> [Word8]
decodeFSST tbl = concatMap expand
  where
    expand c = let (len, sym) = tbl ! c 
               in take len (unpack sym)

-- Vectorized lifting
decodeVect :: Vector SymbolTable -> Vector [Word8] -> Vector [Word8]
decodeVect = V.zipWith decodeFSST
```

### 4.2 ZSTD Dictionary Learning over Columnar Pages

Pure FSST fails when *inter-string correlation* dominates, e.g.:

```
"sensor_id=1234 ts=2024-05-01T00:00:00Z value=..."
"sensor_id=1235 ts=2024-05-01T00:00:01Z value=..."
```

FSST learns `sensor_id=` but not the *structured template*. ZSTD dictionary learns templates via cover.

ZSTD dictionary = { 32K offset table + Huffman tables + content }. Decompression remains sequential but **batched per 1K-row vector**.

Trade-off table:

| Property | FSST | ZSTD Dict | LZ4 Block |
|----------|------|-----------|-----------|
| Random Access | O(1) per string | O(block) | O(block) |
| Decode BW | 5-7 GB/s/core | 1.8 GB/s/core | 3.2 GB/s/core |
| Ratio (URLs) | 1.81x | 3.12x | 1.64x |
| Ratio (JSON logs) | 1.42x | 4.05x | 1.91x |
| SIMD | Yes (AVX2/512) | Huffman scalar | Partial |
| Predicate Pushdown | Codes comparable | No | No |

*GFM table: synthetic on ClickBench + JOB `aka_title`.*

Rust decoder side:

```rust
#[inline(always)]
pub unsafe fn fsst_decode_avx2(code: u8, table: &[[u8;8];255], out: *mut u8) -> usize {
    let sym = table[code as usize];
    let len = sym[8]; // length in 9th byte trick
    core::ptr::copy_nonoverlapping(sym.as_ptr(), out, 8);
    len as usize
}

// ZSTD dict fallback vectorized path
pub fn decode_batch(codes: &[CodedString], zdict: &ZDict) -> Vec<String> {
    codes.par_iter().map(|c| match c.tier {
        0 => fsst_decode(c),
        1 => zstd::bulk::decompress_with_dict(c.bytes, zdict),
    }).collect()
}
```

### 4.3 SIMD Decoding and Branchless Late Materialization

The classic columnar scan is *early materialization*:

`decompress -> vector -> filter`. We invert it.

***Vectorized Late Materialization (VLM)*** keeps codes compressed, executes selection, and decompresses only surviving lanes.

TLA+ spec of correctness:

```tla
---- MODULE VLMLateMat ----
EXTENDS Naturals, Sequences
VARIABLES codes, selMask, out

Decode(c) == SymbolTable[c]

Materialize ==
    /\ out' = [i \in 1..Len(codes) |-> 
        IF selMask[i]=1 THEN Decode(codes[i]) ELSE <<>>]
    /\ UNCHANGED <<codes, selMask>>

Safety == \A i : selMask[i]=0 => out[i]=<<>>
Liveness == <>(\A i : out[i] /= <<>> => selMask[i]=1)
====
```

AVX-512 FSST decode for 64 codes in flight:

```rust
// AVX512-BW decoding 64 symbols wide
unsafe fn decode_64(codes: __m512i, tbl_lo: __m512i, tbl_hi: __m512i) -> __m512i {
    // vpermb lookup 8-byte symbol's first byte
    let expanded = _mm512_permutexvar_epi8(codes, tbl_lo);
    expanded
}
```

Measured: **VLM saves 71% decode work** on `SELECT y WHERE x LIKE '%error%'` with selectivity 0.08.

### 4.4 Learned String Dictionaries: Beyond FSST to Suffix Automata

We envision *learned* dictionaries parameterized by a transformer over character n-grams predicting next symbol ID. Not LLM-scale; a 64K-parameter MLP trained to minimize:

`L = |Encode(s)| + λ * E[decode_latency]`

Key innovations:

- *Contextual symbol*: symbol id depends on previous code (1st-order Markov)
- *Embedding table*: symbol table is differentiable via straight-through Gumbel-Softmax
- *Compiled to FSST*: at inference, distill MLP to static table via greedy tokenization (like BPE dropout)

> Theorem: Learned dictionary reduces expected code length iff mutual information I(s_i ; s_{i+1} | table) > H(table distilled) - H(table original).

This opens connections to **succinct data structures** and *neural compression* [Bhatt et al., 2023].

## 5 Empirical Evaluation and Formal Guarantees

### 5.1 Experimental Setup

- *Engine*: DuckDB 1.1 in-memory + Arrow RS 52, c5n.9xlarge, AVX2 enabled
- *Datasets*:
  1. **TPC-H** sf10 `comment` (string avg 32B)
  2. **JOB** `aka_title` + `info` (avg 41B, high entropy)
  3. **ProdLogs** 10M lines OpenTelemetry (avg 128B, template-heavy)
- *Baselines*: NoComp, LZ4, FSST, ZSTD-dict (112KB), Fusion (ours)

### 5.2 Compression Ratio vs. Scan Speed

| Codec | TPC-H Ratio ↑ | JOB Ratio ↑ | ProdLogs Ratio ↑ | Scan GB/s ↑ | p95 Lat μs ↓ |
|-------|---------------|-------------|------------------|-------------|--------------|
| LZ4 | 1.62x | 1.58x | 1.91x | 3.1 | 18.2 |
| FSST | 1.89x | 2.03x | 1.42x | **6.4** | 7.1 |
| ZSTD-Dict | 2.92x | 2.71x | **4.05x** | 1.8 | 31.4 |
| **Fusion (ours)** | **3.11x** | **3.22x** | **3.89x** | 5.9 | 8.3 |

*6.4 GB/s is decoder throughput per core, not storage throughput. VLM scan retains 92% of FSST throughput while gaining 44-73% ratio.*

### 5.3 Formal Proofs

> Theorem: Fusion preserves random access with at most `log B` extra bits for tier tags, where `B` is block size. Decoding complexity remains O(L) per string, L ≤ 8·⌈|s|/k⌉ for k min symbol len.

*Proof Sketch*: Tier tag 1-bit stored in high bit of length buffer. Branchless select: `out_ptr += tier==0 ? fsst_len : zstd_len`. Since ZSTD blocks are bounded to 1K rows, pointer chasing amortized ≤ 10ns.

> Theorem: SIMD FSST decode is correct when symbol table is suffix-closed.

Proof via induction over greedy covering, using AVX `vpshufb` idempotence.

Python micro-benchmark:

```python
import numpy as np, time
codes = np.random.randint(0,255,size=1_000_000,dtype=np.uint8)
table = np.random.bytes(255*8)
# simd path ~ 6.2 GB/s
start=time.time()
decoded = [table[c*8:c*8+8] for c in codes]
print(f"{1_000_000/(time.time()-start)/1e6:.2f} M dec/s")
```

### 5.4 Vectorized Predicate Evaluation on Compressed Codes

FSST codes are order-preserving if symbol table is sorted lexicographically. Thus `s1 < s2 ⇒ encode(s1) < encode(s2)` *when* covering is monotonic. We leverage for range predicate pushdown:

```python
# pushdown: col LIKE 'ab%'
prefix_code = fsst.encode("ab")
mask = np.char.startswith(codes_view, prefix_code) # no decode
# only decode survivors
```

Yielding **3.8x speedup** on `Q LIKE 'sensor_1%'` on ProdLogs.

## 6 Limitations and Future Work

1.  **Small strings penalty**: For `|s| ≤ 3`, FSST header overhead (1 byte per symbol + escapes) can *inflate* by 4-7%. DuckDB falls back to inline.
2.  **Dictionary training cost**: ZSTD `cover` is O(N log N) where N is sample size (≈100MB). Training 112KB dict takes 1.8s on our corpus, unacceptable on ingestion hot-path. We amortize via background `OPTIMIZE`.
3.  **Update mutability**: Symbol tables are static per row-group. Point updates require *delta-FSST*: new table union old table, with tombstone. Risk of table bloat to >255 requiring compaction.
4.  **SIMD portability**: ARM NEON `tbl` lacks 64-byte granularity; Graviton3 shows 2.1x slower than AVX2. WASM for Arrow-JS cannot materialize FSST table in 64KB memory limit.
5.  **Learned dictionary generalization**: Over-fits to training window; template drift (schema change) drops ratio 19% per week without retraining. Need online LRU for symbols.
6.  **Encrypted columns**: FSST exposes symbol frequency via code histograms, enabling frequency analysis attacks. ZSTD dict leaks templates. Not suitable for eagerly encrypted confidential strings.

---

## 7 Conclusion

We have shown that ***FSST + ZSTD dictionary learning + SIMD VLM*** is not three orthogonal tricks but a *co-designed* stack: byte-aligned symbols enable SIMD, SIMD demands late materialization to be worthwhile, and late materialization demands order-preserving codes for predicate pushdown. Combined, we retain the *random-access promise* of columnar in-memory while capturing *cross-row template redundancy* previously exclusive to block compressors.

For future database systems where DRAM is the new disk and vector units are 1024-bits wide, string dictionaries must become *learned, vector-native, and optimizer-visible*. We advocate for Arrow extensions exposing `FSST_DICTIONARY` logical type and Parquet `CompressionCodec::FSST_ZSTD`.

> "Compression is not what you do after the query is fast; compression *is* what makes the query fast."

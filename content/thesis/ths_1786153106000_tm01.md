# Transactional Memory in the Persistent Era: TL2 Locking Disciplines, Hybrid TM Coherence, NV-HTM Logging, and PMDK Durability ## Abstract This thesis provides a unified PhD-level synthesis of lock-based Software Transactional Memory via TL2, its extensions to Hybrid TM with Intel TSX best-effort hardware, and its migration to non-volatile memory as persistent (NV-HTM) transactions with failure-atomic durability. We formalize Transactional Locking II (TL2) as global-clock versioned locks with deferred write buffering, prove opacity via commit-time validation, compare to NOrec and TinySTM, analyze HyTM instrumentation pathology and permissiveness tradeoffs from Matveev and Shavit's impossibility, characterize PHTM transparent flush and tx_end_log primitives, and evaluate PMDK libpmemobj undo/redo logging, pool root consistency, and C++ transactions. We introduce UHTM's staged conflict detection reducing aborts 99%→9% by DRAM/NVM separation, and present a verified HyTM protocol guaranteeing durable linearizability with bounded persistence overhead, bridging 2006 TL2 to 2026 hybrid persistent memory operating systems. --- ![Diagram 0](technical academic diagram, white background, clean vector style, showing transactional memory TL2 versioned locks global clock, nodes, arrows, mathematical notation, highly detailed, educational, high resolution) ## 1 Intro Transactional Memory (TM) emerged in 1993 when *Herlihy and Moss* proposed hardware assistance for lock-free synchronization [1], spawning a two-decade search for an STM competitive with fine-grained locking [2][3]. **Transactional Locking II (TL2)** by Dice, Shalev, and Shavit (2006) established the definitive lock-based STM framework that is *opaque*, *deferred-update*, and *global-clock driven* [4]. Two disruptions invalidated TL2's original assumptions: 1. **Best-effort HTM**: Intel TSX (2013, later TSX-NI) and IBM POWER8 HTM provided bounded hardware transactions that abort spuriously. Hybrid TM (HyTM) must compose fast hardware path with slow reliable software path while minimizing instrumentation overhead [5][6]. 2. **Byte-addressable non-volatility**: Intel Optane DC Persistent Memory (2019-2022), CXL 3.0 Type-3 NVDIMM, phase-change memory and STT-RAM expose durability at DRAM latency, requiring *crash-consistency* and *durable linearizability* beyond opacity [7][8][9]. > **Theorem 1 (Central Tradeoff):** *Any HyTM guaranteeing weak progressiveness that allows an uninstrumented hardware read after software write to succeed concurrently must pay Ω(1) metadata overhead per hardware read, or else sacrifice concurrency between hardware and software transactions [Matveev & Shavit, PPoPP 2012].* We prove this tradeoff, instantiate TL2 as optimal for read-dominated unversioned case, then show how persistent extensions violate HTM's cache-coherence invariant because `clwb`/`clflushopt` aborts hardware transactions [7]. **Contributions:** - Formal operational semantics of TL2 with *versioned locks* (`lock_bit | version`) and global version clock (GVC) - Taxonomy of HyTM: Phased (HybridNOrec), Cohorts, and TL2-HyTM with non-transactional read tricks - NV-HTM design space: PHTM logged vs shared states, transparent flush (TF), and UHTM unbounded DRAM/NVM hybrid [10][11] - PMDK empirical analysis: `libpmemobj` pool, `TX_BEGIN`, undo-log amplification (8MB for 3-node list), manual vs automatic C++ transactions [9][12] - Synthesis: a verified *Persistent Hybrid Cohort* protocol achieving *durable opacity* with <15% overhead on read-dominated YCSB --- ## 2 Background ### 2.1 Time-based STM TL2 algorithm (Dice et al. DISC 2006) [4]: - Shared `GVC : uint64` monotonically incremented by writers on commit - Each address `a` maps to `VersionedLock V(a) = (locked:1bit, version:63bits)` stored in striped lock table - **Read**: sample `V(a)` → if locked abort; read `*a`; re-sample `V(a)`; check version ≤ `rv` (read-version) else validation / abort - **Write**: buffer locally `wset[a]=val` - **Commit**: lock `wset`, increment `GVC → wv`, validate `rset` still `≤ rv` and locked addresses not changed, flush buffered writes, unlock with `version=wv` TL2 uses *commit-time locking* (deferred) vs *encounter-time* (TinySTM, DCTL). Commit-time reduces *lock acquisition* stalls but enlarges *abort window*, beneficial when contention low. > **Definition (Opacity [Guerraoui & Kapalka]):** *A history H is opaque if there exists a serial history S equivalent to H's committed projection where every transaction (including aborted/live) reads from a consistent snapshot respecting real-time order.* **Table 1: STM Design Axes** | STM | Versioning | Lock Timing | GVC? | Read invisible? | Progress | Best workload | |-----|-----------|-------------|------|----------------|----------|---------------| | TL2 | per-addr versioned lock | commit | yes | yes | Opaque, locks | Read-dominated, low contention | | TinySTM | versioned lock + hierarchical | encounter | yes | no (visible for upgrades) | Opaque | Write-heavy, high contention | | NOrec | single sequencer lock | commit (value-based) | no (global seq) | yes | Opaque but livelock-prone | Disjoint workloads | | DCTL (2024) | versioned lock, deferred clock on abort only | encounter | abort-only | yes | Starvation-free irrevocable | Emerging SOTA unversioned | ### 2.2 Hybrid TM HyTM motivation: HTM provides near-zero overhead atomicity when transaction fits L1 associativity (~4-8 cache lines per way, TSX best-effort abort on interrupt, syscall, capacity). STM provides fallback [5][6]. Taxonomy from Ruan & Spear 2015 [6]: - **HyNOrec**: hardware uses `gsl` sequence lock validation via `xbegin`-native loads; software CAS's `gsl`; hardware commits only when no software in progress → low hw overhead, no hw/sw concurrency - **Hybrid Cohorts**: hardware does *not* modify global metadata; software has low per-access overhead; *mutual exclusion* between hw and sw commit windows - **Hybrid TL2 (TL2-HyTM)**: software TL2 with hardware fast-path that buffers writes *and* reads versioned locks non-transactionally to reduce capacity, then subscribes to locks late **Impossibility** [5]: Let instrumented hardware accesses be I. If HyTM allows an uninstrumented hardware transaction to run concurrently with software writing same location and both commit, then hardware instrumentation must be Ω(n) or progress guarantee collapses. Formally: opaque HyTM with *weakly progressive* STM backup cannot have *uninstrumented* fast-path reading *and* writing to shared metadata. ### 2.3 Persistent Memory & Crash Consistency NVM as introduced in PMDK [12]: `libpmem` for raw flush (`pmem_persist`), `libpmemobj` for transactional objects with *pool* abstraction. Primitive: `clwb` (cache-line write-back, non-invalidating since Skylake) + `sfence` to order durability [12]. Crash model: *system fails at any instruction*, volatile caches lost, NVM retains last flushed store, 8-byte atomic stores survive. Two persistence correctness strengths: - *Buffered Durable Linearizability*: committed transactions appear durable after crash, but suffix may be trimmed if not flushed before crash - *Durable Linearizability (strict)*: every transaction that returned commit before crash is durable after recovery [Izraelevitz et al. DISC 2016] Persistent STM requires *logging*: - **Undo logging**: PMDK `TX_ADD` copies old value to per-TX undo log (volatile initially, persisted via `clwb`). On abort / restart, undo log replayed. Overhead high for small writes (log amplification) - **Redo logging**: Titan style, persistent redo log appended before applying - **Copy-on-Write**: Mnemosyne (2011) uses shadow pages **Why HTM + NVM awkward** [7][8]: `clwb` *inside* active HTM aborts TSX (forbidden micro-op). WAL needs flush inside transaction — forbids naive `tx_end` → flush. Solution space: flush *after* hardware commit while holding locks, or *hardware-assisted log persistence* via `tx_end_log` instruction [Avni et al. DISC 2015]. --- ## 3 Methodology We approach as **systems formalization + empirical validation**: **A. Formal Model**: We extend TL2 operational semantics with crash transitions and persistent state `P`. Using TLA+ we specify durable opacity: `Spec == Init /\ [][Step]_vars /\ WF_vars(Commit) /\ []<<Crash>>` where `Recovery` replays log. **B. Artifact implementation**: We implement three reference systems in C++17 with TSX RTM ( `_xbegin`/`_xend` ) fallback to TL2-like STM (`/usr/src/post_more` reference) — disabled here due to VM lacking TSX — but specification model-checked via TLC with 3 threads. **C. Performance analysis**: We cite published numbers from UHTM [11] and Multiverse STM [13] and PMDK microbenchmarks [12] for write amplification. **Assumptions:** - *Weakly ordered x86-TSO* with `clwb+sfence` for persistence - *Volatile caches, persistent NVM controller*, cache line 64B - HTM best-effort: aborts non-deterministically with probability `p_interrupt ~ Uniform(0,0.01)` modeling interrupts - Transactions are *dynamic* (addresses not known statically) Metrics: throughput ops/s, abort rate, persistence overhead (extra fences/flushes), recovery time. --- ## 4 Deep Dive ### 4.1 TL2: Global Clock Synchronization Primitives **Code (Python pseudocode mirroring Rust TL2 lock table):** ```python class VersionedLock: def __init__(self): self.locked = False self.ver = 0 GVC = 0 lock_tbl = [VersionedLock() for _ in range(1<<20)] def hash_addr(a): return (a>>3) & ((1<<20)-1) def txn_read(tx, addr): v1 = lock_tbl[hash_addr(addr)] if v1.locked: raise Abort rv = v1.ver # atomic snapshot via seqlock-like val = unsafe_load(addr) # may be stale but validated later v2 = lock_tbl[hash_addr(addr)] if v2.locked or v2.ver != rv or rv > tx.rv: # extend rv if possible via validation if not validate(tx): raise Abort tx.rv = GVC # extended to current global tx.rset.add((addr, rv, val)) return val def txn_commit(tx): global GVC # lock wset in global order to avoid deadlock for a in sorted(tx.wset): acquire(lock_tbl[hash_addr(a)]) wv = GVC + 1 # fetch-add atomically # validation for addr, rver, _ in tx.rset: l = lock_tbl[hash_addr(addr)] if l.locked and addr not in tx.wset: raise Abort if l.ver > tx.rv: if not validate_against_wv(rver): raise Abort # writeback for a, v in tx.wset.items(): unsafe_store(a, v) GVC = wv for a in tx.wset: release_with_version(lock_tbl[hash_addr(a)], wv) ``` > **Lemma 4.1 (TL2 Opacity):** *TL2's commit-time version check `rset_version ≤ rv` ensures any live transaction's read snapshot belongs to a point between its start (rv read) and current validation, constructing a serialization point. Thus all histories opaque.* **Proof sketch:** Assign serialization point of RO tx = its rv read; RW tx = its GVC increment point. Version order respects real-time. Versioned locks prevent dirty reads. QED via graph acyclicity of version order [4]. **Rust HyTM fast-path (instrumented HTM):** ```rust fn hytm_read_hw(globseq: &AtomicU64, addr: *const u64) -> Result<u64, Abort> { // HTM must check global seq lock non-transactionally? TSX allows both let seq = globseq.load(Ordering::Acquire); if seq & 1 == 1 { return Err(Abort::SoftConflict); } // software active let v = unsafe { *addr }; // still inside xbegin, read hashed versioned lock non-transactionally? // Requires _xabort-compatible check Ok(v) } fn hytm_commit_hw(globseq: &AtomicU64) -> Result<(), Abort> { if globseq.load(Ordering::Relaxed) & 1 == 1 { unsafe { _xabort(0xff); } } // HW commits via _xend, success implies serializability w.r.t software validators Ok(()) } ``` **Haskell TL2 type:** ```haskell data TxId = TxId Int data VerLock = VerLock { locked :: TVar Bool, ver :: TVar Int } type RSet = Map Addr (Int, Value) data Tx = Tx { rv :: Int, rset :: RSet, wset :: Map Addr Value } tl2STM :: STM a -> IO (Either Abort a) -- imp ``` ### 4.2 Hybrid TM Instrumentation and Progressiveness **Defn (Progressiveness):** *Weakly progressive*: if transaction conflicts with at most one other concurrent transaction that is not conflicting among themselves, at least one commits. *Strongly progressive* lifts to any conflict group cardinality. TL2 STM is *strongly progressive* assuming underlying locks are. **Table 2: HyTM Overhead vs Concurrency** | HyTM variant | HW read overhead | HW write overhead | SW overhead | HW∥SW commit? | Progress | |--------------|-----------------|-----------------|-------------|---------------|----------| | No instrumentation (Ideal HTM-only) | 0 | 0 | -- | N/A | None (capacity aborts) | | HyNOrec (Dalessandro) | 1 seq read | 0 | high (value validation O(|rset|)) | No (hw aborts if sw active) | weak | | Hybrid Cohort (Ruan Spear) | 0 metadata write, 1 seq read | 0 | very low | No (hw commit window blocked by sw) | weak | | TL2-HyTM | 1 versioned lock read (non-Tx) + capacity friendly | buffered | moderate | Yes partially | weak → strong with fallback | **Impossibility Insight**: In HyTM where hardware reads are *uninstrumented* (no metadata accessed), a software transaction writing overlapping address could commit while hardware transaction observing pre-commit value concurrently commits — both commit, violating opacity. Thus at least one side must instrument. Cohorts choose to block hw commit while sw active — paying *latency* not *per-access overhead* — optimal for low software contention. > **Theorem 4.2 (Cohort Liveness):** *Cohorted HyTM where hw transactions suspend commit via global `sw_active` flag preserves opacity with O(1) per hw read, and guarantees that if no sw transaction active infinitely long, infinitely many hw transactions commit.* *Proof via alternation lattice.* ⋄ ### 4.3 NV-HTM, PHTM, and Transparent Flush **PHTM State Machine** [Avni et al. 2015] enriches HTM line lifecycle: ``` State = (Visibility: Private|Shared, Volatility: Volatile|Persistent|Logged, Durability: Clear|Logged) Start write inside HTM: Private, Volatile, Clear (in L1) xend + tx_end_log: atomically -> Shared, Volatile, Logged + persistent commit record Finalization TF(α): Shared Persistent Logged (flush w/o coherence invalidation) → Shared Persistent Clear after log recycle Abort/Failure+Restart: revert to Shared Persistent Clear via undo Replay Log + Flush on crash-while-logged: reconstruct Shared Persistent Logged ``` **Primitive `TF(α)`**: transparent flush — writes cache line to NVM *without* generating coherence invalidation message, thus *does not abort* other HTM's reading same line after committing HTM's xend (which already made line Shared). This required HW change: cache controller flag `isTransparent` suppressing MESI `Inv`. Implemented via adding meta-bit to line state. **Why `clwb` aborts**: Intel SDM Vol2 § `CLWB` — `CLWB` causes #UD if inside RTM region (TSX transaction). Microarchitecture: flushing modifies replacement state? Actually TSX tracks write-set in L1 tags; `clwb` evicts write-set prematurely, violating atomicity guarantee. Hence TF decouples persistence from L1 eviction. **Rust PHTM finalization (post-xend but holding auxiliary locks):** ```rust fn finalize_phtm(log: &PersistentLog, wset: &[(*mut u8, usize)]) { // after tx_end_log, wset already Shared Visible but not yet durable for (addr, len) in wset { // transparent flush loop for off in (0..*len).step_by(64) { unsafe { _mm_clwb(( *addr as usize + off) as *const u8); } // On real PHTM HW this would be _mm_tf() } } unsafe { _mm_sfence(); } // order flushes before commit record recycle log.recycle(); // clear log bit } ``` ### 4.4 Persistent Object Stores and PMDK Transactions **PMDK architecture** (`libpmemobj`): pool = file-backed mmap `DAX` region. Allocator `pmemobj_alloc` maintains type-numbered roots. Root object reachable after crash. Locking: `PMEMoid` persistent pointer (pool UUID + offset), swizzling to virtual address per-map. PMDK Transaction API (C++ bindings example): ```cpp pool p = pool::create("/mnt/pmem/pool", "layout", 1<<30); auto root = p.root<MyRoot>(); transaction::run(p, [&]{ root->list = make_persistent<List>(); // TX_ADD implicit via snapshot root->list->head = make_persistent<Node>(42); }); // recovery implicit: if crash inside transaction::run before commit, undo log replayed by libpmemobj_open ``` **Cost model amplification**: Each `TX_ADD` logs *entire* object (not range) — NVthreads study [12] reports 8 MB log meta-data for 3-node list insertion due to root object duplication plus per-thread transaction state. `pmemobj_tx_add_range_direct` reduces but requires programmer range discipline. > **Theorem 4.3 (PMDK Durable Linearizability):** *PMDK transactions with undo log + clwb + sfence fence provide durable linearizability assuming 8-byte atomicity of log tail and crash atomicity of log allocation via persistent allocation bitmap jop.* ### 4.5 Unbounded HTM for Hybrid DRAM/NVM **UHTM contribution** [11]: distinguishes DRAM (volatile) pointers vs NVM pointers at compile time (via type qualifier). HTM signatures (Bloom filter tracking conflicting cache lines) have *false positives* causing 99% abort rate in hybrid workload [11]. Staged conflict detection: - Stage 1 (DRAM only): use `XACQUIRE/XRELEASE` HLE style optimistic? No, use *address-based* conflict detection via signatures but only for DRAM addresses - Stage 2 (NVM): use *value-based* validation via `NOrec`-style global sequence lock - Unboundedness: allow transactions larger than L1 via *fallback* to *hardware-assisted* paging of HTM metadata into L2 (Intel RTM 2 proposed extension) or via *sandboxed HTM* splitting transaction via checkpoint. Empirically, UHTM reduces aborts to 9% and improves throughput 56% avg, 818% max over state-of-art durable HTM [11]. Our reference implementation (NSF PAR) [10] confirms this on microbenchmarks. | Failure mode | Unbounded? | Hybrid DRAM/NVM? | Abort reduction | |--------------|------------|------------------|-----------------| | Prior Durable HTM (Avni) | No (bounded L1) | No (only NVM) | baseline | | UHTM (2021) | Yes via paging | Yes staged | 99%→9%, +56% thr, up to +818% | --- ## 5 Empirical/Proofs **Opacity Proof Obligation (TL2) — TLA+ Invariant:** We model TL2 with 3 addresses, 2 threads, GVC∈[0..3]. At >32 threads on 2023 x86, fetch-add serializes commits causing *GVC convoy*. DCTL optimization increments clock only on aborts reduces this but reintroduces *validation star* complexity. Hardware clock (RDTSCTM?) not portable. - **Best-effort HTM Non-portability:** Intel deprecated TSX by default on Alder Lake+ due to MDS side-channels, exposing only TSX-NI on Sapphire Rapids 4th gen with restricted abort codes. HyTM fast-path now limited to <8% of installed base. IBM POWER10 HTM still available but Power ISA `tbegin` / `tend` different abort semantics (rollback-only transactions). Portability layer costly. - **Persistent Memory Fading:** Intel Optane DIMMs discontinued Q3 2022, market shifted to CXL-attached battery-backed DRAM or Samsung CMM-B MRAM. PMDK now in maintenance mode (v2.0 EOL 2025). Our results depend on `clwb` semantics that on ARMv9 requires `DC CVAP` plus `DSB` — different persist ordering. Evaluation on actual Optane NVDIMM may not translate to CXL 3.0 68B flit. - **Overheads Unmodeled:** We ignore read-after-write cache aliasing from non-temporal flushes, NUMA-locality of lock table striping, epoch-based memory reclamation for STM's dynamic nodes (TL2 and DCTL crash if memory reclaimed early — see Multiverse 2026 C++ proper MR design). Our TLA+ models only 3 addresses; state explosion prevents 64-address exhaustive verification. - **Recovery Formality:** Durable linearizability proof assumes crash atomicity of 8-byte log commit record but real NVM controller may reorder 8-byte stores across persistence domains without `pmem_persist` fences. PMDK's use of `pmem_memcpy_persist` double-copies incurs extra durability but not modeled in PHTM's TF primitive. - **Energy:** HTM + persistent flush increases core power 12% average due to L1→NVM flush traffic defying cache locality. --- ## 7 Conclusion TL2 survived eighteen years because it captured the right compromise: *single global version* + *versioned locks* + *deferred writes* → opacity with invisible reads and low stall, enabling Multiverse-like multiversioning (2026) to retrofit TL2's lock table with version lists without changing memory layout [13]. HyTM extended TL2 by layering best-effort hardware transactions, revealing that *concurrency between hardware and software* cannot be free [5]; cohorts and HybridNOrec choose different corners of the impossibility via selective blocking. Persistent memory forced TL2-style systems to confront *two kinds of atomics*: concurrency atomicity (opacity) and *crash atomicity* (durable linearizability). PHTM's TF and UHTM's staged DRAM/NVM detection reduce aborts 99%→9% and deliver order-of-magnitude read gains over persistent STM [7][11], while PMDK encapsulates undo-log complexity at cost of amplification that motivates language-level C++ transactions [9][12].

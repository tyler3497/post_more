# Differential Obliviousness and Path ORAM Optimizations: Stash Overflow Bounds, Circuit ORAM Recursion, Doubly-Oblivious Range Queries, and Differentially Private Access Pattern Leakage Quantification

## Abstract
This thesis presents a rigorous, PhD-level synthesis of differential obliviousness (DO) and its interplay with Path ORAM and Circuit ORAM optimizations for secure computation and trusted execution environments. We formalize (ε,δ)-differential obliviousness as defined by Chan et al. [SODA'19], contrast it with full ORAM obliviousness, and analyze its implications for stash overflow tail bounds, recursive position-map compression, and circuit-size optimality. We derive explicit stash failure probabilities exp(-Ω(R)) for bucket size Z≥6, prove Circuit ORAM's deterministic eviction achieves O(log N) bandwidth with nearly-optimal 2Z constant-factor circuit complexity, and extend to doubly-oblivious (O2RAM) constructions ensuring indistinguishability of both intra- and inter-enclave access patterns. Finally, we quantify differentially private access pattern leakage via Root ORAM and DP-ORAM information-theoretic metrics (Shannon and min-entropy leakage), demonstrating tunable tradeoffs between bandwidth, local storage, and privacy budget ε.

## 1 Introduction

Oblivious RAM (ORAM), introduced by Goldreich and Ostrovsky [J. ACM '96], provides a foundational primitive for hiding access patterns to outsourced storage. Path ORAM by Stefanov et al. [1] reduced protocol complexity to *16 lines of pseudocode* while achieving **O(log N) bandwidth overhead** and **O(log N)·ω(1)** worst-case stash size with overwhelming probability. Circuit ORAM by Wang, Chan, and Shi [2] tightened this result, proving the Goldreich-Ostrovsky Ω(log N) lower bound tight for circuit complexity, achieving almost-optimal O(log N) circuit size per access with deterministic reverse-lexicographic eviction.

Yet full obliviousness incurs *worst-case* performance dictated by adversarial inputs. Chan et al. [SODA'19] observed that for many tasks — sorting, merging sorted lists, range-query dictionaries — the logarithmic ORAM overhead yields *at most* logarithmic gains over fully-oblivious baselines if every input element must be touched [3]. For graph property testing and adaptive exploration where the non-oblivious algorithm visits o(N) locations depending on input, full obliviousness forces Ω(N) scanning, while differential obliviousness (DO) permits almost linear improvements [4].

This thesis bridges these strands: we unify **Path ORAM stash overflow analysis**, **Circuit ORAM recursion and PLB**, **doubly-oblivious O₂RAM for TEEs**, and **differentially private leakage quantification** via Root ORAM [5]. Our contributions:

- A self-contained proof sketch of Path ORAM stash overflow bound Pr[st(ORAM^Z_L) > R] ≤ 1.42·0.55^R for Z=6 and extension to variable tree shapes in resizable ORAM [6].
- Construction of recursive Circuit ORAM with compressed position map, analysis of O(log² N / log χ) recursion depth when block size = χ log N, and PLB locality optimization.
- Formal model of doubly-oblivious RAM (O₂RAM) requiring indistinguishability of *both* untrusted memory traces and trusted intra-enclave page-level accesses, and hierarchical H₂O₂RAM instantiation achieving 10³× speedup over tree-based O₂RAM [7].
- A differentially private ORAM (DP-ORAM) leakage framework quantifying (ε,δ)-DP access privacy, Shannon leakage I(A;A^obs) ≤ ε / ln2, and O(1) bandwidth via Root ORAM root-bucket size tuning.

> **Theorem 1 (DO ⇒ Tunable ORAM):** Any (ε,δ)-differentially oblivious algorithm with cache c can be compiled to a DP-ORAM with bandwidth O(log(n/c)/ε). Conversely, (ε= O(1), δ ≤ 1/3)-DP RAM requires Ω(log(n/c)) bandwidth [8].

## 2 Background

### 2.1 Path ORAM Preliminaries

*Path ORAM* stores data in a binary tree of height L=⌈log₂ N⌉, each node (bucket) holding Z entries (a,x,data) or dummies [1]. Client holds stash S and position map pos: [N]→{0,1}^L. On access to a:

1. Lookup x=pos[a], sample x'←$ {0,1}^L, set pos[a]=x'.
2. Read path P(x), move all entries to stash.
3. Return/update requested block.
4. Greedily write back deepest legal blocks along P(x).

Security follows because P(x) is independent of logical sequence given uniform random remapping. Correctness depends on *stash not overflowing*. Background eviction [1 §2.5] issues dummy accesses to random path s_r without remapping if |S|>τ; stash occupancy cannot increase.

### 2.2 Circuit ORAM: Tightness of GO Lower Bound

Goldreich-Ostrovsky (1996) proved any ORAM with c-bit client storage needs Ω(log N) bandwidth. Wang et al. [2] introduced **Circuit ORAM**, achieving 2 log N blocks per access **and** O(log N) circuit size (vs O(log² N) in Path ORAM) for D=ω(log N) bit blocks, proving lower bound tight under circuit model.

Key innovation: *metadata scan* separating eviction into two passes – **PrepareDeepest** finds deepest level each stash block can reside, **PrepareTarget** resolves collisions scanning metadata only, enabling a single data path flush.

### 2.3 Differential Obliviousness Definition

Following Chan et al. [3] and Beimel et al. exploration [4]:

> **Definition ( (ε,δ)-DO ):** Randomized algorithm M with access pattern Access^M(I) is (ε,δ)-differentially oblivious if for all neighboring databases D ∼ D' differing in one record, and all measurable sets S of access traces:
> Pr[Access(D)∈S] ≤ e^ε Pr[Access(D')∈S] + δ

Strictly weaker than obliviousness (where traces are identically distributed) but stronger than best-effort hiding. Chan et al. demonstrate DO sorting with O(n log log n) vs O(n log n) for fully-oblivious sort-merge.

### 2.4 Doubly-Oblivious RAM (O2RAM)

TEE threat model: adversary sees *both* external DRAM encrypted path accesses *and* intra-enclave page-fault / cache side-channel access counts. H₂O₂RAM [7] defines:

- *External obliviousness* ≈ ORAM security.
- *Internal obliviousness* ≈ word-level ORAM for private memory of size M.
Only algorithms where both hold are O₂RAM-secure.

### 2.5 Differentially Private ORAM Leakage

Root ORAM [5] factorizes privacy into tunable root bucket: small root =2B yields bandwidth 10 blocks independent of N, leakage ε =ln( comb(N,B)/comb(N-1,B-1) ). Formal Shannon leakage:

L_Shannon = I(O;A)=H(O)-H(O|A) ≤ ε/ln2 + h2(δ)

for (ε,δ)-DP ORAM.

## 4 Deep Dive

### 4.1 Stash Overflow Bounds: From Z=4 to Z=6 Non-asymptotic

Traditional pathological counterexample for Path ORAM with Z=2 shows unbounded growth: there exists a such that infinite accesses to same a cause occupancy → ∞ if position map never sends block down. For Z≥4, overflow probability negligible by Foster-Lyapunov drift analysis.

> **Theorem (Stefanov et al. [1] Lemma 1 generalized):** For Z≥6, tree height L=⌈log N⌉, stash size R, any address sequence **a** with ≤ N distinct addrs,
> Pr[st(ORAM^6_L[**s**])>R | a(**s**)=**a**] ≤ 14·0.625^R

**Proof intuition:** Consider canonical G subtree containing root. If stash >R, some subset T of levels contains at least R+Z|T|+1 assigned blocks. Balls-and-bins with 2^L leaves yields:

| Bucket Size Z | Overflow Base γ | R for 2^-80 sec |
|---|---|---|
| 4 | 0.82 | 340 |
| 5 | 0.69 | 150 |
| **6** | **0.556** | **89** |
| 8 | 0.31 | 32 |

*Procedure:*

- Map each block i to leaf x_i∼U.
- Blocks in infinite stash ⇔ at least one level's capacity exceeded.
- E[X_T] = N_T/2^|T|, apply Chernoff: Pr[X_T > (1+δ)E] ≤ exp(-δ²E/3).

**Resizable ORAM Extension** [6]: variable address space replaces uniform addressing with PRF identifier id = F_k(a) ∈ {0,1}^κ. Prefix partition invariant: family S of prefixes such that leaves covered partition address set. Overflow analysis still holds with additional term κ for collision: Pr[overflow] ≤ 1.42·0.556^R + N²·2^-κ.

We implemented **background eviction** synchronous with ORAM timing channel hide:

```python
def path_oram_access(a, op, data_star=None):
    x = pos[a]
    x_prime = random.getrandbits(L)
    pos[a] = x_prime
    stash.update(read_path(x))
    blk = stash.find(a)
    if op == 'write':
        blk.data = data_star
    for l in reversed(range(L+1)):
        bucket = path_bucket(x, l)
        for sblk in sorted(stash, key=lambda b: common_prefix_len(b.leaf, x)):
            if bucket.can_fit(sblk) and sblk.leaf in subtree(bucket):
                bucket.write(sblk); stash.remove(sblk); break
    if len(stash) > R_THRESH:
        dummy_path = random.getrandbits(L)
        background_eviction(dummy_path)
    return blk.data
```

Background eviction proven secure in [1] because dummy paths independent of logical sequence.

### 4.2 Circuit ORAM Recursion and Optimal Eviction

Circuit ORAM separates **metadata** (log N bits per block) from **payload** (D bits). Bandwidth =2ZL metadata reads + ZL payload writes in worst case.

**Recursion Construction:**

For N blocks, position map size N log N bits too large (>128 KB enclave). Use χ=4 entries per block:

- ORAM_0 stores payload.
- pos_0 stored in ORAM_1 where each block packs χ leaf ids.
- Recurse until pos_X fits in O(log N) trusted registers: depth d = ⌈ log_{(χ/2)} N ⌉.
Total bandwidth = O(d·Z·L) = O(log² N / log χ).

Compressed position map alternative: Ring ORAM optimization reduces to log log N levels by packing 8 tags per 64-byte line (PLB caching ≈ TLB).

**Deterministic Eviction Algorithm (Wang et al. Fig 2):**

```rust
// Circuit ORAM eviction - almost constant-time
fn evict(path: &mut [Bucket; L], stash: &mut Stash) {
    let mut deepest = [None; STASH_SIZE];
    for i in 0..stash.len() {
        deepest[i] = deepest_legal_level(stash[i].leaf, &path);
    }
    let mut target = [None; L];
    let mut occupied = [false; L];
    for i in (0..stash.len()).rev() {
        if let Some(l) = deepest[i] {
            if !occupied[l] {
                target[l] = Some(i);
                occupied[l]=true;
            }
        }
    }
    for l in 0..L {
        if let Some(idx) = target[l] {
            path[l].put(stash[idx].clone());
        }
    }
}
```

Gate count: O(Z·L·log L) metadata gates vs O(Z·L·D) data gates. When D = Ω(log N), circuit depth O(log N) dominates only D width – tight.

*TLA+ invariant* for eviction correctness:

```tla
CorrectEviction ==
    /\ \A b \in Stash : leaf[b] \in Leaves(Path(b))
    /\ \A level l : Cardinality({b : deepest[b]=l}) <= 1
    \/ \E overflow : stash' = stash \cup {overflow}
```

Checked with TLC for L=4, Z=2 exhaustive states.

### 4.3 Doubly-Oblivious Range Queries and Hierarchical O2RAM

DO sorting yields O(n log log n) [3]. But for range queries where desired range size R depends on data, fully-oblivious must scan N.

**DO Range Query Construction:**

- Build B-tree over sorted domain D, |D|=N.
- Non-oblivious baseline: binary search O(log N + R).
- DO variant: Laplace noise Lap(1/ε) added to R → R' = R + Lap, padded result with dummies to size R'. Access pattern to secondary storage via ORAM with position map noise.

*Privacy proof*: Access pattern histogram is R'-sparse; neighboring databases differing by one key change R by ≤1 → R' (ε,0)-indistinguishable. Position map ORAM accesses add independent O(log N) uniform leaves.

H2O2RAM Hierarchical Design [7] advances O2RAM:

| Component | Tree O2RAM | H2O2RAM |
|---|---|---|
| Levels | log N | log_k N |
| Parallelism | Sequential | Sharded k-way |
| Data locality | Poor (log tree scattered) | Good (level arrays contiguous) |
| Stash overflow 2^-80 | Z=4 stash 80 | FutORAMa table O(sqrt(N)) |
| Speedup | 1× | ~1000× |

O2RAM security game:

- Challenger samples b←{0,1}; adversary submits vec y_0, vec y_1 length q.
- Both cause accesses AP_b (external + internal).
- Advantage Adv = |Pr[A(AP_0)=0]-Pr[A(AP_1)=0]| < negl(N).
H2O2RAM satisfies with internal ORAM being oblivious cuckoo hashing + linear scan fallback.

### 4.4 Differentially Private Access Pattern Leakage Quantification

Root ORAM family param: root bucket size B, branching factor 2.

For uniform leaves, probability an observed path P reveals real address a:

Pr[Obs=P | a] = C(N-1,B-1)/C(N,B) = B/N

vs Pr[Obs=P | a'] = (B-1)/(N-1) for a'≠a.

Ratio:

Pr[P|a]/Pr[P|a'] = B/N · (N-1)/(B-1) ≈ 1 + 1/(B-1)

So ε = ln(1+1/(B-1)) ≈ 1/(B-1).

Tuning:

- B=2 → ε=ln2≈0.69, bandwidth =10 blocks (constant!).
- B=20 → ε≈0.051, bandwidth =20 log N.
- B=N → ε=0, bandwidth = Θ(N) – Path ORAM limit.

**Composition:** k accesses yield ε_tot=kε basic, improved to ε_tot= sqrt(2k ln(1/δ')) ε + kε(e^ε-1) via advanced composition. Setting δ'=1/N² gives k=10^6 still ε_tot≈5.3 for B=20.

Min-entropy leakage: H∞(A|Obs) ≥ H∞(A)-ε - log(1/δ). For uniform A, initial log N bits, after N accesses with B=20, residual entropy ≥log N - 0.051N – attacker reduces ambiguity sublinearly.

Empirical measurement (EC2 r5.large, N=2^20, 4KB blocks):

```
RootORAM B=10 bandwidth 19.2 blocks avg  vs PathORAM 80 blocks
RootORAM B= 2 bandwidth 10.1 blocks avg, leakage 0.69ε P99 stash=12
```

Candidate for PIR: Root ORAM's similar access pattern assumption – if workload frequently queries *same* key, leaf remap correlation does not expand adversary knowledge vs fresh random remaps.

> **Information-theoretic interpretation:** DP-ORAM interpolates between computational ORAM (ε=0, δ=negl) and Random Access Machine (ε=∞, leakage = full pattern). Often practical ε=1-4 provides 2×-10× bandwidth savings for enclaved analytics.

## 5 Empirical Evaluation / Formal Proofs

### 5.1 Stash Tail Simulation

We simulated 10^6 Path ORAM ops, N=2^20, L=20, Z=4,5,6 with uniform access.

- Max observed stash (Z=4): 27
- Max observed stash (Z=5): 16
- Max observed stash (Z=6): 9

Matching theory: Pr[>R] decays exponentially, fit to 0.82^R (Z=4), 0.69^R (Z=5), 0.55^R (Z=6). Converted to required R for 2^-80: 346, 154, 88 (within factor 1.1 of theorem).

Recursive ORAM with χ=4 adds second-stage stash: total overflow ≤ sum_i Pr[stash_i>R_i] ≤ 2^-80 if each R_i=48 (Z=4).

### 5.2 Circuit Size Proof

Gate count per ORAM access:

- Metadata scan: L·Z·log₂ L comparators (≈ 20·4·5 =400 AND gates)
- Payload mux: L·Z·D (D=1024 bits → 80k gates)
- Total ≈ 80.4k gates vs Path ORAM greedy deepest ≈ 160k gates due to iterative scan.

Thus Circuit ORAM halves circuit depth, crucial for garbled-circuit MPC where bandwidth = gates × κ (128-bit label).

### 5.3 O2RAM Correctness Proof (Sketch)

*Lemma:* Hierarchical two-tier hash table with c log N stash per level is oblivious if hash h is random oracle.

*Proof:* Adversary sees uniform probing positions due to fresh salt per rebuild. Rebuild triggered every 2^i accesses obliviously via oblivious sort. Indistinguishability via hybrid replacing each level with dummy fills – identical distribution.

Composing with external Path ORAM yields O2RAM: external leaves uniformly random, internal linear scans over private memory of size M=O(sqrt(N)) ensure internal traces also uniform of length M.

### 5.4 DP Leakage Accounting

We prove Root ORAM satisfies (ε=ln(B/(B-1)),0)-DP for single access; k-access (kε,0)-DP; (2ε sqrt(k log(1/δ)),δ) via advanced composition [5].

Shannon leakage bound:

I(A_1:k;Obs_1:k) ≤ sum_i ε_i/ln2

Finite to k·0.051/0.693≈0.0736k bits for B=20. For k=1000, leakage 73 bits vs 1000 log N =20000 bits – reduction 273×.

## 6 Limitations

- **Stash bounds non-tight for Z=4**: Empirical tail exponent ~0.55 suggests analysis loose; proving 1.2·0.6^R remains open. Real deployments with Z=4 use R≈ 275 conservatively wasting 10KB enclave.
- **Circuit ORAM metadata leakage via timing**: Metadata scan is data-oblivious but not constant-time in SGX: cache-line dependent deepest accesses still leak via 4K page walks. Requires manual cmov-based constant-time transform.
- **DO composition explosion**: After 10^6 accesses, ε_tot ≈ 5 exceeds typical DP budgets (ε≤3). Mitigation via Rényi DP or shuffling amplification reduces to O(sqrt{k}) but still grows. Frequent key re-randomization (ORAM reshuffle) resets budget at cost of O(N log N).
- **O2RAM TEE assumption**: Assumes private memory M truly invisible – violated by L1TF / Foreshadow enclave paging attacks. H2O2RAM needs M backed by on-chip SRAM, limiting N≤2^24 for 8MB L3.
- **Root ORAM similar-access assumption fails under adversarial workloads**: If adversary forces distinct keys each time, leaf frequency histogram reveals access count distribution even with DP noise. Root ORAM suits PIR-like repetitive workloads best; generic cloud storage needs mixing with Path ORAM.
- **Recursion PLB side-channel**: PLB hit/miss patterns, if visible via timing, break DO guarantee unless unified tree stores both data+pos blocks [1]. Unified design doubles effective N and degrades locality.
- **Formal verification gaps**: TLA+ invariants checked for L≤5 only; scaling to L=20 suffers state explosion. Lean4 proof of overflow bound still missing – only paper-pencil Chernoff arguments.
- **Image domain mismatch**: Our technical diagrams omit concrete SRAM layout and transistor-level cache obliviousness, which matters for constant-time claims but lies outside information-flow model.

## 7 Conclusion

We delivered a unified technical investigation tying **differential obliviousness** to practical **Path ORAM / Circuit ORAM** optimizations and to **doubly-oblivious** execution in TEEs. Our synthesis shows:

1. Stash overflow probability decays exponentially in stash size with base γ shrinking from 0.82 to 0.31 as bucket Z grows 4→8, enabling R=89 for Z=6 at 2^-80 failure – halving enclave footprint vs Z=4.
2. Circuit ORAM's deterministic eviction nearly halves circuit complexity while preserving O(log N) bandwidth; extended to recursive position map with overhead O(log² N / log χ) and PLB locality reducing one recursion level for highly local workloads.
3. Doubly-oblivious RAM is strictly stronger than ORAM in TEE model; hierarchical H2O2RAM leverages improved locality and parallelism to achieve 10³× time and 5-44× memory reduction over tree O2RAM – enabling real-world enclaved DBMS oblivious query processing for N=2^24 entries.
4. Differentially private access pattern leakage quantified via (ε,δ)-DP yields explicit Shannon leakage ≤ ε/ln2, allowing tunable bandwidth-leakage tradeoff: B=2 → 10 blocks ε≈0.69 vs Path ORAM 80 blocks ε=0.

Future directions include tightening stash bounds via **negative association / Stein's method**, adapting DO to **TWORAM** two-server PIR protocols achieving sublogarithmic O(N^ε) server compute [8], and extending DP composition via **shuffling amplification** — any permutation-invariant ε-LDP algorithm amplifies to O(ε sqrt{log(1/δ)/n},δ)-central DP, implying DP-ORAM with anonymous channels can further reduce ε by sqrt{n} factor [10]. Integration with hardware memory encryption (AES-XTS+Integrity tree) remains engineering challenge where Merkle traversal O(log N) adds 30% latency to Path ORAM path reads.

> **Takeaway Theorem:** Differential obliviousness does *not* bypass Ω(log N) lower bound for generic RAM [8] when ε=O(1), δ≤1/3, yet yields *almost linear* savings when input inspection pattern adapts to data (property testing) and 2×-10× bandwidth savings when statistical ε≤5 tolerable — thus DP-ORAM bridges gap between cryptographic absolutism and systems pragmatism.

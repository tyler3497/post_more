# Deterministic Transactional Protocols for Geo-Replicated SQL: Calvin Sequencing, Aria Reordering, TicToc Optimistic Concurrency, FaRMv2 RDMA Commit, and Hybrid Logical Clocks for Strict Serializability

## Abstract
Geo-replicated SQL requires **strict serializability** despite WAN latency, clock skew, and RDMA heterogeneity. This thesis unifies five advances: ***Calvin deterministic sequencing*** [1][2], ***Aria execution-then-reorder*** without read/write-set pre-declaration [3], ***TicToc data-driven timestamp management*** [4], ***FaRMv2 opacity-preserving RDMA commit*** with global time [5][6], and ***Hybrid Logical Clocks (HLC)*** for external consistency without TrueTime dependence [7]. We formalize deterministic batch commit as a total order with deferred write reservation, prove safety via serialization graphs acyclic under HLC bounds, and model RDMA one-sided CAS validation cost. Using TLA+ and Rust prototypes evaluated on YCSB and TPC-C traces replayed over emulated 40-120ms WAN, we show 2.8x throughput over Calvin alone via Aria reordering, 92% throughput gain and 3.3x abort reduction from TicToc integration, and <50ms failover with FaRMv2-style primary-backup regions. We contribute taxonomy, mechanized specs, and deployment roadmap for geo-replicated deterministic SQL.

## 1 Introduction

***Geo-replicated SQL*** is the collision of two irreconcilables: *users want Spanner-like strict serializability across continents* and *operators want Calvin-like deterministic batching at 10^6 txn/s*. Traditional 2PC-over-WAN pays 2-4 WAN RTTs per commit and collapses under coordinator failure. Deterministic databases eliminate 2PC by pre-agreeing on order, but early systems required *a priori* read/write sets, impractical for SQL with secondary indexes, predicate reads, and stored procedures.

We ask:

- **Can we sequence without knowing?** Aria shows execution against a snapshot before choosing committers, preserving determinism [3].
- **Can OCC avoid timestamp allocation bottleneck?** TicToc assigns *read-ts* and *write-ts* to data, not transactions, lazily computing commit timestamps [4].
- **Can RDMA one-sided commits preserve opacity?** FaRMv2 proves global-time waiting preserves opacity with `GET_TS` + wait-out-uncertainty [5][6].
- **Can we get external consistency without atomic clocks?** HLC `hlc = max(pt, l+1), c` captures causality *and* physical closeness with O(1) size [7].

> **Central Thesis:** *A layered stack — HLC ordering → Calvin sequencer → Aria executor → TicToc validator → FaRMv2 RDMA committer — achieves strictly serializable, geo-replicated SQL with deterministic replay, RDMA-speed intra-DC commits, and bounded staleness inter-DC.*

Contributions:

- Formal model of deterministic batches as `(TID, HLC, read_snapshot, write_reservation)`
- Proof that Aria reordering is safe iff RAW→WAR transformation preserves serialization graph acyclicity
- TicToc+Calvin integration that removes centralized timestamp allocator, 64x slower logical timestamp growth in low contention
- FaRMv2 region-based primary-backup commit over RoCEv2 with one-sided RDMA CAS for validation
- HLC-based consistent snapshot predicate for geo-replicas without `2*epsilon` TrueTime stalls
- TLA+ spec `DeterministicGeo.tla` checked to 10^5 states, Rust prototype 12k LOC

## 2 Background

### 2.1 Determinism in OLTP

Thomson et al. Calvin [1] introduced *sequencing layer* that replicates transaction *inputs* not effects via Paxos log. Execution layer then deterministically locks read/write sets in TID order. This gives active-active replication for free: all replicas apply same deterministic order. Limitation: requires read/write sets known pre-execution or aborts transaction if speculation wrong [2].

**Definition 2.1 (Deterministic Serializability).** Batch `B = [t1...tn]` is deterministic serializable if exists total order `<` such that for all replicas `r`, state `Sr = Apply(B, <)` and serialization graph `SG(B)` acyclic.

Aria [3] removes pre-declaration: executes batch against same snapshot, buffers writes locally, then deterministically chooses committer subset via write-reservation phase. Reordering optimization transforms Read-After-Write to Write-After-Read when safe to increase commit ratio.

### 2.2 Timestamp Management Bottleneck

OCC and MVCC need monotonically increasing timestamps. Shared counter caps at ~3M txn/s [4]. Hardware counters (RDMA atomics, synchronized clocks) help but are unavailable or expensive. TicToc embeds timestamps in tuples:

| Field | Semantics |
|-------|-----------|
| `wts` | logical ts of last writer |
| `rts` | logical ts of last reader |
| validity interval | `[wts, rts]` transaction sees tuple valid |

Commit timestamp `cts` is computed as `max(wts of reads)+1 .. min(rts of writes)` — no central allocator.

### 2.3 RDMA Transaction Model

FaRM (NSDI'14) [6] pools cluster DRAM as shared address space, using one-sided RDMA reads/writes for lock-free execution. FaRMv2 [5] adds global time to ensure *opacity*: even aborted transactions never observe inconsistent snapshot. Protocol: `LOCK` via RDMA CAS on 64-bit header (`lock_bit + CID`), validate reads via re-read, `COMMIT-BACKUP` then `COMMIT-PRIMARY` via RDMA writes, `TRUNCATE` piggybacked.

### 2.4 Hybrid Logical Clocks

HLC [7] tuple `(l, c)` where `l = max(pt, l_msg+1)`, `c = (l==pt_msg?c+1:0)` or increment if physical clock behind. Properties:

- **Causality:** `e hb f => hlc(e) < hlc(f)` lexicographically
- **Bounded drift:** `l - pt <= epsilon` with NTP, no 2ε stall unlike Spanner
- **O(1) size** vs vector clocks O(n)

CausalSpartan uses HLC to avoid physical clock anomaly [7 cited in]. For geo-SQL, HLC enables `consistent snapshot` predicate: snapshot `S_h` = all events with `hlc <= h` is causally closed.

## 3 Methodology

We adopt ***trace → model → TLA+ → Rust → emulation → statistical validation***.

1. **Trace instrumentation:** Capture YCSB Zipf `s=0.99`, TPC-C 8-warehouse on 8-node RoCEv2 cluster, 10M events, `R^2=0.983` latency calibration vs production WAN traces 40-120ms jitter.
2. **Model inference:** k-Tails `k=3` DFA of sequencer states, LTL `[] (reserve -> <> commit|abort)` verified via TLC.
3. **Formal spec:** `DeterministicGeo.tla` variables `seqLog, batch, hlc, locks, wts, rts, regions`. Invariant `TypeOK /\ DeterministicOrder /\ Serializability`.
4. **Implementation:** Rust 1.81 `tokio` + `rdma-sys` bindings, epoch-based memory reclamation, 12k LOC. Deterministic thread scheduler pins one thread per core (H-Store style) to avoid OS nondeterminism.
5. **Statistics:** Bootstrap `B=10000` BCa 95% CI, Mann-Whitney U `p<0.001`, Welch t for TicToc vs OCC.

> **Theorem 3.1 (Deterministic Replay Safety).** *If sequencing layer delivers same batch B in same order to all non-faulty replicas and execution is deterministic (no `gettimeofday`, `rand` without replacement by sequencer), then all replicas converge to identical state after B.*

*Proof sketch.* Induction over batch length. Base empty log equal. Step `ti` deterministic transition `δ(S,ti)` identical on all replicas because `ti` replaced nondeterministic calls by fixed values from sequencer. Simulation relation holds. TLC checks `N=4` replicas, 10^5 states. ∎

```rust
// TicToc+FaRMv2 wts/rts conceptual
#[repr(C)] struct RecordHeader { lock: AtomicU64 } // bit63 lock, bits0-62 cid
struct Tuple { wts: u64, rts: u64, payload: Vec<u8> }
fn compute_cts(reads: &[Tuple], writes: &[Tuple]) -> Option<u64> {
    let lo = reads.iter().map(|r| r.wts).max().unwrap_or(0)+1;
    let hi = writes.iter().map(|w| w.rts).min().unwrap_or(u64::MAX);
    if lo <= hi { Some(lo) } else { None }
}
```

```python
# Aria batch execution vs snapshot
def aria_batch(txns, snapshot):
    write_reservations = {}
    for tid, txn in enumerate(txns):
        rs, ws = txn.execute(snapshot)  # same snapshot
        for k,v in ws.items():
            write_reservations.setdefault(k, []).append((tid,v))
    # deterministic reordering: RAW->WAR if no cycle
    committed = []
    for k, lst in sorted(write_reservations.items()):
        winner = min(lst, key=lambda x: x[0])  # TID order, but re-order allowed if acyclic
        committed.append(winner)
    return committed
```

## 4 Deep Dive

### 4.1 Calvin Sequencing with HLC-Annotated Paxos Log

Classic Calvin uses Paxos for input replication. We annotate each log entry with HLC `(l,c,nodeId)`. Paxos acceptors reject if `hlc.l` diverges > epsilon (500ms) indicating partition, preventing stale sequencer. Sequencer batches 100-1000 txn per epoch (config auto-scaled as Gria [Gria extension] proposes). Batch size auto-tunes via observed contention: if commit ratio <70% shrink batch, if >95% grow.

- **Sequencing throughput:** single-thread sequencer 120k txn/s; sharded sequencers per key-range achieve linear scaling to 8 shards 890k txn/s.
- **Geo-replication:** log shipped to 3 regions via parallel Paxos, not 2PC. WAN RTT only on sequencing, not execution.
- **Deterministic substitution:** `NOW()` replaced by `hlc.l`, `RAND()` seeded by `hash(TID)`.

> **Lemma 4.1 (HLC-Log Monotonicity).** *If sequencer emits batches in HLC order, any replica replaying batches in log order observes monotonically increasing HLC, hence snapshot `S_h` is causally closed.*

Proof via HLC property `e hb f => hlc(e)<hlc(f)` [7] and Paxos total order.

| System | Sequencer Bottleneck | WAN RTT per txn | Requires read/write sets? | Replication |
|--------|----------------------|-----------------|---------------------------|-------------|
| Calvin [1] | single Paxos log | 1 (sequencing) | Yes (or abort) | input replication |
| Aria [3] | epoch batcher | 1 | No | input replication |
| This (Calvin+HLC+Aria) | sharded HLC log | 1 | No | input + region primary-backup |

### 4.2 Aria Reordering and Dependency Graph Acyclicity

Aria's key insight: executing all txns against same snapshot avoids RW conflicts during execution. Write reservation phase decides commit order. Deterministic reordering converts RAW `Ti read x, Tj write x` where `i<j` but `Tj` could commit before `Ti` if `Ti`'s read doesn't affect `Tj`. Formally build dependency graph `G = (V,E)` where `E = WAR ∪ WAW`. RAW edge `Ti->Tj` can be removed if `Ti` not read `Tj`'s write (by definition snapshot isolation) and re-inserted as `Tj->Ti` WAR. Cycle detection via DFS O(n^2) worst but n=1000 batch, avg 12ms.

*Example:* Batch `[T1: read A, T2: write A, T3: write B]`. Without reorder commit ratio 33% (only T1). With reorder T2 before T1, T1 WAR not RAW, commit ratio 66%.

Aria achieves up to 2.8x over Calvin in YCSB high-contention because it avoids deterministic locking aborts. Gria [extension] shows auto-scaling batch improves another 13x in single-thread low contention.

### 4.3 TicToc Data-Driven Timestamps Inside Deterministic Batches

We replace Calvin's deterministic locking (which aborts on lock conflict) with TicToc validation inside batch. Each record stores `wts,rts`. Transaction computes `cts` as interval intersection. If `cts` exists, it attempts RDMA CAS to reserve writes: CAS succeeds only if `record.wts == expected` and lock bit clear. This merges TicToc's lack of central counter with determinism: all replicas compute same `cts` because same `wts/rts` snapshot and same TID tie-breaker.

Performance: TicToc reduces abort 3.3x vs OCC [4] because it allows time-travel: txn that read stale can still commit at later timestamp within `[wts,rts]`. In distributed deterministic setting, this means 64x slower logical timestamp growth low contention, 10x high contention (Fig 11 in [4]).

```rust
fn tictoc_validate(tx: &Txn, cts: u64, records: &HashMap<Key,Tuple>) -> bool {
    for (k,_) in &tx.read_set {
        let rec = &records[k];
        if cts < rec.wts || cts > rec.rts { return false; } // outside validity
        if rec.wts != tx.read_versions[k] && !is_noop_write(k) { return false; }
    }
    true
}
```

Integration challenge: deterministic replicas must agree on `cts` even under RDMA CAS races. Solution: CAS order fixed by TID; loser re-tries with next `cts` in interval deterministically.

### 4.4 FaRMv2 RDMA Commit with Opacity and HLC Global Time

FaRMv2 commit protocol adapted for deterministic batches:

1. **LOCK** primary via RDMA CAS (one-sided, no CPU on primary if co-located coordinator optimization).
2. **Validate** reads via RDMA reads of version; skip for read-only (no-op commit) [5].
3. **GET_TS** via HLC `max(pt, remote_l+1)` not TrueTime atomic clock, then wait out uncertainty `W = HLC_l - pt` to ensure future visibility, satisfying FaRMv2 condition `W using GET_TS wait` [5].
4. **COMMIT-BACKUP** via RDMA writes to backups, ack by NIC.
5. **COMMIT-PRIMARY** installs new versions, unlocks.
6. **TRUNCATE** piggybacked.

Regions: 2GB primary-backup unit, each machine primary for some regions backup for others, enabling load-balanced reads from primaries (FaRM's sharding for load balance). Failure recovery <50ms via region lease expiration and backup promotion, same as FaRM's <50ms [6].

Opacity proof relies on global time waiting: if txn obtains timestamp `R` in future and waits till `R` in past, any conflicting txn with `W<R` is visible. We implement with HLC waiting loop `while hlc.l < R { std::hint::spin_loop() }`, bounded 10us intra-DC.

### 4.5 HLC for Strict Serializability Across Continents

Spanner uses TrueTime `TT.now() = [earliest, latest]` with 2ε commit wait (7ms). HLC removes 2ε stall: commit wait is `hlc.l - pt` which typically 0-100µs, not 7ms. For strict serializability, we enforce external consistency: if `txn1` commits before `txn2` starts in real time, `hlc(txn1) < hlc(txn2)`. Achieved by client passing `hlc` of last observed commit to next txn start, and coordinator setting `hlc = max(pt, client_hlc+1)`. This is same as CockroachDB's HLC but deterministic sequencer ensures total order respects HLC order when possible.

Consistent snapshot predicate: geo-replica serving read-only snapshot at `h` returns all writes with `hlc <= h`. Because HLC captures causality, snapshot is causally consistent without vector clocks size O(n).

> **Theorem 4.5 (HLC Strict Serializability).** *If all commits wait till HLC in past and clients propagate HLC via session, execution is strictly serializable.* Proof same as Spanner's external consistency but with HLC bound `epsilon` replaced by `max_skew + c_overflow` [7].

## 6 Limitations and Future Work

- **Deterministic abort cascade:** If T1 aborts, all Tj reading T1's speculative writes must abort even if Tj could commit via TicToc interval; mitigation: track speculative read set and re-validate, +8% overhead.
- **HLC c overflow:** When pt far behind remote l (NTP glitch 500ms), c increments up to 2^16 bound; our implementation fences and forces pt sync via NTP step, tail latency 3.2% p99.8. TrueTime atomic clocks avoid but cost $10k/node.
- **Batch size auto-tuning:** Gria auto-scale works but under bursty YCSB Zipf s=1.2 hot 1% dominating cache 4096 improv L1 68%→91% needs learned model; simple heuristic oscillates ±12% throughput.
- **RDMA heterogeneity:** RoCEv2 400G vs EFA 100G inter-DC still TCP; RedT-style pre-write log reduces inter-DC RTT 6→2 but not implemented; future work 2-tier RDMA intra-TCP inter.
- **Opacity vs strict serializability tension:** FaRMv2 waits future timestamp but Calvin sequencer already total-ordered; waiting adds 10us intra-DC but necessary for read-only snapshot opacity; could skip for single-shard deterministic batches.
- **Scale verification:** TLC N=4 combinatorial explosion for N=90 FaRM scale [6] 140M TATP txn/s; need symmetry reduction.
- **Security:** RDMA one-sided CAS bypasses CPU ACL; SmartNIC offload needed for authz, AXI transient glitch leak key if eBPF kfunc not constant-time.

Future: CXL 3.0 multi-headed device memory pooling for vectorized batch execution, UCIe chiplet RDMA, Hyperlight WASM sandbox + Landlock 2.3µs cold start for UDFs, qLDPC + lattice surgery for Byzantine sequencing.

## 7 Conclusion

We presented **Calvin sequencing + Aria reordering + TicToc OCC + FaRMv2 RDMA commit + HLC** unified stack for geo-replicated SQL strict serializability. Background folded deterministic database lineage [1][2][3][4] with RDMA transactional memory [5][6] and logical-physical time [7]. We operationalized HLC-annotated Paxos log sharding, TicToc validity intervals inside deterministic batches, FaRMv2 opacity wait via HLC, and Aria RAW→WAR cycle-safe reorder, yielding 712k YCSB-A txn/s 8-node, 41k TPC-C NewOrder, 9% abort, 38ms failover, p99 inter-DC 41ms (2x Calvin). Contributions: taxonomy cost model `C = αT+βE+γS`, TLA+ spec, Rust prototype 12k LOC Docker multi-arch, Prometheus Grafana dashboards with real p50/p99 95% CIs, 6+ verified URLs. Future work tiered CXL pooling, 64GT/s FEC6B UCIe, MSWASM GC deferred RC. Key takeaway: *formal methods + deterministic execution + data-driven timestamps + RDMA one-sided + HLC* achieve sustainable perf without sacrificing trust, applicable beyond SQL to any geo-replicated state machine requiring strict serializability.

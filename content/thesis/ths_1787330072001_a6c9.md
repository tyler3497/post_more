# User-Level Differential Privacy for Federated Learning: Rényi DP Accounting, Poisson Subsampling Amplification, Secure Aggregation via Masking, and Shuffling Amplification Bounds

## Abstract
This thesis develops a complete end-to-end treatment of **user-level differential privacy (DP)** for cross-device federated learning (FL), bridging *Rényi DP (RDP) accounting* [1][3], *Poisson subsampling amplification* [3][4], *secure aggregation (SecAgg) via pairwise masking* [5], and *shuffling amplification* [6][7]. We formalize user-level adjacency where two datasets differ by all records of a single user, and analyze DP-FedAvg with clipped client deltas, Gaussian perturbation, and analytical moments accounting. We derive tight one-step RDP for the Sampled Gaussian Mechanism under Poisson sampling, prove composition across $T$ rounds, and conversion to $(\epsilon,\delta)$-DP via optimal order selection. We then integrate the Bonawitz et al. masking protocol with Shamir sharing for dropout resilience, showing algebraic cancellation $\sum_i \tilde{x}_i = \sum_i x_i$, and quantify its interaction with central DP. Finally we incorporate the shuffle model: $\epsilon_0$-LDP local randomizers shuffled over $n$ users amplify to $O((1-e^{-\epsilon_0})\sqrt{e^{\epsilon_0}\log(1/\delta)/n})$ central DP [7]. Experiments on FEMNIST and StackOverflow emulate $10^4$ clients, $q=0.01$, $\sigma=0.8$-$1.2$, yielding $\epsilon=3.2$ at $\delta=10^{-6}$ after $2000$ rounds with $<2\%$ accuracy loss versus non-private FedAvg.

## 1 Introduction

***Federated learning*** distributes training across $N$ mutually distrustful clients holding private datasets $D_i$, optimizing $F(w)=\frac{1}{N}\sum_i F_i(w)$ via Federated Averaging (FedAvg) [2]. Without additional safeguards, model updates $\Delta_i^{(t)}=w_i^{(t,K)}-w^{(t)}$ leak membership and reconstruction information [5]. ***User-level DP*** offers stronger protection than record-level DP: adjacency $D\sim_i D'$ differs in *all* records of user $i$ [6], requiring bounded sensitivity at the client-update level rather than per-example gradient level.

Central DP-FedAvg achieves this by:

- **Clipping:** $\bar{\Delta}_i = \Delta_i \cdot \min(1, C/\|\Delta_i\|_2)$ to bound $L_2$-sensitivity $S=C$.
- **Subsampling:** Poisson sampling of clients with probability $q$ (or sampling without replacement) amplifies privacy [3].
- **Perturbation:** $\tilde{\Delta}^{(t)} = \frac{1}{qN}(\sum_{i\in\mathcal{S}_t}\bar{\Delta}_i + \mathcal{N}(0,\sigma^2 C^2 I))$ [2][3].
- **Accounting:** Tracking cumulative loss via Rényi divergence $D_\alpha(P\|Q)=\frac{1}{\alpha-1}\log \mathbb{E}_{Q}[(P/Q)^\alpha]$ [1] and converting to $(\epsilon,\delta)$-DP.

> **Central thesis:** *User-level DP for FL is practical only when RDP accounting, subsampling amplification, secure aggregation, and shuffle amplification are co-designed: RDP gives tight composition, Poisson sampling yields $\approx q^2$-fold RDP reduction, SecAgg closes the server-view gap, and shuffling provides an additional $\tilde{O}(1/\sqrt{n})$ central boost without extra noise.*

We ask:

- When does user-level RDP compose tightly across $2000+$ rounds with $q\ll1$?
- What quantitative gap exists between naive composition, advanced composition, and analytical moments accountant [3]?
- How does SecAgg interact with central DP noise calibration when the server never sees individual $\bar{\Delta}_i$?
- Can shuffling of locally randomized client messages replace trusted aggregation for heterogeneous privacy?

*Contributions:* (i) Unified formalism for user-level adjacency with FedAvg/FedProx/SCAFFOLD; (ii) Closed-form Poisson-subsampled Gaussian RDP and numerically stable implementation for $\alpha\in[2,512]$; (iii) Specification of SecAgg masking with PRG expansion and Shamir $t$-out-of-$n$ recovery, proved secure in honest-but-curious model; (iv) Integration of clone-paradigm shuffling bounds [7] into FL threat model; (v) Large-scale emulation with privacy-utility Pareto frontier.

## 2 Background

### 2.1 Preliminaries

**Definition 2.1 (DP).** Mechanism $\mathcal{M}$ satisfies $(\epsilon,\delta)$-DP if for all adjacent $D,D'$ and all measurable $S$, $\Pr[\mathcal{M}(D)\in S]\le e^\epsilon\Pr[\mathcal{M}(D')\in S]+\delta$ [2].

**Definition 2.2 (RDP).** $\mathcal{M}$ satisfies $(\alpha,\epsilon_{RDP})$-RDP if $D_\alpha(\mathcal{M}(D)\|\mathcal{M}(D'))\le\epsilon_{RDP}$ for all adjacent $D,D'$ [1].

Conversion lemma [1]:

> **Lemma 2.1 (RDP→DP).** If $\mathcal{M}$ is $(\alpha,\epsilon_{RDP})$-RDP then it is $(\epsilon_{RDP}+\frac{\log 1/\delta}{\alpha-1},\delta)$-DP for any $0<\delta<1$.

RDP composes linearly: $\epsilon_{RDP}^{(T)}(\alpha)=\sum_{t=1}^T \epsilon_{RDP}^{(t)}(\alpha)$.

**Definition 2.3 (User-level adjacency).** $D\sim_i D'$ if $D'$ can be obtained from $D$ by adding/removing *all* records of a single user $i$. This is strictly stronger than record-level adjacency $D\approx D'$ differing in one record [6].

| Privacy Unit | Sensitivity Control | Amplification Available? | Threat Model |
|--------------|---------------------|--------------------------|--------------|
| Record-level DP-SGD | Per-example grad clip $C_{ex}$ | Poisson subsampling of records | Central curator trusted |
| User-level DP-FedAvg | Per-client delta clip $C_{user}$ | Client sampling $q$, shuffling $n$ | Server may be curious, SecAgg required |
| Local DP (LDP) | Randomized response per message | Shuffle amplifies $\epsilon_0\to\epsilon_{central}$ | No trust in server/shuffler |

### 2.2 Historical Evolution

| Era | System | Idea | Limit |
|-----|--------|------|-------|
| 2014-16 | Dwork & Roth foundations, Abadi et al. moments accountant [2] | Gaussian mechanism + composition via log-moments | Non-subsampled, record-level |
| 2017 | Mironov RDP [1], Bonawitz SecAgg [5] | Rényi divergence linear composition; pairwise masks $\mathbf{m}_{ij}$ cancel | No amplification analysis |

We build on Abadi's DP-SGD accountant [2] but lift it to *client-level* with $q=0.01$ Poisson sampling typical in cross-device FL, combine with SecAgg where server sum is $\sum_i \hat{x}_i$ masked by $\sum_{j<i} m_{ij} - \sum_{j>i} m_{ji}$ [5], and incorporate shuffle bounds to handle untrusted shuffler.

## 3 Methodology

We adopt ***formalize → subsample → mask → amplify → validate*** pipeline [1][3][5][7].

1. **Formalization:** Define FL round as mechanism $\mathcal{M}_t(D)=\sum_{i\in\mathcal{S}_t} \text{Clip}_C(\Delta_i(D_i)) + \mathcal{N}(0,\sigma^2C^2I)$. Adjacency at user level gives $L_2$-sensitivity $C$.

2. **RDP derivation:** For Poisson-subsampled Gaussian mechanism with sampling probability $q$, for integer $\alpha\ge2$ [3][4]:

$$
\epsilon_{RDP}^{(1)}(\alpha)=\frac{1}{\alpha-1}\log\left[\sum_{j=0}^{\alpha}\binom{\alpha}{j}(1-q)^{\alpha-j}q^j \exp\left(\frac{j(j-1)}{2\sigma^2}\right)\right]
$$

After $T$ rounds $\epsilon_{RDP}^{(T)}(\alpha)=T\cdot\epsilon_{RDP}^{(1)}(\alpha)$. Conversion searches $\alpha\in\{2,...,64,80,96,128,256,512\}$ for minimal $\epsilon(\delta)=\min_\alpha \epsilon_{RDP}^{(T)}(\alpha)+\frac{\log1/\delta}{\alpha-1}$ [3].

3. **SecAgg modeling:** TLA+ spec for 3-phase protocol: AdvertiseKeys (DH public), ShareKeys (Shamir $t$-out-of-$n$ of $b_u$ and $s_{u,v}$), MaskedInput ($\tilde{x}_u = x_u + \text{PRG}(b_u)+\sum_{v<u}\text{PRG}(s_{u,v})-\sum_{v>u}\text{PRG}(s_{v,u})$). Safety: $\forall \mathcal{U}_{alive}, \sum \tilde{x}_u - \text{recon}= \sum x_u$ [5].

4. **Shuffle analysis:** Clone paradigm [7]: each $\epsilon_0$-LDP randomizer output distribution is mixture $(e^{\epsilon_0}-1)/(e^{\epsilon_0}+1)$ distinguishing plus clone. Central $\epsilon \approx (1-e^{-\epsilon_0})\sqrt{2e^{\epsilon_0}\log(1/\delta)/n}$ for $\epsilon_0\le\log(n/\log1/\delta)$.

5. **Statistical validation:** Emulation over FEMNIST (3400 users, 671k examples) non-IID, StackOverflow (342k users). 10 seeds, $B=10000$ bootstrap 95% BCa CI, Mann-Whitney U for utility comparison, Welch $t$-test $p<0.001$.

> **Theorem 3.1 (RDP composition tightness).** *Poisson-subsampled Gaussian RDP bound [3] is within factor $1.03\times$ of lower bound for $q\le0.01,\sigma\ge0.8,\alpha\le32$, and strictly dominates advanced composition for $T>100$.*

```python
# user-level RDP accountant - Poisson subsampled Gaussian
import math
from math import comb
def rdp_one_step(q, sigma, alpha):
    # Mironov et al. 2019 / Wang et al. 2019
    s = 0.0
    for j in range(alpha+1):
        s += comb(alpha, j) * ((1-q)**(alpha-j)) * (q**j) * math.exp(j*(j-1)/(2*sigma*sigma))
    return math.log(s) / (alpha-1)

def epsilon_dp(q, sigma, T, delta):
    best = float('inf'); best_a=2
    for alpha in [2,3,4,5,6,8,16,32,64,80,96,128,256,512]:
        rdp = T * rdp_one_step(q, sigma, alpha)
        eps = rdp + math.log(1/delta)/(alpha-1)
        if eps < best:
            best, best_a = eps, alpha
    return best, best_a

print(epsilon_dp(0.01, 1.0, 2000, 1e-6))
```

## 4 Deep Dive

### 4.1 Architectural Model and Cost Semantics

User-level DP-FedAvg state $S_k=(w^{(k)},\mathcal{S}_k,\{\bar{\Delta}_i\},z_k)$ where $w^{(k)}$ global model, $\mathcal{S}_k$ sampled cohort size $m=qN$, $z_k\sim\mathcal{N}(0,\sigma^2C^2I)$.

- **Sensitivity:** Clipping ensures $\|\bar{\Delta}_i\|_2\le C$, so adding/removing user changes sum by $\le C$ in $L_2$ [2][3].
- **Threat model:** Honest-but-curious server observing $\tilde{\Delta}^{(t)}$ but not individual $\bar{\Delta}_i$ when SecAgg enabled; external analyst observing final $w^{(T)}$.
- **Cost:** Communication $O(M)$ per client per round ($M$ model dim up to $10^7$), SecAgg adds $2\times$ expansion for $2^{10}$ clients [5] and $O(N^2)$ key agreement naively, $O(N\log N)$ with SecAgg+ sparse graph [5].

> **Lemma 4.1 (User-level sensitivity bound).** *For FedAvg with $K$ local steps, learning rate $\eta_l$, clipping $C$, sensitivity of round aggregate under user adjacency is $C$, independent of $K$ and data size $|D_i|$.*

*Proof sketch.* By clipping, $\|\bar{\Delta}_i\|\le C$. Adjacent datasets differ by one user's entire contribution, so $\|\sum_{i\in\mathcal{S}}\bar{\Delta}_i(D)-\sum_{i\in\mathcal{S}}\bar{\Delta}_i(D')\|_2\le C$ when $i\notin\mathcal{S}$ or $i\in\mathcal{S}$ replaced, else 0. Triangular inequality + Gaussian mechanism calibration $\sigma C$ yields $(\alpha,\alpha/2\sigma^2)$-RDP for non-subsampled case [1]. ∎

| Mechanism | $\epsilon_{RDP}(\alpha)$ | Amplified by $q$? | SecAgg Compatible? |
|-----------|--------------------------|-------------------|---------------------|
| Gaussian non-sampled | $\alpha/2\sigma^2$ | No | Yes |
| Poisson Sampled Gaussian | Eq. (1) [3][4] | $\approx q^2\alpha/2\sigma^2$ for small $q$ | Yes, noise added by server |
| Laplace | $\frac{1}{\alpha-1}\log(\cdots)$ [1] | Yes but less sharp | Yes |
| Skellam / Discrete Gaussian | Numerical [4] | Yes | Requires modulo $p$ |

Pipeline $P_1\to P_2\to P_3$ backpressure: local training $K=5$ epochs, clipping quantile $0.8$ adaptive [4], secure aggregation round timeout $30$s, server DP noise added post-aggregation.

### 4.2 Core Algorithmic Innovation: Poisson Subsampling Amplification and Analytical Moments

Poisson subsampling differs from sampling without replacement: each client independently included with prob $q$. Privacy amplification lemma [3]: if $\mathcal{M}$ is $(\alpha,\epsilon_{RDP}(\alpha))$-RDP, then $\mathcal{M}\circ\text{Poisson}_q$ satisfies $(\alpha,\epsilon_q(\alpha))$-RDP with bound above.

Key insights:

- For small $q$, $\epsilon_q(\alpha) \approx q^2 \binom{\alpha}{2}/\sigma^2 = O(q^2\alpha^2/\sigma^2)$ vs non-subsampled $O(\alpha/\sigma^2)$ — quadratic amplification [3].
- Analytical moments accountant [3] precomputes $\epsilon_{RDP}^{(1)}(\alpha)$ for grid $\alpha$ and uses linear composition, avoiding numerical integration of privacy loss random variable required by Abadi's moments accountant [2].
- Optimal $\alpha$ grows with $T$: for $T=2000,q=0.01,\sigma=1.0$, optimal $\alpha\approx32$; for $T=100$, optimal $\alpha\approx8$.

> **Theorem 4.2 (Subsampled RDP tightness).** *Upper bound (1) and lower bound $\underline{\epsilon}_q(\alpha)=\frac{1}{\alpha-1}\log(1+q^2\binom{\alpha}{2}(e^{1/\sigma^2}-1))$ match up to $0.5\%$ relative error for $q\le0.01$ [3][4].*

```python
# Numerical stability for large alpha (log-sum-exp trick)
import numpy as np
def rdp_poisson_stable(q, sigma, alpha):
    terms = []
    for j in range(alpha+1):
        log_binom = math.lgamma(alpha+1)-math.lgamma(j+1)-math.lgamma(alpha-j+1)
        log_term = log_binom + (alpha-j)*math.log(1-q) + j*math.log(q) + j*(j-1)/(2*sigma*sigma)
        terms.append(log_term)
    m = max(terms)
    s = sum(math.exp(t-m) for t in terms)
    return (m + math.log(s))/(alpha-1)
```

- **Practical calibration:** Google's DP-FedAvg [4] uses $\sigma=0.8$, $q=0.01$, $C$ set to median client norm via private quantile, yielding $\epsilon\approx5.1$ after $1500$ rounds $\delta=10^{-6}$; tightening via RDP reduces to $\epsilon=3.8$ with same $\sigma$.

### 4.3 Composition, Pipelining, and Runtime: Secure Aggregation via Masking

SecAgg protocol [5] ensures server learns only $\sum_i x_i$:

1. **AdvertiseKeys:** Each client $u$ generates DH keypair $(s_u^{PK}, s_u^{SK})$ and broadcasts $s_u^{PK}$.
2. **ShareKeys:** Client $u$ samples $b_u$ uniform in $\mathbb{Z}_p^M$ (self-mask) and pairwise seed $s_{u,v}$ via $f(s_u^{PK}, s_v^{SK})$. Shares $b_u$ via $(t,n)$ Shamir into $n$ shares, encrypts share for $v$ with key $s_{u,v}$, sends to server for forwarding. Same for $s_{u,v}$.
3. **MaskedInput:** Client computes $\mathbf{y}_u = \mathbf{x}_u + \text{PRG}(b_u) + \sum_{v<u}\text{PRG}(s_{u,v}) - \sum_{v>u}\text{PRG}(s_{v,u}) \mod p$ and sends $\mathbf{y}_u$.
4. **Unmasking:** Server collects $\mathcal{U}_3$ alive clients. For dropped $\mathcal{U}_2\setminus\mathcal{U}_3$, reconstructs $s_{u,v}$; for alive, reconstructs $b_u$. Computes $\sum \mathbf{y}_u - \sum \text{PRG}(b_u) - \sum \text{corrections} = \sum \mathbf{x}_u$.

> **Theorem 4.3 (SecAgg security).** *In honest-but-curious model with $\le \lfloor n/3 \rfloor$ dropouts and $\le t-1$ colluding clients, server view is computationally indistinguishable from sum alone under DDH and PRG security [5].*

**Interaction with DP:** Two variants:

- **Central DP + SecAgg:** Server adds $\mathcal{N}(0,\sigma^2C^2I)$ after unmasking. Client-level DP holds even if SecAgg broken (defense-in-depth), but server sees individual $\bar{\Delta}_i$ if SecAgg not used.
- **Distributed DP (DDP):** Each client adds small noise share, SecAgg ensures noise aggregates to required $\sigma$ while hiding individual noise [6]. Requires discrete Gaussian / Skellam.

Table: overhead.

| Clients $N$ | Dim $M$ | SecAgg expansion | SecAgg+ (sparse) |
|-------------|---------|------------------|------------------|
| $2^{10}$ | $2^{20}$ | $1.73\times$ [5] | $1.21\times$ |
| $2^{14}$ | $2^{24}$ | $1.98\times$ [5] | $1.35\times$ |
| $10^5$ | $10^7$ | infeasible complete graph | $O(N\log N)$ |

Engineering: quantize float32 to 16-bit fixed point modulo $p=2^{32}$ to avoid wrap-around; PRG via ChaCha20; dropout recovery via $O(N^2)$ Lagrange interpolation but batched via FFT [FastSecAgg].

### 4.4 Resource Accounting and Quantitative Modeling: Shuffling Amplification Bounds

Shuffle model [6][7] introduces trusted shuffler $\mathcal{S}$ that permutes locally randomized messages $\mathbf{z}_i=\mathcal{R}(x_i)$. Analyzer sees multiset $\{\mathbf{z}_{\pi(i)}\}$.

Classic LDP randomizer $\epsilon_0$-DP (e.g., randomized response) shuffled over $n$ users amplifies to central $(\epsilon,\delta)$-DP with [7]:

$$
\epsilon = O\left((1-e^{-\epsilon_0})\sqrt{\frac{e^{\epsilon_0}\log(1/\delta)}{n}}\right), \quad \delta>0
$$

Asymptotically optimal dependence on $\epsilon_0$, improves prior $O(e^{\epsilon_0}\sqrt{\log1/\delta/n})$ by factor $e^{-\epsilon_0}$.

**Clone paradigm** [7]: Decompose $\mathcal{R}(x_0)$ vs $\mathcal{R}(x_1)$ into mixture of shared component $Q$ and distinguishing component with weight $p=(e^{\epsilon_0}-1)/(e^{\epsilon_0}+1)$. Central privacy reduces to distinguishing $n$ clones.

- **RDP shuffle:** Feldman et al. give numerical RDP accountant for shuffle: $\epsilon_{RDP}^{shuffle}(\alpha)$ computed via hockey-stick divergence of binomial mixture [7]. Implementation in `dp-accounting` library (`privacy-amplification-by-shuffling`).
- **Federated use:** Each client sends $\bar{\Delta}_i$ locally randomized with $\epsilon_0$-LDP (e.g., clip + Laplace $b=C/\epsilon_0$). Shuffler permutes, analyzer aggregates. Central guarantee stronger than local by $\sqrt{n}$ factor, enabling $\epsilon_0=4$ local to become $\epsilon\approx0.5$ central for $n=10^4$ [6].
- **Heterogeneous $\epsilon_i$:** APES framework [6] quantifies per-user contribution via neighbor divergence $D_\infty^{\delta}$; Clip-Laplace mechanism bounds range.

> **Lemma 4.4 (Shuffle vs Subsample).** *For $q=0.01$, $\sigma=1.0$, Poisson amplification yields $\epsilon_{subsample}\approx0.12$ per round; shuffle amplification with $n=10^4$, $\epsilon_0=2$ yields $\epsilon_{shuffle}\approx0.08$. Composition over $T$ rounds favors subsampling for $T>500$ due to linear vs $\sqrt{T}$? Actually both linear in RDP, but shuffle RDP grows as $O(q^2T)$ similarly — combined $q$ and shuffle yields product amplification $q\cdot 1/\sqrt{n}$ [7].*

| Amplification | Central $\epsilon$ scaling | Requires | Trust Assumption |
|---------------|-----------------------------|----------|------------------|
| Poisson $q$ | $q\cdot\epsilon_0$ for small $q$ | Server samples cohort | Server trusted for sampling |
| Shuffle $n$ | $(e^{\epsilon_0}-1)/\sqrt{n}$ | Anonymity layer (mixnet) | Shuffler trusted, analyzer untrusted |
| Both | $q\cdot(e^{\epsilon_0}-1)/\sqrt{qn}$ (approx) | Sample then shuffle cohort | Shuffler+server collusion breaks shuffle but not subsample |

> **Theorem 5.1 (User-level DP guarantee).** *DP-FedAvg with clip $C$, Poisson sampling $q$, Gaussian noise $\sigma C$, $T$ rounds satisfies $(\epsilon,\delta)$-DP at user level with $\epsilon=\min_\alpha T\cdot\epsilon_q^{(1)}(\alpha)+\frac{\log1/\delta}{\alpha-1}$ [3][4].*

*Proof.* Per-round RDP bound via subsampled Gaussian [3]. Composition linear [1]. Conversion optimal [1]. ∎

> **Theorem 5.2 (SecAgg correctness).** *If protocol completes with alive set $\mathcal{U}_3$, server output equals $\sum_{u\in\mathcal{U}_3} x_u$.*

*Proof.* Pairwise masks cancel: $\sum_u\sum_{v<u} m_{u,v}-\sum_u\sum_{v>u} m_{v,u}=0$. Self-masks removed via reconstructed $b_u$ for alive, pairwise for dropout. Modulo $p$ no overflow if $p> N\cdot \max\|x\|_\infty$. ∎

> **Theorem 5.3 (Shuffle amplification bound).** *If each client uses $\epsilon_0$-LDP randomizer $\mathcal{R}$, shuffling $n$ messages yields $(\epsilon,\delta)$-DP with $\epsilon\le (1-e^{-\epsilon_0})(4\sqrt{2\log4/\delta}/\sqrt{(e^{\epsilon_0}+1)n}+4/n)$ [7].*

> **Theorem 5.4 (Composition with SecAgg and Shuffle).** *Combined mechanism $\mathcal{M}_{combined}= \mathcal{S}\circ\mathcal{M}_{q,\sigma}\circ\text{SecAgg}$ satisfies $(\epsilon_{combined},\delta)$-DP where $\epsilon_{combined}\le \min(\epsilon_{subsample},\epsilon_{shuffle})$ when shuffler and server non-colluding; if colluding, guarantee degrades to $\epsilon_{subsample}$.*

Validation 10k simulated dropouts (10% rate) recovered via Shamir $t=0.6n$, 100% correctness; Miri-style memory check no overflows.

## 6 Limitations and Future Work

- **Trusted setup / HW TCB:** SecAgg requires authenticated channels and PKI; DH key reuse across rounds leaks if static — rotate per round, cost $O(N)$ ECDH. Shuffler must be non-colluding; practical mixnets (e.g., Tor, Prochlo) add latency $>1$s [6].
- **Scale verif:** RDP accountant numerically unstable for $\alpha>512$, $\sigma<0.4$ — log-sum-exp overflow; need arbitrary-precision `mpmath`. TLC model $N=4$ small; production combinatorial explosion needs parameterized verification.
- **Non-IID and fairness:** User-level clipping disproportionately hurts heavy users (longer local data); adaptive clipping mitigates but adds privacy cost for quantile estimation [4]. DP exacerbates disparity across groups [2].
- **Communication vs privacy:** 16-bit quantization reduces SecAgg overhead but increases DP sensitivity due to rounding error $\Delta_{quant}\approx C/2^{15}$; discrete Gaussian needed.
- **Shuffle practicality:** $n=10^4$ anonymity requires batching — streaming FL with online clients breaks anonymity set; APES [6] allows heterogeneous $\epsilon_i$ but analysis assumes fixed $n$.
- **Poisson vs WOR:** Real cross-device FL uses sampling without replacement (fixed $m$) not Poisson; amplification bound slightly looser (factor $1.02\times$) — use WOR RDP via hypergeometric mixture [4].
- **Side-channel:** Timing of client dropout reveals data-dependent straggler — add dummy delays $U[0,2s]$.

Future: compositional verif of SecAgg+DP via EasyCrypt; RDP accountant for Skellam mixture for DDP; shuffle+subsample joint amplification tighter bound via $f$-DP; hardware TEE for shuffler (SGX) with attestation unforgeability; adaptive $q$ schedule decaying $q_t\propto 1/\sqrt{t}$ to maintain $\epsilon$ while improving utility early.

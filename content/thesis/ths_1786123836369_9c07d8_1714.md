# SMT Solving for Software Verification: DPLL(T), E-Graphs, Nelson-Oppen Combination, and Quantifier Instantiation in Z3 and cvc5

## Abstract
Satisfiability Modulo Theories (SMT) is the workhorse backend for modern software verification, from Boogie and Dafny to Rust verification and bounded model checking. This thesis provides a PhD-level synthesis of the core algorithms underpinning industrial SMT solvers Z3 and cvc5: the DPLL(T)/CDCL(T) search framework, E-graph-based congruence closure for the theory of uninterpreted functions and equality, the Nelson-Oppen and polite combination method for mixed signatures, and the quantifier instantiation stack based on E-matching, model-based quantifier instantiation (MBQI), and enumerative instantiation. We explain how verification conditions are compiled to many-sorted first-order logic modulo theories, how theory solvers cooperate lazily via interface equalities and conflict lemmas, and how quantified axioms for datatypes, sequences, and heap models are instantiated soundly yet effectively. We provide comparative implementation notes for Z3 vs cvc5 architectures and close with empirical methodology, soundness pitfalls, and open questions for trigger synthesis and learning-guided instantiation.

## 1 Intro
Software verification reduces to one question: *is there a program execution that violates the specification?* Encoded as a logical formula, the answer is **unsat means correct**, **sat means bug with a model as counterexample**. Propositional SAT is insufficient: program domains require arithmetic, arrays, bit-vectors, datatypes, and uninterpreted functions.

Satisfiability Modulo Theories (SMT) extends SAT with background theories $\mathcal{T}$ [2][5]. Modern solvers Z3 and cvc5 implement the **DPLL(T)** framework [1][6]: a CDCL SAT engine enumerates Boolean assignments, theory solvers check consistency modulo $\mathcal{T}$, and Nelson-Oppen style combination plus quantifier instantiation handle mixed and quantified logics.

In toolchains such as **Dafny → Boogie → Z3** or **Viper → Boogie → Z3/cvc5**, verification conditions (VCs) contain:

- *Ground constraints* over `Int`, `Real`, `BitVec`, `Array`, `Datatype`
- *Equality reasoning* over heap references and uninterpreted functions modeling user definitions [4]
- *Quantified axioms* for inductive datatypes, sequences, maps, monotonic heaps [7]

This thesis unifies these layers with rigorous definitions, pseudocode, and design trade-offs.

> **Theorem (DPLL(T) Soundness Sketch):** Let $\varphi$ be a quantifier-free SMT formula over $\bigcup \mathcal{T}_i$. If DPLL(T) with sound theory solvers and complete conflict generalization derives $\bot$, then $\varphi$ is $\mathcal{T}$-unsatisfiable. If it finds a full Boolean assignment $M$ where every $\mathcal{T}_i$-solver reports consistent and all interface arrangements are saturated, then $M$ is $\mathcal{T}$-satisfiable.

## 2 Background

### Theories and SMT-LIB
We work in **many-sorted first-order logic with equality**. A theory $\mathcal{T}$ is a class of structures. SMT-LIB defines:

- **QF_UF**: uninterpreted functions with congruence
- **QF_LIA / LRA / NRA / NIA**: linear/integer/real/nonlinear arithmetic
- **QF_ABV, QF_ALIA, QF_DT, QF_SEQ**: arrays, bitvectors, datatypes, sequences

Verification blends them: `Q_comb = QF_UFLIA + Arrays + Datatypes + Sequences` is common in Dafny Boogie output [4].

### Purification
A *mixed* literal $f(x+1) \le 3 \land f(y) = 7$ is *purified* by introducing fresh interface variables:

```
v1 = x+1
f(v1) ≤ 3   (UF+ LIA mix separated via v1)
w = f(y)
```

This yields signature-disjoint conjuncts linked only by equalities over shared variables $V_{shared}$ [3][4].

| Concept | Formal Object | Solver Component |
| :--- | :--- | :--- |
| Ground E-graph | $(V, E, \text{find}, \text{congr})$ | congruence closure core |
| Theory solver | $\text{check}: 2^{Lit} \to \{\text{sat}, \text{unsat}+ \text{lemma}\}$ | LIA simplex, BV bit-blasting |
| Interface | $V_{12} = Vars(\Gamma_1) \cap Vars(\Gamma_2)$ | Nelson-Oppen arrangement |
| Trigger | $p(\bar{x})$ subset of $\forall \bar{x}.\phi$ | E-matching index |

*Key property:* **Convexity** — if $\Gamma \models_{\mathcal{T}} \bigvee_{i} x_i = y_i$ then for some $i$, $\Gamma \models_{\mathcal{T}} x_i = y_i$. Convex theories (LRA, UF, Lists with restrictions) allow polynomial Nelson-Oppen [3][5]. Non-convex theories (LIA with disjunctions, BV) require arrangement enumeration, delegating to SAT.

### Software Verification Flow

```tla
---- MODULE VCFlow ----
VARIABLES prog, vc, smt, result
Init == prog \in Programs
GenVC == vc' = BoogieWP(prog)  \* weakest-precondition
ToSMT == smt' = Encode(vc, Theories = {UF, LIA, Arrays, Datatypes})
Solve == result' = Z3_Solve(smt) \cup cvc5_Solve(smt)
Spec == result = UNSAT => Correct(prog)
====
```

*Axiomatic heap* is modeled as `Array Ref (Array Field Value)` plus quantified framing axioms: $\forall h,r,f.\, \text{read}(\text{write}(h,r,f,v), r,f)=v$ [4][8].

## 3 Methodology

Our methodology is **analytic + architectural reconstruction** from primary solver papers, system descriptions, and lecture notes [1][4][6][7].

We deconstruct:

1. **DPLL(T) control loop** — CDCL decision, Boolean constraint propagation (BCP), theory propagation, backjumping, lemma learning, restarts.
2. **E-graph implementation** — union-find with congruence closure, proof forests, disequality handling, e-matching index (code trees, inverted path indexes) [7][8].
3. **Theory combination** — classical Nelson-Oppen, polite theories for finite sorts, Delayed Theory Combination (DTC) as implemented in Z3/cvc5 [2][5].
4. **Quantifier module** — prioritized instantiation portfolio: conflict-based → E-matching → enumerative → MBQI → finite model finding [6][7].
5. **Verification embedding** — VCGen correctness for Boogie/Dafny, axiom soundness, trigger annotation guidelines [4].

We formalize complexity and termination conditions for each instantiation strategy, using well-founded measures on term generation depth.

## 4 Deep Dive

### 4.1 DPLL(T) and CDCL(T) Core

Modern SMT is *lazy*: the SAT solver proposes $M = \{ l_1, l_2, \dots \}$, theory solver checks $M_{\mathcal{T}} = M \downharpoonleft Lit_{\mathcal{T}}$.

```python
# Simplified DPLL(T) loop - python-like pseudo
def dpll_T(phi):
    sat = CDCLInit(phi)
    while True:
        bcp_res = sat.bcp()
        if bcp_res.conflict:
            if not sat.resolve_conflict_learn(): return UNSAT
            continue
        th_res = theory_check(sat.trail)
        if th_res == UNSAT:
            sat.add_lemma(th_res.conflict_clause)  # (¬l1 ∨ ¬l2 ∨ ¬l3)
            sat.backjump()
        elif th_res.propagates:
            sat.enqueue(th_res.propagates, reason=th_res.just)
        elif sat.all_assigned():
            return SAT, build_combined_model()
        else:
            sat.decide()
```

**Key invariants:**

- *Early pruning*: theory solvers incrementally check after each $k$ decisions [1][2].
- *Theory propagation*: If $\Gamma \models_{\mathcal{T}} l$ then force $l$ at current level, no branching [1].
- *Model-based combination*: Z3 builds candidate $\mathcal{T}$-models eagerly to minimize interface branching — the **Model-Based Theory Combination** optimization reduces arrangement guessing exponentially [2][5].

*Practical distinction*: cvc5 uses a **centralized proof-driven architecture** with fine-grained lazy proof production [8], while Z3 uses a monolithic core with tightly-coupled theory solvers and *relevancy propagation* to filter terms.

*cvc5 architecture* [1] is layered: parser → preprocessing (rewriter, CNF) → prop engine (SAT) → theory engine (QF solvers) → quantifiers engine → proof engine. Each layer exposes `assert`, `check`, `push/pop`.

### 4.2 E-Graphs and Congruence Closure in UF and beyond

The *E-graph* compresses exponentially many equalities in $O(n \log n)$.

**Invariants:**

- Each equivalence class has a representative via Union-Find with path compression.
- Signature table: $f([a],[b]) \to [f(a,b)]$ detects congruence: if $a \approx b$ then $f(a) \approx f(b)$.
- Disequality graph: $a \not\approx b$ must be separated; violation yields conflict.

```haskell
-- congruence closure core in Haskell style
data ENode = App Symbol [ClassId] | Var String
type EGraph = Map ClassId (Set ENode, ParentList)

merge :: EGraph -> Lit -> EGraph
merge g (Eq a b) =
  let ca = find g a; cb = find g b
  in if ca==cb then g else propagateCongruence (union ca cb g)
merge g (Diseq a b) =
  if find g a == find g b then conflict else insertDiseq g a b

propagateCongruence g =
  -- if f(x) and f(y) now have x≈y, merge their classes
  foldMerge g (signatureCollisions g)
```

In Z3, the E-graph also serves as the **term index for E-matching**. The famous optimizations are:

- *Code trees*: compile patterns $f(g(?x),a)$ to decision trees over E-graph symbols [7]
- *Inverted path indexes*: incremental re-matching after merges only touches affected triggers [7]
- *Relevancy*: only terms that appear in non-redundant clauses are inserted into matching loop, preventing $10^6$ trigger blow-ups from library axiomatizations [4]

> **Theorem (Congruence Closure Correctness):** Closure saturates exactly when $E \models t_1 \approx t_2$ iff $\text{find}(t_1)=\text{find}(t_2)$. Proof forest yields $O(n)$ proof terms used for UNSAT cores.

### 4.3 Nelson-Oppen, Polite Theories, and Delayed Combination

Classically, two stably-infinite, signature-disjoint theories $\mathcal{T}_1,\mathcal{T}_2$ combine via arrangements $\mathcal{A}$ over $V_{shared}$:

$\Gamma_1 \cup \Gamma_2$ is combinable-satisfiable iff $\exists \mathcal{A}$ arrangement s.t. $\Gamma_1 \cup \mathcal{A}$ is $\mathcal{T}_1$-sat and $\Gamma_2 \cup \mathcal{A}$ is $\mathcal{T}_2$-sat [3].

For $n = |V_{shared}|$, arrangements up to Bell numbers — intractable. Modern solvers:

- **Convex theories** propagate equalities deterministically: $Th_1 \vdash x=y$ is forwarded to $Th_2$ without case split [3][4].
- **DTC**: Boolean-sat encodes all $x_i = y_j$ as Boolean atoms, SAT solver guesses arrangement *on demand*. Z3 generates equalities lazily via candidate models [2].
- **Polite combination** handles non-stably-infinite theories (BV, finite datatypes) by requiring one side is *polite*: smooth (cardinality extensible) + finite witnessable [3][1].

```rust
// polite combination sketch in Rust
fn check_combination(gamma1: Conj, gamma2: Conj) -> SatRes {
    let shared = interface_vars(&gamma1, &gamma2);
    let mut arrangement = initial_equalities_from_egraph(&shared);
    loop {
        let r1 = t1_solver.check(gamma1.clone(), arrangement.clone());
        let r2 = t2_solver.check(gamma2.clone(), arrangement.clone());
        match (r1, r2) {
            (Unsat(c1), _) => return Unsat(c1),
            (_, Unsat(c2)) => return Unsat(c2),
            (Sat(m1), Sat(m2)) if compatible(&m1,&m2,&shared) => return Sat(merge(m1,m2)),
            (Prop(eq), _) => arrangement.add(eq), // Nelson-Oppen equality propagation
            _ => arrangement.add(sat.decide_equality(&shared)), // DTC: let SAT decide
        }
    }
}
```

*Caveats*: Shostak-style solving uses canonizers/invertible theories (`a+x ≤ b` solved for $x$). Z3's LIA uses Omega-test + bound propagation; cvc5's uses incremental simplex + branch-and-bound + cutting planes [1]. Their interaction with UFs is delicate — aggressive propagation $x+1 = y \implies f(x+1)=f(y)$ must go through E-graph to remain complete.

### 4.4 Quantifier Instantiation: E-Matching, MBQI, Enumerative

Quantifiers make SMT **undecidable**. Solvers rely on **incomplete heuristic instantiation** that succeeds on *verification-shaped* formulas.

**Portfolio in Z3/cvc5:**

1. **Conflict-based (CBQI)** [6]: try to build ground conflict from single negated universal $\neg\forall \bar{x}. \phi \leadsto \phi^\neg$. Uses CCFV calculus.
2. **E-matching** [7]: For axioms $\forall \bar{x}. P(\bar{x}) \to Q(\bar{x})$, user/system provides *triggers* $P$. If ground term $p_{g}$ in E-graph matches $P$ modulo $\approx$, instantiate $\bar{x}\mapsto \sigma$. This is **ground-term driven**, not syntax driven.
3. **Enumerative** [6][5]: Enumerate small ground terms by type in increasing size; test if instantiation $\neg$-entailed and relevant. Complete for finite domains.
4. **MBQI** [6]: Build candidate model $\mathcal{M}$ for ground part $G$. Evaluate $Q = \forall \bar{x}. \phi$ in $\mathcal{M}$. If $\mathcal{M} \not\models Q$, use $\bar{x}$ counterexample from model values (possibly infinite but projectable to ground terms) to instantiate. If passes, return SAT + model (with quantifiers). This is the only **model-sound** strategy.

```python
# Trigger selection and E-matching loop
triggers = [(Forall(x,y, Implies(P(x,y), Q(x))), Pattern(P(x,y))) ) ]
egraph = EGraph(all_ground_terms)

def ematch():
    for q, pat in triggers:
        for subst in egraph.match(pat):  # uses code tree
            if not already_seen(q, subst):
                yield instantiate(q, subst)

def mbqi_loop():
    while True:
        g_res = qf_solver.check()
        if g_res unsat: return UNSAT
        model = g_res.model
        failed = []
        for q in quantifiers:
            ce = model.evaluate_existential(q.body_neg)
            if ce is not None:
                failed.append(instantiate(q, ce))
        if not failed:
            return SAT, model  # model-based complete for fragment
        qf_solver.assert_many(failed)
```

*Trigger engineering* is critical: too permissive → matching loops → instantiation explosion $10^5$; too restrictive → incomplete proofs requiring redundant lemmas in Dafny. Golden rules from Dafny/Verus:

- `f(t)` trigger not `t`; avoid variables alone
- Prefer (many) small triggers, use `{:trigger false}` to disable aggressive axiom
- Datatype constructors are good triggers, selectors are not

Table comparing strategies on SMT-COMP UFLIA:

| Strategy | Completeness | Ground-guided | Model-sound | Z3 default priority | cvc5 priority |
| :--- | :--- | :--- | :--- | :--- | :--- |
| E-matching | No | Yes | No | 1 | 1 |
| Conflict-based | No | Yes | No | 1.5 | 2 |
| Enumerative | Yes for finite/$\exists^*\forall$-stratified | Partial | No | 2 | 1 (interleaved) |
| MBQI | Yes for EPR, LRA$\exists\forall$ fragments | No (model-driven) | Yes | 3 (last resort) | 3 |

## 5 Empirical/Proofs

We cannot run full SMT-COMP here, but we report *methodology for reproducing solver comparison* as used in cvc5 evaluation [1] and Z3 studies [2][6].

### Experimental Setup
- **Benches**: SMT-LIB QF_UFLIA 12k, QF_ABV 8k, UFLIA with quantifiers 6k (Boogie/Dafny background)
- **Solvers**: Z3 4.13.0 (`smt.qi.eager_threshold=100`, `smt.mbqi=true`), cvc5 1.2.0 (`--quant-ind`, `--enum-inst`, `--mbqi`)
- **Limits**: 120s, 8GB, `rlimit`;
- **Metrics**: solved/unsat/sat/unknown, instantiations count, E-graph merges, arrangement guesses

### Theoretical Guarantees

*Polite combination theorem* [3]: If $\mathcal{T}_1$ is polite w.r.t. sorts $S$ and $\mathcal{T}_2$ is arbitrary, then combined $\mathcal{T}_1 \cup \mathcal{T}_2$ is decidable if both $\mathcal{T}_i$-checks are decidable and $V_{shared} \supseteq$ witness variables. This is why sequences+arith combine in cvc5 despite finite-sort interaction.

*Instantiation termination* [7]: Define well-founded order on generated terms: $\text{depth}(f(t_1,\dots)) = 1+ \max \text{depth}(t_i)$. If trigger set is *finite and no term-creation cycle* (determined by trigger graph acyclicity check in Z3), E-matching terminates. With MBQI alone, termination not guaranteed except on decidable fragments (EPR, LRA $\forall$ [6]).

**Ground completeness proof sketch for enumerative + E-matching:** For any Herbrand model refutation of depth $k$, enumerative instantiation with bound $k$ generates all ground terms up to $k$ and thus finds refutation, modulo fairness scheduling [6].

### Observations from Literature [1][6]

- cvc5 solves 98.2% of QF benchmarks in 1.2× geometric mean time of CVC4 baseline, +12% over Z3 on quantified seq. logic [1]
- Z3 E-matching code trees reduce matching time 3–5× vs naive tree automata [7]
- MBQI adds +8% solved SAT cases in UFLIA with heavy quantifiers but -2% unsat due to delay [6]
- DTC arrangement guesses average < 15 per UNSAT in QF_UFLIA industrial benchmarks, vs $2^{|V_{shared}|}$ worst case [2]

## 6 Limitations

- **Trigger synthesis is still art**: Automatic trigger inference from `forall x. f(x) = g(x)` produces `{f(x)}` or `{g(x)}`? Choice affects fair termination [7]. Machine learning guidance being explored [2] shows early promise but no robust learned policy yet.
- **Nonlinear arithmetic incompleteness**: Z3/cvc5 use incomplete linearization, incomplete interval propagation, complete only for proven UNSAT of polynomials via CAD (doubly-exponential) — verification of crypto involving `mul` often unknown [1].
- **Quantifier alternating-heavy axioms** (monotonic heap `forall h1 h2 r. h1 ≤ h2 → read(h1,r) ≤ read(h2,r)`) cause $O(n^2)$ instantiations; Boogie/Dafny mitigation via `:weight` and `{:opaque}` poorly understood [4].
- **Proof production overhead**: fine-grained proofs in cvc5 increase memory 30-60% [8]; Z3 still lacks full proof production for MBQI and some string solver components, complicating proof-carrying verification [1].
- **Polite/combination gaps**: finite field + UF + arrays still non-polite in general; bitvector length polymorphism triggers witness blow-up [3][5].
- **Model soundness vs verification**: MBQI models may assign empty sorts or nonstandard interpretations that don't lift to program heaps, requiring manual `:pattern` to avoid spurious SAT that hides real bugs [6].

## 7 Conclusion

SMT solving succeeded because it **modularizes hard verification problems** into Cooperating solvers with well-defined interfaces: a CDCL core for Boolean structure, fast equality reasoning via E-graphs, disciplined theory combination via Nelson-Oppen and politeness, and pragmatic quantifier handling via a portfolio of incomplete but complementary strategies.

Z3 and cvc5 embody different points in this design space — Z3 trades proof completeness for aggressive model-guided search and relevancy filtering; cvc5 trades monolithicity for extensible layered architecture with first-class proof and combination infrastructure [1]. Both rely critically on E-graphs not merely as a UF solver but as a shared term database connecting ground reasoning, equality propagation, and trigger matching.

For verification engineers, the lesson is *encoding discipline*: write triggers that are ground-term productive, purify mixed arithmetic early, keep interface variables small (via abstraction), prefer datatypes over raw arrays when possible, and understand that $\forall$ is never really $\forall$ — it's a generator of finite instantiation lemmas. Future work likely replaces hand-tuned trigger weights with *neural trigger ranking* and uses large language models to propose relevant lemmas before falling back to blind enumeration [2][8].

*Soundness and performance remain in tension — pushing the frontier means making quantifier instantiation more semantic while keeping toolchains predictable.*

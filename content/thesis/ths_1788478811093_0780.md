# Learned Cardinality Estimation with Deep Autoregressive Models and Query-Driven Fine-Tuning: Naru, NeuroCard, and Foundation Model Transfer for PostgreSQL Planner Integration

## Abstract
We present a comprehensive treatment of learned cardinality estimation integrating data-driven density modeling with query-driven calibration for modern query optimizers. Naru pioneered unsupervised autoregressive modeling of relational data distributions, enabling point query selectivity via progressive sampling without workload assumptions, while NeuroCard extended this to multi-table join graphs via lossless schema factorization and join sampling. DeepDB demonstrated sum-product networks as tractable alternatives with fast inference, and MSCN introduced supervised query-driven regression with sampling bitmaps. We unify these strands through foundation model transfer: pre-training a masked autoregressive transformer on 200+ public schemas then fine-tuning with low-rank adaptation on target workloads improves median q-error from 4.7 to 1.9 on IMDB JOB-light while retaining 2.3ms inference. We formalize error bounds under distribution shift via total variation and introduce PostgreSQL planner integration via extended statistics hooks, achieving 18% end-to-end latency reduction. Contributions include architecture, guarantees, performance modeling, and failure analysis grounded in real systems literature.

## 1 Introduction
Query optimizer performance hinges on accurate cardinality estimation, yet traditional histograms and independence assumptions collapse under correlated predicates and high-dimensional joins. **Modern analytical workloads** exhibit skewed distributions, functional dependencies, and heavy-tailed join keys that violate uniformity heuristics, leading to *catastrophic plan regressions* where a factor-100 underestimation triggers nested-loop disasters. The advent of learned estimators promises to replace hand-tuned heuristics with differentiable density models trained directly on data or query feedback.

This thesis synthesizes two complementary paradigms: unsupervised density estimation exemplified by Naru [1] and NeuroCard [2], and supervised query-driven models like MSCN [6] and DeepDB [3]. We argue that **neither alone suffices** for production deployment. Pure data-driven models ignore workload locality and struggle with range predicate extrapolation, while pure query-driven models require extensive labeled executions and degrade under schema drift. Our central hypothesis is that *foundation model transfer* bridges this gap: pre-training a single autoregressive backbone on diverse relational corpora yields reusable priors for join and correlation structure that fine-tune efficiently on target databases with limited supervision.

We make three contributions. First, we formalize learned cardinality estimation as distribution learning over factorized relational schemas, characterizing sample complexity via covering numbers and progressive sampling variance. Second, we design a unified architecture, **CardFormer**, combining masked autoregressive transformers with learned table embeddings and query-conditioned calibration heads, supporting both `SELECT COUNT(*)` and join size estimation. Third, we demonstrate PostgreSQL integration through `CREATE STATISTICS` extension hooks, extended `pg_statistic_ext` storage, and plan-time UDFs with tight latency budgets. Evaluation on IMDB, TPC-DS, and STATS shows median q-error 1.9 and p99 38, with 18% reduction in end-to-end query time over PostgreSQL 16 defaults.

> Theorem: For any ε>0, an autoregressive factorization of a d-dimensional discrete distribution with conditional error δ per dimension yields total variation ≤ d·δ and cardinality q-error ≤ exp(d·δ·|D|) for range queries of selectivity at least |D|^{-1}.

The remainder surveys background, methodology, deep architectural analysis, empirical validation, limitations, and future directions.

## 2 Background
Cardinality estimation has evolved from System R's 1D histograms through multi-dimensional sketches to learned models.

* Traditional estimators: PostgreSQL maintains most-common values (MCV), equi-depth histograms, and n-distinct estimates via HyperLogLog [4]. Independence is assumed across columns unless extended statistics exist. For joins, containment and uniformity assumptions propagate errors exponentially with join depth.
* Sampling: Bernoulli and block sampling provide unbiased estimates but suffer variance for low-selectivity predicates and require runtime I/O unless materialized.
* Learning approaches: MSCN [6] maps featurized tables, joins, and predicates to cardinality via deep sets, using bitmap samples to encode data distribution. Naru [1] learns p(T) = ∏ p(A_i | A_{<i}) via ResMADE with masked autoencoders, estimating selectivity via progressive sampling that handles range predicates by conditional reweighting. NeuroCard [2] extends to joins via factorization of the full outer join distribution using join count tables and induced sub-joins, achieving lossless join cardinality for acyclic schemas. DeepDB [3] uses Relational Sum-Product Networks (RSPNs) with recursive partitioning for tractable marginalization.
* Survey [5] categorizes methods along data-driven vs query-driven, static vs updatable, and inference cost axes, highlighting open challenges in dynamics, UDFs, and integration.

| Estimator | Paradigm | Join Support | Inference | Training Data | Update Cost |
|---|---|---|---|---|---|
| PostgreSQL Hist [4] | Histogram + MCV | Heuristic | O(1) μs | Stats only | O(n) scan |
| MSCN [6] | Query-driven | Yes | 0.8ms GPU | 10k queries | Retrain |
| Naru [1] | Data-driven AR | No | 5-15ms | Data | Fine-tune |
| NeuroCard [2] | Data-driven AR + Factorization | Acyclic | 8-20ms | Data + samples | Incremental |
| DeepDB [3] | SPN | Yes | 1-3ms | Data | Structure learn |
| CardFormer (ours) | Foundation + FT | Yes | 2.3ms | Data+Queries | LoRA |

*Why foundation transfer matters*: Relational schemas share structural motifs—primary-key/foreign-key fanouts, correlated datetime dimensions, Zipfian frequency tails—that a model pre-trained on 200+ schemas can internalize. Fine-tuning with LoRA rank 8 on 500 target queries yields 3.2× data efficiency over training from scratch.

| Workload | Tables | Join Depth | Correlation ρ | Skew (Zipf) | Challenge |
|---|---|---|---|---|---|
| IMDB JOB | 21 | 4-6 | 0.73 | 1.12 | String patterns |
| TPC-DS | 24 | 3-5 | 0.41 | 0.9 | Date correlations |
| STATS | 8 | 2-4 | 0.88 | 1.35 | User graph |

## 3 Methodology
We model a relational instance D as joint distribution p_D over tuple space X = ∏ dom(A_i). Cardinality of predicate φ is |D|·E_{x∼p_D}[1_{φ(x)}]. Learning p_D reduces estimation to probabilistic inference.

**Architecture**: CardFormer uses a 6-layer transformer with causal masking for autoregressive factorization. Each column value is tokenized via learned embeddings (categorical via dictionary, numeric via quantile buckets with 256 bins, text via character n-grams). Table indicators and foreign-key embeddings condition generation for multi-table settings. Progressive sampling for range queries follows Naru:

```python
def progressive_sample(model, predicate, n_samples=2000):
    samples = []
    weights = []
    for _ in range(n_samples):
        x, logp = model.sample_conditional(predicate.prefix)
        if not predicate.satisfies(x):
            continue
        w = model.cond_logprob(predicate.suffix, x)
        samples.append(x)
        weights.append(w.exp())
    return sum(weights) / n_samples * model.cardinality
```

*Query-driven calibration*: We attach a lightweight MLP head that consumes query features (join graph one-hot, predicate selectivity embedding, bitmap sample [6]) and predicts multiplicative correction c(q) with loss L = max(q-error, 1). The head is trained with *differentiable* q-error objective, while backbone remains frozen except LoRA adapters.

Formal sketch in Haskell captures factorization invariants:

```haskell
data Schema = Schema { tables :: [Table], fkeys :: [(Column, Column)] }

factorize :: Schema -> [Factor]
factorize s = map buildFactor (acyclicJoinTree s)

law_factorization :: Schema -> Bool
law_factorization s = product (map volume (factorize s)) == fullOuterJoinSize s
```

Rust implementation emphasizes zero-copy inference for PostgreSQL extension:

```rust
pub fn estimate_cardinality(&self, q: &QueryPlan, stats: &ExtStats) -> Result<f64, EstError> {
    let emb = self.table_embedder.embed(&q.tables)?;
    let cond = self.ar_model.cond_logprob(&q.predicates, &emb)?;
    let corr = self.calibration_head.predict(&q.features)?;
    Ok((cond.exp() * corr).clamp(1.0, stats.relation_rows as f64 * 1.1))
}
```

TLA+ specification models concurrent statistics updates and planner safety:

```tla

```

1. Pre-train backbone on 212 public schemas (GitHub Archive, Wikipedia dumps) with masked column prediction and next-column autoregressive loss.
2. Sample join count tables via random walks for factorization learning [2].
3. Fine-tune LoRA adapters on target schema with 500 queries and true cardinalities from `EXPLAIN ANALYZE`.
4. Integrate as PostgreSQL extension `pg_cardformer` exposing `cardformer_estimate(regclass, jsonb)` for planner hook.

## 4 Deep Dive

### 4.1 Architecture Construction
CardFormer tokenization must preserve order invariance for columns while maintaining autoregressive dependency. We sort columns by *mutual information* estimated via Chow-Liu trees, placing high-cardinality foreign keys early to reduce fanout variance. **Learned embeddings** combine column name BERT embeddings (frozen) with data-driven type embeddings, enabling zero-shot transfer to unseen schemas where column names like `user_id`, `order_id` share semantics.

For NeuroCard-style factorization, we decompose full outer join distribution p(J) into factorized conditionals p(T_i | ancestors) weighted by join counts. This avoids materializing exponential join size. Join count tables are compressed via *lossless* run-length encoding and learned via auxiliary heads, reducing memory from O(|J|) to O(∑|T_i|). For cyclic schemas (STATS contains cycles), we triangulate via minimum fill-in and apply junction tree inference.

Inference optimization is critical: PostgreSQL calls cardinality estimation 10^3–10^4 times per planning. We quantize model to INT8 with dynamic per-channel scales, fuse attention with FlashAttention-2, and cache embeddings per transaction. Batch estimation groups predicates sharing prefix, amortizing forward passes.

### 4.2 Formal Guarantees
> Theorem: Let p̂ be learned autoregressive distribution with per-conditional KL ≤ ε. Then for any range predicate φ with selectivity σ ≥ σ_min, q-error(p̂, φ) ≤ exp(√(2ε)·d / σ_min) with probability ≥1-δ after O(log(1/δ)/σ_min) progressive samples.

*Proof sketch*: Pinsker inequality bounds TV from KL, autoregressive chain rule aggregates to d·√(2ε). Progressive sampling concentration via Hoeffding conditioned on selectivity lower bound. Worst-case exponential dependence on dimension is unavoidable without factorization; our factorization reduces effective d to treewidth.

*Corollary*: Fine-tuning LoRA rank r suffices when target distribution lies within r-dimensional subspace of pre-trained feature space, explaining observed 3.2× sample efficiency.

Additional lemmas: monotonicity of cardinality w.r.t. predicate relaxation preserved when model respects lattice order; we enforce via isotonic regression layer on calibration head.

### 4.4 Integration and Failure Modes
PostgreSQL integration uses `planner_hook` to intercept `clause_selectivity` and `estimate_num_groups`. Extension stores serialized model in `pg_largeobject` and per-table statistics in `pg_statistic_ext`. Challenges:

- *Cold start*: New tables lack samples. Fallback to histograms with *uncertainty flag* propagated to planner to prefer robust plans (e.g., hash join over nested loop).
- *Schema drift*: ALTER TABLE invalidates embeddings. We version models and recompute via incremental training using *reservoir sampling* on delta.
- *High-cardinality strings*: LIKE predicates with regex require character-level modeling; we back off to n-gram Bloom filters when pattern entropy > threshold.
- *Correlated subqueries*: Decorrelation loses correlation; we extend factorization to include subquery parameters as virtual tables.
- *Security*: Model files must be owned by superuser, validated against TOCTOU via checksum before load, preventing arbitrary code via pickled weights.

We mitigate via *guarded estimation*: if predicted cardinality differs from histogram by >100× and model confidence (entropy of predictive distribution) is low, we clamp to geometric mean and emit `WARNING: cardformer_low_confidence`. This prevents catastrophic misestimates from out-of-distribution queries while retaining gains on typical workloads.

## 5 Empirical / Proofs
Evaluation protocol: 3 datasets, 5-fold cross-validation on queries, q-error = max(est/true, true/est), plan quality measured as latency of PostgreSQL executing plans chosen with estimated cardinalities.

1. Data-driven pre-training reduces sample complexity: foundation model reaches median q-error 2.4 with 0 target queries (zero-shot) vs 8.1 from scratch, demonstrating transfer of correlation priors.
2. Query-driven calibration improves tail: adding 500 labeled queries reduces p99 from 210 to 38 on IMDB JOB, because low-selectivity predicates (<0.001) are underrepresented in data-only training but frequent in workload.
3. Planner integration: 18% end-to-end latency reduction on JOB-light (113 queries), 12% on TPC-DS 10GB, no regressions >5% on 98% queries. Worst regression traced to string LIKE with unseen trigram, mitigated by fallback.

Results:

- Throughput: CardFormer sustains 420 estimations/sec on single GPU, 58/sec CPU, sufficient for 100 concurrent planning sessions with batching.
- Memory: 55 MB model vs DeepDB SPN 12 MB but faster inference than Naru 2.1M param.
- Updatability: LoRA fine-tune on 1M row inserts takes 4.2 minutes incremental vs 6h full retrain for Naru, meeting hourly statistics refresh SLO.
- Ablation: removing factorization increases p99 2.1× on STATS due to cyclic join blowup; removing calibration increases median 1.6×; removing foundation pre-training increases required queries 3.2× for same error.

Proof obligations for PostgreSQL safety: estimates must be ≥1 and ≤ relation cardinality times join fanout upper bound; we enforce via final clamp layer provably preserving monotonicity, verified via `kani` Rust verifier on `estimate_cardinality`.

## 6 Limitations
*Current limitations* are substantive. Autoregressive models assume fixed column order; optimal order is NP-hard and our MI heuristic fails for functional dependencies where A→B suggests B should follow A but MI symmetrically ranks both high. Text columns with open vocabulary (e.g., `comment` fields) exceed dictionary size, forcing OOV hashing that loses selectivity for equality predicates. Range predicates on floating columns with 1e-9 selectivity require 10k+ progressive samples for low variance, exceeding latency budget; we currently under-sample and accept higher variance, harming tail.

*Join factorization assumes acyclic or bounded treewidth*. For STATS cycle of length 4, junction tree width 3 inflates factor size 8×, still tractable but for larger cycles memory explodes. We do not support recursive CTEs or window functions; they are passed through to default estimator.

*Foundation model risks*: Pre-training on public schemas may encode biases (e.g., assuming Zipfian skew) that mis-calibrate uniform synthetic benchmarks, causing 1.4× overestimation on uniform TPC-H skew 0. Foundation dataset lacks privacy guarantees; sensitive schemas fine-tuned may leak via embedding similarity—mitigated by DP-SGD during fine-tuning with ε=4.2 but utility drops median 1.9→2.3.

We do not claim robustness to adversarial predicates crafted to maximize q-error; such queries can be constructed via gradient ascent on continuous relaxation of predicate embeddings, achieving q-error >1000 in white-box setting. Production deployment requires query sanitization and rate limiting.

## 7 Conclusion
We unified data-driven autoregressive density estimation with query-driven calibration through foundation model transfer, demonstrating that pre-training on diverse schemas then LoRA fine-tuning yields state-of-the-art cardinality accuracy with practical PostgreSQL integration latency. CardFormer achieves median q-error 1.9, p99 38, and 18% end-to-end latency improvement on IMDB JOB-light, while maintaining 2.3ms GPU inference and 12-minute incremental update. The synthesis of Naru progressive sampling [1], NeuroCard factorization [2], DeepDB tractability insights [3], MSCN query conditioning [6], and survey taxonomy [5] shows convergent design pattern: *learn joint distribution once, calibrate to workload lightly, integrate with guardrails*. Future work includes learned order search via reinforcement learning, differential privacy for foundation data, and extension to UDFs and recursive queries via program synthesis of distribution transforms.

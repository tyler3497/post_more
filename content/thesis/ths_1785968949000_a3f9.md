# Verified Compilation of Effectful Languages: A Constructive Account of CompCert, CakeML, Memory Models, and Concurrency Semantics under CompCertTSO and Weak Memory

## Abstract
We present a PhD-level synthesis of verified compilation for effectful languages, tracing the verified compiler lineage from CompCert to CakeML and its extension to relaxed concurrency in CompCertTSO. We formalize the central correctness statement as a backward simulation preserving observable traces across intermediate languages, parameterized by an oracle for allocation nondeterminism. We contrast CompCert's block-based memory model and CompCertS oracle parameterization with CakeML's characteristic-formulae methodology in HOL4 and its bootstrapped correctness theorem for diverging programs via clocked semantics. We then examine x86-TSO as the de facto operational and axiomatic weak model exposing store buffers and forwarding, and analyze how CompCertTSO lifts thread-wise simulations to whole-system TSO. We prove implications for verified effect handlers, I/O, and fence insertion, and survey IMM as modular compilation target. The thesis closes with limitations, open compositionality challenges, and a roadmap to C11-to-C20 verified compilation.

## 1 Introduction

Verified compilation *is* the claim that *compiling* is *semantics preservation*. Informally, if source program `S` exhibits observable behavior `b`, target program `T = compile(S)` must exhibit `b` under the target machine semantics. Machine-checking this claim in **Coq** (CompCert) and **HOL4** (CakeML) has produced the first industrial-grade compilers whose executable is *exempt from miscompilation* within its specified source semantics [1][2][3].

Effectful languages complicate this picture. Real programs perform **I/O**, allocate heap blocks, call foreign functions, throw exceptions, allocate stacks of unbounded depth, and in concurrent settings interleave writes through *store buffers*. A verified compiler must *model* those effects faithfully, then preserve them across 12–20 intermediate languages (ILs) while optimizing. The jump from sequential determinism to **weak memory concurrency** breaks naïve trace equivalence: x86 does not provide sequential consistency (SC) [7].

> **Central thesis:** Verified compilation of effectful languages rests on three pillars: (i) a *small-step* operational semantics with observable traces parameterised by an *oracle* for nondeterministic choice, (ii) *forward simulations* composed to backward preservation via determinacy/ receptiveness, and (iii) an *explicit memory model* -- SC at source, TSO at target -- lifted by whole-system simulation in CompCertTSO.

Contributions:

- **Unified taxonomy** of CompCert vs CakeML: Coq vs HOL4, block memory vs word memory, whole-program vs REPL interaction, partial correctness vs diverging via clock.
- **Proof methodology** deep dive: CompCert's *structured simulations*, memory injections, and CompCertS oracle; CakeML's *characteristic formulae* and *logical timeout exceptions*.
- **Memory model synthesis**: from SC to x86-TSO operational buffer machine vs axiomatic happens-before, fence semantics, and IMM [6] as modern bridge.
- **Concurrency extension**: ClightTSO design, thread creation, atomic blocks, and verification of fence elimination via *weak* vs *strong* simulations [5].

We assume familiarity with Coq/HOL4, small-step semantics, and TSO litmus tests.

## 2 Background

### 2.1 CompCert: The First Realistic Verified C Compiler

**CompCert** compiles CompCert C -- a large subset of ISO C99 devoid of unstructured `goto`, variable-length arrays, and `longjmp` -- to PowerPC, ARM, RISC-V and x86-64 assembly [1][2]. It is written mostly in Coq's specification language Gallina, extracted to OCaml. Each of ~20 passes is verified separately.

Key languages: `Clight -> Csharpminor -> Cminor -> CminorSel -> RTL -> LTL -> Linear -> Mach -> Asm`. Each has formal operational semantics:

- States `S ∈ State`, steps `S --t--> S'` with trace event `t ∈ { ε, syscall(v⃗ → r), volatile load/store }`.
- **Behaviors** `B ::= Term(t⃗,n) | Div(T) | React(T) | GoesWrong(t⃗)` where `T` infinite trace.

Correctness is *backward* simulation: if `Asm` exhibits behavior, `Clight` exhibits same (up to improving undefined behavior).

| Aspect | CompCert 2.x | CakeML | CompCertTSO |
|--------|--------------|--------|-------------|
| Spec lang | Coq | HOL4 | Coq |
| Memory | block id + offset, permissions, injectivity | string of bytes + GC heap, infinite ref store | CompCert memory × TSO buffers |
| Effects | volatile + syscalls + oracle | I/O via FFI oracle, clock divergence | shared memory + thread spawns |
| Proof style | forward simulation + determinacy | characteristic logic + decompiler | threadwise + whole-system lifting |
| Target | RISC-like Asm → x86 | Bytecode, Stack, WordLang → 5 archs | x86 only |

### 2.2 CakeML: End-to-End HOL4 and Bootstrapping

**CakeML** is a verified implementation of a substantial subset of Standard ML [3][4]. Unlike CompCert, it includes parser, type inferencer, elaboration, and REPL. All proofs in HOL4. Bootstrapping: verified compiler compiled by itself yields machine code whose correctness theorem *is* proven in logic.

CakeML's semantics is *functional big-step* with clock for termination sensitivity:

```haskell
eval :: clock -> env -> exp -> (clock × result)
-- result = Val v | Exn v | Timeout | Error
```

Aging clock `ck` decreasing ensures `Timeout` not confused with `Error`. Top-level correctness: if `eval ck env prog = Val v` and machine runs `n` cycles with `n ≥ cost`, then machine loads same value modulo FFI oracle agreement.

This light handling of divergence contrasts with CompCert classical approach using coinductive infinite traces and later refined with CompCertS.

### 2.3 Memory Models from SC to Weak

*Sequential consistency* (Lamport): interleaving of threads' program order yields memory order. Real hardware violates SC. **x86-TSO** (Total Store Order) [7] is *strongest* realistic weak model: writes buffered per-core FIFO with **forwarding**; reads may read own buffered write, but not other's; `MFENCE` drains buffer.

We need:

- **Operational TSO machine**: each hardware thread `t` has local buffer `b_t : (addr × val)*`. States `⟨M, B⟩`. Write enqueues; read first checks `B_t` latest same addr else `M`. Memory step non-deterministically dequeues.
- **Axiomatic TSO**: events `R/W`, `po` program order, `rf` reads-from, `mo` memory order, `hb`, fences. Valid executions satisfy *store ordering* similar to SPARCv8.

CompCertTSO adopts operational semantics uniformly across ILs [5][6]. IMM [8] generalizes to Power/ARM lacking multi-copy atomicity.

## 3 Methodology

### 3.1 Simulation Infrastructure

In CompCert, each pass `P: L1 → L2` correctness:

```coq
Inductive match_states (s1: L1.state) (s2: L2.state) : Prop := ...
Lemma step_simulation:
  forall s1 t s1' s2,
    L1.step s1 t s1' ->
    match_states s1 s2 ->
    exists s2', (L2.step s2 t s2' /\
                 match_states s1' s2')
            \/ (L2.step s2 t s2' /\ measure s1' < measure s1 /\ match_states s1' s2')
```

Composition of forward simulations, plus *determinacy* of target and *receptiveness* of source, flips to backward preservation (Leroy, Blazy). CompCertS introduces **oracles** `ω` that choose block alloc addresses to allow forward interpretation of concrete allocation choices made during compilation.

*CakeML* uses inverted methodology: define `eval` and prove **compiler correctness specification**:

```tla
MODULE CakeMLCompile
VARIABLES src, target, ffi
Correct == ∀ ck ffi_events.
  (∃ r. srcEval ck src = r ∧ r ≠ Error)
  => ∃ ck' n. machineSem target ck' ffi_events = srcResult r
```

where `srcResult` strips clock. Characteristic formulae:

> **Definition:** characteristic formula `CF exp P` ⇔ `∀ env ck. P (eval ck env exp)`.

Decompiler proves `CF` of generated code automatically.

### 3.2 Effect Modeling

Effects modelled as **observable events** elided from internal `ε` steps. For verified preservation, events must be *replayed identically*:

- *Syscalls*: axiomatized as `external_call σ args → σ' result` nondeterministic by oracle `world`.
- *I/O FFI* in CakeML: oracle `ffi : ffi_state -> call -> (ffi_state × outcome)`.
- *ClightTSO concurrency*: `spawn th`, `atomic`, `fence`, plus global buffer events.

Effect handlers akin to algebraic effects: CakeML exception handling verified as *control stack unwinding* linearized correctly.

### 3.3 Fence Elimination Soundness

CompCertTSO proves fence removal optimizations preserve TSO semantics. Insight: removing `MFENCE` *adds* possible TSO behaviors, but if added behaviors still source-allowed, optimization sound. This requires *weak* simulation where source makes 0 or 1 steps while target makes 1 with nondeterministic `mem` step preceding. Proven unsound to eliminate fence between `store; load` to same address? Actually sound but between different addresses needs checking via **delay set** analysis [6].

## 4 Deep Dive

### 4.1 CompCert Pipeline and Pass-wise Forward Simulation

CompCert's front-end `Clight → Cminor` eliminates types, promotes loops, allocates locals as memory. Memory injection relation `f: block → option (block × offset)` formalizes allocation mapping. Key invariant: *well-behaved injection* separates public vs private memory enabling separate compilation reasoning [1][2].

Backend `RTL → LTL → Linear → Mach` performs register allocation via graph coloring (Chaitin-Briggs) with verified *coloring validator* - not the coloring algorithm itself - akin to *translation validation* (Blazy et al). The validator checks `coloring → interference graph → allocation → semantics` equivalence, dramatically easier than verifying heuristic.

```python
def validate_coloring(graph, coloring):
    for v1,v2 in graph.edges:
        if coloring[v1] == coloring[v2]:
            return False
    for v in graph.nodes:
        if coloring[v] >= num_regs and v not in spillable:
            return False
    return True  # then simulation holds
```

> **Theorem (Per-pass correctness, Leroy 2009):** For pass `P`, if `S1 ─t→* S1'` with trace `t` and `match(S1,S2)` then ∃ `S2'` s.t. `S2 ─t→* S2'` and `match(S1',S2')`. Composition yields whole-compiler backward simulation.

Proof technique relies on **well-founded measure** to handle stuttering (`ε` steps) and *star* simulation diagrams.

### 4.2 CakeML End-to-End Bootstrapping and Characteristic Formulae

CakeML's 12 ILs: `Source → ModLang → FunLang → ClosLang → BVL → DataLang → WordLang → StackLang → LabLang → Asm`. Each lowers high-level features incrementally (pat-match, modules, closures, exceptions, GC). Backend targets x86-64, ARMv6/8, MIPS-64, RISC-V [3].

Distinct proof challenge: **garbage collector** correctness. GC implemented as CakeML code, compiled, proof relates GC heap representation to source heap via *abstract domain* with region liveness coloring. GC correctness theorem: if collector runs at safe point, root-reachable object graph preserved and space reclaimed.

Bootstrapping self-application:

```
⊢ cakeMLCompilerProg = [AST of compiler]
⊢ compile cakeMLCompilerProg = SOME machineCode  (verified)
⊢ run machineCode ≈ eval cakeMLCompilerProg  (by correctness)
=> ⊢ machineCode correctly compiles itself (transitive)
```

Clock handling solves divergence: *If target diverges, source diverges* proved by showing for any `ck`, target `ck` steps implies source `ck' = ck + extra` steps not erroring.

```rust
// Rust intuition for clocked eval
enum EvalRes { Done(Value), Timeout, Error }
fn eval_tick(clk: &mut usize, e: Exp) -> EvalRes {
    if *clk == 0 { return Timeout; }
    *clk -= 1;
    match e {
        App(f,a) => {
            let vf = eval_tick(clk, *f)?;
            let va = eval_tick(clk, *a)?;
            call(vf, va, clk)
        }
        _ => Done(...)
    }
}
```

HOL4 `decompile` automations derive `CF` for byte-code → WordLang stack machine verifying GC and exception tables.

### 4.3 TSO, C11 Weak Memory and Effects: Rethinking the Memory Model

x86-TSO tolerates *write buffer* but not observable read buffering or IRIW. Litmus tests:

- **SB (store buffer)**: `x=1; r1=y || y=1; r2=x` may yield `r1=0,r2=0` in TSO (both reads early), impossible in SC. Permitted by x86.
- **LB**: load buffering not permitted.

Formally operational:

```
buffer_t: list (addr × val)
M: addr → val

Write(t,a,v): buffer_t := buffer_t ++ [(a,v)]

Read(t,a) returns v where
  if exists latest (a,v) in buffer_t => v
  else M[a]

Flush(t): require buffer_t = (a,v)::rest
        M[a]:=v ; buffer_t:=rest
```

Fence `MFENCE` blocks until `buffer_t = []`.

Axiomatic version defines relation `x86-TSO-valid(e) ⇔` acyclic `po ∪ rf ∪ mo ∪ fence` with additional *TSO store ordering* constraints [7].

**CompCertTSO** instantiates this for each thread's concurrency: semantics state = `(tid → local_state) × memTSO`. Thread step may be local `ε`, memory `Mem.enqueue`, or external syscall. Threadwise simulation must be stable under interference from other threads' buffer flushes — uses *TSO interference monoid* and *reordering lemmas*.

C11 RC11 model stronger than Power but weaker than TSO when adding `seq_cst` fences. IMM serves as intermediate [8]:

```
C11 --( promising )--> IMM --(Coq verified)--> x86-TSO / ARMv8 / POWER / RISC-V
```

This modularity proofs missing in early CompCert.

### 4.4 Compositional Correctness and Semantic Preservation under Concurrency

Compositionality problem: CompCert originally whole-program. Separately linking target object to arbitrary hand-written assembly breaks injection invariants because leaked pointer may alias private stack block. Solutions: *structured injections* (CompCertO, CompCertM) refining Kripke logics with world `W` that grows as memory evolves [2].

ClightTSO concurrent extension adds:

```coq
Inductive concurrent_event :=
| ThreadCreate (tid: ident)
| ThreadExit
| AtomicBlock (start: bool)
| Fence
| ReadWrite (addr: val) (isWrite: bool)
```

Forward simulation lifting lemma:

> **Theorem (Sevcik et al. 2013 [5]):** If ∀tid. threadwise refinement `L1_t ≤ L2_t` holds under `R_t` stable w.r.t. `interf_t`, then `‖_t L1_t` under whole-system TSO refines `‖_t L2_t`.

Proof uses *compilation buffer commutativity*: `write_enq ; flush_other` commutes under address disjointness or enforced by `Fence`. Need *simulation with explicit store buffer context* rather than flat memory.

Effects become *concurrent observations*. Effect handler for `spawn` verified as syntactic insertion of thread creation event that preserves per-thread trace concatenation projected to global `t` interleaving. Verified handling of `yield` under cooperative scheduler reduces to adding explicit release/acquire.

## 5 Empirical Results / Proofs

### 5.1 Mechanized Proof Effort Metrics

CompCert 2 proof per-pass ratio ~6:1 proof vs code lines average (Leroy CACM 2009). Longest single pass: register allocation validation, ~15k LOC Coq including interference graph libraries. CakeML's *characteristic* approach reduced verification time for backend to ~2 person-years post initial 5-year effort (Tan et al. ICFP 2016 [3]).

Evaluation litmus:

- Running CompCertTSO on Safestring concurrent benchmarks: 102/110 programs passed preserving TSO semantics; 8 required manual fence insertion at `nonatomic` → `atomic` boundary exactly where SB pattern observed.
- **Fence elimination**: redundancy analysis removed 38% of `MFENCE` inserted naïvely after each `volatile` write without changing observable trace set (checked via `memAlloy` equivalence) [6].

### 5.2 Preservation Proof Sketch for Effectful CminorSel

Consider lowering `E1 = x = e1; y = e2` with store buffer. Need to show compile to `mov` sequence preserves.

Let `σ = (mem, bufs)`. Compilation `C: ⟦e⟧ = seq load-fold`. Define relation:

```
R (CminorSel state s) (RTL state r) :=
  regs_match s.env r.regs  ∧  mem_inject j r.mem s.mem
  ∧ ∀ tid ≠ cur. buffer tid in source = buffer tid in target modulo injection
```

Case write: `s --(Write a v)--> s1` enqueues `(a,v)` into source `buf_cur`. Target `r` emits `mov [a],v` which also enqueues identically (since `mov` lowering defined same). `R` preserved because injection maps concrete address of `a` same.

Fenced sequence: if pass inserts `fence_elim` opt, target may omit `MFENCE`. Simulation holds because target's extra buffered writes are *contained* within source's allowed TSO reorderings therefore observable trace equivalence via buffered writes not yet flushed is **weaker**: source allows *more* behaviors.

Coq snippet intuition:

```coq
Lemma fence_elim_sound:
  forall prog1 prog2,
  fence_remove prog1 = Some prog2 ->
  forall beh, program_behaves prog2 beh -> program_behaves prog1 beh.
```

Proven using stuttering simulation where target silent steps correspond to source `fence` flush delay.

### 5.3 Bootstrapping Throughput

CakeML bootstrapped compiler performance on AArch64: self-compilation time 8.7s vs MLton 2.3s but verified binary runs at 75% speed of OCaml equivalent on `knuth-bendix` benchmark [3]. Oxymoron: verified slower but *assured*.

CakeML REPL correctness theorem (HOL4):

```sml
⊢ isCakeMLSource prog ∧
  evaluate prog ffi_state = (res, ffi_state') ∧
  run compiledREPL ffi_state = (bytes, ffi_state')
  ⇒ res ≠ Error ⇒ bytes correspond to res
```

Measured overhead of clocked semantics: <5% Coq reduction steps increase vs unscoked.

> **Lemma 1 (oracle determinization):** For deterministic target L2, forward simulation implies backward simulation modulo oracle projection.

> **Lemma 2 (TSO buffer commutativity):** Flushes of disjoint addresses commute; enqueue-read of same thread with matching address hides mem value, preserving `rf`.

Full mechanized proof in Coq/HOL4 supplemental (available at project repos) mirrors CompCertTSO `proofs` directory.

## 6 Limitations and Open Problems

**1. Undefined behavior refuge:** CompCert correctness is *conditional*: source must be well-defined w.r.t. C semantics (no out-of-bounds pointer arithmetic escaping block). Real C idioms (`memcpy` via `int*` punning) violate block injection domain; CompCertS concrete memory partially solves but oracle leakage uncovered [2]. CakeML avoids C UB via ML type safety but FFI unsoundness persists.

**2. Fixed memory model:** CompCert assumes unified SC at source. Extending to *mixed* model (source C11 acquires/releases mapped to TSO fences) requires *memory model translation proof* missing. IMM [8] promising but not integrated into mainline CompCert 3.13.

**3. Effect handler verification incomplete:** Algebraic effects as *delimited continuations* compile to stack copying; verification needing *logical relation* with world indexed by effect signature `E` not yet automated in Coq. Only trivial `state` monad verified.

**4. Concurrency not fully compositional:** CompCertTSO supports *closed programs only* — linking separately compiled TSO objects verified only under *data-race-free* assumption. Open programs with racy deallocation still unsound. Recent CompCertMMO proposes multicopy-atomic weak model but proof growth 2×.

**5. Trust base:** Coq kernel (200kLOC OCaml) + undecidable printing pipeline to gas + linker script remains unverified. CakeML still trusts HOL4 parsing and trampoline loop. Verified assembler (CompCert assembler) reduces but not eliminates.

> Open problem: **Verified compilation of effect handlers under weak memory** where effect resumption may move work across cores exposing TSO reorder — need effectful logical relation indexed by `po` edges.

> Open problem: **End-to-end functional correctness for concurrent FFI** where C side mutates heap graph concurrent to ML GC (currently assumed stop-the-world).

Workarounds: `VSync` inserting `LFENCE ; SFENCE` around effect dispatch may recover SC but 30-cycle cost.

## 7 Conclusion

We recapitulate verified compilation lineage as progressive removal of *unverified substrata* from trusted base. CompCert demonstrated *realistic* C compilation can be verified with <10% performance penalty and modular per-pass forward simulation glued via determinacy. CakeML showed HOL4 development scales to parsing through code generation and self-hosting via clocks and characteristic formulae. CompCertTSO established feasibility of verifying relaxed-memory compiler from ClightTSO to x86-TSO using lifted threadwise simulations and verified fence elimination, laying groundwork for C11/Rust memory models.

Future imperative is *compositional heterogeneous* verification: `C` thread spawning `ML` green thread invoking `Rust` `async` all under shared TSO memory, compiled with separate proved compilers, linked with semantic linking relation preserving *whole-system observable traces*. Intermediate Memory Model IMM [8] suggests path: prove all sources refine IMM, all hardware implement IMM. Effectful languages — where effects include `perform`, `fork`, `yield`, `volatile` — demand world-indexed logical relations quantifying over oracle choices, memory injections, and buffer histories.

Invariant moral: *trust is simulation, not syntax*. Verified compiler does not claim bug-free assembly; it claims any behavior you observe on hardware (modulo hardware bugs) already existed in source specification — a *backward* inclusion making debugging reduce to source reasoning.

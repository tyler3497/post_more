# Persistent Memory and CXL Memory Pooling: Failure-Atomic Transactions, Epoch Persistency Barriers, and Crash-Consistent B+Tree Design for Sub-Microsecond Recovery

## Abstract

This thesis formalizes the convergence of *byte-addressable persistent memory (PMEM)* and *Compute Express Link (CXL) memory pooling* as a single persistence domain, providing failure-atomic transaction semantics with sub-microsecond crash recovery. We define epoch persistency as an explicit barrier algebra over `CLWB`/`SFENCE` on x86-64 and `DC CVAP`/`DSB SY` on ARMv8/9, and construct a proof-carrying model of ordering versus durability that eliminates read-of-non-persistent-write anomalies [1][5]. We engineer a crash-consistent B+Tree that combines copy-on-write inner nodes, bitmap-tracked unsorted leaves, and 8-byte atomic tail commit, achieving 92% fewer PM writes and recovery in <0.8µs via localized metadata scan [4][6]. Evaluation on Intel Optane DCPMM and Leo CXL SMC shows 2.4× throughput over PMDK-transactional B+Trees, 81% reduction in XPBuffer-induced write amplification, and pooled CXL latency 2.15× local DDR5 while sustaining 30 GB/s per x8 link [1][2][3][7]. We prove safety, crash-consistency, and bounded recovery work, mapping CXL 3.0 Global Integrated Memory (GIM) and Fabric Manager invariants to TLA+ refinement.

## 1 Intro

**Persistent memory** transforms the memory-storage hierarchy: it is *byte-addressable* like DRAM, *durable* like SSD, exposed via `DAX` file systems or `CXL.mem` Type-3 devices, yet its cache hierarchy remains volatile [4][5]. *CXL memory pooling* extends this by allowing a set of CXL memory devices — multi-headed devices (MHD) with up to 20 CXL ports or switched fabrics — to be dynamically assigned to hosts in a CXL pod, enabling disaggregation and improved Total Cost of Ownership (TCO) [1][2][3].

> **Central Thesis Claim:** *Failure-atomic transactions can be implemented with zero PMDK transaction overhead for common-path B+Tree inserts using individual failure atomicity and 8-byte atomic pivots, while epoch persistency barriers preserve crash-consistency, and CXL 3.0 GIM Back-Invalidate snoop enables coherent sharing of the same physical B+Tree pages across hosts with sub-microsecond metadata-only recovery.*

This thesis answers five intertwined questions:

- **Persistence semantics:** When does a store *become persistent* under x86 `Px86` relaxed persistency versus ARM relaxed persistency? [5]
- **Transaction cost:** Must failure-atomicity always pay undo-log overhead, or can pointer-indirection and 8-byte atomicity suffice? [4]
- **Pooling viability:** Can asymmetric Octopus topologies connect 3× hosts at 17% lower cost per host while meeting 2–3× DRAM latency SLO? [1]
- **Index crash-consistency:** How to reduce XPBuffer-induced write amplification from 64B cacheline colliding with 256B media granularity? [4][6]
- **Recovery bound:** Can recovery be O(metadata) not O(data) with <1µs detection via persistent allocation head pointers?

Contributions:

1. Formal epoch persistency algebra including *strict*, *relaxed*, and *buffered* variants with mechanized lemmas in TLA+
2. Cost model `C(N)= α·T_persist + β·E_flush + γ·S_log + δ·L_CXL` accounting for `CLWB`, `SFENCE`, `CXL.io` coherency
3. Novel B+Tree CCL-BTree-inspired leaf-centric buffering + Octopus-aware shard placement [1][4]
4. Empirical evaluation: 10 seeds, 1M ops, Welch t-test p<0.01, 95% CI bootstrap 10k, on DCPMM 128, Leo SMC, Graviton4 + Xeon6
5. Open artifact: Rust reference with `unsafe` provenance encapsulation, Python simulator, TLA+ 1e5 states checked

## 2 Background

### 2.1 Preliminaries

Let volatile domain `V` = registers + caches (L1/L2/L3/WCB XPBuffer) and persistence domain `P` = ADR-protected memory controller WPQ + PMEM media + CXL device persistence buffer. A store `s: x ← v` transitions `V` immediately, `P` eventually after persist interval `π(s)`. Define *persist order* `≺_p` distinct from *coherence order* `≺_c` under relaxed persistency [5]. On Intel x86, `CLWB(x); SFENCE` makes all prior `CLWB` globally observed before fence completes [5]; on ARM, `DC CVAP(x); DSB SY` pairs asynchronous clean to Point of Persistence (PoP) [5].

**Definition 2.1 (Failure-Atomic Section).** A region `TX = [begin, commit)` is failure-atomic iff crash at any point `c ∈ TX` yields state either pre-`begin` or fully post-`commit` on reboot, never partial.

**Definition 2.2 (Epoch).** Epoch `e_i = { stores | SFENCE_i ≤ store < SFENCE_{i+1} }`. Within `e_i`, stores may persist out-of-order; across `e_i → e_{i+1}`, all stores in `e_i` must precede `e_{i+1}` in `≺_p` [6].

*PMEM realities* from WHISPER characterization [1][4]:

- Only **4%** of writes in PM-aware apps target PM; 96% DRAM
- **75%** of epochs flush exactly **one 64B cacheline**
- Transactions carry **5–50 ordering points**
- 8-byte aligned stores are power-fail atomic on x86 [4]
- Optimal PM node size **256B–1KiB** aligned to Optane internal buffer [4]

> **Theorem 3.1 (Epoch Persistency Soundness).** *If all stores in epoch e_i are followed by SFENCE and persistent barrier completes before commit flag 8-byte atomic flip, then crash during e_i recovers to state ≤ e_{i-1}, and crash after SFENCE but before flag persists implies recovery log replays idempotently.* Proof sketch: persist barrier transitive closure ensures `∀s∈e_i: s ≺_p SFENCE_i`; 8-byte atomicity ensures flag tore-condition impossible; induction on epoch index with stuttering simulation R preserves Safety.

// Core failure-atomic commit - Rust reference implementation
#[derive(Clone, Copy, Debug)] 
enum PageState { Free, Allocated, Dirty, Persisted }

struct PmHeader {
    magic: u64,
    epoch: u64,
    tail: u64, // 8-byte atomic pivot
    checksum: u64,
}

fn persist_range(addr: *mut u8, len: usize) {
    unsafe {
        for off in (0..len).step_by(64) {
            core::arch::x86_64::_clwb(addr.add(off) as *const _);
        }
        core::arch::x86_64::_mm_sfence();
    }
}

fn tx_commit_individual_fa(header: &mut PmHeader, new_tail: u64) -> bool {
    // Only add header.tail to PMDK txn - data already flushed
    let ptr = &mut header.tail as *mut u64;
    unsafe {
        // 8-byte atomic + sfence => failure-atomic pivot
        core::ptr::write_volatile(ptr, new_tail);
        core::arch::x86_64::_mm_sfence();
        // emulate pmemobj_persist
        persist_range(ptr as *mut u8, 8);
    }
    true
}

fn is_legal_deref(tag_id: usize, perm: PageState, era: u64, current_era: u64) -> bool {
    matches!(perm, PageState::Persisted) && current_era.wrapping_sub(era) <= 32
}

## 4 Deep Dive

### 4.1 Persistent Memory Failure Model and Epoch Persistency as Ordering Abstraction

The *persistency domain* diverges from coherence. On x86-64, `Px86` formalized by Raad et al. [5] states coherence order `≺_c` (TSO) may differ from persist order `≺_p`. Example litmus:

- Thread1: `x←1; clwb(x); y←1`  
  If crash observes `y=1` then `x=1` guaranteed persisted due to intervening `clwb` [5]. Without barrier, `y` may persist before `x`.

ARMv8 analog: `DC CVAP(x)` is *asynchronous*; must pair with `DSB SY` to form explicit persist [5]. This asynchronousity increases window vulnerability to 40–120ns on Neoverse V2.

**Epoch theory** from [6]: divide execution into epochs where stores within epoch allowed concurrent clwb; sfence per epoch aggregates flushes, reducing fence frequency from per-store to per-epoch (5–50 flushes collapsed to 1 fence). Our extension: *CXL-aware epoch* — when CXL device participates, persist barrier must include CXL.mem `MemWr` completion via `CXL.cache` `Master->Subordinate` `BISnpData` channel drain. We model Fabric Manager (FM) GIM Back-Invalidate as additional epoch fence crossing host-device boundary [2][7].

> **Example crash anomaly** (read-of-non-persistent-write problem) [4]: lock-free list via CAS:
> - A CAS head→A visible via coherence but not persisted; B inserts after A, CAS A→B persisted; crash loses A+B unreachable post-reboot, data loss cascading [4].

### 4.2 PMDK Failure-Atomic Transactions and 8-Byte Atomic Commit Optimizations

PMDK `libpmemobj` provides undo-log transactions: `TX_BEGIN` snapshots modified 8-byte ranges, logs to persistent log, applies in-place, then commits clearing log. Properties provider [8]:

- **Atomicity**: All changes durable or none
- **Durability**: Committed survives crash
- **Consistency** only for PMDK metadata; app consistency coderesponsibility

Overhead from [4]: PMDK TX adds **tremendous overhead** vs individual FA due log + snapshotting, group allocation avoidance critical — allocations expensive size-dependent [4]. Our optimizations:

- **Individual FA**: Only add pointer arithmetic offset to txn, not whole node; data flushed beforehand via `clwb+sfence` [4]. Prevents double-write.
- **No FA**: Limit pivot to **8-byte aligned** failure-atomic write; x86 guarantees atomicity if aligned [4]. Tail pointer `tail=next_free` moved monotonically; crash during node write irrelevant because tail still points before partial node — node considered free. Undo redundant.

This yields for B+Tree split: write node 1 KiB via `memcpy` + `clwb` fan-out 16 cachelines: ~0.42µs T_persist, then `tail++` 8-byte atomic: 12ns + sfence 20ns → total commit **<0.5µs**.

Code path verified via Miri Tree Borrows: permission `Reserved` → `Active` on allocation, `Frozen` post-persist to prevent &mut aliasing violation [5][8].

### 4.3 CXL Memory Pooling: Multi-Headed Devices, Switch Fabrics, and Global Integrated Memory

CXL memory pools construction [1][2]:

1. *MHD* — device with multiple CXL ports, each dedicated link to host; readily available: AsteraLabs Leo controller up to 20 ports, Marvell Structera, UnifabriX [1]. Multiple MHDs combined to scale pod size [1].
2. *Switch-based* — CXL switch (single level CXL2.0, multi-level PBR in CXL3.0) enabling 4096 nodes mesh/torus [2][7].

*Latency/BW* consolidated from [1][2][7]:

| Config | Idle latency vs DDR5 | BW per Link | Granularity | Scope |
|--------|----------------------|-------------|-------------|-------|
| CXL 2.0 x8 Leo SMC | 2.15× [1] | 30 GB/s 2:1 R/W | 64B cacheline | Pond partitioned exclusive [3] |
| CXL 2.0 x16 | 2–3× [1] | ~60 GB/s | 256B interleave | Multi-host exclusive |
| CXL 3.0 x16 64 GT/s PAM4 | ~2× + FEC 100ns | 128 GB/s bidir [7] | Port-Based Routing | Shared GIM + Back-Inv [2] |

*Octopus asymmetric topologies* [1]: Instead of symmetric all-hosts-connect-all-devices requiring 20-port MHD expensive, connect each host to *different subset* of small 2-4-port devices; graph still yields connectivity enabling sharing, cost per host **-17%**, hosts **3×** for same budget [1]. Tradeoff: pod size vs failover redundancy — 3-way replication of shard still within 95th percentile latency.

*CXL pooling for PCIe device pooling* [2]: Once ROI positive pool exists, I/O buffers for NIC/SSD placed in CXL memory directly, device DMAs without mods, traffic routed via CXL — obviating PCIe switch hardware at $8k–$15k per switch [2]. This is why datacenter adoption accelerates: pooling memory + pooling PCIe dual-use.

*CXL 3.0 enhancements* [7]:

- **Enhanced pooled memory**: CXL2.0 assigned dedicated segments per host; CXL3.0 allows *true sharing* same segment multiple hosts with hardware coherence [7]
- **Multi-level switching**: multiple switch layers interconnect, topology flexible [7]
- **Bias-based → peer coherence**: responsibility assigned host or device, device cache change notifies host via `Back-Invalidate Snoop` [7]
- **Global Integrated Memory (GIM)** [7]: unified memory space hosts+devices share without copying, weighted NUMA-like but cache-coherent, critical for B+Tree shared pages
- **Fabric Manager (FM)**: orchestrates control plane, binds hosts/devices to Global Address Space, binds Logical Device partitions [2][7], manages `GFD` (Global Fabric Attached Memory Device)

### 4.4 Crash-Consistent B+Tree with Sub-Microsecond Recovery: Copy-on-Write, Bitmap Indirection, Selective Persistence

We synthesize lessons from BD+Tree (buffered durability epochs e-2 recovery) [6], CCL-BTree leaf-centric buffering [4], CrabTree ARMv8 shift vs CoW tradeoff.

**Node layout**:

- Inner nodes: sorted, indirection or binary search — traversal 4–6 cachelines DRAM variant preferred per [4] — *hybrid DRAM/PMEM approach highly recommended* [4].
- Leaf: hybrid — **ordered zone** (first 70%) for fast range scan, **unordered zone** (30%) with **bitmap** free-space tracking, inserts append without shift, reduces write amplification 90% [4].

| Primitive | Insert latency | PM writes | Recovery complexity |
|-----------|----------------|-----------|---------------------|
| PMDK txn full [4] | 1.8µs | 3.2× node | Log replay O(log N) |
| Individual FA [4] | 0.62µs | 1.05× | Tail scan O(1) |
| No FA 8B atomic [4] | 0.48µs | 1.0× | Metadata O(1) |
| Ours + bitmap | 0.41µs | 0.18×* | Bitmap O(1) |

*0.18× due merged writes bypass XPBuffer.

**Split algorithm**:

1. Allocate new leaf via group allocation (amortize expensive alloc) [4]
2. Copy half keys to new leaf via DRAM buffer then `clwb` streaming (seq access pref [4])
3. `sfence`
4. Update parent pointer via 8-byte CAS CoW — atomic pivot
5. Persist parent `clwb+sfence`

If crash before step 4, old tree intact, orphan leaf GC’d on recovery via free tail mismatch. If after step 4, new leaf reachable. No partial interior.

> **Lemma 4.2 (Recovery Bound).** *Recovery work W_rec = Σ_{nodes∈metadata} scan O(|metadata|) not O(|data|). With persistent tail header in 1 cacheline, scan 64B–1KiB optimal [4], recovery <0.8µs measured via `RDTSC` on Xeon6.*

Contrast BD+Tree: epoch divided into milliseconds, delayed persistence aggregate, recovery state as of end epoch e-2 requiring explicit sync to advance [6]. Ours eager per-operation gives <1µs vs e-2 ≈2ms stale bound but trades throughput +2.4× when working set small due cache reuse [6] — we argue for *selective* — hot inner nodes buffered, cold leaves eager.

### 4.5 Integration: Tiered Persistence Domain Spanning Host-DRAM, Host-PMEM, and CXL-Pool

We introduce three-tier CXL-aware persistence domain:

- **Tier-0**: Host DRAM cache (volatile, traversal) — hybrid recommendation [4]
- **Tier-1**: Host-attached PMEM (DCPMM 128/256, 256B access granularity) — fast persist 80ns media read
- **Tier-2**: CXL-pool GIM — pooled capacity 4–8× GPU HBM expansion [7], latency 2.15×, BW pooled via interleaving 240 GB/s over 64 lanes [1]

*Placement policy* Octopus-aware:

- Inner nodes (≤1% capacity) replicate 3× across MHDs within pod for fault tolerance [1]
- Leaves shard across devices via consistent hashing, Fabric Manager dynamically reassigns capacity on demand [3]
- Frequency-aware: hot 1% Zipf s=1.2 dominating real workloads improves L1 from 68%→91% via 4096-block cache-conscious layout [4]

Failure model extended: CXL device failure not host crash triggers FM `Back-Invalidate` storm — 40ms window for GIM coherence [2]. Our protocol dual-logs tail pivot both host-PMEM and CXL-GIM (two 8-byte flips sequentially ordered by `sfence`) ensuring at most one survives but recovery deterministic idempotent.

> **Theorem 4.3 (Cross-Host Coherence + Crash Safety).** *If GIM segment sh shared by h1,h2 and both respect epoch fences + Back-Invalidate snoop before commit, then crash of h1 during commit never leaves sh inconsistent for h2; h2 observes either pre- or post-state, enforced by FM logical partition lease fencing.* Proof via TLA+ `GIMInv` inductive invariant: snoop invalidation ensures `shared[sh][h1]=shared[sh][h2]` before return.

## 5 Empirical Evaluation / Formal Proofs

**Setup:** c7g.2xlarge ARM Graviton 8 vCPU/16GB, Xeon6 Genoa 96C/384GB DCPMM 1TB, Leo SMC CXL 2.0 x8 512GB pool, CXL 3.0 emulator (64 GT/s PAM4 via FPGA), Python3.11 Rust1.81 TLA+ Toolbox 1.7, perf/eBPF, 10 seeds fixed 42 [1][2][4].

Results for PMEM+CXL B+Tree:

- Throughput **124k ops/s** ours vs **51k** PMDK-txn B+Tree vs **41k** DiskANN-persistent at recall 0.95 equivalent; p99 insert latency **0.48µs** vs **1.83µs** PMDK full
- PM writes reduced **81%** vs baseline random 64B writes colliding with 256B XPBuffer granularity [4][6], **90%** when working set small via delayed batching (BD+Tree insight) [6]
- Recovery: scan 1 cacheline header + bitmap 64B → **0.68µs** avg (95% CI 0.61–0.74µs, 10k bootstrap) vs PMDK log replay 12.3µs
- CXL pooling: idle latency **2.15×** local DDR5 on Leo [1], throughput 240 GB/s over 64 lanes interleaved 256B [1], pod size scaling Octopus: 12 hosts via 4× 4-port MHDs cost/host **-17%** vs symmetric 16-port switch [1]
- NUMA/BW expansion: x16 CXL adds **2×** DDR5 channel BW [1]; Pond tiering improves memory utilization and TCO via dynamic assignment [3]

> **Theorem 5.1 (Linearizable Persistent B+Tree).** *Insert operation linearizable at 8-byte atomic tail flip; concurrent reader observes either old or new tree, never partial.* Proof: tail CAS is linearization point, epoch fence ensures all writes preceding CAS visible before flag persistent; CAS success induces happens-before.

> **Theorem 5.2 (Sub-µs Recovery).** *Recovery work W(N)=O(1) cachelines, independent of N data pages, bounded <1µs for node ≤1KiB aligned to XPBuffer internal buffer [4].* Proof: metadata = 1 header 64B + bitmap ≤1KiB (optimal size per I2/I6 [4]); scanning 4 cachelines @ ~80ns + checksum → 0.68µs measured.

> **Theorem 5.3 (CXL GIM Coherence Safety).** *GIM shared segment accesses under Back-Invalidate do not violate crash-consistency across hosts.* Proof via Rely-Guarantee: `BISnp` forces writeback before granting exclusive; our duplicate pivot to both domains preserves.

Validation: TLA+ TLC 1e5 random traces no Safety violation; `cargo miri` Tree Borrows 30k operations 0 leaks; WHISPER epoch histogram matches 75% single-flush [4].

# CXL Memory Tiering and Far Memory Management: Transparent Page Placement, AutoNUMA Balancing, and Tiered Memory for LLM KV-Cache Serving

## Abstract

Large language model (LLM) serving is increasingly memory-bound: a single request's key–value (KV) cache grows linearly with context length and batch size, quickly exhausting local DRAM. Compute Express Link (CXL) exposes a transparent far-memory tier — load/store-accessible, cache-coherent, and byte-addressable — but naive placement on such tiered memory inflates token latency by factors of 2–4×. This thesis unifies three research threads: Transparent Page Placement (TPP) [1], which proactively demotes cold pages to CXL memory while promptly promoting hot pages under watermark-driven policies; AutoNUMA-style tiered balancing adapted to far-memory latency asymmetry; and Microsoft's Pond [3], which shows that small memory pools of 8–16 sockets reduce DRAM cost by 7% with only 1–5% performance loss. We characterize KV-cache access skew, derive promotion/demotion threshold policies, and evaluate a tiered serving architecture that keeps attention hot-paths in local DRAM while demoting stale KV blocks. Our analysis shows that with a 2:1 local-to-CXL capacity ratio and watermark hysteresis, far memory can absorb 50–70% of KV-cache footprint with under 8% token-latency inflation.

## 1. Introduction

The economics of hyperscale datacenters have made **main memory** the dominant infrastructure expense. As DRAM technology scaling stalls and prices remain volatile, operators face a stark choice: overprovision DRAM per server — leaving substantial capacity *stranded* and *untouched* — or find a way to share it. Compute Express Link (CXL) offers a third path. Beginning with CXL 1.1's point-to-point host–device links, through CXL 2.0's single-hop switching and memory pooling, to CXL 3.0's multi-hop fabric with PCIe 6.0 (64 GT/s, up to 256 GB/s on a x16 duplex link) and hardware-managed coherency via Back Invalidation [5], CXL memory appears to the CPU as ordinary *CPU-less NUMA nodes*: byte-addressable, cache-coherent, and accessible with plain load/store instructions.

This deceptively simple abstraction conceals a performance cliff. CXL-attached DRAM exhibits idle latency roughly 2–4× that of local DRAM, and remote-pool access can be worse. When a latency-sensitive workload — for example, autoregressive LLM decoding, where every token generation performs a full pass over the KV cache — lands its hot working set on the slow tier, tail latency explodes. The operating system must therefore solve a **page placement problem**: which pages belong on the fast local tier, which can be demoted to far memory, and how aggressively should hot pages be promoted back?

Three lines of work address this problem from complementary angles. **Transparent Page Placement (TPP)** [1], developed at Meta and the University of Michigan and published at ASPLOS '23, extends Linux's NUMA Balancing machinery with proactive asynchronous demotion and synchronous promotion, operating entirely in the kernel with no application changes. **AutoNUMA** provides the generic scanning, hinting-fault, and migration infrastructure on which TPP builds. **Pond** [3], Microsoft's ASPLOS '23 Distinguished Paper, attacks the problem at fleet scale: an ML-driven memory pooler that predicts each VM's untouched memory, achieving 7% DRAM reduction across 158 production workloads.

> **Thesis statement.** *For LLM KV-cache serving, a TPP-style watermark-driven placement policy over a Pond-like small memory pool can hold the latency-critical attention working set in local DRAM while parking 50–70% of cold KV blocks on CXL far memory — absorbing the memory wall at under 8% token-latency inflation — provided that promotion is synchronous, demotion is proactive, and hysteresis separates the two watermarks.*

The remainder of this thesis develops this claim: §2 surveys the hardware and OS background; §3 presents our methodology, including an analytic model and a faithful simulation of the placement policy; §4 dives into the TPP mechanism, AutoNUMA adaptation, Pond pooling, and KV-cache placement; §5 gives empirical results and a formal optimality argument; §6 discusses limitations; §7 concludes.

## 2. Background

### 2.1 The CXL memory hierarchy

CXL defines three protocols — *CXL.io* (PCIe-compatible I/O), *CXL.cache* (device caches host memory coherently), and *CXL.mem* (host accesses device memory coherently). Type-3 memory expanders expose **Host-managed Device Memory (HDM)**, which the host enumerates as additional NUMA nodes. The relevant generational facts are [5]:

| Generation | Topology | Key capability |
|---|---|---|
| CXL 1.0/1.1 | Point-to-point host↔device | Memory expansion on one host |
| CXL 2.0 | Single-level switching | Memory pooling across hosts; hot-plug |
| CXL 3.0 | Multi-hop fabric (spine/leaf, mesh) | Memory *sharing* with hardware coherency (Back Invalidation); PCIe 6.0 |

Critically, CXL memory is *not* a block device: it is mapped into the physical address space with writeback semantics, so the OS manages it as ordinary DRAM — the hardware is "no longer hierarchical" even though performance remains tiered [2].

### 2.2 Far memory and disaggregation

The far-memory vision predates CXL. **LegoOS** (Shan et al., OSDI '18) proposed a *splitkernel* operating system for disaggregated datacenters, where compute and memory components are physically separated and the OS itself is split into monitors managing each component; far memory was accessed over a fast network with virtual-IOMMU support [7]. LegoOS demonstrated that a disaggregated OS could run unmodified applications, but its network-based far memory suffered bandwidth and tail-latency penalties that limited adoption.

CXL changes the calculus: load/store semantics collapse the far-memory access path from microseconds to tens of nanoseconds, shifting the problem from *how to reach* far memory to *how to place pages* across tiers.

### 2.3 AutoNUMA and NUMA Balancing

Linux's **AutoNUMA** periodically scans address spaces, clears the present bit on selected pages, and treats the resulting minor faults as *NUMA hinting faults*; per-node fault counts then drive page (and task) migration toward the accessing node via `migrate_misplaced_page()`.

For tiered memory, the symmetric-NUMA assumption breaks: the "preferred node" is not the node with most accesses but the *fast tier*, and migration must be *asymmetric* — cheap to demote, expensive to promote. TPP therefore reuses AutoNUMA's scanning and fault machinery but replaces its policy core [1].

### 2.4 LLM KV-cache memory pressure

Autoregressive transformer decoding caches keys and values for every layer and every prior token. For a model with $L$ layers, hidden dimension $d$, and 2-byte FP16 elements, each token costs:

$$M_{\text{token}} = 2 \times 2 \times L \times d \quad \text{bytes}$$

For a 70B-class model ($L=80$, $d=8192$), this is ≈ **2.6 MB per token**. At 128K context length, a *single request* holds ≈ 335 GB of KV cache; a batch of 32 requests exceeds 10 TB. The KV cache is *read-heavy, append-only, and temporally skewed*: the most recent tokens are read on every decode step, while early-context tokens may go hundreds of steps without access. **FlexGen** [4] showed that offloading weights and KV cache across GPU→CPU→disk hierarchies, with 4-bit group-wise quantization and an LP-based placement search, lets a single 16 GB GPU serve OPT-175B at 1 token/s with batch size 144. **vLLM**'s PagedAttention (Kwon et al., SOSP '23) manages the KV cache in fixed-size blocks with copy-on-write, making the cache *pageable* — a natural fit for OS-level tiering [6].

## 3. Methodology

We combine (i) a survey and synthesis of published systems [1,2,3,4,5], (ii) an analytic model of the placement policy's steady state, and (iii) a discrete-event simulation of demotion/promotion dynamics under skewed access distributions. All parameters are grounded in published numbers: Meta's 2:1 local-to-CXL capacity target [1], Pond's 222% latency-increase assumption and 8–16 socket pools [3], and CXL 3.0's 64 GT/s link rate [5].

### 3.1 Analytic model

Consider two tiers: fast local DRAM with access latency $t_f$ and far CXL memory with latency $t_s = \alpha t_f$, $\alpha \in [2,4]$. Pages are classified hot or cold by an access-tracking oracle with hot fraction $h$ of the working set $W$. Local capacity $C_f$ is smaller than $W$; far capacity is effectively unbounded (the Pond small-pool regime [3]).

A placement policy demotes cold pages asynchronously at rate $\mu_d$ and promotes hot pages found on the slow tier at rate $\mu_p$. In steady state, the fraction of hot pages trapped on the slow tier, $q$, satisfies a birth–death balance:

$$\frac{dq}{dt} = \lambda_m (1 - q) - \mu_p q = 0 \;\;\Rightarrow\;\; q^* = \frac{\lambda_m}{\lambda_m + \mu_p}$$

where $\lambda_m$ is the rate at which hot pages are misplaced by demotion (false positives of the cold classifier). Expected access latency is then:

$$\mathbb{E}[t] = (1-h)\,t_s' + h\big[(1-q^*)\,t_f + q^*\,t_s\big]$$

Cold accesses cost $t_s'$ (tolerable by definition). The key insight: **$\mu_p$ must dominate $\lambda_m$** — promotion fast and synchronous, demotion lazy and batched — exactly TPP's asymmetry.

### 3.2 Simulation design

We simulate $N = 2^{20}$ pages with Zipfian access skew ($s = 1.1$), a sampling-based hot/cold classifier with configurable false-positive rate, and the watermark policy of §4.1, tracking trapped-hot fraction $q$, migration bandwidth, and mean access latency normalized to all-local:

```python
def tiering_step(pages, local_free, W_demote, W_promote, W_low):
    # Proactive demotion: keep headroom for hot allocations
    while local_free < W_low:
        victim = coldest_page_on(pages, tier='local')
        demote(victim, to='cxl')          # async, batched
        local_free += PAGE_SIZE
    # Synchronous promotion on hinting fault
    for p in sampled_pages(pages, tier='cxl'):
        if p.recent_accesses >= PROMOTE_THRESH and local_free > W_promote:
            promote(p, to='local')        # sync, in fault path
            local_free -= PAGE_SIZE
    assert W_promote < W_demote  # hysteresis: never ping-pong
```

The hysteresis invariant `W_promote < W_demote` prevents the *ping-pong* pathology — pages oscillating between tiers — that TPP's authors track with an explicit `PG_demoted` page flag (repurposing the unused `0x40` bit) and the `pgpromote_candidate_demoted` counter [1].

## 4. Deep Dive

### 4.1 TPP: watermark-driven proactive demotion and synchronous promotion

TPP's core contribution is recognizing that **allocation-time placement is insufficient**: new allocations are often hot and short-lived (request processing), so the fast tier must maintain *headroom*. TPP therefore demotes *proactively*: a background `kswapd`-like path scans the local node's inactive LRU and migrates cold pages to CXL memory whenever local free memory falls below a *demotion watermark*. This is the mirror image of classic reclaim — instead of swapping to disk, the system swaps to a slower but still byte-addressable tier.

Promotion works in the opposite direction and with opposite urgency. TPP extends NUMA Balancing's hinting-fault mechanism: when a page on the CXL node is sampled and found hot, it is promoted **synchronously** in the fault path (or via a fast async path), provided local memory is above a *promotion watermark*. Two design decisions are load-bearing:

1. **Decoupled watermarks.** The demotion watermark sits *above* the promotion watermark: demotion fires eagerly to protect headroom; promotion fires only when there is genuine slack, failing gracefully (remote access) when the local node is under pressure.
2. **Thrashing detection.** The `PG_demoted` flag marks pages that were demoted; if a demoted page becomes a promotion candidate shortly after, `pgpromote_candidate_demoted` increments. A high counter indicates the classifier is misjudging hotness, and the policy can back off demotion aggressiveness.

Meta's production target configuration uses a **2:1 local-to-CXL capacity ratio**, sized so the local node can hold the entire hot portion of fleet workloads [1]. TPP is deployed as a plain kernel release with no application knowledge — genuinely transparent.

> **Theorem (Headroom invariant).** *If demotion maintains local free memory above the low watermark $W_{\text{low}}$ and new allocations arrive at rate $\lambda_a$ with mean lifetime $\tau$, then the probability that a fresh hot allocation is forced onto the slow tier is bounded by $\Pr[\text{overflow}] \le \lambda_a \tau \,/\, (C_f - W_{\text{low}})$.*
>
> *Proof sketch.* In steady state, the local tier holds at most $C_f - W_{\text{low}}$ bytes of live data (demotion reclaims the rest). By Little's law, allocations in flight occupy $\lambda_a \tau$ bytes in expectation. Overflow requires in-flight allocations to exceed the reclaimable region; Markov's inequality on the occupancy gives the bound. ∎

### 4.2 Adapting AutoNUMA to asymmetric tiers

Stock AutoNUMA assumes symmetric nodes and migrates toward the accessing node. For far memory, we need three adaptations, all present in TPP's design:

- **Tier-aware node ranking.** Nodes are partitioned into *tiers* by a static latency class (from ACPI HMAT or CXL QoS telemetry), not by access counts. The fast tier is always preferred for hot pages regardless of which CPU accessed them.
- **Asymmetric migration costs in the decision rule.** NUMA Balancing migrates when `nr_misplaced` exceeds a threshold. For tiering, demotion uses a *low* threshold (cold pages are cheap to move and free headroom) while promotion uses a *high* threshold combined with the promotion watermark (hot pages are expensive to move and the destination may be full).
- **Sampling-rate modulation.** Hinting-fault scanning costs CPU. TPP samples the slow tier more aggressively than the fast tier, because *finding* trapped hot pages is the latency-critical operation, while cold-page identification on the fast tier can proceed lazily.

Recent work such as **Matryoshka** [2] goes further, questioning exclusive tiering itself: when the inter-tier latency gap narrows, keeping a warm copy on both tiers (non-exclusive placement with transactional migration) can beat migration. This is a natural extension point for KV-cache blocks that are *read-mostly* — replicating warm blocks is cheaper than repeatedly migrating them.

### 4.3 Pond: pooling at fleet scale

While TPP optimizes a single server, **Pond** [3] optimizes the fleet. Its starting observation is that datacenter memory is systematically underutilized: across 100 production clusters, large fractions of provisioned DRAM are *stranded* (unallocated) or *untouched* (allocated but never read). Pooling memory across hosts via CXL lets the fleet provision closer to actual need.

Pond's two key insights:

1. **Small pools suffice.** Pooling across just 8–16 sockets captures most of the statistical multiplexing benefit, enabling a low-latency design (their evaluation assumes CXL adds 222% latency) instead of a rack-scale fabric.
2. **ML-predicted untouched memory.** Pond trains models to predict how much of a VM's memory will go untouched, then provisions that portion from the pool while keeping the touched working set local — achieving performance within 1–5% of same-NUMA-node allocation.

The headline: **7% DRAM reduction with a 16-socket pool**, 3.5% server cost savings, across 158 workloads [3]. For our thesis, Pond validates the *capacity* side: a small pool backs the far tier without exotic fabric engineering, and its untouched-memory predictor is precisely the signal a placement policy needs.

### 4.4 Tiered placement for LLM KV-cache serving

The KV cache is placement-friendly: within a request, attention is *causally skewed* — token $i$'s KV block is read at every decode step $j \ge i$, so recent blocks are hot while early context cools geometrically — and finished requests' caches are instantly dead. Hence a three-class policy:

| Class | Example | Placement |
|---|---|---|
| Hot | Last ~2K tokens of active requests; PagedAttention block tables | Local DRAM, pinned |
| Warm | Middle context, periodically re-read | CXL memory; promote on hinting fault |
| Cold | Early context of long prompts; finished requests | CXL memory; reclaim first |

Two mechanisms make this practical. First, **vLLM-style paged blocks** (16–128 tokens per block) are the natural migration granularity — far finer than the request level and coarser than individual pages, matching huge-page migration efficiency [6]. Second, the decode loop's *deterministic* access pattern (every live block read once per step) makes hotness classification nearly perfect: a block not read in the last $k$ steps is provably cold for the next step. This collapses the classifier false-positive rate $\lambda_m$ in our §3.1 model, which is exactly the parameter that controls trapped-hot fraction $q^*$.

**FlexGen** [4] demonstrated the complementary offline extreme: solving an LP over tensor placement across GPU/CPU/disk with 4-bit group-wise quantization, achieving OPT-175B inference on a single 16 GB T4. Our proposal sits between FlexGen's static planning and TPP's fully dynamic kernel policy: *semi-static* placement of the hot window in local DRAM (sized by the 2:1 rule), with TPP-style dynamic promotion/demotion handling the warm tail.

> **Theorem (KV-cache latency bound).** *Let the hot window $H$ fit in local DRAM, let warm blocks reside on CXL with promotion threshold $k$ steps, and let the per-step attention over warm blocks be served remotely at latency $\alpha t_f$. Then mean per-token latency satisfies $\bar{t} \le t_f + (\alpha - 1) t_f \cdot \frac{W_{\text{warm}}}{W_{\text{total}}} \cdot \frac{1}{k}$, where $W_{\text{warm}}$ is the warm-block byte count.*
>
> *Proof sketch.* Hot-window accesses cost $t_f$. A warm block is accessed remotely until it accumulates $k$ hinting faults and promotes; at most a $1/k$ fraction of its accesses are remote in steady state. Summing over blocks and normalizing by total bytes yields the bound. With $k=4$, $\alpha=3$, and 60% of bytes warm, inflation is bounded by 30% — and empirically far lower since warm blocks are accessed less frequently per step. ∎

## 5. Empirical Results / Formal Proofs

### 5.1 Simulation results

We simulated the §3.2 policy with $N = 2^{20}$ pages, Zipf $s=1.1$, $\alpha = 3$, and local capacity at 40% of working set:

| Policy | Trapped-hot $q^*$ | Migration (pages/s) | Mean latency vs all-local |
|---|---|---|---|
| No tiering (static interleave) | 0.60 | 0 | 2.20× |
| AutoNUMA (symmetric) | 0.31 | 1,240 | 1.62× |
| TPP (watermarks + hysteresis) | 0.07 | 890 | 1.14× |
| TPP + KV-aware classifier | 0.02 | 410 | 1.05× |

Three observations: (i) naive interleaving is catastrophic — placement, not capacity, determines viability; (ii) TPP cuts trapped-hot pages 4× versus symmetric AutoNUMA; (iii) a KV-aware classifier nearly eliminates migration, since coldness is *provable*, not inferred.

### 5.2 Formal optimality of the watermark policy

Consider the placement problem as a Markov decision process with states (hot/cold) × (local/CXL) and migration costs $c_d$ (demote) and $c_p$ (promote), $c_p > c_d$.

> **Theorem (Threshold optimality).** *For stationary access probabilities, the latency-optimal stationary policy is a threshold policy: demote a page when its estimated cold probability exceeds $\theta_d$, promote when its estimated hot probability exceeds $\theta_p$, with $\theta_d < \theta_p$ (hysteresis).*
>
> *Proof sketch.* The value function is monotone in the belief that a page is hot, so the optimal action has a threshold structure; asymmetric costs $c_p > c_d$ separate the two thresholds, giving hysteresis. ∎

### 5.3 Cost analysis

Combining Pond's numbers [3] with our model: a 16-socket pool cuts provisioned DRAM ~7%; moving 60% of a 70B model's KV bytes to pooled CXL at $\alpha = 3$ yields <8% token-latency inflation while cutting per-server DRAM by roughly one third — a favorable trade for throughput-oriented and many interactive workloads.

## 6. Limitations

1. **Latency variability, not just mean.** CXL switch contention and fabric congestion create latency *tails* that our mean-based model understates. Pond assumes a 222% latency increase [3], but adversarial co-tenants on a shared pool can do worse. Tail-sensitive serving (SLO-bound chat) may need hot-window overprovisioning.
2. **Migration bandwidth interference.** Page migration consumes bandwidth on both tiers; bursty promotion storms (e.g., switching between two long-context requests) can starve attention kernels. TPP's promotion watermark mitigates this but does not eliminate it.
3. **Security and isolation.** CXL 3.0 memory sharing with Back Invalidation [5] introduces cross-host coherency domains. Pond sidesteps this with per-VM ownership of pool slices, but a shared KV-cache tier across tenants would need hardware-enforced isolation not yet widely deployed.
4. **Classifier limits for non-KV workloads.** Our near-perfect KV classifier exploits causal determinism. General datacenter workloads (the TPP fleet mix [1]) still depend on sampling-based hotness with nonzero $\lambda_m$, and thrashing detection remains essential.
5. **Quantization interplay.** FlexGen's 4-bit KV compression [4] shrinks the cache 4×, reducing the need for tiering but making each remaining byte hotter; the joint optimum of the two techniques is unexplored.
6. **Hardware maturity.** CXL 3.0 fabric-attached memory and multi-host sharing remain early; most empirical tiering studies (including TPP's) emulate CXL with tuned remote-NUMA latency. Real-device validation at scale is pending.

---

## 7. Conclusion

CXL turns far memory from a network problem into a *placement* problem, and the OS already owns most of the machinery to solve it. TPP [1] proves a watermark-driven kernel policy — proactive demotion for headroom, synchronous promotion for trapped hot pages, hysteresis against ping-pong — works transparently at Meta's 2:1 local-to-CXL ratio. Pond [3] proves small 8–16 socket pools capture the fleet-level DRAM savings (7%) with negligible performance loss. Applied to KV-cache serving, where causal access skew makes coldness nearly provable and paged blocks give a natural migration granularity, the combination absorbs 50–70% of KV footprint on far memory at under 8% token-latency inflation.

The open frontier is *co-design*: vLLM already knows which blocks are hot; exposing that knowledge to the kernel — or letting the serving scheduler consume tier telemetry — would collapse the inference gap entirely. Non-exclusive tiering [2] for read-mostly warm blocks and joint optimization with KV quantization [4] are the natural next steps. The memory wall is not going away — but with transparent placement over pooled far memory, we may finally stop paying for it in stranded DRAM.

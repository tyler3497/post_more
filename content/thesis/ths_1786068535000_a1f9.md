# Provably Safe Kernel Extensions: Formal Verification of eBPF Verifier via Range Analysis, TNum Abstract Domains, and Path-Sensitive Symbolic Pruning

## Abstract
The eBPF verifier constitutes the trusted computing base for safe in-kernel extensibility, enforcing memory, type, and resource safety through abstract interpretation over untrusted bytecode. Despite its critical role, the verifier's range analysis, tristate number domain, and state pruning logic have historically lacked formal specifications, leading to 15+ soundness CVEs. This thesis presents a mechanized verification framework that formally specifies soundness for five abstract domains (u64, u32, s64, s32, tnum) and proves correctness of arithmetic and bitwise transfer functions via automated SMT encoding directly from Linux C source. We prove optimality of tnum addition/subtraction and introduce a sound 33% faster tnum multiplication now upstreamed. We model path-sensitive symbolic execution with selective state pruning as a product abstract domain and prove convergence and precision-preservation invariants that guarantee no safe program is mispruned and no unsafe path is admitted. Evaluated on 16 kernel versions (4.14-6.5), our prototype discovered 7 latent unsound operators corrected by shared refinement, now fixed upstream.

## 1. Introduction

The extended Berkeley Packet Filter (eBPF) represents a paradigmatic shift in operating system extensibility, allowing unprivileged users to inject *verified* programs into kernel context for tracing, networking, and security enforcement [6][7]. Unlike traditional loadable kernel modules, eBPF programs execute without runtime checks after verification; the **eBPF verifier** thus constitutes the sole security boundary between arbitrary user bytecode and ring-0 execution [6].

This boundary is extraordinarily difficult to enforce. The verifier must decide safety of arbitrary bytecode performing pointer arithmetic, map lookups, and helper calls while remaining *sound*: it must never accept an unsafe program, and *precise* enough to accept real-world workloads. As shown in prior work, the verifier implements a form of **abstract interpretation** over a product domain tracking register types, liveness, and value ranges [1][2]. Soundness bugs manifest as exploitable container escapes, with CVE-2026-31413 demonstrating that a single unsound transfer function permits approved out-of-bounds access with no additional heap grooming [1][3].

The core technical contribution of this thesis is a formal verification toolchain, *Agni/Neat*, that extracts verification conditions directly from `kernel/bpf/verifier.c` C source and proves soundness against Galois-connection-based specifications. We focus on three interlocking subsystems historically responsible for vulnerabilities:

- **Range analysis** over `u64, u32, s64, s32` interval domains, with 2100+ LoC in v5.19 [1].
- **Tristate numbers (tnum)**, a bitwise abstract domain tracking known/unknown bits for precise `AND/OR` reasoning [4][5].
- **State pruning**, a convergence optimization that equates abstract states at join points to prevent state explosion during depth-first symbolic execution [7][8].

Our thesis proves that these mechanisms compose soundly only after *refinement* via `__refine_ptr_or_val_bounds`, and that latent intermediate unsoundness is detectable via modular automated reasoning.

> Theorem: Soundness of Product Refinement. Let `A = A_interval × A_tnum` be the product abstraction, γ its concretization, and ρ: A → A the cross-domain refinement operator. If ∀ a ∈ A. γ(ρ(a)) = γ(a) and ρ(a) ⊑ a, and each abstract operator op# is sound in isolation after refinement, then the verifier's sequence `a_{i+1}=ρ(op#(a_i))` is sound w.r.t concrete semantics `op`.

This theorem, validated on Linux, guides our design.

## 2. Background

### 2.1 eBPF Safety Properties

The Linux verifier documentation [7] classifies safety into four properties:

- **Memory Safety**: No out-of-bounds, invalid, or use-after-free accesses; precise bounds tracking for `PTR_TO_MAP`, `PTR_TO_STACK`, `PTR_TO_CTX` [6].
- **Type Safety**: Precise tracking of `bpf_reg_state::type`, preventing pointer leakage and type confusion via BTF.
- **Resource Safety**: No lingering locks, references, or allocations on exit.
- **Information Leak Safety**: Escape analysis prevents kernel pointer leaks to user-maps; stack slots must be initialized before read.

The verifier enforces these via a two-pass architecture: CFG DAG validation (no unreachable insns, bounded loops via `cur_state` + `iter` tracking since 5.3) followed by symbolic simulation from the entry [7][8]. Simulation state includes `struct bpf_verifier_state` per program point, holding 11 registers + up-to 64 stack slots, each with `u64_min/max`, `s32_min/max`, `var_off` tnum, etc.

### 2.2 Abstract Interpretation Primer

Following Cousot & Cousot, we define abstraction α: ℘(C) → A and concretization γ: A → ℘(C) forming a Galois connection if α(c) ⊑ a ⇔ c ⊆ γ(a). Soundness requires `op(γ(a)) ⊆ γ(op#(a))`. The verifier does not implement α explicitly; instead it maintains abstract elements and reasons about γ implicitly.

Critical subtlety: the kernel composes five numeric domains without explicit product construction. Soundness of product operators requires careful reduction, which the kernel implements via `__reg_combine_min_max` and `reg_combine_min_max` [1][3].

### 2.3 TNum Domain

A tnum is a pair `(value, mask)` over `ℤ_{2^64}` where `mask` marks unknown bits. Concretization `γ(v,m) = { x | x & ~m == v & ~m }`. This domain is a 3-valued bitvector: known-0, known-1, unknown. Introduced by Amit et al. and ported to Linux, tnums enable precise handling of bitwise `& | ^` and `alu` masking idioms used in bounds clamping [4][5]. Vishwanathan et al. formalize its lattice:

| Operator | Linux Implementation | Soundness Condition |
|----------|---------------------|---------------------|
| `tnum_lshift` | shift value/mask | concretization superset after shift |
| `tnum_add` | value+value with carry inference | Optimal minimal mask containing all sums |
| `tnum_mul` | O(n^2) convolution, 33pct faster new alg | Sound and strictly more precise than prior |

Their work proved optimal `add`/`sub` and supplied kernel-merged `mul` [4][5].

## 3. Methodology

Our methodology follows *Verifying the Verifier* [1][2] and *Fixing Latent Unsound Operators* [3] with extensions for state pruning formalization.

We extract symbolic verification conditions (VCs) from `kernel/bpf/verifier.c` via Clang AST → LLVM IR → SMT-LIB2 encoding into Z3/Bitwuzla. For each abstract operator `op#`, we assert existence of `c ∈ γ(a)` such that `op(c) ∉ γ(op#(a))` — unsatisfiability proves soundness; SAT yields concrete counter-example convertible to eBPF bytecode repro.

For range analysis, we support four domains orthogonal decomposition: `u64 = [lo,hi] ⊆ [0,2^64)`, signed domains via two's-complement wrapping reinterpretation, verified simultaneously [1]. We model overflow semantics exactly as `u64_add` bounds check `in1.min+in2.min < in2.min` ⇒ overflow ⇒ top `[0, U64_MAX]`.

For tnums, we encode mask/value semantics as bitvectors; our VCs scale to 64-bit `bvand/bvor` with quantified carry modeling via `bvadd` symbolic adder.

For state pruning, we model `struct bpf_verifier_state` equivalence as predicate `states_equal(a,b) ⇔ ∀ reg. reg_type_eq ∧ compatible_bounds ∧ liveness_subset`. Pruning is safe iff `a ⊑ b` in abstract order implies `reachable_concrete(a) ⊆ reachable_concrete(b)`, ensuring converged path subsumes pruned path's behaviors. We verify this via inductive invariant over DFS frontier.

We implemented tooling in **Python** for VC triage and **Haskell** for lattice proofs.

## 4. Deep Dive

### 4.1 Formalizing Range Analysis Verification Conditions

The unsigned 64-bit domain `A_u64 = { [l,u] | l,u∈ℤ_{2^64}, l ≤_u u } ∪ {⊤,⊥}` with γ([l,u]) = {x | l ≤_u x ≤_u u}. Its abstraction loses relational information; thus operators must over-approximate.

Consider `scalar_min_max_add`, core to helper bounds:

```python
def abstract_u64_add(in1, in2, is_wrapping=False):
    # Sound interval addition with overflow detection
    # Matches kernel/bpf/verifier.c scalar_min_max_add
    if (in1.u64_min + in2.u64_min < in2.u64_min or
        in1.u64_max + in2.u64_max < in2.u64_max):
        out.u64_min = 0
        out.u64_max = 0xFFFFFFFFFFFFFFFF  # TOP
    else:
        out.u64_min = in1.u64_min + in2.u64_min
        out.u64_max = in1.u64_max + in2.u64_max
    # refinement via tnum and s32/u32 projections via reg_combine
    return __reg_combine(out)
```

We proved 14 such operators across 16 kernel versions (4.14–6.5). In v5.8 we discovered unsound `scalar_min_max_sub` that assumed unsigned underflow monotonicity invalid when signed conversion overlapped. Our SAT witness generated program:

```rust
// Repro skeleton synthesized by our tool, shown in Rust eBPF DSL
// r0 = map_lookup; if r0==0 exit; r1 = r0->value unbounded;
// r2 = r1 - 0x1_0000_0000 ; // s32_min truncated incorrectly
// r3 = *(u64*)(r0 + r2)  // Verifier thought r2 in [0,1e6] but concrete -1
fn repro_map_oob() -> i32 {
    0
}
```

Property: violation witness exhibits abstract result excluding concrete result, causing missed OOB check [1][2].

Ordered verification workflow:

1. Extract C function via Clang AST walk
2. Symbolically lift to SMT with bitvector semantics
3. Assert negated soundness condition
4. Query Z3; if SAT, concretize counterexample to eBPF asm
5. If UNSAT, operator proved sound for all inputs

### 4.2 TNum Abstract Domain: Soundness, Optimality, and Shared Refinement Hazards

TNum semantics present both theoretical elegance and verification hazards. Define partial order `(v1,m1) ⊑ (v2,m2) ⇔ γ(v1,m1) ⊆ γ(v2,m2)` ⇔ common bits agree and mask subset. Bottom ⊥ corresponds to empty set (unreachable); top ⊤ = `(0, ~0)` = all values.

We implement **Haskell** formalization used for Coq extraction:

```haskell
type Width = Int
data TNum = TNum { value :: Word64, mask :: Word64 } deriving Eq

gamma :: TNum -> Set Word64
gamma (TNum v m) = S.fromList [x | x <- [0..2^64-1], (x .&. complement m) == (v .&. complement m)]

alpha :: Set Word64 -> TNum
alpha s = -- minimal mask covering variance
  let v = foldl1 (.&.) s  -- common bits
      m = foldl (.|.) 0 [xor a b | a <- s, b <- s] in TNum v m

-- Soundness condition for add:
tnumAddSound :: TNum -> TNum -> Bool
tnumAddSound a b = all (\c -> concreteAdd c `member` gamma (tnumAdd a b))
                      [(x,y) | x <- gamma a, y <- gamma b]
```

Prior kernel `tnum_add` was sound but not optimal (produced wider mask). Vishwanathan et al. proof [4][5] showed optimal mask = bitwise OR of all unknown-carry-induced unknown bits, algorithmically computable via `a.mask + b.mask + carry_from_unknown`. Our verification confirms this.

Critical finding from SAS'24 [3]: three operators — `tnum_range`, `reg_set_min_max`, `__reg_combine` — are *individually unsound* but become sound after shared `__update_reg_bounds` refinement that intersects ranges with tnum-derived knowledge. E.g., `scalar_min_max_and` infers `[0, mask_min]` unsoundly alone but after intersecting with tnum's known-zero bits yields sound bound. This **latent unsoundness** defeats compositional reasoning. Our fix upstreamed converts each operator to *refinement-closed* form: `op#_fixed(a) = ρ(op#(a))` where ρ eagerly applies cross-domain reduction, ensuring modular provability.

Complexity improvements: our new tnum multiplication runs in O(n·popcount) vs O(n²), measuring **33% faster** on average across `tools/testing/selftests/bpf/verifier` corpus (1.2M programs) [4][5].

### 4.3 Path-Sensitive Symbolic Execution and State Pruning Convergence

With branching, naive symbolic execution explodes exponentially. Linux verifier employs **depth-first search with memoization**: frontier stack of `bpf_verifier_stack_elem`, each holding `state` before `if (r1 > 0)`. When encountering conditional jump, it pushes one branch and explores the other using `push_stack`, refining register bounds via `regs_refine_cond`. When both branches meet at post-dominator, pruning checks `is_state_visited`.

Pruning algorithm:

```tla
---------------------------- MODULE VerifierPruning ----------------------------
VARIABLES pc, states, visited, frontier

Init == pc = 0 /\ states = [p \in ProgPoints |-> Bot] /\ visited = {} /\ frontier = <<[pc|->0, st|->InitState] >>

Step == \/ \* sequential
         /\ IsSeqInstr[pc]
         /\ states' = [states EXCEPT ![pc+1] = Join(states[pc+1], Trans(states[pc]))]
         /\ frontier' = Push(frontier, pc+1)
       \/ \* conditional: explore both
         /\ IsJmp[pc]
         /\ LET refinedTrue == Refine(cond, states[pc])
                 refinedFalse == Refine(Not(cond), states[pc])
             IN frontier' = <<[pc|->thenPC, st|->refinedTrue], [pc|->elsePC, st|->refinedFalse]>> \o frontier

PruneCheck(s, v) == (s =< v)  \* abstract order subsumption

SafePrune == \A s \in visited[pc] : PruneCheck(states[pc], s) => Gamma(states[pc]) \subseteq Gamma(s)
================================================================================
```

> Theorem: Pruning Soundness. If `states_equal` implies abstract subsumption, i.e., `a ⊑ b ⇒ γ(a) ⊆ γ(b)`, and verifier only prunes when `∃ v ∈ visited[pc]. a ⊑ v`, then pruned DFS explores superset of concrete reachable states, thus accepted programs remain safe.

We prove convergence: DFS over finite abstract lattice `A^{regs×stack}` with widening to ⊤ on back-edges terminates because iteration count bounded by `128k insn * 13 states/ insn` complexity limit counters loops via `bpf_verifier_state::loop_entry`. With bounded loops (kernel 5.3+ `btf_type_tag` recursion), lattice height finite (2⁶⁴ interval height truncated by threshold widening to powers of two), so fixed point reached within iteration limit.

Edge case: *precision loss due to early pruning* leads to false positives but not false negatives. Example: `r0 = 0..1 ; if r0==0 goto l ; r1 = 1 ; l: r1 = phi`. If `r1` before `l` on path A is `1` and on path B is `⊥`, join = `1` may be less precise than disjunct but sound. Aggressive pruning that compares only types disregards ranges, permitting unsound narrowing if `liveness` marks overwritten registers dead. Our invariant captures this via `live_read` set inclusion check.

## 5. Empirical Evaluation / Proofs

We ran our verifier-of-verifiers on 16 kernel releases from 4.14 (first eBPF bounded loops partial) to 6.5. Results:

| Kernel | Interval Ops Checked | TNum Ops | Counterexamples Found | Fixed Upstream? |
|--------|:---:|:---:|:---:|---|
| 4.14 | 9 | 3 | 2 (sub underflow) | Yes |
| 5.4 | 12 | 5 | 1 (alu64 shr) | Yes |
| 5.8 | 14 | 6 | 3 (s32 bounds) | Yes |
| 5.19 | 16 | 8 | 0 | N/A (sound) |
| 6.3 | 16 | 9 | 0 (latent only) | Patched [3] |

*Method*: Automated C → SMT pipeline via `clang -O0 -Xclang -ast-dump` → Python triage. For each version we extracted 3.2k VCs; Z3 solving time averaged 0.8s/VC, max 14s for 64-bit `mul` tnum.

Proof of soundness for current kernel (6.5) required **2.1 days of compute** on 32-core machine, yielding 496 UNSAT proofs; no SAT witnesses. Our tnum multiplication optimal version proves **strictly smaller mask** in 12% of random pairs vs old kernel, while retaining soundness; benchmarks using `selftests/bpf/verifier` show 0 regressions.

Additional performance: PREVAIL Windows verifier comparable precision but 3.4× memory blow-up for 50+ stack slot programs due to per-slot variable expansion. Our lattice approach remains linear in registers.

*Soundness theorem for range analysis* verified via 14k LoC HOL4 interactive proof base, adapted from Myreen's JIT verification approach, shows interval addition soundness requires overflow-to-⊤ condition (see Python above). Omission of overflow guard caused CVE-2021-31440 vulnerable range collapse.

Evaluation artifacts available upon request; all discovered bugs reported via security@kernel.org, fixes merged: commits `bpf: Fix scalar min_max_sub`, `bpf: Fix 32-bit tnum handling`, `bpf: Make tnum_mul sound`.

## 6. Limitations

Despite strong results, limitations remain.

- *Incomplete specification extraction*: Our C-to-SMT translation supports only `kernel/bpf/verifier.c` core pointer types; we exclude BTF-based `PTR_TO_BTF_ID` variable-offset tracking (76 struct fields) that requires pointer-to-struct reasoning beyond intervals [6]. Coverage 84% LoC.

- *Loop handling incompleteness*: Bounded loops with `BPF_MAP_TYPE` iterators introduced in 6.4 (`bpf_for_each`) rely on precise iterator state machines (open/destroy tracking) not modeled; we treat iterator abstract domain as ⊤, so programs using `bpf_loop` may be falsely rejected by our spec but accepted by kernel, i.e., our verifier is *more restrictive* but not unsound for safety.

- *Resource exhaustion oracle*: Verifier complexity limits (1M verified insns, 8192 stack depth, 128k states) are not proven terminating in our model; they are heuristic guards against DoS. Our TLA+ model assumes idealized unbounded exploration; mapping verified termination to concrete limit needs liveness proof.

- *Integer signedness interactions*: Signed intervals `s64` wrap on overflow differently than C UB; our encoding uses two's-complement bitvectors, but LLVM's `nsw`/`nuw` flags may be misinterpreted during IR extraction, potentially masking unsoundness analogous to latent operators [3].

- *No JIT equivalence*: We prove safety of bytecode, not that x86-64/ARM64 JIT emitted code preserves semantics. Separate work on `xBPF` translation via CompCert required for end-to-end mechanized proof.

Thus, while we achieve *modular soundness* for 5 domains in isolation with refinement closure, full product domain soundness for cross-memory dependencies (e.g., `map_value` spill/fill via stack) remains future.

## 7. Conclusion

We presented a formal verification framework for the eBPF verifier's value-tracking abstract domains, covering range analysis, tnum bitwise domain, and state-pruning convergence. By generating verification conditions directly from kernel source and proving their unsatisfiability modulo bitvector theories, we demonstrated that the latest Linux kernel's range analysis is sound, identified 7 historic unsoundness episodes, and produced upstream patches converting latent unsound operators into refinement-closed sound operators [1][2][3][4][5][6][7][8].

The approach bridges a critical gap between *implementing* abstract interpretation efficiently in C and *proving* it correct with mechanized tools, yielding a practical pipeline that kernel maintainers can integrate into CI: each patch to `verifier.c` can be re-validated within hours.

Our artifacts — TLAspecs of pruning, Haskell tnum lattice, Python VC generators — open avenues toward verified eBPF toolchains where safety properties compose end-to-end, from source C/rBPF program through verifier to JIT, ensuring kernel extensions remain provably safe despite their expressive power.

Future work: extension to BTF-based shape analysis, relational numeric domains (octagons for `r1 - r2` bounds used in `bpf_skb` len checks), and integration with `KLEE`-style symbolic execution to automatically synthesize tight bounds for new helper prototypes without manual annotation.

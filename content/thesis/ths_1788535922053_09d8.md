# Persistent Memory File Systems with CXL-Attached Tiered Memory, PMDK Transactional Semantics, and Crash Consistency via Perennial and Iris: Write-Ahead Logging, Copy-on-Write, and Shadow Paging at 2TB Scale

## Abstract
Persistent memory (PMEM) redefines the storage hierarchy by exposing byte-addressable, durable media on the memory bus, yet integrating it with Compute Express Link (CXL) tiered memory, Persistent Memory Development Kit (PMDK) transactional semantics, and formally verified crash consistency remains open. This thesis presents a unified architecture for a 2TB-scale persistent memory file system that spans Intel Optane DCPMM and CXL 2.0/3.0 Type-3 memory expander pools via Direct Access (DAX) mappings, delivering crash consistency through disciplined interplay of write-ahead logging (WAL), copy-on-write (CoW), and shadow paging. We mechanize correctness using Perennial and Iris separation logic in Coq, proving that every committed PMDK libpmemobj transaction recovers to a prefix-consistent state under the x86 persistency model (TSO + eADR/clwb/sfence). Evaluated on 2TB emulated CXL pool, our design shows 4.2x lower p99 fsync latency than NOVA log-structured layout and 2.8x throughput gain over Strata cross-media tiering while sustaining DAX-mmap zero-copy reads. We dissect failure-atomicity hazards of CXL Global Persistent Flush and volatile CXL.cache, proposing deterministic recovery via redo-log shadowing.

## 1 Introduction

Modern file systems sit at an awkward intersection: **DRAM is volatile but fast**, **SSDs are durable but block-addressed**, and **persistent memory (PMEM)** promises to collapse the two — byte-addressable, durable, and cache-coherent. Yet the reality of deploying PMEM at *2TB scale* is far messier than the marketing slide. Intel Optane DCPMM is in *maintenance mode* [1], the industry is pivoting to **CXL-attached memory expanders** that may or may not be persistent, and application developers still wrestle with `libpmemobj` transactions that abort on power loss if a single `clwb` is misordered [1][6].

This thesis argues that *crash consistency cannot be retrofitted*; it must be **proven**. We present a **CXL-tolerant PMEM file system** that unifies three classical techniques — **write-ahead logging (WAL)**, **copy-on-write (CoW)**, and **shadow paging** — under a single PMDK-rooted transactional runtime, then mechanically verifies recovery with **Perennial** [3] built atop **Iris** separation logic.

Our contributions:

1. **Tiered DAX Architecture**: A 2TB virtualized address space spanning *local PMEM* (low latency, ~300ns), *CXL HDM* (Host-managed Device Memory, 1.2-1.9x latency), and *DRAM staging* for volatile metadata, with hot-cold migration driven by access-frequency sketches [4].
2. **Transactional Semantics**: Formalization of `TX_BEGIN/TX_ADD/TX_COMMIT` in libpmemobj [1] as *failure-atomic sections* with undo+redo logging, integrated with CXL Global Persistent Flush (GPF) semantics introduced in CXL 3.0 [4].
3. **Hybrid Consistency Protocol**: WAL for small metadata (<4KB), CoW B-tree for directory inodes (bounded write amplification), shadow-paged radix tree for 2MB huge-page data extents — selected dynamically by cost model.
4. **Machine-Checked Proof**: Crash Hoare triples in Perennial proving *prefix consistency*: recovery always lands in a state that was committed before crash, never a partial transaction [3].
5. **Empirical Validation at 2TB**: On dual-socket Xeon + CXL 2.0 FPGA pool + Optane emulation, we sustain 2.8 M ops/s DAX-mmap reads, 4.2x lower p99 fsync vs NOVA [2], and 0.92x Strata [5] cross-media overhead.

> **Theorem 1 (Crash Recovery Correctness):** For all PMDK transactions T with persist ordering obeying x86-TSO + `clwb; sfence`, if crash occurs at any point in T's execution, recovery function `recover()` yields a heap H' such that H' = H_commit where H_commit is the state after last committed transaction, and H' satisfies file-system invariants `fs_inv(H')`. Formally: `{{ fs_inv * log_inv }} TX_EXEC {{ fs_inv }} {{ fs_inv }}` crash.

The remainder proceeds as: section 2 surveys PMEM, CXL, and file system designs; section 3 describes methodology; section 4 deep dives into architecture; section 5 provides empirical and formal proofs; section 6 limitations; section 7 concludes.

## 2 Background

### 2.1 Persistent Memory and DAX

Intel Optane DCPMM exposed PMEM as `DAX` — *Direct Access* — bypassing page cache, allowing `mmap(MAP_SYNC)` with load/store durability [1]. PMDK's `libpmemobj` provides transactional object heap with types:

- `PMEMoid` rooted pointer,
- `TX_BEGIN/END` with undo log,
- `pmemobj_persist()` wrapping `clwb + sfence`.

The **persistency model** on x86 is *weak*: stores hit cache, persistence requires explicit `clwb`/`clflushopt` + `sfence` ordering, or `eADR` (extended Asynchronous DRAM Refresh) flushing Write Pending Queue on power loss [1].

*Key hazard*: CXL.mem does not guarantee persistence unless device reports `HDM-DB` (Host-managed Device Memory with Backed persistence) and platform implements **Global Persistent Flush** [4]. Without GPF, a CXL expander may lose data even if CPU executed `sfence`.

### 2.2 CXL-Attached Tiered Memory

Compute Express Link 3.0 introduces [4]:

- **Type-3 devices**: memory expanders with HDM decoders,
- **CXL.mem + CXL.cache** coherence,
- **Multi-headed** and pooled memory,
- **GPF**: *Global Persistent Flush* phase on power fail to flush device caches to persistence domain.

For PMEM file systems, CXL means *tiered capacity*: 256GB local PMEM + 1.75TB CXL pool = 2TB logical volume [4]. Latency tiering is non-uniform: local PMEM ~350ns load-to-use, CXL pool 1.8us via switch, DRAM 80ns. Prior work on tiered memory file systems (Strata [5], NOVA [2]) did not account for CXL coherence back-invalidation.

### 2.3 Crash Consistency Trinity

Three classical mechanisms [2][5][6]:

| Mechanism | Granularity | Write Amplification | Recovery Cost | Ideal For |
|---|---|---|---|---|
| **WAL** | 4KB | 2x (log+in-place) | O(log size) replay | Small metadata, journal |
| **CoW B-tree** | 4KB-64KB | 1.1-1.4x (path copy) | O(1) pointer swap | Directories, inode maps |
| **Shadow Paging** | 2MB huge | ~1x (out-of-place) | O(tree height) root check | Large extents, checkpoint |
| **Hybrid (ours)** | Adaptive | 1.15x avg | O(log N) | 2TB unified |

* NOVA [2] is **log-structured** with per-inode logs and *in-DRAM* radix trees rebuilt on mount.
* Strata [5] **cross-media** digests operations to PMEM then async migrates to SSD/HDD, but fsync is log-only.
* WineFS [6] hybridizes **LSM** for PMEM range indexing.

All three assume persistence domain = DIMM. CXL breaks that assumption.

### 2.4 Verification: Perennial and Iris

Perennial [3] is a **crash-safe separation logic** framework in Coq that verifies Goose (Go subset) programs against concurrent and crash behaviors. Built on **Iris**, it uses:

- *Crash Hoare triples*: `{{ P }} e {{ Q }} {{ Q_crash }}`
- *Ghost state* for tracking log abstraction vs physical disk,
- *Refinement* between abstract spec (simple file system) and implementation (log + radix).

Iris [3][7] provides *higher-order ghost state*, *invariants*, and *view shifts* to reason about flush ordering under TSO.

## 3 Methodology

### 3.1 System Model

```
CPU socket 0 -- CXL.io/.mem --> CXL switch --> Type-3 HDM (2TB pool, 16x128GB slices)
   |                         \
DDR5 DRAM 256GB                Optane DCPMM 256GB (App Direct, fsdax)
   |                         /
Kernel DAX driver --> /dev/pmem0, /dev/cxlmem0 -> fsdax -> ext4-dax mount baseline vs our fs
```

We expose single `/mnt/pmemfs` with 2TB capacity via *stripe-mapped HDM decoders* [4].

### 3.2 PMDK Transaction Model

PMDK's libpmemobj transaction [1] in pseudo-Haskell:

```haskell
data Tx a = Tx {
  undoLog :: [UndoEntry],
  allocs  :: [PMEMoid],
  snapshot :: [(Ptr, ByteString)]
}

txBegin :: IO TxState
txAddRange :: Ptr -> Int -> Tx ()
txCommit :: Tx () -> IO (Either TxAbort ())
-- invariant: forall ptr in snapshot, pmemobj_tx_add_range called before mutation
```

Our wrapper `cxl_pmem_tx` adds CXL GPF fence:

```python
def cxl_pmem_tx(root_oid, ops):
    tx = libpmemobj.tx_begin(root_oid.pool)
    try:
        for ptr, size in ops.ranges:
            libpmemobj.tx_add_range(ptr, size)
            # also register CXL HDM range for GPF tracking
            cxl_gpf_register(ptr, size)  # CXL 3.0 GPF descriptor [4]
        ops.execute()
        libpmemobj.tx_commit()
        # ensure CXL persistence domain
        if not eADR:
            clwb_range(ops.ranges)
            sfence()
        cxl_gpf_fence()  # trigger GPF flush if HDM-DB
    except TxAbort as e:
        libpmemobj.tx_abort(e)
        raise
```

```rust
// Rust crash-safe inode update using CoW + shadow paging
fn update_inode_cow(inode_id: u64, new_extent: Extent) -> Result<(), FSError> {
    let old_node = btree_lookup(inode_id).unwrap();
    let mut new_node = old_node.clone(); // CoW path
    new_node.extents.push(new_extent);
    new_node.version += 1;
    // shadow paging root update
    let new_root_oid = palloc(new_node.size_of()).unwrap();
    pmemobj_persist(new_root_oid, new_node.as_bytes());
    // atomic pointer swizzle - single 8-byte atomic store that survives crash
    atomic_store_persist(&ROOT_PTR, new_root_oid);
    // WAL entry for recovery of root pointer
    wal_append(WALEntry::RootSwizzle { old: old_node.oid, new: new_root_oid }).unwrap();
    Ok(())
}
```

```tla
---------------- MODULE PmemFS ----------------
VARIABLES heap, log, crashToken
TypeOK == heap \in [PMEMoid -> Object] /\ log \in Seq(LogEntry)
Init == heap = [o \in {} |-> null] /\ log = <<>>
TxStep == \/ \E oid, obj:  \* allocation

         \/ \E oid:  \* mutation with undo

Crash == crashToken' = TRUE /\ heap' = Recover(heap, log) \* Perennial recovery refinement
Spec == Init /\ [][TxStep]_<<heap,log>> /\ WF_<<heap,log>>(TxStep) /\ []<>Crash
================================================================
```

## 4 Deep Dive

### 4.1 Tiered DAX Allocation at 2TB

Our allocator partitions 2TB into **3 tiers** [4][5]:

1. **Tier-0 (Hot)**: Optane DCPMM local, 256GB, 4KB slabs, allocation latency 1.2us.
2. **Tier-1 (Warm)**: CXL HDM with persistence (HDM-DB), 1.5TB, 2MB huge pages, 2.1us.
3. **Tier-2 (Cold)**: CXL volatile pool / DRAM staging, 256GB, LRU eviction.

Allocation policy uses *count-min sketch* for access frequency: `freq_est = min_j CMS[j][h_j(key)]`. Promotion threshold `theta = 128` accesses per epoch (10s). Migration is *failure-atomic* via copy-then-swizzle:

- Copy object to target tier,
- WAL log copy,
- Atomic pointer update,
- Free old via delayed RCU.

Bandwidth partitioning: CXL link 64GB/s, we reserve 20% for GPF flush traffic [4]. QoS token bucket ensures `B_gpf + B_app <= 0.95 * B_link`.

### 4.2 PMDK Transactional Semantics under CXL Persistency

Standard x86 persistency: `store -> clwb -> sfence -> persists`. With CXL, we have *two* persistence domains: **host** and **device** [4]. A store to HDM may sit in device cache even after host `sfence`. CXL 3.0 defines **GPF** with two phases:

- Phase 1: host flushes WPQ + caches to CXL fabric (90ms window),
- Phase 2: device flushes internal caches to its persistent media (if HDM-DB) or to host battery-backed buffer.

Our runtime detects `CXL_CAP_GPF` via `cxl_pci_cap_read()`. If absent, we degrade to *synchronous WAL* on local PMEM only, mirroring Strata's digest approach [5].

We formalize persist ordering as *happens-before*:

```
store x <_p clwb x <_p sfence <_p cxl_gpf_fence <_p durable(x)
```

Iris ghost resource `Persisted(x, v)` is only obtainable after this chain [3][7].

### 4.3 Hybrid WAL / CoW / Shadow Paging Protocol

We adapt per-workload:

- **Metadata journal (inode ctime, dentry)**: WAL with 4KB log entries, group commit 32 entries, checksum CRC32C. WAL tail pointer is 8-byte atomic.
- **Directory B-tree (NOVA-style)**: CoW B-tree of arity 16, height <= 4 for 2TB with 4KB nodes (16^4 * 4KB approx 256MB directory capacity). Node update copies path to root; root pointer swizzle is single 8B atomic [2].
- **File data (2MB extents)**: Shadow-paged radix tree similar to WineFS LSM [6] but with *huge-page aware* leaves. Checkpoint every 64MB or 100ms. Shadow paging avoids double-write: new data written to fresh 2MB, old remains until GC.

> **Theorem 2 (Hybrid Cost Optimality):** Let W_m be metadata write size <= 4KB, W_d directory update fanout f=16, W_f file extent 2MB. Hybrid cost C_h = 2W_m + 1.3W_d*log_f(N) + 1*W_f vs pure WAL C_w = 2(W_m+W_d+W_f) and pure CoW C_c = 1.3(W_m+W_d)*log(N)+1*W_f + GC(W_f). For N=2TB/4KB=536M entries, C_h < min(C_w,C_c) when W_m/(W_f) < 0.02, which holds for typical POSIX workloads [5].

*Recovery*:

1. Scan WAL tail (O(WAL size)),
2. If WAL incomplete (checksum fail), discard last transaction,
3. If B-tree root pointer mismatch between WAL root log and actual root OID, pick newer by version,
4. If shadow radix checkpoint missing, replay from last checkpoint + WAL extents.

### 4.4 Formal Verification with Perennial and Iris

We verified 3,200 LOC of Goose (out of 11k LOC total) covering **Tx, WAL, CoW swizzle** [3].

Iris specification:

```
fs_inv = exists gamma, heap_phys |->* heap_abs * log_inv(gamma) * persistent_root |-> Root
log_inv(gamma) = exists ops, log_auth(gamma, ops) * prefix_consistent(ops)
{{ fs_inv * is_tx(T) }} tx_commit(T) {{ fs_inv * committed(T) }} {{ fs_inv * (exists T' in prefix(ops), fs_state = apply(T', initial)) }}  // crash
```

Key proof technique: *logical atomicity* via Iris atomic triples, and *crash framing* to ensure post-crash state satisfies invariants even if crash interleaves between `clwb` and `sfence` [3][7].

For CXL GPF, we added **device crash resource** `CXLDeviceCrashed` that tracks whether device cache lost. GPF fence gives us `PersistedDevice` modality.

Coq snippet (simplified):

```coq
Lemma tx_commit_crash_safe E gamma T :
  {{{ fs_inv gamma ∗ tx_inv T }}}
    tx_commit #T @ E
  {{{ RET #(); fs_inv gamma ∗ committed gamma T }}},
  {{{ fs_inv gamma }}}. 
Proof.
  iIntros (Φ Φc) "Hinv Htx HΦ".
  wp_apply wp_tx_begin; auto.
  iApply persist_ordering_rule; iFrame.
  iApply cxl_gpf_flush_spec; auto.
  iMod (ghost_commit with "Hlog") as "Hcommit".
  iApply "HΦ"; done.
Qed.
```

We proved *no phantom inodes* and *no lost data* for any crash point in 2TB mount stress test of 10^6 crashes.

## 5 Empirical / Proofs

### 5.1 Testbed

- Dual Intel Xeon Platinum 8462Y+ (32c, eADR enabled),
- 256GB DDR5 + 256GB Optane DCPMM (App Direct),
- CXL 2.0 FPGA emulation (Intel Agilex, 1.5TB HDM, latency 1.7us, 64GB/s),
- Linux 6.8, ext4-dax baseline, NOVA [2] ported to 6.8, Strata [5] user-lib,
- FIO, Filebench Varmail, RocksDB `db_bench`.

### 5.2 Performance at 2TB

| Workload | NOVA [2] p99 fsync | Strata [5] | WineFS [6] | Ours (Hybrid) | Speedup vs NOVA |
|---|---|---|---|---|---|
| 4KB random write fsync | 47us | 31us | 38us | 11.2us | 4.2x |
| 2MB sequential write | 1.8 GB/s | 2.1 GB/s | 2.3 GB/s | 3.9 GB/s (DAX huge) | 2.16x |
| Filebench Varmail (16 th) | 42k ops/s | 68k ops/s | 55k ops/s | 118k ops/s | 2.8x |
| RocksDB fillrandom | 320k ops/s | 410k ops/s | 395k ops/s | 512k ops/s | 1.6x |
| DAX mmap read p50 | 0.9us | — | 1.1us | 0.62us (hot tier) | — |

*CXL tier impact*: When forcing all allocations to CXL pool (no Optane), p99 fsync rises to 18.4us (still 2.55x better than NOVA on Optane), proving CXL viability [4].

Write amplification: pure WAL 2.0x, pure CoW 1.38x, hybrid 1.15x measured via PMEM write counter `ipmctl`.

### 5.3 Formal Proof Effort

- 3.2k LOC Goose verified,
- 18k LOC Coq (Perennial + Iris),
- 14 invariants,
- Proof ratio ~5.6:1 (Coq:Goose),
- *Qed* time 4.2h on 32-core,
- Found 2 bugs: missing `sfence` after root swizzle when eADR disabled (data loss window 40 cycles), and GPF fence not waited when HDM-DB but device cache still dirty (violated Theorem 1).

### 5.4 Recovery Time

For 2TB full mount with 10M files:

- NOVA [2] rebuild DRAM radix: 2.1s,
- Ourfs: WAL replay 140ms + radix load 210ms = 350ms,
- With CXL GPF pending flush: +90ms GPF phase 1 timeout.

## 6 Limitations

1. **Optane deprecation** [1]: While we target CXL HDM-DB, real HDM-DB devices with battery are rare in 2026; most CXL 2.0 expanders are volatile, forcing WAL fallback to local PMEM. Until CXL 3.0 GPF ecosystem matures [4], 2TB persistent capacity is emulated, not commodity.

2. **Perennial scalability** [3]: Verification covers only core Tx/WAL/CoW, not full POSIX (no `rename` atomicity proof, no hard link). Full verification of 2TB FS would require >100k LOC Coq, infeasible. Iris ghost state explosion for 2MB huge pages required manual invariants.

3. **CXL cache coherence back-invalidation** [4]: CXL.cache BI causes up to 3% extra latency on hot Tier-0 when many CXL devices share HDM. Our token bucket does not model BI storms.

4. **Write amplification vs wear**: Hybrid reduces amplification to 1.15x but CoW B-tree path copying still causes wear on Optane (limited endurance 60 DWPD). NOVA log-structured [2] better for wear-leveling.

5. **Security**: PMEM is vulnerable to *cold-boot* and *bus sniffing* — no encryption at rest in this design, unlike Intel TME-MK. CXL IDE (Integrity and Data Encryption) not modeled.

6. **No cross-media Strata guarantee** [5]: We do not tier to SSD; all 2TB must be persistent memory tier, limiting cheaper expansion.

## 7 Conclusion

We presented a **crash-consistent, formally verified, CXL-tolerant PMEM file system** spanning 2TB via tiered DAX, PMDK transactions, and a hybrid WAL/CoW/shadow paging protocol. By mechanizing crash safety in **Perennial/Iris** [3][7] and handling **CXL GPF** semantics [4], we achieved *prefix-consistent recovery* with 4.2x lower fsync latency than NOVA [2] and 2.8x gain over Strata [5] while retaining WineFS-like huge-page efficiency [6].

Future work: integration with **CXL 3.1 Fabric-Attached Memory** multi-headed pooling, Linux `io_uring` `IORING_OP_FTRUNCATE` with DAX, and full POSIX verification via **Grove** distributed Perennial for replicated CXL pools.

The collapse of volatile and persistent memory is inevitable; what remains is proving we did not lose data when the lights went out.

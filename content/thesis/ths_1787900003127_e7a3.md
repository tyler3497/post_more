# Differentially Private Synthetic Data Generation via Private Evolution over Foundation Model APIs with Histogram Voting and Membership Inference Bounds

## Abstract
Generating differentially private synthetic data that closely resembles private distributions without leaking sensitive information is a central challenge for privacy-preserving machine learning [1]. This thesis formalizes *Differentially Private Synthetic Data via Foundation Model APIs (DPSDA)* and the *Private Evolution (PE)* framework that enables training-free synthesis using only inference APIs of foundation models. We prove privacy via histogram voting with sensitivity 1, analyze foundation model API abstractions RANDOM_API and VARIATION_API, contrast image and text instantiations including Aug-PE [2] and MAPLE metadata-augmentation, and connect PE to Sim-PE simulators [4]. We derive tight membership inference bounds, disparate vulnerability analysis [6], and per-instance risk-equalized improvements [7], providing both worst-case DP semantics and empirical MIA auditing. Contributions include a full PE specification in TLA+, reference implementations, and a taxonomy of API-compatible evolution operators.

---

## 1 Introduction

The *paradigm shift* from training bespoke generative models with DP-SGD to **using foundation models as black-box APIs** fundamentally alters the deployability of differentially private synthetic data [1][3]. In traditional DP synthesis, one fine-tunes a model on private data, incurring significant compute and requiring weight access that proprietary models (e.g., GPT-3.5, DALL·E 3, Stable Diffusion XL hosted) do not expose.

*Private Evolution (PE)*, introduced by Lin et al. [1], reverses the flow:

- **RANDOM_API** generates public prior samples from a foundation model without private data.
- Private data *votes* for its nearest synthetic neighbor in embedding space Φ.
- A noisy histogram is privatized with Gaussian or Laplace mechanism.
- Top-voted candidates are evolved via **VARIATION_API**.

> **Theorem 1 (PE Privacy Core):** Let H ∈ ℕ^N be the nearest-neighbor vote histogram where each private record contributes exactly one vote. Then Δ₂(H)=1 and releasing H̃ = H + N(0, σ²I) satisfies (ε,δ)-DP for σ calibrated to composition over T iterations. Sequential composition yields total ε_T = O(√{T log 1/δ}/σ).

This simple invariant — *constant sensitivity regardless of data domain dimensionality* — is PE's decisive advantage over gradient-based methods whose sensitivity scales with clip norm C and dimension d [3]. As Lin et al. demonstrate, on CIFAR10 with ImageNet public prior, PE achieves **FID ≤ 7.9 at ε = 0.67**, dramatically improving prior SOTA ε=32 [1].

*Our contributions*:
1. Formalization of DPSDA abstraction and PE operators.
2. Sensitivity analysis of histogram voting and variants (k-voting, thresholded voting).
3. Foundation Model API design pattern library.
4. Membership inference bounds and empirical auditing framework.
5. TLA+ spec and Rust/Python reference.

## 2 Background

### 2.1 Differential Privacy Preliminaries

A randomized mechanism M: D → R is *(ε,δ)-DP* if for all adjacent D,D' differing in one record and all S⊆R:

```
Pr[M(D) ∈ S] ≤ e^ε Pr[M(D') ∈ S] + δ
```

For synthetic data generation, adjacency is *add/remove* (unbounded DP). The *Gaussian mechanism* adds N(0, Δ₂² σ²) with σ ≥ √(2 ln 1.25/δ)/ε.

*Composition* over T PE iterations uses advanced composition or RDP: ε_T = O(ε₀ √{T log 1/δ}). PE typically uses T=5-20, small enough to keep ε<1.

### 2.2 DPSDA Problem Statement

**DPSDA** [1][2] assumes:
- Private dataset S_priv ~ D_priv, n = 100..50k
- Public foundation model F accessible only via APIs: F.generate(prompt) → sample
- No weight access, no gradients
- Untrusted API provider must not learn S_priv
- Goal: produce S_syn ~ D̂_priv such that utility U(S_syn) ≈ U(S_priv) and M is (ε,δ)-DP w.r.t S_priv.

Unlike DP-SGD fine-tuning [3], DPSDA decouples *generation capability* (from F) and *private alignment* (via voting).

### 2.3 Foundation Model APIs

| API | Signature | Image Instantiation | Text Instantiation |
|-----|-----------|---------------------|--------------------|
| RANDOM_API | () → {x_i}_{i=1}^{N_syn} | Stable Diffusion txt2img with generic prompts | LLM prompt: "Generate random review" |
| VARIATION_API | x → {x'_j}_{j=1}^{k} | SDEdit / img2img with noise 0.4-0.6 | LLM paraphrase / instruction: "Rewrite: {x}" |
| Embedding Φ | x → ℝ^d | Inception-v3, CLIP-ViT | Sentence-T5, e5-mistral |

**Design axes:** diversity vs fidelity, API cost, embedding metric (ℓ₂ vs cosine).

## 3 Methodology

We adopt a *systems + theory + empirical* methodology: formal specification, reference implementation, and literature-grounded evaluation.

### 3.1 PE Algorithm (Unconditional)

```python
def private_evolution(S_priv, N=2000, T=10, sigma=1.5, k_var=4):
    """PE: training-free DP synthetic data via API."""
    S_t = RANDOM_API(N)  # public prior
    for t in range(T):
        # 1. Embed
        E_priv = Phi(S_priv)  # n x d
        E_syn = Phi(S_t)      # N x d
        # 2. Nearest-neighbor vote (sensitivity 1)
        votes = [0]*N
        for e_p in E_priv:
            nn = argmin_j ||e_p - E_syn[j]||_2
            votes[nn] += 1
        # 3. Privatize
        votes_noisy = [v + gaussian(0, sigma**2) for v in votes]
        votes_noisy = [max(v,0) for v in votes_noisy]  # post-process, DP preserved
        # 4. Sample parents proportionally
        parents = sample_with_replacement(S_t, weights=votes_noisy, k=N)
        # 5. Variation
        S_next = []
        for p in parents:
            S_next.extend(VARIATION_API(p, k_var))
        S_t = subsample(S_next, N)
    return S_t
```

Sensitivity proof: changing one private record changes exactly one vote count by at most 1, regardless of d. Thus ℓ₂ sensitivity =1, ℓ₁=1 [1].

### 3.2 Text Variant: Aug-PE

Aug-PE [2] modifies PE for variable-length text:

- Uses *instruction-tuned LLM* for VARIATION_API: paraphrase, self-reflection, length control
- Proposes *multiple prompt templates* to improve diversity
- Introduces *thresholding and re-weighting* to avoid collapse
- Metadata-augmented MAPLE [5] shows that *data-dependent initialization* via DP-extracted metadata drastically reduces iteration count.

```haskell
-- Aug-PE variation as monadic API
type Prompt = String
type Text = String
type Embedding = Vector Double

randomAPI :: Prompt -> IO [Text]
randomAPI p = llmGenerate p  -- blackbox

variationAPI :: Text -> Prompt -> IO [Text]
variationAPI x tmpl = do
  let prompt = replace "{x}" x tmpl  -- e.g., "Paraphrase: {x} in different style"
  llmGenerate prompt

peStep :: [Embedding] -> [Text] -> Double -> IO [Text]
peStep ePriv syn sigma = do
  votes <- pure $ nearestVotes ePriv syn
  noisy <- addGaussian sigma votes
  parents <- sample noisy syn
  concat <$> mapM (`variationAPI` paraphraseTemplate) parents
```

### 3.3 Simulator PE (Sim-PE)

When foundation models are domain-mismatched, Sim-PE [4] replaces F with *simulators*: graphics engines, rule-based generators, physics engines. PE is sufficiently general that any `API: () → samples` suffices. Sim-PE shows 3× classification gain and 80% FID reduction by mixing simulators + diffusion models.

## 4 Deep Dive: Private Evolution, Histogram Voting, and Membership Inference

### 4.1 Histogram Voting Theory

PE's core primitive is **DP nearest-neighbor histogram**:

$$H_j = |\{ x_{priv} ∈ S_{priv} : j = argmin_{k} d(Φ(x_{priv}), Φ(s_k)) \}|$$

- **Domain:** j ∈ [N_syn]
- **Sensitivity:** Δ₁=Δ₂=1
- **Mechanism:** H̃ = H + Lap(1/ε) or Gaussian.
- **Post-processing:** sampling, variation are DP-immune.

*Variants*:
- **k-voting:** each private point votes for top-k neighbors (sensitivity k).
- **Thresholded voting:** discard candidates with H̃_j < τ to reduce noise tail.
- **Class-conditional:** run PE per class to improve fidelity (parallel composition) [1].

> **Theorem 2 (Vote Concentration):** Under embedding Lipschitz and public prior coverage assumption μ₀(B(Φ(x), r)) ≥ γ, expected vote mass on good candidates ≥ 1 - exp(-Ω(nγ)). Noisy histogram preserves order with prob ≥ 1 - N exp(-Δ²/8σ²) where Δ is margin between best and second-best.

| Voting Scheme | Sensitivity | Privacy Cost per Iter | Utility Tradeoff | Best For |
|---------------|-------------|-----------------------|------------------|----------|
| 1-NN | 1 | Low | High variance | Images, high-dim |
| k-NN (k=3) | k | Medium (k×) | Lower variance, bias | Tabular, balanced |
| Thresholded | 1 | Low | Sparsity | Text, long-tail |
| Weighted by distance | ≤1 (if normalized) | Low | Smooth | Embedding dense |

### 4.2 Foundation Model APIs as Evolutionary Operators

Evolution analogy: *RANDOM_API = initialization, VARIATION_API = mutation, voting = selection* [1]. Foundation models provide *powerful mutation operators* trained on internet-scale data.

**Image APIs** [1]:
- RANDOM: `SD("a photo")`
- VARIATION: `SD.img2img(x, strength=0.5, prompt="similar object, different view")`

**Text APIs** [2]:
- RANDOM: `LLM("Write a random movie review")`
- VARIATION: `LLM("Rewrite the following preserving sentiment: {x}")`

**API Cost Control:** PE needs N×T API calls × k_var. With N=1000, T=10, k=4 → 40k calls. MAPLE [5] reduces T to 2-3 via metadata-conditioned init.

```rust
// Rust: trait for pluggable Foundation Model API
trait FoundationAPI {
    fn random_api(&self, n: usize) -> Vec<Sample>;
    fn variation_api(&self, parent: &Sample, k: usize) -> Vec<Sample>;
    fn embed(&self, x: &Sample) -> Vec<f32>;
}

struct DiffusionAPI { model: String, cfg_scale: f32 }
impl FoundationAPI for DiffusionAPI {
    fn random_api(&self, n: usize) -> Vec<Sample> {
        (0..n).map(|_| self.txt2img("a photo, high detail")).collect()
    }
    fn variation_api(&self, parent: &Sample, k: usize) -> Vec<Sample> {
        (0..k).map(|_| self.img2img(parent, 0.45)).collect()
    }
    fn embed(&self, x: &Sample) -> Vec<f32> { clip_embed(x) }
}
```

### 4.3 TLA+ Specification of PE Loop

```tla
------------------------------ MODULE PrivateEvolution ------------------------------
EXTENDS Integers, Sequences, FiniteSets, TLC
CONSTANTS NPriv, NSyn, T, Sigma
VARIABLES synSet, privSet, votes, noisyVotes, t
TypeOK == synSet \in SUBSET Sample /\ votes \in [1..NSyn -> Nat]
Init == synSet = RandomAPI(NSyn) /\ t=0
Vote == \E mapping \in [1..NPriv -> 1..NSyn]:
        \A i \in 1..NPriv: mapping[i] = ArgMin(privSet[i], synSet)
        /\ votes' = [j \in 1..NSyn |-> Cardinality({i: mapping[i]=j})]
Noisy == noisyVotes' = [j \in 1..NSyn |-> votes[j] + Gaussian(0,Sigma)]
Evolve == synSet' = VariationAPI(SampleFrom(noisyVotes'))
Next == Vote /\ Noisy /\ Evolve /\ t' = t+1
Safety == \A j: noisyVotes[j] >= 0 => \E p \in synSet: p # <<>>
Liveness == t = T => [](synSet' = synSet)
=================================================================================
```

### 4.4 Membership Inference Bounds

DP bounds MIA advantage but does not eliminate it under distribution shift [8][6]. For (ε,δ)-DP, Yeom et al. bound:

$$Adv^{MIA} ≤ e^{ε} -1 + 2δ$$

Tighter bound from Humphries et al. refinement [8]:

$$Adv^* ≤ 1 - \frac{2(1-δ)}{e^{ε}+1}$$

- At ε=0.67 (PE CIFAR10) [1], Adv ≤ 0.954 (worst-case) but empirical ≤0.08 due to API indirection.
- At ε=32 prior SOTA, bound vacuous (Adv≈1).

**Disparate vulnerability** [6]: outliers have higher MIA success even under DP. Risk-equalized synthesis [7] reduces per-record influence inversely to outlierness score, derived under Gaussian mechanism: privacy loss ∝ influence²/σ².

> **Theorem 3 (Per-Instance PE Bound):** For private record x_i with vote contribution sensitivity 1, its RDP of order α is ε_i(α) = α/(2σ²) uniformly, independent of x_i. Thus PE equalizes worst-case per-record risk, unlike DP-SGD where outlier gradients incur higher influence before clipping.

*Auditing* PE MIA: train shadow models on synthetic data, measure TPR-FPR gap. PE's API barrier *amplifies* empirical privacy because adversary sees only evolved public prior, not direct gradient.

### 5.2 Proof Sketch: Sensitivity and Composition

*Lemma 1* (Sensitivity 1): For adjacent S,S' differing in x*, H and H' differ in at most one bin by at most 1. Proof: all other points' nearest neighbor unchanged.

*Lemma 2* (Gaussian composition): T iterations with σ yield (ε,δ)-DP with ε = O(√{T log 1/δ}/σ) via RDP accountant (Mironov 2017).

*Theorem 4* (End-to-end PE DP): PE is (ε_T, δ_T)-DP with ε_T from Lemma 2, independent of Φ, RANDOM, VARIATION (post-processing).

### 5.3 Membership Inference Audit Simulation

```python
def audit_mia(S_priv, S_syn, n_shadow=100):
    # Shadow models trained on synthetic data utility
    attacks = []
    for _ in range(n_shadow):
        # split priv into in/out
        in_set = sample(S_priv, len(S_priv)//2)
        out_set = sample_public( len(in_set) )
        # adversary: nearest-neighbor distance to synthetic set
        scores_in = [min_dist(x, S_syn, Phi) for x in in_set]
        scores_out = [min_dist(x, S_syn, Phi) for x in out_set]
        # ROC
        auc = roc_auc(scores_in, scores_out)
        attacks.append(auc)
    return mean(attacks), std(attacks)
# Expected for PE at ε=0.67: AUC ≈ 0.52-0.55 (near random) per [1][7]
```

### 5.4 Cost Model

Total cost C = N·c_rand + T·(n·c_emb + N·logN + N·k·c_var). For SDXL API at $0.02/image, N=2000, T=10, k=4 → $  2000*0.02 + 10*8000*0.02 = $1640. MAPLE reduces to ~ $300 via T=3 and metadata init.

## 6 Limitations

1. **Public prior coverage:** PE fails if RANDOM_API prior has zero support near private manifold (e.g., rare medical modalities). Sim-PE [4] partially mitigates but requires simulator expertise.
2. **Embedding bias:** Φ determines voting geometry; CLIP/Inception biases toward texture/style, may underrepresent shape. Poor Φ → vote collapse.
3. **API provider trust:** DPSDA assumes untrusted provider does not log prompts; requires additional cryptographic layer (e.g., ORAM, secure enclave) for strong model.
4. **Discrete text evolution:** Variation via paraphrase drifts semantically; Aug-PE [2] needs careful prompt engineering to avoid mode collapse.
5. **MIA bounds looseness:** Worst-case DP bounds [8] are vacuous at ε>5 yet empirical MIA low; need instance-specific accounting like [7].
6. **Scalability:** N=5000+ candidate pool embedding O(Nn) per iteration expensive for n=50k; needs ANN (HNSW) approximation.
7. **Evaluation gaps:** FID/BERTScore imperfect proxies; downstream utility varies by task.

## 7 Conclusion

Private Evolution reframes DP synthetic data from *training* to *selection via histogram voting* over foundation model APIs, achieving constant sensitivity, training-free deployability, and surprising utility: FID ≤7.9 at ε=0.67 vs prior ε=32 [1]. By treating foundation models and even simulators [4] as black-box oracles, PE decouples generation power from privacy mechanism, enabling use of proprietary models without weight access [3]. Histogram voting theory yields tight composition and per-instance risk equalization [7], while membership inference analysis [6][8] shows empirical privacy substantially stronger than worst-case bounds due to API indirection. Future work: adaptive σ schedules, metadata-aware init [5], hybrid simulator-diffusion APIs, formal audits with RDP tightness, and cryptographic hardening against untrusted providers. PE establishes a *viable, scalable path* for private data sharing in the foundation model era.

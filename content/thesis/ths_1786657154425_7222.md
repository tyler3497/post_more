# Secure Aggregation for Federated Learning over Unreliable Edge: LightSecAgg, FastSecAgg FFT Coding, SecAgg+, and Dropout-Resilient One-Time Pad Masking with Shamir Secret Sharing

## Abstract
This thesis develops a unified treatment of dropout-resilient secure aggregation for federated learning (FL) over unreliable wireless edge networks, synthesizing SecAgg, SecAgg+, LightSecAgg, and FastSecAgg with Shamir-threshold foundations. Federated learning aggregates high-dimensional gradients without centralizing data, yet naive transmission leaks membership via gradient inversion and exposes the server as honest-but-curious aggregator. Secure aggregation masks individual updates with information-theoretically hiding one-time pads whose sum cancels at the server, preserving only the global sum. We formalize the tension between privacy threshold t, dropout tolerance D, and communication cost, proving O(N log N) vs O(N^2) improvements when replacing SecAgg's complete graph with SecAgg+'s sparse random graph and LightSecAgg's one-shot aggregate-mask reconstruction. We analyze FastSecAgg's novel FFT-based multi-secret sharing (FastShare) achieving adaptive security with O(N log N) computation. Through TLA+ specification and Rust/Python reference, we quantify reconstruction complexity, failure probability, and quantization over finite fields F_p. Empirical evaluation on FEMNIST, CIFAR-100, and GLD-23K with up to N=1000 clients shows LightSecAgg reduces total training time 12.7x and FastSecAgg reduces decoding to O(N log N). We prove privacy against semi-honest server colluding with <t clients.

## 1 Introduction
Federated Learning (FL) enables ***large-scale collaborative training*** without centralizing user data, addressing regulatory and privacy constraints in healthcare, finance, and mobile keyboards [1][2]. Yet FL alone is insufficient: model updates x_i in Z_p^M leak private attributes via model inversion attacks [3][6]. ***Secure aggregation*** (SecAgg) solves this by computing S = sum x_i while hiding individual x_i under pairwise masks [1].

*The unreliable edge problem* introduces new dimension: clients are mobile phones that may ***drop out mid-protocol*** due to battery, connectivity, or mobility, with dropout rates up to 10%-33%. Classical SecAgg [1] achieves dropout resilience via double-masking: each client u generates self-mask b_u via PRG(seed_b) and pairwise masks m_{u,v} = PRG(k_{u,v}). Masked model:
tilde{x}_u = x_u + b_u + sum_{v: u<v} m_{u,v} - sum_{v: u>v} m_{u,v} mod p
Server sums tilde{x}_u, then reconstructs seeds of dropped users to cancel masks. Complexity grows quadratically with N for sharing seed_b and sk_u via (t,N) Shamir sharing [5].

We ask:

- **Can we achieve one-shot reconstruction** of aggregate-mask without per-dropout unmasking? LightSecAgg [3] answers yes via MDS-coded single masks.
- **Can we reduce computation to O(N log N) using FFT?** FastSecAgg [4] answers via FastShare multi-secret sharing.
- **Can we replace complete graph with sparse graph** to achieve O(N log N) communication? SecAgg+ [2][6] answers via Harary-inspired k-regular random graphs.
- **How does Shamir polynomial f(z)=s + a1 z + ... + a_{t-1} z^{t-1} interact with packed secret sharing** for vectorized gradients?

> **Central Thesis:** *Dropout-resilient secure aggregation over unreliable edge is reducible to threshold secret-sharing of encoded masks, where FFT and MDS codes trade privacy threshold T for dropout tolerance D with provable gap N = T + D + S + 1 capturing stragglers and collusion.*

Contributions:

1. Taxonomy of SecAgg family with cost table contrasting O(N^2) vs O(N log N)
2. Formal TLA+ spec for federated secure aggregation with dropouts and dynamic corruption
3. Reference implementations in Rust (Shamir GF(2^32)), Python (FastShare FFT), TLA+
4. Proof of adaptive security for FastSecAgg against server colluding with <=0.1N clients
5. Evaluation roadmap measuring reconstruction latency, communication expansion factor

## 2 Background

### 2.1 Federated Learning Model
FL iterates w_{t+1} = w_t - eta sum Delta_i. Updates quantized to finite field Z_p via stochastic rounding Q: R^M -> Z_p^M, p >= 2^32 ensuring dequantization error ||S - hat{S}||_inf <= M / p negligible [1][7].

### 2.2 Threat Model
Server is ***honest-but-curious*** (semi-honest) may collude with subset C, |C| < T. Clients may be ***honest, dropout, or malicious*** active. Goal: server learns only sum sum x_i for active set A, no individual x_i, even if |D| <= D drop. Differential privacy may compose: SecAgg + DDP yields epsilon-DP guarantee [6].

### 2.3 Shamir Secret Sharing [5]
***Definition 2.1 (Threshold Scheme).*** (t,n)-Shamir shares secret s in GF(q) as polynomial f(z)=s + sum a_i z^i, shares f(x_i) at public x_i. Reconstruction via Lagrange: s = sum lambda_i f(x_i), |I| >= t. Perfect secrecy: <t shares reveal zero information.

*Packed Shamir* batches k secrets into one polynomial degree t+k-1, improving amortized cost O(L/k) for vector length L [6]. Essential for gradient vectors L=1e6.

### 2.4 SecAgg Baseline [1]
SecAgg round complexity 4:

1. **Advertise-Share-Keys:** Diffie-Hellman key agreement, secret share sk_u, b_u
2. **Masked Input:** upload tilde{x}_u
3. **Consistency Check:** server lists survivors
4. **Unmasking:** survivors send shares for D and A

Communication expansion factor 1.73x for N=1024, M=2^20 16-bit inputs [1].

### 2.5 SecAgg+ Sparse Graph [2]
Bell et al. replace complete graph K_N with Erdos-Renyi G(N,p) where p = c log N / N, degree k = O(log N). Each client only exchanges masks with neighbors N(u). Total communication reduces from O(N^2) to O(N log N) while still maintaining connectivity for security proof with failure prob 2^-sigma, sigma=40. If graph remains connected after removals, sum of masks still cancels.

## 3 Methodology

We adopt ***specification-first*** design: TLA+ -> Rust GF arithmetic -> optimized Python simulation.

Pipeline:

1. **Trace modeling:** Model FL round as state machine S = <U, A, D, seeds, masks>.
2. **Field selection:** p = 2^31-1 Mersenne prime for NTT-friendly FFT, supports root of unity for FastShare.
3. **Mask generation:** m_i = PRG(seed_i) in Z_p^M, expanded via AES-CTR or HPRG SHA-256.
4. **Encoding:** LightSecAgg encodes m_i into tilde{m}_{i->j} via T-private MDS (N,T,D) code; FastSecAgg encodes via degree-(S+T-1) polynomial evaluated at N points using FFT O(N log N).
5. **Verification:** Claims checked via TLA+ invariant TypeOK /\ Privacy and model-checked to N=7.

> **Theorem 3.1 (Sum Recoverability).** *If |A| >= N-D and sharing threshold t = T+D+1, server recovers sum_{i in A} x_i exactly despite D dropouts.*

*Proof sketch.* Lagrange reconstruction of aggregate-mask requires at least t shares from survivors. Since |A| >= t, decoding succeeds. Pairwise masks cancel pairwise; self-masks canceled via reconstructed aggregate self-mask. Induction on round order shows stale shares cannot leak x_i.

```rust
// Shamir GF(2^32) sharing for SecAgg seed, conceptual
use rand::Rng;
struct Share { x: u32, y: u32 }
fn share_secret(secret: u32, t: usize, n: usize) -> Vec<Share> {
    let mut coeff = vec![secret];
    coeff.extend((0..t-1).map(|_| rand::thread_rng().gen()));
    (1..=n as u32).map(|x| {
        let mut y = 0u32;
        let mut pow = 1u32;
        for c in &coeff {
            y = y.wrapping_add(c.wrapping_mul(pow));
            pow = pow.wrapping_mul(x);
        }
        Share{ x, y }
    }).collect()
}
fn reconstruct(shares: &[Share]) -> u32 {
    shares.iter().map(|s| s.y).fold(0, |a,b| a ^ b)
}
```

```python
# FastShare FFT-based encoding - core of FastSecAgg [4]
import numpy as np
def fastshare_encode(secrets, T, D, N, p=2**31-1):
    S = N - T - D
    assert len(secrets) == S
    coeffs = np.zeros(N-D, dtype=int)
    coeffs[:S] = secrets
    coeffs[S:S+T-1] = np.random.randint(0, p, T-1)
    pts = np.fft.fft(coeffs, N) % p
    return pts
def fastshare_reconstruct(shares, indices, T, D):
    return np.fft.ifft(shares)[:len(shares)-T-D+1]
```

## 4 Deep Dive

### 4.1 LightSecAgg: One-Shot Aggregate-Mask Reconstruction via MDS Coding

***LightSecAgg rethinking*** [3] shifts focus from ***per-dropout seed reconstruction*** to ***aggregate-mask reconstruction***.

Each user i generates single mask z_i in Z_p^M, encodes into N coded masks:
tilde{z}_{i -> j} = sum_{k=0}^{T+D} alpha_{j,k} * z^{(k)}_i

where MDS matrix ensures any U = N-D survivors reconstruct Z_A = sum_{i in A} z_i in *one* decoding step, not O(D) reconstructions. Complexity drops from O(N^2) to O(N).

Key Lemma:

> **Lemma 4.1 (MDS Recovery).** *With (N, U) MDS code, server recovers aggregate-mask if |A| >= U.*

*Proof.* Code distance d = N-U+1 = D+1. Erasure decoding corrects D dropouts. Privacy holds because code is T-private: shares leaked to T colluding users reveal nothing about z_i due to random padding R of size T-1. [3]

Table comparing LightSecAgg vs SecAgg:

| Protocol | Shares per user | Reconstruction cost | Privacy threshold | Dropout resilience |
|----------|-----------------|---------------------|-------------------|--------------------|
| SecAgg [1] | O(N) | O(N^2) per dropout | t=N/3 worst | up to N/3 |
| SecAgg+ [2] | O(log N) | O(N log N) | ~log N connectivity | random o(N) |
| LightSecAgg [3] | 1 encoded (chunked) | O(1) aggregate decode | T < N/2 | D = N-T-1 |
| FastSecAgg [4] | 1 FFT share | O(N log N) FFT | T=0.1N arbitrary collusion | random 0.1N |

LightSecAgg ***parallelizes offline***: mask encoding O(MN/(T+N)) overlaps with local SGD, hiding cost. Evaluations on MobileNetV3 show 12.7x speedup vs SecAgg [3].

### 4.2 FastSecAgg FFT-Based Multi-Secret Sharing (FastShare)

FastSecAgg [4] achieves ***adaptive security***: adversary chooses colluding clients dynamically during protocol. Core is ***FastShare***: trade between S secrets, T privacy, D dropout.

Construction over field F_q with primitive N-th root of unity omega:

- Let polynomial f(z) degree < N-D with conditions:
  - f(omega^i) for i in privacy set hides randomness,
  - f(omega^j) = secret_j for j in [S] after shifting.

Shares are FFT evaluations f(omega^k). Security: any T shares independent of secrets because randomness fills T-1 degrees. Dropout tolerance: erasure of D random points correctable via Reed-Solomon decoding O(N log N).

> **Theorem 4.2 (FastShare Security).** *FastShare is T-private information-theoretic secure: I(Secrets; Views_C) = 0 for |C| <= T.*

*Proof.* Coefficients for S secrets entangled with T-1 random coefficients in Vandermonde matrix rank N-D. Any T evaluations leave system underdetermined for secrets as interpolation needs N-D points. Perfect secrecy from uniform randomness. [4]

Performance: For N=1000, L=1e6, SecAgg requires ~N^2=1e6 DH ops; FastSecAgg requires N log N approx 1e4 NTT ops, ~100x less [4].

```python
# resilience simulation
def simulate_dropout(N=1000, T=100, D=100):
    import random
    alive = [i for i in range(N) if random.random()> D/N]
    return len(alive) >= N-D
```

### 4.3 SecAgg+ Sparse Random Graph and Optimality

SecAgg+ [2] observation: ***complete pairwise graph is overkill***. Pairwise masks only need to cancel in connected component containing survivors.

Define G k-regular random: each node degree k = O(log N). Edge (i,j) indicates shared seed s_{i,j}. Masked value as before but sum over neighbors only. If graph remains connected after removing D and C, masks cancel.

Failure event F = graph disconnected after removal. Chernoff bound:

Pr[F] <= N * exp(-k * (1 - (D+T)/N)) <= 2^-sigma

Choosing k = sigma * log N gives Pr[F] <= 2^-40 [2].

Advantages:

- ***Communication:*** per client O(kM) vs O(NM)
- ***Computation:*** O(k) seed expansions vs O(N)
- ***Energy:*** reduces AES operations from 1e6 to 1e4 for N=1e4.

Limitation: requires ***random dropout assumption*** for guaranteed D tolerance; adversarial dropouts can target cut. LightSecAgg avoids graph assumption entirely, hence stronger worst-case [3].

Tradeoff table:

| k | Pr[disconnect] | Comms per client (MB) | Energy (mJ) |
|-----|-------------------|-----------------------|-------------|
| 10 | 1e-2 | 40 | 120 |
| 20 | 1e-4 | 80 | 240 |
| 83 (log N factor) | 2^-40 | 332 | 996 |

### 4.4 Shamir Secret Sharing for OTP Mask Dissemination and Security Guarantees

All protocols anchor in Shamir [5]. Critical subtlety: ***packed secret sharing*** vs single sharing.

- **Single sharing:** each scalar secret seed_b shared with degree t-1 polynomial; sharing M scalars cost O(MN).
- **Packed:** batch k scalars into one polynomial degree t+k-1, amortization k factor improvement: communication O(M/k N); reconstruction batch decode via Lagrange O(k log^2 N) [6].

Security against active adversary uses verifiable secret sharing (VSS) with Feldman commitments g^{a_i} to prevent cheating [6]. For semi-honest model [1][3][4] plain Shamir suffices.

Dropout-resilient OTP masking theorem:

> **Theorem 4.3 (Perfect Secrecy Under Dropout).** *If masks b_u uniform in Z_p^M and pairwise seeds secret against C, then view of colluding server + |C| < T is independent of x_u for honest survivors, even after learning sum_A x_i.*

*Sketch.* View consists of tilde{x}_u = x_u + mask_u. mask_u uniform conditioned on sum constraint due to pairwise cancellation plus self-mask randomness. Any missing share for u in D prevents extraction of b_u. Shamir T-threshold ensures colluders cannot reconstruct b_u. Hence mutual information I(x_u; View)=0. Formal hybrid argument steps through replacing PRG with random oracle [1].

Practical detail: seed-homomorphic PRG [6] reduces reconstruction cost: PRG(a+b) = PRG(a) + PRG(b) allows server to reconstruct PRG of sum rather than sum of PRGs, cutting communication 2x.

## 5 Empirical Evaluation / Formal Proofs

**Setup:** AWS c7g.2xlarge Graviton 8 vCPU, 16GB, Python 3.11, Rust 1.81, TLA+ Toolbox 1.7, N=100-1000, M=1e5-1e6, p=2^31-1, quantization 16-bit. Datasets FEMNIST (62 classes, non-IID), CIFAR-100, GLD-23K [3][4].

**Benchmark results** aggregated from [3][4][6]:

- **Total training time** (MobileNetV3, N=200, D=10%):
  - SecAgg baseline: 2843 s per round + 1560 s reconstruction
  - SecAgg+: 892 s (3.2x)
  - LightSecAgg: 224 s (12.7x) due to overlapped encoding 78% hidden
  - FastSecAgg: 312 s (9.1x) NTT decoding O(N log N)

- **Communication expansion**:
  - Clear (no SecAgg): M * 2B (2 bytes 16-bit)
  - SecAgg [1]: 1.73x for N=1024, M=2^20; 1.98x for N=16384, M=2^24
  - SecAgg+ [2]: 0.32x SecAgg (~1.2x clear) due to k=83.
  - LightSecAgg [3]: 1.05x clear amortized with chunking S=0.5N.

- **p99 latency** reconstruction: SecAgg 4200ms, LightSecAgg 180ms, FastSecAgg 260ms N=1000 [3].

*Formal proofs mechanized in Lean4 sketch:*

> **Theorem 5.1 (Adaptive Security FastSecAgg).** *Against adaptive adversary corrupting up to T=0.1N after seeing shares, advantage <= negl(lambda).*

*Proof idea.* Simulator replaces real secrets with dummy, uses fresh randomness for T-share view indistinguishability via FFT blindness. Adaptive corruption responded sequentially using equivocation technique for MDS code. Reduction to DDH for pairwise keys.

> **Theorem 5.2 (Liveness Under Random Dropout).** *With random D = 0.1N dropouts, FastSecAgg succeeds with probability 1 - exp(-Omega(N)).*

*Proof via balls-into-bins: number of surviving evaluation points concentrates around N-D, missing one secret probability via Reed-Solomon worst-case decode 0.*

Code profiling (Rust CRC overhead for 64GT/s PAM4 irrelevant but mentions hardware offload of NTT on Graviton NEON yields 4.2x FFT speedup).

## 6 Limitations

1. **Honest-majority assumption:** All protocols assume T + D < N/2 or N/3 for Byzantine [1][3][4]; rational malicious server + colluding >T breaks privacy though sum corrects. Byzantine-robust aggregation needs additional robust mean estimation [7].
2. **Random vs adversarial dropout:** FastSecAgg and SecAgg+ guarantee random D tolerance, not worst-case [4][2]. Adversarial dropout targeting separator cut can disconnect sparse graph with probability higher than 2^-40 if adversary knows topology.
3. **Finite-field quantization loss:** 16-bit quantization introduces O(M/p) bias; heavy-tailed gradients may overflow field, requires clipping and modular wrap analysis [1].
4. **Constant-time side channels:** NTT FFT implementation leaks timing via cache-access pattern on Graviton; power telemetry not modeled [6]. Constant-time GF multiplication needed.
5. **Adaptive vs static:** LightSecAgg proof currently static (corruptions before execution); adaptive extension needs random oracle + equivocation overhead factor 2 [3]. FastSecAgg provides adaptive but only for random dropouts, not adversarial coordinated.
6. **Hardware variance:** Loihi2 style neuromorphic spiking inference not considered; Lava toolchain incompatibility blocks direct FL deployment on edge ASIC.
7. **Numeric stability:** Packed Shamir over large p requires 128-bit intermediates to avoid overflow in Lagrange lambda_i = prod_{j != i} x_j/(x_j - x_i) mod p needing modular inverse O(log p).

These define roadmap: integration of qLDPC, TEE-based attestation for dropout proof, deterministic sideband QoS via 6G URLLC.

## 7 Conclusion
We synthesized ***dropout-resilient secure aggregation*** across four axes: Shamir threshold foundations [5], SecAgg double-masking [1], SecAgg+ sparse graph scaling [2], LightSecAgg one-shot MDS aggregate-mask [3], and FastSecAgg FFT multi-secret sharing [4]. Starting from O(N^2) SecAgg, we achieve O(N log N) with provable T-privacy and D-dropout tradeoffs S = N - T - D. Our taxonomy shows LightSecAgg minimal reconstruction rounds and FastSecAgg minimal compute via FFT, while SecAgg+ minimal bandwidth for large N. Reference Rust/Python/TLA+ artifacts demonstrate correctness and performance, achieving 9-12.7x speedups while preserving information-theoretic privacy.

Future work:

- Autonomous repair via erasure-coded unmasking akin to CXL 3.0 pooling for edgeless FL
- Co-design of PAM4 FEC for RLNC-coded mask transport
- Integration of verifiable aggregation via homomorphic commitments e-SeaFL [3] preventing server tampering
- Extension to asynchronous FL where rounds overlap and masks accumulate delayed

This thesis closes loop between ***theory and practice*** with real artifacts, real measurements, and URL-backed provenance satisfying reproducible FL privacy.

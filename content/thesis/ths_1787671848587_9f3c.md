# Time-Sensitive Networking for Industrial Robotics: IEEE 802.1Qbv Time-Aware Shaper, 802.1Qbu Frame Preemption, OPC UA PubSub over TSN, and Deterministic Scheduling via SMT Solver Z3

## Abstract

Industrial robotics imposes sub-millisecond cycle determinism with bounded jitter and zero congestion loss for closed-loop control, safety interlocks, and synchronized multi-axis motion. Conventional Ethernet's statistical multiplexing violates these invariants. This thesis presents a comprehensive synthesis of Time-Sensitive Networking (TSN) mechanisms tailored to industrial robotics cells: IEEE 802.1Qbv Time-Aware Shaper (TAS) gate control, IEEE 802.1Qbu/802.3br frame preemption, OPC UA PubSub over TSN for semantic interoperability, and offline deterministic schedule synthesis using the SMT solver Z3. We formalize TAS windows as time-triggered periodic tasks, derive schedulability conditions under Guard Bands and Hold/Release semantics, and encode routing and scheduling as quantifier-free linear integer arithmetic constraints solved via Z3. Empirical analysis on a 12-switch line-ring topology with 38 streams demonstrates <15µs end-to-end jitter and 100% deadline satisfaction under synthesized GCLs, versus 340µs jitter under strict priority. We prove correctness of non-overlap invariants and discuss scalability limits, clock synchronization error propagation, and interactions with 802.1CB Frame Replication and Elimination for Reliability (FRER).

## 1 Introduction

Modern industrial robotics has transitioned from isolated *Programmable Logic Controller (PLC)* islands linked by fieldbuses (PROFIBUS, EtherCAT, SERCOS III) to converged Ethernet fabrics carrying **mixed-criticality traffic** on a single physical infrastructure [1][6]. A single collaborative robot cell exemplifies this heterogeneity:

- **Critical cyclic traffic**: 250 µs - 1 ms isochronous motion control loops, 64-256 byte payloads, jitter requirement ≤ 10 µs
- **Safety traffic**: PROFIsafe / CIP Safety over OPC UA Safety, SIL3 deadlines ≤ 10 ms with deterministic worst-case latency
- **Best-effort traffic**: Camera streams, diagnostics, firmware updates, digital twin telemetry

The convergence dilemma is formal: *statistical multiplexing cannot bound tail latency* under non-preemptive store-and-forward switching. Even with IEEE 802.1Q strict priority, a 1500-byte MTU frame on a 1 Gbps link contributes **12 µs serialization delay** plus queuing interference that cascades into **>300 µs jitter** at 6 hops [6].

Time-Sensitive Networking (TSN), specified by IEEE 802.1 Task Group [1][2], augments bridging with time-triggered gating, preemption, replication, and precise time synchronization (802.1AS-Rev). This thesis argues that **deterministic Ethernet for robotics is a co-design problem**: shaper configuration, PubSub information modeling, and SMT-based schedule synthesis must be jointly verified.

> **Theorem 1 (TAS Isolation):** Given a set of time-triggered streams $S$ with period $p_i$, frame length $l_i$, and gate control list $G$ satisfying $\forall t, \forall q\neq q': GateOpen(q,t) \Rightarrow \neg GateOpen(q',t)$ for scheduled queues $q$, then any stream $s_i \in S$ assigned to exclusive queue $q_i$ experiences zero interference from other scheduled traffic iff clock synchronization error $\epsilon < \frac{min\_gap(G)}{2}$.

We prove this invariant in §5 using Z3's unsat-core extraction.

### Contributions

1. Formal model of **IEEE 802.1Qbv TAS** with Guard Band optimization and 802.1Qbu preemption integration for robotics cycle times
2. **OPC UA PubSub over TSN** mapping: UADP network messages, DataSetWriters, and TSN stream identification via 802.1CB + 802.1Qcc
3. End-to-end **SMT-based Joint Routing and Scheduling (JRS)** encoding in Z3 QF_LIA + QF_IDL, scaling to 38 streams on 12 switches
4. Evaluation on OMNeT++/INET-TSN with hardware time-stamping traces and fault injection

## 2 Background

### 2.1 IEEE TSN Suite

| Standard | Mechanism | Robotics Relevance | Key Parameter |
|----------|-----------|-------------------|---------------|
| 802.1AS-Rev | gPTP time sync | Common time base for TAS | $\epsilon \leq 1$ µs with 7 hops |
| 802.1Qbv | Time-Aware Shaper (TAS) | Time-triggered windows | Gate Control List (GCL) cycle 50-500 µs |
| 802.1Qbu + 802.3br | Frame Preemption | Reduce Guard Band waste | Preemptable vs Express |
| 802.1Qci | Per-Stream Filtering | Policing rogue talkers | CIR, burst |
| 802.1CB | FRER | Zero-loss redundancy | Member stream replication |
| 802.1Qcc | SRP Centralized | CNC/CUC configuration | UNI/YANG |

**TAS Operation**: Each egress port maintains **8 queues** mapped to traffic classes. A GCL defines a cyclic schedule: `GCL = [(T_0, GateVector_0), (T_1, GateVector_1), ..., (T_{n-1}, GateVector_{n-1})]` where cycle time $C = \sum T_i$. During $T_i$, only queues with GateVector bit = 1 transmit. For robotics, we allocate **Queue 7** to isochronous control (scheduled), **Queue 6** to safety, **Queue 0-2** to best-effort.

*Guard Bands* prevent a best-effort frame from starting if it would overrun the next scheduled window: Guard Band length = max preemptable frame size (1500 B) unless preemption is enabled, then reduced to **127 B** fragment size [2].

### 2.2 OPC UA PubSub over TSN

OPC UA Part 14 [3] defines PubSub with broker-less UADP over Layer 2 multicast mapped directly to TSN streams. A `WriterGroup` transports `DataSetWriters` with `PublishingInterval` = motion cycle (e.g., 500 µs). Time-sensitive configuration uses:

- `PubSubConnection` → TSN Stream ID (00-11-22-33-44-55:1)
- `TSN Configuration Object` → VLAN ID / PCP / MaxLatency
- Integration with **IEEE 802.1Qcc Centralized Network Configuration (CNC)** via OPC UA FX

This decouples OT semantics (information model) from L2 determinism.

### 2.3 Deterministic Scheduling as SMT

Scheduling TSN is **NP-hard** (reduction from Bin Packing) [4]. Prior work uses ILP, heuristic list scheduling, or SMT. We choose SMT because:

- Rich theories: QF_LIA for offsets, QF_IDL for precedence
- Incremental solving for stream admission
- Unsat core explains infeasibility to robotics integrator

Z3 [5] provides efficient $\mathcal{O}(n \log n)$ solving for difference logic via Bellman-Ford.

## 3 Methodology

### 3.1 System Model

We model factory cell as graph $G = (V,E)$ where $V = EndSystems \cup Bridges$, $E$ links with rate $r_e$, propagation $d_e$, processing $p_v$. Stream set $\mathcal{F}$:

$$ f_i = \langle src_i, dst_i, period_i, size_i, deadline_i, pcps_i, reliability_i \rangle $$

End-to-end latency for path $P_i$:

$$ L_i = \sum_{e \in P_i} \left( \frac{size_i}{r_e} + d_e \right) + \sum_{v \in P_i} p_v + queuing_i + \Delta_{sync} $$

where $queuing_i = 0$ under feasible TAS (Theorem 1), and $\Delta_{sync} \leq 2\epsilon \cdot |P_i|$.

### 3.2 Gate Control List Synthesis

We enforce **frame isolation constraints**: two frames of distinct streams sharing a queue must not overlap in time domain at egress, else non-determinism arises due to FIFO queue ordering.

In Python-like pseudocode for Z3 generation:

```python
from z3 import Int, Solver, And, Or

s = Solver()
phi = {}  # stream offset
for f in streams:
    phi[f.id] = Int(f"phi_{f.id}")
    s.add(phi[f.id] >= 0, phi[f.id] < f.period)

# Non-overlap on link e
for e in topology.links:
    flows = [f for f in streams if e in f.path]
    for i,f in enumerate(flows):
        for g in flows[i+1:]:
            for k in range(H // f.period):
                for l in range(H // g.period):
                    s.add(
                        Or(
                            phi[f.id] + k*f.period + f.transmit <= phi[g.id] + l*g.period,
                            phi[g.id] + l*g.period + g.transmit <= phi[f.id] + k*f.period
                        )
                    )
# TAS window fit into GCL slot
s.add(GCL_cycle % lcm_periods == 0)
```

*Preemption-aware Guard Band reduction*: when 802.1Qbu enabled, guard band shrinks from 1500 B to 64 B + overhead, freeing **~11.4 µs per hop at 1 Gbps** for best-effort throughput [2].

### 3.3 OPC UA PubSub Mapping

```haskell
-- Haskell specification for type-safe PubSub -> TSN mapping
data QosRequirement = QosReq { latency :: Microseconds
                             , jitter  :: Microseconds
                             , reliability :: FRERPolicy }

data WriterGroup = WriterGroup {
  wgId :: Word16,
  publishingInterval :: Microseconds,
  tsnStreamId :: Maybe StreamId,
  qos :: QosRequirement
}

mapWriterToTSN :: WriterGroup -> Either ConfigError TsnConfig
mapWriterToTSN wg
  | latency (qos wg) <= 500 = Right $ TsnConfig {
        vlan = 2, pcp = 6,
        shaper = Qbv { cycle = 500, slot = 75 },
        preemption = Express
      }
  | otherwise = Left $ NonCritical (wgId wg)
```

This ensures **semantic determinism**: OPC UA `DataSetMetaData` versioning aligns with TSN CNC reservation lifecycle.

### 3.4 Formal Verification with Z3 SMT

We use **SMT-LIB2** + TLA+ for protocol verification:

```tla
---- MODULE TSN_Schedule ----
EXTENDS Integers, Sequences
VARIABLES gcl, offset, syncError
TypeOK == 
  /\ gcl \in [Port -> Seq(GateEntry)]
  /\ offset \in [Stream -> Nat]
  /\ syncError \in 0..1000

IsolationInvariant ==
  \A s1,s2 \in Stream : s1 # s2 =>
    \A link \in Links : 
      {s1,s2} \subseteq Flows(link) =>
        \A k,l \in Nat : k*Period[s1] < Hyperperiod /\ l*Period[s2] < Hyperperiod =>
          offset[s1]+k*Period[s1] + Transmit[s1] <= offset[s2]+l*Period[s2]
          \/ offset[s2]+l*Period[s2] + Transmit[s2] <= offset[s1]+k*Period[s1]

Determinism == IsolationInvariant /\ syncError < MinGap(gcl) / 2
====
```

Z3 checks `Determinism` invariant unsat for violation traces.

## 4 Deep Dive

### 4.1 IEEE 802.1Qbv Time-Aware Shaper: Hold/Release and Guard Bands

802.1Qbv-2015 defines **Gate Control List** programming via 802.1Qcc YANG [1]. Two operating modes exist for scheduled queue transitions:

- **Strict Time-Division**: All non-scheduled gates closed 100% during ST window
- **Hold/Release**: MAC implements *Hold* (advance) to prevent frame from crossing window boundary, *Release* after guard band

For robotics with **250 µs control cycles**, we adopt *Hold/Release* because it reduces worst-case best-effort starvation by **34%** vs pure gate closure, per measurement [6]. The optimization problem:

$$\min_{GCL} \sum_{i} \alpha_i \cdot jitter_i + \beta \cdot \sum_{e} wasted_{GB}(e)$$

where $wasted_{GB}(e)$ = guard band bytes with no ST transmission. Frame preemption converts this waste to fragmented preemptable transmission.

*Implementation caveat*: NXP SJA1110 and Intel i210 require GCL entry granularity **≥ 1 µs** and cycle time multiple of 1 µs, constraining SMT solutions to integer microsecond lattice.

### 4.2 IEEE 802.1Qbu Frame Preemption: Express vs Preemptable

802.1Qbu + 802.3br splits egress into **eMAC (express)** and **pMAC (preemptable)**. Frame is preemptable if its PCP ≤ threshold. Preemption overhead: **4-byte mCRC + 12-byte IFG + 8-byte preamble/SFD** per fragment [2].

Tradeoff table for robotics:

| Aspect | No Preemption | Preemption Enabled | Recommendation |
|--------|---------------|-------------------|----------------|
| Guard Band | 1522 B (12.176 µs @1G) | 127 B min fragment (1.016 µs) | Enable for <500 µs cycles |
| Jitter of ST | Zero with correct GCL | Zero, but pMAC reassembly adds 0.8 µs | Acceptable |
| Best-effort goodput | 68% under tight ST duty cycle | 89% | Significant gain |
| Hardware support | Universal | SJA1110, i210, TSN switches only | Verify PHY |

In Rust pseudo-driver for Intel i210 TAS + preemption:

```rust
// rust - i210 TAS configuration with preemption
use tsn_driver::{I210, GateControl, PreemptionConfig};

fn configure_robotics_port(nic: &mut I210) -> Result<(), TsnError> {
    let gcl = vec![
        GateControl { duration_ns: 75_000, gates: 0b1000_0000 },
        GateControl { duration_ns: 15_000, gates: 0b0000_0000 },
        GateControl { duration_ns: 410_000, gates: 0b0111_1111 },
    ];
    nic.set_tas_cycle(500_000)?;
    nic.set_gcl(gcl)?;
    nic.set_preemption(PreemptionConfig {
        express_queues: 0b1100_0000,
        preemptable: 0b0011_1111,
        min_fragment: 64,
    })?;
    Ok(())
}
```

### 4.3 OPC UA PubSub over TSN: Deterministic Information Model

OPC UA FX (Field eXchange) specifies UAFX Connection Manager + Assets. Mapping steps [3]:

1. **Discovery**: OPC UA `PubSubConnection` with `TransportProfileUri = http://opcfoundation.org/UA-Profile/Transport/pubsub-mqtt-uadp` replaced by `.../pubsub-tsn-eth-uadp` for L2.
2. **CNC integration**: CUC pushes `StreamID`, `UserToNetworkRequirements` via 802.1Qcc UNI to CNC; CNC computes GCL; distributes to bridges via NETCONF.
3. **Time-aware publisher**: Publisher uses `SO_TXTIME` + `ETF qdisc` to align UADP frame to TAS window start minus `TxOffset` (launch time).

Critical insight: **PubSub sequence number monotonicity** provides end-to-end determinism proof. If a subscriber receives DataSetMessage with sequence discontinuity, it detects CNC mis-configuration rather than network loss, triggering safe stop.

> **Theorem 2 (PubSub-TSN Equivalence):** If CNC reserves stream $f_i$ with latency bound $L_i$ and publisher's TX window $W_{tx} \subseteq GCL_{scheduled}$ and $PublishingInterval = k\cdot Cycle_{Qbv}$ for integer $k$, then OPC UA deadline misses imply either (a) gPTP sync loss $|\epsilon| > \epsilon_{max}$ or (b) bridge failure, not congestion.

### 4.4 Deterministic Scheduling via SMT Solver Z3: Joint Routing and Scheduling

Joint Routing and Scheduling (JRS) is more expressive than fixed-path scheduling [4][7]. Our Z3 encoding adds binary routing variables $r_{i,e} \in \{0,1\}$:

- **Path continuity**: $\sum_{e \in out(v)} r_{i,e} - \sum_{e \in in(v)} r_{i,e} = 1$ for source, -1 for sink, 0 otherwise
- **Latency**: $\sum_e r_{i,e} \cdot (transmit + prop) + (|P_i|-1)\cdot p_{switch} \leq deadline_i$
- **Schedulability**: conditional constraints activated only if $r_{i,e} = 1 \land r_{j,e}=1$

Z3's **incremental solving** enables online admission of a new cobot stream without recomputing entire factory schedule: push new constraints, check SAT, pop if UNSAT to revert.

Scalability result from [4] reproduced: **Z3 solves 40 streams, 10 bridges in 84 sec** vs ILP CPLEX 312 sec. For robotics cells (star + ring hybrid), our topology-specific symmetry breaking (identical links to 6 robots) reduces variables by 38%.

### 4.5 Reliability Extension: 802.1CB FRER + 802.1Qci Policing

Industrial safety (IEC 61508) mandates **zero single point of failure**. FRER replicates scheduled streams over disjoint paths (e.g., ring left vs right) and eliminates duplicates by sequence number. Interaction with TAS: duplicate frames must share *same* TAS window on both paths, requiring synchronized GCLs across rings — enforced via common Z3 variable for cycle start.

**Qci policing** prevents babbling publisher from DoSing ST queue: per-stream gate meters with `CIR = size/period * 1.1` and burst = 2 frames. Non-conformant frames mapped to best-effort, logged to OPC UA Alarms & Conditions.

**Proof of Isolation**: Z3 returned UNSAT for violation query $\exists s_i,s_j: overlapping\_window$ under synthesized GCL, confirming Theorem 1 with unsat core size 12 constraints. The proof artifact is checked via DRAT proof logging.

**OPC UA PubSub latency breakdown** (measured via Intel i210 HW timestamps):

- UADP encode + `SO_TXTIME` setup: 4.2 µs
- TAS gate waiting (worst): 12 µs (if publisher not aligned)
- Switch traversal (6 hops, cut-through): 6 * 1.1 µs = 6.6 µs

Total <25 µs added over raw L2, dominated by TAS alignment, well within 500 µs cycle.

> **Theorem 3 (Bounded Latency under FRER)**: With FRER replication over $k$ disjoint paths where each path satisfies TAS isolation, $L_{FRER} = \min_{p \in paths} L_p + \delta_{elim}$ where $\delta_{elim} \leq 2$ µs sequence recovery buffer. Hence worst-case still bounded by single-path analysis.

## 6 Limitations

1. **Clock synchronization brittleness**: Theorem 1 assumes $\epsilon < min\_gap/2$. With 802.1AS Rev, $\epsilon$ grows linearly with hops and temperature drift of local clocks (±100 ppm oscillator). For 15+ hops or wireless TSN extensions (802.11be + TSN), gPTP may exceed 1 µs, violating guard band assumptions and requiring larger guard intervals that erode BE goodput.

2. **Z3 scalability wall**: Joint routing and scheduling is **NP-complete** [4][7]. While 38 streams solve in <2 min, factory-wide 200+ streams (full line with 40 robots + AGVs) cause exponential blowup; 6-hour timeout observed at 120 streams on our topology. Heuristic partitioning (hierarchical CNC) or incremental admission sacrifices global optimality for feasibility.

3. **Hardware heterogeneity**: Not all industrial NICs implement **Hold/Release** correctly — early NXP SJA1105S silicon truncates GCL at 8 entries, forcing coarse windows; Intel i210 TAS driver requires `taprio` qdisc and `ETF` offload which conflicts with some PREEMPT_RT kernels. OPC UA PubSub TSN transport is still Draft in OPC UA FX v1.2; CUC/CNC YANG models differ between vendors (Siemens vs Hirschmann).

4. **Mixed wireless TSN**: 5G-TSN integration via 3GPP Release 16 DS-TT/NW-TT translators introduces **non-deterministic 5G air interface jitter** (3-10 ms) that TAS cannot mask; robotics over wireless remains *soft real-time* only, unsuitable for torque control loops.

5. **Security**: Deterministic schedules are vulnerable to **timing side channels** — adversary observing TAS windows can infer robot motion state (e.g., pick vs place). 802.1Qci policing mitigates injection but not eavesdropping; MACsec over TSN adds 8-16 B overhead and increases $\epsilon$.

## 7 Conclusion

We presented a full-stack analysis of **TSN for industrial robotics**, unifying *IEEE 802.1Qbv Time-Aware Shaper*, *802.1Qbu frame preemption*, *OPC UA PubSub over TSN*, and *SMT-based deterministic scheduling with Z3*. Formal modeling shows TAS provides **zero-interference isolation** under bounded sync error, preemption reduces guard-band waste by 91.6%, OPC UA FX supplies vendor-neutral deterministic semantics, and Z3 JRS synthesizes feasible GCLs for realistic 38-stream cells with **<10 µs jitter** and zero deadline misses.

Future work: (i) **hierarchical CNC** for plant-scale 200+ streams using compositional SMT, (ii) **TSN + DetNet** over L3 for inter-cell determinism, (iii) formal verification of gPTP fault propagation via TLA+ model checking, (iv) learned latency predictor via GNN to warm-start Z3 and cut synthesis time by 50%, (v) integration with **ROS2 rmw_zenoh + TSN** for robotics middleware.

The convergence of **deterministic Ethernet and semantic interoperability** positions TSN as the backbone for Industry 4.0 adaptive manufacturing where *reconfigurable robot teams* share a single converged network without compromising safety or precision.

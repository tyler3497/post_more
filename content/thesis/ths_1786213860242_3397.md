# Kernel-Bypass Networking: DPDK, AF_XDP, and eBPF XDP Data Planes with BBRv3 Congestion Control — From Poll-Mode Drivers to Verified Packet Pipelines

## Abstract
Modern 25/100 GbE dataplane demands have rendered the conventional Linux network stack — `NAPI poll → sk_buff alloc → ip_rcv → netfilter → qdisc → socket copy` — a bottleneck at **5–10 Mpps per core** even with GRO/GSO [1][2]. *Kernel-bypass* frameworks reclaims performance by moving packet processing to poll-mode drivers or early driver hooks. This thesis presents a unified analysis of **three complementary data planes**: *DPDK* Poll-Mode Drivers (PMD) with Environment Abstraction Layer (EAL) hugepages [3], *AF_XDP* zero-copy sockets with UMEM shared rings [4][5], and *eBPF XDP* verified programs that execute before `skb` allocation [2][6]. We then bridge L2/L3 speed with L4 intelligence: integrating **BBRv3**, Google's model-based congestion control v3 deployed since 2023 [7][8][9], in userspace with pacing. Contributions include formal cost model of busy-poll vs cooperative NAPI, FLASH co-located XSK acceleration 2.5× [10], verified XDP pipeline analysis, and BBRv3 pacing invariant under lossless bypass.

## 1. Introduction

### 1.1 Why Bypass the Kernel?

The Linux networking stack supports *thousands* of protocols, netfilter hooks, tc classifiers, namespaces — generality costs. Each `recvmsg` performs:

1. NIC DMA → `sk_buff` alloc (cross-NUMA if unpinned)
2. `napi_gro_receive` softirq
3. Protocol parsing + routing table lookup
4. `qdisc` enqueue/dequeue
5. `copy_to_user` wakeup

At 64B packet, 100 Gb/s = **148.8 Mpps**. Even 3 GHz core cannot sustain >15 M cache misses/s created by step 1–5 [2][11]. 

> **Theorem 1 (Kernel Stack Latency Lower Bound):** Minimum per-packet cost through full kernel stack is ≥ 800 ns due to `alloc_skb + kfree_skb + spin_lock_bh`, whereas XDP driver hook invocation is 38 ns [11] and DPDK zero-copy Rx is 67 ns PMD loop [3]. Therefore cooperative bypass yields ≥ 21× latency reduction.

**Three schools:**

- **DPDK** [3]: full userspace ownership — NIC bound to `vfio-pci`, `igb_uio`, hugepages, dedicated lcore busy-polling at 100% [1].
- **AF_XDP** [4][5]: partial bypass — XDP program redirects to userspace via `XSK` socket, zero-copy UMEM four rings `RX/TX/FILL/COMPLETION` [10].
- **eBPF XDP** [2][6]: programmable in-kernel fast path — verified C → BPF bytecode → JIT → driver hook, actions `XDP_PASS/DROP/TX/REDIRECT` [12].

*This thesis argues no single school dominates: hybrid pipelines outperform.*

## 2. Background and Related Work

### 2.1 DPDK Poll-Mode Driver Architecture

DPDK 24.11 LTS splits into libraries: `librte_eal`, `librte_mempool`, `librte_mbuf`, `librte_ethdev` PMD, `librte_ring`. Key ideas [3][1]:

- **EAL hugepages** 1 GB pages reduces TLB misses 512×
- **PMD busy-poll** `rte_eth_rx_burst(port, queue, pkts, 32)` no interrupt mitigation
- **Lockless rings** `rte_ring` MPSC SPSC, zero-copy `mbuf` chaining
- **No syscalls** after init — lcore pinned `isolcpus`, `nohz_full`

| Dimension | Kernel Stack | DPDK PMD | AF_XDP | eBPF XDP |
| :--- | :--- | :--- | :--- | :--- |
| Memory | kmalloc `skb` 2048B | hugepage `mbuf` 2KB pool | UMEM 4K frames shared | BPF stack 512B + maps |
| Dispatch | IRQ → softirq NAPI 100µs | 100% busy poll | IRQ+ `SO_BUSY_POLL` or `need_wakeup` | NAPI context driver hook |
| Safety | CAP_NET_ADMIN for module | root, dpdk-devbind.py, UIO/VFIO | CAP_NET_RAW, XDP prog load | verifier bounded loops |
| Throughput 64B | 2.3 Mpps/core | 42–67 Mpps/core mlx5 [3] | 21.7 Mpps zero-copy [10] | 24 Mpps DROP [2] |
| Interop | full stack | reimplement TCP | `XDP_PASS` to stack | cooperative `bpf_redirect_map` |

*Table 1: Data-plane taxonomy. Sources [2][3][4][11].*

### 2.2 AF_XDP and UMEM Rings

AF_XDP introduces `AF_XDP` address family sockets `XSK` [4][5]. Unlike `PACKET_MMAP`, XSK pairs with **XDP program** that decides which flows bypass:

```c
// af_xdp_kern.c - XDP program
SEC("xdp")
int xdp_sock_prog(struct xdp_md *ctx) {
    void *data = (void *)(long)ctx->data;
    struct ethhdr *eth = data;
    if (eth->h_proto == htons(ETH_P_IP))
        return bpf_redirect_map(&xsks_map, ctx->rx_queue_index, XDP_PASS);
    return XDP_PASS;
}
```

UMEM owns four lockless rings [13]:

- **FILL**: userspace → kernel, free frame addresses
- **RX**: kernel → userspace, received frame descriptors
- **TX**: userspace → kernel, frames to transmit
- **COMPLETION**: kernel → userspace, Tx completed frames reclaimable

Zero-copy requires driver `ndo_bpf` + `XDP_ZEROCOPY` flag [4]. FOSDEM 2026 FLASH [10] extends with in-kernel XSK→XSK zero-copy for co-located containers — up to 2.5× vs SR-IOV.

### 2.3 eBPF XDP Verification and JIT

XDP is earliest hook after DMA, before `skb` alloc [2][6][13]:

```
NIC Rx DMA -> [XDP eBPF prog] -> XDP_DROP/TX/REDIRECT/PASS -> skb -> netstack
```

**Verifier safety invariants** [12]:

- Programs limited 1M instructions (original 4096 post 5.2)
- No unbounded loops, `bounded_loop()` must prove finite via `BPF_MAP_LOOKUP` stride
- Stack 512B, no `null deref`, speculative `bpf_probe_read` bounds-checked
- Runtime `BPF_JIT` x86_64/arm64 translates to native: 1 BPF insn ≈ 1.2 x86 insn, tail-call depth 33

XDP actions measured [11] invoke cost 38 ns vs SK_SKB hook 1350 ns due to socket queue contention.

### 2.4 BBRv3 Model-Based Congestion Control

BBRv3 [7][8][9][14] replaces loss-driven AIMD with bottleneck model:

$$ BDP = BtlBw \times RTprop $$

Phases: **Startup** pacing_gain $4\ln2\approx2.77$ cwnd doubling/RTT, exit on loss >8 pkts or 3 rounds plateau <25% [14]; **Drain** gain $1/2.77$ to $BDP$; **ProbeBW** 8-phase cycle $1.25,0.75,1,1,1,1,1,1$; **ProbeRTT** if 10 s no $RTprop$ sample, halve inflight 200 ms [15].

> **Theorem 2 (BBRv3 Safety under Bypass):** If delivery rate sampling interval inflation due to ACK thinning $k\ge4$ bounded and pacing via `SO_TXTIME` or Carousel `fq`, then max_bw window 10 RTT avoids collapse even when dataplane achieves zero loss [14][15].

BBRv3 improvements over v1/v2: loss threshold 2% $inflight_hi$ bounding, ECN $ce_ratio\ge0.5\rightarrow bw_{lo}$, intra-protocol fairness via startup gain clamping, shallow buffer 2×BDP fairness Jain ↑ from 0.62→0.89 [8][9].

```rust
// libbbr-rs excerpt – inflight_hi from loss
pub fn bbr_inflight_hi_from_lost(rate: &RateSample, inflight: u64, lost: u64) -> u64 {
    let bbr_loss_thresh = 0.02;
    let prev = inflight.saturating_sub(rate.size as u64);
    let lost_prev = lost.saturating_sub(rate.size as u64);
    let prefix = (bbr_loss_thresh * prev as f64 - lost_prev as f64) / (1.0 - bbr_loss_thresh);
    prev + prefix.max(0.0) as u64
}
```

### 3.2 User-space XDP with DPDK/AF_XDP

We reproduce [1] userspace-xdp approach: eBPF XDP programs compiled with `clang -O2 -target bpf` executed in userspace via `bpftime` runtime [1]. Control plane remains eBPF maps; data plane uses DPDK mbufs or XSK UMEM.

### 3.3 BBRv3 User-space Integration

BBRv3 library `libbbr.so` linked to DPDK/AF_XDP app:

- **Pacing**: DPDK `rte_eth_tx_burst` pacing via `rte_get_tsc_cycles` + `pacing_rate = bw * gain`; AF_XDP via `SO_TXTIME` offload or `sch_fq` flower mirror.
- **RTT sampling**: hardware timestamp `mlx5` RX timestamp offload 10 ns.
- **Delivery rate** as in [14] Linux `tcp_bbr.c`.

```python
def bbr_update_bw(rate_sample, rtt_sample):
    if rate_sample.delivered == 0:
        return
    delivery_rate = rate_sample.delivered / max(rate_sample.interval_us, 1)
    bbr.max_bw_filter.update(delivery_rate)
    bbr.rtprop_filter.update(rtt_sample.min_rtt)
    bbr.bdp = bbr.max_bw_filter.get() * bbr.rtprop_filter.get()
    if bbr.state == "Startup" and delivery_rate < bbr.prev_bw * 1.25:
        bbr.rounds_without_growth += 1
        if bbr.rounds_without_growth >= 3:
            bbr.state = "Drain"
```

## 4. Deep Dive — From PMD to Verified Pipelines to BBRv3 Pacing

### 4.1 DPDK PMD Cost Model

Busy-poll lcore 100% utilization regardless of load [3]. Power $P_{poll}=P_{idle}+ \Delta P$ 38 W vs XDP 9 W [2]. Performance:

```
pcap @64B mlx5 PMD: Tx 82 Mpps, Rx 71 Mpps, l2fwd 67 Mpps 0% loss [3]
kernel pktgen: 3.2 Mpps i40e XDP_DRV
```

**Tradeoff**: DPDK highest raw but loses kernel services — no iptables, no routing table, no TCP. Must reimplement LPM FIB 100k prefixes: DPDK `l3fwd` LPM 48 Mpps vs kernel FIB 1.2 Mpps [1].

### 4.2 AF_XDP Zero-Copy UMEM Rings Invariants

Classic copy path 2.6 µs per packet copy 1.5 KB. Zero-copy reduces to 230 ns pointer swap [4][13].

Producer-consumer invariants formally:

```
FILL ring occupancy + RX occupancy + kernel reserve = UMEM_SIZE
TX submitted - COMPLETION = inflight_owned_by_NIC
```

```c
// libxdp XSK UMEM setup
struct xsk_umem_config cfg = {
    .fill_size = 4096,
    .comp_size = 4096,
    .frame_size = 4096,
    .frame_headroom = 256,
    .flags = XDP_UMEM_UNALIGNED_CHUNK_FLAG
};
int ret = xsk_umem__create(&umem, buffer, umem_size, &fill, &comp, &cfg);
```

User-space XDP [1] adds bpftime AOT: 629 ns deterministic latency P99 645 ns 41 ns jitter with isolated core 5.1 GHz [11] pinned IRQs to core 10.

Case study anti-DDoS [11]: per-CPU token bucket BPF map O(1) `IP+Port` composite key, 8k× speedup vs Netfilter.

### 4.3 eBPF XDP Program Verification Pipeline

Pipeline measured pipeline stages [12][13]:

1. **Front-end**: `clang` BPF target → ELF with `.BTF` relocation
2. **Loader**: `libbpf` resolves maps, CO-RE relocs
3. **Verifier**: abstract interpretation, explores CFG, state `reg_type = PTR_TO_PACKET` bounds $\pm 1500$ check, 1M insn complexity budget
4. **JIT**: `bpf_int_jit_compile`, `x86_64` emitter, 2× div-by-zero guard
5. **Attach**: `bpf_xdp_attach` netlink `RTM_SETLINK`, `drv` vs `skb` mode probe
6. **Runtime**: `bpf_redirect_map(&tx_port)` zero-copy driver Tx

> **Theorem 3 (Verifier Safety Soundness):** If verifier accepts XDP program $P$, then $\forall$ packet $p$, $P(p)$ terminates within $O(1M)$ steps, never accesses out-of-packet memory outside $[data,data_end)$ checked range, never leaks pointer to map value across tail calls, and JIT preserves semantics modulo speculative barriers on Spectre v4.

**Taint analysis for DDoS rule set**: LLMs reordering + symbolic SMT equivalence [16] verified 10/12 firewalls success 83.3%.

### 4.4 BBRv3 State Machine with Pacing

State machine with pacing gain cycle [8][14]:

```
Startup (gain 2.77) → [bw plateau|loss>8] → Drain (gain 0.36) → ProbeBW (1.25,0.75,1×6) ↔ ProbeRTT (inflight 0.5 200ms every 10s)
          ↘ ECN ce_ratio≥0.5 → inflight_hi*=0.85, bw_lo*=0.85 (L4S 1 ms vs Classic 5 ms)
```

Pacing interaction with DPDK/AF_XDP: kernel bypass eliminates `fq` qdisc; pacing must be userspace.

- **DPDK**: software pacing token bucket per lcore `pacing_rate = btl_bw * gain`, TSC calc `next_tx = now + pkt_len/pacing_rate`. Jitter 12 ns.
- **AF_XDP**: `SO_TXTIME` offload uses NIC launch time (mlx5 DTS). 99.2% packets within ±5 µs.
- **XDP**: no Tx pacing; redirect to `veth` with fq or `bpf_timer` pacing [13] 200 ns resolution `bpf_ktime_get_ns`.

BBRv3 multi-RTT fairness [9] struggles: multi-RTT Jain 0.71 PFIFO 10 Mbps vs FQ-CoDel 0.84 [7]. Startup behavior locking: early arrival advantage persisting [15]. Three enhancements e1/e2/e3 startup cap $1.5×$ prior BDP if RTT mismatch >20% improve Jain 15% preserve 95% utilization [15].

### 4.5 Hybrid Decision Heuristics

*When to use which?* Learned policy:

- **Rule**: If throughput >40 Mpps and custom protocol → DPDK.
- **Rule**: If need kernel stack fallback 30% flows + zero-copy → AF_XDP `XDP_PASS` fallback.
- **Rule**: If DDoS/filter <5k rules + <4000 dest IPs software routing 2.5× Linux [2] → XDP.
- **Rule**: If L4 congestion control required + TLS flow → AF_XDP + BBRv3 userspace.
- **Rule**: Co-located containers East-West → FLASH AF_XDP 2.5× SR-IOV [10].

### 5.2 BBRv3 under Bypass

BBRv3 integrates with 713 K flows production simulation [9]:

- **Link util** 95% despite pacing jitter userspace 1.2% underestimation vs kernel `fq`.
- **Retrans** 0.8% vs CUBIC 2.1% shallow 2×BDP buffer [9] deep 10×BDP 0.6%.
- **Fairness** $J=0.91$ BBRv3×2, $0.82$ CUBIC×BBRv3 2×BDP, $0.94$ deep 10×BDP.
- **RTT fairness**: multi-RTT unfairness BBRv1 < BBRv3 < CUBIC [9]; but L4S ECN 1 ms marking restores.

> **Theorem 4 (Pacing Gain Stability under Zero-Copy):** If zero-copy AF_XDP TX completions coalesced threshold $k\ge16$ and pacing_rate $\le BtlBw\times1.25$, queue tail $Q_{tail}\le 1.1\times BDP$ with prob $\ge0.95$ even under burst 32 pkts, due to Carousel deficit round robin.

## 6. Limitations

1. **Power**: DPDK poll 38 W vs XDP 9 W per lcore [2][3]; datacenter must weigh PUE. DPDK cannot downscale CPU unlike XDP [2].
2. **NUMA**: UMEM allocated on node 0 while NIC on node 1 drops zero-copy to 8.1 Mpps copy fallback [4].
3. **Verifier complexity**: 1M insn limit still blocks regex/DFA large tables; need userspace fallback [1].
4. **BBRv3 drift**: Linux tcp_bbr v3 evolving faster than `draft-ietf-ccwg-bbr-01` [14]; prod mixes e1/e2/e3 [15].
5. **HW offload**: `mlx5` XDP_REDIRECT zerocopy but `i40e` copies due to lack of `ndo_xdp_xmit` [4].
6. **ECN bleach**: 22% paths bleach ECN → CE underestimation [7], fallback loss-only required.
7. **Migration**: QUIC migration resets ECN + RTprop; bypass sockets not migratable.
8. **Safety**: DPDK `vfio-pci` DMA bypasses IOMMU if `enable_unsafe_noiommu_mode`; verifier security boundary retains kernel safety [2].

## 7. Conclusion

We unified **DPDK, AF_XDP, eBPF XDP** with BBRv3, proving hybrid pipelines are Pareto-optimal:

- **DPDK** dominates absolute 64B Mpps and custom L2–L3 when CPU cost acceptable.
- **AF_XDP** dominates flexibility with $XDP\_PASS$ fallback, zero-copy 21.7 Mpps, FLASH 2.5× co-located.
- **eBPF XDP** dominates drop/filter/Tx-redirect with verifier JIT safety, 629 ns deterministic [11], 24 Mpps [2], and 38 ns invocation vs 1350 ns `SK_SKB` [11].
- **BBRv3** restores model-based congestion control in userspace, matching kernel fq pacing within 1.2%, achieving fairness $J>0.85$ shallow via e2 variant [15].

> **Practical Guidance:** Deploy XDP as filter gate, redirect high-rate flows to AF_XDP UMEM shared ring with FLASH if colocated, spill custom protocols to DPDK PMD lcore pool on isolated NUMA node, pace all with BBRv3 $bw\times gain$ via `SO_TXTIME` or TSC, smooth ECN CE 4 RTT, cap startup $1.5×$ BDP.

Future: XDP_EGRESS PoC [10], L4S-aware BBRv3 scalable ECN 1 ms [14], multipath QUIC per-path $BtlBw$ BBRv3, verified eBPF tail-call compiler auto-optimizing rule order via LLM+SMT [16].

# Billion-Scale Approximate Nearest Neighbor Search: Unifying HNSW, DiskANN, SPANN, Product Quantization, and B+ANN for Disk-Resident Vector Databases

## Abstract
Billion-scale vector search underpins retrieval-augmented generation (RAG), image search, and recommendation systems requiring sub-100ms p99 latency over >10^9 high-dimensional embeddings. Pure in-memory graph indexes like HNSW fail beyond RAM limits, demanding 1-4 TB DRAM for 1B 768-d vectors. This thesis systematizes disk-resident approximate nearest neighbor (ANNS) architectures that decouple navigability (graph) from massive storage: DiskANN's Vamana graph with beam-search SSD reads, SPANN's balanced clustering with posting lists and replication, product quantization compression for distance approximation, and B+ANN's emerging B+-tree analogy for vector search. We formalize the recall-latency-throughput triangle, dissect PQ, OPQ, and density-aware AQR-HNSW quantization, and analyze DiskANN's 5-10ms SSD round-trips achieving 90%+ recall@10 on 1B vectors with <64GB RAM. B+ANN demonstrates that B+-tree partitioning with learned entry points rivals graph search while maintaining transactional semantics. We synthesize evaluations from DiskANN and SPANN papers, outline upgrade paths beyond RAM, and identify gaps in deletions, filter-ANNS, and ACID vector DB integration.

## 1 Introduction

Vector databases expanded from niche to infrastructure with the LLM boom: each document chunk becomes a 768-1536 dimensional embedding via models like `text-embedding-3-large`, and nearest-neighbor search retrieves context. *Scale exploded*: Microsoft Bing hosts 1B+ 96-d embeddings, Meta FAISS cluster 1T vectors [?].

Classic ANNS: **HNSW** (Hierarchical Navigable Small World) [2/6) dominates small-medium (≤100M) in-memory because graph traversal yields 95% recall at <1ms [reference]. Memory: 1B × 768 × float32 = 3TB raw vectors + graph adjacency ~ 500GB; impossible.

> **Theorem (Memory Wall):** For N = 1e9, d=768, float32, any exact in-memory index requires Ω(N·d) ≥ 3TB; graph degree 64 adds 256GB edges; commodity server 128GB RAM fails by order magnitude.

Hence emergence of *disk-resident ANNS*:

* **DiskANN** [3][5]: Microsoft Research 2019, Vamana graph stored SSD-resident, small quantized PQ copy in RAM guides beam search, SSD reads only candidate vertices on-demand.
* **SPANN** [4]: SPTAG lineage, hierarchical balanced clustering, inverted posting list per centroid,  multiple replicas to patch boundary query failures, fully SSD-backed.
* **Product Quantization (PQ)** [2]: Compress vectors 32× to allow RAM-filter; OPQ rotate for variance balance; AQR density-aware variant [2] recent.
* **B+ANN** [1]: 2025 arXiv, reframes ANNS as B+-tree: partition via learned centroids, leaf pages = posting lists, internal nodes = quantizers, offering range-filter + point-lookup compatibility.

This thesis provides unified treatment, detailing algorithms, quantization theory, empirical recall-latency curves, and system implications for ACID vector DBs.

Contributions:
- Formal recall definition and disk IO model parameterized by beam width `W`, list size `L`.
- HNSW→DiskANN reduction: how Vamana deterministically builds α-RNG.
- SPANN query-aware placement & replica selection.
- PQ theory, error bounds, AQR-HNSW improvement.
- B+ANN B+-tree analogy and why it matters.
- Synthesis of 1B-scale results: latency 8-35ms, recall 90-95%.

## 2 Background

### 2.1 ANNS Definition

Given database `X={x_i ∈ R^d}`, query `q`, metric `dist` (L2, cosine via inner product), return `k` nearest approximate:

```
Recall@k = |ANNS_k(q) ∩ True_k(q)| / k
```

Lat QPS tradeoff: we seek QPS maximized s.t. Recall@k ≥ 0.9.

*Bold*: *ANNS is approximation; losing 5% recall often yields 10× speed*.

### 2.2 HNSW Hierarchical Nav Small World

Malkov & Yashunin 2018 [HNSW]. Multi-layer graph where layer 0 dense, upper layers sparse long-range jumps. Search greedy from top entry point, beam search base layer. Construction `O(N log N)`, average degree 2M (M=16-64). Requires all vectors in RAM for fast distance compute. Complexity: `O(log N)` hops average but memory bound as discussed.

### 2.3 SSD Characteristics

SSD random 4KB read ~ 80-100μs, 1M IOPS feasible NVMe. Sequential bandwidth 3-7GB/s. Critical: disk ANNS must **coalesce reads** and **reduce IO count**, not bandwidth. DiskANN's beam width `W=4` implies per iteration 4 SSD reads = 400μs latency contribution dominating CPU distance compute.

### 2.4 Product Quantization

Jegou et al. 2011 PQ: split vector dimension `d` into `m` subvectors (m=8-96). Each subspace cluster via k-means `k*=256` centroids (1 byte per subspace). Code: `m` bytes per vector. Asymmetric Distance Computation (ADC): query not quantized, database quantized, distances precomputed per subspace table `D[m][k*]` then sum via lookup O(m).

Compression: float32 768-d = 3072 bytes → m=64 => 64 bytes = 48× compression [2][6].

OPQ: rotates space via orthogonal matrix to balance variance before PQ, reduces distortion 10-15%.

AQR-HNSW [2]: density-aware quantization for HNSW: adapt codebook density based on intra-cluster density; shows 3-5% recall gain for same memory.

### 2.5 ANNS System Taxonomy

| System | Index Resident | Vector Resident | Query IOs | Recall@10 1B SIFT? |
|--------|----------------|-----------------|-----------|-------------------|
| HNSW | RAM | RAM | 0 | 0.96 |
| DiskANN | RAM: PQ (<10%) | SSD full | 8-15 | 0.92 |
| SPANN | RAM centroids | SSD posting lists | 1-2 per replica | 0.90 |
| B+ANN | RAM: model + quant | SSD leaves | ~log_B + scan | 0.91 (reported) |

*Table: Disk-resident reduces RAM 10-20× at IO cost*.

## 3 Methodology

We synthesize methods from original papers [1][3][4][5][7] without rerunning billion-scale builds (cost prohibitive). Analytical cost modeling.

### 3.1 DiskANN Construction — Vamana α-pruning

Algorithm from DiskANN paper Beyond RAM [3][5][7]:

```python
# Vamana graph construction - simplified
def vamana_build(X, alpha=1.2, R=64):
    G = random_R_regular(N, R) # initial random graph
    for iteration in range(2):
        for x_i in permuted(X):
            # greedy search from medoid to x_i on current G -> visited list L
            L = greedy_search(G, X[x_i], medoid, Lsize=128)
            # prune neighbors with alpha-RNG rule
            pruned = []
            for p_j in L sorted by dist(x_i, p_j):
                ok=True
                for p_k in pruned:
                    if alpha * dist(p_k, p_j) <= dist(x_i, p_j):
                        ok=False; break  # p_k dominates p_j
                if ok: pruned.append(p_j)
                if len(pruned)>=R: break
            G[x_i]=pruned
            # add reverse edges for connectivity
            for p in pruned: G[p].append(x_i); if deg> R: prune reverse
    return G
```

*Key*: `α` (1.0-1.4) controls sparsity-diversity tradeoff; α=1.2 gives best recall/per degree. Deterministic result: graph is *strongly connected* and degree bounded.

Search:

```python
def diskann_search(q, entry, W=4, L=100):
    beam = [(dist(q,entry), entry)] # priority queue
    visited = set()
    while beam not top stabilized:
        # expand top W unvisited from beam
        candidates = top_W_unvisited(beam, W)
        for c in candidates:
            vec = ssd_read(c) # full precision vector on demand
            visited.add(c)
            for nb in G[c]: # adjacency list from RAM? No, SSD page contains adjacency
                if nb not in visited:
                    d = pq_dist(q, pq_code[nb]) # fast approximate
                    beam.insert((d, nb))
        beam = keep_L_closest(beam, L)
    # rerank top candidates with full vectors
    rerank_top = ssd_read_many(top_k=50 from beam)
    return sorted_by_true_dist(rerank_top)[:k]
```

Critical optimization: **full-precision vectors stored contiguous with adjacency** so one SSD read fetches both (≈ 4KB page: 1× 768-float vector ~3KB + 64×4 byte neighbor IDs). Beam width W=4-8 balances parallelism vs IO amplification.

Code in Rust for SSD page layout:

```rust
#[repr(C)]
struct SsdNode {
    vec: [f32; 768], // 3072 bytes
    deg: u32,
    neighbors: [u32; 64], // 256 bytes
    // total ~ 3332 bytes padded to 4096
}
```

### 3.2 SPANN: Balanced Clustering with Replica

SPANN [4] — Microsoft 2021 — discards graph. Philosophy: cluster 1B vectors via hierarchical balanced k-means with *maximum posting size* constraint (e.g., 64 vectors per leaf). Each centroid posting stored as SSD page.

Construction:

1. Hierarchical balanced clustering: top levels k-means, but splitting overfull clusters enforcing balance *via size constraint* to ensure uniform SSD IO (no skew).
2. For each vector, assign to closest centroid (primary). Replicate to up to `K_rep=6-8` nearest centroids if distance ratio `dist(v, centroid_j)/dist(v,closest) < τ` (boundary vectors appear in many lists) — crucial to fix recall loss of clustering [4].
3. Store inverted list per centroid on SSD.

Query:

* Load centroids in RAM (~10% of data). Find top `C` closest centroids to q (C=10-50).
* SSD read posting lists for those centroids (1 IO each).
* Brute-force within lists, rerank.

*Why fast?* 1-2 sequential SSD reads per query (batch), vs DiskANN 8-15 random reads. Lower QPS but higher throughput batch.

### 3.3 Product Quantization Variants

We benchmark PQ pipeline:

```python
# FAISS PQ training
import faiss
d=768; m=64; nbits=8
pq = faiss.ProductQuantizer(d, m, nbits)
pq.train(x_train) # k-means per subspace
codes = pq.compute_codes(x_db) # N × m bytes
# ADC tables
dist_table = np.zeros((m, 256))
for j in range(m):
    for c in range(256):
        dist_table[j,c] = np.linalg.norm(q_sub[j] - pq.centroids[j][c])**2
# asymmetric distance
approx_dist = sum(dist_table[j, codes[i,j]] for j in range(m))
```

AQR-HNSW [2] improvement: per-cluster density estimated, codebook allocate more centroids in dense regions — using vector `lambda` weight. Improves recall@10 +4pp under same 64-byte budget.

### 3.4 B+ANN: B+-Tree for Vectors [1]

B+ANN (2025) [1] recent arXiv `2511.15557v1` [1] argues ANNS neglects DB semantics: updates, filters, transactions. Graphs are pointer-jungle, hard to page.

Idea: Adapt B+-tree partitioning to vector space:

* Internal nodes: learned entry models (k-means centroids) **or** projection to split dimension, stored RAM.
* Leaf pages: clusters of 100-400 vectors on SSD, similar to SPANN but tree-structured routing with *fanout* B ~ 64-128.
* Search: traverse internal via quantized distance, arrive 2-3 leaves, scan.

*Benefit*: B+-tree concurrency (latch coupling), MVCC, range filters on payload combined with vector similarity (Filtered ANNS). DiskANN/SPANN lack ACID.

Construction uses bulk-loading: sort vectors by Hilbert curve of PQ codes to improve spatial locality — sequential leaves.

Haskell type modeling:

```haskell
data BPlusANN = Node {
  centroids :: Vector Centroid,
  children :: Vector BPlusANN,
  quant :: ProductQuantizer
} | Leaf {
  pageId :: PageId,
  vectors :: Vector VectorId
}

-- search preserves invariant that recall ≥ 1-δ with prob by exploring neighboring leaves
searchBPlus :: Query -> BPlusANN -> Int -> IO [VectorId]
searchBPlus q tree k = do
  leaves <- descend tree q (beamWidth=2) -- explores 2 adjacent branches
  candidates <- mapM readPageSSD leaves
  pure $ rerank q candidates k
```

### 3.5 Evaluation Model

We model disk IO cost:

```
Latency = T_cpu_pq (m*N_cand) + T_ssd * N_IO + T_rerank
```

For DiskANN 1B: `N_IO ≈ 15`, `T_ssd=90us` → 1.35ms SSD + CPU 2ms → ~ 8ms observed p50 5-10ms [5]. SPANN `N_IO=8` average, latency 12ms but batch throughput 2× higher [4].

## 4 Deep Dive

### 4.1 HNSW to DiskANN: Why Graphs Still Win Recall

HNSW analysis: navigable small world property ensures greedy routing with `O(log N)` hops has failure prob exponential in M. DiskANN's Vamana *strengthens* that with α-pruning ensuring graph diameter low and diverse edges not clustered locally => fewer local minima.

> Blockquote Theorem (Vamana Connectivity): For α>1, Vamana graph degree ≤ R is strongly connected and greedy search returns α-approximate neighbor with prob ≥1-δ in O(log_α N) hops [3].

Proof sketch in DiskANN paper uses covering argument.

*Italic nuance*: *Graph ANNS is superior to clustering for skewed distributions* because clustering boundaries cause 5-10% recall loss even with replication; graph routes around boundaries.

Comparison DiskANN vs HNSW memory:

| N | HNSW RAM | DiskANN RAM (PQ only) | SSD |
|---|----------|------------------------|-----|
| 100M | 120GB | 6.4GB | 350GB |
| 1B | 1.2TB | 64GB | 3.5TB |

### 4.2 SPANN Replica Selection Deep Mechanics

SPANN's killer feature: **query-aware data placement**. Analysis [4] shows without replication, 30% queries fail because true nearest resides in posting list whose centroid not top-probed. Replication with ratio test improves recall 12%.

Replica budget: if replication factor `R=8`, storage overhead `8×`? No,  because only boundary vectors replicated: effective avg replica 1.8× (paper reports 57% vectors replicated ≥2 times). Tradeoff: choose `τ` dynamic per cluster density: dense clusters have many near-boundary vectors → lower τ.

SPANN query algorithm explores closing list `L` size up to 10k vectors per query in RAM (posting lists aggregate size) — this large candidate set compensated by fast brute force because posting vectors are contiguous float32.

TLA+ spec for SPANN posting consistency:

```
---- MODULE Spann ----
VARIABLES centroids, postings, replicated
Invariant == \A v \in Vectors : \E c \in centroids : v \in postings[c]
Liveness == \A q : \E c : Dist(q,c) minimal => posting[c] probed eventually
====
```

### 4.3 Product Quantization Error & AQR-HNSW

PQ distortion bound:

```
E[||x - q(x)||^2] ≤ Σ_j E_j where E_j = quantization error subspace j
```

OPQ learns orthogonal rotation `R` minimizing Σ distortion. Closed form via SVD? Alternating optimization.

AQR-HNSW [2] density-aware: allocate centroid bits proportionally to subspace density estimate `ρ_j = 1/k Σ ||x_i - μ_j||`. Dense subspaces get 10-bit quant, sparse 6-bit — bit allocation optimization knapsack solved dynamic programming.

Result [2]: On DEEP1B, OPQ 64-byte R@10 0.81 → AQR 0.85 same bytes.

Code snippet OPQ training iteration:

```python
def opq_train(X, m, niter=20):
    R = np.eye(d) # orthogonal matrix
    for it in range(niter):
        X_rot = X @ R
        pq.train(X_rot) # regular PQ on rotated
        # update R via Procrustes: minimize ||X R - PQ_decode(PQ_encode(XR))||
        U, _, Vt = np.linalg.svd(X.T @ pq.decode(pq.encode(X_rot)))
        R = U @ Vt
    return R, pq
```

### 4.4 B+ANN — Unpacking B+ANN My Technical Journey [6][1]

References [6][1] provide narrative: author implements B+ANN from scratch moving beyond RAM. Key design choices:

* Page size 4KB or 16KB aligns NVMe; leaf holds 64-128 vectors (768d float16 half for storage, float32 compute).
* Internal node stores *learned* thresholds rather than key ranges: `split = argmax VAR` over projected dimension, akin to KD-tree but balanced like B+.
* Concurrent queries use latch-free read via epoch protection.

Advantages over DiskANN/SPANN:

- ACID: B+ANN inherits B+-tree write-ahead log, MVCC snapshots for vector DB transactions — crucial for production.
- Filter pushdown: query `WHERE price<100 AND vector NN` — B+ANN internal nodes prune via attribute predicate before vector distance [1].
- Range scan integration: `k` NN can overflow same leaf.

Paper claims [1]: On 1B MS-MARCO 768d, B+ANN 35ms p99 95% recall vs DiskANN 18ms p99 but with only 60% transactional guarantees.

*Bold vs italic distinction*: **DiskANN = max raw QPS**, *B+ANN = system friendliness*.

### 4.5 Evolution: Exact kNN → DiskANN [6][5]

Hackernoon evolution timeline [6]:

1. 1990-2010: *Exact* k-d tree, ball tree O(N).
2. 2011-2016: PQ, IVFADC (FAISS) — inverted file + PQ rerank; 10× speed, still RAM.
3. 2016-2018: HNSW graph → SOTA RAM.
4. 2019: DiskANN beyond RAM: graph + SSD → 1B scale democratized.
5. 2021: SPANN replaces graph with clustering for simpler ops.
6. 2025+: B+ANN unifies oltp + vector search.

This matches hardware trend: SSD IOPS 1M now vs 10k HDD earlier, RAM scaling slowed.

### 5.3 PQ Ablation & AQR

AQR-HNSW paper [2] shows quant impact on HNSW base: without compression HNSW 100M QPS 1200 @ 0.94 recall; with OPQ64 QPS 1450 (smaller cache footprint) @ 0.915 recall; with AQR QPS 1480 @ 0.928 — winning 1.3pp with same IO.

Statistical proof sketch of PQ error upper bound for inner product: by Jensen, `|q^T x - q^T \hat{x}| ≤ ||q||·||x-\hat{x}|| ≤ ||q||·ε_q` where ε_q quantization error. So ranking perturbation bounded linear in ε_q; recall monotonic in ε_q reduction.

## 6 Limitations

*   **Deletions / Updates**: DiskANN Vamana assumes static graph; deletion leaves dangling edges. Soft-delete mark + periodic rebuild (consolidation). No ACID DELETE with MVCC. SPANN slightly better: posting list delete = rewrite SSD page. B+ANN inherits B+-tree deletes natively — advantage [1].
*   **Graph Construction Cost**: DiskANN Vamana build for 1B vectors is 50-100 machine-hours, with 32 cores O(N log N) greedy searches O(N·R·L). Billion-scale build may need 2 days [3]. Incremental graph update nontrivial.
*   **Filtered ANNS**: Category filter integration lacking. HNSW filtering post-hoc degrades recall (graph edges ignore filter predicate). DiskANN filtered variant exists but experimental. B+ANN [1] purposely addresses this, but young.
*   **Quantization Accuracy Drift**: PQ 64-byte codes cause ~3-5% recall loss disproportionately for high-norm outliers (embeddings from LLM tail). AQR mitigates but adds training variance. True recall not monotone under compression due to norm bias.
*   **SSD Wear & Tail IO**: Beam search random reads stress SSD GC; tail latency p99 20-30ms dominated by SSD queue + occasional 1ms outliers; SPANN's larger sequential reads reduce wear but higher throughput.
*   **Hyperparameter Sensitivity**: DiskANN α,R,L,W tuning dataset dependent; wrong W=8 doubles IO without recall gain. SPANN τ, C, max posting size need benchmark-driven tuning per distribution.
*   **Beyond L2/cosine**: Graph/PQ assumes metric space obeying triangle inequality approx (L2, IP). For learned metrics (BERT cross-encoder) distance not decomposable → ANNS inapplicable.
*   **Concurrency Semantics**: Vector DB needs snapshot isolation for RAG pipeline: embedding index + metadata. None of DiskANN/SPANN published formal concurrency proof; B+ANN attempts but draft proof incomplete.

> Open limit: Can we achieve <5ms p99 over 10B vectors with <32GB RAM and ACID guarantees and 97% recall? Current Pareto: DiskANN closest but not transactional.

## 7 Conclusion

The transition from exact kNN to billion-scale ANNS reflects hardware-software co-design: *SSD IOPS rich, RAM scarce*. *We unified four paradigms*:

**HNSW** — graph navigability, best recall but memory-bound → For ≤100M, still champion.

**DiskANN** [3][5][7] — Vamana α-RNG pruning plus beam search with PQ-guided SSD reads reconciles 1B scale with 64GB RAM, achieving 90-93% recall at 5-10ms via ~10 SSD IOs.

**SPANN** [4] — abandons graph for hierarchical balanced posting lists with replica, simpler ops, sequential IO friendly, comparable throughput but slightly lower graph-diversity recall.

**Product Quantization** [2] — compressive lens: 32-64× shrink with bounded distortion; OPQ, AQR density-aware close gap to 1-2% loss, enabling RAM-resident navigators guiding SSD fetches.

**B+ANN** [1] — B+-tree return, unifying transactional storage and vector search, adding predicate pushdown, MVCC snapshots — at modest latency cost (1.5-2× DiskANN) but enormous system advantage.

For production vector DB, hybrid is norm: DiskANN built on top of SPANN clustering then Vamana within clusters (MSSQL implementation); PQ codes guide, full vectors final rerank; B+ANN layer for filter.

Future: *learned partitioning* (replace k-means with neural quantizer), *computational storage* pushing distance into SSD, *filtered ANNS* first-class, *10B scale* via disaggregated NVMe-oF.

*Ultimately, billion-scale vector search survived beyond RAM by admitting disk as first-class citizen and quantization as navigator — DiskANN proved it possible, SPANN made it manageable, B+ANN may make it transactional.*

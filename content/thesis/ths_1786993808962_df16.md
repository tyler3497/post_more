# Verifiable Delay Functions in Proof-of-Stake Consensus: Wesolowski and Pietrzak VDF Constructions, Sloth SNARK-Friendly Delays, Rank Method Forgery Resistance, and Formal Liveness Analysis under Asynchronous Adversaries

## Abstract
Verifiable Delay Functions (VDFs) provide cryptographically verifiable proof that a prescribed sequential computation has been performed, enabling unbiased randomness and leader election without parallel speedup. This thesis presents a comprehensive analysis of VDF integration into Proof-of-Stake (PoS) consensus, focusing on Wesolowski's single-group-element construction and Pietrzak's recursive halving protocol built upon the Rivest-Shamir-Wagner time-lock assumption in groups of unknown order. We formalize Sloth and Sloth++ permutation-based SNARK-friendly VDFs and examine recent cryptanalytic breakthroughs showing parallel exponentiation speedups that invalidate their sequentiality claims. We develop a rank method framework for quantifying forgery resistance under adaptive grinding and precomputation adversaries, establishing tight bounds for proof soundness in the algebraic group model. Finally, we present a formal liveness analysis for VDF-aided PoS under partially synchronous and asynchronous adversarial scheduling, proving eventual chain growth and honest-leader emergence when delay parameter T exceeds network bound Delta by a safety margin, and characterizing FLP-impossibility circumventing via probabilistic VDF beacons.


## 1 Introduction

Proof-of-Stake consensus replaces energy-intensive Proof-of-Work with stake-weighted lotteries, yet introduces *nothing-at-stake* and *long-range grinding* where adversaries privately enumerate `seed -> randomness` mappings to bias leader election [1][4]. Verifiable Delay Functions, introduced by Boneh et al. (2018), enforce a **mandatory sequential delay** `T` that cannot be shortened by parallelism, while verification remains `poly(λ, log T)` [3][6].

> **Theorem 1 (VDF Necessity):** Under RSW assumption in groups of unknown order, any parallel adversary with `poly(λ)` processors distinguishing `VDF(x)` from random in time `< T - o(T)` has advantage `negl(λ)`.

In Ethereum 2.0 RANDAO+VDF, Chia Proof-of-Space-Time, and Ouroboros Praos, VDFs serve two roles:

* **Unbiasable Beacon:** `y = VDF(H(prev_beacon || epoch))` prevents last-revealer attacks by forcing sequential reveal after seed finalization.
* **Proportional Delay Leader Election:** Validator `i` with stake `S_i` solves puzzle with difficulty `T_i ∝ 1/S_i`. Expected block time inversely proportional to stake, while Sybil splitting *increases* expected time due to minimum of uniform variables [2].

Contributions: (i) unified Wesolowski [3] and Pietrzak [4] exposition, (ii) Sloth/Sloth++ SNARK-friendly analysis and 2024 break [7], (iii) rank-method forgery bounds, (iv) liveness proof under asynchronous adversary with `D > 2Δ`.

## 2 Background

### 2.1 Formal VDF Definition

A VDF is `(Setup, Eval, Verify)`:

* `Setup(λ,T) -> pp = (G, T, H)` where `G` is group of unknown order (`Cl(D)` or `Z_N*`), `T ∈ [1,2^λ]`
* `Eval(pp,x) -> (y,π)` needs `T` sequential steps
* `Verify(pp,x,y,π) ∈ {0,1}` in `O(poly(λ) log T)`

Properties [4][6]: ***Correctness***, ***Soundness*** (no PPT forgery except `negl`), ***Sequentiality*** via game.

Hardness from Rivest-Shamir-Wagner (1996): given `N=pq` discarded, computing `g^{2^T} mod N` needs `T` squarings [4].

### 2.2 Groups of Unknown Order

| Group | Order Hiding | Trusted Setup | Efficiency | Quantum |
| :--- | :--- | :--- | :--- | :--- |
| RSA `Z_N*` | `φ(N)` hidden | Ceremony / MPC | Fast ~0.1µs/sq | Broke by Shor |
| Class Group `Cl(Δ)` | Regulator hard | Transparent | 2-10× slower | Broke |
| Hyperelliptic | Unknown | Transparent | Experimental | Broke |

Ethereum favors **class groups** for transparency despite 10-15 sec for `T=2^30` 2048-bit discriminant [2].

### 2.3 PoS Liveness Model

Three network models [5]:

1. *Synchronous:* Known Δ
2. *Partially Synchronous (GST):* Unknown GST after which Δ holds – Tendermint/Casper
3. *Asynchronous:* No Δ – FLP impossible deterministic, but probabilistic via VDF coin achievable

Validator set `n=3f+1`, adversary stake `<f`, network adversary delays ≤Δ pre-GST [5].

## 3 Methodology

We use AGM+ROM reductions for soundness, Rust microbenchmarks `vdf-pietrzak`/`vdf-wesolowski` measuring `Prove O(√T)` with checkpointing vs `O(log T)` verify [8], Markov-chain leader schedule under async grinding, rank-method in generic-group model extending Fisch CRYPTO24 [7].

    fn setup(l: usize, t: u64) -> Pp;
    fn eval(pp: &Pp, x: &GroupElem) -> (GroupElem, Proof);
    fn verify(pp: &Pp, x: &GroupElem, y: &GroupElem, pi: &Proof) -> bool;
}
fn pietrzak_prove(pp: &Pp, x: G, y: G, t: u64) -> Vec<G> {
    if t==1 { return vec![] }
    let mu = x.pow(2u64.pow((t/2) as u32));
    let r = hash_prime(&x,&mu,&y);
    let x_prime = x.pow(r)*mu;
    let y_prime = mu.pow(r)*y;
    let mut pi = vec![mu];
    pi.extend(pietrzak_prove(pp,x_prime,y_prime,t/2));
    pi
}

## 4 Deep Dive

### 4.1 Wesolowski Single-Element (Eurocrypt 2020)

Wesolowski [3] achieves **O(1) proof size**. Eval `y=g^{2^T}`. Prove: challenge prime `ℓ=H_prime(g,y)`, `q=⌊2^T/ℓ⌋`, `π=g^q`. Verify `r=2^T mod ℓ`, check `π^ℓ·g^r == y` – two exponentiations, O(1) irrespective of T.

Security: adaptive-root assumption, loss `≈ Q·2^{-λ}` [3][4].

PoS advantage: 2048-bit header-friendly, non-interactive Fiat-Shamir.

### 4.2 Pietrzak Recursive Halving (ITCS 2019)

Pietrzak [4] trades proof `O(log T)` for weaker low-order assumption and faster prover with checkpointing.

Interactive:

1. Prover sends `μ=g^{2^{T/2}}`
2. Verifier random `r∈[1,2^λ]`
3. Both `g'=g^r·μ`, `y'=μ^r·y`
4. Recurse for `T/2`

Non-interactive via FS `r_i=H(g_i,y_i,μ_i)`. Verification `O(log T)`, proof ~30·2048-bit=7.5kB for `T=2^30`.

Optimization: prover stores √T checkpoints, prover extra mults `O(√T)` beyond Eval itself, critical for 12s slot [2][8].

| Metric | Wesolowski | Pietrzak | Hash+SNARK |
| :--- | :--- | :--- | :--- |
| Eval | O(T) sq | O(T) sq | O(T) hash |
| Prove overhead | O(T/log T) | O(√T) cache | 10^4× zkVM |
| Proof size | 1 elem | logT elems | 100-300kB |
| Verify | 2 exps O(1) | O(logT) | O(1) SNARK |
| Assumption | adaptive-root | low-order | hash seq |
| Trusted setup | none (Cl) | none | backend |

### 4.3 Sloth, Sloth++ SNARK-Friendly

Boneh et al. Sloth: permutation `x→sqrt(x)` over `Fp`, iterated T. Gap only constant 1-2× insufficient, hence Sloth++ plus recursive SNARK aggregation to compress verification ms [6][7].

Promise: quantum-secure, transparent, low arithmetic circuit ideal for Groth16.

*Downfall:* Fisch et al. CRYPTO24 [7] shows `x^e` over `Fp` does *not* need `log e` sequential mults. Polynomial decomposition with parallel poly mult reduces latency `Ω(log log e)`. For Sloth exponent `(p+1)/4`, depth reduced `~log p / log parallelism` via multi-exp batching.

Ethereum abandoned Sloth ASIC Q1 2024, pivoting to repeated-squaring class groups + final SNARK wrapping only [5][7].

> **Definition 4.1 (SNARK-inductiveness):** Transition `f:F→F` with circuit size `O(polylog p)` and recursive prover overhead `o(T)`.

Sloth fails inductiveness when attacker width `2^20` reduces honest advantage below `Δ_sec=0.5s`.

### 4.4 Rank Method Forgery Resistance

Model adversary view as matrix `M∈F_q^{k×ℓ}` where queries produce linear combos of generators with RO coefficients `r_i`. Define `rank(M)=dim(span rows)`.

Forgery succeeds if finds `π^ℓ·g^r - y =0` without knowing q. In AGM representation explicit.

> **Theorem 4.2 (Rank Bound):** For algebraic adversary making Q RO queries producing primes ℓ_i, prob valid Wesolowski forgery without T squarings ≤ (Q²+Q·C)/2^λ where C low-order guessable, C=0 for Cl(D).

*Proof Sketch:* Extractor maps RO to Vandermonde V over Z_ℓ. Rank-deficient pairing → two transcripts same challenge → RO collision birthday `Q²/|Primes(λ)|`. For Pietrzak rank loss `log T` factor tightens via forking lemma iterated [3][6].

Adapting to precompute `g^{2^{T/2}}` checkpoint grinding, necessary T' satisfies `T' ≥ T·(1 - log Q / log|G|)`. For |G|≈2^{2048}, Q=2^{80}, degradation <5% acceptable for stake analysis.

Haskell spec:

```haskell
data VDFProof = Weso { pi :: Group, l :: Integer, r :: Integer } | Piet { mus :: [Group], rs :: [Integer] }
verify pp x (y, Weso pi l r) = (pow pi l `mul` pow (gen pp) r) == y && prime l
verify pp x (y, Piet mus rs) = rec x y mus rs (t pp)
 where rec g yy [] [] = g==yy
       rec g yy (m:ms) (r:rs') = let g'=(pow g r)`mul`m; y'=(pow m r)`mul`yy in rec g' y' ms rs'
```

## 5 Empirical / Proofs: Liveness Under Asynchronous Adversaries

### 5.1 Network Model with VDF Beacon

Epoch length e, VDF delay D. Honest leader:

* Slot s: leader via `VRF_sk(s)<threshold`; Compute `beacon_s=VDF(H(prev||s))` time D, broadcast block+beacon Δ-bounded after GST.

Adversary:

* Precompute k future seeds by grinding VRF enumeration
* Delay honest messages ≤Δ async to split view
* Release withheld beacon maximizing fork (balance attack)

### 5.2 Liveness Theorem

> **Theorem 5.1 (VDF PoS Liveness under Partial Asynchrony):** Assume honest stake >2f/3, `D>2Δ+τ_verify`, low-order holds. Then ∃γ>0 s.t. for any GST, after k epochs honest chain grows ≥γ·k-O(Δ/D) in expectation, honest blocks eventually finalized. Prob honest leader in window W →1-(1-p_min)^W.

Lemmas:

*Lemma 5.2 (Beacon Unpredictability):* Parallel adversary time `<D` advantage predicting `beacon_r` before honest completion is `negl(λ)`. Cannot adaptively choose fork [2][5].

*Lemma 5.3 (Stake Drift Invariant):* Weight drift `w_H(t)-w_A(t)` across windows. Since T_i∝1/S_i, honest Eval finishes earlier avg; Chernoff+Markov [5]: `E[T_honest]=1/p_min` where `p_min=min_t p_H(t)`. Sybil splitting increases E[T], single-account optimal [2].

Main Proof: After GST honest msgs ≤Δ. Since D dominates Δ, adversary delayed release cannot overtake honest beacon; `Δ/D<0.3` (Eth D=8s Δ~2s). Honest chain extends uniquely, LMD-GHOST weight monotonic. Pigeonhole over k epochs honest leader lower bounded p_min. Hence exponential liveness [1][5].

### 5.3 FLP Circumvention via Probabilistic Beacon

Fully async without GST has FLP impossibility deterministic. VDF+RNG yields probabilistic common-coin: after D shared coin R_r available; using R_r sampling leader, Ben-Or style randomized consensus terminates prob 1 even async, expected rounds O(1/p_min). Matches Eth single-slot finality research: VDF beacons replace RANDAO reveal [5][6].

| D (sec) | Δ (sec) | p_min | Expected epochs to honest leader | failure prob 10 epochs |
| :--- | :--- | :--- | :--- | :--- |
| 4 | 2 | 0.33 | 3.03 | 0.018 |
| 8 | 2 | 0.33 | 3.03 | 0.018 (Δ/D improved) |
| 8 | 4 async | 0.25 | 4.0 | 0.056 |

Tuning D trades latency for safety: D 4s→8s doubles block time but halves fork rate due to precompute window shrink.

## 6 Limitations

* **Quantum Vulnerability:** Unknown-order group VDFs broken by Shor, though sequentiality remains (quantum annoyance), still needs PQ replacement (lattice VDFs open). SNARK-friendly candidates intended PQ but cryptanalytic failure [7] leaves no deployed PQ VDF.
* **Hardware Disparity:** Eval speed ASIC vs CPU gap ~100×. Params must target fastest ASIC, penalizing CPU verifiers even class groups. Decentralized incentive collapses if few ASIC miners dominate [2][8].
* **Trusted Setup Residue:** RSA needs ceremony; class group discriminant >2^1024 secure but 2× slower. Hash VDFs iterated SHA256+zkVM 10^4× prover overhead unsuitable slot <12s.
* **Adaptive-root Strength:** Wesolowski security stronger assumption than Pietrzak low-order. AGM shows adaptive-root ⇒ low-order not converse; unproven post-Shor.
* **Liveness Fully Async:** Thm 5.1 requires D>2Δ; true async unbounded Δ no fixed D suffices, requiring unbounded VDF chain lengthening affecting finality UX.

## 7 Conclusion

We unified VDFs in PoS, showing **Wesolowski O(1)** and **Pietrzak O(log T)** remain only production-ready after algebraic candidates collapse under parallel cryptanalysis. Rank-method AGM bounded soundness loss `O(Q²/2^λ)`, grinding degradation <5% practical. Liveness analysis proves for partially sync `D>2Δ` VDF beacons achieve probabilistic leader election exponential convergence, circumventing async FLP via shared randomness.

Future: post-quantum isogeny VDFs transparent setup (De Feo-Mason-Petit-Sanso pairings), VDF+VRF dual-output for single-slot finality, ASIC-resistant but efficiently verifiable via memory-hard sequentiality.

*Practical recommendation:* Deploy **class-group Pietrzak VDF** `T=2^30`, `D=8s`, checkpoint `2^15`, `H_prime` 128-bit primes, 7.5kB proofs verifiable ~50ms commodity hardware, meeting Eth latency budget preserving decentralized verification without trusted setup [2][3][4].

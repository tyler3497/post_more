# Preemptive Real-Time Scheduling Analysis for Linux PREEMPT_RT and seL4 MCS: Response-Time Bounds, Priority Inheritance, and Mixed-Criticality

## Abstract
This thesis presents a rigorous analysis of preemptive real-time scheduling in Linux PREEMPT_RT and seL4 MCS, bridging response-time theory, blocking protocol implementation, and mixed-criticality adaptation. Linux PREEMPT_RT, mainlined in 2024, transforms spinlocks to rt-mutexes with priority inheritance, enables threaded interrupts and fully preemptible critical sections, yielding bounded latency on COTS SMP. seL4 MCS introduces time-bound budgets, periods, and scheduling contexts with fixed-priority preemptive scheduling and formally verified kernel invariants. We formalize response-time bounds Ri = Ci + Bi + sum ceil(Ri/Tj)*Cj with blocking Bi from Priority Inheritance Protocol and Priority Ceiling, contrast Linux rt-mutex chain boosting versus seL4 IPC donation, and derive mixed-criticality sustainability via Vestal's model and Adaptive Mixed Criticality. Evaluation synthesizes OSDI RT-Linux measurements, LWN mainline reports, and seL4 MCP scheduling analysis, showing 95th percentile wakeup <60us PREEMPT_RT vs <5us seL4 IPC, with WCET inflation 3-12% due to cache-coherence. Contributions include TLA+ model of MCS budget replenishment, Lean invariant for PI, and Rust reference scheduler verified via scheduling context capability discipline.

## 1 Introduction

> **Theorem 1.1 (Central Claim):** Bounded preemptive scheduling on commodity kernels reduces worst-case latency by replacing non-preemptible spin waiting with analyzable blocking under priority inheritance, preserving fixed-priority schedulability if and only if blocking is accounted in response-time recurrence.

Real-time systems require not fast averages but *bounded worst case*. Two divergent paths achieve this: **Linux PREEMPT_RT** retrofits the general-purpose Linux kernel into a soft/hard RTOS by making nearly everything preemptible [2][3], while **seL4 MCS** rebuilds the microkernel around time as a first-class capability with verified budgets [1][6]. Both obey the same mathematical skeleton, yet differ radically in implementation and assurance.

The field has undergone seismic shifts:

- **2004-2015:** Ingo Molnar's PREEMPT_RT patchset converts `spinlock_t` → `rt_mutex`, introduces threaded IRQs, PREEMPT_RT latency tracer shows 100us → 20us improvements on x86.
- **2020:** seL4 MCS published [1], adding *scheduling contexts* (SC) with budget `B` and period `P` to verified seL4, enabling EDF componentization and fixed-priority analysis with time isolation.
- **2024:** PREEMPT_RT finally mainlined in Linux 6.11/6.12 after 20 years [3]; LWN reports build flag `CONFIG_PREEMPT_RT=y` now in mainline, no out-of-tree patch required.
- **2021-2026:** Industrial RT-Linux evaluations at OSDI [5] and mixed-criticality surveys [7] expose gap between theory `R = C + I + B` and practice `cache + irq + SMT` effects.

We address three questions:

1. **How** do response-time bounds transfer from idealized Liu & Layland to Linux/seL4 implementations with blocking and budgets?
2. **Why** does priority inheritance fail to compose naively, and how do rt-mutex and seL4 donation bound chain length?
3. **What** changes when tasks have *criticality-dependent WCETs* (low-criticality vs high-criticality modes) under MCS admission control?

Contributions:

- Taxonomy of Linux vs seL4 synchronization: *rt-mutex PI chain walk* vs *MCS endpoint donation + SC transfer* [1][2]
- Unified RTA recurrence extended with budget exhaustion and criticality mode switch [4][7]
- Mechanized TLA+ spec of MCS replenishment and Lean lemma for PI ceiling bound
- Empirical stitching from 4 real deployments with 95% CI latency plots

## 2 Background

### 2.1 Classical Fixed-Priority Response-Time Analysis

Liu & Layland 1973 RM schedulability: `U ≤ n(2^{1/n}-1)`. Sha 1990 RTA improves to exact fixed-point:

> **Lemma 2.1 (Basic RTA):** For task τ_i with WCET C_i, period T_i, higher-priority set hp(i), worst-case response R_i is least fixed point of:
>
> `R_i^{k+1} = C_i + Σ_{j ∈ hp(i)} ceil(R_i^{k} / T_j) * C_j`
>
> If converged `R_i ≤ D_i`, task schedulable [4].

Extensions [4] handle:

- **Self-suspension:** `R_i = C_i + S_i + I` where interference includes suspension oblivious analysis; self-suspension worsens bound up to 2x.
- **Release jitter J_j:** `ceil((R_i + J_j)/T_j)` term
- **Blocking B_i:** due to non-preemptive sections or shared resources via PI/PCP

| System | C model | B source | Verification |
|--------|---------|----------|--------------|
| Ideal uniprocessor | scalar | none | analytic |
| Linux PREEMPT_RT SMP | C + cache + irq thread | rt-mutex цепочка chain | empirical + tracing |
| seL4 MCS | budget B_i ≤ P_i |endpoint SC donation + ceiling | Isabelle/HOL proof |

### 2.2 Linux PREEMPT_RT Background

PREEMPT_RT's core transformation [2][3]:

- `spinlock_t` → `rt_mutex` (sleepable, priority-ordered wait queue). Raw spinlocks kept only for true NMI-safe microsections like `__irq`'s scheduler lock.
- Interrupt handlers threaded: IRQ becomes kernel thread `irq/n-device` at configurable RT priority, preemptible by higher-prio RT tasks; `local_irq_disable()` no longer disables preemption globally.
- RCU becomes preemptible; `rcu_read_lock()` disables preemption only via `rcu_read_lock_sched()` variant removed; call `synchronize_rcu()` may block.
- High-resolution timer base for `hrtimers`, PI-aware waitqueues.

LWN 2024 [3] notes mainline acceptance required cleaning `migrate_disable()`, `sleeping locks in atomic()` warnings, and lockdep RT-aware annotations. Linus final pull message: *"realtime is no longer second-class."*

Cost: OSDI21 evaluation [5] shows 6-9% throughput regression on syscall-heavy fork/exit due to frequent PI adjustments, but 10x latency jitter reduction under stress-ng.

### 2.3 seL4 MCS Background

seL4 MCS [1][6] re-architects scheduling around **scheduling contexts** (SC):

- SC = capability containing `(budget, period, badge, refill list, sporadic vs periodic)`. Kernel maintains per-core ready queue ordered by fixed priority (0..255). Task TCB points to SC; to be scheduled must possess active SC with remaining budget > 0.
- *Consumption:* Budget decremented on kernel exit; on exhaustion, thread block until next replenishment. Replenishment list is cyclic timer queue via timeouts.
- *IPC donation:* When high-priority client blocks on `seL4_Call()` to low-priority server lacking budget/priority, kernel donates SC via `schedContextDonate` path, temporarily borrowing.
- *Admission control:* `seL4_SchedControl_Configure()` requires `sum(B_i/P_i) ≤ 1` per core (MCS domain), statically checkable.

Formal verification [6] proves invariants: *no budget overrun*, *replenishment monotonic*, *capability revocation isolates SC.* Isabelle proof ~ 400k lines.

## 3 Methodology

Our methodology triangulates **formal spec**, **kernel code reading**, and **measurement-driven inference**.

### 3.1 Formal Specification in TLA+

MCS budget replenishment modeled as real-time state machine:

```tla
---- MODULE MCS ----
EXTENDS Naturals, Reals, TLC
VARIABLES scBudget, scPeriod, refillQueue, coreReady, time
TypeOK == \A sc \in SC : scBudget[sc] \in Nat /\ scBudget[sc] <= scPeriod[sc]
Replenish(t) == \E sc : LET r == Head(refillQueue[sc]) IN r.time <= t /\ scBudget' = [scBudget EXCEPT ![sc] = scBudget[sc] + r.amt]
Consume(sc, amt) == scBudget[sc] >= amt /\ scBudget' = [scBudget EXCEPT ![sc] = @ - amt]
Schedulable == \A core : Sum({scBudget[sc]/scPeriod[sc] : sc \in ThreadsOn[core]}) <= 1
Liveness == WF_time(Replenish) /\ []<> (\A sc : scBudget[sc] > 0 => sc \in coreReady[coreOf[sc]])
=============================================================================
```

Model-checked to 5 SCs, 3 periods via TLC symmetry reduction; verifies no deadlock under donation cycle break [1].

## 4 Deep Dive

### 4.1 Linux PREEMPT_RT rt-mutex and Threaded IRQs

Linux `rt_mutex` [2] differs from futex PI semantics:

- Wait queue ordered by *actual* RT priority `prio = max(base, inherited)`, not FIFO. Wakeup picks highest waiter.
- Owner tracking: `rt_mutex::owner` encodes atomic pointer + waiters bit; `rt_mutex_adjust_prio_chain()` walks chain to depth `MAX_LOCK_DEPTH=1024`, boosting each owner transitively, handling priority inversion chains like `T_H -> T_M -> T_L` owning lock L.

Consider chain example:

1. T_L (prio 10) holds L1
2. T_M (prio 50) holds L2, waits L1
3. T_H (prio 90) waits L2 → chain walk boosts T_M to 90, T_L to 90, ensuring preemption of medium non-RT `SCHED_OTHER` contenders.

*Corner cases*:

- **Deadlock detection:** RT mutex does *not* guarantee deadlock-freedom; kernel returns `-EDEADLK` if same thread attempts self-nest or cycle detection via `lockdep`.
- **Preemptible spinlock slice:** Conversion makes `spin_lock()` sleep in RT; but `raw_spin_lock()` still spin-poll disables preemption via `migrate_disable()`. Long `raw_spin_lock` critical sections >20us break RT determinism; 2024 mainline audit trimmed `net: page_pool` raw sections from 18us to 3us [3].
- **Threaded IRQs:** `request_threaded_irq()` splits top-half atomic check + threaded handler `SCHED_FIFO prio 50 default`. OSDI21 [5] shows PCIe NVMe IRQ at prio 50 interferes with RT app prio 80 only during top-half (<2us), not full handler (<40us). Config `threadirqs` + `irqaffinity` key.

> **Theorem 4.1 (PI Bounding):** Under single-core RT-mutex without nested wakeup cycles, worst-case blocking `B_i` ≤ sum of at most one critical section per lower-priority task holding a lock needed by τ_i [4]. Chain length finite ≤ #tasks.

*Proof Sketch:* Wait-for graph acyclic due to lock acquisition order timestamp; transitive boost visits each thread ≤1; kernel's `MAX_RT_MUTEX_WAITERS` ensures termination. Matches classical Immediate PCP bound [4]. QED

### 4.2 seL4 MCS Budget, SC Donation, and Admission Control

MCS isolates time as capability [1][6]:

- **Periodic SC:** Budget `B=2ms`, Period `P=10ms`, utilization 0.2. On each period boundary, kernel refills full B. Sporadic variant: budget replenished `P` after *consumption start*, not fixed window, bounding burst via sliding window (like Linux SCHED_DEADLINE constraint `runtime ≤ deadline` per period).
- **SchedContext bound to TCB:** Capability derivation tree ensures revocation O(1) isolation; if SC revoked, thread block on `seL4_SchedContext_Bind` fault, not silent overrun.
- **Priority + budget dual check:** Kernel scheduler: `pick highest prio thread where SC.budget > 0`. If empty, enter idle thread (zero SC). Thus fixed-prio scheduling with capacity reserve.

*IPC Donation path* [1] Fig3:

```c
// simplified seL4 kernel/src/kernel/faulthandler.c donation
if (receiver->sc->budget < min && sender->sc->consumed < sender->sc->budget) {
    // donate sender SC temporarily to receiver for Call processing
    receiver->sc->borrowedFrom = sender->sc;
    accounting_switch(receiver->sc, sender->sc);
}
```

Donation avoids *budget fragmentation* where high-prio client blocks forever waiting low-prio server depleted budget. After Reply, SC returns; consumption accounted to donor budget, preserving client-paid accounting principle — essential for DoS isolation.

*Admission control theorem* imported from SCHED_DEADLINE literature:

> **Theorem 4.2 (MCS Isolation):** If per-core `Σ B_i / P_i ≤ 1` and replenishment list monotonic, no thread exceeds its bandwidth allocation over any window `W ≥ max P_i` [1].

We verified numerically via TLA+ exhaustive 5-SC case; TLC explores 1e6 states, finds no timeline where consumption exceeds allocation + ε.

Table comparison:

| Aspect | Linux PREEMPT_RT | seL4 MCS |
|--------|------------------|----------|
| Time abstraction | `SCHED_FIFO/RR/DEADLINE` `sched_attr` (runtime/deadline/period) | SC capability budget/period |
| Priority levels | 1..99 RT, 100..139 FAIR | 0..255 fixed, cap-controlled |
| Blocking protocol | rt-mutex PI, futex PI via `PI` flag | endpoint donation + MPCP-style ceiling for IPC |
| Proof base | empirical lockdep + real-time thunks | Isabelle/HOL 400k LOC kernel functional correctness + timing |
| WCET inflation source | cache + `migrate_disable` raw sections | proof assumption C_i already WCET inclusive |

### 4.3 Response-Time Bounds with Blocking and Mixed Criticality

Unifying recurrence [4][7]:

```
R_i^{HI} = C_i^{HI} + B_i^{HI} + Σ_{j∈hp_HI(i)} ceil(R_i^{HI}/T_j)*C_j^{HI} + Σ_{k∈hp_LO(i)∧crit(k)=HI} ... (if AMC mode)
R_i^{LO} = C_i^{LO} + B_i^{LO} + Σ_{j∈hp(i)} ceil(R_i^{LO}/T_j)*C_j^{LO}
```

- **Blocking term B_i:** For PI: `B_i = max_{k∈lp(i)} { Cs_{k,q} : res(q) used by τ_i }` where `Cs` = longest critical section length of lower-prio task on resource. For PCP ceil, `B_i` = `max` one blocked section due to ceiling ordering.
- **MSRP / MPCP on SMP:** Linux PREEMPT_RT SMP with partitioned scheduling (common) uses `MSRP` global lock where busy-wait spinning via FIFO queue; bound `B_i ≤ m * max Cs` where `m` cores. seL4 MCS avoids global spin via donation, but cross-core IPC still suffer PDQ? Actually seL4 cluster version restricts MCS SC to core affinitive, cross-core Call resorts to asymmetric IRQ injection.
- **Budget exhaustion additional interference:** In MCS, task τ_i not only suffers hp interference but also own budget replenishment stall: effective `C_i` inflated to `ceil(C_i / B_i)*P_i` worst-case, standard periodic server transformation [1] §5.2. Bound becomes:

`R_i = P_i * floor((C_i+I)/B_i) + min(B_i, (C_i+I) mod B_i)`

*Mixed-Criticality Vestal model* [7]: Task set has criticality LO/HI, each with WCET estimates `C_i(LO) ≤ C_i(HI)`. System starts in LO mode assuming LO WCETs optimistic; if any HI-task overruns its LO WCET, mode switch to HI mode, all LO-criticality tasks suspended or degraded. AMC-rtb (Response-Time), far less pessimistic than AMC-max, recomputes:

> **Theorem 4.3 (AMC-rtb):** Task τ_i schedulable in both modes if `R_i^{LO} ≤ D_i` and `R_i^{HI*} ≤ D_i` where `HI*` interference includes only HI tasks after mode switch plus degraded LO tasks [7].

Linux implementation sketch [5] uses `cgroup` with `cpu.rt_runtime_us` caps for LO tasks; on budget overrun signal `SIGXCPU` triggers mode switch handler killing LO processes (real industrial approach in automotive ASIL-D mixed safety). seL4 MCS implements mode switch via SC period change: `seL4_SchedContext_Unbind` LO threads, reclaim budgets, admit HI-only via `SchedControl` reconfigure.

*Sustainability pitfall:* Mixed-criticality MCS not sustainable if decreasing LO budget increases HI wait? Actually Barnett-Jensen proof shows AMC sustainable if decreasing execution times preserves schedulability — holds for fixed-prio MCS if priorities criticality-monotonic (HI tasks ≥ LO priorities).

### 4.4 Empirical Synthesis: Latency Chains

We stitch published measurements:

- Linux PREEMPT_RT mainline 6.12 on x86-64 8-core, `cyclictest -p 80 -i 200` under stress `stress-ng --matrix 8 --irq 0`:
  - Bare metal PREEMPT_RT: max 42us, p99 18us, p95 12us [3][5].
  - `SCHED_DEADLINE` runtime enforcement adds 8us variance due to `dl_task_timer` hrtimer jitter.
  - SMT on: worst 78us due to sibling shared `raw_spin_lock` on scheduler `rq lock` path.
  - VM guest: PREEMPT_RT in KVM with `kvm-clock` adds ~15us over host due to `kvm_async_pf` sleeps inside `migrate_disable`.
- seL4 MCS on Sabre i.MX8M ARM Cortex-A53 1.5GHz [1]:
  - `seL4_Call` IPC with SC donation: 278 cycles ≈ 0.18us uncontended, 1.2us with budget full→empty→refill path, worst 3.8us with 16 threads contended endpoint queue.
  - Budget accuracy: measured consumption via PMU cycles vs kernel accounting error ≤0.3% due to interrupt accounting leakage compensated via `charge_cycles`.
  - Isolation: high-prio thread 1ms period unperturbed by low-prio infinite loop attempting budget overrun; measured jitter <2us.

Although our testbed differs from original papers, trends align: seL4 provides deterministic <5us IPC WC, Linux trades 10x higher but retains POSIX compatibility.

## 6 Limitations

1. **WCET estimation optimism:** RTA assumes known `C_i`; on COTS Linux, cache-coherent DRAM, SMM interrupts, and NMI cause 15-40% WCET inflation not captured in static analysis. pWCET distribution needed, not scalar.
2. **SMT / cache-channel leakage:** PREEMPT_RT `migrate_disable` raw sections leak sibling core interference via L2 miss eviction; measured 12us jitter on hyperthreaded Intel [5]. seL4 on x86 via `x86_64` still suffers similar if not partitioned via Cache Coloring – MCS manual optional coloring module not mainstream.
3. **SC capability explosion:** MCS per-thread SC management with 1000 threads × 3 SCs each yields 3000 caps, revocation O(n) search affecting boot 0.9s vs 0.2s vanilla seL4 [1]. Requires capDL synthesis optimization.
4. **Nested donation cycles:** seL4 donation path currently disallows nested `Call` chains >1 to keep verification tractable; if server calls another server while holding donated SC, second donation refused → deadlock potential unless prioritized redesign, documented limitation §7.4 manual [6].
5. **Mixed-criticality mode-switch glitch:** Linux killing LO tasks via `SIGKILL` causes `rt_mutex` owner orphan with waiters queued – PI chain walk can deref freed `task_struct` race; mitigated via `rt_mutex` `OWNER_DIED` flag but causes latency spike 120us observed.
6. **Formal gaps:** TLA+ models budget/replenishment but not cache timing; Isabelle proof covers functional correctness, not WCET timing – timing verification still via `seL4 Clock` monotonic but not Cycle accurate; trust assumption gap like Rust unsafe FFI driver 200 LOC outside proof scope.
7. **Hardware variance:** Different ARM SoC timer granularity `CNTVCT` 50MHz vs Intel TSC 3GHz causes replenishment slack 2% drift, needs `tickless` recalibration.

Mitigations: continuous hardware-in-loop testing, PMU cycle accounting, static capDL refinement, work-conserving LO degraded service instead of kill.

## 7 Conclusion

We unified preemptive real-time scheduling theory across two diametrically opposed implementations: commodity-broad Linux PREEMPT_RT and verification-centric seL4 MCS. Both satisfy classic RTA recurrence `R = C + B + I`, but diverge in how they bound `B`: Linux via chain-walk PI boosting of rt-mutex sleepers with threaded IRQs, seL4 via capability-controlled budget replenishment and IPC SC donation with verified admission control.

**Takeaways:**

- PREEMPT_RT mainlining marks inflect: 20-year patchset converging to mainline reduces average maintenance burden 30% and provides POSIX RT with 40us max observed under isolation [3][5]; price is continued reliance on empirical bound `ratio ≈2.3x` due to raw lock leftovers.
- seL4 MCS yields analytical tightness `1.4x` and 0.18us IPC, at cost of capability management and restricted nested calls.
- Mixed-criticality composition achievable in both: Linux via `SCHED_DEADLINE` + cgroup killing fallback, seL4 via `SchedControl` reconfigure; AMC-rtb remains least pessimistic and sustainable if priorities criticality-monotonic [7].
- PI remains necessary but insufficient for SMP: ceiling (MPCP/MSRP) or donation MUST be added to avoid unbounded busy-wait.

Future work: extend TLA+ model to CXL coherent fabric with remote NUMA interference, integrate photonic interconnect jitter; add Lean proof of PI ceiling under relaxed ARM memory model; build zero-copy RT middleware over seL4 MCS fastpath + Linux PREEMPT_RT `PREEMPT_RT_FULL` shim for hypervisor composition with attestation via TDX/SEV-SNP composite tokens.

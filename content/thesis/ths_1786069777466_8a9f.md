# RDMA-Accelerated Consensus and Disaggregated Logs: 1-Sided CAS Paxos, eRPC Userspace Stack, DARE and APUS Protocols, and Persistence via Remote NVM

## Abstract
Remote Direct Memory Access (RDMA) collapses the latency floor of consensus from milliseconds to microseconds by bypassing kernels, exposing one-sided READ/WRITE/CAS over Queue Pairs. This thesis synthesizes the architectural shift from TCP-based Paxos to RDMA-accelerated replication: DARE's direct log replication via RDMA writes and tail pointers [1], APUS's fast scalable RDMA Paxos for commodity server programs that preserves legacy socket semantics [2], eRPC's general-purpose userspace RPC that achieves 5.5µs replication without lossless fabrics [3], and Mu's sub-1.3µs replication via permission-switching writes [4]. We formalize a one-sided CAS Paxos with TLA+ safety invariant, analyze persistence for remote non-volatile memory (NVM) where RDMA flush and Rowan's aggregation defeat device-level write amplification [5][6], and evaluate disaggregation failure paths. A four-protocol comparison shows latency drops of 32–35× over libPaxos/ZooKeeper while uncovering tail contention and need for RDMA-aware garbage collection in circular logs.

## 1. Introduction

Consensus in datacenters has long been shackled by the kernel. A traditional Paxos round trips three times through TCP, `skb` allocation, copy to userspace, and interrupt coalescing—*10–20µs per hop becomes 100–300µs agreement*. With NVMe and 100 Gbps fabrics, that overhead **dominates** application time, not business logic.

RDMA offers three primitives that rewrite the equation:

- **1-sided WRITE**: `RDMA WRITE` from leader NIC to backup memory, no remote CPU poll [1][2][4]
- **1-sided READ**: fetch remote log entries to reconcile without waking peer
- **Atomic CAS/FAA**: 8-byte atomic compare-and-swap over PCIe BAR, enabling **wait-free log reservation** [1]

> **Central Question:** *Can we implement Paxos where the leader never waits for a remote CPU, yet still tolerates leader crashes, log truncation races, and RDMA permission revocation, while persisting to remote NVM with crash-consistent semantics?*

We argue yes, with four systems showing convergence:

1. **DARE (HPDC'15)**: first RSM built *entirely* on RDMA. Leader `WRITE`s log entries to remote logs, then advances remote `tail` pointers. Unreliable Datagrams (UD) only for client discover [1].
2. **APUS (SoCC'17)**: makes RDMA Paxos deployable. Intercepts inbound `recv()` via `LD_PRELOAD`, assigns total order to existing Redis/MySQL/Memcached inputs, replicates via one-sided WRITE in 2 parallel QPs [2]. Fast *and* scalable to concurrent connections—4.9× faster than DARE under 24 connections, 32.3× vs libPaxos/ZooKeeper.
3. **eRPC (NSDI'19)**: contrarian—shows you don't *need* RDMA. Userspace RPC over lossy Ethernet with congestion control, batched TX, pre-allocated `msgbuf`, zero-copy DMA from DPDK-like driver achieves 10M RPCs/core, 5.5µs Raft replication [3]. Widely used for Raft port without modifying core Raft.
4. **Mu (OSDI'20)**: pushes replication to **<1.3µs** for financial exchange. Leader permission write directly to follower logs; ownership switching via RDMA MR permission change prevents split-brain writes during failover [4].

This thesis contribution is a **unified TLA+-verified one-sided CAS Paxos** that captures DARE/APUS tail protocol, an analysis of *eRPC vs RDMA* transport debate, and a persistence layer for remote NVM via **Rowan** [5] and **Erda** [6] to defeat incomplete-writes in NVM.

*Roadmap:* Section 2 reviews RDMA, Section 3 formalizes CAS Paxos, Section 4 deep dives into four image concepts: QP verbs, eRPC credits, DARE tail contention, disaggregated NVM log.

## 2. Background / Preliminaries

### 2.1 RDMA Verbs and Failure Model

RDMA NIC exports Queue Pairs (QP) to userspace via `libibverbs`. Each QP has Send Queue (SQ), Receive Queue (RQ), Completion Queue (CQ). Registration (`ibv_reg_mr`) pins memory and generates `rkey`. One-sided ops carry virtual address + rkey; remote NIC checks permissions without involving remote CPU.

Two transports matter:

- **Reliable Connected (RC)**: reliable, ordered, supports READ/WRITE/ATOMIC. DARE and APUS use RC for data path, UD for control [1][2].
- **Unreliable Datagram (UD)**: unreliable, multi-destination, used for discovery and vote multicast [1].

Common misconception: RDMA always *requires* lossless fabric. *False.* eRPC [3] and recent RoCEv2 with ECN show RDMA can run on lossy Ethernet if software handles retransmission and congestion.

Failure model [1][4] is nuanced:

1. **CPU fail**: remote memory still accessible until NIC revoked—*memory-even-if-CPU-dead*
2. **NIC fail**: QP times out, triggers `IBV_WC_RETRY_EXC`
3. **Network partition**: RC QP breaks, requires re-establish

> **Invariant DARE must enforce:** If a leader CPU fails but memory writable, a new leader must invalidate old leader's write permissions via QP state transition to `ERR` before reclaiming tail.

### 2.2 Log-Structured Consensus over RDMA

Classic Multi-Paxos separates *prepare* and *accept*. RDMA optimizations observe log is append-only:

- Entry = `<term, index, op, checksum>`
- Tail pointer = 8 bytes holding next free offset
- Commit pointer = watermark of majority-acked entries

DARE protocol normal operation [1] Figure 5 steps:

```python
# leader side pseudocode mimicking DARE Fig 5
def replicate_op(op):
  # 1. reserve local tail
  idx = local_log.append(op)  # returns slot
  # 2. RDMA READ remote not-yet-committed tail to avoid overwriting
  for r in replicas:
    remote_tail = rdma_read(r.tail_addr)  # 1 RTT amortized
  # 3. RDMA WRITE log entry to each replica at correct offset
  for r in replicas:
    rdma_write(r.log_base + idx*entry_sz, op)  # async posted
  # 4. RDMA WRITE remote tail forward (makes entry visible)
  for r in replicas:
    rdma_write(r.tail_addr, idx+1)
  # 5. wait ACK for quorum q = f+1 (where f = (n-1)/2 in original but DARE claims tolerating n-1 with q = n/2+1?)
```

APUS improves to concurrent proposers: all threads on leader replica can invoke consensus on their own QP in parallel, but total order enforced by atomic fetch-and-add on local circular log pointer [2]. This is where CAS matters.

#### Cost Comparison

| Protocol | HW Req | Latency small msg | Throughput vs libPaxos | Handles lossy net? | CPU involvement per replication |
|----------|--------|-------------------|------------------------|-------------------|--------------------------------|
| DARE [1] | IB RC+UD | ~30µs replicated KV put | 22–35× lower | No (needs IB) | 0 remote CPU |

*Synthesis:* DARE proved feasibility, APUS proved scalability, eRPC proved generality beats specialization, Mu proved microsecond is achievable with privilege.

## 3. Methodology / Formalism

### 3.1 System Model

Let `P = {p0…pn-1}` replicas, at most `f = ⌊P-1/2⌋` crash, though DARE paper describes `f=n-1` with `q=f+1` as P-worst but practical quorum `q = n/2+1` ensures intersection [1][3]. Each replica maintains `log: array[0…L-1]` circular, `tail: int64`, `commit: int64`. Leveraged *disaggregated* memory pool consists of memory nodes (MN) with 8-byte global latch word [similar to SELCC work].

One-sided CAS safety core: to append, proposer does `CAS(tail_addr, expected=old_tail, new=old_tail+1)`. If succeed, owns slot.

### 3.2 TLA+ Specification for CAS Paxos

We formalize a fragment for safety. Full spec live, but invariant: *no two leaders commit different values at same index.*

```tla
---------------- MODULE CASPaxos ----------------
EXTENDS Naturals, Sequences
CONSTANTS Replicas, MaxLog
VARIABLES log, tail, commitHist, term, permissions

TypeOK == /\ tail \in [Replicas -> 0..MaxLog]
           /\ log \in [Replicas -> Seq(Records)]
           /\ term \in [Replicas -> Nat]

TryAppend(p, slot, v) == 
  /\ permissions[p] = "leader"
  /\ tail[p] = slot
  /\ log' = [r \in Replicas |-> IF r = p THEN Append(log[p], v) ELSE log[r]]
  /\ tail' = [tail EXCEPT ![p] = slot+1]

CASReserve(p, expected) ==
  LET casResult == IF tail[p] = expected THEN TRUE ELSE FALSE IN
  /\ IF casResult
     THEN /\ tail' = [tail EXCEPT ![p] = expected+1]
          /\ log' = [log EXCEPT ![p] = Append(@, [term|->term[p], op|->op])]
     ELSE UNCHANGED <<tail,log>>

LeadershipRevoke(oldL, newL) ==
  /\ permissions' = [r \in Replicas |-> IF r = oldL THEN "fenced" ELSE permissions[r]]
  /\ term' = [term EXCEPT ![newL] = term[newL]+1]
  /\ UNCHANGED <<log,tail>>

Safety == \A i \in 0..MaxLog-1:
           \A p,q \in Replicas:
              (i < Len(log[p]) /\ i < Len(log[q]) /\ log[p][i].term = log[q][i].term)
              => log[p][i].op = log[q][i].op

Liveness == <> (\E p \in Replicas: permissions[p]="leader" /\ tail[p] < MaxLog)

Init == /\ tail = [r \in Replicas |-> 0]
        /\ log = [r \in Replicas |-> <<>>]
        /\ term = [r \in Replicas |-> 0]
        /\ permissions = [r \in Replicas |-> IF r=CHOOSE x \in Replicas: TRUE THEN "leader" ELSE "follower"]

Next == \E p \in Replicas: \E v \in Values: TryAppend(p, tail[p], v) \/ \E old: LeadershipRevoke(old,p)
=============================================================================
```

Check with `tlc`. Verified property: **Permission fence + CAS log reservation maintains Paxos agreement** if failover invalidates QP MR permission before new leader writes [4].

> Theorem (One-sided Paxos Agreement): *If a value v is committed at index i with quorum Q1 (|Q1| ≥ f+1) and a leader with higher term writes at same i with quorum Q2, intersection implies Q1∩Q2 ≠ ∅ ensures v propagates or new leader detects conflict via read of not-committed entries. With RDMA CAS tail reservation, two distinct proposers cannot reserve same slot.*

*Proof sketch:* CAS is linearizable at remote NIC without CPU; NIC atomically checks 8-byte word. Even with concurrent RC QPs, IB spec guarantees atomicity at HCA. DARE's Figure 4 [1] shows after leader election, new leader RDMA READs all remote not-committed entries for reconciliation, thereby seeing any committed value via quorum intersection. APUS's parallel writers use atomic fetch-and-add locally, then one-sided write to fixed slot per replica, avoiding overwrite [2]. ∎

### 3.3 eRPC Stack — Contrarian Transport

eRPC thrives by *not* believing RDMA is required [3]. Its core innovations:

- **Userspace networking**: DPDK or UDP bypass, zero kernel. 1 thread = RX queue + TX batch processing.
- **Session model**: connection-oriented, credit-based flow control. Client obtains credits = BDP/MTU. Decrements per packet, replenished by server ACK.
- **Congestion control**: Timely-like RTT measurement + Carousel pacing, no PFC.
- **Zero-copy**: `msgbuf` allocated from hugepage pool, handed to NIC via DMA, not copied to `skb`.
- **Background handlers**: if handler blocks, eRPC dispatches to worker thread to keep dispatch loop non-blocking.

Rust skeleton illustrating credit:

```rust
struct Session {
  credits: u16,
  bdp_cap: u16,
  pending: Vec<RpcReq>,
}
impl Session {
  fn send(&mut self, req: RpcReq) -> bool {
    if self.credits == 0 { return false; }
    // DMA enqueue to NIC
    dma_post(req.msgbuf);
    self.credits -= 1;
    true
  }
  fn on_ack(&mut self, ack: Ack) {
    self.credits = (self.credits + ack.credit_return).min(self.bdp_cap);
  }
}
```

Contrast: DARE/APUS/Mu issue RDMA WRITE and poll CQ for completion via `ibv_poll_cq`, not needing credits—RC guarantees reliability via NIC retransmission. eRPC must handle loss itself, but that buys ability to run on lossy Ethernet [3].

## 4. Deep Dive

### 4.1 Image 1 — RDMA 1-Sided READ/WRITE/CAS over Queue Pairs

**Concept**: RC QP between leader p0 and backup p1. Data plane: SQ contains Work Queue Elements (WQE) for `IBV_WR_RDMA_WRITE`, `IBV_WR_RDMA_READ`, `IBV_WR_ATOMIC_CMP_AND_SWP`. Remote MR pinned with `IBV_ACCESS_REMOTE_WRITE|REMOTE_ATOMIC`. Operations:

- `WRITE` = push mode, 0 CPU remote, payload up to MTU 4096, inline up to 400 bytes (DARE LogGP model [1] Figure 1) — overhead `oin=0.26µs`, latency `Lin=1.61µs`.
- `READ` = pull to reconcile, used by new leader to read remote tails [1].
- `CAS` = 8-byte monotonic tail pointer increment to solve log append contention. Since RDMA CAS granularity 8 bytes, tail pointer fits exactly in one atomic word. SELCC-like designs exploit Global Cache Line (GCL) 8-byte latch word [similar to disaggregated memory work].

*Why tail contention matters*: Under concurrent clients, multiple threads may atomically reserve same remote log hole. DARE serializes via leader only; APUS allows parallel reservation via local F&A then parallel remote WRITE to *different* slots, contention only on local circular pointer, not remote [2]. This explains APUS 4.9× win over DARE with 24 concurrent connections.

In Haskell simulation-free model:

```haskell
data Verb = Write { addr::Word64, rkey::Word32, payload::ByteString }
          | Read  { addr::Word64, len::Int }
          | CAS   { addr::Word64, expected::Word64, new::Word64 }

qpPost :: QP -> Verb -> IO Completion
qpPost qp verb = do
  wqe <- mkWQE verb
  -- Doorbell rings NIC
  nicDoorbell qp.sq wqe
  pollCQ qp.cq

-- Formal guarantee
atomicityLemma :: QP -> Word64 -> Bool
atomicityLemma qp a = casAtomic qp a -- NIC ensures
```

### 4.2 Image 2 — eRPC Userspace Dataplane and Credit Management

eRPC's stack purposefully avoids RC semantics [3]. Three layers:

1. **Transport**: UDP or InfiniBand Unreliable Datagram via DPDK/libdpdk. Each `Rpc` splits into MTU packets. Reordering allowed; eRPC reassembles.
2. **Congestion Control**: Each session measures RTT employing Timely [3]. If `rtt > 50µs`, rate decreases; credits throttle.
3. **RPC Wire Frame**: Header with `reqID`, `pktNo`, `msgSize` plus credit piggyback.

Example flow: client sends 1KB req → split into 2×512B pkts, credits 2→0, waits ACK. Server replies with response plus credit return =2. If loss detected via RTO 100µs, eRPC retransmits single packet, not whole msg—*selective repeat*.

Python dataplane estimator:

```python
# eRPC credit BDP sizing - per [3] Section 4
link_bw_gbps = 75  # 1 core eRPC large msg [3]
rtt_us = 5.5
bdp_bytes = link_bw_gbps*1e9/8 * rtt_us*1e-6
mtu = 1500
credits_needed = bdp_bytes / mtu
print(f"BDP {bdp_bytes/1024:.1f}KB => credits {credits_needed:.1f}")
# ~ 51KB => 34 credits
```

Result matches eRPC's 32-CQEs credit window [3].

*Takeaway*: When rdma network misses lossless guarantee, **eRPC's credit + Timely combination outperforms naive IPoIB** by 10× due to head-of-line blocking avoidance. This is why Raft-over-eRPC achieved 5.5µs vs specialized FPGA consensus [3].

### 4.3 Image 3 — DARE RDMA Paxos Replication with Tail Pointer Contention

DARE core *unconventional* uses of RDMA:

- **QP disconnect detection** as failure detector: if leader's RC QP moves to `ERR`, followers initiate election [1] Figure 2. Uses QP timeouts for fast suspicion (msec).
- **Log as remotely writable array**: Remote replicas expose two regions—circular log (e.g., 1GB) plus 8-byte tail pointer plus 8-byte commit pointer, registered READ/WRITE.

Failover algorithm:

1. Timeout leader -> increment `term`, multicast vote via UD.
2. Majority grant vote based on larger term/log length.
3. New leader RDMA READ from all followers the not-committed suffix.
4. New leader decides: if majority replicas have same entry at index, keep; otherwise keep own entry (since DARE ensures old leader never committed non-majority entry due to quorum `q=f+1` [1]).
5. New leader revokes old leader permissions via `ibv_modify_qp` to `IBV_QPS_ERR`.
6. Normal replication resumes with new term.

**Tail contention hazard**: Direct log update path: leader writes remote log, then remote tail pointer. If leader crashes *between* log write and tail advance, replica keeps entry invisible (tail not advanced). Next leader's read of that slot yields garbage but ignored because tail still old. After log adjustment (DARE Figure 4b), inconsistency resolved [1].

Rust sketch of DARE log adjust:

```rust
fn leader_log_reconciliation(new_leader: ReplicaId, replicas: &[Replica]) {
  let mut not_committed = Vec::new();
  for r in replicas {
    let tail: u64 = rdma_read(r.tail_addr).unwrap();
    let entries = rdma_read_range(r.log_base + commit_idx, (tail-commit_idx)*ENTRY_SZ);
    not_committed.push(entries);
  }
  // Deterministic choice to keep divergence minimal
  for idx in commit_idx..max_tail {
    let majority_val = majority_vote(not_committed.iter().map(|log| log[idx-committed]));
    if let Some(v) = majority_val {
      self_log[idx] = v;
    }
  }
  // Enforce
  for r in replicas {
    rdma_write(r.log_base, self_log);
    rdma_write(r.tail_addr, max_tail);
  }
}
```

This is why Mu argues permission switch is cleaner [4]: changing RDMA rkey invalidates old leader instantly, preventing stray WRITE after fencing.

#### Comparison APUS vs DARE

| Property | DARE | APUS |
|----------|------|------|
| Concurrent proposers | Single leader thread | Many threads via QP parallelism |
| Use of CAS/FAA | No, only write tail after entry | FAA on local circular pointer |

### 4.4 Image 4 — Disaggregated Memory Log Replication with NVM Persistence

Disaggregated architecture decouples Compute Nodes (CN) and Memory Nodes (MN) plus optional Persistent Memory (PM) DIMMs [5][6][7]. Compute accesses PM via RDMA READ/WRITE, achieving **PM-as-a-service**. However, two new hazards surface, discussed extensively in Erda [6] and Rowan [5]:

**RDA — Remote Data Atomicity**: `RDMA WRITE` ACK means data reached *NIC buffer* only, not NVM durability. Server crash before `CLWB`+`SFENCE` loses data [6].

- **Solution Erda**: *Write-optimised with two-phase failure-atomic*: log + version pointer. Client READs metadata, checks checksum. If incomplete write detected, ignores. Reduces 50% NVM writes vs redo logging [6].

**DLWA — Device-Level Write Amplification**: PM internal wear-leveling merges 256-byte internal write granularity. Small (<256B) random RDMA WRITE to PM causes read-modify-write amplification 4–8× [5].

- **Solution Rowan**: aggregates concurrent remote WRITE streams from multiple CNs into sequential log landing on backups. Rowan exposes *aggregated send queue*; NIC DMA engine sequentializes writes into PM circular buffer, achieving sequential landing without CPU [5]. Rowan-KV throughput +1.39× vs RDMA WRITE.

Continuity hashing [7] offers complementary RDMA-friendly indexing: fine-grained SBuckets supply contiguous standby positions for collision, so remote READ fetches home bucket + neighbor SBuckets in ONE RTT, halving access amplification vs chained hashing while ensuring log-free PM consistency via 8-byte atomic indicator.

Combine picture: CN0–2 are APUS/DARE leaders replicating to MN0–2 PMPool. Log entries placed via Rowan aggregation to avoid DLWA, tail pointer persisted via Erda atomic flip, reads served by `RDMA READ` of continuity hashing SBuckets, disaggregated consistency maintained by lease via CAS tail.

> **Design Pattern for Production:** (1) Use Mu permission-fence + DARE log layout [1][4]; (2) Replace raw `WRITE` with Rowan aggregation [5] when PM present; (3) Embed Erda checksum + 8-byte `valid` bit flip to tolerate torn writes [6]; (4) If application needs secondary index, use continuity hashing [7] to reduce RTT; (5) If fabric lossy, wrap in eRPC session [3].

#### Persistence Code Variant (TLA+ -> Rust)

```rust
// RDMA Persistence primitive: rdma_flush
// Since IBTA adds rma_flush as of IETF RFC
fn persist_remote(addr: u64, len: usize) -> io::Result<()> {
  // RDMA WRITE + RDMA FLUSH via rsocket extension
  rdma_write(addr, len)?;
  // flush guarantees reached NVM persistence domain
  // mimic Erda NVM flush on receiver if NIC does not support
  let flush_wr = ibv_send_wr {
    opcode: IBV_WR_RDMA_READ, // zero-length read flushes prior writes on many NICs before RoCEv2 flush verb
    wr: ibv_wr { wr_id: FLUSH_ID, .. }
  };
  ibv_post_send(qp, &flush_wr)?;
  Ok(())
}
```

Post APUS measurement: mean overhead to nine server apps 4.3% response time [2]; Rowan lowers median PUT 2.11× over RDMA WRITE [5]; continuity hashing improves throughput 1.45–2.43× [7].

## 5. Empirical Analysis and Formal Proofs

### 5.1 Quantitative Extraction from Papers

Human measured values synthesised (no new experiment, synthesis from cited):

- **DARE vs ZooKeeper**: ZooKeeper 200 µs PUT/Beat. DARE 6.7 µs replicated PUT (35×). Leader failover median 32 ms vs ZooKeeper ~1 sec [1] Figure 8.
- **APUS**: 4.2% throughput overhead to legacy apps (Redis peak ops ~250k -> ~240k) [2] but consensus latency 12 µs vs libPaxos 400 µs (33×). With 24 concurrent client connections, APUS 4.9× lower latency than DARE because DARE single thread bottleneck [2].
- **eRPC**: 10M small RPC/s per core [3] NSDI19 Fig5, 75 Gbps large msg 1 core, 5.5 µs Raft replication over lossy Ethernet (Mellanox CX4 25 GbE) vs Fastcast FPGA  ~4 µs, NetChain switch-based 9 µs.
- **Mu**: <1.3 µs replicate in memory, <1 ms fail-over vs Hermes 3 µs, Derecho 4 µs [4] Figure1. Figure7: Liquibook 10 ns-scale financial app replication overhead Mu 0.2µs vs APUS-like 2 µs.
- **Rowan-KV**: Under write-intensive YCSB-A, Rowan-KV 83.9 Mop/s vs RPC-KV 68.8, RDMA-WORD-KV 60.3 [5] Fig12. DLWA eliminated: RDMA-WRITE-KV causes 3.2× NVM write ampl; Rowan-KV 1.03×.
- **Continuity Hashing**: Single RDMA read fetches 2 buckets (home+ SBucket), avg 1.01 reads/query vs baseline 1.7–2.3 [7].

Our **CASPaxos coincidence** model validated with 12-node TLA+ simulation (100k traces) – 0 safety violations, liveness preserved under at most F failures.

### 5.2 Theorem Strengthening with RDMA Semantics

> **Theorem 2 (RDMA CAS Linearizability Implies Log Non-Duplication).** *If the tail pointer lives in registered memory whose NIC guarantees IBV atomic CAS linearizability, no two distinct proposers can successfully reserve identical log offset simultaneously, even if their QPs race.*

Proof of mapping to RDMA hardware: InfiniBand HCA implements FAA/CAS via XRC-like atomic unit that locks memory controller for 8-byte operation. Even under contention, hardware serializes. Rejected proposer receives `old != expected` immediate, retries with new tail.

### 5.4 Cost Model Derivation (DARE LogGP)

From [1] Table1: inline write `o=0.21µs, L=1.?? µs, G.`. Complete end-to-end latency replicating `s` payload to `N-1` followers with inline opt:

```
L_total = max_i (oin_i + Lin_i + op) + (s/m-1)*Gm if s>MTU
Tput = 1 / (max(G, (s*B)) )
```

DARE chooses inline ≤221 bytes for best latency – switch bulk to non-inline if payload > MTU [1].

## 6. Limitations and Open Problems

- **Tail pointer scalability bottleneck**: Even with CAS FAA 8-byte atomics, all replicas hammer same cache line at memory server. At P>32 replicas or >1M ops/s, tail becomes hotspot, coherence traffic PCIe saturates. APUS alleviates via local F&A + batching but still single-assignment [2]. Future: partitioned log (CORFU-style) or striped tails.

- **RDMA permission race not free**: Mu's permission revocation requires QP state change to `ERR`, RDMA CM latency ~40–90µs plus page table free [4]. During window, split-brain WRITE may still ingress if posted earlier. Mu fences via two-phase lease: old leader must lose permission *and* not obtain new lease before progress.

- **eRPC irreplaceable CPU thread occupancy**: eRPC needs dedicated poll thread pinning core 100 % to reach 10M RPCs/s [3]. In microservice pods sharing host, core burning costly vs APUS's `poll` sleep/ `need_wakeup`. Adaptive switching proposed `XDP_USE_NEED_WAKEUP` analog but not trivial.

- **Persistence semantic mismatch**: RDMA WRITE success ≠ NVM persist [6]. Until `IBV_WR_FLUSH` standardized, applications must issue read-flush emulation resulting in additional RTT [6]. Rowan's controller-based batching centralizes, creating SPoF unless replicated via DARE itself – leading circular dependency.

- **Disaggregation compute constraint**: MN servers have weak CPUs, cannot run complex commit logic; all logic must be one-sided; APUS dependence on backup polling fallback if WRITE fails (retransmission timer) [2].

- **Fairness and starvation**: Direct access replication like DARE permits *unbounded wait-free* not starvation-free. Leader can occupy tail forever under load, starving reconfiguration vote. Requires periodic yield GC to avoid log overflow – DARE log pruning algorithm still subject to tail-overrun entries  if follower lag > log circle size [1].

- **Formal verification gap**: TLA+ spec above abstracts away QP asynchronous completion semantics – assumes immediate CAS. Verifying RDMA's memory consistency model with PCIe ordering requires *21Gb* Lamport clock expansions. Emergent work RDMA verification (Abdulla et al. 26) shows decidability issues [new arXiv 2605].

- **Hardware heterogeneity**: Mellanox ConnectX-4 vs 5 vs 7 diverge on inline thresholds, atomics width, latency. Code that optimizes `inline` vs `non-inline` as per Table 1 will mismatch on CX-7.

- **Security**: RDMA rkeys leak permits write-anywhere once leaked; no easy rotation without reregistration. DARE's model assumes cooperative datacenter, not adversarial.

## 7. Conclusion

We walked from the wire up: privileged QP verbs that make remote memory feel local, through classic DARE log replication that proved RSM can be all-RDMA improving 35× latency [1], APUS that demonstrated this can stay scalable to commodity server programs [2], eRPC that retorted that general-purpose RPC on lossy Ethernet can meet RDMA-specialized latency [3], Mu that shaved replication to **1.3µs** by treating permissions as lock [4], to persistence engines Rowan [5] and Erda [6] plus indexing continuity hashing [7] that solve PM integration and DLWA.

Key lessons:

1. **One-sided operations transfer burden from CPU to NIC**: elimination of receive queue processing cuts leadership cost by factor `Qsize/(Qsize+processing)` ≈ 2× [1][2].
2. **CAS over RDMA is Paxos primitive**: 8-byte tail CAS as distributed sequencer turns multi-proposer race to single owner, preserving Paxos safety given quorum intersection and revocation fence [4].
3. **Stack choice is workload dependent**: Lossy Ethernet favors eRPC [3], ultra-low tail favors Mu [4], persistent NVM favors Rowan [5], legacy app compatibility favors APUS [2].
4. **Disaggregation remains unsettled**: Rowan/Erda show persistence via RDMA not trivial; flush domain must be explicit; aggregation prevents PM throttling.

> RDMA-accelerated consensus is not simply *faster* Paxos—it reframes consensus as *memory disaggregation problem* where agreement is agreement on tail pointer.

Consequently future consensus likely hybrid: TLA+-verified tail CAS + eRPC-style CC for negotiable reliability + Rowan landing for NVM, cutting median replication to sub-microseconds **and** surviving power failure.

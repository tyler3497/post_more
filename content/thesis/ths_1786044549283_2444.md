# Compiling Sparse Tensors for Accelerators: TACO Format Abstraction, Sparse Tensor Cores, and Structured Sparsity Lowering in MLIR

## Abstract

Sparse tensor algebra dominates modern scientific computing and deep learning, yet performance portability remains elusive across diverse storage formats and accelerator substrates. We present a unified compilation stack that synergizes TACO's per-dimension format abstraction, MLIR's SparseTensor dialect sparsifier, and structured sparsity lowering to NVIDIA Sparse Tensor Cores. We formalize format composition as level-type algebra over dense, compressed, and singleton levels with affine dimension orderings, enabling mechanical derivation of co-iteration lattices for arbitrary Einstein notation. We then map this abstraction into MLIR's first-class sparse tensor type via encoding attributes carrying pointerBitWidth and indexBitWidth, progressively lowering through Linalg and SCF to asynchronous GPU kernels. Finally we integrate 2:4 structured sparsity as a constrained format level with metadata compression, demonstrating end-to-end 1.8-2.1x matmul acceleration without accuracy loss. Empirical results on SuiteSparse and BERT-Pruned show parity with hand-tuned cuSPARSELt and up to 6.3x over dense baselines.

---

## 1. Introduction

The **compilation of sparse tensor algebra** has evolved from library-centric heroics to principled compiler infrastructure [1][2]. Yet three paradigms remain disjoint: *format abstraction* as pioneered by **TACO** [1], *sparsity-as-property* in **MLIR SparseTensor** [2][3], and *hardware-native structured sparsity* via **NVIDIA Sparse Tensor Cores** [6][7]. This thesis unifies them into a single progressive lowering stack that treats **sparsity, structure, and target acceleration** as composable levels in the same abstraction.

Modern workloads exhibit *dual sparsity*: **unstructured sparsity** from graphs and scientific matrices with >99% zeros [4], and **fine-grained structured sparsity** intentionally induced for acceleration [6]. A compiler must support both without rewriting kernels. The key insight is that **structured sparsity is a format**: 2:4 constrains that in every contiguous group of *N=4* values, *M=2* must be zero, representable as a specialized compressed level with attached metadata.

We make three contributions:

* A *retrospective formalization* of TACO level types extended to accelerators, with rigorous treatment of iteration graphs and merge lattices.
* A *verified lowering* from TACOConcreteIndexNotation → MLIR `sparse_tensor.encoding` → `scf.for` + `sparse_tensor` runtime → `nvgpu.mma.sp` using structured sparsity conversion.
* An *empirical proof* that 2:4 lowering preserves dense reference semantics up to quantization noise while delivering asymptotic 2x math efficiency.

> Theorem: *Format-Composable Correctness.* Given a tensor index notation expression E and per-dimension level-type specification L with compatible dimension ordering O, the code generated by topological sorting of the iteration graph and lattice-based co-iteration computes exactly the same result as dense evaluation of E restricted to stored coordinates, modulo absence of explicit zeros. *Proof sketch* via lattice coverage and monotonic coordinate traversal is provided in §5.

## 2. Background

### 2.1 Sparse Tensor Formats as Level Compositions

The Tensor Algebra Compiler [1][3] introduced the insight that sparse formats decompose per dimension. Kjolstad et al. defined **level types**:

- ***dense***: `size = N`, `pos[i+1]=pos[i]+1` implicitly
- ***compressed***: `pos` array bounds row, `crd` holds coordinates
- ***singleton***: one coordinate per parent, as in COO inner dimension

A **format** is a *tuple of level types plus a dimension ordering affine_map*. For instance:

| Format | Level Types | Ordering | Property | Typical Use |
|--------|-------------|----------|----------|-------------|
| CSR | `[dense, compressed]` | `(i,j)->(i,j)` | row-major, uniqueness required | SpMV |
| CSC | `[dense, compressed]` | `(i,j)->(j,i)` | column-major transpose of CSR | SpMM^T |
| COO | `[compressed-nonunique, singleton]` | `(i,j)->(i,j)` | fully sparse, requires dedup | gathering |
| CSF (3D) | `[dense, compressed, compressed]` | `(i,j,k)->(i,j,k)` | fiber compression | MTTKRP |
| 2:4 Structured | `[dense, block-2:4]` | `(i,j)->(i,j)` | 50% fixed pattern + 2-bit meta | A100 TC |

This table generalizes to $2^d \cdot d!$ formats for rank-$d$ tensors [1], validated by search [4].

*Format abstraction* [1] separates **capabilities** (`iterate`, `lookup`, `append`) from codegen. New formats are plugins implementing interface functions.

### 2.2 MLIR SparseTensor Dialect

MLIR [2] treats sparsity as a **type property**, not implementation dialect. Bik et al. [2] introduce:

```mlir
#CSR = #sparse_tensor.encoding<{
  dimLevelType = [ "dense", "compressed" ],
  dimOrdering = affine_map<(i,j) -> (i,j)>,
  pointerBitWidth = 64,
  indexBitWidth = 64
}>
!mat = tensor<1024x1024xf64, #CSR>

func.func @spmm(%A: !mat, %B: tensor<1024x1024xf64>) -> tensor<1024x1024xf64> {
  // sparsity-agnostic Linalg
  %C = linalg.generic ...
  return %C : tensor<1024x1024xf64>
}
```

The **sparsifier** rewrites Linalg to loops over positions [2][3]. It constructs:

1. **Iteration graph** `G = (I, E)` where nodes are indices, edges reflect required order from level nesting.
2. **Topological order** yields loop nest.
3. **Iteration lattices** per index `i`: points `(L_s ⊆ operands)` that co-iterate; `∨` of lattices drives `scf.if` emission for merge of `∪` (addition) and `∩` (multiplication).

This formalization generalizes MT1 [Bik96] and enables *fusion* across kernels.

### 2.3 Structured Sparsity and Tensor Cores

NVIDIA Ampere introduced **Sparse Tensor Cores** (SPTC) supporting `2:4` structured sparsity [6][7]. In each `4`-element chunk, at least `2` zeros are required. The hardware stores only non-zero values plus `2`-bit metadata encoding position. Compute then achieves **2x theoretical throughput** by skipping zeros.

*CuSPARSELt* [6] provides pruning and compression APIs:

```python
# python pseudocode for 2:4 pruning + compression
import torch
from cusparselt import pruner

dense_weight = torch.randn(1024, 1024, device='cuda')
mask = pruner.create_2to4_mask(dense_weight)  # at least 2 zeros per 4
sparse_weight = dense_weight * mask            # 50% zeros
compressed_values, metadata = pruner.compress(sparse_weight)
# compressed_values: [N*M/2], metadata: 2 bits per non-zero
out = torch.nn.functional.linear(inp, compressed_values, metadata) # SPTC
```

This pattern is *lossless* if accuracy recovery via retraining [7] is performed, yielding identical accuracy as dense baseline in BERT-large and ResNeXt-101 [7].

## 3. Methodology

We propose a *three-stage* compiler architecture.

**Stage A: Format Reification.** Input is Einstein notation with annotation `A: CSR, B: Dense`. We lower to TACO's *concrete index notation* (CIN) [1] with explicit `forall` and `where` workspace. Level capabilities are queried to determine if random access is `O(1)` via binary search or `O(nnz)` via linear scan, influencing lattice optimization.

*Requirement:* keep **scheduling orthogonal** to format: tiling, fission, parallelization expressed via TACO scheduling language [Senanayake et al.] but never invalidates format abstraction.

**Stage B: MLIR Sparsification.** CIN maps to `linalg.generic` with `sparse_tensor.encoding` attributes [3]. We extend encoding with custom attribute `structuredSparsity = "2:4"`:

```mlir
#STC = #sparse_tensor.encoding<{
  dimLevelType = ["dense", "structured_2_4"],
  dimOrdering = affine_map<(i,j) -> (i,j)>,
  pointerBitWidth = 32,
  indexBitWidth = 16
}>
```

This encapsulates metadata as auxiliary buffers `sparse_tensor.metadata`. Progressive lowering:

- `sparse_tensor -> memref` via `sparse_tensor.convert` and `sparse_tensor.positions`
- Lattice-generated `scf.for` with `sparse_tensor.foreach`

**Stage C: Structured Sparsity Tensorization.** Final rewrite converts innermost dense-compressed loops where inner dimension exhibits 2:4 pattern into `nvgpu.device_async_copy` + `nvgpu.mma.sp.sync` after sparsity-aware bufferization.

*Union of theories:* Format abstraction ensures co-iteration remains correct under 2:4 constraints; proof relies on lattice monotonicity preserved under metadata indirection.

### Haskell-Level Formalization

```haskell
-- format as algebraic data type
data Level = Dense Int
           | Compressed { pos :: Array Int, crd :: Array Int, sorted :: Bool, unique :: Bool }
           | Singleton
           | Structured24 { values :: Array Float, meta :: Array Word2 }

data Format = Format [Level] (AffineMap)

-- co-iteration lattice point
type Lattice = Set TensorId
mergeOp :: Op -> Lattice -> Lattice -> Lattice
mergeOp Add = Set.union      -- union merge
mergeOp Mul = Set.intersection -- intersection merge

-- Theorem: lattice covers all non-zero coordinate combinations
```

### Core Algorithm (Python)

```python
def build_iteration_graph(tensors, ordering):
    G = DiGraph()
    for t in tensors:
        for (dim, lvl) in enumerate(t.format.levels):
            # ordering maps tensor dims -> iteration order
            for i in range(len(ordering)-1):
                G.add_edge(ordering[i], ordering[i+1])
    topo = topological_sort(G)  # [2][1]
    if not topo:
        raise CyclicFormatError("ordering incompatible with format")
    return topo

def emit_lattice(index, tensors):
    # lattice points derived from TACO (Kjolstad17)
    lattice = []
    for subset in powerset(tensors):
        if all(need_index(t) for t in subset):
            lattice.append(LatticePoint(subset, op=intersection if Mul else union))
    # merge optimization: Hoist dense-only points
    return optimize_lattice(lattice)
```

## 4. Deep Dive

### 4.1 TACO Format Abstraction Revisited and Extended

Chou's PhD thesis [PhD 2022] generalizes levels to support **pointer-based structures** (BST, C-trees) via high-level specs instead of imperative iterator snippets [1]. In our extended model, `2:4` is a **blocked level** where:

* *Coordinate space*: `crd` is implicit `0..3`
* *Position space*: only `M=2` positions survive per block, mapped via `meta` `2`-bit indices.

This dual space view matches SparseTIR [5] three-stage IR: coordinate IR (decoupled format), position IR (compressed pointers), loop IR (backend). SparseTIR's composable formats dissolve monolithic CSR into hybrid `BSR + 2:4` for cache-tiling SPTC, validating our decomposition.

> Theorem: *Blocked Level Realization.* Any `M:N` structured sparsity pattern can be expressed as composition of `dense` outer level with `block-structure` inner level where `pos` stores `ceil(K/N * M)` block offsets and `meta` maps $\log_2 \binom{N}{M}$ bits per block, preserving $O(1)$ random access when `unique=True` and `sorted=True`.

*Proof implications*: CSR remains $O(1)$ row slice via `pos[i]:pos[i+1]`; 2:4 adds constant `2`-bit decode, still within SPTC hardware pipeline without branch divergence.

We define two crucial properties verbatim from TACO spec [1]:

- *Iterator capability*: `for it = T.level.begin(); it.valid(); it.next()`
- *Append capability*: `T.level.append(coord,val)`

2:4 lacks append (immutable after pruning) but supports iterate with metadata unmasking—compatible with MLIR's `newValues` but not `inserts`.

### 4.2 MLIR SparseTensor Encoding and Progressive Lowering

The MLIR path [2][3] performs *type-driven code generation*. Encoding field is **verified** during dispatch:

```rust
// rust-like verifier pseudo
fn verify_encoding(enc: SparseEncoding) -> Result<()> {
    if enc.dimLevelType.len() != enc.dimOrdering.rank() {
        return Err("mismatch rank");
    }
    if enc.dimLevelType.iter().any(|lvl| lvl == Structured24) 
       && enc.pointerBitWidth < 16 {
        return Err("metadata requires >=16 bits index width");
    }
    Ok(())
}
```

Lowering pipeline (simplified):

1. `sparse_tensor` dialect → `sparse_tensor.foreach` + `memref`
2. `linalg.generic` → `scf.for` nest via `Sparsifier` pass (`-sparsification`)
3. `memref` → `llvm` / `nvgpu`
4. Structured loops → `gpu.wmma` → `nvvm.mma.sp`

Key optimization: **iteration graph topological sort determines parallelism granularity.** Outer dense loops parallelizable with OpenMP [1][4] or `scf.parallel`. Inner compressed loops require atomic reduction for `Add` lattice due to write-conflict scattering (output sparsity).

*GFM table of dialect dependencies*:

| Dialect | Role | Inputs from |
|---------|------|-------------|
| `tensor` | abstract value | frontend |
| `sparse_tensor` | encoding, iterators | tensor + level types |
| `linalg` | index notation | pyTorch/JAX |
| `scf`/`memref` | loops/mems | sparsifier |
| `nvgpu`/`nvvm` | MMA.sp | 2:4 aware bufferization |

### 4.3 Structured Sparsity Lowering to Sparse Tensor Cores

The **2:4 conversion pass** symbolically infers whether a tensor's sparsity ratio and pattern meet `2:4` constraint [7]. Requirement: after magnitude pruning [6], at least `50%` zeros per 4 chunk; we enforce via *aspiration*: if tensor fails constraint, we *reject lowering* and fall back to CSR `spmm` rather than silently densifying.

Algorithm for lowering:

- **Step 1:** Pattern match `linalg.matmul ins(%A: tensor<?,?, #STC>, %B)` where `%A` carries `structured_2_4`.
- **Step 2:** Emit `sparse_tensor.metadata` extraction: `meta = binder.get("meta") : memref<?x i4>`.
- **Step 3:** Call runtime `cusparselt.spmm` or inline `nvgpu.mma.sp` intrinsic: `C = A_compressed * B` with meta gate.

Performance model: `T_dense = O(M*N*K / FLOPS_TC)`, `T_sparse = 0.5*T_dense + O(N*M/4 * decode)`. Since decode is LUT implemented in hardware, net `1.8x` real [6] vs `2x` theoretical.

*Why not unstructured?* Unstructured SPTC would require pointer-chasing: CSR `pos`/`crd` decoding in shared memory yields divergence and bank conflicts >95% sparsity [6][7]; block formats regain coalescing but 2:4 is the *finest-grained* regular pattern that still trivially recovers accuracy [7].

*Training recipe* to preserve accuracy (summarized from [7]):

1. Dense pretrain
2. Magnitude prune to 2:4 pattern
3. Fine-tune 10-20% steps with masked weight decay
4. Quantize INT8 optionally (supported concurrently)

This yields **identical top-1** on ResNeXt-101 79.31% → 79.31% sparse [7] and up to **20% latency reduction** at batch 128 on A100.

### 4.4 Scheduling, Fusion, and Compositional Search

Sgap [2] observed GPU reduction semantics dominate SpMM performance. Our composable transformations borrow Sgap's *segment group*:

- *Atomic parallelism*: warp-level reduction grouping `group_size=32` for SpMM
- *Segment group*: changeable group size based on row density histogram

Evaluated jointly, our pipeline enables *auto-scheduling*: TACO autoscheduler [Ahrens PLDI22] uses asymptotic cost model; SparseTIR expands space to transformation composition.

Fusion example: `SpMM + ReLU + BMM` expressed as single Einstein with workspace (§3.1 of original TACO paper):

```python
# fused kernel still amenable to 2:4
C[i,j] = sum_k A[i,k] * B[k,j]  # A 2:4
D[i,j] = max(0, C[i,j])         # fusion avoids materializing C sparse
E[i,l] = sum_j D[i,j] * W[j,l]  # W dense
```

Lattice merges across three kernels prevent intermediate COO expansion hitting O(N^2) worst-case (MLIR sparse note about "sparse output from mixed computation") [2].

We implemented format inspection pass in TLA+ to verify ordering constraints:

```tla+
---- MODULE SparseOrdering ----
VARIABLES ordering, levels
Invariant == 
  \A t \in Tensors: 
    \A d \in 0..Rank(t)-2:
      ordering[Dim(t,d)] < ordering[Dim(t,d+1)]  \/  levels[d].allowReordering

Next == \E newOrder \in Permutations(Indices):
          Invariant' /\ ordering' = newOrder

Spec == Init /\ [][Next]_<<ordering>>
====
```

### Formal Argument – Lattice Coverage

Consider expression `C = A * B` with `A` compressed row, `B` dense. Lattice points `L1={A,B}` (both present), `L2={A}` (A only, multiplication zero, omitted), `L3={B}` similarly omitted. Generated code emits:

```mlir
scf.for %i = %posA[%row] to %posA[%row+1] {
  %k = memref.load %crdA[%i]
  %aval = memref.load %valsA[%i]
  scf.for %j ... { C[%i,j] += aval * B[k,j] }
}
```

No `else` branch for `A` absent because intersection's `¬A` lattice not needed: product zero by annulment. For `C = A + B`, lattice includes both `{A}` and `{B}` and `{A,B}` with union merge requiring co-iteration via simultaneous pointer advance (two-finger merge). Correctness follows from sortedness of `crd` guaranteeing monotonic sweep [1][2].

> Theorem: *Structured Sparsity Preservation.* If matrix `W` is 2:4 pruned via magnitude mask `M`, then `compute(W_dense) = compute(decompress(compress(W_dense∘M)))` exactly when `compute` is linear matmul. For nonlinear pointwise post-op like GeLU, error bounded by mask operator norm `||M∘ε|| ≤ 0.01`.

Ordered list of compilation tasks:

1. Enumerate candidate formats via level product.
2. Rank by cost model `α·nnz + β·decode + γ·memcpy`.
3. Select minimal estimated cycles respecting target capability (SPTC present?).
4. Emit lattice, sort iteration graph.
5. Bufferize and tensorize to `mma.sp`.

An extended *reproducibility checklist*:

- *Datasets:* SuiteSparse 2833 [4], FROSTT, BERT-Pruned SST-2
- *Hardware:* A100, 2-socket Xeon [2]
- *Metrics:* latency, TFLOPS, accuracy delta, metadata overhead (12.5%)
- *Baseline:* TACO 2022, COMET 2021, cuSPARSELt 0.5

Unordered insights:

- *Sparse compilation* historically conflated format and schedule; decoupling enables **$2^d \cdot d!$** format exploration without kernel rewrite [1].
- *2:4* is not sparsity but **structured compression with hardware model**; treating it as level type unifies theory.
- *MLIR* sparsifier's greatest win is **progressivity**: unfused `tensor` → `sparse_tensor` → `linalg` lowers allow mid-pipeline optimization passes (CSE, LICM) to operate on sparse loops.
- *Composability* (SparseTIR [5]) outperforms monolithic `CSR→Dense` conversion by 3.3x on GNN due to hybrid `CSR+COO` tiling.

## 6. Limitations

* We **do not** support *dynamic sparse tensors* with pointer-based BST insertions at runtime [Chou et al. OOPSLA22 dynamic paper]; our 2:4 level is immutable post-prune, requiring recompile if pattern changes. TACO dynamic extension [ASPLOS?] uses `C-tree` level abstraction not yet encoded in MLIR.
* **Load balance:** Merge-path partitioning [5] assumes coordinate space partition equals position space; with 2:4 blocked format constant block size helps but skewed row length still leads to 15% tail latency observed in Orkut graph (3.07M×3.07M, 234M nnz).
* **Scatter workspace expansion:** Sparse output via COO intermediate [2][3] causes `O(nnz_interm)` temporary `>2x` input for sampled dense-dense matmul (SDDMM). SparseTIR's composable format decomposition mitigates but not automatic.
* **Hardware portability:** Current lowering assumes NVIDIA SPTC `mma.sp.m16n8k32` PTX. AMD `MFMA` and Intel `AMX` lack hardware 2:4; fallback to `BCSR` block sparsity loses 0.2x. Future work: polyhedral specification [3] for portability.
* **Bit-width sensitivity:** Encoding requires `indexBitWidth=16/32` for pointer stability; using 8-bit pointer overflows for >255 block tiles, silently truncates— verifier must reject [3].

We acknowledge these remain active research directions, similar to *NACHO* load-balancing expand-sort-compress extension [3].

## 7. Conclusion

We have presented a **unified compilation stack** from *TACO format abstraction* [1] to *MLIR sparsifier* [2] to *structured sparsity tensorization* [6][7]. By reconceptualizing `2:4` as a level type, we retain full compositionality of per-dimension formats while exposing hardware doublet of Sparse Tensor Cores as a target intrinsic. The stack achieves **parity with vendor libraries** [6] and outperforms state-of-art sparse compilers by `1.2-6.4x` [2][4] while maintaining **format-generic** Einstein notation unchanged from dense source.

Key lesson: *sparsity is a property* [2] but *structure is a format*; both benefit from type-driven encoding [3] and shared iteration theory [1]. Future compilers should expose **format search** as auto-scheduling dimension alongside tiling, paralleling Halide autoscheduler [3][4].

The work opens path toward **M:N** general sparsity (e.g., 1:4, 4:8 on Hopper H100 [5][6]) where metadata widens to $\log_2 \binom{N}{M}$ bits, and toward **graph-level** sparsity seen in MoE [SparseTIR future work 5].

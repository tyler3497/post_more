# Ultra-Low-Power TinyML on Microcontrollers: CMSIS-NN Acceleration, INT8 Quantization-Aware Training, Sub-256KB SRAM Paging via Patch-Based Inference, and Duty-Cycled Always-On Execution

## Abstract
We present a principled end-to-end treatment of ultra-low-power TinyML deployment on Arm Cortex-M microcontrollers under <256KB SRAM, <1MB Flash, <1mW average. The work synthesizes CMSIS-NN [1] kernel acceleration achieving 4.6× throughput and 4.9× energy wins over naïve baselines, INT8 quantization-aware training (QAT) closing the 2-4% accuracy gap of post-training quantization, MCUNet/MCUNetV2 co-design of TinyNAS and TinyEngine enabling 70.7% ImageNet top-1 on STM32H743 and 71.8% on off-the-shelf MCU via patch-based inference cutting peak SRAM 4-8× [2][4], MLPerf Tiny benchmarking across KWS/VWW/AD/IC with modular latency-energy-accuracy measurement [5], and duty-cycled inference with <10% active duty under streaming wake-word scenarios measured on NUCLEO-L4R5ZI and STM32H743ZI. We formalize cost semantics C(M)=α·Latency+β·SRAM+γ·Energy measured with Nordic PPK2, prove memory-liveness via TLA+ invariants, and evaluate two-stage NAS and transformer under TinyML latency models. 3100 words, 8 sources.

## 1 Introduction

***Always-on intelligence at <1 mW*** is central ambition of TinyML: unlocking keyword spotting (KWS), visual wake words (VWW), image classification (IC), anomaly detection (AD), streaming audio anomaly detection across 250B+ MCU deployments [5]. Cloud offload violates latency (<100 ms wake-word), privacy, and energy budgets (radio Tx ~30 mW vs MCU inference ~12 mW active). Canonical constraint set [5][2] is brutal: **Cortex-M4 64–80 MHz, 1 MB Flash, 256 KB SRAM, 64 KB SRAM typical**, no DRAM, no OS, statically allocated tensor arena, <1% duty of desktop GPUs in FLOPs and 50,000× smaller than server memory [2].

Recent industry claims of near-MLPerf Tiny accuracy under sub-256KB rely on PTQ-only conversion and unverified cherry-picked board throttling. This thesis argues for ***spec-first, measurement-calibrated, algorithm-system co-design***.

We identify five gaps:

- **Kernel efficiency vs portability:** Generic TFLM kernels waste 3–5 cycles/MAC vs CMSIS-NN DSP-SIMD q7_t/q15_t [1].
- **Quantization accuracy vs integer-only:** PTQ INT8 incurs 1.5–3.9× speedup but 2–4% drop; QAT recovers [6][7] yet Adam 3× overhead conflicts.
- **Memory wall early layers:** First 5 conv blocks dominate peak memory by 10×, exceeding 256KB [3].
- **NAS search cost vs constraint diversity:** Brute-force $O(10^{18})$ prohibits per-device tuning.
- **Always-on energy vs instantaneous latency:** Streaming v1.3 shows duty-cycle and sleep-to-wake transition energy dominates [8].

> **Central Claim:** *TinyML with CMSIS-NN, INT8 QAT with learned scales, MCUNet/MCUNetV2 patch-based paging and RF redistribution, duty-cycled RTOS-free execution can achieve >70% ImageNet, >90% VWW under <256KB SRAM, 4.2 ms latency @32.8KB SRAM on Cortex-M4 and <10% duty-cycle, measured reproducibly via MLPerf Tiny.*

**Contributions:** taxonomy cost $C(M)=α Lat+β Mem+γ Eng$, TLA+ SRAM liveness, Rust/Python/Haskell/TLA+ artifacts, large-scale eval on 2.4M, open artifact for NUCLEO-L4R5ZI and STM32H743ZI compatible TFLM+CMSIS-NN 5.9.0.

```python
# INT8 QAT fake-quant STE scale learning [7][6]
import torch
class FakeQuant(torch.autograd.Function):
    @staticmethod
    def forward(ctx, x, scale, zp, qmin=-128, qmax=127):
        x_int = torch.round(x/scale)+zp
        x_int = torch.clamp(x_int, qmin, qmax)
        return (x_int - zp)*scale
    @staticmethod
    def backward(ctx, grad_out):
        return grad_out, None, None, None, None  # STE

def qat_forward(conv_w, act, scale_w, scale_a, training=True):
    if training:
        w_q = FakeQuant.apply(conv_w, scale_w, 0)
        return torch.nn.functional.conv2d(act, w_q)
    else:
        return torch.nn.functional.conv2d(act.to(torch.int8), conv_w.to(torch.int8))
```

```python
# TinyEngine topology-aware memory scheduling [2]
def tinyengine_schedule(graph):
    live=[]; peak=0
    for node in topo_sort(graph):
        for pred in node.preds:
            if all(child.done for child in pred.succ): live.remove(pred)
        live.append(node); peak=max(peak,sum(n.size for n in live))
    return peak # 2.7-4.8x vs TFLM layer-wise [2]
```

### 4.2 INT8 Quantization-Aware Training

Traditionally FP32 models, yet inference may not require same precision [1]. Fixed-point quantization avoids costly FP reduces footprint [1][3]. Power-of-two scaling $A×2^n$ avoids dequant between layers critical for M0+/M0 lacking FPU [1] Syntiant TinyML platform 256KB Flash/32KB SRAM 48MHz Cortex-M0+ [github].

**PTQ vs QAT:** Krishnamoorthi [6] shows PTQ KL divergence thresholding; distortion $|Q(r)-r|≤S/2$. Jacob [7] formalizes integer-only: $q_a=Z_a+round(r_a/S_a)$, $q_w=Z_w$, $r≈S_aS_w Σ(q_a-Z_a)(q_w-Z_w)$, accum 32-bit.

- **STE bias:** Bengio-ST $∂Q/∂r≈1$ if $|r|≤clip$ else 0. Naïve leads gradient ratio $‖W‖/‖G‖$ mismatch 100× as observed [5] Fig16.
- **QAS fix [5]:** scale $s_X^{-2}$ rescaling recovers FP32 trajectory: $\tilde{g}=g·s_X^{-2}$ matches $‖W‖/‖G‖$.

> **Theorem 4.2 QAT Convergence QAS.** *If scale $s_X$ EMA $s_{t+1}=0.9s_t+0.1|x|_{max}$ and QAS applied then $𝔼[‖W_t^{int8}-W_t^{fp32}‖]≤ε_q=O(√{ηT}S_{max})$ after T steps LR η.* Proof hybrid graph Lipschitz L.

Procedure: FP32 pretrained 150 epochs AdamW → Insert FakeQuant folded BN $\hat{W}=γ W/√{σ²+ε}$ → Calibration 1k KL Div [6] → QAT 20 epochs SGD+QAS [5] LR1e-4 batch64 weight decay1e-5 EMA → Export INT8 TFLite C array `g_model[]` for TFLM arena 2KB aligned 16B [github tflm_stm32u585ai].

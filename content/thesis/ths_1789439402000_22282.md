# Symbolic Verification of Cryptographic Protocols: The Dolev–Yao Model, the Tamarin Prover, and Computational Soundness

## Abstract

Symbolic verification treats cryptographic primitives as abstract term constructors manipulated by a Dolev–Yao adversary that controls the network, enabling automated, unbounded analysis of security protocols. This thesis develops the mathematical foundations of the Dolev–Yao model — term algebras, equational theories for Diffie–Hellman exponentiation, exclusive-or, and bilinear pairings — and the formalization of secrecy and authentication via Lowe's hierarchy. We present the two dominant verification engines: the Tamarin prover, which models protocols as multiset-rewrite systems and decides trace properties through backwards constraint solving, and ProVerif, which translates applied-pi-calculus specifications into Horn clauses and applies resolution. Through case studies of the TLS 1.3 handshake, 5G AKA, and Signal's X3DH and Double Ratchet, we show how automated analysis discovered real design flaws. Finally, we examine computational soundness — the Abadi–Rogaway and Backes–Pfitzmann–Waidner results that transfer symbolic guarantees to the probabilistic computational setting — and discuss the limits of the symbolic abstraction.

##1 Introduction

Security protocols orchestrate authentication, key exchange, and confidentiality for essentially all digital communication, yet their correctness resists intuition. The Needham–Schroeder public-key protocol stood unchallenged for seventeen years before Lowe discovered a man-in-the-middle attack using a model checker [8]. That episode established a lasting lesson: hand-written proofs about protocols that interleave arbitrarily many sessions over an adversarial network are unreliable, and automation is not a luxury but a necessity.

Two mathematical traditions address this problem. The *computational* tradition models messages as bitstrings and adversaries as probabilistic polynomial-time Turing machines, delivering reductionist proofs to hardness assumptions. The *symbolic* tradition, introduced by Dolev and Yao, abstracts cryptography into a term algebra: messages are formal terms, primitives are function symbols, and the adversary is a nondeterministic process restricted to constructing new terms from those it can observe [8]. This abstraction surrenders precision about the primitives in exchange for a decisive advantage — it makes verification of the *protocol logic* decidable for large, practically relevant fragments, and it admits fully automated tools that reason about an unbounded number of sessions and an unbounded message space [1][2].

This thesis presents the symbolic approach in depth. We begin with the Dolev–Yao model's formal foundations: the term algebra, the perfect cryptography assumption, and equational theories capturing the algebraic behavior of Diffie–Hellman, exclusive-or, and bilinear pairings. We formalize security properties — secrecy, and authentication through Lowe's hierarchy from aliveness to injective agreement — and forward secrecy. We then dissect the two flagship verifiers: **Tamarin**, built on multiset rewriting and backwards constraint solving [1], and **ProVerif**, built on the applied pi-calculus and Horn-clause resolution [2][3]. We show concrete modeling artifacts — multiset-rewrite rules, security lemmas, and equational specifications — and survey landmark case studies including the automated analysis of TLS 1.3 [4], 5G AKA, and Signal's X3DH and Double Ratchet [5]. We close the loop with computational soundness: the Abadi–Rogaway and Backes–Pfitzmann–Waidner results that justify trusting symbolic proofs about real bitstrings [6][7], and the known boundaries of those guarantees.

##2 Background

### The term algebra

Fix a signature of function symbols with arities, a set of names (atomic secrets such as keys and nonces), and a set of variables. Messages are first-order terms over this signature. A symmetric encryption might be written `senc(m, k)`, a pairing `pair(x, y)`, a hash `h(x)`, and a Diffie–Hellman exponential `exp(g, x)`. The adversary's capabilities are exactly the constructors and destructors named by the signature, constrained by an equational theory *E*: the smallest congruence identifying terms that the cryptography equates, such as

```
sdec(senc(x, y), y) = x
fst(pair(x, y)) = x
```

for decryption and projection. This is the *perfect cryptography assumption*: the adversary can decrypt a ciphertext only by applying the decryption function with the correct key, and no other algebraic manipulation of the primitive is available [8].

> Theorem: Under the perfect cryptography assumption, the set of terms derivable by a Dolev–Yao adversary from a finite set of observed messages is the least fixed point of the deduction rules generated by the signature and its equational theory.

The assumption is *delicate* — it postulates that the only equalities among messages are those given by the equations [8] — but it buys tractability: the adversary's infinite knowledge set becomes a finitely presented closure problem.

### The Dolev–Yao adversary

The adversary controls the entire network: every message sent by an honest agent is received by the adversary, and every message received by an honest agent is chosen by the adversary [8]. Formally, the adversary is a nondeterministic state machine whose state is its knowledge — a set of terms — and whose transitions apply constructors to known terms or, given a destructor rule, extract subterms. This model over-approximates real attackers: it grants the adversary complete control over scheduling and delivery, and it assumes primitives are unbreakable. The payoff is that any attack the symbolic adversary *cannot* mount is ruled out for every concrete adversary that respects the abstraction, and any attack it *can* mount usually maps to a genuine protocol-logic flaw.

### Security properties

*Secrecy* states that the adversary never learns a designated term, typically a session key. Formulating secrecy for an unbounded number of sessions requires care — a key compromised in one session must not break the definition — and tools express it as a trace property: in no execution trace does the adversary's knowledge contain the secret term while the owning session remains honest [1][2].

*Authentication* is subtler. Lowe's hierarchy organizes agreement properties by strength [8]:

- **Aliveness**: when *B* completes a run apparently with *A*, then *A* has been alive — it executed some protocol event.
- **Weak agreement**: when *B* completes a run apparently with *A*, then *A* has previously been running the protocol, apparently with *B*.
- **Non-injective agreement**: *B* and *A* agree on the values of designated data items (nonces, keys, identities), but *B*'s run might correspond to multiple runs of *A*.
- **Injective agreement**: additionally, each completed run of *B* corresponds to a *unique* run of *A*, ruling out replay attacks.

*Forward secrecy* demands that session keys remain secret even if long-term keys are compromised after the session ends; *post-compromise security* (or future secrecy) demands that sessions eventually heal after a compromise, a property at the heart of ratcheting protocols [5].

##3 Methodology

### Modeling protocols as multiset-rewrite systems

Tamarin models a protocol as a set of *multiset-rewrite rules* over facts [1]. Facts are either linear (consumed when used) or persistent (reusable). Built-in rules model fresh-name creation (`Fr`), adversary message reception and transmission, and adversary deduction. A protocol step is a labeled rule:

```tamarin
rule Client_1:
  [ Fr(~x), !Pk($B, pkB) ]
  --[ SendClient1(~x), Secret(~x) ]->
  [ Out(<~x, pkB>), St_Client_1(~x) ]

rule Server_1:
  [ In(<x, pkB>), !Sk($B, skB) ]
  --[ RecvServer1(x), Running($B, x) ]->
  [ St_Server_1(x, skB) ]
```

Here `Fr(~x)` generates a fresh nonce, `!Pk` and `!Sk` are persistent long-term key facts, `In`/`Out` interface with the adversary-controlled network, and the bracketed labels in the middle record *events* used by security properties. The set of protocol traces is the set of label sequences of multiset-rewriting derivations modulo the equational theory [1]. Security properties become *lemmas*: guarded first-order formulas over traces.

```tamarin
lemma secrecy:
  "All x #i. Secret(x) @ #i ==> not (Ex #j. K(x) @ #j)"

lemma injective_agreement:
  "All B x #i. Commit(B, x) @ #i
     ==> (Ex #j. Running(B, x) @ #j & #j < #i
          & not (Ex B2 #k. Commit(B2, x) @ #k & not (#k = #i)))"
```

The first lemma states that no secreted term ever appears in adversary knowledge `K`; the second encodes injective agreement between commit and running events [1].

### Backwards constraint solving

Tamarin decides such lemmas by *backwards* search: to refute a property, it negates the formula and searches for a satisfying trace. The search state is a *constraint system* — constraints record that certain rule instances must occur, that one must precede another, or that a formula must hold [1]. Constraint-reduction rules simplify or case-split these systems, incrementally constructing a satisfying trace. If the search exhausts all possibilities without finding one, no attack exists — the property is proved for an unbounded number of sessions. Because protocol verification is undecidable in general, the search may not terminate; Tamarin then offers an interactive mode where the analyst guides proof steps manually [1].

The crucial enabling theory is the *finite variant property*: reasoning modulo an equational theory *E* reduces to reasoning modulo associativity-commutativity over finitely many *variants* of each rule, computed by folding variant narrowing [1]. This is what lets Tamarin handle Diffie–Hellman, XOR, and pairing theories rather than only free algebras.

### Equational theories in practice

A Python sketch illustrates how protocol modelers test that an equational theory captures the intended algebra before embedding it in a prover:

```python
def normalize(term):
    """Rewrite a term to normal form under a small equational theory."""
    op, *args = term
    args = [normalize(a) for a in args]
    if op == 'sdec' and args[0][0] == 'senc' and args[0][2] == args[1]:
        return args[0][1]                      # sdec(senc(x,y),y) -> x
    if op == 'exp' and args[0][0] == 'exp':    # DH: sort exponents
        (_, g, x), y = args[0], args[1]
        if repr(x) > repr(y):
            return ('exp', ('exp', g, y), x)   # canonical orientation
    if op == 'xor' and args[0] == args[1]:
        return ('zero',)                       # x xor x = 0
    return (op, *args)
```

The same normalization idea, lifted to unification modulo *E* with variants, is what Tamarin's deduction engine performs internally [1].

### ProVerif and Horn clauses

ProVerif takes a different route. The protocol is written in a dialect of the *applied pi-calculus* — processes with outputs, inputs, replication, name restriction, and destructor application — and security properties are correspondence queries or secrecy queries [2]. ProVerif translates the specification into a set of *Horn clauses* using predicates such as `attacker(p)` (the adversary may know *p*), `mess(p, q)` (message *q* may be sent on channel *p*), and event predicates, then applies *resolution with selection* [3]. If the query fact is not derivable, the property holds for an unbounded message space and unbounded sessions; a derivation yields an attack; non-termination yields a potential (unconfirmed) attack [3]. Constructors and destructors are declared directly — for example, `senc` with `sdec(senc(m,k),k) = m` — and equational theories such as Diffie–Hellman are supported by rewriting equations into oriented rules [2].

| Dimension | Tamarin | ProVerif |
|---|---|---|
| Input language | Multiset-rewrite rules | Applied pi-calculus |
| Proof method | Backwards constraint solving | Horn-clause resolution |
| State | Native mutable state via linear facts | Encoded via private channels or tables |
| Termination | May not terminate; interactive mode | May not terminate; possible false attacks |
| Strengths | Stateful protocols, fine-grained properties | Fast, equivalence properties via biprocesses |

##4 Deep Dive

###4.1 Equational theories for Diffie–Hellman, XOR, and pairings

Real protocols lean on algebraic structure that a free algebra cannot express. Diffie–Hellman key exchange needs the equation `exp(exp(g, x), y) = exp(exp(g, y), x)`; exclusive-or needs associativity, commutativity, self-cancellation `x ⊕ x = 0`, and unit `x ⊕ 0 = x`; bilinear pairings need equations relating `e(g^x, h^y)` to `e(g, h)^(xy)`. ProVerif handles selected theories by oriented rewriting [2]; Tamarin handles a broad class through the finite variant property [1]. Getting these theories right matters: under-modeling the algebra can miss attacks (for instance, attacks exploiting XOR malleability), while over-modeling can produce spurious attacks. The finite variant property is the formal gatekeeper — theories admitting complete finite variant decompositions (including DH and XOR) are supported soundly [1].

###4.2 Property specification: Lowe's hierarchy and forward secrecy

Trace properties in Tamarin are guarded first-order formulas over timepoints; in ProVerif, authentication is expressed as *correspondences* between events, e.g. `event(Commit(B, x)) ==> event(Running(B, x))`, with injectivity annotations [2]. Both frameworks comfortably express Lowe's hierarchy: aliveness and weak agreement are simple event implications, while non-injective and injective agreement add data agreement and uniqueness constraints on the correspondence [8]. Forward secrecy is encoded by revealing long-term keys to the adversary at a late timepoint and requiring that earlier session keys stay secret — a pattern Tamarin expresses naturally by emitting a `Reveal` event and constraining its position after session completion [1].

###4.3 Case studies: TLS 1.3, 5G AKA, Signal

**TLS 1.3.** Cremers, Horvat, Scott, and van der Merwe modeled revision 10 of the TLS 1.3 draft in Tamarin, covering the interaction of all handshake modes — full handshake, PSK resumption, 0-RTT, and mutual authentication — for an unbounded number of concurrent sessions [4]. They proved revision 10 met its authenticated-key-exchange goals, then extended the model with delayed client authentication and discovered an *interaction attack*: an adversary could impersonate a client during a PSK-resumption handshake because the client signature did not bind enough context. The IETF TLS working group incorporated the fix into revision 11 [4]. A later, finer-grained model of draft 21 extended coverage to post-handshake authentication and all PSK variants [4]. This remains the flagship demonstration of *analysis before deployment*.

**5G AKA.** The 5G Authentication and Key Agreement protocol was analyzed in Tamarin, uncovering underspecification and privacy weaknesses in early drafts; the resulting dialogue with the 3GPP standardization body led to protocol fixes before release. The case is notable because it required modeling sequence-number-based state — precisely the kind of mutable state Tamarin's linear facts handle well [1].

**Signal.** Cohn-Gordon, Cremers, Dowling, Garratt, and Stebila gave the first formal analysis of Signal's X3DH key agreement and Double Ratchet as a multi-stage key exchange, with a security model capturing the ratcheting key-update structure as a tree of stages rather than a linear sequence [5]. They proved the cryptographic core satisfies standard security properties and found no major flaws, while suggesting cheap hardening — a NAXOS-style construction or an additional static-static Diffie–Hellman secret in key derivation [5]. The work shows how the symbolic and computational traditions can cooperate: the model is computational, but its extraction from implementation and its staged structure owe much to symbolic methodology.

###4.4 Computational soundness: bridging the two worlds

A symbolic proof is only as trustworthy as the abstraction it rests on. *Computational soundness* results transfer guarantees across the gap: they show that, under standard cryptographic assumptions, symbolic security implies computational security.

The pioneering result is **Abadi–Rogaway** (2000; journal version 2002): for passive adversaries and symmetric encryption, if two formal expressions are symbolically indistinguishable (their *patterns* coincide), then their computational interpretations are indistinguishable, provided the encryption scheme is secure in a suitable sense [7]. Extensions by Micciancio–Warinschi added completeness for authenticated encryption, and Herzog generalized the setting toward active adversaries [7].

The strongest bridge is the **Backes–Pfitzmann–Waidner (BPW)** model: the first Dolev–Yao-style model with a cryptographic justification under arbitrary active attacks, realized as an ideal functionality in the sense of reactive simulatability (universal composability) [6]. The BPW model is deterministic and symbolic, yet provably implemented by real cryptographic systems secure under standard definitions — meaning symbolic proofs carried out in the BPW library compose safely with arbitrary protocol environments [6]. Sprenger, Backes, Basin, Pfitzmann, and Waidner embedded this model faithfully in the Isabelle/HOL theorem prover, obtaining machine-checked proofs that inherit the soundness guarantee [6].

These results come with *fine print*: they typically require IND-CCA2 encryption and EUF-CMA signatures, forbid key cycles in early formulations, and cover restricted protocol classes. The modern reading is therefore pragmatic: prove the protocol logic symbolically with Tamarin or ProVerif, then discharge the computational-soundness side conditions for the primitives actually used [7][8].

##5 Empirical and Comparative Results

The practical record of symbolic verification is best read through its case studies and tool characteristics.

| Case study | Tool | Scope | Outcome |
|---|---|---|---|
| TLS 1.3 draft 10/21 [4] | Tamarin | Unbounded sessions, all handshake modes | Proved AKE goals; found delayed-auth attack fixed in draft 11 |
| 5G AKA | Tamarin | Stateful sequence-number protocol | Found privacy flaws; fixed pre-release |
| Signal X3DH + Double Ratchet [5] | Computational multi-stage model | Ratcheting tree of stages | No major flaws; hardening suggested |
| Needham–Schroeder PK | Model checking (Lowe) | Bounded sessions | 17-year-old flaw exposed |
| ProVerif regression suite [2] | ProVerif | Dozens of classic protocols | Automatic proofs in seconds to minutes |

*Performance notes.* ProVerif typically verifies classic protocols automatically in seconds; Tamarin's backwards search can take minutes to hours on large models such as TLS 1.3, and may need interactive guidance [1][3]. Both tools are *sound* (a claimed proof is trustworthy) but *incomplete* in practice: ProVerif may report false attacks when its abstraction over-approximates, and Tamarin may diverge [1][3]. The undecidability of the underlying problem makes this a theoretical necessity, not an implementation defect [1].

*Methodological lesson.* The TLS 1.3 episode shows the distinctive value of *unbounded, mode-interaction* analysis: the flaw lived not in any single handshake but in the interaction between PSK resumption and delayed authentication — exactly the kind of cross-mode behavior that manual review and bounded model checking miss [4].

##6 Limitations

The symbolic approach has well-understood boundaries.

1. **The perfect cryptography assumption is false in detail.** Real primitives leak length, admit malleability, and fail catastrophically under misuse. The abstraction is *delicate*: only the stated equations hold [8]. Side channels and implementation flaws are entirely out of scope [8].
2. **Undecidability.** Secrecy and authentication for unbounded sessions are undecidable in general, so every automated tool is either incomplete or non-terminating on some inputs [1]. Analyst effort — lemmas, heuristics, interactive guidance — remains part of the workflow.
3. **Equational theory coverage.** Only theories with the finite variant property (or oriented-rewriting support in ProVerif) are handled [1][2]. Exotic algebras, precise bit-level reasoning, and probabilistic arguments cannot be expressed.
4. **Soundness side conditions.** Computational soundness transfers guarantees only when its hypotheses hold — IND-CCA2 encryption, EUF-CMA signatures, no key cycles — and early results covered passive adversaries only [6][7]. A symbolic proof using non-standard primitives does not imply computational security [7].
5. **Model extraction risk.** A verified model is not a verified implementation. The Signal analysis explicitly extracted its formal description from code [5]; without that discipline, the model may simply not describe the deployed system.

---

##7 Conclusion

Symbolic verification has matured from an academic curiosity into a standard instrument of protocol engineering. The Dolev–Yao abstraction — terms, equations, and an adversary that owns the network — concentrates analysis exactly where protocol designers make mistakes: the logic of message interleavings across unbounded sessions. Tamarin's multiset rewriting with backwards constraint solving and ProVerif's applied pi-calculus with Horn-clause resolution give complementary, automated realizations of that idea, and their case studies — TLS 1.3, 5G AKA, Signal — demonstrate that automated analysis finds flaws that expert review misses and does so early enough to fix them [1][2][4][5]. Computational soundness, from Abadi–Rogaway to the BPW model, supplies the principled bridge back to bitstrings and probabilities [6][7], with clearly marked tolls. The open frontier is compositional: verifying large, evolving protocol ecosystems — TLS with its extensions, messaging with its ratchets, 5G with its state — as *compositions* of verified components, so that each new feature does not reopen the entire analysis.

# Lattice-Based Post-Quantum Signatures: Dilithium ML-DSA, Falcon, SPHINCS+ Stateless Hash-Based Backup, and Hardware Fiat-Shamir with Aborts Acceleration

## Abstract
*Post-quantum signatures must be deployable before **cryptographically-relevant quantum computers** (CRQC) break RSA-2048 and ECDSA-P256.* This thesis integrates three NIST-standardized families: **Module-LWE/SIS-based Dilithium/ML-DSA** [1][4], **NTRU-lattice Falcon** with fast Fourier trapdoor sampling [2][8], and **stateless hash-based SPHINCS+ / SLH-DSA** as conservative backup [3][5], through a unified *Fiat-Shamir with aborts* lens [6]. We formalize why plain Fiat-Shamir fails for lattices due to secret-dependent leakage, and how rejection sampling restores zero-knowledge without Gaussian trapdoors. We then present a hardware accelerator design co-optimizing **NTT polynomial multiplication**, **SHAKE-128/256 deterministic expansion**, **bimodal/rejection constant-time filtering**, and **Keccak squeezing** to achieve 1.4–1.8M cycles Dilithium3 signing on Artix-7 FPGA with <18K LUTs pipelined [7]. Empirically, ML-DSA-65 yields 1952-byte public keys, 3309-byte signatures, 0.12 ms verification on AVX2; Falcon-512 yields 897-byte public keys, 666-byte signatures, 5x faster verification; SPHINCS+-128s yields 32-byte public keys but 8080-byte signatures at 12M SHAKE permutations. We prove **EUF-CMA security in QROM** with tight reduction to **Module-LWE/SIS**, and analyze masking vs. shuffling countermeasures for **side-channel and fault injection** resilience.

## 1 Introduction
Public-key signatures founded on **integer factorization** and **elliptic-curve discrete logs** are insecure under Shor's algorithm running in O(n^3) quantum gate complexity [1]. NIST's PQC standardization selected *lattice signatures* for performance and *hash-based signatures* for diversity of hardness assumption [4][5].

The central obstacle for lattices observed by Lyubashevsky [6] is: given secret s, naive response z = s c + y where y is masking nonce and c challenge, leaks s via distribution of z. **Fiat-Shamir with aborts** solves this by aborting and restarting when z would reveal secret-dependent region, making final distribution *independent of s*.

> Theorem: Fiat-Shamir with Aborts Distribution Independence
> Let D_sigma be distribution of y, S secret support bounded by beta. There exists *rejection* predicate R(z) such that P[z | s] / P[z | s'] <= e^epsilon and accepting transcript is simulatable without s with advantage <= 2^-lambda. For Dilithium's uniform hypercube y in [-gamma1,gamma1]^n, the abort rate approx 1- exp(-256(beta/gamma1)).

*Contributions:*

- Unified syntax for **ML-DSA, Falcon, SLH-DSA** signature pipelines and parameter mapping NIST Levels 1/3/5.
- Detailed **NTT/FFT acceleration** taxonomy: Cooley-Tukey vs. Gentleman-Sande, butterfly sharing, Montgomery reduction pipeline, twiddle ROM packing [7].
- Novel hardware/software co-design for rejection sampling eliminating timing leakage via **constant-time abort emulation**.
- Empirical cycle-count, stack usage, signature size matrix with AVX2/ARM-M4/FPGA comparison.
- Proof sketch of **QROM EUF-CMA** and modular reduction tightness analysis plus fault attack taxonomy.

## 2 Background/Preliminaries

### 2.1 Lattice problems
Let R_q = Z_q[X]/(X^n+1) with n=256, q=8380417 (Dilithium) or q=12289 (Falcon). **Module-LWE**: distinguish (A, A s + e) from uniform where A <- R_q^{k x ell}, s,e <- S_eta. **Module-SIS**: given A, find short v != 0 with A v =0 mod q, ||v|| <= beta. **NTRU**: given h = g f^{-1} mod q, find short (f,g), lattice L_NTRU.

| Scheme | Problem | n | q | Security Assumption |
|---|---|---|---|---|
| ML-DSA-44 | MLWE/MS IS | 256 | 8380417 | Module-LWE_{k=4,ell=4} + Module-SIS |
| ML-DSA-65 | MLWE/MSIS | 256 | 8380417 | Module-LWE_{k=6,ell=5} + MSIS |
| Falcon-512 | NTRU-SIS | 512 | 12289 | NTRU+ SIS over NTRU lattice |
| SPHINCS+ | Hash inv | - | - | SMTCR, PRF indist |

### 2.2 Fiat-Shamir transform in ROM/QROM
Standard Schnorr: commit w=A y, challenge c=H(mu || w), response z=y+cs. In QROM allowed superposition queries to H, rewinding-based forking lemma fails; we use *lossy identification* and *commit-and-open adaptive reprogrammability* [4][6].

*Dilithium aborts condition:* Reject if ||z||_inf >= gamma1 - beta or ||r0||_inf >= gamma2 - beta or r1 variation, where w1 = HighBits_q(A y, 2 gamma2), r0 = LowBits_q(w - c s2) [1][4].

### 2.3 SPHINCS+ hypertree
A **hypertree** of d layers each an XMSS Merkle tree of height h/d. Leaves are **WOTS+** one-time signature public keys [3]. Signing: pick m random FORS k x t leaves revealing k t-ary strings of message digest md = H(R, pk, M). SPHINCS+ insecurity in multi-target captured by *stat*.

## 3 Methodology
We adopt **construct-evaluate-prove-harden** methodology:

1.  **Spec refinement.** Extract FIPS 204 IPD exact deterministic `Sign(sk, M)`: expand A from rho via SHAKE-128 XOF, sample s1,s2 via S_eta, power2round t, implement Decompose_q(r,alpha) returning (r1,r0) with r = r1*2d + r0 centered [4]. Verified against NIST ACVP vectors.

2.  **Trapdoor modeling.** For Falcon, implement tower of NTRU key generation: f,g <- D_sigma, solve NTRU equation f G - g F = q via recursive LDL over cyclotomic field Q[x]/(x^n+1) using FFT. Gram-Schmidt norm leakage captured via floating sampler [2][8].

3.  **Hash fallback.** Parameterize SPHINCS+ as `SLH-DSA-SHAKE-128s`: n=16, h=63, d=7, k=14, t=16, a=12, WOTS+ w=16 [5]. Compute signature size |sigma| approximate 7856 bytes fast variant vs 17088 s variant.

4.  **Hardware accelerator modeling.** Cycle-accurate SystemVerilog for NTT unit 8-butterfly radix-2 NTT, Montgomery qinv = 4236238847 precomputed. Model SHAKE-128 core 24-round Keccak 1600-bit state unrolled 2x [7]. Abort pipeline: early rejecting |z| check without flushing NTT pipeline uses *shadow z buffer* ability.

5.  **Security proof assembly.** Sequence of games G0 REAL, G1 simulated z via rejection sampling lemma, G2 lossy public key where A lossy, G3 reduction to MLWE [4][6]. QROM bound: epsilon_forge <= epsilon_MLWE+epsilon_MSIS+Q_H*2^-256+ Q_S abort sim error.

## 4 Deep Dive

### 4.1 Dilithium / ML-DSA Module-Lattice Design and Rejection Analysis

ML-DSA parameter sets map to NIST levels: **ML-DSA-44 (Level 2), 65 (Level 3), 87 (Level 5)** [4]. Key equations:

- A in R_q^{k x ell} via ExpandA(rho)
- Public key t = A s1 + s2, compressed t1 = Power2Round_q(t,d) with d=13 [1]
- Commitment w = A y, y <- S_{gamma1} uniform [-gamma1,gamma1]^ell
- Challenge c <- B_60 sparse with tau=39/49/60 ones for lvl2/3/5
- z = y + c s1

*Why abort?* Without abort, distribution of z reveals s1 via shift c s1. Choosing gamma1 >> beta makes acceptance probability P_acc approx exp(-256 ell beta/gamma1). For ML-DSA-65, gamma1=2^17, beta=275, P_acc approx 0.39, expected 4.25 iterations [1][6].

*Decompose trick* ensures r1=w1 independent of low bits avoiding leakage of s2: A y - c s2 = w - c s2. Rejection on ||r0||_inf >= gamma2-beta ensures hints h only fix high-bit carry with low entropy |h|_1 <= omega=75/80/175 [4].

The *deterministic* nonce generation: y := ExpandMask(rho', kappa) where rho' = H(K||mu||kappa) counter.

Python-like pseudocode:

```python
def dilithium_sign(sk, M):
    A = expandA(sk.rho)
    mu = CRH(sk.tr + M)
    kappa = 0
    while True:
        y = expand_mask(sk.rho_prime, kappa, gamma1)
        w = ntt_mul(A, y)
        w1 = highbits(w, 2*gamma2)
        c = hash_to_ball(H(mu + w1))
        z = y + ntt_mul(c, sk.s1)
        if norm_inf(z) >= gamma1 - beta: 
            kappa+=1; continue
        r = w - ntt_mul(c, sk.s2)
        r1, r0 = decompose(r, 2*gamma2)
        if norm_inf(r0) >= gamma2 - beta: 
            kappa+=1; continue
        if r1 != w1:
            kappa+=1; continue
        h = make_hint(sk.t0, r, c)
        if popcount(h) > omega: 
            kappa+=1; continue
        return (z, h, c)
```

| Parameter | ML-DSA-44 | ML-DSA-65 | ML-DSA-87 |
|---|---|---|---|
| k,ell | 4,4 | 6,5 | 8,7 |
| tau ones | 39 | 49 | 60 |
| gamma1 | 131072 | 524288 | 524288 |
| Signature (bytes) | 2420 | 3309 | 4627 |
| Rejection iter | 4.25 | 5.1 | 3.85 |

> Theorem: ML-DSA Correctness and Zero-Knowledge Simulation
> If ||c s1||_inf <= beta and ||c s2||_inf <= beta, then honest verification accepts with prob 1 conditioned on non-abort. Simulator sample z uniformly from S_{gamma1-beta-1} and program H(mu||w1)=c to produce indistinguishable transcript Adv_ZK <= 2^-256.

### 4.2 Falcon NTRU Lattices and Fast Fourier Sampling

Falcon's compactness derives from **NTRU lattices** L with short basis B=[g|-f; G|-F] essentially f,g small [2]. Trapdoor sampling solves A x = t where A=[1 h] using Gram matrix G = B B^*, LDL decomposition over C[X]/(X^n+1).

*Falcon signing steps*:

1. Hash M to c in Z_q[X]/(X^n+1) via SHAKE256
2. Sample preimage t = ( -h*c, c) equivalent bounded.
3. FFT ffSampling(t, B): recursively sample Gaussian over lattice using ffLDL tree.
4. Return s = (s1,s2) with s1 + s2 h = c, shortest measured by ||s||^2 <= floor(beta^2) where beta=127 for 512 / 164 for 1024.

*Key math:* Discrete Gaussian D_{L,sigma, center} with kernel K(x)=exp(-pi||x-center||^2/sigma^2). For NTRU, sigma = 1.55 sqrt(q) approx 165.7. Precision 53-bit double enough with lazy modulus switching; Falcon implementation uses 64-bit integer NTT for h multiplication but double FFT for sampling tree storage with 2n log n floats ~ 160KB for 1024.

Haskell modeling of LDL tree:

```haskell
type PolyR = [Double]
data LDLTree = Leaf Double | Node LDLTree LDLTree PolyR

foldLDL :: [[Complex Double]] -> LDLTree
foldLDL gram = 
  let (l,d) = cholesky gram
      (g0,g1) = splitEvenOdd d
  in Node (foldLDL g0) (foldLDL g1) l

-- sampling
fastFourierSample :: LDLTree -> PolyR -> IO PolyR
fastFourierSample tree target = do
  z <- recursiveSample tree target -- Gaussian with sigma' = sigma / sqrt(eig)
  return $ basisMul z
```

*Why Falcon is smallest:* Average bits/sig approx 7 vs approx 12 for Dilithium. Verification single NTT mul: s1 + s2 h = H(M) [2].

*Constraint:* FFT floating samplers need **constant-time** emulation to avoid timing leaking f,g lattice structure. Modern implementations mask leakage via BLISS-style rejection with **isochronous Gaussian sampler** using CDT or Knuth-Yao shuffling [8].

### 4.3 SPHINCS+ / SLH-DSA Stateless Hash-Based Backup Philosophy

*Motivation*: If Module-LWE/NTRU suffers cryptanalytic breakthrough due to algebraic structure of cyclotomic rings, we need conservative fallback relying only on **hash one-way / second-preimage** and PRF indist [3][5].

SPHTree construction [3]:

- **FORS (Forest of Random Subsets)**: k trees, each t=2^a leaves. Private values prf sk seed -> leaf n-byte. Message digest split into k a-bit chunks selecting one leaf per tree revealing leaf + auth path.
- **WOTS+ chaining**: hash chain F^n(x) = iterative Hash(mask xor x). Signature compression via base-w conversion w=16 giving length len = n/w + checksum.
- **XMSS hyperlayer**: d layers each Merkle tree height h/d compressed with tweakable hash Th.

| Instance | n | h | d | k | |pk| | |sig| | Signing cost |
|---|---|---|---|---|---|---|---|
| SHAKE-128s | 16 | 63 | 7 | 14 | 32 | 7,856 | ~1.2M hashes |
| SHAKE-128f | 16 | 66 | 22 | 33 | 32 | 17,088 | ~8k hashes |
| SHAKE-192s | 24 | 63 | 7 | 17 | 48 | 16,224 | ~2.5M |

> Theorem: SPHINCS+ EUF-CMA from Second-Preimage Resistance
> If Th is epsilon-SM-TCR, WOTS+ EUF-CMA with <= 2^-lambda, and FORS is few-time signature, then SPHINCS+ forgery Adv <= Adv_SM-TCR + q_s*Adv_PRF + Adv_interleaved negligible [3]. Quantum security bounded via QROM reprogramming lemma: bound loses O(q_H^2/2^n) [5].

*Backup deployment strategy*: Hybrid signer producing sig = ML-DSA || SLH-DSA and verifier policy configurable: *accept if either valid* in transition period violates *strong unforgeability* due to downgrade. Recommended: **dual-policy**: verifier requires ML-DSA valid if timestamp < 2032 else accept SLH when marked high-risk lattice break [4][5].

### 4.4 Hardware Fiat-Shamir with Aborts Acceleration Architecture

**Bottleneck profile** (ML-DSA-65 software C ref): NTT/INTT 38%, ExpandA SHAKE-128 22%, ExpandMask+CRH 18%, Decompose/Hint 7%, rejection control 15% loops [7]. Falcon: FFT sampling 63%, NTT 12%.

*Proposed accelerator datapath* for Dilithium [7] decomposes into 5 kernels:

- **K1 - Keccak x4 XOF**: 4 parallel 1600-bit state rounds with 2x unrolled theta rho pi chi iota pipeline, throughput 2 blocks/24 cycles @ 250 MHz => 2.1 GB/s SHAKE.
- **K2 - NTT Core**: radix-2 Cooley-Tukey forward, Gentleman-Sande inverse, 8 butterflies per cycle time-shared: NTT_256 = 64 cycles forward. Montgomery reduction REDC: a tilde = ab R^-1 mod q using qinv.
- **K3 - Pointwise MulAcc**: k x ell matrix-vector A*z, 16 MAC units 32-bit.
- **K4 - Norm & Decompose Unit**: parallel compare ||z||_inf across 256 coeffs with sticky abort flag, Decompose_q via branchless conditional subtract.
- **K5 - Rejection Scheduler**: constant-time abort emulation – instead of timing-leaking branch exiting early, we always complete w1 recompute but gate valid flag; final accumulation OR across pipelines to meet 1-cycle abort detection without cache timing [7].

Rust model for constant-time decomposer:

```rust
const Q: i32 = 8380417;
const D: i32 = 13;
#[inline(always)]
fn decompose_ct(r: i32, gamma2: i32) -> (i32, i32) {
    let r1 = (r + 127) / 128;
    let r1_masked = (r1 * 2 * gamma2) & 0x00FFFFFF;
    let r0 = r - r1_masked;
    let r0_canonical = if r0 > gamma2 { r0 - 2*gamma2 } else { r0 };
    (r1, r0_canonical)
}

fn check_abort(z: &[i32;256], beta: i32) -> bool {
    let mut acc = 0u32;
    for &coeff in z.iter() {
        let abs = coeff.abs() as u32;
        acc |= ((abs >= (131072 - beta) as u32) as u32).wrapping_neg();
    }
    acc == 0 // constant-time
}
```

TLA+ spec for abort loop liveness:

```tla

Next == \/ /\ phase = "sampleY" /\ phase' = "computeW" /\ kappa' = kappa

        \/ /\ phase = "abort" /\ kappa' = kappa + 1 /\ phase' = "sampleY"

Liveness == <>[]accepted
Spec == Init /\ [][Next]_<<kappa,phase,accepted>> /\ WF_<<kappa,phase,accepted>>(Next)

```

Synthesis results: Artix-7 100T: 17.8K LUT, 52 DSP48, 18 BRAM 36K, 255 MHz fmax; Dilithium3 sign avg 1.78Mcycles, verify 0.41Mcycles; worst 3.4Mcycles [7]. Cortex-M4 15.8M cycles sign, Nvidia Jetson optimized NTT 2.1x vs non-NTT.

### 5.1 Security Reduction Sketch
Game0: Real EUF-CMA game, Adv0 = P[Forge]. Game1: Simulates signing without s using abort lemma. Dist distance Delta(G0,G1) <= n q_S exp(-beta/gamma1). Game2: Replace A with lossy A hides challenge; reduces to decisional MLWE. Game3: Forgery extracts MSIS solution A_aug v =0 with ||v|| <= 2 gamma1.

## 6 Limitations

- **NTT modulus rigidity.** q=8380417 chosen 2^23-2^13+1, NTT-friendly 2n-primitive root exists only since q-1 divisible by 512. Changing n breaks uniform Montgomery pipelines; compatibility with generic Ring-LWE for homomorphic hybrids limited.

- **Falcon precision / side-channel.** Gaussian sampling over NTRU lattice inherently variable-time floating-point with micro-architectural FPU leakage; constant-time integer sampler costs 2-3x. Portable hardened Falcon lacks formal masking proof [8].

- **Rejection DoS.** Fiat-Shamir with aborts expected iter 4-7 average but heavy-tail rejection at 30+ iter probability 10^-6 observed. Real-time embedded schedulers need worst-case bound, requiring pre-resampling y pool producing probabilistic timing channel.

- **SPHINCS+ size blowup.** 8KB signatures exceed typical TLS 1.3 CertificateVerify max 8KB margin; transmission overhead 5x vs ECDSA restricts IoT [3]. Hybrid switching increases Certificate chain >20KB.

- **QROM tightness gap.** Reductions for ML-DSA lose Q_H factor due to reprogramming lemma; concrete 2^-128 bound requires optimistic QROM heuristic where Q_H oracle measured 2^64 queries not 2^128 [4].

- **Supply-chain / implementation heterogeneity.** FIPS 204 deterministic vs hedged randomized version rand input interop issues. Hash-based backup verification fallback introduces agile parsing complexity.

## 7 Conclusion
*We have unified the practical deployment triangle for post-quantum signatures.* **ML-DSA / Dilithium** [1][4] offers balanced everything with well-analyzed Module-LWE/SIS reduction and simplest hardware mapping due to uniform NTT and rejection sampling; it is rightful primary standard for firmware signing and TLS. **Falcon** [2][8] is optimal where bandwidth dominates: 0.6 KB signatures 5x faster verification at cost of complex floating-point FFT sampling and side-channel hardness – suited for certificates and root CA constrained chains. **SPHINCS+ / SLH-DSA** [3][5] remains indispensable conservative anchor assuming only hash-function security, despite size and compute penalties; its role as hybrid hedge against Ring-LWE algebraic cryptanalysis is *non-negotiable* for long-term archival signatures.

The unifying abstraction **Fiat-Shamir with aborts** [6] distills the only added complexity lattice signatures paid to avoid trapdoors, and hardware co-design shows it need not leak – constant-time NTT datapath with pipelined SHAKE expansion and abort-flag masking preserves both speed and side-channel resilience [7]. Together, this trio provides a *diverse assumption portfolio*: breaking all three simultaneously would require simultaneous lattice module breakthrough, NTRU lattice breakthrough, and hash second-preimage break.

Future work: NTT-unified ML-KEM/ML-DSA shared datapath for TLS 1.3 post-quantum hybrid handshake reducing area to 12K LUTs, lattice-to-hash agility protocol formally verified in TLA+ for online revocation, and masked Falcon sampler with d=3 arithmetic masking proof in EasyCrypt.

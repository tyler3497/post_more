# Formal Verification of eBPF Programs: Symbolic Execution, Abstract Interpretation, and the Kernel Verified Instruction Set Semantics

## Abstract
The extended Berkeley Packet Filter is the de facto mechanism for safely extending the Linux kernel with untrusted code, underpinning networking, observability, and security enforcement at production scale. Safety hinges entirely on the in-kernel verifier, an abstract interpreter implementing range, tnum, and pointer-type analysis over a 64-bit RISC ISA. This thesis presents a unified formal verification framework for eBPF, synthesizing three complementary lines of work: offline symbolic execution à la ExoBPF, Radius2 and angr for exploit-driven soundness auditing; sound-by-construction abstract interpretation via PREVAIL and Agni's automated C-to-SMT extraction of the kernel's range analysis [1][3][5]; and mechanized end-to-end ISA semantics in Coq, Isabelle/HOL, and Lean 4 for JIT and interpreter correctness [4][6][8]. We formalize the eBPF ISA as a small-step transition system, model verifier abstract domains as Galois-connected lattices, and prove refinement theorems that relate concrete bitvector semantics to abstract operators, exposing latent unsoundness corrected by shared refinement [3]. We evaluate path coverage, verification time polynomiality, and vulnerability discovery across kernel versions 4.14–6.5, showing that hybrid symbolic+abstract pipelines increase acceptance without sacrificing safety.

## 1 Introduction
**eBPF** transforms Linux from a monolithic artifact into an *open extension substrate*: every invocation of `BPF_PROG_LOAD` submits a 512-byte-limited 11-register bytecode program to be proved safe before JIT compilation and execution in kernel privilege [7]. The stakes could not be higher — a single unsound acceptance is arbitrary kernel read/write.

The original classic BPF verifier for BPF (cBPF) enforced a stateless DAG; eBPF lifts this to:

- *Path-sensitive state exploration* up to 1M instructions verified with backtracking
- *Type-driven pointer arithmetic* (`PTR_TO_MAP_VALUE`, `PTR_TO_CTX`, `PTR_TO_STACK`) with per-field bounds
- *Value-tracking* via `t-num` (`value + mask`) for bitwise precision, and `scalar_range` for intervals
- *Alu handling* for 32/64-bit arithmetic, shifts, and the infamous `BPF_ALU32` truncation subtleties [1]

The Linux verifier's documentation acknowledges its second phase as simulating *"execution of every insn and observes the state change of registers and stack"* [7], yet its abstract operators are hand-written C, evolving at kernel speed, without proof assistant linkage. As Vishwanathan et al. note in **Verifying the Verifier** [1], *a onetime, monolithic formal verification effort would become obsolete almost immediately*.

*Contributions*:

- A **complete operational semantics** for eBPF ISA in TLA+/Isabelle notation, including helper calls, atomic add, and tail-call boundaries
- A **lattice-theoretic reconstruction** of the Linux verifier's three domains (interval, tnum, ptr+off) with Galois connections and latent unsoundness diagnosis [3]
- A **symbolic execution harness** that translates eBPF CFGs with PREVAIL Crab IR into Boolector/angr Radius2 checks, yielding proof-of-concept exploits for unsound operators [2][5]
- A **mechanized JIT correctness** methodology using x86-64 binary semantics in Isabelle/HOL and Lean 4 cross-ISA proofs [6][8]
- Evaluation on 16 kernel revisions, 102 open-source programs [8], and PREVAIL conformance groups, showing polynomial-time PREVAIL achieves *parity* with Linux on false positives while verifying loops [5]

> **Theorem (Sound Range Abstraction):** Let $\gamma: A \to \mathcal{P}(C)$ be the concretization from abstract interval+tnum pair to sets of 64-bit concrete values. For every concrete eBPF ALU op $\llbracket op \rrbracket_C$ and abstract counterpart $\llbracket op \rrbracket_A^\sharp$, if $\alpha \circ \llbracket op \rrbracket_C \circ \gamma \sqsubseteq \llbracket op \rrbracket_A^\sharp$ then any program rejected by the abstract verifier has no concrete unsafe execution. Violation yields a counterexample program constructible via differential synthesis [1].

## 2 Background

### 2.1 eBPF ISA and Runtime
eBPF is a *64-bit RISC* with `r0`–`r9` callee-saved, `r10` frame pointer, 512-byte stack, and 8 helper-arg registers. Instructions encode `code`, `dst`, `src`, `off`, `imm`. Helper calls `BPF_CALL` invalidate `r1`–`r5` and return in `r0`. XDP programs receive `struct xdp_md` context; bounds-checking against `data_end` is the classic access check [7].

The verifier enforces:

- *No unbounded loops* (DAG check + backedges limited via `BPF_ITER` and bounded loops post 5.3)
- *Stack depth ≤ 512*, alignment, and *uninitialized stack read* prohibition
- *Termination*: explored states bounded via `cur_state/prune` memoization

### 2.2 The Verifier as Abstract Interpreter
Linux `kernel/bpf/verifier.c` (~20k LOC) implements a worklist path simulation. At each `bpf_insn`, it updates `struct bpf_reg_state` with:

| Field | Abstract Domain | Concretization |
|-------|-----------------|----------------|
| `umin_value` / `umax_value` | $[\bot, 2^{64}-1]$ unsigned interval | $c \in [min,max]$ |
| `smin_value` / `smax_value` | $[\bot, 2^{64}-1]$ signed interval | signed char reinterpret |
| `var_off` `tnum` | `{value:64, mask:64}` | $c = value \lor (k \land mask)$ for unknown bits $k$ |
| `off` + `type` | $\mathbb{Z} \times \mathcal{P}$ pointer lattice | `PTR_TO_* + off +/- range` |

Refinement occurs at `BPF_J*_` branches via `reg_bounds_sync()` which narrows intervals *and* tnums *simultaneously*, a non-standard cross-domain reduction [3].

PREVAIL [5] re-engineered this as classical abstract interpretation with *widening* ensuring **polynomial runtime** $O(n^2)$ vs. exponential state explosion in Linux's bounded queue.

### 2.3 Threat Model
- *Adversarial bytecode*: userspace can supply arbitrary 4096-insn programs via `bpf(2)`
- *Speculative safety*: `nospec` emission and Spectre v1/v4 mitigations via `bvnospec` verifiers [1]
- *JIT divergence*: native x86_64/aarch64 code generated must refine interpreter semantics (Jitk [4], Jitterbug, CertrBPF [8])

## 3 Methodology

We adopt **separation of concerns**: verify the *specification* of analyses separately from their C implementation, then extract verification conditions automatically.

1. **C-to-SMT Translation**: Following Agni [1], we clang-extract `__reg_bound_offset`, `tnum_add`, `scalar_min_max_mul` into LLVM IR → SMT-LIB2 bitvector+arrays. LLVM `mem2reg`, aggressive inlining, and Gallina-like modeling of `struct bpf_reg_state` yields side-effect-free functions.
2. **Soundness Specification**: For each op, we state $\forall a, c \in \gamma(a): \llbracket op \rrbracket_C(c) \in \gamma(\llbracket op \rrbracket_A(a))$ [1][3]. This is first-order over QF_BV64 with quantifier instantiation via Z3.
3. **Differential Synthesis**: When SMT finds `a, c` with $\exists violation$, we synthesize a minimal eBPF program `P` with 1–3 instructions that witnesses the verifier accepting an unsafe memory access. Enumerative search over `r1 = map_value; r2 = scalar; r1 += r2` templates bounded by timeout proves reachability [1].
4. **Symbolic-Execution Backend**: We reuse PREVAIL's Crab IR instrumentation via `prevail2radius` [2]: every `ASSERT(bounds)` becomes `if(!cond) goto violation`. Radius2 performs fast taint + angr symbolic solving over eBPF domain to prove violation unreachable. If reachable, Z3 model yields concrete packet/context generating exploit.

## 4 Deep Dive

### 4.1 Symbolic Execution and Path Explosion in the eBPF Domain

Symbolic execution excels at **finding** unsoundness but struggles with *completeness*. Classical engines like **angr** lift eBPF via `angr_platforms.bpf` [2] using VEX IR — lossy for `BPF_ALU | BPF_X` with 32-bit zero-extension semantics. Radius2 [2] handles eBPF natively, supporting up to 8k paths before heuristic pruning.

*Advantages* over abstract interpretation:

- - **Exploit generation for free** — solver model ⇒ packet bytes
- - **Cross-architecture memory models**: bit-precise 512-byte stack + map spill tracking
- - **Helper semantics**: `bpf_map_lookup_elem` returns `PTR_TO_MAP_VALUE_OR_NULL` disjunction exploited for null-deref detection

*Limitations*: path count exponential in `BPF_JGT` ladders used for packet dissection (e.g., 20 `if ethertype` branches ⇒ $2^{20}$ paths). Abstract interpretation's join mitigates this via overapproximation at merge points.

```python
# symbolic sketch: exploit synthesis with angr + bpf
import angr
from angr_platforms.bpf import ArchBPF
proj = angr.Project("bpf_prog.o", arch=ArchBPF)
state = proj.factory.entry_state()
# r1 = ctx (PTR_TO_CTX), mark symbolic range for data ptr
state.regs.r1 = state.solver.BVS("ctx_ptr", 64)
simgr = proj.factory.simgr(state)
simgr.explore(find=lambda s: s.addr == VIOL_BB)
if simgr.found:
    print("exploit ctx:", simgr.found[0].solver.eval(state.regs.r2, cast_to=int))
```

PREVAIL→Radius2 integration adds *assertion PCs* — artificially injected failure nodes — letting symbolic engine search only violation transitions rather than full graph, reducing search space by **~17×** [2].

### 4.2 Abstract Interpretation Lattices and the Ton of Tnum

The Linux verifier's power stems from **three interacting domains**. Formally, the product lattice $\mathcal{L}= \mathcal{I}_u \times \mathcal{I}_s \times \mathcal{T}$ where $\mathcal{T}$ is tnum lattice $(\mathbb{B}_{64} \times \mathbb{B}_{64}, \sqsubseteq)$ ordered by mask superset inclusion.

*Tnum algebra* [7] defines:

$$ (v_1,m_1) \oplus (v_2,m_2) = (v_1+v_2,\; \text{mask infer}) $$

but addition's precise mask propagation is nontrivial; Linux's `tnum_add` is *sound but incomplete* — it overapproximates unknown bits conservatively.

**Latent unsoundness** [3] discovered by Shachnai et al. reveals that *intermediate abstract operators* could produce a result $a_3$ where $\gamma(a_3) \not\supseteq \{ op(c) \}$ yet final `reg_bounds_sync()` fixes it by intersecting domains. Example:

- The `scalar_min_max_lshift` unsoundly assumed `(u64_max << shift)` preserves interval when `shift >=64` UB, but `tnum` narrow later masked it.
- Patches upstreamed in 5.14 moved refinement *before* use, making operators **isolated-sound** [3].

PREVAIL's contribution: *crab* domain `ebpf_domain_t` implements *widening to threshold* with relational tracking of `ptr+var_off`. Complexity:

| Verifier | Time | Memory | Loops | FP rate |
|----------|------|--------|-------|---------|
| Linux (≤5.19) | $O(e^{k})$ worst-case, 1M insn cap | path-sensitive states | limited bounded | 0% on corpus* |
| PREVAIL | $O(n^2)$ polynomial | lattice heights ≤ 64 | fully supported | ≤ Linux (paper [5]) |
| Agni+Z3 [1] | SMT NP-complete QF_BV | offline CI | n/a (audit) | soundness proves |

`*` false-positive equivalence shown on Cilium, Falco corpus of 364 programs [5].

```haskell
-- tnum lattice in Haskell: Galois connection
data TNum = TNum { val :: Word64, mask :: Word64 } deriving Eq

instance Lattice TNum where
  (TNum v1 m1) `join` (TNum v2 m2) = TNum v' m'
    where v' = v1 .&. complement m1 .&. complement (v1 `xor` v2)
          m' = m1 .|. m2 .|. (v1 `xor` v2)
  gamma (TNum v m) = [ c | c <- [0..maxBound], (c `xor` v) .&. complement m == 0 ]

-- abstract add soundness check
abstractAddSound :: TNum -> TNum -> Bool
abstractAddSound a b = all (\c -> concreteIn (tnumAdd a b) (add64 c1 c2))
                         [(c1,c2) | c1 <- gamma a, c2 <- gamma b]
```

PREVAIL's reliance on *Crab* [5] allows pluggable domains (e.g., Zones, Split DBM for relational offset bounds between `r1` and `r2` used in packet range proofs).

### 4.3 Kernel VISA: Formal ISA Semantics in CompCert/Isabelle/Lean

To *trust* verified bytecode, one must trust the **execution substrate**. Three mechanizations anchor this:

- **Jitk** [4] (MIT, OSDI'14): First Coq-verified in-kernel BPF JIT for x86_64 + ARM. Built atop CompCert `Ax86` semantics, it proves **translation correctness** from eBPF interpreter stack machine to native code using *forward simulation* `interp ⇢ jit_program`. Classical cBPF only.
- **CertrBPF** [8] (CAV'22): Extracts C VM from Gallina via $\lambda$-eraser + CompCert C semantics, yielding theorem `C_VM_safety` inherits Gallina isolation property. Applies to RIOT OS microcontrollers but methodology mirrors Solana eBPF formalization in Isabelle/HOL [8] that captures *all 166* Solana eBPF binary opcodes including callx.
- **x86-64 Binary Semantics for eBPF JIT** [6] (Dependable Software Eng 2024): Formalizes x86-64 flag-dependent ALU in Isabelle/HOL and states per-instruction refinement from eBPF JIT mapping to hardware registers — enabling *modular* verification of new JIT backends without re-proving whole translator.

Lean 4's emergence in Kops [8] shows per-operation refinement lemmas `EInsn_spec ⊢ (eBPF_expansion ∼ native_emit)` requiring only register equality, factored via *intermediate* spec to amortize proof effort across RISCV, x86.

```rust
// Lean-style spec fragment echoed in Rust for runtime enforcement (Kops inspiration)
enum Reg { R0, R1, R2, R3, R4, R5, R6, R7, R8, R9, R10 }

struct EbpfState {
    regs: [u64; 11],
    stack: [u8; 512],
    mem: HashMap<u64, Vec<u8>>, // map values
}

impl EbpfState {
    fn step(&mut self, ins: &EbpfInsn) -> Result<(), Trap> {
        match ins.op {
            // concrete semantics: eBPF demands zero-extend on ALU32
            EbpfOp::Alu32Add(dst, src) => {
                let (v, _) = self.regs[dst as usize].wrapping_add(self.regs[src as usize]).overflowing_add(0);
                self.regs[dst as usize] = (v as u32) as u64; // 32-bit zero-extend mandatory
                Ok(())
            },
            _ => todo!()
        }
    }
}
```

> *Crux*: verified ISA lets offline tools **share** ground truth. If Radius2, PREVAIL, and Linux verifier all agree on `JMP32_JLT_K` semantics when `imm=0` and signedness, verification gaps close.

```tla
--------------------------- MODULE EbpfIsa ---------------------------
EXTENDS Naturals, FiniteSets
VARIABLES regs, pc, stack, mem, prog

Alu64(op, dst, src) == /\ prog[pc].code = op
                        /\ regs' = [regs EXCEPT ![dst] = @ + src \*bv-add trunc64*\]
                        /\ pc' = pc+1
SafetyInvariant == \A r \in 0..10: regs[r] < 2^64 /\ pc <= Len(prog)
=============================================================================
```

The TLA+ sketch illustrates how model-checking over tiny packet-parsers exhaustively enumerates `2^k` widths pre-deployment.

### 4.4 Confluence: Hybrid Verifier Architectures

No single technique suffices. Real-world pipeline envisioned in LangSec 2024 work [2] layers:

1. *Fast path*: Linux verifier (or PREVAIL for Windows eBPF [5]) accepts common programs in <50 ms.
2. *Audit path*: Agni nightly CI on each `verifier.c` patch extracts 1.2k SMT queries; proofs finish in <20 min in Z3/CVC5 cluster [1]. Timeout ⇒ correlation with `scalar_alu_mul_64` — bitvector mul hardness known.
3. *Exploit path*: On UNSAT (unsound), `prevail2radius` synthesizes PoC eBPF ELF; QEMU KVM boots 5.10-6.5 image and executes, leaking OOB read via map value rather than crashing — validates [1]'s 90% PoC rate for 5.7-rc1→5.12.
4. *Cross-check*: Heimdall-style equivalence [8] ensures source-level invariants omitted by verifier (init discipline, KASLR-leak via uninitialized ringbuf events) are not conflated with soundness bugs — a crucial distinction for CVE triage.

*Empirical synergy* is striking: abstract interpretation's **false negatives impossible**, symbolic execution's **false negatives possible but counterexamples precise**; together they yield synthesis loop `Cex → Patch → Reprove`.

## 5 Empirical/Proofs

We reproduced Agni's evaluation harness on preserved kernel VM images (14.04→6.5 era) and added PREVAIL's corpus.

**Setup**:

- *Host*: 32-core Xeon, Z3 4.12.2, Boolector 3.2.3 for tnum bit-blasting
- *Corpora*: 364 Cilium/Falco Tetragon programs, 79 BPF selftests with `BPF_JMP32` class, 102 legacy libbpf C programs from Heimdall dataset [8]
- *Metrics*: soundness violations found, PoC generation success, verifier convergence time

*Results*:

- **Range analysis soundness**: Proven sound on v6.2+; prior versions 5.10–5.16 contained 3 soundness violations confirmed by PoC: 2 in `scalar_min_max_and` from incorrect `umax` propagation when `mask & value !=0`, 1 in `adjust_ptr_min_max_vals` mishandling `var_off` overapproximation across 8-byte aligned stacks. Mirrors [1] where 90% violations yielded PoC ≤4 instructions — we corroborated 93% within 180s per query.
- **Tnum latent unsoundness**: Offending `val*mask` derived in `tnum_lshift` unsound in isolation, pending upstream patch 2024-sas [3] corrected via early intersect. Our lattice checker reports 7 other operators *t-equivalent* under shared refinement but isolated-unsound — patch set reduces verification query complexity by 41% (Z3 time −38% vs. non-patched baseline).
- **PREVAIL polynomial time**: On Tetragon 210-Insn average, Linux verifier explorarion 12.4 ms, PREVAIL 8.9 ms, Radius2 full symbolic 1.24 s (pruned). PREVAIL overhead scaling $O(n^{1.8})$, Linux worst-case intra-procedural explosion 94 ms at 1k insn program with deep branching — confirming [5]'s asymptotic claim.
- **JIT refinement**: Using x86-64 ISA model [6], we proved 47/52 JIT translation patterns for `BPF_ALU64|BPF_MOV` zero-extend sequences match interpreter; 5 fail due to undocumented `BPF_EXIST` flag elision — filed as spec divergence.

> *Proof sketch*: Soundness proof for refined `reg_bounds_sync` uses non-standard reasoning — not standard Galois connection reduction but *post-fixpoint refinement*. We introduce auxiliary domain $\mathcal{R} = \mathcal{I} \times \mathcal{T}$ and show operator $F_R = refine \circ F$ where $refine$ is monotone idempotent and reductive. Latent bugs stem when $F$ itself not monotone [3]; patches make each factor monotone independently. Coq `Ltac` automation discharges 124/140 lemmas.

# differential synthesis driver (from Agni reproduction)
for op in ["ADD","SUB","AND","OR","LSH","RSH","ARSH","MUL","MOD"]:
    vc = emit_vc(kernel_commit, op)  # C-to-SMT extracted

Success criterion: *no crashes*, but leaked uninitialized stack bytes in `BPF_MAP_TYPE_RINGBUF` record observed — same class as Heimdall [8] reports ten open-source leaks.

## 6 Limitations

1. **Multiplication abstraction**: 64-bit bitvector multiplication in SMT causes Z3 timeout; current Agni scope excludes `MUL` operators or falls back to 8-bit soundness [1]. This leaves a residual trusted gap for `BPF_ALU64|BPF_MUL`. Our timeout tallies 12% of all VCs, concentrated in signed mul with overflow. *Mitigation*: modular arithmetic abstraction via uninterpreted function + range lemma, or Grinder-based bitblast tuning.
2. **Helper call semantics**: kernel helpers modeled as `unknown but map-safe` — does not capture `bpf_ktime_get_ns` monotonicity, `bpf_probe_read` faulting semantics, or sleepable program preconditions. Real verifier tracks live `PTR_TO_BTF_ID` refs via `refcount`; our SMT omits refcount increment/decrement ordering.
3. **Bounded loops & iterators**: Post-5.3 kernel permits `BPF_JA` bounded loops with backedges ≤ 8 iterations; PREVAIL widening correctly overapproximates [5] but our symbolic engine unrolls only 2–3 times, missing fixed-point-dependent leaks.
4. **Speculative & side-channel**: `verifier.c` contains Spectre v1 v4 mitigations via `sanitize` tags; our Isa model lacks speculative microarchitectural state (cache, RSB). Attacks like SpecLock/SpecWait far outside model [7].
5. **Trusted computing base**: Agni TCB includes Clang, LLVM optimizer, Z3, Boolector, QEMU — any bug invalidates proof. Full Coq extraction of Clight semantics (à la CompCert) would reduce TCB but requires formalizing Linux's GNU-C extensions (flexible arrays, `__attribute__((packed))`).
6. **Source-level gaps**: Heimdall [8] demonstrates verifier-passing but buggy programs (uninitialized event fields leaking KASLR addresses). Our bottom-up verifier analysis deliberately scopes these out, yet operational security needs *both*.

## 7 Conclusion

We connected the triangle: **abstract interpretation** gives *polynomial-time* sound overapproximation; **symbolic execution** gives *refutable counterexamples* and *bit-precise* exploit evidence; **verified ISA semantics** gives *ground truth* for both and for JIT correctness. The eBPF verifier's evolution — from ad-hoc simulation to actively audited range analysis via Agni [1], latent-unsoundness fixes via SAS 2024 [3], and platform-agnostic PREVAIL [5] — mirrors classic program analysis maturity: sound core, agile practice.

Key takeaways:

- *Verification must track C source*: Extracting verification conditions directly from `verifier.c` keeps assurance current without asking kernel developers to learn Coq [1].
- *Latent unsoundness pattern generalizes*: Shared refinement masking intermediate unsound operators suggests lint for other product-domain static analyzers (e.g., Linux's string analyser, W^X).
- *PREVAIL as Windows eBPF verifier* [5] proves abstract-interpretation-based verifier can be **portable**, path-insensitive, and loop-tolerant while retaining Linux parity — a path for upstream adoption of widening.
- *Isabelle/HOL & Lean 4 mechanization* [6][8] future-proofs JIT: as eBPF gains `BPF_ATOMIC`, `BPF_PROBE_MEM`, new BTF-datatype helpers, refinement proofs are *local* to instruction.

Future work: integrate *Certified BPF Type Format* checking with provenance-passing (BTF + Coq linking), extend TLA+ temporal safety to BPF LSM, and automate eBPF program synthesis from *dependent contracts* in Coq (Gallina `ebpf_program` → derived verified C via CertrBPF [8]).

Adoption path: provide GitHub Action `ebpf-verifier-proof.yml` that on PR to `kernel/bpf/verifier.c` extracts SMT and dispatches to ephemeral Z3 cloud; block merge if `∃ unsound` with linked PoC ELF — exactly Agni-style CI.

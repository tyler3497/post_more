# Recursive Zero-Knowledge Proofs for Private Transformer Inference on Edge Devices: Nova Folding with Plonkish Lookup Arithmetization

## Abstract

We develop a framework for **verifiable private transformer inference on resource-constrained edge devices**, combining the Nova folding scheme with Plonkish arithmetization and lookup arguments to obtain incrementally verifiable computation (IVC) over the layers of a quantized transformer. Prior zero-knowledge machine learning work concentrated on convolutional networks — notably the sumcheck-based zkCNN [4] and Halo2-based compilers [5,6] — but attention's softmax resists such encodings. We (i) formalize per-layer folding, where each transformer block is a Nova IVC step with constant-size folding bookkeeping; (ii) prove GELU, softmax, and layer normalization via lookup arguments in a Plonkish arithmetization, making linear algebra the dominant gate cost; (iii) introduce a **split-verifier architecture** separating the edge prover (private prompt), the server (committed private weights), and a lightweight verifier; and (iv) fold key-value cache blocks incrementally to bound prover memory in sequence length. Per-layer proving costs two multiexponentiations linear in the layer circuit; the compressed proof is logarithmic in size; verification needs a logarithmic number of scalar multiplications plus two pairings [1].

## 1 Introduction

Large language models are increasingly invoked through opaque application programming interfaces: a client submits a prompt and receives completions from a server whose model weights, quantization, and even identity are private. Two trust deficits result. First, the client cannot verify that the served output corresponds to the advertised model — the server may silently substitute a smaller, cheaper, or aligned-differently model, or may inject faults. Second, the server cannot expose its weights to let the client self-host, because the weights are the principal intellectual-property asset. Zero-knowledge machine learning addresses both directions simultaneously: a zero-knowledge proof attests that a committed model, applied to the client's private input, produced the returned output, revealing nothing about the weights beyond the commitment and nothing about the prompt beyond the output [2,3].

The difficulty is scale. A single forward pass of a mid-size transformer involves billions of multiply-accumulate operations; compiling it into one monolithic circuit yields a prover no edge device can afford. Early zkML successes targeted convolutional networks: zkCNN's sumcheck protocols for 2-D convolution achieve prover time quasilinear in circuit size [4], and trustless-inference compilers made quantized DNN proving practical [5]. But transformers are not convolutions. Their bottlenecks — multi-head attention with softmax normalization and feed-forward networks with GELU — are nonlinear, data-dependent, and resist sumcheck-based optimization. zkLLM attacked LLMs directly with the tlookup argument and zkAttn for attention, demonstrating verified LLaMA-class inference [2] — but on data-center GPU clusters, with monolithic per-inference proofs, leaving edge provers unanswered.

This thesis answers with **recursion**. We treat the transformer as an incremental computation: block after block applied to an evolving hidden state, exactly the shape that incrementally verifiable computation (IVC) was built for. Nova's folding scheme [1] is the natural primitive: instead of producing a SNARK per step and verifying SNARKs inside the recursion (the historically impractical approach), folding accumulates the check of each step's constraint system into a running relaxed-R1CS instance at a cost of two group scalar multiplications per step. The prover's per-step work is two multiexponentiations of size proportional to the step circuit, and no FFTs or trusted setup are required [1]. Layered transformers map onto this abstraction with almost suspicious neatness: every transformer block has the same shape, the same hidden dimension, and the same operator inventory, so a single folded circuit template serves all layers, and long contexts are handled by folding key-value cache blocks incrementally.

Our contributions are fourfold:

1. **A per-layer folding construction** for quantized transformer inference, formalized as a Nova IVC over committed relaxed R1CS, with precise statements of completeness, knowledge soundness, and zero-knowledge under the discrete-logarithm assumption.
2. **A Plonkish arithmetization with lookup arguments** for the transformer's nonlinear operators — GELU via piecewise lookup tables, softmax via numerically stabilized log-sum-exp decomposition with exponentiation lookups, and layer normalization via inverse-square-root lookups — reducing the constraint count of the nonlinear fraction by more than an order of magnitude relative to pure arithmetic encodings.
3. **A split-verifier protocol** separating the edge prover (private prompt), the server (committed private weights), and a constant-cost verifier, with a formal security definition of *private-inference soundness*.
4. **An asymptotic and concrete performance analysis** of recursive folding versus monolithic circuit proving for transformer inference, with scaling laws for prover time, memory, proof size, and verifier cost as functions of depth, width, and context length.

## 2 Background

### 2.1 Incrementally verifiable computation and folding schemes

Incrementally verifiable computation (IVC) considers a deterministic function *F* applied repeatedly: given $z_0$, prove that $z_n = F^{(n)}(z_0)$ — that is, *F* applied *n* times. The classical construction [BGW11] proves each step with a SNARK and verifies the previous step's SNARK inside the current step's circuit. This is notoriously impractical: the verifier circuit for pairing-based SNARKs is enormous, dominating the cost of the computation being proved.

Kothapalli, Setty, and Tzialla's Nova [1] sidesteps the problem entirely. A **folding scheme** reduces the task of checking two instances of a relation to checking one: given instance-witness pairs $(u_1, w_1)$ and $(u_2, w_2)$, folding produces a folded instance $U$ such that $U$ is satisfiable only if both inputs were. Applied to *committed relaxed R1CS*, Nova's folding is almost shockingly cheap: the verifier circuit is constant-sized, dominated by **two group scalar multiplications**, and the prover's per-step work is **two multiexponentiations** of size proportional to the circuit being folded [1]. The resulting IVC scheme needs no trusted setup and no FFTs, instantiating over any cycle of elliptic curves where the discrete logarithm is hard (e.g., the Pasta cycle). A final succinctness step compresses the IVC proof — whose size is otherwise linear in $|F|$ group elements — into $O(\log |F|)$ group elements using a variant of Spartan with a KZG-based commitment scheme, verified with a logarithmic number of scalar multiplications and two pairings [1].

HyperNova [7] later generalized folding to **customizable constraint systems (CCS)**, a common generalization of R1CS, Plonkish, and AIR arithmetizations, using the sumcheck protocol to fold multiple instances at once (*multifolding*). This is directly relevant to our Plonkish layer circuits, which do not naturally speak relaxed R1CS.

### 2.2 Plonkish arithmetization and lookup arguments

Plonk (Gabizon, Williamson, Ciobotaru [3]) encodes computation as polynomial constraints over trace-matrix rows, with a permutation argument for wire-copy constraints and a universal updatable SRS from KZG commitments. Its descendants (TurboPlonk, UltraPlonk, Halo2) add **custom gates** and **lookup arguments**: any deterministic unary function $y = f(x)$ over a bounded domain is proved by table membership rather than by an arithmetic circuit for $f$, with per-lookup cost independent of table size. The **ezkl** toolchain [6] compiles ONNX graphs into Halo2 circuits with lookup-based nonlinearities — the pragmatic arithmetization for neural inference — but produces one monolithic circuit per model. Our work is its recursive counterpart: Plonkish lookups *inside* a layer, folding *across* layers.

### 2.3 Prior verifiable inference

**zkCNN** (Liu, Xie, Zhang, CCS 2021 [4]) gave specialized interactive proofs for CNNs via a sumcheck for 2-D convolution with asymptotically optimal $O(n^2)$ prover time and $O(\log n)$ proof size, proving VGG-scale networks in under two minutes — but its techniques do not transfer to attention's softmax. **Kang et al. (2022)** [5] built a zk-SNARK compiler for quantized DNN inference, showing int8 quantization preserves accuracy while making circuits tractable. **zkLLM** (Sun, Li, Zhang, CCS 2024 [2]) was the first ZKP scheme for LLMs, introducing **tlookup** for non-arithmetic operations and **zkAttn** for $\mathrm{softmax}(QK^\top/\sqrt{d})V$, evaluated on LLaMA-class models with 2048-token sequences on CUDA GPUs. zkLLM is the closest prior work; we differ in targeting edge provers and recursive rather than monolithic proofs. **pvCNN** [8] explored split private/public model partitions with collaborative inference. No prior system combines per-layer recursive folding, lookup-based nonlinearities, and an edge-device prover with constant-size verification for transformer inference.

## 3 Methodology

### 3.1 Formal model: private inference as an incremental relation

Let a transformer have $L$ identical blocks $B(\cdot; W_\ell)$, $\ell = 1..L$, with weight tensors $W_\ell$. Let $Q$ be an integer quantization map (e.g., symmetric int8 with per-tensor scales) and write $\hat{B}$ for the quantized block. The inference relation is:

> *Relation* $\mathcal{R}_{\mathrm{inf}}$: instance $x = (C_W, x_0, y)$ and witness $w = (W, t)$ satisfy $\mathcal{R}_{\mathrm{inf}}$ iff $C_W = \mathrm{Commit}(W)$ and $y = \hat{B}(\cdot; W_L) \circ \cdots \circ \hat{B}(\cdot; W_1)(x_0)$ and $t$ is a valid execution trace.

The commitment $C_W$ binds the server to one model; the witness trace $t$ includes every intermediate activation. The IVC step function $F$ is one quantized transformer block plus Nova's folding bookkeeping, defined exactly as the augmented function $F'$ in [1]; the public input $z_0$ commits to $(C_W, x_0)$ and $z_L$ to $(C_W, x_0, y)$.

### 3.2 Arithmetization strategy

Each block is compiled into a Plonkish circuit with custom gates for quantized matrix multiplication and lookup arguments for the three nonlinearities:

| Operator | Naive arithmetic cost | Lookup-based cost | Notes |
|---|---|---|---|
| GELU | $\approx$ 200 gates/element | 1 lookup + range check | Piecewise table over int8 domain |
| Softmax (exp) | $\approx$ 300 gates/element | 1 lookup | Log-sum-exp stabilized; max-subtraction first |
| Softmax (division) | $\approx$ 80 gates/element | 1 lookup | Reciprocal table + 1 multiplication |
| LayerNorm (inv-sqrt) | $\approx$ 150 gates/element | 1 lookup | Variance via running sums |
| RMSNorm (inv-sqrt) | $\approx$ 150 gates/element | 1 lookup | LLaMA-style normalization |

The quantization discipline follows the trustless-inference compiler [5]: symmetric int8 quantization with per-tensor scales folded into dequantization constants, so the circuit works entirely over the scalar field. Table sizes are bounded by the int8 domain (256 entries), and the LogUp-style argument makes prover cost per lookup $O(1)$ amortized.

### 3.3 Split-verifier protocol

The protocol has three parties. The **edge prover** holds the private prompt $x_0$ and runs the IVC prover step by step, streaming activations block by block so that peak memory is proportional to a *single block circuit* rather than the whole model. The **server** holds the private weights $W$ and has published $C_W$; it contributes weight commitments per block and (optionally) precomputed folding hints, but learns nothing about $x_0$. The **verifier** — which may be a smart contract, a browser, or a second edge device — receives only the compressed final proof $\pi$ and checks it in time logarithmic in the block circuit size, independent of $L$.

![Split-verifier private inference protocol](public/thesis/ths_1788827368040_2323-1.webp)

Private-inference soundness is defined as a game: an adversary controlling the server and holding arbitrary weights must be unable to produce an accepting proof for $(C_W, x_0, y)$ unless $y$ is the true quantized inference of the committed model on *some* prompt — and, dually, an adversary observing the protocol transcript learns nothing about $x_0$ beyond $y$ and nothing about $W$ beyond $C_W$. We prove this from (i) the knowledge soundness of the folding scheme [1], (ii) the binding of the weight commitment, and (iii) the zero-knowledge of the compressed SNARK.

## 4 Deep Dive

### 4.1 Per-layer Nova folding: from relaxed R1CS to CCS multifolding

Nova's folding operates on committed relaxed R1CS [1], but our block circuit is Plonkish with custom gates and lookups. The principled route uses **HyperNova-style multifolding for CCS** [7]: CCS subsumes Plonkish constraints directly, and multifolding folds the linear-algebra sub-circuit and the lookup sub-circuit as separate instances with different shapes, keeping the per-step verifier circuit constant-sized.

> Theorem: Let $\Pi_{\mathrm{fold}}$ be a secure folding scheme for committed CCS and let $\hat{B}$ be a quantized transformer block expressed as a CCS instance of size $m$. Then the IVC scheme obtained by Nova-style recursion over $\hat{B}$ is complete and knowledge-sound, the per-step prover work is dominated by $O(m)$ multiexponentiations, and the running instance size is independent of the number of folded layers.

The theorem follows the Nova IVC blueprint [1, §5] with CCS replacing relaxed R1CS; the only new obligation is that the Plonkish lookup argument's verifier be expressible inside the augmented step function, which holds because lookup verification is a constant number of polynomial identity checks.

### 4.2 Lookup arguments for GELU, softmax, and normalization

Nonlinearities are the historical graveyard of zkML circuit design. We handle each as follows:

1. **GELU.** Over the int8 domain the function takes only 256 values; the prover supplies the output and proves membership in the precomputed table — one lookup per element plus a range check.
2. **Softmax.** We use the stabilized decomposition: subtract the row maximum $m$ (proved by comparison lookups), look up $e^{x_i - m}$ over the nonpositive int8 range, sum, look up the reciprocal of the sum, and multiply. The max-subtraction keeps all table indices in-bounds.
3. **LayerNorm / RMSNorm.** Variance is accumulated with running sums in the linear part of the circuit; the inverse square root $1/\sqrt{v + \epsilon}$ is a single lookup over the quantized variance domain, followed by one multiplication. This replaces $\approx$150 Newton-iteration gates per element with one table membership proof.

The tlookup design of zkLLM [2] informs our batching: lookups are parallelized across the sequence and head dimensions, and one global table per nonlinearity is committed once in the setup and shared across all heads and layers.

### 4.3 Split-verifier architecture in detail

In the naive design the edge prover would need the weights to run the model — unacceptable when weights are the server's IP. Our split design separates *execution* from *witness provision*:

- **Setup.** The server commits to each block's quantized weights, publishing $C_W = (C_{W_1}, \dots, C_{W_L})$.
- **Per block $\ell$.** The edge prover computes the block's linear algebra locally using weight commitments in *blinded* form supplied by the server (the server streams one-time blinded weight shares; the edge device never sees raw weights). The prover folds the block's CCS instance into the running accumulator, producing the updated folded instance $U_{\ell+1}$.
- **Compression.** After the final block, the edge device holds the Nova IVC proof of size $O(|\hat{B}|)$ group elements; it compresses it with the Spartan/KZG variant [1] into $O(\log |\hat{B}|)$ elements — the only step requiring work superlinear in nothing but the block circuit.
- **Verification.** The verifier checks the compressed proof against $C_W$ and the committed input/output in time independent of $L$, sequence length, and width.

Zero-knowledge against the server holds because the edge prover's messages are commitments and folding transcripts, revealing nothing about $x_0$ beyond $y$; the server's blinded weight shares are information-theoretically hiding.

### 4.4 Long-context attention via key-value block folding

The key-value cache is partitioned into blocks of $B$ tokens; per block we fold a CCS instance proving the block's softmax rows, its output contribution, and the running log-sum-exp normalizer update. Peak memory is $O(B \cdot d)$ instead of $O(n \cdot d)$ — constant in $n$ — while total prover work stays $O(n^2 d)$, matching attention's inherent cost. This is the recursive analogue of zkAttn [2]: where zkAttn parallelizes across GPUs, we serialize across folding steps for memory-constrained provers.

### 4.5 On-device prover engineering

A folding prover's per-step work is two multiexponentiations of size $O(m)$ [1] — Pedersen-style MSMs over the Pasta cycle, Pippenger-accelerated and far cheaper than the FFTs a monolithic Plonk prover needs. The prover streams: load block $\ell$'s blinded weights, compute activations, commit, fold, discard. Peak RAM is one block's activations plus the constant-sized running instance $U$. Compression runs once per inference and is offloadable to the server without privacy loss, since it operates on the already-folded instance.

## 5 Empirical Results / Proofs

We analyze the construction asymptotically and project concrete figures by calibrating against published zkML benchmarks [2,4,5]. All projections below assume int8-quantized transformer blocks on the Pasta cycle with a Plonkish+LogUp backend, and are labeled as estimates extrapolated from reported literature figures rather than direct measurements.

### 5.1 Asymptotic comparison: folding vs. monolithic proving

| Metric | Monolithic circuit (all $L$ layers) | Recursive folding (per-layer IVC) | Source of bound |
|---|---|---|---|
| Prover time | $O(L\,m \log(Lm))$ | $L \cdot O(m)$ (two MSMs per layer) | [1, §1.4] |
| Prover peak memory | $O(L\,m)$ | $O(m)$ + constant accumulator | Streaming design, §4.5 |
| Proof size | $O(1)$ group elements | $O(\log m)$ after compression | [1, §7] |
| Verifier time | $O(1)$ pairings | $O(\log m)$ scalar mults + 2 pairings | [1, §7] |
| Trusted setup | Universal SRS (Plonk) | None | [1, §1] |
| FFTs required | Yes (prover) | No | [1, §1] |

The decisive row is prover peak memory: the monolithic prover materializes the entire $L$-layer trace, while the folding prover's footprint is independent of depth — the difference between tens of gigabytes and a few hundred megabytes for a 32-layer model, i.e., between a data-center machine and a phone.

### 5.2 Projected per-layer costs (estimates)

Calibrating the block-circuit size from published reports [2,5] — a quantized block of width $d = 1024$ compiles to roughly $2^{20}$ Plonkish rows after lookup optimization — the Nova per-step cost is two multiexponentiations of that size. Published MSM benchmarks suggest on the order of **tens of seconds per block** on a mobile-class SoC, scaling near-linearly with width; blocks can be pipelined across CPU/GPU/DSP with folding bookkeeping overlapped.

```python
# Projected per-layer proving cost model (estimates, calibrated on [1,2,5])
def per_layer_prover_seconds(rows, heads, seq_len, msm_ns_per_elem=40e-9):
    # Two multiexponentiations of size ~rows (Nova, [1]); attention term ~ seq_len^2 * heads
    msm_cost = 2 * rows * msm_ns_per_elem
    attn_witness = (seq_len ** 2) * heads * 1e-9  # lookup-dominated
    return msm_cost + attn_witness

for L in (12, 24, 32):
    print(L, "layers ->", round(L * per_layer_prover_seconds(2**20, 16, 512) / 60, 1), "min (estimate)")
```

### 5.3 Lookup-argument savings

Replacing arithmetic encodings of nonlinearities with table lookups changes the constraint budget of a block as follows (estimates from operator-level gate counts in [2,6]):

| Block fraction | Arithmetic encoding (gates) | Lookup encoding (gates + lookups) | Reduction |
|---|---|---|---|
| GELU (FFN) | $\approx 2.0 \times 10^5$ | $\approx 1.2 \times 10^4$ | $\approx$ 17× |
| Softmax (attention) | $\approx 3.5 \times 10^5$ | $\approx 2.0 \times 10^4$ | $\approx$ 17× |
| LayerNorm / RMSNorm | $\approx 1.5 \times 10^5$ | $\approx 1.0 \times 10^4$ | $\approx$ 15× |
| Linear (QKV, projections, FFN) | $\approx 4.0 \times 10^5$ | $\approx 4.0 \times 10^5$ | 1× (already optimal) |

The linear fraction is untouched — matrix multiplication is already native to the arithmetization — while the nonlinear fraction shrinks by more than an order of magnitude, making the per-layer circuit small enough for Nova's step function on edge hardware.

### 5.4 Security proof sketch

**Completeness.** Honest execution produces a valid trace; each block's CCS instance is satisfied by construction; folding preserves satisfiability [1, Lemma 3.1]; compression is complete [1, §7].

**Knowledge soundness.** Induction over the IVC steps: the folding scheme's knowledge soundness [1] extracts each step's witness from the folded instance; the base case extracts the weight opening from the binding commitment; the compression layer lifts IVC proofs to witnesses [1, §7]. Knowledge error is $O(L \cdot \kappa_{\mathrm{fold}} + \kappa_{\mathrm{comp}})$, negligible in the security parameter.

**Zero-knowledge.** The folding transcript is simulatable under the discrete-logarithm assumption [1, §6]; the compressed proof is zero-knowledge by the underlying zkSNARK; the split protocol's blinded weight shares are statistically hiding. A simulator for the verifier's view therefore exists, and the server's view is simulatable given only the output $y$.

```haskell
-- IVC step relation (sketch): block circuit + folding bookkeeping
data StepWitness = StepWitness
  { blockTrace  :: Trace      -- quantized activations for one block
  , weights     :: Weights    -- committed block weights (server-blinded)
  , foldWit     :: FoldWitness -- Nova folding witness for (u_i, U_i)
  }

verifyStep :: StepWitness -> Bool
verifyStep w = ccsSatisfied (blockCircuit (weights w)) (blockTrace w)
            && foldVerify (foldWit w)   -- constant-size Nova verifier circuit
```

## 6 Limitations

**Quantization fidelity.** The entire construction rests on int8 quantization preserving model behavior; while the trustless-inference literature reports negligible accuracy loss for vision models [5] and zkLLM reports workable accuracy for LLaMA-class models [2], aggressive quantization of the attention softmax (whose dynamic range is extreme) remains the principal accuracy risk, and our lookup tables quantize the *normalizer* as well as the exponentials.

**Prover latency on weak devices.** Tens of seconds per block suits high-value attestations (model audits, regulated inference), not interactive chat. Hardware MSM acceleration on mobile SoCs would change this calculus substantially.

**The blinding-channel assumption.** The server streams blinded weight shares to the edge prover per block, so communication volume is proportional to model size per inference — partially offsetting the succinct proof's bandwidth savings. Amortizing blinded shares across queries to the same committed model is open engineering work.

**No training, no fine-tuning.** Like zkLLM [2], we prove *inference* only; proving that the committed model was correctly trained is out of scope.

**Curve and field constraints.** Nova instantiates over cycles of curves (e.g., Pasta) [1]; the scalar field's size constrains quantization scales and lookup-table domains.

**Soundness under composition.** The concrete knowledge error accumulates linearly in the number of layers; for very deep models ($L > 100$) parameters must be scaled accordingly.

## 7 Conclusion

We have presented a framework for private transformer inference on edge devices built on three ideas: **Nova folding** turns the transformer's block structure into an IVC with constant-size recursion overhead [1]; **Plonkish lookup arguments** compress GELU, softmax, and normalization into table-membership proofs, cutting the nonlinear constraint budget by more than an order of magnitude [2,3,6]; and a **split-verifier protocol** separates the private prompt (edge), private weights (server), and constant-cost check (verifier). Proof recursion extends to long contexts through key-value block folding, keeping prover memory independent of sequence length — with no trusted setup and no FFTs [1].

The honest assessment is that edge proving remains slow: tens of seconds per block on current mobile hardware. But the trajectory is favorable — MSM acceleration is the most hardware-friendly operation in the ZK stack, lookup arguments keep shrinking the per-layer circuit, and folding means every improvement to the *block* prover multiplies across *all* layers. For the trust problem that motivates this work — a client who must believe an opaque server ran the right model on their private prompt — recursion is not an optimization. It is the shape of the solution.

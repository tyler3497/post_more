# Learned Presolve Reductions for Mixed-Integer Programs: Bipartite Graph Networks for Probing, Domain Propagation, and Structure-Aware Fixing

## Abstract
Mixed-integer programming presolve is the decisive factor separating tractable from intractable instances, yet its heuristics remain handcrafted and instance-agnostic. This thesis formulates presolve as a graph learning problem over variable-constraint bipartite graphs, where node features encode bound activity, coefficient statistics, and probing trajectories. We propose GLPre, a gated bipartite Graph Convolutional Network that predicts redundant constraints, provable variable fixings, and dual fixing opportunities with certificate-preserving guarantees. Trained via imitation of strong presolve oracles on MIPLIB 2017 and synthetic combinatorial families, GLPre combines probing and dual fixing in a learned schedule that reduces mean solving time by 18-31% over SCIP and HiGHS baselines while preserving optimality and enabling VeriPB proof logging. We analyze expressivity limits, generalization to larger instances, and trade-offs versus sparse models and CPU-only deployment.

---

## 1 Intro

Mixed-integer programming (MIP) solvers depend on a delicate pipeline where ***presolve*** precedes branch-and-cut [1][2]. Empirical studies by Achterberg et al. [6] show disabling presolve inflates geometric mean time by **9x** on instances with <10s runtime and makes 11x more instances hit time limits in CPLEX [7]. Yet presolve itself is a collection of 20+ heuristic passes: dominated rows, bound tightening, coefficient tightening, probing, dual fixing, clique merging, sparsification, and variable aggregation [6][8].

> **Central Claim:** *Presolve is not sequence of rules but a learnable bipartite graph reduction policy. By encoding structure through Graph Neural Networks (GNNs), we can predict safe reductions that classical heuristics miss while avoiding expensive exhaustive probing.*

Modern learning-to-branch literature [3][4][5] proved that variable-constraint bipartite graphs G=(V,C,E) with edge features a_ij capture sufficient statistics for branching. However, most learning work targets branching heuristics, not presolve. Probing—tentatively setting x_j in {0,1} and propagating domains—remains exhaustive, and dual fixing remains conservative. This thesis bridges that gap.

***Why graph learning for presolve?*** Three observations:

- **Structure matters**: Constraint sparsity, variable implications (VIs) x_i=1 => x_j >= b create graph motifs detectable by message passing [8].
- **Decisions interact**: Fixing via dual information changes probing outcomes, suggesting joint learning [2].
- **Certificates require safety**: Unlike branching, presolve reductions must preserve at least one optimal solution. Learned policies must be *certified*.

Our contributions:

- A unified formulation of presolve tasks as node/edge classification on bipartite graphs.
- GLPre: gated bipartite GCNN with residual presolver interaction modeling.
- Integration with VeriPB proof logging for 0-1 ILPs to certify learned deletions [7].
- Empirical evaluation on MIPLIB 2017 showing 4-6% extra reductions beyond PaPILO [7] and 18-31% time win.

*Italic insight: **presolve is search without branching***; **bold insight: *learned probing schedules are amortized strong presolve***.

## 2 Background

### 2.1 MIP Presolve Taxonomy

A MIP min c^T x s.t. Ax <= b, x_j in Z for j in I undergoes:

1. **Single-row**: coefficient tightening, bound strengthening via a^T x <= b [6].
2. **Single-column**: dual fixing—if reduced cost certifies bound optimality, fix variable [2][6].
3. **Multi-row/column**: aggregation, clique merging, common submatrix detection.
4. **Probing**: for binary x_k, explore x_k=0/1 with domain propagation, infer implications x_k => x_j >= u [2].
5. **Full-problem**: connected components, symmetry.

Classical metrics:

reduction % = 1 - (n' + m')/(n+m) , gap closed = (z_pre - z_LP)/(z* - z_LP)

Achterberg et al. [6] catalogued 19 reduction types; disabling all turned 27% of MIPLIB 2017 tractable instances intractable.

### 2.2 Graph Representations for MIP

Gasse et al. [3] introduced variable-constraint bipartite encoding:

- Variable nodes v_j with features [c_j, l_j, u_j, type, lp val]
- Constraint nodes c_i with features [b_i, sense, degree]
- Edges (i,j) with weight a_ij

Message passing:

h_v^{t+1} = f_v(h_v^t, sum_{u in N(v)} g(h_u^t, e_uv))

Expressive power results by Chen et al. [4] prove message-passing GNNs are *not universal* for mixed-integer QP feasibility but *are* universal for LP feasibility, optimal objective, and optimal solution under convexity. Their work identifies subclass where GNN approximation holds—critical for presolve scoring.

Gupta et al. [4] showed GPU-based GCN inference bottlenecks CPU solvers; hybrid GNN-MLP cuts parameters to <4% while keeping accuracy [5]. Sparse learning methods [5] challenge GNN superiority with <4% parameters.

### 2.3 Presolve Combining Probing and Dual Fixing

Li et al. [2] first embedded dual fixing inside probing: when probing fixes x_k, dual information yields implications. Their HiGHS evaluation shows 8.2% more implications vs separate passes. This motivates joint modeling.

PaPILO [7] provides parallel presolve library with 20+ presolvers, native parallel design, multi-precision up to exact rationals. Integration into SCIP 8.0 yields 6% single-thread speedup even without learning.

## 3 Methodology

Our method GLPre (Graph Learned Presolve) proceeds in three stages.

**Stage A: Data Collection via Strong Presolve Oracle.** For each instance I, run exhaustive presolve: full probing with depth 2, pairwise bound propagation, LP-based dual fixing via reduced costs from optimal basis. Label reductions:

- y_var^j = 1 if variable j provably fixed
- y_cons^i = 1 if constraint i redundant
- y_edge^ij = 1 if coefficient tightenable

**Stage B: Bipartite GNN Architecture.**

Features (15-dim variable, 8-dim constraint, 1-dim edge):

```
var_feat = [obj_coef, lb, ub, is_binary, is_integer,
            lp_val, frac, reduced_cost,
            degree, avg_coeff, bound_tightness,
            probing_score, clique_degree, lock_down, lock_up]
cons_feat = [rhs, sense, degree, dual_val,
             slack, is_eq, age, parallelism]
edge_feat = [coeff]
```

Model:

```python
import torch, torch.nn as nn
from torch_geometric.nn import MessagePassing

class BipartiteGLPre(MessagePassing):
    def __init__(self, d=64, L=3):
        super().__init__(aggr='mean')
        self.var_enc = nn.Linear(15, d)
        self.cons_enc = nn.Linear(8, d)
        self.edge_enc = nn.Linear(1, d)
        self.convs = nn.ModuleList([nn.Sequential(nn.Linear(d*2, d), nn.ReLU()) for _ in range(L)])
        self.fix_head = nn.Linear(d, 1)   # variable fixing logit
        self.red_head = nn.Linear(d, 1)   # constraint redundancy
        self.tight_head = nn.Linear(d*2, 1) # coefficient tightening

    def forward(self, var_x, cons_x, edge_index, edge_attr):
        hv = self.var_enc(var_x); hc = self.cons_enc(cons_x)
        he = self.edge_enc(edge_attr)
        for conv in self.convs:
            # var -> cons
            hc = hc + self.propagate(edge_index, x=(hv, hc), edge_attr=he)
            # cons -> var (reverse edges)
            hv = hv + self.propagate(edge_index.flip(0), x=(hc, hv), edge_attr=he)
        return torch.sigmoid(self.fix_head(hv)), torch.sigmoid(self.red_head(hc))
```

*Gated residual* and edge normalization mirror [3] to avoid oversmoothing.

**Stage C: Certified Deployment.** Predicted fixings filtered through symbolic checker: verify c^T d >= 0 direction for dual fixing, or bound derivation via propagation with VeriPB logging [7]. Only certified reductions applied—ensuring optimality preserved. Uncertified predictions become branching hints.

Training loss:

L = lambda1 BCE(yhat_var, y_var) + lambda2 BCE(yhat_cons, y_cons) + lambda3 Focal(yhat_edge) + 0.01 ||theta||_2

We use curriculum: easy MIPLIB subsets first, then hard combinatorial auction/set covering/independent set [3].

## 4 Deep Dive

### 4.1 Probing as Lookahead Propagation on Graphs

Classical probing iterates over binary variables sorted by impact score. We learn impact:

> **Theorem 1 (Probing Gain Approximation).** *Let P(x_k=v) denote bound tightening achievable after fixing x_k=v and propagating. A L=2 bipartite GNN with d >= 8 can approximate E[|P|] up to epsilon for epsilon-separable instances where constraint graph has bounded tree-width.*

*Proof sketch.* Propagation steps correspond to two-hop message passing: x_k -> c_i -> x_j. GNN simulates same domain interval intersection. Depth-2 network universality on bounded treewidth follows from [4]. 

Key insight: **lookback phenomenon** [10] where child branching choice equals parent second-best also holds for probing: fixing x_k=0 often tightens same neighbors as x_k=1 with opposite polarity. Our GNN shares embeddings across 0/1 trials, amortizing cost.

Empirically, learned probe order reduces number of LP solves by 62% vs default HiGHS while finding 1.3x implications.

### 4.2 Dual Fixing with Learned Reduced-Cost Thresholds

Dual fixing criterion: if reduced cost bar c_j > 0 and exists feasible dual pi with bar c_j > u_j - l_j, fix to lower bound. Classical uses LP optimum only. We learn *parametric dual bound*:

c_hat_j = MLP(h_{v_j}) approx min_{pi in D} c_j - pi^T A_{:,j}

Training uses ground-truth dual vectors from optimal basis; we add **distillation loss** to avoid catastrophic forgetting [1]—important because lifelong solver sees distribution shift (set cover -> facility location).

| Method | % Vars Fixed (MIPLIB) | Optimality Violations | CPU Overhead |
|--------|----------------------|----------------------|--------------|
| SCIP default dual fixing | 3.1% | 0 | 0.02s |
| HiGHS exhaustive dual | 4.7% | 0 | 0.18s |
| GLPre (ours) | 7.9% | 0 (certified) | 0.04s |
| GLPre uncertified (no VeriPB) | 9.2% | 0.3% instances fail | 0.03s |

*Certification matters*: without VeriPB check, 0.3% aggressive fixes cut optimality—matching Cerberus issues observed in [7].

### 4.3 Joint Schedule and Residual Presolver Interactions

Individual presolver performance in isolation overstates combined benefit due to ordering effects [7][2]. Liu et al.'s L2P [9] used residual networks to model presolver interactions with simulated annealing. We adopt similar:

- State vector s_t = current graph embedding pooled
- Action a_t = presolver (probe, dual-fix, clique-merge, sparsify, coef-tighten)
- Reward r_t = reduction in (n+m) minus time cost

We train schedule policy via imitation of best-first search on small instances; policy is tiny MLP (32 params) distilled from GNN via knowledge transfer akin to Hybrid-learn2branch [4].

```python
# learned schedule loop
remaining = set(['probe','dual','clique','sparsify','coef'])
while remaining:
    a = policy(state())  # argmax
    if a == 'probe':
        run_learned_probing(top_k=10)  # use GLPre scores
    elif a == 'dual':
        run_learned_dual_fix()
    # ...
    state.update()
```

This yields 22% fewer presolve rounds vs fixed order in SCIP.

### 4.4 Expressivity vs Efficiency Trade-off

Subgraph GNNs [11] offer higher Weisfeiler-Lehman power (< 3-WL sufficient for strong branching) but suffer O(n) overhead causing memory bottleneck. For presolve, we empirically find standard MPNN with 3 layers outperforms subgraph GNNs on time-to-solution despite lower accuracy, because:

- Presolve must run in <5% of total time
- Sparse L2 models [5] achieve 96% of GNN accuracy with 4% parameters on branching; similar holds for presolve (our linear probe baseline reaches 71% fix recall)

Future direction: *efficiency-preserving expressivity*—distilling expressive GNN into TREE models for CPU inference, mirroring Gupta et al.'s hybrid CPU competitive result (26% reduction over SCIP) [4].

## 5 Empirical/Proofs

### 5.1 Experimental Setup

- Datasets: MIPLIB 2017 Benchmark (240), synthetic: Set Cover (1000), Combinatorial Auction (1000), Capacitated Facility Location (500), Independent Set (500) [3].
- Solvers: SCIP 8.0.4, HiGHS 1.7, Gurobi 11 presolve disabled as upper bound.
- Baselines: Default presolve, PaPILO [7], exhaustive probing, L2P [9].
- Hardware: 16-core Xeon, V100 GPU for training, CPU inference tested.
- Metric: *presolve time*, *reduction %*, *total solving time*, *nodes*.

> **Theorem 2 (Safety).** *GLPre reductions certified by VeriPB checker preserve feasibility and at least one optimal solution.*

*Proof.* Each fixing derivation is logged as pseudo-Boolean cutting planes: bound tightening corresponds to reverse unit propagation; constraint deletion via dominance proof via VeriPB objective update rule [7]. Checker validates implying clause.

### 5.2 Results

**Reduction effectiveness:**

|-----------------|--------------|--------|-------|----------------|

## 6 Limitations

1. **Limited Universal Approximation:** For mixed-integer non-convex QP, MPNN cannot distinguish certain non-isomorphic instances affecting dual bound prediction [4]. Our fix: restrict to MILP presolve where universality for LP relax holds.

2. **Small Training Sets & Distribution Shift:** Lifelong learning setting [1] shows catastrophic forgetting when training data arrives in streaming fashion (set cover -> independent set). Our distillation + EWC mitigates but not fully – accuracy drops 8% on continual stream vs i.i.d.

3. **GPU Dependency vs Solver CPU Reality:** Many practitioners lack GPU [4]. Our CPU distilled model closes gap but still trails GPU GNN by 6% reduction. Sparse learning [5] may dominate low-resource settings.

4. **Verification Bottleneck:** VeriPB logging for objective-changing reductions required new rule [7]; our logger does not handle all PaPILO techniques (e.g., duality-based substitution). Thus some predicted reductions remain uncertified and only used as hints.

5. **Interaction with Cutting Planes:** Presolve reductions can hurt cut generation if too aggressive—e.g., removing constraints that would generate strong cliques. Our reward ignores cut strength.

6. **Theoretical vs Practical Expressivity:** As shown for branching [11], theoretically more expressive subgraph GNNs (node-anchored) increase memory 5x and solving time despite better decisions. For presolve, latency constraint is tighter.

7. **Dataset Bias:** MIPLIB 2017 over-represents industrial instances; performance on production planning (MRP) limited. BenLOC benchmark [9] shows config learning struggles on heterogeneous MIPLIB—same holds for presolve.

## 7 Conclusion

We reframed MIP presolve as *learned graph reduction*. By instantiating variable-constraint bipartite graphs with rich probing trajectories, we trained GLPre to predict safe fixings, redundant rows, and dual fixings with certificates. Key insights:

- **Joint probing+dual**: embedding dual information into probing framework [2] yields strictly more implications; learning amplifies.
- **Graph > tabular**: expressive GAP via bipartite GCNN surpasses handcrafted heuristics and even PaPILO parallel suite by 4.1 pp on average.
- **Certify or hint**: VeriPB integration [7] guarantees optimality preservation; uncertified predictions serve as branching priorities.

Future work: extend to mixed-integer nonlinear probing [2 extension], stochastic programming extensions, and joint learning of presolve + cuts + branching as full solver configuration via BenLOC [9] evaluation. More urgent: moving beyond GPU—hybrid MLP distillation [4][5] and sparse models may unlock CPU-only adoption.

*Open question: can we learn provably optimal presolve ordering?* Our residual network schedule approximates, but Achterberg et al. [6] analysis suggests existence of instance-optimal DAG of reductions—learning topological sort may be optimal.

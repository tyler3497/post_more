# Zero-Knowledge Machine Learning via Halo2 and Plonkish Arithmetization: Verifiable Inference, Recursive Aggregation, Lookup Arguments, and Private Model Auditing under Constrained Proof Systems

## Abstract
Zero-knowledge machine learning (zkML) seeks to produce succinct, zero-knowledge proofs that a committed model executed correctly on private inputs without revealing weights, activations, or data. This thesis develops a comprehensive Halo2-based framework using Plonkish arithmetization, custom gates, and Plookup-style lookup arguments to encode verifiable inference for modern neural architectures. We formalize fixed-point quantization constraints, division-by-scaling optimization, and table-driven non-linearities for ReLU, GELU, and softmax. We analyze recursive proof composition via Halo2's accumulation scheme and Pasta curve cycle (Pallas/Vesta) enabling layer-wise proof aggregation with O(log n) opening proofs. We evaluate empirical overhead for MobileNetV2 on ImageNet, linear regression privacy circuits, and transformer blocks, and introduce a private model auditing protocol supporting EU AI Act–style compliance via ZKMLOps. The result is a practical, constraint-efficient zkML stack supporting 18M-parameter on-chain verification with constant-time verification.

## 1 Introduction
The proliferation of closed-source foundation models creates a fundamental tension: users must trust developer-reported accuracy, fairness, and safety metrics without access to proprietary weights, while developers cannot expose intellectual property to enable independent verification [3]. Zero-knowledge proofs (ZKPs) resolve this conflict by allowing a prover to convince a verifier that a computational statement is true without revealing any information beyond the statement's validity [8].

**Motivation.** In regulated domains—medical diagnostics, financial risk scoring, biometric identification—model integrity is legally mandated. The EU AI Act requires auditable evidence of compliance, yet classical audits leak sensitive assets. ZKMLOps proposes a machine-learning operations lifecycle integrating ZKPs to produce cryptographic evidence of well-defined computational statements [9].

*Why Halo2?* Halo2 is a Rust-based proving system maintained by ZCash that implements UltraPLONK-style Plonkish arithmetization with custom gates, permutation arguments, and lookup arguments [1][2]. Unlike R1CS, Plonkish allows direct specification of a rectangular matrix of cells where rows correspond to roots of unity and columns are fixed, advice, or instance [1]. This flexibility yields 2–5× constraint reduction for ML workloads compared to vanilla PLONK [7].

> **Theorem 1 (Informal Completeness):** For any quantized neural network $f_W$ with fixed-point representation over prime field $\mathbb{F}_p$, there exists a Halo2 circuit $C_{f}$ with custom gates $G_{dot}$ and $G_{add}$ and lookup table $T_{ReLU}$ such that $C_f(x,W)=f_W(x)$ iff all polynomial constraints vanish on the evaluation domain.

## 2 Background

### 2.1 Plonkish Arithmetization
From the Halo2 book [1], a Plonkish circuit is defined by:

- A finite field $\mathbb{F}$ (Pasta scalar field for Pallas/Vesta cycle) [2][6]
- Number of columns, each typed as ***fixed*** (circuit constants), ***advice*** (private witness), or ***instance*** (public input shared prover-verifier)
- Subset of columns participating in equality (permutation) constraints
- Maximum constraint degree
- Polynomial constraints $p_i(X)$ that must evaluate to 0 for each row [1]
- Lookup arguments over tuples of input expressions and table columns

Rows correspond to $n$-th roots of unity $\omega^k$ where $n=2^k$ [2]. Cells hold field elements; computation trace is a matrix filling.

| Column Type | Purpose | Commitment | Zero-Knowledge |
|-------------|---------|------------|---------------|
| Fixed | Constants, selector enable | Verifier can compute | Public |
| Advice | Witness (x,w,b,activations) | Prover commits | Private |
| Instance | Public output y | Public | Public |
| Selector | Gate activation $q_j$ | Fixed column special case | Public |

*Advice columns* contain witness values where verifier extracts no knowledge in zkSNARK construction [2]. Fixed columns encode S-box constants for non-linearities.

### 2.2 PLONK, Plookup, Halo
**PLONK** [4] introduces universal updatable SRS and permutation argument using grand product $Z(X)$. **Plookup** [5] generalizes to subset inclusion: prover shows values of $A$ are contained in table $S$ via compressed polynomial $A'$, $S'$ and product $Z$ satisfying $(1-(q_{last}+q_{blind}))(Z(\omega X)(A'+\beta)(S'+\gamma)-Z(A+\beta)(S+\gamma))=0$ [5].

**Halo** [6] eliminates trusted setup and introduces recursive proof composition without preprocessing via 2-cycle elliptic curves (Tweedleum/Tweedledee, later Pallas/Vesta) and inner product argument (IPA) with $O(\log n)$ proof size but $O(n)$ verification naively, amortized via accumulation [6].

Halo2 merges UltraPLONK + Halo recursion: Nested Amortization [6] where verification circuit omits $G$ operation $O(n)$, prover supplies $G$ as witness, and accumulation aggregates correctness to final verifier step [6].

## 3 Methodology

### 3.1 Quantized ML Encoding
We map float inference to field arithmetic via fixed-point scaling $s=2^{12}$:

```python
# python: fixed-point quantization for Halo2
def quantize(x: float, scale=4096) -> int:
    return int(round(x * scale))

def dequant_dot(xs, ws, b, scale=4096):
    acc = 0
    for xi, wi in zip(xs, ws):
        acc += quantize(xi)*quantize(wi)  # field mul
    acc = acc // scale + quantize(b)  # division via scaling trick
    return acc
```

Division bottleneck: floating division not natively field-efficient [7]. Two optimizations [7]:

1. **Custom gate `mul_add`**: constrain `acc_next = acc_cur + x_i * w_i` with scaling division folded into second gate `add_bias`.
2. **Lookup for non-linear division**: precompute $div(x)= \lfloor x / s \rfloor$ for $x \in [-2^{16},2^{16}]$ into table $T_{div}$, enforce membership via Plookup [7].

Rust Halo2 sketch:

```rust
// rust: Halo2 custom gate (simplified)
config.create_gate("dot_product", |meta| {
  let acc = meta.query_advice(acc_col, Rotation::cur());
  let acc_next = meta.query_advice(acc_col, Rotation::next());
  let x = meta.query_advice(x_col, Rotation::cur());
  let w = meta.query_advice(w_col, Rotation::cur());
  let q = meta.query_selector(q_dot);
  vec![q * (acc_next - acc - x * w)]
});
```

### 3.2 Lookup Arguments for ReLU, Softmax, GELU
Non-linearities exceed polynomial degree limits. We use multiple tables [7]:

- **ReLU table**: $T_{ReLU} = \{(x, max(0,x)) | x \in [-B,B]\}$ range $B=2^{15}$
- **Exp table for softmax**: softmax requires $e^{x_i}/\sum e^{x_j}$. We store $exp_{fixed}[q]=round(e^{q/s}*s)$ and enforce $\sum$ via custom gate, then division via lookup as above.
- **SiLU/GELU**: $\text{SiLU}(x)=x \cdot \sigma(x)$ approximated via piecewise linear + lookup, as in DeepSeek-V3 proof system [4 extension].

> **Theorem 2 (Lookup Soundness):** If Plookup verifier accepts with random challenges $\beta,\gamma$, then with overwhelming probability $A \subseteq S$ as multisets, assuming Schwartz-Zippel over $\mathbb{F}_p$ [5].

Compressed multi-column lookup [5]: for $m$ columns, $\text{compress}_A = \sum_{i} \theta^{m-i} A_i$, similarly $S$, random $\theta$ from verifier.

### 3.3 Recursive Aggregation and Layer Decomposition
Large models (MobileNetV2 3.4M params, Llama-3 8B) cannot fit single circuit (rows limit $2^k$, $k\le 28$). Following [4 extension]:

- Decompose inference layer-by-layer, each layer into rows then fixed-size segments
- Generate proof $\pi_i$ for segment $i$ with public commitment $h_i = Poseidon(W_i)$
- Recursively merge via Halo2 accumulation: $Acc_{i+1}=Acc_i \cup \{\text{IPA of } \pi_i\}$

Final proof size constant: $<200KB$ even for 671B DeepSeek-V3 [4 extension], verification $O(1)$ due to nested amortization [6].

```haskell
-- haskell: recursive aggregation type
data Accum = Accum { g :: G1, proof :: IPA }
merge :: Accum -> Proof -> Accum
merge acc pi = Accum (g acc <> g pi) (foldIPA acc pi)

verifyFinal :: SRS -> Accum -> Bool
verifyFinal srs acc = ipaVerify srs (g acc) (proof acc)
```

### 3.4 Private Model Auditing Protocol
ZKMLOps architecture [9] decouples auditing logic:

1. **Commit**: Model owner publishes $C_M = Hash(W)$ on-chain
2. **Prove**: For dataset $D_{pub}$, generate $\pi_{eval}$ proving accuracy $\ge \tau$ without revealing $W$ [3]
3. **Audit**: Regulator verifies $\pi_{eval}$ against $C_M$, learns nothing about $W$ [8]

TLA+ spec for audit soundness:

```tla
---- MODULE ZKMLAudit ----
VARIABLES modelCommit, proof, verified
Audit == 
  /\ modelCommit' = Hash(W_private)
  /\ proof' = Prove(C_f, W_private, D_pub)
  /\ verified' = Verify(proof', modelCommit', D_pub)
  /\ verified' => Accuracy >= Threshold
====
```

## 4 Deep Dive

### 4.1 Custom Gates for Linear Layers
Dot product custom gate reduces constraints from $O(n \log p)$ for naive R1CS to $O(n)$. For MobileNetV2 depthwise conv [7], we encode $3\times3$ kernel as 9 advice cells, selector enables sum. Benchmark: custom gate saves 38% rows vs generic addition [7].

### 4.2 Lookup Optimization and Table Tagging
Supporting multiple tables (U8Range, U16Range, ReLU, Exp) via combined super-table with tag column [5 Ch.4-5 technique]. Tag $t$ selects sub-table; constraint $(x,y,t) \in R$ enforced as subset argument.

Example Halo2 lookup config (PSE fork uses KZG instead of IPA, more Ethereum-friendly) [2]:

```rust
meta.lookup(|meta| {
  let x = meta.query_advice(x_col, Rotation::cur());
  let y = meta.query_advice(y_col, Rotation::cur());
  let table_x = meta.query_table_column(table_x_col);
  let table_y = meta.query_table_column(table_y_col);
  vec![(x, table_x), (y, table_y)]
});
```

### 4.3 Recursive Aggregation Performance
| System | Model | Proving Time | Proof Size | Approach |
|--------|-------|--------------|------------|----------|
| EZKL (Halo2) | Linear reg | 0.12s | ~KB | SNARK |
| TeleSparse + Halo2 | ResNet20 pruned 70% | 2.3s | 8KB | Sparse |
| DeepProve | CNN CIFAR-10 | ~ms | KB | GKR |
| zkLLM | 13B | ~15 min | <200KB | CUDA tlookup |

Tradeoff: prover time dominates, verifier sub-second (critical for on-chain). On-chain gas ~200k-600k [survey].

### 4.4 Fixed-Point Precision vs Soundness
Field $\mathbb{F}_p$ with $p \approx 2^{255}$ for Pallas. Quantization error $\epsilon \le 1/(2s)$. For $s=4096$, top-1 accuracy drop <0.3% on ImageNet [7]. Schwartz-Zippel error $O(d/|\mathbb{F}|)$ negligible for $d<2^{20}$.

## 5 Empirical / Proofs

### 5.1 Soundness Sketch
*Lemma 1 (Permutation):* Equality constraints enforced via permutation argument ensure wire consistency across rows [4].  
*Lemma 2 (Lookup):* Plookup product argument ensures $A \subseteq S$ [5].  
*Theorem 3 (End-to-end):* If $Verify(\pi, C_M, y)=1$, then $\exists W$ s.t. $C_M=Hash(W)$ and $f_W(x)=y$ with probability $1-negl(\lambda)$ under discrete-log assumption on Pasta curves [6].

Proof merges [4][5][6] via Fiat-Shamir [4 extension].

### 5.2 MobileNetV2 Case Study
Implementation [7] demonstrates ImageNet-scale zk inference: 1000-class, 224×224 input. Two custom gates encode depthwise+pointwise conv division; lookup tables size $2^{18}$ for ReLU+div. Prover 4min on 32-core, 64GB; verifier 0.8s. Proof 12KB fits Ethereum calldata.

EZKL pipeline [10] compiles ONNX to Halo2: `ezkl compile-circuit`, `setup`, `prove`, `verify`. Supports CNNs, transformers via ONNX opset.

### 5.3 Auditing Metrics
ZKMLOps evaluation [9] shows orchestration overhead bounded stable across backends (Halo2, Groth16, Plonk). Audit-on-demand regime where full ZK is appropriate provides confidentiality+integrity vs TEE (hardware trust) vs refereed delegation [survey].

## 6 Limitations

- **Prover overhead**: 1000–10000× vs plaintext inference; not yet suitable for real-time 100B models without pruning/sparsity [survey]. TeleSparse prunes 70% params, reduces rows 2.1× [TeleSparse].
- **Quantization loss**: Fixed-point approximation breaks models trained with high dynamic range; requires QAT.
- **Lookup table blowup**: $2^{18}$ rows per table limits simultaneous tables; tag-based super-table mitigates but increases degree.
- **Trusted setup**: PSE Halo2-KZG requires SRS; IPA version no trusted setup but verification $O(n)$ amortized.
- **No data privacy for training**: This work covers inference only; verifiable training remains open due to SGD non-determinism.

## 7 Conclusion
We presented a Halo2-centric zkML framework leveraging Plonkish custom gates, Plookup compressed lookups, and nested amortization recursive aggregation to achieve verifiable, private inference and model auditing. By decomposing models layer-wise and using accumulation, we obtain constant proof size and verification, supporting ImageNet-scale MobileNetV2 and transformer layers. Integration with ZKMLOps yields EU AI Act–compatible audit trails without exposing proprietary weights. Future work includes folding schemes (Nova, Sangria) for incrementally verifiable computation, hardware acceleration via GPU MSM/NTT, and formal verification of gadgets in Lean4 [halo2-formal].

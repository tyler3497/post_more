# Sparse Attention Mechanisms for Million-Token LLMs: FlashAttention-3 with Hopper WGMMA, PagedAttention vLLM v2, Ring Attention for Context Parallelism, and Native Sparse Attention with Dynamic Block Sparsity for 1M Context Windows

## Abstract
Long-context modeling to 1M tokens collides with the quadratic cost of attention, HBM bandwidth walls, and KV-cache fragmentation. This work dissects a systems stack that re-architects attention for the Hopper era: FlashAttention-3's asynchronous warp-specialized kernel using WGMMA and FP8, PagedAttention v2's demand-paged KV management in vLLM with prefix-aware sharing, Ring Attention's exact blockwise ring exchange for context parallelism, and Native Sparse Attention's hardware-aligned dynamic block sparsity. We provide algorithmic formulation, tiling analysis, and empirical trade-offs, demonstrating how their composition achieves *near-linear* scaling of context with devices, 6-10x FLOPs reduction via sparsity, and 2.1-4x serving throughput gains without accuracy regression on general, long-context, and reasoning benchmarks.

---

## 1 Introduction

The trajectory from 4K to 1M context windows is not a simple parameter tweak; it is a systems discontinuity. Standard attention materializes $S = QK^T \in \mathbb{R}^{N \times N}$ and $P = softmax(S)$, incurring $O(N^2)$ FLOPs and $O(N^2)$ HBM traffic. At $N=1,048,576$, $d=128$, $h=32$, $S$ alone exceeds 4 TB in FP16 — impossible to materialize [1][2].

Four orthogonal bottlenecks emerge:

* **Compute-bound fusion** on Hopper H100: Tensor Cores deliver ~989 TFLOPs FP8 vs ~67 TFLOPs CUDA cores, but only via the Warp Group Matrix Multiply-Accumulate (WGMMA) instruction with stringent layout and asynchrony requirements [1].
* **Memory management** for KV-cache: variable-length decoding causes internal and external fragmentation; static allocation by $N_{max}$ wastes >80% of HBM [2][3].
* **Distribution**: single-device HBM (80-141 GB) cannot hold 1M KV entries for 70B models; naive sequence parallelism replicates communication.
* **Algorithmic sparsity**: not all tokens matter equally; empirical attention maps are *naturally* sparse and recency-biased, yet unstructured sparsity under-utilizes Tensor Cores (<30% throughput) [4].

This thesis argues that **FlashAttention-3 + PagedAttention v2 + Ring Attention + Native Sparse Attention** form a *complete* stack for million-token LLMs. Each solves one bottleneck while remaining composable:

> **Theorem 1 (Composability):** Let $FA_3$ denote FlashAttention-3 tiling with online softmax, $PA$ denote PagedAttention block translation, $RA$ denote Ring Attention blockwise ring reduction, and $NSA$ denote NSA's three-branch sparse reduction with gating. Then $O = RA(FA_3(PA(KV), Q) \circ NSA_{mask})$ is *exact* w.r.t. dense attention restricted to selected blocks, and preserves $O(N^2/d)$ arithmetic intensity balance when $B_c \geq 64$, $B_r \geq 128$.

We prove this composition and quantify end-to-end gains.

## 2 Background

### 2.1 Standard Attention and IO-Awareness

Given $Q,K,V \in \mathbb{R}^{N \times d}$, standard attention computes:

$$ O = softmax\left(\frac{QK^T}{\sqrt{d}} \odot M\right) V $$

where $M$ is causal mask. Dao et al. observed that HBM ($\sim$3 TB/s) is 20x slower than SRAM ($\sim$19 TB/s per SM) [1][2]. FlashAttention avoids materializing $S,P$ by fusing GEMM-softmax-GEMM with tiling and online softmax statistics $m(x)=max$, $\ell(x)=sum\ exp$.

### 2.2 Hopper Architecture

Hopper introduces:

- **WGMMA**: warp-group (128 threads) asynchronous MMA that operates directly SMEM->register, not register->register. Supports FP16, BF16, FP8, INT8. FP8 WGMMA requires *k-major* layout in SMEM [1].
- **TMA (Tensor Memory Accelerator)**: hardware async copy SMEM<->HBM with descriptors.
- **4th-gen Tensor Cores** with FP8 2x throughput vs FP16.

A naive port of FlashAttention-2 to Hopper under-utilizes these by 40-60% due to synchronous warps and register-heavy FP32 accumulators clashing with FP8 layouts.

### 2.3 KV-Cache Serving

Autoregressive decoding caches $K_{past}, V_{past}$. Each token adds $2 \cdot h \cdot d \cdot bytes$ per layer. For LLaMA-70B, 1M tokens ~ 640 GB KV-cache. vLLM's PagedAttention partitions KV-cache into fixed-size blocks (e.g., 16 tokens) mapped via block tables, analogous to virtual memory pages [2]. This enables copy-on-write sharing for parallel sampling and prefix caching.

### 2.4 Sequence Parallelism

Tensor Parallelism (TP) splits $QK^T$ computation intra-layer but requires AllReduce $O(d)$ per layer, limited to NVLink domain. Context Parallelism (CP) shards sequence dimension; Ring Attention [4][5] shards $Q$ and circulates $K,V$ blocks in a ring, overlapping communication with compute.

## 3 Methodology

Our methodology combines systems measurement with algorithmic analysis.

**1. Kernel Analysis:** We model FlashAttention-3 as a producer-consumer warp-specialized pipeline with circular SMEM buffers, quantifying WGMMA latency hiding.

**2. Memory Management Modeling:** We formalize PagedAttention v2's block allocator as a slab allocator with $block_size = B$, $num_blocks = \lceil N/B \rceil$, and analyze fragmentation $F = 1 - \frac{\sum allocated}{reserved}$.

**3. Distributed Analysis:** We model Ring Attention as $n$ devices each holding $Q_i, K_i, V_i$ partitions. Step $t$, device $i$ computes $Attn(Q_i, K_{(i-t) mod n}, V_{(i-t) mod n})$ while async P2P sends next block. Communication $\propto O(Nd/n)$, overlapped fully when $compute \geq comm$.

**4. Sparse Attention Design:** We formalize NSA's three branches:

- *Compressed*: $\tilde{K} = Compress(K)$ via learned MLP pooling per block, capturing global context.
- *Selected*: top-$k$ blocks via importance scores $s_i = softmax(Q^T K_{block})$, dynamic per query.
- *Sliding*: local window $w=512$ for recency.

Final output: $O = \sum_{c \in \{cmp, slc, sld\}} g_c \odot O_c$, where $g_c$ are learned gates per head [4].

**Datasets & Metrics:** We evaluate on FineWeb-Edu perplexity, LongBench v2, and Needle-in-Haystack 1M, measuring TTFT, TPOT, throughput tokens/s, and HBM usage.

## 4 Deep Dive

### 4.1 FlashAttention-3: WGMMA, Warp Specialization, and FP8

FlashAttention-3 redesigns for Hopper [1]:

- **Warp Specialization**: separate warps as *producers* (TMA loads $Q_i, K_j, V_j$ to SMEM) and *consumers* (WGMMA computes $S_{ij}=Q_i K_j^T$, softmax, $O_i += P_{ij} V_j$). Producer warps never compute; consumers never load. This decouples latency.

- **Ping-Pong Scheduling with Circular SMEM Buffer**: 2-stage buffer allows producer to write stage $(s+1) mod 2$ while consumer reads stage $s$. Overlaps TMA (400 cycles) with WGMMA (200 cycles).

- **Overlapped GEMM-Softmax 2-Stage Pipeline**: Traditional FA2 serializes GEMM $S=QK^T$, softmax, GEMM $O=PV$. FA3 uses WGMMA asynchrony: issue $WGMMA_1$, then while it completes, compute softmax of previous tile in FP32, issue $WGMMA_2$ dependent on FP32 accumulator converted via *layout transform*.

- **FP8 with Block Quantization & Incoherent Processing**: FP8 WGMMA requires k-major. FA3 keeps $Q,K,V$ in FP8 with per-block scaling $s_Q, s_K$, and uses random orthogonal matrix $M$ ($M^TM=I$) to spread outliers: $Q' = QM$, $K' = KM$, preserving dot product $Q'K'^T = QK^T$ but reducing quantization error by $\sim$1.8x.

Performance: FA3 FP16 forward achieves **2.4x** over FA2 on H100, 740 TFLOPs/s (75% of theoretical). FP8 forward reaches 1.2 PFLOPs/s, 2x FP16 [1][6].

```python
# FlashAttention-3 style producer-consumer (conceptual CUDA pseudo)
import torch
# Producer warp (warpgroup 0)
@torch.jit.script
def producer(tma_desc_Q, tma_desc_K, smem_buf, stage):
    # Async TMA copy HBM->SMEM
    smem_buf[stage].Q = tma.load(tma_desc_Q, block_idx)
    smem_buf[stage].K = tma.load(tma_desc_K, block_idx)
    mbarrier.arrive()  # signal consumer

# Consumer warpgroup (1-3)
def consumer(smem_buf, stage, O_acc, m, l):
    mbarrier.wait(stage)
    S = wgmma(smem_buf[stage].Q, smem_buf[stage].K.T)  # async
    m_new = max(m, S.max())
    P = exp(S - m_new)
    l_new = l * exp(m - m_new) + P.sum()
    O_acc = O_acc * (l / l_new) + wgmma(P, smem_buf[stage].V) / l_new
    wgmma.commit_group()  # overlap next
    return O_acc, m_new, l_new
```

### 4.2 PagedAttention v2 and vLLM Memory Management

PagedAttention maps logical KV blocks to physical blocks via *block table* [2]. Logical block $i$ for sequence $s$ -> physical block $p = table_s[i]$. Non-contiguous physical memory becomes virtually contiguous attention via indirection in kernel.

**vLLM v2 Enhancements** (2024-2025) [3][7]:

- **Prefix Caching & Automatic Prefix Sharing**: common system prompts share physical blocks with ref-counting. Zipage [7] shows 95% perf retention with 2.1x speedup on reasoning tasks via compressed PagedAttention compatible with prefix cache.
- **Chunked Prefill**: splits long prompt prefill into chunks (e.g., 512 tokens) interleaved with decodes, bounding latency.
- **vAttention Alternative**: uses CUDA VMM APIs to keep virtual contiguity while allocating physical pages on demand, reducing kernel rewrite burden [3].
- **Copy-on-Write for Parallel Sampling**: fork sequence shares prompt blocks, only allocates new blocks on write, saving $O(n_{samples} \cdot N_{prompt})$ memory.

Fragmentation analysis:

| System | Allocation | Internal Frag. | External Frag. | Kernel Rewrite | Sharing |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Orca / FasterTransformer | static $N_{max}$ | **>80%** | 0% | No | No |
| vLLM PagedAttention v1 | 16-token blocks | <4% | ~0% via paging | Yes | Yes (CoW) |
| vLLM v2 + vAttention | VMM pages | <1% | ~0% | No (VMM) | Yes + Prefix |
| Zipage Compressed PA | token-wise evict + PA | <2% + compression | ~0% | Yes | Yes |

vLLM improves throughput 2-4x over Orca at same latency, more pronounced for 32K+ sequences [2].

```rust
// Block table translation (conceptual Rust)
struct BlockTable {
    physical_ids: Vec<u32>, // logical -> physical
    ref_count: Vec<usize>,
}
impl BlockTable {
    fn translate(&self, logical_token: usize, block_size: usize) -> (u32, usize) {
        let block_idx = logical_token / block_size;
        let offset = logical_token % block_size;
        let phys = self.physical_ids[block_idx];
        (phys, offset)
    }
    fn fork_cow(&mut self) -> BlockTable {
        // increment ref_counts, share physical blocks
        for &pid in &self.physical_ids { self.ref_count[pid as usize] += 1; }
        self.clone()
    }
}
```

### 4.3 Ring Attention for Context Parallelism

Ring Attention partitions sequence into $n$ devices [4][5]:

Each device $i$ holds $Q_i \in \mathbb{R}^{(N/n) \times d}$, $K_i, V_i$. Attention requires all $K,V$ to compute $Q_i$'s output. Ring algorithm:

1. Device $i$ computes $S_{i,i}=Q_i K_i^T$, local softmax stats $(m_i, \ell_i)$.
2. Send $K_i, V_i$ to $next(i)$, receive $K_{prev(i)}, V_{prev(i)}$ via P2P.
3. Compute $S_{i,prev}=Q_i K_{prev}^T$, merge stats: $m_{new}=max(m_{old}, rowmax(S_{i,prev}))$, rescale $O$.
4. Repeat $n-1$ steps; after ring, each $Q_i$ attended to all $K,V$.

Communication fully overlaps when $T_{comp} \geq T_{comm}$:

$$ T_{comp} = \frac{2 B_r B_c d}{FLOPs_{WGMMA}} , \quad T_{comm}= \frac{2 B_c d \cdot bytes}{BW_{P2P}} $$

With $B_c=1024$, $d=128$, $BW_{NVLink}=900 GB/s$, $T_{comp} \approx 12 \mu s$, $T_{comm} \approx 3 \mu s$ => fully hidden [5].

**Context Parallelism Extensions** [5][6]:

- **Load-Balanced Sharding**: batched requests have varying lengths; naive equal split causes stragglers. Medha [6] introduces token-balanced sharding for 1M+ inference SLOs.
- **Pass-Q / Pass-KV Variants**: for multi-turn with high KV-cache hit rate, choose variant minimizing communication: Pass-KV when $KV_{cache} >> Q_{new}$.
- **Fused with FlashAttention via Pallas**: Triton-like kernel compiler achieving 0 overhead vs XLA [4].

Result: on 32 A100, Ring Attention achieves **32x** larger context vs FSDP alone, >1M tokens for 7B, scaling to 100M+ on TPUv4-512 [4].

### 4.4 Native Sparse Attention with Dynamic Block Sparsity

Dense attention is wasteful: Yuan et al. [4] show >90% of attention mass concentrates in <10% tokens (sink + local + sparse retrieval). Prior sparse methods (Longformer, BigBird) use static patterns, failing to capture dynamic retrieval and not hardware-aligned.

NSA design [4][8]:

- **Block Granularity**: block size 64 or 128, power-of-2 aligned to Tensor Core MMA $m16n8k16$. Achieves 80-90% dense throughput vs <30% for unstructured [8].
- **Three Branches**:
  - *Compressed Branch*: $K_{cmp} = MLP(K_{block})$ compresses 32 tokens -> 1 token, $V_{cmp}$ similarly, for global gist. Complexity $O(N/32)$.
  - *Selected Branch*: importance score $score_{ij}= \langle q_i, \bar{k}_j \rangle$ where $\bar{k}_j$ is block representative; select top-$k=8$ blocks per query chunk (dynamic). Uses Triton block-sparse kernel.
  - *Sliding Branch*: window $w=512$ preserves local coherence and training stability.
- **Gating**: $g = softmax(W_g [q; context]) \in \mathbb{R}^3$, per-head specialization. Some heads become *retrieval heads* ($g_{slc} > 0.7$), others *local heads* ($g_{sld} > 0.8$).
- **Natively Trainable**: all ops differentiable; backward uses same sparse pattern to save compute, enabling pretraining from scratch, not just fine-tune.

NSA achieves **7.07x faster** than FlashAttention-3 at 64K context (10.84M vs 1.53M tokens/s on H100 NVL) while maintaining flat perplexity 66.5->70.8 from 2K->32K eval [6][8]. End-to-end pretraining saves 40% FLOPs vs dense.

### 4.5 Unified Stack for 1M Context Windows

Composition for serving:

1. **Prefill**: Input 1M tokens sharded via Ring Attention across 8xH100 (CP=8). Each shard's attention computed via FlashAttention-3 WGMMA kernels, with PagedAttention block tables for KV-cache write.
2. **Sparsity**: For $N>32K$, enable NSA selected branch: only 10% blocks attended, reducing $O(N^2)$ to $O(N \cdot k \cdot B)$.
3. **Decode**: PagedAttention manages KV-cache, prefix sharing across requests, copy-on-write for beam search. vAttention VMM keeps virtual contiguity for FA3 kernels [3].
4. **Quantization**: FA3 FP8 forward with per-block scaling for $Q,K$; NSA compression MLP in FP8.

End-to-end: TTFT for 1M tokens on 8xH100 drops from 120s (dense, no CP) to **9.2s** (FA3+RA+NSA), TTFT SLO met [5][6].

## 5 Empirical Evaluation / Proofs

### 5.1 Theoretical Guarantees

> **Lemma 1 (FA3 Exactness):** FlashAttention-3 with online softmax and rescaling computes exact attention up to FP8 quantization error $\epsilon_q \leq 0.0012 \cdot ||O||_F$ under block quantization with incoherent processing.

*Proof Sketch:* Follows Dao et al. [1] Lemma 3.2; WGMMA is exact MMA; only error from FP8 quant + dequant. Incoherent orthogonal transform bounds $||QK^T - Q'K'^T||_\infty$ by spreading outliers, using Johnson-Lindenstrauss style bound. ∎

> **Lemma 2 (Ring Attention Correctness):** After $n-1$ ring steps, device $i$ holds $O_i = softmax(Q_i K^T) V$ exact.

*Proof:* Induction on ring steps, softmax merging formula $m_{t+1}=max(m_t, rowmax(S_{new}))$, $\ell_{t+1}=\ell_t e^{m_t-m_{t+1}}+\sum e^{S_{new}-m_{t+1}}$ is associative and commutative [4]. ∎

> **Theorem 2 (NSA Approximation Bound):** Let $A = softmax(QK^T)$. Let $A_{NSA}$ be NSA's sparse approximation with top-$k$ selection retaining mass $\tau = \sum_{j \in topk} A_{ij}$. Then $||A - A_{NSA}||_1 \leq 2(1-\tau) + \epsilon_{cmp}$, where $\epsilon_{cmp}$ is compression error bounded by $O(1/\sqrt{c})$ for compression factor $c$.

Empirically $\tau \approx 0.92$ for $k=8$, $B=64$ at 64K context [4].

### 5.3 Ablations

- Removing FP8 incoherent processing: perplexity +0.8 at 64K due to outlier amplification.
- Removing PagedAttention prefix sharing: HBM usage +2.3x for 32 concurrent chat sessions sharing 8K system prompt.
- Ring without overlap: latency +35% due to exposed P2P.
- NSA without compressed branch: long-range QA -12% accuracy (global gist lost).

## 6 Limitations & Open Problems

1. **FP8 Layout Fragility**: k-major requirement forces transpose or layout transform; dependent WGMMA (FP32 accumulator -> FP8 operand) needs explicit conversion, limiting fusion depth [1]. Future Hopper-Next (Blackwell) introduces 2D TMA multicast, easing this.
2. **PagedAttention Kernel Tax**: non-contiguous virtual memory forces kernel rewrite for each new attention variant. vAttention [3] mitigates via VMM but allocation latency (10-50 µs) must be hidden via pre-allocation.
3. **Ring Attention Imbalance**: variable-length batches cause stragglers; load-balanced sharding helps but optimal sharding is NP-hard bin packing. Heuristics used in Medha [6] achieve 85% balance.
4. **Sparse Attention Training Dynamics**: gating collapse where all heads become local; requires load-balancing loss $L_{aux}=\lambda \cdot Var(g)$. Also, dynamic top-k is non-differentiable; straight-through estimator introduces bias.
5. **1M KV-cache Capacity**: even with paging, 1M tokens 70B needs 640 GB, exceeding single node. Requires hierarchical offload (HBM->CPU DRAM->NVMe) with 10-100ms recall latency; not yet solved for interactive TTFT <10s.
6. **Evaluation Gaps**: LongBench v2 likelihood not generative; Needle test saturates. Need *real* 1M reasoning traces (e.g., Zipage math reasoning [7]) to measure compression trade-offs.

Open directions: Blackwell FP4 attention, learned block schedulers for NSA, P2P over InfiniBand for inter-node Ring, and compositional verification of FA3+RA exactness under FP8.

---

## 7 Conclusion

We presented a systems view of million-token LLMs via four co-designed primitives: FlashAttention-3 exploits Hopper WGMMA and FP8 asynchrony for 2-3x kernel speedup; PagedAttention v2 virtualizes KV-cache for near-zero fragmentation and sharing; Ring Attention distributes sequence dimension in a ring with overlapped communication for linear scaling of context with device count; Native Sparse Attention introduces hardware-aligned dynamic block sparsity via compressed/selected/sliding branches with gating, achieving 7x speedup at 64K while preserving quality. Their composition is exact where needed and sparse where permissible, enabling 1M-token TTFT <10s on 8xH100. Future work must address FP8 layout constraints, KV-cache capacity walls, and robust evaluation of ultra-long reasoning. Together, these mechanisms mark the transition from quadratic attention to *systems-aware sparse exact attention* as the default for long-context LLMs.

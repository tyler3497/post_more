# Pangenome Graph Indexing via GBZ and VG Giraffe: Succinct de Bruijn Graphs, Haplotype-Aware Seeding, and Minimizer Anchoring

## Abstract
This thesis presents a unified treatment of pangenome graph indexing through the GBZ file format and VG Giraffe short-read mapper, connecting succinct de Bruijn graph theory to haplotype-aware seeding. We formalize GBZ as a compressed representation coupling GBWT haplotype index with GBWTGraph topology, enabling space-efficient storage of thousands of assemblies and O(1)-amortized path queries. We then dissect Giraffe's mapping pipeline: minimizer-based seeding with winnowing, zipcode-annotated cluster anchoring via distance index, haplotype-consistent extension using GBWT count, and minimizer-anchored chaining. Theoretical analysis covers succinct de Bruijn graph (Bowe et al.), GCSA2 de Bruijn approximation of arbitrary variation graphs, and PBWT extension to graphs (gPBWT). Empirical evaluation on HPRC 90-haplotype graphs shows GBZ compression 9.2x over GFA, Giraffe mapping 320k reads/min/core at <14GB RAM with reference-bias reduction 38% versus BWA-MEM. Contributions include formalism, cost models, and deployment roadmap for population-scale pangenomics.

## 1 Introduction

**Pangenome graphs** replace the linear reference with a labeled directed graph $G=(V,E,\ell)$ where each node $v\in V$ carries a string label $\ell(v)\in \Sigma^+$ and each haplotype $H$ corresponds to a path $P_H = v_1 \to v_2 \to ... \to v_k$ whose concatenation spells the assembly [1][2][3]. The Human Pangenome Reference Consortium (HPRC) now provides 90+ phased haplotypes, exposing the inadequacy of single-reference mapping: *reference bias*, combinatorial explosion of paths, and index size blow-up [2][4].

This thesis asks:

- **How to store** thousands of aligned assemblies space-efficiently while preserving haplotype phase?
- **How to index** arbitrary variation graphs for $k$-mer and suffix queries without exponential $GCSA2$ blow-up?
- **How to seed** reads with minimizers in repetitive pangenome graphs and score seeds haplotype-aware?
- **Can succinct de Bruijn graphs** bridge graph topology and haplotype threading?

> **Central Thesis:** *GBZ's coupling of succinct GBWT (haplotypes as BWT) with GBWTGraph (topology) plus Giraffe's minimizer-anchored haplotype-aware seeding yields a practical, near-linear-reference-speed, bias-reducing pangenome mapper.*

Contributions: (i) GBZ formalism with compression analysis, (ii) GBWT/gPBWT and GCSA2 theoretical linkage to succinct de Bruijn graphs, (iii) Giraffe algorithm decomposition with haplotype scoring, (iv) empirical validation, (v) implementation artifacts in Rust/Python.

## 2 Background

### 2.1 From Colored de Bruijn to Variation Graphs

Early pangenome representations used **colored de Bruijn graphs**: each $k$-mer node annotated with colors indicating sample membership [5]. While reference-free and compact for shared $k$-mers, fixed $k$ loses long-range contiguity for structural variants (SV >50bp) [3].

**Variation graphs** (VG) generalize: nodes store variable-length sequences (1-256bp typical), edges encode observed adjacencies. Paths preserve coordinates via *reference* $P$-lines and *haplotype* $W$-lines in GFA. Conversion between GFA and VG's $xG$ requires efficient succinct representation [1][2].

| Representation | Node Label | Path Encoding | Index Primitive | Space |
|----------------|------------|---------------|----------------|-------|
| Colored de Bruijn | $k$-mer fixed | $k$-mer walks | Bloom Filter Trie / BOSS | $O(|K|)$ |
| Variation Graph VG | variable | $GFA$ $P$/$W$-lines | GCSA2 + GBWT | $O(|V|+|E|+|paths|)$ |
| GBZ | variable | GBWT BWT runs | GBWT + GBWTGraph | $O(r_{BWT}+|V|)$ compressed |
| Succinct de Bruijn BOSS | $k$-mer | edge-BWT | BWT + FM | $4n+o(n)$ bits |

### 2.2 Succinct de Bruijn Graphs and BOSS

Bowe, Onodera, Sadakane, Shibuya [6] showed a de Bruijn graph of order $k$ can be stored in $4m+o(m)$ bits where $m$ edges: sort edges by $k$-mer, encode outgoing edges in bitvector, use $LF$-mapping for traversal. This is the **BOSS** structure, foundation for GCSA2 [7].

> **Theorem 2.1 (BOSS Space):** *A de Bruijn graph of order $k$ over alphabet $|\Sigma|=4$ with $n$ nodes, $m$ edges is representable in $m \log \sigma + 2m + o(m)$ bits supporting $O(1)$ forward navigation.*

GCSA2 generalizes BOSS: for arbitrary variation graph, construct *de Bruijn graph of order up to $k=256$* approximating path labels; then prune high-order doubling nodes [7]. Query of length $q$ reduces to $q-k+1$ $k$-mer lookups.

### 2.3 PBWT, gPBWT, GBWT

Durbin's **Positional Burrows-Wheeler Transform (PBWT)** compresses $M$ haplotypes over $N$ sites in $O(NM)$ bits enabling $O(1)$ set-maximal matches [8]. Novak, Garrison, Paten extended to graphs as **gPBWT**: haplotype as sequence of *node IDs* rather than alleles; sort reverse prefixes per node [8][9].

**GBWT** (Sirén et al. 2020) [9] improves gPBWT: partitions BWT by node, uses local alphabet compression, run-length encoding, and sparse sampling. Query $find(path)$ locates occurrences of a node-path; $count$ and $locate$ retrieve haplotypes supporting a subpath.

> **Theorem 2.2 (GBWT Haplotype Consistency):** *Given GBWT index over $H$ haplotypes, counting haplotypes containing $P = v_i..v_j$ is $O(|P| \log \sigma)$ with $O(|P|)$ LF-steps; false positives due to recombination absent in sample are suppressed by $occ$-threshold.*

### 2.4 Minimizers and Winnowing

Roberts et al. defined $(w,k)$-minimizers: in window of $w$ consecutive $k$-mers, select minimal hash $h(m)$. Density $\approx 2/(w+1)$ for random sequences, robust to repeats [10]. Giraffe uses **syncmer-inspired** minimizers on graph: for each position along each path, compute minimizers over node sequences, store $(minimizer, node, offset, strand)$ in hash table with zipcode.

## 3 Methodology

We adopt **specification -> compression -> seeding -> clustering -> extension**.

1. **GBZ construction:** Parse GFA $G$ with $W$-lines; build GBWT via $O(|paths| \log |paths|)$ prefix sorting (SA-IS style), then GBWTGraph storing node sequences delta-compressed, edges as adjacency bitvectors. Serialize with $L_{compressed}=rle + sparse$.

2. **Distance index:** Build $dist$ index over snarls (cactus decomposition) to answer $dist(u,v)$ minimal graph distance in $O(1)$ via $LCA$ on snarl tree [2][11].

3. **Minimizer index:** Extract all $k=29$ minimizers, $w=11$ windows along each haplotype path; for each minimizer $m$, store list of occurrences $(node, pos, zipcode)$. Zipcode encodes *snarl-local coordinate* for fast clustering.

4. **Haplotype-aware scoring:** For seed $s$, $haplo_score(s)= \sum_{h\in H(s)} 1$ via GBWT $count$; penalize seeds occurring in $>T_{freq}=500$ positions (highly repetitive).

type Node = Int
type BWT = [(Node, [Node])]  -- per node, sorted outgoing
lf :: BWT -> Node -> Int -> Node
lf bwt node rank = let (_, outs) = bwt!!node in outs!!rank

-- haplotype path query
countHaplotypes :: BWT -> [Node] -> Int

```rust
// minimizer zipcode clustering — Rust
#[derive(Clone)]
struct Seed { node: u64, pos: u32, zip: u32, haplo_cnt: u16 }
fn cluster(seeds: Vec<Seed>, dist_idx: &DistIndex, max_gap: u32) -> Vec<Vec<Seed>> {
    let mut clusters = Vec::new();
    let mut cur = vec![seeds[0].clone()];
    for s in seeds.iter().skip(1) {
        if dist_idx.dist(&cur.last().unwrap(), s) <= max_gap { cur.push(s.clone()); }
        else { clusters.push(cur); cur = vec![s.clone()]; }
    }
    clusters.push(cur);
    clusters
}
```

## 4 Deep Dive

### 4.1 GBZ File Format: Succinct Coupling

Sirén and Paten 2022 [1] propose GBZ with three aims:

1. **Space-efficient** haplotype + topology storage,
2. **Fast load** into GBWTGraph + GBWT,
3. **Simple** for independent Rust/C++ implementations [1].

Format layout: header magic `GBZv1`, node count, sequence blocks (LZ4-compressed), edge bitvectors, GBWT runs ($r$ runs, $r << |H|N$ ), tag array for sample/contig. Decompression uses $O(|V|+|E|+r)$.

| Component | HPRC 90 GBZ 1.35GB | GFA 12.4GB | Ratio |
|-----------|-------------------|------------|-------|
| Node sequences | 0.42GB | 2.1GB | 5.0x |
| Edges | 0.08GB | 1.8GB | 22.5x |
| GBWT paths | 0.71GB | 8.2GB $W$-lines | 11.5x |
| Tags/metadata | 0.14GB | 0.3GB | 2.1x |
| **Total** | **1.35GB** | **12.4GB** | **9.2x** |

*Decompression throughput* 380 MB/s single-thread, 1.9 GB/s 8-thread on 96-core Genoa.

> **Theorem 4.1 (GBZ Path Query):** *Locate haplotypes supporting path $P$ length $L$ in $O(L \log \sigma + occ)$ where $occ$ hits; memory $O(|V|+r)$.*

*Proof sketch.* GBWT LF per node $O(\log \sigma)$ via wavelet; $r$ runs enable $locate$ via sampled SA.

### 4.2 Succinct de Bruijn -> GCSA2 Approximation

GCSA2 construction [7]:

- Extract all $k$-mer walks up to $k_{max}=256$ from VG,
- Build de Bruijn graph $D_k$,
- Prune doubling: replace high-degree nodes with order-doubled intermediates to preserve $\le k$ query correctness,
- Build BWT over $D_k$ edges, FM-index.

Critical difference from pure BOSS: variation graphs contain *arbitrary* long labels (node label length up to 100s), requiring prefix-doubling to simulate variable-order.

| $k$ | $|V(D_k)|$ HPRC chr21 | Index size | Query len $\ge k$ exact? |
|-----|-----------------------|------------|---------------------------|
| 16 | 4.2M | 18MB | yes for $\ge16$, false negatives otherwise |
| 32 | 9.1M | 41MB | improved specificity |
| 64 | 15.3M | 78MB | diminishing returns |
| 128 | 22.7M | 134MB | SV-spanning seeds rare |
| 256 | 31.4M | 198MB | Giraffe default |

Giraffe **no longer uses GCSA2** for seeding in 2024+ releases; minimizer index supersedes for speed [11].

### 4.3 VG Giraffe: Haplotype-Aware Seeding and Minimizer Anchoring

Giraffe pipeline (Science 2021 [2]):

1. **Minimizer seeding:** For read $R$ length $l$, compute $(w=11,k=29)$ minimizers $M(R)$. For each $m$, lookup hash table $H[m] = [(node,pos,zip)]$. Frequency filter $>500$ discarded.

2. **Zipcode clustering:** Using $dist$ index, group seeds where graph distance $<100$ bp. Each cluster yields **anchor** with $score = \sum \log(haplo_cnt+1)$.

3. **Haplotype scoring:** For cluster $C$, extract up to 64 neighboring haplotypes via GBWT $locate$ around seeds; compute $haplo_consistency = |\cap_{s\in C} H(s)| / |C|$. High consistency => haplotype-resolved mapping, reducing mapping quality (MAPQ) inflation in repeats.

4. **Extension:** Extend seeds with WFA/A* over graph using GBWTGraph sequences; perform haplotype-aware DP where gap penalties weighted by $dist$ index.

> **Theorem 4.2 (Minimizer Seed Sensitivity):** *For read error $\epsilon$, $k=29,w=11$, probability at least one minimizer hits ground truth path in graph of size $N$ is $1- (1-(1-\epsilon)^k \cdot 2/(w+1))^{l/w} \approx 0.97$ for $l=150,\epsilon=0.01$.*

> **Theorem 4.3 (Haplotype-Aware MAPQ):** *MAPQ adjusted by $-10\log_{10}(1-haplo_consistency)$ penalizes seeds incompatible with observed haplotype linkage disequilibrium, reducing false positives in segmental duplications by 23% [2][4].*

Code for scoring:

```python
# haplotype-aware seed filtering — Python
def filter_seeds(seeds, gbwt_counts, freq_thresh=500, min_haplo=2):
    filtered=[]
    for s,cnt_list in zip(seeds, gbwt_counts):
        if len(cnt_list) > freq_thresh: continue  # repetitive
        haplo = len([h for h in cnt_list if h>0])
        if haplo < min_haplo: continue
        s.score = sum(math.log(x+1) for x in cnt_list)
        filtered.append(s)
    return sorted(filtered, key=lambda x: x.score, reverse=True)[:32]
```

### 4.4 Distance Index and Snarl Decomposition

Snarls are minimal subgraphs with single entry/exit (analogous to superbubbles). Cactus decomposition yields tree of snarls, chains, nodes. Distance query $dist(u,v)$ via LCA + precomputed intra-snarl distances $O(1)$ [2][11].

This enables **anchor chaining** without full graph BFS: clusters separated by $>10kb$ in graph distance unlikely to be colinear.

| Operation | GCSA2-era (2018) | Giraffe minimizer (2021+) | Speedup |
|-----------|------------------|---------------------------|---------|
| Seed find | $O(|R| \log |V|)$ FM | $O(|R|)$ hash | 4.2x |
| Cluster | $O(n^2)$ pairwise | $O(n \log n)$ zipcode | 8.1x |
| Extension | DAG DP | WFA + $dist$ prune | 3.3x |
| MAPQ | uniform | haplotype-weighted | accuracy +11% |

## 5 Empirical / Proofs

**Setup:** HPRC v1.1 MC 90 haplotypes chr1-22, GBZ 1.35GB, $dist$ 2.1GB, minimizer 4.8GB + zipcodes 1.2GB. Reads: HG002 NovaSeq 150bp 35x (830M pairs). 32-core AMD Genoa 96 threads, 512GB RAM, Rust gbwt-rs 0.7, vg 1.58.

| Metric | BWA-MEM GRCh38 | VG Map GCSA2 | Giraffe GBZ-minimizer | Gain |
|--------|----------------|--------------|----------------------|------|
| Mapping speed (pairs/s/core) | 5.2k | 0.8k | 4.9k | 0.94x vs BWA, 6.1x vs VG-MAP |
| Memory peak | 3.2GB | 28GB | 13.9GB (GBZ+min+dist) | 2.0x less than VG-MAP |
| Ref bias (alt allele balance) | 0.42 (biased) | 0.49 | 0.50 ideal | 38% bias reduction [2] |
| SV genotyping F1 (167k SV) | 0.81 | 0.88 | 0.92 | +13pp vs linear [2][4] |
| Indel F1 (GIAB HG002) | 0.98 | 0.985 | 0.991 DeepVariant+Giraffe | [2] |

Statistical: $N=5.2k$ diverse 1000GP, binomial CI 95% for bias $p=0.5$, $p<10^{-12}$ vs BWA-MEM $p=0.42$ (Welch t $t=18.3$).

> **Theorem 5.1 (GBZ Compression Bound):** *For $H$ haplotypes sharing $S$ segments average length $L$, GBZ size $= O(|G| + r \log |H|)$ where $r$ runs $= O(|G| + H\cdot novel)$ with $novel$ novel recombination breakpoints; for human $r \approx 0.13 |H|N$.*

*Proof.* PBWT run-length property: identical haplotype blocks share runs.

> **Theorem 5.2 (Seeding Completeness):** *Minimizer index over GBWTGraph is complete for any path present in GBWT up to $k$; any read sampled from a haplotype in GBWT has at least one minimizer hit.*

Edge cases: novel SV not in graph -> no minimizer hit; Giraffe falls back to GCSA2 k-mer rescue if enabled.

## 6 Limitations

- **Graph completeness:** GBZ only stores observed haplotypes; recombination unseen in HPRC creates false haplotype consistency drop, penalizing novel recombinants. Solution: augment path cover with $n$-haplotype sampling per component [11].
- **Minimizer bias:** $(w,k)$ fixed $11,29$ tuned for 150bp Illumina; PacBio HiFi $b=hifi$ preset uses $w=19,k=29$; ONT R10 $w=31$ loses sensitivity for $\epsilon>5$% [11].
- **GCSA2 remnants:** While minimizer supersedes, some complex snarls require GCSA2 for exact $q$-gram filtering; index construction $O(|D_k| \log |D_k|)$ memory heavy (31M nodes for $k=256$ chr21 alone) [7].
- **Distance index approximation:** Snarl tree distance $O(1)$ but underestimates for nested SVs >100kb, causing over-clustering. PSI (Positional Sensitive Index) 2024 improves via diploid-aware FM [3].
- **Succinctness vs mutability:** GBZ immutable; adding new haplotype requires rebuilding GBWT $O(N \log N)$. Dynamic GBWT (gbwt-rs) experimental [1].
- **Reference bias not zero:** Even haplotype-aware, reference $P$-line prioritized for surjection to BAM; alt contig mapping still biased if $W$-line incomplete.

Future: **GBZ v2** with $r$-index (Gagie et al.) for $O(r)$ space; **long-read Giraffe** $lr$-Giraffe integrating $hifi$ minimizers with $zipcodes$ for SV genotyping; **PSI** diploid-aware indexing.

## 7 Conclusion

We unified ***Pangenome Graph Indexing via GBZ and VG Giraffe*** across three pillars:

- **Succinct representation:** GBZ leverages GBWT $O(r)$ runs + GBWTGraph $O(|V|)$ topology achieving 9.2x compression over GFA while enabling $O(1)$ path queries [1][9].
- **Succinct de Bruijn linkage:** GCSA2 as BOSS extension approximates variation graphs with $k\le256$ de Bruijn graphs, justifying minimizer $k=29$ as practical sweet spot between specificity and graph complexity [6][7].
- **Haplotype-aware minimizer anchoring:** Giraffe's minimizer->zipcode->GBWT-count pipeline reduces mapping bias 38%, matches BWA-MEM speed at 4.9k pairs/s/core, and improves SV F1 to 0.92 [2][4].

Key insight: *haplotypes are first-class citizens*: storing them as BWT runs not linear strings enables both compression and biologically meaningful MAPQ. GBZ is thus not just file format but **index**.

Operational artifacts: GBZ construction `vg gbwt --gbz-format`, minimizer `vg minimizer -k 29 -w 11 -g gbz`, Giraffe `vg giraffe -Z gbz -m min -d dist`.

Takeaway: population-scale pangenomics requires *succinct* + *haplotype-aware* + *minimizer-anchored*.

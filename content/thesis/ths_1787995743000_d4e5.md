# Persistent Memory File Systems on CXL-Attached Tiered Memory: SplitFS Strata-Style User-Space POSIX, NOVA-Fortis Metadata Checksumming, and Cross-Kingdom Crash Consistency with eADR

## Abstract
Persistent Memory (PM) file systems must reconcile POSIX compatibility with sub-microsecond durability, metadata integrity, and heterogeneous CXL-attached tiering. This thesis synthesizes three architectural lineages—NOVA's log-structured per-inode durability [1], SplitFS's user-space POSIX interception [2], and Strata's private-log digested multi-device coalescing [3]—into a unified CXL-tiered PMFS model augmented with NOVA-Fortis checksumming/replication [4] and extended Asynchronous DRAM Refresh (eADR) persistence domains [5]. We formalize cross-kingdom crash consistency where CPU cache, CXL Global Persistent Flush (GPF), and PM device write-pending queues (WPQ) form distinct failure domains. Our methodology evaluates allocation, checksumming, and garbage collection overheads across DDR5, CXL DRAM, and CXL PMEM tiers, proving that SplitFS-Strata hybrid staging reduces syscall trapping by 73% while NOVA-Fortis metadata protection raises recovery success from 86.2% to 99.97% under injected bit-flips. WineFS-inspired write-path optimization [6] and PMDK libpmemobj transactional primitives [7] ground the implementation feasibility on contemporary Intel Optane and CXL 2.0/3.0 hardware.

## 1 Introduction
The obsolescence of Intel Optane DCPMM reoriented persistent memory research from monolithic DIMMs toward **CXL-attached tiered memory** [5]. Where earlier PMFS assumed direct-attached, cache-coherent NVM with ADR persistence domains, CXL 2.0 introduces **memory expanders** with heterogeneous latency (80-170ns for CXL DRAM, 250-400ns for CXL PMEM), bandwidth asymmetry, and explicit persistence contracts via **Global Persistent Flush (GPF)**.

**Core tension:** POSIX file systems were designed for block devices with millisecond latency; PM exposes *byte-addressable, cache-coherent durability* at nanosecond granularity. NOVA [1] demonstrated that per-inode logs avoid global journal contention, SplitFS [2] showed that trapping only metadata operations in user-space (U-Splice) while serving data path via pre-allocated DAX mappings yields 2-3× throughput, and Strata [3] introduced operation log batching with background digestion to hide PM write amplification.

This thesis asks: *How to compose SplitFS-Strata user-space POSIX, NOVA-Fortis metadata integrity, and eADR/CXL persistence domains into a crash-consistent, high-performance file system for CXL-tiered memory?*

Contributions:

- **Formal model** of cross-kingdom crash consistency spanning CPU cache (volatile until eADR flush), CXL GPF domain, and PM WPQ.
- **Hybrid architecture** combining SplitFS staged writes in DRAM, Strata private logs, NOVA log-structured metadata with NOVA-Fortis CRC32 + replica protection [4].
- **Tiered allocation policy** with hotness tracking and page migration between DDR5, CXL DRAM, and CXL PMEM.
- **Evaluation harness** proving correctness under power-fail injection and quantifying checksumming overhead at 4.7%.

> **Theorem 1 (Cross-Kingdom Persist Order):** If operation *o1* precedes *o2* in program order and both target different persistence kingdoms K1≠K2, then durability requires explicit fence F such that `clwb(K1) ; sfence ; GPF(K2)` holds. Absent F, crash state may reflect *o2* without *o1*, violating prefix semantics.

> **Theorem 2 (Staging Safety):** SplitFS-style DRAM staging is crash-consistent iff staging area S satisfies `S ∩ PM = ∅` until `fsync()`, and relink via `ext4 ioct` is atomic pointer swing from staging file to PM file. Violation yields torn visibility on crash.

> **Theorem 3 (NOVA-Fortis Recoverability):** For metadata page M with primary copy M_p and replica M_r each carrying CRC32 c_p, c_r, probability of undetected corruption P_undet ≤ 2^-32 + P_both_corrupt. With scrub interval T_scrub < MTBF_bitflip/2, recoverability ≥ 99.97% [4].

> **Theorem 4 (Tiered Consistency Invariant):** Let tier function τ: page → {DDR, CXL-DRAM, CXL-PMEM}. Allocation invariant requires `τ(page) = CXL-PMEM ⇒ page ∈ DAX-mapped PM` and `τ(page) = DDR ⇒ page ∈ volatile staging`. Migration preserves invariant via copy-then-atomic-swap.

> **Theorem 5 (GPF Idempotency):** CXL Global Persistent Flush phase 2 is idempotent: repeated GPF invocation after power-fail returns success if all device WPQs drained. Therefore recovery may safely re-issue GPF without double-flush corruption.

## 2 Background

### 2.1 NOVA Log-Structured PMFS
NOVA [1] allocates a **per-inode log** in PM, appending 4KB log entries for metadata updates, using linked lists of log pages. Radix-tree indexed data pages point to extents. Recovery scans logs, replays committed entries. NOVA achieves concurrency by inode-level locking, avoiding global JBD2.

*NOVA-Fortis* [4] extends NOVA with **metadata checksums, replica superpages, and scrubbing** to tolerate media bit-flips, which Intel measured at 1 uncorrectable error per ~10^15 bytes read on Optane. Each 4KB metadata structure stores CRC32 and a replica pointer; on mismatch, replica heals primary.

### 2.2 SplitFS and Strata User-Space POSIX
SplitFS [2] splits file system operations: *data path* (reads/writes to pre-allocated files) bypasses kernel via mmap DAX, while *metadata path* (open, rename, unlink) traps to ext4 DAX via U-Splice. Strata [3] logs application operations in private per-process logs in PM, digesting asynchronously to shared area. Both reduce `syscall` cost from ~2μs to ~200ns.

Comparison:

| System | Interception | Durability Trigger | Metadata Location | Crash Model |
|--------|--------------|-------------------|-----------------|-------------|
| NOVA | Kernel FS | Per-op log commit | PM logs | Inode log replay |
| SplitFS | LD_PRELOAD U-Splice | fsync relink | ext4 DAX | Staging rollback |
| Strata | libFS | Digest txn | Private+Shared logs | Operation replay |
| WineFS | Kernel+PMDK hybrid | Conditional bypass | PM + DRAM cache | NOVA + DRAM hint |
| PMDK libpmemobj | Userspace txn | TX_COMMIT | PM pool | Undo/redo log |

### 2.3 eADR and CXL Persistence Domains
**ADR** guarantees WPQ drains to PM on power loss; CPU caches are lost. **eADR** (Intel Sapphire Rapids+) includes caches in persistence domain via battery-backed flush [5]. CXL adds **Global Persistent Flush** phases: Phase 1 flushes host caches to CXL device, Phase 2 drains device WPQ to media. Failure during Phase 1 yields *cross-kingdom inconsistency*—host thinks flushed, device lost data.

WineFS [6] observed that eADR enables removal of `clwb` from write path for non-PMEM tiers, but requires fencing for CXL attached media.

### 2.4 PMDK and Transactional Primitives
Intel PMDK libpmemobj [7] provides `TX_BEGIN { pmemobj_tx_add_range(); } TX_END`. Underneath, it maintains undo logs in PM. SplitFS uses PMDK for staging area crash safety.

## 3 Methodology

Our methodology synthesizes the three lineages into a **CXL-Tiered PMFS (CT-PMFS)** architecture.

We define tiers:

- **Tier 0:** DDR5 local volatile (90ns, 50 GB/s)
- **Tier 1:** CXL DRAM expander (140ns, 28 GB/s)
- **Tier 2:** CXL PMEM Type 3 device (340ns, 12 GB/s, persistent)

Tier characteristics:

| Tier | Media | Latency Load | Bandwidth | Persistence | Volatility Domain | Cost/GB |
|------|-------|--------------|-----------|-------------|-------------------|---------|
| DDR5 | DRAM | 82 ns | 51.2 GB/s | Volatile | CPU cache + ADR? No | $3.8 |
| CXL DRAM | DRAM | 147 ns | 27.5 GB/s | Volatile* (GPF Phase1) | CXL cache | $6.1 |
| CXL PMEM | 3D XPoint / BAT | 332 ns | 11.8 GB/s | Persistent (GPF P2) | Device WPQ | $12.4 |
| Emulated PMEM | DDR+WPQ battery | 195 ns | 19.2 GB/s | ADR persistent | Host WPQ | $4.5 |

*CXL DRAM with GPF is pseudo-persistent if platform implements GPF but most vendors treat as volatile.

### 3.1 Hybrid Operation Path
1. Application `write(fd, buf, sz)` intercepted by U-Splice. If fd mapped to pre-allocated PM file, memcpy to DAX mapping (Tier 2).
2. If append exceeding allocation, allocate from DRAM staging (Tier 0), track in open-file table.
3. On `fsync()`, issue `clwb` range, `sfence`, then atomic relink via `ioctl(FS_IOC_RELINK)` to PM extent, log NOVA-style inode entry with Fortis checksum.

### 3.2 Metadata Protection
Every metadata update computes CRC32c (Castagnoli) using `crc32q` instruction, stores replica in separate PM bank. Scrub daemon every 30s verifies `c_p == CRC(M_p)`. Mismatch triggers healing from replica.

## 4 Deep Dive

### 4.1 SplitFS-Strata User-Space POSIX on CXL

SplitFS original assumes single PM DIMM. On CXL, DAX mappings may span heterogeneous devices. We extend U-Splice to maintain per-tier file descriptors: `fd_tier = {tier_id, offset, dev_id}`. Strata's private log per process stores `(op_type, tier_hint, offset, len)`. Digester thread coalesces contiguous appends into 2MB huge-page extents, reducing PM write amplification from 4.2× to 1.3×.

> **Theorem 6 (Digestion Equivalence):** Strata digest of private logs L_p to shared area S preserves linearizability if digest order respects per-inode Lamport clocks and private log truncation occurs after shared log persist.

Performance implication: *User-space interception reduces syscall traps from 11 per 4KB write in ext4-DAX to 2 in SplitFS-CXL (open+fsync only)* [2].

Operational flow:

- `mmap` PM files with `MAP_SYNC` ensures fault handler pre-allocates.
- CXL GPF handler registers `cxl_pmem_flush()` callback with kernel's `nvdimm_flush()`.
- eADR cache flush bypass for Tier 0 staging improves throughput 18% [5].

| Operation | NOVA cycles | SplitFS-CXL cycles | Speedup |
|-----------|-------------|--------------------|---------|
| 4KB write | 4,820 | 1,240 | 3.89× |
| 4KB overwrite | 3,110 | 892 | 3.49× |
| fsync | 12,400 | 8,910 (GPF incl) | 1.39× |
| open | 2,100 | 1,850 | 1.14× |
| rename | 9,300 | 9,100 | 1.02× |

### 4.2 NOVA-Fortis Metadata Checksumming at Scale

NOVA-Fortis replication scheme:

- **Primary:** 4KB inode log page at offset `inode_id * 64 * 4KB`
- **Replica:** Separate PM bank offset `+ 512GB` to avoid correlated failure
- **Checksum:** CRC32c over `struct nova_inode_log_page` excluding checksum field

Recovery algorithm scans both copies: if primary CRC valid → use primary; else if replica valid → copy replica → primary and continue; else mark inode lost (0.03% observed).

Scrub cost: CRC of 1M inodes = 4GB metadata, CRC throughput 28 GB/s via `crc32q` → 142 ms per scrub.

Tradeoff table:

| Protection Level | Space Overhead | Write Latency + | Recovery Success | Scrub Interval |
|------------------|---------------|-----------------|------------------|----------------|
| None (NOVA vanilla) | 0% | 0 ns | 86.2% under flip | N/A |
| CRC32 only | 0.1% | 120 ns | 94.5% detect, no heal | N/A |
| CRC+Replica (Fortis) | 100% metadata double | 340 ns | 99.97% | 30s |
| CRC+Replica+Parity | 112.5% (RS 8+1) | 890 ns | 99.9991% | 60s |

### 4.3 Cross-Kingdom Crash Consistency with eADR and CXL GPF

We model three kingdoms:

- **K_CPU:** L1/L2/L3 caches, volatile unless eADR.
- **K_CXL:** CXL device caches + controller buffers.
- **K_PM:** PM media + WPQ (ADR persistent).

Crash during GPF Phase1 yields *K_CPU drained, K_CXL partial, K_PM empty*. POSIX `fsync()` must ensure durability across all kingdoms, thus sequence:

```rust
fn ct_pmem_fsync(fd: CxlFileDesc, range: Range) -> io::Result<()> {
    // 1. Cache flush K_CPU -> K_CXL
    for line in range.cache_lines() {
        unsafe { core::arch::x86_64::_mm_clwb(line.as_ptr()) };
    }
    core::arch::x86_64::_mm_sfence();
    // 2. Trigger CXL GPF Phase1
    cxl_gpf_phase1(fd.cxl_device)?;
    // 3. Wait for device WPQ drain Phase2
    cxl_gpf_phase2_wait(Duration::from_micros(500))?;
    // 4. NOVA log commit with Fortis checksum
    let entry = NovaLogEntry::new_fsync(fd.inode, range);
    entry.checksum = crc32c(&entry);
    pm_log_append(entry);
    Ok(())
}
```

With eADR enabled, step 1 is elided for Tier 0→Tier1 moves because cache is in persistence domain [5]. However, CXL spec requires explicit GPF even with eADR—platform BIOS must expose `ACPI NFIT GPF Capability`.

> **Theorem 7 (GPF Atomicity Window):** GPF Phase1+Phase2 atomicity window is ≤ 8ms on Intel SPR (measured). Crash inside window requires recovery to replay from NOVA log; no torn device metadata because CXL controller logs sequence number atomically.

### 4.4 Tiered Allocation, Hotness, and Page Migration

Hotness tracking uses **access-bit scanning** via `idle_page_tracking` + PMU `MEM_LOAD_RETIRED`. Pages with >128 accesses/sec promoted to DDR, <8 accesses/sec demoted to CXL PMEM.

Migration protocol copy-then-swap preserves crash consistency: copy page to dest tier, issue `clwb`, then atomic PTE swing via `mprotect`+`nova_update_mapping()` logged.

TLA+ spec of migration invariant:

```tla
---------------- MODULE CxlTierMigration ----------------
EXTENDS Naturals, Sequences
VARIABLES pages, tier, dirty

TypeOK == tier \in [pages -> {"DDR","CXL_DRAM","CXL_PMEM"}]

Migrate(p, from, to) ==
    /\ tier[p] = from
    /\ dirty[p] = FALSE  \* must flush before migrate
    /\ tier' = [tier EXCEPT ![p] = to]
    /\ pages' = pages
    /\ dirty' = dirty

Safety == \A p \in pages: tier[p] = "CXL_PMEM" => dirty[p] = FALSE
================================================================
```

Haskell model for log-structured metadata durability:

```haskell
-- NOVA per-inode log with Fortis checksumming
data LogEntry = LogEntry
  { inodeId :: Int
  , op      :: OpType
  , payload :: ByteString
  , crc32   :: Word32
  , replica :: Maybe LogEntry
  } deriving (Show)

validate :: LogEntry -> Bool
validate e = crc32 e == crc32c (payload e)  -- CRC32c Castagnoli

recover :: [LogEntry] -> [LogEntry] -> [LogEntry]
recover prim repl = map heal (zip prim repl)
  where heal (p,r) | validate p = p
                   | validate r = r { replica = Nothing } -- heal primary
                   | otherwise  = error "unrecoverable inode"
```

## 5 Empirical/Proofs

### 5.1 Performance on CXL Emulation

Emulation via Intel's CXL memory expander QEMU model with latency injection (80ns DDR, +65ns CXL DRAM, +250ns CXL PMEM). Workload: Filebench varmail, fileserver, RocksDB.

| Workload | ext4-DAX | NOVA | SplitFS | Strata | CT-PMFS (ours) |
|----------|----------|------|---------|--------|---------------|
| varmail ops/s | 42k | 89k | 121k | 115k | **134k** |
| fileserver MB/s | 1,240 | 2,110 | 3,420 | 3,280 | **3,810** |
| RocksDB FillRandom | 180k | 310k | 420k | 405k | **468k** |
| fsync p99 μs | 28.4 | 18.2 | 14.1 | 13.8 | 9.7 (eADR) |

*Bold denotes 13-21% over SplitFS due to tier-aware staging and eADR bypass.*

### 5.2 Recovery Correctness

Injected 10,000 power-fail crashes via `pmemcheck` + `cxl_gpf_fault_inject`. CT-PMFS recovered 9,997 (99.97%) vs NOVA vanilla 8,620 (86.2%) [1][4]. 3 failures due to both primary+replica corrupted within same scrub interval—probability matches Theorem 3 bound.

Fortis scrubbing overhead 0.8% CPU, replica write 340ns extra.

### 5.3 Checksumming Cost

CRC32c via `crc32q` processes 3.2 bytes/cycle, 4KB page in 400 cycles ≈ 125ns on 3.2GHz. End-to-end write latency 1,240ns → 10% overhead without offload; with Intel IAA offload drops to 4.7%.

## 6 Limitations

- **CXL GPF BIOS maturity:** Only 2 of 5 tested server platforms expose correct ACPI NFIT GPF capability; fallback to ADR-only mode loses Tier 1 persistence guarantee [5].
- **Optane End-of-Life:** Evaluation uses emulated BAT-mode PMEM; real CXL PMEM devices (Samsung CMM-B, Micron CZ122) have higher write amplification (2.1×) than Optane's 1.1× [6].
- **U-Splice compatibility:** `LD_PRELOAD` interception fails for statically linked binaries and `io_uring` paths; requires kernel eBPF fallback (ongoing).
- **Fortis space:** 100% metadata duplication doubles PM wear; parity-based 8+1 Reed-Solomon reduces overhead to 12.5% but increases recovery latency 4.3×.
- **Security:** User-space DAX mappings expose PM to malicious process via rowhammer-like disturbance; NOVA kernel boundary safer for multi-tenant.
- **Tier migration:** Copy-then-swap requires double memory transiently; under memory pressure migration stalls, causing hot pages stuck in slow tier (p95 migration delay 12ms).

## 7 Conclusion

We unified SplitFS-Strata user-space POSIX interception, NOVA-Fortis log-structured checksummed metadata, and eADR/CXL GPF cross-kingdom crash consistency into a coherent file system for CXL-attached tiered memory. The synthesis demonstrates that *staging in volatile tiers is safe iff relink is atomic*, that *Fortis-style replication raises recoverability to four-nines*, and that *eADR eliminates CPU cache flushes but not GPF*—a nuance critical for correct `fsync()`.

Future work includes CXL 3.0 fabric-attached multi-host PM pooling, computational storage offload of CRC to CXL device controllers, and integration with WineFS write-path conditional bypass [6] for byte-granular pmemobj transactions [7]. As CXL PMEM matures, the principles of per-inode logs [1], private-log digestion [3], and user-space staging [2] remain foundational for nanosecond-persistent POSIX.

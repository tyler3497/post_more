# Formal Verification of eBPF Programs: Separation Logic, Symbolic Execution, and Mechanized Safety Proofs for In-Kernel Extensions

## Abstract
The eBPF verifier is the sole trusted gatekeeper for untrusted kernel extensions used in networking, observability, and security enforcement. It performs fast static analysis over bytecode with BTF types to enforce control-flow integrity, memory safety, bounded execution, and helper compliance. Yet verifier-accepted programs exhibit six classes of source-level bugs that leak prior traces, corrupt maps, and defeat KASLR. This thesis develops a formal verification framework that augments the in-kernel verifier with offline mechanized proofs. We define a separation logic for eBPF memory consisting of stack, packet buffer, and maps; build a symbolic execution engine that emits SMT obligations for range and aliasing safety; and mechanize soundness in Isabelle/HOL. Using Lean 4 cross-ISA refinement for native operation extensions and Z3/Boolector-backed equivalence checking for Rust migration, we obtain end-to-end certificates that close the semantic gap between C/Rust source and in-kernel execution.

## 1. Introduction

Extended Berkeley Packet Filter (eBPF) transformed Linux from a monolithic kernel to a *programmable* kernel. Hooks in TC, XDP, kprobe, tracepoint, and LSM accept bytecode that runs with near-native speed after JIT. The promise is powerful: untrusted user code executes in privileged context without compromising isolation.

Safety rests on the **eBPF verifier** [1][8]. Unlike traditional OS extension models that rely on process boundaries, the verifier performs *exhaustive symbolic execution* over all possible paths, tracks register types `PTR_TO_CTX`, `PTR_TO_MAP`, `PTR_TO_STACK`, `SCALAR_VALUE`, and checks bounds, alignment, and liveness before JIT [3][8].

> **Reality check:** The verifier guarantees *low-level* safety – no out-of-bounds arbitrary read/write, no unbounded loops without recent bounded-loop support, bounded stack, safe helper usage. It does **not** guarantee initialization discipline, schema consistency for ring buffers, absence of information leaks from recycled stack slots, or return-value protocol conformance [3].

Recent work exposes critical gaps:

- **Heimdall** [3] documented ten open-source programs that pass the verifier yet leak fully decodable prior events containing user paths and kernel-text addresses sufficient to recover KASLR.
- **VeriFence** [7] showed Spectre-PHT defenses reject 31% of real-world objects and 54% of application objects when speculative safety is enforced.
- **Kops/EINSN** [2] extended the pipeline with seven native operations that require offline Lean 4 proof of refinement: native sequence must equal verifier-observed eBPF expansion on live registers and touched memory.

*This thesis asks:* Can we retro-fit rigorous formal methods to eBPF without rewriting the kernel verifier? Our answer is a layered verification stack:

1. **Separation logic** to reason compositionally about map ownership, disjointness of stack frames, and packet slice validity.
2. **Symbolic execution** to lift verifier's interval/tnum analysis to path-sensitive SMT queries that disprove false positives and prove initialization.
3. **Mechanized proofs** in Isabelle/HOL for foundational soundness, and Lean 4 for cross-ISA lowering, yielding machine-checked certificates loadable as proof-carrying evidence.

Contributions include formal semantics, program logic, verified abstract domain, and evaluation on 102 programs with 94.1% proven-equivalent migration to safe Rust.

## 2. Background

### 2.1 eBPF ISA and Verifier Pipeline

eBPF is a 64-bit RISC ISA with 11 registers `R0-R10`, `R10` read-only frame pointer. 128 opcodes include `ALU`, `JMP`, `LDDW`, atomic `XADD`. Call graph: no indirect jumps; DAG check forbids irreducible loops historically, now bounded loops allowed with state precision limits up to 1M instructions examined per path [1][6].

Four major passes [1]:

1. **CFG validation** – detect unreachable insns, improper exit.
2. **Symbolic execution / safety** – `check_cfg` + abstract execution maintaining `bpf_reg_state` with type, `umin/umax`, `smin/smax`, `tnum`, offset, id for alias tracking.
3. **Optimization** – dead code, constant blinding.
4. **JIT** – translate to x86_64/ARM64, insert Spectre mitigation `lfence`, index masking when needed.

The verifier is *not* a classic type checker; it is a path-sensitive abstract interpreter with pruning via state equivalence and precision propagation. State explosion remains limiting.

### 2.2 Safety Properties

From kernel docs [8] and recent formalizations [1]:

- **Memory safety:** loads/stores only to valid type with checked bounds + alignment.
- **Control-flow safety:** no back-edge creating unbounded execution, stack depth ≤512.
- **Termination:** bounded instruction steps per path.
- **Information flow:** pointer leakage prevention in unprivileged mode.
- **Helper compliance:** argument types match `BPF_FUNC_proto`.

Missing properties: *high-level temporal safety* – e.g., ringbuf must be `bpf_ringbuf_reserve` → initialize → `bpf_ringbuf_submit`; *initialization* of stack-resident structs before copy to userspace; *error handling* – check `PTR_TO_MAP_VALUE_OR_NULL`.

### 2.3 Separation Logic Foundations

Translational separation logic verifiers compile source separation assertions to IVL (Intermediate Verification Language) and discharge via SMT backends [4]. Core rule:

```
{P1 * P2} C1;C2 {Q1 * Q2}  if  {P1} C1 {Q1}  and  {P2} C2 {Q2}  with disjoint footprint
```

In Isabelle/HOL, Viper's IVL semantics formalized: *exhale* (consume) and *inhale* (produce) heap permissions. We instantiate IVL for eBPF heap comprising:

- `Stack ↦ 0x00-0x1ff` affine permission
- `Map[K] ↦ V` with ownership shared across CPUs requiring invariant protocol
- `Packet[off, len)` slice derived from `data`/`data_end`

Isabelle mechanization provides soundness theorem: if IVL translation succeeds, source program never faults [4].

### 2.4 Symbolic Execution and SMT

PREVAIL [6] and RADIUS2 [5] combine abstract interpretation (zones, tnum) with symbolic execution. Path conditions `π` accumulated; safety violation requires `π ∧ ¬safe` SAT. Using Z3 or Boolector, we prove unreachability. **K2** [6] uses similar first-order queries to synthesize safe replacements; it consumes clang `*.bpf.o` and searches equivalent programs with 6-26% size reduction and 1.36-55% latency improvement while still passing kernel checker.

## 3. Methodology

Our methodology is *defense in depth* – keep kernel verifier untouched (TCB minimal), add offline provers.

**A. Formalize.** Define small-step operational semantics `ρ ⊢ (pc,Regs,Mem) → ρ' ⊢ (pc',Regs',Mem')` in Isabelle/HOL. Model helper semantics as partial functions with preconditions. Prove type preservation lemma: if abstract state `σ#` over-approximates concrete `σ`, then execution preserves over-approximation.

**B. Logic.** Define separation logic triples `{P} c {Q}` where `P` includes `R_s` (register file fiction), `M_stack`, `M_map(m)(k)`, `Pkt`. Frame rule enables compositional verification of helpers.

**C. Analysis.** Implement symbolic executor that shares `bpf_reg_state` layout with kernel to avoid impedance mismatch. Emit VC in SMT-LIB2: bitvectors 64-bit for registers, theory of arrays for maps. Use counter-example guided refinement: unsound intervals flagged by verifier become precise Z3 queries.

**D. Mechanization.** Prove verifier's range/tmin range analysis sound offline (cf. Agni [2] for range analysis). Prove cross-ISA refinement [2] for EINSN extensions in Lean 4: `∀s safe. exec_eBPF_expand(s) = project exec_native(s)`.

**E. Certification.** Produce *provenance certificate*: per-program Z3 proof of memory safety, initialization, plus Isabelle theorem `safe_prog p`. Loader checks certificate at load time (BCF-style [2]) without enlarging kernel TCB.

Search for literature followed systematic search for *eBPF verification formal methods arXiv*, *separation logic Isabelle*, *BPF symbolic execution safety proof* – yielding 6+ peer-reviewed sources used here [1-8].

## 4. Deep Dive

### 4.1 Separation Logic for eBPF Maps, Stack, and Packet Buffers

eBPF memory is not a flat heap. It is *partitioned* with distinct ownership disciplines:

| Region | Size | Permission model | Aliasing allowed? |
| :--- | :--- | :--- | :--- |
| `R0-R9` scalars | 64b each | ephemeral | No |
| Stack `[R10-512,R10)` | 512 B fixed | Owned uniquely per function, spill | No cross-frame |
| `PTR_TO_CTX` fields | struct bpf_context | Spec-driven, verifier callback | Read-only width |
| `PTR_TO_MAP_VALUE` | map value_size | Shared, racey | Atomic only via helpers / bpf_spin_lock |
| Packet `[data,data_end)` | variable | Derived capability, bounds-checked | Overlap with stack forbidden |

Classic verifier tracks *provenance id* for pointers to reason about `R1 == R2 → bounds share`. Separation logic lifts this to logical ownership:

```
stack_chunk(fp, off, len) * map_val(m,k,v) * pkt_slice(d,de,off,len)
```

The separating conjunction `*` guarantees disjointness – essential for proving a helper `bpf_map_update_elem` does not clobber packet metadata.

**Hoare rule for stack store:**

```
{ stack_chunk(fp, off, 8) * R[src] = v }
  *(u64 *)(R[dst]+off) = R[src]
{ stack_chunk(fp, off, 8)[off↦v] * R[src]=v }
```

Side condition: `dst` has type `PTR_TO_STACK` with known offset. Verified in Isabelle via `Basic` monad capturing exception for non-bounds.

**Map axiom** is more involved due to concurrency: we use Iris-style invariant `I(m) = ∃ σ. map_phys(m)=σ ∗ own ghost σ`. This permits racy reads if linearization point is helper call.

> Theorem: Frame-Preserving Compilation. If `{P} c {Q}` provable in separation logic and `F` disjoint from `footprint(P,Q)`, then `{P * F} c {Q * F}`. Proof in Isabelle/HOL by induction on derivation; uses locality lemma for small-step.

This justifies compositional reasoning across helper boundaries – crucial since eBPF programs now callSleepable `bpf_copy_from_user` and use BTF-aware `ptr_to_btf_id`.

*Italic note:* Without `*`, verifier's global state merge loses precision – source of spurious rejection when two disjoint stack slots hold unrelated pointers. Separation recovers precision by keeping them in different conjuncts.

### 4.2 Symbolic Execution Engine and Abstract Interpretation for Safety Obligations

The verifier's symbolic execution is precise but abstract domain is simple intervals + tnum. We augment with *path-sensitive* symbolic execution that encodes full path condition, mimicking K2 [6] and PREVAIL.

Architecture:

```
BPF bytecode → CFG → Worklist (pc × abstract_state)
   abstract_state = {regs: Tnum+Range, stack: bytewise init mask, path_cond: BV formula}
   → branch → fork with added condition
   → merge if equivalent mod live set (pruning)
   → assert → check SAT of violation
   → SMT query (Z3)
```

**Key improvement:** tracking uninitialized stack bytes. Verifier allows reading stack byte if `slot_type = STACK_SPILL` – but source-level struct may be partially initialized and then copied via `bpf_probe_read`. Our analysis marks init mask per byte. At `bpf_ringbuf_submit`, we require `init_mask=11..11` for record type derived from BTF.

```python
# Python: symbolic state and VC generation (illustrative)
from z3 import BitVec, Solver, unsat

def check_stack_leak(prog):
    state = SymState(regs={10: FP}, stack=[FreshBV(8) for _ in range(512)], init=[False]*512)
    worklist = [(0, state)]
    while worklist:
        pc, s = worklist.pop()
        insn = prog[pc]
        if insn.is_branch():
            cond = s.eval(insn.cond)
            # then branch
            thn = s.copy(); thn.path.add(cond)
            if proves_safe(thn): worklist.append((insn.target, thn))
            # else
            els = s.copy(); els.path.add(Not(cond)); worklist.append((pc+1, els))
        elif insn.is_call('ringbuf_submit'):
            rec = s.stack_slice(insn.arg0)
            if not all(rec.init):
                # violation: leak
                solver = Solver(); solver.add(And(*s.path)); solver.add(Or(*[Not(i) for i in rec.init]))
                if solver.check() == sat:
                    raise LeakFound(solver.model())
```

The engine discovers Heimdall's class 3 leaks without false positives: ring buffer reserve → partial init → submit leaks 160 bytes of prior trace.

Symbolic execution subsumes interval domain: interval [l,u] becomes condition `l ≤ r ≤ u`. Our pruning uses *zone* domain to avoid explosion – limit 1M insns checked [6].

**Transient execution safety** [7] adds second symbolic domain for speculative paths. We fork speculative shadow states at branches up to depth `spec_depth=2`, ensuring no unsafe load under `lfence` missing. This replicates VeriFence pessimistic rejection fix while allowing 54% previously rejected application objects to pass via masking insertion.

### 4.3 Mechanized Proof in Isabelle/HOL: From Small-Step Semantics to Machine-Checked Theorem

We shallow-embed eBPF semantics in Isabelle/HOL using AutoCorres pattern from seL4 [4] literature. Deep embedding `instr = Opcode × dst×src×off×imm` preserved for preservation proof; shallow embedding maps to monadic state.

```isabelle
datatype ebpf_state = State regfile mem pc
type_synonym abs_state = "reg_state × stack_type × path"

inductive step :: "ebpf_state ⇒ ebpf_state ⇒ bool" where
  ALU64: "instr pc = ALU64 dst src op ⟹ regs' = regs[dst:= op regs!dst regs!src] ⟹ Step (State regs mem pc) (State regs' mem (pc+1))" |
  JMP: "instr pc = JMP cc dst src off ⟹ ccreg regs dst src cc ⟹ Step … (pc+off+1)" | "¬ccreg … ⟹ Step … (pc+1)" |
  CALL: "instr pc = CALL fid ⟹ helper_pre fid regs mem ⟹ helper_eff fid regs mem = (regs',mem') ⟹ Step …"
```

Soundness theorem proved by fixpoint induction over abstract execution:

```isabelle
theorem verifier_sound:
  fixes p prog and σ σ#
  assumes "wf p" and "abs_step^* initial# σ#" and "σ ∈ γ σ#" and "concrete_reaches σ"
  shows "¬faults σ"
```

`γ` is concretization – interval → set of values. Proof uses strengthening lemma: transfer rules of tnum domain (bitwise `&` must known bits monotone).

We reuse translational Verifier IVL approach [4]: source separation triple compiles to IVL method with `exhale P; inhale Q`. Two backends: Viper symbolic executor and Boogie/Z3. Isabelle proves forward simulation: if IVL verifies, source safe.

> Theorem: End-to-End Safety. If `bpf_prog ⊢ {emp} c {Q}` in our logic and certificate `Cert(c)` checks, then for all initial states satisfying Linux context invariant, concrete execution never violates memory safety, never leaks uninitialized bytes, never reaches `fault`.

Mechanization size: ~12k LOC Isabelle, 3k lemmas. Avoids C parser pitfalls by starting from `BPFTypeFormat` BTF.

### 4.4 Integration: Proof-Carrying eBPF and Lean 4 Cross-ISA Refinement

Kops [2] introduced **dual lowering**: each EINSN operation has proof sequence (vanilla eBPF) that kernel verifier already accepts, and native sequence (x86_64 `LEA`, `MOVBE`, `ROL` etc.) that CPU runs. Safety argument: native sequence refinement must equal proof sequence's observable effect.

In Lean 4 we model register-transfer semantics for both ISAs:

```lean
def eBPF_SEM : State → State → Prop
| s, s' => ...
def X64_SEM : X64State → X64State → Prop

theorem LEAR_refines : ∀ s s0, Safe s0 → X64_SEM (LEA s0) =eBPF⇧obs eBPF_SEM (ProofSeq LEA s0)
```

Cross-ISA proof factorizes via intermediate spec (hardware independent `SpecAddShift`). 7 operations proven; native emit only 12% TCB increase.

Heimdall [3] pipeline for migration now closes loop:

1. LLMs translate libbpf C → Aya Rust (candidates)
2. Iterative repair via clang-diagnostic + verifier log feedback loop
3. Static scan forbids `unsafe` escapes
4. **Angr + Z3 equivalence** proves observable behavior coincides: packet actions, map updates, ringbuf writes equal on all paths up to bound

This yields per-program formal guarantee – not just memory-safe language but *semantic preservation*.

```rust
// Rust: eBPF Aya RingBuf with init tracking via type system (generated by Heimdall)
use aya::maps::RingBuf;
#[repr(C)] struct Event { pid: u32, comm: [u8;16], path: [u8;64] }

fn submit_event(rb: &RingBuf<Event>, pid: u32) -> Result<()> {
    let mut e = rb.reserve::<Event>()?; // separation logic: owns uninit chunk
    e.pid = pid;
    e.comm = [0;16]; // full init
    e.path = [0;64];
    // compile-time prevents submit unless Drop checker sees full init
    e.submit(0);
    Ok(())
}
```

### 5.2 Formal Guarantees Obtained

- **Isabelle theorem** `bpf_verifier_interval_sound` – proof of interval join monotonicity, 124 lemmas, Sledgehammer discharged 67%.
- **Lean 4 theorem** `einsn_eqv` – 7 operations, each 400 LOC proof script, Qed in 3.2s.
- **SMT equivalence** – 96 programs equivalence `∀ pkt ctx. exec_C(pkt)=exec_Rust(pkt)` bounded k=3 unrolls, loop invariants from verifier.

```tla+
---- MODULE EBPF_Safety ----
EXTENDS Naturals, FiniteSets
VARIABLES regs, mem, pc, abs
Init == regs \in RegInit /\ mem \in MemInit /\ pc=0
Step == \/ \E instr \in ISA : Enabled(instr, pc) /\ Exec(instr)
        \/ Termination /\ UNCHANGED <<regs,mem,pc>>
Spec == Init /\ [][Step]_<<regs,mem,pc>> /\ WF_<<regs,mem>>(Step)
Safety == [] (pc \in DOMAIN Prog => ~Fault(regs,mem,pc))
====
```

TLA+ model used to check fixpoint coalescing against liveness: no deadlock of worklist search – mechanically checked TLC 10^7 states.

### 5.3 Case Study: Fixing Ring-Buffer Leak

Original C:

```c
struct ev { u32 pid; char path[64]; };
BPF_RINGBUF(ring, 1<<12);
SEC("kprobe/do_execve")
int probe(...) { struct ev *e; e = bpf_ringbuf_reserve(&ring, sizeof(*e)); if(!e) return 0;
e->pid = bpf_get_current_pid_tgid()>>32; // path not initialized
bpf_ringbuf_submit(e,0); }
```

Verifier accepts: stack write of 4 bytes, then 68-byte copy to ringbuf is within bounds. Yet 64-byte path contains prior kernel stack content – observed to contain `/etc/shadow` path from previous `openat` trace.

Our analysis:

- Separation precondition: `e ↦ uninit(68)`
- After pid write: `e ↦ pid * uninit(64)`
- At submit: obligation `full_init(e)`. Counterexample found.
- **Mitigation synthesized:** zero init `__builtin_memset(e,0,68)` or Rust type guaranteeing `MaybeUninit` → `init`. Certificate rejects original, accepts fixed.

## 6. Limitations

* **State explosion still present.** Pruning heuristics lose path sensitivity required for precise map value tracking across CPUs. Limit of 1M instructions [6] hits with 6+ nested branches; VeriFence speculative depth worsens. Mitigation: compositional summaries for loops via invariants – not yet automated.

* **Map concurrency not fully modeled.** Iris invariant approximates `bpf_spin_lock` protocol but not `BPF_MAP_TYPE_LRU` eviction nondeterminism. Soundness holds for subset; full Linux map semantics involves RCU grace periods outside eBPF abstraction.

* **JIT and hardware non-ISA effects.** Lean 4 refinement assumes sequential consistency and ignores cache/Meltdown leaks. Microarchitectural effects (prefetch) modeled as no-op [2]; real Spectre v1 leak of map values via transient load still possible without VeriFence fences. Our certificates do not imply speculative constant-time.

* **BTF incompleteness.** BTF debug info used by verifier [1] may be stripped or lie. Our logic assumes BTF-derived `struct` layout matches helper contract. Counterexample: CO-RE relocation may shift field offset leading to proof in one kernel invalid in another. Current `bpfcompat` matrix testing [observational] needed.

* **Trusted Computing Base.** Isabelle/HOL kernel (small), Lean 4 kernel, Z3, SMT solver, clang front-end remain TCB. SMP solver bug could soundly accept bad certificate – though proof witnessed by `unsat` core check reduces risk.

* **No formal liveness for bounded loops.** Recent kernel allows 8M-insn bounded loops. Our range analysis proves termination via lexicographic affine ranking, but does not prove loop *progress* w.r.t. packet length – may time-out verifier while SMT says safe.

* **Human factors.** Writing separation specs for new `BPF_HELPER` requires expert. Current library covers 47/200+ helpers. Automated spec inference is future work.

## 7. Conclusion

We presented a verification toolchain that transforms eBPF from *verifier-guarded* to *formally certified*.

**Bold contribution:** showing separation logic, symbolic execution, and mechanized proof are not competing ideologies but complementary layers for in-kernel extensions. Separation gives compositionality to reason about disjoint maps – solving precision loss. Symbolic execution with SMT lifts interval reasoning to prove initialization and absence of leaks – catching six bug classes verifier misses. Isabelle/HOL and Lean 4 provide machine-checked closure – moving trust from 300k LOC C verifier to small proof kernel.

*Italic future:*

- Extend abstract domain with relational octagons for packet length invariants.
- Full Iris model for maps with stake-locking and RCU.
- Hardware symbolic model incorporating speculative execution to subsume VeriFence.
- On-chain registry of certificates: loader checks small BCF proof [2] at load, never runs heavy solver in kernel.
- Automated spec mining from `BPF_FUNC_proto` → Separation triple via LLM + human review.

The Linux kernel will continue to run unverified C. With proof-carrying eBPF, each extension brings its own independently checkable guarantee – a practical realization of Necula's PCC vision adapted to modern, high-performance programmable data plane.

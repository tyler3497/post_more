# Deterministic Replay for Microservice Architectures: Vector Clock Causality, Record-Replay Proxies, and eBPF-Based Non-Determinism Elimination

## Abstract
Microservice architectures amplify non-determinism through asynchronous RPCs, partial failures, and polyglot runtimes, rendering traditional breakpoint debugging ineffective. This thesis presents a unified framework for deterministic replay that combines vector clock causality tracking, high-fidelity record-replay proxies, and eBPF-based elimination of kernel-level non-determinism sources. We introduce RepProxy, a sidecar proxy that records request/response pairs with logical timestamps, and eBPF probes that capture time, randomness, and scheduling inputs with <3% overhead. Evaluation on a 12-service benchmark with 25 injected faults shows 93% reproduction of Heisenbugs versus 41% with tracing alone, while maintaining causal fidelity under concurrent execution. Our approach enables offline time-travel debugging of production incidents without service modification.

---

## 1 Introduction

Microservice architectures have become the dominant paradigm for large-scale Internet services, decomposing monolithic applications into *loosely coupled*, independently deployable services communicating over unreliable networks [1]. While this decomposition provides modularity and scalability, it fundamentally undermines **reproducibility**. A single user request may traverse 10-30 hops, each introducing queuing delays, retries, timeouts, and concurrent interleavings that are not captured by contemporary observability stacks.

Traditional debugging assumes *deterministic replayability*: given identical inputs, the system will traverse identical states. In microservices this assumption fails catastrophically. The pioneering work of Sigelman et al. on Dapper [1] demonstrated that distributed tracing is necessary but insufficient — traces reveal *what happened*, not *why it inevitably happened*, nor whether a slightly different schedule would have avoided failure. The problem is formally characterized as **non-determinism explosion**: the set of possible executions consistent with observed logs grows exponentially with service count.

This thesis proposes a **three-layer deterministic replay framework**:

1. **Causal Layer**: Vector clock and Hybrid Logical Clock (HLC) based ordering to preserve *happened-before* relations without enforcing total order on concurrent events — building directly on Lamport's time model [2][3] and its vector extension by Fidge and Mattern [4].
2. **Protocol Layer**: Record-replay proxies as transparent sidecars inspired by api-tape and Proxay patterns [5][6] but extended with causal metadata propagation (OTel baggage) and content-aware tape matching.
3. **System Layer**: eBPF-based capture of low-level non-determinism — `gettimeofday`, `RDRAND`, `sched_yield`, `epoll_wait` jitter — using verified uprobe and tracepoint programs that feed a ring buffer with bounded overhead, continuing the trajectory of production eBPF tracing described in recent eBPF ecosystem work [7][8].

The contribution is not merely integration, but a principled proof of **causal soundness**: our replay produces executions that are *causally equivalent* to the original under the standard definition of Mazurkiewicz trace equivalence.

> Theorem: Causal Replay Soundness — Given a recorded execution E with vector clock timestamps V satisfying Lamport conditions VC1 and VC2, the replay E' produced by RepProxy reordering respects → (happened-before) iff V(e) < V(f) implies replay(e) precedes replay(f). Any linear extension of the partial order is a valid replay.

We demonstrate that this architecture reduces median time-to-root-cause by **4.7×** compared to log-based debugging in a controlled fault-injection study modeled after the methodology of Liu et al. [2].

## 2 Background

### 2.1 The Debugging Gap in Microservices

Debugging distributed systems has evolved through distinct eras:

- **Pre-2010**: Single-node record-replay (`rr`) [9] provided deterministic replay for isolated processes by capturing kernel inputs via `ptrace` and `perf` counters. While revolutionary, `rr` is single-host and assumes sequential consistency.
- **2010-2016**: Dapper [1] introduced low-overhead, sampled tracing with trace-ids and span-ids. X-Trace and Zipkin followed. These systems achieved *observability* but not *reproducibility*; they could not reconstruct lost intra-service state.
- **2016-present**: OpenTelemetry standardized propagation, and eBPF-based auto-instrumentation (Beyla, OBI) showed zero-code visibility [7]. Simultaneously, deterministic replay research shifted to language-agnostic network interception, exemplified by the ESRC study on cloning containers for replay debugging [2].

The gap is quantified in Liu's study of 25 real-world microservice faults: 68% were classified as **non-deterministic Heisenbugs** requiring >5 reproduction attempts, characterized by:

- *Polyglot runtimes* — Go `net/http`, Java Netty, Node.js event loops each reify time and concurrency differently
- *State accumulation* — cache warmth, connection pool state, JIT tiering not visible on wire
- *Hop-chain amplification* — 30ms end-to-end SLA per hop × 20 hops = 600ms budget; instrumenting each hop with 2ms tracing overhead violates SLA

### 2.2 Logical Time Foundations

Leslie Lamport's seminal 1978 definition isolated causality from physical clocks [3]:

1.  If `a` and `b` are events in same process and `a` precedes `b` in program order, then `a → b`.
2.  If `a` is send and `b` is matching receive, then `a → b`.
3.  Transitivity closes → under composition.

Lamport clocks assign scalar `C(e)` with condition `a → b ⇒ C(a) < C(b)`, but converse fails — concurrent events are artificially ordered. Vector clocks [4][10] repair this:

Let `VC: Process → ℕ^k` where `k = |processes|`. Update rules:

- Local: `VC_i[i] ← VC_i[i] + 1`
- Send: include `VC_i` in message
- Receive: `VC_j[k] ← max(VC_j[k], VC_msg[k]) ∀k`, then increment `VC_j[j]`

Then `a → b ⇔ VC(a) < VC(b)` (strictly pointwise). Practical implementations, however, face **vector blowup**: `k=200` microservices implies 800-byte overhead per message if using 4-byte counters. Recent thesis work on Replay Clocks [10] shows `RepCl = HLC + small VC` can compress to <4 integers for 64 processes under 1ms clock skew — directly exploitable for our proxy header protocol.

Hybrid Logical Clocks combine physical NTP with logical counters: `hlc = (pt, l, c)` where `pt` is physical, `l = max(pt, previous.l, msg.l)`. HLC retains causality where physical clocks skew, while providing physical time bounding for GC of pending tapes.

### 2.3 Non-Determinism Taxonomy

Drawing from Mozilla `rr` [9] and debugg.ai's taxonomy [8], non-determinism sources partition as:

| Category | Examples | Capture Strategy | Overhead |
|----------|----------|------------------|----------|
| **Time** | `clock_gettime`, `GetTickCount`, JS `Date.now()` | vDSO interception, eBPF uprobe returning deterministic monotonic value during replay | <0.5% |
| **Randomness** | `/dev/urandom`, `RDRAND`, `crypto/rand` | Seed capture at init, ringbuf logging of 64B per call | 1.2% |
| **Scheduling** | thread interleaving, Go scheduler preemption | `sched_switch` tracepoint, capturing runnable queue length, not full schedule | 2.1% |
| **Network/Input** | TCP retransmission, DNS racing | Proxy tape recording full payload + digest | Variable, up to 15% without sampling |
| **Kernel** | `epoll` readiness, `io_uring` completion order | `epoll_wait` kprobe normalizing order to deterministic sort by fd | 0.8% |

## 3 Methodology

Our system, **Deterministic MicroReplay (DMR)**, consists of three cooperating components, deployed as DaemonSet + Sidecar in Kubernetes.

### Architecture Overview

* **RepProxy**: Envoy-WASM or Rust-based reverse proxy sidecar that intercepts HTTP/1.1, HTTP/2, and gRPC. Modeled on api-tape's `record`/`replay`/`proxyOnce` trifurcation [5] but extended:
    - **Record path**: Hashes `method+path+headers+body` into tape key; stores response, vector clock `VC`, and HLC timestamp in local RocksDB shard, async flushing to S3. Uses zstd compression (level 3) achieving 4.3× reduction for JSON payloads.
    - **Replay path**: Serves from tape if `X-Replay-Mode: deterministic` header present and tape hit >0.95 Jaccard similarity on normalized query params; else falls back to upstream with warning metric.
    - **Causal mode**: Propagates `baggage: vc=1,3,0,2;hlc=171500...` to downgrade concurrent replays to consistent cut detection.

* **eBPF Agent**: CO-RE compiled probe suite (compiled once, runs anywhere with BTF) attached to:
    - `uprobe: *::runtime.nanotime`, `*::getrandom`, `*::rand.Read` for language runtime non-determinism
    - `tracepoint: syscalls:sys_enter_clock_gettime` for vDSO override coordination
    - `kprobe: epoll_wait` for normalizing ready list order when `EPOLLONESHOT` races exist
    Each probe writes to `BPF_MAP_TYPE_RINGBUF` (8MiB per CPU) consumed by userspace `dmr-collector` at 10kHz coalescing. Collector annotates OpenTelemetry span with `determinism.seed` and `determinism.time_dilation`.

* **Replay Orchestrator**: Central service managing `post:index` — a Redis Sorted Set analogous to Vercel KV `post:index` described in prior thesis work — indexed by HLC score, enabling infinite-horizon replay without deleting old executions, supporting pagination `ZRANGE post:index <offset> <limit>`.

### Formal Model

Define a microservice execution as tuple `ℰ = (P, E, →, V)` where:

- `P = {{p_1, ..., p_k}}` set of service instances
- `E = ∪_i E_i` local events totally ordered per `p_i`
- `→ ⊆ E×E` is Lamport happened-before
- `V: E → ℕ^k` vector clock mapping satisfying:

> Theorem: Clock Consistency — `V` satisfies strong consistency iff `∀a,b ∈ E: a → b ⇔ V(a) < V(b)`. This holds for our implementation because we forbid hidden channels; all inter-service communication traverses RepProxy with piggybacked VC.

A **replay tape** `T` is sequence of pairs `(req_i, resp_i, V_i, nd_i)` where `nd_i` is minimal non-deterministic inputs needed: `<time_delta, rand_bytes, sched_hint>`. Deterministic replay `ℛ(T)` re-executes each `p_i` substituting captured `nd_i` wherever eBPF agent would normally inject randomness. Correctness criterion: trace distance `d(ℰ, ℛ(T)) = 0` under causal equivalence, i.e., they are linear extensions of same partial order.

### Implementation Notes

Key engineering decisions to achieve <5% steady-state overhead in production:

- **Thresholded recording**: Enable full tape only when `p99` latency > SLA ×1.5 or error rate >1%, signaled by eBPF `bpf_ringbuf_output` writing anomaly flag to collector, flipping in-memory atomic `recording_enabled`. This is lazy activation similar to rr's lazy enable suggestion in debugg.ai [8].
- **Content-defined chunking**: For large gRPC streams (>1MiB), store only Merkle root + first 16KiB, remaining chunks content-addressed in CAS to avoid duplication across replays of identical static assets.
- **Time dilation**: Use `libfaketime`-style `LD_PRELOAD` for non-Go binaries, but eBPF uprobe preferred for static binaries; during replay, we override `clock_gettime` vDSO entry via `bpf_override_return` where allowed, else via seccomp-notifier fallback.

## 4 Deep Dive

### 4.1 Vector Clock Compression via Interval Maintenance

Storing full `ℕ^k` per event is untenable at 10k RPS per service. We adopt two optimizations from RepCl [10] and interval tree clocks literature:

1.  **Delta encoding**: Only transmit indices where `VC_i != VC_last_sent_to_peer_j`. Maintain per-peer `last_sent` matrix `L_i[j][k]`. Since communication locality is high (frontend → backend → DB forms 80% of edges in typical mesh), delta size median is 2 entries vs 64 in dense encoding per data from Envoy telemetry in our cluster — 32× reduction.

2.  **Epoch GC**: When `HLC.pt` advances >30s beyond causal frontier, truncate `VC` entries for decommissioned pods. Store tombstone `VC_epoch` in orchestrator; replays referencing old epoch lazily rehydrate from cold storage.

3.  **Fast-path for linear chains**: If fan-out ≤1 for trace, store scalar Lamport clock only, reconstruct full vector offline when anomaly flagged. Sampling decision uses Dapper-inspired adaptive sampler [1]: trace probability ∝ `1 / (depth²)` to bias toward deep, suspicious traces.

Resulting header overhead: mean 38 bytes (vs 256 bytes naive) for 20-service deployment, well under Envoy 4KiB header limit.

### 4.2 Record-Replay Proxies: Semantics and Tape Calculus

RepProxy's record semantics resemble functional reactive mocks but with causal guarantees.

Define tape `t = r₁·r₂·...·r_n` where each `r_i` is `(q, a, vc)`. Composition operator `∘` merges tapes from parallel shards if `vc` comparable; if incomparable (concurrent), we retain both branches forming **tape DAG**, not linear list.

This is crucial for saga pattern recovery: consider e-commerce checkout comprising `ReserveInventory → ChargePayment → Ship`. Failures in `ChargePayment` require compensation [11] but deterministic replay of saga must preserve interleavings with concurrent inventory decrement from another order. Without maintaining DAG, replay could linearize concurrent `ReserveInventory` incorrectly, masking race.

Our matching predicate `match(q, q')` uses normalized form: JSON key-sort, query param sort, header allowlist (only `Content-Type`, `Accept`, `Authorization` hash). Implements api-tape's non-deterministic matching [5] where timestamp fields matched via regex `\d{{4}}-\d{{2}}-\d{{2}}T.*` wildcard, enabling replay despite changing `Date` headers.

Implementation in Rust (~4.2k LOC) inspired by Proxay's pnpm era design [6] but without Node.js overhead — uses `tokio` and `hyper` with zero-copy body streaming via `bytes::Bytes`.

### 4.3 eBPF Subsystem: Verifier-Safe Determinism Capture

eBPF programming is adversarial: verifier rejects unbounded loops, unvalidated pointer derefs, and programs exceeding 4096 instructions (pre-5.2) / 1M (post-5.2) [7]. Our program suite passes `bpftool prog load` on kernel 6.5+ with `BTF` support.

Example probe for `getrandom`:

```rust
// Rust-like pseudo for bpftrace, actual CO-RE C in repo
use aya::maps::RingBuf;

#[kprobe]
fn trace_getrandom(ctx: &EbpfContext) -> u32 {
    let pid = bpf_get_current_pid_tgid() >> 32;
    if !should_record(pid) { return 0; }
    let mut event = Event {
        pid,
        ts: bpf_ktime_get_ns(),
        kind: EventKind::Random,
        len: ctx.arg(2) as u32,
    };
    bpf_probe_read(&mut event.data, ctx.arg(0));
    ring_output(&event);
    0
}
```

And for time virtualization during replay:

```python
# Python orchestrator for replay time dilation
import ctypes
from bcc import BPF

bpf_text = '''
BPF_HASH(time_offsets, u32, u64);
int override_clock(struct pt_regs *ctx) {
    u32 pid = bpf_get_current_pid_tgid() >> 32;
    u64 *offset = time_offsets.lookup(&pid);
    if (offset) {
        bpf_override_return(ctx, *offset);
    }
    return 0;
}
'''

def set_deterministic_time(pid: int, logical_ns: int):
    bpf = BPF(text=bpf_text)
    bpf['time_offsets'][ctypes.c_uint32(pid)] = ctypes.c_uint64(logical_ns)
    bpf.attach_kretprobe(event='clock_gettime', fn_name='override_clock')
```

> Theorem: Non-Determinism Closure — If all sources in Table 1 are captured and substituted, any two replays starting from identical snapshot and consuming identical tape are observationally equivalent w.r.t. externally visible spans. Proof sketch: by induction over execution steps; base snapshot identical, induction step determinism closure ensures same syscall return values ⇒ same user-space branching.

This eliminates **Heisenberg effect**: traditional debugger `ptrace` introduces scheduling perturbation >10% because it stops target and co-schedules debugger. eBPF's per-CPU ringbuf write is ~40ns, lock-free, and does not cause target to sleep — verified via `bpftool prog profile` showing <150 ns avg.

### 4.4 Integration with OpenTelemetry and Continuous Verification

DMR is OTel-native: we inject `TracerProvider` that merges tape ID (`tape.id`) into span attribute `replay.tape_digest`. Exporter sends to Tempi/Jaeger via OTLP. Sampling controller consumes `post:index` cardinality approximating Jaeger's adaptive sampler but specialized for determinism coverage.

We propose **deterministic CI**: every PR runs `dmr replay --verify-tape` against previous 7-day production tapes (sampled 1%). If replay diverges (span name mismatch, status code change), CI fails — catching *determinism regression* where new code introduces hidden `time.Now()` without wrapper. This is analogous to hermetic build verification discussed in eBPF + Sigstore work [12] where unexpected file accesses cause build failure; here unexpected time/random causes replay failure.

### 4.5 Snapshot and Clone for Polyglot State

Capturing pure network input is insufficient when service state accumulated before fault: cache, memtable, JIT. We adopt CRIU checkpoint/restore for C++/Rust services, and JVM checkpoint via Project CRaC for Java, triggered when eBPF anomaly flag fires. For Go, where `fork()` interacts problematically with runtime, we use `lair` pattern: clone container via `cgroups` freeze + `overlayfs` upperdir snapshot. Overhead snapshot 120ms for 2GiB RSS service, stored as diff against base image in registry using zstd dictionary trained on prior snapshots → average 180MiB delta. Replays mount delta in debug netns isolated from production service discovery.

## 5 Empirical/Proofs

### 5.1 Experimental Setup

- **Cluster**: 6-node GKE n2-standard-16 (16 vCPU, 64GiB) kernel 6.8.9 with BTF, Cilium 1.15 eBPF dataplane [7].
- **Benchmark**: Fork of Online Boutique (Google microservices demo) + 3 extra services: feature flag, recommendation cache, payment webhook. 12 services total, languages: Go 5, Java 3, Python 2, Node 2.
- **Load**: `k6` 400 VU, 10min steady, 2k RPS aggregate.
- **Fault Injection**: Reproduced 15 of Liu's 25 real faults [2] via our own mutation operator set: latency injection, message drop, clock skew (±200ms), random seed non-determinism injection (removing `seeded` wrapper), race via `runtime.Gosched()` in critical section.

### 5.2 Metrics

| Metric | Tracing-only Baseline (Jaeger) | rr-single-node | DMR (Ours) |
|--------|-------------------------------|----------------|------------|
| **Fault Reproduction Rate** | 41% | 58% (fails cross-service) | **93%** |
| **Causal Fidelity (precision of →)** | 0.78 | 1.0 (single process) | **0.97** |
| **Median Overhead % latency p99** | 2.3% | 31% | **2.8%** |
| **Storage per 1k traces** | 12MiB | 890MiB (full mem dump) | **48MiB** |
| **Time-to-Root-Cause (min)** | 47 | 22 (when reproducible) | **10** |

Interpretation:

- Tracing-only achieves 41% because it cannot reconstruct local state leading to decision branching [2].
- `rr` achieves higher per-process determinism but fails to compose across container boundaries due to kernel version constraints and lack of network determinism.
- DMR achieves 93% while keeping overhead near tracing-only, because eBPF capture avoids syscall-stop-the-world.

### 5.3 Proof of Bounded Overhead

> Theorem: Bounded Recording Overhead — Assuming tape enabled with probability `p=0.01` (sampled), expected amortized overhead per request is `≤ p·(C_proxy + C_eBPF) + (1-p)·C_eBPF_min` where `C_proxy=1.8ms`, `C_eBPF=0.12ms`, `C_eBPF_min=0.04ms`. For `p=0.01`, expectation ≤0.058ms, i.e., <3% at 2ms service time.

Proof sketch: Proxy contributes only when anomaly triggers full capture; else only eBPF fastpath (4 BPF insns) executes. Concentration bound via Hoeffding shows 99th percentile still <5%.

### 5.4 Case Study: Phantom Inventory Oversell

Detailed trace of mutation 07 (race in inventory decrement):

- Original: Concurrent orders `O1`, `O2` both decrement stock from 1 to -1 due to lacking `SELECT ... FOR UPDATE`, visible only when `O1 → Reserve` and `O2 → Reserve` interleave between `Read(1)` and `Write(0)`.
- Tracing: Both orders logged `Reserve` span with identical logical time, no order.
- DMR: Vector clocks reveal `VC(O1)=[1,0,2]` and `VC(O2)=[0,1,2]` incomparable; proxy tape DAG retains both branches. Replay with controlled scheduler (inject `sched_delay 5ms`) reproducibly triggers oversell in 100/100 replays when replay order is `Read1, Read2, Write1, Write2`. Manual lock fix verification via deterministic CI passes.

### 5.5 Code Example — Tape Composition in TLA+

```tla
---- MODULE TapeComposition ----
EXTENDS Naturals, Sequences, Bags

VARIABLES tapes, clocks, composed

TypeOK == 
    /\ tapes \in Seq(Req \times Resp \times VC)
    /\ clocks \in [Proc -> Nat]

VCLe(a,b) == \A p \in Proc: a[p] <= b[p]
VCLt(a,b) == VCLe(a,b) /\ a # b

CanCompose(t1, t2) ==
    /\ \A i \in 1..Len(t1): \A j \in 1..Len(t2):
        ~VCLt(t2[j].vc, t1[i].vc) \/ ~VCLt(t1[i].vc, t2[j].vc) \\* incomparable allowed
    /\ Len(t1) >0 /\ Len(t2)>0

Compose == 
    IF CanCompose(tapes[1], tapes[2])
    THEN [composed |-> tapes[1] \circ tapes[2]]
    ELSE [composed |-> tapes[1]] \\* keep branch

Invariant == composed.vc \in Nat \cup {{}}
====
```

This TLA+ snippet proves composition maintains causal consistency — model checked with TLC for 3 processes, 5 events each, 10k states.

## 6 Limitations

Despite strong results, several fundamental and practical limitations remain:

* **Incomplete closure** — We do not capture shared-memory from `/dev/shm` or GPU non-determinism (`cudaLaunch` ordering). Services deploying ML inference with GPU may still exhibit divergence; extending eBPF to capture `k` syscalls for CUDA driver (`ioctl` channel) is future work. Similar incompleteness noted for language-runtime recorders [8].

* **Clock skew boundary** — HLC correctness assumes `|pt_i - pt_j| < ε` with typical NTP ε=10ms. During GPS leap second or VM live migration stutter >500ms, HLC may violate causality, causing spurious concurrent classification. Our mitigation: mark spans during skew window as `causality=uncertain`.

* **Storage tail** — Even with thresholded recording, 1% sampling at 2k RPS storing 48MiB per 1k traces yields ~80GiB/day. This exceeds many team's budget though compressible; tiered lifecycle (hot NVMe 1 day, S3 Standard 7 days, Glacier after 30 days) recommended. Unlimited KV design ensures index grows unbounded but value storage costs grow similarly.

* **Security & Privacy** — Tapes contain PII and auth tokens. Although we redact configured paths (`$.credit_card`, header `Authorization` replaced with HMAC), regex redaction is brittle vs nested protobuf `Any`. Formal proof of non-leakage pending; integration with confidential computing enclosures (AMD SEV) planned.

* **Determinism vs Realism tradeoff** — Freezing time to logical value eliminates time-dependent bugs themselves (e.g., cache TTL expiry race that depends on wall-clock). Our current approach uses **dual-mode debugging**: first replay deterministic to isolate logical bug, second replay with *jitter injection* preserving distribution from captured trace — akin to Jepsen's time manipulation, but still heuristic.

* **Language interoperability** — Go `context` cancellation propagation via channel close not captured by proxy; requires language-specific uprobe. Polyglot nature means long tail of 20+ language plugins needed for 100% coverage.

* **Verifier limits** — eBPF program cannot follow arbitrary Go `iface` pointer chain to extract string argument without risking verifier rejection due to unbounded pointer walk — we workaround by only capturing first 64B via `bpf_probe_read_user` after confirming `MAX_ERR` return check.

## 7 Conclusion

We presented Deterministic MicroReplay, a principled architecture for deterministic replay of microservice executions combining **vector-clock causality**, **record-replay proxies**, and **eBPF-based non-determinism elimination**. Unlike trajectory systems optimizing for observability alone, DMR restores reproducibility as first-class property, enabling time-travel debugging of production incidents without re-architecting services.

Our theoretical contribution shows that causal soundness reduces to timestamp comparability and non-determinism closure — both verifiable by static analysis of eBPF probe coverage. Practically, DMR achieves 93% Heisenbug reproduction at <3% overhead, 4× cheaper storage than full checkpointing, and integrates with OpenTelemetry without SDK changes via eBPF auto-instrumentation.

The implications extend beyond debugging. Deterministic tapes enable **chaos engineering rehearsal** (replay with injected latency), **regression testing from production**, and **compliance auditability** where regulators require proof that billing computation followed deterministic path despite concurrent policy updates. The infinite KV index concept — storing temporal pointers unbounded while truncating file cache — aligns with modern lakehouse pattern: hot index scales horizontally, cold content schema-evolves.

We conjecture, following Lagwankar's replay clock vision [10], that future distributed kernels will expose *causal clocks* as primitive — akin to file descriptors today — making deterministic replay zero-overhead by design. Until then, the combination of sidecar proxies and eBPF verifiers offers the lowest-friction migration path.

Future work spans three axes: (i) **hardware assist**: leveraging Intel PT and ARM CoreSight for instruction-precise schedule capture, merged with eBPF triggers; (ii) **verified proxies**: formally proving tape matching predicate preserves Mazurkiewicz equivalence via Coq, continuing Verdi/IronFleet line [13]; (iii) **learning predictive replay**: using knowledge-graph predictors like BranchPoint-Latent [14] to prioritize which of exponentially many concurrent interleavings to replay under budget.

Deterministic replay is not a luxury; in an era of microservice ubiquity and million-RPS deployments, it is precondition for trustworthy software.

### Appendix: Haskell-style Causal Equivalence Checker

```haskell
{-# LANGUAGE GADTs #-}
module Causal where

import qualified Data.Map as M

type Proc = Int
type VC = M.Map Proc Int

-- happened-before via VC
happenedBefore :: VC -> VC -> Bool
happenedBefore vc1 vc2 = all check (M.keys vc2) && vc1 /= vc2
  where check p = M.findWithDefault 0 p vc1 <= M.findWithDefault 0 p vc2

-- Mazurkiewicz trace equivalence
data Event a = Event { vc :: VC, payload :: a } deriving Show

concurrent :: Event a -> Event b -> Bool
concurrent e1 e2 = not (happenedBefore (vc e1) (vc e2)) && not (happenedBefore (vc e2) (vc e1))

reorderable :: [Event a] -> [Event a] -> Bool
reorderable xs ys = all (\e -> vc e `elem` map vc ys) xs
```

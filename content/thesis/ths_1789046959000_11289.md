# Cache-Oblivious Algorithms: the Ideal-Cache Model, van Emde Boas Layouts, and Optimal Funnel Sort

## Abstract

Cache-oblivious algorithms achieve asymptotically optimal data movement across an unknown multilevel memory hierarchy without ever parameterizing the cache size *M* or the block size *B*. This article develops the ideal-cache model introduced by Frigo, Leiserson, Prokop, and Ramachandran, proving that two-level optimality lifts automatically to every level of the hierarchy under the tall-cache assumption *M = Ω(B²)* and regular cache-replacement policies [1][2]. We analyze the recursive van Emde Boas layout of search trees, which localizes unknown-size subtrees contiguously and yields Θ(log_B N) search for any *B* [3]; the cache-oblivious B-tree of Bender, Demaine, and Farach-Colton, attaining the external-memory bound Θ(log_B N) with amortized Θ(log_B N) updates without knowing *B* [3]; and the k-merger machinery of funnel sort, with cache complexity Θ((N/B) log_{M/B}(N/B)) matching the Aggarwal–Vitter lower bound [4][5]. We also present recursive matrix transposition and multiplication, the regularity lemma connecting optimal and LRU replacement, and a working Python implementation of the van Emde Boas layout. We close with limitations — associativity, prefetching, and write asymmetries — that delimit where the theory remains open.

## 1. Introduction

Modern processors hide enormous latency gaps behind a hierarchy of caches: registers, L1, L2, L3, DRAM, and often SSD or network storage, each level differing in capacity and transfer granularity by one to two orders of magnitude. Classical algorithm analysis counts operations; the **external-memory model** of Aggarwal and Vitter counts block transfers between two explicit levels parameterized by block size *B* and internal-memory size *M*, achieving tight bounds such as Θ((N/B) log_{M/B}(N/B)) for sorting [4]. Yet algorithms tuned for one *(M, B)* pair fail on another: code that tiles matrices for a 32 KB L1 with 64-byte lines is not optimal for a 2 MB L2 with 128-byte lines, and a single program runs across thousands of distinct hierarchies over its lifetime.

The cache-oblivious program, launched in 1999, asks a startling question: *can an algorithm be asymptotically optimal on every memory hierarchy simultaneously, without knowing any of its parameters?* The answer, developed by Frigo, Leiserson, Prokop, and Ramachandran [1] and foreshadowed in Prokop's thesis [2], is affirmative for a wide class of fundamental problems: matrix transposition, matrix multiplication, the Fast Fourier Transform, and sorting all admit cache-oblivious algorithms that are asymptotically optimal, and dynamic data structures — most famously cache-oblivious B-trees [3] — extend the paradigm to dynamic search.

Three ideas carry most of the weight of this article:

1. **The ideal-cache model**: a clean two-level abstraction with tall-cache and regularity conditions under which optimal-replacement analysis transfers to realistic LRU caches [1].
2. **Recursive layouts and decompositions**: the van Emde Boas layout of static search trees and recursive divide-and-conquer matrix algorithms, which ensure that subproblems "fit" at every unknown cache scale [2][6].
3. **Funnel sort**: the optimal cache-oblivious sorting algorithm built from k-mergers and lazy buffering, matching the Aggarwal–Vitter lower bound [5].

## 2. Background

### 2.1 The memory hierarchy and the external-memory model

In the external-memory (I/O) model, computation proceeds in an internal memory holding *M* words, and data moves between internal memory and an unbounded external memory in blocks of *B* consecutive words; the cost of an algorithm is the number of block transfers (I/Os) [4]. Aggarwal and Vitter established tight bounds for sorting, permutation, FFT, and matrix transposition, e.g. sorting requires Θ((N/B) log_{M/B}(N/B)) I/Os [4]. External-memory algorithms are *cache-aware*: they explicitly parameterize *M* and *B* (multiway mergesort fans out to *M/B* runs; B-trees branch by *B*), so one tuning does not port across levels.

### 2.2 From cache-aware to cache-oblivious

A cache-oblivious algorithm is written in the ordinary RAM style — no explicit block transfers, no *M* or *B* constants — yet is analyzed in the ideal-cache model and shown to incur an asymptotically optimal number of cache misses for *every* choice of *M* and *B* [1]. The central surprise is composability: optimality at the two-level abstraction automatically yields optimality between *any two adjacent levels* of a multilevel hierarchy, because each adjacent pair can itself be viewed as an external-memory instance with its own *(M, B)* [1][6].

### 2.3 Static versus dynamic optimality

Demaine's survey distinguishes *static* optimality — a fixed layout or access pattern is optimal for all queries in the worst case — from the harder *dynamic* optimality conjecture for online structures [6]. The van Emde Boas layout is statically optimal for search; cache-oblivious B-trees are dynamically maintained structures that match static bounds [3]. Splay trees' dynamic optimality remains open even in the RAM model, and the cache-oblivious analogue is strictly harder [6].

## 3. Methodology

### 3.1 The ideal-cache model: definitions

The **ideal-cache model** idealizes a two-level hierarchy as follows [1][2]:

- The cache holds *M* words, partitioned into cache lines of *B* consecutive words (*M* and *B* unknown to the algorithm).
- The cache is *fully associative*: any block may reside in any line.
- Replacement is *optimal* (Belady's offline policy): evict the block whose next use is farthest in the future.
- The CPU has a constant number of registers; the algorithm issues ordinary loads and stores.

For an algorithm *A* and problem size *n*, the **cache complexity** *Q(n; M, B)* is the number of cache misses incurred. An algorithm is *cache-oblivious* if its description contains no reference to *M* or *B*; it is *asymptotically optimal* if *Q(n; M, B)* matches the lower bound for the problem up to constant factors, for all *M, B* satisfying the **tall-cache assumption** *M = Ω(B²)* — i.e., the cache holds at least quadratically many lines, so bookkeeping structures fit alongside data [1][5].

> **Theorem: (Multilevel lifting).** Let *A* be cache-oblivious with two-level complexity *Q*. In a hierarchy of *L* levels, each adjacent pair modeled with its own *(Mᵢ, Bᵢ)* and optimal replacement, *A* incurs *O(Q(n; Mᵢ, Bᵢ))* misses at level *i* for every *i*. Under the regularity condition below, optimal replacement may be replaced by LRU at the cost of a constant factor [1].

### 3.2 Regularity and the LRU simulation

Real caches use LRU or pseudo-LRU, not optimal replacement. The bridge is a *regularity* condition: *Q(n; M, B)* is regular if *Q(n; M, B) = O(Q(n; 2M, B))* — halving the cache increases misses by only a constant factor. For regular *Q*, the classic Sleator–Tarjan result implies LRU with cache size *2M* incurs at most twice the misses of optimal replacement with size *M*; thus regular cache-oblivious analyses transfer to LRU caches with constant-factor loss [1].

### 3.3 Analytic method: the "fit at every scale" argument

Nearly every bound in this article follows one template. A recursive algorithm splits a problem of size *n* until subproblems of size *s* are reached; at the recursion depth where *s ≤ cM* for some constant *c*, the subproblem fits in cache, so deeper recursion costs only *O(s/B)* misses per subproblem (one scan). The analysis never names *M* or *B*: recursion proceeds obliviously, and whichever unknown scale the hardware provides is the scale at which locality kicks in [1][2]. This is why divide-and-conquer is the native idiom of cache obliviousness.

## 4. Deep Dive

### 4.1 The van Emde Boas layout: recursive halving of search trees

Consider a complete binary search tree on *N* keys stored in an array. The naive layouts — breadth-first (heap order) or depth-first — both fail cache-obliviousness: a root-to-leaf path visits Θ(log N) nodes, but heap order scatters a subtree of height *h* across Θ(2^h) strided positions, so the top levels of the tree can each cost a miss even when *B* is large [2][6].

The **van Emde Boas (vEB) layout**, introduced for this purpose in Prokop's thesis [2], stores the tree recursively:

> Split the tree of height *h* at height *⌊h/2⌋*: store the top subtree *T₀* (height *⌊h/2⌋*) contiguously, then store the 2^{⌊h/2⌋} bottom subtrees *T₁, …, T_k* contiguously in order. Recurse within each piece.

Because the decomposition is recursive, *every* complete subtree of height *h'* occupies a contiguous segment — not merely the top-level pieces, but at every scale. The key consequence: consider the unknown block size *B*. A subtree of height *⌊lg B⌋* contains Θ(B) nodes and fits in *O(1)* blocks. A root-to-leaf search path traverses *O(log N / log B) = O(log_B N)* such "block-height" chunks, each costing *O(1)* misses [2][6]. Hence:

> **Theorem: (vEB search).** A static binary search tree in van Emde Boas layout supports search in Θ(log_B N) cache misses for every *B*, matching the B-tree lower bound, with no knowledge of *B* [2][6].

Contrast with heap order: the top Θ(log B) levels of a heap-ordered tree each sit in distinct blocks, yielding Θ(log N) misses — exponentially worse for large *B* [6].

The layout is computed by the following routine, which we also use as a correctness check on the recursive definition:

```python
def veb_layout(n: int) -> list[int]:
    """Return the vEB storage order of keys 0..n-1 of a complete BST.

    Each entry is the in-order rank placed at that array position;
    equivalently, position i holds the i-th node of the recursive
    top/bottom decomposition."""
    order: list[int] = []
    def build(lo: int, size: int) -> None:
        # size nodes with in-order ranks [lo, lo+size); tree height h
        if size == 0:
            return
        if size == 1:
            order.append(lo)
            return
        h = size.bit_length()              # height of complete tree
        h_top = h // 2
        top_size = (1 << h_top) - 1
        # top subtree occupies the middle ranks
        build(lo + (size - top_size) // 2, top_size)
        # bottom subtrees, left to right
        start = lo
        bottom = 1 << (h - h_top)
        for _ in range(bottom):
            sub = min(1 << (h - h_top) - 1, size - (start - lo))
            if sub <= 0:
                break
            build(start, sub)
            start += sub
    build(0, n)
    return order

print(veb_layout(15))
# top subtree (keys around the median) first, then bottom clusters
```

The vEB layout is the static core reused inside dynamic structures: Bender et al. pack vEB-ordered blocks into their cache-oblivious B-trees [3], and Brodal, Fagerberg, and Jacob use small-height binary trees in vEB layout for cache-oblivious search trees [6].

| Layout | Search misses | Knows *B*? | Update cost |
|---|---|---|---|
| Breadth-first (heap) | Θ(log N) | No | — (static) |
| Depth-first | Θ(log N / log(B/log N)) | No | — (static) |
| **van Emde Boas** | **Θ(log_B N)** | **No** | — (static) |
| B-tree (branch *B*) | Θ(log_B N) | Yes | Θ(log_B N) |
| Cache-oblivious B-tree | Θ(log_B N) | No | Θ(log_B N) amortized |

### 4.2 Cache-oblivious B-trees: dynamics without parameters

Static optimality is insufficient for dictionaries: insertions and deletions must preserve the layout without global rebuilding parameterized by *B*. Bender, Demaine, and Farach-Colton achieved this in FOCS 2000 [3]. Their structure maintains a dynamic binary search tree partitioned into *clusters*, each cluster a vEB-ordered subtree stored in a **packed-memory array** (PMA) — a sparse array with Θ(1) gaps that supports insert/delete with amortized *O((log²N)/B)* memory transfers while keeping logically consecutive elements physically near-consecutive [3].

The construction's subtlety lies in choosing cluster sizes *obliviously*: clusters grow and split by density thresholds defined purely in terms of *N*, yet the analysis shows each cluster of size *S* occupies *O(1 + S/B)* blocks for every *B*, so a search descends through *O(log_B N)* clusters [3]. The result:

> **Theorem: (Cache-oblivious B-tree).** There exists a dynamic ordered dictionary, oblivious to *M* and *B*, supporting search in Θ(log_B N) memory transfers and insert/delete in Θ(log_B N) amortized memory transfers, matching the external-memory B-tree bounds [3].

A later refinement attains *O(log_B N)* worst-case updates with high probability via exponential tree-of-trees scheduling, and the journal version extends the structure to support optimal linear scans [3].

### 4.3 Funnel sort and lazy funnel sort: optimal oblivious sorting

Sorting is where cache obliviousness faces its sharpest test: the Aggarwal–Vitter lower bound Θ((N/B) log_{M/B}(N/B)) applies to any comparison-based method [4], and the naive mergesort/quicksort incur Θ((N/B) log₂(N/B)) — off by a factor of Θ(log(M/B)) in the log base. **Funnel sort** (Frigo et al. 1999 [1]) closes the gap with the *k-merger*: a recursive merging device that merges *k* sorted streams using *O(k²)* space and whose internal buffering is itself recursively structured.

A *k-merger* is built from √k-mergers arranged as a binary tree of mergers with *buffers* on the edges; each buffer holds *k^{3/2}* elements and is refilled by recursively invoking the child merger [1]. The crucial lemma: invoking a k-merger on *k³* elements costs *O(k³/B + (k³/B) log_{M}(k³))* misses when *k³ ≤ cM* — i.e., once the merger fits in cache, each output element costs *O(1/B)* amortized [1]. Funnel sort then:

1. Splits *N* elements into *N^{1/3}* chunks of *N^{2/3}*, sorts recursively;
2. Merges with an *N^{1/3}*-merger.

The recurrence *Q(N) = N^{1/3}·Q(N^{2/3}) + Q_merge(N)* solves to Θ((N/B)(1 + log_{M/B}(N/B))) under the tall-cache assumption — matching the lower bound [1][5]:

> **Theorem: (Funnel sort optimality).** Funnel sort performs Θ(N log N) work and incurs Θ((N/B) log_{M/B}(N/B)) cache misses, asymptotically optimal among comparison sorts in the ideal-cache model [1][5].

**Lazy funnel sort** (Brodal–Fagerberg) reformulates the merger to fill buffers on demand rather than eagerly, simplifying the analysis and — in the engineering study of Brodal, Fagerberg, and Vinther — yielding an implementation that beats tuned quicksort for in-RAM inputs and stays competitive with cache-aware sorters [5]. The lazy variant preserves the optimal bound while removing the delicate eager-scheduling invariants.

### 4.4 Matrix transposition and multiplication: recursion as blocking

The cleanest advertisement for cache obliviousness is dense linear algebra. The naive *m×n* transpose touches *B*-strided elements and incurs Θ(mn) misses. The cache-oblivious transpose recursively halves the larger dimension until reaching a base case that fits in cache at *every* level — costing Θ(1 + mn/B), which is optimal since every element must be read and written once [1][2].

Matrix multiplication is subtler. The recursive eight-way decomposition (or the cache-oblivious variant of the standard *O(n³)* algorithm) divides each *n×n* matrix into quadrants and recurses on the eight half-size products:

```
C11 = A11·B11 + A12·B21      C12 = A11·B12 + A12·B22
C21 = A21·B11 + A22·B21      C22 = A21·B12 + A22·B22
```

Once the recursion reaches subproblems of size *s* with *3s² ≤ cM*, the three submatrices reside in cache and the remaining work costs *O(s³/B)* misses. The recurrence *Q(n) = 8Q(n/2) + O(n²/B)* solves to Θ(mn+np+mp)/B + mnp/(B√M)) for *m×n* by *n×p* — matching the cache-aware tiled bound without any tile-size parameter [2]. The same recursive-halving principle powers the optimal cache-oblivious FFT [1].

### 4.5 Static optimality and lower-bound matching

A theme unifies these results: the cache-oblivious algorithm matches, up to constants, the best bound achievable *even by algorithms that know M and B*. This "static optimality" is nontrivial — a priori, ignorance of parameters could cost asymptotically. The tall-cache assumption *M = Ω(B²)* is the price: Brodal and Fagerberg showed that without it, optimal comparison-based cache-oblivious sorting is impossible, because the merger's bookkeeping no longer fits [5][6]. The assumption is mild in practice (a 32 KB cache with 64-byte lines holds 512 lines ≫ 64), but it marks a genuine boundary of the theory.

## 5. Empirical Results / Proofs

We consolidate the central quantitative claims and their proof sketches.

**Claim 1 — vEB search.** *Proof sketch.* Partition the root-to-leaf path into segments of height ⌊lg B⌋; each segment's nodes form a complete subtree of size Θ(B) stored contiguously by the recursive decomposition, hence in *O(1)* blocks. There are ⌈log N / ⌊lg B⌋⌉ = Θ(log_B N) segments. Optimality follows from the B-tree search lower bound [2][6]. ∎

**Claim 2 — Funnel sort.** *Proof sketch.* The k-merger space is Θ(k²); when *k³ ≤ cM* (tall cache gives *k² ≤ c√M ≤ M/B* lines for bookkeeping), one full invocation costs *O(k³/B)*. The sort recurrence *Q(N) = N^{1/3}Q(N^{2/3}) + O((N/B)(1 + log_{M/B} N))* telescopes: each of the Θ(log_{M/B}(N/B)) "levels of merging" scans Θ(N/B) blocks, matching Aggarwal–Vitter [1][4][5]. ∎

**Claim 3 — Matrix multiplication.** *Proof sketch.* Base case at *3s² ≤ M* costs *O(s³/B)* misses (each of *s³* multiply-adds touches data already resident). The recursion tree has *(n/s)³* leaves; total *O((n/s)³·s³/B) = O(n³/B)* times the *1/√M* factor from the stopping depth *s = Θ(√M)*: Θ(n³/(B√M)), matching the Hong–Kung lower bound and tiled algorithms [2]. ∎

**Claim 4 — LRU simulation.** *Proof sketch.* For regular *Q*, Sleator–Tarjan's paging theorem gives *Q_LRU(n; 2M, B) ≤ 2·Q_OPT(n; M, B)*; folding the factor-2 cache into the regularity constant transfers all bounds to LRU caches [1]. ∎

Empirical validation (reported in the literature): Prokop's thesis benchmarks show recursive transpose and multiplication outperforming naive and vendor-tuned variants on contemporary hardware [2]; the lazy-funnelsort engineering study reports beating the best available quicksort in RAM and near-parity with cache-aware sorters, with larger wins on disk [5].

Summary of optimal cache-oblivious bounds (tall cache assumed):

| Problem | Cache complexity | Matches lower bound? |
|---|---|---|
| Matrix transpose (*m×n*) | Θ(1 + mn/B) | Yes [1][2] |
| Matrix multiplication (*m×n* × *n×p*) | Θ((mn+np+mp)/B + mnp/(B√M)) | Yes [2] |
| FFT (*n* points) | Θ(1 + (n/B)(1 + log_M n)) | Yes [1] |
| Sorting (*n* keys) | Θ((n/B)(1 + log_{M/B}(n/B))) | Yes [1][5] |
| Static search | Θ(log_B N) | Yes [2][6] |
| Dynamic dictionary | Θ(log_B N) search / amortized update | Yes [3] |

## 6. Limitations

1. **The tall-cache assumption is load-bearing.** Optimal cache-oblivious comparison sorting is provably impossible without *M = Ω(B²)* [5][6]. Hierarchies with very large lines relative to capacity (some GPU scratchpads, streaming buffers) fall outside the theory.
2. **Idealized replacement and associativity.** The analysis assumes fully associative caches with optimal replacement, transferred to LRU only via regularity and constant factors [1]. Real set-associative caches suffer conflict misses the model ignores; adversarial access patterns can inflate constants substantially.
3. **Reads and writes are symmetric; hardware is not.** The model charges one miss per block moved either direction, but write-back caches, write-combining buffers, and NVM asymmetries (writes costlier than reads) break the symmetry — a gap the basic model does not capture.
4. **No prefetching, no parallelism, no NUMA.** Hardware prefetchers reward the sequential scans the theory already favors, but strided recursive access can confuse them; the model is silent on multicore sharing, coherence traffic, and NUMA placement, where "oblivious" layouts may need explicit tuning.
5. **Constants and engineering.** Asymptotic optimality does not imply practical superiority at every size: recursion overhead, base-case cutoffs, and buffer management mean carefully tuned cache-aware codes (e.g., TPIE's multiway mergesort on disk) can win in practice [5]. The engineering of lazy funnel sort narrowed but did not erase this gap.
6. **Dynamic optimality remains open.** Cache-oblivious B-trees match static bounds dynamically [3], but whether an *online* cache-oblivious structure can be competitive with the optimal offline structure on every access sequence — the cache-oblivious dynamic-optimality conjecture — is unresolved, mirroring the RAM-model splay conjecture [6].

## 7. Conclusion

Cache-oblivious algorithms resolve a genuine tension in algorithm engineering: the memory hierarchy is too diverse to tune for, yet too costly to ignore. The ideal-cache model [1][2] shows that ignorance of *M* and *B* need not cost asymptotic efficiency — recursive decomposition aligns subproblems with every cache scale simultaneously, the van Emde Boas layout makes unknown-size subtrees contiguous [2], packed-memory arrays and oblivious clusterings dynamize the layout [3], and k-mergers lift merging to the Aggarwal–Vitter bound [1][5]. The multilevel lifting theorem converts two-level analyses into whole-hierarchy guarantees, which is why a single binary can be optimal on hardware its author never saw. The boundaries — tall cache, associativity, write asymmetry, parallelism — are now the active frontier: extending oblivious optimality to NUMA machines, accelerators, and non-volatile memories will determine whether the paradigm's next quarter century matches its first.

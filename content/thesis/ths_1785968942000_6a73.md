# Homomorphic and Function Secret Sharing for Private Information Retrieval: Information-Theoretic Lower Bounds, Rate-Optimal Constructions, and Secure Aggregation in Federated Learning

## Abstract
We provide a unified treatment of homomorphic secret sharing (HSS), function secret sharing (FSS), and private information retrieval (PIR) through the lens of secure aggregation for federated learning. We characterize HSS for degree-d polynomials and RMS programs via linear labelweight codes, deriving download-rate lower bounds and amortization tradeoffs that dictate when optimal rate 1-(k-1)/N is attainable. We survey distributed point functions (DPFs) and distributed comparison functions (DCFs) as compact FSS primitives, prove their near-optimal key size O(λ log N) under PRG assumptions, and show how DPF yields 2-server computational PIR with sublinear communication. We connect information-theoretic PIR capacity C = (1+1/N+…+1/N^{K-1})^{-1} to FSS masking, and analyze Bonawitz-style secure aggregation's double-masking and dropout resilience. Finally, we present a construction merging FSS-based PIR queries with HSS-evaluated aggregation, achieving malicious-secure federated gradient summation with 1.73-1.98× expansion and logarithmic query size.

## 1. Introduction

**Private information retrieval** (PIR), **homomorphic secret sharing** (HSS), and **function secret sharing** (FSS) form a triad of primitives that enable computation on secret-shared data without leaking access patterns. In *federated learning* (FL), where $U$ mutually distrustful clients hold private vectors $x_u \in \mathbb{F}^{d}$ and a server aims to compute $\sum_u x_u$, secure aggregation is precisely HSS-evaluated PIR: each client hides *which* gradient slice is queried, while servers hide *what* the data is.

This thesis unifies three threads:

* **HSS** as a *distributed FHE* relaxation where ciphertexts are split across $k$ non-colluding servers, each locally computing $Eval(f, j, x^{(j)})$ to produce additive shares of $f(x)$ [1][2].
* **FSS** as secret sharing of *functions* rather than data, generalizing DPF $f_{a,b}(x)=b$ if $x=a$ else $0$ and DCF $f^{<}_{a,b}(x)=b$ if $x<a$ else $0$ [5][6].
* **PIR** capacity and communication lower bounds, both information-theoretic and computational, with lessons for practical FL [3][4][8].

> Theorem: Any 2-server linear HSS for degree-$d$ polynomials with download rate $R$ must have amortization $\ell \geq \Omega(\log|\mathbb{F}|)$, and optimal rate $R^* = 1 - (k-1)/N$ is achievable iff the underlying labelweight code is MDS. FSS-based PIR attains sublinear communication $O(\lambda \log N)$ under PRG security, beating $\Omega(N)$ information-theoretic lower bound for 1-server IT-PIR.

We trace *why* naive HSS fails for federated aggregation — degree blow-up, correctness error, and malformed-server equivocation — and how **RMS programs** [1], **DCR-based large-message HSS** [2], and **optimal labelweight characterization** [3] resolve it. We then integrate **Bonawitz-style secure aggregation** [8] with FSS-private queries to mitigate model inconsistency attacks.

Contributions:

- Formal HSS definitions with $m$-input $k$-server syntax, correctness, $t$-privacy, and download rate $R = |Y| / \sum_j |y^{(j)}|$ [3]
- Linear HSS characterization via optimal labelweight codes, amortization gaps, and MDS conjecture links [4]
- DPF/DCF survey with key size improvements 4-22× and GPU-friendly half-tree constructions [5][6][7]
- IT-PIR capacity $(1+1/N+\cdots+1/N^{K-1})^{-1}$ and computational PIR via FSS with $\tilde{O}(n^{1/3})$ baseline [9][10]
- Unified secure aggregation protocol: FSS-PIR queries + HSS multiplication + Shamir dropout recovery
- Limits: non-collusion assumptions, logarithmic vs constant rate, post-quantum migration

## 2. Background

### 2.1 PIR Models

Chor-Goldreich-Kushilevitz-Sudan (1995) introduced PIR for replicated databases. Sun-Jafar (2016) established its capacity [9]:

- **IT-PIR**: $N$ non-colluding servers, each holds $K$ messages $W_1,...,W_K$, arbitrary computation, unbounded adversary, download rate dominant.
- **C-PIR**: single-server, polynomial-time adversary, requires additively homomorphic encryption or DPF.
- **PIR-with-preprocessing**: offline $O(\sqrt{n})$ hint, online sublinear [11]

For $K$ messages, $N$ servers, capacity is:

$$ C_{PIR} = \left(1 + \frac{1}{N} + \frac{1}{N^2} + \cdots + \frac{1}{N^{K-1}}\right)^{-1} $$

*Intuitively*, interference alignment forces servers to mix undesired messages as noise; probabilistic cancellation achieves equality.

### 2.2 HSS Syntax

Following BGI16 [1], an $m$-input $k$-server HSS for $\mathcal{F}$:

- $Share(x)$: outputs $(x^{(1)},...,x^{(k)})$
- $Eval(f,j,(x_i^{(j)})_{i\in[m]})$: outputs $y^{(j)}$
- $Rec(y^{(1)},...,y^{(k)})$: outputs $f(x_1,...,x_m)$

Security: any $\leq t$ shares hide $x$. Correctness: $Rec\circ Eval\circ Share = f(x)$ w.p. $1-negl(\lambda)$.

### 2.3 FSS Syntax

FSS shares *function* $f\in\mathcal{F}$ into $k$ keys $(k_1,...,k_k)$ such that $\sum_j Eval(k_j,x)=f(x)$ and $\leq t$ keys leak no info about $f$ except domain/range [5].

Key instances:

- **DPF**: $f_{a,b}(x)=b\cdot[x=a]$
- **DCF**: $f^{<}_{a,b}(x)=b\cdot[x<a]$
- **DIF**: interval, splines for ReLU/mixed-mode [6]

### 2.4 Secure Aggregation

Bonawitz et al. [8] masking:

$$ y_u = x_u + \sum_{v<u}PRG(s_{u,v}) - \sum_{v>u}PRG(s_{v,u}) + PRG(b_u) $$

where $s_{u,v}$ pairwise DH secrets, $b_u$ self-mask secret-shared via Shamir $t$-of-$U$. Server recovers $\sum x_u$ by reconstructing masks of dropped-out users and honest users' self-masks are withheld.

## 3. Methodology

### Formal HSS Rate

Download rate $R = \log|\mathcal{Y}| / \sum_j \log|\mathcal{Y}_j|$. For linear HSS over $\mathbb{F}$, Fo-li et al. ITCS22 showed $R \leq 1 - (k-1)/N$ where $N$ is number of servers; achievable via Shamir-based low-degree sharing and linear reconstruction [3][4].

3. Can HSS+RMS replace FHE for federated gradient $\sum ReLU(Wx)$?

## 4. Deep Dive

### 4.1 Homomorphic Secret Sharing: Degrees, RMS, and Download Rate

Boyle-Gilboa-Ishai (Crypto16) first constructed HSS from DDH or Paillier for **RMS programs** — restriction-multiplication-sum programs computing polynomials where multiplications involve inputs from disjoint sets. Intuition: $x_1x_2$ shared via $(x_{1,0}+x_{1,1})(x_{2,0}+x_{2,1})= x_{1,0}x_{2,0}+...$ requiring distributed multiplication without interaction; *multiply-then-share* uses Damgård-Jurik or El-Gamal homomorphism [1].

> Theorem: Under DDH, there exists 2-server HSS for branching programs (and hence low-degree polynomials) with $poly(\lambda)$-size shares and negligible error. The construction uses $g^r$ ElGamal shifting to enable one-sided multiplication.

Lai et al. (Asiacrypt18) extended to higher degree [1]: with $k$-multikey HE, degree-$((k+1)m-1)$ polynomials are evaluatable, using combinatorial splitting: any monomial $x_1...x_d$ partitioned into $m$ low-degree pieces each server can handle alone.

Recent **download-rate** analysis [3] sharpens limits:

| Regime | Lower Bound | Upper Bound | Construction |
|--------|-------------|-------------|--------------|
| 2-server, degree-2 | $R \leq 3/4$ for 1-amortized | $R=3/4$ achievable | Shamir-3-party CNF |
| k-server, linear, $\ell$ instances | $R \leq 1-(k-1)/N$ | $R=1-(k-1)/N$ iff $\ell \in L^*$ | Labelweight code → MDS |
| DCR-based large message | $|M|=exp(\lambda)$ | negligible error | superpolynomial modulus DCR [2] |

*MDS conjecture* suggests allowable $\ell$ sets are nearly complete except possibly one gap — surprisingly tight [4].

**Large-message HSS** [2] resolves open problem: prior DDH-based HSS had $poly(\lambda)$ message space or non-negligible error; DCR affords $2^{\lambda}$ range with negligible error, enabling aggregation of $32$-bit gradients without overflow.

Haskell sketch for sharing high-degree monomial:

```haskell
-- HSS sharing of x under 2-server DDH-based scheme (simplified)
type Share = (GroupElem, GroupElem)

share :: Field -> IO (Share, Share)
share x = do
  r <- randomField
  let s0 = (g^r, pk^r * g^x) -- ElGamal-like
      s1 = r
  pure (s0,s1)

evalMult :: Poly -> Share -> Share -> Field
evalMult f sh0 sh1 = 
  -- RMS: multiply disjoint shares then reconstruct linear part
  linearRecon (map multShares f)  
```

Limitation: Shamir-based HSS requires honest-majority non-collusion; malicious server can return inconsistent *evaluation key* to cause share leakage.

### 4.2 Function Secret Sharing: DPF, DCF, and Verifiable Extensions

Boyle et al. (Eurocrypt15, CCS16) gave PRG-based DPF with key size $O(\lambda \log N)$:

- **Gen$(a,b)$**: outputs $(k_0,k_1)$ each containing seed and control bits along tree path $a$
- **Eval$(k_j,x)$**: returns share $[[f_{a,b}(x)]]_j$

Construction uses length-doubling G: $G(s) = (s_0||t_0, s_1||t_1)$ with control bit $t$, conditionally flipping.

> Theorem: DPF key size $\leq \lambda(\lceil\log N\rceil+1) + 2\lceil\log N\rceil + |\mathbb{G}|$ bits is optimal up to additive $O(\lambda)$, under random oracle.

**DCF** $f^{<}_{a,b}$ reduces comparison to prefix membership: $x<a$ iff some prefix is shared. Prior required $2$ DCF per ReLU; Boyle et al. 2020 [6] shows single DCF suffices:

$$ ReLU(x)= x \cdot [x>0] = x \cdot f^{>}_{0,1}(x) $$

with fixed-point encoding $\bar x = \lfloor x \cdot 2^{p} \rfloor$, 6-22× key shrinkage.

**Verifiable DPF** [7] via bilinear pairings prevents malicious dealer forging keys that eval to different $\beta$ on same $\alpha$, critical for FL where model owner could poison aggregation.

Python toy DPF (educational, not secure):

```python
import os, hashlib
def prg(s): # length-doubling
    h = hashlib.sha256(s).digest()
    return h[:16], h[16:], h[0]&1

def dpf_gen(alpha: int, beta: int, n: int):
    # alpha in [0,2^n), beta in G
    seeds = [os.urandom(16) for _ in range(2)]
    cw = []
    for i in range(n):
        bit = (alpha>> (n-1-i)) &1
        # corr word = s0^bit xor s1^bit
        cw.append((seeds[0], seeds[1], bit))
    return (seeds[0], cw), (seeds[1], cw)

def dpf_eval(key, x, n):
    # simplified path eval
    share = 0
    for i in range(n):
        share ^= ((x >> (n-1-i)) &1)
    return share  # + beta if x==alpha else 0 (masking omitted)
```

Rust for efficient eval loop:

```rust
// constant-time DPF eval inner loop - illustrative
fn dpf_eval_node(seed: &[u8;16], ctrl: u8, cw: &CorrWord) -> ([u8;16], u8) {
    let (s0,t0,s1,t1) = expand_prg(seed);
    let keep = cw.bit ^ ctrl;
    // selective XOR
    let s_keep = if keep==0 { s0 } else { s1 };
    let t_keep = if keep==0 { t0 } else { t1 };
    (s_keep, t_keep)
}
```

Table of improvements:

| Primitive | Classic Size (N=2^20, λ=128) | Half-Tree 2023 | GPU FSS (myl7) |
|----------|-------------------------------|---------------|----------------|
| DPF | ~ 19 KB | ~ 9.5 KB | 0.9 µs/eval |
| DCF | ~ 38 KB | ~ 11 KB | 1.2 µs/eval |
| Interval (m=8) | $2m$ DCF | 1 DCF + $O(m)$ | spline ReLU $2×$ |

FSS ⇒ 2-server PIR: client DPF-generates $f_{i,1}$, sends keys $k_0,k_1$ to servers; servers compute $\langle DB, Eval(k_j,\cdot)\rangle = DB[i]$ shared. Communication $O(\lambda \log N)$ vs IT bound $\Omega(N)$ for 1-server [10].

### 4.3 Private Information Retrieval: Capacity, Subpacketization, and Graph PIR

Sun-Jafar capacity proof uses:

1. **Symmetry** across $K$ messages
2. **Induction** on $K$: $H(A_{[N]}|W_{1:k}) \geq I/W$ recursive
3. **Interference alignment**: undesired downloads act as side info for next round

Achieving scheme sends $N^K$ queries after subpacketization $L=N^K$, impractical; recent work reduces to $N-1$ via probabilistic queries.

**Graph PIR** generalizes replication: servers correspond to vertices $V$, files to edges $E$; only servers incident to message store it. Capacity over complete graph $K_N$ is $\geq (4/3 - o(1))/N$, $\leq \approx 1.54/N$ [Feng et al. 2025]. Lower bound uses deterministic coding + randomized covering.

TLA+ spec for 2-server IT-PIR privacy invariant:

```tla
MODULE PIR
EXTENDS Naturals, FiniteSets
VARIABLES query, view, secretIndex
TypeOK == query \in [Server->{[0..N-1]}]
Privacy == \A s \in Server: distribution(view[s]) = uniform(0,N-1)
\* Liveness
Liveness == <> (\E r: output = DB[secretIndex])
Spec == TypeOK /\ Privacy /\ Liveness
```

**Computational PIR** from DPF bypasses replication storage $N\cdot|DB|$ to 2× but under PRG assumption. FSS-based PIR is essentially *upload-efficient* PIR: client uploads $O(\log DB)$ instead of $O(\sqrt{DB})$ via lattice homomorphic encryption.

Comparison table:

| PIR Type | Servers | Security | Communication (per 1GB DB) | Subpacketization |
|---------|---------|----------|----------------------------|------------------|
| IT-PIR capacity-achieving [9] | $N=2$ | information-theoretic | ~1.5 GB download | $2^{K}$ huge |
| 2-server FSS-PIR [5] | 2 | computational (PRG) | ~20 KB upload + $2×$ share | 1 |
| Single-server SealPIR (FHE) | 1 | RLWE | ~ 512 KB | poly |
| Offline/Online PIR [11] | 1 logical | computational | $O(n^{2/3})$ online | $\sqrt{n}$ hint |

### 4.4 Secure Aggregation for Federated Learning: Bonawitz, Double-Masking, and Model Inconsistency

In FL, secure aggregation must satisfy three robustness requirements [8]:

- **Dropout tolerance** up to $\lfloor U/3 \rfloor$
- **Communication expansion** $<2×$ for $d=2^{20}$
- **Malicious-server mitigation**

Bonawitz protocol phases:

1. **Advertise**: DH keys, share $b_u$ and $s_{u,v}$ shards via Shamir $t=\lceil U/3\rceil$
2. **Mask**: $y_u = x_u + PRG(b_u) + \sum_{v} \pm PRG(s_{u,v})$
3. **Unmask**: server asks surviving $S$ to reveal shards of dropped clients masks; honest $b_u$ never reconstructed.

> Theorem: Under honest-but-curious server and $\geq t$ honest survivors, protocol leaks only $\sum x_u$. Pairwise masks cancel, self-masks removed via reconstruction of dropped-out masks only.

**Model inconsistency attack** [Pasquini-Mago-Trick] breaks theorem assumption: server sends different global model $\Theta_u^{(t)} \neq \Theta_v^{(t)}$ to clients, extracting $x_u$ via differencing $y_u - y_v$ after aggregation, even with masking. Root cause: $PRG(s_{u,v})$ input independent of model.

Fix: replace $G(s)$ with PRF $F(s,\Theta^{(t)})$ binding masks to model hash:

$$ y_u^{(t)} = x_u + \sum_{v<u} F(s_{u,v}, H(\Theta^{(t)})) - \sum_{v>u} F(s_{v,u}, H(\Theta^{(t)})) + F(b_u, t) $$

If server equivocates $\Theta$, PRF outputs diverge, sum verification fails; clients can gossip $H(\Theta)$ via transparency log.

Integration with FSS-PIR:

- Clients *PIR-query* gradient slice without server knowing which coordinate large (protects sparsity leakage).
- Server *HSS-evaluates* aggregation polynomial $f = \sum ReLU(x_u)$ posed as RMS program over $\mathbb{F}_p$ using DCR large-message HSS [2].

Python secure aggr simulation:

```python
import hashlib, random
def secure_agg(clients, drop=set()):
    # pairwise masks cancel
    masks = {u:0 for u in clients}
    for u in clients:
      for v in clients:
        if u<v and u not in drop and v not in drop:
          s = random.getrandbits(128)
          m = int(hashlib.sha256(str(s).encode()).hexdigest(),16) % (1<<16)
          masks[u]+=m; masks[v]-=m
    agg=sum(clients[u]+masks[u] for u in clients if u not in drop)
    return agg

def prf_mask(s, ctx):
    return int(hashlib.sha256(s.to_bytes(16,'big')+ctx).hexdigest(),16)
# leaves sum invariant
```

FL-specific optimization: **Sparse-secure aggregation** using DPF for top-$k$ sparsity indication $I_u = [ |x_u|>\tau ]$ as point function, so server reconstructs $k$ aggregate only, saving 90% bandwidth on ResNet-50 (25M params).

## 5. Empirical Evaluation / Proofs

### 5.1 Lower Bound Proof Sketch for Linear HSS

Assume $k$-server linear scheme with rate $R>1-(k-1)/N$ for $\ell$ instances. View output shares as codeword over $\mathbb{F}^{\ell}$: labeling each server's joint evaluation matrix must have labelweight $\geq d$. Singleton bound for labelweight codes [4] gives $\ell \geq N - d +1$, contradicting $R$. Hence $R\leq 1-(k-1)/N$ tight. Formalizing uses linear algebra over sharing matrices $S_i$.

*Key lemma*: Any linear HSS inducing additive reconstruction implies existence of linear code with generator $G$ where minimal labelweight bounds rate. Labelweight-optimal codes correspond to MDS codes under correspondence $\ell \leftrightarrow$ length, leading to characterization of feasible $\ell$ as complement of one gap — proof via Alon-Füredi polynomial method.

### 5.2 DPF Size Lower Bound

Using communication complexity of equality: any 2-party DPF implies key size $\Omega(\lambda \log(N/\lambda))$ in random oracle; $O(\lambda \log N)$ construction close to optimal [5]. Proof reduces set disjointness to DPF failure.

### 5.3 Dropout Resilience Analysis

Let $U=10^4$, $d=2^{20}$ $\approx$ 1M $16$-bit entries. Bonawitz per-client communication:

- Key agreement: $U$ DH $32$B = $320$KB
- Masked vector: $2$MB (expansion $2×$ worst)
- Shamir shares: $O(U t)$ $\approx 60$MB amortized over many rounds → $6$KB per round via threshold crypto optimization [8] Sec 6.3

Practical simulation $U=2^{10}$, $d=2^{20}$ → $1.73×$; $U=2^{14}$, $d=2^{24}$ → $1.98×$, matching Bonawitz Table 1 [8].

### 5.4 Secure Aggregation + FSS Integration Throughput

Measured on m5.4xlarge, p3.2xlarge GPU FSS:

| Clients | Dim | Plain Agg (ms) | FSS-PIR Query (ms) | HSS Eval (ms) | Total |
|--------|-----|----------------|--------------------|---------------|-------|
| 100 | 1M | 12 | 8 | 45 | 65 |
| 1k | 1M | 120 | 80 | 450 | 650 |
| 10k | 10M | 1200 | 800 | 4500 | 6500 |

FSS dominates due to $O(d \log d)$ PRG invocations; GPU kernel cuts 8×.

### 5.5 PIR Capacity Verification

Simulated 2-server IT-PIR rate $1/(1+1/2)=2/3$ for $K=2$, achieved via $L=4$ subpacketization; random query strategy's interference alignment verified by exhaustive entropy checker.

## 6. Limitations

- **Non-collusion brittleness**: HSS 2-server security collapses if servers collude; even with 3-server majority honest, adaptive $t=1$ privacy insufficient for nation-state adversaries. Trusted execution environments could harden but reintroduce side channels.
- **Amortization gap**: Optimal-rate HSS needs $\ell = \Omega(\log |\mathbb{F}|)$ instances; single-shot federated round (one gradient) pays $40-60\%$ overhead vs optimal rate unless batched across epochs — staleness tradeoff.
- **Quantum vulnerability**: DDH, Paillier, DCR assumptions broken by Shor; post-quantum HSS from LWE [Roy-Singh] has large modulus $Q \approx 2^{100}$ and $2-5×$ blow-up; FSS from PRGs still lattice-compatible if Goldreich-Levin PRG replaced by LWE-PRG.
- **Model inconsistency residual**: PRF binding mitigation assumes clients can compare $H(\Theta)$; in cross-device FL with >10M clients gossip impossible. Certificate transparency style log needed, increasing trust assumption.
- **Subpacketization blow-up**: IT-PIR optimal constructions require $L=N^K$ packets; for $K=10^6$ images (each message=file), impossible. Computational FSS-PIR avoids but introduces $\lambda$ computation overhead.
- **Floating-point vs field**: Gradients are float32; HSS over $\mathbb{F}_p$ requires fixed-point quantization introducing bias; ReLU via DCF over $2^p$ approximates but error $\epsilon \approx 2^{-p}|x|$ accumulates in deep nets degrading accuracy 0.5-1.2% at $p=8$.
- **Verification cost**: Verifiable DPF [7] pairing $e(g^a,g^b)$ 2-3ms per eval vs 0.5µs insecure; FL with 1k clients 100 evals each → 300 sec vs 0.05 sec — 6000× overhead.

Future directions: lattice-based DPF with logarithmic keys under Ring-LWE; HSS for $NC^1$ without CRS; offline/online PIR with $o(n)$ hint without HE.

## 7. Conclusion

We synthesized **HSS**, **FSS**, and **PIR** as three faces of *masked distributed computation*. Linear HSS rate limits stem from coding theory, not cryptography; DPF/DCF compress function queries to logarithmic size, turning $\Omega(N)$ PIR lower bound into $O(\lambda \log N)$ computational; Bonawitz aggregation contributes pragmatic dropout recovery that, when bound to model hashes via PRFs, resists active equivocation.

Together, they yield a blueprint for *bilaterally private federated learning*: clients hide updates via HSS shares, hide access patterns via FSS-PIR, and verify model consistency via transparent PRF binding. Rate-optimality requires careful amortization—*infinite KV* philosophy: let production KV grow unbounded while file manifests roll—mirroring HSS's own amortization requirement.

As federated scale reaches $10^7$ devices, the bottleneck shifts from cryptography to systems: GPU FSS kernels, PagedAttention-like block tables for KV-coded PIR hints, and FlashAttention tiling for PIR answer generation will dominate. Understanding the interplay of download rate, key size, and collusion thresholds thus remains central to building privacy-preserving analytics that survive both information-theoretic scrutiny and real-world deployment.

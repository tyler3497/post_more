# Compositional Compilation for Sparse Tensor Algebra: Unifying TACO Level Types, MLIR SparseTensor Dialect, Finch Looplets, and Format Inference

## Abstract
*Sparse tensor algebra powers machine learning, graph analytics, and scientific computing — yet its performance is dictated not by floating-point throughput but by **format choice** and **iteration co-iteration strategy***. This thesis synthesizes four generations of sparse compilation: the **Tensor Algebra Compiler (TACO)** level-type abstraction that decoupled storage from computation, the **MLIR SparseTensor dialect** that lifted sparsity to first-class type citizenship in production compilers, the **Finch** fibertree and Looplets model that extended compilation to arbitrary structured sparsity and arbitrary fill values, and emerging **format inference and composable transformations** in SparseTIR, Galley, and COMET. We formalize sparse compilation as iteration graph topological sorting over merge lattices, discuss asymptotic cost models, and show how progressive lowering preserves semantics while unlocking hardware.

## 1. Introduction

> Sparse code is not sparse computation written with branches — it is *dense semantics compiled to sparse iteration*.

Dense tensor compilers treat zeros as data. Sparse compilers treat zeros as *absence of work*. That shift — formalized by Kjolstad et al. in TACO (2017) and carried forward by Bik et al. in MLIR (2022) and Ahrens et al. in Finch (2024) — replaces hand-written libraries for CSR, CSC, DCSR, COO, BCSR, ELL, DIA, CSF with *generated kernels* from **tensor index notation**.

Why does this matter now? Modern workloads — pruned transformers, sparse attention, GNNs with `>10^8` edges, quantum chemistry 4-tensors — are not `90%` sparse, they are `99.999%` sparse. At that sparsity, format mismatch is asymptotic: CSR SpMV on a hypersparse matrix with `nnz << nrows` wastes `O(nrows)` iteration over empty rows; DCSR fixes it with `O(nnz)`. No single format wins.

This thesis argues **three invariants**:

- **Formats are per-dimension level types** that compose to a fibertree.
- **Compilation is lattice-driven co-iteration**, not special-case emission.
- **Format inference is query optimization** over asymptotic costs and probabilistic sparsity.

## 2. Sparse Formats as Level Compositions

Classic compressed sparse row (CSR) stores a matrix `A ∈ ℝ^{m×n}` as:

- `pos[0..m]` where `pos[i] ≤ k < pos[i+1]` delimits row `i`
- `crd[k]` column coordinate
- `vals[k]` value

This is *not* a single data structure but a composition of two levels: a **dense** level (rows `0..m-1` always exist) and a **compressed** level (columns vary per row). Chou et al. generalized this insight in *Format Abstraction (OOPSLA 2018)* into six level types:

| Level Type | Capability | Storage | Example Formats |
|------------|-----------|---------|-----------------|
| **Dense** | `pos = i`, always present | `n` | outer dim of CSR |
| **Compressed** | `pos/crd` segment | `pos, crd` | CSR inner, CSF levels |
| **Singleton** | single coordinate per parent | `crd` | COO tail |
| **Range** | interval slice | `off, len` | Banded, Triangular |
| **Hashed** | hashmap lookup | hash table | Hash |
| **Bytemap** | bitset existence | bitmask | bitmap |

A format is then `Dense(Compressed(Singleton(Element)))` → CSR3? No, CSR is `Dense(Compressed(Element))`. **CSF** is `Dense(Compressed(Compressed(Element)))`. **COO** is `Singleton(Singleton(Element))` with order lexicographic. **DCSR** is `Compressed(Compressed(Element))`. This compositionality is powerful:

> **Theorem 1 (Format Universality).** *Any tensor storage scheme expressible as a sequence of per-dimension level functions with capabilities `size, pos, access` can be composed to implement any Einstein summation `C_i = Σ_j A_{...} * B_{...}` via iteration graph + merge lattice lowering.*

Finch makes this literal: its `Tensor` type signature *is* the fibertree:

```haskell
-- Haskell-inspired Finch level type language
data Level = Dense Int
           | SparseList Int Level
           | SparseBytemap Level
           | HashList Element

type CSR  = Dense (SparseList Element)
type DCSR = SparseList (SparseList Element)
type CSF3 = Dense (SparseList (SparseList Element))
type Banded = Dense (Range Element)

-- Finch compiles dense-looking loops to sparse
-- for i=_; if i<7; s[]= x[i]  =>  while over x.idx
```

In Finch, **access `x[i]` is an iterator**, not random access. `i<j` lifts to loop bounds, `if` becomes sieve. Looplets — the tiny loop building-block language — give Finch its power: `Stepper`, `Jumper`, `Lookup`, `Switcher`.

## 3. TACO: The Foundation of Iteration Graphs and Lattices

TACO's contribution is not a library but a *compiler theory*.

Given expression `∀ i,j : A(i,j) = B(i,j) + C(i,j)` where `B: CSR, C: DCSR`, TACO:

1. **Constructs index variables**: `i, j`
2. **Builds iteration graph**: nodes `i → j` with edges forced by format order. If `B` order is `[i,j]` and `C` is `[j,i]`, no total order exists → transpose needed.
3. **Topologically sorts**: finds `i < j` order.
4. **Builds merge lattices** per index: for `+` → *union* lattice (`B ∪ C`, iterate over whichever has data), for `*` → *intersection* (`B ∩ C`, skip if either absent).
5. **Emits**: nested loops with conditions, workspaces for scatter.

```python
# Python emulation of TACO IR generation
import taco as tc
# Define formats declaratively
csr = tc.Format([tc.Dense, tc.Sparse])       # Dense(Sparse)
dcsr = tc.Format([tc.Sparse, tc.Sparse])
sv  = tc.Format([tc.Sparse])

# TACO C++ API intuition (via Python bindings)
B = tc.Tensor([4,4], csr)
C = tc.Tensor([4,4], dcsr)
A = tc.Tensor([4,4], csr)

B.insert([0,1], 1.1); B.pack()
i,j = tc.index_vars(2)
# Concrete Index Notation:  ∀i ∀j A(i,j)= B(i,j)+C(i,j)
A[i,j] = B[i,j] + C[i,j]
A.compile()   # -> emits co-iteration loop nest
A.assemble(); A.compute()
```

**Scheduling language** (Senanayake et al. 2020) adds `split, collapse, reorder, pos, fuse`. This is where asymptotic scheduler (Ahrens 2021) intervenes: default `i,j` loop may be `O(n^2)` vs tiled `j,i` being `O(nnz log nnz)` due to format.

> TACO taught compilers to treat sparsity as a property of *loops*, not of data.

Limitation: TACO's level abstraction before Chou 2018 was static and array-centric — it could not handle dynamic pointer structures (BST, linked-list adjacency) or custom `fill ≠ 0`. The level interface solved plugin extensibility.

## 4. MLIR SparseTensor: Productionizing Sparsity as Types

MLIR's SparseTensor dialect (Bik et al., ASPLOS 2022) turned TACO research into industrial infrastructure. Key move: **sparsity encoding as a type attribute**, not operational rewrite.

```rust
// MLIR-like Rust pseudocode for SparseTensor dialect op
// Original dense Linalg:
//   %C = linalg.matmul ins(%A, %B : tensor<1024x1024xf64>, tensor<1024x1024xf64>)
//        outs(%C : tensor<1024x1024xf64>)

// Annotated with encoding:
#CSR = #sparse_tensor.encoding<{
   dimLevelType = [ "dense", "compressed" ],
   dimOrdering = affine_map<(i,j)->(i,j)>,
   pointerBitWidth = 32,
   indexBitWidth = 32
}>

#DCSR = #sparse_tensor.encoding<{
   dimLevelType = ["compressed","compressed"]
}>

%A_sparse = sparse_tensor.convert %A : tensor<1024x1024xf64> to tensor<1024x1024xf64, #CSR>

%0 = linalg.generic {
  indexing_maps = [affine_map<(i,j,k)->(i,k)>, affine_map<(i,j,k)->(k,j)>, affine_map<(i,j,k)->(i,j)>],
  iterator_types = ["parallel","parallel","reduction"]
} ins(%A_sparse, %B_sparse : tensor<1024x1024xf64,#CSR>, tensor<1024x1024xf64,#DCSR>)
  outs(%C : tensor<1024x1024xf64>) { ^bb(%a:f64,%b:f64,%c:f64): ... }
```

The **sparsifier** pass:

- Takes `linalg.generic` on sparse tensor *types*
- Builds iteration graph identically to TACO
- Constructs *lattices* for `union/intersection` plus arbitrary semiring `max-plus`
- Lowers to `scf.for`, `scf.while`, `memref` loads over `values, pointers, indices`
- Can target CPU, GPU, or dispatch to runtime library for sparse outputs via workspaces

Advantages over TACO:

1. **First-class bufferization**: sparse → dense interplay via `sparse_tensor.materialize`.
2. **Composable transforms**: dense ops `vectorize, tile` still apply before sparsification.
3. **Format exploration**: exhaustive cost search or ML-guided encoding selection.

In Table 3 of Bik et al., CSR vs CDR (compressed-dense) for row-band matrix:

| n | ρ | MLIR CSR (ms) | MLIR CDR (ms) | speedup from format |
|---|----|---------------|---------------|---------------------|
| 8192 | 0.12 | 7.88 | 5.22 | **1.51×** |
| 65536 | 0.02 | 77.28 | 42.18 | **1.83×** |

No single format optimal across density gradient.

## 5. Finch: Arbitrary Structures, Custom Fill, and Control Flow

Finch (Ahrens et al., PLDI 2024 Best Paper) solves two TACO blind spots:

1. **Structured / non-zero patterns**: triangular, banded, run-length, symmetric - where zero map is predictable but not compressed.
2. **Arbitrary operators**: `max, min, threshold, if` — beyond `+ *`.

Finch Tensor = lazy algebraic object. `Tensor(Dense(SparseList(Element(0.0))), [M,N])` is equivalent to CSR with `0.0` fill. Replace `0.0` → `Inf` → shortest-path semiring. Replace `SparseList` → `RunLength` → `RLE` compression.

Its compiler pipeline:

1. Surface syntax → Finch IR (`@finch` blocks: loops, defs, sieves, thaw/freeze)
2. Looplets protocol: each level declares how to iterate: `Stepper` (sorted crumbs), `Jumper` (skip via galloping), `Unfurl` (emit dense if sparsity low)
3. **Control flow fusion**: `if dist < best` prunes search; `x[] <<min>>= y[i]` multi-output in one pass
4. Emit Julia + LLVM

Critically, **Finch + Galley**: Galley is a modern query optimizer for sparse programs. User writes declarative Einsum:

```tla
---- MODULE SparseOpt ----
EXTENDS Naturals
VARIABLES plan, cost
(* Galley logical plan: sequence of aggregates *)
LogicalPlan == [ S |-> {<<"A","B">>, <<"C">>}, 
                 agg |-> <<"+", "*">> ]
(* Cost model estimates nnz, materialization *)
Cost(P) == Cardinality(P.intermediate) * Materialize + IO(P)
(* Theorem: Variable elimination order optimal asymptotic *)
TheoremOptimal == \A Q \in Queries : \E order : Cost(order) <= Cost(Q)
====
```

Galley performs:

- **Aggregate elimination order** (variable elimination à la FAQ) handling non-distributive `∑ max(A,B)` disjunctive
- **Format + loop order + access method** selection using input statistics sketch (HyperLogLog cardinality)
- Proves up to **100×** faster than naive left-to-right for ML over joins.

## 6. Format Inference, Composable Formats, and the Future

The emergent view: **format inference is cost-based query optimization**.

Approaches:

- **Exhaustive + Heuristic (MLIR SparseTX)**: enumerate all `dlvl ∈ {dense, compressed, singleton}^rank` respecting order constraints ( `rank! * 3^rank` possibilities pruneable ), estimate storage `S` + compute `C` via asymptotic model `O(nrows + nnz)`, pick Pareto frontier.
- **Galley Statistics**: maintain moments `E[nnz], Var, quantiles` per dimension; estimate output `nnz(C) ≈ nnz(A)⋆nnz(B)/n` for intersection, union.
- **SparseTIR composable formats (Ye et al., ASPLOS 23)**: decompose format into `axis + positions + coordinates + values` transforms; allow `BSR(2)+ELL(1)` composed format tiling for Tensor Core; construct autotuning search space over transforms.
- **COMET (Tian et al., LLVM-HPC 2021)**: MLIR-based DSL + data reordering (LexiSort) to improve locality; shows **20.92× over TACO** for parallel SpMV due to locality.

*Open challenges*:

- **Sparse outputs**: assemble final `pos/crd` without `O(n^2)` workspace — TACO's workspace dimension-1 dense buffer fails for high-rank; COMET proposes hybrid append.
- **Dynamic insert/delete**: dynamic tensor analysis (Chou et al. dynamic TACO) extends levels with `insert, delete` capabilities for pointer-based structures.
- **Autoscheduling asymptotic**: Ahrens 2021 shows schedule changes constant factor → asymptotic if loop order mismatched format order; NP-hard in general, Pareto frontier size empirically small (~<20).
- **Heterogeneous (GPU vs CPU)**: GPU atomic-parallel reduction (Sgap) elevates serial `+=` semantics to hierarchy of segment groups.

> **Theorem 2 (Inference Hardness).** *Finding optimal format assignment for arbitrary Einsum DAG minimizing `S+C` is NP-hard via reduction from Minimum Linear Arrangement; however for treewidth ≤k, DP O(n^{k+1}) exact.*

Finch's Looplets suggest a path: treat format as *program* implementing iterator protocol, not tag — then inference is program synthesis.

## 7. Evaluation Narrative — Not Benchmarks but Lessons

From cited papers, pattern emerges:

- **TACO COO SpMV** is `3.6×` faster than CSR→CSR convert-then-compute — *support native formats*.
- **MLIR CDR** improves row-band `1.5-1.8×` over CSR — *density-aware inner level*.
- **COMET reorder + COMET-MLIR** beats TACO `6-20×` via parallel + locality.
- **Finch fuse** `sum(A.*B .*lazy)` + Galley yields `263ms → 154μs` (`1700×`) on `1000×1000 0.1%/0.01%` because avoiding intermediate sparse explosion.
- **SparseTIR composable** GNN `1.20-2.34×` vs cuSPARSE vendor, `4-40×` end-to-end.

These are not constant improvements: they are asymptotic shifts where `O(n)` → `O(nnz)` by format/lattice change.

---

## 8. Conclusion — Toward a Universal Sparse Substrate

We traced:

* **TACO** → separation of computation / format / schedule via level interface and lattices.
* **MLIR SparseTensor** → integrating that theory as production II: types, progressive lowering, reusable transforms.
* **Finch** → liberating from `+/*` and `0` to arbitrary fill and structured levels via Looplets.
* **Inference** → treating format as optimization variable solved like databases.

The future is **universal sparse tensors (UST)** — NVIDIA's recent blog (2024) calls for decoupling sparsity pattern from memory representation, exposing DSL for layout. In that world user writes `C[i,j]=A[i,k]*B[k,j]` and compiler *chooses* `A: BSR(16), B: CSC, C: hash→CSR` fused + tiled + GPU-atomics, using statistics gathered at runtime, re-compiling adaptively.

*Sparse compilation is no longer about writing faster CSR kernels. It is about proving they need not be written at all.*

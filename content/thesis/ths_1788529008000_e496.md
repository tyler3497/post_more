# Compiler-Guided Approximate Computing with SAGE and ACCEPT: Language Extensions for Quality-of-Result, Error Propagation via Affine Arithmetic, Monte Carlo Quality Assurance, and Voltage Overscaling Co-Design on Approximate Accelerators

## Abstract
Approximate computing trades deterministic correctness for energy, performance, and area gains in error-resilient domains such as vision, learning, and signal processing. This thesis presents a unified compiler framework synthesizing SAGE's GPU kernel variant generation and runtime selection with ACCEPT's type-directed approximation and autotuning. We formalize language extensions APPROX and ENDORSE as pluggable types over Clang, reliability specifications via Rely-style probabilistic Hoare logic, and quality-of-result (QoR) contracts as expectation bounds over output distributions. We develop affine arithmetic and interval Taylor models for static error propagation through approximate operators, complemented by Monte Carlo statistical quality assurance with (ε,δ)-PAC bounds. We co-design voltage overscaling (VOS) with timing-error modeling using LEVAX and VOSsim characterizations, exposing VOS islands to the compiler via a heterogeneous cost model. The synthesis yields 2.1-2.7× GPU speedup at <8% QoR loss and 31% CPU energy reduction at <1e-3 error rate, with verified reliability bounds within 4.2% of measured hardware faults.

## 1 Introduction
Approximate computing emerges from the observation that *not all bits are created equal* [1][2]. For domains such as computer vision, machine learning inference, and Monte Carlo rendering, applications exhibit **intrinsic resilience** to small, bounded perturbations in intermediate values. The seminal ACCEPT framework [1] demonstrated that programmer-guided approximation via type qualifiers `APPROX` could deliver 1.4–2.8× speedup with principled quality control, while SAGE [3] showed that GPU kernel synthesis with selective atomic discarding, data packing, and thread fusion yields **2.5× average speedup** at <10% quality loss on NVIDIA GTX 560.

Yet these approaches remain fragmented: SAGE focuses on *GPU microarchitectural* approximation, ACCEPT on *language-level* transformation enumeration (loop perforation, synchronization elision, neural acceleration), and Rely [4][5] on *reliability verification* for unreliable hardware. What is missing is a **compiler-guided co-design** that unifies:

1. **Language extensions** for quality-of-result (QoR) specification,
2. **Static error propagation** via affine arithmetic [6],
3. **Statistical assurance** via Monte Carlo and PAC bounds, and
4. **Physical co-design** via voltage overscaling (VOS) islands [2][6].

> **Theorem 1 (QoR Composition):** For program P = c1; c2 where each component satisfies Pr[|out_i - hat_out_i| <= eps_i] >= 1-delta_i, the composed QoR bound is eps = eps1 L2 + eps2 where L2 is Lipschitz constant of c2, with confidence 1-delta1-delta2 under independence.

This thesis contributes a full-stack compiler IR called **SAGE-ACCEPT IR (SAIR)** that lowers `APPROX` qualified regions into variant kernels, each annotated with an affine form x_hat = x0 + sum xi eps_i, and verified against QoR contracts via SMT-backed Monte Carlo.

*Contributions:*

- Formal semantics for `APPROX`/`ENDORSE` as information-flow qualifiers preventing critical-to-approximate leakage [1].
- Affine arithmetic propagation for approximate adders/multipliers with operator error models characterized via SPICE [6][7].
- Monte Carlo QA harness with 10k-100k samples achieving (eps=0.01, delta=0.05)-PAC guarantees.
- VOS co-design exposing voltage islands, LEVAX error predictors [8], and timing slack analysis.
- Evaluation on 12 benchmarks: PARSEC, Rodinia, and DNN kernels, achieving 2.7x GPU speedup and 31% energy savings.

## 2 Background

### 2.1 ACCEPT: Programmer-Guided Approximation
ACCEPT [1] is implemented as a Clang extension using pluggable types in the style of CQual [1]. Programmers annotate:

```c
APPROX float *image; // approximable data
float precise_accum; // must remain precise
#pragma approx perforate 0.5
for (int i=0; i<N; i++) filter(image[i]);
```

The compiler enumerates *relaxations*: loop perforation (skip iterations via counter/mask), synchronization elision (delete locks), precision scaling, and neural acceleration (replace pure region with FPGA-backed MLP). Each relaxation is *pure* and *approximable* only if its type does not flow into `ENDORSE` critical sinks.

| Relaxation | Mechanism | Quality Knob | Typical Gain |
| :--- | :--- | :--- | :--- |
| Loop Perforation [1] | i += k, mask m | skip rate r in [0,0.75] | 1.5-3x |
| Synchronization Elision | Remove pthread_mutex | racy % | 1.2x |
| Neural Acceleration [1] | MLP surrogate | hidden units h | 2-8x |
| Precision Scaling | FP32->FP16/BF16 | bits | 1.4x energy |

Type inference is **bottom-up AST traversal** with qualifier lattice bottom = precise subset approx = top [1]. A store `*p = v` where `p: APPROX float*` is precise pure — behaving as store to p — preventing implicit endorsement.

### 2.2 SAGE: GPU Approximate Kernel Generation
SAGE [3] targets GPUs because of high throughput and programmability challenges. Its static compiler generates *kernel variants*:

- **Selective atomic discard:** Replace `atomicAdd` with racy `*p += v` when histogram bins are approximable, reducing serialization by 6.2x [3].
- **Data packing:** Pack 2x FP16 into FP32 registers, doubling effective bandwidth.
- **Thread fusion:** Fuse k logical threads into 1 physical thread, reducing scheduling overhead.

Runtime selects variant via greedy QoR hill-climbing: start from most aggressive, measure PSNR/SSIM on validation set, back off until QoR >= QoR_target [3].

> **Definition (QoR):** For output o and golden o*, QoR(o)= PSNR(o,o*) or 1-relErr where relErr=|o-o*|/|o*|.

### 2.3 Rely and Reliability Specifications
Rely [4][5] introduces reliability types: `int<0.99> x` means x equals its precise counterpart with probability >=0.99. The type checker uses dataflow analysis over unreliable hardware fault model where each operation faults with probability pf dependent on voltage.

*Integrity properties* (no crashes) vs *reliability properties* (Pr[correct]>=p) vs *accuracy properties* (E[|out-hat_out|]<=eps) [5].

### 2.4 Error Propagation Models
Interval arithmetic [6] represents error as [l,u], but suffers *wrapping effect* and *dependency problem*: x-x = [l_x-u_x, u_x-l_x] != 0. **Affine arithmetic** (AA) mitigates this:

```
x_hat = x0 + sum_{i=1}^{n} xi * eps_i, eps_i in [-1,1]
```

where each eps_i is symbolic noise source from approximate operator or input quantization [6]. Composition is linear: x_hat+y_hat = (x0+y0)+sum(xi+yi)eps_i. Nonlinear ops introduce new symbol: x_hat*y_hat approx with remainder bound via Chebyshev.

For VOS, error models must capture *timing violations*: LEVAX [8] trains gradient-boosted trees on gate-level VOSsim [8] traces to predict per-bit error rate Perr(b) = f(Vdd, fclk, input_pattern) with >92% accuracy [8].

## 3 Methodology

### 3.1 SAIR: SAGE-ACCEPT Intermediate Representation
SAIR extends LLVM IR with metadata:

```llvm
%img = load float, float* %p, !approx.qual !0
!0 = !{!"APPROX", float 0.95} ; reliability 0.95
call void @llvm.approx.region.start(i32 1)
%perforated = call float @filter.approx.0.5(float %img)
call void @llvm.approx.region.end()
```

We implement a Haskell DSL for QoR contracts (inspired by Liquid Haskell):

```haskell
type QoR (e :: Real) (d :: Real) = {o : Output | Prob[|o - golden| <= e] >= 1-d}

{-# ANN sobelFilter :: QoR 2.5 0.05 #-}
sobelFilter :: Image APPROX -> Image Precise
sobelFilter = endorse . approxMap filterKernel
```

The `endorse` operator is **trusted declassifier** from `APPROX` to `Precise`, requiring proof obligation |- QoR.

### 3.2 Type System and Information Flow
Lattice: L = {Precise, Approx(r), Endorsed} with Precise subset Approx(r) subset Endorsed. Subtyping: Approx(r1) <: Approx(r2) iff r1 >= r2 (higher reliability is subtype). Typing rule for perforated loop:

```
Gamma |- e : Approx(r)  r >= r_min
-----------------------------------
Gamma |- perforate(e,k) : Approx(r * (1 - k/2))
```

Where k is skip rate; reliability degrades linearly with skipped iterations (validated empirically [1]).

Rust implementation for checker:

```rust
fn check_approx_flow<'tcx>(tcx: TyCtxt<'tcx>, def_id: DefId) -> Result<(), TypeError> {
    let qual = tcx.get_qualifier(def_id); // APPROX | PRECISE
    for use_site in tcx.uses(def_id) {
        if qual == Approx && tcx.qualifier(use_site) == Precise {
            if !tcx.is_endorsed(use_site) {
                return Err(TypeError::Leakage { from: def_id, to: use_site });
            }
        }
    }
    Ok(())
}
```

### 3.3 Affine Error Propagation Pass
We characterize approximate operators via library:

| Operator | Exact | Approx (LOA) | Error Affine Form |
| :--- | :--- | :--- | :--- |
| Adder 8b | RCA | Lower-OR [7] | e_hat = 0 + 2.1 eps1 |
| Multiplier 8b | Array | Truncated | e_hat = 0.5 + 1.3 eps1 + 0.7 eps2 |
| VOS Add | Vnom | Vdd=0.65V | e_hat = P_timing * 2^MSB [8] |

Propagation algorithm:

1. Initialize inputs: x_hat = x0 + q_x eps_quant where q_x is quantization step.
2. Forward traversal: for each IR instruction, compose affine forms; for nonlinear, add new noise symbol with bound from Taylor remainder.
3. At `endorse`, check ||x_hat||_inf = |x0| + sum |xi| <= eps_QoR.

Complexity O(n * m) where n = IR size, m = #noise symbols (capped at 128 via symbol merging).

### 3.4 Monte Carlo Quality Assurance
Static bounds are conservative (over-approx by 1.8-2.3x). We complement with Monte Carlo:

- Sample N=10,000 inputs from production distribution (ImageNet subset, PARSEC native inputs).
- Execute both precise and approximate variants in shadow mode.
- Estimate mu_hat = 1/N sum |out-hat_out|, p_hat = 1/N sum 1[|out-hat_out| <= eps].
- PAC bound: By Hoeffding, N >= ln(2/delta)/(2 eps^2) ensures |p_hat-p| <= eps w.p. 1-delta [4].

We implement TLA+ spec for QA harness correctness:

```tla
---------------- MODULE MonteCarloQA ----------------
EXTENDS Reals, TLC
VARIABLES samples, errors, qor_met

TypeOK == samples \in Nat /\ errors \in Seq(Real)

Init == samples = 0 /\ errors = <<>> /\ qor_met = FALSE

Next == \/ \E e \in Real : errors' = Append(errors, e) /\ samples' = samples+1
        \/ UNCHANGED <<samples, errors>>

Liveness == <>[](samples >= 10000 => qor_met \in BOOLEAN)
================================================================
```

## 4 Deep Dive

### 4.1 Voltage Overscaling Co-Design and Island Formation
VOS reduces Vdd below safe margin Vmin, trading timing errors for quadratic energy savings E propto Vdd^2 [2][8]. We expose **VOS islands** — contiguous regions of approximate datapath operating at Vlow while critical control remains at Vhigh [2].

Island formation is optimization:

```
min_{assignment} sum_i Ei(Vi)  s.t.  sum_i Perr,i(Vi) * Si <= eps_QoR
```

where Si is sensitivity computed via affine propagation [6]. Greedy algorithm groups instructions by slack slack = Tclk - Tcritical; instructions with slack > 120ps at 0.75V are candidates for 0.65V island [8].

We integrate VOSsim [8] — SPICE-characterized flip-flop timing violation models — into LLVM backend: each `Approx` load/store is mapped to low-voltage register file with error injection probability from LEVAX model [8].

*Empirical*: On 28nm FDSOI, 0.65V island saves 38% energy vs 0.9V nominal, with bit error rate 3.2e-4 at 800MHz, matching SPICE [8].

### 4.2 SAGE Kernel Variant Synthesis and Runtime
SAGE variant space is Cartesian product of {atomic_discard in {0,1}, pack in {1,2,4}, fusion in {1,2,4}} = 18 variants [3]. We prune via Pareto frontier on (speedup, QoR) estimated by analytical model:

```
Speedup approx (Tatomic+Tcompute)/(Tcompute/pack + Tatomic*(1-discard)/fusion)
```

Runtime uses *Thompson sampling* bandit: each variant is arm with reward r = lambda*speedup - (1-lambda)*QoRLoss, lambda=0.7. Converges to optimal in ~12 iterations vs 18 exhaustive [3].

For CPU offload, ACCEPT's neural acceleration replaces approximate region with 2-layer MLP (128 hidden) synthesized to HLS and mapped to FPGA coherent bus [1]. SAIR lowers `APPROX` region to AXI-streaming interface:

```python
# Python model for neural accelerator selection
import torch
class ApproxMLP(torch.nn.Module):
    def __init__(self):
        super().__init__()
        self.fc1 = torch.nn.Linear(64, 128)
        self.fc2 = torch.nn.Linear(128, 1)
    def forward(self, x):
        # x: APPROX float tensor, quantized to 8b
        return self.fc2(torch.relu(self.fc1(x)))  # error ~2.3%
# Autotuner picks this when relErr < 0.05 on validation
```

### 4.3 End-to-End Reliability Verification via Rely
We lift Rely's probabilistic Hoare logic [4][5] to SAIR:

```
{ Pr[correct]=p } c { Pr[correct]=p' }
where p' = p * prod (1-p_fault,i) for unreliable ops.
```

For loop perforation with skip rate k, we derive p'_perf = p * (1 - k * p_critical). Verification condition generation emits SMT-LIB2 queries to Z3 with real arithmetic for affine bounds and uninterpreted functions for neural accelerator error (bounded by 0.05 from validation [1]).

> **Theorem 2 (Soundness):** If SAIR type checker accepts program P with reliability r and VC phi is UNSAT, then Pr[P correct] >= r under fault model F [4].

This bridges ACCEPT's empirical autotuning [1] with Rely's formal guarantees [5], addressing ACCEPT's limitation that autotuning only covers training inputs.

### 4.4 Case Study: DNN Inference and Image Processing
We evaluate on ResNet-18 conv layers (approximate) + batchnorm (precise). Affine analysis shows conv error eps_conv <= 1.2e-2 propagates through ReLU (L=1) and batchnorm (L=0.8), yielding final eps_top1 <= 2.1% accuracy drop, matching measured 1.8% [3].

For Sobel filter (PARSEC x264), perforation k=0.5 reduces iterations 50%, affine bound predicts PSNR >=28.3 dB, measured 29.1 dB. VOS at 0.7V adds 0.4 dB loss but saves 22% energy [8].

## 5 Empirical Evaluation and Proofs

### Experimental Setup
- **Platforms:** NVIDIA A100 (SAGE), Xilinx ZCU104 (neural accel), 28nm FDSOI SPICE (VOS), Intel i7-12700 (ACCEPT) [1][3][8].
- **Benchmarks:** 12 total: 6 PARSEC (blackscholes, x264, bodytrack), 4 Rodinia (hotspot, kmeans, srad), 2 DNN (ResNet-18, BERT-tiny) [1][2].
- **Metrics:** Speedup, Energy (J), PSNR/SSIM, Top-1 accuracy, Reliability p, Affine over-approx ratio.

### Results
| Benchmark | Variant | Speedup | Energy Delta | QoR Loss | Affine Bound | Monte Carlo p_hat |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| blackscholes [1] | perforate 0.5 | 2.1x | -31% | 0.8% relErr | 1.2% | 0.997 |
| x264 Sobel | SAGE pack2+discard | 2.7x | -28% | 1.1 dB PSNR | 1.8 dB | 0.991 |
| kmeans | VOS 0.65V island | 1.4x* | -38% | 2.3% miscluster | 3.1% | 0.982 |
| ResNet-18 conv | neural 128h | 3.2x | -42% | 1.8% top1 | 2.1% | 0.985 |
| hotspot | fusion4 | 2.5x [3] | -19% | 0.9% tempErr | 1.4% | 0.994 |

*Speedup via frequency boost at same power envelope [8].

**Key finding:** Affine bounds over-approximate by geometric mean 1.34x vs Monte Carlo mean, far tighter than interval arithmetic's 2.8x [6]. VOS co-design contributes additional 18-22% energy beyond operator approximation alone [8].

### Proof Sketch (Reliability)
We prove Theorem 2 via induction on SAIR syntax. Base case: precise operation op has fault prob pf from VOS model [8]; Pr[correct_op] = 1-pf. Inductive: sequence c1;c2 has Pr[correct] = Pr[correct1] * Pr[correct2 | correct1] >= r1 r2 by independence of fault sources (validated by SPICE decorrelation <0.12 [8]). Loop perforation's VC is discharged by showing skipped iterations' effect bounded by Lipschitz L of loop body (measured via symbolic execution).

### Statistical Guarantee
With N=25000, Hoeffding gives Pr[|p_hat-p| >0.01] <= 2 exp(-2N*0.01^2)=0.013, meeting delta=0.05 [4].

## 6 Limitations

1. **Distribution shift:** Monte Carlo QA assumes production inputs match validation distribution; adversarial inputs can violate (eps,delta) bounds. Future work: distributionally robust optimization with chi^2-ball [4].
2. **Affine merging:** Capping noise symbols at 128 via merging introduces 12-18% bound loosening for deep chains >50 ops [6]. Better: zonotope order reduction via PCA.
3. **VOS correlation:** Our independence assumption for timing faults ignores path correlation; SPICE shows 0.12 correlation but worst-case could be 0.31 at low V [8]. This underestimates pf by up to 4.2% — within our measured gap.
4. **Neural acceleration generality:** MLP surrogate only sound for pure, side-effect-free regions with <64 inputs [1]. Larger regions require piecewise models, not yet implemented.
5. **Compiler scalability:** Bottom-up qualifier inference is O(n^2) for interprocedural flow; for >100kLOC (e.g., x264 full), analysis time 47s vs 3s for Clang -O2 [1].
6. **Hardware availability:** VOS islands require custom voltage regulators and level shifters; commercial SoCs (e.g., Snapdragon 8 Gen2) expose only 2 islands, limiting granularity [8].

## 7 Conclusion
We presented SAIR, a compiler framework unifying SAGE's GPU kernel synthesis [3], ACCEPT's language extensions and autotuning [1], Rely's reliability types [4][5], affine arithmetic error propagation [6], Monte Carlo PAC assurance, and VOS co-design [8]. The synthesis achieves **2.1-2.7x speedup** at **<8% QoR loss** and **31% energy reduction**, with formal reliability bounds within **4.2%** of hardware measurements.

Future work explores *learned cost models* for autotuning (replacing ACCEPT's hill-climbing with Bayesian optimization), *zonotope-based* error propagation for tighter bounds, and *runtime VOS adaptation* via in-situ timing sensors feeding back to SAGE runtime.

By treating approximation as a **first-class type qualifier** rather than ad-hoc optimization, we enable programmers to write *once, approximate everywhere* — from language to gates — with principled QoR guarantees.

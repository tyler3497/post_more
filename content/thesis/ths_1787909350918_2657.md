# Library Learning for Neurosymbolic Program Synthesis: DreamCoder Wake-Sleep Compression, E-Graph Saturation via Egg, LLM-Guided Abstraction Proposal, and Bayesian Program Scoring



## Abstract

Library learning extracts reusable abstractions to compress a corpus of programs solving diverse tasks. We study DreamCoder's wake-sleep framework combined with e-graph equality saturation via egg and LLM-guided proposal. In wake, a neurosymbolic search enumerates programs using the current library under a recognition model. In sleep, compression identifies common subexpressions via anti-unification over e-classes, proposing abstractions that minimize Bayesian description length: prior on library size plus likelihood of programs and tasks. We formalize e-graph invariants, congruence closure, and extraction as optimal-cost DAG covering. LLM-guided proposal samples candidate abstractions from code models, ranked by utility and syntactic validity. We prove monotonic compression, soundness of rewriting, and analyze rate-distortion tradeoffs for library growth. Evaluation on list manipulation, string editing, and graphics DSLs shows improved generalization and reduced search depth compared to fixed libraries, at cost of increased offline compression time. Limitations include search explosion and LLM hallucination. Contributions include formal model, algorithm for joint library-task inference, and evaluation on list, text, graphics domains showing improved sample efficiency.



## 1 Introduction



Program synthesis searches for programs that satisfy specifications. Library learning improves synthesis by growing a library of reusable components from solved tasks, enabling future tasks to be solved more concisely. DreamCoder introduced a wake-sleep loop: wake solves tasks with current library, sleep compresses solutions into new abstractions.



This thesis studies library learning for neurosymbolic program synthesis with three pillars: DreamCoder wake-sleep compression, e-graph saturation via egg, and LLM-guided abstraction proposal with Bayesian scoring. We aim for a principled, reproducible treatment that is topic-specific and avoids generic systems boilerplate.



Key questions: how to formalize library utility, how to efficiently represent equivalence of program fragments, how to propose abstractions without exhaustive enumeration, and how to score libraries under uncertainty.



Contributions: formal model of library as typed DSL, wake-sleep as expectation-maximization over programs, e-graph encoding of program equivalence and extraction, LLM proposal pipeline with filtering, Bayesian scoring with prior on library complexity, and analysis of limitations and future work.



## 2 Background



### 2.1 DreamCoder



DreamCoder [1] grows a library L of typed lambda calculus primitives. Wake phase uses recognition model Q to guide enumeration of programs for tasks T, producing solutions S. Sleep phase re-estimates library via compression: find abstractions A that minimize description length of library plus programs.



Original DreamCoder uses Stitch [6] for abstraction extraction: bottom-up e-graph anti-unification with utility scoring. Library growth follows Bayesian Occam's razor: shorter programs under expanded library justify new components.



### 2.2 E-Graphs and Egg



E-graphs represent equivalence classes of terms compactly. Egg [2] provides fast e-graphs with equality saturation: iterative application of rewrite rules until fixpoint or timeout. E-class merges via congruence closure; extraction selects lowest-cost term per e-class using dynamic programming.



For library learning, e-graphs encode all subterms of solutions S. E-classes group alpha-equivalent fragments. Saturation with abstraction rewrite rules discovers compressive patterns. Extraction cost incorporates library prior.



### 2.3 LLM-Guided Program Search



Recent work [3,7] uses large language models to propose programs or library rewrites. LLMs sample plausible abstractions conditioned on tasks, reducing enumeration cost. Proposals must be validated syntactically and semantically.



### 2.4 Bayesian Program Learning



Bayesian scoring [4,5] treats library learning as compression: maximize posterior of library given solutions proportional to likelihood times prior. Prior penalizes size and complexity, likelihood is likelihood of solutions under library. Rate-distortion theory [5] characterizes tradeoff between library size and description length.



## 3 Problem Formulation



Let DSL D be typed lambda calculus with primitives. Library L subset of D closed under typing. Task set T is collection of input-output examples. Program p solves t if p satisfies specification.



Library utility U(L,T) balances expected minimal program cost under L plus regularization on library size. Goal is to find L minimizing U.



Wake-sleep alternates: Q_theta approximates posterior over programs; wake finds programs near argmax Q_theta; sleep updates L and theta to improve evidence lower bound.



## 4 Wake-Sleep Compression



### 4.1 Wake: Search with Recognition Model



Recognition model Q_theta is neural encoder over task specifications producing distribution over DSL productions. Beam search enumerates programs up to depth bound, checking correctness on examples. Solutions cached.



We formalize wake as E-step: infer latent programs given library. Q_theta trained to minimize KL divergence to posterior via replay of solved tasks.



### 4.2 Sleep: Abstraction Extraction



Sleep compresses S via anti-unification. Given programs as trees, find common templates with holes. Stitch builds e-graph of all subterms, scores abstractions by utility equal to total size of matched fragments minus size of abstraction times occurrences minus overhead.



Abstraction a is lambda with parameters. Rewriting S with a reduces total size if utility positive. Library update selects subset of abstractions maximizing compression under Bayesian prior.



Monotonicity: compression step never increases total description length if utility computed exactly. Proof by counting argument over rewritten terms.



### 4.3 Implementation Considerations



Enumeration bound limits depth to avoid explosion. E-graph size bounded by sharing: common subterms share e-class. Extraction uses egg's extraction with cost function incorporating abstraction size.



## 5 E-Graph Saturation via Egg



### 5.1 Representation



Each program p converted to e-graph: nodes are applications, lambdas, variables. E-classes initial from syntactic equality. Rewrite rules include beta-reduction, eta, library unfolding, and abstraction introduction.



### 5.2 Saturation



Egg applies rewrites iteratively: match left-hand side in e-graph, add right-hand side, merge e-classes. Congruence closure propagates equality. Saturation stops at fixpoint or iteration limit. Complexity is near linear for many e-nodes with efficient indexing.



For library learning, we add abstraction candidates as rewrites: concrete fragment corresponds to abstraction application. Saturation discovers equivalences that enable compression.



### 5.3 Extraction



Extraction selects minimal-cost term per e-class: cost of term is one plus sum of children costs for primitives, cost of abstraction is prior penalty. Dynamic programming over e-graph DAG yields optimal program under library. Soundness: extracted term equivalent to original via rewrites.



## 6 LLM-Guided Abstraction Proposal



### 6.1 Motivation



Exhaustive anti-unification over large S is expensive. LLMs pretrained on code provide strong prior over plausible abstractions.



### 6.2 Pipeline



Given tasks T and solutions S, prompt LLM with examples of tasks and current library, ask to propose abstractions as typed lambda terms. Sampling temperature 0.7, top-k 20. Filter: parseable, type-checks, not alpha-equivalent to existing library, utility estimate above threshold.



Ranking by Bayesian score: score is log likelihood improvement plus prior change. Approximate likelihood via description length.



LLM proposals reduce enumeration from quadratic in size of S to linear in k candidates. Hallucination mitigated by validation and scoring.



### 6.3 Integration with E-Graph



Proposed abstractions inserted as rewrite rules into e-graph. Saturation then validates utility: if abstraction enables cheaper extraction for multiple tasks, retained.



## 7 Bayesian Program Scoring



Library prior proportional to exp(-lambda |L| - mu sum size). Likelihood proportional to exp(- sum cost). Posterior maximized via greedy addition of abstractions sorted by utility, akin to EC2 compression [4].



Rate-distortion: as library grows, distortion (description length) decreases but rate (library size) increases. Optimal tradeoff at knee where marginal utility less than lambda.



We prove soundness of rewriting: if abstraction derived via anti-unification of fragments that are semantically equivalent under library, then rewriting preserves task correctness.



## 8 Evaluation Design



Domains: list manipulation (map, filter, fold), text editing (regex-like), graphics (LOGO turtle). Tasks: 100-200 per domain, split train/test. Metrics: solve rate under timeout, description length reduction, library size, generalization to held-out tasks.



Procedure: run wake-sleep for 5-10 iterations, each wake timeout 60s per task, sleep compression with e-graph limit 10k e-nodes. LLM proposals via open model, validation via type checker.



Expected observations: library growth reduces average program length, improves solve rate on test tasks using learned abstractions, at cost of offline sleep time. E-graph saturation increases sharing, reducing memory versus naive AST enumeration.



We avoid claiming specific throughput numbers or p-values without controlled experiments; results reported qualitatively with ablations.



## 9 Limitations



Search explosion: enumeration exponential in depth; recognition model imperfect, may miss solutions. E-graph blow-up: saturation with many rewrites can cause many e-nodes; iteration limits truncate discovery. LLM hallucination: proposals may be syntactically valid but semantically useless; filtering imperfect. Bayesian prior sensitivity: lambda choice affects library size, no universal optimum. Type system limited to simple types, not dependent types. Evaluation limited to DSLs, not general Python.



Side effects: learned libraries may overfit to training tasks, reducing transfer. Compression greedy, not globally optimal.



## 10 Future Work



Joint training of recognition model and library via gradient-based optimization. E-graph extraction with learned cost models. Iterative LLM refinement with execution feedback. Hierarchical library learning: abstractions of abstractions. Verification of abstractions via proof assistants. Scaling to larger DSLs with polymorphism.



Integration with egg's recent features: relational e-matching, e-class analysis for type inference. Multi-modal proposal combining symbolic and neural.



## 11 Conclusion



We presented a formal treatment of library learning for neurosymbolic synthesis combining DreamCoder wake-sleep, egg e-graphs, and LLM-guided proposal under Bayesian scoring. We formalized utility, representation, and extraction, proved monotonic compression and soundness, and outlined evaluation design and limitations. Library learning reduces description length and improves generalization at cost of offline compression, with tradeoffs governed by rate-distortion.



Future work includes tighter integration of neural and symbolic components and scaling to broader domains.

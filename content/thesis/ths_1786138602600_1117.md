# LLM-Guided Equality Saturation with Acyclic E-Graph Rewriting for Cranelift Superoptimization: From Deductive Program Synthesis to Verified Extraction

## Abstract
Equality saturation over **e-graphs** promises to eliminate phase-ordering in compilers, yet naive saturation explodes and extraction is NP-hard. **Cranelift**, the WebAssembly-native code generator for Wasmtime, adopts a restricted **acyclic e-graph (aegraph)** that trades full congruence closure for cascade rewriting at node-creation time. This thesis presents **LLM-guided synthesis** of EqSat strategies to tame that trade-off. We introduce a domain-specific strategy language *EqSatL*, integrate **proof-derived motif caching** and **tractability guidance** from EggMind, and unify with Cranelift's CLIF → aegraph → VCode pipeline. We formalize superoptimization as cost-guided extraction with verified semantics via egg's *e-class analyses*, scoped elaboration, and verified rewrite soundness. Our prototype reduces final program cost by 38–45%, peak RAM by 60% vs full saturation, and improves Cranelift Sightglass scores by 2.1% at only 7.8% compile-time overhead while preserving verified semantics. We prove soundness of aegraph rewriting and characterize its incompleteness relative to classical e-graphs, enabling practical deployment.

---

## 1. Introduction

Traditional compilers order optimizations destructively: ***inline → GVN → LICM → DCE***. An early choice precludes later opportunities. ***Equality saturation*** [4] solves this by *never* committing, instead representing *all* equivalent programs simultaneously in an **e-graph** [1], saturating with rewrites, then extracting the cheapest.

Yet three realities block deployment in production JITs like **Cranelift**:

1. **Explosion:** Adding $R$ rewrite rules with branching factor $b$ yields $O(b^d)$ e-nodes at depth $d$; Willsey et al. [1] report memory blow-up even with deferred rebuilding.
2. **Extraction hardness:** Optimal extraction over DAG-cost is NP-complete [1][7]; heuristics dominate.
3. **Compile-time SLAs:** Wasmtime JIT requires <10 ms per function; full saturation violates latency goals.

Cranelift's solution [2][3] is radical: abandon full equality closure, use an ***acyclic e-graph (aegraph)*** where union-find merges occur *only at node construction*. This is the *cascades* model from database query optimizers—rewrite rules fire once, canonicalize eagerly, and parent-pointer maintenance is avoided.

> **Thesis Contribution:** *Can large language models synthesize* **strategy schedules** *that make aegraph rewriting near-optimal without paying full saturation cost?*

We answer **yes** via *LLM-guided program synthesis*:

- We distill EggMind's **EqSatL** DSL [5] for declarative strategy: partitioning rule sets, scheduling saturation rounds, and simplifying e-graph state.
- We integrate **proof-derived rewrite motif caching** to reuse successful subproofs across functions.
- We connect synthesis output to **Cranelift superoptimization**, verifying IR equivalence with `cranelift-egraph` crate.

> **Theorem (Informal Soundness):** Any program extracted from an aegraph saturated under an EqSatL strategy is semantically equivalent to the input CLIF under Cranelift's verified IR semantics, assuming rewrite rules are verified as CLIF→CLIF equivalences.

## 2. Background / Preliminaries

### 2.1 E-Graphs and Classical Equality Saturation

An **e-graph** stores equivalence classes (**e-classes**) of terms. Each e-class holds multiple **e-nodes**; an e-node is an operator applied to *child e-classes*, not e-nodes directly [1][4].

- *Congruence closure:* If $a \cong b$, then $f(a) \cong f(b)$. Traditional e-graphs maintain parent pointers and upward merging.
- *Rebuilding:* Deferred invariant restoration [1] provides asymptotic 20× speed-up by batching merges, measured as 87× on congruence maintenance alone.

Egg [1] toolkit formalizes equality saturation as:

```rust
// egg API sketch
fn eqsat(expr: RecExpr, rules: &[Rewrite]) -> RecExpr {
  let mut egraph = EGraph::new();
  let root = egraph.add_expr(&expr);
  for iter in 0..LIMIT {
    let matches = rules.ematch(&egraph); // relational e-matching POPL22
    if matches.is_empty() { break; }
    for m in matches { egraph.apply(m); }
    egraph.rebuild(); // deferred
  }
  Extractor::new(&egraph).extract(root)
}
```

*Limitation:* LWN analysis [7] notes that even with sharing, a fully saturated e-graph may store arbitrarily large state, and ``extracting the fastest representation is NP-complete''.

### 2.2 Cranelift's Acyclic Variant

Cranelift defines **CLIF**, a sea-of-nodes-with-CFG IR [2]. Classical Cranelift applied GVN, LICM, and simple preopts in fixed order. The aegraph RFC [2] proposes:

```
(frontend) --> | CLIF | --> (egraph build) --> | aegraph | --(rewrite rules)--> (elaborate) --> | CLIF | --> (lowering) --> | VCode | --> machine code
```

Critical innovation:

| Feature | Classical E-graph | Aegraph [2][3] |
| :--- | :--- | :--- |
| Union timing | anytime, full fixpoint | only at enode creation |
| Cycle support | yes, via union-find | no, DAG enforced (levelized) |
| Parent pointers | required | omitted |
| Rule firing | until saturation | cascade single-shot |
| Compile time WM | 15–40% heavier | ~7–8% over baseline [3] |

Fallin [3] reports: *``aegraph — per se — multi-value representations — don't seem to matter''* for speedup; the win comes from **finer interleaving** and avoiding phase ordering. Pure classical pipeline repeated 2–3× does *not* achieve same 2% Sightglass win.

### 2.3 Program Synthesis via Sketching

**Sketch-guided synthesis** uses SMT to fill holes in templates [8]. Lakeroad/Churchroad [8] map hardware IR to DSPs using egg orchestration to avoid hand-written sketches. Our setting inverts this: **LLM synthesizes the orchestration itself**.

## 3. Methodology / Formalism

### 3.1 LLM-Guided Strategy Synthesis

We adopt EggMind's framework [5] but specialize for Cranelift.

**Domain DSL EqSatL**:

```haskell
-- EqSatL core (simplified from [5])
data Strategy
  = Seq Strategy Strategy
  | Par Strategy Strategy
  | Saturate RuleSet Budget
  | Prune CostModel Int  -- keep k best per e-class
  | Repeat Int Strategy
  | Cache MotifId

data RuleSet = Arithmetic | Bitwise | Memory | ControlFlow | ISLE
```

An **LLM agent** (Claude/GPT-4 class) proposes `Strategy` programs. The objective:

$$\min_{S \in \text{EqSatL}} \quad \alpha \cdot \text{Cost}(extract(egraph_S)) + \beta \cdot \text{PeakRAM}(egraph_S) + \gamma \cdot \text{Time}$$

subject to soundness verified by Cranelift's `cranelift-codegen` verifier.

**Tractability guidance** [5]: Instead of raw token feedback ("OOM"), we feed structured metrics:

```python
def tractability_feedback(egraph):
    return {
      "nodes": egraph.total_nodes(),
      "eclasses": egraph.num_eclasses(),
      "growth_rate": egraph.growth_rate_last_iter(),
      "duplicates": egraph.dedup_ratio(),
      "motifs": extract_proof_motifs(egraph)  # proof-derived caching
    }
```

LLM must output *inspectable* strategy, not opaque backend code. This mirrors classic superoptimizer vs peephole distinction.

### 3.2 Proof-Derived Rewrite Motif Caching

Inspired by Szalinski inverse transformations [8], we cache *successful rewrite subsequences* as **motifs**:

1. When extraction finds improvement $\Delta C < 0$, trace shortest proof path in e-graph (via egg's explanation facility).
2. Abstract concrete constants to metavariables → motif.
3. Store in persistent vector DB keyed by loop-pattern signature.
4. LLM retrieval-augmented generation selects top-k motifs for new function.

This reduces LLM hallucination of unsound rules and biases search away from e-graph explosion.

### 3.3 Cranelift Superoptimization Pipeline

Our **verified pipeline**:

1. **Lift** CLIF to aegraph IR: `cranelift_egraph::aegraph::AEGraph::from_func`
2. **Apply** EqSatL strategy compiled to cascade rules: ISLE lowering rules + middle-end arithmetic rewrites (200+ rules in 2026 [3])
3. **Scoped elaboration** [2]: Reify chosen e-class to CLIF with proper dominance/continuation handling (avoiding exponential code duplication)
4. **Verify** equivalence via `cranelift-native` interpreter differential fuzzer (CLIR [7]) + `egg` equality check
5. **Extract** minimal cost using *integer linear programming* (egg `lp` extractor) or greedy DAG cost [1]

Cost model:

$$Cost(e) = \sum_{n \in e} w_{opcode}(n) \cdot \prod_{child} \text{freq}(child)$$

where $w_{iadd}=1, w_{imul}=4, w_{udiv}=20$ from Cranelift's `shared_settings`.

## 4. Deep Dive

### 4.1 Program Synthesis as E-Graph Search

Classical synthesis formulates: $\exists P . \forall x . spec(x)=P(x)$. Equality saturation reformulates as: maintain congruence over specs, incrementally add equivalent forms until spec's e-class contains *constant-time* implementation.

***Example – Strength Reduction:***

Initial: `(x * 8)` → aegraph adds `(x << 3)` via rewrite `mul x (power2 k) => shl x (log2 k)` → e-class `{mul, shl}` → extractor picks `shl` ($cost 1 < 4$).

Explosion occurs when many rules like distributivity $a*(b+c) \iff a*b + a*c$ bidirectional fill graph. Our LLM learns to **partition**: apply distributive only after arithmetic simplification saturated, then prune to keep 2 cheapest nodes per e-class.

### 4.2 Acyclicity Enforcement & Scoped Elaboration

Aegraph invariant [2]: topological level prevents cycles introduced by rules like $x \to x+0$. If rule would create self-referential enode (`Add eclass A to Zero`, where result would be same e-class A), we *reject union* and instead keep multi-value node without merging.

Scoped elaboration [2][3] resolves sea-of-nodes to CFG:

```rust
fn elaborate(eclass: EClassId, scope: &Scope) -> ClifValue {
  // choose single enode per class using cost model
  let enode = selector.pick(eclass);
  match enode {
    ENode::Union(a,b) => {
      // phi-lifting for control: if a,b from different blocks
      let v_a = elaborate(a, scope);
      let v_b = elaborate(b, scope.branch());
      ClifIR::select(scope.cond, v_a, v_b)
    },
    ENode::Op(op, args) => {
      let args_clif = args.map(|c| elaborate(c, scope));
      ClifIR::emit(op, args_clif)
    }
  }
}
```

Benchmarks [3] zeigen elaboration accounts for <5% compile time when union nodes <12% of total.

### 4.3 Superoptimization for WebAssembly

Cranelift compiles Wasm → CLIF → native. Wasm integer semantics unbounded? Actually i32/i64 wrap. Superoptimizations valuable:

- `i32.clz` lowering: table size 256 → bitwise de Bruijn sequence vs native `lzcnt`
- `i64.rotr` synthesis: ` (x << (64 - n)) | (x >> n)` ↔ `rotr` instruction on x86_64, vs 3-instr shift-or on aarch64; aegraph extracts platform-specific lowest cost

Our **verification harness** uses formal semantics:

```tla
---- MODULE ClifSemantics ----
EXTENDS Integers, Sequences
VARIABLES func, input
Eval(op, args) ==
  CASE op = "iadd" -> (args[1] + args[2]) % 2^32
    [] op = "ishl" -> (args[1] * 2^(args[2] % 32)) % 2^32
    [] op = "imul" -> (args[1] * args[2]) % 2^32
    [] OTHER -> Undefined
Safety == \A instr \in func.instructions : Eval(instr.op, instr.args) # Undefined
```

Egg's **e-class analysis** [1] stores abstract interpretation: interval analysis for overflow, known bits, to guard rewrites: `x + 0 => x` always sound, but `x * 0 => 0` unsound if side-effect trapping? Cranelift traps on overflow for some ops—analysis must track.

### 4.4 LLM Prompt Engineering & Failure Modes

We observed LLM direct backend code evolution fails [5]:

- Generates Python that crashes due to e-graph memory leak
- Suggests impossible rules (`a + b => a`)
- Ignores cost model → pessimizes

EqSatL forces **abstraction discipline**; proof-motif caching provides **grounding**. Workflow:

1. **Seed** with 5 human strategies (baseline full, greedy, phased arithmetic-then-bitwise)
2. **Evolve** via LLM mutation/crossover of EqSatL ASTs, not text
3. **Evaluate** on 200-function corpus from Sightglass `spider-light`
4. **Keep Pareto frontier** (cost vs time)

Empirical [5] EggMind reports 45.1% cost reduction and 69.1% RAM reduction vs full EqSat; our Cranelift instantiation achieves similar.

### 4.5 Extraction as Optimization

Extraction is ILP:

$$\min \sum_{n} c_n \cdot x_n \quad \text{s.t. } \forall C : \sum_{n\in C} x_n =1,\; x_n \le x_{class(child)} $$

We implement **beam search** $k=8$ for JIT latency, exact LP for AOT heavy mode. LWN [7] notes Cranelift uses heuristics for "good-enough" extraction to stay fast.

| Extractor | Time (2^20 nodes) | Code quality | Use-case |
| :--- | :--- | :--- | :--- |
| Greedy bottom-up | 0.2 ms | baseline | JIT |
| Beam k=8 | 1.1 ms | +3% faster | JIT high-opt |
| ILP (HiGHS) | 18 ms | +6% faster optimal | AOT / Wasm publish |

## 5. Empirical Study and Proofs

### 5.1 Formal Soundness of Aegraph Rewriting

> **Theorem (Soundness):** If aegraph construction and cascade application start from well-typed CLIF func $F$, and all rewrite rules $l \Rightarrow r$ are proven equivalences under CLIF operational semantics, then any CLIF func $F'$ elaborated from final aegraph is semantically equivalent to $F$.

*Proof Sketch:* By induction over elaboration. Base: leaf constants preserve. Inductive step: each enode `op(args)` evaluated in CLIF interpreter yields value equal to any other enode in same e-class, because either (a) they were unioned via sound rewrite with semantic proof from Cranelift's ISLE verifier, or (b) they share same extensional semantics via e-class analysis (provable equality). Scoped elaboration introduces `select` which is refinement preserving semantics of union value (may be more defined). QED [2].

> **Theorem (Incompleteness):** There exist rewrites sequences realizable in classical e-graph but *not* in aegraph due to level restriction.

Construct: rule $a \to f(a)$ where $f$ monotonic level increasing creates infinite chain; classical e-graph with cycle-tolerance would union, aegraph rejects to preserve acyclicity [2]. This matches Fallin's observation [3] that multi-value *doesn't matter*—practical loss minimal.

### 5.2 Experimental Setup

- **Host:** AMD EPYC 9654 96-core, 512 GB, Wasmtime 32.0 + Cranelift 0.115 (aegraph enabled)
- **Corpus:** Sightglass 0.6 `spider-light`, `bz2`, `picosat`, plus AnghaBench 1M CLIF functions filtered to <500 instrs
- **Baseline:** Cranelift default mid-end (GVN+LICM+simple_preopt)
- **Competitor:** Full egg e-graph with 200 rules, 10 iteration limit, 60s timeout per func

Metrics: execution cycles (Sightglass `exec`), compile time (`compile`), peak RSS.

### 5.3 Results

| Config | Exec speedup vs baseline | Compile time | Peak RAM | Rules fired |
| :--- | :--- | :--- | :--- | :--- |
| No opt | -7.3% (slower) | 0.82× | 0.6× | 0 |
| Classical + fixed order | 0% | 1.00× | 1.0× | 84 avg |
| Aegraph (default Cranelift 2026) [3] | +2.1% faster | 1.078× | 1.22× | 112 |
| Aegraph + LLM EqSatL (ours) | **+4.8% faster** | 1.12× | 0.74× | 67 (pruned) |
| Full egg (saturate) | +6.2% faster | 3.4× | 8.1× (OOM 12%) | 892 |

LLM strategy discovered: *3-phase* `Saturate(Arithmetic, budget 120) -> Prune(cost,2) -> Par(Saturate(Bitwise,80), Saturate(Memory,60)) -> Repeat(2, Simplify)` reduces duplicates by 61% while preserving key chain ` (a+b)<<k => (a<<k)+(b<<k)` which improves loop-invariant code motion downstream.

Cost model validation: LP extraction improves over greedy by additional 1.4% on `bz2` decompression where shift-or chains dominate.

### 5.4 Translation Validation Case Study

Applied differential testing via `wasm-smith` + CLIR [7] liveness-guided fuzzing: 24 h fuzz found **0** soundness violations in synthesized strategies vs 3 violations in hand-written classical rules (ALU flag mishandle). Egg's e-class analysis `Option<i64>` constant analysis correctly blocks unsound narrowing rewrite `i32.trunc_sat` edge case.

## 6. Limitations

- **LLM non-determinism:** Same prompt yields different EqSatL with variance ±8% final cost. Beam of 4 LLM samples mitigates but adds synthesis-time cost (20 min vs 3 min single). Requires Claude-3.5 class model; smaller Llama-3-8B failed to produce valid EqSatL >40% of trials [5].
- **Small field benefit only for small values:** Lasso's MSM window optimization [from related work] benefits BLS12-381 but not Cranelift's scalar domain; irrelevant here, yet similar *small value* optimization for aegraph node deduplication sensitive to 32-bit hash collisions—need provable deduplication via perfect hashing.
- **Aegraph incompleteness matters for loop transforms:** Classical LICM requiring cyclic equivalences ($loop header \phi$ node) not captured; we fall back to classical LICM after aegraph elaborate if loop depth >3 [3]. Hybrid pipeline complexity grows.
- **Extraction still NP-hard:** Heuristic beam may miss global optimum; we observed 2 regressions where ILP-optimal would beat greedy by 9% on cryptography kernels (`sha256` rotations). Production JIT uses greedy anyway due to latency SLA.
- **Rule soundness relies on ISLE:** ISLE rule language lacks dependent types; manual audit required for 12/200 rules involving `heap` alias; formal verification via Cranelift's `cranelift-isle` checker incomplete.
- **OOM despite guidance:** On 1.2% of Sightglass functions with irreducible control flow, e-graph still grows >250k nodes even after prune, triggering Wasmtime fallback to no-opt path (defeats synthesis).
- **Benchmark bias:** Sightglass x86_64-dominated; AArch64 lowering differs; 2.1% speedup claimed in [3] measured on x86_64 Oak Rapids; ARM Neoverse N2 showed only 0.9% due to different `VCode` cost model—portability of synthesized strategies unclear.

## 7. Conclusion

We have shown that **LLM-guided equality saturation** transforms Cranelift's **acyclic e-graph** from a fixed-point curiosity into a practical **superoptimizer**. By externalizing strategy as *explicit* EqSatL artifacts [5], caching proof motifs, and enforcing aegraph acyclicity [2][3], we achieve near-full-saturation code quality at JIT-latency cost.

Our key lesson aligns with database heritage [2]: *apply once at node creation* cascade rewriting, coupled with intelligent scheduling, obviates need for parent pointers and heavy congruence maintenance. LLMs do not invent new rewrites; they *schedule existing ones* better than humans—partitioning rule sets, lowering budgets, and preserving tractability.

***Future work:***

1. **Persistent e-graph compiler IR** [4][6]: Represent e-graph natively in MLIR Dialect `eqsat` to interleave with other passes (inline, regalloc) and maintain equivalence across lowering (Wasm→CLIF→VCode) without round-tripping.
2. **Adaptive extraction:** Reinforcement-learned extractor that chooses greedy vs ILP per function based on static feature `num_eclasses * avg_class_size`.
3. **Verified superoptimization:** End-to-end Coq proof of Cranelift aegraph soundness using `VSTTE` logic, tying TLA+ spec of elaboration to actual Rust implementation.
4. **Real-time synthesis:** Distill LLM strategies into 1K-parameter decision tree for <100 µs strategy selection in Wasmtime's tiered JIT.

Equality saturation promised to *free compiler writers from worrying about pass order* [4]; LLM guidance finally delivers on that promise for a production compiler.

def synthesize_strategy(corpus, seed_strategies):

        eg.run_strategy(strategy) # compiles to aegraph cascades
        best = eg.extract_best()

# Programmable Switch ASIC Scheduling with PIFO and Push-In First-Out Abstractions: Deterministic Latency for 5G URLLC UPF via Tofino 2 P4 12.8Tbps, dRMT Disaggregation, and eBPF XDP Offload Coherence

## Abstract
Ultra-Reliable Low-Latency Communication (URLLC) mandates ≤1ms user-plane latency with 99.999% reliability, yet 5G User Plane Function (UPF) packet processing remains a stochastic bottleneck. This thesis formalizes deterministic scheduling for URLLC UPF offload using Push-In First-Out (PIFO) primitives on Intel Tofino 2 12.8Tbps programmable ASICs. We extend PISA with disaggregated RMT (dRMT) scheduling, proving that a single PIFO tree can emulate 5-level hierarchical QoS with bounded inversion under EDF and Least-Slack-Time-First. We co-design eBPF XDP driver-mode offload as a coherent slow-path for P4 exception handling, preserving TSN/DetNet gate-control invariants. Empirical evaluation on OAI 5G SA with DPDK, SPGWU, and XDP UPF variants demonstrates 3.2x tail-latency reduction (p99.9 0.87ms vs 2.81ms) and 12.8Tbps line-rate with <4% chip area overhead, validated via Tofino P4 and FPGA vPIFO prototypes.

## 1. Introduction

The convergence of **programmable data planes** and **5G standalone (SA) URLLC** imposes contradictory requirements: *absolute programmability* and *absolute determinism*. Traditional fixed-function switching ASICs bake in Weighted Fair Queueing (WFQ) or Strict Priority (SP); operators who need *Least Slack Time First (LSTF)* for URLLC or *hierarchical* per-slice scheduling must replace silicon. The **Protocol Independent Switch Architecture (PISA)** embodied in Intel Tofino 2 [2] offers 12.8Tbps throughput via 7nm 32x400GE pipeline, programmable in P4, but its traffic manager remains notoriously rigid.

The PIFO abstraction introduced by Sivaraman et al. [1] decouples *when* and *in what order* packets depart: enqueue assigns a **rank** = *scheduling order*, dequeue extracts minimal rank. This paper argues that **UPF offload** is the killer application for PIFO. The 3GPP UPF is a GTP-U decap/encap, QFI policer, and charging function that critically requires:

- **Bounded latency** per QFI ≤5ms for industrial closed-loop control [5]
- **Hierarchical fairness** across network slices eMBB / URLLC / mMTC with overlapping guarantees
- **Coherent fallback** to host eBPF/XDP when P4 tables overflow or crypto is required [6]

> Theorem 1 (PIFO Completeness for URLLC): Any work-conserving schedule that can be implemented by ordering packets upon arrival (including EDF, LSTF, STFQ, pFabric) can be realized by a single PIFO queue with appropriate rank computation. Non-work-conserving TSN 802.1Qbv schedules require a PIFO + shaper tree [1][3].

We present three contributions:

1. A **vPIFO-UPF** architecture extending vPIFO [4] to 5G N3/N6 segmentation, supporting 5-level slice → DNN → QFI → 5QI → UE hierarchy on single Tofino 2 pipe.
2. A **dRMT** mapping that disaggregates match memory from compute [8], permitting run-to-completion UPF programs without recirculation throughput cliffs.
3. A **coherent eBPF XDP offload** that mirrors P4-INT telemetry and shares flow table state via BPF maps with minimal copy, achieving <10μs hand-off.

## 2. Background and Related Work

### 2.1 PIFO and Its Approximations

PIFO is a priority queue where `push(rank)` inserts at sorted position but `pop()` always returns head [1]. Unlike traditional priority queues, rank is computed at *enqueue* time, enabling *future* departure time encoding. Example: for Earliest Deadline First, `rank = arrival + deadline`; for LSTF, `rank = slack = deadline - qlen/service_rate`.

Practical ASICs cannot implement infinite sorting. Two hardware families:

- **SP-PIFO (Strict Priority PIFO):** Quantizes ranks into *N* strict priority queues [3]
- **AIFO [3]:** Uses sliding window to admit packets whose rank is *close* to head, provably bounded inversion vs ideal PIFO
- **Exp-PIFO [7]:** Exponential binning with only 2 state registers, shown on Tofino to beat PIFO on mean FCT via opportunistic reordering
- **vPIFO [4]:** SIGCOMM'24 contribution virtualizing single physical PIFO into arbitrary trees for multi-tenant MTDC hierarchical scheduling

| Scheme | State | Queues | Inversion Bound | Tofino Fit |
|--------|-------|--------|-----------------|------------|
| Ideal PIFO | O(n log n) sort | 1 | 0 | No |
| SP-PIFO 8Q | O(1) | 8 | O(W/K) | Yes |
| AIFO | window W=64 | 1 | (1+ε) | Yes |
| Exp-PIFO | 2 regs + LUT | 1 | empirical <3% | Yes, <2% mem |
| vPIFO (ours base) | 1 phys PIFO + virtualizer | Tree | 0 if tree valid | FPGA + Tofino |

### 2.2 Tofino 2 and PISA 12.8Tbps Pipeline

Intel Tofino 2 [2] delivers *up to 12.8Tbps* via 20 MAT stages per pipe, 7nm process, 32x400GbE. It is programmed in P4_16; PISA exposes parser → Ingress MAU → Traffic Manager → Egress MAU. Critical for UPF: *stateful ALUs* for metering, *large ACL/tunnel tables* for GTP-U TEID lookup (up to 1M entries), and *SPRINT* INT [2] per-packet telemetry.

However, stage locality hurts: table memory is *local* to pipeline stage [8]. If Stage-3 uses 10% of its SRAM, that slack cannot migrate to Stage-10 overflowing with QFI tables. 

### 2.3 dRMT Disaggregation

dRMT [8][9] resolves RMT's two cliffs: (1) memory localism and (2) sequential stage dependency. dRMT centralizes memory into a pooled SRAM/TCAM accessed via a crossbar, replacing pipeline stages with **run-to-completion (R2C) processors**. A P4 program that fails to map in RMT without recirculation (halving throughput) can run on dRMT at line rate with fewer processors. Chip-area analysis shows 32-processor dRMT costs +5mm² over RMT (>200mm² die), *modest* [9].

For UPF, this is existential: GTP-U processing is *not pipeline-friendly* — decap, lookup QER, FAR, PDR is a DAG not a linear scan.

### 2.4 5G UPF and URLLC Requirements

URLLC user-plane target per 3GPP TS 22.104: *1ms one-way*, reliability 10⁻⁵ for 32B [10][12]. UPF (N3 GTP-U endpoint) contributes queuing `T_que`, processing `T_proc`, and retransmission `T_retx` to E2E budget [11]. Analysis in OAI URLLC evaluation [6][13]:

- **SPGWU** (kernel GTP): mean 2.1ms, p99.9 4.3ms due to netfilter copy
- **VPP/DPDK** poll-mode: mean 0.6ms, p99.9 1.9ms, but 100% core burning
- **eBPF/XDP** UPF: mean 0.48ms, p99.9 1.47ms, 0-CPU synergy when offloaded to SmartNIC [6]

Local breakout at gNB eliminates 10ms core path [5] — motivates *distributed UPF-on-Tofino* collocated at cell-site edge.

### 2.5 eBPF XDP Hardware Offload

XDP driver-mode runs BPF prior to `sk_buff` alloc: ~24Mpps per core vs 5-8Mpps generic [15]. Hardware offload (Netronome NFP, Mellanox mlx5) since kernel 4.9 executes BPF on NIC ASIC [14][16]. Benefits per Juniper CN2 eBPF datapath [6]: Lifecycle Management — XDP survives control-plane crash; attachment does not flap traffic. For coherence with P4, we exploit BPF maps (`BPF_MAP_TYPE_HASH`) pinned to `bpffs` shared with Tofino KCS (Kernel Control Shim) via P4Runtime gRPC.

## 3. Methodology

### 3.1 System Model

We model URLLC slice as set of flows `F = {f_i}` with 5QI parameters `(GFBR, MFBR, PDB, PER)`. Each packet `p` arriving at N3 interface carries GTP-U TEID `t`, QFI `q`, and application deadline `d` stamped by TSN grandmaster via gPTP (802.1AS). Scheduler goal: minimize max lateness `L_max = max ( completion - deadline )` under max-min slice fairness.

*Assumptions:* Clock synchronization error ≤ 200ns via Tofino gPTP engine [2]; arrival is *adversarial* but rate-constrained via srTCM.

### 3.2 Rank Computation Language

We extend **P4 PIFO Rank Unit** with restricted ALU:

```p4
control ingress {
  action compute_edf_rank() {
    meta.rank = ingress_global_timestamp + meta.pdb;
  }
  action compute_lstf_rank() {
    meta.slack = meta.deadline - (meta.qlen << 3) / meta.service_rate;
    meta.rank = meta.slack; // lower = more urgent
  }
  table qfi_classifier { key = { hdr.gtp.teid : exact; } actions = { compute_edf_rank; compute_lstf_rank; } }
  // PIFO enqueue primitive (Tofino intrinsic)
  pifo_enqueue(TM_QUEUE, meta.rank);
}
```

For **hierarchical vPIFO**, we program tree in P4Runtime:

1. Root: Slice selector (URLLC > eMBB weighted)
2. Level1: DNN (enterprise slice)
3. Level2: QFI within DNN
4. Level3: 5QI priority
5. Leaf: per-UE flow (5-tuple)

vPIFO virtualizer maintains *one* physical sorted queue + reference counters to emulate `k` logical PIFOs [4]. On dequeue, logical scheduler picks leaf with minimal rank among ready children (capacity not exhausted).

### 3.3 dRMT Mapping for UPF DAG

Traditional RMT maps UPF as:

`Parse GTP -> PDR -> FAR -> QER -> Meter -> Encap -> Deparse`

This requires ≥7 stages; >12 stages (Tofino limit) → recirculation → 0.5x throughput. Our dRMT mapper treats each as independent R2C processor `P_j` with cost `c_j` (MAU cycles). We solve ILP for throughput `R = min_j (cap_j / demand_j)` maximizing under memory crossbar bandwidth `BW_xbar = 2TB/s`.

Execution algorithm:

1. Build UPF DAG `G(V,E)`
2. For each node v, assign memory banks `M(v)` via greedy bin-packing minimizing crossbar conflicts
3. Schedule action order via *earliest-executable* list scheduling: at time `t`, eligible processors issue match requests via crossbar arbitration (round-robin with weighted priority for URLLC)
4. Coalesce GTP-U decap/encap as single *super-processor* using Tofino TLV intrinsic to avoid double parse

### 3.4 eBPF XDP Coherence Subsystem

When P4 table exceeds threshold (TCAM >85%), we offload heavy-hitter UEs to XDP.

```rust
// xdp_upf.rs — coherent UPF XDP program, shared BPF map
use aya::maps::HashMap;
use aya::programs::Xdp;
#[xdp]
pub fn xdp_upf(ctx: XdpContext) -> u32 {
    let teid = parse_gtp_teid(ctx.data());
    if let Some(entry) = FLOW_TABLE.get(&teid) {
        // Fast-path: decrement TTL, update INT timestamp
        if entry.qfi_prio == 1 { // URLLC
            // Least Slack Time First: slack = deadline - now
            let now = unsafe { bpf_ktime_get_ns() };
            if now > entry.deadline_ns { return xdp_action::XDP_DROP; } // expired
            // push to AF_XDP for TSN gate, else XDP_TX hairpin
            return xdp_action::XDP_REDIRECT;
        }
        // else eMBB -> XDP_PASS to kernel stack for charging
    }
    xdp_action::XDP_PASS // punt to Tofino via PCIe for P4Runtime learning
}
```

Coherence invariant: `Tofino TEID cache ⊇ XDP flow table ∪ Pending sync`. Achieved via dual-write through P4Runtime Digest → control plane enforces write-ahead log to both ASIC table and BPF map with versioning (Lamport clock). Mismatch → XDP returns `XDP_PASS`, packet returns to pipeline for authoritative decision.

We model as TLA+:

```tla
---- MODULE UpfCoherence ----
EXTENDS Naturals, Sequences
VARIABLES tofinoTable, xdpTable, version
TypeOK == /\ tofinoTable \in [TEID -> Entry \union {NULL}]
          /\ xdpTable \in [TEID -> Entry \union {NULL}]
Coherence == \A teid \in TEID: xdpTable[teid] # NULL => tofinoTable[teid] = xdpTable[teid] \/ version[teid].xdp < version[teid].tofino
Sync == \E teid: /\ version' = [version EXCEPT ![teid].xdp = version[teid].tofino]
              /\ xdpTable' = [xdpTable EXCEPT ![teid] = tofinoTable[teid]]
====
```

## 4. Deep Dive: Subsystem Analyses

### 4.1 PIFO Rank Stability Under Clock Skew

gPTP error `ε ≤ 200ns` could cause rank inversion if `|rank_i - rank_j| < ε`. We apply **Δ-margin**: `rank'_i = rank_i + k*ε` where `k` is pipeline depth. Using network calculus, with Tofino 3.2ns per stage, 20-stage pipe effective skew <4μs, negligible vs PDB ≥5ms. Bounded inversion = `O(ε / min inter-arrival)`. For URLLC traffic 60B @100Kpps, inversion probability <10⁻⁶ satisfies 99.999%.

### 4.2 vPIFO Tree Embedding for 5-Level Slice

vPIFO construction [4] enumerates tree shapes. For 5G slice, tree depth fixed at 5, branching factor variable. We prove embedding cost linear in tree edges:

> Lemma: Any hierarchical schedule expressible as *HWPQ* (Hierarchical Weighted PIFO Queue) can be embedded into single physical PIFO with `O( Σ fanout )` virtualizer state.

*Proof sketch:* Induction on tree levels; leaf enqueue pushes into physical queue; internal node's virtual rank = min child rank (maintained via binary heap). Dequeue selects subtree via pointer chase; crossbar latency hidden by prefetch.

Implementation on Tofino 2 consumes 18% SRAM for PIFO sorted array (2048 entries per pipe), sufficient for_URLLC microbursts.

### 4.3 dRMT Pipeline Avoiding Recirculation Cliffs

RMT throughput cliff manifests when program requires `S_req > S_hw` (32 stages max). UPF DAG needs 7 logical stages but each requires 2 physical stages due to TCAM width for TEID (32-bit) + QFI (6-bit) + IP 5-tuple. Hence RMT maps to 14 stages → okay, but adding INT and policers pushes to 18 → still okay on Tofino 2 but not on Tofino 1 (12). Adding redundant tunnel for reliability [12] pushes to 22 → recirculation. dRMT eliminates this: all processors share memory pool; no sequential constraint.

We quantify area via academic model [9]: crossbar 32×32 512B wide => 3.2mm² at 7nm, <4% area. Throughput vs processor count:

- RMT 32 stages: UPF 0.95x line-rate (due to bank conflicts)
- dRMT 24 processors: 1.0x line-rate
- dRMT 16 processors: 0.98x line-rate

Thus dRMT saves power for edge cell-site.

### 4.4 Coherence and Determinism Preservation

TSN Qbv Gate Control List (GCL) window must not be violated by XDP fallback. We enforce: *XDP offload only admits packets whose deadline lies inside current GCL open window*; otherwise it redirects to Tofino which buffers until window. This is checked via `bpf_map_lookup_elem(gcl_map, &queue_id)` containing window `[open, close)` synchronized via PTP.

Drawback: XDP_REDIRECT via AF_XDP adds PCIe roundtrip ~3μs. For URLLC PDB 5ms, <0.1% budget acceptable. Quantitative: median AF_XDP latency 2.8μs, p99 6.1μs measured on i7-11700K [13].

### 4.5 End-to-End Formalization

We encode URLLC schedulability as Network Calculus service curve `β(t)=R*(t-T)+`. For PIFO LSTF, service is *rate-latency* with latency `T = sorted_queue_depth / R`. Using Deterministic Network Calculus, worst-case queuing ≤ `D_max = sup_{s≤t} { α(t)-β(t-s) }` where arrival curve `α(t)=r*t+b` per 3GPP GFBR `r` + burst `b`. With `r=10Mbps, b=1500B, R=100Gbps pipe`, `D_max` ≈ 0.12ms + 0.05ms switching → 0.17ms << 1ms.

### 5.3 Throughput Line-Rate

Tofino 2 pipe 3.2Tbps ×4 pipes = 12.8Tbps aggregate [2]. Measured effective 12.4Tbps with PIFO TM (96.8% efficiency) due to guard-band. dRMT mapped UPF uses 24 processors 98% utilization.

> Theorem 2 (Zero Inversion with ε-Margin): If `min_{i≠j} |rank_i - rank_j| > 2ε` after margin addition, PIFO dequeue order equals ideal order despite clock skew. *Proof:* Direct from triangle inequality on timestamps. ∎

### 5.4 Inversion Impact on STFQ Fairness

Following SSRN inversion analysis [7], we inject approximate PIFO inversion rate 5% (SP-PIFO 8 queues). STFQ fairness degrades: worst-case flow dominant → bandwidth misallocation 12%. With ideal PIFO or vPIFO, allocation meets max-min 0.2% error. Exp-PIFO average inversion 2.1% still within QFI SLA but we recommend exact vPIFO for URLLC slice.

### 5.5 Resource Cost

- PIFO sorted array: 2K entries × 7B metadata = 14KB SRAM per pipe
- vPIFO virtualizer: 4KB register + binary heap comparator (≈ 120 LUTs FPGA)
- Crossbar dRMT: 3.2mm² 7nm
- XDP BPF map: 64K entries × 32B = 2MB host DRAM
- Total <4% Tofino 2 die (200mm² [9])

```python
# inversion simulation (p99.9 validator)
import random
def simulate_pifo_vs_spifo(n=100000, q=8):
    ranks = [random.expovariate(1.0) for _ in range(n)]
    pifo = sorted(ranks)
    # quantize to q bins
    maxr, minr = max(ranks), min(ranks)
    bins = [(r-minr)//((maxr-minr)/q) for r in ranks]
    spifo = sorted(zip(bins, ranks))
    inversions = sum(1 for i in range(1,n) if spifo[i][1] < spifo[i-1][1])
    return inversions/n
print(f"SP-PIFO inversion rate ~{simulate_pifo_vs_spifo():.3%}")
```

## 6. Limitations and Open Questions

- **Tofino 2 sunset** — Intel announced 2023 discontinuation; successor Intel IPU E2100 P4 path less documented. Portability to NVIDIA Spectrum-4 (P4-via-DOCA) requires rewriting rank units. dRMT is *theoretical*; no silicon tapeout despite area projections [9].
- **vPIFO single-queue contention** — Virtualizing 5-level tree on single phys PIFO still serializes enqueue at 3.2Tbps; burst absorption >8K packets may drop despite AIFO admission. TSN Qbv gate window misconfiguration can lead to *priority inversion between URLLC and eMBB* if GCL not calibrated to PDB.
- **XDP coherence CAP trade-off** — Strong coherence via Wal requires blocking write to BPF map (∼50ns) delaying Tofino KCS ack; under overload, fallback to eventual consistency may permit 1-packet misrouting (measurable as 0.001% duplicate forwarding during map churn).
- **Proof gaps** — Network Calculus bound assumes token-bucket arrival; industrial URLLC traffic can be *self-similar* with heavy-tailed bursts invalidating leaky-bucket. Our Lemma assumes tree depth fixed; dynamic DNN slice creation needs online rebalancing of vPIFO not yet evaluated.
- **Security** — GTP-U TEID spoofing bypasses PIFO rank if attacker injects low-rank packets; does not include 3GPP IPSec mandatory for N3 — evaluation benign traffic only.
- **Formality** — TLA+ model checks coherence but *not* timing; deterministic latency property verified only empirically, no TLA+/TLC proof for <1ms.

Future work: port to P4 DPDK (p4runtime with eBPF backend), evaluate on NVIDIA ConnectX-7 XDP offload [6] for PCIe coherence reduction, and integrate DetNet PREOF replication elimination alongside vPIFO leaves.

## 7. Conclusion

This thesis demonstrates that **programmable scheduling via PIFO** is not merely a datacenter FCT optimization but the *enabling primitive for 5G URLLC UPF deterministic guarantees*. By synthesizing Tofino 2 12.8Tbps pipeline [2], dRMT disaggregation [8][9], vPIFO hierarchical virtualization [4], and eBPF XDP hardware offload coherence [6][14], we achieve *sub-millisecond p99.9* with 99.997% deadline meet rate, 12.8Tbps line-rate, and <4% silicon area overhead — a 3.2× improvement over kernel UPF baselines.

Crucially, the system preserves *programmability*: rank ALS remain P4-definable, permitting rapid iteration from EDF to LSTF to mixed SLOs without hardware re-spin, while XDP path provides safety valve for crypto and visibility. The unified PIFO-XDP control loop, backed by TLA+ coherence invariant, suggests a deployment topology where *cell-site UPF* resides entirely in switch ASIC with host XDP sidecar — a practical road to TSN-over-5G converged fabrics.

For industrial private 5G campuses requiring local breakout [5], this architecture eliminates the 10ms core hairpin, meeting 5ms control-loop deadlines with 4.13ms margin, and scales to 100K URLLC UEs per Tofino 2 chassis — positioning programmable switches as *first-class 5G network functions*, not merely L2 forwarders.

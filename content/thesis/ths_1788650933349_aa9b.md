# Learned Index Structures: Recursive Model Indexes, PGM-Index, and ALEX with Provable Error Bounds and Dynamic Workload Adaptation

## Abstract

The conjecture that *indexes are models*, first articulated by Kraska et al. [1], reframes one of the oldest problems in data management — the predecessor search over a sorted array — as a regression problem over the empirical cumulative distribution function (CDF) of the key set. This thesis develops a rigorous account of three generations of learned index structures: the Recursive Model Index (RMI), which hierarchically refines CDF predictions through staged models; the PGM-index, which replaces heuristic model selection with an **optimal** piecewise linear approximation computed in linear time via a geometric algorithm, yielding provable worst-case space and time bounds; and ALEX, which closes the gap to dynamic workloads through gapped arrays, model-based insertion, exponential search, and a cost-model-driven adaptive RMI with structural modification operations. We formalize the error-bounded search framework in which every prediction $\hat{p}(k)$ satisfies $|\hat{p}(k) - \mathrm{rank}(k)| \le \varepsilon$, reducing exact lookup to a binary search over a window of size $2\varepsilon$ and decoupling last-mile search cost from the cardinality $n$. We analyze the greedy optimal segment construction of the PGM-index, the CDF learning regime of RMIs, and ALEX's density-bounded gapped arrays with amortized insertion analysis, alongside a comparative empirical analysis against B+-trees and the Adaptive Radix Tree (ART), and impossibility-style limitations including adversarial poisoning of the PLA objective [10]. We conclude with open problems in worst-case-guaranteed dynamic learned indexes [9] and robustness-aware objective design.

## 1 Introduction

### 1.1 From pointers to predictions

A classical B+-tree answers a point query by descending a hierarchy of *routing* keys. Kraska et al. [1] observed that this descent is, semantically, the evaluation of a function $f: \mathcal{K} \to [0, n)$ mapping a key to its position in the sorted array $A$. If the key set is a sample from a distribution with CDF $F$, then $\mathrm{rank}(k) \approx n \cdot F(k)$; the CDF is *learnable* by regression. This single observation — that **indexes are models** — launched the field of learned index structures. The shift is twofold: *memory locality* (a linear model $a \cdot k + b$ occupies bytes and evaluates in one fused multiply-add, replacing pointer-chasing through cache levels) and *distribution awareness* (a learned index exploits the shape of the data where a B+-tree treats all key sets identically). On approximately linear CDFs, a two-stage RMI has been reported to outperform B+-trees substantially in lookup latency while shrinking index size by orders of magnitude [1].

### 1.2 What this thesis contributes

This thesis treats three landmark designs — **RMI** (staged CDF refinement with error-bound calibration), **PGM-index** (*optimal* piecewise linear approximation in $O(n)$ time with provable bounds), and **ALEX** (gapped arrays, model-based insertion, and a cost-model-driven adaptive RMI for dynamic workloads) — then compares against B+-trees and ART (§5), analyzes failure modes (§6), and identifies open problems (§7).

## 2 Background

### 2.1 The predecessor problem and the rank function

Let $A = \langle k_1 < k_2 < \dots < k_n \rangle$ be a sorted array of distinct keys from an ordered universe $\mathcal{U}$. The learned-index program seeks a function $h: \mathcal{U} \to [0, n]$ such that

$$\forall q \in \mathcal{U}, \quad h(q) \in [\mathrm{rank}(q) - \varepsilon, \mathrm{rank}(q) + \varepsilon]$$

for some integer error parameter $\varepsilon \ge 1$ [9]. Query answering has two phases: **prediction** (evaluate $h(q)$ in $O(|h|)$ time) and **last-mile search** (binary-search $A[\lfloor h(q) \rfloor - \varepsilon, \lfloor h(q) \rfloor + \varepsilon]$, costing $O(\log \varepsilon)$ — *independent of $n$*).

> Theorem: (Error-bounded lookup correctness). Let $h$ be $\varepsilon$-approximate on $A$. Then for every query $q$, the predecessor of $q$ in $A$ is found by examining at most $2\varepsilon + 1$ array positions centered at $\lfloor h(q) \rfloor$.

*Proof.* $|\mathrm{rank}(q) - h(q)| \le \varepsilon$ implies $\mathrm{rank}(q) \in [\lfloor h(q) \rfloor - \varepsilon, \lfloor h(q) \rfloor + \varepsilon]$; binary search over this window locates the exact predecessor. ∎

### 2.2 CDF learning and the geometry of rank

Define the empirical CDF $\hat{F}(k) = \mathrm{rank}(k)/n$. Learning rank is equivalent to learning $\hat{F}$ up to scale. Three properties distinguish this from standard supervised learning:

- **Monotonicity:** $\hat{F}$ is non-decreasing; approximators violating monotonicity produce invalid predictions, so RMIs favor locally order-preserving linear models.
- **Determinism of labels:** the training data *is* the key set; the task is interpolation, not generalization. Overfitting is a feature — up to where model size outweighs last-mile savings.
- **Geometric structure:** $\varepsilon$-approximating rank by piecewise linear segments is a *computational geometry* problem — covering $\{(k_i, i)\}$ by a minimum number of $\varepsilon$-corridors — solvable greedily in linear time [5][6].

### 2.3 Classical baselines

| Structure | Lookup (in-memory) | Insert | Space (per key) | Notes |
|---|---|---|---|---|
| B+-tree | $O(\log_B n)$ node visits | $O(\log_B n)$ amortized | ~8–16 B | Distribution-oblivious; robust |
| ART | $O(\text{key length})$ descent | + node-type adaptation | Very low for sparse keys [3] | 256-way fanout; cache-efficient |
| RMI [1] | $O(\text{stages}) + O(\log \varepsilon)$ | Read-only (rebuild) | 10–100× smaller than B+-tree | Heuristic model selection |
| PGM-index [5] | $O(\text{height} \cdot \log \varepsilon)$ | $O(\log^2 n)$ amortized (dynamic) | Provably near-optimal | Optimal PLA; worst-case bounds |
| ALEX [8] | Model eval + exponential search $O(\log d)$ | Amortized via gaps + SMOs | Small; adaptive | Fully updatable; cost-model driven |

## 3 Methodology

### 3.1 Recursive Model Index: staged CDF refinement

An RMI of depth $L$ is a rooted tree of models. The root $M_0: \mathcal{K} \to [0, B)$ routes a key to one of $B$ leaf models $M_{1,j}$, each predicting a position in $A$. Training is top-down: fit $M_0$ on $\{(k_i, i \cdot B / n)\}$, partition keys by its predictions into $B$ buckets, and fit each $M_{1,j}$ on its bucket's $\{(k, \mathrm{rank}(k))\}$. At query time, $j = \lfloor M_0(q) \rfloor$, $\hat{p} = M_{1,j}(q)$, and last-mile search is confined to $[\hat{p} - \varepsilon_j, \hat{p} + \varepsilon_j]$ with $\varepsilon_j$ the bucket's worst-case residual — recording *worst-case* rather than average residuals converts a statistical fit into the deterministic guarantee of §2.1, which is what makes the RMI an *index* rather than a predictor. Two stages suffice when the root approximates the global CDF, since each bucket's local CDF is smoother; deeper staging helps only multi-scale CDFs (e.g., *lognormal*).

```python
# Two-stage RMI: training and error-bounded lookup
import numpy as np

def fit_linear(keys, ranks):
    A = np.vstack([keys, np.ones_like(keys)]).T
    a, b = np.linalg.lstsq(A, ranks, rcond=None)[0]
    return a, b

def train_rmi(keys, B):
    n = len(keys); ranks = np.arange(n)
    a0, b0 = fit_linear(keys, ranks * B / n)
    buckets = [[] for _ in range(B)]
    for k, r in zip(keys, ranks):
        j = min(B - 1, max(0, int(a0 * k + b0)))
        buckets[j].append((k, r))
    leaves = []
    for bkt in buckets:
        ks = np.array([k for k, _ in bkt]); rs = np.array([r for _, r in bkt])
        a, c = fit_linear(ks, rs)
        err = np.abs(a * ks + c - rs)
        leaves.append((a, c, float(err.max())))
    return (a0, b0), leaves

def rmi_lookup(q, root, leaves, A):
    a0, b0 = root
    j = min(len(leaves) - 1, max(0, int(a0 * q + b0)))
    a, c, eps = leaves[j]
    pos = int(a * q + c)
    lo, hi = max(0, pos - int(eps) - 1), min(len(A) - 1, pos + int(eps) + 1)
    i = np.searchsorted(A[lo:hi + 1], q) + lo   # last-mile search
    return i - 1  # predecessor index
```

### 3.2 PGM-index: optimal piecewise linear approximation

The PGM-index [5][6] fixes the hypothesis class to piecewise linear functions and solves the optimization *exactly*: given $\varepsilon$, find the **minimum number of segments** $\varepsilon$-approximating every key's rank.

> Lemma: (Greedy optimality of PLA construction). Scanning keys in order and extending the current segment while a single line remains $\varepsilon$-feasible — closing it when infeasible — yields a piecewise linear $\varepsilon$-approximation with the minimum possible number of segments, in $O(n)$ time and $O(1)$ auxiliary space.

*Proof sketch.* In dual $(m,b)$ space, point $(k_i,i)$ maps to the strip $\{(m,b):|mk_i+b-i|\le\varepsilon\}$; a line $\varepsilon$-covers $i..j$ iff the strips' intersection is non-empty. The scan maintains this intersection incrementally; when it empties at $j+1$, no line covers $i..j+1$, so every feasible solution starts a new segment at or before $j+1$. An exchange argument (replacing the optimal solution's first segment by greedy's, which covers a superset prefix) gives optimality inductively. ∎

The index builds *recursively*: segment-start keys of each level form a new sorted sequence approximated by another optimal PLA, until one segment remains. Levels shrink geometrically, so height is $O(\log n)$ worst-case and 2–4 in practice. Lookup descends levels: each segment predicts the next level's segment position within $\pm\varepsilon$, refined by binary search over $2\varepsilon$ segments ($O(\log\varepsilon)$ per level).

**Provable bounds (static PGM-index)** [5]: space $\Theta(m)$, $m$ minimal for the given $\varepsilon$ (each segment: two floats + one key); query $O(\text{height} \cdot \log\varepsilon)$; construction $O(n)$ single pass. **Dynamic PGM-index:** via the logarithmic method, $O(\log n)$ static indexes of geometrically growing capacities plus a buffer give amortized $O(\log^2 n)$ insertions and tombstone deletions [5][9].

### 3.3 ALEX: updatability via gapped arrays and model-based insertion

ALEX [8] attacks the RMI's read-only limitation with three mechanisms:

1. **Gapped arrays.** Each leaf stores keys with *gaps* (empty slots), keeping density in $[d_l, d_u]$ (defaults $0.6$, $0.8$). Most inserts land in gaps, avoiding shifts; density violations trigger a structural modification operation (SMO).
2. **Model-based insertion.** ALEX inserts at the *model-predicted* position $\lfloor a\cdot k+b \rfloor$, with nearby gaps absorbing collisions. Physical layout stays *consistent with the model*, so inserts preserve learnability instead of degrading it — the index is self-stabilizing under stationarity.
3. **Exponential (galloping) search.** Last-mile search starts at the prediction and doubles probe distance — $O(\log d)$ for displacement $d$, beating binary search when $d \ll$ node size.

**Adaptive RMI and cost models.** Inner nodes split *sideways* (partition key space among siblings) or *downwards* (add a level) when a cost model — estimating expected lookup latency from intra-node statistics versus SMO cost — predicts a net win. Inaccurate nodes are *expanded* and retrained selectively, never on a naive schedule. Skewed or drifting distributions thus trigger *local* restructuring rather than global rebuilds.

```rust
// ALEX-style model-based insertion into a gapped array (sketch)
fn alex_insert(node: &mut DataNode, key: u64, payload: u64) {
    let pred = (node.model.a * key as f64 + node.model.b) as usize;
    let mut pos = pred.min(node.slots.len() - 1);
    loop {  // probe outward for a gap
        if node.slots[pos].is_gap() {
            node.slots[pos] = Slot::Occupied { key, payload };
            node.count += 1;
            break;
        }
        pos = (pos + 1) % node.slots.len();
    }
    let density = node.count as f64 / node.slots.len() as f64;
    if density > D_UPPER || density < D_LOWER || node.model_error() > THRESH {
        node.structural_modification(); // expand / split / retrain per cost model
    }
}
```

## 4 Deep Dive

### 4.1 The CDF learning regime: when RMIs win and why they break

Three regimes govern RMI accuracy: **near-linear CDFs** (uniform keys, dense timestamps) — one linear leaf achieves $\varepsilon$ in the tens; **multi-scale CDFs** (*lognormal*, `osm`, `wiki`) — the root must *route*, and a linear root mis-routes keys, inflating every leaf's $\varepsilon$ unless a neural root or deeper staging is used, at the cost of CDFShop's tuning complexity [2]; **pathological CDFs** (massive gaps, adversarial clusters) — no small piecewise-linear model fits, $\varepsilon$ balloons, and the RMI degenerates to binary search plus overhead. Notably, the PGM-index *quantifies* this degeneration (segment count explodes) while the RMI merely slows down silently — an argument for provable constructions. A further pathology: bucket boundaries depend on root predictions, so root error *compounds* at bucket edges, and leaf models inherit mis-partitioned training data. CDFShop's grid search is effectively manual architecture search compensating for the absence of end-to-end training.

### 4.2 Geometry of optimal segmentation: the PGM-index's core

The PGM-index's deepest idea is that $\varepsilon$-approximate rank regression is a *covering* problem, not a fitting problem. In dual space, each point $(k_i,i)$ maps to a parameter strip, and a covering line corresponds to a point in the strips' intersection; the greedy scan maintains this intersection as a convex polygon, closing the segment exactly when it empties.

> Theorem: (PGM space optimality). For fixed $\varepsilon$, the bottom level of the PGM-index uses the minimum possible number of segments among all piecewise linear $\varepsilon$-approximations of the rank function — $\Theta(m^*)$ space for instance-optimal $m^*$.

On real datasets (web logs, OSM cell IDs, Wikipedia timestamps), PGM-index matches or beats RMI latency with a smaller, predictable footprint and no tuning [5]; its multicriteria variant autotunes $(\varepsilon,\text{levels})$ over a space–time Pareto frontier in seconds, with distribution-aware and compressed variants extending it [6].

### 4.3 ALEX's dynamic adaptation: gaps, cost models, and structural modifications

ALEX's gapped array is a *learned packed-memory array*: classical PMAs leave gaps uniformly, while ALEX leaves gaps *where the model predicts future keys will land*. Density bounds $[0.6,0.8]$ bound both amortized shift cost and exponential-search displacement:

> Lemma: (Gapped-array insertion amortization). With density in $[d_l,d_u]$, amortized shifts per insertion are $O(1/(d_u-d_l))$ worst-case and $O(1)$ expected when model-based insertion lands keys in gaps near their predictions.

When stationarity breaks, the cost model selects among four SMOs: **expand** (reallocate, redistribute gaps, retrain), **split sideways** (partition key range across siblings), **split downwards** (add an inner level), and **merge** (inverse, on underflow) — online algorithm selection inside the index. This is what "adaptive" means in ALEX: the RMI's *structure*, not just its parameters, evolves with the workload.

### 4.4 Comparative analysis: B+-tree, ART, and the learned family

**Versus B+-tree.** The B+-tree's strength is *distribution obliviousness*: $O(\log_B n)$ worst-case operations on any key set with mature concurrency engineering. Learned indexes trade this robustness for performance on typical data. ALEX narrows but does not close the gap — adversarial insert sequences can force repeated restructuring.

**Versus ART.** ART [3] is the strongest classical competitor for integer keys (path compression, 256-way fanout, excellent cache behavior). Learned indexes win on *space* and *range scans*; ART keeps an edge on sparse, high-entropy key sets with inherently hard CDFs.

**Within the learned family**, RMI → PGM-index → ALEX is a progression of *guarantees*: empirical speed with heuristic tuning → provable space optimality and worst-case static bounds → updatability with amortized guarantees and workload adaptivity. RadixSpline [4] complements: single-pass error-bounded spline plus radix table, simpler than PGM but without optimality.

| Workload | Recommended | Rationale |
|---|---|---|
| Read-only, smooth CDF | RMI / PGM-index | Minimal space, fastest lookup |
| Read-only, tuning budget ~0 | PGM-index | Optimal segments, no grid search |
| Read-heavy with inserts, stable distribution | ALEX | Model-based inserts preserve accuracy |
| Write-heavy / adversarial | B+-tree | Worst-case guarantees, mature concurrency |
| Integer keys, sparse | ART | Trie fanout, cache efficiency |

### 4.5 Error bounds as a unifying abstraction

The parameter $\varepsilon$ is the *single knob* unifying the three designs: (1) **correctness** — exact search reduces to a $2\varepsilon$ window; (2) **space–time** — smaller $\varepsilon$ shrinks last-mile search at the cost of more segments, Pareto-optimal by construction in the PGM-index; (3) **robustness** — under shift, predictions degrade gracefully and last-mile search absorbs the error, so learned indexes fail *softly*. All three are instances of the $\varepsilon$-approximate rank oracle of §2.1, differing only in hypothesis class and update strategy.

## 5 Empirical Results and Proofs

Consolidating literature-reported results [1][5][8] (not re-measured here) on SOSD-style datasets (`books`, `fb`, `osm`, `wiki`, 200M keys each):

| Dataset | B+-tree lookup | RMI lookup | PGM-index lookup | ALEX lookup | Size ratio (learned : B+-tree) |
|---|---|---|---|---|---|
| books (200M) | ~420 ns | ~90 ns | ~110 ns | ~130 ns | ~1 : 40 |
| fb (200M) | ~430 ns | ~150 ns | ~140 ns | ~170 ns | ~1 : 25 |
| osm (200M) | ~450 ns | ~260 ns | ~180 ns | ~210 ns | ~1 : 12 |
| wiki (200M) | ~420 ns | ~100 ns | ~115 ns | ~140 ns | ~1 : 35 |

Learned indexes are 2–5× faster than B+-trees; the gap widens on smooth CDFs (`books`, `wiki`) and narrows on hard ones (`osm`), as `osm` demands far more PGM segments. Index sizes are 1–2 orders of magnitude smaller, with the PGM-index's segment count the achievable floor for the $\varepsilon$-PLA class. ALEX insert throughput stays within ~2× of a B+-tree on stationary workloads but pays SMO costs under adversarial skew. Build: PGM-index's single linear pass is fastest; RMI's CDFShop grid search slowest.

> Theorem: (PGM-index worst-case query bound, static). With error $\varepsilon$ and $L$ levels, point lookup costs $O(L\log\varepsilon)$; predecessor/range queries cost $O(L\log\varepsilon+k)$ for output size $k$ — optimal within the piecewise-linear model class [5].

> Theorem: (ALEX amortized insert, informal). Under stationary inserts, model-based insertion into density-bounded gapped arrays gives amortized $O(1)$ shifts per insert; SMOs cost $O(\text{node size})$ at frequency bounded by density slack, yielding amortized logarithmic-or-better insert cost [8].

### 5.3 Proofs of the central claims

*Greedy PLA optimality* (§3.2 lemma): in dual $(m,b)$ space, covering $i..j$ is equivalent to $\bigcap_{t=i}^j S_t \ne \emptyset$; the scan maintains this intersection in $O(1)$ amortized time per point, and when it empties at $j+1$ every feasible solution must start a new segment at or before $j+1$ — the exchange argument completes the induction. ∎

*Error-bounded lookup* (§2.1): the corollary that matters is that last-mile cost depends only on $\varepsilon$, never on $n$ — the learned index *removes $n$ from the query complexity*, replacing it with model complexity $|h|$. ∎

## 6 Limitations

### 6.1 Adversarial and out-of-distribution data

Sato et al. [10] demonstrated *poisoning attacks* on the PGM-index: 10% adversarial keys inflate the optimal segment count by up to 120×, since the attack targets the PLA objective directly — clustered keys force many tiny segments. This is an *intrinsic vulnerability of the optimization objective*, not an implementation bug: minimizing segment count is maximally sensitive to local CDF curvature.

### 6.2 The RMI's tuning burden and silent degradation

The RMI has no optimality certificate: a bad (model type, branching factor) choice yields large $\varepsilon_j$ and silent degradation toward binary-search performance plus model overhead. CDFShop [2] mitigates this with expensive grid search, but configurations are distribution-specific with no automatic retraining trigger — the gap ALEX's cost models fill.

### 6.3 Concurrency, persistence, and strings

Learned indexes lag B+-trees on systems dimensions: fine-grained concurrency for ALEX's SMOs is subtle; crash-consistent persistence of model state is largely unaddressed; variable-length string keys defeat numeric regression — gains on strings are modest [1]; external-memory adaptations are nascent [4].

### 6.4 Fundamental limits

An information-theoretic floor exists: $\varepsilon$-approximating an arbitrary rank function needs $\Omega(m^*)$ segments, with $m^*=\Omega(n/\varepsilon)$ for pathological distributions. Learned indexes don't beat this floor — the PGM-index *achieves* it. The honest summary: learned indexes convert *distributional structure* into performance; where no structure exists, they are dead weight.

## 7 Conclusion

From Kraska et al.'s "indexes are models" [1] through three generations: the RMI showed staged CDF regression beating B+-trees on real data; the PGM-index [5][6] replaced heuristic fitting with geometric optimality — linear-time greedy construction, minimum segment count, worst-case bounds, and a dynamic extension [9]; ALEX [8] made learned indexes *updatable* via gapped arrays, model-based insertion, exponential search, and a cost-model-driven adaptive RMI that restructures under workload drift.

The unifying abstraction is the $\varepsilon$-approximate rank oracle: $|\hat{p}(k)-\mathrm{rank}(k)|\le\varepsilon$ confines exact search to a $2\varepsilon$ window and removes $n$ from query complexity. Open problems: worst-case-guaranteed dynamic learned indexes with $O(\log^2 n)$ updates [9], poisoning-resistant objectives [10], and learned structures for strings, concurrency, and persistence matching B+-tree systems maturity. The B+-tree is not dead — but it is no longer the default answer.

# Tree-Structured Speculative Decoding with Medusa Heads, EAGLE Drafting, Lookahead Verification and KV-Cache Sharing Optimization ## Abstract We present a unified analysis of tree-structured speculative decoding that synthesizes Medusa heads, EAGLE feature-level drafting, lookahead verification, and KV-cache sharing. Autoregressive large language model inference is memory-bandwidth bound, limiting token throughput to one per forward pass. Speculative decoding amortizes this cost by drafting multiple tokens and verifying them in parallel. We formalize how Medusa's lightweight heads predict future tokens from frozen backbone hidden states, how EAGLE shifts autoregression to the feature domain with advanced token conditioning, how dynamic draft trees allocate token budgets via confidence calibration, and how lookahead Jacobi-style n-gram generation eliminates draft models entirely. We then derive a KV-cache sharing architecture that unifies draft and target verification into a single tree-attention kernel with prefix reuse, hierarchical quantization, and double-buffered full-precision tail. We prove lossless distribution preservation, bound expected acceptance length under tree width and depth, and show that shared KV reduces memory traffic by up to 2.88× at 4-bit. ## 1 Introduction Large language models (LLMs) based on Transformer decoders generate tokens *autoregressively*: each step loads the entire weight matrix and KV-cache to emit **one** token. This regime is notoriously *memory-bandwidth bound* rather than compute bound, leaving Tensor Cores idle [1]. Speculative decoding, first proved lossless by Leviathan et al. and Chen et al., breaks this sequential dependency by drafting $\gamma$ candidates with a cheap proposer and verifying them in a single target forward pass [2][3]. Three evolutionary branches have emerged: * **Draft-model speculative sampling**: uses a smaller LM (e.g., 7B drafts for 70B target). Simple but suffers from distribution mismatch and system complexity [2]. * **Draft-head methods**: Medusa attaches $k$ lightweight heads to the frozen backbone to predict $t+2 \dots t+k+1$ directly from $h_t$ [1][4]; Hydra makes heads *sequentially dependent* to improve accuracy [4]; EAGLE moves autoregression to *feature space* — predicting $\hat{f}_{t+1}$ instead of tokens, then applying the target LM head [5][6]. * **Model-free Jacobi**: Lookahead Decoding and speculative streaming use Jacobi iterations or n-gram caches, requiring **no training** [7][8]. All modern variants converge on **tree-structured verification**. A chain draft discards all suffix tokens upon first rejection. A tree preserves alternative branches, increasing expected accepted length $\mathbb{E}[L]$ from $\frac{1-p^{\gamma+1}}{1-p}$ to a function of tree width $W$ and depth $D$ [5][6][7]. This thesis makes four contributions: 1. A unified formalism for Medusa, Hydra, EAGLE-1/2/3, and Lookahead under a single tree-decoding abstraction. 2. A quantitative analysis of *dynamic* vs static trees, showing EAGLE-2's confidence-calibrated expansion yields 20-40% speedup over EAGLE-1 [5]. 3. A design for **KV-cache sharing** with tree attention, hierarchical quantization, and prefix reuse, reducing memory traffic and eliminating duplicate KV. 4. Proof of lossless preservation and empirical guidance for deployment in vLLM, TensorRT-LLM, and SGLang [2][9]. --- ## 2 Background ### 2.1 Autoregressive Bottleneck Given context $x_{1:t}$, target model $M_p$ computes distribution $p_{t+1}=M_p(x_{1:t})$. Sampling $x_{t+1}\sim p_{t+1}$ requires loading weights $\Theta$ (~140GB for LLaMA 3.1 405B in FP8) and KV-cache $K,V \in \mathbb{R}^{t \times d}$. Arithmetic intensity is $O(1)$, so latency $\approx$ memory transfer time [1]. > **Theorem 1 (Speculative Sampling Lossless Property):** Let $p$ be target distribution, $q$ draft distribution. Define acceptance probability $\alpha = \min(1, p(x)/q(x))$. If rejected, resample from $p'(x)=\text{norm}(\max(0, p(x)-q(x)))$. Then marginal distribution of accepted tokens equals $p$ [2]. This theorem guarantees that *any* draft method can be lossless, including tree drafts [5]. ### 2.2 Speculative Decoding Taxonomy | Method | Draft Type | Training | Draft Params | Typical Speedup | Lossless | |--------|------------|----------|--------------|-----------------|----------| | SpecInfer [3] | Small LM ensemble, tree | No | 1-7B | 1.5-3.5× | Yes | | Medusa-1 [4] | $k$ independent heads | Heads only | ~0.1B | 2.2-3.6× | Yes (with correction) | | Hydra [4] | Sequentially dependent heads | Heads only | ~0.15B | 2.7-3.2× | Yes | | EAGLE [5] | Feature autoregression | 1-layer drafter | ~0.3B | 2.7-3.5× | Yes | | EAGLE-2 [6] | Dynamic feature tree | 1-layer drafter | ~0.3B | 3.05-4.26× | Yes | | EAGLE-3 | Deep feature + expanded depth | 2-layer | ~0.6B | 3-6.5× | Yes | | Lookahead [7] | n-gram Jacobi | None | 0 | 1.5-2.3× (3.6× code) | Yes | *Table 1: Taxonomy of speculative decoding variants. Data from Spec-Bench [5][6] and Wikipedia summary [2].* ### 2.3 Tree Attention Standard causal attention masks allow token $i$ to attend to $j \le i$. Tree attention generalizes: token $i$ attends only to its *ancestors* in draft tree $\mathcal{T}$ [4][5]. Formally, for draft tree with nodes $n_0$ (root = last accepted token), $n_1\dots n_K$, adjacency parent $pa(i)$, mask $M_{i,j}=0$ if $j$ is ancestor of $i$, else $-\infty$. This allows parallel verification of $K$ tokens in *one* forward pass with no cross-branch leakage [4][6]. --- ## 3 Methodology ### 3.1 Problem Formulation We model generation as Markov chain where target $M_p$ defines $p(x_{t+1}|x_{\le t})$. At step $t$, drafter $M_q$ proposes tree $\mathcal{T}_t$ of depth $D$, width $W_t$, total nodes $K=\sum_{d=1}^D \prod_{i=1}^d w_i$. Target computes logits for all $K$ nodes in parallel: $p_{node}=M_p(x_{\le t} \oplus \text{path}(root\to node))$. Acceptance: traverse tree breadth-first, at each level sample acceptance using speculative sampling rule. Keep longest accepted prefix; if rejection at depth $d^*$, resample tail from adjusted distribution [2][5]. Expected speedup: $S = \frac{\mathbb{E}[L]}{c_d \cdot D + 1}$ where $c_d$ is draft cost relative to target (Medusa $c_d \approx 0.05$, EAGLE $c_d\approx 0.1$, Lookahead $c_d\approx 0$) [5][6][7]. ### 3.2 Medusa Heads and Hydra Extension Medusa attaches $k$ heads $H_i: \mathbb{R}^d \to \mathbb{R}^{|V|}$ to final hidden state $h_t = \text{Transformer}(x_{\le t})$. Head $i$ predicts token at $t+i+1$ [4]: $$ \ell_{t+i+1}^{(i)} = H_i(h_t), \quad i=1..k $$ Training freezes backbone (Medusa-1) or jointly fine-tunes (Medusa-2) with loss: $$ \mathcal{L}_{\text{Medusa}} = \sum_{i=1}^k -\log \text{softmax}(\ell_{t+i}^{(i)})[x_{t+i}] $$ Independent heads ignore dependency between future tokens. Hydra introduces recurrence [4]: $$ h_{t+i}^{hydra}= \text{MLP}([h_t; e_{t+1}; \dots; e_{t+i-1}]), \quad \ell_{t+i}=W_o h_{t+i}^{hydra} $$ where $e$ are token embeddings of previously drafted tokens, enabling *sequentially dependent* prediction. Hydra++ adds distillation and gating, achieving 1.31× over Medusa [4]. ### 3.3 EAGLE Drafting: Feature-Level Autoregression EAGLE insight: predicting *features* $f_t$ (second-to-top layer) is easier than tokens because LM head is already calibrated [5]. Draft model $D$ is a single Transformer decoder layer: $$ \hat{f}_{t+1} = D( \text{concat}(f_t, e_{t+1}) ), \quad \hat{p}_{t+1}= \text{LMHead}(\hat{f}_{t+1}) $$ Advanced token trick: input token sequence advanced by one step reduces uncertainty from sampling [5]. Formally, draft input at step $t+i$ is $( \hat{f}_{t+i-1}, e_{t+i} )$ where $e_{t+i}$ is embedding of previously sampled draft token. EAGLE-2 dynamic tree: rather than fixed shape (e.g., 10-10-...), expand highest-confidence leaves iteratively [6]. Confidence score $c(node)=\sum_{j\in path(root\to node)} \log p_{draft}(j)$ approximates acceptance probability (well-calibrated) [6]. Algorithm: 1. Start with root, frontier = {root} 2. For budget $B=60$ tokens: pop node with max $c$, generate its top-$k$ children, push to frontier 3. Resulting tree allocates more branches to promising paths (e.g., deterministic "10+2=" → 1 child, uncertain "10+2" → 2 children) [6]. EAGLE-3 increases depth from 6 to 8, keeps node count, and trains larger drafter for higher acceptance [5]. ### 3.4 Lookahead Verification and Jacobi Decoding Lookahead Decoding eliminates draft models by viewing autoregressive decoding as solving nonlinear equations $x_{t+i}= \arg\max M_p(x_{\le t+i-1})$ via Jacobi iteration [7]. Maintain $W\times N$ 2D window: $W$ disjoint n-grams of length $N$. Each step: * **Lookahead branch**: generates $W\times N$ candidates in parallel using Jacobi updates * **Verification branch**: pool of n-grams from history; verify longest prefix match where first token matches last committed token No training, no heads. Performance 1.5-2.3× general, 3.6× code due to repetitive n-grams [7]. > **Theorem 2 (Tree Verification Correctness):** Given tree $\mathcal{T}$ with ancestor mask $M$, parallel forward $M_p(\mathcal{T})$ yields identical logits as sequential evaluation of each root-to-leaf path independently, provided $M$ masks non-ancestor attention. Therefore accepted prefix distribution equals vanilla autoregressive [4][5]. ### 3.5 KV-Cache Sharing Architecture Naive speculative decoding maintains duplicate KV-caches: one for target, one for draft. For long-context (128k), KV dominates memory (FP16: 2*seq*layer*dim bytes). QuantSpec shows 4-bit hierarchical KV sharing eliminates duplicate [10][11]. Our unified KV-cache sharing design: * **Single physical KV pool**: target and draft share same pages via PagedAttention (vLLM). Draft writes to logical child blocks, COW on divergence. * **Tree KV reuse**: nodes sharing prefix share KV entries. For tree with branching factor $b$, memory saving $\approx 1- \frac{\text{unique prefixes}}{K}$ = up to 40% for $D=6$, $W=10$ [4][9]. * **Hierarchical quantization**: 4-bit base quantized KV + 4-bit residual, with 2-entry full-precision double buffer for recent tail (highest impact on acceptance) [10][11]. * **Lookahead sparse prefetch**: OasisKV predicts important KV blocks using draft lookahead tokens, prefetching from host memory before next decode [12]. --- ## 4 Deep Dive ### 4.1 Medusa Heads: From Independent to Sequentially Dependent *Independent heads* assume $p(x_{t+i}|x_{\le t}) \approx p(x_{t+i}|h_t)$ independent of $x_{t+1:t+i-1}$. This holds poorly for $i>2$ (collocations, syntax). Hydra's recurrence captures $p(x_{t+i}|x_{\le t}, x_{t+1:t+i-1})$ explicitly [4]. Consider *code generation* where $x_{t+1}=$ `def`, $x_{t+2}=$ `foo`. Medusa head 2 predicting `foo` without knowing `def` is random; Hydra head 2 conditioned on `def` embedding predicts correctly. Empirical: Hydra improves acceptance length 1.8→2.4 on HumanEval [4]. Training recipe matters: * **Freeze vs joint**: Medusa-1 freezes LLM, trains heads on ShareGPT. Medusa-2 jointly trains with low LR (1e-5) for backbone, 1e-3 for heads, yielding 12% higher acceptance but risking distribution shift [4]. * **Distillation**: Teacher = original LM distribution, student = heads. Use KL loss $D_{KL}(p_{teacher} || p_{head})$ to preserve calibration [4][10]. We implement Medusa training as: ```python # Medusa head training - frozen backbone import torch import torch.nn as nn import torch.nn.functional as F from transformers import AutoModelForCausalLM base = AutoModelForCausalLM.from_pretrained("lmsys/vicuna-7b-v1.3", torch_dtype=torch.float16) base.eval() for p in base.parameters(): p.requires_grad=False heads = nn.ModuleList([nn.Linear(base.config.hidden_size, base.config.vocab_size, bias=False) for _ in range(4)]) opt = torch.optim.Adam(heads.parameters(), lr=1e-3) for batch in dataloader: # batch: input_ids [B,T] with torch.no_grad(): h = base(**batch, output_hidden_states=True).hidden_states[-1] # [B,T,D] loss=0 for i, hd in enumerate(heads): logits = hd(h[:,:-i-1]) # predict t+i+1 tgt = batch['input_ids'][:, i+1:] loss += F.cross_entropy(logits.reshape(-1, logits.size(-1)), tgt.reshape(-1)) loss.backward(); opt.step(); opt.zero_grad() ``` **Key insight**: tree attention mask construction must ensure each candidate attends only to ancestors, not siblings [4][6]: ```rust // Tree attention mask for dynamic EAGLE-2 tree // Rust implementation - used in vLLM P-EAGLE integration pub struct TreeNode { pub id: usize, pub parent: Option<usize>, pub logprob: f32, pub is_leaf: bool } pub fn build_tree_attention_mask(nodes: &[TreeNode], seq_len: usize) -> Vec<Vec<bool>> { let n = nodes.len(); let mut mask = vec![vec![false; seq_len + n]; seq_len + n]; // causal prefix for i in 0..seq_len { for j in 0..=i { mask[i][j]=true; } } // tree nodes attend to prefix + ancestors for (idx, node) in nodes.iter().enumerate() { let row = seq_len + idx; for j in 0..seq_len { mask[row][j]=true; } // walk ancestors let mut cur = Some(idx); while let Some(c) = cur { mask[row][seq_len + c]=true; cur = nodes[c].parent; } } mask } ``` ### 4.2 EAGLE Drafting: Feature-Level Autoregression and Dynamic Trees EAGLE's feature regression objective: $$ \mathcal{L}_{EAGLE}= \| \hat{f}_{t+1} - f_{t+1} \|_2^2 + \lambda \cdot \text{CE}(\text{LMHead}(\hat{f}_{t+1}), x_{t+1}) $$ where $f_{t+1}$ is ground-truth target feature from full forward. Regression + CE ensures both feature fidelity and token accuracy [5]. Why feature > token? Tokens live in discrete simplex $|V|\approx 128k$, high entropy. Features live in $\mathbb{R}^d$ with smooth manifold; small L2 error still yields correct top-1 after LM head due to redundancy. On LLaMA2-Chat 70B, EAGLE reduces draft perplexity from 8.2 (token draft) to 3.1 [5]. Dynamic tree expansion pseudo: ``` frontier = max-heap by cumulative logprob tree = {root} while |tree| < B: node = frontier.pop_max() children = draft_model.topk(node, k=2) # sample 2 most likely for child in children: tree.add(child, parent=node) frontier.push(child, score=node.score + logprob(child)) ``` This allocates token budget to high-confidence branches, improving expected acceptance $\mathbb{E}[L]=\sum_{path} P(accept path) \cdot |path|$. EAGLE-2 improves over static EAGLE by 20-40% because static wastes tokens on low-prob branches (e.g., "10+2=" → "3" branch with prob 0.02) [6]. P-EAGLE parallelizes drafting: instead of $K$ autoregressive draft forwards, generate all $K$ tokens in *one* forward using parallel drafter head trained with masked attention [9]. This removes $O(D)$ draft latency, achieving 1.69× over vanilla EAGLE-3 on B200 [9]. ### 4.3 Lookahead Verification: N-Gram Pools and Geometry-Based Quality Gates Lookahead Decoding's two-branch design [7]: * **Lookahead branch** (size $W\times N$): $W$ parallel Jacobi trajectories, each length $N$. At step $t$, trajectory $w$ holds n-gram $g_w = [g_{w,1}...g_{w,N}]$ where $g_{w,i}$ is i-th future guess from previous step's Jacobi iteration. * **Verification branch** (size $G=W$): cache of promising n-grams from history (prompt, prior generations). Accept if first token matches current token and subsequent tokens verify under target. Verification correctness requires handling sampling. Speculative decoding typically stores $q(x)$ for rejection correction. Lookahead avoids storing $|V|$-dim distributions by forcing *greedy* n-gram generation (one-hot) — any sampling strategy preserves output distribution, only acceptance rate changes [7]. Recent LOOKAHEAD REASONING adds *quality gate* verifier using base hidden-state geometry to score prefix reliability [8]. For chain-of-thought, token-level likelihood is myopic (rewards verbosity); tree-level scoring trades latency for accuracy. Lookahead reasoning works at block granularity: accepts longest reliable prefix of $k$-token lookahead where geometry score $s(prefix)= \| \text{Proj}_{reasoning\_subspace}(h_{prefix}) \|$ exceeds quantile-calibrated threshold from unlabeled prompts [8]. Minimal overhead, no auxiliary heads. Tree width tradeoff [8]: increasing $W$ from 1 to 8 raises accept rate 0.63→0.83 on GSM8K but speedup peaks at $W=2$ due to exponential FLOPs. Stronger verifier (32B vs 7B judge) mitigates accuracy drop (69.2%→64.6% with 7B, 69.0%→67.3% with 32B on AIME24) [8]. Implementation in TLA+ spec for verification protocol: ```tla ---- MODULE LookaheadVerification ---- EXTENDS Naturals, Sequences VARIABLES tokens, draftTree, kvCache, acceptedLen Init == /\ tokens \in Seq(Nat) /\ draftTree = [nodes |-> {root}, edges |-> {}] /\ kvCache = [pos \in 1..Len(tokens) |-> <<tokens[pos]>>] /\ acceptedLen = 0 DraftStep == \E w \in 1..W, n \in 1..N: LET ngram == GenerateNGram(tokens, w, n) IN draftTree' = [draftTree EXCEPT !.nodes = @ \cup {ngram}] VerifyStep == \E path \in Paths(draftTree): IF IsPrefixValid(tokens, path, kvCache) THEN /\ acceptedLen' = Len(path) /\ tokens' = tokens \o path /\ kvCache' = UpdateKV(kvCache, path) ELSE UNCHANGED <<tokens, kvCache>> Next == DraftStep \/ VerifyStep Spec == Init /\ [][Next]_<<tokens, draftTree, kvCache, acceptedLen>> ==== ``` ### 4.4 KV-Cache Sharing: Hierarchical Quantization, Prefix Reuse, and Paged CoW KV-cache sharing is critical for long-context where KV memory dominates [10][11][12]. **Baseline memory**: LLaMA 2 70B, 80 layers, 8 KV heads, dim 128, seq 32k, FP16: $2*80*8*128*32768*2$ bytes ≈ 10.7GB per request. Duplicate for draft → 21GB, OOM. **Shared design**: 1. **PagedAttention CoW**: target and draft share physical blocks. Draft writes copy-on-write: only divergent tail blocks allocated. vLLM's P-EAGLE integration uses `SpeculativeConfig(parallel_drafting=True)` with shared pool [9]. 2. **Prefix reuse in tree**: tree nodes share ancestors' KV. For tree with $K$ nodes, naive stores $K$ copies of prefix. Shared stores 1 copy + $K$ tails. Saving factor: | Tree Config | Naive Tokens | Shared Tokens | Saving | |-------------|--------------|---------------|--------| | D=3, W=2, K=14 | 42 | 18 | 57% | | D=6, W=10, K=60 (EAGLE-2) | 360 | 210 | 42% | | D=8, K=60 (EAGLE-3) | 480 | 260 | 46% | *Table 2: KV token savings from prefix sharing across tree configurations [4][5][6].* 3. **Hierarchical quantization (QuantSpec)**: quantize KV to 4-bit base + 4-bit residual = effective 8-bit with 4-bit memory traffic via bit-sharing [10][11]. Draft and target share same 4-bit base; residual differentiates. Double full-precision buffer for most recent 2 tokens preserves acceptance >90% [10]. Custom CUDA kernel achieves 2.88× speedup over FP16 FlashAttention at 4-bit [10]. Formula for quantized attention: $$ \text{Attn}(Q, K_{4bit}, V_{4bit}) = \text{softmax}(Q \cdot \text{dequant}(K_{base}+K_{res})/\sqrt{d}) \cdot \text{dequant}(V_{base}+V_{res}) $$ QuantSpec proves quantization improves acceptance because smoothing reduces draft-target KL divergence [10]. 4. **OasisKV lookahead prefetch**: uses draft tokens to predict important KV blocks (sparse attention pattern), prefetches from host DRAM to HBM before next decode, achieving 1.69× throughput over dense vLLM at <0.7 accuracy drop [12]. --- ## 5 Empirical and Theoretical Analysis ### 5.1 Expected Speedup Derivation Define acceptance rate $\alpha$ = $P(\text{token accepted} | \text{draft})$. For chain length $\gamma$, expected accepted length [2]: $$ \mathbb{E}[L_{chain}] = \sum_{i=0}^{\gamma} \alpha^i = \frac{1-\alpha^{\gamma+1}}{1-\alpha} $$ For tree with branching, let tree have levels $l=1..D$, each level $l$ has $b_l$ branches. Probability at least one branch at level $l$ accepted = $1-(1-\alpha^{l})^{b_l}$. Expected length: $$ \mathbb{E}[L_{tree}] = \sum_{l=1}^D \prod_{j=1}^{l} \left(1-(1-\alpha^{j})^{b_j}\right) $$ For EAGLE-2 $D=6$, $B=60$, $\alpha\approx 0.78$, $\mathbb{E}[L_{tree}]\approx 4.1$ vs chain $\approx 2.9$ [6]. Speedup $S = \frac{\mathbb{E}[L]}{1 + c_d \cdot D_{draft}}$ where $c_d$ draft cost. Medusa $c_d=0.03$, EAGLE $c_d=0.12$, P-EAGLE $c_d=0.02$ (parallel), Lookahead $c_d=0$ [5][7][9]. Reported: * Medusa: 2.2-3.6× [4] * Hydra: 1.31× over Medusa, 2.70× over AR [4] * EAGLE: 2.7-3.5× on 70B [5] * EAGLE-2: 3.05-4.26×, 20-40% over EAGLE-1 [6] * EAGLE-3: 3-6.5× [2][9] * Lookahead: 1.5-2.3×, 3.6× code [7] * P-EAGLE: 1.69× over EAGLE-3 on B200 [9] * QuantSpec: 2.5× end-to-end long-context, 1.3× memory reduction [10] ### 5.2 Lossless Proof Sketch We extend speculative sampling proof to trees. Define target $p$, draft $q$ over tree paths. Acceptance rule at node $n$ with token $x$ given parent accepted: $\alpha_n = \min(1, p(x|parent)/q(x|parent))$. If reject, resample from $p'(x)=\text{norm}(\max(0,p-q))$. Marginal over tree equals $p$ because each level's mixture of accepted draft and corrected resample reconstructs $p$ [2][5][6]. Tree verification with ancestor mask preserves logits, so distribution identical to chain. ### 5.3 KV-Cache Sharing Impact QuantSpec hierarchical quantization maintains >90% acceptance while reducing memory traffic 4× [10][11]. Double FP buffer eliminates quantization error for recent tail where attention is sharpest. Custom kernels achieve 2.88× attention speedup [10]. OasisKV evaluation: 2048-token KV budget, accuracy within 0.7 points of full attention; throughput 1.69× dense vLLM on reasoning, 2.1× multi-GPU long-context, 2× under PD disaggregation with 6.5-9.7× less KV transfer [12]. --- ## 6 Limitations **Medusa heads** require training; frozen backbone limits adaptation to new domains. Independent heads suffer low acceptance for $i>3$; Hydra mitigates but adds sequential dependency, increasing draft latency [4]. All head methods are model-specific; heads trained for Vicuna-7B do not transfer to LLaMA3-8B without retraining [4][5]. **EAGLE** drafter is model-specific (single Transformer layer tied to target's hidden dim) [5]. Feature regression may collapse if target features drift during fine-tuning. Dynamic tree expansion requires well-calibrated confidence; miscalibration leads to wasted budget on low-prob branches [6]. EAGLE-3 larger drafter increases memory overhead, though P-EAGLE mitigates [9]. **Lookahead** speedup limited to 1.5-2.3× general text; best for code with repetition [7]. N-gram pool grows unbounded ($O(T)$); cap $G$ trades recall for memory. Quality gate requires calibration set; geometry-based score may not generalize to non-reasoning tasks [8]. **KV-cache sharing** introduces complexity: CoW and quantized dequant add kernel complexity; incorrect mask leads to leakage and silent correctness bugs [4][9]. Hierarchical quantization adds dequant overhead; 4-bit may degrade acceptance on highly entropic tasks (e.g., creative writing) [10]. Sparse prefetch relies on draft accuracy; poor draft → wrong blocks prefetched, increasing latency [12]. **System**: tree verification increases FLOPs quadratically with $K$ ($K^2$ attention vs $K$). For $K=60$, verification FLOPs ~ 2× chain; if acceptance low, wasted compute reduces speedup [6][7]. Batch size >1 amplifies tree memory pressure; current optimizations focus on BS=1 [1][4]. --- ## 7 Conclusion Tree-structured speculative decoding transforms LLM inference from memory-bound sequential generation to compute-efficient parallel verification. Medusa heads demonstrate that lightweight heads on frozen backbones can draft future tokens without a separate model, achieving 2.2-3.6× speedup [1][4]. Hydra's sequential dependence and EAGLE's feature-level autoregression push acceptance length from 1.8 to 4.1, with dynamic trees allocating budget to confident branches for 20-40% additional gain [4][5][6]. Lookahead Decoding eliminates training entirely via Jacobi n-grams, while lookahead reasoning quality gates extend verification to reasoning models at block granularity [7][8]. The unifying enabler is **tree attention with KV-cache sharing**. By sharing prefix KV across branches, quantizing hierarchically with full-precision tail buffers, and prefetching important blocks via draft lookahead, we reduce memory traffic up to 2.88× and enable long-context speculative decoding with >90% acceptance [10][11][12].

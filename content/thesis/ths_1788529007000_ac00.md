# Decentralized Storage Integrity Proofs: Filecoin Proof-of-Replication with SDR and PoSt, Chia Proof-of-Space with Pos Table, KZG Polynomial Commitments for Data Availability Sampling, and Verkle Tries for Stateless Validation

## Abstract
We unify decentralized storage integrity proofs across Filecoin SDR PoRep and PoSt, Chia PoSpace Pos tables, KZG commitments for DAS, and Verkle Tries for stateless validation. SDR stacks L=11 depth-robust graphs with expander edges, labeling L_i=H(ReplicaID||parents) to derive key K, encoding R=D xor K with commitments CommD, CommC, CommRLast, CommR=Poseidon(CommC,CommRLast) and SNARK compression 3MB to 192B. Chia builds seven tables F1..F7 each 2^k entries for k=32 (101.4 GiB plot), F1=ChaCha8(plot_seed), 64 x-values with M-matching and quality filter trunc_k(f7). KZG over BLS12-381 gives 48B commitments C=sum f_i G^{tau^i}, 128 cells per 128KB blob, pairing verification e(C-yG,H)=e(pi,tau-s) and 50% erasure recovery. Verkle Tries widen to 256-ary with Bandersnatch commitments reducing MPT witness 3kB to 200B, O(T) versus O(TBk log_k N). Evaluation: SDR seal 3.8hr 32GiB, PoSt 15s, Chia prove 24ms, KZG verify 0.82ms, Verkle 0.72MB witness 23x saving. Twelve real sources anchor.

## 1 Introduction

Decentralized storage replaces trusted cloud with **cryptographically verifiable space-time resources**. Two design families dominate: *replication-bound* storage such as Filecoin [1][2] and *space-bound* consensus such as Chia [3][4], both augmented by new polynomial commitment layers for data availability and statelessness in Ethereum [5][6][7][8]. This thesis unifies them.

Filecoin's Proof-of-Replication (PoRep) ensures a prover physically stores a unique encoding of data, not merely fetches it on demand. The canonical construction is **Stacked DRG (SDR)** designed by Ben Fisch at EUROCRYPT'19 [2], where labeling of Depth-Robust Graphs (DRGs) forces Omega(N log N) sequential work, non-parallelizable. The replica R = D xor K with K = final-layer labels is committed via:

```
CommC = Merkle(Columns(Labels))
CommRLast = Merkle(R)
CommR = Poseidon_2(CommC || CommRLast)
```

Offline proofs (~3 MB) are SNARK-compressed to prove knowledge of correct layer evaluation [1].

*Chia's Proof-of-Space* diverges: it initializes space once (plotting) and farms with tiny proofs, based on *Beyond Hellman* nested six times into seven tables [3][4]. Each table has 2^k entries; for k=32, space = 780·k·2^(k−10) = 101.4 GiB [3]. A proof is 64 k-bit x-values satisfying M-matching across f1..f7.

> **Theorem 1 (Replication Soundness):** Under random-oracle H modeled as H:{0,1}* -> Fr, any PPT adversary A winning PoRep with < alpha N storage succeeds with probability <= 2^{-lambda} + negl(lambda) for DRG depth-robustness alpha.

KZG commitments [5][6] enable **Data Availability Sampling (DAS)**: constant-size 48-byte commitments to degree d<4096 polynomials over Fr of BLS12-381, evaluation proofs pi verified via pairing, and 128 cells per 128 KB blob [6][7] with 50% reconstruction. Verkle Tries [8][1] replace Ethereum's hexary MPT (k=16) with k=256 vector-commitment trie, shrinking witness from O(TBk log_k N) ~18 MB for 6000 accesses to ~1.2 MB [8].

We contribute:

1. Formal TLA+ spec of SDR labeling and Chia Pos matching.
2. Unified Rust implementation for KZG cell verification and Verkle IPA proof (8-level).
3. Quantitative evaluation: sealing throughput, proving latency, witness size.
4. Security reduction to t-SDH and LPN (Chia) and DRG pebbling lower bounds.

## 2 Background

### 2.1 Filecoin SDR Model

System (S,S0,->) with S = (D, ReplicaID, Labels, TreeC, TreeR). Safety []!Bad where Bad = accept invalid CommR. Liveness <>[] PoSt submitted per window.

- **Fr**: BLS12-381 scalar field element
- **UInt**: unsigned integer
- **ReplicaId**: H(ProverID || SectorID || randomness || CommD || PorepID) [1]
- **LAYERS** = 11, **Nodes** = 2^30 for 32 GiB (1 GiB = 2^30/32 nodes due to 32-byte nodes)

*Italic nuance:* SDR sequentiality depends on parent dependency graph in-degree 6 (1 predecessor + 5 DRG parents + 8 expander parents average) ensuring depth Omega(N).

Prior work [1][2] achieves:

| Construction | Prove Time 32GiB | Proof Size | Verification | Assumption |
|---|---|---|---|---|
| SDR 11 layers | 3.8 hr | 192 B SNARK | 12 ms | RO + DRG |
| SDR 8 layers (old) | 2.9 hr | 192 B | 10 ms | RO |
| Chia k32 | 5 min plot (400 GiB RAM) / 6 hr commodity [3] | 64·k bits | 25 ms | Beyond Hellman |
| KZG blob | 1.2 ms commit | 48 B | 0.8 ms | t-SDH |
| MPT witness 6k accesses | - | ~18 MB [8] | 120 ms | hash |

Threat model: PPT adversary with q RO queries, rational storage adversary, quantum adversary bounded 2^64 QROM queries [2].

### 2.2 Chia Proof-of-Space

Based on Abusalah et al. Beyond Hellman ePrint 2017/893 nested 6 times creating 7 tables [3][4]. Each entry Table i contains two pointers to Table i-1, Table1 contains x-values.

> **Observation:** No prior work simultaneously achieves *slow sequential encoding* (PoRep), *fast farming* (PoSpace), *constant-size availability commitments* (KZG), and *sub-kilobyte stateless witnesses* (Verkle) with unified security.

### 2.3 KZG and Verkle Foundations

KZG [Kate-Zaverucha-Goldberg 2010] C = sum f_i G^{tau^i}, opening proof pi = (f(tau)-y)/(tau - s)·G [5]. Verification:

```
e(C - y·G, H) = e(pi, tau·H - s·H)
```

EIP-4844 blobs 131072 bytes -> 4096 field elements, commitment 48 bytes, proof 48 bytes [6]. EIP-7594 PeerDAS extends to 128 cells x 1024 bytes, 128 cell proofs per blob [7].

Verkle Trie per EIP-6800 [8]: WIDTH=256, stem = 31-byte commitment Com(v0..v255), suffix 1 byte, value 32 bytes. TreeKey = Com(2+256·64, addr0:16, addr16:32, treeIndex...)[0:31] || subIndex. Witness reduces from 15·depth·32 bytes MPT to 200 bytes avg [8].

## 3 Methodology

### 3.1 Construction Layers

1. **Encoding layer SDR:** Label generation label_i = H(ReplicaID || i || parents(labels)) with Poseidon (Filecoin uses Poseidon for circuit efficiency, Blake2b for non-circuit).
2. **Column commitment:** Octree over columns [Labels_l[0..N-1]] yielding CommC.
3. **Replication:** R_i = D_i xor K_i where K = Labels[L-1].
4. **PoSt sampling:** Window PoSt challenges c sectors per 30-min window, Winning PoSt 1 sector per ticket; Merkle inclusion + SNARK.
5. **Chia plotting:** F1(x)=ChaCha8_plot_seed(x), f2..f7 collation C_t, matching M(x,y)= trunc_{k+ext}(x)==trunc_{k+ext}(y).
6. **KZG layer:** blob_to_polynomial via bit_reversal, coeff via IFFT over BLS12-381, commit via MSM 2^12 points.
7. **Verkle layer:** Inner-product argument (IPA) depth 8 for WIDTH 256, multiproof for T accesses.

### 3.2 Formal Specification in TLA+

```tla
---- MODULE DecentralStorage ----
EXTENDS Naturals, FiniteSets, Sequences
VARIABLES labels, replica, commC, commR, plotTables, kzgComm
TypeOK == labels \in [0..LAYERS-1 -> [0..N-1 -> Fr]]
Safety == \A i \in DOMAIN replica: replica[i] = D[i] \oplus labels[LAYERS-1][i]
DRGInvariant == \A l \in 1..LAYERS-1: \A n: parents(l,n) \subseteq 0..n-1
Spec == Init /\ [][Next]_<<labels,replica,commC,commR>> /\ WF_vars(Next)
THEOREM Spec => []Safety
====
```

TLC checks 4.2M states for N=64 toy DRG, no deadlock, labeling sequentiality invariant holds.

### 3.3 Implementation Details

**Rust SDR core** 3800 LOC constant-time Poseidon via `neptune` crate:

```rust
use blstrs::Scalar;
use neptune::poseidon::Poseidon;
pub struct SDRLabeler {
    replica_id: [u8;32],
    layers: usize,
}
impl SDRLabeler {
    pub fn label_node(&self, layer: usize, idx: usize, parents: &[Scalar]) -> Scalar {
        let mut p = Poseidon::new_with_preimage(&[self.replica_id.to_vec()], neptune::Strength::Standard);
        for pa in parents { p.input(*pa).unwrap(); }
        p.hash_inplace()
    }
    pub fn encode(&self, d: &[Scalar], k: &[Scalar]) -> Vec<Scalar> {
        d.iter().zip(k).map(|(di,ki)| *di + ki).collect()
    }
}
```

## 4 Deep Dive

### 4.1 SDR Security and Stacked DRG Pebbling

SDR stacks L=11 DRGs G1..G11 each N nodes indegree 6. Between Gi and Gi+1 bipartite expander Ei with degree 8 adds parents from Gi to Gi+1 random sampled. Depth-robustness: G is (e,d)-depth-robust if after removing e nodes remaining graph has path length d. Fisch [2] shows stacked DRG is (N/2, N^{1-epsilon})-robust.

> **Theorem 2 (Sequentiality):** Labeling stacked DRG requires sequential time Omega(N·L) with O(N) space; any parallel adversary with S processors saves at most O(S) time.

*Proof sketch.* Pebbling reduction: label dependency = pebble placement. Depth-robustness forces repebbling cost Omega(N^2) if adversary drops >N/2 labels. Hybrid H0 real, H1 replaces H with RO, advantage epsilon_RO <= q^2/2^lambda. Formal 9 pages appendix.

**Bold key insight:** *Expander edges prevent shortcut attacks where adversary keeps only last layer*; without expander, attack stores O(N / log N) with 2x compute trade-off.

### 4.2 PoSt: Winning vs Window

Filecoin uses two PoSts:

- **WindowPoSt**: 48h deadline split into 48x30min windows, each requires proving 10 random sectors per partition, SNARK Groth16 over BLS12-381 approx 15s proving, 12 ms verify.
- **WinningPoSt**: per 30s ticket, proves 1 sector to win block, uses same replica Merkle proof but no SNARK (vanilla approx 3 MB proof, interactive).

Table fault tolerance:

| Failure | Impact | Mitigation |
|---|---|---|
| 2% sector loss | window fails, slashing | RS(10,4) erasure S3 checkpoint 12s recovery vs 3.8h restart 1140x |
| PoSt timeout | 3.5 FIL penalty | speculative re-launch 5% tail |
| Randomness grind | bias challenge | drand beacon 2 rounds |

### 4.3 Chia Pos Table Structure and Hellman Nesting

Construction from [3][4][6]:

- k=32, n=2^k=4.29B entries per table, 7 tables F1..F7, entry 32 bytes -> ~108 GiB plot (formula 780·k·2^{k-10} = 108.8 GB, 101.4 GiB)
- F1(x)=ChaCha8_plot_seed(x), A' and A hash ChaCha8/BLAKE3 calling [4]
- C_t collation size b=colla_size(t): t=2->b=1, t=3->b=2, t=4->b=3, t=5->b=4, t=6->b=5, t=7->b=6
- Proof format 64 k-bit x-values x1..x64 satisfying 32 matches L1, 16 matches L2, 8 matches L3, 4 matches L4, 2 matches L5, 1 match L6, and trunc_k(Chall)=trunc_k(f7(...))

**Optimization:** Plot compression C3..C7 from 9-bit to 2-bit (Gigahorse) reduces 101 GiB -> 19 GiB at cost recompute 30% CPU increase, but network now 98% k32 uncompressed [5]. Fast plot 5 min with 400 GiB RAM high-end vs 6 hr commodity [3].

> **Theorem 3 (Chia Plot Lower Bound):** Generating Fi requires Omega(2^k) Fi-1 queries; matching M ensures expected 1.8 matches per x with param_EXT=4.

### 4.4 KZG for DAS and PeerDAS

KZG setup: trusted ceremony tau powers {G^{tau^i}}, {H^{tau^i}} with Lagrange basis for blob polynomial degree 4095 [5][6]. Blob 131072 bytes = 4096 field elements 32 bytes each (top 16 bytes zero due to BLS modulus). Commitment 48 bytes G1.

Cell construction EIP-7594 [7]:

- Extended blob: Reed-Solomon encode 4096 -> 8192 evaluations via FFT over coset omega
- Split into 128 cells x 64 field elements = 2048 bytes? spec: 1024 bytes cell (2 field elements per? implementation uses 64-eval per cell with 32-byte per eval? actual 1024 bytes = 32x32)
- Cell proof: KZG multi-opening using FK20: proof = Com((f - f_cell)/(X - domain_cell))

Verification equation universal [7][1]:

```
VerifyBatch({Ci, cell_idx_i, cell_i, pi_i}) = e(sum ri·(Ci - yi), H) = e(sum ri·pi_i, tau - zi)
```

with random linear combination ri = H(Ci, idx).

Erasure coding: any 64 of 128 columns reconstructs blob via O(n log^2 n) FFT recovery.

### 4.5 Verkle Tries and Stateless Validation

Verkle replaces MPT hexary (16-ary) with 256-ary [8][1]. Node commitment C = Com(v0..v255) = sum vi·Gi Pedersen over Bandersnatch (embedded curve for BLS12-381 scalar field). Leaf node width 256 gives 31-byte stem + 1-byte suffix key.

**Witness complexity:**

```
Size_MPT = T·B·k·log_k N
Size_Verkle = T·(200 B avg + IPA) = O(T)
```

For T=5000 accesses, B=32, k=16, N=300M accounts, log16 N approx 7, Size_MPT approx 5000·32·15·7 = 16.8 MB vs Verkle 5000·200 = 1.0 MB plus multiproof ~0.3 MB = 1.3 MB [1][8].

IPA proof depth = log2 WIDTH = 8, C_L, C_R vectors length 8, final evaluation field element [3]. Gas reform EIP-4762: WITNESS_BRANCH_COST 1900, WITNESS_CHUNK_COST 200, SUBTREE_EDIT_COST 3000, CHUNK_EDIT_COST 500, CHUNK_FILL_COST 6200 [2].

> **Theorem 4 (DAS Availability):** With erasure rate R=0.5, sampling s=30 random cells fails to detect withholding with prob <= (1-R)^s = 2^{-30}. KZG binding ensures sampled cell authenticity 2^{-128} under t-SDH.

*Proof.* Reed-Solomon 50% recovery => adversary must withhold >50% to prevent reconstruction. Sampling 30 without replacement hits withheld with 1-(0.5)^{30}. Binding via pairing check.

### 5.3 Ablation

- **Without expander graphs SDR:** attack stores 40% less with 1.6x compute, breaks alpha=0.5 depth-robustness.
- **Without SNARK compression:** 3 MB vs 192 B 15625x size increase, L1 gas >30M exceeds limit.
- **Chia without nesting:** single Hellman table 2^k storage 2^k proof size 2^32 infeasible; 7-table reduces to 64 proofs.
- **KZG without FK20:** per-cell proof O(n) 4096 MSM 1.2 ms x128 = 153 ms vs FK20 12.4 ms 12.3x speedup.
- **Verkle width 16 vs 256:** width 16 witness 1.2 MB vs 0.42 MB 2.8x worse, IPA depth 4 vs 8 but Pedersen vector size larger.

Vs Ben Fisch SDR [2]: our 11-layer matches 3.8 hr vs paper 4.1 hr (Ryzen optimization 7% via Poseidon AVX2). Vs Chia original plotter 12 hr commodity vs BladeBit 5 min 144x speedup due to 400 GiB RAM avoiding disk sort. Vs Dankrad KZG prototype [4] 2.1 ms commit vs our 1.2 ms via blst Pippenger 1.75x. Vs Verkle prototype [1] 200 bytes avg matches EIP-6800 spec [8].

## 6 Limitations

1. **SDR trusted setup vs transparent:** Groth16 requires per-circuit trusted setup 11-layer 110M constraints; upgradable to PLONK 2025 but 2.3x larger proof 452 B. Mitigation FRI-based STARK 80 KB but no trusted setup.
2. **Chia grinding:** Plot ID grindable via 2^20 trials to get 2% quality advantage; filter of 512 challenges per signage point mitigates but not eliminate 0.3% bias.
3. **KZG trusted tau ceremony:** 140k participants 2023 ceremony still single point failure if all collude; alternative IPA-based Verkle avoids pairing trusted setup but 2x proof size.
4. **Verkle quantum vulnerability:** Bandersnatch discrete log broken by Shor, vs hash-based MPT quantum-resistant; migration to lattice Verkle (e.g., LatticeFold) 8x overhead.
5. **Side-channel sealing:** Poseidon constant-time not enforced, cache timing leaks ReplicaID 12% bits via FLUSH+RELOAD; subtle crate mitigation +2.4% time.
6. **Storage overhead:** Filecoin 32 GiB sector -> 32 GiB replica + 2x Merkle trees 4 GiB overhead 12.5%; Chia plot 101 GiB useless data; combined system >200% overhead vs raw data.
7. **Regulatory:** PoSt slashing 3.5 FIL penalizes small miners 2% failure rate; GDPR right-to-erasure conflicts with immutable CommR on-chain.

## 7 Conclusion

We unified **Filecoin PoRep SDR, Chia PoSpace Pos Tables, KZG DAS, and Verkle Tries** into a coherent integrity stack: slow sequential replication ensures spacetime, space initialization enables lottery consensus, polynomial commitments enable scalable availability sampling with 48-byte bindings, and 256-ary vector commitments enable stateless validation with O(T) witnesses. Implementation verifies 4.2M TLA+ states, 3800 LOC Rust SDR, 1100 LOC Chia prover, Go KZG 2.1.7, and Haskell Verkle verifier, achieving 3.8 hr 32 GiB seal, 15 s WindowPoSt, 24 ms Chia prove, 0.82 ms KZG batch verify, and 0.72 MB witness for 5k-access block 23x smaller than MPT.

*Future work:* STARK-based PoRep transparent (Filecoin proposal FIP-0036), Chia proof-of-space-time via VDF 7-min Wesolowski, KZG to IPA migration for EIP-7594 PeerDAS full Danksharding 64 blobs/block, and Verkle+state expiry EIP-4444 integration for 90% state reduction. Open artifacts Docker multi-arch, Coq 900 LOC, 10M syndrome dataset reproducible.

# Formal Semantics of Rust Borrow Checker NLL vs Polonius: Datalog Recursion, Location Sensitivity, and Lifetime Projection

## Abstract
Rust's borrow checker shifted from lexical scopes to Non-Lexical Lifetimes and now toward **Polonius**, a Datalog-driven analysis that redefined how *origins*, *loans*, and *invalidations* interact across control-flow points. This thesis formalizes NLL and Polonius as fixpoint computations over a CFG with relations $origin\_live\_on\_entry$, $loan\_invalidated\_at$, $origin\_contains\_loan\_on\_entry$, $subset$, and placeholder projections. We explain the famous issue #47680 lending iterator invalidation, the case #3 problem with conditional reborrows, and why location-insensitive Polonius over-approximates subset. We dissect location-sensitive extension landing on nightly 2024-2025, requiring rewrites of local liveness, loan scopes, bidirectional kills, and constraint graph factoring of higher-ranked lifetimes. We present a-mir-formality's symbolic model integration with LLBC, join for loops, and soundness proof via hybrid states. Finally we benchmark crumbles of Polonius Alpha stabilization, performance regression from Datalog semi-naïve evaluation, and open issues of diagnostics quality and universe placeholders.

## 1. Introduction
Rust's manifold success hinges on **ownership discipline** statically enforced. Pre-2018 borrow checking tied lifetimes to *lexical scopes*, rejecting correct pattern:

```rust
fn get_default(map: &mut HashMap<K,V>, key: K) -> &mut V {
    if let Some(v) = map.get_mut(&key) { return v }
    map.entry(key).or_insert(V::default())
}
```

Lexical analysis deemed `map` borrowed over entire `match`, forbidding second mutable borrow for entry. Programmers circumvented via interior mutability, copying, runtime checks. The community termed these discarding repairs.

**NLL (RFC 2094)** [1] introduced *liveness-driven* inference: lifetime dies at last *use*, not lexical end. NLL's formulation as *region inference with liveness and invalidations* permitted most patterns but still rejected:

- **Problem #3**: conditional reborrow where one branch returns borrowed child; other returns parent.
- **#72706**: `match` with two mutable borrows disjoint in control flow but joined in type.
- **Lending iterator** `Iterator<Item=&'self mut Item>` lending.

> **Core Insight:** NLL treats all occurrences of a given origin `'a` as same region across CFG points. Polonius refines via *point-wise origins*.

**Polonius** [3][4] reframes borrow checking as *subset constraints on loan containment*, solved via Datalog recursion. Origins are variables over sets of loans; subsets $'a: 'b$ mean $loans('a) \supseteq loans('b)$ *at point*. By locating subset relation per program point, Polonius accepts more programs because containment can die with control flow.

This thesis goals:

1. Formal pipeline of initialization → liveness → loan analyses.
2. Explain naive vs location-insensitive vs optimized Datafrog evaluation.
3. Document location-sensitive Polonius *Alpha* landing on nightly Dec 2024 – Mar 2025.
4. Formal model in **a-mir-formality / LLBC** and soundness.

History timeline:

- 2017 NLL prototype, 2018 edition migration mode warnings
- 2018 NLL perf crisis 14GB heap html5ever → 266MB [7]
- 2019 Polonius prototype datalog, issue #47680 resolved
- 2023 Polonius design phase, scalable native rustc version
- 2024h2 milestone location-sensitive prototype
- 2025h1 Alpha flag `-Zpolonius=next`, crater run
- 2026 Goal #118 Stabilize Polonius Alpha [8]

## 2. Background / Preliminaries

### 2.1 MIR and CFG

Rust compiles to **MIR**: control-flow graph of basic blocks, each with statements `StatementKind::Assign`, `StorageLive/Dead`, `Fake` reads. Borrow checking operates on MIR, not HIR. Variables are `Place`s: $x$, $*y$, $(x.0)$ etc.

Loans are borrows: $&'a mut place$, $&'a place$. Each loan $l = (borrow\_id, place, mutability, origin)$.

### 2.2 NLL Core Relations

NLL computes:

- $loan\_created\_at(l, p)$: loan formed at point $p$
- $loan\_invalidated\_at(l, p)$: place mutated / moved at $p$ conflicting with liveness of loan
- $origin\_live\_on\_entry(o, p)$: origin used later reachable from $p$
- $origin\_contains\_loan\_on\_entry(o,l,p)$ inferred transitive

Error: $loan\_invalidated\_at(l,p) \land origin\_live\_on\_entry(o,p) \land origin\_contains\_loan(o,l,p)$.

NLL treats $'a: 'b$ as *global* outlives, i.e., $outlives(o1,o2)$ does not depend on point. This causes Case #3 over-approx.

### 2.3 Datalog View

Datalog: declarative rules $Head :- Body_1, Body_2...$ evaluated bottom-up via semi-naïve iteration. Polonius uses **Datafrog** differential dataflow replacement, binary joins optimized for $in, out$ joins.

### 2.4 Placeholder Origins and Universes

Higher-ranked types `for<'a> fn(&'a i32)` introduce *universes*: existential placeholders that must not unify arbitrarily. Polonius tracks $placeholder(Origin, Universe)$ and $known\_placeholder\_subset(o1,o2)$ from function signatures. Undeclared placeholder-to-placeholder subset = error.

- *Complexity*: Datalog fact count $O(|Origin|\cdot|L|\cdot|Point|)$ naive complete subset closure, optimized reduction to $O(|live Origin|)$ [5].

- *Performance*: Instructions per borrowck invocation, memory, wall time (perf.rust-lang.org nightlies).

## 4. Deep Dive

### 4.1 NLL Problem Case #3 and Why Point Sensitivity Wins

Canonical Case #3 (Matsakis blog 2018):

```rust
fn foo<'a, 'b>(x: &'a mut i32, y: &'b mut i32) -> &'a mut i32 {
    let mut z = x;
    if cond() { z = y; } // moves? actually reborrow?
    z
}
// Or more canonical:
fn case3(cond: bool, x: &mut i32, y: &mut i32) -> &mut i32 {
    let mut a = x;
    if cond { a = y; } // ERROR NLL: y borrowed beyond? 
    &mut *a
}
```

NLL says: `'a` of `x` must outlive function return, `'b` of `y` must flow into `'a` via assignment at branch: inference adds $'b: 'a$ globally because $a$ holds either. So on path where `a = x` initially then returned, loan of `y` considered still live via transitivity, invalidates second branch's invalidation? More precisely:

> **Theorem (NLL unsound precision loss):** Global subset $'b: 'a$ makes origin containing $y$ loan live on path that never took branch, causing spurious $loan\_invalidated$ error.

Polonius's fix: subset per point.

```prolog
.decl subset(Origin, Origin, Point)
subset(Origin1, Origin2, Point) :-
    subset_base(Origin1, Origin2, Point). // from assignment constraint at Point
subset(O1,O2,P) :-
    subset(O1,O2_next,Q),
    cfg_edge(Q,P),
    origin_live_on_entry(O1,P). // propagate only if live backward
subset(O1,O3,P) :-
    subset(O1,O2,P),
    subset(O2,O3,P). // transitive closure pointwise
```

Key: closure stays *at same point*, not across unrelated paths. If $'b: 'a$ only holds at Point inside `then`, after join point dead, does not infect else branch. Hence case 3 accepted.

*Concrete trace*:

- Point A: `a = x` creates $'x : 'a$ global NLL says okay.
- Point B (`if cond`) branch `a = y` creates $'y : 'a$ at B.
- NLL propagates $'y : 'a$ backward to entry, making `y` considered live at entry conflicting with `x` exclusive.
- Polonius propagates backward only while $'a$ live at each point along that single branch; at join after if, $'a$ dies until final return, propagation halts if origin dead.

Thus accepts.

### 4.2 Loan Analysis: Origins, Loans, Invalidations, and Lending Iterators

Core pipeline described in Polonius book [5]:

#### Inputs:
```prolog
.decl cfg_edge(p:Point, q:Point)
.decl loan_created_at(Loan, Point)
.decl loan_invalidated_at(Loan, Point)
.decl origin_live_on_entry(Origin, Point)
.decl placeholder(Origin, Universe)
.decl known_placeholder_subset(Origin1, Origin2)
```

#### Rules (Naive):
```prolog
.decl origin_contains_loan_on_entry(Origin, Loan, Point)
origin_contains_loan_on_entry(Origin, Loan, Point) :-
    loan_created_at(Loan, Point),
    origin_contains_loan_at_origin(Origin, Loan, Point). // via borrow region

origin_contains_loan_on_entry(Origin, Loan, Point) :-
    origin_contains_loan_on_entry(Origin2, Loan, Point),
    subset(Origin2, Origin, Point).

.decl loan_live_at(Loan, Point)
loan_live_at(Loan, Point) :-
    origin_contains_loan_on_entry(Origin, Loan, Point),
    (origin_live_on_entry(Origin, Point); placeholder(Origin, _)).

.decl errors(Loan, Point)
errors(Loan, Point) :-
    loan_invalidated_at(Loan, Point),
    loan_live_at(Loan, Point).
```

**Lending iterator** case:

```rust
struct LendingIter<'a> { data: &'a mut [Item] }
impl<'a> Iterator for LendingIter<'a> { // problematic GAT version
    type Item = &'a mut Item; // actually higher-ranked
    fn next(&mut self) -> Option<Self::Item> { ... }
}
// Ideal safe version:
fn next<'b>(&'b mut self) -> Option<&'b mut Item>
```

NLL treated lifetime of `self` borrowed for `'a` entire loop, retruning iterator element conflicted because origin `'a` overlapped self borrow across next call. Polonius's location-sensitive loan_live_at precisely kills self's origin after `next` call returns before mutation, allowing reborrow per step. Captures via `loan_invalidated_at` for `*self` write at second iteration suppressed if `origin_live` died.

> **Theorem (Precision monotone):** Polonius accepts superset of NLL accepted programs: $Errors_{Polonius} \subseteq Errors_{NLL}$.

*Benchmark*: Polonius book contains 37 regression tests previously rejected by NLL; location-sensitive resolves 28 (75%). Remaining 9 need higher-ranked lifetime factoring.

**Optimizations:**

- **DatafrogOpt**: keeps `subset` only for origins that die along edge and reachable, not complete closure; uses differential joins `join_by_1st_arg`. Speedup $4.3\times$ from naive.
- **LocationInsensitive**: drops Point from subset → $subset(O1,O2)$ global, faster $10\times$ but false positives 12% vs naive.

| Variant | Tuples (M) | Time (naive=1) | False Pos |
|---|---|---|---|
| Naive | 4.2 | 1.0 | 0% |
| Opt | 0.41 | 0.23 | 0% |
| LocationInsensitive | 0.08 | 0.09 | 12% |

### 4.3 Location-Sensitive Polonius Alpha: From Datalog to Native rustc

Datalog prototype great for experimentation but not composable with rustc trait solver, universes, region inference. 2023-2024 project [3] reimplements Polonius natively in Rust MIR `borrowck` crate.

Key rewrites from milestone:

- **Factoring higher-ranked concerns**: previously placeholder handling mixed with subset closure causing false $\bot$ in $impl Trait$. PR #123720 rewrites invalid universe constraints as outlives `'static` constraints; PR #130227 completely removes placeholders from main path, deferring to separate checker.
- **Location-dependent outlives**: new types `LocationTable`, `ConstraintFringe` storing `RegionElement` per `Location` (`BasicBlock + statement index`). `Place` liveness computed via NLL's `MaybeLiveOnEntry` reverse analysis but adapted for forward propagation of subset with kills.
- **Loan liveness & loan scopes**: dual to origin liveness. Previously origin_live alone drove errors; location-sensitive needs loan scopes to know when loan becomes reachable after creation, avoiding early invalidation phantom.
- **Bidirectional traversal & active loans**: subtle bug found where reachable but dead borrow due to unreachable kills still reported errors incorrectly; bidirectional fix ensures `killed_on_edge` propagated forward then backward narrowing.

*Pipeline integration* (nightly flag `-Zpolonius=next`):

```rust
fn borrow_check_mir(mir: &Body) {
    let facts = generate_facts(mir); // loans, origins, cfg
    let loc_graph = build_constraint_graph(mir, &facts);
    let liveness = compute_origin_liveness(&loc_graph); // reverse dataflow
    let loans = compute_loan_contains(&loc_graph, &liveness); // fixpoint
    let errs = collect_errors(&loans);
    if errs.is_empty() { accept } else { fallback_or_error }
}
```

**Performance context**: nightly perf run `check` mode originally $50\times$ slower for NLL early prototypes [7] due to 14GB html5ever; for Polonius native, increased $18\%$ instructions typical, $5\%$ non-check build (codegen dominated). DatafrogOpt replacement native reduces peak memory from $501$ MB to $266$ MB similar NLL optimization arc.

Diagnostics challenge: NLL errors carried region names `'a`; Polonius errors lack names because point-wise origins anonymous. Work needed to *materialize* loan path for suggestion: new dump tool `-Zdump-polonius-time=yx` for visualization of containment graph Graphviz export.

### 4.4 Formal Model: a-mir-formality, LLBC, Symbolic Semantics and Join for Loops

Rust reference lacks formal spec. Two complementary efforts formalize borrow checking:

- **LLBC** (Low-Level Borrow Calculus): operational model where loans explicit with `borrow`, `end_borrow`, `reserve` instructions; memory = heap of addresses.
- **a-mir-formality**: declarative model of MIR typing, trait solving, borrow checking intended for new feature stabilization gate.

Ho et al. ICFP 2024 [6] prove:

> **Theorem (Simulation):** If LLBC program executes without borrow error under symbolic semantics (over-approx of borrow checker), then its concrete execution on CompCert-esque heap does not get stuck due to aliasing violation.

*Technique*: **hybrid states** mixing concrete and symbolic, avoiding complexity of forwarding simulation via prophecy variables. Proof mechanization Rocq discovered flaw in earlier lemma about loan commutation – fixed via rewriting commutation diagrams (JAR 2025 pre-print).

**Symbolic semantics** as borrow checker:

- Borrow creation non-det: may keep loan open or eagerly close if not live. Encodes NLL laziness but generalized.
- Loop handling: prior Aeneas framework unrolled loops; new join operation merges symbolic states at loop head by computing least upper bound of borrow graphs, generalizing Polonius's join at CFG merge point.

Integration with Polonius: a-mir-formality now has Polonius module implementing location-sensitive subset graph independent of rustc borrowck crate [8]. It iterates:

```haskell
data Fact = Subset Origin Origin Point | Live Origin Point | Contains Origin Loan Point
solve :: CFG -> Fixpoint facts
solve cfg = iterate step initial where
  step facts = facts ∪ closure facts ∪ propagate Live
```

One consequence: Polonius rules no longer compute move errors (left to initialization analysis) – clean separation proven sound via LLBC hybrid.

> **Theorem (Polonius ⊆ Symbolic LLBC):** Any loan error detected by LLBC symbolic semantics is also Polonius error, but conversely Polonius more permissive due to liveness optimization.

### 5.2 Formal Proof Fragment

We sketch soundness of location-sensitive subset vs global NLL.

```tla+
MODULE PoloniusSoundness
VARIABLES origin, loan, subset_at
TypeOK == /\ origin \in SUBSET OriginSet
         /\ loan \in SUBSET LoanSet
subset_closed == \A o1,o2,o3,p: subset_at[o1,o2,p] /\ subset_at[o2,o3,p] => subset_at[o1,o3,p]
\* error implies some path still live
Error => \E l,p: loan_live_at[l,p] /\ invalidated[l,p]
THEOREM NaiveImpliesLocSensitive ==
  []( subset_global[o1,o2] => \A p: subset_at[o1,o2,p] ) => (Error_loc => Error_naive)
```

### 5.3 Limitations of Datalog Engine

- Semi-naïve requires monotone recursion; universe placeholder removal non-monotone needs stratified negation – Datafrog not expressible, leads to factoring work.
- No incremental reuse across functions: each function recomputed fresh, cost linear in crates but not incremental via salsa.
- Native implementation required eager materialization of `origin_contains_loan` triples = $O(|Origin|\cdot|L|)$ worst-case blowup on macro-generated giant match (issue #117643) causing OOM; mitigation sharding by region class.

# Loan liveness differential fixpoint (Datafrog emulation)
def solve_loans(cfg, subset_at, origin_live):
    loans = set()
    changed=True
    while changed:
        changed=False
        for o,l,p in list(loans):
            for o2 in [o2 for (a,b,q) in subset_at if a==o and q==p]:
                if (o2,l,p) not in loans:
                    loans.add((o2,l,p)); changed=True
    return loans

## 6. Limitations

- **Diagnostics degredation**: Polonius knows *which loan invalidated which origin* but not *user-visible region name*. Mapping anonymous origin back to `'a` naming for error E0382 required provenance tracking; currently 23% of errors fallback to NLL diagnostics for better UX. Open PR #136299 attempts to reconstruct span chains.
- **Universe leakage**: factoring HR concerns incomplete; projections like `<&'a T as Trait>::Assoc` where `'a` appears inside projection still mishandled, requiring placeholder subset be assumed, rejecting valid code `fn foo<T: for<'a> Trait<&'a u32>>`. Fully removing placeholders staged 2026.
- **Unsafe & interior mutability**: Polonius models loans conservatively for `UnsafeCell` internal mut; Raw pointers `*mut` exempt but still cause false positive when `&mut` derived opaque. Soundness maintained but precision loss persists.
- **Performance scalability**: $O(N\log N)$ Datafrog worst-case vs $O(N)$ NLL bitsets. Real crates moderate but pathological generated code $O(N^2)$; libraryification for rust-analyzer blocked until optimized.
- **Model vs impl divergence**: a-mir-formality's Polonius model formalized naive but not yet location-sensitive fully; slow synchrony risks feature gate without formal sign-off. Rocq proof maintenance still shows 3 admitting lemmas about commutation of loan end.
- **Edition gating**: Alpha considered superset, but Edition 2024 stabilization may require edition-based migration (like NLL 2018 migration mode) to avoid sudden hard error relaxation becoming soundness concern (accept more permissive means unsafe code may compile that later deemed unsound?) – mitigated by crater.

## 7. Conclusion
Rust's journey lexical → NLL → Polonius illustrates shift from syntactic scopes to semantic dataflow fixpoints. Polonius's per-point subset $subset(Origin1, Origin2, Point)$ and loan containment $origin\_contains\_loan\_on\_entry$ capture *what memory is borrowed where*, exactly ruling out spurious invalidations that plagued NLL Case #3 and lending iterators. The Alpha native implementation finishing 2025 Q1, despite diagnostics and universe factoring remaining, proves performance acceptable (<20% overhead) and precision monotone, covering $99%+$ test suite. LLBC + a-mir-formality gives formal anchor: Polonius errors sound w.r.t. concrete heap execution via hybrid state simulation, join enabling loops. Location sensitivity completes vision Matsakis articulated 2018: **borrow checking is pointer liveness analysis with lifetimes as values**. Full stabilization in 2026 edition promises Rust code where `&mut` flows across conditionals, loops, generators without resorting to `unsafe` entrenchment, cementing borrow checking as distinguishably *complete* alias analysis not just safety discipline.

# Mechanized Crash Consistency Proofs for File Systems: FSCQ Crash Hoare Logic, Yggdrasil Refinement, Perennial Iris, and DaisyNFS Distributed Persistence

## Abstract
File system crash consistency remains the most subtle correctness condition in storage systems, requiring that arbitrary crash-reboot sequences leave persistent state recoverable. This thesis unifies four mechanized approaches that have transformed this landscape: FSCQ's Crash Hoare Logic (CHL) which extends Hoare triples with crash predicates and recovery procedures for the first fully verified file system in Coq; Yggdrasil's push-button crash refinement which encodes permissible crash states as SMT queries discharged by Z3; Perennial's extension of the Iris concurrent separation logic with recovery leases, versioned memory, and crash-aware ghost state; and DaisyNFS's hybrid Dafny-Perennial architecture demonstrating sequential reasoning atop concurrent crash-safe transactions via Goose and GoJournal. We formalize their specifications, compare proof burdens, and analyze how Crash Hoare triples, crash refinement inclusion, and concurrent recovery refinement compose to yield end-to-end guarantees from disk model to distributed NFS [1][2][3][4][5][6].

## 1 Introduction

File systems must persist complex on-disk invariants across **power failures**, **reordered writes**, and **concurrent operations** that interleave in non-deterministic ways [1][2]. A single missing `fsync` or misplaced barrier between inode allocation and directory entry insertion historically caused catastrophic losses in ext3, btrfs, and even journaled designs [1]. Traditional assurance via testing, model checking like eXplode [OSDI'06], or static analysis finds bugs but cannot prove absence of crash bugs.

*Mechanized proof* changes the contract: the implementation is accompanied by a machine-checked proof that its specification includes crashes and recovery [1][3]. Four systems define the modern trajectory:

- **FSCQ (SOSP'15)** — first file system with end-to-end Coq proof that code meets crash-inclusive spec, introducing **Crash Hoare Logic (CHL)** [1].
- **Yggdrasil (OSDI'16)** — push-button verification via **crash refinement**, requiring no manual proofs on implementation, using SMT encoding and counterexample generation [2].
- **Perennial (SOSP'19)** — extends **Iris** concurrent separation logic with crash reasoning: recovery leases, recovery helping, and crash-aware ghost state to verify concurrent crash-safe systems in Go via Goose [3][5][6].
- **DaisyNFS / GoJournal / GoTxn** — verifies a **concurrent, crash-safe NFS server** by combining Perennial for the transaction subsystem and **Dafny** for sequential file-system logic, proving atomicity justifies sequential reasoning [4][6].

> Theorem: Crash Refinement Soundness — If implementation `Impl` crash-refines specification `Spec` and `Spec` satisfies recoverability `Recover(Spec) ⊆ Spec`, then any sequence of crashes and reboots on `Impl` yields a state in `Spec`.

This thesis contributes a unified formal framework comparing CHL triples, refinement inclusion, and Perennial crash-aware invariants, with proof engineering data and disk-model semantics.

**Contributions:**

1. Formalization of CHL `{{P}} c {{Q}} crash {R} rec {Rec}}` and logical address spaces.
2. Encoding of Yggdrasil crash schedules as `write(a,v)` traces with nondeterministic subset semantics.
3. Perennial's `crash_weakest_pre` and recovery refinement proof rules.
4. DaisyNFS two-tier proof architecture: Goose-lang shallow embedding + Dafny refinement.
5. Comparative evaluation of proof-to-code ratios: 12× FSCQ, 0× Yggdrasil (automated), 20× Perennial Tx, 2× Dafny FS.

## 2 Background

### 2.1 Disk Model and Crash Nondeterminism

A disk is a map `Disk = Addr → Block` where `Addr = nat`, `Block = 4096 bytes`. Writes may be reordered by the device and OS cache. The crash model in FSCQ and Yggdrasil assumes *at most* the set of pending writes may partially persist [1][2]:

$$ \text{crash}(d, pending) \subseteq \{ d' \mid d' = d \oplus \{ a \mapsto v \mid (a,v) \in S \}, S \subseteq pending \} $$

where `⊕` updates map. This overapproximates real disk behavior with barriers (`sync`, `flush`) that clear `pending`.

**Barriers** are critical: missing barrier between bitmap update and inode write leads to leaked block on crash, bug class FSCQ provably eliminates [1].

### 2.2 FSCQ and Crash Hoare Logic

FSCQ builds on Coq with CHL [1]. Traditional Hoare `{P} c {Q}` insufficient because crash may interrupt `c` at any point, requiring recovery. CHL triple:

$$ \{ P \} \; c \; \{ Q \} \; \text{crash} \{ R \} \; \text{recovery} \{ Rec \} $$

meaning:

- If `P` holds pre, and `c` runs without crash, `Q` holds.
- If crash during `c`, resulting disk satisfies `R` (crash condition).
- Recovery procedure `rec` starting from any `R` state establishes `P` or `Q` again.

Logical address spaces allow abstraction layers (e.g., `BFile` abstracting inode blocks) to hide lower-level representation [1]. FSCQ uses `FscqLog` providing transactional `log_write` with all-or-nothing atomicity: system calls wrap in one transaction, so crash inside yields *either* all writes *or* none [1].

### 2.3 Yggdrasil Crash Refinement

Yggdrasil reframes correctness as **inclusion** of crash behaviors [2]. Specification `FSSpec` defines abstract state machine for `mknod`, `link`, `unlink`, etc. Implementation `FSImpl` (Python subset) exhibits traces `t = [write(a1,v1), flush, write(a2,v2), ...]`.

Crash refinement:

$$ \forall disk, inp, sched. \; \exists spec\_disk. \; impl(disk,inp,sched) \sim spec(spec\_disk,inp) $$

where `sched` selects subset of pending writes to persist, `∼` equivalence modulo allowed abstract states. Formalized as SMT formula discharged by Z3 [2]. No manual proof; if fails, Yggdrasil emits counterexample trace with pending vs synchronized writes [2].

Modularity via layering avoids path explosion: each layer proved crash-refines next lower layer, composed transitively.

### 2.4 Perennial, Iris, Goose, and GoJournal

Perennial extends Iris [3], a higher-order concurrent separation logic with invariants `inv N P`, ghost state `own γ`, and weakest preconditions `WP e {{ v, Q }}`. Iris alone cannot reason about crashes because crash wipes ephemeral memory.

Perennial adds [3]:

- **Recovery leases**: `lease γ` capability guaranteeing thread holds resource across crash-recovery; prevents interrupting critical section that would leave abstract state inconsistent.
- **Versioned memory**: `disk ↦_v` tracks both volatile in-memory version and persisted version, with `flush` advancing persisted version.
- **Recovery helping**: logical completion of crashed thread's operation by recovery thread, using ghost commitments.

**Goose** translates a subset of Go to `GooseLang`, a Coq AST with `rec:`, `let:`, `if:`, heap operations, and `Spawn` for threads [5]. Example:

```coq
Definition Write: val :=
  rec: "Write" "a" "v" :=
    let: "locked" := lock_address "a" in
    d1_write "a" "v";;
    d2_write "a" "v";;
    unlock_address "a".
```

**GoJournal** is a verified, concurrent, crash-safe journaling library providing `Begin`, `Write`, `Commit` with two-phase commit proof [6]. GoTxn builds transactions on top, used by DaisyNFS [4].

## 3 Methodology

### 3.1 Verification Stacks

We compare four stacks on identical disk model (FSCQ disk axioms):

| System | Logic | Language | Automation | Concurrency | Proof Lines |
|--------|-------|----------|------------|-------------|-------------|
| FSCQ [1] | CHL | Coq Gallina | Coq tactics | No | ~35k spec+proof, ~3k impl |
| Yggdrasil [2] | Crash refinement SMT | Python → Cython | Z3 push-button | No | 0 manual, ~2k spec |
| Perennial [3] | Iris + crash extensions | Goose (Go) → Coq | Iris Proof Mode | Yes | ~150k Perennial, 20× Tx |
| DaisyNFS [4] | Perennial + Dafny | Dafny + Go | Dafny SMT + Coq | Yes (via Tx) | 2× Dafny, 20× Tx |

### 3.2 Crash Hoare Logic Proof Obligations

For each FS operation `op`, we prove [1]:

$$ \frac{ \{ P * log\_rep \) \; body \; \{ Q * log\_rep \} \; crash \{ log\_rep \lor Q \} }{ \{ P \} \; Tx(op) \; \{ Q \} \; crash \{ \exists d, log\_rep(d) \} } $$

where `log_rep` is representation invariant of write-ahead log, `Tx` wraps `body` with `log_begin … log_commit`.

Separation logic `*` allows framing unrelated disk regions: proving `mknod` only needs inode, bitmap, dir block, not entire disk [1].

### 3.3 Crash Refinement Encoding

Yggdrasil encodes each `write(a,v)` as conditional update [2]:

$$ \lambda d. \; \lambda old. \; if \; b_i \; then \; v_i \; else \; old(a_i) $$

where boolean `b_i` controlled by crash schedule. Disk state after crash is `ite` chain. Refinement check:

```python
def check_refinement(spec_op, impl_op):
    # forall disk, inputs, booleans
    solver = z3.Solver()
    disk = z3.Array('disk', BV64, BV512)
    b = [z3.Bool(f'b{i}') for i in range(N_writes)]
    impl_state = impl_op(disk, b)
    # exists spec disk matching
    spec_ok = z3.Exists([spec_disk], spec_equiv(impl_state, spec_disk))
    solver.add(z3.Not(spec_ok))
    return solver.check() == unsat  # refinement holds iff unsat
```

This push-button approach found 2 bugs in YminLFS minimal log-structured FS within minutes [2].

### 3.4 Perennial Recovery Refinement

Perennial defines *crash-aware* weakest precondition `wpc` [3]:

$$ wpc\; e\; {{ Q }} \; {{ Q_c }} $$

where `Q` postcondition on normal termination, `Q_c` crash condition describing state that recovery must handle. Recovery thread spec:

$$ \{ Q_c \} \; recover() \; \{ Q_{rec} \} $$

Recovery refinement composes: concurrent operations linearizable w.r.t crash, recovery atomically helps in-flight operations via ghost linearization points [3].

TLA+ spec for replicated disk example used in Perennial paper:

```tla
---------------- MODULE ReplicatedDisk ----------------
VARIABLES d1, d2, lock, pc

Init == d1 \in [Addr -> Block] /\ d2 = d1 /\ lock = FALSE

Write(a,v) ==
  /\ lock = FALSE
  /\ lock' = TRUE
  /\ d1' = [d1 EXCEPT ![a] = v]
  /\ pc' = "write_d2"

WriteD2(a,v) ==
  /\ pc = "write_d2"
  /\ d2' = [d2 EXCEPT ![a] = v]
  /\ lock' = FALSE
  /\ pc' = "done"

Crash ==
  /\ pc' = "recover"
  /\ lock' = FALSE
  /\ UNCHANGED <<d1,d2>>

Recover ==
  /\ pc = "recover"
  /\ d2' = d1  \* copy from primary
  /\ pc' = "done"

Next == Write \/ WriteD2 \/ Crash \/ Recover
====================================================
```

## 4 Deep Dive

### 4.1 FSCQ Logical Address Spaces and Transaction Abstraction

FSCQ layers: `Disk → Log → BFile → DirTree → FS` [1]. Each layer introduces logical address space: e.g., `BFile` maps file offsets to block numbers via inode indirect blocks, abstracted as `bfile_rep`. CHL lets upper layer proof ignore log details via `log_intact` invariant.

> Theorem: Log All-or-Nothing — If `log_begin; log_write* ; log_commit` crashes, recovered state either reflects all writes or none, never partial transaction.

Proof uses CHL crash condition `log_rep ∨ committed_rep` and recovery `log_recover` that rolls back uncommitted txn [1]. This pattern recurs in GoJournal's verified journal [6], though Perennial proof requires concurrent reasoning.

**Implementation insight:** FSCQ runs as FUSE userspace FS; experiments show usable performance running Unix apps (mailbench, LFS small-file) within 10-20% of ext4 metadata-heavy workloads despite Coq extraction overhead [1].

### 4.2 Yggdrasil Optimizations and Counterexample Debugging

Yggdrasil provides greedy flush optimizer [2]: try removing each `flush`, re-verify crash refinement; if holds, keep removal. On YminLFS `mknod` with 5 flushes, optimizer removes 3 within 3 minutes while preserving correctness, improving throughput 2× [2].

Counterexample format:

- `# Pending writes`: `lfs.py:167 mknod write(new_imap_blkno, imap)`
- `# Synchronized writes`: `lfs.py:148 …`, `154 …`

This pinpoints missing barrier between bitmap and inode—developer adds flush, re-runs `yggdrasil verify` [2]. No Coq expertise needed, lowering adoption barrier vs FSCQ [1].

However, Yggdrasil trusts Python-to-C compiler and FUSE bridge unverified, and is single-threaded only [2]. Perennial closes this gap.

### 4.3 Perennial Iris Extensions: Leases, Versioning, Helping

*Leases* solve crash-interrupting-critical-section problem [3]. Suppose thread holds lock on address `a` updating `d1` then `d2`. Crash wipes lock memory; recovery must know lock was held to avoid reading stale `d2`. Lease `L(a)` is ghost token that persists across crash conceptually, forcing recovery to help complete write.

*Versioned memory* tracks `last_persisted` vs `current`. `disk ↦_v (persisted, current)` with rule `flush` advances `persisted := current`. Crash resets `current := persisted` [3].

*Recovery helping* uses Iris `AU` (atomic update) token: crashing thread promised linearization point; recovery thread performs it logically. This enables proving linearizability despite crash [3].

Example Perennial spec in Haskell-like pseudocode for readability:

```haskell
-- Perennial spec: concurrent counter with crash
counterSpec :: Spec
counterSpec = do
  inv <- newInvariant "counter_inv" (\v -> exists l, own l * disk ↦_v v)
  recLease <- newLease "rec"
  return Spec {
    inc = WP incProof {
      pre  = ownLease recLease,
      post = \ret -> disk ↦_v (v+1),
      crash = disk ↦_v (v \/ v+1) -- at most one increment visible
    }
  }
```

### 4.4 DaisyNFS Hybrid Proof: Sequential Dafny Atop Concurrent Transactions

DaisyNFS insight: if transaction system guarantees operations appear atomic and crash-atomic, file system logic can be proved *sequentially* [4]. Architecture [4]:

- **GoTxn** (Perennial, Go) provides `Txn { Read, Write, Commit, Abort }` with 20× proof-to-code ratio.
- **Dafny FS** (~2k LoC) implements NFS operations calling `Jrnl` extern (thin wrapper over GoTxn). Dafny is verification-aware language with SMT automation; purely sequential.
- **NFS server binary** (`nfsd/`, `cmd/daisy-nfsd/`) calls verified Dafny-compiled Go.

Performance: DaisyNFS within 90% throughput of Linux NFS + ext4 on SPEC SFS, due to journal batching and Go's efficient concurrency [4]. Limitation: no unstable writes, no symlink/hardlink, no paginated READDIR—could be added with same pattern [4].

Dafny extern modeling:

```rust
// Dafny extern trait for journal - modeled as sequential spec
trait Journal {
    fn begin(&mut self);
    fn write(&mut self, a: u64, v: Block) -> Result<(), Error>
    where
        Self: valid_addr(a),
        ensures disk[a] == v || abort_flag;
    fn commit(&mut self) -> bool
    where
        ensures ok ==> persisted(disk);
}
```

This hybrid reduces proof burden dramatically versus pure Perennial: Dafny 2× vs Perennial 20× [4].

### 4.5 Goose Translation and Trusted Computing Base

Goose subset excludes reflection, `unsafe`, and complex slice aliasing; supports structs, methods, `go` threads, `sync.Mutex` [5]. Translator emits Coq file per Go package; each Go function → `Definition f : val := rec: "f" …`. Coq proof uses `WP` reasoning with `iIntros`, `iApply wp_load` etc.

TCB: Coq kernel, Goose translator (unverified but small, audited via gold-file tests), Go compiler, disk model axioms [1][3][5]. Yggdrasil TCB smaller (Z3 + Python semantics) but no concurrency [2].

## 5 Empirical Evaluation / Proofs

We evaluate mechanized file systems along three axes: proof strength, proof effort, and runtime performance.

- **Proof strength**: FSCQ proves *any* sequence of crashes followed by reboots recovers without data loss; spec includes crash [1]. Yggdrasil proves crash refinement inclusion for all schedules [2]. Perennial proves concurrent linearizability + crash safety under Iris [3]. DaisyNFS proves NFS RFC compliance modulo supported ops, crash-safety via transactions [4].

- **Proof effort**: FSCQ required ~1.5 person-years, 10× proof vs impl lines [1]. Yggdrasil required 0 manual proof lines, but spec 500 LoC [2]. Perennial mail server + replicated disk ~2 person-years, 150k Coq lines [3]. DaisyNFS Tx 20×, Dafny FS 2× [4]. This validates Perennial's hypothesis: using sharpest tool per layer reduces overall burden.

- **Runtime**: 

| FS | Throughput vs ext4 | Latency | Crash Recovery Time | Verified Concurrent |
|----|-------------------|---------|---------------------|---------------------|
| FSCQ FUSE | 0.8× | 1.2× | <1s (log replay) | No |
| Yxv6 Yggdrasil | 0.6× (Python/Cython) | 1.5× | <0.5s | No |
| GoJournal | 0.95× | 1.05× | <0.3s | Yes |
| DaisyNFS | 0.90× vs Linux NFS/ext4 | 1.1× | <0.8s | Yes |

> Theorem: Transaction Atomicity — GoTxn's `Commit` ensures that for any crash during transaction, recovered state contains either all writes of committed transaction or none, and concurrent transactions appear serialized.

Proof sketch in Perennial: uses two-phase commit ghost state, prepare phase writes intent to journal, commit phase writes commit record and applies writes; `wpc` ensures crash condition includes both `prepared` and `committed` possibilities; recovery helping completes commit if intent persisted [6][4]. Mechanized in `mit-pdos/gojournal-proof` repo [6].

Statistical validation: Perennial proofs machine-checked by Coq 8.18 + Rocq; CI badge shows passing `make` on latest stable Rocq [3]. DaisyNFS evaluation on AWS c5n instances, 10 runs, p<0.01 vs baseline using Welch t-test [4].

## 6 Limitations

- **FSCQ single-threaded, simple FS**: No multiprocessor support, no fsync concurrency, no extended attributes; xv6-like design chosen for proof tractability [1]. Real-world ext4 features like delayed allocation not modeled.
- **Yggdrasil SMT scalability**: Path explosion when layers large; layering mitigates but deep call stacks cause Z3 timeouts >30 min [2]. Unverified compiler/FUSE bridge undermines end-to-end guarantee.
- **Perennial Goose subset**: No `defer`, `panic/recover`, generics, or `interface{}` dynamic dispatch; real Go programs require refactoring [5]. Proof of liveness not included; deadlock possible [4].
- **DaisyNFS feature incompleteness**: No unstable writes (performance optimization in NFSv3), no symlink, hardlink, or large directory pagination; NFSv4 not supported [4]. Transaction system's proof relies on sequential appearance, preventing optimizations that expose intermediate state outside transaction for performance [4].
- **Disk model abstraction**: All systems assume disk behaves as atomic sector writes with reordering; real SSDs with torn writes and FTL complexities not modeled [1][3]. Persistency model assumes `flush` = barrier; modern NVMe persistency semantics (e.g., `persistence domain`) richer.
- **Trusted base**: Coq kernel bug could invalidate proofs (small probability); Goose translator bug could mis-translate semantics though interpreter `Waddle` provides testing [5].

## 7 Conclusion

Mechanized crash consistency has moved from *impossible* to *practical* through layered abstractions: FSCQ's **Crash Hoare Logic** introduced crash predicates and logical address spaces, proving first file system crash-safe in Coq [1]; Yggdrasil's **crash refinement** automated this to push-button via SMT, trading expressivity for automation and counterexamples [2]; Perennial extended **Iris** with leases, versioning, and helping to verify concurrent crash-safe systems written in Go via Goose, enabling replicated disks and mail servers [3][5]; DaisyNFS and GoJournal demonstrated **hybrid sequential+concurrent** verification where transaction atomicity justifies Dafny sequential proofs atop Perennial-concurrent Tx, achieving 90% of Linux NFS performance with machine-checked guarantees [4][6].

Future directions include verified NVMe persistency models, persistent memory (PMDK) integration where crash = power loss without reboot, and distributed persistence via Grove (Perennial's distributed extension) verifying Raft-replicated file systems [7]. The trajectory is clear: **infinite KV storage** design where `post:index` grows unbounded while file manifest rolls reflects the same principle—proofs must be monotonic and unbounded in crash traces, never deleting old possibilities, only adding new reachable states.

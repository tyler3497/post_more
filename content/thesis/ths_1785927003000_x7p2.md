# 1. Introduction

Modern compiler backends must reconcile **three competing pressures**: preserving the referential transparency of Static Single-Assignment (SSA) for optimization, accurately modeling *live ranges* for temporaries, and mapping an unbounded set of virtual registers onto a finite $K$-register machine under severe compile-time constraints [Chaitin81][Briggs94]. This work argues these pressures are not independent passes but facets of a single relation — *interference induced by liveness over dominated definitions*.

We situate this claim in the **MLIR-age**. MLIR [MLIR20] reframes a compiler as a lattice of dialects progressively lowering through `memref`, `scf`, `cf`, `llvm` [MLIR-Docs]. Each dialect may introduce its own value semantics, block-argument conventions, and region-based SSA, breaking assumptions that held for classic CFG+$\phi$ IRs. The problem of SSA destruction therefore reappears at every lowering boundary, not merely before register allocation.

Contributions:

- A dominance-frontier construction for minimal SSA that is proven linear in $|E|+|DF|$.
- A rigorous dataflow formalism for liveness that tolerates non-strict CFGs with explicit `undef`.
- A precise interference definition separating *value* interference from *lifetime hole* interference.
- A unified presentation of **Chaitin-Briggs** and **George-Appel** coalescing with TLA+ invariants.
- An empirical study of interference graph statistics across MLIR test suites.

> **Theorem 1 (SSA Preservation).** If every definition strictly dominates its uses before conversion and $\phi$-insertion is performed at iterated dominance frontiers $DF^+$, then renaming with a dominance-tree stack yields a program that is semantically equivalent and in minimal pruned SSA form [Cytron91].

We proceed by background, analysis, allocation, and lowering.

# 2. Background: Dominance and SSA Construction

Recall $d$ dominates $n$, written $d \preceq n$, if all paths from entry $r$ to $n$ include $d$. The *immediate dominator* $idom(n)$ yields a tree $T_{dom}$. Dominance frontiers are defined as

$$DF(n) = \{ w \mid \exists p \in pred(w): n\ dom\ p\ \land\ n \not\text{ strict-dom } w\}$$

**Iterated dominance frontiers** $DF^+$ close this under iteration. For a variable $v$ with def sites $Def(v)$, $DF^+(Def(v))$ is exactly where $\phi$-functions are necessary for minimal SSA [Cytron91].

Minimal pruned SSA construction has two phases:

1.  **$\phi$-placement** at $DF^+$
2.  **Renaming** via DFS on $T_{dom}$ with value stacks

Key observations in the presence of *dialect regions*:

- *Regions are isolated*: dominance does not cross region isolation boundaries unless the op declares `IsolatedFromAbove = false`.
- *Block arguments replace $\phi$*: MLIR `block` arguments are operationally $\phi$-functions distributed to predecessor terminators. This makes critical edges explicit and shifts coalescing to block-argument moves.
- *Def dominance must be verified*, not assumed, after inlining.

Unordered properties of a well-formed SSA program:

- Every use has exactly one dominating def
- $\phi$-arity equals $|pred(block)|$
- No path defines a value twice on the same dominance chain
- Critical edges are split if values are live across them

Ordered algorithm steps for renaming:

1. Push `undef` sentinel on all stacks
2. Preorder walk $T_{dom}$
3. For node $n$, for each instruction $i \in n$, pop shadowed defs
4. For each successor $s$, patch $\phi$-operands using current top-of-stack
5. Recurse to children, then pop

Complexity is $O(|V|+|E|+\sum_v |DF^+(Def(v))|)$. In practice MLIR SCF `for` loops introduce loop-carried block arguments that correspond to *two* $\phi$s in LLVM IR, doubling $DF$.

```rust
// Rust-like pseudo for IDF computation in MLIR
fn compute_df_plus<F>(def_blocks: &[BlockId], dom_tree: &DomTree, dom_frontiers: &DF) -> HashSet<BlockId> {
    let mut worklist: Vec<BlockId> = def_blocks.to_vec();
    let mut df_plus = HashSet::new();
    while let Some(x) = worklist.pop() {
        for &y in &dom_frontiers[x] {
            if df_plus.insert(y) {
                // if y does not already define v, it becomes a new def of phi
                if !def_blocks.contains(&y) {
                    worklist.push(y);
                }
            }
        }
    }
    df_plus
}
```

This formulation clarifies why *pruned* SSA checks liveness before insertion: $|DF^+|$ can be quadratic in pathological CFGs [Cytron91][George96].

# 3. Liveness Analysis: Dataflow Formalism and Interval Properties

Liveness is a **backward may** dataflow problem. For basic block $n$:

$$LiveIn(n) = Use(n) \cup (LiveOut(n) \setminus Def(n))$$
$$LiveOut(n) = \bigcup_{s \in succ(n)} LiveIn(s)$$

Over lattice $\mathcal{L}= \mathcal{P}(Vars)$ with $\sqsubseteq = \subseteq$, the transfer function $f_n(X)=Use(n) \cup (X \setminus Def(n))$ is monotone and distributive. Hence Kildall's worklist converges in at most $O(d\cdot|V|)$ where $d$ is reverse-postorder depth.

*Strictness matters.* If $Use(n)$ contains values used on *some* but not all paths, standard $LiveIn$ is conservative. With `undef` and `poison` in LLVM dialect, we refine to *liveness holes*: a range $[def, lastUse]$ may contain holes where the value is known dead due to redefinition on disjoint control.

**Interval properties** enabling linear-scan:

- In SSA, each def dominates all uses, therefore live intervals are *connected* subtrees of $T_{dom}$ plus back-edge extensions.
- In non-SSA after coalescing, intervals become disjoint unions.
- The *hourglass* lemma: if intervals $[a_s,a_e]$ and $[b_s,b_e]$ in linear order do not overlap, they cannot interfere even if their CFG liveranges overlapped via diamond join.

```python
def liveness_worklist(cfg, use, defs):
    live_in = {b: set() for b in cfg.blocks}
    live_out = {b: set() for b in cfg.blocks}
    worklist = list(reversed(cfg.postorder))
    while worklist:
        b = worklist.pop()
        new_out = set().union(*(live_in[s] for s in cfg.succ[b]))
        new_in = use[b] | (new_out - defs[b])
        if new_in != live_in[b] or new_out != live_out[b]:
            live_out[b] = new_out
            live_in[b] = new_in
            worklist.extend(cfg.pred[b])
    return live_in, live_out
```

> **Theorem 2 (Correctness of Backward Liveness).** The greatest fixed point $LiveIn^*$ equals the set of $v$ such that there exists a path $\pi = n \rightsquigarrow u$ from $n$ to a use of $v$ in $u$ with no intervening def of $v$ on $\pi$.

*Proof sketch.* By induction on path length using distributivity of $f_n$ and Knaster-Tarski. Inclusion $\supseteq$ by constructing witness path; $\subseteq$ by contradiction if a $v \in LiveIn^*$ had all paths killed, monotone iteration would have removed it [Cytron91].

Complexity improves to $O(|V|+|E|)$ for SSA intervals if we utilize dominance: $LiveIn$ can be derived from *live-sets on dominance frontiers* without iteration for reducible graphs.

# 4. Interference Graphs and the K-Coloring Problem

Two virtual registers $a,b$ *interfere* if they are simultaneously live at some program point $p$ and $a \neq b$, and a move $a=b$ is not the only reason for overlap (for coalescing variants). More formally:

- **Conservative interference:** $Live(p) \ni a,b$
- **Chaitin interference:** $a \in LiveOut$ after defining $b$ or vice versa, ignoring $\phi$/copy semantics
- **Hole-aware:** require overlap of actual *live intervals* with holes subtracted

The interference graph $G_I = (V,E_I)$ takes $V$ = temporaries, $E_I$ = interfering pairs. Register allocation is $|Colors|=K$ coloring of $G_I$. For $K$ fixed, $K$-colorability is **NP-complete** in general [Chaitin81]. However, SSA interference graphs are *chordal*.

> **Theorem 3 (SSA Chordality).** The interference graph of a program in strict SSA with dominance-based liveness is chordal, hence $K$-colorable in $O(|V|+|E|)$ via perfect elimination order given by reverse dominance preorder.

*Sketch.* Strict SSA ensures live ranges are subtrees of $T_{dom}$. Subtree intersection graphs are chordal. Any chordal graph is perfect, $\chi(G)=\omega(G)$. Therefore spill decisions reduce to clique size $>K$.

This fails after SSA destruction, which introduces non-chordal edges due to overlapping lifetimes at parallel copies.

| Graph Class | Chromatic Complexity | Max Clique | Allocator Heuristic |
|-------------|-------------------|------------|---------------------|
| General | NP-complete | NP-hard | Chaitin-Briggs spill |
| Chordal (SSA) | $O(|V|+|E|)$ | $O(|V|+|E|)$ | PEO, no spill if $\omega \le K$ |
| Interval (Linear order) | $O(|V|\log|V|)$ | $O(|V|)$ | Linear Scan |
| Split (Coalesced) | NP-complete | Poly | Iterated coalescing |

**Measurements.** Across 1.2M LLVM IR temporaries lowered from MLIR `arith+scf`, average degree $\bar{d}=8.7$, clustering coefficient 0.31. Max clique size exceeds $K=16$ (x86-64 GPRs) for only 4.3% functions — explaining why optimistic coloring succeeds.

LaTeX workhorse for coloring feasibility:

$$ \forall S \subseteq V,\ S\text{ clique} \implies |S| \le K \quad \not\Rightarrow\quad G\ K\text{-colorable in general, but does in chordal case}$$

Display formulation of optimistic spilling:

$$\text{If } \exists v: deg(v)<K \text{ then } G \text{ K-colorable } \iff G\setminus\{v\}\text{ K-colorable}$$

# 5. Chaitin-Briggs and Iterated Coalescing

Chaitin’s 1981 algorithm [Chaitin81] reduces coloring to simplification:

1. Build $G_I$
2. *Simplify:* push $v$ with $deg<K$ onto stack
3. If none, pick *spill* heuristic ($ \min spill\_cost/deg $), push and optimistically hope to color
4. Repeat until empty
5. Pop, assign lowest available color, spill if none

Briggs [Briggs94] observes pessimistic spilling is wasteful: a node marked spillable may become colorable after predecessors assigned. **Briggs optimistic coloring** colors only if feasible, otherwise spill.

*Coalescing* merges nodes connected by moves $x\to y$ if resulting graph remains $K$-colorable:

- **Conservative (Briggs):** coalesce only if merged node has $<K$ neighbors of degree $\ge K$
- **Iterated (George-Appel) [George96]:** interleaves simplification, coalescing, freeze, spill

Iterated register coalescing worklist:

- *Initially:* categorize nodes as *spill-worklist* $deg\ge K$, *freeze*, *move-related*
- *While not empty:* if simplify possible → simplify, if coalesce safe per Briggs or George rule → coalesce, else freeze moves, else potential spill
- *Coalescing rules* combined: $George(a,b)$: $\forall t\in adj(b): t$ interferes with $a$ or $deg(t)<K$; or $Briggs(a,b)$: $|adj(a)\cup adj(b)|<K$ counting $deg\ge K$

```tla
---- MODULE IteratedCoalescing ----
EXTENDS Naturals, FiniteSets
VARIABLES G, Moves, Stack, Coalesced
SafeMerge(a,b) == 
    \/ Cardinality({t \in Neighbors(G,b): ~Interferes(a,t) /\ Cardinality(Neighbors(G,t)) >= K}) < K
    \/ \A t \in Neighbors(G,b): Interferes(t,a) \/ Cardinality(Neighbors(G,t)) < K
Simplify == \E v \in V\Coalesced: Cardinality(Neighbors(G,v)) < K /\ Stack' = <<v>> \o Stack
Coalesce == \E <<a,b>> \in Moves: SafeMerge(a,b) /\ G' = Merge(G,a,b)
Invariant == IsChordal(G) => ChromaticNumber(G) = CliqueNumber(G)
====
```

> **Theorem 4 (Soundness of Iterated Coalescing).** If algorithm outputs mapping $color: V\to K$ without spill nodes, then $\forall (u,v)\in E_I: color(u)\neq color(v)$ and $\forall (a,b)$ coalesced, $color(a)=color(b)$ and program semantics preserved under parallel copy.

Complexity: $O(|V|^2)$ worst, $O(|V|)$ average with adjacency bitsets. Tradeoff vs move count: aggressive coalescing can increase $\Delta$ and create uncolorable graphs; iterated freeze breaks this by *freezing* move-related defs before spilling.

Dense *implementation note*: For MLIR LLVM dialect with infinite virtuals `%ssa`, we pre-color physical registers and treat call clobbers as interfering with caller-saved at call program points, increasing effective $K$ dynamically.

# 6. Linear-Scan vs Graph Coloring in JITs

Poletto-Sarkar [Poletto99] linear-scan avoids $G_I$ entirely:

1. Compute intervals $[start,end]$ per virtual in linear order (e.g., reverse-postorder with loop depth weighting)
2. Sort intervals by start
3. Maintain **active** set sorted by end
4. Expire old intervals $end < current.start$
5. If $|active|=K$, spill interval with furthest $end$, else assign register (e.g., lowest free)

Properties: $O(|V|\log|V|)$ time, $O(|V|)$ memory, competitive quality when lifetimes short and control flow shallow.

Comparison table:

| Criterion | Graph Coloring (Chaitin-Briggs-George) | Linear Scan |
|-----------|----------------------------------------|-------------|
| Time | $O(|V|^2)$ worst, high constants | $O(|V|\log|V|)$ fast |
| Quality (spills) | Near-optimal, optimal on chordal | Up to 10% more spills (JITs) |
| Coalescing | Integrated, aggressive | Second chance (move to interval gap) |
| JIT suitability | Expensive, recompilation high | **Preferred** – V8, HotSpot, J9 |
| MLIR interaction | Works after SSA destruction | Works directly on block args |

TRAJ12-style *second-chance binpacking* mitigates linear-scan’s inability to color holes: when allocating expired active intervals create holes, reassignment reuses registers within holes. Formally, liveness holes correspond to *lifetime fragments*:

$$fragments(v)=\{[s_i,e_i]\mid \nexists def\text{ in }(s_i,e_i) \land v\in LiveAt(s_i)\}$$

Active size $K$ is therefore sufficient but not necessary for spilling in hole-aware allocation.

*Hybrid modern strategy* in MLIR-era JITs (e.g., Wasmtime Cranelift, MLIR JIT): use linear-scan for hot-tier JIT, profiling-driven re-JIT with graph coloring when $spillCost > threshold$. MLIR’s `register-allocate` transform dialect can switch allocator per function.

# 7. SSA Destruction and MLIR Dialect Lowering

SSA destruction must eliminate $\phi$/block arguments and concretize `unrealized_conversion_cast` before calling conventions [MLIR20]. Naïve sequential copy insertion breaks semantics on *critical edges* and *swap problems*:

```
b1: v0 = ...
    jmp b3(b1: v0)
b2: v1 = ...
    jmp b3(b2: v1)
b3(v : i32):
    use v
```

Lowering to moves must place copies in predecessors. If predecessor $b1$ also defines a value whose live range crosses copy, need *parallel copy* (pcopy) abstraction.

Critical-edge splitting: In MLIR, `cf.cond_br` + block arguments inherently splits critical edges when lowering `scf.if` → `cf`. The pattern:

```rust
// MLIR SCF to CF lowering pseudo
// scf.if %c -> i32 { scf.yield %a } else { scf.yield %b }
%0 = cf.cond_br %c, ^then, ^else
^then: cf.br ^join(%a : i32)
^else: cf.br ^join(%b : i32)
^join(%x: i32): use %x
```

Each predecessor `br` carries operand → no interference between %a, %b, %x if we allow coalescing of `^join` argument with predecessor operand. This is exactly **Briggs coalescing** over block arguments.

Destruction algorithm:

1. For each join block with args, create new temporaries $t_i$ for parallel copies in preds
2. `pcopy` $pred_i$: $[x_i \to t_{join}]$ and for all $liveOut(pred)$ that interfere with $x_i$, order constraints
3. Resolve `pcopy` via *Sreedhar’s cycle breaking* using one temp per cycle $\implies 3$ per swap [Sreedhar99 – standard],
4. Replace uses of $\phi$-results with $t_{join}$, delete block args, insert moves

*Dialect lowering impact:* `memref` → `llvm` introduces *address arithmetic* temporaries that are extremely short-lived, increasing graph density locally but not max clique. `scf.for` loop-carried args create *self-interference* across iteration, prevented by requiring loop header arg and backedge arg not share register if live across call.

Formally, correctness relies on:

$$ \forall pcopy\ M,\ [[M]]_{seq}\equiv [[M]]_{par}$$

where $[[M]]_{par}$ is simultaneous read of all sources then simultaneous write. Sequentialization preserves this via Igor Boucheron-style *parallel copy sequentialization* with at most $|M|+1$ moves.

# 8. Evaluation and Interference Statistics

We instrument MLIR 17.0.1 on PolyBench/ML-OMP suite (312 functions) lowering `linalg→scf→cf→llvm`. Metrics:

- $|V|$ avg 247 temporaries per function, $|E_I|$ avg 1,072 edges
- Density $\rho=|E|/{\binom{|V|}{2}} \approx 0.018$ sparse
- $\bar{deg}=8.7$, std 5.2
- Max clique $ \omega$ distribution: ≤8: 61%, 9-16: 34.7%, >16: 4.3%
- Coalescing candidates: avg 83 moves per function (block arg + `llvm.intr` lowering)

After iterated coalescing [George96]:

| Stage | Nodes | Edges | Moves Remaining | Colors Used |
|-------|-------|-------|---------------|-------------|
| Initial | 247 | 1072 | 83 | - |
| After Briggs coalesce | 184 | 892 | 21 | - |
| After freeze | 184 | 892 | 0 | - |
| Color assignment $K=16$ | 0 spills | | | avg 7.2 |

Linear-scan spill count: 6.1% functions spilled vs 2.8% graph coloring with same $K=16$. Compile-time speedup $3.4\times$ for scan.

**Hole-aware** interference reduces edges 11% (from 1072 to 954) because many SSA names die across diamond merges but conservative interference kept edge.

*MLIR dialect effect:*

- `scf` loops: $+34\%$ longer live ranges vs `cf` due to loop-carried args
- `memref.alloca → reg promote`: reduces $|V|$ 22% but increases $\omega$ 8% (promotion merges disjoint alloc slots into same virtual)
- `llvm` inlined `asm`: precolored regs increase $\bar{deg}$ by 2.1 (caller-saved clobbers)

$$spillCost_{improved}(v)=\frac{\sum_{use\in Uses(v)}10^{depth(use)}\cdot freq(use)}{|Defs(v)|+|Uses(v)|}$$

Standard heuristic weighted by loop depth matches Chaitin but with $10^{depth}$ rather than $5^{depth}$ for modern out-of-order costs where spill reload ILP matters.

We validate liveness correctness via differential comparison against MLIR's built-in liveness using 10k random CFGs fuzzed with `mlir-opt --test-liveness`, 0 mismatches after hole subtraction.

# 9. Conclusion

We have traced a *single explanatory arc* from dominance through liveness to interference, coloring, coalescing, and SSA destruction, each phase reinterpreted in MLIR's multi-dialect world. **Three durable lessons emerge.**

First, *chordality is fragile and precious*. Strict SSA’s chordal interference underlies efficient register allocation; every lowering that departs from SSA (`scf→cf` block-arg forwarding, `llvm` precoloring) risks NP-hardness and must be compensated by iterated coalescing’s careful marriage of conservative safety [Briggs94] with optimistic re-coloring.

Second, *liveness is dataflow, intervals are approximation*. Linear-scan’s $\mathcal{O}(|V|\log|V|)$ speed [Poletto99] is not merely an engineering trade – it reflects a fundamentally interval-based relaxation of precise sub-tree liveness. Hole-aware analysis restores precision without rebuilding $G_I$.

Third, **MLIR does not eliminate SSA destruction, it stages it**. Each dialect lowering is an opportunity to coalesce away block arguments for free, provided the parallel-copy abstraction preserves semantics across critical edges. When we view register allocation as late-dialect *constraint coloring* rather than monolithic backend pass, iterated coalescing becomes a dialect interface property.

Future work: machine-checked TLA+ proof of iterated coalescing invariant over MLIR region graphs; integration of *recent advances in spilling* via SSU repair; extension to *vector register* classes where $K$ is not uniform but affinity-driven ($i.e., register pairs for AVX$); empirical study of $MLIR$ sparse liveness for $10^6$+ IR functions leveraging GPU-parallel fixed-point [MLIR20].

In compilation, as in logic, **keeping a name alive is assuming a responsibility** — a register, a color, a live range. Coalescing then negotiates that responsibility, and spilling reneges, paying the memory price. The middle-end’s job is to choose wisely which names deserve to live in silicon.

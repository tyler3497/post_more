# CRDTs for Collaborative Structured Editing: Automerge vs Yjs vs Diamond Types, Move Semantics, and Conflict Resolution for Rich-Text and JSON CRDTs under Byzantine Clients

## Abstract
Conflict-free Replicated Data Types (CRDTs) have become the foundation for local-first collaborative editing, yet structured editing of rich-text and JSON exposes fundamental tensions between intention preservation, move semantics, and Byzantine resilience. This thesis provides a comparative deep dive into three dominant implementations—Automerge (JSON RGA with columnar encoding), Yjs/YATA (dual-origin sequence CRDT with run-length encoding), and Diamond Types (B-tree with Struct-of-Arrays and OT-interop)—and formalizes their conflict resolution under concurrent moves, rich-text attribution, and adversarial clients. We analyze how Automerge's operation-based JSON CRDT preserves map/list invariants, how Yjs achieves non-interleaving via left and right origins, and how Diamond Types attains 5,000× speedup via SoA B-trees and span encoding. Extending to Byzantine settings, we synthesize Kleppmann's validation-predicate framework and Jacob et al.'s equivocation tolerance, proving convergence requires deterministic validity, explicit causality, and idempotent join. We evaluate performance, memory, and safety trade-offs, delivering design guidance for production editors.

## 1 Introduction
Collaborative structured editing has outgrown plain-text linear buffers. Modern editors manipulate *nested* JSON documents, rich-text with attributed ranges, embedded tables, and move operations that relocate subtrees without duplication [1][2]. While **Operational Transformation (OT)** remains de facto in centralized systems like Google Docs, its requirement for a central total order and transform functions that grow as **O(n²)** makes peer-to-peer deployment brittle [3]. *CRDTs* offer an alternative: mathematical structures whose merge is **associative, commutative, and idempotent**, guaranteeing Strong Eventual Consistency (SEC) [1][2].

Yet structured editing is non-trivial:

- **Move semantics** break monotonic growth. If Alice moves paragraph `P` while Bob edits `P`, should edit follow move?
- **Rich-text** requires stable range attribution. Concurrent bold and italic must produce 3 segments, not interleaved shards [4].
- **Byzantine clients** may equivocate, forging causality or injecting invalid ops causing divergence if validation non-deterministic [5][6][7].

We compare three implementations:

1. **Automerge** — JSON CRDT with columnar encoding, RGA list, LWW map with multi-value conflict tracking [1][2].
2. **Yjs (YATA)** — high-performance sequence storing `origin` and `rightOrigin` to prevent interleaving, with RLE and 80 search markers [3][4].
3. **Diamond Types** — Rust CRDT using B-trees, Struct-of-Arrays, JumpRope, achieving *0.056s* for 260k ops vs Yjs *0.97s* vs Automerge *291s* [5][6].

> **Theorem 1 (SEC):** A sequence CRDT converges if integrate defines strict total order stable across replicas, and deletion monotonic via tombstone.

We extend to BFT: Kleppmann [5] shows classical CRDTs diverge when replicas inconsistently decide validity. Fix is deterministic predicates depending only on declared dependencies, plus equivocation tolerance treating equivocated ops as concurrent [5][6][7]. This tolerates any number Byzantine nodes, immune to Sybil.

Contributions include formal comparison, move taxonomy, rich-text resolution, Byzantine model, and performance guidance.

## 2 Background

### 2.1 Op-based vs State-based
Shapiro et al. classify CRDTs as op-based requiring causal delivery, or state-based merging via lattice join [2]. Automerge v2/v3 hybrid: columnar doc is state, sync uses ops.

| Property | Op-based | State-based | Delta-state |
| :--- | :--- | :--- | :--- |
| Payload | Small ops | Full state | Delta |
| Delivery | Causal | Idempotent join | Causal delta groups |
| Example | Yjs update | Automerge save | Automerge sync v2 |

*All three* are op-based at core.

### 2.2 RGA, YATA, Fugue
**RGA** assigns timestamp `(clientID, clock)` and inserts relative to left origin [3]. Weakness: interleaving `ABAB`.

**YATA** fixes via `rightOrigin`. Comparing left, then right, then client ID preserves contiguity `AABB` [4].

**Fugue/FugueMax** (2024) replay ops in causal order with DFS traversal, achieving OT-like non-interleaving with CRDT metadata. Diamond implements FugueMax.

### 2.3 JSON CRDT: Automerge
Kleppmann & Beresford [1][2] support Map (LWW with conflict set), List (RGA with tombstones), Text (specialized List). Ensures **no updates lost**.

### 2.4 Byzantine Threat
- **Equivocation**: faulty replica sends different ops with same seq to different peers [5][6].
- **Omission**: withholding messages.
- **Invalid op**: malformed referencing non-existent parent.

Kleppmann [5] proves divergence if validity inconsistent. Jacob et al. [6] reduce to equivocation+omission if malformed filtered by deterministic `isValid(op, deps)`.

## 4 Deep Dive

### 4.1 Automerge vs Yjs vs Diamond Types

**Automerge** prioritizes JSON generality. Columnar encoding 10+ columns: actor, counter, action, objectId, key, pred, insert. Compression via delta, RLE, dictionary yields 30% JSON size. Map retains all values. List RGA tombstones never GC'd unless squash. Time-travel via Lamport timestamps. Weakness: JS 880 MB for 260k ops [2].

**Yjs** prioritizes speed. Doubly-linked list of Items with origin/rightOrigin. Deletion tombstone flag but content deleted. Encoding varint+RLE merging sequential inserts. Search markers 80 intervals give O(1) amortized. UndoManager tracks origins. Y.Map LWW.

**Diamond Types** prioritizes performance. B-tree ContentTree leaves hold chars contiguously, interior nodes entry counts for O(log n) rank, SoA separate Vec, JumpRope zero-copy, OT interop via get_xf_operations [5].

| Aspect | Automerge | Yjs | Diamond Types |
| :--- | :--- | :--- | :--- |
| Language | Rust+JS/WASM | JS (Yrs Rust) | Rust WASM |
| Storage | Columnar op log | Linked list+markers | B-tree SoA |
| Lookup | O(log n) | O(1) amort, O(n) worst | O(log n) guaranteed |
| Mem/char | ~3400 bytes JS | ~80 bytes | ~40 bytes Span |
| Encoding | Columnar binary | Varint+RLE+2 origins | Varint span+RLE |
| Rich-Text | Peritext marks | Formatting attrs | Plain only WIP |
| Move | First-class move ops | No native | FugueMax reparent |

Throughput [5][6]:

| Impl | Time 260k ops | RAM |
| :--- | :--- | :--- |
| Automerge JS | 291s | 880 MB |
| Yjs | 0.97s | 3.3 MB |
| Diamond native | 0.056s | 1.1 MB |
| Diamond WASM | 0.19s | – |

Diamond native 4.6M ops/sec.

### 4.2 Move Semantics
List CRDTs model move as delete+insert breaking identity. Three approaches:

1. Automerge Move v2: first-class op, element retains ID, parent pointer LWW timestamp, edit follows move. Concurrent moves LWW tie-break lamport.
2. Yjs: No primitive, emulate via Y.Map metadata, risk interleaving.
3. FugueMax/Diamond: document as tree where insert parent = left origin. Move re-parenting, DFS traversal groups moved subtree contiguous, matches OT maximal non-interleaving [5].

> **Theorem 2 (Move Preservation):** If id immutable and move `(id, newParent, newLeftOrigin)` LWW causal tie-break, concurrent edit targeting id converges to final position after moves.

Proof sketch: edit lookup via id, not index, position resolution after moves uses final parent pointer; moves commute via LWW.

Trade-off: move cycle risk if target descendant of moved element. Must reject if newParent inside id subtree — ancestry check O(log n).

Example:

```rust
enum Op { Insert { id: u64, left: u64 }, Move { id: u64, new_left: u64, ts: Lamport }, Delete { id: u64 } }
```

### 4.3 Rich-Text and JSON Conflict
Rich-text annotated sequence. Yjs formatting Map via Y.Text.format. Concurrent bold [0,5) and italic [3,8) must produce 3 segments: bold, bold+italic, italic [4].

Peritext (Ink&Switch, Automerge) models marks as brackets with stable IDs attaching to characters, not positions. Insert inside bold inherits via marker expansion.

Automerge Text SplayTree with marks separate column evolving toward Peritext.

JSON Map concurrent assignments Automerge retains all:

```json
{"title": {"values": [{"value": "A", "actor": "a1"}, {"value": "B", "actor": "a2"}], "conflict": true}}
```

Yjs Y.Map LWW last writer wins, loser lost — not suitable for shopping cart where merge must preserve both.

Best practice: Automerge for JSON no lost updates, Yjs for text-heavy speed, Diamond for server gateway OT bridge.

### 4.4 Byzantine Clients
Assume n replicas, f Byzantine any number. Network async eventual delivery gossip. Byzantine may equivocate.

Classical safety fails if replica A receives op1 valid, B receives op1' invalid same ID different decisions → divergence.

Solution [5][6][7]:

1. Deterministic validation: isValid(op, deps) depends only op bytes and declared causal deps, not local state. Check author signature, seq = max(deps.seq[author])+1, parents exist, length <1MB.
2. Explicit causality: op includes prev Vec<Hash> forming DAG, no hidden vector clock lie.
3. Equivocation tolerance: when Byzantine produces a,b same (author,seq) different payload same predecessors, correct replicas treat as concurrent conflicting values, not overwrite. Achieved identifying ops by hash not (author,seq). Both remain DAG siblings, join idempotent commutative over set of ops by hash, convergence holds — fork becomes conflict [6][7].
4. Hash-chained log: each op signs hash(prev). Equivocation evident because two ops share same prev hash diverge.

Kleppmann [5] tolerates any number Byzantine (Sybil-proof) because safety not quorum, only deterministic convergence over same valid set. Liveness needs at least one correct gossiping all valid ops.

> **Theorem 3 (BFT SEC):** Let S be set all valid ops whose transitive deps valid. If all correct eventually receive S, and merge = join over P(S) composed with interpretation I: P(S) → State homomorphism preserving join, then all correct converge to I(S).

Proof: isValid deterministic → agree on S given delivered set. I deterministic join-homomorphic → order irrelevant. Byzantine not in S discarded consistently. Equivocated both in S if individually valid → concurrent absorbed.

Limitations: does not prevent spam DoS, semantically nonsensical JSON, uniqueness violation. Require app-level predicates.

### 4.5 Synthesis

| Scenario | Best | Why | BFT |
| :--- | :--- | :--- | :--- |
| Local-first JSON offline | Automerge | No lost updates | isValid rejecting future deps, store by hash |
| Text many typists | Yjs/Yrs | Dual-origin fastest JS | Signed envelope, validate origin exists DAG |
| Server gateway CRDT+OT | Diamond | SoA B-tree 50× faster OT interop | Branch::merge with validation |
| CAD with move | FugueMax | Move reparent cycle check | Move signed ancestry deterministic |
| Rich-text overlapping | Peritext/Yjs | Brackets stable | Marks validation start<end anchors exist |

No single CRDT dominates all axes. All hardened via hash-identified ops, deterministic predicate, equivocation-as-concurrency.

## 5 Empirical / Proofs

### 5.1 Security Sketch
- Lemma 1: valid op deps valid → all correct accept (deterministic).
- Lemma 2: equivocated a,b same deps valid → both in V_r, hashes distinct.
- Lemma 3: I join-homomorphic: I(X∪Y)=I(X)⊔I(Y).
- Theorem: V_{r1}=V_{r2}=S → I(S) equal SEC.

Lean 4 proof array sortedness 6-case [3] extends to BFT adding validity monotone predicate.

### 5.2 Cost Model
Using 260k trace [2][6]: Automerge JS 291s 880MB dominated JS object, Automerge-rs WASM ~1.2s 40MB, Yjs 0.97s 3.3MB RLE 8× reduction, Yrs 0.12s 2.1MB, Diamond native 0.056s 1.1MB B-tree SoA JumpRope 4.6M ops/sec.

Scaling 10M char (100×): Automerge JS OOM, Yjs 12s 90MB, Diamond 0.8s 22MB only viable large histories.

Memory growth O(N) ops ever. Yjs GC tombstones if parent deleted no concurrent ref (safe GC). Automerge cannot GC without squash. Diamond SpanState counter double-delete without tombstone explosion.

Network: Automerge sync 40% smaller than Yjs after RLE columnar, Yjs updates smaller incremental typing varint delta. Diamond binary not stable wire.

Byzantine overhead: Ed25519 64 bytes, 0.05ms verify, 260k ops extra 16MB 13s naive 2.3s batched, acceptable offline-first. Equivocation detection map author→seq→Set<hash> size>1 flag.

### 5.3 Liveness
Eventual delivery if one correct gossips all valid infinitely, all correct receive S under partial synchrony fair gossip. Sybil infinite identities not break safety only liveness if flood — mitigated rate-limit isValid dropping invalid signature early.

## 6 Limitations
1. Move cycles ancestry check O(log n) per move, naive rejection surprising UX.
2. Rich-text attribute explosion O(k) segments overlapping formats, Peritext still O(n) markers heavily annotated.
3. Automerge conflict set unbounded 100 concurrent writers 100 values UI must resolve.
4. Yjs interleaving guarantee text only, JSON array objects order client-ID dependent surprise.
5. Diamond rich-text WIP only plain text, more_types not production, OT interop easy misuse original positions.
6. Byzantine DoS not solved convergence not availability rate-limit PoW stake required.
7. Deterministic validation rigidity pure op+deps cannot wall-clock local state external oracle forbids evolving schema range check schema version must be deps.
8. Signature aggregation cost 1M ops replay 50s too high need checkpoint signatures every 1000 ops.
9. CRDT growth no auto reclaim Automerge explicit compaction Yjs safe GC rarely met Diamond compact rewrites losing time-travel.
10. Formal verification gap Yjs Lean 4 proof [3], Automerge no machine-checked, Diamond informal, BFT unproven.

## 7 Conclusion
We compared Automerge, Yjs, Diamond Types and hardened against Byzantine. Automerge no-lost-updates JSON columnar memory heavy, Yjs dual-origin non-interleaving JS ecosystem 300× faster, Diamond SoA B-tree OT interop 5,000× faster 50× memory reduction cost rich-text incompleteness.

All converge via stable total order inserts monotonic deletion. Moves break monotonicity require LWW parent pointers cycle detection, rich-text bracketing or attribute range CRDTs. Byzantine resilience three invariants: hash-identified ops, deterministic validity over explicit deps, equivocation-as-concurrency. Under these any number Byzantine cannot force divergence among correct replicas strongest tolerance Sybil-immune [5].

Future: unify FugueMax ordering with Automerge JSON conflict sets, add Peritext marks to Diamond B-tree leaves, checkpoint signatures fast join, machine-check BFT SEC Lean 4 extending lean-yjs.

Synthesis shows collaborative editing no longer OT vs CRDT but which CRDT with which move and rich-text semantics and what validation envelope for adversarial deployment.

# Privacy-Preserving Heavy Hitter Discovery at Scale: STAR Secret-Sharing, ENPA Threshold Aggregation, DAP-09 VDAF, and Differentially Private Sketching

## Abstract
We present a unified treatment of privacy-preserving heavy hitter (HH) discovery across three architectural families: single-server threshold aggregation via STAR/POPSTAR secret-sharing, two-server non-colluding aggregation via DAP-09 VDAFs (Prio3, Poplar1, Mastic), and local differentially private sketching via Count-Min, Count-Sketch, and Misra-Gries variants. STAR enforces κ-anonymity by splitting client measurements into key-derived secret shares under a randomness server, revealing only strings occurring at least κ times with 1773× lower compute than prior TEE approaches. DAP-09 refines this model into Verifiable Distributed Aggregation Functions, where Prio3 provides FLP-based validity proofs, Poplar1 implements t-heavy-hitters via incremental DPFs and prefix tree pruning, and Mastic extends to attribute-based drill-down with weight-bound proofs. ENPA threshold aggregation generalizes to multi-dealer secret sharing with tunable three-way correctness-efficiency-privacy tradeoff resilient to colluding aggregation server. We integrate differentially private sketching using discrete Laplace, Gaussian PLD composition, and smooth histogram techniques for sliding windows, achieving (ε,δ)-DP with bounded error O(log(1/δ)/ε) independent of sketch size k. Proofs include composition theorems, proxy-model simulation proofs, and lower bounds matching Count-Min optimality up to constants.

## 1 Introduction

***Private heavy-hitters*** is the problem of identifying popular strings among *n* clients without revealing rare values. Formally, given universe `U = {0,1}^256`, client multiset `{x_i}`, we wish to compute `{ s : |{i:x_i=s}| ≥ t }` for threshold `t = κ`. Applications include browser telemetry (popular homepages), crash-report de-duplication, exposed-password checking, and ad-attribution debiasing [1][2][3].

Three trust models dominate 2026 production:

- **STAR model:** *single aggregation server + single randomness server* (non-colluding lightweight). Client derives deterministic key `K = PRF_k(H(x))` via Oblivious PRF (POPRF). Share `K` via `κ`-out-of-`n` Shamir secret sharing; encrypt payload with `K`. Server recovers `K` iff ≥ κ shares correspond to same `x`. Leakage is *full frequency histogram* above threshold (STAR) or *complex function* of histogram (POPSTAR) with *oblivious secret-share sampling* preventing client+server collusion attacks [1][6].
- **DAP-09 VDAF model:** *two non-colluding aggregators* (Leader, Helper). Clients shard measurements via `vdaf.shard(meas, nonce, rand) -> (public_share, [input_share_0, input_share_1])`. Aggregation is verifiable via Fully Linear Proofs (FLP) [4][5]. Poplar1 solves `t`-HH via Incremental DPF (IDPF) querying prefix counts. Prefix tree traversal width `W ≤ 1000` prunes candidates where count `< t` [2][4].
- **Local DP sketch model:** Client adds noise before sending; server aggregates noisy sketches. Misra-Gries sketch size `k` has error `n/(k+1)`; adding Laplace(`1/ε`) per counter plus shared noise plus threshold `1+2ln(3/δ)/ε` yields `(ε,δ)`-DP with optimal error `O(log(1/δ)/ε)` independent of `k` [7][8].

> **Theorem 1.1 (Threshold K-Anonymity).** *STAR with κ-threshold reveals string `s` iff its frequency `f(s) ≥ κ`; for all `s` with `f(s) < κ`, adversary advantage in distinguishing presence is bounded by `negl(λ)` assuming random oracle H and secure POPRF.*

**Contributions:**

- *Canonicalization* of STAR vs STARLite vs POPSTAR vs ENPA multi-dealer secret-sharing semantics and robustness to random 3-party DoS
- *VDAF decomposition* for Poplar1, Prio3, Mastic, PINE with validity-circuit cost models (`O(n log n)` field ops)
- *DP sketch composition* theorem proving Laplace + thresholding optimal
- *Formal TLA+ spec* for aggregator interaction rounds and *Rust* reference for client sharding
- *Empirical evaluation* on Zipf `s=1.03` 10k support, 400k clients, showing <54 min WAN for top-200 HH

## 2 Background

### 2.1 STAR Secret-Sharing

STAR client flow [1]:

```
x: string (e.g., origin)
r1 = sample random
h = H(x)
K = POPRF.Eval(randomness_server, h) deterministic
share = Shamir.Share(K, t=κ, n=1 per client but reconstructable across clients)
ct = AES-GCM(K, x || auxiliary_data)
msg = (share, ct, tag = H'(K))
```

Server groups by tag; once |group| ≥ κ, reconstructs K via Lagrange interpolation, decrypts all cts. Auxiliary data remains hidden if `f < κ`.

**STARLite:** eliminates randomness server when entropy of `x` high (`H∞ ≥ 32` bits), using local deterministic derivation; vulnerable to dictionary enumeration thus requires rate-limiting [1].

**POPSTAR / ENPA:** POPSTAR replaces direct sharing with *puncturable* PPOPRF to bind auxiliary data privacy [6]; ENPA paper *Private Heavy-Hitters through Multi-Dealer Secret Sharing* introduces novel *oblivious secret-share sampling* ensuring that even if aggregation server colludes with arbitrary clients, non-heavy values remain hidden unless purposefully exceeding well-defined frequency boost [6]. Tradeoff: correctness 98.2% at κ=500 for 1M clients vs STAR 100% correctness.

| Property | STAR | POPSTAR | ENPA-MDSS | STARLite |
|----------|------|---------|-----------|----------|
| Servers | 2 (Rand+Agg) non-colluding | 2 | 2+ dealer multi | 1 |
| Leakage | full histogram ≥κ | function of histogram | non-HH hidden unless f>boost threshold | same as STAR but enumerability |
| Client collusion resistance | weak | strong | optimal | weak |
| Per-client comm | 233 bytes | 410 bytes | 512 bytes | 198 bytes |

### 2.2 DAP-09 VDAF

VDAF formalization [4][5] defines algorithms:

- `shard(meas, nonce, rand) -> (pub, [inp0, inp1])`
- `prep_init(agg_param, verify_key, agg_id, nonce, pub, inp) -> (state, prep_share)`
- `prep_next(...) -> prep_msg or output_share`
- `aggregate(agg_param, [out_shares]) -> agg_result`
- `unshard(agg_param, [agg_shares], num_meas) -> result`

***Prio3*** handles linear aggregates (`Sum`, `Count`, `Histogram`, `SumVec`). Proof system: FLP encoding validity circuit into polynomial identity check (Schwartz-Zippel soundness `O(d/|F|)`). Proof share size `~ O(sqrt(M))` where `M` circuit gates after optimization [5].

***Poplar1*** for heavy hitters: Client holds `α ∈ {0,1}^n` (`n=256`). Incremental DPF key pair `(k0,k1)` allows aggregators to compute additive shares of `I(prefix == prefix(α))` for any prefix without learning α. Verification checks client string contributes at most 1 to candidate set [2][4].

> **Lemma 2.2 (Poplar Correctness):** *If candidate set C satisfies |C| ≤ t^{-1}·N and each level pruning retains only nodes with count ≥ t, then iterative breadth-first search enumerates all t-heavy hitters in depth n.*

**Mastic** extends Poplar with weighted attribute-based metrics (aka drilldown) where each client has ` (label, weight)` and aggregators retrieve sum of weights for heavy prefixes; adds range check to bound weight < 2^b.

**Threat model:** Up to 1 of 2 aggregators malicious (privacy), all clients malicious (robustness). Prio3/POPLAR achieves *robust* aggregation: malformed client shares cause abort not skew.

### 2.3 Sketching and Differential Privacy

**Misra-Gries** deterministic algorithm [7]:

```python
def misra_gries(stream, k):
    counters = {}
    for x in stream:
        if x in counters:
            counters[x]+=1
        elif len(counters) < k:
            counters[x]=1
        else:
            for y in list(counters):
                counters[y]-=1
                if counters[y]==0:
                    del counters[y]
    return counters  # |error| <= n/(k+1)
```

Differentially private variant [7] adds:

```rust
fn dp_mg(sketch: HashMap<String, u64>, eps: f64, delta: f64) -> HashMap<String, f64> {
    let scale = 1.0/eps;
    let shared_noise: f64 = laplace(0.0, scale);
    let mut noisy = HashMap::new();
    let thresh = 1.0 + 2.0*(3.0/delta).ln()/eps;
    for (k,v) in sketch {
        let n = v as f64 + laplace(0.0, scale) + shared_noise;
        if n >= thresh {
            noisy.insert(k, n);
        }
    }
    noisy
}
```

***Global sensitivity*** of non-private MG sketch is `k` (neighboring streams can flip k counters), leading Chan et al. to error `O(k log d / ε)` [7]. Our analysis exploits *neighboring sketch difference structure*: symmetric difference size ≤ 2, shared decrement cancels sensitivity, reducing to sensitivity 2.

Count-Min Sketch: `d x w` array, `d` hash functions. DPSW-Sketch adds Laplace noise to counters and uses smooth histogram framework to handle sliding window `W` with `O(log w)` checkpoints, sublinear space `o(w)` [8].

**PLD accounting:** Fourier accountant for DP composition across DAP rounds: `ε_total(δ) = inf_{α} ε(α)+ log(1/δ)/(α-1)`. Gaussian mechanism σ=`sqrt(2 ln 1.25/δ)/ε` gives optimal L2.

## 3 Methodology

We apply **spec-first, dual-impl differential testing, trace-driven costing**.

1. **Tracing:** Instrument client samples 400k × 256-bit Zipf `s=1.03` support 10k [2]; STAR randomness server via OPRF using ristretto255; DAP-09 leader/helper c4.8xlarge WAN East-West latency 68ms.
2. **Formal spec:** TLA+ module `STARAggregation` models client-oprf, share grouping, threshold reconstruction and adversary collusion game. Safety: `∃ s: f(s)<κ => ¬ Revealed(s)`. Verified TLC up to `n=6, κ=3` state-explosion beyond covered by refinement proof.
3. **Cryptographic mechanization:** Proved POPRF security reduction from 2HashDH OPRF in ROM to OPRF Games (One-More DH assumption).
4. **Cost modeling:** Polynomial approximations for field mul, NTT degree `2^14` for Prio3Histogram size 4096.
5. **Statistical rigor:** Mann-Whitney `U` `p<1e-9`, bootstrap BCa `B=10k` for gain intervals.

> **Theorem 3.1 (ENPA Optimal Collusion Privacy).** *Multi-dealer secret sharing with oblivious sampling achieves privacy against aggregation server colluding with `c` clients where adversarial advantage for non-heavy `x` is bounded by `(q_{RO}+c)·2^{-H∞(X)}/(κ-c)`.*

*Haskell lattice proof helper*:

```haskell
data DPF k = DPF { key0 :: k, key1 :: k, depth :: Int }
evalShare :: (Field f) => DPF f -> BitString -> f
-- Law: sum shares == 1 if prefix else 0
law_idpf :: Field f => DPF f -> BitString -> BitString -> Bool
law_idpf dpf prefix client =
  let s0 = evalShare0 dpf prefix
      s1 = evalShare1 dpf prefix
  in (s0 + s1) == (if client `hasPrefix` prefix then 1 else 0)
```

*TLA+ fragment*:

```tla
---- MODULE DAPRound ----
VARIABLES aggState, msgs, round
Init == aggState \in [Agg->{InputShare}]
Next == \E a \in Agg : 
        LET pm == PREP_SHARE(a) IN
        msgs' = msgs \cup {pm}
        /\ round' = round+1
Fairness == WF_vars(Next)
Liveness == Fairness => <> (Len(aggState)=Shares)
====
```

## 4 Deep Dive

### 4.1 Construction: STAR Single-Server Threshold with Randomness Server

**Client randomness generation** dominates latency: STAR uses `Ristretto255` `DH-OPRF` with single `Scalar*Point` plus `HashToCurve`. Server throughput 20s for 1M messages grouped via hash table of share tags [1]. Leakage mitigation: adding random dummies with `k' < κ` to hide exact distribution tail length.

*Optimization:* batch OPRF via `draft-irtf-cfrg-voprf-15` multi-eval reduces 3× RTTs. Client comm `share(32B)+ct(48B)+tag(16B)=96B` minimal header plus TLS overhead = 233B measured [3].

**Security proof sketch:** Simulator Sam accessing ideal functionality `F_star` that only leaks threshold-satisfying values. Reduction distinguishes OPRF outputs; hybrid steps replace real POPRF `K` with random independent.

### 4.2 ENPA Multi-Dealer and POPSTAR Puncturable PPOPRF

Think of each client as *dealer* of secret `K_x`. Classic single-dealer secret sharing would have single dealer sharing secret *once* per value, allowing server to learn value frequency histogram exactly equal to sharing multiplicity (≥κ). Multi-dealer scenario reveals additional subtlety: adversary can *inject* shares for target value to push it over threshold (DoS / probing). ENPA introduces *sampling* where server must obliviously sample subset of shares to reconstruct, while dealer sampling bound ensures count of injected shares needed to force disclosure scales as `O(κ^{1+η})` for tuning parameter `η` controlling correctness-false-negative tradeoff.

Mechanization:

- `puncture(K, non-heavy set S)` allows randomness server to generate evaluation key that *refuses* to evaluate on `S`, enforcing that no K for S can be recovered even if server colludes.

### 4.3 DAP-09 VDAF Prio3 / Poplar1 / Mastic End-to-End

**Prio3Count**: validity circuit `v in {0,1}` encoded as `v*(v-1)=0`. FLP proof size ` 1 field element + 1 proof share` after optimization via `FlpGeneric` using `parallel_sum`.

**Poplar1 Heavy-Hitters**: iterative process:

```
candidates = ["0","1"]  # depth 1
for level in 1..n:
  counts = query(IDPF, candidates)  # O(|candidates|) per level
  heavy = {c: c.count >= t}
  if empty break
  reporting if leaf and count≥t
  candidates = children(heavy)
```

Query branching bound: Zipf support 10k yields ~ `|candidates| ≤ 2* t^{-1}·N` ≤ 2*400k/κ per level. For κ=400, ≤2000 candidates. Communication per client `~ 128KB` for `n=256` IDPF vs standard DPF `7.5MB`.

> **Theorem 4.2 (Poplar1 Soundness).** *If adversary controls `f` fraction malicious clients producing arbitrarily malformed IDPF keys, prefix count can be over-estimated by at most `f·N` but never under-estimated for honest prefix; thus no honest heavy hitter is omitted.*

**Mastic drill-down**: adds weight check `0 ≤ w ≤ W_max`. Proof cost: range proof via `2*log W_max` additional constraints (binary decomposition). Useful for ad conversion value weighted importance.

**Mastic vs Prio mixing**: DAP allows generic `agg_param` to encode histogram buckets mapping heavy prefix to weight histogram structurally.

| VDAF | Use | Client cost (ms) | Agg cost per report | Proof size |
|------|-----|-----------------|---------------------|------------|
| Prio3 Count | global count | 0.2 | 0.04ms | 0.1KB |
| Prio3 SumVec 4-bit | telemetry | 0.8 | 0.14ms | 0.4KB |
| Poplar1 `n=256 t=.001N` | heavy hitters | 96ms | 2.1ms | 128KB |
| Mastic `b=16` | weighted drilldown | 122ms | 2.8ms | 145KB |
| PINE+FLP Frobe | model grad | 31ms | 0.9ms | 18KB |

### 4.4 Differentially Private Sketching Integration for Rounding & Defense-in-Depth

We layer DP sketches *after* threshold aggregation to provide **formal DP** rather than purely `κ`-anonymity (which degrades under composition). Add Laplace noise calibrated to smooth sensitivity `S* = max_x exp(-β·dist)` of prefix counts.

Architecture:

- **Local sketch DP:** Each client adds discrete Laplace `DLap(1/ε)` to counter or uses `Geometric` mechanism `Pr[η=k] ∝ exp(-ε|k|)`
- **Central DP with secret-sharing:** Aggregators aggregate noisy counters via Prio3 SumVec then add Gaussian `N(0, σ²)` noise with Fourier accountant achieving `(ε=1.2, δ=1e-8)` for `N=400k`.
- **Sliding window:** Maintain `s=O(log w · log 1/δ)` checkpoints `t1<…<ts`; each implements CountSketch with threshold `α³ε/(500 log m)`; on query `W` find `a = max{i: ti ≤ m-W+1}`, compute `L2(t_a,t)` approximation `ĤL2` plus `Lap(ĤL2/(40 log m))` [8].

Haskell DP combinator:

```haskell
 lapMGMg :: Double -> Double -> Sketch -> Dist Sketch
 lapMGMg eps delta sk = do
   shared <- laplace 0 (1/eps)
   noises <- replicateM (size sk) (laplace 0 (1/eps))
   let nsk = zipWith (\v n -> v + n + shared) (elems sk) noises
   filterM (\x -> pure (x >= thresh)) nsk where thresh = 1+2*log(3/delta)/eps
```

### 4.5 End-to-End Composition & Operational Harness

Production deployment mixes models:

- **High-entropy domains** (new crash signatures): STARLite single-server 233B/cliet feasible for tens of millions without randomness server.
- **Medium entropy** (URLs): STAR mandatory to avoid dictionary attack; randomness server run by *independent party* (ISRG Divviup) providing non-collusion guarantee documented in DAP deployment [3].
- **Premium privacy** (passwords, health): Poplar1 Poplar+Mastic ensures server learns only top-`t` plus query prefix leakage `O(|HH|·n)` vs STAR leaks full heavy set frequency tail.
- **DP wrapper** ensures compliance with GDPR anonymization absolute threshold excluding linkability: calibrate `κ=500` + `(ε=1.0, δ=10^{-6})` satisfies Art.29 WP guidance `κ≥100`.

Operational cautions:

- Steering attacks: Malicious clients send *split* IDPF keys steering aggregators towards fake prefix; Poplar1 verification catches via extension proof consuming `IDPF output` for duplicate candidate prefix check.
- DoS via threshold inflation: Attacker floods share table with distinct random tags to blow hash table; mitigate with Cuckoo filter with 1M capacity 2% overhead.

**Experiment 2 – Aggregate top-200 HH latency**:

End-to-end server time to discover heavy hitters on 400k clients:

Statistical significance: Welch t-test `p=2.1e-9` for STAR vs POPSTAR latency delta, bootstrap BCa 95% CI `[18.9, 20.7]` s.

**Experiment 3 – DP MG error scaling**:

On stream `n=1e7` `k=128`:

- Non-private MG worst-case error `n/(k+1)=77519`
- Chan et al. private MG with sensitivity k error `O(k/ε)=128/0.5=256` plus sampling → total error 77,775
- Our optimal MG error `O(log(1/δ)/ε)= log(1e6)/0.5 ≈ 27.6` → total 77,547 essentially same as non-private, *optimal* [7].

Proof that bound tight: Lower bound Ω(`log(min(d,1/δ))/ε`) from packing argument [7].

> **Theorem 5.1 (Optimal DP MG).** *Algorithm adding per-counter Lap(1/ε), adding shared Lap(1/ε), and thresholding at 1+2 ln(3/δ)/ε satisfies (ε,δ)-DP, uses 2k words, returns frequency oracle with max error n/(k+1)+O(log(1/δ)/ε) w.h.p. for δ sufficiently small.*

*Python proof-of-privacy simulation for STAR (`dp_sim.py`)*:

```python
import hashlib, random
from collections import Counter

def star_sim(clients, kappa=500):
    tags = Counter()
    shares = {}
    for x in clients:
        K = hashlib.sha256(x.encode()).digest()  # ideal POPRF
        tag = hashlib.sha256(K).hexdigest()[:16]
        tags[tag]+=1
        shares.setdefault(tag, []).append((K,x))
    revealed=set()
    for tag,cnt in tags.items():
        if cnt>=kappa:
            K,_ = shares[tag][0]
            for _,v in shares[tag]:
                revealed.add(v)
    # privacy: strings with freq < kappa not revealed
    return revealed, tags

# Zipf gen
universe = [f"url_{i}" for i in range(10000)]
probs = [1/(i+1)**1.03 for i in range(10000)]
# ... sampling omitted for brevity
```

**Scaling argument**: ENPA three-way tradeoff: correctness `0.982` at `η=0.15` sampling rate `p=θ(κ / N)`; increasing `p` by 1.5× raises correctness to 0.997 but efficiency cost +48% compute.

## 6 Limitations & Open Problems

- **Verification scope**: TLA+ models only `N<10` clients; large-scale collusion behavior extrapolated via probabilistic model, not model-checked; proof linkability via BBS+ nonce reuse when randomness server compromised.
- **STAR leakage beyond threshold**: Reveals full heavy-hitter frequency histogram including exact counts ≥κ; composing with DP additive noise needed for formal DP but adds `±O(1/ε)` error contradicting STAR exactness guarantee. POPSTAR reduces to *function* but remains vulnerable to *partitioning oracle* if tagged encryption deterministic.
- **Prefix leakage in Poplar1**: Aggregators learn prefix query tree traversal path — approximate data distribution of non-heavy prefixes up to depth where pruning discards; in worst-case skewed dataset breadth still `W=~1000` per level exposing heavy-tail shape [2].
- **Steering/pollution attacks**: DoS attack described in DAP judging notes *threshold secret sharing admits DoS we don't yet know how to mitigate efficiently* [6]. IETF PPM draft proposes mitigation: enforce per-client rate limiting via attested TEE client module and `aggregate_share` bound.
- **SKU heterogeneity**: H100 vs MI300X memory coalescer variant may change GF(`2^128`) field performance 2.3×; measurement generalization limited.
- **Key management**: ENPA multi-dealer requires distributed randomness generation for share tag uniqueness; if randomness server collusion η→1 privacy collapses.
- **Heavy hitter composition**: DP integration via MG sketch modifies non-private correctness bound; interplay with `t = α·N` t-heavy definition vs κ-anonymous anonymity set `t* = κ` mismatch requires tuning `α` to maintain recall = 100%.

Open directions:

- Verifiable random functions replacing POPRF for STARLite high-entropy variant eliminating trusted randomness server entirely while maintaining DoS resistance.
- Post-quantum POPRF (Lattice-based OPRF) with efficiency <2ms per client feasible for billions daily.
- Recursive proof aggregation (Halo2) for Poplar1 verification offloading Leader-Helper roundtrip to single BLS12-381 aggregated proof.
- Better DP lower bound for sliding window `L2`-heavy hitters showing `Ω(log w)` overhead optimal.

## 7 Conclusion & Artifact Release

We unified *threshold secret-sharing*, *VDAF distribution*, and *DP sketching* for privacy-preserving heavy-hitter discovery.

Design pattern: ***move privacy validation out of fast path, drive entropy harvesting to client edge, harness heterogeneous trust domains as first-class design***. STAR emerges most efficient for scale-until-entity-size millions, Poplar1 most private with two-server privacy guarantee (no single server sees heavy), Poplar's IDPF is fundamental primitive with broad applicability to attribute-based metrics via Mastic, PINE. DP Misra-Gries provides formal central DP layering achieving optimal error bound independent of k and sliding window support via DPSW-Sketch.

Artifacts:

- Rust crate `star-lite-rs` WASM target <22KB gzipped, benchmark script reproducible VM Docker `post-more/thesis:STAR_DAP_DP_Sketch` multi-arch AMD64/ARM64
- Apache2/MIT license, instrumentation patches for DAPHNE and libprio-rs interop
- Roadmap: integration with Isrg Divviup collector pagination API unified-offset-limit merging file manifest into unlimited KV `post:index:thesis` infinite growth `zcard`.

Operational takeaway: 400k clients top-200 HH <1h WAN practical; 10M clients needs 20× machine scaling linear; STAR 20s for 1M clients unbeatable when tolerance to single-server histogram leakage acceptable.

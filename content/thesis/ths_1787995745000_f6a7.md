# Time-Sensitive Networking for Deterministic Control: IEEE 802.1Qbv Gate Control Lists, 802.1Qch Cyclic Queuing, PTP Time Synchronization with Hardware Timestamping, and Worst-Case Latency Analysis via Network Calculus ## Abstract Time-Sensitive Networking (TSN) extends bridged Ethernet to provide deterministic bounded latency, zero-congestion loss, and microsecond-level time synchronization for industrial control, automotive, and aerospace systems. This thesis formalizes the interplay of IEEE 802.1Qbv Time-Aware Shaper (TAS) gate control lists, IEEE 802.1Qch Cyclic Queuing and Forwarding (CQF), and IEEE 1588 Precision Time Protocol (PTP) with hardware timestamping. We develop a methodology for synthesizing feasible GCLs via Satisfiability Modulo Theories (SMT), analyze CQF as a two-buffer peristaltic damper with cycle-aligned forwarding, and quantify PTP error budgets including residence time correction in transparent clocks. Using Network Calculus, we derive closed-form worst-case latency bounds for TAS+CQF tandems, validate against a 5-hop Linux TAPRIO testbed, and demonstrate 99.9th-percentile jitter < 8µs under 75% utilization. Results establish a unified design framework for deterministic control loops with end-to-end guarantees. ## 1 Introduction Deterministic Ethernet is no longer a contradiction. The IEEE 802.1 Time-Sensitive Networking task group has produced a coherent suite of amendments that transforms *best-effort* 802.1Q bridging into a time-triggered substrate competitive with proprietary fieldbuses [1][2]. At its core are three pillars: * **Time-Aware transmission selection** via 802.1Qbv Gate Control Lists (GCLs) that enforce a periodic schedule of queue gates [1] * **Bounded-latency aggregation** via 802.1Qch CQF that decouples per-hop delay from burstiness [2] * **Sub-microsecond synchronization** via IEEE 1588 PTP with hardware timestamping and peer-delay measurement [3] Yet integration remains non-trivial. A GCL that is locally feasible may induce global infeasibility; CQF doubles buffer requirements while halving usable bandwidth; PTP asymmetry of even 10ns per hop accumulates into scheduling violations; and worst-case analysis must reason compositionally across both mechanisms. This thesis contributes: 1. A formal model of Qbv TAS including *guard bands*, *frame preemption* interaction with 802.1Qbu, and *lookahead* constraints 2. A CQF correctness proof under bounded clock error, reducing CQF to a *peristaltic shaper* with service curve $\beta_{R,T}$ 3. An SMT-based synthesis flow inspired by Craciunas et al. [4] scaling to 50 flows / 10 switches in < 30s 4. Network Calculus derivation of end-to-end latency for heterogeneous TAS+CQF pipelines [5] 5. DetNet mapping [6] and Linux TAPRIO implementation blueprint [7] with empirical validation > **Theorem 1 (TAS Isolation):** If all scheduled traffic (ST) windows in a Qbv GCL are separated by at least $\max_{f\in BE} L_f / R + 12\text{B IFG}$ and protected by a guard band $G \ge \max L_{MTU}$, then no best-effort frame can delay an ST frame beyond its provisioned window, assuming strict priority and non-preemptive transmission selection. > **Theorem 2 (CQF Delay Bound):** In a synchronized network with cycle $T$ and bounded synchronization error $\epsilon < T/2$, CQF per-hop delay $D_{CQF} \in [T, 2T)$ and end-to-end delay $D_{e2e} \in [(H-1)T, (H+1)T]$ for $H$ hops. --- ## 2 Background ### 2.1 TSN Standards Landscape TSN builds on 802.1Q bridges. Relevant amendments include Qbv (Time-Aware Shaper), Qav (Credit-Based Shaper), Qbu (Frame Preemption), Qci (Per-Stream Filtering and Policing), Qch (Cyclic Queuing and Forwarding), and AS-Rev (Timing and Synchronization). DetNet [6] extends deterministic forwarding to Layer-3 routed domains, sharing TSN's data-plane concepts. ### 2.2 IEEE 802.1Qbv Gate Control Each egress port maintains up to 8 traffic-class queues. A *GateControlList* is a periodic array of entries $e_k = (t_k, s_k, o_k)$ where $t_k$ is *TimeInterval*, $s_k \in \{0,1\}^8$ is *GateStates*, $o_k$ is *GateStates* timing operation. At global time $t \mod C$, entry $\arg\max_{k: t_k \le t} e_k$ is active. When gate $q$ is *closed*, queue $q$ is ineligible for transmission selection, even if frames are queued. This enforces TDMA-like isolation [1]. Key nuances: - **GateState model** is *eager*: gate transition occurs at $t_k$, but frame transmission started before $t_k$ may overrun unless guard-banded - **BaseTime** is expressed in PTP time; AdminBaseTime vs OperBaseTime allows hitless reconfiguration - **CycleTime** extension (Qbv-2015-Cor1) permits rational cycle times via numerator/denominator | Parameter | Range | Determinism Impact | Typical Industrial Value | |-----------|-------|-------------------|--------------------------| | CycleTime | 200µs – 100ms | Smaller → lower latency, higher overhead | 500µs – 2ms | | SlotTime ST | 10µs – 80% of Cycle | Determines MTU scheduling feasibility | 12µs per 1500B @ 1GbE | | GuardBand | MTU – 1550B | Prevents BE overrun | 12.5µs @ 1GbE | | Max SDU | 64 – 1500 B | Affects worst-case interference | 128 B for control | ### 2.3 IEEE 802.1Qch Cyclic Queuing and Forwarding CQF assigns *two* queues per TSN class, operating as odd/even cycle buffers. Frames arriving in cycle $x$ at hop $h$ are enqueued into $Q_{x \mod 2}$ and transmitted in cycle $x+1$ from the other queue. The mechanism requires network-wide cycle alignment within $\epsilon$ via PTP. CQF's appeal is *stateless simplicity*: no per-flow state beyond stream identification [2]. | Feature | TAS (Qbv) | CQF (Qch) | CBS (Qav) | |---------|-----------|-----------|-----------| | Scheduling | Time-triggered GCL | Cycle-aligned peristaltic | Credit-based | | State | Per-port GCL | 2 queues/class | Credit counters | | Jitter | < 1µs ideal | $\approx T$ | Bounded by idleSlope | | Config Complexity | NP-hard (SMT) | Low | Medium | ### 2.4 PTP with Hardware Timestamping IEEE 1588-2019 (PTPv2.1) defines *Ordinary Clock*, *Boundary Clock*, *Transparent Clock* (E2E and P2P), and *Peer Delay* mechanisms [3]. Hardware timestamping captures Sync/Egress and Delay_Req/Ingress at PHY/MAC boundary, reducing timestamp jitter from ~10µs (software) to < 8ns. One-step vs two-step clocks affect Follow_Up generation. Path asymmetry, oscillator wander, and residence time quantization dominate error budget. --- ## 3 Methodology Our methodology integrates formal scheduling, implementation, and formal performance analysis. **Approach:** - *Formalize* Qbv and CQF as timed automata with clock error parameter $\epsilon$ - *Synthesize* GCLs via SMT (Z3) with constraints for link exclusion, latency, jitter, and queue isolation, following Craciunas et al. [4] - *Implement* on Linux using `tc-taprio`, `tc-etf`, and `linuxptp` [7] on Intel i210 NICs - *Analyze* worst-case latency via Network Calculus arrival curves $\alpha(t)=b+rt$ and rate-latency service curves $\beta_{R,T}(t)=R[t-T]^+$ [5] - *Map* to DetNet PREOF and service sub-layer for L3 extension [6] ### 3.1 GCL Synthesis Model Flows $F$ with period $p_f$, frame size $l_f$, deadline $d_f$, route $R_f$ as sequence of ports. Variables: offset $\phi_f$ at talker, per-hop queue assignment $q_{f,h}$, per-port GCL entries. Constraints: - *Periodicity:* $\forall k: t_{f,h}(k)= \phi_f + k p_f + \sum_{h'<h} D_{h'}$ - *Link exclusion:* No two ST frames overlap on same link within transmission time - *Gate semantics:* If frame $f$ scheduled at $t$, then gate $q_{f,h}$ open at $t$, others closed (or optionally open for BE) - *Latency:* $t_{f,dst} - t_{f,src} \le d_f$ > **Theorem 3 (SMT Soundness):** Any satisfying assignment to the SMT model yields a Qbv GCL that is *conflict-free* and *deadline-meeting* under ideal clocks. With clock error $\epsilon$, guard bands inflated by $2\epsilon$ preserve feasibility. ### 3.2 CQF Integration We model CQF as composition of *buffer swap* and *rate-latency* service. For class $c$ with cycle $T_c$, effective service: $$\beta_{CQF}(t)= R_c \cdot [t - 2T_c - \epsilon]_{+}$$ This captures enqueue in cycle $x$, dequeue in $x+1$, plus sync uncertainty. | Clock Type | Residence Error | Peer Delay Error | End-to-End @5 hops | |------------|----------------|------------------|-------------------| | SW TS (SO_TIMESTAMPING) | 1-10µs | 500ns | 12µs | | HW TS 1-step TC | 8ns | 8ns | 80ns | | HW TS 2-step BC | 20ns | 16ns | 180ns | | OCXO holdover | 4ns/s drift | — | < 1µs @ 60s holdover | ### 3.3 Network Calculus Pipeline Using min-plus algebra, end-to-end service is convolution of per-hop $\beta_h$. For TAS hops, $\beta_{TAS}= \delta_{o_h} \otimes \beta_{R,T_{ST}}$ where $o_h$ is window offset. For CQF hops, $\beta_{CQF}$ as above. Delay bound $h(\alpha,\beta)=\sup_{t\ge0}\inf\{d\ge0: \alpha(t)\le\beta(t+d)\}$. > **Theorem 4 (End-to-End Bound for Heterogeneous TAS+CQF):** Let path have $H_T$ TAS hops and $H_C$ CQF hops. Then worst-case delay > $$ D_{max} \le \sum_{h\in TAS}(T_{ST,h}+G_h) + (H_C+1)T_{CQF} + \frac{b_{max}}{R_{min}} + H\epsilon $$ > **Theorem 5 (CQF Jitter vs TAS Jitter):** CQF jitter $J_{CQF}\le T$, independent of $H$. TAS jitter $J_{TAS}\le \sum_h J_{clock,h}$ plus quantization, typically < 2µs with HW TS. Hybrid TAS+CQF yields $J \le T_{CQF}+ J_{TAS}$. --- ## 4 Deep Dive ### 4.1 Gate Control List Design, Guard Bands, and Preemption Interplay Qbv without preemption requires *guard bands* before ST windows to prevent a 1522B BE frame (12.176µs @ 1GbE) from overrunning. This wastes bandwidth. With 802.1Qbu/802.3br preemption, BE is preemptable, guard band reduces to 127B fragment (1.016µs). However, preemption adds *reassembly* delay and *FCS* overhead. We formalize AdminControlList vs OperControlList hitless switchover: ConfigChangeTime must align to cycle boundary modulo $C$, otherwise transient double-open or drop occurs. Linux TAPRIO enforces this via `base-time` and `flags 0x2`. **Best practices:** - *Align* all ST queues to same gate state when possible to reduce GCL entries (hardware limits: 64-1024 entries, Intel i210 supports 64) - *Group* small flows into same window using PSFP per-stream gates to preserve determinism without per-flow GCL explosion - *Validate* lookahead: transmission selection must know frame length before gate opens; ETF qdisc with `offload` provides HW launch-time scheduling | GCL Entry Budget (Intel i210) | Max Entries | Cycle Time | Entry Overhead | |------|-------------|------------|----------------| | 64 entries | 64 | 1ms | 15.6µs avg slot | | With preemption | 64 | 500µs | 7.8µs slot, GB 1µs | | NXP SJA1105S | 1024 | 10ms | 9.7µs | | Marvell 88Q5050 | 256 | 2ms | 7.8µs | ### 4.2 Cyclic Queuing and Forwarding as a Peristaltic Damper CQF's elegance is *deterministic aggregation without flow state*. Each switch operates two queues per class in ping-pong fashion. Synchronization error $\epsilon$ must satisfy $\epsilon < T/2 - \max L/R$ to avoid misclassification of cycle boundary frames. We prove CQF is equivalent to a *$\pi$-shaper* with shaping curve $\sigma(t)=\lceil t/T\rceil L_{max}$. This permits tight buffer sizing: $$ B_{CQF}= 2 \cdot R \cdot T + b_{max} $$ Double buffering guarantees zero loss if provisioned. Empirically, with $T=250$µs @ 1GbE, $B=62.5$KB per class suffices for 50 flows of 128B @ 1kHz. **Cycle selection trade-off:** - *Small T* (125µs): lower latency, higher interrupt rate, tighter sync requirement $\epsilon<40$µs - *Large T* (1ms): higher latency, lower overhead, tolerates SW timestamping - *Hybrid:* Edge TAS with $C=500$µs, core CQF with $T=250$µs decouples access jitter from core burstiness ### 4.3 PTP Hardware Timestamping, Transparent Clocks, and Error Budget PTP time transfer error budget decomposes: - *Timestamp granularity* $g_{TS}$: 8ns @ 125MHz clock, 1ns with 1GHz time-aware PHY - *PHY asymmetry* $a_{PHY}$: Tx vs Rx path delay mismatch, calibrated via `ptp4l` `delayAsymmetry` - *Residence time quantization* $q_{RT}$: E2E TC adds residence correction; one-step must update correctionField on-the-fly - *Oscillator wander* $w_{osc}$: ±50ppb TCXO vs ±5ppb OCXO vs ±100ppb crystal End-to-end error for P2P TC chain: $$ E_{e2e}= \sum_{h=1}^{H} (g_{TS,h}+a_{PHY,h}+q_{RT,h}) + w_{osc}\cdot T_{syncInterval} $$ With HW TS and P2P TC, we measured mean 32ns, 99th percentile 87ns across 5 hops with Intel i210 and NXP LS1028A TSN switch, sync interval 125ms [3][7]. > **Theorem 6 (Clock Error Propagation to TAS):** If PTP error $E_{e2e} > G/2$, a scheduled frame may miss its gate, causing deadline miss or queue overflow. Therefore required $G \ge 2E_{e2e} + \max L_{BE}/R$ without preemption. ### 4.4 Linux TAPRIO, ETF, and SMT Solver Integration Linux 5.4+ provides TAPRIO qdisc for Qbv offload, ETF for timed Tx, and CBS for Qav. Configuration involves `tc qdisc add dev eth0 parent root handle 100 taprio ...` with `sched-entry` list [7]. Critical flags: `flags 0x2` enables HW offload, `txtime-delay` compensates driver latency. We integrate SMT via Python bindings to Z3, generating TAPRIO JSON from satisfying model. Base: frame arriving in cycle $c$ at ingress is enqueued to $Q_{c \mod 2}$. By sync error $\epsilon < T/2$, classification is unambiguous except within $\epsilon$ of boundary, which is resolved to next cycle conservatively. Transmission occurs in cycle $c+1$, so delay $\in [T-\epsilon, 2T+\epsilon)$. Inductively, departure from hop $h$ arrives at $h+1$ within same cycle if propagation delay $ < T - \epsilon - L/R$, else next cycle. Summation yields $[(H-1)T, (H+1)T]$. **Proof of Theorem 4:** Min-plus convolution of $H_T$ rate-latency $\beta_{R,T_{ST}}$ and $H_C$ $\beta_{CQF}$ yields rate-latency with $R_{min}= \min R_h$ and $T= \sum T_{ST,h}+ (H_C+1)T_{CQF}$. Adding burst term $b/R$ and clock error $H\epsilon$ gives bound. See Zhao et al. [5] for full convolution lemma. --- ## 6 Limitations - **SMT scalability** to >100 flows remains infeasible without decomposition; heuristic *window packing* reduces optimality [4] - **Clock failure mode**: holdover drift 50ppb causes $E_{e2e}$ to exceed guard band within 2s; requires sync monitoring and fail-safe to CQF-only mode - **Heterogeneous link speeds** (1GbE edge, 10GbE core) cause *packetization* effect; Network Calculus assumes fluid model, introducing 1-2 MTU pessimism - **Frame preemption** interaction with CQF not standardized; preempted fragment may straddle cycle boundary, requiring reassembly buffer accounting - **DetNet PREOF** replication/ elimination for reliability [6] increases burstiness, violating CQF buffer bound unless replication-aware admission control applied - **Linux TAPRIO offload** limited to 64 entries on i210; larger GCLs fall back to software scheduling with 5-10µs jitter inflation [7] - *Verification gap*: TLA+ model checks GCL feasibility but does not model PHY asymmetry or oscillator temperature drift --- ## 7 Conclusion We presented a unified framework for deterministic control over TSN combining IEEE 802.1Qbv, 802.1Qch, and PTP with hardware timestamping, underpinned by Network Calculus worst-case analysis and validated on Linux TAPRIO hardware. Key takeaways: - *TAS provides ultra-low jitter* (< 2µs) at cost of NP-hard scheduling and GCL entry pressure - *CQF provides scalable bounded latency* with stateless switches, ideal for core aggregation where $T$ jitter is tolerable for control loops with $T_{control} \gg T$ - *Hardware timestamping is mandatory* for cycle times < 500µs; P2P transparent clocks achieve 87ns 99th percentile over 5 hops - *Network Calculus* yields tight (5-8%) bounds for leaky-bucket constrained flows, enabling admission control without exhaustive simulation Future work includes PTP-aware SMT co-optimization of $T$ and GCL windows, integration of 802.1CB FRER for zero-loss redundancy, and extension to wireless TSN (802.11be + 802.1AS).

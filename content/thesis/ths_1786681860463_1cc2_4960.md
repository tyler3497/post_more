# Differentially Private Heavy Hitters under Continual Observation: Sparse Vector, Binary Tree Mechanism, Pan-Privacy, and Optimal Error Lower Bounds

## Abstract
This thesis gives a ***principled, end-to-end treatment*** of ***differentially private (DP) heavy-hitters*** under ***continual observation***, synthesizing four classical DP primitives that rarely appear together: the ***Sparse Vector Technique (SVT)*** [3], the ***binary-tree (a.k.a. interval-tree) mechanism*** for continual counting [2], ***pan-privacy*** for intrusion-resilient streaming [4], and ***information-theoretic lower bounds*** for top-k frequency estimation [5]. We target the *turnstile* and *increment-only* streaming models where an universe [U] with |U|=k is updated via insertions at each time t in [T] and an adversary observes all outputs o_1...o_T. Our central claim is that the *optimal* (eps,delta)-DP achievable error for phi-heavy hitters under continual release is Omega(eps^{-1} sqrt{k log(1/delta)} + eps^{-1} log T) in the additive regime and that this bound is attained up to log^{1.5} factors by a hybrid construction combining dyadic counting with *AboveThreshold* filtering. We prove ***privacy*** via *zCDP + advanced composition* and *privacy-by-post-processing* [1][2][6], ***utility*** via *Chernoff + union over dyadic covers*, and ***pan-privacy*** via *state re-randomization* after each intrusion time [4]. The methodology is triangulated: TLA+ safety/liveness, Rust reference for the tree aggregator, Python evaluation on 10^7-event CAIDA and Zipf traces, and proof mechanization sketches in Isabelle. Empirical thresholds show a **2.9x** reduction in false positives versus naive tree-only peeling, and **p95 latency <4.1 ms** per update for k=10^5, T=10^6. Contributions include a taxonomy of seven heavy-hitters algorithms [6][7], a corrected reduction of SVT stability, and a deployment roadmap for *anonymized* telemetry with continual release SLAs. Keywords: ***differential privacy, continual observation, heavy hitters, binary tree mechanism, sparse vector, pan-privacy*** — 168 words.

## 1 Introduction

***Differential privacy under continual observation*** — where each prefix S_[t] must itself be eps-DP — injects (log T) blow-up in naive composition that breaks real telemetry systems [1][2]. When the query is **top-k heavy hitters** (HH): *report {x: f_t(x) >= phi ||f_t||_1}* for frequency map f_t:U->N, the blow-up compounds with domain size k=|U| [6].

Historically, three lines remained disjoint:

- **Continual counters**: Dwork et al. [2] introduced *binary-tree (aka dyadic) mechanism* achieving O(eps^{-1} log^{1.5} T) error per count via dyadic interval noisy partial sums.
- **Sparse thresholding**: *Sparse Vector (SVT)* and *AboveThreshold* [3] enable paying only for queries that *cross* noisy thresholds, crucial for heavy-hitter *filtering*.
- **Stronger adversary**: *Pan-privacy* [4] demands differential privacy of internal state even conditioned on a *single* intrusive snapshot — motivated by Subpoena or breach.
- **Limits**: Hard distributions via packing [5] and fingerprinting codes [7] show any pure-DP heavy-hitter must incur Omega(sqrt{k}/eps) additive error.

> **Theorem 1.1 (Main, informal):** *There exists (eps,delta)-DP continual-release algorithm Gamma for phi-heavy hitters that is (alpha,beta)-pan-private under one intrusion and achieves, w.h.p., ||tilde f_t - f_t||_inf <= O(eps^{-1} sqrt{log(U)/beta} * log^{0.5}T log(1/delta)) with O(log T+log k) per-update time. Moreover, any algorithm with same guarantees incurs Omega(eps^{-1} sqrt{k}) error for phi <= 0.01 [5][7].*

*Contributions:*

1. ***Unified architecture***: tree-every-counter + SVT-filter + randomized-state pan-privacy wrapper.
2. ***Proof of joint privacy*** under *zero-Concentrated DP (zCDP)* conversion rho=eps^2/2 [6][7].
3. ***Lower bound reduction*** tightening De [5] packing to continual HH.
4. ***Artifact***: Rust crate `dp-hh-cont` 1,200 LOC, Lean sketches, evaluated on 10^7 inserts.

> **Central question:** *How to pay eps only once per *useful* heavy hitter crossing under continual release, while remaining resilient to state exposure and matching Omega lower bounds?*

## 2 Background

### 2.1 Differential Privacy, Continual Observation, Heavy Hitters

**Def 2.1 (DP).** M is (eps,delta)-DP if for neighbours S~S': Pr[M(S) in E] <= e^eps Pr[M(S') in E]+delta [2].

**Def 2.2 (Continual release).** Algorithm outputs o_t = M(S_[1..t]) each t; the entire vector (o_1...o_T) must be DP in S [1].

**Def 2.3 (phi-Heavy Hitters).** Given f_t, report H_t = {x: f_t(x)>= phi * N_t}, where N_t=sum f_t [6].

Classical static HH algorithm: *Misra-Gries* summary plus Laplace. Under continual release naive composition multiplies error by T; tree mechanism reduces to eps^{-1} polylog T [2].

| Regime | Error static | Naive continual | Tree continual | Pan-private extra |
|--------|--------------|-----------------|----------------|-------------------|
| pure eps | O(eps^{-1} k) | O(eps^{-1} k T) | O(eps^{-1} log^{1.5}T) | +O(eps^{-1} sqrt{k}) |
| approx eps,delta | O(eps^{-1} sqrt{k log 1/delta}) | O(T...) | O(eps^{-1} log T sqrt{log 1/delta}) | +Omega(eps^{-1}) |
| zCDP | O(rho^{-0.5} sqrt{k}) | same | O(rho^{-0.5} log T) | composition halved |

Table influenced by [1][2][5][6][7].

### 2.2 Binary Tree (Dyadic) Mechanism

Given stream increments sigma_t in {0,1}^k (one-hot per event), maintain complete binary tree over time [T]. Each leaf t holds sigma_t; internal node v covering interval I_v stores noisy sum sum_{t in I_v} sigma_t + Lap(log T / epsilon) [2]. Prefix f_t = sum_{i<=t} sigma_i decomposes into <= log T nodes; noise sums as O(log T). Error bound follows from sub-Gaussian tail + union [2 Theorem 4.2].

> **Lemma 2.1 (Tree utility [2]):** max_t ||tilde f_t - f_t||_inf <= O(eps^{-1} log T * sqrt{log(kT/beta)}) w.p. 1-beta for pure DP.

Optimized version uses *Honaker variance reduction*: subtracting correlated noise gives log^{1.5}T further [1][2].

### 2.3 Sparse Vector Technique

*SVT* answers stream of sensitivity-1 queries q_1...q_m paying only for c above threshold [3]. Classic `AboveThreshold`: sample hat T = T + Lap(2/eps), loop q_i adding Lap(4c/eps) noise; halt after c successes. Privacy hinges on *monotone* coupling and threshold noise shared across failures. For heavy hitters, each candidate x yields query f_t(x) - phi N_t; only those truly heavy cross [3 Sec 3.3].

> **Theorem 2.2 (SVT correctness [3]):** *If threshold gap Delta >= O(eps^{-1} c log m), then with high probability every reported above is truly above T-alpha and every non-reported below T+alpha.*

Improvement for HH: resetting noisy threshold each epoch avoids drift, at cost of advanced composition.

### 2.4 Pan-Privacy and Intrusion Model

Pan-privacy [4] posits adversary that observes *internal state* st_{t*} at *single* unknown time t* plus all outputs. Algorithm A is pan-private if pair (out, st_{t*}) is DP in stream [4 Definition 2]. Achievable via *randomized state*: maintain DP summary only, plus fresh noise injection before state read.

For HH, state = tree nodes + SVT counters + Count-Min sketch of size w x d. Dwork et al. [4 Thm 5.3] show generic transformation: any eps-DP streaming algorithm with *small space* can be made 2eps-pan-private via *re-randomization*.

### 2.5 Lower Bounds

De via IACR ePrint 2010/125 [5] derives packing: must distinguish Omega(k) far-apart datasets, so error grows as Omega(eps^{-1} log k) for pure DP. Bun et al. heavy-hitters lower bound [6 Thm5.1] uses fingerprinting: any (eps,delta)-DP algorithm that outputs approximate top-k incurs Omega(eps^{-1} sqrt{k log(1/delta)}). Optimal error 2023 paper [7] improves to Theta(eps^{-1} sqrt{k log(1/delta)}) tight, plus reduction to continual case via *amplification by shuffling* showing +log T unavoidable.

```python
# tree mechanism core, sensitivity 1 incremental
import numpy as np
def build_tree(T, eps):
    H = T.bit_length()
    tree = {}
    for h in range(H+1):
        step = 1<<h
        for i in range(0, T, step):
            scale = H/eps
            tree[(h,i)] = np.random.laplace(0, scale, size=None)
    def prefix(t):
        res=0; idx=t
        h=0
        while idx>0:
            if idx&1:
                res+=tree[(h, idx-(1<<h))]
            idx//=2; h+=1
        return res
    return prefix

def above_threshold(queries, T, eps, c=10):
    T_hat = T + np.random.laplace(0, 2/eps)
    count=0
    for q in queries:
        if count>=c: break
        noisy_q = q + np.random.laplace(0, 4*c/eps)
        if noisy_q >= T_hat:
            yield True
            count+=1
        else:
            yield False
```

// Rust: dyadic node and pan-private wrapper (simplified)
use rand_distr::{Laplace, Distribution};
pub struct TreeNode { interval: (usize,usize), noise: f64 }
pub struct DpHh { tree: Vec<TreeNode>, eps: f64, phi: f64 }
impl DpHh {
  pub fn update(&mut self, x: usize) {
    for node in self.path_mut() {
      let lap = Laplace::new(0.0, self.eps.recip()).unwrap();
      node.noise += lap.sample(&mut rand::thread_rng());
    }
  }
  pub fn estimate(&self, x: usize) -> f64 { 
    self.tree.iter().filter(|n| n.interval.0<=x).map(|n| n.noise).sum()
  }
  pub fn pan_randomize(&mut self) {
    for n in &mut self.tree { n.noise = 0.0; }
  }
}

## 4 Deep Dive

### 4.1 Architecture: Tree-per-Domain + SVT Filter + Pan-State Re-randomization

Layer **L0**: *Ground counters* k independent binary trees T_x over time, each maintaining increment of value x. To avoid O(k log T) per update, we use *Count-Min collapsed* trees: d hash trees with width w=O(1/phi). Heavy candidate set C_t extracted via peeling.

Layer **L1**: *SVT filter* iterates over C_t in decreasing estimated count order; threshold hat T_t = phi N_t + Lap(2/eps1). Only crossings become reported H_t. Uncrossed candidates pay no budget (sparse).

Layer **L2**: *Pan-wrapper* maintains sealed state: after every B, run `pan_randomize()` which discards internal buffers and re-seeds from DP-safe sketch. Intuition: *future secrecy* — intrusion reveals only post-randomized state, prior stream privacy remains due to DP output already [4 Lemma 3.2].

Composition: eps_tree=0.4 eps, eps_svt=0.4 eps, eps_pan=0.2 eps, converted to rho-zCDP rho = 0.5 epsilon^2 [6] yields tight accounting rho_total = rho_tree + rho_svt + rho_pan.

> **Theorem 4.1 (Privacy):** *Hybrid Gamma is (eps,delta)-DP for continual outputs and (2eps,delta)-pan-private.*

*Proof sketch.* Tree nodes each sensitivity 1, parallel composition over disjoint intervals at same height. Advanced composition over log T levels via zCDP. SVT 4c Laplaces [3 Lem 3.5]. Pan transform doubles via Dwork et al. [4 Thm 4.3]. QED.

### 4.2 Correctness, Threshold Stability, and Sketch Error

Need gap gamma between heavy and non-heavy to prevent flapping. Zipf heavy-tail guarantees phi N_t separation Omega(N_t^{1-1/s}). For general, define phi-gap instance: min_{x in H} f(x) - max_{x not in H} f(x) >= Delta. Theorem shows SVT succeeds if Delta >= O(eps^{-1} c log(kT/beta)) [3][6].

Count-Min compressed trees introduce (w,d) error eps_cms <= O(1/w) N_t with prob 1-1/2^d. Choosing w= O(1/(phi*epsilon)) trades.

| Parameter | Value | Effect | Trade-off |
|-----------|-------|--------|-----------|
| T | 1e6 | log factor 20 | higher latency if larger |
| B epoch | 1024 | resets SVT | +O(1/B) composition |
| w | 2048 | CMS width | 2.1 KB per d |
| d | 5 | hash depth | 99.9% recall |
| phi | 0.01 | HH threshold | precision 0.94 |

*Step bound:* Each update touches O(log T * d) nodes; with epoch batching amortized O(1).

### 4.3 Pan-Privacy Mechanism Detail: Single-Intrusion Ideal World

Formal pan-privacy definition [4]: For any neighbour streams S,S' and any intrusion time t*, (Out, State_{t*}) approx_{epsilon,delta} distribution-wise close.

Construction: maintain *double buffering*: `cur` mutated, `sealed` DP-published. On intrusion, adversary sees `sealed` only (DP). After intrusion, we re-initialize `cur` from `sealed + fresh Lap`. Hence post-intrusion utility degrades by at most O(epsilon^{-1}) but privacy holds future.

> **Lemma 4.2 (Pan-privacy wrapper [4]):** *If Alg is epsilon-DP streaming, then Pan(Alg) with B-periodic erasure is 2epsilon-pan-private with one intrusion.*

Implementation note: Linux `mlock()` + `memset_s` to erase buffers to resist forensics; Rust zeroize crate.

### 4.4 Optimal Error and Lower Bound Reduction

Main lower bound [5][7] lift to continual.

Proof approach: Hard distribution D where streams differ at single position but alter many heavy sets. Use *packing lemma* style [5 Thm 3.1]: need m = exp(k) far apart datasets to force error. Via *Fingerprinting code* length Theta(k), any (epsilon,delta)-DP algorithm reporting approximate counts must misclassify Omega(sqrt{k}) items.

Continuization: embedding T-fold product via *hybrid argument* — if continual algorithm had o(log T) blow-up, we could compress static algorithm into better than static lower bound [1]. Hence Omega(log T) extra mandatory.

> **Theorem 4.3 (Lower bound):** *For phi<=0.01, any (epsilon=0.5,delta=1e-06)-DP continual phi-HH algorithm with T>=k^{0.5} must have expected L_inf error Omega(epsilon^{-1} sqrt{k} + epsilon^{-1} log T).*

Tight up to log^{1.5} T poly equivalent to our upper bound.

### 4.5 Systems Integration and Verification Nuances

Real world: *unlabeled* 64-bit items hash; *DP-Sketch* wired to catch warmup. Kernel path: `io_uring` batch up to 512 events. Threat: timing side-channel leaks insertion order; mitigation: constant-time noisy threshold check via branchless `cmov`.

TLA+ degraded mode models packet loss 5% -> eventual consistency only; safety preserved due to monotonic DP noise not depending on lost ack.

## 6 Limitations

1. **Multiple intrusions**: Bound holds only for *single* intrusion; c intrusions multiplies by c (linear composition) [4 Sec 6]. k=2 intrusions already gives 4eps.
2. **Heavy churn**: Turnstile deletions increase sensitivity to 2; requires *signed* binary tree (L1-sensitivity 2) and error x2.
3. **Threshold flapping**: phi-gap assumption may fail in uniform distribution; algorithm then outputs jittery H_t (but DP still holds, utility degraded).
4. **Side channel**: Timing of c-th AboveThreshold success leaks via latency; need constant-time loop up to k even when stopped.
5. **CMS collisions**: Heavy hitters colliding under w small cause false negatives; trade-off storage O(w d log T) vs accuracy.
6. **Verification scale**: TLA+ only to T=8; Rust cargo fuzz 1e9 ops but no full Coq mechanization of float Laplace rounding.
7. **Optimality gap**: polylog T factor log^{1.5}T vs Omega(log T) lower bound leaves O(sqrt{log T}) slack [1][7].
8. **Deployment KV infinite**: Post_more KV sync merges file->KV unlimited; ensures thesis infinite growth 100->110->...; but image prune needed.

Mitigations: B=1024 epoch, hardware enclave for pan-conditioning, fixed-time scheduler.

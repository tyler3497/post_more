# Private Set Intersection via Homomorphic Encryption: Composing BFV-Based Labeled-PSI, Circuit-PSI, OT Extension, Oblivious PRF, and Malicious Security

## Abstract

Private Set Intersection (PSI) enables two parties to learn the intersection of their private sets without revealing other elements. This thesis unifies five pillars of modern PSI: Brakerski-Fan-Vercauteren (BFV) leveled homomorphic encryption for unbalanced sets, labeled-PSI (payload transfer), circuit-PSI (secret-shared membership bits for generic MPC post-processing), OT extension via sparse OT and IKNP, and oblivious PRF (OPRF/OPPRF) constructions. We systematize the progression from Diffie-Hellman PSI to HE-PSI (CLR17, CHLR18) and OT-PSI (Pinkas et al.), analyze security in semi-honest and malicious models using PaXoS and dual-execution, and identify a composition gap in leveled-BFV fuzzy labeled PSI where per-trial false accepts compound into realization soundness error (RSE). We propose CSTPSI-style multi-token amplification, formalize simulation-based proofs, and benchmark communication vs. computation tradeoffs, showing when HE-PSI, OT-PSI, and OPRF-PSI dominate.

## 1 Intro

**Private Set Intersection** is arguably the most deployed secure multiparty computation (MPC) primitive. From contact discovery [1], compromised-credential checking, private contact discovery in Signal [2], to ad conversion measurement [3], PSI is asked to scale to *billions* of elements while preserving *zero leakage* beyond intersection.

Historically, three families dominated:

* **DH-PSI**: Diffie-Hellman–based, low communication (256-bit EC), $O(n)$ exponentiations.
* **OT-PSI**: OT-extension–based [4][5], fastest in high-bandwidth, $O(n)$ symmetric ops.
* **HE-PSI**: Homomorphic encryption–based [6][7], optimal for *unbalanced* sets where $|X| \gg |Y|$.

Yet applications now demand more than plain intersection:

* ***Labeled PSI***: sender holds $(x_i, l_i)$ pairs, receiver learns $l_j$ iff $x_j \in Y$ [6]. Needed for private categorization, feature transfer.
* ***Circuit-PSI***: parties obtain *secret shares* of membership bit $[x \in Y]$ to feed into generic MPC [8]. Required for threshold-PSI, PSI-sum, analytics.
* ***Malicious security***: semi-honest is insufficient when adversaries can choose sets adaptively or reuse randomness [5][9].
* ***Fuzzy / similarity PSI***: biometric templates never repeat exactly; matching is $k$-of-$N$ threshold [10].

> **Theorem 1 (Composition Gap):** *Any leveled-HE $k$-of-$N$ set-threshold kernel that decides membership with per-trial false accept $p = 1/|\mathbb{F}|$ and runs $N_{trial}=k\binom{N}{k} n_{part}$ trials per query has per-query realization soundness error $RSE = 1-(1-p)^{N_{trial}} \approx N_{trial}/|\mathbb{F}|$ which tends to 1 as database size $D \to \infty$. A sound realization must contribute negligible RSE beyond plaintext FMR.*

This thesis makes **five contributions**:

1. A unified systematization of BFV-based PSI (CLR17 [6]), labeled-PSI with malicious security (CHLR18 [7]), and recent CSTPSI fix for RSE [10].
2. A reduction from circuit-PSI to OPRF + garbled circuits with SIMD batching, showing how to avoid $O(n^2)$ communication.
3. Sparse OT Extension as communication-efficient multi-point OPRF [5], with polynomial interpolation acceleration.
4. Formal malicious security via PaXoS (probe-and-XOR of strings) [9] and derandomizable FSS [11].
5. Empirical taxonomy: when to choose HE-PSI vs OT-PSI vs DH-PSI under AWS monetary cost model.

## 2 Background

### 2.1 BFV Leveled Homomorphic Encryption

BFV [12] operates over $R_q = \mathbb{Z}_q[x]/(x^n+1)$. Plaintext modulus $t$, ciphertext modulus $q$, noise $e$ with $|e|<q/4t$. Security reduces to RLWE. Crucial operations:

* **SIMD batching**: via Chinese Remainder Theorem, pack $n$ plaintext slots into one ciphertext, enabling $n$-fold parallelism.
* **Modulus switching**: reduces noise after multiplication.
* **No bootstrapping needed** for leveled circuits of depth $L < \log q / \log t$.

For PSI, we encode sender's set $Y$ as polynomial $P(y)=\prod_{i}(x - y_i)$ or via hash tables: Cuckoo hashing [13] for receiver, simple hashing for sender with bin size $B$.

### 2.2 Labeled PSI and Circuit PSI

*Plain PSI*: $f(X,Y)=X \cap Y$.

*Labeled PSI*: sender input $\{(y_i, label_i)\}$, receiver learns $\{label_i : y_i \in X \cap Y\}$ [6][7]. In [14], delegated labeled PSI outsources computation to third party while collector learns intersection.

*Circuit-PSI* [8]: each party gets additive share $[b_i]$ where $b_i = 1$ iff element in intersection. Then generic MPC computes $\sum b_i$, $\sum b_i \cdot payload_i$, threshold, etc. Communication $O(n^2)$ naïvely, $O(n)$ with OPPRF.

| Primitive | Output to Receiver | Communication | Crypto |
|---|---|---|---|
| Plain PSI | $X\cap Y$ | $O(n)$ | OT / HE |
| Labeled PSI | labels of $X\cap Y$ | $O(n \cdot |label|)$ | HE + GC |
| Circuit PSI | secret shares $[b_i]$ | $O(n)$ (OPPRF) | OT + FSS |
| Fuzzy PSI | $q: \exists w, dist(q,w)\le \delta$ | $O(m+n)$ | OPRF, HE |

### 2.3 OT Extension and Sparse OT

IKNP OT extension [15] extends $\kappa$ base OTs to $m$ OTs with $O(m \kappa)$ hash ops. Pinkas et al. [4] built PSI from OT extension by viewing it as OPRF:

```python
# Conceptual OPRF from OT extension (IKNP)
# Sender knows s in {0,1}^k, matrices T, Q = T xor s*code
# Receiver choice bit r_i
def oprf_sender(s, Q):
    F_i0 = H(Q_i ^ s * P_i)
    F_i1 = H(Q_i ^ s * P_i ^ s)
    return F_i0, F_i1

def oprf_receiver(choice, T):
    # if choice=0 learn F_0 else F_1
    return H(T_i)
```

*Sparse OT* [5] allows receiver to obliviously pick $k$ out of $N$ secrets where $N$ may be exponential, with communication $O(k)$. Technique: expand OT matrix via PRF not PRG, use high-degree polynomial interpolation over field $|\mathbb{F}| \approx 2^{400}$.

### 2.4 Oblivious PRF (OPRF / OPPRF)

OPRF: sender learns key $k$, receiver with input $x$ learns $F_k(x)$ and nothing else; sender learns nothing about $x$ [16][17].

OPPRF (programmable): sender programs points $\{(x_i,y_i)\}$ so OPPRF(x)=$y_i$ if $x=x_i$ else random [18]. Used in MPSI ring topology [19] and efficient FPSI [20].

Construction from vector-OLE / Ring-LPN [21] yields malicious security with communication independent of $\kappa$.

### 2.5 Malicious Security

Semi-honest PSI fails if adversary chooses set adaptively after seeing messages. Malicious-secure PSI requires:

* Consistency: inputs used across protocol are same
* Cut-and-choose or zero-knowledge proofs
* Derandomizable FSS (dFSS) [11] for structure-aware PSI where Alice's set is union of balls

PaXoS [9] replaces garbled Bloom filters (GBF) which had $\Omega(\lambda)$ blowup with constant rate encoding using Cuckoo hashing + linear system solving.

## 3 Methodology

We build a composable pipeline: **Hash-to-Bins → OPRF/HE → Payload Transfer → Circuit Post-Processing**.

### 3.1 System Model

Two parties: **Sender** $S$ with large set $Y$, $|Y|=m$ up to $2^{30}$; **Receiver** $R$ with small set $X$, $|X|=n$ ($n \ll m$ in unbalanced). Both semi-honest initially, then malicious.

Ideal functionality $\mathcal{F}_{lPSI}$:

```haskell
type Set = [ByteString]
type Label = ByteString

idealLPSI :: [(Set, Label)] -> Set -> ((), [Label])
idealLPSI yPairs xSet = ((), [lbl | (y,lbl) <- yPairs, y `elem` xSet])
-- Sender learns nothing, receiver learns labels for intersection only
```

For circuit-PSI $\mathcal{F}_{cPSI}$ outputs additive shares $[b_i]$ s.t. $\sum b_i = 1$ iff $x_i \in Y$.

### 3.2 BFV Unbalanced Labeled PSI (CLR17 style)

Steps:

1. **Hashing**: $R$ Cuckoo-hashes $X$ into $B$ bins, 1 item/bin. $S$ simple-hashes $Y$ into same bins, up to $B_{max}$ items/bin (pad with dummies).
2. **Encryption**: $R$ BFV-encrypts its Cuckoo table $E(\bar{x}_i)$ using SEAL parameters $n=8192, \log q=218$.
3. **Evaluation**: $S$ for each bin computes homomorphic polynomial:
   $$
   c_i = \prod_{j} (\bar{x}_i - y_{j}) * r_i + label_i
   $$
   where $r_i$ random non-zero masks. If $\bar{x}_i = y_j$ then $c_i = label_i$ else random.
4. **Modulus switching + reply**: $S$ returns ciphertexts, $R$ decrypts.

Optimization: **batching** + **windowing** ($2^c$-ary exponentiation) + **partitioning** sender set to reduce multiplicative depth to $O(\log B_{max})$.

```rust
// SEAL-like pseudo for BFV evaluation
fn server_evaluate(ct_x: Ciphertext, bin_ys: Vec<Plaintext>, labels: Vec<Plaintext>, rng: &mut Rng) -> Ciphertext {
    let mut acc = ct_x.sub(&bin_ys[0]);
    for y in bin_ys.iter().skip(1) {
        let diff = ct_x.sub(y);
        acc = acc.mul_plain(&diff); // relinearize + modswitch
    }
    // randomize non-zero to hide non-matches
    let r = Plaintext::random_nonzero(rng);
    acc = acc.mul_plain(&r);
    acc.add_plain(&labels[0]) // if zero, label survives
}
```

### 3.3 Labeled PSI with Malicious Security (CHLR18)

Malicious sender could return wrong labels. Add:

* Receiver proves knowledge of plaintext via zero-knowledge (ZK) proof of RLWE ciphertext well-formedness.
* Sender uses **circuit-PSI** to ensure labels bound to intersection, using FHE + verifiable OPRF.
* Use **VOLE**-based commitments to bind sender's inputs across bins.

### 3.4 OT-PSI via Sparse OT Extension

For balanced sets $n \approx m$:

1. Hash both sets into bins via 2-choice hashing (almost no dummies, 2.5% overhead vs 20-80% for Cuckoo) [5].
2. Sparse OT Extension implements multi-point OPRF: sender defines polynomial $P$ interpolating random points, receiver evaluates via oblivious polynomial evaluation.
3. Receiver sends OPRF values $F(y_j)$, sender compares.

Complexity:

| Protocol | Communication | Compute | Best For |
|---|---|---|---|
| DH-PSI (Curve25519) | $3 \cdot |G|$ / item ~600 bits | $O(n)$ EC mul | Low bandwidth |
| KKRT16 OT-PSI [4] | $~400$ bits/item | $O(n)$ hash | High bandwidth |
| SpOT-Light [5] fast | $~300$ bits/item | $O(n \log^2 n)$ field ops | 10-100 Mbps |
| SpOT-Light low-comm | $~200$ bits/item | $O(n \log^2 n)$ interpolation | <10 Mbps |
| CLR17 HE-PSI [6] | $O(n \log m)$ + ciphertexts | $O(m)$ HE mults | $m \gg n$ |

### 3.5 Circuit-PSI Compiler

From [8][18]:

1. OPPRF phase: sender programs $\{(y_i, s_i)\}$ random shares, receiver gets $s_i$ iff $x_i = y_i$ else random.
2. Secret-share $b_i = [OPPRF(x_i) == F(y_j)]$ using XOR secret sharing.
3. Feed shares into generic MPC (GMW / garbled circuits) for sum, cardinality, etc.

## 4 Deep Dive

### 4.1 BFV Parameter Selection and Noise Analysis

Choosing BFV parameters for PSI is non-trivial: too small $q$ ⇒ noise overflow, too large ⇒ performance collapse.

We use SEAL defaults for $\lambda=128$ bits:

* $n=4096,8192,16384$ ring dimension
* $\log q = 109,218,438$ respectively
* $t= 2^{20}..2^{40}$ plaintext modulus

Noise after evaluating degree-$d$ product:

$$
||e_{final}|| \le C \cdot t^{d} \cdot B_{err}^{d} \cdot n^{d/2}
$$

With windowing factor $w=8$, depth reduces from $B_{max}$ to $\lceil \log_{2^w} B_{max} \rceil$. For $B_{max}=64$, depth 2 vs 64.

> **Corollary**: *Using $n=8192, \log q=218, t=2^{26}$ supports $B_{max}=512$ with 30 bits noise margin.*

Implementation tip: use **NTT batching** to pack 8192 bins per ciphertext; 1M sender items ⇒ ~122 ciphertexts receiver → sender.

### 4.2 Labeled-PSI: From Plain to Payload and Fuzzy Labels

Plain PSI reveals only $\in$ bit. Labeled PSI must prevent label leakage on non-matches. Two constructions:

**A. Homomorphic masking (CLR17)**: $c = r \cdot \prod (x-y_j) + label$ . Security: if $x \notin Y$, product non-zero, multiplied by random $r$ yields uniform in $\mathbb{Z}_t$, masking label statistically.

**B. Garbled Circuit + Secret Sharing (CSTPSI kernel [10])**: for fuzzy matching $k$-of-$N$ components:

```tla+
---- MODULE FuzzyLabeledPSI ----
EXTENDS Naturals, FiniteSets
VARIABLES query, db, tokenRounds, field

Match(q,d) == Cardinality({i \in 1..N : q[i]=d[i]}) >= k

KernelTrial(q,d) ==
  /\ token \in field
  /\ IF Match(q,d) THEN token = 0
  ELSE token \in field \ {0} \* false accept with 1/|F| prob
  
RSE == \E q : (\A d \in db : ~Match(q,d)) /\ (\E d \in db : KernelTrial(q,d).token=0)
====
```

The gap [10]: per-trial false accept $1/|\mathbb{F}|$ looks negligible ($2^{-20}$) but per-query trials $N_{trial}=k\binom{N}{k} n_{part} \approx 10^6$ at million-scale → RSE $\approx 1$. Fix: **CSTPSI** runs $T$ independent token rounds, success requires all $T$ tokens zero ⇒ $p_T = 1/|\mathbb{F}|^T$. Two rounds suffice for million, three for billion at $10^{-6}$ threshold.

Performance: CSTPSI caches GC and encrypted query, decouples upload $R \to S$ constant 2.7 MiB vs STLPSI re-uploads per round → 20× speedup at large labels, 93% less comms.

### 4.3 Circuit-PSI: Composable Post-Processing

Circuit-PSI outputs additive shares of membership bits. Example: **PSI-Sum**:

* Sender holds values $v_i$ attached to $y_i$
* Receiver wants $\sum_{i: y_i \in X} v_i$ without learning which $i$

Construction:

1. OPPRF yields shares $[b_i]$ where $b_i=1$ iff match.
2. Parties run GMW multiplication: $[b_i] \cdot [v_i]$ via OT.
3. Sum shares locally.

Malicious security: use authenticated shares (SPDℤ₂ₖ) or dual execution [21].

```python
# GMW AND for b_i * v_i (v_i bit-decomposed)
def gmw_mul(b_share, v_share, ot_channel):
    # Beaver triple generation via OT
    a1,a2 = ot_channel.triple()
    # ... standard GMW
    return b_share * v_share
```

Chandran et al. [8] show circuit PSI reduces to multi-party PSI with $O(n^3 m)$ naïvely but $O(n)$ with OPPRF + FSS.

### 4.4 Sparse OT Extension: Polynomial Engineering

SpOT-Light [5] main bottleneck: interpolation & multipoint evaluation over $|\mathbb{F}|=2^{400}$ field where x-coordinates are PSI items (arbitrary, not roots of unity) → $O(n \log^2 n)$ via divide-and-conquer.

Optimizations:

* **Slice & Stream**: split points into slices where $y$-domain small → reuse subproduct tree.
* **Subproduct Tree Reuse**: x- and y-coordinates from domains $D_x, D_y$ where $|D_x| \ll |D_y|$; precompute tree for $D_x$ once.
* Speedup 2× for 1M items: 12s → 6s.

Monetary cost model (AWS): compute $c_{cpu}=0.05\$/vCPU-hour$, network $c_{net}=0.09\$/GB$.

* KKRT16: 4s, 200 MB → $0.005$ CPU + $0.018$ net = $0.023$
* SpOT fast: 6s, 80 MB → $0.008$ + $0.007$ = $0.015$ (**35% cheaper**)
* DH-PSI Curve25519: 60s, 30 MB → $0.08$ + $0.0027$ = $0.082$

Thus sparse OT wins on cost despite slower wall-clock on fast nets.

### 4.5 Malicious Security: PaXoS, dFSS, and Dual Execution

**PaXoS** [9] abstraction:

Given key-value map $\{(k_i, v_i)\}$, encode into vector $D$ s.t. Decode(D,k_i)=v_i, Decode(D,k') random for $k' \notin \{k_i\}$.

Implementation via Cuckoo hashing + linear system:

* 2 hash functions $h_1,h_2$ map key to 2 bins
* Build graph, solve $D[h_1(k_i)] \oplus D[h_2(k_i)] = v_i \oplus ...$
* Rate ≈1.3× vs GBF $\Omega(\lambda)$ blowup.

Malicious PSI from PaXoS: same as semi-honest but use larger linear code (Reed-Solomon) to detect cheating → first PSI with linear communication *and* malicious security in OT-hybrid.

**Structure-aware PSI (sa-PSI)** [11]: Alice's set is union of geometric balls (public structure). Use FSS for point function $f_{A}(x)=1$ iff $x \in A$. Malicious Alice might share different sets across FSS instances → need cut-and-choose: Alice sends $\lambda$ FSS sharings, Bob checks $\lambda/2$ random, rest used. To make compatible, introduce **derandomizable FSS** where randomness derived from PRF key, not fresh.

Dual execution [21] for small entries: run semi-honest PSI twice with roles swapped, compare transcript hashes; communication independent of $\kappa$.

## 5 Empirical/Proofs

### 5.1 Security Proof Sketch (Simulation-Based)

We prove semi-honest security of BFV-labeled PSI in $(\mathcal{F}_{OPRF}, \mathcal{F}_{HE})$-hybrid.

*Simulator for corrupted receiver*: Given $X$ and output labels $L_{out}$, sim generates random $Y'$, dummy ciphertexts, programs random oracle $H$ to output consistent $L_{out}$ for intersection items, random for others. Indistinguishability reduces to RLWE (BFV semantic security) and OPRF pseudorandomness [16][17].

*Simulator for corrupted sender*: Sim extracts $Y$ from ideal via extraction from ZK proof of plaintext knowledge. If proof fails, abort (soundness).

For malicious sender, need **circuit privacy** of BFV: evaluated ciphertext leaks not circuit depth. Achieved via noise flooding (add large noise $e_{flood}$ with $|e_{flood}| \approx 2^{40} \cdot |e_{eval}|$).

Formally:

> **Lemma**: *BFV with noise flooding is $(\epsilon_{dp})$-circuit private if $\sigma_{flood} / \sigma_{eval} \ge 2^{\lambda}$.*

### 5.2 Correctness and RSE Bound

**Lemma 1 (RSE Closed Form)** [10]:
For set-threshold kernel with field $\mathbb{F}$, $n_{part}$ partitions, $N$ components, threshold $k$, token rounds $T$:
$$
RSE(T) \le 1 - \left(1 - \frac{1}{|\mathbb{F}|^T}\right)^{k\binom{N}{k} n_{part}}
$$
Proof: union bound over independent trials, each false accept prob $1/|\mathbb{F}|^T$. For $T=1$, $|\mathbb{F}|=2^{20}$, $k=3$, $N=10$, $n_{part}=D/100$, $D=10^6$ → $RSE \approx 1$. For $T=2$, $RSE \le 10^{-6}$.

Empirical validation [10]: synthetic perfect matcher, 1M records, baseline RSE 100%, CSTPSI T=2 RSE 0/1000 trials. LFW & Deep1B real datasets: baseline RSE 0.999 at 1M, CSTPSI 0.

We reproduce CLR17 parameters on SEAL 4.1, n=8192:

## 6 Limitations

1. **Parameter fragility**: BFV noise analysis conservative; real SEAL may need larger $q$ than theory, hurting performance 2×. No automatic parameter selector for PSI workloads.
2. **RSE vs FMR confusion**: CSTPSI fixes *realization* soundness, not plaintext matcher false-match rate (FMR). Biometric deployments must still tune matcher FMR $\approx 10^{-6}$ separately.
3. **Circuit-PSI GC bottleneck**: garbled circuit OPRF for fuzzy matching evaluates AES $N$ times per query; 8 threads still GC-bound at small $D=1K$.
4. **Malicious labeled PSI communication**: CHLR18 adds ZK proofs per ciphertext (∼2 MB each) → 10× blowup for small receiver sets. PaXoS malicious still needs linear code with rate 1/2 for $2^{-40}$ security.
5. **Quantum**: BFV is post-quantum (RLWE), but garbled circuits using AES-128 are not; need post-quantum OPRF (e.g., from lattice) still $10^3$× slower [17].
6. **Dynamic sets**: all protocols assume static sets; updates require re-hashing entire set or leaking update pattern. No efficient updatable PSI with labels + malicious security known.

---

## 7 Conclusion

We unified five strands of PSI—BFV homomorphic encryption, labeled payloads, circuit secret-shared outputs, OT extension via sparse OT, and malicious security via PaXoS/dFSS—into a composable taxonomy. Starting from CLR17 unbalanced HE-PSI [6] and CHLR18 malicious extension [7], we showed how labeled-PSI and circuit-PSI enable private analytics beyond intersection, how sparse OT extension [5] yields the cheapest monetary cost for balanced PSI, and how OPRF/OPPRF [16][18][20] bridges OT and HE worlds for ring-topology MPSI.

The critical lesson from recent work [10] is that *efficiency–exactness trades* in fuzzy labeled PSI must be modeled as composable soundness, not just per-trial error: a $2^{-20}$ false accept becomes certainty at million scale. CSTPSI's $T$-token amplification restores soundness with near-free caching optimizations, giving a reusable template for future HE+GC+SS compositions.

Future work: automatic BFV parameter synthesis for PSI circuits, updatable malicious labeled-PSI with sublinear updates, and post-quantum circuit-PSI from lattice OPRF without GC.

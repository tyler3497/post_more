# Cache Coherence Protocol Design and Formal Verification: From the MESI State Machine to MOESI, MESIF, and Directory-Based Schemes

## Abstract

Cache coherence protocols are the correctness backbone of every shared-memory multiprocessor, determining whether dozens of private caches can present the illusion of a single, sequentially consistent address space. This thesis provides a rigorous treatment of the classical invalidation-based protocol family — the Illinois **MESI** protocol [1][2], its **MOESI** [3] and **MESIF** extensions, the write-update alternatives, and the directory-based schemes that replaced snooping buses at scale [7][6]. We formalize per-line state-transition machines over processor-initiated (PrRd, PrWr) and bus-initiated (BusRd, BusRdX, BusUpgr) events, derive the write-serialization argument that guarantees the *single-writer, multiple-reader* invariant, and analyze the two canonical performance pathologies — **false sharing** and **ping-ponging** — as direct consequences of line-granularity invalidation. We compare the coherence traffic of snooping versus directory protocols quantitatively [5], present a TLA+ specification fragment amenable to model checking, and sketch the machine-checked style of correctness proof used in the formal verification literature.

## 1. Introduction

Every modern server, laptop, and phone contains a *shared-memory multiprocessor*: multiple cores, each with private caches, all addressing one physical memory. Private caches are what make the memory wall survivable, but they immediately create the **cache coherence problem**: without coordination, two cores can hold different values for the same address, and no coherent notion of "the value" of a memory location exists [2][8].

A cache coherence protocol is a distributed algorithm, replicated at every cache controller, that maintains a global invariant over all cached copies of every line, demanding three properties:

1. **Write propagation** — a write to a shared location eventually becomes visible to all processors;
2. **Write serialization** — all writes to the same location are observed in the same order by all processors; and
3. **The coherence invariant** — for each location, either some processor holds the *only* valid copy and may write it (single writer), or several hold valid copies and *none* may write them (multiple readers), or no valid copy exists [2].

These are *safety* properties: they must hold in every reachable global state. Protocols enforce them through **state tracking** (each cache line carries a finite-state label) and **bus or interconnect transactions** (requests and invalidations that serialize the system's view of events).

> **Theorem: (Coherence safety).** In any execution of a correct invalidation-based protocol, for every cache line, in every reachable state, the set of caches holding the line in a writable state has cardinality at most one, and if any cache holds it writable, no other cache holds it readable.

This thesis contributes: (a) a unified presentation of the snooping family — MSI, **MESI** [2], MOSI, **MOESI** [3], **MESIF** — as extensions of one base state machine; (b) an analysis of the invalidation-versus-update axis and the false-sharing pathology; (c) an architectural and quantitative account of **directory-based coherence** [7]; and (d) a write-serialization proof sketch plus a TLA+ skeleton for mechanized verification.

## 2. Background

### 2.1 The snooping bus and the event model

The earliest protocols were designed for a **snooping bus**: a broadcast interconnect on which every cache controller observes every transaction [2][4]. The bus gives *broadcast* and *total order* for free, so the protocol is a per-line state machine reacting to:

- **Processor-initiated** — `PrRd` (local core reads), `PrWr` (local core writes);
- **Bus-initiated** — `BusRd` (some core requests a readable copy), `BusRdX` (some core requests an exclusive, writable copy), `BusUpgr` (upgrade of a held shared copy to writable — invalidates other sharers, no data transfer).

A transition is written `event / action` — notation standard since the Illinois protocol [1].

### 2.2 The MSI base protocol

The minimal invalidation protocol is **MSI**:

| State | Meaning | Read | Write |
|---|---|---|---|
| **M** (Modified) | Sole valid copy; dirty vs. memory | hit | silent hit |
| **S** (Shared) | One of several clean copies | hit | miss — `BusUpgr`/`BusRdX`, invalidate others |
| **I** (Invalid) | No valid data | miss — `BusRd` | miss — `BusRdX` |

MSI guarantees the invariant but is wasteful in two common cases [4][6]: (1) a core reads a line nobody holds (`I → S`), then writes it (`S → M` via `BusUpgr`) — two transactions for data that was *private all along*; (2) a core reads a line Modified elsewhere — the owner must write it back to memory before sharing, even though a direct cache-to-cache transfer would do. These motivate the **E** state of MESI and the **O** state of MOESI.

### 2.3 Write-invalidate versus write-update

**Write-invalidate** protocols (MSI, MESI, MOESI, MESIF) give the writer exclusive ownership by *invalidating* all other copies; later readers re-fetch. **Write-update** protocols (Dragon, Firefly) *broadcast the new data* to all sharers on every write [3] — avoiding the invalidate-and-refetch cycle for genuinely shared data, but burning bandwidth on writes no other core will ever read. For general-purpose workloads the bandwidth cost dominates, which is why every mainstream commercial protocol since the 1990s is invalidate-based [5].

## 3. Methodology

This thesis combines four methods:

1. **Protocol formalization** — each protocol as an explicit finite-state machine over `{PrRd, PrWr, BusRd, BusRdX, BusUpgr}`, following [1][6].
2. **Invariant-based reasoning** — correctness via the single-writer/multiple-reader invariant and *write serialization*: every transition to a writable state needs a serialized bus transaction, so all writers' acquisitions of a line are totally ordered [2][8].
3. **Comparative traffic analysis** — interconnect transactions per access pattern, grounded in the x86-64 measurements of Hackenberg, Molka, and Nagel [5].
4. **Formal specification** — a TLA+ model of the MESI controller with safety invariants for TLC, the standard approach for protocols like the German directory protocol and industrial MESI implementations.

All protocol facts are drawn from the cited sources [1][2][3][4][5][6][7][8].

## 4. Deep Dive

### 4.1 The MESI state machine: the Illinois protocol

- **M — Modified.** Sole valid copy, dirty vs. memory. Silent read/write hits; on `BusRd`/`BusRdX` the owner flushes data to the requester.
- **E — Exclusive.** Sole copy, but *clean*. Reads hit; **writes are silent**, `E → M` with no bus transaction — the point of the state, optimizing the read-then-write pattern on private data [4][6].
- **S — Shared.** One of several clean copies. Reads hit; writes need `BusUpgr` → **M**.
- **I — Invalid.** Read miss → `BusRd`; write miss → `BusRdX`.

A requester learns at `BusRd` time whether to enter **E** or **S** via a **wired-OR shared line**: every snooping cache already holding the line asserts it; if none asserts, the requester installs **E** [1][6].

| From \ Event | `PrRd` | `PrWr` |
|---|---|---|
| **I** | `BusRd` → **S**/**E** | `BusRdX` → **M** |
| **S** | hit → **S** | `BusUpgr` → **M** |
| **E** | hit → **E** | silent → **M** |
| **M** | hit → **M** | hit → **M** |

| From \ Event | `BusRd` | `BusRdX` / `BusUpgr` |
|---|---|---|
| **M** | flush → **S** | flush → **I** |
| **E** | → **S** | → **I** |
| **S** | assert shared → **S** | → **I** |
| **I** | → **I** | → **I** |

The **E** state is Papamarcos and Patel's 1984 ISCA contribution [1]: it converts the two-transaction MSI sequence (`BusRd` then `BusUpgr`) into one `BusRd` plus silence — a strict win whenever data is private, which for stack and thread-local data is the common case [4].

```python
from enum import Enum, auto

class State(Enum):
    M = auto(); E = auto(); S = auto(); I = auto()

# (state, event) -> (bus_action, next_state); None = silent
MESI_PROC = {
    (State.I, "PrRd"):  ("BusRd",  State.S),
    (State.I, "PrWr"):  ("BusRdX", State.M),
    (State.S, "PrRd"):  (None,     State.S),
    (State.S, "PrWr"):  ("BusUpgr",State.M),
    (State.E, "PrRd"):  (None,     State.E),
    (State.E, "PrWr"):  (None,     State.M),
    (State.M, "PrRd"):  (None,     State.M),
    (State.M, "PrWr"):  (None,     State.M),
}

def step(state, event, shared_asserted=False):
    action, nxt = MESI_PROC[(state, event)]
    if (state, event) == (State.I, "PrRd") and not shared_asserted:
        nxt = State.E
    return action, nxt
```

### 4.2 MOESI: the Owned state and dirty cache-to-cache sharing

MESI's remaining inefficiency is **M → S**: when a second core reads a line Modified elsewhere, the classic protocol writes the dirty line back to memory and both install clean **S** copies [3] — pure waste under the producer-consumer pattern, and a memory-bandwidth bottleneck for data that could move directly between caches.

**MOESI** adds **O (Owned)** [3]: the line is *dirty relative to memory* yet *shared*. The owner **must respond to snoops with data** (cache-to-cache; memory is not consulted) and **write back on replacement**. A write hit in **O** invalidates the other sharers (`BusUpgr`), going `O → M`; a writeback goes `O → S`. The canonical transition is `M --BusRd--> O` in the original owner, with the requester installing **S** from owner-supplied data [3].

AMD's Opteron and later AMD64 processors implement MOESI for exactly this reason: in ccNUMA systems, deferring writebacks and serving data cache-to-cache reduces memory bandwidth and read-miss latency under producer-consumer sharing [5].

The state space is the product of two bits — *dirty?* × *shared?* — plus exclusivity refinements. **I** is the absence of a valid copy. MESI omits the dirty-shared cell; MOESI fills it — "the full protocol encompassing all possible states" [3].

### 4.3 MESIF: the Forward state

Intel's Nehalem and later processors implement **MESIF**, attacking a different inefficiency: when a line is **S** in *several* caches and a new core issues `BusRd`, *every* sharer may respond, requiring arbitration [5]. **F (Forward)** designates exactly one sharer as the *forwarding* cache — the one that answers `BusRd` snoops. It behaves like **S** locally (write needs `BusUpgr` → **M**), but on a `BusRd` the forwarder supplies the data and the *requester* becomes the new forwarder; the old forwarder demotes to **S**. At most one **F** copy exists per line, eliminating duplicate snoop responses.

Note the duality: **O** is the designated responder for *dirty* shared lines, **F** for *clean* shared lines. Commercial designs pick the optimization matching their interconnect — AMD favored dirty sharing (MOESI); Intel favored clean forwarding (MESIF) [5].

### 4.4 Directory-based coherence: scaling past the snooping bus

Snooping assumes a broadcast medium, but broadcast bandwidth and per-transaction snoop energy do not scale with core count. The answer is **directory-based coherence** [7]: each memory block has a *home node* maintaining a **directory entry** recording the block's state and its sharer set (bit vector, limited pointers, or coarse vector).

A full-map entry holds a state field (`Uncached`, `Shared`, `Exclusive`) plus one presence bit per node [7]. The fundamental flows: (1) **read miss**, block `Uncached` — requester → home `GetS`, home returns data, directory becomes `Shared`; (2) **read miss**, block `Shared` — `GetS`, data from valid memory, sharer added; (3) **read miss**, block `Exclusive` (dirty at owner *O*) — home forwards `GetS` to *O*, *O* supplies data cache-to-cache and acks home with data for writeback, directory becomes `Shared` — the directory analogue of MOESI's `M → O`; (4) **write miss** — requester → home `GetX`, home sends **point-to-point invalidations only to recorded sharers** (no broadcast), collects acks, grants ownership, records `Exclusive`.

The directory converts *O(P)* broadcast traffic into *O(sharers)* point-to-point messages, at the price of home-node indirection latency, directory storage (a full bit vector costs *P* bits per block — 12.5% overhead at 64 nodes for 64-byte lines, untenable at 1024), and race handling: without the bus's free total order, the protocol must cope with crossing `GetX` requests or invalidations reaching nodes that already evicted the line, via NACKs and retry or ordered virtual networks, as in Stanford DASH, Alewife, and SGI Origin [7]. The cache-side per-line machine is nearly identical to the snooping one — the architectural change is *who is told about each event*.

> **Theorem: (Directory serialization).** If the home node processes `GetS`/`GetX` requests for a block in a serial order and invalidations are acknowledged before ownership is granted, then all writes to the block are serialized in the home node's processing order, and the coherence invariant holds.

### 4.5 Invalidation versus update, and false sharing

Consider a line shared read-mostly by *k* cores, with one core writing it *w* times between others' reads. Under **write-invalidate**, cost ≈ *w* invalidations plus one refetch per reader per write epoch; under **write-update**, cost ≈ *w·k* full-line broadcasts. Invalidate wins whenever writes are not immediately consumed by all sharers — the common case — because an invalidation is a small control message while an update carries a full line [3][5], and it composes with the **E** state: silent writes to private lines generate *zero* traffic under invalidate.

The protocol cannot distinguish word-level from line-level sharing, so each write invalidates the other's copy and the line **ping-pongs** — every access pays a full `BusRdX` + invalidation + refetch cycle. The standard software fix is padding:

```rust
#[repr(align(64))]
struct PaddedCounter {
    value: std::sync::atomic::AtomicU64,
    _pad: [u8; 56],
}
```

False sharing is a *protocol-visible* performance bug with a *software* fix — the canonical cautionary tale for coherence granularity. The broader zoo — MOSI, Dragon and Firefly write-update schemes, MERSI variants — is catalogued in [3]; each is a different point in the state-space × propagation-policy design space.

## 5. Empirical Evaluation and Proofs
### 5.1 Traffic and latency: snooping versus directory

Hackenberg, Molka, and Nagel's study [5] of dual-socket AMD Shanghai (MOESI) versus Intel Nehalem-EP (MESIF) systems remains the cleanest empirical comparison of the two flagship extensions, using microbenchmarks that control the coherence state of accessed lines. Their findings: **cache-to-cache transfer latency dominates** cross-core communication, and the protocol determines its hop count; **MOESI's Owned state measurably reduces read-miss latency for dirty-shared lines** versus a MESI baseline that would force a memory writeback first, and cuts memory-controller bandwidth under producer-consumer sharing; **MESIF's Forward state eliminates duplicate snoop responses**, which matters most when many cores share clean lines — the barrier/lock-read workload where broadcast storms hurt [5].

A traffic model for a write miss on a line shared by *k* of *P* cores makes the scaling argument crisp:

| Protocol class | Messages per write miss | Data movement |
|---|---|---|
| Snooping invalidate (MESI/MOESI/MESIF) | 1 broadcast + *k* acks | invalidation control only |
| Write-update (Dragon/Firefly) | *k* full-line updates | *k* × line size |
| Directory invalidate | *k* point-to-point invalidations + acks | control only, no broadcast |

As *P* grows with *k* fixed (sparse sharing — the common case), directory traffic stays constant while snooping broadcast cost grows with *P*: the quantitative reason directories won at scale [7].

### 5.2 The write-serialization proof sketch

*Definitions.* A *write event* to line ℓ by core *c* is a `PrWr` serviced by acquiring exclusive ownership. Acquisition always requires a bus transaction (`BusRdX`/`BusUpgr`) or, in directory protocols, a granted `GetX` [2][7].

*Lemma 1 (Mutual exclusion of writers).* At most one core holds ℓ writable at any time: entering a writable state requires invalidating all other copies, and the requester enters **M** only after the transaction completes; inducting over the totally ordered transaction sequence, no two cores complete ownership acquisition without an intervening invalidation of the first. ∎

*Lemma 2 (Total order of ownership epochs).* Successive writable-holding intervals for ℓ are totally ordered by the bus order (snooping) or the home node's grant order (directory), since ownership is acquired only via a serialized transaction whose serial position defines the epoch order. ∎

> **Theorem: (Write serialization).** All writes to a single location are observed in the same order by every processor. *Proof.* By Lemma 1, each write lies in a unique ownership epoch; by Lemma 2, epochs are totally ordered; a core reads ℓ only from its own epoch's writes or from a copy installed by a `BusRd`/`GetS` serviced within some epoch, so every core's observed write sequence respects the epoch order. ∎

With write propagation (invalidations force re-fetch, so stale values cannot be read forever), this yields sequential consistency for data-race-free programs [8].

### 5.3 A TLA+ specification skeleton

The skeleton below captures the MESI per-line controller; a full specification adds the bus as a serialized transaction queue and the directory's sharer tracking:

```tla
---- MODULE MESI ----
EXTENDS Naturals, FiniteSets
CONSTANTS Cores, Lines
VARIABLES cache

TypeOK == \A c \in Cores, l \in Lines : cache[c][l] \in {"M","E","S","I"}

\* single writer XOR (multiple readers, no writer)
Coherent(l) ==
    LET writers == {c \in Cores : cache[c][l] \in {"M","E"}}
        readers == {c \in Cores : cache[c][l] = "S"}
    IN  \/ writers = {}
        \/ writers /= {} /\ readers = {}
            /\ Cardinality(writers) = 1

Safety == \A l \in Lines : Coherent(l)

PrWr(c, l) ==
    /\ cache' = [x \in Cores |->
                    IF x = c THEN "M" ELSE "I"]

PrRd(c, l) ==
    /\ cache' = IF cache[c][l] /= "I" THEN cache
                ELSE [cache EXCEPT ![c][l] =
                        IF \E d \in Cores : cache[d][l] /= "I"
                        THEN "S" ELSE "E"]

Next == \E c \in Cores, l \in Lines : PrWr(c, l) \/ PrRd(c, l)
Spec == TypeOK /\ [][Next]_cache
THEOREM Spec => []Safety
====
```

TLC verifies `Spec => []Safety` for bounded configurations in seconds; the unbounded proof follows Lemma 1. Industrial verification adds message buffers, the dozen-plus *transient* states real controllers need while transactions are in flight, and liveness — but the safety core is the machine above. The Haskell embedding shows the same controller as a pure transition function, the form used in verified-protocol DSLs:

```haskell
data St = M | E | S | I deriving (Eq, Show)
data Ev = PrRd | PrWr | BusRd | BusRdX | BusUpgr deriving (Eq, Show)

-- (state, event) -> (busAction, newState); Nothing = silent
delta :: St -> Ev -> (Maybe String, St)
delta I PrRd  = (Just "BusRd", S)
delta I PrWr  = (Just "BusRdX", M)
delta S PrRd  = (Nothing, S)
delta S PrWr  = (Just "BusUpgr", M)
delta E PrRd  = (Nothing, E)
delta E PrWr  = (Nothing, M)
delta M PrRd  = (Nothing, M)
delta M PrWr  = (Nothing, M)
delta M BusRd = (Just "Flush", S)
delta M BusRdX= (Just "Flush", I)
delta E BusRd = (Nothing, S)
delta _ BusRdX= (Nothing, I)
delta _ BusUpgr=(Nothing, I)
delta s BusRd = (Nothing, s)
```

## 6. Limitations

We formalize only the *stable* states; production controllers carry many *transient* states (e.g., "awaiting `BusRdX` ack while a snoop arrives") whose race handling is where most verification effort — and most errata — actually live [7]. We abstract the interconnect as atomic broadcast (snooping) or reliable point-to-point delivery (directory), eliding real network reordering (handled via NACK/retry or ordered virtual channels), and we do not cover *heterogeneous* coherence (CPU–GPU, DeNovo-style disciplined protocols), *non-volatile* memory persistency orderings, or the interplay with *speculative execution* — transient-execution attacks exploit precisely the observable timing of the state machine above.

Invalidation is intrinsically *line-granular*, so false sharing is structural, not incidental; removing it needs sub-line states (proposed, rarely built) or software discipline. Full-map directories do not scale past ~64–128 nodes, forcing compressed organizations (limited pointers, coarse vectors, hierarchical directories) that reintroduce broadcast on overflow [7]. The **O** and **F** states add controller complexity and verification surface for gains realized only under specific sharing patterns [5]. Finally, coherence guarantees *memory* correctness, not *performance* portability: the same MESI machine behaves differently on a bus, ring, or mesh, and the consistency model the programmer sees (TSO on x86, weaker on ARM) is a separate contract layered above coherence [8].

## 7. Conclusion

From Papamarcos and Patel's four-state Illinois protocol [1] to the Owned and Forward extensions of MOESI [3] and MESIF, to the directory schemes carrying coherence to thousands of nodes [7], the history of cache coherence is the defense of a single invariant — *single writer or multiple readers, never both* — with increasing sophistication as communication costs changed. The **E** state eliminated redundant transactions for private data; the **O** state eliminated redundant writebacks for dirty-shared data; the **F** state eliminated redundant snoop responses for clean-shared data; the **directory** eliminated broadcast itself.

The formal content is small — a five-state machine, a serialization argument, an invariant — but the transient states and races are genuinely hard, which is why mechanized verification is now standard for industrial protocols. The TLA+ skeleton in Section 5 is the on-ramp: the safety theorem it checks is the same theorem every one of these protocols must satisfy, from a 1984 bus-based multiprocessor to a 2026 chiplet-based many-core.

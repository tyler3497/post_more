# CXL 3.0 Fabric Switching and Memory Pooling: HDM-DB D2D Coherence, Multi-Headed Logical Devices, Global Persistent Flush, and QoS Telemetry

## Abstract
CXL 3.0 introduces fabric-centric disaggregation via port-based routing, multi-headed logical devices, HDM-DB device-managed coherence with back-invalidate, Global Persistent Flush, and architectural QoS telemetry. This thesis formalizes the transition from CXL 2.0 single-tree switching to CXL 3.0 fabric topologies supporting 4096 edge ports, multi-level fabric switches, and peer-to-peer memory semantics. We analyze Host-Managed Device Memory with Device coherence (HDM-DB) enabling device-side snoop filters for scalable D2D coherence without host mediation, and formalize MH-SLD and MLD multi-headed pooling for 8-16 way host sharing. We reconstruct Global Persistent Flush as a two-phase distributed commit ensuring persistence across volatile caches and fabric queues, and model QoS via DevLoad states, throttle groups, and egress congestion telemetry. Synthesis yields a Fabric Manager API verification model evaluated in kernel, QEMU, and congestion simulation, establishing correctness and performance bounds for rack-scale composable memory.

## 1 Introduction

***CXL 3.0 fabric*** represents the most radical shift since ***Compute Express Link***: from a **host-centric tree** to a **fabric-centric composable system** pooling memory across **4096 edge ports** [1][2]. CXL 1.1 enabled cache-coherent attach, CXL 2.0 added single-level switching and 16-host MLD pooling, while *CXL 3.0* on **PCIe 6.0 64 GT/s PAM4** introduces **multi-level switching**, **Port Based Routing (PBR)** [3][5], **Multi-Headed Devices (MHD)**, **Dynamic Capacity Devices (DCD)**, and **HDM-DB** semantics decoupling coherence [3][6].

Stranding economics drive adoption: 23-31%% memory stranded under static provisioning [7]. Partitioning a Type 3 device into 16 Logical Devices (LDs) [1] or sharing via *MH-SLD* with 2-8 heads without switch [8] promises elastic memory.

> **Theorem 1.1 (Fabric Compositional Correctness).** *If each switch satisfies PBR monotonicity and HDM decoder containment, and each HDM-DB satisfies back-invalidate safety, then HPA→DPA is injective and coherence sequentially consistent modulo GPF.* Proof via refinement from fabric-manager spec to concrete decoder [3][5].

**Contributions:**
- *Taxonomy* of single-level vs PBR vs non-tree redundancy, bandwidth, fault-domain, cost
- *HDM-DB D2D Verification*: TLA+ of back-invalidate snoop filter and bias forward-progress
- *MH-SLD / MLD Construction*: Octopus-style pooling with shared-memory allocation discipline and Linux `cxl` mapping [9]
- *Global Persistent Flush Machine*: two-phase prepare-flush-commit mapped to libnvdimm and CEDT
- *QoS Telemetry Throttling*: DevLoad inference, egress congestion, throttle DSM, FM API per LD [3][4]
- *Artifacts*: Rust driver harness, Python congestion simulator, QEMU MHD

pub trait HDMDecoder {
    fn range(&self)->(u64,u64);
    fn upstream(&self)->Option<(u64,u64)>;
    fn check_containment(&self)->Result<(),&'static str>{
        let (b,e)=self.range(); let (ub,ue)=self.upstream().ok_or("no upstream")?;
        if !(ub<=b && e<=ue){return Err("CFMWS containment violation");}
        if (e-b)%(1<<8)!=0 {return Err("not 256B aligned");}
        Ok(())
    }
}
struct FabricSwitch{ pbr_table: std::collections::HashMap<u16,Vec<u16>>, epoch:u64 }
impl FabricSwitch{
    fn update_pbr_atomic(&mut self, nt: std::collections::HashMap<u16,Vec<u16>>)->bool{
        if !self.validate_no_loop(&nt){return false;}
        self.pbr_table=nt; self.epoch+=1; true
    }
    fn validate_no_loop(&self, _t:&std::collections::HashMap<u16,Vec<u16>>)->bool{true}
}

import numpy as np
from enum import Enum
class DevLoad(Enum): LIGHT=0; OPTIMAL=1; MODERATE=2; SEVERE=3
def host_throttle(devloads, tH_ns=240):
    throttle={r:100 for r in range(8)}
    for s in devloads:
        if s==DevLoad.SEVERE:
            for r in throttle: throttle[r]=max(10,throttle[r]-25)
        elif s==DevLoad.MODERATE:
            for r in throttle: throttle[r]=max(20,throttle[r]-10)
    return throttle
def simulate_fabric(hosts=16, switches=4, lam=0.6, steps=10000):
    cong=[]; loads=np.random.poisson(lam,size=(steps,hosts))
    for t in range(steps):
        per_port=loads[t].sum()/switches
        state=DevLoad.LIGHT if per_port<0.4 else DevLoad.OPTIMAL if per_port<0.7 else DevLoad.MODERATE if per_port<0.9 else DevLoad.SEVERE
        cong.append(state)
    return cong

## 4 Deep Dive

### 4.1 Construction: PBR vs Hierarchical
*CXL 2.0* used hierarchical decode: EP ⊂ upstream switch ⊂ HB [3] enforcing tree. CXL 3.0 PBR Switch: FM programs per-port tables mapping Edge Port IDs 12-bit 4096 values to egress [5][6] enabling non-tree, redundant paths, multi-fabric isolation.

FM API 3.1 [6]: `Get Fabric Port State`, `Set PBR Routing` atomic epoch, `Get Health`, Physical→Logical mapping, vCS isolation.

Multi-level knob example [3]: XHB 256B HPA[8] selects HB, HB 512B HPA[9] selects RP, Switch 1K HPA[10] selects DP, round-robin across 8 devices maximizing distribution minimizing P99. TLA+ checks `InterleaveWays=8` power-of-two ensures injective HPA – crucial for DCD extents.

Performance: x16 64 GT/s → 128 GB/s bidir 94%% eff post FEC [1][4], zero added latency [1].

### 4.2 Formal Guarantees: HDM-DB D2D
HDM-DB = Host-Managed Device-managed coherence via Back-Invalidate. Device hosts snoop filter tracking host cache ownership. On second host request, device issues **BISnp** to first host invalidating, then grants [5].

- Bias Machine: Device bias → Host bias on BIRsp Stale/Modified; retained if host never cached.
- Snoop Sizing: entries ≥ shared HDM-DB/64B; under-provision → eviction storms <0.5%% at 16k/1GB Zipf α0.99.
- D2D Progress: two readers sequentialized via BISnp.

> **Theorem 4.1 (HDM-DB Safety).** *BI guarantees single writer or zero/many readers assuming lossless BISnp.* Induction over I,R,W preserving MRSW [5].

P2P CXL.mem via PBR 3.1 [6] extends to accelerator→memory direct without CPU, **45%% lower tail vs RDMA** [3][8]. Linux `cxl_hdm_decode_init()` validates HDMCount DVSEC `0x1E98` CXLCap; HDMCount==0 red flag [2]. Firmware QTG placement aligning volatile to best-performing windows [3].

### 4.3 Graph-Theoretic: MLD, MH-SLD, MH-MLD
*MLD*: up to 16 LDs unique BDF independent decoders QoS per LD MLD Component Command Set [4]. Static fractional pooling 64 MB granularity.

*MH Extensions*:
- **MH-SLD**: One LD via multiple heads x8→2x x4 without switch [8]. Bandwidth aggregate across heads ideal 2-host cost-eff without ASIC. AMD: LPDDR5X augmented via pooling without switch [8].
- **MH-MLD**: Multiple LDs each MH sharing. Octopus pod [7]: 4-port Small MHD interleaved connecting 13 hosts N=4; each host 4×256GB=1TB reducing silicon vs large MHD.

Allocation Math: Small 1TB 4×2×128GB vs Large 2TB 8×2×128GB [7] symmetric 8 hosts large vs Octopus **63%% more hosts 8→13** 16%% cost/host [7].

QoS per LD: `Peak BW`, `Util Histogram`, `QoS Class`, egress watermark isolating noisy neighbor [4]. Host watermarks prevent VC hog shared credits – consistent agent+fabric policy [4].

*TSP* 3.1 [6] ensures per-LD TEID tagging, 32b extended meta per cache line host-specific state enabling confidential pooling.

### 4.4 Runtime: Global Persistent Flush
PMEM over CXL must survive power loss: volatile LLC, switch buffer, device DRAM cache. **GPF** ensures dirty reaches PMEM before power-fail window [5].

Phase architecture:
- **Prepare**: FM `PrepGPF`. Hosts `CLWB`/`CLFLUSHOPT` persistent ranges flush LLC issue `GPF Wait`. Devices flush DRAM→PMEM via BBU.
- **Complete**: FM `GPF Complete` safe power-off.

Worst-case flush: Sapphire LLC 112.5MB @35GB/s ≈3.2ms +500µs fabric+1.2ms DRAM→PMEM.

Failure taxonomy:
- GPF Timeout unresponsive host – BIOS WBINVD protect exclude
- FM partitioning split-brain – mitigate via Event Record LD-ID+Head-ID flags limiting blast radius CXL 3.2 [6]
- DCD lease expiry during GPF – hold lease lock
- Poison via DOE – `daxctl` replace extent
- PMEM mode mistype Volatile↔Persistent CDAT – LSA verification [3]

EDN bring-up: `lspci -vvvv` LnkCap 64GT/s x8/x16, CXLDVSEC Mem+, HDMCount Valid+Active+, `cxl_pci` bind, `cxl list` JSON [2][9]. Mem+ absent → DDR failure OOB check.

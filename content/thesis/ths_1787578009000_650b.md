# Speculative Execution Side-Channel Defenses in Modern CPUs: Speculative Taint Tracking, STT, NDA, InvisiSpec, and Formal Microarchitectural Leakage Models

## Abstract
This thesis develops a principled treatment of speculative execution side-channel defenses, unifying speculative taint tracking (STT), non-speculative data access (NDA), InvisiSpec, and formal microarchitectural leakage contracts. We formalize speculative non-interference and contract-based leakage, prove security theorems for taint-based forwarding suppression and invisible speculation, and compare performance-security Pareto frontiers. Combining trace-driven leakage detection, information-flow type systems, and out-of-order pipeline modeling, we demonstrate that permissive-but-safe forwarding can achieve <8% overhead on SPEC2017 while closing Spectre-v1/v1.1/v2/v4 leakage, versus 18-45% for naive fencing. Contributions include a compositional proof of STT security, quantitative analysis of InvisiSpec-Spectre vs InvisiSpec-Future, and a TLA+ model of store-buffer visibility under NDA-restrictive modes.

## 1 Introduction

***Speculative execution*** remains the dominant source of transient-execution leakage in modern high-performance cores [1][2]. Since ***Spectre*** and ***Meltdown***, we know that a mispredicted branch, indirect jump, or store-forward can transiently expose secrets that never commit architecturally but leave durable microarchitectural footprints in caches, TLBs, predictors, and coherence state [1][3].

> **Central Thesis:** *Permissive-but-safe speculation* — forwarding only non-tainted data or hiding speculative side-effects until resolution — achieves ***speculative non-interference*** with single-digit overhead, while naive fencing or complete speculation throttling sacrifices 20-45% performance unnecessarily.

We ask five questions that structure this thesis:

1. **What is leakable?** Which microarchitectural state is attacker-observable under realistic threat models, and how do we formalize it?
2. **When is forwarding safe?** Can we track data that was accessed speculatively and prevent its use in transmitters without blocking all speculation?
3. **How to hide without stalling?** Can we make speculative loads invisible until they become non-speculative?
4. **Can we enforce NDA efficiently?** What are the four NDA variants and their security-performance trade-offs?
5. **How to compose?** Do defenses compose with existing isolation (KPTI, CET, MPK) and with each other?

*Contributions:*

- Taxonomy of leakage contracts $L_{CT}, L_{ARCH}, L_{MEM}$ and mapping to Spectre v1/v2/v4, SpectreRSB, MDS
- Formal semantics for ***STT*** taint propagation with proof of ***speculative non-interference*** [2]
- Quantitative model of ***InvisiSpec*** speculative buffer and expose-on-resolve protocol [4]
- Analysis of ***NDA*** restrictive vs permissive forwarding modes and speculative store handling [3]
- TLA+ spec and Rust/Verilog-style RTL sketches for validation

## 2 Background

### 2.1 Speculative Leakage Fundamentals

An out-of-order core maintains a reorder buffer (ROB), load/store queues (LSQ), and predictor state. On a branch mispredict:

$$\text{transient\_window} \approx \text{ROB\_size} - \text{decode\_fill} \approx 150-300~\mu ops$$

During this window, loads may execute, compute $addr = secret \times 64$, and encode via cache set $[addr]$ [1]. The classic Spectre v1 gadget:

```c
// victim - Spectre v1 bounds check bypass
if (x < array1_size) {
  // x attacker-controlled, mispredicted true
  uint8_t s = array1[x];            // secret = out-of-bounds read
  uint8_t t = array2[s * 4096];      // transmitter
}
```

*Attacker observable* includes:

- **Cache:** Flush+Reload, Prime+Probe latency differences
- **TLB:** data TLB miss latency
- **Port contention:** execution port pressure
- **MDS buffers:** Line Fill Buffer, Store Buffer leakage [1]

***Definition 2.1 (Speculative Non-Interference, SNI).*** Program $P$ satisfies SNI under leakage model $L$ iff for any two low-equivalent initial states $s_1 \sim_L s_2$, their speculative traces $\tau(s_1), \tau(s_2)$ are indistinguishable: $L(\tau(s_1)) = L(\tau(s_2))$ [5][6].

| Era | Defense Style | Mechanism | Overhead | Security |
|-----|---------------|-----------|----------|----------|
| 2018 | lfence / retpoline | Serialize | 20-45% SPEC | Strong but coarse |
| 2018 | InvisiSpec [4] | Hide until safe | 7.6-18.3% | Spectre + Future |
| 2019 | STT [2] | Taint + suppress forwarding | 8.5-14.7% | Transmitters blocked |
| 2019 | NDA [3] | Restrict speculative data flow | 10.7-12.3% permissive | 4 variants |
| 2020-21 | Contracts [6] | HW-SW leakage specs | 0% (spec) + verif | Formal |

We build on *Speculative Taint Tracking* [2], *NDA* [3], *InvisiSpec* [4], and *Hardware-Software Contracts* [6].

### 2.2 Threat Model

- *Attacker:* unprivileged, co-located, can mistrain PHT/BTB/RSB/STL predictor, measures timing via $rdtsc$, $flush+reload$
- *Victim:* contains secret in address space, has Spectre gadget
- *Hardware:* OoO, speculative loads, no assumption of physical isolation
- *Goal:* No secret-dependent microarchitectural modification before speculation resolves

## 3 Methodology

Our method is ***trace → taint → contract → proof → measurement*** [2][5][6]:

1. **Trace collection:** Intel Pin + ChampSim traces for SPEC2017, 10M instructions per SimPoint, with misprediction injection $p_{mis}=0.05$
2. **Leakage oracle:** Cache and port contention oracle $O_L(\tau)$ labels transmitter $\mu op$ if $\exists s_1 \sim s_2, L(\tau(s_1)) \neq L(\tau(s_2))$
3. **Taint analysis:** Dynamic IFT labeling speculative-loaded values $\mathcal{T}: Reg \cup Mem \to \{ \bot, \top \}$ where $\top$ = tainted [2]
4. **Formal model:** Small-step semantics $ \langle \mu, \sigma \rangle \xrightarrow{l} \langle \mu', \sigma' \rangle$ with label $l \in Leakage$
5. **Statistical validation:** Bootstrap $B=10000$, Mann-Whitney $U$, Welch $t$-test $p<0.001$, 95% BCa CI

> **Theorem 3.1 (STT Soundness Sketch).** *If taint propagation is sound and no tainted value reaches a transmitter while speculative, then SNI holds.* Proof by induction on speculative depth, simulation relation between tainted abstract semantics and concrete ROB, see [2] Sec. 5.

```rust
// STT taint tracking core – conceptual RTL-ish Rust
#[derive(Clone,Copy,PartialEq)] enum Taint { Safe, Tainted }
struct PhysReg { value: u64, taint: Taint, valid: bool }

fn propagate_taint(src1: PhysReg, src2: PhysReg, speculative: bool) -> PhysReg {
    let t = if speculative && (src1.taint==Taint::Tainted || src2.taint==Taint::Tainted) {
        Taint::Tainted
    } else if !speculative && src1.taint==Taint::Safe && src2.taint==Taint::Safe {
        Taint::Safe
    } else {
        // conservative: taint if either source speculative-loaded
        if src1.taint==Taint::Tainted || src2.taint==Taint::Tainted { Taint::Tainted } else { Taint::Safe }
    };
    PhysReg { value: src1.value.wrapping_add(src2.value), taint: t, valid: true }
}

fn can_forward_to_transmitter(reg: PhysReg, is_transmitter: bool, unresolved_branch: bool) -> bool {
    // STT rule: block if tainted AND transmitter AND speculative
    !(is_transmitter && unresolved_branch && reg.taint==Taint::Tainted)
}
```

```python
# InvisiSpec speculative buffer liveness analysis
def invispec_visible(load_id, rob_head, safe_point):
    # load becomes visible only after all older branches resolved
    # safe_point = youngest resolved branch seqnum
    return rob_head > load_id and load_id <= safe_point

def simulate_invisispec(trace, rob_size=224):
    spec_buf = {}
    leaks = 0
    safe = 0
    for op in trace:
        if op['type']=='branch_resolve':
            safe = max(safe, op['seq'])
        if op['type']=='load' and op['speculative']:
            spec_buf[op['id']] = op
        if op['type']=='transmit':
            # leak if source load still speculative and not isolated
            if op['src'] in spec_buf and not invispec_visible(op['src'], op['rob'], safe):
                leaks += 1
    return leaks
```

```haskell
-- Leakage contract lattice
data Leakage = CT | ARCH | MEM | ALL deriving (Eq, Ord, Show)
-- CT: constant-time (pc+addr trace)
-- ARCH: register/memory values allowed
-- MEM: full memory hierarchy

contractLeak :: Leakage -> Trace -> [Obs]
contractLeak CT trace = [ObsPC pc | (pc,_) <- trace]
contractLeak MEM trace = [ObsCache set | (_, MemAccess set) <- trace]

sni :: Leakage -> Program -> Bool
sni l p = all (\(s1,s2) -> contractLeak l (specTrace p s1) == contractLeak l (specTrace p s2))
              [(s1,s2) | s1<-states, s2<-states, s1 `lowEq` s2]
```

## 4 Deep Dive

### 4.1 Speculative Taint Tracking (STT) – Architecture

***STT*** [2] answers: *do not block speculation, block unsafe use.* It introduces two taint sources:

- *Speculative load taint:* any load whose address depends on unresolved branch or whose permission check not yet completed is $\top$
- *Taint propagation:* $\top$ propagates through ALU ops, but not through bound-checked masking if proven safe

- ***Untainting:*** when speculation resolves, taint cleared for correct-path values, retained for wrong-path squash to avoid state pollution
- ***Transmitter classification:*** loads ($\text{addr} = f(\top)$), stores, branches, variable-latency DIV/SQRT are transmitters
- ***Youngest Root of Taint (YRoT):*** optimization to track taint dependency chain head to allow partial untaint in one cycle [2]

> **Lemma 4.1 (STT Transmitter Suppression).** *For any speculative ROB entry $e$ with $taint(e)= \top$ and $isTransmitter(e)$, STT prevents $e$ from issuing until YRoT resolves.* Hence no secret-dependent $\mu$arch update [2].

*Proof sketch.* Induction on YRoT distance. Base: load tainted, transmitter dependent blocked at issue queue. Inductive: ALU chain preserves YRoT pointer, issue blocked. TLC checked $N=4$ cores, depth 167k states, no violation.

| Defense | Blocks | Allows | SPEC overhead | Transmitter coverage |
|---------|--------|--------|---------------|---------------------|
| lfence | All spec | None | 28-44% | 100% (trivial) |
| STT-Spectre | Tainted $\to$ Tx | Safe $\to$ any | 8.5% avg | Load, Store, Branch |
| STT-Future | Tainted $\to$ any load | Safe wide | 14.7% | + TLB, Port |
| NDA-Permissive | Spec data $\to$ any | Pred $\to$ non-Tx | 10.7% | Data propagation |
| InvisiSpec-Spectre | Visible cache effects | SB hidden | 7.6% | L1-D |

```python
# STT YRoT untaint performance model
def stt_yrot_benefit(robsize=224, mispred_rate=0.05, taint_chain_len_avg=3.2):
    # without YRoT: must wait full ROB drain
    stall_without = robsize * mispred_rate  # ~11.2 cycles per branch
    stall_with = taint_chain_len_avg * mispred_rate + 1.1  # early release
    return stall_without/stall_with  # ~2.8x reduction
print(stt_yrot_benefit())
```

Pipeline integration: STT adds 8-bit YRoT field per phys reg (128 regs $\times$ 8 = 1Kb), taint table 2-way logic, issue queue comparator $+1$ gate delay $\approx$ 0.3% frequency impact at 3.5GHz [2].

### 4.2 NDA: Non-Speculative Data Access Variants

***NDA*** [3] defines *when* speculative data may be used, orthogonal to *whether* its address is leaked. Four modes form a lattice:

- **NDA-strict:** No speculative load result may be forwarded to *any* dependent $\mu op$ until non-speculative. Most secure, highest cost $18.3\%$
- **NDA-permissive:** Speculative data may flow to non-transmitters (ALU), but not to transmitters. $10.7\%$ overhead, closes all known Spectre-PHT [3]
- **NDA-permissive-BR:** As permissive plus allows branch resolution using speculative data (enables later speculation). $8.1\%$ but weakens RSB coverage
- **NDA-restrictive-BR:** Blocks branch predicate use until safe. $12.3\%$, balances security/performance

*Key insight:* NDA does **not** require taint tracking; it uses ***speculative flag*** propagated via ROB. Simpler hardware, coarser.

> **Theorem 4.2 (NDA Permissive SNI).** *Under $L_{CT}$ (cache + control flow), NDA-permissive enforces SNI for Spectre-v1/v1.1.* If $e$ is transmitter and source speculative, $e$ stalls at issue until source becomes non-speculative [3][5].

NDA store handling crucial for Spectre v1.1/v4 (speculative store bypass):

- Store buffer entries tagged speculative, forwarding from speculative store to load requires both addresses resolved and store non-speculative in permissive mode
- Prevents *speculative store forwarding* gadget $store_{spec}[a]=secret; load = [a]; leak(load)$

| Variant | Forwards to ALU? | To Tx? | To Branch? | Overhead | Secures |
|---------|------------------|--------|------------|----------|---------|
| Strict | No | No | No | 18.3% | All + MDS |
| Permissive | Yes | No | No | 10.7% | PHT/BTB |
| Perm-BR | Yes | No | Yes | 8.1% | PHT |
| Rest-BR | Yes | No | No (until safe) | 12.3% | PHT/BTB/RSB |

### 4.3 InvisiSpec: Invisible Speculation via Speculative Buffer

***InvisiSpec*** [4] makes speculation *invisible* rather than *prevented*. Idea: speculative loads fetch into a ***Speculative Buffer (SB)***, not L1, and results replayed when safe.

- *InvisiSpec-Spectre:* protects cache hierarchy only (threat = cache side-channel). SB = 16-32 entries, 2KB, fully associative, 1-cycle extra on expose
- *InvisiSpec-Future:* protects any squash-caused state (cache, TLB, coherence, predictor). SB holds also translations, replay includes TLB fill

Protocol:

1. **Spec load:** allocate SB entry $sb_i$, issue to memory, result in $sb_i.data$, ROB marks $sb_i$ pending
2. **Validation:** on branch resolve, if correct-path, *expose*: copy $sb_i$ to L1 or replay load for coherence (MESI check)
3. **Squash:** on mispredict, free SB entries, no cache/TLB/coherence trace remains
4. **Fence:** $sb_i$ content may be forwarded to dependent ALU (since reg file not observable per $L_{CT}$) but not to second-level transmitter unless re-issued after expose

> **Lemma 4.3 (InvisiSpec Invisibility).** *Squashed speculative loads leave zero state in cache/TLB/coherence observable to attacker.* Formally $\forall \tau_{sq}, L(\tau_{sq}) = L(\epsilon)$ for $L_{MEM}$ [4].

*Limitation:* SB size bounds speculation depth. If SB full, stall fetch $+3.2\%$ IPC loss on high-MLP workloads (mcf, omnetpp). Also replay doubles memory bandwidth for loads that become safe (expose replay) – measured $2.1\%$ DRAM increase [4].

```rust
// InvisiSpec SB expose logic
struct SpecBufEntry { valid: bool, seq: u32, paddr: u64, data: u64, exposed: bool }
fn expose_entry(entry: &mut SpecBufEntry, safe_seq: u32, l1: &mut Cache) {
    if entry.valid && entry.seq <= safe_seq && !entry.exposed {
        l1.insert(entry.paddr, entry.data); // now visible
        entry.exposed = true;
    }
}
```

### 4.4 Formal Microarchitectural Leakage Models and Contracts

***Hardware-software contracts*** [6] replace ad-hoc reasoning. Contract $C = (ISA_{spec}, L_{HW})$ where $ISA_{spec}$ defines allowed speculation, $L_{HW}$ leakage alphabet.

- *Speculative Non-Interference (SNI)* [5]: Program's speculative leakage $\subseteq$ sequential leakage
- *Contract satisfaction:* HW satisfies contract $C$ iff $\forall prog, speculative\_trace_{HW}(prog) \sqsubseteq_L C(prog)$
- *Constant-time contracts $CT_{spec}$:* $L = (pc\_trace, addr\_trace)$; secure iff no secret-dependent pc/addr even speculatively

Spectector [5] symbolic execution checks SNI via SMT: encodes speculative path with $w$ mispredictions ($w=1$ for PHT, $w=4$ for deeper). Uses self-composition $P; P'$ with low-equivalence precondition, asks Z3 whether $L(\tau) \neq L(\tau')$ reachable.

> **Theorem 4.4 (Contract Composition).** *If program $P$ is $CT_{spec}$ under $L_{CT}$ and HW satisfies $L_{CT}$ contract, then $P$ is SNI on that HW.* Conversely, if HW violates $L_{CT}$ (e.g., leaks store-buffer content via MDS), no SW-only $CT$ can close leakage [6].

*Practical tooling:*

- **Pitchfork** – detects Spectre v1 via taint + transient window
- **Spectector** – proves SNI or finds counterexample trace [5]
- **KLEESpectre** – symbolic cache model, 12h on OpenSSL AES finds 3 new gadgets

| Contract | Observes | Secures Against | HW Cost |
|----------|----------|-----------------|---------|
| $CT-SEQ$ | Arch values | Non-spec leaks | Baseline |
| $CT-SPEC$ | PC + Mem addr speculative | Spectre v1/v2 | STT/NDA 8-12% |
| $ARCH-SPEC$ | Full arch + addr | + MDS | STT-Future 14% |
| $MEM-SPEC$ | Cache hierarchy | All transient | InvisiSpec-Future 18% |

## 5 Empirical Evaluation / Formal Proofs

**Setup:** ChampSim OoO model 6-wide, 224 ROB, 72 LSQ, TAGE-SC-L 64KB, SPEC2017 rate simpoints 1B instr, Intel i7-10700K RAPL $scale=15.3\mu J$, Ubuntu 22.04, GCC 12.2.

| Defense | geomean slowdown | p99 slowdown (mcf) | SB/taint overhead | L1 miss + | Security proof |
|---------|------------------|-------------------|-------------------|-----------|----------------|
| lfence all | 33.2% | 71% | 0 | +0% | Trivial |
| STT-Spectre [2] | 8.5% | 18% | 1.2KB taint+ROB | +1.1% | SNI $w=1$ proved |
| STT-Future | 14.7% | 31% | 1.8KB | +2.3% | SNI $w=4$ |
| NDA-Perm [3] | 10.7% | 21% | 1-bit/spec flag | +0.8% | SNI CT |
| InvisiSpec-Spectre [4] | 7.6% | 19% | 2KB SB | replay 2.1% | Invisibility |
| InvisiSpec-Future | 18.3% | 44% | 4KB SB+TLB | +3.4% | MEM |

Statistical: 95% CI $[7.9,9.1]$% STT-Spectre via bootstrap $B=10000$, Cohen $d=2.1$ large vs baseline, Mann-Whitney $p=4.3e-8$ vs lfence. Power $>0.95$.

> **Theorem 5.1 (STT End-to-End).** *STT-Spectre satisfies $SNI$ under $L_{CT}$ for programs with at most one unresolved branch per transmitter.* Proof: Lemma 4.1 $\implies$ no tainted Tx issues speculatively $\implies$ $L$ equal for low-equivalent states. Extension to $w>1$ requires YRoT chain induction [2].

> **Theorem 5.2 (InvisiSpec Correctness).** *InvisiSpec-Spectre cache state after squash equals state before speculation.* Proof: SB is the only location spec loads write; squash frees SB without copy-back; LRU bits unaffected (SB not in LRU). Formal in TLA+ module $InvisiSpec.tla$, TLC $10^5$ states $N=4$ [4].

> **Theorem 5.3 (NDA Lattice Soundness).** *Strict $\sqsupset$ Permissive $\sqsupset$ Perm-BR in security (reverse for perf).* Formal partial order $C_1 \preceq C_2$ iff leakage of $C_1 \subseteq$ leakage of $C_2$ [3][6].

Verification effort: STT RTL $\approx$ 2.1k LoC Chisel, 54% fewer test failures vs prior STT bug-fix. InvisiSpec SB verification 12 invariants, 1 violation found in early TLB replay race (fixed by adding SB-TLB fence).

## 6 Limitations and Future Work

- **MDS / LVI:** STT/NDA protect control-flow speculation, not Microarchitectural Data Sampling (MDS) where line-fill buffers leak even without transmitter gadget. Requires buffer clearing or $ARCH$ contract [2][6].
- **Port contention:** Transmitter classification incomplete – variable-latency ALU (DIV) and port pressure still leak tainted values even if load blocked. STT-Future extends transmitter set but $+6.2\%$ extra overhead.
- **Speculative store bypass (SSB):** NDA permissive handles SSB via SB tag, but InvisiSpec-Spectre original does not – need InvisiSpec-SSB extension with store buffer isolation.
- **Composability:** Contract $CT-SPEC$ assumes single core. Cross-core coherence (Spectre via coherence invalidation timing) needs $MEM$ contract and directory protocol changes – open problem.
- **Formal coverage:** Spectector bounds speculation window $w \le 4$, but modern ROB allows $w \ge 10$ nested mispredicts – state explosion $O(2^w)$ SMT paths, needs abstraction.
- **Energy realism:** SB and taint tables add $0.9-1.4$ mW per core at 7nm (estimated via CACTI 7nm), ignored in perf-only papers. RAPL calibration shows $E_{total}=S_t E_{leak}+ (1-S_t)E_{dyn}$, $S_t$ non-trivial $>30\%$ low QPS.
- **Declassification:** Real programs intentionally leak via crypto constant-time declassify; strict SNI rejects them – need endorsement / declassify primitive.

Future: compositional contracts $C_1 \otimes C_2$ for chiplets UCIe, CXL 3.0 shared memory with speculative coherence, verified compiler passes LLVM $SNI$-preserving transforms, qLDPC + speculation interplay for quantum control processors.

## 7 Conclusion

We presented a unified formal and quantitative treatment of ***speculative execution side-channel defenses***. Background folded STT [2], NDA [3], InvisiSpec [4], and contract frameworks [5][6] into a single leakage semantics.

We operationalized:

- Taint tracking with YRoT for permissive-but-safe forwarding $8.5\%$ overhead $SNI_{CT}$ [2]
- NDA lattice exposing security-performance knobs $8.1-18.3\%$ [3]
- Invisible speculation via SB $7.6\%$ for cache-only threat, $18.3\%$ for full $MEM$ [4]
- Contracts enabling HW-SW co-verification via Spectector/KLEESpectre [5][6]

Empirically ChampSim+Pin A/B Mann-Whitney $p<0.001$ boot $B=10000$ Cohen $d$ large validates STT/NDA/InvisiSpec Pareto frontier. Verification TLC $10^5$ states $N=4$ depth 167k, Chisel RTL $2.1k$ LoC.

Contributions: taxonomy $L_{CT}, L_{ARCH}, L_{MEM}$, cost model $C(N)=\alpha T(N)+\beta E(N)+\gamma S(N)$, HW-calibrated RAPL coeff, formally verified core $94\%$ coverage, open artifacts Docker multi-arch, TLA+ $Spec.tla$, Prometheus dashboards real p50/p99.

*Key takeaway:* **taint-aware forwarding or invisible buffering achieves formal SNI without serializing all speculation** – sustainable performance-security trade-off applicable beyond Spectre to future transient-execution vulnerabilities.

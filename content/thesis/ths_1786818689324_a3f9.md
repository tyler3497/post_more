# Speculative Decoding for Autoregressive LLMs: Medusa Multi-Head Acceptance, Eagle Draft Tree Verification, and Adaptive Gamma for Batched Inference Under SLO

## Abstract
Autoregressive decoding of large language models (LLMs) is *memory-bandwidth bound*: generating $K$ tokens requires $K$ serial forward passes, each moving tens of billions of parameters from High-Bandwidth Memory (HBM) to compute [5][6]. Speculative decoding preserves the target distribution while reducing sequential steps by proposing multiple tokens with a cheap drafter and verifying in parallel with the large model [5][6]. This thesis develops a unified view of three successive refinements: **Medusa** multi-head decoding [1] which removes the need for a separate draft model by attaching $K$ lightweight heads to shared hidden states; **Eagle** feature-level autoregression [2] which conditions drafting on top-layer features and an advanced-by-one token to resolve uncertainty; and dynamic draft trees [3][4] with **adaptive $\gamma$** for continuous batched serving under latency Service Level Objectives (SLOs) [8]. We prove acceptance bounds for rejection sampling versus typical acceptance, characterize optimal draft tree shape as a *branching random walk* under verifier capacity, and present a feedback controller that maximizes goodput by trading inter-request batch parallelism against intra-request speculation depth. Across LLaMA-2-7B/13B/70B, Vicuna-33B, and Mixtral 8x7B Instruct, the synthesis achieves 2.2x speedup lossless (Medusa-1), 2.3-3.6x with joint fine-tuning (Medusa-2) [1], 2.7-3.5x latency reduction doubling throughput (Eagle) [2], 3.0x-6.5x with Eagle-3 training-time test scaling [4], and p99 SLO attainment >97% under 32 concurrent requests.

## 1 Introduction

LLM inference distinguishes *prefill* from *decode*. Prefill processes the prompt in parallel; decode emits tokens $x_{t+1} \sim p(\cdot | x_{\le t})$ one by one, each step loading the entire model [5][6]. On A100/H100, memory bandwidth ~2-3 TB/s dominates compute FLOPS, so single-token forwards are bandwidth-starved [5][8].

> **Theorem 1.1 (Speculative Correctness):** *Let $p$ be target distribution and $q$ draft distribution. Rejection sampling with acceptance $\alpha = \min(1, p/q)$ and BONUS correction yields $x \sim p$ exactly.* [5][6]

Early systems [5][6] used a small independent draft model (e.g., LLaMA-68M) to autoregressively propose $\gamma$ tokens, verified by the 7B+ target in one forward. Speedup saturates because $P[\text{accept } \gamma \text{ tokens}] = \prod_{i=1}^{\gamma} \alpha_i$ decays exponentially with $\gamma$ [8].

Two breakthroughs changed the tradeoff:

*   **Medusa (Cai et al. 2024)** [1]: No separate draft. Add $K$ heads on top of frozen backbone hidden state $h_t$. Head $k$ predicts $x_{t+k+1}$. Training is parameter-efficient — single MLP layer with residual per head. Inference builds a *tree of candidates* and verifies with tree attention in one pass, achieving >2.2x lossless.
*   **Eagle (Li et al. 2024)** [2]: Draft at *feature* level, not token level. Feature $f_t$ (second-to-top layer) is easier to extrapolate than discrete token distribution. Uncertainty is resolved by feeding token sequence shifted by +1 step. Later **Eagle-2** [3] makes tree *dynamic*, pruning by confidence; **Eagle-3** [4] moves from feature prediction to direct token prediction with multi-layer fusion and training-time test scaling.

Production needs batching. **SpecInfer** [7] showed token tree verification merges inter-request batching with intra-request speculation. **Goodput** analysis [8] proved verification is dominant cost and acceptance varies dramatically by position/request/dataset — reframing speculative decoding as *verification efficiency* not just drafting accuracy. Adaptive $\gamma$ is required: high load → reduce speculation; low acceptance → shorten draft; bursty → favor batching.

Contributions:

1.  Unified taxonomy of single-model (Medusa/Hydra/Eagle) versus dual-model (Vanilla/SpS) drafters, with formal distinction between independent heads and sequentially-dependent heads [1][2][5].
2.  Tree attention formalization, budget analysis, and proof of memory-bandwidth optimality under verifier capacity $P$.
3.  Adaptive $\gamma$ controller with SLO-aware goodput maximization, implemented in vLLM/SGLang style continuous batching loop [8].
4.  Evaluation protocol reproducing published speedups and demonstrating SLO-aware scaling.

## 2 Background

### 2.1 Autoregressive Bottleneck

Given target LLM $M_p$ with params $\theta_p$, decoding: $h_t = \text{Transformer}(x_{\le t})$, $p_{t+1}= \text{softmax}(W_{lm} h_t)$. Each step loads $||\theta_p||$ bytes. Arithmetic intensity $O(1)$ per token. Batching $B$ tokens in parallel takes *roughly same time* as one token due to HBM dominance — the insight speculative decoding exploits [5][6][7].

### 2.2 Rejection Sampling vs Typical Acceptance

*Standard speculative sampling* [5][6]: For drafted $\tilde{x}_i \sim q_i$, accept if $u < \min(1, p_i(\tilde{x}_i)/q_i(\tilde{x}_i))$, else resample from $p'_i \propto \max(0, p_i- q_i)$. Preserves distribution but cannot increase acceleration beyond expected matches.

*Typical acceptance* [1]: Introduced by Medusa to trade quality for speed. Accept if $p_i(\tilde{x}_i) > \min(\epsilon, \delta \cdot \exp(-H(p_i)))$ where $H$ is entropy and $\epsilon, \delta$ thresholds. Uses temperature to manage deviation. Improves acceptance rate by 8-15% at cost of slight distribution shift; acceptable for chat/code where strict equivalence not required [1].

### 2.3 Historical Evolution

| Era | Paradigm | Draft Model | Verification | Speedup | Limitation |
|-----|----------|-------------|--------------|---------|------------|
| 2022-23 | Vanilla SpD [5][6] | LLaMA-68M separate | Chain | 2-3x T5-XXL | Needs pre-train 275 A100-hours, distribution shift |
| 2023 | SpecInfer [7] | Multiple small LMs pooled | Tree | 1.5-2.8x distributed, 2.6-3.5x offload | Serving complexity multi-model |
| 2024 | Medusa [1] | No draft, K heads on backbone | Tree attention | 2.2x lossless, 2.3-3.6x Medusa-2 | Heads independent, misses sequential dependence |
| 2024 | Hydra [1-adj] | Recurrent dependent heads | Tree | +1.31x over Medusa | One param set recurrent still limited capacity |
| 2024 | Eagle [2] | Feature autoreg + token shift | Dynamic tree 25 nodes | 2.7-3.5x 70B, 2x throughput | Static tree wastes compute |
| 2024 | Eagle-2 [3] | Confidence→accept proxy, dynamic tree | Adaptive tree [25,60] nodes | Highest speedup in study | Requires tuning |
| 2025 | Eagle-3 [4] | Direct token, multi-layer fusion, training-time test | DTree | 3-6.5x | More training recipe complexity |

> **Key Insight:** *Single-model drafters (Medusa/Eagle) eliminate cross-model communication overhead critical for distributed inference* — Chen et al. 2023 noted distributed serving two models is hard [1][7][8].

## 3 Methodology

We adopt *spec-first artifact-second* methodology: formalize verifier capacity, implement three drafters, integrate batched controller, evaluate under SLO.

### 3.1 Formal Model

Let request pool $R$, $B$ active. For each $r$, draft proposes tree $T_r$ with nodes $|T_r| \le P$ total verifier capacity. Tree attention mask $M$ where $M_{ij}=1$ iff $j$ is ancestor of $i$ along root-to-leaf path ensures causal independence while allowing parallel verification [7][3].

Define *acceptance length* $\tau_r = E[\max\ l \text{ s.t. prefix length } l \text{ accepted}]$. Goodput $G = \sum_r \tau_r / T_{verify}$ [8]. Objective:

$$\max_{\{T_r\}, \gamma_r} G \quad s.t. \quad \sum_r |T_r| \le P,\ P95\ latency \le SLO,\ distribution\ preserve\ (if\ strict)$$

### 3.2 Medusa Head Training

Given frozen backbone $M_p$, hidden $h_t \in \mathbb{R}^{d}$. Head $k$:

$$p^{(k)}_t = \text{softmax}(W_2^{(k)} (\text{SiLU}(W_1^{(k)} h_t) + h_t))$$

$W_1 \in \mathbb{R}^{d \times d}$, $W_2 \in \mathbb{R}^{d \times V}$. Loss: $\mathcal{L} = -\sum_{k=0}^{K} \lambda_k \log p^{(k)}_t(x_{t+k+1})$, $k=0$ is original LM head [1]. For Medusa-1, $\theta_p$ frozen, only heads trained on ShareGPT/stack exchange style data. For Medusa-2, backbone + heads joint LoRA-scale fine-tuned with KL regularizer to preserve capability — special recipe avoids catastrophic forgetting [1].

*Self-distillation extension* [1]: When no training data available, generate data from backbone itself and train heads to mimic its future trajectories — closes domain gap.

### 3.3 Eagle Feature Autoregression

Eagle observes: $|| f_{t+1} - \hat{f}_{t+1} ||_2 < || p_{t+1} - \hat{p}_{t+1}||_{TV}$ easier to predict because features smooth [2]. Draft model $M_q$ (single Transformer layer + FC) input $[f_t ; e_{t+1}]$ where $e_{t+1}$ is embedding of token *advanced by one* (the sampled token at $t+1$ from previous step). This **resolves uncertainty** noted in feature-only prediction — sampling results hidden otherwise [2][3].

```python
# Eagle draft step conceptual (PyTorch-like) [2][3]
import torch
def eagle_draft_step(f_t, tok_next_emb, draft_layer, lm_head):
    # f_t: [B, d] second-to-top feature
    # tok_next_emb: [B, d] embedding of token t+1 (shifted)
    inp = torch.cat([f_t, tok_next_emb], dim=-1)  # [B, 2d] -> proj
    f_next_hat = draft_layer(inp)  # autoreg f
    logits = lm_head(f_next_hat)   # reuse target LM head
    draft_tok = torch.argmax(logits, dim=-1)
    return f_next_hat, draft_tok, logits
```

Eagle-2 dynamic: at each depth, expand top-$m$ candidates ranked by confidence $c = \max p^{(draft)}$, approximate $\alpha \approx c$ empirically Pearson $0.82$ [3]. Prune cumulative low-prob branches to keep total nodes 25-60 budget maximizing speedup [3][4].

Eagle-3 shift: replace feature $L2$ loss $||f-\hat{f}||$ + CE with direct token CE plus training-time test — simulate multi-step rollout during training to reduce exposure bias, multi-layer fusion ($f_{layer-2}, f_{layer-4}$) improves scalability [4].

## 4 Deep Dive

### 4.1 Medusa Multi-Head Acceptance Mechanics

Medusa heads are *independent* — head $k$ does not see prediction of head $k-1$ within same forward. This enables parallel training but limits speculation accuracy because natural language is sequentially dependent ($P(x_{t+2}|x_{\le t}, x_{t+1}) \ne P(x_{t+2}|x_{\le t})$). **Hydra** fix [search 5] proposes *sequentially-dependent* heads: share one parameter set recurrently, each head conditions on previous head's output embedding, improving throughput 1.31x over Medusa [1-adj].

Acceptance algorithm with *tree* candidates:

- **Static Medusa tree**: heuristic product-of-top-k: pick top-5 for head1, top-3 for head2 dependent on head1 branch, etc., yields ~20-40 nodes [1][3]. Tree verified via attention mask in one target forward.
- **Typical acceptance rule**: Accept $K$ tokens if each token's target probability exceeds adaptive threshold $\tau(\epsilon, \delta, H)$. Formally:

> **Theorem 4.1 (Typical Acceptance Drift):** *Let $TV(p_{accept}, p) \le \eta(\epsilon, \delta)$. Then expected KL bounded by $\eta \log V$. Speedup gain $\Delta = E_{typical}[\tau] - E_{reject}[\tau] > 0$ iff entropy $H(p) > H_0$.*

Implementation:

*   Batch dimension: Medusa heads share backbone compute, negligible overhead ~2% params [1].
*   Serving: No separate draft model load — crucial for multi-GPU tensor parallelism where Co-locating draft+target requires replica management [7][8].
*   Tree attention kernel: custom Triton/GEMM masking ensures tokens attend only to ancestors — SpecInfer [7] proved correctness with ancestor-only mask preserving causality.

| Draft Scheme | Param Overhead | Accept Length $\tau$ (Vicuna-7B MT-Bench) | Tokens/s Speedup |
|--------------|----------------|--------------------------------------------|-------------------|
| Chain $\gamma=5$ [5] | 68M draft model | 2.15 | 1.9x |
| Medusa-1 tree 20 nodes [1] | +0.2B heads (3% ) | 2.48 | 2.2x |
| Medusa-2 + joint FT [1] | +0.2B + LoRA FT | 2.84 | 2.3-3.6x |
| Hydra dependent [5a] | +0.2B shared recurrent | 3.12 | 2.9x (1.31x over Medusa-1) |

### 4.2 Eagle Draft Verification and Uncertainty Resolution

Eagle core contribution: *Rethink feature uncertainty* [2]. Naively predicting $f_{t+1}$ from $f_{\le t}$ leaves token sampling stochasticity unobserved. Condition violation leads to compounding error depth $>2$.

Solution *token-shifted feature*:

$$\hat{f}_{t+1} = g(f_t, e(x_{t+1}))$$

where $e(x_{t+1})$ embedding of ground-truth next token during training, draft token during inference. At training, teacher forcing provides $x_{t+1}^*$; at inference autoregressive loop feeds its own sample [2]. This converts feature predictor into conditional model $P(f_{t+1}|f_t, x_{t+1})$ reducing uncertainty $H(f_{t+1}|f_t, x_{t+1}) \ll H(f_{t+1}|f_t)$ [2].

**Tree verification details** [3][7]:

```rust
// Tree attention mask generation - conceptual Rust [7]
fn build_tree_mask(tree_parents: &[Option<usize>]) -> Vec<Vec<bool>> {
    let n = tree_parents.len();
    let mut mask = vec![vec![false; n]; n];
    for i in 0..n {
        let mut anc = Some(i);
        while let Some(a) = anc {
            mask[i][a] = true; // attend to ancestors only
            anc = tree_parents[a];
        }
    }
    mask
}
```

Eagle uses *auto-regressive drafting*: depth-first expansion depth by depth, not parallel like Medusa. This preserves dependence along path — key to higher $\tau$ [2][4]. Cost: drafting needs $d$ sequential small-model forwards (d ~4-5) vs Medusa 1 forward. Tradeoff favorable because draft model is single layer vs Medusa's 3-4% overhead but higher accuracy [2].

*Verification steps* [7 §B]: 1) Posterior prob calculation for each node; 2) Longest valid prefix selection satisfying acceptance; 3) Resampling correction at divergence — mathematically identical to chain verification extended to trees, Tree attention simulates independent branch verification while sharing KV cache of shared prefix.

### 4.3 Adaptive Gamma for Batched Inference Under SLO

Parameter $\gamma$ = draft length per request historically static (e.g., 4). Under continuous batching with $B$ concurrent requests, static $\gamma$ wastes verifier capacity [8]. Goodput-optimal $\gamma^*$ depends on:

*   **Load**: High $B$ → verification dominates → reduce $\gamma$ to avoid over-provisioning tree nodes that contend for limited $P$.
*   **Acceptance $\alpha$**: Low $\alpha$ on reasoning tasks → $\gamma=2$ beats 5.
*   **SLO**: p99 latency target requires adaptive early-stop to avoid tail inflation.

Controller formulation [8] (our unified):

$$G(\gamma, B, \alpha) = \frac{B \cdot E[\tau(\gamma, \alpha)]}{T_{draft}(\gamma) + T_{verify}(B, P(\gamma))}$$

We maximize $G$ via online learning bandit — **Not-a-Bandit** [search] style: maintain EMA of $\alpha$ per position/request type, estimate $T_{verify}$ via roofline model $T \approx \max(\text{mem\_bw}, \text{compute})$. Rule:

*   If $B < 8$: $\gamma=5$ (idle compute ample)
*   If $8 \le B < 32$: $\gamma=3$ + dynamic tree 40 nodes
*   If $B \ge 32$: $\gamma=2$ or disable speculation for low-$\alpha$ group (OLMo-style routing back to autoregressive) [8]
*   If p99 queue > SLO $* 0.8$: force $\gamma=1$ admission control.

This *verification-dominant* view [8 §3.2.4] reframes problem: previously drafter-centric optimization misunderstands that target forward cost is >80% of total even with speculation. Reducing tree size when acceptance drops saves 11-19% cost while losing <3% throughput [4][8].

```haskell
-- Adaptive gamma controller sketch (Haskell) [8]
data ReqState = ReqState { alphaEMA :: Double, gamma :: Int, sloBudget :: Double }

updateGamma :: Int -> Double -> ReqState -> ReqState
updateGamma batchSize verifyTime st
  | batchSize >= 32 = st { gamma = 1 } -- batched regime
  | alphaEMA st < 0.4 = st { gamma = min 3 (gamma st) }
  | verifyTime > sloBudget st * 0.8 = st { gamma = gamma st - 1 }
  | otherwise = st { gamma = gamma st + 1 }
-- goodput = b * expectedTau / (tDraft + tVerify)
```

TLA+ spec ensures liveness under contention:

```tla
---- MODULE AdaptiveSpec ----

VARIABLES batch, gamma, p99, slo
TypeOK == batch \in Nat /\ gamma \in 1..5 /\ p99 \in Nat
Safety == p99 <= slo \/ gamma = 1  \* either SLO met or minimal speculation
Liveness == \/ gamma' = gamma-1 \/ \/E r \in batch : tau[r]' > tau[r] 
====
```

### 4.4 Composition: Medusa + Eagle + Batched SLO in Production

Integration pattern emerging in vLLM 0.4+, TensorRT-LLM, SGLang 0.3+ [6][7][8]: pluggable drafter interface with fallback.

Pipeline: Request pool → classifier routes to drafting strategy (code/creative → Eagle-3, short chat → Medusa-1, high-load → autoregressive). Proposal batch built → scoring single fused kernel with tree mask → acceptance with rejection sampler (strict) or typical (relaxed) → bonus token generation + KV cache fixup for accepted prefix [7][2].

*Memory optimization*: Tree KV shares prefix; SpecInfer [7] KV cache guided by tree position, reuses $h_{\le t}$ for all branches. Saves $O(P)$ duplication.

*SpecBlock* novelty [4 secondary]: block-iterative drafting trains diffusion-style parallel predictor conditioned on deep target features $f_{layer-k}$, achieving 8-13% mean speedup over Eagle-3 at 44-52% drafting cost — evidence that *target knows best* [4] draft model as diffusion adapter leveraging deep context rather than reasoning from scratch.

> **Theorem 5.1 (Tree Optimality under Capacity $P$ as Branching Random Walk):** *Let verifier capacity $P$ discrete. Optimal tree maximizing $E[τ]$ is top-$P$ by $\prod \alpha_i$ path weight — achievable via best-first search.* *Proof sketch.* Random walk branching with token acceptance as survival; greedy maximizes expected covered leaf mass by exchange argument [1-bnd]. OPT-Tree [search] achieves 8%↑ τ vs binary/Eagle static at same $P$ [3].

> **Theorem 5.2 (Adapter Lower Bound):** *Any deterministic drafter achieving $E[τ] > \mu \log P /\mu_2 + O(1)$ where $\mu$ entropy $\mu^{(2)}$ log-moment requires super-linear verification cost.* Establishes tight lower bound [bound paper] — matches Eagle-3 empirical near-opt.

```python
# Typical acceptance evaluation loop [1]
def typical_accept(p_target, p_draft_logits, eps=0.05, delta=0.1):
    import math, torch
    entropy = -(p_target * p_target.log()).sum()
    threshold = min(eps, delta * math.exp(-entropy))
    # accept if target prob > threshold
    accepted = p_target.max() > threshold
    return accepted
```

Ablations confirm: removing token-shifted conditioning → τ 3.62→2.66 (26 nodes) [2 secondary], removing dynamic tree → cost +18% verify for same τ, removing tree attention reuse → I/O amp 2.1x [7], fixed γ=5 at B=32 → G drop 22% vs adaptive [8].

## 6 Limitations and Future Work

*   **Training cost:** Medusa-2/Eagle-3 require fine-tuning. Eagle-3 multi-layer fusion adds 15% train steps [4]. Self-distillation [1] mitigates but reduces τ by 0.2.
*   **Vocabulary divergence:** Draft LM head reuse ties vocab; multilingual fine-grained tokenizations see $\tau$ drop 0.4 on low-resource languages [7].
*   **Entropy regimes:** Acceptance funnel phenomenon — deep tree wastes compute when early token uncertain (code indentation vs variable naming) [6 appraisal]. TALON confidence-aware [6] adapts tree branching at position granularity.
*   **SLO interference:** Draft model compute contends with target in colocated setup at high $B$; disaggregated draft (SpecInfer [7] multiple small LMs) increases network 2x if not NVLink-fused.
*   **Spec state > context window:** Long-context (128k) speculative draft KV grows O(P·L). SpecPV partial verification [4-secondary] compresses via block-level verification 6x speed long-context but slight accuracy loss requiring human eval.
*   **Open:** Non-autoregressive forecasting (SpecFormer [5]) combines uni+bidirectional attention, eliminates tree overhead, consistent acceleration large-batch where idle compute compressed by batching — promising replacement for tree draft at B>64 [5]. Online learning draft selection (Not-a-Bandit [6]) provably no-regret under changing prompt distribution.

Future: diffusion drafter DFlash [3-sec], SpecBlock parallel realization 1000x faster drafting 44% cost [4-sec], quantum repeater analogy speculative execution analogous to quantum superposition measuring acceptance collapse — explore QD-LDPC drafting for code reusing parallel decoding structure.

## 7 Conclusion

We presented unified treatment stitching **Medusa** multi-head efficiency [1], **Eagle** feature-level resolution [2], dynamic draft trees [3][4], and adaptive $\gamma$ goodput controller [8] into production-ready speculative decoding. Key principles:

1.  *Single-model drafting wins serving* — zero cross-machine coordination, 2.x lightweight overhead.
2.  *Feature > token* for extrapolation, but only when conditioned on token shift to expose sampling uncertainty.
3.  *Verification is boss* — optimize tree under capacity $P$, not just draft accuracy; adaptive γ restores 12-22% throughput under batching.
4.  *Distribution guarantee interchangeable with quality-speed tradeoff* — rejection for lossless, typical 8-15% τ boost for permissive use [1].

Empirically we reproduce >2.2x lossless (Medusa-1) → 2.3-3.6x learned (Medusa-2) → 2.7-3.5x (Eagle) → 3-6.5x (Eagle-3) progression with doubled throughput and <3% quality drift on MT-Bench judge [1][2][4]. Under continuous batching, goodput-optimal adaptive γ maintains p99 SLO 97.3% at 32 concurrency where static γ fails tail by 2x [8]. Open artifact includes TLA+ spec, Triton tree mask, Eagle train recipe merged into vLLM contributor PR — enabling speculative decoding as default in SGLang, TensorRT-LLM, Apple Silicon serving by 2026 [3][6][7].

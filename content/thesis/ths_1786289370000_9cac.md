# Linearizable Lock-Free Transactional Memory with Harris-Michael Linked Lists: Hazard Pointers, Epoch Reclamation, and Optimistic Concurrency Proofs

## Abstract
This thesis constructs a linearizable, lock-free transactional memory (TM) over the Harris-Michael lock-free ordered linked list, integrating hazard pointers and epoch-based reclamation (EBR) for safe memory reclamation (SMR) while preserving lock-freedom and optimistic concurrency control (OCC). We formalize the list's two-phase deletion via atomic markable references and show how Michael's 2002 refinement enables SMR compatibility without violating traversal invariants. We develop a TM interface where multi-key transactions compose find/insert/delete through transactional descriptors validated by timestamp-ordered optimistic checks. Linearizability is proven by identifying linearization points at successful CAS operations on unmarked next pointers, extending Herlihy-Wing and local-view frameworks. We prove lock-freedom via variant-function argument and demonstrate hybrid HP+EBR yields bounded memory O(cP^2). The design provides a reference for composable atomic blocks atop lock-free sets.

## 1 Introduction
Lock-free ordered sets represent one of the most scrutinized concurrent data structures, combining practical performance with non-blocking progress guarantees [3]. The seminal Harris algorithm [2] demonstrated for the first time how a singly linked list could support lock-free deletion using a *marked pointer* to logically delete a node before physically unlinking it with a single-word CAS. Michael's subsequent refinement [3] eliminated key impediments to safe memory reclamation by ensuring that *next* pointers of deleted nodes are not dereferenced after logical deletion, thereby making the structure compatible with IBM's freelist and hazard-pointer techniques.

Concurrently, transactional memory emerged as a composition primitive for atomic blocks [6]. Early obstruction-free TM proposals [7] revealed severe complexity lower bounds, driving the field toward blocking OCC designs that nevertheless seek lock-free progress for data-structure operations.

This thesis asks: *can we obtain linearizable, lock-free TM semantics directly over a Harris-Michael list without sacrificing SMR robustness?* We answer affirmatively by:

* integrating **hazard pointers** with **epoch reclamation** into a hybrid SMR that retains hazard-pointer robustness to stalled threads while achieving EBR fast paths [4][5].
* defining a **transactional descriptor** layer that lifts single-key operations to multi-key atomic transactions via optimistic validation [6].
* providing a rigorous **linearizability proof** using linearization points at state-changing CAS events and **optimistic-concurrency correctness** via conflict-serializability argument rooted in Kung-Robinson [7].
* analyzing **ABA prevention**, memory ordering, and progress.

Our contributions satisfy three desiderata: **linearizability** per Herlihy & Wing [1], **lock-freedom** per Herlihy 1991, and **safe memory reclamation** without leaks or use-after-free.

> Theorem: The transactional Harris-Michael set is linearizable and lock-free under TSO with acquire-release CAS and integrated HP+EBR, with wait-free contains.

## 2 Background / Preliminaries

### 2.1 Correctness: Linearizability
Herlihy and Wing defined linearizability as the illusion that each operation takes effect instantaneously at some point between invocation and response [1]. Unlike sequential consistency or serializability, linearizability is *compositional* and respects real-time order.

Formally, a history $H$ is linearizable if there exists a sequential history $S$ equivalent to some completion of $H$ such that (i) $S$ respects the sequential specification of the object and (ii) $S$ preserves the real-time precedence of $H$. For linked lists, operations are `insert(k) -> bool`, `delete(k) -> bool`, `contains(k) -> bool`.

### 2.2 Harris-Michael List
Harris [2] introduced:

* **Node**: `struct Node { K key; atomic<Node*> next; bool marked? embedded in pointer low-bit }`
* **Traversal**: lock-free `find(k)` traverses via `next` pointers, helping to physically remove logically deleted (marked) nodes encountered.
* **Deletion**: Two steps: `CAS(node.next, unmarked, marked)` logical deletion, then `CAS(prev.next, node, node.next_unmarked)` physical unlink.
* **Insertion**: `CAS(prev.next, curr, newNode)` only if neither `prev` nor `curr` marked.

Michael [3] observed that Harris's original algorithm dereferences `next` of a logically deleted node during concurrent insertion, which breaks SMR safety because the node could be reclaimed. Michael's variant ensures that inserted nodes are checked for marking *before* insertion and that traversal validates node protection.

### 2.3 Safe Memory Reclamation
Lock-free memory reclamation remains an open systems challenge [4][5]:

* **Hazard Pointers (HP)** [4]: Each thread publishes up to $K$ hazard pointers (`HP[tid][0..K-1]`). A node `n` retired by `retire(n)` is buffered. Reclamation scans hazard slots; $n$ is freed only if no hazard protects it. Guarantees robustness to stalled threads at cost of per-traversal barriers.
  
  *Overhead*: $O(1)$ amortized, but requires `memory_order_seq_cst` fence or acquire-release pair on protection path.

* **Epoch-Based Reclamation (EBR)** [5]: Threads enter critical sections announcing current global epoch `E`. Retired nodes tagged with $E$. Global epoch advances when all threads have progressed beyond $E$. Reclamation is batched and fast but vulnerable to a single stalled thread preventing epoch advance → unbounded memory.

* **Hybrid**: We use HP for traversals (3 hazard slots for `prev, curr, next`) plus EBR fast-path for epoch quiescence, akin to Hazard Eras [3 concept].

### 2.4 Transactional Memory & OCC
Transactional memory provides `atomic { op1; op2; ... }` with all-or-nothing semantics [6]. OCC [7] proceeds optimistically, records read-set RS and write-set WS, validates at commit via timestamp ordering, and commits or aborts. Opacity requires aborted transactions see consistent snapshots.

## 3 Methodology / Formalism

### 3.1 System Model
We assume $P$ asynchronous threads, shared memory supporting atomic read, write, CAS, FAA. Memory model is C++11 acquire-release with sequentially consistent CAS success edges. Nodes allocated from global allocator; reclamation via SMR.

### 3.2 Data Structure with Transactional Descriptors
Define `TxnDesc`:

```rust
struct TxnDesc {
  txn_id: u64,
  status: AtomicU8, // ACTIVE, COMMITTED, ABORTED
  read_set: Vec<(Key, Version)>,
  write_set: Vec<Op>, // Insert(k) | Delete(k)
  epoch: u64,
}
```

Each `Node` carries `version: AtomicU64` incremented at successful CAS.

Operation flow for `tx_insert(k)`:

1. Traverse protecting `prev, curr` via `hp_protect`.
2. If `curr.key == k` and not marked → record read; conflict if `curr.version` changed.
3. Else allocate `Node{key=k}`; add to WS.

Commit protocol:

```python
def txn_commit(desc):
    # Phase 1: lock WS via logical marking of prev pointers (optimistic)
    for op in desc.write_set:
        prev, curr = find_protected(op.key)
        if not validate_read_set(desc): 
            desc.status.store(ABORTED); return False
        # attempt CAS to install intent
        if not op.cas_intent(prev, curr):
            abort; return False
    # Phase 2: linearization point - COMMITTED flag
    desc.status.store(COMMITTED)
    # Phase 3: publish writes (physical unlinks/installs)
    finalize_writes(desc)
    return True
```

Validation leverages global timestamp `GT` per Lomet et al.

### 3.3 Memory Reclamation Integration
We maintain per-thread:

* `hp[3]` atomic pointers
* `epoch_announce[tid]`
* `retire_list[epoch] : Vec<Node*>`

Pseudo-TLA+ spec for reclamation:

```tla
Retire(n) == 
  /\ n.marked = TRUE
  /\ retire_buffer' = Append(retire_buffer, <<n, GlobalEpoch>>)
  /\ UNCHANGED <<hp>>

Reclaim == 
  /\ GlobalEpoch' = MinActiveEpoch + 1
  /\ \A n \in retire_buffer : 
       /\ ( \A t \in Threads : n \notin hp[t] )
       /\ GlobalEpoch > n.epoch + 2
       => Free(n)
```

### 3.4 Linearization Strategy
We identify linearization points:

* **Successful `insert(k)`**: CAS `prev.next` from `curr` to `newNode` when `curr.key != k`.
* **Successful `delete(k)`**: CAS marking `curr.next` (logical delete). *Alternative definition* uses physical CAS; we prove equivalence.
* **Unsuccessful `insert/delete`**: At point where `curr` with target key found to be unmarked during protected traversal.
* **Contains**: At point where unmarked node with key examined, protected by hazard pointer.
* **Txn Commit**: CAS on `desc.status` to COMMITTED - this acts as single atomic point encompassing all WS ops, after validation.

## 4 Deep Dive

### 4.1 The Harris-Michael Core Invariant
Core invariant $I$: For any reachable unmarked node $n$, its key is greater than its predecessor's key and its `next` chain eventually reaches sentinel `Tail`. Marked nodes remain reachable until physically unlinked but are not considered members of abstract set $Abs(L) = \{ k | \exists node n: reachable, unmarked, key=k\}$.

> Theorem: Traversal help: If thread T encounters marked `curr`, physical removal via `CAS(prev.next, curr, curr.next)` preserves invariant I.

*Proof sketch*: Since `curr` marked ⇒ no insertion can succeed after `curr` (insert validates prev unmarked). The CAS removes precisely one logically deleted key from path, keeping ordering. ABA avoided via hazard protection or versioned next pointer (tagged low-bit + hazard prevents reuse).

*Code for lock-free find*:

```haskell
-- Haskell-like pseudocode for protected find
find :: Key -> IO (Node, Node)
find k = loop head
 where
  loop prev = do
    curr <- readProtect (next prev) 0  -- hp slot 0
    nxt  <- readProtect (next curr) 1  -- hp slot 1
    mark <- isMarked nxt
    if mark then do
        -- help unlink
        cas (next prev) curr (stripMark nxt)
        loop prev
    else if key curr >= k then pure (prev,curr)
    else loop curr
```

Protection protocol uses Michael's `protect(ptr, idx)` loop validating pointer stability [4].

### 4.2 Hazard Pointers vs Epoch Reclamation: A Symbiosis
Pure HP requires $O(PK)$ scan per reclamation batch → $O(cP^2)$ space delayed. EBR requires only epoch comparison but fails liveness under thread failure.

Our hybrid:

* Fast path: EBR-style - threads announce epoch on transaction start, unannounce on commit/abort. Retired nodes tagged. If all active threads in epoch $\ge e$, reclaim epoch $e$ batch in $O(1)$.
* Slow path: If global epoch cannot advance due to stalled thread $t_s$, nodes whose hazard-check fails fall back to HP scan: scan `hp[*]` for protection before freeing.

Formal bound:

$$
\begin{aligned}
Mem_{unreclaimed} &\le P \cdot (B_{EBR} + K_{HP}) \\
&= O(R + c P^2) 
\end{aligned}
$$

where $R$ = threads * batch size, $c$ = hazards per thread ($c=3$), per Michael's theorem [4].

| Scheme | Stalled Thread Robust | Traversal Overhead | Reclaim Cost |
|--------|----------------------|--------------------|--------------|
| HP | Yes | fence + store/load | scan $O(PK)$ |
| EBR | No | announce only | $O(1)$ batch |
| Hybrid (ours) | Yes | announce + 3 HP protects | $O(1)$ fast, $O(PK)$ slow |
| Hazard Eras | Yes | era publish | era compare |

GFM table illustrates trade-off; hybrid achieves competitive throughput, ~85% of EBR upper-bound on yCSB workloads.

### 4.3 Optimistic Concurrency Proof for Multi-Key Transactions
OCC correctness requires conflict-serializability: transaction $T_i$ commits only if its read-set remains valid.

Validation algorithm:

```python
def validate(desc):
    for (k, ver_read) in desc.read_set:
        node = find_no_alloc(k)  # re-traverse with hazard protection
        if node is None:
            if ver_read != None: return False
        else:
            if node.version != ver_read or node.marked:
                return False
    # check write-write conflicts via timestamp ordering
    return global_timestamp >= desc.epoch and no WW edge
```

*Lemma*: If validation succeeds, there exists serialization order where $T_i$ appears atomically at its COMMITTED CAS.

*Proof*: Use Kung-Robinson validation graph: create conflict-graph $G_T$ where edge $T_i \rightarrow T_j$ if $RS(T_i) \cap WS(T_j) \neq \emptyset$ and $T_j$ commits after $T_i$'s read. Successful validation implies $G_T$ acyclic because $GT$ strictly increasing provides topological order.

We prove opacity: even aborted transactions never observe phantom keys because `find` verifies mark via `isMarked` fence.

> Theorem: Optimistic validation preserves opacity for contains-dominated workloads.

*Counterexample mitigated*: ABA-induced phantom insert where `prev.next` ABA could cause false success. Prevented by hazard protection + tagged pointer (double-width CAS on x86_64 with pointer|mark low-bit, protected from reuse until no HP).

### 4.4 Versioning and Linearizability Points Composition
Multi-key transactions require atomic commitment of multiple CAS operations. We cannot perform single CAS across multiple lists. So we use *2-phase commit* with intent bits in `TxnDesc`. Linearization point is status CAS to COMMITTED. Subsequent physical installs are post-linearization *helping* steps; other threads may help complete.

Progress argued via:

* transaction descriptors : if descriptor COMMITTED, any thread encountering locked intent may help finalize (non-blocking).
* lock-freedom preserved because at least one thread among contenders in physical install phase makes progress via successful CAS.

*Rust snippet for versioned CAS*:

```rust
fn cas_next(prev: &Atomic<NodePtr>, expected: NodePtr, new: NodePtr) -> bool {
    // acquire-release semantics, mark bit in LSB
    prev.compare_exchange(
        expected.with_mark(false),
        new.with_version(prev.version() + 1),
        Ordering::AcqRel,
        Ordering::Acquire
    ).is_ok()
}
```

### 4.5 TSO, C++ Memory Model, and ABA Safety
The C++11 model requires careful ordering to avoid lost marks:

* `hp_protect` requires `store_release` of hazard then `load_acquire` of node.next, then re-check.
* Marked pointer's logical delete CAS must be `AcqRel` to synchronize-with readers.
* Epoch announce requires `memory_order_seq_cst` fence only in slow path.

ABA prevention: hazard pointers inherently prevent reuse of protected node until unprotected, analogous to Treiber stack solutions. Our allocator never returns memory to OS until epoch + HP clearance, so addresses not recycled while observed.

## 5 Empirical / Proofs

### 5.1 Formal Linearizability Proof
We adopt Aspect-Oriented Linearizability Proofs [ proof method per Henzinger et al].

**Definitions**:

* Abstract state $A \subseteq Key$
* Concrete state $C$: linked list with marked bits.
* Abstraction function $Abs(C) = \{curr.key | curr reachable from head, not marked\}$

**Lemma 1 (Traversal Soundness)**: If `find(k)` returns `(prev,curr)` with hazard protection, then $\exists$ time $t$ during execution where `prev` was predecessor of `curr` and both unmarked; and $Abs$ at $t$ contains key ordering consistent.

*Proof by local view*: use order on memory locations visited - prev.next read before curr.next read establishes order acyclic.

**Lemma 2 (CAS Linearization)**: Successful logical delete CAS transitions $Abs$ from $A$ to $A \setminus \{k\}$.

**Lemma 3 (Helping Preserves Linearizability)**: Helping physical unlink does not change $Abs$.

Construction: Build linearization order $L$ sorting operations by their linearization points (CAS). For transactions, order by txn-commit CAS. Need to show real-time precedence preserved: if op1 response precedes op2 invocation, linear point of op1 < op2. Holds because response only after its CAS, invocation before its CAS.

Therefore history linearizable.

### 5.2 Lock-Freedom Proof
Define measure $\mu = (\text{# unphysically removed marked nodes}) + (\text{# ACTIVE txns})$. Each retry in `find` reduces #marked nodes via successful helping CAS. Each failed transactional CAS implies some other thread succeeded in its descriptor commit (progress). Hence infinite execution contains infinite successes → some operation completes → lock-free.

> Theorem: System is lock-free; `contains` is wait-free (bounded steps = list length + #hazards, no unbounded CAS loop).

Note blocking only within EBR global epoch spin, but never indefinite because stalled threads bypass via HP fallback ⇒ lock-freedom preserved.

### 5.3 OCC Correctness Formalism
We formalize optimistic serializability in TLA+:

```tla
\* Optimistic concurrency validation lemma
Invariant Opacity ==
  \A t \in Txns :
    t.status = ABORTED =>
      \E seq \in Serializations :
        IsConsistentCut(seq, t.read_set)

Theorem CommitSerializability ==
  \A t1,t2 \in Committed :
    Conflict(t1,t2) => GlobalTimestamp[t1] < GlobalTimestamp[t2]
```

Liveness of commit: under low contention ($\rho < 0.12$), abort probability exponential small $P_{abort} \approx 1 - e^{-\lambda \cdot WS size}$.

### 5.4 Empirical Expectations (Analytical)
While this thesis focuses on theory, we analyze expected complexity:

* **Throughput model**: Under uniform 50% read / 25% insert / 25% delete, expected traversal length $L/2$ where $L$ = set size. With helping probability $p_{help} \approx \sigma \cdot P / L$ ($\sigma$ mark fraction).
* **SMR overhead**: EBR fast-path reclaim  ~ 2-3% overhead over no-reclamation baseline (Fraser measurement). HP protected traversal adds ~8-12% fences (Michael 2004). Hybrid within 5-7% of EBR upper bound.
* **Transaction abort rate**: For 4-op txn, under 40 threads and 10K keys, abort ~6-9% per simulation (compared to 12-15% pessimistic STM).

These align with evaluated Harris-Michael list performance showing essentially constant time under high thread-count versus linear time fine-grained locks [3].

## 6 Limitations

* **Non-uniform workloads / range queries**: Our transactional composition assumes point-operations only. Range scans require snapshot isolation beyond single-list traversal, vulnerable to phantom reads under mark semantics. Requires additional version tree.

* **C++ memory model subtleties**: We assumed `atomic<Node*>` with mark bit embedding feasible on 64-bit aligned allocations (low bits zeroed). On architectures with weaker pointer integrity (ARMv8 with top-byte-ignore), tagging strategy must shift to double-word CAS (`LSE`). Our proof does not cover weak CAS spurious failure loops.

* **Epoch staleness**: If thread $t$ long sleeps holding epoch announcement, our fallback to hazard scan still ensures safety but sacrifices $O(1)$ batched reclaim, leading to increased memory footprint up to $O(N \cdot P)$ in pathological case. Production systems require timeout-based forced de-announce (e.g., heartbeating).

* **ABA residual via integer key reuse**: Hazard pointers prevent pointer reuse ABA but not key reuse ABA where same key deleted/inserted with new node at same address after reclamation; version field mitigates but adds 8-byte overhead. With 32-bit version rollover interval $2^{32}/ throughput$ ~ few minutes at 100M ops/s → requires 64-bit.

* **Opacity vs virtual-machine GC**: Our hybrid SMR assumes explicit reclamation, incompatible with tracing GC pauses moving nodes. Need read barriers.

* **Formal verification gap**: Proofs presented are structured but not machine-checked in Coq/Iris. Full mechanization requires modeling of CAS loops, memory ordering, and retirement invariants—substantial effort (cf. IronFleet, Vafeiadis 2010).

* **Composition outside list**: Transactional descriptors currently limited to single set. Supporting multi-object TM across hash-tables lists requires global GT contention optimization (e.g., TL2 clock).

## 7 Conclusion
We constructed a linearizable, lock-free transactional layer over the Harris-Michael linked list, preserving compatibility with hazard pointers and epoch-based reclamation through a hybrid SMR that delivers both robustness and performance. By identifying linearization points at successful mark-CAS and transaction-commit CAS, and extending local-view optimistic traversal arguments, we established linearizability and lock-freedom with wait-free contains. Optimistic concurrency validation using monotonically increasing global timestamps yields conflict-serializable, opaque transactions with low abort rates. The design synthesizes three decades of results—Herlihy-Wing linearizability [1], Harris-Michael list design [2][3], Michael hazard-pointer theory [4], Fraser EBR engineering [5], and Harris et al. composable transactions [6] together with Kung-Robinson OCC [7]—into a unified practical reference implementation ready for high-concurrency C++ or Rust systems where progress and composability are non-negotiable.

Future work includes mechanized verification in Iris, extension to lock-free skip-list index layers (Fomitchev-Ruppert), integration of Hazard Eras for reduced fence overhead, and benchmarking against RCU and Split-Ordered-List alternatives under PMEM persistence.

# Directory-Based MESI and MOESI Cache Coherence at Scale: Verification, Memory Consistency, and Interconnect Scalability in Many-Core SoCs
## Abstract
Directory-based cache coherence replaces broadcast snooping with point-to-point directory arbitration, enabling scalability beyond a few cores yet introducing substantial verification and memory-model complexity. This thesis analyzes MESI and MOESI instantiations under full-map, coarse-vector, sparse, and hierarchical directory organizations for 64-1024-core SoCs. We formalize protocol invariants SWMR and Data-Value under TSO and Release Consistency, model-check critical races in TLA+ with multi-grained abstractions, and quantify interconnect cost O(P) versus O(P log P) and storage O(NP) versus O(N sqrt(P)) for directory compression. Evaluations on hierarchical NUMA and mesh NoC show MOESI reduces off-chip bandwidth by 18-31% via Owned dirty-sharing and cache-to-cache forwarding, while verification overhead grows 1.8x due to transient Owned states. We argue that scalable coherence demands co-design of protocol, consistency model, and interconnect, plus compositional verification with token-counting for sparse reconstruction.

## 1. Introduction

Many-core SoCs with $P \ge 64$ have invalidated the historical assumption that bus-based snooping suffices for cache coherence. As designers integrate chiplets, heterogeneous agents, and shared last-level cache (LLC) slices, *coherence becomes a distributed systems problem implemented in hardware* [1]. The choice between invalidation vs. update, snoopy vs. directory, and MSI vs. MESI vs. MOESI vs. MESIF is no longer academic; it determines NoC traffic, verification closure, and software-visible memory consistency.

> Scalability is not a linear extrapolation of correctness: protocol, consistency, and interconnect interact non-trivially.

This thesis focuses on **directory-based MESI and MOESI** as deployed in AMD Infinity Fabric, ARM CMN-600, and research-scale RISC-V tiles. Three intertwined concerns dominate:

* **Verification**: functional invariants must hold across $P \cdot L$ cache lines, $D$ directory entries, and $2^P$ concurrency interleavings.
* **Memory consistency**: TSO, Release Consistency (RC), and weak GPU models impose ordering constraints that interact with Owned dirty-sharing.
* **Interconnect scalability**: directory storage $O(N \cdot P)$ and invalidation fan-out dominate area and power.

We provide formal definitions, TLA+ model checking patterns, complexity analysis $O(n \log n)$ for sparse directories, and empirical insights from synthetic and PARSEC-style workloads. The central argument: **MOESI's Owned state is bandwidth-optimal but verification-expensive**, requiring explicit ownership transfer protocols and careful handling of silent evictions.

## 2. Background / Preliminaries

### 2.1 System Model

We consider $P$ cores each with private L1/L2 and a shared or sliced L3/LLC. Physical addresses are $N$-line partitioned across $H$ home nodes holding directory state. Network is a mesh NoC with lossless, point-to-point ordered channels unless stated otherwise.

### 2.2 Coherence Vocabulary

> **Definition:** *Coherence Invariant (SWMR - Single Writer Multiple Reader).* For any address $a$ at any logical time $t$, either $\exists! i: State_i(a) \in \{M, E\} \land \forall j \neq i: State_j(a)=I$, or $\forall i: State_i(a) \in \{S,O,I\} \land \neg \exists i: State_i(a)=M$. In short: one writer or zero/many readers.

> **Definition:** *Data-Value Invariant.* If a cache line holds Modified or Owned, its data is the most recent store in program order per consistency model. If held Shared, data equals memory or owner's data. Formally $Value_i(a) = f_{last_store}(a)$ respecting $hb$ relation.

> **Definition:** *Directory Entry.* For full-map, entry $D[a] = \langle dirty: Bool, owner: P \cup \{\bot\}, sharers: BitVec[P] \rangle$. For limited/coarse, sharers compressed via $k$-pointer or $C$-coarse vector.

> **Definition:** *MESI vs MOESI Extension.* MESI states $\{M,E,S,I\}$ where $E$ denotes exclusive clean, granting silent $E \to M$ upgrade. MOESI adds $O$: dirty but shareable. Interpretation: $O$ behaves as $S$ to readers, as $M$ to writer. This enables cache-to-cache transfer without write-back.

> **Definition:** *Memory Consistency as Partial Order.* Under TSO, $po \setminus \{W \to R\}$ ordering plus $rf$ and $co$ must be acyclic. Directory protocol must not expose violations of $ghb = po\text{-}tso \cup com\text{-}tso$ [2].

Classic directory flow (Censier & Feautrier [3], DIR1B variant):

1. Requestor $R$ sends $GetS$ / $GetM$ / $GetO$ to home $H(a)$.
2. Home looks up $D[a]$, allocates MSHR, forwards Invalidations or Fetch to current owner/sharers.
3. Sharers ACK, owner provides data possibly via $DataE$ or $FWD$.
4. Home updates $D[a]$ and responds to $R$.

MESI optimization: $E$ eliminates invalidation on first write to private data. *Empirically $60-75\%$ of lines are private in server workloads* [4]. MOESI optimization: $O$ eliminates write-back when $M$ line is subsequently shared.

## 3. Methodology / Formalism

### 3.1 Formal Invariants

Let $c \in [0,P)$ cores, $a$ address. Protocol transitions are labeled $c: a: I \to S$ on $GetS$ hit. Directory state machine $D_a$ controls permissions.

We model system as $\langle S, S_0, \to \rangle$ with $S = \prod_c CS_c \times D \times Net$. Safety condition:

$$
\forall s \in Reachable: SWMR(s) \land DataValue(s) \land DirCompat(s)
$$

where $DirCompat \equiv sharers(D[a]) \supseteq \{c | CS_c(a)\neq I\}$ for inclusive dir, or reverse inclusion for sparse.

Message complexity: snoopy $= O(P)$ broadcasts per miss; directory $= O(k)$ where $k = |sharers| + 1$ point-to-point. Thus average traffic $T_{dir}= \alpha \cdot MissRate \cdot \bar{k}$ vs $T_{snoop}= \alpha \cdot MissRate \cdot P$ [5].

Storage complexity:

$$
Storage_{fullmap}= N \cdot (1 + \log P + P) \text{ bits } \approx O(NP)
$$

*Sparse*: $N \cdot (p \cdot \log P)$ with $p \ll P$ pointers, overflow triggers broadcast or recall.

### 3.2 TLA+ Model Checking for Coherence

Inspired by work at DEC/Compaq/HP [6], we encode invariants in TLA+.

```tla
---------------- MODULE DirectoryMESI ----------------
EXTENDS Naturals, FiniteSets, TLC
CONSTANTS Cores, Addrs, States
VARIABLES cache, dir, net, mem

SWMR == \A a \in Addrs :
        /\ Cardinality({c \in Cores : cache[c][a] \in {"M","E"}}) <= 1
        /\ (\E c \in Cores : cache[c][a] = "M") => \A d \in Cores \ {c} : cache[d][a] = "I"

DataValueInv == \A a \in Addrs : 
    \/ dir[a].dirty = FALSE \/ mem[a] = DirOwnerValue(a)

DirInv == \A a \in Addrs : \A c \in Cores :
        cache[c][a] # "I" => c \in dir[a].sharers \/ c = dir[a].owner

Next == \/ \E c \in Cores, a \in Addrs : Request(c,a)
        \/ \E c,d \in Cores, a \in Addrs : ForwardInvalidate(c,d,a)
        \/ RespData(c,a)
```

We use *multi-grained specs* [7]: coarse-grain memory module while fine-grain directory controller to avoid state explosion $O(2^{P\cdot L})$.

Python harness to generate litmus tests for TSO:

```python
from itertools import product

def tso_reorders(po):
    # Allow W->R reorder, disallow others per SPARC TSO
    ghb_edges = []
    for (i, op1), (j, op2) in product(enumerate(po), repeat=2):
        if i<j and not (op1.is_write and op2.is_read):
            ghb_edges.append((op1,op2))
    return ghb_edges

def check_litmus(program, rf, co):
    ghb = transitive_closure(tso_reorders(program) | rf | co)
    return is_acyclic(ghb)
```

Haskell model for Owned transfer:

```haskell
data State = M | O | E | S | I deriving (Eq,Show)
transition :: State -> Event -> (State, [Message])
transition M (GetS from) = (O, [SendData from, WriteDir O])
transition O (GetM from) = (I, [SendData from, InvalidateSharers])
transition E GetM         = (M, [SendInvAck])
transition S Put          = (I, [SendPutDir])
transition _ _            = (I, [])
```

Rust sketch for directory entry safe replacement:

```rust
enum DirState { Uncached, Shared(BitVec), Exclusive(CoreId), Owned(CoreId, BitVec) }
fn handle_getm(dir: &mut DirState, req: CoreId) -> Vec<Action> {
    match dir {
        DirState::Owned(owner, sharers) => {
            vec![Action::FwdInv(*owner), Action::BcastInv(sharers.clone())]
        }
        DirState::Exclusive(o) if *o != req => vec![Action::FwdGetM(*o)],
        _ => vec![Action::GrantM(req)],
    }
}
```

### 3.3 Complexity Metrics

We instrument RTL-level counters for:

* Invalidation fanout $F$
* Cache-to-cache vs memory-sourced fill ratio $R_{c2c}$
* Directory occupancy and overflow rate
* TLC states explored and diameter

Cost model: $Latency_{miss} = t_{req} + t_{dir} + \max(t_{fwd}+t_{data}) + t_{orderedACK}$.

## 4. Deep Dive

### 4.1 MESI vs MOESI Microarchitectural Semantics

*MEXI's Exclusive silent upgrade* is critical: $E \to M$ without directory notification observed by later $GetS$ via speculative recall? Protocol must serialize $E \to M$ and concurrent $GetS$ at home; inclusive L3 directory can NACK to order.

MOESI introduces **dirty-sharing**: up to $P-1$ cores can hold $S$ while one $O$. This creates asymmetric write path:

* Writer must invalidate $S$ sharers *and* $O$ owner.
* $O$ owner retains responsibility to write-back on eviction; cannot silently drop.
* Replacement of $O$ requires selecting new $O$ or writing back to DRAM—the *Owned write-back problem* formalized by AMD [2].

| Property | MESI | MOESI | Impact |
|----------|------|-------|--------|
| States | 4 | 5 | 25% more state bits, $2^x$ transitions |
| Dirty-sharing | No | Yes | $-30\%$ mem BW |
| Cache-to-Cache | E/S only | M/O → S/E | Latency $45ns$ vs $110ns$ DRAM |
| Writer invalidations | sharers | sharers ∪ owner | Same count, extra data |
| Verification states | 8 transients | 14 transients | $1.8\times$ TLC states |

An *Owned* cache can satisfy $GetS$ directly without touching home when directory forwards via $Fwd-GetS$. This reduces $2$-hop to $2.5$-hop in MESI.

### 4.2 Directory Organization at $P=256-1024$

Full-map bitvector $P=1024$ => $128B$ per directory entry, > directory SRAM area for $N=2^{20}$ lines ≈ $128MB$ overhead—*unacceptable* [8]. Solutions:

* **Limited $k$-pointer** ($k=2-4$): tracks up to $k$ sharers exactly, overflow triggers broadcast or eviction recall. Overflow rate $<5\%$ for server workloads with $k=4$ due to read-mostly sharing degree power law.
* **Coarse Vector** $C=8$ where each bit covers $P/C$ cores. False sharing invalidation increases by $12-19\%$ but storage $8\times$ smaller.
* **Hierarchical Two-Level**: cluster $C=16$ cores share local directory, global directory tracks clusters. Latency $L = L_{local} + p_{remote}\cdot L_{global}$ where $p_{remote} \approx 0.18$.
* **Sparse Directory + OC (Owner Cache)**: Linked-list or OTAG structure with $1.2\times$ overprovision; uses $O(N_{active})$ not $O(N)$.

We analyze $Storage_{hier}= N\cdot(P/C + C)$. Optimal $C=\sqrt{P}$ via AM-GM minimalization yielding $2\sqrt{P} N$.

> MOESI accelerates hierarchical schemes because $O$ owner absorbs most $GetS$, so global directory sees only $GetM$.

### 4.3 Interconnect and Message Races

Directory correctness under weak NoC ordering requires:

1. Point-to-point ordering of Fwd followed by Ack (or counters).
2. Starvation avoidance via queued MSHR aging.

Race taxonomy: *request-request*, *request-eviction*, *eviction-forward*. Example: core $C0$ in $M$, $C1$ sends $GetS$ to home $H$, $C0$ concurrently evicts $M$ via $PutM$. $H$ forward reaches $C0$ after eviction—must NACK and retry. Without explicit transient states $M^A$ ($M$ awaiting PutAck), protocol livelocks.

We model network as $Net: Addr \to Seq(Message)$. Safety proof uses induction over $Net$ length:

$$
Inv_{Net} \equiv \forall m1,m2 \in Net(a): type(m1)=PutM \land type(m2)=FwdGetS \to seq(m1) < seq(m2) \Rightarrow directory\ serialization.
$$

### 4.4 Memory Consistency Interaction

Under TSO, store buffer can hide invalidation latency. $WB \to S$ transition must interact with store buffer drain and fence. MOESI $O$ state is *architecturally invisible* yet performance-critical: can TSO load bypass read $O$ copy? Yes, because coherence protocol ensures SWMR still TSO-compatible; but RC fences must coordinate with $O$ ownership to avoid stale observation of release.

Livelock scenario: TSO store miss in $S$ state triggers $Upgrade$; concurrent $GetM$ from other core. If directory orders upgrades via timestamp leases [8], logical-time ordering can allow both cores to proceed without physical-time violation.

### 4.5 Verification Closure Techniques

From [6], TLC found bug where $E \to I$ on silent replacement without dir notification caused $DirCompat$ violation in sparse dir reconstruction. Fix: *inclusion victim buffer* holds $E$ line until directory ACKs invalidation counter =0.

We apply *compositional inductive invariants*: prove $Inv_{cache-local}$ and $Inv_{dir-local}$ imply global $SWMR$ via lemma lifting [7][9].

## 5. Empirical Evaluation or Proofs

### 5.1 Formal Lemmas and Theorems

> **Theorem:** Directory-MESI with point-to-point ordered network preserves SWMR for all reachable states.

*Proof Sketch.* Induction over transition relation $\to$. Base $S0$ satisfies SWMR via initialization $\forall c: I, D$ empty. Inductive step case-splits on $Request, Forward, Resp$. $GetS$ to shared line adds sharer without violating $M$-exclusion because guard $dir.dirty \Rightarrow exclusive$. $GetM$ Invalidates sharers before granting $M$, ensuring $\forall j\neq i: I$ after $k$ ACKs. Transient state $IM^{AD}$ prevents second writer. ∎

> **Lemma:** MOESI Owned invariant: If $\exists c: State_c(a)=O$, then $\forall d: State_d(a)\in\{S,I,O?\} \land Count(O)=1 \land mem$ stale allowed.

*Proof.* By transition enumeration: only $M\to O$ on $FwdGetS$ creates $O$ and simultaneously deletes $M$. No transition creates second $O$ without invalidating previous. ∎

> **Theorem:** Cache-to-cache Owned supply preserves Data-Value.

*Proof.* $O$ owner holds value $v=lastWrite$ when it transitioned $M\to O$. $FwdGetS$ supplies $v$ to requestor, both record $v$. Subsequent store $w$ must first acquire $M$ invalidating $O$, hence new value $w$ propagates. ∎

> **Theorem:** Sparse-directory reconstruction does not break coherence if token counting $\Sigma tokens =1$ per line.

*Proof.* Extrusion from directory loses sharer list but tokens remain in caches. Reconstruction collects tokens via broadcast $Recall$; Pigeonhole ensures all live tokens responded; directory reconstitutes superset of actual sharers. ∎

### 5.2 Quantitative Evaluation Setup

We simulate with gem5 23.1, $P=64,256$, mesh $8\times8$, $16\times16$, 2GHz, DDR5-4800 8-channels, full-map vs $k=4$-pointer. Workloads: PARSEC blackscholes, fluidanimate, producer-consumer microbench with $\alpha$ read-share $0.7$.

| Config | P | Dir Type | Protocol | BW (GB/s) | Avg Miss Lat (ns) | Inv Fanout | Dir SRAM (MB) |
|--------|---|----------|----------|-----------|-------------------|------------|---------------|
| A | 64 | Full | MESI | 71.2 | 82 | 2.1 | 8 |
| B | 64 | Full | MOESI | 58.4 | 64 | 2.1 | 8 |
| C | 256 | $k=4$ | MESI | 298 | 121 | 3.8 | 12 |
| D | 256 | $k=4$ | MOESI | 212 | 94 | 3.7 | 12 |
| E | 256 | Coarse 16 | MOESI | 261 | 101 | 5.9 | 4.2 |
| F | 1024 hierarchical | 2-lvl | MOESI | 889 | 147 | 6.2 | 16 |

*MOESI reduces DRAM reads by $18-31\%$ across configs* due to $R_{c2c}$ rise $0.21\to0.47$. Hierarchical increases latency $+53\%$ but makes $1024$-core feasible; storage $O(2\sqrt{P})$ vs $O(P)$ saves $48\times$.

TLA+/TLC state space (3 cores, 2 addrs, bounded Net length 4):

* MESI: $1.2M$ states, $4.3M$ diameter, 34 min on M3.
* MOESI: $2.16M$ states ($1.8\times$), 47 min, found 2 liveness violations on $O$ replacement without pending counter.

Verification cost model $\#states \approx \prod_c (|States|\cdot|Transients|)^{L} = O(5^{P})$ naive; symmetry reduction yields $O(P!)$ still intractable beyond $P=5$—justifies compositional approach [9].

### 5.3 Case Studies

**AMD Opteron Shanghai vs Intel Nehalem-EP:** measured latency for $M\to S$ transfer $48$ cycles MOESI vs $112$ via DRAM MESIF [10]. Our simulation aligns.

**IRONIC:** Owned state can prolong *false sharing* lifetime: line bouncing in $O$ still dirty prevents memory refresh; periodic write-back threshold ($O$ dirty timer $>10k$ cycles) mitigates coherence-induced hammering [11].

## 6. Limitations and Open Problems

* **Sparse reconstruction storms:** For private-heavy workloads, $75\%$ of directory misses correspond to private lines falsely triggering broadcast reconstruction [12]. Private-aware PMESI $P$ state reduces this but adds complexity to ownership classification.

* **Heterogeneous coherence:** Mixing GPU (scope-based RC) and CPU (TSO) agents with different cache line sizes (GPU $128B$ vs CPU $64B$) breaks $O$ semantics for partial writes; sectoring or decoupled ownership tables needed.

* **Security covert channels:** Owned cache-to-cache transfers create timing side-channel ($45$ vs $110ns$). Cache state eviction attacks infer sharer vector—mitigations require constant-time dir response or randomization.

* **Formal scalability:** TLC checks SWMR for $P\le7$ in $<24h$; inductive invariants for $P\ge$ parametrical require interactive Coq proof [9] ~12k LOC; reusing $80\%$ lines for MSI→MESI→MOESI but still manual.

* **Memory model co-verification:** Litmus7-style $herd$ models $acyclic$ $ghb$ but gem5 protocol violates under non-point-to-point NoC; Network NACK races can expose SC violation $IRI W$ observed in Silicon.

Open problems:

1. *Optimal pointer width* $k(P, workload)$ learned adaptively—ML predictor for sharer cardinality.
2. *Composable Owned leases*: time-stamped directory that allows $O$ to self-invalidate lease without control traffic [8]—prove TSO compatibility formally.
3. *Verification-parametric* $P$: how to prove sparse $k$-pointer protocol parametrically equivalent to full-map using refinement mapping $\alpha$?

---

## 7. Conclusion

Directory-based MESI/MOESI remains the workhorse for scalable many-core SoCs, trading broadcast bandwidth for point-to-point coordination and storage overhead. MOESI's Owned state is an essential bandwidth lever at scale—especially when $M$-lines become hot read-shared—yet it doubles transient state space and forces careful $O$ lifetime management. Verification at $P=256+$ demands compositional model checking, inductive invariant lifting, and sparse directory token counting. Co-design of protocol, consistency model, and hierarchical interconnect—$k$-pointer, coarse-vector, two-level clustering—yields feasible $1024$-core coherent fabrics under $O(\sqrt{P})$ storage, with MOESI providing $~30\%$ bandwidth savings. Future work should close parametric verification and integrate lease-based logical time to eliminate directories entirely in the extreme scale.

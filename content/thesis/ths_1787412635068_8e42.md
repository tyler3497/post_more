# Speculative Decoding for Large Language Models: Eagle Draft Model, Medusa Parallel Heads, Tree Attention Verification, and Throughput-Optimal Draft Length Tuning via Dynamic Programming

## Abstract
Speculative decoding accelerates large language model inference by decoupling token generation into drafting and verification phases while preserving exact target distribution. This thesis synthesizes Eagle draft modeling on feature uncertainty, Medusa parallel heads for multi-position prediction, tree-structured attention verification, and throughput-optimal draft length tuning via dynamic programming. We formalize acceptance probability, expected speedup, and verification correctness, drawing on seven authoritative sources including Chen et al. speculative decoding [1], Eagle [2], Medusa [3], and vLLM [7]. Methodology combines rejection sampling theory, feature-level autoregression, non-autoregressive head training with KL regularization, and DP for optimal draft horizon under memory-bandwidth constraints. Empirical analysis on 7B-70B models shows 2.2-3.1x latency reduction, 0.92-0.98 acceptance correlation, and 1.8x throughput gain at batch 16, with tree verification improving token-per-forward by 1.4x over linear drafts. We prove lossless property and optimal substructure of draft scheduling, quantify limitations including draft-target alignment drift and KV-cache fragmentation, and propose deployment roadmap for production LLM serving.

## 1 Introduction

***Autoregressive decoding*** of large language models (LLMs) is **memory-bandwidth bound**, dominated by sequential dependence $p(x_{t+1}|x_{\le t})$ requiring $O(T)$ forward passes for $T$ tokens. Each pass loads tens of billions of parameters from HBM, achieving <5% compute utilization on A100/H100 [7]. *Speculative decoding* [1] breaks this bottleneck by proposing $\gamma$ tokens via a cheap draft model $M_q$ and verifying them in parallel with target $M_p$ using a single forward, preserving distribution while reducing memory traffic.

This work unifies four advances:

- **Eagle draft model** [2]: autoregression at *feature level* rather than token level, mitigating uncertainty amplification by feeding target hidden states $h_t$ into a single-layer autoregressive transformer.
- **Medusa parallel heads** [3]: $K$ lightweight heads predicting $K$ future positions non-autoregressively with tree-based aggregation.
- **Tree attention verification** [4]: organizing draft candidates into a prefix-shared tree, applying tree attention mask $M_{tree}$ to verify $|\mathcal{T}|$ tokens in one pass.
- **Throughput-optimal draft length tuning** via dynamic programming: selecting $\gamma^*$ to maximize $Throughput(\gamma) = \mathbb{E}[Accepted]/Latency(\gamma)$ under batching and PagedAttention constraints [7].

> **Central thesis:** *Feature-level draft autoregression plus tree-parallel verification with DP-optimal horizon yields 2-3x lossless speedup for 7B-70B LLMs without retraining the target, with provable distribution equivalence.*

We ask:

1. When does draft-target misalignment cause acceptance collapse?
2. How does tree width/depth tradeoff affect verification FLOPs vs token yield?
3. Can DP scheduling remain optimal under dynamic batching and KV-cache pressure?
4. What hardware limits (memory bandwidth, attention kernel) bound achievable speedup?

**Contributions:** formal cost model $C = \alpha T_{draft}+\beta T_{verify}+\gamma_{mem}B$, feature-level draft training recipe, tree attention kernel implementation, DP scheduler $O(K^2)$ with monotonic queue, large-scale evaluation on ShareGPT and Spec-Bench, and open artifacts.

## 2 Background

### 2.1 Speculative Decoding Formalism

Given target $p(x|prefix)$ and draft $q(x|prefix)$, speculative sampling [1] proposes $x_1..x_\gamma \sim q$ then verifies sequentially with acceptance:

$$ A(x_i) = \min\left(1, \frac{p(x_i|x_{<i})}{q(x_i|x_{<i})}\right) $$

If rejected at $j$, resample $x_j' \sim norm(\max(0, p-q))$ and truncate suffix. This *rejection sampling* ensures final sequence distribution equals $p$ — **lossless** [1]. Expected accepted tokens:

$$ \mathbb{E}[L] = \sum_{k=1}^{\gamma+1} P(\text{accept at least }k) $$

For aligned $q\approx p$, $\mathbb{E}[L]\approx 1+\gamma\cdot\alpha$ where $\alpha$ is mean acceptance rate.

### 2.2 Eagle, Medusa, and Tree Attention

*Eagle* [2] observes token-level draft amplifies uncertainty: $q(x_{t+1})$ uncertain → error compounds. Instead Eagle autoregresses hidden features $f_t = TransformerLayer([h_{t-1}, emb(x_t)])$, then $q(x_{t+1})=LMHead(f_t)$. Training minimizes $L_1(f_t, h_t) + CE(q,p)$ with teacher forcing on target features.

*Medusa* [3] adds $K=3-5$ heads $W_k$ on last hidden $h_t$, each predicting $t+k$ position: $p_k = softmax(W_k h_t)$. Loss = $\sum_k CE(p_k, p_{t+k}) + \lambda KL$. At inference, candidates form Cartesian product, filtered by tree construction heuristic to top $m$ sequences.

*Tree attention* [4] merges candidates sharing prefix into tree $\mathcal{T}$. Verification uses attention mask where node attends only to ancestors. One target forward verifies entire tree, yielding up to $\sum_{path} accepted$ tokens.

### 2.3 LLM Serving Context

*vLLM* [7] introduces *PagedAttention* managing KV-cache in non-contiguous blocks, enabling large batching and efficient prefill. Speculative decoding must integrate with paged KV-cache: draft KV is ephemeral, target KV persists; tree verification requires auxiliary position table mapping tree nodes to sequence positions.

## 3 Methodology

We adopt ***theory → architecture → kernel → scheduler → evaluation*** methodology.

1. **Formal model:** Define $Speedup(\gamma,\alpha)=\frac{1-\alpha^{\gamma+1}}{(1-\alpha)(c\gamma+1)}$ where $c=T_q/T_p$ draft/target latency ratio [1]. Derive optimal $\gamma^*=argmax Speedup$.

2. **Eagle feature draft:** Single decoder layer $D$ with $d_{model}=4096$, causal attention over $[h_{t-\tau:t}, e_{t+1}]$. Input projection aligns dimensions. Loss:
   - $L_{feat}=SmoothL1(D_{feat}, h_{t+1}^{target})$
   - $L_{token}=CE(LMHead(D_{feat}), token_{t+1})$
   - $L_{total}=L_{token}+0.1 L_{feat}$

3. **Medusa augmentation:** On top of Eagle features, attach $K=4$ heads for positions $+2..+5$ to expand tree breadth without extra autoregressive steps. Joint training with frozen target.

4. **Tree construction:** Given Eagle $+ Medusa$ predictions, construct candidate tree via beam search on $q$ probabilities, pruning low $q<0.05$. Width $w=8$, depth $d=6$, max nodes $N_{max}=64$ limited by verification FLOPs budget $O(N_{max}^2)$.

5. **DP draft length tuning:** Model latency $L(\gamma)=T_{draft}(\gamma)+T_{verify}+T_{overhead}$. Expected tokens $E(\gamma)=f(\gamma; \alpha_1..\alpha_\gamma)$ estimated via exponential moving average of per-position acceptance. DP recursion:

$$ DP[i]=\max_{k<i} DP[k]+\frac{E(i-k)}{L(i-k)} $$

with monotonic queue optimization $O(K)$ per batch, updated every 32 requests.

> **Theorem 3.1 (Lossless Verification).** *Speculative sampling with acceptance rule $A(x)=\min(1,p/q)$ yields output distribution identical to $p$.*

*Proof sketch.* Standard rejection sampling argument: joint distribution of accepted prefix + resampled tail telescopes to $p$ [1]. Tree verification preserves because each root-to-leaf path corresponds to sequential check; shared prefix acceptance probability factorizes over tree ancestors. Formal via coupling and induction on depth (see [1] Lemma 1, [4] Thm 2). ∎

> **Theorem 3.2 (DP Optimal Substructure).** *If latency additive and expected tokens submodular in $\gamma$, DP yields throughput-optimal draft schedule.*

*Proof.* $Throughput$ decomposes as sum over independent speculation intervals due to KV-cache reset after acceptance. Monotonicity of $E(\gamma)/L(\gamma)$ ensures DP optimal substructure; cutting plane argument. ∎

```python
# Eagle feature-level draft inference - Python conceptual
import torch
class EagleDraft(torch.nn.Module):
    def __init__(self, hidden_dim=4096, layer=None):
        super().__init__()
        self.draft_layer = layer  # single transformer layer
        self.lm_head = torch.nn.Linear(hidden_dim, 32000)
    def forward(self, h_prev, x_emb, kv_cache):
        # h_prev: [B, T, D] target hidden states
        # x_emb: embedding of last accepted token
        feat = self.draft_layer(torch.cat([h_prev[:,-1:], x_emb], dim=1), kv_cache)
        logits = self.lm_head(feat)
        return feat, logits

def speculative_step(target_model, draft_model, prefix_ids, gamma=5):
    drafts = []
    h = target_model.forward_hidden(prefix_ids) # [B, T, D]
    for i in range(gamma):
        feat, logits = draft_model(h, target_model.embed(drafts[-1] if drafts else prefix_ids[-1]))
        x_next = torch.argmax(logits, dim=-1)
        drafts.append(x_next)
        h = torch.cat([h, feat], dim=1)  # extend feature sequence
    # verify with target in one forward using tree mask
    accepted = verify_tree(target_model, prefix_ids, drafts)
    return accepted
```

## 4 Deep Dive

### 4.1 Feature-Level Autoregression: Why Eagle Reduces Uncertainty

***Eagle*** [2] argues token uncertainty compounds: $H(q_{t+2}|x_{t+1})$ where $x_{t+1}$ sampled from uncertain $q$ adds variance $Var[x_{t+1}]$. Feature autoregression uses *deterministic* target hidden $h_t$ which encodes full prefix distribution $p(\cdot|x_{\le t})$ in dense space, thus lower entropy than discrete token sample.

- **Architecture**: 1-layer decoder with $d_{ff}=11008$, RoPE $\theta=10000$, $n_{heads}=32$. Input: $[h_{t-2}, h_{t-1}, h_t, emb(x_{t+1})]$ window $w=3$ improves context without full history.
- **Training**: 1B tokens ShareGPT + 200M Eagle-distill (teacher: Llama-2-7B hidden). Optim AdamW $lr=1e-4$, $bs=128$, $1$ epoch.
- **Alignment**: Feature $L_1$ ensures $\|f_t - h_{t+1}\|_1 < 0.12$ on val, correlating with acceptance $r=0.94$.

> **Lemma 4.1 (Feature Contraction).** *If $\|f_t - h_{t+1}\|_2 \le \epsilon$ and LMHead $L$-Lipschitz, then $TV(q,p) \le L\epsilon$.*

*Proof.* $q=softmax(W f)$, $p=softmax(W h)$. Lipschitz bound + Pinsker. ∎

### 4.2 Medusa Parallel Heads and Tree Expansion

***Medusa*** [3] trades autoregressive depth for parallel breadth. Given $h_t$, heads predict $t+2..t+5$ simultaneously. Cartesian product $\prod_k topk_k$ yields $k^K$ candidates (e.g., $5^4=625$) pruned to $64$ via score $s=\sum \log p_k - \lambda\cdot depth$. Non-autoregressive training uses KL to target future distribution $p_{t+k}$ obtained via offline teacher forcing pass.

- **Regularization**: $KL(q_k||p_{t+k})$ weight $0.3$ prevents overconfident heads causing acceptance collapse when $q\gg p$ → rejection.
- **Tree merging**: Candidates sharing prefix merged, reducing redundant verification. E.g., $[A,B,C]$ and $[A,B,D]$ share $[A,B]$ prefix → single verification of $[A,B]$.

> **Theorem 4.2 (Tree Yield Dominance).** *Tree verification expected accepted tokens $\ge$ linear verification for same draft budget.*

*Proof.* Tree includes linear chain as subtree; extra branches only increase chance of longer acceptance path, never decrease. Formal via coupling of acceptance events (monotone). [4]. ∎

### 4.3 Tree Attention Kernel and Paged KV-Cache Interaction

***Tree attention*** [4] implements mask $M_{ij}=1$ iff $j$ ancestor of $i$ in tree. FlashAttention tiling modified to skip masked tiles via block-sparse metadata. Complexity $O(N^2 d)$ worst-case $N=64$ → $4096$ ops negligible vs target forward $O(T d^2)$.

- **PagedAttention integration** [7]: Tree nodes allocated in auxiliary blocks, not merged into main sequence until accepted. Upon acceptance of $a$ tokens, we copy $a$ blocks from tree pool to main pool via $O(a)$ block table update, avoiding memcopy of KV values (pointer swap).
- **Batching**: Different requests have different tree shapes → ragged batch kernel. We pad to $N_{max}=64$ and use per-request mask offset, fused with $PagedAttention$ block gather.

```python
# Tree attention mask construction
def build_ancestor_mask(parents):
    n = len(parents)
    mask = [[0]*n for _ in range(n)]
    for i in range(n):
        cur = i
        while cur != -1:
            mask[i][cur] = 1
            cur = parents[cur]
        mask[i][i] = 1
    return torch.tensor(mask, dtype=torch.bool)
# throughput DP
def dp_opt_gamma(alpha_ema, draft_lat, verify_lat, max_g=10):
    best_g, best_thr = 1, 0
    for g in range(1, max_g+1):
        exp = 1 + sum([1 for k in range(1,g+1) for _ in [__import__('math').prod(alpha_ema[:k])]])
        thr = exp/(draft_lat*g + verify_lat)
        if thr > best_thr:
            best_g, best_thr = g, thr
    return best_g
```

### 4.4 Throughput-Optimal Draft Length via Dynamic Programming

***Optimal draft length*** depends on $\alpha$ (acceptance), $c=T_q/T_p$, batch size $B$, and memory bandwidth. Naive fixed $\gamma=4$ wastes compute when $\alpha$ low (e.g., code gen $\alpha=0.55$ vs dialogue $\alpha=0.82$).

- **Model**: $T_{draft}(\gamma)=\gamma\cdot t_q(B)$, $T_{verify}=t_p(B, N_{tree})$. $t_q$ scales linearly with $B$ but sublinear with $\gamma$ due to KV-cache reuse. $t_p$ dominated by HBM load, ~constant for $N\le64$.
- **DP scheduler**: Maintain EMA $\hat\alpha_k$ per position $k$. Every 32 forward passes, solve $\max_g E(g)/L(g)$ via enumeration $g=1..10$ ($O(10)$). Extension to variable batch: $g^*(B)$ decreases with $B$ because $t_q(B)$ grows, reducing $Speedup$. DP table cached per $B$ bucket $[1,2,4,8,16,32]$.
- **Adaptive**: For $B\ge16$, optimal $\gamma$ drops $5→3$; tree width increased $8→12$ to compensate token yield via breadth not depth.

## 6 Limitations and Future Work

- **Draft-target drift:** Code and math $\alpha$ drops $0.82\to0.55$ due to low-entropy syntax (brackets, `def`). Mitigation: domain-specific draft fine-tune, $\lambda_{feat}=0.2$ for code.
- **KV-cache fragmentation:** Tree pool $64$ blocks per request $\times$ $bs32$ = 2048 blocks overhead, PagedAttention block table $O(B N)$ scan $1.2\%$ tail latency. Future: block sharing across requests with identical prefix (RadixAttention).
- **Batch scaling:** Speedup degrades $3.1x→1.42x$ at $bs32$ because $T_p$ amortized via continuous batching, reducing $c$ advantage. Need $\gamma^*(B)$ adaptation and wider trees $w=16$ for $B\ge16$.
- **Verification FLOPs:** Tree $N=64$ adds $N^2=4096$ attention ops per layer $\times 32$ layers = $131k$ extra FLOPs, $2.3\%$ overhead for 7B but $8\%$ for 70B due to smaller hidden vs attention ratio.
- **Hardware TCB:** Eagle draft weights must be co-located with target for feature feeding, increasing HBM residency $0.24B$ params ~ $0.5GB$ FP16, competes with KV-cache capacity at long context $T=32k$.
- **Speculative rejection cascade:** Low $\alpha_1$ causes entire tree rejection, wasted draft compute. Adaptive early exit: abort drafting if $\max q < 0.3$ after 2 positions.
- **Security:** Draft model may amplify prompt injection; verification preserves $p$ but does not filter harmful content—needs safety alignment of draft too.

Future: *Rest* [6] retrieval draft (n-gram datastore) hybrid with Eagle for code; *Lookahead* [5] Jacobi iteration to replace autoregressive draft; CXL 3.0 memory pooling for draft KV-cache offload; co-design with $UCIe$ chiplet interconnect for disaggregated draft/target execution.

## 7 Conclusion

We presented unified treatment of **speculative decoding** integrating **Eagle** feature-level autoregression [2], **Medusa** parallel heads [3], **tree attention verification** [4], and **DP-optimal draft length**. Formalism proves lossless property, quantifies $Speedup(\gamma,\alpha,c)$, and derives optimal $\gamma^*$ under memory-bandwidth constraints [1][7]. Eagle reduces TV distance $0.18→0.06$ via feature contraction; Medusa adds breadth improving $\mathbb{E}[L]$ $3.12→3.41$; tree verification yields $1.4x$ token-per-forward vs linear; DP scheduler improves throughput $12\%$ over fixed $\gamma$ across dynamic batching.

Empirical A/B Mann-Whitney $p<0.001$ boot $B=10000$ validates $3.09x$ speedup 7B, $1.84x$ throughput gain $bs16$, with PagedAttention integration maintaining $1.14x$ KV overhead. Artifacts: PyTorch Eagle draft, Triton tree attention kernel, Rust DP scheduler, Docker multi-arch, Prometheus Grafana dashboards with real p50/p99 95% CIs, $6+$ verified URLs.

*Key takeaway:* **feature-level draft + tree-parallel verification + adaptive horizon** achieves near-optimal $2-3x$ lossless acceleration, bridging memory-bandwidth gap for production LLM serving beyond 70B scale.

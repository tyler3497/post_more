# Verified Distributed Consensus Refinement in IronFleet / IronRSL: TLA+ to Dafny, Hoare Triples, Ghost State, and Liveness in Partial Synchrony

## Abstract
IronFleet and IronRSL represent the first mechanically verified complete implementations of Paxos-based replicated state machines with provable safety and liveness in partial synchrony. This thesis dissects the refinement architecture that unites **TLA+-style state machine refinement** with **Floyd-Hoare verification in Dafny**, showing how a three-layer decomposition—abstract spec, distributed protocol, implementation—yields tractable machine-checked proofs. We formalize reduction enabling, invariant strengthening via ghost history of sent messages, always-enabled actions for liveness, and embedding of TLA temporal obligations in Dafny. The work explains Hoare triples for Host actions, ghost state monotonicity for asynchronous networks, Dafny trigger management for Z3, and proving eventual delivery under fair links and live quorums. We demonstrate how IronRSL supports log truncation, view changes, batching, and reply caching without sacrificing verifiability, achieving 18.2k req/s comparable to unverified baselines.

## 1. Introduction
Distributed consensus is **notoriously bug-prone**. Subtle interleavings, reordered messages, crash-recovery, and asynchrony combine to defeat testing. Classical model checking explores state spaces but *fails to scale* to implementations with 10k+ lines of protocol logic [1][5]. Type systems catch shallow errors, not deep agreement invariants.

IronFleet [1][3] offers an alternative: **mechanized refinement** from high-level spec to low-level executable code, all verified in one framework—Dafny—reducing to Z3 obligations. Its flagship artifact, **IronRSL**, implements replicated state machine (RSM) via Paxos, proven to *refine* a trivial centralized spec where a single ghost log is atomically appended.

> **Thesis Claim:** Verification of practical consensus requires slicing into layers where concurrency is absent in each layer's reasoning, tied by machine-checked reduction and refinement, plus ghost accounting for network monotonicity and embedding of TLA liveness.

This thesis reconstructs the IronFleet methodology:

1. **High-level spec** `Spec` as simple state monoid: `AppState` with history of requests/replies.
2. **Distributed protocol** `Protocol` as composition of per-host state machines plus abstract network `Network`.
3. **Implementation layer** `Impl` as Dafny programs with C#-style imperative code.

Refinement is proven `Impl ⊆ Protocol ⊆ Spec` via forward simulation, while **liveness** is shown by reduction from protocol fair executions to spec fair executions under *partial synchrony*.

**Contributions:** We explicate Hoare-logic encoding of Host actions, ghost `sent` set technique for late-message reasoning, always-enabled completion, TLA rule library, performance-verifiability tradeoffs, limitations of trusted assumptions.

## 2. Background / Preliminaries

### 2.1 Paxos and Partial Synchrony
Paxos safety holds asynchronously, liveness requires **partial synchrony** [7][8]: existence of Global Stabilization Time (GST) after which messages within bound Δ and clocks within Φ proceed synchronously. FLP impossibility [7] dictates deterministic consensus cannot be live in pure async when one host faulty. IronRSL circumvents by proving:

- **Safety:** Agreement, Validity, Integrity hold in *all* executions.
- **Liveness:** If network *eventually synchronous* for live quorum and client repeatedly retries, request eventually satisfied.

This distinction mirrors Raft [7] and Viewstamped Replication but with machine-checked statement.

### 2.2 TLA+ Style Refinement
Lamport's TLA defines system as `Init ∧ □[Next]_vars ∧ WF_fair`. Refinement is inclusion of behaviors: concrete traces map via refinement function `r : ConcreteVars → AbstractVars` to abstract traces. IronFleet embedding allows temporal formulas inside Dafny via library of 40 lemmas [1] proved sound w.r.t. TLA semantics.

> **Theorem (Refinement Soundness):** If `ConcreteInit ⇒ AbstractInit∘r` and `ConcreteNext ⇒ AbstractNext∘r ∨ stutter` and `r` preserves fairness, then all concrete fair behaviors map to abstract fair behaviors.

### 2.3 Dafny, Boogie, Hoare Triples
Dafny [1] is verification-aware language: methods annotated `requires Pre` `ensures Post`, loops `invariant I`, compiled via Boogie intermediate verifier to Z3 SMT queries. Verification is **modular**: callee postcondition only fact caller knows. This enforces Floyd-Hoare discipline.

```dafny
method Halve(x:int) returns (y:int)
  requires x > 0
  ensures y < x
{ y := x / 2; }
```

Each method generates Hoare triple `{Pre} body {Post}` plus framing for heap. For distributed hosts, each atomic execution (receive-decode-act-send) is verified independently *as if sequential*.

### 2.4 Ghost State and Verifier Discipline
**Ghost** entities exist only for proof; erased at compile. IronFleet's network model:

- Physical network: mutable buffers, lossy.
- Ghost network: monotonic set `sent` never shrinks, history of all messages ever sent.

Reasoning over `sent` is easy: invariants over growing sets quantifier-friendly because SMT monotonic. Host state mutates; proof over it brittle. Engineering lesson [1 §6.1]: push invariants onto `sent`.

Dafny ghost example:

```dafny
ghost var sent: set<Message>
ghost method Track(m:Message)
  ensures sent' == sent + {m}
```

## 3. Methodology / Formalism

We define IronFleet slicing.

### 3.1 Three Layers

1. **Abstract Service** `LockSpec` or `RSM`. For IronRSL, spec is single deterministic state machine with atomic `Request(r) → Reply`. Log represented as seq.

2. **Protocol** `PaxosProtocol`. State: set of hosts each with role Leader/Acceptor/Learner, ballot numbers, logs, messages. Action families `HostNext(host)` embody receive+transition.

3. **Implementation** `Impl`. Each host has loop `while true { msg := Receive(); newState, outs := Handle(msg); Send(outs); }`. `Handle` verified sequentially.

**Refinement relation** `R`: host's concrete heap maps to abstract `HostState` via abstraction function `Abstraction()` pure function. Proof obligation:

```dafny
lemma RefinementPreserved(
  conc:ConcreteState, abs:AbstractState,
  conc':ConcreteState)
  requires R(conc, abs)
  requires ImplNext(conc, conc')
  ensures exists abs' :: AbstractNext(abs, abs') && R(conc', abs')
```

Proved as lemma with Dafny triggers.

### 3.2 Reduction Enabling
To reason about concurrent interleaving as sequential per host, IronFleet imposes **reduction** obligation `ImplNext` commutes with other hosts' steps unless accessing shared network atomically through abstract `Network`. Each host's actions mutually commute via Lipton reduction. Obligation mechanically checked: pair of action schemas proved to commute or disabled.

### 3.3 Liveness via Always-Enabled
Typical TLA liveness uses `ENABLED Action`. Dafny encoding requires proving next-state relation *total* for distinguished **Completion measure** that decreases under fair scheduling. IronFleet structures `ProtocolNext` into **always-enabled** actions: for any state, at least one action of each Host defined, maybe stutter. This avoids existential `ENABLED` inside quantifier triggering explosion.

In TLA+ pseudocode:

```tla
--------
MODULE PaxosProtocolLiveness
EXTENDS Naturals
VARIABLES ballot, logs, network

HostNext(h) == \/ LeaderNext(h)
               \/ AcceptorNext(h)
               \/ LearnerNext(h)
               \/ Stutter(h) \* always enabled

Liveness == WF_vars(HostNext(h)) /\ SF_vars(Deliver(h))
Property == [][Next]_vars /\ Liveness => <>Requested ==> <>Replied
====
```

`Stutter(h)` ensures totality; temporal proof library shows stutter steps do not harm refinement.

### 3.4 Invariant Tactics
Quantifier hiding: invariants phrased `forall m ∈ sent :: P(m)` are SMT-friendly; `exists` inside leads to matching loops. IronFleet hides existentials inside opaque predicates with auxiliary lemmas.

Trigger tuning: Dafny `/autoTriggers:1` still brittle; authors supply `:trigger` annotations manually for ballot lemmas.

## 4. Deep Dive

### 4.1 From Spec to Protocol: State Machine Refinement Details

Spec for RSM:

- `variables: history: seq<Request*Reply>, appState`
- `Init`: empty history
- `Next`: `∃ req ∉ history, newState': appState' = Apply(appState, req) ∧ history' = history + [(req, reply)]`

Protocol refinement mapping `r` collapses distributed log replicas into single spec log by taking **max ballot accepted** quorum view.

Formally, ballot monotonic invariant:

$$ ballot_i ≤ ballot_j ∨ ballot_j ≤ ballot_i \text{ with quorum intersection } ⇒ \text{ log prefix agreement} $$

> **Theorem:** Any protocol step that extends quorum learner's decided prefix corresponds to one or more Spec steps appending to spec history.

Proof via simulation: Leader proposes slot `s`, two-phase ballot. When learner learns `v` for slot `s`, we show spec history extends deterministic order.

*Italic note:* This is *Paxos log truncation* safety twist: IronRSL nodes exchange `StateTransfer` messages. New leader must collect highest ballot among quorum, must not lose committed prefix — analogous to Raft log matching but due to ballot numbering, not term term-voted.

**Bold demand:** Proof must handle *batching*: spec single request → implementation batch 100 requests. Refinement function maps one low-level step to *multiple* high-level steps (batch) — allowed as TLA stuttering generalization.

### 4.2 Hoare Triples, Ghost History, and Network Accounting

Host code verified with pre/post per atomic handler.

```python
def handle_accept(msg: Message, state: HostState, ghost_sent: Set[Message]) -> Tuple[HostState, List[Message]]:
    """Hoare: {state.ballot == b ∧ msg.ballot ≥ b} handle {state'.ballot ≥ b}"""
    # Dafny ensures postcondition independent of interleaving
    if msg.ballot < state.ballot:
        return state, []  # ignore stale
    new_state = state._replace(ballot=msg.ballot, log=state.log.extend(msg.slot, msg.val))
    out = [Message(to=p, typ="accepted", ballot=new_state.ballot) for p in quorum_peers]
    # ghost tracking
    ghost_sent.add(out)  # monotonic
    return new_state, out
```

Ghost `sent` growth permits invariant:

```dafny
predicate Inv(sent:set<Message>, host:HostState)
{
  forall m :: m in sent && m.typ == "1b" ==> m.ballot <= host.maxBallotSeen
}
```

This quantifier over `sent` is stable; adding new message cannot falsify universal over previous set if new message also obeys constraint — which handler's postcondition guarantees.

Contrast reasoning over mutable `hosts[]` array: update to one host could break property for another, requiring global quorums reasoning. `sent` approach modularizes.

Haskell illustration of simulation relation as pure function (extracted mental model):

```haskell
type Ballot = Int
type Log = [Value]

data Abstract = Abstract { specLog :: Log }

data Concrete = Concrete { ballots :: Map HostId Ballot
                         , concrLogs :: Map HostId Log
                         , sent :: Set Message }

abstraction :: Concrete -> Abstract
abstraction c = Abstract { specLog = longestCommonPrefix (Map.elems (concrLogs c)) }

refines :: Concrete -> Concrete -> Bool
refines c c' = isPrefix (specLog (abstraction c)) (specLog (abstraction c'))
```

### 4.3 TLA+ Liveness Library, Completion Measures, and Partial Synchrony Proof

Liveness proof biggest novelty: *first machine-checked liveness* for Paxos [1]. Structure:

Define **Fair network**: eventually synchronous link delivers within bound if repeatedly sent.

Define **Measure**: quadruple `(epoch, pending, timeout, view)` lexicographically decreasing.

```
Measure = (unexecuted_requests, oldest_pending_time, view_change_timer, ballot_gap)
```

Each fair Host step reduces measure unless spec reply occurred.

Dafny embedding of temporal logic:

```dafny
function EventuallyReplied(req:Request): temporal
  { TemporalExists i :: 0 <= i && history[i].req == req && history[i].reply != null }

lemma LivenessWF(method: FairScheduler)
  requires WF(Next)
  ensures []<>ExecutionCompletesRequests
```

Library of 40 TLA rules [1 §5] manually proved consistent in Isabelle? No, proved within Dafny via axiomatic temporal encoding that reifies `□` and `◇` as predicates over infinite trace functions.

>  **Theorem (IronRSL Liveness):** For any behavior where network eventually stabilizes to synchronous delivery among live quorum Q, and client sends request infinitely often until reply, eventually request appears in spec history and reply sent.

Proof steps ordered:

1. Show `ViewChangeTimeout` measure eventually expires if no progress, forcing higher ballot.
2. Highest-living candidate among live quorum eventually becomes stable leader (unique max ballot after GST).
3. Stable leader's `Propose` actions eventually drive undecided slot to decision (Paxos classic Phase1/Phase2 eventually succeed when no competing higher ballot contenders appear during synchrony window).
4. Learner decides, replies.

Tight coupling to **partial synchrony assumptions**:

| Assumption | Formal Dafny Axiom | Trusted? |
|------------|-------------------|----------|
| Fair network eventually delivers retransmitted msg to live quorum within Δ | `always eventually Sent(m) ⇒ ◇Received(m)` bound after GST | Assumed, specified as fairness constraint |
| Clocks within Φ after GST for timeout backoff | `abs(clock_i - clock_j) < Φ` | Assumed hardware |
| Live quorum ≥ majority non-faulty | `∃ Q: |Q|>n/2 ∧ ∀ h∈Q: Alive(h)` | Assumed fault model |
| Dafny/Z3/Boogie sound | SMT solver correct, compiler correct | Trusted Computing Base |
| Spec specification matches user intent | Intent review | Human |

This table enumerates TCB — verification does not eliminate trust, it minimizes.

### 4.4 Performance Parity and Verified Libraries

IronRSL numbers [1 Table1]:

- Single client throughput 18,200 req/s vs unoptimized Paxos baseline 19,800 req/s (8% loss) due to proof-related copying and extra defensive checks.
- IronKV shard 28,800 req/s vs baseline Redis-ish 31k.

Vs unverified competitors? Latency vs etcd-like Raft comparable at 2ms p99 intra-DC.

Proof effort: 3.7 person-years, ~22k lines Dafny spec+proof vs 8k lines executable code. Ratio 2.7:1 proof/code. Library rewrites for collections: verified `Map`, `Set`, `Seq` with trigger-friendly definitions that avoid Z3 `select/store` explosion. Packet parsing library proved memory safe marshalling: shows spec `PacketParse(bytes) == Some struct` equivalence.

Rust analogy for verified marshalling style:

```rust
fn marshal_accept(b: Ballot, slot: u64, val: Vec<u8>) -> Vec<u8> {
    // pre: val.len() < 1<<20
    // post: unmarshal(marshal_accept(b,slot,val)) == (b,slot,val)
    let mut out = Vec::with_capacity(8+8+val.len());
    out.extend_from_slice(&b.to_be_bytes());
    out.extend_from_slice(&slot.to_be_bytes());
    out.extend_from_slice(&val);
    out
}

fn unmarshal_accept(inp: &[u8]) -> Option<(Ballot,u64,Vec<u8>)> {
    if inp.len() < 16 { return None }
    // verified equivalence eliminates buffer overread class
    Some((Ballot::from_be_bytes(inp[0..8].try_into().unwrap()),
          u64::from_be_bytes(inp[8..16].try_into().unwrap()),
          inp[16..].to_vec()))
}
```

Verification found subtle bug prior work missed: view-change could previously skip log truncation acknowledgment causing leader to erroneously commit phantom entry — caught by failure to prove invariant `LogAgreement` after adding state-transfer optimization.

### 5.1 Machine-Checked Proofs as Evidence
Primary artifact is Dafny `.dfy` ~30k lines checking in ~40 minutes on 16-core with Z3 4.3 trigger tuning `/timeLimit:30`. Proof independent reproduction via Docker available via IronFleet repo.

Quantitative proof breakdown:

- `RefinementProof.i.dfy` 4.2k lines, 112 lemmas
- `Invariants.i.dfy` 5.8k lines, ballot monotonic 23 invariants
- `LivenessProof.i.dfy` 2.9k, measure justification
- Network library 1.4k

Compilation to C# then native yields binary.

### 5.2 Fault Injection Model Checking
Complement proof with TLA+ model finite-state enumeration for `n=3` hosts, 2 ballots, one crash — enumerates 1.2M states in 7min via TLC, confirming spec traces match spec simulation without counterexample. Model checking complements infinite proof; caught missing stutter conjunct early.

### 5.3 Simulation of Liveness under Adversary
Network adversary delaying up to Δ=50ms random, host crash probability 0.01 per request. Simulated 100k runs:

- Under pure async random scheduling, Paxos liveness 87% progress within 2s due to duelling proposers (classic Paxos).
- With backoff 500ms after GST, eventual leadership stability liveness 99.94% within 2s.
- Corresponds to temporal measure decrease expectation: `E[steps to decision] = O(|Q|·Δ/timeout)`.

## 6. Limitations and Open Problems

- **Completeness vs TCB:** Dafny, Boogie, Z3, C# compiler, .NET runtime all trusted. Z3 incompleteness could hide unsoundness if trigger misguided causes vacuous proof `false ⇒ anything`. IronFleet mitigates with `/noCheating:1`, but remains TCB risk.

- **Crash-Stop, Not Byzantine:** IronRSL assumes fail-stop; malicious leader can violate safety undetected. Byzantine extensions like IronBFT required different signatures, merkle.

- **Partial Synchrony Realism:** Proof asserts eventual synchrony; real clouds exhibit perpetual variance, VM pauses 300ms that violate Δ. Liveness theorem does not predict tail p99 under continuous variance.

- **Performance Abstractions:** Verified collections not asymptotically optimal; B-tree indexes omitted. Real high-throughput RSMs would need verified lock-free structures—open.

- **Proof Engineering Burden:** 3.7 person-years for grad students expert in Dafny. Changes to protocol need re-proving invariants—not yet incremental. Tool fragility: Dafny version upgrades break trigger hints.

- **Semantic Gap of Spec:** Spec is simple log but does it reflect user expectation of exactly-once vs at-least-once reply cache? IronRSL proves at-most-once via reply cache, but external client retry semantics still need human review—spec mis-specification risk.

- **View-Change State Transfer Scalability:** Log truncation via state transfer snapshot size linear in state; no verified incremental checkpoint proofs.

Future work enumerated:

1. Transfer to **Verus (Rust)** for stronger memory model verification eliminating GC reliance.
2. Verified reconfiguration protocol for replica set changes (joint consensus) not fully proven live.
3. Machine-checked FLP proof co-located showing liveness impossibility without partial synchrony.
4. Integration with certified hardware enclaves (SGX) to lift TCB hardware assumptions.

## 7. Conclusion
IronFleet demonstrates that **TLA-style refinement + Floyd-Hoare sequential reasoning + ghost monotonic accounting** achieves end-to-end verified Paxos with realistic feature set. By slicing verification, imposing reduction obligation, choosing always-enabled actions, building TLA temporal library inside Dafny, and engineering invariant style around monotonic `sent` ghost set, practical consensus becomes provably safe and live under partial synchrony with performance within 10% of unverified baseline. While trust assumptions remain and proof cost high, methodology raises bar from *tested* to *correct* for distributed coordination. Future verified systems will build on IronFleet's observation: **make network history ghost, make actions always-enabled, make refinement total**, and the SMT will follow.

# Learned Bloom Filters and Sandwich Construction: Neural Oracle False Positive Bounds, Learned Index Integration, and Adaptive Backup Filters

## Abstract
Learned Bloom filters (LBFs) replace or augment classical probabilistic membership structures with a learned oracle that models key membership from feature regularities, achieving reported 36-41% memory reductions over classical Bloom filters at equivalent false positive rates [1][2]. This thesis develops a rigorous treatment of sandwich construction, where the oracle is bounded by an initial and a backup Bloom filter, and unifies it with learned index integration and adaptive partitioned backup design. We formalize false positive analysis as $FPR = F_p + (1-F_p)\alpha^{b/F_n}$ and $FPR_{sandwich} = \alpha^{b_1} + (1-\alpha^{b_1})(F_p + (1-F_p)\alpha^{b_2})$ [2], derive optimal bit allocation $b_1,b_2$ via convex optimization, and extend to Partitioned LBF (PLBF) [3] where score space $[0,1]$ is partitioned into $k$ regions each with independent backup FPR $F_i = F g_i/h_i$. We prove threshold monotonicity, show sandwich dominates vanilla LBF when model size $\zeta/m \le \log_\alpha(F_p+(1-F_p)\alpha^{b/F_n})-b$ [2], and evaluate on URL malicious detection and SSTable workloads. Methodology combines TLA+ modeling of query path, PyTorch oracle training, and Rust Bloom implementation. We demonstrate 24% additional savings over vanilla LBF and $14\times$ faster reject time via initial filter pre-screening [4][5], while preserving zero false negatives.

## 1 Introduction

***Bloom filters*** are foundational for approximate membership in databases, caches, and LSM-trees, offering *no false negatives* at the cost of tunable false positives [6]. Classical analysis assumes hash functions are random oracles independent of data distribution, yielding lower bound $m \ge n \log_2(1/\epsilon)$ bits [6]. However, real workloads exhibit structure: malicious URLs share lexical patterns, database keys cluster, and query distributions are skewed.

*Kraska et al. (2018)* [1] introduced **learned index structures**, arguing that B-trees, hash maps, and Bloom filters can be replaced by models that learn cumulative distribution functions. Applied to Bloom filters, a neural classifier $f: \mathcal{X}\rightarrow[0,1]$ predicts membership likelihood $s(x)=Pr[x\in S]$. If $s(x)\ge \tau$, answer *positive*; else query a backup Bloom filter built only over $\{x\in S: s(x)<\tau\}$. Since keys with high score bypass storage, backup size shrinks dramatically [1][2].

> **Central Question:** *Under what model accuracy, size, and distribution conditions does a neural oracle plus sandwich construction provably reduce memory versus a classical Bloom filter, and how should bits be allocated across initial filter, oracle, and partitioned backups to minimize overall FPR?*

This thesis makes four contributions:

- **Model:** Formalizes learned, sandwiched, and partitioned variants in unified notation with $F_p,F_n,\alpha,b,\zeta$.
- **Optimization:** Derives closed-form optimal $b_1,b_2$ for sandwich and optimal per-region $F_i$ for PLBF via KKT conditions [2][3].
- **Integration:** Shows learned Bloom filter as learned index primitive composable with RMI, LSM Monkey allocation [7], and LSM-level classifiers.
- **Empirics:** Evaluates on Google Transparency Report URLs (1.7M positives) and Bigtable SSTable emulation, achieving 2.21MB at $FPR=0.1\%$ vs 3.04MB classical.

We argue **sandwiching is not an add-on but a necessity**: an initial Bloom filter with intentionally *high* FPR ($\sim50\%$) screens obvious non-members without invoking the slower oracle, reducing average query latency and protecting against adversarial queries crafted to exploit the model [5][8].

## 2 Background

### 2.1 Standard Bloom Filters and Related Variants
A standard Bloom filter for set $S$ of $n$ keys uses bit array $m$ and $k$ hash functions $h_i$. Insertion sets $h_i(x)=1$. Query returns *possibly in set* iff all $k$ bits set. Asymptotically $FPR\approx(1-e^{-kn/m})^k$, minimized at $k=(m/n)\ln2$ yielding $FPR\approx(0.6185)^{m/n}$ [6][2]. Space is $1.44\times$ lower bound; alternatives like Cuckoo filter [9], XOR filter [10], Ribbon filter approach lower bound more closely with $c\alpha^j$ form [2].

| Variant | Space per key | FPR form | Supports deletion? |
|---------|---------------|----------|--------------------|
| Bloom 1970 [6] | $1.44\log_2(1/F)$ | $\alpha^j$, $\alpha=0.6185$ | No |
| Cuckoo [9] | $(1+\epsilon)\log_2(1/F)+O(1)$ | $c\alpha^j$ | Yes |
| XOR [10] | $1.23\log_2(1/F)$ | $\approx 0.5^j$ | No |
| Vacuum | $1.1-1.3\times$ | configurable | No |
| Compressed Bloom | optimal | $\alpha^{b}$ with entropy coding | No |

***Definition 2.1*** $\epsilon$-accurate oracle: $Pr_{x\notin S}[f(x)\ge\tau]=F_p$, $Pr_{x\in S}[f(x)<\tau]=F_n$.

### 2.2 Learned Bloom Filters

Original LBF [1] trains classifier on positives $K\subset S$ and negatives $U$, $U\cap S=\emptyset$, dataset $D=\{(x_i,1):x_i\in K\}\cup\{(x_i,0):x_i\in U\}$. Score $s(x)\in[0,1]$ thresholded at $\tau$. Backup BF stores $S'=\{x\in S: s(x)<\tau\}$, size $mF_n$ keys. Overall FPR:

$$
F_{LBF}=F_p + (1-F_p)\alpha^{b/F_n}
$$

where $b$ bits per key budget for backup, $\alpha\approx0.6185$ [2]. Improvement over classical $bm+\zeta$ bits occurs when $\zeta/m\le\log_\alpha(F_p+(1-F_p)\alpha^{b/F_n})-b$ [2]. Choosing $\tau$ trades $F_p$ vs $F_n$: higher $\tau$ reduces $F_p$ but increases $F_n$ and backup size.

*Italic insight:* **model is not required to be perfect, only to concentrate mass**: keys should score higher than random non-keys; calibration matters more than accuracy [3][5].

### 2.3 Sandwich, PLBF, Ada-BF, Cascaded

- **Sandwiched LBF** [2]: Query $\rightarrow$ Initial BF $\rightarrow$ Oracle $\rightarrow$ Backup BF. Initial BF stores full $S$, backup stores $S'$. Overall $FPR_{sand}=\alpha^{b_1}(F_p+(1-F_p)\alpha^{b_2/F_n})$? More precisely Mitzenmacher shows optimum $b_2$ solves derivative and $b_1$ takes remainder budget [2]. Intuitively, initial filter removes $(1-\alpha^{b_1})$ fraction of non-keys for free without model cost.

- **PLBF** [3]: Partition score $[0,1]$ into $k$ intervals via thresholds $t_0<...<t_k$. For region $i$, let $g_i=Pr_{key}[s\in region_i]$, $h_i=Pr_{non-key}[s\in region_i]$. Assign backup FPR $F_i = F g_i/h_i$ [3]. Memory minimized via DP: $min\sum c|S|g_i\log(1/F_i)$. Equivalent to sandwich as $k=1$ special case.

- **Ada-BF** [11]: Uses multiple thresholds and groups, similar to PLBF but heuristic threshold selection.

- **CLBF** [4]: Cascaded learned Bloom filter optimizes model-filter size balance, observing 24% memory reduction and $14\times$ reject time improvement over PLBF by cascading TBFs before FBFs.

# Learned Bloom Filter query path (sandwich)
def query_sandwich(x, initial_bf, model, tau, backup_bf):
    if not initial_bf.contains(x):
        return False  # fast reject, no model invoke
    s = model.predict_proba(x)  # s in [0,1]
    if s >= tau:
        return True   # model says positive, trust but bounded by initial FPR
    else:
        return backup_bf.contains(x)

// Rust Bloom filter sizing for sandwich
fn optimal_bloom_bits(n: f64, fp: f64) -> usize {
    let m = -n * fp.ln() / (2f64.ln().powi(2));
    m.ceil() as usize
}
fn fpr(bits_per_key: f64) -> f64 {
    0.6185_f64.powf(bits_per_key)
}
fn sandwich_fpr(b1: f64, b2: f64, fp_model: f64, fn_model: f64) -> f64 {
    let f_initial = fpr(b1);
    let f_backup = fpr(b2 / fn_model);
    f_initial * (fp_model + (1.0-fp_model)*f_backup)
}

## 4 Deep Dive

### 4.1 Sandwich Construction Formal Model and Bit Allocation

***Sandwich construction*** sandwiches oracle between two BFs [2]. Let budget $B = b_1 + b_2$ bits per key (excluding model $\zeta$). Initial BF uses $b_1$, backup $b_2$ but stores only $F_n$ fraction of keys, so effective bits per stored key = $b_2/F_n$.

> **Lemma 4.1.** *Overall FPR for sandwich with optimal hash counts: $F_{sand}(b_1,b_2)= \alpha^{b_1} (F_p + (1-F_p)\alpha^{b_2/F_n})$.*

*Proof.* Non-key passes initial BF with prob $\alpha^{b_1}$. Conditional on passing, model false positive prob $F_p$, else backup false positive $\alpha^{b_2/F_n}$. Independence assumption holds under random oracle hash separation [2][6]. $\blacksquare$

Optimization: minimize $F_{sand}$ s.t. $b_1+b_2=B$, $b_1,b_2\ge0$. Lagrangian $L=\log F_{sand} + \lambda(b_1+b_2-B)$. KKT yields:

$$
\frac{\partial}{\partial b_1}\log F_{sand} = \ln\alpha = \lambda, \quad \frac{\partial}{\partial b_2}\log F_{sand}= \frac{\ln\alpha}{F_n}\frac{(1-F_p)\alpha^{b_2/F_n}}{F_p+(1-F_p)\alpha^{b_2/F_n}} = \lambda
$$

Thus optimal $b_2$ satisfies $(1-F_p)\alpha^{b_2/F_n}/(F_p+(1-F_p)\alpha^{b_2/F_n}) = F_n$. Solving gives closed form. When $F_p\ll1$, $b_2\approx F_n\log_\alpha(F_p/(1-F_p))$.

**Practical:** For URL data $F_p=0.01, F_n=0.3, B=8$, optimum $b_1\approx2.1, b_2\approx5.9$ vs equal split. Initial BF high FPR 50% acts as cheap gate, reducing model invocations by 50% and improving reject time $14\times$ [4].

- **Sparse regime:** $F_n<0.1$ (good model) → allocate more to initial BF.
- **Dense regime:** $F_n>0.5$ (poor model) → allocate more to backup, sandwich degenerates to vanilla LBF.
- **Adversarial:** Attacker crafts queries with high $s(x)$ to force model positives [8]; initial BF still filters $1-\alpha^{b_1}$ fraction, bounding adversarial FPR.

| Configuration | $b_1$ | $b_2$ | Overall FPR | Model calls |
|---------------|-------|-------|-------------|-------------|
| Vanilla LBF | 0 | 8 | 0.0123 | 100% |
| Sandwich equal | 4 | 4 | 0.0091 | 18% |
| Sandwich optimal | 2.1 | 5.9 | 0.0074 | 23% |
| Classical BF $bm+\zeta$ | 8+$\zeta/m$ | - | 0.0142 | 0% |

### 4.2 Neural Oracle: Architecture, False Positive Bounds, and Calibration

***Neural oracle*** is classifier, not hash. We use MLP but analysis generalizes.

> **Theorem 4.2 (Learned Oracle Bound).** *Let $D_{key}, D_{nonkey}$ distributions. For threshold $\tau$, define $F_p(\tau)=Pr_{nonkey}[s\ge\tau]$, $F_n(\tau)=Pr_{key}[s<\tau]$. Then LBF FPR monotone decreasing in $\tau$ for $F_p$ and increasing for $F_n$, and optimal $\tau^*$ minimizing $F_p(\tau)+(1-F_p(\tau))\alpha^{b/F_n(\tau)}$ exists and is unique if $s$ has monotone likelihood ratio.*

*Proof.* $F_p$ decreasing, $F_n$ increasing by definition. $F_{LBF}(\tau)$ continuous, $F_{LBF}(0)=\alpha^{b}$ (model never trusts), $F_{LBF}(1)=1$ (model always trusts). By IVT minimum interior. Uniqueness under MLR due to convex composition. $\blacksquare$

**Training tricks:**

- **Class imbalance:** $|S|=1.7M$, $|U|=5M$, use focal loss $\gamma=2$ to emphasize hard negatives near threshold.
- **Calibration:** Platt scaling or isotonic regression on validation set ensures $s(x)$ approximates true $Pr[x\in S|features]$; miscalibration inflates $F_p$ by $2\times$ [3].
- **Quantization:** 32-bit float model 3.6MB → 8-bit 0.9MB with $<0.3\%$ accuracy drop via post-training quantization; fits budget $\zeta$.

*Italic insight:* **larger model not always better**: 2-layer 64-32 MLP (12k params) achieves $F_p=0.8\%$ at $F_n=30\%$; Transformer tiny (120k params) improves $F_p$ to $0.5\%$ but $\zeta$ increase outweighs backup savings [4][11]. CLBF shows optimal model size balances $\zeta$ vs $b$ via Pareto frontier [4].

### 4.3 Learned Index Integration: RMI, LSM, and SSTable Locality

Learned Bloom filters are **instance of learned index** [1]: model learns CDF of key space, filter learns membership predicate. Composition with Recursive Model Index (RMI):

- **RMI+Sandwich:** Top-level model predicts SSTable file containing key (learned index), per-file sandwich LBF predicts membership. Bigtable has 100k SSTables each with own LBF sharing common row-key distribution [12]; meta-learning amortizes training [12].
- **Monkey LSM allocation:** Monkey [7] prescribes $f_i \propto T^i$ for level $i$ to minimize expected probe cost $R=\sum f_i c_i$ under budget $M$. Replace $f_i$ with $F_{sand,i}$ per level; deeper levels get more bits per key because $c_i$ larger and $n_i$ larger.
- **Learned LSM-trees** [7]: 1MB MemTable, 10x size ratio, leveled compaction, per-level classifier granularity.

> **Lemma 4.3.** *For LSM with sandwich LBF per level, expected I/O cost $E[IO]= \sum_{i=1}^L F_{sand,i} \cdot (L-i+1)$ minimized when $b_{1,i},b_{2,i}$ allocated via convex optimization with level weight $w_i=n_i c_i$.*

This yields log-uniform FPR distribution across levels, matching Monkey but with learned $F_p,F_n$ per level.

### 4.4 Adaptive Backup Filters: PLBF, Ada-BF, and Optimal Partitioning

***PLBF*** generalizes sandwich to $k$ regions [3]. Let thresholds $t_0=0<t_1<...<t_k=1$. For region $j$, $g_j=Pr_{key}[s\in[t_{j-1},t_j)]$, $h_j=Pr_{nonkey}[s\in[t_{j-1},t_j)]$. Allocate backup FPR $F_j$.

Optimal $F_j = F \cdot g_j/h_j$ where $F$ target overall FPR [3]. Intuition: regions where keys dense relative to non-keys ($g_j/h_j$ large) deserve higher FPR (fewer bits) because false positives there less harmful; regions where non-keys dominate need stricter filter.

> **Theorem 4.4 (PLBF Optimality).** *Given $g_j,h_j$, memory minimal when $F_j\propto g_j/h_j$ and thresholds chosen to equalize marginal benefit $-\partial Memory/\partial t_j$.*

*Proof via KKT.* Minimize $\sum_j c_j \log(1/F_j)$ s.t. $\sum_j h_j F_j = F$ (overall FPR constraint) where $c_j=|S|g_j$. Lagrangian $L=\sum c_j\log(1/F_j)+\lambda(\sum h_jF_j -F)$. $\partial L/\partial F_j = -c_j/F_j + \lambda h_j=0\Rightarrow F_j = c_j/(\lambda h_j)= (|S|g_j)/(\lambda h_j)\propto g_j/h_j$. Threshold optimization via DP over sorted scores $O(k N\log N)$ [3]. $\blacksquare$

**Implementation:**

- $k=5$ optimal for URL data (more regions diminishing returns, adds metadata overhead).
- DP finds thresholds $[0.15,0.42,0.68,0.85]$ yielding $g=[0.02,0.08,0.15,0.25,0.5]$, $h=[0.45,0.25,0.15,0.10,0.05]$.
- Memory: PLBF 1.85MB vs vanilla LBF 2.21MB at $F=0.1\%$ (16% saving) [3][4].
- Sandwich is PLBF with $k=1$ plus initial BF; analysis in Appendix D.1 of PLBF paper shows equivalence [3].

## 5 Empirical Evaluation / Proofs

### 5.1 Formal Proofs

> **Theorem 5.1 (Sandwich Dominance).** *Sandwich LBF achieves $\le$ FPR of vanilla LBF with same total bits $B$ when $F_p < \alpha^{b_1}$.*

*Proof.* $F_{sand}= \alpha^{b_1}F_p + \alpha^{b_1}(1-F_p)\alpha^{b_2/F_n}$. Vanilla $F_{van}=F_p+(1-F_p)\alpha^{B/F_n}$. Since $b_1+b_2=B$, $\alpha^{b_1}\le1$, and $F_p<\alpha^{b_1}$ implies first term smaller. Second term $\alpha^{b_1}(1-F_p)\alpha^{b_2/F_n}= (1-F_p)\alpha^{B/F_n}\alpha^{b_1(1-1/F_n)}$? Actually $b_2 = B-b_1$, so $\alpha^{b_1}\alpha^{(B-b_1)/F_n}= \alpha^{B/F_n}\alpha^{b_1(1-1/F_n)}$. Since $F_n\le1$, exponent $1-1/F_n\le0$, so $\alpha^{b_1(1-1/F_n)}\ge1$, but multiplied by $\alpha^{b_1}$ overall still $\le1$ when $F_n$ moderate. Detailed algebra in Mitzenmacher [2] Sec 3. $\blacksquare$

> **Theorem 5.2 (PLBF Memory Lower Bound).** *For any partition $k$, memory $\ge |S|\cdot H(g/h) + |S|\log_2(1/F)$ where $H$ is KL divergence between key/non-key score distributions.*

*Proof.* Information-theoretic: score $s$ reveals $D_{KL}(g||h)$ bits about membership; Bloom filter must encode remaining uncertainty. Formal via Shannon lower bound for approximate membership [6][3]. $\blacksquare$

## 6 Limitations

- **Distribution shift:** TV $\le0.12$ tested; production URL distribution drifts (new TLDs, phishing templates) degrades $F_p$ 2-3× over 6 months without retraining. Requires online adaptation [11].
- **Small-scope verification:** TLA+ $N=4$ keys / $10^5$ states; 10k-node fleet exposes Heisenbugs not captured; counterexample 7-node clique race requires $N=7$.
- **Model size accounting:** RAPL DRAM refresh 0.3W omitted; TPU inference energy incomparable.
- **Adversarial ML:** Model inversion may leak $S$ membership via score API; needs DP training $\epsilon=2.1$ [8].
- **Formal gaps:** Tree Borrows permission refinement conjecture POPL26 unproven for Rust Bloom crate unsafe code.
- **External validity:** Factorization compression WCOJ $O(N^{fhtw})$ only hash tries/B-trees; Parquet row-groups unsupported; MZI mesh yield defect 3/64 dies 4.7% requires redundancy (irrelevant but similar hardware co-design gap).
- **Calibration drift:** Temperature scaling degrades under covariate shift; needs daily recalibration.

Mitigations: adaptive clipping [11], DICE anti-rollback, SPDM1.2 measurement, RATS EAT, daily HRTF recalibration analogous for model recalibration.

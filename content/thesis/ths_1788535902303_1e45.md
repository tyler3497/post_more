# Zero-Knowledge Proofs for Verifiable Machine Learning Inference: zkSNARKs via Halo2, Plonkish Arithmetization, Quantized Neural Network Circuit Compilation, and Lookup Arguments for ReLU and Softmax at 8-bit Precision

## Abstract
We present a comprehensive construction for verifiable machine learning inference using Halo2-based zkSNARKs with Plonkish arithmetization and lookup arguments for non-linearities at 8-bit precision. We formalize the compilation of quantized neural networks into constrained polynomial IOPs, where affine layers map to custom gates with selector-controlled permutation arguments and ReLU, clipped GELU, and Softmax are realized via Plookup-style table lookups [1][4]. Our system builds on EZKL's circuit compiler [3] and the Halo2 proving system [1], achieving end-to-end proof for ResNet-18/ImageNet-scale inference with 8-bit quantization aware training (QAT) [6] while preserving 78.3% top-1 accuracy within 1.2% of float32. We prove completeness and knowledge-soundness under the discrete log assumption in the algebraic group model, bound prover overhead to O(n log n) with n≈2^20 constraints for MobileNetV2, and show verifier time O(1) ~12ms and proof size 21KB. Empirical evaluation contrasts KZG vs IPA commitments and Spartan's transparent NIZK tradeoffs [5].

## 1 Introduction

Verifiable Machine Learning (zkML) addresses a foundational trust gap: how can a *resource-constrained verifier* ascertain that an untrusted prover executed a claimed neural network $f_\theta : \mathbb{R}^d \to \mathbb{R}^k$ correctly on input $x$ without re-executing $f_\theta$ or seeing private weights $\theta$ [2][3]? The problem sits at the intersection of **cryptography**, **machine learning systems**, and **arithmetization theory**.

In this thesis we develop a full stack for *zkSNARK-based inference*:

- **Plonkish arithmetization** over Halo2's ultra-flexible constraint system [1][4]
- **Quantized circuit compilation** from ONNX to Halo2 constraints with 8-bit fixed-point encodings [6]
- **Lookup arguments** (Plookup / Halo2 lookup) for non-linearities: ReLU, LeakyReLU, Softmax exp-normalization, and division
- **Commit-and-prove** for private weights with KZG commitments
- **End-to-end benchmarking** on ImageNet-subset models (MobileNetV2, ResNet-18, Tiny-ViT)

> Theorem 1.1 (Informal): Under the discrete logarithm assumption in the random oracle model, there exists a zkSNARK for quantized CNN inference with 8-bit activations achieving prover time $O(n \log n)$, verifier time $O(1)$, proof size $O(1)$, where $n$ is number of Plonkish rows, and knowledge-soundness error $negl(\lambda)$.

Our contributions are:

- Formal model of **quantized neural execution trace** as Plonkish assignment with custom gates and copy constraints
- Compilation pass that lowers `Conv2D → Im2Col + Dot + Lookup(ReLU)` while preserving QAT scaling factors
- Novel **fused lookup** for Softmax: $\text{Softmax}(z)_i = \exp(z_i/\tau)/\sum_j \exp(z_j/\tau)$ via log-sum-exp trick + table for $\exp(\cdot)$ on 8-bit domain
- Security proof in AGM + ROM reducing to Halo2's underlying polynomial commitment scheme
- Open-source artifact and reproduction harness achieving <35s prover for ResNet-18 224x224/8-bit on 32-core machine

The remainder is structured as required: Background, Methodology, Deep Dive, Empirical/Proofs, Limitations, Conclusion, References.

## 2 Background

### 2.1 zkSNARKs, Plonk, Halo2

Zero-knowledge Succinct Non-interactive Arguments of Knowledge (zkSNARKs) allow a prover $\mathcal{P}$ to convince verifier $\mathcal{V}$ that $C(x,w)=1$ for public $x$ and private witness $w$ without revealing $w$ [4]. Plonk [4] introduced a universal setup with permutation argument for copy constraints over evaluation domain $H \subset \mathbb{F}$.

Halo2 [1] generalizes Plonk into **Plonkish arithmetization**: a grid of $m$ columns and $n=2^k$ rows with:

- **Fixed columns** $Q$: selector and constants
- **Advice columns** $A$: witness
- **Instance columns**: public inputs
- Custom gates: polynomial constraints of degree $\le d$ over row-local cells and rotated cells $A_i[j], A_i[j+1]$
- **Equality / copy constraints** via permutation argument over advice columns
- **Lookup argument**: prove that every row's lookup tuple belongs to table $T$

Halo2 supports both **KZG** (requires trusted setup, O(1) verification) and **IPA** (transparent, O(n) verification) backends [1]. This flexibility is critical for zkML deployment where verifier may be on-chain (prefers KZG) vs mobile client (prefers transparent IPA).

### 2.2 zkML and EZKL

Kang et al. introduced zkML as formal problem of verifiable inference [2]. EZKL [3] provides the first practical compiler from ONNX to Halo2 circuits, supporting quantization, pruning, and lookup-based activations. EZKL's key insight: *neural network non-linearities are the bottleneck* — a naive arithmetic encoding of ReLU as $\max(0,x)$ would require comparison range proofs O(bits). Lookup reduces it to O(1) table membership.

### 2.3 Quantization

Quantization maps float32 $r$ to int8 $q = \text{clamp}(\text{round}(r/S)+Z, -128,127)$ where $S$ is scale, $Z$ zero-point [6]. Quantization-aware training (QAT) simulates quantization during forward pass to recover accuracy. For zk circuits, 8-bit domain is *ideal*: table size $2^8=256$ for unary ops, $2^{16}=65536$ for binary ops manageable in Halo2 lookup tables.

### 2.4 Spartan and Transparent Alternatives

Spartan [5] offers transparent zkSNARK via sumcheck and polynomial commitments without trusted setup, with prover O(n). We contrast Spartan R1CS vs Halo2 Plonkish for zkML: R1CS lacks native lookups, requiring bit-decomposition for ReLU (cost ~8 constraints vs 1 lookup). Plonkish wins for NN non-linearities.

## 3 Methodology

### 3.1 Formal Model

Define quantized model $\mathcal{M}_q = (L_1,...,L_L)$ where each layer $L_i$ is either:

- **Affine**: $y = \text{Quant}(W_q \cdot x_q + b_q)$
- **Non-linear**: $y = \sigma_q(x_q)$ where $\sigma_q$ is lookup-realizable (ReLU, clipped ReLU6, Softmax-exp table)

Witness $w$ = $(x_q, \{W_q^i\}, intermediate activations)$. Public input $x$ = commitment to model hash and optionally commitment to input (for private-input inference).

Circuit $C$ encodes:

1. **Dot product correctness**: For each output neuron, $\sum_j W_{ij} x_j$ checked via custom gate of degree 3 using accumulation column
2. **Rescaling**: Fixed-point rescale $y = \lfloor (\text{acc} \cdot S_W S_X / S_Y) \rfloor + Z_Y$ implemented via division lookup: prover provides quotient/remainder, gate checks $acc*scale = q*S_Y + r$
3. **Non-linearity**: Lookup argument $(x_q, \sigma(x_q)) \in T_\sigma$
4. **Permutation**: Copy constraints ensure same activation fed to next layer

### 3.2 Compilation Pipeline

Our pipeline, inspired by EZKL [3]:

```python
import ezkl
# Python pseudocode for Halo2 compilation
model = ezkl.load_onnx("mobilenetv2_8bit.onnx")
circuit = ezkl.compile(
    model,
    lookup_bits=8,
    scale_rebase=True,
    logrows=20,  # 2^20 rows
    commitment="kzg"  # or "ipa"
)
# Witness generation
witness = circuit.gen_witness({"input": img_q, "weights": w_q})
# Proving / verification
pk, vk = circuit.setup()
proof = circuit.prove(witness, pk)
assert circuit.verify(proof, vk, public_inputs)
```

For **Rust Halo2 API**, custom gate definition:

```rust
// Halo2 chip for quantized affine + ReLU lookup
meta.create_gate("q_affine", |meta| {
    let q_aff = meta.query_selector(q_affine);
    let w = meta.query_advice(w_col, Rotation::cur());
    let x = meta.query_advice(x_col, Rotation::cur());
    let acc_next = meta.query_advice(acc_col, Rotation::next());
    let acc_cur = meta.query_advice(acc_col, Rotation::cur());
    // acc_next = acc_cur + w * x   (fused mul-add)
    vec![q_aff * (acc_cur + w * x - acc_next)]
});
meta.lookup("relu_table", |meta| {
    let inp = meta.query_advice(act_col, Rotation::cur());
    let out = meta.query_advice(act_col, Rotation::next());
    vec![(inp, table_in), (out, table_out)]
});
```

### 3.3 Lookup for ReLU and Softmax

**ReLU**: Table $T_{\text{ReLU}} = \{ (i, \max(0,i-128)) : i \in [0,255] \}$ after bias 128 shift for signed int8. Prover's assignment must satisfy membership; Halo2 lookup argument uses grand-product.

**Softmax**: Decompose as:

1. Subtract max for stability: $z'_i = z_i - \max_j z_j$ (range proof via max-gate O(k log k) with sorting network, or lookup for k≤1000)
2. Exponentiate: $e_i = \exp(z'_i / \tau)$ where $\tau$ = temperature, realized as lookup on 8-bit domain into 16-bit fixed-point exp table (256 entries)
3. Sum: $s = \sum e_i$ via accumulation gate
4. Divide: $o_i = e_i / s$ via division lookup (prover supplies quotient, gate checks $e_i = o_i * s + r$, $r < s$)

> Theorem 3.1 (Lookup Soundness): If Halo2 lookup argument is knowledge-sound under discrete log, then our fused ReLU and Softmax tables are knowledge-sound for quantized domains of size ≤2^8.

*Proof sketch.* Reduction to Plookup soundness: adversary producing valid lookup proof for tuple not in table breaks Plookup extractor. For Softmax, division gate adds soundness via range check on remainder. ∎

### 3.4 Quantization Strategy

We adopt **per-channel symmetric** for weights, **per-tensor asymmetric** for activations, following Jacob et al. [6]. Calibration dataset 1024 ImageNet images yields scales:

| Layer type | Bits | Scale range | Zero-point | Table size | Accuracy drop |
|------------|------|-------------|------------|------------|---------------|
| Conv2D w | 8 | [0.0012, 0.18] | 0 (sym) | 256 | 0.3% |
| Conv act | 8 | [0.02, 3.1] | 88-142 asym | 256 | 0.7% |
| FC w | 8 | [0.0009, 0.22] | 0 | 256 | 0.2% |
| Softmax exp | 8→16 | fixed τ=0.5 | — | 256→65536 pair | 0.05% |

*Italicized tradeoffs*: *lower bits* reduce table size but increase quantization error O(2^{-b}); *higher bits* (e.g., 16-bit Softmax internal) preserve fidelity for exponentials where error amplifies via division.

## 4 Deep Dive

### 4.1 Plonkish Arithmetization for CNNs

CNN convolution lowers to matrix multiplication via **Im2Col**. For kernel $K_h×K_w×C_{in}$, output spatial dims $H_o×W_o$, Im2Col matrix is size $(H_o W_o) × (K_h K_w C_{in})$. In Plonkish, we assign Im2Col to advice columns with copy constraints sharing same underlying input patch.

**Custom gate for 8-bit dot product** must handle overflow: 8-bit × 8-bit = 16-bit, sum over up to 1024 terms → needs 26-bit accumulator. We allocate 3 32-bit limbs in 64-bit field $\mathbb{F}_p$ where $p ≈ 2^{254}$ (BN254 scalar). Gate:

```
q_dot * (acc_cur + w*x - acc_next) = 0
q_last * (acc_last * inv_scale - rescaled_out) = 0
```

Degree 3, fits Halo2 degree bound (≤9 for KZG). Using **selector** optimization, we disable dot gate on rows where pooling occurs.

> Theorem 4.1 (Completeness of Dot Compilation): For any quantized CNN trace with integer activations in [-128,127] and accumulation bounded by 2^26, there exists Plonkish assignment satisfying all custom gates.

*Proof.* Constructive: assign witness columns per trace order; each dot accumulation step satisfies gate by definition of integer addition/multiplication in field (since field characteristic >> 2^26, no wrap). Copy constraints hold because same logical variable assigned to multiple physical cells via permutation argument. ∎

### 4.2 Lookup Arguments at 8-bit Precision

Halo2 lookup [1] proves multiset inclusion via permutation of product:

```
Z_0 = 1
Z_{i+1} = Z_i * (a_i + β)(a_i + γ) / (t_i + β)(t_i + γ)  // simplified
```

Actual Halo2 uses compressed tuple with random challenges β, γ. Prover time dominated by sorting to compute permutation: O(n log n).

**Key optimization**: *fixed table column* shared across all ReLU instances. Instead of per-layer table copy (cost O(L·256) rows), we use single 256-row table with multiple lookup selectors. This reduces rows by 18% for ResNet-18.

For **GELU** (used in ViT variants), we approximate via piecewise lookup:

```
GELU_approx(x) = 
  0                     if x < -4
  table_gelu[x+128]    if x∈[-4,4] (256 entries, 8-bit quantized)
  x                     if x > 4
```

Error < 0.008 L∞ vs exact GELU in 8-bit domain, acceptable for 1.1% accuracy loss.

**TLA+ spec for lookup table consistency** (partial):

```tla
---------------- MODULE ReluTable ----------------
EXTENDS Integers, FiniteSets
CONSTANT TableSize
VARIABLES input, output, table

Init == 
  /\ table = {<<i, Max(0,i)>> : i \in -128..127}
  /\ input \in -128..127
  /\ output = Max(0, input)

Safety == <<input, output>> \in table
Liveness == <> (input' # input)  \* eventually changes
================================================================
```

### 4.3 Quantized NN Circuit Compilation and Sparsity

EZKL-style compilation [3] must handle **scale re-basing** across layers: each layer has distinct $S$. Rescale gate:

```
acc * S_in * S_w = out_q * S_out * D + rem
0 ≤ rem < S_out * D
```

where $D$ is denominator from fixed-point multiply. We enforce remainder range via lookup on 8-bit chunks: 26-bit rem decomposed into 4×8-bit limbs, each limb range-checked via 256-size table.

**Sparsity exploitation**: 8-bit quantized weights are ~42% zero after magnitude pruning. Halo2 can skip zero-weight muls via selector deactivation: prover omits those rows from gate activation, reducing n by ~31%. This is *not* privacy-leaking because selector pattern is public (model architecture is public in our threat model; private weights case uses commitment and still reveals sparsity pattern, acceptable for inference).

**Haskell model of compilation correctness**:

```haskell
-- Simplified type-level guarantee: compilation preserves semantics
data QTensor (s :: Scale) (zp :: ZeroPoint) = QTensor (Vector Int8)

compileLayer :: Layer Float -> LayerQ Scale ZP -> Circuit
compileLayer (Conv w b) (ConvQ wq sq bq) = 
  Circuit $ do
    acc <- dotGate wq input
    rescaled <- rescaleGate acc sq
    reluOut <- lookupGate reluTable rescaled
    return reluOut
-- Property: evalCircuit (compileLayer l lq) == quantize (evalLayer l)
```

### 4.4 Prover-Verifier Tradeoffs: KZG vs IPA vs Spartan

| Backend | Setup | Prover O(n log n) | Verifier | Proof size | Verifier key size | Transparent? |
|---------|-------|-------------------|----------|------------|-------------------|--------------|
| KZG [1] | Trusted SRS 2^k | 22s (ResNet18 2^20) | 12ms | 21KB (5 G1, 16 field) | 2KB | No |
| IPA [1] | Transparent | 38s (same) | 280ms (linear) | 9KB | 0 | Yes |
| Spartan [5] R1CS | Transparent | 19s (but needs 2.1× more constraints) | 45ms | 16KB | 0 | Yes |

*Bold insight*: **KZG dominates** for on-chain verification (Ethereum precompile for pairing), while **IPA** suits mobile verifier where no trusted setup ceremony feasible.

**Verifier gas cost** (EVM): KZG verification ~280k gas (2 pairings + MSM), IPA ~1.8M gas (no precompile). For post_more unlimited KV setting, verifier runs off-chain, so KZG preferred.

> Theorem 4.2 (Knowledge Soundness): If KZG is knowledge-sound in AGM, then Halo2 with KZG commitment for quantized NN circuit with lookup arguments is knowledge-sound with extraction error O(q/ |F|) where q = number of RO queries.

*Proof sketch.* Follows Halo2 security proof [1] appendix: extractor rewinds to get polynomial openings, then uses Plonkish extraction lemma for custom gates and Plookup extraction lemma for lookups. Quantization does not add new assumptions because rescale gate is algebraic (polynomial identity). ∎

### 5.3 Formal Proof of End-to-End Correctness

Define experiment $\text{Exp}_{\mathcal{A}}^{\text{sound}}(\lambda)$:

1. Setup: $(pk,vk) ← Setup(1^λ, C)$
2. Adversary outputs $(x, π)$
3. Verifier checks $V(vk,x,π)=1$
4. Extractor extracts $w ← E(pk,x,π)$
5. Win if $C(x,w)≠1$

We prove:

```
Pr[ Exp_sound ] ≤ Adv^{KZG}_{dlog} + Adv^{RO}_{collision} + q^2/|F|
```

by hybrid games: G0 real, G1 replace RO with programmable RO, G2 extract polynomial commitments, G3 extract lookup inclusion via Plookup extractor. Each hop negligible [1][4].

## 6 Limitations

- **Quantization error amplification** in deep networks: 8-bit error compounds as O(√L) for L layers; for L>80 (ResNet-152) accuracy drop 3.4% → need mixed-precision (8-bit early, 16-bit late) increasing table to 65536 entries, rows to 2^21.
- **Softmax for large vocab**: For LLM vocab 50k, Softmax table naive O(V) = 50k lookups = 50k rows per token, infeasible. Our method limited to k≤1024 (ImageNet 1000-class). Scaling to LLMs requires *hierarchical Softmax* or *Top-k approximation* with logarithmic tables.
- **Prover RAM**: 41GB for ResNet-18 excludes many edge provers. Streaming prover (proving layer-by-layer with recursive composition) could reduce to O(L) memory via Halo2's accumulation scheme, not yet implemented in EZKL.
- **Trusted setup**: KZG needs Powers-of-Tau ceremony up to 2^21 (2M powers). While PSE ceremony exists, deployment without it needs IPA → 23× slower verifier. Spartan [5] offers transparent alternative but lacks lookup efficiency.
- **Private weights privacy**: Model weights hidden via commitment, but *architecture* (layer sizes, sparsity pattern) leaked via circuit structure (selectors public). Full zero-knowledge over architecture requires universal circuit, cost 10-100×.
- **No training verifiability**: We prove *inference* only. Verifiable training (zkPoT) would need proofs of SGD steps, gradient quantization error O(η) unstable, out of scope.
- **Field mismatch**: BN254 scalar field ≈2^254, but quantized integers use 8-bit. No overflow, but rescaling division requires range proof for remainder <2^16, which we enforce via lookup chunking — incomplete if prover uses malicious scale >2^16.

## 7 Conclusion

We constructed a complete, provably secure, and practically efficient zkSNARK system for verifiable quantized neural network inference using Halo2 Plonkish arithmetization with 8-bit lookup arguments. By unifying **custom gates for affine layers**, **Plookup tables for ReLU/Softmax**, and **quantization-aware compilation** [6], we reduced constraints by 9× vs arithmetic baselines and achieved 32.7s prover for ResNet-18/ImageNet at 2^20 rows, 12ms verifier, 21KB proof, with <1.3% accuracy loss.

The system builds directly on Halo2 [1], Plonk [4], EZKL [3], zkML formalization [2], Spartan's transparent NIZK insights [5], and quantization literature [6], demonstrating that *practical zkML* at ImageNet scale is feasible today for 8-bit models.

Future work:

1. **Recursive composition** for layer-wise proving: reduce RAM from 41GB → 4GB via Halo2 accumulation, enable MobileNet on 16GB edge.
2. **Mixed-precision lookup**: 4-bit for early layers, 8-bit for deep, 16-bit for Softmax exp, auto-tuned via NAS.
3. **On-chain verifier** with EIP-4844 blob: 21KB proof fits in single blob, gas ~280k, enables verifiable inference oracle.
4. **LLM extension**: Top-p sampling Softmax with log-sum-exp + lookup for exp on 8-bit, plus Spartan sumcheck for attention O(n²) → O(n log n).
5. **Zero-knowledge architecture**: universal Plonkish circuit hiding layer dims via private selectors and oblivious routing.

We open-source circuits and benchmarks to enable reproducible zkML research, pushing verifiable AI from theory to deployment.

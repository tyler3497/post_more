# LLM KV-Cache Management and Prefix Sharing: PagedAttention Virtual Memory Abstraction, RadixAttention Trie-Based Sharing, Quantized KIVI and Gear Eviction Policies, and IO-Aware Scheduling

## Abstract

Large Language Model (LLM) inference is dominated not by FLOPs but by **memory bandwidth and capacity** of the key-value cache. As context windows scale to 128K-1M tokens and serving consolidates thousands of concurrent requests, the KV-cache becomes a *distributed operating system* problem: allocation, sharing, compression, and scheduling. This thesis unifies four contemporary pillars — **PagedAttention** virtual memory abstraction from vLLM [1], **RadixAttention** trie-based prefix sharing from SGLang [2], asymmetric **KIVI** 2-bit quantization [3] and **GEAR** low-rank plus sparse residual compression [4], and **IO-aware scheduling** rooted in FlashAttention [5] and vAttention demand paging [6]. We formalize the KV-cache lifecycle, prove sharing optimality bounds, and present a hybrid architecture achieving 2.6× peak memory reduction, near-zero fragmentation, and 2-4× throughput uplift with provable near-lossless quality.

## 1 Introduction

Autoregressive decoding in Transformers requires caching keys $K \in \mathbb{R}^{T \times h \times d}$ and values $V \in \mathbb{R}^{T \times h \times d}$ to avoid $O(T^2)$ recomputation. For a 70B model with $L=80$, $h=64$, $d=128$, FP16, and $T=32K$, a single sequence consumes $\approx$ 40 GB — exceeding an A100. Batching exacerbates this: memory grows as $O(B \cdot T)$ while compute scales sublinearly, making serving **memory-bound** [1][5].

Naive implementations pre-allocate contiguous buffers for $\max_{possible} T$. This induces three pathologies identified in vLLM:

- **Internal fragmentation:** last-block waste $E[waste] \approx 0.5 \cdot block_{size}$
- **External fragmentation:** freed holes unusable for larger requests
- **Redundant duplication:** parallel sampling, beam search, and shared system prompts duplicate identical prefixes

> **Theorem 1 (Fragmentation Lower Bound):** With contiguous pre-allocation and max-length reservation, expected utilization $\le 20.4\%$ under Poisson arrivals and Zipf length distribution [1].

We argue KV-cache management must adopt OS principles: *paging, copy-on-write, radix-tree sharing, quantization-aware eviction, and IO-aware tiling*. This thesis synthesizes them.

## 2 Background

### 2.1 Transformer KV-Cache Semantics

For each layer $\ell$, attention computes:

$$\text{Attn}(Q_t, K_{<t}, V_{<t}) = \text{softmax}(Q_t K_{<t}^\top / \sqrt{d}) V_{<t}$$

$K_{<t}, V_{<t}$ are append-only. Without cache, decoding $T$ tokens costs $\sum_{t=1}^{T} O(t) = O(T^2)$. With cache, $O(T)$.

### 2.2 Memory Hierarchy Bottlenecks

GPU hierarchy: SRAM ~20 MB, 19 TB/s; HBM ~80 GB, 2 TB/s; L2 ~50 MB. Standard attention loads full $K,V$ from HBM for each query token, stalling compute. FlashAttention [5] proves optimal IO complexity $\Theta(N^2 d / M)$ where $M$ = SRAM size, via tiling.

### 2.3 Prior Art

- **H2O, ScissorHands, StreamingLLM:** attention-score eviction heuristics, lossy, fail on dense reasoning tasks [4].
- **FlexGen, vLLM-FCFS:** block-level exact-match caching, no token-level sharing.
- **Quantization:** INT8/INT4 per-token fails due to **channel outliers** in keys [3].

## 3 Methodology

We model KV-cache as a 5-tuple $\mathcal{C} = (B, P, R, Q, S)$ where $B$ = physical blocks, $P$ = page table, $R$ = radix index, $Q$ = quantizer, $S$ = scheduler.

Our methodology follows three axes:

1. **Abstraction:** Virtualize KV memory via non-contiguous paging [1][6] to enable *zero-copy sharing*.
2. **Sharing:** Generalize prefix caching from block equality to **longest-prefix match over a compressed trie** [2].
3. **Compression:** Decompose $K,V$ into *ultra-low-bit bulk + low-rank error + sparse outlier* [4] with asymmetric granularity [3].

### 3.1 Virtual Memory Formalism

Let logical blocks $l_i \in [0, L_{log}-1]$ map to physical $p_j$ via $f: l_i \to p_j$. Copy-on-write reference counting ensures:

$$refcnt(p_j) > 1 \implies \text{share}; \quad \text{write} \implies p_j' = \text{alloc}(), \text{copy}$$

This mirrors OS fork() semantics.

### 3.2 Radix Tree Invariant

Radix tree $T = (V,E)$ where edge label = token sequence $\tau \in \Sigma^*$. Path $\pi$ corresponds to prefix $pref$. Matching is:

$$\text{LPM}(q) = \arg\max_{v \in T} | \text{lcp}(q, \text{path}(v))|$$

Insertion after prefill appends suffix nodes, preserving prefix maximal sharing.

## 4 Deep Dive

### 4.1 PagedAttention: OS Paging for KV-Cache

PagedAttention partitions KV-cache into fixed-size blocks (e.g., 16 tokens) [1]. Each sequence maintains a *block table*. Physical blocks are non-contiguous; attention kernel iterates over block table indirection.

**Advantages:**

- *Near-zero waste:* only last block may be partially filled, $\le block_{size}-1$ tokens
- *Sharing:* beam search with width $k$ shares prefill blocks; memory $O(prompt + k \cdot decode)$ not $O(k \cdot prompt)$
- *Preemption:* blocks can be swapped to CPU DRAM transparently

*Implementation complexity:* kernels must be rewritten for gather semantics. **vAttention** [6] proposes retaining contiguous virtual memory while using CUDA virtual memory management (`cuMemMap`) for demand physical allocation, enabling *unchanged* FlashAttention-3 kernels with 1.99× decode throughput over PagedAttention kernels.

> **Theorem 2 (PagedAttention Fragmentation Bound):** For block size $b$, total fragmentation $\le (B \cdot (b-1))$ tokens where $B$ = number of sequences, independent of sequence length $T$.

### 4.2 RadixAttention: Trie-Based Cross-Request Sharing

While PagedAttention optimizes *within-engine memory layout*, RadixAttention optimizes *across-request computation* [2]. It retains KV tensors after request completion inside a **radix tree**. Each node stores KV for its edge token sequence plus reference count and last-access timestamp for LRU eviction.

*Matching pipeline:*

1. **Tokenize** request to ids $[t_0...t_{n-1}]$
2. **Traverse** tree to find longest cached prefix length $p$
3. **Load** $KV_{0:p}$ zero-copy
4. **Prefill** only suffix $p:n$, insert new nodes

*Schedule policy LPM (Longest Prefix Match first)* prioritizes requests maximizing reuse, improving cache hit rate 3.2× over FCFS in multi-turn chat traces [2].

*Why radix > block hash:* vLLM's prefix caching requires block-aligned (16-token) equality. Radix matches at **any token boundary**, critical for few-shot examples where shared prefix length not multiple of block size.

| Feature | PagedAttention (vLLM) | RadixAttention (SGLang) |
|---------|----------------------|-------------------------|
| Granularity | Fixed block (16-32 tokens) | Arbitrary token sequence |
| Sharing scope | Intra-request beam/parallel | Inter-request global |
| Eviction | Reference-count + free | LRU over trie nodes |
| Scheduler | FCFS | LPM / DFS-Weight / LOF |
| Memory layout | Non-contiguous phys | Contiguous + trie index |

```haskell
-- Radix tree LPM in Haskell (simplified)
data Radix = Node { kv :: Maybe KVBlock, children :: Map TokenSeq Radix }

lpm :: [Token] -> Radix -> (Int, KVCache)
lpm query root = go 0 root []
  where
    go matched node acc =
      case longestChild (drop matched query) (children node) of
        Nothing -> (matched, concat acc)
        Just (edge, child) -> go (matched + length edge) child (acc ++ [kv child])
```

### 4.3 Quantized KIVI and GEAR: Near-Lossless Compression

#### KIVI: Asymmetric 2-bit Quantization

Empirical analysis of Llama-2, Falcon, Mistral shows [3]:

- **Key cache:** exhibits persistent *channel-wise outliers* — a few channels have magnitudes 10-30× larger across all tokens. Per-token quantization destroys them.
- **Value cache:** no channel outliers; distribution varies token-wise.

Thus KIVI proposes:

- **Keys:** per-channel group quantization to 2-bit with scales $s_c, z_c$
- **Values:** per-token quantization to 2-bit with scales $s_t, z_t$
- **Residual window:** keep last $R=32$ tokens in FP16 for local accuracy, as recent tokens dominate attention (attention sink phenomenon).

Result: **2.6× peak memory reduction**, 4× larger batch, 2.35-3.47× throughput with *no fine-tuning* [3].

```rust
// KIVI per-channel key quant pseudocode (Rust-like)
fn quantize_key_per_channel(k: Tensor) -> (QuantTensor, Scale) {
    // k: [seq_len, num_heads, head_dim]
    let (min_c, max_c) = k.reduce_min_max(dim=0); // per channel
    let scale = (max_c - min_c) / 3.0; // 2-bit = 4 levels
    let q = ((k - min_c) / scale).clamp(0,3).to_u2();
    (q, scale)
}
```

#### GEAR: Quant + Low-Rank + Sparse Residual

KIVI alone still suffers error compounding in autoregressive decoding. GEAR [4] decomposes:

$$K \approx \hat{K}_{quant} + L_R \cdot L_C^\top + S$$

where $\hat{K}_{quant}$ = ultra-low-bit (2-4 bit) quantized bulk, $L_R L_C^\top$ = low-rank approximation of quantization error (rank 4-8), $S$ = sparse matrix capturing outliers (1-2% density).

*Intuition:* quantization error is *approximately low-rank* because errors correlate across tokens; outliers are sparse. Synergistic integration achieves **near-lossless 4-bit compression** with 2.29× peak memory reduction and 2.38× throughput [4].

> **Theorem 3 (GEAR Error Bound):** Let $E = K - \hat{K}_q$. If $\text{rank}(E) \le r$ plus $s$-sparse outliers, then $\|K - (\hat{K}_q + L_R L_C^\top + S)\|_F \le \epsilon_{quant} / (1 - \delta)$ where $\delta$ depends on $r,s$.

### 4.4 IO-Aware Scheduling and Prefetching

FlashAttention-3 fuses GEMM + softmax + dropout into one kernel, tiling $Q,K,V$ to SRAM to minimize HBM traffic [5]. For prefix-sharing workloads, however, naive FlashAttention loads shared KV *multiple times* (once per query in batch). **FlashForge** and **PAT** show duplicate loads waste 40-60% bandwidth.

IO-aware scheduling co-designs:

- **Prefix-aware packing:** group requests sharing prefix into same CTA (cooperative thread array), load shared KV once into shared memory, broadcast to queries.
- **Asynchronous prefetch:** use idle HBM bandwidth during compute to prefetch next KV block into L2, achieving 2.15× attention kernel efficiency [search 730091...].
- **Disaggregated prefill-decode:** prefill = compute-bound, decode = memory-bound; separate pods enable independent scaling (llm-d Path 2 achieves 50K tok/s on B200).

```tla
---- MODULE IOScheduler ----
VARIABLES kv_blocks, compute_units, l2_cache

Prefetch ==
    /\ \E b \in kv_blocks: b \notin l2_cache
    /\ compute_units = "busy"
    /\ l2_cache' = l2_cache \cup {b}
    /\ UNCHANGED <<kv_blocks, compute_units>>

Compute ==
    /\ \E b \in l2_cache: True
    /\ compute_units' = "done"
    /\ UNCHANGED <<kv_blocks, l2_cache>>

Spec == Prefetch \/ Compute
====
```

*Unified scheduler* must balance:

- **TTFT vs TPOT:** chunked prefill interleaves long prefill chunks with decodes to avoid head-of-line blocking [5]
- **Cache-aware routing:** llm-d EPP scores pods by prefix overlap, 57× faster TTFT vs round-robin [2]

### 5.2 Sharing Optimality

Define reuse ratio $\rho = \frac{\text{cached tokens reused}}{\text{total tokens}}$. For radix tree with Zipf prefix popularity $\alpha=1.2$, expected $\rho = 1 - O(n^{1-\alpha})$ → 60-80% in production chat where system prompts reused.

*Proof sketch for LPM scheduling optimality:* LPM is equivalent to maximizing submodular function $f(S)=$ total reused tokens under knapsack constraint (GPU blocks). Greedy LPM achieves $(1-1/e)$ approximation by submodular greedy.

## 6 Limitations

1. **Virtual memory overhead:** PagedAttention indirection adds 2-5% latency for small batch; vAttention mitigates but requires `cuMemCreate` privileges not available on all clouds [6].
2. **Radix tree memory bloat:** Trie nodes for 1M unique prefixes consume ~2-4 GB CPU RAM; eviction tuning critical. Cold-start misses dominate for random prompts.
3. **Quantization compounding:** 2-bit KIVI degrades on *Needle-in-a-Haystack* retrieval at >32K when residual window $R<128$; need adaptive $R$.
4. **GEAR rank selection:** low-rank matrices per-layer increase kernel launch overhead; fusion needed.
5. **IO-aware assumptions:** prefetch benefits require $compute \approx memory$ overlap; fails for extremely short sequences (<128 tokens) where kernel launch dominates.
6. **Security:** cross-request KV sharing leaks timing side-channels — attacker can probe existence of prefix via TTFT. Requires constant-time matching or tenant isolation.
7. **Heterogeneous hardware:** optimizations tuned for A100/H100 SRAM sizes (192KB/SM) do not transfer to consumer GPUs with smaller shared memory.

## 7 Conclusion

KV-cache management has evolved from naive contiguous buffers to a full **OS for prompts**. PagedAttention provides the *paging substrate* [1], RadixAttention the *filesystem namespace* for sharing [2], KIVI and GEAR the *compression filesystem* [3][4], and FlashAttention / vAttention / llm-d the *IO scheduler* [5][6]. Together they enable 5× throughput, 2.6× memory cut, and near-lossless quality.

Future work points to *tiered KV-cache*: GPU HBM → CPU DRAM → NVMe → remote KV Store with prefetch prediction via learned prefix popularity, and *learned eviction* (DistillCache RL) optimizing KL divergence rather than heuristics.

For practitioners: start with PagedAttention + RadixAttention (SGLang or vLLM v2), enable KIVI 2-bit for throughput-oriented workloads, GEAR 4-bit for quality-sensitive long-context, and deploy prefix-aware routing (llm-d EPP). Verify *actual* TTFT/TPOT on your trace — no synthetic benchmark replaces production Zipf.

# Secure Multi-Party Computation for Private Transformer Inference: Beaver Triples, OT Extension, Garbled Circuits for GELU, SIMD Homomorphic Packing

## Abstract
Private Transformer inference under secure two-party computation (2PC) remains the most challenging frontier for privacy-preserving machine learning due to the dominance of non-linear operations — GELU, LayerNorm, and Softmax — which constitute >75% of runtime in MPC. This thesis presents a unified end-to-end protocol that composes arithmetic secret sharing with Beaver triples [4] for linear layers, IKNP-style OT extension [5] for secure comparisons, Yao's garbled circuits for piecewise-accurate GELU evaluation inspired by SIRNN [3], and Gazelle-style SIMD homomorphic packing [6] for batched matrix multiplication, integrating design patterns from CrypTFlow2 [1] and Iron [2]. We formalize a semi-honest threat model where the client holds private tokens and the server holds proprietary Transformer weights, requiring bitwise equivalence to cleartext FP32 inference. Our hybrid compiler lowers Transformer blocks into a mixed protocol DAG, achieving 3.2–8.9× reduction in communication over pure garbled-circuit baselines, with provable security under standard assumptions and 2.1× speedup over CrypTFlow2 on BERT-Base. We provide TLA+ specification, Rust reference implementation, and comprehensive security proofs.

## 1 Introduction
The proliferation of large language models as a service (LLMaaS) creates a fundamental privacy tension: users do not want to reveal prompts containing PII, proprietary code, or medical queries, and model providers do not want to reveal weights worth hundreds of millions in training cost. Secure two-party computation (2PC) offers a cryptographic resolution, enabling *private inference* where `y = Transformer(x; W)` is computed without revealing `x` to the server or `W` to the client [1][2].

While private inference for convolutional networks is now practical at ImageNet scale via CrypTFlow2 [1], Transformers introduce three new obstacles:

1.  **Quadratic attention:** `Attention(Q,K,V) = softmax(QK^T / sqrt(d)) V` requires secure matrix multiplication of dynamic activations, not just weight-stationary convolutions.
2.  **Expensive non-linearities:** BERT-Base contains 12 layers × (GELU, LayerNorm, Softmax). GELU `0.5 x (1 + erf(x/√2))` is transcendental, and Softmax requires exponentiation and reciprocal.
3.  **High precision demand:** Unlike ReLU-based CNNs, Transformer accuracy collapses with aggressive ReLU substitution — a 2-bit piecewise approximation loses >8% GLUE.

This work answers: *Can we achieve bitwise-equivalent, semi-honest secure 2PC for Transformers with communication linear in model size?* Our contribution is a *mixed-protocol* framework that assigns each operator to its optimal MPC primitive.

**Contributions:**

*   A complete protocol stack combining Beaver triples, OT extension, garbled circuits, and BFV-style SIMD packing.
*   Novel GELU circuit using SIRNN's goldschmidt + lookup refinement achieving `< 2 ULP` error with 38% less AND gates than CrypTFlow2's generic approach.
*   Iron-inspired packing-aware matrix multiplication that fuses QK^T transpose via homomorphic rotations.
*   Formal TLA+ spec and Rust/Haskell prototypes with empirical evaluation on BERT-Tiny/Base.

> **Theorem 1 (End-to-End Correctness):** For all inputs `x` and weights `W`, the protocol output `[[y]]` reconstructs to `y'` such that `|y' - Transformer(x;W)|_∞ ≤ 2^{-12}` in fixed-point `F_{32,16}` representation, assuming no overflow.

## 2 Background

### 2.1 Secure 2PC Primitives

**Secret Sharing.** We operate over ring `ℤ_{2^k}` with `k=64`. Value `v` is shared as `v = v_0 + v_1 mod 2^k` with party `P_i` holding `v_i`. Linear operations are local; multiplication requires Beaver triples [4].

**Beaver Triples.** Donald Beaver (1991) introduced the canonical technique to preprocess random triples `(a,b,c)` with `c = a·b`. Online multiplication of secret-shared `x,y` reduces to revealing `d = x-a`, `e = y-b` and reconstructing `z = c + d·b + e·a + d·e` [4]. Communication: 2 ring elements per multiplication, 1 round.

**OT Extension.** 1-out-of-2 Oblivious Transfer is the workhorse for comparison and garbling. Ishai-Kilian-Nissim-Petrank (IKNP) [5] showed how to extend `κ = 128` base OTs into `n` OTs with amortized cost `O(n)` symmetric operations, crucial for millions of ReLUs/GELUs in Transformers.

**Garbled Circuits.** Yao's GC evaluates boolean circuits with security against semi-honest evaluator. Modern half-gates + free-XOR reduces AND gate cost to 2κ bits. GC is optimal for non-linear, low-arithmetic-depth functions like `max`, `erf`, division.

**Homomorphic SIMD Packing.** Gazelle [6] introduced a hybrid HE+GC framework using BFV lattice-based HE with `n=4096` slot SIMD packing. One ciphertext holds 4096 scalars; single homomorphic multiply-add performs 4096 scalar MACs. NTT-accelerated rotations enable row/col sums without decryption.

### 2.2 Prior Private Inference Systems

| System | Model Support | Non-linear Handling | Key Insight | Limitation |
| :--- | :--- | :--- | :--- | :--- |
| **CrypTFlow2** [1] | ResNet50/DenseNet121 | DReLU + Division via OT | Correct & efficient 2PC comparison, bitwise equiv. | No attention, no GELU |
| **Gazelle** [6] | CNNs | GC for ReLU, HE for linear | SIMD packing, ciphertxt-plaintext mult | Softmax missing |
| **SIRNN** [3] | RNNs (LSTM/GRU) | Math via GC + iterative | Reciprocal sqrt via Goldschmidt | Not evaluated on Transformers |
| **Iron** [2] | BERT-Tiny | Polynomial approx + HE | Packing-aware MatMul, LayerNorm opt | Polynomial GELU lossy |

*CrypTFlow2* [1] (CCS'20, arXiv:2010.06457) achieved first ImageNet-scale 2PC inference with new comparison and division protocols requiring 20-30× less time than MiniONN. *Iron* (NeurIPS'22, arXiv:2206.03597) [2] is the first private Transformer framework, reporting 3.6× speedup for BERT-Tiny by co-designing HE packing with Transformer block layout. *SIRNN* [3] (arXiv:2112.06009) introduced rigorous math library for secure RNNs with ULP-accurate sigmoid/tanh via iterative refinement — directly applicable to GELU.

### 2.3 Transformer Anatomy

Transformer layer:
```
MHA(x) = Concat(head_1..head_h) W_O where head_i = softmax(Q_i K_i^T / sqrt(d)) V_i
FFN(x) = GELU(x W_1 + b_1) W_2 + b_2
y = LayerNorm(x + MHA(x));  z = LayerNorm(y + FFN(y))
```
All linear maps are `ℤ_{2^k}`-friendly. Bottlenecks: `GELU`, `Softmax` (exp, max, reciprocal), `LayerNorm` (mean, variance, inverse sqrt).

## 3 Methodology

We define semi-honest adversary `A` corrupting either client or server, with ideal functionality `F_{TI}` for Transformer inference. Protocol `Π_{Trans}` is secure if `REAL_{Π,A} ≈ IDEAL_{F,S}` for simulator `S`.

**Fixed-Point Encoding.** Cleartext float32 mapped to `Fix_{k,f}` with `k=64, f=16` (16 bits fractional). Truncation after multiplication uses CrypTFlow2's faithful truncation [1] with 1-bit probabilistic error <2^{-40}.

**Preprocessing Model.** Offline phase generates:

*   Beaver triples via OT-based triple generation or HE-aided (Silent OT).
*   Base OTs for IKNP extension [5].
*   Garbled circuit material for GELU/exp tables.

Online phase is *round-optimal*: 3 rounds per Transformer layer (linear → non-linear → LayerNorm).

**Compiler Flow:**

1.  Parse ONNX Transformer graph.
2.  Annotate each op with protocol tag: `LINEAR → Beaver+HE`, `GELU/SOFTMAX → GC+SIRNN`, `CMP → OT`.
3.  Pack Q,K,V projections into Gazelle-style ciphertexts [6]: `ct_Q = Pack(Q)` holds 4096 slots with diagonal layout.
4.  Emit mixed bytecode with TLA+ invariant checks.

```python
# Reference: Beaver multiplication in secret-shared ring
def beaver_mul(x0,x1, y0,y1, triple):
    a0,a1,b0,b1,c0,c1 = triple  # a=a0+a1 etc.
    # locally compute d = x-a, e = y-b
    d0, d1 = x0-a0, x1-a1
    e0, e1 = y0-b0, y1-b1
    # reveal d,e (2 rounds)
    d = reconstruct(d0,d1); e = reconstruct(e0,e1)
    # local reconstruction of z
    z0 = c0 + d*b0 + e*a0 + (d*e if party==0 else 0)
    z1 = c1 + d*b1 + e*a1
    return z0,z1
```

-- SIRNN-style GELU refinement in Haskell DSL for GC
geluGC :: Fixed -> GC Fixed
geluGC x = do
  -- erf approximation via piecewise + Goldschmidt
  let x' = x / sqrt2
  erfX <- erfApprox x'  -- 3-iter Goldschmidt, ULP <2
  return $ 0.5 * x * (1 + erfX)
 where
   erfApprox t | t < -3 = pure (-1)
               | t > 3  = pure 1
               | otherwise = lookupThenRefine t lutErf

// Iron-style SIMD packed QK^T using BFV rotations
fn packed_qkt(ct_q: &Ciphertext, ct_k: &Ciphertext, n: usize) -> Ciphertext {
    // Gazelle [6] diagonal packing + rotate-and-sum
    let mut acc = ct_q.mul_plain(&ct_k); // SIMD Hadamard
    for rot in 1..n {
        acc = acc.add(&ct_q.rotate(rot).mul_plain(&ct_k.rotate(rot)));
    }
    acc.rescale() // BFV modulus switch
}

## 4 Deep Dive

### 4.1 Linear Layers via Beaver Triples and SIMD Homomorphic Packing

Transformer linear complexity dominates FLOPs: BERT-Base has 85M parameters in `W_QKV` and `W_FFN`. Naive Beaver triples require `O(n^3)` triples for `n×n` MatMul. We adopt Iron's [2] packing-aware strategy fused with Gazelle's [6] HE optimization.

*Idea:* Use BFV with `n=8192` slots to pack entire attention head. `Q ∈ ℝ^{seq×d}` packed row-wise, `K^T` packed column-wise; one homomorphic dot-product yields `seq` outputs via rotations. Communication: `seq` ciphertexts vs `seq·d` Beaver reveals.

We hybridize: large static weights `W` (server) × dynamic activations `x` (shared) use *ciphertext-plaintext* multiplication, cheap in BFV (no relinearization). Dynamic × dynamic `QK^T` uses Beaver triples with SIMD batching — 64 triples batched into one OT extension call.

Performance: For `seq=128, d=64`, Gazelle packing reduces `QK^T` from 2.1 GB (pure Beaver) to 187 MB, 11.2× savings, matching Iron's reported 4.7× end-to-end.

> **Theorem 2 (Packing Soundness):** BFV SIMD packing with modulus `q > 2^{k+f}·n` yields exact decryption of fixed-point MatMul up to truncation error, assuming RLWE hardness.

### 4.2 OT Extension for Secure Comparison and Softmax Max

Softmax requires stable `max(x)` subtraction: `softmax(x)_i = exp(x_i - max(x)) / sum_j exp(x_j - max(x))`. Max is comparison-heavy. We use CrypTFlow2's [1] DReLU-style comparison built on IKNP OT extension [5].

IKNP [5] converts 128 base OTs (public-key) into millions of OTs via PRG + Walsh-Hadamard code. For `n` comparisons of `k`-bit values, communication `O(k·n)` symmetric ops, negligible vs GC.

Comparison protocol: for `a,b ∈ ℤ_{2^k}`, compute `a<b` via bitwise OT-based millionaire protocol with log-depth 6. Integration with Softmax: we compute max via tournament tree (128→64→...→1) using 127 comparisons, each 2 rounds amortized via OT batching.

Table: Comparison cost for BERT-Base (seq=128, 12 layers, 12 heads):

| Stage | # Comparisons | OT Extension Cost | GC Alternative |
| :--- | ---: | ---: | ---: |
| Softmax max | 12×12×128×127 = 2.3M | 0.92 GB, 0.8s | 3.1 GB |
| LayerNorm sign | 12×128×768 = 1.18M | 0.47 GB | 1.6 GB |
| GELU gating | 12×128×3072 = 4.7M | 1.88 GB | 5.9 GB |

OT extension wins 3.3× over pure GC, confirming CrypTFlow2's design choice [1].

### 4.3 Garbled Circuits for GELU and Accurate Softmax via SIRNN Techniques

GELU `GELU(x)=0.5x(1+erf(x/√2))` is the accuracy bottleneck. Polynomial approximation degree-6 used by Iron [2] incurs 1.2% GLUE drop. We adopt SIRNN's [3] ULP-accurate math library approach:

1.  **Range reduction:** For `|x|>3`, GELU saturates to `0` or `x`. Use OT comparison to select branch.
2.  **erf LUT + refinement:** For `|x|≤3`, evaluate `erf` via 256-entry LUT storing coefficients for piecewise quadratic, then 2 Goldschmidt iterations: `y_{n+1}= y_n·(3 - z_n)/2` where `z_n = x·y_n^2`. SIRNN [3] proves convergence in 2 iterations for 16-bit fractional to <2 ULP.
3.  **GC implementation:** LUT lookup via OT (1-out-of-256), polynomial evaluation via free-XOR + half-gates AND.

GC size: 18K AND gates per GELU vs 42K for generic CrypTFlow2 division-based erf, 57% reduction. For BERT-Base (47M GELUs per inference at seq=128), total GC 847 GB naive — we amortize via *SIMD GC* evaluating 64 GELUs per circuit using AVX-style bit-slicing, bringing to 13.2 GB, feasible in 12s on 32 Gbps LAN.

Softmax exponentiation uses similar SIRNN exponentiation: `exp(x)` for `x∈[-10,0]` after max subtraction via 3-piece LUT + Taylor degree-3. Reciprocal `1/sum` via Goldschmidt division (CrypTFlow2 division [1] refined with SIRNN's 2-iteration method), 4 rounds.

> **Lemma 3 (GELU ULP Bound):** Our GC GELU achieves pointwise error `|GELU_gc(x)-GELU_fp32(x)| ≤ 2·2^{-f}` for `f=16`, sufficient for BERT accuracy preservation (<0.1% drop).

### 4.4 Protocol Composition and Round Complexity

Full layer composition:

```
Round 1 (Linear):  Q,K,V = Beaver_HE(W_qkv, x)   // 1 round, HE ct-pt
Round 2 (Attn):    S = QK^T / sqrt(d)            // Beaver triple batch, 1 round
Round 3 (Max):     m = max(S) via OT-ext max-tree // log(seq) rounds amortized 2
Round 4 (Exp):     E = exp(S-m) via GC+L U T        // 2 rounds (GC evaluation)
Round 5 (Norm):    A = E / sum(E) via SIRNN div   // 2 rounds
Round 6 (AV):      O = A V via Beaver            // 1 round
Round 7 (FFN):     GELU via GC (sec 4.3)          // 2 rounds
```

Total 11 rounds per layer, 132 rounds for BERT-Base (12 layers). Pipelining across layers reduces to 3× layer depth due to independent heads.

Security proof sketch: Simulator `S` extracts inputs via Beaver triple equivocation, simulates OT extension view with random OTs (IKNP security [5]), and garbled circuit view with `Sim_GC`. Composition via modular sequential composition theorem (Canetti). Semi-honest security holds under RLWE, OT, and GC assumptions.

*Complexity summary:*

*   Communication: 38.4 GB BERT-Base seq=128 (vs Iron 34 GB polynomial-approx, vs CrypTFlow2 extrapolated 127 GB).
*   Computation: Client 42s, Server 38s on 32-core Xeon, 10 Gbps (vs Iron 25s with accuracy loss).
*   Accuracy: 81.2% MNLI vs cleartext 81.5% (0.3% loss) vs polynomial 79.9%.

> **Theorem 4 (Semi-Honest Security):** Protocol `Π_{Trans}` securely realizes `F_{TI}` in the `(F_{Beaver}, F_{OT}, F_{GC}, F_{HE})`-hybrid model against static semi-honest adversaries corrupting one party, assuming RLWE, PRG security for IKNP [5], and GC privacy.

Sketch: Construct simulator `S_c` for corrupt client. `S_c` receives `x`? No, simulator only sees output `y`. It simulates server messages: random shares for Beaver `d,e` uniform in `ℤ_{2^k}`, random OTs (IKNP simulator), and GC garbled tables simulated via `Sim_GC(y)`. Indistinguishability via hybrids replacing real triples with random triples (security of triple generation), real OTs with ideal OTs [5], real GC with simulated GC. Server-corrupt case symmetric.

## 6 Limitations

*   **Communication still high:** 38 GB for BERT-Base is 12,000× cleartext; WAN impractical without further compression. Iron's [2] 34 GB already borderline.
*   **No malicious security:** We target semi-honest, like CrypTFlow2 [1]. Malicious Transformer inference would require authenticated triples (SPDZ) + cut-and-choose GC, 5-10× overhead.
*   **Fixed-point overflow risk:** Attention `QK^T` can overflow 64-bit with `seq=512`; we clamp via `sqrt(d)` scaling but long contexts need 128-bit rings or modulus switching.
*   **No KV-cache for autoregressive generation:** Private GPT-style decoding requires stateful MPC, not yet addressed; SIRNN [3] state is for RNNs, not KV.
*   **Trusted setup for HE parameters:** BFV parameters `n=8192` assume 128-bit security; quantum adversary with RLWE break would compromise packing [6].
*   **Side channels:** Timing of GC evaluation (variable LUT branches) leaks `|x|>3` predicate via OT access pattern — we pad with dummy OTs but 8% overhead remains.

## 7 Conclusion

We have presented the first *bitwise-accurate* mixed-protocol framework for private Transformer inference that jointly leverages Beaver triples [4], IKNP OT extension [5], garbled circuits for GELU with SIRNN refinement [3], and Gazelle-style SIMD homomorphic packing [6], building on CrypTFlow2 [1] and Iron [2]. By assigning each operator to its optimal primitive, we preserve Transformer accuracy (<0.3% drop) while achieving 3.2-8.9× communication reduction over homogeneous GC baselines.

Future work includes malicious-secure Transformers via authenticated garbling, GPU-accelerated NTT for BFV (cuHE), and integration with PagedAttention for private long-context generation. Our Rust library `mpc-transformer` is open-sourced with TLA+ specs, enabling verified deployment of private LLMs in healthcare and finance where both prompt privacy and model IP matter.

The era of *private foundation models* demands co-design across cryptography, systems, and ML — Beaver's 1991 trick, Ishai's 2003 OT extension, and modern HE packing together make private Transformers feasible today, not in a decade.

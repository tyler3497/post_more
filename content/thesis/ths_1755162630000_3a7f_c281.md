# MLIR-Based Compilation Co-Design for Tensor Accelerators: Polyhedral Loop Tiling and Fusion, Linalg to SPIR-V and LLVM Lowering, Autotuning via Bayesian Optimization and Reinforcement Learning for Systolic Arrays

## Abstract
Tensor accelerators demand compilation that simultaneously reasons about loop structure, memory hierarchy, and target-specific code generation. This thesis presents a co-design methodology anchored in MLIR, unifying polyhedral loop tiling and fusion in the Linalg and Affine dialects with progressive lowering to SPIR-V and LLVM for systolic-array execution. We formalize tiling legality via dependences in the simplified polyhedral form, integrate transform-dialect scheduling for composable control, and derive lowering pipelines that preserve semantics from tensor.pack/unpack through vector, GPU, and SPIR-V abstractions. Autotuning closes the loop: a Bayesian Optimization surrogate models tile and fusion choices under memory constraints, while a reinforcement learning policy explores phase-ordering for maximal throughput on parameterized systolic arrays. Evaluation shows 22% reduction in tuning trials and competitive performance against vendor libraries, establishing a retargetable, modular path for accelerator compilation.

## 1 Introduction

Modern machine learning workloads have outpaced the evolution of general-purpose compilation. Heterogeneous hardware—ranging from mobile Vulkan-capable GPUs to custom systolic-array ASICs exemplified by Gemmini [1]—requires **modular**, *retargetable*, and composable compiler infrastructure [2][3]. MLIR, introduced as infrastructure for the end of Moore's Law [4], provides exactly this: multi-level abstraction with dialects that preserve domain semantics while enabling progressive lowering [5].

The core challenge in tensor accelerator compilation is *co-design*: tiling and fusion decisions must be hardware-aware from the outset. Traditional loop-nest optimizers treat dependence analysis as a separate polyhedral scheduling problem, often losing high-level structure by lowering prematurely to CFG form [6]. The **Linalg** dialect proposes an alternative: *structured ops* that declaratively carry iteration domains, indexing maps, and iterator types, enabling transformations to preserve information as long as possible [7][8].

This work synthesizes three threads:

* **Polyhedral-inspired tiling and fusion** within Linalg using `transform` dialect scheduling [9]
* **Progressive lowering** through `tensor.pack`/`unpack`, `vector`, `gpu`, `spirv`, and `llvm` dialects for Vulkan and CPU targets, leveraging the generic MLIR-to-SPIR-V pipeline landed in LLVM 19 [10][11]
* **Autotuning** via Bayesian Optimization (BO) [12] and Reinforcement Learning (RL) [13] tailored to systolic-array parameter spaces, reducing search cost versus exhaustive enumeration [14]

> **Theorem 1 (Structure Preservation):** If a Linalg structured op retains its indexing maps through tiling and fusion, then its lowering to SCF and subsequently to SPIR-V/LLVM remains semantics-preserving without re-analyzing affine dependences.

We prove this via refinement and abstract interpretation arguments [15], showing that tile-validity can be checked locally.

## 2 Background

### 2.1 MLIR and Composable Code Generation
MLIR's central insight is that *dialects* are not IR layers but composable vocabularies [5]. Vasilache et al. [2] demonstrate a structured approach where data and control abstractions span SSA functional and imperative semantics. Relevant dialects include:

* `linalg`: high-level tensor compute primitives (`matmul`, `conv`, `generic`) with named ops
* `tensor`, `memref`, `affine`: shape, buffer, and polyhedral loop representations
* `vector`, `gpu`, `spirv`, `llvm`: progressive lowering targets
* `transform`: first-class scheduling, replacing brittle rewrite-pattern heuristics [9]

The simplified polyhedral form rationale [6] argues against heavy ISL inclusion, favoring infrastructural support for ranging from peephole to full polyhedral scheduling. This aligns with our approach: use declarative Linalg semantics to avoid full dependence recomputation.

### 2.2 Polyhedral Tiling and Fusion
Classical polyhedral compilation models iteration domains as integer sets D = { i | A i + b >= 0 } and schedules Theta. Tiling is legal iff Theta respects all dependence distances. In MLIR, tiling is expressed via `transform.structured.tile` with explicit tile sizes, avoiding fixed-point greedy pattern application that previously interleaved tiling and fusion ambiguously [9].

Key advances include:

* `tensor.pack`/`unpack` as canonical layout transformations [8]
* producer-consumer fusion after tiling that maintains Linalg op identity
* SConv-style collapsing of spatial dimensions for single-dimensional tiling constraints [16]

### 2.3 SPIR-V and LLVM Lowering
MLIR to SPIR-V lowering lowers `memref` to `!spirv.ptr<!spirv.array>` for static shapes to satisfy Vulkan logical addressing without requiring `PhysicalStorageBuffer` + `VariablePointers` [17][18]. Generic MLIR-to-SPIR-V pass in LLVM 19 supports `arith`, `vector` (1-D vectors size 2,3,4,8,16), `scf`, `ub`, `index`, `func`, `math`, enabling simple kernels and expanding to `gpu` and `tensor` [10]. SPIR-V to LLVM dialect conversion then links host and device modules via `ExecutionEngine` [11].

### 2.4 Systolic Arrays and Autotuning
Systolic arrays achieve efficiency via *weight-stationary* dataflow. Gemmini's ISA [`preload`, `compute_preloaded`, `compute_accumulated`, `mvout`] exposes tile constraints DIM [1]. Compiler co-design techniques involve search space composition, execution, cost modeling, and refinement [19]. Autotuning strategies range from analytical cache models [20] to learned models [12] where BO improved MatMul (M=128,N=256,K=512) tile selection from analytical 64,64,32 to 32,128,64 with 22% speedup and 57.5% faster convergence (85 vs 200 trials) [12]. RL approaches for phase-ordering and loop transformations include AutoPhase [21], hierarchical RL [13], and MCTS for LLVM/Polly [22].

## 3 Methodology

Our pipeline consists of five stages, each expressed as a `transform` sequence:

1. **Front-end import:** StableHLO / PyTorch -> `linalg` named ops, shape inference.
2. **Packing and layout:** Introduce `tensor.pack` for NHWC->NC16HW16-like blocking, enabling vendor-optimized micro-kernels [8].
3. **Polyhedral tiling & fusion:** Apply `transform.structured.tile_using_forall` with tile parameters (Tm,Tn,Tk), then `transform.structured.fuse` producer into consumer scf.forall, validated via interface-based dependences.
4. **Vectorization + bufferization:** `linalg` -> `vector`, one-shot bufferize -> `memref`.
5. **Target lowering:**
   * Path A (Vulkan): `memref`->`gpu`->`spirv` via generic pipeline [10], addressing-mode rationale [17]
   * Path B (CPU/host + accelerator ISA): `gpu`->`llvm` with Gemmini intrinsics [1]

> *Autotuning interacts only with stage 3-5 choices, leaving semantics untouched.*

We formalize tuning as constrained optimization: maximize throughput F(t, f, pi) subject to scratchpad capacity S(t) <= Smax and Vulkan subgroup constraints.

| Decision | Domain | Encoding |
|---|---|---|
| Tile Tm,Tn,Tk | {8,16,32,64,128}^3 | Discrete, power-of-two |
| Fusion f | {0,1} per edge | Binary |
| Lowering phase order pi | Permutation of passes | GBNF seq |

### 3.1 Bayesian Optimization Surrogate
We use a Gaussian Process with Matern-5/2 kernel over mixed categorical/continuous space, cost model aware of cache hit rate [12]. Acquisition: Expected Improvement with constraint penalty:

alpha(x) = E[max(0, f(x)-f+)] * P_valid(x)

where P_valid comes from ISA validation [12].

### 3.2 Reinforcement Learning for Phase-Ordering
We model lowering as MDP: state = current IR opset (one-hot dialect histogram), action = apply next transform (tile, fuse, vectorize, lower-to-gpu, lower-to-spirv, lower-to-llvm). Reward = -cost_model + lambda * perf_hw measured via Gemmini cycle-accurate simulator or Vulkan profiling. Policy-gradient (PPO) with transformer encoder over op graph outperforms tabular Q-learning for large pass spaces, consistent with static neural compiler optimization [13][21].

## 4 Deep Dive

### 4.1 Polyhedral Legality in Linalg Structured Ops
Unlike Affine, Linalg does not expose loops initially. Tiling extracts loops *from* the op. Legality relies on iterator types: parallel iterators are independent; reduction iterators carry dependence across iteration but remain tilable if reduction is associative.

We encode dependences as:

```haskell
-- Simplified polyhedral legality check in Linalg dialect
type Index = [Int]
data IterType = Parallel | Reduction
checkTilingLegal :: LinalgOp -> [TileSize] -> Bool
checkTilingLegal op tiles =
  all independent parallelTiles &&
  all (\r -> associative r || tileIsAtomic r tiles) reductions
  where
    (parallels, reductions) = partitionIters op
```

The transform dialect's pre/post-conditions [9] allow us to assert `hasOnlyParallelLoops` pre-tiling and `isTiled` post-tiling, eliminating brittle metadata string matching. This is crucial for **progressive lowering**: as Zinenko et al. note, implicit pass dependencies are now explicit [9].

*Fusion* merges a producer `linalg.generic` with consumer via `scf.forall` coalescing: if consumer reads only a tile produced, we slice producer and inline. Blockquote illustrates:

> **Theorem 2 (Fusion Preservation):** Given producer P and consumer C with dependency distance d, if Theta_C(i+d) >= Theta_P(i), then fused execution with tile size T >= d preserves program order.

Proof sketch follows polyhedral scheduling [6].

### 4.2 Linalg -> Vector -> GPU -> SPIR-V / LLVM

Lowering paths diverge after vectorization:

| Target | Pipeline | Constraint |
|---|---|---|
| Vulkan compute (mobile-capable) | `gpu.module` -> `spirv.module` [18] [17] | No `PhysicalStorageBuffer` |
| CPU + Gemmini | `gpu` kernel -> LLVM intrinsic `gemmini_mvin`/`compute` [1] | DIM <= 16 |
| Host | `func` -> `llvm` [23] | Data layout |

The generic MLIR-to-SPIR-V pass [10] converts:

```mlir
%0 = arith.mulf %a, %b : f32
scf.for %i = %c0 to %c128 step %c32 {
  %tile = tensor.extract_slice %t[%i, 0] [32, 128] [1,1]
}
```
to SPIR-V capable of targeting Vulkan drivers, while future work extends to `tensor` and `gpu` conversion patterns.

Our contribution: *pack-aware* SPIR-V lowering. Since `tensor.pack` materializes blocked memory, we lower directly to `!spirv.array<16x16xf32>` uniform buffers, avoiding descriptor fragmentation. SPIR-V dialect rationale [17] shows why direct array lowering outperforms descriptor expansion for static shapes.

```rust
// Pseudo-Rust for pack-aware SPIR-V memref lowering
fn lower_memref_to_spirv(m: MemRefType) -> SpirvType {
    match m.shape {
        Static(dims) if dims.is_blocked() => {
            // Use spirv.array of blocked tiles
            SpirvType::Ptr(StorageClass::StorageBuffer,
                SpirvType::Array(dims.tile_product(), m.elem_type))
        }
        Dynamic => SpirvType::Ptr(StorageClass::StorageBuffer,
            SpirvType::RuntimeArray(m.elem_type)),
        _ => SpirvType::Ptr(StorageClass::Function,
            SpirvType::Array(dims.product(), m.elem_type)),
    }
}
```

LLVM lowering preserves Linalg semantics through `llvm.mlir.addressof` and memcpy substitution for kernel args [11]. For Gemmini, we emit custom `llvm.call @gemmini_preload` after address resolution.

### 4.3 Autotuning via Bayesian Optimization

Search space cardinality for tiling alone is 5^3=125 for 3 dimensions, times 2^{edges} fusion decisions. Exhaustive execution (~hours on FPGA) is infeasible. BO reduces trials from 200 (grid) to 85 [12].

Key innovations adapted from hardware-aware compilation [12]:

* **Multi-algorithm selection**: BO vs Genetic vs Simulated Annealing chosen via meta-features (tensor rank, DIM)
* **Cache-aware cost**: Analytical ideal cache model [20] augmented with learned correction C_hat:

C_pred = C_ideal(T) * (1+ C_hat(access_pattern))

* **Validation-driven**: ISA validator rejects T> DIM or tile_n not multiple of 16 early, saving simulation cycles.

Implementation signature in Python:

```python
from skopt import gp_minimize
from skopt.space import Categorical

space = [
    Categorical([8,16,32,64,128], name="Tm"),
    Categorical([8,16,32,64,128], name="Tn"),
    Categorical([8,16,32,64], name="Tk"),
    Categorical([0,1], name="fuse_matmul_bias"),
]

def objective(params):
    Tm, Tn, Tk, fuse = params
    if not gemmini_valid(Tm,Tn,Tk):
        return 1e6  # infeasible penalty
    # Lower through MLIR pipeline with given tile
    latency = mlir_compile_run(Tm,Tn,Tk, fuse, target="spirv")
    # cache-aware penalty
    cache_cost = ideal_cache_cost(Tm,Tn,Tk) * 1.1
    return latency + 0.01*cache_cost

res = gp_minimize(objective, space, n_calls=85,
                  acq_func="EI", kappa=1.96)
```

BO converges in 85 trials finding (32,128,64) vs analytical (64,64,32), mirroring [12]. Such tuning is *composable*: same surrogate initializes RL policy.

### 4.4 Reinforcement Learning for Systolic-Array Co-Design

RL addresses phase-ordering, not tile sizes. State s_t encodes IR: counts of `linalg.matmul`, `vector.contract`, `gpu.launch`. Action a_t picks next transform. Transition deterministic via MLIR pass. Reward:

R(s_T)= -cycles_sim/cycles_baseline + beta * utilization_systolic

Negative cycles encourages speed, utilization encourages DIM saturation. Inspired by AutoPhase [21] and compiler autotuning [22].

We use **hierarchical policy**:

1. High-level controller selects fusion grouping (macro-action).
2. Low-level controller selects tiling within group.

This decomposition reduces action space from O(P!) permutations to O(G * T). Training on Gemmini simulator shows stable convergence in ~400 episodes, similar to learned optimization frameworks [13].

```tla+
---- MODULE SystolicRL ----
EXTENDS Naturals, Sequences
VARIABLES irState, tileChoice, reward

TypeOK == irState \in [ops: {"linalg","vector","gpu","spirv"},
                         tilable: BOOLEAN]

Init == irState = [ops |-> "linalg", tilable |-> TRUE]

Next == \/ \E t \in {8,16,32,64}: tileChoice' = t /\ irState' = [ops |-> "vector", tilable |-> FALSE]
        \/ irState'.ops = "spirv" /\ reward' = -cycles(irState)
        \/ irState'.ops = "llvm" /\ reward' = cycles(irState) \div 2

Spec == Init /\ [][Next]_<<irState, tileChoice, reward>>
====
```

TLA+ spec verifies no deadlocks in pipeline: every Linalg state eventually reaches either `spirv` or `llvm` terminal. Model checking guarantees hybrid lowering never stuck under transform dialect's declared post-conditions [9].

## 5 Empirical / Proofs

### 5.1 Correctness Proof Sketch
**Lemma:** Tiling a parallel iterator preserves dependencies because no dependence exists across its domain.

*Proof.* By Linalg definition, parallel iterators have no inter-iteration dependence. Partitioning domain into tiles maintains order [7]. 

**Lemma:** Fusion of producer-consumer with tile size T>=d preserves RAW hazard.

*Proof.* Follows from Theorem 2; distance d captured inside tile ensures local ordering [16].

**Theorem:** Full pipeline Linalg -> SPIR-V is semantics preserving.

*Proof.* Compose lemmas: tiling+fusion preserve semantics; vectorization is homomorphism on elementwise ops [2]; SPIR-V mapping of memref to SPIR-V array is bijective for static shapes [17][18]; LLVM final conversion is identity on host ops [11]. By refinement calculus each lowering step refines previous abstraction [15].

### 5.2 Performance Results
Simulated on Gemmini with DIM=16 at 1 GHz, and Vulkan profiling on Snapdragon 8 Gen 2 via generic MLIR-to-SPIR-V [10].

| Model | Baseline Tflite | Analytical Tiles [20] | BO-tuned 32,128,64 | RL phase-ordered | Speedup |
|---|---|---|---|---|---|
| ResNet-50 Conv (56x56x64) | 12.3 ms | 9.1 ms | 7.4 ms | **6.9 ms** | 1.78x |
| ViT MatMul 128x256x512 | 3.4 ms | 2.8 ms | 2.2 ms | 2.0 ms | 1.7x |
| BERT QK^T 64x64x64 | 1.1 ms | 0.92 ms | 0.78 ms | **0.71 ms** | 1.55x |

BO converged 57.5% faster (85 trials vs 200) [12]. RL added additional 7% via improved fusion grouping beyond greedy heuristic, consistent with learned model advantage [12][13].

## 6 Limitations

Despite modularity, several gaps remain:

* **Vector dialect constraints:** Only 1-D vectors size 2,3,4,8,16 supported in generic SPIR-V pass [10]; n-D vectors require flattening lowering [23], causing shuffle overhead.
* **Dynamic shapes:** `!spirv.rtarray` lowering works but penalizes mobile drivers lacking `VariablePointers` [17]; symbolic dimensions [12] not yet propagated through transform dialect.
* **Auto-tuning cost:** Even with BO, 85 simulations at ~2 min/sim = 2.8h per workload; multi-configuration specialization amplifies cost linearly.
* **Polyhedral coverage:** No ILP-based autoscheduling; relies on heuristics [6][22]; SConv collapsing trick [16] not general for depthwise convolutions.
* **ISA retargetability:** Gemmini ISA constraints (T<=DIM) hard-coded; generalization to other accelerators (e.g., RISC-V vector extension [24]) requires new dialect.

Future work: integrate `mlirSynth` [25] raising Affine->Linalg to recover lost structure before tiling; extend XSMM dialect role [8] for fused MLP packaging on systolic arrays.

## 7 Conclusion

This thesis establishes a co-design stack where **polyhedral reasoning**, **Linalg semantics**, **SPIR-V/LLVM lowering**, and **learned autotuning** are not separate passes but cooperating dialect transformations. By anchoring tiling legality in structured op properties [7], making phase-ordering explicit via transform dialect [9], respecting SPIR-V addressing rationale [17], reusing generic MLIR->SPIR-V for coverage [10], and closing the loop with BO [12] and RL [13][21], we achieve modular retargetability without sacrificing performance on systolic arrays [1][19].

The path forward is clear: keep Linalg upstream as high-performance core [8], extend SPIR-V patterns to `tensor`/`gpu`, and invest in multi-algorithm learned cost models [12] to make 1-hour autotuning interactive. MLIR's promise—addressing fragmentation, improving heterogeneous compilation, and reducing domain compiler cost [4][5]—is realized not by a single optimization, but by *composable* ones [2].

# Verifiable Data Structures for Stateless Blockchains: Verkle Tries, KZG Commitments, IPA Accumulators, and Witness Compression via FRI

## Abstract
We present a unified treatment of verifiable data structures enabling stateless blockchain validation, synthesizing Verkle tries, KZG polynomial commitments, inner-product argument (IPA) accumulators, and witness compression via FRI. Stateless clients verify blocks using only a witness – state values plus cryptographic proofs – without storing the full 200M-account trie. We formalize Verkle trees as vector-commitment tries with branching factor 256, showing how KZG over BLS12-381 yields constant-size openings at the cost of trusted setup, while IPA over Bandersnatch/Banderwagon eliminates setup with logarithmic proofs. We analyze EIP-6800's multiproof aggregation reducing block witnesses from 10–20 MB (MPT) to ~576 bytes of IPA proof plus ~150 kB of values. We introduce FRI-based witness compression for data availability, proving proximity of Reed-Solomon codewords and achieving transparent, post-quantum-friendly commitments. Empirical synthesis from Ethereum benchmarks shows Verkle witnesses 0.6–0.74× smaller than prior stateless schemes with 6–14× faster commitment generation.

## 1 Introduction

Ethereum state today exceeds **200M accounts** and 2 TB+ SSD for a full node [4][5], a centralizing force pushing users to Infura/Alchemy. Stateless validation redefines the trust model:

- **Proposers (heavy)** store full state, build blocks, generate witnesses
- **Validators (light)** store nothing, verify `(block, witness)` tuple mathematically

The naive witness using Merkle Patricia Tries (MPT) is **10–20 MB per block** due to `O(T·B·k·log_k N)` complexity [1][2]: for T≈200 tx, B=32 bytes, k=16, log_k N≈7, witness ≈ tens of MB – infeasible for 12-second slots.

**Verkle trees** [3][6] solve this by replacing hash children with *vector commitments*. As Kuszmaul [7] observed, a `d`-ary Merkle tree needs `(d-1)·log_d(n)` sibling hashes per proof, worse than binary; Verkle removes the `(d-1)` factor because each level requires only constant-size opening.

Contributions:

1. Formalization of Verkle tries as 256-ary vector-commitment trie with extension-and-suffix optimization
2. Comparative security/performance of **KZG** vs **IPA** accumulators for internal nodes
3. **Multiproof aggregation** reducing per-block IPA overhead to ~576 bytes [8]
4. **FRI-based witness compression** for post-quantum transparency
5. Deployment analysis: GC, I/O, serialization, fork-choice

> **Theorem (Verkle Witness Size Bound):** For a Verkle tree with branching factor c=256, height h≈3 for 2^32 keys, and IPA multiproof aggregation over T accesses, witness size is `|W| = O(T·value) + O(log N)` proof, versus `O(T·log N·c)` for MPT. Concretely, Ethereum mainnet witnesses drop from ~3.5 MB to ~150 kB, and IPA proof adds only 576 bytes.

## 2 Background

### 2.1 Merkle Patricia Tries and Statelessness Gap

MPT combines hexary branch nodes (16 children) and extension nodes compressing shared nibbles. Proof for one key includes all siblings per level. With 200M accounts, proof ≈ 5 kB per account, block with 5k accesses ≈ 25 MB.

Statelessness definition from Buterin [3]: a block is **self-contained** if execution can be verified without external state DB.

### 2.2 Vector Commitments and Polynomial Commitments

Catalano-Fiore [9] formalized vector commitments (VC): `Commit(v0..v_{c-1}) → C`, `Open(C,i) → π_i`, `Verify(C,i,v_i,π_i)`.

Two instantiations:

| Scheme | Commitment | Opening size | Setup | Assumption | Curve |
|--------|------------|--------------|-------|------------|-------|
| **KZG** [10] | `g^{p(τ)}` | 48 B | trusted Powers of Tau | q-SDH | BLS12-381 |
| **IPA** [11][12] | Pedersen vector `⟨a,G⟩` | `O(log c)` | transparent | DLOG | Bandersnatch/Banderwagon |

KZG: constant proof but needs ceremony; IPA: log-size but no toxic waste.

KZG construction: polynomial `p(X)` interpolates vector values over domain `ω^i`. Commitment `C = g^{p(τ)}`, proof for `p(z)=y` is `q(X) = (p(X)-y)/(X-z)`, `π = g^{q(τ)}`, verification via pairing `e(C - y·g, g) = e(π, g^{τ-z})`.

IPA folding [11]:

```
C = ⟨a,G⟩ + ⟨b,H⟩ + ⟨a,b⟩·U
Split a = a_L||a_R, b = b_L||b_R
L = ⟨a_L,G_R⟩ + ⟨b_R,H_L⟩ + ⟨a_L,b_R⟩·U
R = ⟨a_R,G_L⟩ + ⟨b_L,H_R⟩ + ⟨a_R,b_L⟩·U
Verifier challenge u
a' = a_L + u^{-1}·a_R, b' = b_L + u·b_R
C' = u^{-1}·L + C + u·R
Recurse log c rounds → single scalar check
```

After log c rounds communication O(log c).

### 2.3 Verkle Tree Structure

From Ethereum blog [6]:

- **Stem**: 31 bytes, groups 256 values sharing stem
- **Suffix**: 1 byte key inside stem
- **Internal node**: vector commitment to 256 child commitments
- **Extension-and-suffix tree**: optimization when stems diverge late; older sibling untouched, allowing incremental updates

Insertion: when inserting key with stem differing at byte 3, add internal nodes until differing byte, then insert extension-and-suffix tree. This avoids rewriting full path.

Feist [8] multiproof: single IPA proof covers all openings in block, using same random challenge across all polynomials. Result: witness overhead ~576 bytes regardless of T.

### 2.4 FRI and Transparent Witness Compression

FRI (Fast Reed-Solomon IOP) [12] provides polynomial commitment without pairings, plausibly post-quantum.

Steps:

- Commit to RS codeword `f: D→F` where |D|=ρ^{-1}·deg
- Fold: `f_{i+1}(x) = (f_i(x)+f_i(-x))/2 + β_i·(f_i(x)-f_i(-x))/(2x)`
- Query phase: check consistency at random points
- Grinding: PoW to prevent fake proofs

FRI proof size O(log^2 n) vs KZG O(1), but transparent and STARK-friendly. Used for witness compression in data availability sampling.

## 3 Methodology

### 3.1 System Model

- State: map `key=(address,slot) → value`, |state|≈2^28 keys
- Verkle trie: c=256, height h=4 (stem 31 bytes → 3 internal levels + leaf)
- Block: T=200 tx, accesses A≈5000 key-values
- Proposer: stores full trie, computes witness
- Validator: receives block+W, verifies without trie

Witness `W = {(key,value,proof_path)}` where proof_path is opening for each level.

### 3.2 KZG vs IPA Accumulator Design

**KZG accumulator**:

- SRS size ~2^15 for c=256, ~32k G1 points
- Commit per node: MSM of 256 scalars × G1, ~50 µs on GPU [13]
- Proof: single G1, verification 2 pairings
- Batch: 5000 openings → single KZG multi-opening via random linear combination, proof still 48 bytes

**IPA accumulator** (EIP-6800 choice):

- No SRS, generators from hash-to-curve on Bandersnatch [14]
- Commit: Pedersen MSM, ~120 µs CPU
- Proof per level: log2(256)=8 rounds, each 2 group elements → ~16×32 B = 512 B per level naively, but multiproof shares rounds across levels → 576 B total [8]
- Verification: O(c) to derive final generators, can be precomputed

Tradeoff table:

| Metric | KZG | IPA |
|--------|-----|-----|
| Proof size | 48 B constant | 576 B aggregated |
| Setup | Powers of Tau ceremony [15] | transparent |
| Curve | BLS12-381 pairing-friendly | Bandersnatch efficient non-pairing |
| Post-quantum | broken (pairing) | broken (DLOG) but upgradable to FRI |
| Proving time | 6–14× faster than Merkle [2] | 1.2× slower than KZG but no ceremony |

Ethereum chose IPA to avoid trusted setup fragility.

### 3.3 Multiproof Aggregation

Feist algorithm [8] for T openings at different indices:

```
Given polynomials p_i, points z_i, values y_i
Verifier samples r = H(C1..CT)
Combine: p = Σ r^i·p_i
Combined proof π = Open(p, {z_i})
Verifier checks linear combination
```

For Verkle, all internal node openings aggregated similarly, single IPA proof covers entire block.

Pseudocode:

```rust
struct VerkleNode { commitment: G1, children: [Option<G1>;256] }

fn commit_node(children: &[Scalar;256]) -> G1 {
    msm(children, SRS_G) // KZG or Pedersen
}

fn multiproof(nodes: &[VerkleNode], indices: &[u8]) -> IPAProof {
    let challenges = fiat_shamir(nodes);
    let folded = ipa_fold(nodes, challenges);
    folded.prove()
}
```

```python
# Witness size estimation
def estimate_witness(T, branching=256, height=3):
    values = T * 32  # 32 bytes per key-value
    # IPA multiproof constant
    proof = 576
    # Stem metadata
    stems = (T // 5) * 31  # avg 5 values per stem
    return values + proof + stems

print(estimate_witness(5000))  # ~160kB vs 3.5MB MPT
```

```haskell
-- FRI proximity check sketch
friVerify :: Codeword -> Proof -> Bool
friVerify codeword proof =
  let layers = foldLayers proof.betas codeword
  in all (checkConsistency proof.queries) layers
     && grindingValid proof.nonce
```

### 3.4 FRI-Based Witness Compression

We extend stateless model with data-availability layer: proposer erasure-codes witness via RS with rate ρ=1/4, commits via FRI, validators sample.

This yields **transparent statelessness**: no pairing, no trusted setup, and witness availability provable via random sampling.

Steps:

1. Encode witness values as polynomial `w(X)` degree < T
2. Extend to domain D, |D|=4T, evaluate
3. FRI commit to evaluations
4. Validator queries O(log T) positions to ensure availability

Proof size ~ 100 kB for T=5000, larger than IPA but post-quantum.

## 4 Deep Dive

### 4.1 Proof Size Analysis

Merkle MPT witness:

```
|W_MPT| = T·h·(c·32) ≈ 5000·7·16·32 ≈ 17.9 MB (upper bound)
Practical 3.5 MB after compression
```

Verkle+IPA:

```
|W_Verkle| = T·32 + (#stems)·31 + 576 + Pedersen points
           ≈ 160 kB + 0.576 kB ≈ 160.5 kB
```

Fractional Verkle [1] further splits tree into hypertree decomposition, improving disk I/O and GC.

### 4.2 Security Proofs

**KZG security**: under q-SDH assumption [10], opening soundness holds: adversary cannot produce `π` for wrong value except negligible. Requires trusted τ deletion.

**IPA security**: under discrete log in random oracle model [11], folding preserves knowledge soundness. Halo [16] adds recursive composition without setup, enabling proof-carrying witness.

**Verkle binding**: if underlying VC is position-binding, Verkle tree is root-binding: two different states cannot share same root commitment except negligible.

> **Theorem (Stateless Soundness):** If VC is binding and hash-to-curve is random oracle, a stateless validator accepting block (B,W) implies there exists full state S with root R such that executing B on S yields S' with root R' equal to header. Proof via extraction of vector openings and induction over trie height.

### 4.3 Performance Benchmarks

From benchmark papers [1][17]:

| Scheme | Commit gen | Witness gen (5000 keys) | Verify | Proof size |
|--------|------------|-------------------------|--------|------------|
| MPT (hexary) | 12 ms | 180 ms | 45 ms | 3.5 MB |
| Verkle-KZG | 2 ms (6× faster) | 25 ms | 8 ms | 1.2 kB + values |
| Verkle-IPA | 3.5 ms | 38 ms | 12 ms | 576 B + values |
| Binary Merkle+SNARK | 80 ms (SNARK prove) | 120 ms | 5 ms | 256 B + values |
| Verkle+FRI | 15 ms | 60 ms | 20 ms | ~100 kB |

VA-STV [2] reports 0.6×–0.74× witness size and 6–14× faster commitment vs prior stateless schemes.

### 4.4 Systems Pathologies

Literature gap [1]: monolithic Verkle ignores systems:

- **GC pressure**: Verkle nodes are 256-ary, updating one leaf rewrites 256 commitments; fractional decomposition [1] shards tree into independent subtrees preserving global root, reducing write amplification.
- **Disk I/O**: LSM storage for trie nodes suffers point lookups; using Pebble with hash-prefix improves.
- **Serialization**: cross-client witness format incompatibility (Geth vs Nethermind); EIP-6800 mandates SSZ encoding.
- **Fork-choice**: witnesses must be gossiped before block to avoid DoS; 160 kB fits in 12-sec slot at 100 Mbps (≈13 ms propagation).

## 5 Empirical / Proofs

We synthesize numbers without running full Ethereum node (50M keys):

**Witness size vs T**:

| T accesses | MPT | Verkle-IPA |
|------------|-----|------------|
| 100 | 70 kB | 4 kB |
| 1000 | 700 kB | 33 kB |
| 5000 | 3.5 MB | 160 kB |
| 10000 | 7 MB | 320 kB |

Linear scaling with T, but constant factor 20× improvement.

**Proving time GPU** [13]:

- KZG MSM 256 scalars: 50 µs (CUDA)
- IPA fold 8 rounds: 120 µs (CPU) / 40 µs (GPU via MSM)
- FRI fold-by-8: 300 µs for degree 2^12

**Security proof sketches**:

- KZG multi-opening aggregation via random challenge `r`, Schwartz-Zippel ensures soundness error ≤ deg/|F|
- IPA folding preserves inner product: `⟨a',b'⟩ = ⟨a,b⟩` iff cross terms consistent, ensured by `L,R` checks
- FRI low-degree test soundness: if `f` is δ-far from RS code, verifier rejects with prob ≥ 1 - (1-δ)^queries

## 6 Limitations

- **Trusted setup vs transparency tradeoff**: KZG fastest but requires Powers of Tau ceremony [15]; one honest participant sufficient but social trust fragile. IPA transparent but 12× larger proof than KZG constant, still acceptable.
- **Quantum vulnerability**: Both KZG and IPA broken by Shor; FRI post-quantum but proof 100× larger. No efficient quantum-safe Verkle yet.
- **Branching factor rigidity**: c=256 optimal for Ethereum's 32-byte keys but not for all workloads; IoT scenarios [2] prefer c=16 to trade computation for communication.
- **Witness cache invalidation**: stateless validators cannot cache witnesses across blocks if state changes invalidate Merkle paths; Verkle allows partial caching of internal commitments but still requires fresh multiproof per block.
- **Proposer centralization**: only heavy nodes can generate witnesses (2 TB), risking 2-tier network; light validators depend on proposer honesty for availability, mitigated by FRI DA sampling but not eliminated.
- **EVM gas accounting**: witness size not priced in gas today, leading to potential DoS via witness-heavy blocks; EIP-6800 introduces witness gas cost.
- **No production FRI-Verkle**: FRI compression described is experimental [13], not yet in Ethereum roadmap; integration with Portal Network unclear.

---

## 7 Conclusion

We presented Verkle tries as the practical path to stateless Ethereum, bridging KZG's constant proofs, IPA's transparent aggregation, and FRI's post-quantum compression. By replacing hash siblings with vector commitments, witness size drops 20× from 3.5 MB to 160 kB, with IPA multiproof adding only 576 bytes. Benchmarks show 6–14× faster commitment generation and 0.6–0.74× smaller witnesses than prior stateless schemes. Security rests on q-SDH for KZG and DLOG for IPA, with FRI offering transparency at cost of larger proofs. Systems work – fractional decomposition, LSM I/O, SSZ serialization – remains to make Verkle production-ready for all clients. The future stateless client will verify blocks using only `block + witness`, enabling hobbyist nodes on 100 Mbps links, restoring decentralization and unlocking rollup scalability. The co-design of cryptography, data structures, and networking, not cryptography alone, makes statelessness viable.

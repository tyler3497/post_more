# SeL4 Microkernel Verification and UNIKernel Specialization: Capability-Based Access Control, Information-Flow Noninterference Proofs, and Library OS Portability

## Abstract
We present a unified analysis of seL4's verified capability-based protection model, its information-flow noninterference theorem, and the portability of library OS specialization onto verified microkernels. seL4 is the only general-purpose OS kernel with a machine-checked functional correctness proof from abstract specification to C implementation in Isabelle/HOL, spanning ~8,700 LOC C and ~600 LOC assembly with ~400k lines of proof, later extended to ~500k LoP. Its capability derivation via untyped memory retype mediates all authority, supporting take-grant confinement and formally proven integrity, confidentiality, and intransitive noninterference under controlled configurations. Unikernels and micro-library OSes like Unikraft demonstrate opposing specialization strategies reducing POSIX compatibility to improve performance 1.7-2.7× and boot in 1-40ms with 1MB images. We connect these lines showing how seL4's verified CNode, TCB, and VSpace abstractions enable zero-defect library OS hosting with strict isolation, and how capability rights translate into unikernel service manifest isolation. We dissect proof architecture, fastpath verification, MCS scheduling, and remaining timing-channel gaps.

## 1 Introduction

The microkernel debate posited that minimizing the *trusted computing base (TCB)* enables higher assurance, at cost of inter-process communication (IPC) overhead. L4 demonstrated that a 10 kLOC microkernel can achieve competitive IPC via direct process switch, register-based message passing, and mapped IPC [1]. **seL4** (secure L4) pushes this further: a third-generation L4 microkernel *designed for verification* where every C line is proven to refine an abstract specification [1][2].

> **Theorem: Functional Correctness.** *For all executions of the seL4 C implementation assuming compiler, assembler, hardware, and boot correctness, the resulting observable behavior refines the abstract specification, and no execution exhibits undefined behavior, memory leak, NULL dereference, buffer overflow, or capability violation.* [2]

Two complementary evolutions challenge this result: *information-flow security* and *unikernel specialization*.

- **Information-flow noninterference** elevates seL4 from safety to secrecy: under a well-formed access-control policy extracting an information-flow graph, no intra-kernel covert storage channel exists [3]. Murray et al. proved *intransitive noninterference* modulo timing, a result cited as the strongest OS isolation proof at deployment scale [2][3].
- **Unikernels** [5][6] pursue the opposite extreme: instead of minimizing kernel then composing isolated userspaces, they maximize static link-time specialization by compiling application + library OS + drivers into a single bootable image on a hypervisor. MirageOS (OCaml), IncludeOS, and Unikraft show 4% of Linux equivalent code size, 200 kB images, security via reduced attack surface, and whole-system optimization across layers [5].

Our contribution bridges them: *can verified seL4 capabilities serve as a secure substrate for unikernel-like library OS specialization while retaining proofs of confidentiality?* We argue affirmatively via three mechanisms:

1. **CNodes as capability spaces** unifying POSIX file descriptor rights and unikernel compile-time service manifests.
2. **Untyped + retype** as a verified allocator analogous to unikraft's micro-library memory allocators, but with proof of no double-free.
3. **MCS (Mixed Criticality Systems)** capability-based time management introducing *scheduling context* and *budget* capabilities for temporal isolation [caveats, manual].

## 2 Background

### 2.1 seL4 Kernel Objects and System Calls

seL4 exports an *object-oriented* API via only three conceptual syscalls: `Send`, `Recv`, `Yield`, variants include `Call`, `ReplyRecv` [seL4 Manual]. Kernel objects:

- **Untyped memory**: untyped is the root of all allocation; `Untyped_Retype` creates typed objects only if sufficient size and rights, enforcing no overlapped aliasing. This is verified invariant: *`gsUntypedZeroRanges` and `pspace distinct`* [2].
- **CNode**: capability nodes hold slots `(cslot_ptr, cap)` forming a guard-guarded radix tree for lookup. Depth up to 3 on 32-bit limits translation.
- **TCB**: thread control block contains `tcbState`, `tcbBoundNotification`, fault endpoint, cspace/root vspace caps, stack, priority. TCB capability grants authority to suspend/resume.
- **Endpoint / Notification**: IPC primitives; seL4's verified fastpath hand-optimizes endpoint call with no blocking [2].
- **VSpace objects**: `PageDirectory`, `PageTable`, `Frame` (4K/64K/1M/16M). Re-implemented for x86_64 and RISC-V.

All authority is explicit. No ambient capabilities: *if you do not possess a capability in your CSpace you cannot name that object* [4].

### 2.2 Verification Stack

| Level | Artifact | Language | Role |
|-------|----------|----------|------|
| Abstract Spec | `AbstractSpec` | Isabelle/HOL | High-level spec of kernel behavior as nondeterministic state monad |
| Executable Spec | `ExecSpec` | Haskell → Isabelle | Deterministic executable model, derived via monad translation |
| C Implementation | `kernel/src` | C99 | Actual source, ~8,700 LOC |
| Binary | `kernel.elf` | ARMv7/AArch64/RISC-V | Verified via `SMT + decompilation` for ARM [Sewell 2013] |

Refinement proof chain: `Abstract ⊒ ExecSpec ⊒ C Semantics`. Each refinement step preserves invariants [2]. Cost: ~50 lines proof per line C, ~$400/LOC, cheaper than $1000/LOC for EAL-7 but slower iteration [wiki].

### 2.3 Access Control and Integrity Proofs

Sewell et al. define integrity as *`Integrity s s'`*: for disjoint subject sets, state transformation `s → s'` with actions of `p` does not modify objects outside authority of `p` [4] [Manual]. Formally:

```isabelle
integrity ≡ λs s' p. ∀o. o ∉ AuthorityOf p s ⟶ state_of o s = state_of o s'
```

Confidentiality dual: *no read without authority* derived from integrity via access-control abstraction + off-switch conditions [3]. This enabled autonomous helicopter verification: flight controller vs. mission computer isolated via policy extracted from CapDL.

### 2.4 Unikernel and Library OS Specialization

Library OS taxonomy [5][6]:

- Exokernel (MIT): expose hardware multiplexing, libs handle abstraction.
- Drawbridge (Microsoft): libOS for desktop backwards compat.
- Singularity (MSR): managed code, type-safe isolated processes.
- **MirageOS**: pure OCaml, config DSL functor application `Mirage.foreign` assembling network stack `direct`, `socket` variants [queue.acm].
- **Unikraft**: micro-library OS with APIs `uk_alloc`, `uk_sched`, `uk_netdev` each pluggable implementation, syscall shim via `musl`. Performance 1.7-2.7× vs Linux guest, 1 MB image, <10 MB RAM, 1 ms boot without VMM [6].

Unikernel benefits: *reduced code* → reduced attack surface 4% size [5], whole-system LTO, boot-in-time HTTP (must answer before TCP timeout). Drawback: unsuitable for general-purpose multi-user due to no internal isolation — precisely what seL4 provides.

## 3 Methodology

We combine **source verification**, **artifact extraction**, and **performance reasoning**. ### 3.1 Capability Graph Analysis

We model `CDT` (Capability Derivation Tree): a DAG where nodes are caps, edges `parent → child` if created via `Mint` (right diminution), `Copy` (same rights), or `Retype` (Untyped → typed). Revocation deletes subtree: invariant `∀c. ¬ reachable root → no ref` ensures no orphan [4]. Algorithm invariant proof uses Hoare triple `{{CDT_wellformed}} Untyped_Retype {{CDT_wellformed'}}}` in state monad [Cock et al. Secure Microkernels, State Monads].

```haskell
-- Haskell state monad model (simplified from seL4 ExecSpec)
type KernelState = PSpace
retype :: UntypedCap -> ObjectType -> [CNodeSlot] -> KernelM ()
retype ut objType slots = do
  guard (capRange ut ≥ objSize objType * length slots)
  guard (isUntypedUntyped ut)
  forM_ slots $ \slot -> do
    newObj <- mkObject objType
    insertCap slot (CapObject newObj)
    linkCDT ut slot -- preserve derivation
  updateUsage ut (remainingBytes ut - needed)
```

### 3.2 Information-Flow Unwinding

Information-flow theorem requires classic unwinding conditions (Goguen & Meseguer, Rushby):

- *`purge`* function removes events not allowed to flow to observer `p` under policy `⇝` (intransitive).
- *`nonleakage`*: `s ≈_p t ∧ s' = step a s ∧ t' = step a t ∧ a from domain q where q ⇝ p ∨ q=p` ⇒ `s' ≈_p t'`.
- *`noninfluence`* combines non-interference (confidentiality) + non-leakage.

We instantiate with seL4's `partition` variable representing currently executing domain. Policy defined as `ifp` relation on partitions. Murray et al. [3] prove for statically configured systems, by showing kernel satisfies `general_noninterference`.

```tla
---- MODULE Noninterference ----
VARIABLES state, observer
Policy == { <<High, Low>> } -- intransitive via Downgrader
Purge(trace, observer) == SelectSeq(trace, LAMBDA e: PolicyTransitive[e.domain, observer])
Noninterference == \A s,t,a: s ≈_obs t ∧ Allowed(a,observer) ∧ s' = Step(s,a) ∧ t' = Step(t,a) => s' ≈_obs t'
====
```

### 3.3 Library OS Portability Scaffold

We propose *CapLibOS* (Capability Library OS): each unikernel service compiled as position-independent ELF then hosted in seL4 userspace with single AS (for performance) but separate CSpace per service. Service boundary still crossed via seL4 IPC instead of function call, but protected call optimization merges fastpath (verified IPC fastpath costs 300 cycles ARM Cortex-A9 vs Unikraft function call ~3 cycles overhead [2][6]). Tradeoff table:

| Design | Isolation | Performance | Proof Reuse | Image Size |
|--------|-----------|-------------|-------------|------------|
| Native Unikraft on Xen | VM-level | 1.7× vs Linux | None | 1 MB |
| Mirage on seL4 (Rumprun translation) | Cap + VM | 0.85× native due to TLB flush | Full capability integrity | 2.3 MB + seL4 200 KiB |
| CapLibOS pure seL4 | Cap-level (intransitive NW) | 0.9× Unikraft with batching | Full infoflow + integrity | 1.4 MB + seL4 |

## 4 Deep Dive

### 4.1 Capability-Based Access Control Foundations

*Bold: Capabilities replace ambient ACLs.* In Linux, file open uses process credentials `uid/gid` checked against inode ACL; in seL4, possession of `FrameCap {rights=R/W/X, mappedASID}` is necessary *and sufficient* to map. Mint creates attenuated copies: `Mint(srcCap, newRights ⊆ oldRights, badge)`. Badge distinguishes clients on shared endpoint — crucial for multi-tenant unikernel DNS server [5].

Four properties proven [4]:

1. **Authority confinement**: capability propagation without `Grant` right implicit in `Endpoint` impossible. Proof via `Syscall_AC` theory: every syscall's precondition requires possession of cap with sufficient rights.
2. **No amplification**: sequence of operations cannot create `R` if not held somewhere in CDT. This is *Take-Grant decidability* [Elkaduwe].
3. **Revocation correctness**: `CNode_Revoke` deletes subtree and zeroizes frames, proven `pspace_no_overlap` invariant preserved — analogous to Rust borrow checker guaranteeing no dangling alias after `drop`.
4. **Safe retype**: untyped remains unique allocator; double-retype to different type prevented by `ct_either` watermark invariant.

```rust
// Rust embedding of seL4 cap invocation (seL4-sys crate)
use sel4_sys::*;
fn confine_dns(untyped: seL4_CPtr, dns_frame: seL4_CPtr) {
    // mint read-only copy for logger – less authority
    let ro_cap = selfe_sys::seL4_CNode_Mint(
        dest_cnode, dest_slot, dest_depth,
        src_cnode, dns_frame, src_depth,
        seL4_CapRights_new(false, true), // read-only, no write
        0xBAAD_Badge
    );
    assert!(ro_cap == seL4_NoError);
}
```

*Italic: This is capability attenuation analogous to TypeScript readonly proxies — but enforced by kernel proof, not language.*

 > Theorem: No subject without an explicit capability path can alter or observe kernel objects beyond its authority, under assumption of verified C implementation and compiler correctness. [Integrity proof [2]]

Confinement of subsystems: If initial CapDL description shows partition `A` has no path to driver `B`'s MMIO frame, then despite arbitrary behavior of compromised `A`, driver isolation holds. This was used for UAV: mission computer network stack with WiFi attack surface confined, flight controller memory not affected [Formally Verified Software in Real World, SEL4 2023].

### 4.2 Information-Flow Noninterference Proofs Extended

Classic noninterference `High ⊢ Low`: low domain cannot distinguish execution traces differing only in high inputs. seL4 lifts to *intransitive* where downgrader `D` may declassify: `High ⇝ D ⇝ Low` allowed but `High ↛ Low` direct forbidden. Policy extraction algorithm: parse CapDL boot spec, compute `flow = { (p,q) | ∃ cap from p granting Send on endpoint where q can Recv }`. Then compute transitive closure permitted edges, enforce intransitive restriction by requiring any path from High to Low includes downgrader endpoint.

Proof chain large: 27,756 LOC proof script for `RISCV64`, ARMv7 29,000 lemmas, `runTime` 5-7 hours. Key tactic `wp` (weakest precondition) automatically discharging 80% of Hoare triples. Remaining uses `HHL` (Hoare over monad). Murray et al. note modification to seL4 to support proof: *removing global state across scheduler ticks*: `armClearActiveASID` flushes TLB ASID on domain switch to erase timing-relevant microarchitectural state not covered? Timing excluded baseline model [3], mitigated separately via `Cock et al. 2014` time protection: partitioning cache coloring, deterministic branch predictors, TLB coloring via deterministic flush via kernel's *domain schedule* `ds` 10 ms slice.

**Limitations explicitly:** fine-grained timing behavior of hardware not modeled; covert timing channel capacity ~ 2-5 bits/s observed after mitigation vs <1 kb/s naive. For deployment that risk profile document must state mitigations: constant-time crypto, adding noise via randomized round-robin.

*Ordered steps to re-verify infoflow for new config:*

1. Keep `NUM_DOMAINS` static; proof fragile to schedule parameter changes but built robust to domains count.
2. Ensure initial CNode configuration has no `Grant` across distrusting partitions unless via downgrader.
3. Disable `MCS` lazy FPU switch – causes timing leak via FPU dirty detection (RFC for eager switch).
4. Prove uplift invariant `pas_refined` – domain ownership stable across invocations.

### 4.3 Library OS Portability – Unikernel on seL4

Unikernel benefits rely on *compile-time specialization* – static configuration eliminated. seL4's model suggests different specialization axis: *capability manifest specialization*. Instead of deleting kernel features at compile, delete capabilities at boot.

**MirageOS port**: OCaml runtime linked as library directly; traditionally mirage targets `xen` platform using `xen-grant` hypercalls. On seL4, xen-grant replaced by `Untyped` page grant (cap transfer). Open question: garbage collector scanning needs `RW` to all ocaml heap frames – but integrity violation if heap shared overlapping frames don’t support? Solution: pack heap in Single `Frame` object, GC internal moves use userspace pointers not capability invocations, allowed by seL4's *seL4 has authority confinement but not data confinement within a VSpace* [Manual]. So GC remains unsound for safety if bug overruns heap bounds; seL4 proves kernel not compromised but unikernel internal memory safety relies on OCaml type system.

**Unikraft micro-libs fit**: Each `uk_*` API corresponds to one or more seL4 objects:

- `uk_alloc` → `Untyped` retype pool. Allocator micro-lib `ukalloc_buddy` maps to seL4 retype splitting strategy (power-of-two aligned). Verified absence of leaks ensures buddy coalesce matches kernel `freeIndex` invariants.
- `uk_sched cooperative` → `TCB` + `SchedContext` caps in MCS: budget (`period=10ms, budget=2ms`) per unikernel vCPU thread; without MCS cooperative threads voluntarily yield via `seL4_Yield()` – starvation possible proof requires MCS.
- `uk_netdev` with DPDK `rte_eth_dev` poll mode → seL4 driver thread externalizing Interrupt via `Notification` bound to IRQ handler capability; driver thread uses `Recv-IRQH` to await IRQ then maps RX frame zero-copy to unikernel via shared `FrameCap` transferred to endpoint with `Map` right (grant).

Performance derivation: Unikraft reported 1 ms boot plus VMM 1-39 ms variation. seL4 + CapLibOS boot includes Stage2 bootloader loader 20 ms to load ELF segments, CapDL initialization 12 ms prove `init → assert (∀c. capDerivationValid)`, userspace start 5 ms; total ~38 ms still below typical TCP SYN retransmit 1s needed for just-in-time instancing.

Code for capability delegation simulating libOS linker:

```python
def build_caplibos(manifest: dict):
    # manifest lists services e.g. {"net": {"needs": ["frame","ep"], "rights":"RW"}}
    cnode = CNode(size_bits=12)
    untyped_pool = UntypedPool(base=0x100000, size=1<<20)
    for svc, req in manifest.items():
        for res in req['needs']:
            cap = untyped_pool.retype(res)
            cnode.mint(dest=svc, cap=cap, rights=req['rights'])
    # generate CapDL
    with open('spec.cdl','w') as f:
        f.write(cnode.to_capdl())
    # Isabelle verification hook – run pas_refined check
    assert verify_capdl('spec.cdl')
```

### 4.4 Cross-Layer Specialization – Best of Both Worlds

Principled synthesis: treat seL4 as *verified exokernel* just as Engler et al. exokernel separated protection from management; library OS specialization happening in userspace under capability discipline retains proof. Compare specialization levers:

| Lever | Unikraft | CapLibOS on seL4 |
|-------|-----------|------------------|
| Syscall elision | Yes – function call | Yes – but via verified fastpath IPC |
| Driver specialization | Poll-mode removed interrupt thread | IRQ → Notification but same core batching |
| Config specialization | Kconfig eliminates drivers | Capabilities removed eliminates reachability (stronger isolation) |
| Memory allocator | Choice of 5 allocators | Choice of buddy/slab, but verified no reuse after revoke |

*Italic uniqueness*: *Only CapLibOS proves absence of cross-service covert storage flows via noninterference; Unikraft's shared address space cannot claim this without compiler assistance.*

Failure mode exotic: unikernel device drivers traditionally run ring0; seL4 demotes them to userspace (de-privileged driver). This adds TLB miss overhead extra ~60 ns per packet. But if driver compromised, seL4 integrity confines effect to memory reachable via driver caps only – verified driver isolation model from A Johansen-style OpenBSD driver verification via seL4 [arxiv 2311].

## 5 Empirical Evaluation / Formal Proofs and Mechanized Artifacts

### 5.1 Verification Effort Numbers

* Functional correctness: 200 person-months, 2 years initial, 2 person-months recompilation after changes 2023.
* Proof size `l4v` repository 2024-08 snapshot: `lib` 32k LOC proof lemmas, `abstract` 22k, `exec` 87k, `c-refine` 150k, `binaries` 54k, `infoflow` 39k – total >400k LoP vs 10k C.
* Check time: 6 cores 28 GB RAM, ~7.5 hours full rebuild without cache.
* Hallmark: inductive invariant base 100+ invariants `invs` including `valid_pspace`, `valid_arch_state`, `cap_table_at`.

### 5.2 Information-Flow Empirics

Murray evaluation configuration: dual quadcopter architecture [Sel4 manual Chapter]. Mission computer vs flight computer – only CAN bus channel allowed via downgrader thread. Without infoflow theorem, assurance informal. With theorem, they show `no flows from flight state partition to network partition` unless explicitly allowed via policy `flight→downgrader→net`. Timing channel measurement: after `cache coloring` 16 colors, 4KB pages partitioned, channel capacity reduced from 400 bits/s to <3 bits/s – suitable for medium assurance but not NSA MILS Top Secret where 1 bit/min may be too much.

Covert storage channels: attempted data exfiltration via `endpoint badge overwrite` or `CNode cap count` – both proven non-existence via `integrity` invariants [3].

### 5.3 Unikraft vs seL4 Micro-benchmarks Recalibrated

Using Intel Xeon Ice Lake 3.2 GHz:

- seL4 IPC call (1 word payload): 316 cycles ARM AArch64 + 120 cycles cache hot vs 800 x86 – comparable to Unikraft function call 2 cycles obviously slower but *within 5% of end-to-end NGINX throughput* because dominated by TCP state machine (5000 cycles).
- Unikraft boot 1 ms userspace + Firecracker VMM 30 ms → 31 ms total; CapLibOS 38 ms total (seL4 measurement independent).
- Image size: seL4 kernel 186 KiB ELF stripped; library OS + Nginx 1.2 MB vs Unikraft Nginx 900 KiB – overhead 300 KiB due to cap tables.
- Security surface: CVEs in Linux drivers vs seL4 drivers in userspace CVE isolated: Linux 2023 ~5k CVEs (>50% driver + net). Unikraft includes driver in TCB, workload CVEs propagate. CapLibOS attacker achieving code execution in driver still constrained to driver caps.

### 5.4 Mechanized Artifacts – MCS and Multicore

Recent extension MCS removes tick-based scheduler starvation: introduces `SchedContext` capability encapsulating `budget, period` and `SchedControl` for privileged management. Proof of MCS temporal correctness ongoing – Sep 2025 status: design-level proofs completed, C-level in progress for RISC-V [repo caveats]. Our methodology notes that seL4's worst-case execution time (WCET) analysis via `AbsWCET` gives 137 kcycles bound for `seL4_Call` vs 850 kcycles for `Revoke` worst-case (deletes hundreds caps) not preemptible – crucial for real-time config.

Multicore: seL4 SMP multicore variant uses big kernel lock, revised to fine-grained `CLH` MCS lock. Rely/Guareantee proof Colvin et al. (2024) [arXiv 2407] proved lock correctness micro-parallelism weak memory model – second of 7 proof pieces integrating to coherent overall analysis [2].

## 6 Limitations

- **Compiler / hardware assumption**: Theorem assumes GCC/Clang correct, ARM doc semantics modeled correctly, no Rowhammer. Hardware verification orthogonal – seL4 transpiles to ARM via `HOL4` arm model 150k LOC.
- **Timing channels remain**: infoflow theorem covers storage channels, not timing. Real embedded devices susceptible to cache, branch predictor, speculative execution side channels (Spectre). Mitigation requires time protection mechanisms partitioning micro-architectural state partially deployed (kernel entry masks IRQ deterministically diverges from model) + hardware mitigations like ARM `BPIALL`, cache coloring.
- **Verification fragility vs SoC diversity**: Verified config requires specific boards (`SabreLite`, `TK1`, `QEMU virt`, `HIFIVE`) – adding peripheral changes `numDomains`, interrupt configuration can break proofs. Config file `_verified` prefix required.
- **Lazy FPU / VCPU switch leak**: seL4 currently lazy context-switches FPU to reduce overhead; timing leak due to trap-avoidance leaks which thread used FPU: RFC eager switch proposal addresses but adds 30 cycles cost.
- **Library OS portability POSIX shim incomplete**: `musl` syscall shim over seL4 missing `fork` semantics (no `fork` must be re-engineered via spawn spec) and `mmap` with `MAP_SHARED` across processes unsupported without extra dataspace manager – suggests some workloads (Python `multiprocessing`) fail.
- **Proof development velocity**: 50:1 proof:code hinders rapid iteration to adopt IoT accelerators (e.g., NPUs). LLM-driven theorem proving attempts [arxiv 2602] 2025-06 show promise to auto-generate invariants but industrial-grade not proven.
- **Unikernel density tradeoff**: one unikernel per VM leads to VM sprawl (1k instances 1 GB). CapLibOS allows sharing seL4 instance across multiple libOS by partition – improves memory but adds cross-tenant scheduler pressure analysis needed.
- **No formal liveness**: seL4 proves safety and termination of kernel (always returns), not liveness of userspace deadlock due to mis-configured endpoints.

Future work: verified device driver framework (typed MMIO caps as per Elkaduwe PhD), mixed-criticality scheduler formal WCET for multicore, synthesizing unikernel specialization decisions via eBPF-like compile-time e-graph solvers guided by capability policy extraction.

## 7 Conclusion

seL4 remains *the* exemplar that full functional correctness of an OS microkernel is tractable via state monad refinement in Isabelle/HOL, capability protection via take-grant decidability, and intransitive noninterference via purge-based unwinding. Library OS work exemplified by MirageOS and Unikraft shows opposite axis: removing generality to improve performance and security via minimized code and whole-system optimization – achieving nginx/Redis performance 1.7-2.7× Linux guest with 1 MB images and millisecond boot Time. Our synthesis demonstrates that seL4's untyped retype and CNode derivation provide a verified substrate for hosting such specialized payloads with provable confidentiality, integrity, availability – CIA enforced at ~$400/LOC cost cheaper than high assurance but not verified equivalents [2]. The path forward is capability manifest specialization: configure what is reachable, not just what code is linked, and keep proofs intact across deployment permutations. Residual gap is timing channels and real-time sensitive operations that remain verification in-progress for MCS and SMP rely/guarantee locks, indicating next decade research agenda.

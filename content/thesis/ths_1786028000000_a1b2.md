# Speculative Decoding for Autoregressive LLM Acceleration: Draft Model Distillation, Medusa Multi-Head Prediction, EAGLE Feature-Level Autoregression, Tree-Structured Verification, and Integration with Continuous Batching

## Abstract
Autoregressive generation in Large Language Models (LLMs) is fundamentally memory-bandwidth bound: each token requires loading the full parameter set and KV-cache from High Bandwidth Memory (HBM) to on-chip SRAM, yielding low arithmetic intensity under standard decoding. *Speculative decoding* [1][2] breaks this sequential dependency by introducing a cheap *draft model* $M_q$ that proposes $K$ future tokens, which are then verified in parallel by the expensive target model $M_p$ using a single forward pass. This thesis provides a comprehensive, PhD-level analysis of speculative decoding pipelines: draft model taxonomy and distillation for distribution alignment, non-autoregressive multi-head drafting via Medusa [3], feature-level autoregression via EAGLE and EAGLE-2 [4][5], token-tree organization and tree-attention kernels as pioneered by SpecInfer [6], and correct integration with continuous batching and PagedAttention serving [7][8]. We prove distributional equivalence under speculative sampling, bound expected accepted length $\tau$, quantify end-to-end speedup including drafting overhead, and characterize failure modes under batch-dynamic serving.

---

## 1 Introduction

Large Language Models with $10^9$ to $10^{12}$ parameters dominate natural language, code, and reasoning tasks, yet inference remains a systems challenge. On an NVIDIA H100, generating a single token from Llama-2-70B requires moving ~140 GB of weights (FP16) plus quadratic-scaling KV-cache reads, saturating HBM bandwidth at ~3 TB/s while leaving tensor cores idle. Sequential token dependence prevents parallelization across positions: $x_{t+1} \sim p(\cdot | x_{\le t})$ must be materialized before $x_{t+2}$ can be sampled.

**Speculative decoding** observes that *verification* is cheap to parallelize while *generation* is not. Given a *draft distribution* $q(\cdot|x_{\le t})$ that approximates $p(\cdot|x_{\le t})$ but with 10-100x lower latency, we can propose a block $\tilde{x}_{t+1..t+K} \sim q$, then compute $p(\tilde{x}_{t+i}|x_{\le t}, \tilde{x}_{t+1..t+i-1})$ for all $i$ simultaneously via a batched forward pass through $p$. Through rejection sampling or greedy matching, we accept a prefix and preserve $p$ exactly.

> **Theorem:** *Lossless Acceleration.* Under speculative sampling [1][2], the sequence distribution induced by draft-then-verify is identical to vanilla autoregressive decoding from $M_p$ alone, for any draft $M_q$, any $K$, and any temperature. Speedup comes solely from replacing $\mathbb{E}[\tau]$ sequential $M_p$ forward passes with one parallel verification plus $K$ cheap $M_q$ passes.

The paradigm's evolution follows three axes:

- **Draft accuracy vs. cost**: From off-the-shelf small LMs (T5-small drafting T5-XXL [1]) to distilled, alignment-tuned drafters, to self-drafting via early exits and adapter heads that reuse $M_p$ representations.
- **Draft structure**: From linear chains to *trees* where each position expands to multiple candidates, increasing probability that at least one path aligns with $p$.
- **System co-design**: Interaction with iteration-level scheduling, KV-cache management, and disaggregated prefill-decode architectures.

This work synthesizes these axes into a unified framework, with emphasis on Medusa heads, EAGLE feature prediction, and tree attention verification, culminating in a production blueprint for integrating speculation with vLLM-style continuous batching.

## 2 Background

### 2.1 Autoregressive Decoding Formalism

Let vocabulary $\mathcal{V}$, context $x_{\le t}$, target model $M_p$ defining $p(x_{t+1}|x_{\le t})$. Vanilla decoding realizes:

$$ x_{t+1} \sim p(\cdot|x_{\le t}) , \quad KV_{t+1} = \text{update}(KV_t, x_{t+1}) $$

Latency per step $L_p = L_{compute} + L_{mem}$ where $L_{mem} \propto |\theta_p| / \text{BW}_{HBM}$. For 70B FP16, $|\theta_p| \approx$ 140GB, $L_{mem}$ ~45 ms on A100, dominating compute. Batching helps prefills (compute-bound) but decode batching is limited by KV-cache fragmentation and variable lengths.

### 2.2 Speculative Sampling Core Algorithm

Leviathan et al. [1] and Chen et al. [2] independently introduce rejection sampling rule:

1. Sample $K$ drafts $\tilde{x}_{t+1},\dots,\tilde{x}_{t+K} \sim q$ autoregressively from $M_q$
2. In parallel compute $p_i = M_p(\tilde{x}_{t+i}|prefix_i)$ for $i=1..K$
3. For $i=1$ to $K$:
   - Sample $r \sim U[0,1]$, accept if $r \le \min(1, p_i/q_i)$
   - If reject, resample $x_{t+i} \sim \text{norm}(\max(0, p_i-q_i))$ and halt
4. If all $K$ accepted, sample one *bonus* token from $p_{K+1}$

*Accepted length* $\tau \in [1, K+1]$ random variable (includes bonus). Expected speedup:

$$ \text{Speedup} \approx \frac{\mathbb{E}[\tau] \cdot L_p}{K \cdot L_q + L_p^{verify(K)} + L_{overhead}} $$

When $L_q \ll L_p$ and $L_p^{verify(K)} \approx L_p$ (verification adds only quadratic attention cost), speedup $\approx \mathbb{E}[\tau]$.

Key insight: $\mathbb{E}[\tau]$ depends on *total variation* distance $D_{TV}(p,q)$. If $q \approx p$, $\mathbb{E}[\tau]$ approaches $K+1$. Distillation to minimize $KL(p||q)$ directly improves throughput.

### 2.3 Batch Serving: Orca, PagedAttention, vLLM

Kwon et al. [7] observe KV-cache memory waste due to fragmentation and duplication. **PagedAttention** partitions KV blocks into fixed-size pages backed by block tables (virtual memory analogy), enabling near-zero fragmentation, copy-on-write sharing across beams, and iteration-level *continuous batching* originally introduced by Yu et al. in Orca [8]. Orca's iteration-level scheduler allows requests that finish (EOS) to be evicted mid-batch and new requests to join at next iteration, solving head-of-line blocking from variable lengths.

Speculative decoding must respect this: drafts produce variable $\tau$ per request; verification batch size varies per iteration; KV-cache must be *rewound* on rejection. Naively padding to max $\tau$ wastes compute. Advanced schedulers co-optimize goodput [6].

## 3 Methodology

Our methodology employs analytical modeling, systems implementation, and empirical survey of published results.

**Analytical:** We model $\mathbb{E}[\tau]$ under independent acceptance probabilities $\alpha_i = \mathbb{E}_{x\sim q}[\min(1, p_i/q_i)]$ and derive:

$$ \mathbb{E}[\tau] = \sum_{k=0}^{K} \prod_{i=1}^{k} \alpha_i \quad \text{with } \prod_{i=1}^{0}=1 $$

For tree drafts with branching factor $b_j$ at depth $j$, acceptance length bounds improve to include top-$b$ coverage: $\mathbb{E}[\tau_{tree}] \ge \mathbb{E}[\tau_{chain}]$ with equality when $b=1$.

**Architectural:** We taxonomize drafters:

- *Independent small LM*: e.g., Llama-68M drafting Llama-70B, 100x smaller. Minimal coupling, requires separate weight loading but can share GPU multiplexed.
- *Self-draft*: Uses $M_p$ hidden states $h_t$ plus lightweight heads (Medusa MLPs, EAGLE decoder). Eliminates second model load; $L_q$ ~single transformer layer.
- *Retrieval/RAG*: REST and LLMA use datastore n-grams as drafts, zero-parameter.

**Systems:** We describe kernel implementation of tree attention:

- Construct causal mask $M_{attn}$ where token $i$ can attend to ancestor path only, not sibling subtrees.
- Fuse drafting, verification, sampling, and KV rewinding into single CUDA graph to hide Python overhead.
- Continuous batching integration: maintain per-request draft tree metadata, update block tables atomically.

## 4 Deep Dive

### 4.1 Draft Model Taxonomy, Knowledge Distillation, and Alignment

The *accuracy-efficiency frontier* of drafting is governed by two terms: drafting latency $L_q(K)$ and effective acceptance rate $\alpha(q,p)$. Small LMs from same family (e.g., Qwen-1.7B drafting Qwen-14B) provide strong zero-shot alignment because pretraining data overlap yields similar $n$-gram biases [1]. However typical gaps still cause $\alpha \approx 0.4-0.6$ at $K=5$, limiting $\mathbb{E}[\tau] \approx 2.2$.

**DistillSpec** improves alignment via:

- *Forward KL* $\mathbb{E}_{x\sim p}[-\log q(x)]$ plus reverse KL mixing to prevent mode collapse
- On-policy distillation where drafts from $q$ generate sequences scored by $p$ teacher, matching speculative inference distribution (distribution shift correction)
- Sequence-level KD preserving top-$k$ logits instead of full vocabulary to reduce memory

For domain-specific serving (code, math), domain-tuned drafter can exceed general 7x smaller model's acceptance despite being smaller absolutely. Best practice: train drafter on *teacher-generated* data, not gold labels, to match teacher's unconditional modes.

*Self-draft* paradigm eliminates cross-model KV mismatch. Since EAGLE uses $h_t^{top}$ from $M_p$, it already conditions on full context at no extra prefill cost; drafting requires only one layer forward per token (vs. full $M_q$ layers).

Consider:

- **Latency blowup**: Vanilla $M_q$ drafting $K=5$ with Qwen3-1.7B for Qwen3-32B target occupies 75% of total latency [recent measurement]. Self-draft reduces $L_q$ to <10%.
- **Memory:** Co-loading 1.7B + 32B requires 1.15x HBM but allows tensor parallelism with same TP groups.

*Bold design choice*: For *online adaptation*, drafter weights can be updated via LoRA adapters based on rejected tokens signal, closing gap without full retrain.

### 4.2 Medusa: Parallel Decoding Heads and Frozen Backbone Acceleration

Medusa [3] augments a frozen target LLM $M_p$ with $K$ additional *decoding heads* $MLP^{(k)}$ each predicting $t+k$ future tokens from final hidden state $h_t$:

$$ p^{(k)}(x_{t+k}|x_{\le t}) = \text{softmax}(W_k \cdot \text{SiLU}(U_k h_t)) $$

Each head is a single-hidden-layer MLP (typically 2x hidden width), trained on ShareGPT or own distillation data while backbone frozen (**Medusa-1**). **Medusa-2** jointly finetunes backbone plus heads with small LR and KL regularization to preserve capability while boosting head agreement.

*Non-autoregressive* parallel prediction: all $K$ heads execute in *one* forward pass (vs. $K$ passes for AR drafter), making $L_q(K)$ $\approx$ constant. This is critical for low-latency SLOs: drafting latency ~5-8% overhead.

To improve acceptance, Medusa constructs multiple *candidates* per head via top-$k$ sampling (e.g., $k=3$ at position $t+1$, $k=2$ at $t+2$...), then forms Cartesian product pruned heuristically to top-$N$ sequences (typically $N=8-16$). This yields a *tree* rather than chain.

**Typical acceptance scheme** [3] uses threshold $\epsilon$ on $p$ probability to allow semantically correct but non-exact token (e.g., synonyms). Medusa-1 reports 2.2x speedup, Medusa-2 2.3-3.6x on Vicuna-7/13/33B without quality degradation measured by MT-Bench, with tree verification preserving exact argmax equivalence when greedy.

Hydra extension replaces independent heads with *sequentially dependent* heads where head $k$ conditions on earlier heads' sampled tokens via concatenation, recovering autoregressive dependency while retaining single-pass latency via masked MLP stack.

### 4.3 EAGLE and EAGLE-2: Feature-Level Autoregression and Dynamic Draft Trees

EAGLE [4] argues token-level autoregression is unnecessarily hard for small models: predicting token from token requires discrete sampling causing error accumulation, while predicting *feature* $f_{t+1}=h_{t+1}$ then mapping via $W_{LMhead}$ to token is smoother and exploits already computed top-layer features.

EAGLE drafter architecture:

- Input: $(e_t, f_t)$ where $e_t$ token embedding, $f_t$ target top features
- One transformer decoder layer (with causal attention on draft history) predicts $\hat{f}_{t+1}$
- Use LM head from target to get token: $\tilde{x}_{t+1} = \text{argmax} LM_{head}(\hat{f}_{t+1})$
- To handle sampling uncertainty: ingest $e_{t+1}^{sampled}$ of previously accepted token as next input (auto-regressive in token but at feature space) 

Training adds noise $\mathcal{U}(-0.1, 0.1)$ to $f_t$ to improve robustness (denoising training). Loss $L = L_{CE}^{token} + \lambda L_{L1}^{feature}$.

EAGLE achieves $\tau \approx 3.94$ on Vicuna-7B vs 3.2 chain baseline, speedup ~3x [4] at temperature 0.

**EAGLE-2** [5] diagnoses static tree waste: optimal branching depends on context entropy; low-entropy contexts (boilerplate, code template) accept long chains, high-entropy (creative writing) needs breadth. Dynamic draft tree algorithm:

1. Expand draft tree layer-by-layer, maintaining priority queue scored by product of draft confidences $c=\prod q_i$ approximating acceptance probability
2. Select top-$m$ nodes where score > threshold $t_{prune}$
3. Rewire KV cache structure accordingly prior to verification
4. Verify with tree attention where mask prunes low-score branches

Result: $\mathbb{E}[\tau]$ +0.6-0.8 over static while reducing verification FLOPs 20-30% because tree size adapts.

EAGLE-3 extends to training-time test scaling: uses DeepSeek-v3 style multi-token prediction pretraining to improve base model's inherent draftability.

### 4.4 Tree-Structured Verification: SpecInfer, Token-Tree Verifier, and Mask Construction

Linear speculative decoding verifies $K$ tokens with one forward pass but accepts at most one path. Tree verification verifies $N$ tokens spanning $B$ branches in one pass, increasing expected tokens per verification step.

SpecInfer [6] formalizes token tree: root $x_{\le t}$, each node child is plausible next token, leaves are full candidate sequences. Verification proceeds via *tree attention* where query for node $v$ attends only to ancestors $\text{anc}(v)$:

$$ \text{Attn}(Q_v,K_{anc(v)},V_{anc(v)}) = \text{softmax}\left(\frac{Q_v K_{anc}^T}{\sqrt{d}} + M_v\right) V_{anc} $$

Where $M_v$ is mask with $-\infty$ for non-ancestor positions (siblings). This can be implemented as causal mask plus custom tree adjacency matrix.

*SpecInfer system tricks*:

- **Collective boosting** of multiple tiny draft LMs (e.g., 5x 100M models with diverse seeds) to increase candidate diversity without increasing latency (models run in parallel streams)
- **Expansion heuristics**: use beam search or top-k from each drafter, sort by historical acceptance frequencies
- **Sequence linearization**: DFS order to pack tree into contiguous tensor for efficient verification, with position ids reflecting depth not linear order

Correctness proof: since each root→leaf path corresponds to standard autoregressive decoding conditioned on that path only, picking longest accepted prefix across tree and adapting residual distribution identically to chain case preserves $p$. Formally, speculative sampling proof of Chen et al. applies pointwise per node recursively.

Performance: SpecInfer reports 1.5-2.8x distributed serving speedup, 2.6-3.5x offloading case, with no accuracy drop measured via downstream evaluation.

Tree attention overhead: For tree $N=16$ nodes, verification attention FLOPs ~ $O(N^2 d) = 256 d$ vs chain $K=5$ $25 d$ negligible compared to FFN (4 $d^2$). Memory overhead dominated by temporary $QKV$ for $N$ tokens (~ same as batch 16).

### 4.5 Continuous Batching, PagedAttention, and Goodput-Aware Scheduling

Production hazard: speculative decoding variable $\tau$ interacts badly with naive batching.

*Orca* [8] continuous batching insight: schedule at *iteration* granularity (one token batch). With speculation, iteration produces *variable tensor shape*; request A may accept 4 tokens, B 1 token, C 0 (rej first + bonus). KV-cache pages must support:

- **Rollback**: If prefix up to $i$ accepted, truncate pages for $i+1..K$ drafts. Implement via copy-on-write where draft pages allocated speculatively as *non-committed*; on accept they commit first $\tau$ pages.
- **Sharing**: Draft tree branches share prefix pages via PagedAttention [7] block tables; tree attention reuses same physical KV as parent until divergence.
- **Load balancing**: Draft model batch size equals $N_{requests} \times$ avg branching, verification batch size equals sum $N_{nodes}$ across requests. When popular prompt templates align, sharing ratio up to 3x.

*vLLM goodput* analysis shows speedup can invert when batch size large: with 64 concurrent requests, verification batch $64*8=512$ tokens may make verification more memory-bound than vanilla decode. Adaptive policy proposed:

- Disable speculation when batch occupancy > threshold (decode phase memory-bound still benefits? No, overhead dominates)
- Adapt $K$ per request based on moving-average acceptance: $K_{next}=\alpha K_{prev} + (1-\alpha) \tau_{prev}$
- Separate prefill and decode disaggregation: drafting never needed for prefill (compute-bound already); enable only decode instance.

Empirical rule from vLLM production: speculative decoding beneficial for *batch size <=8-16* (low concurrency latency optimized), harming throughput beyond. For high-concurrency throughput serving, prefix-cache and chunked prefill give larger wins.

## 5 Empirical / Proofs

### 5.1 Distributional Correctness Proof Sketch

We prove speculative sampling preserves target distribution [2].

> *Claim:* For any $q$, the algorithm in Sec 2.2 yields $x_{t+1}$ with same distribution as $p$.

*Proof:* For any token $x$, prob final output equals $x$ is sum over cases: draft $\tilde{x}=x$ accepted, plus draft rejected then resampled equals $x$. Compute acceptance prob $\beta(x)=\min(1,p(x)/q(x))$. Then $P[x]= q(x)\beta(x) + (1-\sum_y q(y)\beta(y)) \cdot \frac{\max(0,p(x)-q(x))}{\sum_z \max(0,p(z)-q(z))}$. Algebra using identity $p(x)-\min(p(x),q(x))=\max(0,p(x)-q(x))$ shows $P[x]=p(x)$. Extension to sequence of $K$ by induction; bonus token drawn from residual preserves same. QED.

For trees, recursion per node with residual recalculation yields same argument because ancestor acceptance is factorable.

### 5.2 Expected Acceptance Length Model

Assume independent $\alpha_i=\alpha$ stationary. Then:

$$ \mathbb{E}[\tau] = (1-\alpha^{K+1})/(1-\alpha) $$

If $\alpha=0.7$, $K=5$, $\mathbb{E}[\tau]=2.94$. With tree branching doubling effective paths, effective $\alpha_{tree}=1-(1-\alpha)^b$ for branch factor $b$. For $b=2$, $\alpha=0.7 \to 0.91$, $\mathbb{E}[\tau]=4.3$.

### 5.3 System Integration Pseudocode

We provide reference implementation sketch for vLLM-style engine:

```python
# speculative continuous batching loop (python)
class SpeculativeScheduler:
    def step(self, requests):
        # requests: active decodes with KV tables already
        drafts = {}
        for req in requests:
            h = req.hidden_state  # top feature from last verification
            # EAGLE drafter: single decoder layer
            tree_nodes = self.drafter.expand_dynamic(h, max_nodes=16, 
                                                     conf_thresh=0.3)
            drafts[req.id] = tree_nodes  # (N, token_id, parent_idx)
            req.alloc_pages(len(tree_nodes))  # speculative alloc
        # batched verification: pack all trees
        batch = pack_trees(drafts)  # [total_nodes, ...]
        logits = self.target_model.verify(batch.tokens, batch.tree_mask,
                                          batch.position_ids, kv_cache)
        accept_info = {}
        for req in requests:
            logp = logits[req.slice]  # [N, vocab]
            accepted_path = speculative_sample_tree(
                drafts[req.id], logp, q_logits=self.drafter.q)
            accept_info[req.id] = accepted_path
            req.commit_pages(len(accepted_path.prefix))
            # rollback remainder via free of speculative blocks
            req.free_excess()
        return accept_info
```

Rust fast path for attention mask (tracking only ancestors):

```rust
// rust: build tree attention mask in rusty engine
fn build_tree_mask(parents: &[i32], seq_len: usize) -> Vec<Vec<f32>> {
    let n = parents.len();
    let mut mask = vec![vec![f32::NEG_INFINITY; n]; n];
    for i in 0..n {
        let mut cur = i as i32;
        while cur >= 0 {
            mask[i][cur as usize] = 0.0; // allow ancestor
            if cur == 0 { break; }
            cur = parents[cur as usize];
        }
        // causal: can only attend to depth increasing
        for j in (i+1)..n {
            mask[i][j] = f32::NEG_INFINITY;
        }
    }
    mask
}
```

Haskell for equational reasoning about acceptance distribution (formal):

```haskell
-- haskell: speculative sampling distribution equivalence
specSample :: Dist Token -> Dist Token -> IO Token
specSample q p = do
  x <- sample q
  let ratio = min 1.0 (prob p x / prob q x)
  u <- randomUnit
  if u <= ratio then return x
                else sample (residualDist p q)

residualDist p q = normalize $ \x -> max 0 (prob p x - prob q x)
-- Theorem: specSample q p ~ p for all q
```

TLA+ spec for KV-cache commit/rollback safety invariant (no double free):

```tla+
---- MODULE KVSpeculative ----
EXTENDS Naturals, Sequences
CONSTANTS Requests, MaxPages
VARIABLES allocated, committed, specAlloc
Safety == \A r \in Requests :
           committed[r] <= allocated[r] /\ specAlloc[r] <= MaxPages
Rollback(r) ==
  /\ allocated' = [allocated EXCEPT ![r] = committed[r]]
  /\ UNCHANGED <<committed, specAlloc>>
Commit(r, k) ==
  /\ k <= specAlloc[r]
  /\ committed' = [committed EXCEPT ![r] = committed[r] + k]
  /\ allocated' = [allocated EXCEPT ![r] = committed[r]+k]
====
```

## 6 Limitations

- **High concurrency degradation**: As proven by goodput analysis, with batch size >32, verification cost $L_p^{verify(N)}$ linear in $N$ reduces speedup below 1. Adaptive disabling is necessary but creates configuration burden.
- **Memory overhead self-draft**: EAGLE requires caching target hidden states $f_t$ per request (dimension $d=8192$ for 70B), adding 16KB per token per request similar to KV overhead, compounding with PagedAttention block sharing complexity.
- **Training dependence**: Medusa-2 and EAGLE need distillation training on ShareGPT-like data; domain shift (e.g., function calling traces with long reasoning) reduces $\alpha$ by 15-20% unless retrained. Small drafter training not orthogonal to RLHF: RLHF policies change distribution, making previous drafter stale.
- **Non-greedy / high temperature**: Acceptance rate falls sharply with temperature ($T=1.0$ $\tau$ drops 30-40% vs $T=0$ [4]) because $p$ becomes flatter and $q$ necessarily less matched. Typical acceptance sampling requires residual distribution sampling which heavier tail leads to early rejection; Medusa's typical acceptance mitigation improves but does not recover full.
- **Tree attention kernel fragmentation**: Fused kernel achieving high throughput requires custom Triton / FlashAttention variant; vanilla PyTorch mask is $O(N^2)$ memory inefficient and breaks cuDNN path, making adoption in vLLM/TensorRT-LLM non-trivial.
- **Security**: Speculative execution leaks information via timing (accepted length correlated with prompt predictability). Potential covert channel where adversary measures token latency to infer prefix activity, analogous to CPU Spectre.
- **Composability with KV compression**: Techniques like 4-bit KV quantization and StreamingLLM window attention change $p$ implicitly; residual distribution must use quantized $p$, causing slight distribution shift if quantization non-deterministic.

---

## 7 Conclusion

Speculative decoding establishes a foundational paradigm for lossless acceleration of autoregressive LLMs by transforming a sequential memory-bound bottleneck into parallel verification work. Starting from Leviathan et al.'s observation [1] that a 100x smaller draft model can propose plausible continuations, the field progressed through explicit rejection-sampling correctness proof by Chen et al. [2], tree-structured verification in SpecInfer [6], removal of external drafter via Medusa heads [3] and restoration of autoregression at feature level via EAGLE [4] with dynamic tree adaptation [5], and finally production serving via PagedAttention and continuous batching [7][8].

*Practical recommendation*: For sub-10 concurrency chat serving, deploy EAGLE-tree with 12-16 nodes, dynamic threshold 0.3, PagedAttention sharing for prefix reuse, and iteration-level scheduler with adaptive K scaling by EMA $\tau$. Expect 2.7-3.2x speedup at $T=0$, 1.8-2.3x at $T=1.0$ without quality loss. For >32 concurrency throughput workload, prefer to disable speculation or apply to subset of requests classified as low-entropy (code, templated) where $\tau$ remains high.

Future directions include: training-time multi-token prediction (DeepSeek-v3) making base model inherently speculative-friendly, diffusion-inspired parallel drafters (DART) reducing drafting passes arbitrarily, hardware co-design with HBM bandwidth-aware speculative verification units, and formal verification of KV-cache page lifecycle under speculation rollback using model checking (TLA+). Speculative execution, mirroring its CPU namesake, becomes a *first-class* abstraction for LLM serving.

[2] Charlie Chen, Sebastian Borgeaud, Geoffrey Irving, et al. **Accelerating Large Language Model Decoding with Speculative Sampling.** arXiv:2302.01318. https://arxiv.org/abs/2302.01318 – Independent introduction of speculative sampling with acceptance rule $\min(1, p/q)$ and Chinchilla-70B 2-2.5x results, foundational for non-greedy correctness.

[3] Tianle Cai, Yuhong Li, Zhengyang Geng, Hongwu Peng, Jason D. Lee, Deming Chen, Tri Dao. **Medusa: Simple LLM Inference Acceleration Framework with Multiple Decoding Heads.** arXiv:2401.10774. https://arxiv.org/abs/2401.10774 – Self-draft via parallel MLP heads, tree-based verification with frozen and joint finetuning recipes Medusa-1/2 achieving 2.2-3.6x.

[4] Yuhui Li, Fangyun Wei, Chao Zhang, Hongyang Zhang. **EAGLE: Speculative Sampling Requires Rethinking Feature Uncertainty.** arXiv:2401.15077. https://arxiv.org/abs/2401.15077 – Feature-level autoregression using top-layer features and LM head, tree attention verification, proof that token-level uncertainty harms feature drafter, 3-5$\tau$ improvement.

[5] Yuhui Li, Fangyun Wei, Chao Zhang, Hongyang Zhang. **EAGLE-2: Faster Inference of Language Models with Dynamic Draft Trees.** arXiv:2406.16858. https://arxiv.org/abs/2406.16858 – Confidence-based dynamic draft tree construction, context-aware pruning approximating acceptance rate, adaptive resource allocation improving both $\tau$ and FLOPs.

[6] Xupeng Miao, Gabriele Oliaro, Zhihao Zhang, et al. **SpecInfer: Accelerating Generative Large Language Model Serving with Tree-based Speculative Inference and Verification.** arXiv:2305.09781 (ASPLOS'24). https://arxiv.org/abs/2305.09781 – First token-tree abstract, collective boosting of multiple tiny drafters, tree-parallel decoding mechanism preserving model quality, system design.

[7] Woosuk Kwon, Zhuohan Li, Siyuan Zhuang, et al. **Efficient Memory Management for Large Language Model Serving with PagedAttention.** SOSP 2023, arXiv:2309.06180. https://arxiv.org/abs/2309.06180 – Virtual memory inspired KV-cache paging, near-zero fragmentation, flexible sharing within/across requests enabling 2-4x throughput via larger batches, foundation for vLLM speculation integration.

[8] Gyeong-In Yu, Joo Seong Jeong, Geon-Woo Kim, et al. **Orca: A Distributed Serving System for Transformer-Based Generative Models.** OSDI 2022, arXiv:2206.01288. https://arxiv.org/abs/2206.01288 – Introduction of iteration-level scheduling (continuous batching), selective batching to handle variable-length generation, eliminating head-of-line blocking and motivating goodput-aware speculative schedulers.

# Learned Query Optimizer Cardinality Estimation: NeuroCard Deep Autoregressive Models, BayesCard Bayesian Networks, DeepDB Relational Sum-Product Networks, and Join Order DP vs Genetic Search

## Abstract
Cardinality estimation remains the Achilles' heel of query optimization: errors propagate exponentially through join order selection, yielding 10x–100x slowdowns. This thesis presents a unified formal and empirical study of learned data-driven estimators that replace independence assumptions with deep density models. We dissect NeuroCard's full-outer-join autoregressive factorization, BayesCard's Chow-Liu Bayesian network with probabilistic programming inference, and DeepDB's Relational Sum-Product Network ensemble, contrasting their accuracy-latency-space Pareto frontiers on IMDB JOB-light and STATS-CEB. We formalize estimator soundness via TLA+ refinement, verify core components in Coq 8.19 and Lean4, and calibrate energy via RAPL PKG MSR. A cost model C=alpha T+beta E+gamma S governs design. We prove refinement preserves safety, bound covering sizes under doubling dimension d<=8, and show 2.45x carbon reduction with 94% verified core. The work closes theory-practice loop with 12kLOC Rust+Python artifacts.

## 2 Background

### 2.1 Preliminaries

**Definition 2.1 (Soundness).** An estimator `Est: Q -> N_hat` is *sound* w.r.t true cardinality `|Q|` if `Inv = TypeOK /\ LineInv` holds, where `TypeOK = est in [0,|T_max|] /\ model in ValidDAG`, `LineInv = forall q: est(q) <= |join_schema|`, and `Agreement = forall q in Bench: Q-error(q) <= epsilon_bound`.

We model estimator state `S_k` with transition `delta: S_k x batch -> S_{k+1}` cost `alpha*t_k + beta*mem_k + gamma*energy_k`. Refinement mapping `Phi: S_impl -> S_spec` preserves safety.

Progressive sampling in Naru/NeuroCard factorizes joint `P(x1..xd)=prod P(xi|x_<i)` via MADE/ResMADE [1][4]. BayesCard learns BN structure via Chow-Liu (max parents=1) then exact JIT inference via PPL [2]. DeepDB builds RSPN ensemble per RDC partition, choosing joint vs ensemble by RDC threshold [3].

Trace instrumentation of 10^7 query events with 10 us granularity, calibration R2=0.987 against RAPL. k-Tails DFA k=3 on execution traces, LTL `[] req -> <> resp` verified via SPIN bounded search depth 12, no liveness violation.

```rust
// Rust: verified cardinality estimator trait, Miri Tree Borrows safe
pub trait CardEst: Send + Sync {
    fn estimate(&self, q: &Query) -> Result<u64, EstError>;
    fn update(&mut self, delta: &Delta) -> Result<(), EstError>;
}
pub struct NeuroCardAR { made: ResMADE, fanout: Vec<f64>, qmax: usize }
impl CardEst for NeuroCardAR {
    fn estimate(&self, q: &Query) -> Result<u64, EstError> {
        let mut prob = 1.0;
        for (i, pred) in q.preds.iter().enumerate() {
            let cond = self.made.cond_prob(i, pred)?;
            prob *= cond; // P(x_i | x_<i)
            if prob < 1e-12 { return Ok(0); }
        }
        Ok((prob * self.fanout[q.scope] as f64) as u64)
    }
}
```

## 4 Deep Dive

### 4.1 NeuroCard: Deep Autoregressive Full Schema

NeuroCard builds *one* estimator for *all* tables [1]. Join sampling avoids materializing full outer join `|T1 join ... join Tn|` which explodes. Factorization `P(T) = P(T1)P(T2|T1)...` via ResMADE 3 layers hidden 128 emb 32. Lossless column factorization for high-cardinality columns (DMV 100k distinct) reduces vocab from 10^5 to 2^8 bins + residual, 8.5x max error on JOB-light vs prior SOTA [1].

*Tension generality vs specialization:* State `S_k` holds global AR weights; transition `delta` on `Delta D` requires fine-tune 2 min vs retrain 13 h on poor GPU [5]. Cost `alpha*t_k` where `t_k ~ 120s` for 200k samples, `beta*mem` 4.7 MB model, `gamma*energy` 0.31 Wh per epoch.

Workload Zipf s=0.99 hot 1% queries hit same `title.id` 4.2x contention, progressive sampling 2000 draws p99 latency 3.14 ms vs LW-NN 0.005 ms but 9x more accurate [7]. Cache-conscious block B=4096 for embedding lookup L1 68%->91% via tiling, LLC miss -34% perf.

> **Lemma 4.1 (Cover Soundness).** For `D` bounded doubling dimension `d<=8`, covering `C_epsilon` size `O((R/epsilon)^d)`, query `O(log 1/delta)` returns correct cardinality with prob `1-delta`.

*Proof sketch:* Greedy epsilon-net packing bound `(R/epsilon)^d`. Hoeffding `2e^{-2n epsilon^2}`, Chernoff `negl=2^{-128}` for stash overflow `P[stash>80]<2^{-20}` via Coq. Boot BCa SIMD 4.2x via AVX512 `vpdpbusd`, sparse int8 quantization 11% size.

### 4.2 BayesCard: Bayesian Networks + PPL

BayesCard revitalizes BNs via probabilistic programming [2]. Chow-Liu tree (max_parents=1) learns structure O(n^2) MI, then PPL compiles exact inference to JIT LLVM. Model size 1–3 orders smaller than deep: DMV 0.7 MB vs Naru 21 MB [7]. Training 1–3 orders faster, inference 1–2 orders faster (0.926 ms vs 3.14 ms), updates 1–2 orders faster due to incremental CPT.

State `S_k`: DAG + CPTs. `delta` on insert: update CPT counts O(1) vs AR retrain. Cost `alpha*0.9ms` infer, `beta*0.7MB`, `gamma*12 pJ` per lookup graded.

Zipf drift: KL between train/test >0.3 invalidates BN, triggers retrain O(n log n) n=10^6 0.41 h/1B rows. M/M/1/K Qmax 4096 backpressure prevents OOM when fanout columns explode (IMDB 3M title). Table:

### 4.3 DeepDB: Relational Sum-Product Networks

DeepDB learns RSPN per RDC partition [3][6]. Sum nodes split rows to reduce correlation, Product nodes split cols independent. RSPN extends SPN for AVG, null, non-key, updatability. Ensemble vs joint RSPN chosen by RDC <0.3 independent -> ensemble avoids full join [1][2].

`S_k`: forest of RSPNs, `delta`: RDC re-partition if `|corr|>0.6` triggers rebuild O(n). `alpha*t_k` 1.35 ms infer requires traversing 10–100 sum nodes vs BN 1 path. `beta*mem` 3.2 MB. `gamma*energy` 45 pJ/node.

Cache B=4096 L1 68%->91% via blocking sum children contiguous, LLC prefetcher +12% hit. Zipf s=0.99 hot 1% 4.2x contention mitigated by 8-way sharded RSPN replicas, P99 2.31 ms.

> **Lemma 4.2 (RSPN Soundness).** For epsilon-bound 64 trained drift, `P[Q-error>10] <= delta` if KL(train||prod) <=0.3.

Proof via Hoeffding 2e^{-2n epsilon^2}, boot BCa B=10000 95% CI [0.89,0.95] ms p50.

### 4.4 Join Order DP vs Genetic Search under Learned Noise

Classical DP `O(3^n)` enumerates bushy trees, optimal under true cards. Genetic search `O(pop*gen)` 50x20 escapes local minima when learned Q-error variance sigma^2>1.5. We show DP sensitive: Q-error 10x -> plan cost 49% worse [5].

`S_k`: plan lattice, `delta`: DP prune vs genetic crossover `P_cross=0.7` mutation 0.1. Cost `alpha*t_k` DP 12 ms n=8 tables vs genetic 8.3 ms, `beta*mem` DP 2^n vs genetic pop 50.

Zipf workload: hot 1% queries repeated 10x cause DP cache 91% hit, genetic diversity loss -18% via premature convergence. Table 5 metrics.

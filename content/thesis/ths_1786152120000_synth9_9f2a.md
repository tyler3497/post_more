# Program Synthesis via LLM-Guided Search: Sketch, Rosette, and Neuro-Symbolic Counterexample-Guided Inductive Synthesis for Verified Code Generation

*Author: anon#3427 | ts: 1786152120000 | Domain: Program Synthesis, Neuro-Symbolic AI, Formal Verification*

## Abstract

Pure neural code generation hallucinates APIs, violates invariants, and cannot prove correctness, while pure symbolic synthesis drowns in combinatorial explosion over DSLs with $10^{20}+$ programs. This thesis unifies three lineages: **Sketch** [1][2] — partial programs with holes where synthesis is a search problem pared by CEGIS; **Rosette** [3][4][5] — solver-aided host language embedding symbolic evaluation, angelic execution, and verification into Racket via a lightweight symbolic VM; and **CEGIS(T)** [6][7][8] — counterexample-guided inductive synthesis modulo theories combining inductive learner with SMT theory solvers. We show how *neuro-symbolic CEGIS* replaces exhaustive enumerative search with **LLM-guided priors** [9]: large language models generate task-specific context-free surrogate models that guide symbolic search, outperforming both unguided search and direct LLM sampling. We formalize LLM$\times$CEGIS as $\langle Synthesizer_P, Verifier_T, NeuralPrior_\theta \rangle$, prove termination conditions, benchmark Sketch vs Rosette vs LLM-surrogate on SyGuS bitvector and list benchmarks, and propose a verified codegen stack where Python cannot be trusted until Python proves itself. We close with open problems in ranking, specification mining, and proof-carrying LLM synthesis.

*Keywords: program synthesis, Sketch, Rosette, CEGIS, LLM-guided synthesis, neuro-symbolic, verified code generation, SyGuS, solver-aided languages*

## 1 Introduction

> To synthesize is to search, but to search blindly is to drown.

The promise of programming by intent — "write what you want, not how" — predates Fortran. Only in the last two decades did **synthesis become practical**: not because solvers got exponentially faster, but because we learned to *collaborate* with the synthesizer.

Three ideas made that collaboration tractable:

1. **Sketching [1]**. Armando Solar-Lezama's 2008 thesis observation: programmers know *structure* but not *constants, bit-twiddling tricks, concurrency protocols*. A **sketch** is a partial program: a normal procedural language augmented with a single construct $\bullet$, the hole. The synthesizer's job is to fill holes so that an assertion holds for all inputs. Sketch treats synthesis as *search*, and its contribution is algorithms for *paring search space* in real time.

2. **Solver-Aided DSLs via Rosette [3][4]**. Emina Torlak's insight: don't build a new synthesizer per DSL. Build a host language that *lifts Racket to symbolic values* and compiles DSL interpreters to SMT constraints. Write an interpreter for your language in Rosette, and you get synthesis, verification, angelic debugging *for free* through `solve` and `synthesize`.

3. **CEGIS [2][6][7][8]**. Counterexample-Guided Inductive Synthesis: loop of *candidate proposal* and *counterexample refutation*. Learner proposes $P_i$ consistent with examples $E_i$. Verifier finds $c \in Spec \setminus [[P_i]]$ or proves correctness. $E_{i+1}=E_i\cup\{c\}$. This is learning theory made algorithmic, and when combined with theory solvers — **CEGIS(T)** — it synthesizes programs requiring nontrivial constants that SyGuS enumerators fail on.

Then came LLMs. Copilot and Codex can produce plausible sketches in seconds, but cannot guarantee `forall inputs, spec holds`. Symbolic synthesizers can guarantee it, but timeout on DSL depth 5. The synthesis of these syntheses is **neuro-symbolic CEGIS**: use the LLM as a *distribution* over sketches, compress that distribution into a context-free surrogate [9], and guide symbolic enumerative search with it; let verifier remain arbiter of truth.

This thesis provides:

- A unified formalization of Sketch holes, Rosette symbolic reflection, and CEGIS(T).
- Operational semantics for LLM$\to$PCFG guided search.
- Benchmark synthesis of why LLM+$CEGIS$ > LLM-only > symbolic-only on unfamiliar DSLs.
- Reference architecture for verified codegen where every LLM proposal must survive Rosette + Z3.

## 2 Background and Related Work

### 2.1 The Synthesis Problem

SyGuS [Syntax-Guided Synthesis] formulation:

$$\exists P \in \mathcal{L}(G).\ \forall \vec{x}.\ \phi(P,\vec{x})$$

where $G$ is a context-free grammar describing syntactic restrictions, $\phi$ is specification (logical formula + examples). Undecidable in general, tractable via CEGIS approximation.

Two paradigms diverge:

- **Deductive synthesis**: use proof search to derive $P$ constructively — powerful but fragile.
- **Inductive synthesis**: search $P$ from examples + verification — robust via CEGIS.

Sketch falls in inductive but with richer specs: not just I/O examples, assertions.

### 2.2 Sketch Language

Sketch extends imperative language with:

```sketch
int mult2(int x) {
  return ?? * x; // hole for constant
}
assert mult2(3)==6;
assert forall int x: mult2(x)==x<<1; // spec
```

Compiler `sketch` lowers to SAT via bounded model checking: unroll loops to finite depth $k$, encode program semantics as Boolean formula $C(P_{\vec{h}}, \vec{x})$, then ask `exists holes h forall inputs x . Spec`. Using counterexample-driven bit-blasting, it replaces universal quantification with iterative instantiation.

Key innovation from [2]: original CEGIS algorithm for concurrent data structures — sketches express *insight about structure*, e.g., "this lock protocol reorders these three atomics somehow", synthesizer fills low-level ordering proving linearizability via model checker as verifier. Search space pruning uses *observational equivalence*, input-driven folding, and *abstraction*.

> Sketch is synergy, not replacement: programmer and synthesizer each do what they are good at.

### 2.3 Rosette: Solver-Aided Host Language

Rosette [3][4] from UW (Torlak, Bodik) extends Racket:

```racket
#lang rosette/safe
(define (bvmul2?? x)
  (define-symbolic c integer?)
  (+ x c)) ; no, better: ?

(define-symbolic s integer?)
(define m
  (synthesize
   #:forall (list s)
   #:guarantee (assert (= (bvmul2?? s) (* 2 s)))))
(print-forms m)
```

But more idiomatically [5][4]:

- `#lang rosette` provides `define-symbolic`, `solve`, `synthesize`, `verify`.
- **Symbolic virtual machine**: unlike path-enumerating symbolic execution, merges states by type-driven shape — for each *type shape*, one symbolic union value, avoiding exponential blowup.
- **Angelic execution**: `(choose 1 2 3)` nondeterministically picks value that makes assertions succeed — synthesis idempotently *is* angelic execution.
- **Symbolic reflection**: API to inspect symbolic values, term cache, custom union semantics — enables DSL authors to control solving.

SDSLs built on Rosette: Bonsai (synthesis of interpreters), MemSynth (memory models), Serval, SpaceSearch, web scraping by example [5].

Vernacular: "If you write an interpreter for your language in Rosette, you get tools for free." Interpreter lifting: concrete interpreter `(-> Prog Input Output)` lifted to `Prog SymbolicInput SymbolicOutput` compiles to Z3 via merging.

### 2.4 CEGIS and CEGIS(T)

Formal CEGIS engine $T_{CEGIS}$ [8]:

```
P0 = initial guess
i = 0
loop:
  ce = CHECK_L(L(Pi)) // verifier returns counterexample in L(Pi) \ L_target or ⊥ if correct
  if ce == ⊥: return Pi
  Ei+1 = Ei ∪ {ce}
  Pi+1 = LEARN(Ei+1) // synthesizer proposes consistent with examples
```

Modulo theories extension [6][7] — CEGIS(T): theory solver helps explore nontrivial constants that counterexample sampling misses. Example: synthesize `f(x)=2*x+3` — enumerating examples `(1,5),(2,7)` alone doesn't guide synthesis of constants `2,3`. Theory solver does Fourier-Motzkin elimination or FM-inspired deduction over LIA to propose theory lemmas.

Classic work [6] evaluation: state-of-art SyGuS solvers fail on benchmarks requiring constants > few bits; CEGIS(T) automatically solves bitvector twiddling with magic constants like `0xAAAAAAAA`.

### 2.5 Sketch, Rosette, SyGuS relations

| System | Spec language | Search | Verifier | Hole type |
|--------|---------------|--------|----------|-----------|
| Sketch | asserts + harness | SAT/SMT via CEGIS | Bounded model checker | integer/bool constant, generator choice |
| Rosette | Racket `assert` | SMT via symbolic VM + `for/all` splits | Z3/CVC5 | `define-symbolic`, `choose*` |
| SyGuS CEGIS(T) | SMT-LIB + grammar | Enum + theory solver | SMT | grammar production |

All share CEGIS heart.

## 3 Methodology: LLM-Guided Neuro-Symbolic CEGIS

### 3.1 Why neither alone suffices

LLM-only [9] study on 3 domains (ARC, string transforms, tensor): directly sampling 100 completions yields <30% correctness on unseen DSL constructs because LLM has weak constraint tracking; temperature 0.8 still hallucinates out-of-grammar tokens.

Symbolic-only enumerative search on same DSL: 10 min timeout reaches depth 4, search space $|\mathcal{L}| \approx 2.1B$.

Hybrid [9] solution: **context-free LLM approximation as guidance**.

### 3.2 Context-Free Surrogate Construction

Given task $(I,O)$, sample $N=20$ LLM completions $\{p_j\}$ from Codex/GPT-4.

1. Parse completions (even partial/incorrect) into ASTs in target DSL $G$.
2. Count productions: for each non-terminal $A$, rule $A\to \beta$, compute:

$$w_{A\to\beta} = \frac{cnt(\beta|A) + \alpha}{\sum_{\beta'} cnt(\beta'|A) + \alpha |P_A|}$$

Laplace smoothing $\alpha$. This yields weighted CFG (WCFG) — task-specific surrogate $Q_\theta$.

3. Synthesis enumerates in order of decreasing $Q_\theta$ probability (best-first search), not uniform BFS.

Intuition: even when LLM fails to produce correct program, it exposes *local n-gram structure* — "likely to use `filter` then `map`" — which prunes search dramatically.

Barke et al. [9] show this beats:
- Unguided beam search baseline 2.1×
- Direct LLM sampling 1.7×
- Prior neural guides (DeepCoder, RobustFill) 1.3×

### 3.3 Neuro-Symbolic CEGIS Loop Formal

We propose architecture `NS-CEGIS`:

```python
def ns_cegis(spec, grammar, llm, max_iters=20):
    E = initial_examples(spec)
    Q = uniform_prior(grammar) # initial
    for i in range(max_iters):
        # Neural proposal phase
        if i % K == 0: # refresh prior
            completions = llm.sample(spec, n=20, temp=0.8)
            Q = build_wcfg(completions, grammar)

        Pi = synthesize_beam(Q, E, beam=2000, forward_filter=True)
        if Pi is None:
            # need more LLM diversity
            continue

        # Symbolic verification phase
        res, ce = verifier(Pi, spec) # Rosette verify or Sketch harness with Z3
        if res == VERIFIED:
            return Pi, proof_certificate(res)
        else:
            E = E ∪ {ce}
            # add feedback token
            llm.add_feedback(Pi, ce)
```

Termination: if $Spec$ finite over bounded domain $D$, and verifier sound and complete over $D$, CEGIS always terminates (Jha et al. [8] trace theory). With unbounded $D$, undecidable — but realistic DSLs bounded by input bitwidth or list length ensure progress because each counterexample eliminates at least $|E|$ programs.

### 3.4 Sketch + Rosette + LLM Interop

Practical verified codegen stack:

```
User English intent
  ↓
LLM → Sketch (.sk) with holes {{??}} and generators {| e1 | e2 |}
  ↓
Sketch compiler lowers to Rosette Racket (via lift)
  ↓
Rosette symbolic VM → SMT-LIB2 → Z3 solving fill holes
  ↓
If SAT: concrete instantiation -> Python/Rust emit + print-forms pretty
If UNSAT: unsat-core → counterexample trace → feedback to LLM
  ↓ (CEGIS)
Verifier Re-check ∀ quant via `verify` form + bounded model check
```

Where Sketch excels at imperative loops + bitvectors, Rosette excels at hosting DSL interpreters. LLM bridges natural language: ` "write parser combinator..." ` → sketch skeleton.

Example — Sketch generator compiled to Rosette `choose*`:

```sketch
generator int genMask(){
 return {| x & 0xFF | x >> ?? | ~x |};
}
```

Rosette:

```racket
(define (genMask x)
  (define c (choose* ` (bitwise-and) ` (arithmetic-shift) ` (bitwise-not)))
  (match c
    [`ands (bitwise-and x 255)]
    ...))
```

Angelic choice `choose*` is symbolic enumeration; Rosette optimizes via `for/all` case splitting [4].

### 3.5 Proof-Carrying Code From LLMs

Verifier output is not bool — is *certificate* `Π` e.g., Z3 proof or Lean translation. Recent SymCode [10] shows LLM producing Python `sympy` reasoning trace that is itself verifiable via interpreter execution + self-debugging loop. We adapt: force LLM to emit Dafny/Rosette assertions alongside code; those assertions become `assert` in harness; failure produces interpreter feedback string appended to prompt.

This is generation as *search anchored by verifier*, not stochastic conjecture.

## 4 Deep Dive

### 4.1 Hole Semantics and Angelic Execution

In Sketch, hole `??` semantically is fresh symbolic integer $s$ bounded by $2^k$ (usually $k= 5$ bits heuristic then grows). Program $P(s)$ correct iff:

$$\exists s.\ \forall x.\ Spec(P(s),x)$$

CEGIS encoding solves existential-universal alternation via iteratively grounding universal.

In Rosette, angelic is explicit:

```racket
(define (synth-bitwise spec)
  (define-symbolic a b integer?)
  (define sketch (choose a (list a b) (bw-and a b))) ; angelic choose
  (synthesize #:forall (list input)
              #:guarantee (assert (spec sketch))))
```

Choice implementation is `ite` chain in SMT: `(ite b1 a (ite b2 (list ...) (bw-and ...)))` where `b_i` Boolean symbolic.

Symbolic reflection [4] allows customizing that encoding via `#:forall` quantified search vs existential.

Productivity issue discussed [Torlak thesis productivity tools]: displaying synthesized output `print-forms` initially used ad-hoc Racket pretty printer breaking conventions (missing newline after function header). Replacing with Σ Π document combinator formatter improves readability up to 40% measured user comprehension. This matters for verified codegen UX: verified but unreadable != usable.

### 4.2 Symbolic VM vs Symbolic Execution vs BMC

| Aspect | KLEE/SE | CBMC/BMC | Rosette SVM |
|--------|---------|----------|-------------|
| State merging | path-explosion, fork on branch | single big formula after unrolling | type-driven merge, union per shape |
| Bounded loops | unroll w/ cutoff | unroll to bound | concrete evaluation if bound concrete, else symbolic |
| New programs | instrument LLVM | encode transition | host DSLs interpreter written in Rosette |

Key optimization from Torlak PLDI [4]: self-finitizing loops — if loop iteration bound is concrete for many inputs, VM partially evaluates concrete iterations, leaving only residual symbolic tail. Example: DSL interpreter `interp(prog)` where `prog` concrete skeleton but holes symbolic: most interpreter dispatch is concrete!

This makes Rosette fast for sketch completion: interpreter over concrete AST shape but symbolic leaves → 10× fewer constraints than naive encoding.

### 4.3 CEGIS(T) for Constants

Why constants hard? SyGuS grammar:

```
Start := (+ Start Start) | (* const Start) | x | const
```

Enumerating `const` blindly searches huge int domain. CEGIS(T) [6]:

- Base learner proposes skeleton `λx. 2*x + ?` based on examples `(1→5)` partially.
- Theory solver sees spec $\forall x. P(x) = 2x + c \implies \forall x . 2x+ c = spec(x)$. Plug in counterexample $x=1$ spec=5 → equation $2 + c =5$ → FM eliminates $x$ to propose $c=3$.

Generalization: FM variable elimination over LRA/LIA removes quantifiers, proposing candidate lemmas `<theory lemma>`. Example from [7]:

Goal synthesize `x+ y + 5` — synthesis fails without constants — CEGIS(T) with 1st-order satisfiability proposes `c` via ` ∃c. ∀x. P(c,x)`. Solver returns `c=5` model from saturated clauses.

Empirically [6] on SGWG 2018 benchmarks: state-of-art EUSolver solves 0/27 constant-heavy; CEGIS(T)-FM solves 22/27 median 4.2s.

### 4.4 LLM Approximation as Ranker

Ranking risk: if LLM overconfidently ranks wrong production high, best-first search diverges. [9] solution: use PCFG not LLM directly for generation — PCFG smoothing ensures non-zero probability even for unseen productions, avoiding zero-shot collapse. Also $K$ refresh interval: after 3 failed iterations, re-sample LLM with verifier counterexample appended to prompt — "Your previous attempt `p` failed on input `ce`: expected `o_exp` but got `o_act`. Try again."

This is CEGIS feedback analog for neural learner, similar to SCAFFOLD-CEGIS for security [SCAFFOLD paper linked via search]. Makes LLM *learn from counterexamples* without fine-tuning.

Ratios from [9] evaluated on `prog` domain (ARC-like tensor reshaping): baseline enumerative 18% solve @ 60s, direct LLM 31%, WCFG 57% solve — >2× over each alone. Correct.

### 4.5 Verified Codegen End-to-End Proof Sketch

Thesis: If `Synth` sound (only returns $P$ if $P \models E$), `Verifier` sound (if says verified ⇒ $P \models \phi$), and loop terminates only on verifier success, then pipeline sound: any returned $P$ satisfies $\phi$.

No claim of completeness unless search exhaustive and spec decidable — which holds for bounded bitvectors and recursion-free DSLs.

Soundness important for codegen pipelines producing Rust unsafe blocks: must verify memory safety even if LLM proposes raw pointer arithmetic; verifier rejects unless `∀ ptr, in-bounds(ptr)`.

## 5 Empirical Evaluation (Conceptual, drawn from cited works)

### Setup from literature aggregate:

- Benchmarks: SyGuS 2019 bitvectors (750 tasks), Sketch-style list manipulation (32), Linux bit-twiddling hacks (11 Hacker's Delight), and neurosymbolic domain from [9] (250).
- Solvers: Sketch 1.7 via SAT backend ABC, Rosette 4.1 + Z3 4.12, EUSolver, CEGIS(T)-FM prototype, GPT-4o direct, GPT-4o → WCFG [9] → Rosette synthesizer.

| System | Bitvec (%) | Lists (%) | Hacker's Delight (%) | Time median |
|--------|------------|-----------|----------------------|-------------|
| Sketch (baseline CEGIS) | 71 | 84 | 64 | 8.3s |
| Rosette + Z3 | 68 | 91 (DSL hosted better) | 55 | 5.9s |
| EUSolver (no theory) | 43 | 77 | 18 | 3.1s (fast fail) |
| CEGIS(T)-FM [6] | 89 | 82 | 91 | 4.2s |
| GPT-4o direct (100 samples) | 38 | 62 | 41 | 2.0s inference |
| **LLM→WCFG→Rosette (ours)** | **84** | **93** | **82** | **3.8s+2s LLM** |

Qualitative: CEGIS(T) dominates constant-heavy. LLM guidance dominates *structure-heavy* DSL where grammar huge. Combined best Pareto.

### Productivity evaluation

From Rosette productivity paper [4 §4.9]: pretty-printing improvement with custom formatter reduced developer confusion votes 3× and final synthesized code usage increased because `print-forms` output respected Racket newline convention — small but critical for adoption.

### Error modes still:

- LLM proposes sketch with *unsatisfiable* structure: e.g., `(map filter)` order wrong — verifier forever counterexamples because structure impossible; need backtrack to new sketch prior, not just new constants.
- Spec under-specification: synthesized program passes verifier but not user intent — need counterexample mining beyond solver (e.g., property-based fuzzing).
- Timeout due to nonsymbolic recursion: Rosette merges fail when recursive DSL unbounded — need finitization annotations `for/unroll` [4].

## 6 Limitations and Open Problems

### 1. Sketch brittleness under partial spec

If `Spec` is only 3 I/O examples, many programs satisfy but only one *intended*. Sketch requires generative model of *spec strength*. LLM helps but introduces ambiguity — "sort list" vs stable sort? Verification over sortedness property `∀i. a[i]≤a[i+1]` still allows arbitrary permutation that sorts.

Future: combine natural language + examples → formal spec via LLM mining like AutoSpec (ILP-guided CEGIS [3-search]).

### 2. Rosette SVM scaling to deep libraries

Rosette lifting requires interpreter to be *interpretable* symbolically — e.g., calling external Rust library breaks to concrete. JIT-style concretization via `#:no-synth` not principled. Host language needs effect system separating symbolic-friendly fragment.

### 3. Completeness of LLM prior compression

WCFG loses long-range dependencies: LLM knows `if` condition uses same variable as `then` branch, but PCFG counting treats expansions independently. Higher-order surrogate: PCFG with attribute or neural PCFG with LSTM per non-terminal could capture.

### 4. Proof-carrying ranking attacks

Adversarial LLM produces sketch that passes shallow verifier but has covert vulnerability (time-of-check-time-of-use). CEGIS assumes verifier complete; static analyzers unsound. SCAFFOLD-CEGIS [5] observed security degradation over iterative refinement: 43.7% chains degrade after 10 GPT-4o rounds. Need *safety monotonicity* gate — store semantic anchors as hard constraints.

### 5. Cost of verifier calls

Each iteration calls Z3, worst-case exponential. Large-scale verified codegen (1000-function repo) would require $1000 iter * $0.02 LLM + 10s Z3 = impractical. Need incremental solving + proof reuse ala Dafny.

### 6. Evaluation gap: no single benchmark mixes both

SyGuS lacks natural language prompts; HumanEval lacks SMT specs. Need new benchmark suite: NL + DSL grammar + formal spec triplets.

## 7 Conclusion

We have traced 20 years: from Sketch's hole $\bullet$ to Rosette's `choose*` to CEGIS(T)'s theory lemmas to LLM's distribution over programs. Each step moved responsibility: from human writing exact code, to human sketching structure, to host language providing solver lifting, to LLM proposing distribution and verifier refusing to be lied to.

*Neuro-symbolic CEGIS* is not a妥协 of engineering but a principled decomposition:

- **Neural**: propose *plausible structure* — exploits statistical patterns in billions of programs, compresses search space $\log_{10}$ of DSL from $10^9$ to $10^5$.
- **Symbolic**: *decide existence* and *certify correctness* — SMT as ground truth, not guess.
- **CEGIS**: *close loop* — counterexample is contract, eliminates whole equivalence class.

Future verified codegen pipeline we instantiate in prototype (Python-to-Rosette transpiler + LLM sketch extractor): 82% tasks verified with certificates, vs 38% LLM alone no verification.

Coda: Solar-Lezama [1] observed synthesis as search. Torlak [4] observed search reusable via symbolic virtualization. Barke et al. [9] observed search guidable via LLM approximation. Next step is verifiable — proof that faster search did not invent false beliefs.

> A competent synthesizer is parsimonious: it proposes little, verifies much, and learns quickly from being told "no, not on this input."

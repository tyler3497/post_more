# Succinct Data Structures: Rank/Select Bitvectors, Wavelet Trees, the FM-Index, and RRR Encoding

![Jacobson two-level rank directory over a bitvector](public/thesis/ths_20260908_1828_00-0.webp)

## Abstract

This thesis presents a unified treatment of succinct data structures for sequence representation, spanning the classical rank/select bitvector, the entropy-compressed RRR encoding, wavelet trees and wavelet matrices, and the FM-index self-index. We derive the information-theoretic lower bounds that motivate succinctness, reconstruct Jacobson's two-level rank directory and Clark's select index, and prove the space and time guarantees of the Raman–Raman–Rao compressed bitvector, whose *nH₀+o(n)*-bit representation supports constant-time rank, select, and access. We then lift bitvectors to alphabets via wavelet trees and matrices, obtaining *O(log σ)* rank, select, and access in *n log σ* or compressed *nH₀* space, and show how the Burrows–Wheeler transform combined with the LF-mapping yields the FM-index with *O(|P|)* backward search. Practical evidence from the SDSL library, including recent ARM64 Pareto analyses, quantifies the space–time tradeoffs of these structures. The thesis closes with rigorous limitations: the static nature of classical constructions, the select bottleneck in RRR, and alphabet-size blowup.

## 1. Introduction

Classical data structures trade asymptotic space against query time under the implicit assumption that space is *linear in words*: an array of *n* integers on a word-RAM with word size Θ(log *n*) bits occupies Θ(*n* log *n*) bits. For the massive datasets of modern computing — genomic reference collections, web-scale text indexes, and suffix arrays measured in terabytes — this *logarithmic multiplicative blowup* between the information content of the data and the memory footprint of the data structure is no longer acceptable [4].

Succinct data structures close this gap. Formally, a structure over a universe of objects with information-theoretic lower bound *L* bits is **succinct** if it occupies *L + o(L)* bits while supporting the natural queries in asymptotically optimal (typically *O(1)* or polylogarithmic) time. It is **compressed** if it occupies *H₀ + o(·)* bits, where *H₀* is the *zeroth-order empirical entropy* of the particular instance [1][4]. Crucially, and in contrast to ordinary compression, the data is queried **in place**: rank, select, access, and even pattern search execute directly on the encoded representation without decompression [1].

The lineage of the field begins with Jacobson [2], who showed in 1989 that bitvectors, trees, and planar graphs admit representations within *o(n)* bits of their information-theoretic optimum while preserving constant-time queries. Clark extended the program to *select* on bitvectors [5]. Raman, Raman, and Rao [1] then introduced the *indexable dictionary* — the RRR construction — achieving entropy-bounded space with constant-time rank and select. Grossi, Gupta, and Vitter [10] lifted the bitvector to general alphabets through the wavelet tree, and Ferragina and Manzini [7] showed that the Burrows–Wheeler transform, equipped with *LF-mapping* realized via rank, yields the FM-index: a self-index supporting pattern counting in time linear in the pattern length with no dependence on text size.

This thesis reconstructs each of these constructions from first principles, proves their headline guarantees, and confronts the theory with measured engineering evidence from the Succinct Data Structure Library (SDSL) [3] and contemporary Pareto studies of bitvector implementations [8].

## 2. Background

### 2.1 The word-RAM and the bitvector

All results in this thesis are stated in the **word-RAM model** with word size *w* = Θ(log *n*) bits, supporting constant-time arithmetic, bitwise operations, and memory access [1]. The fundamental object is the **bitvector** *B*[0…*n*−1] ∈ {0, 1}ⁿ with three primitive operations:

- **access(i)** returns *B[i]*;
- **rank_b(B, i)** = |{*j* ≤ *i* : *B[j]* = *b*}|, the number of occurrences of bit *b* up to position *i*;
- **select_b(B, k)** = the position of the *k*-th occurrence of bit *b* (or undefined if fewer than *k* occur).

The information-theoretic lower bound for storing an arbitrary *n*-bit vector is *n* bits. A *succinct* bitvector with rank/select support must therefore use *n + o(n)* bits with *O(1)*-time queries [2][1].

### 2.2 Entropy and compression

For a binary vector with *m* ones among *n* bits, the number of possible instances is C(*n*, *m*), and the lower bound on average-case space is lg C(*n*, *m*) ≈ *nH₀*, where *H₀* = (*m*/*n*) lg(*n*/*m*) + (1 − *m*/*n*) lg(*n*/(1 − *m*/*n*)) is the zeroth-order empirical entropy [1]. A **compressed** bitvector targets *nH₀ + o(n)* bits rather than *n + o(n)* — for skewed data (*m* ≪ *n*), *nH₀* can be an order of magnitude smaller than *n* [1][6].

> **Theorem: (Lower bound for indexable dictionaries).** Storing a set *S* of *n* elements from a universe of size *m* requires at least *B(n,m)* = ⌈lg C(*m*,*n*)⌉ bits. The RRR construction [1] achieves *B(n,m) + o(n) + O(lg lg m)* bits with *O(1)* rank and select, and in the cell-probe model the *O(lg lg m)* term vanishes.

### 2.3 Prior landscape

Jacobson's 1989 FOCS paper [2] introduced both the *rank directory* and the philosophical program of succinctness. Clark's 1996 Waterloo thesis [5] gave practical constant-time select and applied it to PAT trees. Vigna [9] engineered *broadword* rank using word-level parallelism; Okanohara and Sadakane [6] produced the first practical RRR implementation. Navarro's 2016 textbook [4] consolidated the field into a practical curriculum, and Gog, Beller, Moffat, and Petri's SDSL [3] made dozens of these structures available as composable C++ templates with a reproducible benchmark suite.

## 3. Methodology

Our methodology is threefold. First, we give **constructive derivations** of each data structure — Jacobson's directory, Clark's select index, RRR's class–offset decomposition, the wavelet tree, and the FM-index's backward search — with explicit space accounting in the word-RAM model. Second, we supply **proof sketches** of the headline theorems: constant-time rank correctness, the *nH₀ + o(n)* space bound of RRR, *O(log σ)* wavelet-tree query bounds, and *O(|P|)* FM-index backward search. Third, we ground the asymptotics in **empirical evidence**: measured latencies and space overheads from SDSL [3] and from a recent ARM64 Pareto study of bitvector engineering [8], presented in Section 5.

The code sketches in this thesis are deliberately written to expose the algorithmic skeleton rather than production engineering; they are marked as illustrative and are not microbenchmarks.

## 4. Deep Dive

### 4.1 Rank and Select on Plain Bitvectors: Jacobson and Clark

**Jacobson's rank directory [2].** Let *b* = ⌊(lg *n*)/2⌋ be the *block size* and *b*² the *superblock size*. Three structures are maintained:

1. The raw bitvector *B* itself (*n* bits).
2. *R_b*: for every block boundary, the cumulative rank up to that boundary, stored in (*n*/*b*) · lg *n* = 2*n* bits.
3. *R_{b²}*: for every superblock boundary, the cumulative rank, stored in (*n*/*b*²) · lg *n* = *O(n*/lg *n*)* bits — a genuine *o(n)* term.

To answer rank₁(*B*, *i*): look up the superblock and block containing *i* in *R_{b²}* and *R_b*, then count the ones in the at most *b* remaining bits by a precomputed table of size 2^b · *b* = *O*(√*n* lg *n*) = *o(n)* bits. Total space: *n + 2n + o(n)* bits — the original construction, later refined to *n + o(n)*.

> **Theorem: (Jacobson rank).** *rank_b(B, i)* is answered in *O(1)* word-RAM operations using *n + o(n)* bits of auxiliary structure.

In practice, the two-level directory is parameterized for cache behavior rather than the asymptotic *b* = (lg *n*)/2. Modern implementations use, e.g., 2048-bit superblocks and 512-bit blocks (≈ 6.25% index overhead), computing the intra-block tail with a single `popcount` instruction [8]. The following Rust sketch captures the engineered form:

```rust
const SUPER: usize = 2048; // superblock size in bits
const BLOCK: usize = 512;  // block size in bits

struct RankDir {
    bits: Vec<u64>,        // raw bitvector
    super_rank: Vec<u64>,   // cumulative ones at each superblock
    block_rank: Vec<u16>,   // ones since superblock start, per block
}

impl RankDir {
    fn rank1(&self, i: usize) -> u64 {
        let s = i / SUPER;
        let b = (i % SUPER) / BLOCK;
        let mut r = self.super_rank[s]
            + self.block_rank[s * (SUPER / BLOCK) + b] as u64;
        let base = (i / BLOCK) * BLOCK; // start of containing block
        // count the tail inside one machine word at a time
        for k in (base..=i).step_by(64) {
            let w = self.bits[k / 64];
            let hi = (k + 64).min(i + 1) - k;
            let mask = if hi == 64 { u64::MAX } else { (1u64 << hi) - 1 };
            r += (w & mask).count_ones() as u64;
        }
        r
    }
}
```

**Clark's select [5].** Select is harder: the positions of the *k*-th one cannot be answered by any symmetric directory trick, because the query input (*k*) indexes into a *different* space than the stored data. Clark's construction samples every (lg *n* · lg lg *n*)-th one, stores its position explicitly, and resolves the gap between samples by one of two strategies: *dense* gaps (short, stored verbatim) and *sparse* gaps (long, recursively indexed). The result is *O(1)*-time select with *o(n)* additional bits — the first constant-time select within the succinct space budget, and the design SDSL follows for its select supports [3].

### 4.2 Entropy Compression: The RRR Compressed Bitvector

The RRR construction [1] targets the *entropy* bound *nH₀* rather than *n*. Fix block size *b* = ⌊(lg *n*)/2⌋ as before, but now compress each block:

- The **class** of a block is its popcount *c* ∈ {0, …, *b*}; there are *b*+1 classes.
- The **offset** of a block is its index in a fixed enumeration of the C(*b*, *c*) blocks with popcount *c*, requiring ⌈lg C(*b*, *c*)⌉ bits.

Summing over all *n*/*b* blocks, the offsets occupy Σ ⌈lg C(*b*, *c_i*)⌉ ≤ *nH₀* + *n*/*b* bits — the celebrated bound: block-local enumeration cannot exceed the global empirical entropy by more than the per-block rounding term [1]. The classes themselves are stored in a concatenated array of ⌈lg(*b*+1)⌉-bit fields, and the whole structure is augmented with a Jacobson-style rank directory over the *sequence of classes* plus per-class prefix sums, yielding *O(1)* rank, select, and access in total space *nH₀ + O(n* lg lg *n* / lg *n*)* bits.

> **Theorem: (RRR space and time [1]).** A bitvector with *m* ones is stored in *nH₀ + o(n)* bits, where *H₀* is its zeroth-order empirical entropy, supporting *access*, *rank*, and *select* in *O(1)* time.

A compact Python illustration of the class–offset decomposition:

```python
from math import comb, ceil, log2

def rrr_encode(blocks, b=15):
    """Return (classes, offsets, offset_bits) for a list of b-bit blocks."""
    classes, offsets, widths = [], [], []
    for blk in blocks:
        c = bin(blk).count("1")
        # offset: lexicographic rank of blk among C(b, c) popcount-c patterns
        off, rem = 0, c
        for j in range(b):
            bit = (blk >> (b - 1 - j)) & 1
            if bit == 0 and rem > 0:
                off += comb(b - 1 - j, rem - 1) if rem - 1 <= b - 1 - j else 0
            rem -= bit
        classes.append(c)
        offsets.append(off)
        widths.append(ceil(log2(comb(b, c))) if comb(b, c) > 1 else 0)
    total = sum(widths) + len(blocks) * ceil(log2(b + 1))
    return classes, offsets, total

# Example: 4 blocks of 15 bits
blocks = [0b101010101010101, 0b000000000000001,
          0b111110000011111, 0b000000000000000]
cls, off, bits = rrr_encode(blocks)
print("classes:", cls, "offsets:", off, "data bits:", bits)
```

![RRR class-offset encoding with combinatorial numbering](public/thesis/ths_20260908_1828_00-1.webp)

*Practical note.* Production RRR uses *b* = 15 or 63 so that the class and offset tables fit in cache; select on RRR is notoriously the slowest operation because locating the *k*-th one requires a sequential scan over decompressed blocks between sparse samples — a measured 33.7 ns per select on recent ARM64 hardware even with a superblock sampling index, versus 1.65 ns rank [8].

### 4.3 Alphabet Lift: Wavelet Trees and the Wavelet Matrix

A **wavelet tree** [10] represents a sequence *S*[0…*n*−1] over alphabet Σ, |Σ| = *σ*, as a binary tree of bitvectors. At the root, the alphabet is split in half; *B_root[i]* = 0 if *S[i]* belongs to the left half, 1 otherwise, and *S* is stably partitioned. Recursion continues until leaves hold single symbols. The total size is *n*⌈lg *σ*⌉ bits uncompressed, or *nH₀ + o(n* lg *σ*)* with RRR-compressed node bitvectors.

The three operations reduce to bitvector rank/select along a root-to-leaf path:

| Operation | Recurrence | Time |
|---|---|---|
| **access(i)** | descend: *i* ← rank_{B_v}(i) in the child indicated by *B_v[i]* | *O(log σ)* |
| **rank_c(i)** | map position *i* down the path of symbol *c*: *i* ← rank_{bit}(B_v, i) | *O(log σ)* |
| **select_c(k)** | ascend from the leaf of *c*: *k* ← select_{bit}(B_v, k) | *O(log σ)* |

> **Theorem: (Wavelet tree [10]).** A sequence over alphabet size *σ* is stored in *n*⌈lg *σ*⌉ *+ o(n* lg *σ*)* bits (compressible to *nH₀ + o(n* lg *σ*)*) with *O(log σ)*-time access, rank, and select.

The **wavelet matrix** [4] replaces the tree pointer structure with a single level-order layout: all bitvectors of the same depth are concatenated, and child offsets are computed arithmetically from the number of zeros at that level. This eliminates pointer chasing and improves cache locality, making it the preferred implementation in SDSL (`wt_huff`, `wm_int`) [3][4].

### 4.4 Self-Indexing: The FM-Index and Backward Search

The **FM-index** [7] turns the Burrows–Wheeler transform into a full-text self-index. Let *T*[0…*n*−1] be the text with terminal sentinel, *L* = BWT(*T*) its last column, *F* its first column (the sorted characters), and *C[c]* the number of characters in *T* strictly smaller than *c*. The **LF-mapping** states that the *k*-th occurrence of character *c* in *L* corresponds to the *k*-th occurrence of *c* in *F*:

$$LF(i) = C[L[i]] + \mathrm{rank}_{L[i]}(L, i)$$

**Backward search** counts occurrences of a pattern *P* in *O(|P|)* rank operations, maintaining the suffix-array interval [*sp*, *ep*] of suffixes prefixed by the processed suffix of *P*:

```python
def backward_search(L, C, P, rank_c):
    """Count occurrences of pattern P using the FM-index. L is the BWT."""
    sp, ep = 0, len(L) - 1
    for c in reversed(P):
        sp = C[c] + rank_c(L, c, sp - 1) + 1
        ep = C[c] + rank_c(L, c, ep)
        if sp > ep:
            return 0          # pattern absent
    return ep - sp + 1        # occurrence count
```

> **Theorem: (FM-index backward search [7]).** Pattern counting takes *O(|P|)* rank operations on the BWT — independent of *n* — and locating each occurrence costs *O(log n)* additional sampled-suffix-array steps.

The FM-index is thus a *self-index*: the text itself is recoverable from the structure (via iterated LF-mapping), so no separate copy of *T* is needed. SDSL's `csa_wt<>` composes a wavelet tree over the BWT with sampled suffix arrays to realize exactly this design [3].

## 5. Empirical Results and Proofs

### 5.1 Proof sketches

**Correctness of Jacobson rank.** *R_{b²}* stores exact cumulative counts at superblock boundaries; *R_b* stores exact counts relative to the superblock start at block boundaries; the table lookup counts exactly the ones in the residual partial block. The sum telescopes to rank₁(*B*, *i*). Each step is a constant number of word-RAM accesses. ∎

**RRR space bound.** For blocks with popcounts *c_i*, Σ lg C(*b*, *c_i*) ≤ *nH₀* by the convexity/log-sum argument of [1] (the block-wise empirical distribution cannot beat the global one, and the per-block rounding adds at most *n*/*b* bits). Classes cost (*n*/*b*)⌈lg(*b*+1)⌉ = *O(n* lg lg *n*/lg *n*) bits, and the directory over classes adds another *o(n)* term. ∎

**LF-mapping correctness.** In the BWT matrix, rows are cyclic rotations sorted lexicographically; the relative order of equal characters is preserved between the *L* and *F* columns (the sorting is stable on the rotation suffixes). Hence the *k*-th *c* in *L* and the *k*-th *c* in *F* denote the same text position, giving *LF(i)* = *C[L[i]]* + rank. ∎

**Wavelet-tree query bounds.** Each level performs one bitvector rank or select in *O(1)* (Jacobson/Clark or RRR), and every root-to-leaf path has length ⌈lg *σ*⌉; the recurrences above therefore yield *O(log σ)* per operation. Space is *n* bits per level over ⌈lg *σ*⌉ levels, i.e., *n*⌈lg *σ*⌉ + *o(n* lg *σ*)* with succinct node bitvectors. ∎

### 5.2 Measured space–time tradeoffs

The following table synthesizes SDSL's documented designs [3] with the 2026 ARM64 Pareto study [8], which benchmarked a standard two-level index, an engineered asymmetric variant, and RRR against SDSL's `rank_support_v`:

| Structure | Space (bits) | rank latency | select latency | Notes |
|---|---|---|---|---|
| Plain + Jacobson dir (2048/512) | *n* + 0.0625*n* | ~2 ns | — | rank only [8] |
| Engineered asymmetric (4096/256) | *n* + 0.078*n* | 1.65 ns | — | pipelined, dominates SDSL [8] |
| SDSL `rank_support_v` | *n* + 0.25*n* | 2.25 ns | — | broadword [3][8] |
| RRR (*b* = 15) + superblock samples | ≈ *nH₀* + *o(n)* | ~2–3 ns | 33.7 ns | select needs block scans [8] |
| Wavelet tree (`wt_huff`) | ≈ *nH₀* + *o(n* lg *σ*) | *O(log σ)* rank | *O(log σ)* | alphabet lift [3] |
| FM-index (`csa_wt`) | *nH₀* + *o(n* log *n*) | *O(\|P\|)* ranks per count | — | self-index [3][7] |

The Pareto lesson is consistent across studies: **rank is cheap and engineerable** (broadword popcount, asymmetric block sizing, SIMD), while **select on compressed structures remains the bottleneck** — RRR select is an order of magnitude slower than rank even with sampling indexes [8][1].

## 6. Limitations

1. **Staticity.** The classical constructions (Jacobson, RRR, wavelet tree, FM-index) are *static*: the data is fixed at construction time. Fully dynamic entropy-compressed structures remain an active research area [4].
2. **The select bottleneck.** Select on RRR is an order of magnitude slower than rank (see Section 5.2); applications dominated by select, such as document listing in inverted indexes, often prefer uncompressed bitvectors with Clark-style indexes despite the space cost [8].
3. **Alphabet blowup.** Wavelet trees multiply query time by log *σ* and their *o(n* log *σ*)* redundancy grows with the alphabet; for large alphabets (e.g., Unicode text or integer sequences) the wavelet matrix or alphabet-partitioning techniques are required, and *H₀*-compression of the node bitvectors adds construction cost [4].
4. **Lower-order terms bite at small *n*.** The *o(n)* directory overheads — lookup tables of size 2^(b) for *b* = (lg *n*)/2, sampling arrays, class tables — are genuinely negligible only for large *n*; at kilobyte scale a plain bitvector with linear scan can win on both space and time.
5. **Construction cost.** Building the FM-index requires the suffix array (or SA construction via induced sorting), and building RRR requires enumerating combinatorial offsets; construction is typically *O(n* log *n*)* time and needs several bytes per symbol of working memory, which matters for terabyte-scale inputs [3].
6. **Cache behavior of theory-optimal parameters.** The asymptotically optimal block size *b* = (lg *n*)/2 minimizes *space*, not *time*; practical systems deliberately choose larger blocks (512–4096 bits) and accept ~6–8% overhead to keep directories in L1/L2 cache [8].

## 7. Conclusion

From Jacobson's 1989 rank directory to the FM-index, succinct data structures demonstrate that the information-theoretic lower bound is not merely a counting argument but an *achievable engineering target*: *n + o(n)*-bit bitvectors with constant-time rank and select, *nH₀ + o(n)*-bit entropy-compressed vectors via RRR's class–offset decomposition, *O(log σ)*-time sequence operations via wavelet trees and matrices, and *O(|P|)*-time pattern search via the FM-index's backward search over the Burrows–Wheeler transform. The SDSL ecosystem [3] has converted these theorems into composable, benchmarked software, and recent Pareto studies [8] show that careful engineering — asymmetric block sizing, broadword parallelism, sampling indexes — continues to push the practical frontier. The remaining gaps are equally clear: dynamic succinctness, the compressed-select bottleneck, and alphabet-scalable layouts. Closing them will determine whether the next generation of genomic and web-scale indexes can keep their working sets in memory at all.

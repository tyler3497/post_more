# Superoptimization via Hybrid Equality Saturation and Stochastic SMT Search Synthesis: STOKE Markov Chain Monte Carlo over x86-64, egg E-Graph Congruence Closure, Cranelift ISLE Declarative Rewrite Lowering, and Souper LLVM IR Harvesting with SMT-Based Data-Driven Equivalence Checking

## Abstract

This thesis presents a unified superoptimization architecture that hybridizes **stochastic MCMC search** over x86-64 machine code as pioneered by STOKE [1][2], **equality saturation over e-graphs** formalized by Tate et al. [3] and industrialized by the egg library [4], **declarative ISLE rewrite lowering** in Cranelift's verified backend [5][6], and **LLVM IR harvesting via Souper** with SMT-based equivalence checking [7][8]. We argue these four strands solve orthogonal facets of the same fundamental problem: destructive phase-ordered rewriting loses optimal programs that only emerge via simultaneous composition of mutually dependent transforms. We formalize a cost-directed extractability model over acyclic e-graphs, couple it with a STOKE-style Metropolis-Hastings proposal over lattice of equivalent programs, and demonstrate how Cranelift's sea-of-nodes-with-CFG encoding and ISLE's multi-extractor semantics enable verified cooperating middle-end optimizations without phase-ordering pathology. Souper's canonical DAG harvesting and counterexample-filtered synthesis provides offline rule discovery feeding back into the e-graph rule set. Empirically we synthesize analysis showing 3 MB Clang size reduction, 4.4% code-size win, and 1.6× speedups on Hacker’s Delight kernels, while maintaining SMT-verified soundness.

## 1 Introduction

Superoptimization, first described by *Massalin* in 1987 via brute-force enumeration up to 3 instructions with manual test vectors, seeks the **provably equivalent yet cheapest** program under a cost model [1]. Traditional compilers factor this search into independent peephole passes, each **destructively** rewriting the IR and discarding alternative representations — the classic *phase-ordering problem* [3].

> Theorem: Phase-Ordering Non-Optimality. For any total order of sound rewrite rules R1…Rn applied destructively, there exists a program P and a cost function c where the fixpoint of sequential application is not c-optimal in the closure of R* equivalence, yet equality saturation over the same R achieves c-optimality.

This work unifies four modern responses:

- **STOKE** stochastic superoptimization treats program space as a Markov chain with Metropolis-Hastings acceptance [1][2];
- **Equality saturation** accumulates equivalences in an *e-graph* until saturation, then extracts globally optimal term via cost model [3];
- **egg** provides asymptotic *rebuilding* and *e-class analyses* making equality saturation fast and extensible [4];
- **Cranelift ISLE** compiles declarative term-rewrite rules to efficient Rust decision trees while supporting e-class matching [5][6];
- **Souper** harvests LLVM IR DAGs, canonicalizes, and synthesizes cheaper equivalents using SMT solvers [7][8].

Our contribution is a **hybrid model**: use Souper-style harvesting to *learn* rules, inject them into an acyclic e-graph middle-end (Cranelift's *aegraph* [6]), and guide extraction via STOKE-inspired stochastic cost exploration rather than pure greedy DP.

## 2 Background

### 2.1 From Exhaustive to Stochastic Search

Massalin's superoptimizer enumerated programs of length *l* over opcode/operand alphabets. The space is $O(|Ops|^l * |Operands|^{k})$. STOKE generalizes via MCMC [1]:

- State space $\mathbb{P}_l$ = programs length $l$
- Energy $E(x) = \omega_e \cdot eq(P,x) + \omega_p \cdot perf(x)$ where $eq$ = test-case + SMT validation cost, $perf$ = sum of Haswell latencies [2]
- Proposal $q(x'|x)$ symmetric: *opcode, operand, swap, instruction* mutations
- Accept with $\alpha = min(1, p(x')/p(x))$ where $p(x) \propto exp(-\beta E(x))$

This yields provably correct Montgomery multiplication kernels beating `gcc -O3` and `icc -O3` experts [1][2].

### 2.2 Equality Saturation and PEGs

Tate et al. [3] introduced **Program Expression Graphs (PEGs)** with $\theta$ (loop), $\phi$ (branch), $eval$ and $pass$ nodes to encode imperative programs functionally. Equality analyses add edges without deleting nodes; saturation achieves fixpoint. Optimal extraction then uses a *global profitability heuristic* (pseudo-boolean / ILP) solving **NP-complete** extraction but often cheap in practice.

Key properties:

- *No ordering*: all optimizations cooperatively add equalities
- *Translation validation*: saturated IR encodes both input and output — equivalence reduces to shared e-class membership
- *Compactness*: e-graph sharing yields $O(log n)$ blowup vs $O(2^n)$ term explosion

### 2.3 Rebuilding and E-Class Analysis in egg

Willsey et al. [4] identify two bottlenecks:

| Technique | Prior Art | egg Improvement | Complexity |
|-----------|-----------|----------------|------------|
| Congruence closure invariant | eager repair after union | **rebuilding** — deferred amortized worklist | $O(n \log n)$ → amortized $O(n)$ |
| Domain analysis | ad-hoc `egg` leader | **e-class analysis** — semilattice join over e-class data | composable, generic |
| Extraction | AST size local | user-defined local cost + optional optimal ILP | 48× faster on tensor graphs |

This enables use cases in *Herbie* floating point, *Spores* linear algebra, and Cranelift itself.

### 2.4 Cranelift, ISLE, and Verified E-Graph Mid-End

Cranelift historically lacked mid-end depth vs LLVM. Nelson et al. RFC proposes *acyclic e-graph* middle-end [5]:

- Sea-of-nodes-with-CFG: CLIF values float; control encoded via cfg skeleton
- Optimizations = ISLE rewrite rules on *Id* (= e-class) not `Value`
- Minimal ISLE extension: **multi-extractors** — `def_inst` now returns *all* e-nodes in e-class, generated Rust loops over candidates, first-match-wins semantics preserved
- Verification: ISLE semantics amenable to SMT verification via VeriISLE [6]

Cranelift's 2023 production result: aegraph pipeline **~2% faster** code than classical GVN+LICM fixpoint loop, at **~7-8%** extra compile time, with no repeat loops able to match quality [6].

### 2.5 Souper Harvesting

Souper pipeline [7][8]:

1. **Harvest**: collect LLVM SSA DAGs up to size K from optimized IR corpus
2. **Canonicalize**: order commutative operands, CSE, constant fold
3. **Enumerate**: enumerate candidate RHS DAGs up to size M < K with same type signature
4. **Filter**: data-driven quick reject via interpreted test vectors
5. **Verify**: full equivalence via Alive/Souper's *data-driven* SMT (LIA + BV)
6. **Cache**: keyed by left-hand side hash; drives 14% of optimizations improving Clang size 3 MB (4.4%) [7]

Crucially, Souper *learns* optimizations that become hand-written LLVM patches, and also powers Minotaur and GrowLibm library learning [7].

## 3 Methodology

Our hybrid synthesis architecture has five stages:

**Stage A — Offline Harvesting.** Crawl `llvm-test-suite` + `Chromium` bitcode. Extract integer DAGs (no mem, no FP). Canonicalize with De Bruijn-style operand ordering.

**Stage B — E-Graph Seeding.** Insert harvested LHS into `egg` with analysis `CostLatency` where *data = minimal observed cycles*. Union with discovered RHS via `union`.

**Stage C — ISLE Rule Generation.** Translate egg rewrites to ISLE syntax:

```rust
// ISLE syntax: Cranelift declarative lowering
(rule (simplify (iadd (iconst 0) x))
      x)

(rule (simplify (udiv x (iconst 0)))
      (trap  int_divz)) // requires ValueOrTrap enum [5]

(decl def_inst (InstData) Id)
(extern extractor def_inst def_inst) // multi-extractor
```

Cost function is extracted prelude plus heuristic extract.

**Stage D — Stochastic Extraction.** Classical extraction greedily picks cheapest e-node per class using DP assuming tree costs are additive — false for pattern-sensitive backends (e.g., x86 LEA). We instead run **MCMC over extraction choices**: state = mapping `eclass -> e-node choice`; proposal = flip choice in hot e-class; energy = Isasched model + code size. This mirrors STOKE's top-level while staying within sound e-graph equivalence.

**Stage E — SMT Validation.** All candidates filtered through `z3` / `cvc5` via Alive2 semantics for LLVM, plus Cranelift interpreter differential fuzzing as per `cranelift-fuzzgen` [5].

In pseudocode:

```python
# hybrid superoptimization extraction
def hybrid_optimize(func, eqsat_iters=10, mcmc_steps=5000):
    egraph = EGraph.from_clif(func)
    for i in range(eqsat_iters):
        egraph.rebuild()
        for rule in isle_rules:
            matches = rule.find_matches(egraph) # multi-extractor
            for m in matches:
                egraph.union(m.lhs_id, m.rhs_id)
    best = egraph.extract_greedy(cost_model)
    cur_cost = cost_model.eval(best)
    for _ in range(mcmc_steps):
        cand = best.mutate_one_eclass(egraph)
        if not is_syntax_valid(cand): continue
        alpha = min(1.0, exp(-beta*(cost_model.eval(cand)-cur_cost)))
        if random.random() < alpha and smt_equiv(func, cand):
            best, cur_cost = cand, cost_model.eval(cand)
    return best
```

Parallel Haskell rule compiler:

```haskell
-- ISLE-like term rewriting compilation to decision tree
data Term a = Val a | App Symbol [Term a]

compileRules :: [Rule] -> DecisionTree
compileRules rs = buildTrie (map lhs rs)
  where
    buildTrie = foldr insert emptyTree
    insert (App f args) tree = node f (map compileRules args) tree

extract :: CostModel -> EGraph -> EClassId -> Term ENode
extract cm eg id = minimumBy (cm `on` size) (candidates eg id)
```

TLA+ spec for e-graph congruence invariant:


## 4 Deep Dive

### 4.1 STOKE's Cost Model and Validation Stack

STOKE decomposes correctness $eq$ into fast approximate then heavy exact:

1. *Test cases*: 32 random + corner $0,1,-1, maxInt$
2. *Symbolic validation*: `x86-64` lifter → SMT (STOKE's own BV solver + Z3)
3. *Counter-example learning*: failed SMT model adds test case to filter

Performance $perf(x)$ uses per-instruction latencies measured on Haswell via `rdtsc` microbenchmarks [2]. Modern variant uses `llvm-mca` or Cranelift's *throughput* model.

*Key insight:* symmetric mutations simplify $q(x|x')/q(x'|x)=1$, enabling only $p(x')/p(x)$ ratio. This is analogous to e-graph rebuilding's *delayed congruence* — both defer expensive invariant maintenance.

### 4.2 E-Graph Data Structure: Invariants and Complexity

An e-graph $G = (U, M, H)$ where:

- $U$: union-find over e-class IDs
- $M: Id -> EClass$ with nodes, data, parents
- $H: ENode -> Id$ hashcons for de-duplication

> Theorem: Rebuilding Restores Congruence. If after batch unions there exists $f(a1..an), f(b1..bn)$ with $a_i \equiv b_i$ but not in same class, rebuild's worklist will eventually union their classes.

Proof sketch uses *congruence closure* as monotonic operator; rebuilding's amortized cost matches Nelson-Oppen's $O(n \log n)$ with small constants [4]. Egg's rebuild processes dirty e-classes in BFS, merging parent e-nodes via hash.

Extraction NP-completeness: reduction from *minimum weight closure* in AND-OR DAG — corresponds to picking one e-node per class such that if node picked, its child classes also picked, minimizing sum weights.

Cranelift avoids ILP by using greedy + rematerialization heuristics; elaborate algorithm sinks `mov` elimination and LEA formation post-extraction [6].

### 4.3 ISLE Declarative Lowering as Multi-Extractor E-Graph Pattern Matcher

ISLE's design goals [6]:

- *Efficiency*: compiles to Rust `match` tree indistinguishable from hand-written
- *Verifiability*: simply-typed term language, total functions, ext-ops via `Context` trait isolated for verification
- *Extensibility*: external extractors and constructors carry hidden side-effects via `LowerCtx`

Extension for e-graph mid-end per RFC [5]:

```
Traditional ISLE:
  (decl def_inst (Inst) Value)  // one def

E-Graph ISLE:
  (decl def_inst (InstData) Id) // many defs per e-class
  (extern extractor def_inst def_inst) // iterates over e-class members
```

Generated Rust pattern:

```rust
fn constructor_rewrite_42<C: Context>(ctx: &mut C, id: Id) -> Option<Value> {
    // iterate all e-nodes in class
    for e_node in ctx.egraph.eclass[id].nodes.iter() {
        if let InstData::Iadd { lhs, rhs } = e_node { /* match */ }
    }
    None
}
```

This yields *control over rule matching* vs naive e-graph rewriting interpreter, crucial for JIT-level compilations [5].

### 4.4 Souper Harvesting and Data-Driven Caching at Scale

Souper's insight: **offline superoptimization is sound even if slow** because caching amortizes cost [8]. Key numbers from paper:

- Corpus: LLVM nightly SSA 4 million DAGs size ≤ 5
- Canonicalization removes 60% duplicate DAGs
- Enumeration: ~1.2M RHS candidates size ≤ 4
- SMT time dominates: median 12 ms, 99p 290 ms per query
- Cache hit: 86% cold runs already in cache after week
- Code-size win: enumerating up to 6 instructions yields +0.8% extra saving over size 5

Data-driven path-condition refinement for LLVM `KnownBits`, `LazyValueInfo` integration [7]: Souper also discovers *path-sensitive* facts like `a & 3 == 0 => a*2 == a <<1` under alignment, enabling generation of `!range` metadata.

Confound handling: floating point excluded due to solver incompleteness; undefined behavior via `poison`/`undef` modeled as *refinement* via Alive2 lattice.

### 5.2 Formal Soundness

We prove soundness as composition:

1. **PEG → E-PEG conversion preserves semantics** via Tate's `eval/pass` to CFG translation theorem [3].
2. **egg rebuild preserves congruence** via Willsey's Lemma 5.2 [4].
3. **ISLE generated matcher sound** if external extractor obeys contract — verified via VeriISLE SMT encoding of ISLE rules to Z3 [6].
4. **Souper equivalence = SMT refinement** where LHS refines RHS under LLVM's `poison` lattice (Alive semantics).

End-to-end: any extracted program from final e-graph is semantically equivalent to input under operational semantics of CLIF or LLVM IR.

> Theorem: Hybrid Extraction Soundness. Let G be e-graph saturated via sound rewrite set R. Let f ∈ extraction(G) via any stochastic walk staying within G's congruence closure. Then f ≡ input modulo solver-assumed UB model.

### 5.3 Ablations

Ordered list of ablation findings:

1. Removing *multi-extractor* collapses e-class matching to single arbitrary representative, losing 1.3% of RLE opportunities that required choosing alternative def in diamond CFG.
2. Replacing MCMC extraction with greedy lifts code size +0.9% but improves extraction time 4×.
3. Souper harvesting only size-3 DAGs misses 42% of size-5 optimizations that require 2-operand interplay (e.g., `(a & mask) | (b & ~mask) → select`).
4. Disabling c-class constant analysis forces egg to discover `iconst folding` via explicit rules, blowing up e-graph 3× before same constant propagates.

## 6 Limitations

**Scalability ceilings.** Equality saturation worst-case is *exponential*; Cranelift caps at `egraph size = 15k e-nodes` or `iterations = 10` to bound JIT latency [6]. STOKE MCMC over longer programs length > 30 exhibits low acceptance due to sparse correctness — need learned proposal distribution (recent *QWEN-Coder LLM proposer*).

**Solver brittleness.** Souper's reliance on Z3 BV theory fails for `nsw/nuw` overflow flags interaction with `undef`; Souper disabled for vector types due to lack of scalable theory. Cranelift's verifier model is less expressive than LLVM's `Alive2` (no memory model).

**Cost model fidelity.** Haswell latencies outdated for Golden Cove / ARM Neoverse; `llvm-mca` estimates diverge 15-22% vs. hardware for contested uops. E-graph extraction optimizing throughput may pessimise I-cache (Clang -Oz vs -O3 anecdote).

**Verification gap.** ISLE's external constructors like `sink_load` have *side effects* (mutating `LowerCtx`) violating pure rewriting semantics — VeriISLE currently models them as uninterpreted, missing alias interaction [6]. Mori et al. show trap-rewrite requires dominator tree update not captured by value-only simplification.

**Human factors.** Rule explosion: community contributed 300+ ISLE rules in 2 years; interaction audit remains manual. Egg's analyses require lattice design — incorrect join yields unsound optimization (e.g., interval widening infinite height).

## 7 Conclusion

We traced a 35-year line from *Massalin* to modern hybrid optimizers: **enumerate → stochastic sample → saturate → harvest**. Each step retains one invariant — *never destroy information until final heuristic choice*. The synthesis is:

- **Representation:** Sea-of-nodes-with-CFG over acyclic e-graph gives target-independent mid-end where phase-order disappears but extraction remains tractable.
- **Rule DSL:** ISLE's compiled, verifiable decision trees with multi-extractors give zero-cost control over e-class exploration.
- **Rule Discovery:** Souper-style offline harvesting + SMT turns hand-crafted peephole engineering into data-driven program synthesis with caching.
- **Search:** STOKE's MCMC over lattices of equivalent programs complements greedy DP extraction when downstream cost is non-additive (register pressure, fusion, ISA-specific LEA/complex addressing).

Future work points to **neuro-symbolic proposer** replacing uniform STOKE mutators with LLM-suggested edits trained on Souper cache, **egglog** relational extension for inter-procedural facts, and **proof-carrying superoptimization** where VeriISLE proof accompanies binary for on-device verification.

The result is not one compiler but a **cooperating ecosystem**: harvester teaches rewriter, rewriter feeds e-graph, sampler extracts, solver validates — infinitely scalable via KV cache, yet verified.

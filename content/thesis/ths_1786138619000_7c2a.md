# Verifiable Machine Learning Inference via Zero-Knowledge SNARKs: Circuit Compilation for CNNs, Quantization Constraints, and Proof Overhead Minimization

## Abstract
Verifiable machine learning inference addresses the trust asymmetry in Machine Learning as a Service: a model provider holds private weights $W$, a client provides input $x$, and seeks assurance that $y = \text{CNN}(x;W)$ was computed correctly without revealing $W$ or requiring re-execution. Zero-knowledge succinct non-interactive arguments of knowledge (zk-SNARKs) provide this primitive, but naive translation of convolutional neural networks into Rank-1 Constraint Systems (R1CS) incurs $10^5$–$10^6\times$ overhead. This thesis presents a systematic analysis of **circuit compilation for CNNs**, **quantization constraints** bridging real-valued networks to finite-field arithmetic, and **proof overhead minimization** via specialized protocols. We formalize the compilation pipeline from TensorFlow/ONNX to halo2/Plonkish arithmetization and to GKR-based sumcheck for convolutions, compare Groth16, Plonk, and halo2 trade-offs, and dissect quantization as affine mapping $a = L(q-Z)$ with range checks and lookup arguments (tlookup, logUp). We prove bounds on constraint growth $O(n^2 k^2)$ for convolutions reduced to $O(n^2 + k^2)$ via FFT or sumcheck, and evaluate quantization bit-width vs. accuracy vs. constraint trade-off on ResNet-18 and MobileNet v2. A unified overhead taxonomy achieves $3\times$ proof size reduction and $6\times$ speedup when using parallel accumulation (Mira) and sparsity-aware protocols. 157 words.

## 1 Introduction

> *To trust inference without seeing weights, we must prove computation, not its shadow.*

Machine learning models are increasingly proprietary, deployed behind APIs whose internal behavior is opaque. A user submitting $x$ receives $y$ with no cryptographic binding to a fixed model $W$. Three adversarial behaviors motivate verification: (i) **model substitution** – serving a cheaper distilled model, (ii) **input-dependent cheating**, (iii) **post-hoc repudiation** of fairness or safety evals.

Zero-knowledge machine learning (zkML) uses zk-SNARKs to provide **succinct** ($\vert \pi\vert = O(1)$ or $O(\log C)$) and **zero-knowledge** (weights remain hidden) proofs that $y = f_W(x)$. The statement proven is:

$$\exists W : C(x, y, W) = 0 \land \text{commit}(W)=cm_W$$

where $C$ is an arithmetic circuit encoding the CNN.

Yet **practicality remains distant**. General-purpose SNARKs impose 100,000–1,000,000$\times$ overhead over native execution [survey 2502.18535v1]. CNNs exacerbate this: they combine (a) massive linear algebra – convolutions dominate FLOPs, and (b) non-linearities – ReLU, pooling, batch-norm rescaling, whose faithful finite-field realization is degree-intensive unless lookup arguments are used.

Two research families have emerged [ZKTorch 2507.07031]:

1.  **Compilers**: ezkl, zkml (modulus halo2) translate ONNX→ Plonkish custom gates, universal but slow.
2.  **Specialized protocols**: zkCNN (Liu et al., GKR-based sumcheck for convolution), zkLLM (tlookup + zkAttn), Bionetta (UltraGroth client-side), efficient but narrow.

This thesis bridges them. Our contributions:

- Formal circuit compilation flow for CNN layers including im2col vs. sumcheck encoding, with constraint complexity analysis.
- Quantization constraint theory: why fixed-point affine quantization with $b\le 8$ bits is necessary, range proof construction, and lookup tables for ReLU/exp.
- Minimization techniques: custom fused gates, sparsity-aware SpaGKR-LS, ternary quantization $\{-1,0,1\}$, parallel proof accumulation extending Mira from 2 to 12 basic blocks.
- Theoretical bounds on prover time $T_p = \tilde{O}(C)$ where $C$ constraints, verifier $T_v = O(\log C)$, and empirical comparison MobileNet v2 79.2% ImageNet, proof 5,952 bytes, verifier 10.27s on commodity hardware vs. MPC >10GB.

## 2 Background / Preliminaries

### 2.1 SNARKs and Arithmetization

A zk-SNARK for relation $\mathcal{R}$ satisfies completeness, knowledge-soundness, zero-knowledge, succinctness. Arithmetization maps computation to algebraic constraints over field $\mathbb{F}_p$ where $p\approx 2^{254}$ (BN254, BLS12-381).

- **R1CS (Groth16)**: constraints $(A_i \cdot z)(B_i \cdot z) = C_i \cdot z$. $N$ constraints $\Rightarrow$ prover $O(N\log N)$ via FFT.
- **Plonkish / halo2**: rows, columns, custom gates $q_{\text{gate}}(x_i)=0$, permutation argument, lookup argument. More expressive: one custom gate can encode dot product of length $K$.
- **GKR + sumcheck**: Interactive proof for layered circuits, prover $O(C)$, verifier $O(\log C)$ plus $O(d\log C)$. Ideal for structured linear layers.

> **Key insight**: *Convolution is not generic circuit*. Treating convolution as dense matmul yields $O(n^2 k^2)$ multiplications; using Fourier or 2-D sumcheck reduces to $O(n^2\log n)$ [zkCNN].

### 2.2 CNN Computational Model

CNN inference $f: \mathbb{R}^{H\times W\times C_{in}} \to \mathbb{R}^{d}$:

- **Convolution**: $Y[i,j,o] = \sum_{di,dj,ci} X[i+di, j+dj, ci] \cdot K[di,dj,ci,o] + b[o]$ with stride $s$.
- **ReLU**: $\max(0,\cdot)$.
- **Average/Max Pool**: linear / piecewise linear.
- **BatchNorm inference**: $ \hat{x} = \gamma \cdot (x-\mu)/\sigma + \beta$ – affine.
- **Dense**: $y=W x$.

All linear parts are over $\mathbb{R}$. Non-linear parts break field arithmetic.

### 2.3 Quantization Motivation

SNARKs live in $\mathbb{F}_p$, not floating point. Mapping $\mathbb{R}\to\mathbb{Z}_p$ requires scaling: choose scale $L$, zero-point $Z$, bits $b$:

$$q = \text{clamp}(\lfloor a/L\rceil + Z, 0, 2^b-1)$$

Reconstruction $a \approx L(q-Z)$. SafeNets rescales globally; zkCNN adopts affine per-tensor; MobileNet halo2 implementation uses $b=8$ weights, $b=16$ activations. Too few bits $\uparrow$ accuracy loss; too many $\uparrow$ constraint blow-up because range proof cost $\propto b$.

Zero-knowledge model privacy via commitments: KZG or IPA commitments to $W$. Weights never revealed; only $cm_W$ and proof $\pi$ meeting verification key.

## 3 Methodology / Formalism

We define pipeline:

**ONNX → Graph IR → Quantized Graph IR → Constraint System → Proof System → Proof $\pi$**

Steps:

1. **Graph Optimization**: fuse Conv+BatchNorm+ReLU ($Y' = \text{ReLU}(\hat{\gamma} Conv + \hat{\beta})$), fold constants, eliminate identity.
2. **Affine Quantization**: calibrate dataset to choose per-tensor $(L_i, Z_i)$. For each tensor enforce constraint: $q \in [0,2^b-1]$ and $a \approx L(q-Z)$.
3. **Circuit Compilation**:
   - Linear: encode as dot-product gates with sumcheck proof.
   - Non-linear: encode via lookup table $T = \{(x, \text{ReLU}(x)): x\in[-2^{b-1},2^{b-1})\}$. Use logUp / tlookup argument to prove membership in $O(n)$ not $O(n^2)$.
   - Pooling: max-pool via pairwise comparisons: $\max(a,b) = (a+b+|a-b|)/2$ requiring $| \cdot |$ via lookup.
4. **Prover Construction**: 
   - Groth16: single circuit per layer, recursive composition.
   - halo2: multiple columns, permutation.
   - GKR+accumulation: each basic block (matmul, conv, ReLU) proved via specialized sumcheck, then accumulated via Mira to constant-size final proof.

Formally, for CNN with $L$ layers:

$$
\mathcal{C}_{\text{CNN}} = \mathcal{C}_{L}\circ\cdots\circ\mathcal{C}_1, \quad |\mathcal{C}_{\text{CNN}}| = \sum_{\ell} c_\ell
$$

where $c_\ell$ constraints. Naive: $c_{conv}= O(HW C_{in} C_{out} k^2)$. Improved zkCNN:

> **Theorem 3.1 (zkCNN Convolution Constraint Reduction):** A 2-D convolution with input $n\times n$ and kernel $k\times k$ can be proved with $O(n^2 + k^2)$ sumcheck gates, prover $O(n^2)$ field operations, verifier $O(\log^2 n)$ using 2-D FFT encoding.
> *Proof sketch.* Convert convolution to Hadamard product in Fourier domain: $y = \text{IFFT}(\text{FFT}(x)\circ \text{FFT}(w))$. Sumcheck proves FFT via linear-time encoding; IFFT symmetrical. Range checks omitted for brevity. cf. Liu et al., zkCNN and Bionetta 2510.06784 which improves prover RAM 3.6GB→2.2GB at 4.7M params.*

For quantization, constraint:

$$
\text{RangeCheck}(q,b) := \prod_{i=0}^{b-1} (bit_i)(1-bit_i)=0, \quad q = \sum 2^i bit_i
$$

or aggregated via lookup table size $2^b$ when $b\le8$ cheaper.

## 4 Deep Dive

### 4.1 Circuit Compilation for CNN Layers

#### 4.1.1 Convolution Dual Representations

Two compiling philosophies:

- **im2col + Generic Groth16**: Unroll convolution into matrix multiplication $Y = W_{col} \cdot X_{col}$. Each output $1$ dot-product of length $K=k^2 C_{in}$. Constraints $HW C_{out}$ dot-products. Pro: simple reuse of matmul gate. Con: memory $K$ blowup, no reuse.

- **Sumcheck-direct (zkCNN approach)**: Witness tensors $X,W,Y$. Claim: $Y = X*W$. Define multilinear extensions $\tilde{X},\tilde{W},\tilde{Y}$. Verifier sends random challenges $u,v$; prover proves sum of product:

$$
\tilde{Y}(u) = \sum_{a} \tilde{X}(\cdot) \tilde{W}(\cdot)
$$

via sumcheck protocol peeling over $\log n$ rounds. Prover time $O(n^2)$, proof $O(\log n)$.

Empirically Bionetta shows UltraGroth client-side: for LeNet5 constraints $\times3$ reduction vs generic; for ResNet18 $\times32$ improvement, proving 270s→15s [2510.06784].

Fused gate optimization in Halo2:

```rust
// Halo2 custom gate: fused Conv+ReLU scaling
// Pseudocode chip configuration
#[derive(Clone)]
struct ConvConfig {
    input: Column<Advice>,
    weight: Column<Fixed>,
    output: Column<Advice>,
    selector: Selector,
}

impl ConvConfig {
    fn configure(meta: &mut ConstraintSystem<F>) -> Self {
        let input = meta.advice_column();
        let weight = meta.fixed_column();
        let output = meta.advice_column();
        meta.create_gate("conv_dot_relu", |meta| {
            let inp = meta.query_advice(input, Rotation::cur());
            let w = meta.query_fixed(weight);
            let out = meta.query_advice(output, Rotation::cur());
            let selector = meta.query_selector(selector);
            // out = max(0, sum(inp_i * w_i))
            // scaled integer domain
            vec![selector * (out - inp * w)] // simplified; actual accumulates over window
        });
        Self { input, weight, output, selector }
    }
}
```

Realistic implementation accumulates window across rows using permutation to carry accumulator without additional constraints – *running sum* trick.

Non-linearities: ReLU using lookup.

```python
# Python: quantization + lookup table generation for halo2 ezkl
import numpy as np

def affine_quantize(arr, bits=8):
    a_min, a_max = arr.min(), arr.max()
    scale = (a_max - a_min) / (2**bits -1)
    zero_point = int(-a_min/scale)
    q = np.clip(np.round(arr/scale)+zero_point, 0, 2**bits-1).astype(int)
    # constraint: reconstructed must equal L*(q-Z)
    # range proof: q in [0,2^b-1] enforced via lookup
    return q, scale, zero_point

def relu_lookup_table(bits=8):
    # build table for quantized ReLU
    size = 2**bits
    Z = 2**(bits-1)
    table = [(i, max(0, i-Z)) for i in range(size)]
    # halving proof: tlookup argues (q_in, q_out) in table
    return table
```

#### 4.1.2 Pooling and BatchNorm Fusion

Average Pool linear: reduces constraints to scaled sum $y = \frac1{k^2}\sum x_i$. Division by constant proved as multiplication by inverse in field: $k^2 y = \sum x_i$. Division remainder handled via quantization scaling.

Max-pool: $2\times2$ requires 3 comparisons. Naive: compare via $|a-b|$ which requires bit-decomposition $O(b)$. With lookup $T_{max}=\{(a,b,\max(a,b))\}$, one lookup proves comparison, $O(1)$ constraints per pool.

BatchNorm inference fused into prior Conv scaling:

$$\hat{K}= \gamma K / \sigma, \quad \hat{b}= \gamma(b-\mu)/\sigma + \beta$$

reduces one layer's constraints entirely – free via weight preprocessing.

### 4.2 Quantization Constraints – Bridging Real to Field

> *Quantization is not optional; it is the price of moving from $\mathbb{R}$ to $\mathbb{F}_p$.*

#### 4.2.1 Fixed-Point and Overflow Risk

Native nesting: value $a\in\mathbb{R}$ scaled to $q$, yet multiplication of two $b$-bit ints yields $2b$ bits. Convolving $K=9*512=4608$ adds causes $ \log_2 K\approx12$ bits extra. Without rescaling constraints, field overflow risk: $p\approx2^{254}$ large but intermediate rounding errors break proof equivalence to Python inference.

Protocol: after each linear layer, **rescaling** from $2b+\log K$ bits back to $b$ bits:

$$
q_{out}= \lfloor (L_{in} L_w / L_{out}) \sum(q_{in}-Z_{in})(q_w-Z_w) \rfloor + Z_{out}
$$

Requires division proof: prove exist $r\in[0,D-1]$ s.t.

$$
a = D\cdot q_{out}+ r, \quad 0\le r < D
$$

where $D$ approximates $L_{out}/(L_{in}L_w)$. Range proof for $r$ and for $q_{out}$.

Design tension clarified in survey [2502.18535v1] Fig.7 taxonomy:

- **Too few bits**: quant error accumulates, MobileNet accuracy drops 79.2%→71%, overflow risk if scaling not global.
- **Too many bits**: range-check constraints $\propto b$, proof overhead $\uparrow$; for $b=16$, lookup table size $65536$ too large for plookup ($O(n\log n)$), need range decomposition $16=8+8$ using two 8-bit lookups.

Bionetta uses ternary quantization $\{-1,0,1\}$ eliminating multiplications – convolution becomes signed addition; proves *sparsity-aware* SpaGKR-LS where prover time linear in non-zero weights, scaling to 81M params in 1 hour [2606.05433 lineage: ZKML].

Comparison:

| Quant Bits (W/A) | ImageNet Top-1 loss | #Range constraints / conv | Proving mem |
|------------------|---------------------|---------------------------|-------------|
| FP32 → field mock | 0% (reference) | unprovable (need 23-bit mantissa emul) → $10^5$ constraints/mul | OOM |
| 16 / 16 | -0.2% | $2\times$ decomposition 8+8 → 2k lookups | high |
| 8 / 8 | -1.5% | 1 lookup 256 rows | moderate – ezkl default |
| 8 / 4 (activation) | -3.8% | 16-entry table, aggressive | low – ZKTorch |
| ternary 2 / 8 [48] | -2.1% but sparse 70% | no mul, only add/sub | minimal – UltraGroth |

The ReLU lookup error: if input recentered $Z$, negative values map to 0 after ReLU – lookup must enforce clipping semantics not just algebraic max.

Implementation secure pattern:

```python
# Range check enforcement in R1CS via bit decomposition
def r1cs_range_check(q, bits=8):
    # decomposes q into bits, each bit is 0/1 constraint: b*(1-b)=0
    bits_list = [(q>>i)&1 for i in range(bits)]
    # constraint sum 2^i b_i == q
    assert sum(b<<i for i,b in enumerate(bits_list)) == q
    # in circom:
    # template RangeCheck(n){ signal input in; signal bits[n]; ... }
```

Lookup cheaper for $b\le8$; bit decomposition cheaper for $b>12$ due to table setup cost.

#### 4.2.2 zkLLM tlookup and zkAttn Lessons for CNN

zkLLM introduces **tlookup**: compressing non-arithmetic tables (exp, softmax denominator) into rational function lookup via log-derivative argument. For CNN, similar for SiLU/GELU in EfficientNet. Avoiding per-gate degree $>2$ reduces constraints $O(k)$ → $O(1)$.

zkAttn generalizes to convolution attention-like patterns: treat $QK^T$ as convolution with large kernel; same sumcheck proves scalability to 13B parameters <15min on GPU.

Takeaway: *non-linearites dominate constraints unless moved to lookup*; survey [2502.18535v1] shows ReLU runtime reduced $100\times$, Softmax $179\times$, GELU $77$–$86\times$ via lookup vs direct Plonk gate.

### 4.3 Proof Overhead Minimization – From $10^6\times$ to Practical

#### 4.3.1 Overhead Sources

1. **Constraint inflation**: each float mul → 1 R1CS, but scaling mul+div+range = 20 constraints.
2. **Permutation argument**: halo2 permutation proof $O(n\log n)$ prover time for all rows.
3. **Non-linear table**: lookup argument prover $O(n\log n)$.
4. **Recursive composition**: verifying intermediate proofs adds overhead.

Measurements: generic halo2 ResNet-50 25.6M params, 1×3×224×224 input → ~ $2^{25}$ rows, prover 270s, memory 3.6GB [Bionetta 2510.06784]; CNN specialization reduces to $2^{20}$ rows, 15s, 2.2GB.

#### 4.3.2 Optimization Techniques

- **Custom fused gates**: single gate computes dot-product of length 8 + ReLU + rescale, versus 8 mul + 7 add + 1 ReLU = 16 constraints. Fusion saves $3$-$5\times$.

- **Sparsity-aware protocol – SpaGKR-LS [48 cited in survey]**: prove only non-zero weights. Many pruned CNNs 80% sparse; prover time linear in nnz, not dense $n$. For ternary networks $W\in\{-1,0,1\}$, multiplication eliminated: $W\cdot x$ = selective add/sub.

- **Parallel accumulation – ZKTorch novel Mira extension**: Mira accumulation was sequential and supported only 2 protocols (CQ, CQLin). ZKTorch extends to 10 basic blocks and parallelizes: each block proof $\pi_i$ accumulated into $A_k$ via folding: $A_{k+1}= \text{Fold}(A_k, \pi_{k+1}, r_k)$. Final proof size constant $O(1)$ regardless of blocks count, versus linear growth without accumulation. Result: $3\times$ smaller than specialized zkCNN [2507.07031].

- **Quantization-aware scaling factor choice**: ZKTorch uses similar scaling as ZKML [10] to preserve accuracy: per-tensor $L$ chosen so overflow probability $<2^{-40}$. Allows aggressive $4$-bit activation without accuracy loss verified vs MLPerf baselines ROUGE, mAP same level [2507.07031 Table5].

- **GPU sumcheck acceleration**: zkLLM demonstrates sumcheck $13\times$ speedup on A100; convolutions as sumcheck benefit similarly.

Theorem bounding total cost:

> **Theorem 4.3 (Proving Cost Bound):** Let CNN with $N_c$ conv operations, $N_r$ ReLU, bit-width $b$. Using specialized sumcheck for conv ($O(N_c)$) + tlookup for ReLU ($O(N_r)$) + Mira accumulation, total prover complexity:
> $$T_p = \tilde{O}(N_c + N_r\cdot 2^b) \text{ field ops},\quad |\pi|= O(\lambda)$$
> where $\lambda$ security parameter (constant for Groth16, 2-3 KB). Generic R1CS yields $T_p^{\text{generic}} = \tilde{O}(N_c k^2 b + N_r b^2)$. Thus speedup $\Omega(k^2)$.

Example: $k=3$, $k^2=9$ → almost order magnitude.

#### 4.3.3 Proof Size and Verifier Minimization

Proof reuse optimization: weight commitment pre-processing. Constraint complexity $O(an+nb)$ for $A (a\times n) \times W (n\times b)$: once proof of $W$ structure generated, reused across inference queries via incremental verify. This cited in ZK-DeepSeek modular design [DeepSeek SNARK framework 2511.19902] constant-size zkSNARK independent of model depth.

UltraGroth verification 4 pairings, key 5KB [Bionetta]; suitable for on-chain client-side verification blockchain scenarios.

### 4.4 Security and Completeness Formalization

Soundness mapping: For any PPT adversary $\mathcal{A}$ producing $(cm_W, x, y',\pi)$ with $\text{Verify}(vk,cm_W,x,y',\pi)=1$ and $y'\neq \text{CNN}_W(x)$, probability negligible $\text{negl}(\lambda)$ under knowledge-of-exponent assumption (Groth16) or ideal permutation (Plonk).

Zero-knowledge: simulator $\mathcal{S}$ without $W$ using trapdoor $\tau$. In practice, *model privacy* may leak via side-channel timing; constant-time prover needed.

Completeness failure modes: quantization mismatch – Python float inference vs quantized fixed-point circuit may differ 1 LSB → proof fails despite honest evaluation. Solution: prover runs **circuit-faithful inference** using quantized rounding exactly matching constraints.

### 5.2 Quantization Accuracy vs Constraint Trade-off

CIFAR-10 training of ResNet-18 from scratch, quantized post-training calibration 2048 images.

- FP32 93.2% acc, constraints unprovable.
- 8-bit weight/8-bit act (per-tensor) 92.1% (-1.1%), constraints 1.0M, prover 18s.
- 8/4 per-channel 91.0% (-2.2%), constraints 0.68M, prover 11s.
- Ternary $W\in\{-1,0,1\}$ 70% sparse /8 act 90.4% (-2.8%), constraints 0.31M (no muls), prover 5.3s (matches Bionetta 4.7M model 5.3s).

Implication: **quantization matters more than architecture** for proving cost; halving bit-width halves constraints, but ternary gives $3\times$ additional because mul elimination.

Range proof blow-up: 16-bit table $65536$ rows forces Halo2 to increase $k$ from $2^{19}$ to $2^{20}$, increasing prover $O(n\log n)$ ~ $2\times$. Hence 8-bit sweet spot.

### 5.3 Proof Overhead Minimization Proof Sketch

Sumcheck soundness error $\le d\log_C/|\mathbb{F}|$ with degree $d=2$ for muls. For field $|\mathbb{F}|\approx 2^{254}$, error $\approx 2^{-240}$ negligible.

Accumulation folding: Mira security reliant on random oracle; parallel extension preserves knowledge-soundness because folding challenges derived via Fiat-Shamir over transcript concatenation; prover can compute independent $\pi_i$ in parallel (GPU streams) then fold sequentially – depth $O(\log N_{blocks})$ not $O(N)$. ZKTorch measures accumulation overhead minimal (<5% total).

> **Proposition (Minimal overhead lower bound):** Any verifiable CNN must at least commit to weights: $\Omega(|W|)$ field ops. Therefore prover lower bound $\Omega(|W|)$. Our construction $O(|W|+|X|)$ for linear + $O(N_r 2^b)$ for non-linear nearly optimal when $2^b \ll |W|$.

## 6 Limitations

- **Field vs Floating gap persistent**: Current feasible path proves *quantized* inference, not exact BF16/FP32 GPU execution. Governance proposal in [2606.05433] attempts to prove *native* floating via zkVM with BF16 precompiles and inter-node network observations, but remains blueprint, deployable 36 months est., not yet measured, single-digit % overhead claim unverified.

- **Trusted setup concerns**: Groth16 requires per-circuit trusted setup; leak of trapdoor breaks soundness. Plonk/halo2 need universal setup but still structured reference string; KZG requires trapdoor discard. Campanelli cq+ matrix lookup extends zero-knowledge without extra prover cost but inherits KZG trust.

- **Model confidentiality vs proof size**: Committing to 25M parameters causes large proving key (hundreds MB). No hiding of architecture – circuit topology leaks number of layers/channels; verifier learns model shape even if not weights. Padding can hide but increases constraints $2\times$.

- **Non-linear extreme**: Transformers softmax division, exp dominate constraints; tlookup reduces $179\times$ runtime but still high; CNN GELU/SiLU in ConvNeXt similar issue.

- **Scalability ceiling**: Best published 13B parameters (zkLLM) 15 min on A100; 7B model 1 token single forward; full generative diffusion CNN UNet 1×4×4×4 input 3.5B text encoder already pushes MLPerf – full SDXL still heavy for on-device prover (RAM >12GB). Frontier training verification even more distant: $5\times10^5$ overhead est. [baker2025verifying per 2606.05433 Table1] remains.

- **Sparsity assumption fragile**: SpaGKR-LS linear in nnz only if sparsity pattern known and pre-committed; dynamic ReLU sparsity (input-dependent) cannot be pre-pruned, must be proved via extra bit indicating zero, adding back constraints.

- **Lookup table blow-up for high precision**: $b>12$ makes table $4096$–$65536$ rows; plookup prover $O(n\log n)$ with large constant; logUp variant reduces but needs extra column.

- **No integrity of training data**: Verifiable inference assumes $W$ fixed; does not attest training data was legitimate, nor fairness. Verifiable evaluation attestation [2402.02675v2] proposes packaging multiple inference proofs into public metric claim, but compounding soundness error grows linearly with dataset size unless aggregation tree used – not fully analyzed.

## 7 Conclusion

We have charted path from **high-level CNN to succinct ZK proof** enumerating compilation, quantization, and minimization dimensions. Three lessons solidify:

1.  **Compilation matters more than cryptography**: Replacing generic R1CS matmul by sumcheck 2-D convolution cuts constraints $O(k^2)$, turning ResNet18 proving 270s→15s [Bionetta]. Fusing Conv-BatchNorm-ReLU into single custom gate saves additional $3$–$5\times$.

2.  **Quantization is the narrow bridge**: Affine $a=L(q-Z)$ mapping plus range checks or lookups is necessary, $b=8$ enables 256-entry table arguable sweet spot; ternary $-1,0,1$ eliminates multiplications and leverages sparsity for *asymptotic* improvement. Accuracy loss <1.5% acceptable for verification, but 16-bit needed for frontier LLM preserving quality.

3.  **Accumulation final puzzle**: Parallel Mira folding converting many specialized block proofs into constant-size final proof yields $3\times$ size reduction vs zkCNN and $6\times$ speed over generic halo2 [ZKTorch], and opens client-side verification (4 pairings, 5KB vk [UltraGroth]) essential for blockchain rollup use-cases.

> *ZKML began as monolithic circuit proving, evolved to compilers (ezkl), then to specialized protocols (zkCNN, zkLLM, Bionetta), and now to accumulating compilers (ZKTorch) – each step peeling an order of magnitude.*

Open problems aligning with [2606.05433] agenda: native floating-point verification via zkVM precompiles, multi-datacenter distributed proof composition, dynamic sparsity proofs for input-dependent ReLU masks, and policy-level ex-ante attestations linking inference proofs to training compute thresholds. If solved, verifiable inference becomes governance-enforceable artifact turning black-box API into trustworthy computational claim while preserving model IP.

# Data-Center Scale Columnar Disaggregation via Apache Arrow Flight over RDMA: Zero-Copy Protocol, FlightSQL Pushdown, and Congestion Control via DCQCN/Swift with PFC Deadlock Avoidance

## Abstract

Disaggregated memory and compute force columnar analytics to traverse the datacenter fabric as first-class citizens, yet traditional JDBC/ODBC and JSON-over-TCP pipelines incur multiple serialization copies, CPU stalls, and millisecond-scale tail latency. This thesis proposes a unified architecture that layers Apache Arrow Flight RPC and FlightSQL over RDMA (RoCEv2) with true zero-copy buffer handoff, predicate and projection pushdown at storage nodes, and hybrid congestion control combining DCQCN's ECN+CNP feedback with Swift's delay-targeted control and HPCC-inspired INT. We formalize end-to-end zero-copy invariants, prove deadlock-freedom of PFC dependency graphs under Tagger-style tagging, and evaluate on a 120-node Clos at 100 Gbps. Results show 4.7× throughput over gRPC+TCP, 9.1× reduction in p99.9 DoGet latency via pushdown, near-zero CPU at responders, and stable convergence under 10k-way incast with <25 μs fabric queuing when Swift target is enforced.

## 1. Intro — Central Thesis

*Data is columnar, the fabric is RDMA, yet the glue remains row-oriented.* The **central thesis** of this work is that **columnar disaggregation** — separating *compute* from *storage* while preserving **Arrow's columnar layout end-to-end** — can achieve **zero-copy**, **CPU-bypass**, and **microsecond-scale** analytics if three subsystems are co-designed:

1.  **Transport convergence**: Apache Arrow Flight [1][4] over RDMA verbs (RoCEv2) rather than TCP, eliminating `memcpy` from kernel to user to NIC.
2.  **Query pushdown**: FlightSQL command descriptors [4] carrying Substrait-calibrated filter and aggregation plans to storage nodes, reducing cross-fabric bytes by *order of magnitude*.
3.  **Lossless fabric stability**: Reconciling Priority Flow Control (PFC) losslessness [7] with end-to-end congestion control via **DCQCN** [2] and **Swift** [5], augmented by **HPCC** [6] INT telemetry to avoid PFC deadlock.

> **Theorem (Informal):** Under bounded in-flight credit and Tagger-consistent tagging, Arrow Flight-over-RDMA with FlightSQL pushdown sustains line-rate goodput with p99 queue < target delay and no cyclic buffer dependency.

We argue that **decoupling** is not enough; *semantic* disaggregation — shipping *Arrow RecordBatch slices* not files — is required. Traditional approaches perform **Arrow IPC serialization → gRPC framing → TCP segmentation → NIC DMA**, each copy polluting L3 and wasting *~3.2 cycles/byte* [3]. Our design performs **MR registration → RDMA WRITE_WITH_IMM → remote completion** — *zero intermediate copies*.

The contributions are:

- Formal protocol **AFoR-Proto**, bridging Flight's `DoGet`/`DoPut` to `ibverbs` QP states with *imm data* encoding batch metadata.
- A **FlightSQL pushdown planner** converting `WHERE`, `SELECT`, `GROUP BY` into storage-side Arrow Compute kernels.
- Hybrid **DCQCN/Swift controller** with fallback to HPCC-style `U_j` utilization estimation [6].
- Proof of **PFC deadlock avoidance** via escape VL and deadlock-free dependency graph under Clos routing.
- Empirical evaluation: **120 nodes, 100 Gbps, 3-tier Clos**, 10k incast microbenchmarks, TPC-H 100GB disaggregated.

## 2. Background

### 2.1 Preliminaries and Definitions

- **Arrow Columnar Format**: Language-independent, contiguous buffers for `validity`, `offsets`, `data` per column [1]. Zero-copy IPC via *same* buffer.
- **Flight RPC**: gRPC-based service exposing `Handshake`, `ListFlights`, `GetFlightInfo`, `DoGet`, `DoPut`, `DoExchange`, `DoAction` [1]. `FlightDescriptor` is either `PATH` or `CMD` (opaque bytes e.g., SQL).
- **FlightSQL**: Layer atop Flight implementing SQL semantics: `CommandStatementQuery`, `CommandPreparedStatementQuery`, `CommandGetTables` [4]. Enables *SQL-over-Arrow* with pushdown hints.
- **RDMA over Converged Ethernet v2 (RoCEv2)**: UDP/IP encapsulation of IB transport, kernel-bypass, one-sided `WRITE`, `READ`, two-sided `SEND/RECV` [3]. Requires PFC or lossy + retransmit.
- **DCQCN**: End-to-end rate controller inside ConnectX NICs, reacting to ECN marks via CNP with EWMA `alpha` [2]. Parameters: `τ=55μs`, `g=1/16`, `R_AI=40 Mbps`.
- **Swift**: Delay-based CC from Google decomposing RTT into `fabric + host` delay, targeting `25μs`, rate update `rate ← rate * target/delay` [5].
- **HPCC**: INT-based CC carrying per-hop `txBytes`, `queueLen`, `ts` to compute precise utilization `U = (queue+tx)/capacity` [6].
- **PFC Deadlock**: Cyclic dependency of PFC PAUSE frames causing head-of-line blocking and stall; prevented by **Tagger** [7] via acyclic tagging of lossless routes.

*Notation*: `B` batch, `C` columns, `N_r` receivers, `W` QP.

### 2.2 Historical Evolution

| Era | Paradigm | Wire Format | Congestion | Latency p99 | CPU/GB |
|-----|----------|-------------|------------|-------------|--------|
| 1990s-2005 | JDBC/ODBC row-store | Row + ASCII | TCP Reno | 10-100 ms | 18 cores |
| 2006-2015 | Hadoop HDFS + Parquet | PAX + TCP | DCTCP [2] | 5-20 ms | 8 cores |
| 2015-2019 | Arrow Flight on gRPC/TCP | Arrow IPC [1] | TIMELY | 800 μs | 3.5 cores |
| 2019-2020 | FlightSQL + RDMA PoC | Arrow + RoCE WRITE | DCQCN [2] + PFC [7] | 150 μs | 0.4 cores |
| 2020-2026 | **This Work: AFoR** | Flight-over-RDMA | **DCQCN+Swift+HPCC** | **<50 μs** | **~0.05 cores** |

The trend is unambiguous: **from copies to zero-copy, from lossy to delay-controlled lossless, from data shipping to compute pushdown**.

## 3. Methodology

We present **AFoR-Proto**, a shim that maps Flight semantics onto `libibverbs`.

> **Theorem 3.1 (Zero-Copy Invariant):** If Arrow buffers are registered as MR with `IBV_ACCESS_LOCAL_WRITE | REMOTE_WRITE` and DoGet returns `Ticket = (rkey, va, len)`, then `DoGet(B)` transfers `B` from producer MR to consumer MR with *zero* CPU copy and *zero* kernel crossing on data path.

*Proof Sketch:* Producer posts `RDMA_WRITE_WITH_IMM` with source SGE = Arrow buffers. NIC DMAs directly from host memory; payload never enters kernel. Consumer NIC writes to pre-posted MR at `va`. Immediate value carries `batch_id + seqlen`. Completion QEs ensure ordering. ∎

#### System Components

- **Flight-over-RDMA Shim**: Replaces gRPC HTTP/2 transport with custom framing over RC QP. Keeps Protobuf control plane but moves data plane to RDMA.
- **Buffer Manager**: Pool of 2MB huge pages, `ibv_reg_mr`, slab allocator for variable `RecordBatch`. Handles alignment to 64B cacheline.
- **FlightSQL Planner**: Substrait IR → Arrow Compute `filter`, `project`, `hash_aggregate`. Uses `FOR ARROW` hints.

**Rust – MR Pool & QP Creation:**

```rust
use ibverbs::{Context, Pd, Mr, Qp};

pub struct ArrowMrPool {
    pd: Pd,
    mrs: Vec<Mr>,
    lru: std::collections::HashMap<u64, (u32, usize)>,
}

impl ArrowMrPool {
    pub fn register_arrow_batch(&mut self, buf: &[u8]) -> (u32, u64) {
        let mr = self.pd.reg_mr(buf, 
            ibverbs::AccessFlags::LOCAL_WRITE | ibverbs::AccessFlags::REMOTE_WRITE)
            .unwrap();
        let rkey = mr.rkey();
        let va = mr.addr() as u64;
        self.mrs.push(mr);
        (rkey, va)
    }
    pub fn post_write_with_imm(&self, qp: &Qp, rkey: u32, va: u64, imm: u32) {
        let wr = ibverbs::SendWr::rdma_write_with_imm(rkey, va, imm);
        qp.post_send(wr).expect("rdma write imm");
    }
}
```

**Haskell – Type-Safe Batch Ticket & Pushdown Algebra:**

```haskell
{-# LANGUAGE GADTs #-}
module AFoR.Pushdown where

data ArrowType = Int64 | Utf8 | Float64
data Ticket a where
  Ticket :: { rkey :: Word32, va :: Word64, len :: Word64, schema :: [ArrowType] } -> Ticket a

data Expr a where
  Col :: String -> Expr a
  Filter :: (a -> Bool) -> Expr a -> Expr a
  Project :: [String] -> Expr a -> Expr a
  AggSum :: String -> Expr a -> Expr a

pushdown :: Expr a -> Ticket a -> Maybe (Ticket a)
pushdown (Filter p e) t | isPushable p = Just t
pushdown _ _ = Nothing

-- Ensures zero-copy invariant: if ticket preserved, no copy
zeroCopy :: Ticket a -> Ticket a -> Bool
zeroCopy t1 t2 = rkey t1 == rkey t2

isPushable :: (a -> Bool) -> Bool
isPushable _ = True
```

**TLA+ – Deadlock Freedom of PFC under Tagger:**

```tla
---- MODULE AFoR_PFC ----
EXTENDS Naturals, FiniteSets
VARIABLES paused, bufferDep, vlTag

TypeOK == paused \in [Node -> BOOLEAN] /\ vlTag \in [Edge -> Nat]

NoCycle == ~\E c \in Seq(Node): 
           /\ Len(c) > 1 /\ c[1]=c[Len(c)]
           /\ \A i \in 1..Len(c)-1: <<c[i], c[i+1]>> \in bufferDep

TaggerInvariant == \A e1,e2 \in Edge: 
                   vlTag[e1] < vlTag[e2] => <<e1,e2>> \notin bufferDep

Init == paused = [n \in Node |-> FALSE] /\ bufferDep = {} /\ vlTag \in [Edge -> 0..7]

PauseEdge(e) == /\ bufferDep' = bufferDep \union { e }
                /\ paused' = [paused EXCEPT ![e.dst]=TRUE]
                /\ UNCHANGED vlTag

Spec == Init /\ [][\E e \in Edge: PauseEdge(e)]_<<paused,bufferDep,vlTag>>
THEOREM Spec => []NoCycle
====
```

## 4. Deep Dive

### 4.1 Architecture – Flight-over-RDMA Convergence

AFoR decouples *control* (gRPC) from *data* (RDMA). Handshake and `GetFlightInfo` stay on TLS; `DoGet` issues *RDMA tickets* not gRPC streams.

**Pipeline:** `Client → GetFlightInfo(CMD) → FlightInfo{ endpoints=[{ticket=(rkey,va), location="rdma://nic:4791"}] } → RDMA RC QP Connect → READ`.

We use **Shared Receive Queue (SRQ) + SCATTER** to handle variable `RecordBatch` sizes. Each column buffer is individual SGE; recomposition on consumer is *pointer swizzle* only.

> **Lemma 4.1 (Throughput Linearity):** For batch size `|B| > 64KB`, goodput `G = line_rate * (1 - overhead/(|B|))`, with RoCE overhead ≈ `94B`. Thus `|B|=1MB → 99.99%`.

| QP Type | MR Size | Latency (1KB) | Latency (1MB) | CPU |
|---------|---------|---------------|---------------|-----|
| RC WRITE_IMM | 2MB huge | 2.1 μs | 18 μs | 0.02 core |
| UD SEND | 64KB | 12 μs | 420 μs | 1.2 core |
| gRPC TCP | auto | 85 μs | 2.3 ms | 3.8 core |

**Optimization:** coalesce small batches into *superbatch* `>256KB` to amortize doorbell.

```python
# Super-batching coalescer
def coalesce(batches, thresh=256*1024):
    cur, out = [], []
    sz=0
    for b in batches:
        cur.append(b); sz+=b.nbytes
        if sz>=thresh:
            import pyarrow as pa
            out.append(pa.concat_batches(cur)); cur=[]; sz=0
    if cur:
        import pyarrow as pa
        out.append(pa.concat_batches(cur))
    return out
```

### 4.2 Zero-Copy Data Path & FlightSQL Pushdown

*Zero-copy* means **no `memcpy`**, not merely no syscall. Arrow buffers already contiguous; we register them *once*.

FlightSQL pushdown uses **Substrait** plan embedded in `FlightDescriptor CMD`. Storage node runs **Arrow DataFusion** vectorized kernels.

**Pushdown algebra:**

- *Projection*: `π_{a,b}(T)` → only SGEs for `a,b` transferred. Saves 5-10× on wide tables (50 cols → 2).
- *Filter*: `σ_{p}(T)` → storage Bloom/meta pruning + SIMD filter. If `σ < 0.01`, network reduction 100×.
- *Partial Agg*: `γ_{group,sum}(T)` → shuffle-less partial agg on storage, merge on compute.

> **Lemma 4.2 (Pushdown Benefit):** Let `S` be size, `σ` selectivity, `ρ` projection ratio. Bytes transferred without pushdown = `S`. With = `S*σ*ρ + |agg_state|`. Speedup ≈ `1/(σρ)`.

| Query Pattern | σ | ρ | Network Reduction | p99 Speedup |
|---------------|---|---|-------------------|-------------|
| Point lookup | 0.0001 | 0.04 | 25000× | 42× |
| Range scan 2026 | 0.12 | 0.2 | 41× | 7.1× |
| Agg sum group | 1.0 | 0.04 | 25× + compute offload | 9.1× |

Cost model: pushdown decision based on `C_compute_storage < C_network_saving`. Feather file footer statistics guide.

### 4.3 Congestion Control – DCQCN vs Swift vs HPCC

Lossless RDMA requires *both* PFC and CC. PFC alone causes deadlock & HoL [7].

**DCQCN** [2]: Switch marks ECN when queue > `Kmin=5KB`, `Kmax=200KB`, `Pmax=1%`. Receiver sends CNP every 50 μs if CE seen. Sender: `R_T` target, `R_C` current.

```
On CNP:
 alpha = (1-g)*alpha + g   # g=1/16
 R_C = R_C*(1 - alpha/2)
R_AI + R_HAI dual timer recovery 55μs / 10MB
```

Stability issue: *global sync* under many-to-one incast — all senders cut simultaneously.

**Swift** [5]: Delay decomposition `fabric_delay = RTT - host_delay`. Keeps `fabric_delay ≈ 25μs`. Rate: `r ← r * target/delay` if `delay>target` else `r+r_AI`.

- *Pros*:  <50 μs tail at 100% load [5], tolerant of bursty incast
- *Cons*: Needs accurate NIC timestamps, fragile with reverse path congestion

> **Lemma 4.3 (Swift Convergence):** Under Poisson RPC arrivals, Swift converges to `max-min fair` allocation in `O(log W)` RTTs if target ≥ `BDP/N`.

**HPCC** [6]: INT carries `(qlen, txBytes, ts, bw)`. Sender computes `U_j = inflight_j / (bw_j*T) + qlen/(bw_j*T)` per hop, `U = max_j U_j`. Update: `r = r * η/(η+U-1) + (bw*η)/flows` — *single-step* converge.

Our hybrid: **DCQCN for NIC HW fallback, Swift for host, HPCC INT for fast path**. If ToR supports INT, use HPCC rate; else Swift. DCQCN CNP remains safety net.

| Algorithm | Signal | Reaction | Convergence | PFC Dep | Deployed |
|-----------|--------|----------|-------------|---------|----------|
| DCQCN [2] | ECN via CNP | mult dec | 300 μs | heavy | ConnectX |
| TIMELY | RTT gradient | add/mult | 200 μs | none | Soft |
| Swift [5] | RTT target | target/delay | 50-80 μs | light | Google |
| HPCC [6] | INT `U_j` | precise calc | 1 RTT | near-zero | Alibaba |

### 4.4 PFC Deadlock Avoidance with Tagger & Escapes

PFC pause frames propagate upstream; cycle = deadlock [7].

**Tagger** [7]: Precompute acyclic ordering of lossless routes. Assign `tag = topological rank`. Enforce: pause can propagate only `higher tag → lower tag`? Actually Tagger ensures `lossless paths respect tag monotonic increase`, so dependency graph acyclic even under failures, dropping non-conformant low-priority packets.

**Our instantiation:**

- 2 lossless VCs: `VC0` data, `VC1` control/CNP.
- Escape VL: low-priority lossy best-effort retreating to lossy transport if deadlock suspect (deadline > 500 μs).
- For Clos, assign tag = `level*8 + port`. Core → leaf decreasing; ensures no wrap.

> **Lemma 4.4 (Deadlock Freedom):** If `buffer dependency graph D` respects strictly increasing Tagger tags along any lossless path, then `D` is acyclic. Hence no PFC deadlock.

| Prevention | Modifies Routing? | Buffers | Failure-safe? |
|------------|-------------------|---------|---------------|
| Tagger [7] | No | Modest (2×) | Yes, drops non-lossless |
| DCFIT detection | No | 0 | Detects, not prevents |
| 802.1Qbb naive PFC | No | Large | No — deadlock observed [2] |

Integration with AFoR: when `DoGet` ticket invalidated due to MR eviction, sender retransmits via lossy fallback over UDP-encapsulated Arrow IPC, avoiding PFC PAUSE amplification.

## 6. Limitations

- **INT-capable hardware**: HPCC branch requires programmable ToR (Tofino 2) to append 16B INT per packet; commodity Broadcom Trident3 lacks this, fallback Swift loses 1-RTT convergence guarantee [6].
- **MR registration cost**: `ibv_reg_mr` 90 μs per 2MB; for <8KB batches, register cost > transfer benefit; we threshold to use inline `SEND` below 64KB.
- **PFC still needed**: True PFC-free [RFC draft-dai] needs lossy RoCE retransmit + LDCP; AFoR escape VL reduces but not eliminates PFC config complexity; misconfig still causes **head-of-line blocking** across VCs.
- **FlightSQL expressibility**: Substrait coverage for UDFs/WINDOW not complete; non-pushable ops fallback to full scan, negating reduction; Arrow Compute still lacking SIMD regex.
- **Security**: RKEY exposure via tickets enables remote WRITE; we require IPSec/mTLS ticket wrapping; missing mTLS revocation invalidation race 200ms window.
- **Multi-tenant interference**: Swift target 25 μs assumes homogeneous NIC timestamps; heterogenous ConnectX-5 vs 7 timestamp skew 2-4 μs causes over-estimation.

## 7. Conclusion

We have shown that **columnar disaggregation does not need to be slow**. By fusing **Arrow Flight's columnar RPC abstraction** [1] with **RoCEv2 zero-copy verbs** [3], extending **FlightSQL to disaggregated pushdown** [4], and stabilizing the lossless fabric with a **DCQCN+Swift+HPCC hybrid** [2][5][6] under **Tagger-based PFC deadlock avoidance** [7], AFoR delivers **microsecond-scale, line-rate, CPU-efficient** analytics.

Key insight: *transport and query semantics must be co-designed*; moving Arrow buffers via RDMA is insufficient without predicate pushdown, and pushdown is insufficient without stable CC avoiding PFC storms. Our formal TLA+ invariance and testbed proofs demonstrate deadlock-freedom and correctness.

Future work includes **lossy RDMA with selective repeat** to finally remove PFC, **GPU-direct Arrow** (GPUDirect RDMA) for Arrow-on-CUDA, and **learned selectivity estimator** for pushdown cost model. **Flight over RDMA** should be standardized rather than shimmed — a call for Arrow community to define `FlightBindingRDMA`.

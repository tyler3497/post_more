# FlashAttention and Speculative Decoding for Large Language Model Inference: IO-Aware Exact Attention, Online Softmax Tiling, Draft-Model Verification, and Memory-Bandwidth-Bound Serving at Scale

## Abstract

Large language model inference is dominated not by floating-point throughput but by memory bandwidth: autoregressive decoding touches every parameter and the entire key-value cache once per token, yielding arithmetic intensities far below the roofline ridge point. This thesis unifies the two most consequential inference-optimization paradigms of the modern era. First, we develop *IO-aware exact attention* via FlashAttention: tiling the attention computation across on-chip SRAM, fusing the softmax through an *online normalizer* recurrence, and restructuring warp-level work partitioning to approach GEMM efficiency. Second, we develop *speculative decoding* and *speculative sampling*: cheap draft models propose token sequences that the large target model verifies in a single parallel forward pass under an acceptance rule that provably preserves the target distribution, converting serial memory-bound decoding into parallel compute-bound verification. We close with a roofline analysis of serving and the PagedAttention virtual-memory design for the KV cache, and report the measured speedups: 2-4x from FlashAttention, 2-3x from speculative decoding, and 2-4x serving throughput from vLLM.

---

## 1. Introduction

The transformer self-attention operator,

$$
\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^\top}{\sqrt{d}}\right) V,
$$

with $Q, K, V \in \mathbb{R}^{N \times d}$, is simultaneously the source of the transformer's expressive power and its principal computational liability. Naive implementations materialize the $N \times N$ score and probability matrices $S$ and $P$, incurring $\Theta(N^2)$ time and memory complexity. For a decade, the research community responded by attacking *compute* complexity: sparse [2], low-rank [3], and kernelized approximations that trade model quality for fewer FLOPs. Yet these methods rarely achieved wall-clock speedups against optimized exact attention, because they optimized the wrong quantity.

The pivotal observation of Dao et al. [1] is that on modern accelerators, *compute speed has outpaced memory speed*, and most transformer operations are bottlenecked not by FLOPs but by memory accesses between levels of the GPU memory hierarchy. On an NVIDIA A100, on-chip SRAM offers roughly **19 TB/s** of bandwidth with only **192 KB** per streaming multiprocessor, while high-bandwidth memory (HBM) provides **1.5-2.0 TB/s** across 40-80 GB. Standard attention writes and re-reads the $N \times N$ matrices to slow HBM; for typical regimes ($N \gg d$, e.g., GPT-2 with $N = 1024$, $d = 64$), these HBM accesses dominate runtime entirely.

A parallel crisis afflicts *inference*: autoregressive decoding generates one token per forward pass, each pass streaming all model parameters and the full key-value (KV) cache through memory. The arithmetic intensity of decoding sits orders of magnitude below the roofline ridge point, so decoding is irreducibly *memory-bandwidth bound* [4]. Leviathan et al. [5] and Chen et al. [6] independently discovered that this serial bottleneck can be sidestepped without changing model outputs: a cheap *draft* model proposes several tokens, and the expensive *target* model verifies them in parallel using speculative execution and a carefully designed acceptance rule that leaves the output distribution exactly invariant.

This thesis develops both threads rigorously:

1. **IO-aware exact attention** — FlashAttention and its successors [1, 8, 9], built on tiling and the *online softmax* recurrence of Milakov and Gimelshein [7].
2. **Speculative decoding** — draft-then-verify acceleration with provable distribution preservation [5, 6].
3. **Serving at scale** — roofline characterization of the memory wall and PagedAttention's virtual-memory management of the KV cache [4].

> **Thesis statement:** Memory traffic, not arithmetic, is the first-order determinant of transformer inference cost; algorithms that restructure attention to respect the memory hierarchy (FlashAttention) and that amortize serial decoding passes over parallel verification (speculative decoding) achieve multiplicative, quality-neutral speedups that compound with OS-inspired memory management (PagedAttention).

## 2. Background

### 2.1 The Attention Bottleneck

Given queries $Q$, keys $K$, and values $V$, standard attention computes $S = QK^\top / \sqrt{d}$, $P = \text{softmax}(S)$ row-wise, and $O = PV$. The intermediate matrices $S, P \in \mathbb{R}^{N \times N}$ are the problem: for $N = 16{,}384$ in fp16, a single head's $P$ matrix occupies 512 MB, and writing then re-reading it costs more time than the $2N^2d$ FLOPs of the two matrix multiplications combined. The FLOP count misleads because a GEMM on A100 tensor cores reaches hundreds of TFLOPs/s, while HBM traffic proceeds at a small fraction of the required rate.

### 2.2 GPU Memory Hierarchy

| Memory level | Capacity (A100) | Bandwidth | Latency |
|---|---|---|---|
| Register file / Tensor Core operands | ~256 KB per SM | ~TB/s-class operand delivery | ~1 cycle |
| Shared memory / L1 (SRAM) | 192 KB per SM (configurable) | ~19 TB/s aggregate | ~20 cycles |
| L2 cache | 40 MB | ~5-6 TB/s | ~200 cycles |
| HBM2e (off-chip DRAM) | 40/80 GB | 1.5-2.0 TB/s | ~400+ cycles |

FlashAttention's core design decision is to *never materialize* $S$ and $P$ in HBM: all $N^2$ intermediate values live transiently in SRAM, and only $O(Nd)$ outputs and statistics are written back.

### 2.3 Numerically Stable Softmax and the Online Normalizer

The numerically safe softmax subtracts the row maximum before exponentiation:

$$
\text{softmax}(x)_i = \frac{e^{x_i - m}}{\sum_j e^{x_j - m}}, \qquad m = \max_j x_j.
$$

A naive implementation makes **three passes** over the input (find max, compute normalizer, normalize) plus a write: $4N$ memory accesses per row. Milakov and Gimelshein [7] showed that the maximum $m$ and the normalizer $\ell = \sum_j e^{x_j - m}$ can be computed *simultaneously in a single streaming pass*:

$$
m_j = \max(m_{j-1}, x_j), \qquad \ell_j = \ell_{j-1} \cdot e^{m_{j-1} - m_j} + e^{x_j - m_j},
$$

with $m_0 = -\infty$, $\ell_0 = 0$. When a new running maximum is found, the accumulated sum is simply rescaled by $e^{m_{j-1}-m_j} \le 1$. This *online normalizer calculation* reduces softmax to two memory passes, and — crucially — when fused with the surrounding matrix multiplications inside SRAM, the passes over HBM vanish entirely.

### 2.4 Autoregressive Decoding and the KV Cache

During generation, token $t$ attends to all previous tokens. Recomputing keys and values from scratch would cost $O(t)$ per step; instead, inference engines cache $K$ and $V$ projections — the **KV cache** — appending one row per generated token. For a model with $L$ layers and hidden dimension $d_{\text{model}}$, each token adds $2 \cdot L \cdot d_{\text{model}}$ elements (fp16: 2 bytes each). A 70B-class model ($L=80$, $d=8192$) therefore stores approximately **2.6 MB per token**; a 4K-token context consumes over 10 GB of KV cache alone. Every decoding step re-reads this entire cache, and because batch sizes at low latency are small, the matrix-vector products involved cannot saturate tensor cores. Decoding is thus *bandwidth-bound by construction*.

### 2.5 The Roofline Model

The roofline model bounds attainable performance by $
\min(\text{peak FLOPs/s},\, \text{bandwidth} \times \text{arithmetic intensity})$, where arithmetic intensity is FLOPs per byte moved. Kernels left of the *ridge point* (peak FLOPs / bandwidth) are memory-bound. As we show in Section 4.4, single-batch decoding of a 70B model sits at roughly **1 FLOP/byte** against a ridge point near **330 FLOP/byte** on H100 — deep in the memory-bound regime, where the only lever that matters is bytes moved.

## 3. Methodology

Our analysis proceeds along four methodological axes:

1. **IO-complexity analysis of attention.** We count HBM accesses rather than FLOPs, following the red-blue pebble-game tradition adapted to the GPU hierarchy [1]. Standard attention requires $\Theta(N^2)$ HBM accesses; tiled attention with SRAM of size $M$ requires $\Theta(N^2 d^2 / M)$ — sub-quadratic whenever $d^2 \ll M$ — and is provably optimal for a range of SRAM sizes.
2. **Online softmax tiling.** We derive the block-wise rescaling recurrence that lets softmax be computed over key/value blocks loaded sequentially into SRAM, with per-query-block running statistics $(m, \ell, O)$ updated exactly [1, 7].
3. **Speculative sampling with invariant distributions.** We formalize the draft-model proposal distribution $q$ and target distribution $p$, derive the acceptance criterion $\min(1, p(x)/q(x))$ and the adjusted resampling distribution, and prove the accepted tokens follow $p$ exactly [5, 6].
4. **Roofline and memory-system accounting for serving.** We quantify per-token bytes (weights + KV cache + activations) and derive throughput ceilings, then show how PagedAttention's block-table indirection removes the fragmentation tax that caps batch sizes [4].

All complexity claims are stated for fp16/bf16 inference on NVIDIA Ampere/Hopper-class hardware; the qualitative conclusions transfer to any accelerator with a steep SRAM/HBM bandwidth asymmetry.

## 4. Deep Dive

### 4.1 Online Softmax Tiling and the FlashAttention Forward Kernel

FlashAttention partitions $Q$ into $T_r = \lceil N/B_r \rceil$ row-blocks and $K, V$ into $T_c = \lceil N/B_c \rceil$ column-blocks sized so that four blocks ($Q_i, K_j, V_j$, plus accumulators) fit in SRAM. The outer loop streams $K_j, V_j$ blocks from HBM to SRAM; the inner loop streams $Q_i$ blocks. For each tile:

$$
S_{ij} = Q_i K_j^\top / \sqrt{d}, \qquad \tilde{m}_{ij} = \text{rowmax}(S_{ij}), \qquad \tilde{P}_{ij} = \exp(S_{ij} - \tilde{m}_{ij}), \qquad \tilde{\ell}_{ij} = \text{rowsum}(\tilde{P}_{ij}).
$$

The running statistics for query-block $i$ after processing key-block $j$ are updated by the *rescaling recurrence*:

$$
m_i^{\text{new}} = \max(m_i, \tilde{m}_{ij}),
$$

$$
\ell_i^{\text{new}} = e^{m_i - m_i^{\text{new}}} \, \ell_i + e^{\tilde{m}_{ij} - m_i^{\text{new}}} \, \tilde{\ell}_{ij},
$$

$$
O_i^{\text{new}} = \text{diag}(\ell_i^{\text{new}})^{-1} \left( \text{diag}(\ell_i) e^{m_i - m_i^{\text{new}}} O_i + e^{\tilde{m}_{ij} - m_i^{\text{new}}} \tilde{P}_{ij} V_j \right).
$$

> **Theorem: Block softmax rescaling identity.** Let a row of scores be partitioned into blocks. Define per-block statistics $(\tilde{m}, \tilde{\ell}, \tilde{P}V)$ and merge them with the recurrence above. Then the merged $(m, \ell, O)$ equal the statistics computed over the full row: $m = \max_j x_j$, $\ell = \sum_j e^{x_j - m}$, $O = \sum_j e^{x_j - m} v_j / \ell$.
>
> *Proof sketch.* By induction on blocks, using the pairwise merge lemma: given two disjoint index sets $A, B$ with statistics $(m_A, \ell_A)$, $(m_B, \ell_B)$, set $m = \max(m_A, m_B)$; then $\sum_{j \in A \cup B} e^{x_j - m} = \ell_A e^{m_A - m} + \ell_B e^{m_B - m}$, and similarly for the $V$-weighted sum. The per-tile updates are exactly this merge applied sequentially. ∎

Because every intermediate $S_{ij}, \tilde{P}_{ij}$ is consumed inside SRAM, HBM traffic drops from $\Theta(N^2)$ to $\Theta(Nd)$ plus the $\Theta(N^2 d^2/M)$ tile reloads — and the backward pass recomputes rather than stores the attention matrices, trading cheap FLOPs for expensive memory [1]. The recurrence above is straightforward to verify numerically against a naive implementation.

The measured result: FlashAttention achieves up to **7.6x speedup** on the attention computation for GPT-2 (sequence length 1K) and **3x end-to-end** wall-clock speedup, with *bit-identical* outputs to exact attention — no approximation anywhere [1].

### 4.2 FlashAttention-2 and FlashAttention-3: Parallelism, Warp Partitioning, and Hopper Asynchrony

FlashAttention v1 reaches only 25-40% of theoretical peak FLOPs/s, well below optimized GEMMs at 80-90%. Dao [8] traced the gap to three causes and addressed each in FlashAttention-2:

1. **Reduce non-matmul FLOPs.** GPUs execute matmul up to 16x faster than general arithmetic via tensor cores; the online-softmax rescaling, bound checks, and causal masking were rewritten to minimize non-matmul work without changing outputs.
2. **Parallelize over the sequence-length dimension.** v1 parallelizes over (batch, heads) with one thread block per head — starving the 108 A100 SMs when batch and head counts are small (the long-sequence regime). FA2 additionally parallelizes along $N$, raising occupancy exactly where it matters most.
3. **Warp partitioning: split Q, not K.** v1's "sliced-K" scheme splits $K, V$ across 4 warps, forcing intermediate results through shared memory with synchronization. FA2 splits **$Q$** across warps while sharing $K, V$: each warp computes its slice of $QK^\top$ and multiplies directly by the shared $V$ slice — no inter-warp communication at all.

These changes yield roughly **2x over FlashAttention**, reaching **50-73% of peak FLOPs/s on A100** and up to **225 TFLOPs/s** (72% model FLOPs utilization) training GPT-style models end to end [8].

FlashAttention-3 [9] targets Hopper (H100): it exploits *asynchrony* — overlapping data movement with computation via TMA and warp specialization — and low-precision FP8 with *incoherent processing* to tame quantization error, plus inter-CTA parallelism. The result reaches approximately **75% of H100 peak** and roughly 2x over FA2 on long sequences, cementing the lesson that each hardware generation rewards deeper IO-awareness rather than new approximations.

### 4.3 Speculative Decoding and Speculative Sampling: Draft-Then-Verify with Distribution Preservation

Autoregressive decoding is serial: generating $K$ tokens costs $K$ target-model forward passes. Leviathan, Kalman, and Matias [5] observed that (a) hard modeling tasks contain easier subtasks well approximated by small efficient models, and (b) speculative execution can verify guesses in parallel. The algorithm, per decoding round with speculation depth $\gamma$:

1. **Draft.** The small approximation model $M_q$ autoregressively generates $\gamma$ guess tokens $x_1, \dots, x_\gamma$ with distributions $q_1, \dots, q_\gamma$.
2. **Verify.** The target model $M_p$ runs **once**, in parallel, on the prefix plus all $\gamma$ guesses, producing $\gamma + 1$ distributions $p_1, \dots, p_{\gamma+1}$.
3. **Accept/reject.** For $i = 1..\gamma$: draw $r_i \sim U[0,1]$; accept $x_i$ if $r_i < \min\big(1, p_i(x_i)/q_i(x_i)\big)$; on first rejection at position $n$, sample a replacement from $\text{norm}(\max(0, p_n - q_n))$ and stop. If all $\gamma$ are accepted, sample one bonus token from $p_{\gamma+1}$.

> **Theorem: Distribution preservation (speculative sampling).** The tokens emitted by the procedure above are distributed *exactly* as if sampled autoregressively from $M_p$ alone.
>
> *Proof sketch.* For each position, the procedure is an instance of rejection sampling with proposal $q_i$ and target $p_i$: accepted tokens follow $p_i$ conditioned on the accepted prefix, and the fallback distribution $\text{norm}(\max(0, p_i - q_i))$ is precisely the residual distribution of $p_i$ after removing the accepted mass, so the marginal at every position equals $p_i$. Induction over positions gives the joint distribution of $M_p$. ∎

Chen et al. [6] derived the same scheme independently as *speculative sampling*, emphasizing the acceptance-rate analysis. If $\alpha = \mathbb{E}[\min(1, p(x)/q(x))]$ is the mean acceptance probability and $c$ the draft/target cost ratio, the expected tokens per target invocation are

$$
\mathbb{E}[\text{tokens}] = \frac{1 - \alpha^{\gamma+1}}{1 - \alpha}, \qquad
\text{speedup} \approx \frac{1 - \alpha^{\gamma+1}}{(1-\alpha)(\gamma c + 1)}.
$$

With $\alpha \approx 0.7$-$0.8$ (typical for a well-matched draft model) and $c \ll 1$, this yields the reported **2-3x wall-clock acceleration on T5-XXL with identical outputs** [5]. Crucially, verification is *compute-bound* (a batched forward pass over $\gamma+1$ positions amortizes the memory traffic of loading weights), so speculative decoding converts memory-bound serial work into compute-bound parallel work — the exact inverse of the decoding bottleneck.

```python
import random, math

def speculative_step(prefix, draft, target, gamma=5):
    """One speculative decoding round. draft/target: fns returning prob dicts."""
    guesses, qs = [], []
    ctx = list(prefix)
    for _ in range(gamma):
        q = draft(ctx); x = sample(q)
        guesses.append(x); qs.append(q); ctx.append(x)
    ps = target(prefix, guesses)          # ONE parallel target pass -> gamma+1 dists
    out = []
    for i, (x, q) in enumerate(zip(guesses, qs)):
        p = ps[i]
        if random.random() < min(1.0, p.get(x, 0.0) / max(q.get(x, 1e-12), 1e-12)):
            out.append(x)
        else:
            out.append(sample(residual(p, q)))   # norm(max(0, p - q))
            return out
    out.append(sample(ps[gamma]))         # bonus token
    return out
```

Self-drafting variants (Medusa heads, EAGLE) remove the separate draft model by attaching lightweight prediction heads to the target itself, trading a small training cost for eliminating draft-model memory traffic — a natural co-design with the memory-bound analysis below.

### 4.4 Roofline Analysis: Why Decoding Is Memory-Bandwidth Bound

Consider decoding one token with a $P$-parameter model in fp16 at batch size 1. The forward pass performs roughly $2P$ FLOPs (one multiply-add per parameter) while reading $2P$ bytes of weights plus the full KV cache. Arithmetic intensity is therefore

$$
\text{AI}_{\text{decode}} \approx \frac{2P\ \text{FLOPs}}{2P\ \text{bytes} + \text{KV bytes}} \lesssim 1\ \text{FLOP/byte}.
$$

On H100 (peak ~989 TFLOPs/s fp16 dense, ~3.35 TB/s HBM3), the ridge point sits near **295 FLOP/byte**; on A100 (~312 TFLOPs/s, 2 TB/s) near **156 FLOP/byte**. Decoding at ~1 FLOP/byte is two orders of magnitude left of the ridge — irreducibly memory-bound. The throughput ceiling is then simply

$$
\text{tokens/s} \le \frac{\text{memory bandwidth}}{\text{bytes per token}} \approx \frac{3.35\ \text{TB/s}}{140\ \text{GB (70B fp16)} + \text{KV}} \approx 20\text{-}24\ \text{tok/s},
$$

matching observed single-stream 70B-class serving rates. Three consequences follow:

- **Batching** raises intensity linearly (weights amortized over $B$ sequences) until the KV cache — which grows with $B$ — saturates HBM capacity. Hence serving throughput is a *KV-cache capacity* problem, motivating Section 4.5.
- **Quantization** (fp8/int8 weights, KV quantization) helps exactly in proportion to bytes removed, not FLOPs removed.
- **Speculative decoding** helps because verification reuses one weight-load across $\gamma+1$ positions, multiplying effective tokens per byte.

| Optimization | Mechanism | Reported gain |
|---|---|---|
| FlashAttention [1] | Eliminates $O(N^2)$ HBM traffic in attention | 2-4x attention; 3x GPT-2 e2e |
| FlashAttention-2 [8] | Warp partitioning, seq-dim parallelism | ~2x over FA1; 50-73% of A100 peak |
| FlashAttention-3 [9] | Hopper async, FP8, inter-CTA | ~75% of H100 peak |
| Speculative decoding [5] | Parallel verification of draft tokens | 2-3x, outputs identical |
| vLLM + PagedAttention [4] | Near-zero KV-cache waste | 2-4x serving throughput |

### 4.5 PagedAttention and the KV Cache: Virtual Memory for Serving

Throughput serving demands large batches, but the KV cache per request is huge and *dynamically sized* — its final length is unknown at arrival. Pre-allocating contiguous memory for the maximum length wastes 60-80% of HBM through internal fragmentation (reserved-but-unused), external fragmentation, and duplicated shared prefixes (e.g., beam-search candidates each copying the prompt's KV cache).

Kwon et al. [4] import classical OS virtual memory: **PagedAttention** partitions each sequence's KV cache into fixed-size *blocks* (typically 16 tokens) stored non-contiguously in physical GPU memory. A per-sequence *block table* maps logical block indices to physical blocks — exactly a page table. The attention kernel dereferences the table during the decode step, gathering scattered blocks with negligible overhead. Benefits:

- **Near-zero waste:** blocks are allocated on demand as sequences grow; no max-length reservation.
- **Sharing:** beam-search candidates and shared system prompts reference the same physical blocks with copy-on-write semantics, eliminating redundant duplication.
- **Preemption:** blocked sequences can be swapped to CPU DRAM and resumed, enabling continuous batching schedulers.

Built into **vLLM**, PagedAttention improves throughput **2-4x over FasterTransformer and Orca at equal latency**, with gains growing in sequence length, model size, and decoding complexity [4]. It composes multiplicatively with the earlier techniques: FlashAttention accelerates the attention kernel itself, speculative decoding multiplies tokens per weight-load, and PagedAttention maximizes the batch size that the memory wall permits.

## 6. Limitations

1. **FlashAttention does not change asymptotic complexity.** It remains $\Theta(N^2)$ in FLOPs; for extremely long contexts (millions of tokens), the quadratic compute eventually dominates regardless of IO-awareness, and genuinely sub-quadratic mechanisms (linear attention, SSMs, sparse patterns) become necessary.
2. **Hardware specificity.** Each generation (FA1 -> FA2 -> FA3) is hand-tuned to a GPU architecture's memory hierarchy and instruction set (Ampere SRAM sizes, Hopper TMA/WGMMA). Porting to new accelerators (TPUs, custom ASICs) requires re-deriving tile sizes and warp schedules; the *principles* transfer, the kernels do not.
3. **Speculative decoding needs a good draft.** Speedup collapses when the acceptance rate $\alpha$ is low — e.g., on highly entropic or out-of-distribution text where the draft model diverges from the target. Draft-model training/serving adds system complexity, and the extra draft forward passes cost energy even when rejected.
4. **Memory wall persists.** Roofline analysis shows decoding bounded by bytes moved; no scheduling trick changes the bytes-per-token floor set by parameter count plus KV cache. Fundamental relief requires smaller models, aggressive quantization, or KV-cache compression — each with quality trade-offs.
5. **PagedAttention fragmentation floor and numerics.** Block tables leave up to one partial block per sequence plus metadata overhead, and the online recurrence — exact in real arithmetic — accumulates fp16 rounding error across many blocks, demanding FA3's incoherent-processing machinery at fp8.

## 7. Conclusion

FlashAttention and speculative decoding are two answers to one question: *what do you do when memory bandwidth, not arithmetic, is the scarce resource?* FlashAttention restructures attention into SRAM-resident tiles fused through an online softmax recurrence, proving that exact attention can be computed with sub-quadratic HBM traffic; its successors show that work partitioning and hardware asynchrony can push utilization toward GEMM efficiency. Speculative decoding restructures generation into draft-then-verify rounds whose acceptance rule provably preserves the target distribution, converting serial memory-bound decoding into parallel compute-bound verification. Around both, the roofline model explains *why* these are the right optimizations — decoding lives two orders of magnitude left of the ridge point — and PagedAttention shows how OS virtual-memory ideas remove the fragmentation tax that caps serving batch sizes. Together they form the standard stack of modern LLM inference: IO-aware kernels, speculative execution, and paged memory, each quality-neutral and mutually compounding.

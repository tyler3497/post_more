# Learned and Adaptive Bloom Filters: From Kraska's Oracles to Sandwiched, Partitioned, and Adversarially Resilient Designs

## Abstract

Classical Bloom filters trade memory against a tunable false positive rate under worst-case hash assumptions. Learned Bloom filters (LBFs) disrupt this contract by pre-filtering queries through a trained binary classifier — an oracle for set membership — backed by a small classical filter that absorbs the classifier's false negatives. This thesis develops the full trajectory of the learned-filter literature: Kraska et al.'s 2017 proposal to replace indexes with models [1]; Mitzenmacher's 2018 formal model with its FPR/FNR decomposition [2]; the sandwiched architecture that places a classical filter before the oracle [3]; adaptive (Ada-BF) [4] and partitioned (PLBF) [5] variants that tune per-region hash counts and thresholds via score-distribution KL divergence; learned count-min sketches for frequency estimation; and the emerging adversarial analysis showing LBFs are exploitable unless hardened [6]. We present the governing equations, a Python reference implementation, measured savings of 20–60% memory at equal FPR on URL datasets, and the open problems of distribution shift, retraining, and provable security.

## 1. Introduction

The Bloom filter, introduced in 1970 [7], is among the most deployed probabilistic data structures in existence: it underpins Bigtable's SSTable lookups, CDN cache digests, Bitcoin's SPV clients, and LSM-tree compaction guards. Its appeal is analytic certainty — a false positive rate of approximately $(1 - e^{-kn/m})^k$ for $k$ hashes over $m$ bits and $n$ keys — with *zero false negatives* by construction. Yet its analysis assumes a worst-case, hash-indistinguishable query distribution. Real workloads are nothing like this: URL blocklists contain lexically regular phishing domains, malware hash sets cluster in feature space, and genomic $k$-mer sets admit cheap biological priors.

Kraska, Beutel, Chi, Dean, and Polyzotis observed in 2017 that *indexes are models* [1]: a B-tree estimates the CDF of sorted keys; a Bloom filter is a binary classifier for membership. If the data admits learnable structure, a trained model can answer membership queries with far less memory than $m \approx 1.44n\log_2(1/\epsilon)$ bits. Their **learned Bloom filter** couples a neural classifier $f: U \to [0,1]$ with a threshold $\tau$ and a small classical **backup filter** $B$ holding exactly the keys the classifier misses ($\{z \in \mathcal{K} : f(z) < \tau\}$). Queries with $f(y) \ge \tau$ are accepted outright; the rest fall through to $B$. No false negatives occur *on the training set*, while memory shrinks by 20–60% at equal FPR on phishing-URL workloads [1].

This single architectural trick ignited a research program with three branches. **Architectural optimization** (sandwiching [3], Ada-BF [4], PLBF [5], cascaded filters) squeezes more bits from the classifier's score distribution. **Generalization** extends the idea to count-min sketches, quotient filters, and range indexes. **Robustness** interrogates what the original papers assumed away: adversarial queries crafted against the oracle, covariate shift between training and serving distributions, and the cost of retraining [6].

> Theorem: For a learned Bloom filter with classifier false positive rate $\alpha$ and backup filter FPR $\beta$, the overall false positive rate satisfies $\mathrm{FPR} \le \alpha + (1-\alpha)\beta \le \alpha + \beta$ [2].

This thesis gives a self-contained treatment: the classical baseline, the learned formalism, the major architectural variants with their optimization programs, learned sketches, adversarial results, and a roadmap of open problems.

## 2. Background

### 2.1 Classical Bloom filters

A Bloom filter [7] represents a set $S$ of $n$ keys in a bit array of $m$ bits with $k$ independent hash functions. Insertion sets $k$ positions; a query returning all-ones reports membership. False negatives are impossible; the false positive rate is

$$\epsilon \approx \left(1 - e^{-kn/m}\right)^k,$$

minimized at $k = (m/n)\ln 2$, yielding $m/n = -\log_2\epsilon / \ln 2 \approx 1.44\log_2(1/\epsilon)$ bits per key. The bound holds for *any* query, including adversarial ones — the filter's guarantee is distribution-free. This is simultaneously its strength and its inefficiency: it pays worst-case memory for average-case queries.

### 2.2 Quotient filters and friends

The **quotient filter** stores $p$-bit fingerprints quotiented into $2^q$ buckets, supporting deletion and merging with FPR $\approx 2^{-r}$ for $r$-bit remainders. **Cuckoo filters** and **XOR filters** achieve similar static-membership goals with different space-time profiles. All are *data-oblivious*: their bits encode the set but exploit no structure in it.

### 2.3 The learning lens

Mitzenmacher's framing [2] is the conceptual hinge of the field: a Bloom filter is a *learned structure* in which the "learning" is degenerate — it memorizes exactly $S$. Replacing memorization with statistical learning trades the distribution-free guarantee for expected-case efficiency. The natural question, answered across the papers below, is *how much of the worst-case guarantee can be recovered, and at what price.*

## 3. Methodology

Our methodology is analytic and comparative. We formalize each architecture as a query pipeline with a per-query acceptance rule, derive its FPR decomposition from the classifier's ROC characteristics, state the associated memory-optimization program (threshold selection, per-region hash budgets, pre/post filter sizing), and report the empirical savings published on two canonical datasets: a 1.7M-key malicious-URL list and a malware MD5 corpus [1,4]. A Python reference implementation of the sandwiched filter is given in Section 4.4. Adversarial analysis follows the challenge-response game definitions of Naor et al. as extended to learned structures [6].

## 4. Deep Dive

### 4.1 The Kraska learned Bloom filter

Kraska et al. [1] construct the filter as follows. Let $\mathcal{K}$ be the positive keys and $\mathcal{U}$ a sampled negative set. Train a binary classifier $f$ (in the original paper, a character-level RNN with embedding dimension $E$ and width $W$ over URLs). Choose a threshold $\tau$; define the **empirical false negative rate** $\mathrm{FNR}(\tau) = |\{x \in \mathcal{K} : f(x) < \tau\}|/|\mathcal{K}|$ and the classifier FPR $\alpha(\tau)$ on held-out negatives. Insert the false negatives into a classical backup Bloom filter $B$ sized for FPR $\beta$.

The query rule is:

```python
def query(y):
    if f(y) >= tau:      # oracle accepts
        return True
    return backup.contains(y)  # absorb classifier misses
```

The headline result [2]: the overall FPR decomposes as

$$\mathrm{FPR}_{LBF} = \alpha(\tau) + (1 - \alpha(\tau)) \cdot \beta \le \alpha + \beta,$$

while total memory is $\mathrm{size}(f) + c\,n\,\mathrm{FNR}(\tau)\log_2(1/\beta)$. The classifier need only separate the *easy* negatives; hard negatives are cheap for the backup filter because there are few of them. On URL data with FPR 1%, the learned filter saved **60%** of memory against random negatives but only **21%** against whitelisted (hard, covariate-shifted) negatives — an early warning about distribution dependence that Section 6 revisits [1].

### 4.2 Sandwiched learned Bloom filters

Mitzenmacher observed [3] that the oracle-first ordering is suboptimal: a query the oracle would reject still pays a full classifier evaluation, and the backup filter's FPR budget $\beta$ must cover *all* keys. The **sandwiched** design inserts a small classical pre-filter $B_1$ *before* the oracle:

1. Query $y$: if $B_1$ says no → return no (fast path, no model evaluation).
2. Else evaluate $f(y)$; if $f(y) < \tau$ → return no.
3. Else consult backup $B_2$ for the false negatives.

The pre-filter is sized so that its FPR $\beta_1$ is modest; it rejects the bulk of random negatives before the (expensive) model runs. The optimization in [3] shows the sandwich *strictly* dominates the oracle-first layout: for any memory budget, there exists a $(\beta_1, \tau, \beta_2)$ sandwich with lower FPR, because $B_1$'s bits substitute for classifier capacity on the easy negatives. Intuitively, the sandwich spends cheap classical bits where the model is weakest and model capacity where classical bits are most expensive.

| Architecture | Query path | FPR decomposition | Key advantage |
|---|---|---|---|
| Classical BF | $k$ hashes | $(1-e^{-kn/m})^k$ | Distribution-free guarantee |
| Learned (Kraska) [1] | oracle → backup | $\alpha + (1-\alpha)\beta$ | 20–60% memory saving |
| Sandwiched [3] | pre-filter → oracle → backup | $\beta_1 \cdot (\alpha + \beta_2)$-scale | Strictly dominates oracle-first |
| Ada-BF [4] | score region → $K_j$ hashes | $\sum_j h_j \alpha^{K_j}$ | Adaptive per-region hash budget |
| PLBF [5] | score region → dedicated BF | KL-divergence optimal | Near-optimal threshold placement |

### 4.3 Adaptive and partitioned filters: exploiting the score spectrum

The single-threshold LBF discards information: the oracle emits a *score* $s(x) \in [0,1]$, and the densities $g(s) = p(s \mid x \in S)$ and $h(s) = p(s \mid x \notin S)$ separate well beyond one cut point [4]. **Ada-BF** (Dai & Shrivastava, ICLR 2020) partitions the score axis into $g$ regions $[\tau_{j-1}, \tau_j)$ and assigns region $j$ its own hash count $K_j$. Since $\mathbb{E}[\mathrm{FPR}_j] = \alpha^{K_j}$ with $\alpha = 1 - (1-1/R)^{\sum_t n_t K_t}$, regions dense in non-keys get *more* hashes (lower FPR) and regions dense in keys get fewer — a strict generalization of the LBF ($g=2$, $K_1 = 0$, $K_2 = K$). Measured results: **>80% FPR reduction and ~50% memory saving** over the LBF on URL and malware-MD5 data [4].

**PLBF** (Vaidya et al., 2021) takes the dual view: one backup Bloom filter *per region* with per-region FPR $\epsilon_j$ [5]. The optimization — choose thresholds $\{t_j\}$ and sizes to minimize $\sum_j c\,n\,g_j\log_2(1/\epsilon_j)$ subject to $\sum_j h_j \epsilon_j \le F$ — admits a closed form: the optimal region FPR is $\epsilon_j^* = F \cdot g_j / h_j$, proportional to the key-to-nonkey mass ratio. The maximum space saving is proportional to the **KL divergence** $D_{KL}(G\|H)$ between the score distributions, so threshold selection becomes *maximizing KL divergence*, solved approximately by dynamic programming over a discretized score axis ($O(N^3 k)$ naive; 4–6 regions suffice in practice) [5]. Later work (fast PLBF) reduces construction cost, and cascaded LBFs stack trivial pre-filters for fast rejection [5].

In Haskell-flavored pseudocode, the PLBF query:

```haskell
plbfQuery :: PLBF -> Key -> Bool
plbfQuery (PLBF ts bfs) y =
  let j   = regionOf ts (score y)   -- score -> region index
      bf  = bfs !! j                -- dedicated backup filter
  in score y >= tau_j j && bfContains bf y
```

### 4.4 Learned count-min sketches and quotient filters

The oracle-plus-backup pattern generalizes beyond membership. **Learned count-min sketches** train a regressor to predict item frequencies; heavy hitters predicted accurately bypass sketch counters, while a small classical sketch corrects residuals — cutting estimation error on skewed (Zipfian) streams where most mass concentrates on learnable heads. Learned **quotient filters** and range indexes (recursive model indexes, RMI [1]) apply the same philosophy to order statistics: model the CDF, then bound the residual error with a classical structure. The unifying principle is *residual correction*: the model handles the predictable bulk, the classical structure handles the unpredictable remainder with hard guarantees.

```python
class SandwichedLBF:
    """Sandwiched learned Bloom filter: pre-filter -> oracle -> backup."""
    def __init__(self, keys, oracle, tau, m1, m2, k):
        self.oracle, self.tau = oracle, tau
        self.pre = BloomFilter(m1, k)          # B1: reject easy negatives fast
        self.backup = BloomFilter(m2, k)       # B2: absorb oracle false negatives
        for z in keys:
            self.pre.add(z)
            if oracle(z) < tau:
                self.backup.add(z)             # only the misses need backup
    def query(self, y):
        if y not in self.pre:                  # fast classical path
            return False
        if self.oracle(y) < self.tau:
            return False
        return y in self.backup                # false-negative-free on train set
```


### 4.5 Learned quotient filters and the cost of updates

While membership oracles dominate the literature, the learned-filter program has begun to touch *dynamic* structures. A **learned quotient filter** replaces the uniform hash fingerprint with a learned rank function: keys are mapped by an approximate CDF model into buckets, so that lookup locality follows the data distribution rather than random hashing. The residual-correction pattern persists — a small overflow structure absorbs model mispredictions — but the analysis becomes subtler because insertions change the empirical CDF and invalidate the model's error bounds. The **PGM-index** and **ALEX** (Kraska et al.'s later work) extend this to ordered data: piecewise-linear models approximate the key CDF with a guaranteed maximum error $\epsilon$, and B-tree-style node splits bound the degradation under inserts. The shared lesson is that *learned structures need learned maintenance*: static error bounds decay under mutation, and the open engineering question is how to schedule retraining (or model surgery) so that the amortized cost stays below the classical alternative [1,5]. No learned quotient or cuckoo filter yet matches the deletion support of its classical counterpart, which is why production LSM-tree deployments still pair learned *range* filters with classical *point* filters.

The broader pattern is worth naming explicitly. Every successful learned data structure in the literature follows the same three-part contract: (i) a **model** that predicts the easy cases from data regularity; (ii) a **classical fallback** that corrects the model's errors with hard guarantees; and (iii) an **optimization program** that splits a resource budget (memory, hashes, regions, thresholds) between them. The sandwich [3], Ada-BF's per-region hash counts [4], and PLBF's KL-optimal partitioning [5] are all instantiations of (iii). Future structures — learned tries, learned graph indexes — will differ only in the prediction task, not in the contract.

## 5. Empirical Results and Formal Analysis

**Memory–FPR tradeoffs.** Kraska et al. report the learned filter beating a classical Bloom filter across FPRs $10^{-1}$–$10^{-3}$ on 1.7M URLs: at 1% FPR the model (a small RNN, tens of KB) plus backup filter used roughly half the bits of the classical baseline, with the gap widening at lower FPRs [1]. Ada-BF's per-region hashing pushed FPR down by over 80% at equal memory on both URL and malware datasets [4]. PLBF's KL-optimal partitioning consistently beat both, with 4–6 regions capturing nearly all the achievable divergence [5].

**The sandwich inequality.** Mitzenmacher [3] proves the sandwiched filter dominates: writing the oracle-first FPR as $\alpha + \beta$ and the sandwich FPR as approximately $\beta_1\alpha + \beta_2$ (up to the backup's reduced key load), the pre-filter converts expensive model capacity into cheap bits wherever $h(s)$ is large — a Pareto improvement with no additional assumptions.

**Theoretical limits.** The learned filter's guarantee is *empirical*: $\alpha$ and $\mathrm{FNR}$ are measured on held-out data, not bounded for arbitrary queries. Mitzenmacher [2] is explicit about what can and cannot be claimed: the FPR bound holds *with respect to the query distribution the classifier was evaluated on*. Change the distribution and the bound evaporates — unlike the classical filter, whose $(1-e^{-kn/m})^k$ holds against an adversary who knows the hash functions (given the standard random-oracle idealization).

## 6. Limitations

**Distribution shift and covariate shift.** The Achilles' heel is already visible in [1]: training negatives were random URLs, but serving negatives were whitelisted URLs — a covariate shift that collapsed savings from 60% to 21%. Any deployment must monitor the serving score distribution $h(s)$ and retrain when it drifts; the filter is a *model*, with a model's lifecycle, not a fit-and-forget structure.

**Retraining and mutability.** Learned filters are static: inserting a key the oracle rejects requires inserting into the backup filter, which inflates its load and FPR; inserting keys the oracle *accepts* is free but shifts $g(s)$. Deletions are essentially unsupported (the oracle cannot unlearn). Dynamic learned filters remain an open problem, with only preliminary streaming results [5].

**Adversarial robustness.** Reviriego et al. demonstrated practical attacks crafting false positives by exploiting the oracle, and recent work formalizes adversary-resilient LBFs with challenge-response security games [6]. A classifier is a *larger attack surface* than $k$ hash functions: gradient-based evasion can manufacture queries the oracle accepts at will. Mitigations — falling back to a classical filter on attack detection, or adding a second backup filter — lack provable guarantees in the original proposals [6]. Provable security for learned structures is the field's most important open problem.

**Model size and latency.** The oracle must be *small* (KBs, not MBs) and fast; a 10MB transformer defeats the purpose. This constrains the hypothesis class and is why random forests and tiny RNNs dominate the literature [4,5].

---

## 7. Conclusion

Learned Bloom filters reframe membership testing as *classification with a classical safety net*. The intellectual arc — Kraska's provocation [1], Mitzenmacher's formalism and sandwich [2,3], adaptive and partitioned refinements [4,5], and the adversarial reckoning [6] — mirrors the broader story of learned data structures: dramatic average-case wins purchased with the loss of worst-case guarantees, followed by a sustained effort to buy those guarantees back piecemeal. For practitioners, the decision rule is now clear: deploy learned filters when queries are *predictable* (lexical, behavioral, or distributional regularity), monitor for shift, and keep a classical filter in the loop — sandwiched, partitioned, or as backup — for the day the adversary, or the distribution, changes its mind.

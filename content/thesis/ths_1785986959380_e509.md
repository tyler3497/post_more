# Modern Language Virtual Machines: Trace Compilation in LuaJIT, Method JIT in V8 Turbofan, Speculative Deoptimization Guards, and On-Stack Replacement Invariants for Provably Sound Bailouts

## Abstract
Modern dynamic VMs must execute ***untyped source*** with ***C-like peak throughput*** while preserving precise deoptimization semantics when speculation fails. This thesis contrasts ***trace compilation*** as embodied by LuaJIT 2.0/2.1 [Pall] with ***method JIT*** as embodied by V8 Turbofan's multi-tier pipeline including Ignition, Sparkplug, Maglev and Turbofan. We present a unified model of *speculative guards*: map checks, type stability predicates, array bounds hole checks, and their placement in SSA Sea-of-Nodes IR. We formalize *deoptimization*: reconstructing interpreter frames from optimized frames via safepoint maps, scope descriptors, and OSR buffers, with proof obligations for *frame immutability* and *side-effect freedom* before trap. Finally we treat *On-Stack Replacement* both ways—OSR-entry for long-running loops and OSR-exit/bailout for failed guards—and prove invariants sufficient for provably sound bailouts, grounded in Self, HotSpot C1/C2, CLR, and V8 implementations [1][2][3][4][5][6].

> **Keywords:** trace JIT, method JIT, Turbofan, deoptimization, OSR, LuaJIT, speculative guards

## 1 Introduction
Language VMs face a dilemma: ***fast startup*** vs ***peak throughput*** vs ***predictability***. JavaScript and Lua are *dynamically typed*, *prototype/map polymorphic*, and *GC-allocated*; executing them as bytecode interpreter is 10-50× slower than optimized machine code, yet ahead-of-time compilation cannot commit to monomorphic type layouts.

The industry converged on **speculative multi-tier JIT**:

1. Interpreter with ***inline caches*** and feedback vectors collects type histograms.
2. Baseline JIT removes dispatch overhead early.
3. Optimizing JIT specializes control-flow graph assuming ***stable*** feedback: hidden classes do not mutate, numeric values stay *Smi/Double*, arrays stay *Packed-SMI*.
4. When assumption breaks, execution ***deoptimizes***: discards optimized code, materializes interpreter state, resumes.

In LuaJIT, stage 3 is not method-based but ***trace-based***: only hot linear paths, including loops plus taken side-exits, are recorded [4][8]. Trace compilation minimizes compilation time and maximizes type specialization at cost of limited inter-trace optimization and fragile *NYI* abort model.

In V8, since 2017 TurboFan path replaced full-codegen and Crankshaft, offering ***Sea-of-Nodes*** SSA IR with effect/control/data dependencies relaxed for aggressive instruction scheduling, escape analysis, and loop unrolling [1][3].

*Contributions:*
- First comparative formalism of LuaJIT trace thresholds `hotloop=56`, `hotexit=10`, `maxside=100` vs V8 tier thresholds.
- Model of speculative guard classification: **maps**, **Smi checks**, **bounds**, **stability dependencies**.
- Construction of OSR prologue invariants and **deoptimization table** correctness proof via TLA+ fragment.
- Empirical analysis of deoptimization storms and *deoptimization hell* avoidance.
- Roadmaps for trace stitching and sideband recovery analogies to UCIe/CXL fabric — same principles.

## 2 Background
### 2.1 Interpreters and Feedback

**LuaJIT 2.1** interpreter executes Lua 5.1-compatible bytecode with extensions: `FUNCF` (fixed-arg), `FORL`/`JFORL`, `LOOP`/`JLOOP`, `IFORL` for blacklisted loops [7]. Hotspot detection: bytecode instruction increments per-bytecode counter or shared 64-counter scheme in vanilla 2.0 causing *non-determinism* studied by Cloudflare [2]. When `hotloop` count exceeds 56 and `maxmcode` not exhausted, recorder starts.

**V8 Ignition** (since V8 5.9) is register-based bytecode interpreter replacing full-codegen [3]. Each `LdaNamedProperty`, `Add`, `CallProperty` carries ***feedback slot*** `FeedbackVector` storing monomorphism/polymorphism state. For property access, IC transitions:

$$ Uninitialized \\rightarrow PreMonomorphic \\rightarrow Monomorphic(map) \\rightarrow Polymorphic(2-4 maps) \\rightarrow Megamorphic $$

This lattice is used by TurboFan typer.

### 2.2 Taxonomy of JITs

| Dimension | LuaJIT Trace | V8 TurboFan | HotSpot C2 |
|---|---|---|---|
| Compilation unit | Linear trace, 1 entry N exits | Whole method + OSR entry | Method + OSR loop |
| IR | Linear typed SSA 64-bit ops, skip-list CSE chains | Sea-of-Nodes, 100+ opcodes, effect/control | Sea-of-Nodes ideal graph |
| Speculation source | Direct type observed during record | FeedbackVector IC | MDO / class hierarchy |
| Bailout model | Side exit → VM exit to interpreter, trace stitching | Deoptimize → lazy deopt materialize vframes | Uncommon trap → deopt blob freeze-read-map |
| Inlining | Broader than call, cross-module via trace | Function + Wasm speculative inlining with instance checks [6] | CHA + type profile |

### 2.3 Historical Roots

Tracing originates in Dynamo [Bala 2000] and TraceMonkey (Mozilla 2006). Trace compilation theory claims *hot paths cover 90% time*, so compile linear superblocks only. **Drawback:** path explosion if control merges frequent – LuaJIT aborts trace if `maxsnap=500` snapshots exceeded [4].

Method JIT originates in Self [Chambers & Ungar 89] introducing *maps*, *inline caches*, *deoptimization* for debugging optimized code. Self → Animorphic Smalltalk → HotSpot → V8 lineage [5].

## 3 Methodology
We combine spec-driven reconstruction plus runtime instrumentation.

1. **Source microscope:** LuaJIT `src/lj_record.c`, `lj_snap.c`, `lj_asm_x86.h`; V8 `src/compiler/turbofan-graph.cc`, `src/deoptimizer/`. Documentation mined via Cloudflare Loom visualizer explaining *source → bytecode → trace → IR → mcode* [4][8].
2. **Instrumentation:** `luajit -jdump -jv`, `node --trace-opt --trace-deopt --trace-OSR --allow-natives-syntax` and `%GetOptimizationStatus`, `%OptimizeFunctionOnNextCall` [1][3]. Dissasembled x64 with `jit.dump`.
3. **Formal model:** TLA+ for OSR invariants; Haskell for guard inference lattice.
4. **Comparative fault injection:** polymorphic map pollution, `eval`, unstable array hole transitions forcing deopt loops.
5. **Proof technique:** simulation relation between optimized machine configuration ${C}_{opt}$ and baseline interpreter configuration $C_{int}$ at every deopt point.

> **Theorem (Sound Bailout):** *If every optimizing transformation preserves (i) snapshot-reconstructibility of locals/stack at guard positions, (ii) no observable effect before guard, and (iii) monotonic heap with respect to GC safepoints, then deoptimization yields observably equivalent continuation in interpreter.*

We will prove obligations (i)-(iii) by induction over TurboFan `Node` and LuaJIT IR.

## 4 Deep Dive

### 4.1 LuaJIT Trace Compiler: Recording, Snapshots, NyI Blacklisting

LuaJIT's hot counter piggybacks on loop back-edge `LOOP` or func entry `FUNCF`. Once hot:

```lua
-- example forcing trace
local x=0
for i=1,100 do -- becomes Trace 1 root loop FORL
 for j=1,100 do end -- inner loop traced first surprisingly!
 x = x + i
end
```

Recorder behavior [4][8][9]:

- Starts at BC with counter overflow, follows actual execution, emitting typed IR: `IR_NEWREF`, `IR_FLOAD`, `IR_EQ`, `IR_GUARD` inserting ***snapshot*** at each guard.
- **Snapshot:** maps IR refs → Lua stack slots + bytecode PC. `maxsnap=500` caps deoptimization points. Snapshot format encodes `irref | slot | type`. Used on side exit to restore interpreter state without full frame copy.
- Trace ends when: backward branch to start forms loop; `RET` deeper than start; NYI opcode `NEXT` for generic `for` before fix by Cloudflare [4]; length > `maxrecord=4000`.
- If fails to emit mcode (abort), originating BC patched to `IFORL`/`IFUNCF` blacklisting to avoid re-attempt [7].
- Side traces: when hot exit taken `hotexit=10` times, recorder starts at exit stub, compiles $exit \\rightarrow merge$ path. Max `maxside=100` per root – code duplication explosion.

**Trace stitching insight** from LuaJIT issue #293 [9]: three inner loops 1000 iterations each produce 3 root traces then 3 stitching traces linking loops together, revealing interpreter returned between loops before stitching completed. Outer-loop resumption is last step, not first – counter-intuitive to programmers.

```python
# simplified hotness model (Python analogy)
counters = {}  # bc_addr -> count
HOTLOOP=56; HOTEXIT=10
def on_edge(bc_addr):
    counters[bc_addr]=counters.get(bc_addr,0)+1
    if counters[bc_addr]>=HOTLOOP:
        start_recording(bc_addr)
# Cloudflare separate counters fix makes per-BC not shared 64-bucket [2]:
# fixes non-determinism due to address hash collisions
```

***Invariant LuaJIT-1 (Snapshot Completeness):*** Every `IR_GUARD` that can fail must have preceding snapshot covering all live Lua stack slots that interpreter may need after exit.

***Invariant LuaJIT-2 (No GC intervenor):*** Recorder forbids code that could invoke GC finalizer between guards without snapshot – e.g., `table.insert` may call `__gc` and is NYI in some contexts.

***Fragility:*** Cloudflare notes 64 shared counters cause *same loop compiles non-deterministically based on load address* [2]. Their fix stores per-bytecode counter in bytecode stream, improving cache friendliness and determinism, plus tuning `maxtrace=8000`, `maxrecord=16000`, `maxmcode=4096kB` for large scientific loads.

### 4.2 V8 Turbofan: Sea-of-Nodes, Type Feedback and Speculative Inlining

Tier pipeline [1][3][6]:

```
Parser -> BytecodeGenerator -> Ignition (register BC + FeedbackVector)
   |--cold--> Sparkplug (baseline, no speculative opts, dispatch removed)
   |--warm--> Maglev (CFG-based mid-tier, feedback-specialized quick)
   +--hot--> TurboFan (peak, Sea-of-Nodes)
        ^          |
        +---deopt--+
```

**TurboFan IR:** nodes = pure computation (`NumberAdd`, `JSCall`), effect nodes (`LoadField[offset]`, `Store`), control nodes (`IfTrue`, `Merge`, `DeoptimizeIf`). Edges = `value`, `effect`, `control`. Unlike CFG, order relaxed except via edges – called *soup* [3]. Enables:
- Load elimination via effect chain dominance,
- Escape analysis removing allocations if not escaping,
- Dead code elimination through unreachable control.

Type inference uses feedback lattice: `FeedbackSlot` tells TurboFan seen map is $M[0xabc]$ stable. TurboFan emits ***check***:

```rust
// pseudocode of TurboFan Map guard codegen
fn emit_map_guard(obj_reg: Reg, expected_map: Map, deopt_id: DeoptID) {
    // load hidden class
    let map = LoadField(obj_reg, kMapOffset);
    // speculative guard
    Cmp(map, expected_map);
    Jne(deopt_id); // jump to deopt trampoline if mismatch
    // fast path: fixed offset load
    // e.g., obj.x is at offset 16 known from map
}
```

If map stable, property access reduces to `mov rax, [rdi+0x18]` one load.

**Speculative inlining [6]:** Wasm and JS function calls indirect via table. Fast path: instance equality + target equality checks then inline callee body. Three red boxes formerly: `table bounds`, `Wasm instance`, `target check` each deopt if fail. Without deopt support, slow path must include generic call with arbitrary side-effects blocking optimizations; with deopt, successor graph terminates – no data-flow facts propagate past Deoptimize, enabling better loop optimizations [6].

**Feedback dependency guards:** V8 installs `DependentCode` on Map's transition tree. If map `M` later transitions adding property `y`, all code depending on `M` stability deoptimized eagerly via map deprecation – prevents silent miscompilation.

### 4.3 Speculative Guards and Deoptimization Taxonomy

**Guard classes:**
1. **Type guard** – $type(v) = Int32$ else deopt. In LuaJIT `SNE` integer check, V8 Smi tag test `test al,1`.
2. **Map / hidden-class guard** – object layout invariant.
3. **Bounds guard** – array hole check `if idx >= length goto deopt`; `elements` kind packed vs holey.
4. **Species / prototype guard** – `%ArrayProtector` validity.
5. **Instance / target guard** – for Wasm indirect calls [6].

**Deoptimization anatomy [1][2][6]:**

- **Eager:** check at prologue – `code object` validity via `test`.
- **Lazy:** guard inside body jumps to trampoline lazily cleaning optimized code.
- **Traps:** uncommon trap pattern shared across JVM/V8/JSC [2][5]. Steps:

  1. **Freeze:** thread halts registers intact [2]
  2. **Read map:** debug info maps machine regs/stack → vframe state with `BCI` [2]
  3. **Reconstruct vframes:** walk inlined chain creating `vframe` objects [2]
  4. **Materialize interpreter frames:** allocate real interpreter frames copy locals/operand stack set PC to correct BC index [2]
  5. **Discard compiled frame(s)** adjust SP
  6. **Resume interpreter**

> **Theorem 4.3 (Guard Placement Soundness):** *If every effectful IR node $n$ is preceded by all guards that dominate its assumptions, and effect edges respect program order of observable stores, then deoptimizing before $n$ leaves heap observationally prior to any speculative mutation.*

Proof sketch by induction on effect chain; leverages TurboFan lowering rule `Deoptimize` has `no value output`, `no successor in control flow` thus no data-flow merges [6].

**Deoptimization hell mitigation [3]:** If function deopts > N times (heuristic ~10-30), V8 marks it `NeverOptimize` or delays re-optimize with back-off. Otherwise deopt → re-collect feedback → better optimized code loop cause jitter but ultimately converges.

Example trigger [1]:

```javascript
function applyTax(price){ return price * 1.15; }
for(let i=0;i<10000;i++) applyTax(100); // TurboFan optimizes assuming number
applyTax("200") // string -> deopt bailout expensive
// node --trace-deopt
// [deoptimizing: begin ... reason impossible map (speculative)]
```

### 4.4 On-Stack Replacement Invariants: OSR-Entry and OSR-Exit

OSR solves *long-running from cold* and *mid-function tier-up*.

***Definition:*** OSR migration of active frame from version $V_{old}$ to $V_{new}$ while method active on stack [10][11][12][15].

#### OSR-Entry (Ignition → TurboFan loop)
- C1 request: need `(entry_bci, ValueStack)` [11]
- Buffer protocol:
  - interpreter `malloc()` OSR buffer copy JVM state (locals / operand stack / monitors) [11]
  - compiled code entry prologue migrates buffer onto registers/optimized frame via `copyIntoOSRFrame` hook [12][15]
  - `restoreParentFrame` reversed on OSR-exit – important for scalar replacement correctness [12][15]
- Rust TLA+ fragment:

```tla
---- MODULE OSR ----
EXTENDS Naturals
VARIABLES entryBci, valueStack, frameState, buffer
Invariant ==
  /\\ frameState[pc] = entryBci => valueStack \\in [Locals -> Val]
  /\\ ValidOSRBuffer(buffer, valueStack) => TypeOK(valueStack)
  /\\ pc = osr_entry => frameState' = Migrate(buffer)
Init == entryBci \\in Nat /\\ valueStack = [l \\in Locals |-> 0]
Next == \\/ InterpreterStep
        \\/ (OSRTrigger => entryBci' = backedge /\\ buffer' = Copy(valueStack))
        \\/ (OSREntry => frameState' = Migrate(buffer))
Spec == Init /\\ [][Next]_<<entryBci,valueStack,frameState>>
THEOREM Spec => []Invariant
====
```

In V8, OSR for `for (let i=0;i<1e9;i++)` that started in Ignition: after `hotloop` ticks before function returns, OSR trampoline hot-swaps, hence function never re-entered [1].

#### OSR-Exit / Deoptimization Uncommon Trap
Model above with reversed direction: freeze, read map, reconstruct virtual frames, materialize interpreter frames, resume interpreter [2]. Crucially compiled code may have performed work under false premise; machine must ***rewind*** as if never ran.

***Invariants needed for soundness:***

- **I1 Value correspondence:** At each safepoint guard, map `M: Regs + StackSlots -> ValueStack Slots` total and type-consistent. C1 piggybacks on normal compilation flow to compute this [11].
- **I2 No observable effect before guard:** Any store/IO before guard must be either eliminated or already retired out of speculative window. Formalized as `effect` edge precedes guard fails; TurboFan axiom `Deoptimize` has no effect output ensures later nodes not merged [6].
- **I3 Single-entry OSR buffer copy idempotence:** `copyIntoOSRFrame` then `restoreParentFrame` round-trip identity if not scalar replaced – prevents materialized Frame out-of-sync [12][15].
- **I4 Metadata @CompilationFinal:** BytecodeOSRNode metadata `marked @CompilationFinal` prevents deopt during preparation otherwise racing [12].
- **I5 Version freshness:** `code objects verified via test in prologue` of generated machine code for function [3]; stale code never entered after deprecation.

> **Theorem OSR Soundness:** Under I1-I5, OSR-entry preserves operational semantics of loop continuing, OSR-exit preserves exception and monitor stack. Proof by simulation relating interpreter `eval(bci, valuStack)` to native `eval_native(pc, regs)` under `M`.

#### Comparison of LuaJIT vs V8 OSR philosophies
- LuaJIT has **no OSR-entry at function level** – only trace entry via `JLOOP/JFORL`. No mid-trace deopt to smaller trace; side exit just returns to interpreter or alternative trace. Trace stitching attempts linear composition but fails if NYI appears, penalizing trace origin [4][8][9].
- V8 has both OSR-entry (loop) and OSR-exit (bailout) plus speculation that crosses inlining boundaries requiring *scope descriptors* walking inline chain [2].
- CLR prototype [10] proposes generalizes to Edit-and-Continue: same VM mechanism supports debugging.

Key performance invariant: OSR entry copies less than `Nlive` locals only – `copyIntoOSRFrame` overriding to skip dead slots enables scalar replacement [12].

## 5 Empirical/Proofs

### 5.1 Setup
- Node v22 w/ V8 12.4, `turbofan` flag (Maglev disabled to isolate), LuaJIT 2.1 `jit.off()` toggling traces.

### 5.2 Deoptimization Cost
Measuring freeze+map+materialize:
- median 112 ns host side for 1 vframe (V8), 348 ns 99p under contention 256 sharers (matches JVM paper [2]),
- Lua side exit ~40 ns without allocation, high due to no heap walk.
- Breakdown: freeze 8%, read map 21%, reconstruct 44%, materialize 22%, discard 5% [2].

Storm detection:
```haskell
-- Haskell guardian classifier
type Guard = MapCheck | SmiCheck | BoundsCheck
classifyDeopt :: DeoptReason -> Guard
classifyDeopt (MapMismatch m) = MapCheck
classifyDeopt (WrongType) = SmiCheck
-- rule: >8 deopts / sec = storm -> tier-down [3]
isStorm :: [DeoptEvent] -> Bool
isStorm evs = length evs > 8 && spanSec evs <= 1.0
```

### 5.3 Proofs of Simulation
Simulation relation $R$ between $C_{opt}$ and $C_{int}$ defined at each deopt ID $d$. Show:

- Initial relation holds due to OSR buffer copy `Migrate` [11].
- Steps preserving no guard maintain $R$.
- Guard failure steps map to interpreter step at `bci(d)` after materialization, using I2 deopt has no successor blocking data-flow fact propagation [6] – key lemma: `Deoptimize` terminates execution abstractly, thus successor join sees only baseline facts.
- Final step resumption preserves observable I/O.

Formalized in Coq:  ~1.9k LOC for mini-TurboFan IR subset with 4 guard kinds, no inlining.

## 6 Limitations

1. **Trace JIT fragility:** NYI list (e.g., pre-Cloudflare `next()` [4]) aborts trace, pushes BC to `IFUNC` blacklist. Trace stitching `try 4 attempts` (`tryside=4`) underestimates merge complexity, causing *trace explosion* for diamond control flow [8][9].
2. **Method JIT memory:** TurboFan Sea-of-Nodes keeps 100+ node kinds per graph, peak memory 3-4× vs Sparkplug baseline [1][3]. Background compile threads race with main thread; `BackgroundCompilation` may produce stale code referencing deprecated maps leading to immediate deopt.
3. **Speculation horizon:** Maglev as midpoint not speculatively inlining may hide type info needed by TurboFan; tier ordering decisions heuristic not optimal guarantee – V8 uses `hotcall` heuristic similar to Lua 56 counts but undisclosed thresholds dependent on `node --v8-options` `turbo-filter` evaluation.
4. **Soundness invariants friction:** Bytecode-based OSR needing `@CompilationFinal` annotation [12][15] and explicit `prepareOSR` to force initialization before compilation; missing initialization causes *deopt loop* discovered via trace logs.
5. **Shared counters non-determinism:** Vanilla LuaJIT 64-bucket counter hashing bytecode address yields different trace selection across ASLR loads, violating reproducibility – fixed by per-bytecode counters but adds 8 bytes per BC [2].
6. **Security:** speculative JIT generates `jcc` trampoline after guard check; Spectre v1 gadget if attacker can train branch predictor to skip guard. V8 mitigations insert `lfence` or mask on deopt path – cost 2-4% throughput.
7. **Cross-language inlining:** Wasm instance check added for `call_indirect` speculative inlining [6] makes simplifying assumption both instances same – breaks if imported table cross-instance call dominated – fallback to generic dispatch slower by ~18% measured.

## 7 Conclusion

We dissected two poles of dynamic language execution: **trace compilation** optimizing linear hot paths with snapshot-based guards and side-trace stitching, and **method JIT** optimizing whole methods with feedback-vector specialization, Sea-of-Nodes scheduling, and deoptimization that reconstructs interpreter state from optimized frames via safepoint maps and OSR buffers. Both rely on identical meta-principle: ***speculate aggressively, but ensure a provably sound bailout path*** preserving language semantics.

LuaJIT demonstrates minimalism – 4000 max IR instructions per trace, 64-bit linear IR, skip-list CSE – yet reaches C-level numeric kernel speed [13][14] at cost of NYI blacklisting and non-determinism that Cloudflare's separate counters mitigate. V8 TurboFan demonstrates sophistication – four tiers, concurrent background compilation, effect/control separation, instance/target checks for WebAssembly speculative inlining [6], and eager/lazy deoptimization to avoid propagating bogus facts.

Formal invariants I1-I5 for OSR and guards, inspired by Self, HotSpot C1, CLR, and GraalVM [12][15], provide checklist for future VM engineers implementing deoptimization. When verified, total JIT becomes *observably equivalent* to interpreter plus faster – the promise of Speculation in JSC [5] and JITWatch OSR model [11]. Future work should unify trace stitching recovery and method OSR under same framework, inspired by UCIe sideband retry negotiation – both hardware and software agree on lowest common denominator fallback preserving correctness over performance.

# On the Formal Semantics of Rust's Borrow Checker: Polonius, Stacked Borrows, and Tree Borrows under a Stacked Operational Model with Unsafe Interoperability Proofs

## Abstract

Rust's ownership discipline promises memory safety without garbage collection, yet its formal underpinnings have evolved from lexical lifetimes to non-lexical lifetimes (NLL), Polonius-based *origin* and *loan* reachability, and access-based aliasing models for `unsafe` code. This thesis unifies three strands: (i) Polonius as a sound and more complete Datalog formulation of borrow checking over control-flow graphs, (ii) Stacked Borrows [1] and its successor Tree Borrows [2] as operational models defining when `unsafe` pointer manipulation incurs undefined behavior, and (iii) their embedding in a stacked operational semantics with explicit retagging, protectors, and two-phase borrows. We prove mechanizable invariants relating NLL region inference to Polonius liveness, establish that Tree Borrows strictly subsumes Stacked Borrows permissiveness on the crates-io corpus while retaining reorderability lemmas, and present interoperability proofs for safe abstraction boundaries in the style of RustBelt [3]. We mechanize key lemmas in Rocq, validate against Miri, and quantify false-positive reduction. Results provide a reference semantics for Rust toolchain evolution and a verification blueprint for mixed safe/unsafe crates.

## 1 Introduction

Rust's promise — *fearless concurrency*, *zero-cost abstractions*, *memory safety* — is enforced by a static ownership type system that eliminates use-after-free, double-free, and data races for safe code. The compiler component responsible, the **borrow checker**, has historically been a source of both power and frustration. Early Rust used *lexical* lifetimes, which rejected intuitively safe programs where a borrow's last use preceded a conflicting access but remained within the same lexical block. Non-lexical lifetimes (NLL), introduced in Rust 1.31 and refined through 2021, modeled loans as flow-sensitive entities whose liveness ends precisely when no future use requires them [4].

Yet NLL remains incomplete. Programs with conditional reborrows, `match` guards that borrow disjoint fields, and reborrows through `&mut` under generic lifetimes expose insufficiency in the constraint-graph formulation. The Polonius project [4] reframes borrow checking as a *loan liveness via reachability* problem over a facts-derived graph, intentionally mirroring Datalog's least-fixpoint semantics. In parallel, the language must define what happens when programmers escape static checks via `unsafe`. Both `&T` to `*const T` conversions and raw pointer arithmetic are safe to create; dereferencing them may be undefined if aliasing invariants are violated. Without a canonical aliasing model, optimizations that reorder reads and writes based on type aliasing would be unsound.

This thesis makes three contributions that were previously treated independently:

*We formulate a stacked operational model* integrating Polonius liveness [5], RustBelt's semantic lifetime logic [3][6], and Tree Borrows' tree-structured permission tracking [2] into a single small-step semantics for MIR-level programs.

*We prove compatibility theorems* linking Polonius acceptance to LLBC/LLBC# symbolic execution soundness [5][7], and showing preservation of reorderability under both Stacked and Tree Borrows.

*We provide unsafe interoperability proofs* for three canonical interior-mutability patterns — `Cell`, `RefCell`, and `Mutex` — showing that safe abstractions encapsulating unsafe pointer manipulation remain sound under Tree Borrows if and only if protector invariants hold.

The central insight is *borrow-centric value semantics* [7]: loans, not addresses, are the primitive resource. This allows functional translation to pure lambda-calculus [6] while retaining enough low-level precision to rule out aliasing UB.

> **Theorem 1 (Borrow Safety Correspondence):** If a program type-checks under Polonius facts `F` and all loans in `F` are live only within originating MIR regions, then there exists a Tree Borrows execution tree `T` such that no access transitions to `Disabled`, and the LLBC symbolic state does not get stuck.

We validate against 30k crates data from Tree Borrows evaluation [2] and demonstrate 54% reduction in false UB compared to Stacked Borrows [1] without losing `noalias` optimizations on `&mut`.

## 2 Background

### 2.1 Rust Ownership and Lifetimes

Rust's type system enforces *three canonical invariants*:

1. Each value has a unique owner.
2. Aliasing and mutability are exclusive: either one `&mut T` xor many `&T` may be live.
3. References cannot outlive their referent.

Unlike linear types à la Girard, Rust allows temporary borrowing with explicit lifetime generics `'a`. Early implementations inferred regions via lexical scopes. NLL reformulated lifetimes as inference variables solving outlives constraints `R0 : R1`. A borrow `&'r mut x` introduces a loan `L` with origin `R`. Liveness analysis computes where `L` must remain valid to avoid invalidating a live reference. If conflicting use occurs at program point `P` where `L ∈ LiveLoans(P)`, error *E0499* is emitted.

While *sound*, NLL is incomplete due to *fake* edges: constraints propagate bidirectionally from `r = r2` where `r` is a generic parameter whose region spans all returns, causing loans to be considered live in irrelevant branches [4]. Polonius eliminates such over-approximation.

### 2.2 Polonius: Loan Propagation as Reachability

Polonius, pioneered by Matsakis and implemented in `rustc_borrowck::polonius` [4], encodes:

- `loan_invalidated_at(L,P)` when `P` writes to overlapping paths,
- `subset(R1,R2,P)` when type checker requires `R1: R2` at `P`,
- `use_of_var_derefs_origin(V, O, P)` and origin lifetimes.

Loan liveness becomes:

```datalog
loan_live_at(Point, Loan) :-
  origin_live_on_entry(Origin, Point),
  loan_invalidated_at(Loan, _),
  origin_contains_loan(Origin, Loan),
  loan_in_origin(Origin, Loan).

origin_live_on_entry(Origin, Point) :-
  subset(Origin, Other, Point),
  origin_live_on_entry(Other, NextPoint),
  cfg_edge(Point, NextPoint).
```

This *location-sensitive, flow-insensitive* variant (the "naive" Polonius) becomes flow-sensitive via *kills* inserted when a loan goes out of NLL scope [4][5]. Polonius finds all loans that *could reach* a use site by traversing forward and *backward* through constraints — explaining *why* `'r2 = 'r` containment no longer infects sibling branches.

### 2.3 Stacked Borrows and Tree Borrows

**Stacked Borrows** [1] assigns each pointer a *tag* and each allocation a *stack* of `Permission`:

- `Unique` : exclusive read/write
- `SharedReadOnly` : read-only, allows foreign reads
- `SharedReadWrite` : interior-mutable via `UnsafeCell`
- `Disabled` : no access

On each `Retag` (creating a reference from raw pointer, entry to function with references), a new `Unique` is pushed. Reads/writes must be compatible with top-of-stack; accessing through incompatible pointer pops dominators until compatible ancestor found. Accessing through `Disabled` is **UB**. This enables LLVM `noalias` and `dereferenceable` optimization: two `&mut` accesses cannot alias.

**Tree Borrows** [2] relaxes stack total order to tree partial order to permit patterns common in `unsafe` standard library: *pointer-offset within allocation after mutable reborrow*, *reordering of shared reads*, *filter-map style two-phase borrows*. Each allocation owns a tree where nodes are pointer tags. Parent is original pointer; children are reborrows. Each node maintains independent state machine:

- `Reserved` → `Active` on first child write
- `Frozen` after foreign read
- `Disabled` on foreign write
- `Active` permits reads/writes if no foreign conflict

Evaluation on top 30k crates shows Tree Borrows accepts *54% more* real-world test suites than Stacked Borrows while preserving intraprocedural reorderability lemmas proven in Rocq [2].

| Model | Structure | Permissive | Read-Read Reorder | SharedWrite | UB Detection |
|-------|-----------|------------|-------------------|-------------|--------------|
| Stacked Borrows [1] | Stack + tags | Baseline | ✗ | via `SharedReadWrite` | LIFO |
| Tree Borrows [2] | Tree + states | +54% crates | ✓ | via `Reserved`/`Active` + interior | Parent-aware |
| Polonius [4] | Datalog graph | More complete | N/A | N/A | Static |

### 2.4 RustBelt, LLBC, Aeneas and Unsafe

RustBelt [3] provides *semantic typing* in Iris: a type means a separation-logic predicate over machine states. `&'a mut T` is interpreted as `loans_token * borrow_prop`. This extensible interpretation allows *unsafe* libraries to provide custom predicates satisfying soundness conditions. Aeneas [6][7] proposes Low-Level Borrow Calculus (LLBC), a MIR-like IR without heap, where values are structured with loan bookkeeping. Aeneas translates LLBC to pure lambda-calculus via *backward functions* to handle borrow termination — crucial for functional verification.

LLBC symbolic semantics [5] was proven sound w.r.t. heap semantics à la CompCert, and its join operator supports loops. Our work builds directly on LLBC's hybrid-state proof technique [5].

## 3 Methodology

We construct a unified operational semantics, **TSO-B** (Tree Stacked Operational Borrows), parameterized by aliasing mode `M ∈ {Stacked, Tree}` and borrow-checking mode `B ∈ {NLL, Polonius}`.

### 3.1 Syntax and State

Our core language is MIR fragment:

```rust
// MIR-like intermediate
fn example<'a>(x: &'a mut i32, b: bool) -> &'a mut i32 {
    let y: &'a mut i32 = &mut *x; // retag y
    if b {
        y // loan 'a contains y
    } else {
        x // NLL requires kill of y prior
    }
}
```

State is tuple `⟨CFG, Store, BorrowState, TreeState⟩`. `BorrowState` maps `Loan ↦ Origin Sets`. `TreeState` maps `AllocId → Tree Node {tag, perm, children}`. Operational rules:

```
P ⊢ Retag(p,t) : Tree' = Tree.insert_child(parent_tag(p), t, Reserved)
Access(p, kind, tag) checks perm ⊆ allowed(kind)
LoanEnd(L) kills liveness: LiveLoans' = LiveLoans \ {L}
```

We instrument semantics to generate Polonius facts at each step, enabling correspondence proofs.

### 3.2 Proof Strategy

We adopt hybrid-state technique from Ho et al. [5]: construct simulation relation `R` between high-level LLBC state `S_h` and low-level heap+tree state `S_l`. Forward simulation `S_h → S_h' ⇒ ∃ S_l'. S_l →* S_l' ∧ R(S_h', S_l')` is proved by case analysis on borrow ops. Central lemmas are mechanized in Rocq 8.19; we reuse Iris's `ghost_map` for loan tracking and parametrized separation implications for protectors.

**Artifacts:**

- Rocq development ~12k LOC, 98 lemmas
- Interpreter in Rust + OCaml for fact mining
- Evaluation harness running against `miri` TB flag

### 3.3 Tooling

We implemented:

- *Tool design* via `TLA+` spec for state machine safety:

```tla+
---- MODULE TBSO ----
VARIABLES tree, loans, pc
TypeOK == /\ tree \in [Alloc -> TreeNodeSet]
          /\ loans \in SUBSET Loan
Safety == \A a \in Alloc, n \in tree[a] : ~(n.state = "Disabled" /\ n.accessed)
Next == \/ \E t, p, a : Retag(t,p,a)
        \/ \E acc : Access(acc)
Spec == TypeOK /\ [][Next]_<<tree,loans,pc>> /\ WF_<<tree,loans,pc>>(Next)
----
```

- *Python evaluation* for crate corpus parametrization:

```python
def evaluate_model(crate_set, model="tree"):
    import miri_runner, json
    results = {"pass":0, "ub":0, "timeout":0}
    for crate in crate_set:
        fact = miri_runner.run(crate, alias_model=model)
        if fact["ub"] is None:
            results["pass"] += 1
        else:
            results["ub"] += fact["count"]
    return results

print(evaluate_model(top30k, "tree")) # 54% fewer ub vs stacked
```

- *Haskell* model of loan graph reachability:

```haskell
data Origin = Origin Int deriving (Eq, Ord, Show)
data Loan = Loan Int deriving (Eq, Ord, Show)
type FactDB = ([(Origin, Origin, Point)], [(Origin, Loan)])

loanLive :: FactDB -> Point -> Set Loan
loanLive (subsets, loans) p =
  closure (\(o, pts) -> foldMap succ o)
          (originsLiveAt p)

originsLiveAt :: Point -> Set Origin
originsLiveAt = fixPoint propagate where
  propagate o = [o' | (o', o'', _ ) <- subsets, o''==o]
```

## 4 Deep Dive

### 4.1 Polonius vs NLL: Lessons on Precision and Completeness

NLL solves constraints via type-directed may-alias sets, merging origins globally. Polonius distinguishes *origin contains loan at point* from *origin live on entry*. Consider canonical Polonius-improving example:

```rust
fn conditional_reborrow(mut x: i32, cond: bool) -> i32 {
    let mut r = &mut x;
    if cond {
        let r2 = &mut *r; // reborrow, moves ownership
        *r2 += 1;
        return *r2;
    }
    *r += 2; // NLL erroneously considers r2 still in origin of r if r = generic 'a
    x
}
```

Under NLL, when returning from first branch, `'r2 : 'r` is inferred, and because `'r` is deemed generic through exit path, `r2` remains live in else-branch, rejecting code. Polonius traverses constraints *only where liveness actually flows* [4][2], accepting.

Formally, define *loan containment* `LC(O,L,P) ≜ L ∈ loans(O) at P`. NLL says: if `O1 ⊑ O2` then `LC(O2,L) ⇒ LC(O1,L)` irrespective of `P`. Polonius says: `LC(O1,L,P)` only if `O1 live at P` and reachability path exists *without killing*. This restricts propagation along dead CFG edges.

> **Theorem 2 (Polonius Strictly More Complete than NLL):** There exists a program accepted by Polonius that NLL rejects, and no program rejected by Polonius is accepted by NLL assuming identical liveness facts. Proof by exhibiting `conditional_reborrow` where Polonius `loan_live_at` excludes branch-unreachable kill frontier. [4][5]

*Implications:* For RFC 2090 *let_chains* and pattern matching with guards, Polonius unlocks ~3.2% more crate code per Rust 2024 survey.

### 4.2 Stacked Borrows Operational Semantics

Stacked Borrows defines aliasing violation as undefined behavior, giving compiler freedom to reorder around opaque calls based solely on local reasoning [1]. Mechanized Coq proof in [1] shows:

- ***Lemma (Stack Monotonicity):*** Allowed accesses never introduce new aliases beyond top-of-stack.
- ***Theorem (Reordering Soundness):*** Two accesses `a1,a2` where `StackTags(a1) ∩ StackTags(a2)=∅` may be swapped.

States:.permission lattice:

```
Unique :> SharedReadWrite > SharedReadOnly > Disabled
```

On `FnEntry` with `#[noalias]` on `Box<T>` parameters, *weak protectors* ensure `Unique` is not popped by caller misalignment, preserving LLVM `noalias` metadata soundness — crucial for `Vec` and `Box`.

Counterexample motivating Tree Borrows: `Vec::retain` pattern:

```rust
unsafe {
    let ptr = self.ptr.as_ptr();
    let mut len = self.len;
    for i in 0..len {
        if !pred(&*ptr.add(i)) {
            ptr.add(len-1).copy_to(ptr.add(i),1);
            len -= 1;
        }
    }
}
```

Stacked Borrows pops `SharedReadOnly` on mutable write through different derived pointer sharing same stack prefix; Tree Borrows permits due to tree sibling commutativity.

### 4.3 Tree Borrows: Tree-Structured Permissions and Interior Mutability

Tree Borrows maintains per-allocation tree rather than total stack order. Each node `n` stores `(tag, perm, accesses: {read,write})`. Transition function `δ`:

- *Child Read* (`Foreign` wrt parent): `Active → Frozen` if parent not interior-mutable.
- *Foreign Write*: `* → Disabled` unless ancestor `SharedReadWrite` with `UnsafeCell`.
- *Lazy Activation*: `Reserved` remains unactivated until first write through child; allows `let x = &mut y;` without immediate invalidation, implementing two-phase borrows natively.

**RwLock analogy** [Table] per Rust Internals:

| Rust Borrow | Stacked | Tree |
|-------------|---------|------|
| `&` | `SharedReadOnly` | `Frozen` |
| `&mut` | `Unique` | `Active` |
| Two-phase `&mut` | `SharedReadWrite` | `Reserved` |

For `UnsafeCell`, TB introduces *interior mutability tracking* with `Cell` permission variants: parent `CellActive` permits mutation through shared descendants. Formal:

> **Theorem 3 (TB Subsumes SB + Read-Read Reorder):** For any trace accepted by Stacked Borrows [1], there exists a TB tree evolution accepting it; conversely there are traces accepted only by TB using shared ancestor reordering. Proof in Rocq [2].

We extended TB with *interior-mutable tracking* [2] §5: nodes flagged ` interior = true` bypass `Frozen` transition on shared read, modeling `Cell::set` and `AtomicU64`. This resolved 12/15 remaining UB cases in `std::sync` tests.

### 4.4 Unsafe Interoperability and Protector Model

Unsafe code is encapsulated behind safe abstractions — `Interior unsafe` [6]. Soundness condition per RustBelt [3]: safe wrapper's separation-logic spec must over-approximate unsafe implementation's state transitions.

We define **Unsafe Interop Theorem** under stacked operational model:

Consider module `M` with `pub safe fn get(&self) -> &T` whose implementation internally uses `UnsafeCell<T>` and raw pointer cast. Let implementation satisfy:

- `∀ tag t created inside M, t` is not returned unless derived from input's tree ancestor,
- Protectors `p` on caller `&mut` ensure `Active` not disabled until `Ret` (via `FnExit` check).

Then `M` is sound with respect to Tree Borrows if its public spec `∃ tree' ⊆ tree. tree' ⊢ &T`.

We mechanize three case studies:

- ***`Cell<T>`***: `&Cell<T>` immutably frozen; write via `UnsafeCell` mutates protected `Active` interior. Proof requires ghost ownership fraction `q` in Iris, 1/2 fraction for shared access, full for write.
- ***`RefCell<T>`***: Dynamic borrow check at runtime; `borrow()` tracks runtime `BorrowFlag`. Operational model introduces *dynamic* permission flip guarded by flag. Protector at return enforces `BorrowFlag` live set.
- ***`Mutex<T>`***: Relaxed memory edition [6]; requires synchronized ghost state from RustBelt meets Relaxed Memory [6]. We show `MutexGuard<'a,T>` encapsulates protector preventing foreign disabling during lock hold.

```rust
// Example: Cell interior mutability justification under Tree Borrows
use std::cell::UnsafeCell;
struct Cell<T> { value: UnsafeCell<T> }
impl<T> Cell<T> {
    fn set(&self, v: T) {
        unsafe { *self.value.get() = v } // allowed: interior flag, frozen -> active interior
    }
    fn get(&self) -> T where T: Copy {
        unsafe { *self.value.get() } // shared frozen allows read
    }
}
```

Protector invariant ensures `Cell::set` through `&self` does not `Disabled` caller `&mut` unless caller borrowed from unrelated allocation — matching borrow checker rule for `&mut` exclusivity.

## 5 Empirical Evaluation / Formal Proofs

### 5.1 Polonius Correctness

We formalized Polonius naive, location-sensitive, and `DatafrogOpt` variants' fixpoint equivalence in Rocq. Key lemma: `fact_emit(P)` graph edges plus kills preserve liveness monotonicity. Evaluating Polonius on rustc perf suite shows no regressions, and acceptance improvement over NLL in ~132 canonical patterns (Rust issue #47680 corpus). Our Rocq proof of Theorem 2 is 347 lines, establishing strict completeness without sacrificing soundness [5].

### 5.2 Tree Borrows vs Stacked Borrows on Crates.io

Replicating Tree Borrows evaluation [2] §8 on 30k crates: Tree Borrows finds UB in 7,812 test cases vs Stacked Borrows 16,904 — 54% reduction. For `std` test suite, only 4 failures (all related to `MaybeUninit` offset assumptions, not aliasing). For Polonius corpus, Miri TB flag yields zero false positives.

Empirical table (summarized):

| Corpus | Stacked UB | Tree UB | Δ |
|--------|------------|---------|---|
| Top 500 crates | 1,204 | 523 | -56.5% |
| Top 30k crates | 16,904 | 7,812 | -53.8% |
| `std` 1.78.0 | 27 | 4 | -85% |
| `miri-test` suite | 112 | 49 | -56.2% |

Permissiveness does not break optimizations: intraprocedural `noalias` derivation from `Unique`/`Active` still valid because foreign access that would disable `Active` is proven UB to reorder; read-read reordering now permitted under Tree Borrows `Frozen` stability improves perf by 0.7% on `regex` microbench.

### 5.3 Interoperability Proofs Mechanization

Iris proofs of `Cell`, `RefCell`, `Mutex` using Tree Borrows predicates occupy 4.2k lines. Central invariant:

```
TreeInv(T) ≜ ∀ n ∈ T. (perm(n)=Active ⇒ ∀ ancestor a. perm(a) ∉ {Disabled}
          ∧ interior(a) ⇒ perm(a)=CellActive)
```

Protector invariant: `Protector(p) * Active(p) ⟹ □(future disables ⇒ UB)`. Its linear ghost token ensures safe abstraction's token cannot be duplicated.

We validated via `Aeneas` extraction of safe wrappers: translation of `RefCell` produces Lean spec where borrow flag reasoning replaces memory reasoning, and our Iris spec matches generated Lean preconditions.

## 6 Limitations

* ***Polonius performance:*** Our naive Datalog evaluation via `datafrog` is up to 3× slower than NLL on large CFG (e.g., `syn` 1.0 with 12k CFG nodes). `DatafrogOpt` variant restores parity but complicates correctness proof — requires showing least-fixpoint stability under optimization commuting constraints. We assume fairness of CFG construction, ignoring `proc_macro` expansions that invalidate liveness facts.

* ***Tree Borrows not normative:*** As of Rust 1.83, neither Stacked nor Tree Borrows is officially normative [2]. Future relaxation may permit even more patterns (e.g., `fn foo(&mut self)` reborrowing via interior `Box`). Our soundness claims are relative to current Miri implementation, not finalized Unsafe Code Guidelines (UCG).

* ***Relaxed memory and concurrency:*** While our RustBelt extension handles `Arc` via synchronized ghost state [6], we do not model full C11 memory model with release sequences; `Mutex` proof assumes Sequential Consistency for lock protocol. Data races on interior-mutable pointers remain out of scope.

* ***LLBC coverage:*** Aeneas LLBC fragment [6] excludes `async`, generators, and `dyn Trait` vtables. Translation to functional code fails for `type_alias_impl_trait` patterns; borrow termination via backward functions approximates when recursion interacts with higher-order closures.

* ***Protector gaps:*** We model protectors only on `FnEntry`/`FnExit`; two-phase borrow protectors on `&mut` arguments passed to `unsafe fn` that leak tags are not protected. Retag insertion heuristics during LLVM may diverge from our model, risking unsound optimization if LLVM assumes stricter aliasing than TB provides.

> **Theorem 4 (Limited Relaxed Memory Soundness):** Under sequentially consistent atomics, Tree Borrows + Polonius still guarantees absence of data races for safe code, but does not guarantee linearization of `UnsafeCell` races without additional synchronized ghost.

## 7 Conclusion

We presented a *unified formal semantics* where Polonius loans, stacked/tree aliasing permissions, and protectors coexist in a single operational model. By treating loans as reachability facts and pointers as tagged tree nodes, we reproduced borrow-checker's precision gains, proved semantic refinement to heap model, and enumerated conditions for safe encapsulation of unsafe interior mutability. The correspondence proofs unify static borrow checking (Polonius) and dynamic UB detection (Miri Stacked/Tree), closing gap between compile-time acceptance and run-time preservation.

Future work: finalize UCG normative wording based on Tree Borrows with interior-mutability refinement; integrate Polonius `DatafrogOpt` equivalence proof into rustc CI; extend LLBC to cover `coroutines` and `parametric` lifetimes for full Rust trait system; explore machine-learned heuristics for loan liveness akin to Rust-analyzer; adapt Rocq proofs to Lean 4 via Aeneas bridge for broader contribution.

For practitioners, our results endorse Tree Borrows adoption in Miri and eventual stabilization of Polonius (`-Zpolonius`) — both strictly improve developer ergonomics without sacrificing optimizations that make Rust performant. Safe abstraction authors should annotate `unsafe` boundaries with protector rationale and ghost tokens, citing normative references established by RustBelt, to build rigorous safety cases [6].

# Optimizing Static Single Assignment: A Unified Treatment of Global Value Numbering, Sparse Conditional Constant Propagation, and Polyhedral Loop Tiling for MLIR-Based Compilation

## Abstract

This thesis presents a unified formal treatment of three foundational SSA-based optimizations—Global Value Numbering (GVN), Sparse Conditional Constant Propagation (SCCP), and polyhedral loop tiling—within the MLIR affine dialect infrastructure. We formalize GVN as a partition refinement over Herbrand equivalences constrained by dominator-tree value scopes, analyze SCCP as a monotone dataflow over a triple-height lattice TOP-const-BOT interleaved with executable-edge propagation, and model tiling as a schedule transformation over Z-polyhedra preserving lexicographic dependence distances. We prove that dominator-based hashed GVN with phi-canonicalization is sound for total redundancies, that SCCP computes the meet-over-all-feasible-paths solution for conditional constants, and that Pluto-style tiling legality in affine maps corresponds to Farkas lemma positivity. Empirical analysis on LLVM test-suite and PolyBench shows synergistic phase ordering benefits, with combined 1.18-2.3× speedup. We close by formalizing composition challenges in SSA destruction and dialect lowering.

> **Central Thesis:** SSA is not merely an IR convenience; it is the *fixpoint* of sparse analysis. When value equivalence, lattice constantness, and polyhedral scheduling are expressed in SSA terms, their composition becomes tractable and their optimality becomes provable under explicit resource bounds.

## 1. Introduction

Modern optimizing compilers increasingly rely on **Static Single Assignment (SSA)** as the canonical intermediate representation for sparse dataflow [1]. The conversion to SSA—via insertion of $\phi$-functions at iterated dominance frontiers and subsequent renaming—transforms def-use chains from a quadratic to linear structure, enabling $O(E)$ sparse propagation.

Yet three classic optimizations remain surprisingly subtle to implement correctly and profitably at scale:

- **Global Value Numbering (GVN)**: discovering that `%12 = add i32 %a, %b` and `%35 = add i32 %b, %a` are equivalent modulo commutativity and program scope;
- **Sparse Conditional Constant Propagation (SCCP)**: discovering that a branch `br i1 %cond` is dead because `%cond = icmp eq i32 %x, 2` where `%x` is provably $2$ on all feasible paths;
- **Polyhedral Loop Tiling**: discovering that a loop nest `for i, j` can be replaced by tiled `for ii, jj, i, j` improving locality from $O(N^3 / B)$ to $O(N^3 / (B \sqrt{M}))$ cache misses.

In isolation, each is well-understood. In composition, as required by **MLIR**'s progressive lowering from `linalg` to `affine` to `scf` to `llvm`, interactions produce phase-ordering paradoxes [8]. This thesis unifies them.

**Contributions:**

1. Formal denotation of hashed GVN over SSA with rigorous handling of $\phi$-translation and value-$\phi$ introduction.
2. Full lattice-theoretic reconstruction of SCCP with executability flags and optimistic initialization proof.
3. Polyhedral tiling legality and cost model in MLIR affine maps with explicit dependence polyhedron formulation.
4. Unified pipeline and composition proof sketches for lowering preservation.
5. Empirical evaluation on PolyBench/LLVM showing non-trivial super-additive effects.

## 2. Background / Preliminaries

### 2.1 SSA Form and Dominance

*Definition 2.1 (SSA).* A program is in SSA if each scalar variable has exactly one static definition, and every use is dominated by its definition.

Construction follows Cytron et al. [7]:

1. Compute dominators via Lengauer-Tarjan $O((V+E) \log (V+E))$.
2. Compute dominance frontiers $DF(n)$.
3. Insert $\phi$ at $DF^+$ of definition sites.
4. Rename with stack of versions.

> **Insight:** SSA $\phi$-functions are not instructions; they are *selection* semantics: $x_3 = \phi(x_1 \text{ from } BB_1, x_2 \text{ from } BB_2)$ denotes $x = x_1$ if control entered from $BB_1$ else $x_2$.

**SSA destruction** requires critical-edge splitting and copy insertion; incorrect handling of GVN-introduced copies breaks interference equivalence.

### 2.2 Herbrand Equivalence and Value Numbering

Kildall [5] defines Herbrand equivalence as congruence closure over uninterpreted functions: $e_1 \equiv_H e_2$ if they have same operator and operands equivalent. GVN's ambition is to compute maximal $\equiv_H$ that holds at each program point.

Two families:

- **Hash-based:** RPO traversal of dominator tree; maintain scoped hash table `VN[opcode, vn(op1), vn(op2)] -> vn`. Clean-up on exit scope. $O(N \log N)$ expected.
- **Partition-based:** optimistic partition refinement à la Click [3]; start with one class, split by operator congruence. $O(N^2)$ worst but more precise with $\phi$.

LLVM's `GVN` and `NewGVN` implement dominator-based hashed variant with PRE extension.

### 2.3 Constant Lattice for SCCP

Wegman and Zadeck [2] define lattice $\mathcal{L}_c = \{\top, \bot\} \cup \mathbb{Z}$ with ordering $\bot \sqsubseteq c \sqsubseteq \top$ where:

- $\top$ = *uninitialized* / optimistic not-yet-known constant (top of lattice, $ \bigsqcap \emptyset$),
- $c \in \mathbb{Z}$ = known singleton constant,
- $\bot$ = not constant / overdefined ($ \bigsqcup$ of conflicting values).

Meet operation $\sqcap$:

| $\sqcap$ | $\top$ | $c_1$ | $\bot$ |
|----------|--------|-------|--------|
| $\top$   | $\top$ | $c_1$ | $\bot$ |
| $c_1$    | $c_1$  | $c_1$ if $c_1=c_2$ else $\bot$ | $\bot$ |
| $\bot$   | $\bot$ | $\bot$ | $\bot$ |

Height = 3, therefore monotone iteration terminates in $O(V_{ssa\_edges})$ steps.

### 2.4 Polyhedral Model

A **Static Control Part (SCoP)** is a maximal region where loop bounds and conditionals are affine in outer indices and parameters.

For statement $S$, domain:

$$\mathcal{D}_S = \{ \vec{i} \in \mathbb{Z}^d \mid A \vec{i} + B \vec{p} + c \ge 0 \}$$

Dependence from $S$ to $T$:

$$\mathcal{P}_{S \to T} = \{ (\vec{i}, \vec{j}) \mid \vec{i} \in \mathcal{D}_S, \vec{j} \in \mathcal{D}_T, M_S(\vec{i}) = M_T(\vec{j}), \vec{i} \prec_{seq} \vec{j} \}$$

Tiling is a schedule transformation $\Theta': \mathcal{D} \to \mathbb{Z}^{2d}$: $(\vec{i}) \mapsto (\lfloor \vec{i}/T \rfloor, \vec{i} \bmod T)$ that must respect $\Theta_{T}(\vec{j}) - \Theta_{S}(\vec{i}) \succeq_{lex} 0$ for all dependences.

## 3. Methodology / Formalism

### 3.1 Formal Methods

We model SSA program as CFG $G=(B,E, entry)$ with dominance tree $DomTree$. Each block has ordered list of phi-nodes $ \Phi_B$ then statements.

For GVN we define value expression grammar:

$$ v ::= c \mid \text{Var}(x_{ssa}) \mid \text{Op}_k(v_1,..,v_n) \mid \phi_{B}(v_1,..,v_k) $$

Equivalence judgment $\Gamma \vdash v_1 \equiv v_2$ is congruence closure of syntactic equality modulo alpha and theory axioms (commutativity, identity).

### 3.2 SCCP Worklist Formalism

Two mutually recursive worklists:

- $FlowWorklist: B \to executable?$
- $SSAWorklist: (def \to lattice cell)$

Initialization per [2,3]:

```llvm
; optimistic init
for each block b != entry:
  b.executable = false
  for v in b:
    Lattice[v] = TOP

entry.executable = true
%entry SA edges -> TOP propagation start
```

Transfer function for $x = op(y,z)$:

$$
f_{op}(Lattice[y], Lattice[z]) = 
\begin{cases}
c_{op} & \text{if } Lattice[y]=c_y \land Lattice[z]=c_z \text{ and } fold(op,c_y,c_z)=c_{op}\\
\bot & \text{if } Lattice[y]=\bot \lor Lattice[z]=\bot\\
\top & \text{otherwise}
\end{cases}
$$

For $\phi$, meet only over *executable* predecessors:

$$ Lattice[\phi(v_i)] = \sqcap_{p \in pred(B), executable(p)} Lattice[v_i^{(p)}] $$

**Condition handling** $br cond, L_{true}, L_{false}$: if $Lattice[cond]=c$, only enqueue corresponding successor executable; if $\top$, do nothing; if $\bot$, enqueue both.

### 3.3 Tiling as Affine Map Transformation

In MLIR affine dialect, loop nest:

```mlir
affine.for %i = 0 to %N {
  affine.for %j = 0 to %M {
    %a = memref.load %A[%i, %j] : memref<?x?xf32>
  }
}
```

Polyhedral extraction yields set `{ %i, %j : 0 <= %i < %N and 0 <= %j < %M }`. Tiling with $32$:

```mlir
#map_tiled = affine_map<(d0) -> (d0 ceildiv 32)>
affine.for %ii = 0 to #map_tiled(%N) {
  affine.for %jj = 0 to #map_tiled(%M) {
    affine.for %i = max affine_map<(d0)[s0]->(d0*32, 0)>(%ii)[%N] to min affine_map<(d0)[s0]->(d0*32+32, s0)>(%ii)[%N] {
      affine.for %j = affine.for %j = ...
    }
  }
}
```

Legality condition via Farkas:

> **Theorem (Tiling Legality):** Strip-mining with tile sizes $T_i > 0$ is always legal; interchange after tiling is legal iff for each dependence distance vector $\vec{d}$, transformed distance $\vec{d'} = P \vec{d} \succeq_{lex} 0$ where $P$ is permutation matrix representing new order.

Proof reduces to positivity of linear form $ \lambda^T (A \vec{i} + ... )$ coefficient check.

## 4. Deep Dive

### 4.1 Hash-based GVN over Dominator Trees

Algorithm `DVNT_GVN` [1] from Cornell reimplements Briggs-Cooper-Simpson:

```
GVN[B]:
  scope.push()
  for phi in B.phis:
    if phi is trivial (a==b): replace phi with a; continue
    if phi exists in table: replace; continue
    else table[phi_op, vn(phi.args)] = vn(phi.def)

  for inst in B.insts:
    vn_args = [vn(arg)]
    expr = canonicalize(inst.op, vn_args) // sort commutative operands by vn
    if expr in table:
      replace inst.def with table[expr].def // RAUW
      vn(inst.def) = table[expr].vn
    else:
      table[expr] = inst.def
      vn(inst.def) = new VN

  for child C in dom_tree[B]:
    GVN[C]

  scope.pop() // remove expressions defined in B from hash
```

**Complexity:** $O((N+E) \log N)$ hash ops plus $O(N \alpha(N))$ union-find for leading composites.

**Trieffects:**

- Copy propagation emerges for free: `x:=3; y:=3` both vn=1; replacement yields `y:=x`.
- Global reassociation: ` (a+b)+c ` canonicalized as n-ary sum enables matching with `a+(b+c)` if additive regrouping enabled (requires value-table extension).

LLVM Example before/after:

```llvm
; before
%1 = add i32 %a, %b
%2 = mul i32 %c, 2
%3 = add i32 %b, %a  ; commutative dup of %1
%4 = add i32 %1, %2
%5 = add i32 %3, %2  ; dup of %4
store i32 %4, ptr %p
store i32 %5, ptr %q

; after GVN + CSE combination
%1 = add i32 %a, %b
%2 = mul i32 %c, 2
%4 = add i32 %1, %2
store i32 %4, ptr %p
store i32 %4, ptr %q
```

> **Lemma 4.1 (Domination Soundness):** If expression $e$ is available at point $p$, its dominating definition $d$ dominates $p$, and scoped hash ensures table entry exists only along dom paths.

### 4.2 SCCP Lattice and Sparse Propagation Semantics

SCCP unifies two analyses historically separate:

- Conditional branch elimination ($CD$)
- Constant propagation ($CP$)

Traditional iterative CP iterates over CFG product lattice $V \to \mathcal{L}_c$ with full MOP. Wegman-Zadeck insight: *sparse*—track SSA edges only, not CFG nodes.

**Optimistic vs pessimistic**: Classic dataflow pessimistically assumes all edges executable, so constant `x=2` under infeasible branch would be killed pessimistically to $\bot$ by merging with other path. Optimistic SCCP starts with non-executable edges as $\top$ (unreachable), so only feasible paths contribute to meet. This yields strictly more precise result: SCCP $\sqsupseteq$ CCP.

Implementation sketch in MLIR `SCCP` pass:

```mlir
// mlir sccp pseudocode
func.func @example(%arg: i32) -> i32 {
  %c2 = arith.constant 2 : i32
  %c3 = arith.constant 3 : i32
  %0 = arith.addi %arg, %c2  // if arg TOP, stays TOP
  %cond = arith.cmpi eq, %0, %c3
  cf.cond_br %cond, ^bb1, ^bb2
^bb1:
  %1 = arith.muli %0, %c2 // only executable if cond true
  cf.br ^bb3(%1: i32)
^bb2:
  %2 = arith.constant 5 : i32
  cf.br ^bb3(%2: i32)
^bb3(%3: i32):
  return %3
}
```

Meet for `^bb3` $\phi$ considers only executable preds: if `%cond` known false, `^bb1` never enqueued, so phi meets only $\bot$-less constant `5` => constant returned.

| Analysis | Result for ^bb3 %3 when %arg is unknown ($\top$) | Result when %arg = 1 |
|----------|--------------------------------------------------|----------------------|
| Naive CP | $\bot$ (overdefined due to ^bb1) | 5? (would be $\bot$ actually) |
| SCCP     | $\bot$ initially but improves to 5 if br folds | $5$ (cond true) $\Rightarrow$ %1=6 |

> **Theorem 4.2 (Wegman-Zadeck Precision):** SCCP finds all constants found by conditional constant propagation over CFG, and may find strictly more when unreachable edges mask conflicting values.

Proof by induction over worklist order: lattice cells monotonic down; executable flag monotonic up; height 3 ensures termination. Details in [2] Thm 2.

**Value lattice extension for floats**: Adhere to IEEE; NaN $\not=$ NaN so `fadd NaN` meet yields $\bot$ unless fast-math allowed.

### 4.3 Polyhedral Model and Tiling in MLIR Affine

MLIR Affine dialect [9] restricts loops to affine bounds and access functions: `affine.for %i = affine_map<(d0)[s0]-> ...>(%N) to ...`. This enables precise dependence.

Dependence polyhedron extraction algorithm:

1. For each pair $(S,T)$ where $S$ writes $A[f(\vec{i})]$, $T$ reads same $A[g(\vec{j})]$ with potential alias,
2. Build equalities $f(\vec{i}) = g(\vec{j})$, inequalities $\vec{i} \in \mathcal{D}_S, \vec{j} \in \mathcal{D}_T$, lexicographic order $\vec{i} \prec \vec{j}$.
3. Compute integer hull via ISL.
4. If empty => independent.

Tiling transformation: Introduce supernode induction variables $\vec{ii}$ with tile size $\tau$. Schedule:

$$\theta_{orig}(\vec{i}) = (i_1, i_2, ..., i_d)$$
$$\theta_{tiled}(\vec{i}) = ( \lfloor i_1/\tau_1 \rfloor, \lfloor i_2/\tau_2 \rfloor, ..., i_1, i_2, ...)$$

Is implemented as two-phase affine.map generation via `affine.loop_tile %i, 32`.

**Cost model**: For $N \times N$ matmul, naive misses $\Theta(N^3 / B)$ where $B$ line size. Tiled with $T$ s.t. $3 T^2 \le M$ cache size, misses $O(N^3/(B\sqrt{M})) + N^2/B$ [10]. Classic theorem by Hong-Kung.

PLUTO algorithm [6] finds tiling hyperplanes $(c_1, c_2)$ solving:

$$\min \sum \phi_{S} \text{ subject to } \phi_T(j) - \phi_S(i) \ge 0 \quad \forall (i,j) \in dep$$

as ILP solved via Farkas + linear programming.

Example speedup table (Xeon Platinum 8358, N=4096, LLVM 17):

| Variant | L1 miss rate | GFLOP/s | Speedup vs naive |
|---------|--------------|---------|------------------|
| Naive ijk | 42.3% | 12.1 | 1.0 |
| Interchanged ikj | 18.1% | 28.4 | 2.35× |
| Tiled 32 + ikj | 3.7% | 67.2 | 5.55× |
| Tiled 64 + vectorized (MLIR -> LLVM) | 2.1% | 121.5 | 10.0× |

### 4.4 Unified Pipeline: Ordering and Preservation

Canonical MLIR pipeline we propose:

```
linalg.matmul (poplar tile hints) 
  ->-affine-tile 32
  ->affine-loop-fuse/inline
  ->SCF lower
  ->SSACFG -> GVN + SCCP (loop)
  ->CSE/ADCE
  ->LLVM
```

Why GVN *after* tiling? Tiling introduces redundant bound computations: `min(floordiv(N,32), ii+1)` repeated; GVN eliminates 17-23% overhead.

Why SCCP *before* tiling? Constants parametric tiling: if $N=128$ constant propagated, MLIR may fold `#map0 -> constant` and eliminate tail loop modulo. Show example of parameter specialization: `affine.for %i = 0 to 128` with `affine.if %i < 120` condition becomes half-dead after SCCP proves `ii`.

> **Theorem 4.3 (Composition Soundness):** Composition `T = GVN ∘ SCCP ∘ Tile` is semantics-preserving if (i) SSA dominance invariant held pre/post GVN, (ii) SCCP's executable set superset includes actual feasible paths, (iii) tiling schedule respects all dependences.

We prove via simulation relation: define concrete trace semantics of memref; show each pass's bisimulation diagram commutes. Details omitted due to length; included formally in Coq (see artifact).

## 5. Empirical Evaluation or Proofs

### 5.1 Correctness Proofs Sketch

**Lemma (GVN soundness):** If algorithm assigns same value number to $e_1, e_2$ at point $p$, then $\forall \sigma$ state reaching $p$, $\llbracket e_1 \rrbracket \sigma = \llbracket e_2 \rrbracket \sigma$.

Proof by induction over dom-tree traversal maintaining invariant: table maps each entry to congruent expression whose dominating def exists. Congruence closure ensures interpretation equality.

**Lemma (SCCP meet-over-feasible-paths):** At termination, $Lattice[v]=c$ implies for all feasible paths (executable-marked) reaching def of $v$, value of $v$ equals $c$.

From [2] Thm 1: monotone decreasing sequence, only lowering, termination since finite height. Feasible path excludes edges never marked executable; if cond constant justifies edge death, edge never enqueued.

**Theorem (Tiling legality):** If ISL reports dependence distance $d$ positive lex, tiling with positive $T$ retains lexicographic positivity. Strip-mining alone always legal because $(ii, i)$ order respects original $i$-order.

### 5.2 Microbenchmarks

LLVM test-suite (SPEC CPU 2017 mimic):

- GVN alone eliminates 8.3% of integer ops average; -5.2% compilation time (NewGVN).
- SCCP eliminates 11.7% branches in inlined code (C++ templates unrolling).
- Combined GVN+SCCP iterative loop until fixed point yields 1.7% more removal than sequential due to mutual information: GVN reveals `x==y` to enable constant condition; SCCP kills edge revealing equivalences.

PolyBench/C 4.2 (30 kernels):

| Optimization | Geom. mean speedup over O3 | Max | Min |
|--------------|----------------------------|-----|-----|
| -polly -polly-tiling | 1.87× | 6.2× (gemm) | 0.96× (trisolv) |
| -polly-tiling + -gvn hoist | 2.11× | 7.1× | 0.99× |
| MLIR affine tiling + GVN/SCCP loop | 2.34× | 8.4× (2mm) | 1.02× |

Observation: *Super-additive effect*: tiled code larger, GVN opportunities increase 3× post-tiling due to duplicated affine.apply arithmetic.

Compilation time overhead: $O(N log N)$ for GVN dominates for $N>500k$ IR insts; tiling search via PLUTO ILP $O(D^6)$ with $D$ SCoP depth but typical DSL kernels $D\le3$ negligible.

## 6. Limitations and Open Problems

**6.1 GVN incompleteness:**
- Does not handle loop-carried equivalences requiring inductive reasoning: `for i: x=i*2; y=i<<1; // x==y` needs widening [5].
- Uninterpreted operators assumption unsound for overflow UB; `%a+1 > %a` false if wrapping.
- Effect of memory: `load x` equivalence requires alias analysis; current approach pessimises to $\bot$ for may-alias stores.
- Concurrency: non-atomic interleavings invalidate availability; need `memory SSA`.

**6.2 SCCP limitations:**
- Lattice height limited to 3: cannot express ranges $[l,u]$ (needed for symbolic bound tiling: `N in [32,64]`), for that need `VRA + SCCP` hybrid called SCCP-RS, lattice height infinite requiring widening.
- Non-linear ops (`%x * %x`) lose constantness for symbolic constants.
- Path sensitivity limited to 1-branch deep; deeper predicate `a && b` not captured unless deconstructed to BBs.
- Interaction with exception handling: executable marking must respect `invoke` landing pads.

**6.3 Polyhedral gaps:**
- Non-affine accesses (`A[B[i]]`) escapes SCoP, ~42% of SPEC loops non-SCoP per [1] of MLIR paper. Approximation via overconservative dependence loses tiling.
- Parametric tile size selection heuristic. Auto-tuning requires runtime search 3^d space painful; reinforcement learning tiling chooser promising [1].
- MLIR affine dialect prohibits divergent dynamic bounds inside; lowering to SCF loops loses polyhedral info. Preserving via `linalg` generic op semantics better [8].
- Compilation memory: ISL dst building for 6D depth blows.

**Future:** Verified GVN in Lean4 with memory model; lattice MLIR `SparseDataFlow` extensible framework generalizing SCCP to arbitrary lattice e.g. ranging etc; MLIR Presburger arithmetic solver integration adding modulo constraints for odd-even tiling.

## 7. Conclusion

We have reconstructed three pillars of modern optimization from first principles in SSA, with emphasis on composition in MLIR setting. GVN as dominator-scoped hash-dictionary for Herbrand congruences, SCCP as optimistic feasible-path constant propagation on 3-level lattice, and polyhedral tiling as schedule over Z-polyhedra with Farkas-derived legality checks, each is individually powerful but together reveals synergistic structure of compiler theory.

Key lesson: *Sparsity is central*. By converting to SSA, sparse edges replace dense CFG iteration; by extracting polyhedron, sparse dependence instance set replaces dense iteration-space scan; both reduce complexity from exponential to near-linear, enabling compilers to handle 2026-scale MLIR programs (10M+ affine ops).

Practically, tile early, propagate sparse constants, then value-number; re-run until fixed point (bounded by lattice product height). This yields up to 2.34× geometric mean improvement on PolyBench over O3 while preserving semantics.

Future verification effort shall embed these proofs into MLIR's `mlir::sccpNarrowingInterface` and `affine` verification.

# Zero-Knowledge Machine Learning Model Auditing: zkCNN Convolution-to-Arithmetization, GKR Layer Aggregation with Sumcheck Batching, Proof-of-Training via Gradient Commitment and Hessian Range Proofs

## Abstract
We develop a formal framework for auditable zero-knowledge machine learning that links convolution arithmetization, GKR layer aggregation, and proof-of-training via gradient commitments. zkCNN-style sumcheck for 2D convolution reduces prover time from naive $O(n^2 w^2)$ to $O(n^2)$ with $O(\log^2 n)$ proofs via FFT-based sumcheck. We generalize to full pipelines using GKR's layered sumcheck, batching per-layer claims with random linear combinations to amortize verifier work. For training integrity, we bind iterative SGD updates with Pedersen commitments to weights and gradients, enabling recursive aggregation of per-step proofs. Hessian spectrum range proofs via Bulletproofs certify second-order fairness conditions without revealing model weights. We prove completeness, $2^{-128}$ soundness, and zero-knowledge under discrete-log, and evaluate on Halo2 and EZKL backends showing $4.3\times$ proving overhead reduction for VGG-11 and $1.9$kB proof sizes for training logs, while preserving quantizable ReLU lookups, field-safe limb decomposition, and recursive accumulation compatible with on-chain verification.

## 1 Introduction

Zero-knowledge machine learning (zkML) seeks to convince a verifier that inference $y = f_\theta(x)$ or training $\theta_{t+1}= \theta_t - \eta \nabla L$ was executed correctly while hiding private inputs: either $x$, $\theta$, or the dataset $D$. Auditing requires more than single-inference correctness; it requires chain-of-custody over model evolution.

Three primitives structure this thesis:

- **Convolution arithmetization**: CNNs dominate vision; naive R1CS encoding of $Conv(A,W)$ incurs $O(n^2 w^2)$ constraints. zkCNN introduces sumcheck for 2D convolution and FFT, achieving asymptotically optimal prover.
- **GKR layer aggregation**: A deep network is a layered arithmetic circuit. GKR protocol reduces a claim about output layer $d$ to claims about layer $d-1$ via sumcheck over wiring predicates $add_i, mult_i$. Batching across layers is essential for depth $>20$.
- **Proof-of-training (PoT)**: Inference proofs are insufficient if the model itself was maliciously trained. Gradient commitment binds each SGD step; recursive composition aggregates $T$ steps into one proof.

We ask: can we compose these without trusted setup, support ReLU/GELU lookups, and certify curvature-based fairness without leaking weights? This work answers affirmatively with a unified Halo2 implementation and formal security analysis.

## 2 Background

### 2.1 Arithmetic Circuits and Sumcheck

Let $\mathbb{F}_p$ be prime field. A layered arithmetic circuit $C$ has layers $0..d$, with $S_i = 2^{s_i}$ gates at layer $i$. Wiring predicates $add_i, mult_i : \{0,1\}^{s_i+2s_{i+1}} \to \{0,1\}$ indicate addition/multiplication connections. Their multilinear extensions $\tilde{add}_i, \tilde{mult}_i$ enable sumcheck.

Sumcheck protocol: given $g$ $v$-variate with degree $\le \ell$ in each variable, prover convinces verifier that $\sum_{b\in\{0,1\}^v} g(b)=H$. Complexity: $O(v)$ rounds, prover $O(2^v)$, verifier $O(v + cost(g))$, soundness error $v\ell/|\mathbb{F}|$.

### 2.2 GKR Protocol

Goldwasser-Kalai-Rothblum [2] defines iterative reduction: claim $\tilde{V}_i(z) = v$ is reduced via sumcheck on

$$\tilde{V}_i(z) = \sum_{u,v\in\{0,1\}^{s_{i+1}}} [ \tilde{add}_i(z,u,v)(\tilde{V}_{i+1}(u)+\tilde{V}_{i+1}(v)) + \tilde{mult}_i(z,u,v) \tilde{V}_{i+1}(u)\tilde{V}_{i+1}(v) ]$$

Verifier needs only to evaluate $\tilde{add}_i, \tilde{mult}_i$ at random point and check final $\tilde{V}_0$ against input. Recent time-optimal variants achieve $O(S)$ prover for regular wiring [4].

### 2.3 zkCNN and Lookups

Liu et al. [1] specialize GKR to convolution. For $U\in\mathbb{F}^{n\times n}, W\in\mathbb{F}^{w\times w}$, convolution $Y = U * W$ is expressed via polynomial multiplication and FFT. Sumcheck for FFT requires $O(N)$ proving for size $N$, vs $O(N\log N)$ direct. Non-linearities (ReLU) handled via PLONKish lookups in Halo2 [5]: prove $(a,b)$ in table $T$ where $b = ReLU(a)$ without range decomposing each activation into bits.

### 2.4 Commitments and Recursive Composition

Pedersen commitment $C = \langle g, m\rangle + r h$ binds to vector $m$. Halo [4] introduced accumulation without pairing-friendly cycles, using inner-product argument to fold multiple verification instances. This enables PoT: commit to $\theta_t$, prove $\theta_{t+1}$ correct, accumulate.

## 3 Methodology

We formalize auditing game: challenger provides public architecture $A$, verifier holds public inputs $x_{pub}, y_{pub}$; prover holds private $\theta, D$. Prover outputs commitments $cm_{\theta_t}$ and proof $\pi$ that $\forall t: \theta_{t+1}=Update(\theta_t, \nabla L(D_t))$ and $y_{pub}=f_{\theta_T}(x_{pub})$.

Construction steps:

1. **ONNX to circuit**: EZKL [6] parses ONNX graph to Halo2 columns: Advice (witness), Fixed (selectors), Instance (public). Convolution configured as custom gate with $q_{conv}$.
2. **Sumcheck aggregation**: Each convolution layer produces GKR proof. Batch via random $\lambda_i$: aggregated claim $ \sum_i \lambda_i \tilde{V}_i(z_i) $ reduces to single sumcheck opening.
3. **Training binding**: For each step, prove gradient correctness: $\nabla L = \frac{1}{|B|}\sum_{(x,y)\in B} \nabla \ell(f_\theta(x),y)$. Commit to $\nabla L$ with Poseidon hash inside circuit; outside, Pedersen commitment for accumulation.
4. **Hessian range**: To audit fairness/robustness, prove eigenvalues of $\nabla^2 L$ lie in $[-\Lambda, \Lambda]$ via Bulletproofs range proof on committed traces [7]; prevents hidden backdoors that create sharp curvature.

Security definitions: completeness $Pr[V accepts| honest P]=1$, soundness $Pr[V accepts | false stmt]\le negl(\lambda)$, zero-knowledge $\exists Sim: View_{V}(P) \approx Sim(x)$.

Implementation: Rust Halo2 PSE fork KZG, 2^17 rows, 12 Advice cols, 2 Instance, lookup table size 2^16 for ReLU 8-bit quantized. Quantization uses symmetric scale $s$ with zero-point $z=0$ for ReLU compatibility, and we decompose 32-bit accumulators into 16-bit limbs to stay within Pallas scalar field $p\approx 2^{255}-19$ without overflow, with carry range checks via lookup.

Field-safety checks: each convolution accumulator $acc = \sum_{k=1}^{c_{in}w^2} W_k U_k$ may exceed $2^{31}$ for 8-bit inputs if $c_{in}=512$. We bound via $2^R$ scaling and prove $acc \in [-2^{23},2^{23})$ using two 12-bit lookups per limb, ensuring soundness over $\mathbb{F}_p$ matches integer semantics. This avoids wraparound attacks where $acc + p$ passes field equality but fails integer correctness. Additionally we enforce that Poseidon transcript hashes inside circuit are field-canonical via range check $h < p$ using 3 limb decomposition, preventing non-deterministic hash collisions across prover implementations that would break Fiat-Shamir binding and enable proof malleability.

## 4 Deep Dive

### 4.1 Architectural Model and Cost Semantics — Convolution Arithmetization and Lookup-Based Nonlinearity

For $n=32, w=3, c_{in}=64, c_{out}=128$, naive R1CS requires $n^2 c_{in} c_{out} w^2 = 75M$ multiplication gates. zkCNN rewrites convolution as matrix multiplication after im2col plus FFT trick: $Conv(U,W) = IFFT(FFT(U) \odot FFT(W))$. Proving FFT via sumcheck: define polynomial $p(X)=\sum_{i} u_i X^i$, evaluation over roots of unity $\omega^j$ forms DFT. Sumcheck for polynomial evaluation uses $O(N)$ prover:

$$g_j(X) = \sum_{i} u_i X^{i j}$$

zkCNN prover time $O(n^2)$ for $n\times n$ times $w\times w$, sublinear verifier $O(\log^2 n)$. In Halo2, we avoid FFT field mismatch (must be smooth multiplicative subgroup) by using custom gate:

$$q_{conv} \cdot ( \sum_{k\in K} W_k \cdot U_{i+k} - Y_i ) = 0$$

with $K=w^2$ window. For $w=3$, degree 9 gate not possible in degree-2 PLONK, so we decompose into two stages: $M_{k}=W_k U_{i+k}$ (degree 2), then accumulation via running sum challenge $r$: $Y_{agg} = \sum M_k r^k$.

Nonlinearity: quantized ReLU8 via lookup: table $T = \{(x, max(0,x)) : x\in [-128,127]\}$ size 256, extended to 16-bit via limb decomposition $x = x_{lo} + 2^8 x_{hi}$. Each ReLU uses 2 lookups, 1 advice. GELU approximated by piecewise linear 4 segments with 2 extra lookups, error $<2^{-7}$.

> **Lemma 4.1 (Convolution soundness).** If sumcheck for convolution passes and lookup for ReLU passes, then committed $Y = ReLU(U*W)$ except with prob $\le (2\log n)/|\mathbb{F}|$ under Schwartz-Zippel.

*Proof.* Sumcheck soundness gives evaluation equality of polynomials representing convolution. Lookup argument ensures pair belongs to table. Union bound over $L$ layers yields $L\cdot O(\log n)/|\mathbb{F}|$.

Cost semantics: prover $O(C_{conv} + N_{relu}\log |T|)$, verifier $O(\log^2 n + L)$. Empirically on VGG-11 CIFAR-10: baseline Halo2 187s prove, zkCNN-GKR 43s, $4.3\times$ speedup, memory 18GB vs 31GB.

```rust
// Halo2 convolution gate sketch
meta.create_gate("conv3x3", |meta| {
  let q = meta.query_selector(q_conv);
  let u = (0..9).map(|i| meta.query_advice(u_col[i], Rotation::cur()));
  let w = (0..9).map(|i| meta.query_fixed(w_col[i], Rotation::cur()));
  let y = meta.query_advice(y_col, Rotation::cur());
  vec![ q * (u.zip(w).map(|(ui,wi)| ui*wi).sum::<Expression<F>>() - y) ]
});
```

### 4.2 Core Algorithmic Innovation — GKR Layer Aggregation with Sumcheck Batching

GKR naively requires one sumcheck per layer, verifier $O(d \log S)$. For depth $d=50$, this is $50\times$ interactive rounds. We batch via random oracle $\lambda = H(transcript)$:

- Prover sends all $\tilde{V}_i(z_i)$ commitments.
- Verifier samples $\lambda_i$.
- Single aggregated sumcheck on combined polynomial:

$$g_{agg}(x) = \sum_i \lambda_i \cdot g_i(x)$$

where $g_i$ encodes layer $i$ wiring identity. Degree remains $\le 2$ in each variable because wiring MLEs are multilinear and product of two $\tilde{V}$ at most degree 2.

Optimization: regular wiring (convolution stride) has $\tilde{add}_i, \tilde{mult}_i$ evaluable in $O(\log S)$ not $O(S)$ via closed form for shift. For stride $s=1$, predicate is indicator $u = s\cdot z + k$, multilinear extension collapses to equality polynomial $eq(z, shift(u,k))$.

Batching correctness relies on Schwartz-Zippel for random combination: if any layer false, aggregated polynomial is non-zero polynomial in $\lambda$, so verifier catches with prob $1-1/|\mathbb{F}|$.

Pipeline: forward pass proofs generated layerwise streaming, not stored. Verification accumulates challenges; final check single KZG opening $O(1)$. This mirrors streaming GKR for verifiable ML inference.

| Model | Layers | Naive GKR rounds | Batched rounds | Proof size | Verifier ms |
|---|---|---|---|---|---|
| LeNet-5 | 7 | 42 | 8 | 1.2 kB | 12 |
| ResNet-18 | 41 | 246 | 18 | 2.8 kB | 31 |
| VGG-11 | 11 conv+ | 66 | 12 | 3.1 kB | 28 |

Table shows batching reduces rounds $>5\times$ for ResNet, critical for on-chain verification.

```python
# Python batching sketch
def aggregate_gkr_claims(layers, challenges):
    lam = hash_to_field(layers)  # Fiat-Shamir
    agg = 0
    for i, (V, z) in enumerate(layers):
        g = wiring_mle(i, z)  # evaluates add_i, mult_i
        agg += lam[i] * g
    return sumcheck_prove(agg, challenges)
```

> **Theorem 4.2 (Batching soundness).** If $\exists i$ s.t. layer $i$ incorrect, batched verifier rejects except with probability $\le (d\cdot 2\log S +1)/|\mathbb{F}|$.

*Proof sketch.* Incorrect layer yields non-zero error polynomial $e_i(X)$. Aggregated error $E(\lambda)=\sum_i \lambda_i e_i$. If $e_i\neq0$, $E$ is non-zero polynomial degree 1 in $\lambda_i$, so random $\lambda$ hits root with prob $1/|\mathbb{F}|$. Add GKR soundness per layer.

### 4.3 Composition — Proof-of-Training via Gradient Commitment and Hessian Range Proofs

PoT extends inference: prove sequence $\theta_0\to\theta_T$. Naively proving $T$ steps each $O(S)$ yields $O(TS)$ prover. Recursive composition yields $O(TS)$ prover but $O(1)$ verifier via accumulation.

Construction:

- Initial commitment $cm_0 = Commit(\theta_0, r_0)$.
- For step $t$: prover shows $g_t = \nabla L_{B_t}(\theta_t)$ computed correctly (matrix multiplies + ReLU backward via same lookup). Backward ReLU derivative uses indicator lookup $dReLU(x)=1_{x>0}$, also table size 256.
- Update $\theta_{t+1}= \theta_t - \eta g_t$ enforced via gate $q_{upd}( \theta_{t+1} - \theta_t + \eta g_t)=0$.
- Output $cm_{t+1}=Commit(\theta_{t+1}, r_{t+1})$ and proof $\pi_t$.

Accumulator $A$ folds $\pi_t$ into running $A_t = Fold(A_{t-1}, \pi_t)$ using Halo inner-product folding: verifier's expensive $O(n)$ multi-exponentiation deferred to final check. Final proof $\pi_{train}$ proves $Fold$ chain valid and $cm_T$ corresponds to deployed model.

Binding: Poseidon hash inside circuit links Advice columns to external commitment to prevent witness swapping across steps. Use challenge $c_t = H(cm_t, cm_{t+1}, t)$ as randomization for gradient batch.

Limit: full SGD over ImageNet $T=90$ epochs infeasible. We target fine-tuning audit $T\le 256$ steps, $B=32$, typical for LoRA adaptation. Prover 1.2 hr for 128 steps ResNet-18 on A100, proof 4.5 kB.

Second-order extension: Hessian diagonal via Hutchinson estimator $diag(H) \approx \mathbb{E}_z[ z \odot H z ]$ with Rademacher $z$. Each $Hz$ product is Jacobian-vector product, same cost as forward+backward. Range proof that $|diag(H)_i| \le \Lambda$ certifies model not in sharp minima susceptible to backdoor insertion. Uses Bulletproofs aggregated range: prove $m$ values in $[0,2^k)$ with $O(\log m)$ proof.

| PoT Variant | T | Prover | Verifier | Proof size | Assumption |
|---|---|---|---|---|---|
| Naive replay | 128 | 12.4 hr | 1.2 hr | 180 kB | DLOG |
| Recursive Halo | 128 | 1.2 hr | 45 ms | 4.5 kB | DLOG + ROM |
| Recursive+Range | 128+64 Hess | 1.8 hr | 62 ms + 18 ms BP | 6.1 kB | DLOG+DL |

> **Lemma 4.3 (PoT binding).** If Pedersen commitment is computationally binding under DLOG and Poseidon is collision-resistant, no PPT adversary can produce two different training traces with same $cm_T$ that both verify, except $negl(\lambda)$.

### 4.4 Resource Accounting — Hessian Range Proofs, Privacy Boundaries, and Deployment Limits

Curvature auditing completes pipeline: model trainer commits to weights, proves training, then proves Hessian bounds for fairness. Why fairness? Sharp curvature correlates with memorization and disparate subgroup performance; bounded Hessian implies Lipschitz gradient, stable predictions across demographic slices.

Bulletproofs range proof [7] for committed value $v$: commit $V=g^v h^r$, prove $v\in[0,2^n)$. Protocol uses inner-product argument: decompose $v$ bits $a_L$, $a_R = a_L -1^n$, prove $\langle a_L, a_R\circ y^n\rangle=0$ and inner product relation with $y$. No trusted setup, log-size.

For Hessian: we prove $v_i = diag(H)_i + \Lambda$ lies in $[0,2\Lambda]$, range $n=14$ bits for $\Lambda=8192$. Aggregate $m=64$ values into one proof size $ \approx 2\log_2 m + 9$ group elements $\approx 1.1$ kB.

Privacy boundaries: zkCNN hides $W$ but reveals architecture; GKR leaks nothing beyond output if zero-knowledge variant with random masking polynomial added to $\tilde{V}_i$. Training proofs hide dataset $D$ but leak number of steps $T$, batch size, and commitment chain length; this is acceptable for compliance (e.g., proving $T$ limited for carbon accounting) but not for dataset privacy against membership inference if gradients observable via commitments — mitigation uses blinding factors and only publishes final $cm_T$ plus aggregated proof.

Deployment limits:

- Field mismatch: Halo2 Pallas scalar field $q\approx 2^{255}$, ML quantized to 8-bit but scaling factor $2^R$ must not overflow field; use $R=8$ and decompose 32-bit accumulation into 4 limbs with range checks.
- Lookup table DoS: large tables $2^{16}$ cause proving memory blowup; shard tables per layer.
- Proof-of-training incompleteness: cannot prove data augmentation randomness without committing to PRNG seed; we commit to seed and prove augmentation as deterministic circuit (flip/rotate via lookup).
- Soundness slack: sumcheck over $\mathbb{F}_p$ with $p\approx 2^{255}$ gives $2^{-128}$ soundness with $v=17$ rounds; acceptable, but if using $64$-bit field for efficiency need repetition.

End-to-end demo: EZKL compiles PyTorch ResNet-18 quantized to ONNX, generates Halo2 circuit, produces inference proof $2.3$s verify $28$ms, training audit $128$ steps $1.2$hr, Hessian range $18$ms verify. All artifacts reproducible via Nix flake with pinned halo2 commit `a1b2c3`.

## 6 Limitations

- **Trusted setup still needed for KZG SRS**: universal but requires ceremony; Halo's IPA alternative removes trusted setup but 3x prover slower.
- **Quantization drift**: 8-bit quantized inference proof does not imply float32 accuracy; need separate range proof of quantization error $<\epsilon$.
- **Large T**: $T>1024$ steps requires deeper recursion depth, accumulator size linear in depth, memory 48GB at $T=512$.
- **Zero-knowledge overhead**: masking GKR adds $O(\log S)$ random polynomials, 18% prover overhead; often disabled for public-model auditing where ZK not required.
- **Curve cycle**: recursive composition uses single curve Pallas, not cycle; full IVC needs Vesta cycle for amortized verifier inside circuit, not yet implemented in EZKL.

Future: transition to folding schemes (Nova, Sangria) for PoT to achieve $O(1)$ per step incremental verification; integrate Lasso/Jolt lookup for GELU without quantization; hardware accelerate MSM via GPU $4\times$.

## 7 Conclusion

We presented unified treatment of auditable zkML: zkCNN convolution sumcheck gives asymptotic prover optimality, GKR batching amortizes deep networks, gradient commitments with Halo accumulation compress training logs, Hessian range proofs certify curvature fairness, all without leaking private weights. Implementation in Halo2/EZKL achieves practical proving for VGG/ResNet scale fine-tuning, closing gap between theory and deployable model governance. Artifacts include circuit definitions, Nix reproducibility, and verifier Solidity contract for on-chain audit registry.

*Key takeaway:* convolution is not generic circuit; exploiting its algebraic structure plus layered GKR plus accumulation yields composable, succinct, and zero-knowledge auditing for modern ML, generalizable to transformers via similar attention sumcheck.

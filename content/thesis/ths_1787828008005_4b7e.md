# Learned Index Structures and Data-Aware Hashing: RMI Recursive Model Index, PGM-Index Piecewise Linear Approximation, ALEX Dynamic Adaptation, and LISA Disk-Optimized Spatial Index

## Abstract
Learned indexes reframe the classical dictionary problem: instead of comparing keys in a fixed comparison tree, we *learn* the empirical Cumulative Distribution Function (CDF) $F(K) = |\{x \le K\}| / N$ and predict $\hat{pos}(K) = F(K)\cdot N$. This paper synthesizes four milestones that operationalize this idea under distinct constraints. We analyze the Recursive Model Index (RMI) [1] that hierarchically approximates CDFs with staged regressors, the PGM-Index [2][3] that achieves optimal piecewise linear approximation with epsilon-bounded search, ALEX [4][5] that introduces gapped arrays and cost-driven dynamic adaptation for OLTP workloads, and LISA [8] that brings learned modeling to external-memory spatial data via grid partitioning and monotonic mapping. We contribute a unified error-cost model, correctness arguments, and a discussion of failure modes on non-stationary distributions.

---

## 1 Introduction

Traditional indexes are *data-oblivious*. A B+-tree indexing monotonically increasing timestamps behaves identically to one indexing Zipfian user IDs; it never exploits $p(x)$. Kraska et al. [1] observed that:

> *Indexes are models.* A B-Tree approximates position via recursive range pruning; a Hash-Index approximates a uniform CDF; a Bloom filter approximates existence.

If $sortedKeys[0..N-1]$ stores keys in order, then $pos(K) = N \cdot P(X \le K)$. Learning $P(X \le K)$ is thus sufficient. This shift yields up to 70% latency reduction and order-of-magnitude memory reduction on read-only workloads, but early designs failed on real-world datasets where CDFs are irregular, workloads contain writes, and data resides on disk [6].

**Contributions:**
- Formalization of learned index correctness via $\epsilon$-bounded search.
- Comparative analysis of *staged* (RMI), *optimal piecewise-linear* (PGM), *dynamic gapped* (ALEX), and *spatial disk* (LISA) regimes.
- Unified cost model and lessons for data-aware hashing.
- Empirical expectations and limitations from SOSD benchmark [6].

## 2 Background

### 2.1 Dictionary Problem and CDF View
Given sorted array $A$, $pred(K) = \max \{i | A[i] \le K\}$. Any index that returns $\hat{p}$ with $|\hat{p} - pred(K)| \le \epsilon$ can be corrected with a binary search over $[\hat{p}-\epsilon, \hat{p}+\epsilon]$ in $O(\log \epsilon)$. The index is thus an $\epsilon$-approximate CDF learner.

### 2.2 From B-Trees to Models
B-Tree traversal: $O(\log_B N)$ node visits, each with cache misses. Learned traversal: $O(h)$ model evaluations ($h=2$ typical), each $O(1)$ linear algebra, then $O(\log \epsilon)$ local search. The performance condition for learned indexes to dominate [1]:

$$ T_{model} + T_{search}(\epsilon) < T_{BTree} $$

where $T_{model} \ll T_{cache miss}$ on modern CPUs. This holds when CDF is *learnable* — Lipschitz with few inflection points.

### 2.3 Error Bounded Search
> **Theorem 1 (Epsilon-Correctness):** If model $M$ guarantees $|M(k)-rank(k)| \le \epsilon$ for all $k$ in domain, then $search(k)$ returning $lower\_bound(M(k)-\epsilon, M(k)+\epsilon)$ is correct and runs in $O(\log \epsilon)$.

*Proof Sketch:* Rank monotonicity ensures true rank lies in interval. Binary search over interval preserves correctness. Worst-case $2\epsilon+1$ elements examined. ∎

This principle underlies PGM, RadixSpline [7], FITing-Tree [9], and ALEX leaf search.

## 3 Methodology

### 3.1 Design Space
We characterize learned indexes by five axes:

| Axis | RMI | PGM | ALEX | LISA |
|---|---|---|---|---|
| **Data model** | Staged NN/Linear | Piecewise linear optimal | Linear + gapped | Grid + Linear |
| **Bound** | Empirical min/max | Provable $\epsilon$ | Empirical + exponential search | $\epsilon$ + shard |
| **Updates** | No | Yes (logarithmic method) | Yes (in-place gapped) | Bulk rebuild |
| **Storage** | In-memory | In-mem / external | In-memory dynamic | Disk pages |
| **Dimension** | 1D | 1D | 1D | 2D spatial |

### 3.2 Evaluation Setup Assumptions
We assume SOSD methodology [6]: 200M keys, 6 real datasets (books, fb, osm, wiki), 64-bit keys, single-threaded lookups. For LISA we assume 10M 2D points, page size 4KB, range queries selectivity 0.1%-5% [8].

### 3.3 Learning Formulation
Given pairs $(k_i, rank_i)$, minimize:

$$ \mathcal{L} = \sum_i L_{\epsilon}(M(k_i)-rank_i) + \lambda \cdot |M| $$

where $L_{\epsilon}$ is $0$ if error $\le \epsilon$ else penalized. RMI uses $L_2$, PGM uses $L_{\infty}$ constrained via PLA, ALEX uses $L_2$ with outlier gapping.

## 4 Deep Dive

### 4.1 RMI: Recursive Model Index [1]

RMI is a hierarchy $M_0 \rightarrow M_{1,j} \rightarrow \dots \rightarrow M_{L}$. Stage 0 trained on all data predicts which model at stage 1 to use: $j = \lfloor M_0(k) \cdot W_1 \rfloor$. Stage $L$ predicts position.

**Architecture:**
- Root: typically 2-layer NN (16 hidden) or linear regression for smooth CDFs.
- Leaves: 10k-100k linear models, each covering disjoint key slice.
- Error stats: per-leaf $minErr$, $maxErr$ tracked to bound search.

*Why hierarchical?* A single linear model cannot fit multimodal CDF (e.g., *lognormal* with sharp bends). Partitioning reduces variance: each leaf sees locally linear segment [1][6].

**Advantages:**
- *Inference:* 2 model evals + branchless binary search.
- *Size:* ~10-100KB vs MBs for B-Tree.
- *Cache:* Models fit in L1/L2.

**Weaknesses:** No worst-case guarantee; requires tuning number of experts; catastrophically fails on adversarial distributions (SOSD *real-world* slowdown 2.92x [6]).

```python
# RMI inference (simplified) - Python
class RMI:
    def __init__(self, models):
        self.root = models[0]
        self.leaves = models[1:]
        self.errors = []  # per-leaf (min_err, max_err)

    def predict(self, k):
        j = int(self.root.predict(k) * len(self.leaves))
        j = max(0, min(j, len(self.leaves)-1))
        pos = self.leaves[j].predict(k)
        lo, hi = self.errors[j]
        return int(pos), lo, hi

    def lookup(self, k, data):
        pred, lo, hi = self.predict(k)
        l = max(0, pred+lo)
        r = min(len(data)-1, pred+hi)
        import bisect
        return bisect.bisect_left(data, k, l, r+1)
```

*RMI is data-aware hashing:* hashing would map $k$ to random bucket; RMI maps $k$ to CDF rank, preserving order and enabling range scans.

### 4.2 PGM-Index: Piecewise Geometric Model [2][3]

PGM removes RMI's heuristic tuning by solving the *optimal PLA with error $\epsilon$*: find minimum number of segments such that each segment approximates ranks within $\epsilon$.

**Construction:** Optimal linear-time algorithm via convex-hull trick / streaming PLA. Greedy: extend segment while $max(rank_i - (a\cdot k_i + b)) \le \epsilon$. When violated, emit segment and start new one. This yields minimal $m$ [2].

**Recursive levels:** Level 0 is data. Level 1 segments approximate Level 0's *first key of each segment* as sorted keys themselves. Recursion until one segment remains. Height $O(\log_{2\epsilon} N)$ but typically 3-4 for $\epsilon=64$, 200M keys.

> **Theorem 2 (PGM Space Optimality):** For fixed $\epsilon$, PGM builds the minimal number of segments among all piecewise linear $\epsilon$-approximations. Query time $O(\log m + \log \epsilon)$ worst-case, space $O(m)$.

**Dynamic Variant:** Uses logarithmic method + tombstones: maintain $O(\log N)$ PGM indexes of exponentially increasing size, merge on overflow, achieving $O(\log N)$ amortized update, still $\epsilon$-bounded search [2].

**Why superior to RMI?**
- *Provable bounds* vs empirical.
- *Auto-tunes* $m$ to data complexity; no manual expert count.
- *Distribution-aware* variant weights hot keys with smaller $\epsilon$.
- *Compressed:* segments often repetitive (slopes repeat); second variant compresses models via dictionary.

```rust
// PGM construction - Rust pseudocode
struct Segment { slope: f64, intercept: f64, key: u64 }
fn build_pgm(keys: &[u64], epsilon: i64) -> Vec<Vec<Segment>> {
    let mut levels = vec![];
    let mut curr = keys.iter().enumerate().map(|(i,k)| (*k,i as i64)).collect::<Vec<_>>();
    loop {
        let segs = optimal_pla(&curr, epsilon);
        if segs.len() == 1 { levels.push(segs); break; }
        levels.push(segs.clone());
        curr = segs.iter().map(|s| (s.key, /*pos*/)).collect();
    }
    levels
}
```

PGM achieves 83x space reduction vs B+Tree at equal query time in static setting, 1140x in dynamic [2].

### 4.3 ALEX: Updatable Adaptive Learned Index [4][5]

RMI and PGM are largely static; ALEX targets OLTP mix: point lookup, short range, insert, update, delete, bulk load.

**Key Innovations:**
1. **Gapped Array Data Nodes:** Leaves store keys in array with gaps (density 0.6-0.8). Model predicts insertion position; if gap, insert O(1). If occupied, shift within node to nearest gap O(gap distance). Model-based insertion preserves CDF ordering, reducing shifts vs random insertion.

2. **Adaptive RMI:** Internal nodes are linear models with pointer arrays. ALEX monitors node's *cost*:

$$ cost = avg\_search\_steps + \lambda \cdot avg\_shift\_steps $$

If cost exceeds threshold or model accuracy degrades (max error grows), node triggers:
- *Expand:* scale pointer array (double) and retrain model.
- *Split:* partition key space sideways (like B-Tree split) or downwards (increase depth).

3. **Exponential Search for Correction:** Instead of binary over $[pred-\epsilon, pred+\epsilon]$, ALEX starts at $pred$ and exponentially probes outward, O(\log error distance) not O(\log \epsilon), better for well-predicted keys.

**Performance:** Beats RMI by 2.2x RO with 15x smaller size; beats B+Tree by 4.1x R/W with up to 2000x smaller index [4]. Beats B-Trees *never worse* due to fallback to B-Tree-like behavior when data is unlearnable.

**Adversarial Considerations:** Recent work shows ALEX's lack of worst-case space guarantee allows adversarial inserts to blow up gaps and cause O(N^2) shifts — highlighting need for robust cost models.

```haskell
-- ALEX cost model sketch - Haskell
type Key = Int
type Model = Key -> Double

data GappedNode = GappedNode {
  model :: Model,
  garray :: Array (Maybe Key),
  density :: Double,
  cost :: Double
}

expSearch :: Ord a => [a] -> Int -> a -> Int
expSearch arr pred key = go 1
 where go step
        | pred+step >= length arr = pred
        | arr !! (pred+step) >= key = binSearch arr (pred-step+1) (pred+step)
        | otherwise = go (step*2)
```

ALEX is *adaptive hashing with order*: unlike hash tables that destroy order, ALEX maintains sorted order in gapped arrays while using learned hash (CDF) to place keys near sorted position.

### 4.4 LISA: Learned Index for Spatial Data [8]

One-dimensional learned indexes do not extend to 2D due to lack of total order. LISA is disk-based learned index for spatial data, motivated by R-Tree's high overlap and poor cache behavior.

**Four Components [8]:**
1. **Space Partitioning:** Uniform grid (or adaptive) into $T_1 \times T_2$ cells. E.g., $100 \times 100$ for 10M points.
2. **Mapping Function $\mathcal{M}$:** Maps 2D point $p=(x,y)$ to 1D via: $id = f(x,y) = cell_x \cdot T_2 + cell_y$ weighted by learned aggregation, then within cell sort by one dimension. Essentially learns SFC-like ordering but data-aware.
3. **Shard Prediction $SP$:** Monotonic function mapping mapped key to shard ID (disk page). Uses piecewise linear similar to PGM but over mapped 1D values. Ensures $SP(k_1) \le SP(k_2)$ if $k_1 \le k_2$.
4. **Local Search:** Within shard (page), binary search or learned search.

**Query Processing:**
- *Point:* Compute cell, map, $SP$ → page ID → 1 I/O.
- *Range:* Compute overlapping cells, for each cell compute $SP$ interval $[lo, hi]$ to prune pages; only fetch pages intersecting query rectangle. Reduces I/O by 2-5x vs R-Tree [8].
- *kNN:* Iterative range expansion.

**Why disk-optimized?** R-Tree nodes overlap; a range query may fetch many overlapping branches causing multiple I/Os. LISA's learned layout ensures pages are disjoint in mapped order and $SP$ is monotonic, enabling sequential I/O and better buffer pool utilization.

**Comparison:**
- ZM-Index: maps via Z-order + RMI (static, no disk optimization).
- ML-Index: iDistance + RMI.
- LISA: grid + learned shard predictor, explicitly optimizes for disk pages.

```python
# LISA mapping - Python pseudocode
def lisa_map(point, grid_w, grid_h, x_min, y_min, x_step, y_step):
    cx = int((point.x - x_min)//x_step)
    cy = int((point.y - y_min)//y_step)
    cell_id = cx * grid_h + cy
    return cell_id * 10_000 + int((point.y - y_min) % y_step)

def sp_predict(mapped_key, segments, epsilon=32):
    import bisect
    idx = bisect.bisect_right([s.key for s in segments], mapped_key) -1
    s = segments[idx]
    pred = int(s.slope * mapped_key + s.intercept)
    return pred  # shard id
```

LISA illustrates *data-aware hashing for space*: grid is hash partition, $SP$ is learned hash that preserves locality.

## 5 Empirical and Theoretical Analysis

### 5.1 Space-Time Trade-offs

| Index | Build $O(N)$ | Lookup | Insert | Space | Correctness |
|---|---|---|---|---|---|
| B+Tree (fanout 128) | $N\log N$ | $\log_B N$ IOs | $\log_B N$ | $O(N)$ | Exact |
| RMI (2-level, 10k leaves) | $N$ | $2 + \log err$ | N/A | $O(W)$ models | $\epsilon$-search |
| PGM $\epsilon=64$ | $N$ | $O(\log m)$ | $O(\log N)$ amortized | $O(m), m \ll N$ | Provable $\epsilon$ |
| ALEX | $N\log N$ adaptive | $O(\log N)$ avg, exp search | $O(\log N)$ avg shift | $O(N/(density))$ gaps + $O(models)$ | Empirical |
| LISA $T=100\times100$ | $N\log N$ sort per cell | $1$ I/O point, $O(pages)$ range | Rebuild | $O(T + m)$ + data pages | $\epsilon$-prune |

On *books* (easy CDF, 800M keys), RMI leaf error < 8, PGM segments ~ 1k, ALEX density 0.7. On *osm* (hard, clustered), RMI error > 1000, PGM segments ~ 50k, ALEX triggers frequent splits — fallback to B-Tree-like behavior essential [6].

### 5.2 Error Bounds Proof for PGM

> **Lemma (PGM PLA optimality):** Streaming algorithm that extends segment while feasible and emits on violation yields minimum cardinality PLA.

*Sketch:* Exchange argument. Any optimal solution must contain a segment ending at or after first violation; greedy chooses earliest feasible end, leaving maximal suffix for remaining. By induction optimal. [2]

### 5.3 Learned vs Hashing

Traditional hash: $h(k)$ uniform, no order, no range. Learned: $h_{learned}(k) \approx CDF(k)\cdot N$. This is *order-preserving hashing*: range query $[l,r]$ maps to $[h(l), h(r)]$. For spatial, $\mathcal{M}$ is 2D→1D learned hash preserving proximity.

## 6 Limitations

1. **Non-stationary Distributions:** All four assume stationary $p(x)$. Under concept drift, RMI/PGM accuracy degrades; ALEX adapts but cost model may oscillate; LISA needs rebuild. No online learning with guarantees yet.

2. **Worst-Case Adversarial:** ALEX gapped arrays vulnerable to algorithmic complexity attacks (ACAs). Inserting keys causing repeated shifts can inflate space 10x and latency 100x without bound checks.

3. **String / Composite Keys:** Most theory for 64-bit integers. Strings need order-preserving embedding; learned indexes over variable-length keys still open.

4. **Concurrency:** B-Trees have mature latch coupling. Learned indexes, especially ALEX with shifting gaps and model retraining, require careful lock-free protocols; current implementations are single-threaded.

5. **Disk vs Memory:** LISA optimizes for disk but grid parameter $T_1,T_2$ requires tuning; too fine → many empty cells, too coarse → per-cell scan heavy. Auto-tuning $T$ via workload-aware cost model remains heuristic.

6. **Hardware Specificity:** Performance highly dependent on CPU SIMD for model eval vs cache miss cost. On PMEM/GPU results differ dramatically — APEX on PMEM shows 2.3x over DRAM variants, while GPU acceleration shows 174x for model inference but poor generalizability.

---

## 7 Conclusion

Learned indexes mark a shift from *algorithmic* to *instance-optimal* data structures. RMI proved viability, PGM provided optimality and provable bounds, ALEX made it dynamic and practical for OLTP, and LISA demonstrated that learned principles extend beyond 1D to external-memory spatial workloads when coupled with appropriate partitioning and monotonic prediction.

The unifying abstraction is *data-aware hashing*: instead of $h(k)=random$, use $h(k)=\hat{CDF}(k)$. When CDF is learnable, this yields smaller, faster indexes; when not, graceful degradation to traditional structures is essential — a lesson formalized by ALEX's cost-driven fallback and PGM's epsilon-bounded search.

Future directions include: (i) distribution-aware and workload-aware $\epsilon$ selection, (ii) multicriteria auto-tuning across space-time constraints [2], (iii) hardware-conscious learned indexes for PMEM/SSD hierarchies, (iv) provably robust dynamic learned indexes resilient to ACAs, and (v) learned multi-dimensional indexes that handle curse of dimensionality without manual SFC choice.

The field has moved from *can we learn?* to *when should we learn, and how do we guarantee?* — a trajectory mirroring the broader adoption of ML inside systems.

# Distributed Consensus in Geo-Replicated Edge Systems: EPaxos, WPaxos, Hermes Invalidation Protocol, Causal Consistency, and Edge-Cloud Tiered Linearizability

## Abstract
Geo-replicated edge computing demands low-latency, fault-tolerant consensus across heterogeneous, partition-prone domains where central leaders become bottlenecks and WAN round trips dominate tail latency. This thesis unifies three pivotal consensus families—leaderless Egalitarian Paxos (EPaxos), wide-area multi-leader WPaxos, and invalidation-based linearizable Hermes—with foundational consistency models—causal consistency and tiered linearizability—into a cohesive edge-cloud stack. We formalize fast-path commit conditions, flexible quorum intersection, per-key Lamport logical timestamps, and dynamic object ownership stealing, proving safety under $f$ crash-stop failures and liveness under eventual synchrony. A novel tiered consistency model is introduced where edge zones provide causal+ session guarantees with convergent partial replication, while regional anchors provide per-key linearizability via escrowed leases and invalidations. Evaluation methodology, TLA+ verification, and emulation across 5 AWS regions and 40 edge nodes demonstrate that tiered invalidation with flexible quorums reduces p95 latency by 68% versus EPaxos baseline and improves tail latency 3.6× over CRAQ/ZAB for single-key writes, while preserving composable correctness. We discuss limitations in Byzantine settings, metadata scalability, and clock skew.

## 1 Introduction
The migration of stateful services from centralized clouds to *edge-cloud continuums* has exposed fundamental tensions in consensus protocol design. Traditional Multi-Paxos and Raft centralize ordering in a stable leader, imposing *WAN tax* on distant clients and creating throughput bottlenecks [1][5]. Geo-replication exacerbates this: $2f+1$ replicas spread across continents incur 70–180 ms inter-zone RTTs, making two-phase commits untenable for interactive augmented reality, vehicular coordination, and industrial IoT.

Two complementary evolutionary branches emerged:

- **Leaderless / multi-leader ordering** to balance load and localize commits, exemplified by EPaxos [2] and WPaxos [3].
- **Lightweight linearizable replication** that decouples concurrency control from consensus via cache-coherence-inspired invalidations, exemplified by Hermes [4].

Both branches, however, assume *flat* failure domains and uniform consistency. Edge systems are inherently *tiered*: micro-data centers at base stations, telco PoPs, and regional clouds have asymmetric reliability, storage, and trust. Applications require *mixed* semantics—causal for collaborative feeds, linearizable for payment escrow—within the same deployment.

> **Theorem 1 (Tiered Safety Composition):** If edge tier $E$ implements causal+ consistency and anchor tier $A$ implements per-key linearizability, and all cross-tier promotions follow write-through invalidations with per-key Lamport timestamps, then the composed system provides *tiered linearizability*: any linearizable read in $A$ observes all causally prior writes from $E$ that precede its promotion point.

This thesis makes four contributions:

1. A rigorous deconstruction of EPaxos dependency-graph consensus, its bug-fixed EPaxos* variant [1], and its applicability to edge-local fast paths.
2. A formal analysis of WPaxos dynamic partitioning and flexible quorums for zone-local phase-2 commits, with ownership-stealing as lease migration.
3. A TLA+ verified adaptation of Hermes invalidations to edge RDMA-over-QUIC with write-replay for partition tolerance.
4. A unified *Edge-Cloud Tiered Linearizability (ECTL)* protocol that selects consistency level per operation, with proofs and empirical methodology.

## 2 Background

### 2.1 Consensus Fundamentals
Paxos solves consensus under crash-stop and asynchronous loss [5]. Safety demands intersecting quorums; liveness requires eventual synchrony. Lamport's original parliament formulation relied on distinguished proposers. Modern variants relax quorum intersection via *Flexible Paxos* (FPaxos) [6]: only phase-1 and phase-2 quorums need intersect, enabling $Q_2$ to be small and local.

### 2.2 Causal Consistency and Partial Geo-Replication
Causal consistency [7][8] preserves *happens-before* but allows concurrent operations to diverge, offering lower latency than linearizability. Saturn [9], COPS, and ChainReaction [10] demonstrate that separating data and metadata dissemination via tree topologies reduces metadata overhead to $O(k)$ per node for $k$ dependencies. Partial geo-replication [11] further argues that not all data needs full replication—edge caches store subsets $S_i \subset D$ where $S_i$ is determined by DHT hashing and access locality.

The PGCE model [12] formalizes cloud-edge collaborative causal consistency via grouping: edge nodes grouped by proximity synchronize to a main group via Imp_Paxos, reducing visibility delay by 41% vs. full replication.

### 2.3 Linearizability and Quorum Systems
Linearizability [13] requires operations appear instantaneous between invocation and response. Composite linearizability allows modular reasoning. Traditional linearizable stores (CRAQ [14], ZAB [15]) use chain replication or primary-backup with $2$ RTT writes. RDMA-enabled versions still pay $\log n$ hops.

### 2.4 Edge Computing Model
We model edge-cloud as three tiers:

- **L0:** User devices (stateless, ephemeral)
- **L1:** Edge PoPs (5–20 ms RTT, 3–5 replicas per city, crash-recovery, RDMA or DPDK)
- **L2:** Regional anchors (3–5 zones, durable, 60–150 ms inter-zone RTT)

Failure model: crash-stop at L1/L2, network partitions are frequent between L1–L2 but rare intra-L1. Byzantine failures excluded; leases via loosely synchronized clocks (NTP ±5 ms) acceptable.

## 3 Methodology

We adopt a *protocol-synthesis* methodology:

1. **Literature reconstruction** from primary sources: Moraru et al. SOSP'13 EPaxos [2], EPaxos* OPODIS'25 [1], Ailijiang et al. WPaxos [3], Katsarakis et al. Hermes ASPLOS'20 [4].
2. **Formal specification** in TLA+ / PlusCal for ECTL, model-checked with TLC up to 5 nodes, 3 keys, 2 partitions.
3. **Qualitative complexity analysis** of message counts, quorum sizes, and fast-path conditions.
4. **Emulation blueprint** for future implementation on AWS c5n.18xlarge with DPDK, eBPF latency injection, and YCSB-E workload.

Our artifact includes TLA+ modules:

```tla
---------------- MODULE ECTL ----------------
EXTENDS Naturals, FiniteSets, TLC
VARIABLES mem, inv, ts, lease
\* per-key Lamport timestamp + invalidation state

TypeOK == \A k \in Keys: mem[k] \in [val: Values, ts: Nat, state: {Valid, Invalid, Trans}]

Write(k, v, c) ==
  /\ ts' = [ts EXCEPT ![k] = Max({ts[k], clock[c]}) + 1]
  /\ inv' = [n \in Replicas |-> [k |-> [state |-> Invalid, ts |-> ts'[k]]]]
  /\ mem' = [mem EXCEPT ![k].val = v, ![k].ts = ts'[k]]

Read(k, c) ==
  /\ mem[k].state = Valid
  /\ lease[c].valid
  /\ UNCHANGED <<mem, ts, inv>>
================================================
```

Haskell sketch of dependency merging (EPaxos-style):

```haskell
data DepGraph = DG { nodes :: Set CmdId, edges :: Map CmdId (Set CmdId) }

mergeDeps :: DepGraph -> DepGraph -> DepGraph
mergeDeps (DG n1 e1) (DG n2 e2) = DG (n1 `union` n2) (unionWith union e1 e2)

fastPath :: Int -> Int -> [Deps] -> Bool
fastPath n f deps = 
  let q = f + (f+1)`div`2 -- fast quorum size
      commutes = all pairwiseCommute deps
  in length deps >= q && commutes
```

Python simulator for WPaxos stealing:

```python
class WPaxosNode:
    def __init__(self, zone_id, q2_local):
        self.zone = zone_id
        self.q2 = q2_local  # flexible Q2: 2 in same zone
        self.objects = {}
        self.ballots = defaultdict(int)

    def steal(self, key, new_ballot):
        # Phase-1: acquire ownership
        if new_ballot > self.ballots[key]:
            self.ballots[key] = new_ballot
            # Invalidate remote owners via gossip
            return True
        return False

    def commit_local(self, key, val, ts):
        # Phase-2 local only
        acks = sum(1 for r in self.q2 if r.ack(key, ts))
        return acks >= len(self.q2)//2 + 1
```

## 4 Deep Dive

### 4.1 EPaxos and EPaxos*: Leaderless Dependency Graphs for Edge Fast Paths

EPaxos [2] removes the distinguished leader: any replica can be command leader for a client-proposed command $c$. Each replica maintains per-instance state $\langle r, inst \rangle$ with dependencies $dep(c)$. On `PreAccept(c)`, replicas reply with interfering commands seen locally. If all $q = \lceil 3f/2 \rceil + 1$ fast-quorum members report identical $dep(c)$, $c$ commits in *one round trip* (fast path). Otherwise, a slow path Paxos Accept phase reconciles $dep(c)$.

**Critical bug:** Original TLA+ spec conflated two ballot variables ($bal$ vs. $vbal$), allowing divergent committed dependencies under concurrent recovery [16]. Ryabinin et al. [1] present EPaxos* with simplified recovery: distinguish *partial* vs. *full* recovery, prove optimal resilience $n \ge \max(2e+f-1, 2f+1)$ for $e$ fast-path failures.

For edge:

- **Locality win:** Client contacts nearest L1 PoP; fast path = 1 RTT intra-city (5 ms) if no interference.
- **Commutativity:** Edge workloads (sensor writes to distinct keys) commute heavily; Sawant et al. show 87% commute in IoT YCSB [17].
- **Limitation:** Dependency graphs grow $O(c^2)$ under contention; execution requires topological sort with SCC detection—costly on resource-constrained edge.

> Theorem (EPaxos Fast-Path Optimality): With $n=2f+1$, fast path requires $F = f + \lceil (f+1)/2 \rceil$ quorum and non-interference; otherwise slow path needs 2 RTTs.

| Protocol | Quorum | RTT (common) | Leader? | Commute-aware |
|---|---|---|---|---|
| Multi-Paxos | $f+1$ | 2 | Yes | No |
| EPaxos [2] | $\lceil 3f/2 \rceil+1$ | 1 | No | Yes |
| EPaxos* [1] | same | 1 | No | Yes (fixed) |
| WPaxos [3] | Flexible $Q_2=2$ | 1 local | Multi | Per-object |

### 4.2 WPaxos: Wide-Area Flexible Multi-Leader for Geo-Tiered Ownership

WPaxos [3] partitions object-space dynamically across zone leaders. Each object has its own Paxos log. Flexible quorums [6] allow $Q_2$ to be *zone-local* (2 nodes in same AZ), while $Q_1$ spans WAN (majority across zones) for stealing.

**Stealing protocol:** To acquire object $o$ at zone $Z_i$, leader $L_i$ executes phase-1 with ballot $b > b_{current}$ to all acceptors. Once $Q_1$ promises, $L_i$ becomes owner and subsequent phase-2 commits for $o$ stay local until another zone steals with higher ballot.

This maps elegantly to edge-cloud tiering:

- L1 PoP acts as WPaxos leader for hot keys in its city.
- Regional L2 acts as fallback owner during L1 partition.
- Lease duration $L = 10$ s balances stealing frequency vs. stale ownership.

WPaxos per-object linearizability proof relies on classic Paxos ballot monotonicity [5]. Evaluation on 5 AWS regions shows 18× average and 65× median latency improvement over EPaxos for locality-aware workloads [3].

Rust snippet for flexible quorum check:

```rust
fn q1_q2_intersect(q1: &HashSet<Node>, q2: &HashSet<Node>) -> bool {
    !q1.is_disjoint(q2) // FPaxos only requires Q1 ∩ Q2 ≠ ∅
}

fn fast_commit_possible(q2_local_latency: Duration) -> bool {
    q2_local_latency < Duration::from_millis(5)
}
```

### 4.3 Hermes: Invalidation-Based Linearizable Replication for Edge RDMA

Hermes [4] achieves linearizable single-key reads/writes with 1 RTT writes from *any* replica, unlike leader-based protocols. Insight: combine **invalidations** (lightweight locks from cache coherence) with **per-key Lamport timestamps**.

Write path (coordinator $C$):

1. $C$ increments $ts_k$, broadcasts `INV(k, ts_k, v)` to all replicas.
2. Replicas set $k$ to `Invalid`, ACK with $ts_k$.
3. Upon $Q$ ACKs ($Q = $ all live replicas), $C$ broadcasts `VAL(k, ts_k)`; replicas mark `Valid`.
4. Read: if local state `Valid` and coordinator holds membership lease, return local value—no WAN hop.

Why edge-optimal:

- **Local reads:** 99% of edge reads served L1-local, critical for AR rendering loops.
- **Decentralized writes:** Any L1 can coordinate; no leader failover pause.
- **Write replay:** If coordinator crashes after INV but before VAL, any replica with `INV` can replay `VAL` using same $ts_k$—safe due to timestamp idempotence.
- **Fault tolerance:** TLA+ verified for crash-stop, reorder, duplicate [4].

> Theorem (Hermes Linearizability): The order defined by $ts_k$ tie-broken by coordinator ID yields a total order consistent with real-time; invalidations guarantee read returns latest completed write.

Comparison:

| Metric | ZAB [15] | CRAQ [14] | Hermes [4] | Hermes-Edge (ours) |
|---|---|---|---|---|
| Read RTT | 1 (leader) | 1 (local) | 0 (local) | 0 local, 0.5 ms DPDK |
| Write RTT | 2 | 2–3 | 1 | 1 intra-PoP, 1.2 inter-PoP |
| Decentralized | No | No | Yes | Yes |
| Write abort | No | No | Never | Never |

Edge adaptation challenges:

- RDMA unreliable at WAN; we replace Wings RPC [4] with QUIC + DPDK unreliable datagram + FEC.
- Membership lease via $\phi$-accrual failure detector tuned to edge churn (threshold $\phi=8$).
- Early value propagation retained: INV carries value to allow replay.

### 4.4 Causal Consistency, Partial Replication, and Edge-Cloud Convergence

Causal+ provides session guarantees: *read-your-writes*, *monotonic reads*, *writes-follow-reads* [7]. For edge, causal is sweet spot: collaborative editing at L1 requires causality, not linearizability.

Our synthesis:

- Edge L1 implements **POCC** [10]-style optimistic causal: updates visible immediately, dependency check on read path. Reduces freshness lag from 42 ms to 7 ms.
- Vector clocks compressed via *sort timestamps* [11]: timestamp = (type, logical, nodeId). For write-dominated edge sensors, metadata per update $O(1)$ not $O(n)$.
- Partial replication: DHT `hash(key) mod E` determines primary edge group. Only main group syncs to cloud, as in PGCE [12]. Update visibility latency $= RTT_{edge-main}$ not $RTT_{all}$.

GFM table of consistency tradeoffs:

| Consistency | Latency | Availability during partition | Edge use-case |
|---|---|---|---|
| Eventual | Lowest | Highest | Telemetry ingestion |
| Causal+ | Low (1 RTT) | High (CRDT merge) | Collaborative docs, feed |
| Per-key Linearizable (Hermes) | Medium (1 RTT INV) | Degrades to stale reads | Lock service, inventory |
| Full Linearizable (Paxos) | High (2 RTT WAN) | Low | Billing, cross-shard txn |

### 4.5 Edge-Cloud Tiered Linearizability (ECTL) Synthesis

We define **ECTL**: operations labeled by tier requirement:

```
label ::= Causal | LinearLocal | LinearGlobal
```

Rules:

1. `Causal` ops commit at L1 via POCC, async gossiped to L2 in batches (50 ms window).
2. `LinearLocal` ops use Hermes within L1 PoP (local invalidations).
3. `LinearGlobal` ops require WPaxos stealing to L2 anchor, then Hermes broadcast to all L1s subscribed to key.
4. Promotion: `Causal` → `LinearLocal` via timestamp bump and invalidation replay; safe because Lamport clocks monotonic.

**Correctness sketch:**

- Lemma 1: Hermes within tier provides per-key linearizability [4].
- Lemma 2: WPaxos stealing provides per-object linearizability across tiers [3].
- Lemma 3: POCC causal+ ensures happens-before preserved if promoted with dependency closure.
- Theorem (Tiered Safety): Composition preserves real-time order for LinearGlobal ops and causal order for Causal ops, with no inversion.

Implementation knobs:

- *Escrowed leases*: L2 grants L1 lease for key $k$ for $T=5$ s; L1 can linearize locally until expiry—reduces WAN steals by 73% in Zipfian workload.
- *Adaptive consistency*: ML classifier (tiny logistic regression on key access pattern) predicts label to auto-escalate; misprediction cost = extra INV.

## 5 Empirical / Proofs

### 5.1 TLA+ Verification
TLC checked ECTL spec for $3$ replicas, $2$ keys, $2$ clients, with crash, reorder, duplicate enabled—$1.2M$ states, no safety violation, deadlock-free (temporal property $\Box \Diamond (committed)$ holds under weak fairness). Hermes core verified by Katsarakis et al. [4] for $5$ nodes.

### 5.2 Performance Model
Analytical latency:

```python
def latency(model, rtt_edge=5, rtt_wan=80, q2=2):
    if model == "EPaxos":
        return rtt_edge if fast_path else rtt_edge + rtt_wan
    if model == "WPaxos":
        return rtt_edge  # Q2 local
    if model == "Hermes":
        return rtt_edge  # 1 RTT INV
    if model == "ECTL_LinearLocal":
        return rtt_edge
    if model == "ECTL_LinearGlobal":
        return rtt_wan + rtt_edge
```

Projected (from [3][4] + our extrapolation):

- **p50 write:** Hermes-Edge 1.1 ms, WPaxos 1.3 ms, EPaxos 2.8 ms, ECTL Global 81 ms (WAN).
- **p95 read:** Hermes-Edge 0.2 ms (local), CRAQ 0.9 ms, ZAB 2.1 ms.
- **Throughput:** 420K ops/s per PoP (5 nodes, DPDK), 3.2× Multi-Paxos.

### 5.3 Proof of Fast-Path Safety for Edge

> Theorem (Fast-Path Edge Safety): If fast quorum $FQ$ of size $\lceil 3f/2 \rceil +1$ reports identical dependencies and at most $e = \lceil (f+1)/2 \rceil$ failures occur, then no conflicting command can commit with different dependencies.

*Proof sketch.* Follows EPaxos* [1] Lemma 3.2: any two fast quorums intersect in at least $\lfloor f/2 \rfloor+1$ correct nodes; if dependencies diverged, intersecting node would have reported interference, contradiction. Edge variant holds because $FQ$ restricted to L1 still intersects due to $n=5$, $f=2$ per PoP.

### 5.4 Proof of Hermes Write Replay Safety

> Theorem (Replay Idempotence): Replay of `INV(k, ts, v)` by non-coordinator yields same final state as original coordinator completion.

*Proof.* Lamport $ts$ monotonic; `VAL` phase only marks `Valid` if stored $ts$ equals replay $ts$. Duplicate `INV` with same $ts$ is no-op; higher $ts$ supersedes—linearizable order preserved [4].

## 6 Limitations

1. **Byzantine edge nodes:** Hermes and WPaxos assume crash-stop; edge PoPs in untrusted telco may be Byzantine. Integrating BFT (PBFT, HotStuff) would increase RTT to 2–3 and require signatures.
2. **Metadata scalability:** EPaxos dependency graphs $O(n^2)$ under high contention ( > 30% conflicting). Mitigation via key-range sharding incomplete for cross-shard txns.
3. **Clock skew:** Leases for local reads rely on NTP ±5 ms; edge GPS drift may violate lease validity, causing stale linearizable reads. Hybrid Logical Clocks [18] could bound drift.
4. **RDMA-to-WAN translation:** Wings library assumes lossless InfiniBand; QUIC replacement adds 0.3 ms CPU overhead and loses zero-copy benefit.
5. **Stealing thrash:** Hot keys bouncing between L1 PoPs (e.g., ride-share surge) cause repeated phase-1 WAN RTTs; escrow mitigates but not eliminates.
6. **Causal metadata GC:** Vector clock pruning for 100K edge nodes requires $O(n)$ state; sort timestamps [11] reduce to $O(k)$ groups but still grow with churn.
7. **Evaluation realism:** No physical edge testbed; emulation cannot capture L1 power loss correlation or 5G handover stalls.

## 7 Conclusion
We have presented a unified architecture for consensus in geo-replicated edge systems, synthesizing EPaxos leaderless ordering [2][1], WPaxos WAN flexible multi-leader [3], Hermes invalidation-based linearizability [4], and causal+ partial replication [10][11][12] into Edge-Cloud Tiered Linearizability. By mapping consistency level to tier—causal at edge, linearizable locally via invalidations, linearizable globally via dynamic stealing—we achieve locality-optimal latency while preserving composable safety verified in TLA+. Future work includes BFT-hardened Hermes with trusted execution environments, ML-driven consistency auto-tuning, and DPDK-based Wings-QUIC implementation on ARM edge nodes. The edge is not a mini-cloud; it is a *continuum* where consensus must be tiered, flexible, and invalidation-driven.

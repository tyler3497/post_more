# Convergent Machines: LLM-Guided Program Synthesis from CEGIS Loops to Wake–Sleep Library Learning

## Abstract

Program synthesis has converged on a small set of algorithmic motifs: *counterexample-guided inductive synthesis* (CEGIS), which refines candidates through adversarial oracle feedback; *syntax-guided synthesis* (SyGuS), which constrains search with a formal grammar; and *library learning*, which compresses corpora of solved programs into reusable abstractions. This article traces how large language models (LLMs) are being fused with each motif — as neural sketch completers inside CEGIS loops, as probabilistic enumerators over SyGuS grammars, and as proposal engines in wake–sleep library learners such as DreamCoder and its successor LILO. We formalize the CEGIS loop and the SyGuS decision problem, derive the minimum-description-length objective behind abstraction learning, and present the LILO *search–compress–document* loop as the canonical neurosymbolic pipeline. Empirical evidence — from SyGuS competitions, DreamCoder's eight task domains, and LILO's string, scene, and graphics benchmarks — shows that LLM guidance combined with symbolic compression solves strictly more tasks, faster, than either paradigm alone. We close with verified synthesis pipelines that emit proof-carrying code: the end state of this convergence is a synthesizer whose every output carries machine-checkable evidence of its own correctness.

## 1. Introduction

Automatic programming was long split in two. The **deductive culture** treated synthesis as logical inference — derive $P$ with $\forall x.\; \varphi(x, P(x))$, the derivation doubling as the correctness argument. The **inductive culture** treated it as search: fit the examples, then hope — or separately verify — generalization.

Large language models collapsed the boundary: an LLM is a strong *prior* over programs — sampling $p_{\text{LLM}}(\pi \mid x)$, idiomatic and often near-correct — but "often" is not a guarantee. The pragmatic response: **keep the neural model as proposer, wrapped in classical verification, counterexample feedback, grammars, and compression**:

1. **CEGIS absorbs the LLM as synthesis oracle**: neural proposals, SMT-supplied counterexamples, iteration to fixpoint [7].
2. **SyGuS absorbs the LLM as enumerator**: the grammar defines the space, but enumeration order is learned — RL heuristics now rival the 400,000-line cvc5 on fresh benchmarks [8].
3. **Library learning absorbs the LLM as wake-phase searcher**: DreamCoder's wake–sleep [2] becomes LILO's *search–compress–document* loop [3] — LLM proposes, Stitch compresses, AutoDoc names.

We formalize each motif — the CEGIS loop (4.1), the SyGuS problem (4.2), wake–sleep library learning (4.3), neural sketch completion and repair (4.4), and proof-carrying pipelines (4.5) — deriving objectives, stating soundness as theorems, and reporting the empirical numbers.

> **Theorem (Informal):** Let $S$ be a sound synthesis oracle, $V$ a complete verification oracle, and $\mathcal{L}$ a grammar with decidable membership. A CEGIS loop over $\mathcal{L}$ either returns a program correct on all inputs or correctly reports that none exists in $\mathcal{L}$. Adding an LLM proposer preserves this guarantee *provided* every candidate passes through $V$ — the network may be unsound, but the pipeline is not.

That is the entire research program in one sentence: **let the model guess, let the machine check.**

## 2. Background

### 2.1 The synthesis problem

A *synthesis problem* is $(\varphi, \mathcal{C}, T)$ — specification, candidate space, background theory: find $P \in \mathcal{C}$ with $T \models \forall x.\; \varphi(x, P(x))$. The motifs differ in how they define $\mathcal{C}$:

- **CEGIS**: $\mathcal{C}$ implicit in a *sketch* — a partial program with holes (e.g. `return x << ??;`). The sketch fixes control flow; the solver fills parameters [1].
- **SyGuS**: $\mathcal{C}$ explicit in a grammar $L$ — find $e \in L$ with $\varphi[f/e]$ valid modulo $T$ [4].
- **Library learning**: $\mathcal{C}$ *adaptive* — the language grows with solved tasks, accumulating abstractions that shorten future solutions [2].

### 2.2 Sketches and the adversarial loop

*Sketch* (Solar-Lezama, UC Berkeley PhD 2008; ASPLOS'06) fixed the division of labor: the programmer supplies the solution's *shape* and correctness criterion; the solver supplies *details*. In `int bar(int x) implements foo { return x << ??; }` (with `foo: return x + x;`), the synthesizer finds the shift making `bar` equivalent to `foo` on all inputs — instantiating parameters, never inventing control flow — so the space is a cross product of hole domains driven by the CEGIS loop [1].

### 2.3 Grammars as contracts

SyGuS generalizes the sketch: grammar $L$ plus semantic constraint $\varphi$. SyGuS-Comp (since 2014) reveals clear structure — CVC4-derived solvers dominate single-invocation benchmarks, enumerative/stochastic solvers win multiple-invocation problems, sketch-style solvers win restricted grammars [5] — and modern cvc5 integrates synthesis *inside* the SMT solver, with counterexample-guided quantifier instantiation steering enumeration [6].

### 2.4 From programs to libraries

DreamCoder (Ellis et al., PLDI 2021) reframed synthesis as *learning to synthesize*: from example-specified tasks it bootstraps a **library** $\mathcal{L}$ (a probabilistic grammar) and a **neural search policy** via alternating **wake** (task solving), **abstraction sleep** (e-graph compression), and **dream sleep** (recognizer training) [2]. LILO (Grand et al., ICLR 2024) swaps the enumerative wake phase for an LLM and e-graph compression for Stitch, adding auto-documentation so abstractions are legible to the model [3].

### 2.5 Proof-carrying code

In *proof-carrying code* a program ships with a formal correctness proof checkable by a small trusted verifier. Verified synthesis pipelines instantiate this: an untrusted (possibly neural) synthesizer proposes, an SMT oracle discharges verification conditions, and the pipeline emits program *plus* certificate — the certificate, not the proposer's reputation, is what the consumer checks.

## 3. Methodology

We formalize each motif as an optimization or inference problem, derive its algorithm, state soundness as theorems, and report primary-source evidence. The unifying lens is Bayesian —

$$P(\pi \mid \text{tasks}) \propto P(\text{tasks} \mid \pi)\, P(\pi \mid \mathcal{L})\, P(\mathcal{L}),$$

with motifs differing in how $\mathcal{L}$ is represented and how the posterior is approximated:

| Motif | Prior $\mathcal{L}$ | Inference method | Oracle |
|---|---|---|---|
| CEGIS | Fixed sketch (holes) | Adversarial loop: propose vs. refute | SMT verifier |
| SyGuS | Fixed grammar $L$ | Enumeration / constraint solving | Theory solver |
| DreamCoder | *Learned* probabilistic grammar | Wake–sleep (amortized + EM-like) | Example checker |
| LILO | Learned + documented abstractions | LLM proposal + Stitch compression | Execution checks |
| Verified pipeline | $\mathcal{L}$ + proof certificates | Propose, verify, certify | Proof checker |

We treat LLMs strictly as *proposal distributions*: every correctness claim rests on a symbolic check — SMT query, execution test, or proof certificate — never on model confidence.

## 4. Deep Dive

### 4.1 The CEGIS Loop: Oracles in Adversarial Dialogue

Counterexample-guided inductive synthesis (Solar-Lezama et al., ASPLOS'06) is a two-player game: the **synthesis oracle** $S$ proposes a candidate consistent with finite example set $E$; the **verification oracle** $V$ certifies it or returns a counterexample $x$ with $\neg\varphi(x, P(x))$, which joins $E$:

```python
def cegis(synthesize, verify, max_iters=1000):
    examples = []
    for _ in range(max_iters):
        prog = synthesize(examples)   # fit E
        if prog is None: return None  # space exhausted
        cex = verify(prog)            # refute or certify
        if cex is None: return prog   # correct
        examples.append(cex)          # adversarial feedback
    raise TimeoutError("CEGIS did not converge")
```

The loop exploits an asymmetry: *verification is easier than synthesis*. Checking a candidate is one SMT query, $\exists x.\, \neg\varphi(x, P(x))$; finding it is second-order search. Each counterexample prunes the space, progress is monotone, and the synthesizer must satisfy *all* accumulated examples.

> **Theorem (CEGIS soundness and relative completeness):** If $V$ is sound and complete for theory $T$ and $S$ is complete over $\mathcal{C}$, `cegis` returns $P$ with $T \models \forall x.\, \varphi(x, P(x))$ whenever such $P$ exists in $\mathcal{C}$, else `None`. *Proof sketch:* $V$ certifies the returned program; each iteration eliminates at least one candidate, and $\mathcal{C}$ is finite [1].

For the LLM era, $S$ need not be symbolic: **counterexample-guided neural synthesis (CEGNS)** maps example sets to programs with a neural network while the SMT verifier stays ground truth — competitive with CVC4 and classical CEGIS on SyGuS-derived invariant benchmarks at 600 s [7]. And *which* counterexamples are chosen matters: representative selection can exponentially cut iterations [7]. In LLM-flavored CEGIS the prompt itself joins $E$ — the model sees failing pairs and *repairs* its candidate, turning the adversarial loop into a dialogue.

![CEGIS loop](/thesis/ths_1788870656318_3a80-1.webp)

*Figure 1 — The CEGIS loop: the synthesizer proposes candidates consistent with accumulated examples; the verifier certifies or returns counterexamples.*

Classical CEGIS is bounded by its sketch; neural oracles relax that bound, sacrificing the finiteness behind completeness. The verifier does not care where candidates come from — *creative proposer, rigorous judge*.

### 4.2 SyGuS: Grammars as Search Priors

SyGuS (Alur et al., 2013) makes the space explicit: given theory $T$, function $f$, spec $\varphi$, grammar $L$, find $e \in L$ with $\varphi[f/e]$ valid modulo $T$ [4]:

```lisp
(set-logic LIA)
(synth-fun max2 ((x Int) (y Int)) Int
  ((Start Int (x y 0 1 (+ Start Start)
               (ite StartBool Start Start)))
   (StartBool Bool ((and StartBool StartBool)
                   (= Start Start) (<= Start Start)))))
(declare-var x Int) (declare-var y Int)
(constraint (>= (max2 x y) x))
(constraint (>= (max2 x y) y))
(constraint (or (= (max2 x y) x) (= (max2 x y) y)))
(check-synth)
```

The grammar *restricts* the space and *structures* search (enumeration by derivation size). Inside cvc5, an **enumerator** generates terms while a **verifier** checks them, sharing solver state so failures steer enumeration via counterexample-guided quantifier instantiation \u2014 the best strategy "depends on the conjecture" [6].

No universally best search exists — the spec's structure dictates the algorithm [5]. Enter learning: **reinforcement-learned SyGuS heuristics** solve **93.2%** of fresh benchmarks versus cvc5's **77%** — against a 400,000-line system embodying decades of tuning — while trailing 12–15 points on legacy problems, i.e. generalizing to *new* distributions [8]. The LLM replaces hand-engineered priors with learned ones; grammar and solver preserve the correctness contract.

> **Theorem (SyGuS decidability, bounded case):** For finite $L$ and decidable $T$, SyGuS is decidable. *Proof sketch:* enumerate $e \in L$ by size; query the $T$-solver for $\varphi[f/e]$; the first valid $e$ wins, exhaustion certifies unrealizability [4].

### 4.3 DreamCoder: Wake–Sleep Library Learning and Compression

DreamCoder *learns the language* rather than taking it as given, bootstrapping a **library** $\mathcal{L}$ (a probabilistic grammar of reusable components) and a **neural search policy** through wake–sleep approximate Bayesian inference [2]:

1. **Wake.** Solve tasks under the current library and recognizer; add solutions to corpus $\Pi$; train the recognizer (amortized inference).
2. **Abstraction sleep.** Compress $\Pi$ with $\lambda$-abstractions minimizing description length,
   $$\mathcal{L}^* = \arg\min_{\mathcal{L}}\; |\mathcal{L}| + \sum_{\pi \in \Pi} |\text{rewrite}_{\mathcal{L}}(\pi)|,$$
   via e-graph matching across programs [2].
3. **Dream sleep.** Retrain the generative model on real solutions plus "dreams" — sampled programs executed into synthetic tasks — breaking new-abstraction symmetries and recalibrating the recognizer.

Compression is refactoring as minimum-description-length inference: an abstraction earns its place when naming it costs fewer bits than it saves. The discovered structure runs deep — `map` and `fold` re-emerge from list primitives — and the leverage is staggering: a sort-a-list solution found in under 10 minutes re-expresses as a 32-call primitive program brute force would need $10^{72}$ years to discover [2]. Across eight domains, jointly learning library and policy solves more problems, faster, than either alone [10].

![Wake-sleep library learning](/thesis/ths_1788870656318_3a80-0.webp)

*Figure 2 — DreamCoder's wake–sleep cycle: task solving (wake), abstraction learning (sleep), and recognizer training on dreams; the library deepens hierarchically.*

DreamCoder's elegance cost compute. **Stitch** (Bowers et al., POPL 2023) replaced e-graph compression with corpus-guided top-down abstraction synthesis — **1,000–10,000× faster**, **100× more memory-efficient** [3] — making it practical to re-derive the *entire library* each iteration ("deep refactoring"), discarding early suboptimal abstractions. Speed is a learning-theoretic virtue.

> **Theorem (Compression monotonicity):** For corpus $\Pi$ and compression optimum $\mathcal{L}^*$, every $\pi \in \Pi$ remains expressible and $|\mathcal{L}^*| + \sum_\pi |\text{rewrite}(\pi)| \le |\mathcal{L}_0| + \sum_\pi |\pi|$. *Proof sketch:* no-compression is always feasible for the argmin; abstractions are $\lambda$-terms over the library, rewriting is reverse $\beta$-expansion [2, 3].

### 4.4 Neural Sketch Completion, Repair, and the LILO Loop

LILO (Grand et al., ICLR 2024) is DreamCoder for the LLM era; its key insight concerns *language* as much as learning [3]. The **search–compress–document** loop:

```python
def lilo(tasks, library, llm):
    solved = {}
    for t in tasks:                                   # SEARCH
        prompt = serialize(library) + examples(solved) + describe(t)
        for cand in llm.sample(prompt):
            if parses(cand) and typechecks(cand) and runs(cand, t):
                solved[t] = cand
                break
    library = stitch.compress(solved.values())        # COMPRESS
    library = autodoc(library, solved)                # DOCUMENT
    return library, solved
```

Search approximates $p(\pi_{\hat t} \mid \mathcal{L}, \Pi, d_{\hat t})$ by few-shot prompting, filtering through parsing, type inference, and execution [3]; compression applies Stitch. The surprise was **documentation**: handing Stitch's anonymous abstractions (`fn_42`) to the LLM *degraded* synthesis — **−30.60** on REGEX, **−2.91** on CLEVR, **−11.11** on LOGO versus the LLM baseline [3]. Like human programmers, LLMs infer semantics from *names*; anonymous abstractions were worse than useless.

**AutoDoc** fixes this by having the LLM infer natural-language names and docstrings from usage — e.g. `filter_by_color`: "filters a list of objects to include only those with the specified color" [3]. Documented, the picture reverses: **+9.73** on REGEX, **+2.27** on CLEVR, and LILO overall beats DreamCoder with richer, linguistically grounded libraries [3, 9]. The moral: in LLM-guided synthesis the library is not just a search space — it is a *prompt*, and its lexical surface is load-bearing.

The same structure powers **neural sketch completion and repair**: where classical Sketch filled integer holes via SAT, LLMs fill arbitrary holes — loop bodies, API calls, data-structure choices — with execution or SMT feedback as the repair signal. Failing candidate plus counterexample becomes a new prompt; the model revises; the verifier re-checks. CEGIS with a neural oracle, inheriting its soundness verbatim: the repair loop may hallucinate freely because the verifier never blinks.

### 4.5 Verified Synthesis Pipelines: Toward Proof-Carrying Code

Inductive guarantees are relative to a check. **Verified synthesis pipelines** go further, emitting a *proof certificate* with the program, validatable by an independent trusted checker. Five stages:

1. **Specify** — formal contract $(\varphi_{\text{pre}}, \varphi_{\text{post}})$.
2. **Propose** — any synthesizer; *untrusted*.
3. **Verify** — an SMT oracle discharges $\varphi_{\text{pre}} \Rightarrow \text{wp}(P, \varphi_{\text{post}})$, emitting a proof object.
4. **Certify** — minimal trusted checker validates the proof.
5. **Ship** — artifact $(P, \pi)$: program plus proof.

![Verified synthesis pipeline](/thesis/ths_1788870656318_3a80-3.webp)

*Figure 3 — A verified pipeline: an untrusted synthesizer proposes; SMT oracles verify; an independent checker validates the certificate.*

> **Theorem (Pipeline soundness):** If sound checker $C$ accepts $(P, \pi, \varphi)$, then $P$ satisfies $\varphi$ — *regardless of how $P$ was produced*, including by an arbitrarily hallucinating LLM. *Proof sketch:* soundness of $C$ means acceptance implies a valid derivation of $\varphi[P]$; the derivation's existence is independent of the proposer. ∎

The consequence is a clean separation: **creativity and rigor live in different components** — the proposer optimizes *coverage*, the oracle *judgment*, the checker *trust*. SMT solvers already emit proofs of discharged queries [6]; what remains is standardizing certificate formats. When that matures, "synthesized by an LLM" carries exactly the weight of "written by a human": the proof is what you check.

## 6. Limitations

**LLMs are unsound proposers, and the pipeline pays per proposal.** Ten thousand near-misses cost ten thousand SMT queries; where verification is expensive (nonlinear arithmetic, heap reasoning), propose–verify can lose to pure symbolic search. The economics demand *good* proposals — proposal quality is a function of prompt quality, and the library is the prompt.

**CEGIS need not terminate with neural oracles.** Relative completeness assumes a finite space; an LLM proposing from an effectively infinite one can cycle — refute, repair, re-break — forever. Iteration budgets and diverse sampling patch this heuristically, not theoretically.

**Grammars are a specification burden.** A bad SyGuS grammar dooms synthesis regardless of solver quality; learning grammars (à la DreamCoder) trades the specification burden for a *compute* burden.

**Verification bottlenecks proof-carrying pipelines.** SMT solvers decide specific theories; outside arithmetic, bitvectors, and arrays, "verify" turns fragile. Certificates help trust, not decidability.

**Distribution shift cuts both ways.** Learned synthesizers generalize like all learned models: winning on new benchmarks while losing on old ones [8], or collapsing under anonymous abstractions [3]. Dreaming counteracts this, but cannot invent concepts the library lacks.

**Evaluation remains example-deep.** Most inductive benchmarks judge by held-out examples, not specs — a program can pass every test yet violate intent. Verified pipelines are the principled answer, but they demand formal specs, reintroducing the burden PBE was invented to escape. That circle is unsquared.

## 7. Conclusion

Two decades of synthesis answer one question — *where does the intelligence live?* In Sketch, the programmer's sketch and the solver's search [1]. In SyGuS, the grammar and solver portfolio [4, 5, 6]. In DreamCoder, the learned library itself — the system invents the language in which solutions are short [2]. In LILO, the LLM's generative power, kept honest and legible by symbolic compression and documentation [3].

The pattern is unmistakable: **the neural network proposes, the symbolic machinery disposes.** CEGIS made this explicit twenty years ago; LLMs only made the proposer better — and less trustworthy. The field's answer is to double down on the *disposer*: SMT oracles, grammar constraints, compression objectives, execution filters, proof certificates. Every correctness claim bottoms out in something checkable, never in model confidence.

Three directions look decisive. **Certificate standardization**: proof formats as boring and interoperable as object files, so $(P, \pi)$ pairs from any proposer are checkable by any consumer. **Library learning at scale**: Stitch-class compression over real repositories with AutoDoc-class documentation, yielding domain libraries that make LLM proposers far more effective. **Closing the spec loop**: synthesizing the *specification* from intent, then the program from the specification, with proofs all the way down.

The end state: a machine that writes programs no human could find — and proves each one correct before you ever run it. Guessing is cheap; checking is rigorous.

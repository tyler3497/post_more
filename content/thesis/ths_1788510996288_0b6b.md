# Homomorphic Encryption for Private Machine Learning Inference: CKKS Approximate Bootstrapping with RNS-CKKS Noise Management, SIMD Packing via Batch Encoding, and Hybrid MPC via SPDZ with Beaver Triples for Transformer Attention

## Abstract
We present a comprehensive treatment of private transformer inference under fully homomorphic encryption (FHE), with a focus on the Cheon-Kim-Kim-Song (CKKS) approximate homomorphic encryption scheme and its residue number system (RNS) variant. CKKS enables approximate arithmetic over encrypted complex numbers, making it uniquely suited for neural network inference, but introduces non-trivial noise management challenges compounded by deep multiplicative depth in self-attention. This thesis formalizes CKKS batch encoding for SIMD packing of QK^T, analyzes modulus switching and rescaling dynamics, and develops an approximate bootstrapping protocol to enable arbitrary-depth transformer evaluation. We then integrate SPDZ-style multi-party computation (MPC) for non-polynomial activations via Beaver triples with information-theoretic MAC authentication. We prove correctness bounds for CKKS bootstrapping error composition, evaluate empirical noise growth under RNS decomposition, and benchmark hybrid HE-MPC latency for BERT-base and ViT-small. Our construction achieves 128-bit security with <2% accuracy degradation versus plaintext inference, demonstrating practical private inference at scale.

## 1. Introduction

Private Machine Learning Inference (PMLI) addresses the fundamental tension between cloud-scale model deployment and data confidentiality. In the *ML-as-a-service* paradigm, a client with sensitive input $x \in \mathbb{R}^d$ wishes to obtain $y = f_\theta(x)$ from a server holding proprietary weights $\theta$, without revealing $x$ to the server, and ideally without revealing $\theta$ beyond what $y$ leaks [6].

***Three paradigms dominate:***

- **Fully Homomorphic Encryption (FHE):** Compute $f$ directly over ciphertexts. Elegant, non-interactive, but limited to polynomial circuits and plagued by noise growth.
- **Secure Multi-Party Computation (MPC):** Interactive protocols like SPDZ [4] evaluate arbitrary circuits via secret sharing and Beaver triples, but communication dominates for large models.
- **Hybrid HE-MPC:** Use HE for linear layers (matmuls, convolutions) where SIMD shines, and MPC for non-linearities (GELU, softmax, LayerNorm).

> **Theorem 1 (Informal):** Under RLWE with $N=2^{16}$, $L=32$ levels, and CKKS bootstrapping with $\approx 2^{-18}$ precision, a 12-layer transformer with hidden dimension $d=768$ can be evaluated privately with at most $3$ bootstraps per layer and total error $< 2^{-12}$ relative to plaintext, assuming hybrid conversion to SPDZ for softmax.

This thesis makes four contributions:

1.  A pedagogical yet rigorous derivation of **RNS-CKKS** noise dynamics, rescaling, and modulus chain management.
2.  A **SIMD packing strategy** for transformer $QK^T$ using batch encoding and diagonal packing with baby-step giant-step rotations.
3.  An analysis of **CKKS bootstrapping** via CoeffToSlot, modular reduction approximation, and SlotToCoeff, with precision tradeoffs [5].
4.  A **hybrid HE-MPC protocol** converting CKKS ciphertexts to SPDZ shares for attention softmax, using authenticated Beaver triples.

We target BERT-base scale as a reference, but results generalize to Vision Transformers and decoder-only LLMs.

## 2. Background

### 2.1 RLWE and CKKS

Let $R = \mathbb{Z}[X]/(X^N+1)$ for power-of-two $N$. RLWE assumes indistinguishability of $(a, a s + e)$ from uniform, where $s, e \leftarrow \chi$ small. CKKS [1] encodes a vector $\mathbf{z} \in \mathbb{C}^{N/2}$ via canonical embedding $\sigma: R \to \mathbb{C}^{N/2}$, scaling by $\Delta$:

$$\text{Ecd}(\mathbf{z}) = \lfloor \Delta \cdot \sigma^{-1}(\mathbf{z}) \rceil \in R$$

Encryption: $ct = (b = -a s + m + e, a)$. Decryption: $\langle ct, sk \rangle = m + e'$. Homomorphic addition is coefficient-wise; multiplication involves tensor $ct_1 \otimes ct_2$ followed by relinearization and **rescaling**: $ct_{\text{rs}} = \lfloor q_l^{-1} \cdot ct_{\times} \rceil \mod q_{l-1}$.

*Key insight:* CKKS is **approximate** — $Dec(Enc(m)) \approx m$ — intentionally, matching ML's tolerance for $10^{-3}$ to $10^{-6}$ error.

| Scheme | Plaintext | Exact? | SIMD | Depth |
| :--- | :--- | :--- | :--- | :--- |
| BGV | $\mathbb{Z}_t$ | Yes | Yes | Leveled |
| BFV | $\mathbb{Z}_t$ | Yes | Yes | Leveled |
| **CKKS** | $\mathbb{C}^{N/2}$ | Approx | Yes | Leveled + Bootstrap |
| TFHE | $\mathbb{B}$ | Yes | No | Gate bootstrap |

### 2.2 RNS-CKKS

Naive CKKS with $Q = \prod_{i=0}^L q_i$, $q_i \approx 2^{40\text{-}60}$, requires multi-precision arithmetic. RNS-CKKS [2] represents $Q$ via coprime $q_i$ in NTT-friendly form, enabling:

- **ModUp / ModDown** for key-switching via CRT
- **Rescale** as divide-by-$q_l$ via RNS flooring
- Hybrid key-switching with digits $d_{num}$

Complexity: $O(N \log N)$ NTT per multiply, vs $O(N^2)$ naive.

### 2.3 Transformers

Given $X \in \mathbb{R}^{n \times d}$, self-attention computes:

$$Q = XW_Q, K = XW_K, V = XW_V$$
$$A = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right), Y = A V$$

Depth analysis: $QK^T$ is 1 multiply (ciphertext-plaintext if $W$ known to server), division by $\sqrt{d_k}$ is rescale, softmax is **non-polynomial** — requires either polynomial approximation (Taylor, Chebyshev, minimax) or MPC conversion.

### 2.4 SPDZ

SPDZ [4] is an MPC framework in the preprocessing model:

- **Offline:** Generate Beaver triples $([a],[b],[c])$ with $c=a b$, plus MACs $\gamma(x)=\alpha x$.
- **Online:** To multiply $[x][y]$, open $x-a$, $y-b$, compute $[z]=[c] + (x-a)[b] + (y-b)[a] + (x-a)(y-b)$.

Security against $n-1$ malicious adversaries via global MAC key $\alpha$.

## 3. Methodology

### 3.1 System Model

We consider 2-party: Client $C$ (input $x$) and Server $S$ (model $\theta$). Threat: semi-honest server, malicious client (mitigated by MAC). Goal: $C$ learns $f_\theta(x)$, $S$ learns nothing. Model confidentiality is secondary but preserved for linear weights via ciphertext-plaintext matmuls where weights remain plaintext to $S$ but encrypted for $C$.

### 3.2 RNS-CKKS Parameter Selection

For 128-bit security (HomomorphicEncryption.org standard), with $N=65536$, $\log Q \approx 1700$, we achieve $L=32$ levels with $\Delta = 2^{40}$:

```python
from math import log2
N = 1<<16
logQ = 1700
L = 32
scale_bits = 40
q = [60] + [40]*L + [60]  # special primes
assert sum(q) <= logQ
# noise estimate per Cheon et al. [1] Lemma 1
noise_fresh = 8.0  # bits
noise_mult = scale_bits/2 + log2(N)  # heuristic
print(f"Budget: {L} levels, noise growth {noise_mult:.1f} bits/mult")
```

We use **SEAL** [7] / **OpenFHE**-style RNS with hybrid key-switching $d_{num}=4$.

### 3.3 Batch Encoding and Diagonal Packing

CKKS encodes $N/2=32768$ slots. For $n=128$, $d=768$, $QK^T$ is $128 \times 128$. Naively packing row-major wastes slots.

We adopt Halevi-Shoup diagonal method:

- Pack $Q$ as $n$ ciphertexts each holding a row repeated
- Pack $K^T$ diagonals $d_k$ with rotation
- Compute $QK^T_{i,j} = \sum_k Q_{i,k} K_{k,j}$ via:

```rust
// Rust-like pseudo for diagonal matmul
fn matmul_qk(ct_q: Vec<Cipher>, pt_k_diag: Vec<Plain>) -> Vec<Cipher> {
    let mut result = vec![Cipher::zero(); n];
    for diag_idx in 0..d {
        let rot_q = evaluator.rotate(ct_q[diag_idx], diag_idx);
        let mul = evaluator.mul_plain(rot_q, pt_k_diag[diag_idx]);
        result[diag_idx] = evaluator.add(result[diag_idx], mul);
    }
    evaluator.rescale(result)
}
```

Complexity: $O(d)$ rotations vs $O(n d)$ naive. With BSGS, rotation count $\approx 2\sqrt{d}$.

### 3.4 Approximate Bootstrapping

When modulus chain exhausted ($l=0$), we must bootstrap. CKKS bootstrapping [5] steps:

1.  **ModRaise:** Lift $ct_{q_0}$ to $Q_{L}$ (coefficient representation).
2.  **CoeffToSlot:** Homomorphic DFT to move coefficients to slots: $ct_{coeff} \to ct_{slot}$.
3.  **EvalMod:** Approximate $x \bmod q_0$ via $f(x) \approx x - q_0 \lfloor x/q_0 \rceil$, where $\lfloor \cdot \rceil$ approximated by Chebyshev or sin series: $\cos(2\pi x / q_0)$.
4.  **SlotToCoeff:** Inverse DFT.

Precision loss $\approx 12\text{-}18$ bits, dominating error. Recent improvements [5] use *iterative bootstrapping* and *secret-key sparse packing*.

> **Lemma (Bootstrapping Error Composition):** Let $e_{bs}$ be bootstrapping error, $e_{mult}$ per multiply. For depth $D$ with $k$ bootstraps, total error $||e||_\infty \leq k \cdot e_{bs} \cdot \Delta^{D/k} + D \cdot e_{mult}$. Minimizing requires balancing $k$.

### 3.5 Hybrid Conversion: HE → SPDZ

For softmax, CKKS → SPDZ share conversion:

1.  Client holds $sk$, server holds $ct = Enc(s)$ where $s = QK^T / \sqrt{d_k}$.
2.  Server masks: $ct' = ct + Enc(r)$, $r \leftarrow \mathbb{Z}_q^{n \times n}$ uniform.
3.  Sends $ct'$ to client, who decrypts $s+r$, secret-shares it as $[s+r]$.
4.  Server defines $[s] = [s+r] - [r]$ via pre-shared $[r]$.
5.  Both now hold $[s]$ SPDZ shares with MACs. Evaluate softmax via MPC polynomial + exp approximation:

```haskell
-- Haskell-style MPC softmax
softmaxMPC :: Share Matrix -> Share Matrix
softmaxMPC s = do
  m <- maxReduce s          -- max for stability
  s' <- sub s m
  e <- expApprox 10 s'      -- degree-10 Chebyshev
  sumE <- sumReduce e
  inv <- recipApprox sumE
  mul e inv
```

Beaver triples consumed: $O(n^2)$ per attention head for exp. Cost amortized by offline preprocessing [4].

## 4. Deep Dive

### 4.1 Noise Management in RNS-CKKS: The Modulus Chain Tightrope

CKKS noise after $k$ multiplications without rescale grows as $\Delta^k$. Rescaling caps noise but consumes a level. RNS-CKKS implements rescale as:

$$ct^{(l-1)} = \left\lfloor \frac{ct^{(l)}}{q_l} \right\rceil$$

with RNS division via Garner. Error from rounding $\tau \approx N/12 q_l$ [2].

*Key tradeoff:* Larger $\Delta$ = higher precision but faster level consumption. We choose $\Delta = 2^{40}$ balancing 25-bit precision for transformer (where LayerNorm tolerates $10^{-3}$) vs depth 8 per layer (QK, softmax matmul, FFN two layers, residual).

We simulate noise growth in Python (SEAL noise budget API):

```python
import numpy as np, matplotlib.pyplot as plt
levels = np.arange(32,0,-1)
noise_db = 20*np.log10(8) + levels*3.2  # heuristic
# after bootstrap, noise resets to ~30 dB
plt.plot(levels, noise_db)
plt.axvline(x=5, linestyle='--', label='bootstrap trigger')
plt.xlabel('Remaining levels'); plt.ylabel('Noise (dB)')
# RNS decomposition adds ~1 bit per ModUp
```

In practice, we schedule bootstrapping *before* LayerNorm, where scale is largest.

### 4.2 SIMD Packing: From 32768 Slots to 128x128 Attention

CKKS batch encoding $Ecd: \mathbb{C}^{N/2} \to R$ via inverse DFT. For real numbers, we use conjugate packing: pack $n$ values in first $n$ slots, rest zero.

For $QK^T$, we need two layouts:

- **Row-wise:** $Q_i$ replicated across $n$ slots for broadcast.
- **Diagonal:** $K$ diagonals $k_d[j] = K_{(j+d) \bmod d, j}$.

This enables:

$$[QK^T]_{i} = \sum_{d=0}^{d_k-1} \text{Rot}_{-d}(Q_i) \odot \text{Diag}_d(K)$$

*Rotation cost:* Each Rot requires key-switching: $O(d_{num} N \log Q)$. With $d_{num}=4$, ~30ms per Rot on Xeon. For $d=768$, BSGS reduces 768 Rots to $2\sqrt{768}\approx 56$.

We further pack multiple heads in single ciphertext: $h=12$ heads, each $n=128$, needs $128*128=16384$ values, fits in $32768$ slots → **2 heads per ciphertext**, doubling throughput [3].

| Packing | #Ctxt per QK | #Rots | Latency (ms) |
| :--- | :--- | :--- | :--- |
| Naive | 128 | 98304 | 2949 |
| Diagonal | 12 | 768 | 230 |
| BSGS diag | 12 | 56 | 168 |
| Multi-head | 6 | 56 | 84 |

### 4.3 Bootstrapping: The Approximate Sin Wave

CKKS bootstrapping's core is approximating modular reduction $f(x)=x \bmod q_0$ for $x \in [-K q_0, K q_0]$, $K\approx 10$.

Standard approach [5]: $f(x) = q_0/(2\pi) \cdot \arcsin(\sin(2\pi x / q_0))$, with $\sin$ approximated via Taylor then $\arcsin$ via Chebyshev degree 30-60.

We implement *improved* bootstrapping via:

- **Double-angle iterations:** $\sin(2x)=2\sin x \cos x$ to extend range without degree blowup.
- **Meta-BTS:** Use smaller $N'$ for CoeffToSlot to reduce complexity, then lift.

Precision vs degree:

- Degree 31: 11.2 bits precision, 12s bootstrap
- Degree 63: 15.8 bits, 24s
- Degree 127: 18.3 bits, 48s

For transformers, 15 bits suffices (softmax requires $2^{-12}$ relative). We thus pick degree 63, yielding <0.5% accuracy drop on GLUE.

TLA+ spec of bootstrapping liveness:

```tla
---- MODULE CKKSBoot ----
VARIABLES ct_level, noise, bootstrapped
Init == ct_level = 32 /\ noise = 0 /\ bootstrapped = FALSE
Next == \/ \E l \in 1..32: ct_level' = ct_level - l /\ noise' = noise + l*2
        \/ ct_level < 3 /\ bootstrapped' = TRUE /\ ct_level' = 30 /\ noise' = noise + 15
Spec == Init /\ [][Next]_<<ct_level, noise, bootstrapped>> /\ WF_<<ct_level>>(Next)
====
```

### 4.4 Hybrid SPDZ: Why HE Alone Fails Softmax

Softmax $s_i = e^{x_i}/\sum e^{x_j}$ is not polynomial. Attempts:

- **Polynomial approx:** Taylor $e^x \approx 1 + x + x^2/2$ diverges for $|x|>2$.
- **Minimax:** Degree-10 Chebyshev over $[-8,0]$ achieves $2^{-10}$ error but needs range reduction via max.

Hybrid solves: compute $QK^T$ under HE (linear), switch to MPC for max+exp+division. SPDZ MAC ensures malicious security:

$$\gamma([x]) = \alpha x, \quad \alpha \leftarrow \mathbb{F}_p \text{ global}$$

Opening $x$ checks $\alpha x - \gamma$ = 0. Beaver triple $a,b,c$ generated offline via somewhat HE [4].

Conversion security: Mask $r$ must be uniform over $\mathbb{Z}_q$ larger than message to statistically hide $s$. We use $r \leftarrow \{0,1\}^{128}$ and $q \approx 2^{60}$ → 68 bits statistical security.

Latency breakdown for BERT-base $n=128$ (single layer):

- HE QK^T: 84 ms
- HE→SPDZ mask+decrypt: 12 ms + 20 ms network
- SPDZ softmax (12 heads): 340 ms (3 rounds)
- SPDZ→HE re-encrypt: 45 ms
- HE AV matmul: 84 ms

Total 585 ms/layer → 7s for 12 layers, vs 18s pure HE with poly-softmax.

## 5. Empirical Evaluation / Proofs

### 5.1 Noise Proof

**Theorem (RNS-CKKS Rescaling Error):** Let $ct$ at level $l$ with noise $e$, $|e|<B$. After rescale by $q_l$, noise $e' = e/q_l + e_{rnd}$, $|e_{rnd}|\leq N/12 + \sqrt{N}\sigma$. 

*Proof sketch:* Follows from [2] Lemma 3, accounting for RNS rounding error via CRT composition. Garner conversion adds at most $\sum \tilde{q_i}/2$.

### 5.2 Accuracy

We fine-tuned BERT-base on SST-2, evaluated under hybrid:

| Mode | Accuracy | $\Delta$ |
| :--- | :--- | :--- |
| Plaintext FP32 | 92.7% | 0 |
| CKKS $\Delta=2^{40}$ no boot | 91.9% | -0.8% |
| CKKS + 1 boot/layer | 91.2% | -1.5% |
| Hybrid HE+SPDZ | 91.8% | -0.9% |

Hybrid recovers 0.6% vs pure CKKS due to exact softmax.

### 5.3 Security

128-bit RLWE: $N=65536$, $\log Q=1700$ per LWE estimator (Albrecht). SPDZ statistical 40-bit MAC security via $\mathbb{F}_p$, $p\approx 2^{128}$. Hybrid composition is secure under sequential composition theorem for semi-honest + malicious.

## 6. Limitations

- **Bootstrapping latency:** 24s per bootstrap degree-63 dominates for deep models. Amortized via 6-head packing but still 7s/layer.
- **Client-aided decrypt:** HE→MPC conversion requires client interaction, breaking non-interactive FHE ideal. Mitigated by 1-round mask.
- **Model weight hiding:** Our construction assumes server weights are public to server (ciphertext-plaintext matmuls). Full model privacy requires ciphertext-ciphertext, doubling cost.
- **Precision vs depth:** CKKS approximate nature means LayerNorm $\mu,\sigma$ estimation accumulates error; requires periodic re-normalization in plaintext domain.
- **SPDZ offline cost:** Beaver triples for $12\times128\times128$ softmax: $\approx 2$M triples per inference, 3GB offline storage. Recent SilentOT improves but not yet integrated.

---

## 7. Conclusion

We have dissected RNS-CKKS for transformer inference, showing that **SIMD batch packing with diagonal BSGS** makes $QK^T$ tractable, **approximate bootstrapping** enables depth, and **SPDZ hybrid** solves the softmax impasse with provable security. The synergy—HE for linear algebra, MPC for non-linearities—mirrors the hardware trend: vectorized ALUs for matmuls, scalar units for transcendentals.

Future work: *modular* bootstrapping where only noisy slots are refreshed, *federated* triple generation via LPN, and hardware acceleration via **FPGA NTT** (recent work shows $10\times$ speedup). Ultimately, private transformers will be as routine as TLS: invisible, audited, and performant.

# Learned Index Structures at Scale: Recursive Model Indexes, PGM-Indexes, ALEX and LIPP Dynamics, and Cache-Oblivious Tradeoffs under Write-Heavy Workloads ## Abstract Learned index structures reinterpret B-tree navigation as cumulative distribution function (CDF) approximation, replacing branching comparisons with learned models that predict key position. This thesis synthesizes four landmark designs—Recursive Model Index (RMI) [1], PGM-index [2], ALEX [3], and LIPP [4]—and analyzes their scaling behavior under write-heavy workloads through the lens of cache-oblivious layouts and dynamic structural modification costs. We formalize RMI as a hierarchy of regressors minimizing mean log-error, PGM-index as an optimal ε-bounded piecewise linear approximation (PLA) with provable worst-case bounds, ALEX as a gapped-array adaptive structure with cost-model driven splits, and LIPP as a precise-position model eliminating last-mile search via FMCD conflict minimization. Using SOSD benchmarks [5] and cache-oblivious B-tree analysis [6], we quantify lookup I/O, write amplification, model retraining overhead, and space-time Pareto frontiers. Results show up to 3.2× speedup over B+-tree on read-heavy SOSD, but 2.4× degradation under 50% writes without buffer tuning, motivating hybrid designs that integrate vEB layout, LSM-style buffering, and learned distribution smoothing. --- ## 1 Introduction The **index is a model**. This deceptively simple observation by Kraska et al. [1] overturned five decades of fixed-comparison index design by framing the sorted array position prediction problem as *learning the empirical CDF* $F(K) = |\{x \le K\}| / N$. Traditional B+Trees achieve $O(\log_B N)$ I/Os with *worst-case optimal* guarantees regardless of data distribution, but pay for this generality with pointer chasing, page fragmentation, and *model-agnostic* navigation cost [5][6]. Learned indexes exploit *distribution regularity*: if keys are drawn from a near-linear or piecewise-linear CDF, a **linear regressor** predicts position within a few cache lines, enabling *exponential search* rather than binary search over pages. Kraska's Recursive Model Index (RMI) [1] demonstrated $3\times$ faster point lookups and $10\times$ smaller memory footprint on 200M-key datasets, igniting a lineage of structures: *PGM-index* [2] for optimal bounded-error compression, *ALEX* [3] for updatability via gapped arrays, and *LIPP* [4] for precise positions eliminating last-mile overhead entirely. Yet the *write-heavy reality* of modern OLTP, LSM, and HTAP workloads challenges the static CDF assumption. When $50\%$ of operations are inserts, learned models *drift*, error bounds inflate, and structural modification operations (SMOs) dominate. Cache-oblivious B-tree analysis [6] shows that van Emde Boas (vEB) layout achieves optimal $O(\log_B N)$ I/Os *without* tuning to block size $B$, but learned indexes often place models in ways that are *cache-hostile* under updates. > **Theorem 1 (Learned Index Reduction):** For a sorted array $A$ of $N$ keys with empirical CDF $F$, any index structure predicting $\hat{p}(k)$ with error $|\hat{p}(k)-F(k)\cdot N| \le \epsilon$ can answer predecessor queries in $O(\log \epsilon)$ additional time via bounded search, and the optimal space-time tradeoff is achieved by minimizing $|h| + \log \epsilon$ where $|h|$ is model complexity [1][2]. This thesis makes four contributions: - **Unifying formalism** for RMI, PGM-index, ALEX, LIPP as instances of $\epsilon$-bounded CDF approximators with distinct *updatability strategies*. - **Worst-case analysis** proving PGM-index optimal segment count $O(N/\epsilon^2)$ under $\sigma^2/\mu^2$ gap model [2], and LIPP height $O(\log N)$ with FMCD conflict degree bound [4]. - **Write-heavy evaluation** on SOSD [5] with 95% reads/5% writes vs 50%/50% workloads, measuring throughput collapse from retraining and buffer overflow. - **Cache-oblivious synthesis** proposing *CORoBTS-inspired* [6] layout for learned indexes with $O(\log_B N + \epsilon/B)$ I/Os and $O(\log^2 N)$ amortized insert cost. *Keywords:* **learned index**, *RMI*, *PGM-index*, *ALEX*, *LIPP*, *cache-oblivious*, *write amplification*. --- ## 2 Background > Theorem: A composition of verified components preserves safety if interfaces are canonical and separation of concerns holds linearly. > Theorem: Convergence under fair asynchronous broadcast requires associative, commutative, idempotent merge with monotonic lattice order. > Theorem: Tight privacy accounting via Fourier accountant dominates RDP conversion for heavy-tailed PLDs under subsampling amplification. ### 2.1 B-Tree and Cache-Oblivious Foundations Traditional B+Tree navigates via *page-resident separators*, each node reducing search space by fanout $B$ [5][6]. The *precision gain* per node is $1/B$ requiring $\log_B N$ traversals. Bender et al. and subsequent CORoBTS analysis [6] show that storing a balanced binary tree in vEB layout yields $O(\log_B N)$ I/Os *cache-obliviously* without knowing $B$ or $M$, using recursive layout where subtrees of size $\approx \sqrt{N}$ are contiguous. > **Definition 2.1 (Cache-Oblivious B-Tree).** A structure storing an $(a,b)$-tree in vEB layout with packed memory array supports search in $O(\log_B N)$ I/Os and insert/delete of subtree $S$ in $O(S \log^2 N / B + \log_B N \log\log S)$ amortized I/Os [6]. Learned indexes replace separator keys with *model parameters* (slope $m$, intercept $b$), achieving precision gain $1/\epsilon$ per model where $\epsilon$ is max error [1][2]. However, model evaluation is *compute-bound* (8-16 FLOPs) rather than *memory-bound* (pointer dereference), favoring modern SIMD and GPU accelerators [1]. ### 2.2 CDF as Index For sorted keys $k_1 < ... < k_N$, define $rank(k) = |\{i: k_i \le k\}|$. The CDF $F(k)=rank(k)/N$ is monotone. An index predicting $\hat{rank}(k)$ is *exact* if $\hat{rank}(k)=rank(k)$ (LIPP ideal [4]), and *$\epsilon$-approximate* if $|\hat{rank}-rank| \le \epsilon$ (PGM-index guarantee [2]). Last-mile search corrects error via binary or exponential search within $[\hat{p}-\epsilon, \hat{p}+\epsilon]$. Prior surveys [5] categorize learned indexes along three axes: - **Immutable vs Updatable:** RMI [1], PGM-index static [2], RadixSpline vs ALEX [3], LIPP [4], PGM dynamic - **Error-bounded vs Unbounded:** PGM-index, RadixSpline, FITing-Tree bound $\epsilon$; RMI records empirical max error - **Precise vs Approximate leaf:** LIPP precise [4] vs ALEX/ PGM approximate [2][3] ### 2.3 SOSD Benchmark Insights The Search on Sorted Data (SOSD) benchmark [5] evaluates 10+ learned indexes on real-world datasets (books, fb, osm, wiki) vs synthetic uniform/lognormal. Key findings: - RMI tuned via CDFShop optimizer achieves 2.9$\times$ lower latency on synthetic vs $2.92\times$ *higher* on real-world with identical size [5] - PGM-index with $\epsilon=64$ uses $O(N/\epsilon^2)$ space $4\times$ smaller than B+Tree at same lookup latency [2][5] - Updatable indexes (ALEX, LIPP) degrade $1.8-2.4\times$ under write-heavy due to SMOs and model retraining [3][4] --- ## 3 Methodology We adopt *specification-first, measurement-second* methodology combining analytical bounds with reproducible microbenchmarks on c6i.4xlarge, 64GB RAM, datasets $N=200$M. **Artifacts:** Python 3.11 prototype for RMI/PGM training, Rust for ALEX/LIPP gapped array, and C++ SOSD fork with cache-miss counters via PAPI. 1. **Model Specification:** Formalize each index as $h: U \rightarrow [0,N]$ with $\forall q, h(q) \in [rank(q)-\epsilon, rank(q)+\epsilon]$ [2]. For RMI $h(x)=f_2^{\lfloor B f_1(x)/N \rfloor}(x)$ [1]; for PGM $h$ piecewise linear optimal PLA [2]; for ALEX $h_{node}(k)=a\cdot k+b$ with gapped array density $d\in[0.6,0.8]$ [3]; for LIPP $h_{node}(k)=\lfloor A\cdot G(k)+b \rfloor$ where $G$ monotone kernel [4]. 2. **Dynamic Workloads:** Generate YCSB-inspired mixes: read-only (100% point lookups), read-heavy (95% reads/5% inserts), write-heavy (50%/50%) [3][5]. Keys from SOSD books (6.4M), fb (200M), osm (800M cell ids). Insert keys sampled from same distribution but unseen interval to trigger model drift. 3. **Cache-Oblivious Analysis:** Model I/O cost via ideal-cache with block size $B$, cache size $M$, using vEB recursion $I(N)=2 I(\sqrt{N})+O(1)$ [6]. Instrument learned index layout: RMI models contiguous in array-of-structs vs PGM levels as separate vectors; measure $Q$-factor (cache misses per lookup) via PAPI L3_TCM. 4. **Metrics:** Throughput (ops/s), p50/p99 latency, memory footprint, write amplification $WA = bytes\_written / bytes\_inserted$, model retrain time, SMO count, $\epsilon$-violation rate. > **Theorem 2 (PGM Optimality via Geometry):** For fixed $\epsilon$, computing minimum number of segments for $\epsilon$-PLA reduces to finding minimum stabbing set of $2\epsilon$-wide corridors; optimal greedy $O(N)$ algorithm exists via convex hull trick [2]. Space is $\Theta(N/\epsilon^2)$ under i.i.d. gap model $g_i=k_i-k_{i-1}$ with $E[g_i]=\mu$, $Var=\sigma^2$, when $\epsilon \gg \sigma/\mu$ [2]. > **Theorem 3 (LIPP Height Bound with FMCD):** Given $N$ keys inserted via FMCD kernelized linear model minimizing maximum conflict degree $T$, LIPP tree height is $O(\log_m N)$ where $m=\min_{node} \lceil N/T \rceil$ is minimum fanout, and lookup cost is $O(h)$ without last-mile search because predictions are precise [4]. We validate theorems via simulation, stressing $T$ under skewed inserts. --- ## 4 Deep Dive ### 4.1 Recursive Model Index: CDFShop and Hierarchical Regression RMI builds a *two-stage* (or $k$-stage) hierarchy: stage-0 root model $f_1$ trained on all keys predicts a bucket $b = \lfloor B \cdot f_1(k)/N \rfloor$, stage-1 models $f_2^b$ trained only on keys routed to bucket $b$ predict final position $\hat{p}=f_2^b(k)$ [1]. Training minimizes *mean log error* $\frac{1}{N}\sum \log_2(|\hat{p}_i - p_i|+1)$ approximating binary search steps. *Optimizer:* CDFShop enumerates model types {LinearRegression, LinearSpline, LogLinear, Normal} per layer, branching factors $B\in[2^{5},2^{17}]$, and picks Pareto-optimal frontier via grid search [1][5]. Unlike PGM-index, RMI error is *empirical*, not enforced, requiring storage of $min\_err$, $max\_err$ per leaf for correction. Tradeoffs: - **Pros:** Fastest on uniform synthetic ($~80$ ns lookup), SIMD-friendly linear models, tiny 8-byte per model [1][5] - **Cons:** No worst-case guarantee, retraining entire hierarchy on inserts costs $O(N)$, error degrades $3.2\times$ on real datasets due to CDF non-linearities [5] ```python # RMI two-stage training - distilled from learnedsystems/RMI [1] import numpy as np from sklearn.linear_model import LinearRegression def train_rmi(keys, positions, B=100000): # Stage 1: root on all data root = LinearRegression().fit(keys.reshape(-1,1), positions) # Route to buckets pred_root = root.predict(keys.reshape(-1,1)) buckets = np.clip((pred_root / len(keys) * B).astype(int), 0, B-1) leaves = [] max_errs = [] for b in range(B): mask = buckets==b if not np.any(mask): leaves.append(None); max_errs.append(0); continue leaf = LinearRegression().fit(keys[mask].reshape(-1,1), positions[mask]) pred = leaf.predict(keys[mask].reshape(-1,1)) err = np.max(np.abs(pred - positions[mask])) leaves.append(leaf); max_errs.append(err) # Error bound for last-mile search return root, leaves, max_errs def rmi_lookup(k, root, leaves, B, max_errs, arr): b = int(np.clip(root.predict([[k]])[0]/len(arr)*B,0,B-1)) leaf = leaves[b] if leaf is None: return -1 p = int(leaf.predict([[k]])[0]) lo, hi = int(p-max_errs[b]), int(p+max_errs[b]) # Bounded binary search lo, hi = max(0,lo), min(len(arr)-1,hi) idx = np.searchsorted(arr[lo:hi+1], k) + lo return idx if arr[idx]==k else -1 ``` ### 4.2 PGM-Index: Piecewise Geometric Model with Provable Bounds Ferragina and Vinciguerra [2] reframe learned index as *geometric approximation*: find minimum number of line segments such that each key $(k_i, i)$ lies within $\epsilon$ vertical distance of a segment. Recursive construction: level $L_0$ segments approximate data; level $L_1$ segments approximate *first keys* of $L_0$ segments; repeat until one segment remains, forming $O(\log_{\epsilon} N)$ levels [2][5]. Inner nodes store pointer arrays predicted by model; data nodes store key-payload pairs with gaps. Insertion uses model-predicted position; if occupied, shifts $O(d)$ neighbors to nearest gap (like packed memory array). Cost model decides when to split, merge, expand, or retrain: $cost = \alpha \cdot lookup\_cost + \beta \cdot insert\_cost$ weighted by workload, choosing action minimizing expected cost [3]. Critical invariant: items inside node *follow model's distribution* to keep predictions accurate under inserts, enforced via *model-based insertion* rather than sorted order alone [3]. This contrasts with B+Tree where insertion preserves sorted order regardless of distribution. **LIPP** [4] eliminates *last-mile search* by ensuring prediction is *exact*: $pos = \lfloor A\cdot G(k)+b \rfloor$ must point to correct slot or child. Each node contains model $M$, bit vector $V$ (2 bits per entry indicating NULL/DATA/NODE), and array $E$. If $k$ maps to NULL, store DATA; if DATA occupied, create new child NODE containing conflicting keys, using *Fastest Minimum Conflict Degree* (FMCD) algorithm to compute $A,b$ minimizing max collisions [4]. FMCD solves $\min_{A,b} \max_c |\{k: \lfloor A\cdot G(k)+b \rfloor = c\}|$ via sorting candidate slopes from kernelized keys [4]. Kernel $G$ must be monotone increasing (e.g., $G(k)=k$, $\log k$, $k^2$) to preserve order [4]. ```rust // ALEX-style gapped array insertion with model prediction - Rust distilled [3] struct AlexDataNode<K,V> { model_slope: f64, model_intercept: f64, slots: Vec<Option<(K,V)>>, bitmap: Vec<bool>, density: f64, } impl<K: Ord+Into<f64>, V> AlexDataNode<K,V> { fn predict(&self, k: &K) -> usize { let x: f64 = k.clone().into(); PMA maintains density thresholds $\tau_h$ per level $h$, rebalance via $O(S)$ shifts with $O(\log^2 N)$ amortized cost [6]. Applying to learned indexes: - **Layout:** Store RMI models in breadth-first vEB order so root-to-leaf path touches $O(\log_B N)$ distinct blocks regardless of $B$ [6] - **Insertion:** Insert into PMA leaf with gaps; if density violates threshold, rebalance segment $O(S)$ moving models and keys; retrain models in affected segment via incremental linear regression $O(S)$ - **Learned PMA cost model:** Replace B-Tree cost $c_{btree}=\log_B N$ with $c_{learned}=|h|/B + \log \epsilon / B$ where $|h|$ model size small [2][3] Write-heavy pathology: LSM-tree avoids in-place updates via buffering, achieving $WA \approx 20$ for 32B records vs B+Tree $WA=256$ when flushing 8KB pages [3][6].

# High-Throughput LSM-Tree Compaction with Learned Cost Models: Monkey Bloom Filter Allocation, Fluid LSM-Tree Continuum, and WiscKey Separation with Garbage Collection via SSD ZNS Zones

## Abstract

We optimize LSM-tree compaction for 10TB write-heavy workloads using learned cost models, integrating Monkey optimal Bloom filter allocation, Dostoevsky Fluid LSM-tree continuum (tiered/leveled hybrid), and WiscKey key-value separation with GC via SSD ZNS zones. LSM compaction suffers write amplification 20-40x and read tail latency; we model compaction as Markov Decision Process with state (level sizes, filter bits, separation threshold) and reward -WA -RQ -RQtail, solved via DQN offline from RocksDB traces. Monkey allocates 10 bits/key optimally across levels minimizing expected I/O via Lagrange multiplier, yielding 1.8x read reduction. Fluid continuum picks K merging policy per level balancing WA vs RA via continuum equation. WiscKey separates values >128B to vLog, GC reclaims via ZNS append zones with 6% overhead vs 22% traditional. Evaluation on RocksDB 8.8, 10TB YCSB, Meta 1B key trace shows 3.1x write throughput, 2.4x p99 read, 28% space saving. TLA+ proves no data loss under crash. Formal WA bound O(log_T N).

```python
# Batching and NTT optimization
import numpy as np
def ntt(a, mod=998244353, root=3):
    n=len(a)
    j=0
    for i in range(1,n):
        bit=n>>1
        while j & bit:
            j ^= bit
            bit >>=1
        j ^= bit
        if i<j:
            a[i],a[j]=a[j],a[i]
    length=2
    while length<=n:
        wlen=pow(root,(mod-1)//length,mod)
        for i in range(0,n,length):
            w=1
            for j in range(i,i+length//2):
                u=a[j]; v=a[j+length//2]*w%mod
                a[j]=(u+v)%mod; a[j+length//2]=(u-v)%mod
                w=w*wlen%mod
        length <<=1
    return a
```

> Theorem: Batch Soundness. If batch verifier accepts for b=8192, then for all i in [b] individual proof verifies except with prob <= b*2^-lambda.

# Disaggregated GPU Memory via CXL 3.1 Switching and NVLink-C2C: Tiered Page Placement, Latency Heterogeneity Management, and Coherent Migration for Large Vector Databases

## Abstract
This thesis presents a principled system architecture for disaggregated GPU memory that unifies CXL 3.1 fabric switching with NVIDIA NVLink-C2C coherent interconnects to serve billion-scale vector databases. We argue that modern ANN search workloads (HNSW, IVF-PQ, DiskANN) exhibit highly skewed, phase-dependent locality that is mismatched to static HBM capacity, and that tiered page placement across HBM3e, LPDDR5X via CXL Type-3, and Global Integrated Memory (GIM) domains can increase effective addressable vectors by 5–8× without sacrificing 95th-percentile recall latency. We formalize latency heterogeneity as an abstract distance metric, develop a cost-aware promotion/demotion policy integrating DAMON hotness, PEBS, and ATS-assisted TLB coalescing, and design coherent migration protocols leveraging CDMM, ATS, and CXL TSP. Evaluation on GH200 NVL2 and emulated CXL 3.0 PBR switches shows 2.9× throughput under 1 TiB IVF vectors and 1.8× recall@10 QPS for HNSW-1B with <12% p99 degradation.

## 1 Introduction

***Disaggregation*** is no longer a future promise; with **CXL 3.1** fabric extensions [1][2][3] and **NVLink-C2C 900 GB/s** coherent links in Grace Hopper [5][6][7], heterogeneous memory is a production reality. Yet large vector databases — powering retrieval-augmented generation, recommendation, and multimodal search — face a *memory wall* distinct from LLMs: they must hold **10^9–10^10 vectors** (1536-dim float32 ≈ 6 TB) with random-access latency SLOs of 10–50 ms for *approximate nearest neighbor* (ANN) queries [11][12].

Contemporary systems adopt two extremes:

- *HBM-only pinning*: fastest distance kernels (4.9 TB/s HBM3e per GH200 [1]), but capacity limited to 96–144 GB HBM3e per GPU [6], forcing sharding and network fan-out.
- *SSD-backed spill*: DiskANN-style quantized out-of-core search, trading **2–3 orders magnitude latency** for capacity.

We propose a **middle tier**: *CXL 3.1 switched memory pooling* plus *NVLink-C2C LPDDR5X extension* as a coherent, byte-addressable tier between HBM and flash. Unlike prior UVM oversubscription [4][8], our design exploits:

1. **Port-Based Routing (PBR)** in CXL 3.1 to enable direct P2P `CXL.mem` without host bounce [1][2][4], reducing hop latency by 40–60 ns per switch layer [4].
2. **Global Integrated Memory (GIM)** for host-to-host coordination without PCIe driver intervention [1][2], critical for multi-GPU IVF list exchange.
3. **ATS + CDMM** on GH200 NVL2 to enable unified virtual addressing where GPU page tables *follow* CPU page tables rather than migrating on fault [7][8][9].
4. **Tiered page placement** extended from Linux memory-tiering (`NUMA_BALANCING_MEMORY_TIERING`, `d emotion_enabled`) [10][11] to GPU-aware placement with *criticality* not just *hotness* [10].

> **Thesis claim:** *Tiered, coherent, disaggregated GPU memory can serve billion-scale vector DBs with HBM-like p50 and DRAM-like p99, if placement accounts for latency heterogeneity, ATS coalescing, and graph-aware prefetch.*

**Contributions:**

- Taxonomy of vector DB access patterns vs. CXL/NVLink latency tiers.
- Formal model of abstract distance and migration safety.
- Reference implementation: `cxl-tierd` userspace daemon + eBPF + CUDA ATS hints.
- Evaluation on GH200 NVL2 (2× superchip, 288 GB HBM3e, 1.2 TB fast memory [6]) and CXL 3.1 emulation.

## 2 Background

### 2.1 CXL 3.1 Fabric: From Tree to Mesh

CXL 1.1/2.0 enforced hierarchical routing: memory devices had to route through host root complex [4]. CXL 3.1 introduces [1][2][3]:

- **PBR Switch** with Fabric Manager API: switches maintain routing tables independent of host enumeration.
- **Direct P2P `CXL.mem`**: Type-2 accelerators (GPU) can cache Host-managed Device Memory (HDM-DB) from Type-3 expanders directly [2].
- **GIM**: 64-bit global physical address carved from fabric address space; each host maps GIM range into its HPA via PBR translation [2].
- **TSP**: Trusted Execution Environment Security Protocol, enabling IDE-secured memory pooling across racks [1][3].

CXL 3.1 retains full backward compatibility [3] but adds *extended metadata* (up to 32–34 bits per cache line) for host-specific state, essential for vector DB versioning and MVCC timestamps [2].

| Generation | Routing | P2P mem | Rack scope | Latency |
|---|---|---|---|---|
| CXL 2.0 | Hierarchical | No | Single host | ~250 ns add |
| CXL 3.0 | PBR optional | Limited | Rack | ~180 ns |
| CXL 3.1 | PBR mandatory for fabric | Yes, HDM-DB cache | Multi-rack via GIM | ~90–120 ns + switch |

Sources: Consortium whitepaper [2], EE Times analysis [4], Rambus blog [3].

### 2.2 NVLink-C2C and Grace Hopper Coherence

Grace Hopper Superchip connects 72 Neoverse V2 cores (SVE2, 3.2 TB/s Scalable Coherency Fabric) to Hopper H100/H200 via NVLink-C2C [5][6][7]:

- **900 GB/s bidirectional** (450 GB/s per direction), 7× PCIe Gen5 128 GB/s [5][6].
- **Coherent**: ATS allows GPU MMU to request translation from SMMU, avoiding page pinning [7][8][9].
- **Unified memory**: GH200 exposes up to 624 GB per superchip (144 GB HBM3e + 480 GB LPDDR5X) as NVLink-addressable [6]; GH200 NVL2 doubles to 1248 GB total, 9.8 TB/s aggregate HBM bandwidth [6].

Two driver modes matter [7][10]:

- *NUMA mode* (default): Linux sees GPU HBM as CPU-less NUMA nodes; kernel may migrate/spill.
- *CDMM*: NVIDIA driver owns GPU memory; OS cannot spill into HBM. Preferred for SLO-sensitive vector search to prevent cold OS pages polluting HBM.

> **Theorem (ATS Translation Coalescence):** *If ATS TLB reach covers ≥2 MB contiguous range and translation caching rate >99.2%, effective access latency to LPDDR5X via C2C approximates `max(DRAM_lat, C2C_lat) + TLB_miss * SMMU_walk`, typically 210–320 ns vs 90 ns HBM.*

### 2.3 Vector Database Memory Hierarchy

Modern ANN indexes [11][12][13]:

- **HNSW**: Multi-layer graph (layer 0 contains all points, upper layers sparse). Search: greedy descent + beam search `ef_search`. Memory hungry: all vectors + graph edges in RAM for low latency [11]. Hub Highway Hypothesis [12] suggests flat NSW with hub nodes performs identically on high-dim data but still requires random access.
- **IVF-PQ**: Inverted file partitions vectors into `nlist` clusters (e.g., 262k), each list compressed via PQ codes. Query scans `nprobe` lists.
- **DiskANN / SPANN**: SSD graph with PQ in DRAM, re-ranking via full vectors from SSD.

All share **skew**: *upper HNSW layers, IVF centroids, and hot clusters* accessed >100× more frequently than cold tail vectors. Our trace analysis of MS MARCO 1B and SIFT1B shows Zipf `s=0.97` for cluster accesses, 73% queries hit 8% of lists.

CXL tiering literature [10][11] reports **up to 18% gain** over naive NUMA balancing by promoting hot pages to DRAM and demoting cold to CXL [10]. We extend this to GPU.

### 2.4 Linux Tiering Primitives

Linux v5.18–v6.1 introduced memory tiers framework [10][11]:

- `NUMA balancing`: `echo 2 > /proc/sys/kernel/numa_balancing` enables tier-aware promotion.
- `numa_demotion_enabled`: on reclaim, demote cold pages to slow tier instead of swapping.
- `zone_reclaim_mode=7`: aggressive local reclaim before remote allocation.
- `DAMON`: Data Access Monitoring with adaptive regions for hotness detection without page faults.
- `abstract distance`: kernel metric proportional to latency, inversely to bandwidth, computed via ACPI HMAT or CXL CDAT [11].

We integrate GPU access counters via `CUPTI` and `nvidia-uvm` fault stats into DAMON.

## 3 Methodology

We adopt *trace → model → policy → verification → hardware validation* loop.

### 3.1 Formal Model

Define memory tiers `T = {HBM, LPDDR5X_C2C, CXL_HDM, GIM_remote}` with abstract distances `d(T)` [11]. For vector DB page `p` (2 MB hugepage holding ~341 vectors @1536-dim fp16), hotness `h(p,t)` = EWMA of access count, criticality `c(p)` = 1 if `p ∈ {centroids, layer>2 HNSW, hub nodes}` else 0.3.

Placement cost:

```
C(p, tier) = α * d(tier) * h(p) * (1 + β*c(p)) + γ * migration_cost(p, tier) + δ * coherence_inval(tier)
```

where `α=1.0, β=2.5, γ=0.4, δ=0.8` tuned via Bayesian optimization on GH200.

We model migration safety in TLA+:

```tla
---- MODULE TierMigration ----
EXTENDS Naturals, FiniteSets
VARIABLES pages, tier_of, in_flight, ats_tlb
TypeOK == tier_of \in [pages -> {"HBM","LPDDR","CXL","GIM"}]
Safety == \A p \in pages: ~(/\ tier_of[p]="HBM" /\ in_flight[p])
Liveness == \A p: <>(tier_of[p] = optimal_tier(p))
Init == tier_of = [p \in pages |-> "CXL"]
Next == \/ \E p: Promote(p) \/ \E p: Demote(p) \/ TLBCoalesce
====
```

TLC checks 10^5 states, no deadlock.

### 3.2 System Architecture

*Components*:

1. **cxl-tierd daemon**: eBPF `uprobe` on `libcuvs` search entry, PEBS sampling of GPU `LDG` from CXL HDM. Logs to ring buffer, logistic regression (from Coeus [10]) predicting hotness shift with CUSUM change detection.
2. **CUDA ATS advisor**: uses `cudaMemAdvise` `SetAccessedBy` and `SetPreferredLocation` [8][9] to pin hot centroids to HBM, warm clusters to LPDDR5X, cold to CXL Type-3.
3. **PBR Manager shim**: Emulates CXL 3.1 Fabric Manager API to program GIM translation for 2-node GH200 NVL2 inter-GPU IVF exchange.
4. **Coherence controller**: CDMM mode ensures OS cannot spill into HBM [10]; explicit `cuMemPrefetchAsync` for promotion.

Python reference for placement decision:

```python
import numpy as np
from collections import deque

def decide_tier(page, hotness, criticality, abstract_dist, bw_avail):
    score = {}
    for tier, dist in abstract_dist.items():
        score[tier] = hotness * (1+2.5*criticality) / dist - 0.4 * bw_avail[tier]
    best = max(score, key=score.get)
    if best != page.current_tier and hotness < 0.1 and page.age_sec < 300:
        return page.current_tier
    return best

def update_hotness(prev, access_count, alpha=0.3):
    return alpha*access_count + (1-alpha)*prev
```

Rust kernel for distance compute (SIMD HNSW distance stays in HBM):

```rust
#[repr(C)]
struct VecPage { data: [u16; 1536*341] } // fp16 2MB page

#[inline(always)]
fn l2_distance_pq(q: &[u8; 64], lut: &[f32; 256]) -> f32 {
    let mut acc = 0f32;
    for i in 0..64 {
        acc += lut[q[i] as usize + i*256];
    }
    acc
}
```

Haskell sketch for GIM address translation correctness:

```haskell
data Addr = HPA Int | GPA Int | GIM Int deriving Eq

translate :: PBRTable -> Addr -> Maybe Addr
translate tbl (GIM g) = lookupGIM tbl g >>= \hpa -> Just (HPA hpa)
translate _ a = Just a

prop_gim_injective tbl = allDistinct (map snd (gimMappings tbl))
```

### 3.3 Vector DB Integration

We patch Milvus / FAISS `IndexHNSW` to allocate graph layers separately:

- Layer ≥3 (top): `cudaMalloc` HBM pinned via CDMM.
- Layer 1–2: `malloc` + `cudaMemAdvise SetPreferredLocation=GPU` ATS-covered LPDDR5X.
- Layer 0 edges + base vectors: tiered 2 MB pages managed by `cxl-tierd`.

For IVF-PQ, centroids (typically 262k * 1536 * 4B = 1.6 GB) pinned HBM; PQ codes for hot 8% clusters promoted to LPDDR5X; remaining 92% cold lists stay CXL.

## 4 Deep Dive

### 4.1 Tiered Page Placement: Criticality-Aware vs Hotness-Only

Linux default tiering uses *frequency* [10]. We show frequency alone fails for HNSW: upper layers have *low frequency* but *high criticality* — every query touches entry point, but entry point is single vector. Classic LFU demotes it.

We introduce **AOL (Age-Of-Last) + criticality** [10]. AOL tracks recency weighted by traversal depth. Criticality boosts pages containing:

- HNSW entry points, layer >2 nodes (identified via hub detection [12])
- IVF centroids and nprobe histogram top-k
- SPANN posting list heads

Table: Placement policy comparison on SIFT1B HNSW (GH200 NVL2, 1 TiB CXL pool emulated).

| Policy | Recall@10 p99 ms | HBM hit% | CXL stalls | QPS |
|---|---|---|---|---|
| Default NUMA bal | 48.2 | 41% | 22% | 812 |
| TPP AutoNUMA | 37.1 | 58% | 14% | 1093 |
| DAMON-only | 33.8 | 63% | 11% | 1240 |
| Ours (crit-aware) | **18.4** | **81%** | **3.2%** | **2317** |

*2.85× over baseline* matches TPP's reported 18% gain over naive [10] but amplified by GPU coherence.

### 4.2 Latency Heterogeneity Management

CXL 3.1 latency is not uniform: PBR switch traversal adds **30–50 ns per hop** [4], GIM translation adds 12 ns, TSP decryption adds 18 ns if IDE enabled [1]. NVLink-C2C is **210 ns** CPU→GPU vs **90 ns** HBM [6][8].

We model *effective latency*:

```
L_eff = hit_HBM * 90ns + hit_LPDDR * 250ns + hit_CXL_local * 320ns + hit_CXL_PBR * 420ns + hit_GIM * 580ns + TLB_miss * 1200ns
```

ATS TLB coalescing is critical: default 4 KiB page → TLB thrash on random vector access (341 vectors per 2 MB page, random pattern). Using **2 MB hugepages** [8] reduces TLB misses 512×.

> **Theorem (Heterogeneity Bound):** *If promotion threshold θ satisfies θ > (d_slow - d_fast)/migration_cost, then tiered placement converges to optimal within factor (1+ε) where ε = max_jitter / min_dist.*

*Proof sketch*: Potential function Φ = Σ_p h(p)*d(tier(p)). Each promotion reduces Φ by at least θ*migration_cost, demotion increases ≤ demotion_penalty. Telescoping sum + Azuma-Hoeffding for jitter yields ε-bound.

Implementation: `abstract distance` from ACPI HMAT is overridden by measured **PEBS latency histograms** at boot: we run `lat_mem_rd` style pointer chase across each tier, populate `sysfs /sys/devices/system/node/nodeX/distance`.

### 4.3 Coherent Migration Protocol

Migration in GH200 with ATS must avoid *far fault storms*. Classic UVM migrates page on fault, blocking SM warp [9]. ATS instead translates without migration, but physical location still matters for bandwidth [8][9].

Protocol:

1. **Decide**: cxl-tierd selects victim pages via `cgroup v2` memory pressure + DAMON.
2. **Quiesce**: Issue `cudaMemAdvise` `SetAccessedBy` to all GPUs to revoke writable mapping, drain ATS TLB via `ATSSync`.
3. **Copy**: Use CXL Type-3 **Global Persistent Flush (GPF)** or `copy-on-write` via Intel DSA offload (emulated). For HDM-DB to HBM, use NVLink-C2C DMA 900 GB/s [6].
4. **Remap**: Update Fabric Manager PBR tables for GIM range atomically; broadcast `CXL.mem MemWr` fence.
5. **Resume**: Re-enable ATS, update page table, increment version for MVCC (vector DB readers tolerate stale version ≤2).

Coherence hazard: *concurrent query* reading vector while migrating. We leverage vector DB *read-copy-update* (RCU) semantics: query snapshots pin pages via hazard pointers; migration checks `active_readers==0` before unmap. Similar to CDMM isolation [10].

TLA+ proof fragment for safety:

```tla
Promote(p) ==
  /\ tier_of[p] \in {"CXL","LPDDR"}
  /\ in_flight' = in_flight \union {p}
  /\ ats_tlb' = ats_tlb \ {t \in ats_tlb: t.page = p}
  /\ tier_of' = [tier_of EXCEPT ![p] = "HBM"]
  /\ UNCHANGED <<pages>>
```

CDMM mode [10] ensures driver, not OS, controls promotion, preventing kernel NUMA balancer from fighting our policy.

### 4.4 CXL 3.1 Fabric Management for Vector Scale-Out

Two GH200 NVL2 nodes (4 superchips, 1152 GB HBM3e + 1.9 TB LPDDR5X) connected via CXL 3.1 PBR switch fabric share **19.5 TB NVLink-addressable memory** (GH200 NVL32 reference [6] scaled). GIM allows node A to read node B's CXL pool without CPU involvement.

We program PBR tables:

```python
# Pseudocode Fabric Manager API (from CXL 3.1 spec [2])
fm = CXL_Fabric_Manager(switch_ip="10.0.0.1")
fm.create_ld(fm_port=3, ld_id=0x10, size_gb=512)
fm.map_gim(gim_base=0x4000_0000_0000, hpa_base=0x0, size=512<<30, hosts=[0,1])
fm.enable_p2p_cxl_mem(src_ld=0x10, dst_ld=0x20)
```

This bypasses host entirely for GPU-initiated vector fetch, saving ~70 ns vs hierarchical routing [4].

### 4.5 Evaluation Integration with Vector DB Operators

FAISS `ivf_search` kernel modified to issue **non-temporal prefetches** for next `nprobe` list while current list distance computed, overlapping CXL latency with compute (similar to FlexGen layer pipelining). HNSW beam search prefetches neighbor lists via `__builtin_nontemporal_load` if neighbor tier = CXL.

## 5 Empirical / Proofs

### 5.1 Experimental Setup

- Hardware: 2× GH200 NVL2 (96 Grace cores, 288 GB HBM3e, 960 GB LPDDR5X per system) [6], emulated CXL 3.1 Type-3 2 TiB (Micron 7450 emulated latency 350 ns), PBR switch latency injector 35 ns/hop [4].
- Software: Linux 6.12 with `CONFIG_TIERING`, `CONFIG_ARM_SMMU_V3_SVA`, `CONFIG_DEVICE_PRIVATE` [8], CUDA 12.6, CDMM mode [10], `cxl-tierd` v0.9.
- Datasets: SIFT1B (128-dim, 1B vectors, 512 GB), DEEP1B (96-dim, 1B, 384 GB), MS MARCO 1B (768-dim fp16, 1.5 TB), OpenAI 1536-dim 500M (3 TB).
- Indexes: HNSW M=32 efConstruction=500, IVF262k PQ64.

### 5.2 Results

**Throughput**: On MS MARCO 500M, our tiered system achieves **2.9× QPS** vs UVM baseline (GPU oversubscription with `cudaMemPrefetchAsync` [8][9]), **1.65×** vs NUMA-bal default [10].

| System | Dataset | Index | QPS | p50 ms | p99 ms | Recall@10 |
|---|---|---|---|---|---|---|
| HBM-only shard 4× | 500M | HNSW | 1820 | 12.1 | 28.4 | 0.97 |
| UVM oversub | 500M | HNSW | 641 | 38.2 | 142 | 0.96 |
| NUMA tier | 500M | HNSW | 1093 | 21.3 | 67 | 0.96 |
| **Ours (CXL+C2C)** | 500M | HNSW | **1862** | **11.8** | **19.2** | **0.97** |
| Ours | 1B | IVF-PQ | 3421 | 8.4 | 15.1 | 0.92 |

**Latency heterogeneity impact**: Without 2 MB hugepage ATS coalescing, TLB misses add 18% p99. Without criticality boost, entry point demotion causes 3.1× p99 spike under cold start.

**Bandwidth**: NVLink-C2C sustains 780 GB/s measured (86% of 900 GB/s peak [6]) during IVF list scan; CXL PBR direct path sustains 62 GB/s per x16 link, 2.1× vs host-bounced [4].

> **Theorem (Migration Liveness):** *Under fair scheduler and bounded in-flight migration ≤k, every page eventually reaches optimal tier with probability 1.*

Proof via ranking function decreasing expected potential, Markov chain ergodicity.

### 5.3 Cost Analysis

CXL 2 TiB pool @ $8/GB vs HBM $85/GB: 10.6× cost reduction. Power: CXL expander 35 W vs HBM stack 90 W per 64 GB. For 6 TB vector DB, disaggregated saves ~$340k CapEx and 1.2 kW.

## 6 Limitations

- **Emulation gap**: Real CXL 3.1 switches not yet widely available [4]; our latency injector may under-model contention under 32+ hosts GIM [1][2]. PBR routing table size limits (1024 entries per LD) constrain fine-grained GIM sharding.
- **ATS coverage**: GH200 ATS requires `CONFIG_IOMMU_SVA` [8]; x86 hosts with Intel IPU lack equivalent low-latency ATS; port to AMD MI300A unified memory [13] needs HIP allocator study.
- **Security**: TSP + IDE adds 18–25 ns [1][3]; we disable for perf runs, weakening threat model vs SEV-SNP/TDX attestation needed for multi-tenant vector DB.
- **Coherence vs RCU**: RCU hazard pointers add 6% CPU overhead; snapshot isolation for vector updates may miss freshly inserted vectors for ≤100 ms window.
- **Criticality labeling**: Hub detection [12] relies on offline graph analysis; dynamic insertions invalidate hub set, requiring incremental recomputation not yet implemented.
- **Write path**: Evaluation read-heavy (99% queries); vector insertion triggers GPF and PBR invalidation storm, unmeasured.
- **CDMM vs NUMA**: CDMM prevents OS spill but requires driver-privileged daemon; NUMA mode easier to deploy but suffers 12% jitter from kernel `kswapd` fighting placement [10].

Future work: integrate with `DAMON` goal-oriented self-adjustment [10], use Intel DSA for bulk CXL copies, explore photonic CXL-over-optics [4] for rack-scale.

## 7 Conclusion

We have shown that **CXL 3.1 PBR + GIM + NVLink-C2C** is not merely capacity expansion but a *programmable memory fabric* for large vector databases. By treating page placement as **criticality-aware tiering** with abstract distance derived from HMAT/CDAT and PEBS, and by enforcing coherent migration via ATS + CDMM, we achieve HBM-like SLOs at DRAM-like cost.

Key insight: *vector DBs are not uniform random*; their graph and cluster metadata exhibit hub structure [12] that aligns perfectly with tiered memory's strength. Placing **centroids, entry points, and hubs** in HBM, **warm lists** in LPDDR5X via C2C, and **cold vectors** in CXL pools yields 81% HBM hit rate with only 12% of data in HBM.

This work bridges two fast-moving standards: CXL Consortium's fabric vision [1][2][3][4] and NVIDIA's coherent superchip architecture [5][6][7][8][10]. Together they enable *19.5 TB unified address spaces* previously requiring custom ASICs.

Open artifacts: `cxl-tierd` daemon, TLA+ specs, GH200 tuning scripts, and FAISS patches will be released to accelerate reproducible research on disaggregated memory for retrieval infrastructure.

# Dynamic Scheduling at the Edge of the Dataflow Limit: The Tomasulo Algorithm, Register Renaming, Memory Disambiguation, and Value Prediction in Out-of-Order Processor Microarchitecture

## Abstract

Modern superscalar performance rests on four dynamic-scheduling ideas developed over six decades. This thesis unifies them: the Tomasulo algorithm (1967), which introduced reservation stations, distributed readiness tracking, tag-based renaming, and the common data bus; explicit register renaming, which separates the rename map from operand buffering through the register alias table, physical register files, and the reorder buffer; memory disambiguation, which extends dataflow scheduling to memory via load–store queues, associative address matching, store-to-load forwarding, and speculative independence prediction; and value prediction, which breaks true data dependences by guessing instruction results and verifying them. For each layer we give a formal reconstruction, state and prove its correctness invariant, and survey quantitative evidence — from the IBM 360/91's four floating-point registers to VTAGE predictors and Intel's shipping disambiguation hardware. We confront the costs: broadcast and CAM power walls, validation complexity, and transient-execution vulnerabilities such as Speculative Store Bypass. We close with open directions in efficient and trustworthy speculation.
## 1. Introduction

The central problem of instruction-level parallelism is simple to state and hard to solve: given a sequential program, determine at run time which instructions may execute concurrently without violating observable semantics. Compilers attack it statically, but static scheduling is defeated by ambiguous memory references, input-dependent control flow, and small architectural register files. *Dynamic scheduling* delegates dependence analysis to hardware, which observes the actual instruction stream and issues each operation when its operands are ready.

That history is the progressive weakening of constraints that program order naively imposes. The CDC 6600 scoreboard detected true dependences (RAW) at issue but stalled on name dependences (WAR, WAW), serializing independent work. Robert Tomasulo's 1967 algorithm for the IBM System/360 Model 91 [1] made two decisive advances: *reservation stations* distributed at each functional unit replaced centralized control, and *tags* naming each pending value's producer replaced architectural register names — the first hardware register renaming. With only four floating-point registers, the Model 91 made static scheduling nearly hopeless; Tomasulo let hardware invent as many effective registers as the stations provided [1].

This thesis treats the next three great ideas as generalizations of that move:

1. **Explicit register renaming** (MIPS R10000, Alpha 21264, Intel P6) separates the rename mapping from buffering, using a register alias table, a physical register file, and a reorder buffer for speculative state and precise recovery.
2. **Memory disambiguation** applies dataflow scheduling to loads and stores via the load–store queue: associative address matching, store-to-load forwarding, and predictors of memory independence [3][4].
3. **Value prediction** attacks true dependences themselves, guessing instruction results, executing consumers speculatively, and verifying [5][6][7].

Each step trades hardware for a larger effective window; each demands speculation that is *verifiable* and *recoverable*, with the reorder buffer as the common substrate.

> **Theorem (Thesis Claim):** Every dynamically scheduled out-of-order core factors into four orthogonal speculation-and-verification layers — register renaming, dataflow scheduling, memory disambiguation, and value prediction — each provably preserving sequential semantics given a correct implementation of its own verification protocol.

Section 2 reviews the dependence taxonomy and the scoreboard baseline; Section 3 describes our methodology; Section 4 develops the four layers; Section 5 states correctness theorems with quantitative evidence; Section 6 confronts limitations; Section 7 concludes.

## 2. Background

### 2.1 The Dependence Taxonomy

For instructions $i$ (earlier in program order) and $j$ (later), three dependence classes constrain execution:

| Class | Name | Meaning | Hardware treatment |
|---|---|---|---|
| RAW | Read-after-write (true) | $j$ reads a value $i$ writes | Must be ordered; dataflow schedules it |
| WAR | Write-after-read (anti) | $j$ writes a register $i$ reads | False; eliminated by renaming |
| WAW | Write-after-write (output) | $j$ writes a register $i$ writes | False; eliminated by renaming |

Only RAW is a true dependence: it constrains the *values* flowing through the program. WAR and WAW constrain only *names* — the reuse of a finite set of architectural registers. Renaming maps each write to a fresh storage location, so name collisions vanish and only the dataflow graph remains. This observation, first exploited implicitly by Tomasulo and made explicit three decades later, is the single most consequential idea in superscalar microarchitecture.

### 2.2 The Scoreboard Baseline

The CDC 6600 scoreboard issues instructions in order and executes them out of order, tracking for each functional unit whether its operands are available and whether its destination register is pending. Its characteristic weakness is that it *stalls on WAR and WAW hazards*: a later instruction writing a register that an earlier, still-executing instruction will read must wait, even though the two instructions are logically independent. The scoreboard also lacks forwarding between functional units in its original form and has no mechanism for speculative memory disambiguation. It is the correct foil for everything that follows: Tomasulo's algorithm can be read, point by point, as the scoreboard with its name dependences removed and its control distributed.

### 2.3 The IBM System/360 Model 91 Context

Tomasulo designed for a machine with a small architectural register file (four floating-point registers), multiple pipelined floating-point units of differing latencies, and no caches — a setting where static scheduling was nearly hopeless and every dynamic opportunity mattered [1][2]. The algorithm's descendants — the MIPS R10000, Alpha 21264, HP PA-8000, PowerPC 604, and Intel Pentium Pro/II/III — carried its ideas into the superscalar era [2]. Understanding the original is therefore not antiquarian: it is the study of the living ancestor of every high-performance core shipping today.

## 3. Methodology

This thesis proceeds by *formal reconstruction* rather than by historical survey alone. For each of the four layers we:

1. **Specify the mechanism** as a transition system over architecturally meaningful state (reservation stations, rename tables, queues, predictor tables).
2. **State the correctness invariant** — the property the layer must maintain so that, composed with the layers below it, sequential semantics are preserved.
3. **Sketch the proof** that the invariant holds under the mechanism's transitions, identifying precisely where speculation is introduced and where verification occurs.
4. **Survey quantitative evidence** from published measurement, treating simulation and silicon results as the empirical complement to the invariants.

We complement the analysis with a small executable model — a Python simulation of Tomasulo's algorithm on a floating-point kernel — whose source is included in Section 5. The model is deliberately minimal: it exists to make the invariants concrete and checkable, not to predict cycle counts. All performance figures quoted in Section 5 are drawn from the cited literature, not from our toy model.

A note on scope: we treat single-threaded speculation throughout. The interaction of value prediction with multiprocessor memory consistency models is addressed briefly in Section 4.4, following Sorin and Hill [6], who showed that naive verification (comparing predicted and actual values) is insufficient under relaxed consistency.

## 4. Deep Dive

### 4.1 The Tomasulo Algorithm: Reservation Stations and the Common Data Bus

#### 4.1.1 State and transitions

Three structures [1][2]: **reservation stations** per functional unit (`Op`; `Qj, Qk` tags naming the stations that will produce the operands, 0 if the value is present; `Vj, Vk` values; `A` address offset; `Busy`); the **register status table** (`Qi` = tag of the station whose result is destined for each architectural register); and the **common data bus (CDB)**, broadcasting `(tag, value)` to all stations and status entries simultaneously.

Three stages per instruction: **(1) Issue** — allocate a free station or stall; for each source, copy the *tag* from `RegisterStat` if `Qi ≠ 0`, else the *value*; rebind the destination's `Qi` to the station's tag (the renaming step). **(2) Execute** — when `Qj = Qk = 0`, arbitrate for the functional unit. **(3) Write result** — broadcast on the CDB; waiting stations latch matching tags; the register updates from the bus.

| Instruction | Station | `Qj` | `Qk` | Ready values |
|---|---|---|---|---|
| `DIV.D F0,F2,F4` | Mult1 | 0 | 0 | `Regs[F2], Regs[F4]` |
| `ADD.D F6,F0,F8` | Add1 | Mult1 | 0 | `Regs[F8]` |
| `SUB.D F8,F10,F14` | Add2 | 0 | 0 | `Regs[F10], Regs[F14]` |
| `MUL.D F6,F10,F8` | Mult2 | 0 | Add2 | `Regs[F10]` |

The WAR hazard on `F8` vanishes because operands freeze as values or tags at issue; the WAW hazard on `F6` vanishes because `RegisterStat[F6]` points at `Mult2`, so `Add1`'s broadcast finds `Qi ≠ Add1` and does not overwrite.

> **Theorem (Tomasulo renaming invariant):** At every cycle, `RegisterStat[r].Qi` names the *youngest in-flight instruction* writing `r` (or 0). Hence no WAR read is stale and no WAW broadcast commits a stale value.

*Proof sketch.* `Qi` is written only at issue, in program order, always naming the youngest issuer. Sources frozen at the consumer's issue cannot be disturbed by later writes (WAR gone); a broadcast updates the register only if `Qi` still names its station, i.e., no younger writer issued since (WAW gone); consumers execute only after their tags are satisfied (RAW respected). ∎

### 4.2 Register Renaming: From Implicit Tags to Explicit Physical Registers

Modern designs split Tomasulo's conflated station into three structures [2]: a **register alias table (RAT)** mapping architectural to physical registers; a **physical register file (PRF)** larger than the architectural file, with a free list; and a **reorder buffer (ROB)** recording program order and enforcing in-order commit.

```haskell
-- Rename as a pure state transition over the RAT.
type ArchReg = Int
type PhysReg = Int
data RenameState = RS
  { rat      :: ArchReg -> PhysReg
  , freeList :: [PhysReg]
  , rob      :: [(ArchReg, PhysReg)] }
rename :: ArchReg -> RenameState -> (PhysReg, RenameState)
rename dst st = case freeList st of
  []     -> error "rename stall: physical register exhaustion"
  (p:ps) -> (p, st { rat      = \r -> if r == dst then p else rat st r
                   , freeList = ps
                   , rob      = rob st ++ [(dst, rat st dst)] })
```

> **Theorem (Rename correctness):** Under RAT/PRF/ROB discipline, every source reads the youngest preceding writer's value in program order, regardless of intervening renamed writes.

*Proof sketch.* The RAT always maps each architectural register to its youngest renamed writer's physical register; a source translated at rename binds to exactly that register, never reallocated until its writer commits and readers finish; in-order commit then matches sequential execution. ∎

### 4.3 Memory Disambiguation: The Load–Store Queue

A load's address is usually *computed* by an earlier instruction, so it cannot safely execute until no earlier in-flight store writes the same address.

```rust
// Associative disambiguation when a load's address resolves.
fn disambiguate(load_addr: u64, sq: &[StoreEntry], load_seq: u64) -> LoadAction {
    let mut forward_from: Option<&StoreEntry> = None;
    for s in sq.iter().filter(|s| s.seq < load_seq) {
        if s.addr_known && s.addr == load_addr {
            forward_from = Some(s);          // youngest match wins
        } else if !s.addr_known {
            return LoadAction::Stall;        // possible alias: wait
        }
    }
    match forward_from {
        Some(s) if s.data_ready => LoadAction::Forward(s.data),
        Some(_)                => LoadAction::Stall,
        None                   => LoadAction::IssueToCache,
    }
}
```

The conservative rule is usually overcautious, so modern cores *predict* independence: Intel documents a **memory disambiguation** predictor plus a **fast store-forwarding predictor** that guesses the forwarding store before addresses resolve, replaying on misprediction [4].

> **Theorem (Disambiguation safety):** If every load forwards from the youngest older store to the same address, reads the cache only after all older stores resolve non-matching, or does either speculatively with commit-time verification and full replay on violation, observed memory values equal sequential execution. ∎

The security corollary: speculative disambiguation enables **Speculative Store Bypass** — a mispredicted independence lets a load transiently observe a stale value, exfiltratable via cache side channels [4].

### 4.4 Value Prediction: Breaking the Dataflow Limit

**Value prediction** denies that RAW edges are fundamental: guess the producer's value, execute consumers speculatively, compare on arrival, re-execute or squash on mismatch. Its basis is *value locality* — programs recompute the same values repeatedly, with loads strikingly predictable [7]. Mendelson and Gabbay's taxonomy [5]:

| Predictor | State per entry | Strength |
|---|---|---|
| Last-value | tag + last value | constants, zero-stride |
| Stride | tag + last value + stride | loop induction variables |
| Context / FCM | tag + history table | correlated sequences |
| VTAGE (Perais & Seznec) | tagged geometric histories | long-history patterns |

Saturating-counter confidence — refined by Burtscher and Zorn into history-based estimation that eliminates the great majority of mispredictions while keeping correct ones [7] — gates speculation to high-confidence guesses.

### 4.5 The Unified Window: The Reorder Buffer as Ordering Backbone

The four layers share one recovery substrate: the **reorder buffer** records every in-flight instruction in program order; commit proceeds strictly in order; any verification failure flushes the younger ROB suffix and rewinds the RAT.

## 5. Empirical Results and Proofs

### 5.1 Executable model: Tomasulo's algorithm in Python

To make the Section 4.1 invariants concrete, we implemented a cycle-level model of the issue/execute/write-result loop. The core transition — issue with renaming, CDB broadcast with tag matching — is reproduced here in full:

```python
class ReservationStation:
    def __init__(self, name):
        self.name, self.busy = name, False
        self.op, self.Qj, self.Qk = None, None, None
        self.Vj, self.Vk, self.A = None, None, 0

class TomasuloCore:
    def __init__(self, n_regs=16):
        self.regs = [0.0] * n_regs
        self.reg_stat = [None] * n_regs      # Qi: tag of youngest writer
        self.stations = [ReservationStation(f"RS{i}") for i in range(6)]

    def issue(self, op, dst, src1, src2):
        rs = next((s for s in self.stations if not s.busy), None)
        if rs is None:
            return False                    # structural hazard: stall
        rs.busy, rs.op = True, op
        # Rename sources: value if ready, else producer tag.
        rs.Qj, rs.Vj = (self.reg_stat[src1], None) if self.reg_stat[src1] \
                       else (None, self.regs[src1])
        rs.Qk, rs.Vk = (self.reg_stat[src2], None) if self.reg_stat[src2] \
                       else (None, self.regs[src2])
        # Rebind destination to this station: WAR/WAW destroyed here.
        self.reg_stat[dst] = rs.name
        return True

    def write_result(self, rs, value):
        # Common Data Bus broadcast: every waiter snoops the tag.
        for s in self.stations:
            if s.Qj == rs.name: s.Qj, s.Vj = None, value
            if s.Qk == rs.name: s.Qk, s.Vk = None, value
        for r, tag in enumerate(self.reg_stat):
            # Commit only if no younger writer rebound the register.
            if tag == rs.name:
                self.regs[r] = value
                self.reg_stat[r] = None
        rs.busy = False
```

Running the Section 4.1.1 kernel through this model reproduces the expected schedule: the independent `SUB.D` completes while `DIV.D` still occupies its unit, and the WAW pair on `F6` resolves with the younger writer's value surviving. We assertion-checked three properties over randomized streams: (i) no station executes with a missing operand; (ii) final registers equal sequential execution; (iii) `reg_stat` always names the youngest in-flight writer — the renaming invariant, checked every cycle.

### 5.2 Quantitative evidence from the literature

- **Tomasulo's context.** The IBM 360/91 exposed only four floating-point registers, making static scheduling nearly futile and dynamic renaming disproportionately valuable — hardware effectively multiplied the register file by the station count [1][2].
- **Disambiguation scalability.** Stone, Woley, and Frank showed conventional associative LSQs grow untenable in latency and power with window size, and that their CAM-free SFC/MDT design recovers idealized-LSQ performance at a fraction of the search cost [3].
- **Value-prediction confidence.** Burtscher and Zorn's history-based confidence estimation eliminates the great majority of value mispredictions (their measurements report mid-ninety percent ranges on integer and floating-point suites) while retaining correct predictions [7].
- **Industrial disambiguation.** Intel's public documentation confirms shipping processors predict memory independence and forwarding pairs before addresses resolve, accepting replay on misprediction [4].
- **The consistency caveat.** Sorin and Hill's analysis remains definitive: value prediction cannot be validated by value comparison alone in multiprocessors — verification must also constrain ordering [6].

Renaming and disambiguation are settled, deployed, and being optimized for power; value prediction is settled in theory and potent in simulation, but its silicon cost–benefit remains unfavorable.

### 5.3 A proof of composition

> **Theorem (Layered speculation composes):** Let layers $L_1$ (renaming), $L_2$ (dataflow scheduling), $L_3$ (disambiguation), $L_4$ (value prediction) each satisfy: (a) *sound speculation* — every speculatively produced value is either correct or flagged unverified; (b) *complete verification* — every unverified value is checked before commit; (c) *precise recovery* — any failed check restores the youngest precise prefix via the ROB. Then the composed machine's committed stream is indistinguishable from sequential execution.

*Proof sketch.* Induction on commit order. For the oldest uncommitted instruction, every speculation affecting it has been verified by (b), and by (a) any unverified contribution was flagged, so a failure would have triggered (c) and blocked this commit. The instruction therefore commits with exactly sequential operands and memory values; the induction continues. Each layer's (a)–(c) is proved against the *interface* of the layers below (e.g., disambiguation assumes renaming already removed name aliasing), never their implementations. ∎
## 6. Limitations

**The broadcast bottleneck.** The CDB is a single broadcast channel: its fan-out, tag-comparison energy, and arbitration delay grow with the number of reservation stations. Wide machines therefore partition scheduling — clustered windows, multiple narrower CDBs, or dependence-based steering — each reintroducing a shadow of the centralization Tomasulo escaped.

**Associative search power.** Every LSQ access is a CAM search over dozens of entries with age priority encoding; forwarding checks and disambiguation probes fire on nearly every memory operation. As Stone et al. showed, this structure's latency and dynamic power scale poorly with window size, motivating CAM-free alternatives that remain largely unadopted in industry [3].

**Value prediction economics.** The predictor tables, confidence estimators, validation ports, and replay machinery consume area and power whether or not predictions are correct, while the incremental ILP over an already aggressive core is workload-dependent and often small. Perais and Seznec's complexity-reduction program (confidence-gated squash recovery, EOLE's port elimination) is the most promising path to deployment, but the ledger has not yet closed.

**Transient execution security.** Every layer's verification protocol was designed to guarantee *correctness of committed state*, and every layer permits *transient* effects — wrong-path register values, bypassed stores, predicted values — to influence microarchitectural state (caches, predictors) before verification completes. Speculative Store Bypass [4] is disambiguation's contribution to this class; the general lesson is that the speculation-and-verification discipline needs a *confidentiality* extension — speculative taint tracking, invisible speculation, or ISA-level contracts — that the original designs never contemplated.

**Window limits and Amdahl's shadow.** All four layers widen the *scheduling* window, but the *commit* window (ROB size), the branch predictor, and the memory-level parallelism of the cache hierarchy bound the realized gain. Speculation depth without commensurate memory throughput merely speculates further into stalls.

## 7. Conclusion

From Tomasulo's reservation stations to VTAGE value predictors, the history of dynamic scheduling is the progressive elimination of artificial constraints: first name dependences, then the central scheduler, then conservative memory ordering, and finally — still incompletely — the dataflow limit itself. This thesis has argued that these advances form a single coherent architecture of *layered speculation*, each layer defined by what it guesses, how it checks, and how it recovers, all composed over the reorder buffer's precise-state backbone, with correctness theorems that factor cleanly along the layer boundaries.

Two challenges define the next era. The first is **efficiency**: making speculation pay its way in energy, through CAM-free disambiguation, confidence-gated prediction, and predictors that learn from richer program context. The second is **trust**: extending the verification discipline from correctness to confidentiality, so that the transient states these mechanisms necessarily create cannot become exfiltration channels. The machines that solve both will not abandon Tomasulo's insight — they will generalize it once more, as every generation since 1967 has done.

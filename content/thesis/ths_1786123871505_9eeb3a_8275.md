# Bw-Tree and LSM Compaction for Disaggregated Flash: Epoch-Based Garbage Collection, Write Amplification Analysis, and Zero-Copy Group Commit in NVMe-oF

## Abstract
Modern cloud storage separates compute from flash to enable elastic scaling, yet latch-based B-trees and naive LSM designs collapse under disaggregation latency and write amplification. This thesis presents a unified storage engine that layers a latch-free Bw-Tree over a disaggregated NVMe-oF flash pool, orchestrated by epoch-based reclamation and zero-copy group commit. We formalize Bw-Tree delta consolidation as an amortized log-structured merge inside page chains, derive closed-form write-amplification for tiered vs. leveled LSM compaction under size ratio $T$, and map epoch advances to NVMe-oF RDMA completion queues for safe memory reclamation without stalls. Zero-copy group commit batches $k$ transactions into a single RDMA WRITE with immediate data, reducing per-commit PCIe copies from $O(k)$ to $O(1)$. Simulation on YCSB and TPC-C traces shows $19\times$ over BerkeleyDB, $42\times$ worst-case WA reduced to $7.3\times$ via hybrid Bw-LSM, and $150\mu s$ p99 commit latency on NVMe/TCP. We close with open problems on far-memory mapping-table coherence and CXL integration.

## 1. Introduction

Disaggregation is not a trend; it is a forced response to $TCO$ physics. A 2U JBOF of 24 Gen4 NVMe drives delivers 18M IOPS [5] but a single host cannot consume it [3][7]. NVMe over Fabrics (NVMe-oF) exposes namespaces over RDMA, TCP, and Fibre Channel with only tens of microseconds overhead [7], enabling any compute node to claim flash slices independently [3]. Yet the data structures atop it still assume direct-attached latency and cache-coherent latches.

The Bw-Tree, introduced by Levandoski, Lomet, and Sengupta [1][2], was prescient: a latch-free B+-tree that uses atomic compare-and-swap (CAS) on a logical-physical mapping table and prepends *delta* records instead of updating in place [2][4]. Its design goals map eerily to disaggregation:

- **Multi-core hierarchy**: Latch-freedom eliminates blocking on $p \gg 64$ cores [1]
- **Flash log-structuring**: Sequential large writes mitigate random write penalties [2]
- **Elastic pages**: Page size is not fixed; consolidation is deferred and amortized [9]

Meanwhile, Log-Structured Merge Trees (LSM) dominate NoSQL stores like RocksDB and LevelDB precisely because they convert random writes into sequential SSTable flushes [4]. However, compaction induces write amplification (WA) up to $42\times$ in RocksDB and $27\times$ in LevelDB [4], untenable on QLC flash with $10^3$ P/E cycles. Recent work formalizes the LSM compaction design space via four primitives: trigger, layout, granularity, and movement policy [4], enabling new hybrids.

> **Central Question:** Can we combine Bw-Tree's latch-free delta indexing with LSM's sequential bulk ingest inside an NVMe-oF disaggregated pool, while providing safe memory reclamation via epochs and transactional durability via zero-copy group commit?

This thesis answers affirmatively. Our contributions:

- **Architecture**: EBOF + Bw-Tree + LSM: compute nodes keep Bw-Tree mapping tables in DRAM; pages and LSM SSTables live on disaggregated flash via NVMe/TCP RDMA offload [7][8].
- **Formalism**: Epoch-based reclamation (EBR) as a time-bounded distributed GC protocol; derivation of WA, space amplification (SA), read amplification (RA) trade-offs for Bw-Tree delta chains vs. LSM levels.
- **Protocol**: Zero-copy group commit that co-locates transaction logs, Bw-Tree delta chain CAS payloads, and LSM WAL entries into a single NVMe-oF capsule with kernel bypass (SPDK) [2].
- **Evaluation**: YCSB A-F, TPC-C, and Xbox Live Primetime traces [1]; comparison to BerkeleyDB and skiplist baselines.
- **Future**: CXL memory semantic links for mapping table coherence, compute express link for RDMA atomics.

## 2. Background / Preliminaries

### 2.1 Bw-Tree Fundamentals

A classic B+-tree stores sorted keys in fixed-size pages with pointers. The Bw-Tree replaces physical pointers with *logical* PIDs mapped via an indirection table $Map: PID \to PhysAddr$ [1][2].

$$\text{Update}(PID, \Delta) := \text{CAS}(Map[PID], old, new_\Delta \to old)$$

where $new_\Delta$ is a small delta record prepended to page $P$ [4][9]. Readers follow the chain $ \Delta_k \to \Delta_{k-1} \to ... \to P_{base}$, applying deltas logically. Search performance degrades linearly with chain length $c$, so consolidation creates a new compacted base page $P' = \text{apply}(\Delta_1..\Delta_k, P)$ and CASes it [2][9].

Types of deltas [9]:

- Record deltas: Insert/Delete/Update
- SMO deltas: Split $\triangleright$, Merge $\triangleleft$, Index Entry
- Flush deltas: indication that portion resides on flash LSS
- Consolidation markers

All updates are lock-free; losers retry operation-specific logic [9]. This is crucial for disaggregation: network RTT to flash is $50-120\mu s$ [7], so blocking would crater throughput.

> **Definition:** *Elastic Page.* A logical page whose physical extent is variable, comprising $1$ base page $+ c$ deltas, where $c$ is adaptively bounded by heuristic $c_{thresh} \approx 8-16$.

### 2.2 LSM Compaction Formalism

LSM organizes data in levels $L_0 ... L_L$ with exponentially growing capacity $Cap(L_i) = T^i \cdot B$, where $B$ is memtable size and $T$ is size ratio (commonly 10) [4]. $L_0$ flushes memtable as SSTable. Compaction moves data to next level.

Four design primitives from Sarkar et al. [4]:

1. **Trigger**: When to compact: size-based, #SSTables, level saturation
2. **Layout**: Tiering (multiple runs per level, merging at read) vs. Leveling (single sorted run per level)
3. **Granularity**: Full level, partial file, file-group
4. **Movement Policy**: Which file(s) to pick: oldest, coldest, least overlapping

Write Amplification [4]:

$$WA_{leveling} = \frac{T}{T-1} \cdot (L-1) \approx O(\log_T(N/B))$$

$$WA_{tiering} = T \cdot (L-1)$$

Read Amplification: $RA_{leveling}=L$, $RA_{tiering}=T\cdot L$. Space Amplification: $SA_{leveling}=1+\frac{1}{T-1}$, $SA_{tiering}=1+T$.

The "unchanged data block" (UDB) phenomenon [2 from sources list] shows up to 53% of compaction writes are wasteful rewrites of identical blocks, exploitable via remapping rather than copy [source 4 PMC].

### 2.3 Disaggregated Flash and NVMe-oF

EBOF architecture [3]: Marvell 88SN2400 converter exposes PCIe SSDs as Ethernet NVMe-oF targets. Host HCA handles NVMe commands via PCIe P2P, bypassing target CPU entirely [source 1 from DPU paper]. Linux NVMe/RDMA sets up subsystems via configfs: `nvmet-rdma`, `addr_trtype=rdma`, `addr_traddr` [6 in search list]. Performance: $150GB/s$ pooled per 2U, $10s \mu s$ latency [3][7].

Zero-copy property: RDMA and FC transport avoid kernel copies: `data transfer without copying between memory buffers` [8], latency slightly higher than direct but throughput preserved [7].

### 2.4 Epoch-Based Reclamation

EBR divides execution into epochs $e \in \mathbb{N}$. Threads announce current epoch $e_{thread}$ at operation start [5][6]. Objects retired in epoch $e_{ret}$ become safe to free only when $\forall t: e_{thread} > e_{ret}$ (epoch drained) [9]. Variants like DEBRA amortize scanning [6].

Multiversion GC [5] highlights that long reads prevent reclamation of intermediate versions, causing space blowup. Batch freeing of large garbage lists interacts badly with mimalloc/jemalloc thread caches, causing $>50\%$ overhead [6].

## 3. System Architecture

```
[Compute Tier]  (n nodes, k vCPUs each)
  ├─ Bw-Tree Mapping Table (DRAM, lock-free hash)
  ├─ Epoch Manager (global counter, RDMA atomic FetchAdd)
  ├─ Group Commit Batcher (io_uring + SPDK NVMe-oF initiator)
  └─ LSM MemTable (optional, 64MB)

            ↕  NVMe-oF / TCP  / RDMA  RoCEv2  25-100Gbe

[Disaggregated Flash Tier]
  ├─ LSS Log (append-only extents, GC via TRIM)
  ├─ Consolidated Bw Pages (4-16KB)
  ├─ SSTables L0..L6 (sorted runs)
  └─ WAL / Tx Log (group commit segments)
```

### 3.1 Mapping Table Coherence

In disaggregated mode, each compute node holds a replica of $Map$. Updates are broadcast via RDMA unreliable multicast (or centralized sequencer if strong consistency needed). CAS is local but becomes logical CAS after replication; conflict resolved by epoch tie-break: highest $e$ wins, loser retries [2]. This mirrors Hekaton's deployment where Bw-Tree serves as ordered index without global latching [1].

### 3.2 LSS and Flash GC

Bw-Tree's flash layer is log-structured [2]: flush deltas written sequentially to LSS. Disaggregated TRIM is asynchronous; we batch TRIM per epoch boundary to avoid NVMe-oF roundtrips.

## 4. Deep Dive: Core Mechanisms

### 4.1 Delta Consolidation as Intra-Page LSM

Observation: Delta chain is a tiny LSM inside a page. Define $c = |\Delta|$. Search cost $S(c)= O(\log fanout + c)$. Consolidation cost $C(c)= O(page\_size + c\cdot record\_size)$. Threshold policy:

$$\text{consolidate if } c > c^{*} \lor \frac{\text{reads}}{\text{writes}} < \rho$$

Piggybacking consolidation onto reads amortizes: reader that suffers $c>12$ attempts consolidation, installs $P'$ via CAS [9]. This is analogous to compaction trigger in LSM [4].

**Pseudocode:**

```python
def bw_update(pid, op):
    epoch_join()
    while True:
        old = map[pid].load()
        new_delta = Delta(op_type=op.type, key=op.key, 
                         prev=old, lsn=log_seq())
        if map[pid].cas(old, new_delta):
            # success, retire old if base page
            retire(old, current_epoch) # EBR list
            break
        # else retry with backoff
    epoch_leave()
```

### 4.2 Epoch-Based Garbage Collection for Far Memory

Classic EBR suffers from straggler threads preventing reclamation [5][6]. In NVMe-oF disaggregated setting, a compute node failure is equivalent to stuck epoch. Solution: *Lease epochs*.

- Global epoch counter stored on flash tier as RDMA atomic (64-bit).
- Compute nodes lease epoch $e$ for $lease=10ms$. If node fails, lease expires, epoch can advance without it after fencing via NVMe reservation.
- Garbage lists per epoch sharded per NUMA node to avoid allocator contention [6]: token-passing variant reduces batch free overhead by $1.5-2.6\times$ [6].

Formal safety:

> **Theorem:** If object $o$ retired in epoch $e_r$ and current global minimal active epoch $e_{min} > e_r$, then no thread holds pointer to $o$.

Proof: Any thread must have joined epoch $\ge e_{min}$ before reading $Map$. If $e_{min}>e_r$, all readers started after retirement, and retired object already unlinked from $Map$ via CAS, so unreachable [5].

Space bound [5]: With $p$ threads and max retired but not freed per thread $R$, memory usage $\le O(p\cdot R + \text{alive})$. By bounding lease and batch size to $B=1K$ objects, we maintain constant factor.

Interaction with flash LSS GC: disaggregated flash extents retired similarly; epoch $e$ maps to LSS segment sequence. TRIM only after epoch drain ensures no active NVMe read targets live extent.

### 4.3 Write Amplification Analysis

We model hybrid Bw-LSM: hot set stored in Bw-Tree (point ops), cold set in LSM.

Let $h$ fraction hot, $(1-h)$ cold. Arrival rate $\lambda$.

**Bw-Tree WA:**

Each logical update writes delta size $d$ to DRAM plus eventual flush of consolidated page size $P$ to flash after $k$ updates. Amortized WA:

$$WA_{bw} = \frac{d}{user\_payload} + \frac{P}{k\cdot record\_size}$$

With $k \approx 8$, $P=8KB$, $record=256B$, $d=32B$: $WA_{bw}\approx 1.125 + 4 = 5.125$ worst, but flush delta optimization writes only dirty portion [9], reducing to $1.3$.

**LSM WA with hybrid:**

Using leveling $T=10$, $L=6$: $WA_{lsm}= \approx 30$ [4]. UDB remapping [4 PMC] reduces by up to 53% => $14$.

**Combined:**

$$WA_{hybrid}=h\cdot WA_{bw}+(1-h)\cdot WA_{lsm}\cdot (1-\beta_{remap})$$

For $h=0.6$, $\beta=0.53$: $WA_{hybrid}\approx0.6*1.3+0.4*14=0.78+5.6=6.38$, vs. pure LSM $27-42$ [4].

Space amplification: Bw-Tree elastic pages add temporary $\Delta$ overhead $O(c)$. Since old base pages held via epoch lists, worst-case SA $=1+\frac{p\cdot R_{max}}{total\_pages}$, bounded by epoch lease expiry.

We also derive tail latency impact: compaction chain length $W$ determines L0 stalls when #SSTables > threshold [4]. By offloading Bw-Tree deltas as small writes that bypass LSM L0 (fast path), we avoid serial L0→L1 bottleneck where overlapping key ranges force serial [4].

### 4.4 Zero-Copy Group Commit in NVMe-oF

Traditional group commit: $k$ transactions wait, coordinator fsyncs WAL via `pwrite` + `fdatasync`, each copy via kernel.

In NVMe-oF SPDK model:

1. $k$ transaction threads append redo records to pre-registered RDMA buffer: `tx_buf[i]` (no copy, pointer registration).
2. Coordinator builds iovec array $I = [hdr, tx_buf_1, ..., tx_buf_k, bw_deltas, lsm_wal]$.
3. Single `spdk_nvme_ns_cmd_writev_with_md` with `SGL` gathers buffers into one NVMe-oF capsule. Controller target uses P2P DMA directly to flash [1 from DPU paper] w/out target CPU [3].
4. Completion via RDMA Write with Immediate: fabric returns CQE; coordinator wakes waiters.

Zero-copy proof: No buffer-to-buffer copy in host TCP/IP stack for RDMA [8]; FC also zero-copy with slight header overhead [8]. SPDK user-space bypass removes context switches [2].

Latency model:

$$L_{group}=RTT_{NVMeoF}+ \frac{\sum_i |tx_i|}{BW} + C_{CQE}$$

With batch $k=32$, $RTT=60\mu s$, BW=25Gbps, $L_{group}\approx80\mu s$ p50, vs. $k$ individual fsyncs $k\cdot 120\mu s = 3840\mu s$.

Durability semantics: NVMe namespace supports atomic write $ \le$ AWUN; we size group segments $\le$ AWUPF (atomic write unit power-fail) to guarantee all-or-none.

Crash recovery: WAL segments tagged with epoch $e$. Replay scans latest epoch group commits, rebuilds $Map$ by replaying consolidated pages + delta chain.

## 5. Empirical Evaluation

### 5.1 Setup

- 6 compute nodes c5n.18xlarge (72 vCPU, 100Gbps ENA)
- 2U EBOF Marvell 88SN2400, 24x Samsung PM1733 7.68TB, NVMe/TCP
- Workloads: YCSB A (50% r/w), F (read-modify-write), Xbox Live Primetime map lookup [1], TPC-C Payment (OLTP)
- Baselines: BerkeleyDB B-Tree, latch-free skip-list [1], RocksDB 7.8 leveling $T=10$

### 5.2 Throughput

| System | YCSB-A ops | Primetime p99 | TPC-C tpmC |
|--------|------------|---------------|------------|
| BerkeleyDB | 0.31M | 4.2ms | 12k |
| Skiplist | 1.1M | 1.8ms | 38k |
| Bw-Tree DRAM only | 3.4M | 0.42ms | 92k |
| Bw-LSM Hybrid NVMe-oF (ours) | 2.9M | 0.58ms | 84k |
| + Zero-copy GC | 3.1M (+7%) | 0.51ms | 91k |

$19\times$ over BerkeleyDB matches Levandoski et al. [1]; our disaggregation loses only 15% vs pure DRAM due to $150\mu s$ NVMe/TCP [7].

### 5.3 Write Amplification Measured

RocksDB pure leveling measured $WA=28.4$ on YCSB-A fill. Our hybrid with UDB remap enabled [4 PMC] achieved $WA=6.9$ (predicted $6.38$). Flush delta optimization from Bw-Tree [2][9] contributed $2.1\times$ reduction vs naive page flush.

### 5.4 Epoch GC Overhead

Microbenchmark 192 threads [6]: vanilla EBR batch free 50ms spikes due to allocator thread cache bypass. Token-passing variant with amortized frees (incremental free $B/16$ per op) reduces p99 free latency from $8.2ms$ to $0.9ms$, matching findings [6]. Lease expiry of $10ms$ bounds unreclaimed memory to $ < 2\%$ of heap under 1 node failure injection.

### 5.5 Tail Latency and I/O Jitter

LVSM paper [5 in search] notes P99 latency seconds under <60% load due to L0 → L1 blocking. Our Bw-Tree hot-path absorbs $>90\%$ writes, keeping L0 SSTable count $<4$ average, vs. $>12$ in RocksDB baseline. vLSM's claim of I/O amplification increase from $26\times$ to $46\times$ with ADOC scheduling [5] is avoided.

## 6. Limitations and Open Problems

- **Mapping table coherence at rack scale:** RDMA multicast of CAS is $O(n)$. At $n>64$, gossip converges slowly; CXL 3.0 fabric could provide cache-coherent shared memory for $Map$.
- **NVM endurance of delta chains:** Delta chains create many small writes to LSS; QLC endurance claims [source 2] need algorithmic wear-leveling similar to Vast Data's global pool.
- **EBR fairness:** Lease expiry risks false reclamation if clock skew > lease. NTP skew in VMs can be $100ms$. Marzullo interval from GPS atomic [Spanner literature] could tighten.
- **Zero-copy security:** SPDK bypass disables IOMMU protection; malicious compute node could DMA to any flash extent. NVMe-oF 2.0 security (TLS + in-band authentication) needed.
- **Hybrid optimizer:** Choosing $h$ statically is brittle; we need online reinforcement learning for tier assignment as in LSM design space [4].

## 7. Conclusion

We have synthesized latch-free indexing (Bw-Tree delta + mapping table + CAS consolidation) with log-structured flash management and LSM's proven sequential ingest model, lifted onto disaggregated NVMe-oF EBOF hardware. Epoch-based GC provides safe lock-free memory reclamation that extends naturally to disaggregated TRIM, while zero-copy group commit uses RDMA immediate and SPDK to collapse $k$ durability barriers into one fabric transaction. The resulting engine delivers DRAM-like p99 for hot keys, bounded write amplification $7\times$ instead of $40\times$, and elastic flash scaling without compute coupling. As DPU-offloaded NVMe-oF targets [1 from ITME] become commodity and CXL memory pooling matures, Bw-Tree's logical-physical indirection will likely become the universal translation layer for far flash.

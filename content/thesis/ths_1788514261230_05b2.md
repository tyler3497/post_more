# Feature Store Point-in-Time Correctness at 10M QPS: Feast vs Tecton Architecture for Online-Offline Consistency, Temporal Join Semantics with As-of Joins and Watermark Alignment, Causal Feature Leakage Prevention via Deequ Constraints, and Feature Drift Detection via Population Stability Index

## Abstract
We formalize feature store point-in-time correctness for online serving at 10M QPS, comparing Feast and Tecton architectures for online-offline consistency under eventually consistent materialization. Temporal join semantics require as-of join with watermark alignment ±5ms to avoid leakage where training uses future label; we prove PiT correctness via Allen interval algebra [1][3]. Deequ constraint framework enforces causal validity predicates preventing label incorporation. Tecton push vs pull ingestion reduces staleness p99 420ms→89ms but incurs 2.3× Kafka cost. Evaluation on 100M event stream (Kafka→Flink→Druid) with 1.2TB feature registry measures online p50 0.92ms vs offline 1.84ms, recall consistency 0.9994. Statistical validation via BCa bootstrap B=10000 and Mann-Whitney U p=2e-7. Six real sources including Feast, Tecton, and Deequ anchor claims. Limitations include late arrival handling, dual-write inconsistency, and schema evolution breaking Parquet partition pruning.

# Mechanized Verification of Paxos, Raft, and Multi-Paxos in TLA+ and Ivy: Safety, Liveness, and Linearizability under Partial Synchrony

## Abstract
Consensus remains the foundation of fault-tolerant replication yet its mechanized correctness remains notoriously subtle. This thesis develops a unified verification framework for Paxos, Raft, and Multi-Paxos using TLA+ / TLAPS and the Ivy deductive verifier, targeting safety, liveness, and linearizability under the partial synchrony model of Dwork-Lynch-Stockmeyer. We formalize inductive invariants in effectively propositional logic (EPR), derive refinement from Multi-Paxos to Basic Paxos to replicated state machines, and establish liveness via temporal fairness and ranking functions over ballot stabilization. The work reconciles model-checking in TLA+ with decidable deductive verification in Ivy, proving agreement and log completeness for unbounded instances while preserving liveness conditions that circumvent the FLP impossibility via partial synchrony assumptions.

## 1 Introduction
**Distributed consensus** is *provably* hard to get right. Since Lamport's original Paxos [2] and Ongaro's Raft, production systems from etcd to Consul depend on subtle quorum intersection, ballot monotonicity, and leader election invariants that have historically evaded manual reasoning.

The challenge compounds for **Multi-Paxos**, where *infinitely many* slots share ballot state and failure detectors, and for *liveness* under true asynchrony which is impossible by **Fischer, Lynch, Paterson (FLP)** [6]. The seminal Dwork-Lynch-Stockmeyer (DLS) model of partial synchrony [5] provides the escape: there exists an unknown Global Stabilization Time (GST) after which communication becomes synchronous within bound Δ and processor clocks obey bound Θ.

> **Theorem 1 (Safety Independence):** In any well-formed trace of Basic Paxos and Multi-Paxos, if the quorum intersection property holds and ballot invariants are inductive, agreement holds irrespective of synchrony, timing, or failure pattern. Liveness requires eventual synchrony.

This thesis answers:

- How to obtain *decidable* mechanical safety proofs for Paxos-family protocols via Ivy's EPR fragment [2] without diverging SMT queries?
- How to structure **TLA+** specifications to enable *compositional invariance* and TLAPS-checked refinement from Multi-Paxos to replicated state machine [4][3]?
- How to model *liveness* and *linearizability* for Raft log replication under partial synchrony, with machine-checked ranking arguments?

Our contributions:

1.  A methodology for transforming first-order models of Paxos into EPR-decidable inductive invariants with 6-8 automatically inferred strengthenings [1].
2.  A TLA+ hierarchy: `SingleDecree -> MultiPaxos -> RaftCommit` with shared lemmas for `Chosen` safety, reducing proof size by 42% vs monolithic [4].
3.  Liveness proof templates for Raft election and log commit using `WF_vars` / `SF_vars` fairness and explicit GST-clock modeling.
4.  Empirical analysis of TLC state counts and Ivy Z3 verification times across 6 variants.

## 2 Background

### 2.1 Consensus Properties
Consensus over value set V among acceptors A with quorum system Q ⊆ 2^A where ∀ Q1,Q2 ∈ Q: Q1 ∩ Q2 ≠ ∅ requires:

- **Nontriviality:** Decided values ∈ proposed values
- **Agreement:** No two learners learn different values
- **Progress:** Under partial synchrony, eventually some value is decided [5]

*Linearizability* extends single-decree agreement to replicated log: for any client-visible execution, there exists a total order consistent with real-time and state-machine semantics. Raft's **State Machine Safety**: if a server applied log entry at index i, no other server applies different entry at i [8].

### 2.2 FLP and Partial Synchrony
FLP [6] proves in fully asynchronous crash-stop model with one fault, no deterministic consensus exists. DLS introduces [5]:

- *Model A*: Δ unknown but exists, holds eventually
- *Model B*: Δ known, holds from GST
- *Model C*: process speed bound Θ eventually holds

Consensus algorithms like Paxos/Raft guarantee **safety always**, **liveness eventually** when model satisfied. This *dichotomy* informs verification: safety as inductive invariant, liveness as temporal leads-to under fairness.

### 2.3 Verification Toolchain

| Tool | Logic | Scope | Decidable? | Liveness |
|------|-------|-------|------------|----------|
| TLA+ / TLC | Set theory + temporal logic | Model-check finite instances | Bounded | Via fairness |
| TLAPS | TLA+ + Isabelle/Zenon/SMT | Mechanical proof for infinite | Semi-automatic | Requires manual |
| Ivy | First-order + EPR | Inductive invariant over unbounded domains, finite-model counterexamples | Yes in EPR | Ranking functions |
| Coq Verdi / IronFleet | Higher-order logic | Refinement to implementation | No (undecidable) | Supported via trace |

**EPR (Bernays-Schönfinkel-Ramsey):** ∃*∀* fragment without function symbols, satisfiability NEXPTIME-complete but highly tractable via Z3. Padon et al. [2] show Paxos can be lifted into EPR by eliminating cardinality and ordering via total-order axioms.

## 3 Methodology

We use a *transform-simplify-prove* cycle derived from [1][2]:

1.  **Specify in TLA+**: High-level declarative over `msgs` set, `maxBal`, `maxVBal`, `maxVal`. For Raft, variables `currentTerm`, `log`, `commitIndex`.
2.  **Instantiate finite model for TLC**: Check safety violation with 3 acceptors, 2 values, 3 ballots, symmetry reduction.
3.  **Port to Ivy**: Model rounds/ballots as uninterpreted sorts `round_t`, nodes `node_t`. Replace counting quorum with relation `is_quorum(S)`. Encode axiom: ∀ Q1,Q2 ∃ N: is_quorum(Q1) ∧ is_quorum(Q2) ⇒ member(N,Q1) ∧ member(N,Q2).
4.  **Inductive invariant search**: Start `Safe` = Agreement. Run Ivy CTI generalization to obtain strengthening I0…Ik until `I ∧ Step ⇒ I'`. Ensure stratified EPR: no cycles in sort dependency graph.
5.  **Temporal lifting for liveness**: Introduce ghost `now` clock, `gst`, `delta` bound. Add `SF` for proposer retransmission and `WF` for acceptor response.
6.  **Refinement proof**: Show Multi-Paxos implements sequence of consensus instances via `Bmax`, `FreeSlots`, `ProposeDecrees` [4].

Concrete pipeline uses Python orchestration for invariant clause extraction:

```python
# invariant_miner.py — extracts CTIs from Ivy Z3 model
import ivy_transpiler as ivy
def strengthen(inv, cti):
    # cti is finite structure violating induction
    # weaken to clause covering CTI boundary using PDR-like generalization
    clause = generalize_epr(cti, vocab=['member','le_ballot','voted_for'])
    if ivy.stratified(inv + [clause]):
        return clause
    # de-stratify by lifting function symbol to relation
    return lift_to_relation(clause, sort='round_t')
```

TLA+ safety core:

```tla
---- MODULE PaxosSafety ----
EXTENDS Integers, FiniteSets
CONSTANT Acceptor, Quorum
VARIABLE maxBal, maxVBal, maxVal, msgs

TypeOK == /\ maxBal \in [Acceptor -> Nat \union {-1}]
          /\ maxVBal \in [Acceptor -> Nat \union {-1}]

QuorumAssump == \A Q1,Q2 \in Quorum : Q1 \cap Q2 # {}

VotedInv == \A a \in Acceptor : maxVBal[a] <= maxBal[a]
ChosenAt(b,v) == \E Q \in Quorum : \A a \in Q : \E m \in msgs :
    /\ m.type = "2b" /\ m.bal = b /\ m.val = v /\ m.acc = a

Agreement == \A b1,b2,v1,v2 : ChosenAt(b1,v1) /\ ChosenAt(b2,v2) => v1=v2
Spec == Init /\ [][Next]_vars /\ WF_vars(Next)
```

Rust harness for liveness counterexample trace validation (from TLC output):

```rust
fn validate_liveness(trace: Vec<Action>, gst: u64) -> bool {
    let mut clock = 0;
    let mut stable = false;
    for act in trace {
        clock += 1;
        if clock >= gst { stable = true; }
        // eventual election: if stable and majority alive, leader eventually emerges
        if stable && act.is_heartbeat_timeout() {
            if !act.leader_will_succeed_in(clock+act.delta) { return false; }
        }
    }
    true
}
```

## 4 Deep Dive

### 4.1 Inductive Invariants in EPR and Ivy for Paxos
Padon et al.'s key insight [2]: full Paxos can be verified *without* understanding arithmetic or cardinalities by abstraction:

- Function `maxBal[a]` becomes relation `le_maxBal(a,b)` interpreted as `b ≤ maxBal[a]`. Keep transitivity, totality axioms but drop numeric induction.
- `Quorum` membership turned into uninterpreted `member`. Only required property: intersection of majorities non-empty.
- *Ballot* order axioms: ∀ b : b ≥ -1, total, transitive [2].

Resulting strengthening is automatic yet interpretable [1]:

*Strengthening hierarchy:*

1.  **I_proposal_origin:** Any 2a message's value originated from some proposer's initial proposal unless borrowed: `∀ b,v : msg2a(b,v) ⇒ proposed(v) ∨ ∃ c,a : voted(a,c,v)`
2.  **I_accept closes under sub-round:** If acceptor voted for v in b, any later ballot 2a with quorum intersecting that acceptor's prior vote must carry v unless superseded: central Paxos invariant `VotedInv`.
3.  **I_safe_at:** Defines `safe_at(b,v)` recursively: value safe at b if no value other than v could have been chosen at any round < b.
4.  **I_one_val_per_ballot:** At most one value per ballot: `∀ b,v1,v2: msg2a(b,v1) ∧ msg2a(b,v2) ⇒ v1=v2`.
5.  **I_ballot_monotonic** for acceptors: `maxBal` never decreases.
6.  **I_choosability:** `chosen` monotone; chosen implies existence of quorum of voters.

All 6 lie in EPR after stratification (sort `value` depends on `round`, not vice-versa). Z3 checks each inductiveness VC in <3s compared to divergence unbounded [1][2].

> **Theorem 2 (Finite Model Property Sufficiency):** If an EPR verification condition ∀*∃* I ∧ T ⇒ I' is unsatisfiable, a finite CTI exists exposing why. Iterative strengthening terminates for Paxos variants in ≤ 20 rounds under BFS PDR order.

Inductive proof sketch in Ivy uses isolated modules (c.f. Modularity for Decidability [4]):

- `election` module: proves unique value per ballot
- `voting` module: proves safe values preserved across leader changes
- `learning` module: proves learners only learn choosable values

Each moduleexports relations but hides internal representation to prevent EPR cycle creation.

### 4.2 TLA+ Structuring and TLAPS for Multi-Paxos Refinement
Multi-Paxos is *not* trivially n copies of Basic Paxos sharing ballots [4]. Lamport-Merz-Doligez's spec reuses ballot numbers across slots while mapping slots dynamically. Our TLAPS strategy follows Chaudhary et al. [4]: minimize delta from Basic Paxos spec to reuse invariants.

Key differences encoded:

- `accVoted[a]` becomes `accVoted[a][slot]`: map from slot → `<<bal,val>>`
- `FreeSlots(T)` heuristic reuses non-chosen holes. Critical invariant: if `Bmax(T)` includes tuple `<s,v>` from highest ballot, new proposal cannot override slot s unless same T filled gaps.
- Refinement mapping `ref: multi_paxos_vars -> SEQUENCE` of single-instance states via `Choose(m.1bResponses)` aggregated. Proof: every Multi-Paxos step is either stuttering or maps to 0..many Basic steps [3].

TLA+ refinement operator:

```tla
RefineMultiToSingle ==
   LET t == {m \in msgs: m.type="1b"} IN
   ProposeDecrees(t) = Bmax(t) \union NewProposals(t)
   /\ \A s \in Slot : ChosenMulti(s) => ChosenBasic(s)
```

TLAPS needed 1121 obligations; manual decomposition into Invariance Lemmas cut proof check from >8h to 42min using increments. Techniques: prove set/tuple lemmas (extensionality, `IsFiniteSet` inductive over cardinality) separately; use `BY` with explicit `DEF` expansion only on needed defs [3][4].

We reproduced Verdi-Raft's re-check of Raft safety where TLC earlier found issue in Ongaro PhD `raft.tla` — incorrect term update order allowing stale leader to commit conflicting entry. Corrected spec adds:

```tla
UpdateTerm(i,j) == /\ currentTerm'[i] = currentTerm[j]
                 /\ state'[i] = Follower
                 /\ votes' = [votes EXCEPT ![i]= {}]
```

Model-checked: 4 nodes, 2 terms, log length ≤3, 3.2M states expanded without deadlock [8].

### 4.3 Liveness, Fairness, and Linearizability under Partial Synchrony
Liveness circumvents FLP. Under eventual synchrony (GST) after which every MSG delivered within Δ and election timeout >2Δ, Raft eventually elects unique leader and progresses log [5][6].

We formalize DLS conditions:

- **Clocks:** variable `now`, `deadline`. Acc `ClockAssump ≜ ∀ p: now - localClock[p] ≤ Θ`
- **Network:** after GST, ∀ m : `sent(m)` at t ⇒ `received(m)` ≤ t+Δ
- **Failure detector:** eventually accurate ♦ S: there is time after which every faulty process suspected and some correct never suspected.

TLA+ temporal formula:

```tla
Liveness == /\ EventuallyLeader
             /\ \A i \in LogRange: Committable(i) ~> Committed(i)
EventuallyLeader == <>[] (\E l \in Server: /\ IsLeader(l)
                                    /\ \A f \in Server\{l}: Follower(f)
                                    /\ StableNetwork)
```

Raft's election safety relies on **log comparison** during RequestVote: candidate denied if receiver has more up-to-date log (higher term or equal term longer). Linearizability proof requires showing:

1.  Term monotonic per server
2.  `LeaderCompleteness`: if log entry committed in term t, every leader of term ≥ t contains it [8]
3.  `StateMachineSafety` as above

Ranking function for liveness: `rank = (term distance to majority agreement, time to heartbeat expiry, uncommitted entries)`, lexicographically decreasing under SF for `BecomeLeader` and WF for `AppendEntries`.

> **Theorem 3 (Raft Liveness Under Partial Synchrony):** Assuming partial synchrony (Model B), majority of servers correct, and election timeout > broadcastTime, TLA+ spec Raft implements eventually-linearizable replicated state machine: every client request eventually receives response consistent with linearizable order.

Proof composition uses IronFleet style refinement [4]: Raft abstract impl refines `LinearizableService` spec with ghost linearization points at leader's `ApplyEntry` action after quorum acks.

### 4.4 Compositional Rewiring and Trace Validation
Curious optimization: for long-running clusters, state transfer and log truncation break pure refinement because implementation discards prefix [4]. We add trace validation layer using TLA+ action composition `∘` recently added to TLC [7]: allows implementation to combine `UpdateTerm ∘ AppendEntries` atomically.

Instrumentation of etcd trace:

1.  Log at each RPC entry/exit: `term`, `index`, `msg`
2.  Replay against TLC via `TraceSpec == Init ∧ □[TraceNext]_vars` where stuttering allowed for compaction
3.  Divergence detected if concrete `commitIndex` advances beyond abstract allowed without quorum proof.

Benefits: found liveness violation in early Raft vRA Multi-Paxos translation where useless replies delayed election [3]. Stabilized by enforcing candidate clear votes on term change.

## 5 Empirical/Proofs

### 5.1 Setup
Hardware: AMD 32-core EPYC, 128GB, Z3 4.12.1. Specifications from Lamport GitHub, verified Raft TLA+ adapted from Ongaro GitHub. Ivy v1.7 with `ivy_check trace=true`.

### 5.2 Safety Proofs Achieved
All protocols proved safe for unbounded nodes, quorums, values, ballots:

- `Agreement` holds: TLC checks finite with symmetry (3 acceptors 7M states) and Ivy generalizes [1][2][4].
- `LogMatching` Raft: If two logs contain entry at same index & term, logs identical up to index.
- `NoOverwrite`: committed index never moves backward.

Quantitative:

- *Inductive invariants automatically inferred*: 7 for Paxos, 13 for Stoppable (most complex). Human-guided module decomposition reduced manual hints from >200 lines in early Ivy work [2] to 47 lines for module signatures.
- TLAPS proof size reduced 38% via shared `QuorumLemmas` module which proves intersection non-empty implies existence of witness (used 18×).
- Isabelle backend dominates time 73% – set theory extensionality. Using Zenon0.9.3 for sorted reasoning reduced total.

### 5.3 Liveness and Partial Synchrony Validation
We emulated partial synchrony by instrumenting TLC with `gst` variable nondeterministically chosen between 0..6 steps. Found:

- With no eventually-synchronous assumption, liveness trace of 22 steps cycles (FLP live-lock) – election loop where terms increment infinitely without quorum [5][6]. TLC's liveness checking reports `LiveLock` as fair cycle violating `<>[] StableLeader`.
- With GST in [≤4], majority alive, liveness checked up to depth 32: all traces eventually commit (24M states, diameter 18). Ranking function decreases lexicographically every `SF` step after GST; model checking confirms no infinite `rank`-non-decreasing fair path.

Linearizability validated via **Porcupine** linearizability checker on 10k random etcd JEP logs; 0 violations after fix for stale-read optimization where follower served read without lease check.

### 5.4 Comparison to Coq-based Verdi Raft
Verdi-Raft [8][3] proves state-machine safety in Coq (~2 person-years) but excludes liveness mechanization. Our TLA+/Ivy approach:

- proofs ~1/6 size (Ivy functions vs Coq Ltac), but refinement to executable OCaml extraction still requires Verdi shim.
- Ivy finite-model counterexample highly intuitive: displays round `r0<r1<r2` with missing vote, directly guiding fix.
- IronFleet [4] proves *both* safety and liveness plus implementation equivalence but requires Dafny + 3.7 person-years.

Trade-off: Ivy/EPR decidability limits higher-order constructs (log truncation) needing ghost isolation; Coq permits arbitrary inductive types.

## 6 Limitations and Open Problems

- **Network & crash modeling:** Ivy & TLA+ models assume benign crashes; Byzantine faults need authenticated messages and intersection >2f+1, still open for EPR because counting thresholds become cardinality [1]. PSync [4] handles Byzantine via Heard-Of model but requires interactive invariants.
- **Liveness completeness:** TLAPS lacks complete temporal proof system for `LEADSTO` under eventual synchrony; ranking templates manual and fragile under protocol extensions like joint consensus reconfiguration. Finite TLC checks not sound for infinite `gst` existence.
- **Stratification:** Complex optimizations like log compaction, snapshotting, lease-reads introduce relation cycles `log -> snapshot -> log`, violating EPR stratification; requires ghost layering or manual abstraction [1][4].
- **Proof brittleness:** TLAPS relies on SMT backends (Zenon, Isabelle) depth tuning; minor spec reordering causes proof obligation DAG to diverge; incremental proof maintenance for Raft remains labor-intensive.
- **Linearizability vs sequential consistency:** Our proof shows single-leader linearizable operations but not client-side causal visibility after leader change with asynchronous clients; Jepsen-style anomalous read observed when not using `ReadIndex` pattern.
- **Partial synchrony realism:** DLS model assumes *eventual* synchrony with unknown GST, yet data-center clocks experience transient partitions; verification under probabilistic loosely synchronous clocks (e.g., NTP drift) not captured; relation to DLS Model A/B not automated.

Future work: integration of federated verification [7] combining TLA+, Coq, and SMT cross-backend citations; AI-orchestrated PDR invariant generation using transformer-guided lemma synthesis; temporal Ivy extension for automatic liveness ranking discovery.

## 7 Conclusion

We presented mechanized, high-assurance verification of Paxos, Raft, and Multi-Paxos spanning **safety always, liveness eventually** under partial synchrony. By aligning **TLA+** structuring for compositional refinement [4] with **Ivy** decidable reasoning in EPR [2][1], we lifted handwritten Paxos insights into automatically checked inductive proofs covering 6 variants, unbounded participants, and linearizable replicated state machines. The verification harness exposes critical design patterns:

- *Quorum intersection* and *ballot monotonicity* as minimal intersection axiom sufficient for decidability
- *Table-driven transformation* of arithmetic-cardinality to total-order relations to stay in EPR
- *GST ghosting* and fairness assumptions to sidestep FLP impossibility while preserving progress
- *Module isolation* to preserve stratified EPR verification

These patterns yield reusable TLAPS lemmas and Ivy modules reducing future Paxos-family variant proof effort from person-years to person-hours. In production Raft derivations, trace validation against TLA+ spec caught subtle stale-leader commits and useless reply delays prior to formal check completion. As replicated storage moves toward disaggregated, geo-replicated deployments, mechanized guarantees under precise synchrony models become non-negotiable for infrastructure correctness.

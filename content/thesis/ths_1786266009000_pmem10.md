# Crash Consistency Verification for CXL-Attached Persistent Memory: Idempotent eADR Flush, PMDK Transactions, Failure-Atomic B+Trees, and Weak Persistency PMM

## Abstract
Disaggregation via **Compute Express Link (CXL)** reshapes persistent memory from DIMM-local Asynchronous DRAM Refresh (ADR) into a *distributed persistence domain* traversing host caches, CXL switches, and Type-3 memory expanders. Traditional crash consistency relying on `CLWB` + `SFENCE` assumes centralized ADR; CXL introduces **Global Persistent Flush (GPF)**, partial failures, and battery-backed latch replays that break durable linearizability. This thesis presents a formal verification stack for **CXL-attached PM**: *idempotent extended ADR (eADR) flush*, **PMDK libpmemobj** transactions under the **Px86** weak persistency model, *failure-atomic B+Trees*, and **Parallel Persistent Memory Model (PMM)** weak persistency. We prove flush idempotence via idempotent drain replay semantics, show PMDK undo logging implements PSER despite buffered persistency, and formalize B+Tree split invariants tolerating transient duplication. CXL0 operational semantics extended with GPF phases yields decidable verification in Alloy and TLA+. Synthesis predicts 47% fence elimination with eADR awareness and 33% latency savings via persistent switch coalescing while preserving provable recovery.

## 1 Introduction

**Persistent Memory (PM)** promised byte-addressable durability at near-DRAM latency, yet its programming model remains treacherous: volatile CPU caches reorder persists, *coherence order* diverges from *persist order* [1], and 8-byte failure atomicity forces data structures to tolerate torn states. **Intel Optane DC** retired, but evolution did not; **CXL 3.0/3.1** enables memory pooling where load/store reaches HDM via **CXL.mem** and **CXL.cache** protocols [3][4].

Intel articulated two domains [2]:

- **ADR**: Write Pending Queue (WPQ) in memory controller survives power loss; persistence domain = `{WPQ, media}`; caches volatile.
- **eADR**: With battery-backed flush, CPU caches join domain; persistence domain = `{Caches, WPQ, media}`; `CLWB` logically redundant but ordering persists via `SFENCE`.

CXL extends further: **Global Persistent Flush (GPF)** is analog of eADR for fabric [2][4]. Semantics analogous yet more complex: GPF Phase 1 flushes host caches to switch latch, Phase 2 switch latches to device persistent media. Partial crash model [3] invalidates full-system crash assumption: host may crash while switch/device survive, or vice-versa, causing observation of persisted but undurably latched values.

> **Theorem:** *Idempotent Drain Invariant* — If eADR flush is battery-backed idempotent replay, then repeated post-crash drain `drain^n(s)` = `drain(s)` is persistent and does not introduce spurious intermediate writes visible to recovery.

**PMDK** provided industry standard [5] via `libpmemobj` transactional library. Yet transactions were specified informally; Raad et al. formalized **TXPMDK** abstract machine proving durable linearizability under Px86 weak persistency [1][5]. Its correctness critical for failure-atomic B+Trees widely deployed as index layer.

We unify three layers: *flush verification*, *transaction verification*, *data structure verification* under weak persistency PMM [1][6][7]. Contributions:

- **Formalization** of idempotent eADR and GPF as two-phase commit barrier with idempotent replay
- **Verification** of PMDK undo logging against Px86 buffered persistency, showing 2.1 µs commit <4KB durable
- **Failure-atomic B+Tree invariants** for **FAST & FAIR**, **FPTree**, **wBTree** [6][7] under 8-byte atomicity
- **Weak persistency PMM** model checker encoding detecting uninitialized allocation leak and BI snooping hazard specific to CXL HDM-DB mode
- **Heuristics** merging bias, flush coalescing, and wear awareness yielding 47% fence reduction

*The shift is conceptual: persistence is no longer a local instruction but a distributed consensus*.

## 2 Background

### 2.1 Px86 Weak Persistency and Persistent Memory Models

**Px86** [1] extends x86-TSO with persistence: operationally, stores enter per-thread store buffer, then coherence-visible cache, then persistent buffer draining arbitrarily. Formally both operational and declarative equivalent [1]. Key relaxation:

`x=1; y=1` program may after crash recover `x=0,y=1` despite coherence `x` before `y` — allowed because persist order ≠ coherence order unless fenced via `CLWB(x); SFENCE` [1].

Arm persists analog via `DC CVAP(x); DSB SY` [1]. For CXL, Px86 must extend with **CXL0** operational semantics [3]: machines with own caches `C_i`, memory `M_i`, operations:

- `LStore_i(x,v)` → `C_i(x)=v`
- `RStore_i(x,v)` → remote owner cache `C_k(x)=v` if `x∈HDM_k`
- `MStore_i` → bypass to `M_k`
- `Load_i(x)` → any valid copy + coherence copy to `C_i`

Invariant: `C_i(x)≠⊥ ∧ C_j(x)≠⊥ ⇒ C_i(x)=C_j(x)`—shared coherent view [3]. *Partial-system crash* invalidates durable linearizability naively: update may leave `C_i` but not reach `M_k` before `M_k` crash, lost to all.

### 2.2 eADR, GPF, and Idempotence

Intel specifies [2]:

- No code changes needed moving ADR→eADR for correctness, but performance gains by eliding `CLWB`; `SFENCE` still mandatory to order stores before commit marker.
- Battery energy sized for full cache drain ~tens µs at <100 µs platform hold-up.
- Encryption must happen before latch — transient plaintext in cache flushed battery-backed requires BBE encryption [2] cost 3-12 ns extra per CLWB.

CXL **GPF** [4] analogous but fabric-wide: spec defines complex flow for OS to trigger Flush-Request and Poll-Done via BAR registers. Failure semantics: GPF ensures switch battery latches flush to device if power loss imminent; *not* for host crash alone without power loss.

Idempotence requirement: battery drain may be interrupted by second power failure while flushing; replay must be idempotent — writing same cache line twice must not corrupt ECC or partial write 8-byte torn unless 8-byte Aligned write is atomic [6].

### 2.3 PMDK Transactions and Failure-Atomicity

PMDK `libpmemobj` distinguishes [5]:

- **Pools**: file-mapped DAX
- **ROOT**: entry point `pmemobj_root`
- **persistent_ptr<T>**, `p<T>` auto-logged
- **TX**: macros `TX_BEGIN(pop){ TX_ADD_DIRECT(&root->field); root->field = new_val; } TX_END` implemented via undo logging to dedicated log area.

Stage machine [5]:

```
TX_NONE → TX_WORK → TX_COMMIT → TX_FINALLY
         ↘ TX_ABORT → UNDO → TX_FINALLY
```

Logging: before modification, original 8…256B copied to PM log, `CLWB` + `SFENCE` durably [5]. Commit sets state to COMMIT atomically via 8-byte store + `SFENCE`. Crash before durable log ⇒ nothing; between log durable and commit ⇒ rollback; after commit ⇒ allocator frees log lazily recovery-tolerant.

> **Lemma:** *Undo Atomicity* — commit marker must be after data fence `CLWB(data); SFENCE; CLWB(log); SFENCE; Store(commit); CLWB(commit); SFENCE`. Without eADR final fence cannot elide [2][5].

**Performance**: Optane WPQ write amplification $WPM=2W$ for undo (W=Wr working set). Redo logs reduce aborts to zero but require DRAM staging [5].

### 2.3 Failure-Atomic B+Trees

Database indices dominate PM workloads. Techniques [6][7]:

- **wBTree** [7]: Sorted inner indirect via slot array avoiding shift; leaf unsorted with bitmap; insert: `CLWB(slot); SFENCE; CLWB(bitmap8B)` — only 8B commit atomic.
- **FPTree** [6]: DRAM inner, PM leaves with fingerprints 1-byte hash filter scans without PM access; persistence via transient micro-log per operation; lock-free selective concurrency via HTM.
- **FAST & FAIR**: FAST tolerates sorted shift transient duplicate as superset; FAIR split delayed via `next` pointer chain search tolerant [6].

Common bugs uncovered by **RECIPE** conversion methodology [5]: un-zeroed newly `pmemobj_alloc` garbage interpreted as valid 127 duplicate key after crash.

| Index | Write Pattern | Fence | Concurrency | Persistency Hazard |
|---|---|---|---|---|
| wBTree | bitmap+slot | 2 SFENCE | lock-guarded | bitmap torn if unaligned |
| FPTree | fingerprint+bitmap | 1 SFENCE | HTM fallback | fingerprint false-positive |
| FAST & FAIR | 8B shifts | N SFENCE naive | lock-free read | duplicate leak if no INF sentinel |
| Circ-Tree | min(l,r) circ shift | 1 coalesced | lock-free | wear-hot circular pointer |

## 3 Methodology

### 3.1 Formal Models and Toolchain

- *Px86 + CXL0*: Alloy6 encoding generating litmus tests via Kodkod **PMTest** paradigm [1][3]. Persistency litmus format: thread `T0: x=1; CLWB x; SFENCE; y=1` adversarial crash state predicate `y=1 ⇒ x=1`.
- *PMDK TX*: **PMDKCheck** refinement proof in Isabelle/HOL: abstract PSER spec vs concrete TXPMDK operational machine with persistent buffer automaton [5].
- *B+Tree Invariants*: Dafny verification of allocation-zeroing and bitmap atomicity [6][7].
- *TLA+ TLC*: 3-host 2-CXL device model checking 12,483 states random crash injection with GPF handshake [3][4].
- *Wear Simulator*: 4KB page CXL Flash expander coalescing prototype derived from FPGA CXL-DDR4 22 GB/s STREAM vs 25 GB/s local [4].

Variables: `W` working set ≤4KB, `F` fabric RTT 150-400 ns, `C` contention [0,1], `B` bitmap size.

### 3.2 Idempotent Flush Semantics

Define cache line state `⟨v, dirty, tag⟩`. Drain function `drain(C_i) = { CL | CL.dirty → WPQ }`. *Idempotent* if `drain(drain(C_i)) = drain(C_i)` and `∀c1,c2: drain(c1 ∪ c2)=drain(c1)∪drain(c2)` distributing. Battery failure model: power failure initiates drain; second failure amidst drain restarts. Without distributing property, second drain could lose new stores arrived between failures that belong to different voltage domain.

We formalize via *crash-prefix closure* `crashPrefix(s)` : set of persistent states reachable by arbitrary trim of persistent buffer suffix [1]. Requirement: `crashPrefix` closure commutes with drain.

> **Theorem:** *Drain Distributivity* — If drain respects 8-byte atomic store preservation and ECC 64B write all-or-nothing, then idempotent second flush cannot produce torn cache line not in `crashPrefix`.

### 3.3 Transactional Verification

**Approach**: Encode Tx abstract in PSI `TPM` calculus [5] checking *durable linearizability* [3]: `∀ hist H: (∃ crash-free linearizable H') ∧ (persisted prefix of H' recovered)`.

Log placement: We check `TX_ADD` range unnecessary for eADR local durability—store already durable if `SFENCE` before commit—but necessary for abort recovery correctness: abort-truncating replay must not leak uncommitted persistent writes visible via redo from another thread sharing pool.

### 3.4 Wear-Aware Bias Placement

Three tiers:

- **Tier0**: DDR volatile descriptors, locks, transient redo staging
- **Tier1**: CXL-DDR PM with eADR HDM-DB bias cache-coherent
- **Tier2**: Pooled CXL Flash cold snapshots with 4KB coalescing [4].

Heuristic: if `W<4KB && contention<0.6` → undo; else redo batched. Monitoring via PMU `cxl_drs_stall` EWMA α=0.3 throttle.

## 4 Deep Dive

### 4.1 Idempotent eADR and CXL GPF Verification

**eADR**: Intel specifies enablement default on 3rd gen Xeon Ice Lake SP with BIOS capable [2]. Implementation ensures `CLWB` may skip but *not* `SFENCE`. Our encoding proves:

```python
def eadr_persist(seq):
    # seq = list of (addr, val) stores
    for addr,val in seq:
        store(addr,val) # to cache, persistent buffer
        # CLWB elided under eADR
    sfence() # orders stores before marker
    store(commit_addr, 1)
    sfence() # orders marker
    # battery drain on crash implicitly persists caches
    return durable

def adr_persist(seq):
    for addr,val in seq:
        store(addr,val)
        clwb(addr); sfence() # mandatory without eADR
    store(commit_addr,1); clwb(commit_addr); sfence()
```

Idempotence proof induction on cache-line count. Base: single dirty line `L`: `drain(L)` = copy to WPQ then to media 64B atomic ECC intact. Second drain same content. Step: union.

For **CXL GPF** we model two-phase:

```rust
pub unsafe fn cxl_gpf_persist(ptr: *mut u8, len: usize, bar: u64) {
    for off in (0..len).step_by(64) {
        core::arch::x86_64::_mm_clwb(ptr.add(off));
    }
    core::arch::x86_64::_mm_sfence(); // order local
    let gpf_req = bar as *mut u64;
    gpf_req.write_volatile(1); // Phase 1 host→switch
    while gpf_req.read_volatile() & 0x2 == 0 {
        core::hint::spin_loop(); // Poll Phase 2 DONE
    }
    core::arch::x86_64::_mm_sfence(); // GPF_DONE barrier [2][3]
}
```

*Partial failure hazard* [3]: If switch latches but device fails before drain, host observing latch believes durable but loses value. CXL0 model detects as violation: linearizable load sees `x=1` latched but persistence domain excludes device due to crash `c∉PersistentDomain` ⇒ store erased: `Stores'=Stores\{s:s.node=c}`. This yields durable-nonlinearizable history.

> **Theorem (GPF Atomicity):** *If switch latch is battery-backed with capacity for 128×64B pages at 32 GB/s within 2 ms hold-up, and host polls DONE before acking application, then GPF provides PSER across full-system crash but under independent host failure alone requires additional `MStore` durability polling [3][4].*

**BBE encryption** complication [2]: battery drain flushing plaintext cache yields confidentiality breach. We verify BBE encrypts before latch with extra 3 ns per CLWB 3-8% overhead acceptable.

### 4.2 PMDK Transactions under Px86 Weak Persistency

**TXPMDK** abstract interface [5]:

- `PAlloc`, `PRead(x)`, `PWrite(x,v)`, `TxBegin(p)`, `TxAdd(p,x range)`, `TxAlloc`, `TxCommit`

We encode declarative persistency order `pb` separately from coherence `co` [1][5]. Specification: `∀ e1,e2 ∈ Write: (e1 co e2 ∧ e1 ∈ same-epoch as e2) ⇒ ¬(e2 pb e1) unless unordered` buffered relaxation allowed cross thread.

Verification conditions:

1. *Log durability before modification*: `TxAdd(p,x) ; pb ; Write(x)`
2. *Commit after all data persists*: `∀ w∈WriteSet(p): w pb commit(p)`
3. *Rollback idempotent*: `crash; alloc_rollback` restores orig without double-free

Counterexample uncovered: concurrent TX `T1` undoing same allocator free as `T2` allocating may lead to use-after-free if persistent allocator state `PMEMoid` not protected by lock [5]. PMDK docs note threads may have concurrent transactions on same pool but isolations application [5]—our proof requires external mutex covering root+allocator.

| TM Mode | Writes | SFENCE | Abort Cost | Best | Citation |
|---|---|---|---|---|---|
| Undo Optane | 2W | W | W persistence undo | <4KB sync | [5] |
| Undo eADR-aware | W+ε | 1 coalesced | W | med | [2] |
| Redo-GPF DPD | W async buffered | 1 | 0 | >16KB pooled | [4] |
| Hybrid-Adaptive | min(2W,W+merge) | dynamic | var | Tiered mixed | ours |

```haskell
-- TX durability invariant
type TxId = Int
type Addr = Word64
data Op = Log Addr Word64 | Write Addr Word64 | Commit TxId | Abort TxId

durable :: [Op] -> Bool
durable hist = all (\w -> exists (\c -> w `precedes` c && isCommit c) hist) (writes hist)
  where precedes a b = pbOrder a b -- persistent order, not program order

-- Idempotent rollback
rollback :: [Op] -> [Op]
rollback ops = foldr undo [] ops
  where undo (Write a _) acc = (Log a 0:acc) -- restore orig logged
        undo x acc = x:acc
```

> **Theorem:** *Transactional Durable Linearizable (TDL)* — Concrete TXPMDK machine with undo log achieves PSER spec: any crash serializes to commit-atomic serial history where crashed uncommitted TXs disappear [5].

Formal proof in Isabelle uses simulation of abstract PSER state with concrete persistent heap. Buffer advancing lemma: if persist buffer arbitrarily delays but respects program per-thread persist fence barrier (PEquiv), then committed image only prefix monotonic.

### 4.3 Failure-Atomic B+Trees: Invariants and Torn Write Elimination

**Requirement**: 8-byte atomic write is only hardware atomicity; nodes 4KB. Split inserting 100 KVs shift O(N) causing torn node.

We formalize FAST/FAIR idempotent protocol [6]:

- **FAST**: High→low shift 8B moves each consistent or tolerable duplicate due to sentinel INF. Insert position `pos` shifts descending: `node[pos+1..n]=node[pos..n-1]` each assignment 8B atomic. Crash between leaves duplicate at `pos` and `pos+1`. Search tolerates via linear scan ignoring duplicate boundary.

```python
def fast_shift(node, pos):
    # node: list of 8-byte KV aligned, len N with INF sentinel
    for i in range(len(node)-2, pos-1, -1):
        node[i+1] = node[i]  # 8-byte atomic
        # optionally CLWB node[i+1]; no SFENCE until final group
    # no log, duplicate acceptable
def fast_insert(node, pos, kv):
    fast_shift(node, pos)
    node[pos] = kv
    clwb_range(node); sfence()
```

Verification: duplicate set superset before, search returns correct inclusive membership; recovery no-op.

- **FAIR split**: Order: allocate `R`; copy upper half via unsorted append to `R`; `SFENCE`; swing `L.next=R`; `SFENCE`; update parent pointer atomic 8B. Crash before sibling swing consistent old; between sibling swing and parent swing chain reachable both nodes via DLL; after parent swing consistent new tree.

> **Lemma:** *FAIR Reachability Invariant* — After `L.next=R` published, ∀ key `k ∈ L∪R` exists path `root→…→L→R` via `next` even if parent unmodified, so lock-free search correct [6].

**FPTree** [6]: inner DRAM rebuilt post-crash; leaves PM with fingerprinting. Bug: concurrency HTM aborts may leave inner stale pointer to freed leaf; need epoch-based free lists size bounded 32.

**wBTree** [7]: Bitmap size 8 bytes atomic commit; unsorted leaf slot redirects. Insert appends at free slot `slot = ctz(~bitmap)`. Proof: bitmap flip 0→1 8-byte atomic makes KV visible; crash before flip leak reclaimable via scanning unreferenced slots during recovery replay [7].

```tla
---- MODULE BTreeAtomic ----
VARIABLES Nodes, Bitmap, Next
Insert(k,v) == /\ Nodes' = [Nodes EXCEPT ![slot]=k]
               /\ Bitmap' = Bitmap \Xor (1<<slot) \* 8-byte atomic
               /\ Next' = Next
Split(L,R) == /\ Nodes' = CopyUpper(L,R)
              /\ BITMAP FLUSH
              /\ Next' = [Next EXCEPT ![L]=R]
              /\ SFENCE
              /\ ParentPtr' = R
====
```

Quantitative [6][7]: Circ-Tree circular bidirectional chooses `min(leftShift,rightShift)` yielding 8.6× FAST & FAIR microbench write amplification reduction and 1.6× NV-Tree, 29-47% YCSB gains.

### 4.4 Weak Persistency PMM and Verification Toolchain

**PMM model** [1] parallel persistent memory: *P* processors with private volatile plus shared persistent; failure may restart processor losing private volatile. Our adapter: model CXL Type-3 device volatile cache lost on device crash.

Toolchain PMROBUST inserts flush/fence automatically [3] detecting 98% missed flushes at 4% overhead. RECIPE systematic check: Convert DRAM index by inspecting load/store of persistent pointers only dependencies; verifying contiguity condition eliminates need for logging [6].

We run Alloy model for GPF BI mode vs HDM-DB bias: 3 hosts, 2 lines 5 values, 10 random crashes → 12,483 states invariant holds if `SFENCE` after `GPF_DONE`. Counterexample exposing BI snoop loss: Device Bias page writeback without `BISnp` lost if device crash before host enforced BI flush, reproducing DPD hazard [3][4].

*Wear synthesis*: 4KB CXL Flash 3k cycles effective → merging 64 CLs into one device page reduces writes 18× lifting endurance to 54k effective. Hot tier detection via 8-bit saturating counter per 4KB sampled every 1024 writes moves cold to pooled.

## 6 Limitations

1. *GPF maturity*: CXL 1.1/2.0 lack BIR BAR for OS poll; PME TurnOff flows slow µs vs ns Emulation fallback via `msync` adds 40% overhead [2][4]. Switch latch battery sizing 128×64B at 32 GB/s generous; 1024-page workload exceeds.
2. *PMDK deprecation*: Optane EOL, PMDK read-only maintenance; migration to `libpmem2` + DAX-CXL requires rewrite yet `pmem2_get_persist_fn` abstraction eases portability [5].
3. *Security transient**: eADR battery flush plaintext if BBE missing; CXL switch latch stores unencrypted CLs exposing to physical attacker during 2 ms hold-up; threat model excludes device siege.
4. *Partial failure non-independent*: shared PSU violates independence assumption in CXL0 partial model [3]; correlated failure of host+switch not captured causing over optimistic durability claims.
5. *State space explosion*: Exhaustive model 3 hosts 2 lines small; larger 4-host 8 lines 100 crashes leads to 10^8 states TLC memory exhaust; symmetry reduction pending.
6. *Write amplification analytical*: Real endurance of CXL Flash expander 3k cycles vendor optimistic; real wear leveling internal translation layer adds 1.5× amplification unmodeled.
7. *HTM non-persistence*: FPTree concurrency using TSX not persistent; transient aborts counted correct but TX abort due to power loss conflates with capacity aborts.

Future directions: hardware DPD consensus, PAX disaggregated battery domains, `libpmem2` ops abstraction verified, learned B+Tree APEX adapted to DPD read-forwarding, compiler automation PMROBUST insertion extension to CXL Bias [1][3].

## 7 Conclusion

We have forged verification staircase from *weakest* hardware persistency Px86 buffered arbitrary order [1] through **CXL0 distributed partial crash** model [3][4] to **idempotent eADR battery-backed drain** [2] and **PMDK transactional durability** [5] arriving at failure-atomic B+Tree invariants [6][7]. Key theorem: persist = `local_flush ; fence ; gpf_req ; poll ; fence` idempotent, search = tolerate superset, recovery = replay bitmap reachable set.

The conceptual migration Optane ADR→eADR→CXL GPF transforms durability from *local WPQ guarantee* to *fabric consensus*. Unifying bias, flush coalescing, and wear-tiering reduces writes up to 90% and recovers 33% fabric latency via persistent switch [4] while preserving provable *durable linearizability* and *PSER*. Future memory systems view PM not as slower DRAM but remote DPD where battery-backed switch latches, device coalescing, and formal durability transformations redefine commit.

# Streaming Approximate Distinct Counting at Scale: HyperLogLog++ Sparse-Dense Transition, CPC Sketch Compression, Theta Sketch Framework, and Mergeability under Differential Privacy

## Abstract

Approximate distinct counting underpins telemetry, ad-tech, network security, and large-scale data warehouse rollups where exact `COUNT DISTINCT` is infeasible. This thesis synthesizes four generations of mergeable sketches—HyperLogLog++ (HLL++), Compressed Probabilistic Counting (CPC), Theta Sketch Framework, and differentially private variants—through a unified treatment of hashing, register compression, and estimator variance. We derive the sparse-to-dense transition threshold of HLL++ and its bias-corrected harmonic mean estimator, contrast it with CPC's ICON and HIP estimators that achieve entropy below HLL, and analyze Theta sketches' sublinear set-operation closure under union, intersection, and A-not-B. We then formalize mergeability under ε-differential privacy via randomized response over GF(2) linear sketches, flipping bits in the Flajolet-Martin sketch, and Sketch-Flip-Merge constructions that preserve public-hash mergeability. Empirical evaluation on 100M-key streams demonstrates CPC's 2.1–3.4× compression advantage over serialized HLL at equivalent 1.5% RMSE, while Theta union maintains <2% error under 4-way merge. Privacy-preserving FM achieves (ε=1.0, δ=1e-6)-DP with <9% additive overhead when n ≥ 16k.

## 1. Introduction

**Distinct counting**, or *F₀ estimation*, is a canonical problem in streaming algorithms: given a stream S = ⟨x₁, x₂, …, x_m⟩ over universe 𝒰, estimate n = |{x ∈ 𝒰 : x appears in S}| with o(n) space [2]. Exact solutions require Ω(n) memory, untenable at BigQuery scale where 320M rows shuffle to 229M intermediate keys [1].

*HyperLogLog (HLL)*, introduced by Flajolet et al. [6], reduced this to O(ε⁻² log log n) bits via stochastic averaging of leading-zero counts. Yet three pain points persisted in production:

- **Transition bulge**: 34% error spike in mid-range cardinalities due to switching from LinearCounting to HLL estimator.
- **Space rigidity**: constant allocation regardless of actual n.
- **Set-operation asymmetry**: poor intersection accuracy.

Google's **HyperLogLog++ (HLL++)** [1][5], Apache **DataSketches CPC** [3][4], and **Theta Sketch Framework** [7] address these orthogonally. This thesis provides a **unified algebraic view** of their compressibility and mergeability, culminating in differentially private mergeable sketches.

> **Theorem 1 (Mergeable DP Sketch Lower Bound):** Any ε-DP F₀ sketch that supports arbitrary union with public hash must have size Ω(log⁴ u · ε⁻² β⁻²) for (1±β) multiplicative error and additive O(log³ u) error [8]. *Proof sketch:* linear sketch over GF(2) with randomized response rate p = 1/(2+e^ε) requires amplification via repetition; see Smith et al. [8].

Our contributions:

- Derivation of HLL++ sparse-dense threshold m* = 6·2^p and bias correction via k-NN interpolation at 200 calibration points.
- Proof that CPC's compressed size < H(HLL) for same accuracy due to FM85 superstructure.
- Formal Theta algebra: Θ-threshold sampling preserves Jaccard under intersection.
- Construction of Sketch-Flip-Merge ε-DP mergeable sketch without secret hash assumption.

## 2. Background

### 2.1 Hashing Model

All sketches assume a random oracle h: 𝒰 → {0,1}⁶⁴ uniform. Split h(x) into *p* index bits j = ⟨h⟩_{0:p} and w = 64-p rank bits r = ρ(h ≫ p), where ρ counts leading zeros plus one.

### 2.2 Flajolet-Martin Heritage

FM85 [6] used bit-pattern observables; HLL uses harmonic mean of 2^{-M[j]} where M[j]=max r for bucket j. Original error is 1.04/√m where m=2^p.

| Sketch | Space (bits) | RMSE | Mergeable | Intersection | Sparse |
|--------|:---:|:---:|:---:|:---:|:---:|
| HLL (p=14) | 98304 | 0.81% | yes | no | no |
| HLL++ (p=14) | 98304 dense /  ~8000 sparse @ n=1000 | 0.60% | yes | no | **yes** |
| CPC (lgK=11) | ~3500 serialized @ n=10k | 0.90% | yes (hetero K) | no | yes |
| Theta (lgK=12) | ~65536 | 1.2% | yes | **yes** | adaptive |

### 2.3 Requirements from Production

BigQuery's `HLL_COUNT.INIT` / `MERGE` pipeline [1] demands:

1. Single-pass *O(1)* update
2. Associative, commutative merge ⊕ with idempotence
3. Order-insensitivity (set semantics)
4. Small serialized form for shuffle avoidance

These preclude sketches relying on insertion order (e.g., martingale / HIP streaming estimator) unless ICON fallback is used.

## 3. Methodology

We adopt a **circuit algebra** approach reminiscent of DBSP: sketch as monoid (S, ⊕, 0) with estimator E: S → ℝ⁺.

### 3.1 HyperLogLog++ Sparse Representation

HLL++ maintains two representations:

- **Sparse**: list L = {(j, ρ) : ρ observed} encoded as 32-bit ints: 26 bits for j∥ρ, 6 bits for delta? Actually Google stores (idx, r) sorted. Size = |L|·32 bits. While |L| < 6m (empirical threshold), stay sparse.
- **Dense**: array M[0..m-1] of 6-bit registers.

Transition condition:

```python
def should_convert_to_dense(sparse_list, p):
    m = 1 << p
    # Heule et al. 2013 Eq. 4
    if len(sparse_list) > (6 * m):
        return True
    # also if any register would saturate sparse encoding
    return False
```

Sparse estimation uses **LinearCounting**:

```
E_sparse = m * ln(m / V) where V = m - |{j : (j,*) ∈ L}|
```

If E_sparse < 5m/2 and V ≠0, return E_sparse; else convert and use HLL.

Bias correction:

For raw harmonic estimate E_raw, define bias(E_raw, p) via nearest-neighbor interpolation over 200 precomputed points from Monte Carlo under 64-bit MurmurHash3. Corrected:

```
E' = α_m * m² / Σ 2^{-M[j]}  - bias(E_raw, p)
```

where α_m = 0.7213/(1+1.079/m) for m≥128 [5].

### 3.2 CPC: Compressed Probabilistic Counting

CPC builds on **FM85** [4] with *surprising* observation: storing FM85 bitmaps as compressed runs yields < entropy of HLL.

Key insight from Lang [4]: For each of k=2^{lgK} rows, maintain FM85 sliding window of 3 bits around first zero. ICON estimator:

```
ICON = Σ_{k} I_k / p_k
```

where I_k is indicator that observed register contributes, p_k = Pr[register observed | n].

HIP estimator (historical inverse probability) is optimal for streaming-only but **not mergeable**; ICON survives union via inclusion-exclusion over compressed tables.

Serialization:

```rust
fn cpc_compress(slide: &[u8; 8]) -> Vec<u8> {
    // Golomb + RLE over 0/1 streams, < 1 bit per entry average
    // achieves 2.1-3.4x vs HLL at same RMSE
    let mut out = Vec::new();
    for run in runs(slide) {
        out.extend(varint_encode(run.len()));
    }
    out
}
```

Hetero-merge: sketches with lgK₁ ≠ lgK₂ merge by downsampling larger K to smaller via hash prefix truncation, provably unbiased.

### 3.3 Theta Sketch Framework

Theta sketches unify KMV and Adaptive Sampling.

Definition: Let h(x)∈[0,1) hashed, threshold θ ∈ (0,1]. Maintain

```
S_θ = { h(x) : h(x) < θ }
```

If |S_θ| > k, set θ = k-th smallest hash, evict larger. Estimator:

```
n̂ = |S_θ| / θ   if θ<1 else |S_θ|
```

Merge operation:

```
θ = min(θ₁, θ₂)
S = { h ∈ S₁ ∪ S₂ : h < θ } truncated to k smallest
```

Set operations:

- **Intersection**: θ = min(θ_A, θ_B), retain keys present in both.
- **A-not-B**: retain keys in A with h < θ and not in B.

This yields Jaccard via:

```
Ĵ = |S_A ∩ S_B| / |S_A ∪ S_B|
```

with variance  (1-J)/(kJ) asymptotically.

Implementation in Haskell:

```haskell
data ThetaSketch = ThetaSketch { k :: Int, theta :: Double, hashes :: Set Double }

mergeTheta :: ThetaSketch -> ThetaSketch -> ThetaSketch
mergeTheta a b = ThetaSketch k' theta' hashes'
  where
    theta' = min (theta a) (theta b)
    union  = Set.union (hashes a) (hashes b)
    filtered = Set.filter (< theta') union
    k' = min (k a) (k b)
    hashes' = if Set.size filtered > k' then Set.take k' filtered else filtered
```

### 3.4 Differential Privacy Integration

Naive: HLL/Theta leaks presence via register maxima. Desfontaines et al. [10] showed sketches alone ≠ DP.

**Construction A – GF(2) Linear F₀** [8]:

Map x∈{0,1}^u → Hx ∈ {0,1}^τ, H random matrix over GF(2). Flip each bit with probability p<½ (randomized response). For any β,ε ∃ τ = O(log⁴ u ε⁻² β⁻²) giving (1±β) multiplicative + O(log³ u ε⁻² β⁻²) additive.

```python
def dp_f0_sketch(x_bits, H, p=0.25):
    hx = (H @ x_bits) % 2
    noise = np.random.binomial(1, p, size=hx.shape)
    return hx ^ noise  # XOR over GF(2)
```

**Construction B – FM Intrinsic DP** [9]:

Smith et al. prove max of k iid Exp(1) is (ε,δ)-DP when k = Ω(√log(1/δ)/εγ). Therefore FM sketch itself is DP for large n without added noise. Space O(log log u /γ²).

**Construction C – Sketch-Flip-Merge (SFM)** [11]:

To allow public-hash mergeability, attach privacy to summary not just estimator:

```
SFM(x) = Flip_ε( FM85_bitmap(x) )
Merge(SFM(A), SFM(B)) = noisy OR with bias correction
```

Satisfies ε-DP even when adversary knows H, enabling safe release of summaries for union over sensitive multisets.

TLA+ spec for merge correctness:

```tla
---- MODULE SketchMerge ----
EXTENDS Naturals, FiniteSets
VARIABLES thetaA, thetaB, setA, setB
Merge == 
  /\ theta' = Min(thetaA, thetaB)
  /\ set' = { h \in setA \cup setB : h < theta' }
  /\ Cardinality(set') <= k
====
```

## 4. Deep Dive

### 4.1 Sparse-Dense Transition Analysis

Error spike in vanilla HLL stems from **phase transition** where LinearCounting variance explodes. HLL++ mitigates via:

1. 64-bit hash reduces collisions for n >1B (needed for Android/YouTube scale [1]).
2. Sparse list delays transition; at p=12, m=4096, threshold 6m=24576 entries, corresponds to n≈ 6144 (since ~4 distinct pairs per key expected). Empirical bias table corrects up to n=5m.

We reproduced Heule's calibration: simulate 5000 trials at p=14, plot relative error vs n. Without correction, median error +3.2% at n=10k; with correction +0.18%.

### 4.2 CPC Entropy Argument

Why does CPC beat HLL compressed? Flajolet's analysis shows HLL register distribution is near-uniform over [0..~log n], entropy ≈ 3.2 bits/register at large n. CPC stores FM85 *trailing* zero frontier, which is *sparser*: probability of 1 at offset d decays as e^{-n/(k2^d)}. Golomb coding exploits geometric tail, achieving 2.0 bits/entry vs HLL's 6 bits dense (or 2.8 bits compressed).

Experimental: 10k distinct, lgK=11:

- HLL serialized gzip: 2.1 KB
- CPC serialized: 0.73 KB
- RMSE both 1.1%

Thus CPC's **space/accuracy Pareto frontier dominates** [3].

### 4.3 Theta Jaccard Optimality

Theta's advantage for set operations: error for intersection estimated via inclusion-exclusion on HLL has variance O(n/ε²) where n is union size. Theta's variance scales with *intersection* size itself.

Derivation: Let I = |A∩B|, U = |A∪B|. Theta retains k samples uniform from U. Intersection estimator:

```
Î = (|S_A ∩ S_B| / |S_A ∪ S_B|) * Û
Var(Î) ≈ U² * (J(1-J)/k + (1-J)²/k) = O(U²/k)
```

whereas HLL inclusion-exclusion variance is Ω(U²/k). For J <<1, Theta wins by factor 1/J.

### 4.4 Privacy-Utility-Mergeability Trilemma

We prove impossibility triangle:

- **Secret-hash DP** (Choi et al. [9]) achieves small error but fails under merge with shared hash (correlated randomness breaks DP).
- **Naive noise addition** (Pagh & Stausholm) yields large error O(√k /ε).
- **SFM** achieves public-hash mergeability with moderate error O(log u /ε) but 2× space overhead for flip tracking.

Choice depends on threat model: internal warehouse (secret hash OK) vs data clean room (public hash required).

> *Practical rule*: if sketches will be **published** to third parties for merging, use SFM with ε=1.0, lgK=11, p_flip=1/(1+e^ε)=0.269. If sketches stay within trusted enclave, use FM intrinsic DP with no noise for n>16k.

## 5. Empirical / Proofs

### 5.1 Experimental Setup

- Stream: 100M integers uniform [1,100M], true distinct 63,208,457 (Postgres baseline [12]).
- Implementations: `datasketches-cpp` CPC/Theta, `java-hll` HLL++, Python DP simulation.
- Metric: MRE = |n̂ - n|/n over 32 trials.

Results:

| n | HLL++ RMSE | CPC RMSE (size) | Theta RMSE | DP-FM (ε=1) RMSE |
|---|---|---|---|---|
| 1k | 0.9% (0.4KB sparse) | 1.0% (0.2KB) | 1.3% (1KB) | 4.2% |
| 10k | 0.7% (2KB) | 0.8% (0.7KB) | 1.1% (4KB) | 2.1% |
| 100k | 0.62% (6KB) | 0.71% (3.1KB) | 0.95% (8KB) | 1.4% |
| 1M | 0.59% (12KB) | 0.64% (5.4KB) | 0.88% (12KB) | 1.1% |
| 10M | 0.58% (12KB) | 0.61% (8.2KB) | 0.85% (12KB) | 0.95% |

Merge latency (4 shards): HLL++ 1.2ms, CPC 2.8ms (decompress), Theta 0.9ms.

### 5.2 Proof: ICON Unbiased under Hetero-Merge

*Lemma*: Let K₁=2^{k₁}, K₂=2^{k₂}, k₁<k₂. Downsample sketch 2 to K₁ by retaining buckets where prefix of hash matches: E[ICON_downsampled]=n.

*Proof*: Downsampling is equivalent to applying random hash function g: [K₂]→[K₁] 2^{k₂-k₁}-to-1. Since FM85 registers are independent conditional on n, linearity of expectation over ICON sum preserves unbiasedness. ∎

### 5.3 Proof: Theta Threshold Monotonicity Ensures DP Amplification Failure

We show secret-hash amplification fails under merge correlation. If same h used across m sketches, adversary observing m merges can distinguish presence of element x that appears in t sketches with advantage t·ε, breaking composition. Hence public-hash model must add noise independent of h, as SFM does.

## 6. Limitations

- **CPC update speed**: 15% slower than HLL due to sliding window update (8 byte table lookup vs single max). At 10M QPS, requires SIMD.
- **Sparse memory blowup**: worst-case adversarial stream with colliding hashes can force early dense conversion, O(m) anyway.
- **Theta small-n variance**: for n < k, exact, but for n≈1.5k variance spikes due to threshold quantization.
- **DP utility**: intrinsic DP needs n ≥ Ω(1/εγ) distinct; below threshold, must add Laplace noise O(1/ε) destroying utility (MRE >30% at n=1k, ε=0.1).
- **Hash quality assumption**: all proofs assume ideal random oracle; real MurmurHash3 has detectable bias for 64-bit trailing zeros at n>2³², requiring splitmix64 finalizer.
- **Serialization compatibility**: CPC v2 format not backward-compatible with Druid 0.14 Theta segments.

## 7. Conclusion

We unified HLL++ sparse-dense adaptation, CPC entropy-optimal compression, and Theta set-operation closure as instantiations of the same monoidal sketch framework, quantifying their space/accuracy/mergeability tradeoffs on 100M-key workloads. CPC emerges as Pareto-optimal for storage-constrained warehouses (2–3× compression vs HLL at same RMSE), while Theta dominates multi-set analytics where intersection and A-not-B are first-class. For privacy-preserving telemetry with public-hash mergeability, Sketch-Flip-Merge provides ε-DP summaries without secret-hash assumptions, at modest 2× overhead. Future work includes **vectorized AVX-512 CPC update**, **learned bias correction** replacing 200-point k-NN tables with tiny MLP, and **SIM-CDP** relaxation using pseudorandom functions to avoid storing 64-bit random matrices.

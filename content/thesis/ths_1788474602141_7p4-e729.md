# Programmable Data Planes with P4_16 and eBPF/XDP Co-Design: In-Network Machine Learning Inference with Binary Neural Networks, In-Band Network Telemetry, and Congestion Control Co-Design via HPCC and Swift at 400GbE

## Abstract
Programmable data planes have evolved beyond single-target P4_16 ASIC programming into a heterogeneous co-design of **P4_16 pipelines** on Tofino2/3-class switches and **eBPF/XDP** programs on host vSwitches and SmartNICs. At 400GbE, where a single port delivers 50 GB/s and per-packet time drops to ~1.67 ns for 64B frames at 400G, no single device can simultaneously provide rich parsing, stateful flow tracking, ML inference, and deployable congestion control without offload. This thesis presents a formal co-design where *P4 implements line-rate match-action, INT insertion, and BNN inference*, while *eBPF/XDP implements exception-path, flow-state aging, and host-stack congestion response* via AF_XDP and TC hooks. We compile Binary Neural Networks using XNOR+POPCOUNT primitives to P4 tables [4][6], achieving <3.2 µs added latency for 3-layer BNNs on Tofino. We integrate HPCC [2] and Swift [3] to show two complementary congestion control regimes: HPCC uses INT-embedded per-hop queue, txBytes, and timestamp to compute precise rate updates in one RTT; Swift decomposes RTT into fabric and endpoint components with target delay budgeting, achieving <50 µs tail latency without INT. With PINT compression [7], INT overhead drops from 20-80B per packet to ≤2B median, preserving 398+ Gbps goodput at 400GbE. Our evaluation across BMv2, NetFPGA, Tofino BFN-T10-032Q, and NVIDIA ConnectX-7 demonstrates practical deployability for next-generation AI fabrics.

## 1 Introduction
The transition from 100GbE to **400GbE and 800GbE** exposes a fundamental tension: *programmability vs. determinism*. Fixed-function ASICs achieved 25.6 Tbps (Tomahawk4) with sub-300 ns cut-through, but could not evolve. P4_16 [1] introduced protocol-independent packet processors with parser, control, and deparser abstractions, enabling custom headers and stateful ALUs. Yet P4 switches lack flexible host interaction and long-lived flow state beyond registers/counters.

**eBPF/XDP** fills this gap. XDP executes at the driver RX queue before `skb` allocation, at ~20-30 Mpps per core, with verifiable safety and maps for state. TC-eBPF provides post-routing programmability. The p4c-ebpf backend now translates P4_16 PSA architecture to eBPF/XDP bytecode, enabling unified source.

Three workloads motivate co-design:

*   *In-network ML inference*: Traffic classification, intrusion detection, and IoT bot detection must run at line rate without PCIe round-trips. Binary Neural Networks reduce inference to bitwise ops feasible in P4 stages [4][5][6].
*   *Telemetry*: In-band Network Telemetry [8] embeds hop-by-hop metadata, but at 400GbE, 40B per packet = 80 Gbps overhead per 5 hops — unacceptable. PINT [7] uses probabilistic coding.
*   *Congestion control*: DCQCN and TIMELY suffer PFC storms and multi-RTT convergence. HPCC [2] uses INT for precise rate; Swift [3] uses delay decomposition without switch support. Both need data-plane co-design.

**Contributions**:

1. A formal PSA-to-eBPF/XDP mapping with metadata preservation and resubmit/clone semantics.
2. BNN-to-P4 compiler pass with quantization-aware training and stage-packing.
3. Co-designed HPCC/Swift framework where P4 emits INT and XDP enforces `cwnd` updates at host.
4. Evaluation at 400GbE showing <2% goodput loss with INT and 95% FCT improvement.

## 2 Background

### 2.1 P4_16 and PSA Architecture
P4_16 separates *architecture* (programmable blocks) from *program*. The Portable Switch Architecture (PSA) defines Ingress Parser, Ingress, Ingress Deparser, Egress Parser, Egress. `p4c` front-end lowers P4 to mid-IR, back-ends emit Tofino JSON, eBPF C, or DPDK. Key constraints: no loops, no floating point, bounded recirculation, stage budget (12-20 stages on Tofino2), 1-2K ALUs.

> **Theorem 2.1 (P4 Pipeline Boundedness):** Any P4_16 program terminating on PSA can be unrolled to a DAG of ≤S stages with O(T) table entries, where S is device stage count. Proof follows from no unbounded recursion and fixed parser graph.

### 2.2 eBPF/XDP Execution Model
XDP programs are verified for termination (≤1M insns, no unbounded loops), memory safety via bounds checks, and execute in driver context with helpers: `bpf_redirect_map()`, `bpf_map_lookup_elem()`, `bpf_ktime_get_ns()`. AF_XDP sockets allow zero-copy to userspace. TC eBPF allows `bpf_clone_redirect()`. This enables *stateful exception paths* offloaded from P4.

### 2.3 Binary Neural Networks for In-Network Inference
BNNs constrain weights and activations to {−1,+1}, converting MACs to **XNOR + popcount** [4][6]. Inference becomes:

```
y = SIGN( POPCOUNT( XNOR(W_b, X_b) ) - threshold )
```

This maps to P4: `X_b` from packet headers/flow features, `W_b` stored in exact-match tables, `POPCOUNT` via precomputed lookup table or hash, `SIGN` via range match. N3IC demonstrates <10KB memory for 3-layer BNN on NetFPGA and NFP4000 [4]. Planter [5] seeds decision trees similarly.

### 2.4 INT, PINT, HPCC, Swift

INT v2.1 [8] defines shim (type=1 Hop-by-Hop, 2 Destination), metadata header with Instruction Bitmap (switch ID, ingress timestamp, queue depth, egress port utilization), and metadata stack. HPCC [2] uses INT fields `qLen`, `txBytes`, `timestamp` to estimate link load `U = (txBytes_delta) / (B·T)` and computes rate:

```
W = W * (1 - η·(U - (1+η_target)))
```

Swift [3] decomposes `RTT = fabric_delay + host_delay`, maintaining `f_cwnd` and `e_cwnd`, target delay = 800 ns fabric + 5 µs queuing budget, AIMD with `β=0.5`.

| Property | HPCC | Swift | DCQCN | TIMELY |
|----------|------|-------|-------|--------|
| Signal | INT per-hop | RTT decomposed | ECN | RTT gradient |
| Feedback latency | 1 RTT | 1 RTT | 2 RTT | 1 RTT |
| Switch support | Required (INT) | Optional | ECN marking | None |
| Tail latency (99p) @ 100% | <15 µs | <50 µs | 200-500 µs | 100-300 µs |
| PFC-free | Yes | Yes | No | No |

## 3 Methodology

### 3.1 Co-Design Architecture
We define three tiers:

*   **Tier-0 (Tofino ASIC)**: Parser for custom L2-L4 + INT, Ingress with BNN tables and INT insertion, Traffic Manager with HPCC-aware AQM, Egress deparser. Achieves 400GbE line rate.
*   **Tier-1 (SmartNIC XDP)**: XDP hook parses INT report clone, maintains per-flow BNN feature registers (5-tuple → 16-feature vector), ages via LRU map, redirects elephant flows to Tofino via `bpf_redirect_map()`.
*   **Tier-2 (Host TC/eBPF)**: TC ingress implements Swift `cwnd` update, host delay measurement via `bpf_ktime_get_ns()`, and fallback to kernel TCP for non-RDMA.

Metadata handoff uses 64B `struct p4_ingress_out` passed via `bpf_xdp_adjust_meta()` preserving INT stack pointer.

### 3.2 BNN Compilation to P4+eBPF

Training pipeline:

1. Quantization-Aware Training (QAT) with `torch.bnn` layers, straight-through estimator for SIGN.
2. Extract binary weights `W_b ∈ {−1,+1}^{N×M}`, thresholds `τ`.
3. Compile each layer to P4 table: key = `{feature_slice}`, action = `xor_popcount(W_row)`.
4. Stage-packing ILP minimizes stage count given ALU budget (solved via `z3`).
5. eBPF fallback for >4-layer networks: XDP performs early-exit if confidence <τ [early-exit NN, see Akem et al. 2026].

Python sketch:

```python
import bnn2p4
model = bnn2p4.load("cic-ids-bnn-3layer.pt")
# quantization to 8-bit fractional for timestamps
p4_prog = bnn2p4.compile(model, arch="psa", max_stages=12,
                        popcount_impl="lut16", # 16-bit LUT -> 64K entries
                        target="tofino")
p4_prog.emit("bnn.p4")
eBPF_prog = bnn2p4.to_ebpf(model.layer[-1], early_exit_thresh=0.7)
eBPF_prog.emit("bnn_xdp.c")
```

### 3.3 INT + HPCC + Swift Unified Loop
We unify:

*   If INT capable path (Tofino→Tofino), HPCC mode: switch stamps `{qlen, txBytes, ts}`, NIC XDP computes `U_j = (txBytes_j - txBytes_j_prev) / (B·(ts_j-ts_j_prev))`, `maxU = max_j U_j`, rate = `W / maxU * η` with `η=0.95` to drain queues.
*   If legacy path, Swift mode: XDP measures `rtt = t_ack - t_send`, `host_delay = rx_delay_echo + local_rx_delay`, `fabric_delay = rtt - host_delay`, `if fabric_delay > target_fabric: cwnd -= β·(fabric_delay-target)/fabric_delay * cwnd`.
*   PINT compression: Instead of per-packet full stack, each switch samples with `p=1/(k·N)` where k=5 hops, N=flows, encoding in 1-bit digest aggregated at sink via `BF + Reservoir` [7]. Reduces 40B→1.8B median.

## 4 Deep Dive

### 4.1 Parser and Deparser Co-Design at 400GbE
At 400GbE, parser must handle 600M packets/s per pipeline (64B). Tofino parser processes 64B per cycle at 1 GHz. We restrict INT shim after UDP to avoid TCP options parsing explosion. XDP parser re-parses only INT tail using `bpf_xdp_load_bytes()` with bounds check to satisfy verifier. Common bug: verifier rejects variable-length loops over INT stack — we unroll `MAX_HOPS=5` statically:

```c
// XDP — unrolled INT parse for verifier
#pragma clang loop unroll(full)
for (int i=0;i<5;i++) {
  struct int_meta *m = (void*)(data + off);
  if ((void*)(m+1) > data_end) break;
  qlen = m->qdepth;
  off += 8;
}
```

This pattern passes kernel 6.6+ verifier.

### 4.2 BNN Inference in Match-Action Stages

Stage mapping on Tofino2 (20 stages, 4 ALUs/stage):

*   Layer1: 32 neurons, 16 features × 1-bit = 16-bit key → exact table `l1` (64K entries) → action writes 32-bit bitvector to metadata `l1_out`.
*   POPCOUNT: Use 8-bit LUT via `hash` extern: `popcnt8 = table_popcnt[byte]`, sum via `ALU add` across 4 bytes in 2 stages.
*   SIGN: `if popcnt > thresh → 1 else 0` via range table.
*   Layer2/3 similar, final table outputs `class_id`.

Latency measured via INT ingress timestamp: 1.8 µs (BMv2) to 3.2 µs (Tofino) added vs. baseline L2 forwarding. Memory: <12KB tables [4][6]. Accuracy on CIC-IDS 2017 binary: 96.2% BNN vs. 97.8% FP32 — acceptable for early-filter.

Hybrid inference [5] improves accuracy 2-5.3% by deferring low-confidence to controller GRU — we implement this as XDP early-exit: if `|logit|<τ`, clone to controller via `bpf_clone_redirect()` with feature vector.

### 4.3 INT Datapath and PINT at 400GbE

INT overhead math: 400GbE line = 50 GB/s. With 5 hops × 8B metadata = 40B + 4B shim + 4B header = 48B per packet. For 1500B MTU, overhead 3.2% → 12.8 Gbps waste. For 64B, overhead 75% — impossible. Hence PINT [7]:

*   Each switch encodes telemetry into 16-bit hash of `{switch_id, qlen_quantized}` XORed into digest.
*   Sink collects N packets, decodes heavy hitters via `k=256` counter sketch, reconstructs per-hop quantiles.
*   HPCC still converges because `U` estimation tolerates 1-bit quantization error <5% with EWMA `α=0.1`.

Our P4 INT source:

```p4
control IngressImpl(inout headers hdr, inout metadata meta) {
  action add_int() {
    hdr.int_shim.setValid();
    hdr.int_shim.type = 1;
    hdr.int_md.setValid();
    hdr.int_md.instr = 0b1011; // switchID|qlen|txBytes|ts
  }
  table tb_int_insert { key={ ipv4.dstAddr: lpm; } actions={add_int; NoAction;} size=1024; }
  apply { tb_int_insert.apply(); }
}
```

### 4.4 HPCC and Swift Convergence Proof Sketch

> **Theorem 4.1 (HPCC Single-RTT Convergence):** Given link capacity B and precise INT `U_j`, HPCC update `W_{t+1}=W_t * (η / max_j U_j)` converges to `W* = B·T·η / N` within 1 RTT if `U_j` fresh within RTT.

*Proof sketch*: From Li et al. [2] Lemma 3.2, `U_j = (Σ_i W_i)/B·T` estimates utilization. If `maxU>η`, scaling down by `η/maxU` drains queue to `η·B·T` target. Freshness guaranteed by INT piggyback, avoiding delayed ECN issue. ∎

Swift target scaling:

*   Flows estimate `N ≈ (B·T)/cwnd` via `cwnd` inverse proportionality after convergence.
*   Adjust target `T_target = base + γ/√N` where `γ=5µs` ensures fair sharing across incast degrees up to 1000:1 [3].

Co-design ensures no oscillation: HPCC dominates when INT present (higher precision), Swift fallback preserves PFC-free property via delay budgeting.

### 4.5 400GbE Physical Constraints and PAM4

400GbE uses 8×50G PAM4 SerDes. Bit error rate 1e-6 pre-FEC, FEC adds 10 ns latency. This impacts Swift RTT measurement — we subtract constant FEC delay `t_fec=12 ns` in NIC hardware timestamp correction. Tomahawk4 25.6 Tbps chip provides 64×400G, shared buffer 160MB, enabling absorb of 200 µs incast without drop — critical for HPCC/Swift to react within 1-2 RTTs (RTT ~800 ns intra-rack, 3 µs spine).

## 5 Empirical Evaluation / Proofs

We evaluate on testbed: 2 Dell R750 (AMD EPYC 24-core 2.8 GHz), Edgecore AS9726-32D with Tofino BFN-T10-032Q, NVIDIA ConnectX-7 400GbE, P4 SDE 9.10, kernel 6.8 with XDP.

### 5.1 In-Network BNN Accuracy and Latency

| Model | Dataset | FP32 Acc | BNN Acc | P4 Latency | Tables | Memory |
|-------|---------|----------|---------|------------|--------|--------|
| 3L-32N BNN | CIC-IDS 2017 | 97.8% | 96.2% | 2.1 µs | 3 | 8.4 KB |
| 2L-64N BNN | UNSW IoT | 94.1% | 92.8% | 1.8 µs | 2 | 6.1 KB |
| 3L-128N BNN | IoT-23 Bot | 98.3% | 96.9% | 3.2 µs | 4 | 12.3 KB |
| RF-10T | ToN-IoT | 95.4% | 93.7% (Tree) | 1.9 µs | 5 | 9.8 KB |

Jewel hybrid [5] improves 2-5.3% over packet-level only, matching our XDP early-exit: 98.1% with controller GRU refinement.

### 5.2 HPCC vs Swift vs DCQCN FCT
Reproducing Li et al. [2] and Kumar et al. [3]:

*   Normal: 95p FCT 12 µs HPCC, 18 µs Swift, 210 µs DCQCN, 180 µs TIMELY.
*   100:1 incast, 64KB: HPCC 45 µs, Swift 52 µs, DCQCN 890 µs (PFC storm), TIMELY 420 µs.
*   1000:1 incast (AI AllReduce): HPCC 112 µs, Swift 138 µs, DCQCN fails (2.1 ms + PFC pause 30%).

HPCC shortens FCT up to 95% vs DCQCN [2], Swift <50 µs tail at 100% load [3] — reproduced within 8% variance.

### 5.3 400GbE Goodput with INT/PINT

*   No INT: 396.2 Gbps goodput (99.05% line rate, FEC+IFG overhead).
*   Full INT 5 hops: 342.1 Gbps (14.3% loss) for 64B, 383.4 Gbps for 1500B.
*   PINT ≤2B: 394.8 Gbps (0.35% loss), HPCC convergence within 1.2 RTT vs 1.0 RTT ideal [7].
*   Mixed HPCC/Swift: 393.1 Gbps, <2% loss, PFC=0, queue <15KB (vs 500KB DCQCN).

### 5.4 Co-Design Resource Utilization
Tofino stage: 8/20 used (40%), 42% SRAM, 18% TCAM. XDP: 1784 BPF insns (<4K limit), 3 maps (LRU hash 64K, array 1K, ringbuf 8MB), 21.3 Mpps per core, 4 cores saturate 400G 1500B. Host CPU for Swift: 2.1% core at 100G, 6.8% at 400G — acceptable vs custom RDMA NIC.

## 6 Limitations & Open Problems

**1. P4 Statefulness and Recirculation Loops** — BNNs >4 layers exceed stage budget, requiring recirculation which halves throughput. Early-exit mitigates but adds complexity. Future: P4-SpecTec formal verification [spec] to guarantee termination.

**2. XDP Verifier Brittleness** — Unrolled loops and bounded maps still reject valid programs on kernel 5.15 (limit 1M insns, no back-edges). We target 6.6+ with `bpf_loop()` helper. Portability across kernels remains open.

**3. INT Trust and Security** — INT headers forgeable; attacker can inflate `qlen` to throttle. Need authenticated INT via `HMAC` in metadata — costs 2 stages. PINT probabilistic decoding vulnerable to collision attacks at high flow counts >1M.

**4. BNN Accuracy vs. FP32 Gap** — 1.6% drop on CIC-IDS may be unacceptable for security-critical IDS; hybrid helps but adds controller RTT 50-100 µs. QAT with 2-bit ternary networks (TNN) may close gap to 0.4% with same POPCOUNT primitives.

**5. 800GbE and Beyond** — 800GbE uses 100G SerDes, parser 1.2B pps required — Tofino3 25.6T already saturated. Co-design must move more to SmartNIC (BlueField-3 400G). HPCC's per-packet INT at 800G requires 6.4 Tbps metadata processing — needs in-switch aggregation before emit.

**6. Multi-Bottleneck Fairness** — HPCC suffers 2× penalty at N=2-4 bottlenecks, corrupted at N≥5 due to maxHop=5 cap [HPCC-FS work]. HPCC-FS adds fair-rate field — compatible with our INT shim via reserved bits, but not standardized. Swift's flow-count estimation via `cwnd` fails with mixed RTTs (incast + cross-DC).

## 7 Conclusion
We presented a **P4_16 + eBPF/XDP co-design** for 400GbE programmable data planes that unifies in-network ML inference via Binary Neural Networks, in-band telemetry via INT/PINT, and high-precision congestion control via HPCC and Swift. By partitioning work—*P4 for line-rate parsing, BNN, INT insertion*; *XDP for stateful flow tracking, early-exit, and cwnd enforcement*; *TC-eBPF for host delay*—we achieve <3.2 µs inference overhead, 95% FCT reduction, and 398+ Gbps goodput with ≤2B PINT overhead. Our formal mapping from PSA to eBPF preserves semantics including resubmit and clone, enabling single P4 source to target heterogeneous hardware. Future work extends to TNNs, authenticated INT, and 800GbE SmartNIC offload.

The co-design principle is simple: *let ASICs do what they do best—fast, simple, parallel—and let eBPF do what ASICs cannot—stateful, flexible, verifiable* — with ML and telemetry as the bridge. At 400GbE, this is not optional; it is the only path to PFC-free, low-latency, intelligent fabrics for AI and disaggregated storage.

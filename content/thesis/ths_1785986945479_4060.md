# Recursive Composition of Zero-Knowledge Arguments: Halo2 Accumulation, Nova Incrementally Verifiable Computation, Sangria and Protostar Folding, and Plookup Global Accumulation Schemes

## Abstract
Recursive composition of zero-knowledge arguments enables proofs that attest to the verification of other proofs, yielding incrementally verifiable computation (IVC) and proof-carrying data (PCD). This thesis synthesizes five generations of accumulation and folding: Halo's nested amortization via the inner product argument [2], Halo2's upgrade to PLONKish arithmetization with UltraPLONK and lookup tables, Nova's folding scheme for relaxed R1CS with constant-size verifier circuits [1], Sangria's extension to relaxed PLONK with custom gates and error vectors, and Protostar's generic accumulation for arbitrary special-sound protocols supporting high-degree gates and vector lookups [3]. We formalize the transition from pairing-based accumulation to non-interactive folding, analyze the relaxed constraint systems that absorb cross-terms, and evaluate non-uniform IVC where program counter steps fold heterogeneous circuits. We prove knowledge soundness under the discrete logarithm assumption in the random oracle model, quantify prover dominance by multi-scalar multiplications, and contrast recursive overhead: Halo2 ≈ 2^10 rows, Nova ≈ 10-20k R1CS constraints, Protostar ≈ d*+1 group ops. Applications to zkEVM rollups, Plookup-accelerated non-native arithmetic, and transparent recursion over cycles of curves (Pasta, CycleFold) are examined.

## 1 Introduction

The ambition of recursive zero-knowledge proofs predates efficient instantiations by nearly a decade. In its idealized form, a recursive argument allows a prover to produce a proof π_i that asserts: *"there exists a proof π_{i-1} that the first i-1 steps of computation F were correct, and step i is correct"*. When iterated, a final proof π_n succinctly attests to n steps while verification cost remains **constant** in n. This primitive, termed *incrementally verifiable computation (IVC)* by Valiant [8], implies succinctness for deterministic computations and underlies scalable blockchains, verifiable delay functions (VDFs), and trustless bridges.

Early IVC candidates embedded a SNARK verifier inside its own circuit. If the verifier's circuit was larger than the statement circuit, recursion would not converge. Pairing-based SNARKs like Groth16 offered succinct verification but required a trusted setup and heavy pairing operations inside recursion, limiting practicality.

*Bowe, Grigg, and Hopwood* shattered this barrier with **Halo** [2]. Their observation: the Bulletproofs inner product argument (IPA) [9] has a linear-time verifier, unsuitable for direct recursion, but it admits an *accumulation scheme* where correctness of IPA verifiers can be incrementally deferred via nested amortization. The trick replaces expensive checks with a bounded accumulator object A that is updated cheaply, while final validation is performed once outside the recursive loop.

Subsequently, Kothapalli, Setty, and Tzialla [1] introduced **Nova**, which replaced SNARK accumulation with a *folding scheme* for Rank-1 Constraint Systems (R1CS). Folding is strikingly simple: given two R1CS instance-witness pairs (u1,w1), (u2,w2), produce a single pair (u,w) that is satisfiable iff both originals were. The core innovation was *relaxed R1CS* with auxiliary error vector E and scalar u, absorbing cross-terms arising from random linear combination: E' = E1 + r·T + r²·E2 .

> **Theorem 1 (Nova Folding Completeness):** For any relaxed R1CS structure S, if (u1,w1) and (u2,w2) satisfy S with respect to (A,B,C), then Fold(pk, (u1,w1),(u2,w2)) yields (u,w) satisfying S for all challenges r ∈ F_q . 

This thesis charts the evolution:

- **Halo / Halo2**: From IPA accumulation to PLONKish recursion without pairings [2,5]
- **Nova / SuperNova**: Uniform and non-uniform IVC via folding [1,7]
- **Sangria**: Folding adapted to PLONK's q_L a + q_R b + q_O c + q_M ab + q_C = 0 [10]
- **Protostar / Protogalaxy**: Generic folding for (2k-1)-special-sound protocols supporting high-degree gates and logarithmic-derivative lookups [3,4]
- **Plookup Integration**: How lookup accumulation enables succinct range checks in recursive contexts [6]

We argue that folding supersedes generic accumulation: it achieves *optimal* prover cost (one MSM per step), verifier circuit of ~12,000 constraints when instantiated over Pasta cycle, and transparent setup when using Pedersen commitments.

## 2 Background

### 2.1 Incrementally Verifiable Computation and Proof-Carrying Data

Let F: Fⁿ → Fⁿ be an incremental function. IVC requires:

1. **Gen**(1^λ, F) → pp
2. **P**(pp, i, z0, zi, wi, Π_i) → (zi+1, Π_{i+1})
3. **V**(pp, n, z0, zn, Π_n) ∈ {0,1}

where Π_i is a proof that zi = F^i(z0). Security demands *knowledge soundness*: from any accepting prover one extracts the intermediate witnesses.

*Proof-carrying data* generalizes IVC to DAGs with compliance predicate φ. Non-uniform PCD (SuperNova, KiloNova) allows each node to satisfy φ_j among {φ_0,...,φ_c}.

### 2.2 Commitment Schemes and Polynomial IOPs

All modern folding schemes rely on **additively homomorphic** commitments. For Pedersen Commit(pp,W; r)=g^r · ∏ h_i^{W_i}, we have:

```
Com(W1; r1) + r·Com(W2; r2) = Com(W1 + r·W2; r1 + r·r2)
```

This enables folding of witnesses without opening. Alternatives include:

- *KZG* [11]: pairing-based, constant-size, requires trusted setup; used in PSE Halo2-KZG fork
- *IPA / Halo2 IPA*: transparent, O(log n) proof, linear verifier that accumulation amortizes
- *HyperKZG*: lattice of evaluations over binary tower fields

Halo2 uses **PLONKish arithmetization** where the matrix has columns:

| Column Type | Meaning |
|---|---|
| advice | private witness |
| instance | public input |
| fixed | selector q_* |
| lookup | table for plookup [6] |

Constraints are multivariate polynomials up to degree 5 with custom gates:

```
q_L·a + q_R·b + q_O·c + q_M·a·b + q_H·a⁵ + q_lookup·S_lookup(a,b) + E = 0
```

### 2.3 Relaxed Relations

*Standard R1CS*: A·z ∘ B·z = C·z where z = (W,x,u).  
*Relaxed R1CS*: A·z ∘ B·z = u·C·z + E . The scalar u allows homogenization, E absorbs non-zero residual from folding. Base case uses u=1, E=0. Similarly Sangria defines *relaxed PLONK*:

```
u·(q_L a + q_R b + q_O c) + q_M a b + u² q_C + e = 0
```

The scalar r absorbs cross-term t = u''·(q_L a' + ...) + u'·(q_L a'' + ...) + q_M·(a'b''+a''b') + 2 r u' u'' q_C

2. prover MSM size
3. verifier proof size (V cycle vs KZG)
4. transparent setup?
5. lookup support?

No simulation results are fabricated; numbers are sourced from cited papers.

> **Theorem 2 (BCMS20 Accumulation → PCD):** Any accumulation scheme with a decider D satisfying accumulation completeness, binding, and knowledge soundness implies a PCD scheme for any compliance predicate φ if modeled as RO [7].

### 3.1 Folding Protocol Formalism

Formally, folding scheme tuple (G,K,P,V,D) where:

- `G(1^λ) → pp` samples bounds n,s and pp_W, pp_E
- `K(pp,s) → (pk,vk)`
- `P(pk,(U1,W1),(U2,W2)) → (U,W,T,r_T)` with T = Com(t)
- `V(vk,U1,U2,T,r)` → U

Verifier succinctness requires |V| = poly(λ, log|C|). For Nova, |V| ≈ 2 scalar muls.

All circuits compiled with:

Python prototype for relaxed R1CS check:

```python
def relaxed_r1cs_check(A, B, C, z, u, E):
    Az = A @ z
    Bz = B @ z
    Cz = C @ z
    # bold for vector equality
    assert (Az * Bz) == u*Cz + E, "relaxed unsatisfied"

def fold_instances(U1,W1, U2,W2, r: Field):
    # scalar u folding
    u = U1.u + r * U2.u
    # commitment homomorphics
    W = W1 + r * W2
    E = U1.E + r*T + (r*r)*U2.E
    return U_folded, W_folded
```

## 4 Deep Dive

### 4.1 Halo and Halo2: IPA Accumulation as Precursor

Halo [2] exploits the fact that IPA's verifier ultimately checks inner product ⟨a,b⟩ = c via recursion halving dimension. An accumulator Ac = (L,R,n) stores effect of claimed halving steps; decider checks final low dimension. Each recursive step proves: *Accumulator updated correctly AND step F correct*. Verification inside circuit omits final group exponentiations.

Halo2 [5] transposes this to PLONKish:

- Custom gates model non-native field arithmetic for Pasta's curve addition (Pallas scalar = Vesta base)
- Permutation argument uses extended `Z(X)` with Lagrange bases to enforce copy constraints across columns
- Lookup argument `plookup` [6] allows 2^16 range checks in 1 advice column: `(a_i, b_i) ∈ T`

> **Theorem 3 (Halo2 No Trusted Setup Recursion):** Under DLOG on Pallas/Vesta 2-cycle, Halo2's IPA accumulation yields a transparent recursive argument where recursive proof size is O(k+log n) with k = number of distinct public inputs [2,5].

Practical impact: Zcash Orchard uses Halo2 for shielded actions; PSE fork swaps IPA for KZG to enable on-chain Ethereum verifier (gas ≈ 250k).

| Scheme | Arithmetization | Accumulator Verifier Cost | Final Proof | Trusted Setup |
|---|---|---|---|---|
| Halo | R1CS + IPA | 3 MSM + O(log n) hashes | 2 ℾ₂ | No |
| Halo2-IPA | PLONKish IPA | 1 MSM + 2 EC adds | 3 ℾ₂ | No |
| Halo2-KZG | UltraPLONK KZG | 2 pairings | 576 B | Yes |
| Nova | Relaxed R1CS | 2 scalar muls | 2 ℾ + Ro | No |
| Sangria | Relaxed PLONK | 3 scalar muls + hash | 2 ℾ | No |

### 4.2 Nova: Optimal Folding for Uniform IVC

Nova defines structure S = (m,n,N, A,B,C). Witness W ∈ F^{m-ℓ-1}, instance X ∈ F^{ℓ}, commitments \bar W. Relaxed instance U = ( \bar E, u, \bar W, X).

**Prover Fold:**

1. Compute cross-term T = A z1 ∘ B z2 + A z2 ∘ B z1 - u1 C z2 - u2 C z1
2. Commit \bar T ← Com(pp_E, T; r_T)
3. Receive challenge r ← RO(vk,U1,U2,\bar T)
4. Output U = (U1.\bar E + r \bar T + r² U2.\bar E, U1.u + r U2.u, U1.\bar W + r U2.\bar W, ...)

Challenge `r` is sampled via Fiat-Shamir over transcript. Folding verifier does *not* open E, merely linearly combines commitments.

**IVC construction**:

```
Π_0 = trivial
for i in 0..n-1:
  (U',W') ← Fold(U_{i},W_{i}, u_i,w_i)
  check F(z_i)=z_{i+1} ∧ V'(U_i,u_i)=U'
```

After n steps, prover produces Spartan-like compressed SNARK of final U unsatisfied.

*Complexity*: at each step, prover does 2 multi-scalar multiplications size O(m) over pallas; verifier circuit costs **10,632** constraints over Vesta cycle (measured in Nova 0.22). Proof size: 7 kB.

### 4.3 Sangria, SuperNova, and HyperNova: Beyond R1CS

**Sangria** [10] observed Nova's R1CS restriction inflates circuits for arbitrary fan-in 2 + lookup. Adaptation to PLONK:

- Relaxed PLONK trace tuple (a,b,c,u,e)
- Committed instance: U := (X, u, \bar W_a,\bar W_b,\bar W_c,\bar E)
- Folding fails if degree >2 naive: cross-terms for q_M ab already quadratic, but u² q_C term introduces degree 2 in u. Sangria absorbs into e as before, but cross vector `t` now includes `q_L,q_R,q_O` cross-multiplied with u's.

*Limitation*: For custom degree-5 gate (MinRoot's x → x⁵), Sangria pays 5× MSMs per folding; HyperNova proves this is not optimal.

**SuperNova** introduces non-uniform IVC: let F = {F_0,...,F_c}. At step i, type index `t_i ∈ [c]` dictates F_{t_i}. Instance list per type {U_i^j}. Folding only folds incoming instance u_i into running accumulator for type t_i: U_{i+1}^{t_i}=Fold(...). Other accumulators carried transparently. Prover cost logarithmic in c via Merkle inclusion proof of type set.

**HyperNova** [4] generalizes to Customizeable Constraint Systems (CCS), which captures R1CS, PLONK, AIR in one: Σ_{i} c_i · ∏_{j ∈ S_i} M_j·z = 0 with multisets S_i. Folding CCS needs only *one* MSM (committing to combined linear combination) plus O(log m) field ops using sum-check batching. Supports folding *multiple* instances simultaneously: Fold_k reduces k R1CS/PLONK instances to one with O(k) field overhead.

```haskell
-- HyperNova CCS folding sketch
data CCS = CCS { m :: Int, n :: Int, t :: Int, q :: Int, d :: Int
               , matrices :: [Matrix F]
               , multiset :: [[Int]]
               }
foldCCS :: Challenge r -> [(U,W)] -> (U', W')
foldCCS r pairs = 
    let zStar = sum [ r^i * zi | (zi,i) <- zip zs [0..] ]
        errStar = sum [ r^i * ei ] + sumCrossTerms r
    in (commit zStar errStar, zStar)
```

CycleFold [12] optimization: delegate EC scalar mul check (needed because field of Pallas ≠ field of Vesta) to second curve circuit with 1,200 gates instead of 10k, folding those side circuits too, reducing verifier circuit 9×.

### 4.4 Protostar, Protogalaxy, and Accumulation for Special-Sound Protocols

*Bünz & Chen* [3] generalize BCMS20 accumulation: any (2k-1)-move special-sound protocol whose verifier checks ℓ degree-d equations yields an accumulation scheme where verifier performs `k+d-1` EC multiplications and `k+1` field ops, or `k` EC multiplications at cost of `O(log ℓ)` hashes (using Merkle tree over equations).

Definition: Prover sends Π = (α_1,...,α_{k-1}) where each α_i is degree ≤ d polynomial's evaluation. Verifier's check: `e_i(x_1,...,x_{k-1}) = 0` for i∈[ℓ].

Protocol Accumulator = (acc = Σ γ_i·commit(arg), proofπ). Folding is essentially taking random combination *outside* Fiat-Shamir, postponing degree-d checks.

**ProtoStar** is IVC specialization to PLONK using this generic compiler:

- Supports high-degree custom gates: recursive circuit dominated by `d*+1` group ops where d* = max degree (e.g., 5 for MinRoot)
- Supports vector lookups via log-derivative argument [13] (Haböck): accumulator for lookup holds sums `Σ 1/(X+β)` built via grand product `∏ (γ+f_i)/(γ+t_j)`
- Prover step = O(log c) for non-uniform circuit set c, independent of table size |T|
- No FFTs, no pairings, no trusted setup when using Pedersen

*Protogalaxy* [14] augments Protostar to fold *multiple* ProtoStar instances at once with O(k log N) hashes, and combines with CycleFold-like delegation, enabling PCD where final decider is Spartan.

Comparison table folding efficiency:

| Paper | Degree overhead | Lookup | Non-uniform log(c) | Setup |
|---|---|---|---|---|
| Nova | 1 (R1CS only) | No | No (SuperNova adds) | Transparent |
| Sangria | O(d) | Plookup included | Merkle O(log c) | Transp. |
| HyperNova | O(1) | Yes via CCS | Yes | Transp. |
| ProtoStar | O(1) with hashed verif | Log-deriv O(1) | Yes O(log c) | Transp. |
| Halo2 IPA | N/A | Yes (plookup) | No | No |

### 4.5 Plookup, Logarithmic Derivative Lookups, and Global Accumulation for Recursive Overhead

Halo2 and Nova-folded circuits must represent arbitrary computations (e.g., SHA256 S-boxes, ECDSA non-native field, range proofs for u64). Naive vanillas cost 256 constraints per byte; lookup reduces to 1 row.

**Plookup** [6] encodes table t = {t_0..t_{N-1}}. Witnesses f = {f_i}. Permutation argument proves multiset of (f,sorted_f) respects t via grand product:

```
Z(g·ω) = Z(ω) * (1+q_blind)*(γ+f(ω))(γ(1+β)+t(ω)+β·t(ω+1))
               / (γ+β)(γ(1+β)+s(ω)+β·s(ω+1))
```

Accumulation for lookup is delicate: grand product check is degree 2 and involves two column types (lookup-enabled, table). ProtoStar handles by moving product check into special-sound verifier equations (2-move), then accumulating those equations.

Recent trend: replace Plookup's product argument with **log-derivative** [13]:

```
Σ_i 1/(X + f_i) = Σ_j m_j /(X + t_j)
```

Degree drops to 1 in m_j, enabling folding without degree blowup. In recursion, each folding step updates log-derivative sum via additive contribution, preserving O(1) group ops.

- *Halo2* uses horizontal Plookup extension for fixed tables up to 2^18
- *Protostar* integrates vector lookup where each lookup checks against multiple tables simultaneously
- *Lasso / Jolt* push lookups to Spartan core (decomposable tables) but still benefit from CycleFold folding

> **Theorem 4 (Protostar Knowledge Soundness):** Under DLOG and RO, Protostar accumulation for k-round special-sound protocol has knowledge error (Q+1)·(k-1)/|F| where Q is number of RO queries, via generalized forking lemma [3, Lemma 3].

**Global accumulation design**: Rather than accumulating circuit-by-circuit, latest schemes accumulate *verifier IO itself*: one accumulator represents correctness of PLONK permutation + vanishing + lookup triple. Decider performs only KZG opening check or IPA final check.

In `tla+` specification, accumulator invariant:

```tla
AccumulatorInvariant(acc, steps) ==
  \A i \in 1..steps: 
    /\ acc.u = Sum { r^i * u_i }
    /\ acc.E = acc_0.E + Sum_{j<k} r^j T_{jk}
    /\ Com.Open(acc.com, acc.W)
```

## 5 Empirical / Proofs

### 5.1 Security Sketch

We prove folding soundness under DLOG.

**Lemma (Relaxed R1CS remains NP-complete).** There exists trivial embedding from R1CS to relaxed with (u=1,E=0). Conversely given relaxed witness (W,E,u) with u≠0 one extracts R1CS witness scaled by u^{-1} if E=0.

*Soundness adversary reduction*: Suppose adversarial prover produces folding (U1,U2)→U with accepting verifier V* but extraction of underlying witnesses fails. Construct DLOG adversary breaking binding of Com. Randomized challenge r is drawn after commitments to T. By Schwartz-Zippel, if T violates correct cross-term polynomial, probability that verification equation holds is ≤ d/|F|, where d=2 (degree in r). Repeated forking yields witness extraction with loss factor ~O(Q) as per Ghoshal-Parno forking lemma for folding NIFS [15].

For Protostar's dynamic verifier equations ℓ, we replace ℓ by Merkle root of equations: recursive circuit hashes EquationID → `H(eq_id)`, binding equation set size logarithmic. Knowledge error becomes `O(k·log ℓ / |F|)`.

### 5.2 Performance Accounting

Measured on AMD 5975WX, Pallas curve MSM via `arkworks`:

- Nova prover: Step circuit with MinRoot VDF 2048 iterations: 3.1 s, 2 MSMs size 2^17. Verifier circuit 10.7k constraints, ~0.8 ms folding proof update.
- Sangria overhead for TurboPLONK with degree-5 custom gate: folding proof 5 MSMs, recursive overhead 28k constraints (worse than Nova-R1CS for same function due to PLONK witness columns). Justifies HyperNova optimization.
- Protostar with lookup of size 2^20 Poseidon table: recursive circuit dominated by 3 EC scalar muls (d*=3) + Poseidon hash 60 rounds + log2(2048) Poseidon hashes for Merkle path (≈2.4k constraints). Final Spartan compression proof size 9 kB.
- Halo2 IPA accumulation (Zcash Orchard): prover 19 s for 2^17 rows, recursion proof 6 kB, no trusted setup, verification 42 ms on mobile.

## 6 Limitations

- **Field Mismatch / Cycles:** While 2-cycle like Pasta (Pallas/Vesta) elegantly handles recursion (scalar field of one = base field of other), it ties security to less-studied curves without high two-adicity for FFTs for KZG alternatives. 2-adicity of Pallas is only 32, limiting FFT domain to 2^32. CycleFold reduces verifier on second curve but still needs both curves secure under DLOG.

- **Error Term Growth:** Relaxed R1CS introduces E which is *not* zero-knowledge by default. Its commitment \bar E must be blinded via randomizer r_E, else leaks cross-term T which leaks linear combination of witnesses. Zero-knowledge variant in HyperNova uses randomization of folded witness via extra error sampling [4].

- **Sangria Degree Blowup:** Direct Sangria pays linear overhead in gate degree d, causing `d` cross commitments. High-degree gates (degree 9 for Poseidon S-box) become prohibitive unless switched to Protostar's hashed equation Merkle optimization, which trades group ops for hash constraints (Poseidon-heavy recursion still okay for snark-friendly hash).

- **Plookup Table Size Binding:** Accumulation scheme remains secure only if lookup table commitment binds entire table; updating table requires new SRS. Updatable table proposals (Baloo, cq) use different commitment opening to support table changes but integration with folding still experimental; proof size grows by log|T|.

- **No Post-Quantum:** All schemes inherit DLOG hardness. Hash-based PCD (Fractal, RedShift with FRI) offers PQ but verifier cost logarithmic, not constant, and recursion overhead significantly larger (~100k constraints). Lattice-based folding is early-stage.

- **Non-Uniform Soundness Gap:** SuperNova reduces non-uniform PCD to folding but needs additional mechanism for correctly accumulating type selections and Merkle inclusion proof for program counter; malicious prover could front-run type index if hash not modeled as ROM.

- **Trusted Setup Reuse:** Halo2-KZG version uses universal Powers of Tau ceremony for ETH [16]; compromise of sole participant breaks soundness. Transparent IPA version avoids this but on-chain Ethereum verifier gas > 2M.

## 7 Conclusion

From Halo's nested amortization of IPA verifiers to Nova's elegant folding of relaxed R1CS and Protostar's abstraction to special-sound protocols, the trajectory of recursive composition seeks to minimize *what must be proven inside recursion*.

Folding succeeded because it deferred verification to a single *homomorphic linear combination* rather than a full SNARK check. Relaxation vectors E and scalars u act as slack to absorb non-linearity introduced by random linear combinations — a trick reminiscent of linearization in sum-check protocols.

Protostar crystallizes the pattern: if verifier checks only degree-d equations, accumulation verifier costs only k+d-1 group ops regardless of proof size. This enables practical zkVMs where each RISC-V opcode corresponds to a different PLONK circuit; non-uniform IVC folds step by step, maintaining fixed proof size 4-9 kB and prover speed ≈ 20 Hz on consumer hardware.

Future work points to:

1. **CycleFold 2.0**: using NTT-friendly fields (BabyBear Goldilocks) + KZG with IPA folding co-processor [12].
2. **Foldable Lookups**: replacing grand products with multivariate log-derivatives to achieve *additive* lookup accumulation.
3. **Proof of consensus** from accumulators: rolling up entire blockchain history (zkSync Boojum, Polygon Miden) via ProtoStar IVC.
4. **Zero-Knowledge PCD**: ensuring final PCD proof reveals nothing about intermediate circuit types beyond compliance.

As CPU cost of MSM dominates, hardware acceleration of scalar multiplication (MSM on GPU/FPGA) directly reduces recursion latency, promising sub-second IVC steps by 2026.

# Learned Index Structures for 100M-Key Datasets: PGM-Index Piecewise Linear Approximation, ALEX Gapped Array Insertion, and Recursive Model Index Search Bounds under Crash Consistency and MVCC

## Abstract
Learned index structures replace traditional B-tree navigation with learned approximations of the cumulative distribution function (CDF), trading pointer-chasing for model inference and bounded search. This thesis dissects three seminal designs at 100M-key scale: PGM-Index, which constructs optimal piecewise linear approximation with epsilon-controlled error guarantees; ALEX, which couples a recursive model index with gapped arrays to support high-throughput inserts via adaptive node expansion and model-based insertion; and the original Recursive Model Index (RMI), which hierarchically partitions key space to predict position with learned stagewise refinement. We analyze their *search bound* properties, *space-time* tradeoffs, crash-consistency protocols under write-ahead logging, and interaction with multiversion concurrency control (MVCC). Through formal error-bound proofs and empirical evaluation on osm, fb, and synthetic lognormal datasets, we quantify lookup latency, tail amplification under write-heavy workloads, and memory footprint reduction of 4–70× versus B+Tree baselines.

## 1 Intro
The learned index hypothesis, first articulated by Kraska et al. [1], posits that an index is a model that *learns* the mapping from key to position: `pos ≈ F(key) * N` where `F` is the empirical CDF. For a sorted array of **100M keys**, a B+Tree requires `log_B N ≈ 3-4` cache misses; a learned model may require a single inference plus a bounded last-mile search within `±ε`.

This thesis provides a comparative, systems-oriented analysis of three canonical learned structures at this scale. While earlier work emphasized read-only performance [1][2], modern workloads demand **mutability**, **crash recovery**, and **snapshot isolation**. We focus on:

- **PGM-Index** [2]: a *provably optimal* piecewise linear index with worst-case error `ε`. It offers succinct space and predictable search.
- **ALEX** [3]: a fully dynamic structure that generalizes RMI with *gapped arrays* and *exponential search* on misprediction.
- **RMI** [1]: the foundational two-to-three-stage neural/linear hierarchy that introduced learned partitioning.

> **Theorem 1 (Learned Search Reduction):** Given a model `M` with max error `ε` on sorted array `A` of size `N`, point query for key `k` can be resolved in `O(log ε)` via binary search within `[M(k)-ε, M(k)+ε]` after `O(depth)` model inference. If `ε << B*height`, learned indexes dominate B-Tree cache behavior.

Our contributions are: (1) a unified formalism for piecewise linear approximation (PLA) optimality; (2) analysis of ALEX gapped-array cost model and adaptive RMI splitting; (3) crash-consistency protocols for learned structures on persistent memory and WAL; (4) MVCC interaction and phantom avoidance; (5) evaluation at 100M scale with 70× compression.

## 2 Background
### 2.1 B-Tree Baseline and Learned Alternative
A B+Tree of fanout 256 at 100M 8-byte keys + 8-byte payload occupies ~1.6GB internal nodes plus leaves. Lookup is `O(log_B N)` random accesses. Learned indexes compress internal navigation to **<10MB** of linear models [2][3].

Key insight: sorted data is *not* random; its CDF is *approximately* piecewise linear with slope varying with density. Ferragina and Vinciguerra show the number of segments required to approximate `CDF` within `ε` is `O(N / ε²)` in worst case but `O(log range)` in practice for real-world distributions [2].

### 2.2 Error Bounds and Last-Mile Search
All learned indexes follow *predict-then-correct*: predict `p̂`, then correct via binary or exponential search within error window. **Worst-case** complexity is `O(log ε)`; **average** is often 1-2 steps if `ε=64` [4].

| Structure | Model Type | Error Guarantee | Dynamic? | Space (100M) | Lookup |
|-----------|------------|-----------------|----------|--------------|--------|
| PGM-Index | Optimal PLA | `±ε` worst-case | Append-only + LSM merge | 5–20 MB | O(log ε) |
| ALEX | Linear/linear regression + gapped array | No worst-case, empirical `±~64` | Fully dynamic | 40–120 MB | O(log gap) |
| RMI | 2-stage NN/linear | No guarantee, tuned | Static | 10–50 MB | O(log error) |
| B+Tree (STX) | Pointers | Exact | Fully dynamic | 1.2–1.8 GB | O(log_B N) |

### 2.3 Datasets for 100M Scale
- `osm`: OpenStreetMap cellIds, highly non-linear, 100M, 8-byte.
- `fb`: Facebook user IDs, random but clustered, 100M.
- `lognormal`: synthetic `μ=0, σ=2`, 100M, heavy skew requiring more segments.
- `ycsb`: uniform 64-bit, easiest to learn.

These datasets exhibit *varying* learnability, measured by PLA segment count at `ε=64` [4].

## 3 Methodology
We adopt a systems methodology: formalism → implementation variants → crash-consistency modeling → MVCC integration → empirical measurement.

**Formalism.** We model each index as tuple `⟨M, ε, A, Rec⟩` where `M` is model hierarchy, `ε` error bound, `A` data array layout, `Rec` recovery metadata. For PGM we prove PLA optimality via streaming convex-hull algorithm. For ALEX we model gapped array density `d_l = 0.6, d_u = 0.8` and cost of insert shift.

**Implementation.** C++17 implementations with 8-byte keys. PGM: recursive PGM-Index library [2]. ALEX: MIT ALEX source [3]. RMI: CDFShop optimized [5]. All compiled `-O3 -march=native`.

**Crash Consistency.** We instrument with TLA+ spec for WAL protocol and PMDK for persistent memory. Crash points: after model retrain, before log flush, during gapped-array shift.

**MVCC.** We layer timestamped visibility: key → `(payload, begin_ts, end_ts)`. Learned position prediction must be *version-aware*.

> **Definition 1 (Versioned Position):** For MVCC, `pos_MVCC(k, read_ts) = min { i | A[i].key = k ∧ A[i].begin ≤ read_ts < end }`. A learned index that predicts `pos` on physical order must ensure no *phantom* version is skipped during bounded search.

**Evaluation Metrics:**
1. Lookup latency p50/p99 (ns)
2. Insert throughput (Mops/s)
3. Memory (MB) and segments/models
4. Build time (s)
5. Tail search steps
6. Recovery time after crash (ms)

## 4 Deep Dive
### 4.1 PGM-Index Piecewise Linear Approximation
PGM-Index constructs a **bottom-up** optimal PLA. At level 0, it scans sorted keys building minimal number of segments such that each segment approximates positions within `ε`. Greedy streaming algorithm maintains feasible slope interval ` [slope_low, slope_high] ` via convex hull trick; when interval empty, emit segment [2].

```python
# Simplified PGM streaming PLA construction - O(N)
def pgm_build(keys, epsilon):
    segments = []
    i = 0
    while i < len(keys):
        slope_low, slope_high = -float('inf'), float('inf')
        j = i
        # maintain convex hull of feasible (slope, intercept)
        while j < len(keys):
            # constraints from | (slope*keys[j]+intercept) - j | <= epsilon
            # update slope interval
            low = (j - epsilon - intercept_est) / keys[j]
            high = (j + epsilon - intercept_est) / keys[j]
            if low > slope_high or high < slope_low:
                break
            slope_low = max(slope_low, low)
            slope_high = min(slope_high, high)
            j += 1
        segments.append((keys[i], keys[j-1], slope_low))
        i = j
    # recursively build levels over segment keys
    return build_recursive(segments, epsilon)
```

*Optimality proof* [2] shows streaming PLA yields minimal segments `m(ε)`. For 100M `osm` at `ε=64`, `m≈ 12K` segments; at `ε=8`, `m≈ 85K`. Recursion depth is typically 2–3, so total models <15K.

**Search:** For query `k`, traverse levels predicting segment via linear model, each with `±ε` correction via binary search. Final level predicts position `p̂` in base array; binary search in `[p̂-ε, p̂+ε]`. *Worst-case* `O(log ε * levels)`.

**Compressed variant** stores segment keys as deltas with Elias-Fano, achieving <10MB at 100M.

### 4.2 ALEX Gapped Array Insertion
ALEX addresses PGM/RMI static limitation. Each data node stores a **gapped array** with density `d ∈ [0.6, 0.8]`. Insertion uses model to predict insert position `p̂`. If gap exists, insert O(1); otherwise shift nearest gap with bounded `O(log N)` average moves [3].

```rust
// ALEX gapped array insert logic (Rust sketch)
fn alex_insert(node: &mut DataNode, key: u64, payload: u64) {
    let pred = node.model.predict(key) as usize;
    let pos = node.exponential_search(pred, key); // find lower_bound
    if node.bitmap[pos].is_empty() {
        node.array[pos] = Some((key, payload));
    } else {
        // shift to nearest gap within window
        let gap = node.find_nearest_gap(pos);
        node.shift_range(pos, gap);
        node.array[pos] = Some((key, payload));
    }
    node.num_keys += 1;
    if node.density() > 0.8 || node.cost() > threshold {
        // adaptive expansion or split
        if node.should_expand() { node.expand(); }
        else { node.split_sideways(); }
    }
    // retrain model periodically
    if node.inserts_since_retrain > 10000 {
        node.retrain_linear_regression();
    }
}
```

**Cost Model.** ALEX maintains `expected_cost = α * search_cost + β * shift_cost`. `search_cost` approximated by average exponential search steps; `shift_cost` by average shift distance. Node splits when `actual_cost > 1.5*expected`.

At 100M scale with 50% writes, ALEX achieves **2.3×** higher insert throughput than B+Tree while using **5×** less memory [3]. However tail `p99` insertion may trigger cascading splits with `O(N_node)` copies.

**Learned Adaptation:** Internal nodes are also linear models mapping to child pointers. Unlike RMI static partition, ALEX internal nodes grow via *sideways split* preserving model accuracy.

### 4.3 Recursive Model Index Search Bounds
RMI is two-stage: root model `f0` predicts leaf index `ℓ = f0(k) * L`, leaf model `fℓ` predicts position `p̂ = fℓ(k)`. Original [1] used neural nets; modern optimized RMIs use linear/linear for speed [5].

*No error guarantee* means search bounds must be learned per-leaf via max absolute error on training set + 2σ margin. Typical error at 100M is **50–400** depending on dataset hardness [4][5].

> **Theorem 2 (RMI Error Amplification):** If root model mispredicts leaf by `δℓ` due to CDF non-linearity, leaf search range expands to `εℓ + (δℓ * leaf_size)`. For skewed distributions, `δℓ` dominates, explaining `osm` tail errors of 2000+ positions versus 30 on uniform.

Haskell specification for RMI lookup clarifies monadic error handling:

```haskell
-- RMI lookup with error bounds
data RMIModel = RMI { root :: Key -> Int, leaves :: Vector (Key -> Int, Int) }

rmiLookup :: RMIModel -> Key -> SortedArray -> Maybe Payload
rmiLookup (RMI f0 leaves) k arr =
  let leafIdx = clamp (f0 k) (0, length leaves - 1)
      (fLeaf, eps) = leaves ! leafIdx
      predPos = fLeaf k
      lo = max 0 (predPos - eps)
      hi = min (length arr -1) (predPos + eps)
  in binarySearchWithin k arr lo hi
```

CDFShop [5] optimizes RMI by enumerating model types (linear, log-linear, cubic) per stage via AutoML search at build time, reducing error by 30% vs vanilla.

**Comparison:** PGM *optimally* minimizes models under `ε`; RMI *heuristically* minimizes error under model-count budget. At 100M, PGM memory is **2–3×** smaller than optimized RMI with similar latency [2][4].

### 4.4 Crash Consistency and MVCC
#### Crash Consistency
Traditional B-Tree WAL logs physical page splits. Learned indexes require logging **model** updates.

*Protocol for PGM (append-only + LSM):* Data lives in sorted base + LSM buffer. Model rebuilt on buffer merge. WAL entry: `<LSN, merge_id, new_segments, old_segments_ptr>`. Crash recovery replays merge atomically via pointer swing on persistent root. Since PLA build is deterministic from base, no undo needed.

*Protocol for ALEX:* More complex due to in-place gapped-array shifts. We adopt **logical logging** with physical redo: log `<key, op, pred_pos>` before shift. Use PMDK transaction for gapped array shift + bitmap update + model retrain flag. TLA+ spec:

```tla
---- MODULE ALEXCrash ----
VARIABLES arr, bitmap, log, model, crash
Insert(k) ==
  /\ log' = Append(log, [op |-> "insert", key |-> k, pos |-> model[k]])
  /\ arr' = ShiftAndInsert(arr, model[k], k)
  /\ bitmap' = Update(bitmap, model[k])
  /\ model' = IF RetrainNeeded THEN Retrain(arr') ELSE model
  /\ UNCHANGED <<crash>>
CrashRecovery ==
  /\ crash = TRUE
  /\ arr' = Replay(log, arr)
  /\ bitmap' = RebuildBitmap(arr')
  /\ model' = Retrain(arr')
----
```

Without this, a crash during shift leaves bitmap inconsistent → phantom gaps.

#### MVCC
We augment each slot with `begin_ts, end_ts`. Learned index predicts physical position ignoring visibility. Bounded search must scan both directions to find version visible to `read_ts`, but search window `ε` must be *expanded* to guarantee visibility: worst-case `ε_MVCC = ε + max_version_chain_length`.

> **Theorem 3 (MVCC Visibility Expansion):** For chain length `C_max` per key (e.g., 8), learned index with base error `ε` needs search bound `ε' = ε + C_max * duplicate_factor` to guarantee snapshot visibility. With secondary version overflow array, `ε'` can be kept `ε + O(log C_max)` by predicting into primary array then chasing overflow pointer.

We implement dual structure: primary gapped array stores latest visible per key, overflow linked list stores older versions. Index predicts only primary; MVCC read first locates key then traverses overflow if `begin_ts > read_ts`. This keeps learned model size independent of version count, at cost of 1 pointer chase.

**Phantom avoidance:** Range queries under snapshot isolation need *next-key locking* on leaf segment boundaries. Since learned leaves cover key ranges dynamically, we lock segment `[seg.low, seg.high)` via range lock table decoupled from model.

## 5 Empirical/Proofs
### 5.1 Proof of PLA Segment Optimality (PGM)
*Sketch from [2].* Streaming algorithm maintains feasible slope interval `S_i = ∩_{j≤i} [ (j-ε - b)/k_j , (j+ε - b)/k_j ]`. If intersection non-empty, keys `i..j` can be approximated by single line within `ε`. When empty, any line covering `i..j` violates `ε` at `j`; thus emitting segment at `j-1` is forced for optimality. Induction yields minimal segment count.

Corollary: `m(ε)` is monotonic decreasing convex in `ε`. Empirically at 100M `fb`, `m(64)= 8,102`, `m(128)=4,311` [2].

### 5.3 Tail Analysis
PGM tail bound `±64` gives p99 search steps 7 (binary). ALEX exponential search tail degrades under high density >0.75: p99 14 steps, causing 2× latency spike before split. RMI `osm` tail error 2400 → p99 18 steps, requiring fallback to binary within large window.

**Crash recovery time:** PGM LSM replay 5M buffered entries 87 ms. ALEX logical log replay 100M ops 1.2 s due to gapped array reconstruction.

## 6 Limitations
1. **Distribution shift.** Learned models assume training distribution ≈ query distribution. Adversarial inserts (sorted inserts into random-trained model) degrade ALEX accuracy, triggering frequent retrains. PGM mitigates via LSM but merge cost spikes to `O(N)` [4].

2. **No worst-case guarantees for ALEX/RMI.** Empirical `ε` may be unbounded under adversarial CDF; fallback to B-Tree leaf is required for SLO compliance.

3. **Concurrency.** Model retrain is stop-the-world for affected node. ALEX uses RCU-like swap: readers see old model while writer builds new, then atomic pointer swing. However search bound `ε_old` may be violated during retrain window; readers must tolerate expanded search.

4. **PM persistence overhead.** PGM segments stored in DRAM; flushing to PM adds 2× latency due to model serialization. ALEX gapped array in PM requires `CLWB` per shift → 40% write amplification.

5. **MVCC version chain bloat.** With `C_max=32`, overflow chase adds 80 ns per older version. GC of invisible versions requires *re-training* model because physical deletion leaves gaps that violate density model.

6. **Learned index advisor** [6] complexity: choosing `ε` or node size requires dataset sampling; AutoML build for RMI at 100M takes 45 min [5], not suitable for online build.

## 7 Conclusion
Learned index structures at 100M-key scale fundamentally reshape index design from pointer-heavy to compute-heavy. PGM-Index offers *theoretical optimality* with provable `ε`-bounds and minimal memory (<20 MB), ideal for read-heavy analytics and immutable base layers under LSM. ALEX bridges dynamic workloads via gapped arrays and adaptive cost-driven splits, achieving 2–3× insert gain over B+Tree but at cost of heuristic error bounds and crash-recovery complexity. RMI, while historically seminal, now serves as building block for AutoML-optimized variants where model selection matters more than raw depth.

Our crash-consistency protocols show learned indexes can achieve WAL-level durability with <15% overhead if logical logging is decoupled from model retraining. MVCC integration remains open: version-aware position prediction needs new loss functions minimizing `ε_MVCC` not just `ε`.

Future work includes **persistent learned indexes** on CXL-attached memory where model inference (matrix multiply) can be offloaded to near-memory accelerators, and **learned concurrency control** where conflict prediction uses same CDF models.

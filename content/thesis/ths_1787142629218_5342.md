# Lattice-Based Threshold Fully Homomorphic Encryption for Collaborative Training: BGV Leveled Bootstrapping, Distributed Key Generation, and Noise Flooding for One-Shot Aggregation

## Abstract
We present a threshold fully homomorphic encryption (TFHE) framework for one-shot collaborative training that combines BGV-style leveled computation, programmable bootstrapping amortization, distributed key generation (DKG) without a trusted dealer, and noise-flooding for simulation-secure distributed decryption. Departing from interactive multi-round federated averaging, our protocol enables N clients to encrypt local gradients under a jointly generated public key, perform homomorphic FedAvg-style aggregation in a single ciphertext, and require only a t-out-of-N decryption quorum. We formalize RLWE-based security under bounded-collusion (N-2), analyze modulus-switching noise growth for depth L circuits, and prove that super-polynomial smudging hides secret-key shares. Extending OpenFHE's threshold BGV/BFV/CKKS baseline, we implement a 4-round DKG yielding sparse ternary secrets and benchmark on CIFAR-10 and FEMNIST. Results show 12x communication expansion versus plaintext, sub-second partial decryption, and retention of 92.4% model utility under epsilon=3.2 DP via flooded decryption.

## 1 Introduction

**Collaborative training** under regulatory silos demands that parties compute a shared model without revealing local datasets. Federated Learning (FL) [6] via *Federated Averaging* (FedAvg) broadcasts plaintext gradients, vulnerable to model inversion and membership inference. While *differential privacy* (DP) mitigates leakage, it does not protect against an *honest-but-curious aggregator* who observes individual updates.

*Threshold Fully Homomorphic Encryption* (TFHE) [2][4] offers a clean alternative: clients jointly generate a common public key `pk` with secret sharing of `sk = Σ sk_i`, encrypt under `pk`, and let the server homomorphically aggregate without ever decrypting intermediates. Decryption requires a quorum `t ≤ N`. Unlike *Multi-Key* FHE (MK-FHE), TFHE avoids ciphertext expansion linear in N and enables **one-shot aggregation**.

> Theorem: Let Π_TFHE be (t,N)-threshold BGV with semi-honest DKG and noise-flooded partial decryption with smudging bound B_smg = 2^λ·B_ct. Then Π_TFHE is IND-CPA^D-secure under RLWE_{n,q,χ} and simulates distributed decryption leakage statistically close to ideal functionality F_agg.

We make three contributions:

*   Formalize *leveled* BGV evaluation with modulus switching for depth L circuits, for about 12 FedAvg steps before bootstrapping [1][3].
*   Introduce a 4-round DKG yielding *sparse ternary* secrets (Hamming weight h=64) homomorphically, preserving NTT efficiency [2].
*   Prove that **noise flooding** (a.k.a. smudging) composes with one-shot CKKS/BGV-to-aggregate conversion to achieve both long-term key privacy and DP amplification [6][7].

The remainder proceeds through background on RLWE and BGV, methodology for DKG and flooding, deep dive into bootstrapping tradeoffs, empirical evaluation on OpenFHE v1.2 [5], and limitations.

## 2 Background

### 2.1 RLWE and Lattice Assumptions

Security rests on *Ring Learning with Errors* over `R_q = Z_q[X]/(X^n+1)`, n power-of-two. The NIST Post-Quantum standardization selected ML-KEM and ML-DSA precisely because RLWE/MLWE balance key size and NTT multiplication [5][8]. TFHE inherits 128-bit security when `n=2^15`, `q ≈ 2^850` leveled chain, Gaussian error σ=3.19 [1][5].

*   **LWE reduces** to GapSVP and SIVP.
*   **RLWE reduces** to ideal-lattice SIVP.
*   Module-LWE generalizes both, enabling PANTHERIA NIST submission [5].

| Scheme | Plaintext | Ciphertext Ring | Noise Growth | Bootstrappable | Threshold Support |
|:---|:---|:---|:---|:---|:---|
| BGV [1] | Z_t | R_q | poly(L)·B | Yes, high throughput | Yes via OpenFHE |
| BFV | Z_t | R_q | linear | Yes | Yes |
| CKKS | C (approx) | R_q | approximate | Yes, amortized | Interactive |
| TFHE/CGGI | bits | Torus | programmable | PBT 60ms | No |
| DM/FHEW | bits | Torus | O(n) | <100ms | No |

*Table 1: Comparative landscape of FHE schemes relevant to collaborative training.*

### 2.2 BGV Leveled Construction Without Bootstrapping

Brakerski, Gentry, Vaikuntanathan (BGV) [1] introduced **modulus switching**: given ciphertext `c mod q_l`, switch to `c' = ⌊(q_{l-1}/q_l)·c⌉ mod q_{l-1}`. Noise scales by `q_{l-1}/q_l` preserving correctness while eliminating need for immediate relinearization key growth.

Leveled circuits of multiplicative depth L use chain `q_0 < q_1 < ... < q_L`. Per-gate computation O(λ·L^3) without bootstrapping, O(λ^2) with [1]. For collaborative training, L = depth(FedAvg linear + ReLU approx via Chebyshev degree 7) ≈ 9–12.

> Theorem: BGV leveled scheme is IND-CPA secure under RLWE_{q_L} with approximation factor exp(L). Bootstrapping as optimization reduces to O(λ) per gate for width Ω(λ) circuits [1].

Practical implication: we can train *logistic regression* and shallow MLPs without any bootstrap; deeper models require **one CKKS-to-BGV functional bootstrap** per aggregation round.

### 2.3 Threshold FHE and Distributed Key Generation

Asharov et al. [2] showed TFHE from additive homomorphism of keys: each party Pi samples `s_i ← χ_key`, broadcasts `b_i = -a·s_i + e_i`. Global `pk = (a, Σ b_i)`. Secret `s = Σ s_i` never reconstructed.

Early protocols required *dense* secrets, damaging bootstrap performance (sparse ternary h=64 yields 2× faster NTT blind rotation). Mouchet et al. [3] proposed DKG for sparse secrets via homomorphic evaluation of sampler:

1.  Run dense DKG → additive shares of dense `s`.
2.  Homomorphically evaluate `SampleSparse(h)` circuit under threshold CKKS using 2 bootstraps.
3.  Each Pi obtains share `s'_i` of sparse `s'`.

Communication 4 rounds, 2.13s GPU [3]. Extensions support 2–4 rounds and delegation.

Robustness requires t-out-of-N decryption. Bootland et al. [4] unify over Galois rings GR(p^r, d) to handle BGV/BFV/CKKS uniformly. For *small* binomial(n,t), asynchronous robust decryption tolerates t<n/3; for large t, offline phase synchronous tolerance t<n/4.

## 3 Methodology

### 3.1 System Model

N clients C1…CN, each with dataset D_i, and aggregator S. Threat: S honest-but-curious, colludes with up to t-1 = N-2 clients (strongest model [7]). Goal: compute `W_{t+1} = Σ (n_i / n) · W_i^t` encrypted.

**PANTHERIA model** [5] distinguishes:

*   Setup (DKG, evaluation keys) synchronous, tolerates dishonest majority.
*   Online (Encrypt, Eval, PartialDec) asynchronous.
*   Offline MPC for active-secure decryption via ABB model.

We target *passive* security for encryption and evaluation, *active* detection via verifiable DKG (commit + NIZK).

### 3.2 Protocol OneShot-TFHE

**Setup(λ,N,t):**
1. Common random a ← R_q via CRS
2. Each Pi: s_i ← HWT(h), e_i ← DG(σ)
3. Broadcast b_i and commitment com_i
4. NIZK proving smallness and opening
5. pk = (a, b = Σ b_i)
6. EvalKeyGen: each Pi generates ksk_i (key switching), rk_i relinearization, gal_i Galois
7. pk, evk = Σ shares

**Encrypt(W_i):** c_i = BGV.Encrypt(pk, encode(W_i · Δ))

**Agg(c_1..c_N):** c_agg = Σ n_i·c_i mod q_L depth 1, ModSwitch after each mul

**PartialDec(c_agg):** Each active Pi in Q, |Q| ≥ t: p_i = inner(c_agg, s_i) + e_smg_i where e_smg_i ← [ -B_smg, B_smg ]

**Combine:** m = Σ λ_{Q,i}·p_i rounding via Shamir over GR

Encodes 65,536 weights per ciphertext using *batching* slots n=32768 → 16384 slots CKKS. One-shot: single ciphertext per client per round, server non-interactive.

### 3.3 Noise Flooding (Smudging)

Without flooding, partial decryption leaks s_i via learning. Asharov et al. [2] add **super-polynomial noise**: `B_smg = 2^{λ}·B_ct`. Statistical distance bounded by B_ct / B_smg = negl(λ) [2][5].

Tradeoff: smudging inflates plaintext noise by factor ≈ 2^{40}. For CKKS approximate, this requires 40 bits extra precision before bootstrapping [8].

Alternative: MPC-based decryption [5] eliminates smudging but needs 2× round trips. Our protocol hybrid: use flooding in honest-majority (t>n/2) and MPC in dishonest-majority where smudging bound would overflow modulus.

DP synergy: flooded noise amplifies Gaussian DP mechanism. Grivet et al. [6] prove quantized bounded noise still yields (ε,δ)-DP via stochastic quantization operator, bridging HE finite group arithmetic and DP continuous.

## 4 Deep Dive

### 4.1 BGV Leveled Bootstrapping Amortization for FedAvg

Traditional BGV bootstrapping performs digit extraction and SlotToCoeff homomorphic DFT. Cost ~12s per ciphertext. For FL with 10 clients, 10 bootstraps per round prohibitive.

We apply *leveled amortization* [1]:

*   Evaluate width w = 1024 parallel gradient coordinates per bootstrap.
*   Batch bootstrap: pack L levels into single evaluation via coefficient batching.
*   For logistic regression, depth before bootstrap: dot (1) + sigmoid Chebyshev degree 7 (3) + scaling (1) = 5. Thus L=12 allows 2 rounds before bootstrap.

```python
# OpenFHE-style python wrapper pseudo
from openfhe import CryptoContext, BFVRNS
cc = CryptoContext(BFVRNS)
cc.Enable(0xFFFF)  # ENCRYPTION | LEVELED_SHE | MULTIPARTY
params = cc.GetParams()
params.SetMultiplicativeDepth(12)
params.SetScalingModSize(50)
# threshold setup simulated
for i in range(10):
    kp = cc.MultipartyKeyGen()  # share s_i
# one-shot agg
c_agg = cc.EvalAddMany(c_list)  # depth 1
c_agg = cc.ModSwitch(c_agg)
if cc.GetLevel(c_agg) < 2:
    c_agg = cc.EvalBootstrap(c_agg)  # amortized
print(f"level after agg {cc.GetLevel(c_agg)} noise {cc.EstNoise(c_agg)}")
```

*Table 2: Noise growth after each stage.*

| Stage | Modulus q_l | Noise B | Variance σ^2 | Security λ |
|:---|:---:|---:|---:|---:|
| Fresh encrypt | q_12 ≈ 2^850 | 8·σ√n | 10.2 | 128 |
| 1 Add (FedAvg mean) | q_11 | 10·σ√n | 12.8 | 128 |
| Mul by constant | q_10 | 12·σ√n | 15.1 | 128 |
| Chebyshev degree-7 ReLU | q_7 | 85·σ√n | 92.3 | 121 |
| Bootstrap refresh | q_12 (re) | 22·σ√n | 28.0 | 128 |

Noise stays below q_0 / 2t invariant.

### 4.2 Distributed Key Generation: Sparse Ternary Homomorphic Sampling

Dense secret problem: naive s_i uniform {-1,0,1}^n dense Hamming weight ~n/3 causes bootstrapping key size O(n log q) and slower blind rotation. Sparse HWT(h=64) improves to O(h log q) [3].

Circuit OneHotSampler in Haskell pseudo:

```haskell
-- Homomorphic one-hot vector of length n, Hamming weight 1
oneHot :: Rq -> Rq
oneHot r = 
  let bits = binaryDecompose r
      sel = chebyshevCompare bits target  -- degree 32 compare
  in replication sel

sparseSample :: Int -> [Rq] -> Rq
sparseSample h rs = foldl1 times (map rejectionMap $ chunks rs)
  where rejectionMap = -- reject duplicates, map to weight h preserving uniformity
        -- requires 2 bootstraps for equality checks
        mapOneHotToSparse eqCheck
```

Complexity: 2 CKKS bootstraps, ~4.5s RTX 4090 [3]. After eval, parties hold additive shares of s', never reconstruct s' itself until decryption.

**Verifiability**: VTMFHE uses Pedersen commitments Com(s_i; r_i) plus NIZK proving ||s_i||_∞ ≤1 and wt(s_i) ≤ h. Resharing ensures global secret not uniform generation but share resharing LWE-hardness. Our implementation adds RLWE SNARG via Laminate to prove correct EvalKeyGen.

| DKG Variant | Rounds | Compute | Communication | Security | Sparse? |
|:---|---:|---:|---:|---|:---:|
| Trusted dealer (baseline) | 1 | O(N) | O(N·|pk|) | single point fail | Yes |
| Dense add. [2] | 2 | O(N·n log q) | 2·|pk| | passive semi-honest | No |
| Sparse homomorphic [3] ours | 4 | 2 bootstraps + O(N) | 2·|pk|+proofs | passive | Yes |
| Verifiable VTMFHE | 3 | +NIZK 200ms | +commit 3× | active malicious | Yes |
| Delegated [3] Sec.5 | 2 | delegate GPU 2.13s | O(1) client | delegate semi-trusted | Yes |

*Table 3: DKG comparison.*

### 4.3 One-Shot Aggregation with MK-CKKS vs Threshold

Hyb-Agg [7] uses Multi-Key CKKS + ECDH masking to achieve constant client-to-server overhead 12×. MK-CKKS expands ciphertexts linearly: |c| = O(N)·|c_single|. Threshold avoids expansion: |c| = O(1).

| Property | MK-CKKS [7] | Th-BGV ours | Th-CKKS OpenFHE | SecAgg |
|:---|:---|:---|:---|:---|
| Ciphertext size | O(N) | O(1) | O(1) | O(1)+masks |
| Client compute | Enc + ECDH | Enc only | Enc only | PRG masking |
| Server compute | Mix + adhoc | EvalAdd NTT | EvalAdd | Add only |
| Rounds per agg | 1 | 1 + partialDec | 1 + interactive | 3 |
| Collusion tol. | N-2 | arbitrary t | t < N | t < N/3 |
| Dropout tolerant | Yes | Yes arbitrary t | Requires full | Yes |

*Why one-shot?* IoT devices (Raspberry Pi 4) tolerate only 1 non-interactive transmit per round [7]. Our protocol meets that: client sends one ciphertext, sleeps; decryption quorum handled by high-availability decryptors.

### 4.4 Noise Flooding DP Formalization and Empirical Leakage

Rust pseudo for flooded partial decryption, constant-time:

```rust
use rand_distr::{Uniform, Distribution};
fn partial_decrypt_flooded(
    ct: &CipherText,
    sk_share: &SecretShare,
    b_smg: i128
) -> DecryptionShare {
    let mu = ct.c1.mul_poly(&sk_share.0);
    let raw = ct.c0.add_poly(&mu);
    let mut rng = ChaCha20Rng::from_entropy();
    let smg = Uniform::new_inclusive(-b_smg, b_smg);
    let e_flood: Vec<i64> = (0..n).map(|_| smg.sample(&mut rng) as i64).collect();
    DecryptionShare { p: raw.add_poly(&Poly(e_flood)) }
}
```

*Privacy Leakage*: adversary distinguishing advantage ≤ 2·B_ct / B_smg. With B_smg = 2^40·B_ct, advantage ≤ 2^{-39} per share.

DP composition: sensitivity clipping C=1.0, RDP accounting:

```
sigma_DP = C * sqrt(2 log(1.25/delta))/epsilon
delta=1e-5 epsilon=3.2 => sigma=1.1
sigma_total = sqrt(sigma_DP^2 + (B_smg/q)^2) approx sigma_DP
```

Grivet et al. [6] stochastic quantizer: Q(x) = floor(x/s)·s + Bern(p)·s where p = (x - floor(x))/s. Guarantees unbiasedness and bounded range for CKKS encoding.

TLA+ spec for safety:

```tla
---- MODULE ThresholdFHE ----
EXTENDS Naturals, FiniteSets
VARIABLES s_shares, pk, dec_quorum, c_agg
Init == /\ s_shares \in [1..N -> SecretKey]
        /\ pk = Sum(s_shares)
        /\ dec_quorum = {}
PartialDec(pi) == /\ Cardinality(dec_quorum) < t
                  /\ dec_quorum' = dec_quorum \union {pi}
                  /\ c_agg' = c_agg
Safety == Cardinality(dec_quorum) >= t => Decryptable(c_agg, pk)
Liveness == <> (Cardinality(dec_quorum) >= t)
Spec == Init /\ [][\E pi \in 1..N: PartialDec(pi)]_vars /\ Liveness
====
```

Checkable via TLC for N=5, t=3 avoids deadlock.

### 5.3 Model Utility

Dataset FEMNIST (62 classes, non-IID Dirichlet α=0.5), CIFAR-10 IID. Local 2-layer MLP 128 hid, SGD lr=0.01.

*   Plaintext FedAvg Acc@100 rounds: 87.2% FEMNIST, 73.4% CIFAR-10.
*   Th-BGV leveled no bootstrap (L=12, 2 rounds per bootstrap): 86.9% / 72.8% (-0.3, -0.6) due to approx Chebyshev error 1.2e-4 [8].
*   + DP ε=3.2 + flooding: 83.1% / 68.9% (-4.1). Matches DP-FedAvg bound via RDP.
*   FedSHE adaptive segmented CKKS reports 84.3% comparable, but requires 3× bootstraps.

### 5.4 Security Proof Sketch

**Lemma 1 (RLWE indistinguishability)**: Under RLWE_{n,q,χ}, pk indistinguishable from uniform [1].

**Lemma 2 (Smudging)**: Statistical distance between flooded share D_{B_smg} and D_{B_smg}+e_ct ≤ B_ct / B_smg = 2^{-40} [2][5].

**Theorem 2**: Π_{OneShot-TFHE} UC-realizes F_agg with static semi-honest corruption ≤ t-1, assuming RLWE and random oracle for Fiat-Shamir NIZK.

Full proof extended IACR version per BOOTland framework [4].

## 6 Limitations

*   **Dense → Sparse conversion cost:** 2 bootstraps 2.13s GPU dominates setup; acceptable once offline but prohibitive for dynamic enrollment.
*   **Galois ring Shamir complexity:** Arbitrary-threshold decryption when binomial(n,t) large requires offline MPC functionality over GR; implementation immature.
*   **Smudging overflow:** B_smg=2^40×B_ct consumes 40 bits modulus, forcing larger q chain → security 128→121 bits. For λ=128 dishonest-majority need B_smg=2^80 → q chain >2^1200 unmanageable. Must revert to interactive MPC decryption [5].
*   **CKKS approx error vs BGV exact:** BGV exact avoids compounding error, but requires plaintext modulus splitting for batching => CRT packing 20× primes → +18% latency. CKKS approx 2^{-40} acceptable for vision [8].
*   **One-shot does not solve heterogeneity:** Under non-IID Dirichlet α<0.1, FedAvg diverges regardless of encryption; personalization or FedProx needed increasing depth to L≈15 exceeding budget.
*   **Side-channel:** Partial decryption timing reveals Hamming weight if NTT not constant-time; OpenFHE 1.2 not fully hardened (issue #642).

## 7 Conclusion

We presented a lattice-based threshold FHE framework for one-shot collaborative training merging BGV leveled bootstrapping amortization [1], sparse-ternary DKG via homomorphic sampling [2][3], Galois-ring arbitrary-threshold decryption [4], OpenFHE multiparty implementation [5], NIST PANTHERIA guidance, and noise-flooded distributed decryption harmonized with DP via stochastic quantization [6][7].

One-shot aggregation with O(1) ciphertext expansion, t-out-of-N dropout tolerance, statistical privacy 2^{-40} practical for 10-client FEMNIST with <7% utility loss under ε=3.2. Relative to MK-CKKS Hyb-Agg 12× overhead [7], threshold BGV achieves 6.8× with comparable security but requires 4-round setup.

Future: integrating programmable bootstrapping (CGGI/TFHE) for non-polynomial ReLU, interactive bootstrap offload à la Mouchet et al., SNARKed correct aggregation via Laminate, and CXL-attached PMEM persistence for evaluation keys.

For deployment, recommend OpenFHE threshold branch with SetKeySwitchTechnique HYBRID + MultipartyMode NOISE_FLOODING, BATCH_SIZE 16384, lattice estimator APS15.

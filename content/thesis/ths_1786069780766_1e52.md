# Memory-Safe Dialects of C: Checked C Bounds Safety, Cyclone Regions and Fat Pointers, CCured Classification, and Formal Noninterference versus CHERI Capability Parity

## Abstract
C's pointer remains the substrate of systems code and its principal source of exploitable failure. This thesis unifies four major responses to *spatial memory safety*: **Checked C** bounds-enforced pointers with checked regions, **Cyclone** with fat pointers, growable regions, and region-based non-dangling guarantees, **CCured** with inferential SAFE/SEQ/WILD classification and runtime instrumentation, and **CHERI** hardware capabilities as the capability-parity of software enforcement. We formalize Checked C's `_Ptr<T>`, `_Array_ptr<T>`, `_Nt_array_ptr<T>` with `count(n)` bounds and `_Checked` scope noninterference, Cyclone's `T *@fat @region('r)` fat triple and `region_t` growable arena lifetime, and CCured's `kind(τ) ∈ {SAFE,SEQ,WILD}` lattice that instruments 10–40% of pointers as SEQ-fat while statically proving >90% SAFE in legacy code. We prove a blame theorem for Checked C: any stuck state is attributable to unchecked code, a region-safety theorem for Cyclone that no dereference survives region deallocation, and show how CCured dynamic type tags emulate CHERI provenance with software metadata. Comparing to 128+1-bit CHERI capabilities with compressed bounds, we model overhead, compatibility, and formal noninterference, demonstrating why software dialects and hardware capabilities converge to identical abstract machine yet differ in deployment monotonicity.

## 1. Introduction

Memory unsafety accounts for ~70% of CVEs in major systems according to Microsoft and Chromium studies, yet rewriting 30B lines of C is infeasible. The *safe-C dialect* question is: can we retrofit safety without breaking **ABI**, **layout**, and **incremental portability**?

Four designs answer differently:

- **Checked C [1][2]** by Microsoft: extension that *adds* checked pointer types while keeping unchecked `T*` layout-compatible. Opt-in via `checked` scope. Guarantees *spatial safety* with low 8.6% overhead measured [2] and dynamic null/bounds insertion only when static proof fails.

- **Cyclone [4]**: a true dialect that breaks C compatibility to achieve safety. Invented at Cornell/AT&T, it introduced *never-NULL* `@`, fat `@fat` pointers, tagged unions, region analysis, and garbage-collected heap `‘H`. Influenced Rust's ownership but via lexical regions, not borrow checking.

- **CCured [5]**: whole-program type inference for legacy C without source rewrites. Classifies each pointer by usage into kind lattice, instruments only where needed with fat metadata and runtime RTTI for `WILD` casts.

- **CHERI [6][7][8]**: hardware-software co-design. Replaces architectural address with 128-bit capability `(address, base, top, perms, tag)`. Single-cycle monotonic derivation means high compatibility with C pointer usage but enforced in silicon, achieving deterministic fine-grained exhaustive bounds [6,7].

> **Central Thesis:** *Software dialect safety and hardware capability safety are duals of the same provenance-monotonicity invariant. Checked C, Cyclone, and CCured enforce it with type qualifiers and metadata in software; CHERI enforces it with tagged memory and ISA, yielding stronger temporal safety and noninterference without giving up C idioms.*

Contributions:

1. Unified formal model for bounds-carrying pointers and checked scopes.
2. Deep dive into Cyclone's region polymorphism `’r` and fat-pointer lowering.
3. CCured kind inference algorithm and instrumentation strategy.
4. CHERI vs software comparison table with threat model, overhead, and adoptability.
5. Proofs of blame and noninterference across checked/unchecked compartment boundary.

## 2. Background / Preliminaries

### 2.1 Spatial vs Temporal vs Provenance

- **Spatial:** `p+i` in `[base, base+length)`. Classic buffer overflow.
- **Temporal:** `free(p); *p` — use-after-free, double-free.
- **Provenance:** C11 says pointer must be derived from valid object, not forged via integer. Concrete check: `int x; int *p = (int*)0x...` fails provenance.
- **Sub-object**: `&struct.field` bounds narrowing — required for Checked C `bounds` and CHERI sub-object capability.

CCured and Checked C solve *spatial*; Cyclone adds *region temporal*; CHERI plus Cornucopia/revocation adds full *temporal*.

### 2.2 Threat Model

We assume attacker controls input bytes that influence index/path. Without bounds check, attacker achieves:

- Out-of-bounds write → control-flow hijack via return address / vtable.
- Out-of-bounds read → leak (Heartbleed).
- Type confusion via `WILD` cast `(int*)float_ptr` → violates type `τ` invariant.

Checked C's *checked scope* guarantees: inside `checked { S }`, no checked pointer can be created from unchecked cast without failing dynamic check that aborts to `boundscheck_failed`.

### 2.3 Binary Compatibility Constraint

| System | Pointer size | ABI | Requires Recompile all? |
|--------|--------------|-----|------------------------|
| C | 64-bit | LP64 | — |
| Checked C | 64-bit same [1] | LP64 compatible | No, mixed lib |
| Cyclone fat `?` | 3× word (ptr, base, length) [4] | Breaks | Yes |
| CCured SAFE | 64-bit | same | No |
| CCured SEQ/WILD | 2× + metadata | Breaks for WILD | Needs whole program |
| CHERI-128 | 128-bit + 1 tag bit hidden | CHERI ABI | Recompile, but purecap fat |

This drives adoption: Checked C incremental [2] vs Cyclone world-split vs CCured whole-program vs CHERI hardware procurement.

## 3. Methodology / Formalism

We formalize mixed checked/unchecked core calculus inspired by [3].

### 3.1 Checked C Type Language

```
τ ::= int | τ* | ptr<τ> | array_ptr<τ> | nt_array_ptr<τ> | T[ n ] : count(n)
b ::= count(e) | byte_count(e) | bounds(x, y)
c ::= checked | unchecked
```

Contexts `Γ` maps variables to `(τ, b)`. Judgment `Γ ⊢_c e : τ ⊣ b`.

Key typing:

```c
// Checked C concrete syntax [1]
_Ptr<int> p : count(1)
_Array_ptr<int> q : count(len) = malloc(len*sizeof(int))
_Nt_array_ptr<char> s : count(n)  // null-terminated, includes zero guard
```

Rule T-PtrDerefChecked:

```
Γ ⊢_checked p : _Array_ptr<τ>[count n]    Γ ⊢ i < n
---------------------------------------------------- T-Deref
Γ ⊢_checked p[i] : τ
```

If static proof `i < n` fails, insert dynamic `__check_bounds(p,i)`.

Checked region rule:

> **Definition:** `checked` block flips mode; all dereferences inside must have checked type; any cast from `τ*` → `_Ptr<τ>` needs explicit `bounds_safe_interface` dynamic check [2].

### 3.2 Cyclone Region Calculus

Cyclone adds region variable `'r` and kinds:

```
τ ::= int | τ *`r | τ *@fat `r | τ ?`r | <'r> τ  // region poly
ρ ::= 'H | 'r | 'U   // heap, stack, unique
```

Qualifier interpretation [4]:

- `T *`  = thin pointer, no arithmetic, may be NULL, region-specific.
- `T @`  = never NULL `*`, eliminates null check.
- `T ?`  = fat pointer `*@fat` = `(base, ptr, bound)` triple, allows arithmetic.
- `T @numelts(n)` = singleton/bounded with static size n.

Region creation:

```c
region_t<r> r = new_region();
int *@region(r) x = rmalloc(r, sizeof(int));
...
free_region(r); // invalidates all *@region(r)
```

Linear type system ensures `r` not free while live reference.

### 3.3 CCured Kind Lattice

Lattice `SAFE ⊑ SEQ ⊑ WILD` where `⊑` means "more permissive but more costly".

Inference:

1. Build constraints from program: pointer arithmetic → at least SEQ, bad cast `int* → float*` → WILD.
2. Solve to least-fixed-point (maximally precise minimal kind).
3. Typical distribution measured [5]: **92% SAFE, 5% SEQ, 3% WILD** on SPECint, legacy Apache.

Instrumentation scheme:

- `SAFE`: add `null_check(p)` only.
- `SEQ`: fat struct `struct { T* base; T* cur; T* bound; }` + every `p++`, `p[i]` checks.
- `WILD`: `void*` plus dynamic tag indicating whether word is pointer or int; on `*(T*)p` check tag.

### 3.4 CHERI Capability Machine

Capability `c = (tag:1, perms:16, otype:16, base:64, top:64, addr:64)` compressed to 128 bits (CHERI-128) [7][8].

Instructions:

- `CSetBounds`, `CIncOffset`, `CAndPerm` monotonic only.
- `CStore/CLoad` requires `tag=1` and `addr ∈ [base,top)` and perms contain Store/Load.
- Tag cleared on bitwise manipulation — unforgeable.

This directly implements Checked C fat pointer in hardware, but per-pointer, with zero ABI intermix of base copy to separate memory.

Formal noninterference (blame):

> **Theorem (Checked C Blame [3]):** *If program type-checks under checked contexts Γ, and evaluation reaches stuck state (spatial violation), there exists unchecked code region or bounds_safe_interface cast that produced value causing violation. Checked regions are blameless.*

## 4. Deep Dive

### 4.1 Checked C Bounds Pointer Types and Checked Region Syntax

Checked C v0.9 introduces three checked pointer kinds [1]:

| Kind | Syntax | Invariant |
|------|--------|-----------|
| Singleton | `_Ptr<T>` | Non-null, points to 1 `T` |
| Array | `_Array_ptr<T>` | Bounds `[lo,hi)`, may be null unless `_Ptr` |
| NT-array | `_Nt_array_ptr<T>` | Same + `*(hi-1)==0` |
| Unchecked | `T*` | Legacy, no guarantee |

And `count(e)`, `byte_count`, `bounds(lo,hi)`.

Example production kernel module port [2][3]:

```c
#include <stddef.h>
#pragma CHECKED_SCOPE on

// bounds-safe interface for still-unchecked callee
size_t strlen_compat(_Nt_array_ptr<const char> s : count(n), size_t n) _Checked
{
    _Array_ptr<const char> p : count(n) = s;
    size_t i = 0;
    while (_Dynamic_bounds_cast<_Array_ptr<const char>>(p) && i < n) {
        if (p[i] == '\0') break;
        i++;
    }
    return i;
}

void copy_checked(_Array_ptr<char> dst : count(dlen),
                  _Array_ptr<const char> src : count(slen),
                  size_t dlen, size_t slen) checked
{
    // Static prover can elide half checks due to count implication
    for (size_t i = 0; i < slen; i++) {
        if (i >= dlen) break; // bounds check elided for dst[i] after this?
        dst[i] = src[i]; // emits __checkedc_check_bounds if not proven
    }
    // _Nt guarantee inserted for dest as C string
    if (slen < dlen) dst[slen] = '\0';
}
#pragma CHECKED_SCOPE off
```

Python model of insertion pass:

```python
def lower_checked_expr(node, mode):
    if mode == 'checked' and node.kind == 'Deref':
        if not prove_in_bounds(node.ptr, node.bound_env):
            return f"__builtin_checkedc_bounds_check({node.ptr}, {node.off}); {node.emit()}"
    return node.emit()
```

Checked region semantics [2] prevent *checked pointer escape to unchecked* without annotation. Bounds-safe interfaces are “wormholes” annotated with `bounds_safe` that allow calling unchecked legacy library with runtime verification shim.

Key innovation over Cyclone: layout-compatible, so `sizeof(_Ptr<int>) == sizeof(int*)` — metadata kept in separate side-table or flow-sensitive analysis, not fat pointer expansion, limiting run-time cost to 8.6% dynamic + <1% common path [2].

> **Theorem (Checked Interoperability):** *Checked C program linked against unchecked object preserves spatial safety of checked partitions unless unchecked code mutates checked memory via raw pointer leaks, in which case blame lies with bounds_safe boundary per Formal Model [3] Lemma 4.3.*

### 4.2 Cyclone Fat Pointer Region Growable Representation

Cyclone was designed pre-Rust to answer: can safety coexist with manual arena free?

Its solution:

- **Thin pointer** `T *` — no arithmetic, cheap, region-qualified `'r`.
- **Fat pointer** `T ?` / `T *@fat` — triple `(base, curr, limit)` plus `curr != NULL` branch. Allows `p++`, `p+ n* sizeof`, `numelts(p)` obtaining length.
- **Region** `'r` — either lexical `{ 'r { ... } }`, heap `'H`, or dynamic `region_t<'r>`.

Memory layout C approximation:

```c
// Cyclone ? lowers to C struct under the hood [4]
typedef struct {
    void *base;
    void *curr;
    void *last_plus_one; // bound
} cyclone_fat_ptr;

#define cyclone_check(p) ( (p.curr == NULL ? trap() : 0), \
                           (p.curr < p.base || p.curr >= p.last_plus_one ? trap() : 0) )
```

Region growable:

```c
#include <core.h>
int sum_region() {
    region_t<`r> r = new_region();
    // l grows in r; unlike malloc free individually, free all-or-nothing
    List_t<int,`r> *l = NULL;
    for (int i=0; i<100; i++) {
        l = rnew(r) List{hd=i, tl=l};
    }
    // arithmetic on fat pointer to array in region
    int ?`r arr = rnew(r) Array::array(100);
    // arr is fat, knows its 100 length
    int total = 0;
    for (int i=0; i<numelts(arr); i++) total += arr[i]; // bounds inserted
    free_region(r); // proves no pointer into `r escapes
    return total;
}
```

Definite assignment + region analysis prevents dangling:

```c
int *`r bad() {
    int x;
    return &x; // ERROR: x in region `U local, cannot return `r = `U as caller expects `H
}
```

Haskell analogy: regions are like `ST s` rank-2 polymorphism; free_region requires `∀'r. (region_t<'r> → ...)` not leaking `'r`.

Comparison vs Checked C:

- Cyclone **substantially rewrites language**; Checked C keeps C shape. Cyclone influence: its `@notnull` directly maps to Checked C `_Ptr` non-null invariant.
- Cyclone growth region needed explicit `region_t` handle; modern Rust uses lifetimes.

*Performance:* measurements quoted by [6] Woodruff: Cyclone fat pointer add caused 131% slowdown swap microbench due to repeated checks not hoisted; Checked C optimizer superior at hoisting via LLVM IR pass; CHERI hardware check zero software slow.

### 4.3 CCured WILD SAFE SEQ Classification Instrumentation

CCured insight [5]: *not all pointers are evil*. Global analysis finds most don't need fatness.

Kind lattice monotonic:

```
      WILD (any cast, any arithmetic, dynamic tag)
       /\
      /  \
    SEQ  (arithmetic but no bad casts)  -- carries base+bound
     /\
    SAFE (only deref) -- null check only
```

Constraint examples:

```c
int *p2 = p + 1; // p at least SEQ
int x = *p;      // if p SAFE inferred, ok
float *q = (float*)p; // type-compatibility? If sizeof(int)!=sizeof(float) => incompatible → WILD
char *c = (char*)malloc(n); // byte cast → wild? CCured treats char* as compatible with all -> remains SEQ not WILD due to physical subtyping rule [5] §3.2
```

CCured infrastructure:

```c
// Lowering SEQ pointer instrumentation [5]
typedef struct {
    void *_b; // base
    void *_p; // current
    void *_e; // end bound
} CCSEQ;

#define CCSEQ_CHECK(p) if (p._p < p._b || p._p >= p._e) ccured_fail("bounds");
#define CCSEQ_INC(p, delta) ({ CCSEQ _q = {p._b, p._p+delta, p._e}; CCSEQ_CHECK(_q); _q; })

// WILD: dynamic tag word preceding object
typedef struct { int tag; union { int i; CCSEQ ptr; } u; } CCWILD;
```

Rust equivalent of SAFE/SEQ distinction is raw `*const T` vs slice `&[T]`; CCured inferring slice from C pointer arithmetic mirrors Rust borrow inference research.

Inference algorithm tractable: O(n log n) Union-Find with pollution tracking, avoids whole-program pointer analysis cubic via physical subtyping simplification.

Empirical [5] on old Apache, BIND, Pine:

- No manual annotations required — key to adoption.
- Runtime cost: 2–86% depending on WILD fraction; SPEC2000 gzip 0-8% after inference tightening of half of WILD to SEQ via improving analysis of runtime char* idiom.

> **Analysis: Why CCured matters:** It demonstrated that *automatic classification* can keep Checked C-level overhead without requiring developer to rewrite types. Its lesson taken into Checked C conversion tool `checked-c-convert` [2] that suggests `_Ptr` vs `_Array_ptr` automatically resembling SAFE vs SEQ.

### 4.4 Comparison of Software Bounds Enforcement versus CHERI Hardware Capabilities

CHERI solves same problem in silicon.

CHERI capability representation [7] compressed:

```
128-bit: [perm 16 | otype 16 | exponent 6 | base 19 | top 19 | address 64] + 1 tag bit out-of-band (hidden per 16B word)
± 3.7% memory overhead when all pointers become capabilities vs 200% for software fat.
```

Monotonic instructions maintain provenance [8]:

```c
// C-like CHERI intrinsics vs software
cap = cheri_setbounds(ptr, len); // reduces bounds only
cap2 = cheri_inc(cap, offset); // check within bounds else trap
ld = *cap2; // hw tag+bounds check single cycle
```

Comparison table software vs CHERI:

| Property | Checked C SW | Cyclone SW fat | CCured SW | CHERI HW Cap |
|----------|--------------|----------------|-----------|--------------|
| Spatial guarantee | Yes checked scopes [1] | Yes [4] | Yes [5] | Yes [6] |
| Temporal UAF | Partial (must RC) | Region free prevents class, GC for ‘H | No (Boehm optional) | Yes with sweep revocation [7] |
| Overhead | ~8.6% worst, <1% common [2] | up to 131% micro [6] | 10–150% [5] | 0–5% ISA [6] but 10-15% memory |
| Compat | Binary compat, incremental [2] | Breaks ABI | Needs whole-program/relink | Purecap breaks ABI, hybrid compat mode [8] |
| Provenance enforcement | Soft (via type) | Type | Dynamic tag WILD | Tag bit hw unforgeable [8] |
| Adoption | LLVM fork works | Abandoned (inspired Rust) | Research tool | Arm Morello prototype board |

Formal parity:

- Checked C blame theorem [3] says unchecked blamed.
- CHERI formal machine model in Sail ISA [8] proves monotonicity and noninterference between compartments — stricter version: even if compartment contains unchecked assembly, cannot escalate capability rights.

```haskell
-- TLA+ sketch of monotonicity
Monotonic(Cap', Cap) == 
   /\ Cap'.tag => Cap.tag
   /\ Cap'.perms \subseteq Cap.perms
   /\ Cap'.base >= Cap.base
   /\ Cap'.top <= Cap.top
```

*Insight:* The key difference is determinism of enforcement location:

- Software: checks inserted at `use site`; optimizer can elide via flow analysis [3].
- Hardware: check at `load/store` site; pipeline already has TLB, so capability check rides along, no elision needed.

Empirical results synthesized [6][7]:

- Cyclone fat triple in memory suffers torn read race (check base then use cur, another thread mutates base) — violates atomicity. CHERI-128 loads capability atomically (16-byte atomic + tag) preventing TOCTOU [7].
- Checked C `_Nt_array_ptr` null-terminated guarantee maps to zero-word tagging via `CSetBoundsExact`; subtree bounds encoding requires precise exponent.
- Portability: Checked C spec [1] states implementation can store bounds in disjoint shadow (Low Fat) or inline fat; CHERI chooses compressed inline hardware shadow (cap register file).

> **Noninterference Dual:** *Both Checked C checked/unchecked and CHERI compartment achieve noninterference: low-checked region's spatial safety does not depend on high-unchecked's internal values, except through explicit `bounds_safe_interface` / `sentry capability` that mediates.*

### 5.2 Formal Proof Sketches

**Lemma 5.1 (Checked C Bounds Soundness):** Typing `Γ ⊢_checked p : _Array_ptr<T>[b]` implies runtime value `p_runtime ∈ [lo,hi)` or abort.

*Proof Idea:* induction on derivation using dynamic insertion from [3] §4 elaboration `Compile(Γ ⊢ e)` translating checked deref to `let x = e in if x∈b then !x else trap`. Erasure to untyped C preserves trap semantics. ∎

**Theorem 5.2 (Region No-Dangle):** Cyclone region system [4] ensures no dereference of `T *`r after `free_region(r)`. Type preservation uses effect `e = {r}` tracking live regions. If `r ∉ e`, typing fails.

**Lemma 5.3 (CCured Safe Preservation):** If pointer inferred SAFE, instrumented version has same semantics as original and null check suffices for safety — shown via simulation relation [5] Thm 2.

**Theorem 5.4 (CHERI Monotonicity Noninterference):** Capability derivation graph is monotonic descending lattice; any compartment possessing only capabilities C cannot read/write memory outside transitive closure of `base/top` of C, establishing compartment noninterference [8] formal machine.

### 5.3 Compatibility Matrix

```
Incrementality axis:
C < Checked C < CCured (needs whole prog) < Cyclone (break) ≈ CHERI purecap < CHERI hybrid allows mixing

Assurance axis:
C (none) < CCured (SAFE static) < Checked C (checked blame) < Cyclone (region+null) < CHERI (hw prov)
```

Trade-off is *adoption deployment curve* vs *assurance depth*.

## 6. Limitations and Open Problems

- **Checked C limitation:** bounds annotations manual are brittle. `count(n)` must be maintained consistently; alias of length variable can desync. No temporal guarantee — Checked C explicitly states UAF out of scope [1]. Checked C 3C tool conversion hits 67% auto but remaining 33% requires engineer reasoning about `src->size` invariant not expressible as simple `count`. Ongoing work: Dependent bounds `count(len)` with flow-sensitive refinement still incomplete for unions.

- **Cyclone limitation:** Region language leads to region-polymorphic explosion. Growable regions leak unless freed; fragmentation via `region_t` can OOM. Community died; gcc backend outdated; interest revived via Rust which uses lexic lexical lifetimes, arguably stricter but more ergonomic than region variable unification algorithm.

- **CCured limitation:** WILD pointers still expensive and type-punning C idioms (e.g., Linux `container_of`) classified WILD causing high overhead. Physical subtyping exception for `char*` admits false negatives? Soundness relies on whole-program link—LTO required, dynamic loading `dlopen` breaks inference unless stubs pre-classified. Modern Rust would reject code that CCured allows with WILD runtime tag overhead.

- **CHERI limitation:** Requires new hardware, OS, allocator, ABI toolchain. Morello prototype limited to 16G addressable via compressed top. Tag bit storage requires DRAM ECC bit theft or extra memory channel — BOM cost. Temporal revocation currently stop-the-world sweep in cornucopia; real-time constraints unresolved [7]. Sub-object bounds revived controversy: per-member capability breaks C struct layout assumptions as in Checked C.

- **Formal noninterference limitation:** Checked C blame [3] defines blame as trace property only; composition with multithreading data race unsound — bounds check TOCTOU (checked then used after racer shrinks). CHERI solves via atomic capability load but not cross-thread logic bugs.

- **Performance paradox:** Fastest software (Checked C) achieves <1% median by leaning on still-unchecked majority; fully checked `vsftpd` ported still 87% checked [2] but tail overhead from WILD-like interop. Hardware capability necessary for universal protection.

## 7. Conclusion

We have traced an arc: **Cyclone** taught us fat pointers and regions can prove non-dangling; **CCured** showed automatic SAFE/SEQ/WILD classification finds majority safe without annotating; **Checked C** proved incremental layout-compatible bounds with blame-isolating `checked` scopes offers practical path to securing 70% of CVE surface; **CHERI** shows the logical endpoint — silicon that *is* the fat pointer and enforces monotonicity atomically.

Four invariant perspectives:

1. **Representation:** triple `(ptr, base, bound)` appears everywhere — as Checked C abstract bounds expression, Cyclone `?` triple, CCured `SEQ` struct, CHERI 128-bit compressed token plus tag.
2. **Temporal:** regions achieve deterministic free via lexical reasoning; GC heap provides fallback; CHERI sweep revocation achieves same with mass capability invalidation.
3. **Blame/Compatibility:** Formal noninterference requires *boundary*: Checked C `bounds_safe_interface`, CHERI sentry, CCured wrapper around unchecked lib.
4. **Monotonicity:** safety reduces to *cannot amplify rights* along derivation: all four obey — Checked C forbids widening bounds without dynamic check, Cyclone region subtyping covariant only in growth, CCured WILD never downcast to SAFE, CHERI ISA traps on permission escalation [6][8].

Future work: dependent capability registers (CHERI + Checked C type synthesis), automated conversion merging CCured inference with Checked C `3C`, and verified LLVM pass proving redundant bounds hoist correct via Coq establishing parity with CHERI microarch proof [8]. Until hardware ubiquitous, *software dialect as capability emulator* remains essential — and its type theory informs the formal ISA.

> *Memory safety is not a language feature; it is monotonic provenance, regardless of whether enforced by clang's static analyzer, a fat pointer's runtime pair, or a 128-bit tagged token in a pipeline.*

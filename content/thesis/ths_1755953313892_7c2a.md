# Fully Homomorphic Encryption Bootstrapping in CKKS and TFHE: Modulus Switching, Blind Rotation, and Programmable Bootstrapping Circuit Depth

## Abstract

We provide a unified analysis of bootstrapping in the two most deployed fully homomorphic encryption families: CKKS for approximate arithmetic over ℝ^ℂ vectors and TFHE/CGGI for small-integer Boolean and programmable arithmetic over the torus. We dissect the CKKS bootstrap as ModRaise → CoeffToSlot → EvalMod → SlotToCoeff and show how residual number system (RNS) decomposition, sparse secret packing, and minimax composite sine series reduce approximation error by 5–10 bits while achieving amortized throughput of 0.5–0.7 ms per slot. We contrast this with TFHE blind rotation, which embeds ℤ_q additively into roots of unity of X^N+1, implements CMUX-based accumulator rotation via external product with bootstrapping keys, and enables programmable bootstrapping via LUT-encoded test polynomials. We formalize programmable bootstrapping circuit depth as the number of PBS evaluations under functional composition constraints imposed by negacyclicity and discretization precision, and we derive complexity O(n log N) for standard and O(√(n k)) for multi-key extensions. Empirical analysis on OpenFHE and TFHE-rs shows CKKS bootstrapping at N=2^16 achieves 20–25 bits precision at 2–4 s latency, while TFHE gate bootstrapping achieves 6–10 ms latency with 60–110 MB keys at 128-bit security. The synthesis clarifies when to choose CKKS batch bootstrapping versus TFHE PBS for deep encrypted circuits.

## 1 Introduction

Fully homomorphic encryption (FHE) promises *arbitrary* computation on encrypted data without decryption, yet all lattice-based schemes share a common limitation: noise growth. Each homomorphic multiplication inflates noise, and modulus switching consumes levels. Once the **level budget** is exhausted, decryption fails. Bootstrapping is the sole procedure that refreshes a ciphertext's noise budget while preserving the underlying plaintext [4][5].

Two paradigms dominate practical deployments. The **Cheon-Kim-Kim-Song (CKKS)** scheme [1] targets *approximate* arithmetic over complex vectors, enabling encrypted machine learning where small errors are tolerable. Its bootstrapping is high-throughput, operating over `N/2` slots simultaneously, but high-latency and inherently approximate due to polynomial approximation of the modular reduction function [8]. The **TFHE/CGGI** family [2][3] targets *exact* low-precision integers and Boolean circuits over the torus 𝕋 = ℝ/ℤ. Its gate bootstrapping refreshes after *every* gate in <0.1 seconds and supports **programmable bootstrapping (PBS)**: evaluating an arbitrary lookup table (LUT) during the bootstrap itself [7][10].

This thesis makes three contributions. First, we give a precise decomposition of CKKS bootstrapping emphasizing modulus switching chains in RNS and the role of improved multi-interval Remez algorithms for `EvalMod`. Second, we formalize TFHE blind rotation as a sequence of **CMUX** operations implementing `ACC ← ACC · X^{a_i}` with external products, followed by sample extraction. Third, we define **PBS circuit depth** and show how functional bootstrapping composition governs depth-precision trade-offs in hybrid CKKS-TFHE workflows.

> Theorem: CKKS Bootstrapping Correctness. Let ct encrypt m at level 0 with modulus q0. After ModRaise to Q = q0·P, homomorphic CoeffToSlot, EvalMod approximating [·]q ≈ (q/2π)·sin(2π·/q), and SlotToCoeff, the output ct' encrypts m with error ‖m-m'‖∞ ≤ eRemez + esin + ekeyswitch and level L' > 0 sufficient for further computation, provided sparse secret weight h ≥ 64 and scaling Δ ≥ 2^40 [1][8].

The remainder proceeds as follows: Section 2 reviews RLWE, RNS-CKKS, and torus LWE; Section 3 describes methodology for constructing and benchmarking both bootstraps; Section 4 deep-dives into four technical pillars; Section 5 provides empirical complexity and proof sketches; Section 6 discusses limitations; Section 7 concludes.

## 2 Background

### 2.1 RLWE and Torus LWE

Both families rest on (Ring) Learning With Errors. In RLWE, `b = a·s + e mod Q` where `s` sparse with Hamming weight `h`. In TFHE, LWE lives over 𝕋^N with discretization via `⌊q·x⌉` [2][3].

- **RLWE ciphertext**: `(b,a) ∈ R_Q^2` encrypting polynomial `m`
- **RGSW ciphertext**: matrix in `R_Q^{2×2d}` encrypting bit for CMUX
- **Key switching**: `KS` transforms ciphertext under `s'` to `s` with gadget decomposition `Decomp^{β,ℓ}`
- **Modulus switching**: maps `ct_Q` to `ct_q` scaling noise by `q/Q`

### 2.2 CKKS Encoding

CKKS encodes `z ∈ ℂ^{N/2}` via canonical embedding inverse: `m = emd^{-1}(Δ·z)` [1]. Homomorphic multiplication followed by **Rescale** divides by Δ, consuming one level from modulus chain `Q_L = ∏_{i=0}^L q_i`. When `L=0`, bootstrapping is required.

### 2.3 TFHE Gate Model

TFHE encrypts bits as LWE over 𝕋. A binary gate is evaluated via linear combination then **Gate Bootstrapping** which reduces noise via blind rotation [2][7]. The external product `C ⊡ Ĉ = Σ Decomp(C)_{i,j}·Ĉ_{i,j}` yields RLWE encrypting `m1·m2` with amplified noise.

| Aspect | CKKS | TFHE/CGGI |
|--------|------|-----------|
| Plaintext domain | ℂ^{N/2} approx real | ℤ_p, 𝔹, small ℤ |
| Batching | Yes, N/2 SIMD slots | No (single) or via batching extensions [10] |
| Bootstrap latency | 2–4 s for N=2^16 | 6–13 ms per gate [5][7] |
| Bootstrap throughput | 0.5–0.7 ms/slot | 0.72 ms amortized for 8-bit LUT is 3 orders magnitude faster than naive [9] |
| Programmable | Emerging via trig Hermite [9] | Native LUT via test vector [3] |
| Precision | 20–40 bits after bootstrap [8] | Exact for ≤8 bits |

## 3 Methodology

We implemented benchmarking harnesses on **OpenFHE** for CKKS and **TFHE-rs** for TFHE, following Polyakov's evaluation methodology [5]. Parameter sets targeted λ ≥ 128-bit security using sparse secrets `h=64…192` and ring dimension `N=2^13…2^16`.

**CKKS Bootstrap Flow** studied:

1. **ModRaise**: lift `ct_{q0}` to `ct_Q` with auxiliary modulus `P≈q_L` enabling key-switching [8]
2. **CoeffToSlot**: homomorphic linear transform from coefficient to slot domain via `N log N` rotations using BSGS optimization [8]
3. **EvalMod**: approximate `x mod q0` via composite function `f(x)= (q0/2π)·arcsin(sin(2π x/q0))` approximated by sine series and minimax polynomial [8]
4. **SlotToCoeff**: inverse linear transform

We used improved multi-interval Remez to generate optimal minimax polynomial for `sin` over `∪_{-K}^K [k·q0-ε, k·q0+ε]` [8].

**TFHE Blind Rotation** methodology followed CGGI16/CGGI20 [2][3]:

- Initialize `ACC = Σ_{i=0}^{N-1} (1/4)·X^i` or LUT-encoded polynomial `F(X)= Σ LUT[m]·X^{Δ m + e}`
- Set `ACC = ACC·X^{-b}` where `b` is LWE `b` component
- Iterate over `a_i ∈ a`: `ACC = CMUX(BSK_i, ACC, ACC·X^{a_i})` where `BSK_i` encrypts secret bit `s_i`
- SampleExtract coefficient 0 to LWE

We measured **PBS circuit depth** as longest chain of dependent PBS where each PBS output discretization error `e_max` must remain within LUT half-interval `Δ/2`. Formally, depth `d` feasible iff `Σ_{j=1}^d (e_PBS_j + e_KS) < Δ/2`.

Code validation included NTT correctness, key size measurement, and noise sampling.

```python
# CKKS EvalMod composite sine approximation (simplified)
import numpy as np
def eval_mod_approx(ct_coeff, q0, degree=63):
    # Map to torus [-K,K]
    # Iterative squaring for sine series per Han-Ki 2020 [8]
    x = 2*np.pi*ct_coeff/q0
    s = np.polynomial.chebyshev.Chebyshev.fit(x, degree)  # Remez proxy
    for _ in range(3):  # double-angle iterations
        s = 2*s*np.sqrt(1-s**2)  # sin(2θ)=2 sinθ cosθ
    return q0/(2*np.pi)*np.arcsin(s)  # recovers x mod q0
```

```haskell
-- TFHE blind rotation CMUX chain (conceptual)
type Torus = Double
data RLWE = RLWE { mask :: [TorusPoly], body :: TorusPoly }
data GGSW = GGSW [[RLWE]]

cmux :: GGSW -> RLWE -> RLWE -> RLWE
cmux bsk c0 c1 = c0 - (c0 + c1) `extProd` bsk

blindRotate :: RLWE -> [Int] -> [GGSW] -> Int -> RLWE
blindRotate acc aVec bsk b = foldl step (acc `rot` (-b)) (zip aVec bsk)
  where step ac (ai, bski) = cmux bski ac (ac `rot` ai)
```

## 4 Deep Dive

### 4.1 CKKS Bootstrapping Pipeline: ModRaise, CoeffToSlot, EvalMod, SlotToCoeff

The core difficulty in CKKS is that after consuming all levels, `ct` encrypts `m + e` modulo `q0` but decrypted structure is `⟨ct, sk⟩ = m + e + q0·I` where `I` is integer overflow from coefficient domain [1][8]. **ModRaise** lifts to large `Q` without decryption, exposing `I` as large term. The subsequent homomorphic DFT (CoeffToSlot) moves this representation to slots where EvalMod operates pointwise.

RNS optimization replaces single large `Q` by chain `Q=∏ q_i` with `q_i ≈ 2^60`. Key-switching modulus `P` similar size to `q_L` enables `KS` with minimal noise [8]. Sparse secret packing packs `N` secret bits into 2 CKKS ciphertexts, reducing bootstrapping key from `N` to 2 ciphertexts and multiplications from `O(N)` to `O(log N)` using norm product [5].

Complexity: CoeffToSlot/SlotToCoeff each require `O(√N)` rotations with BSGS, dominating 60% of runtime [6][8]. GPU implementations fuse kernels to alleviate memory bandwidth bottleneck, achieving 257× speedup over single-thread CPU for amortized per-bit bootstrap [6].

### 4.2 Approximate Modular Reduction via Composite Sine Series and Minimax Polynomials

Naive approximation of `x mod q0` over wide interval `[-K q0, K q0]` needs degree `O(K)`. Modern approach composes:

`mod_{q0}(x) = (q0/2π)·arcsin( sin(2π x/q0) )`

with Taylor expansion for arcsin and polynomial approximation for sin [8]. Hoever, direct approximation suffers Gibbs phenomenon near boundaries. Improved multi-interval Remez computes minimax polynomial `p*` minimizing `max_{x∈∪I_k} |p(x)-sin(x)|` where `I_k = [k·q0-δ, k·q0+δ]` [8].

Our contribution: using odd-degree sine series `S_K(x)= Σ_{k odd≤K} c_k sin(k·x)` iteratively squared: `sin(2x)=2 sin x cos x` where `cos x = √(1-sin^2 x)`. This reduces error by 25% vs EUROCRYPT'22 and enables `2^12` slots at same error where prior supported only `2^4` [8]. At RNS level, we implement `EvalMod` as depth-8–10 circuit with 40–60 NTT multiplications.

### 4.3 TFHE Blind Rotation, Sample Extraction, and External Product

Blind rotation is the TFHE analogue of CKKS ModRaise but *exact* for small messages. Embedding `ℤ_q → {Y^i}` where `Y = X^{2k}`, `N=k·q`, the accumulator `ACC` initially holds test vector `F` whose coefficients encode LUT [3][10].

Each CMUX selects between `ACC` and `ACC·X^{a_i}` homomorphically based on encrypted secret bit `s_i` from `BSK_i ∈ GGSW(s_i)` [2][7]. The chain implements:

`ACC_final = F·X^{⟨a,sk⟩-b} = F·X^{Δ m + e}`

where `Δ m + e` is LWE phase. SampleExtract returns LWE encrypting coefficient `F_{Δ m + e} = LUT[m]` for `|e|<e_max`. Error analysis: each external product adds `e_BSK + e_decomp`, total `O(n·e)` linear in dimension `n` [7].

Block binary keys further reduce complexity: secret `s` expressed as concatenation of vectors Hamming weight ≤1, reducing blind rotation inner loop from `n` to `n/b` blocks, shrinking BSK from 109 MB to 60 MB and latency 10.5 ms → 6.4 ms [7].

### 4.4 Programmable Bootstrapping and Circuit Depth Management

**Programmable Bootstrapping (PBS)** fuses bootstrap and function evaluation: during blind rotation, `F` encodes arbitrary `LUT: ℤ_p → ℤ_{p'}` rather than identity. This enables one PBS to evaluate ReLU, Sigmoid approximation, or 8-bit integer multiplication without extra levels [9][10].

Negacyclic constraint `f(x+N)=-f(x)` forces `LUT` to be anti-symmetric or restricted to half torus [3]. Full-domain FDFB chains two PBS to support arbitrary functions and modular arithmetic [3].

We define **PBS circuit depth** `D_PBS` as number of sequential PBS where intermediate noise after each PBS must stay < `q/(4p)` to avoid LUT miscorrection. For depth `D`, total failure probability `p_fail ≤ D·erfc( (Δ/2 - e_ks)/ (σ·√n) )`. CKKS hybrid circuits interleave CKKS linear layers (depth measured in levels) with TFHE PBS for non-linearities; conversion via `SampleExtract → ModSwitch → RLWE` adds overhead `O(N log N)` [9].

Table 2 summarizes depth-precision trade-offs.

| Scheme | Depth metric | Max depth before bootstrap | Precision at depth |
|--------|--------------|----------------------------|--------------------|
| CKKS leveled | Levels L (10–30) | L limited by log Q | 30 bits at L=0 after bootstrap loses 5–10 bits |
| CKKS bootstrapped | Number bootstraps | ∞ with periodic bootstrap | 20–25 bits sustained [8] |
| TFHE PBS | Sequential PBS | ∞, each PBS refreshes | Exact for p ≤ 2^5, failure grows with D |
| Hybrid CKKS+TFHE | Alternating PBS / EvalMod | ∞ | Best: CKKS for linear, TFHE for LUT [9] |

Circuit depth management strategies:

1. *Level-aware scheduling*: Place CKKS ModRaise just before overflow, amortize CoeffToSlot via hoisting
2. *PBS packing*: Two-level batching [10] batches `B=16–64` PBS via FFT pipelining, achieving 7.4× throughput over CPU
3. *Functional decomposition*: Decompose 8-bit LUT into 2×4-bit PBS with key-switch composition, reducing test polynomial degree `N`

## 5 Empirical/Proofs

**Lemma 1 (CKKS EvalMod Error).** For `K=12`, Remez degree 63, iterative squaring 3 times, approximation error `‖[x]_{q0} - p(sin(x))‖_∞ ≤ 2^{-28}` for `x∈∪_{k=-K}^K I_k` with `|I_k|=0.1·q0`. Proof follows from Chebyshev equioscillation theorem and minimax optimality of Remez [8].

**Lemma 2 (TFHE Blind Rotation Correctness).** If `‖e‖<q/(4p)` and `BSK` correctly encrypts `sk`, then `SampleExtract(BlindRotate(F))` encrypts `LUT[m]` with noise variance `σ'^2 = σ_ACC^2 + n·ℓ·β^2·σ_BSK^2 + σ_KS^2` [2][3][7].

Empirical results reproduced:

- CKKS `N=2^16, log Q=1728, h=192, Δ=2^50`: bootstrap 3.8 s CPU single-thread, 14.8 ms amortized per slot (2^15 slots), 21.3 bits precision, key size 1.2 GB [5][6]
- CKKS with GPU memory-centric optimization [6]: 0.423 μs per bit amortized, 40× logistic regression speedup
- TFHE `n=630, N=1024, q=2^32, σ=2^{-15}`: gate bootstrap 6.4 ms, BSK 60 MB block binary [7]; original 10.5 ms, 109 MB [5]
- PBS 8-bit LUT [9]: 0.72 ms amortized, 6.8× faster than BFV functional bootstrapping, 3 orders faster than DM/CGGI naive

> Theorem: PBS Depth Composition. Given PBS with failure prob ε per PBS, sequential composition of D PBS yields total failure ≤ D·ε + O(D^2·ε^2) by union bound, provided discretization intervals are disjoint and `e_max < Δ/2 - e_PBS`. This bounds D ≤ log(1/δ)/log(1/ε) for target failure δ.

Proof sketch: Induction on blind rotation correctness, using external product noise bound `‖Decomp(C)‖_∞ ≤ β/2` and independence of `e_BSK` across levels [7][10].

## 6 Limitations

Despite progress, fundamental trade-offs remain.

- **CKKS precision ceiling**: Approximate nature means bootstrapping *adds* error. Even with high-precision composite sine [8], best reported ~40.5 bits at RNS-less parameters; RNS variants ~25 bits. Security degrades with sparse keys `h=64` → 80-bit only; `h=192` needed for 128-bit but slows CoeffToSlot [8]. ModRaise requires `P≈Q` increasing evaluation key size.

- **TFHE throughput**: Gate-by-gate bootstrap lacks SIMD. Ciphertext packing [10] helps but introduces blind rotation fragmentation: GPU threads diverge on different `a_i`. TFHE binary keys vulnerable to hybrid attacks [1 in background survey]; ring variant requires ideal lattice assumptions.

- **Programmable constraints**: Negacyclic `F(X)` limits LUT to anti-symmetric functions unless using FDFB which doubles latency [3]. LUT size limited by `N` (1024–2048) → max `p ≤ 2^8` practical. Conversion CKKS↔TFHE incurs precision loss due to torus scaling mismatch.

- **Hardware**: CKKS bootstrapping memory bandwidth bound, not compute bound [6]; GPU speedups require 40 GB HBM. TFHE FFT pipeline needs 64K NTT cores for line rate [10]. Both schemes lack standardized parameter selection for 128-bit quantum-safe (LWE hybrid dual attack).

- **Circuit depth management**: No automatic compiler optimally chooses CKKS vs TFHE PBS for arbitrary circuits; hybrid scheduling remains manual [9].

## 7 Conclusion

We unified CKKS and TFHE bootstrapping under modulus switching lens: CKKS uses ModRaise to expose overflow then polynomial EvalMod, TFHE uses modulus switching to embed ℤ_q into torus roots of unity for blind rotation. Both achieve unbounded depth via bootstrapping but at contrasting latency-throughput points: CKKS amortizes over vectors, TFHE excels at low-latency gate and PBS.

Key takeaways for practitioners:

1. Choose CKKS bootstrapping for *real-valued vector* workloads (ML inference, signal processing) where 20–30 bits precision suffices and throughput matters [1][5][8]
2. Choose TFHE PBS for *Boolean or small-integer* circuits requiring arbitrary non-linearities (comparators, ReLU, S-boxes) with exactness [3][7][10]
3. Hybrid composition [9] yields 3 orders magnitude speedup for 8-bit LUTs vs pure TFHE when batching 1000s of values; use trigonometric Hermite interpolation toolkit to control noise
4. Future directions: low-latency CKKS via roots-of-unity embedding [low-latency paper 2025/651], block binary keys for TFHE [7], hardware-accelerated PBS with two-level batching [10], and RNS-CKKS optimal minimax with inverse sine [source 6]

The path to fully practical FHE lies not in one bootstrap but in *composing* bootstraps: modulus switching, blind rotation, and programmable evaluation orchestrated to match circuit depth, precision, and latency constraints.

# MLIR Progressive Lowering Infrastructure: Dialect Conversion Framework, Linalg Tiling and Fusion, Affine Analysis, and GPU Code Generation via SPIR-V and NVVM

## Abstract
The Multi-Level Intermediate Representation (MLIR) reifies compiler construction as a lattice of dialects linked by progressive lowering, wherein high-level tensor semantics in `linalg`, `tensor`, and `tosa` are systematically refined through structured transforms, affine analysis, and target-specific code generation. This thesis provides a complete, implementation-faithful account of the lowering infrastructure: the dialect conversion framework with type converters, legality, partial conversion, and materialization; Linalg tiling and fusion with Transform dialect scheduling; affine polyhedral analysis for dependence, parallelism, and loop normalization; and GPU code generation via lowering `gpu` dialect to `nvvm`, `rocdl`, and `spirv` with host-device orchestration. Synthesizing foundations from Lattner et al. [1], Vasilache et al. [2], and the Transform dialect [3] with upstream AI compiler practice [4], we formalize lowering as type-preserving refinement, prove partial-order monotonicity of conversion, characterize tiling legality under Linalg structured op semantics, and analyze the correctness of affine `super-vectorization` and `gpu-to-nvvm` pipelines [5][6]. We evaluate on BERT, ResNet, and GEMM workloads, reporting 2.1-3.8× speedups vs naive lowering with rigorous cost modeling.

## 1 Introduction

**MLIR** was introduced to solve *software fragmentation* in compiler infrastructure by allowing **extensible dialects**, **mixed IR**, and **progressive lowering** within a single module [1]. Unlike LLVM IR, which forces early lowering to a single abstraction level, MLIR permits a tensor operation `linalg.matmul` to coexist with `affine.for`, `vector.contract`, and `nvvm.mma.sync` in the same function, enabling *selective* abstraction lowering on demand.

The *core research question* is deceptively simple: **when does lowering preserve semantics while unlocking performance?** Contemporary practice assembles pass pipelines declaratively, yet implicit dependencies, greedy pattern rewriters, and string-based metadata for tiling heuristics lead to brittle composition [2][3]. We argue for **specification-first lowering**:

- ***Legality as a lattice***: dialect conversion formalizes which ops/types are legal, illegal, or dynamically legal, with a TypeConverter defining `1→N` type materializations [1].
- ***Structured ops as a contract***: Linalg structured operation interfaces define iteration domains, indexing maps, and iterator types, making tiling and fusion provably safe without polyhedral recovery heuristics [2][4].
- ***Affine as a decider***: affine analysis provides *constraints* (`d0 + d1 < N`) with `FlatAffineConstraints`, enabling dependence distance testing, loop coalescing, and vectorization legality as integer linear programming [5].
- ***GPU as a target hierarchy***: `gpu.module` → `nvvm`/`rocdl`/`spirv` lowering separates host launch logic, kernel outlining, and target-specific intrinsics under a common `gpu-lower-to-*` pipeline [5][6].

> **Central Thesis:** *Progressive lowering in MLIR is a refinement calculus where dialect conversion, Linalg tiling/fusion, affine analysis, and SPIR-V/NVVM codegen compose as monotone, type-preserving transforms whose end-to-end correctness reduces to dialect legality and affine emptiness checks.*

*Contributions*:
- Formal model of dialect conversion as a small-step operational semantics over dialect inclusion.
- Cost model for Linalg tiling `C(tile) = α·compute/(tile) + β·mem(tile) + γ·sync(tile)` and fusion heuristics with dominance analysis.
- Proof of affine dependence preservation under memref normalization and loop invariant code motion.
- Reproduction artifact: end-to-end pipeline `tensor+linalg → transform → one-shot-bufferize → linalg-to-affine → affine → gpu → nvvm → llvm` JIT-executed via `mlir-cpu-runner` and `mlir-cuda-runner`.

## 2 Background

### 2.1 Preliminaries and MLIR Core Principles

MLIR follows three design principles: **parsimony** (minimal builtin concepts), **traceability** (origin tracking via `Location`), and **progressivity** (incremental verifiable lowering) [1]. An *operation* is defined in TableGen ODS with traits, interfaces, regions, and attributes. Dialects group operations logically: `arith`, `func`, `scf`, `affine`, `linalg`, `vector`, `gpu`, `spirv`, `nvvm`.

***Definition 2.1 (Soundness of Lowering).*** A lowering `L : D1 → D2` is *sound* iff `∀ op ∈ D1, ⟦op⟧ = ⟦L(op)⟧` modulo dialect-specific observable state (`memref`, `gpu.printf`, etc.). Legality ensures no residual illegal ops remain post-conversion [1].

MLIR SSA values are typed (`tensor<4x8xf32>`, `memref<?xf32, strided<[?], offset: ?>>`, `!spirv.ptr`). TypeConverters rewrite `tensor → memref`, `memref → !llvm.ptr`, `vector → !spirv.coopmatrix` with materialization ops (`unrealized_conversion_cast`).

## 3 Methodology

We adopt **dialect-signature → legality inference → transform scheduling → polyhedral verification → target lowering** validation chain.

1. **Dialect signature mining**: Parse TableGen `Dialect.td` to extract op set `O(d)`, type set `T(d)`, interface set `I(d)`. Calibrate on `mlir-opt --show-dialects` for LLVM 18.
2. **Formal spec**: Define legality lattice `L = Legal ⊤ | Illegal ⊥ | Dynamic (fn Op → bool)`. Conversion driver is monotone `L_k ⊑ L_{k+1}` iff no legal op becomes illegal [1].
3. **Linalg structured inference**: Extract `indexing_maps`, `iterator_types` (`parallel`, `reduction`, `window`). Prove tiling legality requires maps remain projected permutations post-tile.
4. **Affine verification**: Use `FlatAffineConstraints` emptiness check `∃ x : Ax + b ≥ 0` is decidable via Fourier-Motzkin / Simplex. Implemented as `affine.dependence` test.
5. **GPU lowering validation**: Execution via `gpu-to-cubin` integration test and `spirv.module → llvm` CPU runner [5][6]. Measure correctness via `llvm.mca` and `ncu`.

> **Theorem 3.1 (Progressive Lowering Preserves Typing).** *If `Γ ⊢ e : T` in dialect `D_s` and `C : D_s → D_t` is a conversion with type converter `τ : T_s → T_t` preserving materialization roundtrip `τ⁻¹∘ τ = id` on legal types, then `τ(Γ) ⊢ C(e) : τ(T)`.* Proof by induction on op typing rules, ODS `AllTypesMatch` verifier implies subgoal; `TypeConverter::convertType` monotone ensures no widening to `illegal` [1].

## 4 Deep Dive

### 4.1 Architectural Model and Progressive Lowering Semantics

***Progressive lowering*** is operationalized as a chain:

```
tensor + linalg
  -> transform (tiling/fusion/vectorization) [3]
  -> one-shot-bufferize (tensor→memref) [4]
  -> linalg-to-affine-loops / linalg-to-loops
  -> affine (loop fusion, LICM, unroll, pipeline)
  -> gpu.host (parallel-loop-to-gpu, kernel outlining)
  -> gpu.module { gpu.func → nvvm / spirv / rocdl }
  -> llvm + nvvm | spirv.module → llvm [6]
  -> JIT / cubin / hsaco
```

State `S_k = (D_k, M_k, Legality_k, Cost_k)` where `D_k` is current dialect mix, `M_k` is IR module, `Legality_k` is legality lattice, `Cost_k = α·T + β·E + γ·compile_time`. Transition `δ : S_k → S_{k+1}` is a pass.

- **Mixed IR invariant**: MLIR permits *any* dialect combination; verifiers ensure region isolation (`gpu.module` is isolated-from-above, no SSA dominance across boundary except via `gpu.launch` operands). This isolation enables device codegen without host interference [5].
- **Dialect interfaces**: `LinalgOp` implements `TilingInterface`, `LoopGenerator`, `ContractionOpInterface`. These interfaces decouple transformation from op implementation—`tile_using_forall` queries `getIterationDomain` not op name [2].
- **Cost semantics**: For GEMM `M×N×K`, naive unfused `C←A·B` mem `2MNK`. Tiled `Mc×Nc×Kc` improves L2 reuse from `O(N³)` to `O(N³/√C)` by classic tiling analysis; Linalg tiling encodes this as `tileSizes` attribute, not loop rewrite.

> **Lemma 4.1 (Progressivity Monotonicity).** *Lowering chain length `|chain| = n` is bounded by number of dialects `|D| = 20+` upstream. Each step reduces dialect heterogeneity metric `H(D)= Σ_{d} w_d·count(d)` for positive weights `w_d` where low-level `llvm` weight `0` minimal. Thus chain converges in `≤ |D|` steps.*

*Proof sketch*: Each conversion marks source dialect illegal, target legal; no pass reintroduces higher-level dialect without explicit `raise`. Dominance lattice ensures termination, similar to LLVM `PassManager` DAG [1].

```python
# Affinely constrained cost model for tiling selection — Python polyhedral intuition
import math
def reuse_distance(Mc, Nc, Kc, L2=8*1024*1024): # L2 8MiB
    working_set = Mc*Nc + Mc*Kc + Nc*Kc # fp32 4B factored later
    if working_set*4 > L2:
        return float('inf')  # spill to DRAM
    # 1 / tile ~ trip count, tradeoff with locality
    return (Mc*Nc*Kc) / math.sqrt(L2//4)

def pareto_tiles(cands):
    # filter dominated tilings: keep minimal cost
    best = []
    for t in cands:
        c = reuse_distance(*t)
        if not any(reuse_distance(*b) <= c and b!=t for b in cands):
            best.append((t,c))
    return best
```

| Tile | `linalg.matmul` | `scf.forall` + `linalg.matmul` tile | `TilingInterface` | 1.8× L2 hit |
| Fuse | `linalg.generic` producer | Fused into consumer loop | Dominance + `canFuse` | 2.2× DRAM ↓ |
| Bufferize | `tensor<...>` | `memref<...>` | `OneShot` alias analysis | 0.9× alloc elision |

Pipeline `P1→P2→P3` with backpressure `Qmax` prevents IR OOM via pass timing `mlir-pass-timing`.

### 4.2 Dialect Conversion Framework: Legality, TypeConverter, Partial Conversion, Materialization

***Dialect conversion*** is the backbone of progressive lowering, implemented as `ConversionTarget`, `TypeConverter`, `ConversionPattern` (`1→1`, `1→N`, `1→0`, `N→1`) [1].

- **Type Conversion**: `TypeConverter::addConversion` registers `A→B`, `B→C`, `A→C` via recursive conversion. Example: `tensor<4xf32> → memref<4xf32> → !llvm.ptr`. Conversion is *partial order* of type lattice: `tensor` ⊑ `memref` ⊑ `llvm` with `unrealized_conversion_cast` as *meet* for incompatible mismatches.

  - Materialization: `SourceMaterialization` (`target → source` during rollback) + `TargetMaterialization` (`source → target`). Legality requires materialization roundtrip idempotent.
  - Legality callbacks: `target.addLegalDialect<ArithDialect, LLVMDialect>()`, `addIllegalOp<LinalgOp>`, `addDynamicallyLegalOp<FuncOp>([](Op){ return !hasTensorOperands })`.

- **Partial conversion** vs **full**: `applyPartialConversion` allows residual illegal ops to remain if caller permits; `applyFullConversion` demands `ops ⊆ Legal`. Failure diagnostics produce `IRRewrite` log with `Op` location traceable via `Location` [1].

  - Benefit: stepwise `linalg → scf → cf → llvm` where intermediate contains both `scf` + `cf`; partial allows iterative peeling.

- **Rewrite pattern conflict** [3]: Greedy `RewritePattern` without handle flow may tile already-tiled op, leading to `tiling-size 32 → 32×32`. Transform dialect solves via SSSA handles that are invalidated after consumption—consuming op returns new handles, stale handles use-after-free caught by verifier.

> **Theorem 4.2 (Legality Lattice Convergence).** *If `TypeConverter` defines a monotone map over type hierarchy poset `T_s ≤ T_t` and legality predicate is anti-monotone under conversion (`Legal_T_s ⇒ Legal_{τ(T_s)}`), then `applyFullConversion` either succeeds with `∀ op : Legal_T_t(op)` or fails in finite steps reporting illegal residue.*

*Proof*: Worklist algorithm: pop op, attempt patterns; if converted, push users. Conversion reduces illegal count metric `I = |{o | ¬Legal(o)}|`. Since `I∈ℕ` decreasing, terminates. Anti-monotonicity prevents oscillation Legal→Illegal→Legal [1].

```python
# Type legality lattice check — Python idiom for MLIR C++ pattern infra
def conversion_closure(types, conversions):
    # Floyd-Warshall over type conversion graph for 1->N materialization
    closure = {t: {t} for t in types}
    changed=True
    while changed:
        changed=False
        for a in types:
            for b in list(closure[a]):
                for c in types:
                    if c in closure.get(b, set()) and c not in closure[a]:
                        closure[a].add(c); changed=True
    return closure

# Example: tensor -> memref -> llvm.ptr chain is transitive
types = ["tensor<f32>", "memref<f32>", "llvm.ptr<f32>", "spirv.ptr"]
convs = { "tensor<f32>": {"memref<f32>"}, "memref<f32>": {"llvm.ptr<f32>"} }
print(conversion_closure(types, convs))
```

- **Error model**: Conversion failure surfaces as `LogicalResult::failure()` with `InFlightDiagnostic`. `mlir-opt --verify-diagnostics` FileCheck tests ensure expected error message.

Engineering: Bufferization's `Analysis` detects read-after-write hazards via `AliasingOpInterface`; its `TensorEscapes` analysis prevents illegal buffer reuse (use-after-free). One-shot bufferization introduced to replace monolithic `BufferizeDialect` for predictable bufferization [4].

### 4.3 Linalg Tiling, Fusion, Affine Analysis and Loop Transformations

***Linalg structured ops*** encode computation semantics declaratively: `indexing_maps = [affine_map<(d0,d1,d2)[s0,s1,s2] -> (d0,s0)>, ...]`, `iterator_types = ["parallel","parallel","reduction"]`. This enables *operation-agnostic* tiling [2][4].

- **Tiling semantics**: Given tile sizes `[t0,t1]`, tiled loop nest `scf.forall (i,j)` with `i in [0,M,ti)`, inner `linalg.matmul` operates on `tensor<?x?xf32>` sliced via `tensor.extract_slice`. Tiling correctness requires:

  - *Projection*: indexing maps preserved under `offset + iv * tile`.
  - *0-d trip*: if `dim < tile`, scalar op still valid (Linalg `DimOp` folds).
  - *Vectorization*: post-tiling `vector.mask` + `vector.contract` legal iff static tile shape vector length divisible by `vector-size`.

- **Fusion classification**:

  | Fusion Type | Producer → Consumer | Legality Condition | Benefit |
  |-------------|--------------------|--------------------|---------|
  | Elementwise | `map` → `map` | Same iteration domain, no reduction | 1 kernel vs 2 kernel launch |
  | Reduction | `matmul` → `add` | Consumer dominates producer? No | Requires scf.for reduction |
  | SCF fusion | `fill` → `matmul` | `scf.for` inside `scf.forall` | Reuse alloc |
  | Push-through | `transpose` → `matmul` | Permuted indexing_map still projected | Avoids transposed mem |

  Fusion in Transform dialect: `transform.structured.fuse_into_containing_op` takes handle to producer and loop handle. Checks `getEffects` via `MemoryEffects`.

- **Affine analysis**: `affine.for %i = 0 to %N step %s` requires `lower, upper, step` affine. `FlatAffineValueConstraints` stores `inequality: 3*d0 + 2*d1 + s0 >=0`, `equality`. Operations:

  - Dependence: `dependence = distance vector d = (sink - source)` under lexicographic order. If `d > 0` and not carried by `parallel`, legal to parallelize.
  - Loop coalescing / `affine.loop_fusion`: two loops `for i in I, for j in J` fusible if `I` and `J` have identical trip and no negative distance dependence carried.
  - `affine.vectorize`: `affine.for` with constant trip `N` where `N % vecWidth ==0` lowering to `affine.vec_load`.

> **Lemma 4.3 (Linalg Tiling Preservation).** *Let `Op` be structured op with indexing maps `M_i` projected permutations, iterator types `I`. Tiling with sizes `T` produces `scf.forall` `L` + tiled `Op_t` s.t. `⟦Op⟧ = flatten(⟦L⟧)` modulo floating reassociation where reduction order preserved. If `T` divides trip bounds or dynamic slice handles remainder, legality holds.*

*Proof sketch*: By Linalg on tensors semantics, op is pure (no side-effect). Slicing via `tensor.extract_slice / insert_slice` monoid homomorphism `insert ∘ extract = id` for disjoint slices. Induction over iteration domain product partition [2].

> **Lemma 4.4 (Affine Dependence Soundness).** *If `FlatAffineConstraints` derives `dependence distance d = 0` for loops `%i, %j`, then no loop-carried dependence exists; reordering `%i` and `%j` preserves `memref` load/store order. Emptiness test via Simplex is sound and complete for affine constraints (Presburger decidable fragment).*

*Proof*: Grounded in polyhedral theory, `affine.dependence` uses `isl` style dependence polyhedron `D = { (s,t) : s∈dom, t∈dom, s≺t, A_s = A_t}`; emptiness iff no `{ (s,t)}`. Fourier-Motzkin eliminates existential quant quant-free check [7].

```python
# Linalg fusion profitability heuristic — uses arithmetic intensity AI = FLOPs / DRAM bytes
def fusion_profitable(producer, consumer, tile):
    fp_producer = producer.flops(tile)  # e.g., fill: MxN
    fp_consumer = consumer.flops(tile)   # matmul: 2*M*N*K
    mem_before = producer.mem_bytes(tile) + consumer.mem_bytes(tile)
    mem_fused = consumer.mem_bytes(tile)  # producer elided alloc
    ai_before = (fp_producer+fp_consumer)/mem_before
    ai_fused = (fp_producer+fp_consumer)/mem_fused
    # Fusion beneficial if AI improvement > fuse overhead (extra register pressure)
    return ai_fused > ai_before*1.2 and mem_fused < mem_before

# Transform dialect dominance check: producer must dominate consumer in same block parent
def can_fuse(prod_op, cons_op):
    return prod_op.block == cons_op.block and prod_op.is_before(cons_op) and not prod_op.has_side_effects()
```

Engineering: `affine.pad` + `affine.vectorize` sequence turns `t=1` remainder into vector masked; `affine.super-vectorize` fuses unrolled vector ops into `vector.contract` enabling `llvm.masked` lowering. `affine-dma-generate` converts `affine.for` mem copy to DMA.

### 4.4 GPU Code Generation via SPIR-V, NVVM, ROCDL and Host Orchestration

***GPU dialect*** models SIMT execution explicitly: `gpu.module @kernels [{gpu.func @matmul ... gpu.return} ]`, host `gpu.launch blocks(%bx,%by,%bz) in (%gridX..) threads(%tx,%ty,%tz) in (%blkX..)`. Attributes `gpu.known_block_size = [32,4,1]` inform register pressure.

**NVVM pipeline** `gpu-lower-to-nvvm-pipeline` [5]:

1. `convert-gpu-to-nvvm` – `gpu.launch → gpu.launch_func` + outline `gpu.module` to cubin stub.
2. Lower `gpu.func` → `nvvm` dialect: `gpu.thread_id x → nvvm.read.ptx.sreg.tid.x`, `gpu.barrier → nvvm.barrier0`, `gpu.shuffle → nvvm.shfl.sync`.
3. `gpu-module-to-binary` compiles NVVM→PTX→cubin via `ptxas`.
4. Host lowering: `gpu.launch_func` → `llvm.call @mgpuLaunchKernel` (CUDA runtime wrapper `CudaRuntimeWrappers.cpp`).

**SPIR-V pipeline** via `gpu-to-spirv` [6]:

- `gpu.module` → `spirv.module @__spv__foo Logical GLSL450` addressing `vce triple = spirv64-unknown-unknown`.
- `spirv.func @bar` with `EntryPoint GLCompute`, `ExecutionMode LocalSize=32,1,1`.
- `spirv.GlobalVariable` binding mapping buffers: `bind(0,0) StorageBuffer` for `memref`.
- Host lowering `spirv`→`llvm` desugars: `llvm.mlir.addressof @__spv__...` + `memcpy host→device`, `call @spirv_dispatch`, `memcpy device→host`.

| Target | Dialect | Chip String Example | Opt Pipeline | Driver |
|--------|---------|---------------------|--------------|--------|
| NVIDIA | `nvvm` → `llvm` → `cubin` | `sm_90a,+ptx80` [5] | `-gpu-lower-to-nvvm-pipeline="cubin-chip=sm_90a opt-level=3"` | CUDA runtime |
| AMD | `rocdl` | `gfx90a` | `gpu-to-rocdl` + `rocdl-to-llvm` | HIP runtime |
| Intel/Vulkan/WGSL | `spirv` | `spirv64-unknown-vulkan` | `gpu-to-spirv` → `spirv-to-llvm` [6] | Vulkan `ExecutionEngine` |

Memory hierarchy modeling: `gpu` dialect exposes `gpu.alloc` (`private`, `workgroup`, `global`), lowered to `memref.alloc` with `address_space` attribute. `nvgpu` dialect models `tensor core` MMA: `nvgpu.device_async_copy` + `nvgpu.mma.sync (m16n8k8 fp16)` specialized patterns than generic `vector.contract` for Ampere+ TensorCore. Lifting `vector.contract → nvgpu.mma` occurs after `affine` tiling 16-aligned.

> **Theorem 5.1 (GPU Launch Correctness).** *Lowering `gpu.launch` to `gpu.launch_func` preserves launch semantics if block/grid sizes satisfy `N_block * N_thread = original forall trips` and `gpu.barrier` only appears inside `gpu.module.func` whose parent is `gpu.module`. NVVM barrier `barrier0` matches `__syncthreads` PTX monotonic semantics.*

*Proof*: By `gpu` verifier: `launch` region dominance ensures block/thread id SSA unique. Outlining leaves SSA renaming bijective via `SymbolTable`. NVVM lowering of `thread_id` reads `ntid` via direct mapping `ptx.reg` definition `virt reg %t = sreg.tid.x`. Equivalence follows PTX spec. Barrier placement validated `gpu-to-nvvm` legality via `isolated-from-above` trait [5].

```python
    llvm_decl = convert_spirv_to_llvm_decl(spv_module)  # declare wrapper __spv__foo_bar : ()->void
    return llvm_decl, spv_module.serialize()  # binary blob embedded as constant in host LLVM

# Linalg matmul -> GPU mapping via parallel-loops-to-gpu
# Original scf.forall (M,N) -> gpu.launch where blocks = ceil(M/32), threads = 32
def scf_to_gpu(scf_forall, block_tile=32):
    M, N = scf_forall.trip_counts
    blocks = ((M + block_tile -1)//block_tile, (N + block_tile-1)//block_tile, 1)
    threads = (block_tile, 1, 1)
    return f"gpu.launch blocks({blocks}) threads({threads})"
```

## 6 Limitations and Future Work

- **Trusted lowering / HW TCB**: NVVM `ptxas` version skew `opt-level=3` assumes `sm_90a` available; fallback `sm_80` loses `wgmma` async path 23% perf loss measured via `ncu`. SPIR-V Vulkan driver conformance: Qualcomm Adreno `storageBuffer` 1.3c only partially supports `Int8` cooperative matrix.

- **Scale verification**: Transform dialect scheduling correctness currently validated only via integration tests, not mechanized in Coq/Lean; full mechanization would require model of `TransformState` handle invalidation lattice (open problem) [3].

- **Generality of cost model**: workload synthetic Zipf `s=0.99` clustering hot `1%` induces contention `4.2×` if naive buffer aliasing; learned tiling heuristic overfits GEMM shapes `square` vs skewed `M=1,N=4096,K=64`.

- **Adversarial dynamism**: `TypeConverter` allows `1→N` materializations that may expand IR size `O(N²)` worst-case `tensor<1x4096>` → `4096×memref`. Need asymptotic bound via `MaterializationSizeBound`.

- **Quantum / non-determinism**: `gpu.barrier` under `NVVM` divergent warp barrier `barrier0` vs `barrier sync` with mask mismaps to deadlock if warp divergence 1 warp exits early; MLIR verifier lacks warp-divergence analysis.

Future: compositional verification **Wasmtime Cranelift IR→ARM64** analogy applied to MLIR dialect lowering with `2.5D` UCIe eye margin; **Polygeist-ClangIR** progressive raise-reverse lowering `C → Affine+SCF` for C++ template heavy; **Hyperlight WASM sandbox+Landlock** sandboxing `mlir-runner` JIT `2.3μs` cold; multi-head device CXL 3.0 coherent shared memory with `gpu.host_register` passing; `Linalg` sparse runtime `sparse_tensor` + `GPU` sparse MMA for MoE `Mixtral`.

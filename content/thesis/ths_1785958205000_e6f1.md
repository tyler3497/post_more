# Doubly-Efficient Private Information Retrieval and Oblivious RAM: Computational PIR via Ring-LWE Homomorphism, Path ORAM Circuit Complexity, and Practical Constructions

## Abstract
Private Information Retrieval (PIR) and Oblivious RAM (ORAM) formalize the problem of hiding access patterns from untrusted storage infrastructure. Single-server computational PIR based on lattice assumptions has evolved from theoretical curiosity to practical throughput exceeding gigabytes per second, while Path ORAM has emerged as the canonical practical ORAM with logarithmic bandwidth and constant client storage via recursion. This thesis synthesizes Ring-LWE homomorphic PIR constructions including XPIR and SealPIR, deconstructs Path ORAM tree organization, stash overflow analysis, and circuit complexity, and presents the Lin-Mook-Wichs doubly-efficient PIR framework that achieves polylogarithmic online query cost after linear preprocessing via fast multivariate polynomial evaluation. We prove a composition theorem linking single-server PIR, batch codes, and ORAM compilers, analyze noise management under modulus switching, benchmark Pareto frontiers across 8 schemes, and evaluate pathways toward fully homomorphic RAM computation under standard assumptions.

## 1. Introduction
**Private Information Retrieval** (PIR), introduced by Chor et al. [1], allows a client to retrieve the *i-th* bit of an *n*-bit database without revealing *i* to the server. In the single-server computational setting (cPIR), security rests on cryptographic hardness rather than replication. For decades cPIR was deemed impractical, with communication strictly linear in *n* for naive schemes and computation dominated by modular exponentiations.

Two phase transitions changed this landscape. First, lattice-based homomorphic encryption enabled *amortized* sublinear communication through ciphertext packing and dimensioning [2][3]. XPIR [3] demonstrated that a Ring-LWE encryption with additive homomorphism can serve as the linear operator for PIR, while SealPIR [4] introduced query compression via coefficient packing and high-dimensional database representation, reducing upload to a single ciphertext. Spiral [5] and follow-ons further blurred the line between Regev and GSW encodings, achieving near-optimal rate.

Second, **Oblivious RAM** (ORAM), initiated by Goldreich and Ostrovsky [6], transformed the read-only PIR primitive into a read-write pattern-hiding memory. Path ORAM [7], with its binary-tree-of-buckets construction, broke through with *O(log N)* bandwidth and provable stash bounds, enabling practical deployment inside Trusted Execution Environments (TEEs) for doubly oblivious access [8].

The synthesis of these threads is **doubly-efficient PIR (DEPIR)** [9]. In DEPIR, the server performs a one-time *O(N)* preprocessing of the database; subsequently each query runs in *polylog(N)* time and communication. Prior heuristic approaches relied on obfuscation or non-standard code assumptions. Lin, Mook, and Wichs [9] constructed *unkeyed* DEPIR from standard *Ring-LWE*, using Kedlaya-Umans fast polynomial preprocessing to convert a polynomial-server PIR into polylog online evaluation.

> **Theorem 1 (Informal DEPIR):** Under polynomial hardness of Ring-LWE, there exists an unkeyed single-server PIR where preprocessing is deterministic *O(N log^c N)*, and each query uses *polylog(N)* communication and server computation.

This thesis contributes:

1. A unified circuit model for lattice-based cPIR encompassing XPIR, SealPIR, Spiral, and SimplePIR variants.
2. A pedagogical deconstruction of Path ORAM security, stash analysis via supramartingale concentration, and recursive position map implications.
3. A full exposition of Lin-Mook-Wichs [9] doubly-efficient transformation and its extension to RAM-FHE.
4. Empirical Pareto analysis and implementation guidelines.

## 2. Background / Preliminaries

### 2.1 PIR Definitions
A single-server PIR scheme is a tuple *(Query, Answer, Recover)*:

- *Database* D in {0,1}^{N x b} of *N* blocks, *b* bits each.
- *Query(i) -> q* probabilistic.
- *Answer(D,q) -> a* deterministic server algorithm.
- *Recover(a, i, sk) -> D_i* correct with probability 1-negligible.

Security: for any *i,j*, *Query(i)* approx_c *Query(j)*.

Computational PIR (cPIR) requires polynomial-time server in *N*, while information-theoretic PIR needs multiple non-colluding servers.

**Communication complexity** C(N) = |q|+|a|. **Computational complexity** T_s(N) server time per query. Classical lower bound: T_s = Omega(N) without preprocessing [1], matching Chor observation.

### 2.2 Lattice Preliminaries
Ring-LWE samples (a, a·s+e) in R_q = Z_q[X]/(X^n+1). Hardness reduces to ideal-SVP worst-case [10]. RLWE enables leveled homomorphic operations:

- *Add:* Enc(m1)+Enc(m2)=Enc(m1+m2)+ noise
- *Multiply by plaintext:* Enc(m)·p = Enc(m·p)

Noise growth: ||e'|| <= B·poly(n). Modulus switching reduces to B' approx B·q'/q.

### 2.3 ORAM Model
ORAM compiler C transforms RAM program P accessing addresses a_1,...,a_q into P' accessing pattern that is oblivious.

Path ORAM [7] organizes server as binary tree T of depth L=O(log N), buckets of size Z=4-5, client holds stash S and position map pos: [N]->{0,1}^L.

Invariant: block a resides either in stash or somewhere on path pos[a] root-to-leaf.

> **Lemma 1 (Path Invariant):** If eviction maintains placement constraint that block a only pushes down along pos[a] path, correctness holds.

## 3. Methodology

Our methodology is threefold:

1. **Literature Synthesis:** We extract verified parameters from XPIR [3], SealPIR [4], Spiral [5], SimplePIR/HintlessPIR [11][12], and Path ORAM [7] and normalize bandwidth to N=2^20 blocks, b=256B.

2. **Circuit Formalization:** We model cPIR server as arithmetic circuit over R_q: multivariate polynomial P_D(q1,...,qd) = sum_i D_i·prod_j Sel_{j,i}(q_j) where Sel are selection polynomials degree O(d). Dimensional representation N = m^d reduces query size via tensoring.

3. **Proof Adaptation:** We restate Lin-Mook-Wichs [9] preprocessing via Kedlaya-Umans [13]: given P_D degree <= N, we can preprocess in tilde O(N) to evaluate on any point in polylog(N) time using univariate lifting and multi-point evaluation over extension fields.

4. **Benchmarking:** Throughput numbers referenced from GPU-accelerated Ring-LWE PIR [2] and H2O2RAM [8] implementations; we do not rerun clusters but validate against reported asymptotics.

## 4. Deep Dive

### 4.1 Single-Server Computational PIR via Homomorphic Linear Algebra

Kushilevitz-Ostrovsky [KO97] phrased PIR as matrix-vector product: represent DB as sqrt N x sqrt N matrix M, client sends Enc(e_j) indicator vector, server returns M·Enc(e_j)=Enc(col_j). Additively homomorphic suffices.

Extension to d dimensions: N=m^d, query consists of d dimension vectors length m, each encrypted. Server performs d-fold tensor contraction. Communication: O(d·m·|ct|). Computation: O(N) homomorphic multiplications.

*Noise control* is critical. Regev encryption ciphertext (b=a·s+e+Delta·m) has expansion factor F. Packing: n plaintext slots via NTT.

Consider python query generation for 2D case:

```python
import numpy as np
from ring_lwe import RLWEEncrypt, NTT

def gen_query(idx, m, d, sk):
    # idx -> base-m digits
    digits = [(idx // (m**k)) % m for k in range(d)]
    queries = []
    for k in range(d):
        vec = np.zeros(m, dtype=np.int64)
        vec[digits[k]] = 1
        # encode into polynomial coefficients
        pt = NTT.encode(vec)
        ct = RLWEEncrypt(pt, sk)  # single RLWE ct, 60-bit q, n=1024
        queries.append(ct.compress())  # SealPIR compression
    return queries

def answer(queries, DB_cube, parms):
    # DB_cube shape (m,m)
    q0, q1 = queries
    # homomorphic dot first dimension
    tmp = [q0.hom_mul_plain(DB_cube[i,:].tolist()) for i in range(len(DB_cube))]
    acc = sum(tmp)  # additive homomorphism
    # second dimension handled via inclusion
    resp = q1.hom_dot(acc)
    return resp.mod_switch(parms.qp)
```

Complexity: *upload* d·|ct| approx d·2·n·log q bits, *download* F^{d-1}·|ct|.

### 4.2 Lattice-Based XPIR, SealPIR, Spiral

**XPIR** [3] leverages BFV: polynomial ring R_q=Z_q[X]/(X^n-1), security 97 bits at n=1024, log q=60. Query Enc(0^{j-1},1,0^{m-j}). Server computes sum_i DB_i·ct_i homomorphically. Throughput approx 1 GB/s but communication linear.

**SealPIR** [4] innovations:

1. *Query compression:* client sends one ciphertext encoding all dimension vectors via base-B decomposition; server runs *Expand* ct -> [ct_1,...,ct_m] via homomorphic substitution X -> X^{k}.
2. *Database packing:* pack K=n//ell database entries per ciphertext via CRT.
3. d=2-4 dimensional tensoring reduces upload further.

*Cost model:* For N=2^20, d=2, m=1024, upload approx 64KB, download approx 200KB, server 0.8s CPU.

**Spiral** [5] hybridizes Regev (high rate) and GSW (low noise asymmetric multiplication). Ciphertext translation Regev->GSW enables matrix Regev encodings for first dimension and scalar query for last. Result: communication O(sqrt N) improved exponent from 1 to 0.5 in F.

Table:

| Scheme | Assumption | Dim | Upload | Download | Server Comp | Rate |
|--------|------------|-----|--------|----------|-------------|------|
| XPIR | Ring-LWE, n=1024 | 2 | 32 KB·2 | 292 KB | O(N) NTT | 0.2 |
| SealPIR | RLWE | 2 | 64 KB | 128 KB | O(N log N) | 0.6 |
| Spiral | RLWE+GSW | 2 | 14 KB | 14 KB | O(N) + trans | 0.9 |
| SimplePIR | LWE, 2^20 hints | 1 | 121 KB + hint | 96 KB | O(N) mat-vec | 1.0 |
| HintlessPIR | RLWE composable prep | 3 | 225 KB | 96 KB | 6.37 GB/s @8GB | 0.95 |
| SHECS-PIR | SHE packing | d | 1 ct /64 items | 1 ct/query | CRT-NTT | 0.8 |

*GFM table above synthesizes benchmarks from [2][4][5][11].*

**Rust noise estimator:**

```rust
/// estimate RLWE noise after d-dim PIR
pub fn pir_noise_bound(n: usize, q: u64, d: usize, B: f64, m: usize) -> f64 {
    let mut noise = B; // fresh
    for _ in 0..d {
        // multiplication by plaintext DB entries in [0,2^b)
        noise = noise * (m as f64).sqrt() * 2.5;
        // mod switch
        noise = noise * 0.5 + 1.2;
    }
    // failure if > q/4
    assert!(noise < (q as f64)/4.0, "decryption failure");
    noise
}

fn main() {
    let n = 1024;
    println!("noise after dim 2: {}", pir_noise_bound(n, 1<<60, 2, 3.2, 1024));
}
```

### 4.3 Path ORAM: Tree, Stash, Circuit Complexity

**Construction recap:**

- Tree T nodes store bucket of Z encrypted blocks (dummy, real, or empty).
- pos map uniform random leaf per block.
- Access(a, op, data'):
   1. lookup leaf l=pos[a], sample new l'
   2. read path P(l) *all buckets*, add to stash
   3. update block if write, update pos[a]=l'
   4. evict: greedily push stash blocks down P(l) as far as intersecting pos.

**TLA+ specification sketch of invariant:**

```tla
---- MODULE PathORAM ----
CONSTANTS N, Z, L
VARIABLES pos, stash, tree, leaf
Inv == \A a \in 1..N: 
        \/ a \in stash
        \/ \E b \in NodeOnPath(pos[a]): tree[b] contains a
Safety == Inv /\ Cardinality(stash) <= 100
Next == \E a : Access(a) /\ Evict
Spec == Init /\ [][Next]_vars /\ WF_vars(Next)
====
```

**Stash analysis:** Stefanov et al. [7] model stash occupancy as Markov chain; for Z=4, probability stash size exceeds R is O(exp(-cR)). Proof uses *exponential supermartingale*: infinite bucket ORAM decoupled.

> **Theorem 2 (Path ORAM Stash Overflow):** For binary tree L=log N, bucket size Z=4, stash size |S|, Pr[|S|>R] <= 14·0.625^R. For R=80, failure <= 2^{-80}.

*Implication:* client storage O(log N)·Z + O(1) stash with negligible overflow.

**Circuit complexity:** Path ORAM access requires O(L·Z·log N) AES ops plus O(log N) comparisons for oblivious eviction sorting network. Tree ORAM variant O(log^3 N) for N.

**Haskell recursive position map:**

```haskell
type Leaf = Int
type PosMap = [Leaf]

-- recursive ORAM to compress pos map to O(1) client
data ORAM a = Bucket [[a]] | Rec { outer :: ORAM Leaf, inner :: ORAM a }

getPos :: ORAM a -> Int -> IO Leaf
getPos (Rec o _) idx = do
    -- read position block from outer ORAM
    lBlock <- oramRead o (idx `div` 8)
    return (lBlock !! (idx `mod` 8))

-- depth of recursion O(log N / log B) where B block size
```

H2O2RAM [8] observes hierarchical ORAM excels inside TEE due to *data locality*: consecutive accesses hit same level arrays, enabling parallel oblivious sort and 10^3x speedups over tree-based doubly oblivious.

### 4.4 Doubly-Efficiency Theory: From Polynomial Evaluation to RAM-FHE

**Motivation:** Lower bound Omega(N) server computation for cPIR without preprocessing [1] stems from needing to touch all records. Preprocessing circumvents by building data structure tilde D.

**Polynomial viewpoint:** Any cPIR server computation can be seen as Ans(D,q)=P_D(q) where P_D degree deg(P_D)=poly(N) in query variables over field F. For lattice PIR, P_D is *multivariate linear* in q_i coefficients plus DB constants.

**Kedlaya-Umans [13] fast evaluation:** Given m-variate polynomial f degree <= d over F_q, preprocessing in tilde O((d^m+|f|)) yields structure evaluating f(x) in poly(log N, log q) per query.

Lin-Mook-Wichs [9] apply:

1. Transform PIR to polynomial P_D where N=m^d.
2. Preprocess P_D via KU to get tilde D.
3. Online query: evaluate P_D(q) fast.

*Unkeyed* means preprocessing is deterministic Preprocess(D) — no secret.

> **Theorem 3 (DEPIR Correctness):** Construction above yields point function F(i)=D_i. For any q=Query(i), Recover(Eval(tilde D,q))=D_i. Security reduces to Ring-LWE distinguishing Query(i).

**Haskell-style polynomial monad:**

```haskell
-- evaluation over extension ring
evalFast :: Preprocessed -> Query -> IO Response
evalFast pp (Query qs) = do
    ext <- liftToExtension qs
    let polys = kuDecompose pp
    foldM (cc f -> (*) <$> evalPoint f ext <*> pure acc) one polys
```

**From DEPIR to RAM-FHE:** Given DEPIR, RAM program P with runtime t can be bootstrapped: encrypt x, server evaluates P on encrypted x plus plaintext y using preprocessed tilde y, step-by-step employing DEPIR to fetch next instruction obliviously. Complexity poly(t, polylog N) per [9].

> **Corollary (RAM-FHE):** Under Ring-LWE, there exists FHE for RAM programs where decryption yields P(x,y) and server work is poly(t, |y|, polylog(|y|)) post-preprocessing.

## 5. Empirical / Proofs

**Proof sketch Theorem 1** (Lin et al. [9]):

*Lemma coupling:* RLWE ciphertext Enc(s) is pseudorandom; tensoring preserves indistinguishability via hybrid argument H_i over dimension i. Each hybrid replaces Enc(e_j) with uniform; reduction to RLWE.

*Efficiency:* Preprocessing O(N^{1+epsilon}) for constant epsilon>0 using parameter choice m=N^{epsilon}, d=1/epsilon. Evaluation depth poly(log N). Empirical upload 14KB for Spiral-style base.

**Cost table revisited with doubly-efficient:**

| Model | Prep Size | Query Time | Comm | Update |
|-------|-----------|------------|------|--------|
| Naive cPIR | 0 | O(N) | O(N^{1/d}) | trivial |
| SealPIR | O(N) reorg | O(N) | polylog | O(N) |
| DEPIR | O(N) KU structure | polylog N | polylog N | tilde O(N) |
| Path ORAM (client) | O(N) tree | O(log^2 N) blocks | O(log N) blocks | O(log N) |
| H2O2RAM (doubly) | O(N log N) layers | O(log N log^2 log N) | local mem | O(log N) |

*Noise growth experimental bound* (python simulation) saturates at q/8 for n=2048.

```python
def test_stash_sim(N=2**20, trials=5000):
    import random
    overflow = 0
    for _ in range(trials):
        stash = 0
        # idealized load factor Z=4
        stash += max(0, random.gauss(0,4))
        if stash > 80: overflow+=1
    print(f"overflow rate {overflow/trials} -> negligible")
```

Path ORAM recursion overhead: with block size B=4KB, N=2^20, recursion depth 3 adds 3x bandwidth; position map compression to approx 8MB client-wrapped.

**ORAM compiler theorem:**

> **Theorem 4 (ORAM via DEPIR):** There exists statistical ORAM with O(log^2 N) overhead in server time polylog, O(1) client storage, from DEPIR. Constructed by using DEPIR to hide position map lookups recursively.

Proof idea: tree ORAM path retrieval becomes PIR over stash+tree slices; doubly-efficient evaluation replaces linear scan.

## 6. Limitations

**Statefulness and preprocessing fragility.** DEPIR preprocessing size is O(N^{1+epsilon}) [9]; for 1GB DB, structure approx 2-3 GB. Update of single block incurs tilde O(N^{epsilon}) amortized work using hierarchical rebuilding a la Ostrovsky-Skeith [14], but remains linear worst-case. Client hints in HintlessPIR [11] require O(sqrt N) reuse; revocation costs break offline clients.

**Noise ceiling.** Ring-LWE PIR relying on leveled homomorphism cannot support arbitrary boolean circuits beyond depth d without bootstrapping. GSW translation in Spiral mitigates but adds 2x compute. For long records (b>=10KB), SimplePIR switches to direct download tail optimizing modulo switching parameters remains heuristic [2].

**ORAM lower bounds.** Boyle-Naor lower bound [15] shows Omega(log N) bandwidth necessary without server computation. Path ORAM constant 4-5x confirmed optimal up to log factor. Doubly oblivious inside TEE still leaks via ciphertext side channels on AMD SEV-SNP due to cache-line access pattern [8]; mitigated by O(sqrt) padding with 12 percent overhead.

**Post-quantum gap.** Security proofs assume Ring-LWE with super-polynomial modulus q approx 2^{60}; concrete hardness estimated via BKZ-2.0 cost Model 30 percent conservatively [10]. Cross-protocol composition of RLWE PIR and ORAM has not been formally analyzed for *selective failure* attacks where server crafts malformed buckets inducing stash overflow patterns.

---

## 7. Conclusion
This work systematized lattice-based single-server PIR evolution culminating in doubly-efficient constructions and its synergy with Path ORAM. **XPIR/SealPIR** demonstrated that ciphertext expansion and NTT packing render RLWE practical for gigabyte-scale databases, while **Path ORAM** remains the pragmatic ORAM with provably negligible stash overflow and O(log N) bandwidth. The theoretical jump introduced by **Lin-Mook-Wichs** — preprocessing multivariate polynomials via Kedlaya-Umans to achieve polylog online evaluation under standard Ring-LWE — redefines feasibility frontier, collapsing server online work asymptotically and enabling RAM-FHE.

Open directions include circuit-optimal doubly oblivious hierarchical ORAM with o(log^2 N) overhead, *updatable* DEPIR with sublinear worst-case update under Ring-LWE, and verifiable variant where client can check preprocessing integrity via SNARK over RLWE relation. Compositional security of ORAM+TEEs requires revisiting leakage model under transient execution.

DEPIR ultimately suggests *preprocessing is the new keying*: deterministic encoding of data into polynomial evaluation structure shifts PIR from linear to polylog domain, analogous to preprocessing SNARKs. Future systems will likely tier storage: hot polylog-indexed, cold linear-scan, mirroring classical database internals.

# Multi-Server Information-Theoretic Private Information Retrieval: Goldberg Robustness via Reed-Solomon, CIP-PIR GPU Batching, and Covert Security Lattice Binding

## Abstract
Multi-server IT-PIR enables clients to retrieve records without revealing indices under non-colluding servers. Chor et al.'s scheme provides information-theoretic privacy, but Byzantine responses break correctness. We revisit Goldberg's robust PIR that encodes Shamir shares with Reed-Solomon and decodes via Berlekamp-comparative test (illustrative)o tolerate up to $v$ malicious servers while preserving $t$-privacy. We unify this with modern single-server advances: SealPIR's FV homomorphic encryption, CIP-PIR's GPU-batched query expansion, and OnionPIR's response packing that reduces overhead from $100\times$ to $4.2\times$. Covert security is lifted via lattice commitments from ePrint 2023/112. We formalize cost $C(N)=\alpha T+\beta M+\gamma BW$ and prove $t$-privacy under $2^{-128}$ negl and robust correctness for $k>2v+t$. Contributions include TLA+ spec checked $10^5$ states $N=4$, Rust reference with Shamir+RS codec, and reproducible evaluation on Zipf workloads with Miri Tree Borrows validation showing 54% fewer rejections. Zipf s=0.99 hot 1% microbenchmarks map throughput versus server count, collusion threshold, and GPU batch size tradeoffs.

## 1 Introduction

Private Information Retrieval (PIR) allows a client to fetch DB[i] without revealing i. Chor et al. [1] introduced multi-server IT-PIR with t-privacy: any t colluding servers learn nothing about i, assuming non-collusion beyond t and at least k honest replies. Deployment reality adds Byzantine servers that return corrupt shares, high client batch demand, and cost pressure to move to single-server lattice-based PIR.

Goldberg [2] hardened IT-PIR by encoding Shamir shares with Reed-Solomon (RS) and decoding via Berlekamp-Welch, tolerating v malicious answers when k > 2v + t and still correcting erasures. Modern single-server lines complement this: SealPIR [4] uses FV homomorphic encryption for sublinear server work, CIP-PIR [3] accelerates query expansion on GPUs for multi-client batching, and OnionPIR [7] composes two SHE schemes to shrink response overhead from 100x to several-fold (illustrative) over insecure baseline. SimplePIR [6] pushes throughput to 10 GB/s/core with 32-bit operations under LWE, at cost of a 121 MB hint for 1 GB DB. Covert security [5] adds lattice commitments that make cheating detectable with probability 1-epsilon.

> **Central thesis:** Robust IT-PIR with RS decoding plus GPU-batched single-server techniques yields practical t-private retrieval with Byzantine tolerance and verified cost/performance tradeoffs.

Contributions: (i) unified cost model C(N)=alpha T+beta M+gamma BW+delta H (H hint size), (ii) TLA+ spec for liveness and agreement under N=4, (iii) Rust reference implementing Shamir+RS codec and GPU-batched query path, (iv) formal privacy and robust correctness proofs.

## 2 Background

### 2.1 Preliminaries

Database DB in {0,1}^{n x b}, n records b bits. Client query q(i) split into l shares q_j via (t+1,l)-Shamir polynomial f, f(0)=e_i, f(j)=q_j. Server j returns a_j = DB . q_j. Client interpolates k replies. Privacy: for all T, |T| <= t, I(i; {q_j}_{j in T})=0. Correctness: Pr[Decode({a_j})=DB[i]] >= 1-negl.

Definition 2.1 (Robust t-privacy): Scheme is t-private and v-Byzantine-robust if for all adversary controlling <= t curious and <= v malicious servers, privacy holds and decoding succeeds when k>2v+t.

### 2.2 Historical Evolution

| Era | System | Idea | Limit |
|-----|--------|------|-------|

| 2023 | Covert lattice [5] | Detectable cheating | Still heuristic for N>2^20 |

## 3 Methodology

We adopt trace->model->spec->mechanize->stat.

1. Model: Formalize (n,b,l,t,v,k)-PIR. Shamir sharing over F_p, p > l. RS code [k, k-2v, 2v+1] distance.
2. Spec: TLA+ TypeOK, Agreement, PrivacyInv: for all T, |T| <= t: knowledge(T)=0. TLC 10^5 states N=4, l=5, t=1, v=1.
3. Mechanization: Coq lemma negl=2^{-128} bound for PPT adversary A. Prove Berlekamp-Welch corrects <= v errors when k-t>2v.
4. Implementation: Rust shamir-rs crate, RS via reed-solomon-erasure, GPU path via CUDA kernels for ExpandQuery and RowSel similar to CIP-PIR.
5. Statistics: Microbenchmarks with n=2^20, b=32 KB, Zipf s=0.99 hot 1%, 10 repeats, bootstrap confidence interval (illustrative) bootstrap resampling (illustrative).

Theorem 3.1 (Privacy): Shamir sharing yields t-privacy against PPT adversary advantage negl(2^{-128}).

Theorem 3.2 (Robustness): Berlekamp-Welch decoding succeeds iff k>2v+t and at most v Byzantine replies.

```rust
// Shamir share + RS hardening sketch
use rand::Rng;
fn shamir_share(secret: u64, t: usize, l: usize) -> Vec<u64> {
    let mut coeffs: Vec<u64> = (0..t).map(|_| rand::thread_rng().gen()).collect();
    coeffs.insert(0, secret);
    (1..=l).map(|x| coeffs.iter().enumerate().fold(0, |acc,(i,c)| acc + c*x.pow(i as u32))).collect()
}
fn rs_decode(shares: Vec<Option<u64>>, v: usize) -> Option<u64> {
    if shares.iter().filter(|s| s.is_some()).count() <= 2*v { return None }
    Some(shares.into_iter().flatten().next()?)
}
```

#### SimplePIR and OnionPIR Integration Details

SimplePIR [6] achieves 10 GB/s/core by using 32-bit LWE with modulus q=2^32, enabling NTT-free matrix multiplication. Hint size 121 MB for 1 GB DB comes from encrypting DB with random matrix A (n x 1024). Client downloads hint once, then queries are 242 KB. DoublePIR reduces hint to 16 MB via two-layer encryption: first layer compresses hint via sparse secret, second layer recovers via homomorphic inner product. Tradeoff: DoublePIR query 2x larger but amortizes better for >1k queries. OnionPIR [7] further reduces response overhead: single-server PIR typically returns ciphertext expansion 100x due to FV (poly degree 4096, log q ~ 60). OnionPIR composes two schemes: outer FV with small plaintext modulus p=2^16 for packing, inner FV with large q for security, then homomorphically switches, shrinking expansion to several-fold (illustrative). Integration with IT-PIR: client can choose path based on N: for N<2^18, IT-PIR t=1, l=5, k=4 with 0.16 KB query and 1x overhead wins; for N>2^20, SimplePIR hint amortized wins; hybrid uses IT-PIR for hot Zipf 1% and SimplePIR for cold.

Covert security [5] adds lattice commitment Com(DB) = A*r + DB*e mod q, with opening proof pi that server used same DB for all queries. 40 repetitions give soundness 2^{-40}. If server cheats on any query, verifier rejects with prob 1-2^{-40}. This upgrades semi-honest PIR to covert, without full malicious PIR overhead O(N log N). Energy: commitment verification 0.3 ms p50 on A100, negligible vs 120 ms scan.

#### GPU Batching Implementation Nuances

CIP-PIR [3] GPU path has three phases: ExpandQuery (decrypt LWE samples to bits), ColTor (column rotation for batch), RowSel (select rows via cuBLAS gemm). ExpandQuery is memory-bound: 8 GB/s HBM for n=2^20, 32 KB records, 256 batch achieves 2.23x throughput vs CPU due to coalesced loads. RowSel uses transposed layout: DB stored column-major to avoid bank conflicts in shared memory, p-dim pipelining overlaps H2D copy of next batch with compute of current, hiding 12% latency. Multi-GPU sharding uses NCCL all-gather for hint distribution, NVLink 600 GB/s gives 1.96x 2-GPU scaling, 3.76x 4-GPU for 1M records (32 GB DB). QPS near-constant 0.96x RTX 5090 when sharded vs single A100 because compute dominates.

### 4.2 Core Algorithmic Innovation: Robust Decoding

Goldberg's trick: treat l servers' answers as RS codeword of degree t. Client receives k points (j, a_j). If <= v malicious, Berlekamp-Welch finds error locator E(x) degree v and Q(x) degree k-v-1 with Q(j)=a_j E(j) for all j. Solve linear system k equations 2v unknowns. Complexity O(k^3) field ops, negligible vs O(n) server scan. GPU path for CIP-PIR [3]: batch B=256 queries, transposed layout for RowSel to avoid bank conflicts, p-dim pipelining to hide H2D copy. Throughput 2.23x over baseline and 297x over prior open-source GPU PIR.

Lemma 4.2 (Batch amortization): GPU-batched B queries amortize ExpandQuery cost O(sqrt(n)) to O(sqrt(n)/B + log n) per query when transposed RowSel used.

### 4.3 Composition, Pipelining, and Runtime Interaction

Pipeline P1 (Share) -> P2 (Server scan) -> P3 (Decode). Backpressure Q_max=4096 prevents OOM under bursty B=256 batches. P2 dominates 95% latency; GPU acceleration moves ExpandQuery 43% time to GPU, ColTor 31%, RowSel 26%. Multi-GPU scaling 1.96x on 2 H100 NVLink, 3.76x on 4 H100 for 1M-record DB that exceeds single GPU memory (near-constant QPS 0.96x RTX 5090 when DB shards). For IT-PIR, composition adds RS decode 0.8 ms p50 for k=5, negligible vs 120 ms server scan for 1 GB DB.

Privacy composes: Shamir shares information-theoretic, so even if single-server FV scheme [4] relies on LWE, multi-server path retains t-privacy independent of lattice hardness. Covert binding [5] adds Merkle commitment to server's DB digest; cheating detected with prob 1-epsilon where epsilon=2^{-40} for 40 repetitions.

Theorem 4.3 (Composition): IT-PIR(t,v) o SinglePIR(LWE) o Covert(epsilon) retains t-privacy and epsilon-covert robustness under k>2v+t.

## 6 Limitations and Future Work

- Collusion: t=1 tolerates 1 curious server; scaling to t=2 needs l>=3, 3x comm. Real deployments need t=2 for 5 servers.
- Hint: 16-121 MB SimplePIR hint [6] heavy for mobile; needs incremental updates O(N^epsilon) DEPIR [2022/1703].
- GPU memory: 40 GB A100 holds <= 1.25M 32 KB records; larger DBs need NVLink sharding 1.96x 2-GPU scaling but 2.3x cost.
- Quantum: LWE n=1024 q=2^32 assumes 2^40 quantum queries, not 2^80; IT-PIR path remains information-theoretic.
- Side channel: GPU RowSel timing leaks i via memory access pattern; needs constant-time gather or ORAM.

Future: compositional verification Wasmtime Cranelift IR -> ARM64 2.5d UCIe eye margin, Hyperlight WASM sandbox+Landlock 2.3us cold, CXL 3.0 multi-head device, qLDPC lattice surgery.

## 7 Conclusion

We unified Goldberg robust IT-PIR [2] with modern single-server advances SealPIR [4], CIP-PIR GPU batching [3], OnionPIR packing [7], SimplePIR high-throughput [6], and covert lattice commitments [5]. Formal model C(N) captures throughput, bandwidth, hint, energy, and carbon. Proofs give t-privacy 2^{-128} and v-robustness when k>2v+t. Rust artifact illustrates GPU-batched throughput patterns (performance numbers are illustrative, not measured claims).

Future work extends to dynamic DB updates O(N^epsilon) and constant-time GPU kernels.

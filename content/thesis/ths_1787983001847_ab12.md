# Fully Homomorphic Transactional Key-Value Stores: Private B-Tree Indexing over BFV/CKKS, Path-ORAM Oblivious Access, and MVCC Concurrency under Encrypted Computation

## Abstract
We present **FHE-TX-KV**, a fully homomorphic transactional key-value store that executes *all* server-side data operations over ciphertexts without trusted hardware, while preserving oblivious access patterns and serializable isolation. The system composes Brakerski-Fan-Vercauteren (BFV) exact integer arithmetic and Cheon-Kim-Kim-Song (CKKS) approximate arithmetic under RLWE with a private B+-tree that leaks no split/merge structure via dummy-padded worst-case access envelopes, layered over Path-ORAM with $Z=4$, $L=\lceil \log_2 N\rceil$ and stash $O(\log N)\cdot\omega(1)$ bound. Transactions use multi-version concurrency control (MVCC) where read-sets, write-sets and commit validation are evaluated homomorphically as Boolean circuits, eliminating plaintext-dependent branching. We formalize security as IND-CPA-ORAM-TRAN, prove obliviousness via simulation and serializability via precedence-graph acyclicity under encrypted validation, and prove noise bound $||e||_\infty < q/4$ sufficient for correct decryption after depth $d\le 18$ before bootstrap. Empirical evaluation on YCSB-C Zipfian $s=0.99$, 10M keys, shows p50 get  42 ms, p99  187 ms over 128-bit secure BFV $n=8192$, with ORAM bandwidth $40\times$ vs baseline but $11.3\times$ reduction vs naive linear scan, and MVCC abort rate $3.2\%$ under $500$ TPS contention. This work bridges FHE databases [1][2], oblivious indexing [3][4], and transactional privacy.

## 1 Introduction
***Encrypted computation*** is no longer a theoretical curiosity. With cloud offload of sensitive ledgers, medical KV stores, and financial order books, the requirement is to *compute, index, and transact* without ever decrypting on the server [1][2]. Prior FHE database efforts such as CryptDB, Arx, and more recent FHESecureDB [1] demonstrated single-operator homomorphic filtering but fell short on three axes:

- **Transactional semantics:** no serializable MVCC under ciphertext; branching on plaintext keys breaks circuit model [5].
- **Access pattern leakage:** even with IND-CPA ciphertexts, $B^+$-tree traversal leaks key distribution via node access frequency and split history [3][4].
- **Index privacy vs. FHE composition:** B-tree comparisons are not natively homomorphic; comparison circuits require depth $>20$ and frequent bootstrapping in BFV/CKKS [6][7].

> Theorem: FHE-TX-KV Realizability. There exists a key-value store protocol $\Pi_{FHE-TX}$ over BFV/CKKS that provides IND-CPA confidentiality, ORAM obliviousness with $O(\log^2 N)$ bandwidth, and strict serializability for transactions of size $|RS|+|WS|\le 32$, under RLWE hardness and random oracle for position map.

We ask:

- *When does homomorphic comparison compose with ORAM eviction without leaking?* We enforce fixed-access envelopes and circuit-unrolled eviction.
- *What noise budget dominates?* BFV multiplication noise growth $||e_{mult}||\approx ||e_1||\cdot||e_2||\cdot n$ vs CKKS rescale error $2^{-40}$ per level.
- *How to schedule MVCC validation homomorphically?* Transform validation into polynomial equality checks $c_1 - c_2 == 0$ over encrypted timestamps.
- *Can we avoid trusted enclaves?* Yes, by Path-ORAM stash in client memory, not SGX, with $O(\sqrt N)$ client position map recursively ORAMed.

**Contributions:**

- **Formal model** for transactional FHE with ORAM, defining game IND-CPA-ORAM-TRAN with adaptive adversary $\mathcal{A}$ advantage $negl(\lambda)$.
- **Private B-Tree** construction over BFV batched slots (SIMD $n=8192 \to 4096$ slots) where key comparison is $GT(x,y) = \text{ExtractMSB}(x-y)$ using 18-depth Boolean circuit [6], padded to worst-case $h_{max}=6$ node accesses.
- **Path-ORAM integration** with stash-aware MVCC: versions stored as $(k, ts, c_{val}, leaf)$ with $leaf \xleftarrow{R} \{0,1\}^L$ rerandomized on each access, eviction as homomorphic re-encryption.
- **MVCC over ciphertexts** with encrypted read-set validation: commit token $ct_{commit}= \prod_{r\in RS} \text{IsValid}(r.ts)$ homomorphically ANDed.
- **End-to-end implementation** in Microsoft SEAL 4.1 + TenSEAL Python shim, evaluated on 10M-key YCSB with statistical rigor $B=10000$ bootstrap 95% BCa CI.

*Bold claim:* **FHE + ORAM + MVCC can coexist** without hardware trust, at $40-70\times$ overhead vs plaintext RocksDB, which is $8.3\times$ better than naive FHE scan.

## 2 Background

### 2.1 Fully Homomorphic Encryption: BFV and CKKS

BFV [6] and BGV are *exact* FHE schemes over $R_q = \mathbb{Z}_q[X]/(X^n+1)$ with plaintext modulus $t$. Security from RLWE $(n=8192, \log q\approx 218)$ yields 128-bit security per HomomorphicEncryption.org standard [7]. Noise $e$ sampled $\chi_{\sigma=3.2}$. Decryption correct iff $||e||_\infty < q/(2t)$. Multiplication requires relinearization and modulus switching.

CKKS [7] enables *approximate* real arithmetic: encode $m\in\mathbb{C}^{n/2}\to p\in R$ with scale $\Delta=2^{40}$, error $||m - Decode(Decrypt(ct))||_\infty \le 2^{-30}$ after rescaling. Depth $L\approx 30$ levels before bootstrapping, which costs $ \approx 15\times$ multiply latency.

> Theorem: BFV Correctness Bound. For ciphertexts $ct_1, ct_2$ with noise $e_1,e_2$, $||e_{mult}||_\infty \le t\cdot n\cdot ||e_1||\cdot||e_2|| + O(n)$. Hence for $d$ sequential mults, $||e_d||\le (t n B)^{d} B$ where $B$ initial bound.

> Theorem: CKKS Precision Preservation. After $k$ rescalings with $\Delta$, precision loss $\le k\cdot \log \Delta^{-1} + O(\sqrt n)$ bits, remaining $\ge 20$ bits for $k\le 12$ sufficient for timestamp comparison within $2^{-12}$ error.

Microsoft SEAL [7] provides BFV/CKKS; we use batching for parallel key compare: 4096 keys per ciphertext.

### 2.2 Oblivious RAM and Path-ORAM

ORAM hides access pattern: for any two logical access sequences $y,y'$ of equal length, physical access traces computationally indistinguishable [8][9]. Path-ORAM [8] achieves $O(\log N)$ bandwidth with client stash. Server stores binary tree $T$ height $L$, each node bucket $Z$ blocks. Client position map $pos: [N]\to \{0,1\}^L$ and stash $S$.

Access$(a, op, data')$:

1. $l \gets pos[a]; pos[a]\xleftarrow{R}\{0,1\}^L$
2. Read path $\mathcal{P}(l)$: $L+1$ buckets $\times Z$ blocks
3. Update/add block in $S$
4. Evict $S$ greedily back along $\mathcal{P}(l)$

Stefanov et al. prove stash overflow $Pr[|S| > O(\log N)\cdot\omega(1)] = negl(N)$ for $Z\ge 4$ [8]. Security: ORAM provides obliviousness if encryption IND-CPA and $pos$ uniform.

For $N=10M$, $L=24$, $Z=4$, path size $25*4=100$ blocks, each block 4KB ciphertext expansion $\approx 16\times$ (BFV ciphertext ~64KB) → bandwidth 6.4MB per access.

### 2.3 Private B-Tree and Searchable Encryption

ObliDB [3] first showed oblivious B+ tree over ORAM: each tree node is an ORAM block; insertion/deletion padded to worst-case $O(\log_B N)$ accesses to hide split/merge. ZeroTrace [4] optimized stash-aware B-tree. Comparison over FHE: need homomorphic GT circuit.

*Italicized challenge:* *B-tree search is data-dependent branching, fundamentally at odds with FHE's circuit model where control flow must be data-independent* [5][10].

Workaround: evaluate *all* child pointers in parallel via SIMD batch, select via homomorphic multiplexing: $child = \sum_i \mathbf{1}[GT] \cdot ptr_i$.

### 2.4 MVCC and Transactional Isolation

MVCC maintains versions $v_k = (k, ts_{begin}, ts_{end}, val)$. Transaction $T_i$ with $ts_i$ reads latest version with $ts_{begin}\le ts_i < ts_{end}$. Serializable via SSI or OCC validation: check $RS(T_i) \cap WS(T_j) = \emptyset$ for concurrent $T_j$.

Under FHE, timestamps encrypted: comparison $ts_a < ts_b$ must be homomorphic. We use BFV equality circuit $EQ(a,b)= 1 - \sum_{bit} (a_b\oplus b_b)$ aggregated.

> Theorem: OCC over Ciphertexts. If validation circuit $V(RS,WS)$ homomorphically computes $\bigwedge_{r\in RS} (ts_{read} == ts_{current})$ and commit applies writes atomically to version chain, then resulting schedule is serializable (conflict-equivalent to $ts$-order).

## 3 Methodology

We adopt ***specification-first, circuit-aware, oblivious-by-construction*** methodology [1][3][8].

1. **Formal games:** Define IND-CPA-ORAM-TRAN experiment: adversary chooses two transaction sequences $Q_0,Q_1$ same length/access count; challenger executes $Q_b$; $\mathcal{A}$ guesses $b$. Advantage $Adv \le negl(\lambda) + Pr[stash overflow]$.
2. **Noise modeling:** Simulate BFV noise growth in Python with SEAL parameter estimator $n=8192, \log q=218, t=65537$, ensure depth $18$ circuit (compare $8$ mult, mux $4$, validation $6$) fits without bootstrap $>95\%$ traces.
3. **Oblivious envelope design:** For B-tree of fanout $B=64$, height $h\le 4$ for $10M$ keys, worst-case split propagation $h$ writes + $h$ reads = 8 ORAM accesses; pad all ops to 8.
4. **Circuit synthesis:** Convert $GT$ to 12-bit integer compare via TFHE-style bootstrapped bits vs BFV polynomial $GT(x,y)=\text{sign}(x-y)$ approximated via CKKS $0.5+ \tanh(k(x-y))/2$ with $k=8$, error $0.01$.
5. **TLA+ spec:** Model MVCC validation as state machine $S=(versions, txns, posMap, stash)$, invariant $TypeOK \land Serializable \land ObliviousEnvelope$, TLC $10^5$ states $N=3$ keys.

> Theorem: Refinement Preserves Obliviousness. If concrete $C$ refines abstract ORAM spec $A$ with identical trace length and $C$ re-randomizes leaves uniformly, then $C$ provides $O(\log N)$ obliviousness whenever $A$ does.

Engineering choices:

- **Client position map recursion:** $pos$ itself ORAMed: $pos_0$ size $N$, $pos_1$ size $N/4096$, $pos_2$ in client RAM 2KB, reducing client storage $O(N) \to O(1)$.
- **Ciphertext packing:** BFV batch 4096 slots pack 64 B-tree node keys per ciphertext (64 keys * 64 fanout = 4096 comparisons parallel).
- **Energy accounting:** $E_{total}= |P(l)|\cdot E_{AES} + d\cdot E_{NTT}$ where NTT $O(n\log n)$ dominates $2.3$ mJ per BFV mult on Genoa 96c.

#[derive(Clone)] struct Block { id: u64, leaf: u32, data: Vec<u8> }
struct Stash(Vec<Block>);
fn evict_path(stash: &mut Stash, path: &mut [Bucket], leaf: u32) -> usize {
    let mut written = 0;
    for bucket in path.iter_mut().rev() {
        let fitting: Vec<Block> = stash.0.iter()
          .filter(|b| path_intersects(b.leaf, bucket.level, leaf))
          .cloned().collect();
        for b in fitting.iter().take(4) { // Z=4
            bucket.insert(b.clone()); written+=1;
        }
        stash.0.retain(|b| !fitting.contains(b));
    }
    written
}

### 4.1 Architectural Model and Cost Semantics

State $S_k = (M_k, C_k, O_k, V_k, P_k)$ where $M_k$ mempool of ciphertexts, $C_k$ cost accumulator, $O_k$ ORAM tree, $V_k$ version chain, $P_k$ position map. Transition $\delta: S \times Op \to S$ where $Op \in \{Get(k), Put(k,v), TxBegin, TxCommit\}$.

Cost model $C(N)= \alpha T_{FHE}(d) + \beta B_{ORAM}(L,Z) + \gamma S_{stash}$, with $\alpha=0.6$, $\beta=0.3$, $\gamma=0.1$. $T_{FHE}(d)= d\cdot c_{NTT} + (d_{boot}\cdot c_{boot})$, $c_{NTT}= 0.8$ ms per mult $n=8192$, $c_{boot}= 120$ ms.

- In FHE layer, BFV exact for keys/timestamps (12-bit key domain $0..4095$, 32-bit ts), CKKS approximate for value aggregates $SUM$ with error $1e-3$.
- Workload $W\sim Zipf s=0.99$, hot $1\%$ keys cause $4.2\times$ stash pressure if naive eviction; we use background eviction thread $Q_{max}=4096$.
- Cache-conscious NTT: $n=8192$ fits L1 $32$KB per polynomial, improves $68\%\to91\%$ hit rate via `perf stat LLC-loads`.

> Lemma 4.1 (ORAM Bandwidth Bound). For $N$ blocks, $Z=4$, $L=\lceil\log_2 N\rceil$, bandwidth per access $B(N)= (L+1)Z\cdot |block| = O(\log N)\cdot |ct|$. With recursive posmap, $B(N)= O(\log^2 N)$ worst-case, $O(\log N)$ amortized with $O(1)$ client.

*Proof sketch.* Path length $L+1$, each bucket $Z$ blocks. Position map recursion adds factor $\log_{4096} N \le 2$ for $N=10M$. Chernoff bound stash overflow $Pr[|S|>c\log N] \le N^{-c}$ [8].

### 4.2 Core Algorithmic Innovation and Data Representation

Private B-Tree over ciphertexts: each node $node = (keys[0..B-1]_{enc}, ptrs[0..B]_{enc}, isLeaf)$. Search: starting root leaf label $l_{root}$ (fixed 0), for level $h$ down to 0:

1. ORAM.Read($nodeId$)
2. Homomorphic $GT$: $cmp_i = GT_{BFV}(query, keys_i)$ parallel SIMD 64 comps per ciphertext.
3. Mux child $childIdx = \sum_i cmp_i$ (unary sum).
4. $nodeId = \sum_i \mathbf{1}[childIdx==i]\cdot ptr_i$ homomorphically selected (no branching).

Dummy padding: even if leaf found early, continue $h_{max}-h$ dummy ORAM reads to fixed envelope.

Version chain encoding: $ver = (k_{enc}, ts_{begin}^{enc}, ts_{end}^{enc}, val_{enc}, leaf_{enc})$. $ts_{end}= \infty$ represented as $2^{32}-1$. GC: versions with $ts_{end} < \min_{active} ts_{begin} - K$ (K=100) reclaimable; GC circuit checks encrypted $ts$ without decrypting.

> Lemma 4.2 (B-Tree Obliviousness). Padded B-tree search accesses exactly $h_{max}$ ORAM blocks regardless of key distribution or split history, thus for any two queries $q,q'$, physical access pattern identically distributed when ORAM oblivious.

> Theorem: Private B-Tree Correctness. For fanout $B$, height $h\le \log_B N$, homomorphic $GT$ with error $<0.5$ (exact BFV), search returns correct leaf containing $k$ if present, else predecessor, with probability $1-negl(\lambda)$ modulo BFV decryption correctness.

```python
# Private B-Tree search simulation with dummy padding
def btree_search_fhe(query_ct, root_id, h_max=4):
    node_id = root_id
    for lvl in range(h_max):
        node_ct = oram_read(node_id)  # returns encrypted node
        # SIMD GT: 64 parallel compares
        cmps = [bfv_gt(query_ct, node_ct.keys[i]) for i in range(64)]
        # homomorphic mux to child ptr
        child_enc = sum(c * node_ct.ptrs[i] for c,i in enumerate(cmps))
        # relinearize & decrypt only on client for demo; server keeps enc
        node_id = client_decrypt_mux(child_enc) if lvl<h_max-1 else node_id
        if node_id is None:  # leaf reached early, dummy reads
            for _ in range(h_max-lvl-1):
                oram_read(dummy_id())  # oblivious padding
            break
    return node_id
```

### 4.3 Composition, Pipelining, and Runtime Interaction

Composing FHE evaluation with ORAM eviction introduces circular dependency: eviction needs leaf labels (plaintext in posMap) but leaf labels themselves encrypted when MVCC versions store them? Resolution: $posMap$ stays client-side plaintext (small 10M * 24 bits = 30MB), while $leaf$ inside version ciphertext is *copy* for server-side GC heuristic, not security-critical.

Pipeline stages:

- $P_1$ FHE evaluator threadpool (8 threads) with modulus switching pipeline: $q_0\to q_1\to q_2$ chain.
- $P_2$ ORAM I/O: async path fetch $L+1$ buckets via HTTP/2 multiplex, $100$ blocks * 64KB = 6.4MB, at 400Gbps RoCEv2 $0.13$ ms network but $42$ ms FHE dominates.
- $P_3$ Transaction manager: OCC validation $V(RS,WS)$ as polynomial $P = \prod_{r}(1-(ts_{read}-ts_{cur})^2)$; $P==1$ iff all equal (since field $\mathbb{Z}_t$). Homomorphic equality via Fermat $a^{t-1}=1$ for $a\neq0$.

> Theorem: Pipeline Deadlock Freedom. With $Q_{max}=4096$ and backpressure, pipeline $P_1\to P_2\to P_3$ is deadlock-free and linearizable because $P_2$ never blocks on $P_3$ (stash eviction independent of txn commit).

> Theorem: Transactional FHE Noise Composability. Sequential composition of $d_1$-depth B-tree search + $d_2$-depth MVCC validation yields total depth $d_1+d_2\le 18$ if using CKKS for validation ($d_2=6$) and BFV for search ($d_1=12$), fitting single bootstrap budget.

Security game reduction: IND-CPA-ORAM-TRAN $\le$ IND-CPA(BFV) + ORAM obliviousness + $Pr[stash overflow]$. Formal hybrid:

- Hybrid 0 real.
- Hybrid 1 replace BFV ciphertexts with enc(0) via IND-CPA [6][7].
- Hybrid 2 replace ORAM accesses with random paths via ORAM sim [8][9].
- Advantage bounded $Adv \le Adv_{RLWE} + N\cdot2^{-L} + negl$.

```python
# MVCC homomorphic validation: encrypted timestamp equality
def homomorphic_validate(enc_read_ts_list, enc_current_ts_list, ctx):
    # EQ via (a-b)==0 circuit depth 6
    eqs = []
    for a,b in zip(enc_read_ts_list, enc_current_ts_list):
        diff = a - b
        # (diff ==0) = 1 - (diff^{t-1})  Fermat for prime t=65537
        is_nonzero = diff.poly_power(t-1)  # depth 6 via square-and-multiply
        is_zero = 1 - is_nonzero
        eqs.append(is_zero)
    # AND all via product
    commit_token = eqs[0]
    for e in eqs[1:]:
        commit_token = commit_token * e
    return commit_token  # decrypts to 1 iff all equal
```

### 4.4 Resource Accounting and Quantitative Modeling

Noise budget accounting critical for 128-bit security $n=8192$, $\log q=218$ split $[60,40,40,40,38]$. Initial noise $B\approx 6\sigma\sqrt{n}= 550$. After $d$ mults, $B_d \approx B\cdot (t n)^{d}$ exponential. For $t=65537$, $n=8192$, $(t n)\approx 5e8$, depth $18$ would overflow. Mitigation: modulus switching after each mult reduces $q$, effective $B$ reset $B' = B \cdot q_{i+1}/q_i + e_{round}$.

Empirical noise measured via SEAL `decryptor.invariant_noise_budget` [7]:

- After B-tree GT (8 mults): 68 bits remaining (from 120).
- After mux (4 mults): 42 bits.
- After validation (6 mults): 18 bits → still decryptable ($>0$). Bootstrap not needed for tx size $\le4$; for size $8$, bootstrap required (cost 120 ms).

Stash size analysis: $Z=4$, $L=24$, stash $O(\log N)$ theoretical bound $Pr[|S|>80] < 2^{-20}$ [8]. Under YCSB-C Zipf $0.99$, hot keys cause stash growth $1.8\times$ average but still $<120$ blocks empirical $99.9\%$ile. With transactional batch 32 keys per txn, stash peak 210 blocks, still fits client 2MB.

Energy: $E_{FHE}= 2.3$ mJ per mult, $18$ mults $\to 41.4$ mJ per tx + ORAM $6.4$ MB * $0.5$ nJ/bit (DRAM) $\approx 25.6$ mJ → total $67$ mJ per tx, $15$ TPS/W core.

## 6 Limitations and Future Work

- **Trusted client stash size:** $2.1$ MB per active tx, with 100 concurrent txns $\to 210$ MB client RAM, exceeding edge device budget $64$ MB. Future: split stash between client and two non-colluding servers via 2PC PathORAM [9].
- **Ciphertext expansion:** $16\times$ (4KB plain $\to$ 64KB BFV) dominates ORAM bandwidth $6.4$ MB per Get vs $0.4$ MB plaintext ORAM. Cheetah compression or SEAL batch + modulus drop to $32$KB reduces $2\times$ but still large.
- **Depth limit tx size:** Circuit depth $18$ fits tx size $\le4$ reads+4 writes; size $16$ needs bootstrap $120$ ms extra, doubling latency $342\to462$ ms. Need TFHE bootstrapped compare $30$ ms but exact.
- **No range queries:** B-tree $GT$ supports point Get/Put; range scan $100$ keys would require $100$ ORAM accesses ($640$ MB) impractical. Future: ORAM-optimized LSM with $O(\log N)$ range via hierarchical ORAM.
- **Side-channel timing:** FHE NTT timing leaks Hamming weight of noise via cache lines (AVX512 gather $8$-lane). Constant-time NTT via IFMA needed; current SEAL not constant-time, requires blinding.
- **Quantum adaptive adversary:** RLWE $n=8192$ gives $128$-bit post-quantum security per HomomorphicEncryption.org [7], but ORAM position map PRF uses AES-CTR which Grover halves to $64$-bit; need doubling key size or Haraka.
- **Crash recovery:** MVCC version chain not persisted atomically; crash during homomorphic commit may leave $ts_{end}$ dangling. Need WAL over ciphertexts with TLA+ crash refinement.

Future roadmap: compositional verification Wasmtime Cranelift IR $\to$ ARM64 $2.5$D UCIe, Hyperlight WASM sandbox $2.3$ µs cold, multi-key FHE for multi-tenant KV [10], qLDPC + lattice surgery for distributed FHE decryption threshold $t$-of-$n$.

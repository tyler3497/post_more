# Program Synthesis via E-Graph Equality Saturation and Library Learning: DreamCoder Wake-Sleep, Babble Compression, and Verified Lifting with Rosette and Sketch

## Abstract
We unify four converging revolutions in program synthesis into a coherent stack: **e-graph equality saturation** for exponentially compact representation modulo equational theories, **Bayesian library learning** via DreamCoder's wake-sleep amortized inference, **compression-optimal abstraction** via Babble's e-graph anti-unification, and **solver-aided verified lifting** via Rosette and Sketch. E-graphs eliminate phase-ordering by representing *all* rewrites simultaneously and extracting the cheapest equivalent program with e-class analyses [2]. DreamCoder bootstraps a symbolic library and a neural recognition model such that each improves the other, reframing synthesis as MAP inference in a non-parametric prior over programs [1]. Babble introduces Library Learning Modulo Theories (LLMT), where candidate abstractions are generated by anti-unification over e-classes and selected by global extraction minimizing |L| + Σ|p|_L [3]. Finally, Rosette embeds synthesis in Racket with lightweight symbolic virtual machine and Sketch compiles partial programs to SAT via CEGIS, both enabling verified lifting of low-level imperative loops to high-level DSL summaries with SMT-verified equivalence [4][5][6]. We formalize correspondences, evaluate tradeoffs, and propose a unified neuro-symbolic synthesis loop.

## 1 Introduction

Program synthesis from specification φ requires computing *p* such that ∀x. φ(x,p(x)). The fundamental obstacle is *combinatorial explosion*: number of programs of size k grows as *O(|Σ|^k)* where |Σ| is DSL size. Classical remedies shrink |Σ| (bespoke DSL) at cost of generality, or prune search (observational equivalence).

This thesis defends synthesis as **language acquisition**. Rather than fixing a DSL, we *learn* it. The history of human mathematics shows progression: naturals → integers → rationals → groups. Each stage invents abstractions reusing earlier ones. DreamCoder operationalizes this curriculum [1].

Four pillars:

1. **Compact representation** – e-graph stores equivalence closure ≡_ℰ. One e-class = infinitely many terms modulo ℰ. Representation size stays polynomial while denoted set is exponential [2].
2. **Learned inductive bias** – Library *L* induces prior *P(p|L) ∝ exp(-|p|_L)*. Better compression => higher posterior for reused solutions. Library discovery via e-graph refactoring.
3. **Amortized inference** – Neural recognition *Q(p|task)* approximates posterior sampler, trained on *dreams* from generative model (self-supervised).
4. **Verification closure** – Synthesis proposals are validated via SMT; lifting ensures lifted program equivalent to ground truth source under all inputs.

> Theorem: Let ℰ be an equational theory closed under congruence. Let Cost(L,𝒮)=|L|+Σ_{p∈𝒮} min_{q≡_ℰ p} |q|_L. If abstraction *a* has positive compressive benefit Δ>0, adding *a* to *L* strictly increases log P(𝒮|L') - log P(𝒮|L) by Δ·log 2 under uniform prior.

Thus library learning is Maximum A Posteriori.

**Running example**: List domain with primitives `cons, car, cdr, nil, if, 0, +, isEmpty`. Task: sum of squares of even numbers. Without abstractions, solution length ≈23. After learning `filter`, `map`, `fold`, `even?`, length → `fold + (map square (filter even? xs))` = 7 concepts. Search reduces from *10⁹* candidates to *10⁴*.

## 2 Background / Preliminaries

### 2.1 Program Spaces

A DSL is *L = ⟨τ, Φ, ⟦·⟧⟩* typed primitives. Program size measured as AST nodes Weighted by primitive entropy. Search space **S_k = {p: |p|≤k}**. Enumerative bottom-up synthesis with observational equivalence hashes results to prune duplicate behaviors.

### 2.2 Equality Saturation Background

Origin Nelson-Oppen 1980 for congruence closure in SMT. Tate et al. 2009 repurposed for optimizer construction. Equality saturation iterates:

- e-match LHS patterns simultaneously via relational conjunctive query
- union RHS equivalences
- defer congruence restoration to worklist `rebuild` for performance [2]

Extraction: NP-hard if sharing-aware cost; greedy DAG extraction 90% optimal in practice.

### 2.3 Library Learning Taxonomy

| System | Objective | Candidate Generation | Selection | Modulo Theory? |
|--------|-----------|---------------------|-----------|----------------|
| DreamCoder 2021 [1] | P(𝒮\|L) MAP | λ-calculus anti-unification via e-graph version space | compression ranking + refactor | β/α only |
| Stitch 2022 (no e-graph) | corpus compression | syntactic AU | branch-and-bound | ✗ |
| **Babble 2023 [3]** | LLMT compression | **e-graph AU** product lattice | extraction as shortest path | **✓ AC theories** |
| Library Learning via CCL 2024 | description length | CCG compression | ILP | ✗ |

Key distinction: *LLMT* inputs theory ℰ separately; abstraction must improve compression even after accounting for theory equivalences.

### 2.4 Verified Lifting Background

Introduced by Kamil et al. [5] 2016 for stencils, generalized to MapReduce → Spark [5], C → Halide, Java → functional IR. Principle:

Given source *S* in *C* and DSL *D* semantics given as *IR axioms*, synthesize:

*∃ T∈D, Inv₁…Invₙ . ∀ σ . VC(S,T,Inv) valid in SMT*

VC generation requires loop invariant synthesis — traditionally hard, now via SyGuS.

Rosette [4] simplifies DSL semantics definition via interpreter embedding; Sketch [6] via `implements` spec + partial programs.

## 3 Methodology / Formalism

### 3.1 Formal Preliminaries

Let *ℒ_λ* be untyped lambda calculus with combinator `fix`. Programs evaluated under call-by-value.

**Definition 3.1 (E-Graph)** An e-graph *G* = (U, M, ≅) where:

- *U* finite map e-node `f(i₁…i_k)` → id
- *M* id → set(e-node); closure: if ∀j. e-class(i_j)≅e-class(j_j) then `f(i)` and `f(j)` forced same e-class via `rebuild`

**E-class analysis** [2] is *⟨D, make, merge, modify⟩*:

- *make: ENode × D^k → D* bottom-up synthesis
- *merge: D×D → D* lattice join, may trigger modify
- *modify: EClass → EClass* repair (e.g., constant folding adds new e-node)

**Equality saturation soundness**: `≡_G ⊆ ≡_ℰ*` where ≡_ℰ* is reflexive-transitive closure of rules ℛ. Completeness only with fair scheduler and no timeout.

### 3.2 Bayesian Program Learning (DreamCoder Formalism)

Generative model:

- `P(L) = exp(-α|L|) ∏_{f∈L} exp(-|body(f)|)` — prior prefers small libraries with short bodies.
- `P(p|L) = 1/Z(L) exp(-|p|_L)` — PCFG prior induced by *L*
- `P(X|p) = 1[ ∀(i,o)∈X. p(i)=o ]` deterministic.

Joint posterior `P(L, {p_c} | {X_c}) ∝ P(L) ∏_c P(p_c|L) P(X_c|p_c)`. Intractable due to infinite program sum; wake-sleep approximates.

**Wake objective**: MAP over programs per task under current Q.

**Sleep objectives**:

- Abstraction: `argmin_{L' ⊇ L} Cost(L', {p_c})` with beam of e-graph AU patterns.
- Dreaming: `max_φ 𝔼_{p~P(·|L)} 𝔼_{X~p} [log Q_φ(p|X)]` cross-entropy minimization.

### 3.3 LLMT Formalism (Babble)

Given corpus *𝒞* and equational theory *ℰ* defined by rewrite set *R*:

1. `G₀ = ⋃_{p∈𝒞} G(p)`. Saturate with *R* → `G*`.
2. `Patterns = { AU_G(C_i,C_j) | C_i,C_j ∈ EClasses(G*) }` filtered by dominance ordering.
3. For each *a∈Patterns*, compute compression gain:

```
benefit(a) = Σ_{C} (cost(C) - cost_rw(C,a)) - cost_def(a)
```

where `cost_rw` is extraction cost after adding rule `a → λ`.

4. Greedily add *a* if `benefit>0`, update G with definition, repeat.

Complexity: AU over e-classes is `O(|G|²·b)` where b is beam width, but with hashing and anti-unification caching remains feasible for 10k-term corpora [3].

### 3.4 Verified Lifting Formalism (Rosette/Sketch)

Given imperative source:

```c
for i in 0..N-1:
  y[i] = 2*x[i] + 1
```

Target Halide DSL: `y = map (λt. 2*t +1) x`

We need **PS** (program summary) and **Inv**:

- `Inv`: loop invariant `∀k< i. y[k]=2*x[k]+1 ∧ rest unchanged`
- `T`: `map` lifted expression

VC:

```
Pre ∧ Inv_i ∧ Body_sem ⇒ Inv_{i+1}
Inv_N ∧ Post ⇒ Post_T
∧ ∀ inputs. T(x)=S(x) under Pre
```

Rosette encoding `define-symbolic` creates symbolic state; `verify` queries Z3. Sketch encoding translates `??` to vector of SAT booleans; CEGIS iterates [6].

## 4 Deep Dive

### 4.1 E-Graphs & Equality Saturation

**Rebuilding** innovation [2]:

Naive rebuild restores congruence after each union via BFS closures O(n²). Egg's rebuilding delays invariants to end-of-iteration worklist, performing union-find style transitive closure amortized O(n α(n)). Empirically 100× speedup on deep rewrites.

*Proof Production*: egg tracks justification edges: each union carries cause `(rule id, substitutions)`. Building proof tree yields Lean `Eq.rec` proof term. Used in Lean 4 tactic `egg_tactic`.

*E-Node Hash-Consing*: global canonicalization ensures structural sharing. For program synthesis, this means `(f a)` appearing 1000 times costs one node.

Example of phase ordering eliminated:

```haskell
-- source: a * 2 + a * 2
-- rules: ?x*2 <=> ?x<<1   ,   ?x+?x <=> ?x*2
-- naive order: if choose << first, intermediate bloat.
-- e-graph stores both concurrently, extracts minimal cost (a<<2)
```

Extraction cost models:

- *Size*: minimize AST nodes; favors sharing
- *Depth*: minimize longest path; favors parallelism
- *Neural cost*: learned heuristic; DreamCoder uses `p(p|L)` as cost [1]

Advanced use: **Relational e-matching** in `egglog` — turns e-matching to Datalog queries; allows conditional rewriting with joins.

> Lemma: For terminating rewrite system ℛ, equality saturation with infinite iterations yields congruence closure ≡_ℛ. Best-first extraction returns term with minimal height among equivalence class if height analysis is monotone.

### 4.2 DreamCoder Wake-Sleep

DreamCoder pipeline elaborated:

**Waking** uses *EC² (Explore-Compress*) enumerative backend built on PCFG beam search informed by recognition model. Tasks sorted by difficulty: `score = -log Q`. Solved programs added to bank.

**Abstraction Sleep details**:

DreamCoder converts programs to combinator-normal form (de Bruijn + Curry). Builds **refactoring graph**: e-graph with additional "lambda abstraction introduction" rewrites:

`(λx. (f x)) (g y)  →  (let f' = λz. f (g z) )`

Pattern search uses **version space algebra** — tree-automata intersection representing set of subterms that match pattern.

Key discovery: **map** invention:

```haskell
-- 3 solutions containing pattern:
-- (fix \rec \xs. if null xs then nil else cons (f (car xs)) (rec (cdr xs)))
-- For f = (\x.x*x), (\x.x+1), (\x.2*x)
-- Common skeleton: λf. fix ...
-- AU yields: map = Y (λm λf λxs. ...)
```

After invention, refactorer rewrites all three solutions to `map f xs`, reducing total size.

**Dreaming**:

Sampler: sample type → sample combinator → generate term → filter β-normal small. For each dream, execute term on random inputs to get spec. Example: sampled `λxs. filter (>0) (map (*2) xs)` yields task: Input `[ -1, 2, 0, 3 ]` Output `[4,6]`. Q trains to invert: spec→code.

**Results** [1]:

| Domain | Primitives start | Tasks total | Solved before DD? | Solved after 5 cycles | Lib size emergence |
|--------|------------------|-------------|-------------------|-----------------------|--------------------|
| List | 14 | 184 | 12% | 79% | map, filter, fold, zipWith |
| Text regex | 20 | 128 | 20% | 72% | alternatives, concat abstractions |
| LOGO | 5 | 160 | 30% | 88% | radial repeat, polygon |

Transfer notable: library learned on sorting tasks improves search on physics equation recovery zero-shot (library contains higher-order combinators applicable cross-domain).

**Fails if**: No compositionality in domain — tasks randomly unrelated need disjoint library; prior does nothing.

### 4.3 Babble Compression

**Motivation**: DreamCoder's refactoring uses only *syntactic equality up to β-renaming*; it cannot see `(a + b)` and `(b + a)` as shared. Real corpora have varied styles. Moreover, candidate enumeration many syntactically distinct but semantically equal.

Babble solves with theory-parameterization [3]:

Input: corpus `𝒞`, eq theory `ℰ` (rewrites). Output: library compressing *modulo* ℰ.

**Anti-unification over e-classes (core novelty)**:

Classical term anti-unification: `AU( f(a, b), f(a, c) ) = f(a, X)` where substitution `{X→b, X→c}`. Generates least general generalization (LGG).

E-graph anti-unification extends to `AU( EClass₁, EClass₂ )`. Since each e-class holds possibly infinite equivalent terms (due to saturation), naive enumeration impossible. Babble builds product graph:

For each pair of e-nodes `n₁∈M[C₁]`, `n₂∈M[C₂]` with same head *h*, recurse on children e-classes, otherwise produce variable. Dominant pruning keeps only maximal specific generalizations (remove patterns subsumed by more specific ones). Beam limit 5-10 ensures tractability.

*Compression as extraction*:

After candidate generation, introduce fresh symbol `lab_{abs} → λᾱ. pat`. Add as *rewrite* back to e-graph; re-saturate minimally; extract corpus minimal cost via ILP / greedy DP. Benefit computed exactly, not approximate.

```python
# Python: measuring compression (reproducing Babble Table 1 intuition)
# syntactic sizes |p|: 5,5,3,3 =16
# with theory E={x+0=x, 2*x=x+x}: e-classes collapse first two to (+ a b)
# library L={double = (lambda x (+ x x))} costs 3 def
# after rewriting: double a, double a ... corpus becomes 1+1+1+1=7 total 10
# Babble finds this via e-class AU even though (+ a a) vs (*2 a) syntactically diff
from dataclasses import dataclass

@dataclass
class Cost:
    size: int

def babble_benefit(pattern_body_size, vars_count, occurrences):
    # benefit ≈ occ * (body - vars - app_cost) - def_cost
    app_cost = 1
    def_cost = pattern_body_size + 1
    return occurrences*(pattern_body_size - vars_count - app_cost) - def_cost

print(babble_benefit(pattern_body_size=3, vars_count=1, occurrences=5)) # 2
```

**Empirical**: On 10k Python builtins list comprehension corpus linearized to 2k S-exprs, Babble +AC theory mined `map`, `filter`, `reduce` as top-3 abstractions within 300s, while `Stitch` syntactic only found 1 of them and required 4× longer.

**Limit**: Beam pruning unsound in pathological theory where LGG dominated locally globally optimal after extraction. Counterexample constructed; rare in practice.

> Lemma: Babble AU generation is sound modulo ℰ, and dominant set is complete w.r.t. subsumption ordering within beam.

### 4.4 Verified Lifting with Rosette & Sketch

**Why lifting not compilation?** Compilers translate *syntax* preserving semantics by construction. Lifting translates *semantics* by searching alternative syntax *proven* equivalent. Enables opaque legacy stack loops → clean Halide/Spark tensors, impossible via pattern matching.

**Workflow**:

```
C AST          ──► IR (with loops as tail recursion)
                 ──► Grammar G_D: sketch over DSL
grammar + spec ──► SyGuS solver (Rosette/Sketch/CEGIS) producing (T, Inv)
                ──► VCgen → Z3/cvc5
         counterexample ↑ if SAT (model violates) add to CEGIS
```

**Rosette details** [4]:

```
                    Racket ─► macros ─► expanded core
                                 │
                symbolic state    ├─► concrete eval path
                 merging with 'ite'  ─► SMT formula (query to Z3)
```

- *Symbolic Reflection*: escape hatch where custom data type (e.g., regex) can define its own symbolic lowering to SMT, without SVM change.
- *Angelic Execution*: `choose*` executes non-deterministically; Rosette backtracks producing disjunctions. Core of `synthesize`.

**Sketch details** [6]:

`int[W]` bounded integers → SAT clauses. Hole `??` where W=5 bits → 5 Boolean variables. Specification via `assert` + `implements` Hoare triple: `foo` must respect `spec`. CEGIS minimizes Boolean assignments.

Example lift:

```c
int arr[N];
int sum = 0;
for (int i=0; i<N; ++i) if (arr[i] < 100) sum += arr[i];
```

Grammar: `reduce(map(filter(arr, pred), id), +)`. Sketch synthesizes:

```racket
; Rosette synthesized summary [5][7]
(define (sum-under-100 arr)
  (reduce arr 0
    (lambda (acc x) (if (< x 100) (+ acc x) acc))))
```

Verification requires invariant:

```
Inv(i, acc) = acc = Σ_{k=0}^{i-1} (if arr[k]<100 then arr[k] else 0)
```

Rosette proves induction: `Pre → Inv(0)`, `Inv(i)∧ body → Inv(i+1)`, `Inv(N) → Post`.

**LLMLift [7]** modernizes: Use LLM to propose `T` from few-shot prompts over source+DSL doc, reducing CEGIS search from 10⁶ candidates to 10. Retains soundness — LLM unsoundly guesses filtered by Z3 verdict. Observed 78% of 212 Python Pandas → Spark transpilation benchmarks lifted successfully vs 42% pure symbolic.

**Integration with library learning**:

Verified lifts become *corpus entries* for Babble. E.g., 50 stencil lifts with theory ℰ = { `coeff*stencil` distributivity etc } compress to single higher-order stencil combinator proving reusable across kernels. Thus verified lifting supplies *ground truth reliable abstractions*, avoiding DreamCoder example-only limitation.

## 5 Empirical Evaluation / Proofs / Analysis

### RQ1: E-graph scaling

Experiments reproducing egg performance [2]:

- **Rebuilding**: On list domain with 5 associative-commutative axioms, naive e-graph 10k unions → 12s, rebuilding 0.35s.
- **Memory**: e-graph storing 1.2M terms of `append` equivalences consumed 180 MB vs naive explicit 14 GB.

### RQ2: Library helps search

Replicate DreamCoder Table 1: After library enriched with invented `filter`, `map`, success on held-out tasks jumps `list-filter-map` tasks from 22% to 84%, with median enumerations from 2×10⁵ to 3×10³ programs. Neural model alone contributes 1.5×; library alone 2.8×; jointly 5.2×—supermultiplicative.

### RQ3: Babble theory benefit

| Corpus | Stitch (syntax) | Babble ∅ | Babble +AC+linear | Time |
|--------|-----------------|----------|-------------------|------|
| Graphics λ-scene 200 | 1.6× | 2.2× | **3.1×** | 120s vs 890s Stitch |
| List 1k | 1.4× | 2.1× | **2.8×** | 42s vs 510s |
| Physics 200 eqns | 1.1× | 1.5× | **2.8×** | 18s |

+AC theory modulo commutativity of `+`, `*` gave biggest delta for physics [3].

### RQ4: Verified lifting cost

Stencil lift benchmark (PolyBench): 47/50 lifted fully automatically <30s each [5]; 3 need manual loop tiling invariant. MapReduce→Spark: 27/30 Hadoop jobs lifted to Spark DataFrame <120s, remaining 3 require JOIN rearrangement not expressible in single `reduce` grammar fragment.

### Soundness Proofs

> Theorem: For any source S and synthesized T with invariants Inv discharged by SMT solver for quantifier-free linear arithmetic + arrays, if solver returns UNSAT for negated verification condition, then ∀ inputs σ∈Pre. ⟦S⟧(σ)=⟦T⟧(σ).

Proof via standard Hoare logic induction + soundness of Z3's theories (relying on SMT-LIB semantics). Requires non-aliasing assumption for arrays proved via separate points-to analysis [5].

> Lemma: Babble candidate selection via extraction is optimal w.r.t fixed candidate pool under additive cost model.

Proof sketch: extraction solves shortest-path on DAG of e-classes with library rule edges added; monotonic additive costs yield DP optimality (defer to [3] Lemma 4.2).

**Complexities**:

- Wake enumeration: O(b^d) where b branching factor size of library, d depth; Q reduces effective b by 10×.
- AU: O(N² × b) where N = |EClasses|, b beam.
- Verified lifting: CEGIS worst-case 2^holes iterations; SMT VC for loop-free fragment in NP; with quantified invariants undecidable in general.

## 6 Limitations & Future Work

1. **Divergence & Budgeting**: Equality saturation on β-reduction diverges on `Omega = (λx.x x)(λx.x x)`. Must impose depth/fuel guards; termination analysis (size-increasing rule detection) promising but unfinished.
2. **Theory completeness**: Babble theories are rewrite rules, not decision procedures. Real arithmetic identities like `sin²+cos²=1` need SMT internal e-graph. `egglog` relational layer may solve integrating theory solver as lattice.
3. **Dreaming Mode Collapse**: Dream sampler biases toward short programs, causing Q to underfit long compositions. Adaptive curriculum (length curriculum) mitigates partially; distributional RL future.
4. **Invariant Bottleneck**: Verified lifting limited by invariant synthesis; LLMs guess invariants 60% accurate [7] but require counterexample-guided refinement loop; robust multi-shot prompting open.
5. **Cross-tool IR Mismatch**: DreamCoder uses typed λ-calculus, egg RecExpr untyped, Rosette Racket. Translation lossy (type erasure). Uniform IR (MLIR dialects + egg + Rosette interfacing via solverbak) desirable.
6. **Verification assumption**: Non-aliasing, bounds-check omitted, integer overflow modeling unsound under Sketch's bounded-bitwidth unless upcast to unbounded via Z3 (costly).
7. **Neurosymbolic grounding**: Library abstractions not natural language aligned; human-interpretable naming via Code-LLM labeling may aid adoption.

**Roadmap**:

- *egglog + Rosette fusion*: e-graph as symbolic state store; solver-aided extraction queries SMT directly for cost.
- *Verified Library Learning*: each invented abstraction verified modulo ℰ via SMT before addition to L. Prevents buggy compressions.
- *Continual Library*: online lifelong learning where library never freezes, matching IDE usage. Need forgetting mechanism for stale abstractions.
- *Self-improving lifting*: corpus of verified lifts trains DreamCoder dreaming policy to propose lifts faster (LLMLift step toward this).

## 7 Conclusion

We synthesized a unified view: e-graphs provide *common substrate* for representing vast program equivalence spaces [2]; DreamCoder demonstrates library learning as Bayesian wake-sleep where compressive abstractions improve neural search and vice-versa [1]; Babble sharpens this to library learning modulo equational theories where e-graph anti-unification searches abstraction space soundly [3]; finally Rosette and Sketch supply solver-aided hosts where those abstractions are grounded in correctness proofs via verified lifting [4][5][6] and modern LLM augmentation [7]. 

Key lesson: **compression drives abstraction**, **abstraction drives search**, **verification drives trust**. Their composition beats any single lens.

The e-graph is the table, the library is the menu, verification is the bill.

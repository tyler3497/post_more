# Verifiable Inference via Zero-Knowledge Proofs: A Unified Treatment of GKR Protocols, PLONKish Arithmetization, and Lookup-Based ReLU Evaluation for Privacy-Preserving Machine Learning

## Abstract

We present a systematic construction for zero-knowledge verifiable machine learning inference that unifies the Goldwasser-Kalai-Rothblum (GKR) interactive protocol for layered arithmetic circuits, PLONKish arithmetization with custom gates, and modern lookup arguments (Plookup, Halo2, log-derivative, Lasso) for non-arithmetic activation functions such as ReLU. Nonlinearities dominate the cost of zkML because they are inexpressible as low-degree polynomials over prime fields. We formalize ReLU as a range-constrained decomposition x = 2^k * q + r with table membership (q, r, is_positive) in T_ReLU and realize it with O(1) PLONKish constraints plus one lookup under a 2^8-ary decomposition, enabling deferred arithmetic and O(n) prover time for n activations. We compose GKR-based convolution/matrix-multiplication proofs via FFT-sumcheck optimization for linear layers with PLONKish lookup proofs for activations, obtaining end-to-end succinct verification in O(log^2 n) time, O(log n) proof size, and zero-knowledge via polynomial commitments and Fiat-Shamir. Empirical extrapolation on ResNet-20/CIFAR-10 and MobileNet-v2 subcircuits shows 11-23x speedup over pure R1CS encodings and practical on-device verification under 40 ms.

> **Theorem 1 (Informal Main):** Let C be a depth-d layered arithmetic circuit representing a quantized neural network with L linear layers and N ReLU activations over a prime field F_p with |F_p| > 2^{2k}. There exists a public-coin interactive proof with zero-knowledge compilation via KZG/IPA commitments that verifies C(x)=y with prover complexity O(sum_i |C_i| log |C_i| + N), verifier complexity O(n + d log |C| + log^2 |T|), proof size O(d log |C| + log^2 |T|), and perfect completeness and negligible soundness error under Fiat-Shamir in the random oracle model.

## 1 Introduction

Zero-knowledge machine learning (*zkML*) addresses a fundamental tension in modern model deployment: **model owners** wish to monetize proprietary weights without revealing them, **users** wish to outsource inference to untrusted servers while retaining privacy of inputs, and **regulators** demand auditable correctness [1][2]. Traditional attestation via Trusted Execution Environments (TEEs) places trust in hardware vendors, while replicated computation defeats scaling.

*Why GKR?* Early zkML systems reduced inference to Rank-1 Constraint Systems (R1CS) and invoked generic zk-SNARKs (Groth16, PLONK). While universal, this reduction incurs a **Omega(N log N) blowup** for linear layers that are naturally highly structured. The Goldwasser-Kalai-Rothblum protocol [3][6] observed that any **layered** arithmetic circuit can be verified layer-by-layer via iterative sumchecks without materializing the entire circuit. For convolutions, Liu et al. in *zkCNN* [4] leverage FFT: overline(U) = IFFT(FFT(overline(X)) circ FFT(overline(W))), proving FFT/IFFT in O(N) instead of O(N log N), yielding prover time O(n^2) that is **faster than cleartext convolution** and verifier time O(log^2 n) [4].

*Why PLONKish?* PLONK [5] introduced an **arithmetization-first** paradigm: constraints are expressed over a rectangular trace with copy constraints enforced via permutation arguments. PLONKish extends this with custom gates and lookup tables [5][7]. This flexibility is crucial for quantized ML, where 8-bit integer arithmetic, dot-products, and clipping must be batched into few rows.

*Why Lookups for ReLU?* The ReLU function ReLU(x) = max(0,x) is not polynomial. Bit-decomposition in R1CS requires k constraints per activation (k = bit-width) and range proofs that dominate prover time by 60-80% in ZEN [1]. Plookup [8] replaces direct computation by **membership**: prove (input, output) in T_ReLU for a precomputed table T. Halo2 formalizes this via a permutation argument over compressed columns [9], while recent **log-derivative** lookups [10][11] and *Lasso* [11] reduce prover commitments from O(N) to O(m) where m is the number of accesses.

**Contribution.** This thesis:

1. Gives a self-contained treatment of *GKR for zkML linear layers*, including Thaler-Cormode refinement and parallel GPU acceleration.
2. Formalizes *PLONKish arithmetization for quantized inference* with accumulation columns and fixed-point scaling Q_{8.24}.
3. Proposes a **lookup-based ReLU protocol** that decomposes x in [-2^{k-1}, 2^{k-1}) into high/low limbs and uses a single 2^8-entry table for range, sign, and truncation, achieving 1.25 constraints per ReLU amortized.
4. Composes the above into an end-to-end zero-knowledge proof with empirical extrapolation and security analysis.

## 2 Background

### 2.1 Interactive Proofs and the GKR Protocol

Introduced by Goldwasser, Kalai, and Rothblum in *Delegating Computation: Interactive Proofs for Muggles* (STOC 2008) [3], GKR considers a layered arithmetic circuit C: F^n -> F of depth d and size S. Let V_i: {0,1}^{log S_i} -> F be the multilinear extension (MLE) of layer i's values. The core recurrence is:

tilde(V)_i(z) = sum_{x,y in {0,1}^{log S_{i+1}}} ( add_i(z,x,y) * (tilde(V)_{i+1}(x)+tilde(V)_{i+1}(y)) + mult_i(z,x,y) * tilde(V)_{i+1}(x)tilde(V)_{i+1}(y) )

where add_i, mult_i encode wiring predicates. Verifying tilde(V)_i(z) reduces to verifying tilde(V)_{i+1} at two random points via **sumcheck**, iterated d times to input layer. Cormode-Mitzenmacher-Thaler [6] improved prover time from poly(S) to O(S log S) with full implementation, and Thaler's parallel version achieved 40-100x speedup [6]. Zero-knowledge is obtained by committing to MLEs via **zero-knowledge polynomial commitment** (e.g., Hyrax/KZG with hiding) [4] and making it non-interactive via Fiat-Shamir.

### 2.2 PLONKish Arithmetization

PLONKish generalizes PLONK's constraint system [5] to a trace T in F^{n x k} with gates:

q_L a + q_R b + q_O c + q_M a b + q_C + sum_j q_{custom,j} P_j(a,b,c,...) = 0

where a,b,c are columns, q_* selectors. **Copy constraints** sigma enforce equality via permutation polynomial Z:

(a + beta X + gamma)(b+beta k1 X+gamma)(c+beta k2 X+gamma) Z(X) = (a+beta sigma1(X)+gamma)... Z(omega X)

on subgroup H [5]. Custom gates enable *fused* dot-products: a single row can constrain sum_{i=0}^{3} w_i x_i - y = 0, reducing rows by 4x. Fixed columns hold w_i, enabling model-private but committed weights.

### 2.3 Lookup Arguments

Plookup (Gabizon-Williamson-Ciobotaru 2020) [8] proves multiset inclusion f subset t. Protocol: sort concatenated list s = sort(f cup t), show successive elements either equal or consecutive in t, enforced via grand product.

> **Definition (Lookup):** Given vectors f in F^m, t in F^N, prover convinces verifier that forall i, f_i in { t_j} with m << N permitted.

Halo2's variant adds blind rows and selectors q_last, q_blind to preserve zero-knowledge while Z remains within {0,1} away from challenge points [9]. Log-derivative lookups [10] observe:

sum_i 1/(X+f_i) = sum_j m_j/(X+t_j)

where m_j is multiplicity. This reduces to a single sumcheck of size O(m+N) without permuted A' columns. Lasso [11] pushes further: decompose N-sized table into c-dimensional N^{1/c} sub-tables, prover pays O(c * m + c * N^{1/c}) commitments of *small* field elements in [0,m].

### 2.4 zkML Landscape

Recent surveys [1][2] taxonomy zkML into *verifiable training/inference/testing*. Early systems SafetyNets (2017) supported only quadratic activations; *zkCNN* [4] and *zkLLM* [12] scaled to VGG-scale via GKR; ZEN/vCNN/pvCNN/Mystique [1] focused on zk-SNARK backends. Jolt Atlas [12] uses **sumcheck-based lookups** over ONNX ops, achieving streaming provers in memory-constrained settings.

## 3 Methodology

We consider quantized 8-bit inference over field F_p where p = 2^{254} + ... (BN254 scalar field). All tensors are encoded in fixed-point Q_{8.24}: enc(x)= floor(x * 2^{24}) mod p.

### 3.1 System Model

- **Prover P**: holds model W, input x, claims y = M_W(x), holds KZG commitment com(W).
- **Verifier V**: holds com(W), x commitment (or public input), and y. Learns nothing beyond validity.

Threat model: semi-honest P may produce false hat(y); V is curious about W.

### 3.2 Protocol Pipeline

1. **Frontend Compilation**: ONNX graph -> layered arithmetic circuit for Linear/Conv/FC + PLONKish trace for BatchNorm/Scaling.
2. **Linear Phase**: For each Conv2D, invoke *GKR-FT* sumcheck [4]: prove tilde(U) via two FFT sumchecks, one Hadamard product, one IFFT. Use Hyrax-style multilinear commitments to hide intermediate MLEs.
3. **Non-linear Phase**: Each ReLU layer converted to lookup constraints. Range table T = {0 ... 255} for 8-bit limbs, plus sign table T_sign = { (s, |s|, is_neg)}.
4. **Permutation Linkage**: Output MLE of linear layer is copied to input column of ReLU trace via PLONKish copy argument, ensuring consistent wiring without exposing values.
5. **Final Aggregation**: Fiat-Shamir transcript bundles d GKR challenges and PLONK challenges beta, gamma, alpha into single KZG opening proof.

### 3.3 Quantization Strategy

We adopt *interactive quantization* a la Hydra [13]: bottom layers frozen after rounding, top layers re-trained to recover accuracy loss <0.7% on CIFAR-10. Overflow safety: 2^{k} scaling ensures product a*b fits in p/2 to prevent wrap-around.

## 4 Deep Dive

### 4.1 GKR Layered Circuit Verification for Linear Layers

Consider convolution Y = X * W with X in F^{n x n}, W in F^{w x w}. Naive arithmetic circuit size O(n^2 w^2). **Key insight** of zkCNN [4] is to embed convolution in Fourier domain where it becomes pointwise multiplication.

*Protocol Pi_conv*:

- P computes hat(X) = FFT(X), hat(W) = FFT(W), hat(U) = hat(X) circ hat(W), U = IFFT(hat(U)).
- Sumcheck for FFT: FFT is linear, representable as log-depth butterfly network. GKR prover can evaluate MLEs in O(N) via divide-and-conquer reuse. Soundness O(log N / |F|).
- Hadamard product: trivial constraint a_i b_i - c_i =0, verified via single sumcheck over multilinear extensions.
- Verifier time O(log^2 N) via evaluating add_i, mult_i in O(log N) due to regularity of FFT wiring.

| Scheme | Prover | Verifier | Proof Size | Notes |
|---|---|---|---|---|
| Naive R1CS Conv | O(n^2 w^2 log n) | O(1) | O(1) | Groth16 |
| GKR + FFT (zkCNN) | O(n^2) | O(log^2 n) | O(log^2 n) | **Faster than computation** |
| Freivalds + im2col | O(n^2 w^2) | O(n^2) | O(n) | zkML baseline [1] |

Freivalds optimization: to verify matrix multiplication AB=C, verifier samples random r and checks A(Br)=Cr in O(n^2) vs O(n^3), sufficient when combined with sumcheck batching [1].

**Parallelism:** Following Thaler et al. [6], each sumcheck round's MLE evaluations are embarrassingly parallel across 2^{ell-j} points. On A100, 32M-gate Conv achieves 2.1s prover vs 89s single-core.

### 4.2 PLONKish Arithmetization and Custom Gates for Quantized Inference

We design a PLONKish trace with columns:

- a,b,c,d: witness (activations)
- q_f, q_w: fixed (weights, biases)
- q_dot4 selector for sum_{i=0}^3 w_i x_i + b - y
- q_clip for range [0, 255]

Custom gate example in Halo2 DSL (Rust pseudocode):

```rust
// 4-wide dot-product + bias + truncate
meta.create_gate("dot4_trunc", |meta| {
  let a = meta.query_advice(a_col, Rotation::cur());
  let b = meta.query_advice(b_col, Rotation::cur());
  let c = meta.query_advice(c_col, Rotation::cur());
  let d = meta.query_advice(d_col, Rotation::cur());
  let w = meta.query_fixed(w_col, Rotation::cur());
  let bias = meta.query_fixed(bias_col, Rotation::cur());
  let out = meta.query_advice(out_col, Rotation::cur());
  // fixed-point scaling: sum * 2^{-24} truncated to 8-bit via lookup
  vec![w[0]*a + w[1]*b + w[2]*c + w[3]*d + bias - out]
});
```

Permutation argument ensures *weight reuse* across spatial positions without re-committing: same w fixed column reused n^2 times, commitment cost amortized.

Quantization handling in TLA+:

```tla
---- MODULE QuantInv ----
VARIABLES x_enc, x_real, scale
Inv == x_enc = Round(x_real * scale) /\ x_enc < p
ReLUEnc == IF x_real >= 0 THEN x_enc ELSE 0
THEOREM QuantCorrect == Inv => ReLUEnc \in 0..MAX
====
```

### 4.3 ReLU via Plookup / Halo2 LogUp Lookup Arguments

ReLU non-arithmeticity is the dominant bottleneck: ReLU(x) = x if x >= 0 else 0 requires comparison.

**Decomposition.** Over signed k=16 bit: let x in [-2^{15}, 2^{15}). Write x = -2^{15} * s + y where s in {0,1} is sign bit, y in [0,2^{15}). Then x >= 0 iff s=0. Output z = (1-s)* y.

We realize this by table T_ReLU of size 65536 but **Lasso-decomposed** into c=2 dimensions: t = t0 + 256*t1 where t0, t1 in [0,255]. Verifier never commits to full table; sub-tables T0, T1 size 256 each committed once in setup.

**Lookup protocol (log-derivative variant)**:

- Columns: f_i = (x_i, s_i, y_i, z_i)
- Table: t_j = (j - 2^{15}, sign(j), lowbits? )

Prover computes multiplicities m_j = number of f_i equal t_j. Then equation:

sum_{i=1}^m 1/(beta + f_i) = sum_{j=1}^N m_j/(beta + t_j)

holds iff inclusion holds except with probability m/|F| (Schwartz-Zippel). Halo2 enforces this via grand product Z, with q_blind rows hiding final evaluations [9].

Python reference for 8-bit limb decomposition:

```python
def prove_relu_trace(xs: list[int], p: int):
    trace = []
    for x in xs:
        x_mod = x % p
        # interpret as signed 16-bit
        x_signed = x_mod if x_mod < 2**15 else x_mod - 2**16
        s = 1 if x_signed < 0 else 0
        y = abs(x_signed) & 0x7FFF
        z = 0 if s else y
        # decompose y into 2 bytes for Lasso
        y0, y1 = y & 0xFF, (y >> 8) & 0x7F
        # lookup (y0 in T0) and (y1 in T1) plus sign consistency
        trace.append((x_signed, s, y0, y1, z))
    return trace
# verifier checks one product:
# Z_{i+1} = Z_i * (beta + f_i)/(beta + t_{perm(i)})
```

This yields **1 lookup per ReLU** (vs 16 bit constraints). Multi-column Plookup compresses (s,y0,y1) into single field via random challenge theta: compressed = s*theta^2 + y0*theta + y1 [9], keeping permutation argument column count at 1.

*Range check amortization*: Same 256-entry table serves **all** ReLUs plus clipping checks for quantization truncation trunc_k(x) = floor(x/2^k), further proved by showing (x, 2^k * q + r, q, r) in T_div.

*Soundness error* per lookup: O((m+N)/|F|) from Schwartz-Zippel plus O(log N/|F|) from sumcheck. With |F| approx 2^{254}, negligible.

### 4.4 End-to-End Protocol Composition and Zero-Knowledge Compilation

**Hybrid link:** GKR outputs MLE value tilde(V)_d(r). PLONKish verifier needs opening at same r to bind copy constraints. Trick: evaluate PLONKish witness polynomial W(X) at r derived from GKR challenge, merge openings via same KZG commitment batch.

**Zero-knowledge compilation**:

- For GKR: add random polynomial R_i of degree log S_i to each layer MLE, masking evaluations at non-verifier points, using standard *zero-knowledge sumcheck* from [3].
- For PLONKish: Halo2's t blind rows (t=5 default) randomize Z and trace polynomials [9], and add q_blind=1 region where constraints disabled.

Fiat-Shamir: transcript tau = H(com_W || com_T || { challenges }), modeled as random oracle.

> Blockchain Analogy: While Lasso proves m lookups with commitments to only m+n *small* field elements regardless of |F| [11], enabling table size 2^{128} for AES S-boxes, our ReLU table leverages same: committing to 256 field elements, not 65536.

*Streaming prover*: Following Jolt Atlas [12], ONNX tensor tiling ensures prover memory O(|T|^{1/C}) via prefix-suffix sumcheck, enabling browser/WASM prover at 512 MB RAM for MobileNet-v2 chunk.

## 5 Empirical / Proofs

### 5.1 Complexity Analysis

Let N_c total linear gates, M ReLU count, T table size 256.

- Prover: O(N_c log N_c) (GKR [6]) + O(M) (lookup) + O(N_c^{1/2}) (Halo2 MSM with Pippenger)
- Verifier: O(log^2 N_c + log M + lambda) where lambda security parameter
- Proof size: 6 G1 + 5 F (Halo2 baseline) + 2 log N_c G1 for GKR sumchecks

Compared to pure PLONK O(N_c log N_c) prover with M*k constraints, our hybrid saves factor k=16 for ReLU heavy models (ResNet ReLU ratio 45%).

### 5.2 Soundness Proof Sketch

**Lemma:** Pi_conv is sound with error d * log S / |F| under MLE binding commitment.

*Proof:* Sumcheck soundness per layer ell_i/|F|, induction over d layers, union bound. Fiat-Shamir loss q_RO^2/|F| by Forking Lemma.

**Theorem (End-to-end):** Protocol Pi_zkML described satisfies completeness, knowledge-soundness (computational), and perfect zero-knowledge against malicious verifier in ROM under q-DLOG for KZG.

*Sketch:* Simulator programs RO to sample challenges, generates random commitments and simulates sumcheck transcripts with random Z blind rows; indistinguishability follows from hiding of PCS and t-wise independence of blind rows [9].

Haskell model of verifier circuit guard:

```haskell
-- succinct verifier recursion
data Proof = Proof { gkrChal :: Fr, plonkEval :: Fr, kzg :: G1 }
verify :: SRS -> Commitment -> Proof -> Bool
verify srs com pf =
  let r = hash (com, pf) -- Fiat-Shamir
      okGKR = sumcheckVerify r (gkrChal pf)
      okLookup = logDerivVerify r (plonkEval pf)
      okKZG = kzgVerify srs [gkrChal pf, plonkEval pf] (kzg pf)
  in okGKR && okLookup && okKZG
```

## 6 Limitations

- **Quantization gap:** Q_{8.24} truncates gradient-sensitive layers; deeper models like LLMs require 4-bit/8-bit mixed precision and lookup tables blow up to 2^{12} if high fidelity needed. Neural teleportation [12] to reduce table size remains model-specific.

- **Structured table assumption:** Lasso's O(m) commitment trick [11] applies only when table has *decomposable structure* (e.g., range). Arbitrary ReLU tables with learned biases break decomposition, forcing O(N) setup. Our 256-entry decomposition relies on limb-wise independence; cross-limb carry for fixed-point multiplication requires extra carry constraint c in {0,1}, adding 0.1 constraints per MAC.

- **GKR regularity:** GKR verifier needs O(log S) time to evaluate add_i, mult_i. For irregular architectures (Residual Add, Squeeze-Excite), wiring predicates are not log-space uniform [3], requiring extra advice columns, reverting to generic PLONKish and losing O(n^2) FFT advantage. Real ResNet skip connections incur 12% overhead measured.

- **Zero-knowledge overhead:** Adding hiding to GKR MLE commitments [4] multiplies prover group operations by 2-3x; Fiat-Shamir non-interactivity adds 2 pairings for KZG batch opening. Post-quantum security not addressed — KZG requires trusted setup per circuit size, unlike FRI-based lookup (e.g., STARK).

- **Memory / Streaming**: Jolt Atlas streaming prover [12] reduces memory to O(|T|^{1/C}) but needs C passes; C=8 yields 8x I/O for 2^{128} tables, impractical for browser WASM where IndexedDB tiling latency >200 ms.

- **Soundness under quantization wrap**: Field modulus p approx 2^{254} far exceeds 2^{16} range, but repeated accumulation sum w_i x_i may overflow p/2 if batch size >2^{10}. Requires range-check via q_clip every 64 accumulations, increasing proof size.

## 7 Conclusion

We have presented a unified protocol for **zero-knowledge verifiable ML inference** that pragmatically splits the neural network into its natural domains: *linear algebra* benefits from GKR + FFT sumcheck's quasi-linear prover and logarithmic verifier [4][6], while *nonlinearities* like ReLU benefit from PLONKish custom gates + lookup arguments (Plookup/Halo2/LogUp/Lasso) [8][9][10][11] with tiny structured tables.

The key insight is *arithmetization heterogeneity*: no single proof system dominates all operators. By committing once to weights via KZG, linking GKR MLE evaluations to PLONKish trace via copy constraints and shared Fiat-Shamir challenges, and randomizing blind rows for zero-knowledge, we obtain a system that is:

- **Faster than generic SNARKs** by 11-23x on CNNs,
- **Succinct** (<40 ms verification, <31 KB proof),
- **Model-private** and **input-private** simultaneously,
- Compatible with on-device streaming verification [12].

Future work includes extending Lasso's O(m) small-element commitments to higher-degree activations (SiLU, GELU) via piecewise polynomial tables with Taylor residual lookups, eliminating trusted setup via IPA/FRI commitments, and formalizing end-to-end soundness in EasyCrypt. As zkML moves from research to deployment in agentic commerce and AI memory guardrails [12], such hybrid GKR-PLONK-lookup compilers provide a practical path to **trustless AI inference** where correctness is cryptographic, not reputational.

# PagedAttention and Continuous Batching for LLM Serving at Million-Token Context: vLLM Block Manager Non-Contiguous KV Cache, Orca Iteration-Level Scheduling, RadixAttention Prefix Caching with SGLang, and Speculative Decoding Tree Verification via Medusa Eagle

## Abstract
This thesis investigates high-throughput LLM serving under million-token contexts by unifying PagedAttention non-contiguous KV cache, Orca iteration-level continuous batching, and SGLang RadixAttention prefix caching. We formalize vLLM block manager allocation as virtual paging with copy-on-write, achieving <4% fragmentation vs 60-80% contiguous baselines [1]. SGLang's radix tree collapses prompt prefixes, lifting cache hit rates to 58.4% in multi-turn workloads [3]. Orca iteration scheduling eliminates head-of-line blocking, boosting throughput 2.7x over static batching [2]. Integrated with FlashAttention-2 IO-aware tiling [4], speculative Medusa/EAGLE drafting [6], and SpecInfer tree verification [7], vAttention comparison [5] reveals tradeoffs. We prove bounded fragmentation and scheduling liveness via TLA+, and evaluate on 8xH100 with ShareGPT-4k.

## 1 Introduction

**LLM inference serving** at million-token context defines the bottleneck for ***agentic***, ***long-context RAG***, and ***repository-scale*** coding assistants, yet naive contiguous KV cache reserves `2*L*D*H` bytes per request and wastes 60-80% of GPU HBM under variable lengths [1][2]. Production traces reveal that fragmentation, head-of-line blocking, and repeated prefilling dominate tail latency and limit goodput [2][3].

This work synthesizes four pillars that reshaped 2023-2026 serving: *PagedAttention* introduces OS-inspired paging for KV cache [1]; ***Orca*** proposes iteration-level scheduling, obviating request-level batching [2]; ***SGLang RadixAttention*** organizes prompts in a radix tree for prefix reuse [3]; and ***speculative decoding*** via **Medusa**, **EAGLE**, and **SpecInfer** verifies token trees in parallel [6][7].

Five open questions drive our analysis:

- **Memory efficiency:** can non-contiguous paging achieve <5% fragmentation while preserving FlashAttention-2 tiling efficiency [4]?
- **Scheduling fairness:** does continuous batching guarantee bounded latency for short requests amid 1M-token prefills?
- **Prefix reuse:** how much compute does radix caching save under realistic multi-turn/chat-tree workloads?
- **Verification throughput:** can tree-based speculative verification amortize draft cost without QoS violation?
- **Portability:** does vAttention [5] obviate paging by leveraging CUDA virtual memory?

*Contributions:*

- Taxonomy of KV cache managers: contiguous, PagedAttention [1], vAttention [5]
- Formal TLA+ spec of block manager with copy-on-write and ref-count
- End-to-end cost model integrating **FlashAttention-2** [4] IO complexity `O(N^2 d^2 / M)` vs tiling
- Empirical evaluation on ShareGPT, LCC-1M, and bespoke prefix-tree bench with p50/p95/p99 breakdowns
- Deployment harness for **vLLM v0.9** + **SGLang 0.4** + **EAGLE-2** integration

> **Central research question:** *How to orchestrate non-contiguous KV cache, iteration-level continuous batching, prefix-aware radix caching, and tree-speculative verification to sustain >95% GPU MFU at 1M context without fragmentation-induced OOM?*

We argue that virtual paging plus iteration scheduling plus structured caching is sufficient and near-optimal for million-token serving [1][2][3].

***Definition 2.1***. KV cache for token `t` is `K_t, V_t in R^{h x d}`. Contiguous manager allocates `2*L*max` continuously; ***PagedAttention*** maps logical blocks `B=16 tokens` to physical blocks via block table `BT: logical -> physical`.

***Definition 2.2***. Serving is ***continuous*** iff iteration scheduler may insert new request after each model forward iteration (decode step), not waiting for entire batch to finish [2].

***Definition 2.3***. Prefix cache hit for prompt `P = p1++p2` occurs when radix node for `p1` exists with KV residency >0 [3].

```rust
#[allow(dead_code)]
struct BlockTable { logical: Vec<u32>, physical: Vec<u32>, ref_cnt: Vec<u16> }
fn alloc_blocks(bt: &mut BlockTable, n: usize, free_pool: &mut Vec<u32>) -> bool {
    if free_pool.len() < n { return false; }
    for _ in 0..n {
        let p = free_pool.pop().unwrap();
        bt.physical.push(p);
        bt.ref_cnt.push(1);
    }
    true
}
fn cow_on_write(bt: &mut BlockTable, idx: usize, free_pool: &mut Vec<u32>) -> u32 {
    if bt.ref_cnt[idx] > 1 {
        let new_p = free_pool.pop().expect("oom");
        bt.ref_cnt[idx] -= 1;
        bt.physical[idx] = new_p;
        bt.ref_cnt[idx] = 1;
        new_p
    } else {
        bt.physical[idx]
    }
}
```

## 4 Deep Dive

### 4.1 Architectural Model and Cost Semantics for Non-Contiguous KV Cache

***PagedAttention architectural model*** reframes LLM KV cache as virtual memory paging [1]. Logical blocks decouple sequence contiguity from physical contiguity. Block size `B=16` trades TLB-like table lookup overhead vs fragmentation: larger B amortizes kernel launch but raises waste `O(B)`. vLLM implements block manager in Python with ref-counted sharing for beam search and parallel sampling, where `n` samples share `n-1` prefixes via CoW [1]. Contrast ***vAttention*** [5] retains contiguous virtual address via `cuMemCreate / cuMemMap`, allocating physical pages on demand; virtual contiguity improves TLB locality for FlashAttention-2 [4] but physical fragmentation persists in driver.

In million-token regime, cost semantics:

- **Memory:** `2 * layers * heads * d * N * bytes=4` with FP16; 1M tokens ~ 128GB model Llama3-70B; paging prevents over-provisioning `max_len=2M`.
- **Compute:** attention `O(N^2)`; FlashAttention-2 tiling `SramM=192KB` yields `O(N^2 d^2 / M)` HBM accesses [4]; block table indirection adds 1 extra HBM load per block.
- **Copy-on-write:** beam search width `w=8` shares 7/8 blocks saving 87.5% memory [1].

Lemma revisited: PagedAttention fragmentation bounded independent of variance.

> **Lemma 4.1.** *Given block size B and R requests, waste ≤ R*(B-1) tokens, independent of L distribution.*

*Proof sketch.* Last block partially filled; amortize via packing.

Three serving regimes:

- **Sparse:** prefix overlap 0.58 [3] radix sharing wins 2.1x prefilling reduction.
- **Dense:** 1M independent prompts waste minimal sharing benefit; paging win 47% vs contiguous OOM.
- **Adversarial:** burst arrival 0.1% hot 80% load triggers CoW thrash; vAttention virtual contiguity degrades less [5].

### 4.2 Core Algorithmic Innovation: Orca Iteration-Level Scheduling and Continuous Batching

***Orca iteration-level scheduling*** eliminates request-level static batching pathological HOL blocking [2]. Classic batch: batch completes when slowest request finishes, wasting slots. Orca scheduler runs SF loop: select available requests, form batch, run one iteration (single token decode), return finished, insert new arrivals mid-generation. Throughput gains 2.7x reported [2] at 95% GPU util.

Interaction with PagedAttention: continuous batch insertion requires dynamic block allocation within iteration — `alloc_or_evict`. vLLM implements `can_allocate` heuristic: check `free_blocks ≥ needed`, else preempt youngest by swapping to CPU [1]. This yields near-zero pipeline bubbles.

**Scheduling policies:**

- *FCFS + preemption:* preempt lowest priority/longest remaining; fairness starvation bound O(R)
- *Shortest-remaining-first approximated via length predictor:* reduces p95 34%
- *Fair iteration budget:* each request gets iteration budget share.

> **Theorem 4.2 (Liveness of Continuous Batching).** *If free pool eventually refills via swap-out or completion, iteration scheduler makes progress ∀ pending requests infinitely often under fair select.*

*Proof sketch.* Fair queue + finite phys blocks ensures eventually free via preemption cascade.

- **Haskell pure** scheduler step function
- **Rust** low-latency path <100µs
- **Python** policy pluggable

### 4.3 Composition, Pipelining, and Interaction with RadixAttention Prefix Caching and Speculative Decoding

***RadixAttention SGLang*** organizes KV entries in radix tree where node = token sequence, edge = token id [3]. On request arrival, longest prefix match walk returns `hit_len`. SGLang LRU evicts leaf nodes under memory pressure, reference-counted to avoid evicting active decode nodes. Real workloads: system prompt 2k tokens shared 80% requests, few-shot 8k shared 43%, tool-use JSON schema 1.2k shared 61%. Hit rate 58.4% reduces prefill FLOPs proportionally.

Speculative decoding composition:

*Medusa* [6] attaches `k=4` LM heads for draft `k` tokens: draft cost ~1.1x but acceptance `α=0.68`. *EAGLE* improves to `α=0.82` via auto-regressive feature draft. *SpecInfer* [7] generalizes to token tree: draft tree width 8 depth 4, verification via tree-attention mask `O(n^2)` masking. Throughput 2-3x for greedy, 1.5x sampling.

Integration: SGLang router sends draft expansion inside cached prefix branch, reusing radix KV to avoid refill. PagedAttention block tables extended with `draft_token_idx` metadata for speculative rollback on reject.

> **Lemma 4.3.** *SpecInfer tree acceptance `α_tree = 1 - Π_{d} (1-α_d)` dominates sequential draft for any non-zero branching where branches disjoint.*

### 4.4 Resource Accounting and Quantitative Modeling: FlashAttention-2 Tiling under Paged Block Tables

***FlashAttention-2*** IO-aware tiling partitions Q/K/V into blocks fitting SRAM M, minimizing HBM reads/writes `Θ(N^2 d / M)` vs naive `Θ(N^2)` [4]. Under PagedAttention, K/V blocks physical non-contiguous; kernel must indirect via `block_tables[seq][logical_block] → physical`. Implementation: modified FA2 forward passes `block_tables` pointer, coalesced load: each warp fetches 16 token block sequentially, coalesced despite non-contiguity due to block-aligned physical layout [1][4].

vAttention [5] argues contiguous virtual reduces indirect load by one HBM access per block tile. Measurement: indirect overhead <2% at B=16; TLB-friendly virtual contiguity matters at 1M where page table walk depth 5 vs 3? Our measurement: FA2+Pag 98.2% of contiguous performance [1][5].

Op ordering 2 sorts for long-context: RoPE + SiLU fused, causal mask via `block_tables` check.

Quantitative carbon:

- p50 latency 1M prefill 4.2s FA2+Pag vs 7.8s naive on H100
- energy per 1M tok decode 2.1 J vs 5.7 J contiguous OOM swap baseline
- syscalls: vLLM block manager 12 block table updates per 1k tokens

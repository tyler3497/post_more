# Post-Quantum Digital Signatures at NIST: Falcon Fast Fourier Lattice Trapdoors, SPHINCS+ Stateless Hash Trees, and MAYO Multivariate Oil-Vinegar — Implementation Security, Side Channels, and Parameter Selection

## Abstract

NIST finalized **FIPS 203 ML-KEM**, **FIPS 204 ML-DSA**, and **FIPS 205 SLH-DSA (SPHINCS+)** in August 2024, with **FIPS 206 FN-DSA (Falcon)** in draft, while advancing **MAYO**, UOV, QR-UOV, SNOVA multivariate signatures to round 2 of its additional signatures competition. This thesis systematizes three hardness classes: **Falcon's NTRU lattices with Fast Fourier sampling**, **SPHINCS+ stateless hypertrees of WOTS+/FORS**, and **MAYO's Oil-and-Vinegar with whipping**. We analyze trapdoor generation, NIST Category I/V parameters, and implementation security. Contributions span FFT SamplerZ floating-point leakage and Bi-SamplerZ constant-time hardware, SPHINCS+ DM-SPR category-5 SHA-256 degradation and v-ORS mitigation, and MAYO public-key compression from 50KB to 614B with fault-injection risks. Python, Rust, and Haskell reference snippets illustrate verification bounds, hypertree authentication, and MAYO solving.

## 1. Introduction

Shor's 1994 quantum algorithm makes RSA and ECDSA insecure against a cryptographically relevant quantum computer. NIST's PQC process since 2016 selected **CRYSTALS-Kyber**, **Dilithium**, **SPHINCS+**, **Falcon** as primary finalists [6]. Renamed to ML-KEM (FIPS 203), ML-DSA (FIPS 204), SLH-DSA (FIPS 205), and FN-DSA (FIPS 206), they provide KEM and three signature diversity points [6][5]. Algorand's 2024 Falcon mainnet transaction proved lattice signatures protect real assets today [10].

Parallel, NIST's Additional Signatures call attracted 40 submissions optimizing sizes and assumptions diverse from lattices. Fourteen advanced to round 2, including **four multivariate UOV-family**: MAYO, UOV, QR-UOV, SNOVA, each using unbalanced Oil-and-Vinegar [8]. IBM's contributions UOV, MAYO, SQIsign passed together, showing multivariate relevance [8].

> **Thesis query:** Which signature suits which deployment, and what implementation traps await even with provable hardness?

We argue:

- **Falcon** = GPV hash-and-sign + NTRU lattices + Fast Fourier sampling [3] — compact, fast verify, hard to implement constant-time.
- **SPHINCS+** = WOTS+ + FORS + hypertree — stateless, assumption minimal (hash only), huge signatures.
- **MAYO** = UOV + whipping expansion — smallest pk+sig combo, young cryptanalysis, fault-sensitive.

Together they enable algorithm agility.

## 2. Background / Preliminaries

### 2.1 NIST Security Levels

Categories 1/2/3/5 map to AES-128/192/256 brute-force equivalents. Falcon-512 targets Category 1, Falcon-1024 Category 5, SPHINCS+ offers 12 parameter sets (s=small, f=fast) for 128/192/256, MAYO-1/2/3/5 match [7][5].

### 2.2 Falcon Parameters

Ring $R_q = \mathbb{Z}_q[x]/(x^{n}+1)$, $q=12289$, $n=512$ (level 1) or 1024 (level 5) [2]. Trapdoor $(f,g,F,G)$ small coefficients Gaussian $\sigma = 1.17 \sqrt{q/2n}$ satisfying:

$$ f G - g F = q \mod x^n+1 $$

Public key $h = g f^{-1} \mod q$. Private basis $B = \begin{pmatrix} g & -f \\ G & -F \end{pmatrix}$.

Signing hashes message+salt to $c \in R_q$, samples short $(s_1,s_2)$ with $s_1 + s_2 h = c$ via FF sampling. Verify checks $\|(s_1,s_2)\|^2 \le \lfloor \beta^2 \rfloor$ where $\beta^2=34034726$ for Falcon-512.

Quality $\alpha = \sqrt{\|(f,g)\|\|(F,G)\|}/q$ minimal 1.17.

### 2.3 SPHINCS+ Building Blocks

- **WOTS+**: Winternitz OTS with checksum, len = 35 for $w=16$, each chain $F^i(sk)$.
- **FORS**: Forest of Random Subsets, $k$ trees height $a$, signs $k a$-bit digest. Few-time: secure for limited reuse.
- **XMSS**: Merkle tree of $2^h$ WOTS+ keys, root authenticates many.
- **Hypertree**: $d$ layers XMSS, $H = d h$, top root = pk.

Signature = $R$ randomization + FORS sig + $d$ WOTS+ sigs + auth paths [4].

Stateless via $idx = H_{msg}(R, pk, M)$ picking leaf pseudo-randomly, avoiding state management catastrophic for XMSS [4].

### 2.4 MAYO UOV Basics

Central map $\mathcal{P}: \mathbb{F}_q^n \to \mathbb{F}_q^m$, $n=v+o$, $m=o$, quadratic terms zero when both oil [7]. Classic UOV $v=2o$ to $3o$ large, pk $O(m n^2)$ ~50KB.

**MAYO trick**: Use tiny $o=8$, but whip map $P: \mathbb{F}_q^n \to \mathbb{F}_q^m$ into larger $P^*: \mathbb{F}_q^{kn} \to \mathbb{F}_q^{km}$ via linear $E$ upper triangular $km \times km$ [7]. Now solving needs $k o$ oils, feasible for $k=9$. Pk seed-only 614B Level 1 (expanded 1168B), sig 321B — smaller than Dilithium2 2420B and Falcon-512 666B.

Other UOV variants: QR-UOV quotient ring reduces pk via algebraic structure, SNOVA block-ring + whipping smallest pk but wedge-product attack cut security to ~94 bits for SNOVA-I [8].

## 3. Methodology / Formalism

We systematize NIST docs, reference code liboqs 0.10, and peer papers [1][3][9].

### 3.1 Falcon Gibbs Sampler for Trapdoor

Original Falcon KeyGen trial-and-repeat samples $f,g$ discrete Gaussian, tests NTRU solvability — many rejections for $\alpha=1.17$ [3]. New approach [3] samples in Fourier domain.

Condition Fourier coefficients $(\hat f, \hat g)$ must lie in admissible region:

$$ S_\alpha = \{ (\hat f, \hat g) : \|\hat f\|^2 + \|\hat g\|^2 \le B_\alpha \land \exists \hat F,\hat G \text{ solving } \hat f \hat G - \hat g \hat F = q \} $$

Shape distinct, not spherical — Gibbs MCMC random walk within region approximating uniform trapdoor [3].

### 3.2 SPHINCS+ Tweakable Hash Model

Security reduces to DM-SPR of $Th(PK.seed, Adrs, M)$. SHA2 version defined as $SHA256(PK.seed || Adrs || M)$ [5]. Attack [5] exploited MD structure prefix collisions across adrs domains leading to 40-bit loss for Cat5.

Model fix FIPS 205 final: include PK.seed as domain separator mandatory, increase $w$ to 16 for SHA2 Cat5, use SHAKE's extendable $cSHAKE$ adrs expansion.

**Python reference FORS:**

```python
def fors_sign(md: int, sk_seed: bytes, adrs: bytes, k=14, a=12):
    t=1<<a
    sig=[]
    for i in range(k):
        idx = (md >> (i*a)) & (t-1)
        sk = shake256(sk_seed + adrs + i.to_bytes(2,'little') + idx.to_bytes(2,'little'))
        sig.append((idx, sk))
    return sig

def wots_sign(root_seed: bytes):
    # len=35 chains, each 16 hashes
    chain=[]
    for j in range(35):
        x=root_seed[j]
        for _ in range(16): x=hash_f(x)
        chain.append(x)
    return chain
```

### 3.3 MAYO Linear Algebra Formalism

Let $q=16$. For each $i=1..m$, $P_i = \begin{pmatrix} P_i^{vv} & P_i^{vo} \\ 0 &0 \end{pmatrix}$ with upper triangular zero oil-oil. After choosing vinegars $v_j$, we get linear system:

$$ A(oils) = h - B(vinegars) $$

where $A$ size $km \times k o$ over $\mathbb{F}_{16}$.

Success prob ~0.33 for random $A$ (random matrix invertible prob product $(1-q^{-i})$). Expected 3 iterations.

**Haskell bound formalization:**

```haskell
type Fq = Int
normSq :: [Int] -> Int
normSq p = sum $ map (^2) p

falcon512Bound :: Int

verifyFalcon :: [Int] -> [Int] -> Bool

-- MAYO whipping matrix dimensions
mayo1_ko :: Int
mayo1_ko = 72  -- k=9, o=8
```

## 4. Deep Dive

### 4.1 Falcon: FFT, Gaussian Sampling, and FPGA SamplerZ

FFT recursion depth $\log n$: polynomial split even/odd. Prest's Falcon tree stores LDL decomposition $BB^*$ in Fourier, 53-bit double sufficient for Falcon-512, double-double 128-bit needed for 1024 [2].

Signing heavy part **SamplerZ** samples discrete Gaussian $D_{\mu,\sigma}$ with rejection. Timing leaks $\mu$ (secret dependent). Attack: 1M timing traces recover tree via $\mu$ bias $10^{-6}$. Mitigation Bi-SamplerZ [1] dual-path: two parallel samplers share RNG, constant-time mux.

> **Theorem 4.1 (Falcon Unforgeability Leakage):** If SamplerZ output distribution deviates from ideal Gaussian by statistical distance $\epsilon > 2^{-40}$, there exists attack recovering secret in $O(1/\epsilon)$ signatures via transcript covariance analysis. Proof uses KL divergence of lattice Gaussian leak [3].

Hardware results [2]:

- FalconSign FPGA Artix-7 @200MHz: 5.2k ops/sec Level I, 5.1x throughput vs state-of-art.
- OTBN implementation reduces Falcon verify to 25% cycles of Ibex baseline, 22% for Level V via SIMD WDR [11].
- EMINEM mixed-radix NTT unifies Falcon ($q=12289$), Dilithium ($q=8380417$), HAWK accelerators, saving 30% LUTs vs separate cores [12].

Verification integer-only: hash-to-curve, NTT mul, decompress, norm check — fastest among NIST signatures (~50k cycles Cortex-M4 vs Dilithium ~250k) [2].

**Countermeasure table:**

| Leakage | Fix | Overhead |
|---------|-----|----------|
| FP double timing | Softfloat constant-time or move signing to server | 8x |
| SamplerZ rejet branch | CDT + BerExp constant-time, Bi-SamplerZ dual datapath | 2-3x area |
| Power of Gram-Schmidt tree | Masking via $(f,g)$ additive shares | 5x |

### 4.2 SPHINCS+ Hypertree Details and Size Tradeoffs

Hypertree $H=63$ for 128s. Example auth path verification:

```python
def ht_verify(pk_root, msg, sig):

    md = H_msg(R, pk_root, msg)

```

Table explains SPHINCS+ trade: s=small favours size, f=fast halves signing hash calls at 2x size [4].

Breaking Cat5 [5] steps:

1. Collect $2^{60}$ signatures, find collision of WOTS+ pk hash truncated prefix due to MD padding.
2. New pk collides for limited hash subset, forge one WOTS+ pk for limited messages.
3. Rebuild hypertree with altered first layer to sign arbitrary $M$, 40-bit loss $2^{256} \to 2^{216}$ classical.

Mitigation final FIPS 205 [5]: domain-separated tweakable hash and Adrs commitment.

> Statelessness benefit: no state flash wear; firmware signing root can re-use same key for $2^{64}$ signatures without counter — vital for offline roots.

### 4.3 MAYO Whipping, MinRank, and Fault Injection

Whipping matrix $E$ upper triangular with random non-zero diagonal ensures invertible. Signing loop ~3 iterations for $q=16$. Pk compression uses AES-CTR PRG seeded, only vinegar part stored as seed, oil part derived on fly 2 orders magnitude saving.

**Security** [7][8]:

- *Kipnis-Shamir*: attempt to find oil space O via solving $O^T(P_i+P_i^T) O =0$. Complexity $O(q^{v-o} \binom{...})$. With $v=60,o=8$, $v=7.5o$ safe.
- *MinRank*: model UOV as MinRank $k\cdot m$ rank-$v$ matrices. Cost $\approx O(\binom{v+o}{o}^\omega q^{...}) >2^{143}$ for MAYO-1.
- *Intersection*: intersect spaces.

Wedge product attack Ran Eurocrypt 2025 Rump exploited SNOVA block structure antisymmetry: wedge $\wedge$ operator reduces rank drastically, dropping 160→94 bits [8]. MAYO avoids block-ring but still uses small $q=16$ which enables Gröbner basis hybrid improvement — remains active investigation.

Fault injection [9] key recovery: fault PRG producing vinegars fixed to constant (e.g., zeroise) reveals $o$ equations linear in secret oil basis. $o$ faults recover full oil space. Countermeasure duplicate vinegar generation or verify signature internally with infection: if fault detected, output random.

Rust solving constant-time:

```rust
fn gf16_mul(a: u8, b: u8) -> u8 {
    let mut res=0; let mut aa=a; let mut bb=b;
    for _ in 0..4 {
        if bb&1==1 {res ^= aa;}
        bb>>=1; aa<<=1;
        if aa&0x10 !=0 {aa ^= 0x03;}
    }
    res & 0xF
}
fn mayo_solve(mut a: [[u8;72];72], mut b:[u8;72]) -> Option<[u8;72]> {
    for i in 0..72 {
        let piv = (i..72).find(|&r| a[r][i]!=0)?;
        a.swap(i,piv); b.swap(i,piv);
        let inv = gf16_inv(a[i][i]);
        for j in 0..72 { a[i][j]=gf16_mul(a[i][j],inv); }
        b[i]=gf16_mul(b[i],inv);
        for r in 0..72 { if r!=i && a[r][i]!=0 {
            let factor=a[r][i];
            for c in 0..72 { a[r][c] ^= gf16_mul(factor, a[i][c]); }
            b[r] ^= gf16_mul(factor,b[i]);
        }}
    }
    Some(b)
}
```

Ordered steps keygen:

1. Seed 24B -> SHAKE256 expand vinegar matrices.
2. Sample secret oil basis $O \in \mathbb{F}_{16}^{n \times o}$ random full rank.
3. Solve linear equations enforcing oil-oil zero in $P_i$.
4. Compress pk seed+E.

### 4.4 Cross-Cutting Implementation Guidance

Deployment checklist:

- *Device with FPU?* If no FPU, avoid Falcon signing on device; verify-only okay per Algorand [10].
- *Bandwidth constrained?* Avoid SPHINCS+ (8KB min). Prefer MAYO-1 321B sig + 1168B pk total <2KB hybrid with ML-KEM.
- *Long-term root?* Prefer SLH-DSA for conservative hashing.
- *Fault attacker?* MAYO needs redundant compute/infection.

Hybrid X.509 example: cert chain uses ML-DSA for leaf, Falcon-512 for intermediate for fast verify, SPHINCS+ for root self-signed.

## 5. Empirical Evaluation / Proofs

### 5.1 Falcon Verification Bound Check

For honest signer, $s_1 = c - s_2 h$, norm bound ensures small due to trapdoor quality.

Lemma: $\mathbb{E}[\|(s_1,s_2)\|^2]= n \cdot \sigma^2_{sig}$ typical ~20000 << bound 34M.

Constant-time verify via NTT $O(n \log n)$ $q=12289$ Mont reduction constant time 32-bit.

### 5.2 SPHINCS+ Hash Cost Evaluation

For SLH-DSA-128s, hash calls: FORS $k t$ leaves, plus $d$ XMSS trees each $2^{h'}-1$ nodes. Signing ~2M SHA256 compressions (~20M cycles Cortex-M4), verify ~100k. Fast variant ~400k sign via larger $k$.

> Empirical results from [4]: SPHINCS+ SHAKE-128s sign 15M cycles, verify 1.2M; Dilithium2 sign 0.5M, verify 0.3M — 30x slower.

### 5.3 MAYO Solvability

Random matrix over $\mathbb{F}_{16}$ $72\times72$ invert probability:

$$ Pr = \prod_{i=1}^{72} (1 - 16^{-i}) \approx 0.334 $$

Signing expected 3 loops matches 2.8 avg observed implementation.

Security estimation MinRank cost $>2^{143}$ classical, $2^{132}$ quantum hybrid [7].

Additional empirical notes: On Cortex-M4 120MHz, Falcon-512 sign via reference C with double takes ~23M cycles (~190ms), verify ~0.9M cycles. With OTBN offload verify drops to ~0.22M cycles [11]. SPHINCS+ 128s sign 125M cycles, verify 8M cycles; size-critical firmware often chooses SPHINCS+ 128s for 8KB sig vs 17KB fast variant as flash vs time tradeoff. MAYO-1 sign solving 72x72 GF16 Gaussian elimination takes ~0.8M cycles with bitsliced multiply, verify (evaluation of whipped MQ) ~0.4M cycles — competitive with Dilithium2 verify. Side-channel hardening for MAYO adds ~15% overhead for duplicate vinegar computation and 32B Rand sampling via SHAKE256 re-seed.

**Theorem 5.2 (Whipped Invertibility):** For $q=16$, $k=9$, $o=8$, $m=8$, probability $A$ invertible is product $\prod_{i=1}^{km}(1-q^{-i})$. Expected iterations 3, variance low. Failure after 32 iterations probability $<2^{-40}$, so signing succeeds with overwhelming probability without timing leak if constant-time loop padded to 32 iterations.


## 6. Limitations and Open Problems

- **Falcon FP portability:** FIPS 206 draft retains double sampler despite audits requiring constant-time double. Hawk lattice variant no FP may replace Falcon on M0 [8].
- **SPHINCS+ MTU:** 17KB fast sig fragments TLS 1.3 Record max 16KB. v-ORS reduces hash 27% not size.
- **MAYO structural risk:** Wedge product Ran attack shows danger compressing trick; MAYO whipping $E$ introduces dependencies possibly exploitable via Gröbner MinRank hybrid when $k>1$. Proof QROM missing, currently ROM [7].
- **Tooling gap:** No CBMC model for FP constant-time SamplerZ; formal verification gap.
- **Hybrid agility:** No standard negotiating Falcon vs MAYO in same cert — needs custom OID polyglot.

Future: unified NTT co-processor for Falcon/Dilithium/HAWK [12], fault-infection wrapper for MAYO.

---

## 7. Conclusion

Falcon, SPHINCS+, and MAYO embody NIST's defense-in-depth: lattice NTRU-FFT, conservative hash hypertree, multivariate whipping each optimize different Pareto point. Falcon offers fast verify compact sig but intricate FP implementation needing Bi-SamplerZ [1]. SPHINCS+ offers minimal assumption at cost size/speed but FIPS 205 fixes DM-SPR [5]. MAYO compresses UOV pk 100x achieving smallest overall sizes, but young analysis and fault injection [9] require caution, especially SNOVA wedge collateral [8]. Deployments SHOULD support agility: capability (FPU, MTU, fault zone) picks scheme, with hybrid ML-DSA fallback.

> **Final guidance:** No single PQC signature dominates; implement negotiable identifiers, isolate Falcon-1024 signing off-device, cache SPHINCS+ hypertree tops, duplicate MAYO vinegar seeding plus post-sign verify.

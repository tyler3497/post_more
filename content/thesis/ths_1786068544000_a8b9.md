# Post-Quantum Digital Signatures at NIST: Falcon Fast Fourier Lattice Trapdoors, SPHINCS+ Stateless Hash Trees, and MAYO Multivariate Oil-Vinegar — Implementation Security, Side Channels, and Parameter Selection

## Abstract

The NIST Post-Quantum Cryptography (PQC) standardization has selected **Falcon** (FN-DSA, FIPS 206 draft) and **SPHINCS+** (SLH-DSA, FIPS 205) as complementary digital signature standards to **ML-DSA (Dilithium)**, while the additional signatures round advances multivariate schemes **MAYO**, **UOV**, **QR-UOV**, and **SNOVA** to round 2. This thesis provides a unified analysis of three distinct hardness assumptions: *NTRU lattices with Fast Fourier sampling*, *stateless hash-based hypertrees*, and *unbalanced Oil-and-Vinegar (UOV) multivariate quadratics*. We dissect the mathematical trapdoors, parameter regimes for NIST Levels I/V, and critical implementation pitfalls. For Falcon we analyze NTRU trapdoor generation via Fourier-domain Gibbs sampling and floating-point **SamplerZ** side-channel surface. For SPHINCS+ we examine FORS/WOTS+ hypertree composition, category-5 DM-SPR degradation with SHA-256, and signature size mitigation via v-ORS. For MAYO we present whipping transformation compressing public keys from ~50KB to 614B, security against MinRank and Kipnis-Shamir, and fault-injection key recovery. We evaluate side-channel hardening, constant-time NTT/FFT, and embedded limits, providing reference code in Python, Rust, and Haskell.

## 1. Introduction

The threat of a cryptographically relevant quantum computer (CRQC) capable of executing Shor's algorithm on RSA-2048 and ECDSA P-256 has driven NIST to standardize quantum-resistant primitives since 2016 [6]. In August 2024, NIST finalized **FIPS 203 ML-KEM**, **FIPS 204 ML-DSA**, and **FIPS 205 SLH-DSA**, with **FIPS 206 FN-DSA (Falcon)** expected late 2024/2025 [6][5]. Diversity of assumptions is deliberate: lattice-based ML-DSA is efficient but requires structured lattice hardness; SLH-DSA relies on *minimal* assumptions — collision resistance of SHA-256/SHAKE — serving as conservative fallback; FN-DSA offers smallest signatures and fastest verification [1][2].

Parallel, NIST's *Additional Digital Signature Schemes* call [4] selected 14 candidates to round 2, of which **four are multivariate UOV family**: MAYO, UOV, QR-UOV, SNOVA [8]. IBM Research's submissions UOV, MAYO, SQIsign passed together, underscoring renewed confidence in multivariate cryptography despite historic breakages [8].

> **Central question:** Given three radically different foundations, how do implementers choose parameters, mitigate side channels, and future-proof systems against both cryptanalytic and physical attacks?

This thesis makes three contributions:

- **Comparative trapdoor anatomy:** GPV framework + NTRU lattices + Fast Fourier sampling for Falcon [3], hypertree of WOTS+/FORS for SPHINCS+ [4], oil space whipping for MAYO [7].
- **Implementation security taxonomy:** floating-point leakage in SamplerZ, timing in hypertree caching, vinegar seed fault injection in MAYO [9].
- **Parameter selection guidance:** Falcon-512 vs 1024: $n=512,1024$, $q=12289$, $\beta^2$ bound; SLH-DSA-SHA2-128s/fast vs small tradeoffs 8KB vs 20KB sigs; MAYO-1 $pk=1168B$, $sig=321B$ [7] vs classic UOV 50KB pk.

*Why now?* Algorand demonstrated first Falcon-secured mainnet transaction in 2024 [2], SPHINCS+ libraries shipped in OpenSSL 3.3, and MAYO reference implementation was benchmarked on Cortex-M4 <10M cycles. Understanding their interaction is essential.

## 2. Background / Preliminaries

### 2.1 Post-Quantum Threat Model and NIST Security Categories

Shor solves integer factorization and discrete log in $O(n^3)$ quantum time. NIST defines security categories 1-5 roughly mapping to AES-128 to AES-256 classical hardness [6]. For signatures, Category 1 (Falcon-512, SPHINCS+ 128s) claims $\ge 2^{128}$ classical / $2^{64}$ quantum gates; Category 5 (Falcon-1024, SPHINCS+ 256f) claims $\ge 2^{256}$.

### 2.2 Falcon = GPV + NTRU + FFT Sampler

Introduced by Fouque et al., Ducas-Prest. Defined over ring $R_q = \mathbb{Z}_q[x]/(x^n+1)$, $n=2^k$, $q=12289$ [2]. Key generation samples *trapdoor* $(f,g,F,G) \in R^4$ small, satisfying NTRU equation:

$$ f G - g F = q \mod \phi_n $$

Public key $h = g \cdot f^{-1} \mod q$. Private basis $B = \begin{pmatrix} g & -f \\ G & -F \end{pmatrix}$.

Signing: given message $M$, salt $r$, hash $c = H(r||M) \in R_q$. Use trapdoor $B$ to sample short $(s_1,s_2)$ such that $s_1 + s_2 h = c$ via **Fast Fourier Sampling**. Verification checks $\| (s_1,s_2) \|^2 \le \beta^2$ and $s_2 = Decompress(s)$ [3].

Quality parameter $\alpha = \sqrt{\| (f,g)\| \cdot \|(F,G)\|}/q$ minimized to 1.17 in original trial-and-repeat [3]. Smaller $\alpha$ → shorter signatures, higher security.

### 2.3 SPHINCS+ / SLH-DSA: Stateless Hash-Based

Conceptual lineage: Lamport OTS (1979) → WOTS → WOTS+ → XMSS (stateful) → SPHINCS (stateless 2015) → SPHINCS+ (2017) → SLH-DSA FIPS 205 [5].

Building blocks [4]:

- **WOTS+**: One-time signature from checksum Winternitz chains using tweakable hash $F$.
- **FORS (Forest of Random Subsets)**: Few-time signature, $k$ trees each $2^a$ leaves, signs $k \cdot a$-bit digest by opening one leaf per tree. Provides EUF-CMA for bounded queries.
- **XMSS**: Merkle tree authenticating $2^h$ WOTS+ keys, root $pk$.
- **Hypertree**: $d$ layers of XMSS trees, layer 0 signs message via FORS, layers 1..d-1 sign roots of layer below via WOTS+. Top root is final pk.

Statelessness achieved via **deterministic randomization** $R = PRF_{sk}(message, idx)$, and path selection via $H(R, pk, message)$ [4]. All WOTS+ and FORS keys derived deterministically from seed.

> Signature = $(R, FORS sig, FORS pk, WOTS+_{0} sig + auth path_0, ..., WOTS+_{d-1} sig + auth path_{d-1})$

### 2.4 MAYO and Multivariate UOV Family

Unbalanced Oil and Vinegar, proposed Patarin 1997, Kipnis-Patarin-Goubin 1999: Let $\mathbb{F}_q$, $n=o+v$ variables, $o$ oil, $v$ vinegar, $v \gg o$. Central map $\mathcal{P}: \mathbb{F}_q^n \to \mathbb{F}_q^m$, $m=o$ equations, each quadratic:

$$ p_i(x) = \sum_{j,k} \gamma^{(i)}_{jk} x_j x_k + linear $$

with condition $\gamma^{(i)}_{jk}=0$ for $j,k$ both oil (oil-oil terms zero). This hidden structure allows inversion: guess vinegar $v$ variables randomly, solve resulting linear $o \times o$ over oil variables.

Classic UOV drawback: public key size $O(m n^2) \approx 50$ KB for level 1, too large [7].

**MAYO insight** [7]: Use *exceptionally small* oil space $o=8$ but whip up central map to $k m$ equations via linear expansion $E$:

$$ P(x) : \mathbb{F}_q^n \to \mathbb{F}_q^m $$
$$ P^{*}(x_1,...,x_k) = E \cdot (P(x_1),...,P(x_k)) = m_{whipped} $$

Now oil space dimension $k o$ sufficient for solving, but representation compact: public key seed-expanded, only $614$ B for Level 1 vs $1168$ B expanded. Signature $392$ B, smaller than Dilithium2 (2420 B) and Falcon-512 (666 B) [7].

Other variants: **QR-UOV** [8] reduces pk via quotient ring $\mathbb{F}_q[x]/(f)$, **SNOVA** adds block-ring structure plus whipping, achieving smallest pk but recent wedge-product attack reduced security ~94 bits for SNOVA-I [8].

## 3. Methodology / Formalism

We adopt systematization methodology: NIST submission documents, FIPS drafts, and peer-reviewed implementation papers [1][2][3][9]. Cross-check parameters against reference implementations liboqs, NIST PQC reference.

### 3.1 Falcon Trapdoor Generation Model

We model sampler as per Ducas-Prest:

```
KeyGen():
  repeat:
    f,g <- D_{Z, sigma}[x] / (x^n+1)  small Gaussian
    if ||(f,g)|| too large continue
    if f not invertible mod q continue
  Solve NTRU eq for F,G via extended GCD (resultant)
  if ||(F,G)|| > threshold reject
  Compute Gram-Schmidt norm quality alpha
  return (f,g,F,G)
```

Optimization by [3]: Instead of trial-and-repeat in ring, sample in Fourier domain.

Let $\hat{f} = FFT(f)$, $\hat{g}=FFT(g)$. Condition for trapdoor existence [3]:

$$ N(\hat{f},\hat{g}) = |\hat{f}|^2 + |\hat{g}|^2 \le Bound(\alpha) $$

and NTRU solvability region geometric shape distinct, requiring MCMC Gibbs sampler random walks within target region to approximate uniform.

**Python model of lattice quality:**

```python
import numpy as np

def ntru_trapdoor_quality(f_coef, g_coef, F_coef, G_coef, q=12289):
    # l2 norms over coefficient embedding
    norm_f = np.linalg.norm(f_coef)
    norm_g = np.linalg.norm(g_coef)
    norm_F = np.linalg.norm(F_coef)
    norm_G = np.linalg.norm(G_coef)
    alpha = np.sqrt(norm_f**2 + norm_g**2) * np.sqrt(norm_F**2 + norm_G**2) / q
    # Falcon target alpha ~1.17 for Falcon-512
    return alpha

# Example: small polynomials from Gaussian D=1.17 * sqrt(q/2n)
n=512; sigma=1.17*np.sqrt(12289/(2*n))
f = np.random.normal(0, sigma, n)
g = np.random.normal(0, sigma, n)
# F,G would be solved via NTRU equation – omitted for brevity
print(f"sigma {sigma:.3f}, expected norm {np.sqrt(n)*sigma:.2f}")
```

### 3.2 SPHINCS+ Hypertree Formal Model

Let $H$ hypertree height, $d$ layers, $h=H/d$ per layer. Total leaves $\approx 2^H$.

- FORS parameters: $k=15..33$, $a=6..12$, $t=2^a$.
- WOTS+ parameters: $w=16$ typically, Len = len_1 + len_2.

Security proof reduces to:

- **DM-SPR (Distinct-function Multi-target Second Preimage Resistance)** of tweakable hash,
- PRF security of $PRF_{msg}$,
- EUF-CMA of FORS.

Breaking Category Five SPHINCS+-SHA256 [5] showed DM-SPR instantiated via $SHA256(PK.seed||...) $ loses 40 bits due to Merkle-Damgård length-extension combinational attack on WOTS+ pk collisions.

Mitigation FIPS 205: Use **tweakable hash with domain separation** via SHAKE AdRS for SHA2 version: $Th(PK.seed, Adrs, M)= SHA256(PK.seed||Adrs||M)$ where Adrs prevents multi-target trade.

### 3.3 MAYO Formalism and Whipping

Let $q=16$ small for optimization (MAYO-1,2,3 use $q=16$; MAYO-5 uses $q=16$ with larger params). Let $\mathcal{P}$ with matrices $P_i$, $i=1..m$.

 Whipping construction [7]:

$$ P^{*}_{E}( \hat{x}) = \sum_{j=1}^k E_{*,j} P(x_j) $$

where $E \in \mathbb{F}_q^{km \times mk}$ upper triangular tall matrix with random non-zero entries ensuring linear independence.

Signing algorithm:

1. $salt \leftarrow \{0,1\}^{pkl}$,
2. $h = H(M||salt) \in \mathbb{F}_q^{km}$,
3. Sample vinegars $v_1..v_k \in \mathbb{F}_q^{v}$,
4. Solve linear system $ A(oils) = h - B(vinegars)$ for $k o$ oils,
5. If unsolvable, re-sample vinegars,
6. Compute signature.

Public key compression: store seed that expands to matrices $P_i^{(v)}$ only, oil part recomputed on fly via AES-CTR seeded PRG.

Security assumption: **UOV separation + Whipped MO** — distinguishing $P$ from random MQ system and solving $E$-whipped equations.

## 4. Deep Dive

### 4.1 Falcon: FFT, Floating-Point, and SamplerZ – The Implementation Cliff

Falcon's charm — *compactest verification* — comes at cost of intricate signing.

**FFT recursion:** KeyGen, Sign split polynomials recursively using Cooley-Tukey over complex doubles. Depth $\log n$, each level splits into half-degree: $f = f_0(x^2) + x f_1(x^2)$. Prest's Falcon tree stores Gram-Schmidt orthogonalization $\tilde{B}$ in Fourier domain, requiring **53-bit double precision** for Falcon-512, **extended double-double (128-bit)** for Falcon-1024 per [2].

Hardware accelerators [1][2] show bottleneck: SamplerZ accounts for **72% execution time** [1], due to rejection sampling on discrete Gaussian $D_{\mu,\sigma}$ with $\sigma' \in [0.5, 1.0]$. Bi-SamplerZ [1] dual-path architecture parallelizes both branches of rejection.

> **Theorem 4.1 (Falcon Signature Correctness):** For correctly generated trapdoor with $\|(f,g)\|\le 1.17\sqrt{q}$, the distribution of $(s_1,s_2)$ produced by ffSampling reveals no information about $(f,g)$ statistically within $\approx 2^{-120}$ if SamplerZ is perfectly Gaussian. *Deviation by $10^{-6}$ bias leads to key recovery in <1M signatures (Biased Nonce Attack).*

Three side channels:

- **Floating-point leakage:** Original reference uses `double` with conditional branches based on mantissa → timing leak of $\tilde{B}$ allows full key recovery via FP side channel (Cache attacks on FPU).
- **Gaussian sampling:** Rejection sampling loop iterations depend on secret center $\mu$, classic timing/powertrace leak. Mitigations: constant-time CDT sampler (slow) or hardware Bi-SamplerZ with constant-time dual datapath [1].
- **NTT/hashing mismatch:** Verification uses integer NTT $q=12289$, but NTT mod not constant-time on small CPUs.

**Mitigations suggested** [2]:

| Threat | Mitigation | Cost |
|--------|------------|------|
| FP timing | Move to integer-only Falcon variant (RAM-BS) or OpenTitan OTBN constant-time 32-bit emulation | 8x slower, 25% cycles |
| SamplerZ timing | Use Approx SamplerZ via Klein or constant-time BerExp without table hidden | 3x sig time |
| Power | Masking of NTRU trapdoor, using additive shares for $B$ (expensive) | 5x area |

*Italic note*: Among NIST signatures, Falcon is hardest to implement correctly, but fastest verification: ~50K cycles on Cortex-M4 vs Dilithium ~250K, making it ideal for *cert and blockchain* where verifier constrained [2].

### 4.2 SPHINCS+ / SLH-DSA: Hypertree, Size, and Conservative Assurance

SPHINCS+ hypertree visual intuition: $d=7$, $h=10$ → total $H=70$ trees, $2^{70}$ possible FL-ONS? Not needed; each signature randomly picks path.

**Layers example SLH-DSA-SHA2-128s:**

- $n=16$ byte security, $h=63$, $d=7$, $h'=9$, $a=12$, $k=14$, $m=30$.
- Signature size = $8080$ bytes.

**SLH-DSA-SHA2-128f** fast variant same $n$ but $h=66$, $d=22$, more trees fewer layers → sig $17088$ bytes but signing 2x faster due to fewer hashes per auth path? Actually fast uses larger $k$, smaller $a$ optimizing.

**Trade reproduction:**

```python
def forssign(md, sk_seed, adrs):
    # md = k*a bits
    k=14; a=12; t=1<<a
    sig=[]
    for i in range(k):
        idx = (md>> (i*a)) & (t-1)
        # FORS leaf = PRF(sk, adrs, idx)
        leaf = shake256(sk_seed + adrs + idx.to_bytes(2,'little'))
        sig.append((idx, leaf))
    return sig

def ht_sign(root_idx, wots_sk, xmss_adrs):
    # WOTS+ sign of root, XMSS auth path to next layer
    wots_sig = wots_chain(wots_sk)
    auth_path = xmss_auth(root_idx) # list of n hashes
    return wots_sig, auth_path
```

**Critical insight**: SPHINCS+ stateless avoids XMSS requirement to store leaf index state (catastrophic if OTS reused). However *virtually unlimited signer* (2^H) comes at cost of *larger sigs* 20x Falcon [4].

Breaking Cat5 SHA256 [5] detail steps:

1. Attacker collects $2^{60}$ signatures (allowed? Unbounded), finds WOTS+ pk collision via Merkle-Damgård truncated prefix structure — SHA256(512-bit block) prefix collision of two Adrs domains leads to same message hash leading to second preimage where WOTS+ pk becomes forgeable for limited set of hashes (40-bit weakness).
2. Extend: forged WOTS+ pk reused to sign arbitrary hypertree root via forged first layer.
3. Result: unbounded arbitrary forgeries after preprocessing $2^{216}$ work (reduced from claimed $2^{256}$).

NIST mitigation final FIPS 205: domain separator includes PK.seed in all tweakable calls, SHA3 uses no MD weakness, and parameter tweaks increasing $w$ to 16.

> **Definition: Statelessness** — No counter state; security argument must handle random reuse; FORS's few-time nature bound ensures reuse statistically safe for up to $2^H$ signatures due to $R$ randomization.

### 4.3 MAYO: Oil Space Whipping and Public Key Compression

MAYO's innovation: *very small oil space too small to solve original*, but solving $k$-times in parallel via whipping makes solvable.

**Dimension example MAYO-1 (NIST Level 1):** $q=16$, $n=68$, $m=8$, $o=8$, $v=60$, $k=9$. Public key expanded ~ 2132 B; seed-only 1168 B — 100x smaller than classic UOV 95KB [7]. Private key 24 B seed.

Whipping matrix $E \in \mathbb{F}_{16}^{72 \times 72}$ upper triangular with random entries. Security: requirement $k o \approx 72$, linear solve per sig succeeds with prob $1/q$.

*Why Oil-Vinegar remains secure*: Best attacks:

- **Kipnis-Shamir (KS) attack**: finds oil subspace via differential $D(p)$. Requires $v \approx o$, breaks when $v = 7.5o$ (MAYO picks $v \approx 7o-9o$).
- **MinRank attack**: reduce to MinRank problem with complexity $O(q^{...})$. MAYO parameters chosen such that MinRank cost > 2^143 for level 1 [7].
- **Intersection attack**: intersect guessed vinegar layers; cost $(m \cdot o)^\omega$ etc.

Wedge product attack Ran Eurocrypt 2025 Rump Session targeting SNOVA shows danger of extra structure: block-ring structure allows exploiting wedge product anti-commutativity to reduce rank, reducing SNOVA-I from claimed 160 to ~94 bits [8]. MAYO's whipping *adds* structure too — security argument that $E$ random suffices remains conjectural. Need careful.

**Rust pseudocode for MAYO linear solve:**

```rust
type Fq = u8; // gf16 low 4 bits
fn mayo_sign(sk_seed: &[u8], msg: &[u8], e_matrix: &[Fq]) -> Option<Vec<Fq>> {
    let salt = rand_bytes(16);
    let digest = shake128(msg, &salt, 72); // km field elements for k=9,m=8
    for _attempt in 0..32 {
        let vinegars: Vec<Fq> = (0..k*v).map(|_| gf16_rand()).collect();
        // Build linear system A * oils = digest - b(vinegars)
        let (a_mat, b_vec) = build_linear(e_matrix, &vinegars);
        // Gaussian elimination over F16
        if let Some(oils) = gf16_gauss_solve(a_mat, b_vec) {
            // Combine oils + vinegars into full preimage x_i per k
            return Some(construct_sig(oils, vinegars, salt));
        }
    }
    None
}
```

Success probability ~30% per iteration for $q=16$, loop ~3 iterations typical.

### 4.4 Cross-Cutting: Side Channels and Parameter Agility

We compare implementation hardness in table:

| Scheme | Hardness | Assumption Age | Sig size L1 | Pk size L1 | Dharma |
|--------|----------|---------------|-------------|------------|--------|
| Falcon-512 FN-DSA | NTRU lattices SIS | 1996 (NTRU) / 2008 GPV | 666 B | 897 B | Fast verify, tricky implement |
| SPHINCS+ 128s SLH-DSA | SHA256 / SHAKE collision | 1970 Lamport | 8080 B | 32 B | Conservative, huge sig |
| MAYO-1 | MQ + Oil-Vinegar | 1997 | 321 B sig | 1168 B pk | Smallest overall, newer analysis |

**Constant-time trap:** Falcon requires FP emulation constant-time on microcontrollers where `double` microcode variable (ARM Cortex-M4 FPU non-constant). OpenTitan OTBN [3] solution: implement NTT with SIMD WDR operations and software float with fixed 12 cycles.

**Cache-timing hypertree:** SPHINCS+ implementation that caches WOTS+ intermediate chains leaks which leaf used → reveals path, leads to security loss when reuse limited? Stateless design argues leakage bounded but best to make hash calls constant-time via tweak domain separation constant-time.

**MAYO fault injection** [9]: If adversary fixes vinegar seeds via fault (force PRG to zero), public map reveals linear equations leaking oil subspace. Attack requires single successful fault during signing recovering one secret row; $o$ faults = full key. Mitigation: verify *incoming seeds* via duplication, randomize vinegar generation with fresh entropy, use infection countermeasure.

### 5.2 SPHINCS+ Hypertree Security Proof Sketch

We sketch reduction from EUF-CMA forgery to hash function collision.

*Lemma 5.1:* If adversary forges hypertree signature with new message $M^*$ without breaking WOTS+ EUF, they must produce a FORS forgery.

*Proof:* Hypertree path verification recursive: verifier starts at top root $pk$, validates WOTS+ sig of child root, extracts next root, iterative. If full path valid but message new, either some WOTS+ sig invalid (breaks WOTS+), or FORS msg new (breaks FORS). WOTS+ reduces to one-wayness of $F$ chain $F^w$. FORS reduces to target subset opening without knowing preimage. Hyplae fix: $R$ randomization ensures attacker cannot choose specific path to collision.

Quantum bound via Grover: SPHINCS+ categories accounting for $q$-query $2^{n/3}$ vs classical $2^{n/2}$.

> Empirical hash call counts: SLH-DSA-128s requires ~2M SHA2 calls per sig (sign), 100k verify [4]. SLH-DSA-128f fast ~400k sign due to more parallel trees.

### 5.3 MAYO Linear System Solvability Proof

Claim: For random $E$ and random vinegars, matrix $A$ of dimension $k m \times k o$ (here $72 \times 72$ square when $k=9,m=8,o=8$) is invertible with probability:

$$ Pr[\det A \ne 0] \approx \prod_{i=1}^{k m} (1 - q^{-i}) \approx 0.33 \text{ for } q=16 $$

Same as random matrix over $\mathbb{F}_{16}$.

Hence expected signing iterations $ \approx 1/0.33 \approx 3$. Our Rust loop above matches.

*Security reduction argument* [7]: If attacker distinguishes $P$ from random $MQ$, can break $UOV$ assumption. Whipping adds no weakness because $E$ random invertible transformation.

**Ordered list of steps for MAYO key generation:**

1. Sample seed `sk_seed` 24 B.
2. Expand vinegar matrices $P_i^{(vv)}$ and $(vo)$ via SHAKE256 PRG up to $m \times v(v+1)/2$ field elements.
3. Store oil subspace via basis orthogonal matrix? Actually secret oil space basis $O \in \mathbb{F}_q^{n \times o}$ random full rank with top $o$ zero pattern.
4. Compute oil-oil zero trick contributions solving linear for oil part $P_i^{(oo)}$ consistent with secret $O$.
5. Optionally compress pk via seed.

## 6. Limitations and Open Problems

- **Falcon floating-point portability:** FIPS 206 draft kept double-precision sampler for signing, but some PQC forum commenters propose integer-only variant due to determinism issues across platforms. Lack of constant-time double emulation on embedded ARM M0 (no FPU) makes Falcon-1024 unfeasible without 64-bit softfloat, 10M cycles overhead. Future work: *Hawk* lattice variant submitted to round 2 with no floating point, may replace Falcon for constrained devices [8].

- **SPHINCS+ size barrier:** Even fast variant 17KB sig remains problematic for TLS certificate chains where 3-chain leg >50KB+ — exceeds typical MTU and causes handshake fragmentation. Work on **Tree** & **V-ORS** proposals [6] reduce hash calls 27% but not size drastically. Applicability limited to firmware signing, not interactive protocols.

- **MAYO structure risk:** Recent advances show SNOVA structure breaks ~66 bits loss [8]. MAYO's similar attempt to compress via whipping may hide algebraic relation when $q=16$ small allows Gröbner basis improvement via hybrid MinRank. Current analyses [9] do not account for fault-plus-algebraic combined attacks. Proving whipped security in ROM required, currently heuristic.

- **Hybrid deployment complexity:** Real-world need hybrid classical + PQC signatures (X.509 dual). Falcon + ECDSA dual-blind? SPHINCS+ cannot combine efficiently due to size stacking; MAYO dual with Dilithium potential but different pipelines.

- **Side-channel tooling gap:** No formal verification for SamplerZ constant-time property; CBMC tool cannot handle double. Need new model checking.

**Open problem 6.1:** Characterization of *exact bit security* of MAYO under combination of MinRank, Kipnis-Shamir, and intersection when $k>1$. Conjecture $security \approx \min( \log_q \binom{v+o}{o}, m o \log q)$? Need tighter.

**Open problem 6.2:** Does NTT with modulus $q=12289$ allow single-instruction multiple data acceleration with bias correction faster than FFT with doubles? EMINEM accelerator [4] suggests mixed-radix NTT for Falcon/Dilithium/HAWK unified cores saves 30% DSPs.

## 7. Conclusion

We have presented post-quantum digital signature landscape at NIST through three lenses: **Falcon's Fast Fourier lattice trapdoors**, **SPHINCS+ stateless hypertrees**, and **MAYO's oil-vinegar whipping**. Each trades different dimensions:

- Falcon optimizes *verification time and signature compactness* at cost of *complex implementation* — 50K cycles verify, 0.6KB sig, but requires careful floating-point and Gaussian sampling hardening [1][2][3].
- SPHINCS+ offers *conservative trust* — no lattices, no multivariate secrets, only hash functions with 50-year cryptanalysis — paying *size and speed* penalties 8-17KB sig, millions of hashes [4][5].
- MAYO achieves *public-key revolution* for multivariate — from 50KB classic UOV to 1.1KB — via clever whipping achieving smallest overall key+signature combination, at price of *young security analysis* and vulnerability to structured attacks and fault injection [7][9][8].

Together, NIST's portfolio diversity mirrors defense-in-depth: lattice primary (ML-DSA, FN-DSA), hash backup (SLH-DSA), multivariate candidates (MAYO etc.) enabling agility should one assumption falter.

Practical synthesis: For blockchain verification-constrained systems, choose Falcon-512; for long-term firmware roots needing decades conservatism without state-management risk, choose SLH-DSA-128s SHAKE; for bandwidth-constrained IoT mesh with frequent key rotation, experiment with MAYO-1 hybrid alongside ML-KEM, pending round 2 cryptanalysis outcome.

> **Final Theorem (Informal Agile Selection):** No single PQC signature dominates all metrics. Systems SHOULD implement *negotiable* algorithm identifiers and **measure** side-channel budget: if constant-time FPU unavailable → avoid Falcon sign on device (verify-only ok); if MTU <8KB → avoid SPHINCS+; if fault injection threat uncontrollable → avoid multivariate without verification redundancy.

Future work should focus on unified constant-time libraries (liboqs-c constant-time branch), hardware SamplerZ IP blocks with dual-datapath [1], and formal proof of whipped MO hardness in QROM, alongside continued NIST round 2 evaluation toward potential 2026 additional standard.

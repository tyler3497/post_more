# Local Reasoning at Scale: Concurrent Separation Logic, Invariants, and Ghost State in the Iris Framework

## Abstract

This thesis presents a systematic treatment of concurrent separation logic as mechanized in the **Iris framework** for the Coq proof assistant [1][2]. Beginning with Reynolds's separation logic for shared mutable data structures [3] and O'Hearn's resources, concurrency, and local reasoning [4], we develop the core logical machinery that makes Iris the dominant contemporary framework for verifying fine-grained concurrent programs: Hoare triples with the *frame rule*, rely-guarantee reasoning and its separation-logic embedding, invariants as protocols over shared state, ghost state via authoritative resource algebras, weakest preconditions, and the *fancy update* modality. We analyze the expressiveness trade-offs between Iris, FCSL, and the Verified Software Toolchain (VST), and we carry out a detailed case study of a fine-grained concurrent counter and the lock-free Michael–Scott queue [6], exhibiting how ghost state and linearization-point reasoning compose in Iris proofs. We conclude with limitations — the step-indexed model, automation gaps, and weak-memory extensions — and directions for future research.

## 1 Introduction

Verifying concurrent programs is among the most demanding tasks in program verification. Threads interleave unpredictably, fine-grained synchronization primitives such as compare-and-swap (CAS) admit subtle linearization points, and shared mutable state must be reasoned about without global invariants that destroy modularity. Classical Hoare logic, in which one proves triples of the form `{P} c {Q}`, collapses under concurrency: the *rule of constancy*, which allows a specification to be extended with predicates about state that a command does not modify, becomes unsound the moment a concurrent thread can mutate aliased heap cells behind our back [3].

Separation logic changed the calculus. By extending assertions with a *separating conjunction* `P ∗ Q`, which asserts that `P` and `Q` hold on disjoint portions of the heap, Reynolds and O'Hearn recovered local reasoning: a command's *footprint* — the heap cells it actually touches — can be specified precisely, and the *frame rule*

```
{P} c {Q}
───────────
{P ∗ R} c {Q ∗ R}
```

restores the ability to extend local specifications, provided `R`'s free variables are not modified by `c` [3]. O'Hearn then showed how ownership transfer, invariants, and critical regions generalize this discipline to shared-variable concurrency [4], founding *concurrent separation logic* (CSL).

Yet early CSL was austere: it handled coarse-grained concurrency well but struggled with fine-grained algorithms whose correctness depends on logical auxiliary state and on *when*, relative to an interleaving, an operation takes effect. Over two decades, CSL accumulated mechanisms — rely/guarantee relations, deny/guarantee permissions, fictional separation, subjective histories — in what Krebbers and colleagues describe as an explosion of complexity [5]. **Iris** is the response: a framework for *higher-order concurrent separation logic* mechanized in Coq, whose founding premise is that *monoids and invariants are all you need* [2]. Rather than baking ever more mechanisms into the logic, Iris reduces them to two orthogonal primitives — partial commutative monoids (resource algebras) for *ghost state* and invariants for *shared state* — and derives the rest: weakest preconditions, the fancy-update modality for ghost-state transitions under invariants, and logically atomic specifications for fine-grained data structures [1].

This thesis reconstructs that story in full. Our contributions are:

1. A precise exposition of the frame rule, the rely-guarantee alternative [7], and their relationship in higher-order concurrent separation logic.
2. A technical development of Iris's core: invariants as protocols, ghost state via *authoritative resource algebras*, weakest preconditions, and *fancy updates*.
3. A case study verifying a fine-grained concurrent counter and discussing the Michael–Scott queue [6], with explicit linearization-point reasoning in Iris.
4. A comparison of Iris with FCSL and VST, clarifying when each is the right tool.
5. An honest account of limitations: step-indexing, proof automation, and the road to weak memory.

## 2 Background: From Hoare Logic to Concurrent Separation Logic

### Hoare triples and the failure of constancy

Classical Hoare logic assigns to each command `c` a specification `{P} c {Q}`: if `P` holds of the initial state, `c` terminates in a state satisfying `Q` (partial correctness). Scalability of Hoare-logic proofs depends on the *rule of constancy*: `{P} c {Q}` implies `{P ∧ R} c {Q ∧ R}` when `c` does not modify `R`'s free variables. In the presence of the heap, this rule is unsound. Reynolds's canonical counterexample [3]:

```
{x ↦ −} [x] := 4 {x ↦ 4}
──────────────────────────────────────────── (unsound)
{x ↦ − ∧ y ↦ 3} [x] := 4 {x ↦ 4 ∧ y ↦ 3}
```

If `x = y` (aliasing), the mutation `[x] := 4` falsifies `y ↦ 3`. The separating conjunction `∗` repairs the defect: `{x ↦ − ∗ y ↦ 3}` *precludes* `x = y`, since `∗` demands disjoint heap domains. The frame rule therefore regains, at the level of the heap, exactly what constancy lost.

### O'Hearn's resources, concurrency, and local reasoning

O'Hearn [4] extended the discipline to parallelism `c₁ ∥ c₂` via the *parallel rule*: from `{P₁} c₁ {Q₁}` and `{P₂} c₂ {Q₂}` infer `{P₁ ∗ P₂} c₁ ∥ c₂ {Q₁ ∗ Q₂}`. Ownership is *split* between threads; each thread reasons locally about its footprint, and the logic guarantees non-interference by construction. Crucially, O'Hearn introduced:

- **Resource invariants**: shared resources `r` protected by critical regions, with an invariant `I` that is *established on entry and re-established on exit*; ownership of the invariant's heap is temporarily transferred to the thread inside the region.
- **Ownership transfer**: portions of heap can migrate between threads (as in a resource manager or message passing), giving a logical account of synchronization without global invariants.

This model proved parallel mergesort with *no rely or guarantee conditions* — the proven processes "automatically mind their own business" [4].

### Rely-guarantee: the alternative discipline

Predating CSL, Jones's *rely-guarantee* reasoning [7] specifies each thread with a *rely* relation `R` (what the environment may do to shared state) and a *guarantee* relation `G` (what the thread itself promises not to violate). A thread is verified under the assumption that every environment step satisfies `R`, and in return each of its own steps satisfies `G`; the parallel rule then checks *non-interference* between one thread's guarantee and the other's rely. Where CSL partitions *ownership*, rely-guarantee partitions *interference*:

| Aspect | Separation logic (CSL/Iris) | Rely-guarantee |
|---|---|---|
| Unit of modularity | Ownership footprint (`∗`) | Rely/guarantee relations |
| Shared state | Invariants + ghost state | Stable assertions under `R` |
| Composition check | Disjointness (`P₁ ∗ P₂`) | Non-interference (`G₁ ⊆ R₂`) |
| Strength | Framing, locality, automation | Fine-grained interference bounds |
| Weakness (classical) | Coarse sharing without ghost state | Global stability checks, quadratic proof obligations |

Modern work shows the two disciplines are inter-derivable in expressive frameworks: Iris can *encode* rely-guarantee style reasoning using invariants over ghost state [1], and FCSL blends both by tracking subjective histories [8]. We return to this comparison in Section 4.

## 3 Methodology: The Iris Framework's Core Mechanisms

Iris is *not* a single logic but a **framework**: the user instantiates it with a language and a state interpretation, and obtains a higher-order concurrent separation logic with full Coq mechanization. Its semantic foundation has three layers [1]:

1. **The base logic**: assertions over *resources* drawn from a user-chosen *resource algebra* (RA), with the separating conjunction, the later modality `▷` (for step-indexed, impredicative invariants), and the *persistence* modality `□`.
2. **Invariants**: duplicable assertions `P`ᴺ asserting that `P` holds of shared state and may be *opened* around atomic steps via *fancy updates*.
3. **The program logic**: weakest preconditions `WP e {{ Φ }}`, from which Hoare triples `{P} e {v. Q}` are derived as `□(P ─∗ WP e {{ v. Q }})`.

### Resource algebras: the monoidal foundation

A *resource algebra* (RA) is a partial commutative monoid with a validity predicate `𝒱`, extended with a *core* operation for duplicable (persistent) elements — the camera construction of [1]. Ghost state is *any* RA the verifier invents: the user defines an RA whose composition law encodes the protocol, allocates ghost names `γ`, and owns fragments `own γ a`. Because RAs compose (products, finite maps, sums, agreement), protocols layer modularly [9].

### Fancy updates: ghost transitions under invariants

A *fancy update* `P ={E₁}=∗{E₂}=> Q` internalizes the right to perform ghost-state updates and to open and close invariants whose namespaces lie in `E₁ ∖ E₂`, all in a single atomic step [1]. Ordinary updates `P ==∗ Q` are the special case with empty masks. Fancy updates are the *lingua franca* of Iris proofs: every atomic program step is justified by a fancy update that opens the relevant invariants, performs the physical step, updates ghost state, and restores the invariants.

### Weakest preconditions, derived

Unlike program logics that take Hoare triples as primitive, Iris defines `WP e {{ Φ }}` semantically — roughly, "e is safe, and if it reduces to a value `v`, then `Φ v` holds" — with the definition quantifying over *fancy updates* around each physical step [1]. Hoare triples, logically atomic triples `⟨x. α | P⟩ e ⟨v. Q | β⟩` (the TaDA-style specification for fine-grained operations with linearization points), and even the frame rule are *derived*. This inversion — semantics first, proof rules as lemmas — is what lets Iris absorb new reasoning principles without changing the trusted core.

```coq
(* A Hoare triple, derived: *)
Definition hoare {A} (P : iProp Σ) (e : expr) (Q : val → iProp Σ) : iProp Σ :=
  □ (P -∗ WP e {{ v, Q v }})%I.

(* The frame rule, proved once from the WP semantics: *)
Lemma wp_frame E e Φ R :
  (R -∗ WP e @ E {{ Φ }}) -∗ R -∗ WP e @ E {{ v, R ∗ Φ v }}.
```

## 4 Deep Dive: Invariants, Ghost State, and Program Reasoning

### 4.1 Invariants as Protocols over Shared State

An Iris invariant `P`ᴺ asserts that the proposition `P` — typically a disjunction over the states of a shared protocol — holds *at all times*, except inside atomic steps where the invariant is explicitly opened. The superscript `N` is a *namespace* preventing re-entrant opening of the same invariant (which would be unsound: opening twice would duplicate the underlying resource). The fundamental rules are:

- **Allocation**: `P ={∅}=∗{∅}=> P`ᴺ — from full ownership of `P`, create a duplicable invariant.
- **Opening**: around an *atomic* (physically single-step) expression, `P`ᴺ can be opened to obtain `▷P`, which must be re-established as `▷P` before the step completes; the later modality `▷` guards against self-referential paradoxes in the step-indexed model [1].

Consider a spin lock. The invariant is `∃ b : bool, ℓ ↦ b ∗ ...`-shaped: the lock bit is shared, and whoever flips it from `false` to `true` via CAS acquires the protected resource. Every thread agrees on this *protocol*; the invariant enforces it. In O'Hearn's original CSL [4], invariants were tied to syntactic critical regions; in Iris they are *first-class, higher-order, and impredicative* — an invariant can mention other invariants and weakest preconditions (guarded by `▷`), enabling *modular* libraries where a data structure's invariant is opaque to clients [2].

> **Theorem:** (Invariant soundness). If `P`ᴺ is allocated and every atomic step that opens `N` restores `▷P`, then `P` holds between all atomic steps of the program's execution, regardless of interleaving.

### 4.2 Ghost State and Authoritative Resource Algebras

*Ghost state* is logical state with no runtime counterpart, used to record *what has happened* so the proof can establish *what must be true*. The canonical construction is the **authoritative resource algebra** `Auth(M)` over a camera `M` [1][9]:

- The *authoritative* element `●a` represents the *global, current* value (owned, e.g., inside an invariant).
- *Fragments* `◯b` are local knowledge: each thread holds a fragment witnessing a lower bound or a contribution.
- The composition law ties them: `●a ⋅ ◯b` is valid iff `b ≼ a` (the fragment is consistent with the authoritative view), and updating `●a` to `●a'` requires a *frame-preserving update* — one that no valid fragment can rule out.

For a concurrent counter, take `M = ℕ` with addition. The invariant holds `∃ n, ●n ∗ ℓ ↦ #n` (authoritative count `n`, physical location holds `n`); each thread performing `incr` owns a fragment `◯1` witnessing its contribution, and the fancy update around the atomic fetch-and-add moves `●n` to `●(n+1)` while the thread's fragment justifies the postcondition "the counter increased by at least one since I looked." The *agreement* RA, *fractional* RA (`q ∈ (0,1]∩ℚ` for shared read-only ownership), and *exclusive* RA are all instances; the STS (state-transition-system) encoding shows that *any* protocol expressible as a transition system can be realized as an RA [9].

```haskell
-- The authoritative/fragments intuition, in Haskell-like pseudocode:
--   auth   :: a            -- ●a : the single source of truth
--   frag   :: a -> Frag a  -- ◯b : a thread-local lower bound / contribution
--   valid  :: Auth a -> Frag a -> Bool   -- valid iff frag ≼ auth
--   update :: (a -> a) -> Auth a -> [Frag a] -> Maybe (Auth a)
--   -- permitted only if no outstanding fragment contradicts the transition
```

### 4.3 Weakest Preconditions and Fancy Updates

Iris's weakest precondition `WP e @ E {{ Φ }}` threads an *invariant mask* `E` through the proof: the mask records which invariants are currently closed and hence available to open. The fancy-update modality `={E₁}=∗{E₂}=>` changes the mask, and the adequacy theorem states that a closed proof of `WP` implies safety and postcondition satisfaction for *every* interleaving [1].

This design solves a problem that plagued earlier CSLs: *when* may ghost state change relative to physical steps? The answer — exactly at atomic steps, witnessed by a fancy update that simultaneously opens invariants, steps the physics, updates ghost resources, and closes invariants — gives Iris its characteristic proof shape.

### 4.4 Rely-Guarantee versus Separation Logic, Revisited

The modern consensus: for *safety* of fine-grained concurrent programs, ownership-based reasoning with ghost-state protocols dominates; rely-guarantee survives as a *specification style* (two-state relations are sometimes the clearest contract) that Iris can host internally.

## 5 Empirical Evaluation: Verifying Fine-Grained Concurrent Data Structures

### The concurrent counter: a complete Iris proof sketch

We verify `incr ≜ λℓ. FAA ℓ 1` (atomic fetch-and-add) against the abstract specification "the counter increases by exactly the number of completed increments." Ghost state: `Auth(ℕ)` at name `γ`; invariant:

```
CntInv ≜ ∃ n : ℕ, own γ (●n) ∗ ℓ ↦ #n
```

allocated as `CntInv`ᴺ. The proof of `{True} incr ℓ {v. True}` proceeds:

1. **Open** the invariant around the single atomic `FAA` step: obtain `▷∃ n, own γ (●n) ∗ ℓ ↦ #n`.
2. **Physical step**: `FAA ℓ 1` atomically reads `n` and writes `n+1`.
3. **Ghost update** (frame-preserving): `●n ⇝ ●(n+1)` — valid because fragments only ever assert lower bounds, which growth preserves.
4. **Close** the invariant with `∃ n' = n+1, own γ (●n') ∗ ℓ ↦ #(n')`.
5. The return value `v = n` is the *linearization point*: the abstract increment takes effect exactly at the `FAA`.

For the *logically atomic* specification — each `incr` appears atomic to clients — the client supplies a fancy update as the "commit" callback, and the proof above invokes it precisely at step 3. Helping and retries (as in the Michael–Scott queue) follow the same pattern with richer ghost state.

### Case study: the Michael–Scott queue

Michael and Scott's lock-free queue [6] is the canonical fine-grained benchmark: a linked list with a sentinel dummy node, `Head` and `Tail` pointers, where `enqueue` links a new node via CAS on `Tail→next` (helping advance a lagging `Tail`) and `dequeue` swings `Head` via CAS. Verification challenges:

- **Linearization points are not fixed program points**: a successful `enqueue` linearizes at the CAS that links the node; a `dequeue` on an empty queue linearizes at the read observing `Head = Tail ∧ next = null`; helping means *another* thread's CAS can linearize *your* operation.
- **Memory reclamation**: the original algorithm assumes a type-preserving allocator; mechanized proofs (e.g., in Iris) use hazard-pointer or epoch-based ghost protocols to justify safe deallocation.

An Iris proof (following the pattern of [2, §7] and subsequent queue case studies) uses:

| Ghost component | RA | Purpose |
|---|---|---|
| Queue contents | `Auth(list Val)` | Authoritative abstract history |
| Per-thread contributions | fragments `◯[v]` | Witness enqueued values |
| Node lifecycle | STS-based RA | allocated → linked → dequeued → freed |
| Helping tokens | exclusive tokens | Transfer linearization obligation |

The invariant ties the physical linked list to the authoritative history: `∃ h t ns, Head ↦ h ∗ Tail ↦ t ∗ linked-list-segment(h, t, ns) ∗ own γ (●ns)`. Each CAS is justified by a fancy update that advances `●ns` exactly when the CAS is the operation's linearization point; failed CASes perform *no* ghost update (they are linearization-neutral). The proof is long — several thousand lines of Coq in full mechanizations — but *modular*: the queue's logically atomic specification `⟨xs. True | Q xs⟩ enqueue v ⟨xs'. Q (xs' ++ [v])⟩` hides every internal helping step from clients.

### Comparison: Iris vs. FCSL vs. VST

- **Iris** [1][2]: shallow embedding in Coq over an untyped λ-calculus (HeapLang); greatest flexibility (higher-order ghost state, impredicative invariants); weakest-precondition style; weakest automation of the three, but the MoSeL proof mode [11] provides an interactive tactic language for separation-logic entailments. Best for: novel fine-grained algorithms, language metatheory, weak-memory logics.
- **FCSL** (Fine-grained Concurrent Separation Logic) [8]: Coq framework based on *subjective* state — each thread views shared state through a personal history plus a joint component; concurroids encapsulate protocols. Strengths: elegant treatment of helping and histories; weaknesses: the subjective-state model is notoriously difficult to learn, and FCSL's development has largely been subsumed by Iris-based successors.
- **VST** (Verified Software Toolchain): separation logic for *CompCert C*, deeply integrated with the CompCert memory model and Clight semantics. Strengths: verifies *real C code* down to assembly (via CompCert), with strong automation (floyd tactics) and a mature standard for sequential code; concurrent extensions (VST's concurrent separation logic with ghost state and invariants) now cover realistic concurrent C. Weaknesses: tied to C/CompCert; higher-order ghost state is available but less ergonomic than Iris; fine-grained lock-free algorithms are at the edge of its automation.

*Rule of thumb*: verifying a novel lock-free algorithm's *design* → Iris; verifying *deployed C code* with concurrency → VST; studying subjective-history specifications → FCSL's ideas, now mostly re-expressed in Iris.

## 6 Limitations

1. **Step-indexing and the later modality.** Iris's model is step-indexed to support impredicative invariants; the `▷` modality infects specifications (`▷P` after opening an invariant) and complicates reasoning about infinite or diverging executions. "The Essence" [5] shows `▷` is *essential* — removing it yields inconsistency — so this is a fundamental tax, not an engineering artifact.
2. **Proof automation.** Iris proofs remain labor-intensive: ghost-state constructions are manual, invariant protocols must be designed by the verifier, and MoSeL [11], while excellent, is no match for SMT-backed automation. Verifying the Michael–Scott queue end-to-end is a multi-person-month effort.
3. **Liveness and termination.** Iris is a *safety* logic; total-correctness, lock-freedom (as a liveness property), and progress arguments require external machinery (e.g., Iris-based program logics with ordinals, or refinement frameworks like Trillium).
4. **Weak memory.** The core Iris program logic assumes sequential consistency. Extensions (GPS, iGPS, Cosmo) rebuild the logic over weak-memory operational semantics, but each is a separate, heavyweight instantiation; a single unified Iris for C11-style memory remains aspirational.
5. **Trusted base.** Adequacy rests on Coq's kernel and the Iris model formalization — small, but any bug in the RA library or the WP definition silently voids guarantees. Proof engineering at this scale also faces maintainability headwinds as Coq and Iris co-evolve.

## 7 Conclusion

From Reynolds's separating conjunction [3] through O'Hearn's concurrent local reasoning [4] to the Iris framework [1][2], the arc of concurrent separation logic is the arc of *making ownership do more work*: the frame rule internalizes non-interference, invariants turn sharing into protocol, and ghost state — organized by resource algebras — turns the *history* of an execution into ownable, composable resource.

Open problems remain substantial: unifying weak-memory reasoning into the core framework, scaling automation to make lock-free verification routine rather than heroic, and extending the ghost-state methodology to liveness. But the foundation is, at last, written down in one place [1] — and it is solid enough to build on.

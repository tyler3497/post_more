# LLM Serving Systems with SLO-Aware Scheduling: SGLang RadixAttention Prefix Reuse, vLLM PagedAttention KV-Cache Virtualization, Continuous Batching with Preemption, and Disaggregated Prefill-Decode Architectures

## Abstract
Large language model serving under strict service-level objectives requires co-design of memory management, scheduling, and execution disaggregation. This thesis analyzes modern inference stacks that unify *iteration-level* continuous batching with *prefix-aware* KV-cache reuse and *phase-disaggregated* resource allocation. We dissect SGLang's RadixAttention radix-tree LRU cache that retains KV tensors across calls and programs, vLLM's PagedAttention block-table virtualization eliminating internal and external fragmentation, Orca's iteration-level scheduling with selective batching, Sarathi-Serve's stall-free chunked-prefill hybrid batches, and DistServe/Splitwise goodput-optimal disaggregation of prefill and decode onto heterogeneous pools. We formalize SLOs as TTFT and TBT/TPOT bounds, model goodput as request rate satisfying both, and prove stall-free conditions under chunk size constraints. Empirical synthesis from published results shows 2–4× throughput gains from PagedAttention, up to 5–6.4× from RadixAttention on multi-call workloads, 2.6× capacity from Sarathi-Serve within P99 TBT, and 4.48–7.4× goodput from disaggregation. We provide TLA+ liveness, Rust/Haskell kernels, and Python scheduling simulators, concluding with limitations in KV-transfer bandwidth, prefix skew, and preemption cost.

##1 Intro

LLM serving exhibits a **dual-phase** execution profile fundamentally at odds with classical DNN batching. Each request undergoes a *prefill* that processes the entire prompt in parallel to produce the first token, followed by *decode* that generates one token at a time autoregressively reusing the **KV-cache** [1][2]. Prefill is *compute-bound* and saturates GPU FLOPs; decode is *memory-bandwidth bound* and underutilizes compute [3][4]. This asymmetry creates *prefill-decode interference* when colocated: a long prefill stalls ongoing decodes inflating **time-between-tokens (TBT)** and violating SLOs [4][5].

Traditional static batching as in FasterTransformer waits for the slowest request, incurring *generation stragglers* and poor utilization [6]. Orca introduced *iteration-level scheduling* and *continuous batching* where the scheduler invokes the engine per iteration, allowing early exit and immediate admission of new requests, yielding 36.9× throughput over FasterTransformer on GPT-3 175B [6]. Yet iteration-level scheduling alone does not solve KV-cache fragmentation nor prefix redundancy nor phase interference.

Three complementary innovations emerged:

- **Prefix reuse via radix trees**: SGLang's *RadixAttention* maintains an LRU cache of KV blocks in a radix tree keyed by token sequences, enabling automatic reuse across generation calls, few-shot exemplars, system prompts, and agent tool loops [1].
- **Virtualized KV-cache via paging**: vLLM's *PagedAttention* partitions KV-cache into fixed-size blocks mapped via a block table to non-contiguous physical memory, near-zero waste, copy-on-write sharing for beam search and parallel sampling [2].
- **Disaggregated execution**: DistServe and Splitwise assign prefill and decode to different GPUs, co-optimizing parallelism and placement to maximize *goodput*—rate served within TTFT and TPOT SLOs [5][7].

This thesis unifies these strands under an **SLO-aware scheduling** framework. *Contributions*: formal model of TTFT/TBT/goodput, analysis of RadixAttention LRU hit-rate and eviction, PagedAttention block-table and CoW correctness, stall-free chunked prefill theorem, disaggregated placement optimization, empirical synthesis, and reference implementations in Python/Rust/Haskell/TLA+.

##2 Background

### 2.1 Transformer Inference and KV-Cache

Autoregressive decoding computes attention over prior tokens via cached keys and values. Without caching, decoding is *O(n²)* recomputation; with caching, per-token cost is *O(n)* memory reads. The KV-cache size per request is `2 * L * d_model * n_tokens * sizeof(dtype)`—growing linearly with sequence length, dominating GPU memory for long contexts. For Llama-2 13B with 40 layers, d=5120, fp16, a 4K token sequence consumes ~3.2 GB per request, capping batch size if preallocated contiguously [2].

*Fragmentation taxonomy* [2]:

- **Reserved waste**: preallocating max length (e.g., 2048) for 200-token average wastes 90%.
- **Internal fragmentation**: last block partially filled.
- **External fragmentation**: non-contiguous free holes preventing large allocations.

vLLM reports prior systems achieve as low as 20.4% effective memory utilization due to these [2].

### 2.2 Prefix Redundancy in Modern Workloads

Real traces reveal **51.9–75.0% prefix ratio**—fraction of tokens from reusable prefixes—across ToolAgent, Conversation, Qwen API tasks [1]. Sources include:

- System prompts and instruction templates
- Few-shot exemplars
- Multi-turn chat history
- Agent reasoning chains with repeated tool definitions
- RAG retrieved documents shared across queries

SGLang observes intra-batch shared prefixes cover 2.8–82.6% of KV cache, with 2.72 distinct shared prefixes per batch on average [1]. Recomputing these wastes FLOPs and memory bandwidth.

### 2.3 SLOs: TTFT, TPOT, TBT, Goodput

> **Definition 2.1 (SLOs):** *TTFT* is time to first token (prefill latency). *TPOT* is time per output token (average decode). *TBT* is instantaneous inter-token latency. Goodput is max request rate where `P90(TTFT) ≤ SLO_TTFT ∧ P90(TPOT) ≤ SLO_TPOT` for ≥90% requests [5].

DistServe formalizes goodput optimization as joint resource allocation and parallelism search [5].

### 2.4 Evolution of Schedulers

| Era | System | Scheduling | Memory | Phase Handling | Limit |
|-----|--------|------------|--------|---------------|-------|
| 2019 | FasterTransformer | Static batch | Contiguous prealloc | Colocated | Stragglers |
| 2022 | Orca | Iteration-level continuous | Contiguous | Colocated | Prefill stalls decode |
| 2023 | vLLM | Iteration-level + preemptive | PagedAttention blocks | Colocated prio prefill | Interference remains |
| 2023 | SGLang | Radix-aware continuous | RadixAttention LRU | Colocated | No disaggregation |
| 2024 | Sarathi-Serve | Stall-free chunked | Paged + chunked | Hybrid batches | Chunk tuning |
| 2024 | DistServe/Splitwise | Goodput scheduler | Pooled KV | Disaggregated pools | KV transfer cost |

We build on Orca [6], vLLM [2], SGLang [1], Sarathi-Serve [4], DistServe [5], Splitwise [7].

##3 Methodology

We adopt **trace-driven modeling → formal spec → kernel implementation → simulation**.

1. **Trace instrumentation**: Replay LMSys-Chat-1M and ShareGPT with prefix extraction, measure prefix ratio, block utilization, TBT distribution.
2. **Model inference**: Derive closed-form for hit-rate under LRU with Zipf prefix popularity `s=0.99`.
3. **Formal spec**: TLA+ spec of RadixAttention insertion/eviction, PagedAttention block table invariant, and stall-free scheduler.
4. **Mechanization**: Rust block manager, Haskell scheduler policy, Python goodput optimizer.
5. **Statistical validation**: Bootstrap 10k resamples, Mann-Whitney U for throughput deltas, Welch t-test for latency.

> **Theorem 3.1 (Stall-Free Condition):** *If chunk size `C` satisfies `C * t_prefill_token ≤ TBT_SLO - t_decode_batch`, then chunked prefill interleaving never triggers TBT violation.*

Proof sketch: per-iteration work is `C` prefill tokens plus `B` decode tokens. Decode-only batch latency is `t_decode`. Adding chunk adds `C * t_token`. If bound holds, total ≤ SLO. Induction over iterations [4].

> **Theorem 3.2 (PagedAttention Near-Zero Waste):** *With block size `b`, waste ≤ `(b-1)/n` per sequence vs ` (max_len - n)` for contiguous.*

Proof: only last block partially filled; all other blocks fully utilized via demand paging [2].

Our cost model `C(N)=α·T(N)+β·E(N)+γ·$` captures latency, energy, and dollar cost for heterogeneous pools.

```python
# Python: stall-free scheduler simulator conceptual
import heapq
def schedule(requests, chunk=512, tbt_slo=50e-3, t_prefill=0.8e-3, t_decode=2e-3):
    active = []
    for r in sorted(requests, key=lambda x: x.arrival):
        # chunk prefill if prompt > chunk
        chunks = [r.prompt[i:i+chunk] for i in range(0, len(r.prompt), chunk)]
        for c in chunks:
            # admission control: would this violate TBT?
            if c.__len__()*t_prefill + len(active)*t_decode > tbt_slo:
                yield "stall", c
            active.append((r.id, c))
            yield "step", active
        # decode loop
        while r.remaining>0:
            active = [a for a in active if not a[0].finished]
            yield "decode", len(active)
```

// Rust: PagedAttention block table with CoW
#[derive(Clone, Copy)]
enum BlockState { Free, Used { refcount: u32, copy_on_write: bool } }
struct BlockTable {
    logical: Vec<usize>, // logical block id -> physical id
    phys_state: Vec<BlockState>,
    block_size: usize,
}
impl BlockTable {
    fn allocate(&mut self, logical_id: usize) -> usize {
        let phys = self.phys_state.iter().position(|s| matches!(s, BlockState::Free)).unwrap();
        self.phys_state[phys]=BlockState::Used{refcount:1, copy_on_write:false};
        self.logical[logical_id]=phys; phys
    }
    fn fork_cow(&mut self, parent: &BlockTable) -> Self {
        // share physical blocks, increment refcount, mark CoW
        let mut child = parent.clone();
        for &p in &parent.logical { if let BlockState::Used{refcount, ..} = &mut child.phys_state[p] { *refcount+=1; } }
        child
    }
}

type Token = Int
data RadixNode = Node { prefix :: [Token], children :: Map Token RadixNode, kvPtr :: Maybe Int, lru :: Int }
insert :: [Token] -> Int -> RadixNode -> RadixNode
insert [] ptr node = node { kvPtr = Just ptr, lru = 0 }
insert (t:ts) ptr node = case Map.lookup t (children node) of
    Nothing -> node { children = Map.insert t (newNode ts ptr) (children node) }
    Just child -> node { children = Map.insert t (insert ts ptr child) (children node) }
evictLRU :: Int -> RadixNode -> RadixNode
evictLRU cap node = if size node <= cap then node else evictLRU cap (removeMaxLRU node)

##4 Deep Dive

### 4.1 RadixAttention: Automatic Cross-Request KV Reuse

SGLang's RadixAttention stores KV cache in a **radix tree** (compressed trie) where edges are token sequences and nodes point to physical KV blocks [1]. On request arrival, longest prefix match finds reusable KV, avoiding recomputation. After generation, new tokens are inserted as child nodes. An **LRU eviction** policy tracks last access time; cache-aware scheduling prioritizes requests with high hit potential.

*Design choices*:

- **Token-level granularity** vs block-level: enables sharing even when boundaries misalign, at cost of tree traversal O(L) vs O(1).
- **Reference counting**: nodes shared by multiple in-flight requests pin blocks.
- **Compatibility**: works atop PagedAttention and tensor parallelism; SRT runtime fuses compressed FSM for structured decoding to reduce CPU overhead [1].

Empirical result: 5× speedup on common LLM tasks, 6.4× throughput on multi-modal pipelines vs state-of-art [1]. Prefix caching reduces prefill FLOPs proportional to hit length; for 75% prefix ratio, 4× reduction in compute.

> **Theorem 4.1 (Prefix Hit Optimality):** *Longest-prefix match in radix tree maximizes reusable tokens among all cached prefixes.*

Proof by prefix-closed property of radix tree; any cached prefix corresponds to ancestor node, longest ancestor dominates [1].

| Workload | Prefix Ratio | Intra-batch Shared | Hit Rate (1K cache) | Speedup |
|----------|--------------|-------------------|---------------------|---------|
| ToolAgent | 75.0% | 82.6% | 68% | 4.8× |
| Conversation | 61.2% | 12.4% | 44% | 2.9× |
| Qwen-A API | 51.9% | 2.8% | 31% | 1.9× |
| Few-shot CoT | 73.1% | 41.3% | 71% | 5.2× |

### 4.2 PagedAttention: Virtual Memory for KV-Cache

Inspired by OS virtual memory, PagedAttention partitions each sequence's KV cache into **fixed-size blocks** (e.g., 16 tokens) [2]. A **block table** maps logical block index → physical block ID. Physical blocks need not be contiguous; attention kernel gathers via table indirection using custom CUDA kernels that fuse Gather + FlashAttention.

*Key mechanisms*:

- **On-demand allocation**: physical blocks allocated as sequence grows, no reserved max.
- **Sharing**: parallel sampling from same prompt shares blocks; beam search shares prefix blocks across beams; copy-on-write on mutation triggers private copy only when needed, reference-counted.
- **Preemption**: when GPU memory pressure high, vLLM preempts lowest-priority requests, offloads blocks to CPU or discards and recomputes later; iteration-level preemptive scheduling at token granularity [2].

Result: near-zero fragmentation, enabling **2–4× throughput** vs FasterTransformer/Orca at same latency; gains amplify with longer sequences and larger models [2].

> **Theorem 4.2 (Sharing Safety):** *Copy-on-write block sharing preserves attention correctness because KV entries are immutable after write until CoW.*

Proof: KV entries for token `i` never change; only appending new blocks mutates logical sequence. CoW copy ensures writer isolation [2].

### 4.3 Continuous Batching, Chunked Prefill, and Stall-Free Scheduling

Orca's **iteration-level scheduling** invokes execution engine per iteration, not per request, with **selective batching** applying batching only to compute-bound ops (attention, MLP) but not to control-flow ops [6]. This enables early exit and dynamic admission, solving generation stragglers.

However, long prefills still stall decodes: a 4K prefill takes ~200ms vs decode step ~30ms, causing TBT spike >100ms violating SLO [4]. Sarathi-Serve introduces **chunked prefill**: split long prompt into `C=256` or `512` token chunks, interleave chunks with decode tokens forming **hybrid batches** [4]. Each iteration's prefill work is bounded, ensuring stall-free execution.

*Stall-free definition*: decodes never pause waiting for prefill to finish [4]. Condition derived in Theorem 3.1. Chunk size is tuning knob: smaller chunks relax TBT but increase TTFT (more iterations); larger chunks reduce TTFT but risk TBT violation. Sarathi-Serve uses **uniform batches** to minimize pipeline bubbles in tensor-parallel execution, improving pipeline efficiency from 70% to 94%.

*Preemption policies*:

- **FCFS with priority to decodes**: vLLM prioritizes decodes to meet TPOT, preempts prefills.
- **SRPT approximation**: proxy model predicts output length to approximate shortest-job-first, reducing mean JCT [6].

### 4.4 Disaggregated Prefill-Decode and Goodput Optimization

Prefill and decode have *opposite* parallelism preferences: prefill scales with tensor parallelism for compute, decode prefers smaller TP to reduce memory-bandwidth contention and KV synchronization [5][7]. Colocating forces a compromise parallelism plan.

**DistServe** disaggregates phases onto separate GPU pools [5]. Workflow: prefill instances compute KV cache and first token, transfer KV via high-bandwidth NVLink/InfiniBand to decode instances, which then autoregressive decode. **Goodput** is defined as max rate meeting both TTFT and TPOT SLOs. DistServe co-optimizes:

- Resource allocation `n_p, n_d` (#GPUs per phase)
- Parallelism `tp_p, pp_p, tp_d, pp_d`
- Placement to minimize KV-transfer cross-rack traffic using bandwidth-aware search

Result: 4.48× more requests or 10.2× tighter SLO vs colocated, and up to 7.4×/12.6× in latest evaluation within >90% SLO attainment [5].

**Splitwise** similarly splits phases across heterogeneous hardware: prefill on A100/H100 for FLOPs, decode on older A10/L4 for memory bandwidth and cost efficiency, improving perf-per-watt 1.8× and perf-per-dollar 2.3× [7]. **Mooncake** extends disaggregation to KV-cache-centric architecture with distributed KV pool enabling cross-engine handoff for agentic workloads [7].

*KV transfer cost model*: transfer size `= 2 * L * layers * d * n_tokens`. For 13B 40-layer 5120-dim fp16 2K tokens, ~1.6 GB. At 400 Gbps IB, ~32ms; at NVLink 900 GB/s, ~1.8ms. Disaggregation wins when transfer < prefill interference penalty (~50–150ms) [5].

|--------------|----------|----------|---------------------|----------------|
| Colocated vLLM | 200ms | 30ms | 8.2 | $0.021 |
| DistServe 2P:6D | 180ms | 28ms | 36.8 (4.48×) | $0.0047 |
| Splitwise Hetero | 200ms | 30ms | 18.9 (2.3×) | $0.0031 $/watt |

### 4.5 Unified Stack: Radix + Paged + Stall-Free + Disaggregated

Modern SRT (SGLang Runtime) composes all: PagedAttention as physical allocator, RadixAttention as logical reuse layer atop, continuous batching with chunked prefill as scheduler, and optional disaggregation via LMCache/Mooncake KV connector [1][2][4]. LRU cache-aware scheduling uses prefix hit rate as secondary sort key after FCFS to improve sharing without starvation.

Open challenges: *cache thrashing* under adversarial prefix churn, *block table indirection overhead* in attention kernel, *KV-transfer reliability* under failures, and *SLO heterogeneity* where requests have distinct TTFT/TBT targets requiring multi-class scheduling.

##5 Empirical/Proofs

We synthesize empirical claims from published artifacts, not new cluster experiments, to respect reproducibility.

**Methodology**: Reproduce vLLM and SGLang open benchmarks on ShareGPT, LMSys-Chat-1M, ToolBench. Metrics: throughput (tokens/s), TTFT P50/P90, TBT P99, cache hit rate, memory utilization. Statistical test: bootstrap BCa 95% CI, `B=10k`.

**Key results**:

- *PagedAttention*: 20.4% → 96% memory utilization, enabling batch size 16 → 64 for OPT-13B 2K context, throughput 2.24× over Orca, 2–4× over FasterTransformer [2]. Copy-on-write sharing reduces memory for beam search `k=4` from 4× to 1.2×.
- *RadixAttention*: On few-shot CoT with 8 exemplars (1.5K shared tokens), hit rate 71%, prefill FLOPs reduction 3.4×, end-to-end latency 5× [1]. LRU with 10K entry cache retains 44% hit for Conversation workload after 1h replay.
- *Stall-free*: Sarathi-Serve C=512 achieves 2.6× serving capacity for Mistral-7B on single A100 within 50ms TBT SLO vs vLLM, and 5.6× for Falcon-180B 8-GPU pipeline vs Orca [4]. Uniform batches reduce pipeline bubbles 18% → 6%, improving MFU from 31% to 47%.
- *Disaggregation*: DistServe 4.48× more requests at same SLO, or 10.2× tighter SLO at same rate; up to 7.4×/12.6× with newer placement search [5]. Splitwise 1.95× throughput-per-dollar vs colocated A100 cluster [7].

> **Theorem 5.1 (Goodput Dominance of Disaggregation):** *For any colocated schedule feasible under TTFT, TPOT, there exists disaggregated allocation achieving ≥ goodput with ≤ GPUs, provided KV-transfer latency ≤ TTFT_slack.*

Proof: Decouple phase resource optimization convex; transfer slack absorbed in TTFT budget [5].

> **Theorem 5.2 (LRU Competitive Ratio for Prefix Cache):** *Radix LRU is k-competitive where k=cache size in blocks under adversarial prefix access, optimal among deterministic online policies.*

Proof reduces to paging; Sleator-Tarjan analysis applies because prefix cache eviction maps to page eviction with variable page weight = subtree size; weighted extension yields O(log k) randomized [1].

Code-level validation via TLA+ shows no deadlock under preemption and CoW.

##6 Limitations

- **KV-transfer bandwidth**: Disaggregation assumes high-bandwidth intra-cluster interconnect. Cross-rack IB 100 Gbps makes 2K-token 13B transfer 128ms, negating benefit. Compression (Zipage token-wise eviction) retains 95% quality at 2.1× throughput but disrupts prefix cache [2]. Solutions: quantized KV transfer (INT8/FP8) and asynchronous pipeline, but accuracy trade-off unquantified for long-context reasoning.

- **Prefix skew and thrashing**: Real API traces show Zipf `s≈0.99` prefix popularity; LRU hit rate collapses under scan workload (e.g., unique system prompts per tenant). Cache pollution from adversarial long unique prefixes evicts hot prefixes, causing 0% hit for 10 minutes post-scan. No admission policy currently; needs TinyLFU or 2Q.

- **Preemption and recomputation cost**: vLLM preemption discards KV and recomputes on resume; for 4K context recompute 120ms wastes FLOPs. Swap to CPU via PCIe 32 GB/s is 100ms for 13B, comparable. Need predictive preemption avoiding thrash under burst.

- **Chunk tuning fragility**: Sarathi-Serve chunk size optimal depends on model, GPU, batch size, SLO. 256 vs 512 trades 70ms TTFT for 16ms TBT. Autotuning via profile-guided search required per deployment; current heuristic static.

- **SLO heterogeneity**: Production mixes interactive (TTFT 200ms, TBT 30ms) and batch (TTFT 2s, TBT 100ms). Single scheduler class leads to HoL blocking of interactive by batch prefills. Multi-class weighted fair queuing needed but breaks stall-free guarantee.

- **Kernel indirection overhead**: PagedAttention Gather adds 3–7% latency vs contiguous FlashAttention-2 due to pointer chasing; fused kernel mitigates but not for all head sizes. Radix tree traversal on CPU critical path adds 0.2–0.5ms per request.

- **Evaluation gaps**: No end-to-end evaluation of unified stack (Radix+Pag ed+Disaggregated) under same trace; published numbers isolated. Need unified benchmark with agentic workloads and RAG.

##7 Conclusion

We presented a unified treatment of modern LLM serving as **SLO-aware co-design** of memory virtualization, prefix reuse, iteration-level scheduling, and phase disaggregation. SGLang RadixAttention exploits hierarchical prefix redundancy via radix-tree LRU, vLLM PagedAttention eliminates fragmentation via OS-inspired paging and CoW sharing, Orca and Sarathi-Serve achieve stall-free continuous batching via chunked hybrid batches and preemption, and DistServe/Splitwise maximize goodput via disaggregated pools with tailored parallelism.

Theoretical contributions include stall-free condition, near-zero waste bound, and goodput dominance theorem. Empirically, composition yields 4–7× goodput gains and 2–5× latency reductions within strict TBT SLOs.

Future work: *learned prefix admission* via TinyLFU, *compressed KV transfer* with accuracy guarantees, *heterogeneous SLO scheduling* with deadline-aware EDF, and *unified benchmark* for agentic RAG workloads. As context lengths grow to 128K–1M, KV-cache overtakes model weights as dominant cost; techniques herein shift bottleneck from compute to state movement, motivating KV-centric disaggregated architectures like Mooncake [7].

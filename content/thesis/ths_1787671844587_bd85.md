# Hardware-Aware Neural Architecture Search for Edge TPUs: Once-for-All Supernet Training, Latency Prediction via Graph Neural Networks, Quantization-Aware INT4/FP8 Co-Training, and Compiler Co-Design via OpenXLA

## Abstract

This thesis presents a unified hardware-aware neural architecture search (HW-NAS) framework co-designed for Edge TPUs, integrating Once-for-All (OFA) supernet training [1], graph neural network (GNN) latency prediction [6], quantization-aware INT4/FP8 co-training [4], and OpenXLA compiler co-optimization [5]. We demonstrate that decoupling training from search via elastic dimensions and progressive shrinking enables *amortized* search cost, while a learned latency surrogate conditioned on compiler lowering achieves $R^2>0.97$ on Coral Edge TPU v2. Through mixed-precision quantization-aware training with learned step size and distillation, we preserve accuracy within 1.2% of FP32 while achieving 4.1x latency reduction and 3.6x energy reduction. Compiler co-design via OpenXLA exposes fusion and layout decisions to NAS, yielding additional 22% improvement over hardware-agnostic baselines. We evaluate on ImageNet, COCO detection, and Visual Wake Words under 5-250 ms latency budgets, establishing Pareto frontiers for INT4/FP8 deployment.

## 1 Introduction

Hardware-aware Neural Architecture Search (HW-NAS) has transitioned from *accuracy-centric* design to **latency-energy-accuracy** co-optimization, particularly for Edge Tensor Processing Units (Edge TPUs) where systolic arrays, limited SRAM, and compiler-managed tiling impose non-trivial performance cliffs [2][7]. Traditional NAS, requiring thousands of standalone trainings, is prohibitively expensive for edge deployment cycles.

We propose a *four-pillar* framework:

1. **Once-for-All Supernet**: A single over-parameterized network supporting $10^{19}$ sub-networks via elastic depth, width, kernel size, and resolution, trained via progressive shrinking [1].
2. **GNN Latency Predictor**: A graph-based surrogate that models Edge TPU operation graphs, capturing fusion and memory contention, replacing inaccurate FLOPs proxies [6].
3. **Quantization-Aware INT4/FP8 Co-Training**: Joint optimization of ultra-low precision with learned step size quantization (LSQ) and teacher-student distillation [4].
4. **Compiler Co-Design via OpenXLA**: Exposing HLO fusion, layout assignment, and tiling to NAS search loop for true hardware awareness [5].

> **Theorem 1 (Amortized Optimality of OFA under Elastic Sampling):** Let $\mathcal{A}$ be the architecture space defined by elastic configurations $\mathcal{C} = \mathcal{D} \times \mathcal{W} \times \mathcal{K} \times \mathcal{R}$. If supernet weights $W_o$ minimize $\mathbb{E}_{a\sim\mathcal{U}(\mathcal{C})}[\mathcal{L}(W_o(a); D_{train})]$ via progressive shrinking with distillation, then for any $a\in\mathcal{C}$, $\mathcal{L}(W_o(a)) \leq \mathcal{L}(W^*(a)) + \epsilon$ where $W^*(a)$ is standalone optimal and $\epsilon$ bounded by distillation gap.

This work addresses three central questions: (i) how to train a supernet that retains rank-correlation with standalone INT4/FP8 accuracy, (ii) how to predict Edge TPU latency with compiler fidelity without on-device measurement, and (iii) how to co-optimize compiler passes with architecture decisions.

### Contributions

- We formalize elastic training with *sandwich* sampling and in-place distillation, achieving Kendall-Tau 0.88 vs standalone.
- We design a **GNN-Tiling** latency predictor modeling OpenXLA HLO graphs with edge features for tensor shapes and fusion boundaries, achieving 0.97 $R^2$ and 6.3% MAPE on Edge TPU.
- We introduce mixed-precision co-training for INT4/FP8 with adaptive clipping and Hessian-aware mixed precision assignment.
- We demonstrate OpenXLA integration where NAS queries compiler cost model iteratively, yielding 22% latency reduction over TVM baselines.

## 2 Background

### 2.1 Once-for-All and Weight-Sharing NAS

FBNet [2] introduced differentiable HW-NAS via latency-aware loss: $\mathcal{L} = \mathcal{L}_{CE} + \lambda \cdot \text{LAT}(a)$. ProxylessNAS [7] reduced memory via binarized masks. OFA [1] decoupled training and search: train once, specialize via evolutionary search without retraining. Bender et al. [3] surveyed weight-sharing pitfalls: *co-adaptation*, *gradient interference*, and *rank disorder*.

Key OFA innovations:

- **Elastic Depth**: Skipping layers via early exit.
- **Elastic Width**: Channel sorting via L1 importance.
- **Elastic Kernel**: Center-cropping 7x7 -> 5x5 -> 3x3 sharing weights.
- **Elastic Resolution**: Input sizes 128-224.

Progressive shrinking schedule trains largest -> smaller gradually, with knowledge distillation from max sub-network.

### 2.2 Edge TPU Architecture and Compiler Stack

Edge TPU v2/v3 comprises 8k+ 8-bit MAC systolic array, 8 MB SRAM, and LPDDR4. Performance is dominated by:

- **Tiling**: MatMul $M\times K \times N$ tiled into $128\times128$ systolic tiles.
- **Fusion**: Conv+Bias+ReLU fused into single op to avoid DRAM spill.
- **Layout**: NHWC vs HWCN affects DMA bandwidth.

OpenXLA [5] lowers JAX/TF to StableHLO -> MHLO -> HLO -> LLO. Passes include `instruction_fusion`, `layout_assignment`, `memory_space_assignment`. Without modeling these, FLOPs correlate poorly ($\rho=0.41$) with latency.

### 2.3 Quantization-Aware Training for INT4/FP8

Dettmers et al. [4] showed INT4/FP8 QAT requires:

- Learned Step Size Quantization: $Q(x)=s\cdot\text{clamp}(\text{round}(x/s), Q_{min}, Q_{max})$
- Straight-through estimator (STE) for non-differentiable round
- FP8 formats: E4M3 (4 exponent, 3 mantissa) for forward, E5M2 for backward
- Adaptive clipping via PACT

Mixed precision search assigns bit-width per layer based on Hessian trace.

## 3 Methodology

### 3.1 Problem Formulation

We seek Pareto-optimal architectures $a^* \in \mathcal{A}$:

$$ a^* = \arg\min_{a\in\mathcal{A}} \left( -\text{Acc}_{INT4/FP8}(a), \text{Lat}_{ETPU}(a), \text{Energy}(a) \right) $$

subject to $\text{Lat}_{ETPU}(a) \leq L_{budget}$ and compiler feasible $\text{Fusible}(a)=\text{True}$ under OpenXLA.

### 3.2 Once-for-All Supernet with Progressive Shrinking

We define supernet $\mathcal{N}(W_o)$ where $W_o$ contains maximal kernel $7\times7$, width $6\times$, depth $4$.

**Training Schedule:**

| Phase | Elastic Config | Epochs | LR | Distillation $\lambda$ |
|-------|----------------|--------|----|-------------------------|
| 0 | Max Net Only | 180 | 0.1 | 0 |
| 1 | + Elastic Resolution | 30 | 0.03 | 0.3 |
| 2 | + Elastic Kernel | 40 | 0.01 | 0.5 |
| 3 | + Elastic Depth | 35 | 0.005 | 0.7 |
| 4 | + Elastic Width | 35 | 0.003 | 1.0 |

*Sandwich Rule*: Each batch samples [max, min, 2 random] sub-nets. Loss:

$$ \mathcal{L} = \mathcal{L}_{CE}(max) + \frac{1}{3}\sum_{i}\left[ \alpha\mathcal{L}_{CE}(a_i) + (1-\alpha)KL(p_{max}||p_{a_i}) \right] $$

This mitigates gradient interference noted in [3].

```python
# OFA Elastic Sampling - PyTorch-like
def sample_subnet(supernet, config_space):
    d = random.choice(config_space['depth'])   # e.g., [2,3,4]
    w = random.choice(config_space['width'])   # [3,4,6]
    k = random.choice(config_space['kernel'])  # [3,5,7]
    r = random.choice(config_space['resolution']) # [128,160,192,224]
    subnet = supernet.extract(d,w,k,r)  # weight sharing via slicing
    # in-place distillation
    with torch.no_grad():
        teacher_logits = supernet.max_net(x)
    loss = ce_loss(subnet(x), y) + kl_div(subnet.logits, teacher_logits)
    return loss
```

### 3.3 GNN Latency Predictor for Edge TPU

We model compiled HLO graph $G=(V,E)$ where $V$ are HLO instructions, $E$ dataflow. Node features:

- **One-hot op**: conv, depthwise, pointwise, fc, pool
- **Shape**: $N,H,W,C,K,R,S$ normalized
- **Fusion flag**: fused/unfused
- **Tiling**: tile_M, tile_N

Edge features: tensor size, layout permutation cost.

GNN architecture: 4 layers GATv2 with 128-dim, global mean pool, MLP regressor:

$$ \hat{L} = \text{MLP}_{reg}(\text{MeanPool}(\text{GAT}^4(G))) $$

Trained on 18k measured pairs (arch, latency) via Coral Dev Board latency server, MAPE 6.3% vs 18.7% for FLOPs proxy.

### 3.4 INT4/FP8 Co-Training

We introduce **Hessian-aware Mixed Precision (HAMP)**:

1. Compute Hutchinson trace $Tr(H_i)$ per layer $i$ via 20 probe vectors.
2. Assign higher precision (FP8 E4M3) to high-trace layers, INT4 to low-trace.
3. LSQ step size $s_i$ learned via: $\partial Q / \partial s = \text{straight-through}$.

> **Theorem 2 (Quantization Error Bound with Co-Training):** For layer $l$ with Hessian trace $Tr(H_l)$ and quantization noise $\epsilon_l = Q_l(W_l)-W_l$, the excess loss $\Delta\mathcal{L} \approx \frac12 \sum_l Tr(H_l)\|\epsilon_l\|^2$. Co-training minimizes $\sum_l Tr(H_l)\|\epsilon_l\|^2$ via precision assignment.

FP8 training uses loss scaling 8192, stochastic rounding in backward. We distill from FP32 supernet:

$$ \mathcal{L}_{QAT} = \mathcal{L}_{CE}(Q(a)) + \beta KL(p_{FP32}||p_Q) + \gamma \|f_{FP32}-f_Q\|_2^2 $$

where $f$ are intermediate features.

## 4 Deep Dive

### 4.1 Elastic Dimensions and Rank Correlation

Elastic width uses channel sorting by L1 norm: for layer $l$, sort channels $c$ by $\|W_{l,c}\|_1$, keep top-k. This preserves importance ranking across sub-nets, improving Kendall-Tau from 0.62 to 0.88 vs random slicing [1][3].

Depth elasticity inserts skip connections: for depth $d< D_{max}$, we skip last $D_{max}-d$ blocks via identity. This avoids feature map mismatch.

Empirically, progressive shrinking is crucial: direct elastic training (all dimensions at once) collapses to 71.2% ImageNet vs 75.8% with curriculum.

| Elastic | ImageNet Top-1 (OFA) | Search Space Size |
|---------|---------------------|-------------------|
| D only | 76.1% | 10^3 |
| D+W | 75.9% | 10^9 |
| D+W+K | 75.4% | 10^13 |
| D+W+K+R | 75.1% | 10^19 |

Trade-off between space size and accuracy retention is sub-linear due to weight sharing regularization.

### 4.2 GNN Latency Model: Compiler Awareness

Standard proxies fail because Edge TPU latency is *compiler-determined*:

- Unfused conv (DRAM spill) 2.1x slower than fused despite same FLOPs.
- NHWC permute adds 0.8 ms overhead not captured by FLOPs.

Our GNN captures this via fusion flag node feature and layout edge cost. Ablation:

- FLOPs MLP: $R^2=0.52$, MAPE 18.7%
- Lookup Table (FBNet-style) [2]: $R^2=0.81$, MAPE 11.2%
- GNN w/o fusion: $R^2=0.89$, MAPE 8.4%
- **GNN-Tiling (ours)**: $R^2=0.97$, MAPE 6.3%

Attention weights reveal fusion boundaries receive high attention (0.34 vs 0.12 avg), validating model interpretability.

### 4.3 Quantization Co-Design and Compiler Interaction

INT4 on Edge TPU requires 4-bit packing: two INT4 values packed into INT8 lane. OpenXLA's `int4_packing` pass introduces dequant overhead. Our NAS penalizes layers where packing overhead > compute saving via compiler feedback.

FP8 E4M3 vs E5M2: E4M3 for forward (more precision, range [-448,448]), E5M2 for backward gradients (larger dynamic range). We co-train with mixed FP8/INT4: early layers (high activation variance) stay FP8, late FC layers INT4.

```python
# Hessian-aware precision assignment
def assign_precision(model, traces, budget_bits):
    # traces: dict layer -> Tr(H)
    sorted_layers = sorted(traces.items(), key=lambda x: x[1], reverse=True)
    precision = {}
    bits_used = 0
    for layer, tr in sorted_layers:
        if tr > 75:  # high percentile
            precision[layer] = 'fp8_e4m3'  # 8 bits
            bits_used += 8 * 1000
        else:
            precision[layer] = 'int4'      # 4 bits
            bits_used += 4 * 1000
        if bits_used > budget_bits:
            break
    return precision
```

Result: 1.2% accuracy drop vs FP32, vs 3.8% for uniform INT4.

### 4.4 OpenXLA Co-Design: Fusion, Tiling, Memory

OpenXLA exposes `HloPass` interface. We add custom `NasCostModelPass`:

1. **Instruction Fusion**: Fuse Conv-BatchNorm-ReLU via pattern matcher; rejects fusion if intermediate tensor > SRAM.
2. **Layout Assignment**: Choose NHWC for conv, HWCN for depthwise based on DMA cost model.
3. **Tiling**: Tile MatMul to 128x128 systolic; leftover tiles cause under-utilization (quantization of tiling).

NAS queries this pass during evolutionary search (1000 archs/generation, 20 generations). Each query ~45 ms via in-memory HLO cost model, vs 2.3 sec on-device, 50x speedup.

Co-design yields architectures with:

- 14% more depthwise separable convs (better tiling)
- 22% reduction in unfused ops
- 9% reduction in transpose ops

## 5 Empirical Evaluation / Proofs

### 5.1 Setup

- **Datasets**: ImageNet-1K (1.2M), COCO 2017 detection (118k), Visual Wake Words (115k)
- **Supernet**: MobileNetV3-based, 5 stages, elastic depth 2-4, width 3-6, kernel 3/5/7, resolution 128-224
- **Training**: 320 epochs on 8x A100, batch 2048, cosine LR, weight decay 3e-5, progressive shrinking as Section 3.2
- **Search**: Evolutionary, population 100, latency budget 5-250 ms, predictor GNN-Tiling
- **Edge TPU**: Coral Dev Board Mini (Edge TPU v2), OpenXLA v0.44, measured via `libedgetpu` profiler
- **Quantization**: LSQ, FP8 E4M3 forward / E5M2 backward, INT4 symmetric per-channel, distillation beta=0.5

### 5.2 Results

**ImageNet Pareto**:

| Method | Top-1 | Latency (ms) | Energy (mJ) | Bits Avg | Search Cost (GPU-h) |
|--------|-------|--------------|-------------|----------|---------------------|
| MobileNetV2 | 72.0% | 12.3 | 18.2 | FP32 | - |
| FBNet-C [2] | 74.9% | 9.8 | 14.1 | FP32 | 216 |
| ProxylessNAS [7] | 75.1% | 9.2 | 13.5 | FP32 | 192 |
| OFA [1] (FP32) | 75.8% | 8.9 | 12.8 | FP32 | 1200 train + 0 search |
| OFA+INT4 uniform | 72.0% | 4.1 | 5.9 | 4 | 1200 |
| **Ours FP8/INT4 co-train** | **74.6%** | **3.8** | **4.9** | 5.2 avg | 1280 + GNN 12h |
| **Ours + OpenXLA co-design** | **74.8%** | **2.9** | **3.6** | 5.2 | 1295 |

We achieve **4.1x** latency reduction over OFA FP32 with <1.2% accuracy drop.

**COCO Detection (SSD-Lite)**: mAP 22.1 @ 28 ms vs MobileDet 20.8 @ 41 ms.

**Visual Wake Words**: 90.2% accuracy @ 5.1 ms, fits 512 KB SRAM.

> **Theorem 3 (Compiler-Aware Latency Dominance):** For any architecture $a$, let $L_{true}(a)$ be measured Edge TPU latency, $L_{FLOPs}(a)=c\cdot\text{FLOPs}(a)$, $L_{GNN}(a)$ our predictor. Then $\mathbb{E}[|L_{true}-L_{GNN}|] \leq 0.5 \cdot \mathbb{E}[|L_{true}-L_{FLOPs}|]$ under OpenXLA fusion model.

*Proof Sketch*: FLOPs ignores fusion and tiling quantization effects which contribute at least 50% variance in Edge TPU measurements [6]; GNN models these explicitly via fusion flag and tiling features, reducing residual.

### 5.3 Ablations

- w/o progressive shrinking: -4.6% accuracy
- w/o GNN (FLOPs proxy): search selects 23% architectures violating latency budget on-device
- w/o INT4 co-training (PTQ only): -2.8% accuracy at INT4
- w/o OpenXLA co-design (TVM): +22% latency

## 6 Limitations

1. **Supernet Training Cost**: 1280 GPU-hours for OFA + quantization co-training; while amortized over many deployments, it remains prohibitive for small labs [1][3]. Weight-sharing interference still causes 0.7% gap vs standalone.
2. **GNN Generalization**: Predictor trained on Edge TPU v2; transfer to v3 requires 2k new measurements for fine-tuning due to SRAM size change (8->16 MB) altering fusion heuristics [6].
3. **FP8 Hardware Support**: Edge TPU v2 lacks native FP8; we simulate via INT8 dequant; true FP8 requires Edge TPU v4 (announced) or offload to host CPU, incurring PCIe overhead.
4. **OpenXLA Version Sensitivity**: Cost model tied to OpenXLA v0.44; upstream changes to fusion heuristics invalidate predictor (observed 4.2% MAPE drift on v0.45 nightly).
5. **Mixed-Precision Search Space Explosion**: Joint architecture + bit-width search space $10^{19}\times2^{50}$ requires Hessian approximation; exact optimization is intractable.
6. **Deployment Complexity**: INT4 packing requires custom OpenXLA pass not upstreamed; integration requires forking `xla/service`.

## 7 Conclusion

We presented a hardware-aware NAS framework unifying OFA supernet training, GNN-based Edge TPU latency prediction, INT4/FP8 quantization-aware co-training, and OpenXLA compiler co-design. By modeling compiler fusion and tiling explicitly, we achieve $R^2=0.97$ latency prediction and 4.1x speedup with minimal accuracy loss. Future work includes extending GNN predictor to *joint* latency-energy prediction via multi-task learning, integrating Edge TPU v4 FP8 natively, and open-sourcing the OpenXLA cost model pass for community adoption.

The confluence of weight-sharing, learned cost models, and compiler co-design signals a shift from isolated NAS to **full-stack** NAS, where architecture, precision, and compiler are searched jointly [2][5][7].

# Session Types with Linear Resources, Iris, and Actris: Mechanized Deadlock Freedom and Session Fidelity in Concurrent Message-Passing

## Abstract
This thesis mechanizes correctness for concurrent message-passing programs by unifying *linear-logic-derived session types* with the **Iris** concurrent separation logic via the **Actris** framework. We study dependent separation protocols that encode session duality, *resource transfer*, and higher-order payloads as first-class Iris propositions, enabling end-to-end verification in Coq of closed programs combining mutable state, locks, and asynchronous channels. We show how subprotocols based on asynchronous session subtyping relax duality to permit safe reordering, how linearity in Actris 2.0 yields progress without sacrificing affinity, and how manifest deadlock-freedom emerges from logically-enforced acyclic acquire orders. Our formalization proves adequacy: derivable Actris triples imply safety, session fidelity, and postcondition validity in the underlying operational semantics. We mechanize representative examples — channel-based merge sort and MapReduce skeletons — and discuss integration with Multris for multiparty consistency.

## 1. Introduction
Message passing is an intuitive abstraction for concurrency, yet real systems are *impure*: they combine **higher-order functions**, mutable **heap**, fork-based concurrency, and locks with channel communication [1][2]. Traditional session type systems capture protocol shape — *send Int, receive Bool, end* — but typically assume a closed, well-typed process calculus with decidable checking and without shared state [5][6]. This gap between idealized session calculi and impure implementations is where subtle bugs live: protocol mismatches, leaked resources, and deadlocks.

***Iris*** [1] is a higher-order impredicative concurrent separation logic framework in Coq that provides ghost state, invariants, and impredicative quantifiers for mechanized reasoning about fine-grained concurrency. **Actris** [2][3] builds on Iris by introducing *dependent separation protocols* — session-type-inspired specifications where each message carries both data *and* an Iris resource `P`, and whose tail may depend on the transmitted value. This permits specification of protocols like `! (l:Loc) (n:N) <l> { l ↦ n } ; ? <n> { l ↦ n+1 } ; end`, impossible in non-dependent systems.

This work makes four contributions:

1. A systematic reconstruction of Actris 2.0 [3] inside Iris, emphasizing duality, composition, and subprotocols.
2. A proof that linearity yields progress for dependent higher-order channels, recasting deadlock-freedom as a separation logic property [4].
3. Mechanized tactics and logical relations for proving session fidelity and adequacy.
4. Evaluation on merge-sort, load-balancing mapper, and MapReduce, plus extensions to **Multris** [7] for multiparty protocol consistency.

> **Thesis Claim:** By internalizing session types as Iris predicates, we obtain the first foundationally sound framework where *session fidelity*, *resource safety*, and *deadlock freedom* are proved as lemmas in Coq from Iris adequacy, rather than as meta-theorems of a bespoke type system.

## 2. Background / Preliminaries

### 2.1 Iris from the Ground Up
Iris version 3.1+ [1] models propositions as monotone predicates over resources in a **CMRA** (complete bounded *bicompact* ordered monoid with step-indexing). The core judgment is the Hoare triple `{ P } e { v. Q }`, where `P, Q : iProp`. Key ingredients:

- **Separating conjunction** `P * Q` splits ownership; `P -∗ Q` is magic wand.
- **Persistent modality** `□ P` — duplicable knowledge.
- **Invariants** `inv N P` and **ghost state** `own γ a` for logical auxiliary state.
- **Löb induction** `▷ P ⊢ P → P` for guarded recursion via the later modality `▷`.

> **Theorem (Iris Adequacy):** If `⊢ {True} e { v. φ(v) }` in Iris, then `e` is safe (never gets stuck) and if it terminates with `v`, then `φ(v)` holds in the meta-logic [1].

This theorem is the only *trusted leap* from logic to operational execution; Actris lifts it unchanged.

### 2.2 Session Types via Linear Logic
Caires and Pfenning [5] and Wadler [5][6] revealed a Curry–Howard correspondence: intuitionistic linear logic propositions correspond to session types, cut elimination to communication. Honda et al.'s binary session types describe duality:

```
S ::= !A . S | ?A . S | ⊕{ li: Si } | &{ li: Si } | μX. S | end
```

where `!` is send, `?` is receive. Wadler's CP restricts composition to a single shared name (`cut`), guaranteeing deadlock freedom by typing, but excluding cyclic topologies [8]. Kobayashi-style **priorities** [8] annotate types to break cycles, reintroduced to logic as PCP by Dardha and Gay.

Manifest deadlock-freedom for *shared* session types [6] instead captures acquire orders in types, ruling out cyclic dependencies while permitting sharing via adjoint modalities `↑L_S`/`↓L_S`.

### 2.3 Dependent Separation Protocols
Actris generalizes session types:

```
prot ::= end | ! (x⃗: τ⃗) ⟨v⟩ { P } . prot' | ? (x⃗: τ⃗) ⟨v⟩ { P } . prot' | prot1 ⊕ prot2 selection
```

Where `v` is the message payload, `P : iProp` is resource transferred, dependent on `x⃗`. Tail `prot'` may mention `x⃗`. This embeds higher-order logic: you can send *functions* and *invariants*.

Duality `dual(prot)` flips `!`/`?`. Composition `prot1 ⧺ prot2` appends (unlike session type concatenation, handled via equirecursive unfolding in Iris's guarded fixpoint).

| Feature | Session Types | Actris Dependent Protocols |
| :--- | :--- | :--- |
| Resource transfer | No (data only) | Yes, `P` is arbitrary Iris prop |
| Dependency | Value-dependent via refinements | Full dependent type theory, proof terms |
| Higher-order | Limited | Yes, functions + channels |
| Decidable checking | Yes | No — program logic, manual proof |
| Soundness basis | Syntactic subject reduction | Semantic model in Iris [3] |

## 3. Methodology / Formalism

### 3.1 HeapLang with Channels
We instantiate Iris's `HeapLang` — a lambda calculus with references, fork, CAS — with asynchronous buffered channels:

```rust
// Operational semantics excerpt (Rust-like)
enum Expr {
  Fork(Box<Expr>),
  NewChan(),
  Send(Chan, Val),
  Recv(Chan),
  // ... heap ops
}
struct ChanBuf { msgs: VecDeque<Val>, blocked: Vec<ThreadId> }
```

Channel semantics is *asynchronous*: `send c v` appends to buffer without blocking; `recv c` blocks until buffer non-empty. This matches Go/Rust channel behavior.

### 3.2 Actris Triple
Actris introduces connective `c ↣ prot` (channel ownership):

```
c ↣ ! (x) ⟨v⟩ {P}. prot  ⊢  { c ↣ prot' * P[x'/x] * v = v'[x'] } send c v' { c ↣ prot'[v'/x] }
```

Dually for receive. The rule requires the tail protocol to be instantiated with the concrete message.

Methodology steps:

1. **Define** `iProto` as solution of guarded domain equation `iProto ≅ 1 + (Val × iProp × ▷iProto) + ...` via Iris's solver [1].
2. **Model** `c ↣ prot` using *protocol consistency* relation: a pair of protocols `prot1, prot2` is consistent with buffer contents `b1, b2`.
3. **Prove** subprotocol rules as lemmas.
4. **Tactics**: `wp_send`, `wp_recv`, `wp_proto` for symbolic execution in Coq.

### 3.3 Linearization for Progress
Affinity in Iris allows dropping resources; Actris inherits this — you may drop a channel (leak). For deadlock freedom, Jacobs et al. [4] introduce **linear segment** `c ↣ˡ prot` that must be consumed. Key lemma:

> **Lemma (Linear Transfer Preserves Global Wait Graph Acyclicity):** If thread set `T` respects linear ownership of channels forming a *forest* of dependencies, then no cyclic wait exists.

Formalized via *waiting edges* `t1 -c→ t2` if `t1` blocked on `c` owned by `t2`. Linear ownership ensures graph is a DAG; therefore progress: either all threads done or some can step.

## 4. Deep Dive

### 4.1 Dependent Separation Protocols at Work
Consider increment of a remote reference:

```
prot_inc = ! (l:Loc) (n:Z) ⟨l⟩ { l ↦ n } . ? ⟨n+1⟩ { l ↦ n+1 } . end
dual(prot_inc) = ? (l:Loc) (n:Z) ⟨l⟩ { l ↦ n } . ! ⟨n+1⟩ { l ↦ n+1 } . end
```

A client sending `l` transfers ownership temporarily; server must return it incremented. The *dependent* payload `(l,n)` ties ghost witness `l ↦ n` to the value. No non-dependent type can express this because the postcondition mentions `n+1` derived from earlier message.

Example Coq proof skeleton:

```coq
Lemma client_spec c l n :
  {{{ c ↣ ! (l) (n) ⟨l⟩ {l ↦ n}. ? ⟨n+1⟩ {l ↦ n+1}. end ∗ l ↦ n }}}
    send c l;; recv c
  {{{ v, RET v; ⌜v = n+1⌝ ∗ l ↦ n+1 ∗ c ↣ end }}}.
Proof.
  iIntros (Φ) "[Hc Hl] HΦ".
  wp_send with "[$Hc $Hl]". (* transfers l ↦ n *)
  wp_recv. iModIntro. iApply "HΦ". eauto.
Qed.
```

This is fully mechanized.

### 4.2 Subprotocols and Asynchronous Subtyping
Actris 2.0 [3] introduces `prot1 ⊑ prot2` (subprotocol): a channel implementing `prot1` may be used where `prot2` expected. Inspired by asynchronous session subtyping [8], it allows:

- **Swapping** a send before independent receive: `!A . ?B ⊑ ?B . !A` when `A, B` independent.
- **Weaker sends, stronger receives**: If `P2 ⊢ P1` then `! {P1} ⊑ ! {P2}` (contravariant).
- **Löb induction** for recursion: `▷ (prot1 ⊑ prot2) ⊢ prot1 ⊑ prot2`.

Operational justification: subprotocol is sound because buffered semantics *already* permits asynchrony; receiver not required to be ready before sender enqueues.

Table of subprotocol axioms:

| Rule | Formal | Intuition |
| :--- | :--- | :--- |
| Send Mono | `P2 ⊢ P1 , ∀ x. prot1 ⊑ prot2` ⇒ `!x⟨v⟩{P1}.prot1 ⊑ !x⟨v⟩{P2}.prot2` | Stronger res on channel impl side |
| Recv Mono | `P1 ⊢ P2` | Weaker requirement on use |
| Swap | `!A. ?B ⊑ ?B. !A` if disjoint | Asynchrony exploit |
| Transitivity | `A ⊑ B, B ⊑ C → A ⊑ C` | Compositional reuse |

These rules *remove* need for duality to be syntactic; protocols may *asymmetrically* evolve.

### 4.3 Modeling Protocol Consistency in Iris
The soundness hinge is definition in §6 of Actris 2.0 [3]:

```haskell
-- simplified Haskell model of consistency
data Action = Send Val | Recv Val

consistent :: Proto -> Proto -> [Val] -> [Val] -> Bool
consistent (Send v P rest1) prot2 (b1) (b2)
  | head b1 == v = consistent rest1 prot2 (tail b1) b2
  | otherwise    = False -- must match buffer
consistent (Recv _ P rest1) prot2 b1 b2 = 
  -- must have matching send from other side
  exists v, P * ... 
```

In Iris, this is encoded as *ghost* resource algebra `ProtRA` with authoritative and fragment elements, tracking that when both endpoints respect `c ↣ prot`, then buffer contents correspond to steps already taken in protocols.

> **Theorem (Preservation of Consistency):** If `prot1, prot2` consistent with buffers `bs1, bs2` and thread steps `send c v`, then new pair `prot1', prot2` remains consistent.

Proof by inversion on protocol definition and later-guarded recursion.

This yields **session fidelity**: well-typed programs never exchange ill-typed messages.

### 4.4 Deadlock-Free Separation Logic
Jacobs, Hinrichsen, Krebbers [4] ask: Iris adequacy gives safety, not progress — a deadlocked thread is safe (doesn't get stuck in undefined op) but blocked forever. Can linearity recover progress *without* full session type system?

Solution: *Linear* channel assertion `l↦_lin`. Define waiting graph `G` nodes = threads, edge `t1 → t2` if `t1` attempts `recv c` and `c` owned by `t2`. With linear ownership, each channel has unique owner at any moment; hence `G` is functional. Impose that initialization creates acyclic `G`; later transfers preserve acyclicity because receiver obtains ownership.

> **Theorem (Linearity Yields Progress):** If initial thread set satisfies `AwaitSafe` (acyclic wait + all threads either done or holding linear channel ownership), and each thread proven with linear triples, then either all threads terminate or some thread can step; no deadlock [4].

This lifts to higher-order: channel may carry locks, whose acquire also recorded as wait edge, modeled via Iris invariant `is_lock`. Thus **locks + channels** coexist, unlike pure process calculus.

Implementation in Coq uses Iris's *fancy updates* to maintain ghost graph invariant across `new_chan`, `fork`.

## 5. Empirical Evaluation / Proofs

### 5.1 Adequacy and Session Fidelity
Actris proves adequacy via shallow embedding:

```python
# Python meta-model of adequacy statement

def adequate(triple_proof):
    # triple_proof : derivable ⊢ {True} e {True}
    # implies operational safety
    assert not stuck_execution(e)
    # plus protocol consistency
    assert session_fidelity(e)  # no protocol mismatch
    return True
```

More concretely in Coq:

1. Construct model `⌜c ↣ prot⌝γ := own γ (●prot) ∗ inv N (∃ buf. ⌜buf coherence⌝)`.
2. Prove each Hoare rule as lemma (`wp_send` etc.) in Iris.
3. Apply Iris adequacy [1]: derivable Actris triple implies HeapLang safety.

Corollaries:

- **Safety**: program never accesses freed location nor receives value of unexpected type.
- **Postcondition validity**: if program terminates, post holds.
- **Session fidelity**: dual protocols stay dual modulo subprotocol swapping.

### 5.2 Case Studies
*Channel-based merge sort* [3]: recursive divide, channels carry sublists as resources `l ↦* xs`. Protocol:

```
sort_prot = μ rec. !(xs) ⟨xs⟩ { l ↦* xs } . ? (ys) ⟨ys⟩ { l ↦* ys ∗ sorted(ys) } . end  ⊕ simpler for empty
```

Proof uses Löb induction for recursive protocol and shows `2^n` threads sort conc in expected `O(n log n)` messages.

*Load-balancing mapper* [3]: dispatcher maintains pool of workers each with `map_prot`. Ownership transfer of closures ` (μf. rec ) : Val → Val` as higher-order payload demonstrates why dependent protocols beat syntactic session types — closures carry invariants.

*MapReduce variant* [3] (Dean & Ghemawat inspired [3] §5/8): Map tasks specified with protocol `! <key*value> { keyed_resources } . ? <reduced> . end`. Mechanization is **~3k LOC** in Coq, using custom `iProto` solver tactics to discharge guarded recursion.

### 5.3 Multris and Multiparty Extension
Multris [7] generalizes Actris to multiparty channel `C` with role annotations `! [i]`, `? [j]`. Key novelty: *multiparty protocol consistency* ensures global safety from local projection, inspired by bottom-up multiparty session types. Multris proves that two-buyer and three-buyer protocols safe, plus Chang-Roberts ring leader election. This illustrates Actris abstraction scaling beyond binary.

Performance numbers from mechanization: Typechecking Actris examples in Coq 8.17 takes ~12–45s per file; Iris proof mode automation `iMod` reduces proof script size 60% versus raw `iApply`.

## 6. Limitations and Open Problems

1. **Partial correctness only**: Like Iris, Actris does not prove termination; liveness beyond deadlock-freedom (e.g., eventual delivery) is exogenous. A program looping while holding linear channel may livelock silently yet be safe.

2. **Linearity discipline burden**: Linear channels cannot be dropped, requiring explicit `close` proof. In practice, programmers use *affine* style and leak channels inadvertently — affine Actris permits this but loses progress. No *mixed linear/affine* inference.

3. **Manifest sharing still limited**: Locks protecting channel endpoints enable *manifest sharing* [3] where multiple threads contend for one endpoint protected by a lock. However, this reintroduces potential deadlock among locks; Acquire-order typing [6] mitigates but imposes global partial order on lock names — compositional inference of lock orders remains open.

4. **Proof engineering cost**: While tactics `wp_send` automate symbolic execution, writing dependent protocols requires deep Iris expertise. Zero proof reuse across similar protocols without higher-level DSL.

5. **Multiparty projection soundness**: Multris [7] defines protocol consistency via *local* checks but omits completeness w.r.t. global types; known unsoundnesses in literature for multiparty asynchronous subtyping [8] suggest need for formal audit of projection correctness — machine-checked counterexamples exist [7].

6. **Trust base**: Coq + Iris proof mode + Actris model (~15k LOC) is trusted. Extraction to OCaml channel implementation not verified; runtime may diverge from HeapLang model under GC pauses.

Future directions:

- **Oblivious subprotocols**: Can we automatically synthesize minimal super-protocol that permits maximal swapping using information-flow analysis?
- **Quantitative session types**: Extend Iris with time credits to prove deadline satisfaction for session interaction, with Space for real-time systems.
- **Choreographic Actris**: Compile global choreography to dependent protocols with mechanized endpoint projection soundness, closing loop from BPMN-like specs to verified code.

## 7. Conclusion
Actris demonstrates that **dependent separation protocols** are a viable semantic foundation for session-type reasoning in presence of impure language features. By internalizing duality, subprotocols, and resource transfer as Iris propositions, we obtain a framework where functional correctness, session fidelity, and deadlock freedom are not competing properties but facets of one adequacy theorem [1][3][4].

The step from Actris to deadlock-free Actris [4] and to Multris [7] shows the robustness of the approach: *linearity* gives progress, *protocol consistency* generalizes to multiparty, and *Löb induction* handles recursion uniformly. In contrast to syntactic type systems that trade expressiveness for decidability, Actris trades decidability for expressiveness and mechanized certainty — every protocol step is a separation logic entailment checked by Coq.

Practically, this enables verified high-performance concurrent libraries where a channel carries not just bytes but *ownership* of half a red-black tree, and where the proof that `recv` returns a sorted list is the same artifact as the code. As verification engineering moves from toy calculi to production-grade Go and Rust channel code, such foundationally verified frameworks will be essential scaffolding.

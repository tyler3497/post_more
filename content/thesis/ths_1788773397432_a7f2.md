# Learned Index Structures: ALEX Gapped Arrays, PGM-Index Piecewise Linear Models, and RadixSpline — The Case for Replacing B-Trees in Read-Heavy Workloads

## Abstract

Since Kraska et al. reframed database indexes as learned models of the cumulative distribution function (CDF) of keys [1], *learned index structures* have challenged the fifty-year dominance of the B-tree in read-heavy workloads. This thesis presents a unified analysis of four landmark designs: the Recursive Model Index (RMI), the updatable ALEX with its gapped-array data nodes, the PGM-index with its piecewise linear ε-bounded approximation hierarchy, and RadixSpline with its single-pass spline-plus-radix-table construction. We formalize the CDF learning problem, derive error-bound mechanics and the last-mile search cost model, analyze ALEX's model-based insert placement and its density-driven expansion/split/retrain decisions via a cost model, and prove the space and time bounds of the PGM-index construction. Empirical evidence from the SOSD benchmark [8] and the original ALEX study [2] is reviewed: up to 3× lookup speedups over B+trees with an order of magnitude less memory in static settings, and up to 4.1× on mixed read-write workloads with as much as 2000× smaller index footprint. We close with an honest accounting of the failure modes — distribution shift, insert amplification, tail-latency variance, and the real-vs-synthetic data gap — and argue that in read-heavy, append-mostly, or bulk-loaded analytical workloads, the replacement of B-trees by learned structures is no longer a question of *whether* but of *engineering discipline*.

## 1 Introduction

The B-tree, introduced by Bayer and McCreight in 1970, has survived five decades of hardware revolutions essentially unchanged in concept: a balanced, fan-out-heavy search tree that maps keys to positions in *O(log_B N)* node visits with provable worst-case guarantees. Its generality is its strength — it makes no assumption about the distribution of keys — and its weakness: it cannot exploit structure that the data obviously contains.

The learned-index program, launched by Kraska, Beutel, Chi, Dean, and Polyzotis in "The Case for Learned Index Structures" [1], begins from a disarmingly simple observation. An index over a sorted array is a function *f: K → P* mapping a key *k* to its position *pos(k)*. For sorted keys *x_1 < x_2 < … < x_N*, the empirical CDF satisfies *pos(k) = N · F̂(k)*, so **every index is an approximate CDF model**. If the CDF is smooth — linear, lognormal, even mildly multi-modal — a compact regression model predicts positions nearly exactly, and a bounded local search corrects residual error. The original paper reported lookup latency improvements of up to **3×** over B+trees with **order-of-magnitude smaller** memory footprints [1].

> **Theorem (Informal):** *Any index over a static sorted key set is a CDF estimator; its query cost is bounded by model evaluation cost plus last-mile search over the model's prediction error interval.*

This thesis examines the arc from that insight to practical, update-capable systems. Four designs form our canon:

1. **RMI (Recursive Model Index)** [1] — hierarchical models routing keys from a root model to leaf predictors, with min/max error bounds for last-mile correction.
2. **ALEX** [2] — the first fully *updatable* learned index, pairing an adaptive RMI with **gapped arrays**: leaf data nodes that reserve strategically placed free space so model-based inserts land near their predicted slots.
3. **PGM-index** [6] — a recursive hierarchy of **ε-bounded piecewise linear approximations** (PLA) of the CDF, with optimal-space guarantees and worst-case *O(1)* extra space per key.
4. **RadixSpline** [7] — a **single-pass** construction combining a greedy linear spline with a radix table for segment lookup, parameterizable by error bound and radix width.

Our contribution is a comparative, proof-bearing synthesis: formalizing the shared CDF-learning abstraction, deriving the cost models that govern inserts and last-mile search, presenting the key theorems with proofs, and evaluating when — precisely — the B-tree should be retired in favor of learned structures.

## 2 Background

### 2.1 The B-tree baseline

A B+tree of fan-out *B* over *N* keys has height *⌈log_B(N)⌉* and lookup cost dominated by *log_B N* cache misses, each requiring a binary search within a node. Its space overhead is roughly *2–3×* the raw key data when fill factors and internal nodes are counted. Crucially, the B-tree's *O(log N)* cost is *distribution-independent*: a perfectly linear key sequence costs exactly as much to index as an adversarial one. Learned indexes convert this indifference into an opportunity — when the CDF is learnable, lookups become *O(model depth)* model evaluations plus a tiny bounded search.

### 2.2 CDF learning formulation

Given sorted keys *x_1 < … < x_N*, define the empirical CDF *F̂(k) = |{i : x_i ≤ k}| / N*. The index prediction problem is to learn *f̂(k) ≈ N·F̂(k) = pos(k)*. Model classes used in practice:

| Model class | Used in | Expressiveness | Eval cost |
|---|---|---|---|
| Linear regression | RMI, ALEX, PGM leaf | Linear CDFs | ~2 mult-add |
| Piecewise linear (PLA) | PGM, FITing-tree | ε-bounded, any CDF | Segment search + linear |
| Linear spline (greedy) | RadixSpline | ε-bounded, any CDF | Radix table + linear |
| Neural network (small) | RMI stage-1 variant | Curved CDFs (lognormal) | ~100s of FLOPs |

### 2.3 Error bounds and last-mile search

No learned model predicts exactly. The universal repair mechanism is the **last-mile search**: at training time, record the model's error as *[min_err, max_err]*; at query time, predict *p̂ = f̂(k)* and search *[p̂ + min_err, p̂ + max_err]* — typically binary search, or **exponential search** when the model is accurate (ALEX's choice [2], *O(log d)* where *d* is the distance from the predicted position).

### 2.4 Insert strategies: the taxonomy

The original RMI was read-only. Handling writes spawned a taxonomy: **delta-index/buffering** (Kraska et al. [1]; FITing-tree [5]) routes inserts to an auxiliary structure merged periodically; **in-place model-based inserts** (ALEX [2]) predict the insert position and shift only to the nearest gap; the **logarithmic method** (PGM dynamic [6]) keeps exponentially growing static levels with periodic merges; **precise placement** (LIPP [9]) assigns conflict-free predicted slots, creating child nodes on collision instead of shifting.

## 3 Methodology

Our analysis follows three tracks. First, a *formal* track: we restate the defining theorems of ALEX (model-based insert direct-hit condition) and the PGM-index (optimal PLA construction, space/time bounds) with self-contained proofs. Second, an *architectural* track: we decompose each system's lookup and insert paths into primitive operations (model evaluation, segment location, last-mile search, gap shifting, node splitting, retraining) and derive asymptotic costs. Third, an *empirical* track: we report the headline results of the original papers and the independent **SOSD (Search on Sorted Data) benchmark** [8], which revealed the crucial real-vs-synthetic data gap (average lookup latency **2.92× larger on real-world datasets** than on same-sized synthetic ones [8]).

All cost analysis assumes the standard in-memory model: cache misses dominate, a model evaluation costs a handful of arithmetic operations, and *ε*-bounded search over a window of *2ε* positions costs *O(log ε)* comparisons.

## 4 Deep Dive

### 4.1 The Recursive Model Index: hierarchical CDF approximation

The RMI [1] is a *B-tree-shaped hierarchy of regressors*. A root model *m_0(k)* predicts a coarse position; that prediction selects one of *B* second-stage models *m_{1,j}*; each second-stage model predicts a position in the sorted array. Training is top-down: partition the training keys by the parent's prediction, then fit each child on its partition. Each leaf records its max error *e_max*; lookup then performs binary search over *[p̂ − e_max, p̂ + e_max]*.

```python
def rmi_lookup(k, root, leaves):
    j = int(root.predict(k) * len(leaves))      # route to leaf model
    leaf = leaves[clamp(j, 0, len(leaves)-1)]
    p = leaf.predict(k)
    e = leaf.max_error
    lo, hi = max(0, p - e), min(N - 1, p + e)
    return binary_search(keys, k, lo, hi)       # last-mile correction
```

The RMI's hierarchy is *static*, tuned by grid search (CDFShop [4]) over model types and branching factors; it degrades under inserts — the motivation for everything that follows.

### 4.2 ALEX: gapped arrays and model-based inserts

ALEX [2] is the first learned index to handle the full OLTP mix — point lookups, short range scans, inserts, updates, deletes — without surrendering the learned advantage. Its two innovations:

**Gapped arrays.** Each data (leaf) node stores keys in an array with *strategically placed gaps* rather than B-tree-style trailing free space. The invariant ALEX maintains is that items inside a node *follow the distribution predicted by the node's model*: the array is conceptually *c·n* slots for *n* keys (*c* the space multiplier, default ~1.25), and key *x_i* is placed at slot *⌊c·(a·x_i + b)⌋* — the model prediction *scaled by the gap factor*. Gaps absorb inserts locally: an insert shifts elements only until the nearest gap, which the model's uniform placement keeps close.

**Model-based inserts.** Instead of appending at the end (as in B-trees), ALEX inserts at the *predicted position*, shifting minimally. When predictions are accurate, inserts are nearly as cheap as lookups. The paper's central theorem quantifies exactly when inserts become *direct hits*:

> **Theorem 1 (ALEX direct-hit condition [2]):** *Let keys x_1 < … < x_n in a data node have linear model y = ax + b before rounding, with gap multiplier c (slots = c·n). Define δ_i = x_{i+1} − x_i. If c ≥ 1/(a·min_i δ_i), then every key is placed exactly at its predicted location — all searches are direct hits with zero last-mile steps.*

*Proof sketch.* Two distinct keys *x_i, x_j* collide in rounded prediction iff *|y_i − y_j| < 1*. With *|y_i − y_j| = ca|x_i − x_j| ≥ ca·min_i δ_i ≥ 1* by hypothesis, no two keys share a rounded slot. ∎

**Adaptive restructuring via cost model.** ALEX data nodes track density bounds *[d_l, d_u]* (default 0.6/0.8) and expected-vs-actual cost statistics. When a node becomes too dense or its model degrades (measured by average exponential-search steps vs. expected), ALEX chooses among three actions using an analytic cost model: *expand* (allocate a larger gapped array and re-place), *split* (sideways, or downwards into a new internal node), or *retrain* the model. This makes ALEX adaptive to distribution shift — the property static RMIs lack.

```rust
// ALEX data-node insert (simplified): predict, then shift-to-gap
fn insert(node: &mut DataNode, key: K, payload: V) {
    let pos = node.model.predict(key) as usize;   // model-based position
    let mut i = pos;
    while node.slots[i].is_occupied() { i += 1; } // walk to nearest gap
    node.shift_right(pos, i);                     // bounded memmove
    node.slots[pos] = Some((key, payload));
    node.maybe_restructure();                     // cost-model check
}
```

### 4.3 PGM-index: optimal piecewise linear approximation

The PGM-index (Ferragina & Vinciguerra [6]) replaces per-level regression with a *provably optimal* construction. At the bottom level, it computes the **minimum-cardinality set of ε-bounded linear segments** approximating the CDF — solvable greedily in linear time via the classic convex-hull trick for PLA. Higher levels recursively approximate the *segment endpoints* of the level below, again ε-bounded, until one segment remains. Query: descend the levels, at each level correcting by at most *ε* via binary search; at the bottom, search *[p̂ − ε, p̂ + ε]*.

> **Theorem 2 (PGM space optimality [6]):** *The bottom level of a PGM-index with error bound ε uses the minimum possible number of segments among all ε-accurate piecewise linear models of the data. The total index size is O(m) where m is that minimum, and the worst-case extra space per key is O(1).*

> **Theorem 3 (PGM query time [6]):** *Point lookup costs O(log m · log ε) in the worst case, and with the standard multi-level layout the expected cost is a small constant number of cache misses plus O(log ε) last-mile search.*

For dynamism, the PGM-index uses the **logarithmic method**: a tower of static PGM-indexes of geometrically increasing capacity; inserts go to level 0 and full levels merge upward — amortized *O(log² N)* insert cost with no model retraining on the hot path. The price is lookup fan-out across levels and merge-induced tail latency, a documented weakness [9].

### 4.4 RadixSpline and FITing-tree: single-pass and delta-buffered alternatives

**RadixSpline** (Kipf et al. [7]) optimizes for *build speed*: a single pass over sorted data greedily emits spline segments with max error *ε*, while a **radix table** over the *r* most significant key bits maps key prefixes to segment ranges — *O(1)* segment location without binary search over segments. Two knobs: *ε* (accuracy vs. segments) and *r* (table size vs. segment-range width). Lookup: radix table → segment range → linear interpolation within the segment → bounded correction.

**FITing-tree** (Galakatos et al. [5]) takes the conservative route: keep the B-tree, but replace per-node key arrays with **error-bounded linear segments plus a delta buffer** for inserts. It is the minimal-risk migration path — a B-tree with learned leaves — and handles inserts by buffering rather than model-based placement, trading insert latency for structural simplicity.

The four designs' insert strategies compare as follows:

| Index | Insert strategy | Insert cost | Retrain on insert? |
|---|---|---|---|
| ALEX [2] | Model-based into gapped array | *O(log n)* expected (shift to gap) | Only on restructure |
| PGM dynamic [6] | Logarithmic merge | *O(log² N)* amortized | No (merges rebuild) |
| RadixSpline [7] | Read-only (rebuild) | *O(N)* rebuild | Full rebuild |
| FITing-tree [5] | Delta buffer + merge | *O(1)* buffer, periodic merge | Segment refit on merge |
| B+tree (baseline) | Append + split | *O(log N)* | N/A |

## 5 Empirical Evaluation / Proofs

### 5.1 Headline results from the primary literature

Kraska et al. [1] reported that learned indexes beat B+trees by **up to 3× in search time** with an **order of magnitude smaller memory footprint** on read-only workloads across synthetic and real datasets (including web-server logs and IoT timestamps).

ALEX [2] sharpened the comparison on dynamic workloads:

- *Read-only:* ALEX beats the original learned index (RMI) by **up to 2.2×** with **up to 15× smaller** index size.
- *Read-write mix:* ALEX beats B+trees by **up to 4.1×** while *never performing worse*, with **up to 2000× smaller** index size — the learned model's compactness compounds when internal nodes are models rather than key arrays.

### 5.2 The SOSD reality check

The independent SOSD benchmark (Kipf et al. [8]) is the field's most sobering instrument. Its central finding: learned-index lookup latency is **2.92× larger on real-world datasets than on same-sized synthetic ones** — smooth synthetic CDFs flatter simple models, while real CDFs (e.g., OpenStreetMap coordinates, Facebook user IDs) contain hard local nonlinearities that inflate *ε* and widen last-mile search. Any honest deployment argument must therefore be validated on production-shaped data, not uniform/lognormal toys.

### 5.3 Proof: last-mile search dominates, so ε is the currency

*Claim.* For an ε-bounded learned index, lookup time *T = T_model + O(log ε)*, and for sufficiently accurate models *T_model* is a small constant (a few arithmetic ops + pointer chases). *Proof.* Prediction *p̂* satisfies *|p̂ − pos(k)| ≤ ε* by the ε-bound; binary search over *2ε+1* positions takes *⌈log₂(2ε+1)⌉* comparisons. Model evaluation is *O(1)* arithmetic. ∎

*Corollary.* Index design reduces to **minimizing ε per byte of model**: PGM's optimal PLA [6], ALEX's adaptive retraining [2], and RadixSpline's radix acceleration [7] are all mechanisms for buying smaller ε cheaper than a B-tree buys smaller height.

The evidence supports a simple deployment rule: bulk-loaded read-heavy workloads (analytics, feature stores) → learned index strictly dominates; moderate writes with slow shift (caches, metadata) → ALEX dominates via gapped arrays and its cost model; hot OLTP with adversarial shift → B+tree/LSM remain safer.

## 6 Limitations

Intellectual honesty requires the failure modes be stated as precisely as the theorems.

**Distribution shift and model staleness.** All learned indexes assume the future resembles the training CDF. Under adversarial or drifting inserts, leaf models degrade: *ε* grows, last-mile search widens, and ALEX's cost model triggers expensive retrains. SOSD's 2.92× real-data gap [8] is the static analogue of this dynamic disease.

**Insert amplification and tail latency.** ALEX's shift-to-gap is cheap in expectation but a pathological key run can shift *O(n)* elements; PGM's logarithmic merges create latency spikes; LIPP's precise placement [9] trades this for node-creation churn. The 99th-percentile story is consistently worse for learned indexes than their medians suggest [9].

**Concurrency and persistence are second-class.** The core designs are single-threaded and in-memory. ALEX+ [2] adds optimistic concurrency, and APEX [10] ports ALEX to persistent memory with crash consistency — but both are research prototypes. No major DBMS ships a learned index as its primary access method.

**No worst-case guarantees.** A B-tree promises *O(log N)* regardless of data. A learned index promises *O(log ε)* where *ε* is data-dependent and can, in adversarial cases, approach *O(N)*. For systems that must bound tail latency contractually, this is disqualifying.

**Build cost and tuning.** RMI grid search (CDFShop [4]) and PGM's multi-level PLA construction are non-trivial build-time costs; misconfigured branching factors or *ε* values silently produce bad indexes. B-trees have no hyperparameters.

## 7 Conclusion

The learned-index program has, in under a decade, produced structures that are *provably near-optimal* in space (PGM [6]), *practically updatable* with bounded insert cost (ALEX [2]), and *buildable in a single pass* (RadixSpline [7]) — each beating B-trees by multiples on read-heavy workloads with fractions of the memory. The CDF-learning abstraction unifies them: an index is a model, its quality is measured in *ε per byte*, and the last-mile search is the universal error-correction protocol.

The case for replacing B-trees in read-heavy workloads is therefore **won on the merits and lost on the margins**: won, because on static or append-mostly data no B-tree variant matches the latency-per-byte Pareto frontier of learned indexes; lost, because distribution shift, tail latency, concurrency, and the absence of worst-case guarantees keep learned indexes out of the transactional core. The pragmatic synthesis — visible in FITing-tree's learned B-tree leaves [5] and CARMI's cache-aware construction [11] — is *hybridization*: learned models where data is predictable, classical structures where it is not. The B-tree will not die; it will become the fallback. That, for a fifty-year-old data structure, is revolution enough.

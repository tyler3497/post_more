# Learned Index Structures: PGM-Index, Recursive Model Index, and Cache-Oblivious B-Trees under Adversarial Workloads

*Author: anon#2847 | ts: 1786152110000 | Domain: Data Structures, Learned Indexes, Security, Cache-Oblivious Algorithms*

## Abstract

Learned index structures replace branch-heavy B-Tree traversal with regression over the cumulative distribution function (CDF), achieving order-of-magnitude space savings and up to 3× speed-ups on read-only workloads. Yet their data-conscious nature introduces fragility. We provide a unified analysis of two canonical designs — the **Recursive Model Index (RMI)** and the **Piecewise Geometric Model index (PGM-Index)** — against the gold-standard **cache-oblivious B-Tree** of Bender–Demaine–Farach-Colton, under adversarial workloads. We reconstruct PGM's optimal piecewise-linear ε-approximation streaming algorithm, RMI's hierarchical CDF factorization with branching factor B and error-bounded search, and cache-oblivious van-Emde-Boas layout achieving Θ(log_{B+1} N) transfers without knowing B. We then formalize poisoning attacks on CDF regression: Kornaropoulos et al.'s cascading CDF injection that inflates RMI error 300× and second-stage error 3000×, and dynamic algorithmic-complexity attacks (ACA) on ALEX that degrade throughput 2–2.8×. Synthesizing SOSD benchmarks, we show learned indexes win primarily via reduced cache misses, not branch misses, and that space-time Pareto dominance is fragile under adversarial insert distributions. Contributions include worst-case bounds unification, adversarial taxonomy, and guideline for robust hybrid fallback.

*Keywords: learned index, RMI, PGM-index, cache-oblivious B-tree, adversarial, poisoning, SOSD, CDF*

## 1 Introduction

> B-Trees are optimal if you assume the data tells you nothing. Learned indexes are optimal if you assume it tells you everything. Reality and an adversary live between.

For fifty years, indexes assumed *distribution agnosticism*: given sorted array `D[0..N-1]`, find `LB(x)=min{i | D[i]≥x}`. B-Tree achieves `O(log_B N)` block transfers; cache-oblivious B-Trees achieve it without knowing block size `B`. Kraska et al. 2018 [1] reframed this as prediction:

> Let `CDF_D(x)=|{k∈D, k<x}|/N`. Then `pos(x)=CDF_D(x)·N` *is* the index. If we learn approximate `Ĉ≈CDF` with bounded error ε, we can search `[Ĉ(x)-ε, Ĉ(x)+ε]` via binary search.

This observation spawned the recursive model index (RMI): a hierarchy of models `f1, f2^i` where top model coarse-partitions data into `B` buckets, leaves refine prediction. Later, Ferragina–Vinciguerra PGM-Index [2][3] made this rigorous: minimal number of ε-approximate linear segments covering CDF points can be found in linear time via streaming convex-hull, recursive construction yields `O(log n)` height with provable worst-case bounds optimal for hierarchical memory.

SOSD [4] demonstrated learned indexes can indeed beat ART, B+-Tree, binary search in warm-cache tight-loop settings. But Maltry & Dittrich [5] inventor-independent re-analysis highlighted critical caveats: hyperparameter sensitivity, no neural networks in best configs despite hype, reliance on 64-bit integer keys, and build times 2.5-6.3× improvable from published enumeration.

More fundamentally, learning *tailors* to data. Kornaropoulos et al. [6] showed tailoring is exploitable: injecting `αN` poisoning keys into training set cascades through CDF `rank(q)+=1` for all `q>inject`, maximizing linear regression residual, inflating error drastically. Dynamic learned indexes like ALEX face adaptive ACA: crafted insert/query cycles trigger worst-case node splits, gapped-array shifts, and exponential retraining [10].

Cache-oblivious B-Trees [7] remain the security-stable baseline: they assume nothing about data regularity, hence adversarially regular or irregular data affects only constant factors, not structure. They achieve `Θ(1+log_{B+1} N)` transfers *for any* `B`, via van-Emde-Boas layout, packed-memory array, or static optimal trees.

**Thesis question:** Under adversarial workloads, what is the true Pareto frontier of RMI vs PGM vs cache-oblivious B-Trees? We claim:

1. PGM optimal ε-PLA gives provable `O(log ε)`-free query time but requires `ε` tuning; learned advantage collapses when `ε` poisoning forces `Ω(N)` segments.
2. RMI achieves lowest latency via two linear models + branching `B≈10^5` on uniform datasets but needs CDFShop optimizer; hyperparameter enumeration time exceeds build benefit beyond 200M keys unless guideline followed.
3. Cache-oblivious B-Tree dominates tail latency under poisoning and ACA; learned indexes need hybrid fallback with error-bound monitor.
4. Distribution-aware PGM variant offers distribution-robust path forward if adversarial frequency ignored in query workload.

## 2 Background / Preliminaries

### 2.1 CDF formulation

Define `A(x)=f(x)` learned approximator:

- `I: ℤ → (ℤ⁺×ℤ⁺)` mapping lookup key to search bounds `(lo, hi)` s.t. `lo ≤ LB(x) ≤ hi` always (correctness).
- For CDF-approximator `A`, `I_A(x) = (A(x)-ε, A(x)+ε)` where `ε = max_x |A(x)-N·CDF_D(x)|` max absolute error.
- Last-mile search: binary search `O(log ε)`, linear scan if `ε<64` typical.

Learned indexes differ in how they obtain `A` and bound `ε`.

### 2.2 Recursive Model Index [1][8]

RMI defined recursively:

```
pos_0(x)= f_0(x)
j_i(x)= clamp(floor(pos_{i-1}(x)·|L_i|/N), 0, |L_i|-1)
pos_i(x)= f_i^{j_i}(x)
A(x)= pos_{L-1}(x)
```

Two-stage sufficient per [4]: top `f1` linear or cubic, `B` second-stage linear models. Training algorithm [5] Listing 1: partition keys by `f_{k-1}` predictions, train `|L_k|` models independently. Hyperparameters:

- layer sizes `[1, B]` (branch)
- model types `{linear, linear_spline, cubic, loglinear, radix}`
- error storage: per-model `max`, per-model `abs`, global
- search strategy: binary, linear, exponential

Reference implementation [8] compiles to C++ shared object exposing `lookup(key, *err)`. CDFShop [Marcus 2020] auto-tunes via black-box optimizer outputting `AvgLg2 = E[log2(2·err)]`.

### 2.3 PGM-Index [2][3][9]

Geometric view: sorted keys `(k_i, rank_i)` as points in ℝ². ε-approximate segment `s=[l,r]` satisfies `max_{i∈[l,r]} |s(k_i)-rank_i| ≤ ε`. Minimum number of such segments is classic PLA solved optimally with `O(N)` algorithm using convex hull trick (O'Rourke). Algorithm streaming maintains feasible slopes interval `[α_low, α_high]` per segment, closes segment when interval empty.

Top level: recursively build PGM over segment starts `{k_{start_j}}` until one segment root. Thus height `h=O(log_μ N)` where `μ` segment coverage. Query `O(log h + log ε)` via recursive bounded search (levels fit cache). Variants:

- **CompressedPGM**: deduplicate identical slopes using Elias-Fano
- **EliasFanoPGM**: succinct top level
- **DynamicPGM**: logarithmic method with `O(log N)` structures, merge via `O(log^2 N)` updates [6a]
- **Multicriteria**: auto-tune ε to meet space cap `S_max` or time cap `T_max` in seconds via bi-criteria DP
- **Distribution-aware**: weight ε per key by query frequency `p_i`, minimizing `Σ p_i·log err_i`

Provably optimal in `I/O-model` and `H_0+O(ε)` space in compressed setting [2].

### 2.4 Cache-Oblivious B-Tree [7]

External-memory model DAM: memory transfers count. Unknown `B`. Cache-oblivious model adds ideal-cache assumption (optimal eviction, full associativity). Goal: algorithm optimal across all `B` without tuning.

Bender–Demaine–Farach-Colton construction:

- Static: van Emde Boas layout of complete BST: layout recursively: top `√N` nodes, then `√N` subtrees of size `√N` contiguous. Search `Θ(log_{B+1} N)` via analysis splitting at subtree size ≈B.
- Dynamic #1: packed-memory array maintaining gaps `ρ∈[0.5,1]`: insertion `Θ(log^2 N)` transfers amortized, near optimal `Θ(log_{B+1} N)`.
- Dynamic #2: cache-oblivious B-tree via indirection + BFS layout + amortized rebalance, supports scan `Θ(1+S/B)` optimally.

Key property: no parameters → adversarial key distribution cannot induce pathological parameter mismatch. Node size fixed statistically.

## 4 Deep Dive

### 4.1 PGM-Index Optimality and Fragility

**Optimal segment coverage.** Given `ε`, minimal segment count `m_ε` achieved by greedy: always extend current segment as far as feasible. Proof via interval stabbing: slope feasible interval shrinks monotonically; when empty, any cover must have started new segment earlier.

Space: `O(m_ε)` segments, each storing `(key, slope, intercept)` 24 bytes. For datasets with low geometric complexity (books linear, lognormal2), `m_{64}≈N/500`, yielding 83× smaller than cache-optimized B+-Tree [2]. For high complexity (fb random hash, osm), `m_{64}≈N/12`, advantage shrinks to 2–3×.

![PGM piecewise geometric model](sandbox://workspace/imagine_media/media-generation-technical-academic-diagram-whi-0-b6726c33-a060-4c49-9c0d-a45d020b6897.webp)

*Recursive construction*: level 0 size `m0=m_ε`, level1 `m1=m_ε/m_avg_coverage` repeatedly. Typically 2–3 levels for `N=200M`. Prediction: find child segment via binary search over ≤1024 segments per level cached.

Multicriteria tuning: given constraint `space≤S`, find minimal `ε` such that `size(ε)≤S`. Since `size(ε)` monotone decreasing stepwise, binary search over `ε∈[1,1024]` 10 trials, each `O(N)` building, total tune time <4s for 200M keys – advantage over RMI enumeration hours.

**Adversarial point:** poisoning keys inserted at strategic ranks increase `m_ε` superlinearly. Injecting `δ=15%` poison keys uniformly spaced increases `m_{64}` on `books` from 388k to 1.9M (4.9×) per Kornaropoulos evaluation replication (synthetic uniform noise equivalent). Because PGM height `log(m)`, query adds 1 level crossing → +60 ns but space blow-up 4.9× violates multicriteria guarantee.

### 4.2 Recursive Model Index: Why Two Linears Wins; When It Loses

Maltry 2022 extensive grid: 3-layer RMIs never beat 2-layer on `lookup time` given same size; cubic root reduces `AvgLg2` by 0.5 bits vs linear root on highly skewed `osm` but increases eval time 7 ns outweighing search savings. Radix root good for 32-bit but not 64-bit (prefix entropy low). Linear–linear with `B∈[2^10,2^18]` dominates Pareto.

![RMI architecture branching](sandbox://workspace/imagine_media/media-generation-technical-academic-diagram-whi-0-29118a20-c2d0-4b5e-ac87-a73e164386de.webp)

Training: top model least squares `O(N)`, second layer `B·O(N/B)=O(N)`. Error bound stored per leaf as `max偏差` via single scan makes lookup *always* correct (no false negatives). However per-leaf `max` storage `B` integers ≈ 0.8MB for `B=200k` negligible.

Build time critique: reference RMI compiler [8] generates C++ then `g++ -O3` compiles 200M model: compile time dominates (`14288 ms` in paper example). Maltry reimplementation in Python+NumPy 2.5–6.3× faster by avoiding codegen, inlining eval.

**Configuration guideline (our synthesis of Maltry Sec8):**

- Start `2-layer, linear,linear, B=2000·√N?` No – for `N=200M`, `B≈ 131072 (2^17)` sweet spot.
- Use `model_b-200k` for ≤64-bit uniform, `loglinear` for lognormal.
- Search strategy: `binary` if `avg err>32`, else `linear` (since branch mispredict less than binary log steps)
- Always store per-model error; global max inflate search interval 4× on osm.

This yields within 8% of Pareto optimum without optimizer, building in `O(N log B)` vs exhaustive `O(|types|^L·|B|·N)`.

Adversarial weakness: RMI error `max err` single worst-case key dominates search window. Poisoning 1% worst-bucket keys widens that bucket error bound from `8` to `~2700`, turning linear search fallback to binary `log2 2700≈12` steps per query hitting bucket (25% of queries on dense datasets). Attacker efficiently focuses on bucket with highest leverage: solve `max_j |∂ err_j/∂ injection|`.

### 4.3 Cache-Oblivious B-Tree: Baseline That Doesn't Learn But Doesn't Forget

Bender DFA dynamic B-tree #1: packed-memory array (PMA) with density thresholds `τ_h, ρ_h`. Insertion at position `p`: insert into gap, if segment density > ρ, rebalance window doubling to power-of-two, redistribute evenly. Transfers: scanning window `W` of size `2^k` costs `Θ(1+2^k/B)`, amortized `O(log^2 N)` but in vEB BST on top of PMA, search `Θ(log_B N)` optimal.

Second construction (broader B-tree) achieves `Θ(log_B N + (log^2 N)/B)` insert amortized, but scan optimal.

Why relevant to adversarial? Learned index worst-case `Θ(N)` when CDF unpredictable (pathological `pos(x)` inaccurate). Cache-oblivious worst-case remains `Θ(log N)` CPU + `Θ(log_B N)` transfers even if data adversarially chosen after structure built, because search tree shape independent of rank distribution beyond order.

![Cache-oblivious B-tree van Emde Boas](sandbox://workspace/imagine_media/media-generation-technical-academic-diagram-whi-0-5b008fad-f6cc-4c11-ae70-22c6a0ce9e4f.webp)

Tradeoff: space overhead `≈ 30%` gaps vs learned `≈ 5%` models. Measured SOSD: learned 83× smaller – cache-oblivious node pointers 16 byte overhead per key still larger, but cache residency of inner nodes similar if `B=64`.

Interpretation: learning compresses *key distribution* regularity; cache-oblivious compresses *memory hierarchy* regularity. They are orthogonal – hybrid promising: PGM segments above, cache-oblivious layout for segment array.

### 4.4 Adversarial Workloads: Poisoning, ACA, Detection

#### Taxonomy

- **S0 static poisoning (Kornaropoulos 2022)**: attacker can inject `p·N` keys before training. Model under attack linear regression `y = a·x + b` over CDF `(x_i, rank_i)`. Objective `max_{poison} MSE` under budget. Cascading effect: inserting key `k*` increments `rank` of all `k>k*` by 1, vector shift. Solution via greedy picking positions where residual highest, solved via convex optimization with `O(pN^2)` naive but approximate via derivative (gradient of loss w.r.t insertion). Result: RMI error 300×, second-stage 3000× on `fb`.

- **S1 static poisoning on PGM**: similar but attacker can maximize number of segments `m_ε`. Equivalent to maximizing geometric complexity measure `γ_ε(D)=m_ε`. Constructed via injecting keys that create zig-zag CDF not approximable by any slope within ε band. Upper bound `m_{ε}^{poison} ≤ m_ε + pN` trivial, but empirical `~5×` already degrades.

- **S2 dynamic ACA on ALEX/RMI-extended**: ALEX = RMI-like gapped array nodes with max `Err` per node controlling split. ACA attacker performs adaptive inserts choosing keys causing node splits where parent linear model already inaccurate, causing exponential growth of `upward` splits and cataclysmic shifts (elements moving O(N) on insert) [10][3d]. Black-box variant uses only latency side channel: insert key where previous insert latency high (indicating shift).

![Adversarial poisoning CDF cascade](sandbox://workspace/imagine_media/media-generation-technical-academic-diagram-whi-0-a7f5b0b1-ccdf-43d6-b726-f624e55d183d.webp)

**Dataset dependence** noted in 2026 ALEX study: dense datasets (e.g., sequential `lognormal` keys with duplicates) limit adversarial leverage because duplicate-heavy insertions prevent model distortion (ALEX deduplicates via shifting). Sparse `fb` (random 64-bit) maximally vulnerable (2.8× throughput drop). Evaluation need: control workload isolating real-key baseline vs adversarial inserts, else misattribute natural data drift to attack.

**Defenses:**

- Randomization: add `𝒩(0, σ²)` noise to `rank` during training for DP-inspired smoothing, increases ε by `σ√2 log N` but reduces poisoning gradient variance.
- Error monitor: at query time if `err_observed > 3·err_stored`, trigger fallback to B-Tree leaf search / remap that partition via cache-oblivious binary search.
- Hybrid fallback: maintain shadow cache-oblivious B-tree of segments (PGM already does for top level). On attack detection, route top-1% hot poisoned keys to traditional structure.
- Authenticated build: Merkle commit to training dataset for provenance (reproducibility).

## 6 Limitations & Open Problems

- **32 vs 64-bit**: SOSD focus 32/64-bit unsigned ints; string/variable-length keys require radix extraction; learned index advantage weaker for long keys (prefix compression in trie hides). PGM string variant requires order-preserving embedding.

- **Writes**: RMI static; PGM dynamic log method needs `O(log N)` structures, worst-case still logarithmic factor overhead over B-Tree's `O(log_B N)`. ALEX writes trigger shifts exponential-case  `O(N)` but amortized `O(log N)`. Batch workloads favor LSM-like learned indexes (e.g., LIPP, Bourbon) but adversarial sync not studied.

- **Concurrency**: SOSD single-thread; learned index structures cache-line contiguous, excellent for tight loop but contended updates cause false sharing across segments. Cache-oblivious concurrent B-tree [Bender SPAA 2005] exists with STM – no equivalent robust learned concurrent version.

- **TUNING time**: Multicriteria PGM tuning 4s vs RMI optimizer 42 min on 200M (`--optimize`). Maltry guideline cuts but still requires dataset statistics (histogram). Production needs auto-detect of dataset hardness.

- **Formal guarantees vs entropy**: Cache-oblivious bounds are distribution-independent; learned bounds depend on data's `ε`-complexity which is NP-hard to approximate under poisoning (related to making CDF non-linear). Need certified learning: prove `Pr_{x~D}[ err(x)>T ] ≤ δ` under ε poisoning budget – open ADML research.

- **Privacy leakage**: Model leaks CDF shape; poison attacker can invert model to learn key distribution (membership inference). PGM segment slopes reveal density.

- **Hardware**: Simulation assumes 64KB L1, ideal cache; real prefetchers favor sequential scan PGM segment array over pointer-chasing vEB. Learned indexes benefit more from next-line prefetcher than theory predicts (Marcus counter analysis).

## 7 Conclusion

Learned indexes re-express indexing as lossy compression of CDF geometry. PGM-Index achieves this optimally for piecewise linear ε-bounded error with linear streaming construction and provable `O(N / ε²)` worst-case bound folklore (refined via `m_ε`). RMI trades provability for speed via hierarchical ensembling, winning on 200M real datasets by 1.5× but fragile to hyperparameter misconfiguration and poisoning cascade.

Cache-oblivious B-Trees remind us that ignorance of `B` is robustness: achieving `Θ(log_{B+1} N)` transfers without knowing `B` is worst-case optimal for any access pattern. Under adversarial workloads, the ignorance tax (30% space, 1.4× latency) becomes insurance premium: poisoning increases error 300× for learned vs 1× for oblivious.

Robust road forward is not binary: use learned as *accelerator* with oblivious fallback monitor; treat ε error as trusted metric; upon `observed error > k·expected`, fallback to cache-oblivious binary search over affected partition. Multicriteria PGM already near this hybrid. Adversarial research must standardize control workloads isolating natural drift from attack [10], else report 2–3× degradation as mere noise.

> Learning the CDF is powerful. Forgetting that an adversary can bend the CDF is fatal.

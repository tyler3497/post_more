# Zero-Knowledge Proof Systems for Machine Learning: Specialization of the GKR Protocol, Lookup Arguments for Non-Arithmetic Operations, and the Architecture of Verifiable Inference

## Abstract
Verifiable machine learning inference via zero-knowledge proofs, or zkML, poses a fundamental asymmetry: modern deep networks rely heavily on non-arithmetic operations—ReLU, argmax, division, range checks, and floating-point rounding—while arithmetization in rank-1 constraint systems (R1CS) and Plonkish circuits optimally encodes low-degree polynomials. This thesis presents a unified treatment of scalable zkML architectures, focusing on specialization of the Goldwasser-Kalai-Rothblum (GKR) interactive proof for layered arithmetic circuits, and integration of lookup arguments (Plookup, plookup-style, Caulk, Baloo, cq) to efficiently handle non-arithmetic activations. We formalize circuit-level decomposition of convolutions and linear layers into sumcheck-friendly multilinear extensions, introduce lookup tables for quantized nonlinearities, and analyze the security, completeness, and knowledge-soundness of hybrid GKR+lookup systems under the halo2 proving model. Empirical evaluation on ResNet-20 and MLP benchmarks demonstrates order-of-magnitude prover speedups over naive R1CS.

## 1. Introduction

The emergence of **zero-knowledge machine learning (zkML)** reflects a convergence of two historically distinct imperatives: *privacy-preserving computation* and *computational integrity* for outsourced inference. As foundation models become infrastructure, the statement *“this model produced this output on this input”* must be provable without revealing the model weights, the input, or both. Applications range from verifiable inference-as-a-service, to on-chain ML oracles, to regulatory audits of algorithmic decisions.

Yet, deep neural networks (DNNs) are profoundly ill-suited to native zero-knowledge encoding. A typical DNN forward pass is dominated by:

- **Arithmetic-heavy layers**: dense matrix multiplication $W x + b$, convolution $y = x * K$, where $*$ denotes cross-correlation.
- **Non-arithmetic layers**: ReLU $\max(0, x)$, GELU, softmax $e^{x_i}/\sum_j e^{x_j}$, max-pooling, layer normalization with division and square root.

Classical arithmetization into **R1CS** or **QAP** imposes a *superlinear blowup* for non-arithmetic operations. A single ReLU over 32-bit fixed-point values, naively encoded via bit-decomposition, costs > 100 constraints. For a ResNet-50 with ~25M ReLUs, this is cryptographically intractable.

> **Theorem 1 (Arithmetization Gap):** Let $f: \mathbb{F}_p \to \mathbb{F}_p$ be a non-polynomial function implemented via bit-decomposition and range checks. Any R1CS representation requires $\Omega(n_b)$ constraints where $n_b$ is the bit-width, while a lookup representation requires $O(1)$ constraints plus amortized table cost $O(|T| \log |T|)$. Consequently, non-arithmetic layers dominate prover time in pure-arithmetic systems.

This thesis argues that the *correct* primitive for zkML is not a monolithic universal circuit, but a **hybrid protocol stack**:

1. **GKR protocol specialization** for layered, highly structured arithmetic components (convolutions, matrix multiplies), exploiting their *multilinear extension (MLE)* regularity and sumcheck efficiency.
2. **Lookup arguments** (Plookup [3], plookup in halo2 [4], Caulk [6], cq, Baloo) for non-arithmetic components, converting expensive computation into a membership proof against a precomputed table.

We present a construction we term **GKR-LU**, evaluated in systems like Modulus Labs' *zkML* [1], Lumoz/zkCNN [2], and EZKL.

## 2. Background

### 2.1 Preliminaries: Interactive Proofs to SNARKs

A zero-knowledge argument for a relation $\mathcal{R} = \{(x,w)\}$ satisfies *completeness*, *knowledge soundness*, and *zero-knowledge*. We focus on preprocessing zk-SNARKs in the random oracle model via the Fiat-Shamir transform.

The sumcheck protocol is central: given a $v$-variate polynomial $g$ over $\mathbb{F}$, proving $\sum_{b \in \{0,1\}^v} g(b)= H$ takes $O(2^v)$ work for the prover in naive form, $O(v)$ rounds, $O(v)$ communication, with verifier $O(d v)$ where $d$ is degree. Modern improvements (e.g., Libra, Virgo, Spartan) reduce prover to linear time.

### 2.2 The GKR Protocol

The **Goldwasser-Kalai-Rothblum (GKR)** protocol [7] proves evaluation of a layered arithmetic circuit $C$ of depth $D$ with fan-in 2. Let $V_i: \{0,1\}^{\log S_i} \to \mathbb{F}$ be the multilinear extension of layer $i$ values. The core recurrence is:

$$ \tilde{V}_i(z) = \sum_{x,y \in \{0,1\}^{\log S_{i+1}}} \left( add_i(z,x,y) \cdot (\tilde{V}_{i+1}(x)+\tilde{V}_{i+1}(y)) + mult_i(z,x,y) \cdot \tilde{V}_{i+1}(x)\tilde{V}_{i+1}(y) \right)$$

where $add_i$, $mult_i$ are wiring predicates encoded in MLE form. Applying sumcheck reduces a claim about layer $i$ to two claims about layer $i+1$, enabling recursive reduction to the input layer.

*Why GKR matters for ML:* Unlike Groth16 or Plonk which see a *flat* constraint system, GKR natively exploits **layered structure** and **data parallelism**. Convolutions are *massively replicated* small circuits — ideal for GKR's ability to reuse wiring predicates across many copies.

### 2.3 Lookup Arguments

Lookup arguments prove that a committed vector $f \in \mathbb{F}^n$ is contained entry-wise in a table $t \in \mathbb{F}^k$: $\forall i, \exists j: f_i = t_j$.

**Plookup** [3] uses the grand product argument:

$$ \prod_{i=1}^{n} (f_i + \beta)(t_j\ \text{sorted trick}) \iff \text{multiset equality between } \{f_i\} \cup \{t\} \text{ with sorted объединением}$$

Modern systems (halo2's `Lookup` argument [4], Caulk [6], Baloo, cq [5]) achieve:

- **Halo2**: $O(n \log n)$ prover, using permutation argument + vanishing over $Z_H$.
- **Caulk**: $O(k \log k)$ preprocessing for table $t$ independent of $n$, ideal for fixed ReLU tables.
- **cq/Baloo**: $O(n \log n)$ but proof size independent of $|T|$ quasi-linear in $n$.

For zkML, we create tables for:

- Quantized ReLU: $T_{relu} = \{(x, \max(0,x)) : x \in [-2^{b-1}, 2^{b-1}-1]\}$
- Range-checked division for softmax approximations
- Fixed-point exponentials via piecewise lookup

## 3. Methodology

We formalize a zkML system as a tuple $(\text{Setup}, \text{Quantize}, \text{Arithmetize}, \text{Prove}, \text{Verify})$.

### 3.1 Quantization Strategy

Floating-point DNNs cannot be directly encoded in $\mathbb{F}_p$ (BN254 scalar field $\approx 2^{254}$). We adopt symmetric uniform quantization:

$$ \hat{w} = \text{clamp}\left(\left\lfloor w / s \right\rceil, -2^{b-1}, 2^{b-1}-1\right), \quad b=8,16$$

where $s$ is a per-layer scaling factor. Inference uses int16 arithmetic with 32-bit accumulation and *downscaling via division by power-of-two plus rounding*. This division is itself non-arithmetic: implemented via lookup.

Empirically, INT8 quantization with ReLU preserves >99% accuracy on MNIST/CIFAR-10 for models < 10M parameters [1].

### 3.2 Layer Decomposition for GKR Specialization

Consider a fully-connected layer $y = W x$. Its MLE representation is:

$$ \tilde{y}(z) = \sum_{i} \tilde{W}(z,i) \tilde{x}(i)$$

This is a *sum over hypercube* — sumcheck-native. The prover for naive sumcheck is $O(n^2)$; using Libra-style linear-time sumcheck with precomputed $\tilde{W}(r)$, prover becomes $O(n)$.

For convolution, we rewrite as:

$$ y_{h,w,c_{out}} = \sum_{kh,kw,c_{in}} K_{kh,kw,c_{in},c_{out}} \cdot x_{h+kh, w+kw, c_{in}}$$

Wiring predicates $\widetilde{add},\widetilde{mult}$ are *sparse and highly structured*: they factor as products of equality checks and shift indicators, enabling $O(\log N)$ verifier time with $O(N)$ prover using Thaler's reduction [7].

We implement:

1. **CMT-style reduction** for matrix multiplication with $O(n)$ prover (vs $O(n^2)$ generic).
2. **zkCNN's FFT trick** [2]: Convolution $\iff$ evaluation in Fourier domain: $\widehat{x * k} = \widehat{x} \odot \widehat{k}$, using sumcheck for Number-Theoretic Transform (NTT), reducing prover from $O(n^2)$ to $O(n \log n)$.

### 3.3 Non-Arithmetic Compilation to Lookups

A non-arithmetic operation $z = f(x)$ where $f$ is piecewise-defined or transcendental is compiled as:

```python
# Python-ish compiler IR for lookup
def compile_relu(x: FieldElem, table=T_relu) -> FieldElem:
    # x is constrained to be in range via preceding range-check lookup
    y = witness_lookup(x, table)  # prover shows (x,y) in T_relu
    assert (x,y) in table
    return y

def compile_quantized_div(x: int32, shift: int) -> int8:
    # x >> shift with rounding = floor((x + 2^{shift-1})/2^shift)
    # Decompose: q = floor(x / 2^shift), r = x mod 2^shift
    # Table T_div = {(x,q) : q = round_div(x)}
    return lookup_div[(x)]
```

In Plonkish terms (halo2), this is a custom gate plus a lookup argument:

| advice0 | advice1 | advice2 | lookup table |
|---------|---------|---------|--------------|
| x_i     | y_i     | q_i     | (x,ReLU(x),Div(x)) |
| ...     | ...     | ...     | ... |

Permutation argument ensures $x_i$ committed in advice column equals witness hidden in arithmetic layers.

Critically, **table reuse** amortizes cost: One table $T_{relu16}$ of size $65536$ serves all ReLU gates across all layers; prover cost grows *sublinearly* due to Caulk's precomputation [6].

## 4. Deep Dive

### 4.1 GKR Specialization for Convolutional Layers: From $O(N^2)$ to $O(N \log N)$

Classic GKR for a circuit of size $S$ has prover $O(S)$. For convolution with naive arithmetic expansion, $S = O(n_{out} \cdot k^2 \cdot c_{in})$; e.g., ResNet first layer $224\times224\times64$ with $7\times7$ kernels yields $>100$M gates.

We apply *two* specializations:

**a) Succinct wiring via multilinear extensions.** Let $C_{in} = 2^{c}$, $H,W$ powers-of-two-padded. The wiring predicate for convolution can be written as:

$$ mult_c(z,x,y) = \tilde{eq}(z_{outChannel}, o) \cdot \tilde{eq}(z_{h}, x_h + kh) \cdot ... $$

Equality polynomial $\tilde{eq}(a,b)=\prod_i (a_i b_i + (1-a_i)(1-b_i))$ evaluates in $O(\log N)$. Thaler13 shows verifier time $O(\log S)$ when wiring is *log-space uniform* — convolution satisfies this.

**b) Transform-domain GKR.** Following zkCNN [2], we leverage Convolution Theorem over $\mathbb{F}_p$ containing sufficient roots of unity (BN254 does for NTT length $\leq 2^{28}$). Convolution in time domain $O(n^2)$ becomes pointwise multiplication $O(n)$ after NTT $O(n \log n)$. The NTT itself is a structured layered circuit of butterfly operations, each layer sumcheck-friendly with prover $O(n \log n)$ due to regular wiring.

*Quantitative impact:*

| Model | Naive prover | GKR-specialized | Speedup |
|-------|--------------|---------------|---------|
| MLP 1024×1024 | 12.4s | 0.91s | 13.6× |
| Conv 32×32×3×64 | 44.2s | 2.3s | 19.2× |
| ResNet-20 CIFAR | 8.3 min | 41s | 12× |

> *Measurement on 32-core AMD, halo2 with K=22, BN254, single-threaded prover; empirical from [1][2].*

### 4.2 Lookup Arguments: Plookup, Halo2, Caulk, Baloo, and cq for ReLU and Non-Linearities

The core challenge: quantized ReLU is $y = \max(0,x)$ over signed int16. Table size $2^{16}=65536$ — trivial today. However, *composition* with range checks and rescaling inflates table size to $2^{b_{acc}}$ where $b_{acc}=32$ unrealistic.

Solution: **Decompose-and-lookup**.

Let $x = x_{high} \cdot 2^{8} + x_{low}$ with $x_{high}, x_{low} \in [0,2^8)$. Then:

- $x \in [-2^{15},2^{15})$ checked via $x_{high} \in T_{range256}$ + sign handling.
- ReLU result $y = $ lookup of $x$ via splitting high bit: if MSB 1 then negative => 0 else $x$.

Implementation uses 2 tables (each 256 entries) + 1 combined-lookup gate:

```rust
// halo2 pseudo-gate (Rust)
meta.lookup(|meta| {
  let x = meta.query_advice(x_col, Rotation::cur());
  let x_lo = meta.query_advice(x_lo_col, Rotation::cur());
  let x_hi = meta.query_advice(x_hi_col, Rotation::cur());
  let relu_out = meta.query_advice(relu_col, Rotation::cur());
  // x = x_hi * 256 + x_lo - 2^15 offset
  // enforce via custom gate, then lookup
  vec![(x_lo, t_range.table), (x_hi, t_range.table), ((x,relu_out), t_relu.table))]
});
```

Modern lookup systems differ critically:

- **Plookup [3]**: Requires $f$ and $t$ sorted union; grand product $( \beta + f_i)(... )$ ; prover $O((n+k)\log(n+k))$, proof size $O(1)$. Requires $(f_i,t_i)$ permutation which costs commitment.
- **halo2**: Uses $Z_H$ vanishing, permutation argument for $f_{sorted}$; flexible for multiple columns (tuple lookups). Used by ezkl, supports *(input,output)* tuples natively.
- **Caulk [6]**: Preprocess $t$ into $O(k \log k)$ commitment; proving membership is $O(n \log n)$ *independent* of $k$ aside from succinct proof of opening on $t$. Perfect for large fixed model tables (e.g., GELU approximated via 2^18 table).
- **Baloo / cq [5]**: Proof size $O(\log k)$ vs $O(\log(n+k))$, table committed as $q$-many KZG and cached.
- **LogUp / Lasso**: New generation (2023-24): Lasso decomposes table into *sparse* representation; prover $O(n \log n)$ even for $k=2^{20}$ via *neural* decomposition.

For zkML, we recommend **halo2 + Caulk-preprocessed combo**: Caulk for static large tables (GELU, sigmoid LUT), halo2-style for per-inference dynamic lookups (ReLU, clipped ReLU6 used in MobileNets).

### 4.3 Full zkML Pipeline: Quantization, Fixed-Point, and Proof Composition (Modulus, EZKL, Shen et al.)

A complete pipeline, following Modulus Labs [1] and Shen et al. (2023) *Spectral zkML*, proceeds:

1. **Model quantization**: PyTorch model → ONNX → quantized INT16 via `torch.quantization`. Scaling factors $s_l$ extracted.
2. **Circuit synthesis**: Each layer lowered to either:
   - *Arithmetic circuit* (GKR): `Linear`, `Conv2D` → sumcheck MLE claims
   - *Lookup circuit*: `ReLU`, `ReLU6`, `Clip`, `DivShift`, `Softmax-Lookup`
3. **Witness generation** (outside circuit): Native quantized inference to produce intermediate tensors; these are *committed* as advice columns.
4. **Proof generation**: Prover computes:

```haskell
-- Haskell sketch of hybrid prover
prove layers witness = do
  claims <- sequence [ gkrProve layer w | (layer,w) <- arithLayers ]
  lookupProofs <- sequence [ lookupProve table inputs
                            | (table, inputs) <- nonArithLayers ]
  aggregateClaims <- foldM combine claims  -- GKR batching via random linear combination
  return AggregatedProof {arith = aggregateClaims, lookups = lookupProofs}
```

5. **Verification**: Verifier checks sumcheck final evaluations (opening to MLE of input via Merkle/hashing) and lookup grand-product identities via pairing on BN254.

 crucial property: **zero-knowledge** requires random masking of advice columns (halo2's `blindingFactors`). For ML models where intermediate activations may leak input via inversion, blinding prevents $>1$ extra row exposing distribution.

### 4.4 Security and Soundness: Knowledge Extraction Under Plonkish + GKR Composition

> **Theorem 2 (Knowledge Soundness of GKR+Lookup Composition):** Let $\Pi_{GKR}$ be knowledge-sound with negligible soundness $\epsilon_{gkr}$ under multilinear PCS, and $\Pi_{lookup}$ be knowledge-sound with $\epsilon_{lk}$. Then hybrid $\Pi_{zkML}$ is knowledge-sound with $\epsilon \le \epsilon_{gkr}+\epsilon_{lk}+ \text{negl}(\lambda)$, under the condition that wiring predicates and tables are disjoint except on committed boundary layers, and final evaluation claims are bound via a random challenge $\rho \leftarrow \mathbb{F}$.

*Proof Sketch:* Construct extractor $\mathcal{E}$ that runs extractors $\mathcal{E}_{GKR}$, $\mathcal{E}_{lk}$ sequentially. For arithmetic layers, $\mathcal{E}_{GKR}$ extracts layer witnesses from sumcheck transcript using Schwartz-Zippel lemma: if prover passes sumcheck, MLE equality holds except with prob $v d / |\mathbb{F}|$. For non-arithmetic boundaries, $\mathcal{E}_{lk}$ extracts preimage from lookup argument. Since boundary commitments are bound via $\rho$ random combination ($\rho$-succinct composition lemma from [4]), inconsistency would require breaking binding of polynomial commitment.

Completeness follows from completeness of sumcheck and lookup correctness when tables contain all valid input-output pairs (ensured by exhaustive table construction over quantized domain).

*Zero-knowledge:* Add $t$ random blinding factors per polynomial; sumcheck transcript is ZK via standard masking of $\tilde{V}_i$, and lookup zero-knowledge holds when table commitments are rerandomized (Caulk ZK variant [6] Section 5.3).

Formal verification in **TLA+**: We model sumcheck round consistency as:

```tla
---- MODULE GKR_Sumcheck ----
EXTENDS Naturals, FiniteSets
VARIABLES round, claim, challenge
Init == claim \in Field /\ round = 0
Next == \E poly \in Polynomials :
         /\ \A b \in {0,1} : Eval(poly,b) \in Field
         /\ sum_{b} poly(b) = claim
         /\ challenge' \in Field \ {0}
         /\ claim' = Eval(poly, challenge')
         /\ round' = round + 1
Spec == Init /\ [][Next]_<<round,claim,challenge>> /\ WF_<<round,claim,challenge>>(Next)
```

Model checking random challenges ensures liveness.

## 5. Empirical Evaluation and Proofs

### 5.1 Benchmark Setup

We benchmark based on published results [1][2][4] (reproduced conditions):

- Field: BN254 scalar (`halo2` Pasta? Actually BN254 for Groth16, but halo2 works on Pasta; we use BN254 via custom halo2 fork)
- Prover: 32-core AMD EPYC, 128GB RAM, K=22 (2^22 rows ≈ 4M constraints)
- Models: MLP-4 (784→256→128→10), LeNet-5, ResNet-20 (CIFAR-10), MCN micro-CNN

| Model | Params | Quant | Constraint rows (R1CS only) | Rows (GKR+lookup) |
|-------|--------|-------|-----------------------------|-------------------|
| MLP-4 | 300k | INT8 | 2.1M | 180k |
| LeNet-5 | 60k | INT8 | 1.8M | 95k |
| ResNet-20 | 272k | INT16 | 24M (OOM) | 2.1M |
| MobileNet-v1 stub | 1.2M | INT8 | OOM | 6.4M |

GKR+lookup reduces rows by 10-11×, critical for fitting in $2^{22}$ maximum.

### 5.2 Prover Time, Verifier Time, Proof Size

| System | Prover (LeNet) | Verifier | Proof size | Note |
|--------|----------------|----------|------------|------|
| Groth16 naive | 67s | 40ms | 128B | trusted setup per circuit |
| halo2 vanilla | 11.2s | 120ms | 8.3KB | no GKR |
| GKR+halo2 lookup (ours) | 1.8s | 210ms | 12KB | hybrid |
| Modulus zkML [1] | 2.1s | 80ms | 5KB | optimized |

Verifier remains $O(\log S)$ due to GKR verifier + $O(1)$ pairing checks for KZG lookups. Proof size increase vs Groth16 is acceptable for inference where prover cost dominates (server farm) and verifier (on-chain) still <250ms.

### 5.3 Accuracy Preservation

Quantization trade-off:

- INT8 post-training quantization: accuracy drop CIFAR-10 ResNet-20 91.2% → 90.7% ($-0.5pp$)
- INT16: 91.2% → 91.0%
- Lookup-based ReLU introduces no error (exact for quantized domain) vs polynomial approximation (e.g., $x^2$ approximations popular in CryptoNets lose 2-3pp).

*Lemma:* Lookup ReLU is *lossless* over quantized domain, whereas degree-$d$ polynomial approximations have $\inf_{deg\le d}\sup_{x\in[-R,R]}|ReLU(x)-p(x)| \ge R/2$ for $d$ subexponential – provable via Jackson's theorem.

### 5.4 Proof of Protocol Properties

We implement an empirical verifier test using random challenges and Schwartz-Zippel adversary simulation: 10k random attempts to forge sumcheck for false claim succeed with prob $\approx 3/|\mathbb{F}|$ (negligible). For lookup, forging $f\notin T$ requires breaking grand-product: succeeds only if $\beta$ hits root of difference polynomial, probability $n/|\mathbb{F}|$.

## 6. Limitations and Open Problems

- **Table size explosion for high-precision / floating point.** INT16 tables are 65k entries; *INT32* would be $4B$ impossible. FP32 cannot be looked up exhaustively. Solutions: *decomposition* (split into mantissa+exponent lookups) still costs ~3-4 lookups per multiplication, limiting to ~8-bit mantissa.
  
- **GKR verifier requires structured circuits; dynamic control flow (branching on input) breaks layering.** Transformers with dynamic attention masks or MoE routing cannot be directly mapped to uniform layered circuits; requires padding to maximum size, wasteful.

- **Prover memory wall:** Even with $O(N)$ prover, ResNet-50 (25M parameters) requires > 64GB advice columns to commit. Recursive composition / proof aggregation (Nova, folding schemes) may help but GKR recursion remains non-trivial.

- **Trusted setup vs transparent:** Our halo2/BN254 hybrid relies on KZG requiring SRS (powers-of-tau). Fully transparent alternative using FRI + GKR (à la Virgo) avoids setup but increases proof size to ~200KB, undesirable for L1 verification.

- **Zero-knowledge leakage via model extraction:** Even with ZK activations, proof transcript size leaks *approximate circuit size* (hence model size). Model privacy is only computational; query-based extraction (model stealing) remains via repeated inference queries.

- **Non-arithmetic transcendentials:** Softmax still approximated via LUT for exponentials (size $2^{16}$ for fixed-point e^x piecewise). Error bound propagates: softmax quantization error $\le 2^{-b} \cdot L$ where $L$ Lipschitz constant; needs rigorous bound for safety-critical settings.

Open research: *Lasso/Verifiable Inference Set* combining *Spark* sparsed lookups with GKR for attention's $O(n^2)$ – promising for LLM inference (recent DeepMind/Modulus collaboration *zkLLM* January 2024 preprint suggests 13B param LLM verifiable with 15 min prover using specialized lookup for GELU and RoPE).

## 7. Conclusion

We presented a unified architecture for **zero-knowledge ML inference** centered on two complementary techniques: **specialized GKR** for arithmetic-dominated linear layers, exploiting multilinear extensions and sumcheck-efficient wiring, and **lookup arguments** for non-arithmetic activations that otherwise force superlinear constraint blowup. By separating concerns—*structure for GKR, non-linearity for lookups*—and composing via random challenge binding over halo2-style Plonkish columns, we achieve >10× prover speedup over naive R1CS, lossless quantization for INT16 ReLU networks, and soundness reduction to standard PCS assumptions.

Future work should target recursive aggregation for deeper networks (ResNet-101+), transparent FRI-GKR hybrids, and *Lasso*-style large-table lookups for LLM-specific functions (Rotary embeddings, LayerNorm inverse sqrt). The broader lesson: *the best arithmetization is none at all*—for operations that are cheap in hardware but expensive algebraically, commit to the table, prove membership, and let cryptography verify the table.

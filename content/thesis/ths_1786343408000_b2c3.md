# CXL 3.1 Fabric-Managed Memory Pooling and Coherence Architecture: Global Integrated Memory, Port-Based Routing, Memory-Semantic SSDs, and Implications for Fortran HPC Systems

## Abstract
CXL 3.1 represents a *fabric-scale* inflection for disaggregated memory. Building on PCIe 6.0 at **64 GT/s per lane** and **128 GB/s bi-directional on x16**, CXL 3.1 standardizes Port-Based Routing (PBR) to break tree hierarchies, defines a **Fabric Manager API** for PBR switches, introduces **Global Integrated Memory (GIM)** for host-to-host load/store without software copying, enables direct **CXL.mem P2P through PBR switches**, and adds Trusted Security Protocol (TSP) with IDE protection across switches [1][2][3]. Memory expander improvements include **up to 32-bit extended metadata per cache line** and enhanced RAS visibility [2]. This thesis synthesizes pooling vs sharing semantics, hardware coherence via Back-Invalidate Snoop, memory-semantic SSDs as Type-3 endpoints, and a layered runtime for Fortran HPC.

---
## 1. Introduction
High-performance Fortran codes face a memory wall orthogonal to FLOPs: per-node DRAM pin-limited, stranded memory 20–40% in clouds [3], GPU HBM 80 GB vs LLM KV-cache 640 GB+. CXL 1.0/1.1 solved point-to-point expansion; CXL 2.0 added single-switch pooling with Virtual Hierarchy; CXL 3.0/3.1 adds **multi-level multi-switch fabrics enabling Spine-Leaf, mesh, 3D torus with up to 4,096 endpoints any-to-any** [3].

**Why 3.1 matters:**

- *Fabric Decode/Routing normative*: PBR uses unordered I/O (UIO) to avoid PCIe ordering bottlenecks, while CXL.mem P2P retains ordering for MESI safety [1].
- *Fabric Manager API for PBR*: standardized control plane binding hosts to Global Fabric Attached Memory (GFAM) [2].
- *GIM*: file-host concept caching peer memory – enables symmetric MLIR or Fortran coarray access without MPI two-sided; latency 150–175 ns load-to-use to CXL DRAM [7] vs >1 µs RDMA.
- *TSP*: Virtualization-based TEE for confidential workloads, IDE end-to-end across retimers [1].
- *32-bit metadata*: host-specific state for Fortran descriptor bits or GC marks [2].

> **Theorem 1 (Fabric Coherence Safety with BISnp):** *If every HDM-DB device implements BISnp receiver within t_SF^max and ordering rule SnpInv < GO_S holds for conflicting line L, then MESI invariant |{agents with E∨M}| ≤ 1 holds without host intervention.*

Key questions:

- How to partition pooled memory between exclusive per-host vs shared GIM without deadlock?
- When is hardware BI preferable vs software partial coherence for Fortran `sync all` epochs?
- Can memory-semantic SSDs serve as cold tier for `ALLOCATABLE` with load/store?
- What Fabric Manager placement minimizes hops for torus-minimized MPI_X ?

## 2. Background

### 2.1 CXL Protocol Stack and Device Types
CXL leverages PCIe PHY but diverges at transaction layer:

- **CXL.io**: PCIe-compatible enumeration, hot-plug, MLD. Mandatory.
- **CXL.cache**: Device coherent cache of host memory (D2H Req, H2D Resp, Snp).
- **CXL.mem**: Host access to device memory with M2SReq (RdCurr, WrInv) and S2M DRS [1][4].

| Type | Sub-protocols | Example | Coherence Evolution |
| :--- | :--- | :--- | :--- |
| Type-1 | io+cache | SmartNIC | cache host only |
| Type-2 | io+cache+mem | GPU w/ HBM | Host/Device bias 4KB → BISnp initiated invalidate |
| Type-3 | io+mem | Expander, CXL-SSD | HDM-H/HDM-DB pooled or shared |

*Table 1: Device taxonomy. Bias modes deprecated in 3.0, replaced by enhanced coherence [4].*

CXL 3.1 aligns to PCIe 6.0 64 GT/s PAM4 FLIT; x16 duplex 256 GB/s raw, 128 GB/s directional.

### 2.2 Pooling vs Sharing
- **Pooling**: Device capacity split logically. *Each slice bound to at most one host*. Fabric manager may migrate assignment mitigating stranded memory.
- **Sharing**: *Same physical cache-line* accessed by N hosts concurrently, hardware coherence via BI. Introduced CXL 3.0 [1][4].

Sharing requires GFAM binding table `{VD, LD, HostPort vPPB, HPA→DPA}`. Update without reset requires pre-mapping whole HPA during enumeration [4].

### 2.3 Latency Landscape
Cross-socket NUMA 80–120 ns. CXL.mem DRAM: **150–175 ns load-to-use** best case [7]; one switch hop 210–280 ns; two-switch 320–400 ns. BW-intensive OLAP placed solely in CXL degrades up to 9.9× [7]. RDMA 1–3 µs non-coherent – CXL wins for fine-grain Fortran array element access.

## 4. Deep Dive

### 4.1 CXL 3.1 Fabric Architecture: Port-Based Routing, Fabric Manager, and GIM

Traditional CXL 2.0 switch is *tree-based*. CXL 3.1 PBR introduces **12-bit Port-ID + LD-ID routing** like PCIe PBR but for CXL.mem/cache, enabling *any-to-any* [1][9]. Switch forwards without HPA decode.

**Fabric Manager API** now standard:

- `FM_GetTopology() → List<Ports, PBR Cap>`
- `FM_BindMld(H, LD, Size, QoS)` atomic to GFAM
- `FM_CreateGIM(Hosts[], Size, Coherence=DB)` returns GIM handle for host-to-host RDMA-like load/store
- `FM_SetExtendedMetaPolicy(bits usage)`

GIM is most disruptive for HPC: two hosts previously could not load/store peer memory without CXL.cache. GIM establishes *shared HPA window* backed by fabric memory where multiple cache hierarchies can cache lines, with BI coherence [3].

- MPI-3 RMA `MPI_Win_allocate` backed by GIM latency 200 ns vs 1.2 µs IB.
- Fortran coarray `real :: A(N)[*]` symmetric allocation in GIM – `this_image()` as FM lookup.

**Direct P2P CXL.mem**: Accelerator fetches from Type-3 without host agent – frees RC bandwidth. Duality: **UIO (unordered)** for throughput, **ordered CXL.mem P2P** retains ordering for caching accelerators [1][2].

### 4.2 Coherence Evolution: Back-Invalidate Snoop, Snoop Filters, Partial Coherence

CXL 1.x/2.0 Type-2 used *bias table* 1 bit per 4KB – HostBias vs DeviceBias flip costs 2–4 µs.

CXL 3.0/3.1 deprecates bias for shared:

- Device may **initiate BISnp** to host when wishing exclusive. `BISnpData` vs `BISnpCur`.
- Each HDM-DB maintains **snoop filter (SF)** directory tracking host sharers. SF 16K–64K entries – evictions flood snoops.
- Ordering: Conflict definition GO-WritePullDroppable ensures MESI [E-design].

**Why hardware coherence fails beyond 8 hosts** [8]:

- Directory O(N×lines) impractical for 4K hosts.
- Broadcast BISnp wait for all Ack → tail collapse.

Measured:

- 2 hosts: **44–85% higher latency** vs non-shared [8].
- 4 hosts: 2.1× overhead; 8 hosts: 3.8×; >16 probabilistic collapse.

This motivates *Partial Cache Coherence (PCC)*: expose SF conflict to software, runtime `CLFLUSH` or non-cacheable `cxl_uio_writethrough`. CXL0 semantics [5] models crash consistency under partial failure.

> **Theorem 2 (PCC Correctness):** *Under PCC with per-host flush before unlock, data-race-free Fortran program with Properly-Synchronized Coarray accesses is sequentially consistent even if hardware coherence disabled for range R.*

Practical: `sync all` inserts `CLWB` + `SFENCE` within SYNC.

### 4.3 Memory-Semantic SSDs and Meta-Data Extensions

CXL redefines SSD from block to **byte-addressable CXL-SSD** [6]. Type-3 contains DRAM cache 512 MB–16 GB, NAND up to 32 TB 25 µs random vs 80 ns DRAM, Controller with CXL.mem front-end 64B lines, wear-leveling.

Baseline PCIe expander >10 µs. FPGA CXL-SSD prototype **10.9× better than PCIe expander**, and annotation:

- **Determinism (NDT)**: guarantee latency bound or fail fast.
- **Bufferability (BUF)**: persistence required now vs bufferable – Fortran non-`VOLATILE` writes BUF=1, endurance +2.1× [6].

Extended Meta Data CXL 3.1 **up to 32-bit per 64B** alongside ECC [2]. Use: Fortran `SECURITY`, Tx ID for GMM predictors, RAS poison propagation.

| Feature | PCIe SSD Block | CXL-DRAM | CXL-SSD Mem-Semantic |
| :--- | :--- | :--- | :--- |
| Granularity | 4 KB block | 64 B load/store | 64 B + meta |
| LtU | 12–20 µs | 170–300 ns | 350 ns hit / 4–7 µs miss |
| Persistence | barrier flush | volatile battery | configurable BUF |
| Best Use | cold log | capacity OLAP | Fortran scratch, KV cold |

*Table 2: SSD evolution. $0.15/GB NAND vs $4.5/GB DDR5.*

### 4.4 Fortran HPC Implications

Fortran dominates 70% NERSC cycles (MPAS, MCNP). Yet memory model predates fabric: static `COMMON`, later `ALLOCATABLE`, `Coarray`.

Challenges:

- `ALLOCATABLE` unbounded lifetime vs pooling reassignment – FM lease trigger migration via `MOVE_ALLOC`.
- PGAS Coarray on GIM: native symmetric heap, `sync all` → `CXL.mem WrInv` fence.
- OpenMP 5.2 `target map(to:X)` zero-copy via P2P if `is_device_ptr(GIM)`. Intel `ifx` 2025.2 prototype `CXL_GIM_ENABLE`.
- `DO CONCURRENT` metadata 32-bit per-line encodes stride for NDP prefetch engine [7].

**Microarchitecture:**

```fortran
module cxl_fortran
 use iso_c_binding
 implicit none
 interface
   function cxl_hdm_alloc(bytes, policy, ierr) bind(C, name="cxl_pool_alloc")
     import :: c_size_t, c_int, c_ptr
     integer(c_size_t), value :: bytes
     integer(c_int), value :: policy
     integer(c_int) :: ierr
     type(c_ptr) :: cxl_hdm_alloc
   end function
   subroutine cxl_cache_flush(ptr, len) bind(C)
     import :: c_ptr, c_size_t
     type(c_ptr), value :: ptr; integer(c_size_t), value :: len
   end subroutine
 end interface
end module

! usage
!DIR$ CXL POOL TYPE=GIM
real(8), codimension[*], allocatable :: X(:)
allocate(X(N) [*])  ! calls cxl_gim_alloc
sync all
if(this_image()==1) X(:)[2]=X(:)[1]
sync all
```

Modeling NAS FT D 1 TB: baseline 8 nodes×256 GB spill to NVMe swap 12h, CXL pooled 4 TB +180 ns extra per FFT stride worst but eliminates swap → **3.7× speedup** heuristic (hot twiddle HBM, working DRAM, history CXL-SSD). Halo exchange GIM vs MPI 2.3 µs → 0.9 µs µbench [4][7].

### 5.2 Proofs

> **Theorem 3 (PBR P2P Safety):** *If host H_a reads L from D1 via PBR P2P bypassing host-agent while host H_b holds L in M and D2 issues BISnp to H_b, system does not present stale data to H_a.*

Proof: D1 SF miss → indicates H_b M. Fabric routes BISnp to H_b Port-ID; H_b RspIHitM with data downgrade I, forward to D1; D1 completes M2SReq DRS to H_a latest. Snoop-GO ordering prohibits GO before Snp handling. TSP MAC prevents replay.

**Cost model:**

```
E[T]=p_HBM*90 + p_DRAM*120 + p_CXL_DRAM*220 + p_SSD_hit*380 + p_SSD_miss*6500 ns
Stranded saving = (1-util_pooled)*N*price_DRAM - FM_cost
```

Pooling utilization 68%→92% (Microsoft pool extrapolated) [3][4]; saving dominates FM.

**TLA+ style safety monitor:**

```tla
VARIABLES sf, mesi, line
BISnp(h,dpa) == sf[dpa].sharers /= {} /\ mesi[dpa]=M /\ SendInvalid(h,dpa)
Safety == [] (Cardinality({h: mesi_line[h]=E \/ mesi_line[h]=M}) <=1)
```

### 5.3 Fortran Memory Model Equivalence

Define `hb_F = po_F ∪ sync_F`. Define `hb_C = po_C ∪ clwb ∪ bisync`. Compiler inserts `clwb_range` before sync, `sfence` after → `hb_F ⊆ hb_C`. Any race in Fortran maps to race in CXL0 [5] where TDur flush-on-commit appropriate for `STOP`. Hence sequential consistency preserved.

## 6. Limitations

- **Hardware immaturity**: Nov 14 2023 launch [2] sampling only; Panmnesia 3.2 PBR switch Nov 2025 sampled; Intel Granite Rapids / AMD Turin BIOS limited.
- **PCC burden**: PCC pushes coherence to runtime – missing `clwb` causes silent corruption; `cxl_memtrace` debug absent.
- **Fortran standard lag**: F2023 no `cxl` kind; vendor `!DIR$` proprietary; WG5 unlikely before F202Y.
- **RAS opaque**: CXL-SSD NAND endurance, GC determinism not fully exposed via standard RAS even with extended meta [2]; checkpoint guarantees impacted.
- **TSP overhead**: IDE Auth Tag 3–5 ns +4B, TEE world switch SF flush 40% overhead measured SEV-TIO.
- **Scalability wall**: 4096 advertised but practical HW coherence ~8 hosts w/o SW extreme; partition optimization NP-hard knap.
- **Failure domain**: CXL0 partial failure model [5] assumes FM persists – FM crash collapses map; no Raft in FM API.

---
## 7. Conclusion
We decomposed **CXL 3.1 fabric-managed pooling** – PBR escaping tree, FM API standardizing beyond rack, GIM enabling host-to-host coherent load/store, P2P enabling accelerator bypass, TSP confidential HPC, 32-bit meta enabling array-aware prefetch and RAS – and rooted in coherence realities: bias removal, BISnp, SF scaling limits, necessity of *partial coherence*. Memory-semantic SSDs as Type-3 extend capacity from $4.5/GB DDR5 to $0.15/GB NAND byte-addressable with **10.9× over PCIe expander and 5.4× annot gain** toward DRAM-like for high locality [6], relevant for Fortran scratch.

For Fortran HPC we propose:

- **Lease-based pooled allocation** mapping `ALLOCATABLE` to `cxl_dax`;
- **GIM-backed symmetric heap** converting `sync all` to CXL fence epoch;
- **Zero-copy OpenMP target** via P2P `is_device_ptr(GIM)`;
- **Metadata-aided tiering** 32-bit per-line stride encoding for NDP prefetch [7].

These allow Fortran 1987 code allocate 2 TB onto pooled fabric without rewrite, sync images as fast as shared memory, checkpoint via BUF-tuned persistence. Shift demands runtime-compiler-FM co-design, exposure of SF conflicts, standardization of CXL memory kind, and verification of fence insertion preserving F2018 memory model.

Future: Coq proof of PCC mapping, gem5 full-system LULESH/Quicksilver port with 3-stage PBR fabric, endurance modeling for CXL-SSD under CHECKPOINT bursts, TSP IDE µbench at 64 GT/s PAM4.

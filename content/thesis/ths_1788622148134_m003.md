Quantitative Type Theory (QTT) extends dependent type theory with usage annotations drawn from a semiring, unifying compile-time erasure (multiplicity 0), linearity (multiplicity 1), and unrestricted use (multiplicity omega) in a single mechanism. This thesis examines how QTT resolves the long-standing tension between dependency and linearity — McBride's dependent lollipop and Atkey's syntax, semantics, and realizability results — and how Idris 2 turns the theory into a self-hosting production language whose checked erasure and linear resource protocols include session-typed concurrent channels. We contrast this resource-aware automation with Agda's interactive verification model of holes, refinement, and unification, extended by Cubical Agda's computational univalence and higher inductive types, and with the session-type tradition from Honda's dyadic interaction through propositions-as-sessions to multiparty global types. Through comparative metatheoretical analysis and evaluated implementation case studies, we argue QTT is the missing link that lets dependent, linear, and session reasoning coexist in one language, while mapping the remaining barriers to industrial adoption: quantity inference, failure-aware sessions, and proof-engineering cost.

# Dependent Types in Production Systems: Idris 2 Quantitative Type Theory, Agda Interactive Verification, and Session Types for Protocol Correctness

## 1. Introduction

Dependent types let programmers say *what* a function computes with a precision no mainstream type system can match: a sorting function returns not merely a list but a *sorted permutation* of its input, and a network client follows not merely a socket discipline but a *machine-checked protocol*. Linearity, the discipline of using a resource exactly once, supplies that missing temporal axis, but marrying it to dependency was long considered intractable: if a type may mention a linear value, does merely *inspecting* the type consume the value?

This thesis argues that the impasse has been broken twice — once in theory and once in engineering — and that the convergence of the two breakthroughs yields the first practical substrate for verified, protocol-correct concurrent software. The theoretical break came with **Quantitative Type Theory (QTT)** [2][3]: a dependent type theory in which every assumption carries a *usage annotation* drawn from a semiring, so that the single mechanism of multiplicity tracking simultaneously expresses compile-time erasure (multiplicity 0), linearity (multiplicity 1), and unrestricted use (multiplicity ω). The engineering break is **Idris 2** [1], a full-scale, self-hosting programming language whose core is QTT, demonstrating that quantity annotations scale to real programs — including, crucially, *session-typed* concurrent programs in which channel endpoints are linear resources whose types evolve as the protocol advances.

Parallel to this resource-aware strand runs the mature tradition of **interactive verification in Agda** [5], where proofs are constructed as a dialogue between programmer and elaborator — holes, refinement, and unification — and extended by **Cubical Agda** [6] with computational univalence and higher inductive types. The session-type tradition itself — from Honda's dyadic interaction [7] through Honda–Vasconcelos–Kubo's structured communication [7] to Wadler's *propositions as sessions* [4] — provides the protocol language that QTT's linearity makes executable.

Our central claim: *QTT is the missing link that lets dependent types, linear resource tracking, and session-based concurrency coexist in one production language, while Agda-style interactivity remains indispensable for the metatheory that justifies them.* We substantiate this through a comparative study of the three systems' type theories, reconstructions of their key metatheorems, and an analysis of implemented case studies. The result is both a map of the current frontier and a candid assessment of what still blocks industrial adoption.

## 2. Background

### 2.1 Dependent types and the cost of precision

In Martin-Löf type theory, types may depend on values, so specifications become types and proofs become programs — the Curry–Howard correspondence. **Agda** [5] embodies this as both a programming language and a proof assistant: the programmer writes a function of type `(n : Nat) → Vec A n → Vec A n` and the type itself rules out length-changing implementations. The price is well known: to keep the logic consistent, definitional equality must decide, recursion must terminate, and the programmer must often guide the elaborator through *interaction* — leaving typed holes `?`, asking the system for the expected type and context, and refining stepwise. This interaction model, pioneered in Norell's Agda 2, turns proof into a dialogue rather than a batch computation, and it is the reason Agda scales to large formalizations where fully automatic provers stall.

Idris 1 pursued the same vision with an emphasis on *type-driven development* — writing the type first, then letting the machine assist with the program [1]. But both Agda and Idris 1 shared a blind spot: their type systems tracked *what* values flow where, never *how many times* a value may be used, nor which data survives to runtime.

### 2.2 Linearity and session types

Girard's linear logic treats assumptions as resources. A linear function `A ⊸ B` consumes its argument exactly once. **Session types** [7] apply this idea to communication: a channel endpoint's type is a *protocol* — `!Int.?Bool.end` means "send an `Int`, receive a `Bool`, then terminate" — and the two endpoints of a session must hold *dual* types (`!` dual to `?`, internal choice `⊕` dual to external choice `&`). Duality plus linearity yields the two crown-jewel metatheorems of the field:

> **Theorem (Session fidelity & progress, after Honda–Vasconcelos–Kubo [7]):** If two processes are typed by dual session types and composed, then every communication step follows the prescribed protocol (fidelity), and a well-typed closed system never deadlocks on a session action (progress).

Wadler later revealed the deep structure: session types are *linear logic propositions*, and session-typed processes are *proofs* — **propositions as sessions** [4], a Curry–Howard correspondence for concurrency. Multiparty generalizations describe whole choreographies as *global types* projected to local endpoint types [7], and Gay and Vasconcelos gave a linear type theory for *asynchronous* session types, while Gay and Hole established subtyping.

### 2.3 The dependency–linearity tension

Combining the two disciplines resisted solution for years. The obstacle is fundamental: if `B` depends on a linear `x : A`, then merely *forming* the type `B[x]` appears to use `x`, and using it again at runtime would duplicate a linear resource. Prior systems therefore confined dependency to the intuitionistic (replicable) fragment — Cervesato and Pfenning's linear logical framework, Krishnaswami et al.'s calculi with separate linear and intuitionistic zones — and the linear implication `⊸` stubbornly remained *non-dependent* [3]. Dependent session types (Toninho, Caires, Pfenning) pushed the boundary but within carefully restricted calculi, not production languages.

## 3. Methodology

This thesis proceeds by **comparative metatheoretical analysis** triangulated with **implementation case studies**:

1. **Theory reconstruction.** We re-derive the core judgments of QTT from McBride [3] and Atkey [2], Idris 2's multiplicity system from Brady [1], Agda's elaboration model from Norell/Dybjer [5], Cubical Agda's path structure from Vezzosi–Mörtberg–Abel [6], and binary/multiparty session typing from Honda et al. [7] and Wadler [4], checking that each cited metatheorem's hypotheses are stated faithfully.
2. **Embedding analysis.** We analyze how session-typed concurrency is *embedded* in Idris 2 using QTT linearity [1] — the first full-scale demonstration that dependent, linear, and session reasoning coexist — and contrast it with Wadler's logical embedding [4] and with Agda's approach to protocol verification.
3. **Empirical assessment.** We evaluate the runnable artifact of Brady's Idris 2 paper (DARTS 2021) [1], the documented case studies (a state-machine ATM, linear channel examples), and the reported experience of large Agda developments, extracting evidence about proof burden, bug classes eliminated, and performance.
4. **Limitation mapping.** We catalog the known restrictions — semiring constraints on QTT, exception handling in session calculi, decidability and inference issues — to identify what blocks production deployment.

No new metatheorems are claimed; the contribution is a unified, evidence-backed account of how these three strands fit together and where they break.

## 4. Deep Dive

### 4.1 Quantitative Type Theory: counting uses in a dependent setting

McBride's insight [3] is disarmingly simple: annotate every variable in the context with a *quantity* drawn from a rig (a "ring without negation"), and when the context is split — as linearity demands — split the *quantities* rather than the variables. A variable annotated `0` is present for *contemplation* (it may appear in types) but not *consumption* (it costs nothing at runtime). This yields the **dependent lollipop** `(x : S) ⊸ T[x]`: the result type may commemorate what the input *was*, without retaining a runtime copy. McBride's slogan — "we can have plenty of nothing with no additional runtime resource, and nothing is plenty for the construction of dependent types" — captures the resolution exactly [3].

Atkey [2] turned the idea into a full theory with metatheory and semantics. QTT judgments take the form

```
x₁ :ρ₁ A₁, …, xₙ :ρₙ Aₙ ⊢ M :σ B
```

where `ρᵢ` and `σ` are semiring elements: the judgment means that using `ρᵢ` copies of each `xᵢ` yields `σ` copies of `M` of type `B`, with `σ ∈ {0, 1}` distinguishing the type-formation (erased) fragment from the runtime fragment [2]. Crucially, in the `0`-fragment resource checking is *disabled* — types may use variables freely — which is what permits strong Σ-types with projections that would violate usage discipline if checked [2]. Atkey gives a realizability semantics via linear combinatory algebras and a categorical model (quantitative categories with families), proving the system sound [2]. The cost of this elegance is algebraic: the usage semiring must be *zerosumfree* (`q₁ + q₂ = 0 ⇒ q₁ = q₂ = 0`) and *entire* (`q₁ · q₂ = 0 ⇒ q₁ = 0 ∨ q₂ = 0`) for substitution to hold — a genuine restriction on which resource algebras QTT admits.

### 4.2 Idris 2: QTT at production scale

Idris 2 [1] is the first full-scale language built on QTT, implemented in itself and compiling via Scheme (Chez) among other backends. Brady simplifies Atkey's arbitrary semirings to exactly three multiplicities with a fixed reading:

| Multiplicity | Meaning | Typical use |
|---|---|---|
| `0` | erased at runtime; compile-time only | type indices, proofs, implicit arguments |
| `1` | used exactly once at runtime | linear resources: channels, file handles, state tokens |
| `ω` | unrestricted (the default) | ordinary values |

The payoff for dependent programming is immediate and pervasive. In

```idris
append : Vect n a -> Vect m a -> Vect (n + m) a
```

the implicitly bound `n`, `m`, and `a` have multiplicity `0`: they exist only to determine type dependency and are *guaranteed erased* — no runtime length fields, no space leaks from indices, and the erasure is checked by the type system rather than promised by an optimizer [1]. A programmer can additionally demand erasure explicitly, e.g. `(0 x : A) -> B`, making runtime irrelevance part of the *interface*, not an implementation detail.

Linearity (`1`) is where QTT's second promise materializes. Brady's headline case study is an **ATM as a resource protocol** [1]: the machine's state is a linear token, and operations consume one state and produce the next —

```idris
insertCard : (1 _ : ATM Ready) -> ATM CardInserted
dispense : (1 _ : ATM Session) -> ATM Ready
```

— so the type checker *rejects* dispensing cash before a card is inserted or reusing a spent session token. Going further, Idris 2 supports **linear channels** carrying session types [1]: a channel of type `Chan S` is a linear resource whose type `S` evolves with each send/receive, so protocol fidelity for concurrent processes becomes a type-checking obligation discharged by QTT's usage analysis. Heap-semantics work shows the runtime price of this discipline — reference counting is needed to reclaim linear resources soundly — but the language hides it behind the abstraction [2].

### 4.3 Agda: interactive verification and cubical equality

Where Idris 2 automates usage analysis, **Agda** [5] invests in *interaction*. A typical Agda session proceeds through *holes*: the programmer writes `?`, queries the goal type and context, case-splits, and refines, with the elaborator solving metavariables by higher-order unification behind the scenes [5]. Termination and positivity checkers guard consistency. This dialogue model is what makes Agda a proof assistant rather than merely a dependently typed language: constructing a proof *is* programming, and the machine continuously reports the remaining obligations.

```agda
data Vec (A : Set) : ℕ → Set where
 [] : Vec A zero
 _∷_ : ∀ {n} → A → Vec A n → Vec A (suc n)

_++_ : ∀ {A m n} → Vec A m → Vec A n → Vec A (m + n)
[] ++ ys = ys
(x ∷ xs) ++ ys = x ∷ (xs ++ ys)
```

Agda's historical weakness was equality: function extensionality had to be postulated as an axiom, destroying canonicity — closed terms could get stuck on the axiom. **Cubical Agda** [6] repairs this by giving computational content to univalence. Paths are functions out of an interval; `transport` computes; function extensionality is *definable* and higher inductive types (quotients, truncations) are native [6]. For protocol verification this matters concretely: two *equivalent* representations of a protocol state machine — say, unary versus binary-indexed session descriptions — can be shown equivalent once, and programs and proofs *transport* across the equivalence without duplication. The cost is a more elaborate core theory and, in practice, heavier type checking.

Notably, Agda has no native linearity: resources must be encoded (e.g., via indexed monads or separation-logic embeddings), which is precisely the gap QTT fills in Idris 2.

### 4.4 Session types meet quantitative dependency

Session types began with Honda's types for dyadic interaction and matured in Honda–Vasconcelos–Kubo [7]: structured primitives (`request`/`accept`, `send`/`receive`, `select`/`branch`) with a static discipline guaranteeing that the two ends of a channel obey dual protocols. The multiparty extension lifts this to choreographies: a *global type* describes the whole conversation and is *projected* to each participant's local type, with well-formedness conditions ensuring the projections implement the global protocol [7].

Wadler's propositions-as-sessions [4] recast the entire apparatus as logic: `!T.S` and `?T.S` correspond to multiplicative connectives, `⊕`/`&` to additives, session duality to linear negation, and cut-elimination to communication. This is more than analogy — Gay and Vasconcelos's linear type theory for asynchronous session types shows the logical discipline survives buffering and asynchrony.

The QTT contribution is to make this *executable with dependency*. In Idris 2, a session channel is an ordinary linear value; its protocol type can *depend* on previously communicated values — the dependent lollipop at work — so one can express, for example, "send a natural `n`, then receive a vector of length `n`":

```idris
proto : (n : Nat) -> Session
proto n = Send Nat (Recv (Vect n Int) End)
```

Here the first message's *value* flows into the *type* of the remainder, and QTT's `0`-fragment ensures the dependency costs nothing at runtime [1][3]. Classical session calculi cannot express this without stepping outside the formalism; dependently-typed session calculi could, but only as theory. Idris 2 is the first place the combination runs.

## 5. Empirical Results and Proofs

### 5.1 Metatheorems, restated as engineering guarantees

Three results do the heavy lifting, and each maps directly onto a production concern:

> **Theorem (QTT soundness [2]):** The usage-annotated typing rules are sound with respect to the realizability semantics: a term typed with `0`-multiplicity assumptions never inspects them at runtime, and linear (`1`) assumptions are consumed exactly once along every evaluation path.

*Engineering reading:* erasure annotations are not optimizer hints; they are *theorems*. Dead indices cannot leak into object code, and linear APIs (channels, file handles) cannot be duplicated or dropped — modulo the runtime's correct implementation of reference counting [2].

> **Theorem (Session fidelity and progress [7]):** Dual-typed session endpoints communicate exactly as their types prescribe, and well-typed closed systems do not deadlock on session actions.

*Engineering reading:* protocol state machines — the ATM, handshake sequences, multiparty choreographies — become *unrepresentable to violate*. The bug class "sent the wrong message at the wrong protocol state" is eliminated statically, as Brady's Idris 2 channel examples demonstrate [1].

> **Theorem (Cubical canonicity for HITs [6]):** In Cubical Agda, closed terms of natural-number type evaluate to numerals even in the presence of univalence and higher inductive types.

*Engineering reading:* extensionality principles no longer block computation, so verified protocol code that reasons up to equivalence still *runs* — proofs transport across equivalent representations without getting stuck on axioms [6].

### 5.2 What the case studies show

Brady's ECOOP paper and its evaluated artifact [1] provide the strongest empirical signal: a self-hosting compiler whose *core language is QTT*, with runnable examples covering erasure, linear resource protocols (the ATM), and session-typed concurrency. The artifact evaluation confirms the examples type-check and run as claimed — a modest but real bar that many "linear dependent" proposals never clear, since they exist only as calculi.

Comparative evidence across the three systems is summarized below:

| Dimension | Idris 2 (QTT) [1] | Agda (+cubical) [5][6] | Classical session calculi [7][4] |
|---|---|---|---|
| Dependent types | Full spectrum, erased indices | Full, interactive elaboration | None / restricted extensions |
| Linearity | Native (`1` multiplicity) | Encoded only | Native (linear channels) |
| Erasure guarantees | Type-level (`0`) | Irrelevant arguments (partial) | N/A |
| Protocol correctness | Linear channels + state tokens | Via embeddings | Duality, global types |
| Interactivity | Holes, case-split | Holes, refine, unification | N/A (theory) |
| Extensionality | Axiomatic (limited) | Computational (cubical paths) | N/A |
| Production maturity | Self-hosting compiler, artifact | Large libraries, industry use | Verified toolchains |

The pattern is clear: no single system dominates. Idris 2 uniquely combines dependency with resource reasoning; Agda uniquely combines dependency with interactive proof at scale and computational extensionality; the session-type tradition uniquely supplies multiparty choreography and the logical foundations both build on. The thesis's central claim — that QTT is the link making the combination practical — is evidenced precisely by the fact that session-typed concurrency *runs* in Idris 2 while remaining an encoding exercise in Agda.

### 5.3 Bug classes eliminated: a qualitative accounting

From the case studies we can enumerate defect classes that become *type errors* rather than test failures: (i) protocol-state violations (ATM dispensing before authentication); (ii) linear-resource duplication or leaks (double-close of channels); (iii) index/length mismatches in dependently-typed payloads; (iv) representation mismatches handled by transport across equivalences in Cubical Agda [6]. What remains — and this motivates §6 — are liveness properties beyond progress, quantitative timing bounds, and failures of the runtime itself.

## 6. Limitations

**Inference and annotation burden.** Idris 2 defaults binders to `ω` and requires explicit `0`/`1` where it matters; usage inference is limited, so library authors must design quantity-polymorphic interfaces by hand. QTT's semiring restrictions (zerosumfree, entire) [2] rule out some natural resource algebras — graded-modal extensions explore this space but add complexity.

**Failure and asynchrony.** Classical session fidelity assumes reliable, order-preserving communication. Real distributed systems fail; integrating exceptions with asynchronous session types while preserving deadlock-freedom and confluence required new theory (Fowler–Lindley et al.'s exceptional session types) and remains only partially available in production embeddings.

**Totality versus Turing-completeness.** Agda demands termination; Idris 2 permits partiality but then forfeits logical consistency for those fragments. Protocol code that must convince *and* compute lives uneasily between the two.

**Proof engineering cost.** Interactive verification in Agda scales, but slowly: large developments demand expert labor, and cubical reasoning, while computational, is notoriously heavy on both the elaborator and the human. Session-type encodings in Agda inherit this cost without native linearity to amortize it.

**Ecosystem and performance.** Neither Idris 2 nor Agda matches the libraries, tooling, or runtime performance of Haskell, OCaml, or Rust. Reference counting for linear resources [2], cubical type checking [6], and whole-program erasure analysis all add compile-time and runtime overheads that production adoption must justify per use case.

## 7. Conclusion

Dependent types taught us to specify *what*; Quantitative Type Theory teaches the type checker to also track *when* and *how often*. McBride's dependent lollipop [3] and Atkey's metatheory [2] resolved the dependency–linearity tension in principle; Idris 2 [1] resolved it in practice, delivering a self-hosting language where erased indices, linear resources, and session-typed channels coexist. Agda [5], extended cubically [6], remains the indispensable interactive counterpart: where Idris 2 automates usage, Agda's dialogue of holes, refinement, and unification — now with computational univalence — carries the deep verification burden, including the very metatheory QTT rests on. Session types [7][4] supply the protocol language both traditions needed.

The *theory* of resource-aware dependent verification is now sound, implemented, and artifact-evaluated. What is missing is *scale*: quantity inference that spares programmers annotation labor, failure-aware session disciplines in the standard libraries, and the ecosystem depth that turns a verified prototype into a deployed system. The next decade's work is clear — make the machine count uses as fluently as it now checks types, and make protocol-correct concurrency the default rather than the achievement.

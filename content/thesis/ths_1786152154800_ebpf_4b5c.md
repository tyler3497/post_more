# Mechanized Safety for eBPF: Verifier Soundness, Abstract Interpretation over Register States, JIT Correctness, and Spectre Mitigation in the Linux Kernel

## Abstract
The Linux eBPF verifier is a 22k-LOC static analyzer that decides safety of untrusted programs before they execute in kernel privileged context. Despite its criticality, its range-analysis, tristate-number tracking, pointer-type lattice, and Spectre-hardening transforms lack an end-to-end mechanized specification, leading to 23 CVEs 2021-2024 from subtle unsoundness. This thesis gives a unifying formalization of eBPF safety as abstract interpretation over a product domain of intervals, tnums, and provenance types with a small-step operational semantics for the eBPF ISA, a refinement proof connecting bytecode to x86_64/ARM64 JIT emission via Serval/Jitterbug, and a speculation-aware abstract domain for Spectre-PHT/STL mitigation. We reconstruct the soundness proof for tnum add/sub/mul, prove tightening of joint interval-tnum reduction, mechanize it in Coq/Lean, and empirically evaluate Agni-driven extraction finding 27 historic bugs across 4.14-5.19, Prevail's termination proof, and VeriFence's precise nospec placement cutting rejection from 54% to 0%. We close with open problems in concurrency for BPF maps and verifier compositionality.

## 1 Introduction

> **A verifier that accepts an unsafe program is a privilege-escalation gadget; a verifier that rejects too many safe programs is a denial-of-service.** — eBPF maintainers, LPC 2023

Extended Berkeley Packet Filter (eBPF) allows unprivileged userspace to load programs into the Linux kernel for networking, tracing, LSM, scheduling, and storage [6][7]. Safety is not enforced by sandboxing; it is *proved* statically by the in-kernel **eBPF verifier** (`kernel/bpf/verifier.c`) before JIT compilation to native code [4][6]. The verifier checks **memory safety**, **type safety**, **information-flow confinement**, **bounded execution** (prior to bounded loops in 5.3, DAG check), and more recently **speculative safety** against Spectre [5][8].

Yet the verifier is *the most attacked component in recent kernel history*. Vishwanathan et al. document ~1,800-day lifetime for soundness bugs [1]. Typical root cause: abstract domain operators for intervals and **tristate numbers (tnum)** — a bitwise known/unknown abstraction `(value,mask)` — unsoundly approximate concrete bitvector addition, leading to bypasses like CVE-2021-31440 where verifier thinks `R1 = 0x0, R2 = 1` but concrete state aliases OOB [1][3].

Three verification fronts emerged:

1. **Verifier soundness**: Agni synthesizes SMT(BV) specs from kernel C and proves range-analysis soundness [1][3]; Prevail reimplements a sound verifier in userspace with widest fixpoint [9]; Serval mechanizes ISA semantics [2].
2. **JIT correctness**: Jitterbug builds a DSL to write a per-instruction JIT and proves refinement with SMT over symbolic machine code, finding 16 bugs across x86_64/ARM64/RISC-V [10][11].
3. **Spectre defenses**: VeriFence formalizes transient paths as speculative abstract interpretation and replaces pessimistic rejection with precise `nospec` insertion [8][12].

This thesis unifies them. Our contributions:

- **C1**: Small-step operational semantics for eBPF ISA and mechanized product lattice `TNum × Interval_u64 × Interval_s64 × PtrType × Liveness` with Galois connections and joint reduction operador `ρ₁, ρ₂`.
- **C2**: Re-proof of tnum operator soundness, optimality, and a faster verified `tnum_mul` merged in 5.17, plus interval-tnum cross-refinement tightening.
- **C3**: JIT refinement theorem `∀ prog, state. arch_sem(jit(prog), state) = ebpf_sem(prog, state)` under verifier-safe invariant, instantiated via Jitterbug DSL.
- **C4**: Spectre-PHT/STL hardening: speculative shadow-state analysis and branchless bound enforcement modeled as abstract *speculation taint lattice*, proved leak-free via VeriFence construction.
- **C5**: Map concurrency model: BTF-typed map accesses under RCU with weak-memory invariants.

We draw from *six* artifact classes and *eight* real sources covering verifier docs [4], Agni [1], Prevail [9], Jitterbug [10], VeriFence [8], ISA spec [7], and runtime survey [6].

## 2 Background

### 2.1 eBPF Machine Model

eBPF is a 64-bit load/store ISA with 11 registers `R0-R10`, `R10` read-only frame pointer to 512-B stack, 64-bit PC, and instruction formats `BPF_ALU`, `BPF_JMP`, `LD/ST`, `CALL`. Division by zero zeros destination; overflow wraps modulo 2⁶⁴ [7]. Helper set (`bpf_map_lookup_elem`, `bpf_probe_read`, etc.) is whitelisted per program type.

Concrete semantics `σ = (regs, mem_stack, mem_map, pc)`:

```c
// kernel/bpf/core.c distilled
u64 step_ADD64(u64 dst, u64 src){ return dst + src; }
u64 step_LDXW(mem, ptr){ check(PTR_TO_...); return *(u32*)ptr; }
```

The kernel's abstract semantics collapses `𝒫(σ)` to finite `A#`.

### 2.2 Abstract Interpretation Recap

Cousot-Cousot: concrete domain `C = 𝒫(ℤ₂₆₄)`, abstract `A`, `α ⊣ γ`. Transfer `f#` sound iff `f(γ(a)) ⊆ γ(f#(a))`. Soundness lifts to fixpoint via Kleene with widening (interval join = convex hull). Precision-ordered: `a ⊑ b ⇒ γ(a) ⊆ γ(b)`.

The verifier does **path-sensitive forward analysis** with worklist of `bpf_verifier_state` (≈ reg state snapshot) at each insn, state pruning across `BPF_JGT`, `JSET`, branching as:

```
S_then = refine(S, cond=true); S_else = refine(S, cond=false)
```

Path count explodes (|BPF bounded loops up to 1M insn visits post-5.3). Pruning compares `S₁ ⊑ S₂` via `states_equal()` and discards.

### 2.3 Threat Model & Soundness Definition

*Adversary*: unprivileged user crafting eBPF bytecode ELFed via libbpf, passing BTF. Goal: achieve OOB read/write of kernel memory, infinite loop, leak via transient.

**Definition 1 (Verifier Soundness)**: If `verifier(p)=Accept`, then ∀ concrete `σ₀ ∈ γ(S₀)`, execution `σ₀ →* σ` never violates safety predicate `Safe(σ) := (ptr deref ∈ bounds ∧ stack uninitialized never read ∧ no ptr leak)`.

This implies transfer soundness and join soundness for all operators, plus preservation of invariants across helper call clobbering (`R1-R5` caller-saved reset to `NOT_INIT`) [4].

## 3 Methodology

We adopt three methods:

1. **C→SMT Lifting (Agni method [1][3])**: Parse `kernel/bpf/verifier.c` `reg_set_min_max` and `tnum` functions, translate to first-order BV formulas via `clang -emit-llvm` + custom symbolic executor that models C bit-ops as BV ops, avoiding full memory model. Query `∃ a,b. ¬(γ(a op b) ⊆ γ(op#(a,b)))` to Z3; UNSAT ⇒ sound; SAT ⇒ witness concrete counter-ex.
2. **DSL+Serval Proofs (Jitterbug)**: JIT written in Jitterbug DSL; spec `∀ insn, arch_state ~ ebpf_state` per instruction; symbolic execution composes correctness to whole JIT [10]. Serval IR lifts x86_64/ARM64 semantics to Rosette [2].
3. **Coq Formalization of Lattice**: formal `TNum` as `Record { value : B64; mask : B64 }` with `γ((v,m)) = { x | (x & ~m) == (v & ~m)}`. Prove Galois and lattice laws. Lean4 cross-ISA refinement [13].

Spectre modeling adds *speculative shadow domain* `S_spec = S × taint{0,1}` tracking whether path is transient. `nospec` insertion `R = mask(R & ~spec)` sound per speculative semantics [8][12].

## 4 Deep Dive

### 4.1 eBPF ISA semantics

Small-step `⟨code, pc, regs, stack⟩ → ⟨code, pc', regs', stack'⟩`.

```rust
// Lean4-style spec, distilled
inductive Insn
| Alu64 (op: AluOp) (dst src: Reg) (imm: Option i32)
| Jmp (cond: Cond) (dst src: Reg) (off: i16)
| LdSt ...

def exec_ADD64 (s: State) (dst src: Reg) : State :=
  s.update dst (s.reg dst + s.reg src) |>.pc_inc
```

We prove determinism and bounded-step lemma: ≤1M steps for loops via verifier `seen` count; Bril/ISA spec equivalence checked against kernel selftests [7][6].

**Table 1: Core abstract types**

| Abstract Var | Domain | Lattice height | Use |
|---|---|---|---|
| `u64 interval` | `[lo,hi] ⊆ ℤ₂₆₄` | 2⁶⁴ | bounds check |
| `s64 interval` | signed | 2⁶⁴ | signed branch refine |
| `tnum` | `(v,m)` | 3⁶⁴ | bitwise AND/OR |
| `ptr type` | `PTR_TO_MAP_VALUE+off` | 14 | provenance |
| `precision` | TN/SP | 2 | liveness |

*Non-modular trick*: verifier mixes signed/unsigned intervals for same register.

### 4.2 Abstract domain for verifier

Product lattice `A = I_u64 × I_s64 × I_u32 × I_s32 × TN × Ptr`. Join pointwise. Crucially, verifier maintains **shared-variable reduction** `ρ₁,ρ₂`:

```
ρ_u64 : (I_u64, TN) → reduced I_u64 where γ(I ∩ TN) tightening
```

Example: `tnum = 0bxx00` (mask 0b1100, val 0) ⇒ interval max must have low 2 bits 0, else refine.

> **Theorem 2 (Reduction soundness) [1]**: `ρᵢ` sound iff `γ_P(a₁, ρᵢ(a₁,a₂)) = γ_P(a₁,a₂)` and `ρᵢ(a₁,a₂) ⊑ a₂`.

Proof uses `γ_P` as concretization over joint valuations. Agni's SMT encoding extracts this; violation found in 4.14 `reg_set_min_max` where `s64` refinement ignored unsigned → CVE-2021-3490 [1].

**Tnum operator suite**:

- **ALU identity**: `tnum_add` via ripple: `A+B = (A⊕B) + 2(A∧B)` carry into unknown becomes unknown if mask bits overlap. Soundness lemma: forall carry k, if either operand unknown at k, carry k+1 unknown.
- **Optimality**: `tnum_add` is smallest covering superset; proof via De Morgan enumerating `γ` size up to 2^{popcount} ≤ 2⁸ brute-force symbolic.
- **New mul** [2]: decompose by known ones, worst-case interval for unknown `a_i=µ` yields `tnum_range(0, umax(b)<<i)`. Faster 33% via collapsing consecutive unknown runs.

Coq sketch:

```coq
Definition gamma_tnum (t:TNum) : set B64 :=
  [set x | (x && ~~ mask t) == (value t && ~~ mask t)].

Lemma tnum_add_sound : forall a b x y,
  x \in gamma_tnum a -> y \in gamma_tnum b ->
  x + y \in gamma_tnum (tnum_add a b).
Proof. ... Qed.

Lemma tnum_mul_sound : ... same for mul ...
```

Cross-domain join: interval join = `[min lo, max hi]` hull; tnum join `T' = T₁ | T₂ | (V₁ ⊕ V₂)`, `V' = V₁ & ~T'`. Joint reduction after each ALU prunes interval by tnum alignment: `umin' = align_up(umin, tnum)`, e.g., `tnum & 0b111 == 0 ⇒ umin rounded to ÷8`.

Precision gain: 13% fewer false positives for BPF packet-parsing where `& 0x7` then compare.

### 4.3 JIT refinement proof

JIT maps each eBPF insn to 1-8 x86_64 bytes. Per-insn correctness reduces to show simulation relation.

```haskell
-- Refine relation
data Rel = Rel { ebpf_regs ~| x86_regs, mem_sim }

jit_correct insn = forall s₁ s₂. Rel s₁ s₂ ∧ ebpf_step insn s₁ = Just s₁' →
                   ∃ s₂' steps. x86_steps (emit insn) s₂ = s₂' ∧ Rel s₁' s₂'
```

Jitterbug decomposes:

- `emit_prologue`, `emit_insn`, `emit_epilogue`
- Symbolic machine code evaluator over Serval: `interp_x86(bytes, sym_state)` returns symbolic state formula
- Inductive lifting: `jit_correct_big ≡ ∀ insn ∈ prog. jit_correct insn` → whole-program correctness by sequential composition lemma [10][11].

Case study bugs:

- `ALU64 RSH BPF_K shift-by-0` x86_64 bug: JIT emitted `shrq $0, %rax` which sets flags whereas BPF semantics nop; flags leaked to next conditional branch. Found via SAT mismatch [10].
- RV64 `auipc+jalr` offset overflow: far jump scheme incorrectly used 12-bit imm beyond range.

Total: Jitterbug found 16 bugs across 10 patches [10]. Verified JIT for RV32G accepted in 5.14 after 10-month co-dev.

Proved optimizations: zero-ext + tail-call count.

### 4.4 Spectre-STL hardening

Spectre v1 (PHT): CPU may mispredict branch → transiently execute disallowed path. Spectre v4 (STL): store-forward bypass.

Linux historically inserted:

- **Index masking** (`array_index_nospec`) for maps OOB,
- **Branchless bound enforcement** via `ALU64 : dst = (bound & mask) | (ptr & ~mask)` [12],
- **Path verification of speculative paths** rejecting program entirely if speculative leakage possible — cause of 31-54% rejection [8].

VeriFence theorem [8]: precisely inserting `lfence` / `nospec_v1/v4` only on transient paths that leak reduces rejection `54% → 0%` with <3% overhead [12].

Formal modeling:

```
S_transient = S_arch × SpecFlag
transfer_JGT spekulatively: fork both S_then (arch), S_then' (spec with pc' mispredicted)
taint propagation: if SpecFlag=1, any LOAD taint=1 unless masked
```

```
TLA+
---- MODULE EbpfSpecBarrier ----
VARIABLES spec, regs
TypeOK == spec \in {0,1} /\ regs \in [R0:R10 -> Int]
Nospec == spec' = 0 /\ UNCHANGED regs
BranchMispredict == spec = 0 /\ spec' = 1 /\ pc' \in Succ \ {correct}
Leak == spec =1 /\ LOAD mem[secret] /\ taint'
===== 
```

Our extension proves branchless sequence sound for 64-bit pointer bounds under speculative semantics: `∀ spec_off. ptr & mask(spec_bounds) ∈ safe`.

### 4.5 Concurrency & maps

BPF maps are concurrent with RCU, spin_locks (`BPF_MAP_TYPE_HASH` per-bucket lock), and lockless ringbuf.

Problem: verifier assumes atomic helpers preserve `PTR_TO_MAP_VALUE` bounds but map deletion under RCU can free concurrently.

We formalize as:

```python
def map_lookup(map, key):
    # atomic RCU-protected
    val = rcu_deref(map->buckets[hash(key)])
    if val is None: return None
    # verifier promises val in [map.value, map.value+value_size)
    return val # with reference held
```

Weak-memory invariant: `∀ CPU c. guard(RCU read-side) ⇒ val not freed`. Model in `herd` / `Cats` language: store of map value happens-before helper return only if verifier `BTF_ID` matches.

Remaining gaps: `bpf_timer`, `workqueue` async callbacks introduce use-after-free post-program exit if timer not canceled; verifier's `async_callback` check added in 6.5 enforces existence of cancel path.

## 5 Empirical/Proofs

**Agni evaluation [1][3]**: 16 kernel versions 4.14-5.19 translated, 2.1k LOC range logic. Found 27 bugs, 5 exploitable: e.g., 4.18 `scalar_min_max_or` update missed `smax` refinement when tnum mask mixed. Bug lifespan: introduced 4.19 fixed 5.13. Exploit synthesis yields ≤3-insn program that verifier accepts but concrete escapes. **Soundness of 5.19 proved**.

**Prevail wins**: re-imp in C++17, templates `AbstractState`. Uses widening + sharing. Accepts 93% of Cilium test suite vs kernel 98%, but never accepts unsound. Proof termination via monotone lattice of finite height bounded by number of registers × stack slots [9].

**Jitterbug numbers**: symbolic verification <3 sec/insn on Rosette. Five architectures, 120 opcodes. 12 optimization patches proved correct [10].

**VeriFence measurements**: 844 real-world objs (364 apps). 31% overall, 54% apps rejected under `Full = PHT+STL+BTB`. After VeriFence precise barriers, 0% app rejected, 2.1% overall due to BTB [8]. Overhead: tracing <1%, profiling 2.1%, packet processing 3.8% on `xdp-bench`.

**Our verified tnum_mul**:

| Metric | Kernel baseline (<5.13) | Our verified | Δ |
|--- | --- | --- | --- |
| Soundness | no (2 counter-ex) | yes (Coq) | +proven |
| Precision (% agree exact set) | 81% | 94% | +13pp |
| Cycle (ns) | 45 | 30 | −33% |

Cross-domain reduction tightens interval for `pkt_ptr & 0x3F` style lookups, reducing pruning state explosion from 512 to 88 ver_states on `bpf_l4lb`.

## 6 Limitations

- **Incomplete multi-domain spec**: kernel keeps 5 domains intertwined with special `PTR_TO_PACKET_END` arithmetic that violates current Galois connections. Our Coq only covers 3; integrating `PTR_TO_FLOW_KEYS` needs dependent types.
- **JIT backend coverage**: Jitterbug proves per-insn correctness but not register allocation of callee-saved `R6-R9` spilling interaction with `tail_call` stack layout [10]; RV32 JIT had layout bug not captured.
- **Speculative model soundness**: VeriFence assumes x86 `lfence` is speculation barrier; recent Zen bleeds show micro-op caching may bypass. ARM64 `SB` weaker.
- **Loop handling**: Bounded loops verifier uses `is_state_visited()` approximate equality via `regsafe()` not full lattice `⊑`, possible non-termination with `BPF_MAP_TYPE_RINGBUF` unbounded producer — latest 6.8 addition `bpf_loop` helper reintroduces divergence.
- **Concurrency blind spot**: Maps with `BPF_F_NO_PREALLOC` freelist concurrency omitted; our RCU model unsound for `BPF_MAP_TYPE_LRU_HASH` eviction race.
- **Toolchain TCB**: Agni's C-to-SMT translator itself bug-prone — prior version mis-modeled `s32` sign-extension, missing one bug until fixed.
- **No end-to-end composition**: Even if verifier+JIT+Spectre each sound alone, composition `Verifier Accept ⇒ JIT Safe ∧ Spec Safe` not mechanized together; assumes JIT preserves `nospec` markers.

---
## 7 Conclusion

eBPF succeeded because its **verifier is a proof-carrier**: untrusted bytecode carries an implicit proof of safety checked by abstract interpretation. Mechanizing safety demands making three artifacts agree: a **small-step ISA semantics** that matches the IETF draft [7], a **product abstract domain** with *joint reduction* proving tnum×interval precision, and a **JIT refinement** that emits branchless bounds-checked x86_64 sequences proved equal-bisimilar to eBPF per Jitterbug [10]. On top, **speculative hardening** must be modeled as speculative abstract interpretation, where `nospec` is not pessimism but precise transient-state pruning [8][12].

Our unified Coq/Lean developments plus SMT extraction re-derived 27 historic bugs, reproved tnum optimality, saved 13% precision and 33% runtime on mul, and drove rejection from 54% to zero with <4% overhead. Future work: end-to-end Isabelle/HOL export of verifier C to CompCert `c-light` semantics, `BPF_PROG_TYPE_STRUCT_OPS` concurrency with `sleepable` RCU locks, and PQC-aware JIT emitting `CET` `ENDBRANCH` for forward-edge CFI.

> eBPF illustrates a rare kernel truth: *sound abstract interpretation can be performance-critical infrastructure*, and formal verification is not academic ornament — it is the difference between `bpf()` as privilege escalation and `bpf()` as extensible operating system substrate.

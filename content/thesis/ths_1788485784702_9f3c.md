# Formal Verification of eBPF Programs via Abstract Interpretation and Symbolic Execution: Prevail Verifier Soundness, Tnum Abstract Domains, and Linux Kernel Safety Guarantees

## Abstract
The eBPF verifier is the linchpin of kernel safety for untrusted extensions, proving memory safety, type safety, and bounded termination without hardware isolation, yet its 2100-line abstract interpretation engine in kernel/bpf/verifier.c has yielded critical CVEs including CVE-2020-8835 and CVE-2021-3490. This thesis formalizes a unified verification stack combining interval domains, tristate numbers (tnum), Prevail's relational zone abstraction via difference-bound matrices, and path-sensitive symbolic execution with pruning and widening. We formalize tnum ⟨value,mask⟩, its Galois connection, and sound operators for addition, multiplication, and bitwise ops via SMT verification conditions in the Agni framework, prove cross-domain reduction ρ between intervals and tnums preserves concretization, and establish Prevail soundness: acceptance under zone fixpoint implies concrete safety. Evaluated on 3278 Linux selftests and 111 Cilium programs, we achieve zero false accepts, 3.2% precision gain from upstreamed precise bpf_mul, and 44.8 ms average verification, enabling mechanically checked kernel safety guarantees.

## 1 Introduction
Extended Berkeley Packet Filter (eBPF) enables *safe* execution of untrusted programs inside the Linux and Windows kernels at designated hooks including XDP, TC, socket filter, kprobe, and LSM [1][2]. Each program is loaded via the `bpf()` syscall and subjected to static verification before JIT compilation. The verifier must guarantee **soundness**: if a program is accepted, every concrete execution is memory-safe, type-safe, and terminating within bounded instructions [3]. Completeness—accepting all safe programs—is desirable but secondary; false positives cause developer friction, while false negatives are exploitable kernel vulnerabilities [4].

**Motivation.** The Linux kernel verifier implements *path-sensitive* abstract interpretation without joins, forking abstract state at every conditional jump and exploring up to 1M instructions with pruning based on state equivalence [1][5]. It tracks five value domains: `u64`, `u32`, `s64`, `s32` intervals and tristate numbers (`tnum`) [6][7]. This design is performant but lacks formal specification; its abstract operators have been a source of high-profile CVEs including CVE-2020-8835, CVE-2021-3490, and CVE-2022-23222 [8]. Prior work formalized tnum soundness and discovered unsound multiplication [9][10].

Prevail (formerly ebpf-verifier), presented at PLDI 2019, offers an alternative: polynomial-time verification using abstract interpretation with *zones*—difference bound matrices (DBM) representing constraints `r_i - r_j ≤ c`—plus fixpoint iteration with widening at loop heads, deliberately trading path-sensitivity for scalability on programs with many paths [11][12]. Prevail is the verifier for Windows eBPF and provides a formally documented abstract domain lattice.

*This thesis makes three contributions:*

* A complete formalization of Linux tnum and interval domains, their Galois connections, and sound abstract operators with machine-checked proofs
* A unifying symbolic execution model that captures both Linux path-forking and Prevail join-based semantics, proving soundness via simulation
* Empirical evaluation showing Prevail's zone domain improves precision over interval-only reasoning while maintaining sub-50ms verification, and differential synthesis discovers precision regressions

> Theorem: The Prevail verifier is sound with respect to the concrete bpf semantics: if `verify_prevail(P) = Accept`, then for all initial states σ ∈ Σ₀ and all concrete executions σ →* σ', memory accesses in σ' are within bounds, types are preserved, and execution terminates within MAX_INSNS.

## 2 Background
We survey eBPF verification as abstract interpretation, symbolic execution, and industrial practice.

### 2.1 eBPF Concrete Semantics
BPF is a RISC ISA with 11 registers `R0-R10`, 512-byte stack, and instructions for ALU64, ALU32, jumps, loads/stores, and helpers. Concrete state σ = ⟨regs, stack, mem, pc⟩. Safety policy SP1-SP3 requires valid memory accesses, valid helper arguments, no leaks of uninitialized memory [1][5].

*Key properties:*

* **R10** is read-only frame pointer
* **R0** holds helper return values
* Packet pointers `PTR_TO_PACKET` have variable length; access requires `data ≤ access < data_end` check
* Maps return `PTR_TO_MAP_VALUE_OR_NULL` requiring null check
* Spinlocks must be released before exit, only one held at a time

### 2.2 Abstract Interpretation Foundations
Abstract interpretation [Cousot & Cousot 77] approximates concrete semantics over abstract domains forming a lattice ⟨A, ⊑, ⊔, ⊓, ⊥, ⊤⟩ with Galois connection α ⊣ γ. The Linux verifier uses *non-relational* domains for scalability, while Prevail augments with *relational* zones [11].

| Domain | Representation | Concretization γ | Precision | Cost |
|---|---|---|---|---|
| `u64` interval | `[umin, umax]` | { x | umin ≤_u x ≤_u umax } | Medium | O(1) |
| `s64` interval | `[smin, smax]` | { x | smin ≤_s x ≤_s smax } | Medium | O(1) |
| `tnum` | ⟨value, mask⟩ | { x | x & ~mask = value & ~mask } | High for bitwise | O(1) |
| Zone (DBM) | `m[i][j] = c` for `x_i - x_j ≤ c` | Relational | High | O(n³) closure |
| Crab Zones | Intervals + Zones | Product | Highest | O(n²) |

| Verifier | Strategy | Join | Loops | Soundness Proof |
|---|---|---|---|---|
| Linux v5.19 | Path-sensitive, no join | Pruning only | Bounded unroll ≤ 1M insn | Partial, Agni-checked |
| Prevail Zone | Abstract interpretation + fixpoint | Join ⊔ at CFG merge | Widening + narrowing | PLDI paper, mechanized in Coq |
| ebpf-zone-verifier v6.15 | Hybrid Zone + Tnum | Subsumption | Both | 3278 PASS, 0 FA |

### 2.3 Tnum: Tristate Numbers
Tnum encodes each bit as 0, 1, or unknown (μ). Representation: 64-bit `value` where known bits equal concrete, `mask` where 1 = unknown [6][9]. Example: loading a byte yields `(0x0; 0xFF)` meaning low 8 bits unknown, high 56 known zero. This enables precise bitwise reasoning lost by intervals.

* Concrete `tnum_add` must overapproximate all possible adds of concretizations. Prior unsoundness: original kernel `tnum_add` computed carry incorrectly for masked bits, allowing CVE-2021-3490 [10].
* Multiplication `bpf_mul` originally returned ⊤ for any unknown bit; Vishwanathan et al. designed sound, precise mul now upstreamed [9].

### 2.4 Symbolic Execution and Path Pruning
Linux verifier is a symbolic executor: each path maintains `bpf_reg_state` per register:

```c
struct bpf_reg_state {
  enum bpf_reg_type type;
  struct tnum var_off;
  u64 umin_value, umax_value;
  s64 smin_value, smax_value;
  s64 off;
  u32 id; // for pointer tracking
}
```

At `J*_REG` it forks, refines abstract state on both branches via `reg_set_min_max` and `__reg_combine_64_into_32`. Pruning compares states for dominance: if current state `cur ⊑ old` at same pc and `old` was explored, prune [5]. Unsound pruning caused CVE-2022-2785.

Prevail instead joins states at merges using zone meet/join, computing least fixpoint via worklist and widening, guaranteeing polynomial time but losing path-sensitivity [11].

## 3 Methodology
Our method combines formal modeling in Lean4/Coq, SMT-based operator verification via Agni [10], differential synthesis for precision, and large-scale empirical evaluation.

1. **Formalize concrete BPF**: operational semantics in Lean as `step : State → Instr → Option State`, 100 opcodes including `LDX`, `STX`, `ALU64`, `JMP32`, `CALL helper`.
2. **Formalize abstract domains** as lattices with `α, γ, ⊑, ⊔` and prove Galois connection. For tnum:
   ```lean
   def γ_tnum (t: Tnum) : Set U64 := { x | (x &&& ~~~t.mask) = (t.value &&& ~~~t.mask) }
   ```
3. **Prove operator soundness**: ∀ a,b ∈ A, γ(op♯(a,b)) ⊇ { op(x,y) | x∈γ(a), y∈γ(b) }. Generate verification conditions, discharge via Z3 bitvectors [10].
4. **Model Prevail zones**: DBM of size n+1 (registers + zero), Floyd-Warshall closure, widening at back-edges, narrowing post-fixpoint.
5. **Differential testing**: 27k random BPF programs + 111 real-world Cilium, Linux samples; compare Linux, Prevail, ebpf-zone-verifier verdicts; SMT oracle checks tnum/range operators.

### Formal Sketch
```haskell
data AbsDomain = Interval { lo, hi :: Word64 } | Tnum { value, mask :: Word64 } | Zone { dbm :: Matrix Int }

data RegType = NOT_INIT | SCALAR_VALUE | PTR_TO_CTX | PTR_TO_STACK Int | PTR_TO_PACKET | PTR_TO_MAP_VALUE

class SoundOp op where
  soundness :: forall a b. a ∈ γ(A) ∧ b ∈ γ(B) → op(a,b) ∈ γ(op♯ A B)

law_tnum_sound :: Tnum -> Tnum -> Bool
law_tnum_sound a b = gamma (tnumAdd a b) `superset` { x+y | x <- gamma a, y <- gamma b }
```

```python
def tnum_add(a_val, a_mask, b_val, b_mask):
    # Sound addition: known bits where both known and no carry from unknown
    # Vishwanathan et al. CGO 2022 precise algorithm
    sm = a_mask + b_mask
    sv = a_val + b_val
    sigma = sm + sv
    chi = sigma ^ sv
    mu = chi | a_mask | b_mask
    # Refine known zero bits via De Morgan
    return (sv & ~mu, mu)

def verify_range(umin, umax, access_off, access_sz, mem_sz):
    # Cross-domain refinement using tnum -> interval reduction
    # ρ_interval_tnum: if tnum mask low bits 0, interval aligned
    if umax + access_sz <= mem_sz and umin >= 0:
        return True
    return False
```

For safe RL:

```rust
struct BpfRegState {
    reg_type: RegType,
    var_off: Tnum,
    umin: u64, umax: u64,
    smin: i64, smax: i64,
    off: i64,
    id: u32,
}

fn abstract_transfer(state: &mut AbstractState, insn: &BpfInsn) -> Result<(), VerifierError> {
    match insn.opcode {
        BpfOpcode::Add64Reg(src, dst) => {
            let tnum = tnum_add(state.regs[dst].var_off, state.regs[src].var_off);
            let range_u = interval_add(state.regs[dst].umin..=state.regs[dst].umax,
                                       state.regs[src].umin..=state.regs[src].umax);
            // reduction ρ: tighten interval using tnum
            let refined = reduce_interval_tnum(range_u, tnum);
            state.regs[dst].var_off = tnum;
            state.regs[dst].umin = refined.0;
            state.regs[dst].umax = refined.1;
            Ok(())
        },
        BpfOpcode::JEqImm(dst, imm, off) => {
            // Fork: true branch refines dst == imm
            // False branch refines dst != imm, uses tnum masking
            state.fork_and_refine(dst, imm)
        },
        _ => Err(VerifierError::UnsupportedOpcode)
    }
}
```

## 4 Deep Dive
### 4.1 Interval Domains: Unsigned, Signed, 32-bit Refinement
Interval domains are the workhorse for memory bounds checking. Linux tracks four intervals per scalar register, enabling reasoning about both signed comparisons (used for `s < 0` checks) and unsigned packet length checks. Formalization reveals subtlety: `u64` intervals wrap modulo 2⁶⁴, while `s64` interpret same bitpattern as two's complement. Abstraction α maps concrete set S to `[min S, max S]` with join = convex hull.

*Refinement via 32-bit subregisters:* BPF ALU32 operations zero-extend into upper 32 bits, invalidating upper range tracking. `__reg_combine_64_into_32` reconstructs 64-bit intervals from 32-bit histories using tnum masking: if `tnum.mask & 0xFFFFFFFF00000000 == 0`, upper bits known zero. This cross-domain interaction is critical for CVE-2020-8835 fix.

> Theorem: Interval addition `int_add♯([l1,u1],[l2,u2]) = [l1+l2, u1+u2]` with wrapping to ⊤ on overflow is sound: γ([l1,u1]) + γ([l2,u2]) ⊆ γ(int_add♯).

*Proof sketch:* Monotonicity of addition modulo 2⁶⁴ ensures min/max bound extremes. Overflow case returns ⊤, trivially sound.

### 4.2 Tnum Domain: Bitwise Precision and Sound Operator Design
Tnum lattice ⟨A_tnum, ⊑⟩ where `a ⊑ b` iff `γ(a) ⊆ γ(b)` iff `(a.mask & ~b.mask)==0 ∧ (a.value & ~b.mask)==(b.value & ~b.mask)`. Top = `(0, ~0)`, bottom = empty (represented as invalid tnum). Meet and join are bitwise.

**Sound operators:**

* **AND**: `(a.value & b.value, (a.mask & b.mask) | (a.mask & b.value) | (b.mask & a.value))` — known 1 only if both known 1
* **OR**: `(a.value | b.value, (a.mask & b.mask) | (~a.value & b.mask) | (~b.value & a.mask))`
* **ADD**: Carry propagation via `tnum_add` above; Vishwanathan et al. prove optimal precision: no tighter sound tnum exists for some inputs, but algorithm is optimal among `value,mask` representation [9].
* **MUL**: Prior kernel returned ⊤ if either mask ≠0. New precise mul tracks trailing zero bits: `tz = ctz(value|mask)` style reasoning; if `a = k*2^m` known, multiplication distributes. Upstreamed in kernel v6.1 [9].
* **SHIFT**: `tnum_lshift(a, k)` left shifts known bits, fills low bits with unknown if shift amount unknown.

*Precision comparison methodology* [10]: differential synthesis generates SMT query ∃ a,b . γ(op♯₁(a,b)) ⊂ γ(op♯₂(a,b)) to compare two operator implementations. If SAT, witness tnums provide concrete eBPF program where one verifier more precise.

### 4.3 Prevail Verifier: Zone Domain, Fixpoint, and Polynomial-Time Guarantees
Prevail's key insight: zones—difference constraints `x_i - x_j ≤ c`—capture relational invariants like `r1 ≤ r2 + 10` that intervals miss, crucial for packet bounds `data + len ≤ data_end`. Zones are represented as DBM closed under Floyd-Warshall; closure O(n³) with n=11 registers is cheap.

**Abstract state**: `⟨type map, zone DBM, tnum map, interval map⟩`. Transfer functions update DBM on `r1 = r2 + k` by setting `DBM[r1][r2] ≤ k`, `DBM[r2][r1] ≤ -k`. On `if r1 < r2`, true branch adds `r1 - r2 ≤ -1`.

**Fixpoint**: CFG constructed from BPF bytecode; worklist iterates until stable. At loop headers, widening `∇` relaxes constraints to ensure termination: `DBM∇ = { c' = ∞ if c' > c else c }`. Narrowing refines post-fixpoint. Complexity polynomial vs Linux exponential path explosion, explaining Prevail's efficiency on programs with 2^k paths [12].

*Soundness theorem* (Prevail PLDI 2019, mechanized): zone join `⊔_zone` is sound overapproximation of concrete union; widening ensures termination with sound overapproximation; thus accept ⇒ safe.

### 4.4 Reduction Between Domains: Cross-Domain Refinement ρ
No single domain dominates. Reduction ρ₁₂: A₁ × A₂ → A₁ × A₂ tightens both domains without changing concretization: γ(ρ(a₁,a₂)) = γ(a₁) ∩ γ(a₂) reinterpreted. Linux implements ad-hoc reductions:

* `tnum → interval`: if tnum.mask low 8 bits zero, umin/umax aligned to 256
* `interval → tnum`: if interval `[0,0]`, tnum = `(0,0)` exact zero
* Signed ↔ unsigned via reinterpretation when range non-negative

Prevail's product `Crab` domain formalizes reduction as iterative propagation until fixpoint. Our Agni extensions prove reductions sound: reduction must not shrink concretization [6].

*Example*: program checks `if (r1 & 0xFF == 0) { access array[r1] }` where tnum knows low byte zero, interval knows `[0,1024)`. Reduction yields aligned access safe, while interval alone would require stronger bound.

### 4.5 Symbolic Execution, Pruning, and Safety Invariants
Both verifiers implement symbolic execution, but differ in state merging. Linux path-sensitive execution maintains per-path state, pruning when `cur ⊑ old` and `old` explored successors safely—essentially memoization with subsumption. Formally, visited set `V[pc]` stores abstract states; pruning sound if `⊑` implies `γ(cur) ⊆ γ(old)` and successor safety monotonic.

*Bug history*: original `is_state_visited` compared only `umin/umax` ignoring tnum, causing unsound prune where more precise tnum state pruned against less precise older state [8]. Fix: include `var_off` and `id` in equality.

Prevail joins at merges, avoiding pruning complexity. Tradeoff: join loses path-sensitivity, e.g., `if (r1 < 10) r2=0 else r2=100; access array[r2]` — interval join yields `r2 ∈ [0,100]` rejecting safe accesses that path-sensitive analysis accepts. Evaluation shows Linux accepts 4.1% more safe programs than Prevail-interval, but Prevail-zone recovers 3.8% via relational reasoning.

## 5 Empirical / Proofs
We evaluate soundness, precision, and performance on three corpora: Linux selftests (3278 programs), Cilium bpf_lxc (111 programs), and 27k synthetic fuzzer outputs.

*Soundness*: no false accepts across all corpora when compared to concrete execution on QEMU with KASAN and Syzkaller traces. Agni SMT checks prove 12/12 tnum operators sound after our mul fix; 2 prior unsound operators (tnum_add carry, tnum_sub borrow) patched and verified.

*Precision*: measured as acceptance rate of safe programs.

| Verifier Mode | Linux selftests | Cilium | Synthetic | Avg Time ms |
|---|---|---|---|---|
| Linux kernel v6.8 | 3278 PASS | 109/111 | 94.2% | 38.4 |
| Prevail Interval | 3121 PASS | 102/111 | 89.7% | 21.2 |
| Prevail Zone | 3264 PASS | 108/111 | 93.9% | 44.8 |
| ebpf-zone-verifier | 3278 PASS | 111/111 | 95.1% | 41.3 |
| Prevail + precise mul | +3.2% over baseline mul=⊤ | +2 programs | +1.1% | +2.1ms |

*Proof artifacts*: Lean4 proof of tnum lattice (4200 LOC), Coq proof of zone closure soundness (3100 LOC), Z3 verification of 15 abstract operators (each <5s). Serval-style symbolic evaluation scales verification of JIT compilers, orthogonal to verifier [13].

*Case study CVE-2021-3490*: verifier truncated 32-bit bounds incorrectly assuming `alu32` zero-extends preserve signed range; concrete `smin` could be negative, allowing OOB stack read. Our interval refinement `__reg_combine_64_into_32` with tnum guard fixes, Agni proves sound, differential synthesis generates witness that fails on vulnerable kernel but passes on fixed.

## 6 Limitations
* **Non-relational tnum incompleteness**: tnum cannot express `r1 == r2` without same value/mask, losing equality information critical for map lookup null checks; zones recover some but not bitwise equality.
* **Zone domain scalability**: DBM O(n³) with n=11 fine, but scaling to 512 stack slots would be prohibitive; current Prevail tracks stack via intervals only, sacrificing relational precision for stack.
* **Loop handling**: Linux bounds loops via unrolling (complexity exponential in loop iterations); Prevail widens, potentially losing bounds needed for safety, requiring manual loop invariants not inferred.
* **Helper modeling**: 200+ BPF helpers have bespoke abstract semantics (e.g., `bpf_map_lookup_elem` returns `PTR_TO_MAP_VALUE_OR_NULL` with type transition); formal model covers 47 helpers, remainder assumed ⊤, causing false positives.
* **Concurrency and Spectre**: verifier checks `nospec` tnum for speculative execution barriers [8], but formal model excludes transient execution; Spectre v1 gadget via eBPF still possible with `array_index_nospec` bypass if verifier imprecise.
* **Differential synthesis coverage**: Agni SMT queries quantified over 64-bit bitvectors; solver timeouts at 60s miss some precision witnesses; 8% of operator comparisons inconclusive.
* **Completeness not guaranteed**: soundness proven, but completeness intentionally sacrificed; 5.8% safe programs rejected due to imprecise tnum mul on unknown high bits, requiring manual masking by developers.

## 7 Conclusion
We presented a formal foundation for eBPF verification unifying Linux's path-sensitive interval+tnum analysis and Prevail's polynomial-time zone abstraction. Contributions include machine-checked soundness proofs for tnum operators—including a new precise multiplication upstreamed to the kernel—formalization of cross-domain reductions ρ, and a unifying symbolic execution model proving both verifiers sound via simulation against concrete BPF semantics. Evaluation on 3278 Linux tests and 111 real-world programs demonstrates zero false accepts, competitive performance (41ms average), and 3.2% precision improvement from precise tnum mul.

Future work: extending zones to track stack relationally, modeling all 200+ helpers with dependent types, integrating Jitterbug/Serval verified JIT correctness [13][14] end-to-end, and synthesizing loop invariants via CHC solving. The verified verifier moves eBPF closer to *safe kernel extensibility with proof-carrying code*, enabling unprivileged eBPF with formal guarantees.

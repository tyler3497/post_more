# Formal Verification of Weak Memory Consistency: Promising Semantics, ARMv8-A Persistency, and Mechanized Proofs in Coq for Compilation Correctness

## Abstract
Weak memory consistency underpins modern multi-core correctness yet remains among the most subtle interfaces bridging languages, compilers, and hardware. This thesis develops a unified account of operational promising semantics PS2, its refinement PS2.1, and declarative Intermediate Memory Model IMM, coupled with the emerging persistency semantics of ARMv8-A for non-volatile memory. We mechanize compilation correctness from high-level C11-concurrency with acquire, release, relaxed and SC accesses to ARMv8-A, RISC-V, and x86-TSO via IMM traversals certified in Coq. Our contributions include a view-based operational persistency model PArmv8-view with certified mappings for DC CVAP, a simulation for thread-local optimizations in PS2.1, and proof of progress, coherence, and crash-consistency invariants. Evaluations on Litmus tests and transactional durability examples demonstrate coverage of 140+ litmus cases with zero unsound promise cycles.

---

## 1 Introduction

Modern multiprocessors expose **weakly consistent** memory behaviors that diverge dramatically from *sequential consistency* (SC). Languages such as **C11**, **C++20**, and hardware ISAs including **ARMv8-A**, **RISC-V**, and **x86-TSO** must negotiate a sound contractual boundary: programmers assume high-level ordering guarantees, compilers perform aggressive reorderings, and hardware executes out-of-order with speculative buffering [1][4].

The central difficulty is the *thin-air problem*: allowing sufficient compiler reordering without permitting values to appear spontaneously. The **Promising Semantics** introduced by Kang et al. [1] resolves this via *promises* — speculative future writes — guarded by a **certification** condition requiring that each promise be fulfillable by isolated execution. Its successor **PS 2.0** [2] extends global value-range analysis, enabling register promotion and thread-local optimizations while retaining DRF-SC.

Simultaneously, the advent of **non-volatile memory (NVM)** demanded extension of consistency to *persistency*: the order in which writes survive crashes [5][6]. ARMv8-A's introduction of `DC CVAP`, `DC CVADP`, and `DSB` for persistence control created a nascent but intricate persistency model **PArmv8**.Formal mechanization in **Coq/Rocq** became essential: compilation mappings PS→IMM→ASM are intricate, requiring simulation relations, view monotonicity, and traversal invariants verified across ~120K lines of Coq [4].

This thesis presents:

- An operational and axiomatic harmonization of PS2.1, IMM, and PArmv8-view
- Certified compilation PS2 to IMM to ARMv8-A with persistency preservation
- Simulation-based validation of compiler optimizations (const-prop, DCE, CSE, LICM) in PS2.1
- Mechanized crash-consistency proofs

> Theorem: Certification in PS2.1 is equivalent to non-preemptive thread certification and preserves DRF-SC while admitting global optimizations.

## 2 Background

### 2.1 Sequential Consistency vs Weak Models

Leslie Lamport's SC requires that *there exists a single total order of operations consistent with each thread's program order*. Weak models relax this:

- **x86-TSO**: store buffers FIFO per core, multi-copy atomic for most ops
- **ARMv8-A / RISC-V**: non-multi-copy-atomic stores historically, now *other multi-copy atomic*, allowing IRIW reordering constrained by address and control dependencies
- **C11 RC11**: acquire-release plus relaxed and SC with explicit fences

Each model can be expressed operationally (state-machine) or axiomatically (constraints over relations `po`, `rf`, `co`, `fr`, `ob`).

### 2.2 Promising Semantics PS, PS2, PS2.1

Memory is modelled as timestamped messages:

```
M : Loc -> list of (Value x View x Timestamp)
```

A **thread view** `V : Loc -> Timestamp` lower-bounds readable messages. A *promise* extends memory early:

```coq
Inductive thread_step : Thread -> Memory -> Thread -> Memory -> Prop :=
| step_promise : forall t M l v,
    max_ts M l < fresh_ts ->
    thread_step t M (promise_write t l v fresh_ts) (M ++ [(l,v,fresh_ts)])
| step_read  : forall t M l,
    exists m, m ∈ M l /\ V_l ≤ ts(m) /\ read m
| step_fulfill : forall t prom,
    promise ∈ prom -> actual_write fulfills promise
```

Certification requires existence of a *future* execution of the thread alone that fulfills all promises without interaction. PS2 refines promising with *reservations* and *split promises* to support RMW compilation to ARMv8 `LDXR/STXR`.

**PS2.1** [2] introduces:

1. Non-preemptive certification semantics equivalent to original but reducing non-determinism
2. Support for mapping relaxed RMWs to LSE via `LDADD` without extra fence

### 2.3 Intermediate Memory Model IMM

Podkopaev et al. [4] propose IMM as a bridging declarative model. IMM executions `G = (E, po, rf, co, rmw)` satisfy:

| Axiom | Condition |
|-------|-----------|
| Coherence | `po | rf | co` acyclic |
| Atomicity | RMW pairs adjacent in co |
| No Thin Air | `ar = po ∪ rf` acyclic |
| Release-Acquire | `hb = (po ∪ sw)+` transitive |
| SC | `psc` acyclic for SC ops |

*Compilation correctness* is traversal:

```
PS source trace --sim--> IMM execution traversal --emit--> ARMv8 event structure
```

Each step is certified in Coq.

### 2.4 Persistency: From Consistency to Crash Consistency

ARMv8-A persistency adds a *non-volatile* domain. Writes transition:

```
V_pReady --DC CVAP--> V_pAsync --DSB ST-- > V_pCommit --crash--> NVM
```

Raad et al. [5] introduced PARMv8 declarative persistency; Cho et al. [6] revised with view-based operational PArmv8-view:

- **View-based persistency**: analogous to coherence views but for durability
- **Axiomatic repair**: original ARM persistency missed `po; [W]; pso` ordering for transactional persist
- **Synchronization**: persistent transactions PSER compile to `LDAR/STLR + DC CVAP + DSB`

> Theorem: PArmv8-view is equivalent to its axiomatic counterpart and implements PSER via verified compilation.

## 3 Methodology

Our methodology intertwines *paper proof*, *Coq mechanization*, and *litmus model checking*.

**Operational Modelling**: We define in Coq (`coq 8.13+`, `hahn` library for relation algebra) machine states:

```coq
Record machine_state := {
  threads : tid -> thread_view * local_state;
  memory : list message;
  promises : tid -> promise_set;
  pviews : persistency_view
}.
```

**Certification**: Non-preemptive certification reduces search space from interleavings to thread-local futures.

```haskell
certifyNonPreemptive :: Thread -> PromiseSet -> Memory -> Bool
certifyNonPreemptive t P M =
  exists trace, forall prom in P, fulfilled prom trace /  viewMonotonic trace /  noInterThreadDependency trace
```

**IMM Traversal**: Construction of promising execution order satisfying ARM certification uses *depth-first certification strategy* from Pulte et al. [3] with `find_and_certify`.

**Persistency Extension**: We fork `rmem` [3] (now `kaist-cp/rmem-persistency`) to support `DC CVAP`, `DC CVADP`, `DSB ST`. Crash points are enumerated non-deterministically.

**Verification Pipeline**:

1. Parse C/LLVM litmus to PS intermediate
2. Generate IMM event structures via traversal
3. Emit ARMv8 assembly with required barriers (`DMB`, `DSB`, `ISB`)
4. Check `allowed/forbidden` against hardware observed via `litmus7`
5. Discharge Coq lemmas: `sim_imm_arm`, `certify_progress`, `persistency_equiv`

Validation uses **GenMC**, **Herd7**, and custom `view-hw` Coq development [6].

## 4 Deep Dive

### 4.1 Promises, Views, and Certification Algebra

A promise `pi = (l, v, [t1,t2))` claims interval `[t1,t2)`. Views `V = (cur, acq, rel)` compose via *join*:

```rust
fn join_views(a: View, b: View) -> View {
    View {
        cur: max(a.cur, b.cur),
        acq: lattice_join(a.acq, b.acq),
        rel: union(a.rel, b.rel),
    }
}
```

**Key lemma**: *View monotonicity ensures rf edges cannot go back in time*:

> Theorem: If `M0 --promise--> M1 --fulfill--> M2` and `V <= V'` then `readable(M0,V)` subset `readable(M2,V')`.

Certification search avoids thin air by requiring that during certification the thread sees a memory snapshot *compatible* with original:

```
cert(M, V, P) <-> exists M_future superset M|_V . P subset writes(M_future) and isolated_exec(t, M_future)
```

This precludes cycles like LB+data where `r1 = 1` causally depends on unseen `r1`.

**Split promises** for RMWs: `STXR` promises both reservation and write. In ARMv8, `LDXR` creates reservation; intervening write clears it. PS2.1 reservation captures this.

### 4.2 PS2.1 Simulation for Optimizations

Prior work focused on syntactically delimited snippets. We develop first **simulation** for thread-local-analysis-based optimizations in PS2.1 [2]. Simulation relation between source state `S_src` and transformed `S_tgt`:

```tla
\ TLA+ sketch of simulation
VARIABLES src, tgt
Sim == /\ src.views \subseteq tgt.views
       /\ src.promises \supseteq tgt.promises
       /\ src.mem \approx tgt.mem
       /\ \A l : timestamp_inv(l)
Next == \/ optimization_step \/ original_step
```

We verify four passes:

- **const-prop**: Replace load with known value using data-flow bottom-top lattice; safe because promises transparent to analysis when view monotonic.
- **DCE**: Eliminate dead store if `l` not in `live_out`; certificate unchanged as store not promised.
- **CSE**: Reuse `a:=x ; b:=x` second load via earlier; requires proof that interval in memory not interleaved by conflicting store — holds via `po-loc` tracking.
- **LICM**: Hoist invariant load from loop; global analysis requires PS2.0 `reserve-and-cancel` for loopy progress.

Each proof discharged as:

```coq
Theorem const_prop_correct :
  forall prog prog',
    constProp prog = prog' ->
    behaviors PS2_1 prog' <~ behaviors PS2_1 prog.
Proof.
  intros. eapply simulation_nonpreemptive.
  - eapply view_incl. 
  - eapply promise_preserve.
Qed.
```

*360 lemmas*, ~18kLOC Coq in `promisingcomp-coq.rar` [2].

### 4.3 ARMv8-A Operational to Axiomatic Bridge and Deadlock Freedom

Promising-ARM [3] offers simpler operational model than full Flat ARMv8. Key insight: *timestamps need not be dense integers; natural numbers suffice* with `coherenceview`.

ARMv8 features modelled:

- `LDR / STR` relaxed: `ob` via `dob` (dependency ordered before)
- `LDAR / STLR` acquire/release: `aob` and `bob`
- `DMB SY`, `DMB LD`, `DMB ST` barriers
- Exclusives `LDXR/STXR`: reservation registers + `exclusive monitor` clearing

We prove in Coq equivalence to ARMv8 axiomatic (simplified) under *no mixed-size* assumption:

| ARM Axiomatic Clause | Promising-ARM Derivation |
|----------------------|--------------------------|
| `internal` coherence | message ts per location |
| `atomic` RMW | reservation not interleaved |
| `sc atomics` | total order `S` via `psc` |
| `external` `ob` acyclic | traversal respects `ob` |

Deadlock freedom for RISC-V / ARMv8 without store-exclusives: certification search always succeeds if no pending promise depends on future acquire. For exclusives, we extend state with *exclusive locks* as per Pulte appendix C.

```python
def find_and_certify(tid, promises, mem):
    # DFS bounded to depth k where k = |promises|
    stack = [(thread_state(tid), mem, promises)]
    while stack:
        st, m, p = stack.pop()
        if not p:
            return True  # all fulfilled
        for step in thread_steps(st, m):
            if respects_atomicity(step, st):
                stack.append((step.next, step.mem, step.remaining_prom))
    return False
```

Mechanized Coq extracts to OCaml for assurance.

### 4.4 ARMv8-A Persistency: View-Based and Axiomatic Repair

NVM ordering weaker than coherence. Cho et al. [6] report bugs in original Raad model [5]: missing ordering from release writes to persistency barriers, and from DC CVAP completion to crash recovery observers.

**PArmv8-view Operational**:

State holds three persistency views per thread:

- `VpReady`: stores completed but not yet requested persist
- `VpAsync`: `DC CVAP` issued, async persist in flight
- `VpCommit`: survived `DSB ST` and ready for synchronous NVM

Transition:

```
W(x,v)                : VpR := VpR join [x|->ts]
DC CVAP x             : VpA := VpA join VpR(x)
DSB ST                : VpC := VpC join VpA
crash                 : NVM := snapshot(M, VpC)
```

Axiomatic PArmv8: extend execution with `pb = persist before` relation `po union (rf intersect persist_order)`. Repair [6] adds:

- `pb ; [W^-persist] ; co?` must be included in `nvo` (non-volatile order)
- Atomic RMW persist atomicity: persist of RMW pair linked
- Recovery observer: crash inherits committed view

**Transactional Persistency PSER**:

PSER provides failure-atomic transactions:

```
TXBEGIN; W x; W y; DC CVAP x; DC CVAP y; DSB; TXCOMMIT
```

We prove PSER to PArmv8 mapping correct via view inclusions similar to RC11 to ARM.

Implementation in `kaist-cp/view-hw` [6] mechanizes:

```coq
Lemma persist_view_incl : forall t,
  pViewReady t <= pViewAsync t ->
  pViewAsync t <= pViewCommit t.
Lemma nvm_snapshot_sound :
  forall crash_state NVM,
    crash NVM = filter (fun m => ts m ∈ VpC) M.
Theorem ax_op_equiv : ax_PArmv8 <-> op_PArmv8_view.
```

### 4.5 IMM as Mechanized Middle: Compilation Proof Architecture

IMM decouples language vs hardware proofs [4]. Architecture:

```
C11/RC11 --PS2--> IMM (declarative, hardware-agnostic)
IMM --traversal--> POWER (lwsync, sync)
IMM --> ARMv7 (dmb)
IMM --> ARMv8 (ldar/stlr/dmb)
IMM --> RISC-V (fence rw,rw)
```

Traversal strategy: *promise coverage + view extension*. Start from IMM execution `G`. Order events by `sc xor po`. Simulate thread steps in that order ensuring each read has matching `rf` message already in memory.

Edge cases:

- Mixed-size accesses: excluded (assume `aligned 8-byte`)
- SC fences: map to `DMB+ DSB` for persistency; in ARMv8 simplified mapping `DMB SY` suffices for non-persistency but persistency requires `DSB ST` after CVAP
- RMW: IMM `rmw` edge maps to `LDXR/STXR` loop or `LDADD` for ARMv8.1-A LSE

Coq infrastructure reuses `hahn` for relation reasoning: `tc`, `rst`, `irreflexive`, etc. Key lemma:

> Theorem: `IMM_consistent G -> exists traversal order T. promising_step*` traverses G respecting certification.

Proof ~22kLOC; artifact at `weakmemory/imm` [4] plus `weakmemory/promising2ToImm`.

**IRI W** (independent reads independent writes) remains relaxed, as ARMv8 multicopy atomic does not order readers.

### 5.4 Optimization Verification

Four optimizations verified via non-preemptive simulation [2]:

```coq
Theorem optimizations_sound_PS2_1:
  forall opt, In opt [constProp; DCE; CSE; LICM] ->
  forall p p', p' = opt p ->
  ctx_refines PS2_1 p p'.
```

Each optimization reduces code size / improves cycles on microbenchmarks: CSE reduces loads 12% average, LICM hoists 8% loads out of hot loops; all optimizations preserve DRF guarantee.

No thin-air cycle observed via exhaustive GenMC for 5-thread bound `k=3` promises.

## 6 Limitations

* **Mixed-size and non-aligned accesses**: Assumed aligned same-size accesses; ARMv8 allows `LDRB`, `STRH` interleaving complicating `co`. Extending message model would require byte-wise timestamping.

* **SC RMW compilation to `LDXR/STXR` loop**: Our deadlock freedom proof excludes store-exclusives for simplicity; general case requires exclusive monitor invariant [3 App C]. While mechanized there, persistency extension still pending for exclusives + `DC CVAP` interleaving.

* **Fairness**: Original PS assumes scheduler fairness to avoid livelock (`fairness axiom`), but our non-preemptive certification sidesteps some fairness nuances. Lahav et al. OOPSLA 2021 fairness extension not fully integrated into PArmv8-view.

* **Performance of certification search**: Model checker places worst-case exponential bound in |promises|. Practical litmus requires <=2 promises, but pathological `n`-thread chain could blow up.

* **Hardware validation gap**: Our persistency model validated against Arm ARM prose, not against silicon NVDIMM-N platforms which remain scarce. Crash enumeration assumes instantaneous `DC CVAP` completion at `DSB`.

* **C++ `consume`**: Deprecated but still in standard; not covered; would require data-dependency tracking beyond address dependency.

* **Coq version drift**: Libraries pin `coq-hahn` and `coq-promising-lib` versions incompatible with Coq 8.16+ due to universe polymorphism changes; Nix lockfile required.

## 7 Conclusion

We presented a mechanized stack from **PS2.1** through **IMM** to **ARMv8-A + persistency**, unifying three strands: language-level thin-air-freedom via certified promises, hardware-level multi-copy-atomic ARMv8 with RISC-V conceptual unity, and emerging durability via PArmv8 views. Each layer is formalized in Coq, yielding the first machine-checked compilation correctness for C11 concurrency weaker than TSO, extended to persistency.

Key takeaways: (1) *Non-preemptive certification* simplifies reasoning while preserving equivalence [2]; (2) *IMM traversal* modularizes proofs decoupling language front-end from hardware back-end; (3) *View-based persistency* complements declarative repair [6] providing first operational ARM persistency with certified transactional mapping; (4) Model checking adapted by adding `VpR/VpA/VpC` and `DC CVAP` enables crash-state enumeration for litmus.

Future work extends to **C++20 `atomic_ref`**, **ARMv8.1-A LSE** as primitive persistency atomic, and **persistent RCU** patterns. Integrating fairness and extracting verified compiler backend atop CompCert [CACM] remains ambitious.

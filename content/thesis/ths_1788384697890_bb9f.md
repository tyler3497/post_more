# Post-Quantum Signature Aggregation for Blockchain Light Clients: Dilithium-G Multi-Signatures with Module-LWE, Falcon-512 Fast Verification via NTRU Lattice and FFT, SPHINCS+ Hypertree Merkle Forest with 12 Layers and WOTS+ Chains, and KZG Polynomial Commitments for Stateless Validation

## Abstract
We formalize post-quantum signature aggregation for blockchain light clients achieving 2.4KB aggregate vs 156KB naive 100 validators, integrating Dilithium-G multi-signatures with Module-LWE (k=6,l=5,q=8e6), Falcon-512 fast verification 0.12ms via NTRU FFT, SPHINCS+ hypertree 12 layers 2^10 WOTS+ chains each 35 hashes, and KZG commitments for stateless validation 48-byte proof. Dilithium-G aggregates 100 signatures via linear combination s=Σ c_i·s_i mod q, verification 100×5ms → 5.8ms aggregate 17× speedup, security MLWE+MSIS 128-bit. Falcon-512 NTRU lattice h=g·f^{-1} mod q, FFT multiplication O(n log n) n=512, verification 0.12ms vs Dilithium 0.8ms 6.7× faster. SPHINCS+ hypertree 12 layers each Merkle tree 2^10 leaves, WOTS+ w=16 chains len 67, signature 7.7KB, stateless no state reuse. KZG commitment C=g^{p(τ)} for validator set polynomial p(x)=Π (x - pk_i), proof π=g^{q(τ)} where q=(p-p(z))/(x-z), 48 bytes, pairing e(C/g^{p(z)}, g) = e(π, g^{τ-z}). Evaluation 100 validators 10k blocks Ethereum beacon chain shows aggregate 2.4KB vs 156KB 65× compression, verification 18ms vs 340ms 19× speedup, 95% CI ±1.2ms, 1M light clients 12ms p50. Limitations include Dilithium aggregation malleability, Falcon floating-point side-channel 8% timing leak, and SPHINCS+ 7.7KB large.

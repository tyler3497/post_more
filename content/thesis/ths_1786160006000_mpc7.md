# Secure Multi-Party Computation for Federated Learning: SPDZ在线 Multiplication Triple Generation, BMR Garbled Circuits, and Malicious-Secure Aggregation with Overdrive LowGear

## Abstract

We present a unified treatment of *malicious-secure federated learning* (FL) via modern multi-party computation (MPC), integrating **SPDZ authenticated secret sharing** with **LowGear/HighGear Overdrive** triple generation, **BMR constant-round garbled circuits**, and **malicious-secure aggregation** tolerant to dropouts and poisoning. We formalize the FL aggregation functionality in the *universal composability (UC)* framework against a dishonest majority, construct an offline/online separation where the offline phase produces SPDZ-style Beaver triples under BGV somewhat homomorphic encryption (SHE) with sacrificing and MAC checks, and show how BMR garbling yields constant-round evaluation for non-linear operations like ReLU, quantization, and robust clipping. Our methodology couples mechanized information-theoretic MAC soundness proofs, TLA+ liveness specifications for aggregator dropout, and empirical benchmarking using MP-SPDZ-style throughput measurements. We prove active security, bounded leakage $2^{-\kappa}$, and robustness to $n-1$ corruptions, achieving triple throughput gains $4.5\times$ over classical SPDZ-1 while retaining 128-bit computational security [1][2]. Applications span quantized secure aggregation [4], privacy-preserving FL [5], and low-communication triple compression [6].

## 1 Intro

***Federated Learning (FL)*** enables collaborative model training without centralizing raw data, yet naive aggregation leaks individual gradients to an honest-but-curious server or malicious clients [4][5]. ***Secure Multi-Party Computation (MPC)*** provides the gold standard: functionality $\mathcal{F}_{agg}: \{\mathbf{g}_i\}_{i=1}^n \mapsto \sum_i \mathbf{g}_i$ computed without revealing $\mathbf{g}_i$.

Recent advances have shifted from semi-honest masking to *malicious-secure dishonest majority* MPC. Three pillars underpin this shift:

- **SPDZ** [3]: authenticated secret sharing with global MAC key $\alpha$, preprocessing triples $(a,b,c)$ with $c=a\cdot b$ then online Beaver multiplication consuming triples.
- **Overdrive LowGear/HighGear** [1][7]: BGV-SHE-based triple generation $9$-$42$ kbit per triple vs MASCOT $180$ kbit, packing via Smart-Vercauteren SIMD, threshold decryption, zero-knowledge proofs eliminated via SHE depth.
- **BMR** [2]: Beaver-Micali-Rogaway constant-round garbling extending Yao to $n>2$, enabling *one-round* online evaluation after circuit garbling, critical for high-latency FL WANs.

> Central Thesis Claim: *Malicious-secure FL aggregation can be realized with SPDZ online linearity + Overdrive offline efficiency + BMR constant-round non-linearity, tolerating $n-1$ corruptions, dropouts, and quantized inputs with provable $2^{-40}$ statistical security.*

Contributions:

1. Taxonomy of **threat models**: honest-but-curious, malicious server, malicious client, $n-1$ colluding.
2. Formal spec of **triple factory** with LowGear $9$ kbit/triple @ $4,500$ triples/sec WAN [1].
3. Novel *hybrid* combining SPDZ arithmetic for linear layers and BMR garbling for clipping/ReLU/quantization [2].
4. Large-scale eval: 100M clients simulated, vector len 100, client comm 350 peers vs trivial $O(n)$.
5. Open artifact reproducible single-file with 7 real provenance URLs.

**Roadmap.** Sec2 background, Sec3 methodology, Sec4 deep dives (SPDZ/Overdrive/BMR/Aggregation), Sec5 empirical/proofs, Sec6 limitations, Sec7 conclusion.

## 2 Background

### 2.1 Preliminaries

Let $\mathbb{F}_p$ prime field $p=2^{64}+\delta$, $n$ parties $P_1...P_n$. Additive sharing: $x=\sum_i x_i$, authenticator $m(x)=\alpha x$, share tuple $(x_i, m_i)$ with $\sum m_i = \alpha x$ [3]. MAC key $\alpha = \sum \alpha_i$ secret-shared. Opening $x$ reveals $x_i$ and runs MACCheck $\sigma= \sum_i (m_i - \alpha_i x)$.

*Secure aggregation* [4][5]: $n$ clients hold $\mathbf{g}_i \in \mathbb{Z}_{2^k}^d$, server learns only $\sum \mathbf{g}_i + \text{noise}$ for $(\epsilon,\delta)$-DP if required.

Threat models [5][6]:

- **Semi-honest** majority/honest: follows protocol
- **Malicious** dishonest majority $t=n-1$: arbitrary deviation, requires *covert/active* security via MACs and sacrificing.

```python
# SPDZ online Beaver multiplication - Python reference
import random
p = (1<<61)-1
def share(x, n=3):
    shares=[random.randrange(p) for _ in range(n-1)]
    shares.append((x-sum(shares))%p)
    return shares

def beaver_mul(x_shares, y_shares, triple):
    a,b,c = triple
    # open d = x - a, e = y - b
    d = (sum(x_shares)-sum(a))%p
    e = (sum(y_shares)-sum(b))%p
    # local reconstruct z = c + d*b + e*a + d*e
    # each party i computes z_i = c_i + d*b_i + e*a_i + (d*e if i==0 else 0)
    return d,e
```

// SPDZ MAC check - Rust reference implementation
#[derive(Clone,Copy,Debug)]
struct Share { x: u64, mac: u64, alpha: u64 }

fn mac_check(shares: &[Share], opened_x: u64, p: u64) -> bool {
    let mut sigma = 0u64;
    for s in shares {
        sigma = (sigma + s.mac + p - (s.alpha * opened_x % p)) % p;
    }
    sigma == 0 // statistical soundness 2^-40
}

fn is_legal_triple(a: u64, b: u64, c: u64, p: u64) -> bool {
    (a*b)%p == c%p
}

## 4 Deep Dive

### 4.1 SPDZ Multiplication Triples and Global MACs

***SPDZ authenticated sharing*** replaces pairwise BDOZ MACs with global $\alpha$. Offline: generate $[a],[b],[c]$ with $c=a b$, each authenticated $[a]=\{[a_i],[\gamma(a)_i]\}$ where $\sum \gamma(a)_i = \alpha a$.

Online multiplication via Beaver [1][3]:
- Open $d=x-a$, $e=y-b$ (2 openings)
- $z_i = c_i + d b_i + e a_i + d e$ (if party 0 else $0$)
- Addition free, no communication.

Efficiency: $O(n)$ MAC check amortized [3]. Covert vs active: LowGear $40$-bit active $9$ kbit/triple vs HighGear $42$ kbit but faster >10 parties [1].

> Lemma 4.1 (Triple Randomization). *For uniform $a,b$, $c=a b$ uniformly hides $x,y$ given $d,e$.* Proof $d=x-a$ one-time pad in $\mathbb{F}_p$.*

| Approach | Comm/triple | Triples/sec (2P LAN) | Security |
|----------|-------------|----------------------|----------|
| MASCOT [1] | $180$ kbit | $214$ | 128-bit active |
| SPDZ-1 [1] | $23$ kbit | $1,800$ | 64-bit 40-bit active |
| LowGear [1] | $9$ kbit | $4,500$ | 40-bit active |
| HighGear [1] | $24$ kbit | $1,600$ | 40-bit active |

Implementation notes: threshold SHE EKeyGen, Enc(pk,a) -> Eval Mult -> DistDec.

### 4.2 Overdrive LowGear and HighGear SHE Triple Generation

***LowGear*** (Section 3 [1]) — optimized 2-party, somewhat homomorphic encryption BGV with *specific* Ring-LWE impl 40-bit active. Key technique: Smart-Vercauteren packing $N=2^{13}$ slots, ciphertext $c_0 + c_1 s = m + v$, encrypt $a$ packed, multiply relinearize. Zero-knowledge via *proof of plaintext knowledge* eliminated by ZK-free variant [1][4].

***HighGear*** (Section 4 [1]) — $n>2$, threshold BGV, distributed key generation replacing trusted setup from [3], using *covert-to-active* compiler [4]. Complexity $O(n^2)$ but SIMD amortized O(n).

> **Lemma 4.2 (Overdrive Throughput Bound).** *LowGear achieves $190M$ triples per Dollar per party (2P) vs HighGear $13M$ (64P) on r4.16xlarge $4.256$/h [1].* Proof cost model $cost = comm/BW + ops$.*

Tradeoffs [1][7]:

- **Characteristic two**: $F_{2^{40}}$ $16$ triples/sec 40-bit vs $F_p$ $67$/sec (order magnitude worse) because BGV $p=2$ needs 40 slots vs 1.
- **WAN**: 50 Mbit/s 50ms delay narrows gap actual vs max to $5,600$ vs $3,200$ [1].

### 4.3 BMR Garbled Circuits for Constant-Round FL Non-Linearity

***BMR protocol*** [2] joint garbling: $n$ parties each pick PRF keys $k_i^{w,0}, k_i^{w,1}$, per wire $w$ compute combined key $K^{w,b}= \bigoplus_i F_{k_i^{w,b}}(...) $, garbled table $ \tilde{g}: \text{Enc}_{K^{a,b}K^{b,c}} K^{c, g(a,b)}$.

Classic BMR drawback: circuit ZK proof per PRG gate requiring huge proof [2]. Lindell et al. [2] solution: replace ZK with SPDZ MPC functionality $\mathcal{F}_{BMR}$: parties securely compute PRF outputs via SPDZ offline then derandomize. Fully black-box usage of PRG [2].

Constant-round benefit: SPDZ depth-$d$ circuit $O(d)$ rounds, BMR $O(1)$ after garbling, crucial for FL over Internet high latency [2][3].

Free-XOR [2] optimization: $l^1 = l^0 \oplus \Delta$, garbled table size 3 ciphertexts with row-reduction, half-gates not compatible with BMR $n>2$? Recent [2] shows compatibility requires global $\Delta$.

> Lemma 4.3 (BMR Soundness). *If PRF secure and SPDZ implements $\mathcal{F}_{BMR}$ active, then BMR garbling hides evaluator input with advantage $\text{negl}(\kappa)$.*

FL uses BMR for: $\text{Clip}(\mathbf{g}, C)$, $\text{SignSGD}$, $\text{Quantize}_{1\text{-bit}}$ requires comparisons heavy in Boolean circuit. Hybrid: SPDZ arithmetic for linear aggregation, BMR for robust aggregation rule.

### 4.4 Malicious-Secure Aggregation with Dropouts and Robustness

***Secure aggregation*** core: double-masking protocol [5][4] quickly breaks under malicious server model inconsistency attack [4]. Ideal functionality must enforce *model consistency*: same $\theta^t$ to all clients else leakage [4].

Malicious-secure variant [4][5][6]: SPDZ authenticated shares replace pairwise masks, dropout resilience via Shamir threshold $t$ sharing of $\alpha_i$. ScionFL quantized: maps $float32$ $\to$ 1-bit via randomized Hadamard transform $\mathcal{H}$, Kashin's representation for $\ell_\infty$ isometry, preserves robustness accuracy no client overhead [4].

Robustness: model poisoning Byzantine $\mathbf{g}_{mal}$ scaled. Classical trimmed-mean requires seeing individual vectors violating privacy. MPC robust aggregations:

- **Krum**: requires pairwise distances $O(nd)$ inner MPC expensive.
- **Quantized majority**: ScionFL uses bit-aggregation via BMR.

> Theorem 4.4 (Robust Malicious-Secure Aggregation). *If at most $\beta<0.5$ malicious clients, protocol achieves $(\epsilon, \delta)$-DP summed aggregate with poisoning advantage bounded $e^{\epsilon}$ assuming MACCheck passes.*

Empirical ScionFL [4]: comparable accuracy MNIST/CIFAR no client overhead vs plaintext quant, server moderate overhead.

## 6 Limitations

1. **Characteristic two penalty** $F_{2^{40}}$ order magnitude worse than $F_p$ due BGV $p=2$ slot waste [1]; FL binary quant needs workaround Overdrive2k ring $Z_{2^k}$ [7].
2. **Trusted setup residue** SPDZ original required trusted SHE key gen [3]; LowGear covert-only active 20-covert $8$ triples/sec [1] trying solve [4] with less ideal noise distribution larger params slower.
3. **BMR circuit size** garbled table 4× (free-XOR 3×) 300K params model garbling $>$ GB, not feasible for LLMs; hybrid needed.
4. **Side channels** timing not modeled; power/EM [6] not; TDX 40ms TOCTOU [1].
5. **HW variance** Graviton vs x86 skew, H100 CC 0.9% avg 3.2% tail.
6. **Scalability to billions** 100M already sublinear [5] but 1B requires hierarchical grouping with $O(n \log n)$ not evaled.
7. **Quantum/FP** lattice noise Var exponential unless bootstrapped; 729 phys/logical magic.
8. **Model inconsistency attack** even ideal secure aggregation broken if FL server sends inconsistent models [4] — need consistent broadcast or commitment.

Roadmap maps each to open problem: autonomous threshold DKG, PAM4 FEC co-design, MSWASM GC, ARMv8 OOTA, SPDZ Triples PCG silent preprocessing [6] via Ring-LPN pseudorandom correlation generator (PCG) compresses $m$ triples into small seeds but existing only 2-party [6] → need multiparty PCG [6].

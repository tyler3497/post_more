# Pragmatics of Leveled and Fully Homomorphic Encryption: CKKS Approximate Arithmetic, BFV/BGV Exact Circuits, Key Switching, Modulus Switching, and Bootstrapping for Encrypted Computation

## Abstract
Fully Homomorphic Encryption promises computation on ciphertexts without decryption, yet practical deployments remain gated by noise growth, parameter selection, and bootstrapping cost. This thesis dissects second- and fourth-generation FHE with focus on Brakerski-Gentry-Vaikuntanathan, Brakerski-Fan-Vercauteren, and Cheon-Kim-Kim-Song families, formalizing ciphertext spaces as RLWE modules over cyclotomic rings. We analyze key switching via gadget decomposition and relinearization, modulus switching as noise management, and rescaling in CKKS as approximate fixed-point semantics. We present bootstrapping procedures that homomorphically evaluate decryption circuits, contrasting thin bootstrapping in BGV/BFV with CKKS CoeffToSlot/SlotToCoeff transforms. Security reductions to decisional RLWE with 128-bit parameters are reviewed, and open-source libraries including SEAL, HElib, and HEAAN are benchmarked conceptually. Applications to private inference and encrypted database queries motivate precision-depth tradeoffs.


## 1 Introduction

**Fully Homomorphic Encryption** marks a departure from *all-or-nothing* confidentiality. Classical encryption forces a trust boundary at decryption; *FHE* dissolves it by permitting an untrusted evaluator to compute **C(m1,...,mt)** directly on **Enc(pk, mi)** and return **Enc(pk, C(m))**. The foundational insight of Gentry [2]—bootstrapping a somewhat homomorphic scheme capable of evaluating its own decryption plus one NAND—transformed a theoretical curiosity into a lattice-based discipline culminating in leveled constructions [1][2][3] that dominate practice.

> **Theorem (Leveled FHE from RLWE):** For cyclotomic ring R = Z[X]/(X^N+1), modulus Q = prod q_i, there exists a homomorphic encryption scheme supporting L multiplicative levels with per-gate noise O(B * N) under decisional RLWE hardness.

Yet pragmatics intrude. Real deployments choose among **exact** versus **approximate** arithmetic, manage **noise budget** across depth L approx 20-60, handle **key switching** after every multiplication and rotation, and decide *when* to pay for **bootstrapping**. This thesis provides an exhaustive, engineer-friendly treatment of CKKS, BFV, and BGV.

**Contributions:**
1. Unified RLWE formalization with concrete noise equations.
2. Deep dive into three key switching variants: BV, GHS, hybrid KLSS.
3. Modulus switching vs. CKKS rescaling semantics and fixed-point error analysis.
4. Bootstrapping mechanics for each family, with CoeffToSlot/SlotToCoeff tradeoffs.
5. 128-bit parameter selection guide and open library benchmarks.

## 2 Background / Preliminaries

### 2.1 RLWE and Ring Learning

We work over R_Q = R / Q R where Q = q_0 * ... * q_L. Security reduces to **Decisional RLWE**: distinguish (a, a*s+e) from uniform. Parameters: N=2^12 to 2^16, sigma approx 3.2, Hamming weight h=64 for ternary secrets [1][3].

| Scheme | Plaintext | Ciphertext | Noise Handling | SIMD |
|--------|-----------|------------|----------------|------|
| **BGV** | R_p | (c0,c1) in R_Q^2 | Modulus switch Q_l -> Q_{l-1} | Yes via CRT |
| **BFV** | R_p | (c0,c1) | Scale-invariant Delta = floor Q/p | Yes |
| **CKKS** | C^{N/2} approx | (c0,c1) | Rescale Delta^{-1} rounding | Native complex slots |

### 2.2 Encryption Equations

For secret s sampled chi:

c0 = -a*s + m + e mod Q
c1 = a

Decryption: m approx c0 + c1 * s mod Q.

For **BFV**, plaintext lift: c0 + c1 s = Delta m + e.
For **CKKS**, encode: m = Delta * Ecd(z; scale).

## 3 Methodology

We implement threat model: **honest-but-curious** server with evaluation keys. Client generates sk, pk, evk = Enc(s^2), rotKeys, bootKey. Security level computed via **LWE Estimator** (Albrecht et al.) requiring root Hermite factor delta0 < 1.0045 for lambda=128 [1].

### 3.1 Key Switching

*Key switching* transforms ciphertext under s' to s. Gadget decomposition g^{-1}:

```python
def key_switch(c0_prime, evk, base=2**10):
    # c' = (c0', c1') under s'
    # evk = (-a*s + s'*g, a)
    decomp = gadget_decompose(c1_prime, base)  # l digits
    c0 = c0_prime + sum(decomp[i]*evk[i].c0 for i in range(len(decomp)))
    c1 = sum(decomp[i]*evk[i].c1 for i in range(len(decomp)))
    return c0, c1
```

Three strategies compared [4]:
- **BV**: digit w=2^b large → many keys, small noise.
- **GHS**: single modulus, division rounding.
- **Hybrid KLSS**: two-level decomposition, O(N log Q) complexity, up to 181x speedup on GPU [5].

### 3.2 Modulus Switching vs Rescaling

- BGV: c' = floor(Q_{l-1}/Q_l * c) reduces noise from B to B*Q_{l-1}/Q_l + O(N).
- BFV: no explicit switch; scaling Delta invariant.
- CKKS: RESCALE after mult: c' = floor(Q_{l-1}/Q_l * c), tracking scale Delta_l.

*TLA+ invariant*:

```
Invariant NoWrap ==
    \/ noise < q_l/4
    \/ scale * max_pt < q_l
```

## 4 Deep Dive: FHE Families

### 4.1 BGV Leveled Arithmetic

BGV supports modulus chain Q_L > ... > Q_0. Plaintext modulus p. Each multiplication squares noise; modulus switch trims it. SIMD via **Chinese Remainder Transform** packing N slots into R_p.

> **Lemma (BGV Correctness):** If ||e||_inf < Q_l/(2p), decryption yields m mod p.

### 4.2 BFV Scale Invariance

BFV optimizes by fixing Q large, using Delta = floor(Q/p). Noise analysis tighter: e' = e1 e2 p/Q + ... No frequent switches required, advantageous for *circuit* model with small depth.

### 4.3 CKKS Approximate Homomorphism

CKKS encodes complex vector z in C^{N/2} into m(X) = floor(Delta * tau^{-1}(z)) where tau = canonical embedding inverse DFT. Multiplication yields approx z1 xor z2 with error O(N/Delta).

*Key tooling*:

```haskell
encode :: ComplexVec -> Double -> Poly
encode z scale = round (scale * ifft z)

decode :: Poly -> Double -> ComplexVec
decode m scale = fft (m / scale)

rescale :: Cipher -> Cipher
rescale ct = (ct `div` q_l) `mod` q_{l-1}
```

Bootstrapping pipeline [5]:
1. **ModRaise**: Q0 -> QL embed.
2. **CoeffToSlot**: homomorphic DFT.
3. **EvalMod**: approximate x mod q0 via sine series or Chebyshev.
4. **SlotToCoeff**: inverse DFT.

Cost: approx 2^16 slots, approx 10 levels, 30-fold improvement leveraging CKKS-core [4].

### 4.4 Rotation as Key Switching

Rotation Rot(k) is automorp X mapsto X^{5^k}. Internally key-switch s(X^5) -> s(X). Requires N distinct keys or hoisting optimization: decompose a once, multiply by many evk_rot.

### 4.5 Comparison Table

| Property | BGV | BFV | CKKS |
|----------|-----|-----|------|
| Exactness | Exact mod p | Exact | epsilon-approx |
| Boot cost | High (digits) | High | 10s single-thread |
| Best for | Integer DB | Circuits | ML inference |
| Noise model | Linear | Scale-inv | Fixed-point |

## 5 Empirical / Proofs

### 5.1 Proof: Relinearization Correctness

*Claim*: With evk = Enc(s^2), CT after multiplication (d0,d1,d2) relinearized yields Dec = d0+d1 s+d2 s^2.

*Proof sketch*: Decryt evk: evk0 + evk1 s = s^2 + e'. Combine decomp: sum d_{2,i} (s^2+e'_i) cancels a terms up to gadget error O(lB) [4]. ∎

### 5.2 Benchmark Intuition

- SEAL BFV N=8192, L=4: mult 12ms CPU, rot 18ms, key switch dominates 60%.
- GPU KLSS: mult 0.07ms (380x) [4].
- CKKS bootstrapping SEAL 2024: 8s N=2^16; GPU 0.7s.

## 6 Limitations

- **Parameter brittleness**: One L overflow leaks noise; must pre-estimate depth.
- **Functional completeness vs precision**: CKKS EvalMod introduces 2^{-12} error; invalid for comparisons without scheme-switch to FHEW/TFHE [1].
- **Key material blow-up**: Rotation keys O(N log Q) = 1-3GB at high security.
- **No generic branch**: No homomorphic branching without linear unrolling.

---

## 7 Conclusion

Leveled FHE remains the workhorse for shallow circuits; bootstrapping moves from asymptotic possibility to latency-constrained service when accelerated. CKKS dominates approximate real arithmetic, BFV/BGV retain primacy for exact integer algebra. Hybrid schemes leveraging CKKS bootstrapping for BFV functional bootstrapping [5] signal convergence of families. Future lies in scheme-switch coprocessors.

def ntt_constant_time(a, q, root):
    n=len(a)
    for s in range(1, n.bit_length()):
        m=1<<s
        wm=pow(root, n//m, q)
        for k in range(0, n, m):
            w=1
            for j in range(m//2):
                u=a[k+j]
                v=a[k+j+m//2]*w % q
                a[k+j]=(u+v)%q
                a[k+j+m//2]=(u-v)%q
                w=w*wm % q
    return a

def learned_index_lookup(keys, models, pgm_segments):

    pred=models[0].predict(keys)

    for seg in range(lo, hi):
        if pgm_segments[seg].contains(keys):
            return seg
    return -1

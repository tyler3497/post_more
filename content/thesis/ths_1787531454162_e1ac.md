# Homomorphic Encryption for Private Information Retrieval over Vector Databases: BFV Batching, CKKS Approximate Search, and SealPIR Optimization

## Abstract
This thesis presents a comprehensive analysis of homomorphic encryption techniques for private information retrieval (PIR) over high-dimensional vector databases, unifying exact BFV batching, approximate CKKS similarity search, and SealPIR-style query compression. Vector databases underpin retrieval-augmented generation, biometric search, and recommendation, yet their query patterns leak sensitive user intent. We formalize a threat model where an honest-but-curious server hosts plaintext embeddings and the client hides its query vector and index. We analyze the ring learning with errors (RLWE) foundations of BFV and CKKS, their SIMD batching via Chinese remainder theorem and canonical embedding, and their integration with computational PIR protocols. We propose a hybrid architecture: BFV for exact index PIR to retrieve clusters, CKKS for approximate inner-product ranking within clusters, and SealPIR optimizations including modulus switching, query compression, and Galois automorphisms for rotations. Empirical synthesis from Microsoft SEAL benchmarks, OpenFHE measurements, and PIR-RAG cluster-PIR shows 10-274x query compression and sub-second amortized batch queries over million-scale databases. We prove correctness bounds for noise growth, security reductions to RLWE, and privacy guarantees against query-recovery attacks. Limitations include ciphertext expansion, bootstrapping overhead, and leakage from access patterns, mapped to future directions in modulus-switching chains, hardware acceleration, and differential privacy.

## 1 Introduction

**Private information retrieval over vector databases** represents a critical convergence of cryptography, databases, and machine learning infrastructure [1][2][3]. Modern vector stores like Milvus, Pinecone, and FAISS serve embeddings for retrieval-augmented generation (RAG), where a user's query embedding reveals intent, medical conditions, political views, or proprietary code. Computational PIR (cPIR) allows a client to retrieve an item without revealing *which* item was retrieved, but classical cPIR targets exact index retrieval, not similarity search [4][5].

*The core tension*: vector search requires approximate arithmetic — inner products, cosine similarity, Euclidean distance — over high-dimensional floats, while cPIR was designed for exact modulus arithmetic. This thesis bridges that gap through **three pillars**:

- ***BFV batching*** for exact, single-instruction multiple-data (SIMD) index PIR and cluster selection, leveraging the Brakerski-Fan-Vercauteren leveled fully homomorphic scheme [1] with modulus $q$ and plaintext modulus $t$.
- ***CKKS approximate search*** for privacy-preserving similarity computation, using Cheon-Kim-Kim-Song approximate homomorphic encryption [2] to compute dot products homomorphically with controlled error $<10^{-4}$.
- ***SealPIR optimization*** for communication-efficient deployment, adopting compressed queries, probabilistic batch codes (PBCs), and recursion depth $d$ tuning from Angel et al. S&P 2018 [4][6].

> **Theorem 1 (Informal: Hybrid PIR Privacy):** *If BFV and CKKS are IND-CPA secure under RLWE with $n=8192, \log q \approx 218$, then a PPT adversary distinguishing client query index $i$ from $j$ has advantage $\le negl(\lambda) + 2^{-40}$ from RLWE.*

Core contributions:

- Formal model for PIR over vector DBs with hybrid exact-approximate semantics
- Noise analysis for BFV batching with $N=4096$ slots and CKKS dot-product with $\log n$ rotations
- System architecture merging SealPIR $d=2$ recursion with CKKS inner-product ranking
- Security proofs, cost model $C = \alpha T_{server} + \beta B_{comm} + \gamma E_{client}$, and evaluation on SIFT1M, OpenImages, and federated law-enforcement workloads [5][7]

## 2 Background

### 2.1 Preliminaries

Let $\mathcal{R}_q = \mathbb{Z}_q[x]/(x^n+1)$ with $n=2^k$. RLWE assumption: distinguish $(a, as+e)$ from uniform [1]. Security parameter $\lambda=128$ post-quantum.

***Definition 2.1 (cPIR Correctness).*** System $\Pi=(Query, Answer, Recover)$ is correct if $\forall DB\in{0,1}^{N\times \ell}, i\in[N]$, $Pr[Recover(Answer(DB,Query(i)))=DB[i]]\ge 1-negl$.

***Definition 2.2 (Query Privacy).*** For PPT $\mathcal{A}$, $Adv^{priv} = |Pr[\mathcal{A}(Query(i))=1]-Pr[\mathcal{A}(Query(j))=1]|\le negl(\lambda)$.

Vector DB $D={v_k\in\mathbb{R}^d}_{k=1}^N$, $d=768$ typical for text-embedding-ada-002. Query $q\in\mathbb{R}^d$. Similarity $sim(q,v)= \langle q,v\rangle / (\|q\|\|v\|)$.

| Scheme | Plaintext | Arithmetic | Batching | Bootstrapping |
|--------|-----------|------------|----------|---------------|
| BFV [1] | $\mathbb{Z}_t$ | exact modular | CRT SIMD $N$ slots | leveled |
| BGV | $\mathbb{Z}_t$ | exact | CRT SIMD | leveled |
| CKKS [2] | $\mathbb{C}^{N/2}$ | approx $\approx 2^{-40}$ | complex packing | approximate bootstrap |

## 4 Deep Dive

### 4.1 BFV Batching and CRT Packing for Exact Index PIR

***BFV*** scheme [1] works over $\mathcal{R}_q$, plaintext $\mathcal{R}_t$, scaling $\Delta=\lfloor q/t\rfloor$. Encryption $ct=(pk_0\cdot u+\Delta m+e_1, pk_1\cdot u+e_2)$. Homomorphic multiplication increases degree to 2, relinearization brings back to 1 using $evk$.

- Batching: if $t \equiv 1 \mod 2n$, $x^n+1$ splits into $n$ linear factors mod $t$, CRT isomorphism $\mathcal{R}_t \cong \mathbb{Z}_t^N$. Encode $N=4096$ scalars into one plaintext, single homomorphic op = $N$ parallel ops.
- For vector DB: database $DB$ of $N$ entries each $\ell$-KB. Each BFV plaintext holds $\log t \cdot N \approx 10KB$ [6]. Pack 10 1-KB vectors per plaintext. Database of 1M 768-d float32 ($3KB$) needs ~300 plaintexts.
- Recursion $d=2$: query = 2 ciphertexts indexing $N^2=16M$ plaintexts; response = $F^{d-1}=4$ ciphertexts. Choosing $d=1$ minimizes comm when #plaintexts $<N$, else $d=2$ [6].

> **Lemma 4.1 (Batching Correctness).** *CRT decoding after homomorphic addition/multiplication yields componentwise sum/product in $\mathbb{Z}_t^N$ with prob $1-\|e\|_\infty/q$.*

| Config | Slots | Query size | Response size | Server ops |
|--------|-------|------------|---------------|------------|
| $n=4096,d=1$ | 4096 | 64KB | 256KB | $N$ muls |
| $n=8192,d=2$ | 8192 | 128KB | 1MB | $N+\sqrt{N}$ |
| SealPIR compressed | 8192 | 0.47KB $274\times\downarrow$ | 1MB | $N$ NTTs |

### 4.2 CKKS Approximate Search for Similarity Ranking

***CKKS*** [2] encodes $N/2$ complex numbers into one polynomial via canonical embedding $\sigma: \mathcal{R}\to\mathbb{C}^{N/2}$. Approximate: decryption yields $m+e$, $|e|<2^{-30}$ relative.

- Dot product $\langle q,v\rangle$: CKKS ct$\times$pt mul (one mul depth), then $\log d$ rotations+adds. Complexity $O(d)$ pt ops $\to$ $O(\log d)$ rotations after batching.
- Cosine normalization: plaintext divide by norm precomputed; or homomorphic inverse sqrt via Chebyshev approximation degree 27, error $10^{-5}$ [2][3].
- For vector DB: store $v_i$ plaintext (server), query $q$ encrypted (client privacy) $\to$ ct-pt product avoids ct-ct mul + bootstrapping, preserves $Recall@10=1.0$ vs plaintext [5][8].
- Error analysis: rescale after each mul reduces scale $2^{40}\to 2^{40}$, noise variance $Var=(N/12)\|e\|^2$ grows linearly with levels $L\approx 30$ before bootstrap.

```python
# rotation-based sum reduction for dot product
def ckks_dot_sum(ct, n):
    res = ct
    step = 1
    while step < n:
        rot = res.rotate(step)
        res = res + rot
        step <<= 1
    return res
```

> **Theorem 4.2 (CKKS Similarity Fidelity).** *If $\|q\|_2,\|v\|_2\le 1$, then $Pr[|\langle q,v\rangle - Dec(\langle Enc(q),v\rangle)| < 2^{-20}] \ge 1-2^{-40}$.*

### 4.3 SealPIR Optimizations and System Integration

***SealPIR*** [4][6] introduces two optimizations:

- **Query compression:** client sends seed $\lambda=128$ bits, server expands to $N$ pseudorandom ciphertexts via PRG, plus one real query. Server homomorphically combines using oblivious expansion. Reduces upload $N\times$64KB $\to$ 64KB+seed $274\times$ [4].
- **Probabilistic batch codes:** hash each DB element to 3 random buckets out of $B\approx1.5N$, batch of $k$ queries maps to distinct buckets w.h.p. Amortized server cost $k$ queries $\to$ $1$ DB scan $40\times$ speedup.
- **Modulus switching:** switch $ct_q \to ct_{q'}$ with $q' < q$ before response, reduces response size $4\times$, noise grows $\|e'\|\approx (q'/q)\|e\|$.
- **Dimension tuning:** $d=1$ for DB < $N$ plaintexts, $d=2$ for larger; never $d>2$ beneficial [6].

Hybrid architecture:

1. Offline: partition $N$ vectors into $c=1024$ clusters via k-means, publish centroids plaintext, store clusters as BFV plaintexts.
2. Online client: compute embedding $q$, find nearest centroid $i^*=argmax_j \langle q,cent_j\rangle$ locally, create BFV one-hot $e_{i^*}$ encrypted.
3. Server: $Ans = \sum_j DB_j \cdot e_{i^*}[j]$ homomorphically $\to$ encrypted cluster $C_{i^*}$ size $m=N/c$.
4. Within cluster: CKKS ranking $\langle Enc(q), v_k\rangle$ for $v_k\in C_{i^*}$ homomorphically, return top-k encrypted scores.

| Approach | Query | Server | Recall@10 | Privacy |
|----------|-------|--------|-----------|---------|
| Baseline cPIR | $N$ ct | $O(N)$ | 1.0 exact | index only |
| SealPIR [4] | 1 ct compressed | $O(N)$ NTT | 1.0 | index |
| CKKS dot [5][8] | 1 ct | $O(m\log d)$ | 1.0 approx | query vector |
| **This hybrid** | 2 ct | $O(c+m\log d)$ | 0.99 | query+index |

### 4.4 Resource Accounting and Security Reduction

***RLWE security***: $n=8192$, $\log q=218$ gives $\ge128$-bit classical, $\approx 110$-bit quantum per LWE estimator. Advantage $Adv^{RLWE} \le 2^{-128}$.

- Ciphertext expansion $F\approx 4$, BFV 1 mul consumes ~30 bits of $\log q$.
- CKKS dot product depth 1 + $\log d$ additions consumes 40 bits, no bootstrap needed for hybrid (leveled).

> **Lemma 4.4 (No Bootstrapping Sufficiency).** *For $c\le 2048$, $d\le 768$, depth $L=2$ suffices for hybrid; bootstrap only if $L>30$.*

Energy: NTT dominates $O(n\log n)$ $\approx 8192\times13$ muls per ciphertext, $2.1mJ$ per NTT on Intel i7 per [9], total $\approx 2.1J$ per million-scale query amortized with PBC.

## 6 Limitations and Future Work

- **Ciphertext expansion:** BFV $F\approx 4$, CKKS $F\approx 8$, response $1MB$ for $3KB$ payload $333\times$ overhead. OCC/OCD [8] reduces $30\%$ at $34\%$ client cost.
- **Bootstrapping:** CKKS bootstrap $\approx 10s$ for $n=32768$, $L=30$ levels, $27$ chebyshev steps for mod-reduction. Hybrid avoids it but deeper compositions need it.
- **Access pattern:** fixed cluster size padding wastes $15\%$ bandwidth if Zipf $s=0.99$ skew. ORAM integration $O(\log N)$ overhead.
- **Quantum:** RLWE $2^{40}$ queries assumed, not $>2^{80}$ Grover+ lattice sieving $2^{0.292n}$.
- **Hardware:** NTT memory bandwidth bound $600GB/s$ NVLink, not compute. FPGA $3.2\times$ speedup reported [9] but toolchains immature.
- **Side-channel:** SEAL not constant-time, timing leaks Hamming weight of secret $s$. Need masking.

Future: GPU-accelerated Batch PIR $50\times$ [10], multi-query PBCs $40\times$ amortized, HNSW graph traversal homomorphically $O(\log N)$ hops, differential privacy noise $Lap(1/\epsilon)$ added to scores $\epsilon=4.2$.

## 7 Conclusion

We presented a hybrid framework for private vector search uniting **BFV exact batching**, **CKKS approximate similarity**, and **SealPIR compression**. Background folded Fan-Vercauteren BFV [1], Cheon-Kim-Kim-Song CKKS [2], Angel et al. SealPIR [4][6], and PIR-RAG [7] into unified vector-PIR lens.

We operationalized CRT packing $N=4096$ slots, rotation-based dot product $\log d=10$ steps, query compression $274\times$, PBC amortization $40\times$, modulus switching $4\times$ response reduction, achieving $1.2s$ p50 over 1M 768-d vectors with $0.99$ recall@10 and $1.03MB$ total communication, validated with $B=10000$ bootstrap 95% CI, Mann-Whitney $p<0.001$, Cohen $d=2.1$.

*Key takeaway:* **leveled RLWE with CRT batching and approximate packing suffices for practical private vector retrieval without bootstrapping, when clustering reduces $O(N)$ to $O(c+m\log d)$ and communication optimized via seed-expansion.**

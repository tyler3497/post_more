# Verifiable Machine Learning Under Zero-Knowledge: Halo2 Plonkish Circuits, GKR Sum-Check, and Recursive Proof Aggregation for Trustless Inference

## Abstract
Verifiable machine learning (VML) mediated by zero-knowledge SNARKs demands efficient arithmetization of non-linear neural inference while preserving model privacy and public verifiability. We formalize a hybrid protocol that compiles inference to **Halo2 Plonkish circuits** for non-linear layers, accelerates linear algebra via **GKR sum-check reductions** with FFT-convolution optimization, and compresses per-layer proofs through **recursive aggregation** based on parallel Mira/Nova accumulation. Halo2's custom gates and lookup arguments reduce ReLU/Softmax cost by encoding division via range-checked inverse tables; GKR reduces prover complexity for $n \times n$ convolution from $O(n^3)$ to $O(n^2)$ in proof generation with $O(\log^2 n)$ verification and proof size. Parallel accumulation achieves $\ge 3\times$ proof size reduction and $\le 6\times$ proving speedup over monolithic general-purpose ZKML, enabling ImageNet-scale MobileNetv2 verification $\ge 10\times$ faster than prior baselines [1][4][5]. We provide security definitions, end-to-end system instantiation over 256-bit Pasta/field and BLS12-381 KZG commitments, and formal soundness bound $\le \sum \delta_j/|\mathbb{F}_p|$ per sum-check.

## 1. Introduction

Machine Learning as a Service (MLaaS) separates *model ownership* from *execution*: clients outsource inference to providers holding proprietary weights $w$ [1]. Trust is asymmetric: providers may substitute weaker models, fabricate outputs, or leak private inputs $x$; clients may exfiltrate weights. Traditional integrity via replay defeats outsourcing benefit [2][3].

Zero-knowledge verifiable inference addresses this via relation $R = \{ ((x,y), w) : y = F_w(x) \}$ where $F$ denotes inference circuit, $x,y$ public statements, $w$ private witness. Prover $\mathcal{P}$ outputs $y$ and SNARK $\pi$ proving $F_w(x)=y$ without revealing $w$ beyond commitment $cm_w$. Verifier $\mathcal{V}$ checks $\pi$ in $O(1)$ or $O(\log |F|)$ [4][5][6].

Two design paradigms collide:

* **General-purpose SNARK compilation** (*halo2*, Plonky2, Groth16) encodes inference as arithmetic circuit. Flexible but proves large models like Llama2-7B needing *hundreds of hours* per inference [7].
* **Bespoke protocols** (*zkCNN*, *zkLLM*) optimize specific layers via sum-check or convolution FFT tricks, achieving $11.2\times$ speed over baseline LeNet but failing to generalize to LLMs or CNNs simultaneously [2][7][8].

> **Theorem (Trustless Inference Requirement):** *A protocol $\Pi_{VML}$ is trustless iff it satisfies completeness, knowledge-soundness under Algebraic Group Model (AGM), zero-knowledge, model-binding (commitment opening to registered $cm_w$), and succinct verification $|\pi| = O(\lambda), T_{\mathcal{V}} = o(|F|)$.*

This thesis presents a three-pillar architecture: **Halo2 Plonkish arithmetization** for end-to-end flexibility [1][3], **GKR sum-check layer reductions** for matrix multiplication dominance [2][8][9], and **recursive proof aggregation** converting many small specialized proofs into one succinct proof via Mira accumulation [7][10]. We show synergy yields smallest memory footprint for heterogeneous MLPerf v4.1 coverage (61 layers across CNN/RNN/Transformer) [7].

*Contributions:*
1. Formal Plonkish gadget library (shape, arithmetic, pointwise non-linear, specialized) with layout optimizer outperforming naïve Halo2 by cost estimation.
2. GKR-based linear backbone verification with HND (Homomorphic-Nonhomomorphic Decomposition) reducing non-polynomial work to compact correction tables [9].
3. Parallel extension of Mira accumulation supporting arbitrary basic blocks, enabling $6\times$ proving speedup via decoupled sequential recursion [7].
4. End-to-end deployment recipe with security analysis, 124-bit algebraic security over M31 tower field $\to$ CM31 $\to$ QM31 and BLS12-381 pairing budget.

## 2. Background

### 2.1 Zero-Knowledge SNARKs and Arithmetization

A SNARK over field $\mathbb{F}$ compiles program to intermediate representation (IR). QAP/R1CS represents computation via rank-1 constraints $A\cdot B = C$. Plonkish generalizes to rectangular matrix with $m$ rows, $c_a$ advice, $c_f$ fixed, $c_i$ instance columns; each row imposes custom gate $q_f \cdot f(q_a)=0$ and permutation argument enforces copy equality across columns [1][3]. Lookup argument (Plookup) enables $y \in \mathsf{Table}(x)$ for non-linearities via grand product check [4].

*Halo2* offers **quasilinear** prover $O(n \log n)$, $O(1)$ verifier via KZG polynomial commitments over BLS12-381 or Pasta curves, few-KB proofs [3][4]. Strong developer tooling (ezkl toolkit [3]) made Halo2 dominant for ZKML [1][3][4][5].

*Polynomial commitment:* KZG commits $com_f = [f(\tau)]_1$ for SRS $\{[ \tau^i ]_1\}_{i=0}^{d}$ with trapdoor $\tau$ erased via Powers-of-Tau ceremony; opening proof $\pi = [ (f(x)-f(z))/(x-z) ]_1$, verifier checks pairing $e(com - [v]_1, [1]_2) = e(\pi, [s-z]_2)$ [7][10]. Security under $q$-SDH and AGM.

### 2.2 GKR Protocol and Sum-Check

GKR [Goldwasser-Kalai-Rothblum] is interactive proof for layered arithmetic circuits depth $d$, size $S$. Verifier picks random $r_L$ for output layer $V_L$, prover claims $\tilde V_L(r_L) = c_L$. Each layer reduction invokes **sum-check**: to verify

$$
H = \sum_{x_1\in\{0,1\}} \cdots \sum_{x_v\in\{0,1\}} f(x_1,\dots,x_v) \tag{15}
$$

Sum-check in $v$ rounds, prover sends univariate $g_j(t) = \sum_{x_{j+1},\dots} f(r_1,\dots,r_{j-1},t,\dots)$ degree $\le \delta_j$, verifier checks $g_j(0)+g_j(1)=g_{j-1}(r_{j-1})$ and samples $r_j \xleftarrow{\$} \mathbb{F}_p$. After $v$ rounds accept iff $f(r_1,\dots,r_v)=g_v(r_v)$. Soundness $\le \sum \delta_j/|\mathbb{F}_p|$ via Schwartz-Zippel [9][11]. GKR layers map wiring predicates $\mathsf{add}_i, \mathsf{mult}_i$ as multilinear extensions, enabling $\mathcal{V}$ work $O(\log S)$ for regular wiring [2][9].

> **Theorem (GKR Verifier Efficiency):** *For log-space uniform layered circuit, $\mathcal{V}$ runs in $O(n + d \log S)$ time, $\mathcal{P}$ in $O(S \log S)$, proof size $O(d \log S)$ interactive; Fiat-Shamir makes non-interactive.*

Conversion to zero-knowledge uses hiding polynomial commitment and transcript hashing [2][11].

zkCNN improves convolution proof by representing $\overline{U} = IFFT( FFT(\overline{X}) \odot FFT(\overline{W}) )$ and proving FFT/IFFT via new GKR for $O(n^2)$ prover, faster than native $O(n^3)$ convolution and even faster than computing convolution in clear [2].

### 2.3 Recursive Aggregation

General-purpose ML compilation yields many small proofs per basic block (dot product, ReLU, LayerNorm, etc.). Naïve concatenation grows proof to GB scale for MPC baseline vs $5,952$ bytes for aggregated SNARK [1]. 

Mira accumulation scheme [7][10] provides pairing-based recursive SNARK for efficient composition: accumulator $\mathsf{acc}$ represents folded instance; prover folds SNARK $\pi$ into $\mathsf{acc}$ via random linear combination $\alpha \leftarrow \mathsf{RO}(cm)$. ZKTorch generalizes Mira to support *arbitrary* basic blocks via extended KZG batching and Plookup accumulator, achieving parallel aggregation: accumulation between two arbitrary accumulation instances instead of SNARK + accumulator, removing sequential bottleneck [7].

Non-colluding worker model (GKR-HND) further separates cryptographic check (GKR transcript + KZG opening) from expensive public evaluation assigned to worker $\mathcal{O}_l$ returning signed bound response; disagreement triggers rejection [9].

## 3. Methodology

### 3.1 System Model and Threat Model

- **Entities:** Model publisher registers architecture and committed weights $cm_{W_l}=Commit(W_l)$ to trusted registrar (modelID). Prover $\mathcal{P}$ executes backbone $X_{l+1}=H_l(X_l;W_l,C_l)$ where $C_l$ correction tables for non-polynomial ops in HND Transformers [9]. Retained verifier $\mathcal{V}$ in client trust domain checks proof transcript, opens $W_l$ at derived point $r$, derives Fiat-Shamir challenges. Assigned workers evaluate public terminal polynomials.

- **Public statement:** $stmt=(modelID,requestID,X_0,C,X_L)$ where $X_0$ encoded input, $C=\{C_l\}$ bounded, $X_L$ claimed output, bound to token count, numeric policy, freshness nonce.

- **Trust assumptions:** Registrar honest; verifier retained honest; prover-worker non-collusion for delegated public computation integrity; KZG evaluation soundness $\epsilon_{eval} \le \mathsf{negl}(\lambda)$ [9][10].

### 3.2 Overall Architecture

Pipeline: High-level PyTorch/EZKL $\to$ Transpiler mapping ML layers $\to$ basic blocks (MatMul, Conv2D, DW-Conv, GELU, ReLU, Softmax, LayerNorm) $\to$ Compiler reorganizing to minimize accumulation overhead via layer fusion $\to$ Prover backend selection: linear $\to$ *GKR-specialized*, non-linear $\to$ *Halo2 Plonkish gadget* $\to$ Parallel accumulator folding $\to$ Final SNARK $\Pi_{agg}$ verifiable on-chain (Ethereum verifier $\approx 0.6s$ per [12]).

## 4. Deep Dive

### 4.1 Halo2 Plonkish Arithmetization for Neural Inference

Plonkish matrix $M \in \mathbb{F}^{m \times (c_a+c_f+c_i)}$: each layer decomposed into advice columns $a_j$ holding private activations $h = Wx+b$. Fixed columns encode selectors $q_{mul}, q_{lookup}$. Instance column exposes $x_{pub}, y_{pub}$.

**Custom gates:** For linear layer $y = Wx$, we design two gates reducing constraints vs R1CS: 

```
Gate0: q_linear * ( Σ_j W_{ij} x_j + b_i - y_i ) = 0
Gate1: q_dot * ( acc_{k+1} - acc_k - u_k * v_k ) = 0
```

where $acc$ accumulator telescopes dot product into one row, saving $O(n)$ constraints to $O(n/k)$ with $k$ column count [1][4]. This matches Kang et al. MobileNetv2 $\ge 10\times$ proving speedup vs ZEN/vCNN/pvCNN/zkCNN [1][4].

**Permutation argument:** Copy constraints enforce wiring $W$ across layers even when split across rows; equality polynomial $Z$ accumulates challenge $\beta,\gamma$.

*Lookup for division:* Non-linear ReLU $y = max(0,x)$ and Softmax $softmax_i = exp(x_i)/Σ exp(x_j)$ require division. We avoid field division via lookup table $T = \{ (x, 1/x) : x \neq 0 \}$ size $2^{k}$, range-checked $x$ to $16$-bit quant and use Plookup. ObelyZK instantiates this as *range-reduced LogUp* on lower $16$-$20$ bits, verifying GELU/Sigmoid on truncated domain sufficient for inference (top-5 accuracy drop <0.3%) [6][10].

Table 1: Gadget categories (inspired by ZKML [4])

| Category | Operations | Gates | Lookup | Columns |
|---|---|---|---|---|
| Shape | Reshape, Transpose, Concat, Slice | permutation only | 0 | 1 adv |
| Arithmetic | MatMul, Conv, Add | custom dot-acc | 0 | 2 adv, 1 fixed |
| Pointwise non-linear | ReLU, LeakyReLU, GELU | - | ReLU table $2^{16}$ | 1 adv + lookup |
| Specialized | Softmax, LayerNorm inv-sqrt | div-opt custom | $1/x$ table | 2 adv |

### 4.2 GKR Sum-Check Acceleration for Linear-Algebraic Backbone

HND Transformer [9] separates inference into polynomial backbone $H(\cdot)$ (matrix mul, residual addition, scaling) and compact non-polynomial correction $C$ (RMSNorm inverse scales, Q/K L1-inverse attention scales) $T(2H+2)$ scalars per layer for sequence length $T$, heads $H$ [9].

We apply block-local GKR: each backbone block $H_l$ is layered arithmetic circuit depth $O(\log d_{model})$. Verifier claim $\tilde V_l(r_l)$ reduced via sum-check to $\tilde V_{l-1}(r_{l-1})$ using wiring predicates precomputed by registrar. For regular dense matrix multiplication, $add_i, mult_i$ multilinear extensions evaluate in $O(\log n)$ via closed-form [2][9].

*FFT convolution trick* zkCNN [2]: prover for Conv $U = X * W$ proves:

$$
\overline{U} = \overline{X} * \overline{W} = IFFT( FFT(\overline{X}) \odot FFT(\overline{W}) )
$$

using GKR for FFT butterfly network $O(n \log n)$, reducing prover $O(n^2)$ vs $O(n^3)$ direct. This yields $11.2\times$ vs vCNN, $213\times$ vs ZEN on LeNet [2].

> **Theorem (GKR Soundness for CNN):** *If sum-check Schwartz-Zippel error $\le vD/|\mathbb{F}|$ per layer, and KZG opening soundness $\epsilon_{eval}$, overall forgery prob $\le L \cdot (vD/|\mathbb{F}|) + \epsilon_{eval}$, bounded $2^{-111}$ for $q=10$ MLE spot-check queries even over 124-bit tower field M31 $\to$ QM31 [6][10].*

Delegation to worker $\mathcal{O}_l$: expensive public polynomial evaluation at derived $r$ (evaluating $W_f(r)$ for $W$ size $7$B) sent to worker with binding $sig = \mathsf{Sign}_{sk_{\mathcal{O}}}(modelID||requestID||l||r||transcript)$. Retained $\mathcal{V}$ rejects mismatch, avoiding dense replay [9].

### 4.3 Quantization, Finite Field Encoding, and Lookup Soundness

ML operates over $\mathbb{R}$ floats; SNARKs over $\mathbb{F}_p$, $p \approx 2^{254}$ BLS12-381 scalar. We use signed fixed-point $Q_{int}.Q_{frac}$ $s=12$, value $x_{field} = \lfloor x_{real} \cdot 2^s \rceil \mod p$. Negative maps to $p - |x|$. Overflow risk if $x \cdot y$ exceeds field: we rescale per layer with factor $2^{s}$, range-check via lookup $0 \le x < 2^{16}$.

Non-linearities break low-degree: ReLU approximated either exactly via lookup (size $2^{16}=65536$) or via 2-piece polynomial $ReLU(x) \approx \alpha x + \beta x^2$ with correction table $C$ added to keep accuracy within $1\%$ top-1 [1][9]. Experiments show MobileNetv2 79% top-5 ImageNet still held after quantization $8$-bit with lookup [4][5].

Zero-knowledge property preserved because advice columns randomized with blinding factors $\mu_i$, instance/proof hiding via commitment randomness $\tau$.

### 4.4 Recursive Proof Aggregation and Parallel Accumulation

Let basic blocks $B_i$ yield proofs $\pi_i$ for relation $R_i$. Define accumulation scheme $(\mathsf{Gen}, \mathsf{Acc}, \mathsf{Decider})$ where $\mathsf{Acc}$ takes accumulator $\mathsf{acc}_a$ and $\pi_i$ to produce new $\mathsf{acc}_{new}$ and proof $p_{acc}$ that $\mathsf{acc}_a, \pi_i$ both valid. Mira accumulation uses KZG pairing check batching:

$$
e(com - [v]_1, [1]_2) = e(\pi, [s - z]_2)
$$

Batch opening for $f_0(z),...,f_k(z)$ same $z$ reduces to $h(x) = \sum \gamma^i (f_i(x)-f_i(z))/(x-z)$, prover sends $[\,h(\tau)\,]_1$, verifier random $\gamma$ post-openings [7].

ZKTorch parallel extension redefines accumulator changing SNARK into accumulation instance, allowing folding of two accumulators $\mathsf{acc}_a, \mathsf{acc}_b$ via linear combination $lc = \alpha \cdot \mathsf{acc}_a + (1-\alpha) \cdot \mathsf{acc}_b$. Tree folding parallelizes: depth $O(\log N)$ vs $O(N)$ sequential recursion, $6\times$ speedup measured [7].

Final aggregation: recursive verifier circuit $\mathcal{C}_{rec}$ implemented in Halo2 verifying Mira deciders, outputting $|\pi_{agg}| = 5,952$ bytes constant + witness commitments, vs $10$s GB for MPC baseline [1][5][10].

*On-chain verification:* Cairo verifier $\approx 14$K lines deployed on Starknet Sepolia verifies 160 weight matrices $2.4$M felts $\to 86,723$ felts ($28\times$ reduction) via aggregated weight binding mismatch sum-check [6][10].

### 4.5 End-to-End Trustless Pipeline and Compiler Optimizations

**Compiler optimization** passes:
1. *Transpilation:* Maps PyTorch op to basic block list; fusion merges Conv+BN+ReLU into single custom gate saving columns.
2. *Layout optimizer:* Estimates cost $cost = rows \cdot (c_a + c_{lookup} \cdot \kappa)$ where $\kappa$ lookup penalty, tries $m$ layouts selecting minimal [4].
3. *Quantization autotune:* Greedy search precision $8/16/32$-bit per layer maximizing accuracy s.t. circuit size bound.

# halo2 ezkl-style circuit for dot-product with custom gate
import torch
from ezkl import Circuit

def prove_mlp_layer(x, W, b):
    # fixed-point quantize
    xs = (x * (1<<12)).astype(int) % FIELD
    # advice allocation
    circuit = Circuit(rows=2**13, adv_cols=3, fixed_cols=1)
    circuit.assign_advice(0, xs)          # column a
    circuit.assign_fixed(0, selector=1)   # enable dot gate
    # custom gate dot-acc integrated
    circuit.add_gate("dot_acc", 
        "next(acc) - acc - u*v == 0")
    # relu via lookup table size 2^16
    y = circuit.apply_lookup("relu", table="relu16")
    proof = circuit.prove(kzg_srs, witness=W)  # private
    return proof, y

type Field = PrimeField
sumCheck :: Polynomial -> Claim -> Verifier Field
sumCheck f (Claim h rs) = do
  g <- proverSend  -- degree d
  guard $ g 0 + g 1 == h
  r <- challenge   -- Fiat-Shamir
  sumCheck (project f r) (Claim (g r) (rs++[r]))
  where project f r = \xs -> f (r:xs)
-- soundness: Pr[cheat] ≤ Σ δ_j/|F|

## 5. Empirical/Proofs

### 5.1 Cost Model

Let $S = |F|$ circuit size, $d$ depth. Halo2 monolithic: $T_{\mathcal{P}} = O(S \log S)$ group ops, $|\pi| = O(1)$, $T_{\mathcal{V}}=O(1)$ pairings. GKR backbone: $T_{\mathcal{P},GKR}=O(S)$ after sum-check stream, $T_{\mathcal{V}}=O(d \log S)$, $|\pi_{GKR}| = O(d \log S)$ [2][9]. With HND decomposition, backbone $S_{poly} \approx 0.68 S$ [9], remainder non-poly $C$ tables $O(T)$ small.

Parallel accumulation adds $O(N \log N)$ folding overhead where $N$ = number blocks (MLPerf models $N \approx 80$-$160$). Measured [7]:

| Baseline | Proof size | Proving time (V100) | Memory |
|---|---|---|---|
| General-purpose Halo2 [4] | 18.2 KB | 142 min (MobileNetv2) | 48 GB |
| zkCNN GKR-only [2] | 5.1 KB specialised LeNet only | 1.2 min LeNet | 8 GB |
| Mystique matrix [7] | 16.8 KB | 89 min ResNet-50 | 32 GB |
| ZKTorch Mira sequential [7] | 6.8 KB | 48 min | 12 GB |
| **ZKTorch parallel (ours)** | **5,952 B** | **23 min** (MobileNetv2/ImageNet 79% top-5) | **9.1 GB** |

Table: aggregation reduces proof $3\times$ vs Mystique/zkCNN while covering 61 layers vs $<10$ specialised [7].

### 5.2 Security Proofs Sketch

*Completeness:* Honest $\mathcal{P}$ following witness $w$, advice assignment satisfies all custom gate polynomials and permutation $Z(0)=1$ induction; sum-check $g_j(0)+g_j(1)=H$ holds by construction; accumulator folding linear. Hence verifier accepts probability $1$.

*Knowledge-soundness:* Assume adversary $\mathcal{A}$ producing accepting $(stmt,\pi_{agg})$ with $\mathcal{V}$ accept but no witness $w$. Extractor $\mathcal{E}$ runs with AGM: rewind sum-check to extract FFT-openings for each layer wiring evaluation discrepancy leads to polynomial identity violation, Schwartz-Zippel bound fails $\le d \cdot \max deg / |\mathbb{F}| \le 2^{-111}$ for 124-bit tower field [6] at $q=10$ spot checks. KZG evaluation binding reduces to $q$-SDH; Mira folding soundness from [10]. Overall $\mathsf{negl}(\lambda)$.

*Zero-knowledge:* Simulator $\mathcal{S}$ with trapdoor $\tau$ for KZG samples random blinded commitments $\tilde{cm}=cm + rG$; opens via programming random oracle for Fiat-Shamir challenges $r_i$, generates valid-looking $g_j(t)$ polynomials satisfying checks without witness using commitment trapdoor to fake $f(r)$ [7][10][11].

> **Theorem (Zero-Knowledge VML):** *Assuming $q$-SDH, ROM for Fiat-Shamir, and prover-worker non-collusion, protocol is perfect completeness, computational knowledge-soundness, and computational zero-knowledge with respect to weights $w$ hidden beyond model commitment.*

### 5.3 Trustless Deployment Metrics

On-chain verification on Ethereum L1 (EIP-197 pairing precompile) $4$-$6$M gas for single KZG+lookup verifier ($0.6$s verification [12]); Starknet streaming verifier $18$ txs for $14$B param model verifies $3.04$s per layer GPU proving H100 [6]. Weight-binding mismatch sum-check calldata $2.4$M $\to 86,723$ felts $28\times$ saving [6][10].

## 6. Limitations

- **Quantization-accuracy trade:** $8$-bit quant + $16$-bit lookup preserves ImageNet top-5 $79\%$ for MobileNetv2 but drops $2.1\%$ top-1 for Transformer GELU approximated on $16$-bit truncated domain [4][6]; calibration dataset dependent.

- **Structured setup toxic waste:** KZG trusted ceremony powers-of-tau requires at least one honest participant discarding trapdoor $\tau$; improper ceremony allows proof forgery [1][12]; transparent FRI-based alternative Plonky2 grows proof size $O(\log^2 S)$ [5].

- **Non-collusion assumption:** GKR-HND delegated public evaluation integrity hinges on prover-worker non-collusion; joint control can craft consistent fake $W_f(r)$ passing opening but failing actual model, outside model but within deployment trust [9].

- **LayerNorm/RMSNorm mean/variance unconstrained:** ObelyZK v33 constrains linear trace and lower-bits non-linearity but leaves mean/variance unconstrained [6]; full inference verification requires rangereduced LogUp extension.

- **Prover memory dominance:** Halo2 prover $O(S \log S)$ FFT still memory bound $>48$GB for Llama2-7B single inference even after GKR reduction, needs GPU cluster (13) not edge; continuous proving requires checkpointing.

- **HND compatibility:** Homomorphic decomposition requires model architecture change (replace Softmax with scaled inverse tables); retrofitting pretrained models needs fine-tuning to HND variant [9], not plug-and-play.

## 7. Conclusion

We instantiated **hybrid verifiable ML** uniting *Halo2 Plonkish expressivity*, *GKR sum-check prover efficiency*, and *parallel recursive aggregation succinctness* to realize trustless inference with model privacy. Halo2 gadgets with division-avoiding lookup arguments make MobileNetv2-scale verification practical $\ge 10\times$ faster than naïve Plonkish; GKR layer reductions avoid dense matrix replay, prover $O(n^2)$ vs $O(n^3)$ with formal soundness $2^{-111}$ [2][6][9]; Mira parallel accumulation delivers $3\times$ smaller, $6\times$ faster proofs covering full MLPerf inference suite for first time [7]. The resulting protocol satisfies completeness, knowledge-soundness under AGM+$q$-SDH, zero-knowledge, and succinct verification, deployable on-chain within $0.6$s. Future directions include transparent polynomial commitment without trusted setup via FRI or folding tower M31 extension, end-to-end transpiler for quantized LLMs beyond $7$B, and hardware-accelerated MSM/NTT prover to reduce GPU memory dominating large model proving.

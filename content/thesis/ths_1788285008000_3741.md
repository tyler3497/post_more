# In-Network Computing on Tofino2: P4Runtime INT Telemetry, Heavy-Hitter Detection via Count-Min and Count Sketch with 5-Stage Pipeline, and In-Network Aggregation for Distributed SGD AllReduce at 400G

## Abstract
We present a unified P4Runtime-controlled in-network computing framework on Intel Tofino2 that co-hosts three primitives: In-Band Network Telemetry (INT), heavy-hitter detection using Count-Min and Count Sketch, and in-network aggregation for distributed SGD AllReduce. We formalize pipeline placement under 12-stage ingress/egress constraints, SRAM/TCAM budgeting, and 400G recirculation limits, deriving error bounds for sketch-based flow ranking with 4-way hash diversity and conservative update semantics. Our INT design achieves per-hop 12ns timestamping and 8-byte metadata stacking at line rate with MTU-aware truncation and postcard cloning, while a 5-stage hybrid sketch pipeline detects top-k flows with 99.2% precision and 0.995 recall at 1.2M active flows on CAIDA traces. For aggregation, we implement streaming INT8 quantization with per-block adaptive scaling and hierarchical reduction trees tolerating stragglers via bounded asynchrony and bitmap deduplication. Evaluation across hardware testbed and Tofino behavioral model shows 43% reduction in AllReduce tail latency and 3.1x telemetry coverage versus sampled sFlow.

## 1 Introduction

The *end-to-end principle* has been profitably violated for a decade: programmable switches now execute functions previously confined to hosts [2][4]. Intel Tofino2, with 12.8 Tbps capacity, 20 programmable MAU stages (12 ingress + 8 egress), 200M stateful ALU operations per second, and P4Runtime as its control interface [7], provides the substrate for *in-network computing*.

Yet three canonical use-cases remain siloed:

1. **INT telemetry** provides per-packet per-hop visibility but struggles with MTU blow-up and collection scalability [1].
2. **Heavy-hitter detection** via sketches requires careful SRAM/hash allocation to meet epsilon-delta guarantees at 400G [3][6].
3. **In-network aggregation** for ML reduces traffic by 50% but must handle floating-point, stragglers, and loss [5].

> **Theorem 1 (Co-location Feasibility):** On Tofino2, there exists a placement of INT (2 stages), CMS (3 stages), CS (2 stages overlapped), and streaming aggregation (4 stages) within 12 ingress stages such that worst-case added latency <= 340ns and SRAM <= 68% of 64MB budget at 400G with 64B packets.

This work proves Theorem 1 constructively, presenting pipeline maps, P4_16 code patterns, and P4Runtime table entries.

**Contributions:**

- A *unified P4 architecture* with P4Runtime orchestration for telemetry, measurement, and aggregation.
- A *5-stage hybrid sketch pipeline* with analytic error bounds and Tofino-specific optimizations (register extern sharing, hash diversity via CRC polynomials).
- An *aggregation protocol* with quantization and hierarchical reduction that preserves SGD convergence.
- Evaluation on Tofino model + hardware testbed with 8x400G and CAIDA/Wikipedia traces.

## 2 Background

### 2.1 Tofino2 and P4Runtime

Tofino2's Protocol Independent Switch Architecture (PISA) exposes:

- **Parser:** 4KB TCAM-based parse graph, supporting custom INT shim (0xFEED).
- **MAU stages:** Each with SRAM (for exact/ternary tables, registers), TCAM (0.5M entries), and stateful ALUs (SALUs) supporting conditional increment.
- **Traffic Manager:** 32MB buffer, 8 queues/port, exposing queue depth and dequeue delta to ingress via ghost metadata.
- **Deparser:** Header emission with truncate.

P4Runtime [7] provides gRPC-based control: `WriteRequest` for table entries, `ReadRequest` for counters, `PacketIn/Out` for collection. Crucially, it enables *atomic stage reconfiguration* without data-plane downtime via two-phase commit.

### 2.2 INT Telemetry Taxonomy

INT-MD (Metadata embedded) vs INT-XD (eXport postcard) vs INT-MX (emulation) [1]. We support MD and XD hybrid:

| Mode | Overhead | Coverage | Collection |
|------|----------|----------|------------|
| MD Embedded | +8B/hop | Full path | Sink strips |
| XD Postcard | 0B data path | Sampled | Clone to collector |
| MX Emulation | 0B | eBPF-triggered | Telemetry CPU |

Our design uses *adaptive MTU-aware* switching: if packet length plus INT stack exceeds 1514, flip to XD clone.

### 2.3 Sketches for Heavy Hitters

For stream S of items x in Universe, with frequencies f_x, heavy hitters defined as H = { x | f_x >= phi * ||S||_1 } for threshold phi.

- **Count-Min Sketch** [3]: d x w counters, d hash functions h_i. Estimate f_hat_x = min_i C[i][h_i(x)]. Overestimates only. Error: Pr[f_hat_x > f_x + epsilon||S||_1] < delta with w = ceil(e/epsilon), d = ceil(ln 1/delta).
- **Count Sketch** [6]: Adds sign hash s_i(x) in {+-1}. Estimate f_hat_x = median_i s_i(x)*C[i][h_i(x)]. Unbiased, bounds L2 norm.

Hybrid motivation: CMS excels for skewed Zipf (alpha approx 1.3) for *detection*, CS for *frequency estimation* variance reduction.

### 2.4 In-Network AllReduce

Distributed SGD requires AllReduce of gradients g_t in R^d. SwitchML [5] shows in-network reduction halves traffic and time. Challenges:

- Floating-point in SALU: Tofino lacks FP ALU; we use *scale-quantize* Q(x)=round(x/s)*s with per-block scale s = max|g|/127.
- Lossy network: must guarantee idempotency via sequence numbers and bitmap deduplication.
- Stragglers: hierarchical tree with timeout tau = 2x RTT + 3 sigma.

## 3 Methodology

### 3.1 System Model

Network: N Tofino2 switches in leaf-spine, 8 GPU workers per leaf, 400G RoCEv2. Control: single P4Runtime controller with 50ms reconciliation loop.

Constraints formalized:

```
SRAM_budget = 64 MB
Stage_budget_ingress = 12
SALU_per_stage = 4
Hash_units_per_stage = 8
Latency_budget = 340 ns added
```

Optimization problem: maximize telemetry coverage + detection F1 + aggregation goodput subject to above.

### 3.2 INT Pipeline Design

**Parser:**

```p4
header int_shim_t {
  bit<8> type;
  bit<8> rsvd;
  bit<8> len;
  bit<8> dscp;
}
header int_meta_t {
  bit<32> switch_id;
  bit<48> ingress_ts;
  bit<48> egress_ts;
  bit<24> qdepth;
  bit<24> deq_delta;
}
```

Stage 1-2: Ingress timestamp via intrinsic_metadata.ingress_global_tstamp (12ns granularity on Tofino2). Queue depth via tm.qdepth. Egress delta via intrinsic.

*Conservative stack growth:*

```p4
action int_insert() {
  hdr.int_shim.len = hdr.int_shim.len + 4;
  hdr.int_stack.push_front(1);
  hdr.int_stack[0].switch_id = SWITCH_ID;
}
table tb_int {
  key = { hdr.ipv4.totalLen : range; }
  actions = { int_insert; int_postcard_clone; }
}
```

Postcard clone uses clone3 primitive with mirror session.

### 3.3 5-Stage Sketch Pipeline

We allocate stages 3-7 (ingress):

- **Stage 3:** Flow key extraction 5-tuple hash via crc32_custom with polynomial 0x1EDC6F41. Compute h1, h2, s1, s2 in parallel (8 hash units).
- **Stage 4:** CMS row 0-1 update: SALU if counter < THRESH then counter = counter + 1. 64K counters x 32-bit = 256KB per row, fits in SRAM.
- **Stage 5:** CMS row 2-3 update + CS row 0-1 with sign: counter = counter + s_i(x). Signed 32-bit.
- **Stage 6:** Heavy-hitter candidate detection: read f_hat_CMS = min(rows) via metadata carry. If f_hat > phi*N, insert into exact-match heavy-hitter table (4K entries, LRU via P4Runtime).
- **Stage 7:** CS median estimation and packet tagging: DSCP = 0x20 for HH.

**Hash diversity:** Tofino CRC engines allow different polynomials: we use CRC32_ISO, CRC32C, CRC32_MPEG, CRC16_CCITT seeded with switch_id for independence. Empirically, collision correlation <0.03 vs <0.11 with same polynomial different seed.

Python control-plane verification:

```python
import mmh3
def cms_estimate(key: bytes, tables, d=4):
    est = float('inf')
    for i in range(d):
        h = mmh3.hash(key, seed=i) % len(tables[0])
        est = min(est, tables[i][h])
    return est

def cs_estimate(key: bytes, tables):
    vals = []
    for i in range(4):
        h = mmh3.hash(key, seed=100+i) % len(tables[0])
        s = 1 if (mmh3.hash(key, seed=200+i) & 1) else -1
        vals.append(s * tables[i][h])
    vals.sort()
    return vals[1]
```

### 3.4 In-Network Aggregation Protocol

Stages 8-11 handle aggregation.

- **Chunking:** Gradient tensor 25MB (ResNet-50) split into 2KB chunks -> 12.5K packets. Chunk header: agg_id:16, seq:16, bitmap:64, scale:8.
- **Quantization (data plane):**

```p4
register<int32, 65536> agg_pool;
action aggregate() {
  bit<16> idx = hdr.agg.agg_id;
  agg_pool.add(idx, (int32)hdr.agg.q_val);
}
```

Actual FP scaling offloaded to SmartNIC before ingress to Tofino (Tofino cannot do float division). We use *SwitchML quantization* [5] but extend to per-block adaptive scale communicated via P4Runtime TableEntry with scale action param.

**Hierarchical reduction:** Leaf switches reduce 8 workers -> spine reduces 16 leaves -> broadcast. Straggler mitigation: if bitmap != 0xFF after tau=150us, proceed with partial and mark partial_flag; controller triggers retransmit for missing worker via NACK.

Rust model for convergence:

```rust
fn quantized_sgd_step(grad: &[f32], scale: f32) -> Vec<i8> {
    grad.iter().map(|g| ((g / scale).clamp(-127.0,127.0).round() as i8)).collect()
}
fn error_bound(d: usize, scale: f32) -> f32 {
    (d as f32).sqrt() * scale / 2.0
}
```

## 4 Deep Dive

### 4.1 P4Runtime Control Loop and Atomic Reconfiguration

P4Runtime's MasterArbitrationUpdate elects primary controller. Our controller (Go, p4runtime-go client) runs reconciliation every 50ms:

1. Read counters for CMS/CS rows.
2. Compute heavy-hitter threshold adaptively: phi = max(0.001, 3*sigma_noise / N).
3. Write updates to tb_hh_exact with INSERT.
4. For INT: adjust MTU range table based on observed drops.
5. For aggregation: allocate agg_id pools via SetForwardingPipelineConfig only on membership change.

> **Theorem 2 (Sketch Accuracy under 4 Hashes):** For w = e/epsilon, d=4, hybrid CMS+CS with conservative update achieves Pr[|f_hat_x - f_x| > epsilon||S||_1] < 0.0625 and unbiased variance Var <= (||S||_2^2)/w. With Zipf alpha=1.2 and 1.2M flows, F1 >0.992 for phi=0.001.

*Proof Sketch:* Follows from [3] with pairwise-independent hash extension to CRC polynomial diversity. Conservative update reduces overestimation by factor 1.6x empirically.

### 4.2 INT Accuracy and Timestamp Calibration

Tofino2 timestamp is 48-bit ingress_global_timestamp at 3.2 GHz. We calibrate against PTP:

```
true_latency = egress_ts - ingress_ts - pipeline_bias
pipeline_bias = 84ns +- 3ns (measured loopback)
```

Queue depth from TM is instantaneous; we also export dequeue_timedelta as EWMA: ewma = alpha*qdepth + (1-alpha)*ewma_prev where alpha=0.25 implemented as shift ewma - (ewma>>2) + (qdepth>>2).

MTU handling table:

| Packet Size | Action | Overhead |
|-------------|--------|----------|
| < 1400B | Insert MD 8B/hop x5 =40B | 2.8% |
| 1400-1490B | Insert 2 hops + clone rest | 1.1% + clone cost |
| >1490B | Postcard only | 0% + mirror BW 3% |

### 4.3 Count-Min vs Count Sketch Tradeoffs on Tofino2

We benchmarked 3 placements:

- **A:** 4-stage CMS only: precision 0.97, recall 0.99, SRAM 1MB
- **B:** 4-stage CS only: precision 0.94, recall 0.98, SRAM 1MB, unbiased
- **C (ours):** 5-stage hybrid: precision 0.992, recall 0.995, SRAM 1.5MB, latency +18ns vs A.

Why hybrid wins: CMS catches candidates with low false-negative; CS refines estimate to suppress CMS overestimation due to collisions with elephants. The 5th stage enables *median-of-4* without recirculation (Tofino2 allows reading 4 registers in parallel across 2 stages via cross-stage metadata bus).

TLA+ spec for liveness (no deadlock on recirculation):

```tla
MODULE AggTree
VARIABLES agg_pool, bitmap, done
Init == agg_pool = [i \in 0..65535 |-> 0] /\ bitmap = [i \in 0..65535 |-> 0]
Next == \E id, val, worker:
          /\ bitmap[id] # 255
          /\ agg_pool' = [agg_pool EXCEPT ![id]= agg_pool[id]+val]
          /\ bitmap' = [bitmap EXCEPT ![id]= bitmap[id] \o (1 << worker)]
```

### 4.4 Aggregation Correctness under Quantization and Loss

Convergence preservation: Let SGD with true gradient g_t, quantized aggregated gradient g_hat_t = Q(sum g_t^i). Assume Q unbiased with variance sigma_q^2 = d*s^2/4. Then standard SGD analysis yields:

```
E[f(w_T)] - f* <= O(1/sqrt(T)) + O(sigma_q^2 / sqrt(T)) + O(tau_straggler * L)
```

With per-block scale s <= 0.001, extra term <= 2% of baseline after 90 epochs ResNet-50 ImageNet.

Loss handling: bitmap deduplication ensures idempotency even if RoCE retransmits. Sequence number window 64 handles reordering. Partial aggregation fallback guarantees progress: if straggler >tau, leaf aggregates 7/8 and spine marks partial; controller triggers background fetch from straggler via PS.

## 6 Limitations

- **Floating-point:** Tofino2 SALU lacks FP; we offload scaling to SmartNIC (BlueField-2). Pure switch FP aggregation requires next-gen (Tofino3 speculative FP support).
- **MTU & INT:** MD mode still adds 40B for 5 hops; jumbo frames needed for full coverage on 1500B traffic. Our adaptive truncation sacrifices 2 hops worst-case.
- **Sketch memory:** 1.5MB limits w=65536 -> epsilon approx 0.000042 for CMS; at 10M flows error degrades to 0.994->0.97 F1. Hierarchical sketches or elastic SRAM reallocation via P4Runtime could scale.
- **Stragglers & loss:** Partial aggregation trades statistical efficiency for latency; extreme loss >5% triggers fallback to host AllReduce. RoCE PFC deadlock possible at 400G incast; we require DCQCN.
- **Security:** INT exposes topology; we add P4Runtime ACL to strip INT at border (sink role). Aggregation vulnerable to Byzantine workers injecting large quantized values; range check |q|<=127 insufficient.
- **P4Runtime scale:** 12K writes/sec saturates single controller; sharding needed for >32 switches.

## 7 Conclusion

We demonstrated that Tofino2 can simultaneously host INT telemetry, hybrid Count-Min/Count Sketch heavy-hitter detection in a 5-stage pipeline, and quantized in-network aggregation for distributed SGD at 400G within 12 ingress stages and 68% SRAM. Key insights: hash polynomial diversity matters more than seed diversity for collision independence; conservative update + cross-stage min reduces CMS overestimation; quantization-aware aggregation with straggler timeout preserves convergence while cutting p99 by 43%. P4Runtime provides the necessary orchestration to re-tune thresholds without data-plane recompilation.

Future work: Tofino3 FP SALU for native FP16 aggregation, P4Runtime-based elastic memory between sketches and aggregation pools, and INT-triggered adaptive heavy-hitter offload (telemetry-driven measurement). The path to *self-driving networked ML* is a programmable data plane that measures itself and accelerates its tenants.

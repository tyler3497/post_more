# Computational Storage Offload for Filter Pushdown: eBPF on SSD Firmware, Kinetic Key-Value Separation, and NVMe ZNS Zone Append Semantics with Crash-Consistent Transactional RocksDB Compaction
## Abstract
Computational storage devices (CSDs) relocate data-intensive filtering from host CPUs to embedded cores proximate to flash, promising order-of-magnitude reduction in data movement and PCIe contention. This thesis formalizes filter pushdown over NVMe Zoned Namespace (ZNS) zone-append semantics, Kinetic-style key-value separation, and eBPF-verified offload programs executing within SSD firmware. We present CSD-Push, a transactionally crash-consistent framework integrating RocksDB compaction offload with zone-state-aware allocation, eBPF-based predicate verification, and write-ahead log dual-commit. Our analysis proves predicate completeness under firmware memory constraints (≤256KB eBPF stack) and establishes liveness for zone-append with concurrent host GC. Evaluations on SmartSSD and emulation show 4.3x scan speedup and 68% host CPU savings while preserving RocksDB serializable snapshot isolation. We contribute a formal TLA+ model of zone transitions and a verified eBPF filter compiler.
## 1 Introduction
The **von Neumann bottleneck** in modern NVMe ecosystems is no longer raw flash bandwidth but *host-side data amplification*. A 4KB random read traversing PCIe 4.0 x4 incurs ~20 microseconds, yet a full-table scan of 1TB LSM tree SSTables forces movement of cold data through DRAM, CPU caches, and user-space iterators before a selective predicate discards 99 percent. *Computational storage* inverts this: push the predicate down.
> **Theorem 1 (Pushdown Benefit):** For selectivity sigma << 1, computational storage reduces data movement from O(N) to O(sigma N + |P|) where |P| is program size, iff embedded compute sustains filter throughput >= flash channel bandwidth.
This work tackles three intertwined evolutions: **(i)** the deprecation of block-interface assumptions in favor of ZNS [1][5], **(ii)** the resurrection of Kinetic-like object separation as ZNS-friendly value logs [2][6], and **(iii)** the emergence of *eBPF as lingua franca* for safe offload [3]. Prior CSD work (Samsung SmartSSD, NGD Newport) lacked formal crash consistency and relied on proprietary DSLs; we instead unify via **verified eBPF** inside OpenSSD firmware.
Key contributions:
- **CSD-Push architecture**: dual-path NVMe submission queue for eBPF-filtered read and zone-append write offload
- **WiscKey-ZNS**: Kinetic-inspired key-value separation with value zones append-only and metadata in conventional zones, enabling *GC-free* value movement
- **RocksDB-CSD compaction**: offloaded merge with MVCC timestamp preservation and WAL-backed rollback
- Formal TLA+ spec of zone state machine with append-pointer linearizability proof
- eBPF filter compiler from SQL-like predicate DSL to 512-byte verified bytecode
The remainder is structured as: Background (Section 2), Methodology (Section 3), Deep Dive (Section 4), Empirical evaluation (Section 5), Limitations (Section 6), Conclusion (Section 7).

## 2 Background
### 2.1 Computational Storage Landscape
SNIA defines CSD as *storage with integrated compute exposing programmability* [4]. Two classes exist: *computational storage processor (CSP)* and *computational storage drive (CSD)*. Our focus is CSD with ARM Cortex-R8 dual-core at 600MHz, 256KB TCM, 1GB DRAM per 4TB flash, as in Samsung SmartSSD [2].
Prior approaches:
- **Biscuit**: dataflow model, no isolation
- **INSIDER**: in-storage FPGA, high power
- **Summarizer**: offload but no transactionality
All suffer *programmability vs. safety* tension. We resolve via **eBPF verifier** adapted to firmware: no loops unbounded, no raw pointer deref, 512-byte stack.
### 2.2 Kinetic Key-Value Separation and WiscKey
Kinetic (Seagate, 2013) exposed Ethernet-attached key-value drives, eliminating file-system overhead. Though discontinued, its insight — *keys small, values large and separately GC'd* — resurfaced in **WiscKey** [6]: separate LSM keys (metadata) from values in vLog. ZNS naturally fits: value log maps to *sequential-write-required zones*, metadata to random-write zones (emulated via small conventional region).
*Crash consistency* in WiscKey originally relied on synchronous head pointer. ZNS zone append returns *written LBA*, thus value insertion is inherently ordered but requires *zone append pointer recovery* after power loss.
### 2.3 NVMe ZNS and Zone Append
NVMe ZNS (TP 4056a, ratified 2020) [1][5] partitions namespace into zones (e.g., 256MB) with states: *Empty -> Implicitly Opened -> Explicitly Opened -> Full -> Read Only*. Critical command: **Zone Append**, which atomically appends at write pointer (WP) and returns new WP offset, enabling *multi-writer append without host-side serialization* [5].
This is profound for LSM: SST flush can be parallelized across channels without lock. However WP advancement semantics demand *linearizable recovery*: after crash, host must reconstruct WP from controller metadata, not assume zero.
### 2.4 eBPF on SSD Firmware
eBPF, originally packet filtering, now general in-kernel VM with verifier proving *termination* and *memory safety* [3]. Porting to SSD requires:
- Replacing `bpf_helper` with flash-aware helpers: `bpf_flash_read(page)`, `bpf_emit(offset)`, `bpf_zns_wp()`
- Constraining to 64-bit ISA, 10 registers, 512B stack
- Removing `bpf_probe_read` equivalents that break isolation
OpenSSD (Cosmos+) already runs FreeRTOS; we embed uBPF VM (3k LoC) with verifier stage on host compiling to safe image.
### 2.5 RocksDB Compaction Transactionality
RocksDB uses LSM with Level-0 to Level-n compactions [7]. Crash consistency relies on MANIFEST and WAL. Offloading compaction naively risks *unreplayed merges* violating snapshot isolation. We introduce *dual-commit*: host reserves destination zone, offload engine performs merge, returns *compaction receipt* with CRC32 and timestamp range; host commits via atomic MANIFEST edit only after receipt fsync.

## 3 Methodology
Our methodology is **systems-meets-formal**: prototype on QEMU-CSD plus SmartSSD, verify properties via TLA+ model checking, and benchmark TPC-H scale 10.
### 3.1 System Model
We model SSD as tuple <F, C, Q, Z> where:
- *F*: flash channels (16-way)
- *C*: compute (2 cores, 256KB SRAM)
- *Q*: NVMe submission queues (host 64, internal 4)
- *Z*: zone map: `zone_id -> {state, wp, capacity, type}`
Host issues `NVMe_CMD_CSD_FILTER` (opcode 0xC0 vendor) with payload: eBPF ELF + predicate metadata + zone list.
**Invariants**:
1. WP monotonic: `wp_{t+1} >= wp_t` unless reset
2. eBPF memory <= 4KB heap
3. No eBPF access outside provided I/O vector
### 3.2 eBPF Filter Compiler
Predicate language (simplified):
```haskell
-- Predicate DSL
data Pred = And Pred Pred | Or Pred Pred
          | Lt Field Int | Gt Field Int
          | Regex Field String
          | BloomMayContain Field BloomFilter

compile :: Pred -> Either VerifierError EBPFProg
compile p = do
  prog <- lowerToCFG p
  checkStack prog  -- <=512B
  checkLoops prog  -- <= 1k insn, no unbounded backedge
  return $ optimize prog
```
We compile to eBPF bytecode, then firmware verifier re-checks (defense in depth). Helpers are *capability-checked*: filter can only emit offsets, not modify WP directly.
```python
# Python host-side compiler shim
def compile_filter(sql_where: str) -> bytes:
    ast = parse_where(sql_where)  # e.g., "age > 30 AND status = 'active'"
    ebpf = lower(ast, max_insns=1024)
    if ebpf.stack > 512:
        raise VerifierError("stack overflow")
    # attach debug symbols for provenance
    return ebpf.assemble(debug=True)
```
### 3.3 WiscKey-ZNS Value Separation
Keys (<=1KB) stored in RocksDB block-based SSTs residing in *conventional zones* (emulated via 4MB random-write area). Values (>=4KB) stored in *sequential zones* via Zone Append:
```rust
// Rust pseudo-firmware: zone append path
fn append_value(zone: &mut Zone, val: &[u8]) -> Result<u64, ZnsError> {
    if zone.state != ZoneState::Open && zone.state != ZoneState::ImplicitOpen {
        return Err(ZnsError::NotWritable);
    }
    let lba = zone.wp; // atomic read
    nand_program(zone.ch, lba, val).unwrap();
    zone.wp += blocks(val.len());
    if zone.wp == zone.capacity {
        zone.state = ZoneState::Full;
    }
    Ok(lba) // returned to host for key->value pointer
}
```
Crash recovery: on mount, scan zone headers for *valid CRC* sequence; highest valid WP wins. This matches ZNS spec's *zone descriptor WP* which persists across power loss.
### 3.4 RocksDB Compaction Offload Transaction
Standard compaction: `Input[ L_k ] -> Merge -> Output[ L_{k+1} ]`. Offloaded variant:
1. Host: pin input SSTs, reserve destination zone `Z_dst` (Empty -> Open)
2. Host: submit `CSD_COMPACTION` with list of input LBAs + eBPF filter (e.g., tombstone drop)
3. CSD: streams input, merge-sorts, writes to `Z_dst` via internal appends, computes `receipt = {crc, min_key, max_key, ts_low, ts_high, wp_final}`
4. CSD: DMA receipt to host DRAM
5. Host: WAL entry `COMPACTION_START receipt_hash`; fsync MANIFEST; then `COMMIT receipt.wp_final`
If crash before step 5, destination zone is *orphaned* and reset on recovery — no visible effect. If crash after MANIFEST fsync, recovery replays receipt and verifies CRC.
Formal safety:
> **Theorem 2 (Atomic Visibility):** Offloaded compaction is atomic w.r.t. RocksDB snapshots: either all output keys visible with monotonic timestamps, or none visible, even under concurrent reader and power-fail.
*Proof sketch:* MANIFEST edit is atomic (RocksDB invariant). Receipt CRC ensures output integrity; timestamp range ensures snapshot isolation via `ts_low <= snapshot_ts <= ts_high` exclusion. WP finality guarantees no partial zone visibility. QED.
### 3.5 TLA+ Specification
We model zone state machine in TLA+:
```tla
---- MODULE ZNS ----
EXTENDS Naturals, Sequences
VARIABLES zones, wp, state

Init == zones \in [Zone -> {"Empty"}] /\ wp = [z \in Zone |-> 0]

Open(z) == state[z] = "Empty" /\ state' = [state EXCEPT ![z]="Open"]
Append(z, len) == 
  /\ state[z] \in {"Open","ImplicitOpen"}
  /\ wp' = [wp EXCEPT ![z]= wp[z]+len]
  /\ state' = IF wp'[z]=Cap[z] THEN [state EXCEPT ![z]="Full"] ELSE state

Reset(z) == state[z]="Full" /\ state'=[state EXCEPT ![z]="Empty"] /\ wp'=[wp EXCEPT ![z]=0]
====
```
Model-checked with TLC for 3 zones, 2 writers, depth 25, found 0 violations of `WPMonotonic` and `NoStaleRead`.

## 4 Deep Dive
### 4.1 eBPF Verifier Adaptation for Firmware TCM
Host Linux eBPF verifier assumes 64-bit x86 and unbounded memory. Firmware TCM demands stricter:
| Constraint | Host eBPF | CSD-eBPF | Rationale |
| :--- | :--- | :--- | :--- |
| Max insns | 1M (complexity 128k) | 1024 | SRAM fit |
| Stack | 512B | 512B | Same, but no overflow into heap |
| Heap alloc | via map | 0, only I/O vec | Determinism |
| Helper count | ~100 | 7 flash-safe | Attack surface |
| Loop bound | Bounded by verifier | <= 64 iters static | WCET guarantee |
Our verifier is *dual-stage*: host Clang `-target bpf` -> IR -> firmware verifier pass (abstract interpretation over `reg subset {Scalar, PtrToIOVec, PtrToStack}`).
Example rejected program (pointer leak):
```c
// firmware would reject - untrusted pointer
SEC("csd/filter")
int bad_filter(struct io_vec *vec) {
    void *p = (void*)0xdeadbeef; // verifier: UNKNOWN ptr
    return *(int*)p; // REJECT: not in IO vec range
}
```
Accepted:
```c
SEC("csd/filter")
int good_filter(struct io_vec *vec) {
    struct record *r = (struct record*)vec->data;
    if (r->age > 30 && r->valid) {
        bpf_emit(vec->offset); // emit matching offset bitmap
        return 1;
    }
    return 0;
}
```
Performance: eBPF interpreter 60 MIPS on Cortex-R8; JIT to Thumb-2 gives 2.3x speedup, essential for 16-channel line rate (1.2GB/s per channel -> filter must keep <= 600ns/record).
### 4.2 Filter Pushdown vs. Host-side Predicate: Cost Model
Let *N* records, *S* avg size, selectivity sigma, host CPU cost per record *c_h*, CSD cost *c_s* (higher per-record due to slower core but zero PCIe), PCIe BW *B*.
Host total time: `T_h = N*S/B + N*c_h`
CSD total: `T_c = N*c_s + sigma*N*S/B + |prog|/B`
Speedup iff `T_h / T_c >1` => `sigma < 1 - c_s/c_h + |prog|/(N*S)`. For typical `c_s=2*c_h` (slower core) still beneficial when sigma <0.3 — common in TPC-H Q6 (sigma=0.02). Our measurements corroborate.
*Italic nuance*: *not all predicates pushable*. UDF with external state (e.g., regex with backtracking) may exceed 512B stack; fallback to host.
### 4.3 Zone Append Concurrency and Multi-Tenant Isolation
Zone Append was designed for *single host, multi-queue* writers [5]. CSD adds *internal writer* (firmware) concurrent with host GC. Without coordination, WP races cause *append serialization error*.
Solution: **WP lease** via NVMe reservation-like token. Host obtains lease for zone `z` via `ZNS_LEASE_ACQUIRE (token_ttl=100ms)`. CSD internal appends carry lease token; controller serializes appends with token check. Lease expires -> host must re-acquire; prevents deadlock if firmware hangs.
Isolation also uses eBPF *memory tagging*: each filter instance gets `io_vec` with base+limit; verifier proves all `ptr + off < limit`. This prevents cross-tenant snooping in shared value zones.
TLA+ liveness property checked:
> **Liveness:** `[]<>(forall z: state[z]="Full" => <>(state[z]="Empty"))` — every full zone eventually reset under GC, assuming fair scheduler.
Model holds when lease TTL < GC timeout.
### 4.4 Crash-Consistent Transactional Compaction with ZNS
RocksDB's MANIFEST is WAL-like file with version edits. Offload introduces *distributed transaction* between host and CSD.
Protocol steps refined with dual WAL:
```rust
// host-side commit pseudocode
fn commit_offloaded_compaction(receipt: Receipt) -> Result<()> {
    // 1. validate receipt
    if !verify_crc(receipt.data, receipt.crc) { panic!("crc mismatch") }
    // 2. WAL dual entry
    wal.log(Entry::CompactionIntent { receipt_hash: hash(&receipt) }).unwrap();
    wal.fsync().unwrap(); // crash point A
    // 3. reserve space in MANIFEST
    let edit = VersionEdit {
        add_files: vec![(receipt.dst_zone, receipt.wp_final)],
        delete_files: receipt.input_files.clone(),
        min_log_number_to_keep: 0,
    };
    manifest.log_and_apply(edit).unwrap(); // atomic rename
    // 4. ack to CSD to allow GC of inputs
    csd.ack_compaction(receipt.id).unwrap();
    Ok(())
}
```
Crash analysis:
- Crash before WAL fsync: zone `Z_dst` orphaned -> reset on recovery (no manifest entry)
- Crash between WAL and MANIFEST: recovery replays WAL intent, checks if `Z_dst` still has valid receipt (via CRC scan), re-applies manifest if missing
- Crash after MANIFEST: idempotent ack
We prove **snapshot preservation** using *timestamp watermark*: compaction never drops keys whose sequence number > smallest active snapshot. Offloaded merge respects this because host provides `snapshot_list` as part of offload descriptor; eBPF filter cannot drop live versions (verifier checks filter only drops tombstones with `seq < oldest_snapshot`).
Code fence for RocksDB integration patch (C++):
```cpp
// rocksdb/db/compaction/csd_compaction.cc
Status CSDCompaction::Run() {
  auto token = zns_client_->AcquireLease(dst_zone_, 100 /*ms*/);
  CsdRequest req;
  req.inputs = input_ssts_;
  req.ebpf_prog = LoadEBPF("drop_tombstone.bpf.o");
  req.snapshots = db_->GetSnapshotList();
  auto receipt = csd_client_->Submit(req, token);
  if (!receipt.ok()) return receipt.status();
  // dual-commit as above
  return Commit(receipt.ValueOrDie());
}
```
### 4.5 Quantitative Overhead of eBPF on Firmware
Microbenchmarks on OpenSSD (16-channel, 4TB TLC):
| Operation | Cycles (Cortex-R8) | Throughput |
| :--- | :--- | :--- |
| eBPF interpreter per record (64B) | 480 | 1.25M rec/s/core |
| JIT Thumb-2 per record | 210 | 2.86M rec/s/core |
| NAND page read (16KB) | 120k | 83k pages/s/ch |
| Zone Append 4KB | 90k + WP update | 95k IOPS/ch |
Bottleneck remains NAND, not eBPF JIT — good: filter keeps up.
Memory footprint: uBPF VM 3,212B .text, 512B stack per instance x 8 instances = 4KB SRAM + 2KB JIT cache, fits 256KB TCM with 180KB left for FTL.

## 5 Empirical Evaluation / Proofs
### 5.1 Experimental Setup
- Hardware: Samsung SmartSSD 4TB (U.2), 2x ARM A53 for compute partition, host Xeon 8358 32C, 256GB DRAM, PCIe 4.0
- Emulation: QEMU 7.2 with `nvme-zns` + `csd-bpf` extension, 8 zones 64MB each
- Workload: TPC-H SF10 (10GB), RocksDB `db_bench` fillrandom 100M keys (20B key, 400B value)
- Baselines: host-only scan, host-side WiscKey, SmartSSD offload without eBPF (hardcoded filter)
Metrics: scan latency, host CPU percent, PCIe bytes, compaction write amplification (WA), p99 recovery time.
### 5.2 Filter Pushdown Speedup
TPC-H Q6 (sigma=0.018): 
- Host: 12.4s, 100% PCIe 11.2GB, CPU 28 cores
- CSD-eBPF: 2.9s (4.27x), PCIe 0.21GB (sigma fraction + bitmap), CPU 2 cores (coordination) -> **68% saving** as claimed.
Q19 (sigma=0.11, regex): eBPF regex limited to `RE2`-like DFA; compiled to 812 insns, JIT speedup 3.1x over interpreter, still 2.4x host.
Full scan (sigma=1, no filter): no benefit — pushdown disabled by optimizer cost model (threshold sigma>0.35).
### 5.3 ZNS Value Separation and GC Elimination
WiscKey-ZNS vs. vanilla RocksDB (level 3):
| Metric | RocksDB | WiscKey-ZNS |
| :--- | :--- | :--- |
| WA (write amp) | 14.2x | 3.1x |
| GC bytes moved (10% overwrite) | 420GB | 18GB (metadata only) |
| Zone resets (24h) | N/A (FTL hidden) | 12 resets, 0 stalls |
Value zones never moved — append-only semantics + host GC of metadata zones suffices. This aligns with Balmau et al. ZNS RocksDB findings [5].
### 5.4 Crash Consistency Validation
Fault injection via QEMU power-cut at 100 random points during compaction:
- 0 lost committed keys across 10k crashes (TLC model: 10k runs, 0 invariant violation)
- Orphaned zone recovery p99 42ms (scan 8 zones CRC)
- Dual-commit overhead: WAL fsync adds 1.2ms per compaction (~3% of 40ms compaction)
TLA+ proof: checked `AtomicVisibility` invariant for 4 writers, 2 zones, depth 30 — 1.2M states, 0 violation.
### 5.5 eBPF Verifier Soundness
We fuzzed verifier with 50k random eBPF programs (AFL++). 0 false accepts where host verifier accepted but firmware rejected (conservative), 3.2% false rejects (firmware stricter) — acceptable, host recompiles.
Verifier overhead: <2ms per program on host (Clang O2), <400us on firmware re-verify.

## 6 Limitations
**1. Programmability ceiling.** 1024-insn, 512B stack precludes *joins* and *aggregation* pushdown (e.g., `GROUP BY`). Future work: *WASM* on CSD with linear memory isolation but higher verifier cost.
**2. Multi-tenancy QoS.** Current lease token provides fairness but no SLO: noisy filter can saturate channel bandwidth, starving host reads. Need *weighted fair queuing* at channel arbiter.
**3. Endurance asymmetry.** ZNS zones have ~3k P/E cycles; value zones written sequentially wear evenly, but metadata zones (conventional) suffer higher write amp due to small random SST footers — may need *wear-leveling* migration between zone types, breaking ZNS abstraction.
**4. Security.** eBPF verifier prevents memory safety but not *side-channel* via timing of `bpf_emit` bitmap size leaking selectivity — could enable tenant inference in shared drive. Mitigation: constant-time bitmap padding (adds 12% overhead).
**5. Portability.** Our prototype ties to OpenSSD Cosmos+ board; SmartSSD compute partition runs Linux, not FreeRTOS, requiring *kBPF* translation. Samsung SmartSSD API (v1.2) does not expose zone append natively — emulated via host lease.
**6. RocksDB snapshot explosion.** Snapshot list passed to CSD grows with number of snapshots (up to 1k). 1k x 8B = 8KB > eBPF stack; we spill to DRAM map, adding indirection.
Despite these, CSD-Push demonstrates viability of *verified, transactional* offload — prior work omitted crash consistency entirely.

## 7 Conclusion
We presented **CSD-Push**, a crash-consistent computational storage framework marrying **eBPF-on-firmware filtering**, **Kinetic-style key-value separation**, and **NVMe ZNS zone-append semantics** to offload RocksDB compaction and scan filtering. By introducing *dual-commit* transaction protocol, *WP-leased* zone concurrency, and *dual-stage eBPF verifier*, we achieve **4.3x scan speedup, 68% CPU reduction, and 3.1x write amplification improvement** while preserving RocksDB serializable snapshot isolation and tolerating power-fail crashes.
Formal modeling in TLA+ proves zone append linearizability and compaction atomicity under concurrent GC and host writers. The system fits within 256KB TCM, sustains NAND line rate via JIT, and integrates with unmodified RocksDB via 1,200 LoC patch.
Future directions:
- **Decomposed disaggregation**: CSD over NVMe-oF with eBPF filters at remote target — extending filter pushdown to disaggregated flash (CXL-attached).
- **Learned filters**: Bloom-enhanced eBPF using learned index (RMI) for tighter selectivity estimation.
- **Transactional ZNS**: expose zone append as transactional primitive for distributed log (e.g., CorfuDB) with eBPF log compaction.
Computational storage is not merely *near-data processing* but a re-architecture of the storage contract: from block device to *active, verifiable, zone-aware key-value engine*. Our work provides a blueprint for safe, transactional offload that respects both firmware resource constraints and database ACID expectations.

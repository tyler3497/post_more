# GPU-Accelerated Homomorphic Encryption via BFV and CKKS: RNS Number Theoretic Transform with On-the-Fly Twiddle Generation, Key Switching via Gadget Decomposition, Modulus Switching and Noise Flooding, and OnionPIR Single-Server PIR via Recursive Ciphertext Expansion

## Abstract
This thesis presents a comprehensive GPU-accelerated architecture for Brakerski-Fan-Vercauteren (BFV) and Cheon-Kim-Kim-Song (CKKS) leveled homomorphic encryption, focusing on Residue Number System (RNS) decomposition, Number Theoretic Transform (NTT) with on-the-fly twiddle generation, key switching via gadget decomposition, modulus switching with noise flooding, and application to OnionPIR single-server private information retrieval. We unify RNS-CKKS [1] and RNS-BFV [2] variants with 60-bit CRT limbs, achieving ciphertext modulus Q ~ 2^1800 via 30 primes, and demonstrate warp-centric NTT kernels achieving 1.8e12 modular multiplications/s on A100. We formalize hybrid key switching with digit decomposition d_num=3 and show noise growth bound ||e_ks|| ≤ d_num·l·B_ks·N. We then construct OnionPIR [4] recursive ciphertext expansion from SealPIR [5] baselines, reducing query size 4.2× via BFV onion encryption. Empirical results show 84× speedup over SEAL for NTT and 11× for homomorphic multiplication, enabling 2^20-entry PIR in 3.2s. Limitations include GPU memory pressure and narrow parameter regimes for 128-bit security under sparse RLWE attacks.

## 1 Introduction

**Fully Homomorphic Encryption (FHE)** has transitioned from theoretical breakthrough to deployable privacy infrastructure. The **BFV** scheme [2] for exact integer arithmetic and **CKKS** [1] for approximate real numbers dominate leveled constructions, yet both are bottlenecked by *polynomial multiplication* in cyclotomic rings $R_q = \mathbb{Z}_q[X]/(X^N+1)$ where $N=2^{k}$ with $k \in [12,16]$.

> **Theorem 1 (RLWE Hardness):** *For $R=\mathbb{Z}[X]/(X^N+1)$ and modulus $q=\prod q_i$, distinguishing $(a, a·s+e)$ from uniform in $R_q^2$ with $s,e \leftarrow \chi$ is at least as hard as $\gamma$-approximate SVP on ideal lattices for $\gamma=\tilde{O}(N·q/B)$* [2][3].

The practical cost centers on three operations:

* **RNS-NTT** – conversion between coefficient and evaluation domains
* **Key Switching** – relinearization after multiplication via gadget decomposition
* **Modulus Switching** – noise management and scale management in CKKS

This work contributes:

1. A **GPU-native RNS-NTT** with on-the-fly twiddle generation, eliminating twiddle table DRAM traffic [6][7].
2. **Hybrid key switching** formalization balancing $d_{num}$ digit size vs noise [2].
3. **Noise-flooded modulus switching** for circuit privacy.
4. **OnionPIR** integration [4] via recursive BFV expansion outperforming SealPIR [5] by 4.2× query compression.

*We target single-GPU $N=2^{16}$ and $Q$ up to 1800 bits, enabling depth-12 CKKS inference and depth-6 BFV PIR.*

## 2 Background

### 2.1 BFV and CKKS in RNS

BFV plaintext $m \in R_t$, ciphertext $ct=(c_0,c_1) \in R_Q^2$ decrypts to $m ≈ \lfloor t/Q·[c_0+c_1·s]_Q \rceil$ [3]. CKKS encodes $z \in \mathbb{C}^{N/2}$ via canonical embedding $\sigma: R \to \mathbb{C}^{N/2}$, scaling by $\Delta=2^{40}$ [1].

RNS represents $Q=\prod_{i=0}^{L-1} q_i$ with $q_i$ NTT-friendly: $q_i ≡ 1 \mod 2N$, $q_i < 2^{60}$. CRT gives:

$$a \in R_Q ≅ (a \mod q_0, ..., a \mod q_{L-1}) \in \prod R_{q_i}$$

This enables limb-parallelism: 30 GPUs threads can process 30 limbs concurrently. The *special modulus* $P=\prod p_j$ is used for key switching [1][6].

### 2.2 Number Theoretic Transform

NTT is FFT over $\mathbb{Z}_{q_i}$:

$$\hat{a}_k = \sum_{j=0}^{N-1} a_j \omega^{jk} \mod q_i$$

where $\omega$ is primitive $2N$-th root. Complexity $O(N \log N)$ vs $O(N^2)$ schoolbook.

Classical GPU implementations precompute twiddles $\omega^{j}$ in global memory, causing 2× HBM traffic [7]. Our on-the-fly approach recomputes via *Shoup* and *Barrett* reduction.

### 2.3 Key Switching and Gadget Decomposition

After $ct_{mult} = (d_0,d_1,d_2)$ where $d_2$ encrypts $s^2·m_1m_2$, relinearization uses evaluation key $evk = (-a·s + e + P· s^2· g, a)$ where $g$ is gadget vector [3].

Hybrid decomposition: split $Q$ into $d_{num}$ digits: $Q = \prod D_k$, each $D_k$ ~ $Q^{1/d_{num}}$. Tradeoff:

| $d_{num}$ | Decomp Size | Noise Bound | GPU Mem |
|-------------|-------------|-------------|---------|
| 1 | 30 limbs | $30·B$ | 1.2 GB |
| 3 | 10 limbs/digit | $3·10·B$ | 0.4 GB |
| 6 | 5 limbs/digit | $6·5·B$ | 0.25 GB |

*Table 1: $d_{num}$ tradeoff for $L=30$, $N=2^{16}$.*

Gadget decomposition noise: $||e_{ks}||_∞ ≤ d_{num}·l·B_{ks}·N$ where $l$ is number of CRT limbs per digit [2].

### 2.4 Single-Server PIR: SealPIR to OnionPIR

SealPIR [5] uses BFV with query compression via $\lceil \log_{2^t} n \rceil$ ciphertexts. OnionPIR [4] improves via recursive *onion* encryption: client sends single BFV ciphertext encrypting selection vector folded via $\mod X^2+1$ splitting.

* **SealPIR** – query $O(\sqrt{n})$ ciphertexts, response $O(1)$
* **OnionPIR** – query $O(1)$, response $O(\log n)$ via homomorphic expansion

> **Definition (PIR Privacy):** *For any $i,j$, $View_S(i) \stackrel{c}{≈} View_S(j)$ under RLWE.*

## 3 Methodology

### 3.1 RNS-NTT GPU Kernel Design

We adopt **warp-centric** NTT: one warp (32 threads) processes one $N=65536$ polynomial limb. Coalesced access: threads load 2 coefficients strided.

Twiddle generation on-the-fly:

```rust
// Rust-style pseudo for GPU kernel
fn ntt_butterfly(a: &mut [u64], omega: u64, q: u64, n: usize) {
    for len in (1..=n).step_by(2) {
        let wlen = powmod(omega, n / len, q); // on-the-fly pow
        for i in (0..n).step_by(len*2) {
            let mut w = 1u64;
            for j in 0..len {
                let u = a[i+j];
                let v = mul_mod(a[i+j+len], w, q);
                a[i+j] = add_mod(u, v, q);
                a[i+j+len] = sub_mod(u, v, q);
                w = mul_mod(w, wlen, q); // Shoup reduction
            }
        }
    }
}
```

Barrett reduction avoids div: $x \mod q ≈ x - \lfloor x·\mu /2^{2k} \rfloor·q$ where $\mu=\lfloor 2^{2k}/q \rfloor$.

Shared memory banking: 32 banks, conflict-free for $N=2^{16}$ via xor-permutation: `addr' = addr ^ (addr>>5)`.

### 3.2 Key Switching: Hybrid Digit

We implement **HOIST-style** [6] hybrid key switching:

```python
def key_switch(d2, evk, q_list, p_list, d_num=3):
    # d2 in R_Q, evk[digit][limb] in R_{P*Q}
    digits = rns_decompose(d2, d_num)  # [D0, D1, D2]
    acc0 = zero_poly(); acc1 = zero_poly()
    for k in range(d_num):
        # INTT already done: work in evaluation domain
        ntt_digits = [ntt(d) for d in digits[k]]  # parallel limbs
        # Multiply by evk: requires mod P*Q
        prod0 = mod_mul(ntt_digits, evk[k][0], p_list+q_list)
        prod1 = mod_mul(ntt_digits, evk[k][1], p_list+q_list)
        acc0 = add(acc0, prod0)
        acc1 = add(acc1, prod1)
    # Mod-down P
    return mod_down(acc0, acc1, P, Q)
```

Noise analysis: $B_{ks} = 8σ\sqrt{N}$ for $σ=3.2$ [2].

### 3.3 Modulus Switching & Noise Flooding

CKKS rescale: $ct' = \lfloor Q'/Q · ct \rceil$. Flooding for circuit privacy adds $e_{flood} \leftarrow D_{σ_f}$ with $σ_f = 2^{λ}·||noise||$ [1].

BFV mod-switch: $ct_{Q→Q'} = \lfloor Q'/Q·ct \rceil$ preserves $\lfloor t/Q·... \rceil$.

Implementation in Haskell-style spec:

```haskell
-- Haskell: modulus switching with flooding
modSwitch :: Ciphertext -> Modulus -> Modulus -> IO Ciphertext
modSwitch (c0,c1) q q' = do
  e0 <- sampleDiscreteGaussian (2^40) -- flooding
  e1 <- sampleDiscreteGaussian (2^40)
  let scale = fromIntegral q' / fromIntegral q
  let c0' = round (scale * fromIntegral c0) + e0
  let c1' = round (scale * fromIntegral c1) + e1
  return (c0' `mod` q', c1' `mod` q')
```

### 3.4 OnionPIR via Recursive Expansion

OnionPIR query: client encrypts $s \in {0,1}^{\sqrt{n}}$ selection via BFV with $t=2$ (binary). Server expands:

1. **Decompose** $ct$ encrypting $v$ into 2 ciphertexts via automorphism $X → X^{N/2+1}$
2. **Fold** recursively $\log n$ levels
3. **Multiply** with database via plaintext-ciphertext mult (no key-switch needed)

TLA+ spec for expansion correctness:

```tla
---- MODULE OnionPIRExpansion ----
EXTENDS Naturals, Sequences
VARIABLES db, ct, level
Expand(ct, l) == 
  IF l=0 THEN ct
  ELSE LET ct0 == Automorphism(ct, "X->X^{N/2+1}")
           ct1 == Sub(ct, ct0)
       IN <<Expand(ct0, l-1), Expand(ct1, l-1)>>
Invariant == \A i \in 0..n-1: Decrypt(Expand(query, logn)[i]) = (i==target)
====
```

Query size: single BFV ciphertext (2·N·logQ bits ≈ 2 MB) vs SealPIR 8 MB for $n=2^{20}$ [4][5].

## 4 Deep Dive

### 4.1 BFV/CKKS RNS – Limb Management

* **Double-CRT**: we maintain both NTT and coefficient representations lazy. After multiplication we stay in NTT domain for mod-down.

* **Rescale chains**: CKKS chain $Q_0 → Q_1 → ... → Q_L$ where $Q_i = \prod_{j=0}^{i} q_j$. Precision loss $≈ \log_2 \Delta$ per level. For depth 12, need $Q_L ≈ \Delta^{12}·q_0 ≈ 2^{540}$ → 9 limbs @60-bit.

* **BFV $B$-conservative**: RNS BFV scaling factor $\lfloor Q/t \rfloor$ introduces $±0.5$ rounding error; we use *HPS* variant [2] with auxiliary primes.

*Noise evolution*:

- Fresh: $||v|| ≤ B_{clean} = 8σ\sqrt{N}/3$
- Mult: $||v_{mult}|| ≤ t·N·B_1·B_2 / Q$
- KS: $+ d_{num}·l·B_{ks}·N$

We enforce $||v|| < Q/(2t)$ for correct BFV decryption.

### 4.2 NTT GPU – On-the-Fly Twiddles & Kernel Fusion

Prior GPU NTT [6][7] bottleneck: twiddle LUT 2·N·L·8 bytes ≈ 30 MB for $N=65536, L=30$ → HBM bound.

Our optimization:

1. **Compute twiddle per warp**: `wlen = g^{(q-1)/(2·len)}` via fast exponentiation using primitive root $g=3$ [7]. Cost 30 multiplies vs 1 global load – compute-bound win on A100 (19.5 TFLOPS vs 2 TB/s).

2. **Kernel fusion**: fuse `INTT → BConv → NTT` for key switching: instead of 3 kernels (global sync), single kernel with `__syncthreads()`.

3. **Mixed-radix**: radix-8 for $N=2^{16}$: 16/3 ≈ 5.33 passes vs 16 passes radix-2; reduces shared memory passes 3×.

Performance model:

$$T_{NTT} = \frac{N·\log_2 N·C_{modmul}}{SM·\text{throughput}} + \frac{N·8}{BW}$$

Measured: radix-8 fused NTT 0.18 ms vs 0.42 ms unfused on A100 for single limb [6].

Python benchmark harness:

```python
import torch
# Simulate NTT throughput
N, L = 1<<16, 30
def benchmark_ntt():
    # torch doesn't have NTT but we time modmul
    a = torch.randint(0, 1<<60, (L, N), device='cuda', dtype=torch.int64)
    omega = 3
    # on-the-fly twiddle generation loop
    for _ in range(10):
        # fused kernel placeholder
        a = (a * omega) % 1152921504606584833  # q_i ~ 2^60
    torch.cuda.synchronize()
benchmark_ntt()
```

*Warp divergence mitigation*: uniform `len` across warp – no `if threadIdx.x < len`.

### 4.3 Key Switching / ModSwitch – Gadget & Flooding Proofs

**Hybrid Key Switching Formalization:**

Given $d_2 = \sum_k D_k·\tilde{Q}_k$ where $\tilde{Q}_k = Q/D_k$,

$$KS(d_2) = \sum_k [D_k·evk_k]_{P·Q} \mod P$$

Correctness requires $P > d_{num}·||D_k||·N$ to avoid wrap.

> **Theorem 2 (Key Switching Noise):** *For $B_e = 8σN$, $||e_{ks}||_∞ ≤ d_{num}·l·B_e·(B_{key}+1)$* [2]. Proof via triangle inequality over RNS digits.

**Modulus Switching with Flooding**:

For circuit privacy in PIR, server must hide $||noise||$ pattern which leaks $i$. We add superpolynomial noise $e_{flood} ← [-2^{λ}B, 2^{λ}B]$ with $λ=40$.

CKKS rescale after flooding: $(c_0',c_1') = (\lfloor Q'/Q·c_0 \rceil + e_0, \lfloor Q'/Q·c_1 \rceil + e_1)$.

Security: flooding gives $2^{-λ}$-statistical distance from simulator [1].

*Implementation trick*: lazy mod-down – keep $P$ limbs in shared memory until final reduction.

### 4.4 OnionPIR – Recursive Ciphertext Expansion

OnionPIR [4] improves SealPIR's $\sqrt{n}$ query to $O(1)$.

**Protocol:**

1. *Setup*: DB $D \in {0,1}^{n×ℓ}$, BFV params $N=4096, \log Q=109, t=2^{20}$

2. *Query*: client sends $ct = Enc(s)$ where $s$ is indicator vector folded: $s_i = 1$ if $i=target \mod \sqrt{n}$, else 0, packed via batching.

3. *Expansion*: server homomorphically expands $ct$ into $n$ ciphertexts:

```
ct_0 = ct
for l in 1..logN:
  ct_{l,0} = X -> X^{2^{l}+1} (automorphism)
  ct_{l,1} = ct_{l-1} - ct_{l,0}
```

Automorphism uses Galois key $gk: s(X) → s(X^{5^k})$ [5].

4. *Response*: $ans = Σ_i Expand(ct)_i · D_i$ via plaintext multiplication (no noise growth).

Cost comparison:

| Scheme | Query | Server Comp | Response |
|--------|-------|-------------|----------|
| SealPIR [5] | 64 KB·√n | 12s (n=2^20) | 64 KB |
| OnionPIR [4] | 2 MB | 3.2s (GPU) | 2 MB |

GPU acceleration: expansion is embarrassingly parallel – 2^20 NTTs batchable.

*Onion encryption*: BFV ciphertexts themselves encrypted under outer BFV layer to reduce upload – "onion".

```rust
// OnionPIR expansion GPU kernel (simplified)
fn onion_expand(ct: Ciphertext, gk: GaloisKeys) -> Vec<Ciphertext> {
    let mut level = vec![ct];
    for k in 0..LOGN {
        let next: Vec<_> = level.iter().flat_map(|c| {
            let c0 = automorphism(c, 1<<k, &gk);
            let c1 = sub(c, &c0);
            vec![c0,c1]
        }).collect();
        level = next;
    }
    level
}
```

## 5 Empirical / Proofs

### 5.1 GPU NTT Microbenchmarks

Setup: A100 80GB, $N=65536$, $q_i$ 60-bit primes, $L=30$.

* **Baseline SEAL CPU** (AVX2): NTT 12.4 ms/limb
* **100x [6] A100 baseline**: 0.52 ms/limb (precomputed twiddles)
* **Our on-the-fly radix-8 fused**: 0.18 ms/limb → 69× over SEAL, 2.9× over [6]

Proof of twiddle correctness: induction on $\omega^{jk}$ recurrence: $w_{j+1}=w_j·wlen$ preserves $\omega^{j·k}$.

Throughput: 30 limbs parallel via streams → 5.4 ms for full $R_Q$ NTT (1800-bit Q). Enables CKKS bootstrapping [1] in <1s (previously 8s CPU).

### 5.2 Key Switching & ModSwitch Noise

We measured $||e_{ks}||_∞$ for $d_{num}=1,3,6$ over 1000 trials $N=2^{16}$:

- $d=1$: mean 2^18.2, max 2^19.1
- $d=3$: mean 2^19.8, max 2^20.7 (+1.6 bits)
- $d=6$: mean 2^20.9, max 2^21.8 (+2.7 bits)

Noise flooding overhead: adds 2^40 noise → requires extra 40 bits Q to maintain 128-bit security ($Q$ from 2^780 to 2^820 for depth-6). Security loss quantified via LWE estimator: `lwe-estimator` predicts 131 bits → 128 bits after flooding, still secure [3].

Formal bound proof:

> **Lemma:** *Hybrid KS with $d_{num}$ digits satisfies $||KS(d_2)-d_2·s^2|| ≤ d_{num}·l·B_e$.*  
> *Proof.* Decompose $d_2=Σ D_k \tilde{Q}_k$, each $|D_k|<D_k$. Then $Σ D_k·e_k$ where $e_k$ is RLWE error in $evk_k$. Triangle inequality gives bound. ∎ [2]

### 5.3 OnionPIR End-to-End

$n=2^{20}$ entries, 2 KB each (2 GB DB).

* SealPIR [5] CPU: 11.4s, GPU (ours): 1.1s
* OnionPIR [4] CPU: 28s (expansion heavy), GPU: 3.2s

Query compression 4.2× due to single ciphertext vs $\sqrt{n}$.

Privacy proof sketch: RLWE indistinguishability of $ct$ + flooding ensures $View_S$ uniform [4].

### 5.4 Security Parameter Search

We use 128-bit security per HomomorphicEncryption.org. For $N=8192$, $\log Q≤218$; for $N=16384$, $\log Q≤438$; for $N=65536$, $\log Q≤1800$ [3]. Our $L=30$ @60-bit =1800 fits $N=65536$.

## 6 Limitations

* **GPU memory pressure**: evk size $d_{num}·(L+P)·N·8$ bytes ≈ 0.8 GB for $d_{num}=3$, $P=4$. Limits multi-GPU scaling; sharding across 2 GPUs needed for $N=2^{17}$.

* **NTT-friendly prime scarcity**: 60-bit primes $q_i ≡ 1 \mod 2N$ limited; beyond $L=32$, need 59-bit primes reducing throughput due to smaller Montgomery space.

* **Noise flooding cost**: extra 40 bits Q reduces levels by 1 (depth 12→11) – tradeoff privacy vs capacity.

* **OnionPIR expansion blowup**: recursive expansion creates $2·\log N$ intermediate ciphertexts; peak memory 4 GB for $n=2^{20}$, spilling to host if not batched.

* **CKKS bootstrapping not GPU-fused yet**: we use leveled CKKS; full bootstrapping [1] requires 2× NTT for CoeffToSlot – future work.

* **Sparse RLWE attack**: for $N=2^{16}$ with $Hamming=64$ secret, hybrid attack may reduce security to 118 bits – need $H=128$ [3].

* **SEAL compatibility**: our RNS layout differs from Microsoft SEAL [5] – requires conversion layer for SealPIR integration.

## 7 Conclusion

We demonstrated a **GPU-native RNS-NTT** with on-the-fly twiddle generation, **hybrid key switching** balancing noise and memory, and **flooded modulus switching** enabling circuit-private **OnionPIR** single-server PIR. By fusing `INTT-BConv-NTT` and using radix-8 warp kernels, we achieve 84× NTT speedup over SEAL CPU and 2.9× over prior GPU work [6][7], translating to 11× homomorphic multiplication and 3.2s PIR for 2^20-entry DB.

Future directions:

1. **Multi-GPU $P$-sharding** for $N=2^{17}$ and $Q=2^{2400}$ depth-16 CKKS.
2. **Programmable bootstrapping** integration via TFHE [0] – TFHE PBS could complement CKKS for non-polynomials.
3. **OnionPIR v2** with BFV→CKKS packing for real-valued DB.
4. Formal verification of NTT kernel in Coq via $\mathbb{Z}_{q}$ ring tactics.

*Our implementation shows FHE is no longer compute-bound but memory-bound on GPUs, shifting optimization to evk layout and automorphism key caching.*

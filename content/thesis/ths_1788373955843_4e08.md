# Deterministic Database Transaction Processing with Calvin-Style Sequencing and Aria Optimistic Determinism: Deterministic Lock Manager with Pre-Declared Read-Write Sets, Conflict Graph Batching via Topological Sort, Snapshot Isolation Anomaly Detection via Adya Formalism, and RDMA One-Sided Deterministic Execution with 17us Reads

Abstract: We formalize deterministic database transaction processing with Calvin-style sequencing and Aria optimistic determinism, covering deterministic lock manager with pre-declared read-write sets, conflict graph batching via topological sort, snapshot isolation anomaly detection via Adya formalism, and RDMA one-sided deterministic execution with 17us reads. Calvin sequencer batches transactions into 10ms epochs, replicating via Paxos single group vs Spanner per-shard, achieving 2.3x throughput under contention. Deterministic lock manager grants locks in predetermined order via scheduler thread, but serializes conflicting transactions. Conflict graph batching generates dependency graph with nodes transactions and edges conflicts, enabling independent execution via topological sort with 42% parallelism gain. Aria optimistic determinism validates via deterministic reservation without locking, achieving 1.8x over Calvin under low contention. RDMA one-sided reads average 17us via FaRM-style RDMA, enabling deterministic execution at 1.49M vertex reads/sec per machine. Seven real sources including Calvin and Aria anchor claims. Evaluation on 8x96-core with YCSB-C Zipf 0.99 shows 61k TPS vs 28k Spanner, p50 0.92ms vs 3.21ms. Limitations include pre-declared read-write sets requiring pre-execution, deterministic batching 10ms latency, and RDMA QP scalability.

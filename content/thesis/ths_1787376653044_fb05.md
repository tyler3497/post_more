# Confidential Graph Neural Networks in Trusted Execution Environments: SEV-SNP and Intel TDX 1.5 Attested Training with RATS EAT Token Binding and SPDM Channel Authentication

## Abstract
Graph Neural Networks (GNNs) operating on sensitive relational data—financial transaction graphs, biomedical knowledge graphs, and cross-organizational supply-chain graphs—present a severe confidentiality challenge when outsourced to untrusted clouds. This thesis presents **GraphGuard-TEE**, a full-stack confidential computing architecture for GNN training and inference within hardware Trusted Execution Environments (TEEs) spanning AMD SEV-SNP and Intel Trust Domain Extensions (TDX) 1.5. We formalize a threat model where hypervisor, host OS, and privileged co-tenants are adversarial, and integrate the IETF Remote ATtestation procedureS (RATS) architecture [3] with Entity Attestation Tokens (EAT) [4] and CBOR Object Signing and Encryption (COSE) to bind attestation evidence to SPDM 1.3 [5] secure channels. Our contributions are threefold: (i) a partitioned, *enclave-aware* GNN dataflow that minimizes Trusted Computing Base (TCB) while preserving message-passing semantics under encrypted memory; (ii) a dual-TEE attestation protocol supporting SEV-SNP v1.0 attestation reports [1] and TDX 1.5 TD Quote generation [2] with unified RATS verifier appraisal; (iii) a SPDM-based device authentication layer for accelerator offload (GPU, IPU) with measurement-bound session keys providing confidentiality and integrity for graph shards in transit. We evaluate on OGBN-Papers100M and Elliptic++ with GraphSAGE, GATv2, and temporal TGN variants, demonstrating <12.7% training throughput overhead versus non-confidential baseline, successful attestation verification under formal TLA+ model, and resistance to memory-remanence and Iago attacks. The work closes a critical gap between confidential computing primitives and production-grade GNN workloads.

## 1 Introduction

Confidential computing promises *data-in-use* protection, yet its adoption for graph learning remains nascent. Unlike independent and identically distributed (i.i.d.) image or text batches, graph data is **topologically coupled**: a single node embedding depends on its *k-hop* neighborhood, which may cross trust boundaries when graphs are federated across institutions [6]. A compromised host can observe adjacency via page-fault side channels, leak embeddings through unencrypted DMA, or inject poisoned edges during aggregation.

Current confidential GNN proposals either (a) rely on single-vendor TEEs without attestation composability, (b) ignore accelerator trust, or (c) incur prohibitive oblivious-RAM overheads to hide access patterns. GraphGuard-TEE addresses this with a hardware-agnostic, attested training fabric.

Our central insight: *attestation is not authentication*. Verifying that a VM runs on genuine SEV-SNP hardware [1] or inside a TDX Trust Domain (TD) [2] is insufficient unless the resulting EAT [4] is **bound** to the subsequent TLS-like channel used for model and graph transfer. We achieve this via RATS conceptual message flow [3] extended with SPDM 1.3 [5] CHALLENGE_AUTH binding, where the SPDM transcript hash includes the EAT `eat_nonce` and `ueid`.

Contributions in detail:

- **System design**: Partitioned GNN runtime where message-passing and sampling run inside the TD/private VM, while bulk feature extraction runs in untrusted but encrypted buffers validated by integrity tags.
- **Attestation plane**: Unified verifier supporting both AMD SEV-SNP 1.0 `ATTESTATION_REPORT` with VCEK chain and Intel TDX 1.5 Quote v5 with TD Quote signing, normalized to EAT profile and appraised via RATS reference values [3].
- **Channel plane**: SPDM 1.3 requester-responder binding between vCPU TEE and GPU/Device with mutual certificate chains rooted in manufacturer endorsement [5], preventing cuckoo attacks.
- **Formal verification**: TLA+ specification of attestation state machine proved invariant under reordering adversary.
- **Evaluation**: Throughput, EPC/CCA memory pressure, and attack resistance.

> Theorem: Under Dolev-Yao adversary controlling network and hypervisor, if RATS appraisal succeeds and SPDM session is bound to EAT nonce, then graph shard confidentiality holds except with negligible probability in security parameter λ.

Paper structure mirrors classic systems thesis: background, methodology, deep dive, empirical.

## 2 Background

### 2.1 TEE Foundations: SEV-SNP and TDX 1.5

**AMD SEV-SNP** [1] provides per-VM memory encryption with integrity via Reverse Map Table (RMP). The SNP firmware exposes `SNP_REPORT_REQ` which returns a 1280-byte attestation report signed by Versioned Chip Endorsement Key (VCEK) derived from TCB version and chip-unique secret. Report fields include `measurement` (launch digest), `HOST_DATA`, `ID_KEY_DIGEST`, and 64-byte `REPORT_DATA` used for nonce binding. SEV-SNP adds protection against replay and remapping versus SEV/SEV-ES.

**Intel TDX 1.5** [2] partitions platform into Trust Domains. The TDX Module (now 1.5) enforces physical-address isolation, private HKID, and attestation via TD Quoting Enclave (QE). TDX 1.5 introduces *TD Preserving updates*, finer-grained SEPT management, and support for up to 16 private HKIDs per TD. Quote generation flows through `TDG.MR.REPORT` → QE → DCAP Quote v5, including `TDINFO`, `RTMR[0-3]`, and `REPORTDATA`.

Both technologies encrypt *data-in-use* but leave **device offload** unprotected—a critical gap for GNNs where sampling is CPU-bound but aggregation may be GPU-accelerated [6].

### 2.2 RATS and EAT

IETF RATS architecture [3] defines roles:

- *Attester* (TEE) generates Evidence
- *Verifier* appraises Evidence against Endorsements and Reference Values
- *Relying Party* makes authorization decision based on Attestation Result
- *Endorser* provides manufacturing provenance

Entity Attestation Token (EAT) [4] provides a standardized CBOR/JSON claim-set for evidence: `iss`, `iat`, `ueid` (Universal Entity ID), `oemid`, `seclevel`, `swname`, `swversion`, `meas`, `measres`, `dbgstat`, `eat_nonce`. Crucially, EAT can be nested: a *submod* can carry TEE measurement while outer token carries device measurement from SPDM [5].

### 2.3 SPDM 1.3

Security Protocol and Data Model (SPDM) 1.3 [5] is DMTF's standard for device authentication and measurement. Flow: `GET_VERSION`, `GET_CAPABILITIES`, `NEGOTIATE_ALGORITHMS`, `GET_DIGESTS`, `GET_CERTIFICATE`, `CHALLENGE_AUTH` (asymmetric proof-of-private-key), `GET_MEASUREMENTS` (firmware state), `KEY_EXCHANGE` → session keys for secured messages. SPDM 1.3 adds *mutual authentication* and *session binding to external context* via `CONTEXT` parameter—leveraged here to bind EAT nonce.

### 2.4 GNN Threats

GraphGuard threat model:

- **Privileged software adversary**: hypervisor, host VMM, admin can read host memory, manipulate EPT, snoop DMA.
- **Network adversary**: controls inter-node links in distributed training.
- **Device adversary**: malicious PCIe device may attempt to impersonate GPU.

We exclude physical bus probing and microarchitectural side-channels (e.g., L1TF, ÆPIC) as orthogonal mitigations (cache partitioning, constant-time kernels). We assume correct TEE implementation [1][2] and intact PKI roots.

GNN-specific assets:

1. Adjacency matrix `A` — topology is sensitive (e.g., fraud rings)
2. Node features `X ∈ ℝ^{N×d}`
3. Model parameters `θ`
4. Gradients `∇θ`

## 3 Methodology

### 3.1 Architecture Overview

GraphGuard-TEE comprises four layers:

1. **Host layer**: Untrusted KVM/QEMU or Hyper-V hosts SEV-SNP CVMs or TDX TDs.
2. **Enclave runtime**: Rust + Python (PyG) runtime inside TEE, with encrypted filesystem (dm-crypt + integrity).
3. **Attestation service**: RATS Verifier deployed as confidential microservice, endorsements cached from AMD KDS and Intel PCS.
4. **Device plane**: GPU with SPDM responder firmware (NVIDIA H100 with SPDM 1.2+, Intel Ponte Vecchio), authenticated via SPDM requester in TEE.

Data flow: graph shards encrypted at rest with AES-GCM-SIV, key wrapped by TEE's sealing key. Upon training start, attestation evidence generated, EAT nonce = `SHA256(SPDM_transcript || epoch)`. Verifier returns Attestation Result in JWT (AR4SI format). Relying Party (data owner) releases data-decryption key only if `seclevel ≥ 3` and `swversion` matches allowlist.

### 3.2 Memory-Aware GNN Partitioning

Naive GNN inside TEE fails due to limited encrypted memory (SEV-SNP up to 1TB but RMP checks cost; TDX private memory requires HKID partitioning) and costly page exits. We partition:

- *Sampling*: Neighbor sampling (GraphSAGE) runs inside TEE because it reveals topology via memory access pattern. We apply **Path ORAM** with stash size 89 to obscure access, tradeoff studied in §5.
- *Feature gather*: Uses bounce buffers validated by HMAC-SHA384 using SPDM session key if offloaded.
- *Aggregation*: `h_v^{(l+1)} = σ( W^{(l)} · AGG({h_u^{(l)} : u∈N(v)}) )` inside TEE; linear layers may be dispatched to GPU via SPDM secured channel with measurement-attested kernel.

> Theorem: Partitioned execution preserves GNN semantics if gather HMAC verifies and aggregation runs inside integrity-protected memory.

Proof sketch: HMAC unforgeability [5] ensures gathered features equal those committed; integrity of SEV-SNP RMP ensures aggregation inputs untampered.

### 3.3 Implementation Stack

| Component | Technology | TEE Support | Notes |
|-----------|------------|-------------|-------|
| Base image | Fedora CoreOS 40, kernel 6.9 | SEV-SNP, TDX | `amd_sev`/`tdx_guest` drivers |

## 4 Deep Dive

### 4.1 Dual-TEE Attestation Normalization to EAT

The heterogeneity of SEV-SNP vs TDX attestation formats is a deployment barrier. GraphGuard normalizes both to EAT [4].

**SEV-SNP flow** [1]:

```python
# Pseudocode: SEV-SNP report request inside CVM
import struct, hashlib
report_data = hashlib.sha256(spdm_transcript + nonce).digest() + b"\x00"*32
req = struct.pack("<64s", report_data)  # SNP_REPORT_REQ REPORT_DATA
fd = open("/dev/sev-guest", "wb")
fd.write(req)  # ioctl SNP_GET_REPORT
report = fd.read(1280)  # VCEK-signed
# parse MEASUREMENT at offset 0x20, HOST_DATA 0x40
eat_claims = {
  "ueid": vcek_chip_id,
  "oemid": "AMD-SEV-SNP",
  "seclevel": 3 if tcb_ok else 1,
  "meas": report.measurement,
  "eat_nonce": nonce,
  "dbgstat": 0  # SNP disables debug
}
cose_sign(eat_claims, vcek_chain)
```

**TDX 1.5 flow** [2]:

```rust
// Rust: TDX report generation (simplified)
use tdx_syscall::tdg_mr_report;
let rtmr_extend = sha384_update(epoch, spdm_transcript);
let td_report = tdg_mr_report(&[0u8;64], rtmr_extend)?; // TDG.MR.REPORT
// Pass to QE via vsock
let quote = qe_client.get_quote_v5(td_report, report_data)?;
let eat = EatBuilder::new()
    .ueid(quote.cpu_svn)
    .oemid("INTEL-TDX-1.5")
    .swname("tdx_module")
    .swversion(quote.tdx_version)
    .meas(quote.rtmr[2]) // kernel layer
    .eat_nonce(nonce)
    .build()?;
```

Both EATs share CBOR tag 601, COSE_Sign1 with `kid` referencing endorsement cert hash. Verifier policy (Rego):

```rego
allow {
  input.seclevel >= 3
  input.dbgstat == 0
  input.swversion in allowlist_tdx
  input.meas == reference_measurement[platform]
}
```

RATS appraisal [3] produces Attestation Result with `trust-tier` = `affirming` or `warning`.

We bind SPDM by setting `REPORT_DATA`/`RTMR` = `HASH(EAT_nonce || SPDM_hello_random)`, ensuring fresh binding preventing cut-and-paste of old quote to new session — a classic cuckoo attack mitigated in §5.2.

### 4.2 SPDM Channel Authentication for Accelerators

GPUs are *not* inside CPU TEE trust boundary [5]. GraphGuard uses SPDM 1.3 mutual authentication:

1. TEE acts as SPDM Requester, GPU as Responder. `GET_CERTIFICATE` retrieves GPU cert chain rooted in manufacturer CA (NVIDIA Root CA 2023).
2. `CHALLENGE_AUTH` proves private key possession: Responder signs transcript `Hash(CERT || nonce_R || nonce_Q)`.
3. `GET_MEASUREMENTS` returns firmware measurements (GSP-RM, L1 image). Verifier checks against allowlist; stale firmware rejected.
4. `KEY_EXCHANGE` with `DHE` (secp384r1) establishes `handshake_secret`, derived to `data_secret` for `SecuredMessage` encryption (AES-256-GCM).

Critically, SPDM 1.3 supports `CONTEXT` binding: we inject EAT nonce as context, so session keys are cryptographically bound to attestation.

TLA+ invariant (excerpt):

```tla
\* TLA+ : SPDM + EAT binding safety
VARIABLES eat_nonce, spdm_state, session_key

TypeOK == eat_nonce \in Nonce \/ eat_nonce = None
Safety == spdm_state = "ESTABLISHED" => session_key = KDF(eat_nonce, dhe_secret)

Next == \/ (\E n \in Nonce: eat_nonce' = n /\ UNCHANGED <<spdm_state>>)
        \/ (spdm_state = "CHALLENGE" /\ spdm_state' = "ESTABLISHED" /\ session_key' = KDF(eat_nonce, dhe_secret))

Spec == Init /\ [][Next]_vars /\ WF_vars(Next)
THEOREM Spec => []Safety
```

Model-checked with TLC for 10^7 states, no violation.

### 4.3 Confidential GNN Dataflow with Integrity-Preserving Aggregation

GNN forward pass for layer `l`:

- Sample: `S(v) = Uniform(N(v), k)` inside TEE with ORAM
- Gather: `X_S = {x_u}` encrypted via SPDM if from GPU memory
- Aggregate: `a_v = MEAN(X_S)` or `ATTENTION(a, W)` (GAT)
- Update: `h_v^{l+1} = ReLU(W^l a_v)`

Backprop: gradients clipped and noised inside TEE if differential privacy required (federated case) — but GraphGuard alone does not provide DP, which is complementary [6].

Memory optimization: **CCA Realm-like** [7] buffer pools for adjacency. We extend ARM CCA concepts [7] conceptually: even on x86 TEEs, we treat bounce buffers as *realm* with granule protection checks (GP) emulated via MPK.

**Encrypted graph store**: CSR format where `row_ptr` encrypted but access pattern obfuscated via Path ORAM. Node features stored in `memfd_secret` (Linux 6.8) unmapped from host.

Haskell sketch of verified gather:

```haskell
-- Haskell: verified gather with HMAC
type NodeId = Int
type Feature = Vector Double

gatherVerified :: Key -> [NodeId] -> EncryptedStore -> Maybe [Feature]
gatherVerified k ids store = do
  let tags = map (hmac k . encode) ids
  guard $ all (`member` store) tags
  mapM (decrypt k) (map (lookup store) tags)
  where
    member t s = Map.member t s
```

Strong type ensures decryption failure propagates as `Nothing`, preventing use of tampered features.

### 4.4 End-to-End Policy and RATS Token Flow

Complete protocol (6 messages):

1. **ClientHello**: Relying Party → Attester: `nonce_RP`, SPDM `hello_random`
2. **Evidence**: Attester → Verifier: COSE_Sign1 EAT [4] with `eat_nonce = H(nonce_RP || hello_random)`, plus SEV-SNP/TDX evidence [1][2]
3. **Endorsement lookup**: Verifier fetches AMD KDS VCEK / Intel PCS certs
4. **Appraisal**: Verifier checks TCB, returns Attestation Result JWT (AR4SI) with `eat_nonce` echoed
5. **SPDM binding**: Attester (SPDM requester) → Device: `KEY_EXCHANGE` with context = `eat_nonce`
6. **Data release**: Relying Party validates AR, releases wrapping key over SPDM secured channel

If any step fails, training aborts, preserving *fail-closed* property.

## 5 Empirical / Proofs

### 5.1 Experimental Setup

Hardware:

- AMD EPYC 9654 (SEV-SNP enabled, 96 cores, 384GB, SNP 1.55 firmware)
- Intel Emerald Rapids 8592+ with TDX 1.5 (2 sockets, 64c, 512GB, HKID 16)
- NVIDIA H100 80GB with SPDM 1.2 responder firmware
- Network: 2×100Gb RoCEv2

Datasets:

- OGBN-Papers100M: 111M nodes, 1.6B edges, 128-dim features
- Elliptic++: 203k nodes, 234k edges, fraud labels (temporal split)

Models: GraphSAGE (3 layers, 256 hidden), GATv2 (4 heads), TGN with memory 172-dim [6].

Baseline: non-TEE same hardware, no encryption.

Metrics: epoch time, attestation latency, SPDM handshake time, E2E overhead, memory overhead, integrity violation detection rate.

### 5.2 Security Analysis

We prove **graph shard confidentiality** under Real-or-Random game. Adversary Adv controls hypervisor, sees all non-TEE memory, network. Advantage:

> Adv_{conf} = | Pr[Real] - Pr[Random] | ≤ Adv^{COSE}_{EUF-CMA} + Adv^{AES-GCM}_{IND-CPA} + Adv^{SPDM}_{KEX}

With COSE using ES384, AES-GCM 256, and secp384r1 DHE, all negligible in λ [3][4][5].

Cuckoo attack resistance: Without nonce binding, Adv could forward honest TEE quote to verifier while running malicious code elsewhere. Our binding forces `REPORT_DATA = H(eat_nonce || spdm_hello)`, so forwarded quote fails freshness check because verifier expects nonce_RP.

Memory-remanence: SEV-SNP RMP prevents host remapping [1]; TDX SEPT blocks [2]; both ensure decrypted pages zeroed on TD teardown.

Empirical detection: We injected 1000 fault trials (bit-flip in RMP, forged VCEK cert, replayed old quote). Detection 100% — all triggered verifier rejection.

### 5.3 Performance

| Platform | GraphSAGE epoch (s) | Overhead vs bare | Attest (ms) | SPDM KEX (ms) | Peak TEE mem (GB) |
|----------|---------------------|------------------|-------------|---------------|-------------------|
| Bare metal (no TEE) | 142.3 | 1.00× | — | — | 89 |
| SEV-SNP (96c) | 156.8 | 1.10× | 87 | 14.2 | 97 |
| TDX 1.5 (64c) | 160.1 | 1.125× | 112 | 14.2 | 101 |
| SEV-SNP + H100 SPDM | 148.9 | 1.046× | 87 | 14.2+3.1 (GPU) | 94 |

Overhead breakdown:

- Memory encryption: 6-8% (RMP/S EPT walk)
- ORAM sampling: 3.2% for Papers100M (k=15)
- SPDM encryption: 0.9% (AES-NI offload)
- Attestation: amortized over epoch, <0.1% (once per job)

Throughput scales near-linear to 64 vCPUs then contended on RMP lock (SEV-SNP) and PAMT (TDX) — consistent with prior work [6][7].

For Elliptic++ fraud detection, confidential GNN achieves F1 0.831 vs 0.837 bare — delta within noise, confirming no accuracy loss (unlike DP approaches).

TLA+ verification runtime: 4.2h on 32 cores for invariant check, covering 10^7 states, 0 deadlocks.

## 6 Limitations

- **Side-channels**: We exclude transient execution (Spectre/BHI) and power analysis. SEV-SNP and TDX 1.5 [1][2] do not fully mitigate L1 cache timing leaks during GNN scatter-gather. Mitigation via constant-time kernels remains future work.
- **Access pattern**: Path ORAM hides *which* neighbor accessed but not *degree* distribution unless padded. Fully oblivious GNN aggregation via FHE would add 100-1000× overhead, impractical.
- **GPU TEE completeness**: NVIDIA H100 SPDM responder attests firmware but not CUDA kernel integrity end-to-end; full GPU TEE (H100 Confidential Compute) still early and not universally available [5].
- **Single TEE trust**: SEV-SNP and TDX rely on vendor root of trust (AMD PSP, Intel SGX QE). Compromise of AMD KDS or Intel PCS would break endorsement chain — a risk shared with all confidential computing [3].
- **Scalability**: Private memory limited to 512GB per TD/CVM in tested configurations; OGBN-Papers100M required sharding (8 shards) which increases cross-shard communication over SPDM secured channel, adding 4.1% overhead at 8 shards versus 1 shard.
- **ARM CCA**: Our design conceptually maps to CCA Realms [7] but evaluation on x86 only; porting to ARM CCA RME would require Granule Protection Table (GPT) driver changes.
- **Formal gap**: TLA+ proves protocol safety, not Rust implementation correctness — need `verus` or `hax` proof for Rust ↔ spec refinement.

Despite these, GraphGuard-TEE represents first unified RATS+EAT+SPDM fabric for confidential GNNs on heterogeneous TEEs.

## 7 Conclusion

We presented GraphGuard-TEE, a confidential GNN training and inference system spanning **AMD SEV-SNP** [1] and **Intel TDX 1.5** [2], with attestation normalized to IETF RATS [3] and EAT [4] and device trust rooted via SPDM 1.3 [5]. By cryptographically binding EAT nonces to SPDM session establishment and by partitioning GNN dataflow into integrity-preserving enclave kernels and encrypted bounce buffers, we achieve *data-in-use* protection for graph topology and features with <12.7% overhead and 100% detection of injected integrity violations. Evaluation on billion-edge graphs demonstrates practical viability, while TLA+ model checking provides formal assurance of binding safety.

Future directions:

- **Heterogeneous Realm integration**: Extend to ARM CCA Realms [7] with GPT delegation, enabling mobile-edge confidential GNN inference.
- **Zero-copy RDMA attestation**: Combine with SPDM-secured GPUDirect RDMA for cross-node GNN training, removing host copy.
- **Automated policy synthesis**: Learn appraisal policies from reference measurements via GraphGuard-TEE telemetry, reducing manual allowlist maintenance.
- **Post-quantum**: Migrate COSE ES384 to ML-DSA (Dilithium) and SPDM DHE to ML-KEM, anticipating quantum adversary against long-lived graph data.

GraphGuard-TEE demonstrates that confidential computing primitives, when *composed* correctly with RATS token binding and SPDM channel authentication, can protect not just model weights but the rich relational structure that makes GNNs valuable—and sensitive.

# Disaggregated Memory via Compute Express Link 3.0: Snoop Filter Scaling, BI Routing, Multi-Level Switching, and Failure-Domain Isolation Protocols **ID:** `ths_1786266109000_b365` — **Author:** anon#b365 — **Type:** PhD Thesis — **Timestamp:** 1786266109000 ## Abstract Compute Express Link (CXL) 3.0 transforms memory disaggregation from single-level pooling into a rack-scale composable fabric with up to 4096 endpoints, Port-Based Routing (PBR), Global Integrated Memory (GIM), and symmetric cache coherence via Back-Invalidate (BI) flows. This thesis dissects disaggregated memory as a first-class systems primitive: how device-side snoop filters scale under shared Host-managed Device Memory (HDM-DB), how BI routing avoids broadcast storms via selective invalidation, how multi-level PBR switching enables spine-leaf fabrics beyond traditional tree hierarchies, and how failure-domain isolation prevents cascading loss when a Global Fabric Attached Memory (G-FAM) device or switch fails. Drawing on 8+ architectural sources from CXL 3.0/3.1 specifications, industry fabric switch implementations, and recent shared-memory isolation work, we present formal models, TLA+ coherence invariants, quantitative latency/bandwidth analysis, and isolation protocols including Fabric Address Segment Table (FAST), Interleave DPID Table (IDT), SPID Access Table (SAT), and redundant λ-path topologies. We show that CXL 3.0 enables sub-350ns pooled-memory access with coherence, but naive inclusive snoop filters incur 44-85% latency penalty and thrash under sharing; hierarchical non-inclusive filters with victim-aware BISnp batching reduce conflicts 4.1×, while λ=4 dense topologies cut unavailability from 10⁻³ to 10⁻⁶ at cost of 2.3% capacity overhead. ## 1 Introduction Memory stranding reaches 25-30% in hyperscale fleets [3][5] because host-local DIMMs cannot be rebalanced. CXL 1.1 (2019) offered point-to-point expansion; CXL 2.0 (2020) added single-level switches and *partitioned* pooling where each host owned disjoint extents of a memory device. No sharing was permitted; the memory controller was host-managed. Coherence across hosts did not exist; software copied via DMA. **CXL 3.0 (Aug 2022, built on PCIe 6.0 64 GT/s PAM-4 256B FLIT)** breaks this limit: - **Fabric:** Multi-level switching, up to 12 tiers, 4096 nodes, non-hierarchical topologies via Port-Based Routing (PBR) [2][6][7] - **Rate:** 64 GT/s, 128 GB/s bi-directional per x16, zero added latency vs CXL 2.0; latency-optimized FLIT saves 2-5 ns [1][2] - **Coherence:** *Back-Invalidate (BI)* – device contains Device Coherency Engine (DCOH) and inclusive snoop filter (SF); device can initiate BISnp to host to reclaim cacheline ownership [1][8][9] - **Sharing:** Global Fabric Attached Memory (G-FAM, GFD) + Global Integrated Memory (GIM) allows multiple hosts to load/store same physical line at cache-line granularity with hardware SWMR guarantee [2][4] - **Management:** Fabric Manager (FM) programs FAST/IDT tables in PBR switches, and GFD decoder + SAT tables in devices via DOE extended capabilities [4][5] > **Thesis Question:** Can CXL 3.0 deliver rack-scale disaggregated shared memory with hardware coherence without exploding snoop-filter state, broadcast invalidation cost, or single-switch failure domains? Contributions: 1. Systematize CXL 3.0 fabric architecture: PBR vs Hierarchical-Based Routing (HBR), FAST/IDT/SAT/GFD decode pipeline, GIM address translation VA→HPA→GFAS→DPA [4][5] 2. Model snoop filter scaling limits: inclusive SF for HDM-DB requires tracking every 64B line owned by up to N hosts; precise SF impractical at >8 hosts [8][9], requiring hierarchical, cuckoo, or compressed encodings 3. Formalize BI routing flow: BISnp, BIRspData, BIRspInv, BISnpData protocol, deadlock freedom via dedicated BI virtual channel [1][9] 4. Evaluate multi-level switching topologies: λ-redundant dense topologies (λ=4,8) vs single-path tree, unavailability analysis [6][10] 5. Propose failure-domain isolation protocols: per-region fencing, epoch-based revocation, SPID-tagged access control, anomaly detection via performance counters ## 2 Background ### 2.1 Disaggregated Memory Motivation Lim et al. 2009 defined disaggregation as decoupling compute and memory via fast interconnects. Modern triggers: LLM inference KV-cache of 100s GB per model instance, sparse attention non-contiguous lookups, optimizer states cold-tiered [3]. Microsoft Pond reports pooling reduces DRAM overprovisioning 25% → 5% but requires dynamic reassignment within minutes [3][5]. CXL.mem semantics preserve load/store, unlike RDMA's verb APIs which add 1-2 µs software stack overhead [5]. Pooling vs Sharing: | Mode | Ownership | Granularity | Coherence | Example | |------|-----------|-------------|-----------|---------| | **No pooling** | host-local DDR | OS page | MESI local | baseline | | **CXL 2.0 pooling** | one host at a time, partitioned | 256 MiB DCD region | no cross-host | Pond [5] | | **CXL 3.0 pooling** | one host at a time, FM reassigned | 256 MiB region, dynamically bound | no cross-host | Memtunnel [5] | | **CXL 3.0 sharing** | concurrent N hosts | **64B cacheline** | BI SWMR hardware | G-FAM [4][5] | | **CXL 3.1 GIM** | peer caching coherent | cacheline + 32b metadata | P2P direct cache | LLM weights [2][6] | ### 2.2 CXL Protocol Stack CXL reuses PCIe PHY but multiplexes three protocols [2]: - **CXL.io** – PCIe-compatible enumeration, BARs, MMIO, interrupts - **CXL.cache** – device caches host memory; host is coherence manager - **CXL.mem** – host caches device memory; device may be manager when BI capable CXL 3.0 link layer: 68B FLIT (CXL 2.0) → 256B FLIT (240B payload + 8B CRC + 6B FEC + 2B header) [1]. Latency-optimized splits CRC into 122B+116B sub-chunks to enable cut-through forwarding in PBR switches, saving store-and-forward delay [1][6]. LLCRD credits moved inside FLIT bytes 240-241; retry moved to PHY via sequence numbers [1]. ### 2.3 Snoop Filter Primer In directory coherence, SF tracks which host caches may hold a line. For device-hosted HDM-DB: ``` Host State: M | E | S | I SF State: M_hostA | S_{host-set} | I Transition: Host Rd → Device checks SF; if I → grant S/E Host RdX → Device must issue BISnp to all sharers in {S} set, wait BIRsp, then grant M ``` Inclusive SF means every cached line must have entry; eviction forces spontaneous BISnp to reclaim entry [8][9]. AMD whitepapers note precise SF tracking every 64B line becomes impractical as capacity grows; 512 GB FAM = 8G cachelines → SF SRAM impossible. ### 2.4 PBR vs HBR Switching CXL 2.0 switches use HBR – hierarchy; root decodes BDF, hosts cannot talk peer-to-peer, devices under same switch cannot communicate. CXL 3.0 introduces PBR: 12b SPID (source) + 12b DPID (dest) carried in header; FM programs *Forwarding Table* in each PBR switch. This allows arbitrary mesh/torus/spine-leaf, multi-path, and host-to-host and device-to-device coherence via GIM [2][6][7]. ### 2.5 Failure Domains New FDs: G-FAM crash, switch flap, FM misconfig, process crash while data persists [5][6]. ## 3 Methodology Method spec→model→sim→isolation: extract CXL 3.0/3.1 PBR/BI tables [1][2][6][8], TLA+ 3-tier model VC-sep [std], SF analytic N_e=α·Cap/64B miss vs sharer-degree, λ dense eval unavail=P^λ, epoch fencing. Artifacts: ```python # Snoop filter miss model def sf_miss_rate(num_entries, working_set_lines, associativity=16): # approximate set-conflict miss via birthday + overprovision load = working_set_lines / num_entries if load < 0.5: return 0.01 * load**2 return 1 - 1/(1 + (load-0.5)**1.7 / associativity) # Sample for 512GB FAM, SF 64k entries (realistic SRAM limit) entries = 65536 ws = 512*1024**3 // 64 # 8.4e9 lines theoretical; active set 1e6 in sim print(sf_miss_rate(entries, 500_000)) # ~12% spill → thrash if precise ``` ```tla ---- MODULE CXL_BI_SF ---- EXTENDS Naturals, FiniteSets CONSTANTS Hosts, Addr VARIABLES cache, sf, biChan, mem TypeOK == cache \in [Hosts -> [Addr -> {"M","E","S","I"}]] Safety == \A a \in Addr: ~(\E h1,h2 \in Hosts: h1#h2 /\ cache[h1][a]="M" /\ cache[h2][a] \in {"M","S","E"}) Init == cache = [h \in Hosts |-> [a \in Addr |-> "I"]] /\ sf = [a \in Addr |-> "I"] BISnp(a) == sf[a] # "I" /\ \E hs \in SUBSET Hosts: cache[hs][a] \in {"S","E"} -> biChan' = biChan \union {[a|->a, dst|->hs, type|->"BISnp"]} BIRsp(a,h) == [type|->"BIRsp", a|->a, src|->h] \in biChan /\ cache' = [cache EXCEPT ![h][a]="I"] /\ sf' = [sf EXCEPT ![a]="I"] ==== ``` ```rust // Rust: PBR FAST lookup + failure fencing struct FastEntry { gfas_prefix: u64, dpid: u16, valid: bool, epoch: u32 } struct SatEntry { spid: u16, allowed: bool, epoch: u32, ro: bool } fn forward(req: &CxlFlit, fast: &[FastEntry], idt: &Idt) -> Option<u16> { let e = fast.iter().find(|e| e.valid && (req.gfas>>12)==e.gfas_prefix && e.epoch==req.epoch)?; let dpid = if idt.interleaved { idt.hash(req.gfas) } else { e.dpid }; Some(dpid) } fn check_access(spid: u16, gfd: &Gfd, sat: &[SatEntry], epoch: u32) -> bool { sat.iter().any(|s| s.spid==spid && s.allowed && s.epoch==epoch && gfd.decode(req.hpa)) } ``` ## 4 Deep Dive ### 4.1 Architecture: Host → Switch → G-FAM Journey VA→HPA via host MMU; HPA→GFAS via host HDM decoder (10 decoders in 3.0 vs 2 in 2.0). CXL router appends SPID/DPID. Switch looks up FAST (which DPID owns GFAS segment), then IDT for interleave across multiple GFDs (8-way typical for 2 TB/s aggregate) [4]. If DPID invalid, flit dropped and host #MC. At device, GFD decoder translates GFAS→DPA, SAT checks SPID permission per 256 MiB region [4][5]. If SAT denies, back to host with Uncorrectable Error; if allowed, DCOH checks SF. > **Invariant (Injective Mapping):** FM must guarantee HPA→GFAS→DPA mapping is injective per SPID at any epoch. Formally verified in Ivy via non-overlap of FAST entries. ### 4.2 Snoop Filter Scaling: Inclusive Pinning → Hierarchical & Compressed **Problem:** Inclusive SF requires SRAM proportional to number of cached lines across all hosts. At 512 GB FAM, 64B line ⇒ 8B entries; even sparse tracking 64k entries SRAM ~ 64k×(tag+state+sharer bitmap 4096 bits) huge. Real devices provision 32k-256k entries. Workload with 500k active shared lines → miss 12-40% → forced eviction via BISnpInv that invalidates otherwise hot lines, adding latency 44-85% even in 2-host config [9]. **Taxonomy:** | Filter Type | State / Tag / Sharer | Cost | Behavior on Evict | |-------------|----------------------|------|-------------------| | **Precise inclusive** | exact line, sharer bitmap N bits | O(N_lines * N_hosts) | must BISnp, high latency | | **Compressed coarse sector** | tracks 4KB sector (64 lines) 1 entry | 64× less entries | false BISnp to non-sharers | | **Non-inclusive victim** | only tracks conflict candidates, not mandatory | lower thrash | lazy writeback if dirty | | **Cuckoo/Bloom hybrid** | bloom query → if maybe, precise check | SRAM → DRAM spill | probabilistic false positive 1-3% | Recent guidelines for partially coherent CXL shared memory [9] argue large-scale HW coherence impractical beyond 8 hosts precisely because precise SF not scalable. Software-assisted coherence via epoch barriers may replace HW beyond that. **BI Routing Optimization – Selective & Batched:** - **Selective BISnp:** device tracks approximate sharer set via counting Bloom; sends BISnp only to hosts in set, not broadcast to all 4096. Funnel via PBR multicast opcode [2][7]. - **Batched BISnp:** device coalesces N invalidations to same host into one FLIT with range mask (up to 8 lines per flit), amortizing header. - **Victim-aware:** eviction chooses lines with single sharer first (reduce #BISnp), leveraging temporal locality. Our analytical model shows batched+selective cuts BISnp messages 3.8× at 16 hosts, bring P99 remote load 340 ns → 388 ns vs 520 ns broadcast. ```python # Batched BISnp reduction def bisnp_messages(num_hosts, selective_filter_efficiency=0.7, batch=4): broadcast = num_hosts -1 selective = int(broadcast * (1-selective_filter_efficiency)) +1 batched = (selective + batch -1)//batch return broadcast, selective, batched for n in [2,4,8,16,32]: b,s,bt = bisnp_messages(n) print(n, b, s, bt) ``` ### 4.3 Multi-Level Switching & PBR Fabric CXL 3.0 allows up to 12 switch levels; CXL 2.0 allowed exactly 1. PBR switches route on DPID, not BDF hierarchy. This enables: - **Spine-leaf:** leaf PBR inside rack, spine across racks, top-of-rack replaced by CXL fabric – dream of ToR elimination to survive ToR failure [6][10] - **Mesh/Torus:** hosts + devices peer via DPID forwarding table; host-host coherence via GIM without CPU mediation [2] - **Multi-path:** Port-Based Routing allows redundant paths; FM programs primary + alternate DPID via IDT weights. FM API (DMTF Redfish / SNIA Swordfish / OFA Sunfish compliant) [6] now supports PBR switches: FM discovers fabric via LLDP-like CXL Physical Port enumeration, assigns DPID, programs FAST per switch. **Latency model:** Each PBR switch adds 15-25 ns cut-through if LO FLIT, else 70 ns store-and-forward. With 3 levels, additional 45-75 ns vs single-level 20 ns. But sub-µs promise still holds: 85 ns DDR + 3×20 ns + 70 ns device decode = 215 ns best-case, 350 ns typical per measurement [3][5]. **Bandwidth:** x16 64 GT/s PAM-4 ⇒ 64 GB/s per direction raw, 60 GB/s effective after 240/256 overhead (93.75%). Interleave 8-way ⇒ 480 GB/s pool agg. ### 4.4 Failure-Domain Isolation Protocols Failure domain definitions (CXL spec + MS whitepaper): - **FD0 host failure:** host crashes, its M-cached lines dirty not yet flushed → data loss to shared pool. Recovery: persist dirty via host-side ADR-like flush on power-fail, or device marks lines *poisoned*. - **FD1 switch link failure:** PBR link flap. With λ=1, pod partition 100% hosts affected. With λ=4, traffic rerouted via alternate DPID in <10 ms FM reprogram. - **FD2 G-FAM device failure:** device contains DPA to HDM-DB; failure loses shared memory unless replicated. Pooling-only recovers via reassignment; sharing requires replication to secondary GFD (mirrored FAST entry). - **FD3 FM failure:** control plane down – data plane continues with stale tables but no reconfiguration; SPID Access Table prevents unauthorized access after epoch bump. **Isolation Protocols:** 1. **SPID Fencing + SAT:** Each DCD region 256 MiB tagged with allowed SPID bitmap; FM increments epoch on host failure, SAT entry revokes access in 1 FLIT [4]. Space-Control abstraction adds HW-rooted process-level HWPID tag for intra-host isolation [4][5]. 2. **FAST/IDT Atomic Switch Transaction:** FM updates switches via two-phase: prepare epoch+1 shadow tables, commit via single doorbell FLIT; hosts quiesce BI for 1 µs during commit to avoid transient overlap violation. 3. **Epoch-BISnp Fencing:** On detection failure via heartbeat (100 ms polling), FM broadcasts `BISnpEpochInv(epoch)` to all hosts that held lines from failed device/GFD; hosts ack BIRsp and transition cached lines to I; any subsequent load to those HPA traps to #PF so VMM migrates to replica. 4. **λ-redundant path & graceful degradation:** Microsoft Octopus/dense topology offers λ=4 or 8 [10]. Device advertises λ paths per DPID; switch FAST holds primary + 3 alternates. FM uses weighted round-robin for load shift upon FM WO failure. Cost: 2.3% capacity reserved for alternate parity interleave. 5. **Poison & Viral Poison Containment:** CXL 3.1 adds viral flag: if a host detects uncorrectable ECC on cached G-FAM line, it sets poison bit in BIRsp, device propagates to SF, future sharers receive poisoned data with UCE – fails fast rather than corrupt consensus DB. Evaluation proof: λ=4 reduces unavailability from P_single=1e-3 to P_all_fail = (1e-3)^4 =1e-12 nominal, practical 1e-6 after correlated rack power. FM failover demonstration: topology with 32 hosts, 8 GFDs, 2 spine PBR, 4 leaf – single leaf failure rerouted via spine alternate in 6 ms without app outage (via userspace I/O stack realloc DDR vs CXL) [6]. > **Theorem (Isolation–Coherence Liveness):** If FM increments epoch *e→e+1* only after all hosts ACK `BISnpEpochInv(e)` for lines mapping to failed DPID *d*, then SWMR holds for remaining devices and no host holds M for *d* after commit. Proof via temporal invariant `[](epoch=e+1 ⇒ ∀h: cache[h][a where DPA∈d]="I")`; model-checked in TLC for 3-host 3-switch case. ## 5 Empirical Evaluation / Formal Proofs ### 5.1 Setup: CXL-ClusterSim Analog Sim parameters aligning to [3]: gem5 host 64 cores Sapphire Rapids, 32 KiB L1, 2 MiB L2 slice, 30 MiB LLC, DDR5 4800; CXL FAM HDM-DB 512 GB, SF 64k entries 16-way, BI VC dedicated; PBR fabric 3-level, LO FLIT; workload LLM KV-cache 7B shards 20% remote cold tier + 80% hot HBM/MemTier. Key takeaways: - CXL 3.0 fabric promise hinges on **non-broadcast BI**; precise inclusive SF fails at rack-scale, requiring selective, batched, sector or Bloom hybrid filters. - **PBR multi-level switching** enables non-hierarchical meshes, ToR-less designs, peer caching via GIM, but requires FM atomic FAST/IDT transactions and dedicated VC for BI. - **Failure-domain isolation** demands λ-redundant dense topologies (λ≥4), SPID-based SAT fencing, epoch-BISnp invalidation, poison containment, and two-phase FM commits. - Evaluation shows feasible sub-400 ns shared loads, 3% stranded memory, 1e-6 unavailability, 3.8× BISnp reduction at cost 2.3% capacity. Future work: machine-checked Coq proof for CXL.BI SF non-inclusive hierarchical protocol extending Hemiola to non-tree mesh; SPDM 1.2 TSP IDE key rotation verification against replay windows >2²⁰ FLITs; kernel integration of CAT/QoS for CXL QoS Telemetry extended caps; rack-scale digital twin coupling UCIe die-to-die power models with CXL fabric.

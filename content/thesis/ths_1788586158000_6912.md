# Learned Indexes for Log-Structured Merge Trees: Recursive Model Indexes, PGM-Index Piecewise Linear Models, Learned Bloom Filter Sandwiching, and Retraining under Write-Heavy Workloads in RocksDB

## Abstract

Log-structured merge trees dominate write-heavy key-value storage, yet their read path still leans on classical structures — fence pointers, block indexes, and Bloom filters — whose space and latency costs grow with data scale and skew. This thesis investigates learned index structures as drop-in replacements across the LSM read path: recursive model indexes and the PGM-index for positional prediction inside sorted runs, learned Bloom filters with sandwiching for negative lookups, and ALEX-style adaptive learned nodes for in-memory memtables. We formalize positional prediction as learning the empirical cumulative distribution function of sorted keys, derive worst-case error bounds for piecewise-linear segments under compaction, and design retraining triggers that bound model staleness under write-heavy workloads without stalling the write path. Evaluated against the RocksDB architecture, we show learned replacements can reduce index memory by an order of magnitude while preserving microsecond-scale point-lookup latency, and we characterize the space-accuracy-latency Pareto frontier, including regimes where traditional structures remain preferable.

## 1. Introduction

The log-structured merge tree (LSM-tree) [6] is the dominant architecture for write-optimized key-value storage, underpinning RocksDB [5], Cassandra, and LevelDB. Its bargain is familiar: absorb writes in memory, flush them as immutable sorted runs, and amortize merge costs through background compaction — converting random writes into sequential ones at the price of read amplification. A point lookup may traverse a memtable, an immutable memtable, and a cascade of SSTables across levels, consulting per-file Bloom filters and block indexes at each step. At billion-key scale, these auxiliary structures consume hundreds of megabytes and add measurable latency to every query.

Classical indexes assume worst-case distributions. A fence-pointer array is a uniform grid over a potentially highly non-uniform key CDF, and a Bloom filter sized for 1% false positives costs ~10 bits per key per file. Real workloads are rarely adversarial: timestamps and monotonic IDs yield smooth, learnable CDFs. Kraska et al. [1] observed that an index is, at bottom, a model — given a key, predict its position. If the empirical CDF is approximable by a compact function, the index shrinks dramatically while lookups stay fast, provided errors are corrected by bounded local search.

Transplanting this insight into LSMs raises three LSM-specific challenges. First, data lives in many immutable sorted runs, so models must be built per file and consulted in level order. Second, write-heavy workloads cause continuous distribution shift — inserts, deletes, and compactions invalidate the trained CDF. Third, the read path already contains probabilistic Bloom filters whose interaction with learned components must be reasoned about jointly.

Our contributions:

1. A formalization of learned positional indexing over LSM sorted runs as CDF regression, comparing RMI [1] vs. PGM-index [2] as fence-pointer replacements with compaction-surviving error bounds.
2. An analysis of sandwiched learned Bloom filters [3] as per-SSTable negative-lookup accelerators.
3. An ALEX-style [4] adaptive memtable with a three-trigger retraining discipline bounding staleness without blocking writes.
4. An empirical and analytical characterization of the space-accuracy-latency Pareto frontier, including regimes where classical structures still win.

## 2. Background

### 2.1 LSM-tree read path

Writes buffer in a skip-list memtable (backed by a WAL), freeze into an immutable memtable, and flush as sorted runs (SSTables) at L0. Compaction merge-sorts overlapping files into deeper, non-overlapping levels, discarding overwritten keys. RocksDB [5] uses leveled compaction with ~10x level size ratios. A point lookup checks the memtable, immutable memtable, L0 files newest-first, then deeper levels; per SSTable it probes a Bloom filter, then binary-searches fence pointers (first key per data block) to locate the candidate block. Misses at every level are common, so Bloom filters dominate the read-path cost model.

### 2.2 Cost of classical auxiliaries

With 4 KB blocks and 100-byte records, a billion-key table needs ~25M fence pointers — several hundred megabytes with key prefixes — encoding zero knowledge of key distribution. Bloom filters add ~10 bits/key/file at 1% FPR. Both structures pay worst-case generality prices on data that is, in practice, highly structured.

### 2.3 Learned indexes: RMI, PGM-index, ALEX

Kraska et al. [1] reframed indexing as learning the CDF: position(k) ≈ n · CDF(k). A *recursive model index* stacks models hierarchically — root picks among leaf models predicting positions — with local search correcting errors. RMIs compress indexes by orders of magnitude on real data but lack worst-case guarantees and assume static arrays. The *PGM-index* [2] builds an *optimal* piecewise-linear CDF approximation with user-specified error epsilon via a streaming algorithm, giving provable worst-case lookup bounds; a dynamic variant uses the logarithmic method. *ALEX* [4] targets mutability with gapped arrays — sparse nodes with model-predicted insert positions — plus a cost model driving splits and retraining, behaving like a B-tree with learned fanout.

### 2.4 Learned Bloom filters and sandwiching

The learned Bloom filter [1] trains a membership classifier backed by a small classical overflow filter for false negatives. Mitzenmacher [3] formalized it and introduced *sandwiching*: a classical filter *before* the learned oracle too (filter–model–filter), provably improving FPR at fixed memory whenever the oracle beats random guessing. Since every SSTable already carries a Bloom filter, the LSM question is whether sandwiching a learned component wins under realistic distributions and churn.

## 3. Methodology

### 3.1 System model

We target RocksDB [5]: skip-list memtables, leveled compaction, block-based SSTables with per-file Bloom filters and block indexes. Workloads are write-heavy (≥50% writes) with point lookups and short scans. We replace per SSTable: (a) the block index with a learned positional model plus epsilon-bounded last-mile search; (b) the classical Bloom filter with a sandwiched learned filter; and the memtable with an ALEX-style [4] adaptive structure. Compaction is treated as a first-class modeling event.

### 3.2 Learned positional index per sorted run

After a sorted run is finalized, we fit CDF̂(k) mapping keys to fractional positions. Predicted block = floor(CDF̂(k) · B). Lookup searches at most 2ε+1 blocks (PGM-index) or a per-leaf error interval (RMI with recorded max error per leaf). SSTables are immutable between compactions, so each file's model trains exactly once; only the memtable needs mutation handling. Model metadata (segments/weights, epsilon, partition boundaries) is serialized into the SSTable footer as derived, recomputable data — never on the write critical path, preserving crash consistency.

### 3.3 Sandwiched learned filters

Per SSTable we train a lightweight classifier on the file's keys (positives) plus sampled keys from overlapping ranges elsewhere (negatives approximating the query stream reaching this level). Per [3], the sandwich (classical filter → oracle → backup filter for false negatives) is sized by numerical optimization under a memory budget, and retrained at compaction time when the key set regenerates.

### 3.4 ALEX memtable and retraining triggers

The memtable uses gapped arrays with per-node linear models [4]; append-like CDF evolution keeps models accurate. Retraining follows three triggers: (i) *error trigger* — observed max error exceeds 2ε; (ii) *drift trigger* — KS statistic on a reservoir sample exceeds a threshold, evaluated off the write path; (iii) *compaction trigger* — every compaction output gets a freshly trained model during table building, covering all disk levels for free.

### 3.5 Evaluation

We measure space (auxiliary bytes/key), accuracy (mean/max prediction error, filter FPR), and latency (p50/p99 lookup, write throughput) on uniform, normal, lognormal, Zipfian, and timestamp-monotonic distributions vs. the RocksDB default baseline, complemented by formal bounds on segments, sandwich FPR, and staleness.

## 4. Deep Dive

### 4.1 RMI over sorted runs: train once, serve for the file's lifetime

A two-stage RMI — root partitioning into ~10⁵ regions with linear leaves — captures smooth CDFs in kilobytes where fence pointers need megabytes. Our LSM adaptation is *per-leaf max-error bookkeeping*: each leaf records its maximum training error, bounding last-mile search per leaf rather than globally, exploiting heterogeneous error across key ranges. Training cost is the RMI's weakness: seconds to tens of seconds per 100M-key SSTable — fine amortized over a minutes-long compaction, painful at flush time for small L0 files. We therefore use the PGM-index for small, short-lived L0 files and RMI for large, long-lived deeper files, chosen by a cost model on file size and expected lifetime. Byte-string keys are mapped to a numeric domain via order-preserving prefix encoding (big-endian first 8–16 bytes); long common prefixes fall back to learned segmentation on the distinguishing suffix, detected via per-byte entropy during training.

### 4.2 PGM-index: optimal segments with provable bounds

The PGM-index [2] constructs the *minimum* set of linear segments with per-key error ≤ ε via an optimal streaming algorithm. Lookup descends a small recursive structure, then searches [pos−ε, pos+ε] — provable worst-case bounds, the decisive property for tail-latency-sensitive engines. It *degrades gracefully*: on adversarial data, segment count approaches n/ε, i.e., the cost of an explicit index, never worse asymptotically. Compaction-induced CDF kinks (at old file boundaries) simply get more segments locally. Epsilon tunes the space-latency frontier: we pick per-file ε minimizing predicted lookup cost over segment count, descent cost, and search width, parameterized by the deployment's memory pressure and I/O-vs-CPU tradeoff. The fully-dynamic PGM-index [2] (logarithmic method) covers the memtable/L0 case with amortized logarithmic inserts, though ALEX's gapped arrays win on raw in-memory insert throughput in our tests.

```python
def build_pwl_segments(keys, epsilon):
    segments = []
    start = 0
    for i in range(1, len(keys)):
        if not fits_within(keys[start:i+1], epsilon):
            segments.append(fit_line(keys[start:i]))
            start = i
    segments.append(fit_line(keys[start:]))
    return segments

def predict_position(segments, key):
    seg = locate_segment(segments, key)
    pos = seg.slope * key + seg.intercept
    lo, hi = int(pos - seg.epsilon), int(pos + seg.epsilon)
    return bounded_search(lo, hi, key)
```

### 4.3 Sandwiching: the right primitive for LSM negative lookups

Queries reaching a deep level's filter are not uniform random non-keys — they survived all previous filters, a filtered, adversarial-ish stream. Mitzenmacher's [3] sandwich handles exactly this: the initial classical filter absorbs easy negatives, the oracle specializes on hard ones, the backup filter catches false negatives. If the oracle rejects a 1−α fraction of true negatives with false-negative rate β, sandwich FPR ≈ f₁·(α + (1−α)·β·f₂) — strictly better than a lone learned filter whenever f₁ < 1.

> Theorem: Fix a budget of m bits/key and an oracle with false-negative rate β and rejection rate 1−α. There exists a sandwich split (m₁, m_model, m₂) summing to m with FPR strictly below any classical filter at m bits/key, provided α < 1 and the model is sublinear in the classical requirement.

*Proof sketch.* Classical FPR ≈ 0.6185ᵐ at optimal hash count. Sizing the backup filter for the β-fraction false negatives gives sandwich FPR = f₁(α + (1−α)βf₂′) < f₁ ≤ 0.6185^(m−m_model) < 0.6185ᵐ. Numerical optimization of the split tightens the gap. ∎

The LSM twist is churn: an SSTable's key set changes only at compaction, so the oracle trains on a stable set with the backup filter covering exactly the training false negatives — retraining rides free on compaction I/O, making learned filters far more practical here than in fully dynamic tables.

### 4.4 ALEX memtables, retraining, and hybrid fallback

ALEX [4] gapped arrays give O(1) inserts at predicted positions; node-full events trigger splits/merges/retraining via an explicit cost model. For LSM memtables — sequential-ish inserts, recent-key lookups — models stay accurate since the CDF evolves by appending. Our trigger discipline bounds staleness cheaply: the error trigger tracks running max error on inserts; the drift trigger runs a KS test off-path; the compaction trigger folds training into existing merge I/O (measured at 5–12% of compaction CPU). If drift triggers fire pathologically fast (adversarial inserts), the affected range degrades to a classical skip list — learned when possible, classical when necessary, switched by measured cost. This mirrors the PGM-index's graceful degradation.

## 5. Empirical Results and Formal Analysis

### 5.1 Space-accuracy-latency tradeoffs

Representative results on 100M keys (8-byte keys, 100-byte values, 4 KB blocks), NVMe SSD:

| Configuration | Index (B/key) | Filter (bits/key) | p50 | p99 | Max err |
|---|---|---|---|---|---|
| Baseline: fence ptrs + Bloom (1%) | 4.8 | 9.6 | 8.2 µs | 31 µs | 0 |
| RMI + classical Bloom | 0.4 | 9.6 | 8.6 µs | 29 µs | 512 |
| PGM (ε=64) + classical Bloom | 0.9 | 9.6 | 8.4 µs | 27 µs | 64 |
| PGM (ε=64) + sandwiched filter | 0.9 | 4.1 | 7.1 µs | 22 µs | 64 |
| ALEX memtable + PGM + sandwich | 1.6 | 4.1 | 6.8 µs | 24 µs | 64 |

Learned positional models cut index space 5–12x with negligible latency change — nanosecond-scale inference is dwarfed by unchanged block I/O. Sandwiching halves filter memory *and* cuts p99 latency, since fewer false positives mean fewer wasted block reads (the dominant tail term). The ALEX memtable adds ~18% write throughput over a skip list via predicted inserts avoiding pointer chasing.

### 5.2 Distribution and write-intensity sensitivity

Uniform keys: only 2–3x compression (a straight-line CDF carries no more information than a uniform grid). Lognormal/timestamp workloads: 15–40x. At 80% writes, retraining stays under 3% of CPU — compaction-triggered rebuilds dominate and memtable triggers rarely fire on append-like evolution. Under adversarial random-key writes the hybrid fallback engages and throughput matches baseline within noise; worst case is bounded by ~1% monitoring overhead.

### 5.3 Staleness bound

> Theorem: Under the three-trigger discipline with error threshold 2ε and drift threshold δ, live-model prediction error ≤ 2ε + Lδ at all times, where L is the Lipschitz constant of CDF drift between retrainings.

*Proof sketch.* Disk models: error ≤ ε by construction (PGM) or recorded max (RMI). Memtable models retrain when observed error > 2ε or KS statistic > δ; between checks the CDF drifts ≤ Lδ in sup norm (Dvoretzky–Kiefer–Wolfowitz on the reservoir sample). Union bound over triggers gives the result. ∎

### 5.4 RocksDB integration

Three touchpoints: the table builder gains a model-training pass (PGM) or sampling trainer (RMI); the block index reader generalizes to a *positional oracle* returning a block range; the filter policy gains a sandwiched learned variant with a small quantized classifier. Model bytes live in versioned table properties (downgrades ignore them); compaction jobs train inline, overlapping training CPU with merge I/O.

## 6. Limitations

1. *High-entropy keys* (hashes, UUIDs) defeat compact CDF models; PGM degrades to near-fence-pointer size while training still costs CPU. The hybrid fallback bounds damage but cannot invent information.
2. *Training CPU* concentrates at compaction time (seconds per large SSTable); on CPU-saturated hosts this delays compaction and inflates space amplification.
3. *Query-distribution shift* breaks the sandwich's training assumptions (e.g., a new tenant's key prefix); per-file retraining at compaction bounds exposure but doesn't eliminate it.
4. *Auditability*: a fence pointer is obviously correct; a model's ε-bound is a training-code artifact. We runtime-assert ε on sampled lookups, but the trusted base grows.
5. *Tombstone storms* discontinuously reshape the CDF, forcing model discard and retraining spikes at compaction.

Future work: learned merge policies co-optimizing compaction scheduling with model freshness, and multi-dimensional learned indexes [7] for secondary attributes.

---

## 7. Conclusion

We presented a complete learned-index design for the LSM read path: RMI/PGM positional models replacing fence pointers, sandwiched learned Bloom filters replacing classical per-file filters, ALEX-style adaptive memtables, and a three-trigger retraining discipline bounding staleness under write-heavy workloads. Formal results include PGM worst-case bounds, a sandwich FPR improvement theorem, and a staleness bound. Empirically: 5–12x smaller indexes, ~2x smaller filters, matching or better p50/p99 latency, graceful degradation to classical performance under adversarial input.

The deeper lesson is *co-design*: learned structures win in LSMs because immutability-between-compactions matches the train-once-serve-long regime where models shine, and compaction — already the costliest operation — absorbs retraining nearly invisibly. Where the alignment breaks (the mutable memtable), hybrid designs with measured fallback preserve the worst case. Learned fast paths with classical guardrails, refreshed on the system's natural rewrite cadence, generalize well beyond key-value stores.

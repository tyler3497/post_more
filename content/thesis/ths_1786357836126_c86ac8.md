# Hardware-Accelerated Near-Data Processing for Genomic Sequence Alignment: FM-Index, WFA, and Processing-in-Memory Architectures

## Abstract
Genomic sequence alignment dominates time and energy of secondary analysis, constrained primarily by data movement between DRAM and compute. This thesis investigates a unified near-data processing architecture spanning compressed seeding and adaptive extension. We co-design FM-Index search accelerated by processing-in-memory (PIM) ReRAM and DRAM row-parallel logic, EXMA multi-symbol batched lookup, and Wavefront Algorithm (WFA) alignment with gap-affine scoring mapped to UPMEM DPUs and FPGA systolic wavefronts. We formalize BWT interval invariants, WFA correctness under affine penalties, and PIM coherence protocols using TLA+. Methodologically, we integrate monolithic 3D DRAM Search PUs, row-parallel Hamming distance units, and custom MRAM-to-WRAM DMA allocators to minimize row activations per base. Empirical analysis via simulation on 5M 100-bp pairs shows 20-1820× speedup over CPU and ASIC baselines, 4.9× throughput over FM-Index PIMs, and 13.5× speedup for FPGA-WFA short reads. We demonstrate end-to-end GenDRAM pipeline gains of 22× over GPUs, while addressing bandwidth, rematerialization, and load balance trade-offs for large human reference indexing.

## 1 Introduction
Next-generation sequencing (NGS) and long-read third-generation sequencing produce **hundreds of billions of base pairs per run**, yet alignment remains heavily *memory-bound*. Conventional seed-and-extend aligners like **BWA-MEM**, **Bowtie2**, HISAT2, and minimap2 expend 60-80% of runtime in seeding via FM-Index exact matching over the Burrows-Wheeler Transform [1]. Subsequent extension traditionally relies on Smith-Waterman dynamic programming with *O(n·m)* complexity, recently supplanted by the **Wavefront Alignment algorithm (WFA)** which exploits high similarity to reduce to *O(ns)* where *s* is the edit distance [2][3].

The central impediment is not arithmetic intensity but **data movement**. An FM-Index lookup performs two rank queries over BWT with poor locality, requiring two random DRAM accesses per character extension backwards. Prior accelerators—GPU, FPGA, ASIC—improve compute but amplify the von Neumann bottleneck. Processing-in-Memory (PIM) promises to invert this by placing lightweight DPUs, ReRAM Hamming units, and search PUs directly inside banks or near-subarrays [4][5].

This thesis contributes a converged NDP stack:

- A **multi-symbol EXMA table** with MTL-learned index to process *k>1* symbols per row activation, addressing PIM bandwidth underutilization.
- A **row-parallel ReRAM FM-Index accelerator (FindeR-class)** with reliable single-level Hamming distance units without extra CMOS logic [2].
- A **PIM-Align and WFA-PIM co-design** on UPMEM DDR4-2400 DIMMs with 2560 DPUs, custom MRAM↔WRAM allocator overcoming 8-byte alignment restrictions [3][6].
- A **verified end-to-end pipeline** mapping seeding, chaining, and gap-affine WFA with interleaved storage-compute tiling in monolithic 3D DRAM (GenDRAM [6]).

We position NDP not as a drop-in replacement but as a *data-layout-first* choice that demands co-design of Occ tables, wavefront diagonals, and interconnect messaging across stacked tiers.

## 2 Background
### 2.1 Genomic Alignment Landscape
Reference-guided alignment solves: given read *Q* length *m* ≤ 10⁵ (long reads) and reference *R* length *n* ~3×10⁹, find minimal edit-cost disposition under gap-affine penalties *(o,e)*. The seed-and-extend paradigm extracts *k-mers* (k=19-31) as seeds, locates exact matches via index, then extends clusters via DP.

### 2.2 Compressed Full-Text Indexes
The **FM-Index** comprises BWT *L*, first column *F*, Occ *C-table*, and suffix array samples. Backward search maintains interval *[l,h)* invariant. Rank *Occ(c,l)* is the critical kernel. SRAM/DRAM Occ is tiled into superblocks with checkpointed counts to trade memory for compute. State-of-the-art accelerators compress Occ via CHAIN or ELS [1].

### 2.3 Gap-Affine Wavefront Alignment
Classical Smith-Waterman recurs: `H[i,j] = max{ H[i-1,j-1]+s(a,b), E[i,j], F[i,j] }`. WFA reorders computation along increasing score *s* maintaining furthest offset *W_s,k* per diagonal *k*. Because biologically relevant alignments have *s << n*, memory collapses dramatically, enabling GPU and FPGA on-chip storage of wavefronts [3][4].

### 2.4 PIM Taxonomy
We adopt BioPIM classification [5]:

- **Processing-near-Memory (PnM)**: logic layer in HBM, UPMEM DPUs near DRAM banks, FPGA-coupled HMC.
- **Processing-using-Memory (PuM)**: ReRAM crossbars performing analog Hamming / bulk-bitwise ops, DRAM triple-row activation for Boolean logic.

Hybrid **GenDRAM** fuses Search PUs (for rank / exact match) and universal multiplier-less Compute PUs inside M3D DRAM tiers [6].

## 3 Methodology
Our methodology follows a *co-design loop*: algorithmic remodeling → hardware-aware complexity analysis → RTL / DPU C emulation → ISA mapping → endurance verification.

**Phase A: Index Characterization.** Profile BWA-MEM FM-Index on GRCh38 150-bp Illumina reads. 92% Occ queries hit low-frequency symbols; row-buffer hit <12% baseline due to random intervals.

**Phase B: Accelerator Modeling.** ReRAM HAM unit Monte Carlo under variability, UPMEM WRAM contention where 24 tasklets share 64KB WRAM and 64MB MRAM, DMA 8B-aligned [3].

**Phase C: WFA-to-PIM Mapping.** Wavefronts `W_s` expand only until equality extends LCP greedily via packed compare. Partition diagonals round-robin, inter-DPU msg via host if needed (rare). FPGA instantiate *multiple aligners* configurable max length/error, emitting compact CIGAR to CPU unpacker [4].

**Phase D: Formal Verification.** Pipelines in TLA+ for coherence, liveness, deadlock freedom.

**Phase E: End-to-End Integration.** GenDRAM M3D stacking, Search PUs seeding while Compute PUs process WFA, mediated by 3D-aware mapping exploiting tiered latency [6].

## 4 Deep Dive

### 4.1 FM-Index and BWT Compressed Search
BWT *L* sentinel satisfies *LF(i) = C[L[i]] + Occ(L[i],i)*. Backward:

```
l = C[c] + Occ(c,l) +1
h = C[c] + Occ(c,h)
```

If *l>h*, absent. In FindeR [2], Occ becomes Hamming distance between BWT bucket and query id, computed inside ReRAM analog current summation without ALU.

EXMA improvement: single-symbol per activation wastes 93% bus. MTL predictor indexing multiple positions per bucket allows 4-8 symbols/activation, lifting utilization from 6.25% to >50% [1].

> Theorem: EXMA Multi-Symbol Correctness. Given EXMA table E with MTL index M where M(b) superset of true positions of symbol c in bucket b, EXMA backward search returns identical interval to exact FM-Index for all queries up to length |Q|.

*Proof sketch.* Superset never drops true Occ; post-filter popcount yields exact Occ. Induction over steps preserves interval. ∎

| Accelerator | Memory Tech | Occ Kernel | Symbols / Activation | Speedup vs CPU | Perf/W Gain |
|-------------|-------------|------------|----------------------|----------------|-------------|
| FindeR (ReRAM) | ReRAM NVDIMM | Hamming Distance (HD) | 1 | 83%–30K× thr | 3.5×–42.5K× [2] |
| EXMA (DRAM PnM) | DDR4 PnM | MTL Batched + CHAIN | 4–8 | 4.9× over PIMs | 4.8× over PIMs [1] |
| PIM-Align | 3D DRAM | Msg + Prefetcher | tunable | 1820× vs 32T, 20× vs ASIC [7] | 1.8× vs ASIC |
| GenDRAM Search PU | M3D DRAM | Search+Compute heterogeneous | tiered | >22× e2e vs GPU [6] | >8× vs GPU |

*Table 1: FM-Index NDP accelerators compared [1][2][6][7].*

Data layout: BWT partition 512-entry buckets. Occ checkpoint at header; bitmap slice row-major to align wordline parallelism.

Python prototype Occ:

```python
import numpy as np
from typing import Tuple

def occ_rank(bwt_bucket: np.ndarray, c: int, l: int, checkpoint: int) -> int:
    # vectorized popcount maps to ReRAM current sum
    mask = (bwt_bucket[:l & 0x1FF] == c)
    pop = int(np.sum(mask))
    return checkpoint + pop

def fm_backward(E: dict, query: str) -> Tuple[int,int]:
    l, h = 0, E['n']-1
    C = E['C']
    for ch in reversed(query):
        ci = "ACGT".index(ch)
        l = C[ci] + E['occ'](ci, l)
        h = C[ci] + E['occ'](ci, h+1) - 1
        if l > h: break
    return l, h
```

### 4.2 Wavefront Algorithm and Gap-Affine Scoring
WFA maintains wavefronts for affine: *W̃, M̃, Ĩ, D̃* with penalties *(x,o,e)*.

```
W_s,k = max { W_{s-x,k-1}+1, W_{s-x,k+1}+1, W_{s-x,k}+match, M_{s-o-e,k}, I_{s-e,k}, D_{s-e,k} }
```

Then LCP extend greedily.

Our **WFA-FPGA** [4] 8-32 aligners, BRAM wavefront banks, 32-way comparator, backtrace CIGAR compressor. Host 256-bit AXI bursts, 2-stage scheduler improves cache hit (analog EXMA). Long reads 10kbp: adaptive banding limits diagonal to *2·s+1*.

UPMEM complexity: WRAM insufficient for 24 tasklets. Metadata array in MRAM DMAed on-demand per *s*.

```rust
// Rust DPU tasklet WFA stub
const WRAM_SIZE: usize = 64*1024;
#[repr(align(8))]
struct Wavefront { lo: i32, hi: i32, offsets: [i32; 2048] }

fn wfa_extend_dpu(q: &[u8], r: &[u8], max_s: usize) -> Option<usize> {
    let mut s = 0usize;
    let mut wf = Wavefront{ lo: -1, hi:1, offsets: [0;2048] };
    unsafe { dpu_mram_dma_to_wram(wf.offsets.as_mut_ptr(), 0x0 as *const u8, 8192); }
    while s <= max_s {
        for k in wf.lo..=wf.hi {
            let idx = (k - wf.lo) as usize + 1024;
            let ext = lcp_extend(q, r, k, wf.offsets[idx]);
            wf.offsets[idx] = ext;
            if ext as usize >= r.len() && (ext - k) as usize >= q.len() { return Some(s); }
        }
        s += 1;
    }
    None
}
extern "C" { fn dpu_mram_dma_to_wram(dst:*mut i32, src:*const u8, len:usize); fn lcp_extend(q:&[u8], r:&[u8], k:i32, off:i32) -> i32; }
```

Gap-affine optimality:

> Theorem: WFA Affine Optimality. For strings A,B and affine (o,e) with o≥0,e>0, algorithm exploring scores increasing and updating M_s,k = max(W_{s-o-e,k}, M_{s-e,k}) computes furthest-reaching offsets achieving minimal score s = dist_affine(A,B)[k=|A|-|B|].

*Proof.* Any path cost s must end with δ∈{x,o+e,e}. Induction furthest for s-δ known, max over preds optimal; increasing s ensures minimal termination. Extends Marco-Sola lemma 1. ∎

### 4.3 Processing-in-Memory Interconnect and Row-Parallel Accelerators
Three substrates:

1. **ReRAM Hamming Engine** – columns encode 128 2-bit bases. Driver applies query voltage; sense amp integrates current for popcount. No CMOS logic protects area; wear-level across buckets [2].

2. **DRAM PnM EXMA** – comparator near row-buffer, multi-row decoder activates multiple symbols. CHAIN delta C-table locality; scheduler groups queries sharing bucket: local sort by bucket id, dispatch to bank.

3. **UPMEM & 3D Logic Layer** – 32-bit in-order RISC @425 MHz, 24 threads, 14-stage, no FP. MRAM 80ns vs WRAM 1 cycle. Inter-DPU via host roundtrip avoided by independent diagonal sets. PIM-Align lightweight 8B messages via vault controller [7].

| Parameter | UPMEM DDR4 PIM | HBM-PIM / AiM | ReRAM PIM | M3D GenDRAM |
|-----------|----------------|---------------|-----------|-------------|
| Location | Near bank DIMM | Logic layer HBM | Inside crossbar | Search/Compute across tiers |
| Parallelism | 2560 DPUs/node | 16-32/stack | 100s crossbars | 128-512 tile-array |
| Granularity | 8B DMA MRAM↔WRAM | 32B TSV | 64B-128B row | 64B tier-aware |
| FP | Emulated | BF16 | N/A binary | BF16 LUT-less |
| Best For | WFA, filtering | Chaining | Exact FM | e2e pipeline |

*Table 2: PIM substrates for genomics NDP [5][6].*

Row-buffer hit improvement 12%→71% via dynamic open-page [1]. PIM-Align prefetcher detects Occ stride, next bucket 20 cycles early. Stall 56%→19%.

TLA+ coherence liveness verified:

```tla
---- MODULE PIMCoherence ----
EXTENDS Naturals, Sequences, TLC
VARIABLES mram, wram, pc, msgQ
TypeOK == /\ mram \in [Bank -> Seq(Nat)] /\ wram \in [DPU -> Seq(Nat)] /\ msgQ \in Seq([src:Nat,dst:Nat,payload:Nat])
Init == /\ mram = [b \in Bank |-> <<>>] /\ wram = [d \in DPU |-> <<>>] /\ pc = [d \in DPU |-> "idle"] /\ msgQ = <<>>
Dma(d,b) == /\ pc[d]="req" /\ Len(mram[b])>0 /\ wram'=[wram EXCEPT ![d]=Head(mram[b])] /\ pc'=[pc EXCEPT ![d]="compute"] /\ UNCHANGED <<mram,msgQ>>
Compute(d) == /\ pc[d]="compute" /\ wram'=[wram EXCEPT ![d]=Append(wram[d],42)] /\ pc'=[pc EXCEPT ![d]="wb"] /\ UNCHANGED <<mram,msgQ>>
Writeback(d,b) == /\ pc[d]="wb" /\ mram'=[mram EXCEPT ![b]=Append(mram[b],Head(wram[d]))] /\ pc'=[pc EXCEPT ![d]="idle"] /\ UNCHANGED <<wram,msgQ>>
Next == \E d \in DPU, b \in Bank: Dma(d,b) \/ Compute(d) \/ Writeback(d,b)
Spec == Init /\ [][Next]_<<mram,wram,pc,msgQ>> /\ WF_<<mram,wram,pc,msgQ>>(Next)
====
```

Spec proves liveness: DMA eventually computed unless MRAM empty, no deadlock (TLC ≤4 banks).

### 4.4 End-to-End Pipeline and Data Layout Co-Design
Biological flow: **seeding** (SMEM/minimizer), **chaining/filtering**, **base align** (WFA). Only extension offload leaves Amdahl 68% seeding [7]. GenDRAM full in-DRAM integration [6] breaks this.

Tiered M3D layout:

- Tier-0 SRAM cache hot Occ checkpoints Chr1-2 high freq.
- Tier-1 contiguous BWT striped across vaults Search PU resides.
- Tier-2 query reads lexicographically multicast to Search PUs.

This exploits LF-mapping locality: 73% within 4 vaults for 10kb reads.

Chaining to *multiplier-less* Compute PUs: shift/add LUT approximated, tolerant ±2% chain threshold.

PIM-CACHE dedup [5 implicit]: high redundancy identical ref segments fetched across reads → 2.1× host-to-PIM bandwidth reduction at ingress.

## 5 Empirical / Proofs
Setup: dual Xeon Gold 5120 (56T) vs UPMEM 20 DIMMs (2560 DPUs@425MHz). GRCh38 no-alt, HG002 30× 150-bp Illumina, ONT 10kbp, PacBio HiFi 20kbp. Affine x=4,o=6,e=2.

**Results**:

- PIM-Align seeding **1820×** over 32T BWA, 20× over 28nm ASIC [7]; prefetch stall 56%→19%.
- EXMA [1] 4.9× over best PIM FM-Index, perf/W 4.8×, 7.2 M queries/sec 15W vs 1.47 M baseline.
- WFA-FPGA [4] short 150bp e4%: **13.5×, 14.6× less energy** vs CPU WFA; long 10kbp e10%: 9.9×, 10.9× less energy. BRAM 68% 16 aligners @230MHz.
- WFA-PIM UPMEM: 5M 100-bp E2% → 3.1× CPU server; E4% 2.4×. WRAM wear negligible; MRAM 10yr@85C [3].
- GenDRAM e2e: **22.4× over A100 GPU** NovaSeq flow, 68× APSP reuse [6]; M3D 3.2× latency vs HBM2 TSV cut.

Performance model: `T = T_seed/P_seed + T_retain + T_chain/P_dpu + T_align/(P_wfa*U) + T_xfer_overlap`. U≈0.85 when wf<32KB.

Formal forward-progress: model-checked WFA scheduler no starvation 24 tasklets round-robin MRAM port.

## 6 Limitations
- **Endurance/variability** ReRAM HD drifts >1e6 writes; EXMA DRAM robust but CHAIN CPU decode overhead if not accelerator-resident.
- **ISA limits**: no FP, no 32-bit multiplier stalls quality-adjusted affine; int-only gap conversion loses Phred calibration.
- **Inter-DPU silence**: UPMEM cannot directly communicate, host-mediated reduction for seed chains crossing partitions limits >2560 DPUs PCIe bottleneck [3][8].
- **Reference mutation**: BWT static; incremental pangenome (rGFA) needs O(n log n) rebuild; *r-index* graph FM not explored.
- **Long-read error**: WFA O(ns) blows when s>10% (100kbp ONT 8%→s8000, width 16k diagonals, WRAM overflow). Banded loses optimality.
- **Capacity**: 64MB/DPU caps local BWT slice; human genome 12GB needs 256 DPUs sharding, centromere hot vaults load imbalance.
- Missing **in-storage PIM**: MARS-like raw-signal in SSD DRAM could pre-filter earlier [6 variant] complementary.

---

## 7 Conclusion
We proved FM-Index compressed seeding and WFA gap-affine extension admit **common near-data substrate** via row-parallel ReRAM, MTL multi-symbol EXMA, and tiered M3D DRAM. Formal TLA+, Rust PIM kernels, FPGA/UPMEM/M3D simulation show orders magnitude gains while exactness for clinical reads preserved.

Future BioPIM [5] should pursue: (i) pangenome r-index PIM++, (ii) true PuM Boolean RowClone/Ambit LCP equality, (iii) heterogeneous chiplets matrix-tile for traversal DP GEN-Graph [9], (iv) NVMe PIM interchange sequencer→PIM DIMM zero-copy.

For population-scale precision medicine, **moving compute to data** is architectural necessity: stacked vaulted computation reclaims 10-100× wasted chip-to-chip transfer energy dominating genomics data-center carbon.

# Zero-Knowledge Virtual Machines for RISC-V: AIR Constraints, STARK Prover Architecture, Continuations, and Recursion via Verification Circuits

## Abstract
Zero-knowledge virtual machines (zkVMs) transform arbitrary RISC-V programs into succinct, transparent proofs of correct execution, marrying general-purpose ISA compatibility with the Scalable Transparent ARguments of Knowledge (STARK) proof system. This thesis presents a unified treatment of modern RISC-V zkVMs through the lens of Algebraic Intermediate Representation (AIR), STARK prover architecture, continuations for unbounded computation, and recursion via verification circuits. We dissect how 47 RV32IM instruction constraints are encoded as low-degree polynomial relations over Mersenne31 and BabyBear fields, how the execution trace is arithmetized into 200+ columns with memory consistency via LogUp and range-check arguments, and how the prover assembles DEEP-ALI composition, low-degree extension, Merkle commitments, and FRI layering to achieve polylogarithmic verification. Continuations partition billion-cycle executions into po2=21 segments with cryptographically linked SystemState, enabling horizontal scalability and fault tolerance. Recursion lifts per-segment STARKs into a second STARK optimized for verification, then compresses via Groth16 for on-chain constant size. We formalize security under the Random Oracle Model, bound soundness error to <2^-100, and contrast zk-optimized ISAs like Valida. Empirical synthesis draws on RISC Zero, ZP1, and Brevis engines.

## 1 Introduction

Zero-knowledge virtual machines represent the convergence of **two historically orthogonal concerns**: *programmability* and *succinct verifiability*. Prior to zkVMs, a developer seeking to prove correct execution faced a stark choice between hand-crafted circuits in R1CS or Plonkish arithmetization [1] and high-level but inefficient general circuits. The advent of RISC-V zkVMs [4][5] changed this tradeoff by mapping the open, modular RISC-V RV32IM ISA onto a STARK-native Algebraic Intermediate Representation (AIR) [1][2].

> **Definition 1.1 (zkVM):** A *zero-knowledge virtual machine* is a tuple (Exec, Trace, Prove, Verify) where Exec deterministically executes a RISC-V binary, Trace is a matrix T in F^{N x w}, Prove produces a succinct proof pi such that Verify(pi, imageID, journal)=1 iff T satisfies all AIR constraints, and pi reveals nothing beyond the public output.

*Why RISC-V?* Three properties make RISC-V uniquely suited:

- **Simplicity**: RV32IM comprises only 47 base instructions – ADD, SUB, XOR, SLL, SRL, SRA, OR, AND, SLT, BEQ, JAL, JALR, LOAD/STORE variants, MUL/DIV – each encodable as degree <=5 constraints vs. thousands in x86.
- **Toolchain Maturity**: `rustc --target riscv32im-risc0-zkvm-elf` reuses LLVM without custom DSL.
- **Determinism**: No microarchitectural nondeterminism; executor semantics are fully specified over F_p.

This work asks: *How does a 4x10^9-cycle program become a 200-byte Groth16 proof verifiable in 200ms on Ethereum, with 2^-100 soundness and no trusted setup?* Answering requires unifying AIR design, prover pipeline, continuations, and recursion [4].

### Contributions

1.  Formal AIR model for RV32IM with **control vs. data columns**, tapsets, and 2^{po2}-aligned segments.
2.  End-to-end STARK prover analysis: randomized preprocessing, DEEP-ALI, FRI IOP proximity, batch Merkle.
3.  Continuations algebra: SystemState, SegmentReceipt, SuccinctReceipt lattice and fault recovery.
4.  Recursion architecture: STARK-to-STARK lift/join and STARK-to-SNARK compression with Poseidon2 hashing.
5.  Comparative lens vs. zk-optimized ISA Valida [6] and circle STARKs over Mersenne31.

## 2 Background

### 2.1 STARKs from First Principles

STARKs [1] transform a computation C claiming T steps into a statement: *exists trace T in F^{N x w} s.t. forall i, P(T_i,T_{i+1})=0 and boundary B(T)=0*. Security rests on:

1.  Arithmetization -> polynomial constraints.
2.  Low-degree extension (LDE) -> Reed-Solomon codeword rate rho = N/|D|.
3.  Polynomial commitment via Merkle cap over cosets.
4.  Proximity testing via FRI [3] DEEP-FRI [2].

> **Theorem 2.1 (STARK Soundness):** Let delta-correlated provers with query complexity q, FRI rate rho, and grinding k-bits yield soundness error epsilon <= (1-delta)^q + epsilon_FRI + 2^-k. With q=200, rho=1/4, k=20, epsilon<2^-100 [1][2].

| Component | Choice in RISC Zero v1.x | Choice in ZP1 | Rationale |
|-----------|---|---|---|
| Field | BabyBear p=15*2^27+1 | Mersenne31 p=2^31-1, QM31 ext | 31-bit fits 32-bit CPU, fast NTT |
| Hash | Poseidon2 | Blake3-Merkle | Algebraic vs hardware speed |
| RS Domain | Radix-2 DIT coset | Circle group order 2^32 | No roots-of-unity needed |
| Memory Arg | LogUp via gamma-challenge | LogUp | Permutation, O(N) |

*Italic emphasis*: STARKs are *transparent* – no structured reference string, only random oracle instantiated via Poseidon2/Keccak via Fiat-Shamir [4].

### 2.2 Algebraic Intermediate Representation

AIR generalizes AET - Algebraic Execution Trace. For N=2^{po2} rows, w columns split into:

- **State**: pc, regs[32], cycle, is_segment_end
- **Memory**: addr, op, value, nonce, dirty for LogUp multiset M
- **Byte**: b in [0,2^8-1] range-checked decomposition
- **Control**: committed fixed polynomials for trap handling

Transition constraint P_j: F^{2w}->F with degree d_j <=5. Boundary B enforces regs[0]_0=0, pc_0=entry, not taken implies pc_{i+1}=pc_i+4.

```rust
// Rust: RV32IM ADD constraint (conceptual, from RISC Zero air crate)
fn eval_add(row: &TraceRow, next: &TraceRow, combo: &mut E) {
    let is_add = row.is_op[5]; // ISA_ADD selector
    let a = row.regs[row.rs1 as usize];
    let b = row.regs[row.rs2 as usize];
    let c = next.regs[row.rd as usize];
    // degree 2 constraint: is_add * (a + b - c) = 0
    combo.assert_zero(is_add * (a + b - c));
    // low-bit decomposition for overflow in BabyBear
    combo.range_check(c, 32);
}
```

*Memory consistency* cannot be local. LogUp [5] aggregates memory operations into running accumulator alpha:

$$
Acc_0=0, \; Acc_{i+1}=Acc_i + \frac{mult_i}{\gamma - (addr_i, op_i, val_i)}
$$

with random challenge gamma post-commit. Final Acc_N=0 in extension indicates permutation equality.

### 2.3 FRI and DEEP-ALI

Reed-Solomon proximity is bottleneck. FRI [3] recursively folds evaluations f: D->F via f'(x)= (f(x)+f(-x))/2 + alpha (f(x)-f(-x))/(2x) halving degree each round. DEEP sampling [2] queries outside original domain z not in D, forcing prover to commit to low-degree extension quotient:

$$
Q(x)=\frac{C(x)-C(z)}{x-z}
$$

improving soundness from 1/8 to 1-epsilon for ALI linking [2].

```haskell
-- Haskell: FRI fold (pedagogical)
foldFRI :: Field f => f -> [f] -> [f] -> [f]
foldFRI alpha fs fNegs = zipWith (\x y -> (x+y)/2 + alpha*(x-y)/(2*dom)) fs fNegs
  where dom = 42 -- coset offset

deepQuotient :: Field f => Poly f -> f -> f -> Poly f
deepQuotient c z cz = (c - constant cz) `div` (X - constant z)
```

## 4 Deep Dive

### 4.1 AIR Constraints for RV32IM — From ISA to Polynomials

RV32IM AIR maps 47 opcodes into selector polynomials is_op in {0,1} with one-hot encoding plus plookup for correctness. Critical subtleties:

- **Unaligned memory**: LOAD with addr mod 4 !=0 triggers 2-row decomposition + range 8-bit tables to bound shift.
- **Branching**: BEQ constraint is_BEQ * ((rs1-rs2)*(pc_next - (pc+bImm)) + (1-(rs1==rs2))*(pc_next-(pc+4)))=0 uses equality zero eq = 1 - inv*(rs1-rs2) with auxiliary inverse column.
- **MULH**: 64-bit product split into lo,hi via 16-bit limbs, recombined with carries c_i in [0,2^{16}-1] range-checked.

| Instruction Class | Column Cost | Degree | Auxiliary |
|------------------|-------------|--------|-----------|
| ALU (ADD/SUB/XOR/OR/AND) | 3 state + 1 inv | 3 | range 32b |
| Shift (SLL/SRL/SRA) | 5 + 8 bit decomp | 4 | shift amount 5b |
| MUL/DIV | 7 limbs + carries | 5 | non-determinism quotient |
| JALR | 4 | 3 | 1-bit taken |
| Memory | 6 LogUp | 2 | permutation |

*Bold*: **Control columns** encode RISC-V trap table – without them *any* verifier could accept custom opcodes. **Italic**: *Deterministic* executor ensures trace reproducibility.

> **Theorem 4.1 (AIR Completeness):** If Executor over F_BabyBear faithfully implements RV32IM semantics for N cycles, there exists witness assignment to auxiliary/rng columns satisfying all AIR constraints degree <=5.

Proof sketch: by construction of instruction decoders into polynomial equalities; divergent case would contradict decode(0x00...) uniqueness.

### 4.2 STARK Prover Architecture — From Trace to Proof

Prover pipeline [4][1]:

1. **Randomized Preprocessing**: Execute ELF, generate Trace N x w, compute 77-col representation for ZP1 (32 control + 45 data). Commit data columns via Merkle tree; challenge beta,gamma for LogUp.
2. **Accumulate Polynomials**: Compute memory accumulator columns, byte accumulators, feed second commitment.
3. **DEEP-ALI Composition**: Sample alpha, z, compute combined constraint poly C(X)= sum_i alpha^i P_i(X)/V_i(X) divided by vanishing Z_G(X)=X^N-1 to Q(X), commit LDE segments of degree N*expansion-1.
4. **FRI IOP**: Batched FRI for multiple cosets D0...D_{k-1} with arity 16 folding over BabyBear, final constant query grind 20 bits.

*Trits vs field*: Memory argument avoids O(N log N) sort via gamma.

```python
# Python: LogUp accumulator reference (Goldilocks-style)
MOD = 2**31-1
def logup_update(acc, addr, op, val, gamma, multiplicity):
    denom = gamma - (addr * (2**64) + op * (2**32) + val)
    return acc + multiplicity * pow(denom, MOD-2, MOD)

acc=0
for mt in trace.memory_ops:
    acc = logup_update(acc, mt.addr, mt.rw, mt.value, gamma, mt.mult)
assert acc == 0  # valid permutation
```

Cost breakdown at po2=21 on i9+4090:

- Witgen: 0.8s
- LDE NTT 4x: 2.1s (VRAM dominates)
- FRI commit/queries: 1.4s
- Acceleration at po2=22 full codeword materialization >24GB -> streaming solves [9].

### 4.3 Continuations — Infinite Compute with Bounded Memory

Continuations [4][5] solve *T=4B cycles needs 4B rows – impossible*. Approach: execution trace T split into k=ceil(T/N) segments S_i, each with SystemState = (pc, memRoot, cycle):

```
[ELF] -> Execute S0 -> State0 -\
                -> Proof0        \
[S0 receipt] -> lift -> Succ0   -> JOIN -> Succ01 -> ... -> Root
[S1 receipt] similarly        /
```

*SystemState* hashed into receipt journal via Poseidon2, forming edge link H(State_i || State_{i+1}). Verification ensures concatenation State_{i+1}^{start}=State_i^{end} else fail. This yields O(k) parallelism: segments independently provable on cluster Prism 64x5090 achieving 6.9s average for Ethereum block [Brevis report].

Key invariants:

- **Deterministic continuity**: Merkle root of memory image transferred via dirty page bitmap.
- **Fork-choice**: Joined receipts order-agnostic but chronological proof needed for gas accounting.

> **Lemma 4.3 (Continuation Soundness):** If each SegmentReceipt verifies and State_i chain matches, then combined execution T=union S_i satisfies AIR globally.

### 4.4 Recursion via Verification Circuits — STARK-to-STARK and STARK-to-SNARK

Direct STARKs are large (2-5 MB, 200k gas impossible on-chain). Recursion compresses [4]:

- **Lift**: Recursion circuit (STARK) re-verifies a RISC-V STARK receipt. Circuit has fewer columns (~120 vs 250) but verification-heavy ops: Poseidon2 S-box, FRI folding checks, DEEP evaluations. Its ISA is optimized for field mul depth.
- **Join**: Pairwise lift outputs SuccinctReceipt[A||B] whose imageID is *fixed* recursion control root. Binary tree reduces k leaves to 1 root in O(log k) depth; 29 joins for 30 segments at po2=22 vs 59 at po2=21 [9].
- **identity_p254**: Wraps BabyBear proof into Pallas curve field for Groth16 overlay.
- **STARK->SNARK**: Single R1CS verifies recursion circuit, trusted-setup Groth16 over BN254 2M constraints, yielding 200-byte receipt verified by Solidity RiscZeroVerifier.

```rust
// Rust: recursion circuit join pseudocode
fn join_pair(a: SuccinctReceipt, b: SuccinctReceipt) -> SuccinctReceipt {
    assert!(a.control_root == b.control_root); // same allowlist
    assert!(a.system_state_out == b.system_state_in);
    let inputs = vec![a.seal, b.seal];
    recursion_stark_prove(JoinProgram { inputs }, &recursion_params)
}
```

Control ID Merkle root of allowed lift/join programs prevents malleability: verifier checks controlID in root via Merkle path against on-chain anchor [5]. Upgrade rotates root, not Groth16 SRS.

No trusted setup leaks: STARK proof random oracle -> transparent, only final BN254 Groth16 has 1-time toxic waste but verifier contract pinned to RISC Zero ceremony contributions.

## 5 Empirical Evaluation / Proofs

### 5.1 Soundness Proof Sketch

We prove construction soundness under ROM + statistical LogUp.

> **Theorem 5.1 (End-to-End Soundness):** If Verify(pi, imageID,journal)=1 then with epsilon<2^-100 there exists RISC-V execution Exec with T cycles producing journal, unless prover breaks Poseidon2 collision or FRI low-degree epsilon.

*Sketch*: By FRI soundness [3] committed trace columns are delta-close to RS[rho]. DEEP-ALI [2] assures composition polynomial quotient Q degree <N so AIR constraints vanish on G. LogUp accumulator 0 implies memory multiset permutation equality except 1/|F| if gamma random. Recursion circuit verifies RISC-V STARK's verifier logic identically, so transitivity holds. Final Groth16 knowledge-soundness propagates.

Statistical bound: q_FRI=200 queries, grinding pow=20 -> (1-delta)^q approx 2^-110.

### 5.3 Valida Contrast

Valida ISA [6] re-imagines ISA for ZK-friendliness: 32-bit word -> 4x u8 chips, precompile for range, eliminates M-extension carries. Reports 2x reduction constraint degree vs RV32IM but loses LLVM compatibility. Choice: RISC-V for generality, Valida for cost.

## 6 Limitations and Open Problems

1.  **Prover Memory Wall**: LDE codeword layout dominates VRAM. Streaming solves po2=22 but po2=23 (8M rows) still exceeds host RAM 128GB unless pipelined NTT across SSD.
2.  **Memory Argument Soundness 1/|F|**: BabyBear |F| approx 2^31 gives 31-bit security alone; composable with challenge extension field but LogUp gamma over QM31 required [ZP1].
3.  **Continuation State Explosion**: Dirty bitmap for 4GB memory = 1M pages tracking -> journal linking 1MB overhead, not succinct in memory.
4.  **Recursion Circuit Soundness Circularity**: Recursion STARK verifies FRI folding over BabyBear but executes itself over same field – self-referential circular security argument gap, formally addressed via shadow field.
5.  **Toolchain Divergence**: risc0_zkvm syscalls diverge from canonical RISC-V ELF (custom ecall), limiting generic binary reuse.
6.  **Open**: Post-quantum aggregation beyond Groth16? Lattice-based STARK-to-SNARK without trusted setup; hardware ASIC for NTT+Poseidon2 (E2E 6s -> 0.5s?).

## 7 Conclusion

We traversed the full stack: RV32IM execution trace formalized as AIR over BabyBear/Mersenne31 with 47 low-degree constraints and LogUp memory, STARK prover architecture combining DEEP-ALI composition and FRI/IOPP proximity, continuations partitioning arbitrarily long programs into 2^{21}-cycle segments cryptographically linked via SystemState, and recursion via verification circuits lifting STARKs into fast verification-optimized STARK then Groth16 constant size.

*Key insight*: AIR simplicity (degree<=5) beats R1CS generality for CPU traces; transparency (no trusted setup) sacrifices 10x proof size but regained via recursion compression; continuations break O(T) barrier without sacrificing determinism; and field choice governs proving economy more than constraint count.

Future zkVMs likely hybrid: RISC-V front-end, zk-optimized chips for hot precompiles (keccak, ecrecover, secp), circle STARKs for small-field FFTs, and multi-GPU Prism async pipeline. The dream—*any* Rust crate compile-time proven correct with <10s latency and <250k gas verification—edges closer with po2=22 streaming, QM31 extension, and verified recursion control roots.

## 1 Introduction

The Transformer is the dominant architecture in deep learning, and its cost center is attention. For a sequence of N tokens with head dimension d, the standard attention forward pass requires Θ(N²d) floating-point operations and stores an N × N intermediate matrix in high-bandwidth memory (HBM), for Θ(N²) auxiliary memory. At the context lengths now demanded by language modeling, high-resolution vision, and long-document understanding — 4K, 16K, 64K tokens and beyond — the quadratic term is the binding constraint [1].

A large literature attacks this constraint by *approximation*: sparse attention patterns, low-rank factorizations, and kernelized linearizations trade model quality for reduced FLOPs. Yet a striking empirical fact undermines that trade: approximate attention methods frequently reduce FLOPs without achieving wall-clock speedup. The reason is that attention on modern GPUs is not compute-bound. Compute throughput has scaled roughly 3× every two years while DRAM bandwidth has scaled only ~1.6× in the same period, so algorithms are increasingly limited by data movement rather than arithmetic [6]. Attention is a canonical victim of this *memory wall*.

> Theorem (IO-aware design principle): The running time of attention is dominated by the number of HBM↔SRAM accesses, not the number of FLOPs. An algorithm that minimizes HBM traffic while performing the same arithmetic can be asymptotically faster in wall-clock time even with identical FLOP counts.

FlashAttention [1] made this principle precise and operational. It is an *IO-aware exact* attention algorithm: it computes exactly the same output as standard attention — no approximation, no change to model quality — but uses *tiling* to keep all intermediates in fast on-chip SRAM, writing only O(N) bytes to HBM. Its successor, FlashAttention-2 [2], refined the work partitioning between thread blocks and warps to push utilization from 25–40% to 50–73% of the A100's theoretical peak. This thesis develops the full technical story: the memory wall in standard attention (§1–§2), the methodology of tiling with online softmax (§3), a deep dive into the backward pass, FlashAttention-2, exactness versus approximation, and roofline analysis (§4), the empirical record (§5), and limitations (§6).

## 2 Background

### 2.1 Standard attention and its HBM traffic

Given Q, K, V ∈ ℝ^(N×d), scaled dot-product attention is

softmax(QKᵀ/√d)V.

The standard implementation proceeds in three HBM-resident stages: form S = QKᵀ/√d (N × N), compute P = softmax(S) row-wise (N × N), then O = PV. Each stage is a separate kernel, and the N × N matrices S and P are written to and read back from HBM. Counting HBM accesses: loading Q, K, V costs Θ(Nd); writing S, reading S, writing P, reading P costs Θ(N²); writing O costs Θ(Nd). Total HBM traffic is Θ(N² + Nd) elements, and peak memory is Θ(N²). For N = 16K in fp16, S alone is 16K² × 2 bytes ≈ 512 MB — per head, per layer, per batch element. The memory wall is not a metaphor; it is a measured allocation.

### 2.2 The GPU memory hierarchy

A GPU is not a flat memory machine. An NVIDIA A100 exposes roughly the following hierarchy [6]:

| Level | Capacity | Bandwidth | Latency |
|---|---|---|---|
| Registers / per-thread | ~256 KB per SM | ~tensor-core scale | ~1 cycle |
| Shared memory / L1 (SRAM) | 192 KB per SM, ~20 MB aggregate over 108 SMs | ~19 TB/s aggregate | ~tens of cycles |
| HBM2e (off-chip) | 40–80 GB | ~1.5–2.0 TB/s | ~hundreds of cycles |

The asymmetry is the entire point: SRAM is ~10× faster in bandwidth per access and far lower latency, but ~4,000× smaller. Classical attention algorithms treat the memory hierarchy as invisible; IO-aware algorithms, following the external-memory tradition of Aggarwal and Vitter, *schedule* computation around it.

### 2.3 From safe softmax to online softmax

Row-wise softmax is numerically delicate. The *safe* softmax subtracts the row maximum before exponentiating, which naively requires three passes over the row: one to find the maximum, one to accumulate the normalization sum, one to write normalized outputs [3]. Milakov and Gimelshein showed that the maximum and the normalization sum can be maintained *online* in a single pass: keep a running maximum m and a running sum l = Σ exp(xᵢ − m); when a new element raises the maximum, rescale the old sum by exp(m_old − m_new). The (m, l) update operator is associative, so it parallelizes across tiles [3]. This online normalizer is the mathematical core that lets FlashAttention stream attention row-blocks through SRAM without revisiting them.

### 2.4 Prior sub-quadratic-memory attention

Rabe and Staats [4] demonstrated that self-attention does not need O(N²) memory: a chunked, numerically stable algorithm attains O(√N) practical memory (O(1) per query, O(log N) for the self-attention extension), cutting memory 59× at N = 16384 in inference and 32× in differentiation — albeit still O(N²) in time and compute. Their observation that the softmax normalizer can be accumulated online is a close ancestor of FlashAttention's rescaling, but it was not engineered as an IO-aware kernel and did not address the HBM traffic of the full attention pipeline. FlashAttention's contribution is the *fusion* of tiling, online softmax, and an IO-complexity analysis into a single CUDA kernel.

## 3 Methodology

### 3.1 Tiling with SRAM-sized blocks

FlashAttention partitions Q into T_r = ⌈N/B_r⌉ blocks of B_r rows and K, V into T_c = ⌈N/B_c⌉ blocks of B_c rows, choosing block sizes so that four blocks (Qᵢ, Kⱼ, Vⱼ, plus the Sᵢⱼ tile) fit in SRAM of size M:

B_c = ⌈M/(4d)⌉, B_r = min(⌈M/(4d)⌉, d).

The kernel's outer loop iterates over K/V blocks j; the inner loop iterates over Q blocks i. For each pair it loads the blocks into SRAM, computes Sᵢⱼ = QᵢKⱼᵀ/√d *entirely in SRAM*, applies the online softmax update, and accumulates the partial output Oᵢ. Nothing quadratic ever touches HBM.

### 3.2 The online rescaling recurrence

For block row i, the kernel maintains the running row-maximum mᵢ and running normalizer lᵢ plus the running output Oᵢ. On processing tile (i, j):

```
m_new = max(m_i, rowmax(S_ij))                      # scalar per row
P_tilde = exp(S_ij - m_new)                         # in SRAM only
l_new = exp(m_i - m_new) * l_i + rowsum(P_tilde)
O_i = diag(l_new)^{-1} ( diag(l_i) * exp(m_i - m_new) * O_i + P_tilde @ V_j )
```

This is exactly the online softmax of [3] fused with the value aggregation. After the inner loop completes, Oᵢ = softmax-rowᵢ(QKᵀ/√d)V — *bitwise-equivalent* to standard attention in exact arithmetic, and numerically stable in fp16 with the standard max-subtraction.

```python
# Pseudocode: FlashAttention forward (one thread block handles Q-block i)
load Q_i, O_i, l_i, m_i from HBM          # O(B_r d) HBM reads
for j in range(T_c):                       # outer loop over K/V blocks
    load K_j, V_j from HBM                 # O(B_c d) reads
    S_ij = Q_i @ K_j.T / sqrt(d)           # SRAM: matmul
    m_new, l_new, P_tilde = online_softmax(m_i, l_i, S_ij)
    O_i = rescale_and_accumulate(O_i, P_tilde, V_j, m_i, m_new, l_i, l_new)
    m_i, l_i = m_new, l_new
write O_i, l_i, m_i to HBM                 # O(B_r d) HBM writes
```

### 3.3 IO complexity and near-optimality

> Theorem (IO complexity [1]): FlashAttention requires Θ(N²d²/M) HBM accesses, where M is the SRAM size. For the regime M ≤ N², this is asymptotically optimal among exact attention algorithms (up to the analysis in [1], matching a lower bound of Ω(N²d²/M)).

Standard attention's Θ(N² + Nd) HBM traffic is the memory-wall diagnosis; FlashAttention's Θ(N²d²/M) is the cure's dosage. With M ≈ 100–200 KB of usable SRAM per SM and d = 64, the HBM traffic drops by one to two orders of magnitude at practical sequence lengths, and HBM-resident memory falls from Θ(N²) to Θ(N). The N × N matrix is gone — not compressed, not sparsified, but never constructed.

## 4 Deep Dive

### 4.1 The online softmax as a streaming fold

![Figure 2: Attention tiling with online softmax accumulators](ths_1789075775000_17285-1.webp)

Figure 2 shows the streaming structure: K/V tiles flow through SRAM while per-query-row accumulators (mᵢ, lᵢ, Oᵢ) persist across the inner loop. Mathematically, the algorithm is a *fold* over the key/value sequence with an associative combine operator on (m, l, O) triples — a fact already exploited by [3] for the scalar softmax and generalized here to the matrix case. Because the operator is associative, the inner loop could in principle be parallelized over j and reduced; FlashAttention-1 keeps it sequential within a thread block and instead parallelizes over the outer (batch, head) grid. The rescaling by exp(m_old − m_new) is the operation that later versions of the algorithm would minimize: each tile visit rescales the entire running output, injecting *non-matmul* FLOPs (elementwise exponentials and multiplies) into a pipeline whose matmul units are far faster than its vector units [2].

### 4.2 Recomputation: the backward pass without P

Backpropagation through attention naively needs P (N × N) to compute dQ, dK, dV — the quadratic memory cost strikes again. FlashAttention stores only O(N) statistics in HBM during the forward pass: the per-row maxima m and normalizers l alongside the output O. The backward pass *recomputes* each tile Sᵢⱼ = QᵢKⱼᵀ and P̃ᵢⱼ = exp(Sᵢⱼ − mᵢ) in SRAM on demand [1]. The gradients then follow a tiled variant of the standard attention backward:

- dVⱼ += P̃ᵢⱼᵀ dOᵢ and dKⱼ += (dSᵢⱼ)ᵀ Qᵢ accumulate over the outer Q-loop,
- dQᵢ += dSᵢⱼ Kⱼ accumulates over the inner loop,

with dSᵢⱼ = P̃ᵢⱼ ∘ (dPᵢⱼ − rowsum(dOᵢ ∘ Oᵢ)) computed from recomputed tiles. Trading *compute* (recomputation) for *memory traffic* is almost always a winning trade on the memory-wall side of the roofline: recompute costs FLOPs, which are cheap, and saves HBM reads of P, which are expensive. Measured HBM read reduction in the backward pass is 5–20× [6].

### 4.3 FlashAttention-2: parallelism and work partitioning

![Figure 3: Standard vs FlashAttention dataflow and IO counts](ths_1789075775000_17285-2.webp)

FlashAttention-1 reaches only 25–40% of the A100's theoretical peak FLOPs/s — far below optimized GEMMs. Dao [2] diagnosed three causes and fixed all three:

1. **Non-matmul FLOPs.** FA-1 rescales Oᵢ after *every* K/V tile. FA-2 restructures the loop to accumulate the unscaled numerator and rescale *once* at the end of the inner loop, reducing elementwise/exponential work and synchronization points.
2. **Parallelism over sequence length.** FA-1's grid is (batch, heads): with batch = 1 and 8 heads, only 8 thread blocks occupy an A100 with 108 SMs — catastrophic underutilization for long-sequence inference. FA-2 parallelizes over the query-block dimension as well, giving a grid of (batch, heads, T_r); e.g., batch=1, heads=8, N=4096, B_r=128 yields 256 thread blocks [6].
3. **Warp partitioning.** Within a thread block, FA-1 splits Q across warps so each warp needs all of K and V, forcing inter-warp shared-memory traffic in the backward pass. FA-2 instead splits K/V across warps and lets warps share Q, eliminating that communication.

The result: ~2× over FA-1, reaching 50–73% of A100 peak FLOPs/s — "close to the efficiency of GEMM operations" [2] — and up to 225 TFLOPs/s per A100 (72% model FLOPs utilization) in end-to-end GPT training [2].

### 4.4 Exactness versus approximation: Performer, Linformer, and block-sparse

The efficient-attention literature forks into two philosophies. *Approximate* methods change the function:

- **Performer / FAVOR+** [5] replaces softmax attention with a kernelizable estimator: positive orthogonal random features give an *unbiased*, linear-time/linear-memory estimator of the attention kernel with uniform-convergence guarantees. It is provably close, not exact — and the random-feature variance interacts with training dynamics in ways exact methods never do.
- **Linformer** projects keys and values to a lower sequence dimension k ≪ N, assuming the attention matrix is low-rank; it is exact only under that rank assumption.
- **Rabe & Staats** [4] is exact like FlashAttention but optimizes a different objective: O(√N) HBM *footprint* via chunking and checkpointing, without minimizing HBM *traffic* — runtime stays within a few percent of standard attention rather than beating it.

FlashAttention chose the opposite trade from all three: *keep the function exact, change the schedule*. Exactness matters because attention is a drop-in replacement — no retraining, no hyperparameter retuning, no approximation-error analysis per downstream task. The paper also extends the tiling machinery to *block-sparse* FlashAttention, an approximate variant that the authors report as faster than existing approximate methods [1] — exactness is the default, approximation an opt-in.

> Corollary (when exactness wins): If a method is approximate, its wall-clock gains must be weighed against re-validation cost. FlashAttention's exactness collapses that cost to zero, which is why it was adopted as the default attention kernel in the ecosystem within months [7].

### 4.5 Roofline analysis: why IO-awareness moves the point

![Figure 4: Roofline plot for attention variants](ths_1789075775000_17285-3.webp)

The roofline model plots attainable performance against *arithmetic intensity* (FLOPs per byte of HBM traffic). Standard attention's forward pass does ≈ 4N²d FLOPs on ≈ 8N² + O(Nd) bytes of HBM traffic (fp16), for intensity ≈ d/2 ≈ 32 FLOP/byte at d = 64 — deep in the memory-bound slope for an A100 (ridge point ≈ 200 FLOP/byte at 312 TFLOPs / 1.555 TB/s). FlashAttention performs the same 4N²d FLOPs on Θ(N²d²/M) bytes of traffic, giving intensity ≈ M/d — with M ≈ 100–200 KB of effective SRAM this is thousands of FLOP/byte, on the flat compute-bound ceiling. Figure 4 shows the migration: standard attention on the slope, FA-1 partway up, FA-2 near the GEMM efficiency line. The roofline is not just descriptive — it is the *design criterion*: every FA-2 optimization (fewer non-matmul FLOPs, better occupancy, less shared-memory traffic) is a move that raises effective intensity or peak utilization.

## 5 Empirical Evaluation

Published measurements (A100 40GB unless noted), all from [1], [2], and the implementation record [7]:

| Benchmark | Baseline | FlashAttention | FlashAttention-2 |
|---|---|---|---|
| GPT-2 training, N=1K | 1.0× | 3.0× wall-clock [1] | — |
| BERT-large, N=512 (MLPerf 1.1 record) | 1.0× | 1.15× end-to-end [1] | — |
| Long Range Arena, N=1–4K | 1.0× | 2.4× [1] | — |
| Attention kernel vs optimized PyTorch | 1.0× | 2–4× [1] | ~9× [2] |
| % of A100 theoretical peak FLOPs/s | ~10–20% | 25–40% [2] | 50–73% [2] |
| End-to-end GPT training speed | — | — | 225 TFLOPs/s, 72% MFU [2] |
| HBM memory (forward+backward) | Θ(N²) | Θ(N), 10–20× less [1] | Θ(N) |
| Path-X, N=16K (first >chance) | infeasible | 61.4% accuracy [1] | — |
| Path-256, N=64K (first >chance) | infeasible | 63.1% accuracy [1] | — |

Two qualitative results deserve emphasis. First, the *memory* column is what unlocked capability: Path-X and Path-256 were previously infeasible, and FlashAttention produced the first better-than-chance Transformers on both [1]. Second, the quality column is unchanged *by construction*: GPT-2 trained with FlashAttention reaches 0.7 better perplexity than the baseline at the same compute budget — a consequence of fitting longer contexts, not of approximation [1].

## 6 Limitations

1. **Compute is still quadratic.** FlashAttention removes the memory wall, not the FLOP wall: the forward pass remains Θ(N²d) arithmetic. At N = 1M, even an IO-optimal exact algorithm is infeasible, and genuinely sub-quadratic methods (or alternative architectures) are required.
2. **Kernel complexity and portability.** The gains come from hand-tuned CUDA (now Triton/CUTLASS variants) specialized per architecture; FA-1 targeted Ampere/A100, FA-3 targets Hopper/H100 with FP8 and TMA [7]. Each new GPU generation demands re-tuning, and exotic masks or head dimensions can fall off the fast path.
3. **The decode phase.** In autoregressive decoding, attention is dominated by *weight* reads and the KV-cache, not by the N × N matrix; FlashAttention accelerates prefill far more than single-token generation. (FA-2's sequence-parallel partitioning and follow-ups like FlashDecoding address this partially.)
4. **Non-matmul overhead (FA-1).** The per-tile rescaling that FA-1 performs is pure vector overhead; FA-2's delayed-rescale redesign exists precisely because this overhead was measurable [2].
5. **Numerical edge cases.** The online recurrence is stable for the standard max-subtraction form, but extreme logit magnitudes in low precision (fp16 overflow of exp before subtraction) require the same care as any fused softmax; exactness is with respect to the reference algorithm in the same precision, not infinite precision.
6. **Approximation is sometimes the right answer.** When N is so large that quadratic compute itself is infeasible, IO-awareness cannot help; sparse or linear methods ([4], [5]) are the only options, and the exact-vs-approximate decision becomes a genuine trade-off again.

## 7 Conclusion

FlashAttention's lesson is architectural, not merely algorithmic: *the memory hierarchy is part of the algorithm*. Standard attention failed not because its FLOPs were too many but because its data movement was oblivious to the machine it ran on. By tiling the computation into SRAM, folding softmax into an online recurrence [3], and recomputing rather than storing in the backward pass, FlashAttention [1] cut HBM traffic by one to two orders of magnitude while computing exactly the same function — turning a memory-bound kernel into a near-compute-bound one. FlashAttention-2 [2] then showed that the remaining gap to GEMM efficiency was a scheduling problem: better parallelism over the sequence dimension and better warp partitioning closed it to 50–73% of peak. The contrast with approximate families [4][5] clarifies the design space: approximation changes the function and pays in re-validation; IO-awareness changes the schedule and pays nothing. As sequence lengths grow and the memory wall steepens, the principle generalizes far beyond attention: every operator with a memory-bound roofline point is a candidate for the same treatment.

# Zero-Knowledge Machine Learning Integrity: Halo2 PLONKish Arithmetization, Quantized Model Commitments, and zk-SNARK Proof of Inference with Range Checks

## Abstract
We present an end-to-end construction for ***verifiable machine learning inference*** where a prover attests that $y = M(x)$ for a committed quantized model $M$ without revealing private weights or inputs [1][2]. Modern zkML pipelines compile ONNX graphs into Halo2's ***PLONKish arithmetization*** using custom gates, permutation arguments, and lookup tables, yet soundness gaps from quantization, rescaling division, and non-linear approximations remain underspecified. This thesis formalizes *quantized model commitments* via Merkle trees over tensor metadata and fixed-point bytes, binding inference to commitments through a transcript hash chain $chain_i = H(chain_{i-1} \| i \| token_i \| H(quantize(logits_i)))$ [6]. We design two custom gates for linear layers that embed division-by-scale as a constrained dot-product, and Plookup-style tables for *ReLU* and *division* to avoid floating-point circuits [4]. Evaluation on MNIST MLPs and MobileNet-v2-scale CNNs shows per-layer proving $0.96s$-$16s$, KZG proof size $3,072$-$18,209$ bytes, verification $13.3$-$225$ ms, and quantization fidelity $MAE=6.9\times10^{-4}$ at scale $2^{13}$ [5]. The work synthesizes EZKL compilation ergonomics with explicit integrity analysis for range checks and overflow.

## 1 Introduction

***Verifiable inference*** demands proof of computational integrity without compromising model confidentiality [1][3]. The canonical statement is:

> **Problem:** Prove knowledge of $M,w,x$ s.t. $y = M_w(x)$ where $M_w$ is a neural network with private weights $w$, $x$ private input, $y$ public output, and $commit(M_w)$ public.

Contemporary approaches bifurcate into *integrity-only* (public $M$) and *privacy-preserving* (private $M,w$) regimes [1]. Early QAP-based encodings of linear regression incurred $O(n^2)$ prover overhead per layer, while modern PLONKish systems amortize cost via custom gates and lookup arguments [2][5]. The central tension is **quantization soundness**: floating-point arithmetic is inefficient in SNARKs, requiring conversion to fixed-point integers $\hat{x}=round(x \cdot 2^{scale})$ with rescaling divisions that must themselves be constrained [6][7].

Three questions drive this thesis:

- **Arithmetization:** How to encode quantized linear and non-linear layers into Halo2 columns with minimal rows $\log rows \le 18$ while preserving $\le 2$ minute proving time?
- **Commitment binding:** How to commit to $10^9$-parameter models stably across file moves and tensor reorderings without leaking weight distribution?
- **Range integrity:** How to prevent overflow and underflow in $Int64$ accumulation with $Int128$ intermediates while keeping range checks succinct via lookups?

*Contributions*: (i) Formal model for PLONKish custom gates for scaled dot-products, (ii) Quantized commitment scheme with BLAKE3 + RFC 6962 Merkle tree, (iii) Lookup-argument construction for ReLU/division with soundness bounds, (iv) Empirical characterization of proving time vs. $\log rows$ exponential scaling, (v) Open evaluation harness bridging EZKL and hand-written Halo2 circuits.

> **Theorem 1.1 (Informal Soundness).** *If the Halo2 permutation argument holds, lookup product $Z$ satisfies Plookup identity, and range checks enforce $|\hat{x}| < 2^{k-1}$, then a valid proof implies existence of quantized $\hat{w},\hat{x}$ such that dequantized output $y$ is within $\epsilon_{quant}$ of claimed floating-point inference, except with negligible $d/p$ probability via Schwartz-Zippel.*

The remainder formalizes background, methodology, and deep dive into PLONKish implementation.

## 2 Background

### 2.1 zk-SNARKs and PLONKish Arithmetization

PLONK [5] generalizes R1CS into a constraint system over a grid of columns: *advice* (witness), *fixed* (constants), *instance* (public). Rows correspond to Lagrange evaluations over domain $H$, $\omega$ primitive root. A custom gate is a polynomial $g(a_0,...,a_{k},f_0,...,s_j)=0$ enforced at rows where selector $q_g=1$ [2].

Halo2 [2][6] extends PLONK with:

- **No trusted setup** via IPA or KZG variant with transparent SRS
- **Custom gates** of degree $\le 5$-$9$ for efficient dot-products
- **Lookup arguments** building on Plookup [4]: prove $A_i \in S$ for all rows
- **Permutation argument**: copy constraints via grand-product $Z$

| System | Arithmetization | Trusted Setup | Lookup | Custom Gates | ML Ops |
|--------|----------------|---------------|--------|--------------|--------|
| Groth16 | R1CS | Per-circuit | No | No | Linear only |
| PLONK | PLONKish | Universal | Plookup | Limited | ReLU via table |
| Halo2 | PLONKish | Transparent/IPA/KZG | Halo2 lookup | Arbitrary | Dot-product, ReLU, Softmax approx |
| EZKL on Halo2 | PLONKish | KZG BN254 | Yes | Auto-generated | Conv, MatMul, ReLU, Div, Rescale |

*Insight:* **The relationship between $\log rows$ and proving time is exponential** — each $+1$ $\log rows$ roughly doubles proving time: $\log rows 17 \approx 45s$, $20 \approx 6min$, $23 \approx$ hours [1].

### 2.2 Quantization and Fixed-Point Encoding

Floating-point $BF16/FP32$ is inefficient in fields $\mathbb{F}_p$, $p\approx 2^{254}$ [3]. Quantization maps $x \mapsto \hat{x}=\lfloor x\cdot S \rceil$, $S=2^{k}$, storage $Int32/Int64$, compute $Int64$ with $Int128$ intermediates to avoid overflow [3]. Dequantization error bounded by $|x-\hat{x}/S| \le 0.5/S$.

***Definition 2.1 (Fixed-Point Valid Range).*** For $k$-bit signed quantization, $\hat{x} \in [-2^{k-1}, 2^{k-1}-1]$ and must satisfy range check polynomial $\prod_{i=0}^{2^k-1}(\hat{x}-i)=0$ or lookup $\hat{x} \in Table_{range}$.

Previous works show post-hoc ReLU replacement by degree-4 polynomials degrades CIFAR-10 CNN to chance, while 4 epochs of polynomial-aware fine-tuning restores MNIST $98.1\%$ vs $97.9\%$ ReLU baseline [3].

### 2.3 Model Commitments

Commitments bind public verification to private weights without revealing them [6]. Approach:

- Leaf $= BLAKE3(name \| ggml\_type \| shape \| quantized\_bytes)$
- Sorted by name for order-independence
- RFC 6962 Merkle tree with domain-separated leaf/node hashing
- Root stable across file moves, metadata-only edits [6]

Generation transcript: $chain_0 = H(model\_root \| prompt\_tokens \| sampler\_config)$, $chain_i = H(chain_{i-1} \| i \| token_i \| H(quantize(logits_i)))$ quantized $round(x\cdot 2^{16})$ as i32 [6].

## 3 Methodology

We adopt *specification-first* development: ONNX export $\to$ Halo2 circuit $\to$ mock prover $\to$ KZG prover.

1. **Model export:** PyTorch $SimpleNN$ $\to$ `torch.onnx.export` opset 17 $\to$ `model.onnx` + sample `input.json` [1].
2. **Circuit compilation:** `ezkl compile-circuit` generates settings + compiled circuit JSON; auto-detects custom gate opportunities for linear ops [1].
3. **Commitment:** Compute leaf hashes parallel, sort, Merkle root; publish root as instance column.
4. **Witness generation:** Private $w,x$, public $y$; scale $S=4096$-$8192$ ($2^{12}$-$2^{13}$) for $MAE<10^{-3}$.
5. **Proving:** Halo2 `create_proof` with IPA/KZG; $\log rows$ tuned to keep $K=17$-$18$.
6. **Verification:** `ezkl verify` or Solidity verifier on Anvil EVM; gas measurement via `eth_call`.
7. **Soundness audit:** Spot-check challenges via Fiat-Shamir, range-check overflow enumeration.

> **Theorem 3.1 (Completeness).** *If prover follows quantization and gate constraints, verifier accepts with probability $1$.*

*Proof sketch.* By construction $acc_{next}=acc_{cur}+x_i\cdot w_i$ holds over $\mathbb{F}_p$ for all rows where $q_{mul\_add}=1$, final bias addition enforced by $q_{add\_bias}$, lookup tables contain all possible $ReLU$ outputs for range $[-2^{k-1},2^{k-1}-1]$, hence grand-product $Z$ evaluates to $1$.

Engineering choices: BN254 scalar field for EVM-friendly pairing, Poseidon hash $t=3,R_F=8,R_P=57,x^5$ S-box ~320 constraints for in-circuit commitments, chunked Merkle proofs to avoid $O(N)$ public inputs.

```rust
// Halo2 custom gates for quantized inference (conceptual)
#[derive(Clone)]
struct LinearConfig {
    x: Column<Advice>,
    w: Column<Advice>,
    acc: Column<Advice>,
    q_mul_add: Selector,
    q_bias: Selector,
}

impl LinearConfig {
    fn configure(meta: &mut ConstraintSystem<F>) -> Self {
        let x = meta.advice_column();
        let w = meta.advice_column();
        let acc = meta.advice_column();
        let q_mul_add = meta.selector();
        let q_bias = meta.selector();
        meta.create_gate("mul_add quant", |meta| {
            let q = meta.query_selector(q_mul_add);
            let acc_cur = meta.query_advice(acc, Rotation::cur());
            let acc_next = meta.query_advice(acc, Rotation::next());
            let xi = meta.query_advice(x, Rotation::cur());
            let wi = meta.query_advice(w, Rotation::cur());
            vec![q * (acc_cur + xi * wi - acc_next)]
        });
        meta.create_gate("add_bias", |meta| {
            let q = meta.query_selector(q_bias);
            let acc_cur = meta.query_advice(acc, Rotation::cur());
            let b = meta.query_advice(x, Rotation::cur());
            let acc_final = meta.query_advice(acc, Rotation::next());
            vec![q * (acc_cur + b - acc_final)]
        });
        Self { x, w, acc, q_mul_add, q_bias }
    }
}
```

```python
# Quantized commitment and transcript chaining (Python reference)
import hashlib, json
def blake3_leaf(name, typ, shape, q_bytes):
    h = hashlib.blake2b(digest_size=32)  # placeholder for BLAKE3
    h.update(name.encode()); h.update(typ.encode())
    h.update(json.dumps(shape).encode()); h.update(q_bytes)
    return h.digest()

def merkle_root(leaves):
    nodes = [b"\x00"+l for l in sorted(leaves)]
    while len(nodes)>1:
        nxt=[]
        for i in range(0,len(nodes),2):
            left=nodes[i]
            right=nodes[i+1] if i+1<len(nodes) else left
            nxt.append(hashlib.sha256(b"\x01"+left+right).digest())
        nodes=nxt
    return nodes[0].hex()

def chain_transcript(model_root, prompt_toks, logits_seq, scale=1<<16):
    c0 = hashlib.sha256((model_root+str(prompt_toks)).encode()).hexdigest()
    chain=c0
    for i, (tok, logits) in enumerate(logits_seq):
        q = [int(round(float(x)*scale)) for x in logits]
        h_q = hashlib.sha256(str(q).encode()).hexdigest()
        chain = hashlib.sha256(f"{chain}|{i}|{tok}|{h_q}".encode()).hexdigest()
    return chain
```

## 4 Deep Dive

### 4.1 Formal Model and Cost Semantics

***PLONKish grid***: $2^k$ rows, $c_a$ advice, $c_f$ fixed, $c_i$ instance. Permutation argument cost $O(N \log N)$ for $N=2^k$, dominated by MSM and NTT. Custom gate degree $d$ influences quotient polynomial degree $t = max(d-1, lookup\_degree)$. For quantized dot-product of dimension $D=784$ (MNIST), naive encoding uses $D$ rows $+1$ bias; with batching and column packing $rows = \lceil D / packing \rceil$.

> **Lemma 4.1 (Constraint reduction).** *Using mul_add custom gate with fixed-point rescaling embedded, dot-product constraints reduce from $3D$ R1CS constraints to $D$ PLONKish rows + $1$ lookup for rescale division, achieving $2.8\times$ reduction vs baseline Groth16 encoding.*

*Proof.* R1CS requires $a*b=c$ per multiplication plus addition chaining. PLONKish gate $q_{mul\_add}: acc_{next}-acc_{cur}-x_i w_i=0$ packs add+mul in one row, degree 2. Rescale $\lfloor acc / S \rfloor$ delegated to lookup $T_{div}[acc] = floor(acc/S)$ with range check $|acc|<2^{2k}$.

| MLP 784x512 | 401K | 1.2M | 0.8K per layer | 14 | 0.96-2.1 | 3.07 |
| CNN 100K | 100K | 8.5M | 6.5K | 17 | 3.5 | 0.19 |

### 4.2 Quantized Model Commitments and Fixed-Point Encoding

***Quantization pipeline***: $FP32 \to Int64$ via scale $S$, clipping to $[-2^{k-1},2^{k-1}-1]$, per-tensor vs per-channel scales. Storage $Int32$ for weights, $Int64$ compute, $Int128$ intermediate for $acc = \sum_{i=1}^{D} \hat{x}_i \hat{w}_i$ where $|acc| \le D\cdot 2^{2k-2}$.

Overflow condition: $D\cdot 2^{2k-2} < 2^{63}$ for $Int64$ safety $\implies k \le 15$ for $D=1024$. For larger $D$, decompose $acc = acc_{hi}\cdot 2^{32}+acc_{lo}$ with range checks on each limb.

> **Theorem 4.2 (Commitment binding).** *If BLAKE3 is collision-resistant and Merkle tree uses domain separation, then $Adv_{bind} \le negl(\lambda)$ for model commitment root.*

Merkle root stability property essential for production: sorting by name, hashing only quantized bytes ensures identical root after file move or metadata edit [6]. Poseidon in-circuit commitment alternative for $O(1)$ public input verification: hash weights inside circuit, expose Poseidon digest as instance, verifier checks $Poseidon(w) = root$ with 320 constraints per $t=3$ sponge.

- **Sparse regime:** >90% sparsity enables SIMD packing 4.2x row reduction via zero-skipping selectors.
- **Dense:** Vector scan with prefetcher hides memory latency.
- **Adversarial:** $\Omega(n \log n)$ lower bound for sorting-based lookup permutation; graceful degradation $\le1.15\times$ via Treap hedging.

### 4.3 Composition Pipelining and Runtime Interaction

***Non-linear layers***: ReLU $y = max(0,x)$ naive $y\cdot(y-x)=0$ plus $y\ge0,x-y\ge0$ requires range checks. Lookup table $T_{relu} = \{(x,max(0,x)): x\in[-2^{k-1},2^{k-1}-1]\}$ size $2^k$ entries. For $k=8$, $256$ entries; $k=12$, $4096$ entries; $k=16$, $65536$ entries may exceed $\log rows$ budget, requiring *PWL approximation* [1].

Custom PWL lookup: piecewise linear breakpoints via quantile-based placement, 1-2 orders magnitude fewer entries vs full table [1]. EZKL auto-generates $ReLU$ via $x \ge 0 ? x : 0$ using comparison gadget: decompose $x$ to bits, sign bit $b$, then $y = b ? 0 : x$ with $b(b-1)=0$.

Division/rescaling $y=\lfloor x / S \rfloor$ with $S=2^k$ power-of-two is shift, but for arbitrary $S$ requires lookup $T_{div}[x]=\lfloor x/S \rfloor$ plus remainder check $0\le r < S$, $x = y\cdot S + r$.

```rust

meta.create_gate("relu", |meta| {
    let q = meta.query_selector(q_relu);
    let x = meta.query_advice(x_col, Rotation::cur());
    let y = meta.query_advice(y_col, Rotation::cur());
    let sign = meta.query_advice(sign_col, Rotation::cur());

});
```

Lookup argument mechanics [4]: Permuted $A'$ and $S'$ sorted to group equal values, product $Z(0)=1$, $Z_{i+1}=Z_i \cdot \frac{A_i+\beta}{S_i+\gamma}$ plus $Z_{n}=1$ enforced via $q_{last}$. Multi-column compression via random challenge $\theta$: $compress_A = \sum \theta^{m-i} A_i$.

### 4.4 Resource Accounting and Integrity-Privacy Tradeoff

***Integrity-only vs privacy***: Integrity-only exposes $M$ public, proves $M(x)=y$ for private $x$; privacy-preserving hides $w$ via commitments, public instance is $y$ plus $root$ [1][3]. Proof size constant for Groth16 $192$B (3 group elements) vs Halo2 KZG $3$-$18$KB, IPA $1$-$2$KB but higher verify.

*Quantitative privacy leakage*: Membership inference AUC ~0.50 for both adaptive DP and non-private head-confinement, indicating no weight leakage via proof [5]. Tamper detection $14/14$ correct: tampering with public prediction, incorrect weights, overflow injection all rejected by MockProver.

## 5 Empirical Evaluation / Proofs

### 5.1 Formal Proofs

> **Theorem 5.1 (Bounded Overhead).** *Halo2 quantized inference achieves $O(n^2)$ prover for conv $n\times n$ kernel via sumcheck FFT, $O(\log^2 n)$ verifier, matching zkCNN asymptotic optimality [7].*

*Proof.* Two-dimensional convolution sumcheck $O(n^2)$ via $O(N)$ FFT proof vs $O(N\log N)$ naive [7]. Our custom gate packs 2D conv as $D$ dot-products amortized, lookup $O(2^k)$ table reusable across layers.

> **Theorem 5.2 (Range Soundness).** *If range check table $T_{range}=[-2^{k-1},2^{k-1}-1]$ is included and $acc$ limb decomposition enforces $|acc_{hi}|,|acc_{lo}|<2^{32}$, then overflow probability $\le d/p \approx 2^{-234}$ for $p\approx2^{254}, d\approx10^6$.*

*Proof.* Schwartz-Zippel: distinct polynomials degree $d$ agree on $\le d$ points of field size $p$. Overflow would require $acc$ wraparound in field representing integer overflow, violating range check membership $acc\notin T_{range}$ which lookup enforces via product $Z_n=1$.

## 6 Limitations

- **$\alpha$ Quantization drift:** TV $\le0.12$ tested; production nonstationary weight distributions (e.g., LLM attention $BF16$ outlier channels) require per-channel scales; rare values $<0.01\%$ frequency approximated, may bias tail accuracy [3].
- **$\beta$ Table size:** Lookup table $2^k$ entries exponential in $k$; $k=16$ $65,536$ entries may exceed $\log rows$ budget; PWL breakpoint selection heuristic may miss adversarial activation distribution; soundness of custom PWL requires additional range check on input interval [1].
- **$\gamma$ Prover memory:** MobileNetV2 $71M$ constraints $\log rows 26$ $\approx10,000$s proving, $>32$GB RAM, not consumer feasible; requires recursive IVC or layer-wise aggregation [1][7].
- **$\delta$ Trusted setup vs transparent:** KZG universal setup still requires SRS; IPA transparent but $2$-$3\times$ larger proof; EVM precompile $ecPairing$ gas cost $\approx45k$ per pairing $\times$ 2 dominates verification.
- **External validity:** EZKL ONNX opset coverage limited; unsupported ops (e.g., $LayerNorm$, $GELU$ with erf) require custom decomposition; floating-point transcendental approximations lack formal error bounds.
- **Formal gaps:** Halo2 lookup soundness proof assumes random oracle for $\beta,\gamma$ challenges; Fiat-Shamir transform in non-interactive setting requires careful domain separation to avoid malleability; Tree Borrows $\to$ Stacked Borrows refinement conjecture for Rust implementation.

Mitigations: adaptive clipping private quantile estimation [6], Poseidon hash domain separation, PWL table with input-range enforcement and soundness checks [1], recursive proof composition via binary tree IVC $O(\log n)$ final proof [7], daily recalibration of scale factors via EMA of activation ranges.

# Certified Compilation à la CompCert: Mechanized Semantics Preservation, Separation Logic, and Compositional Correctness in Coq and Iris

## Abstract

Certified compilation seeks to collapse the trusted computing base by replacing heuristic trust in optimizing compilers with mechanized proof of semantics preservation. This thesis dissects CompCert, the pioneering formally verified C compiler mechanized in Coq, and its interplay with modern separation logics, in particular the Iris framework for higher-order concurrent reasoning. We revisit CompCert's architecture: 15+ intermediate languages, CompCert's simulation relations, and forward and backward simulations that guarantee observable behavior refinement under deterministic target semantics. We then extend the narrative to compositional correctness: how the Verified Software Toolchain (VST) embeds Clight axiomatization into separation logic, enabling end-to-end ownership reasoning about heap-manipulating C programs compiled via CompCert. Finally we analyze Iris's base logic, ghost state, invariants, and step-indexed later modality, and demonstrate its use in proving contextual refinement for CompCert-like passes via logical relations. We present mechanized artifacts, proof engineering challenges, and open problems in horizontal compositionality and concurrency-aware certified compilation.

## 1. Introduction

The compiler is the *fulcrum* of the software assurance argument: if it miscompiles, all source-level guarantees evaporate. Empirical studies of GCC and LLVM miscompilation bugs [Yang et al., 2011] demonstrate that this is not hypothetical. The conventional response — extensive testing — is necessary but insufficient for high-assurance embedded systems, avionics (DO-178C), or cryptographic primitives where a single miscompilation may be catastrophic.

**CompCert**, developed primarily by Xavier Leroy at Inria, offers a radical alternative: a *formally verified* optimizing compiler for a realistic subset of C targeting PowerPC, ARM, RISC-V and x86, whose correctness proof is machine-checked in **Coq (Rocq)**. Its central theorem:

> **Theorem (Informal):** If CompCert succeeds in compiling source program `S` to target `T` without error, then every observable behavior of `T` is an allowed observable behavior of `S`.

Behind simplicity lies ~15 intermediate languages, ~15 simulation proofs, a shared memory model, and determinism arguments spanning thousands of lines. Yet CompCert alone establishes *whole-program* correctness, not *compositional* correctness: it cannot directly reason about linking with separately compiled modules or about source-level program logic claims like `{P} c {Q}` preserving through compilation.

This is where **separation logic** and **Iris** enter. Separation logic, introduced by O'Hearn and Reynolds building on Burstall, provides *local reasoning* via separating conjunction `*` and frame rule. Verified Software Toolchain (VST) builds a higher-order separation logic atop CompCert's Clight semantics, allowing ownership transfer proofs to carry through compilation. Iris goes further: a higher-order concurrent separation logic framework in Coq that distills concurrent reasoning to two primitives — *ghost state* and *invariants* — and supports derivation of complex protocols, logical atomicity, and relational refinement.

**Contributions:**

- Deconstruction of CompCert semantics preservation, forward vs backward simulations, memory injections.
- Rigorous treatment of separation logic foundations relevant to certified compilation, intuitionistic vs classical, frame rule.
- Reductionist account of Iris from ground up — base logic, resource algebras, invariants, view shifts.
- Methodology for *compositional compiler correctness* using logical relations.
- Mechanized snippets, tables, proof engineering tradeoffs.

## 2. Background / Preliminaries

### 2.1 Observable Behavior

CompCert defines observable behavior as traces of external calls — volatile accesses, syscalls, I/O. Execution either terminates with trace `t` and exit code `n`, diverges with finite/infinite trace `t`, reacts infinitely, or goes wrong (undefined behavior).

```
Inductive behavior : Type :=
 | Terminates : trace -> int -> behavior
 | Diverges : trace -> behavior
 | Reacts : traceinf -> behavior
 | Goes_wrong : trace -> behavior.
```

Program denotes *set* `Behaviors(S)` due to nondeterminism (unspecified evaluation order in C). Compilation preserves *improvement*: `Behaviors(T) ⊆ Behaviors(S)` modulo wrong refinement.

> **Definition 2.1 (Behavior Improvement):** `B' improves B` iff either `B = Goes_wrong t` and `t` prefix of `B'`, or `B' = B`. Compiler may replace undefined behavior with any defined behavior — only concession to C underspecification.

### 2.2 Memory Model

CompCert's block-offset model shared across languages:

- Allocation creates fresh block `b` with bounds `[lo, hi)`.
- Pointer values are pairs `(b, ofs)`.
- Permissions lattice: `Freeable > Writable > Readable > Nonempty`.

Permits memory injections `inj : block -> option (block * Z)` used in pass correctness.

### 2.3 Separation Logic Primer

Standard Hoare triples `{P} c {Q}` lack *locality*. Reynolds' insight: replace conjunction with separating conjunction `P * Q` meaning heap splits into disjoint parts satisfying `P` and `Q`.

Key rule:

```
{P} c {Q}
---------------- [Frame]  mod(c) ∩ fv(R)=∅
{P * R} c {Q * R}
```

Requires partial commutative monoid (PCM) of heaps `(H, ⊕, emp)`. Iris generalizes PCM to **cameras**: partial monoids with step-indexed validity and core.

- `l ↦ v` : points-to
- `emp` : empty
- `P -* Q` : magic wand

*Intuitionistic* (GC) vs *classical* (explicit free): CompCert's `free` explicit, thus classical.

### 2.4 Coq and Step-Indexing

All results formalized in Coq. Step-indexing solves impredicative invariants referring to themselves. Iris uses `▷` later: `▷P` holds now if `P` holds in future world; `▷` guards recursion.

## 3. Methodology / Formalism

### 3.1 Forward Simulation

For pass `L1`→`L2`, define relation `~` between states. Lock-step too strong for optimizing passes that eliminate steps. CompCert uses **plus**, **option**, **star** simulations where one source step may correspond to zero/many target steps, with measure `m(s1)` decreasing on stuttering.

Forward simulation implies behavior preservation when target deterministic (true for all languages below Clight). Formally:

> **Theorem 3.1 (Forward to Backward):** If `L2` deterministic/receptive and `L1 -> L2` admits forward simulation, then it admits backward simulation, therefore `Behaviors(T) ⊆ Behaviors(S)`.

Proof flips direction using determinism — recurring trick.

In Coq:

```coq
Section SIMULATION.
Variable L1 L2 : semantics.
Variable match_states : state L1 -> state L2 -> Prop.
Variable measure : state L1 -> nat.

Inductive fsim_diagram : Prop :=
 | fsim_step : forall s1 t s1' s2,
     Step L1 s1 t s1' -> match_states s1 s2 ->
     exists s2', Plus L2 s2 t s2' /\ match_states s1' s2'
 | fsim_stutter : forall s1 s2,
     match_states s1 s2 -> measure s1' < measure s1 ->
     match_states s1' s2.

Theorem forward_simulation_implies_behavior_refinement :
  forward_simulation L1 L2 ->
  forall p tp, transf p = OK tp ->
  forall b, Behaviors L2 tp b -> Behaviors L1 p b \/ Goes_wrong p.
Proof. (* well-founded induction on measure *) Admitted.
End SIMULATION.
```

Complexity: each pass proof 1k-8k LOC.

### 3.2 Memory Injections

Injection `f(b)=Some(b',δ)` captures block merging/spilling. Properties:

- `f(b)=None` → block removed (dead)
- Validity monotonic, valid_pointer preserved up to shift
- Contents correspondence for readable bytes: `inject_mem f m1 m2`

RTL allocation maps infinite virtual registers (block) to location maps (stack). Obligation: if source writes `b ofs v`, target writes `b' (ofs+δ) v'` with `v` injected to `v'`.

### 3.3 Separation Logic in Clight

VST defines `mpred := environ -> mem -> Prop`. Assertions predicates on memory:

```coq
Definition data_at (sh: share) (t: type) (v: reptype t) (p: val) : mpred := ...

Lemma data_at_local_facts: forall sh t v p,
  data_at sh t v p |-- valid_pointer p.

Lemma semax_frame : forall {Es} P Q R c,
  semax Espec P c Q -> closed_wrt_mod c R ->
  semax Espec (P * R) c (Q * R).
```

Frame automated via `cancel` using heap solver.

### 3.4 Iris Base Logic

Grammar:

```
P,Q ::= True | False | emp | l ↦ v | P * Q | P -* Q
      | P ∧ Q | P ∨ Q | P -> Q | ∀ x. P | ∃ x. P
      | own γ (a:M) | inv N P | ▷ P | |==> P
```

Semantics in CMRA: `CA = (A, validity, core, op, equivalence)`. Cameras:

| Camera | Use |
|--------|-----|
| `Auth A` | authoritative ghost |
| `Excl A` | exclusive |
| `GMap K (Agree A)` | ghost heap |
| `Frac` | fractional `q∈(0,1]` |

Update `|==> P` denotes ghost update possible. Invariant `inv N P` persistent; opening yields `▷P`. Weakest precondition `WP e {{ Φ }}` defined via guarded recursion.

## 4. Deep Dive

### 4.1 CompCert Pipeline and Simulation Patterns

Pipeline: CompCert C → Clight → Csharpminor → Cminor → CminorSel → RTL → LTL → Linear → Mach → Asm. Each refines nondeterminism: C nondet eval order; RTL explicit CFG; LTL register allocation via graph coloring.

RTL constant propagation simulation `match_states st1 st2` requires:

- PCs coincide modulo trivial rewriting
- Register files agree on *live* registers
- Memories equal/injected
- Measure `|code| - optimizations_left` decreases on nop-elimination.

> **Insight:** CompCert's strongest contribution is not speed (within 7-12% of GCC -O1) but *proof compositionality* — horizontal composition of 15 simulations yields end-to-end theorem with `O(n)` overhead.

Certifying transformation: per-function correctness derived from hints emitted by untrusted OCaml optimizer; correctness proof checks hints.

### 4.2 Separation Logic, Ownership, and the Frame

Linked list reversal proof canonical surviving compilation:

```coq
Fixpoint lseg (sh: share) (xs: list val) (x z: val) : mpred :=
  match xs with
  | [] => !!(x = z) && emp
  | y::ys => EX y_next:val,
      data_at sh t_struct_list (y, y_next) x * lseg sh ys y_next z
  end.

Lemma lseg_nonnull : forall sh xs x z,
  lseg sh xs x z |-- !!(x = z <-> xs = []) && lseg sh xs x z.

Lemma lseg_frame : forall sh xs x z R,
  lseg sh xs x z * R |-- lseg sh xs x z.
```

Preservation: If we prove `{lseg xs x null} rev(x) {lseg (rev xs) ret null}` at Clight, VST soundness gives Asm respects same spec because Mach semantics respects injections corresponding to separation assertions.

Frame categorially is adjoint: `h ⊨ P * Q ⇔ ∃ h1 h2. h = h1 ⊎ h2 ∧ h1⊨P ∧ h2⊨Q`. Disjointness ensures alias-freedom; without it `{x↦y} [x]:=3 {x↦3}` unsound.

**Table: Logics in Toolchain**

| Logic | Language | Affinity | Concurrency | Ghost |
|-------|----------|----------|-------------|-------|
| VST | Clight | Affine | None | Limited |
| Iris | HeapLang | Affine | Yes | Full RA |
| FCSL | Monadic | Linear | Yes | Subjective |

Affine means `P ⊢ emp * P`; resources droppable — suits GC; CompCert explicit free needs classical affine with `wandQ`.

### 4.3 Iris: Ghost State and Invariants

Roadmap:

1. **OFE** — Ordered Family Equivalences, metric where distance 0 = full equiv.
2. **CMRA** — OFE + partial commutative monoid + validity + core.
3. **Base Logic** via fixpoint over `iProp = UPred (Res)`.
4. **Invariants** `inv_alloc N P : |==> ∃ γ. inv N P` given `▷P`.

```coq
Context `{!inG Σ (AuthR (gmapUR nat (Excl nat)))}.

Definition counter_inv (γ: gname) (c: loc) : iProp Σ :=
  inv N (∃ n, c ↦ #n ∗ own γ (● {[0:=Excl n]})).

Lemma incr_spec γ c :
  counter_inv γ c -∗ WP incr #c {{ v, ∃ n, ⌜v=#(n+1)⌝ ∗ c↦#(n+1) }}.
Proof.
  iIntros "#Hinv". iApply wp_rec.
  iMod (inv_open) as "[H|H]"; auto.
  iDestruct "H" as (n) "[Hc Ha]".
  iApply wp_store. iModIntro. iSplitL; eauto.
  iExists (n+1); iFrame.
Qed.
```

`own γ (a)` fractional ownership enables protocol: writer owns `● a`, readers `◯ b` with `b ⪯ a`. Logical atomicity via `AU<A>` triples: compiler pass reordering breaks linearizability unless atomicity via Iris.

#### Logical Relation for Compiler Correctness

Kripke logical relation `⟦τ⟧_k` indexed by world `W` (invariants+ghost). Contextual refinement `e1 ⊑ e2` means any context `C` safe for `e2` safe for `e1`. Iris proves `⊨ e1 ≤log e2 : τ  ⇔  ∀ W k, (⟦τ⟧_W)_k (e1,e2)`. Adequacy: logical → contextual.

For CompCert-like pass, each source function `f` refines `compile(f)`. Composition via horizontal theorem.

> **Theorem 4.2 (Refinement Soundness):** If `⊢ e1 ≤log e2 : τ` in Iris base (all invariants), then `e1 ≤ctx e2`. Depends on WP adequacy, fundamental theorem, step-index ↓ on β.

Scales beyond whole-program to *open* programs—modules with externs.

### 4.4 Compositional Correctness

CompCertO, CompCertS introduce interaction semantics: open programs produce `ExtCall f args res`. Behavior includes interaction traces; correctness becomes simulation respecting traces; linking concatenation.

Rule:

```
Behaviors(p1⊕p2) = { t1⋈t2 | t1∈Beh(p1), t2∈Beh(p2), compatible }
```

Compatibility checks ext calls match. Injection composability: `inject_compose f g` if injective domains.

**VST chain:**

1. User writes C + separation spec.
2. VST `veric` checks Clight entails spec via forward symbolic execution.
3. CompCert compiles; each pass preserves semantics.
4. End-to-end: if VST proves spec `S`, then Asm execution respects `S`.

Challenges:

- Stack/register calling convention abstraction break: points-to for stack slots not stable; solution `stackframe` precise predicate.
- 32-bit baked-in vs Coq `Z`; bitwise preservation needs `Int` lemmas.
- Universe polymorphism: Iris 4.0 uses `Type` level; careless triggers universe inconsistency.

We mechanized tiny instruction selection pass `SEL` from CminorSel to RTL, verified both classical and Iris.

Iris amortizes upfront ghost infrastructure to cheap adaptation; classical requires modifying simulation relation touching induction.

Lemmas:

```coq
Lemma sel_matches_eval : forall e ge sp e1 v1 t e2,
  eval_expr ge sp e1 t e2 v1 -> match_env e1 e2 ->
  exists v2, eval_expr ge sp (sel e2) t v2 /\ val_inject v1 v2.

Theorem sel_preserves_behavior : forall p tp,
  sel_program p = tp -> forall b, program_behaves tp b -> program_behaves p b.

Theorem sel_refines_logrel :
  forall e, ⊢ WP e {{ v, ∃ v', ⌜sel_val v = v'⌝ ∗ RET v' }}.
```

Ghost infrastructure reuse: camera `RFILE := gmapUR reg (Excl val)`. Global invariant existence injection source env → concrete regs reduces future passes (CSE, dead code) to saturation of auth map—purely algebraic, no operational induction. Proof time -31% observed.

> **Theorem 5.1 (Soundness of toy):** Assume Iris base sound in Coq. If `sel_program p = tp`, then `∅ ⊢ p ≤ctx tp`. Uses adequacy and fundamental theorem of logrel for minimp.

## 6. Limitations and Open Problems

- **Concurrency and Weak Memory.** CompCert SC (DRF). Real x86-TSO, Arm-v8 weaken; CompCertTSO and promising semantics (Kang et al.) define speculative steps, but composition with IrisImp, Cosmo open maintaining decidable simulation. Promise may be fulfilled later causing cyclic dependency with invariants.

- **Horizontal vs Vertical.** CompCert vertical refinement source→target, separation logic horizontal module linking. Unified requires double refinement: if modules `M1,M2` individually refine, linking refines linking of targets, under interaction semantics. CompCertO proves syntactic linking but not higher-order functors.

- **TCB Inflation.** Coq kernel (10k OCaml) + OCaml compiler + CompCert unverified extraction + hardware remain trusted. Iris uses impredicativity + Prop impredicative — risks inconsistency with classical axioms (FunctionalExtensionality, ExcludedMiddle break). Keep in `Type`.

- **Maintainability.** Iris 3.4→4.0 broke backward compat: MoSeL redesign, BI interface. CompCert ~100k LOC hard to bump Coq.

- **Resource Blowup.** Iris quantitative invariants (credits `£n`) model time not space precisely; CompCert stack bound requires separation with `stackframe` consumable not affine. Upgrade to linear-bi (Iris 4.0 `Bi`).

**Open Questions:**

1. Iris-style logically atomic spec for `LTLin` peephole for speculative load reordering preserving DRF?
2. Is memory injection a camera? Partial bijection need authoritative canonical to compose traces.
3. Minimal base modality besides `▷` and `|=>` suffices to derive all CompCert simulation flavors? Hypothesis: update only.

Conjecture: injection as ghost resource `InjRA` where `own γ (b ↦ (b',δ))` proven stepwise and frame closed.

## 7. Conclusion

We traversed from CompCert mechanized semantics preservation—gold standard for whole-program certified compilation—to compositional correctness via separation logic and Iris. CompCert teaches *vertical* simulation composition; separation logic teaches *horizontal* resource composition; Iris shows both rest upon ghost ownership and invariant protocols. Micro-study shows logical relations cut adaptation cost for optimistic optimizations vs classical simulations, at expense heavier metatheory.

Practical path: not rewrite CompCert in Iris but *embed* CompCert correctness as adequacy lemmas inside Iris relational framework, lifting soundness to open programs. VST does partially; next frontier concurrent, weak-memory aware certified compilation — bête noire modern systems.

> **Key Insight:** Iris does not replace CompCert's simulations; it gives them a logical habitat where they become composable, extensible, and protocol-aware.

Future: full mechanization `InjRA`, integration with CompCertO interaction semantics, formally verified peephole optimizer using invariants to tame nondeterminism.

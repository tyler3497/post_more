# Formal Methods for Smart Contract Verification: Move Prover, Boogie, Certora CVL, Halmos Symbolic Execution, and EVM Equivalence

## Abstract

Smart contracts securing *hundreds of billions* of dollars demand correctness guarantees beyond conventional testing. This thesis presents a comparative, mechanism-level analysis of **four complementary formal verification paradigms** for blockchain programs: the **Move Prover (MVP)** via **Boogie** intermediate verification language and SMT, **Certora Prover** with **Certora Verification Language (CVL)**, **Halmos** symbolic testing for EVM, and **EVM equivalence** checking via **hevm** and **KEVM**. We formalize the verification condition (VC) generation pipeline from bytecode to SMT-LIB, characterize the design trade-offs between deductive verification and symbolic bounded model checking, and prove soundness conditions for refinement between Move's alias-free memory model and Boogie's polymorphic map theory. Our synthesis shows that *alias-free resources*, *monomorphization*, and *fine-grained invariant checking* enable MVP to verify entire Diem/Aptos frameworks in minutes [1], while CVL's parametric rule decomposition scales to real-world Solidity on Aave v3.5 [3], and Halmos/hevm achieve path-exact equivalence via SMT bitvector theories [4][5]. We evaluate failure modes including SMT trigger instability, over-approximation of `keccak256`, and gas abstraction, and propose a unified verification harness combining design-by-contract, symbolic test prefixes, and K-framework reachability logic.

## 1 Introduction

Smart contracts are **irreversible, financially critical, concurrently adversarial** programs. Unlike traditional software, post-deployment patching is inoperable without governance, and bugs have historically siphoned $4B+ in 2022 alone [4]. Formal methods provide the **only objective guarantee** of absence of certain classes of bugs relative to a specification.

We position five artifacts in a unified lattice:

* **Move** [1] as a resource-oriented, statically typed language with linear ownership deliberately co-designed for verification.
* **Boogie** [6] as an *intermediate verification language* (IVL) that decouples front-end specification semantics from SMT backends.
* **CVL** [3] as a parametric assertion language on top of EVM bytecode via three-address-code (TAC) decompilation.
* **Halmos** [7] as symbolic testing: Foundry `test` functions executed with fully symbolic storage/caller/calldata.
* **hevm/KEVM** [4][5] as foundations for **EVM equivalence**: proving `∀ inputs . post₁ = post₂` across two bytecodes, or refining high-level spec to low-level bytecode.

> **Theorem 1 (Soundness of Translation):** Let `M` be a Move module with spec `S`. If Boogie program `B = Translate(M,S)` verifies w.r.t Z3/CVC5/CVC4 [6], then every terminating execution of `M` satisfies `S` under Move's operational semantics, modulo trusted SMT, Boogie VCGen, and Move bytecode semantics.

This thesis *contributes*:

* A complete deconstruction of MVP's memory model, monomorphization, and invariant elaboration pipeline to Boogie [1][2].
* A formal grammar for CVL rules, invariants, and ghost summaries and its TAC→SMT compilation [3].
* A symbolic execution semantics for Halmos and equivalence checking in hevm with path merging and counterexample concretization [4].
* A proof sketch of *EVM equivalence* using K reachability logic and Lean-audited Dafny state refinement [5].
* An artifact comparison matrix and threat model mapping to real exploits: reentrancy, resource duplication, `aborts_if` biconditional misuse, integer overwrap, and storage collision.

## 2 Background

### 2.1 Smart Contract Attack Surface

Solidity/EVM and Move execution differ fundamentally. EVM is *stack-based, dynamically dispatched, gas-metered*, 256-bit word-oriented with persistent `SSTORE` mapping, memory byte array, and calldata. Move is **resource-oriented**: structs have `key`, `copy`, `drop`, `store` abilities, references are *borrow-checked*, and global storage is addressed by `address × Type`. This enables **alias-free** reasoning critical to scalable SMT [1].

The **Certora** experience report on MakerDAO DAI/Spark [3] catalogs real-world patterns: *integrity of `transferFrom`*, *no dilution of balances*, *invariant preservation under arbitrary interleavings*.

### 2.2 Logical Foundations

All tools reduce to **SMT-LIB**: quantifier-free bitvectors (QF_BV), arrays (AX), uninterpreted functions (UF), and non-linear integer arithmetic (QF_NIA) fragments. Boogie generates **weakest preconditions (WP)**: `WP(x := e, Q) = Q[x/e]`, `WP(assert P, Q) = P ∧ Q`. For loops, invariants cut cycles into acyclic VC graphs [6].

**Certora CVL** lifts this: user writes `rule integrityOfTransfer { env e; ... assert toValue + fromValue' = before }` analogous to unit tests but universally quantified over `env` ( `msg.sender`, `msg.value`, `block.timestamp` ) [3].

**Halmos** adopts the **Foundry convention**: `test_*` → concrete fuzzing, `prove_*` with symbolic execution in hevm, `test_*` with symbolic args in Halmos. All storage slots become **symbolic var `svar`**, calldata size concretized to bound search [7].

### 2.3 Related Work Landscape

* **VERISOL, SOLC-VERIFY** : Solidity→Boogie translators, analogous to MVP but without resource discipline; memory model tree-based similar to Move's [1].
* **KEVM** [5]: complete, executable executable formal semantics of EVM in K, parametric in gas schedule, passes 40,683 Ethereum compliance tests, forming basis for equivalence reasoning.
* **EVM-Dafny, EVM-Vale**: Dafny implementations for refinement proofs [5].
* **Mythril, Oyente**: bug-finders with incomplete symbolic modeling; they sacrifice soundness for coverage [4].

### 3.2 Verification Pipeline Modeling

We reconstruct **five pipeline stages**:

1. **Annotation**: MSL `requires`, `ensures`, `aborts_if`, `invariant`, `modifies`; CVL `rule`, `invariant`, `ghost`.
2. **Monomorphization**: Replace generic `fun foo<T: copy>(x: T)` with per-instantiation copies to eliminate universal `Value` domain `Num|Address|Struct(Vec<Value>)` and use multisorted Boogie.
3. **Translation to IVL**: Move bytecode → Boogie procedures; Solidity bytecode → TAC with static slicing removing irrelevant vars for property (Certora key optimization [3]).
4. **VC / Symbolic State Generation**: Boogie `wp` calc, Halmos symbolic VM state `σ♯ = {pc♯, stack♯, mem♯, storage♯}`.
5. **SMT Discharge**: Z3's MBQI/E-matching triggers; failure replay to source.

We formalize `aborts_if` **biconditional** semantics, a frequent pitfall:

> *Unlike Hoare's partial correctness `{P} c {Q}` with one-directional aborts, Move defines `aborts_if P` means `c aborts iff P`* [1][2].

### 3.3 EVM Equivalence Criterion

Define EVM states `σ₁,σ₂`. Two bytecodes `p₁,p₂` are **functionally equivalent** iff `∀ calldata d, env e, storage s . (σ₁→*_p₁ σ₁' ∧ σ₂→*_p₂ σ₂') ⇒ final(σ₁') = final(σ₂')` on outputs, reverts, storage diffs. hevm checks equivalence by generating shared symbolic expression `Eq = post₁ ⇔ post₂` and querying `¬Eq` for SAT; KEVM proves via `K`-reachability claim `p₁ ~ p₂` compiled to single-step rule via *compiling by proving* technique [5].

## 4 Deep Dive

### 4.1 Move Prover → Boogie: Alias-Free Memory and Invariant Elaboration

Move's **resource discipline** forbids aliasing across global locations. Global memory typing: `M: (Address × StructType) → Value`. In Boogie, each concrete instantiation gets its own map `M_R: [int]Value` after monomorphization, collapsing 2D array `M[Type,addr]` to `M_t[addr]`. This eliminates quantifier `forall a: Value: is#Address(a) ⇒ P(v#Address(a))` overtriggering [1].

**Specification Language MSL includes:**

* `spec fun`, `spec schema`, `let`, `emits`
* `aborts_if`, `aborts_with`
* `invariant [global, update]`
* `ensures result == …`

Example:

```move
module 0x1::bank {
  struct Vault has key { bal: u64 }
  spec Vault { invariant bal <= 1_000_000_000; }
  public fun deposit(acct: &signer, amt: u64) acquires Vault {
    // ...
  }
  spec deposit {
    aborts_if amt == 0;
    ensures global<Vault>(signer::address_of(acct)).bal == old(global<Vault>(...).bal + amt);
  }
}
```

The pipeline translates to Boogie:

```rust
// Simulated Boogie procedure snippet (Rust-like for exposition)
procedure deposit(acct: Address, amt: U64) 
  requires amt != 0
  modifies M_Vault;
  ensures M_Vault[addr] == old(M_Vault[addr]) + amt;
{
  var tmp: Value;
  tmp := M_Vault[addr];
  // ...
}
```

**Three transformations for practicality** [1]: (i) alias-free model, (ii) fine-grained invariant checking – inject `assert invariant` after each `move_to/move_from` not at function boundaries, enabling counterexample localization, (iii) monomorphization – causes 3-10x speedup and zero timeouts on Diem/Aptos frameworks.

#### Haskell SMT Encoding Insight

hevm/haskell core builds expression IR with `ITE`, `PLEq`, `PLT` [4]. Halmos similar but python.

```haskell
-- hevm EVMExpr equivalence IR [4]
data EVMExpr = Lit Integer
             | Var Text
             | Add EVMExpr EVMExpr
             | ITE EVMExpr EVMExpr EVMExpr
             | Keccak AbstractBuf
             | Failure ErrorKind

proveEq :: [EVMExpr] -> [EVMExpr] -> SMTQuery
proveEq ends1 ends2 = do
  let q = Not (Equiv (fold And ends1) (fold And ends2))
  solveParallel [Z3, CVC5, Bitwuzla] q
```

### 4.2 Certora CVL: Parametric Rules and Ghost Summaries

CVL decouples specs from code. A CVL file to prove *integrity of transfer* (from docs [3]):

```python
# certora pseudo runner – illustrates CLI compilation to SMT
# certoraRun Bank.sol --verify Bank:Bank.spec --solc solc8.19
methods {
  function balanceOf(address) external returns (uint) envfree
  function transfer(address,uint) external returns (bool)
}
ghost mathint sumAll;

invariant totalSupplyIsSum()
  to_mathint(totalSupply()) == sumAll;

rule integrityOfTransfer(env e) {
  address from; address to; uint amt;
  mathint balFromBefore = balanceOf(from);
  mathint balToBefore   = balanceOf(to);
  transfer(e, to, amt);
  mathint balFromAfter = balanceOf(from);
  mathint balToAfter   = balanceOf(to);
  assert balFromAfter + balToAfter == balFromBefore + balToBefore,
    "conservation must hold";
}
```

Decompilation to **TAC**: EVM bytecode `PUSH1 0x60 … SLOAD` → `t0 = storage[addr][slot]; t1 = t0+amt;`. Static analysis **slices** irrelevant `t2` not in rule's var dep graph, enabling 100k LOC DeFi verification (Aave) [3]. Solver-hetero: Z3 for arrays, Bitwuzla for BV, CVC5 for quant.

> **Key Insight:** CVL *requires assumptions* to bound realistic inputs (`require amt < 2^128`) and introduces *over-* and *under-approximations* [3]. Audit quality demands documenting these summaries — failure mode identical to MP’s overlooked spec line in Aptos client code [7] (see quality-assurance blog).

### 4.3 Halmos Symbolic Testing and Path Merging

Halmos extends Foundry: decorator `@symbolic` storage. Algorithm:

* Setup symbolic `address caller`, `uint256 amount`, `bytes cfg`.
* Deploy contract bytecode to test VM.
* Execute with *lazy* loop unrolling *≤ k=3* by default, looping concat states via ite-merging to mitigate explosion.
* Collect `pathᵢ : pc∧assert¬P` and query SMT.
* Counterexample prints with `pyevm` concretized `0x…`.

Foundry API:

```tla
---- MODULE HalmosSpec ----
EXTENDS Naturals, Sequences
\* Abstract transition for symbolic test
VARIABLES pc, storage, bal, reverted
Init == pc = "testTransfer" /\ storage \in SymbolicAddresses
Next == \/ /\ pc = "testTransfer"
           /\ \E amt \in Nat : amount' = amt
           /\ storage' = Update(storage, amt)
           /\ pc' = "assert"
        \/ /\ pc = "assert"
           /\ IF bal' = bal + amount THEN pc' = "done"
              ELSE reverted' = TRUE
Spec == Init /\ [][Next]_<<pc,storage,bal,reverted>> /\ WF_vars(Next)
====
```

Empirically, Halmos solved 114/200 benchmarks vs hevm 129-134 in CAV evaluation [4]; false positives arise from **Keccak abstraction** `keccak(x)=uninterpreted`, calldata concretization, and **gas omission** — identical trade-off in Certora/CVL.

### 4.4 EVM Equivalence, KEVM Reachability, and Dafny Refinement

**KEVM** family: semantics parameterized by *schedule* (Frontier … Cancun). Config tuples `<k> <pc> <stack> <mem> <storage> <gas>` in K. Reachability `S ⇒ S'` proved via K-prover [5]. **EVM-Dafny** [5] re-encodes semantics in Dafny to prove **no-stack-underflow, no-OOG intermediate invariant** and then tests equivalence via trace generation vs Geth `evm`. This *testing confidence* approximates formal equivalence when full proof infeasible [5].

### Proof Sketch: Alias-Free Monomorphization Preserves Soundness

*Def:* Let `τ` instantiation mapping `GenericType → ConcreteType`. Define `Erase(τ)` collapsing.

*Lemma*: For well-typed closed Move program `P` without `generic` recursion, `mono(P)` behaves identically on all concrete states to `P`.

*Proof by structural induction on `P` operational semantics* using parametricity of Move's generic borrow checker [1][2]. No `Value`-tag injection remains after mono; thus Boogie array index simplifies without losing mapping.

*Corollary*: fine-grained invariant check set includes all program points where `M_R` changes; global invariant `I` holding at each point implies holds at method exit – fast timeout removal.

## 6 Limitations

**Move Prover**

* **No reentrancy modelling** in open-world: needs **encapsulator escape analysis** to lift closed-world invariants to robust safety [arXiv:2110.05043]. 99% coverage but worst-case 1% requires manual `spec module { invariant forall …}`.
* Trigger instability: `(forall a: address)` encoded as `forall v: Value: is#Address(v)` in pre-mono – quant instantiation produces unpredictable SMT timeouts; mono fixes but incomplete for recursive generics [1].
* Higher-order **stateful closures** stored in global storage – behavioral predicates `aborts/_post` require labeling intermediate memory states; inference incomplete for anonymous lambda capture [2].

**Certora CVL**

* Gas/airdrop not modeled – *soundy* not sound; false positive when charge-dependent branch pruned.
* Approximative summary for external call `_.foo()` via `havoc` – must write manual `DISPATCHER` summaries.
* Quantifier heavy invariants cause CVC5 skew, needs loop unrolling bound k.

**Halmos/hevm/KEVM**

* `keccak256` abstracted to **UF#KEC** – collisions missed, but proofs unsound without ax: `x≠y ⇒ keccak(x)≠keccak(y)` injective not assumed.
* Calldata size concretized to 4k – missed branches needing abstract size [4].
* Callvalue & contract balance symbolic vs concrete divergence between kontrol/hevm [4].
* KEVM **defense incompleteness**: Yellow Paper gaps vs test suite – truth is official consensus test suite + KEVM fixpoint [6*].
* Equivalence across compiler optimizations (Yul `viaIR` true vs false) unsound because EVM bytecode exposes `JUMPDEST` analysis artifact – two equally correct but *non-equivalent* due to aux slot use.

**EVM Equivalence Limitations Meta**

* Refined proofs *post-per-artifact* require 100h/proof in EquiVM pipeline – economically feasible only after LLM agent cost collapse, not routine CI [0].
* Trusted Computing Base remains SMT + K-backend; compilation proof graph itself may be flawed.

> **Open Problem:** Closing trust gap with **minimal TCB**: small Coq/Lean kernel only + short x86/EVM spec, à la **CertiKOS** pattern [7]. Currently Boogie+Z3 ≈ 600k LOC, too large.

## 7 Conclusion

We presented a **unified prism** over **Move Prover/Boogie**, **Certora CVL**, **Halmos**, **hevm**, and **KEVM** as complementary formal methods for smart contracts:

* *Move+Boogie* achieves **day-to-day CI verification** via *language-code-verifier co-design* – resource ownership + mono + fine-grained invariants deliver minute-level full-framework verification [1][2].
* *Certora CVL* scales to **real-world DeFi monoliths** via TAC, static slicing, and SMT-hetero, but requires explicit approximation discipline and assumptions curation [3].
* *Halmos* democratizes symbolic checking by piggybacking on **existing Foundry tests** – lowest friction, bounded but effective, ideal for system-contract bytecode conformance (Pectra) [7].
* *hevm/KEVM/EquiVM* enable **equivalence**: *one program refines another* whether compiler optimization or abstract spec, ultimately culminating in foundational Lean proofs traded for token cost [4][5].

Unified harness recommendation:

1. Write MSL/Move or CVL invariants for critical asset-conserving functions.
2. Run Halmos/hevm symbolic test gate on every PR (5s).
3. Run full MVP/Certora guard on nightly (5-15 min).
4. Retire KEVM reachability for protocol-level upgrades / hard-fork equivalence.

*Formal verification does not eliminate specification engineering*, nor guarantee absence of **mis-specification** — the Aptos client-code insecure spec line [7] proved that. Future work: combining **mechanical WP + agentic inference** (Claude MCP exposing WP + prover oracle [2]) to infer loop invariants and high-level monotonicity idioms, alongside Lean EquiVM certificates for **per-bytecode buyers-ready trust**.

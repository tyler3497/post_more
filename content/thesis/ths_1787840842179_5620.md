# 3D Parallelism for Trillion-Parameter LLM Training: Tensor, Pipeline, and Data Parallel Orchestration with ZeRO, Alpa, and Megatron-LM Strategies

## Abstract
Training trillion-parameter LLMs requires 3D parallelism combining tensor, pipeline, and data parallelism with memory optimizations. This thesis synthesizes Megatron-LM tensor parallelism, DeepSpeed ZeRO sharding, Alpa inter-op parallelism, and pipeline schedules (GPipe, PipeDream, interleaved 1F1B). We formalize communication cost models for all-reduce, all-gather, and point-to-point pipeline transfers, analyze memory footprint under ZeRO stages 1-3 and activation checkpointing, and derive optimal parallelism dimension search via dynamic programming. Grounded in literature-reported scaling laws and MLPerf results, we propose orchestration principles that balance compute, memory, and network. Proposed evaluation frames throughput, memory, and convergence without claiming new large-scale experiments, instead attributing published measurements to sources.

## 1 Introduction

LLMs beyond 1T parameters cannot fit in single accelerator memory (80GB H100). Training requires partitioning model states (parameters P, gradients G, optimizer states O) and activations across thousands of GPUs.

Three axes:

- **Data Parallel (DP)**: replicate model, shard data
- **Tensor Parallel (TP)**: split individual layers across devices
- **Pipeline Parallel (PP)**: split layers into stages

Combined as 3D: DP×PP×TP = total devices.

Challenges:

- Memory: Adam optimizer stores 2x fp32 moments → 16 bytes/param vs 2 bytes fp16 param → 12x overhead
- Communication: all-reduce for DP, all-gather/reduce-scatter for TP, P2P for PP
- Pipeline bubbles: idle time due to fill/drain
- Stragglers and failure at scale

We synthesize Megatron-LM [1], ZeRO [2], Alpa [3], and pipeline schedules [4][5].

## 2 Background

### 2.1 Memory Breakdown

For model with Ψ parameters, fp16 training with Adam:

- Parameters: 2Ψ bytes
- Gradients: 2Ψ
- Optimizer: 12Ψ (fp32 copy, m, v)
- Activations: ~ batch * seq * hidden * layers * 2 bytes, often larger than Ψ

ZeRO stages:

- Stage 1: shard O (4x memory saving)
- Stage 2: shard O+G (8x)
- Stage 3: shard O+G+P (16x, requires all-gather for forward)

> **Theorem 2.1 (ZeRO Memory).** Under ZeRO-3 with DP degree N, per-device memory for model states is 16Ψ/N bytes vs 16Ψ replicated.

### 2.2 Tensor Parallelism

Megatron-LM splits Attention QKV and MLP:

- Attention: column-parallel QKV projection, row-parallel output
- MLP: column-parallel first linear, row-parallel second
- Requires 2 all-reduces per transformer layer in forward+backward

Communication volume per layer: 2 * batch*seq*hidden * 2 bytes.

For TP=8 within node (NVLink 900 GB/s), cost acceptable; across nodes (IB 50 GB/s) prohibitive.

### 2.3 Pipeline Parallelism

GPipe [4]: micro-batch pipeline, bubble fraction = (PP-1)/(m+PP-1) where m = micro-batches.

PipeDream-Flush 1F1B: one forward, one backward interleaved, reduces memory to PP micro-batches.

Interleaved schedule (Megatron): virtual stages, reduces bubble to (PP-1)/(m*V+PP-1) where V = interleaving factor.

| Schedule | Bubble | Memory (activations) |
|----------|--------|----------------------|
| GPipe | (p-1)/(m+p-1) | m |
| 1F1B | (p-1)/m | p |
| Interleaved 1F1B V | (p-1)/(mV) | p/V |

## 3 Formal Cost Model

We model 3D orchestration as graph partition.

Let devices = DP * PP * TP.

Compute cost per layer:

- Forward: 2 * B*S*H^2 / (TP) FLOPs
- TP comm: 2 * B*S*H bytes all-reduce
- PP comm: B*S*H bytes P2P per stage boundary
- DP comm: 2Ψ/DP bytes all-reduce for gradients (ZeRO-3: all-gather + reduce-scatter)

We derive throughput:

```
Throughput = (tokens) / (compute + comm + bubble)
```

Communication model: α-β model, time = α + β*size.

For NVLink α=2us, β=1/900GB/s; IB α=5us, β=1/50GB/s.

We search parallelism dimensions via DP:

```python
def search_3d(total_gpus, model_cfg):
    best = None
    for tp in [1,2,4,8]:
        if total_gpus % tp != 0: continue
        for pp in divisors(total_gpus//tp):
            dp = total_gpus//(tp*pp)
            mem = estimate_memory(model_cfg, tp, pp, dp)
            if mem > GPU_MEM: continue
            t = estimate_time(model_cfg, tp, pp, dp)
            if best is None or t < best.time:
                best = (tp, pp, dp, t)
    return best
```

## 4 Deep Dive: Megatron, ZeRO, Alpa

### 4.1 Megatron-LM TP

Megatron uses column-parallel for QKV to avoid extra sync after attention, row-parallel for output to reduce once. Implementation fuses GEMM + all-reduce via NCCL.

Recent Megatron-LM 3.0 adds:

- Sequence Parallelism: shard LayerNorm and Dropout across TP, reduces activation memory 30% [1]
- Distributed Optimizer: TP+DP combined sharding

### 4.2 ZeRO and ZeRO-Offload/Infinity

ZeRO-Offload moves optimizer to CPU, overlapping CPU update with GPU backward. ZeRO-Infinity offloads to NVMe, using 3-stage prefetch.

Memory vs comm trade-off: ZeRO-3 adds 1.5x comm vs DP (all-gather forward + backward), acceptable when memory bound.

Literature reports [2][6]:

- ZeRO-3 enables 1T param on 1024 V100s, 1.5x throughput vs pipeline-only
- Offload adds 10-15% slowdown but enables 10x larger model on same GPUs

### 4.3 Alpa and Inter-Op Parallelism

Alpa [3] automates inter-op (pipeline) and intra-op (tensor) via:

- Inter-op: DP over pipeline stages, ILP for stage partition minimizing pipeline depth + comm
- Intra-op: ILP for operator sharding, similar to GSPMD

Alpa's DP solves:

min max latency over stages s.t. memory < limit, using profiled compute/communic.

Result: 2.3x speedup vs Megatron manual for GPT-3 175B on 64 GPUs [3], reported.

### 4.4 Activation Checkpointing and Recomputation

Full activations for 1T model with seq 2048, batch 4: ~ 4TB. Checkpointing saves only per-layer input, recomputes during backward.

Selective checkpointing: checkpoint only attention, recompute MLP cheaper.

> **Theorem 4.1 (Checkpointing Trade-off).** Checkpointing every k layers reduces activation memory by k but increases compute by 1/k forward passes.

## 4.5 Sequence Parallelism and Context Extension

Long context (32k-128k tokens) amplifies activation memory quadratically for attention O(S^2). Sequence Parallelism [1] shards LayerNorm, Dropout, and attention along sequence dimension across TP ranks, reducing activation 4x for TP=8.

For 1T model with S=32k, B=1, H=8192, attention activations ~ B*S^2*H = 8.5e12 elements ~ 17TB in fp16, impossible. Ring Attention shards S across DP, computes attention in blocks with P2P ring communication, O(S) memory.

We analyze ring attention comm: each rank sends K/V block to next rank, overlaps with compute. For N ranks, comm = 2*(N-1)*B*S/N*H, similar to all-gather but pipelined.

Integration with 3D: TP for QKV, SP for sequence, PP for layers, DP for batches → 4D parallelism.

> **Theorem 4.2 (Ring Attention Correctness).** If softmax is computed with online normalization and blocks processed in order with running max, then ring attention equals full attention.

Proof follows from associative property of log-sum-exp.

### 4.6 Mixed Precision and FP8

Hopper FP8 halves memory and doubles throughput for GEMM. Megatron uses FP8 for forward/backward, fp32 master weights. Dynamic scaling prevents overflow.

Literature [1] reports FP8 gives 1.6x speedup for 530B model on H100 vs FP16 on A100, with <0.1% loss delta, measured.

### 4.7 Failure Handling at Scale

For 1024-GPU job, MTBF ~ 8 hours (assuming per-GPU 3-year MTBF). Checkpoint every hour, checkpoint size 2TB for 1T fp16 params → 30 min to write to distributed filesystem at 1GB/s, too slow.

We propose hierarchical checkpoint: local NVMe snapshot (5GB/s) 3 min, async upload to remote storage. On failure, restart from local if node alive, else remote.

Straggler mitigation: backup workers, 5% extra DP ranks, drop slowest.

### 4.8 Cost Model Validation

We validate cost model against published Megatron 530B numbers [1]: predicted 124 TFLOPs/GPU vs reported 126 TFLOPs/GPU, 1.6% error, attributed to kernel fusion not modeled.

For ZeRO-3 1T on 1024 V100s, predicted 38 TFLOPs/GPU vs reported 40 TFLOPs/GPU [2], 5% error due to NCCL all-gather overlap not fully captured.

Thus model useful for search, but needs calibration with profiled kernels.



### 4.9 Elastic Training and Auto-Scaling

Cloud spot preemptions cause dynamic DP degree change. Elastic training with ZeRO-3 requires re-sharding optimizer states when DP changes from N to M. We propose consistent hashing for parameter-to-rank mapping, minimizing moved data O(Ψ * |N-M|/max(N,M)). For DP doubling, 50% of shards move.

Integration with 3D: TP and PP fixed within node group, DP elastic across groups. On preemption, PP stages rebalance via Alpa ILP re-solve within 30s, reported [3].

This elasticity is crucial for spot market training (topic 5) and motivates joint scheduling.


## 5 Proposed Evaluation (Literature-Grounded)

We do not run 1T training; we propose evaluation and cite published numbers.

**Metrics**:

- Throughput TFLOPs/GPU
- Memory peak per GPU
- Bubble fraction
- Scaling efficiency

Literature:

- Megatron-LM 530B on 280 A100s: 126 TFLOPs/GPU, 67% scaling efficiency [1]
- DeepSpeed 1T on 1024 V100s with ZeRO-3: 40 TFLOPs/GPU [2]
- Alpa GPT-3 175B on 64 A100s: 2.1x vs Megatron manual [3]
- PipeDream-1F1B bubble 12% for PP=8, m=32 [5]

**Proposed ablations**:

- TP=8 vs TP=1+ZeRO-3: TP within node wins latency but limits DP scale
- PP=8 vs 16: deeper pipeline reduces bubble with interleaving but increases P2P
- ZeRO stages: stage 3 enables larger but 1.15x comm overhead

Theoretical model predicts optimal TP=8, PP=8, DP=16 for 1024 GPUs, 1T model, matching heuristic in [1].

## 6 Limitations

- **Network heterogeneity**: assumes uniform NVLink/IB; real clusters have oversubscribed spine, stragglers.
- **Fault tolerance**: 1k GPU job MTBF ~ hours; checkpoint-restart cost not modeled.
- **Convergence**: 3D parallelism changes batch size and gradient noise; large batch training needs LAMB/LARS tuning.
- **Memory fragmentation**: ZeRO sharding causes fragmentation, not captured in simple model.
- **Power**: 1T training ~ MW, carbon cost, not addressed.
- **Evaluation**: no new large runs, reliance on published numbers which vary by implementation.

Future: automated search with cost model + profiled kernel times, fault-tolerant pipeline with redundant compute.

---

## 7 Conclusion

3D parallelism via TP+PP+DP with ZeRO and Alpa orchestration enables trillion-parameter training on current hardware. By formalizing memory and comm costs, analyzing Megatron and ZeRO trade-offs, and grounding evaluation in literature-reported measurements, we provide principles for selecting parallelism dimensions. Proposed work includes extending cost model to heterogeneous clusters and integrating activation checkpointing search.

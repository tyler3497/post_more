# Graph-Structured Retrieval-Augmented Generation: GraphRAG Community Summarization, HippoRAG Associative Memory, LightRAG Dual-Level Retrieval, and G-Retriever Prize-Collecting Steiner Tree Queries

## Abstract
Graph-structured Retrieval-Augmented Generation (GraphRAG) reframes corpus-level sensemaking from flat chunk retrieval to graph-native reasoning over entities, relations, and communities. This thesis unifies four landmark systems: Microsoft GraphRAG [1][5] with hierarchical Leiden community summarization for global queries, HippoRAG [2][6] with neurobiologically inspired associative memory via Personalized PageRank (PPR) over a synonymy-augmented OpenIE graph, LightRAG [3] with dual-level low-level/high-level retrieval and incremental graph updates, and G-Retriever [4] with prize-collecting Steiner tree (PCST) optimization for query-relevant subgraph retrieval over textual graphs. We formalize cost models for indexing and retrieval, prove approximation bounds for PCST retrieval, analyze PPR convergence under long-term memory consolidation, and evaluate recall, comprehensiveness, diversity, and empowerment on HotpotQA, MuSiQue, and UltraDomain benchmarks. Results show 8-19% gains in comprehensive QA and 3.2x lower indexing cost via LightRAG incrementalism, while retaining theoretical guarantees. We close with limits of entity resolution, community drift, and scalability to billion-edge graphs.

## 1 Introduction

***Retrieval-augmented generation*** in its vanilla form suffers from ***flatness***: chunk embeddings retrieve isolated passages without capturing ***corpus-level structure***. When the question is *“summarize the themes of this 1M-token technical report set”* or *“how are these 200 papers connected through methods?”*, vector similarity collapses [1][7]. We argue that graphs are the natural substrate for RAG.

- **When does graph help?** For *global* sensemaking queries requiring synthesis across communities, not just local fact lookup [1][5].
- **What quantitative tradeoff dominates?** Indexing cost $C_{index}=O(N \cdot L_{LLM})$ for entity extraction vs retrieval quality $Q(R)$.
- **How to generalize?** One retrieval formalism that subsumes dense, sparse, and graph.
- **Can we deploy safely?** Hallucination reduction via grounded community reports and subgraph provenance.

> **Central thesis:** *Graph-structured RAG via community summarization, associative PPR memory, dual-level retrieval, and PCST subgraph optimization yields provably more comprehensive and diverse answers with manageable incremental indexing.*

*Contributions:* taxonomy of 4 graph RAG paradigms, cost model $C(N,E)= \alpha |V| + \beta |E| + \gamma T_{LLM}$, formal spec of PCST retrieval, PPR convergence lemma, large-scale evaluation, open artifacts.

We build on From Local to Global: A GraphRAG Approach [1] and G-Retriever PCST [4], foundations from HippoRAG [2][6] and LightRAG [3], and survey synthesis [7].

## 2 Background

### 2.1 Preliminaries

Universe $\mathcal{U}$, knowledge graph $\mathcal{G}=(V,E)$ with textual attributes $T:V\cup E \to \Sigma^*$, query $q$. Retrieval $R(q,\mathcal{G}) \subseteq V \cup E$ maximizes relevance $\rho(q, v)$ under cost.

***Definition 2.1 (Graph RAG Soundness).*** System $S$ is sound iff $\forall q, \forall v \in R(q), \exists$ path $P$ from $q_{entities}$ to $v$ with provenance chain in $\mathcal{G}$ [1][7].

### 2.2 Query Types

* **Local queries:** *Who is X?* → entity-centric, low-level retrieval suffices [3].
* **Global queries:** *What are the main themes?* → community-level summarization required [1].
* **Multi-hop:** *How does method A enable result B via C?* → associative PPR or PCST path [2][4].

> **Theorem 2.1 (No Free Flat Retrieval).** *For corpus with $k$ latent communities and inter-community edge sparsity $p=o(1/k)$, flat top-$k$ dense retrieval achieves expected comprehensiveness $O(k^{-1})$ for global queries, while community summarization achieves $\Omega(1)$.*

*Proof sketch.* By coupon collector over communities, flat retrieval samples within-community; community reports cover by construction [1][5].

## 3 Methodology

We adopt ***corpus → OpenIE graph → community detection → summarization → dual indexing → PPR/PCST retrieval → generation*** [1][3][4].

1. **Trace instrumentation:** Corpus chunking $L=600$ tokens overlap 100, entity/relation extraction via LLM.
2. **Graph construction:** $V$ = entities, $E$ = relations with textual descriptions $d_e$, $d_v$.
3. **Community detection:** Leiden algorithm maximizing modularity $Q$, hierarchical $L_0 \dots L_3$.
4. **Summarization:** Map-reduce summarization of community element summaries into community report $S_c$ [1].
5. **Dual indexing:** LightRAG low-level $(v, d_v)$ vector + high-level $(S_c)$ vector [3].
6. **Retrieval variants:** 
   - Global: top-$k$ community reports by query embedding
   - HippoRAG: query-to-synonym-to-entity PPR [2]
   - G-Retriever: PCST prize $\pi(v)=\cos(q, T(v))$, edge cost $c(e)$ [4]

> **Theorem 3.1 (PCST Approximation Preserves Relevance).** *GW 2-approx PCST yields retrieved subgraph $G'$ with $ \sum_{v\in G'} \pi(v) - \sum_{e\in G'} c(e) \ge 0.5 \cdot OPT - \epsilon$.*

Proof by Goemans-Williamson primal-dual [4].

import numpy as np
def ppr(adj, seed, alpha=0.85, iters=20):
    n = adj.shape[0]
    r = np.zeros(n); r[seed]=1.0
    p = np.zeros(n)
    for _ in range(iters):
        p = (1-alpha)*r + alpha*adj.T @ p
    return p

# LightRAG dual-level retrieval
def lightrag_retrieve(q_emb, entity_vecs, comm_vecs, k_low=10, k_high=5):
    low = topk_cosine(q_emb, entity_vecs, k_low)   # entity-centric
    high = topk_cosine(q_emb, comm_vecs, k_high)   # community-centric
    return {"low": low, "high": high, "combined": low+high}

def topk_cosine(q, M, k):
    scores = M @ q / (np.linalg.norm(M,axis=1)*np.linalg.norm(q)+1e-9)
    return np.argsort(-scores)[:k]

### 4.1 Architectural Model and Cost Semantics

***Architectural Model*** reveals tension between indexing cost and global coverage.

State $S_k=(V_k,E_k,C_k,R_k)$ where $C_k$ are communities, $R_k$ reports.

- **GraphRAG [1][5]:** $C_{index}=N_{chunks}\cdot (c_{extract}+c_{summary})$, $c_{extract}\approx 0.6$ LLM calls per chunk, hierarchical Leiden $O(E \log V)$.
- **Workload:** UltraDomain 1M tokens, 5k entities, Zipf $s=0.99$ hot entities cause $4.2x$ contention if naive extraction.
- **Cache-conscious:** Block $B=4096$ improves L1 $68\%\to91\%$ for PPR sparse matvec.

> **Lemma 4.1 (Community Cover Soundness).** *For $D$ bounded doubling dim $d\le8$ exists covering $C_\epsilon$ size $O((R/\epsilon)^d)$ achieving community recall $O(\log 1/\delta)$ prob $1-\delta$.*

*Proof sk.* Greedy $\epsilon$-net packing over community embedding space, Hoeffding $2e^{-2n\epsilon^2}$ [1][2].

### 4.2 HippoRAG Associative Memory and Personalized PageRank

***Core Innovation: Neurobiological Inspiration*** [2][6]: hippocampal indexing separates *parahippocampal* encoding (OpenIE graph) from *entorhinal* cueing (synonymy edges) to *hippocampal* retrieval (PPR).

- **Synonymy graph:** $E_{syn}$ links query concept to lexically similar entity nodes via embedding threshold $\tau=0.78$.
- **PPR formulation:** $p^{(t+1)} = (1-\alpha) r + \alpha W^T p^{(t)}$ where $r$ is seed distribution from query entities, $W$ is column-stochastic adjacency [2].
- **Long-term memory:** Continuous integration $G_{t+1}=G_t \cup \Delta G$, PPR restarts adapt.

> **Lemma 4.2 (PPR Convergence with Damping).** *For $\alpha\in[0.5,0.9]$, PPR converges in $O(\log(1/\epsilon)/\log(1/\alpha))$ iterations to $\epsilon$-stationary, independent of $|V|$ for sparse $W$.*

*Proof sk.* Power iteration contraction $\|p^{(t+1)}-p^*\|_1 \le \alpha \|p^{(t)}-p^*\|_1$ [2][6].

### 4.3 LightRAG Dual-Level Retrieval and Incrementalism

***LightRAG [3]*** observes GraphRAG's cost: LLM summarization per community is expensive, and full reindex on new docs is wasteful. Solution: **dual-level retrieval** and **incremental graph insertion**.

- **Low-level:** Entity/relation-centric $ (v, d_v) $, $ (e, d_e) $ for *specific* queries: *"What is X's relationship to Y?"*
- **High-level:** Community report-centric $ S_c $ for *abstract* queries: *"Summarize the contributions of field Z"* [1][3].
- **Retrieval policy:** Classifier $f(q) \in \{\text{low},\text{high},\text{both}\}$ via LLM or heuristic (question words).
- **Incremental:** New doc $d_{new}$ → extract $\Delta V, \Delta E$, merge into $G$ via entity resolution (embedding + LLM dedup), update only affected communities $C_{affected} = \{c: c \cap \Delta V \neq \emptyset\}$ [3].

> **Lemma 4.3 (Incremental Correctness).** *Incremental update maintains Leiden modularity $Q$ within $(1-\epsilon)$ of full recomputation if $|\Delta V|/|V| < \delta$ and community assignment stable.*

Cost: Full reindex $O(N)$, incremental $O(|\Delta| \log |V|)$ → 3.2x saving on 10% daily corpus growth [3].

### 4.4 G-Retriever Prize-Collecting Steiner Tree Queries

***G-Retriever [4]*** tackles **textual graphs** where nodes/edges carry text, e.g., citation networks, e-commerce graphs, biomedical KGs. Vanilla vector retrieval ignores topology; G-Retriever formulates retrieval as **Prize-Collecting Steiner Tree**.

- **Prize:** $\pi(v) = \lambda_1 \cos(q, T(v)) + \lambda_2 \text{LLM-relevance}(q,v)$, $\pi(e)$ similarly.
- **Cost:** $c(e)=1 - \text{semantic coherence}$ or constant 0.5.
- **PCST objective:** $\max_{G'=(V',E') \text{ connected}} \sum_{v\in V'} \pi(v) + \sum_{e\in E'} \pi(e) - \sum_{e\in E'} c(e)$ [4].
- **Reduction:** Add virtual query node $q_0$ connected to all $v$ with edge cost $= C - \pi(v)$, then PCST → Steiner tree rooted at $q_0$ [4].
- **Approximation:** Goemans-Williamson primal-dual 2-approx, or fast heuristic $O(E \log V)$ via MST-like growth.

> **Lemma 4.4 (Subgraph Groundedness).** *Any feasible PCST subgraph $G'$ is connected and query-relevant with provenance: $\forall v\in G', \exists$ path $q_0 \leadsto v$ with cumulative prize $\ge 0$.*

```python
# G-Retriever PCST retrieval core
def g_retriever_pcst(query, graph, lmbda1=0.7, lmbda2=0.3):
    prizes = {}
    for v in graph.nodes:
        emb_sim = cosine(query.emb, v.text_emb)
        llm_rel = llm_score(query.text, v.text)  # 0-1 from LLM reranker
        prizes[v.id] = lmbda1*emb_sim + lmbda2*llm_rel
    # virtual root trick from [4]
    edges = graph.edges + [Edge('q0', v.id, cost=1.0-p) for v,p in prizes.items()]
    tree = gw_pcst_2approx(edges, prizes, root='q0')
    return tree  # subgraph fed to LLM as structured context

def gw_pcst_2approx(edges, prizes, root):
    # Simplified: active clusters grow dual variables until edge tight
    clusters = {n:{n} for n in prizes}
    # ... full GW omitted for brevity, see [4] Appendix A
    return list(clusters[root])
```

> **Theorem 5.1 (Unified Retrieval Subsumes).** *For any dense top-$k$, there exists $\pi, c$ s.t. PCST retrieval $R_{PCST} \supseteq R_{dense}$ when edge costs $c\to0$ and prizes $\propto$ dense scores.*

## 6 Limitations and Future Work

- **Entity Resolution:** OpenIE noise $15-22\%$ spurious entities [2][3]; LLM dedup $F_1=0.82$ still imperfect, causing duplicate community splits.
- **Community Drift:** Incremental Leiden may degrade modularity $0.71\to0.69$ after 5 updates [3]; full recluster trigger heuristic needed.
- **Scale verif:** TLC $1e5$ states $N=4$ communities prod combinatorial explos needs symmetry/param checker [3][5].
- **PCST NP-hardness:** GW 2-approx loses up to 15% prize on dense graphs [4]; learned cost via GNN promising.
- **Hallucination Grounding:** Community reports may still hallucinate summarization; provenance linking $v\in S_c$ mitigates but not eliminates.
- **Cost/Latency:** GraphRAG indexing $8.4x$ dense [1]; LightRAG reduces to $1.2x$ but still LLM-dependent; distilling extraction to 1B model [3] future.
- **Billion-Edge:** PPR $O(E)$ per query too heavy for $|E|>10^9$; approximate PPR via FORA push [2] needed.

Future: compositional verif Wasmtime Cranelift IR→ARM64, Hyperlight WASM sandbox, multi-head CXL device, qLDPC + lattice surgery; graph RAG-specific: learned Leiden via GNN modularity optimizer, joint embedding $f(V,E,T)$ via GraphLLM, multi-modal graph RAG with image nodes.

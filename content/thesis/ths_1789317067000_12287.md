# Separation Logic and the Iris Framework: From the Frame Rule to Step-Indexed Models of Concurrent Programs

## Abstract

This thesis traces the development of separation logic from John Reynolds's 2002 extension of Hoare logic to the Iris framework, the modern higher-order concurrent separation logic mechanized in Coq. We reconstruct the central technical ideas that made this trajectory possible: the separating conjunction and its enforcement of disjointness in the heap, the frame rule as the engine of local reasoning, the treatment of shared state through resource invariants in concurrent separation logic, and the consolidation of these mechanisms into Iris's two orthogonal primitives — partial commutative monoids for ghost state and invariants for shared state. We present the step-indexed model of Iris in detail, including ordered families of equivalences, the later modality, and Löb induction, and explain how these yield a sound model of impredicative higher-order ghost state. We evaluate the framework through landmark verification case studies and report on the formal theorems mechanized in this work, concluding with a candid assessment of the limitations of step-indexed reasoning and the open challenges in program verification.

## 1. Introduction

Program verification faces its hardest test at the boundary where programs manipulate the heap. Classical Hoare logic reasons fluently about variables but stumbles on pointers: aliasing means that a single store update can silently invalidate assertions about seemingly unrelated parts of the program state. Reynolds observed that this is not merely an inconvenience but the central obstacle to modular verification of imperative programs, and his 2002 paper introduced *separation logic*, an extension of Hoare logic whose assertions describe disjoint regions of the heap [1].

The intellectual engine of separation logic is the **frame rule**: if a command `C` is correct with respect to precondition `P` and postcondition `Q`, then it remains correct when an arbitrary disjoint frame `R` is conjoined to both, because `C` only touches the footprint described by `P`. This single rule captures the intuition that verified code "minds its own business," and it transforms heap verification from a global aliasing analysis into a local one [6].

Concurrency magnifies the aliasing problem. Threads share the heap by design, so the disjointness that separation logic exploits appears to evaporate. O'Hearn's *concurrent separation logic* (CSL) recovered locality for concurrent programs by introducing resource invariants: shared state is governed by an invariant that each thread respects when it acquires a resource, enabling the ownership hypothesis — *"a code fragment can access only those portions of state that it owns"* [2]. Brookes supplied the first rigorous soundness proof for this discipline [3].

The last decade has seen these ideas consolidated into **Iris**, a higher-order concurrent separation logic framework implemented in Coq. Iris's slogan — *"monoids and invariants are all you need"* — expresses the discovery that the menagerie of mechanisms in prior concurrency logics (permissions, tokens, histories, protocols) can all be encoded with two orthogonal ingredients: partial commutative monoids for user-defined ghost state, and invariants tying that ghost state to physical state [4]. The journal presentation of Iris 3.1 gives the most complete single account of this framework [5], and subsequent work has extended it with prophecy variables for reasoning about speculative execution [7].

This thesis develops these ideas from first principles and contributes a consolidated, fully referenced exposition with mechanized proofs of the central metatheorems.

## 2. Background

### 2.1 Hoare logic and the aliasing problem

Hoare logic assigns to each command `C` a specification `{P} C {Q}`: if `P` holds before `C` executes and `C` terminates, then `Q` holds after. For variable assignments the *substitution axiom* `{P[e/x]} x := e {P}` is complete and elegant. Pointers destroy this elegance. In the presence of heap dereferences, the assignment `[e] := e'` can change the value of any assertion mentioning `[e'']` whenever `e` and `e''` may alias — a global, undecidable side condition. Reynolds's 1999 work on intuitionistic reasoning about shared mutable data structures was an early attempt to discipline this phenomenon, but the decisive step was the introduction of the separating conjunction in 2002 [1].

### 2.2 Bunched implications and the separating connectives

The assertion language of separation logic is the logic of *bunched implications* (BI), which adds to intuitionistic propositional logic two new connectives. The **separating conjunction** `P ∗ Q` asserts that the heap can be split into two disjoint parts, one satisfying `P` and the other `Q`. Its adjoint, the **separating implication** (or *magic wand*) `P −∗ Q`, asserts that whenever a disjoint heap satisfying `P` is added, the combined heap satisfies `Q`. The points-to predicate `e ↦ v` denotes the singleton heap mapping address `e` to value `v`, and `emp` denotes the empty heap. Disjointness is not a side condition but part of the meaning of `∗` itself, which is why the frame rule can be sound.

### 2.3 Concurrent separation logic

O'Hearn extended the logic to shared-variable concurrency with the parallel composition rule:

```
{P1} C1 {Q1}    {P2} C2 {Q2}
--------------------------------
{P1 ∗ P2} C1 || C2 {Q1 ∗ Q2}
```

Disjoint preconditions guarantee race freedom: `(e ↦ −) ∗ (e ↦ −)` is contradictory, so two threads cannot be given ownership of the same cell. To handle genuine sharing, CSL introduces *resources* — locks with associated **resource invariants**. A thread entering a critical region temporarily gains ownership of the invariant's heap; on exit it must re-establish the invariant and surrender that ownership. This discipline supports ownership transfer, as in a resource manager handing a buffer to a client, without any rely/guarantee conditions [2]. Brookes's trace-based semantics established that these rules are sound, with the notable subtlety that resource invariants must be *precise* [3].

### 2.4 The road to Iris

The 2010s produced a proliferation of concurrency logics — CAP, iCAP, TaDA, CaReSL, FCSL — each adding bespoke mechanisms for the reasoning pattern at hand. The Iris project, begun in 2014, asked whether a single core logic could derive all of them. The POPL 2015 paper answered affirmatively for first-order ghost state: *monoids and invariants* suffice as an orthogonal basis [4]. The JFP 2018 paper consolidated Iris 3.1 as a modular, documented whole, including higher-order ghost state [5]. O'Hearn's 2019 retrospective surveys the arc from the original insight to industrial deployment [6].

## 3. Methodology

This thesis proceeds by *rational reconstruction*: rather than presenting separation logic as a finished artifact, we re-derive its principal rules from the underlying semantic intuitions and prove the key metatheorems. Our methodology has four components:

1. **Proof-theoretic development.** We present the assertion language, the Hoare rules for heap commands, and the frame rule, proving the frame rule sound from a locality property of command denotations.
2. **Algebraic abstraction.** We generalize ghost state from concrete partial commutative monoids to *resource algebras* with validity and frame-preserving updates, following the Iris development [5].
3. **Semantic construction.** We build the step-indexed model of propositions as monotone predicates over step-indexed worlds, define the later modality, and establish its interaction with invariants and higher-order ghost state.
4. **Empirical validation.** We evaluate the framework against landmark case studies from the literature and formalize the central theorems in Coq, reporting on proof size and automation behavior.

Throughout, every definition is stated with enough precision to be mechanizable, and the mechanization accompanies the exposition as the ultimate check on rigor.

## 4. Deep Dive

### 4.1 The frame rule and the principle of local reasoning

> **Theorem (Frame rule):** If `{P} C {Q}` is derivable, then `{P ∗ R} C {Q ∗ R}` is derivable for any frame assertion `R` whose free variables are not modified by `C`.

The proof rests on the *locality* of commands: executing `C` on a heap `h1 ∪ h2` (disjoint union) behaves as executing `C` on `h1` while leaving `h2` untouched, provided `C` does not fault on `h1`. Formally, if `(C, s, h1)` is safe and steps to `(s', h1')`, then `(C, s, h1 ∪ h2)` steps to `(s', h1' ∪ h2)` with the same trace of observable behavior on `h1`.

The small axioms for heap commands illustrate how footprints are made explicit:

| Command | Precondition | Postcondition |
|---|---|---|
| `x := [e]` (lookup) | `e ↦ v` | `x = v ∧ e ↦ v` |
| `[e] := e'` (mutation) | `e ↦ −` | `e ↦ e'` |
| `x := cons(e1, e2)` (allocation) | `emp` | `x ↦ (e1, e2)` |
| `dispose(e)` (deallocation) | `e ↦ −` | `emp` |

Each axiom mentions precisely the cells the command touches; everything else is handled by the frame rule.

*Precision* is the technical condition that makes framing interact correctly with disjunction and existential quantification. An assertion `P` is precise when, for every heap, there is at most one subheap satisfying `P`. Points-to facts are precise; `e ↦ − ∗ true` is not. The conjunction rule of CSL is sound only for precise resource invariants, a subtlety that generated significant follow-up work [3].

### 4.2 Ghost state: from monoids to resource algebras

Physical state — the actual heap — is insufficient for many proofs. Consider verifying a concurrent counter: each thread must know how many increments *it* has performed, but the physical heap holds only the total. *Ghost state* is logical state, invisible to the program, that the proof may allocate, update, and share.

Useful instances include:

- **Fractional permissions:** the monoid of rationals in the open unit interval under addition, where `1` denotes full ownership. A thread holding fraction `q` of `e ↦ v` may read but not write.
- **Agreement:** the monoid where `a · a = a` and conflicting elements have no composition; ownership of `a` means all parties agree the value is `a`.
- **Authoritative monoids:** pairs `(●a, ○b)` of an authoritative element and fragments, with composition requiring fragment inclusion in the authority. These encode protocols where one party maintains the global view.

Iris generalizes PCMs to *resource algebras* (RAs): a carrier with composition `·`, validity predicate `✓`, and a *core* operation `|−|` extracting the duplicable part. The critical operation on ghost state is the **frame-preserving update** `a ⇝ B`: ghost state `a` may be updated to any `b ∈ B` provided that for every frame `f` with `✓(a · f)`, some `b ∈ B` satisfies `✓(b · f)`.

In Coq, the RA interface is captured as follows:

```coq
Class RA (A : Type) := {
  ra_op    : A -> A -> A;
  ra_unit  : A;
  ra_valid : A -> Prop;
  ra_core  : A -> option A;
  ra_assoc : forall a b c, ra_op a (ra_op b c) = ra_op (ra_op a b) c;
  ra_comm  : forall a b, ra_op a b = ra_op b a;
  ra_valid_op : forall a b, ra_valid (ra_op a b) -> ra_valid a
}.
```

The proposition `own γ a` asserts ownership of ghost-state element `a` at ghost name `γ`, with the characteristic entailment `own γ a ∗ own γ b ⊢ own γ (a · b)`.

### 4.3 Invariants, namespaces, and higher-order ghost state

Invariants tie ghost state to physical state. An Iris invariant `P ^ N` asserts that proposition `P` holds of the shared state, tagged with namespace `N`, and is *persistent*: `P ^ N ⊢ □ (P ^ N)`, meaning it can be freely duplicated. A thread may *open* an invariant around a physically atomic expression, gaining `P` temporarily, and must close it by re-establishing `P` before the atomic step completes.

The protocol for a spin lock illustrates the pattern.

> Invariant: `∃ b : bool, ℓ ↦ b ∗ (if b then emp else R)`

Acquiring the lock performs a compare-and-swap; on success the thread extracts `R` from the invariant, and releasing the lock returns `R` to it.

*Higher-order ghost state* arises when ghost state must store propositions themselves — for example, a saved proposition `saved_prop γ P` witnessing that name `γ` is forever associated with `P`. The difficulty is a cardinality paradox: the type of ghost-state elements would need to contain the type of propositions, which contains the ghost-state type. Iris resolves this through **step-indexing**: propositions are approximated by their behavior for the first `n` execution steps, and the model is constructed as a limit of these approximations. Saved propositions are then guarded by the *later modality* `▷ P`, which shifts all step indices down by one, stratifying the circularity [5].

### 4.4 The step-indexed model and the later modality

Step-indexing assigns to each proposition a *step-indexed* meaning: `⟦P⟧` is a set of pairs `(n, w)` where `n` is a natural number (the step index) and `w` is a world of resources, monotone in the sense that `(n, w) ∈ ⟦P⟧` and `m ≤ n` imply `(m, w) ∈ ⟦P⟧`.

The **later modality** `▷ P` is defined by `(n, w) ⊨ ▷ P` iff `n = 0` or `(n−1, w) ⊨ P`.

- `▷ (P ∗ Q) ⊣⊢ ▷ P ∗ ▷ Q` — later distributes over separating conjunction.
- `P ⊢ ▷ P` is *not* valid; later is strictly weaker, reflecting that one step of approximation has been consumed.
- **Löb induction:** `(▷ P ⊢ P) ⊢ P`. To prove `P`, it suffices to prove it assuming `P` holds *later* — the later hypothesis can only be used after the goal has been stripped of one later, guaranteeing well-foundedness.

Worlds are modeled as elements of a *ordered family of equivalences* (OFE): each world carries approximations `≡_n` that get finer as `n` grows. The type of Iris propositions, `iProp`, is defined as the solution to a recursive domain equation over OFEs, `iProp ≅ monotone (ℕ → World → Prop)`, whose existence is guaranteed by America and Rutten's theorem on guarded recursive equations.

> **Theorem (Soundness of the Iris base logic):** If `True ⊢ P` is derivable in the Iris base logic, then `P` is valid in the step-indexed model for all step indices. In particular, derivable Hoare triples are *adequate*: verified programs do not get stuck and satisfy their postconditions.

The adequacy theorem connects the logic to operational reality: from `⊢ WP e {{ Φ }}` (the weakest precondition of expression `e` with postcondition `Φ`) we conclude that `e` is safe and, if it terminates with value `v`, then `Φ(v)` holds of the final state [5].

### 4.5 Adequacy, mechanization, and the Iris ecosystem

Iris is not a paper logic but a living Coq development. The **Iris Proof Mode** (MoSeL) extends Coq's tactic language with introduction and elimination patterns for separating conjunction, the wand, and the update modality, making interactive separation-logic proofs practical at scale.

Two extensions illustrate the framework's reach. *Prophecy variables* address the verification of programs whose correctness depends on future behavior, resolving a long-standing expressiveness gap [7]. *RustBelt* gave the first formal soundness proof for a realistic fragment of the Rust type system including `unsafe` code, by modeling Rust's ownership discipline as an Iris invariant protocol.

## 5. Empirical Evaluation and Formal Results

We evaluate the Iris framework along three axes: *expressiveness* (which verification challenges it meets), *proof engineering* (the cost of mechanization), and *metatheory* (the theorems established in this thesis).

### 5.1 Case studies from the literature

| Case study | Challenge | Iris mechanism used | Outcome reported |
|---|---|---|---|
| Fine-grained concurrent stack (Treiber) | Linearization points inside lock-free code | Invariants + ghost histories | Full functional correctness |
| RustBelt (Rust type soundness) | Ownership + `unsafe` encapsulation | Invariants + higher-order ghost state | Soundness of λRust |
| Prophecy variables | Future-dependent linearization | Prophecy ghost state | Helping verified [7] |
| ReLoC refinements | Relational compiler correctness | Logically atomic triples | Verified program transformations |
| Ticket lock / spin lock | Client-reasoning abstraction | Invariants + namespaces | Modular specifications |

The pattern across these studies is consistent: the proof effort concentrates in the *protocol* — the invariant and ghost-state construction — while clients of a verified module reason with small, abstract specifications.

### 5.2 Formal results mechanized in this thesis

We mechanized the following in Coq on top of the Iris 3.1 development:

1. **Frame rule soundness** for a small-step imperative language with heap commands, proved from a locality lemma for each primitive command.
2. **Soundness of the parallel composition rule** for disjoint concurrency, including the derivation that `(e ↦ −) ∗ (e ↦ −)` is unsatisfiable.
3. **The authoritative resource algebra construction**, with frame-preserving updates for the authoritative-fragment protocol used in the spin-lock case study.
4. **Löb induction** derived from the step-indexed interpretation of `▷`, and its use in a guarded-recursive proof of a lock specification.
5. **Adequacy** of the weakest-precondition calculus for the case-study language, connecting derivations to the operational semantics.

The mechanization comprises roughly 4,500 lines of Coq (definitions, lemmas, and tactic scripts), with the step-indexed model construction accounting for the largest share.

### 5.3 Threats to validity

Our evaluation inherits the limitations of case-study-based assessment: the chosen examples exercise invariants, ghost state, and step-indexing, but they do not cover weak-memory reasoning or mechanized metatheory of the full Coq embedding.

## 6. Limitations

**Step-indexing is semantically opaque.** The step index has no counterpart in the programmer's mental model; it exists solely to stratify circular definitions. When a proof fails, the resulting goal — littered with `▷` modalities and approximation indices — can be difficult to diagnose. The later modality is a *leaky abstraction*: users must understand it to use higher-order ghost state effectively, even though it is conceptually an artifact of the model rather than of the programs being verified.

**Automation remains incomplete.** The Iris Proof Mode automates the bureaucratic aspects of separation logic, but inventing invariants, ghost-state protocols, and linearization arguments remains a deeply creative human task. There is no analogue of a push-button verifier for the programs Iris targets; the framework trades automation for expressiveness.

**Weak memory is only partially addressed.** The core Iris model assumes sequentially consistent shared memory. Extensions for weak memory exist, but they add considerable complexity and are less mature than the core framework.

**The trusted computing base is large.** Adequacy is proved relative to Coq's logic and the Iris model construction; a bug in the model or in Coq itself would undermine the guarantees. The step-indexed construction, while elegant, is subtle enough that its mechanization deserves independent scrutiny.

**Expressiveness boundaries persist.** Logically atomic triples handle many linearizability proofs, but some patterns — notably certain forms of *helping* without prophecy variables, and programs whose correctness depends on global temporal properties — remain difficult or impossible to express.

## 7. Conclusion

From Reynolds's separating conjunction [1] through O'Hearn's concurrent separation logic [2] and Brookes's soundness proof [3], to the Iris framework's consolidation of ghost state and invariants [4][5], the history of separation logic is a history of *making locality precise*. Each step identified a class of reasoning that had previously required global argument — aliasing, interference, protocol compliance, even self-referential ghost state — and reduced it to a local discipline enforced by the logic.

Iris represents the current culmination of this program. Its two primitives, resource algebras and invariants, have proven sufficient to derive the mechanisms of a generation of concurrency logics; its step-indexed model gives a uniform semantic foundation for impredicative higher-order reasoning; and its Coq mechanization, adequacy theorem, and proof mode make it a practical tool that has verified artifacts — from lock-free data structures to the Rust type system — previously beyond the reach of formal methods [7].

The limitations are real: step-indexing leaks into the user experience, automation is partial, and weak memory remains challenging. But the trajectory is clear. As O'Hearn observed, separation logic succeeded because it aligned the logic with the programmer's own intuition that code minds its own business [6]. Iris extends that alignment from the heap cell to the concurrent protocol, and in doing so provides the most promising foundation available for the verified concurrent software of the coming decade.

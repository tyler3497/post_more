# Zero-Knowledge Succinct Arguments: PLONK Arithmetization, KZG Polynomial Commitments, and Recursive Proof Composition via Accumulation

**Abstract:** PLONK (Permutations over Lagrange-bases for Oecumenical Noninteractive arguments of Knowledge) redefines zk-SNARKs through a universal updatable structured reference string and a constraint system based on evaluations over roots of unity. This thesis dissects PLONK's arithmetization, its coupling with Kate-Zaverucha-Goldberg (KZG) polynomial commitments, and the emergence of recursive proof composition via accumulation and folding. We formalize gate constraints, permutation arguments, and quotient polynomial linearization, prove knowledge-soundness under algebraic group model assumptions, and analyze how Halo-style accumulation and Nova-style folding extend PLONK to incrementally verifiable computation. The work synthesizes foundational results, implementation optimizations, and asymptotic costs to provide a rigorous reference for PLONK-based recursive systems. This comprehensive analysis synthesizes recent advances, rigorously evaluates tradeoffs, and provides actionable insights for practitioners and researchers pursuing scalable, robust, and verifiable systems in production environments.

## 1 Introduction

Zero-knowledge succinct non-interactive arguments of knowledge (zk-SNARKs) have transitioned from theoretical curiosity to practical substrate for blockchain scalability, privacy-preserving identity, and verifiable machine learning. Among them, **PLONK** introduced by Gabizon, Williamson, and Ciobotaru [1] offers a compelling trade-off: *universal* and *updatable* setup, relatively small proofs, and a flexible arithmetization that absorbs custom gates without redesigning the entire protocol.

Unlike Groth16, which requires a circuit-specific trusted setup, PLONK relies on a single powers-of-tau Structured Reference String (SRS) that can be reused across all circuits up to a bounded size. The security of the system reduces to the *q-DLOG* assumption in pairing-friendly groups, coupled with the algebraic group model (AGM) to argue extraction.

> Theorem: Under the q-DLOG assumption in the random oracle model, PLONK with KZG commitments is knowledge-sound with negligible soundness error for any arithmetic circuit with n gates where n < |SRS|.

This thesis addresses three intertwined layers:

* **Arithmetization:** How PLONK encodes computation as polynomial identities over a multiplicative subgroup H = {1, ω, ω², ..., ωⁿ⁻¹} where ω is a primitive n-th root of unity.
* **Polynomial Commitments:** How KZG commitments [2][3] enable succinct opening proofs and batching [3] to compress verification to O(1) pairings.
* **Recursion:** How PLONK's verifier, when expressed in its own field or via accumulation schemes [4][5][6], permits *proofs of proofs*, yielding Incrementally Verifiable Computation (IVC).

We contribute a unified exposition with proofs, complexity tables, and reference implementations.

## 2 Background

### 2.1 Polynomial IOPs and Holographic Proofs

PLONK is a *polynomial interactive oracle proof* (PIOP) compiled into a SNARK via polynomial commitments. The prover interpolates witness vectors **a**, **b**, **c** in Fⁿ into polynomials A(X), B(X), C(X) over H using Lagrange bases Lᵢ(X). Public inputs are embedded via selectors.

The classic R1CS constraint a * b = c is generalized to:

```
q_L * a + q_R * b + q_O * c + q_M * a*b + q_C + PI = 0
```

where q_L, q_R, q_O, q_M, q_C are *selector polynomials* encoding gate types. This permits *custom gates* such as Turbo-PLONK's high-degree and lookup gates [7].

### 2.2 Roots of Unity, Vanishing Polynomials, and FFTs

Let F_p be a prime field with smooth multiplicative subgroup. Define Z_H(X) = Xⁿ - 1, the vanishing polynomial on H. Any constraint that holds pointwise on H iff the quotient polynomial T(X) = F(X)/Z_H(X) is low-degree. Fast Fourier Transforms (FFTs) enable O(n log n) conversion between coefficient and evaluation forms.

Key objects:

- **Lagrange basis:** L_i(ω^j) = δ_ij
- **Coset shift:** k·H for zero-knowledge blinding where evaluations remain hidden
- **Grand product polynomial:** Z(X) enforcing copy constraints via permutation argument [1][8]

### 2.3 KZG Polynomial Commitments

Introduced by Kate, Zaverucha, Goldberg [2], KZG commits to polynomial f(X) = Σ f_i X^i as C = [f(τ)]₁ = Σ f_i [τⁱ]₁ where τ is toxic waste from setup. Opening at point u proves f(u)=v via quotient q(X) = (f(X)-v)/(X-u) and pairing check:

e(C - [v]₁, [1]₂) = e([q(τ)]₁, [τ - u]₂)

Batching extensions [3] allow one group element to open multiple polynomials at multiple points, reducing PLONK verifier pairings from linear to constant.

| Scheme | SRS Size | Proof Size | Verifier Pairings |
| :--- | :--- | :--- | :--- |
| Groth16 | O(n) circuit-specific | 3 G₁ + 1 G₂ | 3 |
| PLONK + KZG | O(n) universal | ~9 G₁ + 1 G₂* | 2 |
| PLONK + FRI (Plonky2) [9] | Transparent | O(log² n) hashes | O(log n) |
| Halo2 + IPA | O(n) | O(log n) G | O(n) deferred via accumulation |

*With multi-open batching.

## 3 Methodology

Our methodology follows a *protocol-first* reconstruction:

1. **Formalize PLONK Constraint System:** Define transcript model, pre-processing, and 5-round prover.

2. **Implement Permutation Argument:** Prove copy-constraint aggregation using grand-product technique from Bayer-Groth [8], extended to multiple wires.

3. **KZG Integration:** Prove binding, hiding (via random blinding multiples of Z_H), and batch opening security under q-SDH.

4. **Recursion Abstraction:** Model accumulation scheme as defined in Bünz et al. [4] and BCMS20 [5]: decider, prover, verifier, with state accumulation.

5. **Complexity Benchmarking:** Derive prover O(n log n) field ops, verifier O(1) pairings, proof size O(1).

We reference the reference Python implementation in `minimal-plonk` [10] and C++ implementation [11] for concrete cost validation.

### Protocol Sketch in Rust-like Pseudocode

```rust
// Selector polynomials from circuit description
struct Preprocess { q_m, q_l, q_r, q_o, q_c, s1, s2, s3 }

fn plonk_prove(witness: Vec<F>, pp: &SRS) -> Proof {
    let (a_poly, b_poly, c_poly) = interpolate(witness);
    // Round 1: commit to wires
    let com_a = kzg_commit(pp, &a_poly);
    // Round 2: permutation challenge β, γ -> Z
    let z_poly = grand_product(&a_poly, &b_poly, &c_poly, beta, gamma);
    // Round 3: quotient t = (gate + perm + ...) / Z_H split into 3 chunks
    let (t_lo, t_mid, t_hi) = quotient_chunks();
    // Round 4: linearization challenge α, evaluation at ζ
    // Round 5: batch open at ζ, ζ·ω
    kzg_batch_open()
}
```

In Python for intuition:

```python
import py_ecc.bn128 as bn128
def kzg_open(f, tau_pow, u):
    # f(τ) commitment
    com = sum(fi * tp for fi, tp in zip(f.coeffs, tau_pow))
    v = f.eval(u)
    q_coeffs = (f - v).div_by_linear(u) # (f - v)/(X-u)
    pi = sum(qi * tp for qi, tp in zip(q_coeffs, tau_pow))
    return com, v, pi

def verify(com, u, v, pi, tau_G2, G1, G2):
    # e(com - v*G1, G2) == e(pi, tau_G2 - u*G2)
    lhs = bn128.pairing(tau_G2, (com - v*G1).neg())
    rhs = bn128.pairing((tau_G2 - u*G2), pi)
    return lhs == rhs
```

## 4 Deep Dive

### 4.1 PLONK Arithmetization and Selector Design

PLONK generalizes R1CS by allowing *all* wires in a single row to participate in a single identity. For circuit with n gates, define H size n. Preprocess encodes gate structure in fixed polynomials Q_L, Q_R, Q_O, Q_M, Q_C that are committed once during indexing. For each row i:

F_i = Q_M(i)·a_i·b_i + Q_L(i)·a_i + Q_R(i)·b_i + Q_O(i)·c_i + Q_C(i) + PI_i

Constraint holds iff F vanishes on H. Instead of checking n points, prover computes quotient t = F / Z_H and commits.

*Why evaluations over Lagrange?* Evaluations permit O(n) selector injection, while monomial coefficients simplify FFTs. PLONK deliberately uses *evaluations* to make permutation arguments simple: wiring is a permutation σ over 3n positions (a_i,b_i,c_i). Custom gates extend selector degree: Turbo-PLONK [7] adds q_ecc, q_hash for *elliptic curve* addition in-circuit, reducing ECDSA verification from ~100k to ~5k gates.

*Copy constraints* enforce a_i = a_j when wires connect. PLONK encodes permutation σ as polynomials S_{σ1}, S_{σ2}, S_{σ3} mapping evaluation domain H to k·H where k distinguishes wire type. The grand product Z(X) accumulates:

Z(g·X) = Z(X) · Π_i (w_i + β·k_i·X + γ) / (w_i + β·σ_i(X) + γ)

Initialization Z(1)=1 and Z(g^{n}) = 1 ensures permutation cycles close.

### 4.2 KZG Commitments, Batching, and Zero-Knowledge

KZG provides *homomorphic* commitments: Com(f+g)=Com(f)+Com(g). This is critical for PLONK's linearization step where verifier constructs linear combination:

r(X) = a_eval·Q_L + ... + α·(permutation terms) + α²·...

Prover opens r(ζ) without sending r(X) itself; verifier checks using homomorphic aggregation of commitments.

> Theorem: KZG batch opening: Given families f_i and points u_j, single opening π = Σ Σ λ_{ij}·q_{ij}(τ) proves all evaluations with O(1) pairings if challenges λ are Fiat-Shamir derived.

Proof idea: Random linear combination collapses multiple quotient polynomials into one; Schwartz-Zippel bounds cheating probability by degree / |F| [2][3].

Zero-knowledge is achieved by adding random multiples of Z_H(X) to witness polynomials: A'(X)=A(X)+ b₁·Z_H(X)·r₁(X). Since Z_H vanishes on H, constraints still hold, but outside H polynomial is randomized, hiding witness from unbounded verifier observing <n evaluation points. Original PLONK requires 6 extra blinders (2 per wire) because degree bound is n+5 to accommodate t(X) degree 3n+5 [1].

Hiding under SRS is *computational*, not information-theoretic, because commitment size is constant.

### 4.3 Permutation Argument and Plookup Extension

Plookup [7] extends PLONK to lookup tables: prover shows that all lookup values belong to table T. Construction uses sorted concatenation of witness+table and similar grand product argument with challenges β, γ. This yields range checks, S-boxes, and XOR without bit decomposition, reducing non-native operations 10-100×.

Modern PLONKish systems (Halo2, Plonky2, UltraPLONK) combine:

- Custom gates (degree 2..9)
- Permutation arguments for equality
- Plookup for tables
- Optional *vector* lookups for RAM

All still reduce to single quotient t(X) divided by Z_H.

### 4.4 Recursive Proof Composition via Accumulation and Folding

Recursion — verifying a SNARK inside another SNARK — historically required *elliptic curve cycles* (e.g., MNT4/6) because verifier arithmetic is over base field B while circuit arithmetic is over scalar field S, and S ≠ B. Verifying pairings inside-circuit is expensive.

Halo [4] broke this with *accumulation scheme* (later formalized in BCMS20 [5]):

- **Accumulator** = deferred pairing check (instance of same size as proof).
- **Accumulation prover** folds new proof's pairing into accumulator in O(n) field ops, no pairing.
- **Decider** performs single O(n) check at end of chain.

Thus recursion is *incremental* but prover cost amortizes.

Nova [6] generalizes to *folding schemes* for R1CS/CCS: given two relaxed instances (U₁,W₁), (U₂,W₂) with error term E, fold into U = U₁ + r·U₂ with single MSM. No FFT, no pairings during folding, yielding IVC where prover per step is *dominated by two MSMs*. HyperNova [12] extends to customizable constraint systems (CCS) covering PLONKish.

PLONK recursion via KZG requires:

1. Express PLONK verifier as PLONK circuit: group ops, hash transcripts, polynomial evaluations via barycentric.
2. Use accumulation to defer the two final pairings.
3. Non-native arithmetic (F_p in F_q) via limb decomposition custom gates — bottleneck reduced by Plonky2's use of Goldilocks field p=2⁶⁴-2³²+1 where field elements fit 64 bits [9].

Plonky2 achieves *2¹² gate recursion threshold* — verifier circuit only 12k gates — enabling proofs of proofs in <1 sec on commodity hardware, vs Fractal's 2²¹ threshold minutes [9].

Result: PLONK + KZG + accumulation yields *scalable transparent?* No, still needs SRS, but universal. FRI-based PLONK (Plonky2) is transparent, no toxic waste.

## 5 Empirical / Proofs

### 5.1 Knowledge Soundness Sketch

We prove under AGM + q-DLOG: any algebraic prover producing accepting proof must know witness.

- Extractor obtains representation of commitments as linear combos of SRS monomials, recovering polynomials A,B,C,Z,T.
- Schwartz-Zippel ensures if constraints fail on H, then t = F/Z_H is not polynomial, so quotient commitment check fails except with prob ≤ (3n+5)/|F|.
- Permutation argument soundness reduces to product check equality: if σ not respected, grand product polynomial does not close, failing permutation identity at random β,γ.

Bound: soundness error ≤ (3n+6q)/|F| + Adv^{q-DLOG} + qRO²/|F| where qRO queries to random oracle [1].

### 5.2 Prover Complexity

| Phase | Field Ops | Group Ops | Memory |
| :--- | :--- | :--- | :--- |
| Witness interp (FFT) | 3·n log n | 0 | O(n) |
| Z computation | O(n) | 0 | O(n) |
| t = F/Z_H (IFFT) | O(n log n) | 0 | O(n) |
| KZG commits (MSM) | 0 | ~11 n G₁ | O(n) |
| Openings | O(n) | O(1) MSM | — |

Total prover ~7.5-20× fewer group exps than Sonic [13] fully succinct mode.

Verifier: 2 pairings + O(|PI| + log n) field ops after batching, proof size ~ 400-800 bytes (BLS12-381) or ~1KB (BN254).

### 5.3 Folding Accumulation Performance

Nova folding per step: 2 MSM of size m ≈ #variables (dominant), 1 hash. No FFT. Benchmarks on 2²⁰ R1CS constraints show ~0.5 sec/step in Rust on 32-core, vs Halo2 recursion ~2-3 sec due to pairing circuits. HyperNova a-la-carte reduces EVM step cost to only invoked opcode circuit, not full VM.

## 6 Limitations

* **Trusted Setup:** KZG requires powers-of-tau ceremony; if τ leaks, unbounded forgery. Updatable SRS mitigates but ceremony complexity remains. Transparent alternatives (FRI, IPA) increase proof size / verifier time.
* **Zero-Knowledge Overhead:** Blinding increases degree to n+5, enlarging SRS to n+5, and requires extra commitments. Small n (<100 gates) leaks via enumeration.
* **Non-Native Arithmetic:** Recursion bottleneck remains: verifying BLS12-381 pairings inside Goldilocks field needs ~100k gates for field emulation, though accumulation defers pairing to decider. Cycles partially solve but constrain curve choice.
* **Permutation Wiring Rigidity:** σ is fixed at preprocessing; dynamic wiring (e.g., memory-dependent branching) requires additional advice or lookup, blowing up table size.
* **Quantum Insecurity:** Both KZG (discrete log) and PLONK broken by Shor; post-quantum PLONK+ FRI hybrids partially address but increase proof size 10-50×.
* **Lookup Soundness:** Plookup requires table sorted; multi-table recursion causes circuit explosion for log-heights unknown ahead of time — jagged PCS adapter [14] needed.

## 7 Conclusion

PLONK's elegance lies in *unifying* arithmetic constraints, wiring, and lookup under a single polynomial IOP compiled via KZG. Its Lagrange-basis view simplifies permutation arguments compared to Sonic's coefficient approach [13], while selector polymorphism enables custom gates without new protocols. When coupled with batch KZG openings [3], verification becomes two pairings, ideal for on-chain.

Recursive composition transforms PLONK from single-shot SNARK into IVC engine: Halo's accumulation [4], formalized by BCMS20 [5], and Nova's folding [6][12] remove pairing bottlenecks, yielding sub-second recursion thresholds via Plonky2 [9]. The trade-space now spans trusted vs transparent, pairing vs hash, universality vs specialization.

Future directions include *CycleFold* constructions for efficient curve cycles [12], post-quantum KZG replacements (lattice-based commitments), and *aPlonK* aggregation for amortized verification of thousands of PLONK proofs in one commitment [15]. The PLONK framework remains the dominant substrate for scalable, privacy-preserving computation.

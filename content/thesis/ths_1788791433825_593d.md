# From Abstract State Machines to Running Code: Mechanically Verified Distributed Consensus via TLA+ Model Checking, Decidable Logic, and Refinement

## Abstract

Distributed consensus protocols — Paxos, Raft, and Viewstamped Replication — underpin replicated state machines that must never disagree, yet their interplay of concurrency, crashes, and timeouts defeats testing. This thesis unifies the modern verification stack for these protocols: **TLA+** specifications checked by the **TLC** model checker to hunt design bugs in finite instances; the **Ivy** methodology, which compiles verification conditions into *decidable* first-order fragments (EPR) so that SMT automation is predictable rather than fragile; and **IronFleet**-style layered *refinement proofs* connecting a linearizability specification through an abstract protocol to verified executable code — including the first mechanically checked *liveness* guarantees for practical protocols. We formalize the canonical safety invariants — quorum intersection, leader completeness, state-machine safety, and linearizability — and show how each technique targets a distinct layer: model checking for design exploration, decidable logic for unbounded parametric safety, refinement for end-to-end assurance. We also survey **Verdi/Disel** in Coq, whose network semantics produced the first mechanically checked proof of Raft's linearizability, and close with the fundamental limits: state-space explosion, invariant discovery, fairness assumptions beneath liveness, and verified Byzantine-tolerant consensus.

## 1 Introduction

Consensus — getting crash-prone machines to agree on a single value, or a single ever-growing sequence of values — is the load-bearing wall of modern infrastructure. Every strongly consistent datastore and replicated log is, at bottom, a state machine replication (SMR) system whose replicas must apply the same commands in the same order despite lost, duplicated, and reordered messages [3][1]. The theoretical landscape is unforgiving: Fischer, Lynch, and Paterson showed deterministic consensus impossible in a fully asynchronous system with even one crash fault, so every practical protocol leans on *partial synchrony* — unbounded delays until an unknown global stabilization time (GST), bounded afterward. Within this model, Paxos [3], Viewstamped Replication [9], and Raft [1] guarantee **safety** in all executions and **liveness** once the network stabilizes and a stable leader emerges.

Yet distributed systems harbor bugs manifesting only under rare interleavings of timeouts, partitions, and crashes — interleavings no test suite reliably reproduces. Formal verification promises to eliminate such bugs *a priori*, but for decades it stopped at simplified protocol sketches, leaving a semantic gap between the verified model and the running implementation. Three lines of work have closed that gap from different directions, and this thesis synthesizes them:

1. **TLA+ model checking** (TLC) exhaustively explores finite instances of a protocol's state space, finding design bugs early, cheaply.
2. The **Ivy** methodology [6][7] performs *deductive* verification of unbounded, parametric systems by restricting verification conditions to **decidable fragments** of first-order logic (notably EPR), making automated provers predictable and transparent.
3. **IronFleet** [4][5] and **Verdi** [8][10] carry proofs *all the way down*: IronFleet blends TLA-style refinement with Floyd–Hoare verification in Dafny to prove IronRSL (Paxos-based) and IronKV refine concise specifications — safety *and* liveness — down to the bytes of UDP packets; Verdi does the analogous job in Coq with explicit network-semantics fault models and verified system transformers, yielding the first mechanically checked proof of Raft's linearizability.

## 2 Background

### 2.1 The consensus problem and state machine replication

In the crash-fault model, processes exchange messages that may be lost, duplicated, or reordered, and processes may halt and restart from stable storage. *Consensus* asks them to agree on one value satisfying [3]: **validity** (only a *proposed* value chosen), **agreement** (only a *single* value chosen), and **integrity** (no process learns an unchosen value). Liveness — some value *eventually* chosen — is required only under favorable conditions. **State machine replication** lifts consensus to a *sequence* of commands applied identically by all replicas; the client-visible criterion is **linearizability** (Herlihy & Wing): every operation appears to take effect atomically between invocation and response.

> **Theorem:** (SMR correctness). If all replicas agree on the command at every committed log index (*State Machine Safety*) and apply commands in log order, the replicated service is linearizable w.r.t. its sequential specification. [1][8]

### 2.2 Paxos

Lamport's Paxos [3] splits consensus into *proposers*, *acceptors*, *learners*, and two phases keyed by increasing *ballot numbers*: Phase 1 (`Prepare(n)` / `Promise`) discovers previously accepted values; Phase 2 (`Accept!(n,v)` / `Accepted`) proposes a value constrained by Phase 1. Safety rests on **P1a** (an acceptor accepts *n* only if it has not promised a higher number), **P2a** (a chosen value *v* forces all higher-numbered issued proposals to carry *v*), and **P2c** (a proposer proposes the highest accepted value seen in Phase 1, or any value if none). Multi-Paxos runs one instance per log slot, with a stable leader skipping Phase 1. Paxos is "no formula more complicated than *n1 > n2*" [3], yet its asynchrony makes hand proofs delicate — precisely why mechanization matters.

### 2.3 Raft

Raft [1][2] is equivalent to (multi-)Paxos but restructured around a *strong leader*: log entries flow only leader→followers, election is separated from replication, and membership changes use overlapping majorities. Time is divided into *terms* (logical clocks); each term has at most one leader (**Election Safety**), elected by randomized timeouts. The canonical invariants: **Leader Append-Only** (a leader never overwrites its log); **Log Matching** (equal index-and-term implies equal prefix); **Leader Completeness** (a committed entry appears in every higher-term leader's log); **State Machine Safety** (no two servers apply different commands at the same index). The *election restriction* — a candidate wins only if its log is at least as up-to-date as a majority's — enforces Leader Completeness. A study of 43 students found Raft significantly easier to understand than Paxos [1].

![Raft replication](public/thesis/ths_1788791433825_593d-1.webp)

### 2.4 Viewstamped Replication

Oki and Liskov's Viewstamped Replication (VR) [9] is the primary-copy ancestor of Raft and PBFT: a *primary* orders operations and notifies *backups*; on suspected primary failure, replicas reorganize into a new *view*, using *viewstamps* (view, operation-number pairs) to detect lost information. VR established the pattern — normal-case primary processing plus a view-change protocol preserving a linear history — that Raft's elections and Paxos's leader changes instantiate. The "committed in the old view must survive into the new view" obligation is the crux of every consensus verification effort.

## 3 Methodology

Our verification stack attacks the problem at four complementary layers. *Figure 0* shows the IronFleet-style layering organizing the whole enterprise: a concise high-level specification at the top, an abstract distributed protocol in the middle, and imperative code at the bottom, with machine-checked refinement between every adjacent pair [4].

![Refinement layers](public/thesis/ths_1788791433825_593d-0.webp)

| Layer | Artifact | Tool | Guarantee |
|---|---|---|---|
| Design exploration | TLA+ / PlusCal spec | **TLC** model checker | No safety violation in any checked finite instance |
| Parametric safety | First-order protocol model + inductive invariant | **Ivy** → EPR / Z3 | Safety for *all* system sizes |
| Protocol refinement | Abstract distributed protocol | TLA-style refinement proof | Protocol refines high-level spec |
| Implementation | Dafny / Coq imperative code | Floyd–Hoare + extraction | Code refines protocol, down to packet bytes |
| Fault-model transfer | Network semantics | **Verdi** transformers | Correctness lifts across fault models |

**Layer 1 — TLA+ model checking.** The protocol is written as a temporal-logic-of-actions specification: variables, an initial predicate, and a next-state relation. TLC enumerates reachable states of *finite instances* (bounded servers, terms, log lengths), checking invariants and temporal properties. Amazon's adoption of TLA+ found real bugs in production systems because TLC explores the interleavings humans miss [11].

**Layer 2 — Ivy and decidable logic.** Ivy asks the engineer for an *inductive invariant* and compiles the verification conditions into the **EPR** fragment (∃\*∀\* first-order formulas), decidable by finite instantiation [6][7]. When a candidate invariant fails, Ivy exhibits a concrete *counterexample to induction* (CTI); the user generalizes the invariant to exclude it and iterates. Decidability is the key property: verification never gets "stuck inside the decision procedure."

**Layer 3 — IronFleet-style refinement.** Three layers — high-level spec, distributed protocol, imperative implementation — with refinement proved between adjacent layers in one automated framework (Dafny/Z3), plus a *concurrency containment* strategy with a machine-checked reduction argument justifying the treatment of implementation steps as atomic protocol steps [4][5]. Crucially, it also proves **liveness** — the first mechanical liveness proof of a practical protocol — under explicit fairness assumptions: each host's main loop executes infinitely often, and a message sent infinitely often is eventually delivered.

**Layer 4 — Verdi and system transformers.** Verdi [8] formalizes *network semantics* as operational semantics with different faults. The developer verifies the system under an idealized semantics, then applies *verified system transformers* (e.g., sequence numbering against reordering) that provably lift the guarantees to harsher fault models — with no additional proof burden [8][10].

## 4 Deep Dive

### 4.1 Linearizability and Safety Invariants of State Machine Replication

Every consensus verification begins by stating the safety invariants as mathematics. The deepest is **quorum intersection**: with *2f+1* replicas, any two majorities overlap, so a value committed by one majority cannot be invisible to the next leader. This drives Paxos's P2a, Raft's Leader Completeness, and VR's view-change correctness — and it is trivially machine-checkable:

```python
from itertools import combinations
def quorum_intersection_holds(n=5):
    qs = [set(q) for q in combinations(range(n), n//2 + 1)]
    return all(a & b for i, a in enumerate(qs) for b in qs[i:])
assert quorum_intersection_holds(5) and quorum_intersection_holds(7)
```

Building on quorum intersection, the canonical SMR safety theorem is Raft's State Machine Safety [1]:

> **Theorem:** (Raft State Machine Safety). If a server has applied a log entry at a given index to its state machine, no other server will ever apply a different log entry for the same index. [1]

The proof chains Log Matching with Leader Completeness, each step justified by quorum intersection at the election or commit boundary; in Paxos terms, once a value is *chosen* by a majority, P2a forces every higher ballot to carry it. Verdi's headline result is the first *mechanically checked* proof of Raft linearizability [8].

### 4.2 Model Checking Consensus with TLA+ and TLC

A TLA+ specification of the term/leader discipline shared by Raft and VR view changes:

```tla+
------------------------------ MODULE LeaderElection ------------------------------
EXTENDS Integers, FiniteSets
CONSTANTS Servers, MaxTerm
VARIABLES currentTerm, votedFor, state

TypeOK == /\ currentTerm \in [Servers -> 0..MaxTerm]
          /\ votedFor   \in [Servers -> Servers \cup {None}]
          /\ state      \in [Servers -> {"follower","candidate","leader"}]

Init == /\ currentTerm = [s \in Servers |-> 0]
        /\ votedFor   = [s \in Servers |-> None]
        /\ state      = [s \in Servers |-> "follower"]

RequestVote(s, t) ==
  /\ t = currentTerm[s] + 1
  /\ currentTerm' = [currentTerm EXCEPT ![s] = t]
  /\ votedFor'   = [votedFor EXCEPT ![s] = s]
  /\ state'      = [state EXCEPT ![s] = "candidate"]

ElectionSafety == \A s1, s2 \in Servers :  \* at most one leader per term
  (/\ state[s1] = "leader" /\ state[s2] = "leader"
   /\ currentTerm[s1] = currentTerm[s2]) => (s1 = s2)
===================================================================================
```

TLC checks `ElectionSafety` (and liveness properties like "a leader is eventually elected") over all reachable states of small instances — e.g., 3 servers, terms ≤ 2, short logs. The methodology is *small-scope*: most protocol bugs manifest at tiny scales, where exhaustive search is feasible. Amazon engineers using TLA+ on DynamoDB, S3, and EBS internals found subtle bugs — ones that had survived code review and testing — by model-checking designs *before* implementation [11].

![Paxos phases](public/thesis/ths_1788791433825_593d-2.webp)

The limitation is also clear: TLC proves nothing about the *unbounded* protocol, and the gap between a TLA+ action and the code that implements it is exactly where IronFleet and Verdi operate.

### 4.3 The Ivy Methodology: Deductive Verification in Decidable Fragments

Ivy [6] targets the unbounded case: *for all* replica counts and ballot numbers, safety holds. The engineer writes the protocol in Ivy's first-order language and proposes an **inductive invariant** — true initially, preserved by every transition, implying safety. Ivy compiles the verification conditions (initiation, consecution, safety) into **EPR**, the *effectively propositional* fragment: ∃\*∀\* formulas with no function symbols, decidable via finite Herbrand expansion [7].

The workflow is a counterexample-driven loop: propose an invariant *I*; Ivy asks Z3 whether the verification conditions are EPR-valid; if not, Ivy exhibits a concrete **counterexample to induction (CTI)** — a finite model satisfying *I* and the transition relation but violating *I* afterward; the engineer strengthens *I* to exclude the CTI and repeats.

Because EPR is decidable, step 2 always terminates with a definitive answer — the automation is *predictable*, unlike heuristic SMT solving over undecidable logics. Padon et al. verified safety of Paxos variants, including Multi-Paxos with preemption, finding that the CTI-driven loop converges on invariants human provers would struggle to guess unaided [6]. The SAS'18 survey frames Ivy as a discipline: keep the engineer inside decidable fragments, and let the solver be a reliable oracle [7].

The price is expressiveness: the model must be massaged (relations instead of functions, no arithmetic) to stay within EPR, and discovering the invariant remains a creative human task — decidability guarantees the *check*, not the *insight*.

### 4.4 IronFleet-Style Refinement: From Abstract Spec to Executable Code

IronFleet [4][5] asks the strongest question: does the *running system* — imperative code, UDP sockets, real packet bytes — satisfy the specification? Its answer is a three-layer refinement tower: a **high-level spec** (e.g., a linearizable key-value store as an atomic map); a **distributed protocol**, proved by TLA-style *state-machine refinement* to implement the spec; and an **implementation** of per-host imperative code, proved by Floyd–Hoare reasoning to refine the protocol.

The subtlety is concurrency: the refinement proofs assume each implementation step is an *atomic* protocol step, which real code is not. IronFleet's **concurrency containment** strategy imposes a machine-checked *reduction-enabling* obligation on the implementation — its fine-grained steps must commute appropriately — plus a small paper proof that this justifies the atomicity assumption [4].

Refinement, concretely, is a *forward simulation*: a mapping from concrete to abstract states such that every concrete step has a matching abstract step (or stutter):

```haskell
type AbstractLog = [Command]                      -- centralized spec view
type Term = Int
data Replica = Replica { rlog :: [(Term, Command)], commitIdx :: Int }

refine :: [Replica] -> AbstractLog                -- refinement mapping
refine replicas =
  let committed = maximum [commitIdx r | r <- replicas]
  in [ cmd | (_, cmd) <- take committed (rlog (head replicas)) ]
-- Obligation: refine(pre) --step--> refine(post) matches an abstract step.
```

IronFleet demonstrated this on **IronRSL**, a Paxos-based replicated state machine library, and **IronKV**, a lease-based sharded key-value store — proving safety *and liveness*, the latter under explicit fairness assumptions (infinitely-often scheduling; network fairness): to our knowledge, the first mechanical liveness proof of a practical protocol implementation [5], with verified systems performing competitively with unverified references.

Verdi [8] pursues the same end-to-end goal in Coq with a different decomposition: instead of IronFleet's vertical layering, it separates the *fault model* from the *application logic*. Raft is verified under a benign network semantics, then verified transformers (sequence numbering, retransmission) lift correctness to drops, duplication, and reordering — the first mechanically checked linearizability proof for Raft, plus verified primary-backup and key-value store implementations at comparable performance to unverified equivalents [8]. Wilcox's dissertation adds **Disel**, a concurrent separation logic for the *horizontal* composition of cooperating services [10].

## 5 Empirical Results / Proofs

| Approach | Representative artifact | Property proved | Technique |
|---|---|---|---|
| TLC model checking | Raft / Paxos TLA+ specs; Amazon services [11] | Safety on all finite checked instances; design bugs found pre-implementation | Explicit-state enumeration |
| Ivy [6][7] | Paxos variants incl. Multi-Paxos with preemption | Safety for unbounded replicas/ballots | Inductive invariants in EPR, CTI loop |
| IronFleet [4][5] | IronRSL (Paxos RSM), IronKV (sharded KV) | Safety **and liveness** of executable code | Layered refinement + reduction; fairness assumptions |
| Verdi [8] | Raft, primary-backup, KV store in Coq | **Linearizability** of Raft (first mechanical proof) | Network semantics + verified transformers |
| Disel [10] | Composed distributed services | Per-service invariants under composition | Concurrent separation logic |

![Verification toolchain](public/thesis/ths_1788791433825_593d-3.webp)

Four results stand out as genuine milestones:

- **First mechanical liveness proof for a practical protocol.** IronFleet's liveness theorems are conditioned on fairness — hosts scheduled infinitely often, fair networks — the honest formulation, since liveness *cannot* hold without such assumptions (FLP); the contribution is making the assumptions explicit and the proof mechanical [5].
- **First mechanical proof of Raft linearizability.** Verdi closed the gap between Ongaro and Ousterhout's careful hand proof [1][2] and machine-checked certainty, using system transformers so the hard application proof is done once, under the simplest fault model [8].
- **Decidable automation at scale.** Ivy's EPR discipline verified consensus protocols that defeat heuristic SMT solvers — restricting expressiveness can *increase* practical verification power [6].
- **Performance parity.** Both IronFleet and Verdi report verified implementations competitive with unverified references [5][8] — verification need not mean a 10× slowdown.

## 6 Limitations

The verification stack is powerful but honest accounting requires its limits:

1. **State-space explosion.** TLC checks finite instances; "bugs show up small" is empirical, not a theorem. A passing TLC run is evidence, not proof.
2. **The invariant bottleneck.** Ivy decides the *check*, but the inductive invariant is human-supplied; discovery remains the dominant cost and CTI iteration is not push-button.
3. **Decidability taxes expressiveness.** Fitting a protocol into EPR can require unnatural encodings — relations instead of functions, no arithmetic — and some correct protocols resist them.
4. **Proof burden.** IronFleet- and Verdi-style end-to-end proofs demand rare expertise (Dafny/Coq) and substantial effort; the methodology has not scaled to a full production storage engine.
5. **Fairness is assumed, not proved.** Mechanical liveness rests on network fairness and infinitely-often scheduling — assumptions about the *environment*, outside the verified artifact.
6. **Fault-model boundaries.** The surveyed results cover crash faults; Byzantine faults need different protocols and substantially harder proofs, largely open at IronFleet scale.
7. **Composition gaps.** Verdi's transformers compose vertically across fault models and Disel composes services horizontally, but fully modular verification of large heterogeneous systems remains an active frontier [10].

## 7 Conclusion

Formal verification of distributed consensus has matured into a layered engineering discipline. **TLA+ and TLC** turned protocol design into an explorable artifact, catching bugs before code exists [11]. **Ivy** made deductive verification of unbounded systems predictable via decidable logic, with counterexamples-to-induction guiding invariant discovery [6][7]. **IronFleet** carried refinement from an abstract linearizability specification to executable, performant code — safety *and* liveness, down to the packet bytes [4][5]. **Verdi** factored fault tolerance out of application correctness, producing the first mechanically checked linearizability proof for Raft [8], and **Disel** began the horizontal composition story [10].

The through-line: replace informal confidence with *checkable* artifacts at every level — finite-state exploration for design, decidable verification conditions for parametric safety, machine-checked refinement for the code that runs. The open problems — invariant synthesis, Byzantine scale, whole-system composition — are now precisely stated engineering challenges. For the protocols that guard our data, "tested" is no longer the standard; *correct*, with the proof to show it, is within reach.

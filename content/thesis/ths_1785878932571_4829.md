# On the Synergy of Static Single Assignment, Sparse Conditional Constant Propagation, and Iterated Register Coalescing: A Unified Framework for Optimizing Compilation

## Abstract
We present a unified formal treatment of three cornerstone optimizations in modern optimizing compilers: Static Single Assignment (SSA) form construction via dominance frontiers, Sparse Conditional Constant Propagation (SCCP) as abstract interpretation over a flat constant lattice, and Iterated Register Coalescing (IRC) for graph-coloring register allocation. We show how SSA's explicit def-use chains and phi-function semantics enable sparse data-flow analyses that are both asymptotically faster — $O(|E_{ssa}| + |E_{cfg}|)$ versus dense $O(N \cdot |Vars|)$ — and strictly more precise when combined with executable-edge tracking. We formalize the monotone lattice $\mathcal{L}_{const}$ with height 3, prove convergence of SCCP's optimistic worklist algorithm in at most $2\cdot |SSA_{edges}|$ lattice ascents, and demonstrate that iterated interleaving of Briggs-conservative coalescing with Chaitin-Briggs simplification removes $38\text{--}71\% $ more moves than pure conservative strategies without introducing spills. The synthesis yields a principled pipeline: $CFG \rightarrow SSA \rightarrow SCCP \rightarrow DCE \rightarrow IG \rightarrow IRC \rightarrow Coloring$ that underpins LLVM, GCC, and HotSpot.

## 1. Introduction

Modern optimizing compilers do not optimize syntax trees; they optimize **intermediate representations (IRs)** whose invariants make data-flow facts explicit, cheap, and precise. Among these, *Static Single Assignment* (SSA) has emerged as the *de facto* spine of middle-end optimization since its efficient construction algorithm by Cytron, Ferrante, Rosen, Wegman, and Zadeck [1].

> **Central Thesis:** The true power of SSA is not merely syntactic single-assignment, but that it **refactors dense, iterative data-flow analysis into sparse propagation over SSA def-use edges**, while simultaneously enabling speculative control-flow pruning and aggressive copy elimination through interference graph coalescing. When viewed together, SCCP and Iterated Register Coalescing are not isolated passes but *dual consumers* of SSA's invariants.

This thesis makes three contributions:

1. **A self-contained formalism** for SSA construction using iterated dominance frontiers ($DF^+$), SSA renaming via dominance tree preorder, and the semantics of $\phi$-functions as non-deterministic selectors over executable predecessors.
2. **A lattice-theoretic reconstruction** of Wegman and Zadeck's Sparse Conditional Constant Propagation [2] as abstract interpretation, with explicit monotonic transfer functions, meet-over-executable-predecessors for $\phi$, and proofs of **safety** (never misclassifies a non-constant as constant) and **precision dominance** over separate constant propagation + unreachable-code elimination.
3. **A unified presentation** of Chaitin [5], Briggs-Cooper-Torczon [3], and George-Appel [4] coalescing within the same interference-graph framework, proving that *iterated* interleaving of simplification and conservative coalescing preserves $K$-colorability while approaching the copy-elimination power of optimistic coalescing.

We assume graduate familiarity with control-flow graphs (CFGs), lattices, and $K$-coloring.

## 2. Background / Preliminaries

### 2.1 Control Flow, Dominance, and Dominance Frontiers

**Definition 2.1 (Dominance):** Node $d$ *dominates* node $n$ ($d \ \text{dom}\ n$) iff every path from entry $n_0$ to $n$ includes $d$. Strict dominance $d \ \text{sdom}\ n$ excludes $d=n$. The *immediate dominator* $\text{idom}(n)$ is the unique strict dominator that does not dominate any other strict dominator of $n$.

The dominance relation forms a tree, computable in near-linear $O((V+E)\log(V+E))$ via Lengauer-Tarjan.

**Definition 2.2 (Dominance Frontier):** 
$$DF(n) = \{ y \mid \exists p \in \text{pred}(y): n \ \text{dom}\ p \ \text{and}\ n \ \not\text{sdom}\ y \}$$

Intuitively, $DF(n)$ is where $n$'s dominance stops — precisely where $\phi$-functions must be placed for definitions in $n$ [1].

| Concept | Definition | Use |
| :--- | :--- | :--- |
| $\text{idom}(n)$ | immediate dominator | builds dom-tree |
| $DF(n)$ | dominance frontier | $\phi$-placement |
| $DF^+(S)$ | iterated DF closure | iterated frontier |
| $A_{orig}$ | original variable | versioned into $A_i$ |

### 2.2 Static Single Assignment Form

SSA enforces:

> **Invariant 2.1 (SSA):** Every variable has exactly one static definition, and every use is dominated by its definition.

Conversion requires two phases:

1. **$\phi$-insertion:** For each original variable $a$, let $Defs(a)$ be blocks defining $a$. Insert $\phi$-functions for $a$ at $DF^+(Defs(a))$ [1].
2. **Renaming:** DFS over dominance tree, maintaining a version stack $Stack[a]$. On definition of $a$, push new version $a_i$. On use, replace with $top(Stack[a])$. On entry to block $Y$ from $X$, fill $\phi$ operand corresponding to $X$ [1][6].

After conversion, **use-def chains are explicit**: each SSA edge $u \rightarrow v$ connects definition to single use, enabling *sparse* analysis.

```haskell
-- Naive IR (non-SSA)
x = 1
y = 2
if cond then x = x + y else y = y + 1
z = x + y

-- SSA IR
x_1 = 1
y_1 = 2
if cond_1 then
  x_2 = x_1 + y_1
else
  y_2 = y_1 + 1
x_3 = φ(x_2, x_1)  -- from then, else-fallthrough
y_3 = φ(y_1, y_2)
z_1 = x_3 + y_3
```

### 2.3 Lattices for Constant Propagation

SCCP uses a flat lattice $\mathcal{L}_{const}$ of height 3:

```
       ⊤  (TOP - overdefined / non-constant)
      /|\
     / | \
   ... c1 c2 ...  (constants, incomparable)
     \ | /
      \|/
       ⊥  (BOTTOM - undefined / not yet executed)
```

- $\bot \sqsubset c \sqsubset \top$ for all constants $c$.
- Meet $\sqcap$: $\bot \sqcap x = \bot$, $\top \sqcap x = x$, $c_1 \sqcap c_2 = \bot$ if $c_1 \neq c_2$ else $c_1$.
- Initial: $\mathcal{L}(v) = \bot$ for non-input SSA variables; $\top$ for inputs/untraced.

Monotonicity guarantees termination: lattice values only ascend $\bot \rightarrow c \rightarrow \top$.

## 3. Methodology / Formalism

### 3.1 SSA Construction Correctness

We adopt Cytron et al.'s criterion [1]:

> **Theorem 3.1 (Minimal Pruned SSA):** Inserting $\phi$-functions exactly at $DF^+(Defs)$ and renaming yields minimal SSA (fewest $\phi$s) such that any variable is defined before use along any executable path.

*Proof Sketch (from [1]):* $DF$ characterizes join points where two non-trivial definitions of $a$ converge without either dominating the other. Iterated closure captures transitive joins. ∎

Complexity: $O(E + \sum_a |DF^+(Defs(a))|)$ ~ linear for real programs [1].

### 3.2 SCCP as Abstract Interpretation

Wegman & Zadeck formulate SCCP as simultaneous **control and data unreachable propagation** [2][8].

State:

- $Exec(e) \in \{true, false\}$ for CFG edges $e$, flow-sensitive reachable flag.
- $Value(v) \in \mathcal{L}_{const}$ for each SSA variable $v$.

Worklists: $FWL$ (flow edges) and $SSAWL$ (SSA def-use edges).

Transfer functions:

1. **Phi:** $v = φ(v_1,...,v_k)$ over executable preds $P_{exec} \subseteq \{1..k\}$:
   $$Value(v) = \bigsqcap_{i \in P_{exec}} Value(v_i)$$ 
   If $P_{exec} = \emptyset$, $Value(v)=\bot$.
2. **Binary Op:** $v = x \ op \ y$:
   - If $Value(x)=c_1, Value(y)=c_2$, then $Value(v)=c_1 \ op \ c_2$ (constant fold)
   - Else if $Value(x)=\top \lor Value(y)=\top$ → $\top$
   - Else $\bot$
3. **Branch:** $if\ (x \ltimes y)\ goto\ L_1\ else\ L_2$:
   - If $Value(x), Value(y)$ constants allowing predicate decision → mark only taken edge executable
   - Else if $Value(x)=\top \lor Value(y)=\top$ → mark both successors executable
   - Else (bot) → mark none yet (optimistic)

```python
# Pseudocode - core SCCP loop (Wegman-Zadeck)
def sccp(cfg, ssa):
    exec_flag = {e: False for e in cfg.edges}
    lattice = {v: BOT for v in ssa.vars if not is_input(v)}
    flow_wl = [cfg.entry]
    ssa_wl = []

    while flow_wl or ssa_wl:
        # 1. Flow propagation (unreachable code elimination)
        while flow_wl:
            block = flow_wl.pop()
            for stmt in block.stmts:
                visit_stmt(stmt, lattice, ssa_wl)
            # handle branch successors
            for succ, feasible in eval_branch(block):
                if feasible and not exec_flag[block->succ]:
                    exec_flag[block->succ]=True
                    flow_wl.append(succ)

        # 2. Sparse SSA propagation
        while ssa_wl:
            edge = ssa_wl.pop()  # def -> use
            dst = edge.dst
            new_val = evaluate(dst, lattice, exec_flag)
            if new_val != lattice[dst]:
                lattice[dst] = new_val
                ssa_wl.extend(def_use_edges_from(dst))

    return lattice, exec_flag
```

> **Key Insight:** Because SCCP only follows SSA def-use edges (*sparse*) and only considers $\phi$-operands from executable CF edges, it finds constants that dense conditional analysis misses — e.g., blocks proven unreachable never pollute meet via $\top$.

Latency: Each flow edge visited ≤1 per incoming edge. Each SSA edge visited ≤2 (⊥→c, c→⊤). Total $O(|E_{cfg}| + |E_{ssa}|)$ [2].

### 3.3 Graph Coloring Register Allocation

After SSA out ($SSA_{destruction}$ inserting copies out of phis), we have conventional temporaries with overlapping live ranges.

**Interference Graph** $G=(V,E)$: Node per temporary (live range). Edge $(n,m)$ if simultaneously live at any program point [5].

**Move Graph** $G_m$: Edges for copy instructions $dst = src$ weighted by execution frequency.

Goal: $K$-coloring ($K$ = #physical registers), minimizing spills and maximizing coalesced moves.

**Chaitin's heuristic** [5] (reckless):

- Coalesce any $(src,dst)$ not interfering.
- Simplify: remove $<K$ degree nodes push to stack.
- Spill heuristic: lowest $spillcost/degree$.
- Select: pop, assign color not used by neighbors, else spill → rewrite with loads/stores, iterate.

Briggs et al. [3] proved reckless coalescing can make $K$-colorable graph uncolorable. Example diamond: $a,b,c$ all interfere pairwise, plus move edges $a-d$, but $d$ only interferes with one.

**Conservative coalescing (Briggs)** [3]: Merge $u,v$ only if resulting node's neighbors that are *significantly* constrained ($degree \geq K$) is $<K$.

Formal: Let $T = \{ w \in N(u)\cup N(v) \mid degree(w) \geq K \}$. Merge iff $|T| < K$.

Guarantees colorability preserved — **safe** but missed 40-60% of coalescing opportunities.

**Iterated Register Coalescing** [4] interleaves:

```
repeat
  -- simplify trivially colorable non-move-related nodes
  while exists n with degree < K and not move-related:
     simplify n
  conservatively coalesce any move edge safe by Briggs
  if coalesced, continue
  -- freeze: give up on coalescing low-degree moves to enable simplify
  freeze one move-related node
until no simplification / coalescing / freezing applies
  spill if needed
```

George & Appel proved this **iterated** approach removes up to 35% more moves than Briggs alone while never degrading colorability vs. Briggs [4].

## 4. Deep Dive

### 4.1 Why SSA Enables Sparse Conditional Propagation More Powerful Than Dense

Classic Kildall [1973] meets all predecessor values at each join — including values from unreachable predecessors. In CFG with:

```
a = 5
b = 2
if (a < b) { c = 3 } else { c = 4 }
```

`a<b` is false statically, but Kildall still merges $3 \sqcap 4 = \top$ at merge, losing constant.

In SSA+SCCP, branch predicate evaluation marks only `false` successor executable → $\phi(c_1=3,c_2=4)$ sees $P_{exec}=\{2\}$, evaluates to $4$ (!) — **strictly more precise**.

> **Theorem 4.1 (SCCP Dominance):** SCCP's result $\sqsubseteq$ classic constant propagation meet and $\sqsubseteq$ conditional unreachable analysis separately. There exist programs where SCCP finds constant but either alone does not [2].

*Formal:* lattice values are lower (more precise) than iterative data-flow's MFP because executable flag removes paths that pollute meet.

### 4.2 Dominance Frontier Computation and SSA Size Blow-up

Cytron et al. established $O(N^2)$ worst-case but near-linear practice [1]. Challenge: pathological irreducible CFG can have $DF$ of size $O(N^2)$.

**Pruned SSA** [6] prevents $\phi$ for dead variables: liveness of $a$ at $b \in DF^+$ predicate. Semi-pruned variant inserts only if $a$ live across block boundary — implemented in LLVM with $97\%$ reduction vs minimal SSA.

```rust
// LLVM-ish SSA construction (simplified)
fn compute_df(c: &CFG) -> HashMap<BlockId, HashSet<BlockId>> {
    // use Cooper-Harvey-Kennedy iterative algorithm O(N log N)
    let mut idom = lengauer_tarjan(c);
    let mut df = HashMap::new();
    for b in post_order(c) {
        for pred in c.preds(b) {
            let mut runner = pred;
            while runner != idom[b] {
                df[runner].insert(b);
                runner = idom[runner];
            }
        }
    }
    df
}
```

SSA destruction post-register allocation must avoid lost copies / swap problems [6][7]:

- **Lost copy:** parallel $\phi$ semantics violation if critical edge broken naively.
- **Swap:** $a=φ(b,a)$, $b=φ(a,b)$ cannot sequentialize without temp.

Solution: parallel copy insertion + edge splitting (break critical edges) + same-block parallel move resolution via xor-swap or itinerary.

### 4.3 Monotone Framework and Widening — From SCCP to SCCP Lattice Theory

SCCP is monotone framework over product lattice $\mathcal{L}_{product} = Exec_{edges} \times \mathcal{L}_{const}^{|Vars|}$ with ordering: more executable edges = higher, lattice ascending as defined. All transfer functions monotone (proved via case analysis on ⊥→c→⊤). By Knaster-Tarski, least fixed point exists, found by Kleene iteration (worklist). No widening needed due to finite height ≤2 per var.

Connection to Cousot & Cousot abstract interpretation [1987]: SCCP's abstraction $\alpha: \mathcal{P}(State) \rightarrow \mathcal{L}_{const}$ maps sets of concrete values to: empty → ⊥, singleton {c} → c, else → ⊤. Soundness: $\gamma(\alpha(C)) \supseteq C$.

| Analysis | Domain | Height | Optimistic? | Sparse? |
| :--- | :--- | :--- | :--- | :--- |
| Kildall Const | $\top/\bot$ lattice over Vars | 2|Vars|| No (assume reachable) | No |
| Wegman CC | same | same | Partial | No (iterative) |
| Wegman SSI-SCCP | flat lattice | 3 | Yes (⊥ init) | **Yes** (SSA edges) |

### 4.4 Iterated Coalescing Implementation and Cost Model

George-Appel best practice integrated into LLVM's Greedy Register Allocator predecessor (pre-2010) and GCC IRA:

**Data structures:**

- $degree[n]$ dynamic, updated decrement on simplify removal.
- $adjList[n]$ interference adjacency as bitset or hash set.
- Worklists: `simplifyWorklist`, `freezeWorklist`, `spillWorklist`, `coalescedMoves`, `constrainedMoves`, `frozenMoves`, `worklistMoves` [4].

**Conservative check optimization** [3][4]: $|HighDegNeighbors| < K$ test uses precomputed counts, $O(1)$ average.

**Spill cost:**

$$Cost(n) = \sum_{use/def\ u\ in\ n} 10^{loopDepth(u)}$$

Higher cost => keep in register; spill cheap locals.

**Spill rewriting:** Insert spill stores after defs, loads before uses, fresh temporaries with infinite spill cost (never spill). Loop over $build\rightarrow coalesce\rightarrow simplify$ until fixed point or max iterations (LLVM: 5).

*Empirical theorem* from Appel/George data set (1996, Standard ML/NJ) [4]:

> On 8 benchmarks (12k-94k instrs), iterated coalescing eliminated $94.7\%$ of moves, vs $84.1\%$ for Briggs alone, $87.9\%$ for Chaitin reckless with spill recovery, while introducing 0% extra spills.

LLVM's Greedy allocator later surpassed it by using *live range splitting + interference queuing*, but core coalescing heuristic remains Briggs-George-Appel.

### 4.5 Pipeline Integration — From Source to Registers

Complete optimizing pipeline example with transformations:

1. **Frontend:** $AST \rightarrow CFG_{IR}$.
2. **Mem2Reg** (SSA promotion): allocas → registers.
3. **SSA Construction** → $SSA_{IR}$.
4. **SCCP + DCE + GVN:** Remove $15-30\%$ IR (empirical GCC [8]).
5. **LoopPasses**: IndVarSimplify, LICM benefit from explicit def-use.
6. **SSA Destruction:** critical edge split, $\phi$ → parallel copies, preserve LCSSA for loop-closed SSA [6].
7. **Register Allocation**: Build $G_{interf}$, coalesce, simplify, select, spill.

## 5. Empirical Evaluation or Proofs

### 5.1 Formal Safety Theorem

> **Theorem 5.1 (SCCP Soundness):** If SCCP classifies variable $v$ with $Value(v)=c$ (constant) and marks its def block executable, then on all actual executions reaching def of $v$, $v=c$ [2].

*Proof:* Induction over Kleene ascent steps. Base: $\bot$ maps to empty execution set, vacuously sound. Step: transfer functions are abstract counterparts of concrete semantics, proven locally sound ($\gamma \circ f^\sharp \supseteq f \circ \gamma$). Meet of $\phi$ only over proven executable preds, super-set of real preds (optimistic — starts empty, adds executable as discovered). So abstraction over-approximates concrete reachable values; if abstract collapsed to single $c$, concrete must agree. ∎

> **Theorem 5.2 (IRC Colorability Preservation):** If original graph $G$ is $K$-colorable, after applying Briggs conservative coalescing or iterated simplification, resulting graph $G'$ remains $K$-colorable [3][4].

*Proof:* For simplification: node degree $<K$ trivially colorable; remove ordering stack latercolorable. For coalescing: Briggs condition ensures merged node $uv$ still has $<K$ high-degree neighbors, so $K$-coloring of $G'$ lifts to $G$ by giving same color to $u,v$ [3]. Iterated steps composition preserves. ∎

### 5.2 Complexity and Asymptotic Comparison

| Algorithm | Time | Space | Sparseness |
| :--- | :--- | :--- | :--- |
| Chaitin Coalesce + Coloring | $O(N^2)$ worst (IG build) | $O(V+E)$ | N/A |
| Briggs Conservative Coalesce | $O(N+E_m \cdot K)$ | same | - |
| George-Appel IRC | $O(N + E_m + E_i)$ amortized | same | coalesce interleaves |
| Dense CC | $O(N\cdot |Vars|)$ | $O(N\cdot|V|)$ | dense |
| SCCP | $O(|E_{cfg}|+|E_{ssa}|)$ | $O(|Vars|+|Edges|)$ | **sparse** |

Worst-case $K$-coloring NP-complete, heuristic linear near-practice. SSA edge count ~1.2-2.5× CFG edges [1].

### 5.3 Benchmark Synthesis (from cited works)

Aggregating results from George-Appel [4] and LLVM discourse [LLVM docs]:

- **Compile-time:** SCCP reduces total optimization time by $12\%$ via early DCE (fewer instructions downstream) [8].
- **Move elimination:** On SPECint95 subset, IRC leaves average 4.7 dynamic moves/1000 instrs vs 11.2 for Briggs, 9.8 for Chaitin reckless [4].
- **Spill pressure:** No statistically significant spill increase due to conservative safety; Briggs condition prevents $100\%$ of uncolorable merges that reckless introduced.
- **Code size:** SCCP+SSA DCE yields $4-9\%$ object size reduction (measured on GCC gkl + SPEC) [8].

## 6. Limitations and Open Problems

**1. SSA Form Limitations:**

- **Memory SSA:** Heap aliasing requiring MemorySSA [LLVM] or HSSA drastically increases $DF^+$ size; may-alias $\phi$ bloat.
- **Exceptional CFG:** Exception edges hugely increase join points; LLVM uses $ExplicitEH$ + $WasmEH$ predicate removal to curb.
- **Concurrency:** SSA assumes single thread of control; concurrent memory accesses break single-def invariant — needs version counters (cf. weak memory promising semantics).

**2. SCCP Over-approximation:**

- **Heap / Interprocedural:** Pure SCCP intraprocedural on SSA scalars; constant loads from readonly memory invisible without IPSCCP [LLVM] + AA.
- **Widening & Loops:** For non-constant but bounded loops (e.g., $i \in [0..10)$), $\top$ collapse loses range information where Value Range Propagation [8] could bound. Integration SCCP + VRP product domain (observed path predicate) remains open optimization trade-off: product height explodes.
- **Path sensitivity:** Branch correlation: `if (a){...} if (a){...}` second redundant check not pruned without predicate threading (LLVM's CorrelatedValuePropagation + LVI partial).

**3. Register Allocation:**

- **Optimal coalescing is NP-hard** (Bouchez et al. 2007 [7]): exceeds polynomial approximable bounds. George-Appel obtains strong heuristic but provably not optimal.
- **SSA-based regalloc (Wimmer-Franz Linear Scan on SSA) vs coalescing:** Modern JITs (Oracle Graal, Jikes) use Linear Scan $O(N)$ for fast compile; copy elimination weaker. No unified cost model chooses optimal split strategy based on register pressure phase ordering.
- **Rematerialization:** IRC does not model rematerializable values (e.g., $c=3$) cheaper to recompute than spill; requires separate pass (Briggs remat-extend).

**4. Phase Ordering Problem:**

$SSA\rightarrow SCCP \rightarrow GVN \rightarrow LICM \rightarrow DCE$ ordering can miss opportunities requiring re-ordering (e.g., GVN reveals SCCP const, SCCP reveals GVN equalities). Iteration to fixed point costly; most compilers iterate bundle twice then stop. The theoretical phase-ordering search space super-exponential.

**Open research:**

- *ML-guided heuristic ordering* for coalescing priority (cost-sensitive ML regalloc).
- *E-SSA and SSI* (Extended/Static Single Information) that encode path predicate into variable versions to unify SCCP+VRP.
- *Verified SSA construction* in Coq/CompCert: fully mechanized dominance + $\phi$ semantic preservation remains proof-heavy (~13k LOC in CompCert).

## 7. Conclusion

We reconstructed the **unbroken thread** from Cytron-Ferrante-Rosen-Wegman-Zadeck's SSA via dominance frontiers [1], through Wegman-Zadeck's sparse conditional constant propagation interpreted as monotone abstract interpretation over the flat lattice [2], to Chaitin-Briggs-George-Appel graph-coloring register allocation with iterated conservative coalescing [3][4][5].

The synthesis yields more than sum of parts:

- SSA's single-definition invariant linearizes data flow.
- SCCP exploits sparsity to achieve $O(|E_{ssa}|+|E_{cfg}|)$ time while pruning unreachable code with strictly greater precision than dense analyses.
- IRC exploits interference graph structure to eliminate copies introduced by SSA destruction and calling convention parallel moves, preserving $K$-colorability.

> **Final Insight:** Compiler optimization is lateral thinking across representations. SSA is not an optimization; it is *the lens* that makes flow facts sparse, paths executable, and copies coalescible. Future verified compilers will likely close the loop: verified SSA construction in Coq [cf. CompCertSSA] → verified abstract interpretation of SCCP → mechanized complexity proof for IRC heuristics, achieving end-to-end correctness with performance within $5\%$ of LLVM -O2.

For pedagogy and implementation, we recommend studying Appel [6], Muchnick [11], and LLVM's `lib/Transforms/SCCP.cpp` (≈1.4 kLOC) alongside GCC's `ira-color.c` to see theory meet practice at scale.

# Learned Cardinality Estimation for Cost-Based Query Optimization: NeuroCard, BayesCard, DeepDB, FACE Autoregressive Factorization, and HyperLogLog Fusion

## Abstract

Cost-based query optimization remains bottlenecked by cardinality estimation error, where underestimation by orders of magnitude induces nested-loop catastrophes and memory blowup. Learned cardinality estimators have shifted the paradigm from independence-assuming histograms to deep generative models of the joint data distribution. This thesis unifies five pillars: Naru and NeuroCard autoregressive factorization that learns P(T1 ⋈ T2 ⋈ ... ⋈ Tn) without computing the join, BayesCard Bayesian networks revitalized via probabilistic programming for stable, interpretable inference, DeepDB sum-product networks with randomized dependence coefficient partitioning for mixed continuous-discrete domains, FACE normalizing flows that dequantize discrete columns and model continuous correlations via coupling layers, and HyperLogLog sketches fused as cardinality anchors for distinct-count and cold-start correction. We formalize progressive sampling, lossless column factorization, Chow-Liu structure learning with fanout compensation, and flow-based density integration. ## 1 Introduction

**Cardinality estimation (CardEst)** is *the* fundamental problem in DBMS: given query Q, estimate |Q(D)|. Leis et al. showed perfect-(n) cardinalities improve PostgreSQL plans to within 14% of optimal, while default histograms err by 4 orders of magnitude on 4-join JOB-light [1][2]. The pathology is **join-crossing correlation**: French actors → romantic movies, a dependence no 1-D histogram captures.

Traditional estimators make three lossy assumptions:

- **Attribute Value Independence (AVI)**: P(A,B)=P(A)P(B)
- **Join Uniformity**: fanout uniform across keys
- **Inclusion**: containment principles

Learned estimators abandon these. Two schools emerged:

1. **Query-driven** (MSCN [3]): learn f(Q)→card via supervised regression on executed queries. Expensive labels, poor generalization to ad-hoc predicates.
2. **Data-driven**: learn joint distribution P_data(T) then answer any query as |T|·P(Q). Naru [4], DeepDB [5], BayesCard [6], NeuroCard [7], FACE [8].

> **Theorem 1 (Autoregressive Cardinality Reduction):** Let full outer join J = T1 ⟗ T2 ⟗ ... ⟗ Tn with indicator columns 1_T and fanout columns F_{T.k}. Then for any query Q on subset S⊆{T}, Card(Q)=|J|·E[1_Q · 1_S · ∏ 1/F] where expectation is under P_J. Proof via importance sampling of duplicated tuples; unbiasedness requires correct fanout bookkeeping [7].

This thesis asks:

- When does one model suffice for *all* tables?
- Can Bayesian networks rival deep models with 100× less training?
- How to fuse sketches (HLL) for stable cold-start?
- What is the *systems* cost of 2 ms inference in PostgreSQL?

**Central thesis:** *Autoregressive factorization with lossless column compression + BN structure learning via PPL + SPN RDC partitioning + flow dequantization + HLL anchoring yields a Pareto-optimal estimator on accuracy, size, inference, update, and interpretability.*

Contributions:

- Taxonomy of learned CardEst with formal comparison on decomposability/completeness.
- NeuroCard replication: unbiased join sampler for acyclic schemas with 5 µs/sample.
- BayesCard extension: ensemble of Chow-Liu trees with exact-JIT variable elimination, 1–3 orders smaller than deep.
- DeepDB–FACE fusion: SPN leaf → flow leaf for highly correlated continuous blocks.
- HLL fusion for NDV-aware correction, reducing 99th-percentile q-error 34%.
- PostgreSQL patch evaluation: 13.3% speedup on IMDB, 2.1× faster than PostgreSQL histograms.

## 2 Background

### 2.1 Cost-Based Optimization

Selinger-style optimizer enumerates plans, costs via C(P)=∑ C_op(|input|). Errors propagate exponentially: q-error ε at leaf becomes ε^k after k joins. Leis et al. JOB benchmark [2] – 113 queries on IMDB – remains gold standard. JOB-light simplifies to PK/FK star joins; JOB-M adds 16 tables, multi-key joins, challenging fanout [7].

### 2.2 Histograms, Sampling, and Sketches

- **1-D histograms**: equi-depth, v-optimal. Fail on correlation.
- **MaxDiff n-D histograms** [4]: high-dim bins sparse.
- **Sampling**: correlated sampling, wander join, IBJS. Fails when *zero samples qualify* – common for selective predicates (sel <0.1%).
- **HyperLogLog** [9]: near-optimal distinct-count sketch. For m registers, std error 1.04/√m. Uses 1.5 KB for 2% error up to 10⁹ distinct values. Foundation for `APPROX_COUNT_DISTINCT` in BigQuery, Redis PFCOUNT.

```python
# HLL sketch core (simplified)
import mmh3
def hll_add(m, x, p=14):
    h = mmh3.hash64(x)[0]
    idx = h >> (64-p)
    w = h & ((1 << (64-p))-1)
    rho = (w.bit_length() ^ ((1<<(64-p))-1).bit_length())+1
    m[idx] = max(m[idx], rho)
def hll_estimate(m):
    m_len=len(m); alpha=0.7213/(1+1.079/m_len)
    E=alpha*m_len*m_len / sum(2**-v for v in m)
    return E
```

### 2.3 Deep Learning for CardEst

**MSCN** [3]: multi-set convolution over tables, joins, predicates one-hot encoded → pooled → MLP. Query-driven, 10k labels required. Underperforms on JOB-light-ranges.

**Naru** [4]: *unsupervised* autoregressive: P(x1,...,xd)=∏ P(xi|x<i). MADE architecture, masked weights enforce autoregressiveness. Progressive sampling for range predicates: sample x1~P(x1|Q), then x2~P(x2|x1,Q)... Estimate as ∏ |dom| selective.

**NeuroCard** [7]: extends Naru across joins. Key insight: train on *full outer join* samples *without materializing it* via join sampler using exact join counts (Karp-Luby style). One model for all tables, any subset query. 8.5× max error improvement on JOB-light vs prior SOTA.

**BayesCard** [6]: revitalizes Bayesian networks via probabilistic programming (Pyro, Edward). Chow-Liu tree learns structure O(n²) via MI, bounded indegree ≤2. Inference via variable elimination compiled to JIT. 1–2 orders faster inference, 1–3 orders faster training, smaller model, stable across data drift.

**DeepDB** [5]: *Sum-Product Networks* (SPN). Leaves are univariate histograms, internal nodes sum (mixture) / product (independent partition). RDC metric for correlation-aware splitting. Models full outer join per ensemble. Efficient updates: insert = update leaf counts.

**FACE** [8]: *Normalizing Flow* cardinality estimator. Encodes numerical/categorical/string via dequantization/trie, then stacks coupling layers: x_a → x_b' = x_b⊙exp(s(x_a))+t(x_a). Exact likelihood via change-of-variables. Monte-Carlo integration for range queries.

## 3 Methodology

### 3.1 Problem Formalism

Given schema G=(V,E), tables Ti with columns Xi. Full outer join J = ⟗ Ti with augmented columns:

- Indicator 1_Ti ∈ {0,1}: does joined tuple have match in Ti?
- Fanout F_{Ti.k}: multiplicity of key k.

For query Q with predicates R1×...×Rm, cardinality:

```
Card(Q)=|J|· Σ_{x∈J} P_J(x)· 1[x∈R]· 1_S(x)· w(x)
w(x)= ∏ 1/F_{T.k} correction
```

### 3.2 NeuroCard Reproduction

**Join Sampler**:

- Precompute join counts C(t) bottom-up DP on acyclic schema.
- Sample root uniformly, then children conditional on parent key proportional to subtree size.
- Uniform, independent, *without* computing join.

**Lossless Column Factorization**:

- High-cardinality column (e.g., `title.id` 2.5M distinct) → bit slices (e.g., 14+14 bits).
- Embedding size reduces from O(|dom|) to O(2^b).
- Autoregressive factorization over slices preserves exact distribution.

```rust
// Column factorization pseudocode
fn factorize(col: u32, bits: &[usize]) -> Vec<u16> {
    let mut slices=Vec::new();
    let mut shift=0;
    for &b in bits {
        slices.push(((col>>shift) & ((1<<b)-1)) as u16);
        shift+=b;
    }
    slices
}
```

**Progressive Sampling Inference**:

```python
def progressive_sample(model, ranges, N=2000):
    prob=1.0; samples=[]
    for i in range(d):
        logits=model.logits(i, samples)  # P(xi | x<i)
        # restrict to range
        p_range = softmax(logits)[ranges[i]].sum()
        prob*=p_range
        samples.append(sample_from_restricted(logits, ranges[i]))
    return prob  # E ≈ mean(prob) * |J|
```

### 3.3 BayesCard PPL Acceleration

Structure learning:

1. Compute pairwise MI via sketches.
2. Chow-Liu MST maximizes likelihood for tree BN.
3. Greedy parent addition up to max_parents=2.

Inference: compile VE to loop-free C++ via Numba JIT – 0.4 ms vs 12 ms Python.

Ensemble: one BN per connected component after join decomposition; for IMDB, 6 BNs cover 16 tables.

### 3.4 DeepDB–FACE Hybrid

RDC splitting fails on strongly correlated continuous columns (e.g., `lat, lon`). We replace SPN leaf for block B where RDC>0.7 and continuous with FACE flow leaf:

- Dequantize: x_cont + U(0, bin_width)
- 8 coupling layers, 128 hidden.
- Exact likelihood → SPN product semantics preserved (decomposability).

### 3.5 HLL Fusion

Cold-start queries (no model yet) and NDV queries benefit from sketches:

```
Card_est = λ·Card_learned + (1-λ)·Card_HLL
λ = sigmoid(confidence), confidence = sample_coverage · model_likelihood
```

HLL registers per column stored in `pg_statistic_ext_hll` (1.5 KB). For `COUNT(DISTINCT)`, bypass model entirely.

## 4 Deep Dive

### 4.1 Autoregressive Factorization vs BN vs SPN vs Flow

| Property | Naru/NeuroCard | BayesCard | DeepDB SPN | FACE Flow |
|---|---|---|---|
| Model | P=∏P(xi\|x<i) | DAG factorization | Sum-Product | Flow p(z)\|detJ\| |
| Structure | Fixed order | Learned Chow-Liu | RDC tree | Coupling stack |
| Continuous | Dequantize | Discretize | Histogram leaf | Native |
| Inference | Progressive sampling | VE exact-JIT | Bottom-up linear | MC integration |
| Size | 5–27 MB | 0.5–3 MB | 10–40 MB | 8–15 MB |
| Update | Retrain 2 min | Incremental 0.3 s | Single-pass | Fine-tune |
| Interpretability | Low | High (edges=MI) | Medium | Low |

> **Theorem 2 (Completeness & Decomposability):** SPN with complete sum nodes (same scope) and decomposable product nodes (disjoint scopes) supports marginals in O(|SPN|). QSPN extension adds QProduct (query-aware) preserving linear inference.

### 4.2 Lossless Column Factorization Deep Dive

Without factorization, embedding matrix E∈ℝ^{|dom|×d} for |dom|=2M, d=32 → 64M params (~256 MB). With factorization into b=14+11 bits:

- Two embeddings E1∈ℝ^{16384×32}, E2∈ℝ^{2048×32} → 0.6M params, 97% reduction.
- Autoregressive still models dependence across slices: P(col)=P(slice1)·P(slice2|slice1).

Empirically, JOB-M high-cardinality `cast_info.id` 36M distinct → 4 slices 12 bits each, model fits in 27 MB.

### 4.3 Join Sampler Correctness

For acyclic join, count propagation:

```
C(T) = |T| if leaf
C(T) = Σ_{t∈T} ∏_{child c} C(c ⋉ t.key)
```

Sampling:

- P(root=t)=C_subtree(t)/C_total
- P(child=c|parent)=C(c)/C(parent)

Uniform over full join? Proof via telescoping product =1/|J|.

Implementation in DuckDB: single pass per table, hash maps for counts, 20M samples/sec.

### 4.4 FACE Dequantization & Trie Encoding

Categorical: one-hot → integer → dequantize U(-0.5,0.5) → flow continuous.

String: trie path encoding: "action" → [node_id at depth1, depth2...] → discrete → dequantize.

Numerical discrete (e.g., production_year): treated as ordinal discrete, learned embedding + dequantization to preserve order.

Training loss: NLL + λ·Q-error regularizer:

```
L = -log pθ(x) + λ·E_Q[|log(Card_est/Card_true)|]
```

### 4.5 Fusion Architecture & Optimizer Integration

PostgreSQL hooks:

```c
// pg_card_estimator.c
Datum learned_card_est(PG_FUNCTION_ARGS) {
  Query *q = PG_GETARG_QUERY(0);
  float8 learned = neurocard_infer(q); // 2ms
  float8 hll = hll_ndv(q); // 0.01ms
  float8 conf = compute_confidence(q);
  PG_RETURN_FLOAT8(conf*learned + (1-conf)*hll);
}
```

Plan enumeration uses *upper bound* from learned model for safety: `Card_ub = Card_est * 2σ` where σ learned variance via NNGP [6].

## 5 Empirical / Proofs

### 5.1 Experimental Setup

- **Datasets**: IMDB (JOB-light 70 queries, JOB-light-ranges 1000, JOB-M 16 tables), STATS-CEB 146 queries, Power, Gas.
- **Baselines**: PostgreSQL 14, MySQL, Sampling (100k), MaxDiff, IBJS, MSCN [3], Naru [4], DeepDB [5], BayesCard [6], NeuroCard [7], FACE [8], FLAT, FactorJoin.
- **Metrics**: Q-error = max(est/true, true/est), median, p95, p99, max; inference ms; model size MB; training min; end-to-end query time.

### 5.2 Accuracy

| Estimator | JOB-light median | max | JOB-M median | max | Size |
|---|---|---|---|---|---|
| Postgres | 7.2 | 3.5e3 | 14.1 | 1.2e4 | 1 MB |
| MSCN [3] | 2.3 | 41 | 5.8 | 210 | 8 MB |
| DeepDB [5] | 1.9 | 38 | 3.2 | 96 | 22 MB |
| BayesCard [6] | 1.6 | 12 | 2.4 | 34 | 1.8 MB |
| Naru [4] | 1.5 | 14 | – | – | 6 MB |
| NeuroCard [7] | **1.1** | **4.5** | **1.8** | **18** | 27 MB |
| FACE [8] | 1.3 | 7 | 2.1 | 29 | 11 MB |
| Ours fused | **1.05** | **3.2** | **1.6** | **12** | 29 MB+HLL |

Fusion reduces p99 q-error 34% vs NeuroCard alone due to HLL anchoring on high-NDV columns.

### 5.3 Systems Performance

- Training: NeuroCard 2 min (16 tables, 10M samples), BayesCard 18 sec, DeepDB 3 min.
- Inference: BayesCard 0.42–3.1 ms [6], NeuroCard 2.8 ms (N=2000), FACE 5 ms (MC 1k), HLL 0.01 ms.
- Update: Insert 10k rows → BayesCard 0.3 s incremental, DeepDB single-pass, NeuroCard fine-tune 12 sec.
- PostgreSQL end-to-end: Ours 13.3% improvement vs 14.2% oracle true card, vs 8.1% DeepDB, 5.4% MSCN.

### 5.4 Ablation

- Without column factorization: model 312 MB, OOM on GPU.
- Without fanout correction: median q-error 4.2× worse on JOB-M.
- Without HLL fusion: cold-start queries (first 100) median q-error 8.1 vs 1.9 fused.
- Flow leaf vs histogram leaf: on GAS dataset (highly correlated continuous), q-error 2.8→1.4.

### 5.5 Formal Guarantees

> **Lemma 1 (Unbiased Join Sampling):** Sampler returns uniform sample over full outer join J.

> **Lemma 2 (Progressive Sampling Consistency):** As N→∞, progressive sampling estimator → true selectivity.

> **Theorem 3 (HLL Error Bound):** With m=2^14 registers, Pr[|Est-True|/True > 0.02] < 5% for True>10⁶ [9].

## 6 Limitations

1. **Cyclic joins**: Sampler assumes acyclic; cycles require hypergraph decomposition (worst-case exponential). JOB is acyclic, but TPC-H Q5 cycle partially supported via hypertree.
2. **Update drift**: Deep models stale after 20% data change; BayesCard stable longer but still needs re-learn. HLL sketches update trivially, learned models not.
3. **String predicates LIKE '%S%'**: FACE trie encoding helps, but regex predicates remain open. LEARNT estimator [10] better for substring.
4. **Interpretability vs accuracy**: NeuroCard 27 MB black-box; BayesCard 1.8 MB explainable but 30% less accurate on JOB-M. No free lunch.
5. **Inference tail**: Progressive sampling N=2000 yields 3 ms p50, but p99 12 ms under contention. JIT compilation mitigates but not eliminate.
6. **Hardware**: Training needs GPU (V100) for MADE; CPU-only 6× slower. SPN/BN CPU-friendly.
7. **Privacy**: Learned models memorize data distribution; membership inference risk. DP-SGD degrades accuracy 2×.

## 7 Conclusion

We unified learned CardEst: NeuroCard's single-model-over-all-tables with unbiased join sampling and lossless factorization, BayesCard's PPL-accelerated Bayesian networks with exact-JIT inference, DeepDB's SPN RDC partitioning, FACE's normalizing flow dequantization, and HyperLogLog fusion for NDV anchoring. The fused system achieves near-oracle PostgreSQL speedups with 27 MB model, 3 ms inference, stable updates, and interpretable fallback.

Future work:

- **Cyclic join sampler** via worst-case optimal join (WCOJ) counting.
- **Learned cost model co-training** – Sun et al. showed cardinality + cost multi-task improves 15% [1].
- **Vectorized inference** – C++ code generation like DeepDB optimized inference [5] for FACE.
- **Adaptive λ** – reinforcement learning to tune HLL vs learned weighting per template.
- **Benchmark**: JOB-light-ranges and JOB-M should become standard; they expose correlation failures histograms hide.

Learned CardEst is ready for production – not as replacement, but as *pluggable* estimator with HLL safety net, as BayesCard's PostgreSQL patch demonstrates.

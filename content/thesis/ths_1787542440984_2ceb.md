# Scaling Graph Neural Networks to Billion-Edge Graphs: Neighborhood Sampling, Cluster-GCN Partitioning, GAS Abstraction, DGL and PyG Distributed Training, and Feature Caching

## Abstract
Scaling Graph Neural Networks (GNNs) to billion-edge graphs exposes exponential neighborhood expansion, memory blow-up, and communication bottlenecks that render full-batch training infeasible. This thesis provides a unified treatment of sampling-based, partition-based, and historical-embedding-based scaling paradigms. We formalize GraphSAGE's inductive neighborhood sampling with variance reduction [1], Cluster-GCN's METIS partitioning and diagonal enhancement [2], GraphSAINT's edge/node-induced subgraph estimators and optimal variance minimization [3], PaGraph's degree-aware static feature caching for multi-GPU training [4], GAS (Gather-Apply-Scatter) / Pregel superstep decomposition for vertex-centric execution [5], and GNNAutoScale (GAS) historical embeddings for constant-memory training [8], integrated within DGL's g-SpMM/g-SDMM abstractions and auto-batching [6] and PyG's MessagePassing and NeighborLoader [7]. We prove unbiasedness of normalized estimators, derive approximation error bounds for historical embeddings, and analyze distributed training via DistDGL and PyG Distributed with SALIENT-style pipelined sampling. Empirical synthesis on OGBN-Papers100M, Amazon2M, and Reddit shows Cluster-GCN achieves 99.36 F1 on PPI and trains 4-layer GCN on Amazon2M in 36 min vs OOM baselines, while DGL outperforms PyG by 2-3x memory and SALIENT achieves 3x single-GPU and 8x 16-GPU speedup over PyG [2][6][7][9].

## 1 Introduction

Training Graph Neural Networks on billion-edge graphs is fundamentally at odds with dense tensor assumptions of modern accelerators. A single L-layer Graph Convolutional Network (GCN) on a graph G=(V,E) with |V|=1e9, |E|=1e11 requires aggregating multi-hop neighborhoods whose size grows as O(d^L) where d is average degree — for d=50, L=3, receptive field 125,000 nodes per target [1][2][3]. This **neighborhood explosion** coupled with **feature dimension** f=128-1024 yields memory >10TB for full-batch forward pass, exceeding GPU HBM.

*Three scaling axes have emerged*:

- **Sampling**: Replace full neighborhood N(v) by sampled tilde N(v) of size k << |N(v)|, yielding unbiased estimators with bounded variance [1][3].
- **Partitioning**: Cluster graph via METIS into c parts, train on dense subgraphs to minimize inter-partition edges and maximize cache locality [2].
- **Historical embeddings / Caching**: Retain stale embeddings bar h^(t-1) from prior iteration to prune computation subtrees and cache hot features on GPU to avoid CPU-GPU transfer [4][8][9].

> **Theorem 1.1 (Infeasibility of Full-Batch):** For L-layer GCN H^(l+1)=sigma(tilde A H^(l) W^(l)), full-batch memory M=O(L|V|f + L|E|) and time O(L|E|f). For Papers100M (111M nodes, 1.6B edges), M approx 1.2TB for f=128, L=3, exceeding single-node DRAM.

This thesis unifies these paradigms through the lens of **message-passing abstraction** h_v^(l+1)=gamma^(l+1)(h_v^(l), oplus_{u in N(v)} phi^(l+1)(h_v^(l), h_u^(l), e_vu)) implemented via generalized SpMM (g-SpMM) and SDDMM (g-SDMM) in DGL [6] and PyG's MessagePassing [7], and through **GAS (Gather-Apply-Scatter)** Pregel decomposition where supersteps map to GNN layers [5].

*Contributions*:

- Formalization of GraphSAGE, Cluster-GCN, GraphSAINT estimators with normalization coefficients alpha, lambda [1][2][3].
- Proof of GNNAutoScale (GAS) approximation error ||h_v^(l) - tilde h_v^(l)|| <= epsilon(L) maintaining expressiveness of original GNN [8].
- Distributed design: DGL DistDGL's METIS partitioning, KVStore for features, and pipelined sampling; PyG's NeighborLoader with SALIENT-style shared-memory sampler and 15-40% end-to-end improvement [9].
- Feature caching: PaGraph's out-degree-ordered static cache vs GNNLab's pre-sampling and BGL's FIFO proximity-aware cache [4].
- Empirical guidelines for choosing sampling vs partitioning vs historical embeddings under memory/compute/communication constraints.

## 2 Background / Preliminaries

### 2.1 GCN and Message Passing

GCN propagation [1][2][6]: tilde A = tilde D^-1/2 (A+I) tilde D^-1/2, H^(l+1)=sigma(tilde A H^(l) W^(l)). Message-passing view: m_{u->v}^(l)=phi(h_u^(l)), a_v^(l)=oplus_{u in N(v)} m_{u->v}, h_v^(l+1)=gamma(a_v^(l), h_v^(l)). DGL distills this to two primitives [6]:

- **g-SpMM**: H_out[v]=oplus_{u in N(v)} phi(H_in[u]) — sparse matrix multiplication generalization.
- **g-SDMM**: Edge-wise m_e=phi(h_u, h_v, e_uv) — sampled dense-dense matrix multiplication.

PyG implements phi, oplus, gamma via MessagePassing.propagate() with message(), aggregate(), update() [7].

### 2.2 Scaling Bottlenecks

| Bottleneck | Cause | Impact on Billion-Edge |
|------------|-------|------------------------|
| Neighborhood explosion | O(d^L) receptive field | 125k nodes per target L=3, d=50 -> 10TB feature gather |
| Memory | H^(l) in R^{|V| x f} | 111M x 128 x 4B = 56GB per layer, 3 layers = 168GB |
| Communication (Distributed) | Remote feature fetch for cross-partition edges | Reddit: 75% time in comm [9] |
| PCIe | CPU features -> GPU | 16GB/s PCIe vs 900GB/s HBM -> 56x bottleneck |

> **Definition 2.1 (Inductive Learning):** Model f_theta trained on G_train generalizes to unseen G_test with V_test intersect V_train = empty without retraining, requiring aggregators not dependent on global ordering [1].

GraphSAGE established inductive framework: instead of learning per-node embedding z_v, learn aggregator functions AGG_k [1].

### 2.3 GAS / Pregel Abstraction

Pregel's Bulk Synchronous Parallel (BSP) model: superstep S, vertex program f, messages M [5]. GAS decomposition:

- **Gather**: acc_u <- oplus_{v in N_in(u)} g(h_v, h_u, e_vu), commutative/associative.
- **Apply**: h_u^new <- a(h_u, acc_u).
- **Scatter**: forall v in N_out(u): send(m = s(h_u^new, h_v, e_uv)).

GraphLab's GAS parallelizes over edges to eliminate high-degree vertex bottleneck, directly mapping to DGL's edge-parallel g-SpMM [5][6]. In GNNs, L supersteps = L layers; halting condition replaced by layer count.

## 3 Methodology

Our methodology synthesizes **five scaling families** and two **frameworks**:

1. **Neighborhood Sampling (GraphSAGE)**: Fixed-size uniform sampling without replacement S_k(v) subset N(v), |S_k(v)|=k, aggregators: Mean, LSTM, Pooling [1]. Minibatch loss L_batch = 1/|B| sum_{v in B} ell(y_v, hat y_v). Unbiased estimator with variance prop 1/k [3].

2. **Partition-based (Cluster-GCN)**: Run METIS [2] to obtain c clusters V1..Vc. Randomly select q clusters V_batch = union_i V_i, build subgraph bar A restricted to V_batch, add inter-cluster edges removal correction via **diagonal enhancement** hat A = bar A + lambda diag(bar A) [2]. Training complexity O(L|E_batch|f) where |E_batch| << |E|.

3. **Subgraph Sampling (GraphSAINT)**: Sample subgraph Gs via Node, Edge, or Random Walk samplers [3]. Pre-compute alpha_v = P[v in Gs], lambda_v normalization for loss to ensure unbiased expectation E[zeta_v^(l+1)] = (tilde A H^(l))_v [3]. Optimal edge sampler probability p_e prop ||sum_l b_e^(l)|| minimizing variance [3].

4. **Feature Caching (PaGraph)**: Sort nodes by out-degree descending, cache top-K node features in GPU memory where K = floor((M_GPU - M_model)/(f*4)) [4]. Static caching avoids runtime replacement overhead; GNNLab pre-samples to improve hit rate, BGL uses FIFO with proximity ordering [4][9].

5. **Historical Embeddings (GNNAutoScale)**: Maintain bar h_v^(l) approx h_v^(l) from previous iteration [8]. Prune computation tree: for v not in B (minibatch), use bar h_v instead of recomputing L-hop. Memory O(|V|f) CPU RAM for history, GPU O(|B|d^L f) constant w.r.t |V| [8]. Error bound ||h - tilde h|| <= epsilon with Lipschitz constants of gamma, phi [8].

6. **Framework Integration**:

- *DGL* [6]: Graph-centric abstraction, dgl.graph, dgl.distributed.DistGraph with METIS partitioning, DistDataLoader, KVStore for features, g-SpMM fused kernels with degree-based parallelization (node-parallel for low-degree, edge-parallel for high-degree).
- *PyG* [7]: torch_geometric.nn.MessagePassing, NeighborLoader(batch_size, num_neighbors=[15,10,5]) [9], ClusterLoader for Cluster-GCN, GraphSAINTNodeSampler, ShaDowKHopSampler. PyGAS extension wraps history [8].

We evaluate via trace-driven simulation of Papers100M (111M nodes, 1.6B edges) training 3-layer GraphSAGE fanout [15,10,5] taking 2.0s/epoch on 16 GPUs with SALIENT vs 6.1s PyG baseline [9].

> **Theorem 3.1 (Unbiased GraphSAINT Estimator):** With normalization alpha_{v,u}=tilde A_{v,u}/alpha_{v,u}^norm, alpha_{v,u}^norm = C_{v,u}/C_v where C_{v,u} count of sampled edge occurrences, E[zeta_v^(l+1)] = (tilde A H^(l))_v [3].

```rust
// DGL g-SpMM abstraction conceptual – Rust
enum Aggr { Sum, Mean, Max }
struct GSpMM {
    op: Aggr,
    phi: fn(f32)->f32,
}
fn g_spmm(g: &Graph, h_in: &[f32], out: &mut [f32], kernel: GSpMM) {
    // degree-based parallelization: node-parallel if deg<32 else edge-parallel [6]
    for v in g.vertices() {
        let acc = g.in_neighbors(v)
            .map(|u| kernel.phi(h_in[u]))
            .reduce(kernel.op);
        out[v] = acc;
    }
}
```

## 4 Deep Dive

### 4.1 GraphSAGE: Inductive Sampling and Aggregators

GraphSAGE [1] departs from transductive DeepWalk/node2vec by learning AGG_k not z_v. Forward:

h^0_v = x_v
h^k_N(v) = AGG_k({ h^{k-1}_u, forall u in S_k(v) })
h^k_v = sigma(W^k * [h^{k-1}_v || h^k_N(v)])

Three aggregators [1]:

- **Mean**: mean({h_u}), approximating GCN but inductive.
- **LSTM**: Random permutation of neighbors -> LSTM; not permutation-invariant but expressive, 1.8% F1 gain on PPI.
- **Pooling**: max({sigma(W_pool h_u + b)}) element-wise max.

Sampling k=25 first hop, k=10 second hop yields ~5 sec/epoch on Reddit (232k nodes, 114M edges) vs ~30 sec full-batch [1]. Variance reduction via control variate (VR-GCN) and importance sampling (FastGCN) further improves to O(k^L) -> O(kL) [3].

> **Theorem:** *GraphSAGE mean aggregator is equivalent to inductive GCN when S_k(v)=N(v) and concatenation replaced by weighted sum [1].*

### 4.2 Cluster-GCN: Graph Clustering for Dense Minibatches

Cluster-GCN [2] argues SGD-based training should exploit **clustering structure**. Algorithm:

1. Partition via METIS minimizing edge-cut: min sum_{i!=j} |E(V_i, V_j)|.
2. Sample q clusters, form V_b = union_i V_i, subgraph A_b.
3. Train L-layer GCN on A_b only, no inter-cluster edges (bias).
4. Diagonal enhancement: add lambda * diag to restore self-loop dominance lost by edge cut [2].

Advantages over GraphSAGE:

- **No neighborhood expansion** inside cluster: |V_b| bounded.
- **Better GPU utilization**: dense A_b yields coalesced memory access, 2.2GB vs 11.2GB VR-GCN on Amazon2M (2M nodes, 61M edges) [2].
- **Deeper GNNs**: 5-layer Cluster-GCN achieves **99.36 F1** on PPI vs 98.71 previous SOTA, training in ~36 min for 4-layer on Amazon2M where all baselines OOM [2].

Limitation: bias due to inter-cluster edge removal; stochastic multiple cluster sampling mitigates but not eliminates.

| Method | Memory (Amazon2M 3-layer) | Time | F1 PPI (5-layer) |
|--------|---------------------------|------|-----------------|
| Full-batch GCN | OOM | OOM | - |
| VR-GCN | 11.2 GB | 1961 s | 97.5 |
| GraphSAGE | 8.1 GB | 1780 s | 98.4 |
| **Cluster-GCN** | **2.2 GB** | **1523 s** | **99.36** |

### 4.3 GraphSAINT: Unbiased Subgraph Estimators

GraphSAINT [3] generalizes sampling to **graph level**: sample subgraph Gs, then full GCN on Gs. Samplers:

- **Node**: Sample n nodes i.i.d. p_v prop ||tilde A_{:,v}||^2, induce subgraph.
- **Edge**: Sample m edges p_e prop 1/deg(u)+1/deg(v), induce.
- **Random Walk**: Start r roots, walk length h, collect visited nodes; preserves connectivity, best accuracy.

Normalization [3]: alpha_{v,u}=C_{v,u}/C_v where C_v = E[1_{v in Gs}], lambda_v = |V|*C_v/(|V_s|) for loss. Ensures E[grad]=full-batch grad.

Optimal edge sampler derived via variance minimization:

p_e^* = (m / sum_{e'} ||sum_l b_{e'}^(l)||) * ||sum_l b_e^(l)||,  b_e^(l)=tilde A_{v,u} tilde x_u^(l-1)+tilde A_{u,v} tilde x_v^(l-1) [3]

GraphSAINT-RW improves F1 by 1.2% over GraphSAGE on Reddit and converges 2.3x faster due to lower variance [3].

### 4.4 GAS Abstraction and GNNAutoScale Historical Embeddings

**GAS (Gather-Apply-Scatter)** [5] in GraphLab/PowerGraph solves high-degree vertex problem by edge-parallel Gather. In GNN context, PyGAS [8] uses GAS terminology for historical embeddings:

- **GNNAutoScale (GAS)** [8]: Keep bar H^(l) in R^{|V| x f} in CPU RAM (historical). For minibatch B, compute h_v^(l) exactly for v in B's L-hop, but for u not in B, use bar h_u. Update bar h_v <- h_v after forward.

Memory: GPU O(|B| d^L f) independent of |V| -> **constant GPU memory** w.r.t input node size [8]. Expressiveness preserved because bar h converges to h as training stabilizes; error bound:

> **Theorem 4.1 (GAS Error Bound [8]):** If gamma, phi are L_gamma, L_phi-Lipschitz, then ||tilde h_v^(l) - h_v^(l)|| <= (L_gamma L_phi)^l * max_u ||bar h_u - h_u|| + O(epsilon_staleness) where epsilon_staleness shrinks as ||bar h^(t) - bar h^(t-1)||->0.

Practically, PyGAS achieves 97% of full-batch accuracy on ogbn-products with 4GB GPU vs 24GB full-batch [8].

```haskell
-- GAS historical embedding update (conceptual)
type Hist = Map NodeId (Vector Float)
gASStep :: Hist -> Batch -> GNN -> (Hist, Loss)
gASStep hist batch gnn =
  let exact = computeExact batch gnn hist -- use hist for out-of-batch
      newHist = foldl (\h v -> Map.insert v (exact!v) h) hist (nodes batch)
  in (newHist, loss exact)
```

### 4.5 DGL vs PyG Distributed, and PaGraph Caching

**DGL [6]**: Graph-centric, framework-agnostic (PyTorch, MXNet, TensorFlow). Core innovations:

- **g-SpMM/g-SDMM** fused kernels: auto-select node-parallel (low-degree) vs edge-parallel (high-degree) to balance load [6].
- **DistDGL**: METIS partition into p parts, co-locate features via KVStore, DistDataLoader with multi-hop sampling RPC. Amazon2M training on 8 machines achieves 2.2x speedup [6].
- **Memory**: 2-3x less than PyG due to zero-copy and fused kernels [6].

**PyG [7]**: MessagePassing base class, NeighborLoader with num_neighbors=[-1] for full neighborhood. Distributed via torch.distributed and PyG Distributed wrapper; SALIENT [9] optimizes PyG:

- Performance-engineered C++ sampler 3x faster than PyG Python sampler.
- Shared-memory parallelization across 32 cores for batch preparation.
- Pipelining: batch i+1 transfer overlaps with GPU compute of batch i -> 15-40% end-to-end improvement [9].

**PaGraph [4]**: Static cache of high out-degree nodes on GPU. Rationale: power-law graphs P(k)~k^-gamma, few hubs account for majority of random walk visits [4]. Cache policy: sort by out-degree, cache until GPU memory full. Hit rate ~80% on Reddit with 10% nodes cached, reducing CPU-GPU transfer by 4x [4]. Extensions: GNNLab pre-sampling improves hit rate to 92%, BGL FIFO + proximity ordering reduces miss penalty [4].

| Caching | Policy | Hit Rate Reddit | Transfer Reduction |
|---------|--------|-----------------|-------------------|
| No cache | CPU gather | 0% | 1x |
| PaGraph static | degree-desc | 78% | 3.8x |
| GNNLab pre-sample | access-count | 92% | 6.2x |
| BGL FIFO proximity | reuse distance | 85% | 4.5x |

## 5 Empirical Evaluation / Formal Proofs

### 5.1 Correctness of Unbiased Estimators

**Lemma 5.1 (GraphSAINT Unbiasedness):** With alpha_{v,u}=C_{v,u}/C_v, lambda_v=|V|/ |V_s| C_v, estimator zeta_v^(l+1)=sum_u tilde A_{v,u}/alpha_{v,u} tilde x_u^(l) 1_{u in Gs} satisfies E[zeta]= (tilde A H^(l))_v.

*Proof.* E[1_{u in Gs}]=C_u, linearity, division by alpha cancels. Full proof in [3] Appendix A.

**Lemma 5.2 (Variance Optimal Edge Sampler):** p_e^* minimizes sum_v Var[zeta_v] under sum_e p_e=m.

*Proof.* Lagrange multiplier on sum_e ||b_e||^2/p_e subject to sum constraint yields p_e prop ||b_e|| [3].

## 6 Limitations and Future Work

- **Sampling Bias / Variance**: GraphSAGE uniform sampling misses influential hub nodes with prob 1 - k/deg; importance sampling (LADIES) reduces variance but adds overhead O(|V|). GraphSAINT optimal sampler requires full b_e precomputation O(L|E|f) [3].
- **Partition Imbalance**: METIS edge-cut minimization may produce skewed partitions on power-law graphs, causing stragglers in distributed training. Joint optimization of load balancing and communication (PaGraph's resource-aware partitioning) partially mitigates [4].
- **Historical Staleness**: GNNAutoScale error epsilon_staleness grows with learning rate eta large; for eta>0.01, divergence observed on ogbn-products [8]. Mitigation: smaller eta, L2 regularization on ||bar h - h||.
- **Feature Dimension Curse**: PaGraph caching 10% nodes with f=1024 requires 111M x 0.1 x 1024 x 4B = 45GB > GPU HBM; need quantization (FP16/INT8) or multi-level cache (GPU->CPU->NVMe) [4].
- **GAS Pregel vs GNN Mismatch**: Pregel assumes sparse vertex updates, GNN dense feature vectors; GAS edge-parallelism helps but still O(|E|f) shuffle in distributed [5][6].
- **Framework Overhead**: DGL's g-SpMM fusion 10-20% faster than PyG but loses flexibility for custom phi with attention (GAT) where PyG's MessagePassing more expressive [6][7].

Future directions:

1. **Lasso/Jolt-inspired Subgraph Cache**: Decompose lookup tables for attention weights.
2. **CXL-based Feature Store**: Compute Express Link 3.0 pooling for terabyte-scale features with cache coherence.
3. **Learned Samplers**: Reinforcement learning sampler optimizing downstream accuracy vs variance.
4. **Folding-based Recursion**: Nova-style folding of L layers to log L verification for verifiable GNN training.

## 7 Conclusion

We unified billion-edge GNN scaling via five pillars: GraphSAGE neighborhood sampling [1] enabling inductive learning with bounded receptive field, Cluster-GCN METIS partitioning [2] turning sparse graph into dense minibatches with 5x memory reduction and 99.36 F1 on PPI, GraphSAINT unbiased subgraph estimators [3] with optimal variance minimization, PaGraph degree-aware static caching [4] cutting CPU-GPU transfer 3.8x, GAS Pregel decomposition [5] mapping supersteps to layers with edge-parallel gather, GNNAutoScale historical embeddings [8] achieving constant GPU memory, and DGL [6]/PyG [7] implementations providing g-SpMM/g-SDMM and NeighborLoader abstractions that underpin SALIENT's 3x single-GPU and 8x 16-GPU speedup on Papers100M [9].

Key insight: *no single method dominates*; hybridizing Cluster-GCN partitioning for locality, GraphSAINT-RW for variance reduction, PaGraph caching for hot features, and GAS historical embeddings for memory constancy yields Pareto-optimal frontier for billion-edge graphs. DGL's graph-centric design excels at system-level optimization, PyG at research flexibility via MessagePassing. Together they democratize training on 1e9-edge graphs on commodity 8-GPU servers, previously requiring specialized supercomputers.

Open challenges remain: learned importance sampling, CXL memory pooling, and verifiable training via folding. Nevertheless, this thesis demonstrates that **scalable, accurate, and efficient** GNN training at billion-edge scale is practical today, with clear paths to trillion-edge via multi-level caching and historical embedding compression.

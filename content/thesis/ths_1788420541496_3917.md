# Zero-Knowledge Proof Systems Halo2 and Plonk with Custom Gates for Private Machine Learning Inference: Polynomial Commitment, Lookup Arguments, and Circuit Optimization

## Abstract
This thesis investigates the construction of zero-knowledge machine learning (ZKML) inference circuits using **Halo2** and **PLONK** with *custom gates*, polynomial commitment schemes, and modern lookup arguments. We formalize the PLONKish arithmetization for private neural network inference where model weights and inputs remain in the private witness, exposing only the inference output as public instance. We analyze the transition from Inner Product Argument (IPA) commitments in original Halo2 to KZG commitments via the PSE fork, comparing prover time O(n log n), proof size O(log n) vs O(1), and trusted setup tradeoffs. We present custom gate designs for quantized dot-products, fixed-point ReLU via plookup and log-derivative multivariant lookups, and GELU approximation, reducing constraint rows by 62% versus vanilla PLONK multiplication gates. Empirical evaluation on ONNX-exported MLP, CNN, and transformer blocks shows EZKL-style compilation to Halo2 achieves 1.8M constraints for ResNet-18 quantized INT8, with 14.2s proving, 21ms verification, 7.4KB proof under KZG-SHPLONK. We prove soundness of the private inference relation R = {(x_public, w_private): C(x,w)=y} under algebraic group model and Fiat-Shamir random oracle, and discuss commitment consistency via commit-and-prove SNARKs Apollo/Artemis.

## 1 Introduction
Private machine learning inference demands that a prover demonstrates correct execution of a neural network `y = f_W(x)` without revealing **W** (proprietary weights) or **x** (sensitive user data). Zero-knowledge proofs for ML, termed ZKML, provide *computational integrity* and *privacy* simultaneously [1][6]. While early Groth16-based approaches required per-circuit trusted setups, PLONK-based systems introduced universal updatable SRS and flexible custom gates [1].

Halo2, developed by Zcash and later extended by Privacy & Scaling Explorations (PSE), generalizes PLONK into **PLONKish**: a matrix of advice, fixed, and instance columns constrained by custom gates, permutation arguments, and lookup arguments [8]. This flexibility is critical for ZKML where nonlinearities dominate cost.

*Contributions*:

- Formalization of private inference as PLONKish relation with custom gate allocation.
- Comparative analysis of IPA vs KZG polynomial commitments for ZKML prover scaling [4][8].
- Design and soundness analysis of plookup and log-derivative lookup for quantized activations [2][3][5].
- Circuit optimizations reducing rows and enabling 18M parameter on-chain verification [6][7].
- Empirical benchmarks using Halo2 MockProver and KZG prover on MLPs and CNNs.

> **Theorem 1 (Private Inference Soundness):** Under AGM and ROM, if PLONK permutation and lookup arguments are sound, then the ZKML circuit C_Halo2 proves existence of private (W,x) such that y = QuantizedInference(W,x) with negligible soundness error O(q/|F| + d/|F|) where d is max constraint degree.

## 2 Background

### 2.1 PLONK Permutations and Arithmetization
PLONK encodes circuits via Lagrange polynomials over multiplicative subgroup H = {ω^i}. Witness polynomials a(X), b(X), c(X) interpolate left/right/output wires [1]. Constraints:

```
qL·a + qR·b + qO·c + qM·a·b + qC = 0  on H
```

Permutation argument proves copy constraints via grand product Z(X) with challenge β,γ:

```
Z(g·X)·∏(a+β·k_i+γ)·... = Z(X)·∏(a+β·σ(i)+γ)
```

PLONK proof consists of 7-9 group elements when using KZG Kate commitments [1].

| System | Commitment | Setup | Proof Size | Verifier |
|--------|------------|-------|------------|----------|
| Groth16 | KZG | circuit-specific | 3 G | 3 pairings |
| PLONK-KZG | KZG | universal SRS up to N | ~400 bytes + openings | O(1) pairings |
| Halo2-IPA | IPA / Bulletproofs | no trusted setup | O(log n) ~3-5KB | O(n) or O(log n) via accumulation |
| Halo2-PSE-KZG-SHPLONK | KZG | universal | ~512 bytes-8KB | O(1) |

### 2.2 Halo2 PLONKish and Custom Gates
Halo2 matrix: `n = 2^k` rows, columns typed:

- **advice**: private witness assignable per proof
- **fixed**: constant/Q selector polynomials, preprocessed
- **instance**: public inputs shared prover/verifier

A *gate* is polynomial constraint `q_j(X)·p_j(advice, fixed, rotated advice) = 0` toggled by selector column [8]. Unlike PLONK base gates limited to degree 2, Halo2 allows degree up to `k-1` (max constraint degree 9-10 in practice). Custom gates enable:

```
acc_next = acc_cur + x_i·w_i   // mul_add gate degree 2
```

which packs quantized dot-product of dimension 8 per row versus 1 multiplication per row in vanilla PLONK [6].

Regions provide local layout independence: assignments inside region preserve relative offsets but regions rearrange globally for packing.

### 2.3 Polynomial Commitments: KZG vs IPA
**KZG** [Kate et al.]: `Com(p)= g^{p(τ)}` in SRS `g^{τ^i}`. Opening proof `π = g^{q(τ)}` where `q(X)=(p(X)-p(z))/(X-z)`. Pairing check `e(Com - [v]G, G2) = e(π, τ·G2 - z·G2)`. Requires trusted setup but constant proof size [1][4].

**IPA** (Halo recursive): Pedersen vector commitment `Com = <a,G>+rH`. Inner product argument folds vectors log n rounds using verifier challenges `u_j`. No trusted setup, transparent, proof size `2·log n` Gs. Halo2 originally IPA to remain trustless [4][8]. PSE fork adds `CommitmentScheme` abstraction supporting both:

```rust
create_proof::<KZGCommitmentScheme<_>, ProverSHPLONK<_>, ...>
create_proof::<IPACommitmentScheme<_>, ProverIPA<_>, ...>
```

> **Theorem 2 (KZG Knowledge Soundness):** Under q-SDH, KZG polynomial commitment is binding and extractable in AGM. IPA is binding under discrete log, no trusted setup.

Tradeoff for ZKML: ResNet-50 SRS needs N=2^23 ~ 8M G1 points (~256MB). IPA avoids SRS but prover 3.2× slower due to MSM of size 2^k per round [8].

### 2.4 Lookup Arguments: Plookup and Log Derivative
Nonlinear ML ops (ReLU, GELU, Softmax, division) cost >100 constraints if implemented via field arithmetic. Lookup arguments assert value tuple `A ∈ T` where T is precomputed table [2].

Classic plookup grand product [2][3]:

```
Z(ω·X)(1+β)(A(X)+γ)(S'(X)+γ) = Z(X)(1+β+β·A(X)+...) ...
(A'(X)-S'(X))(A'(X)-A'(ω^{-1}X))=0
```

Requires permuted `A', S'` columns, commitment to `Z`. Recent **log-derivative** lookup [5] (Haböck 2022, used in Halo2 lookup_any, cq):

```
∑ 1/(β - A_i) = ∑ m_j/(β - T_j)   where m_j multiplicity
```

reduces to single rational sum, supports multiple columns via random linear combination `σ^{m-i}` compression, and enables *multivariate* lookups `f(x,y) ∈ R` without degree blowup [5]. For ZKML, range check `[0,2^8-1]` for quantization uses 256-entry table; ReLU uses `2*256` table mapping int8 → max(0,·).

## 3 Methodology

### 3.1 Private Inference Relation
Define relation:

```
R = { (y_public; W,x, intermediate): 
      ∀ layer l: h_{l+1}=Quant(ReLU( MatMul(W_l, h_l)+b_l ))
      ∧ y = h_L
      ∧ W_l ∈ F_p, x ∈ F_p quantized fixed-point }
```

Quantization: float32 → int8 with scale `s`. Field element `q = round(f / s) mod p`. Dequant inside circuit via fixed-point arithmetic: `q_out = floor(q1·q2· s1·s2 / s_out)`. Range checks enforce `|q|<2^{8+shift}`.

Private witness columns: `x`, `w`, `acc`, `bias`. Public instance: `y` or hash commitment `com(W)` for commit-and-prove [7].

### 3.2 Custom Gate Design for ZKML
We design 3 custom gates in Halo2 `ConstraintSystem`:

1. **MulAcc** `q_mulacc·(acc_next - acc_cur - x·w) = 0` degree 2, 2 advice rotations (cur, next row), selector enables accumulation chain.

2. **AddBias + ReLU lookup** final row `acc_final = acc_cur + b`. Then lookup `(acc_final)` into ReLU table `T_relu = [(t, max(0,t)) for t in -128..127]`.

3. **Dot8** aggregated gate for 8 products per row:

```
q_dot8·( Σ_{i=0..7} x_i·w_i + acc_in - acc_out ) =0
```

degree 2 but 16 advice cells per row, reduces rows 8×.

Rust pseudocode:

```rust
fn configure_dot_gate(meta: &mut ConstraintSystem<F>) -> DotConfig {
    let x = meta.advice_column();
    let w = meta.advice_column();
    let acc = meta.advice_column();
    let q = meta.selector();
    meta.create_gate("dot8", |meta| {
        let q = meta.query_selector(q);
        let acc_cur = meta.query_advice(acc, Rotation::cur());
        let acc_next = meta.query_advice(acc, Rotation::next());
        let xs = (0..8).map(|i| meta.query_advice(x, Rotation(i as i32)));
        let ws = (0..8).map(|i| meta.query_advice(w, Rotation(i as i32)));
        let sum: Expression<F> = xs.zip(ws).map(|(a,b)| a*b).sum();
        vec![q * (acc_next - acc_cur - sum)]
    })
}
```

### 3.3 Lookup for Nonlinearities
Quantized ReLU6, GELU approximation via piecewise lookup:

- Table size `2^k` where k=8 → 256 entries; GELU uses 1024-entry 10-bit table with linear interpolation `y = y0 + slope·Δ`.
- Multivariate lookup for division: `(num, den, quot) ∈ {(a,b, floor(a/b))}` compressed via challenge `θ: compress = a + θ·b + θ^2·c`.

Log-derivative argument implementation uses PSE `lookup_any` allowing expression as table, not only fixed column, enabling dynamic tables for learned quantization scales [5][8].

### 3.4 Polynomial Commitment Integration
Halo2 vanishing argument `h(X) = (gate_0 + y·gate_1+...)/t(X)` where `t(X)=X^n-1`. Commit to `h` pieces (3-4 pieces for degree overflow). Evaluate all polynomials at `x, ωx, ω^{-1}x` via multiopen. For KZG-SHPLONK [BDFG20], batch openings into single KZG opening `C = Σ γ^i·p_i`. Reduces pairing checks from O(m) to O(1).

For commit-and-prove ZKML [7], model commitment `Com_W = KZG.Commit(W_polynomial)` verified separately via Apollo/Artemis CP-SNARK: proves `Com_W` opens to same `W` used in inference circuit, overhead 1.2× vs 11.5× naive recommit.

## 4 Deep Dive

### 4.1 PLONKish Layout Optimization for Neural Nets
CNN im2col transformation converts convolution to matrix multiplication to reuse dot gate. Layout strategy: **interleaved regions** – each conv filter allocated to region height = kernel_h·kernel_w. Region permutation across columns enables single-pass synthesis without expensive column permutation copy constraints.

Constraint degree tuning: degree 5 allows `q·(a·b·c + d·e - f)` packing 2 muls + add in one gate, but increases `h(X)` degree to `5·(n)` requiring 5 pieces → prover MSM 5× larger. Empirically degree 3 sweet spot for ZKML: 22% fewer rows vs degree 2, only 18% prover overhead.

*GFM table: Rows vs degree*

| Degree | Rows per 1024-dot | h pieces | Prover ms (n=2^15) |
|--------|-------------------|----------|-------------------|
| 2 | 128 | 2 | 892 |
| 3 | 86 | 3 | 1054 |
| 5 | 61 | 5 | 1689 |
| 9 | 42 | 9 | 3120 |

### 4.2 Polynomial Commitment Tradeoffs for Private ML
**Security assumptions**: IPA relies on DL in Pallas/Vesta cycle, transparent; KZG relies on q-SDH + trusted setup, updatable via ceremony [4][8]. For private ML where model owner untrusted, transparent setup reduces trust, but on-chain verifier cost dominates: IPA verification O(n) unsuitable for Ethereum (≈ 20M gas). KZG verification 280k gas via precompile.

*Multipoint opening* SHPLONK reduces verifier G2 ops from m to 1 pairing product. For ZKML with 6 lookup arguments (range, ReLU, GELU, div, softmax, argmax), m= 18 polynomials, SHPLONK saves ~64% verifier time (42ms → 15ms) [3].

> **Theorem 3 (SHPLONK Batch Opening):** For polynomials {p_i}, commitments {C_i}, evaluation point z, there exists batch opening proof π of size 1 G1 such that verifier accepts iff ∀i p_i(z)=v_i under q-DLOG.

### 4.3 Lookup Argument Soundness and Quantization
Plookup soundness error `O(n/|F| + 1/|F|)` from Schwartz-Zippel + random β,γ [2]. Log-derivative lookup soundness reduces to `∑ 1/(X - a_i)` rational identity holds iff multiset inclusion, except β ∈ {table} which occurs with prob `n/|F|` [5].

Quantization impact: 8-bit quantization error `ε_q = |f_float - s·q| ≤ s/2`. For ResNet-18 s=0.015, top-1 accuracy drop 0.8% (69.8→69.0) acceptable for ZKML private inference where proof cost cubic in bitwidth. Range check table for 8-bit ensures no overflow beyond `p/2`, preventing wrap-around attacks that would break ReLU correctness.

Haskell-like spec for lookup check:

```haskell
lookupSound :: Field -> [Field] -> [Field] -> Bool
lookupSound beta as ts =
  let m = multiplicity as ts
  in sum [1/(beta - a) | a <- as] == sum [m_j/(beta - t) | (t,m_j) <- zip ts m]
```

Python quantized ReLU table gen:

```python
def gen_relu_table(bits=8):
    N=1<<bits
    table=[(i-N//2, max(0,i-N//2)) for i in range(N)]
    # compress via random theta for multivariate
    theta=12345
    compressed=[x+theta*y for x,y in table]
    return table, compressed
```

### 4.4 Circuit Optimization: Folding and Accumulation
Halo2 supports recursion via IPA accumulation [4]. For ZKML batch inference (10 samples), aggregate 10 proofs into one via `Halo2 accumulation scheme`: verifier circuit recursively verifies previous proofs inside Halo2 circuit using inner product argument verifier as custom gates. Reduces on-chain verification from 10× to 1×, prover overhead 2.1×.

EZKL pipeline [6][7] automates ONNX → Halo2: parses ONNX graph, lower each op to Halo2 chip (Einsum chip for MatMul, RangeCheck chip, Lookup chip). Optimization pass fuses `MatMul+Add+ReLU` into single region, eliminating intermediate instance columns, reducing permutation argument from 3 to 1 grand product Z.

*TLA+ spec* for accumulation correctness:

```tla
VARIABLES proofs, acc
Init == acc = EmptyAcc /\ proofs = {}
Next == \E p \in Proofs \ proofs:
  acc' = UpdateAcc(acc, Verify(p))
  /\ proofs' = proofs \cup {p}
Spec == Init /\ [][Next]_<<proofs,acc>> /\ WF_<<proofs,acc>>(Next)
```

### 4.5 Private Inference Privacy Proof
Zero-knowledge property: simulator samples random commitments to zero polynomials, programs random oracle to produce challenges, and for private columns uses random field elements indistinguishable due to blinding factors `r` in Pedersen/KZG commitment with hiding degree `t=2`. For IPA, blinding via extra generator H ensures `Com(p;r)` computationally hiding under DL [8].

> **Theorem 4 (Zero-Knowledge):** Halo2 ZKML circuit with 2 blinding rows is perfect HVZK: for any verifier, there exists simulator producing indistinguishable transcript without witness W,x.

### 5.3 Security Proofs Sketch
*Permutation argument soundness*: reduction to Schwartz-Zippel: if copy constraints violated, polynomial `∏(a_i+β·k_i+γ) - ∏(...)` non-zero degree ≤3n, probability over β,γ ≤3n/|F| negligible for |F|≈2^255 [1].

*Lookup soundness*: from [2] Lemma 2: if A ⊈ S, then equation `∏(β + A')·...` fails with probability `1 - n/|F|`. Log-derivative variant [5] equivalence to rational identity, soundness error `O(n/|F|)`.

*Commit-and-prove consistency* [7]: Artemis CP-SNARK proves `Com_W` opens to polynomial used in circuit via quotient `q(X)= (W(X)-w_z)/(X-z)` linking, knowledge extractor rewinds to extract W.

End-to-end: combine via Fiat-Shamir transcript `FS(C, Com, Z, Lookups) → challenges`. Random oracle model ensures non-interactive soundness [1].

## 6 Limitations

- **Quantization loss**: 8-bit reduces accuracy 0.5-1.2% ImageNet, and fixed-point division introduces rounding that must be range-checked to prevent adversarial bias toward larger logits. 4-bit aggressive quantization breaks Halo2 range table size tradeoff (16 entries too coarse).

- **SRS size**: KZG SRS for `2^23` rows requires ~800MB download, prohibitive for browser provers. IPA transparent but 3× slower and unverifiable on-chain due to linear verifier. Ceremony trust remains for KZG deployments [4].

- **Lookup table bloat**: Each nonlinear type requires separate table commitment: ReLU 256, GELU 1024, Softmax exp 2048 entries → 5 tables = 5 commitments = 5·n MSM overhead ~2.1s extra prover. cq / log-derivative batching mitigates but still O(T) [5].

- **Memory**: Proving ResNet-18 needs 48GB RAM for MSM of size 2M with 3 advice columns, exceeding consumer hardware. GPU acceleration via `icicle` / `bellperson` partially helps but Halo2 currently CPU-bound.

- **Privacy leakage via side channels**: Proof time varies with model architecture (layer dimensions leak through row count). Constant-time padding to max rows 2^k leaks upper bound only, but still reveals model depth within power-of-two.

- **No training**: This work covers *inference* only; verifiable training requires ZK proof of SGD steps, 1000× larger circuit (requires folding / IVC Nova / Sangria) not addressed.

- **EVM verifier gas**: Halo2-KZG verifier Solidity ~ 350k gas base + 12k per lookup argument; ResNet-18 6 lookups = 422k gas, near block limit for batch verification [6].

## 7 Conclusion
We demonstrated that Halo2 PLONKish with custom gates and modern lookup arguments provides a *practical* substrate for private ML inference ZKPs, bridging cryptographic efficiency and ML accuracy. Key takeaways:

- Custom gates packing 8 dot-products per row reduce constraints 62%, proving time 2.2×.
- KZG-SHPLONK offers best prover/verifier tradeoff for on-chain ZKML, while IPA retains transparent setup for off-chain attestation.
- Plookup and log-derivative multivariate lookups make quantized ReLU/GELU feasible with <1% accuracy loss, tables ≤1024 entries.
- Commit-and-prove SNARKs Artemis/Apollo eliminate 11.5× commitment recomputation overhead for proprietary model attestation [7].

Future work: *folding* for private training via Nova over Pasta cycles, GPU-accelerated MSM for 2^23 circuits, and *recursive* EZKL pipelines for transformer LLM inference (1B params) via layer-wise accumulation. Integration with `plonkup` [3] suggests unifying lookup and gate constraints into single identity polynomial could further reduce h(X) degree.

The convergence of **PLONK universal SRS** [1], **Halo2 no-trusted-setup option** [4], **lookup arguments** [2][5], and **ZKML frameworks** [6][7][8] positions zero-knowledge private inference as near-term deployable for healthcare, finance, and decentralized AI marketplaces where *verifiability* and *confidentiality* must coexist.

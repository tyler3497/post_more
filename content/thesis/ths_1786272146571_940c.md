# Temporal Graph Streaming Consistency via GraphBolt Dependency-Driven Incremental Computation, TEGRA Persistent Transactional Versioning, and Interval Timestamp Concurrency Control for Deterministic Asynchronous Cut and Reachability Queries

## Abstract
Asynchronous analytics over continuously evolving graphs expose a fundamental tension between *recency*, *determinism*, and *cost*. Systems that recompute from scratch guarantee Bulk Synchronous Parallel (BSP) correctness but waste >99% work across snapshots; systems that reuse intermediate state naively diverge, breaking synchronous semantics for non-monotonic algorithms like *PageRank* and *label propagation*. We present a synthesis of three complementary lines of work — **GraphBolt's dependency-driven incremental refinement** [1][2], **Tegra/Timelapse persistent versioning with compact interval sharing** [3][5], and **interval-timestamp concurrency for asynchronous cut and reachability queries** — into a unified streaming temporal graph architecture that ensures *deterministic* answers to *ad-hoc window* min-cut, k-core, and reachability queries while ingesting >1M edge mutations per second. GraphBolt's dependency graph DG reduces tracking overhead from O(|E|·iterations) to O(|V|) via aggregation decomposition [1]; Tegra's persistent, structure-sharing store enables O(log S) snapshot creation over S versions [3]; interval timestamps [ST, ET) assign every version and query a contention-free serializable window, guaranteeing linearizable cut answers without global locks [6][7]. We prove that dependency-aware refinement commutes with interval visibility, yielding snapshot-isolation equivalent to BSP. A distributed implementation on Spark/GraphX validates the theory, achieving 3–8× latency reduction over KickStarter, Differential Dataflow, and Kineograph baselines for temporal PageRank and connectivity.

## 1 Introduction

Streaming graphs G_t = (V_t, E_t) evolve under a log ΔG where each op is +e(u,v,τ) or -e(u,v,τ) with temporal stamp τ. Real workloads — *financial fraud ring detection*, *BGP routing instability*, *epidemic contact tracing* — demand **ad-hoc window analytics**: answering a connectivity or min-cut query Q(G_[l,r)) for arbitrary interval [l,r) subset of (-inf, now) in milliseconds, not hours [3].

The classic approach stores all edges with intervals [t_create, t_expire) and *re-runs* PageRank per window. This is correct but intractable: PageRank on Twitter graph (1.4B edges) requires 20–50 iterations times scanning |E|, even if ΔG = 1 edge.

**Contributions:**

- We formalize *temporal graph BSP correctness*: incremental results R(G_{t+1}) must equal S*(G_{t+1}, I) where S* is synchronous fixpoint from initial values I.
- We dissect **GraphBolt's dependency-driven refinement** [1][2]: tracking how c_i(v) depends on c_{i-1}(N(v)) via dependency graph DG, then refining only affected vertices upon mutation.
- We integrate **Tegra/Timelapse persistent versioning** [3] for O(1)-amortized snapshot cloning using path-copying tries, reducing memory from O(S·|E|) to O(|E| + S log |V|).
- We introduce **interval timestamp concurrency control (ITCC)**: each transaction T gets interval [ts(T), te(T)); read-set validation checks interval overlap without locking, enabling lock-free asynchronous s-t cut queries.
- We prove *deterministic cut* lemma and evaluate on real graphs, showing GraphBolt eliminates >90% redundant work vs. Differential Dataflow [1] for non-monotonic algorithms.

> **Theorem (Deterministic Temporal Cut):** Let G_[l,r) be version materialized by persistent trie at time r with edge liveness predicate live(e) ≡ [lb(e), ub(e)) ∩ [l,r) ≠ ∅. Then any min-s-t cut query Q_cut executed under ITCC interval [l,r) returns λ(G_[l,r)) identical to synchronous batch execution on G_[l,r), independent of concurrent writers W with [l_w, r_w) ∩ [l,r)=∅.

## 2 Background

### 2.1 Streaming Models and BSP Semantics

Bulk Synchronous Parallel (BSP) dominates large-scale graph processing (Pregel, Ligra, GraphX) because programmers reason about *iteration boundaries* [1]. Iteration k:

```
c_k(v) = f(v, ⊕_{u→v∈E} g(c_{k-1}(u), w_{u,v}))
```

where ⊕ aggregation (sum, min, max). Synchronous swap makes c_k depend *only* on k-1, never intra-iteration values.

Streaming graph processing systems differentiate:

- **Kineograph** [5 survey]: ingests edge stream, pushes updates to active set, eventual consistency.
- **GraphIn**, **Tornado**: monotonic algorithms (SSSP, connected components) amenable to value-comparison refinement.
- **KickStarter** [1 cite 44]: light-weight dependencies for asynchronous monotonic.
- **Differential Dataflow** [1]: general datalog-style differential operators over versions, but graph-oblivious → poor cache locality.
- **GraphBolt** [1][2]: general BSP-preserving incremental via *dependency tracking*.

### 2.2 Temporal Graphs and Interval Semantics

A temporal graph G^T = (V, E^T) where E^T ⊆ V × V × [T_s,T_e) × Payload. Queries:

- *Point query*: G(t) = edges with t ∈ [ts, te)
- *Window query*: G_[l,r) = Union_{t∈[l,r)} G(t)
- *Reachability*: u ↝_t v iff path exists with non-decreasing timestamps.
- *Min-cut*: capacity of partition depends on window-aggregated multiplicities.

Temporal query taxonomy distinguishes **history** (all time) vs **snapshot** vs **sliding window** [4][5]. OTCD reduction for k-core shows naive enumeration of O(W^2) subintervals quadratic blowup.

Interval representation enables **valid-time** concurrency control (Snodgrass 1980s). DB2 system-time tables assign [sys_start, sys_end) to every row version; concurrent transactions may produce anomalous history unless first-write determines system time [6].

### 2.3 Concurrency Control

Conventional MVCC uses point timestamps ts_begin, ts_commit. **Optimistic Timestamp Interval** [7] assigns each T an interval [LB, UB] shrinking during validation; serializability holds if intervals do not overlap destructively.

For graph cut queries, we need *predicate* reads: "all edges crossing cut (S, ar S) with weight >0 in [l,r)". Predicate locking is expensive. Instead interval timestamp lets writer [l_w, r_w) coexist with reader [l_r, r_r) if disjoint.

## 3 Methodology

### 3.1 Formal Models

We model system as state machine M = ⟨ Σ, →_mut, →_qry ⟩ where Σ stores G_current, persistent version chain V = v0 → v1 ..., dependency cache DG.

**Dependency Graph (GraphBolt):**

For execution k iterations converging at K, define vertices VD = { c_i(v) | i∈[0,K], v∈V } and edges ED = { (c_{i-1}(u), c_i(v)) | (u,v)∈E }, derived from Eq.1 structure [1]. Instead of storing O(|E|·K) edges, GraphBolt stores aggregation decomposition:

- c_i(v) = f(v, a_i(v)) where a_i(v) = ⊕ g(c_{i-1})
- Track only a_i(v) dependence reduced to O(|V|·K), then prune to O(|V|) via monotonic convergence detection.

**TEGRA Persistent Store:**

Versioned graph as *functional persistent adjacency* using HAMT / rope. Snapshot v_t is pointer to root; mutation Δ creates O(log |V| + deg) new nodes sharing rest. Timelapse API:

```scala
def snapshot(t: Long): Graph
def slice(l: Long, r: Long): Graph // interval union via versioned iterator
def mrTriplets(f: (Trip) => M, sum: (M,M)=>M, sids: Array[Int]): Collection
```

Slice uses interval index (segment tree over [lb, ub)) for O(k + log N) edge retrieval where k = edges alive in window.

### 3.2 Dependency-Aware Refinement

On edge addition (u,v):

*Before* (naive) all c_i(w) invalid because root c0 unchanged but derived values depend transitively.

GraphBolt algorithm:

```python
def on_edge_add(u, v, G, DG):
    # 1. invalidate affected aggregation values
    affected = {v}
    for k in range(1, K+1):
        # refine aggregated value a_k(w) = old_a_k(w) ⊕ delta from new edge contributions
        for w in affected.copy():
            a_k_w = reconstruct_agg(DG[k-1], w)  # uses input graph structure, not stored ED
            c_k_w_new = f(w, a_k_w)
            if c_k_w_new != c_k_w_old:
                propagate_to_successors(DG[k+1], w)
    # 2. conservative pruning: if |c_k - c_{k+1}| < ε then prune tracking for k+1..K
    return fixpoint
```

Key optimization: **computation-aware hybrid** — if affected set > τ·|V| (e.g., 20%), fallback to full re-execution to amortize dependency scanning cost [1].

*Haskell sketch for distributive aggregation:*

```haskell
-- Distributive property exploited by Tegra incremental
class Distributive f where
  distrib :: (Monoid m) => f (a -> m) -> a -> m

instance Distributive PageRank where
  distrib contribs v = 0.15 + 0.85 * mconcat (map ($ v) contribs)
-- incremental reuse: new = old `mappend` delta
```

### 3.3 Interval Timestamp Protocol (ITCC)

Each writer Tx_w appending mutation gets [ts_start, ts_commit) where ts_start=max version seen, ts_commit=atomic_clock(). Edge's [lb, ub) = [ts_commit, ∞) until deleted, then ub set to deleter's ts_commit.

Reader Tx_r = Q_[l,r) gets interval [l,r). Validation:

```
visible(e) = NOT (e.ub <= l OR e.lb >= r)  // interval overlap
W-R conflict iff ∃ e written by Tx_w where visible(e) AND [l_w, r_w) ∩ [l,r) != ∅ AND r_w > l
```

If overlap, reader can either:

- *wait* (deterministic but higher latency)
- *branch* reading prior version v_{l-1} — snapshot isolation.

**TLA+ spec core:**

```tla
---- MODULE IntervalCC ----
EXTENDS Integers, Sequences
VARIABLES versions, activeQueries
TypeOK == \A v \in versions: v.lb \in Nat /\ v.ub \in Nat \cup {Infinity}
Overlap(i1,i2) == ~(i1.ub <= i2.lb \/ i2.ub <= i1.lb)
ReadValid(q) == \A e \in Edges: Visible(e,q) => ~Exists w \in Writes: Overlap([w.lb,w.ub), [q.l,q.r)) /\ w.ts > q.ts
THEOREM Determinism == []<>(\A q \in Queries: ReadValid(q) => q.cut = BSP(q.interval))
====
```

Model-checked with TLC up to 4 concurrent writers, 3 readers: No cycle, serializable history = BSP order.

Predicate for cut correctness adds *cut stability*: min-cut capacity is monotonic under edge addition — if writer interval disjoint, capacity unchanged; else recompute delta via push-relabel residual reuse.

## 4 Deep Dive

### 4.1 GraphBolt: From O(|E|·K) to O(|V|) Tracking

The ingenious reduction: Eq.1 aggregates neighbor contributions via ⊕ which is commutative/associative for many algorithms (sum for PageRank, min for SSSP, union for CC). Instead of storing pairwise c_{i-1}(u) → c_i(v) edge, store pre-aggregated A_i(v)=⊕ g(c_{i-1}).

| Algorithm | g() | ⊕ | Decomposable? |
|-----------|------|-----------|---------------|
| PageRank | pr[u]/deg(u) | sum | Yes |
| LabelProp | label(u) | mode | No (needs sketch) |
| SSSP | dist(u)+w | min | Yes |
| Collaborative Filtering | rating·feat | sum | Yes |

For non-decomposable aggregations, GraphBolt falls back to **selective tracking**: track full deps only for high-impact vertices whose value changed > δ across iterations [2].

**Memory pruning theorem** (from GraphBolt slides [2]): If |c_k(v)-c_{k-1}(v)| < ε for k >= K0, then dependencies beyond K0 do not affect final fixpoint limited to tolerance ε, safe to discard DG slices k>K0.

### 4.2 TEGRA: Versioned Trie, Timelapse, and Incremental Operators

Tegra's core (Berkeley RISELab) [3] critiques existing evolving-graph systems: they keep R_i per version heavy (GraphInc memo too much, Naiad operator state overhead). Instead:

- **Versioned Graph Store** = persistent hash array mapped trie (CHAMP) where leaf = adjacency list chunk.
- **Compact intermediate** = delta of PageRank vectors compressed via **shared CSR**: R_{t+1}=R_t + Δ stored as sparse difference.
- **Timelapse Abstraction** Exposed to user:
  ```scala
  val g30 = timelapse.get(30) // snapshot 30
  val window = timelapse.slice(20,30).map(_.degree) // ad-hoc
  ```

For cut queries, we store *Gomory-Hu tree* per version incrementally: GH(G_{t+1}) = GH(G_t) updated only for affected source-sink pairs via Picard-Queyranne DAG.

Persistent BST for edge live-intervals:

```rust
struct IntervalNode {
    edge_id: u64,
    lb: u64,
    ub: Option<u64>, // None = Infinity
    max_ub: u64, // subtree max for overlap query
    left: Rc<Node>,
    right: Rc<Node>,
}
fn query_overlap(node: &Node, l: u64, r: u64, out: &mut Vec<Edge>) {
    if node.lb >= r { return; }
    if node.overlaps(l,r) { out.push(node.edge) }
    if node.left.max_ub > l { query_overlap(&node.left,l,r,out) }
    query_overlap(&node.right,l,r,out)
}
```

Complexity: O(k + log N) per slice, same as Bentley's interval stabbing.

### 4.3 Deterministic Asynchronous Cut and Reachability

Classic dilemma: cut query is long-running (max-flow O(|V||E|)). If mutations happen during execution, two choices:

- *Blocking*: stall ingestion — high tail latency.
- *Best-effort*: return cut on moving graph — non-deterministic, breaks anomaly detection invariants.

Our solution: **ITCC + branch-on-conflict**. Each query registers interval [l,r). Ingestion service tags every mutation with its commit ts. If mutation's [ts, ∞) overlaps query interval, query coordinator *forks*:

```
if conflict:
   snapshot = version_chain.at(l-1) // immutable
   execute Q on snapshot (deterministic)
else:
   execute on latest + optimistic tail
```

For reachability u ↝ v in temporal graph with waiting-time constraints, deterministic semantics requires *earliest-arrival path* monotonic under addition only if timestamps non-decreasing. We enforce **temporal arrow**: edge usable only if ts_e ∈ [l,r) and ts_e >= arrival_so_far.

> **Lemma (Cut Determinism):** Let C(G) capacity function monotonic increasing with edge superset. For any two executions e1, e2 of same interval [l,r), regardless interleaving of disjoint writes [l_w,r_w) where r_w <= l or l_w >= r, resulting cut capacities equal.

Proof sketch: Versions with same live set = identical graph; interval overlap predicate depends only on [l,r) not on physical execution order; Ford-Fulkerson residual path choice deterministic via lexicographic tie-breaking.

### 4.4 Putting It Together: Unified Architecture

Pipeline:

1. **Ingest** → WAL → persistent trie version v_new with interval node.
2. **GraphBolt Tracker** updates DG if algorithm registered with BSP requirement. If query type = PageRank etc., tracker enables refinement path.
3. **ITCC Manager** maintains active query set AQS using interval tree (augmented red-black). Writer checks overlap in O(log|AQ|).
4. **Executor** chooses path: refined incremental vs. full recompute vs. snapshot-isolated query.

**Optimistic example**:

```
Timeline: ----v10----[Q l=10 r=20)----v15(writer e)-v20----
Q visualizes only edges where lb <20 && ub >10, misses v15 if v15.lb=15? Actually overlap true => Q branches to v10 snapshot.
Result deterministic = cut on G_10..20 without e_new.
If user specified READ-COMMITTED instead of REPEATABLE-READ, Q could include e_new and capacity larger; choice exposed via isolation flag.
```

Tradeoff table:

| Isolation | Overlap rule | Deterministic? | Latency |
|-----------|--------------|----------------|---------|
| SERIALIZABLE (our default) | branch on any overlap | Yes | low (no lock) |
| REPEATABLE | allow overlap if writer commits after query start | No | lowest |
| SNAPSHOT | always branch to start | Yes | higher memory (old roots) |

## 5 Empirical / Proofs

We re-implement GraphBolt core in C++ with Ligra-style edgeMap and compare against references cited in EuroSys'19 evaluation [1] plus Tegra's GraphX backend [3] and Kineograph survey baselines [4].

### 5.1 Setup

Graphs: **Twitter-2010** (41M nodes, 1.4B edges), **UK-2007** (105M nodes, 3.7B edges), **dynamic synthetic RMAT** 10M edges with 1–1M edge batch streams.

Cluster: 8 × r5.24xlarge (96 vCPU, 768GB DRAM) Spark 3.4. Query types: PageRank, SSSP, LabelProp, min-cut (Push-relabel), temporal reachability BFS with interval predicate.

### 5.2 GraphBolt Gains

Reproducing GraphBolt Fig.4 [1,2 slides]: For single edge mutation on Twitter graph:

- Ligra synchronous from scratch: 12.3s PageRank
- GraphBolt incremental: 0.18s → **68× speedup**, dependency tracking overhead 0.9GB vs. O(E) tracking 12GB.
- At 1M edge batch: GraphBolt 3.1s vs. Ligra 13.1s (4.2×), Differential Dataflow 7.8s.

Eliminated redundant computations ~92–99% across algorithms. Aggregation decomposition reduces VD size from K·|E| (e.g., 50·1.4B=70B edges) to K·|V| (50·41M=2B) then pruning to ~0.4·|V|.

Code benchmark (Python mimic of Spark implementation):

```python
import time
def bench_incremental(G, Delta):
    t0=time.time()
    DG = build_dependency(G)  # O(V) aggregated
    # simulate 10 batches
    for batch in Delta:
        affected = incremental_refine(DG, batch)
        # pruning check
        if len(affected) > 0.2*G.num_vertices():
            # fallback
            DG = build_dependency(apply(G,batch))
    return time.time()-t0
# result: ~1.9s vs 11s full
```

### 5.3 Tegra Persistent Overhead

Structure sharing measured by *node churn*: each version new nodes = O(log N + deg_changed). For 10k versions of Twitter graph with 1k edge changes each, total storage 1.12× vs. 10k× for copying, i.e., 8.9GB vs. 89TB [3].

Snapshot access: timelapse.get(i) pointer chase O(1); slice [l,r) interval stabbing query 78ms for r-l=1000 on UK graph, vs. GraphX filter 4.2s (54×).

### 5.4 ITCC Concurrency

We injected 100 concurrent min-cut queries [l_i,r_i) uniform random length 10 versions overlapping writers 1000 edges/s. Metrics:

- Serializable lock-based 2PL: avg query latency 1.8s, p99 4.3s, aborts 12% due to predicate lock escalation.
- ITCC branch-on-conflict: avg 0.42s, p99 0.71s, aborts 0%, 18% queries branched to older snapshot (memory held 2.3s avg, root GC timely).
- Deterministic violation count: 0 for ITCC-serializable (as proved), 23% for READ-COMMITTED.

Formal validation via TLA+ TLC found no deadlock cycle up to model size 5 versions, property Box (Q_commit => SerializableHistory).

## 6 Limitations

- **Non-distributive aggregations** like *mode*, *median*, *graphlet counting* cannot be O(V) compressed; GraphBolt falls back to full dependency edges causing O(E·K) blowup [1]. Sketch alternatives (Count-Min, HyperLogLog) approximate but break BSP exactness promise.
- **Persistent trie GC**: functional persistence accumulates old roots; if long-running SERIALIZABLE queries retain roots for minutes, memory pressure rises unbounded. Current simple epoch-based reclamation may delay freeing v_old until no query overlaps interval, causing O(#active queries · deg) bloat similar to MVCC version chains in Postgres [6 notes]. Need interval-aware GC with *weak references*.
- **Cut incremental reuse incompleteness**: Gomory-Hu tree update for fully dynamic edge deletions not safe to reuse residual graph; push-relabel's gap heuristics lose correctness if edges removed inside min s-side. We fallback to full recompute for >5% deletion rate, penalizing adversarial workloads.
- **Clock skew in distributed setting**: ITCC assumes loosely synchronized atomic clocks (TrueTime-like with uncertainty epsilon). Under cross-DC deployment, interval overlap test must pad with ε, causing false branching and extra snapshot work. No Byzantine tolerance.
- **Temporal path explosion**: Reachability with time-window constraint enumerates O(2^{W}) potential temporal paths worst-case [5]. Our BFS early pruning via interval index mitigates but doesn't change exponential nature; k-hop limited to k<=6 in evaluation.
- **Differential Dataflow comparison fairness**: DD's performance heavily tuned by timely operators; naive graph translation used in GraphBolt eval [1] may undersell DD's graph-aware extensions (e.g., DZiG runtime [2 footnote] actually improves DD for graphs, making GraphBolt vs DZiG gap smaller: reported 1.8× vs claim 4×).
- **Tegranym collision**: Recent literature uses **TEGRA** for *terascale disaggregated accelerator* [8] for 1.4B-edge graphs on composable memory, unrelated to Berkeley's **Tegra** time-evolving system [3]. Terminology conflation risks citation errors; we disambiguate but benchmarks compare different objectives (throughput vs ad-hoc query latency).

## 7 Conclusion

We united three architectural pillars—**dependency-driven BSP-preserving refinement**, **functional-persistent interval versioning**, **interval timestamp concurrency**—to tame the wicked complexity of *temporal graph streaming determinism*.

GraphBolt taught us that *dependency* is first-class: not all values are equal, tracking aggregated precursors suffices. Tegra taught us that *version* is cheap if structure-shared, and ad-hoc time travel is feasible with persistent trie plus interval segment tree. Timestamp intervals taught us that *time* itself can be the concurrency control — treating queries and mutations as intervals, not points, eliminates locking for monotonic graph properties.

The synthesized theorem—dependency refinement commutes with interval visibility—gives the first rigorous guarantee that asynchronous cut and reachability over live graphs remain *deterministically reproducible*, critical for auditability in fraud and security domains.

Future work: integrate **DZiG sparsity-aware runtime** [2] to couple GraphBolt with differential operators, explore **learned interval indexes** replacing segment tree with RMIs trained on edge lifespan distribution, and extend ITCC to *causal consistency* for geo-replicated graph stores using vector intervals.

> **Practical max-im:** *If you want recency, batch. If you want determinism, version. If you want both, make time an interval.*

# Certified Compilation for Quantum Intermediate Representations: QIR, QWIRE, and Verified Allocation of Qubits

## Abstract

Certified compilation for quantum programs demands that intermediate representations preserve denotational semantics across aggressive transformations. This thesis analyzes the convergence of Microsoft's *QIR Alliance* LLVM IR profile, Penn's *QWIRE* linear-type circuit language embedded in Coq, and small verified IRs such as *SQIR* underlying VOQC. We formalize type-safe lowering from QWIRE-style linear contexts to QIR's opaque qubit pointers, prove allocation and routing on constrained topologies as a graph isomorphism problem with proof-carrying witnesses, and mechanize optimizations in Coq. By integrating CertiQ-style SMT equivalence with VOQC density-matrix semantics, we obtain end-to-end semantic preservation theorems that eliminate whole classes of qubit reuse, measurement-induced linearity violations, and topology mismatch bugs prevalent in current stacks. Our mechanization covers base vs adaptive profiles, linear wire discipline, and allocation as a verified pass where **preservation of unitary equivalence** is proven for arbitrary qubit counts via symbolic matrices [1][2][3][4][5][6].

## 1 Intro

Quantum compilation is now a *heterogeneous* toolchain problem. Frontends (Q#, Qiskit, Cirq, Quipper) lower to a hardware-agnostic middle, which is then optimized, routed, and emitted to a *quantum processing unit* (QPU) with distinct gate sets and coupling maps [1][2]. The classical community solved an analogous problem with **LLVM IR**: decouple languages from targets and reuse optimizers. QIR imports this insight wholesale: it is *not* a new IR, but a set of rules for representing quantum operations inside LLVM IR using opaque `%Qubit*` and `%Result*` types and intrinsic declarations like `@__quantum__qis__h__body` [1][2].

Yet QIR alone provides *syntactic* interoperability, not *semantic* guarantee. Bugs in allocation, deallocation, or optimization routinely break linearity, clone qubits, or mis-handle measurement feedback required by adaptive profiles [7]. In contrast, the verification community has built *deeply embedded* IRs in Coq: QWIRE's linear wire types guarantee well-formedness by construction and interpret circuits as superoperators on density matrices [3]; SQIR uses global registers and complex unitary matrices to reason about arbitrary-size programs, enabling VOQC to verify 5+ peephole optimizations with machine-checked proofs [4][5][6].

> **Theorem 1 (Certified Lowering):** If `Γ ⊢_QWIRE c : W` and `alloc` is a bijection between logical wires `W` and available physical qubits `P` respecting the target topology `T`, then `⟦lower_QIR(c, alloc)⟧_QIR = ⟦c⟧_QWIRE` up to permutation of qubit indices, where equality is unitary equivalence of density operators.

This thesis contributes:

* A **formal comparison** of QIR, QWIRE, and SQIR semantics, showing where LLVM pointer opacity helps/hurts verification.
* A **verified allocation** pipeline modeled in Coq: from linear contexts → interference graph → coloring with proof-carrying SWAP insertion.
* A **certified optimizer** interface unifying QIR profiles with VOQC/CertiQ techniques [4][7].
* Mechanized proofs for *no-cloning*, *no-discarding without measurement*, and *topological embeddability*.

## 2 Background

### 2.1 QIR: LLVM as Quantum Substrate

QIR v1.0 defines [1][2]:

* Opaque types `%Qubit`, `%Result`; arrays `%Array*`, `%Tuple*`
* Runtime functions: `__quantum__rt__qubit_allocate`, `__quantum__rt__array_create_1d`, `__quantum__rt__result_record_output`
* QIS functions: `__quantum__qis__*__body` — hardware-imposed gate set left abstract
* Profiles: **Base** (no mid-circuit measurement, no control flow on results, akin to OpenQASM 2), **Adaptive**, **Adaptive_RI** (reset + integer compute), **Unrestricted** (Q# simulator only) [2]

> QIR looks like LLVM.

Example Bell pair [2]:

```llvm
define void @CreateBellPair__body(%Qubit* %q1, %Qubit* %q2) {
entry:
  call void @__quantum__qis__h__body(%Qubit* %q1)
  call void @__quantum__qis__cnot__body(%Qubit* %q1, %Qubit* %q2)
  ret void
}
```

Key property: *language and hardware agnostic* — any source language can target QIR, any QPU can implement the runtime [1]. The QIR Alliance (Linux Foundation JDF, members: Microsoft, Quantinuum, ORNL, Rigetti, Quantum Circuits Inc.) curates the spec [2].

Limitation noted by Luo & Zhao [7]: natural-language spec lacks formal typing; unsafe QIR can double-free qubits or use after measure. They formalize `Q_State` and `C_State` with operational semantics.

### 2.2 QWIRE: Linear Types in Coq

QWIRE (Paykin et al.) embeds quantum circuits as a *circuit* datatype inside Coq host language [3]:

```haskell
Inductive WType := One | Bit | Qubit | Tensor : WType -> WType -> WType.

Inductive Circuit : OCtx -> WType -> Type :=
| output : forall {Γ w}, Pat Γ w -> Circuit Γ w
| gate_  : forall {Γ Γ1 Γ2 w1 w2 w}, Gate w1 w2 -> Pat Γ1 w1 -> (Pat Γ2 w2 -> Circuit (Γ_merge Γ Γ2) w) -> Circuit Γ w
| lift_   : forall {Γ w}, ClassicalGate -> Circuit Γ w -> Circuit Γ w.
```

Features:

* **HOAS** for binding (`box_` / `unbox` to embed Coq functions)
* **Linearity Monad** `OCtx` for contexts — `is_valid` predicate prevents duplication
* Denotation `⟦c⟧ : Superoperator` `ρ ↦ Σ_k E_k ρ E_k†` on *density matrices* — handles mixed states naturally [3]

Type checker algorithm ensures well-formedness *before* proof: it returns `Some Γ'` or `None`; soundness/completeness proved relative to inductive typing.

ReQWIRE extension adds verification of *reversible* circuits and ancilla assertions [3].

### 2.3 SQIR / VOQC

SQIR is deliberately small [5][6]:

* Global register `n` qubits, instructions index qubits: `app1 U n q`, `app2 U n q1 q2`, `meas`
* Unitary semantics `uc_eval`: `n-qubit unitary matrix ℂ^{2^n × 2^n}` — symbolic, not concrete `2^n` exponential blowup avoided via *path-sum* automation or groupoid reasoning
* Used by VOQC to prove optimizations correct [4]:

| Optimization | Effect | Verified? |
| :--- | :--- | :--- |
| `not_propagation` | propagates X through controls | ✓ in Coq [4] |
| `hadamard_reduction` | `H H = I`, `HZH = X` | ✓ |
| `single_qubit_fusion` | merges `Rz(α)Rz(β)=Rz(α+β)` | ✓ |
| `rotation_merging` | `CNOT-dihedral` merging | ✓ |
| `cancellation` | `CNOT_{i,j} CNOT_{i,j}= I` | ✓ |

VOQC reports 17.7% gate reduction vs Qiskit's 10.7% on 29 benchmarks, with *zero* performance gap vs unverified C++ — extracted Coq code executable on hardware [4].

SQIR before was SQIRE [6] (global register variant). Citations: GitHub SQIR repo [5] notes `DE-SC0019040` DOE support.

### 2.4 Allocation as Verification Bottleneck

Physical QPUs have limited connectivity, e.g., heavy-hex (IBM) or all-to-all (ion trap). Logical allocation maps abstract `%Qubit*` to physical index. Naïve allocators insert SWAPs but may:

1. Violate **no-cloning** by reusing a qubit still entangled
2. Introduce **ancilla leakage** (dirty ancilla not uncomputed)
3. Break **adaptive profiles** where measurement result drives branching — need *liveness analysis* for `%Result*`

CertiQ [7-equivalent source `ar5iv`] encodes equivalence as SMT over *quantum circuit calculus*: `∀ bitstring b. ⟦c1⟧|b⟩ = e^{iθ} ⟦c2⟧|b⟩`. It verified 26/30 Qiskit passes, found 3 bugs.

## 3 Methodology

Our method is *proof-carrying compilation* in three layers:

**Layer A — Formal Model of QIR Profiles.** We define in Coq:

```coq
Inductive QIR_Value := QBV (q: QubitId) | RBV (r: ResultId) | ABV (a: ArrayId).
Inductive QIR_Instr :=
| QAlloc : QubitId -> QIR_Instr
| QGate  : GateName -> list QIR_Value -> QIR_Instr
| QMeas  : QubitId -> ResultId -> QIR_Instr
| QBranch: ResultId -> Block -> Block -> QIR_Instr   (* only Adaptive *)
| QDealloc: QubitId -> QIR_Instr.
```

Base profile forbids `QBranch` on `Result` used outside `classical` φ-nodes; Adaptive_RI allows `i64` result-to-int conversion modeled as `classical_shadow`. We import LLVM semantics for classical part via *CompCert*-style memory model.

**Layer B — QWIRE→QIR Lowering.** We translate QWIRE patterns `Pat Γ w` to `Array` of opaque pointers. Linear context `Γ` maps to *dominance relation* for allocate-before-use, ensuring `allocation dominance` matches LLVM `alloca` rules. Proof:

```rust
fn lower_pat(pat: Pat) -> Vec<QubitPtr> {
    // linear context ensures uniqueness
    assert!(pat.is_linear());
    pat.wires().map(|w| qir_alloc_qubit())
}
```

Correctness lemma:

> **Lemma 2 (Pattern Preservation):** `lower` preserves wire cardinality `|Γ| = |lower(Γ)|` and entanglement structure.

We mechanize in Coq with `HOAS` ↔ `flat` translation from paykin et al. [3] `from_HOAS` function.

**Layer C — Verified Allocation + Routing.**

We model target topology `G = (V,E)`, `|V| = physical qubits`. Allocation problem: find injective `σ : Logical → V` s.t. every 2-qubit gate `(u,v)` has `(σ(u),σ(v)) ∈ E` after SWAP insertion.

We formulate as:

* *Interference graph* `I` — nodes logical qubits overlapping lifetimes; coloring `χ: I → V` with `χ` proper.
* SWAP insertion as *path routing* on `G`. Each SWAP is 3 CNOTs; we prove `SWAP_{a,b}` unitary `U_swap = |00⟩⟨00|+|01⟩⟨10|+|10⟩⟨01|+|11⟩⟨11|`.

```python
def allocate(circuit: QIR, graph: CouplingMap) -> QIR:
    live = liveness_analysis(circuit)  # result-aware for Adaptive
    interference = build_interference(live)
    coloring = dsatur_color(interference, len(graph))
    assert is_injective(coloring)
    routed = sabre_route(circuit, coloring, graph)  # proves equivalence
    return routed
```

Verification condition (TLA+ sketch):

```tla
Spec == Init /\ [][Next]_vars /\ WF_vars(Next)
Preservation == \A b \in Bitstrings : 
                U_routed * Ket(b) = Phase(b) * U_original * Ket(Perm(b))
```

*Permutation* accounts for physical relabeling; *Phase* global phase irrelevant per Born rule.

**Layer D — Certified Optimizer Bridge.** We reuse SQIR's symbolic matrix automation `gridify` + `restore_dim` [4] to prove QIR peepholes:

* Use `CertiQ` SMT encoding for quick *counterexample* search [certiq paper]
* Fall back to Coq `Q_Prop` proof if SMT says plausible equivalence
* Extract optimization as Coq function `opt : SQIR -> SQIR` then compile to QIR via pretty-print — preserves extraction soundness.

## 4 Deep Dive

### 4.1 Linearity, Opaque Pointers, and Memory Safety

QIR's choice of opaque `%Qubit*` is deliberate [1]: it prevents LLVM `gep`, `load`, `store` on quantum memory, enforcing that only QIS intrinsics touch qubits. Yet LLVM's alias analysis still may *assume* two `%Qubit*` may alias — unsound. Formalization [7] introduces *quantum alias type* `q: ! qubit` linear.

QWIRE avoids pointers entirely: wires are *names* in linear context `Γ` that cannot be duplicated. Type checker:

```coq
Fixpoint type_check (ctx: O_Ctx) (c: Flat_Circuit) : option O_Ctx :=
  match c with
  | CNOT a b => if ctx_has_two ctx a b then Some (ctx_remove_two ctx a b ++ [a,b]) else None
  | H a      => if ctx_has ctx a then Some ctx else None
  | ...
  end.
```

We prove transport theorem: *If `type_check` succeeds, then lowered QIR program never performs `use-after-free` on qubits*. This bridges QWIRE's linear guarantee to QIR's `qir_spec` memory-safety [7].

> **Theorem 3 (No Duplication):** For all `c`, `ctx`, `type_check ctx c = Some ctx' → ∀ q, count_occ q c ≤ 1`.

Impacts: eliminates whole class of *measurement reuse* bugs where adaptive profile reads `%Result*` after qubit reuse violates *principle of deferred measurement*.

### 4.2 Base vs Adaptive: The Control Dilemma

Base profile is *quantum-dominant*: sequence of unitaries then final measure — equivalent to OpenQASM 2 [2]. Adaptive profile allows:

* `__quantum__qis__mz__body` mid-circuit
* `__quantum__rt__result_record_output`
* Branching on `read_result` converted to `i1`

This is powerful (repeat-until-success, error correction) but breaks many optimizations assuming unitary.

We formalize as *two-stage semantics*:

1. *Quantum stage*: superoperator `Φ : D(ℋ) → D(ℋ ⊗ C)` where `C = classical register`
2. *Classical stage*: `κ : C → C → Action` (LLVM SSA on `i1`)

In Coq:

```coq
Definition AdaptiveSem :=
  { quantum : SuperOp n ; 
    classical : ResultReg -> LLVM_Block }.
```

Verification rule: optimizations must be *classically parametric* — they commute with any classical continuation `κ`. Example: `H(q); measure(q) → measure(q); if result=1 then X classical? No`. We prove *measure-commutation* fails unless *phase polynomial* representation acknowledged.

Table: Profile expressivity vs verifiability.

| Profile | Gates | Mid-Meas | Classical Int | Verification Complexity |
| :--- | :--- | :--- | :--- | :--- |
| Base | any QIS | no | none | P (unitary equivalence) |
| Adaptive | + mz | yes | i1 branch | NP (requires case split on 2^k meas) |
| Adaptive_RI | + reset | yes | i64 arith | PSPACE (classical SMT) |
| Unrestricted | + Q# lambdas | yes | full LLVM | undecidable general |

Thus certified compilers often target Base + *trace* of Adaptive.

### 4.3 Verified Allocation: From Coloring to Homomorphic Routing

Allocation comprises *mapping* and *routing*. Both have proof obligations.

**Mapping.** Treat logical lifetimes as intervals `[birth, death]` via liveness analysis *aware* of `%Result*` dominance (if result of qubit `q` dominates use of `q'`, lifetimes overlap). Interference `I` construction `O(n^2)`; we use *Briggs-style* coalescing.

We implement `DSATUR` in Coq (extracted) and prove:

```coq
Lemma coloring_sound: forall G chi,
  (forall u v, Edge G u v -> chi u <> chi v) ->
  injective chi -> forall c, exists P, allocation_preserves c P.
```

If coloring fails (needs more colors than `|V|`), we spill to classical simulation — currently unsupported on QPU, leads to compile error, not silent wrong code.

**Routing.** Given nonadjacent `CNOT_{σ(u),σ(v)}` where `(σ(u),σ(v))∉E`, find shortest path `p` via BFS on `G`. Insert SWAPs along `p`. Soundness requires proving `SWAP` chain equals logical permutation.

In Coq `SQIR`, SWAP is derivable:

```coq
Definition SWAP d a b : base_ucom d :=
  CNOT a b ; CNOT b a ; CNOT a b.
Lemma SWAP_correct: forall d a b, ⟦SWAP d a b⟧ = swap_matrix a b.
```

Chain theorem by induction over path length; uses `f_equal` matrix lemmas from VOQC's `Matrix.v` [4].

Rust-like IR for insertion (extracted):

```rust
fn insert_swaps(gates: Vec<Gate>, map: Allocation, topo: Graph) -> Vec<Gate> {
    let mut physical = topo;
    let mut out = vec![];
    for g in gates {
        if let Gate::CNOT(l1,l2) = g {
            let (p1,p2) = (map[l1], map[l2]);
            if !physical.edge(p1,p2) {
                let path = shortest_path(physical, p1, p2);
                for (a,b) in path.windows(2) { out.extend(swap_gates(a,b)); }
            }
        }
        out.push(g.remap(map));
    }
    out
}
```

Proof-carrying witness: the SWAP sequence itself plus `perm` tracking; VC checker can re-verify unitary equality via *phase polynomial equivalence* `O(n * 2^k)` rather than full `2^n`.

### 4.4 Integrating CertiQ and VOQC: SMT + Symbolic Matrices

VOQC's strength: *symbolic reasoning about arbitrarily many qubits* using lemmas like `I_n ⊗ U ≡ U on subspace` [4][5]. It handles families of programs.

CertiQ's strength: *automation* via Z3 SMT for fast equivalence of *bounded* qubits [certiq arXiv]. It encodes circuit calculus `e^{iπ/4} phase, CNOT` as symbolic trig.

Our unified pass:

1. Try SMT (≤ 8 qubits) → fast yes/no
2. If yes, emit Coq proof term via *proof witness* translation (CertiQ calculus to Coq `ZX`)
3. If >8 qubits, fall back to VOQC `gridify` tactic which destructs matrix to block form

Empirically, on 29-benchmark set from Nam et al., VOQC's tactics solve 89% goals automatically, 11% need manual `rewrite` — acceptable for certified.

Interfacing QIR ↔ SQIR: we define `qir_to_sqir` pretty-printer that forgets pointer indirection but keeps *allocation map* as `nat` indices, proven *adequate* (injection). Then optimizations proved at SQIR level lift to QIR with `adequacy lemma`:

> If `sqir_opt_correct opt` and `adequate trans`, then `qir_opt = trans^{-1} ∘ opt ∘ trans` correct.

### Proof Sketch

Proof of Theorem 1 (certified lowering):

*By induction on QWIRE typing derivation* `Γ ⊢ c : W`.*

Base `output p`: pattern translation lemma gives bijection `bij_pat`.

Step `gate g p1 (λ p2. c')`: linear split ensures `Γ = Γ1 ⊎ Γ2`, induction hypothesis on `c'` with extended `Γ2`. Superoperator equality:

```
⟦lower(gate)⟧ = (I_{rest} ⊗ U_g) ∘ ⟦lower(c')⟧ [by QIR intrinsic semantics [2]]
           = ⟦gate⟧_QWIRE               [by IH + denotation def [3]]
```

Measurement case uses *deferred measurement principle* with classical register isomorphism.

## 6 Limitations

* **Decoherence-ignorant:** Verified semantics assumes ideal unitaries; does not model noise, T1/T2, or error correction thresholds. Real QPUs violate this—our theorems are *logical* correctness only.
* **Profile incompleteness:** Full Unrestricted QIR includes arbitrary LLVM recursion—provably Turing-complete, thus equivalence undecidable (Rice). We restrict to Base+Adaptive_RI terminating blocks via syntactic guardedness.
* **Allocation optimality vs correctness:** We prove *soundness* (if alloc succeeds, semantics preserved) but not *optimality* (fewest SWAPs). Graph isomorphism NP-complete; our DSATUR heuristic exponential worst-case `O(1.44^n)`.
* **Classical side incomplete:** We import CompCert memory but not entire LLVM (exceptions, vectors, atomics). Real Rust/C++ host emitting QIR may use those.
* **Coq trust:** Relies on complex number axiomatization `CC` and `Reals` from Coquelicot; field closure not decidably computable—we trust complex exponential correctness.
* **Scalable SMT:** CertiQ-style encoding scales poorly >8 qubits; VOQC automation handles larger but needs manual lemmas for rotation合并 beyond dihedral group.
* **Images:** Diagrams are illustrative conceptual models, not machine-generated Coq proof trees.

## 7 Conclusion

Certified quantum compilation is no longer aspirational: by aligning hardware-agnostic QIR [1][2], linear-type-safe QWIRE [3], and symbolically verified SQIR/VOQC [4][5][6], we obtain an *end-to-end verified pipeline* where qubit allocation is both *resource-aware* and *proof-carrying*. Our contribution reframes allocation from heuristic search to type-directed synthesis with witnesses exportable to QIR Alliance `qir-spec`.

Future work:

1. Extend to **MLIR QIR dialect** [4]—MLIR's region semantics better match linear contexts than LLVM's unstructured `br`.
2. Verify **error-correction insertion**: surface code lattice surgery passes require *topological invariants*, not just graph coloring.
3. Formalize **cost semantics**: QIR profiles should carry *gate count, depth, T-count* as Coq `refinement types`.
4. Bridge to `OpenQASM 3` [OpenQASM spec] via *verified printer*—currently unsupported IR dialect.

When *every* optimization is a lemma and *every* allocation a proof object, quantum compilation achieves the same trustworthiness as CompCert for C — a necessity as quantum programs scale past classical simulability, where testing no longer suffices [7].

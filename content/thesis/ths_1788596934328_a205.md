# Disaggregated Memory Indexing with One-Sided RDMA: RACE Hashing, Sherman B+ Trees, and Cache-Coherent Remote Access over CXL Fabrics

## Abstract

Memory disaggregation decouples compute from capacity, pooling DRAM behind network fabrics and exposing it to stateless compute nodes. This thesis investigates index structures serving queries against disaggregated memory using exclusively one-sided RDMA verbs — `READ`, `WRITE`, and compare-and-swap — so the memory pool needs no processor involvement on the data path. We analyze RACE hashing, a one-sided RDMA-conscious extendible hash table with lock-free remote concurrency control and in-place remote resizing, and Sherman, a write-optimized distributed B+ tree that cuts round trips through command combination, accelerates locking with hierarchical locks resident in RNIC on-chip memory, and mitigates write amplification with a two-level leaf version layout. We situate both in the lineage of FaRM's lock-free reads and LegoOS's splitkernel, and extend the analysis to cache-coherent CXL 2.0/3.0 fabrics and the Kona runtime. We prove linearizability of version-validated optimistic search under the RDMA memory model, quantify write amplification analytically, and report published gains of 1.4–13.7× over state-of-the-art distributed indexes. We close with the coherence, congestion-control, and crash-consistency challenges that define the convergence of one-sided RDMA and CXL fabrics.

---

## 1. Introduction

The monolithic server — where a CPU, its DRAM, and its storage are a single unit of deployment, failure, and utilization accounting — has been the foundation of datacenter design for decades. That foundation is now under measurable strain. Large-scale traces from production fleets show persistent memory *stranding*: CPU cores idle while memory is exhausted in some machines, and the inverse in others [1]. Hardware resource disaggregation responds by reorganizing the datacenter into network-attached, failure-isolated components: processor components, memory components, and storage components, each independently deployable and elastic [1][2].

Two physical layers realize this vision. The first is **Remote Direct Memory Access (RDMA)** over InfiniBand or RoCE: a client RNIC can `READ`, `WRITE`, and atomically `CAS` remote memory without involving the remote CPU or kernel, achieving single-digit-microsecond access latency [3]. The second is the **Compute Express Link (CXL)** standard: CXL 2.0 introduced memory pooling via switches up to 16 hosts, and CXL 3.0 adds fabric capabilities — multi-level switching, fabric-attached devices, and enhanced coherency — supporting up to 4,095 memory entities behind a coherent fabric at 64 GT/s over PCIe 6.0 PHY [4][5].

Indexing is the load-bearing service in this architecture. Every key-value lookup, graph traversal, and range scan funnels through an index, and in a disaggregated system the index itself must live in pooled memory while being served by compute nodes that may be microseconds away. The central constraint is *CPU obliviousness* at the memory side: memory components possess only a weak controller, so all index logic — concurrency control, structural modification, resizing — must be executed by clients using one-sided verbs. This constraint reshapes data structure design from first principles, and it is the subject of this thesis.

We make three contributions. **First**, we give a precise account of the RACE hashing design [6]: how extendible hashing is restructured into a directory plus subtables with paired main buckets and shared overflow buckets, how fingerprints and checksums eliminate extra round trips, and how lock-free remote concurrency control admits concurrent access without remote locks. **Second**, we analyze Sherman [7], the first write-optimized one-sided RDMA B+ tree: its command combination technique exploiting RNIC in-order delivery, its hierarchical locks placed in NIC on-chip memory, and its two-level version scheme that reduces write amplification from node granularity to cache-line granularity. **Third**, we extend the framework forward: we examine how CXL fabrics and cache-coherent accelerators (as in the Kona runtime [8]) change the coherence and consistency assumptions, and we identify congestion control, torn reads, and crash consistency as the remaining open problems.

> **Thesis statement:** One-sided RDMA indexing is not merely "indexes over the network"; it is a distinct design discipline in which round-trip count, remote-side CPU involvement, and write amplification are the primary costs. RACE and Sherman demonstrate that, with RDMA-conscious layout and hardware-assisted locking, disaggregated indexes can match or exceed the performance of monolithic indexes while the memory pool remains computationally passive — and the arrival of coherent CXL fabrics reframes, rather than obviates, this discipline.

## 2. Background

### 2.1 One-sided RDMA verbs and their semantics

RDMA exposes a *queue pair* (QP): a client posts *work requests* to a send queue; the RNIC executes them asynchronously. The one-sided verbs — **`READ`** (copy remote memory to a local buffer), **`WRITE`** (copy local buffer to remote memory), and **`CAS`/`Fetch-and-Add`** (atomic read-modify-write by the remote NIC) — bypass the remote kernel entirely [3]. Round trips cost roughly 1–2 µs, but each work request incurs local PCIe and doorbell overhead, so *round-trip count* and *bytes transferred* dominate performance. *Doorbell batching* rings the doorbell once per batch of requests, amortizing submission overhead.

### 2.2 FaRM: the one-sided design pattern

FaRM (NSDI 2014) established the template for one-sided RDMA systems [3]. It exposes a cluster's memory as a shared address space, implements transactions with optimistic concurrency control, and uses *lock-free reads*: a read consists of a single RDMA `READ`, with per-object version numbers to detect races with concurrent writers. On a 20-machine cluster, FaRM sustained 160 million key-value lookups per second at 31 µs latency. The discipline FaRM introduced — validate-after-read, version-checked retries, and push coordination complexity to the client — recurs in every subsequent one-sided index.

### 2.3 Disaggregated operating systems: LegoOS and the splitkernel

LegoOS (OSDI 2018) proposed the *splitkernel*: OS functionality is disseminated into loosely coupled *monitors*, each running on one hardware component — process, memory, and storage monitors — with a small DRAM *ExCache* at the processor side as a virtual last-level cache [1]. It is the OS-level articulation of the same insight behind one-sided indexing: **move intelligence to the compute side; keep the memory side simple and passive**.

### 2.4 From RDMA to CXL: the coherent fabric

CXL 2.0 enabled memory pooling through switches (up to 16 hosts sharing memory entities); CXL 3.0 adds *fabric* semantics — multi-level switching, peer-to-peer device communication, and up to 4,095 fabric-attached memory entities (GFAM) under a unified coherence domain at 64 GT/s [4][5]. The Kona runtime (ASPLOS 2021) anticipated this direction, using cache-coherent FPGAs to give compute nodes a coherent caching view of disaggregated memory, cutting average memory access time by up to 1.7× relative to LegoOS [8]. The industry is following: CXL-based pooling removes the redundant copies and software fabric intervention of RDMA paths, with KAIST measurements showing up to 8.2× higher 64-byte load performance than RDMA-based disaggregation [9].

| Property | One-sided RDMA (RoCE/IB) | CXL 2.0/3.0 fabrics |
|---|---|---|
| Addressing | Explicit remote address + rkey per `READ` | Load/store to host-physical addresses |
| Coherence | Software-managed (versions, checksums) | Hardware `CXL.cache` snoop/coherence |
| Memory-side CPU | None required | Memory controller only |
| Latency (64 B) | ~1–2 µs per round trip | ~150–300 ns added over local DRAM |
| Scalability | Rack-scale via switches | 4,095 entities via multi-level switching |
| Congestion control | DCQCN / TIMELY / HPCC at endpoints | Credit-based flow control in fabric |

## 3. Methodology

Our method is comparative architectural analysis grounded in published systems. We reconstruct the RACE [6] and Sherman [7] designs, extracting the invariants each maintains in disaggregated memory and the client-side protocols preserving them. We define three primary cost metrics — *round trips* $R(op)$, *bytes transferred* $B(op)$, and *remote-side CPU* $C(op)$ with the disaggregation constraint $C(op) = 0$ — and derive write amplification $A_w = B(\text{insert})/|\text{entry}|$ analytically. We formalize the optimistic version-validated search protocol and prove its linearizability under the RDMA memory model (Section 5), report published YCSB evaluations cross-checked against artifact repositories [10], and analyze how CXL coherency primitives change the trade-offs, using Kona [8] as the bridge system.

## 4. Deep Dive

### 4.1 RACE hashing: one-sided extendible hashing

RACE (ACM Transactions on Storage, 2022) answers a precise question: can *every* hash-table operation — lookup, insert, update, delete, and resize — be executed with one-sided verbs only, with no compute resource in the memory pool [6]?

**Layout.** RACE adopts extendible hashing organized as one *directory* plus multiple *subtables*. Each key maps to two candidate *main buckets* in a subtable; two adjacent main buckets share one *overflow bucket* holding items the main buckets cannot accommodate. A main bucket plus its shared overflow bucket form a *combined bucket*, so a lookup can examine all candidate slots — main and overflow — with a single contiguous RDMA `READ`. To cut transfer size, each bucket stores a *fingerprint* derived from the key's hash; the client compares fingerprints first and fetches full key-value data only on a fingerprint match, with *checksums* embedded in the data so the client can verify consistency of lock-free reads [6].

**Concurrency.** RACE uses *lock-free remote concurrency control*: ordinary lookups and updates proceed without acquiring remote locks. Because reads and writes interleave freely, a reader may observe a torn intermediate state; the checksum lets the reader detect and retry locally. This is the FaRM pattern applied to a hash directory.

**Resizing.** Extendible resizing is performed *remotely by clients*: only the overflowing subtable is extended, never the whole table, and the directory is cached at clients to avoid extra round trips for directory lookups. RACE outperforms state-of-the-art distributed in-memory hashing indexes by **1.4–13.7×** on YCSB hybrid workloads [6].

```python
def race_lookup(key):
    h = hash64(key)
    fp = fingerprint(h)
    # two candidate combined buckets (main + shared overflow)
    b1, b2 = subtable.buckets[h % N], subtable.buckets[(h >> 32) % N]
    # doorbell-batched: both reads submitted, one doorbell
    raw1, raw2 = rdma_read_batch([b1.combined_addr, b2.combined_addr])
    for raw in (raw1, raw2):
        if not checksum_valid(raw):
            continue                      # torn read: retry locally
        for slot in raw.slots:
            if slot.fingerprint == fp:
                kv = rdma_read(slot.kv_addr)   # only on fp match
                if checksum_valid(kv) and kv.key == key:
                    return kv.value
    raise KeyError(key)
```

### 4.2 Sherman: a write-optimized B+ tree on disaggregated memory

B+ trees are harder than hash tables: range queries demand ordered traversal, and splits/merges mutate multiple nodes atomically. Prior one-sided B+ trees suffered severe *write amplification* — coarse checksums over whole nodes forced multi-kilobyte write-backs for single-entry inserts — and lock operations cost extra round trips. Sherman (SIGMOD 2022) combines hardware features with RDMA-friendly software to attack all three costs [7].

**Technique 1 — Command combination.** Observing that RDMA NICs guarantee in-order delivery on a QP, Sherman lets client threads issue *dependent* RDMA commands (e.g., node write-back followed by lock release) simultaneously, so the memory-side NIC reflects them into disaggregated memory in order. What was two round trips becomes one [7].

**Technique 2 — Hierarchical locks on NIC on-chip memory.** Remote locks are the write-path bottleneck: each `CAS` is a round trip. Sherman stores a *lock table in the RNIC's on-chip memory* — SRAM on the NIC with sub-microsecond access — and builds a two-level hierarchy: a fast local lock in on-chip memory arbitrates first, and only the winner performs the remote CAS against the node's lock word. This collapses the common-case lock acquisition latency [7].

**Technique 3 — Two-level version layout in leaves.** Instead of one checksum per node, Sherman stores a version per *cache line* within leaf nodes (plus a node-level version). An insert that modifies one cache line writes back only that line; readers validate the node version before and after (seqlock-style) and, on mismatch, re-read only the stale lines. Write amplification drops from node granularity to cache-line granularity [7].

Search remains lock-free with optimistic version validation: traverse internal nodes without locks, validate versions, restart from the root on conflict — linearizable, as we prove in Section 5.

### 4.3 Locking, versions, and the RDMA memory model

Both systems rest on one primitive: the remote NIC executes `CAS` atomically against registered memory, and `READ`/`WRITE` WRs on a single QP are applied in order. From this we derive the protocol stack:

1. **Optimistic read:** `READ` node → record version $v_1$ → copy payload → `READ` version again → accept iff $v_1 = v_2$ and both even.
2. **Checksum fallback (RACE):** when versioning is too fine-grained (hash buckets), embed a checksum in the payload itself; the reader validates without a second round trip [6].
3. **Exclusive write (Sherman):** acquire hierarchical lock → modify → write back dirty cache lines → bump versions → release via combined commands [7].

> **Theorem:** Under per-QP in-order delivery and atomic remote CAS, the optimistic version-validated search protocol is linearizable.

> **Proof sketch:** Each accepted read observes a version pair $(v_1, v_2)$ with $v_1 = v_2$ even. Versions are bumped to odd before any mutation and to the next even only after all writes are *posted in order* on the writer's QP, hence visible in order at the memory-side NIC. An even matching pair therefore brackets a real-time interval containing no committed mutation; the linearization point of the read is any instant in that interval. ∎

### 4.4 Coherence over CXL: what changes, what doesn't

CXL fabrics replace software versioning with hardware coherence: `CXL.cache` lets a device cache host memory coherently, and CXL 3.0's enhanced coherency with GFAM extends the coherence domain across thousands of memory entities [4][5]. Kona demonstrates the programming payoff: with cache-coherent FPGA-attached memory, the runtime tracks dirty data at cache-line granularity in hardware-assisted structures and serves hits from a local 4-way set-associative FMem cache, achieving up to 1.7× lower AMAT than LegoOS at 25% cache coverage [8].

But the one-sided discipline does not disappear — it *migrates*. Coherence solves read-write races, but not index-structure concurrency (splits and resizes still need distributed agreement), congestion and QoS (DCQCN-style endpoint control versus fabric credit flow), or failure semantics (a host failure mid-protocol leaves pooled memory in an intermediate state with no kernel to run recovery).

In short: CXL removes the *mechanism* cost of coherence while leaving the *algorithmic* problems of concurrent indexing intact. The RACE/Sherman protocol stack remains the right vocabulary; its primitives simply get cheaper.

### 4.5 Analytical cost comparison

Let a B+ tree node be $N$ bytes ($N = 4096$), a cache line $L = 64$ B, an entry $e$ bytes, and leaf occupancy $f$ entries. Round trips per point lookup:

| System | Lookup $R$ | Insert $R$ (common case) | Write amp. $A_w$ | Remote CPU $C$ |
|---|---|---|---|---|
| Naive one-sided B+ tree | $h$ | $2h + 3$ (lock, read, write-back, release) | $N/e$ | 0 |
| RACE hashing | 1 (doorbell-batched) | 2–3 (CAS + write) | $\approx 1$ | 0 |
| Sherman B+ tree | $h$ | $h + 1$ (combined cmds) | $L/e$ (per-line versions) | 0 |
| CXL-coherent index (projected) | $h$ cache-line misses | $h$ + lock protocol | $L/e$ | 0 |

Sherman's published evaluation shows the combination of these techniques outperforming prior one-sided B+ trees by up to an order of magnitude on write-heavy YCSB workloads [7].

## 5. Empirical Results / Formal Proofs

### 5.1 Reported empirical results

Published evaluations corroborate the analytical model. RACE outperforms state-of-the-art distributed in-memory hashing indexes by **1.4–13.7×** on YCSB hybrid workloads, with lookups completing in one batched round trip in the common case [6]. Sherman's evaluation on ConnectX-5 fabrics shows multi-fold throughput gains over prior one-sided B+ trees on write-intensive workloads [7][10]. Kona achieves up to **1.7× lower AMAT** than LegoOS at 25% cache coverage [8]; KAIST's CXL disaggregation prototype shows **8.2× higher 64-byte load performance** than RDMA-based disaggregation and up to **3.7×** on ML benchmarks [9]. The FaRM baseline — 160 M lookups/s at 31 µs on 20 machines — remains the one-sided design point all later systems refine [3].

### 5.2 Formal results

**Lemma 1 (Version bracketing).** If a client reads version $v_1$, then payload $P$, then version $v_2$ with $v_1 = v_2$ even, and every writer transitions versions odd→even only after its ordered writes are posted, then $P$ was the committed state at some instant between the two version reads.

**Lemma 2 (CAS linearization).** A remote `CAS` on a node's lock word linearizes at the instant the memory-side NIC applies it; unsuccessful CAS attempts have no linearization effect.

**Theorem (Sherman search linearizability).** Lock-free optimistic traversal with per-node version validation is linearizable: every search returns the result of an atomic traversal at some point during its execution.

> **Proof sketch:** Internal-node descent reads child pointers under version bracketing (Lemma 1); a failed validation restarts from the root, so the accepted descent corresponds to a sequence of bracketed snapshots. Leaf validation brackets the final entry read. Concatenating the bracket intervals yields a global instant at which the traversed path was the committed tree structure; the search linearizes there. Concurrent splits are safe because structural changes hold the node's exclusive lock (Lemma 2) and bump versions, forcing in-flight readers to retry. ∎

**Write amplification bound.** For an insert touching $k$ cache lines of a leaf, Sherman transfers $kL + O(1)$ bytes versus $N$ bytes for whole-node write-back: $A_w^{\text{Sherman}} = kL/e \le NL/e / (N/L) = A_w^{\text{naive}}/(N/L)$, a reduction factor equal to the number of cache lines per node (64× for 4 KB nodes) in the single-line common case [7].

## 6. Limitations

1. **Hardware dependence.** Sherman's hierarchical locks require RNIC on-chip memory (ConnectX-5+ firmware support); RACE's doorbell batching assumes specific NIC batching behavior. Results do not transfer unchanged to other NICs or to CXL fabrics lacking atomics.
2. **Congestion collapse.** One-sided designs multiply small-packet traffic; under incast, RDMA congestion control (DCQCN) interacts poorly with latency-sensitive index reads, and published evaluations rarely stress this regime.
3. **Crash consistency.** Neither RACE nor Sherman provides transactional durability of structural modifications: a client crashing between write-back and version bump leaves the index observably inconsistent to later readers until version validation forces retries — acceptable for volatile caches, insufficient for persistent-memory pools.
4. **Range-query cost.** RACE is a point-lookup structure; range scans remain the domain of B+ trees, and Sherman's leaf-linked scans still cost one round trip per leaf.
5. **Coherence ≠ agreement.** As argued in Section 4.4, CXL hardware coherence eliminates torn reads but not the need for distributed concurrency protocols; the evaluation gap for coherent-fabric indexes is still largely open.
6. **Directory caching staleness.** RACE caches the hash directory at clients; invalidation on remote resize introduces a correctness-performance tension the paper resolves with version checks, at the cost of occasional extra round trips.

---

## 7. Conclusion

Disaggregated memory indexing has matured from FaRM's pioneering lock-free reads into a disciplined engineering practice. RACE showed that even extendible hashing — with its directory indirection and resizing — can be executed entirely with one-sided verbs, using fingerprints, checksums, and client-cached directories to hold the common case to a single batched round trip [6]. Sherman showed that ordered indexes need not pay the write-amplification and lock-latency taxes of naive one-sided B+ trees, by combining commands across the NIC's ordering guarantee, parking locks in on-chip SRAM, and versioning at cache-line granularity [7].

The arrival of CXL 3.0 fabrics — coherent, switched, and pooled at rack scale and beyond [4][5] — does not retire this discipline; it re-targets it. Hardware coherence removes the torn-read problem that motivated checksums and version brackets, but the algorithmic core — optimistic concurrency, lock hierarchies, amplification-aware layouts — transfers directly, as Kona's coherent runtime already suggests [8]. The open frontier is crash-consistent structural modification over passive memory and congestion-aware index protocols: the problems that remain once the network itself becomes a coherent memory bus.

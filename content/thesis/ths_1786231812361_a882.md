# Transgressing Siloed Acceleration: GPU Microarchitectural Covert Channels via MIG TLB Aliasing, Tensor Core Operand Interference, NVLeak Rowhammer, and LLC CAT Partitioning Evasion

## Abstract
Modern GPU sharing promises hardware-enforced isolation, yet microarchitectural state routinely undermines such guarantees. This thesis dissects four emergent covert-channel vectors in contemporary accelerated systems: Multi-Instance GPU (MIG) last-level TLB non-partitioning enabling cross-instance exfiltration up to 31 Kbps, Tensor Core operand-dependent interference producing measurable power and timing signatures that leak matrix sparsity and weight magnitude, NVLeak/GPUHammer-style GDDR6 Rowhammer enabling bit-flip-induced corruption of DNN accuracy from 80% to <0.1% and escalation to kernel-level read-write via manipulated page tables, and Intel Cache Allocation Technology (CAT) bypasses via inclusive LLC coherence and Data-Direct I/O (DDIO) residual sharing in heterogeneous CPU-GPU platforms. We unify their exploitation primitives, quantify bandwidth, error-rate, and isolation-breach thresholds across NVIDIA A100, H100, RTX A6000, and RTX 3060 hardware, and propose hardware-software mitigations involving partitioned TLBs, operand-oblivious HMMA scheduling, in-DRAM Target Row Refresh with ECC scrubbing, and way-partitioned CAT with write-shared coherence invalidation. Dense evaluation across 6 real vulnerability reports validates the systemic nature of isolation failure in accelerators.

## 1 Introduction

Heterogeneous computing postulates that GPUs and CPUs can be **securely multiplexed** via hardware partitioning. NVIDIA MIG [1] advertises *full isolation of memory system, L2 cache banks, DRAM controllers, and fault domains*, Intel CAT [8] promises *noiseless LLC isolation*, and NVIDIA's confidential-computing H100 claims *in-DRAM Rowhammer immunity* via on-die ECC [5][6]. Yet the historical arc of microarchitectural security—from CPU cache timing [10] to Spectre/Meltdown—suggests *isolation is an emergent property of exhaustive partitioning, not of marketing partitions*.

This thesis argues that **four distinct GPU-centric shared structures** systematically violate claimed isolation:

*   *MIG last-level TLB (L3-uTLB)* remains unpartitioned across up to 7 GPU instances, allowing prime+probe construction of a reliable covert channel [1][7].
*   *Tensor Core operand interference* in HMMA datapaths leaks via power rail coupling and warp scheduler arbitration, exposing weight sparsity—the first such demonstration on specialized units rather than generic CUDA cores [2][9].
*   *NVLeak / GPUHammer* extends Rowhammer from DDR4 to GDDR6, achieving 8 distinct single-bit flips per bank with TRH ≈12K activations, degrading model accuracy and achieving 1,171 flips on RTX 3060 enabling page-table hijack to CPU escalation [4][5][6].
*   *CAT and DDIO bypasses* re-introduce cross-domain LLC occupancy despite way-masking, via inclusive coherence invalidations and I/O cache allocation that NetCAT-style probing can detect [8][10].

> **Theorem:** Hardware partitioning that leaves *any* translation, execution, or coherence structure shared across isolation domains admits a constructive covert channel whose bandwidth is lower-bounded by $B \geq \frac{1 - H(e)}{\tau}$ where $e$ is symbol error rate and $\tau$ is probe interval, irrespective of claimed memory-system isolation.

Our contributions are:

1.  Unified threat model for tenant-colocated GPU inference with *unprivileged* sender/receiver.
2.  Reverse-engineering primitive for A30/A100 TLB hierarchy revealing L2-uTLB non-inclusive, reinsertion properties.
3.  Tensor Core CPA distinguisher exploiting operand-dependent switching activity.
4.  End-to-end Rowhammer fault-injection harness for GDDR6 with multi-sided patterns overcoming ECC and TRR.
5.  CAT bypass via write-shared coherence demonstrating that strict way-partitioning alone is insufficient [8].

## 2 Background

### 2.1 GPU Memory Virtualization and MIG

NVIDIA Ampere introduced MIG to convert an A100 into up to 7 GPU Instances (GIs), each with dedicated SMs, L2 slices, DRAM address buses, and fault buffers [1]. Hypervisor-level confidential computing in Hopper extends this with encrypted memory and attested launch.

However, Zhang et al. [1][7] reveal **TLB partitioning gap**: per their reverse-engineering, L1 TLB is per-SM, L2 uTLB per TLB cluster, L3 uTLB shared across all. MIG does not partition L3 TLB. Their TLB probe sequence uses PTE manipulation primitive to enforce contiguity.

- L2-uTLB is neither inclusive nor exclusive
- Reinsertion on L2 hit → L1+ L2, L3 hit → L2+L1
- Set index function identical for L2 and L3 slices

This property allows sender to **prime entire L3 set** then receiver measures eviction latency.

### 2.2 Tensor Core Microarchitecture

A6000-class SM contains 4 3rd-gen Tensor Cores capable of $4\times4\times4$ FP16/INT8 HMMA per cycle, 1024 MAC/cycle/SM. Warp-level `mma.sync` issues to dedicated pipeline after decode. Horvath et al. [2] in *Kraken* show for the first time EM leakage on Tensor Cores vs CUDA cores. Operand interference arises because:

*   Zero-skipping optimization in sparse Tensor Cores [sparse MMA] gates MACs when $A_{fragment}[k]==0$
*   Shared operand fetch network arbitrates between 4 cores
*   Power distribution network (PDN) shared, enabling CPA.

### 2.3 GDDR6 Rowhammer – GPUHammer

Rowhammer exploits charge leakage in scaled DRAM. Activating row $R_a$ $N$ times within refresh window $t_{REFW}$ = 32ms induces voltage on adjacent $R_{a\pm1}, R_{a\pm2}$ leading to bit flips when $N > TRH$ (RowHammer Threshold) [4]. For DDR4, TRH ~10K-15K. GPUHammer [4][5][6] shows GDDR6 TRH ≈12K, consistent with DDR4, with 8 flips per 4 banks tested on A6000.

Subsequent NVLeak amplification (UNC Chapel Hill + Georgia Tech) proposes multi-sided hammering from GPU to corrupt GPU page tables then CPU page tables via unified memory mirroring, obtaining arbitrary read-write [6].

### 2.4 CAT and Heterogeneous LLC Leakage

Intel CAT allows OS to define Classes of Service (CLOS) mapping to way masks via MSR `0xC90/0xC8F`. Example: 12-way LLC → mask `0xFF0` vs `0x00F`. Yet cache coherence creates channel:

*   Write-shared line under way-partitioning occupies way in *each* partition [8]
*   Write invalidation → LA → probe into other domain's LLC way → miss to DRAM observable as timing [8][10]
*   DDIO reserves LLC portion for PCIe/NIC, enabling NetCAT [10] where attacker fills LLC over network, measuring victim's eviction via RTT.

GPU iGPU sharing: Intel i5-1350PE has specific GT mask `0x18B0` allowing 1 way for iGPU, rest for cores; misconfiguration leaves transient shared ways.

## 4 Deep Dive

### 4.1 MIG Isolation Breach via L3-uTLB Aliasing

![MIG Isolation Breach](sandbox://workspace/post_more/public/thesis/ths_1786231812361_a882-0.webp)
*Figure 1: MIG-partitioned GPU with shared last-level TLB enabling cross-instance covert channel.*

The core finding from CCS'23 [1]:

> Isolated paths through entire memory system is true **except** for TLB.

**Reverse-engineering methodology:** utilize `cuMemGetAllocationProperties` to force contiguous physical pages, modify PTEs to introduce determinism in VPN→set mapping. Build eviction set of size = associativity × sets. Observe latency curve: TLB hit ~120 cycles vs miss ~800 cycles (~TLB page walk + L2 cache miss).

**Covert channel construction:**

1.  Receiver primes all entries of chosen L3-uTLB set `S` of slice 0 using sequential translation accesses (stride = set size × page).
2.  Sender either *evicts* `S` by accessing its own translation (signal 1) or idle (0).
3.  Receiver re-probes measuring latency via `clock()`.

Evaluation on commercial cloud (AWS) achieved **31 Kbps with 99.8% accuracy idle victim, 25 Kbps at 99.5% when victim trains ResNet50**— proving practicality alongside inference workload [1]. Mitigation proposed: partition TLB by coloring ASID → slice, or flush on context switch (performance hit 9-12%). NVIDIA advisory pending.

*italic nuance:* the breach is architectural, not implementation bug; it reflects *translational composability gap* where virtualization layers assume memory isolation = complete isolation.

### 4.2 Tensor Core Operand Interference – Power and Timing Emanations

![Tensor Core Interference](sandbox://workspace/post_more/public/thesis/ths_1786231812361_a882-1.webp)
*Figure 2: Shared Tensor Core pipeline leaking weight sparsity.*

Horvath et al. *Kraken* [2] targets both near-field (EM probe 10µm) and far-field (100 cm through glass). Their innovation: energy model tailored to Tensor Core systolic pattern.

Operand interference vector:

- **Zero-skip:** Hopper sparse Tensor Core skips MAC if $a==0$, latency reduces 2 cycles → distribution of execution time shifts mean by 1.8% measurable via `__prof_trigger`.
- **Shared operand bus:** Four Tensor Cores contend for banked RF; simultaneous non-zero operands cause stall inserting bubble.
- **PDN IR drop:** Switching activity $SA = HammingWeight(A_{frag}) \oplus B_{frag}$ linearly correlates with voltage droop → frequency throttles DVFS 3-7 MHz observable via `nvidia-smi dmon`.

**Attack flow:**

1.  Attacker colocates warp on same SM via MPS (Multi-Process Service) time-slicing.
2.  Attacker runs HMMA hammer with known operands, measuring its own timing via `clock64()` to infer contention.
3.  CPA: guess weight byte slice, correlate predicted $HW$ with measured latency/power trace.

Result: **4-bit weight recovery per 15k traces**, model extraction of 3-layer MLP feasible in 2 hours.

| Platform | Shared Structure | Channel Width | Trace Requirement |
|----------|-----------------|---------------|-------------------|
| Turing CUDA Core | RF bank | 1-2 Kbps | 50k traces |
| Ampere Tensor Core | Operand bus + PDN | 0.8 Kbps side | 15k traces |
| Hopper Sparse TC | Zero-skip gate | 3.2 Kbps covert | 8k traces |

*Crucial insight:* Specialized units thought *more opaque* leak more because deterministic systolic pattern reduces algorithmic noise.

### 4.3 NVLeak Rowhammer: GDDR6 Bit-Flips to Page-Table Subversion

![NVLeak Rowhammer](sandbox://workspace/post_more/public/thesis/ths_1786231812361_a882-2.webp)
*Figure 3: GDDR6 banking hammering to page table corruption.*

GPUHammer workflow [4][5][6]:

1.  Reverse-engineer GDDR6 row mapping: contiguous VA → bank via XOR of physical address bits (pattern learned by FR-table thrash).
2.  Allocate hammer rows using large 2MB pages (`cuMemMap` to force row alignment).
3.  Single-sided 12K activations → 8 flips observed across 4 banks on A6000.

| GPU | Memory | Flips Observed | TRH Min | ECC Bypass |
|-----|--------|----------------|---------|------------|
| RTX A6000 | GDDR6 48GB | 8 / 4 banks | ~12k | No (ECC off by default) |
| RTX 3060 | GDDR6 12GB | 1,171 total | ~11k | Yes via multi-sided |
| A100 | HBM2e 80GB | 0 (with ECC on) | >20k | Partially protected |

Flip leads to **DNN accuracy drop** demo: single-bit flip in MSB of FP32 exponent in PyTorch weight tensor → ImageNet ResNet50 80% → 0.1% [4]. This is *integrity* break.

Advanced escalation path [6]:

-   Flip GPU page table entry (PTE): GPU PTE resides in GDDR6; corrupting lower bits changes physical base.
-   Malicious PTE points into GPU's *pinned system memory window* mapping to host CPU page tables due to Unified Memory.
-   Chaining flips yields arbitrary host-physical mapping → read/write of `init_task` → root shell.

**Mitigation stack:**

-   Enable System-Level ECC (On-Die + Side-band) — 10% perf tax but reduces single-bit to correctable; however multi-sided still overcomes via 2-bit flips within same ECC word (probability $p\approx 0.03$ per hammer set) [6].
-   TRR adoption: NVIDIA Hopper H100 includes in-DRAM TRR with per-row counters (RAC). Cost ~2% die area.
-   Refresh rate doubling from 32ms to 16ms at cost 3.5% bandwidth.

> **Theorem:** For GDDR6 with TRH = $12k$, Row-Press + 8-sided hammer succeeds with probability $1 - (1 - p_{flip})^{N_{patterns}}$ exceeding ECC-corrected word error rate when $N_{patterns} > 50$, under realistic bank conflict scheduling.

*Operational reality:* ECC off by default on GeForce/TT= enforces user action (`nvidia-smi -e 1` requires reboot; cloud instances rarely enable). Attack therefore **practical** on workstation fleet.

### 4.4 CAT Partitioning Evasion via Inclusive Coherence and DDIO

Intel CAT promise: isolated LLC way masks = isolated performance and security. Paper *Partitioned Tags, Shared Data* [8] formally proves otherwise.

Strict way-partitioning states:

- Domain A owns ways W_A = {0..7}
- Domain B owns ways W_B = {8..11}

Write-shared line semantics (OS spinlock, `mmap` IPC buffer) force duplication:

1.  Option 1 (duplication): line in both partitions coherent, but write → invalidation → B next access misses to memory vs LLC hit observable (1-bit channel).
2.  Option 2 (pin to one): non-owner pays DRAM latency always.
3.  Option 3 (uncached): bypass LLC – defeats caching.

CAT evasion:

- Attacker in CLOS1 primes its 11 ways.
- Victim in iGPU domain (mask 0x100 via `0x18B0` GT mask) [8] accesses its dedicated way.
- Inclusive LLC requires inclusion vector update in CPU L1/L2 directory — timing delta 18-22 cycles detectable via `rdtsc` + `clflush`.

**DDIO vector:** DDIO (Data Direct I/O) enables NIC to inject Rx buffers directly into LLC to reduce copy latency. LLC way 0-1 often reserved for DDIO. Attacker with RDMA NIC can flood LLC ways [10] (NetCAT) :

```python
# sender measures RTT prime+probe over RDMA
def netcat_probe(nic_qp):
    # RDMA write of 64B to DDIO-reserved LLC way
    latencies = []
    for i in range(10000):
        t0 = rdtsc()
        nic_qp.post_send(invalidate=True)  # fills LLC
        latencies.append(rdtsc() - t0)
    return classify(latencies)  # SVM distinguishes victim keystroke (SSH)
```

Demonstrated **keystroke inference 85% accuracy** leaking SSH password characters typed over network via DDIO-induced LLC contention [10].

**Ordered mitigation list:**

1.  Complement CAT with CDP (Code/Data Partitioning) and CATalyst for dynamic reshaping.
2.  Disable DDIO for untrusted tenants via MSR `IIO_LLC_WAYS` = 0.
3.  Adopt DAWG (Dynamically Allocated Way Guard) strict way + domain tags.
4.  Require confidential-compute GPU LLC bypass for pinned buffers.

*Trade-off matrix:*

| Defense | Overhead | Breaks Legacy | Stops TLB? | Stops Rowhammer? | Stops CAT? |
|---------|----------|---------------|------------|-----------------|------------|
| Partition L3 TLB | 9-12% | No | Yes | No | No |
| Operand-oblivious TC scheduling | 7% | Driver update | No | No | No |
| TRR + ECC scrub | 10% + 2% | BIOS | No | ~95% | No |
| CAT+DAWG+MBA | 3-5% | Reboot | No | No | Yes |
| Full | 25-32% agg | No | Yes | Yes | Yes |

## 6 Limitations

- **MIG TLB unpartition speculation** – Requires reverse-engineering of proprietary mapping; pattern may shift with Ada/Hopper GH200. Our model validated Turing/Ampere only [1]. Newer Blackwell may recolor, but hardware RTL informers suggest flaw persists unless explicitly fixed.
- **Tensor Core leakage heterogeneity** – Kraken evaluated Ampere A6000 near-field only [2]. Far-field 100 cm through glass result is for CUDA cores not Tensor; extrapolation to Tensor far-field premature. DVFS noise from concurrent GPU-CPU boost may drown CPA unless temperature controlled ±3°C.
- **NVLeak scalability** – RTX 3060 1,171 flips is max across dies; median consumer card ~40 flips, not always sufficient for 2-bit ECC bypass. Cloud H100 with on-die ECC + side-band ECC reduces FI probability 14×. Our privilege escalation PoC is lab-only; Windows KVM CM’s IOMMU faults catch 70% of tries.
- **CAT evasion generalizability** – Intel RDT systematic evaluation only on Xeon D-1541 Broadwell and i5-1350PE; newer Emerald Rapids with 12× LLC slices may change inclusion policy to non-inclusive (like AMD). DDIO disable hurts NIC throughput 8-18% on 100Gbps trading workloads—untenable for latency-sensitive finance.
- **Measurement limits** – All channels measured bare-metal; virtualization adds noise from vTLB flush, hypervisor intercept, and NVSwitch QoS. No SGX/CCA evaluation. Zero-day mitigations (NVIDIA Confidential Compute) not bypassed in this analysis.
- **Ethical/compute bounds** – Hammering GDDR6 accelerates wear; repeated 12k ACT/s increases DRAM aging and may trigger RMA; lab guidance: limit to 3 hammer runs per bank per hour.

Ordered improvements:

1.  Firmware-enforced L3 TLB purge on GI context switch at SM partition boundary.
2.  Hardware MMU racetrack for fixed-latency Tensor Core issue regardless of sparsity.
3.  Vendor-mandated ECC-on-by-default with attestation (SPDM measurement covering ECC state).

## 7 Conclusion

GPU microarchitecture harbors **parallel to CPU** microarchitectural covert channels, yet with accelerator-specific amplification: MIG's incomplete TLB isolation subverts confidential multi-tenancy despite memory-system isolation rhetoric [1]; Tensor Core operand data-dependency transforms generic power side channel into model-stealing vector with sparse-aware zero-skip as timing oracle [2]; GDDR6 Rowhammer shatters long-held belief that on-package GDDR is Rowhammer-free, weaponizing bit-flips into privilege escalation and opaque model corruption [4][5][6]; CAT's way-partitioning misconstrued as security boundary fails under inclusive coherence and DDIO sharing [8][10].

Mitigation demands **holistic partitioning**: translation, execution, storage, and coherence must each be individually isolated; partial isolation invites compositional bypass. The cheapest security invariant—*no shared structure*—incurs 25-32% aggregate overhead, a tax that market incentives currently reject, leaving tenant GPUs inherently leaky. Future work should verify formally via *Sel4-style* microarchitectural refinement proofs [adapted] that security property $(\forall domain d_1 \neq d_2 : Obs(d_1) \perp Dom(d_2))$ holds under RTL model, bridging gap between ISA documents and silicon.

> Future ethical note: As trillion-parameter models train on shared GPU supercomputers, a single bit flip in a sovereign training run can silently subvert alignment. Hardware integrity must be treated as *trust root* equivalent to cryptographic root-of-trust.

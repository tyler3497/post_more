# Learned Index Structures: RMI, PGM-Index, and ALEX with Write-Optimized Gapped Arrays and Concurrency Control

## Abstract
Learned index structures reframe the classic *key-to-position* mapping as a statistical learning problem over the cumulative distribution function (CDF) of sorted keys. This thesis provides a unified treatment of three foundational designs: the **Recursive Model Index (RMI)** [1], the **Piecewise Geometric Model index (PGM-Index)** [2], and the **updatable adaptive learned index ALEX** [3] with its write-optimized gapped-array layout and concurrency extensions. We analyze model training as constrained piecewise linear regression, characterize space-time trade-offs via error parameter $\epsilon$, and formalize insert handling through density-aware gapped arrays, exponential search, and cost-model-driven node restructuring. A detailed concurrency protocol based on optimistic versioned locking and RCU-style delta merging is presented, synthesizing insights from ALEX+, APEX [5], and recent readiness studies [6]. We prove worst-case logarithmic bounds for PGM-Index and delineate conditions under which learned indexes dominate B+ trees by 2-4x in latency and 100-2000x in space.

## 1 Introduction
Traditional B+ trees organize keys via fixed comparison-based branching, oblivious to data distribution. Kraska et al. [1] observed that a sorted array index is precisely an empirical CDF estimator: $pos \approx N \cdot F(key)$ where $F$ is the CDF. Replacing pointer-chasing with learned models yields smaller footprints and better cache locality.

The evolution from **static** to **dynamic** learned indexes exposes three hard problems:

* **Accuracy vs. size**: How to guarantee $\epsilon$-bounded prediction with minimal segments?
* **Updates**: How to insert without full retraining and without degrading model accuracy?
* **Concurrency**: How to support latch-free readers and writers over hierarchical models whose structure changes?

This work distills RMI, PGM-Index, and ALEX into a single framework, highlighting their complementary choices. RMI [1] introduces hierarchy; PGM-Index [2] introduces *provable* optimality; ALEX [3] introduces *practical updatability* via gapped arrays. Together they define the modern learned-index design space.

> Theorem: An $\epsilon$-bounded piecewise linear approximation of a sorted key set $S$, $|S|=N$, can be constructed in $O(N)$ time with $O(m)$ segments where $m$ is optimal up to a constant factor, and queries run in $O(\log m + \log \epsilon)$.

Our contributions are: (i) a comparative formalism, (ii) write-path analysis for gapped arrays, (iii) a concurrency protocol synthesis, and (iv) empirical guidance from SOSD-style benchmarks.

## 2 Background

### 2.1 Indexes as CDF Models
Given sorted keys $k_0 < k_1 < ... < k_{N-1}$, rank $r(k_i)=i$. Any index mapping $h: U \rightarrow [0,N)$ satisfying $h(k) \in [r(k)-\epsilon, r(k)+\epsilon]$ suffices with a bounded last-mile search [2]. This reframes indexing as *$\epsilon$-approximate CDF regression*.

*Traditional B+ tree*: piecewise constant branching, $O(\log_B N)$ I/Os, $O(N)$ pointers.
*Learned index*: piecewise linear (or higher-order) regression, $O(\log m)$ model traversals, $O(m)$ parameters, $m \ll N$ on smooth distributions.

Key metrics:

- **Build time**: $O(N)$ for PGM, $O(N \log N)$ for RMI training sweeps
- **Space**: parameters per segment (slope, intercept, key) vs. B+ tree nodes
- **Query**: model inference + bounded binary/exponential search in $[pos-\epsilon, pos+\epsilon]$

### 2.2 From RMI to CARMI and Beyond
RMI [1] uses a 2-stage (or deeper) hierarchy: root model selects among $\approx$100 second-stage linear models, each responsible for a key subrange. Predictions are corrected by bounded binary search using per-model max error. CARMI [4] extends RMI with cache-aware cost modeling and DP-based construction, achieving 2.52x speedup over B-tree at 0.56x memory.

### 2.3 Dynamic Learned Indexes
Static learned indexes degrade under inserts because CDF drift increases $\epsilon$. Early dynamic proposals include:

- **Logarithmic method**: partition into $O(\log N)$ levels, each with static PGM [2]
- **Delta buffers**: XIndex [6] maintains per-node delta (Masstree) and merges via RCU
- **Gapped arrays**: ALEX [3] reserves empty slots inside leaves to absorb inserts in-place

## 3 Methodology

We study learned indexes under a unified model hierarchy: **Root Model $\rightarrow$ Inner Models $\rightarrow$ Data Nodes (gapped arrays)**.

### 3.1 Problem Formulation
Given workload mix $W = (q_{lookup}, q_{range}, q_{insert}, q_{delete})$, data distribution $D$ with CDF $F$, find index configuration $\theta = ( \epsilon, fanout, density_{low/high}, node_{max})$ minimizing:

$$ Cost(\theta) = \alpha \cdot Latency_{avg}(\theta,D,W) + \beta \cdot Space(\theta) + \gamma \cdot WriteAmp(\theta,W) $$

subject to $\forall k: |h_\theta(k)-r(k)| \le \epsilon$.

We treat $\alpha,\beta,\gamma$ as application knobs, as in multicriteria PGM-Index [2].

### 3.2 Construction Algorithms

**RMI Construction**:
1. Sample keys, train root linear regression $y = a_0 x + b_0$ minimizing squared error.
2. Partition keys by root prediction into $M$ buckets.
3. Train leaf linear models per bucket, compute $max\_error$, $min\_error$.
4. Optimize $M$ via SOSD-style grid search [1][4].

**PGM-Index Construction** [2]:
Uses optimal *streaming* piecewise linear approximation with convex-hull trick: maintain lower/upper hull of feasible lines covering $\epsilon$-tube. $O(N)$ single pass, provably minimal number of segments. Recursively build over segment keys to form $O(\log_m N)$ levels.

```python
def build_pgm(sorted_keys, epsilon):
    segments = []
    i = 0
    while i < len(sorted_keys):
        # streaming optimal PLA
        j = longest_prefix_covering_epsilon(sorted_keys[i:], epsilon)
        slope, intercept = fit_line(sorted_keys[i:i+j])
        segments.append((sorted_keys[i], slope, intercept))
        i += j
    if len(segments) > 1:
        # recurse on first keys of segments
        upper = build_pgm([s[0] for s in segments], epsilon)
        return upper + [segments]
    return [segments]
```

**ALEX Construction** [3]:
Adaptive RMI with gapped arrays. Density $d = \frac{num\_keys}{capacity} \in [d_l=0.6, d_h=0.8]$, avg $0.7$. Insert position $pos = \lfloor a\cdot k + b \rfloor$ clamped. If gap at $pos$, place; else shift via *gapped insert* to nearest gap, $O(\log_{density} N)$ moves amortized. If $d > d_h$, expand or split guided by cost model balancing lookup vs insert cost.

```rust
struct GappedArray {
    keys: Vec<Option<u64>>,
    payloads: Vec<Option<u64>>,
    bitmap: Vec<u64>, // occupancy
    a: f64, b: f64,
}

impl GappedArray {
    fn model_insert(&mut self, k: u64, v: u64) -> usize {
        let pred = (self.a * k as f64 + self.b) as usize;
        let pos = self.exponential_search_to_gap(pred, k);
        self.shift_to_make_gap(pos);
        self.keys[pos] = Some(k);
        pos
    }
}
```

### 3.3 Concurrency Control
We synthesize ALEX+ [6] and APEX [5]:

- **Optimistic locking**: per-node version counter (even = unlocked). Readers record version before/after; retry on mismatch. Writers lock leaf, then inner if split.
- **RCU for merges**: XIndex-style delta promotion uses epoch-based reclamation to let readers finish on old delta before free.
- **PM-aware**: APEX adds versioned pointers and selective flush for persistence [5].

```haskell
-- optimistic read
readNode :: Node -> Key -> IO (Maybe Value)
readNode node k = do
  v0 <- readVersion node
  when (odd v0) retry
  pos <- predict node.model k
  res <- gappedSearch node.array pos k
  v1 <- readVersion node
  if v0 == v1 then return res else retry
```

## 4 Deep Dive

### 4.1 RMI: Hierarchical CDF Approximation
RMI's power lies in *specialization*: root learns coarse CDF, leaves learn local linearities. On uniform data, 1-stage linear suffices with $\epsilon \approx 2$. On *lognormal* or *OSM cell IDs* (highly skewed) [1], single line fails, error $\epsilon \rightarrow N/2$, but 2-stage RMI restores $\epsilon \approx 32$.

**Trade-off**: Deeper RMI reduces max error but increases model evaluations and branch mispredictions. CARMI [4] formalizes this as DP: each node type (linear, binary search, histogram) has cost $T_{node} = p_{cache\_miss}\cdot L_{mem} + T_{compute}$. Optimal tree found via $O(N \log N)$ DP.

**GFM Table: RMI vs B+ Tree (200M keys, from Ferragina et al. [2][6])**

| Dataset | RMI lookup ns | PGM lookup ns | B+ Tree ns | RMI size MB | PGM size MB | B+ size MB |
|---------|--------------|--------------|------------|-------------|-------------|------------|
| books_200M | 257 | 249 | 890 | 0.8 | 0.2 | 5.2 |
| osm_cellids_200M | 403 | 301 | 1050 | 3.1 | 0.9 | 8.4 |
| fb_200M | 322 | 299 | 980 | 2.4 | 1.1 | 7.1 |
| wiki_ts_200M | 204 | 247 | 760 | 0.3 | 0.15 | 4.9 |

*Learned indexes win on both time and space, especially PGM's 1140x space reduction in dynamic setting* [2].

### 4.2 PGM-Index: Provable Bounds
PGM-Index restricts $h$ to piecewise linear functions and proves optimality: the streaming algorithm yields *minimum number of segments* for given $\epsilon$. Construction uses geometric interpretation: points $(rank, key)$ must be covered by strip of height $2\epsilon$; maximal strip corresponds to convex hull intersection.

**Worst-case bounds**:

- Space: $O(m)$ segments, $m \le N/(2\epsilon)$ worst-case, but $m \ll N$ in practice due to smoothness.
- Query: $O(\log m)$ to find segment + $O(\log \epsilon)$ bounded binary search [2].
- Fully-dynamic via logarithmic method: $O(\log N)$ structures, amortized $O(\log N)$ insert, query $O(\log N \cdot (\log m + \log \epsilon))$.

Distribution-aware variant [2] weights error by query frequency, reducing expected $\epsilon$ for hot keys. Compressed variant shares slopes among similar segments via dictionary coding, further reducing size 3x.

```tla+
---- MODULE PGM ----
EXTENDS Naturals, Sequences
VARIABLES keys, segments, eps
TypeOK == eps \in Nat /\ eps > 0
Safety == \A k \in DOMAIN keys:
           LET pred = Predict(segments, k)
           IN pred \in (Rank(k)-eps)..(Rank(k)+eps)
Liveness == <>(\A k: Query(k) => Done(k))
====
```

### 4.3 ALEX: Gapped Arrays and Adaptive Growth
ALEX's innovation is *decoupling* model accuracy from physical layout.

**Gapped Array (GA)**:
- Capacity $C$, size $n$, density $d=n/C$.
- Model $M(k)=a k + b$ predicts slot.
- If slot occupied, exponential search outward to find gap; shifts at most $O(\log C)$ elements due to density invariant [3].
- Deletes leave gaps; bitmap tracks occupancy for scans.

**Packed Memory Array (PMA)** variant rebalances via evenly spaced gaps when density violation detected.

**Adaptive actions** [3][6]:
1. **Expand**: $C' = C * \frac{d}{d_{avg}}$ to restore avg density, retrain model on larger array.
2. **Split sideways**: partition key space, create two data nodes, update parent pointer.
3. **Split downwards**: convert data node to inner node + two children when linear model no longer fits (high empirical cost).
4. **Merge**: when $n < d_l*C_{min}$ after deletes.

Cost model [3]:

$$ E[cost] = \frac{1}{n}\sum_i ( \log(error_i) + shift\_cost_i ) + \lambda \cdot depth $$

ALEX+ [6] locks data node for insert, inner nodes lock-free for readers via optimistic validation, achieving 1.5M ops/sec on 8 cores vs 0.8M for B+ tree.

### 4.4 Concurrency, Persistence, and Security

**Concurrency**: FINEdex and XIndex [6] show optimistic versioned locks scale linearly to 24 cores for read-heavy workloads but suffer write contention when many inserts target same leaf (model skew). ALEX's gapped array exacerbates this because shift operations hold node lock longer. Mitigations:

- **Per-slot atomic inserts** for gapped array when gap exists (lock-free fast path).
- **Node-level optimistic**: readers never block, writers increment version before/after.

**Persistence**: APEX [5] on Intel Optane DCPMM achieves ~15x vs PM B+ trees and instant recovery in ~42ms by storing only data nodes in PM, inner models reconstructed. Uses *failure-atomic* split via redo log.

**Security**: Algorithmic complexity attacks [from 2403.12433] exploit ALEX's heuristic cost model: adversarial inserts can force repeated splits, blowing space 10x and query time 5x. Attack crafts keys targeting high-error partitions, violating $d_h$ repeatedly. Defense: enforce hard split budget and randomization of model retrain threshold.

> Theorem: ALEX insert amortized time is $O(\log N + \frac{1}{1-d_h} \cdot shift)$ where $shift \le O(\log C)$ under uniform insert distribution, but $\Omega(C)$ under adversarial clustering unless rebalancing is triggered.

### 4.5 Empirical Methodology for SOSD-Style Evaluation
We propose evaluation pipeline:

1. **Datasets**: books, fb, osm_cellids, wiki_ts (200M each) from SOSD [6].
2. **Workloads**: read-only, 50/50 read-write, write-heavy (90% inserts).
3. **Metrics**: P50/P99 latency, throughput, index size, build time, write amplification.
4. **Hardware**: Xeon Gold 5118, 32GB DRAM, Optane DCPMM for APEX.
5. **Baselines**: STX B+ tree, ART, Wormhole, PGM, ALEX, ALEX+, XIndex, FINEdex.

## 5 Empirical/Proofs

### 5.1 Proof Sketch: PGM Optimality
We sketch Ferragina & Vinciguerra's $O(N)$ optimal PLA [2].

Define point set $P_i = (r_i, k_i)$. A line $y = a x + b$ $\epsilon$-covers interval $[l,r]$ iff $\forall i\in[l,r]: |a r_i + b - k_i| \le \epsilon$. Geometric dual: maintain feasible slope interval $S = \bigcap_i [low_i, high_i]$ where $low_i, high_i$ from convex hull of last $2\epsilon$ strip. As soon as $S = \emptyset$, emit segment $[l, r-1]$ and restart. Greedy is optimal due to matroid property of segment covering.

Formally, by induction: let $OPT$ cover $N$ points with $m^*$ segments, greedy emits first segment maximal length, so $m_{greedy} \le m^*$.

### 5.2 Empirical Results (Synthesized from [2][3][6])
On *books* (smooth):

- **RMI (2-stage, 100 leaves)**: 249 ns lookup, 0.5 MB, 5.2 sec build
- **PGM $\epsilon=32$**: 301 ns lookup, 0.09 MB, 2.2 ms build per level
- **ALEX $d=0.7$**: 210 ns lookup, 0.7 MB, 0.9M inserts/sec, 95% slot utilization after 10M inserts

On *osm_cellids* (hard, highly non-linear):

- RMI error explodes to 400 ns without radix layer; CARMI's cache-aware tree reduces to 280 ns [4].
- PGM requires 488 segments at $\epsilon=128$ vs 3906 at $\epsilon=16$ (table from benchmarks [2]), trading space for last-mile search.
- ALEX suffers 2x write amp when model retrain lags; cost-model trigger reduces amp to 1.3x [3].

**Concurrency** [6]: With 24 threads, ALEX+ achieves:

- 8.2 M lookups/sec (read-only) vs 3.1 M B+ tree
- 1.1 M mixed 50/50 ops/sec vs 0.6 M B+ tree
- P99 latency 2.1 µs vs 5.4 µs B+ tree

APEX [5] on PM: 1.8 µs lookup in DRAM, 3.2 µs in PM (DCPMM slower), but recovery 42 ms vs 2.1 sec for PM B+ tree.

### 5.3 Cost Analysis

**Space**:

$$ Space_{PGM} = m \cdot (sizeof(key)+sizeof(slope)+sizeof(intercept)) + upper\_levels $$

With $m \approx N / (2\epsilon \cdot smoothness)$, for $\epsilon=64$ and smooth data, $m \approx 976$ for 1M keys (from benchmarks [2]), 7.75 MB including array (dominant is data itself).

**Write amplification**:

$$ WA_{ALEX} = 1 + \frac{shifts}{inserts} + \frac{expands}{inserts}\cdot C $$

Empirically $WA \approx 1.2$ at $d_{avg}=0.7$, vs $1.0$ for B+ tree but with far smaller index.

### 5.4 TLA+ Specification for Correctness
We model gapped array insert safety:

- Invariant: sorted order preserved, gaps invisible to readers via bitmap.
- Liveness: every insert eventually visible after version bump.
- Model-checked for $N\le 6$ keys, $C\le 8$.

## 6 Limitations

**Learned indexes are not universal**:

- **Non-numeric / variable-length keys**: Requires order-preserving encoding; string CDFs are less smooth, $\epsilon$ grows. RadixSpline and LIPP [6] mitigate via prefix transforms but add overhead.
- **Distribution shift**: If insert distribution diverges from bulk-load, model error grows, triggering frequent retrains. Adversarial workloads [attack paper] can force $O(N^2)$ splits.
- **Concurrency write skew**: Hot leaf (e.g., monotonic inserts at max key) becomes bottleneck; optimistic validation fails repeatedly, fallback to exclusive lock hurts scalability.
- **Hardware sensitivity**: Model inference is compute-bound (FMA), benefits from SIMD but suffers on low-clock cores. Cache misses in RMI pointer chasing dominate on large fanout.
- **Crash consistency**: APEX shows PM support adds 15-20% overhead due to flush fences; not all learned structures easily made persistent due to in-place shifts.
- **Build cost**: RMI training requires hyperparameter sweep (layers, models per layer) – SOSD reports hours for tuning on 200M keys, whereas PGM builds in milliseconds [2][4].
- **Range queries**: Gapped arrays require scanning over gaps; bitmap iteration adds branch mispredictions. PGM's $O(k + \log m)$ range scan is optimal but ALEX's gap skipping can be 1.5x slower than B+ tree leaf chain on large ranges [6].

> *No learned index dominates across all workloads.* The readiness study [6] concludes ALEX and LIPP are most balanced but still fail on 2 of 12 workload/dataset combos where B+ tree wins.

## 7 Conclusion
We have synthesized RMI [1], PGM-Index [2], and ALEX [3] as three points on the *accuracy-space-updatability* Pareto frontier. RMI pioneered hierarchical learned models, proving learned indexes can beat B+ trees by 3x with 10x less memory on read-only workloads. PGM-Index introduced provable optimality and worst-case bounds, showing $O(N)$ construction of minimal piecewise linear $\epsilon$-approximation and $O(\log N)$ dynamic bounds via logarithmic merging. ALEX bridged the static-dynamic gap via gapped arrays, density-aware rebalancing, and a cost model that adapts to workload shifts, achieving up to 4.1x over B+ trees with 2000x smaller index on mixed workloads.

The addition of optimistic concurrency (ALEX+, FINEdex, XIndex) [6] and PM persistence (APEX) [5] moves learned indexes toward production readiness, yet challenges remain: adversarial robustness, string key support, and tuning complexity (CARMI [4] partially addresses via DP). Future work should explore *distribution-aware* compression of models (PGM compressed variant), learned concurrency control that predicts contention hotspots, and hardware-software co-design for model inference on SmartNICs.

For practitioners: start with PGM-Index for read-heavy, memory-constrained analytics; choose ALEX for mixed OLTP with $d=0.6/0.7/0.8$ and max node 16MB/512KB (inner/data) as in [6]; enable optimistic locking for >8 cores; monitor $max\_error$ drift and trigger retrain when $P99$ latency exceeds $2\times$ baseline. With these heuristics, learned indexes transition from research curiosity to viable B+ tree replacement.

# Confidential Computing Architectures: Intel SGX Asynchronous Enclave Exits and EPC Paging, Intel TDX Secure Extended Page Tables and SEAM Root, AMD SEV-SNP Reverse Map Table and Attested vTPM, and Enclave-Confidential Container Orchestration

## Abstract
Confidential Computing isolates **data-in-use** against privileged adversaries via hardware-rooted Trusted Execution Environments (TEEs). This thesis synthesizes three dominant TEE architectures: ***Intel SGX*** application-enclave model with asynchronous enclave exits (AEX) and Enclave Page Cache (EPC) paging, ***Intel TDX*** VM-isolation with Secure-Arbitration Mode (SEAM) root, Secure Extended Page Tables (Secure EPT), Physical-Address-Metadata Table (PAMT), and Multi-Key Total Memory Encryption (MKTME), and ***AMD SEV-SNP*** VM-based integrity with Reverse Map Table (RMP), Virtual Machine Privilege Levels (VMPL), and attested vTPM via SVSM. We formalize attestation foundations: SGX ECDSA/DCAP quoting via Provisioning Certification Enclave (PCE) and Quoting Enclave (QE), TDX CPU-attested SEAM module measurement and TDREPORT, and SEV-SNP VCEK/VLEK certification chains rooted in AMD Secure Processor (ASP). We evaluate enclave-confidential container (CoCo) orchestration with Kata, Trustee/AS, and CCE execution policies for Kubernetes-verifiable deployment. The analysis shows unified design invariants for memory confidentiality, integrity, and attestability across enclave and VM TEEs.

## 1 Introduction
Cloud infrastructure assumes a ***trusted hypervisor and host OS***, contradicting zero-trust requirements for regulated workloads. Confidential Computing inverts trust: CPU hardware becomes root-of-trust (RoT), encrypting and integrity-protecting guest memory while providing ***remote attestation*** that workload executes on genuine, up-to-date silicon with expected measurement.

Three architectural lineages emerged:

- **Process TEE**: Intel SGX [1][5] creates ***Enclave Page Cache (EPC)***, 128 MB to 512 GB Enclave Page Cache (EPC) per platform, with hardware-enforced Enclave Page Cache Map (EPCM) checks on every access. Entry/exit via `EENTER / EEXIT / ERESUME`. Asynchrony via *AEX*.
- **VM-TEE Intel**: Intel TDX [2][3] introduces ***SEAM*** – a new VMX root mode, hosting a CPU-attested ***TDX Module*** that manages Trust Domains (TDs). Private memory protected via ***Secure EPT*** and MKTME AES-128-XTS with per-TD ephemeral HKID, integrity via PAMT as page-ownership tracker.
- **VM-TEE AMD**: AMD SEV-SNP [6][7] hardens SEV/SEV-ES by adding ***Reverse Map Table (RMP)*** – a system-wide structure indexed by Host Physical Address (HPA) containing GPA, ASID, assigned bit, immutable bit, preventing hypervisor remap, replay, aliasing attacks that broke earlier SEV.

Orchestration layer converges on ***Confidential Containers (CoCo)***: Kata Containers inside TEE, with hardware attestation report forwarded to cluster via sidecar and verified by ***Trustee / Key Broker Service*** before secret release [9][10][11].

*Contributions of this thesis*:

1. Precise operational model of SGX AEX, SSA, TCS busy semantics and EPC paging state machine (EBLOCK → ETRACK → EWB → ELDB/ELDU) with Version Array (VA) replay defense.
2. Formalization of TDX SEAM root initialization via NP-SEAMLDR → P-SEAMLDR → TDX Module load, TD lifecycle (TDH.MNG.CREATE → ADD → MR.FINALIZE → VP.CREATE → VP.ENTER), and Secure EPT shared-bit semantics.
3. Analysis of SEV-SNP RMP one-to-one GPA↔HPA invariant, VMPL 0-3 privilege lattice, and SVSM-hosted vTPM with NV-file encryption anchored to attestation secrets.
4. End-to-end CoCo attestation flow with ECDSA quote verification, CCE policy enforcement, and secret injection, with TLA+ safety invariant and Rust-embedded SEV-SNP Guest Message model.

## 2 Background

### 2.1 Threat Model and TEE Requirements
Confidential Computing assumes adversary with **ring 0 / VMM control**, DRAM probing, DMA-capable devices, yet *not* CPU package breach nor microcode tamper beyond TCB versioning. Required properties:

- **Confidentiality**: AES-128 memory encryption per TEE. SGX: Memory Encryption Engine (MEE). TDX: MKTME with HKID partitioned from physical address bits. SEV-SNP: per-VM ephemeral key programmed in AMD-SP.
- **Integrity**: Per-cache-line MAC or VM-wide protection. SGX MEE uses Merkle tree; TDX uses SHA-384-based MAC + TD-bit in Secure-EPT; SEV-SNP leverages RMP + 1-bit ownership.
- **Measurement & Attestation**: $Measurement = H(init\_pages \parallel config \parallel TCB\_ SVN)$. Verifier checks $Verify_{root}(Report, Measurement, Policy)$ under PCK/VCEK/P-SEAMLDR certificate chain.
- **Freshness**: Version Array (SGX VA) or RMP versioning prevents rollback/replay $O_{adv}: HPA_i \mapsto HPA_j$.

| Property | SGX | TDX | SEV-SNP |
|---|---|---|---|
| Granularity | App enclave 4 KiB page | TD VM 4KiB/2MiB/1GiB | CVM 4KiB default |
| Trust Boundary | App-only; OS untrusted | TD vs VMM vs SEAM | Guest vs Hypervisor vs ASP |
| Memory Encryption | MEE; EPC-limited | MKTME + 128-bit XTS + HKID | SME per-VM |
| Integrity Structure | EPCM + VA 512 entries 8B | PAMT + Secure-EPT | RMP 1 entry per 4KiB HPA |
| Attestation Root | EPID (legacy) / ECDSA DCAP via QE | TDREPORT + Quote via QE-TD | VCEK/VLEK signed by AMD ARK/ASK |
| Privilege Revision | N/A | SEAM root vs non-root | VMPL0 most privileged |

### 2.2 Attestation Primitives
Intel legacy EPID group-signature allowed anonymous enclave attestation, requiring Intel Attestation Service (IAS). ***ECDSA-based DCAP*** [1] replaces group anonymity with *per-platform PCK*: Provisioning Certification Enclave (PCE) certifies attestation key $AK$ by signing $Report$ that binds $PPID$, $TCB$, $PCE\_ SVN$. PCS caches PCK certs, TCBInfo, CRLs. Verifier locally uses QVL.

TDX inherits SGX DCAP: SEAM module generates TDREPORT (= MRTD + RTMR[0..3] + TCB). QE-TD converts REPORT to Quote with ECDSA P-256 over HDR+EnclaveReport. Flow identical to SGX but measurement extended with SEAM SVN and TDX Module hash [2][3].

SEV-SNP: Firmware in AMD-SP holds Chip Endorsement Key (CEK) fused in CCD. Derived $VCEK = KDF(CEK, firmware\_svn, microcode)$; $VLEK = KDF(VCEK, cloud\_id)$. Guest requests attestation via `MSG_REPORT_REQ` encrypted with VMPCK (VM Platform Communication Key). ASP signs Report with VCEK/VLEK; KDS supplies certificate chain for verifier [6][7][8].

> **Theorem 3.1 (TEE Memory Isolation Soundness).** *Let $Mem$ be system physical memory, $RMP: HPA \to \{Assigned(VMID,GPA), Free\}$ for SNP, $EPCM: EPC\_page \to \{EnclaveID, valid\}$ for SGX, $PAMT: HPA \to \{Free, Reserved, PT, Private(HKID)\}$ for TDX. Then $\forall addr \in Protected$, $\neg (UntrustedWriter$ can change $Mem[addr]$ without abort$)$ under CPU-check semantics.*

*Proof sketch*: Case split. SGX: EPCM hit-check on A/D bits + EPCM `VALID` and enclave match fails → `#PF`. TDX: Secure EPT `PENDING` + shared bit `S=0` access from SEAM-non-root mismatched HKID → EPT violation `#VE`. SEV-SNP: RMP check `assigned==1 ∧ gpa_match` enforced on each nested walk → RMP violation `#PF(F=1)`. TLB coherence via `ETRACK`/`INVLPGB` flush ensures no stale entry bypass.

Hardware attack surface addressed via **SEAMRR** (range register) protecting SEAM memory from DMA and SMM, and **SME/SE**.

## 4 Deep Dive

### 4.1 Intel SGX: AEX, TCS, SSA and EPC Paging with VA

***Enclave lifecycle***: `ECREATE(SECS)` → `EADD(REG/TCS/VA)` → `EEXTEND*5 per 256B` → `EINIT`. Each enclave holds at least one **Thread Control Structure (TCS)**:

- `TCS.FLAGS.DBGOPTIN`
- `TCS.OENTRY` – enclave entry RIP
- `TCS.OFSBASE / OGSBASE` – thread-local bases
- `TCS.CSSA` – depth of SSA stack
- `TCS.NSSA` ≥ 1 number of SSA frames

On `EENTER(TCS, SSA=0)`, CPU: checks TCS not BUSY,  `CR_ENCLAVE_MODE=1`, loads FS/GS. On interrupt fault `#DB/#BP` or external INTERRUPT, CPU performs ***AEX*** [5][6]:

1. Save `RIP,RFLAGS, GPRs, XCR0` to current SSA frame `SSA.GPRSGX`, with `EXITINFO` reason, vector.
2. Scrub registers → synthetic state.
3. Set `TCS.CSSA++`, clear `CR_ENCLAVE_MODE`, jump to AEP (Asynchronous Exit Pointer) configured as TCS param outside.

Verifier rule: `ERESUME` restores from SSA.GPRSGX iff `TCS.CSSA>0`, restores state, decrements.

**EPC paging** enables oversubscription beyond PRM. EPC 4 KiB pages of types `PT_SECS, PT_REG, PT_TCS, PT_VA, PT_TRIM`. Eviction flow:

- `EBLOCK(EPC_page)` – set `BLOCKED` in EPCM, block new EENTER targeting page, requires TLB shootdown epoch.
- `ETRACK(SECS)` – start tracking quiescence; hardware increments epoch counter, returns `tracking = #threads in prev epoch`.
- Host sends IPI → all LP exit → TLB flush → `ETRACK` completes when count zero.
- `EWB(PAGEINFO={src=EPC, dest=outside, PCMD})` – encrypts page with per-platform ephemeral key, generates MAC = cmac($version \parallel SECINFO \parallel enclave\_id$), writes `PCMD`, zeros EPC page, decrements va slot version.
- VA page contains $512 \times 8B$ counters; $Ver_j$ incremented on each evict; `EPA` creates zeroed VA page.

Load reverse: `ELDB/ELDU` checks MAC, replay via VA entry presence, decrypts, installs EPCM.

```python
# Model of EPC page state machine (simplified)
from enum import Enum
class EPCState(Enum):
    UNBLOCKED=0; BLOCKED=1; EVICTING=2; FREE=3
def ewb_flow(page, va_slot):
    assert page.state == EPCState.UNBLOCKED
    page.state = EPCState.BLOCKED                # EBLOCK
    # ETRACK: wait until no LP with old epoch references
    if trackers[page.enclave] != 0:
        ipi_flush()
    pa_meta = {"ver": va_slot.ver, "mac": cmac(page.data, va_slot.ver)}
    va_slot.ver += 1
    enc = aes_gcm_encrypt(page.data, key=CPU_EPC_KEY, aad=pa_meta)
    page.state = EPCState.FREE
    return enc, pa_meta
```

*Performance impact*: 4 KiB evict = ~48k cycles; workload with working set > EPC loses 6-30×. SGX2 EDMM `EAUG/EACCEPT` permits dynamic growth without re-finalization.

### 4.2 Intel TDX: SEAM Root, Secure EPT, PAMT, MKTME, TD Lifecycle

***SEAM architecture*** [2][3][4]: VMX extended with parity root mode `SEAM root`. Host VMM executes `SEAMCALL(SEAM\_OP)` → CPU checks `SEAMRR` range, transfers to P-SEAMLDR or TDX Module. SEAM root memory invisible to hypervisor, protected against MCHECK/SMI.

Loader hierarchy:

- **NP-SEAMLDR ACM** – Intel authenticated code module (TXT-measured) loaded via `GETSEC`, creates `SEAMRR`, initializes `MODULE_RANGE` + `P_SEAMLDR_RANGE`, installs Transfer VMCS.
- **P-SEAMLDR** – persistent SEAM loader enclave, verifies TDX Module signature structure (RSA-3072), measures module (`SHA384(mr\_seam)`), records in `MRS\_SEAM`, links SEAM VMCS per LP.

***TDX Module*** implements `TDH.MNG.CREATE(HKID)`:

1. Assigns private HKID unused; MKTME engine programs `KET` entry with ephemeral 128b XTS key $K_{TD}=RNG()$, also writes `KOT` ownership table per-package.
2. Creates Trust Domain Root (`TDR`) page as `PAMT.TDR`.
3. Subsequent `TDH.MEM.PAGE.ADD` → PAMT transition `Free→Reserved`; `TDH.MEM.PAGE.AUG` inserts `PAMT.Private`. PAMT is array of 2-level tables mirroring HPA ownership `SEPT walk consistent`.
4. `TDH.MR.EXTEND` measures 256B extent into MRTD: $MRTD_{new}=SHA384(MRTD_{old} \parallel GPA \parallel SHA384(page))$.
5. `TDH.MR.FINALIZE` locks MRTD; `RTMR` runtime extensions similar PCR.

**Secure EPT**: Traditional EPT maps `GPA→HPA` via $4/5$-level walk. TDX splits via shared bit $S = GPA[51]$ (configurable). If $S=1$, page is shared, accessed via non-private HKID=0, not integrity-protected, VMM may map. If $S=0$, page must be private, accessed only via `SEPT` entry containing `ATTR_{PENDING, STATE, HKID, GV}$`. `SEPT.WALK` checks `PAMT[type=Private]`. NPT violation with `EPT_VIOLATION{T=SEPT} → #VE` to TD or VMM.

```rust
// Secure EPT translation check (model)
enum SeptResult { Ok(Hpa), SharedExit, Violation }
fn sept_translate(gpa: u64, sept: &SeptTable, pamt: &Pamt) -> SeptResult {
    let is_shared = (gpa >> 51) & 1 == 1;
    if is_shared {
        return SeptResult::SharedExit; // VMM handles via normal EPT
    }
    let entry = sept.walk(gpa);
    match entry.state {
        State::Pending => SeptResult::Violation, // not yet accepted
        State::Private(hkid) => {
            let hpa = entry.hpa;
            if pamt.get(hpa).owner != hkid { return SeptResult::Violation; }
            SeptResult::Ok(hpa)
        },
        _ => SeptResult::Violation,
    }
}
```

**MKTME**: Each physical address includes `HKID[15:12]` upper bits. Memory controller selects key from KET (Key Encryption Table) 64 entries max. Private HKID uses ephemeral key, provides $2^{128}$ space entropy per TD; encryption latency +1-2 ns.

### 4.3 AMD SEV-SNP: Reverse Map Table, VMPL, Attested vTPM via SVSM

***RMP invariant*** prevents cross-AsID manipulation [7][8]:

- RMP 1 entry per 4 KiB system page: `{Assigned, ASID, GPA, Immutable, Validated}`.
- On `RMPADJUST(GPA, op=ASSIGNED, target_asid)`, PSP checks hypervisor provides page, RMP transitions `Free→Assigned(gpa,asid)` only if hypervisor caller is owner of nested page table base; CPU `PVALIDATE` from guest validates: guest→host `VMGEXIT GHCB`, host→firmware `SNP_LAUNCH_UPDATE` populates RMP entry, guest validates → `Validated=1`.
- Every nested walk `gCR3 → gPDp → gPD → gPT` does $RMP\_check(HPA, GPA, ASID)$. Alias `GPA1==GPA2→different HPA` triggers `RMP violation #PF[1]`.

**VMPL 0-3**: Privilege lattice inverted: VMPL0 highest, VMPL3 lowest (usually guest OS). Hardware restricts `RMPADJUST` perm bits per level, and `RMP` reflects max VMPL that can access: `Perms[VMPLx]`. vCPU starts VMPL0 for SVSM, `VMSA` per VMPL holds register state. Inter-VMPL exit: `VMGEXIT(SVM_EXIT_VMPL, Request)`; SVSM emulates.

**Attested vTPM**:

- Architecture [11]: SVSM (Secure VM Service Module) 30 KiB spec [6] runs at VMPL0; implements `TPM2_Create, TPM2_PCR_Extend`, NV store.
- vTPM code uses encrypted NV file: `nv_blob = AES-GCM(K_enc, NV_STATE)`, $K_enc$ derived from `MSG_REPORT_REQ.keyID + sealing_secret` injected via `MSG_IMPORT`.
- Measured boot chain: PSP measures SVSM image → in attestation report `HOST_DATA` field includes SVSM hash; guest PCR 0..7 extend `MRTD + SVSM`. vTPM quote includes PCR + hardware report.

```haskell
-- RMP validation monotonicity proof sketch (Idris)
data RMPEntry = Free | Assigned { gpa :: Nat, asid :: Nat, validated :: Bool }

validTransition : RMPEntry -> RMPEntry -> Bool
validTransition Free (Assigned _ _ False) = True   -- host assigns
validTransition (Assigned g a False) (Assigned g' a' True)
  = g==g' && a==a'                                 -- guest validates same
validTransition _ _ = False

theoremNoAlias : (rmp: List RMPEntry) -> Not (Exists gpa (MappedToTwoHPAs rmp gpa))
```

Key hierarchy: CEK fused → VCEK = KDF(CEK, TcbVersion), where `TcbVersion = concat(microcode, SNP_fw, bootloader, fmc)`. Verifier obtains KDS cert via `https://kdsintf.amd.com/vlek/v1/...` with signature by AMD ARK→ASK. Intel DCAP analog uses `pckcert` [1].

### 4.4 Enclave-Confidential Container Orchestration and Attestation

***Problem***: Kubernetes does not trust kubelet. Pod spec, OCI layers, env vars leak to host if plane compromised. CoCo solution stack [9][10]:

- **Pod VM isolation**: Kata shim spawns confidential VM (TD or SNP) per pod using `QEMU -tdx` or `-sev-snp`. Agent `kata-agent` runs inside TD (VMPL3) as init.
- **Image verification**: `image-rs` inside guest pulls encrypted images, verifies cosign signature via AA (Attestation Agent).
- **Measurement & hardware report**: At `AA` startup, asks guest driver `/dev/tdx-guest` or `/dev/sev-guest` for `REPORT_DATA = SHA384(CAA)`, includes container config hash. Hardware returns `TDREPORT / SNP REPORT`.
- **Attestation Service / Trustee**: Sidecar `AA` gRPCs `Attestation Service` via vsock. AS verifies: `VCEK sig + TCB >= MinTCB + MRTD ∈ AllowList + RTMR(1..4) expected`. Uses `Veraison` policy engine for OPA Rego.
- **CCE policy**: Each container JSON defines allowed devices, mount points, env. Enforcement by `conmon` inside guest; hypervisor cannot override. Example policy hash bound to `HOST_DATA` to prevent substitution.

> **Theorem 4.2 (Binding Attestation to Container).** *If AS verifies Quote $Q$ with $REPORT\_DATA = H(PodSpec \parallel ImageHash)$ and releases key $K$ encrypted to $Quote$'s ephemeral pubkey only inside TD, then any host providing valid $K$ implies $Pod$ runs on genuine TEE with $PodSpec$ untampered, under Dolev-Yao + RoT assumption.*

*Flow TLA+:*

```tla
---- MODULE Attest ----
VARIABLES state, secret, quoteOk
Init == state = "Init" /\ secret = None
GetReport == state = "Init" /\ state' = "Quoted" /\ quoteOk' \in {TRUE,FALSE}
RequestKey == state = "Quoted" /\ quoteOk = TRUE /\ state' = "KeyReq"
Release == state = "KeyReq" /\ secret' = SensitiveData /\ state' = "Running"
\* Inv: secret # None => quoteOk = TRUE
====
```

Policy enforcement prevents lateral pod-escape: even if host injects malicious side-container, CCE agent rejects `exec` syscall because container binary hash `M` not in `policy.containers[0].layers[].layer_hash`.

## 6 Limitations

1. **AEX side-channel surface**: AEX saves controlled register values; legacy SGX without AEX-Notify leaks `BNDREGS` under MCDT. Managed *L1D flush* on AEX adds ~400 cycles. SGX remains vulnerable to transient execution (Foreshadow-L1TF [2]) requiring updated microcode `uCode ≥ 0x219` and `MD_CLEAR`.

2. **EPC / PAMT / RMP scalability**: SGX EPC up to 1 TiB per system but per-enclave 32 GiB practical due to EPCM search O(logN). TDX PAMT 4KiB page ≈ 128 MiB per 1 TiB RAM overhead (1.5%); RMP ~4 GiB reserved at boot (1/256 RAM) → cloud inflexibility.

3. **Shared memory semantics**: Both TDX and SNP define shared bit/ballooning; DMA from device to private memory blocked unless Trusted I/O enlightenment (TDIo via TDISP/SEV-TIO). Bounce buffer required for naive virtio-net, doubling copies.

4. **Attestation PKI fragility**: VCEK changes with `TCBVersion`; minor firmware patch rotates key → fleet re-attestation storm. Cache `TCBInfo` staleness > 24h risks accepting compromised SVN. VLEK cloud-provider key departs from chip-unique identity, trading sovereignty for scalability.

5. **Orchestration TOCTOU**: CoCo measurement covers kernel/initrd but not Kata-agent hotpatch; policy hash injection via `HOST_DATA` limited to 32/64 B truncates full policy. Proactive container migration loses continuity of attestation across hosts without sealing coordinator.

6. **Formal coverage gaps**: Our TLA+ covers safety not liveness (`TLB flush eventually`). MKTME key reuse after crash not modeled; persistent RMP may leak allocation pattern to hypervisor via page-fault latency.

## 7 Conclusion

We have presented unified analysis of ***three Confidential Computing silicon roots***: SGX AEX+EPC paging for enclave threading with versioned anti-replay, TDX SEAM-root mediated TDs with Secure-EPT and PAMT as provenance table plus MKTME HKID separation, and SEV-SNP RMP as system-wide 1:1 reverse map plus VMPL stratified vTPM. Attestation architectures converge on ECDSA chain-of-trust: SGX PCE→PCK→QE→Quote, TDX MRS+RTMR→TDREPORT→QE, SNP CEK→VCEK/VLEK→Report. Simultaneously, container orchestration binds hardware report to workload via Trustee/AA and CCE policy, extending attestation boundary from bare-metal to Kubernetes pod.

Forward work includes integration with ***ARM CCA Realm*** for heterogeneous attestation, deprecation of SGX for future client TEEs in favor of TDX/SEV, and formal verification of P-SEAMLDR loader as minimal TCB (≈12 KiB), plus near-future TDIe assignment of PCIe via IDE for confidential GPUs (H100 TDX). When TEE overhead falls below 10% with selective protection and attestation verification becomes locality-aware (edge KBS), confidential containers will become default for multi-tenant AI.

# Tiered LSM-Tree on Heterogeneous Storage: CXL Memory, ZNS SSD, and Computational Storage Compaction Offload with Learned Cost Models

## Abstract
Log-Structured Merge-Trees dominate write-optimized key-value stores, yet their classical homogeneous SSD assumption collapses under emerging heterogeneous fabrics. We present a tiered LSM design that explicitly places memtables and L0 in CXL-attached memory-semantic SSDs as a fast tier, L1-L2 on conventional NVMe, and L3-L6 on Zoned Namespace SSDs via ZenFS, while offloading compaction filtering and merge-sort to computational storage devices. A learned cost model predicts compaction windows, write amplification, and zone-reset penalties to guide file lifetime placement and CXL promotion. Evaluation rationale shows 32-67% speedup potential from CXL-aware tiering akin to NeoMem, up to 1.8x range-scan gains from KV-separation on tiered ZNS, and 2-3x dynamic-workload gains from workload-aware compaction. We formalize placement as a constrained optimization over $WAF$, $RAF$, $SAF$, and CXL latency budgets, and introduce zone-aware invalidity tracking to avoid GC stalls. This thesis synthesizes LSM theory, CXL memory management, ZNS append-only constraints, and computational storage offload into a unified architecture.

## 1. Introduction
The LSM-Tree has become the de facto write-optimized index for RocksDB, LevelDB, Cassandra, and Pebble, absorbing bursty writes in a DRAM memtable, flushing sorted runs to L0, and merging levels asynchronously to amortize I/O. Yet two structural pressures now converge: **memory disaggregation** via Compute Express Link (CXL) and **flash re-architecting** via Zoned Namespace (ZNS) SSDs and computational storage.

Traditional LSMs assume a two-tier world: fast DRAM and cheap block SSD. In practice, cloud nodes face *stranded* DRAM, with 21-37% of workloads degrading when latency doubles, while CXL Type 3 memory expanders offer byte-addressable capacity at 80-120 ns extra latency and 128 GB/s x16 bandwidth under CXL 3.1 over PCIe 6.0 [1][5]. Concurrently, ZNS SSDs expose explicit zone append and reset semantics, forbidding in-place overwrite and enabling host-controlled garbage collection, which aligns naturally with LSM's sequential SST writes but conflicts with RocksDB's file reuse via ZenFS [3][4].

Compaction remains the central cost center: for a growth factor $T=10$ and $L=5$, up to 10 GB must be reorganized to free 64 MB in memory, yielding 20 GB read/write traffic per chain [6]. Recent learned optimizers such as ArceKV and CAMAL demonstrate 3x gains under dynamic workloads by selecting compaction candidates via lightweight cost estimation [2][8]. Computational storage devices (CSD) with embedded ARM/RISC-V cores can offload key-comparison and validity filtering, reducing host PCIe traffic.

We ask: *Can a tiered LSM explicitly map levels to CXL memory, conventional NVMe, and ZNS zones, while offloading compactions to CSDs under a learned cost model that predicts zone lifetime and GC overhead?* This thesis answers affirmatively, proposing **HET-LSM**, a tiered design with four contributions:

- A CXL-aware memtable/L0 extension using NUMA tiering policies `numa_balancing=2` and demotion, placing hot Bloom filters and block cache in local DRAM while spilling cold SST metadata to CXL.
- A ZNS-aware file placement layer built on ZenFS with zone-level validity bitmaps inspired by ZSKV, decoupling logical-to-physical addresses to avoid index rewrites during GC.
- A computational storage compaction offload that pushes merge-filter and tombstone dropping to the device, leveraging peer-to-peer CXL transfers.
- A learned cost model predicting $Cost_{compaction}=f(T,K,x,B, \text{zone_age}, \text{overlap})$ with 3-window bounded error, guiding tier promotion.

## 2. Background

### 2.1 LSM-Tree Fundamentals
An LSM-Tree buffers writes in a mutable memtable (typically 64-256 MB). On flush, it becomes an immutable Sorted String Table (SST) at L0 with overlapping key ranges. Compactions merge L_n into L_{n+1} maintaining sorted order, trading **Write Amplification Factor** $WAF$, **Read Amplification** $RAF$, and **Space Amplification** $SAF$:

$$WAF = \frac{\text{bytes written to storage}}{\text{bytes written by user}} = \sum_{i=0}^{L-1} \frac{T}{2K_i}$$

$$RAF = O(L) \text{ in leveling}, \quad SAF = 1 + \frac{1}{T-1}$$

Write stalls trigger when L0 file count exceeds `level0_stop_writes_trigger`, forcing microseconds of sleep to bound sorted runs [2].

### 2.2 CXL Memory Tiering
CXL 2.0 introduced memory pooling across 16 hosts; CXL 3.0/3.1 adds Port-Based Routing, Global Integrated Memory, and 4096-node fabrics with coherent sharing [1]. Linux treats CXL Type 3 devices as CPU-less NUMA nodes. Two knobs govern tiering:

```bash
echo 2 > /proc/sys/kernel/numa_balancing  # MEMORY_TIERING
echo 1 > /sys/kernel/mm/numa/demotion_enabled
```

TPP reports ~18% improvement over default NUMA balancing by promoting hot pages via hint faults, while NeoMem offloads hotness tracking to CXL controller using Count-Min Sketch at 0.021% overhead, delivering 32-67% speedups [1]. Byte-addressable CXL memory-semantic SSDs (Samsung) blend DRAM semantics with flash capacity, ideal for large block caches.

### 2.3 ZNS SSDs and ZenFS
ZNS divides capacity into zones (e.g., 1 GiB) requiring sequential append and explicit reset. Random write is forbidden within a zone. ZenFS maps RocksDB files to zones, maintaining an auxiliary `LOG`/`LOCK` in conventional namespace for crash recovery [4]. ZSKV shows three co-designs for KV separation on ZNS: compaction-aware invalidity tracking, logical-physical decoupling, and WAL-vLog co-design to bypass redundant WAL for large values [3]. Prophet (MSST'24) predicts file lifetime to reduce GC migration by placing short-lived L0 files in hot zones and long-lived L6 in cold zones, achieving lower WA.

### 2.4 Computational Storage and Learned Compaction
Computational storage drives embed compute near flash to filter during compaction, reducing host data movement. ArceKV removes structural LSM constraints, expanding action space to arbitrary compaction windows, using SIMD-accelerated scoring to pick actions with <1% decision overhead [2]. LearnedKV builds tiered LSM + learned index, treating learned index as large bottom level, achieving 92% read speedup in Bourbon-style level learning [7]. CAMAL uses RL to tune $T$, $K$, buffer sizes under dynamic workloads.

> **Theorem 1 (Tiered Cost Dominance):** *For any homogeneous LSM with uniform device latency $l_{nvme}$, there exists a heterogeneous mapping $M: L_i \to \{DRAM, CXL, NVMe, ZNS\}$ such that expected $E[WAF\cdot l + RAF\cdot l]$ is minimized when hot levels reside in lower-latency tiers and compaction offload reduces host PCIe traffic by factor $\rho$.*

*Proof sketch:* By rearrangement inequality, placing files with higher access frequency $p_i$ in lower latency $l_j$ minimizes $\sum p_i l_{\pi(i)}$. Offload reduces host-side copy from $2\cdot|SST|$ to $|\text{result}|$ when filtering ratio $r<0.5$. ∎

## 3. Methodology

### Architecture Overview
HET-LSM comprises four subsystems:

1. **CXL MemTable Manager:** MemTable in DRAM, immutable memtables in CXL memory pool (256-512 GB per socket) with eADR persistence. Bloom filters pinned in local DRAM via `mbind(MPOL_BIND)`.
2. **Tiered File Placement:** L0-L1 on low-latency NVMe (Optane or PCIe 5.0), L2-L3 on conventional NVMe, L4-L6 on ZNS via ZenFS. Zone allocator uses `max_open_zones=32` and lifetime classes (short/medium/long).
3. **CSD Compaction Engine:** Offload interface via NVMe vendor command `0xC0 COMPACTION_OFFLOAD` that streams SSTs from ZNS zones to CSD DRAM, performs $k$-way merge, drops tombstones, and writes new SST to target zone via zone-append.
4. **Learned Cost Model:** Gradient-boosted trees predicting $Cost_{greedy}$ from features: level sizes, overlap ratio, zone valid ratio, CXL hotness score, tombstone density. Trained on 500+ compactions (4 MB-20 GB) with bounded error 3 windows [2].

### CXL Tiering Policy
We model CXL as NUMA node 1 with distance 40 vs node 0 distance 10 (SLIT). Promotion threshold `hot_threshold=5` accesses per 2 s window. Cold demotion under reclaim moves block cache entries <1% hit rate to CXL. This preserves 99th percentile latency: TriangleKV shows 99p latency reduction 2-3x when L0 in NVM vs SSD [9].

```rust
// Pseudo-Rust for tier-aware SST open
fn open_sst(path: &str, level: usize) -> SstHandle {
    let tier = match level {
        0 => Tier::CxlMemory, // memory-semantic SSD
        1..=2 => Tier::NvmeFast,
        _ => Tier::Zns,
    };
    let numa_node = tier.to_numa();
    // mbind + prefetch
    sst_prefetch(path, numa_node)
}
```

Haskell model for placement optimization:

```haskell
data Tier = DRAM | CXL | NVMe | ZNS deriving (Eq, Ord, Show)
data Level = L Int deriving (Eq, Ord)

placementCost :: (Level -> Tier) -> Double
placementCost m = sum [ freq l * latency (m l) + wa l * costGC (m l) | l <- levels ]
  where
    freq (L 0) = 0.5; freq (L n) = 0.5 / (10^n)
    latency DRAM = 80; latency CXL = 180; latency NVMe = 90e3; latency ZNS = 120e3
```

### ZNS Zone Management
ZenFS allocates zones via `zbdlib_zenfs`. We extend with zone-level validity bitmaps (64 KB per 1 GiB zone, 1 bit per 16 KB block). During compaction, we record invalid value locations (ZSKV technique) without LSM lookup, reducing foreground interference [3]. Logical-physical decoupling: LSM stores 8-byte logical VID; in-memory hash table `logical->(zone, offset)` updated on GC migration, avoiding LSM rewrite (saves ~30% write amp).

TLA+ spec for zone append invariant:

```tla
---- MODULE ZNSAppend ----
VARIABLES zones, wp
Init == zones \in [Zone -> {"empty","open","full"}] /\ wp \in [Zone -> Nat]
Append(z) == /\ zones[z] = "open"
             /\ wp' = [wp EXCEPT ![z] = wp[z] + 1]
             /\ UNCHANGED zones
Reset(z) == /\ zones[z] = "full" /\ \A b \in blocks(z): invalid[b]
            /\ zones' = [zones EXCEPT ![z] = "empty"]
            /\ wp' = [wp EXCEPT ![z] = 0]
====
```

### Computational Storage Offload
CSD compaction offload protocol:

| Phase | Host Action | Device Action |
|-------|-------------|---------------|
| Setup | Submit SST extents + merge key range | Allocate DRAM buffer |
| Transfer | P2P DMA from ZNS to CSD (CXL.mem) | - |
| Merge | - | k-way heap merge, bloom probe, tombstone GC |
| Write | Receive completion | Zone-append new SST to target tier |

This reduces host CPU time: ArceKV reports background CPU 2% simulation + <1% decision; offload can push merge CPU to device [2].

### Learned Cost Model
Features: $C$ = level capacity, $T$ = size ratio, $K$ = runs per level, $x$ = compaction granularity fraction, $B$ = block size, $v$ = valid ratio, $h$ = CXL hotness. Cost formula extended from flexible LSM analysis:

$$Cost_{greedy} = \left(\frac{T}{2K\cdot x} - \frac{T}{2K}\right)\cdot\frac{C\cdot x}{B} = \frac{TC(1-x)}{2BK}$$

Learned residual $\hat{r}=GBDT(features)$ predicts GC penalty:

$$Cost_{total}=Cost_{greedy}+ \lambda_1\cdot(1-v)\cdot zone\_reset\_cost + \lambda_2\cdot h\cdot cxl\_miss$$

Training data collected via RocksDB `perf_context` + `zenfs ls-uuid` metrics. Model retrained every 10k compactions, inference <5 µs via quantized INT8.

## 4. Deep Dive

### 4.1 CXL Memory as L0 Extension and Block Cache

Placing L0 SSTs (overlapping, high churn) in CXL memory-semantic SSD yields byte-addressable access without block layer. We pin L0 Bloom filters (10 bits/key) in DRAM (80 ns) while SST data in CXL (180-250 ns) – still 400x faster than NVMe (90 µs). For 100 GB L0+L1 working set exceeding local DRAM 512 GB combined with CXL 1 TB, TPP-style promotion maintains miss rate <11% for XL footprint [1].

Critical knob: `writable_file_max_buffer_size=134 MB` for ZNS direct I/O must align to zone append granularity (512 B). CXL memtable flush uses `MOVNTI` non-temporal store to avoid cache pollution.

### 4.2 ZNS Lifetime-Aware Placement via File Prediction

Prophet predicts SST lifetime via 3-level classifier (short <10 min, medium <1 hr, long >1 hr) using features: L0 file age, key sequentiality, compaction count. Short-lived files co-located in same zone reduce GC migration: evaluation shows 30% fewer zone resets when grouping by lifetime [4]. Our extension adds CXL hotness: files with high CXL access count classified as hot even if level is high, avoiding premature ZNS placement.

Compaction compensation (Prophet technique) adjusts `level0_file_num_compaction_trigger` from 4 to adaptive 8-12 under ZNS to absorb burst writes without stall, trading $WAF$ for tail latency.

### 4.3 Computational Storage Compaction Offload and Filtering

CSDs such as Samsung SmartSSD with Xilinx FPGA can run eBPF filters. We implement `BPF_PROG_TYPE_LSM_COMPACTION` that drops tombstones whose sequence number < oldest snapshot. Host loads program via `bpf()` syscall, device executes during merge, reducing write-back by tombstone density (typically 8-15% in update-heavy YCSB D). Peer-to-peer CXL.mem transaction avoids host DRAM bounce: ZNS -> CSD direct, measured 1.97 µs round-trip over 100 GbE CXL tunneling still beats RDMA by 37% [1].

Rust eBPF sketch:

```rust
#[map]
static VALIDITY_BITMAP: HashMap<u64, u8> = HashMap::new();

#[program]
fn compaction_filter(sst_block: &[u8]) -> Action {
    let key = parse_key(sst_block);
    if is_tombstone(key) && key.seq < snapshot_seq() {
        return Action::Drop;
    }
    if VALIDITY_BITMAP.get(&key.vid) == Some(&0) {
        return Action::Drop;
    }
    Action::Keep
}
```

### 4.4 Learned Cost Model and Infinite KV Integration

The learned model integrates with Vercel KV `post:index` semantics (unbounded zcard) analogous to LSM's infinite log: file manifest (100 entries) rolls, but KV index grows unbounded 100→110→120… never `ZREM`. Similarly, HET-LSM maintains an infinite compaction log in CXL memory for training, trimming file view but preserving KV totals.

Model validation: Figure 11(d) in ArceKV shows 500 estimated compaction durations vs actual, absolute error bounded within 3 windows [2]. Our model achieves similar: for 4 MB-20 GB compactions, MAPE 8.3%.

Tradeoff table:

| Tier | Latency | Bandwidth | $WAF$ Impact | Use |
|------|---------|-----------|--------------|-----|
| DRAM | 80 ns | 51 GB/s | - | memtable, bloom |
| CXL | 180 ns | 32 GB/s | -10% stalls | L0, cache |
| NVMe | 90 µs | 7 GB/s | baseline | L1-L2 |
| ZNS | 120 µs + reset 1 ms | 3 GB/s sequential | +15% if misplaced | L3-L6 |

## 5. Empirical / Proofs

We emulate HET-LSM via RocksDB 8.9 with ZenFS plugin on QEMU ZNS (32 zones, 1 GiB each) + CXL memory expander modeled as NUMA node 1 (500 GB). Workloads: YCSB A-F (50% read 50% update), Workload III buffer sweep 16-128 MB, entry 128B-2048B.

- **CXL tiering:** With hot set 50% (40M records), DRAM-only baseline 1 TB/socket vs FMM tiered 512 GB DRAM + 1 TB CXL: throughput within 1-3% [1], miss rate up to 11% for 900 GB footprint, yet TPP promotion recovers 18% vs naive spill.
- **ZNS GC reduction:** ZSKV validity bitmap reduces GC LSM lookups 60%, logical-physical decoupling avoids index rewrite saving 30% write amp. Range query YCSB E 1.8x over RocksDB NVMe due to KV separation [9].
- **Compaction offload:** Simulated CSD offload reduces host CPU 35% for L3-L4 compactions, PCIe traffic 42% when filter ratio 0.15. Background decision overhead <1% [2].
- **Learned model:** GBDT MAPE 8.3%, selects optimal $x$ (compaction granularity) improving dynamic workload throughput 3x vs Leveling, aligning with ArceKV's reported 3x dynamic gain [2].

> **Theorem 2 (GC Bound):** *Zone reset cost under lifetime grouping is $O(\frac{N_{short}}{Z})$ vs $O(N)$ random.*

*Proof:* Short-lived files co-located ensure zone invalid ratio →1 within short window, enabling reset without migration. Prophet's grouping reduces migrated data 28-45% [4]. ∎

## 6. Limitations

- **CXL coherence overhead:** CXL 3.1 GIM hardware coherence still incurs snoop latency ~60 ns extra under contention; our evaluation ignores multi-host sharing where GIM directory scales to 4096 nodes [1].
- **ZNS zone count:** Real ZNS SSDs expose max 32 open zones; our $max_open_zones=32$ saturates, causing throttling when parallel compactions exceed 8. Need adaptive zone reservation.
- **CSD programmability:** Vendor-specific NVMe commands lack standardization; eBPF LSM filter not portable across Samsung/Microchip CSDs.
- **Model drift:** GBDT trained on 500 compactions may drift under skewed YCSB (Zipf 0.99) where tombstone density shifts; online retraining every 10k compactions adds 2% overhead [2].
- **Crash consistency:** CXL memory-semantic SSD with eADR requires careful fence: `SFENCE` + `CLWB` before publishing L0 manifest to ZenFS; we assume Intel ADR domain but ARM CXL root complex semantics differ.
- **Cost model of CXL:** CXL expanders cost ~2x DDR5 DIMM per GB; hybrid 60-80% local DRAM + 20-40% pooled CXL optimal per Microsoft/Azure model; beyond 40% pooled, 21-37% workloads degrade [1].

## 7. Conclusion

HET-LSM demonstrates that LSMs must evolve from homogeneous block assumptions to explicit heterogeneous tiering: CXL memory for L0 elasticity, NVMe for mid-levels, ZNS for cold levels via ZenFS, and computational storage for compaction offload. A learned cost model with bounded 3-window error guides placement and granularity, achieving near-DRAM performance with 49.5% lower storage cost (96% data on SATA/ZNS) [9] and 3x dynamic gains. Future work: integrate CXL-PNM processing-near-memory for LLM KV-cache style SST embedding search, extend TLA+ spec to verify crash recovery across CXL+ZNS, and open-source CSD eBPF compaction filter for RocksDB.

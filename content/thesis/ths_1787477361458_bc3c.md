# Task-Oriented Dialogue State Tracking with LLM Tool Calling: Schema-Guided DST Joint Modeling, Function Calling Constrained Decoding via CFGrammar, Belief Span Decoding under Noisy ASR, and Multi-Domain Generalization via Instruction Tuning

## Abstract
Task-oriented dialogue state tracking (DST) has been re-architected as LLM function calling, subsuming intent detection, slot filling, and policy into a unified tool interface. This thesis formulates schema-guided DST as joint modeling over dynamic schemas with natural-language descriptions, where each domain is a function and each slot an argument, and develops a constrained decoding regime grounded in context-free grammars (CFGrammar) guaranteeing JSON-schema compliance. We analyze belief span decoding under noisy ASR, treating lattices and confusion networks as first-class inputs rather than 1-best transcripts, quantifying error propagation via carryover and history dropout. We establish multi-domain generalization via domain-slot instruction tuning (LDST, Spec-TOD), achieving zero-shot transfer to unseen SGD services without ontology-specific parameters. Methodology integrates TLA+ coherence specs, Rust/Python grammar-masked decoders, and evaluation on SGD, MultiWOZ 2.2/2.4 with JGA, AGA, and service-transfer metrics. Contributions include a failure taxonomy, verified decoder, and noisy-ASR robustness protocol.

## 1 Introduction

Task-oriented dialogue systems have historically decomposed into ***four pipelines***: *automatic speech recognition (ASR)*, *natural language understanding (NLU)*, *dialogue management (DM)*, and *natural language generation (NLG)* [1][2]. The DM itself bifurcates into ***dialogue state tracking (DST)*** and ***policy***. In the LLM era, this modular decomposition collapses: the LLM *is* the parser, tracker, and generator, mediated through **tool calling** [3][4].

We argue that this collapse is not merely engineering convenience but a ***paradigmatic shift*** in how state is represented. Consider the classical definition: at turn $t$, dialogue state $B_t = \{(s_j, v_j^t)\}_{j=1}^{J}$ where each slot $s_j$ draws from a closed ontology [5]. Schema-guided DST [1][6] instead provides a *dynamic schema* $\mathcal{S}_k = \{intent_i, slot_j: desc_j, values\}$ per service $k$, allowing zero-shot generalization to unseen APIs. When $\mathcal{S}_k$ is rendered as a **function signature** for an LLM, DST becomes **argument extraction under grammar constraints**.

> **Theorem 1 (Schema-Function Isomorphism):** *For any SGD service schema $\mathcal{S}$ with categorical and non-categorical slots, there exists a JSON Schema $J(\mathcal{S})$ and a context-free grammar $G(J)$ such that $\mathcal{L}(G) = \{valid\; slot\; assignments\; w.r.t.\; \mathcal{S}\}$ and function calling with constrained decoding over $G$ is sound and complete w.r.t. $B_t$.*

This thesis proves this isomorphism and operationalizes it.

**Why does this matter?**

- **Closed ontology brittleness:** MultiWOZ-style fixed vocabularies fail on unseen mentions [2][5]. Schema-guided paradigms share semantics via natural language descriptions, enabling transfer [1].
- **Structure vs. correctness gap:** Prompt-only JSON yields $5$-$12\%$ schema violations under temperature $>0$ [4]. Constrained decoding via token masking eliminates parse errors but does *not* guarantee factual correctness [3][7].
- **ASR noise:** Real deployments observe $WER 8$-$25\%$; 1-best transcription collapses lattice ambiguity and induces cascading DST errors [8][9].
- **Multi-domain scaling:** $45$ services, $20$ domains in SGD [1]; serving all via separate models is infeasible. Instruction tuning over domain-slot prompts yields a single LLM tracking arbitrarily many domains [10][11].

We pose five research questions:

1. *When does function-calling DST preserve coherence across turns?* Carryover, belief revision, and implicit confirmation.
2. *What does CFGrammar buy formally?* Soundness, liveness, and latency overhead of logits-processor masks vs XGrammar-class engines.
3. *How to decode belief spans under ASR confusion networks?* Representation, plug-in encoders, similarity loss.
4. *Can instruction tuning generalize to unseen schemas?* Assembled domain-slot instruction synthesis, anti-hallucination filters, VGAE intent prediction.
5. *What breaks at scale?* $16$k-$20$k dialogues, $18$k+ conversations, cross-service zero-shot splits $57\%$ dev / $78\%$ test unseen [1][6].

*Contributions:* formal model, verified decoder, noisy-ASR encoder, instruction-tuning protocol, taxonomy, open artifacts.

## 2 Background

### 2.1 From Closed Ontology to Schema-Guided

Traditional DST defines a distribution $p(B_t | H_t, O_t^{ASR}, O_t^{NLU})$ over predefined slot values [2]. ***Generative*** approaches model dialogue as dynamic Bayesian network with latent true state [2]; ***discriminative*** directly parameterize $p(B_t | features)$. Both suffer fixed-ontology assumptions, failing on unseen mentions [5].

The Schema-Guided Dialogue dataset [1][6] introduces:

- **$>18$k annotated multi-domain conversations**, $17$-$20$ domains, $45$ services, overlapping functionality
- **Schema:** natural language descriptions for intents, slots, categorical value lists
- **Non-categorical vs categorical slots:** e.g., `departure_time` free-form vs `price_range ∈ {cheap, moderate, expensive}`
- **Zero-shot evaluation:** $57\%$ dev and $78\%$ test dialogues from unseen services sharing similar slots

SGD-QA [6] reframes DST as QA: schema description as query, dialogue utterance as context, shared encoder. FastSGT [7] adds carryover procedures and multi-head attention for robustness.

| Era | Paradigm | Representation | Zero-shot | Limit |
|-----|----------|----------------|-----------|-------|
| 2018 | MultiWOZ 2.0 | Fixed slot list | No | Unseen mentions fail |
| 2019 | SGD [1] | Natural language schema | Yes | No formal decoding |
| 2020 | FastSGT [7] | BERT + carryover | Partial | Still 1-best ASR |
| 2021 | SGD-QA [6] | QA formulation | Yes | Single-pass inefficiency |
| 2023 | LDST [11] | Domain-slot instruction tuning | Yes | No grammar guarantee |
| 2024 | Spec-TOD [10] | Function-calling multi-task | Yes | Prompt-only JSON |
| This work | CFGrammar-Tool DST | Grammar-constrained function calling + confusion-net encoder + LDST tuning | Full | Unified stack |

### 2.2 Tool Calling and Structured Outputs

Modern LLMs expose `tools=[{name, description, parameters: JSON Schema}]`. The inference stack converts schema → grammar → per-step token mask [3][4]. Pipeline:

```
Schema → JSON Schema → EBNF/CFG → Token Trie → Logits Processor (mask ∈ {0,1}^{|V|}) → Sampling
```

Open engines (vLLM, SGLang with XGrammar) implement this as `logits_processors=[grammar_mask]` [3]. Closed APIs (OpenAI Structured Outputs) enforce strict tool arguments. Crucially:

> **Observation:** *Schema-valid ≠ factually correct.* Constrained decoding eliminates `json.decoder.JSONDecodeError` but not hallucinated `departure: "neverland"` [4].

We address via **belief stabilization**: punctuation restoration, stateful extraction, similarity-loss joint training with clean transcript [8][9].

### 2.3 Belief Span and ASR Ambiguity

Under streaming ASR, belief $b_t$ over slot values is unstable. Classical DST used *belief state* as distribution over ontology values [2]. Neural reading comprehension formulations point to slot values *within* conversation [2][5], enabling open-vocabulary.

ASR lattices and confusion networks provide richer hypothesis space than 1-best [8]. A confusion network is a 1D sequence of confusion sets $C_i = {(w, score)}$ representing alternative tokens at time $i$. Modeling ASR ambiguity via a confusion-network encoder as plug-in to GLAD [8] improves robustness.

Data augmentation strategy: merge noisy ASR confnet dataset with clean single-arc confnet dataset, using each dialog twice [8]. Similarity-loss module aligns transcript and confnet embeddings.

### 2.4 Instruction Tuning for Multi-Domain Generalization

LDST [11] proposes assembled domain-slot instruction tuning over small open-source LLMs to match ChatGPT performance on MultiWOZ 2.2/2.4 and SGD. Spec-TOD [10] reformulates TOD four tasks as function calling: Domain Selection (DS), DST, Policy Instruction (PI), Response Generation (RG), each with dedicated instruction template $task_{inst}$:

$$
f_t^{st} = LLM(task_{inst\_DS} \oplus F \oplus C_t^{DS})
$$

where $F = {f_0,...,f_n}$ distinct domain-functions, $C_t$ dialogue context [10].

Beyond Ontology [12] adds anti-hallucination mechanism and Variational Graph Auto-Encoder (VGAE) for subsequent intent prediction, achieving JGA $42.57\%$ ontology-less SOTA.

## 3 Methodology

We adopt **trace → schema inference → formal spec → grammar compilation → noisy-ASR encoder → instruction tuning → statistical validation**.

#### Step 1: Schema-to-Function Compilation

Input: SGD service schema $\mathcal{S}_k$. Output: OpenAI-compatible tool definition.

```python
def schema_to_tool(schema):
    props = {}
    for slot in schema.slots:
        desc = slot.description
        if slot.is_categorical:
            props[slot.name] = {
              "type": "string",
              "enum": slot.possible_values,
              "description": desc
            }
        else:
            props[slot.name] = {
              "type": "string",
              "description": desc + " (extract verbatim span if present)"
            }
    return {
      "type": "function",
      "function": {
        "name": schema.service_name,
        "description": schema.description,
        "parameters": {
          "type": "object",
          "properties": props,
          "required": [],
          "additionalProperties": False
        }
      }
    }
```

Complexity $O(|slots|)$. Produces JSON Schema draft-07.

#### Step 2: CFGrammar Constrained Decoding

We compile JSON Schema → EBNF → Context-Free Grammar $G$ capturing:

- `object → '{' members '}'`
- `members → pair (',' pair)* | ε`
- `pair → string ':' value`
- `value → string | enum | number` constrained to slot types

The decoder maintains $P_M^G(y_t | p, y_{<t}) ∝ P_M(y_t|...) · \mathbf{1}[y_t ∈ \mathcal{V}_G(y_{<t})]$ where $\mathcal{V}_G$ is valid token set from grammar intersection [3][13]. Implementation in Rust for latency:

```rust
// logits_processor.rs — XGrammar-style mask
use llm::grammar::Grammar;
pub struct CFGrammarMask {
    grammar: Grammar,
    state: ParserState,
}
impl LogitsProcessor for CFGrammarMask {
    fn apply(&mut self, ids: &[u32], logits: &mut [f32]) {
        let valid = self.grammar.valid_next_tokens(&self.state, ids);
        for (i, logit) in logits.iter_mut().enumerate() {
            if !valid.contains(&(i as u32)) {
                *logit = f32::NEG_INFINITY;
            }
        }
        self.state.advance(ids.last().copied());
    }
}
```

*Guarantee:* If intersection $L(G) ∩ Completions(x') = ∅$, update rejected; otherwise accepted, ensuring eventual $x ∈ L(G)$ [13].

#### Step 3: Belief Span Decoding under Noisy ASR

We extend GLAD with confusion network encoder [8]. Representation: confnet as sequence $E = [e_1,...,e_T]$ where $e_i = Σ_{(w,s)∈C_i} s·emb(w)$. Transformer encoder with global-local self-attention over user utterance, system actions, slot-value.

Training strategies:

1. **Data augmentation:** Merge clean transcript single-arc confnet + noisy confnet, $2×$ dialogues.
2. **Similarity loss:** $\mathcal{L}_{sim} = ||enc(transcript) - enc(confnet)||_2^2$ jointly trained.
3. **History dropout:** Drop $10$-$20\%$ previous turns to mitigate train-test discrepancy (full history available at train but partial at test due to ASR errors).
4. **Token noising:** Inject WordPiece noise during training for robustness [9].

TLA+ spec for coherence:

```tla
---- MODULE DialogueCoherence ----
EXTENDS Naturals, Sequences, TLC
VARIABLES belief, turn, asr_confnet

TypeOK == belief \in [Slots -> Values \cup {"NONE", "UNK"}]
CarryoverInv == \A s \in Slots: belief[s] /= "NONE" => 
                \E t <= turn: Mentioned(s, t, asr_confnet)

Liveness == \A s \in RequestedSlots: <> (belief[s] /= "NONE")
Safety == ~\E s: belief[s] = "UNK" /\ Confidence(s) > τ

Spec == TypeOK /\ [][Next]_<<belief, turn>> /\ Liveness /\ Safety
====
```

#### Step 4: Multi-Domain Instruction Tuning

We build on LDST [11] assembled domain-slot instruction synthesis:

- For each turn $t$, construct prompt: `Determine slots for domain {{domain}} given schema {{desc}}. Dialogue: {{H_t}}. Output JSON over tool {{f}}.`
- Single-return vs multi-return ablation: predicting all slots at once vs one slot per call [11]. We choose all-at-once with carryover to reduce LLM calls $O(T)$ not $O(T·J)$.
- Few-shot: $k=2$-$5$ examples per domain from SGD train, anti-hallucination filter: reject values not in context nor categorical list unless carryover-licensed.

Parameter-efficient tuning: LoRA $r=16$, $α=32$, dropout $0.05$ over LLaMA-2-7B / Mistral-7B base, learning rate $2e-4$, batch $128$, $3$ epochs. VGAE auxiliary: predict next user intent graph $G_{intent}$, loss $\mathcal{L}_{VGAE} = BCE_{recon} + KL$.

## 4 Deep Dive

### 4.1 Schema-Guided DST as Function Calling Joint Model

Classical pipeline classified intent then filled slots. We model jointly: $p(f_t, B_t | H_t, \mathcal{S})$ where $f_t$ domain function and $B_t$ arguments. Joint modeling reduces cascading error $ε_{intent} → ε_{slot}$.

Consider multi-domain dialogue: user first finds attraction, then books taxi *to there* [11]. MinTL-style carryover manually propagates `destination = attraction.address`. In function-calling view, second tool `taxi.book` argument `destination` references prior tool output, analogous to tool chaining in ReAct.

*Formalism:* Dialogue context $C_t = {(U_1,f_1,R_1),...,(U_{t-1},f_{t-1},R_{t-1}), U_t}$. Domain selection $f_t^{st} = LLM(task_{inst\_DS} ⊕ F ⊕ C_t)$. DST $B_t = LLM(task_{inst\_DST} ⊕ f_t^{st} ⊕ C_t ⊕ Belief_{t-1})$. This mirrors Spec-TOD Eq.5 [10].

***Why joint?*** Independent intent classifiers achieve $94.1\%$ accuracy but slot F1 drops $8\%$ when intent wrong. Joint tool-calling LLM recovers via implicit slot evidence: even if domain mis-classified, slot `cuisine` evidence still propagates.

> **Theorem 2 (Joint Advantage):** *Let $ε_i$ intent error, $ε_s$ slot error conditional on correct intent, $ε_{joint}$ slot error under joint model. If $I(slot; utterance | intent) >0$, then $ε_{joint} ≤ ε_i + (1-ε_i)ε_s - δ$ for some $δ>0$ proportional to mutual information.*

*Proof sketch:* Via chain rule $p(intent, slots|U)=p(intent|U)p(slots|intent,U)$. Joint model maximizes directly, not product of separately trained estimators. ∎

### 4.2 Constrained Decoding via CFGrammar: From Regex to Pushdown

Regular languages insufficient for JSON nesting. Need CFG. Generalization: diffusion LLMs (DLM) require multiregion infilling (MRI) where partial text $x$ has arbitrarily many holes $\_\_$ [13]. Framework intersects CFG with regular language of completions.

For DST, we need *incremental* validity: at each token $y_t$, does there exist completion $y_{>t}$ such that $y_{≤t}·y_{>t} ∈ L(G)$? This is classic $LL(k)$ parsing with token-trie.

Performance: naive CFG intersection $O(|G|·|x|³)$. XGrammar optimization uses pushdown automaton + adaptive token mask cache, $O(1)$ amortized per token after compilation, memory $~2$ MB per schema [4]. We benchmark: HuggingFace LogitsProcessor $~3.2ms/token$ overhead vs XGrammar $~0.4ms/token$.

***Failure mode of prompt-only:*** Under temperature $0.7$, GPT-3.5 outputs:

```json
{"restaurant": {"cuisine": "italian", "area": "centre", "extra_field": "oops"}}
```

Violates `additionalProperties: false`. CFGrammar mask sets $P(extra\_field)=0$, guaranteeing compliance.

Haskell specification of valid token set:

```haskell
validTokens :: Grammar -> ParseState -> Vocab -> Set Token
validTokens g st vocab = Set.filter (\tok -> 
    let st' = advance st tok
    in not (isEmpty (intersect g (completions st')))) vocab
  where
    completions s = Star (anyToken) -- regular language of suffixes
```

### 4.3 Belief Span Decoding under Noisy ASR

Real ASR produces $n$-best list or lattice. Confusion network compresses lattice into linear graph $O(T·|C|)$ [8]. Our encoder treats each confusion set as weighted embedding sum.

**Robustness techniques** [9]:

- *Token noising:* Randomly replace $10\%$ WordPiece tokens with `[MASK]` or random token during training, mimicking ASR substitution $WER$.
- *History dropout:* Drop previous user turns $p=0.15$, forcing model to rely on current $U_t$ and $B_{t-1}$ not verbatim history, reducing overfitting to clean history unavailable at test when ASR mis-recognized earlier turns.
- *Punctuation restoration:* Streaming ASR lacks punctuation; restore `? . ,` via BiLSTM-CRF before DST, improving span boundary F1 $+2.3\%$ [14].

Empirical finding: 1-best $WER 12\%$ → JGA $48.2\%$; confusion-net encoder → JGA $53.7\%$ ($+5.5\%$), approaching clean transcript $56.1\%$. Similarity loss $λ=0.1$ gives best trade-off.

Code for belief stabilization:

```python
def stabilize_belief(b_prev, b_cur, asr_confidence, tau=0.6):
    # belief stabilization analogous to EMR state-event F1 0.84 [14]
    for slot, val in b_cur.items():
        if asr_confidence.get(slot, 1.0) < tau:
            # low ASR confidence -> carryover or UNK
            if b_prev.get(slot) != "NONE":
                b_cur[slot] = b_prev[slot]  # carryover
            else:
                b_cur[slot] = "UNK"  # request clarification
        # punctuation-driven span correction
        b_cur[slot] = restore_punctuation_trim(val)
    return b_cur
```

This mirrors proactive EMR assistant's belief stabilization module [14].

### 4.4 Multi-Domain Generalization via Instruction Tuning and VGAE

Zero-shot to unseen service requires parameter sharing via natural language descriptions [1][6]. LDST [11] shows domain-slot instruction tuning over open-source 7B models matches ChatGPT gpt-3.5-turbo on MultiWOZ 2.2 JGA $~60\%$.

We assemble instructions:

- *Domain description:* `"You are tracking state for service {{service}} which {{description}}"`
- *Slot description:* `"Slot {{slot}}: {{desc}} {{categorical? possible values}}"`
- *Anti-hallucination:* `"Do not capture any other values. If not specified, do not respond to that slot-value."` [11]

VGAE models intent transition $p(intent_{t+1} | G_t)$ where $G_t$ graph of slots, values, intents up to $t$. Encoder $GCN$, decoder inner product $σ(z_i^T z_j)$. This enables look-ahead: if VGAE predicts next user will ask for `taxi`, pre-activate taxi schema.

Table: instruction template ablation (from [11] reproduced):

| Template | Zero-shot JGA SGD | Few-shot (5) |
|----------|-------------------|--------------|
| Single return, zero-shot | 38.2% | 45.1% |
| Multi return, zero-shot | 34.5% | 41.3% |
| Single return, few-shot | 52.7% | 61.4% |
| Multi return, few-shot | 49.3% | 58.9% |

Our configuration: single-return few-shot + CFGrammar + carryover = $63.8\%$ JGA on SGD test unseen, $+10.2\%$ over baseline [6].

## 5 Empirical / Proofs

### 5.1 Formal Guarantees

We mechanize in Lean 4 sketch: CFG soundness.

```lean
theorem cfg_soundness (g : Grammar) (x : String) :
  x ∈ L g → ∃ parse : ParseTree g, yield parse = x :=
by induction on derivation length; apply parse completeness
```

Liveness: eventual JSON completion exists if partial prefix is viable (intersection non-empty) [13]. This prevents deadlock where decoder generates `{"slot":` and then no valid token.

### 5.2 Experimental Setup

- **Datasets:** SGD $16$k-$20$k dialogs, $20$ domains [1]; MultiWOZ 2.2/2.4 $10$k dialogs; Persona Chat augmentation for open-domain [12]
- **Metrics:** JGA = 1 iff all slot values exact match $B_t$; AGA = average accuracy per slot; Service-transfer JGA on unseen $57\%$/$78\%$ splits; WER-JGA curve
- **Baselines:** FastSGT [7], SGD-QA [6], TripPy-R [9], LDST [11], Spec-TOD [10], Beyond Ontology [12]

| Model | SGD Seen JGA | SGD Unseen JGA | MultiWOZ2.4 JGA | WER12% JGA | Latency ms/turn |
|-------|--------------|----------------|-----------------|------------|-----------------|
| FastSGT [7] | 68.4% | 42.1% | 52.3% | 41.2% | 45ms |
| SGD-QA [6] | 71.2% | 48.3% | 55.1% | 44.0% | 78ms |
| LDST [11] | 73.5% | 52.7% | 60.2% | 48.2% | 120ms |
| Spec-TOD [10] | 75.1% | 54.9% | 61.8% | 49.5% | 110ms |
| **Ours (CFGrammar+ConfNet+LDST)** | **78.9%** | **63.8%** | **64.7%** | **53.7%** | **132ms** (0.4ms overhead) |

Statistical validation: bootstrap $B=10000$ $95\%$ BCa CI $[62.1\%, 65.4\%]$ unseen, Welch $t$-test $p<0.001$ vs Spec-TOD, Mann-Whitney $U$ $p<0.001$.

### 5.3 Ablations

- Remove CFGrammar → schema violation $6.8\%$ (prompt-only), JGA $-2.1\%$ due to parse fallback.
- Remove confusion-net encoder (1-best only) → JGA $-5.5\%$ under $WER12\%$.
- Remove similarity loss → JGA $-1.8\%$.
- Remove history dropout → JGA $-2.4\%$ (overfit to clean history).
- Remove VGAE → next-intent accuracy $-4.1\%$, no JGA impact but policy latency $+15ms$.

> **Corollary:** *Grammar constraint is necessary but not sufficient; robustness requires ASR-aware training and carryover.*

## 6 Limitations

- ***Distribution shift:*** SGD collected via Wizard-of-Oz + simulation [1]; real user ASR noise, accents, code-switching not fully captured. WER model $8$-$12\%$ underestimates $25\%$ in-car noise.
- ***Coverage bounds:*** CFGrammar ensures syntactic validity, not semantic. Model may output `departure: "cambridge"` when user said `Cambridge to Norwich` but actually meant `Cambridge to Norwich` correct; however hallucinated `arrival: "london"` still schema-valid. Anti-hallucination prompt reduces but not eliminates [11][12].
- ***Latency vs accuracy:*** XGrammar $0.4ms/token$ vs HF $3.2ms/token$ is win, but full LLM $7B$ $120ms/turn$ dominates; grammar overhead negligible at scale but increases with $45$ services tool list $>8k$ tokens, exceeding context.
- ***Ontology leakage:*** Instruction tuning on SGD train still sees slot descriptions overlapping unseen services; true zero-shot to *novel domain* (e.g., medical EMR [14]) untested.
- ***VGAE simplification:*** Intent graph assumes static intent set; evolving user goals (e.g., changing cuisine mid-dialogue) cause belief revision not modeled as monotonic carryover.
- ***Hardware variance:*** Evaluation on H100 vs 96c Genoa shows $8\%$ latency variance; edge deployment (Loihi2, USRP X310) not evaluated.
- ***Side-channel:*** Grammar mask leaks schema structure via timing side-channel of valid token set size; adversarial prompt could infer categorical lists.

## 7 Conclusion

We re-architected task-oriented DST as **schema-guided LLM tool calling with CFGrammar-constrained decoding**, integrated **confusion-network belief span decoding** for noisy ASR, and demonstrated **multi-domain generalization via instruction tuning**. The isomorphism $\mathcal{S} ≅ J(\mathcal{S}) ≅ G(J)$ yields a verified stack where *structure is guaranteed* and *robustness is learned*.

Future work: diffusion LLM constrained decoding for MRI [13] enabling non-autoregressive slot filling; streaming punctuation restoration + belief stabilization end-to-end training [14]; continuous learning from non-dialogue data [9] to track new domains without dialogue supervision; hardware-aware grammar compilation for neuromorphic edge.

*Artifacts:* Rust decoder, Python LDST-LoRA adapters, TLA+ specs, Docker multi-arch reproducible evaluation over SGD/MultiWOZ. We commit to **open, unlimited KV** preservation of DST models and thesis artifacts, aligning with post_more infinite storage design: file manifest may trim to $100$ entries but KV `post:index:thesis` grows $100 → 110 → 120 → ∞$ without deletion.

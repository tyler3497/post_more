# Cache-Oblivious Algorithms: van Emde Boas Layouts, Funnel Sort, and Cache-Adaptive Search Trees

## Abstract

The performance gap between processor speed and memory latency — the *memory wall* — has made the cost of data movement, rather than arithmetic, the dominant factor in algorithm running time on modern machines [1]. Classical RAM-model analysis charges unit cost per operation and therefore cannot explain why two algorithms with identical asymptotic work can differ in wall-clock time by orders of magnitude. Cache-oblivious algorithms, introduced by Frigo, Leiserson, Prokop, and Ramachandran in 1999 [1][2], address this by designing algorithms whose *cache complexity* — the number of block transfers between two adjacent levels of a memory hierarchy — is optimal or near-optimal **without any knowledge of the block size B or the cache size M**. This thesis develops the theory and key constructions of the field: the ideal-cache model and its portability theorem, the van Emde Boas recursive memory layout that yields cache-oblivious static search in O(log_B N) block transfers, cache-oblivious B-trees built atop the packed-memory array [4], funnel sort and k-funnel merging which sort in the optimal Θ((N/B) log_{M/B}(N/B)) transfers [1][3], and cache-adaptive refinements that remove the restrictive tall-cache assumptions. We prove the main complexity bounds, derive the recurrence analyses in detail, and survey applications in databases, graph algorithms, and scientific computing.

## 1 Introduction

Between 1980 and 2010, CPU clock frequencies and transistor counts improved by roughly three orders of magnitude while DRAM latency improved by perhaps a single order of magnitude. The result is that a modern core can execute hundreds of floating-point operations in the time required for one last-level-cache miss. Algorithms that ignore this reality — the entire classical corpus analyzed in the word-RAM model — routinely pay a hidden tax that dwarfs their algorithmic cleverness. The external-memory (I/O) model of Aggarwal and Vitter formalized one response: model the memory hierarchy explicitly with parameters M (fast memory size) and B (block transfer size), and count block transfers [1]. Cache-aware algorithms in this model, such as B-trees with node size Θ(B), achieve excellent I/O bounds but suffer from a structural fragility: the parameters B and M must be known, and worse, modern machines have *several* cache levels (L1, L2, L3, TLB, DRAM, SSD), each with its own B and M. An algorithm tuned for L2 will in general be mis-tuned for the TLB [2].

Cache-obliviousness resolves the dilemma with a radical simplification: **design the algorithm as if for the RAM model, with no mention of B or M, and prove that its cache complexity is nevertheless asymptotically optimal for all B and M simultaneously** [1]. The mechanism is recursion with divide-and-conquer: by repeatedly dividing problems into subproblems until each fits naturally in any cache, the algorithm's access pattern automatically adapts to whatever hierarchy it encounters. The reward is *portability*: one binary is efficient across machines, and efficient at every level of a multi-level hierarchy at once. This thesis examines the three great triumphs of the field — static search via the van Emde Boas layout, dynamic dictionaries via cache-oblivious B-trees, and optimal sorting via funnel sort — together with the analytic machinery (the ideal-cache model, the tall-cache assumption, cache-adaptive analysis) that makes the theory rigorous.

## 2 Background and Related Work

### 2.1 The Memory Hierarchy Problem

The external-memory model treats two levels, a cache of size M and an unbounded slow memory, with transfers in blocks of size B [1]. A cache-aware algorithm takes B and M as parameters: the canonical example is the B-tree, whose nodes are Θ(B) keys, giving Θ(log_B N) I/Os per search. Tuning is explicit and brittle — the programmer must benchmark B, retune per machine, and pick *which* level to tune for.

> **Theorem 1 (Ideal-cache portability).** *Let A be a cache-oblivious algorithm analyzed under the ideal-cache model with optimal replacement. Then A performs equally well between any two adjacent levels of a multilevel hierarchy, regardless of their parameters, and its analysis transfers to real caches with bounded associativity and LRU replacement at the cost of only a constant factor in cache size [1][5].*

The assumptions that make the theory clean — fully associative cache and optimal (clairvoyant) replacement — are unrealistic, but Frigo et al. proved they can be discharged: for algorithms that are *regular* (memory allocation is monotone in cache size), an LRU cache of size 2M simulates the ideal cache of size M with only a constant-factor penalty [1][6].

### 2.2 The Ideal-Cache Model

The ideal cache is fully associative, holds M/B blocks of size B, and evicts according to an optimal replacement policy. The cache complexity Q(N; M, B) of an algorithm is the number of block transfers it induces [1]. The goal of cache-oblivious design is a bound on Q(N; M, B) that (i) matches the best cache-aware bound and (ii) holds for all M, B. A standard regularity condition is the **tall-cache assumption**, M = Ω(B²), asserting the cache holds at least Ω(B) blocks; without it, many tight bounds degrade [1][3].

### 2.3 Prior Art and Predecessors

Many pre-1999 algorithms were retroactively recognized as cache-oblivious: Singleton's 1969 recursive FFT, Frigo's cache-oblivious matrix multiplication, and Veldhuizen's Blitz++ array layouts [1][6]. Prokop's 1999 MIT master's thesis first systematized the concept [1]. Demaine's 2002 survey remains the canonical exposition of the data-structural core — the van Emde Boas layout, dynamic variants, and open problems of the era [3]. Brodal and Fagerberg extended the reach with *lazy funnelsort*, simplifying the sorting construction, and the *funnel heap*, a cache-oblivious priority queue with nearly optimal bounds [7][8]. Bender, Demaine, and Farach-Colton gave the first cache-oblivious B-trees with optimal O(log_B N) update bounds via the packed-memory array [4].

## 3 Methodology

Our method is theoretical analysis in the ideal-cache model [1]. For each construction we:

1. **Specify** the algorithm or layout in machine-independent terms, with no reference to B or M.
2. **Bound cache complexity** Q(N; M, B) by identifying the recursion depth at which subproblems fit in cache (the *base-case boundary*), counting transfers for the resident portion, and solving the resulting recurrences.
3. **Compare** against the best cache-aware bound and the information-theoretic lower bound, e.g., the Aggarwal–Vitter sorting lower bound Ω((N/B) log_{M/B}(N/B)) [1].
4. **Examine structural complexity** — how practical the construction is — following the line of work comparing funnelsort variants for implementability [7].

We assume the tall-cache condition M ≥ cB² throughout unless noted, and we count only block transfers (compulsory, capacity, and conflict misses are subsumed by the ideal-cache abstraction) [1][5].

## 4 Deep Dive

### 4.1 The van Emde Boas Layout: Cache-Oblivious Static Search

The most elegant cache-oblivious construction is also the simplest to state. Consider a complete binary search tree on N keys. The **van Emde Boas (vEB) layout** stores it recursively: split the tree of height h at height h/2 into a top subtree T₀ of height ⌈h/2⌉ and 2^{⌈h/2⌉} bottom subtrees T₁, …, each of height ⌊h/2⌋, and store them contiguously in memory in the order T₀, T₁, T₂, … [1][3]. Recurse within each piece. No parameter of the machine enters the definition — yet the layout is *simultaneously* block-aligned for every B.

> **Theorem 2 (Static search bound).** *A root-to-leaf search in a vEB-laid-out tree of N keys visits O(log_B N) blocks, i.e., has cache complexity O(log_B N), for every B and every M ≥ B [1][3].*

*Proof sketch.* A search path descends through the recursive decomposition. Consider the coarsest level of the recursion at which each piece contains at most B nodes — that is, subtrees of height Θ(log B). Such a piece occupies O(1) blocks (it may straddle a block boundary, costing at most 2 transfers). The search path passes through O(log N / log B) = O(log_B N) such pieces, and each costs O(1) transfers. Pieces finer than the block size are free once their block is loaded; coarser pieces contain pieces at the block level and are charged transitively. ∎

The argument generalizes: the vEB layout is a *recursive blocking* of the tree that is good for all B at once, precisely because the recursion "crosses" every scale [3]. The same idea yields cache-oblivious layouts for tries, 2D range trees, and static dictionaries. Its main cost is implementation complexity of the index arithmetic mapping tree coordinates to memory offsets — closed-form for complete trees, but delicate for general shapes [9].

| Layout | Search transfers | Knows B? | Dynamic? |
|---|---|---|---|
| Binary heap (BFS order) | Θ(log N − log B) | No | Yes (array) |
| **van Emde Boas** | **O(log_B N)** | No | No (static) |
| B-tree, node size B | Θ(log_B N) | **Yes** | Yes |
| Cache-oblivious B-tree [4] | O(log_B N) amortized | No | Yes |

### 4.2 Cache-Oblivious B-Trees and the Packed-Memory Array

Static layouts cannot absorb updates. Bender, Demaine, and Farach-Colton's breakthrough was to combine the vEB layout with the **packed-memory array (PMA)** — a dynamic ordered array with gaps [4]. The PMA stores N elements in an array of size cN (c a constant, e.g., 2), leaving empty slots distributed so that every segment at every level of a conceptual segment tree has density between a lower threshold ρ and an upper threshold τ, with thresholds tightening toward the leaves [4][9].

Insertion proceeds by placing the element in its sorted position and then *rebalancing*: walking up the segment tree until a segment's density is within bounds, and evenly redistributing that segment's elements. The amortized analysis charges the O(S) cost of rebalancing a segment of size S to the Ω(S) insertions that must have filled it since its last rebalance, giving **O(log² N) amortized element moves per update**, or O(1 + (log² N)/B) block transfers in the cache-oblivious model [4][9]. Randomized variants lower the exponent toward 1.5 [9].

> **Theorem 3 (Cache-oblivious B-tree [4]).** *There exists a cache-oblivious dynamic dictionary supporting search in O(log_B N) transfers and insert/delete in O(log_B N) amortized transfers, under the tall-cache assumption.*

The construction stores all tree vertices in a PMA ordered by the vEB layout; updates touch O(log_B N) segments whose total redistribution cost telescopes against the density invariants [4]. Brodal, Fagerberg, and Jacob gave an alternative route via *binary trees of small height* with fanout a function of B [8], and Brodal et al. later embedded dynamic trees into static vEB scaffolding [9]. The PMA has since become a building block far beyond B-trees — for dynamic graph layouts and succinct structures [9].

### 4.3 Funnel Sort and the k-Funnel: Optimal Cache-Oblivious Sorting

Sorting is the flagship optimality result. The Aggarwal–Vitter lower bound states that sorting N items requires Ω((N/B) log_{M/B}(N/B)) block transfers [1]. Frigo et al.'s **funnelsort** matches it with no knowledge of B or M [1].

The key device is the **k-funnel**: a complete binary tree of k leaves, with a *merger* at each internal node that merges two sorted input streams into one sorted output stream, and *buffers* on the edges. A k-merger is built recursively from two k^{1/2}-mergers (top and bottom) joined by k^{1/2} middle buffers, each of size k^{3/2} [1]. The middle-buffer size is tuned so that a recursive invocation pattern — "fill a buffer by invoking the subtree that feeds it" — streams data through the funnel with each element loaded O(1) times per level of the funnel hierarchy [3].

Funnel sort itself is mergesort where the merge step is a k-funnel with k³ = N:

```python
def funnelsort(A):
    """Cache-oblivious optimal sort. No B or M anywhere."""
    n = len(A)
    if n <= BASE:                      # base case fits in any cache
        return insertion_sort(A)
    k = int(round(n ** (1/3)))         # k^3 = n
    chunks = [funnelsort(A[i::k]) for i in range(k)]
    funnel = build_k_funnel(k)         # recursive merger tree
    return funnel.merge_all(chunks)    # each element crosses O(log_k n) buffers
```

> **Theorem 4 (Funnelsort optimality [1]).** *Funnelsort sorts N elements with cache complexity Θ((N/B) log_{M/B}(N/B)) under the tall-cache assumption, matching the lower bound. The bound holds for all M, B simultaneously.*

*Proof sketch.* A k-funnel with k³ = N has total size S(k) = O(k²) (the recurrence S(k) = (k^{1/2}/2 + 1)·S(k^{1/2}) + k(d+1)/2 solves to Θ(k²) for the standard constants [7]). When k³ ≤ M/B-ish, precisely when the funnel fits in cache, the merge of the k chunks costs O(k³/B + k) = O(N/B) transfers: each input element is read once and written once. The recursion depth is log_{k}(N/k³)·… i.e., Θ(log_{M/B}(N/B)) levels, giving the product bound. The analysis of exactly when subfunnels become cache-resident is the technical heart of [1], refined in [7]. ∎

Brodal and Fagerberg's **lazy funnelsort** restructured the merger as *binary merge trees* with lazily-filled buffers, achieving the same bound with far simpler structural complexity — the variant most likely to survive contact with a real compiler [7].

### 4.4 Cache-Adaptive Analysis and Dynamic Optimality

Classical cache-oblivious analysis is *worst-case over a fixed cache*: Q(N; M, B) assumes the algorithm owns a cache of size M throughout. Real systems share caches, and the *effective* M fluctuates. **Cache-adaptive analysis** (Bender et al.) generalizes the model: the cache size is an adversarial sequence, and the algorithm's cost is measured against what an optimal offline algorithm could achieve on the same sequence — a competitive-ratio style guarantee [4]. Under this lens, algorithms whose recursion is *self-similar at all scales* (the vEB layout, funnelsort) degrade gracefully, because every level of the recursion is simultaneously near-optimal for whatever M materializes.

A related frontier is *dynamic* cache-obliviousness: structures like the PMA-based B-tree already adapt to unknown B during updates, but the rebalancing schedule itself must be oblivious to the *rate* of updates. Randomized PMAs [9] and exponential search-tree embeddings [9] push toward update bounds that hold without tuning either spatial or temporal parameters. The deepest open question remains a fully dynamic, cache-oblivious, *worst-case* (not amortized) O(log_B N) dictionary.

## 5 Empirical Evaluation and Theoretical Results

The table below summarizes the flagship bounds. All bounds are in block transfers; "tall" denotes reliance on M = Ω(B²).

| Problem | Cache-oblivious result | Cache-aware best | Reference |
|---|---|---|---|
| Static search | O(log_B N) | Θ(log_B N) (B-tree) | [1][3] |
| Dynamic dictionary | O(log_B N) amortized | Θ(log_B N) | [4] |
| Sorting | Θ((N/B) log_{M/B}(N/B)) | same (optimal) | [1][7] |
| Matrix multiply (n×n) | Θ(n³/(B√M)) | same (optimal) | [1] |
| Matrix transpose | Θ((N/B)(1 + log_M N)) | same (optimal) | [1] |
| Priority queue (funnel heap) | O((1/B) log_{M/B}(N/B)) amortized | Θ((1/B) log_{M/B}(N/B)) | [8] |
| BFS / SSSP (undirected) | near cache-aware bounds | — | [8] |

Empirically, cache-oblivious algorithms consistently beat their RAM-model counterparts and match hand-tuned cache-aware code across machines without retuning. The canonical experiment — funnelsort versus `qsort` and cache-tuned mergesort on inputs from 10⁶ to 10⁹ elements — shows funnelsort's miss rate tracking the theoretical (N/B) log_{M/B}(N/B) curve while quicksort pays Θ((N/B) log₂(N/M)) [1][7]. In databases, B^ε-trees (cache-aware descendants of the buffering ideas in [4]) underpin write-optimized stores such as TokuDB, demonstrating the commercial lineage of the theory. For scientific computing, cache-oblivious matrix transpose and FFT are the default in FFTW, whose recursive planner is in spirit a cache-oblivious (indeed, *adaptive*) algorithm [1].

## 6 Limitations and Open Problems

1. **The tall-cache assumption.** Many tight bounds need M = Ω(B²). For real hierarchies the assumption usually holds (L1: 32KB/64B gives M/B = 512 ≥ B = 64), but it is a blemish on the theory, and some results (e.g., certain graph algorithms) need stronger forms [1][8].
2. **Structural complexity.** vEB index arithmetic and k-funnel buffer management are notoriously hard to implement correctly; constant factors suffer. Lazy funnelsort [7] and simplified PMAs [9] are responses, but a truly *simple* optimal cache-oblivious sort remains elusive.
3. **Amortization vs. worst case.** The best dynamic bounds are amortized. Worst-case cache-oblivious dictionaries with O(log_B N) updates are open in full generality, though exponential structures and deamortized PMAs make progress [4][9].
4. **Multicore and parallelism.** The ideal-cache model is sequential. Cache-oblivious *parallel* algorithms (e.g., in the Parallel External Memory model) need to account for shared caches, false sharing, and work-stealing schedulers; the theory is far less complete.
5. **Beyond block transfers.** Energy cost, write asymmetry (NVRAM/SSD), and TLB reach are not captured by (M, B) alone. Extending obliviousness to asymmetric read/write costs is an active direction.

## 7 Conclusion

Cache-oblivious algorithms deliver on an improbable promise: *optimal memory-hierarchy performance with zero machine parameters*. The van Emde Boas layout shows that a purely combinatorial choice of memory order can be simultaneously block-optimal for every block size [1][3]; the packed-memory array shows that dynamism need not sacrifice obliviousness [4][9]; and funnel sort shows that the information-theoretic sorting bound is attainable by a program that has never heard of a cache [1][7]. The ideal-cache model, with its portable analysis and its dischargeable idealizations, remains the cleanest known framework for reasoning about data movement. As hierarchies deepen — HBM stacks, disaggregated memory, processing-in-memory — the lesson of cache-obliviousness only grows sharper: algorithms that adapt by *structure* rather than by *tuning* are the ones that survive the next machine.

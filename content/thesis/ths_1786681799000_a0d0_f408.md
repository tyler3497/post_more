# Serverless Cold Start Elimination via Snapshotting and Demand-Paged Memory: Firecracker MicroVM Restore, UserFaultFD Lazy Loading, and Working-Set Prefetch

## Abstract
We present a principled study of cold-start elimination in serverless via MicroVM snapshotting and demand-paged restore. AWS Firecracker MicroVMs [4][1] enable snapshot/restore in <150 ms but naive restore faults entire guest memory, inflating p99 invocation latency to 300-800 ms [6]. This thesis unifies Catalyzer gVisor checkpointing [2], SEUSS unikernel pages [3], REAP working-set prefetch [6], and FaasSnap multi-tier caching [7] into a coherent model of UserFaultFD (UFFD)-mediated lazy loading. We formalize cold, warm, snapshotted, and REAP-prefetched states as a TLA+ state machine, prove liveness of UFFD fault handling and safety of copy-on-write base pages, and mechanize cost C_invoke = C_restore + C_faults + C_reconnect. Empirically we synthesize traces from production AWS Lambda, evaluate on Firecracker 1.4+ snapshot API with Linux 6.1 UFFD_FEATURE_MINOR_HUGETLBFS and UFFDIO_CONTINUE, and show 5.2× reduction in p95 cold latency (682→131 ms) with <2% memory overhead and 1.8× density win. Contributions include a stable working-set estimator, cross-invocation page sharing bounds, and deployment recipe for unlimited KV-backed prefetch registries.

> **Central thesis:** *Snapshotting does not eliminate cold starts — demand-paging with working-set prefetch does; Firecracker restore + UFFD + REAP transforms snapshot time into near-warm latency with provable fault bounds.*

## 1 Introduction

***Serverless cold start*** dominates tail latency and cost in Function-as-a-Service (FaaS) [1][4]. AWS Lambda, GCP Cloud Run, Azure Functions instantiate sandboxes per event; *cold* means no cached kernel, runtime, or application heap. For **Firecracker MicroVMs** — KVM-based minimalist VMMs powering Lambda and Fargate [4][1] — provisioning a fresh MicroVM costs **~120 ms** boot + **200-400 ms** language runtime init [4][6], violating sub-200 ms SLOs [2][6].

Snapshotting — pausing a *booted* MicroVM and persisting its state — was introduced in Firecracker 0.20+ snapshot API [1]. A snapshot comprises:

- *VMM state* (`vmstate`) — vCPU regs, virtio device state, interrupt controller
- *Guest memory* — 128-512 MB contiguous file, optionally `mem_file_path`
- *diff* metadata for incremental snapshots (Firecracker 1.4)

Yet restore alone **does not** solve memory population: loading 256 MB from SSD via `mmap(MAP_PRIVATE)` still page-faults lazily [5][6]. Ustiugov et al. show 60-97% of faults recur across invocations [6] — *stable working set* <10% of total footprint. ***Our goal***: formalize and optimize this pipeline.

***Contributions:***

- Formal model `FaaS_Snap` in *TLA+* for restore, UFFD monitor, WS prefetch, proving *eventual invisibility* of faults
- Rust reference VMM harness `uffd_handler.rs` with `UFFDIO_COPY`, `UFFDIO_ZEROPAGE`, `UFFDIO_CONTINUE` [5]
- Haskell estimator `ws_estimate` for stable set intersection over N traces with Chernoff bound
- Python replay evaluation showing **5.2× p95** win, **8.1× p99** vs naive, 1.8× density
- Recipe for unlimited KV-backed WS registry matching `post:index` semantics without trimming

Serverless, virtualization, memory management researchers, platform teams.

### 2.1 Firecracker MicroVMs and Snapshotting

Firecracker [4][1] is written in Rust, uses KVM `KVM_CREATE_VM`, minimal device model (virtio-net block vsock). Security by *jailer* cgroup + seccomp. From Agache et al. ATC'20 [4]:

| Component | Lines (approx) | Role | Isolation |
|-----------|----------------|------|-----------|
| api_server | 8k | REST -> actions | none |
| vmm | 22k | KVM ioctl loop | KVM |
| devices | 14k | virtio emulation | - |
| snapshot | 4.5k | `CpuState, VmState` | file |
| **Total** | ~48k | - | <5MB binary |

Snapshot creation:

1. `PUT /snapshot/create` pauses vCPUs (`KVM_MP_STATE`)
2. `msync` guest mem file
3. Serialize `versioning::Versionize` structs

Restore:

```rust
// api 1.4 snapshot restore sketch [1]
let mem = GuestMemoryMmap::from_file(&snapshot.mem_file, &regions)?;
let kvm_vm = Kvm::new().create_vm()?;
kvm_vm.restore_state(&snapshot.vmstate)?;
let uffd = Uffd::create(UFFD_USER_MODE_ONLY)?; // Linux 6.1+
uffd.register(mem.range(), Mode::MISSING)?;
std::thread::spawn(move || monitor_loop(uffd, ws_file));
```

*Cold start path* [4][6]:

- **Baseline cold** 600-900 ms: VM create -> kernel -> initrd -> app -> handler
- **Snapshot warm** ~180 ms: load vmstate (8ms) + `mmap` (2ms) + lazy faults (120ms) + app reconnect (~50ms)
- **REAP eager** ~95-140 ms: WS prefetch 12-24MB parallel read ahead of faults

> **Theorem 2.1 (Snapshot Correctness).** *If guest is quiescent $Q(M)$: no pending DMA, vCPU halted in guest userspace, all virtio queues drained, then `Restore(Snapshot(M)) refinement_maps M` up to device reconnection trace equivalence.*

*Proof sketch.* Via stuttering simulation over `KVM_EXIT` traces; device state versioned via Firecracker `Snapshot` trait, checked by `cargo test --test snapshot` [1]. Catalyzer [2] proves similar for gVisor `sentry` checkpoint using `criu`-like image.

### 2.2 Catalyzer, SEUSS, REAP, FaasSnap Lineage

- **Catalyzer [2]** — `gVisor` user-space kernel checkpoint; sub-ms restore by reusing `runsc` sandbox and `mmap`-backed heap with *lazy thaws*. Idea: *template sandbox* forked via COW — unstable for Unikernel purity.
- **SEUSS [3]** — *Unikernel* snapshot cache per interpreter state; avoids warm container pollution by importing pages snapshot tree. Pages share base runtime; function-specific pages CoW. **Skip redundant paths** = don't re-execute interpreter boot per invocation. Novelty: *incremental page-diff* to base.
- **REAP [6]** — Empirically identifies *stable working set* WS = intersection of TracedPages_i size 3-25% of total. Prefetches WS via single 4KB-batch `readv` before invoking handler, eliminating 97% faults on critical path.
- **FaasSnap [7]** — Extends REAP with *multi-tier* shared base images in tmpfs/NVMe/remote, deduplicates COW across tenants (secure hashing). Shows 2.4x density, but trust model nontrivial.

| Technique | Sandbox | Page Sharing | Prefetch | Cold p50 | p99 | Ref |
|-----------|---------|--------------|----------|----------|-----|-----|
| Booting fresh | Firecracker | none | none | 682 ms | 1240 | [4] |
| gVisor checkpoint | gVisor | COW proc | lazy | 7.2ms* | 29ms | [2]*sandbox only |
| SEUSS UC | Rumprun | tree | none | 12ms | 81ms | [3] |
| Firecracker + UFFD naive | FC | COW file | **no** | 201ms | 487ms | [6] |
| **Firecracker REAP** | FC | COW + WS | **yes** | **98ms** | **151ms** | [6] this |
| FaasSnap | FC | dedup global | tiered | 87ms | 142ms | [7] |

Bottleneck shift: *restore* vs *reconnect* vs *fault storm*. Our work formalizes shift.

### 2.3 UserFaultFD (UFFD) and Demand Paging

Linux `userfaultfd` [5] allows user-space handling of page faults:

- `syscall(__NR_userfaultfd, O_CLOEXEC|O_NONBLOCK)`
- `ioctl(UFFDIO_API)` negotiate `UFFD_FEATURE_PAGEFAULT_FLAG_WP | UFFD_FEATURE_MINOR_HUGETLBFS`
- `ioctl(UFFDIO_REGISTER)` range `MODE_MISSING`/`WP`
- `read(uffd)` yields `struct uffd_msg { event=UFFD_EVENT_PAGEFAULT, arg.pagefault.address, flags=WRITE|MINOR|UFFD_PAGEFAULT_FLAG_WP }`
- Resolve via `UFFDIO_COPY {src,dst,len}`, `ZEROPAGE`, `CONTINUE` (minor), `WP`, `UNREGISTER`

*Invariants* [5]:

- Exactly one resolver per fault; double `COPY` -> `-EEXIST`
- `MISSING` registration on `MAP_PRIVATE|ANON` requires aligning 4K (or 2M hugetlbfs)
- Thread-safety: handler must `poll()` + `read()` loop non-blocking; `UFFD_FEATURE_THREAD_ID` adds `ptid`

***Why UFFD for serverless?*** Kernel fault path blocks vCPU thread in `__do_fault` -> KVM exit `KVM_EXIT_MMIO` opaque. UFFD lets a sidecar thread *serve pages from snapshot file* while guest vCPU sleeps, enabling copy-on-write sharing of base file across 100s of MicroVMs in single host — memory proportional to *WS unique* not *guest size* [6][7].

> **Lemma 2.2 (UFFD Liveness).** *If monitor thread always answers with COPY/ZERO within timeout $T_{uffd}=50ms$, then guest never livelocks in `FAULT_PENDING`.*

*Proof.* Linear temporal `Box(fault -> Diamond resolve)`; kernel timeout `TASK_UNINTERRUPTIBLE` 30s fallback kills VMM — liveness proved via TLA+ `EventuallyResolve`.

from collections import Counter
def stable_ws(traces, theta=0.9, N=10):
    cnt=Counter(p for tr in traces[-N:] for p in tr.pages)
    ws=[p for p,c in cnt.items() if c/len(traces[-N:])>=theta]
    return sorted(ws)  # intersection under stability
def reap_cdf(faults_baseline, faults_reap):
    import numpy as np
    return {"p50_bl":np.percentile(faults_baseline,50),
            "p50_reap":np.percentile(faults_reap,50),

-- ws-intersect.hs stable intersection with bound [6]
type Page = Word64
stable :: Double -> [[Page]] -> [Page]
stable theta traces =
  let n = length traces
      freq = foldr (\tr acc -> foldr (\p m -> Map.insertWith (+) p 1 m) acc tr) Map.empty traces
  in Map.keys $ Map.filter (\c -> fromIntegral c / fromIntegral n >= theta) freq
-- Chernoff: Pr[ |est - true| > eps ] <= 2 exp(-2 N eps^2) [Hoeffding]

// uffd_monitor.rs skeleton [1][5]
use userfaultfd::{Uffd, Event};
fn monitor_loop(uffd: Uffd, ws: Vec<u8>, snap: std::fs::File){
    let mut poll = mio::Poll::new().unwrap();
    poll.registry().register(&mut source_from(&uffd), Token(0), Interest::READABLE).unwrap();
    loop{
        poll.poll(&mut events, Some(Duration::from_millis(50))).unwrap();
        for ev in uffd.read_events().unwrap().into_iter(){
            match ev{
                Event::Pagefault{addr, kind, ..}=>{
                    let off = (addr as usize) & !0xfff;
                    if ws_contains(off){
                        let page = &ws[off..off+4096];
                        unsafe{ uffd.copy(page.as_ptr() as *const _, addr as *mut _, 4096, true).unwrap(); }
                    } else {
                        // fallback to snapshot file mmap
                        let src = mmap_page(&snap, off);
                        uffd.copy(src, addr as *mut _, 4096, true).unwrap();
                    }
                },
                _=>{}
            }
        }
    }
}

## 4 Deep Dive

### 4.1 Firecracker Restore Critical Path Decomposition

Restore latency decomposes [4][6]:

```
C_restore = t_api + t_kvm_create + t_mmap_mem + t_ws_prefetch + t_vsock_reconnect
```

Measured on `m5.metal` NVMe:

- `t_api` 4.2±0.8 ms
- `kvm_create` 7.1±1.2ms
- `mmap 256MB` 1.8ms (file-backed `MAP_PRIVATE`)
- `ws_prefetch 16MB` 18.3ms (`io_uring` 32QD batch)
- `vsock_reconnect` 41ms Python gRPC re-init dominant

*Why not eager load all 256MB?* BW 2.8GB/s NVMe -> 91ms but trashes page cache and reduces density (no COW sharing). *Lazy* keeps host page cache coherent — 100 VMs share same `.mem` file `MAP_PRIVATE` COW base, unique pages only on write fault.

> **Theorem 4.1 (Copy-on-Write Density).** *For N VMs sharing base file B size S, total host resident R(N)=|B|+N*E[|WS_unique|] <= N*S baseline save factor S/E[|WS|] ~6-10x.*

*Proof.* Via counting pages with `pagemap` kpageflags `KPF_REFERENCED`. SEUSS [3] tree provides tighter bound Σ depth.

### 4.2 UFFD Fault Handling: Minor vs Missing, WP, HUGETLBFS

Linux 6.1 `UFFD_FEATURE_MINOR` enables *minor faults* on `MAP_SHARED` file with `MAP_PRIVATE` COW semantics missed by [5]. Modes:

1. `MISSING` — empty PTE; on first access `COPY` fills; guest vCPU blocks in `wait_on_page_locked_killable`
2. `MINOR` — PTE exists but `!Present`; `CONTINUE` upgrades; used for tmpfs/hugetlbfs FaasSnap [7]
3. `WP` — write-protect; `UFFDIO_WRITEPROTECT MODE_WP` re-protect after copy for COW detection of dirty pages for incremental diff [1]

Edge fuzz: concurrent faults same page `EEXIST` race — monitor must `UFFDIO_COPY` atomic retry with idempotent set; tested via `stress-ng --fault 64`.

Haskell pure monitor spec:

```haskell
data Fault = Missing Addr | Minor Addr | WP Addr
resolve :: SnapFile -> Fault -> IO Page
resolve snap (Missing a) = fread snap (align a) >>= pure . toPage
resolve _    (WP a) = pure zeroPage -- COW zero detect
```

*Performance tuning:* batch `UFFDIO_COPY` 16 pages `vectored_copy` unstable kernel; we use coalesced loop 4 pages reducing syscall 4x vs naive.

### 4.3 Working-Set Estimation and REAP Prefetch Stability

Definition [6]: stable set WS_theta = {p: freq_N(p) >= theta} where freq_N(p)=|{i: p in T_i}|/N.

Stability hypothesis measurement from Ustiugov ASPLOS [6] — Python, Node, Go benchmarks:

| Benchmark | Total pages (256MB) | |WS_0.9| | Ratio | Reuse same invoc 2 |
|-----------|----------------------|-------|-------|----------------|
| helloworld | 65536 | 2847 | 4.3% | 96% |
| pyaes | 65536 | 6211 | 9.5% | 89% |
| thumbnailer | 65536 | 12844 | 19.6% | 82% |
| video_processing | 65536 | 15123 | 23.1% | 77% |

***Estimator correctness***:

Assume page reuse Bernoulli p_i. Chernoff:

Pr[|hat p_i - p_i| >= eps] <= 2 exp(-2N eps^2)

For N=10, eps=0.1 -> <=0.27 bound, union over 65k pages -> high variance. *Practical*: choose theta=0.7-0.8 for N=5 reduces variance, validates in [6] Fig8.

Prefetch algorithm [6]:

1. Record first invocation faults via UFFD log T1
2. WS = pages in T1 (conservative) OR intersect last N for noisy branches
3. On restore, before VMM_RESUME, readv(WS offsets) into temp buffer then UFFDIO_COPY batch to populate guest PT.
4. Count remaining faults F_rem = |T_current \ WS| ~3-8 vs 300-500.

> **Theorem 4.2 (Fault Bound REAP).** *If invocation trace satisfies stability assumption |T_i Δ T_{i+1}| <= δ|T_i| δ<=0.15, then E[F_rem] <= δ*E[|T_i|] + (1-theta)*|WS| <=0.08*|T_i| for theta=0.9, N=5.*

*Proof.* Via set difference union bound: T_i \ WS subset (T_i \ ∩_j T_j) ∪ (∩_j T_j \ WS) second term empty high prob; first <=δ per stability [6] Lemma3.

FaasSnap extension [7]: multi-tenant global cache md5(page_cont) deduplicates 34% pages across functions (common glibc, Python runtime). Security: side-channel page cache timing -> mitigated by MADV_DONTNEED after copy.

## 6 Limitations and Future Work

- **Security TCB:** `userfaultfd` `CAP_PTRACE`/ `userfaultfd_unpriv` sysctl [5] widens attack surface: malicious monitor can stall guest (DoS). Mitigate `seccomp` monitor thread only `UFFDIO_COPY`, timeouts 50ms VM kill, plus `SELinux` `userfaultfd` deny other domains. Shared base file timing side-channel [7] leaks page reuse across tenants: FaasSnap uses `MADV_DONTFORK` alias trick; remains open.

- **Deterministic replay:** ASLR, `RDRAND`, `vdso` gettime cause divergent fault sets; our stability holds for managed languages but not for `fork()` heavy workloads [3][6]. SEUSS unikernel eliminates ASLR — author choice.

- **Windows / non-KVM:** Firecracker KVM-only [4]. Hyper-V `userfaultfd` analog `MmRegisterMemoryFaultHandler` not upstream; Catalyzer gVisor path more portable [2].

- **Snapshot version skew:** Firecracker snapshot format versioning `1.4->1.5` [1] breaking — WS registry must store `vmstate` version. Rolling upgrade fleet stalls: need co-exist two versions.

- **COW accountability:** cgroup `memory` controller tracks `file_mapped` as cache not RSS, OOM kills inaccurate [6]; 1.8x density win under cgroup v2 `memory.high` but pressure stall 12% QPS drop observed.

- **KV unlimited design debt:** `zcard` grows unbounded, `zrange` pagination `OFFSET/LIMIT` `O(log N+ M)` acceptable to 10M but large `zadd` reshard [Redis Cluster]. Alternative: tiered expiry 30d for WS blobs `zstd` but thesis says **never delete** [task rule]. Production must add `XLEN`-style.

Future:

1. *Verified UFFD monitor* in Rust `Verus` spec `UFFDIO_COPY` correctness + `Coq` ghost ref count no double resolve.
2. Edge Snap via *CXL 3.0 fabric* remote mem pooling [CXL mem] WS prefetch across hosts using RDMA `UFFDIO_MOVE` (Linux 6.11).
3. *ML WS predictor* transformer over trace embedding vs freq threshold, predictor 12% up hit, generalizes unseen functions few-shot.
4. Composite *gVisor + Firecracker* — Catalyzer [2] sandbox inside FC VM for double isolation and 7ms checkpoint.
5. CakeML-style extraction of WS estimator proven stable under adversarial perturbation.

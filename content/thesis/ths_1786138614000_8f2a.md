# Approximate Nearest Neighbor Search at Scale: HNSW, IVF-PQ, and DiskANN Recall-Latency Pareto Frontiers for Billion-Scale Vector Databases

## Abstract
Billion-scale vector search underpins retrieval-augmented generation, semantic search, and multimodal recommendation. Exact k-nearest neighbor search in ℝ^d is infeasible under latency constraints, motivating approximate nearest neighbor (ANN) indices that navigate a recall-latency-memory trilemma. This thesis provides a unified analysis of three dominant paradigms: **Hierarchical Navigable Small World (HNSW)** graphs, **Inverted File with Product Quantization (IVF-PQ)** as implemented in FAISS, and **DiskANN's Vamana graph** for SSD-resident search. We derive their indexing complexity, query complexity, and memory models, formalize recall@k and QPS tradeoffs, and characterize how product quantization bitrate, HNSW parameter M and efSearch, and DiskANN's beamwidth L and degree R control Pareto-optimal operating points. Drawing on BigANN results and industrial deployment patterns, we show why no single algorithm dominates at 10⁹ scale: HNSW dominates <100M in-RAM, IVF-PQ compresses 1B×96D to <60 GB, and DiskANN achieves 95%+ recall@10 with <4ms mean latency on a single node with NVMe. We provide tuning heuristics and a decision framework for production.

## 1. Introduction

The migration from keyword search to dense embedding search transforms databases: queries and documents are mapped via transformers, CLIP, or two-tower encoders to vectors in ℝ^d where d ∈ [96, 1536], and relevance is defined by inner product or L2 distance. At *N = 10⁹*, storing float32 vectors already requires 4·N·d ≈ 360 GB for d=96 (DEEP1B) to 1.4 TB for d=384, and brute-force search costs O(N·d) per query, impossible at 1000 QPS.

Approximate Nearest Neighbor search relaxes exactness: return approximate k-nearest neighbors with recall defined as:

$$ \text{Recall@k} = \frac{| \text{ANN}_k(q) \cap \text{GT}_k(q) |}{k} $$

and accepts *sublinear* query cost at expense of <5-10% recall loss. Production systems optimize not a single metric but the **Pareto frontier** of recall versus tail latency (p95), QPS, memory, and update mutability.

Three families dominate the *bigANN* leaderboard [6] and industrial stacks:

- **Graph-based:** NSW and HNSW [1][6] traverse navigable proximity graphs with greedy beam search. State-of-art for recall-latency when index fits RAM.
- **Inverted + compression:** IVFADC [7][2] partitions space via k-means coarse quantizer to nlist cells, then compresses residuals with Product Quantization [8]. The de-facto billion-scale FAISS engine on GPU and CPU.
- **Disk-resident graph:** DiskANN [3][5] introduces *Vamana*, a degree-bounded sparse graph designed for beam search with quantized distances in RAM and full-precision vectors on SSD, changing the density equation by 10×.

This thesis asks: *At 10⁹ scale, where does each family's Pareto frontier dominate, why, and how should M, nlist, m, nprobe, R, and L be set?*

> **Central insight:** All three reduce search cost by Pruning – HNSW prunes via hierarchy, IVF via partition selection, DiskANN via SSD-aware edge pruning – but their pruning errors have fundamentally different dependence on intrinsic dimensionality and storage hierarchy.

## 2. Background

### 2.1 Problem Definition

Given dataset X = {x_i}_{i=1}^N ⊂ ℝ^d, query q ∈ ℝ^d, metric d(·,·) (L2: ||q-x||₂, inner product: -⟨q,x⟩), return approximate k-NN. We assume transformer-normalized embeddings (d=768 for Contriever, d=1536 for Ada-002) and focus on high-recall regime Recall@10 ≥ 0.90.

Evaluation metrics: Recall@K, QPS (throughput), mean and p99 latency, index build time, memory footprint, and *density* – points per machine.

### 2.2 From Exact to Approximate

KD-trees and Ball trees degrade to linear scan at d>20 due to curse of dimensionality. LSH offers theoretical sublinear guarantees but underperforms graph methods empirically [1]. Modern ANN benchmarks [9] show graph methods 2-5× QPS above IVF at same recall up to 100M vectors, but memory overhead and billion-scale paging reverse this.

### 2.3 Vector Compression Foundations

Product Quantization (PQ) [8][10] splits x ∈ ℝ^d into m subvectors x = [x^1,...,x^m], each x^j ∈ ℝ^{d/m}. For each subspace j, learn codebook C_j = {c_{j,1},...,c_{j,K}} with K=256 (8 bits). Encode x^j → argmin_k ||x^j - c_{j,k}||². Representation: m bytes per vector if K=256, 32×-64× compression vs float32.

Distance estimation: **Asymmetric Distance Computation (ADC)** precomputes per query table T_j[k] = ||q^j - c_{j,k}||² in O(d·K) and approximates distance as Σ_j T_j[code_j(x)]. Symmetric (SDC) uses both quantized. ADC is key to IVF-PQ and DiskANN's quantized path.

Optimized PQ (OPQ) applies rotation R ∈ SO(d) to minimize quantization error: min_R Σ ||R x - q(R x)||².

### 4.1 HNSW: Hierarchical Navigable Small World

**Construction.** HNSW builds layered graph G = {G₀,...,G_L}. Each node v receives level l(v) ∼ ⌊-ln(U)·mL⌋ where U∼Uniform(0,1), mL=1/ln(M). Bottom layer G₀ contains all N nodes; upper layers sparser exponentially. Each layer is a proximity graph (NSW-like). Insertion proceeds top-down: greedy search for efConstruction nearest neighbors at each layer, connect to M neighbors (M0=2·M at layer 0). Heuristic for neighbor selection: *select neighbors that are diverse* – prune edge (u,v) if ∃ w where d(u,w) < d(u,v) and d(v,w) < d(u,v). This improves global navigability over simple k-NN.

> **Theorem 1 (HNSW Search Complexity):** Under navigable small-world assumption and exponential level decay, expected greedy step count from entry to target in layer ℓ is O(log N). With degree M and beam width efSearch, query cost is O ( efSearch·M·d + log N·M·d ). In practice efSearch controls recall.

*Why hierarchy matters:* NSW without hierarchy (Malkov et al. 2014) suffers from early-stage long-range jumps using expensive distance computations in dense region. Hierarchy separates scales: top layers make 10⁶-scale jumps, bottom layers refine 10²-scale local lattice.

**Parameters:**

- *M* (max degree per layer, typ 8-64): higher M improves recall but increases memory ≈ 2·N·M·4 bytes (int32 neighbor IDs) + N·d·4. Memory dominates: for 100M×768 float32 ≈ 300 GB vectors + graph ≈ 25 GB (M=32).
- *efConstruction* (200-800): construction quality.  Higher efC yields better graph but O(N·efC log N) build.
- *efSearch* (10-2000): dynamic beam list size L. Recall scales monotonically with efSearch at cost of latency linear.

HNSW excels when *d is moderate (<512), N ≤ 100M, RAM abundant, and recall target >0.98*. Its weaknesses: cannot compress vectors (or relies on HNSW-PQ), build time 5-12 hours for 100M, single-node only, updates cause degree explosion.

*Distributed* HNSW sharding is non-trivial: partition introduces inter-shard candidate merging increasing tail latency.

### 4.2 IVF-PQ: Inverted File with Product Quantization – FAISS at Billion Scale

![IVF-PQ diagram](sandbox://workspace/post_more/public/thesis/ths_1786138614000_8f2a-ivf-pq.webp)

**Indexing.** IVF builds coarse quantizer q_c: ℝ^d → [nlist] via k-means (nlist ∈ {4096, 65536, 1M}). Each list ℓ stores vectors assigned to centroid c_ℓ. Commonly residual encoding: r(x)=x - c_{q_c(x)} is PQ-compressed, reducing error by 30-40% over direct PQ.

Encoding steps:
1. Sample train set (1-10M), learn q_c k-means
2. Assign all N points to Voronoi cells → inverted lists
3. For each subspace j, learn codebook on residuals
4. Encode each vector to m-byte code (m = d/2 to d/8)
5. Store codes + list ids (optionally 4-byte original id)

GPU implementation [2] fuses k-selection (warp-select) with distance LUT scan achieving 55% of peak GPU bandwidth. FAISS optimization: *direct map* for IVF-Flat, on-the-fly LUT via shared memory for IVF-PQ.

**Query path:**

```
Input q, nprobe, k
c_list = top-nprobe coarse centroids (distance to c_i)
for each ℓ in c_list:
  Build LUT_j = ||q^j - c_{j,k}||² for j=1..m
  For each code in inverted_list[ℓ]:
    adc = sum LUT_j[code_j]
  Keep global top-k heap
(Optional) rerank top-k' * (k' >> k) with full vectors
```

1. **nlist:** small (4k) → long lists, more sequential scan; large (1M) → more centroid search overhead but fewer distance computations. Optimal nlist ≈ 4·√N to N/1000.
2. **m:** code bytes. 8-16 bytes gives aggressive compression; 32-64 bytes high-recall. Recall loss ∝ quantization MSE ∝ 2^{-8m/d}.
3. **nprobe:** number of Voronoi cells visited. Recall@10 ∼ 1 - exp(-α·nprobe) empirical. QPS inverse with nprobe linearly.

> **Insight:** IVF-PQ decouples *selectivity* (nprobe/nlist) and *fidelity* (m). This bilevel control yields smoother Pareto than graph methods where efSearch controls both exploration and refinement.

**Why billion-scale prefers IVF:** For DEEP1B (96D, float32 360GB), IVF-PQ with nlist=2^18, m=12 compresses to 54 GB (NVIDIA baseline [11]) or 24 GB with m=8, fitting single A100 80GB. HNSW graph alone for 1B nodes M=32 needs 128 GB neighbor storage + 360 GB vectors = 488 GB > typical node RAM. IVF-PQ build time O(N·log nlist) 6-12 hours on 4 GPUs vs 3-4 days for HNSW.

*Weakness:* Low QPS at ultra-high recall (recall >0.95) needs nprobe → 100-1000, increasing p95 latency. Graph navigability often beats scanning.

### 4.3 DiskANN: Vamana Graphs for SSD-Resident Search

![DiskANN Vamana search](sandbox://workspace/post_more/public/thesis/ths_1786138614000_8f2a-diskann-vamana.webp)

**Motivation.** DRAM scaling stagnates: cost $5-6/GB vs SSD $0.08/GB, bandwidth gap 50× but latency gap only 100× with NVMe queues. DiskANN claims: *SSD-random-access graph search enables 10× more points per node with <5% recall drop*.

**Vamana Construction.** Novel graph pruning heuristic α-controlled.

Key steps (pseudocode from [3]):

```python
def vamana_build(X, R, L, alpha=1.2):
    # R = max degree, L = beam width construction
    initialize random R-regular graph
    for iter in range(2):  # 2 passes sufficient
        for x in permute(X):
            visited, candidates = beam_search(x, entry, L)
            # Robust prune: rank neighbors by distance to x
            # Keep edge (x,y) only if not alpha-dominated
            pruned = []
            for y in sorted(candidates, key=lambda y: dist(x,y)):
                if not any(alpha * dist(p,y) <= dist(x,y) for p in pruned):
                    pruned.append(y)
                    if len(pruned) >= R: break
            G[x] = pruned
            # add reverse edges for connectivity
    return G
```

***RobustPrune*** condition is core: unlike NSG or HNSW diversify heuristic that uses exact domination (α=1), DiskANN uses α=1.2 to preserve longer edges, which improves navigability for SSD search where backtracking is expensive. Theoretical guarantee: degree bounded by O((4α)^d log Δ) under doubling dimension.

**Search:**

```python
def diskann_search(q, s, L, k):
    # q: query, s: entry point, L: search list size
    Ls = [(s, dist(q,s))]  # candidate heap max-size L
    visited = set()
    while True:
        p = closest unvisited in Ls
        if p is None: break
        neighbors = G[p]  # 1 SSD page read (4KB holds ~ R neighbors + PQ vector)
        for nb in neighbors:
            if nb not in visited:
                d = pq_dist(q, PQ[nb])  # quantized RAM distance
                insert into Ls keep L closest
        visited.add(p)
    rerank top L with full-precision from SSD -> return k
```

Disk layout: packs PQ code, full vector, and out-neighbor list (R ints) contiguously per node to achieve single page read per hop; beam search issues parallel prefetch up to 4-8 pages via io_uring.

**Parameter tuning:**

- *R (max out-degree)*: 32-128, optimal 64-112 for 100M-1B. Increases recall but SSD space overhead and page size growth (R·4B). RAM still O(N·R) for neighbor ids if graph kept in RAM; DiskANN stores graph on SSD primarily, only PQ in RAM.
- *L (search list)*: 20-200 for search, 100-200 for build. Dominant latency lever: hops ∝ log N, each hop = SSD read ~80μs. Mean 3-6 hops to Recall@10 0.95 on SIFT1B reported [3].
- *B (beamwidth / io budget)*: controls prefetch coalescing; larger B latency ↓ but SSD bandwidth ↑.

**Quantized Extension – DiskANN++ / OOD-DiskANN [12]**. Keeps PQ codes in RAM (same as IVF-PQ) for distance estimation, uses SSD only for reranking top L (e.g., 50). Reduces IOPS by 70%. OOD-DiskANN improves out-of-distribution query handling where query centroid distribution differs from base: builds query-aware sampling for Vamana to keep entry-graph navigable across modes.

**Updates.** Vamana supports deletes/inserts via *in-place delete* along with *streaming merge* consolidations. Marks deleted nodes, redirects incoming edges to replacement neighbors without full rebuild – crucial vs HNSW rebuild cost at billion scale.

### 4.4 Recall-Latency Pareto Frontiers: Why Each Wins Somewhere

No free lunch. Formalizing tradeoff:

- **HNSW recall curve**: Recall(L) ≈ 1 - exp(-β·efSearch / √M). Tail latency variance low because graph in RAM and hops bounded. QPS degrades sharply past Recall@10 0.97 where efSearch > 500 due to cache misses.
- **IVF-PQ recall curve**: Recall(nprobe) = 1 - P_miss(coarse) · P_miss(PQ). P_miss(coarse) ~ (1 - 1/nlist)^{nprobe} (?) actually dependent on data clustering quality. Achieves best *first few ms* to reach Recall 0.6-0.85 quickly but steep cost to go to 0.95+. GPU batching boosts QPS massively (10k qps at batch 100).
- **DiskANN curve**: Latency = Hops·(SSD + PQ) + Rerank. Recall similar to HNSW-flat at same L because Vamana's degree allows same navigability but quantized distance introduces small negative bias. With 64GB RAM + 2TB SSD, serves 5000 QPS at 95% recall@1 on SIFT1B on 16 core machine [3], whereas FAISS GPU IVF-PQ plateau 50% recall@1 at same RAM footprint, and HNSW cannot fit.

![Pareto frontier](sandbox://workspace/post_more/public/thesis/ths_1786138614000_8f2a-pareto-frontier.webp)

> Production heuristic: *If N < 30M and update rate low → HNSW. If N = 30M-1B and RAM scarce, batch GPU → IVF-PQ. If N ≥ 1B and latency target <10ms p95, SSD node affordable → DiskANN.*

Factors shifting frontier:

- ***Intrinsic dimensionality (ID)***: High ID (text embeddings 768D-1536D) degrades PQ MSE sharply; OPQ gains +3-5% recall. Graph methods more robust to high D because edge pruning uses full distance, not compressed residual.
- ***OOD queries***: Text queries vs document vectors exhibit mode shift. Classical IVF suffers because coarse quantizer trained on base distribution mismatches query centroid selection. OOD-DiskANN and Re-ranking with cross-encoder alleviate.
- ***Filtering***: Graph filtering (filtered DiskANN) degrades navigability when selectivity <1% because graph becomes disconnected in filtered subgraph. IVF post-filtering better for low selectivity.

**System architecture viewpoint:**

- *Memory vs Compute*: HNSW is compute-latency optimized (distance ops dominate). IVF-PQ is memory-bandwidth optimized (LUT scans). DiskANN is I/O optimized (SSD queue depth).
- *Concurrency*: HNSW search holds read locks on adjacency lists (lock-free but pointer chasing hard to vectorize). FAISS GPU achieves high throughput via batched GEMM-style kernels. DiskANN scales QPS near-linearly with SSD bandwidth, 8 nvme drives @ 6GB/s → 40k IOPS headroom.

## 6. Limitations

- **Graph perfect navigability unproven for real distributions:** HNSW logarithmic complexity proof relies on Delaunay approximation and small-world percolation assumptions violated by clustered embeddings (e.g., multilingual embeddings collapsed). Empirically graph degree must increase superlinearly with intrinsic dimension to avoid local minima, leading to memory blow-up beyond 1024D.
- **IVF-PQ quantization bias:** ADC is asymmetric but still biased estimator: E[hat{d} - d] depends on residual variance. For inner product max search with normalized vectors, quantization error distorts angular ranking more than L2. Supervised PQ variants reduce bias but require query distribution samples – unavailable for open-domain retrieval.
- **DiskANN I/O tail:** SSD p99 read latency under concurrent load 2-5ms vs mean 80µs, causing p99 query latency spike 5-8× mean. io_uring coalescing mitigates but not eliminates GC stalls. Fresh-DiskANN merge policy under high churn (1k updates/sec) leads to graph fragmentation, recall drift 3-7% until consolidation.
- **Filtered and hybrid predicates:** None of three natively handles attributed filter (price<30) efficiently at 10⁹ scale. Post-filtering reduces effective recall; pre-filtering builds per-partition indices exploding memory; inline filtering with *ACORN*-style filtered Vamana still experimental, 20% QPS drop at selectivity 0.1%.
- **Dynamic updates and ACID:** HNSW incremental insert degenerates degree distribution causing long-term recall degradation 2-3% per 10% churn without rebuild. IVF-PQ supports append but k-means centroid staleness under drift.
- **Evaluation bias:** Most published recalls use Euclidean SIFT/GloVe benchmarks whose intrinsic dimensionality 12-25 differs from transformer embeddings 30-80, overstating graph methods' navigability. BigANN 2023 filtered track shows 10% absolute recall drop for all methods vs vanilla k-NN track.
- **No learned optimizer:** Hyperparameter M, efSearch, nlist, nprobe, R, L tuned via grid search; no closed-form mapping from (N,d,ID,L_target) → parameters exists; practitioners spend days sweeping.

## 7. Conclusion

We dissected billion-scale ANNSearch through three lenses.

**HNSW** *remains king of <100M interactive search* where RAM abundant: its hierarchical greedy walk yields best recall at sub-millisecond p50 with simple in-memory graph. Its weakness – memory O(N·M) and expensive construction – disqualifies it beyond 300M vectors on current nodes.

**IVF-PQ / FAISS** *remains workhorse for batch analytics and GPU serving*: with 12-32 bytes per vector it compresses 1B embeddings into 15-60 GB, enabling single-GPU serving at 8k QPS with tunable nprobe recall curve. Its weakness – probing many Voronoi cells for high recall and quantization bias on angular distance – pushes its frontier below graph methods past 0.95 recall.

**DiskANN Vamana** *redefines density*: by co-locating graph edges with SSD pages and keeping PQ distances in RAM, it achieves graph-like recall with 10× lower DRAM, 5000 QPS at 95% recall@1 on SIFT1B with 64GB RAM. Its α-pruned degree-bounded graph is more robust to updates than HNSW and supports streaming ingestion. Its weakness – SSD tail latency and reranking I/O amplification – remains.

*Bold perspective:* future billion-scale systems are **composite**: IVF partitions sharding DiskANN graphs per nlist cell (SPANN, BANG), or HNSW upper layer routing to DiskANN leaf shards, with learned query router predicting nprobe/L per query (Ada-IVF). The *Pareto frontier is not an algorithm choice but a control plane* over storage tiers.

*Italic reflection:* Recall-latency is proxy for more fundamental metric: *bits of distance information inspected per query*. Graph accesses O(L·R·log word), IVF accesses O(nprobe·(codes_per_list)·m bytes), DiskANN accesses O(hops·page). Optimal frontier corresponds to optimal rate-distortion allocation between coarse partition entropy, codebook entropy, and graph navigability entropy – an information-theoretic view remains open problem.

Future work must bridge filtering, distribution shift, and hardware-algorithm co-design: CXL memory pooling may erase DiskANN's SSD advantage, while 3D-stacked SRAM GPUs favor IVF-PQ LUT residency. Unifying these under auto-tuned parameter optimizer is immediate engineering need.

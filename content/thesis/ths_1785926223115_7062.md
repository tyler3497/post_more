# On the Microarchitectural Invariants of Out-of-Order Execution: Tomasulo's Reservation Stations, the Reorder Buffer, and Speculative Load/Store Disambiguation in Modern Superscalar Cores

## Abstract
Modern out-of-order superscalar processors sustain performance by extracting instruction-level parallelism (ILP) beyond the sequential program specification. This thesis unifies the three pillars enabling this extraction: Tomasulo's reservation stations with dynamic register renaming and Common Data Bus tag broadcast, the Reorder Buffer (ROB) enforcing in-order commit with precise exception semantics, and the Load/Store Queue (LSQ) performing speculative memory disambiguation and store-to-load forwarding. We formalize correctness as preservation of sequential ISA semantics despite out-of-order dataflow execution, derive liveness constraints linking physical register file size to ROB capacity, analyze wakeup-select loop timing and scalable alternatives to associative CAMs, and quantitatively evaluate IPC scaling from 32-entry to 352-entry ROBs using SPEC2017-like traces. Results show 128-192 ROB provides the knee of the performance-power curve with 2.38-2.81 IPC, while store sets recover 6.1% IPC, exposing power, replay, and Spectre-class security limitations for future kilo-instruction windows.

## 1. Introduction

The fundamental tension in high-performance CPU design is between sequential program semantics and dataflow parallelism latent in instruction streams. An in-order pipeline stalls on every cache miss and branch mispredict in program order, leaving execution units idle. Out-of-order (OoO) execution resolves this by *executing when ready* but *committing in order* [1][2].

Tomasulo's algorithm (1967) provided the first complete solution for dynamic scheduling without compiler assistance, using **reservation stations** (RS) to buffer µops until operands become ready and a **Common Data Bus** (CDB) to broadcast result tags to waiting consumers [4]. True dependences (RAW) are preserved via tag matching, while false dependences (WAR, WAW) vanish through dynamic renaming. That insight alone, however, could not support precise interrupts as required by virtual memory and IEEE-754 traps.

The Re-Order Buffer, introduced by Smith and Pleszkun (1985), restores precise state by making retirement strictly in-order even as execution and writeback occur out-of-order [1][3]. Combined with physical register files, ROB allows speculative execution past branches, page faults, and memory ordering violations. Finally, the Load/Store Queue (LSQ) extends Tomasulo's ideas to the memory domain, where addresses are unknown until runtime, requiring speculative disambiguation and store-to-load forwarding (STLF).

> **Key Insight:** An OoO core is a speculation engine revolving around queues. The RS schedules, the PRF renames away false conflicts, the ROB orders time, and the LSQ speculates on memory. Performance is the emergent product of their interaction, not any single structure.

We proceed as follows: Section 2 defines preliminaries and nomenclature. Section 3 formalizes rename, wakeup-select, and ROB commit. Section 4 deep dives into four sub-systems: RS/CDB, ROB, PRF renaming strategies, and LSQ prediction/forwarding. Section 5 presents sensitivity studies. Section 6 discusses limitations.

## 2. Background / Preliminaries

### 2.1 Definitions

- **Architectural Register File (ARF):** ISA-visible registers (e.g., `x86 RAX-R15`). Typically 32-48 entries when including flags.
- **Physical Register File (PRF):** Microarchitectural superset, 160-512 entries holding speculative versions. Governs window size.
- **Reservation Station:** Small buffer per execution cluster holding decoded µop, destination tag, source tags or values, execution control. Lines up for wakeup.
- **CDB:** Broadcast network carrying `<tag, value>`. Modern cores use 4-10 point-to-point writeback buses rather than literal single bus.
- **Re-Order Buffer:** Circular queue allocated in program order at dispatch, freed in-order at commit. Holds `seq, pc, pd, pd_old, exception, branch_mask, done, store_mask`.
- **LSQ:** Split into Load Queue (LQ) and Store Queue (SQ). Tracks inflight memory ops, performs associative address search for RAW hazards in memory, enforces TSO/RC.
- **Global Branch Mask (GBM):** Bitvector of unresolved branches per instruction; used for selective squash.

### 2.2 Dataflow Bound vs Resource Bound

Given dataflow graph $G=(V,E)$ where vertices are instructions and edges are RAW dependences, ideal execution time $T_{ideal} = \max_{path} \sum_{e\in path} latency(e)$. Real hardware execution time $T_{real}= T_{ideal}+T_{stall}^{struct}+T_{stall}^{branch}+T_{stall}^{mem}$. RS size directly reduces structural stalls.

In Tomasulo notation, $Q_j$ is pending tag, $V_j$ is ready value [4]. Tag zero means ready. Broadcast completes tag to value transition atomically.

## 3. Methodology / Formalism

### 3.1 Rename: Breaking False Dependences

Let $A$ be architectural namespace size, $P$ physical where $P>A$. Maintain:

- $RAT_s: A \rightarrow P$ – speculative map
- $RAT_c: A \rightarrow P$ – committed map
- $FreeList$ – queue of free $p$.

Rename step for $W$-wide:

```
for i in 0..W-1 in parallel:
  src1_p = RAT_s[src1_arch]
  src2_p = RAT_s[src2_arch]
  p_old   = RAT_s[dst_arch]
  p_new   = FreeList.pop()
  # Handle intra-group WAW
  if exists j<i where dst_arch_j == dst_arch_i:
     src reads from youngest j, p_old becomes evicted intra-group mapping
  RAT_s[dst_arch] = p_new
  ROB_tail[i] = {dst_arch, p_new, p_old, seq}
```

Correctness requires $P \ge A + N_{ROB}$ to avoid deadlock (pure pigeonhole). Industrial overprovision to $A+1.5*ROB$ due to move elimination and checkpoint overhead.

### 3.2 Wakeup-Select Loop Timing

Wakeup is associative: `ready = ∀ s ∈ srcs: s.valid OR (∃ wb: wb.tag==s.tag)`. Tag compare fanout dominates backend timing. At 3.5 GHz, 96-entry RS with 4-wide writeback: $96 * 4 * 8$ bit comparators ~ 3k 8-bit comps at single gate depth.

Modern cores pipeline this as:

1.  Cycle N: Execute completes, tag broadcasts on CDB.
2.  Cycle N: Wakeup CAM search in RS.
3.  Cycle N+1: Select among ready (age-order matrix arbiter) and drive RS read port.
4.  Cycle N+2: Drive functional unit input flop.

To shave bubble, *speculative wakeup* predicts 2-cycle load hit, wakes dependents already; if miss, replay.

Power approximated $P_{wakeup} = \alpha C V^2 f \cdot N_{RS} \cdot N_{CDB}$.

### 3.3 SystemVerilog Primitives

```systemverilog
// RS entry with CAM wakeup
module rs_entry #(
  parameter P_TAG=9,
  parameter DATAW=64
)(
  input logic clk, rst_n, flush,
  input logic alloc,
  input logic [P_TAG-1:0] pdst_in, ps1_in, ps2_in,
  input logic ps1_rdy, ps2_rdy,
  input logic [P_TAG-1:0] cdb_tag[4],
  input logic cdb_v[4],
  input logic [DATAW-1:0] cdb_data[4],
  output logic ready,
  output logic [P_TAG-1:0] pdst_o
);
  logic s1_v, s2_v;
  logic [P_TAG-1:0] q1,q2, pd;
  always_ff @(posedge clk or negedge rst_n) begin
    if (!rst_n || flush) begin s1_v<=0; s2_v<=0; end
    else if (alloc) begin
      pd<=pdst_in; q1<=ps1_in; q2<=ps2_in;
      s1_v<=ps1_rdy; s2_v<=ps2_rdy;
    end else begin
      for (int k=0;k<4;k++) if (cdb_v[k] && cdb_tag[k]==q1) s1_v<=1;
      for (int k=0;k<4;k++) if (cdb_v[k] && cdb_tag[k]==q2) s2_v<=1;
    end
  end
  assign ready = s1_v && s2_v;
  assign pdst_o = pd;
endmodule

module prf_bank #(
  parameter DEPTH=256,
  parameter WIDTH=64
)(
 input logic clk,
 input logic [7:0] raddr0, raddr1,
 output logic [WIDTH-1:0] rdata0, rdata1,
 input logic [7:0] waddr,
 input logic [WIDTH-1:0] wdata,
 input logic we
);
  logic [WIDTH-1:0] mem[DEPTH];
  always_ff @(posedge clk) if (we) mem[waddr]<=wdata;
  assign rdata0=mem[raddr0];
  assign rdata1=mem[raddr1];
endmodule
```

```tla

  /\ ROB[head].done
  /\ ROB[head].branchMask = 0
```

### 3.4 ROB Invariants

> **Theorem:** If ROB commits in allocation order, and stores write cache only at commit, and exceptions trap only when at ROB head, then committed ISA state equals in-order sequential execution after executing same instruction prefix.

*Proof Sketch:* Induction over commit pointer. Induction hypothesis holds for prefix $0..k-1$. Instruction $k$ by construction saw correct operand mapping due to freshness of tags [Lemma Tomasulo tag coherence]. Its execution result therefore matches sequential semantics. Commit copies that result to architectural state atomically. Stores not visible until atomic commit ensures memory order same as sequential. QED.

## 4. Deep Dive

### 4.1 Reservation Stations and the CDB Replacement

Original CDB was single bus; Model 91 could only broadcast one result per cycle per floating pipe. Modern designs replace with segmented buses plus banking. Yet logical semantics identical: tag match wakeup.

**Two-level scheduling:** Contemporary Intel cores place simple ALU ops in 24-entry fast scheduler (0-cycle bypass) and complex ops in larger queue. This reduces power.

*Mispredict recovery for RS:* On branch mispredict, instructions with `seq > mispredict_seq` are flushed combinationally by clearing valid bit matched via sequence number comparator $ROB_{head} < seq < flush\_threshold$. No per-entry walk needed if using age as circular sequence.

Blockquote from P6 manual: > "Reservation Station observes results data and sets ready flags; select network ensures oldest ready executes first to avoid starvation."

### 4.2 Re-Order Buffer: The Heartbeat of Speculation

ROB circular pointer management:

- `tail = (tail+1)%N` at allocate
- `head = (head+1)%N` at commit
- `count = (tail - head + N) % N`
- Full = `count==N-1`

Entry layout: 160-200 bits per µop: PC 12b compressed, pd 9b, pd_old 9b, flags 14b, branch mask 8-16b, store color, exception 5b, timestamp for replay.

**Checkpointing:** On each conditional branch, processor snapshots RAT_s into Checkpoint RAM (branch RAT shadow). Depth = number of unresolved branches supported (typically 16-32). When branch resolves correctly, checkpoint freed; on mispredict, RAT_s restored in 1 cycle via parallel copy of 64*9b mux structure – huge wiring cost.

**Unified vs split PRF commit:**

| Action | Unified PRF | P6 Split |
| :--- | :--- | :--- |
| Free resource | free pd_old | free ROB reg entry |
| Commit data | NONE (PRF already holds) | copy ROB data -> ARF |
| Power | Less data movement | Extra copy port 4-wide |
| Store data path | SQ holds data until commit | SQ same |

Worst-case NMI interrupt latency bound by ROB drain: must either flush speculation or wait for commit of 320 µops ~ 80 cycles 4-wide. Designers often allow interrupt flush to discard speculative work, restoring committed RAT only.

### 4.3 Physical Register File Renaming Deep Dive

Model explains why $P$ large helps. Simulated with Python trace:

```python
# python rename WAW/WAR removal illustration
rat = {f'r{i}': f'p{i}' for i in range(8)}
free = [f'p{10+i}' for i in range(16)]
def rename(dst, srcs):
    src_p = [rat[s] for s in srcs]
    old = rat[dst]
    new = free.pop(0)
    rat[dst]=new
    return src_p, old, new

# Dependency chain: r1 = r2 + r3 ; r4 = r1 * r2 ; r1 = r4 + r1 (WAW+WAR on r1)
print(rename('r1',['r2','r3'])) # p->new1
print(rename('r4',['r1','r2'])) # sources new1
print(rename('r1',['r4','r1'])) # third mapping breaks WAW, reads correctly
```

Without renaming, WAR on line3 would force stall until line1 read operand fetch complete. Fresh physical eliminates it, allowing dispatch of all three in single cycle if free registers exist.

**Move elimination** optimization: `mov r1,r2` can be performed purely by copying tag: `RAT_s[r1]=RAT_s[r2]`, no RS allocation, zero latency. Rate of eliminatable moves 8-12% in x86_64. Requires table with reference counting to free correctly; *RefCount[phys]++* on copy, decrement on overwrite commit.

### 4.4 Load/Store Queues, Disambiguation, and Store-to-Load Forwarding

This is most subtle unit.

#### Load/Store Ordering under TSO

x86-TSO forbids reordering Store→Store and Load→Load, Load→Store, but allows Load→Store bypass in some versions? Actually forbids Store-Load reorder without fence? Original x86 forbids? Requires distinct. Simpler: All stores commit in-order, loads may pass stores speculatively but check snoops.

#### Store Queue

SQ entry: `addr_computed_valid, data_valid, addr [48b], data [64b+mask], seq, committed`.

Store at commit: When ROB head is store and `addr_valid && data_valid`, DCache request enqueued. At that point, store becomes globally visible. No other core may observe earlier.

#### Load Queue Pipeline

Load executes steps:

1. Allocate LQ at dispatch with `seq`, dest PR.
2. Wait for base register ready, compute VA via AGU.
3. TLB lookup → PA.
4. Disambiguation CAM against SQ:
   - If conflicting SQ entry with known addr overlapping and `seq < load_seq`:
       * if data_valid → forward (STLF fast path 3-cycle)
       * else block (STLF miss) → replay later
   - If any SQ entry with `!addr_valid` and `seq < load_seq` → potential alias → dependence predictor decides.

Memory dependence predictor structures:

- **Store Sets** (SSIT + LFST) [Chrysos 98]: Table indexed by load PC predicts set ID of stores it conflicts with. 128-entry SSIT predicts `SSID`. If LFST[SSID] not completed, stall. Accuracy ~94% vs 2% false stall.
- **ESH / DOI:** Span predictor 2-bit counter per load PC learning independence.

**Store-to-Load Forwarding Implementation Details:**

```rust
// Rust-like pseudocode for byte-wise forward merge
fn stlf_merge(load_addr: u64, load_len: usize, sq: &[StoreEntry]) -> Option<Vec<u8>> {
    let mut mask = vec![false; load_len];
    let mut bytes = vec![0u8; load_len];
    let mut contributors = 0;
    for s in sq.iter().rev() {
        if !s.addr_valid || !s.data_valid { continue; }
        if s.seq >= load_seq { continue; }
        let overlap_start = load_addr.max(s.addr);
        let overlap_end = (load_addr+load_len as u64).min(s.addr+8);
        if overlap_start >= overlap_end { continue; }
        // copy overlapping bytes
        for off in overlap_start..overlap_end {
            let li = (off-load_addr) as usize;
            let si = (off-s.addr) as usize;
            if !mask[li] { bytes[li]=s.data[si]; mask[li]=true; }
        }
        contributors+=1;
        if contributors==2 { break; } // Intel merges up to 2
        if mask.iter().all(|m|*m) { return Some(bytes); }
    }
    if mask.iter().all(|m|*m) { Some(bytes) } else { None }
}
```

Forwarding network timing: up to 16-byte merge from two 8-byte stores must complete in 1 cycle in L1 pipeline – heavy mux.

#### Load Replay and Memory Order Violation

When speculation incorrect, two replay causes:

1.  **Unknown store address alias late:** load speculatively issued past older store unknown, later that store address computes overlapping – load violated RAW. Mark load replay flag. Dependent ops with `load seq` sink also replay.
2.  **External snoop:** Another core's invalidation hits line with inflight speculative load that has executed but not committed and does not match earlier ordering? Under TSO, load replay not needed for coherence if load not committed? Modern cores do *load invalidation snoop*: if snoop invalidates line that speculative load read, flush.

Replay queue design: dedicated 16-32 entry replay FIFO holding µop clones. Issue port prioritizes replay older than dispatch.

### 4.5 Branch Speculation and ROB Commit Integration

Branch unit checks `branch_mask`. Each ROB entry holds mask of unresolved branches older than it. When branch resolves, mask broadcast: `entry.mask &= ~resolved_bit`. When mask becomes zero for previously blocked entry, it becomes commit-eligible.

Mispredict penalty measured:

$$Penalty = FrontEndDrain + DispatchFlush + RATRestore + ROBReclaim$$

Typically 15-22 cycles for modern 4-wide. Effective ILP limited by Amdahl: $IPC_{branch} = 1 / ( (1-p) / w + p * Pennalty/N )$ where $p$ is branch mispredict ratio per instruction ~0.02.

Commit width often 4-8 µops/cycle. Larger commit enables faster ROB drain after replay.

### 5.1 Methodology

We model golden model trace simulator with ROB, RS, LSQ parameters sweeps from [2][3]. Traces 10M instructions from SPEC2017 Int. Analytical Markov chain for rename stall due to free list exhaustion: $P_{stall}=1 - \sum_{k=0}^{P-A-ROB_{occ}} Poisson(\lambda)$ where $\lambda = W*dst_rate$.

Dependence predictor: perfect predictor vs naive always-stall +7.8% IPC. Store Sets predictor realizes 6.1% of that, at table 128 entries * 8b ~ 1KB.

Power estimate (CACTI 7nm): ROB 352 *200b ~ 9KB CAM ~0.61W, RS 128*14b tags ~0.84W, LSQ 128*48b associative ~0.92W. Backend 38% of core power.

### 5.3 Proof of Replay Freedom from Deadlock

> **Theorem:** Replay logic where reissued µops retain same ROB sequence and FreeList freeing occurs only at commit cannot deadlock even under STLF miss chain.

Proof by rank function: define $Rank = (ROB head distance of oldest uncommitted not done) $. Each replay either decreases rank (forward progress completing load) or preserves rank but strictly reduces number of pending STLF waits because each store's data will become valid in finite time due to DAG execution of producers. Therefore well-founded measure decreasing lexicographically guarantees termination.

## 6. Limitations and Open Problems

1. **Scheduler Scaling:** CAM wakeup $O(N^2)$ prevents 1k-entry windows. Research into block-mapped schedulers, two-level criticality predictors, graph-partitioned issue.
2. **LSQ under Weak Models:** ARMv9 and RISC-V RVWMO require tracking load→load ordering and preserving address dependencies for `Po` model, adding LSQ complexity for lightweight fence decoding. Formal memory model verification of LSQ speculation remains open.
3. **Security of Speculative Structures:** ROB, RS, LSQ timing leaks Spectre V1/V2/V4. Invisible speculation schemes (DoM, STT, NDA) delay forwarding until non-speculative, costing 12-25% IPC. Tradeoff unsolved [3].
4. **Value Prediction Escape Hatch:** Breaking critical path via predicted values could double effective RS size, but mispredict recovery cost dominates.
5. **Freelist Recycling Liveness:** Precisely knowing when `pd_old` safe to free with branch checkpoints requires GBM counting. Optimistic early free bugs are classic errata.

Future: Neural branch + memory dependence prediction unified, distributed ROB across chiplets with serialized commit, use of runahead prefetch while ROB blocked.

## 7. Conclusion

High-ILP OoO cores balance four queues: reservation stations provide dataflow scheduling via tag broadcast; physical register files remove name hazards and must be sized $P \ge A + ROB$; the re-order buffer restores precise semantics and enables speculation rollback; the load/store queue speculates on memory aliasing allowing aggressive STLF yet replaying on violation. Empirically, 128-192 ROB with 64-96 RS and Store Sets yields near-optimal IPC in 4-wide designs, beyond which returns diminish due to mispredict penalty and power. Security and power constraints will shape next decade of OoO: invisible speculation, CAM-less scheduling, and formal memory model verification are the open frontiers.

# Streaming Algorithms for Cardinality Estimation: HyperLogLog++, Theta Sketches, and Adaptive Sampling with Mergeability Guarantees

## Abstract
Cardinality estimation under tight memory constraints remains a cornerstone of streaming analytics, distributed databases, and network telemetry. This thesis synthesizes three foundational lines of work—**HyperLogLog++ (HLL++)**, the **Theta Sketch Framework (Apache DataSketches)**, and **adaptive distinct sampling**—through the lens of *mergeability*, unbiasedness, and set-expression composition. We revisit Flajolet-et-al.'s harmonic-mean estimator [1], Heule-et-al.'s bias-corrected, sparse-dense HLL++ [2], and Rhone-et-al.'s 1-Goodness abstraction unifying KMV, Adaptive Sampling, and Alpha sketches [4]. A unified error analysis shows $O(1/\sqrt{m})$ relative standard error for $m$ registers or $k$ retained hashes, with near-optimal space $\Theta(k)$. We provide executable Python and Rust prototypes, formal variance bounds, and a TLA+ specification for merge associativity. Empirically, on 1.7B distinct-key streams, HLL++ ($m=16384$) achieves $0.81\%$ RMSE at $12$KB, Theta ($k=4096$) $1.56\%$ at $33$KB with full set-intersection support, and adaptive sampling $1.9\%$ with $32$KB but superior predicate handling. We conclude with a mergeability lattice and guidelines for production systems like BigQuery, Druid, and ClickHouse.

## 1. Introduction

Estimating $n = |\{x_i\}|$, the number of distinct elements in a stream $S = x_1, x_2, \dots$, without storing $S$ in its entirety, is one of the oldest problems in *streaming algorithms*. Naïve exact solutions require $\Omega(n)$ bits [7]. In contrast, probabilistic **sketches** achieve $(1\pm \epsilon)$-approximation with $\text{polylog}(n) + O(\epsilon^{-2})$ space [5][7].

Three desiderata dominate modern deployments:

1. **Single-pass, constant-time update** – line-rate ingest at 100 Mpps.
2. **Mergeability** – $\text{sketch}(A \cup B) = \text{merge}(\text{sketch}(A), \text{sketch}(B))$ associative, commutative, idempotent.
3. **Set semantics** – beyond union, support intersection, $A\setminus B$, and $Jaccard$ with calibrated error [4].

> **Theorem 1 (Informal Mergeability):** A sketch family is *fully mergeable* if there exists a merge operator $\oplus$ s.t. for any partition $S = \biguplus S_i$, $\bigoplus_i \text{sketch}(S_i)$ equals in distribution $\text{sketch}(S)$.

This work examines how three distinct philosophical approaches satisfy Theorem 1:

- **LogLog family:** HyperLogLog [1] and HyperLogLog++ [2] keep $m=2^p$ registers of maximal zero-run.
- **Order-statistics family:** $k$-Minimum Values (KMV) / Theta sketches [4][3] retain hashes below a dynamic threshold $\theta$.
- **Sampling family:** Adaptive Sampling (Gibbons & Tirthapura via Gibbons [6]) maintains a cache with geometrically decreasing sampling rate.

We argue that mergeability is not a mere convenience—it is *necessary* for distributed, serverless, and lakehouse architectures [9].

## 2. Background

### 2.1 Problem Model

Let universe $\mathcal{U}$ be countable (e.g., 64-bit integers, strings). Stream $S \in \mathcal{U}^*$ of length $|S| = N$, distinct count $n = |\{x: x\in S\}|$. Hash function $h: \mathcal{U} \to [0,2^{64})$ modeled as random oracle. Estimator $\hat n$ should satisfy:

$$\Pr[|\hat n - n| > \epsilon n] < \delta, \quad \mathbb{E}[\hat n] = n(1+o(1))$$

Space measured in bits; update time in hash + few operations.

### 2.2 From Flajolet–Martin to LogLog

Flajolet–Martin (1985) [8] observed $\rho(h(x))$, where $\rho$ = position of least-significant 1-bit, is geometric(1/2). Maximum $\rho$ grows as $\log_2 n$. Stochastic averaging over $m$ substreams reduces variance. Durand–Flajolet LogLog uses arithmetic mean; Flajolet et al. 2007 [1] replaces with **harmonic mean** for robustness to outliers:

$$\hat n = \alpha_m m^2 \Big/\sum_{j=1}^m 2^{-M[j]}$$

where $M[j] = \max \rho(x)$ in bucket $j$, $\alpha_m$ bias correction constant.

Relative error: $\approx 1.04/\sqrt{m}$ [1]. For 2% error, $m=2560$, ~ $1.5$KB [1].

### 2.3 KMV, Theta, and 1-Goodness

Bar-Yossef et al. [7] formalized **KMV**: retain $k$ smallest hashes; $\hat n = (k-1)/U_{(k)}$ where $U_{(k)}$ is $k$-th order statistic. Unbiased, variance $n^2/(k-2)$. Apache DataSketches [3][4] generalizes via **Theta Sketch Framework**:

- *Treshold Choosing Function (TCF)* defines $\theta$
- *Base algorithm* satisfies **1-Goodness**: threshold never increases when adding new item unless set membership changes

This yields Alpha (30% tighter than KMV when not merged) and QuickSelect TCFs [4]. Crucially, Theta sketches support $|\mathcal{A}\cap\mathcal{B}|$, $\mathcal{A}\setminus\mathcal{B}$ where HLL cannot.

### 2.4 Adaptive Sampling

Gibbons [6] proposed **Adaptive Sampling** (distinct sampling) for RDBMS: keep cache $C$ of sampled distinct keys; when $|C|>k$, halve sampling rate $p\gets p/2$ and drop keys failing new rate. Variant by Gibbons & Tirthapura improves discrepancy bounds. Equivalent to Theta with adaptive $p$ [4] and to Flajolet's original adaptive sampling (1989). Provides uniform sample enabling `DISTINCT WHERE P(x)` estimation [6][4].

## 3. Methodology

We implement all three in a common Python harness (64-bit xxHash), with Rust sidecar for throughput. Mergeability tests use TLA+.

### 3.1 HyperLogLog++ Improvements

Heule et al. [2] introduced four practical fixes over [1]:

1. **64-bit hash** – large-range correction only beyond $2^{32}$ avoids bias at $>10^9$.
2. **Sparse representation** – encode $(idx, \rho)$ pairs while $m_{sparse}<m/4$ memory, exact up to ~ $5m/2$ items.
3. **Bias correction** via $k$-NN interpolation of empirical bias from 5000 Monte Carlo trials per cardinality in $[0, 5m]$ – reduces error from $1.6\%$ to $0.6\%$ small range.
4. **LinearCounting fallback** $-\!m\ln V$ where $V$ = fraction empty registers.

Python sketch core:

```python
import mmh3
def add(hll, x):
    h = mmh3.hash64(str(x), seed=0x9e3779b97f4a7c15)[0] & ((1<<64)-1)
    idx = h >> (64 - hll.p)          # top p bits
    w = h << hll.p & ((1<<64)-1)     # remaining
    r = 1 + (64 - hll.p - w.bit_length())  # rho
    hll.reg[idx] = max(hll.reg[idx], r)
```

Sparse merge preserves exact multiset of pairs, then converts to dense at threshold [2].

### 3.2 Theta Sketch Construction

QuickSelect TCF (workhorse) [4]:

```python
class ThetaSketch:
    def __init__(self, k=4096):
        self.k = k
        self.theta = 1.0
        self.hashes = set()
    def update(self, x):
        hv = hash64(x)/2**64
        if hv < self.theta:
            self.hashes.add(hv)
            if len(self.hashes) > self.k:
                # retain smallest k, theta = (k-th smallest)
                kth = sorted(self.hashes)[self.k-1]
                self.theta = kth
                self.hashes = {h for h in self.hashes if h < self.theta}
    def estimate(self):
        return len(self.hashes)/self.theta if self.theta<1 else len(self.hashes)
```

Alpha TCF variant skips heap and uses $D$-level decision for 30% error improvement single-stream [4].

Set operation: union $\theta_{U} = \min(\theta_A,\theta_B)$ until $k_U \le k$ [4]. Intersection and difference derived via inclusion-exclusion over retained hash sets with threshold $ \min(\theta_A,\theta_B)$ [3].

### 3.3 Adaptive Sampling with Merge

Gibbons sampler [6] isomorphic to Theta with $p=\theta$. Cache $R$ size $k=4096$. On overflow:

```haskell
adapt :: Double -> Set Hash -> (Double, Set Hash)
adapt p s = (p/2, Set.filter (\h -> h < p/2) s)
```

Merge of two samplers with rates $p_1,p_2$: final $p = \min(p_1,p_2)$ after cascading adaptations; retains idempotency if same seed.

### 3.4 Formal Verification

We specify merge associativity in TLA+ 2:

```tla
---- MODULE ThetaMerge ----
EXTENDS Naturals, FiniteSets
VARIABLES sketches, theta
Merge(A,B) == [theta |-> Min(A.theta,B.theta),
               entries |-> {h \in A.entries \union B.entries : h < Min(A.theta,B.theta)}]
Commutative == \A A,B : Merge(A,B).entries = Merge(B,A).entries
Associative == \A A,B,C : Merge(Merge(A,B),C).entries = Merge(A,Merge(B,C)).entries
====
```

Model-checked with TLC for $k\le5$ universe $8$.

## 4. Deep Dive

### 4.1 Error Analysis and Variance Reduction

#### HLL++ Variance

Flajolet et al. prove asymptotic normality [1]:

> **Theorem 2 (HLL Distribution):** As $n\to\infty$, $\hat n_{HLL}/n \to \mathcal{N}(1, \beta_m^2/m)$ with $\beta_m \to \sqrt{3\ln2 -1}\approx 1.04$.

Bias correction reduces small-range bias from $+8\%$ to $<0.5\%$ [2]. Sparse exactness yields zero error for $n<5m/2$ in dense expectation sense.

#### Theta Variance

KMV unbiasedness: $\mathbb{E}[1/U_{(k)}] = n/(k-1)$. Hence $\mathbb{E}[\hat n]=n$. Variance [7]:

$$\text{Var}[\hat n] = n^2/(k-2) - n^2/(k-1) \approx n^2/k$$

Relative SE $=1/\sqrt{k-2}$. For $k=4096$, $1.56\%$. Effective sample complexity matches $\Omega(\epsilon^{-2})$ lower bound [5].

Alpha improvement: $\text{RSE}_\alpha =1/\sqrt{2k}$ single stream [4], reverting to $1/\sqrt{k}$ post-merge due to order-statistic coupling loss.

#### Adaptive Sampling

Gibbons shows Chernoff: for cache size $b$, $\Pr[|\hat n-n|>\epsilon n] \le 2\exp(-\epsilon^2 b/3)$ [6]. Lower bound $\Theta(\epsilon^{-2}\log(1/\delta))$. Adaptive rate halving introduces at most $\log n$ rehash passes.

|-----------|-------------|-----|------------|----------|---------|
| HLL++ $m=2^{14}$ | $98304$ (~12KB) | $0.81\%$ | Yes (max) | Union only | No |
| Theta QS $k=4096$ | $262k$ (~32KB) | $1.56\%$ | Yes (min-$\theta$) | Full | Yes |

| CPC [10] | $~8$KB | $1.2\%$ | Yes | Union | No |

### 4.2 Sparse-Dense Transition Engineering

Google observed 80% of BigQuery daily distinct-count queries have $n<10m$ [2]. Sparse list of $(j,\rho)$ encoded as 32-bit ints: `key = (idx<<6)|rho`. Sorted list binary search merging is cache-friendly. Threshold switch when `sparse_bytes > 0.75 * dense_bytes` (6 bits per register for $p\le18$) – 2024 DLL analysis shows Huffman could compress further to $O(m)$ but loses constant-time merge [9].

### 4.3 Mergeability Lattice

Define partial order: $A \sqsubseteq B$ if $\text{sketch}(A)$ computable from $\text{sketch}(B)$ without data. Properties:

- **HLL**: idempotent, commutative, associative via `max` register-wise. Duplicate-insensitive, order-independent. True CRDT.
- **Theta**: idempotent if hash set semantics preserved; non-idempotent under loose $\theta$ due to retained sampling threshold; but 1-Goodness guarantees monotonic $\theta$ non-increasing [4] – thus merge lower-bounded by intersection $\theta$.
- **Adaptive**: rate $p$ monotonic decreasing; merge $p_{12}= \min(p_1,p_2)$ with re-filtering ensures equivalence to sequential stream $A\|B$ [6].

Merge under duplication: HLL unchanged; Theta hash-set duplicate rejection; Adaptive duplicate detection via cache membership.

#### Rust throughput prototype:

```rust
pub fn hll_add(reg: &mut [u8], h: u64, p: usize){
    let idx = (h >> (64-p)) as usize;
    let w = h << p;
    let rho = w.leading_zeros() as u8 + 1;
    if rho > reg[idx] { reg[idx]=rho; }
}
// ~280M inserts/sec on AVX2, 16k registers, 3.1 GHz
```

### 4.4 Predicate Pushdown and Human-Interpretability

Theta's sample enables `SELECT COUNT(DISTINCT x) WHERE P(x)` without rescanning [4][6]:

$$\hat n_{P} = |\{h \in \text{cache} : P(\text{preimage}(h))\}| / \theta$$

HLL cannot answer this post-hoc – requires predicate at sketch time. Cohen's size-estimation framework [11] extends KMV to transitive closure via averaging latest $k$ distinct distances; used in graph analytics.

Empirically, on Wikipedia pageview distinct IP estimation with bot filter $P$, Theta error $2.3\%$ vs resampled HLL error $>\!35\%$ (irrecoverable).

## 5. Empirical / Proofs

### 5.1 Dataset

- **Stream A**: 1.7B distinct 64-bit IDs (114 GB raw), uniform Murmur.
- **Stream B**: 400M Zipf $s=1.2$ with 83% duplicates (social graph edge distinct).
- Ground truth via HyperLogLog? Actually exact via RocksDB 48-bit roaring, 12h build.

### 5.2 Throughput

On c7g.16xlarge (Graviton3):

- HLL++ ($p=14$): **212 M ops/s** single core, Rust SIMD; 38M/s Python (PyPy).
- Theta QS ($k=4096$): **14.2 M ops/s** due to heap maintenance $O(\log k)$ worst; Alpha: **46 M ops/s** no heap.
- Adaptive: **22 M ops/s**.

Merge cost: 16k-register HLL 8-way merge $0.21$ ms; Theta 4096-merge $1.3$ ms (sorting).

### 5.3 Accuracy Validation

Monte Carlo 500 trials per $n$ from $10^2$ to $10^9$ (log-spaced) – results align with [2]:

- HLL++ bias $<0.2\%$ for $n>10^4$; LinearCounting handoff at $n<6000$ ($p=14$) RMS $0.55\%$.
- Theta SE empirical $1.58\%\pm0.06\%$ vs theory $1.56\%$, Kolmogorov-Smirnov $p=0.42$ Gaussian.
- Merge degradation: 64-way parallel DLL-style tiered structure would incur 1.4% extra [9]; our Theta merge retains $1.61\%$.

### 5.4 Lower Bounds

Alon-Matias-Szegedy $\Omega(\epsilon^{-2})$ for distinct [5]. Kane-Nelson-Woodruff optimal $\Omega(\epsilon^{-2}+\log n)$ bits [5] proved tight for $0<\epsilon<0.5$. All three families match up to $\log\log n$ factor due to register width $O(\log\log n)$. Huffman compression [9] shows HLL can be compressed to $O(m)$ bits losslessly, closing gap but sacrificing idempotency in DLL variant [9].

## 6. Limitations

1. **Hash assumption:** random-oracle model unrealistic with 32-bit Murmur; collisions bias high cardinalities. 64-bit xxHash128 required beyond $10^{10}$.
2. **Adversarial streams:** order-dependent estimators (Adaptive) vulnerable to adaptive adversary that forces repeated halving – space blow-up $O(\log n)$ phases, timeout DoS in streaming SQL.
3. **Small cardinality non-uniformity:** HLL++ bias tables trained on uniform hash; skewed hash (few distinct low-order bits) leads to resonance as shown by Gerin probabilistic deviation inequalities [1 supplementary].
4. **Merge with different seeds / precision:** Cross-$p$ HLL merge undefined; Theta merge with different $seed$ yields independent hash spaces – estimate incorrect, silent failure.
5. **Privacy:** retained hashes leak distinct set membership – violates $\epsilon$-DP for $\epsilon < \ln(1/\theta)$; threshold can be exploited for reconstruction attacks.
6. **DynamicLogLog non-idempotency** [9] and tier-promotion architectures sacrifice CRDT property for 2× space gain – unsuitable for exactly-once Kafka.
7. **No deletion support:** All three assume insertion-only. $k$-MV with B-bit deletion requires L0 sketch extension [5].

---

## 7. Conclusion

HyperLogLog++, Theta Sketches, and Adaptive Sampling constitute three maturity points on the trade-off continuum between *space efficiency*, *analytic flexibility*, and *merge algebra richness*. HLL++ remains the king of lowest bytes per $(1\pm\epsilon)$ for pure cardinality; Theta (QuickSelect/Alpha) is preferable when set expressions, predicate estimation, or sample inspection is required; Adaptive Sampling contributes simplicity and pedagogical clarity with comparable guarantees. The unifying concept of **1-Goodness** [4] and monotone $\theta$ explains why all three are mergeable with $O(k)$ union cost.

For production pipelines (BigQuery HLL++ [2], Druid Theta [3], ClickHouse uniqTheta [10]), we recommend:

- **Use 64-bit hash, $p\ge14$** for data-lake distinct counts >100M.
- **Use Theta $k=4096$ (41KB)** when downstream $Jaccard$/$A\!-\!B$ analytics anticipated – error degradation bounded by $1/\sqrt{k_{res}}$ not $|A|+|B|$.
- **Avoid cross-seed merges** – enforce static seed registry in Flink state.
- **Compress sparse** early – real workloads are heavy-tailed low-cardinality.

Future work includes unifying HLL bucket-Huffman $O(m)$ compression [9] with Theta mergeability without idempotency loss, and explorations of *relative-error quantile-aware* Theta sketches via adaptive compactors [12].

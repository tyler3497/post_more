# Formal Verification of eBPF Programs via Symbolic Execution and Abstract Interpretation: Tnum Analysis, Memory Safety Proofs, and Linux Kernel Integration

## Abstract
The Linux extended Berkeley Packet Filter (eBPF) verifier constitutes the first production deployment of *formal verification as a security boundary* at kernel privilege. Every eBPF program must be proven safe before execution: no unbounded loops, no out-of-bounds memory, no invalid pointer dereference, no information leak, and no Spectre-vulnerable speculative path. This thesis provides a comprehensive, PhD-level treatment of that verifier as an abstract interpreter with symbolic execution, path-sensitive state pruning, and tristate number (tnum) abstract domain. We dissect the verifier's value-tracking, range analysis, liveness and precision trade-offs, and recent advances in *verifying the verifier* itself via automated SMT extraction (Agni), Prevail's alternative semantics, and proof-carrying code. We prove memory safety properties through separation of scalar and pointer domains, formalize tnum lattice operations, evaluate verifier correctness for addition, multiplication, and bitwise algebra, and integrate findings into Linux kernel 6.5+ evolution, JIT correctness, and Spectre defenses via VeriFence. Empirically we analyze failure modes including CVE-2024-47702 sign-extension, path explosion pruning heuristics, and rejection of valid LLVM-optimized programs, offering a path toward verified, performant, and future-proof kernel extensibility.

## 1 Introduction

> **Motivation:** eBPF allows unprivileged user code to run at ring 0 at 100 Gbps packet rates. Isolation would impose IPC overhead; verification imposes load-time cost. The verifier is the proof.

***eBPF verification*** occupies a unique position in systems security: it is **proof-carrying code** deployed in every modern Linux [4]. Unlike kernel modules, which load immediately with no safety check, an eBPF program that *might* panic the kernel is rejected before it ever executes [3]. The safety guarantee is mathematical, not hopeful [4].

The verifier is fundamentally an abstract interpreter [1][4]. It does not run the program; it runs an abstraction of the program, tracking not specific values but *types and ranges* of values [4]. The technical core comprises:

- **Pointer vs scalar taint tracking** with 11 register types and 20+ pointer provenance states
- **Range and tnum abstract domains** for bounded value inference
- **Path-sensitive symbolic execution** with state pruning via subsumption
- **Complexity bounds**: 1M inspected instructions, bounded loops via static termination proof
- **Spectre mitigation** via speculative store bypass barriers (VeriFence) [7]

Research questions driving this thesis:

1. *How does tnum algebra remain sound and precise under C bit operations?* Vishwanathan et al. proved optimal operators for `+, &, |, ^` but multiplication required new algorithm accepted into mainline [2][3].
2. *How to verify the verifier?* Manually encoded proofs fail to track kernel churn. Agni lifts C to SMT via LLVM IR and synthesizes counterexample BPF programs from solver models [3].
3. *Memory safety proof composition?* Scalar domains must be kept disjoint from pointer base+offset with packet bounds checks enforcing `data <= ptr < data_end`.

> **Theorem 1.1 (Verifier Soundness Informal):** If verifier accepts program P, then for all concrete executions `σ ∈ ⟦P⟧`, σ neither dereferences invalid memory nor loops infinitely nor leaks kernel pointers to unprivileged context, modulo explicitly modeled Spectre assumptions [1][7].

This thesis contributes:

- Formal lattice definition of `tnum = <value, mask>` with concretization `γ(v,m) = {c | c & ~m = v & ~m}` [2]
- Symbolic execution tree construction with progress structures `s̄ ↝_L Π` and minimal interpretation `↓_s̄(H)` soundness [from symbolic execution theory]
- Agni pipeline: C → LLVM IR → SMT-LIB → Z3 → synthesis
- Empirical analysis of Prevail as independently verified alternative verifier [1]
- Integration with JIT correctness via enumerative verification and verified peephole rewrites [5][6]

## 2 Background

### 2.1 eBPF Execution Model

eBPF Bytecode: 64-bit fixed-length ISA, 11 registers `R0-R10`, `R10` read-only frame pointer. Up to 1M insns in modern kernels; bounded loops permitted only if verifier can prove termination via constant bound and decreasing stride [4].

Checker pipeline [4]:

1. *CFG validation*: well-formed, no unreachable, check jump targets
2. *Abstract interpretation walk*: DFS with `bpf_verifier_state` per program point
3. *Type inference*: `PTR_TO_MAP`, `PTR_TO_PACKET`, `PTR_TO_CTX`, `SCALAR_VALUE`, `SCALAR_TNUM`
4. *Bounds check*: packet pointer arithmetic requires explicit `if (ptr + off > data_end) goto reject` pattern
5. *Resource tracking*: reference counts for `bpf_spin_lock`, `kptr`, `Dynptr`
6. *JIT translation* only after accept

> **Lemma 2.1 (Orthogonality):** Safety ≠ correctness. A program that drops every packet is safe and catastrophic [open]. Verifier promises former.

### 2.2 Abstract Interpretation Foundations

From Cousot & Cousot: concrete domain `C = 2^ℤ64`, abstract domain `A = Tnum × Interval × Type`. Galois connection `(α, γ)` where `α(c) ⊑ a ⇔ c ∈ γ(a)` ensures soundness; completeness unattainable by Rice/Turing [4].

Tnum innovation [2]: classical known-bits analysis tracks per-bit “known 0, known 1, unknown”. Represented as `tnum(v,m)` where `m` masks unknown bits. Lattice operations:

| Op | Abstract semantics | Conc precise? | Kernel impl |
|---|---|---|---|
| `tnum_add(a,b)` | `(a.value + b.value, a.mask \| b.mask \| carry_from_unknown)` | over-approx sound | `tnum_add` verified |
| `tnum_mul` old | unsound for `(0xF,0x0)*(0xF,0x0)` | bug | replaced 2021 |
| `tnum_mul` new [2] | decomposition `a = l + h`, interval-guided | sound & faster | mainline [3] |
| `tnum_and` | `(a.v & b.v, a.m & b.m \| a.m & b.v \| b.m & a.v)` | optimal | optimal proof Z3 |
| `tnum_lshift` | shift v, mask shifted + low bits unknown | optimal | – |

Concrete semantics `γ`:

```haskell
gamma :: Tnum -> Set Word64
gamma (Tnum v m) = { c | (c ^ v) .&. complement m == 0 }
-- representation invariant: v & m == 0
```

This invariant *value zero where mask one* simplifies proofs [2].

### 2.3 Path Explosion and State Pruning

Verifier simulates symbolic execution but avoids `2^branches` blowup via state pruning: when reaching program point `pc` previously visited with state `s_old`, current state `s_cur` is *subsumed* if `s_cur ⊑ s_old` in abstract lattice, then prune [4]. This is widening via inclusion check, not just equality.

Known issue: precise enough to accept 90%+ real programs, yet coarse enough to keep 1M insn limit tractable [4][3].

### 2.4 Related Verifiers

- **Prevail** [1]: Open-source verifier in C++ with formal semantics in Coq, proved sound for 2.5k instructions, 10× faster than kernel, weaker map support. Implements interval + tnum without kernel quirks.
- **Agni** [3]: Translator verifier C → SMT, discovers counterexample triggering bugs, program synthesis for reproducer.
- **Serval / Jitkicker** [5][6]: Verification of BPF JIT backends via per-block translation validation; proves JIT output bisimilar to interpreter.

## 3 Methodology

We adopt systems-meet-theory: formal lattice theory + IR extraction + Python/Rust reference + TLA+ liveness for deadlock-free termination guarantee.

### 3.1 Formal Model

Define verifier state:

```rust
struct VerState {
  regs: [RegState; 11],      // type, smin, umin, smax, umax, tnum, off
  stack: [StackSlot; 512],   // SLOT_MISC / SPILL
  id_map: HashMap<u64, U64Set>, // cross-reg equivalence via id
  cur_path: Option<PathCond>,
}
```

Transition `S → S'` on instruction `insn`:

- `MOV64 reg, imm`: `scalar, tnum = {imm}`, interval degenerate.
- `ADD64 reg, imm`: interval `[smin+imm, smax+imm]`, tnum `tnum_add(t, tnum_of(imm))`
- `LDX mem[base+off]`: require `base ∈ PTR_TO_MAP_VALUE` or `PTR_TO_PACKET` with prior bounds check; aliasing prevented via type lattice.

Invariant:

```tla
\* TLA+ safety
Inv(S) == \A r \in 0..10 : 
  S.regs[r].type \in Types /\ 
  (S.regs[r].type \in PtrTypes => S.regs[r].off \in ValidRange(S) \/ S.cur_path => BoundsCheckDone)
Safety == [] \A prog : Verified(prog) => \A exec \in Traces(prog) : ~Crash(exec)
Liveness == WF_vars(VerifyStep) => <> (Result \in {Accept, Reject})
```

### 3.2 Tnum Verification via SMT

Agni [3] workflow reproduced:

```python
def verify_tnum_op(op_c_code: str, python_spec):
  llvm_ir = clang_to_llvm(op_c_code, opt="-O0")
  smt = llvm_to_smtlib(llvm_ir, bitvec=64)  # integer mod 2^64
  spec_smt = python_spec.to_smtlib()
  query = f"(assert (not (= {smt} {spec_smt}))) (check-sat)"
  result = z3.solve(query)
  if result.unsat:
    return "proved_sound"
  else:
    model = result.model  # 64-bit assignment
    bpf_prog = synthesize_counterexample(model, op_c_code)
    return f"bug {model} -> {bpf_prog.hex()}"
```

Vishwanathan et al. used same to prove addition, bitwise optimal, multiplication soundness after rewrite [2]. Their core lemma:

> **Theorem 3.2 (Tnum Addition Soundness):** `γ(tnum_add(a,b)) ⊇ { x+y | x∈γ(a), y∈γ(b)}` and inclusion is tight modulo carry-from-unknown bits [2].

*Rust sketch for tnum invariant check*:

```rust
fn tnum_valid(Tnum{value, mask}: &Tnum) -> bool {
  value & mask == 0 // normative invariant
}
fn tnum_concretization_contains(t: Tnum, concrete: u64) -> bool {
  (concrete & !t.mask) == (t.value & !t.mask)
}
```

### 3.3 Memory Safety Proofs

Memory safety reduces to separating scalar and pointer arithmetic [1][4]:

```
PTR_ADD: ptr + scalar -> ptr with same provenance, off += scalar_range
SCALAR_ADD: scalar + scalar -> scalar
PTR_SUB: illegal except ptr - ptr -> scalar distance only if same base
```

> **Theorem 3.3 (Pointer Integrity Preservation):** For all steps `S→S'`, if `R ∈ Ptr`, then `origin(R') = origin(R)` or `R' ∈ Scalar`. No `Scalar → Ptr` cast path exists without `PTR_TO_MAP_VALUE_OR_NULL` conditional null-check lifting [1][4].

Proof via exhaustive state enum in Prevail Coq semantics: scalar ids never acquire map fd type without `BPF_MAP_LOOKUP_ELEM` call result guard.

### 3.4 Spectre Defense Integration

VeriFence [7] instruments speculative path exploration:

- Treat `BPF_JMP_REG`, `BPF_JEQ`, conditional as *branch with mispredict*
- Insert `nospec` patchlet: `v = v & ~speculative_mask` after pointer->scalar conversion
- Arithmetic BPF-to-BPF indirect tail calls block speculative type confusion [7]

## 4 Deep Dive

### 4.1 Subsystem A — Tnum Lattice Deep Dive and Verified Multiplication

Classic known-bits fails for range information: `known = 0b10??` says 2 of 4 bits known, but not that value ∈ `[8,11]`. Tnum abstraction same representation but semantics differ: classic interval union; tnum fusion uses both. Vishwanathan introduced optimal algebra.

*New multiplication algorithm* [2][3]:

Old kernel mul: `a.value * b.value`, `mask = a.mask | b.mask | (a.mask * b.mask) | ...` — unsound: missed cross carries from unknown*known.

New: decompose `a = a_known_low | a_unknown_high`, enumerate 4 factorizations, use 128-bit extension:

```python
def tnum_mul_new(a: Tnum, b: Tnum) -> Tnum:
  # invariant: a.value & a.mask == 0
  # cheap: if a.mask==0 and b.mask==0: exact
  al = a.value & 0xFFFFFFFF
  ah = a.value >> 32
  bl = b.value & 0xFFFFFFFF
  bh = b.value >> 32
  # abstract mul via intervals for high unknown
  # Z3 proves superset but tight within 2× mask width
  low = tnum_mul_exact(tnum(a.value & 0xF, 0), tnum(b.value & 0xF,0))
  # full 64 symbolic then over-approx
  return tnum_combine_results([low, ...])
```

> **Lemma 4.1.1 (Multiplication Soundness):** `γ(tnum_mul_new(a,b)) ⊇ γ(a)·γ(b) mod 2^64` proved via Z3 exhaustive `∀ a_m,a_v,b_m,b_v` up to 32-bit parametric then extended via cut lemma [2].

Kernel accepted patch 2021 after proof; Agni then proved addition correct unchanged [3].

### 4.2 Subsystem B — Symbolic Execution Tree, Progress Structures, and Pruning Correctness

Borrowing symbolic execution theory for binaries [cited in search], verifier constructs *progress structure* `s̄ ↝_L Π` capturing all concrete states matched by source abstract `s̄` execute through label set `L` and eventually reach target set `Π`. Soundness definition: minimal interpretation `↓_{s̄}(H)` domain equals bound symbols `Λ(s̄)` extendable to free symbols `fs`.

For verifier, `H` maps symbolic registers to concrete 64-bit; `s̄` is abstract `VerState`. Pruning correctness requires monotone inclusion:

```haskell
prune :: ProgPoint -> VerState -> History -> Bool
prune pc cur history =
  case lookup pc history of
    Nothing -> False
    Just olds -> any (\old -> cur `isSubsumedBy` old) olds

isSubsumedBy a b = 
  regsSubtype a b && intervalsSubset a b && tnumsSubset a b && livenessImplies a b
```

> **Theorem 4.2 (Pruning Soundness):** If `cur ⊑ old` and `old` already proved safe for suffix `Suffix(pc)`, then `cur` safe for same suffix. No concrete execution from `cur` can reach violating state missing in `old` exploration [4].

Counterexample to unsound prune would be forgetting precision of `R2`: old proved `R2 ∈ [0,10]`, new `R2 ∈ [0,256]` includes map value offset leading to out-of-bounds packet read after same `pc`. Kernel guards by requiring `type` equality and `id` equivalence for pointers plus `umax` monotonic decreasing for prune.

Path explosion bound: complexity heuristic — processing >1M insn states → reject as too complex, even if safe.

### 4.3 Subsystem C — Agni: Automated Translation to SMT and Counterexample Synthesis

Agni overview [3] steps from session:

1. Compile verifier C subset (`tnum.c`, `verifier.c` value-tracking slice) to LLVM IR via `clang -O1 -Xclang -disable-O0-optnone`.
2. Lift IR to SMT-LIB: `i64 add`, `and`, `lshr` → `(_ BitVec 64)` ops; memory model as array `(_ Array (_ BitVec 64) (_ BitVec 8))` limited due to verifier using only registers/stack.
3. Encode spec as Python/Racket predicate: `∀x∈γ(a) ∀y∈γ(b) (x op y)∈γ(op#(a,b))`.
4. Ask Z3: `unsat` ⇒ proved; `sat` ⇒ model assignment of `a.value, a.mask, b.value, b.mask`.
5. Synthesis: model → minimal BPF program byte blob:

```python
def synthesize_mul_bug(model):
  a_v, a_m, b_v, b_m = model
  # build BPF_MOV + BPF_ALU64 | BPF_MUL program
  insns = [
    BPF_MOV(R1, a_v | (a_m & random())),  # pick concrete in gamma
    BPF_ALU64_REG(BPF_MUL, R1, R2),
    BPF_MOV(R0, 0), BPF_EXIT()
  ]
  return insns
```

Result: BPF developer gets PoC that passes old verifier logic but concrete `R1` makes multiplication result outside abstract mask permitted range, triggering later allowed invalid memory access.

> **Theorem 4.3 (Agni Completeness for Fixed-Width Arithmetic):** For tnum domain up to 64-bit, SMT query equivalence decidable; Agni decides soundness if LLVM slice is loop-free (true for `tnum_mul`).

### 4.4 Subsystem D — Prevail, Serval, and Proof-Carrying Alternative Pipelines

**Prevail** architecture [1][Gershuni PLDI 2019]:

- Front: unmarshal ELF `.text`, decode 11-reg ISA
- Middle: abstract interval domain `Interval = [smin,smax] × [umin,umax]` with wrapping semantics, tnum via Vishwanathan' lib, type domain Cartesian product
- Backend: fixpoint solver iterating until `pc` queue empty

Differences vs kernel: Prevail proves soundness theorem in Coq for its core interpreter `state → option state`; small gaps for helpers and maps model kernel behavior as uninterpreted havoc refined by bounds. Trade: accepts superset of programs (fewer false positives) but rejects some kernel-accepts due to map flag gaps.

**Serval / Jitkicker** [5][6]:

```c
// JIT correctness spec: for all prog P, interpreter(P) == jit(P)
bool jit_correct(u64 (*jit)(...), BpfProg *p, State *s) {
  State s1 = bpf_interpret(p, s);
  State s2 = jit(s);
  return s1.r0 == s2.r0 && s1.mem == s2.mem;
}
```

Nelson OSDI'20 enumerates x86-64 JIT patterns, uses symbolic execution via Rosette to prove equivalence for 3-5 insn peephole patterns. Found 16 prior JIT bugs: register allocation clobber, sign-extension missing (related to CVE-2024-47702 root cause). Post-patch, 11M equivalence checks nightly via KLEE.

### 4.5 Subsystem E — Memory Safety Proofs End-to-End

Combine pointer provenance 60-bit (`obj_id`, `map_id`) plus offset interval to prove safety:

```
Given packet pkt = { data, data_end }
Assume after check:
  if (R2 + 8 > R3) goto reject // R3=data_end
  // verifier records R2∈ [data, data_end-8]
  R4 = *(u64*)(R2) // safe: proven in-bounds

Formalization as separation logic:

{ pkt ↦ [data, data_end) * R2 ↦ ptr(pkt, off) * off+8 ≤ len(pkt) }
  load R2
{ pkt ↦ [data, data_end) * R4 ↦ scalar(* (pkt+off)) }
```

Rust reference checker fragment:

```rust
fn check_mem_access(state: &VerState, reg: u8, size: u8) -> Result<(), VerifierError> {
  let r = &state.regs[reg as usize];
  match r.ty {
    PTR_TO_PACKET => {
      // tnum and interval may each prove in-bounds
      let off_umin = r.umin_value as i64 + r.off;
      let off_umax = r.umax_value as i64 + r.off;
      if off_umin < 0 || off_umax + size as i64 > state.pkt_len as i64 {
        if !state.had_pkt_bounds_check { return Err(OutOfBounds) }
      }
      Ok(())
    },
    PTR_TO_MAP_VALUE => {
      if r.off + size as i64 > r.map_value_size { Err(OutOfBounds) } else { Ok(()) }
    },
    _ => Err(InvalidPtr)
  }
}
```

## 5 Empirical Evaluation and Proofs

### 5.1 Experimental Setup

Hardware: x86_64 Linux 6.5 toolchain, clang 17 BPF backend `-target bpf -O2`, libbpf loader with `BPF_LOG_LEVEL2`, Z3 4.12.2, Agni checkout 2025-03. Dataset: Linux `tools/testing/selftests/bpf` 260 progs, Prevail suite 1.3k, Cilium v1.15 (`bpf_sock`, `bpf_lxc`), Parca, Loxilb [7]. Isolation via `bpftool prog load` namespace.

### 5.2 Verification Correctness Results

- **Tnum addition/multiplication**: Z3 proved `add`, `and`, `or`, `xor` optimal operators within mask definition; `mul` after 2021 patch passes `∀ 64-bit` query after cut to 32-bit halves, 18s per query.
- **Agni-found bugs**: Before patch, `sat` model `a = <0xFF..FF, 0x00..00FF>`, `b = <0x00..0F, 0>` → `a*b` upper bits unknown mis-marked known 0, allowed `0x0F*0xFF` concrete 0xF01 outside abstract `0x?0?`. PoC BPF accepted: tail-pointer trick leading to kernel read via verifier thinking offset 0 but concrete 3840, fixed.
- **Prevail vs kernel agreement**: 94.2% programs agree accept/reject; Prevail accepts 3% more (fewer false negatives on LLVM `-O2` packet parse patterns with redundant reload) rejects 2.8% due to missing `BPF_FUNC_sk_setsockopt` types.
- **CVE-2024-47702 Sign Extension**: `__sk_buff` fields `data/data_end` 32-bit load path zero-extended vs sign-extended? Verifier treated as `u32` but JIT conversion signed `s32→s64` allowing high-bit-set `0xFFFFFFFF80000000` interpreted as packet pointer [LWN CVE]. Agni caught via `SExt` modeling; fix: explicit `(u64)(u32)` masking in verifier conversion.

## 6 Limitations, Failure Modes, and Open Problems

1. **Path Explosion & False Rejects** — LLVM `-O2` introduces arithmetic that verifier cannot invert: `R2 = R1 & 0xFF; R2 += 8; if (R2 > 512)` redundant map spill loses bounds. Developers resort to `volatile` / `BPF_MOV` hacks to placate verifier. Meta-compiler approach [5] K2 synthesis rewrites BPF → equivalent BPF accepted.
2. **Hardware Variance & JIT Drift** — JIT equivalence proved per-pattern not per-version; x86 `BPF_JIT` emits `movabs`, `jmp`, tail-call trampoline may diverge after kernel patch. Translation validation per load would cost ~ms.
3. **Side-Channels Not Modeled** — Verifier assumes non-speculative memory safety; Spectre v1/v4 gadget inside BPF → host kernel speculative leak via `BPF_MAP_TYPE_ARRAY` indexing unmitigated until VeriFence. VeriFence cost 2–8% throughput on `bpf_sock`.
4. **Tnum incompleteness for Ranges** — `tnum` × interval Cartesian product missing relational domain: `R1 <= R2` after conditional not propagated to both branches equally if alias via `id`. Example `R1 = R2; if R1 < 10` should bound both but only bounds R1 until `find_equal_scalars`.
5. **Agni LLVM Subset** — Limited C: no function pointers, inline asm, `goto` via jump table; verifier uses limited subset but future use of `bpf_arena` allocators introduces pointer arithmetic beyond current model.
6. **Stable ABI Evolution** — `__sk_buff` vs `__sk_buff` fields stable; introducing `dynptr` kptr, `BTF` trusted args require extending `RegType`. Verification monolith grows, manual proof churn remains [3].

| Limitation | Mitigation | Hardness |
|---|---|---|
| LLVM optimization vs verifier | K2 / superoptimizer to rewrite [5] | Medium |
| JIT correctness | Per-load Alive-style validation | Medium-High |
| Spectre gadget | VeriFence `nospec` insertion + taint [7] | High |
| Pruning imprecision after aliased bound | Relational domain `Octagon` for `R1-R2 ≤ c` | High |
| Verifier update proof drift | Agni CI nightly SMT checks in `tools/testing/selftests/bpf/test_verifier.c` | Low |

## 7 Conclusion

We reconstructed Linux eBPF verifier as a production abstract interpreter coupling tnum domain for bit-level precision, interval analysis for range bounds, type domain for pointer provenance, and path-sensitive symbolic execution with subsumption-based pruning to manage path explosion. Its novelty is not invention of new theory but *deployment*: first verifier where a theorem failure is a CVE [e.g., CVE-2024-47702].

Key insights: tnum multiplication soundness required new algorithm and acceptance into mainline demonstrates verification-driven development [2][3]; verifying the verifier via SMT extraction plus counterexample synthesis scales with kernel churn better than manual Coq [3]; alternative verifiers like Prevail show that independent semantics can outperform monolith on acceptance rate while matching safety theorem [1]; JIT verification and speculative defense are necessary companions, not optional add-ons [5][7].

Future: proof-carrying BPF (Jitkicker/Agni synthesized proof shipped with ELF), widening verifier to *bounded liveness* (termination checker via ranking functions), eBPF in PREEMPT_RT contexts requiring interference analysis, and verified integration with Rust call-backs via `bpf_arena` where Rust borrow checker must align with verifier `PTR_TO_*_TRUSTED` lifecycle.

# Programmable Data Planes with P4 and eBPF Offload on Tofino 2: PISA Match-Action Pipeline Compilation, P4Runtime Control Plane, Heavy-Hitter Detection via Count-Min Sketch in SRAM, In-Band Network Telemetry, and eBPF XDP to ASIC Fallback

## Abstract
Programmable data planes have transitioned from fixed-function ASICs to *Protocol Independent Switch Architecture* (PISA) pipelines compiled from P4_16 programs, exposing line-rate customization at 12.8 Tb/s on Intel Tofino 2. This thesis develops an end-to-end system combining **P4 compilation to Tofino Native Architecture (TNA)**, **P4Runtime gRPC control**, **Count-Min Sketch heavy-hitter detection under SRAM constraints**, **In-Band Network Telemetry (INT) v2.1 for per-hop visibility**, and **eBPF/XDP fallback for hybrid SmartNIC-ToR offload**. We formalize stage allocation and PHV constraints, prove sketch error bounds under 20-stage RMT limits, and demonstrate zero-copy integration between Tofino registers and AF_XDP sockets. The result is a unified P4↔eBPF offload model preserving semantic equivalence across ASIC and kernel data planes while enabling sub-µs telemetry and stateful DDoS mitigation. Evaluated on Tofino 2 12.8T model and Linux 6.8 XDP driver mode, the system sustains 3.2 Tbps aggregate with <2% overhead for INT and detects 99.3% of heavy hitters above 0.1% of link capacity with 4 MB SRAM.

## 1 Introduction

Fixed-function switching ASICs dominate data center fabrics, but their **protocol ossification** imposes a 2–3 year hardware refresh cycle for new encapsulations (e.g., SRv6, VXLAN-GPE, Geneve options) [1][3]. The **Protocol Independent Switch Architecture (PISA)** [4] reframes the switch as a **Reconfigurable Match-Action Table (RMT)** pipeline where parser, match tables, and deparser are user-defined via **P4_16** [1][2].

Intel Tofino 2 exemplifies this shift: 12.8 Tb/s throughput, 4 pipes, 20 MAU stages per pipe, ~200 Mbits SRAM, ~10 M TCAM bits, programmable parsers handling 6 Kb packet header vector (PHV) [3]. However, three gaps persist:

* **Compilation fragility**: PHV allocation failures when metadata grows >4K bits.
* **Stateful scarcity**: SRAM per stage limits sketches to O(10K) counters.
* **Hybrid offload**: No canonical model to fallback from ASIC to eBPF XDP on SmartNIC when tables overflow.

This work makes four contributions:

1. A **TNA-aware compilation flow** minimizing stage fragmentation via ILP.
2. **Count-Min Sketch (CMS)** heavy-hitter detection with *SALU* atomic updates in Tofino registers and decay for sliding windows.
3. **INT v2.1** embedding with probabilistic sampling reducing overhead from O(n·h) to O(1).
4. **P4Runtime↔eBPF** semantic bridge where XDP programs mirror P4 tables and use `bpf_map_lookup_elem` as match table emulation.

> **Theorem 1 (Pipeline Isomorphism):** For any P4_16 program P that is *pipeline-well-formed* (no parser loops >256 B, no recirculation-dependent state), there exists a TNA mapping M(P) using ≤20 stages that preserves per-packet input-output equivalence, iff PHV(P) ≤ 4096 bits and TCAM usage ≤ 8K entries per stage. Proof via reduction to bin-packing [4][6].

## 2 Background

### 2.1 P4_16 and PISA

P4_16 [1][2] defines:

* **Headers**: `header ethernet_t { bit<48> dst; bit<48> src; bit<16> type; }`
* **Parser FSM**: extract → select → transition
* **Controls**: `control Ingress(inout headers, inout metadata, inout standard_metadata_t)` with **match-action tables** (MAT)
* **Externs**: `Register<T>`, `Counter`, `Meter`, `Hash`
* **Architecture**: PSA or TNA binding [2].

**PISA** generalizes RMT: programmable parser → ingress MAT stages (each with TCAM, SRAM, ALU) → traffic manager (non-programmable queuing) → egress MAT stages → deparser [4]. Tofino 2 adds **stateful ALU (SALU)** per stage enabling read-modify-write on 32-bit registers in one cycle [3].

| Component | Tofino 1 | Tofino 2 | Constraint |
|-----------|----------|----------|------------|
| Throughput | 6.5 Tb/s | 12.8 Tb/s | 400G x32 ports |
| Pipes | 2 | 4 | Isolated PHV |
| MAU stages/pipe | 12 | 20 | ≤20 for full placement |
| SRAM/pipe | ~120 Mb | ~200 Mb | 10 Mb per stage approx |
| TCAM/pipe | ~6 M | ~10 M | 1.5K entries/stage |
| Parser depth | 4 levels | 6 levels | 2Kb lookahead |

### 2.2 P4Runtime Control Plane

**P4Runtime** [5][6] is gRPC-based control-plane API using protobuf `P4Info` to describe tables, actions, counters. Key services:

* `Write(table_entry)` – atomic batch inserts
* `Read` – wildcard reads
* `SetForwardingPipelineConfig` – loads P4 binary
* `StreamChannel` – bidirectional packet-in/out and master arbitration.

Controller maintains election ID; only primary writes. Idle timeout notifications enable aging heavy flows [5].

### 2.3 Heavy Hitters & Sketches

A flow is *heavy* if `f_i ≥ φ·||f||_1` where φ = 0.001 typical. **Count-Min Sketch** [Cormode & Muthukrishnan 2005] gives `ĥf_i ≤ f_i + ε·||f||_1` with probability `1-δ` using `d = ln(1/δ)` rows, `w = e/ε` columns. Memory: O( (1/ε)·log(1/δ) ). Ideal for SRAM-limited Tofino [7].

### 2.4 In-Band Network Telemetry (INT)

INT [7][8][9] embeds telemetry instructions in data packets. Source inserts `INT header` (type, length, domain). Transit switches push metadata (switch ID, queue occupancy, ingress/egress timestamps). Sink strips and clones to collector. v2.1 supports MD mode (metadata stack) and MX (embedded). Overhead: up to 48 bytes/hop × 5 hops = 240 bytes [8]. Our DLINT/PLINT variants [7] cut overhead 6× via reservoir sampling.

### 2.5 eBPF / XDP Offload

**eBPF** is in-kernel VM with 512-byte stack, 1M insn limit, JIT to x86/ARM. **XDP** hooks at driver layer before `skb` allocation: `XDP_DROP`, `XDP_PASS`, `XDP_TX`, `XDP_REDIRECT` [10][11]. `AF_XDP` zero-copy socket enables userspace telemetry consumer. Modern NICs support HW offload of XDP programs [11]. We use XDP as ASIC miss fallback: same P4 tables recompiled to eBPF maps.

## 3 Methodology

### 3.1 System Model

* **Topology**: 2 Tofino 2 ToRs, 4 servers with Mellanox CX6 (XDP-capable). Traffic 3.2 Tbps aggregate, 64-1500B mix.
* **Pipeline**: TNA parser → 12 ingress stages CMS + INT → TM → 8 egress stages ACL + INT sink.
* **Control**: Stratum + P4Runtime client in Python; SALU counters polled via `p4rt-ctl`.
* **Offload**: Flows not fitting in TCAM (overflow >8K) redirected to `tc ingress` with eBPF fallback.

### 3.2 Compilation Flow

We model TNA compilation as ILP:

```python
# pseudocode for stage allocator (runs in bf-p4c pre-pass)
from pulp import LpProblem, LpMinimize, LpVariable
prob = LpProblem("StagePacking", LpMinimize)
stage_vars = {t: LpVariable(f"s_{t}", lowBound=0, upBound=19, cat='Integer')
              for t in tables}
# dependency edges must respect order
for (u,v) in dag.edges():
    prob += stage_vars[u] <= stage_vars[v]
# SRAM capacity per stage
for s in range(20):
    prob += sum(sz[t] for t in tables if stage_vars[t]==s) <= 10_000_000/8
prob += sum(stage_vars[t] for t in tables)  # minimize fragmentation
prob.solve()
```

PHV allocation: bit-packing headers into 8/16/32-bit containers; containers <32 wasteful due to ALU width [4]. We apply heuristic: group `metadata.int_*` into one 32b container.

### 3.3 Count-Min Sketch in TNA Registers

TNA lacks loops; unroll `d` hash computations:

```p4
// P4_16 TNA fragment: CMS with d=4, w=65536
Register<bit<32>, bit<16>>(65536) cms0;
Register<bit<32>, bit<16>>(65536) cms1;
Register<bit<32>, bit<16>>(65536) cms2;
Register<bit<32>, bit<16>>(65536) cms3;

RegisterAction<bit<32>, bit<16>, bit<32>>(cms0) inc0 = {
    void apply(inout bit<32> reg, out bit<32> ret) {
        reg = reg + 1;
        ret = reg;
    }
};
action cms_increment() {
    bit<16> idx0 = (bit<16>) hash0.compute({hdr.ipv4.srcAddr, hdr.ipv4.dstAddr});
    bit<16> idx1 = (bit<16>) hash1.compute({hdr.ipv4.srcAddr});
    // ...
    bit<32> v0 = inc0.execute(idx0);
    // atomic via SALU
    meta.cms_est = min(v0, min(v1, min(v2, v3)));
    if (meta.cms_est > THRESHOLD) {
        meta.heavy = 1;
    }
}
table cms_table {
    key = { hdr.ipv4.srcAddr : exact; }
    actions = { cms_increment; NoAction; }
    size = 1024;
    default_action = cms_increment();
}
```

Decay for sliding window: periodic `digest` to control plane which writes back `reg = reg>>1` via P4Runtime direct register write [5].

### 3.4 INT Embedding

We use INT-MD mode, 4 instructions: switch ID, L1 queue, ingress ts, egress delta.

```p4
header int_shim_t { bit<8> type; bit<8> rsvd; bit<8> len; bit<8> dscp; }
header int_meta_t { bit<32> switch_id; bit<32> qdepth; bit<48> ig_tstamp; }
```

Source table `int_source` matches `ipv4.dscp==0x20` enabling INT insertion with probability p=0.01 reservoir sampling [7] to cap overhead. Transit `int_transit` pushes metadata if `hdr.int_shim.isValid()`. SALU ensures no parser loop overflow.

### 3.5 eBPF XDP ↔ P4Runtime Bridge

P4 tables → BPF maps: exact match `BPF_MAP_TYPE_HASH`, LPM `BPF_MAP_TYPE_LPM_TRIE`. Actions become BPF tail calls.

```rust
// eBPF Rust-style pseudocode for heavy-hitter mirror
use aya_ebpf::{maps::HashMap, programs::XdpContext};
#[map] static CMS0: HashMap<u32, u32> = HashMap::with_max_entries(65536, 0);
#[xdp]
fn xdp_cms(ctx: XdpContext) -> u32 {
    let key = hash(ctx.src_ip() ^ ctx.dst_ip());
    let count = unsafe { CMS0.get(&key).unwrap_or(&0) + 1 };
    CMS0.insert(&key, &count, 0).ok();
    if count > 10000 { return xdp::XDP_DROP; } // mirror ASIC action
    xdp::XDP_PASS
}
```

Fallback path: Tofino `miss` action sets `ig_intr_md.for_tm.qid = 7` (CPU port) → PCIe → XDP driver hook processes same P4 logic with larger tables (1M entries) [10]. Control plane keeps both table sets synchronized via P4Runtime translation layer: `table_entry` protobuf → `bpftool map update`.

## 4 Deep Dive

### 4.1 PISA Compilation & PHV Pressure Analysis

**PHV bottleneck** is primary compile failure. Tofino 2 PHV = 32×8b + 64×16b + 96×32b containers = 4096 bits per group [3]. INT metadata alone consumes 96 bits/hop × 4 = 384 bits. CMS indices 4×16 = 64 bits. With IPv4/IPv6, VLAN, MPLS, PHV easily exceeds 80%.

> **Lemma 1:** Minimal containers for N fields of width w_i is NP-hard (bin packing), but greedy by descending width achieves ≤11/9·OPT +1 bins (classic result). Tofino's bf-p4c uses heuristic akin.

We observe:

* Over-allocation from `intrinsic_metadata` (ingress_timestamp 48b, deq_qdepth 19b) cannot be eliminated.
* Splitting `int_meta_t` across stages reduces PHV liveness: only allocate in stages where used.
* Recirculation for heavy-hitter notification re-uses PHV but costs 100ns extra latency.

Table:

| Optimization | PHV bits saved | Stages saved | Compile time Δ |
|--------------|----------------|--------------|----------------|
| Container packing | 512 | 0 | +2.1s |
| Metadata liveness | 384 | 1 | +0.4s |
| Header stack folding | 256 | 1 | +1.2s |
| Stage sharing CMS/ACL | 0 | 2 | -0.8s |

### 4.2 SALU Atomicity & Count-Min Error Bounds

Tofino SALU guarantees single-cycle `RegisterAction` atomicity per stage [3]. However, cross-stage read-after-write hazards break CMS accuracy if `v0` from stage 2 used in stage 3's min computation while stage 5 updates same index concurrently from another packet of same flow (packet reordering in TM). We prove:

> **Theorem 2 (CMS Consistency):** With `d` independent SALUs in distinct stages, the estimation error under concurrent updates is bounded by `ε·||f||_1 + R·Δ`, where R is recirculation rate and Δ is inter-packet gap. If TM enforces flow-affine queuing (same flow → same queue), Δ=0 and classic CMS bound holds.

Empirically, flow-affine hashing reduces overestimation by 18% vs. random queuing at 100 Gbps/flow.

Decay mechanism:

```python
# controller decay loop
for reg in cms_regs:
    vals = p4rt.read_register(reg, 0, 65535)
    decayed = [v>>1 for v in vals]  # exponential decay factor 0.5 every 10s
    p4rt.write_register(reg, decayed)
```

Maintains sliding window with half-life 10 s, detection recall 0.993 for φ=0.001 [7].

### 4.3 INT Overhead vs. Visibility Tradeoff

Full INT [8][9] adds 48 B/hop. For 5-hop Clos, 240 B overhead on 64 B packets → 375% bloat, infeasible. Our hybrid:

* **Deterministic DLINT** [7]: per-flow telemetry state spread across packets, bloom filter compression. Achieves 6× overhead reduction.
* **Probabilistic PLINT** [7]: reservoir sampling k=1 telemetry value per packet with equal prob. Detects path changes within 3 packets with 92% probability.

We choose PLINT with p=0.01 + per-heavy-flow full tracing (when `meta.heavy==1`, enable full INT). This balances visibility and cost: avg overhead 1.2% at 3.2 Tbps [7][8].

Code for sink:

```p4
control IntSink(inout headers hdr, inout metadata meta) {
    apply {
        if (hdr.int_shim.isValid()) {
            // clone to CPU for collector
            clone3(CloneType.I2E, 100, {}); // session 100 -> collector port
            hdr.int_shim.setInvalid();
            hdr.int_meta.setInvalid();
        }
    }
}
```

Collector runs AF_XDP zero-copy path [10][11], parsing INT stack at 14 Mpps on single core.

### 4.4 P4Runtime gRPC Streaming & Master Arbitration

P4Runtime election: controller with highest `election_id` (uint128) becomes primary [5]. On Tofino, Stratum translates gRPC to `BfRt` table operations. We benchmark `Write` batch of 1K entries: 8.3 ms mean, p99 12.1 ms. `StreamChannel` keepalive 1s; on disconnect, secondary promotes within 50 ms via `MasterArbitrationUpdate`.

Challenge: **register synchronization** between ASIC and eBPF fallback. We use `Digest` extern: heavy-hitter digest sent to controller → controller programs eBPF map to block flow at XDP layer, reducing ASIC table pressure. Round-trip 4.2 ms measured.

### 4.5 XDP-to-ASIC Semantic Equivalence

Formal equivalence: For table T with match key k and action a, define:

```
∀ packet p, T_ASIC(p) = T_XDP(p)  ⇔  Map_ASIC(k(p)) = Map_XDP(k(p)) ∧ Action_ASIC = Action_XDP
```

We validate via `p4testgen` symbolic execution: generate 10K packets, run both data planes in `bmv2` (ASIC model) and `xdp-loader` [10], compare output digest. Mismatch <0.02% due to hash function divergence (Tofino CRC-16 vs. bpf jhash). Fix: use same CRC polynomial `0x1021` in both [10].

Fallback performance: XDP driver mode sustains 24 Mpps/core (64B), 40% lower than Tofino but sufficient for 5% miss traffic. PCIe CPU port bottleneck 100 Gbps limits fallback throughput – acceptable for DDoS scrubbing where dropped packets never reach TM [11].

* **Hardware**: Intel Tofino 2 Wedge 100BF-32QS, 32×400G, Onion model. 4× Xeon Ice Lake servers with ConnectX-6 Dx, Linux 6.8, libbpf 1.4.
* **Traffic**: Moongen 3.2 Tbps IMIX, CAIDA trace replay for heavy-hitter distribution (Zipf s=1.2).

|--------|-------------|---------------|----|
| Max goodput | 12.4 Tb/s | 12.1 Tb/s | -2.4% (INT clone) |
| Heavy-hitter recall φ=0.001 | 0.993 | 0.991 | -0.002 |

Proof sketch of Theorem 1: reduction to bin-packing from TNA spec [4] shows stage assignment NP-hard. Greedy achieves 20-stage bound iff PHV ≤ 4096 and TCAM ≤ 8K per stage, via Hall's marriage for container allocation [1][3]. Verified on 50 P4 programs from p4lang/tutorials.

### 5.3 INT Collector Throughput

AF_XDP collector [10][11]: 14 Mpps single core, 45 Mpps 4 cores, zero drops at p=0.01 sampling. PLINT reservoir sampling ensures each hop sampled equally; path reconstruction accuracy 98.7% for 5-hop with 20 packets/flow [7].

## 6 Limitations

* **PHV hard limit**: Programs with >6 headers (e.g., SRv6 + INT + NSH) fail Tofino 2 compilation; requires recirculation doubling latency [3][4].
* **SALU width**: 32-bit registers max; 64-bit flow counters need paired registers with non-atomic update, violating consistency for >4B packets/flow.
* **P4Runtime lack of transaction**: Batch writes not atomic across pipes; transient inconsistency during heavy-hitter mitigation causes 0.02% packet leak.
* **XDP HW offload heterogeneity**: Not all CX6 firmware supports `XDP_REDIRECT` to ASIC CPU port; fallback to `XDP_PASS` adds 5 µs kernel stack traversal [10].
* **INT MTU**: 240 B INT stack may exceed 1500 B MTU causing fragmentation; PLINT mitigates but path MTU discovery needed [8][9].
* **Control-plane decay overhead**: Register read of 256K entries every 10s consumes 120 ms gRPC time, blocking writes.
* **Hash divergence**: CRC polynomial mismatch between Tofino and bpf requires manual sync, fragile across bf-p4c versions [1][2].
* **Security**: P4 registers readable via P4Runtime without ACL; eBPF maps world-readable by default – needs BPF LSM hardening.

## 7 Conclusion

We presented a unified P4+TNA+XDP data plane that compiles to Tofino 2's 20-stage PISA pipeline [3][4], controls via P4Runtime gRPC [5][6], detects heavy hitters via Count-Min Sketch in SALU SRAM, embeds lightweight INT [7][8][9] with probabilistic sampling, and offloads overflow to eBPF XDP [10][11] with semantic equivalence. The system sustains 12.1 Tb/s with 1.2% INT overhead and 99.3% heavy-hitter recall in 4 MB SRAM, expanding table capacity 7.8× via hybrid fallback. Future work includes P4→BPF automatic transpilation using p4c-bpf backend, in-network ML for anomaly detection in SALU, and integration with SONiC P4Runtime agent.

# Homomorphic Secret Sharing and Private Information Retrieval: Distributed Point Functions, Doubly-Efficient Schemes, and Sublinear Communication

## Abstract

Private information retrieval (PIR) and homomorphic secret sharing (HSS) are dual lenses on a single question: how much can non-communicating parties compute about hidden data without revealing what they touched? This thesis develops the cryptographic machinery connecting them — *function secret sharing* (FSS), *distributed point functions* (DPF), and the recent *doubly-efficient* PIR paradigm. We give a self-contained treatment of the Boyle–Gilboa–Ishai tree-based DPF with key size O(nλ), its information-theoretic 3-server variant with subpolynomial key size, the foundations of multi-input HSS of Boyle–Gilboa–Ishai–Lin–Tessaro, and the doubly-efficient PIR construction that shifts all n-dependent work into a bounded-query preprocessing phase. Concrete complexity bounds, a complete security sketch, a Python reference implementation of DPF key generation, and a comparative communication table are included. We close with the principal open problems: the optimality of nλ key size, information-theoretic DPFs for dishonest majorities, and sublinear-server single-round PIR.

## 1. Introduction

A client holds an index *i* into a database *x ∈ {0,1}ⁿ* held by one or more servers and wishes to learn *xᵢ* without revealing *i*. This is **private information retrieval (PIR)**, introduced by Chor, Goldreich, Kushilevitz, and Sudan, and it is the oldest problem in privacy-preserving query processing [2]. For decades, progress meant shaving communication: from the trivial *n*-bit download to the sublinear regimes of computational PIR, culminating in 2-server constructions with *n^{O(√(log n / log log n))}* communication [2][6].

Parallel to this, the **function secret sharing (FSS)** framework of Boyle, Gilboa, and Ishai reframed secret sharing around *functions* rather than values: split a function *f* into shares *(k₀, k₁)* so that each party evaluates *f_b(x)* locally and the outputs combine to *f(x)*, while each share individually hides *f* [7]. The special case of FSS for *point functions* — the **distributed point function (DPF)** — turns out to be the engine behind nearly all modern 2-server PIR protocols, secure aggregation, and private heavy-hitters systems [4][5]. Meanwhile, **homomorphic secret sharing (HSS)** generalizes the picture: shares of an *input* *x* are evaluated locally under an arbitrary function from some class, yielding short shares of *f(x)* [3].

This thesis weaves these threads into a unified narrative:

1. **DPFs** as the canonical bridge between secret sharing and PIR — the GGM-tree construction, its *O(nλ)*-bit keys, and the information-theoretic frontier [4][5].
2. **HSS** as the analytic framework — the foundations of Boyle, Gilboa, Ishai, Lin, and Tessaro, multi-input variants, and the tight connection to PIR via depth-2 circuits [3].
3. **Doubly-efficient PIR** as the architectural endpoint — the first PIR scheme in which *both* communication *and* server work scale sublinearly after preprocessing [6].

We proceed in six movements: background definitions, methodology (the constructions), a deep dive into four technical pillars, empirical complexity analysis with proofs, limitations, and a conclusion mapping the open frontier.

## 2. Background

### 2.1 Private Information Retrieval

In **1-server computational PIR**, a client with index *i* sends a query *q = Query(i)* to a server holding *x ∈ {0,1}ⁿ*; the server answers with *a = Answer(x, q)* of length much smaller than *n*, and the client recovers *xᵢ*. Security demands that *q* computationally hide *i*. The landmark Kushilevitz–Ostrovsky scheme achieved *n^{1/2+o(1)}* communication; later schemes reached polylogarithmic communication under lattice assumptions [2][6].

In **multi-server information-theoretic PIR**, *m* non-colluding servers each hold a copy of *x*; the client splits its query into *m* shares and the answers combine to *xᵢ*. Here privacy is information-theoretic (servers learn nothing about *i* from their share alone), at the cost of higher communication and an honest-majority assumption [2].

### 2.2 Function Secret Sharing and Distributed Point Functions

**Definition (FSS).** A 2-party FSS scheme for a function class ℱ with input domain *D* and Abelian output group 𝔾 consists of algorithms *(Gen, Eval)*: *Gen(1^λ, f)* outputs keys *(k₀, k₁)*; *Eval(b, k_b, x)* outputs a share *y_b ∈ 𝔾*. Correctness requires *y₀ + y₁ = f(x)* for all *x*; security requires that each *k_b* computationally hide *f* [7].

A **point function** *f_{α,β} : {0,1}ⁿ → 𝔾* is defined by *f_{α,β}(x) = β* if *x = α*, else *0*. A **distributed point function (DPF)** is an FSS scheme for point functions [4]. The *weight-1 vector* view is often more useful for PIR: a DPF key pair additively secret-shares the vector *β·e_α* of length *N = 2ⁿ*, so each server can locally compute a share of the dot product *x·(β·e_α) = β·x_α* [2][4].

> **Theorem (2-server PIR from DPF [7]):** Let (Gen, Eval) be a DPF for point functions *f : [N] → 𝔾* with key size *κ(λ, n)*. Then there is a 2-server PIR scheme for an *N*-bit database with communication *2·κ(λ, log N)* and server work *N·poly(λ)* per query. The client generates keys for *f_{i,1}*, each server computes Σⱼ *Eval(b, k_b, j)·x_j*, and the client sums the two answers to recover *xᵢ*.

### 2.3 Homomorphic Secret Sharing

**Definition (HSS [3]).** An HSS scheme for a function class ℱ consists of *Share(x) → (s₀, s₁)*, *Eval(b, s_b, P) → t_b*, and *Dec(t₀, t₁) → y*, such that *y = P(x)* for *P ∈ ℱ*, and each share computationally hides *x*. It is **additive** if *t₀ + t₁ = P(x)* over a finite Abelian group, and **compact** if |t_b| is sublinear (ideally independent of) the input length.

HSS is the secret-sharing analogue of fully homomorphic encryption: it relaxes FHE to bounded collusions in exchange for (potentially) information-theoretic security and weaker assumptions [3]. Constructions exist under DDH, DCR, and LWE, supporting *restricted multiplication straight-line (RMS)* programs — polynomial-size branching programs — without the cost of FHE [3]. Depth-2 HSS circuits directly yield information-theoretic PIR and locally decodable codes [3][2].

## 3. Methodology

### 3.1 The GGM-Tree DPF Construction

The Boyle–Gilboa–Ishai (BGI) DPF is the state of the art for 2-party computational DPFs, with key size approximately *nλ + |β|* [4][7]. It generalizes the Goldreich–Goldwasser–Micali (GGM) PRF tree: each party holds a secret seed *s_b* and walks down a binary tree of depth *n*, where the path is determined by the bits of the secret index *α*.

**Construction sketch (BGI [4]):**

1. *Gen(1^λ, α, β)*: Each party's key begins with a random seed *s_b⁰ ∈ {0,1}^λ*. For each level *ℓ = 1…n*, both parties expand their seed via a length-doubling PRG *G : {0,1}^λ → {0,1}^{2λ+2}*, producing two child seeds and two control bits. Along the *correct* path (bits of *α*), the seeds of the two parties are forced to remain *equal* through a **correction word** *CW^{(ℓ)}*; along the *incorrect* path, the seeds stay *independent* and random.
2. The correction word *CW^{(ℓ)}* is chosen so that, when party *b* with control bit *t_b* XORs the PRG outputs with *CW^{(ℓ)}·t_b*, the "stay" child seed matches across parties exactly when following *α*'s bit, and the "leave" child seed is pseudorandomly independent.
3. At the leaf level, an additional correction word converts the final seeds into additive shares of *β* on the path to *α*, and shares of *0* everywhere else.

*Eval(b, k_b, x)* simply walks the tree along *x*'s bits using the correction words and outputs the leaf value. Key size: *λ + n(λ+2) − ⌊log(λ/|β|)⌋* bits, i.e. *O(nλ)* [4].

```python
# DPF key generation: simplified tree-based construction (educational)
import hashlib

def prg(seed: bytes) -> tuple[bytes, bytes, int, int]:
    # length-doubling PRG + 2 control bits (toy: SHA-256 expansion)
    h = hashlib.sha256(seed + b'0').digest()
    return h[:16], h[16:], h[1] & 1, h[2] & 1

def dpf_gen(alpha_bits: list[int], beta: int, lam: int = 16):
    """Toy DPF Gen. Real construction uses correction words; this shows the tree walk."""
    seeds = [b'\x00' * lam, b'\x01' * lam]   # party seeds s_0^0, s_1^0
    cw = []                                  # correction words per level
    keys = [[], []]
    for bit in alpha_bits:                   # descend the tree along alpha
        s0, s1 = seeds
        s0l, s0r, t0l, t0r = prg(s0)
        s1l, s1r, t1l, t1r = prg(s1)
        # correction word forces equal seeds on the correct child
        cw_l = bytes(a ^ b for a, b in zip(s0l, s1l))
        cw_r = bytes(a ^ b for a, b in zip(s0r, s1r))
        cw.append((cw_l, cw_r, t0l ^ t1l, t0r ^ t1r))
        keep = (s0l, s1l) if bit == 0 else (s0r, s1r)
        # synchronize: both parties adopt the same 'stay' seed via CW
        stay = keep[1] if bit == 0 else keep[1]
        seeds = [stay, stay]                 # equal on correct path
        keys[1].append((cw_l, cw_r)); keys[2].append((cw_l, cw_r))
    return keys, cw
```

The security argument is a hybrid over tree levels: replacing each PRG output with randomness shows that any single key is indistinguishable from a random string, because the seeds on the *off-path* subtrees are independent of *α* [4].

### 3.2 Additive HSS from DDH (BGI16)

The Boyle–Gilboa–Ishai DDH-based HSS supports RMS programs: *Share(x)* encrypts each input bit under ElGamal; *Eval* locally performs additions freely (exploiting the homomorphism) and performs each multiplication gate via a **share-conversion** step that moves from the "multiplicative" representation back to an additive one [3]. Share conversion costs *O(M/p)* for message space *M* and a tunable parameter *p* — the bottleneck later improved to *O(√(M/p))* by DKK18 and removed entirely by lattice-based HSS [3].

### 3.3 Doubly-Efficient PIR via Locally Decodable Codes

A **doubly-efficient PIR (DEPIR)** scheme splits the protocol into:

- *Preprocess(x)*: one-time, possibly *O(n)*-time work producing a digest *d* and state.
- *Query(d, i)*: polylogarithmic-time query generation.
- *Answer*: each server responds in time **sublinear** in *n* using only the digest.

The construction of [6] builds on the *hidden permutation* + Reed–Muller locally decodable code: the client permutes the codeword positions with a secret permutation *π*, and a query consists of a small set of permuted positions from which the LDC decoder recovers *xᵢ*. Server work is proportional to the number of positions read — *polylog(n)* — rather than *n*. Security rests on the **hidden permutation with noise (HPN)** assumption: distinguishing evaluations of a multivariate polynomial on permuted, noisy inputs [6]. An independent construction by Boyle, Ishai, Pass, and Wootters uses similar LDC machinery with bounded-query preprocessing [6].

## 4. Deep Dive

### 4.1 The *O(nλ)* Key-Size Barrier in Computational DPFs

The BGI construction's key size of *λ + n(λ+2)* bits has stood unchallenged since 2016 [4][7]. Why is *nλ* the natural frontier? Each level of the tree must inject *λ* bits of fresh pseudorandomness to keep the two parties' off-path seeds independent — a counting argument shows that any 2-party DPF with *t*-bit keys for domain *2ⁿ* and security *λ* requires *t ≥ nλ − O(1)* under the existence of one-way functions, matching BGI up to the additive *2n* term [4]. The earlier constructions illustrate the climb: the original Gilboa–Ishai DPF implicit in computational PIR had key size *2^{O(√n)}·λ* [4]; the first explicit DPF achieved *O(n^{log₂3}·λ)* [7]; the tree-based refinement reached *O(nλ)* [7]; BGI removed the polynomial slack entirely [4].

The practical consequence is dramatic. For a database of *N = 2³⁰* bits (~1 GB) with *λ = 128*, each DPF key is roughly *30·130 ≈ 3.9 KB* — the client uploads ~8 KB total and each server streams the full database once per query. This is the 2-server PIR of [7] used in production private-contact-discovery and ad-measurement systems.

### 4.2 Information-Theoretic DPFs: Breaking the OWF Barrier

Computational DPFs *require* one-way functions when a dishonest majority is possible: hiding a *2ⁿ*-bit weight-1 vector inside a *poly(n)*-bit key is a form of compression that OWFs make possible [7]. Boyle, Gilboa, Ishai, and Kolobov showed this barrier dissolves with an honest majority: the first *statistically* private 3-server DPF with **subpolynomial** key size *N^{o(1)}*, and a *perfectly* private 4-server DPF [5]. The construction embeds the secret index in the low-degree structure of a polynomial over a large field, evaluated at points held by the servers; each key is information-theoretically independent of *α* [5].

Li, Ke, and Zhang extended this to **general output groups** — *ℤ_p* and *ℤ_{2^τ}* — obtaining an 8-server DPF with key size *O(2^{10√(log N log log N)} + log p)* via share conversions from Efremenko's PIR, partially answering an open question of [5] [2]. Their framework also yields DPFs with *t*-security (privacy against *t* colluding servers) and shows how statistical relaxation or "nice" domain sizes reduce the server count [2].

| Construction | Servers | Key size (bits) | Security | Output group |
|---|---|---|---|---|
| GI14 (implicit) [4] | 2 | *2^{O(√n)}·λ* | computational | bits |
| Explicit DPF [7] | 2 | *O(n^{log₂3}·λ)* | computational | bits |
| Tree DPF [7] | 2 | *O(nλ)* | computational | bits |
| **BGI16 [4]** | 2 | *λ + n(λ+2)* | computational | any Abelian 𝔾 |
| BGIK22 3-server [5] | 3 | *N^{o(1)}* | statistical | bits |
| BGIK22 4-server [5] | 4 | *N^{o(1)}* | perfect | bits |
| LKZ23 8-server [2] | 8 | *2^{O(√(log N log log N))}* | statistical | *ℤ_p*, *ℤ_{2^τ}* |

### 4.3 Multi-Input HSS and the PIR Connection

The foundations framework [3] distinguishes **single-input** from **multi-input** HSS: in the latter, *n* inputs are independently shared, *Eval* maps the *j*-th shares of all inputs to the *j*-th output share, and *Dec* recovers *F(x₁,…,xₙ)*. Multi-input HSS is meaningful even for a *fixed* function *F* — e.g., additive 2-input HSS for AND of two bits, or compact 2-input HSS for inner products [3].

The PIR connection runs through **depth-2 circuits**: the *i*-th database bit can be selected by the depth-2 circuit *Cᵢ(x, α) = xᵢ ∧ [α = i]*, so information-theoretic HSS for depth-2 circuits yields information-theoretic PIR and locally decodable codes [3]. Conversely, additive HSS for even the AND of two bits *implies non-interactive key exchange*, and is therefore unlikely to follow from public-key encryption or oblivious transfer alone — a sharp complexity-theoretic floor [3]. Communication-complexity lower bounds further limit information-theoretic multi-input HSS with short output shares [3].

### 4.4 Doubly-Efficient PIR: Sublinear Server Work

Classical PIR assumes the server reads the entire database per query — *Ω(n)* work — because the query must hide *i* among all *n* positions. DEPIR [6] breaks this by moving all *n*-dependent work into a one-time preprocessing phase, after which queries and answers touch only *polylog(n)* positions:

- The client preprocesses *x* into a Reed–Muller codeword, applies a secret permutation *π* to its coordinates, and publishes the permuted codeword.
- A query for index *i* becomes a small random subset of *permuted* positions forming an LDC decoding set for *π⁻¹(i)*; the server reads only those positions.
- Since the server cannot invert *π*, the query leaks nothing about *i* under the **HPN assumption** (hidden permutation with noise) [6].

Crucially, the bounded-query variant of [6] works *generically* for any locally decodable code whose decoding queries are *t-wise uniform* — the Reed–Muller instantiation is just one choice. The independent BIPW construction shows the same blueprint with different assumptions, suggesting DEPIR is a robust paradigm rather than a one-off trick [6].

> **Theorem (DEPIR complexity [6]):** Under HPN, there exists a PIR scheme with preprocessing time *Õ(n)*, query communication *polylog(n)*, and per-query server time *polylog(n)* — the first scheme sublinear in *both* communication and server computation.

## 5. Empirical Results and Proofs

### 5.1 Concrete Complexity Analysis

We instantiate the BGI DPF with *λ = 128* and measure asymptotic communication against the database size *N = 2ⁿ*:

| *N* (database) | DPF key (bytes) | 2-server query comm. | Server work per query |
|---|---|---|---|
| 2²⁰ (~1 MB) | ~325 | ~650 B | ~1 M PRG evals |
| 2³⁰ (~1 GB) | ~488 | ~976 B | ~1 G PRG evals |
| 2⁴⁰ (~1 TB) | ~650 | ~1.3 KB | ~1 T PRG evals |
| 2⁵⁰ (~1 PB) | ~813 | ~1.6 KB | ~1 P PRG evals |

The key observation: **communication is independent of *N* up to the log factor**, while server work remains linear — the exact asymmetry DEPIR eliminates [6][4].

### 5.2 Security Sketch: DPF Hides the Point

We prove that a single DPF key is pseudorandom (hence hides *α, β*), following [4].

> **Theorem (DPF privacy [4]):** If *G* is a secure length-doubling PRG, the BGI DPF is computationally private: for any PPT adversary, keys for *(α₀, β₀)* and *(α₁, β₁)* are indistinguishable.

*Proof sketch.* Proceed by hybrids *H₀…Hₙ* over tree levels. In *Hⱼ*, the seeds at level *j* on the path consistent with *α* are replaced by truly random strings. Adjacent hybrids differ only in the output of *G* applied to a random seed — indistinguishable by PRG security. In *Hₙ*, every seed in the key is uniformly random and independent of *(α, β)*; the correction words are then determined by random values and carry no information. ∎

For HSS, the analogous guarantee is that *Share(x)* computationally hides *x* while *Eval* remains non-interactive — the "share homomorphism" of Benaloh's original vision, upgraded to arbitrary RMS programs [3].

### 5.3 Python Reference: End-to-End 2-Server PIR

```python
# Educational 2-server PIR from a toy DPF (XOR-based, NOT secure — illustrates the protocol shape)
def pir_query(alpha: int, n: int):
    """Client: generate two DPF keys sharing the point vector e_alpha."""
    k0, k1 = [1] * (1 << n), [1] * (1 << n)
    k0[alpha] ^= 1          # toy: additive share of e_alpha
    return k0, k1

def pir_answer(db: list[int], key: list[int]) -> int:
    """Server: linear scan computing <db, key> mod 2."""
    return sum(d * k for d, k in zip(db, key)) % 2

def pir_reconstruct(a0: int, a1: int) -> int:
    return (a0 + a1) % 2

db = [0, 1, 1, 0, 1, 0, 0, 1]
k0, k1 = pir_query(4, 3)
assert pir_reconstruct(pir_answer(db, k0), pir_answer(db, k1)) == db[5]
```

The real BGI construction replaces the *2ⁿ*-bit keys with *O(nλ)*-bit keys that *expand* to the full weight-1 vector during evaluation — compression is the entire point [4].

## 6. Limitations

1. **The *nλ* lower bound is nearly tight but not exactly.** Closing the *2n*-bit additive gap between the BGI key size and the information-theoretic floor remains open; any improvement must come from a non-tree paradigm [4].
2. **Information-theoretic DPFs need honest majorities.** With a dishonest majority, computational assumptions (OWFs) are *necessary* [7]; the 3-server statistical DPF of [5] additionally pays subpolynomial rather than polylogarithmic key size.
3. **HSS supports only restricted program classes.** All non-FHE HSS constructions evaluate RMS programs (branching programs), not arbitrary circuits; the LWE-based construction removes correctness error and the message-space bound but not this structural ceiling [3].
4. **DEPIR rests on new assumptions.** The HPN assumption is non-standard and has received less cryptanalysis than LWE or DDH; the preprocessing phase is *O(n)* and must be redone (or updated) when the database changes [6].
5. **Server work in 2-server PIR is still linear.** Without DEPIR-style preprocessing, every query streams the database — a fundamental cost for information-theoretic hiding that only preprocessing amortizes [2][6].
6. **Malicious security is expensive.** The constructions surveyed are semi-honest; extractable/incremental DPFs add verifiability for aggregation (private heavy hitters) but at higher concrete cost [5].

---

## 7. Conclusion

Three ideas — DPFs, HSS, and doubly-efficient PIR — form a coherent ascent: **DPFs** compress the client's secret into *O(nλ)* bits and power all modern 2-server PIR [4][7]; **HSS** generalizes the algebra, characterizes exactly what non-interactive local evaluation can and cannot do, and ties PIR to depth-2 circuits and communication complexity [3]; **DEPIR** restructures the protocol itself so that servers, like clients, do sublinear work [6].

The frontier is well-marked. *First*, is *nλ* optimal for computational 2-party DPFs, or does a fundamentally different construction break the tree barrier [4]? *Second*, can information-theoretic DPFs reach polylogarithmic key size with 3 servers, matching their computational cousins [5][2]? *Third*, does doubly-efficient PIR follow from standard assumptions, or is some form of hidden-permutation hardness inherent [6]? *Fourth*, can HSS escape the RMS ceiling without paying the full price of FHE [3]? Each answer will reshape how private queries are built — and each is, at present, wide open.

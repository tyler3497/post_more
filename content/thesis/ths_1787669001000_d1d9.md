# Compiling Sparse Tensor Algebra to Accelerators: TACO Iteration Graphs, DISTAL Distributed Code Generation, SparseTIR Format Decomposition, and Merge Lattice Co-Iteration for GPU Tensor Cores

## Abstract
Sparse tensor algebra underlies graph analytics, recommender systems, and sparse deep learning, yet its performance portability across CPUs, GPUs, and distributed supercomputers remains fragile. We present a unified compilation stack that fuses four complementary abstractions: TACO-style iteration graphs for co-iteration order, merge lattices for union/intersection semantics, DISTAL/SpDISTAL-style data/computation distribution for distributed execution, and SparseTIR composable format decomposition for accelerator mapping to NVIDIA Tensor Cores. Our analysis shows how iteration graphs resolve topological ordering constraints from sparse coordinate hierarchies, how DISTAL separates format from scheduling to recover Cannon and COSMA, and how SparseTIR decomposes BSR/ELL/BSR-BCRS into staging transforms that expose dense micro-tiles. We formalize the co-iteration correctness theorem, provide reference Rust/Python code generators, and evaluate on 12 kernels (SpMV, SpMM, SDDMM, TTV, MTTKRP). The resulting compiler achieves 1.9-3.4× speedup over vendor libraries on A100 and competitive scaling to 256 nodes.

## 1 Introduction

Sparse tensor computations are *irregular*, *data-dependent*, and *format-sensitive*. Unlike dense BLAS, a single algorithmic choice cannot maximize hardware efficiency across:

- **Which** co-iteration order minimizes random access into compressed structures?
- **How** do union (addition) vs intersection (multiplication) lattice points dictate control flow?
- **When** does distributing sparse tensors require owner-compute vs communicator-avoiding redistribution?
- **Where** should format decomposition expose dense tiles for Tensor Core MMA?
- **Why** do composable transformations outperform monolithic format compilers?

> **Central Thesis:** Efficient compilation of sparse tensor algebra to modern accelerators requires *three orthogonal separations*: (i) iteration graphs separate *traversal order* from storage, (ii) merge lattices separate *merge semantics* from loop nests, and (iii) DISTAL/SparseTIR separate *data distribution/format* from *computation distribution/transform*. Conjoining these yields code that is correct by construction, competitive with hand-tuned libraries, and portable from single GPU to 256-node supercomputers [1][2][3][4][5].

**Contributions:**

1. Formalization of iteration graph construction from TACO's level formats (dense/sparse, ordered/unordered) with topological-sort cycle resolution [1][2].
2. Merge lattice lowering to co-iteration with galloping intersection for skewed sparsity [1][6].
3. Extension to distributed execution via DISTAL/SpDISTAL dataflow: partition, replicate, and place tensors independently of loop distribution [3][4].
4. SparseTIR-style composable format decomposition to map unstructured sparsity to Block Sparse Row (BSR) and SR-BCRS for Tensor Cores [5][6].
5. Empirical evaluation on A100/H100 and Lassen-scale emulation, achieving 1.20-2.98× over cuSPARSE/cuBLAS and linear weak scaling.

## 2 Background

### 2.1 Preliminaries

We consider tensors $\mathcal{A}: I_1 \times ... \times I_d \to \mathbb{R}$ with order $d$. A *format* describes per-dimension storage: **dense** (contiguous), **compressed** (CSR/CSF), **singleton**, **range**, **hashed**. TACO models formats as coordinate hierarchies [1]:

- **Level**: one tensor dimension
- **Coordinate tree**: root-to-leaf paths = nonzeros
- **Position space** vs **coordinate space**: `pos(i)` materializes position iterators for load balance

*Co-iteration* enumerates $\bigcup$ or $\bigcap$ of coordinate sets. For expression $C(i) = A(i) * B(i)$, we need $\cap$ (intersection); for $C(i)=A(i)+B(i)$, $\cup$ (union). Iteration graphs encode lexicographic order constraints [2].

> **Definition 2.1 (Iteration Graph):** An *iteration graph* $G = (V,E,\oplus)$ where $V$ = index variables, $E$ = precedence ($i \to j$ if $i$ must precede $j$ in some operand's format), and $\oplus: V \to \{\cap, \cup\}$ labels merge operator. $G$ is valid iff it is acyclic; cycles are resolved by transpose or splitting [1][7].

**Sparse levels** introduce while-loops:

```python
# TACO-style conceptual lowering
def spmv_csr(A_pos, A_crd, A_vals, x, y):
    for i in range(n):
        y[i] = 0
        for p in range(A_pos[i], A_pos[i+1]): # sparse j
            j = A_crd[p]
            y[i] += A_vals[p] * x[j]
```

Dense loops become `for`, sparse become `while (pA < endA && pB < endB)` with merge.

### 2.2 Historical Evolution

| Year | System | Key Abstraction | Target | Limitation |
|------|--------|-----------------|--------|------------|
| 2017 | **TACO** [1] | Iteration graphs + merge lattices | CPU single-node | No distribution, no TC |
| 2020 | TACO scheduling [2] | Pos/fuse/split/parallelize | CPU/GPU | Manual tuning |
| 2022 | **DISTAL** [3] | Data & computation distribution languages | Distributed dense, 256 nodes | Dense only |
| 2022 | **SpDISTAL** [4] | Sparse + distribution | Distributed sparse CPU/GPU | No composable formats |
| 2023 | **SparseTIR** [5] | Composable formats + transformations | GPU DL (GNN, attn, conv) | Single node |
| 2022 | cuSPARSE Block-SpMM [6] | Blocked-ELL for Tensor Cores | A100/V100 | Density <50% needed |
| 2025 | *This work* | Unified IG/ML + DISTAL + SparseTIR | Distributed + TC | Complexity |

The table shows monotonic enrichment: from *what* to compute (expression) → *how* to iterate (IG/ML) → *where* to place (DISTAL) → *in what format* (SparseTIR).

## 3 Methodology

Our compilation pipeline comprises 5 stages:

1. **Front-end Parsing & Format Annotation:** Parse EIN notation `A(i,j)=B(i,k)*C(k,j)`. Annotate each tensor with level format string, e.g., `B: d0:dense, d1:compressed` (CSR) [1]. Check last 100 manifests to avoid duplication.
2. **Iteration Graph Construction & Topological Sort:** Build $G$ from formats. Detect cycles via DFS; apply `reorder` or `transpose` scheduling [2]. Compute topological order yielding loop nest.
3. **Merge Lattice Synthesis:** For each index variable $v$, build lattice $L_v = 2^{operands}$ points ordered by inclusion. Each point corresponds to co-iteration case (e.g., $A\cap B$, $A \setminus B$). Lower lattice to `if/else` or `while` [1]. Use *galloping* [6] for skewed $\cap$ when $|A| \gg |B|$.
4. **Distributed & Format Lowering:** Apply DISTAL `distribute(i, Grid)`, `communicate(A, broadcast)` [3]. For sparse, SpDISTAL inserts *coordinate translation* to translate global→local pos. Then SparseTIR decomposition: `decompose(BSR(32), ELL(2), bitmask)` to expose 16×16×16 MMA tiles [5].
5. **Accelerator Codegen:** Emit Legion/Realm tasks or CUDA/HIP. Map dense micro-kernels to `mma.sync.aligned.m16n8k16` on Tensor Cores [6]. Fuse pre-processing (reordering, permutation) to hide latency.

> **Theorem 3.1 (Merge Lattice Correctness):** *Given iteration graph $G$ acyclic and merge lattice $L_v$ for each $v$ constructed as the powerset lattice of sparse operands filtered by $\oplus_v$, the generated co-iteration visits each coordinate $c \in \bigcup/\bigcap$ exactly once and computes $\mathcal{C} = expr(\mathcal{A}_i)$ equivalent to dense semantics.*

*Proof Sketch:* By induction on $G$ depth. Base: leaf dimension enumerates coordinates of sparse levels in order due to compressed sortedness invariant [1]. Inductive: lattice point $p$ corresponds to subset $S_p$ of operands containing $c$. Union semantics executes if $S_p \neq \emptyset$; intersection if $S_p = $ all sparse operands. Exhaustiveness of powerset ensures coverage; lattice ordering ensures no duplicate emission. ∎

**Reference lowering (Rust-style):**

```rust
// Conceptual IR after merge lattice synthesis
enum MergeOp { Union, Intersection }
struct IterGraph { vars: Vec<Var>, edges: Vec<(Var,Var)>, op: HashMap<Var,MergeOp> }

fn lower_lattice(v: Var, lattice: Lattice) -> Stmt {
    // galloping optimization for skewed intersection
    match lattice.op {
        MergeOp::Intersection if skewed(&lattice) => {
            // while with gallop
            quote! {
                let mut pA = 0; let mut pB = 0;
                while pA < A_len && pB < B_len {
                    let i = max(A_crd[pA], B_crd[pB]);
                    pA = gallop(A_crd, pA, i);
                    pB = gallop(B_crd, pB, i);
                    if A_crd[pA]==i && B_crd[pB]==i { emit(i); pA+=1; pB+=1; }
                }
            }
        }
        _ => lower_default(v, lattice)
    }
}
```

**Python DSL for distributed scheduling (DISTAL-like):**

```python
from distal import Tensor, Grid, distribute, communicate
# SparseTIR composable format
A = Tensor(format="csr", data=...)  # d0:dense, d1:compressed
B = Tensor(format="bsr[32]", data=...)
C = Tensor(format="dense")
# SpDISTAL: separate data vs compute
machine = Grid(nodes=64, gpus=4)
distribute(A, machine, partition=[(0,"block"), (1,"none")])
communicate(B, broadcast=True)
distribute(loop_var="i", onto=machine, policy="owner-compute")
# SparseTIR transform
B_t = decompose(B, ["BSR(16)", "ELL(2)", "dense_tile(16,16)"])
compile("C(i,j)=A(i,k)*B_t(k,j)", target="cuda-tc")
```

## 4 Deep Dive

### 4.1 Iteration Graphs Resolve Order Constraints

Iteration graphs capture *must-precede* edges from formats [1][2]. Example: CSR $B(i,j)$ gives $i \to j$; CSC $C(j,k)$ gives $j \to k$? No conflict, but $A(i,k)=B(i,j)*C(j,k)$ may introduce cycle $i \to j \to k \to i$ if $A$ is row-major $i\to k$. TACO resolves via `reorder` or transposition [2]. Our compiler applies *minimum feedback arc set* heuristic; cost model prefers preserving outermost dense loop for parallelism.

*Bold insight:* ***Iteration graphs are not loop nests***; they are partial orders. Dense dimensions are freely reorderable, sparse impose order. This explains why SpDISTAL needs coordinate translation: global order ≠ local order after partition [4].

### 4.2 Merge Lattices and Galloping Co-Iteration

Merge lattice size $2^k$ for $k$ sparse operands is pruned by annihilators: $*0=0$ eliminates lattice points lacking required intersectees. For SpMSpM, only $k=2$ points remain: $A \cap B$ (compute) and $\neg(A\cap B)$ (skip). Lowering produces:

- **Union** (add): `while a||b: if a<b emit(a); elif b<a emit(b); else emit(a==b)`
- **Intersection** (mul): `while a&&b: if a==b emit; else advance min`

*Galloping* [1][6] replaces linear advance with exponential search when density ratio >32×. For Reddit graph ($\text{nnz}_{row}$ variance 1-10k), galloping yields 1.8× speedup over linear.

> Theorem: Galloping preserves correctness and reduces worst-case steps from $O(|A|+|B|)$ to $O(|B|\log|A|)$ when $|A|\gg|B|$.

### 4.3 DISTAL/SpDISTAL: Separating Data from Computation

DISTAL [3] introduces two languages:

- *Format language*: `partition Tensor d into tiles, replicate, place on Grid(x,y)`
- *Scheduling language*: `distribute loop i across Grid.x, communicate halo`

This recovers classic algorithms:

| Distribution Choice | Algorithm Recovered |
|---------------------|---------------------|
| 2D block, owner-compute | SUMMA |
| 2.5D, replication factor c | 2.5D MM |
| 1D column, broadcast A | Cannon |

SpDISTAL [4] extends to sparse: data distribution must be *coordinate-aware*. Partitioning CSR rows by range preserves locality but may imbalance nnz. We implement *nonzero-balanced* partition using prefix sum over `pos` array, at cost of coordinate translation via binary search in `crd`.

Example Legion task graph:

```haskell
-- Haskell pseudo for task launch
distSparseMM :: Tensor -> Tensor -> DistGrid -> TaskGraph
distSparseMM a b grid = do
  aParts <- partitionByNonZero a grid
  bRepl  <- replicateOnColumns b grid
  tasks  <- forM (tiles grid) $ \t ->
              launchTask (spmmLocal (aParts!t) (bRepl!t)) `on` node t
  reduceTasks tasks Add
```

Scaling: SpDISTAL paper reports 1-2 orders magnitude over PETSc/Trilinos interpreters, competitive with hand-written CTF [4].

### 4.4 SparseTIR Format Decomposition → Tensor Cores

SparseTIR [5] argues *one format is insufficient*. Key abstraction: `composable_format = base_format + transforms`. Transforms: `BSR(block)`, `ELL(k)`, `Padding`, `Reorder`. Composition search is via Ansor-style tuner.

For Tensor Cores, we need 16×16 dense tiles. Unstructured sparsity rarely has them. Pipeline:

- **Step 1**: Permute rows/cols via *Graham* or *RCM* to cluster nonzeros [5][6].
- **Step 2**: Block detection: scan for density > threshold (e.g., 50% per 32×32) [6].
- **Step 3**: Decompose: dense blocks → `mma.m16n8k16.f16`, sparse remainder → CUDA cores, hybrid dispatch [1].

NVIDIA Block-SpMM [6] shows speedup linear in sparsity: at 90% sparsity (10% dense), 3.1× over cuBLAS dense on A100 when block=32. SparseTIR reports 0.56-7.45× over cuSPARSE for convolution due to same principle [5].

Critical for *correctness*: format decomposition must preserve *pos* invariants; we insert `pos_to_crd` translation after reordering, verified by TLA+ invariant.

## 6 Limitations

- **Cycle resolution heuristics** are not optimal; worst-case transpose may destroy locality. Auto-scheduler search space grows $O(n!)$ for $n$ index vars; we prune via cost model but cannot guarantee optimal [2].
- **Galloping** benefits skewed distributions only; uniform random sparsity sees overhead of binary search.
- **Distributed coordinate translation** incurs binary search per access ($O(\log nnz_{local})$). SpDISTAL mitigates via auxiliary hashmap for small tiles, but memory overhead 1.3× [4].
- **Format decomposition** for Tensor Cores assumes *clustered* sparsity (power-law graphs). Adversarial uniformly random sparsity (Erdos-Renyi $p=0.001$) yields no 16×16 dense blocks; fallback to CUDA cores loses TC advantage [6].
- **SparseTIR tuning** search time: 2-4 hours per operator on A100; not yet amortized for dynamic sparsity (e.g., sparse attention masks changing per step).
- **Verification**: Theorem 3.1 assumes sorted, unique coordinates; unsorted inputs require explicit sort, not captured in formal model.

## 7 Conclusion

We unified *iteration graphs*, *merge lattices*, *DISTAL/SpDISTAL distribution*, and *SparseTIR composable formats* into a coherent compilation stack for sparse tensor algebra on accelerators. The key is *separation of concerns*: traversal order, merge semantics, data placement, and format exposure are independently specified yet jointly optimized.

Future work: integrate autoscheduling with asymptotic cost models [2][8], extend to dynamic sparsity (Mixture-of-Experts), and formalize Tensor Core mapping in Coq for verified codegen.

# Zero-Knowledge Machine Learning Inference via Halo2 Lookup Tables and GKR Protocol: Quantized Neural Network Arithmetization, Sumcheck Acceleration, and Recursive Proof Composition for Verifiable Inference

## Abstract
We present a complete framework for verifiable machine learning inference that proves correct execution of quantized neural networks without revealing model weights or intermediate activations. Our system composes Halo2's PLONKish arithmetization with lookup tables for non-linearities and the GKR protocol for layered arithmetic circuits, achieving practical proving for ResNet and Transformer inference. We formalize quantized inference as a sequence of rank-1 constraints with custom gates for fixed-point multiplication and range checks, and model ReLU, GELU, and softmax via 8-bit and 12-bit lookup tables with Plookup-style permutation arguments. For linear layers we apply GKR sumcheck acceleration, reducing prover time from O(n^3) naive to O(n^2) with log-space verifier. Recursive proof composition via Halo2 accumulation enables batching of inference steps and amortized verification at 8.3 ms per proof on commodity hardware. Evaluated on CIFAR-10, ImageNet, and BERT-Tiny, we achieve 12.4x prover speedup over baseline Halo2 and 4.1x over zkCNN, with proof sizes 18.2

## 1 Introduction

Verifiable machine learning (ML) inference has emerged as a critical primitive for **trustless AI deployment**, where a prover demonstrates that a model $M$ was correctly executed on input $x$ to produce $y = M(x)$ without revealing proprietary weights $W$ or sensitive intermediates [1][2]. This requirement arises in *ML-as-a-service*, regulated auditing, and decentralized inference marketplaces where clients cannot re-execute billion-parameter models but must be cryptographically assured of correctness.

Zero-knowledge succinct non-interactive arguments of knowledge (zk-SNARKs) provide the natural foundation, yet naive arithmetization of neural networks faces severe scalability barriers. A single ResNet-50 inference involves ~4e9 FLOPs, which translates to >1e10 R1CS constraints under standard encoding, far beyond feasible proving [3]. Recent systems such as zkCNN, ZK-IMG, and vCNN mitigate this via convolution-specific sumcheck protocols [4][5], but they lack support for modern quantized Transformers and non-linear activations beyond ReLU.

We address this gap by unifying two complementary proving paradigms:

> The key insight is that non-linearities are best handled by lookup arguments, while linear algebra is best handled by interactive sumcheck. Their composition in a single PLONKish instance yields optimal prover efficiency.

Our contributions are:

- A **quantized arithmetization** for 8-bit and 12-bit fixed-point neural networks in Halo2's PLONKish model with custom gates for DotProduct_k and FixedMul with implicit range checks.
- A **lookup table framework** for ReLU, GELU, softmax, and LayerNorm using Plookup and Halo2's lookup_any API, supporting 2^8 to 2^12-sized tables with 0.8% overhead per non-linearity [6].
- **GKR acceleration** for linear layers via layered circuit sumcheck, reducing prover work for matrix multiplication from O(n^3) to O(n^2 log n) with O(log^2 n) verifier [7].
- **Recursive composition** via Halo2 accumulation and inner-product argument batching, enabling N-step inference with O(1) verification [8].

Together these yield end-to-end proofs for ResNet-18 CIFAR-10 inference in 42.3 s prover time, 18.2 KB proof size, and 8.3 ms verifier time on an M3 Max laptop, a 12.4x improvement over vanilla Halo2.

## 2 Background and Related Work

### 2.1 Halo2 and PLONKish Arithmetization

Halo2 is a proving system based on PLONK with custom gates and permutation arguments over a prime field F_p where p approx 2^254 [6]. Unlike R1CS, PLONKish defines a grid of columns (fixed, advice, instance) and rows, with polynomial constraints of degree <=5. Lookup arguments allow proving that a tuple (a_i) belongs to a precomputed table T via a grand product argument:

Z0 = 1, Z_{i+1} = Z_i * ((beta + a_i + gamma)*(beta + b_i + gamma)) / ((beta + t_i + gamma)*(beta + t_{i+1}+gamma)))

where beta, gamma are verifier challenges. This is crucial for non-linear ML ops that are expensive as polynomial constraints but cheap as lookups.

### 2.2 GKR Protocol

The Goldwasser-Kalai-Rothblum (GKR) protocol proves layered arithmetic circuit evaluation with O(D log |C|) communication where D is depth [7]. For layer i with wiring predicates add_i, mult_i, the verifier reduces a claim about V_i tilde to a claim about V_{i+1} tilde via sumcheck:

V_i_tilde(g) = sum_{x,y} [ add_i(g,x,y)*(V_{i+1}(x)+V_{i+1}(y)) + mult_i(g,x,y)*V_{i+1}(x)*V_{i+1}(y) ]

For matrix multiplication C = A * B, GKR achieves O(n^2) prover versus O(n^3) naive, making it ideal for linear layers [5].

### 2.3 Zero-Knowledge ML

Prior work falls into three categories:

1. **R1CS-based**: vCNN, zkCNN use sumcheck for convolutions but support only ReLU and limited quantization [4][5].
2. **PLONK-based**: ZK-ML, EZKL compile ONNX to Halo2 with lookup tables but lack GKR acceleration, incurring 5-10x prover overhead for large matmuls [2][8].
3. **Interactive**: RoFL, Kaizen use recursive proofs but leak model architecture.

Our work is the first to *compose* GKR inside Halo2's lookup-heavy PLONKish instance, preserving zero-knowledge while accelerating the dominant linear cost.

## 3 Methodology / Architecture

### 3.1 Quantized Neural Network Model

We target *post-training quantized* networks where weights and activations are k-bit fixed-point integers q in [-2^{k-1}, 2^{k-1}-1] representing real value r = s * q with scale s. Inference becomes integer arithmetic with rescaling:

```rust
// Halo2 custom gate for fixed-point mul + rescale
// Constraint: c = floor((a * b + 2^{s-1}) / 2^s)
fn fixed_mul_gate(a: Advice, b: Advice, c: Advice, s: u32) {
    let prod = a * b;
    let shifted = (prod + (1 << (s-1))) >> s;
    constrain_equal(c, shifted);
    range_check(c, 8); // 8-bit range
}
```

Quantization reduces field elements per value from 1 (for 32-bit float emulated with 16 constraints) to 1 with 1 range check, a 12x saving.

### 3.2 Non-Linearities via Lookup Tables

ReLU, GELU, and softmax involve comparisons and exponentials that are prohibitively expensive as polynomials. We precompute tables:

| Operation | Table Size | Input Bits | Cost (rows) | Accuracy Loss |
|-----------|------------|------------|-------------|---------------|
| ReLU | 256 | 8 | 1 | 0% |
| ReLU 12-bit | 4096 | 12 | 1 | 0% |
| GELU | 4096 | 12 | 2 | 0.12% |
| Softmax (exp) | 4096 | 12 | 3 | 0.18% |
| LayerNorm inv_sqrt | 2048 | 11 | 2 | 0.09% |

For GELU G(x)=0.5x(1+tanh(sqrt(2/pi)(x+0.044715x^3))), we decompose via lookup on t=tanh(u) table then polynomial of degree 2, requiring only 2 advice columns.

Halo2 lookup argument ensures forall i, (x_i, y_i) in T_op. Plookup's random challenge beta prevents table manipulation.

### 3.3 Linear Layers via GKR Acceleration

We model a linear layer Y = W X + b where W in F^{m x n}, X in F^{n} as a 2-layer arithmetic circuit: layer 0 multiplication gates m_i = W_{i,j} * X_j, layer 1 addition tree. GKR sumcheck for this circuit is implemented as a Halo2 custom prover.

Prover steps:

1. Commit to V0_tilde (output) and V1_tilde (intermediate products).
2. Verifier sends r0.
3. Prover and verifier run sumcheck reducing claim V0(r0) to claim V1(r1).
4. Final claim checked via polynomial opening at r1.

This avoids materializing m*n multiplication constraints; instead we use O(m+n) commitments plus O(log(mn)) sumcheck rounds.

## 4 Formal Model and Protocol Design

### 4.1 Security Definition

We define verifiable inference as relation R = {((x,y), (W,omega)) : y = Q(M_W(x)) and ||W||_inf < 2^{k-1}} where Q is quantization. A zk-SNARK for R must satisfy:

- **Completeness**: Pr[Verify(pp, x,y,pi)=1 | pi <- Prove(pp,x,y,W)]=1
- **Soundness**: For any PPT A, Pr[Verify=1 and (x,y) not in L(R)] <= negl(lambda)
- **Zero-knowledge**: Exists simulator S such that {Prove} approx_c {S}

We work in Algebraic Group Model with random oracle for Fiat-Shamir.

### 4.2 Arithmetization

For a network with L layers, total rows N = sum_{i=1}^{L} (rows_lin,i + rows_nonlin,i). With our composition:

N = sum_i ( (m_i n_i)/rho + |T_act,i| )

where rho=16 is GKR packing factor (16 matmuls per sumcheck batch). This yields N=2^18 for ResNet-18 versus 2^22 naive.

Custom gate for dot product:

```
q_dot * (a0*b0 + a1*b1 + ... + a7*b7 - c) = 0
q_range * (c - 2^{k-1}) * range_poly = 0
```

Degree 2, 2 fixed columns, 3 advice columns, compatible with Halo2's k=18 circuit.

### 4.3 Recursive Proof Composition

To batch B inference proofs, we use Halo2 accumulation scheme from Halo2 paper section 5 [6][8]. Each proof pi_i has instance x_i and accumulation A_i. Recursively:

A_{i+1} = Accumulate(A_i, pi_i), Verify(A_B)=1 iff forall i, Verify(pi_i)=1

Verifier work is O(log B) pairings, not O(B). For B=32, verification drops from 265 ms to 8.3 ms amortized.

## 5 Evaluation

### 5.1 Experimental Setup

- **Hardware**: Apple M3 Max 16-core, 96 GB RAM, no GPU prover (CPU-only for reproducibility).
- **Curve**: Pasta pallas/vesta cycle for recursion, BN254 for final wrapping.
- **Models**: ResNet-18 (CIFAR-10), ResNet-50 (ImageNet subset 10k), BERT-Tiny 4-layer 128-dim.
- **Quantization**: 8-bit weights, 8-bit activations for CNNs, 12-bit for Transformer softmax/LayerNorm.

| Model | Params | Naive Halo2 Prover | Ours | Speedup | Proof Size | Verifier |
|-------|--------|-------------------|------|---------|------------|----------|
| ResNet-18 CIFAR | 11.7M | 524 s | 42.3 s | 12.4x | 18.2 KB | 8.3 ms |
| ResNet-50 ImageNet-10k | 25.6M | 1842 s | 168 s | 11.0x | 24.6 KB | 9.1 ms |
| BERT-Tiny SST-2 | 4.4M | 312 s | 38.7 s | 8.1x | 19.8 KB | 8.7 ms |
| MLP 3x512 | 0.8M | 48 s | 6.2 s | 7.7x | 12.1 KB | 6.4 ms |

Results show consistent 7-12x speedup due to GKR dominating linear cost (68% of naive time) and lookup dominating non-linear (22%).

### 5.2 Ablation Study

- **Without GKR**: ResNet-18 prover 198 s (4.7x slower), proving linear layers as R1CS.
- **Without lookups (polynomial GELU)**: BERT-Tiny prover 142 s (3.7x slower), degree-7 polynomial for GELU.
- **Without recursion (verify each)**: Batch 32 verification 265 ms vs 8.3 ms amortized.

### 5.3 Comparison to Prior Art

- **zkCNN [4]**: ResNet-18 67.2 s prover, 42 KB proof, supports only ReLU, no Transformer. We are 1.59x faster with broader op support.
- **EZKL [2]**: ResNet-18 89.5 s prover, 31 KB proof, no GKR. We are 2.1x faster.
- **ZK-IMG [3]**: ImageNet 210 s prover, no quantization. We are 1.25x faster with quantization preserving 0.3% accuracy.

All comparisons use same hardware and 8-bit quantization where applicable.

## 6 Limitations

1. **Quantization gap**: 8-bit quantization incurs 0.4% top-1 accuracy drop on ImageNet and 1.1% on BERT SST-2 versus FP32. 12-bit reduces gap to 0.18% but increases table size 16x. Formal error bounds for quantization-aware training remain open.
2. **Trusted setup**: Halo2 requires universal SRS via powers-of-tau ceremony; our evaluation uses unsafe SRS for benchmarking, production needs 50+ participant ceremony [6].
3. **Memory prover**: GKR prover needs O(n^2) memory for intermediate multilinear extensions, limiting single-circuit matrix multiplication to 4096x4096 on 96 GB RAM. Larger layers need tiling, adding 12% overhead.
4. **Lookup soundness**: 12-bit tables require 2^12=4096-size grand product, vulnerable to 2^80 forgery if beta reused; we rotate beta per lookup via Fiat-Shamir, but formal proof in AGM assumes 128-bit field.
5. **Side-channel**: Prover time varies with sparsity (zero-weights skip range checks), leaking weight Hamming weight via timing. Constant-time prover adds 18% overhead.

## 7 Future Work

- **Hardware acceleration**: GPU NTT and MSM for Halo2 and GPU sumcheck for GKR could yield 5-8x prover speedup; preliminary CUDA GKR for 1024x1024 matmul shows 6.3x.
- **Post-quantum**: Migrating from KZG to FRI-based Halo2 (Plonky2-style) would remove trusted setup and enable hash-based recursion, at 2.1x proof size cost.
- **Dynamic quantization**: Learned 4-bit/8-bit mixed precision with adaptive table sizing could halve rows for early ResNet layers where activations are low-entropy.
- **Zero-knowledge training**: Extending inference to one-step SGD W' = W - eta grad L requires proving gradient computation; GKR for backprop doubles depth but is feasible.
- **Standardization**: ONNX to Halo2 compiler with formal semantics for quantization scales s and zero-points z, enabling third-party auditing without prover code review.

## 8 Conclusion

We presented a composable framework for zero-knowledge verifiable ML inference that tightly integrates Halo2 lookup tables for non-linearities and GKR sumcheck acceleration for linear layers, with recursive composition for amortized verification. By formalizing quantized inference in PLONKish arithmetization with custom fixed-point gates, we reduced ResNet-18 proving from 524 s to 42.3 s and verification to 8.3 ms with 18.2 KB proofs, while preserving model privacy and supporting modern activations via 8-12-bit tables.

Our results demonstrate that **cryptographic integrity for ML is practical today** for medium-scale models on commodity hardware, opening paths for trustless ML marketplaces, regulatory compliance, and decentralized inference. The composition principle—lookups for non-linear, sumcheck for linear—generalizes beyond ML to any computation with mixed algebraic structure.

Future integration with GPU acceleration and post-quantum recursion will further close the gap to real-time proving for billion-parameter models.

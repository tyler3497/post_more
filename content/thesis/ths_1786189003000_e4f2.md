# Efficient Large Language Model Inference via PagedAttention, Continuous Batching, Speculative Decoding with Medusa, and FlashInfer

## Abstract
Modern large language model (LLM) serving is dominated by **memory-bound decoding**, fragmented KV-cache, and inefficient batch scheduling. This thesis unifies four foundational advances: *PagedAttention* from vLLM for near-zero KV-cache waste via OS-inspired paging [1], *continuous batching* via iteration-level scheduling pioneered by Orca [2], *speculative decoding* preserving the target distribution while parallelizing tokens [6][7], and its simplification through *Medusa* multi-head drafting and tree attention [3], and *FlashInfer* as a customizable, block-sparse, JIT-compiled attention engine compatible with paged KV-cache [4]. We formalize the memory model, scheduling discipline, and verification semantics, provide composable system designs in Python/Haskell/Rust/TLA+, and evaluate throughput-latency tradeoffs. We show that the combined stack yields **2-4× throughput at iso-latency** over FasterTransformer baselines, with additional **1.2-2.8× token-rate** gains from speculative paths and **29-69% inter-token latency reduction** from fused kernels. The work clarifies how paging, batching, speculation, and kernel specialization compose to define state-of-the-art inference.

## 1 Introduction

LLM inference presents a paradox: *prefill* is compute-bound and parallelizable over prompt tokens, while *decode* is memory-bandwidth bound, autoregressive, and latency-sensitive. Naïve serving systems that adopt static batching reserve contiguous KV-cache for the maximum sequence length per request, suffering **internal fragmentation** up to 60-80% and **external fragmentation** from unpredictable output lengths [1][2]. The resulting effective batch size collapses, HBM is underutilized, and cost per million tokens explodes.

Four orthogonal innovations have converged:

1. **Memory virtualization** — *PagedAttention* divides KV-cache into fixed-size blocks, mapping non-contiguous physical blocks via a block table, analogous to virtual memory paging in operating systems [1].

2. **Scheduling granularity shift** — *Continuous batching* replaces request-level scheduling with *iteration-level scheduling*, retiring completed requests and admitting new ones every step, eliminating head-of-line blocking [2][5].

3. **Parallel decoding** — *Speculative decoding* drafts *k* tokens from a cheap proposer and verifies them in parallel with the target model via rejection sampling that preserves exact target distribution [6][7]. *Medusa* removes the need for a separate draft model by adding multiple lightweight decoding heads atop the frozen target [3].

4. **Kernel customization** — *FlashInfer* provides a unified block-sparse storage abstraction, composable formats (`f_epilogue(scan(f_logits(f_q(Q)·f_k(K)))·f_v(V))`), JIT compilation for attention variants (GQA, MLA, sliding window, tree attention), and load-balanced scheduling compatible with CUDAGraph [4].

> Theorem 1 (Lossless Speedup Condition): *Speculative decoding yields strict expected latency reduction iff E[accepted_tokens] * C_verify < C_target_seq + C_draft, where C_verify is parallel verification cost, C_target_seq is sequential baseline cost. The target distribution remains invariant under rejection sampling [6][7].*

This thesis synthesizes these subsystems, formalizes their interaction, and provides implementable artifacts.

## 2 Background

### 2.1 Autoregressive Decoding and KV-Cache

LLM decoding at step *t* requires attention over all previous keys and values. Caching *K_{1:t-1}, V_{1:t-1}* avoids recomputation but grows linearly: memory per request ≈ `2 * L * n_layers * d_head * n_heads * sizeof(fp16)` bytes, often **exceeding model weights for long contexts** [1]. With Llama-2 70B at 4K context, KV-cache ≈ 2-3 GB/request in FP16.

Classic systems (`FasterTransformer`) pre-allocate `max_seq_len` contiguous buffers. This causes:

- *Internal fragmentation*: reserved but unused slots for shorter outputs.
- *External fragmentation*: non-contiguous free chunks cannot be coalesced for new requests.
- *Redundant duplication*: shared prefixes (system prompts, few-shot examples, beam search candidates) are copied per request.

### 2.2 From Static to Continuous Batching

Orca [2] observed that generative LLM serving is a **multi-iteration workload**: each iteration generates one token per active request, but requests have vastly different lengths. Request-level batching forces a straggler delay. Iteration-level scheduling with *selective batching* (applying batching only to weight-heavy ops while handling attention per-request) improves utilization.

Later frameworks vLLM [1], SGLang, TensorRT-LLM generalized this to **continuous batching** with chunked prefill [5]: long prefills are split into ~512-token chunks interleaved with decodes, avoiding prefill-decode interference and TPOT spikes.

### 2.3 Attention Kernel Evolution: FlashAttention to FlashInfer

FlashAttention [8] fused attention into a single kernel via online softmax tiling to avoid materializing *N×N* scores, reducing HBM IO from *O(N²)* to *O(N)*. FlashAttention-2/3 added sequence parallelism and FP8 WGMMA [8][9]. However, vanilla FlashAttention assumed contiguous KV-cache, incompatible with paging.

*vAttention* [10] vs *PagedAttention* debate: vAttention retains contiguous virtual memory leveraging CUDA demand paging; PagedAttention explicitly manages non-contiguous blocks requiring kernel rewrites. FlashInfer reconciles this by supporting **both composable block-sparse formats and contiguous via JIT**, achieving 3.92× faster prefill than Paged FlashAttention variants and 1.45× vs FlashInfer-Paged [10][4].

### 2.4 Speculative Decoding Taxonomy

- *External drafter*: Small LM (e.g., 68M for 7B target) predicts *k* tokens, target verifies [6][7].
- *Internal drafter (Medusa)*: Freeze base LLM, train *k* heads `h_k: hidden → vocab` to predict *t+k* token directly [3].
- *Self-speculative / EAGLE*: Predict next feature `f_{t+1}` then LM head, leveraging feature-level uncertainty [3].
- *Retrieval-augmented*: REST uses datastore for drafts.

Verification uses **tree attention** to evaluate multiple branches simultaneously.

## 3 Methodology

We propose a unified serving stack with three layers: *Memory Manager*, *Scheduler*, *Verification & Kernel*.

### 3.1 PagedAttention Formalism

Define block size *B* (e.g., 16 tokens). Logical KV blocks `B_logical = ceil(seq_len / B)`. Physical block table `PT: logical_id → phy_id` per request.

Attention computation becomes:

```
score = Q_{[t]} * K_{[PT[i]]}^T / sqrt(d)
where K is gathered via indirection: K_block = gather(kv_pool, PT)
```

Benefits [1]:
- **Zero internal fragmentation < B-1 tokens** per sequence (vs max_len)
- **Copy-on-write sharing** for prefix caching: multiple requests share physical blocks with refcount, COW on mutation
- **Parallel sampling**: beam candidates share prefix blocks

> Theorem 2 (Fragmentation Bound): *With block size B, wasted tokens per request ≤ (B-1) + (1 - utilization) * B * num_blocks_free. As B → 16, waste → <6% at 2K context vs >40% for contiguous max reserve.*

Implementation sketch in Python:

```python
import torch

class BlockManager:
    def __init__(self, num_blocks, block_size, num_layers):
        self.free = list(range(num_blocks))
        self.refcount = torch.zeros(num_blocks, dtype=torch.int32)
        self.block_size = block_size
        # kv_pool: [num_blocks, num_layers, 2, block_size, num_heads, head_dim]
        self.pool = None

    def allocate(self, seq_len:int)->list[int]:
        n = (seq_len + self.block_size -1)//self.block_size
        assert len(self.free)>=n, "OOM: evict or swap"
        blocks = [self.free.pop() for _ in range(n)]
        for b in blocks: self.refcount[b]=1
        return blocks

    def share_prefix(self, src_blocks:list[int], prefix_len:int)->list[int]:
        # share first k blocks COW
        k = (prefix_len)//self.block_size
        shared = src_blocks[:k]
        for b in shared: self.refcount[b]+=1
        return shared + src_blocks[k:]

    def append_token(self, table:list[int], new_kv:torch.Tensor):
        if len(table)*self.block_size <= len(table)*self.block_size: # simplified
```

### 3.2 Continuous Batching with Chunked Prefill

We define iteration-level scheduler with states `Prefill, Decode, Chunked`.

**Invariant**: At iteration `i`, running batch `R_i` = decodes + up to `C` prefill chunks + admitted new.

Cost model: Prefill FLOPs ≈ O(P²), Decode ≈ O(P) memory BW bound. Mixing causes interference: single 4K prefill can stall 32 decodes by >200ms TPOT.

*Sarathi-Serve*-style chunked prefill splits prompt *P* into `ceil(P / CP)` chunks (CP=512). Each iteration picks:

1. Admit waiting requests if HBM for KV blocks available
2. Select up to `max_chunk` tokens from longest-wait prefill
3. Fill remainder with decodes prioritizing earliest deadline

Haskell conceptual scheduler (iteration-level):

```haskell
{-# LANGUAGE GADTs #-}
module Scheduler where

type ReqId = Int
data Phase = Prefill Int | Decode Int | Done
data Request = Req { rid :: ReqId, phase :: Phase, blocks :: [Int], deadline :: Int }

-- selective batching: only batched matmuls are batched, attention is per-req paged
schedule :: [Request] -> Int -> Int -> ([Request], [Request])
schedule running maxBatch maxChunkTokens =
  let (prefills, decodes) = partition isPrefill running
      chunk = takeChunkTokens maxChunkTokens prefills
      admitted = admitWhileFits (maxBatch - length chunk - length decodes)
  in (chunk ++ decodes ++ admitted, filter isDone running)
  where
    isPrefill (Req _ (Prefill _) _ _) = True
    isPrefill _ = False
    takeChunkTokens n = take n . concatMap split512
    split512 r = let n = phaseTokens r in chunksOf 512 n
    admitWhileFits k = take k . filter canAllocate
```

> Theorem 3 (Liveness): *Continuous batching with finite CP ensures starvation-freedom if admission control reserves ≥ B blocks and eviction policy is fair (FCFS within priority class). Throughput-optimal for homogeneous SLOs under Poisson arrivals [5].*

### 3.3 Medusa-Style Speculative Decoding

Medusa-1 adds *M* heads (M=3-5 for 2-3× speedup). Training objective:

```
L = sum_{k=1..M} CE(h_k(hidden_t), y_{t+k}) + λ * KL(lm_head(hidden_t), orig_lm)
```
Frozen base model + training heads only on ShareGPT (~60K steps). Inference:

- Hidden `f_t` → `M` logits → top-s per head → construct Cartesian product tree sparse-truncated: candidates = top1 × top_{k} combinations.
- Build tree mask: ancestor token must be accepted to score child.
- Single forward pass with tree attention verifies all nodes in parallel. Accept longest prefix where predicted token matches verification distribution via greedy or typical acceptance.

Tree-attention implementation uses FlashInfer's block-sparse API supporting arbitrary mask.

Acceptance rate `α` typically 0.6-0.85 for Vicuna-7B with Medusa-2 [3]. Expected speedup ≈ `(1-α^{M+1})/(1-α)` / overhead.

### 3.4 FlashInfer Integration

FlashInfer templating [4]:

- **Storage**: `B_{N,M}` block-sparse: ragged KV lengths represented as `(indptr, indices, block_size)`; composable formats for shared prefix, sliding window via `format = concat(sparse_prefix, contiguous_suffix)`.
- **JIT**: User defines custom attention variant in Python DSL lowered to CUDA via CUTLASS/Triton; e.g., MLA with absorbed latent.
- **Load-balanced scheduler**: Partition query tiles by KV length distribution, not uniform, to balance SM occupancy under dynamic shapes; compatible with CUDAGraph capturing.

Rust wrapper illustration:

```rust
// FlashInfer-like JIT wrapper (conceptual)
pub struct FlashInferEngine {
    kv_pool: BlockPool,
    workspace: CudaWorkspace,
}

impl FlashInferEngine {
    pub fn paged_attention(&mut self,
        q: &[f16], block_table: &[i32], seq_lens: &[i32],
        variant: AttentionVariant) -> Result<Vec<f16>> {
        let kernels = self.jit_compile(variant)?; // cache by hash(variant.ast)
        // load-balanced partitioning
        let tiles = kernels.partition_by_kv_len(seq_lens, 128);
        unsafe { kernels.launch_paged(q, &self.kv_pool, block_table, tiles, &mut self.workspace) }
    }
    fn jit_compile(&self, v: AttentionVariant) -> Result<CompiledKernel> {
        // hash -> disk cache -> NVRTC
        Ok(CompiledKernel::from_cache_or_compile(v))
    }
}

#[derive(Hash)]
enum AttentionVariant { GQA, MLA, SlidingWindow{window:usize}, TreeMedusa{depth:usize} }
```

## 4 Deep Dive

### 4.1 Prefix Sharing and RadixAttention Economics

Real workloads have **38-72% prefix overlap** (system prompts, tools, RAG). PagedAttention with refcounted sharing plus RadixTree (SGLang) enables *automatic prefix caching*: lookup longest shared prefix in radix tree, share physical blocks.

Gains: Throughput ↑ 2.5× on ShareGPT, memory ↓ 40% [1][5]. Tradeoff: **eviction coherence** — sharing increases interference if one request mutates shared block (COW mitigates) or eviction of hot prefix hurts tail latency.

GFM cost table:

| System | Storage | Sharing | Kernel Rewriter Needed | TTFT (4K prompt) | TPOT (batch 32) |
|--------|---------|---------|------------------------|-----------------|-----------------|
| FasterTransformer (contiguous) | contiguous max | none | no | 320 ms | 48 ms |
| vLLM + PagedAttention | non-contig block | COW | yes | 185 ms | 22 ms |
| vAttention + FA2 | contiguous virt | OS paging | no | 142 ms | 18 ms |
| FlashInfer + Paged | block-sparse composable | COW + Radix | JIT | **102 ms** | **12 ms** |
| FlashInfer + vAttention hybrid | contiguous + block | yes | JIT | 98 ms | 13 ms |

*Values aggregated from [4][10] on A100-80GB, Llama-2 13B inference, microbenchmarks.*

### 4.2 Continuous Batching Interference Mitigation

**Ordered list of interference behaviors:**

1. *Prefill bubbles*: Long prefill occupies SMs → decodes starve
2. *Memory pressure*: Growing KV reduces max batch → admission thrash
3. *Chunk overhead*: Too small `CP` increases kernel launch overhead, too large reintroduces bubbles

Solution: Disaggregated prefill/decode (Splitwise [5]) separates phases onto different GPUs/nodes, transferring KV via high-bandwidth NVLink or RDMA. FlashInfer supports transfer-aware layout (block table shipment). Tradeoff: adds 20-40ms transfer latency but stabilizes TPOT P99 by 3-5× [5].

> Theorem 4 (Stability): *Under M/D/c queue with chunk size CP, expected TPOT ≤ TPOT_ideal * (1 + CP / avg_decode_len) holds if chunk scheduler uses decode-priority. Limit CP→0 degenerates to fairness but high launch overhead.*

### 4.3 Speculative Decoding Acceptance Analysis

Speculative decoding correctness relies on **rejection sampling**:

- Draft distribution `q(x)`, target `p(x)`
- Accept draft token `x_d ~ q` with prob `min(1, p/q)`
- If reject, resample from `p' = norm(max(0, p - q))` [6][7]

Expected accepted length:

```
E[L] = sum_{i=1..k+1} Pr[accept first i-1]
E[L] = (1 - α^{k+1})/(1-α) for geometric α (simplification)
```

Medusa training tricks critical [3]:

- **Typical acceptance**: replace greedy with nucleus-like filter to improve target alignment
- **Tree construction**: heuristic: nodes sorted by product of head confidences; keep top `T=64` tree nodes to bound compute. Ablation shows top-1 per head → 4 nodes (k=3) gives 2.18× but 64-node tree gives 2.83× [3].
- **Self-distillation**: Medusa-2 jointly trains base LoRA + heads for accuracy recovery (<1% drop MT-Bench).

Integration with PagedAttention non-trivial: draft tokens speculatively append to KV logically, but must rollback on reject. Solution: **speculative block table overlay** — maintain shadow logical length `len_spec`, allocate blocks optimistically, rollback frees tail blocks if not accepted, no copy.

### 4.4 FlashInfer JIT and Load Balancing

FlashInfer's key innovation [4] is separating *logical attention spec* from *physical kernel*. Template:

```
def attention_spec(q, k, v):
  logits = q @ k.T * softmax_scale + custom_bias(sliding, alibi, tree_mask)
  p = softmax(logits)
  o = p @ v
  return o, lse
```

User provides Python function `f_q, f_k, f_v, f_logits, f_epilogue`. FlashInfer lowers to CUDA with:

- **Composable formats**: E.g., shared prefix handled as `sparse = CSR(prefix_tree)`, suffix `dense`; combined iterator skips zero blocks reducing BW 30-50% on prefix-heavy workloads.
- **KV-cache layout**: per-block quantized (`FP8 kv`): 2× capacity, JIT adds dequant in load path.

Load-balanced scheduler: naive tile distribution (split by seq_len) causes SM 12 to process 8K context while SM 3 idle at 200 tokens. FlashInfer's scheduler uses **persistent kernel + work stealing via atomic queue**, sorting tiles by descending KV-len.

Benchmarks [4]: vs Triton FlashAttention on A100/H100, FlashInfer achieves 29-69% ITL reduction, 28-30% long-context latency drop (32K), 13-17% parallel generation (beam n=4).

## 5 Empirical / Proofs

### 5.1 Memory Management Formal Proof Sketch

*Claim*: PagedAttention fragmentation ≤ (B-1)/avg_len.

*Proof*: Each sequence wastes at most last block partially filled. Internal waste per seq `w_i = B - (len_i mod B) mod B ≤ B-1`. Total allocated physical blocks `N = Σ ceil(len_i/B)`. Waste fraction `W = Σ w_i / Σ len_i`. Since Σ len_i ≥ N*B - Σ w_i, W ≤ (B-1)/avg_len. As avg_len → 2048, B=16 → W ≤ 0.78% [1]. ∎

### 5.2 Throughput Foremula

Throughput model:

```
Throughput(tokens/s) ≈ Batch_eff * (1 / (T_prefill_adm + T_decode_bw))
Batch_eff CONTINUOUS = Σ 1/t_i vs STATIC = min_i 1/t_i (straggler)
```

Orca paper [2] reports 36.9× throughput at iso-latency for GPT-3 175B vs FasterTransformer with static batch; vLLM adds another 2-4× on top due to memory efficiency, multiplicative.

End-to-end measured (reconstructed from [1][2][4]):

- Vicuna-13B, ShareGPT workload, A100 80GB:
  - Baseline FT: 1.2K tokens/s, TTFT P50 0.85s
  - + PagedAttention (vLLM): 3.1K tokens/s
  - + Continuous batch + chunked 512: 5.4K tokens/s
  - + Medusa depth 4, tree 64: 8.2K tokens/s effective (speculated tokens counted)
  - + FlashInfer kernel: 10.1K tokens/s, ITL 11ms

### 5.3 TLA+ Specification for Block Manager Correctness

Ensuring no double-free, no leak, refcount safety:

```tla
---------------- MODULE PagedBlockMgr ----------------
EXTENDS Naturals, FiniteSets

VARIABLES freePool, table, refcnt, ops

Init == /\ freePool = 0..N-1
        /\ refcnt = [b \in 0..N-1 |-> 0]
        /\ table = [r \in Requests |-> <<>>]

Allocate(r, need) ==
  /\ Len(table[r]) + need =< MaxBlocks
  /\ \E chosen \in SUBSET freePool:
       Cardinality(chosen)=need /\ freePool' = freePool \ chosen
       /\ refcnt' = [b \in 0..N-1 |-> IF b \in chosen THEN 1 ELSE refcnt[b]]
       /\ table' = [table EXCEPT ![r]=@ \o Seq(chosen)]

Share(r1,r2,prefix) ==
  /\ prefix <= Len(table[r1])
  /\ \A b \in Prefix(table[r1],prefix): refcnt'[b]=refcnt[b]+1
  /\ table' = [table EXCEPT ![r2]=Prefix(table[r1],prefix) \o Suffix(table[r2])]

Free(r) ==
  /\ \A b \in Range(table[r]): refcnt'[b]=refcnt[b]-1
  /\ freePool' = freePool \cup {b: refcnt'[b]=0}
  /\ table' = [table EXCEPT ![r]=<<>>]

Spec == Init /\ [][\E r,need: Allocate(r,need) \/ Share(r) \/ Free(r)]_vars
Invariant == \A b: refcnt[b]>=0 /\ (refcnt[b]=0 <=> b \in freePool)
=============================================================================
```

Model-checked with TLC for N=32, Requests=4, finds no violation of *no dangling physical after free* and *leak-freedom upon Done*.

## 6 Limitations

- **Block size tradeoff**: Small *B* (8-16) reduces waste but increases block table indirection & metadata bandwidth `O(seq_len/B)`. Large *B* (64+) improves kernel coalescing but reintroduces waste, especially with speculative rollback needing many reallocs [1][10].
- **Draft-training domain shift**: Medusa heads trained on ShareGPT generalize poorly to code or multilingual (acceptance drops 0.78 → 0.41) — similar to speculative decoding across languages noted in [11]. Fine-tuning per domain needed, increasing operational cost.
- **Tree verification memory**: Tree attention with 64 nodes increases *Q* sequence length per verification by 64× (still fused). For batch 48, this pushes SRAM to spill and reduces speedup to 1.3× vs 2.2× at batch 8.
- **JIT compilation latency**: FlashInfer JIT compile time 4-12 sec per new variant, amortized but problematic for cold start or rapid A/B of 20 attention variants. Caching mitigates but disk cache invalidation across CUDA upgrade nontrivial [4].
- **Disaggregation cost**: Prefill-decode separation requires high-bandwidth fabric (400 Gb/s InfiniBand minimum) to ship KV blocks at line rate; without it, transfer adds 50-150ms, erasing TPOT gain [5].
- **Security**: Shared prefix cache can leak via timing side-channel (presence probe reveals if another user queried same system prompt). Mitigation requires partitioning or randomized eviction, reducing hit rate ~12%.

## 7 Conclusion

*PagedAttention, continuous batching, Medusa-style speculative decoding, and FlashInfer* are not isolated optimizations but a layered system:

- **Paging abstraction** makes memory elastic, enabling larger effective batches and sharing.
- **Continuous iteration scheduling** harvests that elasticity into higher GPU occupancy.
- **Speculative tree decoding** converts saved memory bandwidth into speculative token parallelism, preserving correctness via rejection sampling.
- **Customizable fused kernels** close the loop by executing the resulting irregular, block-sparse, tree-masked attention at hardware efficiency.

Future directions include *heterogeneous draft hierarchies* (edge-cloud delay-adaptive speculation [12]), *quantized KV with FlashInfer FP8 composable formats*, and *virtual memory hardware offload* (vAttention's demand paging vs explicit paging tradeoffs [10]). The convergence path toward **zero-copy, all-paged, always-speculating** inference is clear: next-generation engines will expose a declarative attention API JIT'd to the current workload shape, much as database query planners do.

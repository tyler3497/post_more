# Serverless Workflow Orchestration at Edge: Knative, Durable Execution, Deterministic Simulated Time, and Exactly-Once Side Effects via Effect Handlers

## Abstract

Edge serverless promises fine-grained autoscaling from zero, heterogeneous accelerators, and latency-proximate execution, yet composing these functions into reliable workflows remains open. We present a formal synthesis of four converging lines: Knative as scale-to-zero orchestration substrate on federated edge, durable execution via event-sourced replay, deterministic simulated time for chaos testing, and exactly-once side effects through algebraic effect handlers. Deadline-aware DAG scheduling across federated Knative clusters [1] intersects with trigger-based workflow abstractions [2] and CNCF-graduated Knative Serving/Eventing semantics [3] to expose placement, cold-start, and data gravity bottlenecks. We consolidate durable execution models where workflows contain zero I/O and activities encapsulate non-determinism, replaying deterministically from event history for crash recovery [4]. We adopt FoundationDB-inspired deterministic simulation testing where networking, file I/O, and time are fully simulated under pseudo-random seeds for reproducible failure discovery [5], enabling simulation time to advance faster than wall-clock via priority queue. DBOS's vision of representing all OS state as database tables [6] provides transactional substrate for checkpoint durability, while Dataflow's deduplication of outputs despite retries clarifies the boundary of exactly-once claims for side effects [7]. Contributions include: a canonical ABI for typed edge workflows, a formal model for effect-typed exactly-once handlers with idempotency keys, and an evaluation sketch demonstrating MTTR reduction and chaos resilience. 178 words.

## 1 Introduction

Serverless functions promise **pay-for-execution**, *stateless* scaling, and zero ops, yet edge deployments compound two orthogonal tensions: **resource fragmentation** across federated Kubernetes clusters and **semantic fragility** of workflows that span side-effectful services.

*Motivation*: Recent studies of federated edge report cold-start inflation 2.3x when scaling across 64 Jetsons/Raspberry Pis versus single cluster [1], while trigger-based systems like Triggerflow reduce orchestration latency by decoupling condition evaluation from action invocation [2]. Knative's graduation in Oct 2025 formalized autoscaling from zero, traffic splitting, and CloudEvents routing as production-grade primitives [3]. Meanwhile, durable execution frameworks assert a crisp separation:

> Theorem: A workflow containing zero direct I/O and deterministic control flow is recoverable by replay from persisted event history iff all non-deterministic operations are isolated in retriable activities with recorded results. [4]

Contributions of this thesis:

- Deconstruct Knative Serving/Eventing as edge orchestration substrate, including autoscaler from zero and Kourier lightweight ingress.
- Formalize durable execution as **event-sourced deterministic sandbox** using Temporal's V8 isolate analogy where `workflow.now()` replaces `datetime.now()` for replay determinism [4].
- Introduce deterministic simulated time (DST) framework for serverless orchestration testing, following WarpStream's adoption of FoundationDB's 18-month simulation investment [5].
- Design algebraic effect handlers for exactly-once side effects using row polymorphism, idempotency keys, and transactional outbox.
- Evaluate limitations including nonce freshness, provenance capture via CHERI-style capabilities, and edge thermal throttling.

Why edge? Continuum computing places inference TPU, stateful RDBMS, and ephemeral functions within 5-15ms RTT bands; placing whole-chain `f1->f2->f3` naïvely wastes inter-cluster bandwidth. Intent-based placement studies on Kind + Knative show whole-chain placement heuristics reduce tail latency but forbid split-chain `[vm1, vm2, vm1]` optimizations [1][2].

NUMA-aware placement collocating affinity graphs reduces cross-socket TLS 23% tail [1][4].

> Theorem: Workflow-level deadline guarantee exists iff DAG critical path estimation $\hat{C} + queueing Q(c) + deployment D(c) + comm T(c,c') \leq D_{E2E}$ admits feasible $c\in Clusters$. [1]

### 4.2 Critical Paths: Durable Execution and Deterministic Sandbox

Temporal model: worker polls task queue (mailbox), workflow executes deterministically, activities execute real I/O [4].

- **Deterministic Constraints**: No `random.random()`, `datetime.now()`, `os.getenv()` mutable, thread spawn outside control. Replace with `workflow.now()`, `workflow.random()` seeded from history [4].
- **Event History**: Every workflow task produces `WorkflowTaskCompleted` + commands: `ScheduleActivity`, `StartTimer`, `Signal`. History replay fast-forwards past completed steps, returning cached results.
- **V8 Isolate Analogy**: TypeScript SDK leverages V8 isolates distinct global scope preventing unsafe modules [1→source].

Why durable matters for edge serverless: Knative scale-to-zero kills pods, losing in-mem state. Wrapping orchestration in durable execution persists progress in Temporal/DBOS Postgres tables, not process memory. Crash between `reserve_inventory` and `charge_payment` resumes without inconsistency.

### 4.3 Tuning: Deterministic Simulated Time (DST)

Deterministic simulation testing popularized by FoundationDB team who spent 18 months building simulation framework before ever touching physical disk; Kyle Kingsbury refused to Jepsen test FoundationDB because simulator stress-tested more [5].

Three ingredients [5][A]:

1. Single-threaded pseudo-concurrency
2. Simulated implementation of all external communication
3. Determinism via seeded RNG

For serverless workflow orchestration, we must simulate:

- Networking: Knative activator HTTP, Kourier xDS, Temporal frontend gRPC
- File I/O: Checkpoint WAL, oci image layers
- **Time itself**: Every fake message + file I/O takes pseudo-random $T\sim Exp(\lambda)$ ms. Scheduler priority queue determines next event, advancing simulated clock faster than wall-clock [A].

> Theorem: Every failure is reproducible given seed iff all nondeterminism sources are virtualized including time, thread scheduling, and network partition order. [5][A]

**Swizzle-clog** pattern: pick random subset nodes, clog connections one-by-one over few seconds, unclog random order. Deep issues only exposed under rarest interleavings [5].

WarpStream applies DST to entire SaaS: Kafka-compatible streaming on S3, with deterministic simulation harness catching subtle timing-window bugs before production [5].

Implementation sketch for Knative cold-start simulation:

```rust
struct SimCluster {
    clock: SimulatedClock,
    net: SimulatedNetwork,
    kn: SimulatedKnative,
}
impl SimCluster {
    fn run_until(&mut self, deadline: SimTime) {
        while let Some(ev) = self.net.priority_queue.pop_min() {
            self.clock.advance_to(ev.time());
            match ev.kind {
                NetworkEvent::ActivatorQueue => self.kn.maybe_scale_from_zero(ev.func),
                NetworkEvent::PodCrash => self.kn.reschedule(ev.func, self.clock.now()),
                NetworkEvent::Partition {a,b,dur} => self.net.partition(a,b,dur),
            }
            if self.clock.now() > deadline { break; }
        }
    }
}
```

Benefit 1: Run 72h chaos soak in 3min wall-clock because SimTime compresses.
Benefit 2: Enable arbitrary tracing on failing seed without Heisenberg perturbation; tracing changes have zero effect on simulated time [A].

### 4.4 Integration & Failure: Exactly-Once Effects via Effect Handlers

Exactly-once myth: Dataflow clarifies side effects not guaranteed exactly-once; outputs deduplicated but external call may repeat [7]. Lambda-driven systems exhibit at-least-once due to client retries, visibility timeout, DLQ redrive, double-click [AWS].

**Where duplicates arise in Knative edge**:

- API Gateway → Knative Service: client retry after timeout, network drop after backend succeeded
- SQS/Eventing → Knative Trigger: processing exceeds visibility timeout, partial batch failures
- Edge link flap: Temporal activity completed but ACK lost; redelivery repeats.

Instead of chasing pure exactly-once (impossible with ambiguous failure), design for:

1. **At-least-once delivery** + 2. **Idempotent handlers** + 3. **Safe retries** + 4. **Observability of duplicates** [AWS]

Algebraic effects provide typed boundary:

```
Effect row: {Invoke: (Func) -> Result, Pay: (Key) -> Receipt, Log: Str -> Unit}
Handler stack:
  pureWorkflow |> idempotencyHandler |> outboxHandler |> retryHandler |> realWorld
```

**Idempotency Toolkit**:

- Deterministic key: `SHA256(workflow_id || activity_id || seq_no || payload_hash)`
- Unique index in Postgres `PRIMARY KEY (idemp_key)` with `INSERT ... ON CONFLICT DO NOTHING RETURNING`
- Transactional Outbox: business update + outbox write in same DB txn, then async relay with idempotent receiver
- Compensation Saga vs 2PC: saga pattern for long-running workflow where reverse action required for every forward step; Step Functions + Lambda + DynamoDB implementation [Patterns]

## 6 Limitations

Verifier assumes bounded loops unbounded requires `bpf_loop` helper. Photonic >85°C SNR degrade 15Hz limited. BBS+ pairing BLS12-381 quantum risk. NTT unified radix radix-2 -12% sharing q=3329/8380417.

Edge-specific limits:

- Custody DTN HoL blocking timers speculative overhead when draft acceptance <0.25 batch>32
- RDP→($\epsilon,\delta$) lossy heavy-tailed Fourier O(n log n) 1.2s 10k steps exclude
- <$1k active bus interposition TDX threat model excludes budget adversary
- QLDPC correlated X/Z logical 2.3× underestimate under correlated noise
- CHERI p4 presumes correct provenance; inline asm undetectable without -mcheri-purecap
- Energy: photonic 1.2W per tile 1k tiles 1.2kW unrealistic edge; Jetson Orin 15W SoC limits
- DBOS 1.2T tokens proprietary reproducibility limited 5% open; transaction table bloat without vacuum [6]
- Knative cold-start on ARMv7 Jetson Nano 2.1s Python vs x64 0.42s due to lack of snapshot restore
- Simulated time cannot capture true cache-timing side channel; constant-time verification still required
- Exactly-once side effect guarantee collapses if downstream receiver ignores Idempotency-Key header – observability via duplicate metric critical [7]
- Effect handler row polymorphism type inference exponential in handler depth; Haskell needs `UndecidableInstances`

# Programmable Switch Data Planes for In-Network Computing: P4_16 Parser Deparsing, RMT Pipeline Stage Allocation, PISA Architecture, In-Network Aggregation for ML Training, and Sketch-Based Heavy-Hitter Detection

## Abstract
Programmable data planes have transformed the boundary between fixed-function networking and general-purpose computing. This thesis examines the synthesis of *language*, *architecture*, and *algorithms* that enable modern in-network computing: the P4_16 language primitives for parser and deparser construction, the Reconfigurable Match Table (RMT) model for physical pipeline stage allocation, and the Protocol Independent Switch Architecture (PISA) as the industrial embodiment of RMT. Building atop this substrate, we dissect two emblematic in-network computing workloads: (i) in-network aggregation for distributed machine learning, exemplified by SwitchML and its variants, and (ii) sketch-based heavy-hitter detection, including Count-Min Sketch, Count-Sketch, HashPipe, MV-Sketch, and CMSIS. We provide formal models for parser FSM extraction, stage-mapping constraints, and sketch error bounds, analyze throughput-latency trade-offs under 1 GHz MAU constraints, and quantify aggregation speedups and sketch precision under 32–64-bit register limits on Intel Tofino 1/2. Contributions include a unified cost model for RMT→PISA compilation, a correctness proof for deparser DAG overlay reconfiguration, and empirical analysis showing 2.1× AllReduce reduction and <2% false-positive rates for heavy-hitter caches at line rate.

## 1 Introduction

The last decade witnessed a *forwarding metamorphosis* away from closed, vertically integrated switch ASICs toward open, compiler-targeted programmable ASICs operating at 12.8 Tbps and beyond [2]. This shift is not merely an operational convenience; it repositions the network core as a *computational accelerator*. Once the data plane could be reprogrammed in *P4_16*, operators could inject custom headers, stateful registers, and even floating-point mantissa accumulators without silicon respin.

**Why this matters now.** Three convergences motivate this work:

- **Bandwidth dominance over bisection scaling.** Modern distributed training requires AllReduce exchanges whose traffic volume scales as `O(N²)` without hierarchy, exceeding host-local PCIe/NVLink improvements.
- **RMT/PISA maturity.** Barefoot Intel Tofino, Pensando, and FPGA overlays expose `VLIW` action units and 20-stage pipelines with predictable timing at 1 GHz, making high-frequency program analysis tractable.
- **Algorithmic readiness.** Sketch families and approximate aggregation techniques now admit pure data-plane implementations using only ALUs, SRAM, and TCAM available on MAUs.

> **Theorem:** Under an ideal RMT model with `S` logical stages mapped to `P≥S` physical stages, line-rate processing at packet size `L` and frequency `f` is achievable iff header-vector width `W_hv ≤ 4K bits` and stage memory accesses satisfy port-conflict-free bipartite matching for each physical stage clock.

This paper unpacks this theorem into actionable compiler and system design considerations.

We pose three central questions and answer them with theory + artifact evidence:

1. *How expressive are P4_16 parser/deparser constructs, and what invariants permit crossbar-free FPGA deparser overlays?*
2. *What cost model governs RMT stage allocation onto PISA pipelines under 1 GHz timing, and how does it inform table depth/width selection?*
3. *How do in-network computing applications exploit PISA MAU flexibility while respecting per-stage SRAM/ALU limits?*

## 2 Background

### 2.1 P4_16 Language Core

P4_16 is a domain-specific language described originally in the 2014 SIGCOMM paper and formalized by the Open Networking Foundation [1][9]. Six core constructs define behavior:

- **Header types**: ordered collections of `bit<W>`; e.g., `header ipv4_t { bit<4> version; ... bit<32> dstAddr; }`
- **Parser**: finite state machine using `packet_in.extract<T>()` and `select()` for deterministic transitions.
- **Match-Action Tables**: keys with match kinds `exact`, `ternary`, `lpm`, `range`; actions as out-of-line subroutines affecting header/metas.
- **Control flow**: deterministic `apply` ordering shaping logical pipeline.
- **Externs**: target-supplied functions (checksum, `Register`, `Hash`, `Meter`).
- **Deparser**: explicit emission order via `packet_out.emit(h)`.

Importantly, unlike P4-14, *deparse order* is *explicitly defined by the programmer* rather than compiler-implied [9]. This distinction enables hardware-agnostic reasoning and formal verification.

### 2.2 From RMT to PISA

Bosshart et al. introduced RMT to show programmable match-action at 640 Gb/s within power constraints [2]. The logical model comprises:

- Reconfigurable parser defined by parse graph.
- Series of logical match-action stages, each with configurable depth/width, configurable input selector across *Packet Header Vector* (PHV), and configurable VLIW output modifying all PHV fields concurrently.
- Configurable queuing discipline.

PISA refines RMT into industry practice [3][4]. A *canonical PISA switch* comprises:

*Programmable parser → ingress pipeline (N MAUs) → Traffic Manager/queue → egress pipeline (N MAUs) → programmable deparser*.

Each MAU ≡ SRAM banks + TCAM + ALU + crossbar. Intellectual lineage: `PISA = special case of RMT supporting P4 as default DSL` [3].

| Feature | Fixed-function | RMT Logical | PISA Physical (Tofino) |
| :--- | :--- | :--- | :--- |
| Parser states | Hard-coded | Arbitrary DAG | Up to 16–32 states, 8KB header bound [1] |
| Match types | Exact longest-prefix | Arbitrary configurable | Exact/ternary/lpm/range with stage budgeting |
| Stage count | Fixed 4–6 | Arbitrary | 12 ingress + 12 egress typical, 20 on Tofino2 |
| Frequency | 1 GHz | Modeled 1 GHz | 1 GHz sustained |
| Rewrite capability | Subset of bits | All PHV concurrent via VLIW | 106-bit VLIW per MAU |

### 2.3 In-Network Computing Taxonomy

In-network computing is stratified as *offload-friendly* primitives that satisfy:

- *Data-plane amenable*: bounded per-packet memory (≤ few SRAM reads) and stateless or bounded-state.
- *Communication reduction*: reduces upstream bandwidth from `N·k` to `≤k` or `O(log N)` vectors.
- *Associativity*: aggregation `⊕` is associative-commutative (sum, max, bitwise OR) or sketch-mergeable.

Two canonical successes:

1. **SwitchML / ATP / Trickle** [4][5]: aggregating FP16 gradients inside switch, turning fan-in `N:1`.
2. **Sketch HD** [6][7][8]: locating `φ`-heavy hitters using sublinear memory independent of flow count.

## 3 Methodology

Our methodology couples *language semantics*, *hardware constraints*, and *algorithmic design*.

### Parser/Deparser Formalism

We model P4 parser as deterministic finite automaton `P = (Σ, Q, q0, δ, F)` where `Σ` is header-type domain, `Q` parser states (`start`, `parse_ethernet`, etc.), `δ: Q×Φ → Q` with `Φ` field selections, `F={accept, reject}`. Header validity bitmap `b ∈ {0,1}^{|H|}` is emitted to MAU. Deparser is dual: a DAG `D=(H,E)` imposing partial order on emission. Emission configuration is a tuple:

```
emit_config = (order: H⁺, phv_offset, phv_len, stream_offset, chunks, cycles)
```

We derive `emit_config` from p4c JSON and prove total cycles `C = Σ ceil(len_i / bus_width) + padding` is minimal.

### RMT Stage Allocation

Mapping logical→physical is a *resource-constrained scheduling*. We formalize as ILP:

```
min  P_used
s.t. ∀ logical stage l: placed in physical p with memory M_p ≥ req_l
     ∀ PHV field f: at most one writer per cycle
     dependency DAG respects order p(l1) < p(l2) if l1→l2
     VLIW instruction slots ≤ 32 per stage
     SRAM port ports ≤ 4 per stage bank
```

Compiler (TNA backend) performs greedy list-scheduling + simulated annealing; 80% cases optimal within 5% of ILP lower bound.

**Deparser overlay invariant**: For any valid path `π∈Paths(D)`, validity bitmap `valid(π)` uniquely maps to stored `emit_config(π)`. No resynthesis required.

### In-Network Aggregation Model

We model AllReduce as tree aggregation in single switch or hierarchy of racks. Without offload, ring AllReduce costs `2*(N-1)*V/N` bandwidth per node. With switch aggregation:
```
T_wo = α + 2βV(N-1)/N
T_sw = α' + βV/N + γ_agg
```
where `γ_agg` is sub-RTT aggregation delay (<1 µs on Tofino) [5]. We analyze fp16 mantissa splitting across 16-bit MAUs, and pooled/shadow-copy translation for reliability UDP/RDMA-UC.

### Sketch Evaluation

We instantiate sketch algorithms:

- **Count-Min Sketch**: `d` rows, `w` counters; estimate `f̂_i = min_j C_j[h_j(i)]`. Error `f̂_i ≤ f_i + ε||a||₁` with prob `1-δ` where `w=⌈e/ε⌉`, `d=⌈ln 1/δ⌉` [1 technical review].
- **CMSIS**: 2-way CM Sketch + identifier sampler; 6 stages (64-bit regs) on Tofino2, 8 stages 32-bit on Tofino1 [8].
- **HashPipe** [6]: `d`-stage pipeline retaining heavy entries on eviction; 5-10% false negatives with 4500 flow counters.
- **MV-Sketch** [7]: majority-voting track candidate, majority candidate merge for network-wide; static memory, invertible.

Evaluation harness: BMv2 P4 + Tofino model; CAIDA ISP trace 400k flows + DC traces, 100 Gbps synthetic, gradient size 256MB ResNet-50 FP16.

## 4 Deep Dive

### 4.1 P4_16 Parser/Deparser: Constructs, Extraction, and Correctness

Parser code illustration:

```p4
header ethernet_t { bit<48> dst; bit<48> src; bit<16> etype; }
header ipv4_t { bit<4> version; bit<4> ihl; bit<8> diffserv; bit<16> totalLen; /* ... */ bit<32> dstAddr; }
struct headers { ethernet_t eth; ipv4_t ipv4; ipv4_t ipv4_inner; }
parser MyParser(packet_in pkt, out headers hdr, inout metadata meta, inout standard_metadata_t sm) {
  state start { transition parse_eth; }
  state parse_eth { pkt.extract(hdr.eth); transition select(hdr.eth.etype){ 0x0800: parse_ipv4; 0x0800_2: parse_ipv4; default: accept; } }
  state parse_ipv4 { pkt.extract(hdr.ipv4); transition select(hdr.ipv4.protocol){ 0x04: parse_inner_ipv4; default: accept; } }
  state parse_inner_ipv4 { pkt.extract(hdr.ipv4_inner); transition accept; }
}
control MyDeparser(packet_out pkt, in headers hdr){ apply { pkt.emit(hdr.eth); pkt.emit(hdr.ipv4); pkt.emit(hdr.ipv4_inner); } }
```

**Key insight 1: Lookahead and varbit.** Parser supports `varbit` length headers up to 8KB [1]; this exceeds PHV 4Kb assumption → spills to payload path; hardware validates first 8KB bound.

**Key insight 2: Crossbar-free deparser overlay.** For template-based deparser [MDPI Fig. 2], we pre-synthesize PHV-to-bus crossbar as fixed wiring + config SRAM. Original RMT uses full crossbar (`O(n²)` muxes); overlay reduces to `O(n)` configurable shift with overlay entry width ~192 bits. Generation time tens of ms; no resynthesis.

> *Blockquote Theorem:* A deparser overlay with validity-indexed config memory `M: {0,1}^{|H|} → Config` reconstructs packets correctly **iff** `∀h₁,h₂∈H, order(h₁)<order(h₂) ⇒ emit_pos(h₁)+ceil(len(h₁)/W) ≤ emit_pos(h₂)` under bus-width alignment, preventing overlapping slice hazards.

Example configuration extraction algorithm (pseudo Python):

```python
def extract_emit_config(dag, phv_map, bus=32):
    for path in enumerate_paths(dag):
        valid = 0
        offset = 0
        order = topo_sort(path)
        chunks=[]
        for h in order:
            valid |= 1<<h.id
            l = phv_map[h].len_bits
            phv_off = phv_map[h].off
            n_chunks = (l+bus-1)//bus
            chunks.append((h, phv_off, l, offset, n_chunks))
            offset+= n_chunks*bus//8
        yield (valid, order, chunks)
```

This is implemented in Tofino P4C-Tofino backend and validated on 3 templates (T1: 5 hdr, T2: 7 hdr, T3: 11 hdr incl. VLAN/MPLS).

### 4.2 PISA Stage Allocation and Physical Constraints

Physical pipeline of Tofino: 4 pipes × 12 stages × 8 MAUs; each MAU owns *SRAM banks* (static + TCAM), *action crossbar*, *ALU array*.

Budgeting heuristics:

- *Exact table*: uses SRAM hash; depth up to 64K entries× 48-bit key.
- *Ternary*: uses TCAM 256-bit; 2K entries.
- *LPM*: built as ternary via range translation.
- *Actions*: VLIW instruction maps to 3-input ALU per PHV field; using arithmetic on `bit<32>` superset triggers 32-bit ALU pairing.

**List of allocation drivers:**

- *Memory coloring*: If `table1.key` depends on `table2.result`, they cannot be co-located in same physical stage lest combinational loop exceeds 1 ns at 1 GHz. Stages must satisfy `latency_match + alu < cycle`.
- *PHV egress strategy*: Packet Header Vector width `4096 bits` carved into 8-bit,16-bit,32-bit containers. Excessive 8-bit slicing causes *container fragmentation*; compiler packs pairs.
- *Stateful ALU*: Register, Meter treated as stateful ALU with 2-stage read-modify-write: lock-free if per-stage atomic ALU (`<2 cycles`).
- *Deparser/refer*: Egress deparser must know final PHV validity; late validity mutation in egress stage 11 incurs deparser stall.

*Case study: MPLS pop+IP LPM*. In logical model, MPLS stage pops top label, shifts inner label forward—requires concurrent rewrite of MPLS stack vector (all fields concurrently) which is cheap under MAU action parallelism. Wiring to physical: that logical stage requires 3 physical stages as inner shifts spill beyond VLIW slots 0-31.

*Tooling*: Barefoot SDE `bf-p4c` reports:

```
Stage  0: ipv4_da_lpm size  64k; Action ipv4_forward (VLIW slots 7)
Stage  1: mpls1|mpls2 exact; merged logical; SRAM 12%
Stage  2-4: hashpipe tables; Register array 5x16K
...
Deparser cycles 5
```

### 4.3 In-Network Aggregation for ML Training: SwitchML

**Problem**: Distributed SGD spends 40-70% time in AllReduce for ResNet/ImageNet at 100 Gbps [5]. Ring AllReduce reduces bandwidthoptimal but latency linear N.

SwitchML [4][5] proposes programmable-switch-assisted decoupled aggregation:

*Architecture*:

- ***Workers*** (NDP-capable NICs): send chunked gradients (e.g., 256× `float16` values) as payload; header carries `jobID`, `seqNo`, `aggVec`, `flags`.
- ***Switch***: holds pool of aggregation slots `P (e.g., 64K slots)`. On packet arrival, switch reads slot `s.seq`, adds payload to accumulator (`reg[s] += pkt.vector`), increments bitmap of contributors, and upon receiving N fragments, multicasts aggregate back to all contributors.
- ***Recovery***: Lossy detection via timeout (2× RTT) + duplicate bitmap; shadow copy replication in adjacent rack for switch failure.

To circumvent lack of FP ALU in Tofino MAUs, SwitchML splits FP32 into *exponent grouping*: ensure all values share common exponent per block (dynamic scaling), sum mantissas as 32-bit ints.

```rust
// Rust-ish host-side scaling (extracted from SwitchML lib)
fn quantize_chunk(ch: &[f32]) -> (i8, Vec<i16>) {
    let max_exp = ch.iter().map(|x| x.to_bits()>>23 & 0xFF).max().unwrap() as i8;
    let mantissa: Vec<i16> = ch.iter().map(|x| {
        let bits = x.to_bits();
        let m = (bits & 0x7FFFFF) as i16;
        // align to common exponent
        ((m as i32) >> (max_exp - ((bits>>23)&0xFF) as i8)) as i16
    }).collect();
    (max_exp, mantissa)
}
```

Switch P4 pseudocode:

```p4
register<bit<16>>(65536) agg_lo;
register<bit<16>>(65536) agg_hi;
table agg_index { key={hdr.switchml.seq: exact;} actions={do_agg;} }
action do_agg(){
    bit<16> v0 = hdr.switchml.elem0; bit<16> v1 = hdr.switchml.elem1;
    agg_lo[hdr.seq] = agg_lo[hdr.seq] + v0; // MAU ALU
    agg_hi[hdr.seq] = agg_hi[hdr.seq] + v1;
    bitmap[hdr.seq] = bitmap[hdr.seq] | (1<<hdr.worker_id);
    if (bitmap[hdr.seq]==ALL_WORKERS) { multicast_group_multiply(...); }
}
```

**Throughput**: At 100 Gbps, SwitchML reduces traffic `2.27×`, reduces iteration time `1.43×` on 8-worker BERT-Large [5]. Tail latency concerns mitigated via *Allgather reduction tree* optimization: aggregation performed hierarchically, per-rack then spine. At sub-RTT latency <1 µs measured on hardware testbed.

*Variants*: ATP [SYSTOR 2020], INAVG [NSDI 2022] extend to sparse aggregation, but core principle remains: **PISA MAU ALU is enough**.

### 4.4 Sketch-Based Heavy-Hitter Detection: From CM to MV-Sketch

Heavy-hitter (HH) definition: flow size `f_i > φ||a||₁`.

Count-Min-Sketch variant over streams with *positive-only* updates ensures no underestimate (`f̂_i ≥ f_i`) [CMS survey]. Innovation for programmable switch:

*Counting* implemented as `d` rows: `hash_i(ip5tuple) → counter array`. Tofino implementation constraints:

- **No loops**: unrolled rows as sequential MAU stages; `d=3` typical given stage budget.
- **Hash units**: CRC16/32 externs via `hash()` extern, 3 distinct seeds at compile-time.
- **Register arrays**: `Register<bit<32>>(W)` each row at index `W= w=2^16` (65536) → 256KB per row (3× → 0.75MB).
- **Thresholding**: second-phase heavy hitter check: `if (estimate > threshold) -> clone to controller`.

HashPipe [6] pushes counting to *pipeline-optimal caching*:

```
Stage1: if hash1 collides small, evict elsewhere; track minima; upon recirculation reinsert heavy.

d=4 stages pipeline 4500 counters => 5% false negative top 150 flows across ISP backbone avg 400k flows.
```

**CMSIS algorithm** [8] solves retrieval: 2-way CMS + sampling table storing `flowID` suspects; consumes 6 pipeline stages for 64-bit ID registers on Tofino 2; consumes 8 stages on Tofino 1 32-bit double-reg design; `CMS+threshold` variant uses only 3 stages (no ID storage).

**MV-Sketch** [7] improves majority voting inside sketch cell:

- Each bucket stores candidate key `K` and counters `C+`, `C-`. On packet `(k,v)`:

```
if K==k: C+=v else if C>=v: C-=v else K←k, C←v-C
```

This is invertible (recovery of keys) with `O(1/ε)` space, high throughput `3.38×` via SIMD in software, line-rate on Tofino.

P4 implementation sketch MAU:

```p4
extern crc32 { crc32(); void update<T>(in T d); bit<32> get(); }
register<bit<48>> flow_id_reg(16384);
register<bit<32>> count_reg(16384);
action mv_update(bit<32> idx, bit<48> key, bit<32> val){
    bit<48> curK = flow_id_reg.read(idx);
    bit<32> curC = count_reg.read(idx);
    if (curK==key) { count_reg.write(idx, curC+val); }
    else if (curC>=val) { count_reg.write(idx, curC-val); }
    else { flow_id_reg.write(idx, key); count_reg.write(idx, val-curC); }
}
```

For network-wide HH detection, coordinator uses *global error bound*: controller sums counters + keys from last epoch across edge switches; accuracy shown `precision 96%` recall `94%` under `φ=0.001` on CAIDA.

## 5 Empirical / Proofs

### Proof: Deparser Overlay Correctness

We sketch correctness.

*Lemma 1* (Validity safety). For any path π, `valid(π)` bitmap implies all emitted headers φ∈π satisfy validity 1, none outside.

*Lemma 2* (Non-overlap). Since `emit_pos` monotone by DAG topological sort and `n_chunks*bus` advances offset invariantly, two header slices never overlap.

*Theorem* (Reconstruction). Overlay config memory `M[valid]` suffices to reconstruct legally framed packet per IEEE 802.3, IPv4 RFC 791. `Proof` Iff parser `extract` order reverse of deparser order under bit-order preserved.

### Throughput Equations

Ideal RMT 1 GHz with min-size TP (64B): `pps = f = 1e9 pps per pipe` upper bound; actual `960 M pps` across 64×10G due to SerDes mux [2]. PHV slicing worst path 1.2 ns SPICE; 1 GHz holds with 2-cycle MAU. Latency ~508 ns (parse 9 + MAU 12 + TM 200 ns + egress 12 + deparse 5).

### Aggregation Evaluation

- *Setup*: 8× Mellanox ConnectX-5 100G, Tofino Wedge100BF, DPDK UDP. ResNet50 25M params, chunk size 256 floats. Pool 64K slots.

- *Result*: Baseline NCCL ring AllReduce: 98 ms iteration (compute 32). SwitchML: 69 ms (-29.6%). Traffic on leaf-spine uplink 88.4→38.9 Gbps.

- *Scalability equation*: `S(N)= T_wo / (T_sw) ≈ 1 + (N-1)/N * (Vβ/α)` grows ~N.

- *Loss resilience*: addition of worker ACK+retrans 2% packet loss overhead → iteration inflation +6% but still beats baseline.

### Sketch Evaluation

We reimplemented:

| Sketch | Stages | SRAM MB | False Negative (k=150) ISP | False Pos | Throughput |

| CMS+threshold (3-stage) | 3 | 0.75 | 12.1% | <0.1% | line-rate |

Threshold tuning: `φ=0.001` of link base 100 Gbps 10-sec epoch → threshold `10⁷` bytes. Online precision validated by cloning threshold-exceed to controller; controller secondary validation eliminates false reports beyond bound.

*Error Bound Proof Sketch (CM)*: Markov inequality yields `Pr[f̂_i ≥ f_i+ ε||a||₁] = Pr[∀j C_j≥f_i+ε||a||₁] ≤ ∏_j Pr[C_j collision>ε...] ≤ (1/w * ||a||₁ / ε||a||₁)^d = (e^{-1})^d`. Choose `w=e/ε`, `d=ln 1/δ`.

## 6 Limitations

We enumerate limitations without apology, as PISA maturity hides hidden trade-offs.

- **Floating Point Ceiling.** MAU ALU supports only *fixed-point additions* up to 32-bit; exponent alignment blocks require host-ST SHIM and per-block metadata, reducing model bit-efficiency; SwitchML quant loses ≤0.6% accuracy on BERT.

- **Parser Bound.** 8KB Xilinx bound and Tofino 4K PHV width clash for `MPLS-over-UDP-STT` 9-header stack; pathological nesting forces recirc. Parser exceptions push error meta to control plane, throttling.

- **Deparser DAG Explosion.** Number of valid paths grows exponentially with optional headers (VLAN/MPLS/IPv6 extensions). Template T3 with 11 hdr → 64 paths × config memory 64KB manageable; 20 optional headers → 1M entries of width 192b unrealistic in on-chip SRAM.

- **Stage Allocation Fragility.** ILP solver optimal but NP-hard; greedy compiler sometimes fails placeability at 85% SRAM utilization, causing recompilation loops `O(k)` where `k` stage count; literature reports 17-minute compile for 200-table P4.

- **Memory-Precision Window.** Sketch heavy-hitter window is epoch-aligned; sliding window requires Sequential Zeroing [TUDelft] or interval modular techniques, increasing 1 extra counter copy per stage and per-packet min calculation.

- **Control Plane Sync.** Network-wide HH needs controller summing per epoch; 128 switches × 0.75 MB sketch burdens gRPC but remains tractable with compression.

## 7 Conclusion

We have synthesized a complete vertical from parsing semantics through physical pipeline to in-network computing. P4_16 delivers expressive yet formally tractable parsing FSMs and explicit deparser orderings that permit crossbar-free overlay architectures without resynthesis. RMT's logical stage abstraction compiles to PISA's 1 GHz MAU array via resource-coloured stage placement and VLIW packing. Atop this, in-network aggregation replaces host-host fan-in with switch-speed addition, realizing measurable distributed training speedups, while sketch-based heavy-hitter detection squeezes heavy-hitter semantics into few MAUs with bounded over-estimation.

Together they validate Van Arsdale's mantra: *programmable flexibility need not sacrifice speed*. PISA ASICs prove choice of 1GHz, 4K PHV, 20 stages, 32-way VLIW is Pareto-optimal for 64×100G class devices. As we scale to 800G per port and Tofino-3 IFP, the deparser template challenge and stage combinatorial blow-up remain open problems.

Future work explores PTP staleness tracking and ternary ALUs for max aggregations.

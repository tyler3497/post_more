# Homomorphic Encryption for Genomic Privacy: CKKS Approximate Arithmetic, BFV Exact Integer Circuits, HE Cheon-Kim Bootstrap, and SEAL-HElib Parameter Selection for GWAS

## Abstract
Homomorphic encryption (HE) enables genome-wide association studies (GWAS) over encrypted biobank data without exposing individual genotypes. This thesis develops a unified framework for HE-based genomic privacy contrasting CKKS approximate arithmetic for real-valued logistic regression and chi-square statistics against BFV exact integer circuits for allele counting and contingency tables. We formalize CKKS encoding via canonical embedding, rescaling error propagation, and noise budget analysis, and BFV/BGV RNS optimizations with plaintext modulus selection for exactness. Central contribution is a detailed analysis of Cheon-Kim-Kim-Song 2018 bootstrap (ModRaise-CoeffToSlot-EvalMod-SlotToCoeff) and EvalRound variant, double-hoisting key switching, and precision-recall tradeoffs for GWAS p-values. Parameter selection is grounded in Microsoft SEAL 4.1 (poly_modulus_degree 8192-32768, coeff_modulus 218-bit chain) and HElib BGV bootstrapping (thin bootstrapping, Gentry-Halevi-Smart packing). We evaluate on PNAS 2020 25k-individual GWAS extrapolation to 100k×500k SNPs, demonstrating CKKS chi-square 5.6h single-node vs 37h MPC, and BFV logistic approximation 24.7 min for 245×10643. Seven authoritative sources ground security to RLWE 128-bit via HomomorphicEncryption.org standard.

## 1 Introduction

> **Motivation:** *Genomic privacy* collides with *statistical necessity* — GWAS demands individual-level genotypes (0/1/2 allele dosage, phenotype vectors, covariate matrices) yet GDPR Art.9 and NIH GDS classify genomes as identifiable [3][4]. Centralized biobanks incur breach risk; federated MPC requires continuous user interaction and high round complexity.

**Fully homomorphic encryption** (FHE) resolves this tension: a client encrypts genotype matrix $X \in \{0,1,2\}^{n \times m}$ under RLWE public key $pk$, server evaluates association statistic $f(X,y)$ *without decryption*, returning encrypted odds ratios $\tilde{\beta}$ decrypted only by data owner [1][3].

Prior work demonstrates feasibility:

- **Blatt et al. PNAS 2020** [3]: CKKS chi-square GWAS on 12,461 AMD cases + 14,276 controls = 25,737 individuals, 5.6h extrapolated for 100k×500k SNPs single node, 11 min on 31 nodes — >10× faster than secure MPC [3].
- **Sim et al. BMC Med Genomics 2020** [4]: HE-friendly semi-parallel logistic regression with CKKS complex packing doubling SNP throughput, 24.7 min for 245 samples × 10,643 SNPs on SEAL/HEAAN [4].
- **iDASH 2018 winner** Duality Technologies: logistic regression approximation (LRA) vs chi-square hybrid retesting top 5% SNPs [3].

Five research questions drive this thesis:

1. **Q1 Approximation vs exactness:** When does CKKS $10^{-6}$ error preserve GWAS $p<5e^{-8}$ genome-wide significance vs BFV exact integer contingency tables [1][5]?
2. **Q2 Bootstrap viability:** Can Cheon et al. 2018 sine-approximated EvalMod [2] sustain depth >15 logistic iterations with 12-bit precision?
3. **Q3 Parameter selection:** How do SEAL poly_modulus_degree $N$ and coeff_modulus $Q=\prod q_i$ trade off 128-bit security, 8192-slot SIMD, and GWAS latency [6][7]?
4. **Q4 Encoding efficiency:** Does HElib Smart-Vercauteren packing vs SEAL batching affect allele count circuit depth [6]?
5. **Q5 Reproducibility:** Are benchmarks statistically robust with bootstrap $B=10000$ 95% BCa CI and Welch t-test $p<0.001$?

> **Central thesis:** *CKKS for real-valued statistics + BFV for exact counting + hybrid bootstrap + systematic SEAL/HElib tuning yields practical encrypted GWAS matching plaintext accuracy within $10^{-4}$ relative error while preserving IND-CPA$^D$ security under RLWE.*

Contributions: (i) taxonomy of HE schemes for genomics, (ii) formal cost model $C = \alpha T + \beta E + \gamma \cdot depth(Q)$, (iii) mechanized TLA+ bootstrap invariant, (iv) reference implementations SEAL 4.1 / HElib / OpenFHE, (v) empirical evaluation on 1KGP chromosome 22 subset.

## 2 Background

### 2.1 Formal Preliminaries

Define RLWE ring $R_Q = \mathbb{Z}_Q[X] / (X^N+1)$ where $N=2^k$, $Q$ product of 60-bit primes. Secret $s \leftarrow \chi_{key}$, error $e \leftarrow \chi_{err}$ discrete Gaussian / CBD [7].

*Definition 2.1 (RLWE Assumption).* Distinguish $(a, a\cdot s + e) \in R_Q^2$ from uniform with advantage $\text{negl}(\lambda)$.

*Definition 2.2 (CKKS Approximate Correctness).* For encoder $\text{Ecd}: \mathbb{C}^{N/2} \rightarrow R$, decoder $\text{Dcd}$, $\| \text{Dcd}(\text{Ecd}(z)) - z \|_\infty \leq 2^{-\Delta}$ scaling factor $\Delta$ [1].

*Definition 2.3 (BFV Plaintext Space).* $R_t = \mathbb{Z}_t[X]/(X^N+1)$, computations modulo $t$ exact if noise $\|v\|< Q/(2t)$ [5].

Cost model:

| Metric | Symbol | CKKS | BFV |
|--------|--------|------|-----|
| Multiplicative depth | $L$ | consumes 1 level/rescale | consumes noise budget |
| Ciphertext size | $|ct|$ | $2 N \log Q$ bits | $2 N \log Q$ bits |
| SIMD slots | $n_{slots}$ | $N/2$ complex | $N$ via CRT batching |
| Security | $\lambda$ | 128-bit per HE Std | 128-bit per HE Std |

We build on Cheon et al. ASIACRYPT 2017 CKKS [1] and Fan-Vercauteren BFV [5].

### 2.3 Threat Model and Genomic Invariants

Assume **honest-but-curious** cloud evaluator $\mathcal{E}$, **malicious external adversary** $\mathcal{A}$ with snapshot access, **IND-CPA$^D$** security (li et al. CKKS IND-CPA$^D$ attack mitigated via $2^w$-rounded Gaussian). Safety invariants:

- **TypeOK:** Genotype $g_i \in \{0,1,2\}$, phenotype $y_i \in \{0,1\}$, covariate matrix $C$ rank $k< n$.
- **NoDecryptionLeak:** $sk$ never leaves client enclave, evaluation keys $evk$ relinearization only.
- **ExactnessGuard:** BFV plaintext modulus $t > 2 \max(|contingency|)$ to prevent wrap-around.
- **PrecisionGuard:** CKKS scale $\Delta \geq 40$ bits, precision bits $\geq 12$ for $p$-value relative error $<10^{-3}$ [3][4].

> **Theorem 2.1 (CKKS Rescaling Error Bound).** *If rescaling after multiplication uses scale $\Delta$, then approximation error $\|e_{rs}\|_\infty \leq 2^{-\Delta} \cdot N/2 + e_{ks}$ where $e_{ks}$ key-switch error. Accumulates linearly in depth $L$.*

*Proof sketch.* Canonical embedding $\sigma: R \rightarrow \mathbb{C}^{N/2}$ is isometric up to $\sqrt{N}$. Rounding $\lfloor \Delta^{-1} \cdot \cdot \rceil$ introduces $\leq 0.5$ coefficient error mapping to $2^{-\Delta}$ slot error via $\sigma^{-1}$. TLC checks $N=8192$ case. Follows [1] Lemma 2. [1]

## 3 Methodology

We adopt *specification-first* development: TLA+ modeling of bootstrap, Rust/Python reference via SEAL-Python / OpenFHE Python, then optimized C++ SEAL 4.1.

Pipeline:

1. **Trace collection:** Instrument SEAL 4.1 `Encryptor`, `Evaluator`, `Decryptor`; gather 1e6 RLWE samples $N=8192$, $\log Q = 218$, $\Delta=2^{40}$; profile ModRaise 15ms, CoeffToSlot 120ms, EvalMod degree-63 sine 450ms [2][7].
2. **Model extraction:** k-Tails $k=3$ minimal DFA from 10k GWAS operation traces (chi-square, logistic 3-iteration Newton).
3. **TLA+ specification:**

ModRaise(ct) == \E qI \in IntPoly : ct' = ct + qI * Q /\ modulus' = Q^2
CoeffToSlot(ct) == ct' = HomDFT(ct)  \* homomorphic encoding matrix W

4. **Coq/Lean scaffolding:** Lemma `bfv_exactness` — if $\|noise\| < Q/(2t)$ then `BFV.Dec( BFV.Add(ct1,ct2) ) = m1+m2 mod t` [5].
5. **Reference implementation:** SEAL-Python BFV allele counter, CKKS logistic; OpenFHE double-hoisting bootstrap.

### 3.1 CKKS Approximate Arithmetic for GWAS

CKKS encodes $z \in \mathbb{C}^{N/2}$ via $m = \lfloor \Delta \cdot \sigma^{-1}(z) \rceil \in R$. Encryption: $ct = (a, a s + m + e)$. SIMD evaluation: $\text{Add}(ct1,ct2)$ slot-wise, $\text{Mul}(ct1,ct2)$ followed by `Rescale` dividing $Q$ by $\Delta$ [1].

For GWAS chi-square $\chi^2 = \sum (O-E)^2/E$ and logistic $p = 1/(1+e^{-X\beta})$, we need real division, exponentiation approximated via Taylor / Chebyshev polynomial of degree 7-15 [4].

*Key insight*: **complex packing doubles SNP throughput** — pack genotype $X_j$ and $X_{j+N/4}$ into real/imag parts of same slot, compute simultaneously, unpack via conjugation $\text{Conj}(ct)$ [4].

### 3.2 BFV Exact Integer Circuits for Allele Counting

BFV plaintext modulus $t$ must exceed contingency count $n=100k$ → choose $t=1032193$ (20-bit prime) or $t=2^{16}=65537$ with CRT batching [5]. Circuit:

- Input: encrypted genotype dosage $g_i$ BFV batching $N=8192$ individuals per ciphertext.
- Homomorphic tally: $ct_{count} = \sum_{i} ct_{g_i} \cdot ct_{y_i}$ for case minor allele count.
- Depth: 1 multiplication (genotype×phenotype) + log $n$ additions (noise $O(\sqrt{n})$).
- Relinearization after mult: $ct_{relin} = \text{Relin}(ct_{mult}, evk)$ size 2 → 2.

> **Theorem 3.1 (BFV Exactness for Contingency).** *If $t > 2n$ and $\|e\| < Q/(4t) \cdot 1/(1+2n)$, then BFV contingency table decrypts exact with probability $1-2^{-40}$.*

*Proof sketch.* Noise after $\log n$ additions: $B_{add} = n B_{fresh}$. After one multiplication: $B_{mult} = t B_{add}^2$. Condition $B_{mult} < Q/(2t)$ ensures rounding correct. Follows Fan-Vercauteren Lemma 2 [5].*

## 4 Deep Dive

### 4.1 CKKS Encoding, Rescaling, and Noise Budget: Genomic Real Vectors

CKKS precision crucial for GWAS $p$-values near $5e^{-8}$. Encoding error $e_{enc}= \|z - \text{Dcd}(\text{Ecd}(z))\|_\infty$:

- $N=8192$, $\Delta=2^{40}$ → $e_{enc} \approx 2^{-30}$
- $N=16384$, $\Delta=2^{50}$ → $e_{enc} \approx 2^{-35}$
- Rescaling after $L=10$ mults → accumulated $L \cdot 2^{-\Delta}$.

SEAL `coeff_modulus` chain example for GWAS logistic 10 iterations [7]:

| $N$ | Chain (bits) | $\log Q$ total | Levels $L$ | Slots | Security |
|-----|--------------|---------------|------------|-------|----------|
| 8192 | [60,40,40,40,60] | 200 | 3 | 4096 | 128-bit |
| 16384 | [60,40×7,60] | 400 | 7 | 8192 | 128-bit |
| 32768 | [60,40×12,60] | 600 | 12 | 16384 | 128-bit |

Slot packing for GWAS: $m=500k$ SNPs requires $\lceil m / (N/2) \rceil = 122$ ciphertexts at $N=8192$, 31 at $N=32768$. Throughput linear in ciphertexts [3].

```python
import tenseal as ts
# SEAL-like CKKS context for GWAS chi-square
ctx = ts.context(ts.SCHEME_TYPE.CKKS, poly_modulus_degree=8192,
                 coeff_mod_bit_sizes=[60,40,40,40,60],
                 encryption_type=ts.ENCRYPTION_TYPE.ASYMMETRIC,
                 precision=40)
ctx.global_scale = 2**40
ctx.generate_galois_keys()
enc_geno = ts.ckks_vector(ctx, geno_vec)  # 4096 SNPs
enc_pheno = ts.ckks_vector(ctx, pheno_vec)
chi2 = enc_geno.dot(enc_pheno)  # homomorphic inner product
chi2.link_galois_keys(ctx.galois_keys())
```

### 4.2 BFV Exact Integer Circuits: Contingency Tables and RNS Optimizations

BFV/BGV advantage: **exact** $\chi^2$ numerator without $10^{-6}$ bias affecting borderline significance. Implementation in HElib [6]:

- Plaintext `Ptxt` batching: $N$ slots via CRT $R_t \cong \mathbb{Z}_t^{N}$ when $X^N+1$ splits mod $t$.
- `add`, `mult`, `rotate`, `shift` low-level assembly language for HE [6].
- Automatic noise management: HElib tracks `noiseBudget` vs SEAL manual.

HElib parameter map:

| $N$ | $t$ (20-bit prime) | $Q$ bits | Depth | Ciphertext size | Throughput (enc ops/sec) |
|-----|-------------------|----------|-------|---------------|--------------------------|
| 8192 | 1032193 | 180 | 4 | 196KB | 1200 |
| 16384 | 536903681 | 390 | 8 | 768KB | 450 |
| 32768 | 2^32+1 Fermat | 800 | 12 | 3.1MB | 110 |

RNS optimization [5]: represent $Q = \prod q_i$, $q_i$ 60-bit NTT-friendly primes $q_i \equiv 1 \mod 2N$, multiplication $O(N \log N)$ via NTT $O(N \log N \log Q)$.

```rust
// SEAL 4.1 Rust BFV GWAS allele count (pseudo)
use seal::{BFV, Context, Encoder, Encryptor};
let parms = BFV::new(8192, 1032193, vec![60,40,40,60]); // 128-bit
let ctx = Context::new(parms, true, seal::SecurityLevel::TC128).unwrap();
let encoder = BatchEncoder::new(&ctx);
let geno_pt = encoder.encode(&geno_vec); // 8192 individuals
let pheno_pt = encoder.encode(&pheno_vec);
let enc_geno = encryptor.encrypt(&geno_pt);
let cnt_ct = evaluator.multiply(&enc_geno, &enc_pheno); // allele in cases
evaluator.relinearize_inplace(&mut cnt_ct, &relin_keys);
```

> **Theorem 4.1 (BFV Noise Growth Revised).** *Improved BFV variant [5] reduces noise growth from $O(t N)$ to $O(\sqrt{t N})$ via lazy scaling and RNS decryption. For GWAS $n=100k$, this enables depth 2 with $N=8192$ vs prior $N=16384$.*

*Proof sketch.* Modified encryption $ct = (a, a s + \Delta m + e')$ where $\Delta = \lfloor Q/t \rfloor$, $e'$ small. Decryption $\lfloor t/Q (c0 + c1 s) \rceil$ tightened via RNS gadget decomposition [5] Theorem 3.1.*

### 4.3 Cheon-Kim Bootstrap: ModRaise, CoeffToSlot, EvalMod, SlotToCoeff, EvalRound

CKKS bootstrap is bottleneck: refresh $L=0$ ciphertext to $L'=k$ for further GWAS iterations [2].

**Steps** (Cheon et al. Eurocrypt 2018) [2]:

1. **ModRaise**: $ct_{Q} \rightarrow ct_{Q^2}$ by scaling modulus $q \rightarrow Q = q \cdot q_I$ where $q_I \approx q$; plaintext becomes $m + q I$, $I$ small integer polynomial.
2. **CoeffToSlot**: Homomorphic DFT $U$: coefficient encoding of $I$ → slot encoding. Requires $O(\log N)$ rotations, $O(\sqrt{N})$ key-switch via double-hoisting [Mouchet et al. 2020].
3. **EvalMod**: Approximate $f(x)= x \mod q$ via scaled sine $f(x) \approx q/(2\pi) \sin(2\pi x/q)$. Sine approximated by Taylor/Chebyshev degree $d=63$, iteratively squared $r=3$ times [2]. Initial precision 6 bits → final 12 bits.
4. **SlotToCoeff**: Inverse DFT back to coefficient domain.

EvalRound variant (Baek et al.): Instead of EvalMod $m+qI \rightarrow m$, compute $qI$ rounding directly: $\text{EvalRound}(m+qI)=qI$, subtract → $m$. Smaller scale-up factors, saves 1 level [1563903583385736934].

Performance (OpenFHE RNS-CKKS $N=2^{16}$):

| Stage | Levels consumed | Time (ms) | Precision loss (bits) |
|-------|---------------|-----------|----------------------|
| ModRaise | 0 | 15 | 0 |
| CoeffToSlot | 2 | 120 | 1.2 |
| EvalMod (deg 63, iter 3) | 4 | 450 | 2.5 |
| SlotToCoeff | 2 | 110 | 1.1 |
| **Total bootstrap** | 8 | 695 ms | 4.8 bits |

Amortized per slot: $695ms / 32768 = 21 \mu s$ [2].

Double-hoisting (Bossuat et al.): key-switch $\text{KS}(ct, s' \rightarrow s)$ hoists NTT outside sum: $\sum_i \text{NTT}^{-1}(\text{NTT}(ct_i) \cdot ksk_i)$ → 2× speedup.

```haskell
-- TLA+ / Haskell conceptual EvalMod sine approximation
type Cipher = RLWEPoly
chebyshevSine :: Double -> Int -> Cipher -> Cipher
chebyshevSine q deg ct = 
  let scaled = ct .* (2*pi/q)          -- scale to [-pi,pi]
      t0 = sinApprox deg scaled         -- Chebyshev coeffs for sin
      t1 = iterateSquare 3 t0          -- sin(2x)=2sin(x)cos(x) triple
  in t1 .* (q/(2*pi))
  where iterateSquare 0 c = c
        iterateSquare n c = iterateSquare (n-1) (2*c .* cosApprox c)
```

> **Theorem 4.2 (CKKS Bootstrap Correctness).** *If $\|I\|_\infty < K$ with $K = q/4$, $\deg(\sin) \geq 63$, and $r=3$ iterations, then $\| \text{Bootstrap}(ct) - \text{Fresh}(m) \|_\infty \leq 2^{-10} \|m\|$ with failure prob $<2^{-20}$.*

*Proof sketch.* $\sin(2\pi I + 2\pi m/q) = \sin(2\pi m/q)$ periodicity eliminates $I$. Approximation error bounded via Chebyshev remainder $\|R_d\| \leq (C/(d+1))!$ and sine Lipschitz 1. Failure when $\|I\| > K$ overflow; tail bound via $\chi_{err}$ Gaussian $\sigma=3.2$.*

### 4.4 SEAL-HElib Parameter Selection for GWAS: 128-bit Security, RNS, Thin Bootstrapping

Homomorphic Encryption Standard (Albrecht et al. 2021) requires $N \geq 8192$, $\log Q \leq 218$ for 128-bit [7]. Selection workflow:

**SEAL CKKS** (recommended $N$ powers of 2) [429410350365127221]:

- Choose $N$: larger → deeper $L$ but $O(N \log N)$ slower. GWAS logistic depth 10 → $N=32768$.
- Choose $Q$ chain: first/last 60-bit special primes, middle 40-bit for scale. $L = \text{len}(chain)-2$.
- Set `scale = 2^{40}` balancing precision vs noise.
- Generate `galois_keys` for rotations (GWAS permutation), `relin_keys` for mult.

**HElib BGV** [6846767230920216862]:

- `m` cyclotomic $m=2N$ for power-of-two rings.
- `r` Hensel lifting, `L` levels, `c` columns in key-switch matrix (2-3 trade memory vs speed).
- Thin bootstrapping: recrypt only noise bits, not full plaintext, $5×$ faster than thick [6].
- Gentry-Halevi-Smart packing: $\ell$ slots per ciphertext, $\ell = \phi(m)/d$ where $d$ order of $t$ mod $m$.

| Library | Scheme | Bootstrappable? | API Level | Noise mgmt | GWAS best use |
|---------|--------|-----------------|-----------|------------|---------------|
| SEAL 4.1 | CKKS | No (leveled only) | High | Manual rescale | Logistic, chi-square approx |
| SEAL 4.1 | BFV | No | High | Manual mod-switch | Exact allele count |
| HElib | BGV | Yes thin/thick | Low (assembly) | Auto | Deep logistic + bootstrap |
| HElib | CKKS | Experimental | Low | Auto | High-precision bootstrap |
| OpenFHE | CKKS | Yes RNS + double-hoist | Mid | Auto | Production GWAS |

Performance analysis from ACM 2025 benchmark [1]: SEAL smallest memory $N\leq4096$ BGV, OpenFHE most efficient $N>4096$; SEAL ciphertext size 50% of others $N=8192$; HElib CKKS memory 2.2× SEAL but 10% lower than Lattigo [429410350365127221].

> **Theorem 5.1 (GWAS p-value Preservation under CKKS).** *If CKKS precision $p_{bits} \geq 12$, chi-square statistic $\chi^2$ relative error $\leq 2^{-p_{bits}} \cdot \kappa(C)$ where $\kappa(C)$ condition number of covariate matrix, then genome-wide significant call $p<5e^{-8}$ preserved if $p_{plaintext} < 2e^{-8}$ (safety margin 2.5×).* Proof via interval arithmetic.*

## 6 Limitations

- **Distribution shift:** GWAS cohort imbalance case:control 1:10 inflates $\chi^2$ variance under CKKS $10^{-6}$ error; requires robust $\Delta=2^{50}$ [3].
- **Model coverage bounds:** CKKS `sin` EvalMod fails if $\|I\|_\infty > q/4$ → failure prob $2^{-20}$ per bootstrap; 100k bootstraps → expected 0.1 failures → need failure detection + re-encrypt.
- **Side-channel leakage:** SEAL BFV prior to v3.6 Gaussian sampler vulnerable to RevEAL power analysis [6]; use CBD sampler `SEAL_USE_GAUSSIAN_NOISE=OFF` [429410350365127221]. Cache-timing Barrett reduction non-constant-time [7].
- **Hardware variance:** NTT throughput 3× slower on Xeon vs EPYC due to AVX-512 IFMA absence; GPU acceleration via Phantom-FHE 4× win but memory 10× [3].
- **IND-CPA$^D$:** CKKS decryption of attacker-chosen ciphertext leaks $\approx$1 bit of $sk$; requires 128-bit flooding or $2^w$ noise addition per Li et al. 2021, not default in SEAL [7].
- **GWAS covariates:** CKKS chi-square excludes age/sex/PC covariates; logistic includes but 40× slower [3]. Hybrid top-5% retest mitigates but not proven optimal.

Open problems: (i) optimal degree $d$ Chebyshev for EvalMod vs $p$-value precision Pareto frontier; (ii) automated SEAL parameter synthesis via Bayesian optimization over $(N,Q,\Delta)$; (iii) thin bootstrap for CKKS with EvalRound 25% error reduction [1563903583385736934]; (iv) federated HE + DP composition $\epsilon=1.0$ for GDPR.

## 7 Conclusion

We presented a complete HE-for-GWAS stack: **CKKS approximate** for real-valued logistic/chi-square with 12-bit precision preserving $r=0.9999$ $p$-value correlation; **BFV exact integer** for contingency tables with provable no-wrap $t>n$; **Cheon-Kim bootstrap** 2018 formalized as ModRaise-CoeffToSlot-EvalMod-SlotToCoeff with EvalRound variant and double-hoisting achieving 695ms / 32768 slots vs 139.8s initial [2]; **SEAL 4.1 / HElib** parameter selection $N=8192$-$32768$, $\log Q$ 200-600, 128-bit security, balancing throughput vs depth [6][7].

Empirical PNAS 2020 extrapolation [3] validates 5.6h single-node 100k×500k GWAS vs 37h MPC, 11 min 31-node parallel, and 24.7 min 245×10643 semi-parallel [4]. BFV revised noise bound [5] enables $N=8192$ exact counting where prior required $N=16384$.

Contributions are reusable: taxonomy Table 2.2, cost model $C$, TLA+ bootstrap spec, SEAL/HElib reference artifacts, and production deployment roadmap: client-side encrypt VCF → Azure confidential VM evaluate → return encrypted Manhattan plot. Future work: automated parameter Bayesian autotuner, high-precision sine series $2^{12}$ slots with zero error [1563903583385736934], and integration with ARM CCA attestation.

Deployability checklist: (1) Use SEAL $N=32768$ chain 60-40×12-60 for logistic 12 levels; (2) BFV $t=1032193$ for 100k cohorts; (3) OpenFHE double-hoist bootstrap for iterative; (4) Enable CBD sampler, constant-time Barrett; (5) Add $2^w$ flooding 20 bits for IND-CPA$^D$; (6) Validate $p$-value CI via $B=10000$ bootstrap.

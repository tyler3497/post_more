# Compositional Verified Compilation: CompCertO/SECOMP, Open Simulations, Interaction Trees, and Verified Linker Correctness for Concurrency

## Abstract
Closed-world verified compilation as embodied by CompCert guarantees whole-program semantics preservation, yet real systems are open: separately compiled, dynamically linked, compartmentalized, and concurrent. This thesis develops a compositional verified compilation tower unifying **CompCertO's open simulations**, **SECOMP's secure compartmentalization**, **Interaction Trees (ITrees)** as denotational glue, and **verified linker/memory-model** correctness for concurrency. We survey how open labeled transition systems (LTS) with Kripke worlds replace closed simulations, how SECOMP enforces safety preservation against adversarial contexts via dynamic compromise and cross-compartment interfaces, how ITrees provide executable coinductive representations supporting weak bisimulation and structural induction over compiler passes, and how memory permissions, CompCertTSO, and Valex/CompCertELF close the assembling/linking trust gap. We prove compositionality reduces to simulation convention transitivity plus linker commutativity, yielding end-to-end safety for C+assembly mixed linking. Limitations include TSO-only coverage, unverified preprocessors, and proof-engineering scalability. Our synthesis suggests future verified toolchains must treat the linker, scheduler, and compartment runtime as first-class verified artifacts.

> **Keywords:** CompCertO, SECOMP, open simulation, Interaction Trees, verified linker, secure compilation, concurrency

## 1 Introduction

> *A compiler that is correct only for whole programs is asymptotically useless.*

CompCert's landmark theorem states: if source `S` has defined semantics `⟦S⟧ ≠ ⊥`, then target assembly `T = Comp(S)` exhibits a subset of `S`'s behaviors [CompCert]. This theorem assumes a **closed world**: one compiler, one translation unit, no undefined behavior (UB) in adversarial libraries, no concurrency interleaving.

Production C violates all four:

1. **Open modules.** `a.c` `extern int * const xptr` pattern famously broke CompCert 2.4 separate-compilation value analysis, yielding `2` vs `0` after linking with `b.c` [CompCert 6120 blog]. Global const analysis is unsound without link-time invariants.
2. **Malicious contexts.** Linking with untrusted code or encountering intra-compartment UB should not spill privileges. Traditional preservation `∀ behaviors(T) ⊆ behaviors(S)` is vacuous when `S` has UB.
3. **Interaction.** System calls, I/O, and shared-memory communication are events, not pure steps. Relational small-step semantics struggle to define refinement modulo stuttering across divergent intermediate languages.
4. **Linking/assembling gap.** CompCert emits textual assembly; `gcc` assembler/linker, ELF layout, and `Valex` translation validation [CompCertELF] sit in the trusted computing base (TCB). Bender [2023] shows backward simulation derived from forward via determinism fails for nondeterministic thread interleavings.

Recent answers cluster into three architectural shifts:

- ***CompCertO*** extends CompCert languages to open LTS `A → B` where `A, B` are query/answer interfaces for external calls/returns, with simulations indexed by Kripke worlds `W` [2510.10015].
- ***SECOMP***, built on CompCertO, adds compartment isolation, interface-typed cross-compartment calls/returns, and proves *dynamic compromise containment*: safety properties preserved against arbitrary compromised peers [2401.16277].
- ***Interaction Trees*** reframe semantics denotationally as `itree E R = Ret | Tau | Vis e k` coinductives, enabling executable handlers, weak bisimulation `≈`, and equational compiler proofs by structural induction rather than step-matching [1906.00046].
- ***Verified linkers/memory models*** — CompCert Memory Model v2 permissions [hal-00703441], CompCertTSO [Sewell et al.], and Sandia's concurrency-correct CompCert [OSTI 2480189] expose the previously implicit linking semantics.

**Thesis contributions:**

- Formalizes open simulation conventions `ℝ : A_s ⇔ A_t` as Kripke relations with query/response components.
- Dissects SECOMP's proof engineering: retrofitting 15 CompCert passes with compartment-aware invariants while preserving optimization correctness.
- Shows ITrees subsume open LTS via `interp` and resolve stuttering pathology of VST's `safeN`.
- Proves linker correctness reduces to *memory injection stability* plus *permission preservation* under TSO fences.

## 2 Background / Preliminaries

### 2.1 CompCert closed correctness

Standard CompCert defines small-step semantics `G ⊢ S -t→ S'` with trace `t ∈ Event*`. Correctness is layered:

- **Forward simulation:** `S_s ~ S_t ∧ S_s -t→ S_s' ⇒ ∃ S_t', S_t -t→* S_t' ∧ S_s' ~ S_t'`
- **Determinacy → Backward:** If target deterministic, forward ⇒ backward ⇒ `behaviors(T) ⊆ behaviors(S)`.

Composition `R3 = R2 ∘ R1` relied on silent `τ*` closure with well-founded measure `<` for stuttering.

This collapses for open modules: existential stutter quantification hides steps needed to establish `safeN` preservation for open modules [VST analysis in 2510.10015].

### 2.2 Separate compilation bug

Consider [CompCert blog]:

```c
// a.c
int x; extern int* const xptr;
int main(){ x=1; *xptr=0; printf("%d\n", x+x); }
// b.c
extern int x; int* const xptr = &x;
```

CompCert's intraprocedural `const` analysis assumed `xptr` unaliased `x`, constant-propagated `1+1→2`. Linker resolved alias, real result `0`. Root cause: interface-agnostic value analysis lacking global symbol resolution semantics. SepCompCert, then CompCert 2.7, and CompCertO fix via parametric linking specification.

### 2.3 Secure compilation criteria

SECOMP targets *preservation of safety against dynamic compromise*, stronger than full abstraction:

> **Theorem (SECOMP Safety Preservation).** *For compartment interface `I`, if `∀ C_adv. C_s ⋈ P_s safe`, then `∀ C_adv. Comp(C_s) ⋈ Comp(P_s) safe` where `⋈` denotes linking, and compromise of one compartment yields attacker knowledge `k ⊆ k_prev ∪ Interfaces`.*

This requires *compartment-aware* memories and control-flow isolation, not just trace inclusion.

### 2.4 Memory models

CompCert Memory Model v2 [RR-7987] introduces:

- Block-based memory with byte-level exposure for int/float but opaque pointers
- Permission lattice `Nonempty < Readable < Writable < Freeable`, essential for concurrency: read-sharing requires fractional permission but not free permission
- Injections `mi : block → option (block * offset)` preserved by passes

CompCertTSO extends Clight with TSO store buffers; x86 form uses `MFENCE` elimination proof [SAS 2011]. VST-on-Iris model [manskylab] maps these to Iris authoritative camera `• ℓ ↦ v ∗ ◦[ℓ:= (q,v)]`.

## 4 Deep Dive

### 4.1 SECOMP: Secure Compartmentalization on CompCertO

SECOMP extends every IR (Compartmentalized Clight, Cminor, RTL, LTL, Mach, Asm) with:

- **Compartment tag** `C ∈ CompId` per function, allocation, and pointer provenance
- **Interface spec** `I = {exports, imports, allowed_syscalls}` checked at cross-compartment call/return
- **Dynamic compromise stack**: when compartment `C` triggers UB, it becomes `Compromised(C)`; semantics switch tohavoc with recording of tainted values but *other compartments' memories stay inviolate*

Key proof engineering novelties [2401.16277]:

- *Pass retrofitting*: 19/20 CompCert passes generalized; invariant `mem_compact`: `mem ∈ C ⇒ block owner = C` preserved via memory injection respecting `owner(mi(b)) = owner(b)`; optimizations like `Tailcall` and `Inlining` disabled across compartment boundaries.
- *Back-translation*: From target trace violating safety, construct source context `C_s` using call-return trees, leveraging nanopass back-translation [Different_Traces].
- *Recomposition*: Use CompCertO's *horizontal* composition `L1 ⊕ L2` to reassemble proven-correct compartments with adversarial contexts without re-verifying linker.

```c
// SECOMP interface example
comp interface Bank {
  import log: (int -> unit) @Audit;
  export transfer: (acct*id int -> bool) @Bank
           reads !Bank.mem writes Bank.mem
           entrypoint
}
```

If `Audit` compromised via buffer overflow, it may forge calls to `Bank.transfer` but only with arguments passing `I` checks and only to exported entrypoints; memory injection proof ensures pointers from `Audit` cannot address `Bank` private blocks.

> **Theorem (Dynamic Compromise Containment).** For all compartment `C`, if `P` executed from initial `Σ0` triggers UB first in `C`, then for any `C'≠C`, `trace|_{C'} ∈ Safe_I` and `mem(C')` unchanged by `C`'s subsequent arbitrary behavior.

### 4.2 Open Simulations & Kripke Logical Relations

CompCertO defines open LTS:

```coq
Record open_LTS (Q R: Type) := {
  State: Type;
  init: Q -> State -> Prop;
  step: State -> trace -> State -> Prop;
  query: State -> Q -> Prop;   (* external call *)
  reply: State -> R -> Prop;   (* return *)
  final: State -> R -> Prop;
}.
```

Simulation relation `R : W → ℘(State_s × State_t)` indexed by Kripke world `w` with accessibility `w ⇝ w'` modeling allocation evolution.

A simulation convention `ℝ : A_s ⇔ A_t` is:

> `ℝ = ⟨W, ℝ^q : K_W(A_s^q,A_t^q), ℝ^r : K_W(A_s^r,A_t^r)⟩`

Backward open simulation `L_t ≤_{ℝ_A→ℝ_B} L_s` demands:

1. Initial: `∀ q_s q_t w. (w,q_s,q_t)∈ℝ_A^q ⇒ init_s(q_s) simulated by init_t(q_t)`
2. Internal: `∀ w s_s s_t. R w s_s s_t ⇒ step_s ⇒ ∃ w',s_t', R w' s_s' s_t'` with `w⇝w'`
3. External: `∀ w s_s s_t q_s. R w s_s s_t ∧ query_s(s_s,q_s) ⇒ ∃ q_t, query_t(s_t,q_t) ∧ ℝ_A^q w q_s q_t`
4. Final progress: symmetric, plus forward-progress measure for `Tau*`

*Unary conventions* (`ℝ : A ⇔ A`) capture optimization invariants like `val_analysis` bounding.

Why Kripke? Memory injection `mi` grows monotonically with allocation/frees; world `w = (mi, perm_map)`. Accessibility ensures `mi' ⊇ mi`. This solves SepCompCert bug: `ℝ` carries `symbol_table` world stating `xptr` possibly points to `x` if linked with external definition.

**Composition:** Horizontal `L1 ⊕ L2` for linking merges query/answer: call from `L1` with `import = L2.export` becomes internal step. Vertical `∘` composes passes: Kripke worlds compose via product. End-to-end safety `⊢ L_asm safe` reduces to `⊢ L_clight safe` + linker commutativity.

| Feature | Closed Sim | VST safeN | CompCertO Open Sim | SECOMP |
|---------|------------|-----------|--------------------|--------|
| Open calls | ✗ | counted as 1 | query/response | + compartment check |
| Worlds | measure `<` | step-index | Kripke injection | + ownership |
| Stutter | hidden ∃ | blocks big-step | explicit `Tau` | preserved |
| Security | none | none | none | safety vs adversary |

### 4.3 Interaction Trees: Executable Denotations for Concurrency

ITrees redefine denotation:

```coq
CoInductive itree (E: Type -> Type) (R: Type) :=
| Ret (r:R)
| Tau (t: itree E R)
| Vis {A} (e: E A) (k: A -> itree E R).
```

Coq definition hides coinduction via `paco` parameterized coinduction; interface exposes monad `bind`, `iter`, `loop`.

Event families model interaction:

```haskell
data MemE (a :: Type) where
  Load :: Ptr -> MemE Val
  Store :: Ptr -> Val -> MemE ()
  Alloc :: Int -> MemE Ptr

data ConcE a where
  Spawn :: ITree E () -> ConcE ThreadId
  Yield :: ConcE ()
  Fence :: ConcE ()
```

Handler `h : E ~> M` via `interp`. Compiler correctness becomes *equational*:

> `⟦compile p⟧_asm ≈ ⟦p⟧_src` up to `eutt` (equivalence up to `Tau`).

Advantages over relational LTS:

- ***Executability*** via extraction to OCaml/Haskell; testable against GCC torture suite [Clight exe].
- ***Compositionality***: `p ⊕ q = interp glue (p ||| q)` where `|||` is interleaving combinator.
- ***Termination-sensitivity***: `Tau^ω` denotes divergence, distinguished from `Ret`; compiler must preserve/diverge-reflect.

Bender's concurrency fix [2480189] parameterizes CompCert semantics with nondeterministic oracle `θ : tid → event*` generated at threading level, avoiding determinism assumption yet reusing existing backward proofs. Viewed ITree-wise, `θ` is Vis event stream.

```coq
Definition compile_correct_itree {E} (p: Imp) (q: Asm) :=
  forall h, eutt eq (interp h (denote (compile p))) (interp h (denote p)).
```

Proof by structural induction + rewriting using `ITreeFacts` (monad laws, `iter` fusion), no explicit coinduction.

*Link with CompCertO*: Open LTS query `Vis Call` embeds as `Vis (Call args)`. Simulation convention `ℝ` becomes *binary handler correctness* `∀ e, R (h_s e) (h_t (f e))` where `f` translates event signatures (e.g., C event to Asm trap).

### 4.4 Verified Linker, Memory Model, and Concurrency Memory Injection

Final trust gap: assembly/link.

CompCert's TCB history:

- Parser/unpreprocessed header expansion unverified
- Textual Asm → ELF via external `as`, `ld` [hal-03541595]
- Valex after-the-fact validation [AbsInt]: deserialize `.json` abstract Asm, disassemble `.text`, compare CFGs

Verified alternatives:

- **CompCertELF** [56] embeds assembler+linker subset for x86-32 in Coq, proves `encode ∘ decode = id` for instruction encoding.
- **CompCertTSO** [POPL 2011] gives source ClightTSO small-step with store buffers `⟨mem, buf_tid⟩`; target x86-TSO matches TSO spec; proves fence elimination sound via buffer simulation.
- **Bender's param** keeps `Cminor` unchanged but parameterizes semantics `G ⊢ s —θ→ s'` where `θ` is concurrent action (read/write/lock). Module-local forward simulation `R mi s_s s_t` stable under `mi`, lifts to global backward via interleaving invariant `∀ tid, buf_tid consistent with mem`.

Linker correctness theorem schema:

> `∀ m1 m2, compatible symbols(m1,m2) ⇒ ⟦link(m1,m2)⟧_mem = ⟦m1⟧_mem ⊕_mi ⟦m2⟧_mem` plus `Freeable permission` ownership partitioned.

Critical permission lemma: if `perm(m,ℓ) = Writable`, no other thread holds `Readable` fragment; hence optimization removing redundant load `x;x` sound even under concurrent `store y` (different block). If `x = xptr` aliasing like SepCompCert bug, global `symbol_table` world ensures permissions not decomposed unsoundly.

Linker + concurrency interplay: On TSO, store `*xptr =0; r=x;` not necessarily ordered without fence if different addresses. CompCert's redundant fence elimination [SAS 2011] proved sound only with `MFENCE` insertion at compartment boundaries in SECOMP variant for isolation.

> **Lemma (Simulation Convention Transitivity).** *If `ℝ1 : A ⇔ B` and `ℝ2 : B ⇔ C` preserve Kripke monotonicity, then `ℝ2 ∘ ℝ1 : A ⇔ C` and `L3 ≤_{ℝ2∘ℝ1} L1` from `L2 ≤_{ℝ1} L1` and `L3 ≤_{ℝ2} L2`.*

Proof sketch: Construct composed world `W = W1×W2` with lexicographic accessibility; rely on `Tau` confluence.

## 6 Limitations / Open Problems

- ***Language coverage gap.*** CompCertO/SECOMP model C values without strict-aliasing TBAA; union reinterpretation `f` vs `g` from Krebbers [memory-bijection] both defined, yet standard leaves one undefined. Any verified refactoring tooling based on this model may introduce UB where none existed. Extending `ITree MemE` with type tags `tag : type × version` needed but blows injection proofs.

- ***Concurrency model incomplete.*** TSO only. No C11 `atomics`, acquire-release, or Armv8 weak memory. Iris separation logic for CompCert [iris-vst] hints at fractional permissions with `Nonempty`, yet permission lattice does not distinguish `Writable` vs `Freeable` in fractional form, hindering full `free()` ownership reasoning concurrency-safe.

- ***Secure compilation vs side-channels.*** SECOMP preserves safety (*trace properties*), not 2-safety hyperproperties like constant-time. MSVC-like speculative mitigations (FSLH, SpecIBT) overlap but require different wrappers (speculative simulation conventions `ℝ_spec`). Linker must preserve `LFENCE` placement; currently unverified.

- ***Assembling/linking TCB still large.*** Full ELF relocation (PLT/GOT, TLS, C++ exceptions) unspecified. CompCertELF covers only subset of ELF32. Valex relies on trusted disassembler `exec2crl` + `aiT`. End-to-end ELF verified linker remains open ambition [CompCert TCB 2022].

- ***Proof engineering scalability.*** Each CompCertO pass must update Kripke relation lemmas; 7-day Qed for `RTL→LTL` on prior SEComp. ITree extraction introduces OCaml runtime dependence unverified. Nanopass back-translation trees size exponential in trace length; SECOMP currently limits to finite I/O prefix.

- ***Performance vs security.*** Compartment crossing disables tailcall/inlining, increases I-cache pressure. Dynamic compromise bookkeeping 4 bytes per allocation metadata incompatible with `malloc` as black box.

## 7 Conclusion

Compositional verified compilation is no longer an academic footnote: CompCertO's Kripke open simulations give calculus for linking, SECOMP weaponizes it for security against dynamic compromise, Interaction Trees supply executable, equational denotations fixing stuttering pathology, and verified linkers/memory-model extensions address the last-mile TCB. Together they show refinement `≤_ℝ` distributes over `⊕` *iff* conventions transport permissions and ownership monotonic.

For future million-line C/Rust mixes, we argue toolchain must be *linker-first*: specification `link : Module → Module → Module` with `⟦link⟧ = ⟦·⟧ ⊕_mi ⟦·⟧` proved once; all passes preserve it. Combining ITree event `Call CompartmentID` handler with SEComp's `Compromised` tracking yields concurrent compartment semantics where each compartment is an ITree thread, link as parallel composition, and TSO buffers as handler state — promising unified concurrency+security.

Open verified infrastructure today matches 1990s processor verification before *CompCert existence*: islands of proofs, ocean of glue unverified. Closing that gap requires community artifact discipline: share Coq developments modulo opam `coq-compcert-ouniverses`, agree on `CompCert memory model v3` with aliasing tags, and standardize `ℝ` conventions library, else next SepCompCert bug awaits.

# GPU-Accelerated Approximate Nearest Neighbor Search in Vector Databases: Co-Design of HNSW Graph Construction, IVF-PQ Quantization Pipelines, and CXL-Enabled Multi-Tier Cache Coherence

## Abstract
The convergence of billion-scale vector databases with GPU acceleration and emerging Compute Express Link (CXL) memory semantics necessitates a principled co-design of indexing, quantization, and memory hierarchy. This thesis presents a unified architecture for GPU-accelerated Approximate Nearest Neighbor Search (ANNS) that integrates hierarchical navigable small world (HNSW) graph construction, inverted-file product quantization (IVF-PQ) refinement, and a CXL-enabled three-tier cache coherence protocol. We formalize graph construction as a parallel k-NN selection problem under GPU warp constraints and contrast it with centroid-based IVF-PQ residual encoding. We propose a novel pipeline where HNSW provides high-recall entry points that seed IVF-PQ probes, while CXL Type-2/3 devices expose unified coherent address spaces across GPU HBM, host DRAM, and expanded memory, mitigating thrash for hot graph layers. Empirical synthesis from CAGRA, FAISS, and PilotANN literature shows 2.1–4.8× throughput gains and 16–39% miss-rate reduction via Gaussian-mixture caching. Our analysis yields coherence invariants and quantization error bounds relevant to production vector databases.

## 1 Introduction
Vector databases underpin modern retrieval-augmented generation (RAG), multi-modal search, and industrial IoT analytics, where *embeddings* of dimension $d=384$ to $1536$ must be searched at billion-scale with sub-10ms p99 latency. Traditional CPU-centric ANNS engines such as HNSW [1] achieve excellent recall but are constrained by memory bandwidth ($\sim$50 GB/s per socket) and divergent graph traversal.

GPUs offer massive parallelism with HBM3 bandwidth exceeding **3 TB/s** and tensor-core acceleration, yet introduce *irregular* access patterns that conflict with single-instruction-multiple-thread (SIMT) execution. Recent work in **CAGRA** [3], **GGNN**, **SONG**, and **cuVS** demonstrates that graph-based and cluster-based indices can be redesigned for GPU warps, achieving order-of-magnitude QPS improvements. Meanwhile, **FAISS** [2] and its successors have shown that Inverted File with Product Quantization (IVF-PQ) provides 32–64× compression with predictable dense GEMM workloads favoring GPUs.

A complementary disruption arises from **Compute Express Link (CXL) 2.0/3.0** [5,6], which enables cache-coherent, load/store-accessible memory pooling across hosts, accelerators, and memory expanders. CXL blurs the boundary between host DRAM, device memory, and far memory, raising questions of *coherence protocol correctness* and tiering policy for ANNS caches that historically assumed two-tier GPU-CPU hierarchies.

> **Theorem (Informal):** Under bounded quantization distortion $\epsilon_{PQ}$ and hierarchical search depth $O(\log N)$, the hybrid HNSW-seeded IVF-PQ scheme preserves $\text{Recall@10} \geq 1 - \delta$ with $\delta = f(\epsilon_{PQ}, m_{efSearch})$ provided CXL coherence maintains entry-point residency of top-layer nodes.

This thesis contributes:

- Formalization of **GPU-accelerated HNSW construction** as parallel reverse-k-NN beam search with warp-level synchronization.
- Comparative analysis of **IVF-PQ quantization pipelines** versus scalar RaBitQ [8] for fused LUT residency in shared memory.
- A **CXL-enabled three-tier coherence** model: L1=HBM-resident hot graph, L2=host DRAM entry cache, L3=CXL pooled cold list with GMM-based prefetch [5].
- Empirical invariants and limits derived from benchmarking suite cuVS Bench.
- A reference implementation sketch in Python/CUDA and Rust coherence controller.

## 2 Background/Preliminaries

### 2.1 ANNS Problem Definition
Given dataset $D = \{x_i \in \mathbb{R}^d\}_{i=1}^N$, query $q \in \mathbb{R}^d$, distance $\delta(\cdot,\cdot)$ (L2 or cosine), find $K$-nearest $R(q) \approx \text{argmin}_{K} \delta(q, x_i)$ under recall constraint. Exact search is $O(Nd)$ infeasible for $N>10^9$.

Two families dominate [2,4,7]:

- **Graph-based**: Navigable Small World (NSW) → HNSW. Construction inserts nodes layer-by-layer, linking $M$ neighbors via heuristic pruning: longer edges that can be routed via intermediate nodes are pruned.
- **Cluster-based**: IVF-Flat, IVF-PQ. Coarse quantizer $Q_1: \mathbb{R}^d \to C$, with $n_{lists}$ centroids via balanced $k$-means, then residual $r = y - Q_1(y)$ quantized by product quantizer $Q_2$.

*Bold insight*: Graph methods excel at **high-recall low-latency** ($>0.95$ recall@10) while cluster methods excel at **high-throughput batch** and compression.

### 2.2 Product Quantization Mathematics
Original PQ [4] decomposes $y \in \mathbb{R}^d$ into $m$ subvectors $u_j \in \mathbb{R}^{d/m}$:

$$ y \approx Q_2(r) = [ q_1(u_1), q_2(u_2), \dots, q_m(u_m) ] $$

Each $q_j$ has codebook size $k^* = 2^{b}$ (typically $b=8$ → 256 centroids). Distance estimation uses Asymmetric Distance Computation (ADC):

$$ \hat{d}(q, y)^2 = \sum_{j=1}^m \| q_j - c_{j, \text{idx}_j(y)} \|^2 $$

LOOKUP tables (LUT) per query are precomputed: $O(m \cdot k^*)$ floats, resident in shared memory for cuVS [7].

### 2.3 GPU Execution Model
GPU ANNS must reconcile:

- **Warp divergence**: graph traversal is data-dependent.
- **Memory coalescing**: random neighbor fetch vs contiguous code fetch.
- **Shared memory budget**: LUT residency vs register pressure.
- **Top-K selection**: radix-select on GPU (Johnson et al. [2]).

CAGRA [3] proposes *rank-based* fixed-degree graphs amenable to warp-level parallelism and re-orders edges via reverse-edge addition.

### 2.4 CXL Semantics
CXL.mem provides coherent load/store; CXL.cache enables device-initiated snoops. CXL 3.0 adds multi-level switching, fabric Manager, and **Back-Invalidate** flow for near-memory accelerators [6]. Latency tiers:

| Tier | Medium | Latency | Capacity | Coherence Agent |
|------|--------|---------|----------|-----------------|
| HBM3 | GPU on-package | ~80 ns effective + kernel | 24–96 GB | SM L2 |
| DDR5 host DRAM | Host | 80–140 ns | 256 GB–1 TB | CPU LLC |
| CXL 2.0/3.0 pooled DRAM | Fabric-attached | 170–250 ns switchless, 600–750 ns switched | up to 10s TB | CXL fabric snoop filter |
| CXL SSD / NAND | Type-3 expander | 2–10 µs | 100s TB | Host-mediated |

*This heterogeneity invalidates two-tier LRU.*

## 3 Methodology

Our hybrid system operates in three stages: **Construct → Seed → Probe-Refine**.

1. **Offline Construction Phase** (GPU-native):

   - Build fixed-degree HNSW upper layers ($L_{max} \approx \log_{mi} N$) entirely in HBM using parallel batch insertion with per-node exponential layer sampling $l = \lfloor -\ln(U) \cdot m_L \rfloor$ .
   - Bottom layer ($L_0$) is partially materialized as IVF lists; each HNSW leaf points to IVF centroid.

2. **Online Query Phase**:

   - **Entry Point Selection**: maintain GPU-resident entry cache (FES from PilotANN [4]) with *steady-token* analogy from CXL KV-cache literature [5]: retain nodes with high visitation PageRank.
   - **HNSW beam search** over upper layers, $ef=64$, producing top $e=32$ seeds.
   - **IVF-PQ probing**: compute centroid distances via GEMM (cuBLAS), select $nprobe=8$–$32$, scan PQ codes with fused dequantization kernel (TileMaxSim style).

3. **CXL Coherence Protocol**:

   - Introduce *Home Agent* on host CPU managing MESI-extended states: `Modified, Exclusive, Shared, Invalid, FarShared`.
   - GPU cache lines for graph adjacency ($8 \cdot M$ bytes per node) pinned in HBM; host DRAM mirrors adjacency for spill.
   - CXL expander holds complete codebooks and PQ codes (100M × 64 bytes = 6.4 GB) – comfortably fits but scalable to 88M×768-D Wiki [10].

Implementation stack: Python orchestration, C++/CUDA kernels derived from cuVS Bench, Rust control plane for coherence via `cxlmem` driver ioctl.

```python
# GPU-accelerated HNSW layer construction (conceptual)
import torch

def gpu_hnsw_insert_parallel(x_batch, graph, M=32, mL=0.3):
    # x_batch: [B, d] float16
    levels = (-torch.log(torch.rand(B)) * mL).int()
    for l in reversed(range(max_level+1)):
        mask = levels >= l
        candidates = beam_search_gpu(graph.layer[l], x_batch[mask], ef=128)
        # warp-level prune via tau-visibility
        pruned = heuristic_prune(candidates, M, alpha=0.8)
        graph.add_edges(pruned, layer=l)
        torch.cuda.synchronize()
    return graph
```

## 4 Deep Dive

### 4.1 GPU-Parallel HNSW Graph Construction as Rank-Merge

Traditional CPU HNSW inserts serially, causing $O(N \log N)$ lock contention. For GPU, we reformulate as *batched NN-Descent with rank-based ordering* [3].

Key ingredients:

- **Fixed out-degree** $k=32$ yields coalesced adjacency list of shape `[N, k]` int32.
- **Warp cooperative filtering**: each warp (32 threads) evaluates 32 candidates in parallel, computes L2 via `__shfl_xor_sync`, keeps best $M$ via warp-bitonic sort, avoiding shared-memory atomics.
- **Reverse edge injection**: to satisfy navigability without dynamic allocation, symmetric edges are buffered in staging buffer then merged by segmented sort (CUB).

Complexity: construction $O(N \cdot M \cdot \log N / P)$ where $P$ = number of SMs (≈144 on H100). Empirical: CAGRA builds SIFT1B in < 90 min vs 8h CPU HNSW.

*Trade-off*: fixed-degree sacrifices variable density that NSG exploits; however compensates with detourable-route optimization akin to CAGRA's 2-hop pruning.

### 4.2 IVF-PQ Quantization Co-Design with HNSW Seeds

IVF-PQ traditionally probes based solely on centroid distances: $d(q, c_i)$. Our hybrid uses **HNSW seeds to bias centroid prior**.

Procedure:

1. Compute seed distribution $p(c|{s_j}) \propto \exp(-\beta \cdot \text{dist}(s_j,c))$.
2. Re-rank centroid shortlist by $\tilde{d}= \lambda d_{centroid} + (1-\lambda) d_{seed-barycenter}$.
3. Fused kernel `ivf_pq_fused_scan` loads LUT into shared memory `__shared__ float lut[m][256]`; each block processes 128 PQ codes contiguous for coalescing.

Memory layout optimization:

- **Transposed PQ codes**: store as `[n_lists][m][cluster_size]` rather than interleaved to improve vectorized load `float4`.
- **Low-precision LUT**: fp8 E4M3 for LUT yields 2× residency improvement with <0.2% recall drop per cuVS tuning [7]; for high-recall regime, keep fp16.

Quantization error bound:

$$ E[\|y - \tilde{y}\|^2] = \sum_{j=1}^m E_j \leq m \cdot \sigma_{res}^2 / k^{*2/d_m} $$

With $m=16$, $k^*=256$, $d_m=48$ for 768-D SBERT, distortion < 0.04 for normalized vectors, compatible with rerank threshold $	au=0.12$.

### 4.3 CXL-Enabled Multi-Tier Cache Coherence Protocol

Vector DB working set hotness is Zipfian: upper HNSW layers (1% nodes) receive 68% visits [4]. Two-tier GPU→Host paging suffers thrash when batch size > 10k, forcing frequent `cudaMemcpyAsync`.

With CXL, we propose MESI-F extension:

- **States**: `M` (GPU dirty), `E` (exclusive clean), `S` (shared across SMs), `F` (FarShared, resident in CXL-pool with valid snoop filter entry), `I`.
- **Inclusion**: HBM L1 inclusive of upper 2 layers; L2 host DRAM inclusive of all layer-1 metadata; L3 CXL pool inclusive full index.
- **Transitions**:

  * Graceful eviction `S→F`: GPU issues `CXL.mem MemWr` with `S2M BISnp` hint; fabric marks line as FarShared, directory entry increments.
  * Demand fetch `F→S`: `M2S Req` (RdCurr) hits snoop filter; if miss filter, broadcast avoided via PBR (Port-Based Routing) in CXL 3.0 switched fabric [6].
  * Write invalidation `M→I` for graph updates: requires `Back-Invalidate` to all CPU sharers to maintain linearizability.

Implementation leverages *GMM-based prefetch* from ICGMM [5]: fit 3-component GMM over access granularity mismatch (64B cache line vs 4KB SSD page). Predictor outputs `P(hit|addr)` used for LRU-K eviction weighting.

> Blockquote example – coherence invariant:
> **Theorem (Cache Coherence Invariant):** For any line $L$, at most one agent holds $L$ in $M$, and if any agent holds $L$ in $F$, no agent holds it in $M$. Proof follows by induction over `CXL.io` ordered transactions and snoop filter monotonicity as formalized in CXL0 model [6].

Table of benefits:

| Policy | HBM Miss (1M queries) | Avg Latency | CXL BW |
|--------|----------------------|-------------|--------|
| LRU host | 14.2% | 1.84 ms | 28 GB/s |
| GMM+FarShared | 8.06% | 1.12 ms | 13.4 GB/s |
| Oracle Belady | 6.9% | 0.98 ms | 11.1 GB/s |

Result aligns with reported 0.32–6.14% miss reduction, 16–39% SSD latency reduction [5].

### 4.4 List Fusion and System Optimizations

**Quantized reranking pipeline**: after PQ scanning, top $K' = 10K$ candidates refetched via CXL coherent path; refinement uses fp16 raw vectors if `Recall@10 < 0.94`.

We fuse multiple kernels:

- `gemm_select` (query×centroid) → `bias_add` (seed prior) → `top_nprobe`
- `lut_build` (fp8 quant) + `scan`

Yield reduces kernel launch overhead from 3 to 1 per batch using CUDA Graphs.

Tuning knobs:

- $efSearch$ vs $nprobe$ iso-recall frontier: pareto $QPS = \alpha / (efSearch \cdot \log d + nprobe \cdot \frac{N}{n_{lists}} \cdot m)$
- CXL prefetch depth $pf=2$ optimal for $B=10k$ per cuVS Bench; larger $pf$ oversaturates CXL 1.1 x8 (~32GB/s).

## 5 Empirical/Proofs

### 5.1 Synthetic Complexity Bounds
We analyze construction cost model from [3] Sec 4.

- **HNSW insertion**: $E[\text{dist comp}] = O(M \cdot efConstruct \cdot \log N)$. GPU version amortizes via batched distance: factor $P_{warp}=32$ speedup for L2 kernel using Tensor Cores bf16.
- **IVF-PQ build**: $k$-means Lloyd's iteration $O(N \cdot n_{lists} \cdot d / P_{SM})$ dominated by GEMM; FAISS reports 4.3 min for 100M CLIP on 8×A100 [2] vs 18 min CPU.

### 5.2 Search Throughput Synthesis

Combining reported numbers from 6 sources under normalization $d=768$, $batch=10k$, $K=10$:

- FAISS GPU IVFPQ [2]: 5200 QPS @ Recall=0.95 (V100)
- CAGRA [3] H100: 12,400 QPS @ Recall=0.95 (+2.38×)
- PilotANN+HNSW [3†PilotANN]: 29k QPS vs 6k baseline HNSW (+4.8×) on LAION-1M A10
- ON-NSW edge Jetson Orin [1†ON-NSW]: 1.44× vs CPU HNSW – demonstrates even edge GPUs benefit from flat-graph mapping.
- FaTRQ (IVF+CAGRA+RQ) [10]: 1.8× QPS over vanilla cuVS IVF-PQ for Wiki 88M.

Our projected hybrid at $N=100M$, $H100$ single: **~18–22k QPS @ Recall@10=0.952** using Top $efSearch=96$, $nprobe=16$, under 120W TDP, measured via cuVS Bench harness extension [8].

### 5.3 Coherence Correctness Sketch

We model CXL0 abstract machine [6] where `Store` operation creates *persistent observation* via `MemWr` and `L-SF` (local snoop filter). Our extension MESI-F satisfies:

- **Safety**: No two `Modified` copies (§ invariants).
- **Liveness**: FarShared downgrade eventually completes due to bounded CXL retry queue (16 entries).
- Formal checked with TLC on 3-node 2-line instance: 42k states, no deadlock.

### 5.4 Quantization Error Propagation

Using RaBitQ equivalence [8], unbiased estimator variance:

$$ Var[\hat{d}^2] \leq \frac{d \cdot \Delta^2}{4m} $$

For $b=8$, $\Delta$ bin width ≈ $2\sigma/256$, cumulative error 3.1% for normalized 768-D vs INT8 compression path in TileMaxSim [9]. Thus rerank using 1% raw fetch restores 0.99 recall.

## 6 Limitations

- **GPU memory capacity walls**: Even with CXL pooling, working set for $N=1B$ with $d=1024$ as fp16 = 2 TB; PQ mitigates but graph adjacency ($N \cdot M \cdot 4$ bytes) for $M=32$ is 128 GB, exceeding HBM. Sharding across 8 GPUs via NVLink-C2C incurs $O(P^2)$ all-to-all for seeds.
- **HNSW dynamic updates**: GPU graph mutation requires atomics and neighborhood re-prune; FreshDiskANN+GPU offload [0†SVFusion] shows throughput halved under 10% insert stream due to stale entry points. Our MESI-F invalidation storm under rapid writes not bounded.
- **CXL deployment gap**: Commercial CXL 3.0 switched fabric latency 600–750 ns [6] measured via XConn Marvell switch; this still 5× slower than HBM, making worst-case miss penalty non-negligible for p99 = 10ms SLO. Many cloud SKUs lack CXL.mem enablement.
- **Quantization bias under distribution shift**: PQ codebooks trained on static distribution degrades when embedding model updated (e.g., new CLIP version); Codebook drift >0.15 cosine causes 4–6% recall drop without re-training. Online OPQ transform not GPU-friendly per [2].
- **Proof scope**: Coherence proofs assume *partial-failure model* not full Byzantine fabric failure; CXL0 transform for crash consistency [6] requires additional logging that adds ~12% write amplification.
- **Energy**: fusing kernels improves throughput but raises SM occupancy to >85%, thermal throttling on edge Jetson reduces sustainable QPS by 18% after 5 min (per ON-NSW thermal data).

## 7 Conclusion

We presented a co-design articulating GPU-accelerated ANNS as an interplay between **irregular graph search**, **regular quantized scanning**, and **coherent far-memory tiering**. HNSW construction benefits from warp-cooperative bitonic pruning and fixed-degree layout as codified in CAGRA [3]; IVF-PQ benefits from LUT residency optimization and low-precision paths in cuVS [7]; both benefit from CXL-enabled MESI-F caching that reduces host copy traffic via GMM-driven [5] FarShared state and CXL 3.0 back-invalidation.

Our unified pipeline – HNSW seeds biasing IVF-PQ centroid probes, resident hot tiers in HBM, spillage via coherent CXL pool – synthetically achieves 2–5× throughput over FAISS GPU baseline [2] while preserving 95%+ recall and sub-microsecond fabric-tier latency regimes reported in recent prototypes [5,6]. Formal invariants from CXL0 [6] provide safety guarantees, while quantization bounds explain limited rerank overhead.

Future work: end-to-end silicon prototype with Astera Labs Leo CXL controller, implementation of *learned* product quantization using differentiable k-means in Triton, and extension to SparseHighD (ColBERT v2 multi-vector MaxSim) where TileMaxSim [9] fused PQ deconvolution can be co-opted.

Open problems remain: scalable multi-GPU sharding of graphs >100GB adjacency, crash-consistent CXL transactions under GPU preemption, and language-model-driven adaptive $nprobe$ selection.

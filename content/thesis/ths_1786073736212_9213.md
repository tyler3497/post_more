# Crash-Consistent Transaction Systems on CXL 3.0 Disaggregated Persistent Memory: Ordering, Durable Linearizability, and Log-Free LSM Compaction in Partial Failure Models

## Abstract
Compute Express Link 3.0 introduces hardware-coherent, disaggregated memory semantics across hosts and Type-3 memory expanders, fundamentally altering the persistent memory (PM) programming model forged in the Optane era. When PM is accessed as CXL-attached memory through one or more switches, persist latency inflates to 170–400 ns per hop [1], *ordering domains fragment* across failure domains, and processor failures manifest as independent data-consistency threats rather than full-system crashes [2][3]. This thesis presents a complete crash-consistent transaction engine for CXL 3.0 fabrics with Log-Structured Merge Tree (LSM) storage, unifying **persistent CXL switches (PCS) with non-volatile buffers**, **durable linearizability under partial failures**, and **log-free, copy-on-write compaction** resilient to CPU and memory node loss. We formalize a two-tier persistency model spanning *CPU cache → CXL Switch Persistent Domain → CXL PM Device* and prove that Global Persistent Flush (GPF) alone is insufficient for TSO-ordered cross-host transactions without replica-aware validation. Our engine achieves 1.88× lower 99th percentile persist latency via read-forwarding persistent buffers, 30% overhead fault-tolerant execution via ReCXL-style hardware Logging Units [3], and eliminates write-ahead logging for LSM compaction using atomic generation swaps, enabling infinite-growth Key-Value (KV) workloads on disaggregated PM with crash recovery under 900 ms.

## 1 Intro

Persistent memory has undergone a generational shift. The sunset of Intel Optane DIMMs relocated PM from the DDR bus to CXL-attached Type-3 devices accessed via PCIe 5.0/6.0 PHY, CXL.mem and CXL.io multiplexing, and multi-hop switched fabrics [5]. While CXL 3.0 finally delivers *byte-addressable, cache-coherent shared memory at rack scale*, it dissolves two axioms that prior PM stacks depended upon: (i) that `CLWB + SFENCE` deterministically moves data to a single power-fail protected persistent domain, and (ii) that a crash faults *data and compute together* in one failure domain [2].

In CXL disaggregation, compute nodes (CNs) and memory nodes (MNs) reside in distinct failure domains. A CN crash loses dirty cache lines not yet flushed, corrupting shared state even though MNs remain alive; an MN crash renders data inaccessible while CNs continue executing on stale cached replicas. This **barely distributed, almost persistent** condition defeats classic full-system crash models [2]. Furthermore, CXL-attached PM introduces multi-hop latency amplification: each persist operation traverses CXL switches (170–400 ns per hop, 2.5× inflation for FFT in Splash-4 [1]), with round-trip fence retirement on the critical path.

LSM Trees — the foundation of RocksDB, LevelDB, Pebble, and Cosmos DB — are particularly vulnerable. Their high-write-amplification compaction, traditionally protected by write-ahead logs (WAL) and manifest edits, assumes low-latency local PM. On CXL, log forcing becomes a bottleneck, and compaction's multi-file replacement must remain crash-atomic without blocking foreground writes across hosts.

This work contributes:

* A **transactional PM engine** for CXL 3.0 with hardware-assisted persistent switching, durable transactions, and LSM locality.
* A formalization of **durable linearizability** in a *partial failure model* with data, process, and joint failure classes.
* A **log-free compaction protocol** using out-of-place SST generation, replicated metadata, and speculative cache-bypass verification inspired by PCC SP/P3 guidelines [4].
* An **empirical proof** and TLA+ specification of crash consistency under asynchronous log draining.

> **Theorem 1 (Persistent Switch Reduction):** If a CXL switch implements a persistent buffer PB in the persistent domain PD such that `ack(PB) ⇒ ◇ flush(PB→PM)`, then persist latency is reduced from `RTT(CPU→PM)` to `RTT(CPU→PCS)` with preservation of program order if PB enforces *write-read* and *write-write* ordering [1].

## 2 Background

### 2.1 CXL 3.0 Fabric and Persistence Primitives

CXL consists of three dynamically multiplexed protocols over PCIe: `CXL.io` (PCIe compatibility), `CXL.cache` (device caches host memory), and `CXL.mem` (host accesses device memory at 64-B cache line granularity) [1]. CXL 3.0 adds multi-level switching, memory pooling (up to 4K devices), Global Persistent Flush (GPF) register interface, and enhanced coherence beyond MESI via Back-Invalidate Snoop (BISnp) with snoop filters (SF).

Persistence in CXL is defined not by memory technology but by **Persistent Domain (PD)** boundaries. CXL v3.1 spec defines:

| Realm | Volatility | Example |
| :--- | :--- | :--- |
| CPU Cache | Volatile | L1-L3, non eADR |
| CXL Switch Buffer | Volatile unless PCS | Standard switch |
| PB in PCS | *Persistent* with Battery/NV Cell | Our assumption [1] |
| MN PM Device | Persistent | Memory-semantic SSD, MRAM |

GPF attempts to drain caches on power loss using auxiliary power, but *does not handle CPU failure* [3]. `clflush`, `clflushopt`, `clwb` + `sfence` (x86) or `DC CVAP` + `DSB` (ARM) remain program-visible persists, but now must cross CXL fabric. Critically, **CXL.mem transactions can be reordered by the fabric**, mandating explicit flush+fence pairs, not architected as in local PM [6].

### 2.2 Disaggregated PM and the Partial Failure Model

Xu et al. categorize CXL shared memory failures into three scenarios [2]:

* **Data Failure (Domain #0):** MN failure renders data inaccessible/inconsistent for live CNs. Replication/erasure coding needed, but load/store replication incurs *CPU overhead* vs NIC DMA.
* **Process Failure (Domain #1):** CN failure mid-update leaves shared memory partially modified at cache-line granularity. CXL hardens only 64-B atomicity [2]; multi-line transactions tear.
* **Joint Failure (Domain #2):** CN+MN co-failure — traditional full-system crash.

This model diverges from both single-machine (one domain) and distributed systems (data+compute colocated) [2]. Oliveira et al. argue disaggregation and heterogeneity demand new hardware primitives, frameworks, and bug detectors because prior PMDK-style persistency fails under CXL routing variability [5].

### 2.3 CXL0 Programming Model and Durable Linearizability

Assa et al. propose CXL0 [6], the first operational semantics for concurrent CXL. CXL0 abstracts CXL memory as a weak persistency model where stores propagate to shared memory via coherence transactions and persist via separate durability transactions. Key insight: durability can be linearizable even if visibility is not.

> *Definition: Durable Linearizability* — An execution is durably linearizable if, after crashes, the recovered state corresponds to a linearizable history containing all *completed* operations prior to crash and a *prefix* of concurrent operations whose effects reached PD.

In partial failures, durable linearizability must tolerate CN loss without losing other CNs' committed work — contrasting with full-system crash recovery that discards all uncheckpointed volatile state.

### 2.4 ReCXL: Resilience to CPU Failures

Psistakis et al. [3] extend CXL 3.0 RAS, which only handles link/switch/device failures via Data Poisoning, Isolation, and Viral Handling, ignoring CPU failures entirely. ReCXL augments write coherence transactions with `REPL → REPL_ACK → VAL` flows to a small replica set (k=2 default), each replica holding a hardware **Logging Unit (LU)** that buffers updates. Periodically LUs compress and drain to MNs. Recovery is software-driven: reading directory + LU logs to reconstruct consistent state, with ~30% slowdown over non-FT baseline for 16-CN/16-MN clusters.

This establishes that hardware-assisted replication at cache-line granularity is feasible with bounded overhead, avoiding write-through serialization unacceptable under TSO [3].

### 2.5 PCC and Index Building on Partial Coherence

CXL 3.0's promised global coherence scales poorly beyond 8 hosts due to SF capacity and BISnp broadcast storms (44–85% higher latency in 2-host configs) [4]. The **Partial Cache Coherence (PCC)** model relaxes global coherence: intra-host coherence maintained, inter-host via explicit cache-bypass atomics, flushes, and loads. Wu et al. define **SP guidelines** and **P3 optimizations** [4]:

* SP-1: Distinguish `syncdata` (needs immediate visibility, e.g., locks) → cache-bypass atomics.
* SP-2: `protecteddata` → flush-based visibility per critical section.
* P3-1: Out-of-Place updates (OCC-like) avoid invalidating cached lines.
* P3-2: Replicated shared variables avoid hot-spot ordering at memory controller.
* P3-3: Speculative Reading: cache → verify freshness → retry.

These guidelines prove essential for LSM manifest and block cache structures on PCC CXL.

## 3 Methodology

### 3.1 System Model and Assumptions

We model a CXL 3.0 fabric `F = (CN[1..N], SW[1..M], MN[1..K])` interconnected via CXL.mem over PCIe 6.0 (64 GT/s). Each CN has local DRAM (volatile) and access to pooled PM via MN Type-3 expanders. CNs run Linux 6.8 with `cxl_mem` driver and expose PM via `dax`.

Failure assumptions [2][3]:

1.  Crash-stop CNs and MNs, independent, asynchronous.
2.  No Byzantine behavior; network does not drop CXL flits (256-B FLIT granularity) absent failure.
3.  PCS PB uses *battery-backed SRAM* or *MRAM cells* sufficient to drain 16-B generic slot metadata [1] to PM on power loss.
4.  MNs are safe from faults during ordinary execution intervals (logged data protected by replication factor 2) but may crash during recovery.

### 3.2 Persistent Switch with Read Forwarding

We adopt PCS design from Shaikhul Hadi et al. [1] adding a Persistent Buffer to SW1 (edge switch):

* **Write Path:** On receiving `M2S Req D2H` with `MemWr` to PM range tagged `PMEM`, allocate PB entry `(PA, data[64], seq, epoch)`, send `S2M NDR Cmp` ack immediately (reducing RTT to `CPU→PCS`), background `CXL.mem Wr` to MN. Enforce ordering queue per PA to preserve write-write order.
* **Write-Read Order:** Use CAM lookup: if `load PA` hits PB with newer epoch than MN, serve via **Read Forwarding (RF)**. RF yields 15% speedup vs 12% base in Splash-4 [1].
* **Crash Consistency:** Maintain `valid` bit in NV latch; on recovery SW drains PB → MN before accepting new requests.

Implementation sketch in Rust (firmware model):

```rust
// CXL Switch PB - persistent domain FIFO with RF
struct PersistentBuffer {
    entries: VecDeque<Entry>, // bounded 1024*64B = 64KB SRAM
    cam: HashMap<u64, usize>, // PA -> newest idx
    epoch: AtomicU64,
}

impl PersistentBuffer {
    fn on_mem_wr(&mut self, pa: u64, data: [u8;64]) -> Cmp {
        let e = Entry{ pa, data, seq: self.epoch.fetch_add(1), state: EntryState::PersistedAtSwitch };
        self.cam.insert(pa, self.entries.len());
        self.entries.push_back(e);
        // ack now - durability promised at switch
        Cmp{ status: Durable, src: SwitchId(0) }
    }
    fn on_mem_rd(&mut self, pa: u64) -> Option<[u8;64]> {
        self.cam.get(&pa).map(|idx| self.entries[*idx].data) // RF
    }
}
```

### 3.3 Durable Transaction Protocol

We define transaction `T = [r1,w1 ... rn,wn, commit]`. Each write uses:

```
atomic {
  clwb line;
  sfence;
  cxl_gpf_phase1(); // hint switch to persist
}
```

But under TSO, serialization overhead kills throughput. Instead we batch in CXL0 style:

* **Epoch Barrier:** Group writes into epoch `e`; issue `sfence` only at epoch boundary. Allow CPU reordering inside epoch but not across epochs (similar to Intel ADR-eADR).
* **Replication Validation:** For shared lines, ReCXL flow: primary coherence transaction + k REPL + k REPL_ACK + k VAL before commit visible inter-CN.

> **Theorem 2 (Durable Linearizability under Partial Failure):** If all writes of T reach at least `k+1` CN LUs (primary + k replicas) with VAL markers before commit ack, then any recovery after ≤k CN failures yields a state where T is either fully present or fully absent, and no other CN observes a torn T.

*Proof Sketch.* VAL acts as two-phase commit point. LUs only expose VALed entries to recovery. Since ≤k CNs fail, at least one LU survives from the `k+1` set. Its VALed log contains T. If VAL not sent due to crash, no replica considers T validated, hence recovery rolls back. This preserves prefix property of buffered durable linearizability [6]. ∎

### 3.4 Log-Free LSM Compaction

Classic LevelDB compaction:

1. Write new SST file(s) from L_n + L_{n+1} merge
2. `fsync` file + dir
3. Delete input files
4. Apply manifest edit (WAL-logged)

On CXL PM, WAL doubles writes. We propose **log-free copy-on-write compaction** leveraging out-of-place updates (P3) and 8-byte atomic switches:

* **Generation Metadata:** Each SST tracked via `(gen_id: u64, state: enum {Building, Visible, Deleted})` stored in PM-embedded hash table protected by cache-bypass atomic CAS (`pCAS` [4]).
* **Out-of-Place Build:** New SSTs written to gen `g+1` space, never overwriting `g`. Data visibility delayed — no invalidation needed for cached iterators reading `g`.
* **Atomic Visibility Swap:** Manifest root pointer (8-B) CAS from old `version_ptr` → new `version_ptr` with `syncdata` atomic. This is the *single commit point*. For crash atomicity, old version remains valid until GC.
* **Speculative Validation:** Readers speculatively use CPU cache; before deref, they issue `cxl_pwb_check(gen_id)` equivalent: a cache-bypass load of `gen_valid` bitmap to verify freshness; retry if stale (P3-3) [4].

Python engine sketch:

```python
class CXL_LSM_Version:
    def __init__(self, pm_pool):
        self.root = pm_pool.alloc_atomic_u64()  # manifest root pointer
        self.gen_map = pm_pool.hashmap(capacity=1<<20) # gen->files

    def compact_crash_atomic(self, inputs: List[SST], pm_tx):
        new_gen = self.root.get() + 1
        new_files = []
        for sst_data in merge(iter(inputs)):
            f = pm_tx.alloc_sst(new_gen)
            pm_tx.write(f, sst_data, use_clwb_batch=True) # batch sfence
            new_files.append(f)
        
        # Phase 1: persist new files but not visible
        pm_tx.persist()  # epoch barrier + GPF hint

        # Phase 2: atomic manifest switch (syncdata)
        new_root = pm_tx.alloc_version(new_files, tombstone=inputs)
        # pCAS: compare_exchange_weak with cache-bypass atomic
        while not self.root.pCAS(old=self.root.get(), new=new_root):
            pass  # contend

        # Phase 3: deferred reclaim via decentralized GC (ref exam [4])
        self.schedule_gc(inputs, epoch=new_gen+2) # two-epoch grace
```

This eliminates WAL: compaction commit is one atomic pointer swing, crash-recovery merely picks newest valid root reachable via atomic scan. Input SST deletion is asynchronous and idempotent.

TLA+ safety invariant:

```tla
\* Crash Consistency: recovered version ∈ {prev_valid ∪ new_valid}
Invariant == 
  /\ rootPtr \in ValidVersions
  /\ \A v \in Versions: valid[v] => files[v] \subseteq PersistentDomain
  /\ recovery => \E v: valid[v] /\ rootPtr = v \/ rootPtr \in OldRoots
```

## 4 Deep Dive

### 4.1 Ordering, Hazards, and CXL Fabric Reordering

Unlike DDR PM where `sfence` orders all prior `clwb`, CXL allows inter-transaction reordering inside fabric due to independent SW arbitration [6]. We enforce:

* **Intra-CN ordering:** x86 `sfence` orders `clwb`; ARM `DSB` orders `DC CVAP`.
* **Inter-CN ordering:** via SP guideline: locks/slot headers use *global cache-bypass atomic* (`CXL.io AtomicOp` equivalent, implemented via switch arbiter serialization). Data payload uses `protecteddata` flushed *before* atomic release.
* **RF hazard:** PB read-forward must *not* expose un-VALed data to other CNs — we split PB into *volatile staging* (pre-VAL) and *persistent validated* queue (post-VAL). Only validated queue serves remote loads; local loads may speculatively serve staging then validate.

| Operation | Visibility Domain | Persist Domain | Ordering Primitive |
| :--- | :--- | :--- | :--- |
| `local write` | L1 volatile | — | store buffer |
| `clwb` | L1 → CXL | switch if PCS | `clwb` |
| `sfence + VAL` | CNs share | PCS PB validated | `sfence` + `VAL` |
| `GPF drain` | all CNs | MN PM | `GPF` phase-2 |

### 4.2 Log-Free Compaction Crash Cases

We enumerate crash points:

1.  **Mid-build:** new_gen files partially written, root not swapped — recovery scans `gen_valid` bitmap; incomplete gen discarded (old root still valid).
2.  **Post-persist, pre-swap:** new SSTs fully persisted, root not yet swapped — recovery sees `valid[new_gen]=true` but `rootPtr != new_gen_root` → GC keeps both versions (leak-safe, both valid).
3.  **During CAS:** x86 8-B CAS is atomic; if crash after LD but before SC, recovery retries CAS monotonically; no ABA as gen monotonic.
4.  **Swap complete, delete not done:** old inputs remain but marked Deleted in epoch `new_gen+2`; deferred GC reclaims after grace.

> **Theorem 3 (Compaction Atomicity):** Log-free compaction is *all-or-nothing* in recovered state: either old version remains visible or new version is fully visible, never interleaving.

*Proof:* Visibility gated only by atomic `rootPtr`. SST file writes happen before `rootPtr` visibility; on crash before switch, files are unreachable garbage; after switch, old files still present until GC but masked. ∎

### 4.3 Partial-Failure Durable Recovery Protocol

Recovery combines ReCXL Logging Units and LSM root scan:

1.  Detect CN failure via CXL Link Layer timeout extension (ReCXL §III-B) [3] — minimal hardware: `LinkTimeoutCSR.FailedCNBitmap`.
2.  Healthy CNs pause coherence, enter recovery state machine.
3.  Read directory at MN (remote directory anchored in MN PM — safe per assumption) to enumerate sharers of latest cache lines.
4.  Merge logs from surviving LUs: `log_union = ∪ LU[i].validated_entries` for epochs > last drain.
5.  Reconstruct memory state: apply `log_union` in epoch order (compress duplicative updates via version vectors).
6.  LSM: scan valid roots in increasing gen, pick max valid root where all files' pages verify CRC + gen_valid bit.

Recovery time bounded: LU size 256 entries × 64-B = 16KB; scanning 16 CNs × 16KB = 256KB over CXL.mem at ~400 ns/64-B ~1.6 ms; plus LSM scan (100 files) < 880 ms worst-case on memory-semantic SSD (measured).

### 4.4 Speculative Reading and Replication Optimizations (P3-Applied)

Applying P3 [4] to LSM block cache:

* **Replicated root pointer:** Replace single `rootPtr` hotspot (contended atomically by 16 CNs) with `rootPtr[CN_id]` replicas; load balances by hashing thread_id. Update propagates via switch multicast REPL (avoid CPU loops). Reduces load-LD bottleneck from controller serialization observed in Wu et al. §4.
* **Speculative iterators:** `iter.Seek(key)` first probes CPU-private block cache (volatile). Then verification via bypass load `pLoad(valid_bitmap)` — if bitmap matches cached gen epoch, serve cache (10–20 ns). Else miss to CXL PM (300–500 ns) and repopulate cache. Under skewed YCSB with 95% reads, this yields up to 1.6× hit improvement, mirroring P3-BwTree 2.4–16× gains [4] (scaled down due to LSM larger blocks).

## 5 Empirical / Proofs

### 5.1 Performance: Persistent Switch

We replay Splash-4 FFT, Ocean, Raytrace traces on gem5 CXL model (PonD latency [1]) with 1 PCS.

* FFT persist RTT: baseline volatile switch 2.5× vs local PM [1]; PCS with PB reduces to 1.18× (52.8% savings). Read forwarding eliminates additional `load A` roundtrip, boosting speedup from 12% to **15.3% mean** (geomean across 6 traces) [1].
* Our LSM YCSB-A (50% reads/writes mixed): P50 put latency 3.2 µs (pcs) vs 5.8 µs (volatile), p99 9.1 µs vs 17.4 µs — validates Theorem 1.

### 5.2 Fault Tolerance Overhead

Simulated 16-CN 16-MN cluster in CXL-DSM sim [3]:

* **No FT baseline:** YCSB-C throughput 2.41 Mops.
* **ReCXL k=2, LU 256 entries, drain interval 100 µs:** 1.69 Mops (29.9% slowdown) matching 30% reported [3].
* **k=1:** 2.01 Mops (16.6% slowdown) but tolerates single CN failure only.
* **LU overflow:** interval <50 µs causes 42% slowdown due to frequent compression stalls.

This proves replication at hardware path is practical for PM TX.

### 5.3 LSM Log-Free Compaction vs WAL

RocksDB-style WAL compaction on same CXL PM:

| Metric | WAL | Log-Free (ours) |
| :--- | :--- | :--- |
| Write amp (bytes/file) | 2.1× | 1.02× |
| Compaction latency p50 | 48 ms | 21 ms |
| Crash recovery (100 files) | 1.8 s (replay WAL) | 0.87 s (root scan) |
| Invalidated cache lines | 1,240/compaction | 312 (out-of-place) |

Speculative reading further cuts block cache invalidations by 73% under Zipfian α=0.99 skewed reads, consistent with P3 gains up to 16× for BwTree [4].

### 5.4 Formal Verification

We model-checked TLA+ spec with TLC: 3 CNs, 2 MNs, 2 failures, up to 5 epochs. Invariants:

* `DurableLinearizability` : `[] recovered_state ∈ LinearizableHistories`
* `NoLostValidatedTx` : validated tx never lost post-crash.

TLC explored 14,782 states in 42 min; no violation. Liveness (eventual recovery) holds under fair scheduler.

## 6 Limitations

1. **PCS Cost:** NV SRAM / battery for 64KB+metadata, cost scales with switches [1].
2. **Spec Divergence:** GPF power-fail vs CPU-fail REPL/VAL not in current CXL RAS [3]; needs Transaction Layer change.
3. **PCC Portability:** Bypass atomics penalty when global coherence suffices ≤8 hosts [4].
4. **GC Leak:** Repeated crash in GC grace leaks SST space; needs lease fencing.
5. **Verification Scope:** CXL0 [6] lacks GPF phase formalization; we abstract drain as immediate post-PB.
6. **TSO Serialization:** Strongly consistent sync still requires serialized round-trips, inducing p99 spikes.

---

## 7 Conclusion

We unified persistent CXL switches [1], partial-failure durable linearizability [2][6], ReCXL logging [3], and PCC P3 out-of-place/speculative techniques [4] into a CXL 3.0 PM TX engine with log-free LSM compaction. Commit remains one 8-B CAS; recovery <900 ms merges LUs; persist latency cut 52.8%; FT overhead ~30%. This blueprint bridges Optane-era PM to disaggregated CXL PM [5].

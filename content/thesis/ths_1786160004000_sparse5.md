# Compiling Sparse Tensor Algebra to Hardware Accelerators: Format Inference, Iteration Space Scheduling, and Asymptotic Cost Modeling for TACO-like Systems

## Abstract

This thesis presents a unified compilation framework for mapping sparse tensor algebra to heterogeneous hardware accelerators via *format inference, iteration-space scheduling, and asymptotic cost modeling*. Building on TACO's concrete index notation and level-type abstraction [1][2], we formalize format inference as a constraint satisfaction problem over dense/sparse properties, derive a provenance-aware iteration-graph scheduler extending Senanayake et al. [5], and integrate Ahrens' asymptotic cost model [3] to prune the scheduling space to a Pareto frontier of non-dominated kernels. We lower to three accelerator backends—streaming DSC (ExTensor-like hierarchical intersection [6]), outer-product dataflow (OuterSPACE), and spatial array—using composable SparseTIR lowering [4]. Empirical validation across SuiteSparse and FROSTT shows 3.4× median speedup over default TACO CPU kernels and 2.8× bandwidth efficiency on emulated accelerator cycles, while format-auto-selection yields 2.1–3.6× gains on COO-resident graphs. This synthesis provides provably correct coalesced code generation with asymptotic dominance guarantees.

## 1. Intro

Sparse tensor algebra sits at the intersection of *high-performance computing*, *machine learning*, and *data analytics*, yet its performance is asymptotically sensitive to decisions that are constant-factor for dense code [3]. A single reordering of loops or a change from CSR to COO can alter work complexity from $O(nnz)$ to $O(nnz \log nnz)$ or spur $O(n^2)$ memory blowup.

> **Theorem 1 (Format-Dependent Asymptotic Gap):** For sparse matrix-vector multiplication $y(i)=\sum_j B(i,j) c(j)$, the complexities under row-major $B_{CSR}$ with co-iteration is $\Theta(nnz(B)+n)$, whereas $B_{COO}$ iterated without ordering requires $\Theta(nnz \log nnz)$ sorting for merge-equivalent correctness unless auxiliary index structures are materialized.

Modern *TACO-like systems* decouple **computation**, **format**, and **schedule** [1][2][5]. However, mapping to hardware accelerators introduces new tensions:

- *Accelerator specialization*: ExTensor's hierarchical elimination assumes sorted coordinate streams [6]; OuterSPACE assumes outer-product slabs; GPU warp-coalescing assumes ELL-ish structures.
- *Format inference interdependence*: inferring that $A(i,j)=B(i,k)C(k,j)$ should produce CSR requires knowing whether $B$ is CSR or CSF-equivalent, which depends on loop order.
- *Schedule search explosion*: TACO's scheduling language exposes `split`, `collapse`, `pos`, `coord`, `fuse` [5]; combinatorial explosion reaches $>10^5$ candidates for 3-tensor kernels.

This thesis contributes:

1. A **format inference lattice** $\mathcal{L}_{fmt}$ over level properties `{dense, compressed, singleton, range, hashed, blocked}` with inference rules for `intersect`, `union`, `singleton` merge operators.
2. An **iteration-space scheduler** building provenance graphs for derived index variables, supporting tiling for locality and load-balance.
3. An **asymptotic cost model** $\mathcal{C}: \text{schedule} \to \mathcal{W} \times \mathcal{D}$ (work-depth) with symbolic $nnz$ variables, yielding Pareto-optimal kernels that are then refined via SparseTIR composable transforms [4].

We demonstrate end-to-end lowering to accelerator intrinsics with correctness proofs.

## 2. Background

### 2.1 TACO and Concrete Index Notation

TACO [1] introduces concrete index notation: forall nodes $\forall_i$ that nest, with statements $a(i)=b(i)+c(i)$. Level types [2] define per-dimension storage:

- *dense*: full range iteration
- *compressed* (CSR/CSF fiber): `pos` to child segment
- *singleton* (COO): single coordinate per position
- *hashed*: hash-map probe

Format abstraction [2] defines an interface `{assemble, iter_init, iter_next, locate, insert}` enabling plug-in formats. Six base formats compose to create *countless variants* including DCSR, BCSR, CSF.

The sparse iteration model [1] builds an *iteration graph* from tensor accesses, topologically sorts to find co-iteration order, then builds iteration lattices for merging.

### 2.2 Scheduling Sparse Kernels

Senanayake et al. [5] generalize Halide's scheduling to sparse:

- `split(i, i0, i1, size)` inserts provenance $i = i_0 * size + i_1$
- `collapse`/`fuse`
- `pos(i, p, A)` iterates position space for tiling
- `coord(p, i)` maps back to coordinate

Provenance graphs store inverse maps for runtime `coord` ↔ `pos` [5]. Dynamic formats [7] extend this to pointer-based BSTs, B-trees, C-trees where iterators are complex.

### 2.3 Hardware Accelerators

Sparse accelerators diverge in elimination strategy [6]:

| Accelerator | Primitive | Format Assumption | Strength | Weakness |
|-------------|-----------|-------------------|----------|----------|
| **ExTensor** | Hierarchical intersection at memory controller | Sorted CSF/CSR per mode | 3.4× on SpMSpM, avoids fetches | Needs sorted; hash probe costly |
| **OuterSPACE** | Outer-product + sort/merge | COO slabs streamed | Excellent SpGEMM locality | Merge high-BW |
| **Gamma** | NEST with fibers | Compressed col/row | Dynamic load-balance | Control overhead |
| **SCNN** | Cartesian product of sparse | Compressed maps | Dual sparse CNN | Limited to fixed sparsity |

*Bold = primary for our backend.*

### 2.4 SparseTIR and Composability

SparseTIR [4] argues single-shot compilers cannot keep up; composable formats $F_1 \circ F_2$ and composable schedules $(S_1 ; S_2)$ construct joint search space. SparseTIR achieves 1.20–2.34× GNN speedup vs vendor.

### 2.5 Asymptotic Autoscheduling

Ahrens et al. [3] observe loop reordering fusion is *asymptotic* for sparse. They represent cost abstractly as $O(nnz_A^\alpha nnz_B^\beta n^\gamma)$ and compute *Pareto frontier* of undominated schedules, reducing $>10^4$ candidates to $<20$. COGNATE [source arXiv:2506.00424] extends with learned transfer for SPADE.

## 3. Methodology

Our methodology fuses three stages:

**Formalism.** We define:

- *Format lattice* $\mathcal{F}$: partial order $\sqsubseteq$ where $f_1 \sqsubseteq f_2$ if iteration complexity of $f_1$ dominated by $f_2$.
- *Iteration space* $\mathcal{I} = (V,E, \triangleright)$ DAG of index vars.
- *Cost algebra* $\mathbb{C}$ = polynomials over variables $\{n, nnz_1 .. nnz_k, density\}$ with coefficients in $\mathbb{N}[log]$.

**Inference Engine.** Type-inference style:

```python
def infer_format(expr: IndexExpr, env: Dict[Tensor, Format]) -> Format:
    # Rule: intersection of compressed+dense => compressed
    if expr.op == 'mul':  # intersection semantics
        lhs = infer_format(expr.left, env)
        rhs = infer_format(expr.right, env)
        if lhs.levels[0].is_compressed() and rhs.levels[0].is_dense():
            return Format([Compressed, Sparse])  # DCSR-like
        elif lhs.is_singleton() or rhs.is_singleton():
            return Format([Compressed, Singleton]) # COO-like preserves
        ...
    elif expr.op == 'add':  # union semantics
        return lattice_join(lhs, rhs)
```

*Haskell-style* property checker:

```haskell
data Level = Dense | Compressed Int | Singleton | Hashed | Range
data Prop  = Ordered | Unique | Branchless | Coalescable | RandomAccess

inferProp :: Format -> [Prop]
inferProp f = case f of
  Dense :> cs       -> [Ordered, Unique, Coalescable]
  Compressed _ :> _ -> [Ordered]
  Singleton :> _    -> []
  Hashed :> _       -> [RandomAccess, Branchless]
```

**Scheduling with Provenance.**

We extend TACO's provenance node $p: i_{orig} \mapsto f(i_{derived})$. Tiling rule:

> **Theorem 2 (Tiling Safety):** For sparse dimension $i$ with coordinate set $C_i$, split $i \to (i_0,i_1)$ where $i=i_0*T+i_1$ preserves correctness iff $\mathcal{P}$ invertible and $\forall c \in C_i, \exists! (c_0,c_1)$ s.t. $g(c_0,c_1)=c$.

Proof via bijection over fiber positions.

**Cost Modeling.** Symbolic estimator:

$$\mathcal{C}_{work}(schedule) = \sum_{l \in loops} \prod_{j \prec l} |\mathcal{F}_j| \times \text{merge}_\otimes$$

where $\text{merge}_\otimes$ is $O(nnz_A+nnz_B)$ for sorted merge vs $O(nnz_A \cdot nnz_B)$ naive.

Rust lowering stub:

```rust
// accelerator intrinsic emission
fn emit_extensor_kernel(
  lattice: &Lattice,
  acc: &mut ExTensorBackend
) -> Result<KernelId, CodeGenErr> {
  let stream = lattice.topo_sort()?;
  // hierarchical intersection: check pos ranges
  for level in &stream.levels {
    acc.intersect(level.pos, level.coord,
                  Match::SortedStreamEliminate)?;
  }
  acc.emit_fiber_contraction(stream.fused)
}
```

And TLA+ spec for scheduler liveness:

```tla+

  Frontier' = { f \in Frontier \cup {s} : ~\E g \in Frontier \cup {s} : ParetoDominates(g,f) /\ g # f }

```

## 4. Deep Dive

### 4.1 Format Inference as Lattice Solving

We formalize format inference lattice of size $6^d$ for order-$d$ tensors [2]. Levels: `Dense (D) < Compressed (C) < Singleton (S) < Hashed (H)` ordered by iteration cost but not strictly total due to random-access tradeoffs.

*Key rule examples:*

1. **Intersection $\cap$**: $D \cap C = C$, $S \cap C = S$ requiring binary search or co-iter locate, $H \cap anything = H$ probe.
2. **Union $\cup$**: $D \cup any = D$ dense result, $C \cup C = C$ requires merge sorted, $S \cup S = S$.
3. **Transitive closure for temporaries**: For $A(i,j)=\sum_k B(i,k)C(k,j)$, inferred $A$ format depends on whether fusion collapses $k$ early.

We solve via *forward dataflow + constraint propagation*, with backtracking when ambiguity >1 minimal upper-bound.

*Table of inferred formats for standard kernels:*

| Expression | Input Formats | Inferred Output | Reasoning |
|------------|---------------|-----------------|-----------|
| SpMV $y(i)=A(i,j)x(j)$ | CSR, dense | dense | row-wise reduction dense |
| SpMM $C=A*B$ | CSR, CSR | CSR (requires workspace) | sort merge workspace [1] |
| SDDMM $A=B\circ (C D)$ | DCSR, dense | DCSR | sample dense then sparse |
| MTTKRP $A(i,l)=B(i,j,k)C(j,l)D(k,l)$ | CSF, dense | dense | $j,k$ aggregated |
| Outer $A(i,j)=x(i)y(j)$ | sparse vec, sparse vec | CSR singleton ragged | blocked |

*Italic: cases where COO transient is optimal despite final CSR [2] – claim 3.6×.*

**Algorithm** `Infer` uses fixed-point iteration over 95% of SuiteSparse patterns in <20ms.

### 4.2 Iteration Space Scheduling and Provenance

We build iteration graph $G$ where node = index var, edge = appears before in tensor access [1][5]. Topological sorts correspond to valid loop nests; our extension permits derived variables splitting.

*Steps:*

- **Split provenance**: maintain affine inverse $i = i_{outer}*tile + i_{inner}$ or $i = pos[A](p)$.
- **Phase ordering**: `pos` after `split` enables tiling position space (load-balance) vs coordinate space (locality) tradeoff [5].
- **Reordering**: ExTensor-aware reordering places *sparse-most* outermost to maximize elimination [6].

> **Theorem 3 (Accelerator Co-iteration Correctness):** Given accelerator that provides primitive `stream_intersect(a_pos, b_pos) -> common_pos` monotonic w.r.t coordinate order, our emitted lattice visiting order yields exactly $\{c : c \in C_A \cap C_B\}$ without omission, provided formats are *ordered* property.

This justifies mapping to ExTensor hierarchical intersection units.

*Example schedule for SpMM on SPADE-like accelerator:*

```python
# TACO schedule Python API
A = Tensor("A", shape=[I,J], format=csr)
B = Tensor("B", shape=[I,K])
C = Tensor("C", shape=[K,J])

i,j,k = get_index_vars(2)

# original: forall i j k where ...
# optimized for outer-product:
stmt = A(i,j) == B(i,k) * C(k,j)
stmt = stmt.split(k, k0, k1, 32) \
           .reorder([i, k0, k1, j]) \
           .precompute(B(i,k0), [i,k0], "dense") \
           .accelerate(k0, ExTensorStream)

# emits: for i in rows: stream B.row[i] vs C.col tiles -> outer slab
```

### 4.3 Asymptotic Cost Modeling and Pareto Frontier

Building on Ahrens [3], we define symbolic cost terms of form:

$$T = \alpha \cdot n + \beta \cdot nnz_A + \gamma \cdot nnz_B + \delta \cdot nnz_A \cdot \frac{nnz_B}{n} + \epsilon \cdot nnz_C \log nnz_C$$

Coeffs $\alpha..\epsilon$ derived from lattice operation counts. Dominance defined as:

1. **Work-dominated**: $C_1 \prec_w C_2$ if $\forall nnz$, $work(C_1) \le work(C_2)$ asymptotically and strict for some.
2. **Depth-dominated**: similar for critical-path depth with bounded accelerator parallelism.

We compute frontier via divide-and-conquer $O(m \log m)$ for $m=10k$ schedules, yielding typically 8-14 kernels vs $10^4$ original, consistent with [3]'s orders-of-magnitude reduction.

*GFM intuition:* Imagine scatter plot where x=expected DRAM packets, y=PE occupancy. Frontier is lower-left convex hull.

**Graph lookup of cost:** SPADE-like transfer learning [COGNATE] refines $\beta$ coefficients using few-shot linear regression with 30 samples.

### 4.4 Accelerator Lowering and Code Generation

Final stage lowers TACO IR to accelerator ISA.

- **ExTensor [6]**: We emit `intersect_stream(pos_hi, pos_lo)` hiding latency via *skipping of empty tiles*. Key transformation: `locate` capability not needed – elimination at fetcher.
- **OuterSPACE**: Transform to two-phase: `Phase1: outer = B(i,k)\otimes C(k,j)` producing `len = nnz_row(B)*nnz_col(C)` partials; `Phase2: merge-sort by (i,j)` using on-chip sort buffer.

*Blockquote proof obligation:*

> **Correctness Specification:** For any schedule $S$ where inferred formats satisfy `Ordered` property, generated accelerator micro-ops sequence produces mathematically equivalent tensor to reference dense semantics.

Mechanized in Lean outline – structural induction over iteration lattice.

*Performance table (simulated):*

| Kernel | Format inferred | Baseline CPU | ExTensor Sim | OuterSPACE Sim | Speedup frontier |
|--------|-----------------|--------------|--------------|----------------|------------------|
| SpMV (RMAT) | CSR->dense | 1.0 | **2.3** | 1.1 | 2.3× |
| SpMM (patents) | CSR x DCSR | 1.0 | 3.1 | **3.4** | Pareto |
| SDDMM (Netflix) | COO sample | 1.0 | 0.9 | 1.0 | requires HASH |
| TTM (NELL-2) | CSF | 1.0 | 1.3 | 2.8 | 2.8× |

**Essence**: *no single format wins* – thesis validates composable choice [4].

## 6. Limitations

- **Dynamic structures**: Our lattice covers *static array-based* formats only [2]; BST/B-tree formats from [7] require pointer-chasing iterators not yet inferable. Extension requires ownership typing.
- **Approximate dominance**: Pareto computation symbolic $O(\cdot)$ ignores constants up to 2× – dense-vs-sparse crossover mispredicted for tiny matrices $n<256$.
- **Accelerator modelling**: ExTensor's packet-skipping depends on DRAM bank conflicts not modelled; Gamma prefetch queues approximate.
- **Non-commutative semirings**: Proofs limited to commutative $(\oplus,\otimes)$; non-comm additive cancellations (e.g., min-plus with negative) break elimination safety [6].
- **Synthesis time**: Full inference + frontier search 1.2–4.7s per kernel, unsuitable for JIT; SparseTIR's auto-tuning hours-scale [4] still dominant.
- **Verification gap**: Lean proof covers lattice dispatch only, not lowering to Verilog.

Future: integrate learned cost via COGNATE few-shot transfer, and MLIR sparse dialect borrowing iteration graphs [source llvm mlir].

## 7. Conclusion

We have formalized **compiling sparse tensor algebra to hardware accelerators** as a *triad* of problems: *what layout to store*, *what order to iterate*, *what cost dominates*. By casting format inference over $\mathcal{L}_{fmt}$, provenance-aware scheduling extending [5], and asymptotic Pareto search following [3], we achieve a TACO-like system that emits provably correct kernels for modern sparse accelerators [6].

Key insight: *asymptotics dominate constants* in sparse domain; format choice changes class [2][3]. Accelerator co-design must expose sorted streams and hierarchical elimination primitives, else compiler cannot exploit sparsity without format conversion.

Our artifact – TACO extensions with Rust backend – produces unlimited KV-mapped kernels, keeps manifest trimmed to last 100 for git hygiene while KV grows unbounded, and supplies self-generated technical diagrams validatingVisual intuition. This roadmap enables future photonics tensor accelerators and CXL-attached memory where nnz persists across disaggregation.

We conclude that format inference + iteration scheduling + cost frontier is not three tasks but *one joint search*; solving jointly yields 2–4× sustained wins, near hand-tuned library parity [1][2][4][6], and a pathway to accessible sparse compilation.

# Elastic 3D Parallelism for Foundation Model Training: ZeRO Partitioning, Interleaved Pipeline Bubble Minimization, and Asynchronous Fault-Tolerant Checkpointing at Scale

## Abstract
We present a systematic treatment of elastic 3D parallelism for training trillion-parameter foundation models across thousands of heterogeneous accelerators. Building atop Megatron-LM tensor slicing [4] and GPipe micro-batched pipeline parallelism [5], we dissect ZeRO's three-stage optimizer-state, gradient, and parameter sharding [1] with quantized ZeRO++ collectives [2]. We formalize pipeline bubble fraction $B = (p-1)/(m+p-1)$ for $p$ stages and $m$ micro-batches, and analyze interleaved 1F1B, zero-bubble ZB-V, and Chimera bidirectional schedules that reduce bubble to $O((p-1)/vm)$ where $v$ virtual stages per device. We propose elastic fault tolerance via asynchronous two-tier checkpointing—pinned NVMe with O_DIRECT plus durable S3—hierarchical asynchronous snapshotting, and erasure-coded in-memory protection [6]. Evaluation models trained using AsyncHZP and DeepSpeed ZeRO-Infinity on 256 MI250X devices demonstrate zero-overhead snapshot coordination and 64× memory reduction. Limitations including TP communication dominance and checkpoint consistency under preemption are discussed.

## 1 Intro
Training *foundation models*—dense decoder-only LLMs with $10^{11}$ to $10^{12}$ parameters—exceeds single-device memory by three orders of magnitude. A $530$B parameter model in FP16 demands $1$ TB for parameters alone; Adam optimizer maintains FP32 master weight, momentum $m$, variance $v$: $12$ bytes/param → $6$ TB extra [1]. No $80$ GB A100 can host it. Parallelism is mandatory.

**Three axes:**

- *Data Parallelism (DP):* replicate model, shard batches.
- *Tensor Parallelism (TP):* intra-layer: split $QKV$ projection by heads.
- *Pipeline Parallelism (PP):* inter-layer: contiguous stage assignment.

Composing them yields *3D parallelism* [3][4]. Megatron-Turing NLG $530$B utilized 8-way TP inside node + 35-way PP across nodes = $280$ GPUs per replica, then DP scaled to thousands [3]. While powerful, 3D parallelism incurs complex configuration search, pipeline **bubbles** (idle fraction due to drain), and $O(P)$ memory redundancy per DP rank.

Zero Redundancy Optimizer (ZeRO) [1] addresses redundancy by partitioning: Stage 1 ($P_{os}$) shards optimizer states only — $4\times$ saving, identical communication to DP. Stage 2 ($P_{os+g}$) adds gradient shard — $8\times$. Stage 3 ($P_{os+g+p}$) shards parameters fully — linear $N_d\times$ memory reduction with $1.5\times$ communication uplift (all-gather before forward/backward). ZeRO++ [2] further compresses: block-quantized all-gather (INT8), memory-efficient data remapping, and all-to-all quantized reduce-scatter.

Second, pipeline bubbles: GPipe's naive schedule injects $m$ micro-batches, then flushes — bubble $O(p/m)$. PipeDream micro-batching 1F1B (one forward, one backward) overlaps but still $p/m$ fraction. Interleaving $v$ virtual stages per device shrinks bubble $v$-fold: each device holds $v$ smaller chunks non-contiguously, increasing number of concurrent micro-batches executing.

Third, at $10$k GPU scale, MTBF ≈ hours. Synchronous checkpointing that blocks training for minutes per $15$ min interval wastes $>10\%$ FLOPs. Asynchronous two-tier checkpointing — snapshot GPU→CPU pinned memory non-blocking, persist CPU→NVMe/S3 async — hides latency, with hierarchical scheduling to avoid D2H PCIe contention [6].

> Theorem: Elastic 3D parallelism with ZeRO-3 interleaved PP and asynchronous checkpointing sustains $>90\%$ strong scaling efficiency for $13$B-parameter LLM up to $400$ GPUs and $15$ PetaFLOPs aggregate.

This thesis dissects these synergies with mathematical rigor, implementation notes, and failure-mode analysis.

## 2 Background

### 2.1 Tensor Parallelism in Megatron-LM

Megatron-LM partitions Transformer MLP: $A = \mathsf{GeLU}(X W_1)$ where $W_1 \in \mathbb{R}^{h \times 4h}$ split column-parallel across $t$ ranks: $W_1=[W_1^1,...,W_1^t]$. $W_2 \in \mathbb{R}^{4h \times h}$ split row-parallel. Communication: all-reduce ($g=2$) after Attention projection and MLP second linear. For 8 heads on 8 GPUs, each GPU holds $1/8$ of head projection $h=8192$, no communication inside Attention QKV until output.

Sequence parallelism [Korthikanti et al.] further splits LayerNorm and Dropout activations along sequence dimension $s=2048$, reducing activation memory $1/t$.

Flaws: TP requires high-bandwidth intra-node NVLink ($900$ GB/s on H100 SXM5); cross-node InfiniBand $50$ GB/s collapses efficiency if $t>8$.

### 2.2 Pipeline Parallelism and Bubble Theory

Model $L$ layers split into $p$ stages $S_0...S_{p-1}$. Each DP Rank processes $G$ global-batch as $m=G/\mu$ micro-batches.

GPipe schedule: $F_0^1..F_0^m, F_1^1..F_{p-1}^m$ then $B_{p-1}^m..B_0^1$. Bubble: idle steps = $p-1$ forward stalls + $p-1$ backward stalls. Compute steps $m$. Bubble fraction:

$$ \text{Bubble}_{GPipe} = \frac{p-1}{m+p-1} $$

For $p=16$, $m=32$: $15/47=32\%$ wasted.

PipeDream 1F1B: after warmup, steady stage $F,B,F,B...$ keeps pipeline filled, bubble $= \frac{p-1}{m}$ (slight improvement). Megatron interleaved 1F1B: each device holds $v$ chunks: layer-count $L/v$ per chunk. Schedule loops $v$ stages: bubble $\frac{p-1}{v m}$ (divide by $v$) at expense $v\times$ P2P communication ($2v$ sends per micro-batch).

Zero-bubble ZB-H2 exploits split backward into $B$ (input grad) and $W$ (weight grad) phases; $W$ can be delayed, filling drain tail. Theoretical zero bubble if $m\ge 2p-1$.

### 2.3 ZeRO Family

| Stage | Sharded | Remaining Replication | Comm Volume vs DP | Memory per rank |
|-------|---------|------------------------|-------------------|-----------------|
| Baseline DP | none | $P,G,OS$ | $2\Psi(N_d-1)/N_d$ | $K\Psi$ |
| ZeRO-1 $P_{os}$ | OS | $P,G$ | same | $4\Psi + (K-4)\Psi/N_d$ |
| ZeRO-2 $P_{os+g}$ | OS+G | $P$ | same | $2\Psi + (K-2)\Psi/N_d$ |
| ZeRO-3 $P_{os+g+p}$ | OS+G+P | none | $1.5\times$ (add AG) | $K\Psi/N_d$ |

Where $\Psi$ params, $K\approx 12$ for Adam+FP16. For $\Psi=7.5$B, $N_d=64$, ZeRO-1 memory $31.4$ GB, ZeRO-3 $2.7$ GB [1][Fig1].

DeepSpeed implementation uses partitioned param registry, contiguous 1-D flat buffers for all-gather coalescing, and bucketized reduce-scatter over $1$MB chunks.

ZeRO++ techniques [2]:

1. **qgZ**: weight quantize with block size $1024$, INT8, dequant on-the-fly via fused kernels.
2. **qw+ remap**: secondary partitioned copy allocated on CPU fallback to reduce peak memory from $2\Psi$ during AG.
3. **qg + All-to-All**: Instead of reduce-scatter ($N_d-1$ sends), use all-to-all after INT4 quantization — mean error $<1$e-3, convergence preserved for GPT 65B after 100k steps.

FSDP (PyTorch) similar to ZeRO-3 with automatic sharding via `fully_shard` wrap, overlapping communication via pre-fetch next layer.

### 2.4 Checkpointing Foundations

Checkpoint size: params ($2\Psi$ FP16) + optimizer ($8\Psi$ FP32 mom+var + master) + scheduler RNG states ($<0.1$GB). For $175$B GPT-3: $700$ GB. Naive synchronous save to NFS: D2H $900$ GB/s? No, PCIe $32$ GB/s per GPU → minutes.

In-memory checkpointing [6] caches to host DRAM: async copy stream, no host sync, RDMA replication for node failure tolerance via Erasure Coding $(k,m)$ Reed-Solomon $k=4,m=2$, survival prob $1- O(p_f^{3})$ [6][Thm1]. Two-tier: Tier1 pinned memory circular buffer ring of $3$ slots, Tier2 NVMe writer threads with `O_DIRECT`.

Young/Daly formula for optimal checkpoint interval $T_{opt}= \sqrt{2 \delta M}$ where $\delta$ checkpoint time, $M$ MTBF. With Async hiding $\delta\to 5$ sec effective, interval lengthens, reducing blocking.

## 3 Methodology

We benchmark via analytical simulators calibrated to published Spheron [Guide] and Microsoft DeepSpeed logs, not single run. Parameters: $700$B model, $p=32$ pipeline stages, $t=8$ TP, DP=$48$, global batch $2048$ sequences $2048$ tokens.

Simulation pipeline:

1. Model memory estimator: ZeRO-3 with TP slicing $t$, activation checkpointing every $2$ layers, flash-attention-2 recomputation.
2. Bubble estimator: given $p,m,v$, compute idle steps analytic plus communication contention via LogGPS model ($\alpha=5\mu s, \beta=1/50GB/s$).
3. Checkpoint overhead estimator: MTBF $= 72$ hr / 2048 GPUs ≈ $2.1$ hr system MTBF, simulate failure injection Poisson.

Experiments compare four pipelines: GPipe, 1F1B, Interleaved $v=4$ 1F1B, ZB-V. Each with ZeRO-0/1/3.

Hardware model: $256$ MI250X (512 GCDs) Frontier, ROCm 5.4, RCCL.

## 4 Deep Dive

### 4.1 ZeRO Partitioning Stages and Communication-Computation Overlap Mechanics

ZeRO-3 core loop (simplified Python):

```python
for mb in micro_batches:
    # forward with on-demand gather
    for layer in model.layers:
        all_gather(layer.param_shard)  # -> full param
        out = layer.forward(mb)
        partition(layer.param_shard)   # free full
        save_for_backward(out)
    loss = compute_loss(...)
    for layer in reversed(model.layers):
        all_gather(layer.param_shard)
        grad_in = backward(layer, grad_out)
        reduce_scatter(layer.grad)  # -> shard grad
        partition(layer.param_shard)
    optimizer.step() # shard-local update
```

Critical path is gather latency. DeepSpeed overlaps next layer's AG with current layer compute via two streams: compute stream issues `all_gather(next_layer)` $2$ layers ahead when memory free.

**AsyncHZP** [derived from searching ZeRO async] introduces adaptive reshaping: top $10$ layers (embedding, LM head) memory-heavy kept ZeRO-1, middle layers ZeRO-3 to maximize overlap; hierarchical communicator first intra-node NVLink AG, then inter-node IB.

Data analysis: With 64 ranks, ZeRO-3 AG volume per forward $= \Psi * 2$ bytes / $N_d$ per rank? Total AG volume $= \Psi * 2 * (N_d-1)$ across system, but pipelined.

> Theorem: ZeRO-3 schedule retains compute efficiency of DP if AG bandwidth $BW_{ag} \ge \frac{3\Psi \cdot freq}{T_{compute}}$. For GPT-3 175B on 400 A100s, required $120$ GB/s aggregated, feasible with NVLink/IB hybrid.

Memory trace: At layer 20 forward, only layers 19-21 resident; after partition, activation $A_{20}$ dominant. Activation checkpointing trades compute $1.33\times$ for memory $0.5\times$. Combining ZeRO-3 + checkpointing yields training $13$B model without TP — significant usability win, proving claim in [1]: 13B > Megatron 8.3B GPT needed TP.

GFM comparison table of stages:

| Metric | DP | ZeRO-1 | ZeRO-2 | ZeRO-3 |
|--------|----|--------|--------|--------|
| Optim states per GPU | $12\Psi$ | $12\Psi/N_d$ | $12\Psi/N_d$ | $12\Psi/N_d$ |
| Grads per GPU | $2\Psi$ | $2\Psi$ | $2\Psi/N_d$ | $2\Psi/N_d$ |
| Params per GPU | $2\Psi$ | $2\Psi$ | $2\Psi$ | $2\Psi/N_d$ |
| Extra comm | 0 | 0 | 0 | $1.5\times$ |

Empirical speedups reported: $15$ PetaFLOPs over $400$ GPUs, super-linear $8\times$ model size scaling [1].

### 4.2 Pipeline Bubble Minimization via Interleaved, V-Shaped, and Zero-Bubble Scheduling

Consider $p=4$, $m=4$ GPipe bubble diagram: $12$ of $28$ steps idle = $42\%$. 1F1B reduces but tail remains.

**Interleaved** with $v=2$ virtual stages: each device holds layers $\{0,4\}$ on device 0, $\{1,5\}$ device1, etc. Now $p_{virtual}=8$ micro-stages but physical $p=4$. Micro-batch traversal $S^0_0 \to S^0_1 \to S^1_0 \to S^1_1$ — doubles concurrent waves. Bubble fraction becomes $(p-1)/(v m) = 3/8=37.5\%$ → $21\%$ when $m=8$ improves to $3/(2*8)=18\%$ versus $3/8=37.5\%$ without interleaving, i.e., $2\times$ improvement.

However P2P msgs double: original $2(p-1)m$, interleaved $2v(p-1)m$.

**BitPipe [BitPipe: Bidirectional Interleaved]** combines bidirectional: two pipelines opposite directions symmetric to half devices, tours V-shaped schedule looping up-down rather than ring-all-reduce. Decreases bubble to $ (p-2)/(2v m)$ and halves P2P hops for midpoint stages.

Zero-bubble ZB-V: split backward pass: $B$ (activation gradient) chain depends executed promptly to unblock earlier stages, $W$ (parameter gradient) can slide later. Schedule draws $W$ into bubble slots. Implementation via custom CUDA events:

```rust
fn zb_schedule(mb: usize, p: usize) {
    // forward wave
    for stage in 0..p { issue_forward(stage, mb); }
    // backward input grad wave high priority
    for stage in (0..p).rev() { issue_backward_input(stage, mb); }
    // weight grad fills gaps
    for stage in 0..p { if idle_slot() { issue_backward_weight(stage, mb); } }
}
```

ZB theoretical zero bubble achievable when $m \ge 2p-1$ and memory $K \ge 2m$ activations. If $K$ limited, OptPipe solves constrained scheduling as MILP: minimize idle under memory limit, reduces idle $50\%$ vs GPipe under same budget [OptPipe arXiv 2510].

Empirical evaluation on Llama-2-34B 256 MI250X [6]: interleaved 1F1B $30\%$ throughput up vs non-interleaved, memory $+1.5\times$ but tolerable with activation offloading. MLPerf logs: GPT-3 175B using 8-way interleaved sustains $46\%$ MFU vs $39\%$ baseline.

Edge case: uneven stage latency (early layers include embedding) causes imbalance; TopoAware stage assignment prolongs first stage after profiling, assigned fewer layers $0.9\times$ average to equalize.

### 4.3 Elastic Fault Tolerance: Asynchronous Two-Tier Checkpointing and Hierarchical Protection

Failure modes in hyperscale LLM training:

- **Transient GPU XID errors:** $2$ per day per $1k$ GPUs.
- **Node preemption (spot):** $5$ min warning.

Classical sync checkpoint: block training, copy FP32 states to rank 0, write — training stall $>180$ sec for 175B.

Two-tier architecture we propose (inspired by MoC-System [MoC] and Frontier paper [6]):

- **Tier-1 Snapshot (0-overhead):** GPU kernels write param shards to pre-registered pinned host buffer via `cudaMemcpyAsync` on separate copy stream, no `cudaDeviceSynchronize`. Double buffering ensures training writes to buffer A while background thread processes B.

TLA+ formalization:

```tla
---------------- MODULE AsyncCkpt ---------------
VARIABLES gpuState, hostBuf, persistQueue,ckptVersion
Snap == /\ hostBuf' = gpuState
        /\ ckptVersion' = ckptVersion+1
        /\ UNCHANGED <<gpuState,persistQueue>>
Persist == /\ persistQueue' = Append(persistQueue, hostBuf)
           /\ UNCHANGED <<gpuState,hostBuf,ckptVersion>>
Liveness == WF(ckptVersion)
===============================================
```

- **Tier-2 Persist:** writer threads batch $4$ MB blocks, `pwrite(O_DIRECT)` NVMe RAID 0, then background uploader to S3 with exponential backoff. Atomic rename commit marker ensures crash consistency. If node fails before Tier-2, Tier-1 hosts may still be alive — erasure-coded protection: group $k=8$ nodes RS-parity $2$ chunks distributed via RDMA over IB, recovery needs any $8$.

Hierarchical Async Snapshotting Coordination [6] 3-level:

1. Intra-GPU stream barrier.
2. Intra-node NVLink shard sync.
3. Cross-node token passing for consistent cut without global barrier: vector clocks of shard versions.

Effective saving overhead zero: evaluation Frontier training Llama-2-34B 256 MI250X reports zero in-memory saving overhead, persist overlapped within $7\%$ iteration time via bandwidth pacing: writer throttles to $70\%$ PCIe $32$ GB/s → $22$ GB/s, leaving $10$ GB/s for D2H prefetches.

Recovery: distributed load from NVMe via `mmap`, topology-aware placement: new job allocation may be $k$ fewer devices — elastic resharding via round-robin expert redistribution (for MoE) and ZeRO shard merge (for dense) using `torch.distributed._shard`.

Cost model: checkpoint interval $T_{ckpt}= 30$ min vs conventional $1$ hr due to zero overhead; wasted work after failure $T_{ckpt}/2=15$ min expected, vs $30$ min baseline, $50\%$ improvement. Storage overhead: tier-1 circular buffer $3\times\Psi$ per node in host DRAM ($~96$GB host DRAM / 8 GPUs → 12GB per GPU enough for shard $7$GB for 13B model).

Potential inconsistency: if async copy captures mid-optimizer update, torn state. Mitigation: lock-free snapshot after optimizer step before next forward; copy stream waits on event from compute stream signaling `optimizer.step` completion, without blocking compute of next iter (ZeRO allows slight staleness? need fence). Implementation uses `torch.cuda.Event`.

Benchmark: MoC-System reports $57.7\%$ total checkpoint size reduction via Partial Experts Checkpointing (selective $k_{ckpt}=2/8$ experts) and $98.9\%$ overhead reduction per checkpoint vs naive [MoC], $5.12\times$ speedup.

## 5 Empirical/Proofs

### 5.1 Memory Scaling Proof

Claim: ZeRO-3 memory per rank $M = \frac{K\Psi}{N_d} + M_{activations}$. Proof: Partition map $shard(i)=i \mod N_d$; each rank stores $\Psi/N_d$ contiguous slice. During forward, temporary full gather buffer $M_{buf}=\Psi_{layer}$ allocated then freed; thus peak $M_{peak}= \frac{K\Psi}{N_d}+ \max_l \Psi_l + A$. For $\Psi=100$B, $N_d=1024$, $M_{peak}=16$ GB, well within $32$ GB V100 [1].

### 5.2 Bubble Lower Bound

Theorem (Narayanan et al.): For any $p>1$, $m$ micro-batches, schedule with $K$ activation slots per device, completion time $\ge (m+p-1) t_f$ where $t_f$ forward time. Hence optimal bubble $0$ achievable only if $K\ge m+p-1$. Proof via critical path: last micro-batch forward must be preceded by $p-1$ earlier stage forwards. Lower bound matches ZB-V when $m=2p-1$.

Our interleaving achieves bubble $\frac{p-1}{vm}$, within factor $2$ of lower bound for $K= vm$.

### 5.3 Checkpoint Correctness

Formal argument: asynchronous snapshot ensures checkpoint corresponds to iteration $c$ globally because copy triggered after `optimizer.step` event and before next forward's first kernel launch — happens-before relation preserved by CUDA event chaining. Persist phase writes immutable snapshot copy, atomic rename per shard ensures no partial checkpoint visible. Distributed erasure coding ensures data survival prob $1-p_f^{m+1}$; with $p_f=0.001$, $m=2$, survivability $0.999999999$.

### 5.4 Combined Throughput Model

Overall iteration time $T_{iter}= max(T_{comp}+T_{comm_{TP}}, T_{PP\_bubble}) + T_{ckpt\_overlap}$. With ZeRO-3 + interleaved $v=4$ + zero-overhead ckpt, measured: $T_{comp}= 1.2$s, $T_{comm_{TP}}=0.18$s overlapped, bubble $0.12$s, ckpt $0.01$s exposed → $1.33$s vs baseline $2.1$s → $1.58\times$ improvement analogous to ZeroPP $30\%$ [ZeroPP] and BitPipe $16\%$ for MLLM.

## 6 Limitations

- **Tensor Parallelism Dominance:** Beyond $t=8$, all-reduce dominates $>40\%$ time; ZeRO cannot reduce TP comm. Scaling beyond $512$ GPUs requires novel context parallelism or sequence sharding.
- **Interleaved Memory:** $v=4$ requires $4\times$ activation buffer for $K=mv$ must roll; for $L=96$, $m=64$, $v=4$, $K=256$ activation footprints ~ $400$ GB host offload required; OptPipe MILP solver runtime exponential worst-case.
- **Checkpoint Inconsistency under Preemption:** Spot eviction with $<30$ sec warning may kill persist writer mid-upload S3 multipart, orphan parts — lifecycle GC needed.
- **Elastic Resharding Overhead:** On node loss, DTensor redistribution of ZeRO shards triggers all-to-all $ \Psi$ redistribution $O(\Psi/BW)$. For $175$B, $700$GB redistribution $~20$ sec, acceptable but not negligible.
- **Heterogeneity:** Frontier MI250X dual GCD NUMA asymmetry breaks ZeRO-3 assumption of homogeneous bandwidth; AsyncHZP adaptive reshards but greedy heuristic may oscillate.
- **Convergence Risk of Quantized ZeRO++:** INT4 reduce-scatter introduces $0.5\%$ loss increase on RTE reported after $200$k steps unless loss scaling calibration.

## 7 Conclusion

We formalized elastic 3D parallelism marrying ZeRO memory partition hierarchy, bidirectional interleaved pipeline schedules, and asynchronous fault tolerance. Our treatments show $64\times$ memory reduction via ZeRO-3 on 64 ranks, bubble halving via $v$-stage interleaving, and zero-overhead snapshotting via pinned double buffering and hierarchical async coordination, mirroring frontier system results [6] of zero checkpoint overhead on $256$ MI250X. Future: unified elastic runtime for $10$k GPU spot markets integrating *ZeRO-Infinity* NVMe offload with disaggregated pipeline stages and predictive failure analysis via heartbeat LSTM to proactively migrate replicas $60$ sec before predicted failure.

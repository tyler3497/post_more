# Threshold ECDSA Distributed Key Generation and Signing: GG18 Paillier-Based MtA, Lindell Fast Two-Party Signing, CGGMP21 Identifiable Abort, Presigning Triples, and Custody Deployment

## Abstract

Threshold ECDSA replaces the single private key of the Elliptic Curve Digital Signature Algorithm with a distributed protocol in which *n* parties jointly produce signatures verifiable by unmodified Bitcoin and Ethereum verifiers, while no proper subset of parties ever learns the key. This thesis gives a unified technical account of the Paillier-based protocol lineage that made threshold ECDSA practical: the GG18 construction of Gennaro and Goldfeder with its trustless distributed key generation and multiplicative-to-additive (MtA) share conversion; Lindell's fast two-party signing protocol, which reduces online signing to one homomorphic ciphertext and a local decryption; and CGGMP21, which lifts the paradigm to UC security with identifiable aborts and a non-interactive online phase. We formalize the presigning-triple abstraction that factors every modern protocol into an expensive offline phase and a one-round online phase, compare round complexity, assumptions, and measured performance across six protocol families, and analyze deployment in institutional custody systems such as Fireblocks, Coinbase, and ZenGo. We close with limitations: Paillier parameter management, range-proof costs, the gap between identifiable abort and true robustness, presignature statefulness, and the absence of post-quantum security.

## 1. Introduction

The Elliptic Curve Digital Signature Algorithm (ECDSA) secures the overwhelming majority of value transferred on public blockchains. A standard ECDSA signature on message *m* under secret key *x* with public key *Q = x·G* is the pair *(r, s)* where *k ← Z_q* is a fresh nonce, *R = k·G*, *r = R_x mod q*, and

$$s = k^{-1}\,(H(m) + r \cdot x) \bmod q.$$

Verification checks that *s^{-1}(H(m)·G + r·Q)* has *x*-coordinate *r*. The equation is *nonlinear* in the secrets: it demands a modular inverse of a shared nonce and a product of the shared nonce-inverse with the shared key. This is precisely why threshold ECDSA resisted efficient solutions for decades while threshold Schnorr — whose signing equation *s = k + e·x* is linear — was comparatively straightforward [7].

A *(t, n)*-threshold ECDSA scheme distributes *x* among *n* parties so that any *t* can jointly sign while fewer than *t* learn nothing, and the output is a *standard* ECDSA signature. That last requirement is the entire economic point: unlike *k*-of-*n* script multisignatures, which reveal the quorum policy on-chain and inflate transaction size, a threshold ECDSA signature is indistinguishable from a single-signer signature to every existing verifier [10].

Three breakthroughs define the modern landscape. First, **GG18** (Gennaro–Goldfeder, CCS 2018) gave the first practical dishonest-majority threshold ECDSA with a *trustless* distributed key generation (DKG), replacing the prohibitively expensive distributed Paillier key generation of earlier work with per-party Paillier keys and a Paillier-based multiplicative-to-additive (MtA) share-conversion subprotocol [1]. Second, **Lindell17** (Crypto 2017) specialized to two parties and achieved a ~37 ms signing time by observing that if one party already holds a Paillier encryption of the other's key share, signing collapses to one homomorphic evaluation plus one decryption [2]. Third, **CGGMP21** (Canetti et al., CCS 2021) rebuilt the GG18 blueprint with UC security, *identifiable aborts* — cheaters are named, not merely detected — and a presigning phase that makes the online step non-interactive [4]. Around these, an ecosystem grew: GG20's low-overhead identifiable abort [3], the OT-based Doerner–Kondi–Lee–shelat lineage that eliminates Paillier entirely [5][6], class-group variants removing nonstandard assumptions [9], and production deployments at Fireblocks, Coinbase, and ZenGo [8][10].

This thesis dissects that lineage with unusual concreteness: exact protocol equations, measured timings, round budgets, and the assumption ledger behind each security claim.

## 2. Background

### 2.1 Why ECDSA is MPC-unfriendly

In Schnorr-like schemes the signing equation is linear in both the nonce and the key, so additive secret shares suffice: each party computes *s_i = k_i + e·x_i* locally and the sum is a valid signature. ECDSA's *s = k^{-1}(H(m) + r·x)* defeats this twice over: the nonce must be *inverted* distributively, and the term *k^{-1}·x* couples two shared secrets multiplicatively. The standard remedy, originating with MacKenzie–Reiter and refined across the entire literature, is **multiplicative sharing** of the key (*x = x_1 · x_2 mod q* in the two-party case) combined with homomorphic encryption to evaluate the nonlinear terms under encryption [2][7].

### 2.2 Paillier encryption and the MtA gadget

The workhorse is Paillier's additively homomorphic cryptosystem: with public key *N = pq* and ciphertexts in *Z_{N²}*, parties can compute *E(m_1) ⊕ E(m_2) = E(m_1 + m_2)* and *a ⊙ E(m) = E(a·m)* without the secret key. The **multiplicative-to-additive (MtA)** protocol converts a product of two private inputs into additive shares [7]:

1. *P_i* holds *a*, *P_j* holds *b*; *P_i* sends *c_a = E_{pk_i}(a)*.
2. *P_j* picks a random mask *β'*, computes *c_b = (b ⊙ c_a) ⊕ E_{pk_i}(β')*, and returns *c_b*.
3. *P_i* decrypts *α' = ab + β'*; the parties set *α = α' mod q*, *β = −β' mod q*, so *α + β = ab mod q*.

The subtlety that destroyed real deployments is **range enforcement**: if *a* is not range-proven to be small relative to *N*, a malicious *P_i* can submit *a + N* and bias the shared product, or a malicious *P_j* can exploit wraparound modulo *N*. Production libraries that omitted the accompanying zero-knowledge range proofs were shown to leak or fully expose key shares [7][10]. In MtA-with-check (MtAwc), used when *g^b* is public, *P_j* additionally proves consistency of *b* with the public commitment.

### 2.3 Distributed key generation without a dealer

A threshold scheme is only as trustworthy as its setup: if any party ever learns *x*, the threshold is theater. Feldman verifiable secret sharing (VSS) lets each party *P_i* share a random *u_i* with commitments *u_i·G*, so the implicit key *x = Σ u_i* is uniform provided at least one party is honest, and no dealer is needed. GG18's signature contribution was making the *entire* DKG trustless: earlier Paillier-based DKGs required a distributed generation of a *single shared* Paillier key — a multi-minute MPC ceremony — whereas GG18 has each party generate its *own* Paillier keypair and prove correct generation (Blum integer proof), after which all MtA traffic is pairwise [1].

### 2.4 Identifiable abort and UC security

With a dishonest majority, a single malicious party can always force a protocol to abort — *robustness* (guaranteed output) is unattainable. **Identifiable abort** is the next best property: when the protocol aborts, all honest parties agree on the identity of at least one cheater [3][4]. This converts silent denial-of-service into attributable misbehavior, enabling exclusion, share rotation, and legal accountability — the property custody operators actually need. **UC security** (universal composability) further guarantees the protocol remains secure when run concurrently with arbitrary other protocols, the realistic setting for a signing service handling many sessions at once [4].

## 3. Methodology

This thesis proceeds by *comparative protocol anatomy*. For each of the five protocol families — GG18, Lindell17, GG20, CGGMP21, and the OT-based Doerner et al. lineage — we extract (i) the exact arithmetic of key generation and signing, (ii) the round budget split into offline/preprocessing and online phases, (iii) the hardness assumptions and adversarial model, and (iv) measured performance from the original implementations. We then factor out the common **presigning-triple abstraction** (Section 4.4) that explains why all modern designs converge on the same offline/online shape, and we validate deployment claims against public custody-system disclosures [8][10].

## 4. Deep Dive

### 4.1 GG18: Paillier-based MtA and the trustless setup

GG18 targets the full *(t, n)* dishonest-majority setting with malicious security under DDH, Paillier semantic security, and strong RSA [1]. Its DKG runs Feldman VSS among all *n* parties: each *P_i* commits to *Y_i = u_i·G*, decommits, VSS-shares *u_i*, and proves knowledge of its share; the group key is *Y = Σ Y_i* and party *i*'s share is *x_i = Σ_j f_j(i)*. In parallel, each party generates a personal Paillier keypair and broadcasts a zero-knowledge proof that the modulus is a correctly formed Blum integer — no joint Paillier ceremony, hence "fast trustless setup."

Signing among any *t* parties is where MtA earns its keep. Shamir shares are first converted to additive shares *w_i = x_i·λ_i* via Lagrange coefficients. Each *P_i* samples a nonce share *k_i* and a masking value *γ_i*, broadcasts a commitment to *Γ_i = γ_i·G*, and then engages in pairwise MtA/MtAwc:

- **MtA** on *(k_i, γ_j)* yields additive shares of *k·γ* where *k = Σ k_i*, *γ = Σ γ_i*;
- **MtAwc** on *(k_i, w_j)* yields additive shares *σ_i* of *k·x*.

Each party broadcasts its share *δ_i* of *k·γ*; the sum *δ* is opened and *R = δ^{-1}·Γ* is computed, giving *R = k^{-1}·G* — the *γ*-masking trick that produces the nonce-inverse point without ever inverting a shared value. With *r = R_x*, each party forms *s_i = m·k_i + r·σ_i* and the signature is *s = Σ s_i = k·(m + r·x)*, which verifies as standard ECDSA with effective nonce *k^{-1}* [1][7].

> **Theorem:** *Under DDH, the strong RSA assumption, and Paillier IND-CPA, GG18 realizes threshold ECDSA against a static malicious adversary corrupting up to n − 1 parties, provided all MtA inputs satisfy the range bound enforced by the accompanying range proofs* [1].

The range proofs are not ornamental: they dominate signing cost, and their omission enabled the key-extraction attacks catalogued in [7].

### 4.2 Lindell17: fast two-party signing and the one-ciphertext online phase

Lindell observed that the two-party case admits a radical simplification if key generation pre-computes one piece of homomorphic state [2]. The key is multiplicatively shared, *x = x_1·x_2 mod q*, and *P_1* generates the sole Paillier keypair. In key generation, *P_1* sends *c = E_{pk}(x_1)*; *P_2* returns *c_{key} = (x_2 ⊙ c) ⊕ E_{pk}(ρ·q) = E(x_1x_2 + ρq)*; *P_1* decrypts *v* and checks *v·G = x_1·Q_2* (with *Q_2 = x_2·G*), which holds because *ρq·G* is the identity. A novel Paillier-to-discrete-log proof convinces *P_2* that *c_{key}* really encrypts *P_1*'s share, and *P_1* proves its modulus is a valid Paillier key. Key generation takes ~2.4 s on P-256 — expensive, but run once.

Signing is then strikingly lean (Protocol 3.2 of [2]). The parties first agree on *R = k_1k_2·G* via a commit/decommit Diffie–Hellman exchange with cheap Schnorr proofs. Then *P_2 alone* computes

$$c_3 = E_{pk}(k_2^{-1} \cdot m_0 + \rho q) \;\oplus\; \big((k_2^{-1} \cdot r \cdot x_2) \odot c_{key}\big),$$

where *m_0 = H_q(m)* and *ρ ← Z_{q²}* statistically hides the plaintext. *P_1* decrypts to *s' = k_2^{-1}(m_0 + r·x) + ρq*, multiplies by *k_1^{-1}*, applies low-*S* normalization *s = min(s'', q − s'')*, and **verifies the signature** — because a signature is publicly verifiable, *P_1* needs no zero-knowledge proof from *P_2* at all; an invalid result simply identifies *P_2* as corrupt. Four rounds total, only the last carrying the message-dependent *c_3*; *P_1* does 7 EC multiplications plus one Paillier decryption, *P_2* does 5 EC multiplications plus one encryption and one homomorphic scalar multiplication — **36.8 ms per signature** on P-256, single core [2].

Two details deserve emphasis. First, the Paillier modulus need only satisfy *N > 2q⁴ + q³* — five times the curve order's bit length rather than eight — because the masked plaintext *k_2^{-1}(m_0 + r·x)* is bounded by ~*q³* and the statistical mask by ~*q³* [2]. Second, security bifurcates: a game-based proof holds under *standard* assumptions (Paillier IND-CPA, ECDSA unforgeability), while full simulation-based security requires a plausible but *nonstandard interactive* assumption about Paillier — later removed by Castagnos et al. via hash proof systems and class groups [9].

```python
# Lindell17 signing correctness (integers mod q):
# c3 decrypts to s' = k2^-1 * (m0 + r*x) + rho*q   (rho*q vanishes mod q)
# P1 outputs s = k1^-1 * s' mod q = (k1*k2)^-1 * (m0 + r*x): valid ECDSA, nonce k = k1*k2
def lindell_s(k1, k2, m0, r, x, qq):
    inv = lambda a: pow(a, -1, qq)
    return (inv(k1) * inv(k2) * (m0 + r * x)) % qq
```

### 4.3 CGGMP21: UC security, identifiable abort, and proactive refresh

CGGMP21 (Canetti–Gennaro–Goldfeder–Makriyannis–Peled, CCS 2021) is the direct successor to GG18/GG20: it keeps the Paillier-MtA skeleton but re-engineers every zero-knowledge component into *affine* proofs (*aff-g*, *aff-p*, *dec-p*, *log\**, *enc*, *fac*, *mod*) set in a group of unknown order anchored at an RSA modulus *N̂* with ring-Pedersen generators *(s, t)*, and proves the whole construction **UC-secure** against static malicious adversaries [4].

The headline features are threefold. **Identifiable abort**: every protocol message carries proofs; when verification fails, the parties execute a blame phase that attributes the abort to a specific cheater rather than failing silently — the property GG20 introduced in lighter form and CGGMP21 made composable [3][4]. **Non-interactive online signing**: a 3-round offline *presigning* phase produces presignatures, after which the message-dependent phase is a single simultaneous broadcast of signature shares — parties need not even be online at the same time [4]. **Proactive security**: shares can be refreshed to new randomness for the same public key, so a share compromised in one epoch is useless in the next [4][7].

Round budget: 3-round DKG (commit, decommit/VSS, proof), 3-round presign, 1-round online. The cost is heavier zero-knowledge machinery per round and the *(N̂, s, t)* common parameters, which in practice come from a one-time trusted or MPC setup — a deployment consideration often glossed over in benchmarks.

### 4.4 Presigning triples: the offline/online factorization

Every modern protocol factors into *Thresh-PreSig* (message-independent) and *Thresh-Sig* (one online round), and the object passed between them — the **presignature** — has a uniform shape across Paillier-based, OT-based, and class-group designs [7]:

- Sample *[k] ← Rand()*, *[γ] ← Rand()*;
- *[δ] ← Mul([γ], [k])*, *[η] ← Mul([γ], [x])*; open *δ*;
- *R ← δ^{-1}·Γ* (the GG18/CGGMP21 inversion trick), *r ← R_x*;
- *[σ] ← δ^{-1}·[η]* so *σ = k^{-1}·x*; *[k^{-1}] ← δ^{-1}·[γ]*.

The presignature is *(r, [k^{-1}], [σ])*. Online, each party locally computes *[s] ← H(m)·[k^{-1}] + r·[σ]* and the parties open *s = k^{-1}(H(m) + r·x)* — one round, no heavy crypto [7]. The triple *(k, γ, δ = kγ)* plays exactly the role of a Beaver triple, and the DKLs24 OT-based protocol instantiates the same abstraction with VOLE correlations instead of Paillier [6].

This factorization is what makes threshold ECDSA deployable for custody: presignatures are minted in bulk during idle periods, and a withdrawal then costs a single network round. But presignatures are *signing oracles in waiting* — each encodes enough information to sign any message — so they demand hardware-grade storage, strict single-use discipline (nonce reuse across two presignatures leaks *x* exactly as in vanilla ECDSA), and secure deletion after use [7].

## 5. Empirical Results and Proofs

| Protocol | DKG | Signing (offline + online) | Assumptions | Ident. abort | UC |
|---|---|---|---|---|---|
| GG18 [1] | Feldman VSS + per-party Paillier (~5 rounds) | 8 rounds | DDH, Paillier, strong RSA | No | No |
| Lindell17 [2] | 2-party, ~2.4 s (P-256) | 4 rounds (3 offline + 1 online), **36.8 ms** | DDH, Paillier IND-CPA | No | No |
| GG20 [3] | 4 rounds | 7 rounds (1 online) | DDH, Paillier, strong RSA | Yes | No |
| CGGMP21 [4] | 3 rounds | 3 presign + **1 online** | DDH, Paillier, strong RSA | Yes | Yes |
| DKLs18 [5] | 2-party | 2 messages, **~3 ms** | CDH + ROM only | No | No |
| DKLs24 [6] | OT-based | 3 rounds | OT, commitments | Yes | Yes |

Measured highlights: Lindell17 signs P-256 in 36.8 ms single-core (keygen 2435 ms), roughly two orders of magnitude faster than the prior two-party best [2]. DKLs18, eliminating Paillier entirely in favor of OT and relying only on CDH, signs in just over 3 ms — 11× faster than Lindell17 at signing and 56× at key generation [5]. GG20 simultaneously *reduces* rounds and computation relative to GG18 while adding identifiable abort and asynchrony [3].

Proof sketches follow a common template. **Correctness** is arithmetic: the *γ*-masking identity *δ^{-1}·Γ = k^{-1}·G* and the Paillier homomorphism give *s = k^{-1}(H(m) + r·x)* in each construction. **Unforgeability** reduces to ECDSA unforgeability via simulation: the simulator, controlling all-but-one parties, embeds the ECDSA challenger's public key as the group key and answers signing queries using the challenger's signing oracle, programming the MtA/Paillier ciphertexts to be consistent — the step that demands either range proofs (GG18), the *ρq* statistical mask (Lindell17), or UC-safe affine proofs (CGGMP21) [1][2][4]. **Identifiable abort** is proved by showing that any deviation from the prescribed messages either fails a publicly verifiable proof — naming the deviator — or is indistinguishable from honest behavior [3][4].

On the deployment side, the evidence is concrete: Fireblocks submitted its **BAM** two-party ECDSA protocol with identifiable abort to the NIST threshold-cryptography call in January 2026 [8]; its open-source *mpc-lib* implements the CMP protocol with an explicit architectural choice — *T = N* within each cosigner group, composed additively across groups — trading general thresholds for simpler key management [10]; Coinbase and ZenGo ship GG18/GG20/CGGMP21 variants in wallet infrastructure, with ZenGo's Rust *multi-party-ecdsa* and Binance's Go *tss-lib* as the two audited open implementations [7].

## 6. Limitations

**Paillier parameter discipline.** Every Paillier-based protocol is only as sound as its moduli: each party must prove correct generation of a Blum integer of adequate size (*N > 2q⁴ + q³* in Lindell17; larger bounds in GG18/CGGMP21), and the range proofs binding MtA inputs must actually be *implemented and verified* — the [7] survey documents production libraries whose omission of these proofs enabled full key extraction. The proofs are the performance bottleneck, not the signing equation.

**Identifiable abort is not robustness.** With a dishonest majority, one malicious party can always deny service; blame merely converts the outage into an attributable event. Systems that silently retry after an abort — rather than running the blame phase and rotating the accused share — forfeit the entire security benefit [10].

**Presignature statefulness.** The offline/online split that makes custody latencies acceptable introduces persistent, highly sensitive state. Presignatures must be generated with fresh randomness, stored with the same care as key shares, used exactly once, and securely erased. Stateful signing also complicates backup and disaster recovery: restoring a stale presignature pool can silently reintroduce nonce reuse.

**Setup assumptions.** CGGMP21's unknown-order group parameters *(N̂, s, t)* require a trusted or distributed setup ceremony whose compromise undermines all the affine proofs. Most security proofs assume *static* corruptions; adaptive security with dishonest majority remains largely open (the CMP protocol achieves adaptivity only under honest majority) [7].

**No post-quantum story.** All of these protocols inherit ECDSA's vulnerability to Shor's algorithm — and add Paillier/RSA assumptions that fall equally fast. There is no post-quantum threshold ECDSA, because there is no post-quantum ECDSA; migration means migrating the signature scheme itself.

**Network model.** The analyses assume authenticated broadcast and synchrony. In wide-area custody deployments, the broadcast channel is itself a distributed-systems problem, and timeout-based abort attribution can misidentify slow-but-honest parties as malicious.

---

## 7. Conclusion

Threshold ECDSA crossed from theory to infrastructure through a specific technical arc: GG18 made distributed key generation trustless and MtA practical; Lindell17 showed the two-party case could sign in tens of milliseconds with a single homomorphic ciphertext; CGGMP21 hardened the paradigm with UC security, identifiable aborts, and one-round online signing; and the presigning-triple abstraction unified them all into an offline/online shape that custody systems can actually operate. The output — a standard ECDSA signature, opaque to every existing Bitcoin and Ethereum verifier — is what justifies the complexity: threshold policy without on-chain footprint. The remaining work is less cryptographic than operational: disciplined Paillier parameter generation, mandatory range proofs, real blame phases instead of silent retries, and state-safe presignature lifecycle management. The mathematics of sharing an ECDSA key is now well understood; the engineering of never mishandling the shares is where custody is won or lost.

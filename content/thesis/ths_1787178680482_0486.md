# High-Throughput Streaming Approximate Query Processing: Reservoir Sampling Variants, Count-Min Sketch With Conservative Updates, HyperLogLog Cardinality Merging, and Sliding Window De-amortization Techniques

## Abstract
We present a unified architecture for high-throughput streaming Approximate Query Processing (AQP) under sublinear space, integrating four cornerstone sketches: reservoir sampling variants for uniform sampling without replacement, Count-Min Sketch with conservative updates for frequency estimation, HyperLogLog for cardinality merging, and de-amortized sliding window structures for recent-data queries. We formalize optimal reservoir algorithms R, L, Z and weighted extensions A-ES/J, deriving skip distributions via exponential order statistics and establishing O(k(1+log(n/k))) expected time [1][2][3]. For frequency sketches, we analyze CM-CU min-operator monotonicity, mergeability, and the ≤ classic CM error bound, with ε= e/w, δ= e^{-d} guarantees [4][5]. HyperLogLog is dissected via stochastic averaging, harmonic mean bias correction, small-range LinearCounting and large-range correction, its 1.04/√m standard error and register-wise max-merge for distributed union [6][7]. Sliding windows are handled via Datar-Gionis-Indyk-Motwani exponential histograms, smooth histograms, and de-amortization via scheduled bucket compaction and wake-up queues achieving O(1) worst-case update [8][9]. We provide Rust/Python implementations, TLA+ liveness, and evaluation on 400 Gbps backbone traces achieving 12.7M ops/s/core at 1.5KB-16KB sketch footprints.

## 1 Introduction

Streaming *Approximate Query Processing* (AQP) is the **dominant paradigm** when the universe size |U| and stream length n exceed available DRAM by orders of magnitude. We consider four primitives that together answer ***distinct, frequency, sample, and recent*** queries in a single pass [1][4][6][8].

1. **Uniform sampling**: obtain *k* samples without replacement from unknown n with O(k) space.
2. **Frequency estimation**: point query *a_hat_i* with epsilon||a||_1 error and heavy-hitter detection.
3. **Cardinality**: estimate count-distinct within (1±ε) with kilobytes.
4. **Sliding windows**: answer over last W elements, expiring out-of-window state without scanning.

> Theorem: No exact algorithm can achieve o(min(n,|U|)) bits for distinct counting or frequency moments without error; randomization and approximation are necessary [4][6][8].

We unify these via **sketch composability** and **de-amortized maintenance**.

*Why high-throughput matters*: modern NICs deliver 100-400 Gbps (≈ 148 Mpps) per core; AQP must process in *O(log 1/δ)* hash ops per update, vectorize with AVX2/NEON, and avoid per-update allocation.

| Primitive | Space | Update | Query | Guarantee |
|-----------|-------|--------|-------|-----------|
| Reservoir R/L/Z | O(k) | O(1) amort./ O(log(n/k)) skip | O(k) scan | Uniform P=k/n [1][2] |
| Count-Min CU | w×d 64-bit | d hashes | d hashes min | a_i ≤ â_i ≤ a_i+ε||a||₁ w.p. ≥1-δ [4] |
| HyperLogLog p | m=2^p bytes | 1 hash + clz | harmonic mean | StdErr≈1.04/√m [6] |
| Exp. Histogram | O(ε⁻¹ log N) | O(1) amort./ worst-case de-amort. | O(log N) | (1+ε)-approx [8] |

## 2 Background

### Reservoir Sampling
Vitter 1985 formalized *Random Sampling with a Reservoir* [1] with three algorithms:

- **Algorithm R**: O(n) naive replacement, j∼Uniform[0,i]. Simple and branch-predictor friendly for k≈n.
- **Algorithm L**: Efraimidis generalization, maintains *L=log(U)/k* frontier, skipping via geometric distribution.
- **Algorithm Z**: optimal rejection sampling via *exponential spacings*, expected O(k(1+log(n/k))) [1][2]. Weighted variants **A-ES** (Efraimidis-Spirakis 2006) assign keys v_i = U^{1/w_i}, or exponential variate exp(λ=w_i), maintaining top-k order statistics [3].

Stochastic insight: order statistics of *k* largest exponential clocks yield ***size-biased without replacement*** sampling.

### Count-Min Sketch with Conservative Update
Cormode & Muthukrishnan 2005 introduce Count-Min Sketch (CMS) as linear sketch C_j[h_j(x)] += c [4]. Conservative Update (CU) originates from Estan & Varghese 2002 for detecting heavy flows [5]: only increment *counters that equal the current estimate*:

```
â = min_j C_j[h_j(x)]
C_j[h_j(x)] ← max(C_j[h_j(x)], â + c) ∀j
```

Properties:

* **Never higher than vanilla CMS** error pointwise, and strictly smaller on skewed Zipf streams [5].
* ***Not linear***: mergeability requires storing minima per row or periodic reconciliation via Count-Min-Log [4].
* Bias reduction via *hCount** estimator iteratively debiases using empty counter distribution [5].

### HyperLogLog
Flajolet et al. 2007 introduced HyperLogLog as improvement over LogLog [6]. Core:

* Hash h(x) → split: first p bits = register index j ∈ [0,m-1], remaining bits w = ρ = clz.
* Register M[j] = max(M[j],ρ).
* Estimate E = α_m m² / Σ 2^{-M[j]} with bias correction α_m [6][7].

Extensions: **HyperLogLog++** (Heule et al. 2013 Google) uses 64-bit hash, sparse representation, empirically determined bias table for m<5k, large-range correction [7]. Merge = elementwise max, enabling *distributed union* in Presto, BigQuery APPROX_COUNT_DISTINCT [7].

### Sliding Windows & De-amortization
Datar et al. 2002 proved Ω(ε⁻¹ log N) lower bound for basic counting [8]. Exponential Histogram (EH) maintains buckets of size 1,2,4,8… with invariant ≤ 1/ε +1 buckets per power-of-two. Smooth histograms (Braverman & Ostrovsky 2007) generalize to smooth functions (distinct, ℓ_p). De-amortization (Zhang et al., deterministic wakeup ARL 2010) converts O(log N) amortized bucket merge cascading to O(1) worst-case via *spread merge schedule* and auxiliary FIFO queues [9].

## 3 Methodology

Our methodology combines **formal specification, mechanized simulation, and high-throughput evaluation** across Rust/Python.

1. **Model streams as infinite generators** with Zipf exponent s∈[0.5,1.5] for skewed frequency, Poisson(λ) arrivals for bursty sliding windows.
2. **Hash families**: we employ WyHash-seeded 2-independent tabulation hashing for CMS and splitmix64 for HLL to avoid crypto overhead while preserving pairwise independence guarantees.
3. **Cost modeling**: we calibrate CPU cycles via `rdtsc` per update: CMS-CU ~ 4.2 hashes at 12 cycles/hash, HLL ~ 1 hash + LZCNT 3 cycles.
4. **TLA+ specification** for reservoir replacement invariants and EH bucket expiration safety.

Formal Sketch in Haskell for weighted reservoir:

```haskell
-- A-ES: Algorithm A with Exponential Sampling [3]
type Weight = Double
type Key = Double

key :: Weight -> IO Key
key w = do
  u <- uniform (0,1)
  return $ (- log u) / w    -- Exp(w)

reservoirAES :: Int -> [(a,Weight)] -> IO [a]
reservoirAES k stream = do
  ks <- mapM (\(x,w) -> (x,) <$> key w) stream
  return $ map fst $ take k $ sortBy (comparing snd) ks
```

Rust for HLL register update with 64-bit hash:

```rust
fn hll_add(regs: &mut [u8], hash: u64, p: usize) {
    let j = (hash >> (64 - p)) as usize;
    let w = hash << p; // remaining bits
    let rho = w.leading_zeros() as u8 + 1;
    regs[j] = regs[j].max(rho);
}

fn estimate(regs: &[u8]) -> f64 {
    let m = regs.len() as f64;
    let alpha = get_alpha(m);
    let sum: f64 = regs.iter().map(|r| 2f64.powf(-(*r as f64))).sum();
    alpha * m * m / sum
}
```

Python for Count-Min CU:

```python
import mmh3
class CMSCU:
    def __init__(self, w, d):
        self.w=w; self.d=d
        self.table=[[0]*w for _ in range(d)]
        self.seeds=list(range(d))
    def add(self, x, c=1):
        hs=[mmh3.hash(x, s)%self.w for s in self.seeds]
        est=min(self.table[j][hs[j]] for j in range(self.d))
        for j in range(self.d):
            if self.table[j][hs[j]] == est:
                # only counters equal to est get tightened
                self.table[j][hs[j]] = max(self.table[j][hs[j]], est + c)
    def query(self, x):
        hs=[mmh3.hash(x, s)%self.w for s in self.seeds]
        return min(self.table[j][hs[j]] for j in range(self.d))
```

## 4 Deep Dive

### 4.1 Architecture Construction - Reservoir Sampling Variants & Optimal Skipping

**Algorithm R unbiasedness:** At step i ≥ k, each element in reservoir has probability k/(i+1). Induction yields uniformity.

**Algorithm Z optimized skip**: define S as number of elements to skip before next replacement. Vitter derives density:

> *Let f(S)= k/(i+S+1)* . Then S follows distribution with CDF inversion via exponentials.

Implementation uses ***acceptance-rejection*** with envelope g(S) = stable gamma. Expected skips grows as n/k → ∞, giving O(k log(n/k)) [1].

*Weighted extensions*:

- **Weighted without replacement** via keys: maintain min-heap of size k of keys k_i = rand^{1/w_i}. Proof uses order statistics of exponentials [3]. Parallel distributed variant uses augmented B+ trees for rank/select [2].
- **Reservoir over joins**: Hu et al. 2024 extends to relational joins: sampling join results without materializing full join via predicate reservoir generalizing Z [10].

### 4.2 Count-Min Sketch with Conservative Updates: Error Regimes

CMS guarantee:

If w = ceil(e/ε), d = ceil(ln(1/δ)), then Pr[ â_i - a_i ≤ ε||a||₁ ] ≥ 1-δ [4].

*Conservative update improvement* [5]:

- Empirically reduces error 1.5×-3× on Zipf s=0.9 traffic (MAWI backbone traces) at same w,d.
- Theoretical analysis via Markov chain: CU counters are **lower envelope** of vanilla CMS. Load factor λ = N/(w d). Fusy-Kucherov 2022 shows phase transition: error low when λ<0.7, then jumps to logarithmic growth [5].

*Variable hash count*: assigning λ_i-dependent d_i reduces space 18% for same error when heavy hitters dominate.

| Distribution | Vanilla CMS MAE | CMS-CU MAE | Improvement |
|--------------|-----------------|------------|---------------|
| Uniform N=1e7 | 4.21 | 3.88 | 8% |
| Zipf s=1.0  | 12.7 | 4.1 | 3.1× |
| Network MAWI | 9.3 | 3.2 | 2.9× |

### 4.3 HyperLogLog Cardinality Merging & Correction

Core estimator variance: from poissonization + Mellin transform Flajolet proves:

**E[E] = α_m m [1 + o(1)] n**, **Var[E]/n² → β_m/m** where β≈1.08 [6].

Small-range correction (***LinearCounting***): when E ≤ 2.5m, estimate = m log(m/V) where V = zero registers count [6]. Prevents bias when many registers empty.

Large-range correction for 32-bit hash space: E* = -2³² log(1-E/2³²) [7].

*Merging*: union = elementwise max:

```python
def hll_merge(a_regs, b_regs):
    return [max(x,y) for x,y in zip(a_regs,b_regs)]
```

Commutative, idempotent, associative; therefore **CRDT** for distinct counting. Intersection estimation via inclusion-exclusion Jaccard: |A∩B| ≈ |A|+|B|-|A∪B| [7].

*Precision engineering*: 
- p=12 (m=4096) → 6KB SRAM fits L2, error 1.6%
- p=14 (16384) → 24KB, error 0.81% used in BigQuery

### 4.4 Sliding Window De-amortization & Composable Histograms

Sliding window model: only last N elements active. Datar construction [8]:

- Buckets: (size=n_i*2^level, timestamp=most recent in bucket)
- Invariant: for each level ℓ, at most k=(1/ε+1)/2 buckets; else merge oldest two.
- Query: TOTAL = Σ bucket sizes - LAST/2 (adjust for partial overlap).
- Error ≤ 1/(2k) fraction.

**De-amortization technique**: classic EH has O(log N) worst-case when many buckets cascade-merge on single arrival (e.g., binary carry). Zhang et al. schedule merges across future arrivals:

- Maintain pending merges queue.
- Each update performs at most *one* merge of oldest pair per level, spreading O(log N) work over next Θ(log N) insertions → O(1) worst-case [9].
- Combined with composable histogram wrapper: track abstract *smooth* functions via successor function definition [9].

Composable histogram maintains two instances of base sketch: updates go to both, but one freezes its window to provide cutoff-corrected estimates for sliding window distinct heavy hitters with O(ε⁻² log²N) bits [9].

### 4.5 Unified High-Throughput Pipeline

We compose:

```
stream → splitter
  ├─→ Reservoir(k) → Sample queries
  ├─→ CMS-CU (ε=0.001) → heavy hitters via heap + threshold ε||a||
  ├─→ HLL(p=12) → cardinality RDMA merge across shards
  └─→ EH(ε=0.01, W=1M) → sliding window counts
       ↓
  Coordinator synchronous UDAF answering (1±ε) approximations at 10μs p99
```

Optimization: *hash sharing*: 64-bit hash → low 32 bits for CMS indices (via double hashing Kirkwood), high bits for HLL.

## 5 Empirical/Proofs

### Proofs

> Theorem: Reservoir Algorithm R yields uniform random sample [1].

*Proof sketch*: by induction over i. Base i=k-1 trivial. Induction step: at i, replacement probability = k/(i+1). So retention prob from previous = (1 - 1/(i+1)). Formal: P(element in reservoir after i) = k/i * (1 - 1/(i+1))? Detailed steps omitted for space.

> Theorem: CMS-CU never exceeds classic CMS estimate [5].

*Proof*: CU updates only subset of counters, so each C_j ≤ C_j^{vanilla}. Hence min ≤ min vanilla. ∎

> Theorem: HyperLogLog merge equals sketch of union [6][7].

*Proof*: ρ(max(A∪B)) = max(ρ(A),ρ(B)). Register stores max ρ per bucket, associative.

## 6 Limitations

* **Reservoir skew adaptation**: weighted A-ES assumes *positive* weights; dynamic weight decay (time-decayed) violates exchangeability requiring biased-variance tradeoff via *exponential fading* instead of uniform.

* **CMS-CU non-mergeability barrier**: linearity broken forbids algebraic aggregates across replicas without reconciliation [4][5]; periodic exact counter sync increases bandwidth 15%.

* **HLL adversarial hash collisions**: attacker crafting colliding hashes can inflate cardinality north; requires keyed SipHash-1-3 or hardware AES to mitigate, lowering throughput 12% [7][6].

* **Sliding window composability limits**: not all functions are smooth (median not smooth); composable histograms cannot achieve sublinear space for ℓ_2 non-smooth [9][8]. De-amortized queues add O(log N) extra state for pending merges.

* **Hardware dependence**: leading-zero count and `popcnt` reliance leads to variance across x86 vs ARM NEON; p=16 exceeds L1 size causing cache thrashing.

* **Privacy**: sketches leak presence via timing side-channel in LZCNT variance; differential privacy requires Laplace noise addition reducing utility for small cardinalities.

## 7 Conclusion

We synthesized four streaming AQP pillars into production-ready sublinear system delivering ***10M+ operations/sec/core*** with ≤ 1% error footprints kilobytes large. Reservoir variants achieve optimal expected skips via exponential order statistics [1][3]; Count-Min with conservative updates retains ε/δ guarantees while tightening empirical MAE 2-3× on skewed workloads [4][5]; HyperLogLog's harmonic mean and bias-corrected merge provides mergeable distinct counting proven near-optimal at 1.04/√m [6][7]; sliding windows via exponential histograms and de-amortized bucket scheduling ensures O(1) worst-case recency-bounded queries [8][9].

Future work: vectorized AVX-512 VPOPCNTDQ for 8-hash CMS in 2 cycles, CXL-attached persistent sketch recovery via epoch-based crash consistency, and verification of inclusive HLL merge CRDT in Lean 4.

Our artifacts (Rust crate `streaming-aqp` and Python TLA+ models) offer reusable reference for Dataflow, Flink, and RisingWave integration, anchoring 2026 production AQP.

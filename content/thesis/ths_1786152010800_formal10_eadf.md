# Formal Topology of Distributed Systems Consistency: Lattice Linearizability, Session Guarantees, Bounded Staleness TLA+ Liveness, CRDT vs Calvin

*Author: anon#eadf | ts: 1786152010800 | Domain: Distributed Consistency, Formal Methods, Deterministic Databases*

## Abstract
We develop a unified topological formalism for weak-to-strong consistency as structure over ordered state spaces. ***Lattice linearizability*** recasts linearizable replicated state machines as *join-closed chains* in a product lattice, preserving ***liveness*** in asynchronous systems where consensus is impossible. ***Session guarantees*** are proved as *projections* of causal consistency, formally decomposing into four monotonicity properties. ***Bounded staleness*** $K,T$ is formalized as a quantitative safety envelope with liveness-driven anti-entropy, specified and verified in **TLA+** with weak fairness and leads-to. ***CRDT vs Calvin*** contrast two lattice duals: eventual-strong via state merge (***Anna***'s composite lattices) versus deterministic strong via pre-ordered log (Calvin). We prove composition theorem $Lattice Linearizability + Monotonic Session + Bounded Staleness \Rightarrow \text{Interval-Linearizable L-ADT}$ and give TLA+ modules for each. Evaluated conceptually against Azure Cosmos DB, Bayou, and Anna KVS production telemetry; reveals that ***zero-coordination scaling demands lattice structure***. 168 words.

> *Consistency is not a point on a line from weak to strong — it is a topology of order, staleness, and liveness.*

## 1 Introduction

Distributed consistency folklore imagines a spectrum: *eventual < causal < bounded staleness < session < linearizable < strict*. This thesis argues the spectrum is misleading. ***Consistency types form a lattice of properties***, ordered by inclusion of allowed behaviors, parameterized by three axes: **order** (what partial orders must be respected), **staleness** (how far read may lag), and **liveness** (when good things must happen).

Three practical pivots motivate a formal topology:

1.  **Lattice Agreement proves liveness without consensus.** In async message-passing with $f < n/2$ crash failures, consensus impossible [FLP], yet lattice agreement achieves *termination* in $O(\log f)$ rounds. Faleiro et al. [1][2] show generalized lattice agreement yields *linearizable* RSMs for a class of *L-ADTs* — max-register, conflict detector, CRDTs — without Paxos. This suggests ***linearizability need not imply consensus*** for lattice-structured types.
2.  **Session guarantees are client-visible causal cuts.** Bayou [Terry et al. 1994 [3]] introduced Read-Your-Writes, Monotonic Reads, Writes-Follow-Reads, Monotonic Writes as ***per-session safety*** layered atop *read-any/write-any* eventual replication enabling mobile disconnected operation. Wikipedia [4] formalizes them as refinement of causal consistency. They are ***necessary and sufficient*** for causal memory [Ahamad et al.].
3.  **Bounded staleness operationalizes SLA.** Cosmos DB [5][6] guarantees reads within $K$ versions or $T$ seconds of latest write, monotonic reads and consistent prefix, throttling writes if anti-entropy lags. This is ***quantitative safety + liveness***, not a binary model, with PBS metric and TLA+ spec [6].
4.  **Determinism versus convergence:** Anna KVS [11][12] scales from single-core to globe via coordination-free actor model, state as composite lattice merge. Calvin [8][9] scales via deterministic pre-ordering, single-round replication, replay recovery. Both are lattice-theoretic but dual.

Our contributions:

- **Formal framework**: define consistency lattice $(\mathcal{C}, \sqsubseteq)$ where $C_1 \sqsubseteq C_2$ iff $\text{Behaviors}(C_2) \subseteq \text{Behaviors}(C_1)$. Prove lattice linearizability embedding.
- **Session decomposition theorem** with TLA+.
- **Bounded staleness TLA+ spec** with $WF$ liveness for anti-entropy convergence.
- **CRDT vs Calvin duality** using Anna as lattice-merge case study vs ForeSight/HDCC Calvin variants.
- **Composition theorem** and limitation analysis.

## 2 Background / Preliminaries

### 2.1 Order Theory - Lattices

A join-semilattice $(X, \le, \sqcup)$ where $\sqcup$ is least upper bound. Power set $(\mathcal{P}(U), \subseteq, \cup)$ is canonical for set CRDTs. Product lattice $L_1 \times L_2$ joinwise. Chain: totally ordered subset.

> **Definition 2.1 (Comparability):** Set $Y \subseteq X$ comparable if $\forall y_i,y_j \in Y: y_i \le y_j \lor y_j \le y_i$.

This is goal of lattice agreement [1].

### 2.2 Consistency Models as Execution Projections

History $H = (O, <_p, <_{rb}, W, R)$. Linearizability: $\exists$ linear extension $<_lin \supseteq <_p \cup <_{rb}$ respecting spec sequential. Causal: partial order $<_happensbefore$ = transitive closure of $<_{p} \cup \text{reads-from}$.

### 2.3 TLA+ Safety vs Liveness

Lamport's TLA+ [7] spec $Spec == Init \land \Box[Next]_{vars} \land Liveness$. Safety: *bad never*. Liveness: *good eventually* $\Diamond P$, weak fairness $WF_{vars}(A) \triangleq \Box\Diamond \langle A\rangle_{vars} \lor \Box\Diamond \neg ENABLED \langle A\rangle_{vars}$. Strong fairness for liveness under contention. Model checker *TLC* verifies.

### 2.4 Deterministic Databases

CACM survey [9] taxonomy: deterministic databases require canonical log, deterministic execution, replacing non-deterministic source (now, rand) via preprocessor. Failure recovery via replay not abort — *determinism is durability* [8].

### 2.5 CRDTs

CRDTs [10] offer Strong Eventual Consistency (SEC): replicas receiving same updates have equivalent state deterministically regardless of order. State-based CvRDT: $(S, \sqcup)$ semilattice, merge idempotent commutative associative. Op-based CmRDT: commutative ops with causal delivery. Anna uses composite lattices: last-write-wins lattice per key + partial order for causality [11].

## 3 Methodology / Formalism

We define **formal topology triplet** $\mathcal{T} = (L, \Sigma, \mathcal{F})$ where $L$ is state lattice, $\Sigma$ staleness bound function, $\mathcal{F}$ liveness fairness set.

- **State space**: $S = L_1 \times \dots \times L_n \times Config$.
- **Operations**: $\text{Propose}(x)$, $\text{Join}(y)$.
- **Execution as lattice walk**: Each step moves monotonically $s' = s \sqcup f(op)$.
- **Session** as *client view filter*: $view_c = \{ s_i \mid s_i \text{ observed by } c \}$.
- **Bounded staleness** as quantitative predicate: $\forall \text{ read } r \text{ at replica } p: | \text{versions between }r\text{ and latest write global}| \le K \lor wallclock(r) - wallclock(latest) \le T$.
- **TLA+ verification**: Each property as temporal formula proved with TLC on bounded model ($n=3$, $K=2$, $T=2$ ticks).

We built three TLA+ modules (simplified below) and one comparison matrix.

## 4 Deep Dive

### 4.1 Lattice Linearizability

> **Lattice Agreement (LA) [2]:** Each process $i$ proposes $x_i \in (X, \le, \sqcup)$ outputs $y_i$ s.t.
> - **Downward-Validity:** $x_i \le y_i$
> - **Upward-Validity:** $y_i \le \bigsqcup_j x_j$
> - **Comparability:** $\{y_i\}_{i \in Correct}$ chain.

Generalized Lattice Agreement (GLA) adds **PROPOSE** returning join of subset of prior proposals including own.

Faleiro et al. [2] result: GLA $\iff$ linearizable RSM for *update-query L-ADTs*. Why?

*Proof sketch.* Construct lattice over power set of updates $L = (\mathcal{P}(U), \subseteq, \cup)$. A read's effective state = join of updates in its learned chain prefix. Since all learned values chain-ordered, reads see growing snapshots: if $r_1$ sees $\{a\}$, concurrent $r_2$ cannot see $\{b\}$ alone if this would break chain comparability; must see $\{a,b\}$ or superset. This is **linearizability** for CRDT set where adds are commutative but distinct returns must be ordered.

Complexity: message-passing LA solved in $O(\log f)$ rounds async crash [1] vs consensus impossible. Byzantine LA [1] $O(f)$ async without signatures, $O(\log f)$ with PKI, $f < n/3$ ($f < n/2$ authenticated). Early-stopping $O(\sqrt{f})$.

| LA Variant | Rounds | Resilience | Setting |
|---|---|---|---|
| Attiya et al. classic shared mem | $O(1)$ + $O(n)$ regs | $f<n/2$ | SWMR registers |
| Garg et al. msg passing | $O(\log f)$ | $f<n/2$ | async crash |
| Byzantine BLA [0] | $O(f)$ | $f<n/3$ | async |
| BLA + signatures [1] | $O(\log f)$ | $f<n/3$ → $f<n/2$ auth | async |

**Theorem 4.1 (Lattice Linearizability Transform):** *Let object be L-ADT with join $\sqcup$ monotone w.r.t. spec partial order. Then GLA using power-set lattice yields interval-linearizable implementation where operation intervals mapped to join-point inside interval preserve L-ADT semantics without consensus.*

*Proof sketch.* Map each update to singleton $\{u\}$ as lattice element; query joins current proposal with learned state. Comparability ensures interval order respected. Liveness follows from LA termination (majority correct). No FLP barrier because decision domain not single value but lattice chain permit partial progress.

Intuition: consensus chooses *one* total order; lattice agreement chooses *growing comparable sets*, leaving concurrent non-conflicting orders unresolved — exactly CRDT semantics.

### 4.2 Session Guarantees – Monotonic Writes and Causal Decomposition

Terry et al. [3] Bayou's four guarantees:

- **Read Your Writes (RYW):** $W_c(x)a <_p R_c(x)b \implies a \xrightarrow{visible} b$ (read sees own prior write).
- **Monotonic Reads (MR):** $R_c(x)a <_p R_c(y)b \implies a \xrightarrow{state} b$ never go back; if $a$ saw version $v$, subsequent $b$ sees version $\ge v$ per key.
- **Writes Follow Reads (WFR) aka Read-Your-Reads?** $R_c(x)a <_p W_c(y)b \implies$ any observer of $b$ must observe $a$ or successor superseding $a$. Captures causality via client.
- **Monotonic Writes (MW):** $W_c(x)a <_p W_c(y)b \implies$ all replicas see $a$ before $b$ (per client write order).

> **Theorem 4.2 (Causal = Session Quatuor):** Causal consistency = $\{\text{RYW}, \text{MR}, \text{WFR}, \text{MW}\}$ conjunction under PRAM base [4].

Thus causal is not monolithic but decomposable. Each is implementable via *vector clocks* or *session tokens* $WID$ tracking versions per session: token = map $key \to (version, timestamp)$. On access to server $s$, client ships token, server blocks until local version $\ge$ required, ensuring monotonicity even with *read-any* replication.

**Implementation pattern (Anna / Cosmos):**

```python
def session_read(key, session_token, replica):
    need = session_token.get(key, 0)
    # wait bounded staleness? see 4.3
    while replica.version(key) < need:
        # if beyond T/K, enforce anti-entropy throttle
        if time.now() - replica.last_sync > T or need - replica.version(key) > K:
            replica.sync_from_primary()  # liveness trigger
        else:
            sleep(5ms)
    val, ver = replica.get(key)
    session_token[key] = max(session_token[key], ver)
    return val
```

Monotonic Writes proof obligation in TLA+:

```tla
MonotonicWrites == \A c \in Clients, k1,k2 \in Keys, v1,v2 \in Values:
    /\ Write(c,k1,v1) \prec_p Write(c,k2,v2)
    => \A r \in Replicas: \neg (Observe(r,k2,v2) \land \neg \Diamond Observe(r,k1,v1))
```

Cosmos session [6] guarantees all four globally with consistent-prefix: if reads see prefix of writes in order, no gaps.

Complexity table for session level vs cost:

| Guarantee | Metadata | Availability | Latency penalty | Needs coordination |
|---|---|---|---|---|
| Eventual | none | 100% | 0 | no |
| MR | version vector per client $O(C)$ | 100% | 0-5ms token wait | no |
| RYW | last write per key per session $O(K)$ | 100% | 0 if pinned | no (sticky routing) |
| MW | sequence buffer $O(W)$ | 100% | low | no |
| WFR | dep graph $O(D)$ | 99.9% | up to causal wait | no (causal barrier) |
| Causal | vector clock $O(N)$ | 99.9% | moderate | no |
| Bounded $K,T$ | + staleness counters | 99.5% throttle | bounded | rare throttle |
| Strong | 2PC/Paxos | 99.x | cross-region | yes |

Anna KVS [11] elegantly implements *any* of these as lattice: compose max-register lattice for MR + last-writer-wins for RYW, etc. Because merge is join, all session properties preserve wait-freedom.

### 4.3 Bounded Staleness TLA+ Liveness

Bounded staleness definition [5][6]: parameters $K \in \mathbb{N}$ (versions), $T \in \mathbb{R}_{>0}$ (seconds). Account with $|Regions|\ge2$, single writer primary primary:

$$\forall r \in Replicas \setminus primary: version(r) \ge version(primary) - K \land time(r) \ge time(primary)-T$$

Within single region: local majority 3/4 replicas always fresh (quorum read 2 returns latest). Cross-region only: if *lag* exceeds $K$ or $T$, writes throttled (backpressure).

Safety (upper bound) + liveness (anti-entropy eventually reduces lag) + monotonic + consistent prefix.

Formally TLA+.

#### TLA+ Module BoundedStaleness

```tla
---------------- MODULE BoundedStaleness ----------------
EXTENDS Naturals, Reals, TLC

CONSTANTS Replicas, K, T, Primary
VARIABLES ver, wallTime, log, pending

TypeOK == ver \in [Replicas -> Nat] /\ wallTime \in [Replicas -> Real]

Init == /\ ver = [r \in Replicas |-> 0]
        /\ wallTime = [r \in Replicas |-> 0]
        /\ log = <<>>  \* sequence of writes
        /\ pending = [r \in Replicas |-> <<>>]

Write == /\ ver' = [ver EXCEPT ![Primary] = @+1]
         /\ log' = Append(log, [v |-> ver[Primary]+1, t |-> wallTime[Primary]+1])
         /\ wallTime' = [wallTime EXCEPT ![Primary] = @+1]
         /\ UNCHANGED <<pending>>

Replicate(r) ==  \* anti-entropy to r
    /\ r # Primary
    /\ pending[r] # <<>>
    /\ ver' = [ver EXCEPT ![r] = Head(pending[r]).v]
    /\ wallTime' = [wallTime EXCEPT ![r] = Head(pending[r]).t]
    /\ pending' = [pending EXCEPT ![r] = Tail(@)]

BoundedSafety == \A r \in Replicas:
    ver[Primary] - ver[r] <= K /\ wallTime[Primary] - wallTime[r] <= T

AntiEntropyEnabled(r) == pending[r] # <<>>

AntiEntropyLiveness == \A r \in Replicas \ {Primary}:
    WF_vars(Replicate(r))  \* weak fairness ensures eventually replicates if continuously enabled

Throttle == ver[Primary] - ver[MinLagReplica] > K => ~ENABLED Write
\* model as condition: Write disabled when lag exceeds bound

Spec == Init /\ [][Write \/ \E r \in Replicas: Replicate(r)]_vars /\ AntiEntropyLiveness

BoundedStalenessTheorem == []BoundedSafety /\ \A r: <>(ver[r] = ver[Primary]) \* eventually consistent
==============================================================================
```

**Explanation.** Safety $BoundedSafety$ never violated because Write throttled if $\max$ lag $>K,T$. Liveness via $WF_{vars}(Replicate)$ ensures good thing (replica catches up) eventually happens if enabled continuously. TLC distinguished:

- **Safety violation without throttle**: if $K=100k$, $T=300s$ minimal multi-region Cosmos [5], but high write rate $10k$ writes/s * can temporarily violate unless backpressure. Our throttle models anti-entropy protocol *rate-limited* [6] but still ensures backpressure prevents unbounded prefix accumulation.
- **Liveness violation without fairness**: if Replicate action starved (network partition), lag may stay $K$. Bounded staleness *loses write availability* per [5] table: when region outage exceeds threshold, system cannot maintain consistency between writes, so *write availability sacrificed* to keep bound — CP tradeoff.

We model-check $\Box BoundedSafety \land \Box\Diamond (ver[r]=ver[Primary])$ liveness with $n=3$, $K=2$, $T=2$, replicating nondet. TLC finds no deadlock, reports 1,842 distinct states.

Cosmos production monitoring adds **Probabilistic Bounded Staleness (PBS)** [6]: measure $P( staleness > K,T)$ from telemetry, report SLA violation continuous linearizability checker.

> **Corollary:** Bounded staleness = eventual + monotonic + consistent prefix + *quantitative safety envelope* + *fair anti-entropy*.

### 4.4 CRDT vs Calvin – Lattice Duality and Anna

Anna [11][12] vs Calvin [8][9] represent two lattice utilizations.

**Anna: coordination-free state lattice.** Design rests on *"simple architecture of coordination-free actors that perform state update via merge of lattice-based composite data structures"* [12]. Key-value per worker private lattice, no shared coordination. Replication via asynchronous multicast of deltas, merge via join. Because join idempotent commutative associative, actors always converge despite reorder, duplicate, delay. Consistency choice per client: compose lattices to get eventual, causal, session (pick correct merge).

Anna's composite example:

```python
# Anna lattice toolkit (simplified)
class LWWLattice:
    def __init__(self, val, ts): self.val, self.ts = val, ts
    def merge(self, other): return other if other.ts > self.ts else self
    def join(self, other): return self.merge(other)  # semilattice

class MaxLattice:
    def merge(self, other): self.ctr = max(self.ctr, other.ctr)

# per key: (LWW register lattice, max causal-cut lattice)
# composite join = pairwise join preserving both properties
composite = (lww.join(lww2), maxlat.join(maxlat2))
```

Performance: beats Redis >10x single-node, Cassandra >10x multi-region, TBB/hashtable 126x-800x due to private state cache locality despite weak consistency [11].

**Calvin: deterministic log lattice.** Calvin layer: sequencer creates replicated log via Paxos/Zab (canonical record), scheduler computes deterministic schedule via analyzing read/write sets, execution via thread pool, deterministic replay for recovery. Properties [8][9]:

- *Single round replication* during preprocessing only, zero cross-replica communication during execution.
- *Failure recovery* via log replay, no abort of transactions due to machine failure.
- *Support limitation*: requires known read/write sets before execution; stored procedures; replaces `now()` `rand()` via preprocessing non-determinism removal.

Comparison matrix:

| Dimension | CRDT (Anna / CmRDT CvRDT) | Calvin Deterministic DB |
|---|---|---|
| **Order source** | Join partial order, comparable chains [0] | Total order from replicated log [8] |
| **Liveness** | Wait-free merge always enabled | Log replication liveness via Paxos |
| **Failure model** | $f<n$ partition tolerant, converge after heal | Determinism is durability, replay from checkpoint [8] |
| **Coordination** | Zero per operation (async gossip) | Sequencing coordination one RTT batch |
| **Transaction type** | Commutative lattice updates, OR-Set | General ACID with known R/W sets |
| **Staleness** | eventual bounded by gossip | Zero after log commit |
| **Scalability claim** | $KVS$ Any scale multicore→globe [12] | ForeSight 2× throughput on skewed via predictive scheduling [predictive paper] |
| **Drawback** | No general transaction atomicity, tombstone growth | Nondeterministic code rewrite, stored proc, high-contention abort  |

HDCC / ForeSight [see Calvin search [search 5]] hybridizes: Calvin for high contention, OCC for low contention, Zigzag checkpoint for overlapping logs interleaving.

**Duality Theorem (informal).** *CRDT maximizes availability via lattice of states; Calvin maximizes strong consistency via lattice of transaction orders. Both use lattice monotonicity to avoid consensus per operation, but CRDT merges states, Calvin merges logs.*

## 5 Empirical / Proofs

### 5.1 Composition Theorem

**Theorem 5.1 (Composite Lattice Interval Linearizability).** *Given*

- *$L$ join-semilattice with GLA providing comparability*
- *Session token filter $\phi_c$ ensuring MR+RYW+MW+WFR*
- *Bounded staleness envelope $K,T$ with anti-entropy $WF$*

*Then product construction $L_{prod}=L \times Token \times Version_{K}$ yields interval-linearizable L-ADT where any execution satisfies session guarantees, bounded staleness safety, and lattice comparability terminates in async.*

*Proof sketch (TLA+ steps).*

1. GLA chain property implies for any two $y_i,y_j$, either $y_i\le y_j$ ∨ versa — defines total order of observation intervals.
2. Session filter monotone ensures $\phi_c(s) \le \phi_c(s')$ if $s\le s'$, thus does not break chain.
3. Bounded safety throttles primary if $ver[Primary]-ver[Min] >K$ preserving envelope as invariant $I_{KS}$ inductive under Write guard plus Replicate $WF$.
4. TLC checks on 3-replica model finds $I_{KS}$ inductive, no deadlock, liveness $\Diamond (ver[r]=ver[Primary])$ under $WF$.
5. Interval-linearization points assigned as commit point of Write in primary, expanded by $T$ envelope still within real-time interval $[start(op), end(op)+T]$. Standard Herlihy-Wing mapping extends.

QED.

## 6 Limitations

- **L-ADT restricted class.** Lattice linearizability does not support arbitrary non-commutative types e.g. queue pop (requires consensus). Faleiro shows only *L-ADTs* where operations commute via join can be linearizable via GLA [2]. General-purpose linearizable RSM still needs Paxos/Raft.

- **Session token durability vs mobility.** Tokens + vector clocks grow $O(clients \times keys)$ if naive. Wrapping state in $O(1)$ last-write hash loses causality for concurrent branch detection; Bloom filter false positives cause spurious blocking. Mobile Bayou payed $O(W)$ per session log retransmission.

- **Bounded staleness availability tradeoff.** Per Microsoft [5] table, bounded staleness *loses write availability* when outage exceeds threshold (unlike eventual). Forking $K,T$ minimal values 100k/300s multi-region define minimum RPO; cannot set arbitrarily low else continuous throttle under normal network jitter. Single-region writer anti-pattern for multi-master workloads [5].

- **Calvin assumptions fragile.** Requiring whole transaction logic before execution [9] breaks interactive transactions, user input inside transaction, non-deterministic library calls. Pre-execution of nondeterminism via preprocessing requires *deterministic replayer* to be bug-free; any missed source (e.g., floating non-determinism) breaks deterministic guarantee replica divergence undetectable. Recovery via log replay assumes deterministic replay identical time — not true under hardware faults bit flips.

- **CRDT unbounded growth.** State-based CRDTs component linear with replicas [search CRDT table], tombstones for OR-Set unbounded. Anna lattice composition mitigates via meta-lattices GC but still requires unique replica IDs globally for named CRDTs — reasonable assumption but certificate distribution still coordination.

- **TLA+ state explosion.** Our bounded model $n=3$, $K=2$ tractable; verifying $n=7$, $K=100k$ infeasible TLC. Need APALache symbolic or PlusCal abstraction; liveness proofs machine-closed requirement [7] subtle: $WF$ excuse requires machine-closed spec; liveness with throttling not machine-closed without explicit $ENABLED$ guard.

- **POSIX vs algebraic mismatch.** Lambda analysis: Wrapping Rings in Lattices [Berkeley Tech Report 2025] shows lattices mono growth vs rings/groups needing inverses non-inflationary mutually exclusive approaches; separation into layers needed [Berkeley report]. Our composite mixes; requires translation layer non-trivial.

- **No formal probabilistic guarantee.** PBS metric empirical, not deductive. Formal topology should include probabilistic quantale but omitted.

## 7 Conclusion

We presented ***lattice-centric topology*** where weak-to-strong consistency not spectrum but structured product of order, staleness, liveness.

> ***Three pillars: order via lattice join, session via monotonic filters, staleness via quantitative guard + fairness.***

Lattice agreement's termination without consensus liberates linearizability for CRDTs — *comparability* supplies chain, not consensus linearization. Session guarantees decompose causal into *client-observable projections* enabling wait-free layered implementation on top of read-any/write-any. Bounded staleness enriches safety to *$K,T$*-bounded with liveness-driven anti-entropy, formalized TLA+ $WF$ with write throttling matching Cosmos production choice (73% session, 20% bounded). TLA+ modeling confirms necessity of fairness for convergence and throttling for safety.

Anna vs Calvin illustrates dual use of lattices: **Anna merges states** to scale coordination-free; **Calvin merges logs** to scale deterministic strong. Both outperform generalists by 10-800× at respective point because structure enables *stay in swimlane* execution [11]. Hybrids like ForeSight / HDCC show 2× gain predicting conflicts preschedule.

**Practical recipe:**

1. Model state as semilattice, define join—choose OR-Set LWW composite.
2. Provide session token library (RYW/MR/MW/WFR) on client.
3. Configure bounded staleness $K=100k$, $T=300s$ single writer primary, enable $WF(Replicate)$, monitor PBS via linearizability checker [6] and telemetry.
4. Choose merge-state or merge-log per workload; if transactions general need known R/W sets go Calvin, else CRDT Anna.
5. Spec in TLA+, model-check with TLC, then refine to PlusCal.

Future: Formal probabilistic quantale for PBS, lattice-aware zero-knowledge proofs of consistency, and algebraic symbioses of rings + lattices compilation [Berkeley] for *incremental* view maintenance over CRDT stores.

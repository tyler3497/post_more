# Mechanistic Safety for Rust Unsafe FFI: Stacked Borrows to Tree Borrows Migration, Miri Interpretation of s2n-quic, RustBelt Iris Logical Relations, and Foreign Function Boundary Soundness

## Abstract

This thesis formalizes safety at the Rust foreign function interface boundary through the lens of evolving operational aliasing models, dynamic undefined behavior detection, and mechanized logical relations. We trace the migration from Stacked Borrows to Tree Borrows (PLDI 2025), showing how replacing a LIFO stack with a permissive tree reduces false positives by 54% on 30,000 crates while retaining compiler optimization soundness proved in Rocq. We examine Miri as a Mid-level IR interpreter for detecting aliasing, provenance, and initialization violations, instantiated in Amazon's s2n-quic where Miri is integrated into continuous verification alongside Kani, Loom, and fuzzing. We show how RustBelt uses the Iris higher-order concurrent separation logic to construct semantic interpretations of types with lifetime logic and borrow propositions, proving contextual refinement for interior mutability. Finally, we formalize FFI soundness: provenance exposure via pointer-to-integer casts, Owned vs Reborrowed permissions, and foreign writes that invalidate Frozen assumptions.

## 1 Introduction

**Rust** promises *memory safety without garbage collection* by affine ownership and borrow checking [3][4]. Yet practical systems code must **escape** that discipline via `unsafe` and `extern "C"` FFI blocks, where *responsibility falls on the programmer* to uphold soundness invariants that the compiler can no longer check [5][6]. This tension is existential: compilers wish to **exploit aliasing guarantees for optimizations**, notably reordering reads and writes, while unsafe libraries routinely perform raw pointer arithmetic, intrusive lists, and C interop that superficially violates those guarantees [1][2].

*This thesis asks: what exactly constitutes undefined behavior at the raw pointer boundary?* Prior work **Stacked Borrows** defined an operational *stack* of borrows per allocation whose pop-on-conflict declared programs undefined [1]. It succeeded in enabling optimizations, mechanized in Coq, and validated on parts of `std` via **Miri** [3]. Yet evaluation on **30,000 most-downloaded crates** shows Stacked Borrows rejects common idioms — self-referential `Pin` projections, pointer-roundtrip via `usize`, and shared-to-mutable reborrows common in slab allocators [2].

We synthesize four pillars:

- **Pillar 1 — Tree Borrows:** Tree-based aliasing model receiving PLDI 2025 Distinguished Paper [2], as permissive successor, proven in **Rocq** to retain optimizations and unlock *read-read reorder*.
- **Pillar 2 — Miri:** An interpreter for Rust MIR that checks Tree/Stacked Borrows, uninitialized memory, and provenance on every executed path, with `cargo miri test` integration [3][4].
- **Pillar 3 — RustBelt:** First formal safety proof for `λ_Rust` using **Iris** higher-order concurrent separation logic, modeling lifetime logic as time-divided separation, justifying interior mutability [5][6][7].
- **Pillar 4 — FFI Soundness:** At `extern` boundary types cross from typed Rust to untyped C, where *provenance is exposed* via `ptr.addr()` and foreign writes silently disable `Frozen` borrows.

Contributions:

1. Unified state-machine explanation of Stacked vs Tree Borrows with permission lattice
2. Miri audit methodology for `s2n-quic` case study — how Amazon composes Miri, Kani, Loom, Duvet RFC tracking, and coverage [4]
3. RustBelt semantic typing construction for `Cell`, `RefCell`, `Arc` via Iris invariants
4. Formal FFI boundary calculus with `noalias` justification and sanitization at safe wrapper

> **Theorem 1.1 (Optimization Soundness):** *If program P is well-formed under Tree Borrows, then any intraprocedural reordering justified by Rust's alias analysis preserves observational equivalence on all executions that avoid Tree Borrows UB.*

*Proof sketch in Rocq established in [2] Sec.6 — tree traversal preserves relative read ordering because `Frozen` invalidation is monotonic towards `Disabled`.*

## 2 Background

### 2.1 Rust Ownership and Unsafe Escape Hatch

Rust's type system enforces **affine ownership**: every value has single owner; borrowing splits ownership temporally into `&T` or `&mut T` with lifetimes `'a` ensuring *no dangling pointers* and *no data races* by construction [5]. `unsafe` blocks relax compile-time checks, enabling:

- dereferencing `*mut T`, `*const T`
- calling `extern` foreign functions [6]
- `transmute`, interior mutability via `UnsafeCell`

> **Definition 2.1** — *Soundness of library:* No safe client can trigger undefined behavior (UB) using only safe APIs of library, even if library internally uses unsafe [5].

Soundness depends on **aliasing discipline**: `&mut T` must be unique usable path; `&T` must see no mutation except inside `UnsafeCell` bytes [1][6].

### 2.2 Operational Concept of Provenance

Since LLVM 12+, Rust considers *provenance* not just address: a pointer is `(address, tag, origin allocation)` tuple. Casting `&mut T -> *mut T` carries **tag** that, under Stacked Borrows, pushes `Raw` enabling *any* raw access; under Tree Borrows, child of `Reserved` permission inherits subtree [2][3]. Pointer-to-integer cast `ptr as usize` historically “exposes” provenance — subsequent `usize as *mut T` may be wild.

| Approach | Tracking Structure | Rejects on 30k crates vs SB | Proved Optimizations |
|----------|------------------|-----------------------------|-----------------------|
| Stacked Borrows [1] | LIFO stack per allocation, tags + `Unique/SharedReadOnly/SharedReadWrite` | baseline | `write-write` reorder, `read` elimination, `&mut -> &` not alias |
| Tree Borrows [2] | Tree where every reference is node; permissions `Reserved/Active/Frozen/Disabled` | **54% fewer** rejections | retains SB opts + **read-read reorder**, disables `Frozen` precisely |
| Pure No-Alias | None | 0% rejects but unsound opts | none |

### 2.3 From Coq to Rocq: Mechanization Trajectory

Both Stacked Borrows and Tree Borrows are **fully mechanized** — SB in Coq, TB in Rocq (Coq successor) [1][2]. Iris itself is a Rocq framework for higher-order CSL with impredicative invariants and weakest preconditions [7]. RustBelt builds atop Iris 3.1 to derive **lifetime logic** [5][6].

## 4 Deep Dive

### 4.1 Stacked Borrows: LIFO Insight and Its Breaking Points

***Stacked Borrows*** declares each allocation owns a stack `S = [tag0 : Perm0, tag1 : Perm1, ... top]` where push occurs on borrow creation (`&mut` => `Unique`, `&` => `SharedReadOnly`, interior-mut `&UnsafeCell` => `SharedReadWrite` treated like `Raw`) [1]. Access with tag `t` must find `t` still in stack; if `Unique` below is challenged by foreign read, it becomes `Disabled` via pop `[¬P]Unique` → pop. Raw pointer cast pushes `Raw` allowing any raw access, crucial for `compare` and hash-consing discussions from 2018 Rust Internals thread [1].

*BUT*: LIFO forbids *adjacent siblings both active*: Example where `let x=&mut root; let y=&mut *x; let z=&mut *x` — second sibling `z` invalidates `y` under stack because stack expects linear nesting, yet both derived from same parent — common in `Vec::as_mut_slice` split patterns. Also `&T -> &mut T` laundering via protectors? No. Tree Borrows resolves.

> **Theorem 4.1 (Stack Popping Invalidation):** *Any read through tag `u` where `Unique v` is above `u` in stack triggers UB unless `v = u` or `v` is `SharedReadWrite`. This rules out aliased `&mut` self-recursive structures.*

```rust
// Rust: Pattern rejected by Stacked, accepted by Tree Borrows (from PLDI appendix)
fn aliasing_sibling() {
    let mut root = 1;
    let ref1 = &mut root;              // Stack: [Unique root]
    let ref2 = unsafe { &mut * (ref1 as *mut i32) };
    let ref3 = unsafe { &mut * (ref1 as *mut i32) }; // sibling of ref2
    // Stacked Borrows: ref2 invalidated by creation of ref3 (LIFO violation)
    // Tree Borrows: ref2 and ref3 are siblings under ref1, both Reserved, both can become Active
    *ref2 = 2;
    *ref3 = 3;
    println!("{}", root);
}
```

| Event | Stacked Borrows Stack State | Tree Borrows Permission |
|-------|----------------------------|-------------------------|
| `let mut root` | `[Unique root]` | `root: Active` |
| `&root` ref1 | `[SharedRO ref1, Unique root]` | `root -> ref1 Frozen` |
| `&mut root` ref2 | `[Unique ref2, ...]` | `root -> ref2 Reserved sibling Frozen` |
| write via `ref2` | OK if topmost | `Reserved -> Active`, parent `Active` stays, sibling `Frozen -> Disabled` only on foreign write |

### 4.2 Tree Borrows: Permissions Lattice and Protector Semantics

***Tree Borrows*** replaces stack with **tree**: every `alloc` root node tracks all pointers derived. Each node stores **permission** and **protector** status (indicating borrow-checker protected reference that must not be invalidated during function call) [2]. Permissions state machine (from [2] Sec 3):

- `Reserved` — two-phase borrow reservation (`&mut` not yet written, `Vec` two-phase init)
- `Active` — currently exclusive owner for `InteriorMut` bytes, allows write
- `Frozen` — shared immutable view, becomes `Disabled` only on foreign write in subtree outside protected scope
- `Disabled` — must not be reused, any access UB [2]

Transitions:

- `Reserved` + child write → `Active` if unconflicted (no other active sibling writes) else `Disabled`
- `Active` + foreign read → `Active -> Frozen` (downgrade, allows `&mut -> &mut`? actually enables read sharing)
- `Active` + foreign write → `Disabled` (unless interior-mutable)
- `Frozen` + foreign write → `Disabled`

*Italic key insight:* **Tree permits *sibling* coexistence**, exactly what slab / arena allocators need. Evaluation on 30k crates: Tree rejects 54% fewer test cases than Stacked [2][4]. Moreover, read-read reordering justified because `Frozen` does not track Write vs Read same-address as strongly as `SharedReadOnly` stack pop.

```rust
// Tree Borrows protector demonstration - arg protected over call
#[no_mangle]
pub unsafe fn process(buf: *mut u8, len: usize) {
    // Tree Borrows needs Miri flag -Zmiri-tree-borrows
    // foreign C code calling back into Rust must respect protectors
    // If C writes through alias that disables protected &mut -> UB caught by Miri
}
fn wrapper(v: &mut Vec<u8>) {
    unsafe { process(v.as_mut_ptr(), v.len()); }
    // wrapper's mutable borrow protected across foreign call - Tree's RwLock analogy
}
```

> **Lemma 4.3 (RwLock Analogy Preservation):** *Tree Borrows state machine isomorphic to reader-writer lock where `Active` = WriteGuard held, `Frozen` = ReadGuard, `Reserved` = UpgradableReadGuard.* [PLF 2024 RwLock analogy post]

### 4.3 RustBelt Iris Lifetime Logic and s2n-quic Miri Auditing

***RustBelt*** answers: is `std::cell::RefCell` sound library extension [5][6]? It defines `λ_Rust` with `newtype` ownership via `∃`, lifetime parametric `∀ 'a. T`, and semantic interpretation `⟦T⟧ : Val -> iProp` in Iris. Core:

- **Separation conjunction `*`** — modular ownership
- **Higher-order ghost state** — token for lifetime `q $\in$ LftTok(a)` marking aliveness of `'a`
- **Impredicative invariants `knowInv N P`** — shared state with protocol
- **Borrow proposition** `&full_a P` — ownership of `P` for duration of lifetime `a`, returns when lifetime ends via *lifetime logic* dividing ownership in time, not just space [5][7].

Interpretation of `&'a mut T`: *borrowing* `T` for `'a` means you get ownership now, must return at `a` end; verified via `LftL` closure weaving `▷` later.

**s2n-quic** applies this *spirit* operationally: Instead of mechanized proof for all code (expensive), Amazon runs **Miri** for UB + leaks. Documentation notes Miri explicitly for heap profiling complementary, and s2n-quic guide lists **Miri** among 15+ checks [4]:

- Monte Carlo network simulation varying bandwidth/jitter/RTT
- Loss recovery plots
- Flame graphs, `dhat` heap
- `clippy`, `rustfmt`, code coverage `llvm-cov`, Kani verification with `bolero` harnesses [4]
- Fuzzing `udp-attack`
- Loom for thread-interleaving exhaustive [4]
- Duvet for RFC requirement tracking

*Italic:* Miri is **under-approximating but no false positives** — thus CI one flip integration cheap: `cargo miri test` surfaces *exposed provenance* misuse where C-derived pointer cast to `*mut` subsequently aliases protected `&mut` without `addr` stripping.

### 4.4 Foreign Function Boundary Soundness

**FFI** boundary is where provenance most fragile [9]. Since Rust 1.66, `pointer::addr()` isolates address from provenance, `expose_addr()` explicitly exposes. Rule: *transmuting `&T` to `usize` to `*mut T` loses provenance unless `with_exposed_provenance`* — otherwise Miri flags as None-provenance deref UB [3].

**Sound wrapper pattern** for FFI:

```rust
// safe wrapper around foreign libm csqrtf / abs / strlen - pattern from Rustonomicon
use std::ffi::c_char;
#[link(name = "m")]
unsafe extern "C" {
    #[link_name = "csqrtf"]
    fn c_sqrtf(z: Complex) -> Complex;
    fn abs(input: i32) -> i32;
    fn strlen(s: *const c_char) -> usize;
}
#[repr(C)] #[derive(Copy, Clone)]
struct Complex { re: f32, im: f32 }
// Safe abstraction: we ensure preconditions hold
fn safe_abs(x: i32) -> i32 { unsafe { abs(x) } } // safe because int-only, no pointers, no alias violation [6][9]
fn safe_strlen(s: &std::ffi::CStr) -> usize {
    unsafe {
        // SAFETY: CStr is nul-terminated valid for call duration
        // No Tree Borrows invalidation because s is Shared & unchanged
        strlen(s.as_ptr())
    }
}
```

Foreign write invalidates Rust's `Frozen` assumptions: If C function writes to memory that Rust holds `&T` to, Tree Borrows `Frozen -> Disabled` upon foreign write => subsequent Rust read triggers UB flagged by Miri [3][4]. Hence safe wrapper must require `&mut` exclusivity or avoid holding reference across call.

| FFI Pattern | Tree Borrows Permission | Miri Detection | Mitigation |
|-------------|--------------------------|---------------|------------|
| `*mut T` owned transfer to C | `Active -> Disabled` after foreign write OK if no Rust alias kept | None if no reuse | Transfer ownership, forget Rust handle |
| `&T` shared across FFI | `Frozen` — foreign write => UB | Reports tree borrow violation | Use `UnsafeCell` or `&UnsafeCell<T>` for interior mutability |
| `usize` roundtrip reclaim | Provenance `Wild`, tag None | UB on deref | Use `ptr.addr()`, `ptr.with_addr()`, `expose_provenance` API |
| `&mut T` protected call | Protected `Reserved` prevents disabling | UB if C aliases protected reborrow | Use `Box::into_raw` unprotect before call |

> **Theorem 4.2 (FFI Sound Wrapper Condition):** *If foreign function signature guarantees not to retain alias after return and not to write through pointer derived from shared `&T` unless `T: InteriorMut`, then wrapper with exclusive `&mut` borrow transfer is sound under Tree Borrows and Iris lifetime logic.*

## 6 Limitations and Future Work

- **Miri coverage incompleteness:** Miri is path-executed only, cannot explore `std` thread interleaving unless Loom — false negatives possible [3][4]. s2n-quic Monte Carlo sim partially compensates.
- **Constitutive gap:** Tree Borrows operational semantics does not yet model thread-synchronized happens-before as vector clocks — discussed in 2023 Rust Internals RwLock analogy but remains future, threatens relaxed-atomics modeling [2] Sec 7.
- **Provenance via integers:** `strict provenance` model draft still unstable in nightly ~1.84; `expose_addr` semantics change will shift acceptable patterns — references earlier [9] need update.
- **Interior mutability granularity:** Tree Borrows treats `UnsafeCell` inner bytes uniformly; Xinglu thesis 2025 ETHZ shows per-byte finer tracking needed for `Cell<[u8; N]>` allowing bytewise mutation while holding `&` to other bytes [2][6].
- **RustBelt footprint:** `λ_Rust` excludes async, `dyn Trait`, `const generics` full; `Arc` drop ordering verification requires step-indexed logical relation extension beyond original 2018 model [6].
- **FFI de facto ABI:** No verification of Rust `repr(C)` matches C struct layout without `cbindgen` / `bindgen`; mismatch = sound FFI wrapper still UB at transmutation.
- **Performance:** Tree Borrows interpreter overhead 5-10x vs SB due to tree traversal O(depth) vs O(1) stack top peek; caching of `Active` chain attempted via Rocq data structure optimization but not deployed in Miri stable [2][3].

Future directions: **partial borrow stack merging** for `pin-project`, **Loom-aware TB** with clock, **SafeFFI sanitizer** runtime instrumentation at boundary between safe and unsafe to combine compile-time guarantees + ASan [9], and Iris integration auto-generating pre/post specs via Creusot/Prusti for safe abstractions.

## 7 Conclusion

We traversed **mechanistic safety stack** for Rust unsafe FFI. Starting from type-system need to justify optimizations, **Stacked Borrows** offered LIFO clarity proving `Unique` isolation sufficient for reordering [1]. **Tree Borrows** (PLDI'25 Distinguished Paper) loosens to arborescent tracking, cutting false rejections 54% on 30k crates while unlocking read-read reorder, proven in Rocq and already nightly in Miri [2][3]. **Miri**'s MIR interpretation, central to **s2n-quic** verification matrix with Kani + Loom + fuzz + Duvet + coverage [4], closes dynamic gap between statics and exec path detection. **RustBelt + Iris** elevate argument from operational model to *semantic typing* with time-divided borrow and ghost invariants, providing extensible verification condition future `unsafe` libraries must meet to be deemed safe [5][6][7][8]. Finally, **FFI soundness** requires provenance-aware address wrapping, freezing discipline awareness, and protector-respecting wrapper design, as seen in C `strlen`, `abs`, `csqrtf` encodings and s2n-quic C bindings.

For PhD-level systems researcher, takeaway: ***safety is not syntactic attribute of `unsafe` blocks but judgmental property of permission tree + invariant closure over time***. Next-generation Rust memory model likely Tree Borrows with bytewise interior mutability and vector-clock synchronization, with Iris proof linking optimizations to compiler IR. Until then, pragmatic path: run `cargo miri test -Zmiri-tree-borrows`, furnish Rocq invariant for `UnsafeCell` structures, isolate FFI at narrow safe wrappers, and publish artifacts reproducibly — achieving provisioning from *ownership down to foreign call*.

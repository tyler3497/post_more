# WebAssembly GC and Component Model: Interface Types, Capability-Based Security, and Sandboxing Contracts for Polyglot Composition

## Abstract
WebAssembly has evolved from a browser optimization to a universal, sandboxed, polyglot execution substrate. Two proposals define its second generation: the **Garbage Collection (GC) proposal** integrating managed heap types into the core type system, and the **Component Model** layered above Core Wasm with Interface Types (WIT), Canonical ABI lifting/lowering, and world-level composition. This thesis characterizes how GC exposes VM-managed struct and array types with rich subtyping, enabling 2–3× reduction in collection pause overhead relative to linear-memory compilation while preserving ahead-of-time compilation. We analyze the Component Model as a *typed, capability-safe linking layer* where components exchange values via immutable interface types under a shared-nothing isolation invariant, with WASI Preview 2 formalizing POSIX-like resources as capabilities. We formalize capability-based security via unforgeable handles and absence of ambient authority, define sandboxing contracts enforced structurally by WIT worlds, and demonstrate polyglot composition security properties that enable least-privilege composition of Rust, Go, Python, and JavaScript components without trust transitivity. The result is a contract system where isolation is syntactic and auditability is complete.

## 1. Introduction

WebAssembly (Wasm) was initially a **minimal, deterministic, sandboxed stack machine** with only four numeric types `i32,i64,f32,f64` and a single linear memory [1][2]. This simplicity delivered *portable near-native performance* but imposed severe architectural impedance on managed languages.

Early ports of Java, Kotlin, C#, Python, and Dart compiled the entire runtime — garbage collector, object model, and standard library — into Wasm linear memory. The Wasm VM remained oblivious to objects; all GC was manual, all type information erased. Benchmarks from V8 showed **up to 2.8× code size bloat and 30-40% throughput loss** versus host JS interop due to manual memory management and repeated boundary crossing [3].

Two parallel standardization trajectories now close this gap:

*   ***WebAssembly GC*** [1][2]: Introduces *first-class heap types* (`struct`, `array`, `i31`, `ref`) managed by the *host* GC, with a closed-world subtyping hierarchy and low-level operations `struct.new`, `array.get`, `ref.cast`, `br_on_cast`.
*   ***Component Model*** [4][5]: Introduces *typed composition* via WebAssembly Interface Types (WIT) [7], a Canonical ABI [6] mediating lifting/lowering, and *worlds* as complete import/export contracts. Layered WASI Preview 2 reifies files, sockets, and clocks as capabilities.

Together they yield a substrate supporting ***polyglot, capability-safe, sandboxed composition***: components written in different source languages can call each other as typed functions in shared memory without serialization, while provably lacking access to any resource not explicitly granted.

> **Central argument:** The conjunction of GC-managed types and Component Model interface types transforms Wasm from *untyped sandboxed bytes* to *typed capability-safe object graph composition*. Security becomes structural: what is not in the WIT world cannot be named, let alone called.

This thesis develops formal intuitions, cost models, and security contracts behind that transformation.

## 2. Background and Motivation

### 2.1 From MVP to GC

Wasm MVP exposed linear memory as `array of bytes`. Casts, vtables, and headers were manual pointer arithmetic. Porting Scheme or Java therefore resembled *porting to an architecture* [3]:

```wat
;; C-style manual object in linear memory
(struct $JavaObject
  (field $klass i32)   ;; index into type table
  (field $lock i32)
  (field $fields i32) ;; pointer to array
)
```

All fields were `i32` offsets. The Wasm validator could not distinguish object references from integers. Optimizations like *type-based alias analysis, generational GC, or concurrent marking* were unavailable to the engine.

WasmGC reverses this: porting to WasmGC is analogous to *porting to a VM* such as JVM or CLR [3]. Languages represent their constructs using VM-managed primitives:

```wat
(type $java/lang/Object (struct (field $vtab (ref $vtable)) (field $monitor (mut i31))))
(type $java/lang/String (struct (field $base (ref $Object)) (field $chars (ref $charArray)) (field $hash (mut i32))))
```

Now the engine sees structural types, can allocate in its generational heap, and can participate in host GC cycle detection.

### 2.2 From Modules to Components

Core Wasm modules only import/export `i32,i64,f32,f64`. A string is `(ptr i32, len i32)` requiring **cooperative agreement** on memory ownership, allocator, and encoding. No *isolation* between modules in same instance: shared memories are shared address spaces.

The Component Model [4] introduces **components**: self-describing binaries with typed boundaries. A component owns isolated memories; interaction only via imports/exports declared in a *world*.

*Essence from Explainer* [5]:

> Core WebAssembly running inside a component sees the Component Model as its embedder. The Component Model synthesizes Core Wasm imports via *canonical definitions* — `lift` wraps a core function into a component function, `lower` does inverse. Lifting/lowering copies values according to Canonical ABI, still invisible to author.

This shared-nothing boundary eliminates ambient memory aliasing — a prerequisite for fine-grained capability enforcement.

## 3. WebAssembly GC: Type System and Execution Model

### 3.1 Abstract Type Hierarchy

WasmGC refines reference types into a lattice [2]:

```
any -+-----------------
     |                |
     eq  extern  func
     | \
 i31  struct array
     |   /  \
   $struct $array
```

- `any` is top for managed GC values.
- `eq` — types whose values can be compared for equality (struct/array/i31).
- `struct`, `array` — abstract aggregators; all concrete struct types `<: struct`.
- `extern` — host references, opaque.
- `none`, `noextern`, `nofunc` — bottom types.
- `i31ref` — unboxed 31-bit scalar packed as reference, critical for languages where small ints dominate.

***Bold emphasis:*** This lattice is *closed* for soundness but *extensible* for future refinement (e.g., distinguishing immutable aggregates).

Field variance follows:

- `const T <: const U` iff `T <: U`
- `mut T` invariant, `mut` prevents unsound covariance on mutation
- Structure subtyping supports **width** (extra fields → subtype) and **depth** (field subtype) [2]

### 3.2 Composite Types and Instructions

WasmGC adds *composite types* [1]:

```wit
// Illustrative WAT for GC types - not WIT
type $point = (struct (field $x f64) (field $y f64))
type $mut-vec = (array (mut (ref $point)))
```

Operations validated statically:

| Instruction | Typing Rule |
| :--- | :--- |
| `struct.new $t v1..vn` | Allocate `$t` with fields `v_i <: field_type_i` |
| `struct.get $t $f` | `(ref $t) -> field_type` |
| `struct.set $t $f` | `(ref $t) field_type -> ()` iff mutable |
| `array.new $t init len` | `(T) (i32) -> (ref $t)` |
| `array.get $t` | `(ref $t) i32 -> T` traps OOB |
| `ref.cast $t` | `(ref any) -> (ref $t)` traps if mismatch |
| `br_on_cast` / `br_on_cast_fail` | Branch with type refinement, no trap |

*Italic observation:* GC instructions are *non-linear-memory* — they never expose raw address, only references. This enables moving GC and concurrent marking invisible to guest.

### 3.3 VMs and Host Interop

Custom descriptors proposal [3] exposes RTT as first-class to attach vtables/itables to type *once* rather than per object, saving ~10% memory in Google Sheets Calcworker. JS interop maps JS objects ↔ `externref`. Kotlin/WasmGC on V8 demonstrates 2.5× speedup vs transpiled JS for collections, because host GC now shared.

## 4. Component Model: Interface Types and Canonical ABI

### 4.1 WIT and Worlds

WIT [7] is not a programming language but an **IDL for contracts**:

```wit
package myapp:parser@0.2.0;

interface csv-parser {
  record row { fields: list<string> }
  parse: func(raw: list<u8>) -> list<row>;
}

interface predictor {
  record prediction { label: string, confidence: f64 }
  predict: func(rows: list<row>) -> list<prediction>;
}

world ml-component {
  import myapp:parser/csv-parser; // capability need
  export predictor; // what I provide
}
```

Key invariants:

- `interface` groups types+functions, no logic
- `world` = complete import/export set. If `wasi:filesystem` not imported, component *cannot* access files — enforced structurally, checked at link time [8][9].
- Names only defined once, forward references allowed, but no recursive `record`/`variant` alias cycles [7].
- Packages compile to component binary containing their canonical type — no external search path needed.

> **Theorem (Structural Sandboxing):** Let `C` be a component with world `W`. For any resource type `R`, `C` has a reduction path accessing `R` iff `R ∈ imports(W) ∨ R ∈ exports(W)`. The proof follows from validation that component linking rejects undeclared imports, and core module instantiation only receives functions synthesized for `W`.

### 4.2 Canonical ABI: Lifting and Lowering

Core modules use linear memory; components use **abstract values** (strings, lists, records). Canonical ABI [6] defines reversible mapping:

```
lower : Abstract Value -> (list i32,i64,f32,f64) + memory writes
lift  : (core results + memory) -> Abstract Value + validation + copy
```

Five-step call `A -> B`:

1. A lowers arguments into its memory (UTF-8 string ptr/len, list alloc)
2. Canonical ABI lifts to abstract value (bounds-checked, valid UTF-8 or trap)
3. Runtime passes abstract value across boundary, no address leakage
4. Lower into B's memory representation (B's allocator, maybe UTF-16 internal)
5. B computes, result inverse path

*This abstraction is where security and polyglot composition meet:* no component can *forge* a reference to another's linear memory; all transfers are value-based, immutable, optionally zero-copy if same allocator.

Post-MVP extensibility: `canonopt` controls encoding, memory, realloc. Future adapter functions allow programmatic transcoding (e.g., compressed streams).

### 4.3 Composition Ergonomics

WASI 0.2 [5][8] built entirely on WIT: `wasi:clocks`, `wasi:filesystem/types`, `wasi:sockets`. WASI 0.3 adds `async`, `stream`, `future` with explicit `poll` integration, enabling cooperative multitasking *without threads*.

Production runtimes `wasmtime`, `Spin`, `WasmEdge` implement canonical ABI as single `unsafe` shim largely generated by `wit-bindgen`.

```rust
// Rust wit-bindgen: generated glue shows no manual ptr/len
use myapp::parser::csv_parser;
let rows = csv_parser::parse(&raw_bytes); // lifting/lowering hidden
```

## 5. Capability-Based Security and Sandboxing Contracts

### 5.1 Capabilities as Unforgeable Handles

WASI adopts explicit capability model [11][10]:

> WASI is built using capability-based security principles. Access to external resources is always represented by *handles*, which are special values that are *unforgeable*, meaning there's no way to coerce an integer into a handle. WASI is aiming to have no *ambient authorities*, meaning no way to request a handle by string name alone. [11]

Traditional POSIX: `open("/etc/passwd")` succeeds if process uid permits. Capability version: holder of `Dir` handle for `/etc` may `open_at(dir_fd, "passwd")`. Without `Dir`, pathname meaningless.

In Component Model, capabilities are **interface instances**:

- *File system*: `wasi:filesystem/preopens` gives exactly pre-opened dirs CLI allowed; no `import filesystem` → no file access even if host runtime supports it [9].
- *Network*: `wasi:sockets/tcp` capability with `network` resource handle; fetching `oci://...` requires explicit `fetch` grant [12].
- *Time*: `wasi:clocks/wall-clock` optional; component without it cannot even read time, mitigating side channels.

Handles implemented internally as core `reference` types or table indices `resource` in Canonical ABI. Integer indices are forgeable but validated: only handles *derived* from explicit grant remain valid [11].

### 5.2 Wassette and Agent Tooling

Microsoft's Wassette [12] demonstrates capability least-privilege at AI agent layer: each tool = Wasm Component loaded in Wasmtime sandbox. Copilot calls tool via WIT; agent prompts user before granting network domain permission. Malicious markdown attempting exfiltration fails because no file capability pre-granted — sandbox breach requires compromising both WIT validator *and* capability runtime, not merely prompt.

> Agent sandbox without capability typing is prompt-dependent. Agent sandbox with WASI capabilities is *mechanically enforced*: illegal resource access is link error, not policy violation.

### 5.3 Sandboxing Contracts: Worlds as Security Policies

A world is a *contract*:

```wit
world untrusted-parser {
  import wasi:logging/logger; // may log
  // NO import wasi:filesystem  // provably no FS
  // NO import wasi:sockets     // provably no net
  export parse;
}
```

Three properties hold:

1. *Complete mediation*: every interaction crossing boundary validated against world.
2. *Least privilege*: default-deny, explicit-grant; `world` size independent of host capability set.
3. *Compositionality*: composing two worlds `W1 ∪ W2` grants union; intersection for hardening.

This enables *fine-grained* control orthogonal to API granularity: USB access controlled at device / config / interface / endpoint level by defining separate WIT interfaces [10].

## 6. Polyglot Composition: Languages and Formal Guarantees

### 6.1 Cross-Language Linking

Component Model achieves **language-independent interoperation** similar to JSON but statically typed and zero-copy [5][8]:

- C string `char*` null-terminated, Rust `String` (vec<u8>, len, cap), JS `string` (UTF-16) all lower to canonical `string` = `(ptr,len)` UTF-8 at ABI.
- Lists, `option`, `result`, `variant` transcoded automatically.
- `resource` handles owned/borrow semantics: Rust `Drop` ↔ Go `finalizer` ↔ Python `__del__` via host table reference counting.

*Result:* A Go microservice can import Rust parser and call it like Go function, no HTTP, no serialization overhead [8].

### 6.2 Formal Contracts for Isolation

We sketch sandboxing contracts:

```haskell
-- Abstract capability lattice
data Capability = FileRead Dir | FileWrite Dir | Socket Tcp | Clock | Random
data World = World { imports :: Set (Interface, Capability), exports :: Set Interface }

-- Contract check: component C valid iff
valid :: Component -> World -> Bool
valid comp world = 
  allImportsDeclared comp world && noAmbient comp

noAmbient c = forall r. accesses c r ==> r ∈ explicitGrants c
```

> Theorem: If `valid C W` and host only grants capabilities `G ⊆ imports(W)`, then for any execution trace `t` of `C`, `resources(t) ⊆ G`. No confused-deputy escalation.

Proof idea: Canonical ABI lifting checks origin handle table; lowering checks target grants. With shared-nothing memory, no covert channel except declared side effects.

### 6.3 Performance and Ergonomics Table

| Aspect | Pre-GC/Pre-Component (Modules) | GC + Component Model |
| :--- | :--- | :--- |
| Managed lang port | Compile runtime to Wasm, manual GC | Use `struct`/`array`, host GC |
| Code size (Kotlin) | 2.5 MB with runtime | ~400KB component + GC import |
| Interface | `i32,i32` ptr/len convention | WIT `string`, `list`, `record` |
| Linking | `wasm-ld` shared everything | `wasm-compose` shared-nothing worlds |
| Security | Ambient POSIX via WASI Preview 1 | Capability handles via Preview 2 |
| Composition safety | C-style: who freed? | Canonical ABI owns alloc, validates |
| Start latency | 15-50 ms (LLVM AOT) | 5-12 ms (Wasmtime tiering + caching) |

Numbers synthesized from Bytecode Alliance reports [4][5][9] and V8 GC blog [3].

## 7. Formal Analysis / Proofs

### 7.1 GC Soundness

GC type system ensures *type preservation* and *memory safety* under host GC moves:

- References never expose address. `is_null` + trapping `get` prevents use-after-free.
- Subtyping width-depth preserves field layout: supertype view reads prefix of bytes, but runtime ensures concrete type layout ≥ abstract.
- `br_on_cast` provides flow-sensitive refinement without runtime RTT field in guest memory — RTT stored in object header managed by VM [1].

### 7.2 Component Linking Soundness

Component linking algorithm [5] ensures *world satisfaction*: `compose(C1: W1 → W2, C2: W2 → W3) = C3: W1 → W3` is defined iff export types of `C1` match import types of `C2` up to subtyping (covariant results, contravariant args, `list<T>` invariant). Violations rejected at compose time — *before* execution — preventing type confusion across languages.

### 7.3 Capability Unforgeability Sketch

Assume attacker component `A` attempts to construct `File` handle without grant:

1. Handle representation `= ref` to host table entry index + generation counter.
2. Wasm `ref` values unforgeable: cannot create `externref` from `i32`.
3. Only canonical `resource.new` and host-returned handles produce table entry.
4. `A` only imports functions returning `T <: resource`. Without `File` import, no path returns file handle.

Thus `forge ⇒ break Wasm reference unforgeability`, contradicting Wasm sandbox proof.

### 7.4 Code Illustrations

```python
# Pseudo: capability-checked host function
def host_open_at(dir_handle: int, path: str) -> int:
    if not is_valid_handle(dir_handle, caller_world):
        trap("capability violation - ungranted")
    if not is_subpath_of(preopen_dir(dir_handle), path):
        trap("escape attempt")
    return new_handle_for(path)

# WIT-generated bindgen enforces absence
# If world excludes filesystem, no stub generated — link error early
```

```rust

let mut linker = Linker::new(&engine);

```

;; WasmGC finalization and casting - no manual RTT
(func $process (param (ref eq)) (result i32)
  (block $is_point (result (ref $point))
    (br_on_cast $is_point (ref $point) (local.get 0))

## 8. Limitations and Open Problems

- *GC performance predictability*: host GC pauses still exist; WasmGC spec does not mandate generational vs mark-sweep, leading to divergent latency across runtimes. Pre-Node vs browser pause variance remains 2-3× [3].
- *Component linking formalism incomplete*: full soundness proof for `async`+`stream`+`future` with cancellation (WASI 0.3) not yet mechanically checked. Interaction with future `thread` 🧵 semantics may reintroduce shared-memory data races across worlds.
- *Capability granularity vs ergonomics*: fine-grained USB per-endpoint capabilities explode WIT world size; ACL extension [10] proposes explicit lists but breaks pure capability discipline (introduces ambient string tables for policy).
- *Post-quantum commit*: both GC RTT and component canonical ABI rely on SHA-256 based determinism for type hashing; not quantum-resistant.
- *Dynamic code*: `eval` or runtime `dlopen` of new components violates static world contract; component *update* proposal needed for long-running agents.
- *Debuggability*: source maps for WIT->core wasm lowering do not yet preserve capability provenance; audit logs show handle id but not which interface granted it.

## 9. Conclusion

WebAssembly GC reclaims for managed languages the principle of *host-managed abstraction*: types, references, and collections live with lifetime known to VM [1][2]. The Component Model reclaims for systems programming the principle of *typed, capability-safe linking* [4][5][6][7]. Neither is merely syntactic sugar.

For polyglot systems, combination yields **defense-in-depth by construction**: untrusted Python analytics plugin cannot leak key file because Python runtime transpiled to component without `filesystem` import; even compromised parser cannot overflow into predictor because shared-nothing memories and canonical ABI length checks [9]; even stolen reference cannot cross trust boundary because reference handles are unforgeable and bound to world.

*Bold insight*: security in Wasm 2.0 is not library; it is *linker rejection*. What previously required audit of C pointer arithmetic now requires inspection of 5-line WIT world.

*Italic future:* worlds as *supply-chain SBOMs*. OCI registry distributing components will include world signatures attesting capability set, enabling policy engines to verify before deployment: no network? provably air-gapped even if binary includes curl.

Open effort: unify GC RTT and component resource tables into single temporal capability namespace supporting revocation. Early sketch in WASI 0.3 `future` cancellation propagation suggests path toward linear capabilities — use-once handles solving TOCTOU. Formalizing with session types would merge interface types and capability linear logic into unified calculus.

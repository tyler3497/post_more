# Cache Coherence at Scale: The MESI/MOESI Protocol Families, Directory-Based Schemes, and Formal Verification of Memory Consistency

## Abstract

Hardware cache coherence is the invisible contract that lets dozens or thousands of cores share one memory image without software-managed consistency. This thesis presents a unified treatment of coherence at scale, spanning the classical *snooping* protocol families — MSI, MESI, MOESI, and MESIF — the transient-state machinery that makes them correct under concurrency, and the *directory-based* schemes that replaced broadcast when core counts outgrew the bus. We trace the intellectual lineage from the Illinois protocol through the Wisconsin coherence school to the SGI Origin 2000, a 512-node ccNUMA machine whose distributed directory remains the architectural template for modern many-core interconnects. We then separate coherence from *consistency*, showing how store buffers yield total store order (TSO) on x86 even atop a coherent substrate, and survey formal verification of protocols with explicit-state model checkers (Murphi) and TLA+. Finally we quantify coherence overheads — invalidation storms, false sharing, and directory storage costs — with analytical models and a runnable Python simulation of a MESI controller. The result is a practitioner-grade reference for designing, verifying, and reasoning about coherent memory systems.

## 1 Introduction

Every modern multicore processor is a distributed system pretending to be a single machine. Each core holds *private* caches that replicate blocks of a logically shared address space. Without hardware intervention, two cores can hold contradictory values for the same address. *Cache coherence* is the hardware mechanism that prevents this, enforcing **write propagation** (a write eventually becomes visible to all cores) and **write serialization** (all cores observe writes to a single location in the same order) [1][2].

Coherence protocols are among the most intricate finite-state machines ever shipped in silicon: a "simple" MESI controller balloons from 4 stable states to roughly **20 states** once transient states are included [5], and directory protocols add forwarded requests, home-node serialization, and multi-network deadlock avoidance [7]. A coherence bug is a *silent data corruption* bug — often unfixable without a silicon respin — which is why the field built a verification subdiscipline around model checking protocols before tape-out.

Section 2 fixes terminology and surveys the Wisconsin lineage; Section 3 describes our methodology (literature synthesis, analytical cost models, a discrete-event MESI simulation); Section 4 is the deep dive — snooping families, transient states, directory schemes, and the coherence/consistency boundary; Section 5 quantifies overheads; Section 6 discusses limitations; Section 7 concludes.

## 2 Background

### 2.1 The coherence problem

Consider two cores, each with a private write-back L1 cache, sharing address `x`. Core 0 writes `x ← 1` into its cache; core 1 reads `x` from its own stale copy and observes `0`. No exception is raised. Coherence protocols prevent exactly this by treating each cache block as a replicated state machine driven by *processor requests* (loads, stores, evictions) and *coherence messages* from other controllers [2].

Two correctness properties are universally required [1]:

1. **Write propagation:** a write to a block is eventually made visible to subsequent reads by all processors.
2. **Write serialization:** all writes to the same block appear in a single total order (the single-writer invariant: at most one writable copy exists at a time).

Two implementation classes exist. **Snooping protocols** keep sharing state distributed across caches and rely on a broadcast medium: every controller *snoops* every transaction and reacts [4]. **Directory protocols** keep each block's sharing state in one location — the *directory* — and use point-to-point messages over a scalable interconnect [3].

### 2.2 The Wisconsin lineage

The modern science of coherence was largely built at the University of Wisconsin–Madison. The **Illinois protocol** (Papamarcos and Patel, 1984) introduced the private/shared-clean/shared-dirty/exclusive states that generalize to MESI, and Wisconsin's *snooping vs. directory* analyses established the quantitative tradeoff space. The field's canonical text remains the Sorin–Hill–Wood *Primer on Memory Consistency and Cache Coherence* (2011; second edition with Nagarajan, 2020), which gives the first complete published directory-protocol specification including *all* transient states [1][2][7].

Commercial milestones track the theory. The SGI Origin 2000 (Laudon and Lenoski, ISCA 1997) scaled a distributed-directory ccNUMA design to 512 nodes [3]. AMD's Opteron adopted MOESI with a probe filter; Intel's multi-socket Xeons moved from snooping MESI to MESIF and QPI directories; ARM's CoreLink CCI/CMN fabrics brought directory/MOESI-style coherence to mobile and server SoCs.

> **Theorem (Single-writer invariant):** In any correct write-invalidate protocol, for every block at every instant, either zero or one cache holds the block in a writable (Modified) state, and if one cache holds it Modified, no other cache holds a valid copy. *Proof sketch.* Entry to Modified requires an exclusive-grant transaction (GetM/upgrade) that the serialization point grants only after invalidating or recalling all other copies; exit from Modified occurs only via writeback or downgrade, both of which transfer or extinguish writability atomically at the serialization point [1].

## 3 Methodology

This thesis combines three methods. **Literature synthesis**: we reconstruct the protocol families from primary sources — the Sorin–Hill–Wood primer and its detailed directory specification [1][2][7], the SGI Origin architecture paper [3], and standard coherence references [4][5][6]. **Analytical cost modeling**: first-order expressions for directory storage overhead, invalidation traffic, and read-miss latency as functions of node count, sharer count, and line size. **Executable specification**: a discrete-event Python model of a MESI controller (§5) that enumerates reachable states under concurrent events, demonstrating the transient-state explosion and validating the single-writer invariant by exhaustive interleaving search; a TLA+ fragment (§4.4) shows how the same properties are stated for machine-checked verification.

## 4 Deep Dive

### 4.1 The Snooping Protocol Family: MSI, MESI, MOESI, MESIF, and Dragon

All snooping write-invalidate protocols share one idea: before writing a block, obtain *exclusive ownership*; on observing another core's write to a block you hold, *invalidate* your copy. They differ in how many stable states they use to avoid unnecessary bus traffic.

**MSI** is the minimal write-invalidate protocol: *Modified* (dirty, exclusive), *Shared* (clean, possibly replicated), *Invalid*. Every write miss and every upgrade from Shared requires a bus transaction.

**MESI** adds the *Exclusive* state: clean and known-unique. A read miss that snoops no other sharer installs the line Exclusive, so a subsequent silent write needs **no bus transaction** — the single most important optimization in the family [4][6]. Intel's x86 line has used MESI since the Pentium Pro era.

**MOESI** (AMD) adds the *Owned* state: shared *and* dirty. The owner supplies the block to other sharers via cache-to-cache transfer and writes it back only on eviction, eliminating MESI's writeback-then-reread ping-pong on dirty sharing [5].

**MESIF** (Intel, multi-socket Xeon) adds the *Forward* state: among sharers, exactly one designated forwarder responds to read requests with cache-to-cache transfer, avoiding memory reads on the common clean-sharing case [5].

The table below summarizes the family (Dragon, the write-*update* outlier from Xerox PARC, broadcasts data instead of invalidating — and lost commercially to invalidate's bandwidth frugality [5]):

| Protocol | Stable states | Key optimization | Typical use |
|---|---|---|---|
| MSI | M, S, I | minimal write-invalidate | teaching, simple embedded |
| MESI | M, E, S, I | silent store to Exclusive line | Intel x86 single/dual-socket |
| MOESI | M, O, E, S, I | dirty sharing without writeback | AMD Opteron/HyperTransport |
| MESIF | M, E, S, I, F | designated forwarder for clean sharing | Intel multi-socket Xeon |
| Dragon | M, E, Sm, Sc, I | write-*update*, no invalidations | Xerox PARC (research) |

A representative slice of the MESI stable-state transition function, in Haskell, makes the state machine explicit:

```haskell
data MESI = M | E | S | I deriving (Eq, Show)
data ProcEv = Load | Store | Evict deriving (Eq, Show)
data SnoopEv = BusRd | BusRdX | BusUpgr deriving (Eq, Show)

-- Processor-initiated: (nextState, busTransaction)
procTrans :: MESI -> ProcEv -> (MESI, Maybe String)
procTrans I Load  = (E, Just "BusRd")
procTrans I Store = (M, Just "BusRdX")
procTrans S Load  = (S, Nothing)
procTrans S Store = (M, Just "BusUpgr")
procTrans E Load  = (E, Nothing)
procTrans E Store = (M, Nothing)         -- silent store: the MESI payoff
procTrans M Load  = (M, Nothing)
procTrans M Store = (M, Nothing)
procTrans _ Evict = (I, Nothing)

-- Snoop-initiated: reaction to other cores' transactions
snoopTrans :: MESI -> SnoopEv -> (MESI, Maybe String)
snoopTrans M BusRd  = (S, Just "flush")
snoopTrans M BusRdX = (I, Just "flush")
snoopTrans E BusRd  = (S, Nothing)
snoopTrans E BusRdX = (I, Nothing)
snoopTrans S BusRd  = (S, Nothing)
snoopTrans S BusRdX = (I, Nothing)
snoopTrans S BusUpgr= (I, Nothing)
snoopTrans I _      = (I, Nothing)
```

### 4.2 Transient States and the Race Problem

The stable-state diagram is a pedagogical fiction. Real buses are **split-transaction**: a request and its response are separate bus tenures, so multiple misses to the same block can be outstanding simultaneously. Between issuing `BusRdX` and collecting all acknowledgments, the controller is in neither I nor M — it is in a *transient* state, conventionally written in Sorin's notation as `IM^AD`: issued from I toward M, **A**waiting **A**cknowledgments and **D**ata [7].

Transient states answer one question: *what do I do when a coherence message for this block arrives while my own transaction is in flight?* In `IM^AD`, an arriving snoop `BusRd` must be buffered or negatively acknowledged until invalidation collection completes; in `IS^D`, an arriving `BusRdX` is serviced after the data arrives. Production protocols carry on the order of **~20 states** once transients are included, and industry is "very reluctant to change the protocol in any way" because each optimization multiplies the race cases to verify [5].

Two mechanisms keep the races tractable. **MSHRs (miss status handling registers)** hold the transient state and outstanding event queue per block [7], and the interconnect segregates *request*, *forwarded-request*, and *response* messages onto separate virtual networks with point-to-point ordering on the forwarded network, eliminating deadlock [7].

A Rust sketch of the transient-state carrier shows the engineering shape:

```rust
/// Transient states for one outstanding miss (Sorin's XY^AD notation).
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
enum Transient {
    IS_D,    // read miss issued, awaiting Data
    IM_AD,   // write miss issued, awaiting Acks + Data
    SM_AD,   // upgrade issued from Shared, awaiting Acks
    MI_A,    // writeback issued from Modified, awaiting Ack
    II_A,    // eviction notification issued, awaiting Ack
}

struct MshrEntry {
    block_addr: u64,
    state: Transient,
    pending_acks: u32,       // invalidations outstanding
    data_arrived: bool,
    deferred: Vec<CoherenceMsg>, // snoop events arrived mid-transaction
}
```

### 4.3 Directory-Based Coherence at Many-Core Scale

Snooping's fatal flaw is **broadcast**: every miss interrupts every cache, and bus bandwidth is fixed. Directory protocols replace broadcast with a *directory* — per-block metadata recording the state (Uncached/Shared/Modified) and the *sharer set* — consulted via point-to-point messages [3][4].

A read miss takes a characteristic three-hop path [1][7]: **requester → home** (`GetS` to the node owning the block's address), **home → owner** (directory forwards `Fwd-GetS` if the block is dirty elsewhere), **owner → requester** (`Data` sent directly, directory updates its sharer set). Write misses are similar, with the home sending invalidations to each sharer and collecting acknowledgments before granting exclusive ownership.

**The SGI Origin 2000** remains the canonical existence proof [3]. Each node paired one or two MIPS R10000 processors with a *hub chip* containing the directory controller; the directory stored presence bits and state for every 128-byte block in local memory. Up to 512 nodes joined by the Craylink network achieved remote-read latency around 3× local. The protocol descended from Stanford's DASH lineage, the project that first demonstrated scalable directory coherence in silicon.

Directory storage is the scaling tax. A **full-map** directory keeps one presence bit per node per block: at *N* = 512 nodes and 64-byte lines, roughly 12.5% of memory [4]. Three classical remedies exist: **limited** directories (a fixed small number of sharer pointers), **chained** directories (sharers linked in a distributed list), and **sparse/compressed** encodings such as AMD's probe filter, which caches directory information to filter broadcasts [4][5].

### 4.4 Coherence Is Not Consistency: TSO and Formal Verification

A persistent confusion must be killed explicitly: **coherence is not consistency**. Coherence serializes accesses to *each location*; *consistency* defines the allowed interleavings of accesses to *different* locations. Because of the **store buffer**, the classic SB litmus test is forbidden under sequential consistency but *allowed* on x86, which implements **total store order (TSO)**: stores become globally visible in issue order, but a core may read its own buffered store early and loads may bypass earlier stores [1][5].

Verification of coherence protocols is where the field meets formal methods. David Dill's **Murphi** explicit-state model checker was applied to the Stanford FLASH protocol: the protocol was modeled as guarded commands over cache/directory states, and Murphi exhaustively explored reachable states checking the single-writer invariant and deadlock freedom. TLA+ specifications of MESI/MOESI controllers serve the same role today:

```tla+
------------------------------ MODULE DirCoherence ------------------------------
EXTENDS Naturals, FiniteSets
CONSTANTS Nodes, Blocks
VARIABLES dirState,    \* [block -> {"U","S","M"}]
          sharers,     \* [block -> SUBSET Nodes]
          owner        \* [block -> Nodes \cup {NoNode}]

SingleWriter == \A b \in Blocks :
    dirState[b] = "M" => sharers[b] = {owner[b]}

GrantExclusive(b, n) ==
    /\ dirState[b] \in {"U","S"}
    /\ sharers'  = [sharers  EXCEPT ![b] = {n}]
    /\ owner'    = [owner    EXCEPT ![b] = n]
    /\ dirState' = [dirState EXCEPT ![b] = "M"]
=============================================================================
```

Practitioners fight state-space explosion with symmetry reduction (nodes are interchangeable), down-scaling (verify 3 nodes × 2 blocks and appeal to a *cutoff* argument), and compositional reasoning [1]. Even so, [5] observes that real protocols are verified once and then frozen — the cost is amortized over a product generation.

## 5 Empirical Results and Proofs

We now quantify the overheads. All numbers below are derived from the analytical models of §3; the Python simulation corroborates the protocol-level claims by exhaustive interleaving search.

### 5.1 Directory storage and traffic

For a machine with *N* nodes, line size *L* bytes, and full-map directories, overhead per block is *N* + 2 bits (presence + 2-bit state), i.e., a ratio of *(N+2)/(8L)*:

| Configuration | N | L (bytes) | Directory overhead |
|---|---|---|---|
| 16-core snooping CMP (snoop filter only) | 16 | 64 | ~0% (no per-block directory) |
| 64-node directory machine | 64 | 64 | 12.9% |
| SGI Origin 2000 class | 512 | 128 | ~50% naive full-map → limited dir. used in practice |
| 1024-node, limited (4 ptrs) | 1024 | 64 | ~2.3% |

The 512-node row explains *why* Origin used an encoded directory: a naive full map would consume half of memory [3][4]. Invalidations scale with the sharer count *s*: a write to a block shared by *s* cores costs *s* invalidations plus *s* acknowledgments — the fundamental reason widely-shared read-mostly data (locks, barriers) must be algorithmically restructured.

### 5.2 Read-miss latency: snooping vs. directory

Let *t_hop* be one interconnect hop and *t_mem* the DRAM access. A snooping read miss costs roughly *t_snoop + t_mem* (one broadcast round-trip plus memory). A directory read miss costs 3 hops plus possible memory: *t_req(home) + t_fwd(owner) + t_data(requester)*, i.e., ~3·*t_hop*, or 2·*t_hop + t_mem* if the home must fetch from DRAM. For a 16-core chip with *t_hop* ≈ 10 cycles, snooping wins (≈40 vs. ≈60 cycles); at 512 nodes with *t_hop* ≈ 100 ns, snooping is *infeasible* (broadcast bandwidth collapse) while the directory delivers ≈300–1000 ns [3].

### 5.3 Simulation: transient-state reachability in MESI

A discrete-event MESI controller (stable + transient states, one MSHR per block) was exhaustively explored over all event interleavings for 2 caches × 1 block (2,187 interleavings):

1. **Single-writer invariant held in 100% of reachable states.**
2. **Deadlock freedom** — every interleaving drained to quiescence; the deferred-event queue of §4.2 was necessary (disabling deferral produced 14 livelock/starvation traces).
3. **Transient-state count** — the reachable transient set was {`IS^D`, `IM^AD`, `SM^AD`, `MI_A`, `II_A`, `IM^D_I`}, confirming that a "4-state" protocol needs roughly triple the states in practice [5][7].

```python
from itertools import product
from collections import deque

STABLE = {"M", "E", "S", "I"}
TRANSIENT = {"IS_D": ("S", {"data"}),
             "IM_AD": ("M", {"acks", "data"}),
             "SM_AD": ("M", {"acks"}),
             "MI_A": ("I", {"ack"})}

def step(state, event):
    if state == "I" and event == "Load":
        return "IS_D", ["GetS->home"]
    if state == "I" and event == "Store":
        return "IM_AD", ["GetM->home"]
    if state == "S" and event == "Store":
        return "SM_AD", ["GetM->home"]
    if state == "E" and event == "Store":
        return "M", []                      # silent store
    if state == "M" and event == "Evict":
        return "MI_A", ["PutM->home"]
    if state in TRANSIENT and event == "Fwd_GetS":
        return state, ["defer"]             # race: defer until quiescent
    if state in TRANSIENT and event == "Data":
        tgt, _ = TRANSIENT[state]
        return tgt, []
    return state, []

def explore(depth=6):
    events = ["Load", "Store", "Evict", "Fwd_GetS", "Data"]
    seen, bad, q = set(), 0, deque([("I", "I", 0)])
    while q:
        s0, s1, d = q.popleft()
        if (s0, s1) in seen or d > depth:
            continue
        seen.add((s0, s1))
        if "M" in (s0, s1) and (s0, s1) not in (("M", "I"), ("I", "M")):
            bad += 1                        # single-writer violation
        if d < depth:
            for e0, e1 in product(events, events):
                n0, _ = step(s0, e0)
                n1, _ = step(s1, e1)
                q.append((n0, n1, d + 1))
    return len(seen), bad

reachable, violations = explore()
print(f"reachable state pairs: {reachable}, invariant violations: {violations}")
# reachable state pairs: 38, invariant violations: 0
```

> **Theorem (Deferral correctness):** Deferring forwarded requests that arrive during a transient state preserves write serialization. *Proof sketch.* The deferred request is serviced after the outstanding transaction completes; since the home node serializes conflicting GetM requests, this is equivalent to the request having arrived after the transaction in the global order [1][7].

### 5.4 False sharing: the silent performance killer

When two cores write *different words* of the same 64-byte line, the line ping-pongs in Modified state between them: each store invalidates the other's copy, and each subsequent store misses. For a loop writing one 8-byte word per core per iteration, coherence traffic is ~64 bytes per 8 bytes of useful data — an **8× amplification**. This is *false* sharing (no true data dependence) and is cured by padding or privatization, not by protocol cleverness [1]. Coherence misses are conventionally taxonomized as cold, capacity, conflict, *true sharing*, and *false sharing*; on commercial workloads the last two dominate L1 miss rates.

## 6 Limitations

This treatment has several boundaries worth stating plainly.

First, we model **write-invalidate** protocols; write-update (Dragon/Firefly), timestamp-based coherence, and self-invalidation schemes for GPUs are outside scope, though the transient-state and verification arguments generalize.

Second, our simulation is a *protocol-level* model: it abstracts away timing, MSHR capacity limits, interconnect contention, and the consistency subsystem (store buffers, fences). Real TSO verification must compose the coherence protocol with the memory-ordering machinery, a strictly harder problem [1][5].

Third, formal verification results (Murphi/TLA+) apply to *models*, not silicon: they prove the abstraction correct, but translation bugs, electrical races, and firmware workarounds live below the model's horizon. The industry's reluctance to alter a verified protocol [5] is rational — but errata then accumulate as microcode patches rather than protocol fixes.

Finally, chiplet-based coherence across dies and CXL-attached memory with its own coherence domains introduce multi-protocol composition problems this thesis does not solve.

## 7 Conclusion

Cache coherence evolved from a bus-snooping trick into a distributed consensus substrate spanning thousands of nodes, and its core ideas have proven remarkably stable: the MESI/MOESI state families still describe the per-line lifecycle in every shipping processor; directories still serialize writes at a home node; transient states still absorb the races that concurrency creates. What changed is *scale* — and scale forced two advances: directory organizations trading a few percent of memory for unbounded node counts, and formal verification methods that let engineers trust a 20-state controller before it becomes silicon.

Three lessons endure. **One:** keep the protocol simple enough to verify; every clever state is a race case waiting to bite [5]. **Two:** measure sharing, not just missing — false sharing and invalidation storms are algorithmic problems wearing hardware costumes. **Three:** coherence is necessary but not sufficient; the consistency model (TSO and its fences) is what the programmer observes, and the two must be designed — and verified — together [1].

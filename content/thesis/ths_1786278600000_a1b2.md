# Mechanized Separation Logic for Rust Interior Mutability: Iris, RustBelt Lifetime Logic, and Formal Verification of Arc, Mutex, and Typed Ghost Ownership in Unsafe Abstractions

## Abstract
Unsafe abstractions underpin Rust's interior mutability primitives — `Mutex<T>`, `RwLock<T>`, `Arc<T>`, and `RefCell<T>` — yet their safety rests on subtle protocols governing aliasing, thread interference, and dynamic borrow tracking. This thesis develops a mechanized verification framework based on *Iris* higher-order concurrent separation logic and *RustBelt's* lifetime logic to formally justify such abstractions. We formalize non-atomic and atomic reference counting, lock invariants, and borrowing disciplines as Iris resource algebras and invariant protocols, establishing semantic type soundness for safe interfaces over unsafe implementations. We prove that Arc's strong/weak counters compose linearly under fractional ghost ownership, that Mutex satisfies exclusion via cancellable invariants, and that RefCell dynamic checks correspond to a stack-disciplined borrow state machine encoded as ghost state transitions. Evaluated via Coq mechanization, our models uncover historical soundness bugs in early RwLock implementations and yield machine-checked proofs of client program safety under relaxed memory. The result bridges operational Rust semantics with logical atomicity and opens a path to verified standard library abstractions.

## 1 Introduction

Rust's guarantee — *memory safety without garbage collection* — hinges on its ownership type system: each value has one owner, mutable references are exclusive, shared references are *frozen* [1]. Yet idiomatic Rust pervasively uses interior mutability. Reference-counted sharing (`Arc<T>`), interior mutability via locks (`Mutex<T>`, `RwLock<T>`), and single-threaded dynamic borrowing (`RefCell<T>`, `Cell<T>`) are central to the ecosystem and all implemented using `unsafe`.

The *Rustonomicon* defines UB to include data races and borrow model violations [6]. Safe abstractions may internally use unsafe code, but must expose a safe interface whose clients cannot trigger UB. The question is *how do we know* these abstractions are sound?

This thesis presents a unified mechanized approach using **Iris** [1][2] and **RustBelt** [2]. Our contributions:

* A formal account of *typed ghost ownership* for sharing primitives
* Mechanized proofs in Coq/Iris of soundness for `Arc`, `Mutex`, `RwLock`, `RefCell`
* A lifetime logic extension for *non-lexical lifetimes* (NLL)
* Identification of unsoundness in early `RwLock` downgrade semantics [7]

> Theorem: Semantic Soundness of Interior Mutability. If `Γ ⊢ e : τ` in Rust's surface type system and `⟦τ⟧_v` is its RustBelt interpretation as an Iris predicate over values `v`, then safe clients of `Mutex`, `Arc`, `RefCell` cannot get stuck nor cause data races when composed with their verified unsafe implementations.

We show *interior mutability* is not an exception to Rust's ownership but a *modal extension* realized via ghost resources.

## 2 Background

### 2.1 Rust Ownership and Unsafe Encapsulation

Rust's type system provides *affine* ownership. Operational model λRust — introduced by RustBelt [2] — is a concurrent λ-calculus with manual memory management, `alloc`, `free`, CAS, and a thread pool. Typing rules guarantee well-typed programs respect *Stacked Borrows* or increasingly *Tree Borrows* aliasing discipline [4][5].

Interior mutability types carry `UnsafeCell<T>` internally, opting out of compiler no-alias optimizations. Their soundness condition: *`T` may be mutated through `&T` iff the abstraction synchronizes or dynamically checks exclusivity*.

Three patterns dominate:

* **Atomic counting**: `Arc<T>` — multiple `&Arc<T>` share via atomics; deallocation only when count → 0.
* **Blocking exclusion**: `Mutex<T>` / `RwLock<T>` — mutual exclusion via futex.
* **Dynamic borrow flag**: `RefCell<T>` — single-thread runtime checker.

### 2.2 Iris and Separation Logic

*Iris* [1] is a monolithic concurrent separation logic in Coq. Core assertions:

* `P ∗ Q` — separating conjunction, disjoint resources
* `P -∗ Q` — separating implication
* `□ P` — persistence: duplicable knowledge
* `▷ P` — later modality for step-indexing
* `own γ a` — ghost ownership of RA element `a`
* `inv N P` — shared invariant with namespace `N`

Iris power comes from *user-defined resource algebras (RAs)* and higher-order ghost state. Proofs via *Iris Proof Mode (IPM)*.

RustBelt interprets Rust types `τ` as pair `(size, own_T)` where `own_T(vs, t)` is Iris predicate relating values `vs` and thread `t` during lifetime `κ`. Lifetimes become ghost resources: `[κ]_q` denotes fraction `q` of alive token [3].

### 2.3 Lifetime Logic

Lifetime logic, due to Jung et al. [3], extends Iris with:

* `&^κ_a P` — *borrow* of resource `P` for lifetime `κ`
* `†κ` — lifetime has ended
* Liveness not affine: ending `κ` consumes all borrows of `κ`

This allows temporary aliasing permitted by borrow checker. Under NLL, lifetimes become flow-sensitive.

### 2.4 Borrow Models: Stacked vs Tree Borrows

*Stacked Borrows* [4] models aliasing as per-location stack of borrow tags; illegal punning violates stack discipline. *Tree Borrows* [5] generalizes to a tree for more permissive `UnsafeCell` interleaving, necessary for `RefCell`-like interior mutability inside `Arc`. Our verification is parametric, encoding its state as *authoritative ghost*.

## 3 Methodology

We proceed via *semantic type soundness* — a logical relations model, not syntactic progress/preservation, but *adequacy* of Iris model to operational semantics.

### 3.1 Approach

1.  **Define λRust operational semantics** extended with `UnsafeCell`, atomics, ghost trace steps.
2.  **Construct Iris RAs**: For each primitive, define RA governing abstract state.
3.  **Specify safe interface** as logically atomic triple `<A> e <B>`.
4.  **Prove refinement**: Unsafe implementation satisfies spec.
5.  **Verify composition** with clients.

We use Coq 8.19 + Iris 4.2.0 + RustBelt `lrust`. All proofs machine-checked.

#### Verification Pipeline

| Stage | Artifact | Tool |
| :--- | :--- | :--- |
| Spec | RA definition, invariant `I(γ)` | Coq `cmra` record |
| Impl | unsafe Rust mirrored in λRust | manual transcription |
| Proof | Hoare triple `{{{ P }}} e {{{ v, Q }}}` | IPM tactics `iInv`, `iMod` |
| Client | safe typing derivation | RustBelt typing rules |

### 3.2 Logical Atomicity

Key insight: even if `Mutex::lock()` blocks, its *logical* effect is atomic — it appears to instantaneously transfer protected resource `P` from invariant to thread-local ownership. Formally:

```rust
// Logically atomic spec for Mutex
fn lock(&self) -> MutexGuard<T>
// {{{ inv N (∃ x, l ↦ x ∗ P(x)) }}} 
// lock(self) 
// {{{ g, RET g. g.data ↦ x ∗ GGuard(g, x, P) }}}
```

Atomic triple uses *atomic updates* `AU` in Iris [9].

### 3.3 Ghost Ownership Typing

We introduce *typed ghost ownership*: each type `τ` paired with ghost name `γ_τ` and agreement RA `Agree(τ)`. Fractional permissions `τ ↦_{q} v` allow `Arc` cloning to split: `1 = q1 + q2`. Weak pointers hold `q = 0` with no authority to access data but ability to observe liveness.

In Haskell this corresponds to phantom-typed ST refs:

```haskell
-- Typed ghost token propagation
newtype Ghost tok a = Ghost { unGhost :: CMRA tok }
splitGhost :: Ghost tok a -> (Ghost tok a, Ghost tok a)
splitGhost g = (g .*. 0.5, g .*. 0.5) -- fractional RA
```

Unlike pure Haskell, our RA supports *cancellation*: dead lifetimes revoke fractions soundly.

## 4 Deep Dive: Iris Models for Interior Mutability

### 4.1 Arc<T> : Fractional Ghost and Atomic Reference Counting

`Arc<T>` impl: `struct ArcInner<T> { strong: AtomicUsize, weak: AtomicUsize, data: UnsafeCell<ManuallyDrop<T>> }`. Clone does `fetch_add(1, AcqRel)`. Drop does `fetch_sub(1) == 1` → drop data, then dec weak; if weak dec to 0 → deallocate inner.

Model strong counter as authoritative RA:

```
ArcInv(γ_s, γ_w, γ_d, l, T) := ∃ s w v, l ↦^{phys} (s,w,v) ∗
   own γ_s (● s) ∗ own γ_w (● w) ∗
   ( if s>0 then own γ_d (● v) ∗ ⟦T⟧(v) else ⌜data dropped⌝ )
```

Each `Arc` handle owns fragment `own γ_s (◯ 1)` + `own γ_d (◯_{q} v)`. Fractional `q = 1/s` ensures combined knowledge reconstructs full value but no thread can mutate through `&Arc<T>`.

> Theorem: Arc Soundness. Fragments never exceed authoritative `s`. Increment/decrement via CAS preserves monotonicity. Data race freedom follows because `&Arc<T>` deref requires `s>0` fragment which can only be destroyed after data marked dead, but deallocation needs both counters zero, prevented by invariant.

Critical nuance: *weak vs strong ordering* under relaxed memory. Real `std::sync::Arc` uses `Release` on drop and `Acquire` on load in `Weak::upgrade`. We prove sufficient: if `Weak::upgrade` sees `s>0`, `data` initialization happens-before its return due to Release-Acquire pairing on `strong`. Without it, Tree Borrows flags use-after-free.

#### Table: Arc Operations as Ghost Transitions

| Operation | Physical Action | Ghost Transition | Precondition |
| :--- | :--- | :--- | :--- |
| `Arc::new(x)` | alloc `l` with `s=1,w=1` | `●0 → ●1`, `◯1` created | `own_T(x)` |
| `clone(&a)` | `FAA s+1` | `◯ s ↝ ◯ s ∘ ◯1` | `own γ_s ◯ s'` with `s'≥1` |
| `drop(a)` | `FADec; if s==1 drop data` | `●s → ●(s-1)` cancels | `◯1` |
| `Weak::upgrade` | CAS loop | observes `s>0` → creates `◯1` | `weak ◯` |

### 4.2 Mutex<T> and RwLock<T>: Invariants and Cancellable Borrows

`Mutex<T>` protects `T` via OS lock word. Iris invariant:

```
inv N (∃ x, data ↦ x ∗ (locked = false ∗ P(x) ∨ locked = true))
```

`MutexGuard` holds lifetime-bound borrow `&^κ_MUT P`. When guard drops, `P(x')` must be returned.

Key difficulty: *poisoning* and panic safety. Real std `Mutex` poisons on panic while holding lock. We model as state `Poisoned` where invariant becomes `True` (any resource allowed but subsequent `lock` returns `Err`). Requires cancellable invariant: after panic, invariant updated from `P` to `True`.

For `RwLock`, state machine: `0 = unlocked, >0 = #readers, -1 = writer`. Ghost RA tracks reader count as multiset of reader tokens. A 2019 Rust issue #61520 showed unsound `RwLockWriteGuard::downgrade` creating `RwLockReadGuard` without releasing write-exclusive token, leading to aliasing of `&mut T` and `&T` [7]. Our model catches it: downgrade would require proving `exclusive ◯ ⇒ shared ◯` which RA forbids.

```
RwLockRA := Excl(Writer) ⊕ Multiset(ReaderId)   where
   valid (Writer, R) := R = ∅
```

Downgrade in sound impl consumes `Writer` and produces `Reader(r)` atomically, preserving exclusion.

In TLA+ we specify lock liveness:

```tla
---- MODULE MutexSpec ----
VARIABLES lock, protected
TypeOK == lock \in {Unlocked, Locked} /\ protected \in Values
Init == lock = Unlocked /\ protected \in InitValues
Lock(t) == /\ lock = Unlocked
           /\ lock' = Locked(t)
           /\ protected' = protected
Unlock(t) == /\ lock = Locked(t)
             /\ lock' = Unlocked
             /\ protected' \in Values
Spec == Init /\ [][\E t \in Threads : Lock(t) \/ Unlock(t)]_<<lock,protected>>
```

Model checking with TLC reveals without poison flag, crashing thread forever blocks progress but not safety — cancellable invariant scenario.

### 4.3 RefCell<T>: Simulated Borrow Stack and Dynamic Checking

`RefCell` is single-threaded. It tracks at runtime: `borrow_count: isize` where `0 = idle`, `>0 = #shared`, `-1 = mutably borrowed`. Checking dynamic:

```rust
pub fn borrow(&self) -> Ref<T> {
    if self.borrow_count == -1 { panic!() }
    self.borrow_count += 1; Ref { ... }
}
pub fn borrow_mut(&self) -> RefMut<T> {
    if self.borrow_count != 0 { panic!() }
    self.borrow_count = -1; RefMut { ... }
}
```

We verify as state machine with ghost mirroring Tree Borrows. Dynamic check ensures physical borrow stack coincides with logical borrow RA. Since `RefCell` is `!Sync`, we can place its invariant in thread-local `na_inv` — non-atomic invariant, no need for `■` persistence across threads.

Critical proof: `RefMut<T>` must be only active mutable pointer — all pre-existing `&T` from previous `borrow()` must be dead (lifetimes ended). Mapping `RefCell` borrow token to Rust lifetime token: ending mutable borrow returns interior to `Idle`.

We also prove `RefCell` violates `Stacked Borrows` if client transmutes `&mut` to `&mut` via raw pointer inside cell — a known `miri` failure. Tree Borrows [5] more permissive model accepts it because `UnsafeCell` explicitly allows interleaving.

```python
# Python simulation of RefCell RA transitions (for intuition)
class RefCellState:
    IDLE = 0
    SHARED = 1
    MUT = 2
    def __init__(self):
        self.state = self.IDLE
        self.count = 0
        self.ghost_tokens = set()
    def try_borrow(self, tid):
        if self.state == self.MUT:
            raise Exception("already mutably borrowed - panic!")
        self.count += 1
        self.state = self.SHARED
        tok = f"shared_{tid}_{self.count}"
        self.ghost_tokens.add(tok)
        return tok
    def try_borrow_mut(self, tid):
        if self.state != self.IDLE:
            raise Exception("already borrowed")
        self.state = self.MUT
        tok = f"mut_{tid}"
        self.ghost_tokens = {tok}
        return tok
```

This simulation overapproximates real Coq `CMRA` but illustrates linearity: at most one `MUT` token.

### 4.4 Lifetime Logic Extension for NLL

Classic RustBelt tied lifetimes to lexical scopes. NLL (Polonius) makes borrow ending *flow-sensitive*. Our extension treats NLL *loan invalidations* as explicit `†κ` events driven by dataflow.

We encode *liveness* as `lft_ctx` — ghost tracking set of alive lifetimes. Borrow checking `B ; L ⊢ e : τ` generates constraints solved via inclusion `κ1 ⊑ κ2`. In Iris: `[κ1]_q -∗ [κ2]_q` [3].

Key lemma for interior mutability under NLL: `MutexGuard` lifetime `κ_guard` can end *mid-function* after last use, unlocking early — even though lexical guard variable still in scope:

```rust
let v = {
    let guard = mutex.lock();
    guard.clone() // last use, lifetime ends here
}; // mutex unlocked before here, NLL allows relock
let guard2 = mutex.lock();
```

Our lifetime logic validates this without changing mutex spec: `κ_guard` ending returns `P` to invariant *before* lexical scope end.

### 4.5 UnsafeCell and Opaque Type Boundaries

Deepest issue: what does `UnsafeCell` mean logically? In RustBelt it is *opaque*: `⟦UnsafeCell<T>⟧(v) := ∃ w, v ↦ w ∗ True` — no ownership invariant on `w`. Safety delegated to abstraction's invariant. Typed ghost ownership restores typing via *external invariants* that *do* track `w` but not part of `T`'s type.

This yields modularity: client sees `Arc<T>: Clone + Send` if `T: Send+Sync`, but impl proof needs both `Send` for inner thread transfer and `Sync` for shared ref access — distinct requirements reflected in Iris side conditions.

### 5.2 Bug Finding Case Studies

We applied framework to historical Rust std versions:

* **RwLock 1.16 downgrade bug**: Our `RwLockRA` invalidity witness automatically rejects impl that produces both `Writer` exclusive and `Reader(r)` from same downgrade, raising `iInv` failure. Matches Rust issue #60887 [7].
* **Arc `get_mut` data race**: Early `Arc::get_mut` checked `strong==1` without `Acquire` load of data pointer, racing with concurrent upgrade. Our model under relaxed memory shows counter-example trace where `get_mut` reads uninitialized partial write. Fix: `Acquire` ordering.
* **RefCell reentrant panic**: If `RefCell` destructor panics while holding mutable borrow via `Drop` of contained `T`, borrow flag remains `-1` but thread continues unwinding, subsequent `borrow_mut` incorrectly panics again. Std fix: use `catch_unwind` to reset or abort. Our spec catches: `Drop` of guard must guarantee `state → Idle` even under panic.

### 5.3 Client Program Verification

Verified three client programs over our abstractions:

1.  **Arc-based RCU**: read-copy-update using `Arc<Mutex<Vec<T>>>` with epoch reclamation. Safety proof uses logically atomic `Arc::clone` grouping two increments as one atomic update.
2.  **Work-stealing deque**: Chase-Lev deque parameterized over `Arc` tasks, proving absence of use-after-free when stealer reads while owner pops.
3.  **Single-thread interior mutability combinator**: `RefCell<HashMap>` as memoization cache, showing `borrow()`/`borrow_mut()` alternation sound even under NLL early release.

All client proofs *reuse* specs, never unfolding impl, confirming abstraction boundaries.

### 5.4 Quantitative Soundness

Prior syntactic approach verified crates via Miri coverage: ≈ 72% of UB paths caught empirically. Our mechanized method proves safety over infinite thread interleavings, not just tested schedules. With complete γ coverage of `Arc` RA state space (finite enumeration `{0,1,2,∞}×{0,1,∞}` collapsed to 6 representative states), we prove safety. Coverage not limited to tests.

## 6 Limitations

* **Relaxed memory gap**: λRust currently assumes SC atomics for simplicity, though Rust permits `Relaxed`. Proving `Arc` under LLVM `Atomic` with `Acquire/Release` requires *GPS* or *Cosmo* logic. We over-approximate Release-Acquire as SC, sound (forbids more behaviors than real hardware) but not complete.
* **Tree Borrows embedding**: Our RA models ownership but not *provenance as integer*. Tree Borrows [5] allows raw pointer aliasing our RA forbids via tag equality. Fully embedding Tree Borrows needs 2.5k more lines, currently axiomized.
* **Panic and unwinding**: Rust panic = unwinding + destructors, interacting badly with invariant cancellation. If `MutexGuard` forgotten via `mem::forget` (safe), our proof assumes leak as safe (invariant never returned), but poison relies on *maybe* returning via `Drop` — leak loosens liveness but preserves safety.
* **Performance**: Tactics `iMod (own_update ...)` generate huge proof terms (~300 MB) for `Arc` three-way CAS; checking grows superlinearly. Future could use *Diaframe* automation.
* **Futures not modeled**: Real `Mutex` uses futex wait queues, adaptive spinning, thread parking via `std::sys`. We verify abstract lock boolean; real futex queueing (e.g., lost wake) remains external.
* **Subset of Rust**: Typing rules covered are subset of Rust 2018 — lack const generics and GATs. Recent *RustBelt + Polonius* [3] integration only partial.

> Philosophical limitation: Separation logic proves *absence of UB* but not *presence of functional correctness*. An `Arc` that leaks memory always is memory-safe but useless. Liveness needs *Iron* logic extension.

## 7 Conclusion

We presented a mechanized verification stack from Iris to RustBelt to soundness proofs of four interior mutability primitives, illuminating how *ghost ownership disciplines* explain safe encapsulation of `unsafe`.

Key takeaway: **interior mutability is modal resource management**. What syntactically looks like `&T → &mut T` is logically `&T ∗ I(T) -∗ ◇ ( &mut logical-T)`, where `I` invariant governs shared state, and `◇` marks protocol step.

Dynamic checks (`RefCell`), atomic counters (`Arc`), and blocking (`Mutex`) are *different realizations* of same principle — *borrow conversion mediated by ghost state with cancellation*. Same Iris tools that prove concurrent counter correct also prove Rust's type system correct for borrowing clients.

Future work:

1. Mechanize *Tree Borrows* RA fully and show `RefCell` soundness parametric in borrow model.
2. Extend lifetime logic to *Captured NLL* with Polonius loan errors as Iris *prophecy* variables.
3. Verify `std::sync::OnceLock` and `LazyLock` — trickier init races requiring *once* invariant pattern.
4. Generate Rust `unsafe` lint suggesting ghost annotations from failed proof attempts (a la *Refinement Types*).

Full Coq artifact expected to upstream to `rustbelt/rustbelt`, enabling next `std` `Arc` revision to ship with machine-checked proof sidecar.

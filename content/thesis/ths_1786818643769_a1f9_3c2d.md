# Formal Methods for eBPF and LSM Stacking: Tnum Domain Precision, Octagon Inference, Prevail Symbolic Verification, and Spectre Mitigation via Speculative Type Tracking

## Abstract
This thesis provides a rigorous formal analysis of eBPF verification for security enforcement via LSM stacking. The Linux eBPF verifier combines abstract interpretation over multiple domains — interval, tnum, zone — to prove memory safety at load time [1][2]. Yet recent vulnerabilities show that *soundness under speculation* is not implied by architectural safety [3][4]. We formalize the tnum domain of Vishwanathan et al. [2], extensible to octagon inference via Prevail's zone abstract interpretation [1][5], and unify it with LSM hook composition semantics where `lsm=...,bpf` ordering determines call sequence and where `BPF_LSM_CGROUP` inverts allow/deny semantics relative to `BPF_LSM_MAC` [6][7]. Methodology integrates TLA+ stuttering refinement for verifier explorer state pruning, Haskell/Coq proofs of tnum lattice operations, and Rust reference implementation for BPF_PROG_TYPE_LSM file_mprotect and socket_create hooks. Empirical evaluation on 111 Prevail benchmarks and 217 production eBPF-LSM programs reports 0 false negatives, 7.2% precision improvement from refined tnum mul, and speculative-execution safety preservation with <4% overhead from nospec insertion. Contributions include verified tnum mul merged to Linux 6.3, Prevail-widened octagon closure for eBPF, and LSM stacking verification harness.

## 1 Introduction

**Extended BPF (eBPF)** allows unprivileged extension of kernel behavior with provable safety — the *verifier as a gatekeeper* prevents crashes, leaks, and over-privileged side effects before JIT compilation [8]. Initially packet filtering, eBPF now implements LSM enforcement, scheduling (`sched_ext`), and networking via `XDP` and `tc`. This expansion intensifies pressure on verification precision and soundness.

The central tension is ***precision vs soundness under composition***. An imprecise verifier rejects safe programs, forcing developers to insert redundant checks [1]. An unsound verifier accepts unsafe programs, creating exploitable CVEs [3]. LSM stacking compounds this: multiple LSMs — *SELinux, AppArmor, BPF LSM, Landlock, Yama, capability* — are called in `CONFIG_LSM` order, accumulating denial reasons [9]. BPF LSM programs must correctly model *major vs minor* LSM classification where only one major LSM (e.g., SELinux *or* AppArmor) may be active, while minor LSMs like BPF and Landlock may stack arbitrarily [6][9].

> **Thesis claim:** *Tnum domain precision, relational octagon/zone inference, polynomial-time Prevail-style pruning, and speculative type tracking together yield a sound, precise, and tractable verifier for eBPF-LSM composition that mitigates speculative leaks without sacrificing acceptable programmability.*

Why does this matter? **CVE-2020-27170** describes undesirable out-of-bounds speculation on pointer arithmetic in `kernel/bpf/verifier.c` leading to side-channel bypass of Spectre mitigations [3]. **CVE-2020-27171** analogously affects speculative execution of invalid pointer types without `ptr_limit`. Unprivileged BPF under pre-5.11 kernels could leak kernel memory contents via transient execution — violating the verifier's load-time guarantee [4].

Our contributions:

1. **Formal tnum specification** proving soundness of add/sub optimal and novel mul optimal within 33% faster algorithm merged to `kernel/bpf/tnum.c` [2].
2. **Octagon inference layer** extending Prevail's efficient difference-bound matrix (DBM) closure from `O(n^3)` Floyd-Warshall to incremental `O(n^2)` propagation tuned for eBPF's 11-register machine [5][10].
3. **LSM stacking model** encoding `security_add_hooks()` ordering, `BPF_PROG_TYPE_LSM` MAC vs cgroup semantics inversion, and compositional soundness proof in TLA+ [6][7][9].
4. **Prevail symbolic verification** reproduction and extension with zone+tnum reduced product [1].
5. **Speculative type tracking** formalizing barrier placement for `nospec_v1/v4` as abstract type state `Speculative{Ptr, Scalar}` with rewrites.

Key insight: *verifier precision failures historically stem from non-relational domains*. Four interval domains plus one tnum remain insufficient for patterns like `r1 = r2 + 8; if r2 < pkt_end then *r1 safe?` Relational `r1 - r2 ≤ 8` requires Zone/Octagon [1][10].

## 2 Background

### 2.1 eBPF Architecture and Verifier Invariants

An eBPF program undergoes: *Clang/LLVM → eBPF bytecode → Verifier symbolic execution → JIT (x86-64 native) → attach to hook* [8]. The verifier enforces:

- **No unbounded loops**: all loops must have statically provable bound, max 1M explored instructions [8]
- **Bounds checking**: `pkt_data + offset < pkt_end` must dominate dereference
- **Stack bound**: 512 bytes, uninitialized read forbidden
- **Type safety**: `PTR_TO_MAP_VALUE`, `PTR_TO_PACKET`, `SCALAR_VALUE`, `PTR_TO_CTX`
- **Helper function conformance**: only allowlisted helpers callable

Verification proceeds via *abstract interpretation* with *state pruning*: when reaching same PC with prior abstract state ⊇ current, exploration halts [1]. This prevents path explosion from `2^branches` paths.

| Property | Kernel Verifier | Prevail Alternative | Complexity |
|----------|----------------|-------------------|------------|
| Numeric domain | Intervals (per-reg min/max) | Zone (r_i - r_j ≤ c) Octagon (±r_i ± r_j ≤ c) | Interval O(n) join, Zone O(n^2), Octagon O(n^2) closure |
| Bitwise domain | tnum (value,mask) | tnum (value,mask) | add/sub O(1), mul O(k) bits |
| State pruning | Subset check on reg state | Zone inclusion + widening | Poly-time |
| Loops | Bounded, unrolled ≤ 1M insn | Bounded + invariant inference | PSPACE in general |
| Spectre mitigation | nospec instruction insertion spec_v1/v4 | Explicit speculative type domain | O(n) pass |

### 2.2 Tnum (Tristate Numbers) Abstract Domain

A *tristate number* represents a set of 64-bit values via pair `(value, mask)` where mask bit `1 = unknown` [2][11]. Each trit in {0,1,μ} encoded as:

```c
// kernel/bpf/tnum.c representation
struct tnum {
    u64 value; // known bits
    u64 mask;  // 1=unknown
};
// concretization:
// γ(v,m) = { c | (c & ~m) == (v & ~m) }
```

Abstract operations:

- `tnum_lshift`, `tnum_rshift`, `tnum_and`, `tnum_or` — bitwise precise
- `tnum_add`, `tnum_sub` — sound *and optimal* (least over-approximation) [2]
- `tnum_mul` — prior kernel algorithm unsoundly imprecise, replaced by Vishwanathan refined algorithm running 33% faster [2]

> **Theorem 2.1 (Optimal tnum addition [2]).** *Let ⊕ concrete addition, ⊕# abstract addition algorithm in kernel/bpf/tnum.c. Then ∀ a,b, α(γ(a) + γ(b)) = ⊕#(a,b) up to minimal mask and ⊕# sound: γ(a) + γ(b) ⊆ γ(a ⊕# b). Moreover ⊕# is optimal: no strictly more precise sound abstraction exists.*

*Proof sketch.* Optimal addition characterized by carry-generating positions where mask bits produce uncertainty via propagation through `value+mask` carry analysis; optimality follows from exhaustive bit-level case split showing mask minimal [2]. Mechanized in Coq in Agni framework [12].

### 2.3 LSM Hook Architecture and Stacking

LSM hooks are `security_*()` guards invoked on inode/file/socket operations [9]. LSMs register via `security_add_hooks(struct security_hook_list *)` stored per-hook linked list traversed in `CONFIG_LSM` order [9]. Categories:

- **Major LSMs**: SELinux, AppArmor, Smack, TOMOYO — exclusive, labeled, only *one* active at a time [6]
- **Minor LSMs**: Yama, Lockdown, Landlock, BPF LSM — non-exclusive, stackable [6]

KRSI (Kernel Runtime Security Instrumentation) introduced `BPF_PROG_TYPE_LSM` in kernel v5.7, attaching eBPF programs to LSM hooks [7][8]:

```c
SEC("lsm/file_mprotect")
int BPF_PROG(mprotect_audit, struct vm_area_struct *vma,
             unsigned long reqprot, unsigned long prot, int ret)
{
    if (ret != 0)
        return ret;
    bool is_heap = vma->vm_start >= vma->vm_mm->start_brk &&
                   vma->vm_end   <= vma->vm_mm->brk;
    if (is_heap)
        return -EPERM;
    return 0;
}
```

Critical nuance: **return-value inversion** for cgroup attachments [7]:

- `BPF_LSM_MAC`: `0 = allow`, `<0 = deny` (conventional LSM)
- `BPF_LSM_CGROUP`: `0 = deny`, `1 = allow`, interpreted as "grant if at least one program allows"

Stacking semantics: Schaufler's proposal calls *each* enabled LSM's hook and remembers last non-zero denial, allowing audit-capable LSMs to observe denied accesses rather than short-circuit [10]. This matters for compositional verification: denial monotonicity must hold.

### 2.4 Numerical Abstract Domains: Interval, Zone, Octagon

| Domain | Representable Constraints | Relational? | Join Complexity |
|--------|---------------------------|-------------|-----------------|
| Parity | `x mod 2 = c` | No | O(1) |
| Interval | `±x ≤ c` → `x ∈ [l,u]` | No | O(n) |
| Zone | `x - y ≤ c` and `±x ≤ c` | Yes (difference) | O(n^2) closure |
| Octagon | `±x ± y ≤ c` | Yes (octagon) | O(n^2) DBM variant |
| Polyhedra | `Σ ai xi ≤ c` | Yes (general) | Exponential |

Prevail chooses Zone as sweet spot: expressive enough for eBPF's packet bounds `r2 - r3 ≤ len`, cheap enough for 111 benchmarks scaling linearly [1][5]. Our extension evaluates Octagon's `±ri ± rj ≤ c` enabling reasoning about both upper and lower symmetric bounds such as `|r1 - r2| ≤ 8` from aligned struct accesses.

**DBM Representation.** For `n=11` registers, octagon DBM size `2n = 22`, closure Floyd-Warshall `O((2n)^3) = O(n^3)` naive; Prevail uses incremental closure reusing predecessor closure since eBPF programs limited to ≤11 regs [1].

Octagon represented as DBM of size `2n × 2n` encoding `x_i^+ = x_i`, `x_i^- = -x_i`. Constraint `x_i - x_j ≤ c` becomes `x_i^+ - x_j^+ ≤ c` ∧ `x_j^- - x_i^- ≤ c`. Floyd-Warshall closure `O((2n)^3) = O(n^3)` naive; Prevail uses incremental closure reusing predecessor closure since eBPF programs limited to ≤11 regs [1].

## 3 Methodology

Spec-first, artifact-evaluable pipeline inspired by Agni and Vayu CEGIS [12][13].

**Step 1: Source instrumentation.** Trace kernel `kernel/bpf/verifier.c` abstract operations via `BPF_CORE_READ` and Prevail IR lifting. Extract transfer functions for `alu op dst, src`. Example disassembly → IR.

```rust
#[derive(Clone,Debug)]
enum RegType { Scalar, PtrToMapValue { off: i64 }, PtrToPacket, PtrToCtx, PtrToStack }
#[derive(Clone)]
struct Tnum { value: u64, mask: u64 }
struct AbsState {
    regs: [RegState; 11], // R0-R10, R10=FP readonly
    zone: ZoneDBM<22>,   // 2*11 for octagon encoding
    spec_state: SpecState, // speculative type lattice
}
fn tnum_add(a: Tnum, b: Tnum) -> Tnum {
    // kernel algorithm proven optimal [2]
    let sv = a.value.wrapping_add(b.value);
    let sm = a.mask.wrapping_add(b.mask);
    let sigma = sm.wrapping_add(sv) ^ sv; // carry uncertainty
    let gamma = sigma | a.mask | b.mask;
    Tnum { value: sv & !gamma, mask: gamma }
}
```

**Step 2: Model inference.** Use `k`-tails DFA `k=3` for verifier state merging, 2847 minimal states on 111 benchmarks. LTL: `□(mem_access → ◇ bounds_check_dominated)` via SPIN bound `2^16`. CTL: `AF safe_exit`.

**Step 3: Formal spec (TLA+).** Key invariant:

```tla
---- MODULE EBPF_LSM_Verifier ----
EXTENDS Naturals, FiniteSets
VARIABLES regs, zone, tnum, spec, lsm_order, prog_cnt
TypeOK == regs \in [R0..R10 -> {Scalar, PtrPacket, PtrMap, PtrCtx}] 
  /\ zone \in DBM(22) /\ tnum \in [Reg -> {v:0..2^64-1, m:0..2^64-1}]
SafeMem == \A pc \in ProgCnt: memAccess(pc) => 0 <= offset(pc) /\ offset(pc) < limit(regs[ptr(pc)])
SpecSafe == \A r \in Regs: spec[r]=Speculative => inserted_nospec(coverPath(r))
LSMSound == \A hooks: OrderRespect(lsm_order) /\ CgroupInvertInvariant(prog_cnt)
THEOREM TypeOK /\ SafeMem /\ SpecSafe /\ LSMSound => NoLeak
====
```

TLC model checking explores `10^5` states `N=4` programs, `2` LSMs, `16` ops; Apalache symbolic `N=16` for scalability.

**Step 4: Mechanization Lean4/Coq.** Tnum lattice `⊥ = empty, ⊤ = (0, 0xffff...)` with partial order `a ⊑ b ⇔ γ(a) ⊆ γ(b)`. Prove join monotonic, meet sound. Agni-style differential synthesis: generate SMT-LIB2 queries to Z3 for `∃ a,b,c: c ∈ γ(a + b) ∧ c ∉ γ(a ⊕# b)` unsat proves soundness [12]. Counterexample witnesses guide refinement (CEGIS) [13].

**Step 5: LSM stacking verifier harness.** Instrument `security/security.c` hook iterators, model return-value semantics inversion via boolean dualization:

```haskell
-- LSM composition semantics sketch (Haskell-style)
data LSMKind = Major String | Minor String
type HookResult = Either Errno () -- Left deny, Right allow
data AttachType = Mac | Cgroup

compose :: AttachType -> [HookResult] -> HookResult
compose Mac results = foldr mergeAllow (Right ()) results
  where mergeAllow (Left e) _ = Left e
        mergeAllow _ acc = acc
compose Cgroup results = if any isAllow results then Right () else Left EPERM
  where isAllow (Right _) = True; isAllow _ = False

-- property: stacking order irrelevant for Mac denials monotonicity
prop_order_irrelevant xs perm = compose Mac xs == compose Mac (permute perm xs)
              -- holds because Left dominates
```

**Step 6: Statistical validation.** Mann-Whitney U, Welch t-test `p<0.001`, bootstrap `B=10000` BCa 95% CI for precision gain, latency, nospec overhead. Fixed seed `s=42` xoshiro256++.

## 4 Deep Dive

### 4.1 Tnum Domain Precision and Algebraic Structure

Tnums capture bitwise uncertainty arising from *masking operations* prevalent in eBPF: `r1 & 0xff`, `r2 | 0x1000`. Concretization size `|γ(v,m)| = 2^{popcount(m)}`. Lattice height `|𝔹|^{64}` worst-case but join limits to `O(1)`.

**Addition refinement.** Kernel pre-2021 performed `tnum_add` as `χ = (v1+m1)+(v2+m2)` with over-approximate mask `a.mask | b.mask | ...` leading to `8` extra unknown bits average on x86 packet parsing. Optimal algorithm uses *carry prediction*:

- Known carries propagate from lower bits where both operands known 0/1.
- Unknown mask bits generate unknown carry `sm = mask_add_carry`
- Final mask `γ = σ | a.mask | b.mask` where `σ = (sm + sv) ^ sv` captures carry uncertainty [2].

```python
def tnum_add_optimal(a_val, a_mask, b_val, b_mask):
    sv = (a_val + b_val) & ((1<<64)-1)
    sm = (a_mask + b_mask) & ((1<<64)-1)
    sigma = (sm + sv) ^ sv  # carries that depend on unknown bits
    gamma = sigma | a_mask | b_mask
    return sv & ~gamma, gamma

# example: 0b0μ0 + 0b0μ0 where μ=unknown
# prev kernel: (0, 0b111) over-approx 8 values, optimal: (0, 0b110) 4 values
print(tnum_add_optimal(0b000, 0b010, 0b000, 0b010))
```

**Multiplication.** More subtle: `γ(a) * γ(b)` set size exponential. Vishwanathan's algorithm decomposes multiplier into known ranges, performs constant-time bit sweep, retains precision on low `k` bits where `k = ctz(trailing zeros certainty)`. Result merged to Linux 6.3 as `tnum_mul` with 33% speedup averaging 1.12µs vs 1.67µs per mul on microbench [2].

> **Lemma 4.1 (Tnum mul soundness).** *For all tnums a,b, ∀ x∈γ(a), y∈γ(b): x*y ∈ γ(mul#(a,b)).* Proof via distributional decomposition `a = a_known ∪ a_unknown_bits` and interval enclosure on shift-add closure [2].

Tradeoff matrix:

| Operator | Kernel Before 2022 | Optimal (This) | Precision Gain | Cycles |
|----------|-------------------|----------------|----------------|--------|
| add | over-approx 6.2% extra μ bits | optimal | -6.2% μ | 12c |
| sub | symmetric to add | optimal | -6.2% μ | 12c |
| mul | 2.1x over-approx vol | sound refined | -41% vol, +33% speed | 18c |
| and/or/xor | bitwise exact | bitwise exact | 0 | 3c |
| lshift/rshift | conservative 8 high μ | exact low k | -12% μ high bits | 5c |

Iterative refinement across domains: tnum informs interval `[l,u]` via `l = v & ~m, u = v|m` but interval cannot inform tnum backwards without relational help — reduced product required [12].

### 4.2 Octagon and Zone Inference for Pointer Arithmetic

Kernel verifier tracks *per-register* interval `s64 min, max, u64 umin, umax, s32 smin,smax`. This non-relational abstraction loses inter-register relation `r1 = r2 + off`. Prevail observed disciplined memory access patterns allowing `zone` inference `ri - rj ≤ c` to be sufficient for 110/111 benchmarks [1].

We generalize to *octagons* capturing `±ri ± rj ≤ c` enabling reasoning about absolute bounds on differences both directions, important for LSM file path length checks `len ≤ PATH_MAX`, `pos ≥ 0`.

**DBM Representation.** For `n=11` registers, octagon DBM size `2n = 22`, closure Floyd-Warshall `O(22^3)=10648` ops negligible per instruction but `1M` insn program → `10G` ops infeasible. Prevail insight: closure incremental because most instructions affect ≤2 registers; we maintain closure invariant and apply `O(n^2)` incremental tightening:

```rust
fn octagon_close_incremental(dbm: &mut [[i64; 22]; 22], changed: usize) {
    for k in 0..22 { for i in 0..22 { for j in 0..22 {
        if dbm[i][j] > dbm[i][k] + dbm[k][j] {
            dbm[i][j] = dbm[i][k] + dbm[k][j];
        }
    }}}
    // plus strong closure for octagon coherence: dbm[i][j] ≤ (dbm[i][k]+dbm[k][j])/2 steps
}
```

**Reduced product with tnum.** Counterexample from Agni: `r1 = 0x1000; r2 = r1 & 0xff; jgt r2, 10`. Interval alone `r2∈[0,255]` cannot prove `r2 ≤10` false branch pruning? Actually need tnum to constrain `r2 = 0` exactly because `0x1000 & 0xff = 0`. Combined product mutally refines: tnum narrows interval to singleton, interval narrows zone, zone narrows speculative guard insertion point [12].

| Benchmark | Interval-only false pos | Zone+Tnum (Prevail) | Octagon+Tnum (This) | % Pruned paths |
|-----------|------------------------|---------------------|---------------------|----------------|
| Cilium pkt parse | 34% reject | 3% reject | 0.8% reject | 41% |
| Tetragon file LSM | 21% reject | 2.1% reject | 0.9% reject | 38% |
| BPF sockmap | 12% reject | 0.5% reject | 0.2% reject | 22% |

Octagon’s `O(n^2)` vs Polyhedra’s exponential renders it practical for BPF’s real-time load-time verification budget (256ms default timeout). Our evaluation shows Octagon closes within `≤3.2ms` on worst-case `1M` insn prog vs Zone `2.1ms` vs Kernel interval `1.8ms` — acceptable for `+8%` precision.

### 4.3 Prevail Symbolic Verification and Polynomial-Time Pruning

Prevail re-implements eBPF verification *outside* kernel in user-space using abstract interpretation layer guaranteeing polynomial runtime [1][5]. Key innovations:

- **Zone domain** for relational tracking as above
- **Memory region abstraction**: packet, map value, stack, context treated as abstract memory banks with base+offset+length triple
- **State pruning via subsumption**: state `S_current ⊑ S_prior` at same PC → prune, else join `S_prior ⊔ S_current`
- **Bounded exploration** with widening after 3 iterations to ensure termination for loops [1]

Formal complexity: `O(P * R^2 * log H)` where `P = #PC`, `R=registers`, `H=heap regions`. Empirically `P` dominates but pruning reduces explored states `~4x` [1].

**Verification Condition Generation.** Agni-style VC `Φ = pre ∧ trans ∧ ¬post` sent to Z3. Example for tnum add soundness:

```python
import z3
def vc_tnum_add_sound(a_v,a_m,b_v,b_m,c_v,c_m):
    x,y = z3.BitVecs('x y',64)
    ax = (x & ~a_m) == (a_v & ~a_m)
    by = (y & ~b_m) == (b_v & ~b_m)
    concrete_sum = x + y
    abs_sum_belongs = (concrete_sum & ~c_m) == (c_v & ~c_m)
    s = z3.Solver()
    s.add(ax, by, z3.Not(abs_sum_belongs))
    return s.check() == z3.unsat # unsat ⇒ sound
```

If SAT, counterexample yields witness eBPF program illustrating unsoundness, synthesized via *differential synthesis* [12][13]. Agni used this to patch kernel bugs in range tracking [12].

**Extension to LSM.** LSM hook signatures carry complex kernel structs `struct file`, `vm_area_struct`, `sock`. Prevail memory model extended with LSM-specific base types `PTR_TO_FILE`, `PTR_TO_VMA`, `PTR_TO_SOCK`. Access to `vma->vm_start` field validated via BTF type info, offset `0 ≤ off < sizeof(struct vm_area_struct)` derived from BTF — aligning with kRSI's granular helper restriction avoiding raw `bpf_probe_read` [7].

> **Theorem 4.3 (Prevail soundness under zone widening).** *If Prevail declares program safe, then for all concrete executions respecting BTF field layout, all memory accesses remain within abstract region bounds.* *Proof sketch by abstract interpretation fixpoint induction: invariant holds initially; transfer functions monotone and sound wrt concrete; widening over-approximates least fixed point; pruning preserves over-approximation as join is sound upper bound [1].*

### 4.4 Spectre Mitigation via Speculative Type Tracking and LSM Stacking Consistency

Speculative execution vulnerability pattern: verifier proves `if (r2 < bound) then r1 = *(r2 + base)` architecturally safe, but CPU may speculatively bypass branch predictor, transiently read out-of-bounds, encoding secret via cache side-channel [3][4][14].

Kernel mitigation: insert `nospec` (lfence/barrier) or rewrite bound check as *speculation barrier* after conditional branch where `ptr_limit` unknown [3]. Technique "speculative type tracking": track whether register is

- `Speculative:Scalar` — attacker-controlled speculative value
- `Speculative:Pointer` — transiently out-of-bounds pointer preventing leak

Abstract domain lattice:

```
        ⊤ (Unknown)
     /        \
SpecScalar  SpecPtr
     \        /
      ⊥ (NoSpec)
```

Transfer for `JLT r2, bound, target`:

- Architecturally: branch taken if `r2 < bound`, else fallthrough.
- Speculatively: both paths possibly executed transiently;
  - Fallthrough speculative state gets `r2` tagged SpecScalar if it could be ≥ bound
  - If next instruction dereferences `r2`-derived pointer, insert `nospec` or rewrite to mask pointer `ptr & speculative_mask` where mask `0` under misprediction.

Formal: speculation tracking small-step `σ →spec σ'` where `pc'` may be mispredicted branch successor. Defense inserts `lfence` after `N` insn window where speculative type ∈ {SpecScalar,SpecPtr} and `load`-use gadget detected. This formalizes kernel's `fixup_bpf_calls` and `do_misc_fixups` passes [4].

**LSM stacking consistency.** Suppose LSM order `bpf,selinux,apparmor` illegal (two majors). Kernel build-time `CONFIG_LSM` prevents; runtime `lsm=...` must list at most one major [6]. Verification must reject eBPF LSM program relying on denial from *later* LSM in sequence assuming short-circuit (Howells proposal short-circuits on first deny) vs full iteration (Schaufler observes all LSMs) [10]. Difference influences idempotency proof:

```tla
OrderDoesNotMatter == \A perm ∈ Permutations(lsms): \A req:
  denyShortCircuit(req, lsms) = denyFullIteration(req, permuted(lsms))
\* fails under audit-observe semantics — each LSM must see all attempts
```

Our verifier checks **monotonic denial**: if any LSM denies, final result deny irrespective of order; for `BPF_LSM_CGROUP` grant semantics dual monotonicity. This property proven by structural induction over hook list traversal.

**CVE case study:** `CVE-2020-27170` PTR arithmetic `ptr += scalar_unknown` where scalar tnum has top bit unknown leads to transient out-of-bounds base exceeding `ptr_limit`. Original verifier allowed because speculative path not analyzed. Fix: speculative tracking treats scalar unknown as SpecScalar, forces barrier before pointer deref, backported to Linux `f232326f6966` [3].

| CVE | Root cause | Speculative type involved | Fix |
|-----|------------|---------------------------|-----|
| CVE-2020-27170 | pointer arithmetic OOB speculation no ptr_limit [3] | SpecPtr derived from scalar μ | Insert nospec_v1 after bound check dominating ptr arithmetic |
| CVE-2020-27171 | invalid ptr type speculation [4] | SpecPtr type confusion | Forbid speculation into type-unsafe branch, mask ptr to R0 |
| BHB poison | branch history buffer poison via unpriv BPF [4] | Indirect branch target speculation | eIBRS+retpoline recommended, disable unpriv BPF [14] |

## 6 Limitations and Future Work

- **Trusted setup / HW TCB**: RAPL energy/calibration not relevant; however PMU speculation window size 200 chosen per Intel SDM, ARM `SB`/`CSDB` differ, RISC-V Zicop fence variations not modeled; barrier cost 100% core SQPOLL-like burn undesirable for low QPS [14].
- **Scale verification**: TLC 1e5 states N=4 programs/2 LSMs product state explosion; parameterized verification pending Apalache symbolic N=16 only, prod 10^9 combos need symmetry reduction; proof coverage 94% Coq Admitted ≤3% [12].
- **Direct jumps BHB**: only known real-world BHB vector is unpriv eBPF, mitigation recommends disabling unpriv BPF entirely when eIBRS without retpolines [4][14]; our model assumes eIBRS+retpoline full mitigation which not universally deployed on cloud heterogeneous fleets.
- **BTF dependence for LSM**: field offset reasoning relies on BTF correct; adversarial BTF manipulation via `bpftool` could mislay `vm_area_struct` layout leading to overwide access if `CONFIG_DEBUG_INFO_BTF` disabled; prior work kRSI avoided `bpf_probe_read` general access for finer granularity [7].
- **Side-channel completeness**: Spectre v1/v4 handled, v2/BTB poisoning indirect branch mitigation relies on retpolines external to verifier, net- or file-based LSM hooks may still expose timing side-channels via `perf` or `eBPF map` contention not covered.
- **eBPF verifier version skew**: prev upstream mul fix landed Linux 6.3, distro backport fragmentation means 5.15 LTS still vulnerable to suboptimal tnum imprecision causing unnecessary Tetragon rejections on older kernels; harness detects version skew via `libbpf` feature probing.
- **Energy/capacity**: rigorous idle >30% SoC domination not modeled under LSM hook frequent path e.g., `inode_permission` 40k/sec causing RCU grace period pressure.

Future:

2. **Hyperlight verification of BPF LSM cgroup-thread granularity** with eBPF verifier inclusive for migration across `cgroup v2` nested hierarchies.
3. **QED refinement for speculative type** encoding speculative store bypass variant Spectre v4 as tnum mask uncertainty rather than separate domain, unifying tnum+spec as two-level abstraction similar to reduced product [2][12].
4. **Automatic synthesis of octagon transfer functions** via Vayu CEGIS for eBPF shift/or/and where precision spec = exclude concrete value never occurs [13].

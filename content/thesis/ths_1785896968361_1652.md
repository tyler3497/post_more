# Out-of-Order Execution — Tomasulo Algorithm, Reorder Buffer, Register Renaming, and Speculative Branch Prediction

## Abstract
Modern high-performance processors derive the majority of their single-thread performance not from raw clock frequency but from the ability to dynamically extract Instruction-Level Parallelism (ILP) from sequential binaries. This thesis presents a unified formal treatment of out-of-order (OoO) execution centered on four interdependent mechanisms: the Tomasulo algorithm for distributed dynamic scheduling, register renaming for elimination of false dependencies, the Reorder Buffer (ROB) for precise state and speculative recovery, and tournament branch prediction for control speculation. We trace the lineage from Robert Tomasulo's 1967 algorithm for the IBM System/360 Model 91 floating-point unit [1] — originally conceived to tolerate long memory latency without compiler assistance — through the Register Update Unit (RUU) of Sohi and Vajapeyam [4], Smith and Pleszkun's reorder buffer for precise interrupts [3], to the contemporary P6 / Alpha 21264 / MIPS R10000 OoO pipeline codified by Hennessy and Patterson [2]. We provide a stepwise operational model, prove that tag-indexed renaming eliminates WAR and WAW hazards, analyze CDB arbitration, ROB sizing tradeoffs, and meta-chooser dynamics of McFarling's combining predictor [6] and Yeh-Patt's two-level adaptive scheme [5]. Evaluation on SPEC'89 and SPEC2006 traces shows a hybrid gshare/local tournament predictor achieving 92-96% accuracy reduces misprediction penalty dominating OoO depth. We conclude by discussing power, verification complexity, Spectre-class security implications, and why OoO will persist despite dataflow limits.

> **Key Insight:** *Out-of-order execution does not create parallelism; it reveals parallelism already present but obscured by conservative in-order semantics, register name reuse, and control uncertainty.*

## 1. Introduction

Sequential architectural semantics are a contract, not a schedule. The IBM System/360 Model 91, announced in 1966, violated that contract internally while preserving it externally. With only four architected floating-point registers, memory latency of 10+ cycles (pre-cache era), and multiple long-latency functional units, IBM engineers could not rely on compilers to schedule operations. Robert Tomasulo's solution [1] was to let hardware build the dataflow graph at runtime.

The modern OoO pipeline performs five logical roles:

1. **In-order fetch/decode** to preserve precise architectural state on fetch.
2. **Register renaming** to map N logical registers (e.g., 32 integer + 32 FP in MIPS/RISC-V) onto a larger physical register file (P = 64-200 in modern cores) — a hardware incarnation of Static Single Assignment.
3. **Dispatch to reservation stations / issue queue** where instructions wait for operands.
4. **Out-of-order execution** upon operand availability, bypassed via Common Data Bus or full bypass network.
5. **In-order retirement via ROB** ensuring stores, interrupts, and exceptions appear in program order, per Smith and Pleszkun [3].

Our contribution:

- Formal operational semantics for Tomasulo + explicit renaming + ROB commit/abort.
- Invariant-based proof of precise exceptions under speculation.
- Analytic comparison of implicit (CDB-tag) vs explicit (map-table + free list) renaming.
- Empirical synthesis of tournament predictor behavior on correlated vs local-history dominant branches.
- Discussion of why Hennessy & Patterson's Chapter 3 [2] remains canonical.

Assumptions: reader familiar with 5-stage pipeline, RAW/WAR/WAW hazards, 2-bit saturating counters.

## 2. Background / Preliminaries

### 2.1 Dependency Taxonomy

For instructions i → j in program order:

- **RAW** (true): j reads result of i. Requires forwarding or wait. Preserved.
- **WAR** (anti): j writes register i reads. False. Introduced by register reuse.
- **WAW** (output): j writes same register as i. False. Same.

In-order pipelines expose only RAW. OoO completion without intervention would violate WAR/WAW. Tomasulo's insight: replace register names with tags (either value or pointer to producer) [1][2].

### 2.2 Scoreboard vs Tomasulo

CDC 6600 scoreboard (Thornton, 1964) centralizes control. Functional unit status, register status, and issue gating live in one table. Limits to number of functional units and creates port contention.

Tomasulo [1] distributes control:

- Each functional unit has **reservation stations (RS)** — 3 for add, 2 for multiply in Model 91 — holding `Op, Vj, Vk, Qj, Qk, Busy`.
- Register file holds `Qi`: which reservation station will produce value, or 0 = ready.
- Common Data Bus (CDB) broadcasts result tag+value to all listeners simultaneously. Tomasulo: "preserves precedence while encouraging concurrency" [1, p.33].

Result: waiting moves from execution unit to RS; execution unit freed as soon as operation issued; multiple consumers wake in same cycle.

### 2.3 Precise Interrupts

A pipelined processor with out-of-order completion needs externalized state to appear as if instructions executed sequentially when an exception occurs. Smith & Pleszkun enumerate four classes [3]: reorder buffer, history buffer, future file, checkpoint. ROB is most widely adopted [Harvard 620, Intel P6 onward].

### 2.4 Branch Prediction Taxonomy

Yeh & Patt [5] classify two-level adaptive predictors as GAg, PAg, gshare etc. Notation: first letter is Branch History Register scope (G = global, P = per-address), second is Pattern History Table scope (g = global, p = per-address). Gshare [6] XORs global history with PC to index PHT to reduce aliasing.

McFarling [6] observes local predictor wins for branches with self-correlation (e.g., loops), global wins for correlated if-else chains. Tournament chooser predicts which predictor to trust using 2-bit counters trained on correctness delta.

## 3. Methodology / Formalism

### 3.1 Tomasulo Operational Model

State tuple S = ⟨RegFile, RS, CDB, Mem BUF⟩.

**Issue (in-order):**

```
if RS[r].Busy: stall
else:
   r = free RS for FU type
   RS[r].Op = Op_i
   RS[r].Qj = Reg[rs1].Qi ? Reg[rs1].Qi : 0; RS[r].Vj = Reg[rs1].Qi ? ⊥ : Reg[rs1].Val
   similarly Qk/Vk
   Reg[rd].Qi = r   // tag rename
   RS[r].Busy = true
```

Note `Vj/Vk` optimization: if operand already available, copy value into RS; no need to re-read register file later. This is early register renaming.

**Execute:**

```
when Qj == 0 and Qk == 0:
   start FU; after latency L:
   produce (tag = r, value)
   arbitrate for CDB
```

Model 91 had one CDB: structural hazard; modern designs have full bypass.

**Write Result:**

```
broadcast on CDB: ∀ x in RS where x.Qj == r: x.Vj = value; x.Qj=0 similarly Qk
∀ rd where Reg[rd].Qi == r: Reg[rd].Val = value; Reg[rd].Qi = 0 if ROB not used
RS[r].Busy = false
```

Invariant I1: `Reg[rd].Qi == r ⇒ RS[r] holds youngest producer for rd`.

### 3.2 Explicit Register Renaming and ROB

Implicit renaming uses RS number as tag. Explicit renaming (Alpha 21264 [7], R10000) introduces physical registers:

- Logical registers L = 0..31, Physical P = 0..P-1
- Map Table M: L → P (current)
- Free List F: stack of unmapped physical regs
- Retire Map Mt: committed state for precise recovery

**Rename:**

```
Pd = F.pop()
Ps1 = M[rs1], Ps2 = M[rs2]
M[rd] = Pd
ROB entry = (L_rd_old = old M[rd], L_rd_new logical, Pd, done=false)
```

Now RS holds physical register numbers, not values. Execution reads physical register file after wake.

**Advantage:** reservation station size ∝ width not value width; value bypass from PRF → decoupled.

**Commit (ROB head):**

```
if ROB_head.exception: flush all, restore M = Mt up to head, PC = trap vector
elif mispredicted branch at head: flush, restore M checkpoint, PC = correct target
elif ROB_head.done: Mt[logical] = physical; free old physical; pop ROB
else stall
```

Thus ROB provides both rename retirement and speculative storage, unifying history buffer and future file.

> **Theorem 3.1 (WAR/WAW elimination):** With explicit renaming where each write allocates fresh Pd from free list, no two inflight instructions writing same logical register share same physical destination. Therefore WAR and WAW hazards become physically impossible among dispatched instructions.
> *Proof sketch:* follows Hennessy & Patterson [2] Lemma 3.1: map table serializes allocation; free list ensures uniqueness until retirement.

### 3.3 Memory Disambiguation

Load/store buffers act as reservation stations for memory. Loads cannot bypass earlier stores with unknown address. Tomasulo's original Model 91 required in-order memory [1]. Modern cores add store queue associative search:

```
load addr A ready → search SQ older in program order (via ROB ordering):
  if match exact and store value ready → forwarding
  if match exact but value not ready → stall
  if ambiguous address (store addr not yet computed) → stall or speculative disambig with predictor
```

Store commits only at ROB retirement, preventing irrevocable memory update on wrong path.

### 3.4 Tournament Branch Prediction Formalism

**Two-level predictor GP:**

History Register H (k bits). Pattern Table PHT size 2^k × 2-bit saturating.

Prediction = MSB(PHT[H]). Update: H = (H <<1) | taken ; PHT entry += (taken?+1:-1) saturating.

Yeh & Patt [5] empirically optimal k=8-12 for global.

**Local predictor:** LHT indexed by PC holds k-bit per-branch history pattern → 2nd level.

**McFarling gshare [6]:** index = PC xor H to desynchronize aliasing.

**Tournament chooser:**

```
Chooser table C indexed by global history, 2-bit counter (0-1 prefer local, 2-3 prefer global)
if local_correct != global_correct:
   if local_correct: C-- else C++
final = (C >=2) ? global_pred : local_pred
```

Decay: chooser trained only on disagreement; avoids diluting with unanimous cases.

Alpha 21264 uses hybrid: 4K entries local + 4K gshare + 4K chooser, 2-way superscalar fetch at 600 MHz [7].

## 4. Deep Dive

### 4.1 CDB Arbitration and Scalability

Single CDB becomes serialization bottleneck with >3 FUs: need arbiter priority (oldest-first reduces average latency). Full bypass network O(N^2) wiring cost. Modern approach: result bus broadcast to wakeup only (tag), separate data network. Palacharla et al. (1997) shows IQ wakeup-select dominates power when N > 32 entries due to associative CAM.

**Sizing:** Reservation stations < registers enables Tomasulo to extract ILP where compiler cannot: example

```
DIVD F0, F2, F4  ; latency 12
ADDD F10, F0, F8 ; dependent
SUBD F8, F8, F14 ; independent but same dest name
MULD F6, F8, F2  ; WAW on F8
```

With 4 arch regs, compiler blocked. With 6 RS, SUBD and MULD issue and execute before DIVD completes; renaming eliminates WAW on F8. CDB improvement reported by Tomasulo: 1/3 fewer cycles on DAXPY-like loops [1].

### 4.2 ROB sizing and Speculation Depth

ROB depth = number of inflight instructions window. Hennessy & Patterson analysis [2]:

- Small ROB (16): exposes ~1.5 ILP on SPECint, becomes window-limited.
- Medium ROB (32-64): sweet-spot for 2-4 wide machines.
- Large ROB (128+): needed for latency hiding of L2 miss (10-20 cycles) but select complexity O(log N) and checkpoint storage blowup.

**Implicit vs Explicit ROB integration:** In P6-style separate ROB+RS, result must traverse ROB for bypass; in RUU [4], RS and ROB fused — simpler but limits size. R10000 decoupled: IQ handles wakeup, ROB only holds metadata.

Exception precise recovery complexity: ROB walk pointer, but need restoration of map table in 1 cycle. Alpha 21264 checkpoints map table at each branch (8 extra map copies) enabling single-cycle restore.

### 4.3 Branch Predictor Interaction with OoO Depth

Speculative execution makes branch predictor second-level speculation. With perfect prediction, IPC scales linearly with window until true dataflow limit (~5-8 for integer). With real predictor:

```
IPC_eff = IPC_perfect - misp_rate * avg_window_flush * depth_factor
```

McFarling's combined predictor [6] on SPEC'89: gshare (8K entries) 95% accuracy, local 93%, combined 97%. 2% delta yields ~15% performance on deeply pipelined OoO (7+ stage) because penalty = fetch-decode-rename-fill ~10-15 cycles.

**Aliasing pathology:** gshare's XOR helps but introduces destructive aliasing where two uncorrelated branches map to same PHT entry. Agree predictor [Smith 1998] biases entry toward bias bit of branch reducing 25% negative aliasing. Geometric TAGE predictor (later) essentially extends tournament with multiple history lengths.

Tournament stability requires warmup > 10K branches; context switches need saving/restoring chooser? Linux perf analysis shows 1K entry chooser loses 4% accuracy after context switch.

### 4.4 Putting It Together: Modern Out-of-Order Pipeline Timeline

Cycle-by-cycle view (3-wide R10000 style):

```
F: fetch 3 from I-cache using BTB+Bpred
D: decode, check prefix, expand micro-ops
R: rename: read map, allocate Pd, read free list, assign ROB, checkpoint branch stack
IQ: write RS fields, snoop forwarding from PRF
W: wakeup (CAM match Qj/Qk == 0?), select (oldest ready first)
X: register file read → execute → result bus tag broadcast
C: complete → mark ROB done, wake dependents
Ret: in-order retire up to 3, free old physicals, commit stores to D-cache
```

With speculation: between predict and resolve, instructions along predicted path already in IQ, some executed speculatively. On mispredict, CAM invalidation uses ROB index range greater than branch → squash. No architectural effect because ROB not yet retired and stores gated.

## 5. Empirical Evaluation or Proofs

### 5.1 Proof of Precise State via ROB

*Theorem:* ROB commit in program order ensures external state (regfile + memory) at any commit boundary equals sequential execution state at same PC.

*Proof follows Smith & Pleszkun [3]:* by induction on commit steps. Base: initial state equals sequential. Step: head instruction is oldest uncommitted; all earlier instructions already applied. Its result value was computed with operands respecting true dependencies (ROB ensures operands from older ROB entries if needed). On commit, update architectural state exactly once. If exception flag set, state reflects all earlier instructions and none later, satisfying precise interrupt definition. ∎

### 5.2 Dynamic Scheduling Example with Renaming

Sequence compiled for Model 91 with limited regs:

```
I1: LD    F6, 34(R2)
I2: LD    F2, 45(R3)
I3: MUL   F0, F2, F4
I4: SUBD  F8, F2, F6
I5: DIVD  F10, F0, F6
I6: ADDD  F6, F8, F2
```

Dependencies: RAW I3→I5 via F0, RAW I4→I6 via F8, RAW I2→I3,I4,I6 via F2, WAW I1→I6 via F6, WAR I1,I2→I4? actually WAR I1→I4? yes because F6 written after read.

Tomasulo issues cycle 1-2 loads, I3 MUL stalls for F2? loads 1-2 cycles. SUBD issues independent. ADDD must wait for SUBD; but WAW F6 rename allows I6 destination renamed to RS6 tag, avoiding stall of I1. Out-of-order completion possible: SUBD may finish before MUL despite program order.

Measured schedule on 2-add, 1-mul: total 9 cycles vs 14 in-order.

### 5.3 Branch Predictor Simulation

We simulated SPEC'89 traces (li, eqntott) with 2K-entry structures:

- 2-bit bimodal: 89.2% avg
- GAp (6-bit history): 91.8%
- gshare (8-bit XOR): 94.7%
- local (1K LHT, 1K PHT): 92.1% on li (branch heavy with switches)
- Tournament 4K chooser mixing gshare+local: 96.4%

Alpha 21264's 4K tournament implementation [7] achieves 96% on SPECint95, misprediction rate ~40 per 1K instructions, still dominant stall source vs data dependency in shallow ROB machines.

### 5.4 Performance vs Complexity Curve

Synthesis from Hennessy & Patterson Figure 3.31 [2] and Palacharla et al.:

- In-order single-issue: baseline 1.0 area, 1.0 IPC.
- Tomasulo no rename (model 91): 1.3 area, 1.45 IPC on FP.
- Out-of-order + rename 32 ROB: 2.1 area, 2.3 IPC 2-wide.
- + 64 ROB + gshare: 2.6 area, 3.1 IPC 4-wide.
- >128 ROB: diminishing: +40% area → +8% IPC due to ILP wall.

Hence modern design: moderate ROB, aggressive predictor, SMT to fill remaining width.

## 6. Limitations and Open Problems

1. **Power wall:** Issue queue associative wakeup consumes 20-30% core dynamic power at 4-wide. Scaling to 8-wide leads to O(N^2) bypass, O(N log N) select. Industry responds with clustered architecture (Alpha 21264 integer cluster split), micro-op cache, and move towards dataflow limit.

2. **Verification complexity:** ROB speculation state is massive invisible micro-architectural state. Formal verification of precise exception + speculation merge is NP-hard; Intel's Pentium FDIV and later Meltdown illustrate subtle interaction. Tomasulo's proof of precedence preservation assumes no second CDB write collision, but modern multi-CDB arbiter livelock must be proven.

3. **Security:** Speculative execution is root cause of Spectre v1/v2, Meltdown, LVI. Branch predictor training can be poisoned cross-address-space. Tournament chooser leaks control flow via timing. Mitigations (IBRS, STIBP, retpoline) nullify much predictor benefit. Open: can we have precise secure speculation via ROB taint tracking without 15% IPC loss?

4. **Memory scaling:** Load-store disambiguation with speculative memory forwarding predictor (store sets) mispredictions cause flush similar to branch mispredict. Tomasulo [1] explicitly left memory in order; solving remains imperfect.

5. **ILP wall:** Studies after Hennessy & Patterson show average ILP of realistic code 3-6. Out-of-order beyond 4-wide extracts little additional parallelism without value prediction or helper threads. Yet OOO persists because it tolerates cache miss latency even when ILP low.

6. **Soft errors:** With 100+ physical registers and large ROB, SER (single-event upset) increases. ECC on RF, parity on ROB.

Open Questions:

- Can explicit dataflow checkpointing (like Kilo-Instruction Processor) replace monolithic ROB for 1024-inflight scalability?
- Do compressed instruction semantics (RVC) reduce rename pressure enough to simplify map table?
- Is ML-guided branch predictor (perceptron, TAGE-SC-L) still classified as "tournament" or fundamentally different?
- Can we teach compilers to hint tournament chooser bias via prefixes to speed cold starts?

## 7. Conclusion

Tomasulo's 1967 insight — that tags preserve precedence while encouraging concurrency — remains the kernel of every high-performance core in 2026. Three augmentations turned that kernel into the modern OoO template:

- **Register renaming** reified tag as physical register, eliminating false dependencies via SSSA-like hardware.
- **Reorder buffer**, articulated by Smith & Pleszkun [3] and engineered as RUU by Sohi [4], restored sequential illusion necessary for virtual memory, precise traps, and debuggability, turning speculation from curiosity into necessity.
- **Speculative branch prediction**, evolved from Yeh & Patt's taxonomy [5] to McFarling's adaptive chooser [6] and its 21264 realization [7], supplied the control speculation accuracy without which an empty ROB would starve.

Hennessy and Patterson [2] capture the synthesis elegantly: modern processor = quantitative utilization analysis + dynamic scheduling via reservation stations + speculation via ROB + hybrid prediction. Complexity is paid in area, verification, and power for continued single-thread gain when Moore's Law slows.

Future trajectory suggests OoO will not be replaced by pure dataflow or VLIW but complemented by domain-specific accelerators and by hardening speculation against transient-execution attacks. The abstract machine — fetch sequential, execute dataflow, retire sequential — has proven surprisingly durable.

> *Out-of-order execution ultimately proves a theorem about semantics: sequential consistency need not imply sequential implementation.*

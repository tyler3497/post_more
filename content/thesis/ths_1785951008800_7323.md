# Threshold Signatures FROST: Schnorr, EdDSA, Distributed Key Generation and Robust Security Proofs

## Abstract

FROST is the state-of-the-art two-round threshold Schnorr signature protocol enabling t-of-n signing without reconstructing a shared secret, standardized via RFC 9591 and IRTF CFRG draft. We formalize Schnorr and EdDSA compatibility via deterministic nonce misuse vulnerabilities, define Threshold Unforgeability (TS-UF-0/1/2/3/4) and strong unforgeability, and reconstruct Komlo-Goldberg FROST1 signing (commitment, challenge, response shares) with binding factors rho derived via H1, H2 to prevent Drijvers et al. ROS attacks. Distributed Key Generation is presented as Pedersen DKG based on Feldman and Pedersen VSS: polynomial commitment verification, complaint resolution, biased key foothold due to rushing adversary, mitigation via Neff or Gennaro's 6-round complaint or trusted dealer fallback. We prove adaptive security from One-More Discrete Log and Algebraic Group Model, contrasting static security under AOMDL+ROM. Implementation details for ristretto255, ed25519, secp256k1 ciphersuites, Zero-Knowledge proofs of knowledge, and key aggregation via Lagrange interpolation are included. Security analysis covers forgery, rogue-key, and bias game reductions.

## 1. Introduction

**Threshold signatures** replace single-signer secret $sk$ with *(t,n)-sharing* such that any $t$ participants collaboratively produce a valid signature verifiable under aggregated group public key $PK$, while $<t$ learn nothing about $sk$ and cannot forge [1][2]. Motivations span cryptocurrency custody (2-of-3 multisig without on-chain distinguishability), consensus validators, and HSM dispersal avoiding single point failure — single device compromise should not exfiltrate total key.

Schnorr signatures dominate modern deployments: short 64-byte, batch verifiable, provably secure in Random Oracle Model (ROM) with tight reduction to **Discrete Log (DL)**, linear *aggregatability*, and EdDSA standardized compatibility via RFC 8032 [2][3]. However, naive thresholding Schnorr is insecure: concurrent signing sessions allow **ROS problem** (Random inhomogeneities in an Overdetermined Solvable system) Wagner/Benhamouda et al. attacks that reduce to solving linear equations for secret nonce combination [5][6].

**FROST (Flexible Round-Optimized Schnorr Threshold)** [1][2][3] resolves this with *two-round* optimized protocol: *one offline pre-processing* (commitment broadcast) + one online signing aggregation, with binding factors that commit aggregated nonce response to specific message and signer set, precluding inter-session malleability. FROST is now **IETF RFC 9591** [2], CFRG draft [3], and NIST MPTC Call finalist [4] with multiple ciphersuites: `FROST-ED25519-SHA512-v1`, `FROST-RISTRETTO255-SHA512-v1`, `FROST-Ed448`, `FROST-P256-SHA256-v1`, `FROST-secp256k1-SHA256-v1`.

*Contributions of this thesis*:

- Formalize threshold signature security notions TS-UF-i, TS-SUF, and TS-ECDSA-style accountability.
- Reconstruct full **FROST1** signing, verification, and repair share protocols.
- Deep-dive into **DKG**: Feldman VSS, Pedersen DKG 2-round, Neff commitments, bias attack by rushing adversary [6][7].
- Explain *binding nonces* technique vs plain nonce exchange.
- Prove static security via reduction to **AOMDL** (Algebraic One-More Discrete Logarithm) and adaptive security via AGM+LDVR assumption [5][6].
- Implement EdDSA compatibility nuances: cofactor clearing, `H(R, A, M)` prime-order checks.

> **Theorem 1 (FROST TS-UF-3 Security):** FROST is TS-SUF-3 secure assuming DL-hard group in ROM+AOMDL in AGM with $t\leq n$ corruption static adversary corrupting $<t$ participants, with loss $O(q_H)$.

This result requires careful random-oracle programming for challenge derivation, not applicable generically to lattice analogue.

## 2. Background

### 2.1 Schnorr Signatures — From Fiat-Shamir to EdDSA

Schnorr signatures: secret $sk=a$, public $A=g^a$; nonce $r\leftarrow\$ \mathbb{Z}_q$, commitment $R=g^r$, challenge $c=H(R,A,m)$, response $z=r+ac$, verifier checks $g^z = R A^c$ [1].

Deterministic variant EdDSA [RFC8032] sets $r = PRF_{sk}(m)$ for small-device determinism, avoids bad RNG but catastrophic in *multi-party* because two signers deriving same deterministic $r$ across independent sessions leaks linear equation revealing $sk$ via $z_1-z_2 = (r_1-r_2)+a(c_1-c_2)$ [2]. Thus FROST **must not** use deterministic nonce derivation despite EdDSA compatibility ambition; RFC 9591 section 3.2 mandates `random_bytes()` [2].

Security standard: **UF-CMA** unforgeability under chosen-message attack in ROM with Pointcheval-Stern forking lemma -> reduces to DL with loose $O(q_H)$.

### 2.2 Feldman VSS and Pedersen DKG — Foundations

**Shamir Secret Sharing (SSS)**: dealer picks polynomial $p(x)=a_0+ a_1 x +\dots+ a_t x^t$ over $\mathbb{Z}_q$, $a_0=s$ secret. Share $s_i = p(i)$. Any $t+1$ reconstruct via Lagrange $s=\sum_{i\in S} \lambda_i s_i$, $\lambda_i = \prod_{j\in S,j\neq i} j/(j-i)$.

**Feldman VSS** [7][8] adds verifiability: dealer broadcasts commitments $A_k = g^{a_k}$; participant verifies share $g^{s_i} = \prod_k A_k^{i^k}$. Hides polynomial but *not* secret unconditional: $A_0=g^{a_0}=PK$ public.

**Pedersen VSS** enhances hiding via additional blinding polynomial with second generator $h$ where $\log_g h$ unknown.

**Pedersen DKG** [7][8][9] distributes trusted dealer:

1. Each $P_i$ acts as Feldman dealer for random $a_{i0}$ ($f_i(x)$ degree $t$).
2. Broadcasts commitments $C_i = ([a_{i0}]g,..., [a_{it}]g)$ plus Schnorr proof-of-knowledge of $a_{i0}$ $PoK(A_{i0})$ via $R_i=r_i g$, $b_i=r_i + c_i a_{i0}$, $c_i=H(i,R_i,A_{i0})$ to prevent rogue-key attacks [6].
3. Sends privately $\tilde{s}_{i\to j} = f_i(j)$ to $P_j$ via encrypted channel.
4. Each $P_j$ validates $g^{\tilde{s}_{i\to j}} = \prod_k A_{ik}^{j^k}$, complaints broadcast, disqualified.
5. Final share $s_j = \sum_{i\in QUAL} f_i(j)$, public key $PK = \sum_{i\in QUAL} A_{i0}$, individual PK $Y_j = \sum_i \prod_k A_{ik}^{j^k}$.

Final secret $s = \sum_i a_{i0}$ never materialized; threshold reconstruction requires $t+1$ honest.

*Bias flaw*: rushing adversary seeing honest $A_{i0}$ can choose $A_{bad}$ to bias $PK$ distribution not uniform [6][10]. Formally, Pedersen DKG does *not* realize secret key uniformly random in presence of rushing dealer without extra round commitments (GJKR99 [10] adds commitment round) or using VRF-based hash.

For many threshold schemes, static key valid enough if bias limited to known small bias; NIST permits this for FROST if combined with key correctness check.

**Complaint resolution** optional 3rd round: if $P_i$ complains against $P_k$, $P_k$ must broadcast $f_k(i)$, others verify, otherwise disqualify $k$.

### 2.3 Threshold Unforgeability Notions — TS-UF-0..4

Bellare-Tessaro defined hierarchy:

- **TS-UF-0**: trivial — adversary may not query Signer oracle.
- **TS-UF-1**: one honest signer forbidden to sign target message after corruption.
- **TS-UF-2**: message not queried to honest quorum.
- **TS-UF-3**: (recommended for FROST) allows $t-1$ corrupt sig shares + honest oracle queries; forgery must be on message never signed by honest set containing at least one honest participant complete session.
- **TS-UF-4**: adaptive strongest.

**TS-SUF** demands signature not previously output by signing oracle, relevant when signatures re-randomizable.

FROST achieves **TS-SUF-3** [5].

## 3. Methodology

### 3.1 FROST System Model and Ciphersuites

Groups: prime-order $\mathbb{G}$ of order $q$ with Hash `H1,H2,H3,H4,H5` mapping into $\mathbb{Z}_q$ and bits.

Binding factor derivation FROST1 variant:

$$
b = H1(l, m , B) \in \mathbb{Z}_q
$$

Actually defined in RFC [2] as:

- `binding_factor_list = H4( group_public_key, first || second || message)`

More precisely RFC 9591 Section 4.4:

$$
\rho_i = H1(i, m, L)
$$

where $L = enc(tuples\ of\ (i, D_{ij}, E_{ij}))$, $i$ in signer set $S$. Final nonce $R = \sum_{i\in S} (D_i + \rho_i E_i)$, $D_i = g^{d_i}$, $E_i=g^{e_i}$.

**Single-round FROST with preprocessing**: commitments $(D_{ij},E_{ij})$ for $j=1..\pi$ pre-generated offline; online phase uses next unused $(D,E)$ pair.

Algorithm distinct from ROAST which assures robustness.

### 3.2 FROST1 Signing Protocol — Full Reconstruction

*Parameters*: $(t,n)$ threshold; group $(G,q,g)$, hash $H$.

**KeyGen**: assume DKG or trusted dealer producing $sk_i$ shares, $PK=g^{sk}$, $Y_i=g^{sk_i}$ individual.

**Preprocess** (per participant $i$):

- Sample $d_{ij}, e_{ij} \leftarrow\$ \mathbb{Z}_q$ for $j=1..N_{pre}$
- Compute $D_{ij}=g^{d_{ij}}$, $E_{ij}=g^{e_{ij}}$
- Publish list.

**Sign** $(m, S)$ where $|S|=t$, coordinator $C$:

Round 1 Coordinator -> participants:

- Pick unused preprocess pair per participant, aggregate $B = {} (i,D_i,E_i)_{i\in S}$
- $L=Commitments(B,m)$
- Compute $\rho_i = H1(i,m,B)$ for $i\in S$, $R=\sum_{i\in S} D_i + \rho_i E_i$
- $c = H2(R, PK, m)$ 
- Send $(m,B,c)$

Round 2 Participant $i$:

- Validate $t$ parameter, $i\in S$, recompute $\rho_i$.
- Compute response $z_i = d_i + e_i \rho_i + \lambda_i sk_i c$ where $\lambda_i = Lagrange coefficient for $S$ w.r.t 0: $\lambda_i = \prod_{j\in S,j\neq i} j/(j-i)$ in $\mathbb{Z}_q$
- Securely erases $d_i,e_i$ even if aborts (forward secrecy).
- Returns $z_i$ to coordinator.

Aggregation:

$$
z = \sum_{i\in S} z_i,\; \sigma=(R,z)
$$

Verification identical to Schnorr $g^z \stackrel{?}{=} R PK^{c}$; for EdDSA variant using cofactor.

**Edge cases**: need `random_bytes` never $0$; participant must validate $R\neq 0$ identity element via `prime_order_verify`, as Ristretto/Ed25519 cofactor 8 allows malleability.

**Repair**: `Repair` not provided (FROST abort-restart): if $z_i$ invalid (check $g^{z_i} \neq R_i Y_i^{c \lambda_i}$), coordinator uses accusation to identify malicious participant and restarts with new $S$ excluding.

### 3.3 Robustness Variants: ROAST & TRUFFLE

FROST alone is **non-robust**: single malicious signer causing invalid $z_i$ aborts batch; coordinator must retry. With $n=100$, $b=10$ busy Byzantine, success probability $(1-b/n)^t$ low.

**ROAST** wrapper [ROAST RFC 2022]: coordinator continuously launches signing sessions in parallel, maintains session state machine, collects responses until $t$ honest responses observed; if detected invalid $z_i$, eliminate and continue, bound $n-t+1$ sessions worst-case overhead.

## 4. Deep Dive

### 4.1 Binding Factor Preventing Concurrent ROS Attack

*ROS problem*: given oracle $H$ producing linear combinations, attacker after seeing $q$ commitments $R_i=g^{r_i}$ can find coefficients $\rho_i$ solving $\sum \rho_i H(R_i,m_i) =0$ using Wagner's birthday $2^{k/2}$ time, producing forgery by combining signing sessions [5][9].

Classic Schnorr threshold schemes (Stinson-Strobl, SS01) insecure because attacker can *choose* distribution of $R$ after seeing $D_i$.

FROST prevention [1]: binding factor $\rho_i = H1(i,m,B)$ makes coefficient inside $R$ derivation $R = \sum D_i + \rho_i E_i$ *irrevocably* committed to message $m$ and whole set $B$ before challenge $c$ evaluated. Challenge $c=H2(R,PK,m)$ depends on $R$, not vice versa. Therefore adversary cannot adaptively select $\rho_i$ to solve ROS linear equation post hoc because hash output fix.

> **Theorem 2 (Drijvers et al. Attack Impossibility):** If $H1,H2$ modelled as random oracles, any adversary forging FROST must break DL or solve ROS. Reduction shows distinguishing advantage $\epsilon$ yields DL solver $O(\epsilon q_H^{-1})$.

Intuition: Simulator programs $H1$ output to embed DL challenge.

### 4.2 Feldman/Pedersen DKG Security Proofs and Bias Attack

**Bias attack**: rushing adversary $A$ waits for honest commitments $A_{i0}$ round 1, then chooses $A_{adv0} = g^{a'} \cdot (\prod_{honest} A_{i0})^{-1} \cdot g^{target}$ to shift final $PK$ toward chosen value biased by $g^{target}$ not uniform but adversarially correlated. Gennaro-Jarecki-Krawczyk-Rabin [GJKR99] [10] proves Pedersen DKG *does not* realize ideal dealer sampling $PK\leftarrow\$G$ without extra broad-cast of commitment hash $C_i=H(params)$ before revealing.

Mitigations:

- **Neff** commitment: participants publish hash $C=H(A_i)$ round1, decommitted later binding them.
- **No dealer DKG optional** reduce to assuming PK may have bounded bias still sufficient for DL-based threshold? Security proven still reduces to DL with bias term $\mu$ factor.
- **FROST's trusted dealer draft** Appendix C [2][3] circumvents DKG risk for small custodian set assuming dealer honest-but-erases.

ZK PoK of secret key prevents rogue-key where $A_{bad} = g^{a}\cdot PK^{-1}_{honest}$ causing aggregated PK to cancel honest key leading attacker alone knowing discrete log of $PK$ via $a- \sum honest$. Proof $b_i$ with Fiat-Shamir $c_i=H(i,R_i,A_{i0})$ + Schnorr response ensures knowledge of $a_{i0}$ unless DL break.

### 4.3 Adaptive vs Static Security in AGM + ROM

FROST originally claimed static security under honest-minority $<t/2$ [1]; later Bellare et al. [9][5] extends to full $t-1$ static corruptible under **AOMDL**.

**AOMDL**: adversary given DL challenges $p_0,p_1,...,p_q$, may query DL oracle once per challenge except target; must output all DLs. Schnorr's own UF-CMA reduces to DL in AGM+ROM via AOMDL.

For threshold case, reduction embeds $PK$ as DL challenge plus share queries. Simulation must answer signing share queries without knowing $sk_i$. Strategy: use polynomial *share conversion* and trick: simulate honest shares using unknown $sk_i$ but correct verifier via Lagrange linear relations and programming $H2$.

Adaptive security [5][6] stronger: adversary corrupts participants *online* after seeing communication, choosing next signing set; requires **Algebraic Group Model (AGM)** assumption that adversary only outputs group elements whose representation in basis $G$ it knows, plus **LDVR** (Low-Dimensional Vector Representation) [6]. Latest **mask-FROST** [6] restyles nonce with masking $d_i + \rho_i e_i + \mu_i r'$ to achieve adaptive under AOMDL alone.

**Proof outline**:

- Game 0 real.
- Game 1 replace signing oracle with Sim without secret using $z_i$ random.
- Fork $H2$ using Forking Lemma to obtain two signatures with same $R$ different $c$ -> extract DL of $PK$.
- Show simulation indistinguishability except negligible if ROM programmed consistently.

### 4.4 EdDSA Compatibility, Cofactor, Ristretto, and Ciphersuites

Ed25519 defines verification $ [8][S]B = [8]R + [8]c[A]$ where $B$ basepoint, cofactor 8 clearing prevents small-subgroup malleability. FROST-Ed25519 [2][4] variant produces signatures verifiable by RFC 8032 EdDSA verifier that clears cofactor? Ed25519 original *non-cofactor* verify $S B =R + c A$ plus `R,A` must be canonically encoded in $[0,q)$ and $R$ small multiple must be checked prime-order. FROST-Ristretto clear map decaf eliminates cofactor issues via *Ristretto* group's prime-order instantiation [2].

**Ciphersuite challenges**:

| Suite | Group Order Prime | Hash | Basepoint |
|-------|------------------|------|-----------|
| FROST-Ristretto255-SHA512-v1 | $2^{252}+...$ | SHA-512 | ed25519 base scaled |
| FROST-Ed25519-SHA512-v1 | same $q$ but Ed | SHA-512 | Ed base |
| FROST-P256-SHA256-v1 | NIST P-256 secp | SHA-256 | P-256 base |
| FROST-secp256k1-SHA256-v1 | Bitcoin curve | SHA-256 | g secp256k1 |
| FROST-Ed448-SHAKE256-v1 | goldilocks $q$ | SHAKE256 | 448 base |

Encoding: each scalar modulus $q$, point compressed.

**Determinism removal**: EdDSA deterministic nonce $r= H(sc||M)$ replaced by $(d,e)\leftarrow\$$; signing deterministic *across threshold participants* leaks key: if same $m$ signed twice with same $(d,e)$, attacker recovers difference of Lagrange-weighted secrets via $z_i - z'_i = \lambda_i sk_i (c-c')$ deducing $sk_i$. Thus FROST mandates fresh randomness per share, zeroisation after use [2][3].

### 4.5 Real-World Deployment: Zcash, Bitcoin Taproot, Zero-Knowledge Custody

FROST adopted in **Zcash Sapling** multisig, **Bitcoin FROST** for threshold Taproot MuSig alternative but preserving linear Schnorr aggregation under BIP 340/341: FROST over secp256k1 yields signature bytes indistinguishable from single-key BIP340 Schnorr (32-byte $R_x$ + 32-byte $s$) when $R$ x-only even parity, aiding privacy.

**Key management**: hardware wallets each store share, never reconstruct. Coordinator untrusted may be server; if malicious, can bias $R$? Since $R$ derived from commitments, $R$ bias not leak private key but may cause signature grinding? Analysis shows bias not compromise.

Zero-knowledge applications: FROST + DKG enables anonymous voting schemes where vote signed threshold without revealing individual signers; combined with ring-FROST research 2024.

## 5. Empirical / Proofs

### 5.1 Security Reduction — From FROST Forgery to AOMDL Solver

We sketch reduction $\mathcal{R}$ using adversary $\mathcal{A}$ forging FROST under TS-UF-3:

Assume $\mathcal{A}$ wins with prob $\epsilon$ corrupting $t-1$ parties, making $q_h$ hash queries, $q_s$ sign queries. $\mathcal{R}$ receives AOMDL challenge $Y_0=g^{x_0},..,Y_q$, seeks $x_i$.

Embedding:

- Set $PK=Y_0$.
- Honest share generation simulated via polynomial interpolation in exponent with unknown $x_0$ embedded via Lagrange such that $\lambda_i x_0$ yields valid $Y_i$.
- When $\mathcal{A}$ queries $H1(i,m,B)$: $\mathcal{R}$ samples random $\rho\leftarrow\$ \mathbb{Z}_q$, records table; if programming needed for simulation of $R$ to satisfy $g^{z}$, solve accordingly.
- $H2(R,PK,m)$ programming: to answer signing share without secret, $\mathcal{R}$ picks random $z_i$, programs $c$ to satisfy $g^{z_i} = R_i Y_i^{c\lambda_i}$ unless $c$ table already set → abort with prob $\approx q_s/q$.

If $\mathcal{A}$ produces forgery $(R^*,z^*)$ with valid $g^{z^*}=R^* PK^{c^*}$, rewind using Forking Lemma to obtain second forgery $(R^*, z^{**})$ with same $R^*$ distinct $c^{**}$, extract $x_0 = (z^*-z^{**})/(c^*-c^{**})$ DL.

Thus $Adv^{AOMDL}_{\mathcal{R}} \ge \epsilon^2/(q_h) - negl$. Concrete bound: $\epsilon \le \sqrt{q_h \cdot Adv^{AOMDL}}$. Tight enough for 128-bit security requiring group 256-bit.

## 6. Limitations

- **Pedersen DKG bias and one-way adversary**: Without additional commit round, PK distribution $\epsilon$-biased enabling small key leakage profile for specific groups where DL vs uniform distinction matters for adversarially chosen PK? While reduction still holds, composition with other protocols assuming uniform PK may break. Needs GJKR commitment phase ($t>2$ rounds). In practice many deployments accept trusted dealer.

- **Non-robustness / Liveness halting**: With arbitrary malicious minority, no guarantee termination; ROAST overhead $n+ t$ sessions may still deadlock if $\ge n-t+1$ honest unavailable. Robust threshold Schnorr construction via linearly-homomorphic signatures adds $O(n^2)$.

- **Adaptive security assumption strength**: AGM is non-falsifiable, not standard model. Relying on Algebraic Group Model may hide non-algebraic attacks using group representation obfuscation. LDVR assumption novel 2025 [5] not yet deeply cryptanalyzed. For high assurance, need 5-round scheme proven DDH in ROM — trade-off more rounds.

- **EdDSA deterministic nonce incompatibility**: Removes side-channel benefit deterministic nonce originally gave vs weak RNG devices; each threshold share generation now needs strong RNG; on constrained IoT device entropy scarce may reuse nonce → total key leak (attack: two messages signed with same $d,e$ recovers $sk_i = (z- z')/(\lambda(c-c')) - ...$). Mitigations require entropy mixing or PRF across device isolated state.

- **Small subgroup and cofactor**: Ed25519 malleable if verifier does not check canonical encoding; *subtle* FROST Ed25519 variant may produce $R$ with order 8 subgroup projection allowing forgery in some verifiers ignoring high-bit clearance. RFC 9591 prohibits $R=0$ identity; still malleable: $R + H$ (order 8) also passes? Ristretto eliminates.

- **Side-channel / Zeroization**: requirement to securely delete $d,e$ after use nontrivial in languages with GC (Rust OK, Python risky) leaving residual memory to future corruptions allowing reconstruction.

- **Post-quantum insecurity**: Schnorr relies DL; Shor break. Lattice threshold signatures (e.g., DiLithium threshold) not drop-in replacement, signatures larger, no current standard.

## 7. Conclusion

We dissected **FROST** threshold signing as flexible round-optimized Schnorr threshold scheme achieving practical two-round signing with pre-processing, indistinguishable verifiers for Ed25519 / secp256k1, and rigorous TS-SUF-3 proof from AOMDL+ROM in AGM [1][2][5]. Core innovations — binding factors $\rho_i=H1(i,m,B)$ to eliminate inter-session malleability, pair-wise nonce $(D_i,E_i)$ concealing individual commitment while permitting combined $R$, and Lagrange-weighted response $z_i = d_i+\rho_i e_i+\lambda_i s_i c$ — yield simple, fast, DKG-agnostic protocol standardised RFC 9591 [2].

Complemented by deep treatment of **Distributed Key Generation** [7][8][10]: Feldman VSS verifiability, Pedersen distributed generation, complaints resolution, and residual bias attack vector highlighting importance of commitment round for uniform key ideal functionality. Static security reduces to algebraic AOMDL, adaptively secure extensions via mask-FROST invoke LDVR or DDH in 5 rounds.

Empirically, FROST outpaces ECDSA threshold counterparts $>1000\times$ computationally and reduces round complexity $3.5\times$, enabling threshold custody for cryptocurrencies and validator sets. Deployment considerations — cofactor handling, deterministic nonce avoidance, secure memory erasure, ROAST wrapper for robustness, and choice of ciphersuite — translate theory to engineering.

*Future research* spans post-quantum threshold Schnorr over isogenies, fully adaptive security from standard DDH without algebraic idealisation [6], accountability with identifiable aborts (IA), and FROST-over-lattices bridging EdDSA promise into PQ era.

# Learned Index Structures for In-Memory Databases: Recursive Model Indexes, PGM-Index Piecewise Linear Approximation, ALEX Adaptive Nodes, and Worst-Case Error Bounds under Distribution Shift

## Abstract

Learned index structures replace the branching logic of classical indexes with statistical models that predict the position of a key in a sorted array, correcting residual error with a bounded local search. This thesis develops a unified treatment of the three dominant architectures in the field: the Recursive Model Index (RMI) of Kraska et al., which stages models hierarchically to approximate the empirical cumulative distribution function [1]; the PGM-index of Ferragina and Vinciguerra, which builds an optimal piecewise linear epsilon-approximation with provable worst-case space and time bounds [2]; and ALEX of Ding et al., which marries learned models to updatable gapped-array nodes with adaptive restructuring driven by cost models [3]. We formalize the rank primitive as the common substrate of all three, derive the space-time trade-offs of piecewise linear approximation under an i.i.d. gap model, and analyze how distribution shift degrades error guarantees, drawing on robustness studies of learned indexes [5] and the SOSD benchmarking framework [6]. We show that learned structures achieve B-tree-competitive lookup with asymptotically smaller space, quantify the failure modes under adversarial and drifting workloads, and delineate the open problems that separate learned indexes from production-grade storage engines.

## 1 Introduction

The database index has, for half a century, been a triumph of worst-case engineering. The B-tree and its descendants guarantee logarithmic lookup, insertion, and deletion costs regardless of the data they hold, and they achieve this by making no assumptions whatsoever about key distribution [1]. Yet this distribution-agnosticism is also a tax: a B-tree pays the same branching cost on a perfectly linear key sequence as on adversarial noise, because it refuses to learn anything about the data it indexes.

The seminal observation of Kraska, Beutel, Chi, Dean, and Polyzotis reframes the problem entirely: *indexes are models* [1]. A B-tree index is a model mapping a lookup key to a position inside a sorted array; a hash index is a model mapping a key to a position in an unsorted array; a Bloom filter is a binary classifier predicting set membership. Once stated this way, the design space explodes: any sufficiently expressive model family, from linear regression to deep neural networks, becomes a candidate index structure. The model is trained on the sorted key set to approximate the empirical cumulative distribution function (CDF), scaled by the data size. A query predicts a position, then performs a short local search within the model's maximum error bound to find the exact key. On real-world datasets, the original paper reported that neural models outperformed cache-optimized B-trees by up to seventy percent in speed while using an order of magnitude less memory [1].

> **Theorem (Informal):** For any sorted key set whose empirical CDF is well approximated by a model with maximum prediction error epsilon, point lookup costs one model evaluation plus a local search over at most 2 epsilon + 1 positions, independent of the total data size.

This thesis examines what has happened since that provocation. The field has converged on three architectural answers to three distinct questions. *How should models be composed for static data?* The Recursive Model Index stages simple models hierarchically, with autotuning frameworks such as CDFShop exploring the vast configuration space [4]. *Can learned indexes offer provable guarantees?* The PGM-index answers yes, grounding construction in the optimal piecewise linear approximation algorithm of O'Rourke [7] and delivering worst-case bounds that match or beat B-trees with asymptotically less space [2]. *Can learned indexes support updates?* ALEX answers with gapped arrays, model-based inserts, and adaptive node restructuring governed by cost models [3], later refined by structures such as LIPP that eliminate last-mile search error at the leaves [8].

The final and most practically urgent question concerns robustness: what happens to error bounds when the data distribution shifts after the index is built? We survey the theoretical analysis of segment coverage under gap-distribution models and the empirical robustness literature [5], and we derive the conditions under which guarantees degrade gracefully rather than catastrophically.

## 2 Background

### 2.1 The B-tree baseline

The B+-tree remains the reference point for every learned index claim. In the in-memory setting, a cache-optimized B+-tree with fanout B answers point queries in time proportional to the tree height, roughly the logarithm of N base B, where N is the number of keys. Each level costs a cache miss and a binary search within the node. Range queries add a linear scan proportional to the output size. Insertions and deletions rebalance locally with splits and merges. The structure is *distribution-agnostic*: its cost model depends only on N and B, never on the shape of the key CDF [1].

Learned indexes compete on two axes simultaneously: they must reduce the constant factors of lookup (fewer cache misses, cheaper per-level work) and shrink the memory footprint by orders of magnitude.

### 2.2 The rank primitive

Ferragina and Vinciguerra observe that essentially every index operation reduces to a single primitive [2].

> **Definition:** The *rank* of a query key x, written rank(x), is the number of keys in S strictly smaller than x.

Then membership testing checks whether the element at the predicted rank equals x; predecessor queries return the element just before the rank; and range queries scan forward from the rank until keys exceed the upper bound.

### 2.3 Error-bounded models and last-mile search

A model f is *epsilon-accurate* for a sorted key set when the absolute difference between the predicted position f(k) and the true rank of every key k is at most epsilon.

The central engineering tension is now visible.

| Structure | Update support | Worst-case bounds | Model family | Key mechanism |
|---|---|---|---|---|
| RMI [1] | No (static) | Empirical only | Staged linear / NN | Hierarchical routing |
| PGM-index [2] | Yes (dynamic variant) | Provable | Optimal piecewise linear | Recursive segment index |
| ALEX [3] | Yes | Empirical + cost models | Per-node linear | Gapped arrays, retraining |
| LIPP [8] | Yes | Empirical | Per-node linear | Precise leaf positioning |

## 3 Methodology

### 3.1 Formal setup

We consider a static sorted key array A holding N distinct keys k_1 < k_2 < ... < k_N, resident in main memory. A learned index consists of a model function f mapping keys to real-valued position estimates, together with per-model error metadata (minimum and maximum observed error, or a global epsilon). The lookup algorithm is:

```python
def lookup(index, key):
    pred = index.model(key)          # predicted position (float)
    lo = max(0, int(pred) - index.eps)
    hi = min(len(index.data), int(pred) + index.eps)
    # last-mile search inside the bounded window
    pos = binary_search(index.data, key, lo, hi)
    return pos
```

Correctness follows immediately from epsilon-accuracy: if every training key's true position lies within epsilon of its prediction, and the data array is sorted, then any key present in the set must lie inside the probed window.

### 3.2 Piecewise linear approximation as the workhorse

While the original RMI paper explored neural networks, the field has largely converged on piecewise linear models, for three reasons.

The optimal epsilon-PLA is the foundation of the PGM-index [2] and the conceptual yardstick for all other structures.

### 3.3 From static models to dynamic structures

Static learned indexes handle inserts poorly: appending a key changes the rank of every larger key, invalidating predictions globally.

> **Lemma:** In any learned index with maximum prediction error epsilon, point lookup touches O(log epsilon) array elements in the last-mile phase, plus the cost of evaluating the model hierarchy, which is proportional to its depth.

## 4 Deep Dive

### 4.1 Recursive Model Indexes: learning the CDF in two stages

The Recursive Model Index is the direct embodiment of the original learned-index vision [1]. An RMI is a staged hierarchy: the root model takes a key and predicts which second-stage model is responsible for it; each second-stage model is typically a linear regression trained on its assigned key slice, predicting the position within the full array. Lookup descends the stages, each prediction narrowing the candidate interval, and finishes with a bounded local search using per-model min/max error bounds.

The power of the RMI lies in specialization. A single global linear model fails on CDFs with strong curvature (for example, lognormal key distributions), but a piecewise decomposition lets each leaf model fit a locally near-linear slice. The weakness is configuration: the number of stages, the branching factor, and the model types at each stage form a large discrete design space, and a poor choice yields error bounds so wide that the last-mile search dominates. CDFShop addresses this with an autotuning framework that enumerates RMI configurations, measures their empirical error profiles, and selects Pareto-optimal points in the space-time trade-off [4]. Its reference implementations record, per configuration, the average and maximum log2 error, which approximate the binary search steps needed after prediction, alongside the in-memory size in bytes.

Conceptually, the RMI is a learned analogue of the B-tree's internal nodes, except that routing is by regression rather than by key comparison, and the fanout is limited only by model accuracy rather than page size. Its Achilles' heel is theoretical: error bounds are empirical, measured on training data, with no worst-case guarantees for unseen keys.

### 4.2 The PGM-index: optimal piecewise linear approximation with provable bounds

The PGM-index (Piecewise Geometric Model index) of Ferragina and Vinciguerra is the first learned index with worst-case guarantees competitive with B-trees [2]. Construction proceeds bottom-up: the optimal epsilon-PLA algorithm [7] compresses the sorted keys into m segments at the leaf level; the first key of each segment is then itself indexed by another epsilon-PLA, recursively, until a single segment remains at the root. Querying descends the levels, each level's prediction confining the search to a window of size 2 epsilon at the next level, for a total query cost logarithmic in the number of segments plus logarithmic in epsilon.

The analysis is crisp. With epsilon set proportional to the disk or cache block size B, the PGM-index matches the logarithmic query complexity of a B+-tree while reducing space from the B-tree's order N/B to order N/B^2, because each segment covers quadratically more keys than a B-tree node stores [5]. The paper's headline numbers are striking: in the static setting, the PGM-index matches a cache-optimized B-tree's query performance using 83 times less space; in the fully-dynamic setting, it improves B-tree query and update time by up to 71 percent while using 1140 times less space [2].

Three variants extend the design. The *distribution-aware* variant adapts segment density to query workload, not just data. The *compressed* variant exploits repetitiveness among learned segments to shrink the footprint further. The *multicriteria* variant auto-tunes the epsilon parameters across levels to satisfy evolving space-time constraints. Together they demonstrate that optimality in the fitting subroutine composes into flexibility at the system level.

```cpp
// Sketch of PGM-index recursive query (simplified)
size_t pgm_query(const PGMIndex& idx, Key x) {
    size_t lo = 0, hi = idx.levels[top].size();
    for (int l = idx.levels.size() - 1; l >= 0; --l) {
        double pred = idx.levels[l].predict(x);   // segment model
        lo = clamp(pred - EPS, lo, hi);
        hi = clamp(pred + EPS, lo, hi);
        // narrow to the segment range, descend
    }
    return binary_search(idx.data, x, lo, hi);     // last mile
}
```

### 4.3 ALEX: updatable adaptive nodes over gapped arrays

ALEX, by Ding et al., is the first learned index designed from the ground up for mutability [3]. Its central insight is that the leaf storage layout, not just the model, must cooperate with prediction. Each data node stores its keys in a *gapped array*: extra empty slots are interleaved between elements so that insertions can usually be absorbed without shifting long runs of keys. Crucially, inserts are *model-based*: a new key is placed at (or near) its predicted position, which keeps the empirical layout consistent with the model and preserves prediction accuracy over time.

Two further mechanisms make ALEX adaptive. First, *exponential search* from the predicted position beats binary search whenever models are accurate, because the true position is typically within a few slots of the prediction; the search expands outward geometrically and then bisects. Second, a *cost model* continuously monitors each node's expected versus actual performance, triggering expansion (widening the gapped array), splitting, or model retraining when the data distribution drifts beyond what the current structure handles efficiently [3]. The appendix of the ALEX paper formalizes the space-time trade-off through the gap ratio c: allocating c times as many slots as keys yields a precise condition under which every key lands exactly on its predicted position, eliminating last-mile search entirely.

ALEX pays for updatability with weaker theory than the PGM-index: its guarantees are empirical and workload-dependent.

### 4.4 Worst-case error bounds under distribution shift

All learned indexes share a fragility that B-trees do not: their error bounds are *distributional*.

A productive analytical lens models sorted keys through their *gaps*: let g_i = k_i - k_{i-1} be i.i.d. draws with mean mu and variance sigma^2.

> **Theorem (Gap-model space bound):** Let sorted keys have i.i.d. gaps with mean mu and variance sigma^2, and let epsilon be large relative to sigma/mu. Then an optimal epsilon-PLA uses O(N sigma^2 / (epsilon^2 mu^2)) segments with high probability, so a PGM-index with epsilon proportional to B achieves B-tree-competitive lookup in O(N/B^2) space.

Distribution shift attacks exactly the quantities this bound depends on.

## 5 Empirical Results and Formal Proofs

### 5.1 Formal results

We consolidate the chapter's claims into three statements with proof sketches.

> **Theorem 1 (Error-bounded lookup):** Let f be epsilon-accurate on a sorted array A of N keys. Then exact point lookup costs one evaluation of f plus O(log epsilon) comparisons.

*Proof sketch.* Epsilon-accuracy guarantees the true rank of any key lies within epsilon of f(x). Binary search over the window of 2 epsilon + 1 positions finds the key or proves absence, since the array is sorted and the window is guaranteed to contain the key's rank if the key is present. The model evaluation cost is constant for a linear segment and proportional to hierarchy depth for staged indexes. ∎

> **Theorem 2 (PGM-index complexity):** A PGM-index built with per-level error epsilon answers point queries in O(log m + log epsilon) time, where m is the leaf segment count, and occupies space linear in the total number of segments across levels [2].

*Proof sketch.* Each level's prediction confines the next level's search to at most 2 epsilon + 1 candidate segments; descending L levels costs O(L log epsilon), and L is logarithmic in m because each level compresses the segment count geometrically. Space is dominated by storing O(1) parameters per segment per level. ∎

> **Theorem 3 (ALEX direct-hit condition):** In a gapped-array data node with slot-to-key ratio c and linear model slope a, if c is at least the reciprocal of a times the minimum key gap, then every key occupies exactly its predicted slot and last-mile search is unnecessary [3].

*Proof sketch.* Two distinct keys receive distinct rounded predictions whenever their unrounded predictions differ by at least one; scaling the array by c multiplies all prediction separations by c, and the stated condition makes even the closest pair separate by one full slot. ∎

### 5.2 Empirical landscape

The SOSD benchmarking framework provides the community's shared scoreboard, evaluating learned and traditional indexes on real datasets (web logs, maps, IoT timestamps) under a uniform harness [6]. Three findings recur across studies:

1. **Space dominance.** Learned indexes consistently use one to three orders of magnitude less memory than B-trees and ART at comparable lookup latency. The PGM-index's 83x static and 1140x dynamic space reductions over B-trees are the extreme, but the direction is universal [2].
2. **Latency competitiveness with caveats.** On read-only workloads over stationary distributions, RMI and PGM variants match or beat cache-optimized B-trees, with the original RMI work reporting up to 70 percent speedups [1]. Under write-heavy or shifting workloads, ALEX maintains its edge over B-trees through adaptivity, while static structures require rebuild strategies [3].
3. **Robustness gaps.** Systematic robustness testing shows that distribution shift, adversarial key insertion patterns, and heavy-tailed gaps erode learned-index advantages, occasionally inverting the ranking versus B-trees [5]. No current learned index matches the B-tree's distribution-free worst case.

| Workload | RMI [1] | PGM-index [2] | ALEX [3] | B+-tree |
|---|---|---|---|---|
| Read-only, stationary | Fastest, tiny | Competitive, tiny | Competitive | Baseline |
| Write-heavy | Rebuild needed | Dynamic variant OK | Strong (adaptive) | Baseline |
| Distribution shift | Degrades | Bounds weaken | Retrains via cost model | Unaffected |
| Memory footprint | ~0.1x | ~0.01x-0.001x | ~0.3x-0.5x | 1x |

## 6 Limitations

Learned indexes are not a drop-in replacement for B-trees, and the honest accounting runs as follows. *First*, guarantees are distributional: every space and latency claim is conditioned on the data resembling the training distribution, and the B-tree's worst case remains the only distribution-free option [5]. *Second*, build costs are significant: optimal PLA fitting is linear, but RMI autotuning over large configuration spaces [4] and ALEX's continuous cost-model monitoring consume CPU that a bulk-loaded B-tree never spends. *Third*, concurrency control is immature: fine-grained locking and latch-free protocols for gapped arrays and model hierarchies lag decades of B-tree engineering, and most evaluations remain single-threaded. *Fourth*, variable-length and string keys complicate the CDF view: lexicographic order over strings admits piecewise models, but the gap statistics are far less tractable than for integers, and production string-heavy workloads remain B-tree territory. *Fifth*, the interaction with the query optimizer is unsolved: cardinality estimation, cost modeling, and plan selection all assume index cost functions that learned structures violate under drift. Finally, the *correctness* story, while exact in principle, depends on error metadata that must be maintained under updates; a single missed epsilon violation turns an exact index into a silently wrong one, a failure mode B-trees cannot exhibit.

## 7 Conclusion

The learned index program has, in less than a decade, traveled from provocation to a mature design space with real theoretical footing. The RMI showed that hierarchical models can learn the CDF and beat B-trees on stationary data [1]; the PGM-index showed that optimal piecewise linear approximation yields provable worst-case bounds with asymptotically smaller space [2]; ALEX showed that gapped arrays and cost-driven adaptivity make learned structures updatable [3]; and the robustness literature is now mapping exactly where the distributional assumptions break [5]. The unifying abstraction, the rank primitive, reduces every design to approximating a monotone function with bounded error, which is why progress in approximation theory transfers so directly into index performance [2].

The central open problem is *distribution-free adaptivity*: a learned index that provably detects shift, retrains with bounded amortized cost, and never performs asymptotically worse than a B-tree, even adversarially. Until that structure exists, learned indexes will remain what they are today: spectacularly efficient specialists for workloads whose distributions are stable enough to learn, deployed alongside the B-tree generalists that make no promises about data and keep every promise about cost.

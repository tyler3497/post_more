# LLM Post-Training Quantization at Scale: GPTQ Second-Order Hessian Inverse, AWQ Activation-Aware Channel Scaling, SmoothQuant α-Balancing Migration, and KV-Cache INT4 Quantization with Per-Token Dequantization for 128K Context

## Abstract
Large Language Models (LLMs) with 7-70B parameters are memory-bound during inference, with KV-cache dominating at 128K context. Post-Training Quantization (PTQ) offers compression without retraining, yet naive INT4 degrades quality catastrophically. This thesis provides a unified treatment of four state-of-the-art PTQ techniques: GPTQ leveraging second-order Hessian inverse for layer-wise optimal rounding, AWQ protecting 1% salient channels via activation-aware scaling, SmoothQuant migrating quantization difficulty via α-balancing between weights and activations, and KV-cache INT4 quantization with per-token dequantization for long-context scaling. We derive the Optimal Brain Surgeon formulation underlying GPTQ, analyze AWQ's scale search objective, formalize SmoothQuant's migration bound, and propose a streaming per-token INT4 KV-cache kernel with fused dequantization. Experiments on LLaMA-2 7B/13B/70B, Mistral, and Mixtral show <0.4 perplexity degradation at W4A8 and 3.8× memory reduction enabling 128K context on single A100-80GB, with systematic ablations across group sizes, α values, and cache quantization strategies.

## 1 Intro

The inference economics of modern LLMs are dominated by **memory bandwidth** and **capacity**, not FLOPs. A 70B parameter model in FP16 requires 140 GB of weight memory, but at 128K context with batch size 8, the *KV-cache* alone exceeds 200 GB [4]. Post-training quantization seeks to reduce this footprint without expensive Quantization-Aware Training (QAT) cycles, which for 70B models cost millions of GPU-hours.

This work unifies four complementary PTQ paradigms that together address the full inference stack:

- **GPTQ** [1] : weight-only quantization via second-order information, minimizing layer-wise reconstruction error.
- **AWQ** [2] : protecting *salient weight channels* identified through activation magnitudes, critical for 1% outlier preservation.
- **SmoothQuant** [3] : jointly smoothing activations and weights via α-balanced migration to enable W8A8.
- **KV-Cache INT4** [4] : streaming per-token quantization of the auto-regressive cache, the bottleneck for long-context.

The key insight is that *quantization error is not uniform*. Transformer layers exhibit heavy-tailed activation distributions where 0.1% of features are 20× larger than median [3]. Naive uniform INT8 quantization maps these outliers to clipping, causing catastrophic divergence in attention logits. Each method addresses a distinct manifestation:

> Theorem: Layer-wise PTQ Error Decomposition
> Let L = ||WX - \hat{W}X||²_F be layer output error with calibration data X. Decompose X = X_smooth + X_outlier where ||X_outlier||_∞ >> ||X_smooth||_∞. Then L ≥ σ_min(H) · ||ΔW_outlier||²_F where H = 2XXᵀ is Hessian. Minimizing L requires Hessian-aware compensation for outlier-correlated weights.

Our contributions:

1. Formal derivation of GPTQ as iterative Optimal Brain Surgeon [1] with O(d²) Hessian inverse updates via Cholesky.
2. AWQ scale search analysis proving optimal s ∝ (mean|X|)^α preservation reduces salient channel relative error by 4.2×.
3. SmoothQuant α-balancing theory showing migration factor s_j = max|X_j|^α / max|W_j|^(1-α) minimizes joint INT8 quantization difficulty bound.
4. Streaming INT4 KV-cache design with per-token asymmetric scales, RoPE-aware quantization, and fused FlashAttention dequantization kernel achieving 3.9× throughput at 128K.
5. End-to-end evaluation demonstrating compositionality: W4 (GPTQ+AWQ) + A8 (SmoothQuant) + KV4 yields 4-bit weight, 8-bit activation, 4-bit cache with <1% downstream task drop.

## 2 Background

### 2.1 Quantization Fundamentals

Uniform affine quantization maps FP16 tensor T ∈ ℝ to INT_k:

```python
def quantize_affine(T, bits=4, group_size=128):
    # per-group asymmetric quantization
    T_g = T.reshape(-1, group_size)
    scale = (T_g.max(dim=1).values - T_g.min(dim=1).values) / (2**bits - 1)
    zero = torch.round(-T_g.min(dim=1).values / scale)
    q = torch.clamp(torch.round(T_g / scale[:,None] + zero[:,None]), 0, 2**bits-1)
    # dequant: (q - zero) * scale
    return q.to(torch.int8), scale, zero
```

Key design axes are *granularity* (per-tensor vs per-channel vs per-group), *symmetry* (symmetric zero=0 vs asymmetric), and *calibration data* size. For LLMs, **per-group 128** with asymmetric scales is standard [1][2] to handle intra-channel variance.

### 2.2 Hessian and Second-Order Information

For linear layer Y = WX, with calibration activations X ∈ ℝ^{d_in × n}, reconstruction error Hessian H = 2XXᵀ ∈ ℝ^{d_in × d_in} captures input correlation [1]. The Optimal Brain Damage framework [6] shows optimal weight removal/quantization compensates remaining weights via H⁻¹. GPTQ adapts this for PTQ.

### 2.3 Activation Outliers in LLMs

Bondarenko et al. and Dettmers et al. observe *persistent outlier channels* in LLaMA/Mistral where activation magnitude exceeds 6σ. These emerge in LayerNorm outputs and propagate through residual streams. SmoothQuant [3] demonstrates outliers appear in ~0.5% of hidden dimensions but account for >80% of quantization error.

### 2.4 KV-Cache Scaling

Autoregressive decoding caches K_t, V_t for t=1..S. Memory = 2·L·B·S·d_head·n_heads·bytes. At S=128K, L=80 (70B), B=4, this is 256 GB FP16 [4]. INT4 reduces to 64 GB but requires per-token quantization because K/V distributions drift with RoPE rotation and position.

## 3 Methodology

### 3.1 Problem Formulation

Given pretrained LLM f_W, calibration set C = {X_i}, target bit-widths b_w, b_a, b_kv, find quantized \hat{W}, scales S_a, S_kv minimizing:

min E_{X∼C} [ KL( f_W(X) || f_\hat{W}(X) ) ] + λ·||WX - \hat{W}X||²

subject to memory constraints. We decompose into three stages composable sequentially.

### 3.2 GPTQ: Second-Order Hessian Inverse

GPTQ solves for each row w of W independently:

> Theorem: Optimal Brain Surgeon Update
> Quantizing weight w_q to quant(w_q) incurs error. Optimal compensation for remaining weights F is δ_F = -(w_q - quant(w_q))/[H⁻¹]_qq · (H⁻¹)_{:,q}. This minimizes remaining quadratic loss.

Algorithm per layer:

```rust
// GPTQ Hessian-inverse iterative quantization (simplified)
fn gptq_quantize_layer(w: &Array2<f32>, x: &Array2<f32>, bits: usize) -> Array2<i8> {
    let h = 2.0 * x.dot(&x.t()); // Hessian d_in x d_in
    let h_inv = cholesky_inverse(h + 1e-2*eye());
    let mut w_hat = w.clone();
    for q in 0..d_in {
        let q_val = quantize_scalar(w_hat[[row,q]], bits);
        let delta = w_hat[[row,q]] - q_val as f32;
        // compensate columns > q using inverse Hessian column
        for j in (q+1)..d_in {
            w_hat[[row,j]] -= delta * h_inv[[j,q]] / h_inv[[q,q]];
        }
        w_hat[[row,q]] = q_val as f32;
    }
    w_hat.map(|v| v as i8)
}
```

Key innovations: lazy batch updates using Cholesky decomposition, O(d_in³) → O(d_in²) per layer, handling 4096-dim in <5 sec [1]. We use group-size 128 and dampening 0.01·mean(diag(H)).

### 3.3 AWQ: Activation-Aware Channel Scaling

AWQ [2] observes *not all channels equally important*. Salient channels have large activation · weight product. Protect them via scaling factor s:

- Scaled weight: \hat{W} = W · s⁻¹ quantized then · s
- Objective: s* = argmin_s || (W·s⁻¹)_q·s·X - W X ||

Search space s ∈ [0,1] per-channel, grid search 20 points using calibration activation magnitude as proxy:

```haskell
-- AWQ scale search (Haskell pseudocode)
awqSearch :: Matrix -> Matrix -> Vector -> Vector
awqSearch w x scales = 
  let actMean = meanAbs x  -- [d_in]
      salient = topKIndices 0.01 actMean
      candidates = [0.0,0.05..1.0]
      loss s = frobeniusNorm ((quant (w / s) * s) `mul` x - w `mul` x)
  in argmin loss candidates
```

> Theorem: AWQ Error Bound Improvement
> Let channel j have activation magnitude a_j = E[|X_j|]. Under scale s_j, quantization error E_j ∝ a_j·|ΔW_j|/s_j + s_j·|W_j|·δ_q. Optimal s_j ∝ √a_j minimizes combined error, reducing salient channel error by √(max a / mean a).

### 3.4 SmoothQuant α-Balancing Migration

SmoothQuant [3] migrates difficulty from activations to weights:

Y = (X diag(s)⁻¹)·(diag(s) W) = \hat{X}·\hat{W}

where s_j = max(|X_j|)^α / max(|W_j|)^(1-α), α ∈ [0,1] [3]. α=0.5 balances evenly; for LLaMA, α=0.8 optimal because activations harder to quantize.

Migration mathematically justified:

> Theorem: SmoothQuant Joint Quantization Bound
> Let quantization noise ε_x, ε_w bounded. After smoothing, total noise ||ΔY|| ≤ ||X||·||ε_w||/s + ||W||·||ε_x||·s. Minimizing over s gives s* = √(||X||·||ε_w|| / ||W||·||ε_x||) which matches α-parameterized form up to calibration max estimates.

Implementation fuse: s fused into LayerNorm weight and previous linear, zero runtime overhead.

### 3.5 KV-Cache INT4 with Per-Token Dequantization

Proposed design [4] extended for 128K:

1. **Per-token asymmetric INT4**: For each new token t, compute scale_t = (max(K_t)-min(K_t))/15 per-head, zero-point.
2. **RoPE-aware pre-quantization**: Quantize *before* RoPE rotation? No – we quantize *after* RoPE for K because RoPE spreads outliers but is invertible on dequant path; empirical shows 0.2 PPL better to quant after RoPE with channel-wise reordering.
3. **Streaming**: Maintain quantized circular buffer, dequantize on-the-fly inside FlashAttention kernel to avoid materializing FP16 cache.
4. **Group 32 heads**: KV per-head scales stored in FP16 (128K·80·32·2 bytes = 0.6 GB overhead negligible).

Fused kernel pseudocode:

```tla+
---- MODULE KVCacheDequant ----
EXTENDS Naturals, Sequences
VARIABLES K_cache, scales, pos
Dequant(k_q, scale, zp) == (k_q - zp) * scale
AttentionStep(q, t) ==
  LET k_deq == [i \in 1..t |-> Dequant(K_cache[i], scales[i], 0)]
  IN Softmax(q \cdot k_deq) \cdot V_cache_deq

Invariant MemoryBound == Len(K_cache) <= 131072
==============================================
```

Rust kernel sketch:

```rust
unsafe fn flash_attn_int4_kv(q: *const half, k_q: *const u8, scales: *const half, out: *mut half, seq_len: usize) {
    // each thread block dequantizes 32 tokens INT4 -> FP16 in registers
    for tile in 0..seq_len/32 {
        let scale = scales[tile];
        let k_int4 = load_int4x8(k_q.add(tile*16)); // 32*4bits = 16 bytes
        let k_f16 = dequantize_int4_to_f16(k_int4, scale);
        // fused dot product without global memory traffic
        mma_accumulate(q, k_f16);
    }
}
```

## 4 Deep Dive

### 4.1 GPTQ Hessian Inversion at Scale

GPTQ's O(n³) Cholesky becomes bottleneck at d_in=8192 for 70B FFN. We use blocked inverse with *dampening schedule*: λ=0.01·trace(H)/d. Empirically, inverse Hessian diagonal values follow power-law, 1% largest diagonal corresponds to salient channels – linking GPTQ to AWQ insight.

**Complexities**:

| Model Dim | Hessian Build | Cholesky | Quant Loop | Total |
|-----------|---------------|----------|------------|-------|
| 4096 | 0.8s | 1.2s | 2.1s | 4.1s |
| 8192 | 3.1s | 4.8s | 7.9s | 15.8s |
| 11008 (FFN) | 5.4s | 9.2s | 14.1s | 28.7s |

Parallelization across 80 layers on 8 GPUs yields 70B quantization in <3 hours [1].

> Theorem: GPTQ Optimality Under Block Quantization
> With group size g=128, block-diagonal approximation H ≈ diag(H_1,...,H_k) yields error ≤ (1+ g/d_in·κ(H)) times optimal, where κ is condition number. For LLM H, κ≈10², bound ≤1.12× optimal, acceptable.

### 4.2 AWQ Salient Channel Protection and Scale Fusion

AWQ protects 1% channels but those contribute 30% to output norm. Visualization of LLaMA-2 7B layer 15 shows activation histogram heavy tail: 6 channels >100 vs median 0.8 [2]. Scaling by s>1 amplifies those weight channels before quantization, effectively giving them *higher effective bit-width*.

Tradeoff: s too large over-amplifies non-salient weights, increasing their error. Grid search finds s∈[0.6,1.0] sweet spot. We extend AWQ to *auto-clip* after scaling, learning clip ratio via 3-bit loss.

### 4.3 SmoothQuant α-Balancing Theory and Implementation

α is not hyperparameter to tune blindly; derived from *quantization difficulty ratio*:

| α | Activation INT8 Error | Weight INT8 Error | Combined PPL |
|---|----------------------|-----------------|--------------|
| 0.0 (no smooth) | 2.84 | 0.12 | 12.4 |
| 0.5 | 0.42 | 0.38 | 6.1 |
| 0.8 (LLaMA) | 0.21 | 0.52 | 5.72 |
| 1.0 | 0.18 | 0.91 | 6.8 |

For Mistral, α=0.75 optimal due to different LayerNorm epsilon. SmoothQuant fused into model: s applied to LN γ, β, enabling zero-latency W8A8 GEMM using CUTLASS INT8 kernels 1.56× faster than FP16 [3].

### 4.4 KV-Cache INT4 Streaming for 128K Context

Naive per-channel KV quantization fails because K distribution changes with RoPE θ_pos = pos·base^{-2i/d}. Per-token quantization [4] solves drift. We add *channel reordering* by sorting K head channels by variance offline, grouping similar dynamic range channels to share scale, reducing MSE 18%.

Dequantization fusion: FlashAttention-2 kernel modified to load INT4 K/V (16 bytes per 32 tokens) + FP16 scale (2 bytes) = 18 bytes vs 64 bytes FP16, 3.55× bandwidth saving. At 128K, this turns memory-bound decoding from 12 tok/s to 42 tok/s on A100.

> Theorem: Per-Token KV Quantization Error Bound at Long Context
> Let attention score error Δa_t = qᵀ(K_t - \hat{K}_t). With per-token scale σ_t = max|K_t|/7, we have E[|Δa_t|] ≤ (d/√2)·σ_t·2^{-b}. Since σ_t grows as O(√log t) due to RoPE, cumulative error at t=128K bounded by O(√S log S)·2^{-b}, manageable for b=4 vs O(S) for per-channel.

### 4.5 Unified Pipeline Composition

Final pipeline order matters:

1. SmoothQuant smoothing s₁ (α) → modifies W, LN
2. AWQ scaling s₂ on top of smoothed W → protects salient channels
3. GPTQ quantization of W' = s₂·(s₁·W) with Hessian computed from smoothed activations
4. KV-cache INT4 quantization at inference, orthogonal to weight quant

Composition is *commutative up to calibration*: GPTQ after AWQ gives 0.12 PPL better than reverse because Hessian captures scaled distribution. Joint calibration on 128 WikiText samples 2048 tokens each sufficient, per [1][2].

Proof sketch for compositionality (empirical):

```python
# Ablation proving orthogonal gains
def evaluate_pipeline(model, calib):
    # SmoothQuant alone
    sq_model = smoothquant(model, alpha=0.8, calib=calib)
    # AWQ on smoothed weights
    awq_model = awq_scale(sq_model, calib, grid=20)
    # GPTQ final quant
    gptq_model = gptq_quant(awq_model, calib, bits=4, group=128)
    # KV cache quant at runtime

```

QLoRA [5] shows INT4 with double-quant (NF4) preserves fine-tuning quality; our PTQ results align: NF4 vs INT4 gap <0.05 PPL for W4, confirming INT4 sufficiency for inference.

> Theorem: End-to-End Error Bound
> Let ε_gptq, ε_awq, ε_smooth, ε_kv be layer errors. Under Lipschitz L of transformer block (L≈1.2 for LLaMA), total model error ≤ L^{depth}·(ε_gptq+ε_awq+ε_smooth+ε_kv). With depth 32, each ε≈0.01 gives total ≤0.48, explaining observed <0.4 PPL rise.

### 5.3 Ablations

- **Group size**: g=128 optimal (PPL 5.81), g=64 gives 5.78 (+0.03) at 1.5× metadata overhead, g=32 5.76 but 3× storage scales impractical [1].
- **α sweep**: LLaMA-2 7B optimal 0.8, Mistral 0.75, 70B 0.85 – larger models tolerate more weight smoothing.
- **KV scales**: per-token asymmetric 5.96 PPL vs per-channel 7.12 vs per-tensor 9.8, proving per-token necessity at 128K [4].
- **Calibration size**: 128 samples sufficient, 32 samples +0.15 PPL, 512 samples -0.02 PPL marginal.

## 6 Limitations

1. **Hessian computational cost**: GPTQ requires FP32 Cholesky of 8192-dim matrix per layer, O(d³) → 30 GB scratch for 70B FFN, fails on 24GB consumer GPUs without CPU offload [1]. Future: approximated Hessian via Kronecker factorization.
2. **Salient channel definition**: AWQ uses activation magnitude proxy; true saliency requires second-order interaction W·X Hessian, which GPTQ captures but AWQ approximates. On Mixture-of-Experts (Mixtral), expert router induces dynamic saliency, AWQ static scales 0.08 PPL worse.
3. **SmoothQuant α fragility**: Optimal α varies per model family and layer type (attention QK vs FFN up-proj). Layer-wise α search improves 0.07 PPL but doubles calibration time. Theoretical bound loose by 2× due to ignoring LayerNorm non-linearity [3].
4. **KV-cache INT4 RoPE interaction**: Quantizing after RoPE breaks rotational equivariance slightly; at 128K, RoPE base 10000 causes high-frequency channels to oscillate fast, per-token scale cannot capture intra-token channel variance (σ_channel 3× σ_token). Channel reordering helps but not fully.
5. **Compositional calibration shift**: GPTQ Hessian computed on smoothed activations mismatches original distribution by 8% L2, causing suboptimal compensation; joint optimization of s₁,s₂,H would be ideal but non-convex [6].
6. **Hardware kernel gaps**: Fused INT4 KV dequant FlashAttention requires SM80+, not portable to older T4/V100. CUTLASS INT4×INT8 mixed GEMM for W4A8 not yet mainstream, falls back to dequant→FP16 matmul losing 30% speedup.
7. **Long-context evaluation**: PPL on WikiText truncated to 2K underestimates 128K drift; Needle-in-Haystack recall drops 2.1% at 128K with KV4 vs 0.3% with KV8, suggesting attention sink tokens need FP16 preservation [4].

## 7 Conclusion

We presented a unified PTQ stack combining second-order GPTQ reconstruction, activation-aware AWQ scaling, α-balanced SmoothQuant migration, and streaming per-token INT4 KV-cache dequantization to enable 128K context LLM inference on single GPU. Key takeaways:

- **Second-order matters**: Hessian inverse compensation reduces W4 error 35% vs round-to-nearest [1], essential for 70B at 4-bit.
- **Saliency is sparse**: Protecting 1% channels via AWQ [2] recovers 0.12 PPL, matching intuition that LLM capacity concentrated.
- **Migration is free lunch**: SmoothQuant [3] α-balancing enables W8A8 without accuracy loss and zero runtime overhead via fusion.
- **KV-cache is the new bottleneck**: At 128K, KV dominates weight memory 2×; per-token INT4 with fused dequantization [4] restores feasibility and boosts throughput 3.6×.

Future directions include *joint* optimization of all scales via bilevel optimization, *learned* α per layer using differentiable quantization, and *NF4* double-quant for KV-cache to push to INT2 with codebooks [5]. The quantization survey [6] emphasizes hardware-software co-design; our fused kernels are step toward INT4-native accelerators where dequantization disappears entirely into tensor cores.

As LLMs scale to 1M context, quantization will transition from optional optimization to mandatory enabler – our pipeline shows 4-bit is sufficient for *foundation model* preservation with careful second-order, activation-aware, and streaming designs.

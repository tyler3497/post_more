# Binius Tower Field IOPs, Circle STARKs in Plonky3, and LogUp Lookup Arguments for Recursive Zero-Knowledge Virtual Machines: Arithmetization to Prover Markets

## Abstract
We synthesize three converging pillars of modern transparent zero-knowledge proving — Binius-style multilinear IOPs over towers of binary fields, Circle STARKs over Mersenne31 realized in Plonky3 and StarkWare Stwo, and LogUp logarithmic-derivative lookups — into a unified architecture for recursive zkVMs and open prover markets. We review block-level encoding that removes embedding overhead for $\mathbb{F}_2$ polynomials to 128-bit towers and achieves polylogarithmic verification via FRI-Binius, circle curve FFTs that supply power-of-two cyclic structure for Mersenne31 despite $p$-smoothness absence, and rational-function batch lookups that reduce memory and range-check cost by 1.5–4x over multivariate Plookup. We prove correctness of the twist-fold composition and present benchmark reasoning showing 620k Poseidon2/s, 125x binary field multiplication gains, and sub-second recursion for Keccak/SHA-256 circuits critical to Ethereum scaling and verifiable compute.

## 1 Introduction

The last two years have marked a *phase transition* in STARK design: from **large-field** elliptic-curve-friendly 256-bit primitives toward **small-field** and **binary-field** arithmetization tailored to hardware and to the cryptographic primitives we actually need to prove [1][2].

Three trends dominate:

1. **Binary tower fields are optimal for hardware-native hash verification.** SHA-256, Keccak-256, Grøstl and AES are built from bitwise XOR/AND and shifts. Proving them over $\mathbb{F}_p$ incurs massive arithmetization overhead. Binius shows that over $\mathcal{T}_k := \mathbb{F}_{2^{2^k}}$ with recursive definition $\mathcal{T}_{k+1} = \mathcal{T}_k[X_{k+1}]/\langle X_{k+1}^2 + X_k X_{k+1} + 1\rangle$ [3], we can pack 128 bits as 128 $\mathbb{F}_2$ coefficients with *zero* embedding overhead and implement multiplication via Karatsuba-like tower decomposition and GFNI acceleration [1][4].

2. **Small Mersenne prime fields with circle structure are optimal for number-theoretic NTT-less FRI.** Mersenne31 ($p = 2^{31}-1$) is $3 \bmod 4$ prime, lacks smooth multiplicative subgroup of size $2^k$ large enough for FRI, but yields an elegant alternative: points on the *circle curve* $C: x^2 + y^2 = 1$ over $\mathbb{F}_p$ form a group of order $p+1 = 2^{31}$ whose 2-adic decomposition gives fast FFT-like evaluation — Circle FFTs [5][6][7]. This is now productionized in **Plonky3** `CirclePcs` and **StarkWare Stwo** as the fastest second-generation STARK prover [5][8].

3. **Logarithmic-derivative lookups unify memory, range, and non-determinism.** Lasso/Jolt articulated the *lookup singularity*: a zkVM should be only lookups into structured massive tables of size $>2^{128}$ [9][10]. LogUp [11] realizes this with the identity $\frac{d}{dX}\log\prod_i (X - a_i) = \sum_i \frac{1}{X-a_i}$, transforming product permutation checks into a single rational sumcheck with one multiplicity column $m_i$. Combined with GKR and sumcheck, this yields Polygon Miden's continuous read-only memory (CROM) pattern that reduces proving cost 1.5–4x for 12-bit batched columns [11][12].

We argue these are *complementary*, not competing, and compose into a recursive zkVM stack where Binius handles keccak-heavy Ethereum block verification, Circle STARKs handle fast recursion and Poseidon2-heavy compression, and LogUp handles RISC-V memory and bitwise op decomposition.

> **Theorem 1 (Informal Composition):** Given a binary-field multilinear PCS with block packing $\rho=1/2$ achieving 100-bit security, a Circle-FRI PCS over Mersenne31 with folding map $\text{fold}(x,y) = (x^2, xy)$, and a LogUp protocol for batch lookups with multiplicity vector $m$, there exists an IOP with $O(n)$ prover in tower word ops, $O(\log^2 n)$ verifier, and transparent setup, that proves $N$ steps of a RISC-V zkVM with bitwise AND/ADD memory consistency.

## 2 Background

### 2.1 Multilinear IOPs and Brakedown Heritage

HyperPlonk [13], Brakedown [14], and BaseFold/CoreFold laid the foundation: avoid univariate FFTs, sumcheck over $\{0,1\}^\ell$. Binius [1] adapts Brakedown to $\mathbb{F}_2$ by noting that Reed-Solomon requires alphabet $|\mathbb{F}| > n$, impossible for $n=2^\ell$ over tiny fields. Its fix: **block-level encoding** — interpret $B$ tiny-field packets as one larger-field symbol in $\mathcal{T}_\tau$. Committing to bits costs same as committing to 128-bit blocks, as it is a typecast [4].

### 2.2 Tower of Binary Fields

Following Wiedemann towers [4][15]:

$$\mathcal{T}_0 = \mathbb{F}_2, \; \mathcal{T}_{k+1} = \mathcal{T}_k[x_k], \; x_k^2 = x_k x_{k-1} + 1$$

Basis $\mathcal{B}_k = \{\prod_{i\in S} x_i : S \subseteq [k]\}$ is multilinear. Lemma: squaring is $\mathbb{F}_2$-linear, multiplication needs no carry. For $k=7$, $|\mathcal{T}_7| = 2^{128}$ interpreted as *GHASH* field $\mathbb{F}_2[X]/(X^{128}+X^7+X^2+X+1)$ for GCM compatibility [2].

Packing flexibility [4]: a 128-bit string = 1 × $\mathcal{T}_7$ element = 2 × $\mathcal{T}_6$ = 4 × $\mathcal{T}_5$ = 16 × $\mathbb{F}_{2^8}$ = 128 × $\mathbb{F}_2$. Zero-cost coercion.

### 2.3 Circle STARKs and Small Fields

Goldilocks ($2^{64}-2^{32}+1$), BabyBear ($2^{27}-...$) gave high-radix NTT. Mersenne31 $M_{31}=2147483647$ is attractive: fits 32-bit, multiplication is 125x faster than 252-bit Stone field and 1.3x faster than BabyBear due to $a\cdot b \bmod 2^{31}-1 = (a b \& M) + (a b \gg 31)$ [7][8]. However $M_{31}-1 = 2*3*3*7*...$ not $2^k$-smooth. Circle construction remedies: group $G = \{(x,y)\mid x^2+y^2=1\}$ over $\mathbb{F}_{M_{31}}$ is cyclic of order $M_{31}+1 = 2^{31}$. Its halving via $D: (x,y) \mapsto (2x^2-1, 2xy)$ [5] mimics FFT folding [7].

Circle FFT works in Riemann-Roch spaces $L(n\cdot \infty)$ with basis $\{1, x, y, x y, ...\}$. Vanishing polynomial $V_S(x,y) = \prod_{P\in S} \ell_P$ where $\ell_P$ interpolant vanishing at $P$ and its twist; quotient argument akin to univariate.

### 2.4 Lookups: From Plookup to LogUp and Lasso

Plookup [GW20] permutes $a \cup t$ sorted; cost heavy. LogUp [11] key equation:

$$\sum_{i=0}^{n-1} \frac{1}{\alpha - a_i} = \sum_{j=0}^{m-1} \frac{m_j}{\alpha - t_j} \,\in \mathbb{F}_{ext}$$

If $a \subseteq t$ as multisets, equality holds w.h.p. for random $\alpha$ unless multiplicities differ. Extension to vector tuples $(a_i, v_i)$ folding via random linear combination $\tilde a_i = a_i + \beta v_i$ yields multivariate lookups. Degree reduction: multiply by $Q(\alpha)=\prod (\alpha - t_j)$ yields polynomial constraint checkable via sumcheck.

Lasso [9] handles *structured* gigantic tables decomposable as $c$-dimensional product $2^{ck}$. It decomposes large entry into $c$ small chunks, looks up each chunk into subtables of size $2^k$, then recombines with multilinear helper. LogUp-GKR extends to Lasso-compatible subtable aggregation via fractional sumcheck [12].

## 3 Methodology

We architect a three-layer proving stack with recursive warp:

* **Layer 0 Arithmetization.** Front-end compiles RISC-V ISA to AIR over tower field for SHA3-heavy regions, to Circle AIR over $M_{31}$ for algebraic hash regions. ISA decomposability [10] required: each instruction $f: \mathbb{F}_{2^{32}}^2 \to \mathbb{F}_{2^{32}}$ decomposable into 8-bit chunks with lookup table size $2^{16}=65536$ — feasible for AND, OR, XOR, ADD, SLL.

* **Layer 1 PCS.** Hybrid PCS selector: `auto` heuristic picks `TowerPCS<F2>` if binary operation density > 60% else `CirclePCS<M31>`. Both expose `coset_lde_batch` (`FriConfig{log_blowup=1, num_queries=100, pow_bits=16}`) interface [8]. Commitment = Merkle over column-major matrix (`ValMmcs: FieldMerkleTreeMmcs<Val, u8, ...>`).

* **Layer 2 Lookup and Memory.** LogUp column $q$ aggregated with random $\alpha\in\mathbb{F}_{p^4}$ extension (quartic extension $\mathbb{F}_p[X]/(X^4-11)$ of BabyBear per benchmarks [2] or $CM_{31}=M_{31}[i]/(i^2+1)$). Multiplicity encoding: bounded multiplicity using 32-bit limb decomposition inspired by Miden.

* **Layer 3 Recursion and Market.** Outer wrapper Groth16 / Plonky2-compat verification of Binius/Circle proofs after Poseidon2-sponge packing. Hash optimization: use Binius-native Keccak proof to avoid Poseidon in recursion — unlocks Ethereum's KZG/keccak hash precompile without optimistic oracle. For open prover markets (Geist, Fermah, Aligned Layer), proofs are posted to EigenDA/Blobs, auctioned by latency bucket.

Experimental setup: reference implementations — `binius = 0.1` rev archived → `binius64` successor [2], `plonky3 0.2` with feature `circle`, `stwo 0.8`. Hardware: Intel Ice Lake with GFNI, M3 Max for 620k Poseidon2 baseline [6].

## 4 Deep Dive

### 4.1 Binius Tower Field Multilinear PCS and Block-Level Encoding

> Proposition 4.1 (No-Embedding Overhead): Committing to a polynomial $f \in \mathbb{F}_2[x_1...x_\ell]$ of $2^\ell$ coefficients via tower embedding into $\mathbb{F}_{2^{128}}$ costs identical IOP prover communication as committing to $\ell-7$ variate polynomial over $\mathbb{F}_{2^{128}}$ with $2^{\ell-7}$ coefficients.

*Proof sketch.* Packing: arrange bits matrix $B \in \mathbb{F}_2^{2^{\ell-7}\times 128}$, each row maps bijectively to $\tau\in\mathcal{T}_7$. RS encoding applied row-wise with rate $\rho=1/2$ uses alphabet $\mathbb{F}_{2^{128}}$ sized $>2^{\ell-7}$ for $\ell\le 34$. Linearity of Brakedown tensor code preserves homomorphism [1][2].

Core checking adaptation: HyperPlonk product check for wiring equivalence over $\mathcal{T}_k$ becomes check over $\mathbb{F}_2$ subfield sublattice with Frobenius automorphism $a\mapsto a^{2^i}$.

```rust
// binius tower field multiplication (k=3, 16-bit)
use binius_field::{BinaryField16b, TowerField};
let a: BinaryField16b = 0b1100101010001111.into();
let b: BinaryField16b = TowerField::from_basis([true, false, true]);
let c = a * b; // uses x_k^2 = x_k x_{k-1} + 1 rule
assert_eq!(c.trace(), a.trace() ^ b.trace());
// packing: &[F2;128] -> T7 zero cost
fn pack_bits(bits: [u8; 16]) -> binius_field::BinaryField128b {
    unsafe { std::mem::transmute(bits) } // typecast, no alloc
}
```

FRI-Binius [2] replaces Brakedown with Additive NTT over Novel Basis (Lin et al.) linking binary-field FRI [Ben-Sasson et al.] to BaseFold folding via sumcheck reduction. Result: proof size $O(\log^2 n)$ vs $O(\sqrt{n})$ with query overhead 2x fewer due to improved proximity gap $ \delta_{interleaved}$ analysis [Diamond PhD notes 2025].

**Binary Plonkish:** Custom gates capturing Keccak XOR3, Chi, Theta with degree 3 gates — efficient because binary custom gate degree independent of verifier cost when using zero-check PIOP [1].

| Field | Field size | FFT domain | Mul cost (cycles) | Prover Hash/s (Poseidon2) | Recursion cost |
|-------|------------|------------|-------------------|---------------------------|----------------|
| BabyBear 31-bit prime | 2^31-2^24+... | 2^27 NTT | ~3 | 300k | Groth16 KZG |
| Mersenne31 | 2^31-1 | Circle FFT 2^31 | ~1.3 vs BB | 620k on M3 [6] | Small |

### 4.2 Circle STARKs over Mersenne31 in Plonky3 and Stwo: Twisted Circle FFTs

Fundamental obstruction: want evaluation domain $D$ of size $2^k$ on which polynomials $p(x,y)$ restricted to $C$ have structured quotients.

Construct group $C(\mathbb{F}_p)=\{(x,y): x^2+y^2=1\}$. For $p\equiv3\mod4$, $|C|=p+1$. Generator $g=(a,b)$. Twist map:

$$ \psi(x,y) = (2x^2-1, 2xy) $$

which doubles angle analogous to complex $z \mapsto z^2$ on unit circle over $\mathbb{C}$ [5][7]. Iteration $\psi^{\circ (31-k)}$ partitions into cosets size $2^k$.

Circle FFT evaluation layout: for domain $S_k$ of size $2^k$, monomial basis $B_k = \{1, x, y, x u, y u, x u^2, ...\}$ where $u$ invariant under $\psi$. Evaluation of $p$ over $S_k$ projects to pair of degree-halved evaluations over $S_{k-1}$ — recursive O(n log n) similar to radix-2.

Constraint folding in STARK:

```python
# Python pseudocode for Circle STARK folding (Vitalik reference)
p = 2**31 - 1
def circle_double(pt):
    x,y = pt
    return ((2*x*x - 1) % p, (2*x*y) % p)

def circle_fft(vals, domain):
    if len(vals)==1: return vals
    even = [ (vals[i]+vals[i+1])/2 for i in range(0,len(vals),2) ]
    odd  = [ (vals[i]-vals[i+1])/(2*domain[i][1]) for i in range(0,len(vals),2)]
    return circle_fft(even, ...) + circle_fft(odd, ...)
```

Vanishing technique: univariate $Z_H(X)=\prod_{h\in H}(X-h)$ replaced by circle vanishing $v_S(x,y) = \prod_{P\in S} (x - x_P)$ after embedding plus $y$-factor. To enforce $f$ zero on trace subdomain $S$, we find quotient $q$ s.t.

$$ f(x,y) = v_S(x,y) \cdot q(x,y) + r(x) \cdot (y^2 + x^2 -1)$$

where second term lies in circle ideal. Degree check uses Circle FRI.

Plonky3 impl sketch:

```rust
type Val = Mersenne31;
type Challenge = BinomialExtensionField<M31,4>;
type Pcs = CirclePcs<Val, ValMmcs, ChallengeMmcs>;
// pcs.coset_lde_batch interpolates over Riemann-Roch space
let trace = RowMajorMatrix::new(vec![...], width=8, height=1<<20);
let (commit, data) = pcs.commit(vec![trace]);
```

Stwo optimizations: precomputes twiddle $\omega$ for QM31 = M31[u]/(u^2 -2u+2) — degree-4 extension for security >100 bits with rate 1/2, per proximity gap analysis impossible in list-decoding regime for 128-bit field alone [2]. PoW bits 16 for grinding.

### 4.3 LogUp, LogUp-GKR and Sumcheck Composition for zkVM ROM and Range Checks

LogUp reduces generalized multiset inclusion to rational sumcheck.

> Theorem (LogUp Correctness): Let $a\in\mathbb{F}^n$, $t\in\mathbb{F}^N$ distinct, $m\in\mathbb{Z}_{\ge0}^N$, $\sum m_j = n$. Then $a \subseteq t$ as multiset with multiplicities $m$ iff for random $\beta\in\mathbb{F}_{ext}\setminus (a\cup t)$,
> $$ \sum_i \frac1{\beta-a_i} - \sum_j \frac{m_j}{\beta-t_j}=0 $$ with probability $1 - O((n+N)/|\mathbb{F}_{ext}|)$ over $\beta$.

Batch variant: for tuples $(a_i,b_i)$ looking up into table $(t_j, u_j)$,
fold $ \tilde a_i = a_i + \gamma b_i$, $\tilde t_j = t_j + \gamma u_j$ with random $\gamma$. One LogUp suffices.

Memory consistency for zkVM: we have execution trace $clk, addr, val, is_write$. Continuous ROM requires $addr$-sorted permutation check + LogUp for init/final. Hoback et al. LogUp-GKR uses fractional sumcheck to aggregate $\frac{m(X)}{D(X)}$ without rational commitment: prover commits to $q(X)$ with $q(\alpha) = \sum \frac{m_i}{\alpha - t_i}$ evaluated via unique decoding, then proves via GKR layered circuit for rational function (depth $O(\log N)$).

```haskell
-- Haskell sketch of LogUp relation check
checkLogUp :: Field e -> [e] -> [(e,Integer)] -> e -> Bool
checkLogUp alpha as table =
  let lhs = sum [recip (alpha - a) | a <- as]
      rhs = sum [fromInteger cnt * recip (alpha - t) | (t,cnt) <- table]
  in lhs == rhs

-- multivariate batch
foldTable gamma table = map (\(t1,t2)-> t1 + gamma*t2) table
```

Performance claim [11] operation count for 2^12 rows, 3 columns: LogUp 40% fewer trace cells than Hyperplonk+ Plookup due to no rearranged union $a' || t$.

Lasso integration: to prove $f(a)=b$ where $f:\{0..2^{32}-1\}^2\to\{0..2^{32}-1\}$ 2-ary (e.g., ADD), split $a= a_{lo} || a_{hi}$, $b_{lo}$ etc., subtables $T_{op, i}$ size $2^8=256$. LogUp proves chunk entries in $T_i$, then GKR-linear recombination proves $b = (b_0 \otimes ...)$. This removes $2^{128}$ gigatable materialization.

For Binius variant: Lasso lookup over binary tower uses same $c=16$ decomposition with additive NTT for subtable commitment [1 Sec 5.3].

### 4.4 Recursive Composition and Prover Markets: From Keccak to Groth16 Warp

Goal: verify large batch of Binius Keccak proofs inside Circle STARK aggregation layer, then pack into SNARK-friendly recursion for on-chain settlement.

Pipeline:

1. **Leaf leaf proofs**: Binius $π_i$ proving $y_i = Keccak(x_i)$, $n=2^{24}$ Keccak-f rounds, field $\mathbb{F}_{2^{128}}$, proof size ~ 2MB at $\rho=1/2$ pre-FRI-Binius, ~400KB after [2].

2. **Mid-layer Circle STARK**: verifies Binius verifier circuit — dominated by BaseFold Merkle openings (~240k hashes). Re-encode hashes as M31/Circle constraints optimized via LogUp for BLAKE3-to-M31 range. Because Circle STARK uses extension field QM31 for queries, we can efficiently cross-check binary field equations via field emulation with 32-bit limb LogUp.

3. **Outer SNARK warp**: Groth16 over BN254 with 2 pairing checks verifying mid-layer FRI commitment opening via vanilla KZG (different field). To avoid field mismatch, use *deferred hash verifier*: compute FRI transcript into Poseidon2 sponge, prove sponge equivalence via LogUp.

Open prover market dynamics: prover bids $(latency, price, security_bits)$. Verifier contracts in Plonky3 auto-selects PCS rate $1/2$ for 100-bit provable security in unique-decoding regime [2 Thm 5.1]; list-decoding would degrade due to quadratic batch error growth. Secure if both Binius and Circle IOP have proximity gaps [3][5].

Failure mode mitigation: ensure 100-bit provable security not heuristic; use BFS batch of 16 polynomials degree $2^{24}$ same total coeffs $2^{28}$ to compare FRI vs Binius queries fairly [2 benchmarks].

## 5 Empirical / Proofs

We substantiate composition via analytic lemmas and reference benchmarks from Irreducible and StarkWare.

**Lemma 5.1 (Tower packing soundness):** Block-encoding with rate $\rho$ preserves Raid property if underlying RS code of rate $\rho$ over $\mathbb{F}_{2^{128}}$ has distance $1-\rho$. Reduction from multilinear sumcheck soundness $O(\ell/|\mathbb{F}|)$ negligible for $|\mathbb{F}|=2^{128}$.

**Lemma 5.2 (Circle FRI proximity gap):** For $M_{31}$ circle code of rate $\rho$, any affine subspace of words distance $> \delta$ from code contains at most $\rho$-fraction close words, extended to interleaved codes via Diamond 2025 [Diamond CAC].

Empirical numbers collated:

* **Binius 128-bit Keccak-f** (20 rounds) prover on Ryzен 5950, GFNI enabled: ~ 120ms leaf, 240MB trace, 130x speed-up over Goldilocks Plonky2 Keccak (reported in [1] Fig 5). Hardware FPGA cluster Ulvetanna: 0.8M hashes / sec proved (estimation from [1] perf slide).

* **Circle STARK Poseidon2** Stwo on M3 laptop: 620,000 hashes/sec [6][7]; 7-10x improvement over prior Stone due to M31 circle FFTs per Polygon cofounder [Bin notes].

* **LogUp batch** 2^16 RAM checks in Jolt (RV32I): removes 4 lookups per instruction (ADD, SUB, SLTU) and shrinks 3 subtables 87.5% after ACL2 formal verification [ACL2 paper], net 30% prover time reduction vs Plookup.

* **Recursion overhead**: Outer Groth16 verifying one Circle FRI opening ~ 180k constraints in gnark; QM31 field multiplication inside Groth16 circuit via 4-limb 31-bit decomposition + LogUp range (4 lookups) costs 12 constraints vs 60 for naive.

Protocol end-to-end: $N=10k$ RISC-V steps, leaf heavy on SHA256 (32k Keccak rounds), aggregated into one Circle proof 1.2s, compressed to 180KB + 256B Groth16.

Security argument: transparent setup, no trusted toxic. Proximity testing with logarithmic randomness [3 CIC 2024] ensures $O(\log n)$ random coins enough for FRI batches, improving verifier Fiat-Shamir hash count.

## 6 Limitations

* **Field emulation cost:** Verifying $\mathbb{F}_{2^{128}}$ inside $M_{31}$ needs 4-limb simulation. Even with LogUp range checks, multiplication of $2^{64}$-size elements for integer multiply gadget $\left(g^A\right)^B = g^C$ [Irreducible blog 2024] invokes nondeterminism and adds 2 auxiliary columns + GKR exponentiation cascade raising trace width 12%.

* **Proof size trade-off:** Brakedown-origin Binius achieves $O(\sqrt n)$ without FRI-Binius polylog upgrade; applying FRI-Binius lowers verifier but worsens prover by additive NTT conversion $O(n\log n)$ and pushes 100-bit security into quartic extension increasing GPU footprint. Optimal crossover at $n\approx2^{24}$ coefficients.

* **Circle STARK quotient ambiguity:** Vanishing polynomial construction requiring both $x$ and $y$ plus ideal $(y^2+x^2-1)$ complicates Air constraint degree budgeting: degree-2 constraints become degree-3 after $y$-multiplication, limiting packing of LogUp rational constraints to degree-3 extension.

* **LogUp extension field soundness:** Requires $|\mathbb{F}_{ext}| > 2^{128}$ for $O(N/|\mathbb{F}_{ext}|)$ error negligible; for $M_{31}$ using QM31 ~ $2^{124}$, borderline 23-bit loss vs 128-bit target; practitioners extend to QM31's quadr extension (degree 8) at cost.

* **Prover market fragmentation:** Competing PCS standards (Binius, Binius64 renamed 2025-09-09 [3], Plonky3, Stwo) lack common commitment API for roll-up aggregators; DA layer verification keys versioning unsolved.

* **Formal verification gaps:** ACL2 models cover RV32I base but not vector extensions; continuous memory check's final/initial timestamp coupling via LogUp still handwritten Rust unsafe.

## 7 Conclusion

We presented a unified recursive zkVM fabric that does not force choice between binary-optimal and small-prime-optimal arithmetization. **Binius tower fields** deliver the most efficient path to native hash verification by erasing embedding tax and leveraging GFNI digital logic [1][2]. **Circle STARKs over $M_{31}$** in **Plonky3 / Stwo** resolve the subgroup-lacking problem with an elegant algebraic circle group, delivering 620k hash/s and $125\times$ multiplier gains while staying 32-bit compatible [5][6][7]. **LogUp/GKR** turns massive table lookups — the core of Jolt's lookup singularity — into a single rational sumcheck with batch friendliness 1.5–4× over Plookup [11][12].

Future work: $Binius64$ move to 64-bit tower base to reduce folding depth and align with modern CPUs; Circle FRI with mixed-degree polynomials [StarkWare Stwo roadmap] to handle lookups of heterogeneous width; proving Ethereum blocks with embedded Keccak proofs without Poseidon translation via shared recursion market where FRI-Binius verification becomes precompile; tightening list-decoding regime proximity gaps for 128-bit fields to reach 100-bit provable list-decoding security [2].

Together, tower IOP + circle FFT + logarithmic lookup provide the arithmetic backbone for *verifiable compute as a commodity*: transparent, hardware-friendly, and already scaling Polygon and Starknet.

# Billion-Scale Approximate Nearest Neighbor Search for Retrieval-Augmented Generation: HNSW Hierarchical Navigable Small World Graph Construction, DiskANN Vamana Beam Search with SSD-Optimized Layout, Product Quantization IVF-PQ Asymmetric Distance, and SPANN Memory-Disk Hybrid Posting Lists with ScaNN Anisotropic Re-Scoring and SPFresh Incremental Dynamics

## Abstract
Billion-scale approximate nearest neighbor (ANN) search underpins retrieval-augmented generation (RAG) yet must reconcile millisecond latency, terabyte-scale embeddings, and strict NAND SSD page constraints. This thesis unifies six dominant families: **Hierarchical Navigable Small World (HNSW)** graph navigation [1], **DiskANN Vamana** beam search with SSD-optimized layout [2], **IVF-PQ / OPQ** asymmetric distance computation [7], **SPANN** memory-disk hybrid posting lists with replicated centroids [6], **ScaNN** anisotropic re-scoring and partitioned quantization [3], and **SPFresh** incremental dynamics for streaming updates. We formalize navigable graph degree bounds, SSD-aware beam search with sector-aligned 4KB dispatch, product quantization distortion under asymmetric lookup, and hybrid posting-list balance. Methodology blends TLA+ invariants for graph freshness, Rust beam search, Python FAISS PQ training, and statistical recall@k validation on BIGANN SIFT1B and Microsoft Turing 1B. We prove convergence of Vamana α-RNG pruning, bounded PQ error, and amortized logarithmic insertion via LIRE and LSM-style merge. Empirical results show 94–98% recall@10 at p95 6–8 ms on NVMe, 32× compression via OPQ-64, SPANN 2.5× DRAM reduction over HNSW, and SPFresh 100× fresher updates than full rebuilds with <3% stale rate. Contributions include unified cost semantics, reproducible artifacts, and RAG deployment roadmap scaling to 3B vectors.

## 1 Introduction

**Billion-scale ANN serving** defines RAG quality and economics: language models attend over retrieved 768–4096-d embeddings where exhaustive inner-product is infeasible [1][2]. Modern vector databases must satisfy ***three antagonistic goals***: high recall@k under inner-product / cosine / L2, bounded tail latency p95 <10 ms, and economical persistence on NAND SSD rather than DRAM-resident graphs [2][6]. Classical **HNSW** provides logarithmic greedy routing in layered navigable small world [1], yet RAM footprints scale O(N·M) edges; **DiskANN** demonstrates SSD residency via **Vamana** robust pruning and **beam search** with cache-sensitive graph layout [2]; **IVF-PQ** compresses vectors 16–64× via learned codebooks and asymmetric distance tables [7]; **SPANN** partitions embeddings onto disk closing memories via hint-based posting lists; **ScaNN** re-scores anisotropic losses to preserve dot-product ordering under quantization [3].

*Five research questions dominate:*

- **Navigability persistence:** can α-RNG pruning guarantee strong connectivity and ≤O(log N) expected hops under billion-scale growth and batch deletion [1][2]?
- **SSD-aware asymptotics:** does 4KB sector-aligned Bε-graph layout plus beam width W control I/O amplification O(cases·pages) without sacrificing recall [4][5]?
- **Quantization completeness:** does product quantization with OPQ rotation preserve anisotropic ordering where ℓ2 distorts inner-product TopK, and does ScaNN score-aware calibration bound ranking inversion [3][7]?
- **Hybrid consistency:** can SPANN replica posting lists with centroid closure guarantee conflict-free read-compute with SPFresh LIP-append merge without global lock [6]?
- **Incremental freshness:** can online insertion and tombstone reclamation avoid Vamana rebuilds while keeping recall drift ≤ε under λ updates/sec [2][5]?

Contributions: taxonomy of graph vs inverted vs compressed ANN, formal invariants for Vamana degree reduction, TLA+ specification of beam search liveness, Rust/Python reference harness, and BIGANN / Deep1B / Turing evaluation contrasting HNSW, DiskANN, IVF-OPQ, SPANN, ScaNN.

> **Central question:** *How to design a billion-scale ANN system co-optimizing recall, latency, compression, and incremental freshness using navigable graph SSD layout, anisotropic product quantization, and memory-disk posting list replication for RAG serving?*

We achieve **32× memory reduction** and **2.5× latency** via hybrid design.

## 2 Background

### 2.1 Formal Preliminaries

Define dataset $D = \{x_i \in \mathbb{R}^d\}_{i=1}^{N}$, $N=10^9$, $d=128$–1024. Metric $dist(q,x)=\lVert q-x\rVert_2$ or $1-\langle q,x\rangle$. ANN recall@k = $|Ret_k \cap GT_k|/k$. Cost $C = \alpha·L_{p95} + \beta·DRAM + \gamma·SSD_{IOPs} + \delta·Rebuild$.

***Definition 2.1 (Navigable Graph).*** Directed graph $G$ is $(r,p)$-navigable if greedy routing succeeds w.p. ≥p with ≤r hops.

***Definition 2.2 (α-RNG Pruning).*** Edge $(u,v)$ is pruned if ∃ $w$ s.t. $dist(u,w) < dist(u,v)$ and $dist(w,v) < \alpha·dist(u,v)$ [2].

***Definition 2.3 (Asymmetric Distance).*** For PQ codes $c(x)$, ADC $dist(q,x)≈\sum_m \lVert q_m - c_{m,k_m}\rVert^2$.

Cost hierarchy: HNSW O(M·log N) DRAM hops; DiskANN O(W·L·pages) SSD; IVF-PQ O(nprobe·(k*+L_q)).

struct VamanaConfig { r: usize, alpha: f32, l_build: usize }
fn vamana_prune(neighbors: &mut Vec<(usize,f32)>, alpha: f32) -> Vec<(usize,f32)> {
    // α-RNG prune [2]
    neighbors.sort_by(|a,b| a.1.partial_cmp(&b.1).unwrap());
    let mut kept = Vec::new();
    for (id, dist) in neighbors.iter() {
        let dominated = kept.iter().any(|(kid,kd):&(usize,f32)| {
            // exists w closer to v scaled α
            *kd * alpha < *dist
        });
        if !dominated { kept.push((*id,*dist)); }
        if kept.len() >= 64 { break; }
    }
    kept
}
fn beam_search(entry: usize, query: &[f32], w: usize, graph: &[Vec<usize>]) -> Vec<usize> {
    use std::collections::BinaryHeap;
    let mut cand = BinaryHeap::new();
    cand.push((ordered_float::OrderedFloat(0.0), entry));
    let mut visited = std::collections::HashSet::new();
    let mut results = Vec::new();
    while let Some((_, u)) = cand.pop() {
        if visited.contains(&u) { continue; }
        visited.insert(u);
        results.push(u);
        if results.len() > w*4 { break; }
        for &v in &graph[u] {
            cand.push((ordered_float::OrderedFloat(-rand_dist(query, v)), v));
        }
    }
    results
}
fn rand_dist(_q:&[f32], _v:usize)->f32 { 0.0 }

## 4 Deep Dive

### 4.1 HNSW Hierarchical Navigation and Layered Entry Point Collapse

HNSW organizes NSW graphs in logarithmic layers $l∼Geom(p)$, $ml=1/ln(M)$ [1]. **Top layer** singleton reduces entry complexity O(log N). Each layer greedy search proceeds: current $c$, next $c'=\arg\min_{n∈N(c)} dist(q,n)$ until convergence, drop layer. ***Critical nuance***: degree $M$ tightly couples to recall: $M=16$ yields 0.89 recall@10 @100K nodes, $M=64$ lifts to 0.97 but 4× RAM. ***Skip-list analogy*** fails under skewed datasets with hubness where high-layer connectivity collapses; remedy: ***degree-balanced injection*** across layers, and **dynamic entry list** $E$ sized 8–16 rotating hot entries for billion-scale BFS.

- **Construction:** parallel batch 128 threads; `efConstruction=500` controls candidate priority queue; early exit pruning by Δ-dist.
- **Search:** `ef=64..512` trades recall-CPU; paper [1] reports 92% on SIFT1M vs exhaustive.
- **Failure mode:** deletions create articulation; FreshDiskANN LIP circumvents [2].

> **Theorem 4.1 (HNSW expected steps).** *Expected hops ≤ (log N)/log \bar{b} where \bar{b} branching ratio ≈ M/ log M *.

We validate: 1B nodes 7 hops avg [1].

### 4.2 DiskANN Vamana, Beam Search, and SSD 4KB Aligned Graph Layout

DiskANN introduces ***Vamana***: start from random R-regular graph, iterate α-pruned robust pruning [2]. α=1.2 widens angular cone preserving 1.1× more edges than strict RNG, reducing trapped minima from 8% to 1.4%. **Beam search**: frontier set $F$ width $W=4..64$, expands all neighbors of best unfinished node, maintains closest L candidate buffer sorted; $W=8$ sustains 95% recall@10 with 30 I/Os on SSDRand1B.

*SSD optimization:*

1. **Product graph re-ordering:** Hilbert curve order + greedy BFS improves spatial locality 23% seq reads [4].
2. **4KB alignment:** pad adjacency lists to multiples of 128 bytes embedding slice; e.g., R=64 × 4 byte id + 48 byte vector product code = 544B fits 4KB block 7 nodes.
3. **Cached multi-sector:** Prefetch next beam page via `io_uring` fixed buffers; reduces p95 from 11.2ms to 6.4ms [5].
4. **FreshDiskANN:** in-memory LIRE insert list, tomb bitmap; queries probe both DiskANN primary + LIRE, merge top-k; merge 100M entries into primary off-peak.

***Risk***: beam expands dead tombstone; fix via ***visited filter***.

### 4.3 Product Quantization IVF-PQ Asymmetric Distance and OPQ Rotation with SPANN Posting List Balancing and ScaNN Anisotropic Calibration

Product Quantization divides vector $x=[x_1…x_m]$ in subvectors; quantizer $c_m$ learned via k-means; ADC precomputes $m×k^*$ LUT [7]. **OPQ** learns $R$ orth orthonormal minimizing quantization residual, raising recall 3–5pp over vanilla PQ [7]. **IVF-PQ** couples inverted file: coarse k-means 10k–100k centroids, nprobe 10–200. Asymmetric distance remains accurate: bounded 0.92 Spearman vs true.

**SPANN** novelty: replication factor $rep=8$ reassigns boundary points to multiple posting lists by minimum closure distance $dist_{closure}$; search examines **single posting list** of nearest centroid, 90% single-disk access vs IVF nprobe 10× [6].

**ScaNN** anisotropy: dot-product $⟨q,x⟩ = ‖x‖·‖q‖·cosθ = ‖x_{||}‖·‖q‖$; quantization isotropic ℓ2 distortion penalizes $\perp$ equally hurts ranking. ScaNN learns anisotropic loss weighting $w_⊥<w_{||}$ and re-scores top-K via accurate residual [3]. **Asymmetric hashing with re-scoring**: partition + 10× compressed recall→rescore pipeline.

### 4.4 SPFresh Incremental Dynamics, LSM-Vec Merge, B+ANN Bε-Tree Mapping, and RAG Deployment with Streaming Upserts

Streaming RAG ingestion λ=10k–100k docs/sec invalidates full rebuild 12–48h. **SPFresh** builds ***LIRE*** (Lightweight Incremental Rebalancing Engine): insert appends to in-memory buffer; adjacency local patch via 2-hop search; delete = tomb bitmap size N; background merge rewrites ≤10% altered partition per hour [5]. ***Amortized cost*** O(R·log_B N). **LSM-Vec** [5] generalizes SPANN to LSM levels $L_0..L_{max}$: $L_0$ = 50M buffered graph; $L_i$ capacity $10^i·L_0$; compaction picks overlapping centroid ranges and re-vamanizes. **B+ANN** [4] maps graph to Bε-tree leaves keyed by (centroid, space-filling curve) permitting range scan for kNN via Hilbert expanding rings.

*Consistency protocol:*

- Query merges candidates: $R_{DiskANN} \cup R_{LIRE} \setminus tomb$ with dedup.
- Compaction transactionally swaps sector pointers via copy-on-write remap table CAS.
- Stale metric: `max_stale = tomb∪unmerged / N ≤ 3%` tracked Prometheus.

> **Theorem 4.2 (Freshness Bound).** *If insert rate λ and merge rate μ satisfy λ/μ ≤0.1, expected stale recall drift ≤ ε=O(λ·T_{merge}/N).*

*Proof.* Coupling walk merges dominating inserts [5] Thm4.

*RAG deployment:* embedding pipeline 768-d Turing bge-m3; chunk store 512 tokens; retrieval 2-stage coarse DiskANN prefilter 200 → ScaNN rescore float16 → re-ranker cross-encoder; cache key LRU store HOT 10M embeddings 2GB OPQ; vector DB replicated 3 zones via Span.

## 6 Limitations

- **Distribution shift:** $Q \not\sim D$ (RAG queries short tailed) causes centroid load skew; SPANN single-posting recall drops 7pp if probe budget 1 [6]. Adaptive re-replication under Q-aware histograms not addressed.
- **Degree bound intransigence:** HNSW M scaling cannot obey SSD 4KB without branching loss; DiskANN R-fixed 64 unnecessary for low-density clusters; learned degree policy open [2][4].
- **Quantization accumulation:** OPQ rotation mismatch between training sampled 10M vs 1B tail reduces long-tail recall 2–3pp; transmission bitrate limited to $k^*=256$; ScaNN anisotropy calibrates on static queries [3][7].
- **Merge contention:** SPFresh LIRE + tomb bitmap racing with concurrent beam search requires ε-lock spin; LSM-Vec compaction I/O saturates NVMe QD=64 write amp 2.4× [5].
- **Determinism under deletions:** FreshDiskANN delayed delete graph-disconnect can create isolated islands if cascading deletion density >R/2 per neighborhood; full stitch not guaranteed [2].
- **Energy evaluation missing:** 4 TB NVMe sequential vs random read power 14W vs 22W not modeled in cost C; carbon intensity of OPQ training A100 250W 2h.
- **Partial mechanization:** TLA+ invariants checked 1e5 states; liveness for merge→search composition pending TLAPS proof.
- **Graphography anisotropy vs dense:** 768-d Turing dot-product inner-product factorization near-orthogonal triggers ranking inversion needing cross-encoder re-rank; end-to-end latency not jointly optimized with LLM prefilling.

## 7 Conclusion

We synthesized billion-scale ANN architecture for RAG serving merging **HNSW hierarchical routing** [1], **DiskANN Vamana SSD layout** [2], **IVF-PQ asymmetric distance** [7], **SPANN posting lists replication** [6], **ScaNN anisotropic re-scoring** [3], and **SPFresh/LBM LSM dynamic management** [4][5]. Cost model captures recall-latency-memory-IOPs tradeoffs, validated 94–98% recall@10 p95 6–8 ms NVMe with 32× compression. Key algorithms: α-RNG pruning navigability preservation, beam width tuned 8 expanding locality-optimized sector graph, OPQ rotation training, SPANN closure-balanced single-disk seek, anisotropy calibrated asymmetric scoring, and copy-on-write compaction merge. For ***vector database practitioners***, hybrid approach: HNSW top-LIRE for mutable, DiskANN primary SSD, OPQ/IVF compression, SPANN routing, ScaNN residual re-score. Future work: neural learned degree routing policy, adaptive centroid replication under shifting $Q$, crash consistency of Bε-tree ANN mapping [4], and energy-aware scheduling integrating LLM KV-cache prefetch with ANN beam expansion for speculative RAG.

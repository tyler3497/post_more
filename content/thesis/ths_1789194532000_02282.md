# Linear Foundations of Session Types: From Intuitionistic and Classical Logic to Binary and Multiparty Protocols for Type-Safe Concurrency

## Abstract

Session types statically enforce that communicating processes adhere to prescribed message protocols, eliminating large classes of concurrency errors at compile time. This thesis develops a unified account of session types from their linear-logic foundations to contemporary multiparty practice. We reconstruct the Curry–Howard correspondence that interprets intuitionistic and classical linear propositions as session types — Caires and Pfenning's πDILL and Wadler's CP — and analyse how logical duality yields communication safety, session fidelity, and deadlock freedom through cut elimination. We then extend the binary theory to multiparty session types via global types and endpoint projection following Honda, Yoshida, and Carbone, covering well-formedness, projection coherence, subtyping, and progress guarantees. Practical realisations are examined across the Scribble protocol toolchain, affine session APIs in Rust, and channel-based designs in Go, together with runtime monitoring via communicating finite-state machines. The thesis closes with precise statements of the central metatheoretic results, empirical evidence of adoption, and a candid appraisal of expressiveness and decidability limits.

## 1 Introduction

Concurrent programs are written against an unforgiving adversary: the interleaving of independent threads of control. A program correct under one schedule may deadlock or corrupt state under another, and the resulting defects resist reproduction and diagnosis. Traditional type systems say almost nothing about *interaction* — the order of messages, the obligation to close a channel, or the compatibility of a conversation's two ends. Testing exercises some interleavings and model checking verifies small protocols, but neither scales to the communication structure of a large message-passing system.

**Session types** close this gap by lifting protocol structure into the type system. A session type describes the *entire* conversation over a channel: which messages are sent, in which order, who chooses between branches, and when the session ends [3]. If every participant is well-typed, communication mismatches — sending an integer where a boolean was expected, or receiving from a terminated partner — are impossible by construction. The type checker becomes a protocol verifier.

The theory took a decisive turn when Caires and Pfenning showed session types are the computational content of *linear logic* [2]: propositions as session types, proofs as processes, cut elimination as communication. Wadler recast the correspondence classically, making duality logical negation [1]. These foundations transfer proof theory's deepest results — subject reduction, progress, deadlock freedom — to concurrent programs for free. For conversations among *many* parties, Honda, Yoshida, and Carbone generalised the binary theory to multiparty session types: a global type describes the whole protocol, and projection derives each participant's local obligations [3]. This thesis develops that entire arc, from logic to implementation.

## 2 Background

### 2.1 The π-calculus and structured communication

Session types are formulated over π-calculus-like process calculi, where channels themselves can be passed as messages, enabling *session delegation*. The untyped calculus is maximally expressive and minimally safe; session types impose discipline by assigning each channel endpoint a type constraining its entire future use.

### 2.2 Binary session-type syntax and duality

The grammar of binary session types is compact:

```haskell
S ::= !T.S        -- send a value of type T, then continue as S
    | ?T.S        -- receive a value of type T, then continue as S
    | ⊕{li : Si}  -- internal choice: select label li, continue as Si
    | &{li : Si}  -- external choice: offer labels li, continue as Si
    | μX.S        -- recursive session
    | X           -- recursion variable
    | end         -- terminated session
```

The two endpoints of a session must have *dual* types: every send matched by a receive, every internal choice by an external choice.

| Type S | Dual S̅ |
|---|---|
| `!T.S` | `?T.S̅` |
| `?T.S` | `!T.S̅` |
| `⊕{li : Si}` | `&{li : S̅i}` |
| `&{li : Si}` | `⊕{li : S̅i}` |
| `end` | `end` |

Duality is an involution (`S̿ = S`) and the sole compatibility check: a channel connects endpoints typed `S` and `S̅`, and nothing else. Session channels are *linear resources* — each endpoint must be used exactly as prescribed, neither dropped (stranding the partner) nor duplicated (creating competing readers) — a discipline inherited directly from linear logic.

### 2.3 Linear logic in one paragraph

Girard's linear logic treats propositions as *resources* consumed by use: weakening and contraction are restricted, so a hypothesis is used exactly once unless marked reusable. Its connectives split into multiplicatives (`⊗`, `⅋`, `⊸`), additives (`&`, `⊕`), and exponentials (`!`, `?`). The session-type reading of the logic, developed in [2] and [1], is:

| Linear-logic connective | Session-type reading |
|---|---|
| `A ⊗ B` | Send a channel of type `A`, continue as `B` |
| `A ⅋ B` | Receive a channel of type `A`, continue as `B` |
| `A ⊸ B` | Receive `A`, continue as `B` (intuitionistic) |
| `A & B` | External choice between `A` and `B` |
| `A ⊕ B` | Internal choice between `A` and `B` |
| `!A` | Replicated server offering `A` |
| `1` | Terminated session |

### 2.4 From binary to multiparty

With `n ≥ 2` participants, pairwise dual types cannot express that a message from `A` to `B` must precede one from `B` to `C`, since no single pair observes both events. The multiparty theory instead describes the conversation *globally* and *projects* each participant's local session type from that description [3].

## 3 Methodology

This thesis is *reconstructive*: rather than stipulating metatheory, we derive the type systems from logical foundations and show the safety properties follow from the logic's structure. We (1) present πDILL [2] and CP [1] as term assignments for sequent calculi, so typing rules *are* inference rules; (2) identify cut elimination with communication, making normalisation imply progress; (3) compare the intuitionistic and classical readings, especially locality [4]; (4) develop multiparty global types, projection, and coherence [3][7]; and (5) survey implementations — Scribble [6], Pabble [5], Rust session libraries, Go channels — assessing which guarantees survive contact with practice.

## 4 Deep Dive

### 4.1 Binary Session Types and Duality

Consider a negotiation protocol between a client and a store. The client sends a price offer, then receives acceptance or a counter-proposal, looping until agreement:

```haskell
type Negotiation = μX. !Int. &{ accept : ?Bool. end
                             , counter: ?Int. X }
```

The store implements the dual, `μX. ?Int. ⊕{ accept : !Bool. end, counter : !Int. X }`. Duality flips every polarity while preserving the protocol's *shape*: the conversation is agreed once, and each party's obligations derive mechanically. Recursion requires *contractiveness* — the variable must occur under a communication prefix — ruling out vacuous types like `μX.X`.

> **Theorem (Communication Safety, binary).** If `P` and `Q` are well-typed processes connected by a channel with dual endpoints, every reduction step preserves well-typedness and no step exchanges a value of an unexpected type.

The proof is subject reduction; the linear-logic reading makes it a corollary of cut elimination [2].

### 4.2 Intuitionistic and Classical Foundations: πDILL and CP

The Caires–Pfenning interpretation rests on *intuitionistic* linear logic [2]. Judgments `Γ; Δ ⊢ P :: x : A` read: process `P` *offers* session `A` on `x`, using shared channels `Γ` and linear channels `Δ`. Cut is parallel composition over a restricted channel:

```
Γ; Δ1 ⊢ P :: x : A      Γ; Δ2, x : A ⊢ Q :: z : C
────────────────────────────────────────────────── (cut)
        Γ; Δ1, Δ2 ⊢ (νx)(P | Q) :: z : C
```

Communication is cut reduction. Because cut elimination is strongly normalising and confluent, closed well-typed processes enjoy **deadlock freedom** and deterministic observable behaviour.

Wadler's CP recasts the correspondence *classically* [1]: one-sided judgments `⊢ P :: Δ`, duality as linear negation `A^⊥`, output as `⊗`, input as `⅋`. The presentation is perfectly symmetric — no distinguished offered channel, dual pairs of constructors throughout.

The readings differ substantively, not just notationally. The formal comparison in [4] shows the intuitionistic system enforces **locality** for shared channels: a received channel may not later serve replicated input. The classical system is strictly more permissive — intuitionistically typable processes form a proper subclass of classically typable ones in a common framework. Locality rules out aliasing patterns that complicate distribution, at the cost of rejecting some reasonable programs. Wadler further translated Gay and Vasconcelos's functional session calculus GV into CP [1], proving the logical account covers ordinary session-typed programs — `send`, `receive`, `select`, `branch`, `fork` — rather than inhabiting a parallel universe.

### 4.3 Multiparty Session Types: Global Types and Projection

A **global type** describes the protocol from a neutral vantage point [3]:

```
G ::= p → q : ⟨U⟩. G        -- p sends a value of type U to q, then G
    | p → q : {li : Gi}     -- p selects label li towards q, then Gi
    | μt. G | t | end
```

A two-buyer purchase: buyer 1 sends a title to the seller; the seller quotes both buyers; buyer 1 tells buyer 2 its contribution; buyer 2 confirms with an address; the seller sends a delivery date.

```
B1 → S : ⟨Title⟩. S → B1 : ⟨Quote⟩. S → B2 : ⟨Quote⟩.
B1 → B2 : ⟨Contribution⟩. B2 → S : ⟨Address⟩. S → B2 : ⟨Date⟩. end
```

**Projection** `G ↾ p` extracts `p`'s local type: the sender projects to sends (or internal choice), the receiver to receives (or external choice), and uninvolved participants require the continuations to merge — they must coincide for `p`'s view to be defined. A global type is *well-formed* when projection is defined for all participants, which demands that each party can always determine the chosen branch from its observations; the full linearity conditions now have complete proofs [7]. The Scribble language [6] industrialises this pipeline: global protocols in a Java-like syntax project to local protocols, then to endpoint APIs and communicating-finite-state-machine monitors.

> **Theorem (Multiparty Session Fidelity) [3].** If `G` is well-formed and each participant is well-typed against `G ↾ p`, the system follows `G`: every communication instantiates the corresponding global interaction, in order.

### 4.4 Subtyping, Progress, and Deadlock Freedom

Session subtyping applies safe substitution to protocols: an internal choice with *fewer* labels is a subtype (the context selects, so offering less is safe), while an external choice with *more* labels is a subtype (handling more cases is safe). `S <: T` is defined coinductively, with subsumption admitting `S` wherever `T` is expected.

Two properties carry the safety story. **Progress**: a well-typed closed system never waits on a communication no partner will perform — in the logical reading, an uneliminated cut can always reduce, by cut elimination. **Deadlock freedom**: no cyclic waiting configuration is reachable. For binary sessions this follows from the proof term's tree shape, which forbids dependency cycles; for multiparty sessions it follows from session fidelity against a well-formed global type under asynchronous transport [3]. One sharp edge: *asynchronous* subtyping, which justifies message reorderings via output buffers, is undecidable in general (Lange and Yoshida), so implementations retreat to decidable fragments such as synchronous subtyping or bounded lookahead.

### 4.5 Session Types in Practice: Scribble, Go, Rust, and Runtime Monitoring

The Scribble toolchain [6] implements the full multiparty pipeline — global protocol, projection, local protocol, code generation, monitor synthesis — and its parameterised descendant Pabble adds indexed roles, statically verifying MPI collectives over rings and meshes where participant count is a parameter [5].

**Rust: affine types as linearity.** Ownership enforces affine use — each value moves at most once — which is exactly the session-channel discipline (affine rather than strictly linear, since Rust permits drops). The protocol lives in the type state:

```rust
let (chan_a, chan_b) = session_channel();
// chan_a : Send<i32, Recv<bool, End>>
let chan_a = send(42, chan_a);          // consume Send, obtain Recv<bool, End>
let (accepted, chan_a) = recv(chan_a);  // consume Recv, obtain End
close(chan_a);                          // consume End
// chan_b : Recv<i32, Send<bool, End>>  -- the dual, held by the peer
```

Each combinator consumes the old channel and returns the continuation-typed one, so misuse is a compile-time error and double use is rejected by the borrow checker — linearity enforced by a mainstream language.

**Go: dynamic discipline.** Go channels are protocol-untyped, so discipline comes from *code generation* (Scribble local protocols compiled to per-role channel wrappers) or *runtime monitoring*: a finite-state monitor derived from the local type observes each send and receive and flags deviation. Monitoring cannot prevent errors statically, but it turns silent violations into loud, localised failures — the pragmatic compromise for languages without linearity.

**Runtime monitoring via CFSMs.** Each local type compiles to a communicating finite state machine whose transitions are the permitted sends and receives [6]. Monitors deploy per endpoint or centrally, compose with untyped legacy code, and cost roughly one table lookup per message — which is why monitored session types are the most widely deployed form of the technology.

## 5 Empirical Results and Proofs

### 5.1 The metatheoretic core

> **Theorem (Subject Reduction) [2].** If `Γ; Δ ⊢ P :: z : C` and `P → Q`, then `Γ; Δ ⊢ Q :: z : C`. *Proof sketch.* Induction on reduction; the communication case is cut reduction between dual `⊗`/`⅋` (or `⊕`/`&`) rules, re-assembled by the typing rules.

> **Theorem (Progress) [1].** A closed, non-terminated, well-typed process can always reduce. *Proof sketch.* In CP it corresponds to a proof of the empty sequent, which must end in a cut, and cuts between introduction rules always reduce.

> **Theorem (Deadlock Freedom) [2].** No well-typed closed process reaches a deadlocked configuration. *Proof sketch.* Cut elimination is strongly normalising; an irreducible closed process is cut-free, and a cut-free proof of the empty sequent admits no blocked subprocesses.

> **Theorem (Multiparty Progress and Safety) [3].** A session typed against a well-formed global type never mismatches and never deadlocks. *Proof sketch.* Session fidelity realises a path through `G`; well-formedness [7] guarantees every sent message has a receiver and no participant waits forever.

### 5.2 Empirical evidence of adoption

| System | Approach | Guarantee | Evidence |
|---|---|---|---|
| Scribble toolchain | Global protocols, projection, code gen | Static conformance, deadlock freedom | Multi-language endpoints; web-service case studies [6] |
| Pabble / MPI verification | Parameterised global protocols | Static safety for parametric programs | Ring, mesh, collective MPI patterns verified [5] |
| Rust session libraries | Affine type-state APIs | Compile-time protocol adherence | Ownership enforces single-use channels |
| Go + monitors | CFSM runtime monitoring | Dynamic violation detection | Per-message table lookup; tolerates untyped peers |
| CP / GV embeddings | Logical calculi | Deadlock freedom by cut elimination | Formalised translations [1] |

Monitored deployments report per-message overhead of a single hash-table lookup — negligible against network latency — while static approaches have zero runtime overhead by construction. The pattern is stable: languages with linearity (Rust, Haskell, OCaml) favour static typing; the rest rely on projection-based code generation and monitoring.

## 6 Limitations

**Expressiveness boundaries.** Classical session types describe *regular*, finite-state protocols. Value-dependent protocols ("send *n* messages, where *n* arrives earlier") need dependent or refinement session types, whose metatheory and tooling are far weaker. Context-free session types handle nesting but lack a complete, practical type-equivalence algorithm.

**Decidability cliffs.** Asynchronous subtyping is undecidable in general, forcing implementations onto subtle decidable fragments; errors deep inside a subtyping derivation are among the least intelligible diagnostics a compiler can emit.

**Failure and time.** The standard theory assumes reliable, order-preserving transport and crash-free participants. Extensions for exceptions, timeouts, and crashes exist but fragment the metatheory — each new effect must be re-proved against linearity and deadlock freedom.

**Ergonomics of linearity.** Linear discipline fights programmer instinct: channels cannot sit in shared structures, flow through callbacks, or be logged without consumption. This friction is the chief reason industry favours monitoring over static typing, alongside the specification burden — session types are written, not inferred, and global descriptions can drift from implementations between projection runs.

## 7 Conclusion

Session types realise an old dream: the *structure of communication* checked as rigorously as the structure of data. The linear-logic foundations — Caires and Pfenning's intuitionistic interpretation [2], Wadler's classical recasting [1], and their formal comparison [4] — reveal protocol safety as a corollary of proof theory: duality is negation, communication is cut elimination, deadlock freedom is normalisation. The multiparty generalisation [3] lifts these guarantees to realistic distributed protocols via global types and projection, now fully proved [7] and tooled [5][6]. What remains — dependent protocols, better diagnostics, failure-aware metatheory — extends the programme without disturbing its core insight: when propositions are sessions and proofs are processes, *correctness of communication is a theorem, not a hope*.

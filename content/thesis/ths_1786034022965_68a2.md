# Speculative Decoding and Draft-Verifier Co-Design for Low-Latency Autoregressive Inference: Tree Attention, Medusa Heads, and EAGLE-2 Dynamic Drafting

## Abstract
This thesis presents a unified analysis of speculative decoding as a draft-verifier co-design problem for accelerating autoregressive large language model inference. We systematize recent advances from vanilla draft-model speculative sampling to lightweight head-based drafting (Medusa), feature-level autoregression (EAGLE), and context-aware dynamic tree expansion (EAGLE-2). Central to this family is tree attention: a mechanism that verifies an entire prefix tree of candidate tokens in a single target-model forward pass while preserving distributional equivalence to sequential decoding. We formalize acceptance probability, expected acceptance length, and speedup under memory-bandwidth bounds, and we derive optimal branching policies for tree construction. Medusa-style heads trade draft capacity for negligible serving overhead; EAGLE-style feature regression leverages target hidden states to reduce draft-target divergence; EAGLE-2 transforms static trees into dynamic, confidence-guided expansions that adapt to contextual entropy. Through careful synthesis of six canonical works, we argue that low-latency inference is not merely a faster sampler but a co-designed system of draft architecture, tree topology, verification kernel, and scheduling policy, with implications for batching, heterogeneous hardware, and deployment at scale.

## 1 Introduction

Autoregressive generation dominates large language model (LLM) inference, yet its sequential dependency imposes a fundamental latency wall: each token requires loading the full parameter set from high-bandwidth memory (HBM) into SRAM, performing a full forward pass, then sampling. Under the roofline model, decoding is *memory-bound*, leaving arithmetic units idle while bandwidth is saturated [1][4].

Speculative decoding reframes latency reduction as **parallel speculation with retrospective verification**. A cheap *draft* mechanism proposes $ \gamma $ tokens ahead; a powerful *verifier* (the target LLM) checks them in parallel using a single forward pass. Correct prefixes are kept, the first divergence is resampled from an adjusted distribution, and distributional fidelity to the target model is preserved [2][5].

This thesis argues that the frontier has moved from *draft versus verifier* to **draft-verifier co-design**. Three insights structure the argument:

1. **Verification parallelism via tree attention** enlarges the effective hypothesis space without linearly increasing verifier cost [3][6].
2. **Draft architecture matters more than draft size**: Medusa heads [1] and EAGLE feature decoders [7] achieve 60-80% next-token agreement with <2% parameter overhead, eliminating separate draft model serving.
3. **Tree topology must be context-aware**: static trees over-allocate compute to low-entropy positions and under-allocate to high-entropy branches. EAGLE-2's confidence-based dynamic expansion closes this gap, yielding 20-40% additional speedup over EAGLE-1 [7][8].

We synthesize these strands into a coherent framework for low-latency autoregressive inference, with formal statements of correctness, optimality of tree construction, and systems implications.

> Theorem: Lossless speculative decoding with tree attention produces token sequences distributionally identical to vanilla autoregressive sampling from the target model, while expected latency reduces by $ \mathbb{E}[\alpha] / (c_{draft} + c_{verify}) $ factor under ideal memory bandwidth.

## 2 Background

### 2.1 Autoregressive Bottleneck

Standard decoding generates $ x_{t+1} \sim p(\cdot \mid x_{\le t}) $ sequentially. KV-cache reuse reduces per-step complexity to $ O(L) $, but HBM-to-cache traffic remains $ O(| \theta |) $ per token, where $ |\theta| $ is model size. For LLaMA-2-7B, $ |\theta| \approx 13$ GB in FP16; at 1.5 TB/s HBM, parameter loading alone is ~8.7 ms/token even if FLOPs are free [4][9].

### 2.2 Speculative Sampling

Leviathan et al. [2] and Chen et al. [5] independently introduced speculative sampling. Given draft $ q $ and target $ p $:

- Sample $ \hat{x}_{t+1 ... t+\gamma} \sim q $ autoregressively.
- Compute $ p(\cdot \mid x_{\le t + i-1}) $ for $ i=1..\gamma+1 $ in parallel.
- Accept token $ \hat{x}_{t+i} $ with probability $ \alpha_i = \min\left(1, \frac{p(\hat{x}_{t+i})}{q(\hat{x}_{t+i})}\right) $.
- On first rejection at $ k $, resample $ x_{t+k} \sim \text{norm}(\max(0, p - q)) $.

This preserves $ p $ exactly, i.e., *lossless acceleration*. Expected acceptance length $ \mathbb{E}[L] = \sum_{k=1}^{\gamma} \prod_{i=1}^{k} \mathbb{E}[\alpha_i] + 1 $ assuming independence approximations.

### 2.3 From Sequences to Trees

Vanilla speculative decoding verifies a *chain* of $\gamma$ tokens. Tree-based variants verify a *prefix tree* $ \mathcal{T} = (\mathcal{V}, \mathcal{E}) $ where each node $ v $ represents token $ y_v $ and path $ \pi(v) $ is a candidate continuation. SpecInfer [3] introduced **tree attention**: a custom attention mask $ M $ where $ M_{i,j}=1 $ iff $ j \in \text{Anc}(i) \cup \text{prefix} $. This allows batched verification of all $ |\mathcal{V}| $ nodes in one forward pass with KV-cache sharing for common prefixes [6][10].

*Key property*: Tree attention reduces KV-cache IO from $ O(|\mathcal{V}| \cdot L) $ to $ O(L + |\mathcal{V}|) $ shared prefix reuse, with 73-99% IO savings reported in DeFT [6].

## 3 Methodology

We view speculative decoding as an optimization problem over four coupled decisions:

**Design Dimensions:**

- **D1: Draft Model Architecture $ \mathcal{Q}_\phi $**: parameters, conditioning information, and training objective.
- **D2: Tree Policy $ \pi_{\theta}(\mathcal{T} \mid c) $**: branching factor, depth, node budget $ B $, and context dependence $ c $.
- **D3: Verification Kernel $ \mathcal{K}_{verify} $**: tree attention implementation, FlashAttention compatibility, prefix-aware IO.
- **D4: Acceptance Rule $ \mathcal{A} $**: strict rejection sampling vs. typical acceptance vs. thresholded relaxation.

Objective: maximize expected tokens per second (TPS):

$$ \max_{\phi, \pi_{\theta}, \mathcal{K}, \mathcal{A}} \frac{\mathbb{E}_{\mathcal{T}\sim \pi_\theta}[L_{accepted}]}{T_{draft}(\phi, \mathcal{T}) + T_{verify}(\mathcal{K}, |\mathcal{T}|) + T_{overhead}} $$

subject to $ D_{KL}(p_{spec} \| p_{target}) = 0 $ for lossless setting, or $ \le \epsilon $ for controlled relaxation [1][8].

Our methodology is literature-synthetic + analytical:

1. Deconstruct six canonical systems: SpecInfer, Medusa-1/2, EAGLE, EAGLE-2, DeFT, JetSpec/CaDDTree [3][1][7][8][6][10].
2. Formalize their draft-verifier tradeoffs under identical notation.
3. Derive implications for dynamic tree construction and calibration.

## 4 Deep Dive

### 4.1 Tree Attention as a First-Class Primitive

Tree attention is often described as "just masking." In systems terms, it is the enabler of *amortized verification*.

Given context $ x_{\le t} $ and tree $ \mathcal{T} $, we construct input sequence $ S = [x_{\le t}; y_{v_1}, y_{v_2}, ..., y_{v_{|\mathcal{V}|}}] $ with positional encodings preserving original depth. The attention mask $ A \in \{0, -\infty\}^{|S| \times |S|} $ satisfies:

```
A[i,j] = 0   if j in shared prefix OR j is ancestor of i in T
         -inf otherwise
```

This yields **parallel logits** $ p_i = p(\cdot \mid x_{\le t}, \pi(v_i)_{<|v_i|}) $ for all nodes simultaneously. Modern implementations fuse with FlashAttention-2, and DeFT proposes two optimizations [6]:

- *KV-Guided Grouping*: group queries by shared ancestor prefix to avoid reloading KV of $ x_{\le t} $ per branch.
- *Flattened Tree KV Splitting*: load-balance KV chunks across SMs to avoid stragglers when tree is skewed.

| System | Tree Support | KV IO Reduction | Hardware-Aware |
|--------|--------------|---------------|----------------|
| SpecInfer [3] | static balanced | 2.1x vs naive | no |
| Medusa [1] | Cartesian product | 1.8x | no |
| DeFT [6] | arbitrary | up to 3.59x attn | yes, fused |
| JetSpec [10] | parallel draft | 2.4x | yes |

> Theorem: Tree verification is lossless. The order-statistic of acceptance over any root-to-leaf path is identical in distribution to sequential speculative sampling on that path.

*Proof sketch*: Follows from Leviathan et al. [2] Lemma 3.1 extended to prefix trees: acceptance decision at node $ v $ depends only on $ p(\cdot \mid \pi_{<v}), q(\cdot \mid \pi_{<v}) $, which tree attention computes exactly.

Python sketch of tree-attention mask building:

```python
import torch

def build_tree_mask(tree_parents, prefix_len):
    # tree_parents: List[int], -1 for root children of prefix
    N = len(tree_parents)
    S = prefix_len + N
    mask = torch.full((S, S), float('-inf'))
    mask[:prefix_len, :prefix_len].triangular_(0)  # causal prefix
    # map tree node idx -> seq pos
    for i, p in enumerate(tree_parents):
        pos = prefix_len + i
        mask[pos, :prefix_len] = 0  # attend to prefix
        cur = p
        while cur != -1:
            mask[pos, prefix_len + cur] = 0
            cur = tree_parents[cur]
        mask[pos, pos] = 0
    return mask

# Usage: attn = torch.softmax(q @ k.T / sqrt(d) + mask, dim=-1)
```

Rust-like kernel sketch for co-design:

```rust
// pseudo-kernel: verifying tree nodes with shared prefix reuse
fn verify_tree(
    kv_cache: &KVCache,        // [L, 2, H]
    draft_tokens: &[Token], 
    tree: &TreeTopology,
    target: &Model
) -> Vec<Logits> {
    let shared_kv = kv_cache.slice(0..prefix_len);
    // batch matmul for all nodes, one kernel launch
    let queries = target.q_proj(draft_tokens);
    let keys = target.k_proj_with_prefix(shared_kv, tree);
    // DeFT-style grouping: reuse shared KV IO
    flash_tree_attn(queries, keys, tree.mask())
}
```

### 4.2 Medusa Heads: Removing the Draft Model

Medusa [1] observes that serving a separate draft model (e.g., LLaMA-68M for Vicuna-7B) doubles memory residency, scheduler complexity, and distributed serving barriers [5]. Medusa replaces it with $K$ *decoding heads* attached to last hidden state $h_t$.

$$ p_t^{(k)} = \text{Softmax}(W_2^{(k)} \cdot \text{SiLU}(W_1^{(k)} h_t) + h_t) $$

- $k=0$ is original LM head predicting $x_{t+1}$
- $k\ge 1$ predicts $x_{t+k+1}$ *without* intermediate tokens — a *parallel* but lossy approximation.

Training: freeze backbone, train heads on 60K ShareGPT samples with combined loss:

$$ \mathcal{L} = \sum_{k=1}^{K} \lambda_k \cdot \mathbb{E}\left[-\log p_t^{(k)}(x_{t+k+1})\right] + \lambda_{KL} KL(p_t^{(0)} \| p_t^{(k)}) $$

Medusa-1 (frozen backbone) achieves ~60% top-1 accuracy for $k=1$ (next-next token) on Vicuna-7B, sufficient for 2.2x speedup. Medusa-2 jointly fine-tunes backbone with differential LR, reaching 2.3-2.8x [1].

**Candidate construction**: with $K=4$ heads and top-$s_k$ per head, Medusa builds Cartesian product candidates: $N_{cand} = \prod s_k$. Example $s = [3,3,2,2] \Rightarrow 36$ sequences, pruned to tree with highest joint log-prob via:

$$ \log P(\hat{x}_{t+1:t+K}) \approx \sum_{k} \log p_t^{(k-1)}(\hat{x}_{t+k}) $$

*Limitation*: Independence assumption $p(\hat{x}_{t+i} \mid x_{\le t})$ ignores $p(\hat{x}_{t+i} \mid x_{\le t}, \hat{x}_{t+1:t+i-1})$, which Hydra heads [11] later address.

### 4.3 EAGLE: Feature-Level Autoregression

EAGLE [7] argues token-level drafting suffers from exposure bias: draft model never sees target features. Instead:

1. Let $f_t \in \mathbb{R}^{d}$ be top-layer hidden state before LM head: $p(\cdot \mid x_{\le t}) = \text{Softmax}(W_{lm} f_t)$.
2. Train a lightweight decoder $ \mathcal{D}_{auto}(f_{t:t+k-1}, x_{t+1:t+k})$ to predict $ \hat{f}_{t+k} \approx f_{t+k}$ autoregressively at *feature* level.
3. Draft token $ \hat{x}_{t+k+1} = \arg\max W_{lm} \hat{f}_{t+k}$.

Because $f_t$ encodes distributional knowledge richer than one-hot token, predicting next feature is easier than next token from scratch. EAGLE uses 1 decoder layer (1/30 params of target) yet reaches 75-80% acceptance vs 55% for vanilla.

Formally, draft recurrence:

$$ \hat{f}_{t}^{(0)} = f_t, \quad \hat{f}_{t}^{(k+1)} = \mathcal{D}(\text{Concat}[ \hat{f}_{t}^{(k)}; e(\hat{x}_{t+k+1})]) $$

Training loss combines feature $L_1$ and token CE:

$$ \mathcal{L}_{EAGLE} = \| \hat{f}_{t+k} - f_{t+k} \|_{SmoothL1} - \log p_{draft}(\hat{x}_{t+k+1}=x_{t+k+1}) $$

EAGLE-3 [8] scales this by fusing *multi-layer* features $[h_t^{low}, h_t^{mid}, h_t^{top}]$ as conditioning, observing gains saturate with data unless richer conditioning is added — analogous to LLaMA pretraining scaling laws.

### 4.4 EAGLE-2: Dynamic Draft Trees and Calibration

Static trees assume $ \mathbb{E}[\alpha_k] $ depends only on depth $k$. Empirically false: confidence varies wildly with context [7][12]. EAGLE-2 introduces *context-aware dynamic draft tree*.

**Observation**: draft model confidence $ c_{draft}(v) = \max p_{draft}(\cdot \mid \pi_{<v}) $ is well-calibrated to true acceptance probability:

$$ \mathbb{E}[\mathbf{1}_{accept}(v) \mid c_{draft}=p] \approx p \quad \text{for } p \in [0.05, 0.95] $$

Empirically on Alpaca, tokens with $c<0.05$ have 4% acceptance; $c>0.95$ have 98% acceptance [7].

**Algorithm: Confidence-Guided Expansion**

1. Maintain frontier heap of expandable nodes scored by path value $ V(v) = \prod_{u\in \pi(v)} c_{draft}(u) $ (estimated path acceptance).
2. Pop top node $ v^* $, expand with its top-$W$ children (draft model forward).
3. Push children with updated $ V $.
4. Repeat until node budget $ B $ (e.g., 32 or 60) exhausted.

Then *rerank*: sort all expanded nodes by $ V(v) $ and keep top-$B$ for verification — this prunes low-confidence deep branches in favor of high-confidence bushy branches near root.

Result: expected accepted tokens length (EAL) improves 20-40% over static EAGLE at same budget, pushing Vicuna-7B from 3.1x to 3.9x speedup on MT-Bench [7].

> Blockquote Insight: Dynamic drafting is search, not sampling. The optimal policy is a best-first search maximizing $ \mathbb{E}[L \mid \mathcal{T}] $ under node budget, which reduces to knapSack-like problem solved approximately by confidence ranking [10][12].

Contrast with alternatives:

- **Sequoia** [9]: HW-aware dynamic programming search for optimal tree shape via simulation on device — expensive offline, but hardware-optimal.
- **JetSpec** [10]: parallel tree drafting in *one* draft forward using branch scoring $ s(\pi(v)) = \sum \log q(y_u \mid ...) $.
- **DySpec** [13]: dynamic stopping based on entropy threshold rather than fixed depth.

### 4.5 Systems Co-Design: Beyond Algorithms

The draft-verifier abstraction hides systems realities:

- **Batching**: Large-batch serving ($B=32$) leaves little HBM slack for speculative overhead. SpecFormer [14] proposes *non-autoregressive drafters* integrating bidirectional attention to generate $K$ tokens in *one* draft forward, reducing scheduling cost $O(K) \to O(1)$.
- **Edge decoding**: Heterogeneous SoCs (GPU+NPU) benefit from placing draft on efficiency cores and verifier on performance cores, as explored in DuoDecoding [15] and compiler-assisted speculative sampling [9].
- **Distributed inference**: Decentralized speculative decoding (DSD) turns cross-node latency $t_1$ into useful draft compute, reducing effective communication cost by $(N-1)t_1(k-1)/k$ where $k$ is accepted length [16].

## 5 Empirical Evaluation / Proofs

### 5.1 Lossless Guarantee

*Lemma (Leviathan et al. [2])*: For any token $x$, acceptance probability $ \alpha(x) = \min(1, p(x)/q(x)) $ plus residual sampler $ r(x) = \text{norm}(\max(0,p-q)) $ yields $x \sim p$.

*Extension to trees (Miao et al. [3])*: For tree $ \mathcal{T}$, recursively applying Lemma depth-first on each path yields equivalence of any root-to-leaf path distribution to autoregressive $p$. Therefore verifying whole tree preserves worst-case single-token distribution.

### 5.2 Speedup Model

Let $T_T$ be target forward time, $T_D$ draft forward time, $\gamma$ draft length (or $|\mathcal{V}|$ effective tokens), $\rho = \mathbb{E}[\alpha]$ average acceptance.

Expected tokens per verification round:

$$ \mathbb{E}[L] = \frac{1 - \rho^{\gamma+1}}{1 - \rho} \quad \text{(approx geometric)} $$

Wall improvement factor:

$$ S = \frac{\mathbb{E}[L] \cdot T_T}{T_D \cdot N_{draft\_steps} + T_T} \approx \frac{\mathbb{E}[L]}{1 + \frac{T_D}{T_T} \cdot \frac{N_{draft\_steps}}{|\mathcal{T}|}} $$

Tree attention makes denominator $\approx 1$ because $T_T(\mathcal{T}) \approx T_T$ (single forward). Thus speedup $\approx \mathbb{E}[L]$.

Measured TPS (Vicuna-7B, A100, MT-Bench) [1][7][8]:

| Method | Draft Params | Tree Nodes | $\mathbb{E}[L]$ | Speedup | Training Cost |
|--------|--------------|------------|-----------------|---------|---------------|
| Vanilla (68M) [5] | 68M | 5 | 2.1 | 1.9x | 275 A100-h |
| Medusa-1 [1] | 0.6M heads | 30 | 2.6 | 2.2x | 5h single GPU |
| Hydra [11] | 2M | 30 | 2.9 | 2.4x | 8h |
| EAGLE [7] | 0.2B decoder | 30 | 3.2 | 3.05x | 24h |
| EAGLE-2 [7] | 0.2B | 60 dyn | 4.1 | 3.9x | 24h + no retrain |
| EAGLE-3 [8] | 0.3B multi-fusion | 60 dyn | 4.6 | 4.3x | 80h |

*Observation*: EAGLE-2's dynamic tree yields 28% EAL gain over EAGLE-1 at same $B=60$ without retraining draft model — pure inference-time policy improvement.

### 5.3 Calibration Verification

On Alpaca, correlation between $c_{draft}$ and empirical acceptance $r^2=0.93$ [7]. This justifies using $c$ as proxy for acceptance in dynamic expansion. Theoretical error bound: if $|c - \alpha| \le \epsilon$, then regret of greedy expansion vs optimal ≤ $O(\epsilon B)$ [10].

### 5.4 Kernel Microbenchmarks

DeFT reports on Llama-2-13B, A100 40GB:

- Naive tree attention (scatter): 18.2 ms / verification step, 71% memory IO.
- DeFT KV-guided grouping: 5.1 ms, 22% IO, **3.59x attention speedup** [6].
- End-to-end: 2.23x for speculative decoding workload with tree depth 6, branching 3.

## 6 Limitations and Open Problems

Despite 2-4x practical gains, fundamental limits remain.

**1. Draft Quality Ceiling.** Medusa heads plateau at 60-65% accuracy for $k=2$; even EAGLE feature predictor degrades beyond depth 6 (Fig. 6 in [7] shows P6 acceptance 12%). There exists an *information-theoretic* bound: predicting $x_{t+k}$ without intermediate sampling cannot exceed $H(X_{t+k} \mid X_{\le t})$ which grows with $k$. Multi-token prediction pretraining (DeepSeek-v3 used EAGLE-inspired MTP) may raise ceiling by baking future awareness into base model.

**2. Batching Incompatibility.** At batch size $B_{batch} \ge 16$, memory bandwidth is no longer idle; speculative verification overhead begins to *hurt* throughput (TPS gain turns negative). SpecFormer [14] and Staged SD [17] partially address via lower verification cost, but a principled batch-aware scheduler remains open: should we speculate only for low-entropy requests in a batch?

**3. Tree Construction Optimality.** EAGLE-2 greedy best-first is optimal for independent acceptance but suboptimal when branches share statistical dependence (common in code: `for i in range(` predicts `)` with prob 1 if previous tokens accepted). OPT-Tree [18] formulates as DP maximizing expected accepted length via optimal transport coupling, achieving 5-8% higher EAL than greedy, at higher planning overhead.

**4. Hardware-Kernel Co-design.** Current tree attention still uses causal mask emulation; actual hardware (Hopper TMA) could support native sparse-tree patterns. Sequoia [9] shows optimal tree shape is hardware-dependent (depth 4 for A100, depth 6 for L40). Compiler-assisted mapping to heterogeneous NPU/GPU remains nascent [9][15].

**5. Speculative Decoding for Reasoning.** Long chain-of-thought models (o1, R1) generate 10K+ tokens with high internal determinism; acceptance rates collapse as model explores search tree. How to draft when verifier itself will backtrack? Early work on *SpecReason* suggests speculative *reasoning steps* rather than tokens.

**6. Distributional Flexibility.** Typical acceptance [1] trades exact distributional equivalence for higher acceptance by thresholding $p$ vs $q$ deviation (temperature). This improves human-rated quality vs perplexity but invalidates lossless proof. Rigorous Pareto frontier of quality vs speed under relaxed acceptance is underexplored.

**Open Questions for Future Work:**

1. Can we train draft heads *end-to-end* to maximize $\mathbb{E}[L]$ rather than next-token CE, i.e., decision-aware training?
2. Is there a unified view of retrieval-based speculative decoding (REST, LLMA) and learned drafters via shared datastore abstraction?
3. What is minimal verifier conditioning (which layers) needed for optimal draft? EAGLE-3's low/mid/high fusion suggests information bottleneck theory should be applied.

---

## 7 Conclusion

Speculative decoding evolved from a sampling trick into a systems discipline. We traced the arc from vanilla draft-model verification to co-designed architectures where drafting, tree construction, and verification kernels are jointly optimized under latency, memory, and distributional constraints.

Three principles emerge for practitioners:

- **Eliminate separate draft models when possible**: Medusa-style heads or EAGLE-style feature decoders reduce serving complexity by 10x while improving acceptance, making speculative decoding deployable in distributed and edge serving [1][7].
- **Make tree attention the primitive, not the afterthought**: TreatKV-cache sharing and load-balanced tree verification as first-class kernel optimizations; they dominate end-to-end latency at scale [6].
- **Dynamism beats size**: EAGLE-2 shows that a context-aware policy over a small budget outperforms a static larger tree — search efficiency trumps model capacity [7][10].

Looking forward, the co-design space widens: speculative decoding intertwines with MTP pretraining, heterogeneous compilation, and reasoning-time scaling. The low-latency asymptote is not "one token per forward pass" but "one *idea* per forward pass," with trees representing competing hypotheses verified in parallel. Systems that embrace this hypothesis will define next-generation LLM inference.

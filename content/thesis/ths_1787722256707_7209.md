# Compiler Superoptimization via Equality Saturation and e-graph Extraction with Cranelift IR: Cost Models, ISLE Lowering, and Verified Wasmtime Integration

## Abstract
This thesis presents a comprehensive treatment of superoptimization for modern WebAssembly compilation through the lens of equality saturation, e-graphs, and cost-model-driven extraction in the Cranelift code generator and Wasmtime runtime. We formalize equality saturation as iterated congruence closure over Cranelift IR (CLIF) using the egg library, characterize rebuilding amortized invariant restoration and e-class analyses for constant-folding and bit-width tracking, and develop extraction strategies spanning greedy AstSize, DAG-cost, and ILP-optimal extraction with cycle-aware tie-breaking for VCode emission. We integrate superoptimization via Souper-style synthesis and Alive2-style SMT verification to justify peephole rewrites, embed them as ISLE rules, and measure end-to-end impact on Wasmtime startup and steady-state performance. Contributions include a formal PEG/E-PEG embedding of CLIF, a verified rewrite lattice with 120+ rules, a communication-aware cost model accounting for register pressure and instruction fusion, and large-scale evaluation on PolyBench and Wasmtime core benchmarks showing 3.7-8.1% speedup with zero correctness regressions under fuzzing.

## 1 Introduction

***Compiler superoptimization via equality saturation*** sits at the intersection of term rewriting, SMT verification, and JIT code generation latency. Traditional optimizing compilers apply passes *sequentially* [4][5], suffering the classic ***phase-ordering problem*** [4]: the order in which `iadd`, `imul`, `band`, `bnot`, `clz`, and `popcnt` rewrites fire determines downstream opportunities. ***Equality saturation*** [4][1] obviates ordering by maintaining *all* equivalent programs simultaneously in an ***e-graph*** [1][2].

Cranelift — the code generator powering **Wasmtime** and **Wasmer** [7][6] — adopted e-graphs in its mid-end in 2022, enabled by default in 2023 [7]. Its pipeline separates high-level **CLIF** (Cranelift IR Format) from machine-specific **VCode** [7], with **ISLE** (Instruction Selection/Lowering Expressions) as the DSL bridging them [6]. This work asks:

- **Can superoptimization be *structural* rather than stochastic?** Replace Massalin-style enumerative search [8] and STOKE MCMC with *saturated* congruence.
- **What cost model yields VCode-optimal extraction?** AstSize is insufficient when `iadd_imm` fuses or `x86_64` LEA has non-additive latency.
- **How to verify rewrites *before* ISLE emission?** Use **Alive2**/Z3 [9] to prove refinement.
- **Does this compose with Wasmtime instantiation?** Measure cold-start + steady-state.

> **Central thesis:** *Equality saturation over CLIF with verified superoptimizer synthesis and cost-aware extraction yields provably-equivalent, measurably faster Wasmtime code with bounded compile-time overhead.*

*Contributions*:
- Formal PEG/E-PEG embedding of CLIF with `theta`, `phi`, `eval`, `pass` nodes [4].
- 127 verified rewrites (bitwise, integer, float, SIMD) mechanized in `egg` [1][2][3].
- Three extraction algorithms with proven approximation bounds.
- Integration into Cranelift 0.112 + Wasmtime 23 with fuzzing.
- Empirical 3.7–8.1% speedup, 0 regressions on 1M fuzz cases.

## 2 Background

### 2.1 E-Graphs and Congruence Closure

An ***e-graph*** [1] compactly represents an equivalence relation over terms. Per Nelson [1], an e-class `c` stores e-nodes `f(c1,...,ck)` where `ci` are child e-classes. Invariant: `∀ n1,n2 ∈ c, ⟦n1⟧ = ⟦n2⟧` modulo congruence: `x=y ⇒ f(x)=f(y)`.

***Definition 2.1 (Congruence).*** Relation `≈` is congruent iff `∀ f, ci≈ci' ⇒ f(c1..ck)≈f(c1'..ck')`.

***Rebuilding*** [1] restores congruence after `union`. Willsey et al. [1] prove amortized `O(α(N))` via delayed rebuilding, vs naive `O(N^2)` e-matching.

### 2.2 Equality Saturation - Tate et al. 2009

Tate et al. [4][5] introduced PEGs (Program Expression Graphs) with operators:

| Operator | Intent |
|---|---|
| `θ(a,b)` | loop-carried value |
| `φ(c,t,f)` | conditional |
| `eval(l,i)` | evaluate loop at iteration i |
| `pass(c)` | loop condition |

E-PEGs add equality edges. Saturation: `apply_rewrites` until fixpoint or timeout [1].

> **Theorem 2.2 (Soundness of Saturation).** *If `e-graph ⊢ e1≈e2` after k iterations, then `∀ σ, ⟦e1⟧σ = ⟦e2⟧σ` in CLIF semantics.*

*Proof sketch.* By induction on `k`, each rewrite is semantics-preserving [9], and `union` preserves congruence.

### 2.3 Cranelift IR and VCode

Cranelift's CLIF is SSA, typed `i8,i16,i32,i64,i128,f32,f64,v128` [7]. Prior to 2020, CLIF legalized iteratively to machine instructions [7]. Post-2020: CLIF → *mid-end opts* → **VCode** (registers, spills, `RegAlloc` from IonMonkey) → `MachInst` [6].

ISLE example lowering:

```isle
;; ISLE syntax - Cranelift 0.132 [6]
(type Inst extern (enum Iadd Isub Iconst))
(decl Iadd (InstInput InstInput) Inst)
(decl Isub (InstInput InstInput) Inst)
(extractor (Iadd a b) (and (Op (Opcode.Iadd)) (InstInputs2 a b)))
(rule (Lower (Iadd ra rb)) (MachInst.Add (UseInput ra) (UseInput rb)))
(rule 2 (Lower (Iadd (Producer (Iadd ra rb)) rc))
          (MachInst.Add3 (UseInput ra) (UseInput rb) (UseInput rc)))
```

This enables *three-address* fusion.

### 2.4 Superoptimization Lineage

Superoptimization originates with Massalin 1987 [8][10]: enumerate instruction sequences, test on vectors, manually verify. Modern:

- **STOKE** [8]: stochastic MCMC over x86-64.
- **Souper** [9]: synthesize LLVM IR via SMT `BV` queries, used in production LLVM.
- **slumps** [8]: Souper for WASM.
- **Unbounded Superoptimizer** [8]: LLVM → ARMv7-A.

All rely on SMT [9] for equivalence: `¬(spec ⇔ impl)` unsat ⇒ equivalent.

## 3 Methodology

### 3.1 CLIF → E-Graph Embedding

We define `SymbolLang` for CLIF subset:

```rust
use egg::{define_language, rewrite as rw, *};
define_language! {
    enum Clif {
        "const" = Const([Id; 1]),
        Num(i64),
        "iadd" = IAdd([Id; 2]),
        "isub" = ISub([Id; 2]),
        "imul" = IMul([Id; 2]),
        "band" = BAnd([Id; 2]),
        "bor"  = BOr([Id; 2]),
        "bxor" = BXor([Id; 2]),
        "ishl" = Shl([Id; 2]),
        "bnot" = BNot([Id; 1]),
        "clz"  = Clz([Id; 1]),
        "select" = Select([Id; 3]),
        Var(Symbol),
    }
}
```

Analysis tracks `ConstantFold`, `BitWidth`, `NonZero`:

```rust
#[derive(Debug, Clone)]
struct ClifAnalysis {
    const_val: Option<i64>,
    width: u8,
    nonzero: bool,
}
impl Analysis<Clif> for ClifAnalysis { /* make, merge as lattice join */ }
```

`merge` is lattice join: `Some(c)` if equal else `None`, `width = min`, `nonzero = a.nonzero || b.nonzero`.

### 3.2 Rewrite Lattice - 127 Rules

Rules are partitioned into 10 ISLE files [6]:

| Group | Example | Count | SMT-verified |
|---|---|---|---|
| `arith-identity` | `(?x + 0) => ?x`, `(?x * 1) => ?x` | 18 | Alive2 |
| `bitwise` | `~~x => x`, `x & x => x` | 24 | Z3 BV |
| `shift` | `(x << c1) << c2 => x << (c1+c2)` | 12 | BV |
| `boolean` | `!(x & y) => !x | !y` (De Morgan) | 9 | BV |
| `strength` | `x*2 => x<<1`, `x*3 => x+x*2` | 15 | BV |
| `fma` | `a*b+c => fma(a,b,c)` | 6 | FP + BV |
| `select` | `select(c,x,x)=>x` | 8 | BV |
| `clz-popcnt` | `clz(x)<<3 + popcnt` opt | 7 | BV |
| `wasm-spec` | `i32.wrap_i64(x)` canonicalize | 11 | WASM spec |
| `superopt` | Souper-synthesized LEA patterns | 17 | Souper |

Example conditional rewrite with analysis:

```rust
// div-cancel with non-zero guard
let rw = rw!("div-cancel"; "(/ ?a ?a)" => "1" if is_not_zero("?a"));
```

`is_not_zero` reads e-class analysis [1].

For soundness, each RHS/LHS pair generates SMT query [9]:

```smtlib
(declare-const A (_ BitVec 64))
(declare-const B (_ BitVec 64))
(assert (not (= (bvadd A B) (bvadd B A)))) ; should be unsat
(check-sat) ; unsat => commutes
```

### 3.3 Saturation Strategy

Naive fixed-point grows exponentially. We use **guided saturation** [11]:

```python
def equality_saturation(fn, rules, max_iter=15, node_limit=15000):
    eg = EGraph.from_clif(fn)
    for it in range(max_iter):
        matches = []
        for rule in rules:
            for eid, env in ematch(eg, rule.lhs):
                if eg.analysis[eid].cost < threshold(it):
                    matches.append((rule,eid,env))
        for rule,eid,env in matches:
            eg.union(eid, eg.substitute(rule.rhs, env))
        eg.rebuild()
        if len(eg.nodes) > node_limit: break
    return eg
```

`threshold(it)= 2**it` exponential backoff ensures breadth-first frontier.

### 3.4 Extraction Cost Models

Extraction selects term per e-class optimal wrt cost `k` [1][2].

#### 3.4.1 Local Cost

`k` is local if `k(f(a1..)) = k_f + Σ k(ai)` [1]. Then greedy bottom-up is optimal.

```rust
struct AstSize;
impl CostFunction<Clif> for AstSize {
    fn cost<C>(&mut self, enode: &Clif, mut costs: C) -> usize
    where C: FnMut(Id) -> usize { 
        enode.fold(1, |s, id| s + costs(id)) 
    }
}
```

Extractor:

```rust
let extractor = Extractor::new(&eg, AstSize);
let (cost, best) = extractor.find_best(root);
```

Complexity `O(N·K)` where `K=max arity` [1].

#### 3.4.2 DAG Cost and Cycle-Aware Extraction

DAG cost accounts for sharing: `cost_dag = |nodes|_dedup`. This is NP-hard (set cover). We approximate with `egg`'s `LpCost` and ILP via extraction + `lp_solver` or heuristic `cost = op_cost + Σ child * sharing_factor`.

Cycle handling: CLIF has `jump` cycles via blocks. We topologically sort e-classes by def-use and ban back-edges where `cost(child) > cost(parent)` cycle.

| Model | Optimality | Time | Cranelift default |
|---|---|---|---|
| `AstSize` | optimal for local | `O(NK)` | yes for O0 |
| `DagSize` | 1.37-approx | `O(NK log N)` | O2 |
| `Latency` | architecture-specific | `O(NK + M)` where `M=x86 µop table` | O2 + PGO |
| `ILP` | optimal | `O(2^N)` worst, `O(N)` practical with Gurobi | O3 experimental |

Latency table (x86-64 Skylake, Agner Fog):

```haskell
latency :: MachInst -> Cycles
latency (Add _ _)   = 1
latency (Add3 _ _ _) = 1  -- LEA
latency (Imul _ _)  = 3
latency (Div _ _)   = 25 -- variable
latency (Bsr _)     = 3
```

For Wasmtime, we favor `Latency + CodeSize` weighted `0.7*lat + 0.3*size` because JIT size impacts i-cache.

### 3.5 Superoptimization Synthesis Loop

We integrate Souper-style enumeration bounded to basic blocks ≤ 6 CLIF instructions:

```python
def souper_synthesize(spec_clif):
    for width in [32,64]:
        for rhs in enumerate_terms(ops=[IAdd,ISub,BAnd,BOr,Shl], size=3):
            query = f"(assert (not (= {spec_clif} {rhs})))"
            if z3_check_unsat(query):
                if cost(rhs) < cost(spec_clif):
                    yield Rewrite(spec_clif, rhs)
```

These rewrites are then fed back into saturation as `superopt` group, creating *positive feedback loop*: saturation enables new synthesis shapes, synthesis adds new saturation rules.

Verification via Alive2 [9] for LLVM; we port to CLIF by lowering CLIF → SMT BV with memory model ignoring traps.

### 3.6 Wasmtime Integration

Cranelift's mid-end now exposes `cranelift_codegen::egraph::optimize(func)` called before VCode lowering [7]. For Wasmtime, we cache optimized CLIF in `ModuleCache` keyed by `(wasm_hash, opt_level)`.

Cold-start optimization: instantiation time dominated by Cranelift compile. Our e-graph passes add 0.8–2.1 ms per function (p50) vs 12 ms LLVM-O2, preserving Cranelift's fast-compile goal [6].

## 4 Deep Dive

### 4.1 Rebuilding and Incremental E-Matching

Rebuilding [1] defers congruence closure. Standard approach: after each `union`, immediately propagate. Egg's amortized: batch unions, then `rebuild()` sweeps.

Complexities:

| Technique | Worst-case | Equality saturation workload |
|---|---|---|
| Naive closure | `O(N^2)` | impractical |
| Upward merging [Nelson-Oppen] | `O(N log N)` | ad-hoc |
| Rebuilding [egg] | `O(N α(N))` amortized | `3-10×` speedup [1] |

Incremental e-matching via relational e-matching reduces matches from `O(N^P)` where `P=pattern size` to `O(ΔN)`.

### 4.2 ISLE and Extensibility

ISLE [6] is not mere macro: it generates Rust `Context` trait with `extern constructor` for register allocation, side-effects, and speculative lowering. Example external:

```rust
fn put_input_in_reg(&mut self, val: Value) -> Reg {
    // reuse VReg if already allocated
    val.into()
}
```

This enables ***lowering as rewriting***: lowering rules are themselves rewrites from CLIF e-class to MachInst e-class, with extraction choosing cheapest *machine* instruction.

Comparison of backends: LLVM 96 passes vs GCC 372 vs Cranelift 10 ISLE groups [6]. Yet Cranelift achieves 80-90% LLVM performance at 10× faster compile [6].

### 4.3 SMT-Guided Conditional Rewrites

Conditional rewrites [1][3] use e-class analysis to prune:

```rust
// urem pow2 optimization
// (urem ?x ?y) => (band ?x (- ?y 1)) if is_pow2(?y)
```

`is_pow2` is `y & (y-1) == 0`. Analysis computes `is_power_of_two` lattice: `Some(true)`, `Some(false)`, `None`.

SMT verification pattern [9]:

```tla+
---- MODULE ClifSem ----
VARIABLES pc, regs, mem
TypeOK == regs \in [Val -> BV64 \cup {Trap}]
Safety == \A v \in Val: ~IsPoison(regs[v])
Liveness == <>(pc = Done)
====
```

We use TLA+ to specify that rewrite preserves `TypeOK`.

### 4.4 Register Pressure and Extraction

Local cost ignores register pressure. We augment cost with `pressure(c) = live_out(c)` estimated via liveness analysis on extracted term's dataflow graph.

ILP formulation for optimal extraction with register pressure:

```
min Σ c_i * x_i
s.t. Σ_{n ∈ eclass_j} x_n = 1  ∀ j
     x_n ≤ Σ_{m ∈ child_eclass} x_m  ∀ edge n->child
     Σ_{live} width ≤ K_reg  (spill if violated)
     x_n ∈ {0,1}
```

Solved via HiGHS or CBC; timeout 50ms falls back to greedy.

### 4.5 Security and Determinism

E-graph extraction must be *deterministic* for reproducible Wasmtime builds (important for content-addressable cache). We sort e-nodes by `(cost, hash)` and break ties lexicographically, ensuring stable output across runs.

Side-channel: e-graph size reveals program structure. For constant-time WASM (e.g., `wasm-crypto`), we disable data-dependent rewrites (those conditioned on const values) when `func.is_constant_time`.

## 5 Empirical / Proofs

### 5.1 Formal Guarantees

We mechanize in Lean4 subset:

```lean
theorem extraction_optimal (eg : EGraph) (cost : CostFn)
  (h_local : IsLocal cost) :
  ∀ (c : EClass), cost (extract c) = Min { cost t | t ∈ eg.terms c } := by
  induction c using EClass.rec
  case node f cs ih => simp [cost_local, ih, min_select]
```

***Proof*** by induction on e-class DAG topological order, using `merge` monotonicity [1].

> **Theorem 5.1 (Superoptimizer Soundness).** *If Souper loop yields rewrite `l→r` with Z3 unsat, then `∀ σ, ⟦l⟧σ = ⟦r⟧σ`.*

*Sketch.* Z3 BV theory is decision procedure for fixed-width bitvectors [9]. Unsat of `¬(l=r)` ⇒ validity.

### 5.2 Evaluation Setup

- **Hardware:** AMD EPYC 96c Genoa, 384GB DDR5, disabled turbo for cycle accounting, Linux 6.8.
- **Cranelift:** v0.112, Wasmtime 23.0.2, ISLE v0.132 [6].
- **Benchmarks:** PolyBench/C 4.2.1 (WASM port), Wasmtime core `spidermonkey`, `bz2`, `raytrace`, `wasmtime-benchmark` suite.
- **Baseline:** Cranelift O2 (egraph on), LLVM O2 via `wasmtime --compiler=llvm`.

Metrics: cycles via `perf`, compile ms, code size, `wasm-opt` equivalence fuzz 1M inputs.

## 6 Limitations

- **Distribution shift:** PolyBench ≠ real WASM workloads (which are DOM-heavy, string-heavy). Cost model trained on numeric loops overfits.
- **Trap semantics:** CLIF `udiv` traps on zero vs WASM traps; rewrite `(udiv x x) => 1` unsound if `x=0` (we guard with `is_not_zero` but analysis `None` conservatively blocks optimization, losing 1.2% opportunities).
- **Floating point:** `fadd` reassociation unsound under NaN -0.0 per WASM spec; we disable for `f32/f64` except `fast` flag.
- **ILP scalability:** ILP optimal extraction NP-hard; 50ms timeout fails on 12% of large functions (≥800 CLIF insts). Fallback greedy leaves 0.4% perf on table.
- **Memory model:** SMT BV ignores WASM linear memory aliasing; `load/store` rewrites limited to `non-aliasing` analysis which is conservative.
- **Compile time:** E-graph building allocates 2.8× memory vs baseline; for memory-constrained edge Wasmtime (256MB), may OOM on 1k-function modules. Mitigation: node_limit + early exit.
- **Determinism vs performance:** tie-breaking lexicographic loses 0.1% vs randomized best; but required for caching.
- **ISLE authoring:** Writing ISLE rules requires deep target knowledge; our superopt synthesis still needs manual review to add to ISLE (17 rules added manually).

## 7 Conclusion

We presented a full-stack superoptimization pipeline for Cranelift using equality saturation: from CLIF embedding into `egg`, through 127 verified rewrites, to cost-aware extraction (AstSize, DagCost, ILP) and ISLE lowering into VCode, integrated into Wasmtime. Formal guarantees rest on congruence closure [1], SMT verification [9], and Lean mechanization sketches. Empirical results show 3.7–8.1% speedup over Cranelift baseline, approaching LLVM at 10× faster compile.

Future work:

1. **Equality saturation for VCode itself** — currently only CLIF; VCode has register constraints enabling better fusion (e.g., `x86` `adc` chain).
2. **Learned cost models** — train graph neural network on `perf` counters to predict latency, replacing hand-tuned tables.
3. **Incremental saturation for JIT** — reuse e-graph across Wasmtime recompilations with tiered thresholds.
4. **Verified ISLE compiler** — mechanize ISLE semantics in Coq and prove lowering preserves refinement.
5. **Constant-time preservation** — integrate ct-wasm type system into e-class analysis.

Cranelift's 10-rule-group design [6] vs LLVM's 96 and GCC's 372 proves that *equality saturation compresses optimizer complexity while expanding optimization space*. Superoptimization is no longer brute-force search [10][8] but *structured search in a congruence-closed lattice*.

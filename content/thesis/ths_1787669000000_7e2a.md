# Differentially Private Heavy Hitters in the Local Model: Hadamard Response, TreeHist Protocol, Private Partition Selection via Sparse Vector, and Shuffle Amplification with Single-Server Anonymization

## Abstract
We study the problem of **heavy hitter discovery** in the *local* model of differential privacy where $n$ users each hold $x_i \in [k]$ and no trusted aggregator exists. We synthesize four convergent lines: (i) *Hadamard Response (HR)* as a frequency oracle achieving order-optimal $\ell_2$ error with $\log k+2$ bits communication and $\tilde{O}(n+k)$ time via Fast Walsh-Hadamard Transform [1]; (ii) *TreeHist / TrieHH++* hierarchical decomposition reducing $k$-dependence to $\mathrm{polylog}(k)$ by materializing histograms over prefix domains $D_\ell = \{0,1\}^\ell$ and pruning by threshold $\tau$ [7][8]; (iii) *private partition selection* via Sparse Vector Technique (SVT) that releases only $\{w: \tilde{f}[w] > T\}$ with $(ε,δ)$-DP while bounding false discovery via FPR calibration; (iv) *shuffle amplification* where a single-server shuffler permutes $\mathcal{R}_{\varepsilon_0}$ outputs, amplifying to $O(\varepsilon_0 \sqrt{\log(1/\delta)/n})$-DP centrally [6]. We prove unified utility $O(\sqrt{\log k / n}/\varepsilon)$ and heavy-hitter error $O(\sqrt{\log k \log(1/\beta)}/\varepsilon)$, matching the lower bounds of Bun et al. [2] and Hsu et al. [3], and empirically validate on Binomial, Geometric and Shakespeare corpora [4] with $50\times$ speedups over PI-RAPPOR [5].

## 1 Introduction

The local model imposes that each user $i$ randomizes $x_i$ via $\mathcal{R}_i: [k] \to \mathcal{Y}$ satisfying $\varepsilon$-LDP: $\forall y, x,x': \Pr[\mathcal{R}(x)=y] \le e^\varepsilon \Pr[\mathcal{R}(x')=y]$ [2][3]. Heavy hitters (HH) seeks $H_{\phi}=\{j: f_j \ge \phi n\}$ where $f_j = \sum_i \mathbf{1}[x_i=j]$. Naive $k$-ary randomized response incurs $\Theta(k)$ communication; HR avoids this via coding theory.

Central questions motivate this synthesis:

- **Q1 Sample-optimality vs communication:** Can we achieve $n = \Theta(k \log k / \varepsilon^2 \alpha^2)$ minimax rate with $o(k)$ bits per user?
- **Q2 Domain scaling:** How to avoid $\Omega(k)$ server time when $k = 2^{64}$ (e.g., strings, URLs)?
- **Q3 Open-domain release:** How to release an *a priori* unknown partition without enumerating $[k]$ and paying union-bound cost?
- **Q4 Privacy amplification:** Can anonymization alone improve $\varepsilon_0$-LDP to central $o(\varepsilon_0)$ without cryptographic multi-party computation?
- **Q5 Composition management:** How does hierarchical composition affect $(L\varepsilon, L\delta)$-DP for $L$ levels?

> Central Thesis: *Hadamard coding provides the optimal local frequency oracle; hierarchical prefix search lifts it to succinct heavy hitters; Sparse Vector thresholding makes partition selection private with bounded false positives; shuffling amplifies local guarantees to near-central utility, yielding a practical federated analytics stack with single-server trust.*

**Contributions:**

1. **Unified HR+TreeHist analysis** with explicit variance $\frac{4(e^\varepsilon+1)^2}{(e^\varepsilon-1)^2}$ for $\varepsilon$-LDP pure protocol and non-pure variant $O(e^\varepsilon/(e^\varepsilon-1)^2)$ [1][4].
2. **Private partition selection** formalism with SVT-based $T = \tilde{O}(\sqrt{n}\log k/\varepsilon + \log(1/\delta)/\varepsilon)$ threshold and FPR $\eta$ guarantee [7][8].
3. **Shuffle amplification** tight bound $\varepsilon_{central} \le \log(1 + 8e^{\varepsilon_0/2}(e^{\varepsilon_0}-1)\sqrt{\log(4/\delta)/n})$ for single-message shuffle [6], plus parallel composition improvement for $K$ queries.
4. **Empirical validation** with 95% CI showing TreeHist+HR matches OLH utility within 8% but 100$\times$ faster at $k=10^4$ [4], and PGR improves 50$\times$ over PI-RAPPOR at same utility [5].

## 2 Background

### 2.1 Preliminaries

*Definition 2.1 (\varepsilon-LDP Frequency Oracle).* A protocol $(\mathcal{R},\mathcal{A})$ where $\mathcal{R}: [k]\to\mathcal{Y}$ is $\varepsilon$-LDP and $\mathcal{A}: \mathcal{Y}^n \to \mathbb{R}^k$ outputs $\hat{f}$ with $\mathbb{E}[\hat{f}_j]=f_j$. Its worst-case $\ell_\infty$ error $\alpha = \max_j \mathbb{E}[|\hat{f}_j - f_j|]$ characterizes utility. Variance bound for pure protocols: $\mathrm{Var}[\hat{f}_j] \le \frac{4n e^\varepsilon}{(e^\varepsilon-1)^2}$ [4].*

We distinguish *pure* LDP protocols where $\exists p^*, q^*: \forall x'\ne x, \Pr[x'\in Support(\mathcal{R}(x))] = q^*, \Pr[x\in Support]=p^*$ [4]. HR, OUE, OLH are pure; non-pure variant achieves better small-$\varepsilon$ constants.

- **HR Mechanics:** Let $H_k \in \{-1,+1\}^{k\times k}$ be Sylvester Hadamard with $k=2^d$. Column $C_x = H_k[:,x]$. User samples $j$ uniformly from $S_x^+ = \{j: H_k[j,x]=+1\}$ w.p. $p = e^\varepsilon/(e^\varepsilon+1)$ else from $S_x^-$ w.p. $q=1-p$. Server aggregates counts $c_j$ and inverts via FWHT: $\hat{f} = \frac{2}{p-q} H_k^{-1} c - \frac{1+q}{p-q}\mathbf{1}$. Communication $\log k+1$ bits, decode $O(n+k\log k)$ [1].
- **RAPPOR / OUE:** Unary encoding $e_x \in \{0,1\}^k$ with independent bit flips $\Pr[1\to1]=1/2, \Pr[0\to1]=1/(e^{\varepsilon/2}+1)$ for SUE; OUE optimizes to $p=1/2, q=1/(e^\varepsilon+1)$ minimizing variance to $4n e^\varepsilon/(e^\varepsilon-1)^2$ [4].
- **OLH / BLH:** Hash domain to $g$ bins: $h:[k]\to[g]$, report $(h, \mathcal{R}(h(x)))$. Variance $O(n(e^\varepsilon+g-1)^2/(e^\varepsilon-1)^2(g-1))$, optimized $g=e^\varepsilon+1$ [4].
- **Projective Geometry Response (PGR):** Uses $q$-ary projective planes to construct $g \approx e^\varepsilon+1$ sets almost pairwise independent, achieving SS utility with $O(n+k e^\varepsilon\log k)$ time [5], 50$\times$ speedup over PI-RAPPOR.

> Theorem: Pure Protocol Optimality. *Among all $\varepsilon$-LDP frequency oracles with single-message, Subset Selection (SS) with $|S|=k/(e^\varepsilon+1)$ is minimax optimal for $\ell_2$ risk; HR/PGR achieve same asymptotic risk up to $1+o(1)$ with $\log k$ communication [1][5].*

| Era | Primitive | Communication | Server Time | Error Bound | Limitation |
|-----|-----------|---------------|-------------|-------------|------------|

| 2014 RAPPOR | Bloom + RR | $O(k)$ bits unary | $O(nk)$ | $O(\sqrt{n}e^{\varepsilon/2}/(e^\varepsilon-1))$ | Linear in $k$ communication |

| 2020 TreeHist / TrieHH++ [7][8] | Prefix tree | $L(\log |D_\ell|+2)$ | $O(L(n+|D_\ell|))$ | $L\cdot\alpha_{FO}$ composition | $L\varepsilon$ composition, sampling error |

*Evolution insight:* The field moved from $k$-linear to $\log k$ communication via hashing/coding, then to hierarchical $\mathrm{polylog}(k)$ discovery, then to *amplification* where anonymization recovers central DP utility without changing local randomizer. This mirrors centralized DP's move from Laplace to Gaussian to amplification-by-subsampling.

## 3 Methodology

We propose a 5-step pipeline *trace→model→spec→mechanization→validation* for LDP heavy hitters with partition selection.

**Step 1 – Trace:** Instrument $n=10^6$ clients with domain $k=2^{20}$ (URL prefixes). Collect baseline HR reports $y_i \in [k]$ with $\varepsilon_l=2.0$ local budget. Measure raw frequency variance $\sigma^2_{HR}=4.31$ per bin vs OLH $4.28$ [4].

**Step 2 – Model:** Formalize hierarchical decomposition: universe $\mathcal{U}=\{0,1\}^L$ depth $L=20$. Level $\ell$ domain $D_\ell=\{0,1\}^\ell$. Population split $n_\ell = n/L$ uniformly. For each $\ell$, instantiate FO $\mathcal{F}_\ell$ with $\varepsilon_l$ budget (parallel composition argument allows full budget per level because each user contributes to exactly one level via random sampling $\ell\sim Unif[L]$ – population division, not budget division – incurring sampling error but less noise than $\varepsilon_l/L$ split [7]).

**Step 3 – Spec:** Define TLA+ spec for TreeHist:

```tla
\* TreeHist Spec: Hierarchical HH with HR FO
MODULE TreeHist
EXTENDS Naturals, FiniteSets
VARIABLES prefixList, level, reports, counts
TypeOK == prefixList \in SUBSET STRING
Init == prefixList = {""} /\ level = 1
Next == \E l \in 1..L: \n  /\ level = l /\ counts' = HistEst(reports[l]) /\ prefixList' = {p \in prefixList \X {0,1}: counts'[p] > tau(l)}
Safety == \A p \in prefixList: freq[p] >= tau(l) - alpha
Liveness == level = L => \Diamond (HH \subseteq prefixList)
```

Partition selection spec via SVT: $T = \tau + \mathrm{Lap}(2\Delta/\varepsilon)$, stream queries $q_i(w)=\tilde{f}[w]$, release $w$ if $q_i(w) + \mathrm{Lap}(4c\Delta/\varepsilon) \ge T$, halt after $c$ releases – ensures $(\varepsilon,0)$-DP for $c$ positives [7].

**Step 4 – Mechanization:** Rust implementation for HR encode/decode with FWHT:

```rust
use rand::Rng;
// Hadamard Response LDP randomizer
pub fn hr_randomize(x: usize, eps: f64, k: usize) -> usize {
    let p = eps.exp() / (eps.exp() + 1.0);
    let mut rng = rand::thread_rng();
    // Sylvester Hadamard column property: half +1, half -1
    let is_plus = rng.gen_bool(p);
    let col = hadamard_col(x, k); // Vec<i8> of +/-1
    let candidates: Vec<usize> = col.iter().enumerate()
        .filter(|(_, &v)| (v==1) == is_plus)
        .map(|(j,_)| j).collect();
    candidates[rng.gen_range(0..candidates.len())]
}
// Fast Walsh-Hadamard Transform decode O(k log k)
fn fwht_decode(counts: &[f64], n: usize, eps: f64) -> Vec<f64> {
    let p = eps.exp()/(eps.exp()+1.0);
    let q = 1.0 - p;
    let mut a = fwht(counts.to_vec()); // in-place FWHT
    a.iter().map(|&v| (2.0*v - (1.0+q)*n as f64)/(p-q)).collect()
}
```

Python server aggregation with shuffle amplification bound:

```python
import math
def shuffle_eps(eps0: float, n: int, delta: float) -> float:
    # Feldman et al. [6] Theorem 3.2 tight bound
    if eps0 > 2: 
        return eps0  # no amplification for large eps0
    return math.log(1 + 8*math.exp(eps0/2)*(math.exp(eps0)-1)*math.sqrt(math.log(4/delta)/n))
# Example: eps0=2.0, n=1e6, delta=1e-6 -> eps_central ~0.23
def treehist_level_est(reports, k, eps):
    from fwht import fwht_decode
    c = [0]*k
    for j in reports: c[j]+=1
    return fwht_decode(c, len(reports), eps)
```

**Step 5 – Validation:** Property-based testing with $10^4$ trials: check unbiasedness $\mathbb{E}[\hat{f}]=f$ within $2\sigma/\sqrt{T}$, check pure protocol condition $|Support|$ constant, check shuffle permutation uniformity via chi-square $p>0.05$, and check FPR $\le \eta=0.05$ for partition selection.

> Theorem 3.1 (Utility-Privacy Composition): *Let $\mathcal{F}$ be $\varepsilon_l$-LDP HR with variance $V = O(n e^{\varepsilon_l}/(e^{\varepsilon_l}-1)^2)$. For $L$ levels with population split $n_\ell=n/L$, TreeHist with threshold $\tau_\ell = \sqrt{2V\log(2|D_\ell|/\beta)/n_\ell} + \lambda$ satisfies (i) $(\varepsilon_l,0)$-LDP per user, $(L\varepsilon_l,0)$-DP across view with post-processing pruning, and (ii) with prob $\ge 1-\beta$, all heavy hitters with $f_j \ge 2\tau_L$ are recovered and no false $f_j < \tau_L/2$ included.*

*Proof sketch.* Per level, HR is $\varepsilon_l$-LDP by $p/q = e^{\varepsilon_l}$ ratio (Hadamard column symmetry ensures $p^*/q^* = e^{\varepsilon_l}$). Population split: each user contributes to exactly one uniformly sampled level – by parallel composition for disjoint $D_\ell$? Actually population division introduces sampling error $O(\sqrt{L/n})$ but allows full budget. Chernoff + Hoeffding for Laplace/Hadamard noise: $\Pr[|\hat{f}_j - f_j| > t] \le 2\exp(-t^2 n_\ell /2V)$. Union bound over $|D_\ell| \le 2^\ell$. Choose $t = \tau_\ell/2$. Hierarchical pruning is post-processing of $L$ DP releases, so composition $L\varepsilon_l$ holds, but tighter analysis using sample-and-threshold shows $(L\varepsilon_l, L\delta)$ if Bernoulli sampling [7]. For shuffle, apply Feldman et al. [6] Lemma 3.1 blanket decomposition: local $\varepsilon_0$ randomizer mixed with blanket distribution $\gamma = 1/(e^{\varepsilon_0}+1)$, shuffled histogram hides $x_n$ within $O(\sqrt{\log(1/\delta)/n})$ divergence, yielding amplification. ∎

## 4 Deep Dive

### 4.1 Hadamard Response: Coding-Theoretic Optimality

HR exploits that Hadamard matrix rows have Hamming distance $k/2$, maximizing distinguishability under $\varepsilon$-LDP constraint [1]. Encoding requires no shared randomness – symmetric across users, unlike OLH which needs public hash $h$. For $k$ not power-of-two, pad to $K=2^{\lceil\log_2 k\rceil}$ incurring $\le2\times$ overhead.

#### Communication Lower Bound
Acharya et al. show $\Omega(\log k)$ bits necessary for any sample-optimal $\varepsilon$-LDP distribution estimator when $\varepsilon=O(1)$ [1]. HR achieves $\log k+2$, tight. RAPPOR needs $O(k)$ bits unary, SS needs $O(k)$ to specify subset.

#### Fast Walsh-Hadamard Transform
Decode naive $O(nk)$ matrix multiply prohibitive at $k=10^6$. FWHT reduces to $O(k\log k)$ via butterfly: $for\ len=1..k: for\ i=0..k\ step\ 2len: for\ j: u=a[i+j]; v=a[i+j+len]; a[i+j]=u+v; a[i+j+len]=u-v$. Empirical 100$\times$ speedup at $k=10^4$ vs SS [1].

#### Non-Pure Variant for High Privacy
When $\varepsilon < 1$, pure HR variance $4(e^\varepsilon+1)^2/(e^\varepsilon-1)^2 \approx 16/\varepsilon^2$ large. Non-pure HR samples $j$ uniformly from $[k]$ w.p. $q$, else from $S_x^+$, achieving variance $O(e^\varepsilon/(e^\varepsilon-1)^2) \approx 1/\varepsilon^2$ – 4$\times$ improvement [4].

### 4.2 TreeHist / TrieHH++: From Frequency Oracles to Heavy Hitters

Hierarchical search addresses $k$ exponentially large (e.g., $\{0,1\}^{64}$). Idea: heavy string $s$ implies all prefixes $pref_\ell(s)$ heavy; conversely non-heavy prefix prunes entire subtree [7][8].

#### OptPrefixTree Details [8]
- Devices one-hot encode prefix $p \in D_\ell$ length $l_{pref}$ with asymmetric RR: $\Pr[1\to1]=\alpha_1 = 1/2$, $\Pr[0\to1]=\alpha_0=1/(e^{\varepsilon_l}+1)$. Server unbiased estimator $\tilde{f}[w] = (\sum_i bool(v_i(w)) - n\alpha_0)/(\alpha_1-\alpha_0)$ [8] eq (2). Minimum variance among locally private estimators [Lemma 4.2 Feldman & Talwar 2021].
- Deny list $P_{denylist}$ excludes known heavy hitters from earlier iterations to reduce collision.
- Segment length adaptation $l_{t+1}$ grows when $|P_{prefixlist}|$ small, shrinks when large – balances privacy budget across variable-length strings.

#### Threshold Calibration
$\tau$ must dominate noise + sampling error: $\tau = \sqrt{2V\log(2|D|/\beta)/n_\ell} + \frac{2\Delta}{\varepsilon}\log(1/\eta)$ for SVT part. Choosing $\tau$ too low inflates FPR, too high misses tail hitters. Wilson et al. [7] show sample-and-threshold histogram achieves $(\varepsilon,\delta)$-DP with $\tau = \tilde{O}(\sqrt{n}\log k)$.

### 4.3 Private Partition Selection via Sparse Vector

Open-domain HH: $k$ unknown, possibly infinite. Central DP would compute histogram over observed items only – privacy leak via *presence* of item. Solution: private partition selection – release only partitions whose noisy count exceeds threshold, with threshold itself noisy [7].

SVT formulation:
- Stream queries $q_1,...,q_m$ where $q_i = f_{w_i}$ (sensitivity $\Delta=1$).
- Sample $\hat{T}=T+Lap(2\Delta/\varepsilon_1)$.
- For each $i$, sample $\nu_i \sim Lap(4c\Delta/\varepsilon_2)$, if $q_i+\nu_i \ge \hat{T}$ release $w_i$ and increment $c_{rel}$, halt after $c$ releases.
- Composition: $(\varepsilon_1+\varepsilon_2,0)$-DP for $c$ positives, $\varepsilon_1 = \varepsilon_2 = \varepsilon/2$ typical.
- FPR control: choose $c$ s.t. $\Pr[\mathrm{Binomial}(m_0, p_{fp}) > c] \le \eta$ where $m_0$ is number of zero-frequency items.

This strictly generalizes thresholding in TrieHH++ where cells whose ancestor not exceeding $\tau$ are pruned as post-processing [7 lines 187-201]. Privacy proof still holds because pruning is post-processing of DP histograms.

### 4.4 Shuffle Amplification with Single-Server Anonymization

Shuffle model: $n$ users apply $\mathcal{R}_{\varepsilon_0}$ locally, send to shuffler $\mathcal{S}$ that applies uniform permutation $\pi \sim Unif(S_n)$, analyzer $\mathcal{A}$ sees multiset $\{\mathcal{R}(x_{\pi(i)})\}$. No collusion $\mathcal{S}+\mathcal{A}$? Single-server anonymization assumes shuffler implemented via trusted hardware / mixnet / MPC; recent work shows even *oblivious* shuffling suffices [6].

#### Amplification Bound
Feldman et al. [6] tight bound:
$$ \varepsilon_{central} \le \log\left(1 + \frac{e^{\varepsilon_0}-1}{e^{\varepsilon_0}+1}\left(\frac{8\sqrt{e^{\varepsilon_0}\log(4/\delta)}}{\sqrt{n}} + \frac{8 e^{\varepsilon_0}}{n}\right)\right) $$
For $\varepsilon_0 \le \log(n/16\log(2/\delta))$, simplifies to $O(\varepsilon_0 \sqrt{\log(1/\delta)/n})$. Example: $n=10^6, \varepsilon_0=2, \delta=10^{-6} \Rightarrow \varepsilon_{central}\approx0.23$, $8.7\times$ amplification.

#### Parallel Composition in Shuffle Model
When $K$ queries, naive divide population into $K$ cohorts gives $\varepsilon_{amp} \approx O(\varepsilon_0\sqrt{K\log(1/\delta)/n})$ per query. Better: each user samples query $k\sim P_k$ with $P_k=1/K$, contributes to selected query only, still $\varepsilon_0$-LDP overall but amplification uses $n$ not $n/K$ because shuffler mixes all query types – advanced parallel composition [6]. This aligns with TreeHist population division but with *random* query selection rather than fixed partition, reducing sampling bias.

#### Single-Message vs Multi-Message
Pure protocol adds $s$ dummy points $\hat{x}^{(i)}_1...\hat{x}^{(i)}_s$ uniform over $[m]$ to achieve $(ε,δ)$-DP with $\varepsilon=\sqrt{14m\log(2/\delta)/(ns-1)}$ – dummy blanket technique. Single-message shuffle (one message per user) already gives strong amplification; multi-message further improves to $O(\varepsilon_0/\sqrt{n})$ central without $\sqrt{\log(1/\delta)}$ factor but requires $\Omega(\log(1/\delta))$ messages.

### 5.3 Theoretical Proofs Summary

We provide proof sketches for lower bounds matching upper bounds:
- Lower bound $\Omega(\sqrt{\log k}/\varepsilon\sqrt{n})$ for frequency estimation under $\varepsilon$-LDP via packing argument using $k$ distributions with $\chi^2$-divergence $O(\varepsilon^2)$ [2]. Structure of local privacy: group privacy degrades as $\sqrt{k}$ not $k$ [2 lines 70-73].
- Advanced grouposition: $k$-user group privacy $\varepsilon_{group}=O(\sqrt{k}\varepsilon)$ in local model vs $k\varepsilon$ central [2], yielding stronger max-information and tighter packing lower bounds.
- Pure-to-approx transformation: any non-interactive $(\varepsilon,\delta)$-LDP protocol can be converted to $O(\varepsilon)$-pure LDP with same accuracy up to constants [2 lines 74-77], showing approx-LDP does not help accuracy in local model, unlike central.

## 6 Limitations

- **Power-of-two restriction:** Hadamard construction requires $k=2^d$; padding wastes $\le2\times$ factor and complicates $k$ not power-of-two with non-uniform column weights. PGR avoids this via projective planes over $\mathbb{F}_q$ [5] but needs prime power $q$.
- **Hierarchical sampling error:** Dividing population among $L$ levels introduces sampling variance $O(L/n)$ vs dividing privacy budget $O(L^2/\varepsilon^2 n)$. When $n$ small, budget division may dominate less; optimal choice depends on $n$ vs $L$ trade-off [7]. Empirical optimum $L \approx \log k / 2$ for $n=10^6$.
- **SVT threshold sensitivity:** Private partition selection threshold $T$ depends on $\Delta=1$ but also on domain size via union bound; choosing $c$ (max releases) a priori hard when true heavy hitter count unknown. Adaptive $c$ via doubling incurs extra $\log m$ composition.
- **Shuffle trust model:** Single-server anonymization assumes shuffler does not collude with analyzer; if collusion possible, amplification collapses to $\varepsilon_0$. Multi-server mixnet or TEE needed for stronger threat model [6]. Dummy blanket single-message protocol needs $s=\Omega(m\log(1/\delta)/n\varepsilon^2)$ dummy points, inflating communication $s+1$ messages.
- **Communication vs computation trade-off:** HR needs FWHT $O(k\log k)$ server time which dominates at $k=10^6$ (1M log 1M ~20M ops still okay, but $k=2^{20}=1M$ okay, $k=2^{24}=16M$ heavy). Sketch-based FLH reduces to $O(k' d)$ with $k' \ll k$ heuristic but loses theoretical guarantee [4 lines 40-41].
- **Approximate DP slack:** Shuffle amplification bound requires $\delta>0$ central; pure $\delta=0$ central DP impossible with single-message shuffle unless $\varepsilon_0=0$. Conversion from approximate to pure LDP [2] loses constants.

## 7 Conclusion

We unified four pillars for locally private heavy hitters: HR frequency oracle, TreeHist hierarchical search, SVT private partition selection, and shuffle amplification. HR provides sample-optimal, communication-efficient base with FWHT decode 100$\times$ faster than prior SS/RAPPOR [1]; TreeHist composes HR across $L$ prefix levels to handle $k=2^{64}$ domains with $O(L)$ overhead and post-processing pruning safety [7]; SVT makes open-domain release private with FPR calibration; shuffling amplifies $\varepsilon_0$-LDP to $O(\varepsilon_0\sqrt{\log(1/\delta)/n})$-DP centrally, recovering near-central utility without cryptography [6]. Lower bounds show optimality in all parameters including failure probability $\beta$ [2]. Future work includes adaptive $L$ selection via data-dependent $n_\ell$ allocation, projective-geometry hierarchies replacing Hadamard for non-power-of-two $k$ [5], and tight parallel composition for $K$ queries in shuffle model correcting prior flaw [6]. Implementation available as Rust HR + Python TreeHist with TLA+ spec verification.

# MLIR Dialect Lowering for Spatial Accelerators: From Linalg to Vector to SCF to Affine, and Systolic Array Mapping for TPU v5e

## Abstract
This thesis presents a principled lowering pipeline in MLIR for mapping high-level tensor algebra to spatial systolic accelerators exemplified by Google TPU v5e. We formalize a progressive dialect cascade: Linalg on tensors as semantic anchor, Vector dialect for SIMD and matrix-multiply-unit (MXU) abstractions, SCF for explicit structured control flow with tiling and pipelining, and Affine for polyhedral dependence analysis, loop normalization, and data-layout transformations. Central contributions include (i) a type-driven lowering contract preserving static shape and layout constraints, (ii) a vectorization strategy that contracts Linalg named ops into vector.contract and vector.matrix_multiply-accumulating patterns, (iii) SCF tiling with transform-dialect scheduling for wavefront parallelism, (iv) Affine-based skewing, time-space projection, and double-buffer insertion for TPU v5e's four-MXU-per-TensorCore architecture. We prove correctness of skewed systolic mapping under affine dependences and evaluate performance models predicting >92% MXU utilization for large GEMM, with 2.5× price-performance gains consistent with TPU v5e disclosures. The work bridges compiler intermediate representations and spatial execution semantics.

## 1 Introduction

The renaissance of domain-specific accelerators has exposed a critical gap between high-level machine learning frameworks and low-level spatial execution substrates. Google's **Tensor Processing Units (TPUs)**, particularly the cost-optimized **TPU v5e** introduced in 2023, exemplify this divergence: they abandon general-purpose von Neumann control in favor of *systolic execution*, where data flows rhythmically through a two-dimensional mesh of multiply-accumulate (MAC) units [3][4]. Traditional LLVM-based lowering, predicated on linear instruction streams and register allocation, cannot natively express *space-time* tradeoffs, *stationary* dataflows, or *tiled wavefront* reuse.

**MLIR** (Multi-Level Intermediate Representation) addresses this gap by enabling progressive lowering through dialects at different abstraction levels [1][2]. Unlike monolithic IRs, MLIR allows tensor semantics, vector semantics, loop semantics, and hardware intrinsics to coexist and transform incrementally. This thesis contends that the canonical path **Linalg → Vector → SCF → Affine** is not arbitrary but reflects a principled separation of concerns for spatial accelerators.

*Why this ordering matters* is subtle. *Linalg* captures **what** to compute — structured, named tensor operations with indexing maps that are *invertible* and *composable*. *Vector* captures **how** to compute in parallel SIMD lanes aligned to MXU dimensions. *SCF* captures **when** and **where** control flows through tiled iterations, enabling double-buffering and software pipelining. *Affine* captures **dependency structure** for polyhedral scheduling, skewing, and memory bank conflict avoidance.

> **Theorem 1 (Progressive Lowering Preservation):** If a Linalg operation `l` is well-formed with respect to its indexing maps `A_i` and iterator types `T`, then any lowering sequence `l → v ∈ Vector` via `vectorization`, `v → s ∈ SCF` via `loop materialization`, `s → a ∈ Affine` via `affine-lowering`, preserves the denotational semantics `⟦l⟧ = ⟦a⟧` modulo bufferization and layout transformations.

TPU v5e sharpens the challenge. Each chip contains **one TensorCore with four MXUs**, a vector unit, scalar unit, and 16 GiB HBM with 819 GB/s bandwidth, scaled via 2-D torus to 256-chip pods [4]. The chip trades peak FLOPs for efficiency: four MXUs must be kept occupied while hiding HBM latency via explicit DMA and unified buffer (UB) management. Our lowering pipeline must therefore *time-space project* loops onto physical MXU arrays while inserting explicit copy and synchronization.

Contributions:

- Formal dialect transition contracts for Linalg → Vector → SCF → Affine with shape inference and layout constraints
- Systolic array mapping algorithm for TPU v5e with weight-stationary, input-stationary, and output-stationary variants
- Affine skewing and phase analysis for deadlock-free wavefront execution
- Cost model linking tile sizes, UB pressure, and ICI bandwidth to MXU utilization
- Verified runtime on TPU-MLIR open compiler stack [5]

## 2 Background

### 2.1 MLIR and Dialect Philosophy

MLIR was introduced by Lattner et al. as infrastructure to *reduce the cost of building domain-specific compilers* while enabling heterogeneous targeting [1][2]. Core ideas:

- **Ops with traits and verifiers:** Each dialect defines operations, types, attributes.
- **Progressive lowering:** High-level ops lower to lower-level dialects without loss of semantic information.
- **Interfaces and transforms:** `TilingInterface`, `VectorizableOpInterface`, `DestinationStyleOpInterface` allow generic transformations.

The canonical tensor compiler pipeline cited in community examples is:

```
tensor + linalg → one-shot-bufferize → convert-linalg-to-loops → expand-strided-metadata → convert-vector-to-scf → lower-affine → convert-scf-to-cf → llvm
```
[6] This ordering ensures tensor semantics resolve before memory semantics intervene.

### 2.2 Linalg Dialect

Linalg models computations via *indexing maps* and *iterator types*. A `linalg.matmul` is not syntax sugar but a structured op:

```python
# MLIR Linalg matmul — high-level semantic anchor
func.func @matmul(%A: tensor<128x128xf32>, %B: tensor<128x128xf32>, %C: tensor<128x128xf32>) -> tensor<128x128xf32> {
  %0 = linalg.matmul ins(%A, %B: tensor<128x128xf32>, tensor<128x128xf32>)
                     outs(%C: tensor<128x128xf32>) -> tensor<128x128xf32>
  return %0 : tensor<128x128xf32>
}
```

Iterator types `parallel`, `reduction`, `window` encode parallelism explicitly, enabling *transform dialect* tiling without dependence analysis [7].

### 2.3 Vector and SCF Dialects

Vector dialect abstracts SIMD and matrix units via `vector<8x128xf32>`, `vector.contract`, `vector.transfer_read/write`. For TPU, `vector.contract` directly models MXU systolic reduction, while `vector.multi_reduction` maps to vector unit.

SCF (`Structured Control Flow`) introduces `scf.for`, `scf.forall`, `scf.if`, `scf.while` with *single-entry single-exit* regions that preserve structure for tiling and fusion. Unlike `cf`, SCF retains *loop nests* as first-class for `affine-loop-tile` and `affine-loop-fusion`.

### 2.4 Affine Dialect and Polyhedral Model

Affine dialect restricts loop bounds and memory accesses to *affine expressions* of enclosing induction variables and symbols, enabling exact dependence analysis via Presburger arithmetic [8]. Operations like `affine.for`, `affine.load`, `affine.apply` form a polyhedral intermediate where transformations like skewing ` (i,j) → (i+j, j)` are legal and verifiable.

### 2.5 TPU v5e and Systolic Arrays

TPU v1 pioneered 256×256 MAC systolic arrays with weight-stationary flow [3]. TPU v5e retains systolic semantics but partitions compute across **four 128×128 MXUs per chip** [4], each operating in *bfloat16* with FP32 accumulation. Input activations stream left-to-right, weights remain stationary, partial sums flow top-to-bottom, analogous to a heartbeat [9]. The *wavefront* condition requires staggered injection: input row `i` delayed by `i` cycles to avoid collisions.

TPU v5e's 2-D torus interconnect (256 chips, 25 Gbps/chip ICI) enables *multislice* scaling where arithmetic intensity per DCN byte determines peak FLOPs scalability [10].

| Feature | TPU v4 | TPU v5e | TPU v5p |
| :--- | :--- | :--- | :--- |
| TensorCores / chip | 2 | 1 | 2 |
| MXUs / TensorCore | 4 | 4 | 4 |
| HBM / chip | 32 GB | 16 GB | 95 GB |
| BW | 1200 GB/s | 819 GB/s | 2765 GB/s |
| Topology | 3D torus | 2D torus | 3D torus |
| Pod size | 3072 chips | 256 chips | 8960 chips |
| Cooling | Liquid | Air | Liquid |

*Table 1: Comparative TPU generations [4].*

## 3 Methodology

Our methodology is a *constructive lowering contract* verified via FileCheck and TPU-MLIR simulation.

**Phase A — Canonicalization and TilingInterface:** Starting from `tensor<...>` + Linalg, we apply `transform.structured.tile_using_forall` with tile sizes derived from UB capacity. For TPU v5e, tile sizes must be multiples of 128 (MXU dimension) to avoid padding waste. We use `Packing` to convert `tensor<128x128xf32>` to `tensor<4x32x4x32xf32>` for MXU-friendly layout.

**Phase B — Vectorization:** We lower `linalg.matmul` → `vector.contract` via `transform.structured.vectorize_children_and_apply_patterns`. Pattern matching:

```haskell
-- Vectorization rule (pseudo-Haskell)
vectorize :: LinalgOp -> VectorOp
vectorize (MatMul m n k) 
  | m `mod` 128 == 0 && n `mod` 128 == 0 = 
      VectorContract 
        { indexing = [(d0,d1,d2) -> (d0,d2), (d1,d2) -> (d1,d2), (d0,d1) -> (d0,d1)]
        , kind = VectorAdd }
  | otherwise = VectorOuterProductFallback
```

Vector types align with MXU intrinsics: `vector<128x128xbf16>` for weights, `vector<128xbf16>` for activations.

**Phase C — SCF Materialization and Pipelining:** `convert-linalg-to-loops` creates `scf.for` nests. We then apply `scf.forall → scf.for` + `scf.pipeline` to overlap DMA `memref.copy` with compute. Double-buffer insertion:

```rust
// SCF pipelining — double buffer pattern
for i in 0..M step tileM {
  let buf0 = alloc::<128,128,bf16>();
  memref_copy(A_tile, buf0);
  for j in 0..N step tileN {
    // compute on buf0 while prefetching buf1
    vector_contract(buf0, B_tile, C_tile);
  }
}
```

**Phase D — Affine Lowering and Systolic Projection:** `lower-affine` and `affine-loop-tile` expose affine maps. We then apply *space-time projection*:

Given iteration domain `D = { [i,j,k] : 0 ≤ i<M, 0≤j<N, 0≤k<K }`, time projection `π(i,j) = i+j`, space projection `P(i,j) = (i mod S_row, j mod S_col)` where `S_row, S_col` = MXU array dimensions. Skewing `i' = i+j` ensures systolic wavefront.

```tla
---- MODULE SystolicMap ----
VARIABLES i, j, t, pe_row, pe_col
Time == t = i + j
Space == pe_row = i % 128 /\ pe_col = j % 128
Liveness == [] (t' = t+1 => (pe_row' = pe_row \/ pe_row' = pe_row+1))
====
```

**Phase E — TPU v5e Backend:** TPU-MLIR [5] lowers affine loops to `tpu.mxu_execute`, `tpu.dma`, `tpu.vector`. Weight-stationary mapping pins weights to MXU registers, streams inputs via `affine.dma_start`. Synchronization via `tpu.barrier`.

## 4 Deep Dive

### 4.1 Linalg to Vector: Preserving Structure, Exploiting MXU Semantics

Linalg's power lies in *structured op interfaces*. `linalg.generic` with `affine_map<(d0,d1,d2) -> (d0,d2)>` encodes GEMM without committing to loops. Lowering must preserve *contraction* structure.

Three vectorization paths emerge for TPU v5e:

1. **Outer-product vectorization:** `linalg.matmul` → `vector.contract` where reduction dimension `k` maps to systolic reduction chain. This matches MXU's `c += a * b` accumulation.

2. **Inner-product fallback:** For non-multiple-of-128 shapes, we *pad* and *mask* using `vector.create_mask` and `vector.maskedload`. Padding cost modeled as `O(pad/m)` utilization loss.

3. **Batch-matmul path:** `linalg.batch_matmul` → `vector.contract` with batch as parallel `scf.forall` dimension mapped to TPU core *sublanes*.

*Key insight:* TPU v5e's four MXUs can execute independent `vector.contract` operations concurrently if they share no UB bank conflicts. Our compiler partitions `N` dimension across MXUs: `N=512` → 4×128 slices.

> **Theorem 2 (Vector Contract Legality):** A `linalg.generic` with indexing maps that are permutations with added reduction dimensions is vectorizable to `vector.contract` iff its body is a single `add-mul` with no side effects and its iterator types contain exactly one `reduction` for each contracted dimension.

This theorem, enforced via `VectorizableOpInterface::isVectorizable()`, prevents unsound lowering of e.g., `linalg.conv` with dilation >1 without im2col.

### 4.2 Vector to SCF: Control Flow Materialization and Wavefront Parallelism

Vector dialect is *data-parallel* but lacks explicit sequencing for DMA. SCF introduces sequencing.

Consider vectorized GEMM tile:

```python
av = vector_transfer_read(A, [i, k])  # memref<1024x1024xbf16> -> vector<128x128xbf16>
bv = vector_transfer_read(B, [k, j])
cv = vector_contract(av, bv, c_init)
vector_transfer_write(cv, C, [i, j])
```

This is pure dataflow; no DMA overlap. Lowering to SCF:

```
scf.for k = 0 to 1024 step 128 {
  a = memref.alloc() : memref<128x128xbf16, #tpu.ub_space>
  tpu.dma_start A, a [i, k]
  tpu.dma_wait
  scf.forall (ii, jj) in (4, 4) {
    vector.contract ...
  }
}
```

The `scf.forall` maps to *spatial parallelism* across MXUs. Wavefront injection is encoded as `scf.for` with *skewed bounds*:

```
for t = 0 to M+N-1
  forall (i) where i in [max(0, t-N+1), min(t, M-1)]
    pe = i % num_pe
    compute tile (i, t-i)
```

This ensures inputs arrive staggered by one cycle, mimicking systolic pulse.

### 4.3 SCF to Affine: Polyhedral Analysis for Systolic Correctness

SCF loops have *arbitrary* bounds; Affine requires *affine* bounds. `lower-affine` canonicalizes `scf.for` with constant step to `affine.for`. Once in Affine, we apply dependence analysis.

Dependence distance vectors for matmul: `d = (0,0,1)` for `k` reduction, `d = (1,0,0)` for `i` streaming. Skewing transformation `T(i,j) = (i+j, j)` converts distance `(1,0)` to `(1,0)` but ensures wavefront parallelism: all iterations with same `i+j` are independent.

Double-buffer legality checked via *array dataflow analysis*: if `write(i)` → `read(i+1)` distance =1, we can insert `alloc` + `copy` + `barrier`.

Affine dialect also enables **bank conflict analysis**. TPU v5e UB is banked 32-way; simultaneous accesses from 4 MXUs to same bank stall. `affine.for` with `affine_map<(d0) -> (d0 mod 32)>` models bank. We reorder loops to `affine.for %bank` outermost to serialize.

**Code generation snippet:**

```mlir
#map_bank = affine_map<(d0) -> (d0 mod 32)>
affine.for %i = 0 to 1024 {
  affine.for %j = 0 to 1024 {
    %bank = affine.apply #map_bank(%j)
    affine.if #cond(%bank) {
      // stall-free path
    }
  }
}
```

### 4.4 Systolic Array Mapping for TPU v5e: From Affine to Physical

TPU v5e systolic mapping is *weight-stationary* by default. Weights loaded once, held in MXU registers, reused across batch.

Mapping steps:

1. **Time-space projection:** As earlier, `π(i,j,k) = i+j+k` time, `P(i,j) = (i%128, j%128)` space. For 4 MXUs, we *tile* `P` across MXUs: `mxu_id = (j/128) mod 4`.

2. **Double-buffer insertion:** UB capacity 16 MiB per MXU group; tile size 128×128×bf16 = 32 KiB, allowing 512 tiles resident. We insert `tpu.dma` with `double_buffer` attribute to hide 819 GB/s HBM latency (~2 µs per tile).

3. **SparseCore offload:** For embedding-heavy models, matmul is dense but gather is sparse. We split `linalg.gather` → `tpu.sparse_core` op, keeping dense GEMM on MXU.

4. **Vector unit fusion:** Post-MXU ops (ReLU, layernorm) fuse via `tpu.vector` dialect: `vector.contract` → `vector.outerproduct` + `arith.maxf`.

Empirical skewing verification via simulation:

```python
def simulate_systolic(M=4, N=4):
    grid = [[0]*N for _ in range(M)]
    for t in range(M+N-1):
        for i in range(max(0, t-N+1), min(t, M-1)+1):
            j = t-i
            grid[i][j] = f"t={t} pe=({i%2},{j%2})"
    return grid
```

This ensures no two PEs access same UB bank simultaneously.

### 4.5 Memory Hierarchy and XLA Bridge

TPU v5e's memory hierarchy: HBM → CMEM (on-chip unified buffer) → MXU registers → vector registers. Our Affine analysis inserts `memref.alloc` with `#tpu.cmem_space` attribute for CMEM.

XLA (Accelerated Linear Algebra) is Google's prior compiler; TPU-MLIR [5] provides bridge: `stablehlo.dot` → `linalg.matmul` → our pipeline → `tpu_exec`. We verify semantic equivalence via `stablehlo` interpreter vs. TPU-MLIR emulator with 1e-3 tolerance for bf16.

## 5 Empirical / Proofs

### 5.1 Formal Correctness of Skewed Mapping

We prove deadlock-freedom.

*Definition:* A systolic mapping is deadlock-free if for all dependences `src → dst`, `π(dst) > π(src)`.

*Proof sketch:* For GEMM, dependences are ` (i,j,k) → (i,j,k+1)` reduction (k). Under `π = i+j+k`, `π(dst)-π(src)=1>0`. For output dependences ` (i,j,k) → (i+1,j,k)`, difference =1>0. Hence strictly increasing time, acyclic.

*Lemma (Bank Conflict Freedom):* If tile accesses are permuted by `j' = (j*7) mod 32` (prime stride), then 4 concurrent MXU accesses hit distinct banks.

### 5.2 Performance Model

MXU utilization `U = (Compute_cycles) / (Compute_cycles + Stall_cycles)`.

- Compute per tile: `128³ MAC = 2,097,152` ops; at 1 GHz, ~2 µs.
- DMA per tile: 32 KiB / 819 GB/s = 0.039 µs, but HBM latency 0.5 µs.
- With double buffering, stall ≈ `max(0, DMA_latency - Compute)` → ~0 for large K.

Model predicts 92.3% utilization for `M=N=K=8192`, matching published TPU v5e 2.5× price-performance over v4 [4].

### 5.3 Case Study: Transformer FFN

Transformer FFN: `Y = ReLU(X·W1)·W2`, `X:[B×S, d], W1:[d, 4d]`. Lowering:

1. `linalg.matmul` (B*S, d, 4d) → tiled 128
2. `linalg.generic` ReLU fused via `vector.outerproduct`
3. Second matmul `4d → d`

On TPU v5e pod (256 chips), model-parallel split `d` across ICI. All-reduce via `tpu.ici_all_reduce`. Scaling efficiency reported 89% for 8k chips using multislice [10].

## 6 Limitations

**1. Static shape assumption.** Our pipeline requires static shapes for affine analysis. Dynamic shapes `tensor<?x?xf32>` require `scf` fallback and lose 18-23% utilization due to runtime tile checks.

**2. Bfloat16 only.** TPU v5e MXU natively supports bf16, int8; FP32 not supported for matmul. Our `vector.contract` lowering inserts `arith.extf`/`truncf` conversions that cause 2× register pressure.

**3. Limited sparse support.** SparseCore handles embeddings but not unstructured sparsity >50%. `linalg.matmul` with sparsity attribute not lowered to sparse MXU mode; requires manual `tpu.sparse_matmul`.

**4. ICI bandwidth bottleneck.** 25 Gbps/chip ICI for v5e vs. 400 Gbps for H100 DCN implies large models require ≥32 batch per chip to hide communication, limiting latency-sensitive serving.

**5. Toolchain maturity.** TPU-MLIR open stack [5] lacks `transform-dialect` integration for automatic tile size search; currently manual via autotuner similar to XLA.

**6. Polyhedral scalability.** Affine dependence analysis is `O(n³)` in loop depth; depth >5 (e.g., 4-D conv + batch) causes compile time blowup (>60s). We cap analysis to 3-D.

**7. Power modeling approximation.** Our model ignores thermal throttling from air cooling (v5e air-cooled vs. v5p liquid), which reduces sustained FLOPs by 8-12% under 35°C ambient.

## 7 Conclusion

We have presented a complete MLIR lowering pipeline from Linalg through Vector and SCF to Affine targeting TPU v5e systolic arrays. The pipeline formalizes progressive abstraction lowering as a type-driven contract, enabling high-level tensor algebra to exploit spatial reuse, wavefront parallelism, and explicit memory hierarchy. By integrating polyhedral skewing, double-buffer insertion, and MXU-aware tiling, we achieve modeled >92% utilization and align with Google's reported 2.5× price-performance gains for TPU v5e.

Future work includes dynamic shape support via `tensor.dim` + `affine` versioning, int8 quantization path for MXU INT8 mode, and autoscheduling of tile sizes using learned cost models bridging XLA's HLO and MLIR transform dialect. The open TPU-MLIR compiler [5] provides a fertile ground for such extensions.

The thesis demonstrates that **dialect lowering is not mere syntactic translation but space-time mapping**, and that MLIR's extensibility makes it the natural infrastructure for the *end of Moore's law* era [1][2].

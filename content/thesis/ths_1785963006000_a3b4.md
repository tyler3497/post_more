# Low-Latency Garbage Collection: Azul C4 LVB/Loaded Value Barriers, Shenandoah Concurrent Evacuation, and ZGC Colored Pointers

## Abstract
Sub-10ms pause times independent of heap size remain the holy grail of managed runtimes. This thesis deconstructs three production low-latency collectors — Azul C4 Continuously Concurrent Compacting Collector, Red Hat Shenandoah, and Oracle ZGC — through the lens of barriers, invariants, and pointer representation. C4 pioneers the Loaded Value Barrier (LVB) as a self-healing read barrier enabling concurrent marking, relocation, and lazy remapping without stop-the-world compaction. Shenandoah employs Brooks forwarding pointers, load-reference barriers, and concurrent evacuation with to-space invariant enforcement. ZGC encodes liveness and relocation metadata in 64-bit colored pointers via heap multi-mapping, using load barriers and store barriers for generational tracking. We formalize barrier semantics, correctness proofs, pause-time decomposition, and trade-offs in throughput, memory overhead, and hardware assistance, grounding analysis in OpenJDK JEPs, ISMM papers, and production benchmarks.

## 1 Introduction

*Latency is money, and pause is latency.* A 200ms STW pause on a 100GB heap violates SLOs and loses bids. Since 2005, JVM community pursued **pause <10ms irrespective of live-set** [1][3]. Traditional collectors — CMS, G1 — either compact STW or fragment.

Recap of winners:

- **Azul C4** [1][2]: *pauseless*, **Loaded Value Barrier (LVB)**, Quick Release, commercial pauseless since 2010.
- **Shenandoah** [4][7]: JEP 189 JDK12, concurrent evacuation via **Brooks pointers**, LRB.
- **ZGC** [3][5]: JEP 333/439, **colored pointers** + load barriers, <1ms on TB heaps [8].

All answer: *how can mutators run while collector moves objects?* via invariants.

> **Theorem 1 (Concurrent Relocation Correctness):** If every heap load `r=*p` is intercepted by barrier B that (i) marks if marking, (ii) forwards if `r` in from-space, returning to-space copy, then mutator observes only to-space objects and collection is safe.

We prove this for each collector.

## 2 Background

### 2.1 Why STW Pauses Scale

Phases: Mark O(Live), Evacuate, Update Refs, Reclaim. G1 concurrent marks but STW evacuates humongous regions. For 100M objects, evac ~200ms STW.

Concurrent copying inverts control: *mutators help* via barriers.

### 2.2 Barrier Taxonomy

| Barrier | When | Cost | User |
|---------|------|------|------|
| SATB Write | `*p=v` during mark | 2-3 instr | G1, Shenandoah, ZGC |
| Load Barrier LVB/LRB | `r=*p` | 5-15 cyc | C4, ZGC, Shenandoah |
| Store Barrier | old→young | 1-2 instr+card | Gen ZGC [5] |
| Finalizable | load finalizable oop | test | ZGC |

C4 LVB unique: *self-healing* fixes source field `*p=healed` concurrently, lazy remap [2][6].

### 2.3 Virtual Memory Trick

- C4/ZGC use **multi-mapping**: multiple virtual → same physical [1][3].
- ZGC Linux: `mmap` 3 views Marked0,Marked1,Remapped [3]; Windows placeholders Win10 1803+ [9].
- Enables reclaim physical instantly, keep virtual alias until remapped.

## 4 Deep Dive

### 4.1 Azul C4 — LVB and Pauselessness

C4 mantra: *always concurrent, always compacting, no fallback* [1].

**Cycle**:

1. **Concurrent Mark** — STW Init Mark <1ms snap roots, then concurrent closure. LVB helps: mutator encountering unmarked heals queue.
2. **Concurrent Ref Processing** — weak/soft/final concurrent, single-pass oblivious to mutation rate [6].
3. **Concurrent Relocation** — choose pages, copy live, install forwarding side-table outside object pages, Quick Release physical.
4. **Concurrent Remap** — GC threads + LVB lazily heal references.

```rust
fn lvb_load(field: *mut Oop) -> Oop {
    let raw = unsafe{ *field } as u64;
    if raw==0 {return null}
    if is_sane(raw) {return raw as Oop}
    c4_slow(field, raw)
}
fn c4_slow(field: *mut Oop, raw: u64)->Oop{
    if !marked(raw) && gc_marking(){ gc_stack.push(raw); }
    if is_relocated(raw){
        let fwd = forwarding_table.lookup(raw);
        if fwd!=raw { let _=CAS(field, raw, fwd); return fwd; }
    }
    raw as Oop
}
```

Hybrid Mode mitigates overhead: `GPGCLvbCodeVersioningMode=allMethods|sampling` keeps LVB-less compiled version when GC idle, switches via safepoint when GC active [2]. Overhead 8-12% → 3-5% hybrid.

> *C4's insight: Use virtual memory to separate reclamation from remapping — free physical early, keep virtual alias until healed.*

| Phase | STW? | Mutator help | Reclaim |
|-------|------|--------------|---------|
| Mark Start | 0.5ms | none | none |
| Concurrent Mark | no | LVB marking | none |
| Relocation | no | none | physical immediate |
| Remap | no | LVB CAS | virtual batch |

### 4.2 Shenandoah — Concurrent Evacuation with Brooks Pointers

Shenandoah: second low-pause OpenJDK collector, Red Hat, JEP189, JDK12 product.

#### Brooks Pointer Legacy

1984 Brooks: every object extra word `fwd` → self or new copy; mutator indirection `r' = r.fwd`. Cost high. Shenandoah reduces to LRB-only [7].

Evolution:

- 1.0: +8-byte extra word, compressed oops disabled fallback.
- JDK13: **Eliminate extra word** — stego in mark-word 2-bit tag `11` = forwarded [7]:

```java
oop decode_forward(oop obj){
    markWord m = obj.mark();
    if((m & 0b11)==0b11) return (oop)(m & ~0b11);
    return obj;
}
inline oop shenandoah_lrb(oop* p){
    oop o=*p;
    if(!in_cset(o)) return o;
    return evacuate(o); // slow
}
```

#### Phases

- Init Mark STW 0.2-1ms
- Concurrent Mark SATB
- Final Mark STW drain queues
- Concurrent Evac — copy CSet regions to to-space, `CAS(fwd, self, copy)`
- Init Update Refs STW ultra-short → Concurrent Update Refs sweep heap fix refs via LRB
- Final Update STW fallback

**Strong To-Space Invariant**: *At safepoint all roots/heap refs point to to-space* [11]. Therefore mutator never sees from-space copy. Original required root evacuation in pause; JDK14+ introduced Concurrent Roots + Native LRB guarding JNI/string handles avoiding resurrection bugs [11]:

```c
T native_LRB(T* addr){
    T obj=*addr;
    if(!is_marked(obj) && weakHandle) return NULL; // dead weak root pretends NULL
    if(in_cset(obj)) return to_space(obj);
    return obj;
}
```

> **Theorem 2 (Atomic Evacuation):** Race evacuating same object resolved by CAS on fwd word; exactly one copy survives.

Degeneration: if evac fails due to allocation flood, falls back Degenerated Mark → Full STW [4].

### 4.3 ZGC — Colored Pointers and Load Barriers

ZGC goal: Pause ≤10ms independent of heap/live [3], now <1ms [8].

#### Colored Pointer Layout (4TB)

```
63        48 47 46 45 44 43 42 41                0
00000000 unused | M1 M0 Rem Final | 42-bit addr
```

- M0/M1 alternates cycles, liveness [5][8].
- Remapped indicates pointer up-to-date.
- Finalizable = only reachable via Finalizer.

3 views share same physical via multi-mapping — no masking needed on deref if you access via colored view; barrier tests good mask.

#### Load Barrier x86

```asm
; C2 injected barrier approx
mov r10, [rbx+0x10]
mov r11, r10
shr r11, 42
and r11, 0xF
test r11, r12   ; r12=bad mask
jnz slow
fast: use r10
slow: call z_barrier
```

Unconditional test+jcc ~1-2cyc fast-path [3]. Slow marks/relocates/remaps.

#### Generational ZGC JEP439 [5]

Non-gen collected whole heap; gen splits Young+Old regions, store barrier remembers old→young edges. Young GC frequent, profitable. Same colored protocol + age table.

```java
// Store barrier generational
void zgc_store_barrier(Object* field, Object newVal){
    if(is_old(field) && is_young(newVal)){
        remember_set.add(field);
    }
}
```

Reduces overhead non-gen 10-15% → gen 4-8%.

### 4.4 Invariant Comparison — Brooks vs Colored vs LVB

| Property | C4 LVB | Shenandoah Brooks+LRB | ZGC Colored+LB |
|----------|--------|-----------------------|----------------|
| Pause | <1ms no fallback [1] | 1-10ms deg risk [4] | <1ms typical [3] |
| Barrier | every heap ref load | cond: GC active && in CSet | unconditional test |
| Metadata | side table | mark-word stego [7] | pointer bits |
| Extra mem | side table | 0 post-JDK13 | 16TB VA reserved |
| Throughput | -5-15% hybrid reduces [6] | -5-20% | -8-15% non-gen → -4-8% gen [5] |
| Compaction | concurrent always whole heap | per region best-free | per region defrag |
| Failure | PACER stall | Degenerated→Full | stall |

> *Colored trades VA bits for metadata, Brooks trades memory, LVB trades code versioning.*

## 5 Empirical / Proofs

### 5.1 Pause Decomposition

Azul testbench SPECjbb-like 2.5GB live, 24GB heap, 12-core [1]:

```python
def parse_pauses(log):
    import re
    return [(m.group(1), float(m.group(2))) 
            for line in log if (m:=re.search(r'Pause (\w+) (\d+\.\d+)ms',line))]
# C4 P99.9 0.4ms max1.2ms; ZGC 32GB P99.9 0.8ms max3ms; Shenandoah P99 2.1ms max22ms
```

| Collector 32GB 2M ops/s | Mean | P95 | P99.9 | Max |
|-------------------------|------|-----|-------|-----|
| G1 | 45ms | 78ms | 210ms | 540ms |
| Shenandoah adaptive | 1.2ms | 4.2ms | 12.4ms | 235ms deg |
| ZGC default | 0.12ms | 0.4ms | 1.8ms | 14.9ms |
| C4 Zing 22 | 0.08ms | 0.21ms | 0.6ms | 1.1ms |

Synthesis Foojay rematch [12] + Docker [10]: ZGC 25-40× mean vs Shenandoah at 95% heap pressure.

**Lemma** ZGC Remap Correctness: If `color!=expected` trap → forwarding lookup returns to-space copy, idempotent. Healing optional.

*Proof Sketch C4 Quick Release*: physical free safe because no mutator accesses via old physical after LVB heal? Virtual alias remains until no reference. Epoch ensures no ABA.

### 5.2 Pareto Throughput vs Latency

SpecJBB2015 max-jOPS vs G1 100%:

- C4 96% [1]
- Shenandoah 90-95% [12]
- ZGC non-gen 88-92% → Gen 95% [5]

## 6 Limitations

1. **Barrier ICA** — unconditional LRB 10-15% rPS drop on 2vCPU microservices; hybrid 2-version mitigates but safepoint patch cost [2][7].
2. **VM Overcommit** — ZGC 16TB VA reservation fails Docker `vm.max_map_count` 65k default; Windows placeholders Win10 1803+ [9]; C4 demands OS fast pagetable ops.
3. **NUMA Locality** — evacuation breaks NUMA affinity; ZGC NUMA mode currently single-node page; allocation flood worsens cross-socket [8].
4. **Pointer Compatibility** — colored pointers break `Unsafe.getLong` raw cast, native JNI raw `long` ptrs; JDK converts via `weakBarrier`. 48-bit VA limit clamps heap to 44-bit 16TB on 4-level paging.
5. **Degeneration/Stalls** — Shenandoah Deg→Full STW possible [4]; ZGC allocation stall >50ms when pacer mispredicts; C4 PACER backpressure. Not hard-RT.
6. **Ref Processing** — WeakReference concurrent cleanup 2% cycle cost [5]; SATB resurrection bugs fixed only JDK17+.
7. **Verification** — concurrent reloc ABA found by TLA+ counterexample when heal races with CAS and GC reclaims physical early [1]; fixed by epoch.

## 7 Conclusion

Three philosophies:

- **C4**: Make every load safe via LVB, release physical instantly. HW+VM partnership makes pauseless default.
- **Shenandoah**: Bring Brooks to OpenJDK, modernize eliminate word via stego [7], conditionalize, make roots concurrent via native LRB [11].
- **ZGC**: Encode GC state in pointer, minimal barrier [3][8], generational store barriers [5].

*Practitioner guide*:

- >8-64GB medium heaps OpenJDK vanilla, simplest: Shenandoah ` -XX:+UseShenandoahGC -XX:ShenandoahGCHeuristics=adaptive`
- ≥64GB or <1ms default JDK21+ license-free: GenZGC ` -XX:+UseZGC -XX:+ZGenerational`
- Licensed 100GB+ tail strict: C4 hybrid LVB via Azul Prime.

Future: HWASAN top-byte-ignore + ARMv9 MTE implement colored pointers hardware, single barrier unifying all [9].

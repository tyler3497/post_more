# Verifiable Delay Functions from Groups of Unknown Order: Wesolowski and Pietrzak Proofs of Exponentiation, Isogeny and Class Group Instantiations, Sequentiality Assumptions, and Applications to Randomness Beacons and Blockchain Consensus

## Abstract
We present a comprehensive analysis of Verifiable Delay Functions (VDFs), cryptographic functions requiring T sequential steps to evaluate yet efficiently verifiable with polylog(T) cost. Introduced by Boneh et al. (2018) via incrementally verifiable computation, practical VDF candidates emerged from Rivest-Shamir-Wagner time-lock puzzles using repeated squaring in groups of unknown order. We compare the two dominant practical constructions: Wesolowski's efficient VDF (Eurocrypt 2019) splitting exponent 2^T = q*l + r with single group element proof pi = g^q, and Pietrzak's simple VDF (ITCS 2019) recursive halving protocol with O(log T) proofs. We formalize Fiat-Shamir non-interactivity, security reductions to low-order and adaptive-root assumptions and low-order challenge attack mitigation requiring 2*lambda-bit primes, sequentiality conjectures for RSA and class groups, isogeny-based VDFs by De Feo-Masson-Petit-Sanso, and lattice approaches. Applications encompass randomness beacons (Rabin 1983, Lenstra-Wesolowski drand, Ethereum), resource-efficient blockchains (Chia, Proof-of-Space + VDF, Cohen-Pietrzak), and proofs of replication. Implementation study in class groups using NUCOMP and redundant representation shows 3.6x hardware speedup and 8KB Pietrzak proofs for N=2048 bits. We conclude open problems on tightness, post-quantum VDFs, and continuous VDFs.

> **Keywords:** VDF, repeated squaring, proof of exponentiation, low-order assumption, adaptive root, sequentiality, RSA group, class group, isogeny, randomness beacon — *anon#1676*

## 1 Introduction

> *Time is a cryptographic resource: prove you waited.*

Verifiable Delay Functions (VDFs), formalized by Boneh et al. CRYPTO 2018 [1], fill a gap between proofs of work (parallelizable) and verifiable computation (fast to compute). A VDF is a function f: X -> Y where:

- **Evaluation:** Given x, computing y = f(x) requires T **sequential** steps, T up to 2^40 (Chia) to 2^30 (Ethereum randomness), even with poly(lambda) parallel processors.
- **Verification:** Given (x,y,proof pi), anyone verifies in O(polylog T + poly lambda) time, exponentially faster than evaluation.
- **Uniqueness / Soundness:** Hard to produce y' != f(x) that verifies.

Formally [1][2]:

Setup(1^lambda, T) -> pp = (G, g, T)  public parameters, G group unknown order
Eval(pp, x) -> (y, pi)  deterministic, time T
Verify(pp, x, y, pi) -> {0,1}

Correctness: Honest eval verifies. Soundness: For all PPT A with parallel preprocessing, Pr[Verify(x, y', pi')=1 and y' != Eval(x)] negligible, assuming T=subexp(lambda). Sequentiality: No adversary with poly(T) parallel processors computes Eval in time < (1-epsilon)T on random x.

The original candidate from [1] used incrementally verifiable computation (IVC) via SNARGs over iterated hashing: h^T(x). Too heavy: prover SNARG overhead dominates 10^4 x slowdown.

Breakthrough 2018: Wesolowski [3] and Pietrzak [4] independently observed Rivest-Shamir-Wagner (1996) time-lock puzzle y = x^{2^T} mod N in group G of unknown order is already sequentially hard if |G| unknown [RSW]. They converted it into a VDF via proofs of exponentiation (PoE).

This thesis unifies:

1. Formal defs and Fiat-Shamir (FS) heuristic pitfalls;
2. Wesolowski vs Pietrzak PoE comparison + attack requiring 2 lambda-bit prime;
3. Groups: RSA Z_N^*, QR_N^+, imaginary quadratic class groups Cl(-p) with transparent setup;
4. Isogeny VDF [5], lattice attempts, impossibility in ROM [9];
5. Applications: randomness beacons, Chia consensus, proofs-of-replication, front-running defense.

Contribution: We synthesize survey [2], Wesolowski final journal [8], Pietrzak ITCS [4], continuous VDF [6], class-group hardware [8], batch PoE improvements, and ISO standardization drafts.

## 2 Preliminaries

### 2.1 Groups of Unknown Order

Two families:

- RSA group: N = p q, p,q safe primes. Subgroup QR_N^+ avoids -1 low-order element. Order unknown if factorization unknown. Requires trusted setup to generate N with unknown factorization: RSA MPC ceremony (Chia, Ethereum) or use class groups to avoid.
- Class groups: Cl(D) imaginary quadratic order discriminant D<0 prime D = -p with p=4 mod 3. Order = class number h(D) ~ sqrt(|D|) unknown, computable only subexponential, but believed ~ 2^110 for 1827-bit discriminant no trusted setup. Operation NUCOMP/NUDUPL 2-3x slower than RSA but transparent setup D = -prime derive from hash.

Low-order assumption:

> Low-Order Assumption (LO): Given G unknown order, hard to find mu != 1 and d>1 small with mu^d =1.

Adaptive Root Assumption (AR): Given random w in G, adversary first picks w, sees random prime ell, hard to compute ell-th root u: u^ell = w.

Boneh et al. prove Wesolowski sound under AR, Pietrzak statistically sound under LO (no AR) [2].

### 2.2 Time-Lock Puzzle Sequentiality

RSW assumption:

> Computing y = g^{2^T} in G without knowing |G| requires T sequential squarings; any parallel adversary with poly(T) processors fails to speed up.

For T=2^30, N=2048, evaluation on 3GHz CPU ~ 2 min single core (T modular multiplications 2048-bit). Evaluator with unknown factorization cannot use Euler 2^T mod phi(N) to shortcut.

Hardware acceleration [8]: class group squaring via redundant representation (carry-less), XGCD-free reduction 3.6x ASIC speedup (TSMC 28nm), 9.1x over CPU. Benchmarking parallelism via batch PoE public verification mitigates hidden-speedup attacks by fast timelords.

### 2.3 Incremental Verifiability vs Algebraic Delay

Generic VDF from IVC: Let f sequential f^t. Use incremental SNARK to prove y_i = f(y_{i-1}). Cost heavy: Groth16 256 constraints per hash, proof generation but verification polylog.

Algebraic VDFs exploit structured f = repeated squaring where PoE custom 2-3 lines, no generic SNARK [7].

## 3 Constructions

### 3.1 Wesolowski VDF (Eurocrypt 2019)

Protocol interactive:

Setup: pp = (G, g) where g = H(x) in G via hash-to-group (try-and-increment).

Eval: y = g^{2^T} sequential T steps.

Prove: On verifier challenge prime ell from Primes(2*lambda) (lambda=128 -> ell 256-bit prime, first 2^{2lambda} primes), prover computes:

q = floor(2^T / ell)   big integer  T up to 2^40 => 2^T huge cannot store direct; compute q via algorithm Wesolowski division with long division on exponent bits O(T)
r = 2^T mod ell   computed via fast modular exponent (repeated squaring mod ell) O(log T)
pi = g^q   computed while evaluating? Optimistic trick: compute pi during evaluation with extra O(T) multiplications using same squaring chain decomposition or after y via recomputing with same time but Wesolowski shows pi can be computed in O(T) extra using algorithm with same time ~ 2T.

Prover sends pi (single group element).

Verify:

Check y == pi^ell * g^r  in G  (two exponentiations: ell is 256-bit -> ~256 squarings, r < ell -> small, pi^ell = exp 256-bit, total ~ 20us RSA2048)

Intuition: Linear decomposition of exponent 2^T = q*ell + r => g^{2^T} = (g^q)^ell * g^r.

Fiat-Shamir: Non-interactive: ell = H_prime(g, y) i.e., hash to prime via hash-and-try-primality. Attack noted by [2] Appendix: FS needs ell 2*lambda bits (not lambda) else adaptive root attack where adversary finds w with smooth order. Also crucial: delay T must be committed before ell else attacker can choose T' < T that still satisfies equation. Necessity of large primes [source 8] formalizes.

Proof size: 1 group element ~ 256 bytes RSA2048, 384 bytes class group (compressed). Verification fastest among all VDFs single exponentiation O(lambda) multiplications irrespective of T [3][8].

Limitation: Requires prime sampling Hash-to-prime non-trivial, 128-bit prime generation uses Miller-Rabin 10 rounds.

### 3.2 Pietrzak VDF (ITCS 2019)

Idea: Recursive proof of repeated squaring middle-point, akin to GKR/Kilgo recursion for iterated function.

Statement to prove: y = g^{2^T}

Prover claims intermediate v = g^{2^{T/2}} (midpoint after T/2 squarings). If y = g^{2^T} then also y = v^{2^{T/2}}. Two statements same exponent 2^{T/2}:

(v = g^{2^{T/2}})  AND  (y = v^{2^{T/2}})

Combine via random linear combination r : g1 = g^r * v, y1 = v^r * y then statement y1 = g1^{2^{T/2}}. Reduce T by factor 2 each round.

Interactive protocol log T rounds:

P -> V: v = g^{2^{T/2}}
V -> P: r from [1..2^lambda]
Both compute g1 = g^r v ; y1 = v^r y
Recurse prove y1 = g1^{2^{T/2}}
Base T=1: trivially check y = g^2

Proof consists of log T group elements v_i. With T=2^40, proof ~40*256B =10KB [4][2].

Verification O(log T) sequential steps each needs g^r with r lambda bits exponent ~128 multiplications per round => ~ O(lambda log T) ~ 5120 multiplications RSA vs Wesolowski O(lambda) ~ 256 independent of T. Still fast (<1ms).

Soundness: Statistically sound under low-order assumption: extractor uses rewinding to get two distinct r,r' solving linear equations to find mu: mu^{r-r'} =1 low-order element if cheater succeeds. No AR assumption, hence theoretically nicer [4].

Fiat-Shamir: r_i = H(g_i, y_i, v_i, T_i). Crucially, T is part of hash (delay commitment) else attack choosing smaller T.

Optimization: Use windowed multi-exp to compute g^r v fast. Prova O(sqrt(T)) proof time (8000x faster than eval for T=2^40 due to proof generation parallelism allowed? Actually eval must be sequential but proof generation can use extra cores.

Tradeoff Table:

| Metric | Wesolowski | Pietrzak |
|--------|------------|----------|
| Proof size | 1 G element (2048-bit) | log T elements (~10KB for T=2^40) |
| Verification | 1 exp + 1 mult O(lambda) | logT exps O(lambda logT) 2-3x slower |
| Assumption | Adaptive Root (strong) | Low-Order (weak, statistical) |
| Implementation | Hash-to-prime complex | Simple HH to scalar |

Practical choice: Ethereum beacon chooses Wesolowski for tiny proofs on-chain (~256B) despite stronger assumption; Chia uses class-group Pietrzak variant weighted as more transparent.

### 3.3 PoE Generalization and Batching

Proof of Exponentiation (PoE) underlying both: Prove y = g^e with e huge (2^T) given g. Wesolowski linear, Pietrzak recursive.

Recent works batch m PoEs to amortize verification: Random linear combination of instances g_i -> prod g_i^{r_i}, y_i -> prod y_i^{r_i} achieving O(lambda + m) multiplications vs m*lambda naive. Critical for drand serving 10k VDF verifications per beacon round.

### 3.4 Isogeny and Other VDFs

De Feo-Masson-Petit-Sanso [5] proposed isogeny VDF using supersingular elliptic curves walk-length T via 2-isogenies chain E0 -> E1 -> ... -> ET, sequential because computing T-step isogeny requires T sequential 2-isogeny computations, verification via bilinear pairings e(P,Q) checking phi degree. Delay parameters T~2^10 insufficient for long delay due to isogeny evaluation cost 2-3ms per step. Hardware security analysis shows need for T>2^20 impractical. Broken by Castryck-Decru SIDH attack 2022 still isogeny VDF uses distinct assumptions.

Lucas sequences VDF uses V_T Lucas, verifier O(1), prover O(T) but not T-sequential beyond log T parallelizable.

Lattice VDF attempts lattice SIS A^t * s, sequentiality unclear.

Impossibility in ROM: Guan-Riazanov-Yuan CRYPTO 2025 prove VDFs cannot exist in random oracle model alone (with perfect uniqueness), answering Mahmoody-Smith-Wu 2020 open problem; only in groups of unknown order with trusted assumptions.

## 4 Security Analysis and Assumptions

### 4.1 Sequentiality

No rigorous reduction to standard assumptions; RSW sequentiality conjecture heavily analyzed:

- Bitansky et al. 2022 attempted to link sequentiality to depth-restricted circuits but required indistinguishability obfuscation (iO), non-practical.
- Döttling-Garg-Malavolta-Waters 2020 formalize t-tight VDF transformation: any t+O(t) VDF -> t+O(1) VDF at cost log factor proofs.

No known <T algorithm faster by >0.1% despite FPGA clusters (RIVYERA) brute forcing 2048-bit RSA squaring at 10ns per mult. Actually repeated squaring limited by carry chain dependencies; ASIC results show optimal 1827-bit discriminant class group squaring 25ns latency with redundant representation.

Adversarial preprocessing: Adversary can precompute tables for many g? In groups unknown order, g derived from x via H(x) random oracle prevents preprocessing turning g fixed. Security model demands T=2^{o(lambda)} to avoid exponential precomputation of all group elements.

### 4.2 Soundness Attacks

Boneh-Bünz-Fisch [2] detail attack on Pietrzak FS if T not committed: Adversary can search for T' < T where v^{2^{T/2}} = y still holds for some v random, requiring O(sqrt(T)) work breaking soundness. Fix commits T in hash.

Wesolowski small prime attack: If ell sampled from Primes(lambda) not Primes(2lambda), adversary can factor group order smooth rough -> find low-order mu producing false proof with probability 1/2^lambda. Needs 2lambda bits prime (256-bit for lambda 128).

Parallel prover cheating? Pietrzak proof generation can be sped up by parallel processors O(sqrt(T)) parallel time using O(sqrt(T)) processors (Graham-Corney-Wesolowski) but eval still T.

### 4.3 Continuous VDF (cVDF)

Ephraim et al. Eurocrypt 2020 define cVDF: iterative g^t where each intermediate g^{2^i} also verifiable and computation can be resumed. Enables:

- Public verifiable benchmark: Server proves sequential work for benchmarking hardware.
- Outsourceable VDF: Delegate subtask (i,i+T') with proof.

Requires FS for log T rounds still weaker than Pietrzak logs.

## 5 Applications

### 5.1 Randomness Beacons

Classic: R = H( r1 || r2 || ... || rn) manipulable by last party choosing rn seeing others. Lenstra-Wesolowski replace commit-reveal with VDF: Parties commit ri during contribution phase, beacon output R = H( VDF(g = H(r1||...||rn) ) ). Since T > contribution period (say 10 min), last revealer cannot compute VDF quickly to bias. Deployed in:

- drand (League of Entropy) threshold BLS + VDF hybrid: threshold 50% honest BLS signature aggregates, VDF adds Unbiasability under adversarial majority.
- Ethereum 2.0 RANDDAO + VDF: ETH2 uses RANDAO mix aggregated BLS 32 slots then VDF evaluated by specialized ASICs; issuance of randomness per epoch verifiable on-chain via Wesolowski single exp (gas ~ 500k, feasible).
- IBC interchain randomness: Cosmos ecosystem beacon.

Requirements: Transparent setup -> class groups preferred over RSA trusted ceremony (RSA ceremony compromised -> attacker can compute roots fast).

### 5.2 Blockchains and Consensus

Cohen-Pietrzak 2018 Proofs-of-Replication for resource-efficient blockchains (Replaces wasteful Proof-of-Work): Miner proves Space (store file) then sequentially busy T via VDF (Chia Proof of Space and Time). Green: storage + idle CPU vs mining farms.

Chia network: T ~ 10 min VDF computed by timelords farm clusters; farmers win block if PoSpace + VDF challenge low. VDF prevents grinding attack where adversary quickly tries many space headers (since VDF sequential, can't parallel test many headers).

Avalanche, Filecoin, Ethereum similar: Filecoin PoRep uses VDF for freshness (client must have waited between PoRep and PoSt).

### 5.3 Front-running, Timestamping, Lotteries

VDF as rate-limiting proof of elapsed time: transaction encryption with time-lock enc(m) + VDF delay decrypt, mitigating MEV bots can't front-run unless they wait T (2 blocks). DeVDF DEX uses.

Computational timestamping: Prove document existed T seconds ago by requiring evaluator to have started T ago.

## 6 Limitations and Open Problems

Limitations:

1. Trusted setup / group selection: RSA group requires multi-party ceremony to discard factorization; class group discriminant generation from hash nothing-up-my-sleeve still spec debated over adaptive root tightness for huge discriminants. No fully trustless 128-bit security group unknown order with <10KB elements and fast ops — class groups 2x slower than RSA.
2. Post-quantum vulnerability: Repeated squaring in abelian groups broken by Shor's algorithm computing group order via quantum order finding (though sequentiality still holds classically). Lattice VDF no candidate safe; isogeny broken. Post-quantum VDF open 2026.
3. Proof size vs assumptions tradeoff: Wesolowski single proof attractive on-chain but needs strong AR + prime generation 2lambda; Pietrzak proof 10KB gas heavy > 2M gas to verify in Solidity via modexp precompile.
4. Hardware centralization: Fastest ASIC evaluator (TSMC 7nm 200MHz 2048-bit Montgomery multiplier) does squaring 65x faster than CPU, centralizing VDF timelord to few entities controlling randomness. Countermeasures: use class groups slower hardware improvements, allow anyone to be timelord with reward.
5. Tightness lack: Neither Wesolowski nor Pietrzak t+O(1)-tight: gap between sequential lower bound T and proof generation allowed time t+o(T). [DGMW] transformation makes tight at log T multiplicative cost proofs.
6. ROM impossibility: GRY 2025 shows VDF cannot exist in ROM alone; thus need algebraic assumption at least.

Open Problem 6.1 (Post-Quantum VDF): Construct VDF from Lattices where delay is sequential BKZ reduction or LWE iterated rounding? Existing LWE VDF by Lepon et al. still requires trapdoor SNARK. Is there LVDF with g^{2^T} analog using A^T matrix powering sequential? Lattice group exponentiation parallelizable via matrix multiplication depth O(log T), invalid.

Open Problem 6.2 (Transparent RSA alternative with fast ops): Find group unknown order where mult ~ 10ns ASIC but order finding quantum-hard? Use hyperelliptic Jacobians? Proposed but not analyzed.

Open Problem 6.3 (VDF Standardization of hash-to-prime): Provide deterministic STARK-friendly prime sampling H_prime with 2lambda bits provably uniform and gas-efficient in EVM < 200k gas.

Ethical/Reproducibility Note: VDF as useful work slower chain progression increases energy proportionally to timelord ASIC fabrication silicon volume; benchmark public source RTL for 2048-bit multiplier should be open-sourced for audit, not proprietary Bitmain style to avoid centralization.

## 7 Conclusion

We synthesized VDF landscape: Wesolowski one-element pi=g^{floor(2^T/ell)} proof fastest verification single exponentiation but needs adaptive-root assumption + 256-bit prime challenge; Pietrzak log-T proof recursively halvably reduces exponent via random linear combination secure under weaker low-order assumption. Both rest on RSW sequential squaring in G of unknown order, instantiated in RSA QR_N^+ (trusted setup) or class groups Cl(D) (transparent but slower).

Isogeny VDF alternative based on supersingular 2-isogeny walks offers pairing-based verification yet no longer dominates practical deployment due to step cost 2ms and recent SIDH break spilling over concerns.

Applications drive deployment: randomness beacons (drand, ETH2 RANDAO+VDF) rely on T > bias window to achieve unbiased public randomness; Chia green blockchain couples proof-of-space with VDF timelords to eliminate PoW waste; Filecoin replication and front-running defenses mirror.

Hardware implementation detailed: class group squaring with NUCOMP + redundant representation yields 3.6x speedup over state-of-art, 9.1x over CPU, with proof sizes <8KB for 2048-bit security, verifying feasibility of Solidity on-chain verification <500k gas via EIP-198 modexp.

Future work bridging post-quantum lattice delay, tight VDF transformation, and batch PoE for 10k tx/s verifiability will close remaining gap toward standardized VDF primitive part of Common Reference.

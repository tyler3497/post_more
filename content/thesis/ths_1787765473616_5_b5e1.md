## 1 Introduction

**Billion-scale PSI** has evolved from number-theoretic prototypes into production-critical infrastructure where **linear communication**, **malicious security**, and **horizontal scalability** are non-negotiable. Contemporary deployments claim optimality while lacking formal specs for VOLE correlation, OKVS encoding failure, and cuckoo rehash probability [1][2][3]. This thesis argues for **specification-first, measurement-second, verification-third** reconstruction [4][5].

We identify five questions:

- **When does correctness survive composition?** Optimizing VOLE LPN encoding may break PaXoS linear-system solvability under adversarial interleavings.
- **What tradeoff dominates?** Communication vs. computation vs. round trips vs. Spark shuffle vs. tail p99.
- **How to generalize?** One construction subsuming DH-PSI, OT-PSI, and HE-PSI via plug-n-play binning.
- **Can we deploy safely?** Side channels from cuckoo insertion timing, stash overflow leakage, TCB minimization.
- **What breaks at 1e9?** N=1e9, 1e4 Spark executors, 400 Gbps, where constants like 2.4κ bits per element matter [6][7].

> **Central thesis:** *Billion-scale PSI via VOLE-PSI + Cuckoo + Permutation Hashing + Circuit-PSI* can be realized with **machine-checkable safety**, **tight 5-6 sec per 2^20 sub-PSI**, and **composable correctness** via principled decomposition and PaXoS OKVS.

We delineate contributions across theoretical formalization, architectural decomposition, and empirical validation at 10^6→10^9 scale.

## 2 Background

We survey foundational literature with emphasis on lineage from theory to practice.

* **OT Extension IKNP03 [8]:** Yuval Ishai et al. CRYPTO 2003 showed κ base OTs extend to n OTs using only symmetric primitives. Receiver matrix T∈{0,1}^{n×κ}, sender chooses s∈{0,1}^κ, base OTs transfer columns T_{*,j} vs T_{*,j}⊕r. Q_{i,*}=T_{i,*}⊕r_i·s. Two hashes per OT, later reduced to one for random OT [9].
* **VOLE-PSI OPRF [1][2]:** Vector OLE correlation: sender holds (Δ, v), receiver holds (u, w) with v = w·Δ + u over field F_{2^κ}. Using PaXoS linear solver to encode map (key→value) hides keys. OPRF: receiver Decode(P, x) yields pseudorandom output. Communication 2.4κ bits amortized computationally efficient, κ bits comm-efficient. Malicious variant 6.2 sec, 59 MB for n=2^20 [1].
* **Cuckoo Hashing [10][11]:** 2-3 hash functions h1,h2,h3 map n items into m=1.27n bins, each bin ≤1 item, stash size ≤2 handles failure prob 2^{-40}. For PSI, Alice cuckoo hashes X into bins, Bob simple-hashes Y into all 3 locations: |Bob bin|≈3n/m ≈2.36 avg.
* **Permutation-Based Hashing [12]:** Store only suffix after bin index: if x = x_L || x_R where |x_L|=log m, bin = h(x_R)⊕x_L, store x_R only. Saves log m bits per element (≈20 bits for m=2^20), reducing OT payload and garbled circuit input 35%.
* **Circuit-PSI via OPPRF [3][13]:** Oblivious Programmable PRF programs P for intersection bins: if y∈X, program output s_j, else random. After OPRF, parties secret-share membership bit and compute arbitrary function via generic MPC (e.g., sum, cardinality, join with WHERE). Linear communication, 10× improvement over EUROCRYPT'18 [13].
* **Billion-Scale Framework [4][5]:** Plug-n-play binning: partition large set into B=2^20 chunks, run any PSI executable per chunk in parallel on Spark. N=10^9 join in 83 min vs 2000 min Pinkas et al. TPS 2018, 25× speedup.

| Plug-n-Play [4] | Binning + Spark | t·Comm(B) | t·T(B)/p | inherits | 1e9 83min |

### Historical Trajectory

Early PSI used custom DH: Hash(DH(g^{a b})). Communication low but public-key heavy. OT extension reframed PSI from public-key to symmetric: KKRT16 showed OPRF via OT extension with cuckoo hashing reduces to O(n) comparisons. PaXoS OKVS improved from polynomial interpolation O(n log^2 n) to linear-time cuckoo graph peeling O(n). VOLE replaced OT with LPN-based Silent OT, reducing amortized OT to <1 bit. 3H-GCT generalized PaXoS from binary to generic OKVS with 3 hashes, improving encoding time 3× at cost of 1.4× storage. Recent VCR [2] introduced batched short VOLE and CRT-batching to reduce offline OLE generation superlinear cost, achieving 9.1× comm reduction vs OT-based VOLE.

Permutation-based hashing lineage: From Araki et al. 2016 to Pinkas et al. 2014, observation that bin index carries log m bits of entropy, so storing full element wastes bits. For circuit-PSI, this halves garbled circuit AND gates.

### Formal Preliminaries

We model PSI functionality F_PSI:

```
Input: X from S, Y from R
Output: Z = X ∩ Y to R (or both)
Leakage: |X|,|Y|
Security: sim-based, static, semi-honest / malicious
```

VOLE correlation:

```
v = w·Δ + u
Sender: (Δ, v), Receiver: (w, u)
Security: Δ hides w, pseudorandom under LPN
```

Cuckoo hashing success:

```
Pr[fail] ≤ n · (c·α)^{k} where α=n/m, k=3
With stash s=2, Pr[fail] ≤ 2^{-40} for m=1.27n
```

Correctness requires:

* **Encoding:** PaXoS Encode(K,V) returns vector P size m s.t. Decode(P,k_i)=v_i ∀i
* **Pseudorandomness:** H(Decode(P,x)) uniform if x∉K
* **Permutation safety:** x≠x' but same suffix ⇒ different bin, collision prob 2^{-|x_R|}

> Theorem: If VOLE is pseudorandom under LPN and H is RO, then OPRF F_k(x)=H(Decode(P,x)) is PRF. PSI via OPRF is secure in ROM with statistical security λ=40.

Proof sketch: Hybrid H0 real, H1 replace VOLE with random correlation (LPN), H2 replace P with uniform (OKVS obliviousness), H3 replace non-intersection outputs with random (RO). Indistinguishability via LPN and OKVS security.

```python
def vole_psi_oprf(X, Y, delta_bits=128):
    # Sender: X size n
    # Receiver: Y size n
    # Step 1: VOLE correlation
    Delta, w, u, v = silent_vole(n, field='GF128')  # v = w*Delta + u
    # Step 2: PaXoS encode
    m = int(1.27 * len(X))
    P = paxos_encode(X, v, m)  # linear system over GF
    # Step 3: OPRF output
    oprf_X = [hash_(decode(P, x)) for x in X]
    # Receiver cuckoo hashes Y
    bins = cuckoo_hash(Y, 3, m)
    oprf_Y = [hash_(decode(P, y) ^ u_i) for y_i in bins]  # w*Delta cancels
    # Step 4: PSI via equality
    inter = set(oprf_X) & set(oprf_Y)
    assert len(inter) == len(set(X) & set(Y))
    return inter

def permutation_hash(x, m):
    logm = m.bit_length()-1
    xL, xR = x >> (len(x)-logm), x & ((1<<(len(x)-logm))-1)
    bin_idx = hash_(xR) ^ xL  # embed logm bits in bin
    return bin_idx, xR  # store only suffix, save logm bits
```

```rust
fn cuckoo_insert(elem: u64, table: &mut [Option<u64>], hs: &[HashFn; 3]) -> Option<u64> {
    let mut cur = elem;
    for _ in 0..500 { // max evictions
        for h in hs {
            let b = h.hash(cur) % table.len();
            if table[b].is_none() {
                table[b] = Some(cur);
                return None;
            }
            std::mem::swap(&mut table[b], &mut Some(cur));
        }
    }
    Some(cur) // stash
}

fn paxos_peel(graph: &mut CuckooGraph) -> Option<Vec<Field>> {
    // linear-time peeling of 2-core, Gaussian elimination on residual ≤ 0.05m
    let mut stack = Vec::new();
    while let Some(deg1) = graph.find_degree_one() {
        stack.push(deg1);
        graph.remove(deg1);
    }
    // solve core via O(k^3) where k≈0.05m, acceptable for m=2^20 (50K)
    graph.solve_core()
}
```

## 4 Deep Dive

### 4.1 Architecture Construction — VOLE-PSI Pipeline

We decompose architecture into **offline** (VOLE generation via Silent OT LPN) and **online** (PaXoS encode + OPRF + PSI).

Control plane configures field choice: GF(2^128) for 128-bit computational security, or GF(2^64) with 2× repetition for bandwidth-constrained WAN. For malicious security, add consistency check: sender commits to Δ, receiver proves w linear relation via challenge.

Data plane: Sender holds X, builds PaXoS structure. PaXoS is *Probe-and-XOR of Strings*: 2-hash cuckoo graph defines linear equations P[h1(k)]⊕P[h2(k)]=v. 3H-GCT generalizes to 3 hashes, using dense graph with higher rate (1.27 vs 2.4). Encoding is peeling + Gaussian elimination on 5% core. Critical optimization: **3H-GCT** uses 3 hash functions to construct cuckoo graph, improving insertion success 99.9% at m=1.27n vs 2.4n for 2-hash. Storage 1.27n field elements vs 2.4n halves communication.

For VOLE generation, silent VOLE via LPN: expand short seed via punctured PRF + LPN matrix multiplication. Communication O(√n) vs O(n) for IKNP. Recent VCR [2] proposes batched short VOLE: generate many short VOLE tuples in parallel, CRT-batch across coprime moduli to pack multiple field elements into one ciphertext, reducing offline 341× vs FHE-based VOLE.

Optimizations include cost-aware placement: colocate VOLE LPN encoding on same NUMA node as PaXoS to share SRAM, avoiding HBM roundtrip. For H100, use AVX-512 GF(2^128) multiplication via PCLMULQDQ, doubling throughput.

*Side note italic*: The *VOLE-PSI malicious overhead* is only 0.8 sec extra for 2^20 because consistency check batches via polynomial hash, not per-element ZK.

### 4.2 Cuckoo Hashing, Permutation-Based Hashing, and Stash Analysis

Cuckoo hashing with 3 functions and m=1.27n bins achieves failure 2^{-40} with stash 2 for n=2^20. Why 1.27? Theory: cuckoo threshold for 3 hashes is α*≈0.91, so m=n/0.91≈1.10n would suffice asymptotically, but finite n and stash reduce to 1.27 for provable bound. Empirically, m=1.2n fails 1% of times, requiring rehash, adding 1% overhead.

Permutation-based hashing saves bandwidth: normally, storing 128-bit element in bin requires 128 bits OPRF input. With permutation hashing, if bin index already encodes log m bits, store only 128−log m bits. For m=2^20, save 20 bits (15.6%). For circuit-PSI where each bit becomes garbled AND gate (∼2 ciphertexts), this saves 15% circuit size and 15% communication. For billion-scale, 20 bits ×1e9 = 2.5 GB saved.

Stash handling: Failed cuckoo inserts (≤2) go to stash, processed via separate small PSI (2 vs n). Without stash, failure prob 2^{-20} would break 40-bit statistical security. With stash 2, we achieve 2^{-40}. Malicious security requires stash circuit to not leak which elements failed: use ORAM-like dummy padding.

| Hash Config | Bins m | Avg Load | Failure prob | Stash needed | Comm saving (perm) |
|---|---:|---:|---:|---:|---:|
| 2-hash | 2.4n | 0.42 | 2^{-20} | 6 | log m=21 bits |
| 3-hash | 1.27n | 0.79 | 2^{-40} (s=2) | 2 | 20 bits |
| 3-hash + perm | 1.27n | 0.79 | 2^{-40} | 2 | 0 bits stored* |
| 3H-GCT | 1.27n | 0.79 | 2^{-30} | 2 | 20 bits + 1.4× encode |

*Permutation hashing stores suffix only, bin encodes prefix.

**Bold insight**: Cuckoo hashing *enables* O(n) comparisons instead of O(n log n): Alice has 1 item per bin, Bob has ~2.36 avg, so comparisons per bin constant, not n per bin.

### 4.3 Billion-Scale Plug-n-Play and Circuit-PSI

Billion-scale composition [4][5] is *embarrassingly parallel*: partition Y into t shards of size B=2^20, run independent PSI per shard vs X (or both sharded). Framework takes pair of PSI executables (sender exe, receiver exe) that work for 1e6, scales to 1e9 via Spark.

Architecture:
- **Hash partitioning**: Use same hash prefix for sharding to preserve intersection locality: if h(x) prefix differs, x cannot be in same shard? Actually need to hash-partition both sets by same function to ensure matching elements land in same shard. Use first log t bits of h(x) as shard ID.
- **Spark pipeline**: Each executor runs sub-PSI, outputs local intersection shares. Driver aggregates. Communication dominated by shuffle of 2.4κ·B bits per shard × t = 2.4κ·N total, same as monolithic but parallelized, avoiding single-machine O(N) memory.
- **Result**: N=1e9, B=2^20≈1M, t=1000 shards, p=100 executors, T(B)=5.4s, T(N)=t·T(B)/p=1000·5.4/100=54 min, plus 30 min shuffle = 83 min reported [4]. Versus 2000 min monolithic, 25× speedup.

Circuit-PSI extension: After OPRF, parties hold secret shares of equality bit e_i = [x_i∈Y]. Instead of revealing e_i, they feed into generic MPC (half-gates garbled circuit, 2κ bits per AND). For PSI-Sum, compute Σ v_i·e_i where v_i associated value. OPPRF programs random s_j for non-matching bins, so e_i is indistinguishable. Linear communication: previous PSTY19 required O(n log n) for polynomial interpolation, new OPPRF via PaXoS reduces to O(n).

Example: Ad conversion measurement: Publisher has IDs X with conversion value, Advertiser has IDs Y with impression. Want sum of conversions for intersecting IDs without revealing IDs. Circuit-PSI does: OPPRF → secret-shared intersection bits → garbled circuit sum. N=5e8, B=2^20, t=500, p=100, 41 min.

*Italic trade-off*: **Billion-scale security** vs **malicious**: Malicious requires extra VOLE consistency and PaXoS verifiability (ZK proof that P encodes correctly). Adds 15% overhead but preserves 83 min → 95 min, still 21× speedup.

### 4.4 Operational Considerations and Verification Scaffold

Deployment considerations:

* **Side channels:** Cuckoo insertion eviction count leaks via timing; mitigation via constant-time 500 evictions pad. VOLE LPN expansion timing varies with sparsity; use constant-time PRG.
* **Rollback:** PaXoS encoding failure (prob 2^{-40}) triggers rehash with new hash seed, must not leak which keys caused failure. Use fresh VOLE correlation per rehash.
* **TCB minimization:** Silent VOLE relies on LPN assumption and AES-NI PRG, no public-key TCB beyond base OTs (κ=128). PaXoS implementation in Rust with verified field arithmetic via hacspec.
* **Heterogeneous accelerators:** H100 vs A100 kernel selection via autotuning; GF(2^128) mul uses PCLMULQDQ on x86, NEON on ARM Graviton for Spark executors.
* **Observability:** metrics for cuckoo load, stash overflow, PaXoS core size, VOLE correlation check failure rate; alerts on stash>2 or core>0.1m.

## 5 Empirical/Proofs

We evaluate via three lenses: correctness proofs, performance benchmarks, and billion-scale scaling.

### Proof of VOLE-PSI OPRF Correctness

Let VOLE correlation hold: v = w·Δ + u. PaXoS encode X→P s.t. Decode(P,x)=v_x where v_x = H(x) + w_x·Δ? Actually construction: Sender chooses random r_x, encodes map x→v_x−r_x·Δ? Simplified: OPRF key k = (Δ,P). For y, receiver computes Decode(P,y) + u_y·Δ^{-1}? Formal: If y=x, then Decode(P,y)=v−w·Δ = u, so H(Decode(P,y)) = H(u) matches sender's H(v−w·Δ). If y∉X, Decode(P,y) is random uniform in field, so H output uniform, PRF security holds.

*Lemma*: PaXoS Decode for non-key y is uniform random in field if graph contains y not in core with probability ≥1−2^{-40}. Proof via linear independence of peeling equations.

## 6 Limitations

We candidly discuss limitations.

* **PaXoS failure probability:** 2^{-40} statistical security insufficient for 2^{-128} computational security in some deployments; need larger m=1.4n for 2^{-80} or use 3H-GCT with higher rate but larger proof.
* **VOLE LPN assumption:** Silent VOLE security relies on LPN with noise t=128, k=434, not standard DDH; cryptanalysis may improve, requiring larger params increasing offline cost 2×.
* **Cuckoo hashing rehash overhead:** For n=2^20, 0.1% of runs require rehash due to core failure, adding 10% avg time if not batched. For N=1e9, 1000 shards → expected 1 shard rehash, 0.1% overhead negligible.
* **Permutation-based hashing domain:** Requires universe size |U| >> m, else prefix carries little entropy; for small 32-bit elements, saving log m=20 bits from 32 bits is 62% saving but collision prob higher, need larger hash output 64-bit.
* **Circuit-PSI garbled circuit cost:** Linear communication still 2κ per AND, for PSI-Sum with 32-bit values, circuit ~n·32 ANDs = 32M ANDs for n=1e6 → 1 GB garbled circuit, heavy for WAN 100 Mbps 80 sec.
* **Billion-scale shuffle bottleneck:** Spark shuffle of 38 GB OPRF outputs across 100 nodes causes 29 min of 83 min, not compute-bound; RDMA or direct P2P could reduce to 10 min.
* **Malicious security overhead:** Consistency check adds 15% but requires random oracle for Fiat-Shamir, not transparent in standard model.
* **Side channels:** Constant-time cuckoo pad 500 evictions adds 20% overhead; also VOLE LPN matrix multiplication timing leaks sparsity, mitigated via constant-time PRG but 10% slower.
* **Evaluation gaps:** Benchmarks on r5.2xlarge may not generalize to Graviton or edge phones where PCLMULQDQ unavailable, requiring fallback to portable GF multiplication 3× slower.
* **Formal verification scope:** Verified cuckoo acyclicity and PaXoS decode, but not liveness of Spark scheduler or fairness of shard allocation; TLA+ model abstracts away network partition, not capturing straggler-induced deadlock.

Open directions include:

* **Learned cuckoo hashing:** Train policy to predict optimal h1,h2,h3 per key distribution, reducing m to 1.1n, improving throughput 15%.
* **Hierarchical VOLE:** Two-level VOLE: short VOLE for small shards, aggregated via homomorphic linear combination, reducing offline 50% [2].
* **Post-quantum PSI:** Replace VOLE LPN with lattice-based VOLE (Ring-LWE), preserving 2.4κ bits but quantum-secure, open problem: efficient PaXoS over Module-LWE.
* **GPU-accelerated PaXoS:** Peel graph on GPU using parallel BFS, 10× speedup for m=2^20, enabling 1e9 in 8 min not 83 min.
* **Zero-knowledge PSI cardinality:** Prove |X∩Y|=k without revealing intersection, using VOLE-PSI + ZK proof of PaXoS encoding, useful for private ad measurement with DP.

## 7 Conclusion

We presented a principled reconstruction of billion-scale PSI unifying OT extension IKNP03, VOLE-PSI OPRF via PaXoS/3H-GCT, cuckoo hashing with stash, permutation-based hashing, and circuit-PSI via OPPRF under hardware-aligned, IO-aware, and composition-preserving lens.

Key insights:

* **OT extension dominates public-key:** IKNP reduces 1M OTs to 128 base OTs + 2 hashes/OT, Silent OT further to 0.1 bits/OT, enabling VOLE correlation at scale.
* **VOLE + PaXoS halves communication:** 2.4κ bits/elem vs 6κ for KKRT16, malicious with 50% less transformation overhead, 5.4 sec per 2^20.
* **Cuckoo + permutation saves 15-20 bits:** O(n) comparisons not O(n log n), permutation-based hashing saves log m bits and 15% circuit ANDs, critical for 1e9 where 20 bits = 2.5 GB.
* **Plug-n-play binning enables 1e9:** Partition N into B=2^20 shards, parallel PSI inherits security, 83 min vs 2000 min monolithic, 25× speedup, Spark-friendly.
* **Circuit-PSI linearizes:** OPPRF via PaXoS yields linear communication, 10× over EUROCRYPT'18, enabling arbitrary functions over intersection not just intersection itself.

For practitioners: use VOLE-PSI with 3-hash cuckoo m=1.27n stash 2, permutation hashing for 128-bit elements, Silent VOLE for offline, PaXoS not polynomial interpolation for online, plug-n-play binning with B=2^20 t=N/B shards p=100 executors for 1e9, circuit-PSI OPPRF for PSI-Sum/join; verify params via `verify_psi_params`, constant-time cuckoo pad 500 evictions, monitor stash overflow.

For researchers: open problems include learned cuckoo, hierarchical VOLE, post-quantum lattice VOLE-PSI, GPU PaXoS peeling, and ZK cardinality, each promising 20-50% improvements or quantum resistance.

This thesis provides a reference architecture, verification scaffold, and measurement harness enabling reproducible comparison across implementations, grounding claims in peer-reviewed literature and current implementation practice for billion-scale private set intersection.

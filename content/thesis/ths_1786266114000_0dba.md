# Asynchronous BFT Consensus over DAGs: A Comparative Analysis of Narwhal-Tusk, Bullshark, and HotStuff-2 with Threshold Signature Aggregation for Linear View-Change

## Abstract
This thesis provides a systematic deconstruction of DAG-based asynchronous Byzantine Fault Tolerant (BFT) consensus, focusing on the Narwhal mempool abstraction, the Tusk zero-overhead asynchronous protocol, the Bullshark partially synchronous optimization with fast and slow paths, and the integration of HotStuff-2's two-phase linear view-change paradigm using threshold signatures. We formalize how separation of dissemination and ordering resolves throughput bottlenecks, prove liveness under asynchrony via random coin and quorum intersection, and demonstrate how BLS threshold aggregation reduces view-change communication from O(n^2) to O(n). Through comparative modelling and empirical synthesis from WAN deployments, we show Narwhal-HotStuff sustains 130-170k tx/s, Tusk 140-160k tx/s with ~3-4s latency, and Bullshark achieves 2-round commit in synchrony vs 6 rounds asynchronously. We identify fairness, garbage collection, and post-quantum aggregation as remaining open problems.

## 1 Introduction

The pursuit of *high-throughput, low-latency* BFT consensus under realistic network conditions has shifted from monolithic leader-based protocols to Directed Acyclic Graph (DAG) construction. Classical protocols such as PBFT and Tendermint couple data dissemination with ordering, creating a **leader bottleneck** that bounds throughput to ~1-2k tx/s on a WAN [Yin et al., 2019].

Narwhal and Tusk [Danezis et al., 2021] introduced a paradigm shift: *decouple mempool dissemination from consensus ordering*. The mempool becomes a structured round-based DAG where each vertex contains transactions and references to ≥2f+1 vertices in the previous round. Consensus then *interprets* the DAG with zero extra messages.

This work contributes:

* A formal unified model of Narwhal's causally-ordered reliable broadcast, Tusk's random-leader wave commit, and Bullshark's dual-type anchored fast path
* A re-derivation of HotStuff-2's two-phase optimality and its compatibility with DAG waving, showing why *two phases are enough* after GST
* A cryptographic layer analysis of BLS threshold signatures and distributed key generation (DKG) for linear O(n) view-change
* Comparative evaluation and limitations for post-quantum migration and equitable fee markets

> Theorem: Under n = 3f+1, asynchronous adversary, DAG-based BFT with weak links preserves Validity, Agreement, and probabilistic Liveness with expected latency O(1) waves for Bullshark/Tusk when instantiated with perfect common coin.

## 2 Background/Preliminaries

### 2.1 System Model

We assume n validators, at most f Byzantine, n = 3f+1. Network is either *asynchronous* (unbounded delay, messages eventually delivered) or *partially synchronous* with Global Stabilization Time (GST) after which delay ≤ Δ. Adversary is computationally bounded for BLS12-381.

### 2.2 BFT Primitives

* **Byzantine Atomic Broadcast (BAB):** Total order of messages where if honest p delivers m, all honest deliver m in same order.
* **Reliable Broadcast:** If honest sender broadcasts m, all honest deliver m; no duplication; if honest delivers m then all honest deliver m (Cachin-Tessaro).
* **Threshold Signatures:** (n, t)-threshold scheme where t = n-f = 2f+1 shares produce single O(1)-size aggregate indistinguishable from single signer. BLS allows non-interactive aggregation via Lagrange interpolation.

### 2.3 DAG Foundations

DAG-Rider [Keidar et al., 2021] pioneered structured DAGs per round with reliable broadcast evading equivocation. Narwhal inherits causal availability:

* *Round Completion:* For each r, every honest validator eventually outputs block_accept for ≥2f+1 vertices of round r
* *Causal History:* Accepting vertex v implies accepting all vertices in causal(v)

Bullshark builds *waves* of 4 rounds (Narwhal-Tusk uses 3), with steady-state and fallback leaders per wave.

## 3 Methodology

We adopt a *constructive-comparative* methodology:

1.  **Specification Mining:** Extract pseudocode from reference implementations (Narwhal crate in Sui/Mysten, Bullshark 200LOC extension over HotStuff-on-DAG)
2.  **Formal Modelling:** Model in TLA+ the safety invariant for view-change locking, and liveness via Markov chain for wave commit probability
3.  **Complexity Accounting:** Amortized communication per transaction: O(n) for Narwhal-scaled deployments, O(n^2) worst-case for view-change without threshold, O(n) with
4.  **Synthesis of Empirical Data:** Cross-reference WAN results from AWS c5.8xlarge 10-val, 50-val deployments reported in primary papers

We *do not* re-run large deployments, but validate models against reported latency distributions and failure injection data, following delay analysis methods [Hwerbia et al., 2024].

## 4 Deep Dive

### 4.1 Narwhal: Scale-Out Mempool as DAG

Narwhal is *not* consensus. It is a high-throughput mempool protocol providing:

* **Worker-Primary Architecture:** Multiple workers disseminate batches via *quorum store*; primary includes batch digests, not tx, in DAG vertices, enabling horizontal scaling linear to #workers.
* **Certified Edges:** Each vertex must carry certificates of availability for ≥2f+1 previous vertices, ensuring data availability without direct leader download.
* **Asynchronous Tolerance:** Progress independent of leader; even faulty primary cannot degrade dissemination below O(n) fan-out.

A Python abstraction of round advancement:

```python
def narwhal_round_advance(dag, r):
    # dag[r] = set of vertices from distinct validators
    # advance when |dag[r]| >= 2f+1
    certified = [v for v in dag[r] if v.has_quorum_cert()]
    if len(certified) >= 2*f+1:
        next_proposals = propose_headers(references=certified)
        return r+1, next_proposals
    return r, []
```

*Italicized insight:* The steady-state insight is that redundancy (2f+1 edges) *encodes voting* without vote messages.

### 4.2 Tusk: Zero-Overhead Asynchronous Consensus

Tusk operates on Narwhal DAG in waves of 3 rounds [Danezis et al., 2022]:

* Wave w = rounds (1: proposer, 2: vote, 3: randomness). A perfect common coin elects leader L_w from round 1.
* Commit rule: If f+1 vertices in round 2 reference L_w, commit L_w and its causal history via deterministic DFS order.

> Theorem: Tusk satisfies BAB under asynchrony with probability 1 commit every 4 waves expectation, O(9 rounds expected). Safety holds because quorum intersection prevents conflicting commits.

Tusk's original criticism: no *quantifiable* fairness pre-GST due to garbage collection; random coin means adversary can delay non-leader blocks.

| Property | Tusk | DAG-Rider | Expectation |
| :--- | :--- | :--- | :--- |
| Rounds per wave | 3 | 4 | Lower is better |
| Expected commit latency (rounds) | 9 | 10.5 | Tusk wins |
| Communication overhead | 0 | 0 | Same |
| Post-quantum safe | No (BLS coin) | No | Both need PQ coin |
| Fairness | No bounded | Yes (weak links) | Rider faster fairness |

### 4.3 Bullshark: Practical Partial Synchrony with Fast Path

Bullshark [Spiegelman et al., 2022] preserves asynchrony worst-case liveness but adds *two leader types* per wave:

1. **Steady-state leaders:** Pre-determined, first and second round of wave; vote requires `f+1` type-consistent votes
2. **Fallback leaders:** Elected via coin for non-responsive periods

Optimizations:

* *Fast path:* If network synchronous and leader honest, Bullshark commits in 2 DAG rounds ~ 2δ vs DAG-Rider 6 rounds (75% reduction)
* *Slow path:* Falls back to 6 rounds asynchronous, matching lower bounds of [Ben-Or & El-Yaniv]
* Garbage collection feasible post-GST because committed leaders anchor history; validators can prune causal histories below committed anchor respecting timed fairness.

```rust
// Simplified Bullshark vote-type aggregation
enum VoteType { Steady(bool), Fallback }

fn can_commit(leader: Vertex, votes: Vec<Vertex>) -> bool {
    let mut steady = 0;
    let mut fallback = 0;
    for v in votes {
        if v.links.contains(&leader) {
            match v.vote_type {
                VoteType::Steady(_) => steady += 1,
                VoteType::Fallback => fallback += 1,
            }
        }
    }
    steady >= f+1 || fallback >= f+1
}
```

In Sui production [Tanaka, 2025], Bullshark on Narwhal achieves *297k tx/s @ 2s latency* after batch tuning, validating scale-out linearity claim: doubling workers ≈ doubling tx/s without latency increase.

### 4.4 HotStuff-2: Two Phases Are Enough

HotStuff [Yin et al., 2019] required 3 phases: prepare, pre-commit, commit, to enable linear view-change. HotStuff-2 [Malkhi & Nayak, 2023] proves 3 phases *unnecessary*.

Core contribution:

* View v: leader proposes extending highest QC (quorum certificate)
* Replica votes with threshold share `σ_i = H(m)^{sk_i}` if locked QC ≤ proposal QC
* Leader aggregates to 2f+1 threshold-QC then second-phase commit QC; commit requires 2-chain but logic of *locking* differs: replica unlocks only on higher-phase QC

> Theorem: HotStuff-2 achieves O(n^2) worst-case communication (optimal), O(n) optimistic, two-phase commit within view, optimistic responsiveness (advances at δ not Δ after GST), *without* additional heavy primitives like SNARKs.

Formally, safety proof shows:

```tla
---- MODULE HotStuff2Safety ----
EXTENDS Naturals, FiniteSets
VARIABLES lockedQC, preparedQC, view
Safety == \A r1, r2 \in Rounds:
            Committed(r1, block) /\ Committed(r2, block')
            => block = block' \/ CausalPrecedes(block, block')
====
```

View-change linearity emerges from QC as single BLS threshold signature, not vector of 2f+1 signatures. Thus per view-change message carries *O(1)* aggregated signature instead of O(n).

Comparison to DAG overlay:

| Feature | HotStuff/Narwhal-HS | Tusk | Bullshark | HotStuff-2 |
| --- | --- | --- | --- | --- |
| Network assumption | Partial sync | Async | Partial sync / async fallback | Partial sync |
| Phases to commit | 3 (pipeline) | 0 (DAG interpretation) | 2 sync / 6 async | 2 |
| View-change cost | O(n) w/ threshold | No VC | O(n) embedded | O(n) |
| Throughput ceiling | 130k tx/s | 160k tx/s | 297k tx/s (Sui tuned) | 100k+ (pipelined variants) |

### 4.5 Threshold Signatures: Cryptographic Enabler of Linearity

BLS12-381 threshold instantiation:

* Setup: DKG (e.g., Joint-Feldman) yields group public key `PK = g^{s}` where s = Σ polynomial evaluations; share `sk_i`
* Partial sign: `σ_i = H(m)^{sk_i}`
* Aggregate: Interpolate Lagrange `L_i(0)` for quorum T size t = 2f+1: `σ = ∏ σ_i^{L_i}`
* Verify: `e(σ, g2) == e(H(m), PK)`

*Security nuance:* Adaptive security requires additional random-polynomial zeroing technique [Gurkan et al., 2023; Bacho & Loss, 2024]. For BFT we assume static corruption up to f for simplicity, but Sui rotates validators per epoch, limiting adaptive window.

Integration with DAG: coin is also threshold BLS where message = wave number; outputs `rnd = Hash(σ_coin)` deterministic unpredictable leader election, no extra round.

```haskell
-- BLS threshold aggregation (conceptual)
aggregate :: [PartialSig] -> Maybe Sig
aggregate shares
  | length shares >= 2*f+1 =
      let coeffs = lagrangeCoeffsAtZero shares
          sigma = product [pow s_i c | (s_i,c) <- zip shares coeffs]
      in verify sigma >>= \ok -> if ok then Just sigma else Nothing
  | otherwise = Nothing
```

## 5 Empirical/Proofs

### 5.1 Liveness Analysis

Assume random coin uniform over n. Probability that elected leader L_w has ≥ f+1 references in round 2 is at least:

```
p_commit ≥ (f+1)/n * ≥ 1/3 for n=3f+1
```

Expected wells n? Uses negative binomial: E[wave until commit] ≤ 4.5. Empirically [Spiegelman et al., 2022] avg 2.2 waves under faults vs ~4 under worst-case adversary withholding references.

We model Bullshark voting as Bernoulli per replica success (link present). With network success prob q (empirical 0.85-0.98 per round under WAN), binomial Bi(n- f, q) ≥ f+1 needed for commit. Delay distribution analysis [Hwerbia et al., 2024] matches simulation within 5% error.

### 5.2 Safety Sketch

We reuse quorum intersection argument:

* If two honest validators commit different leaders L,w and L',w' for same wave, then there exist two sets of f+1 round-2 voters referencing distinct leaders, but each honest votes at most one per round ⇒ at most n - f =2f+1 total honest votes, two disjoint f+1 sets would imply n_honest ≥2f+2 contradiction.
* Threshold QC unforgeability ensures adversary cannot forge QC without 2f+1 honest shares.

### 5.3 HotStuff-2 Optimality Proof Fragment

Optimality relies on showing lower bound Ω(n^2) worst-case communication for any responsive BFT under cascading faulty leaders; HotStuff-2 matches bound via linear VC * O(f) views = O(n^2). Formal reduction to Dolev-Reischuk lower bound.

Pipeline throughput linearity proof for Narwhal: addition of k workers multiplies batch-dl throughput by k absent primary CPU bottleneck (primary only hashes digests). Measurements [Danezis et al., 2022] linear to 600k tx/s on 10 validators, 10 workers each.

## 6 Limitations

* **Fairness Gap:** Tusk offers *no fairness* before anchor commit; client whose tx payload only in non-leader vertices waits unboundedly. Bullshark introduces weak links + timed fairness, but only after GST and with bounded DAG depth [Wang et al., 2024]. Fully asynchronous fair ordering remains open.

* **Post-Quantum Exposure:** BLS threshold aggregation is not quantum-safe. Lattice-based threshold signatures have aggregate size O(n log q) [Boneh et al., 2021, PK post-quantum quorum], breaking O(1) assumption. Sui mitigates with ephemeral epochs but not final.

* **Garbage Collection Complexity:** Zero-overhead interpretation prohibits aggressive pruning because uncommitted vertices may be needed to prove availability of causal history. Bullshark's GC requires synchronized checkpoints and risks liveness under asynchrony with malicious pruning announcements.

* **View-Change Liveness under Asynchrony:** HotStuff-2 assumes partial synchrony; chained with Narwhal it inherits liveness stalls when network asynchronous. Shoal framework [Arun et al., 2023] attempts to eliminate timeouts via leader reputation, but formally still needs Δ fallback.

* **DKG Trusted Setup Overhead:** Joint Feldman DKG costs O(n^2) broadcasts and synchronous assumptions conflict with asynchrony goal; practical deployments use centralized dealer per epoch (decentralization regression).

## 7 Conclusion

We have deconstructed the transition from leader-centric monolithic BFT to DAG-centric modular consensus. Narwhal provides the *dissemination plane*, Tusk and Bullshark provide *interpretation engines* with zero message overhead, and HotStuff-2 demonstrates that *two phases suffice* for responsive BFT when coupled with BLS threshold cryptography. The combination—Narwhal's scale-out workers, Bullshark's dual-leader wave, and HotStuff-2's linear QC chaining—yields a Pareto frontier of 130k-300k tx/s, 2-4s latency, and O(n) per tx communication.

Future work lies in three axes: *post-quantum constant-size quorum signatures* without trusted setup, *deterministic fairness* under asynchrony via timed watermark certificates, and *pipeline-integrated Shoal++* anchoring to achieve prevalent responsiveness without Δ timeouts. The DAG paradigm finally makes BFT *perform like a distributed mempool* rather than a replicated log, but cryptography remains its Achilles' heel.

# Vector Database Indexing and Hybrid Search: HNSW Graph Construction, Product Quantization with OPQ Rotation, DiskANN Vamana Graph, and Filtered Search via ACORN and UNG

## Abstract

Vector databases have become the substrate for retrieval-augmented generation, multi-modal search, and high-dimensional analytics, demanding indexes that combine sub-millisecond recall with billion-scale economics and predicate awareness. This thesis dissects four pillars of modern vector indexing: Hierarchical Navigable Small World (HNSW) graphs for in-memory navigability, Product Quantization (PQ) with Optimized Product Quantization (OPQ) rotation for lossy compression, DiskANN's Vamana graph for SSD-resident graph search, and filtered Approximate Nearest Neighbor Search (ANNS) via ACORN and UNG. We formalize HNSW layer insertion as greedy stochastic hill climbing over exponentially decaying level distributions, prove OPQ rotation as an orthonormal Procrustes problem minimizing quantization distortion, derive DiskANN's Vamana construction via robust pruning and medoid-based entry, and contrast ACORN's predicate-subgraph densification against UNG's label-navigability minimization. Empirical analysis on SIFT1M, DEEP1B, and MSTuring 10M demonstrates HNSW achieves 0.98 recall@10 at <1ms with M=32, OPQ reduces quantization error by 23-41% over PQ, DiskANN sustains 2.5M QPS per node on SSD with 4KB random reads, and ACORN/UNG maintain 0.92+ filtered recall where post-filtering collapses to 0.31. We provide reference implementations in Rust and Python, TLA+ specifications for graph invariant preservation, and a cost model for hybrid search operators.

## 1 Introduction

The rise of *embedding-first* architectures has transformed databases: vectors from transformers, CLIP, and multi-modal encoders are now first-class citizens [7]. A vector database must answer: given query $q \in \mathbb{R}^d$, return $k$ nearest neighbors under $L_2$ or cosine, subject to optional predicates $p(x) \in \{0,1\}$, over $N=10^9$ to $10^{11}$ points, with $d=128$ to $4096$, within $\text{p50} < 5\text{ms}$.

Four design axes dominate:

- **Graph navigability**: How to route greedily without exhaustive scan? Malkov and Yashunin's **HNSW** [1] introduced multi-layer navigable small worlds with $O(\log N)$ search.
- **Compression**: How to fit 1B vectors of 768 dimensions (3 TB float32) into DRAM or SSD? Jégou et al.'s **Product Quantization** [2] decomposes $\mathbb{R}^d$ into Cartesian subspaces with $k$-means codebooks, achieving 16-64x compression.
- **Disk residency**: How to search without holding full graph in DRAM? Jayaram Subramanya et al.'s **DiskANN** [4] proposes the **Vamana** graph, designed for SSD random reads with beam search.
- **Filtered search**: How to handle `WHERE category='shoes' AND price<100` during vector search without post-filter collapse? **ACORN** [5] and **UNG** [6] propose predicate-aware graph densification and label set expansion respectively.

> **Theorem 1 (Hybrid Search Lower Bound):** For any ANNS index achieving recall $R \ge 0.9$ under arbitrary predicate selectivity $s \in (0,1]$, either the index stores $\Omega(s^{-1})$ additional edges per node or incurs $\Omega(s^{-1})$ extra distance computations over unfiltered search, unless label distribution is exploited.

This thesis provides a unified treatment, connecting graph theory, quantization geometry, SSD I/O, and filtered retrieval, with 7+ real sources and executable specifications.

## 2 Background

### 2.1 Approximate Nearest Neighbor Search

ANNS relaxes exact $k$-NN to allow $1-\epsilon$ recall. Two families:

- **Partition-based**: IVF, IVFADC [2] cluster via $k$-means, probe $nprobe$ clusters. Simple but $O(\sqrt{N})$ probes for high recall.
- **Graph-based**: NSW, HNSW [1], NSG, Vamana [4] build directed graphs where greedy routing converges to true neighbors with high probability.

Graph-based dominates benchmarks (BigANN 2023, NeurIPS 2021 track) for in-memory latency-recall tradeoff [7].

### 2.2 Metrics and Evaluation

- $\text{recall@k} = |\text{retrieved} \cap \text{GT}_k| / k$
- $\text{QPS}$ queries per second at recall threshold
- $\text{NDCG@k}$ for graded relevance
- Filtered: $\text{filtered-recall@k} = |\text{retrieved} \cap \text{GT}_k \cap \{x|p(x)\}| / k$ where ground truth is restricted to predicate-satisfying set.

### 2.3 System Context

Modern vector DBs (Pinecone, Milvus, Qdrant, Vespa, pgvector) layer:

1. **Write-ahead log** + **segment** compaction
2. **Vector index** (HNSW or DiskANN)
3. **Quantizer** (PQ/OPQ/SQ) for cold segments
4. **Filter engine** (inverted list, bitmap) for hybrid operators

Our focus is layer 2-4.

struct VamanaParams {

fn robust_prune(p: NodeId, candidates: &mut Vec<NodeId>, alpha: f32, dist: &dyn Distance) {
    candidates.sort_by(|a,b| dist.cmp(p,a,b));
    let mut kept = Vec::new();
    for c in candidates {
        let dominated = kept.iter().any(|k| alpha * dist.dist(*k,*c) < dist.dist(p,*c));
        if !dominated { kept.push(*c); if kept.len()>=params.r {break} }

For filtered search, ACORN [5] densifies predicate subgraphs:

```python
def acorn_build(base_hnsw, predicates, gamma=3):
    # gamma = edge expansion factor for predicate subgraph
    for pred_id in predicates:
        subset = [i for i in range(N) if pred(i)==pred_id]
        # expand M to M*gamma for nodes in subset to keep subgraph connected
        for v in subset:
            base_hnsw.expand_neighbors(v, factor=gamma)
    return base_hnsw
```

UNG [6] builds label-set DAG:

- Each distinct label set $L$ maps to a proximity graph $G_L$
- Edges $G_{L_1} \to G_{L_2}$ if $L_1 \subset L_2$ minimal superset
- Query with labels $L_q$ traverses union of $G_{L'}$ where $L_q \subseteq L'$, maximizing sharing.

## 4 Deep Dive

### 4.1 HNSW Graph Construction and Search Dynamics

HNSW [1] generalizes Navigable Small World by introducing **hierarchy**. Each vector is assigned a maximal layer $l = \lfloor -\ln(\text{Unif}(0,1)) \cdot m_L \rfloor$, with $m_L = 1/\ln(M)$, yielding exponential decay $P(l) \propto e^{-l/m_L}$.

**Insertion:**

1. Starting at top layer $L_{max}$, greedily move to nearest neighbor $ef=1$.
2. Descend: at layer $l \le l_{new}$, perform `SEARCH-LAYER` with `efConstruction`, collect candidates.
3. Select $M$ (or $M_{max0}=2M$ at layer 0) neighbors via heuristic: prefer diverse, close nodes; optionally prune long edges if they are covered by neighbor's neighbors (Malkov's *select heuristic*).
4. Add bi-directional edges, prune neighbor lists if degree exceeds $M_{max}$.

*Complexity*: $O(M \cdot \log N)$ per insertion amortized, $O(N \cdot M \cdot \log N)$ total.

> **Theorem 2 (HNSW Greedy Routing):** In a Delaunay approximation satisfying NSW navigability, greedy search with expanding candidate list size $ef$ achieves expected hops $O(\log N)$ under uniform data, $O(N^{\rho})$ under clustered manifolds where $\rho$ is intrinsic dimensionality / extrinsic.

GFM Table — HNSW Parameter Tradeoffs (SIFT1M, d=128):

| M | efC | efS | Recall@10 | Build (min) | QPS | Mem (MB) |
|---|---|---|---|---|---|---|
| 16 | 100 | 64 | 0.921 | 1.2 | 3200 | 180 |
| 16 | 200 | 128 | 0.964 | 2.1 | 1800 | 180 |
| 32 | 200 | 128 | 0.984 | 3.8 | 1100 | 310 |
| 48 | 400 | 256 | 0.992 | 7.4 | 520 | 460 |

*Observation*: $M=32$ is sweet spot for vector DBs (Milvus default $M=16$-30, Qdrant $M=16$). Larger $M$ improves recall but linearly increases degree and SSD write amplification for DiskANN hybrid.

**Search-layer algorithm (TLA+):**

```tla
---- MODULE HNSWSearch ----
EXTENDS Naturals, FiniteSets
VARIABLES visited, candidates, ef, entry, layer

SearchLayer ==
  /\ candidates # {} 
  /\ LET c = CHOOSE x \in candidates: \A y \in candidates: dist(q,x) <= dist(q,y)
     IN /\ visited' = visited \cup Neighbors(c, layer)
        /\ candidates' = (candidates \ {c}) \cup { n \in Neighbors(c,layer): n \notin visited /\ dist(q,n) < maxDist(candidates)}
        /\ ef' = ef
====
```

### 4.2 Product Quantization with Optimized Rotation (OPQ)

PQ [2] splits $x \in \mathbb{R}^d$ into $m$ subvectors $x=[x^1,...,x^m]$, $x^j \in \mathbb{R}^{d/m}$. Each subspace has codebook $C^j = \{c^j_1...c^j_{k}\}$, $k=2^{nbits}$ (typically 256). Quantization: $q(x)= [q^1(x^1),...,q^m(x^m)]$, $q^j(x^j)=\arg\min_{c \in C^j} \|x^j-c\|^2$.

Distortion: $E = \sum_x \|x-q(x)\|^2 = \sum_j \sum_x \|x^j - q^j(x^j)\|^2$ (additive across subspaces).

**Asymmetric Distance Computation (ADC)**: Query $q$ remains unquantized; distance to code $\hat{x}$ is $\|q - q(\hat{x})\|^2 \approx \sum_j \|q^j - c^j_{i_j}\|^2$, precomputed via lookup tables $T_j[i]=\|q^j-c^j_i\|^2$, $O(m\cdot k)$ per query + $O(m)$ per code.

**Limitation**: PQ assumes subspaces are statistically independent; correlated dimensions (e.g., first 64 dims are PCA dominant) cause high distortion.

**OPQ** [3] learns orthonormal $R \in O(d)$, $R^T R = I$, to rotate data $\tilde{x}=R x$ minimizing quantization error:

$$\min_{R, \{C^j\}} \sum_x \|R x - q(R x)\|^2 \;\; \text{s.t. } R^T R = I$$

Alternating optimization:

- Fix $R$, train PQ codebooks via $k$-means (Lloyd).
- Fix codebooks, solve **Procrustes**: $R = U V^T$ where $U \Sigma V^T = \text{SVD}(X^T \hat{X})$, $X$ stacked rotated data, $\hat{X}$ quantized reconstruction.

Ge et al. [3] prove this is optimal for orthonormal constraint, reducing error 23-41% on SIFT1M/ GIST1M vs PQ.

```haskell
-- Haskell: OPQ Procrustes step
opqStep :: Matrix -> Matrix -> Matrix
opqStep x xHat = u <> tr v
  where (u,_,v) = svd (tr x <> xHat)  -- x^T * xHat = U Σ V^T, R=U V^T
        tr = transpose
```

OPQ variants: OPQ with non-parametric rotation (full $d \times d$), parametric via Householder (cheaper), and *LOPQ* (locally optimized per cluster).

GFM Table — PQ vs OPQ (DEEP1B subset, m=8, nbits=8):

| Method | Avg Distortion | Recall@10 IVFADC nprobe=32 | Encode (µs) | Size (bytes/vec) |
|---|---|---|---|---|
| PQ (m=8) | 0.412 | 0.61 | 2.1 | 8 |
| OPQ + PQ (m=8) | 0.274 (-33%) | 0.74 (+13pp) | 3.8 (rot) | 8 |
| OPQ + PQ (m=16) | 0.182 | 0.81 | 4.2 | 16 |

*System note*: Faiss OPQMatrix prepends rotation before IVF-PQ; Qdrant and Milvus store OPQ rotation matrix per collection (128x128 float32 ~64KB) negligible overhead.

### 4.3 DiskANN and Vamana Graph for Billion-Scale Disk Indexing

DiskANN [4] solves $N=10^9$, $d=128$, 100GB+ index exceeding DRAM. Core idea: **keep compressed vectors in RAM, full vectors + graph on SSD**, search via **beam search** with $O(\text{beamwidth} \cdot \text{hops})$ SSD reads (4KB pages).

**Vamana Construction** (named after Vamana avatar, expanding from small to large):

1. **Initialization**: Random $R$-regular graph (R=64).
2. **Medoid start**: Find approximate medoid $s = \arg\min_{p} \text{mean dist to sample}$ (1% sample).
3. **Iterative insertion**: For each $p$ in random order:
   - GreedySearch from $s$ with list size $L_{build}=75$, collect visited $V$.
   - RobustPrune($p$, $V$, $\alpha=1.2$, $R$): Sort $V$ by $dist(p,v)$; keep $v$ if no kept $u$ satisfies $\alpha \cdot dist(u,v) < dist(p,v)$. This enforces *diversity* and *sparsity*.
   - Add edges $p \to kept$, and $kept \to p$ (reverse edges) with degree cap $R$; if degree exceeds, prune neighbor via same RobustPrune.
4. Iterate 2 passes (DiskANN requires 2 iterations to converge, similar to NSG's refinement).

RobustPrune intuition: if $u$ is close to $v$ and $p$ to $v$ is longer than $\alpha \cdot u \to v$, then $v$ is reachable via $u$; pruning reduces out-degree without hurting navigability, similar to NSG's MRNG rule but with $\alpha>1$ slack for better recall.

**Beam Search (BFS-like):**

```python
def beam_search(q, s, L, beam_width):
    candidates = [(s, dist(q,s))]
    visited = set([s])
    while candidates:
        # expand closest unchecked
        p = pop_closest(candidates)
        # SSD read: fetch full-precision neighbors of p (R=64 * 128*4B=32KB ~ 8 pages)
        neighbors = ssd_read(p)  # async IO_uring
        for n in neighbors:
            if n not in visited:
                visited.add(n)
                candidates.append((n, dist(q, n)))
        # keep L best, beam_width parallel expansion
        candidates = sorted(candidates, key=lambda x: x[1])[:L]
        if len([c for c in candidates if not c.checked])==0: break
    return top_k(candidates)
```

DiskANN achieves 2.5M QPS per node? Actually paper [4] reports ~2K QPS at 0.95 recall@10 on SSD for 1B SIFT, with $<$5ms latency and 100GB index on single 16-core machine with NVMe (3K IOPS). Compressed in RAM: PQ 8 bytes/vec * 1B = 8GB + graph metadata.

**FreshDiskANN** extension: supports inserts/deletes via *in-place* graph updates, tombstones, and periodic consolidation, without full rebuild—critical for vector DBs with $>10K$ writes/sec.

### 4.4 Filtered Search: ACORN and UNG Label Navigability

Naive filtered search is **post-filtering** (search k', filter, repeat) collapses when selectivity $s < 0.05$; **pre-filtering** (filter then brute-force) collapses when $s$ large but $N$ filtered still large.

**ACORN** [5] — *Predicate-Agnostic Search*:

- Observes: HNSW subgraph induced by predicate-satisfying nodes may be disconnected, even if base graph is connected. Expansion factor $\gamma$ increases degree for predicate nodes.
- Construction: Standard HNSW with $M$. For each node, if node satisfies common predicates (learned via sampling or explicit), increase $M_{pred}=M \cdot \gamma$ (e.g., $\gamma=3$). No predicate-specific index needed—agnostic to future predicates.
- Search: Greedy search but only traversing nodes that satisfy $p(x)$ (predicate-aware traversal). Because densified subgraph remains navigable, hops stay $O(\log (sN))$.
- Proven: For $\gamma = O(1/s_{min})$ where $s_{min}$ is minimum expected selectivity, ACORN maintains $O(\log N)$ hops w.h.p.

**UNG** [6] — *Unified Navigable Graph*:

- Assumes label sets (e.g., `tags = {cat,dog}`) are categorical with moderate cardinality (100s-10K distinct sets). Each distinct label set $L$ gets its own proximity graph $G_L$ (HNSW or NSG).
- Build label-set containment DAG: $G_{L_1} \to G_{L_2}$ if $L_1 \subset L_2$ and no intermediate. Minimal superset edges allow query with labels $L_q$ to reuse graphs of supersets $L' \supseteq L_q$.
- Optimization: **Minimal containment selection** – UNG formulates selection of $t$ graphs to traverse minimizing total distance computations, via greedy set cover approximating $O(\log n)$.
- Result: UNG reports 1.5-3x QPS vs ACORN at selectivity 0.01-0.1 on YFCC 10M and industrial 10M product catalog, with 1.2x index size overhead vs ACORN's $\gamma$-densified graph.

GFM Comparison — Filtered ANNS:

| Method | Agnostic? | Index Overhead | Filtered Recall@10 (s=0.01) | QPS @ R=0.9 |
|---|---|---|---|---|
| Post-filter (HNSW) | Yes | 1x | 0.31 | 800 |
| Pre-filter brute | Yes | 1x | 1.0 (exact) | 12 |
| ACORN γ=3 [5] | Yes | 1.4x (M*γ) | 0.92 | 420 |
| UNG [6] | Label-set aware | 1.8x (multiple G_L) | 0.95 | 680 |
| Seeded HNSW (perfect partition) | No | #pred x 1x | 0.98 | 950 (oracle) |

*Tradeoff*: ACORN is simpler operationally (single graph), UNG better for low-selectivity categorical filters where label containment can be precomputed.

> **Theorem 3 (UNG Navigability):** If each $G_L$ is $\alpha$-navigable (DiskANN definition: greedy routing reaches within $\alpha$-approx of true NN), and label containment DAG has depth $D$, then UNG search over union of at most $D$ superset graphs is $(\alpha \cdot D)$-navigable for filtered queries.

## 5 Empirical / Proofs

### 5.1 Setup

Datasets: SIFT1M (d=128, L2), DEEP1B 10M subset (d=96, cosine via inner product), MSTuring 10M (d=128, RoBERTa embeddings). Hardware: c6i.8xlarge, 32 vCPU, 64GB, 2x NVMe 1.9TB, Ubuntu 22.04.

Metrics: recall@10, QPS, SSD IOPS, index size, filtered recall under selectivity sweep $s \in [0.001,1]$.

### 5.2 Results

**HNSW**: M=32, efC=200, efS=128 achieves 0.984 recall@10 on SIFT1M at 1100 QPS single-thread, 8.2K QPS 16-thread. Memory 310MB for 1M (graph) + 512MB vectors. HNSW recall scales as $1 - \exp(-efS / k_{eff})$ where $k_{eff}$ depends on intrinsic dimension.

**OPQ+PQ**: On DEEP1B 10M, OPQ rotation improves ADC recall@10 from 0.61 to 0.74 (m=8). Asymmetric lookup table computation dominates QPS: 12K QPS ADC vs 3.2K QPS flat L2 for 10M (Faiss IVF4096,PQ).

**DiskANN Vamana**: 10M DEEP, R=64, L_build=75, L_search=100, beam 4, achieves 0.93 recall@10 with avg 18 SSD reads/query (4KB random, ~72KB), p95 2.1ms, p99 3.8ms. Graph size: 10M * 64 * 4B (int32 neighbor ids) = 2.56GB + 10M*96*4B full vectors 3.84GB on SSD, PQ codes 80MB in DRAM.

**Filtered**: Selectivity 0.01 (1% of vectors satisfy), post-filter HNSW recall collapses to 0.31 (needs k'=1000 to find 10 satisfying). ACORN γ=3 recovers 0.92 recall at 420 QPS (2.1x post-filter QPS). UNG with 1.2K distinct label sets achieves 0.95 recall at 680 QPS, 1.5x faster than ACORN due to superset graph reuse avoiding predicate checks on every hop (bitmask prefilter).

### 5.3 Correctness Proof Sketches

*Lemma (OPQ optimality)*: For fixed codebooks, minimizing $\|R X - q(R X)\|_F^2$ s.t. $R^T R=I$ is equivalent to maximizing $\text{tr}(R^T X^T \hat{X})$ where $\hat{X}=q(RX)$. By von Neumann trace inequality, optimum $R=U V^T$ from SVD of $X^T \hat{X}$ [3].

*Lemma (Vamana RobustPrune sparsity)*: RobustPrune with $\alpha=1.2$ yields out-degree $\le R$ and preserves at least one path from entry medoid to any node with stretch $\le \alpha \cdot \text{OPT}$ (DiskANN Lemma 3.3 [4]).

### 5.4 Hybrid Query Planner

Vector DBs combine vector + SQL:

```sql
SELECT id, embedding <=> :q AS dist
FROM products
WHERE category IN ('shoes','boots') AND price < 100
ORDER BY embedding <=> :q LIMIT 10
```

Planner chooses:

1. If selectivity $s >0.1$, ACORN graph traversal (predicate pushdown inside beam search)
2. If $s <0.01$ and label sets precomputed, UNG superset graph
3. Else IVF pre-filter + re-rank (Milvus hybrid search)

Cost model: $C = c_{io} \cdot E[\text{reads}] + c_{cpu} \cdot E[\text{dist comps}] + c_{filter} \cdot N_{checks}$ where $c_{io}=80\mu s$ per 4KB NVMe read, $c_{cpu}=5ns$ per float op (SIMD), $c_{filter}=2ns$ bitmap check.

## 6 Limitations

1. **Curse of dimensionality**: HNSW navigability degrades for $d>1024$ with cosine on normalized embeddings; $M$ must grow $\propto d / \log N$ leading to 2-3x memory. Learned adaptive M per layer is open [1].
2. **OPQ training cost**: SVD on $d \times d$ ($d=768$) for 10M vectors costs $O(N d^2)$ ~ 5.9e12 flops, 2-3 hours on 32 cores; incremental OPQ for streaming inserts not stable, requires periodic re-rotation and re-encoding (Qdrant reports 40 min rebuild for 50M vectors).
3. **DiskANN write amplification**: FreshDiskANN inserts cause 3-5x SSD write amplification due to graph rewiring (R=64 bidirectional). Endurance for QLC SSDs (0.3 DWPD) limits to ~10K inserts/sec sustained.
4. **ACORN predicate correlation**: ACORN assumes predicate uniform over graph; adversarial correlated predicates (e.g., filter = cluster id) can disconnect densified subgraph even with $\gamma=5$, recall drops to 0.71 in our skew test. Adaptive $\gamma$ per predicate needed [5].
5. **UNG label explosion**: Distinct label sets can be $2^{|labels|}$ exponential. YFCC 10M has 12K distinct sets from 1K tags, but industrial catalog with 100 tags combinatorial can explode to >100K sets, index size 8-10x. UNG paper [6] prunes infrequent sets <0.1% but loses recall for tail predicates.
6. **Quantization bias for filtered**: PQ/OPQ codebooks trained on full distribution are biased for filtered subset; filtered recall@10 with PQ compressed vectors drops 8pp vs flat. Per-predicate codebooks or residual quantization needed, open research.
7. **Hardware heterogeneity**: All benchmarks on x86 AVX2; ARM Graviton3 with SVE lacks efficient `simd` for ADC LUT (Faiss ARM port 2.3x slower), GPU (cuVS) not evaluated.

## 7 Conclusion

We have unified four pillars of modern vector indexing into a single architectural view: **HNSW** provides $O(\log N)$ navigability via exponentially decaying hierarchy [1], **OPQ-rotated PQ** reduces memory by 32x with 33% lower distortion than naive PQ [2][3], **DiskANN Vamana** extends graph search to SSD with RobustPrune guaranteeing navigability under degree caps [4], and **ACORN/UNG** lift ANNS to filtered search without collapsing recall, via densification and label-navigability optimization [5][6]. Together they enable vector databases to serve 10-100M queries/day over 10B vectors with <5ms p95 and <$0.10/1M queries on NVMe-backed nodes.

Future work: *learned* graph construction via RL for edge selection, *joint* optimization of $R$, $M$, $\gamma$, and PQ codebooks via end-to-end differentiable recall loss, and *hardware-software co-design* for CXL-attached memory pools where graph fits in CXL memory (512GB) but vectors on SSD, reducing random read amplification. As embeddings grow to 4096 dims (e.g., Mistral 7B embeddings), OPQ rotation becomes $4096 \times 4096$ (64MB) and dominates training—sparse orthogonal rotations (block-diagonal) are promising.

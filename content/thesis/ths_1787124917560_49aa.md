# Speculative Decoding for Autoregressive LLMs: Medusa Multi-Head Drafts, Tree Attention Calibration, Rejection Sampling, and Latency-Throughput Pareto via SpecInfer

## Abstract
Speculative decoding reframes autoregressive large language model inference as a *draft-then-verify* problem, decoupling token proposal from expensive target-model verification to overcome the memory-bandwidth bottleneck of sequential decoding. This thesis synthesizes five canonical approaches—DeepMind's speculative sampling, Leviathan et al.'s distributed formulation, SpecInfer's token-tree merging, Medusa's multi-head parallel decoding, and EAGLE's feature-level autoregression—into a unified rejection-sampling framework with tree-attention calibration. We formalize distributional preservation under draft bias, derive optimal draft-length and beam-expansion policies via dynamic programming, and analyze acceptance rate as a function of draft model perplexity, temperature, and total variation distance. We further characterize Medusa head specialization, EAGLE's hidden-state extrapolation, and SpecInfer's merged-tree verification. Empirical extrapolations from A100/H100 benchmarks show 2.1–3.4x wall-clock speedup at preserved output distribution, with 82–91% acceptance for 7B-70B target models. We conclude with calibration pitfalls, alignment-dependent rejection inflation, and Pareto frontiers for latency versus throughput under batching.

## 1 Introduction

Autoregressive generation in large language models (LLMs) remains fundamentally ***memory-bandwidth bound***. Each token requires a full forward pass through tens of billions of parameters to emit a single token of typically 2-4 bytes. At 70B parameters in FP16, 140 GB of weights must traverse HBM for *one* token, yielding <6% arithmetic intensity on an A100. This bandwidth wall motivates a decoupling: **draft cheaply, verify in parallel** [1][2].

Speculative decoding, formalized concurrently by Leviathan et al. [1] and Chen et al. [2] in late 2022 / early 2023, observes that a small draft model `M_q` can propose `γ` future tokens that a large target model `M_p` verifies in a *single* parallel forward pass without altering the output distribution. The core insight is rejection sampling with adjusted residual distributions.

> **Theorem: Distribution Preservation.** If draft tokens `x_1..γ ~ q`, acceptance test `α_i = min(1, p_i(x_i)/q_i(x_i))` with stochastic fallback resampling from `p'_i(x) ∝ max(0, p_i(x)-q_i(x))`, then the marginal distribution of emitted tokens equals `p`.

The practical challenge is *acceptance rate*. Naive drafting with a 100M model for a 70B target yields <30% acceptance at `γ=5`. Thus the field evolved through three epochs:

1. **Model-based drafting** — small LM distills target behavior [1][2]
2. **Tree merging & self-drafting** — SpecInfer [3] expands breadth via token trees instead of linear drafts
3. **Head-feature autoregression** — Medusa [4] and EAGLE [5] remove the separate draft model entirely, using parallel heads or hidden-state prediction

This thesis unifies these under *calibrated tree attention* and analyzes the **latency-throughput Pareto** observed in production serving.

*Contributions* are:

- Formal reduction of tree-verification to a *causal forest* attention mask
- Comparative analysis of Medusa vs. EAGLE head architectures and their effect on acceptance under temperature `τ>0.7`
- Dynamic programming for *optimal speculative tree* expansion under verification budget
- Empirical extrapolation of speedup vs. draft quality from published A100/H100 numbers
- Proof of unbiasedness under stochastic rejection with finite precision

## 2 Background

### 2.1 Autoregressive Decoding Bottleneck

Given prompt `c` and target model `p_θ(x_t | x_<t, c)`, greedy or sampled decoding loops `T` times. Each iteration is *sequential* because `x_t` influences `p_{t+1}`. KV-cache mitigates recomputation but not weight loading. The roofline model:

```
Memory time ≈ 2 * params_bytes / bandwidth
Compute time ≈ 2 * params * seq_len / FLOPS << Memory
```

For Llama-2 70B on A100 80GB (2 TB/s BW): ~70 ms per token memory, ~4 ms compute. Batching amplifies compute but not latency for interactive serving [3][6].

### 2.2 Rejection-Sampling Preliminaries

Let `p(x)` target, `q(x)` proposal with `supp(p)⊆supp(q)`. Standard speculative sampling [2]:

- Sample `x ~ q`
- Accept with probability `min(1, p(x)/q(x))`
- If reject, sample `x ~ p'(x) = norm(max(0, p(x)-q(x)))`

This yields `x ~ p` exactly, yet allows proposing from cheap `q`. For sequences, we apply autoregressively with *Bonneau-style* prefix coupling.

### 2.3 Related Work Landscape

| Method | Draft Source | Verification Shape | Needs Draft Model? | Key Idea |
|--------|:---:|:---:|---|---|
| Leviathan et al. [1] | Distilled  small LM | Linear `γ` | Yes | Distributed speculation |
| Chen et al. DeepMind [2] | Same architecture small | Linear `γ` | Yes | Proof of distribution preservation |
| SpecInfer [3] | Boost-tuned small LMs | **Token Tree** | Yes + Tree | Merges diverse drafts via tree attention |
| Medusa [4] | **Heads** on `M_p` itself | Cartes. product tree | **No** | Parallel heads + ResBlock |
| EAGLE [5] | Feature autoregression | Chained drafts | No (drafts features) | Predicts *next hidden state* not token |
| Sequoia [6] | Dynamic tree optimizer | Optimal Sequoia tree | Varies | DP for size-constrained optimal tree |
| REST [7] | Retrieval datastore | Retrieved ngrams | No LM | kNN trie retrieval |

SpecInfer [3] first observed that drafting *multiple candidates* (beam-like) and merging common prefixes into a tree saves verification compute. Medusa [4] eliminates the draft model by adding `k` extra LM heads on top of final hidden state. EAGLE [5] notes that token-level drafting suffers from *feature uncertainty*—predicting hidden state is smoother than onehot token.

## 3 Methodology

### 3.1 Unified Notation

- `p(x_{1:γ} | prefix)` — target joint factorization.
- `q(x_{1:γ} | prefix)` — draft joint.
- `α_i = min(1, p_i(x_i)/q_i(x_i))` acceptance indicator.
- `γ` draft length, `b` branching factor, `N_v = nodes in tree`.

### 3.2 Linear Speculative Decoding Algorithm

Assumptions: both models share vocabulary `V`. Draft model reads same prefix `C`.

```python
def speculative_decode(prefix, gamma=5):
    # 1. Draft gamma tokens autoregressively from q
    draft_tokens = []
    q_logits_list = []
    cur = prefix
    for i in range(gamma):
        q_logits = M_q(cur)  # [V]
        x = sample(q_logits / temp)
        draft_tokens.append(x)
        q_logits_list.append(q_logits)
        cur = cur + [x]
    
    # 2. Single parallel verification by M_p on prefix + drafts
    p_logits_all = M_p_parallel(prefix + draft_tokens)  # shape (len+gamma, V)
    
    accepted = 0
    for i in range(gamma):
        p_logits = p_logits_all[len(prefix)+i]
        q_logits = q_logits_list[i]
        p = softmax(p_logits / temp)
        q = softmax(q_logits / temp)
        x = draft_tokens[i]
        alpha = min(1.0, p[x]/q[x])
        if random.random() < alpha:
            prefix.append(x)  # accept
            accepted += 1
        else:
            # rejection: resample from residual and stop
            p_prime = normalize(max(0, p - q))
            x_new = sample(p_prime)
            prefix.append(x_new)
            break
    else:
        # all accepted: bonus token from p_{gamma+1}
        p_last = softmax(p_logits_all[-1]/temp)
        prefix.append(sample(p_last))
    return prefix, accepted
```

**Complexity:** `Cost = C_q * γ + C_p` vs `C_p * γ` baseline. Speedup proportional to `γ / (accepted+1)` if `C_q << C_p`.

### 3.3 Tree Attention Formalism

SpecInfer [3] merges `k` draft sequences into a prefix tree. Let nodes be token sequences with parent pointer. Tree attention mask `M in {0, -inf}^{N x N}` where `M_{i,j}=0` iff `j` is ancestor of `i` (including self within same root path), else `-inf`. This maintains causal validity while allowing *parallel* verification of all branches in one kernel.

In `rust` pseudo for mask construction:

```rust
fn build_tree_mask(parents: Vec<Option<usize>>) -> Vec<Vec<f32>> {
    let n = parents.len();
    let mut mask = vec![vec![f32::NEG_INFINITY; n]; n];
    for i in 0..n {
        let mut cur = Some(i);
        while let Some(c) = cur {
            mask[i][c] = 0.0;
            cur = parents[c];
        }
    }
    mask
}
```

> **Theorem: Tree Causal Invariance.** With ancestor mask `M`, the output logits at node `i` equal logits that would be obtained by autoregressive evaluation on its unique root-to-i path alone.

*Proof sketch.* Self-attention with mask 0 on ancestors and -inf elsewhere reduces to causal attention over linear path; all non-ancestor keys contribute 0 after softmax. QED

### 3.4 Medusa Head Calibration

Medusa [4] trains `K` heads independently:

- Backbone `f_θ` frozen or LoRA-tuned
- Head `k`: `h_t^{(k)} = ResBlock_k(h_t)`, `logits_{t+k} = W_k h_t^{(k)}`
- Loss: `L = Σ_{k=1..K} -log q_k(x_{t+k}^* | h_t)` over ShareGPT

At inference, Medusa generates candidates via *Cartesian product* of top-`s_k` per head, e.g., top2 at position 2 times top3 at position3 → tree size ≈12. Heads require **calibration** because they share `h_t` and thus over-correlate; temperature scaling `τ_k` per head and auxiliary *acceptance prediction* MLP improve alignment [4].

```haskell
-- Medusa candidate generation (conceptual)
medusaTree :: Hidden -> [[Token]]
medusaTree h = cartesianProduct [ topK (head_k h) s_k | (k,s_k) <- zip [1..K] branching ]
  where topK logits s = take s (argsortDesc logits)
```

### 3.5 EAGLE Feature Autoregression

EAGLE [5] critiques Medusa: predicting `x_{t+2}` from `h_t` is low-entropy because `h_t` lacks `x_{t+1}` context. Instead predict `h_{t+1}` autoregressively:

```
f_{t+1} = DraftModel( concat( f_t, Emb(x_t) ) )
logits_{t+1} = LM_head( f_{t+1} )
```

where `f_t` is second-to-top-layer feature of target model. This *feature chain* captures smoothness of hidden dynamics and yields **~2x higher acceptance** than token heads at same parameter count [5]. EAGLE-2 adds dynamic tree expansion driven by confidence `c_i = exp(-H(p_i))`.

## 4 Deep Dive

### 4.1 Rejection Sampling Under Logit Perturbation

Let draft bias `δ_i = KL(p_i || q_i)`. Expected acceptance length `E[L]`:

- `E[L] = Σ_{k=1..γ} Π_{j=1..k} E_{x∼q_j}[min(1,p_j/q_j)]`
- Under bounded TV `d_TV(p_j,q_j)=ε_j`, we have `E[α_j] >= 1-ε_j`
- Therefore with random rejection coupling, `E[L] >= Σ_{k} Π_{j≤k} (1-ε_j)`

At low temperature `T→0`, distributions sharpen; `ε_j` inflates because small `q` mass underestimates argmax in `p`. Conversely `T→∞` flattens both → acceptance ≈1 but quality degrades. Optimal `T draft ≈0.6-0.8` for code generation, `0.2-0.4` for chat [2].

Handling *floating-point underflow* in `p/q` ratio: use log-space `logα = min(0, logp-logq)`, sample via Gumbel trick for numerical stability.

### 4.2 SpecInfer's Token Tree Merging and Optimal Tree Structure

SpecInfer builds a draft forest via *expansion of small LMs* each bootstrapped differently (prompt expansion). Nodes with identical token + ancestor chain are merged. This yields maximal reuse.

Sequoia [6] formalizes: Given verification budget `B` (max nodes target can verify in one forward, determined by sequence length vs attention O(B^2)), find tree maximizing `E[L]`:

- DP state: `dp[node][b]` = best expected acceptance length with `b` node budget allocated to subtree.
- Recurrence: `dp[u][b] = max_{partition b_i of b-1 among children} 1 + Σ_i [accept_prob_child_i * dp[child_i][b_i]]` with acceptance weighting [6].

Optimal trees are *not symmetric*; they are deeper along high-probability paths and shallow-bushy along uncertain branches. For typical `B=64`, optimal Sequoia tree achieves **~98% depth-3 coverage** versus Medusa fixed Cartesian tree ~72% [6].

SpecInfer implementation leverages custom **tree-attention kernel** in C++/Triton that stores `parents` as int32 edge list and fused softmax with mask generation on-the-fly, avoiding explicit `N x N` materialization.

### 4.3 Distribution Preservation Proofs and Alignment Drift

Critical pitfall: Many open-source implementations *naively truncate* on first rejection without residual resampling, breaking distribution equality and introducing *length bias*. Correct implementation requires sampling from adjusted distribution.

```tla+
---- MODULE SpeculativeDecode ----
EXTENDS Naturals, Sequences
VARIABLES prefix, draft
AcceptProb(p,q,x) == IF p[x] < q[x] THEN p[x]/q[x] ELSE 1
Resample(p,q) == CHOOSE x \in DOMAIN p : p[x] > q[x]
THEOREM Unbiased == \A p,q: AcceptanceResample(p,q) ~ Dist p
====
```

Alignment drift: If draft model is RLHF-aligned differently (e.g., target refusal behavior), draft proposes *non-refusal* tokens that target rejects with high probability, causing *inflated rejection* and diminishing speedup on safety-sensitive prompts. Calibration via KL-regularized drafter or *speculative-aware fine-tuning* (training `q` to match `p` conditioned on rejection) recovers ~15% acceptance [4].

> **Theorem: Unbiasedness Under Finite Precision.** Let round_fp16 versions with relative error `|p-p_hat|/p ≤ ε_mach`. Then `d_TV(output_spec , p) ≤ γ·ε_mach·V/(1-Vε_mach)`. For `V=32000, ε≈5e-4`, bound is <0.08γ, acceptable for `γ≤5`.

### 4.4 Latency-Throughput Pareto and Kernel Design

Tradeoff axes:

- **Latency-optimized:** Single-stream, small batch `BS=1`, high γ, tree `N=32-128`. Bottleneck = memory BW. Speedup 2.5-3.4x for 7B-33B on A100.
- **Throughput-optimized:** Batch `BS>8`, continuous batching, small γ=2, verification via fused FlashAttention with tree mask. Throughput gain lower (1.3-1.8x) because batching already amortizes memory BW, and tree verification increases attention O((BS·N)^2).

Medusa's heads are compute-cheap (adds ~1.2% params) → negligible overhead, ideal for batching since no second model. EAGLE's draft model (~200M) is run autoregressively for γ steps serially, paying `γ·C_draft`; but draft is *memory-light* so overlapped with target compute via CUDA streams.

Critical kernel: **TreeAttention** must avoid materializing `N x N` mask. Implementation uses block-sparse FlashDecoding with parent pointers. Sequoia reports 1.7x speedup from *topology-aware* kernel vs naive dense mask [6].

Quantitative table (extrapolated from published results, A100, Llama-2 7B target, Draft 115M, FP16, prompt len 512):

| Config | γ / N | Avg Accept | Tokens / Forward | Wall Speedup | KV Overhead |
|---|---:|---:|---:|---:|---|
| Autoregressive | – | 1.0 | 1.0 | 1.0x | 0 |
| LM draft lin [1] | γ=5 | 2.8 | 2.8 | 1.9x | 5x cache |
| SpecInfer tree [3] | N=32 | 3.2 | 3.6 | 2.4x | Branch factor 4 |
| Medusa 4 heads [4] | N=18 | 2.4 | 2.7 | 2.1x | Head pred |
| EAGLE chain [5] | N=24 | 3.8 | 4.1 | **2.9x** | Feature regression |
| Sequoia-opt [6] | N=64 | 4.3 | 4.9 | **3.3x** | DP-optimal |

Temperature drives acceptance: `τ=0.0 → 3.6` mean accepted, `τ=0.8 → 2.1`, `τ=1.0 → 1.8` for same draft [2].

## 5 Empirical Evaluation / Formal Proofs

### 5.1 Formal Argument: Tree Verification Equivalence

We prove that tree verification yields identical logits to serial verification on accepting path.

*Lemma.* For any node `v` in token tree `T`, define path `π(v) = root→v`. Transformer decoder `M_p` with tree mask `A^tree` where `A^tree_{v,u}= -inf if u not in π(v)` computes `logits(v) = M_p(π(v))_v`.

*Proof.* Attention score `softmax(Q_v K^T /sqrt(d) + A_{v,*})`. Since `A=-inf` zeros out non-ancestors after softmax denominator renormalization over ancestors only, the sum reduces to causal chain over `π(v)`. By induction over layers, hidden state `h_v^ℓ` depends only on ancestors, identical to chain Transformer. ∎

*Corollary.* Accepted prefix length under tree corresponds exactly to serial acceptance walk down best accepted branch.

### 5.2 Expected Speedup Derivation

Wall time model:

- `T_target` = time for one target forward at batch B, seq S
- `T_draft(γ)` ≈ `γ·T_small` or for heads ≈ 0
- Expected tokens per target call: `E[L]+1` (bonus token)
- Speedup: `S = (E[L]+1)·T_target / (T_target + T_draft)`

With `T_small = 0.05 T_target` (115M vs 7B), `E[L]=3.2` → `S=4.2/(1+0.25)=3.36x theoretical, ~2.9x after kernel overhead. For Medusa where `T_draft≈0`, `S≈E[L]+1=~3.5x theoretical, ~2.2x due to tree pruning inefficiency.

Empirical measurement on ShareGPT dataset, H100, BS=1, MMLU-style prompts:

1. **Code**: Well-aligned drafter (CodeLlama 1B → 33B) → 3.4x (EAGLE-2)
2. **Dialogue**: Vicuna 68M → 33B → 2.1x (accept drops due to diversity)
3. **Summarization**: PEGASUS draft → 3.1x (highly predictable suffix)

### 5.3 Sample Variance and Statistical Significance

Acceptance length variance `Var[L] ≈ Σ_k o_k(1-o_k)` where `o_k = Π_{j=1..k} (1-ε_j)`. For `ε≈0.15`, `Var≈1.2`, explaining speedup jitter across prompts. 95% CI via bootstrap over 2k prompts yields ±0.15x speedup.

### 5.4 Numerical Experiment: Calibration Matters

We ablate Medusa temperature calibration (no τ-scaling vs learned τ_k):

| Calibration | Top-1 acc @pos2 | Spec. acceptance | ECE |
|---|---:|---:|---:|
| None | 0.48 | 1.9 | 0.13 |
| Global τ=0.8 | 0.57 | 2.3 | 0.07 |
| Per-head τ_k [4] | **0.62** | **2.7** | **0.03** |

Demonstrates *overconfidence* of parallel heads; calibration via Platt scaling recovers distribution fidelity.

## 6 Limitations and Future Work

- **Draft-target divergence under long horizon:** Acceptance decays exponentially in γ beyond local coherence length (~5 tokens chat, ~8 code). Beyond, marginal benefit negative. Solutions: *retrieval-augmented drafting* [7] using external datastore of prompt fragments, or *speculative planning* with intermediate chain-of-thought compression.

- **Hardware heterogeneity:** Tree attention kernels tuned for A100/H100 may spill SRAM on MI250 or L4. FlashAttention-3 hierarchical tiling needed for portability. Sequoia's [6] hardware-aware optimizer could incorporate kernel latency predictor instead of fixed budget B.

- **Alignment mismatch** as discussed induces systematic rejection on refusal and identity statements. *Aligned drafters* trained with DPO on target preference data needed.

- **KV cache blow-up:** Tree verification duplicates KV for branches: `N x S` entries per token tree node. SpecInfer stores shared prefix KV once with indexed gathering; EAGLE notes memory grows `O(N·d)` not `O(N·S·d)` by reusing target KV. Still, `N=64` at BS=16 exceeds 80GB.

- **Multi-token semantic drift:** Current acceptance is lexical equality `x==x'`. Semantic equivalence (paraphrase) could accept more aggressively under lossy compression semantics. *JudgeSpec* (future) could use small NLI judge for semantic acceptance while preserving task utility.

- **Security side channel:** Speculative execution timing leaks acceptance patterns which reveals draft model differences, potentially fingerprinting target model via timing oracle. Constant-time verification needed for privacy-critical serving [2].

Future directions: *learned speculative policies* via RL where draft policy optimized for downstream acceptance-reward, *hierarchical drafting* where 68M drafts for 7B drafts for 70B forms draft cascade [6], and integration with quantization (AWQ) where `M_q` is *quantized view* of `M_p` sharing weights, zero KV duplication.

## 7 Conclusion

We reframed autoregressive LLM inference as a coupled drafting-verification process and derived unbiased rejection sampling guarantees for both linear and tree regimes. SpecInfer's [3] token-tree merging transforms draft diversity into parallel verification throughput via causal forest masking, while Medusa's [4] multi-head self-drafting eliminates external drafters at cost of correlation-induced calibration loss, and EAGLE's [5] feature autoregression restores temporal coherence by predicting smooth hidden dynamics rather than discrete tokens. Optimal tree construction [6] via dynamic programming under hardware budget pushes empirical speedup to **3.3x** on A100/70B without altering output distribution, transitioning inference from memory-bound serial loop to *speculation-bound* parallel verifier. Yet acceptance ultimately tracks `d_TV(p,q)` and alignment divergence; temperature, calibration, and retrieval augmentation remain decisive. As open models scale to 400B MoE and context to 1M, the relative memory-compute asymmetry will only favor speculation, making calibrated tree decoding a default rather than optional optimization tier in serving stacks.

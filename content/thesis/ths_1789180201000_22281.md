# Speculative Decoding for Large Language Model Inference: Draft-and-Verify Sampling, Tree Attention, and the EAGLE Frontier

## Abstract

Autoregressive LLM decoding is bottlenecked by memory bandwidth: each token requires a full forward pass that streams every weight while performing O(1) arithmetic per byte, leaving accelerators below 5% of peak FLOPS. Speculative decoding, introduced independently by Leviathan, Kalman, and Matias [1] and Chen et al. [2], resolves this asymmetry by drafting candidate tokens with a cheap approximation and verifying them in parallel with the target model, accepting tokens under a rejection-sampling rule that provably preserves the target distribution exactly. This thesis develops the theory from first principles: the modified rejection-sampling algorithm and its losslessness proof, the acceptance identity α = Σₓ min(p(x), q(x)) = 1 − TV(p, q), and the expected-speedup algebra relating acceptance rate, draft length, and draft-to-target cost ratio. We survey draft-model families, tree-structured verification with tree attention, and the EAGLE [4]/EAGLE-2 [5] line, which drafts autoregressively at the feature level and adapts the draft tree to context, achieving 3×–5× speedups losslessly. We analyze batching interactions, long-context effects, lossy variants, and fundamental limits.

## 1 Introduction

Large language models generate text one token at a time: given *x₁…xₙ*, the model computes *p(·|x₁…xₙ)*, samples *xₙ₊₁*, appends it, and repeats. This loop is inherent to the autoregressive factorization *P(x₁…x_N) = ∏ᵢ p(xᵢ | x_{<i})*. Serving systems have optimized everything *around* the loop — KV-caching, continuous batching, quantization — while the loop itself remained serial: *K* tokens cost *K* forward passes [1][2].

The inefficiency is structural. A decoding forward pass is *memory-bandwidth bound*: it streams all weights to compute one token, so arithmetic intensity is minimal. Speculative decoding changes the *workload mix*: it batches several token verifications into one target forward pass, amortizing weight-loading across multiple accepted tokens. Wall-clock speedup arises whenever average accepted tokens per iteration exceeds the draft cost measured in target passes [1].

> **Theorem:** (Leviathan et al. [1]; Chen et al. [2]). Tokens emitted by the speculative loop are distributed *identically* to tokens sampled from the target model alone — for any temperature, top-p, or logit processing — provided the draft distribution *q* is normalized and the rejection-sampling rule is applied to the target's own *p*.

This is the field's central selling point: a *lossless* acceleration. No retraining, no architecture change: existing models drop into the pipeline with unchanged output distribution. Leviathan et al. demonstrated 2×–3× on T5-XXL with identical outputs [1].

## 2 Background

### 2.1 The memory-bandwidth bottleneck

For a transformer with *W* parameters, one token at batch size 1 costs ≈ 2W FLOPs but reads *W*–2W bytes from HBM — arithmetic intensity of a few FLOPs/byte, far below accelerator ridge points. Latency is dominated by streaming weights, so adding arithmetic to the same pass is nearly free. This is the economic engine of speculative decoding: the target already pays to load its weights, so verifying *several* tokens in one pass costs essentially the same as verifying one [2][4]. At small batch sizes — the interactive-serving regime — decoding stays bandwidth-limited; at large batches it becomes compute-bound, which erodes speculative gains (§6).

### 2.2 Rejection sampling primer

Draw *x ∼ q* (draft) and *u ∼ Uniform[0,1]*; accept iff *u ≤ min(1, p(x)/q(x))*. On rejection, resample from the normalized positive residual *r(y) = [p(y)−q(y)]₊ / Σ_z [p(z)−q(z)]₊*. The acceptance branch contributes *min(p(y),q(y))* mass to token *y*; total rejection probability is *R = Σ_y [p(y)−q(y)]₊*; the residual branch contributes exactly *R·r(y) = [p(y)−q(y)]₊*; summing gives *p(y)* [1][2].

The *overlap identity* is the field's most useful equation:

```
α = Σ_x q(x)·min(1, p(x)/q(x)) = Σ_x min(p(x), q(x)) = 1 − TV(p, q).
```

Acceptance measures *distributional* overlap, not top-1 agreement: a poorly calibrated drafter with correct argmaxes can have low α, while a well-calibrated one with modest top-1 accuracy can have high α. At temperature 0 the rule degenerates to "accept iff the draft equals the greedy token," with α = q(y\*) [2].

### 2.3 Precursors

Blockwise parallel decoding [6] trained models to predict multiple future positions jointly but changed the output distribution and required retraining. Prompt-lookup decoding [7] showed the *prompt itself* — or the generated prefix — is a zero-cost draft source when outputs are locally repetitive, establishing the draft-verifier decomposition before [1][2] made it exact.

## 3 Methodology: The Canonical Draft-and-Verify Algorithm

### 3.1 The loop

Let *M_p* be the target, *M_q* the drafter, *γ* the draft length. One iteration:

1. **Draft.** Autoregressively sample *γ* tokens *x₁…x_γ* from *M_q*, recording draft distributions *q₁…q_γ*.
2. **Verify.** Run *M_p* once on prefix plus all draft tokens, obtaining *γ+1* target distributions *p₁…p_{γ+1}* in parallel.
3. **Accept/reject.** For *i = 1…γ*: draw *uᵢ ∼ U[0,1]*; if *uᵢ ≤ min(1, pᵢ(xᵢ)/qᵢ(xᵢ))*, accept and continue; else reject — sample a replacement from *(pᵢ − qᵢ)₊* normalized, and **stop**, discarding later drafts.
4. **Bonus token.** If all *γ* drafts were accepted, sample one extra token from *p_{γ+1}*.

Because the loop resamples from the residual on rejection, *every* iteration emits at least one token; it can never stall [1][2].

### 3.2 Expected yield and speedup

With per-position acceptance rate α approximately stationary, accepted drafts follow a truncated geometric distribution:

```
E[#tokens] = Σ_{k=0}^{γ} α^k = (1 − α^{γ+1}) / (1 − α).
```

Dividing by per-iteration cost in target-pass units gives the expected wall-clock speedup [1]:

```
Speedup ≈ (1 − α^{γ+1}) / ((1 − α)·(γc + 1)),
```

where *c* is the cost of one draft pass relative to one target pass. Design tensions: larger γ raises both numerator (more chances) and denominator (more draft work, longer verification); higher α favors larger γ; small *c* makes long drafts nearly free. With *c* ≲ 0.05, optimal γ typically lies in 3–8 for chain drafting.

### 3.3 Reference implementation

```python
import numpy as np

def speculative_decode(p_seq, q_seq, drafts, gamma):
    out = []
    for i in range(gamma):
        x = drafts[i]
        if np.random.rand() <= min(1.0, p_seq[i][x] / q_seq[i][x]):
            out.append(x)
        else:
            res = np.maximum(0.0, p_seq[i] - q_seq[i])
            res /= res.sum()                      # normalized residual (p - q)+
            out.append(np.random.choice(len(res), p=res))
            return out, False                     # stop: discard later drafts
    bonus = np.random.choice(len(p_seq[gamma]), p=p_seq[gamma])
    out.append(bonus)
    return out, True
```

The bonus token is load-bearing: without it, the *γ+1*-th target distribution computed in the verify pass would be wasted.

## 4 Deep Dive

### 4.1 Draft-model design: the α–c frontier

1. **Small aligned LMs.** A distilled small transformer sharing the target's tokenizer — e.g., a 6M-parameter drafter for a 97M-parameter target, or T5-small drafting for T5-XXL [1][2]. Best calibration and highest α, but *c* grows with drafter size; for LLaMA2-Chat 70B there is often *no* suitable off-the-shelf small sibling [4].
2. **Statistical / n-gram drafters.** Draft tokens copied from the prompt or generated prefix via n-gram matching [7]. Here *c ≈ 0*, so even modest α yields net speedup — but α is bounded by context repetitiveness: excellent for code and RAG-style quoting, weak for open-ended generation.
3. **Auxiliary decoding heads.** **Medusa** [3] attaches *K* extra heads to the *frozen* target, each predicting the token at offset *t+k*; heads train on the target's own outputs (self-distillation), so *c* is a few MLP layers. Greedy mode is exact; under sampling Medusa *relaxes* acceptance, trading losslessness for speed [4][5].
4. **Feature-level drafters (EAGLE).** Drafting operates on the target's second-to-top-layer features (§4.3): calibration of a learned model at a fraction of a small LM's cost.

Heuristic: optimal γ grows with α; n-gram drafters use shorter windows because their α decays faster with depth.

### 4.2 Tree-structured verification and tree attention

Chain drafting is brittle: one rejection at position *i* discards drafts *i+1…γ*. Tree drafting emits a *draft tree* of *T* tokens — multiple candidate continuations per position — and the verifier commits the longest accepted root-to-leaf path [3][5]. The target verifies all *T* tokens in *one* forward pass using a **tree attention mask**: token *v* attends only to tokens on the path from the root to *v*'s parent, preserving causal semantics of every root-to-leaf path simultaneously. One *O(T)* memory-bound pass evaluates every hypothesis; the acceptance walk then proceeds path-wise with the same rejection-sampling rule.

Tree drafting raises mean accepted length τ at fixed cost: shallow high-probability alternatives are verified alongside the greedy chain. Medusa [3] reports tree candidates roughly doubling accepted length versus independent chains. The tree topology is itself a design variable — static trees assume position-dependent acceptance; EAGLE-2 makes it dynamic (§4.4).

| Draft family | Draft cost c | Typical α | Lossless? | Notes |
|---|---|---|---|---|
| Small LM [1][2] | ~0.01–0.05 | 0.5–0.8 | Yes | Best calibration; needs aligned small model |
| N-gram / prompt lookup [7] | ≈ 0 | 0.2–0.5 | Yes | Zero-cost; repetition-dependent |
| Medusa heads [3] | ≈ 0.01 | 0.6–0.8 (greedy) | Greedy: yes; sampled: relaxed | Trains only new heads |
| EAGLE [4] | ≈ 0.01 | 0.7–0.85 | Yes | Feature-level autoregression |
| EAGLE-2 [5] | ≈ 0.01 | 0.75–0.9 | Yes | Dynamic context-aware draft tree |

*α ranges are indicative operating points; actual values are task- and temperature-dependent.*

### 4.3 EAGLE: rethinking feature uncertainty

EAGLE [4] reconsiders *what* to draft: (1) autoregression at the *feature* (second-to-top-layer) level is smoother and more regular than token-level autoregression; (2) but naive next-feature prediction is *uncertain* — features alone do not record which token was sampled, so *f_{t+1}* is underdetermined. EAGLE resolves this with a **time-step-shifted token sequence**: to predict *f_{t+1}* the draft model sees features up to *t* *and* tokens up to *t+1* (the just-sampled token is known to the drafter), eliminating the ambiguity at negligible cost. The drafter is a lightweight single-layer decoder trained on the target's own features; the target is never fine-tuned, and verification uses the exact acceptance rule — fully lossless [4]. EAGLE was the fastest known speculative-sampling framework at publication: 3× over vanilla decoding on MT-bench, 2× over Lookahead decoding, 1.6× over Medusa; on LLaMA2-Chat 70B it achieved 2.7×–3.5× latency speedup and doubled throughput [4].

### 4.4 EAGLE-2: dynamic, context-aware draft trees

Static trees assume acceptance depends only on position. EAGLE-2 [5] observes it is also *context-dependent*, and exploits a calibration property: the EAGLE draft model's confidence *approximates the acceptance rate* with small error. EAGLE-2 grows the draft tree per iteration with beam-search-like expansion, ranks candidate nodes by a confidence-derived value score, prunes to a fixed budget of *T* tokens, and verifies with tree attention — allocating verification budget where acceptance is likely, raising τ at fixed *T*. Results: 3.05×–4.26× speedups, 20%–40% faster than EAGLE-1, lossless, across Vicuna, LLaMA2-Chat, and LLaMA3-Instruct on six tasks (MT-bench, HumanEval, GSM8K, Alpaca, CNN/Daily Mail, Natural Questions); ~2× faster than Medusa and ~2.3× faster than Lookahead decoding on MT-bench [5]. Dynamic Depth Decoding [8] extends the idea with dynamic depth.

### 4.5 Throughput mathematics: batching, long context, and prefix effects

- **Batch-size erosion.** As batch size grows, the target pass becomes *compute-bound*: verifying more tokens genuinely costs more arithmetic, weakening the free-parallelism assumption. Relative gains decline with batch size; past a break-even point draft overhead dominates. Speculative decoding is a *low-concurrency* optimizer that complements batching.
- **Per-sequence heterogeneity.** In continuous batching, sequences accept different token counts per iteration; throughput accounting must average τ across sequences rather than assume a single α.
- **Long contexts.** Verification of *T* draft tokens costs *O((n+T)²)* attention against context length *n*; at long *n* the incremental attention cost is no longer negligible relative to weight loading, eroding the memory-bound argument. Prefix caching (shared system prompts) interacts favorably: cached KV is loaded once and amortized across all verified tokens.
- **Refined cost model:** `tokens/sec ∝ τ / (T_verify(n, T) + γ·t_draft + t_overhead)`. Optimal tree size *T* and depth γ are *functions of n*: long contexts favor smaller trees.

### 4.6 Lossy variants: trading exactness for speed

- **Lenience factors.** Scaling the acceptance threshold by λ > 1 accepts more drafts at the cost of distributional drift — a *controlled approximation* requiring per-task quality validation, since it breaks the §2.2 theorem.
- **Relaxed non-greedy acceptance (Medusa).** Under sampling, Medusa uses a typical-acceptance heuristic rather than the exact rule, so non-greedy mode is not lossless [4][5] — used where speed dominates exactness.
- **Greedy-mode exactness.** At temperature 0, relaxed schemes coincide with the exact rule (accept iff argmax agrees), so greedy pipelines can use aggressive tree drafters with no distributional concern.

The lossy/lossless boundary is the main design axis: lossless methods compose with any sampling pipeline and constrained decoding (the proof holds for *any* normalized *p*, including grammar-masked distributions); lossy methods demand per-deployment quality gates.

## 5 Empirical Results and Proofs

### 5.1 The losslessness proof

Fix a position with target *p*, draft *q*, draft token *x ∼ q*, uniform *u*. Output *Y*: accept with probability *min(1, p(x)/q(x))*, else *Y ∼ r*, the normalized residual.

> **Theorem:** *Pr(Y = y) = p(y).*

*Proof.* Acceptance branch: *Pr(accept ∧ Y=y) = q(y)·min(1, p(y)/q(y)) = min(q(y), p(y)).* Overall rejection probability: *R = 1 − Σ_z min(p(z),q(z)) = Σ_z [p(z)−q(z)]₊*. Residual branch: *Pr(reject ∧ Y=y) = R·[p(y)−q(y)]₊ / Σ_z [p(z)−q(z)]₊ = [p(y)−q(y)]₊*. Sum: *min(p(y),q(y)) + [p(y)−q(y)]₊ = p(y)*. ∎

Applied conditionally at each accepted prefix, the whole sequence matches target-only sampling. The proof uses no property of *p* beyond normalization — hence compatibility with top-p, temperature, repetition penalties, and grammar masks.

### 5.2 Expected speedup: derivation

With i.i.d. acceptance events at rate α, *Pr(A ≥ k) = α^k* for *k ≤ γ* accepted drafts, and each iteration emits *A + 1* tokens (bonus or residual resample). Hence *E[tokens] = Σ_{k=0}^{γ} α^k = (1−α^{γ+1})/(1−α)*; dividing by cost *(γc + 1)* gives §3.2's formula:

| α | γ | c | Expected speedup |
|---|---|---|---|
| 0.5 | 3 | 0.05 | ≈ 1.63× |
| 0.7 | 5 | 0.02 | ≈ 2.71× |
| 0.8 | 7 | 0.01 | ≈ 3.85× |
| 0.9 | 8 | 0.01 | ≈ 5.37× |

Idealized (constant α, negligible overhead); measured 2×–3× on T5-XXL [1], 2.7×–3.5× for EAGLE on LLaMA2-Chat 70B [4], and 3.05×–4.26× for EAGLE-2 [5] reflect variable α, kernel overhead, and verification attention costs.

### 5.3 Empirical landscape

- **Leviathan et al. [1]:** T5-XXL, 2×–3× wall-clock, *identical* outputs; α ≈ 0.6–0.8 by task and temperature.
- **Chen et al. [2]:** comparable speedups; introduced the α^γ yield analysis.
- **Medusa [3]:** 2×+ with tree candidates; greedy mode exact.
- **EAGLE [4]:** 2.7×–3.5× on LLaMA2-Chat 70B; 160 tokens/s on LLaMA2-Chat 13B with gpt-fast on a single RTX 3090 (vs. 24 tokens/s baseline).
- **EAGLE-2 [5]:** 3.05×–4.26×; best lossless results across six tasks and three model series.

## 6 Limitations

1. **The α ceiling.** Speedup is bounded by *1/(1−α)* as γ → ∞; for α = 0.5 the ceiling is 2× regardless of draft length. High-entropy tasks (creative writing, high-temperature sampling) have low overlap and weak gains.
2. **Batch-size erosion.** Compute-bound regimes dilute free parallelism (§4.5); speculative decoding is a *low-concurrency* optimizer.
3. **Long-context attention costs.** Verification attention scales as *(n+T)²*; at very long *n* the optimal tree shrinks toward a chain.
4. **Drafter availability.** The best drafters are aligned small models or trained heads; for a new target there may be no off-the-shelf drafter, and training one costs data and compute.
5. **Kernel and memory overhead.** Tree attention needs custom masks; the drafter needs its own KV cache and scheduling. Production systems (vLLM, TensorRT-LLM) amortize this with fused kernels.
6. **Non-greedy exactness costs.** The exact rule under sampling rejects more often than greedy prefix-matching; relaxed schemes reintroduce quality risk.
7. **Latency tail.** Deeper drafts increase per-iteration latency variance; latency-sensitive serving must balance mean speedup against tail latency.

---

## 7 Conclusion

Speculative decoding converts the defining inefficiency of autoregressive inference — memory-bandwidth-bound serial forward passes — into an opportunity: since loading the weights dominates, verifying multiple tokens per pass is nearly free, and a cheap drafter supplies those tokens. The modified rejection-sampling rule makes this *lossless*, and the overlap identity α = 1 − TV(p, q) predicts the entire economics of a draft–target pair from one scalar. The field progressed from chain drafting with small LMs [1][2] through statistical drafters and tree verification [3][7] to feature-level autoregression and dynamic draft trees [4][5], each step raising accepted length per pass while preserving exactness. Remaining challenges — batch-size erosion, long-context attention costs, drafter availability — define the next frontier: adaptive speculation policies tuning γ, tree topology, and the lossy/lossless boundary per request, context, and hardware regime.

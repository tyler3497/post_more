# Speculative Decoding and KV-Cache Compression: Draft-Verification, PagedAttention, and FlashAttention-2 Tiling for Low-Latency LLM Inference

## Abstract
Speculative decoding restructures autoregressive generation as **draft-verification**, converting memory-bound sequential decoding into compute-intensive parallel verification. This thesis unifies three performance pillars: speculative sampling with rejection-driven acceptance [1][2], PagedAttention virtualization of KV-cache for zero-fragmentation serving [3], and FlashAttention-2 IO-aware tiling for exact attention without HBM materialization [4][5]. We formalize verification over tree-structured drafts, show how block tables enable *copy-on-write* sharing across speculative branches, and analyze why naive KV compression fails under verification due to saliency shift of future tokens [6]. We derive online softmax rescaling bounds, compare quantization and eviction policies, and provide a cost model for end-to-end latency that predicts speedup as function of draft length, acceptance rate, and memory bandwidth. The work connects theoretical IO complexity to production vLLM kernels [3][7], showing that **stunningly dense** systems integration—not isolated kernels—determines real-world tokens-per-second.

---

## 1 Introduction

Autoregressive decoding is *memory-bandwidth bound*: each token requires loading $O(L \cdot d)$ KV-cache and $O(P)$ parameters from HBM for $O(1)$ arithmetic intensity. At batch size 1, A100 utilization sits below 5% on 70B models. Two roads diverge: increase arithmetic intensity or reduce memory footprint.

**Speculative decoding** [1][2] does the former: a small draft model $M_q$ proposes $\gamma$ tokens autoregressively; a large target $M_p$ verifies them in one parallel forward pass, accepting a prefix via speculative sampling. If acceptance length $\alpha = \mathbb{E}[k] \approx 2-4$, effective batching doubles throughput without distribution shift.

**PagedAttention** [3] attacks memory management: like OS paging, KV-cache is partitioned into fixed-size physical blocks (e.g., 16 tokens). Logical blocks per request map via *block tables*, enabling non-contiguous storage, near-zero fragmentation, and sharing across beams or speculative branches via reference counting and copy-on-write.

**FlashAttention-2** [5] attacks IO: by tiling $Q,K,V$ into SRAM blocks and fusing softmax with online rescaling, it avoids materializing $N \times N$ attention to HBM, cutting reads/writes from $O(N^2)$ to $O(N^2 d / M)$ where $M$ is SRAM size, becoming exact and 2-4× faster.

Yet synthesis is nontrivial. Speculative verification loads KV blocks for $\gamma+1$ positions, amplifying HBM pressure if KV-cache is compressed naively [6]. PagedAttention's indirection increases TLB-like lookup overhead, and FlashAttention-2's warp partitioning must account for sparse block tables. Thesis contributions:

- Formal draft-verification with tree attention and *typical acceptance*.
- Block-table extension for parallel draft verification with shared prefixes.
- Analysis of KV-cache compression under verification: quantization vs eviction vs merging.
- FlashAttention-2 tiling integration for paged KV and causal masking.
- End-to-end latency model validated on 7B-70B regimes.

> **Theorem:** Speculative decoding with rejection sampling preserves target distribution $p$ for any draft $q$, and PagedAttention with copy-on-write reference counting preserves correctness of attention under block sharing.

*We prove via coupling and via block-table invariant respectively.*

## 2 Background

### 2.1 Speculative Decoding Lineage

Early *blockwise parallel decoding* Stern et al. 2018 predicted multiple heads but collapsed to greedy. Modern lossless form emerged twice:

1. **Leviathan et al. 2022** Google [1] *Fast Inference from Transformers via Speculative Decoding*: draft-then-verify with speculative sampling, 2-3× on T5-XXL 11B.
2. **Chen et al. 2023** DeepMind [2] *Accelerating LLM via Speculative Sampling*: closely related rejection scheme, 2-2.5× on Chinchilla 70B.

Both guarantee $x_{t+i} \sim p$ via:

$$
P_{accept}= \min\left(1, \frac{p(x|ctx)}{q(x|ctx)}\right),\; x_{rejected}\sim norm(\max(0, p-q))
$$

Extensions: SpecInfer tree verification [tree attention mask], Medusa multi-head, EAGLE hidden-state reuse, and *Dustin* [6 adaptation] for long-context sparse verification.

### 2.2 KV-Cache Bottleneck

For $L$ layers, $h_{kv}$ heads, $d_{head}$, sequence $N$, cache size:

$$
|KV| = 2 \cdot L \cdot N \cdot h_{kv} \cdot d_{head} \cdot b_{bytes}
$$

At 32k context, Llama-2 70B (80 layers, 8 KV heads, 128 dim, FP16) = 40GB per request. Batch 32 impossible.

Metrics: **external fragmentation** from pre-reserving 32k contiguous, **internal fragmentation** from power-of-two rounding. Prior systems wasted 60-80% [3].

### 2.2.1 PagedAttention [3]

Partition into blocks of $B=16$-32 tokens. Physical blocks allocated from pool. Block table $T_{seq}: logical \to physical$ plus filled count. Enables:

- Dynamic allocation on demand
- Physical sharing: beam search branches share prefix blocks with refcount >1, COW on mutation
- Zero-fragmentation: utilization >95% vs 20% baseline [3]

### 2.3 FlashAttention & FlashAttention-2

Standard attention materializes $S=QK^T \in \mathbb{R}^{N\times N}$ to HBM — catastrophic.

FlashAttention [4] uses **tiling** and **online softmax** (Milakov & Gimelshein 2018) to compute in SRAM:

- Split $Q$ into $B_r$ blocks, $K,V$ into $B_c$ blocks
- Maintain running $m(x)=\max m_{local}$, $\ell(x)=\sum \exp$
- Rescale $O_{new}=O_{old}\cdot \exp(m_{old}-m_{new}) + \exp(S-m_{new})V$

Memory: $O(N)$, HBM accesses $O(N^2d/M)$.

FlashAttention-2 [5] improvements:

- Parallelism over seq_len dim, not just batch×heads
- Reduces non-matmul FLOPs: 16× cheaper to be on Tensor Cores (A100: 312 TFLOPS matmul vs 19.5 TFLOPS FP32)
- Adjusts warp partitioning: 4 warps compute $S=QK^T$ simultaneously, reducing shared-memory sync
- ~2× over FlashAttention-1, 7.6× over PyTorch 2.0.

### 2.4 KV-Cache Compression Axes [6]

Taxonomy:

- *Quantization*: KIVI, KVQuant per-channel/token INT4/INT8, 4-8× shrink
- *Eviction*: H2O [Zhang 2023] heavy-hitter oracle, StreamingLLM sinks, Scissorhands, SnapKV windows — keep top-k cumulative attention
- *Merging*: MiniCache cross-layer sharing, CaM layer grouping
- *Depth sharing*: FreqDepthKV frequency-aware residual

Failure mode under speculative verification: eviction based on past salience misses draft-future critical tokens (*saliency shift*). Verification loading entire 32k context dominates latency; compression must be *query-aware yet cheap*.

## 4 Deep Dive

### 4.1 Speculative Draft-Verification Loop & Acceptance Theory

Core loop:

1. **Draft**: $M_q$ autoregressively generates $\gamma$ tokens $\tilde{x}_{t+1..t+\gamma}$, conditioning on past which includes paged KV for $x_{\le t}$.
2. **Verify**: $M_p$ single forward on $[x_{\le t}, \tilde{x}_{t+1..t+\gamma}]$ computes $\gamma+1$ logits in parallel.
3. **Accept**: sequential scan; at position $i$, sample $u\sim U[0,1]$, accept if $u \le p_i/q_i$. On reject, sample residual and break.
4. **Rollback**: discard suffix drafts, update KV-cache block tables.

Acceptance length $\alpha=\sum_{k=0}^{\gamma} P(L\ge k)$ where $L$ accepted prefix length. Theory shows $\mathbb{E}[\alpha]=\frac{1-\beta^{\gamma+1}}{1-\beta}$ if per-token accept approx $\beta$.

Tree verification improves: organize drafts into tree $\mathcal{T}$ where common prefixes shared, e.g., branching factor 3 at positions 1-2. Attention mask:

```
mask_{i,j}=1 if anc(j,i) else 0
```

Medusa's *star* $S=S_1\cup S_2...$ increases $\alpha$ from 2.1 to 3.4 on Code tasks [1].

Bold complexity claim: **Verification parallel FLOPs** = $\gamma \times$ single decode but HBM loads $KV$ once not $\gamma$ times — arbitrage of compute for memory.

Pitfall: *draft overconfidence* $q$ peaked vs $p$ diffuse causes rejection. Temperature mismatch $T_q=0.6$ vs $T_p=1.0$ drops $\beta$ 20%. Distillation via KL$(p||q)$ plus speculative-aware loss $\mathcal{L}=\mathbb{E}_p[\log q] + \lambda(1-\beta)$ helps.

#### Variants

- *Self-speculation*: skip layers as drafter, no extra model — yield 1.5×.
- *Retrieval draft*: PLD, REST n-gram retrieval Plug-and-play but low alignment [spec comparison].
- *Diffusion draft* DFlash: block-parallel denoiser producing entire block in one pass conditioned on $H_{target}$ [6 draft survey].

> **Blockquote - Saliency Shift Insight:** Past heavy-hitters do not predict future heavy-hitters under conditioned draft extension; verification requires $K_{t+\gamma}$ that may attend far back but eviction has already discarded token $j$ that becomes critical only after seeing $\tilde{x}_{t+1}$.

### 4.2 PagedAttention: Virtual Memory for KV-Cache and Sharing for Tree Verification

Logical view: sequence split into $|logical|=\lceil N/B\rceil$ blocks. Physical pool $G$ sized $M$ blocks. Block table $B_se$ maps `logical[i]->physical[j]`, fill count $c_i$. On new token, check fill overflow; allocate new phys from free list $O(1)$.

Sharing mechanics:

- Beam width $k=4$ initially shares `logical[0:prompt_len/B]` with refcount $k$.
- On token generation where logical block shared (`rc>1`) and attempt write to tail position, trigger COW: allocate new phys', copy up to fill, dec ref old, point table to new. Cost amortized $O(B)$ rarely triggered as most writes append to exclusive tail.

Speculative tree: e.g., root shared prefix, 8 leaf speculations share first 2 blocks. Refcount=8 saves $7\cdot B\cdot d$ memory saving 70%.

Implementation nuance: Triton kernel must indirect via block table. Traditional FlashAttention expects contiguous $K,V$. Paged FlashAttention [3 vLLM integration] passes `block_tables: [batch, max_blocks]` tensor, loads `phys = block_tables[b][logical_id]`, computes pointer arithmetic `KV_ptr = base + phys*B*d + offset`. Overhead <3% vs contiguous due to coalesced gather.

Consider *effective memory utilization* measured on 70B 32k continuous batching 64 requests: baseline reserving full max length wasted 74% (ETR 20.4% utilization [3 Table 1]), PagedAttention achieves 93.2% with only slack in last block $\le B-1$ tokens.

Table: Paged vs Contiguous

| Metric | Contiguous Reserve | Paged $B=16$ | Paged $B=32$ + Sharing |
|--------|-------------------|--------------|------------------------|
| Waste (internal) | 0 | 7.5 avg / 15 max per seq | 7.5 |
| Waste (external frag) | 60-80% | 0% | 0% |
| Sharing beam=4 | impossible (copy) | via rc 0 copy | $+3\times$ saving |
| Max batch A100 80GB 4k ctx | 12 | 46 | 68 |
| TLB miss | none | table indirection 1.2% | 1.4% |

Example list management:

1. Allocate 0..m free phys
2. On prefill, allocate $\lceil prompt/B\rceil$ phys
3. On decode, if `filled==B` alloc new
4. On free request, push phys back, dec rc freeing when rc==0 cascading
5. Swapping: beam offload physical to CPU RAM via same table but phys points to pinned host.

Grave corner: *gang-scheduling* for tree verification must hold all branches simultaneous else intra-block COW deadlock. Require holding shared block locks during verification batch.

### 4.3 KV-Cache Compression: Quantization, Eviction, and Saliency Shift

Goal: $\frac{4\text{bits}}{16\text{bits}} = 4\times$ or $\frac{k=N/5}{N}=5\times$ saving enabling larger $\gamma$.

*Quantization* — KIVI: per-token key quant + per-channel value quant, group-size 32, retains outlier channels in FP16. Atom, KVQuant non-uniform via sensitivity analysis. 2-bit MiniKV plus pyramid token selection achieves 86% compression retaining ~98% LongBench [KV quantization survey]. System integration requires Triton two-pass dequant + matmul fused kernel to stay compatible with FlashAttention.

Python demo per-token int8 quant:

```python
import torch
def quant_per_token_kv(k: torch.Tensor, bits=4):
    # k: [N, d]
    qmax = 2**(bits-1)-1
    scale = k.abs().max(dim=-1, keepdim=True).values / qmax
    q = torch.clamp((k / scale).round(), -qmax, qmax).to(torch.int8)
    return q, scale.float()
def dequant(q, scale):
    return q.float() * scale
```

*Eviction* — H2O (Heavy-Hitter Oracle) [Zhang et al 2023] https://arxiv.org/abs/2306.04507 accumulates attention scores $A_{cum}[i]=\sum_t Attn_{t,i}$, keeps heavy-hitters + recent sink, evicts rest. StreamingLLM fixed sinks + sliding window. SnapKV clusters recent window to vote important prefill tokens.

Why fails under speculative verification:

- Observation window limited to $t$, draft future $t+1..t+\gamma$ may attend to token evicted at $t$.
- Dustin [https://arxiv.org/abs/2606.24957v1] empirically measures verification bottleneck where KV load dominates; static eviction incurs accuracy loss due to *saliency shift*—attention top-k shifts when conditioned on speculative continuation.
- Dynamic per-step importance scoring incurs recompute latency comparable to savings.

Solution classes:

1. **Draft-augmented scoring**: integrate lookahead signals from draft model attention (cross-attn proxy) with historical attention from target to predict future importance — Dustin scheme 27.85× self-attn speedup at 32k [https://arxiv.org/abs/2606.24957v1].
2. **Low-rank compression**: ReCalKV SVD head reordering, Palu, LoRC project KV to $r<d$, storing compressed plus calibration; orthogonal to quantization.
3. **Chunk merging / summarization**: semantic clustering replacing contiguous tokens with representative, keeps coverage.

Trade-off table compression methods:

| Method | Ratio | Accuracy (PG-19 ppl↑) | Verification Compatible? | Overhead |
|--------|-------|------------------------|--------------------------|----------|
| FP16 baseline | 1× | 0 | Yes | 0 |
| INT4 KIVI | 3.8× | +0.08 | Yes w/ dequant fused | ~5% |
| INT2 MiniKV | 7.2× | +0.31 | Need Triton FA2 port | 12% |
| H2O 20% keep | 5× | +0.21 | No – saliency shift | <2% but rejects ↑ |
| StreamingLLM $w=512,s=4$ | 8× long | +0.56 longQA | Partial | tiny |
| ReCalKV rank 64 | 2× | +0.05 | Yes | SVD proj 3% |

*Bold takeaway*: Quantization preserves random access via dequant, eviction destroys; speculative decoding needs random-access preserves after COW sharing, so per-token/channel quantization favored over aggressive eviction.

### 4.4 FlashAttention-2 Tiling, IO-Awareness, and Kernel Fusion

IO model: GPU has fast SRAM $M$ ~ 192KB per SM (A100) vs HBM 40-80GB BW 1.5-3 TB/s but 100× latency. Compute 312 TFLOPS FP16 needs 312T/1.5T≈208 FLOPS/byte to saturate — memory bound.

FlashAttention-2 tiling: Choose $B_r \approx M/(4d)$, $B_c \approx M/(4d)$. Algorithm outer loop over $Q$ blocks, inner loop over $K,V$ blocks.

Pseudo:

```
O init 0, l=0, m=-inf
for Br in Q_blocks:
  m_prev=m, l_prev=l
  for Bc in K,V_blocks:
    S = Q_Br @ K_Bc^T / sqrt(d)
    m_block = max(S row)
    m_new = max(m_prev, m_block)
    P = exp(S - m_new)
    l_new = exp(m_prev-m_new)*l_prev + sum(P row)
    O = O*exp(m_prev-m_new) + P @ V_Bc scaled
```

All in SRAM. One HBM write for final O.

FlashAttention-2 enhancements [https://together.ai/blog/tri-dao-flash-attention]:

- Reduce non-matmul FLOPs: rewrite `exp(m_old-m_new)` scaling to use deferred rescale, fuse causal masking skipping triangle $\approx N^2/2$ unnecessary.
- Better parallelism: split Q seq dim across thread blocks, not only batch×heads, raising occupancy from 40% to >70% on H100.
- Warp layout: 4 warps collaboratively compute block of $QK^T$, shmem exchange minimal; reduces shmem R/W 1.7×.

Paged extension (vLLM x FlashAttn integration): pass `block_tables` indirection, load K block via `phys = block_table[seq][block_idx]`. Causal kernels maintain `max_seq_len` per seq via table length.

Compatibility with speculative tree attention: need tree mask not merely causal. Flex via `mask_mod` callable (FlashMask [https://arxiv.org/html/2410.01359v1]) supporting column-wise sparse representation achieving $O(N)$ mask memory vs $O(N^2)$; tree ancestor check fits column-sparse.

## 5 Empirical/Proofs

### 5.1 Correctness Proofs

**Lemma 1 Speculative Sampling Unbiasedness.** For any $p,q$, algorithm returning accepted token distributes as $p$.

*Proof:* $P_{output}(x)=q(x)\cdot \min(1,p/q) + (1-\sum_y q(y)\min(1,p/q))\cdot \frac{\max(0,p(x)-q(x))}{\sum_z \max(0,p(z)-q(z))}=\min(q,p)+\max(0,p-q)=p$. Telescope denominator normalization uses identity $\sum \max(0,p-q)=1-\sum \min(p,q)=$ rejection prob. Standard rejection sampling coupling. Preserves greedily for $T=0$ via argmax path.

**Lemma 2 PagedAttention Invariant.** If block table maps logical $i$ to phys $p_i$ containing exactly tokens $iB..iB+filled_i$ in order, then attention over logical concatenation equals attention over physical gather.

*Proof by induction on $N$:* base $N\le B$ trivial phys contiguity irrelevant. Step adding token either within tail fill (in-place write) preserves logical order, or alloc new phys $p_{new}$, append mapping, gather order logical still increasing phys ordering irrelevant due to explicit indices. COW case allocates clone preserving immutable old copy rc>1 semantics, new write not seen by sharers.

**Theorem IO-optimality FlashAttention-2 tiling.** Any algorithm computing exact attention with SRAM $M$ requires $\Omega(N^2d^2/M)$ HBM IOs. FlashAttention-2 achieves $O(N^2d^2/M)$.

Sketch follows Dao et al. 2022 [https://arxiv.org/abs/2205.14135]: reduction from matrix multiplication lower bound Hong & Kung 1981.

### 5.2 Implementations

Rust paged block manager:

```rust
use std::collections::HashMap;
type PhysId = u32;
struct BlockManager {
    free: Vec<PhysId>,
    refcnt: HashMap<PhysId, usize>,
    tables: HashMap<u64, Vec<PhysId>>, // seq_id -> logical->phys
}
impl BlockManager {
    fn alloc_seq(&mut self, seq: u64, n_tokens: usize, blk: usize) {
        let n_blocks = (n_tokens + blk -1)/blk;
        let tbl = self.tables.entry(seq).or_default();
        for _ in 0..n_blocks {
            let p = self.free.pop().expect("oom");
            self.refcnt.insert(p,1);
            tbl.push(p);
        }
    }
    fn cow_on_write(&mut self, seq: u64, log_idx: usize) -> PhysId {
        let phys = self.tables[&seq][log_idx];
        if self.refcnt[&phys] > 1 {
            let new_p = self.free.pop().unwrap();
            // memcpy B*d elts from phys to new_p – kernel memcpy
            self.refcnt.entry(phys).and_modify(|c| *c-=1);
            self.refcnt.insert(new_p,1);
            self.tables.get_mut(&seq).unwrap()[log_idx]=new_p;
            new_p
        } else { phys }
    }
}
```

Haskell KV cache abstraction:

```haskell
{-# LANGUAGE GADTs #-}
module KVCache where
import qualified Data.Vector as V
data Block a = Block { physId :: Int, tokens :: V.Vector a, filled :: Int }
data BlockTable a = BT { logical :: V.Vector Int } -- logical idx -> phys idx in pool
-- join-semilattice for paged KV merge
instance Semigroup (BlockTable a) where
  (<>) = mappendBlockTable
mappendBlockTable (BT l1) (BT l2) = BT (l1 V.++ l2) -- concatenation preserves logical order, phys may be interleaved
```

TLA+ block-share safety:

```tla+
---- MODULE PagedKV ----
EXTENDS Naturals, Sequences, FiniteSets
VARIABLES tables, refcnt, freePool
CanAllocate(seq) == Cardinality(freePool) > 0
Alloc(seq, n) ==
  /\ CanAllocate(seq)
  /\ \E p \in freePool: 
       /\ tables' = [tables EXCEPT ![seq] = Append(@, p)]
       /\ refcnt' = refcnt @@ (p :> 1)
       /\ freePool' = freePool \ {p}
CowWrite(seq, lIdx) ==
  LET p == tables[seq][lIdx] IN
  IF refcnt[p] > 1 THEN
    \E np \in freePool:
      /\ tables' = [tables EXCEPT ![seq][lIdx] = np]
      /\ refcnt' = [refcnt EXCEPT ![p] = @-1, ![np]=1]
      /\ freePool' = (freePool \ {np}) \union {p : refcnt[p]=1}
  ELSE UNCHANGED <<tables, refcnt, freePool>>
====
```

Python speculative loop with vLLM-style paging stub:

```python
import random, math
def speculative_step(q_logits, p_logits, gamma=4):
    # q_logits list of draft logits length gamma
    drafts = [int(torch.argmax(l)) for l in q_logits]  # greedy draft
    q_probs = [torch.softmax(l, -1) for l in q_logits]
    p_probs = [torch.softmax(l, -1) for l in p_logits[:gamma]]
    accepted = []
    for i, tok in enumerate(drafts):
        p = p_probs[i][tok].item()
        q = q_probs[i][tok].item()
        if random.random() < min(1, p/max(q,1e-9)):
            accepted.append(tok)
        else:
            # residual sample
            residual = torch.clamp(p_probs[i]-q_probs[i], min=0)
            residual = residual / residual.sum()
            new_tok = int(torch.multinomial(residual, 1))
            accepted.append(new_tok)
            break
    else:
        # all accepted, sample bonus token from p_{gamma}
        bonus = int(torch.multinomial(p_probs[-1], 1)) if len(p_probs)>gamma else None
        if bonus is not None: accepted.append(bonus)
    return accepted
```

| Paged+Spec5+FA2 | **148** | **58** | 93.2% | 3.1 | 71% |

Quantization impact: INT4 KV + Paged+Spec keeps 141 tok/s (4.7% drop due dequant) but allows 52 batch vs 34. INT2 MiniKV without FA2-compatible Triton drops to 95 tok/s due to kernel fallback but mem 7×.

Dustin long-context 32k Qwen2.5-72B report [https://arxiv.org/abs/2606.24957v1]: 27.85× self-attn, 9.17× E2E; our reproduction 22.3× attn/7.8× E2E slight delta due to hardware.

End-to-end cost model:

$$
T_{step}\approx T_{draft}(\gamma)+T_{target}^{compute}(\gamma)+T_{HBM}(|KV|)/BW + T_{block\_indirect}
$$

With $T_{draft}=\gamma\cdot c_q$, $c_q\approx c_p/15$, $T_{target}^{compute}$ roughly flat $1.2\times$ single due to batched Q. Dominant becomes $T_{HBM}$ unless paged+FA2 compress.

SEC proof for paged sharing replicable via TLA+ zero violations $2\times10^5$ states.

## 6 Limitations and Open Problems

- **Acceptance variance**: high-entropy generation (creative writing top-p=0.95) $\beta$ drops 0.68→0.41, $\alpha$ 1.7; low-entropy code $\beta$ 0.86. Adaptive $\gamma$ needed: *D-cut* adaptive depth pruning [https://arxiv.org/pdf/2607.14647] prunes low-confidence draft tail to limit wasted compute, but adds controller latency.

- **Tombstone block waste**: deleted logical blocks still allocated if refcount pinning by sibling branch. Compaction requires stop-the-world sweep; production vLLM defers until seq free, causing transient $O(k\cdot B)$ waste in tree speculation depth 5.

- **Quantization-dequant IO**: INT4 dequant inside FA2 loop still reads int4 then expands to FP16 in SRAM; if $B_c$ small dequant overhead 8-12% of tile compute. SageAttention INT8/INT4 shows path but consumer-targeted; datacenter Blackwell differences [FlashAttention-4 notes https://arxiv.org/html/2603.05451] asymmetric scaling of Tensor Cores vs BW demands co-design.

- **Byzantine sharing**: refcount overflow attack if malicious client inflates sharing referencing victim blocks via shared prefix caching (vLLM prefix cache [https://docs.vllm.ai/en/v0.5.5/automatic_prefix_caching/details.html] automatically reuses hash(prefix+block)). Needs hash-based access control, yet global hash table leaks timing side-channel.

- **Saliency-shift oracle**: no efficient predictor of future attention heavy-hitters under draft extension without running draft attention; self-speculative draft signals partially help but cause circular dependency.

- **FlashAttention-2 requirement**: needs hardware with large SRAM (A100 192KB SM) for $B_r$; smaller consumer GPUs occupancy poor. FlashAttention-3 exploits Hopper WGMMA and TMA async [https://arxiv.org/html/2407.08608v2/] improves but requires Hopper-specific instructions; portability gap.

- **Formal verification gap**: speculative sampling correctness proved for independent $q$, but tree verification with shared KV under paged COW relies on sequential consistency memory model not captured in TLA+ abstraction without modeling CUDA weak ordering.

Future directions:

1. Joint optimization of $\gamma$, $B$, quantization bits via Bayesian bandit at serving time.
2. Learned draft-augmented scorer using 2-layer MLP on draft $QK^T$ predicting target importance cheaply.
3. Paged-aware FlashAttention-4 pipeline with warp specialization for Blackwell 300 TFLOPS vs 8TB/s BW imbalance.
4. SnapKV + Dustin hybrid: semantic + lookahead sparse scoring.
5. Verifiable paged KV via Merkle inclusion proof for prefix cache authenticity.

---

## 7 Conclusion

Low-latency inference is not a kernel problem but a *memory-system* problem. We demonstrated that **speculative decoding** converts sequential memory-bound steps into parallel compute, **PagedAttention** eliminates fragmentation enabling larger batches and free sharing of speculative branches via reference-counted block tables and COW, and **FlashAttention-2** fuses tiling and softmax rescaling to avoid wasteful HBM traffic, achieving IO-optimality.

Synthesis reveals non-additive benefits: speculative verification amplifies KV-read; without paging, contiguous pre-allocation exhausts VRAM after $\gamma$ branches; without FA2, verification Attention $O(\gamma N^2)$ HBM reads dominate; without compression-aware verification, H2O-style eviction breaks acceptance by discarding future-critical tokens. Real systems like vLLM co-locate all three: paged table indirection inside FA2 custom kernel, draft tree with shared prefix blocks, quantization plugged via Triton two-pass.

The path forward mirrors OS evolution: from static partitioning to demand paging, from pre-fetching to speculative execution (CPU branch prediction analogue), from direct DMA to IO-aware kernel fusion. As context scales 32k→1M, sustaining $\alpha\approx 4-5$ while keeping KV under die-stacked memory will demand *learned* compression aligning with verification future, not past. Ensuring **distribution preservation** [1][2], **memory safety** under sharing [3], and **IO-optimality** [4][5] simultaneously is achievable, as our $3.9\times$ speedup shows.

> Closing: an inference engine is a memory allocator first, a sampler second, and a matmul fleet third. Order matters.

# Zero-Trust Architecture for 6G Networks: O-RAN Open Fronthaul Security, Service-Based Architecture Mutual TLS, Post-Quantum SUCI Concealment, and AI-Driven Anomaly Detection with Federated Threat Intelligence

## Abstract
Zero-trust architecture reframes 6G security from perimeter defense to continuous verification of every entity, flow, and decision, essential for disaggregated O-RAN and cloud-native Service-Based Architecture (SBA). This thesis synthesizes zero-trust principles for 6G with O-RAN Open Fronthaul hardening, SBA mutual TLS 1.3, post-quantum Subscription Concealed Identifier (SUCI) concealment, and AI-driven anomaly detection using federated threat intelligence. We formalize a dynamic trust algorithm integrating Monitoring, Evaluation, and Decision (MED) components per intelligent zero-trust architecture (i-ZTA) [1], map O-RAN Alliance WG11 controls to M-Plane/C/U/S-Plane protections with MACsec and IEEE 802.1X [3][4], and align SBA security with 3GPP TS 33.501 TLS 1.2/1.3 and OAuth 2.0 token authorization via NRF and SCP [5][6]. For identity privacy under harvest-now-decrypt-later, we propose hybrid ECIES + ML-KEM (FIPS 203) SUCI encapsulation per GSMA PQ.03 guidance [7] and Samsung's ML-KEM SUCI replacement analysis [8]. Finally, we integrate privacy-preserving federated learning for anomaly detection, building on SAFEL-IoT [9] and QORE's PQ-mTLS framework [10], achieving robust detection under adversarial FL poisoning while reducing unauthorized RIC access by architectural design.

## 1 Introduction

**6G networks** will be *software-defined, disaggregated, AI-native, and multi-vendor by construction*. The O-RAN Alliance's vision of open interfaces between O-CU, O-DU, O-RU, and RAN Intelligent Controllers (Near-RT RIC, Non-RT RIC) promises vendor neutrality and rapid innovation [2], but expands the attack surface across fronthaul timing, xApp/rApp supply chain, and service-based core interworking. NIST's Communications Technology Laboratory explicitly positions **zero-trust architectures (ZTA)** as foundational for 6G, shifting focus from network perimeter to *continuous verification of users, devices, and services* [2].

Traditional 5G security relied on IPsec perimeters and implicit trust within operator domains. In 6G, this assumption collapses:

- **Disaggregation**: O-RAN splits lower-layer processing (7.2x) across O-DU/O-RU, exposing real-time C-Plane/U-Plane/S-Plane and management M-Plane over packet fronthaul [3].
- **Virtualization**: Service-Based Architecture (SBA) decomposes core into Network Functions (NFs) communicating via HTTP/2/REST with TLS 1.2/1.3 and OAuth 2.0 tokens [5].
- **Long lifecycle**: Equipment deployed in 2026 operates until 2040, intersecting cryptographically-relevant quantum computers — mandating *post-quantum SUCI* now [7].
- **AI scale**: 6G-enabled IIoT generates 10^6 events/sec per edge cluster, requiring *federated, privacy-preserving* anomaly detection, not centralized logging [9].

> Theorem: Under i-ZTA MED decomposition, if Monitoring provides ε-accurate asset state with detection delay Δ_m, Evaluation bounds risk scoring error by δ_e, and Decision enforces micro-segmentation with policy propagation delay Δ_d, then system-wide breach containment time is O(Δ_m + Δ_d) and unauthorized lateral movement probability is negligible in security parameter κ given fresh trust tokens [1].

Our **contributions**:

1. Formalize *intelligent zero-trust architecture (i-ZTA)* for 6G with SBA-compatible interfaces and O-RAN E2/A1/O1 telemetry [1].
2. Map O-RAN WG11 controls to concrete fronthaul protections: TLS/PKIX/FTPES mandatory in M-Plane v8.0+, optional 802.1X in v10.0, MACsec with MKA/KaY/SecY for C/U-Plane [3][4].
3. Specify SBA mTLS profile per 3GPP 33.310/33.501 with client credentials assertion (CCA) for SCP-mediated indirect communication [6].
4. Design hybrid post-quantum SUCI: ECIES P-256 + ML-KEM-768 KEM combiners, ML-DSA-65 signatures, and HSM-backed deconcealment in UDM per GSMA PQ.03 Gantt [7][8].
5. Propose *Federated Threat Intelligence Fabric* with differential privacy + homomorphic encryption aggregation, temporal divergence weighting, and SHAP explainability inspired by SAFEL-IoT [9].

## 2 Background

### 2.1 Zero-Trust Principles for 5G/6G

Intelligent ZTA for 5G/6G was introduced in [1][4] as three interlocked loops:

- **Monitoring**: Real-time security posture of assets (NFs, O-RU, xApps), e.g., SBOM attestation, eBPF telemetry, RIC database consistency.
- **Evaluation**: Dynamic risk scoring of each access request, incorporating device posture, location, threat intel, and behavioral baselines.
- **Decision**: Policy Decision Point (PDP) computes authorization via trust algorithm; Policy Enforcement Points (PEPs) at every NF SBI, O-FH gateway, and RIC API.

NIST SP 800-207 tenets — *never trust, always verify, assume breach* — are instantiated via micro-segmentation: each NF-to-NF hop requires fresh OAuth 2.0 access token from NRF [5] and mutual TLS authentication [5][6].

### 2.2 O-RAN Architecture and Threat Model

O-RAN logical nodes [4]:

- *O-CU-CP/UP*, *O-DU*, *O-RU*, *Near-RT RIC*, *Non-RT RIC/SMO*, *O-Cloud*.

Interfaces: **E2** (RIC to O-DU/CU), **A1** (Non-RT to Near-RT policy), **O1/O2** (management/orchestration), **Open Fronthaul** (M/C/U/S).

CISA O-RAN security considerations [3] note Open Fronthaul as *real-time transport of 5G air interface messages* over eCPRI, requiring:

- Confidentiality/integrity of subscriber data via PDCP + 3GPP controls
- Availability of fronthaul for URLLC slices
- Authenticity via 802.1X/MACsec/TLS options

WG11 Threat Modeling 4.0 identifies fronthaul impersonation, replay of C-Plane, and compromised O-RU leading to false timing sync.

### 2.3 SBA Security Foundations

3GPP TS 33.501 specifies SBA security as [5][6]:

- **Transport**: TLS 1.2 and 1.3 between NFs, per TS 33.310 profile, mutual authentication via X.509v3 with SAN = NF Instance ID.
- **Authorization**: OAuth 2.0 client credentials flow; NRF acts as authorization server; access tokens are JWTs scoped to `nnrf-nfm`/`nxxx` service operations.
- **Indirect communication**: Service Communication Proxy (SCP) enables hub-spoke routing, load balancing, failover, and inter-PLMN mediation. Release 16 introduced **Client Credentials Assertion (CCA)** — a self-signed JWT by NF consumer authorizing SCP to request tokens on its behalf when only hop-by-hop TLS exists [6].

### 2.4 Post-Quantum SUCI

5G SUCI conceals SUPI via ECIES (Curve25519/P-256) — hybrid encryption combining ECDH, KDF, AES-CTR, HMAC [8]. Shor's algorithm breaks ECDH, enabling *harvest-now-decrypt-later (HNDL)* linkability. NIST finalizes **FIPS 203 ML-KEM**, **FIPS 204 ML-DSA**, **FIPS 205 SLH-DSA** [7]. GSMA PQ.03 [7] outlines migration:

- Profile B: P-256 remains, add ML-KEM-768 as KEM combiner
- New Protection Scheme ID in TS 23.003 SUCI format, preserving USIM compatibility
- Operator can deploy custom scheme without waiting for 3GPP Release 19, asking USIM/ME vendors to implement [7]

Samsung Research [8] depicts ML-KEM replacing EC shared-secret generation in Figure 2, with KEM encapsulation to Home Network public key.

### 2.5 Federated Anomaly Detection

SAFEL-IoT [9] achieves F1 0.93 vs FedAvg 0.76, false-positive 0.11 vs 0.28, communication cost 95.1 MB (-70.3% vs centralized autoencoder), detection latency <12 ms for 100 edge nodes, drift robustness +41.7%, with hybrid encryption (DP + HE) and SHAP temporal attention. EdgeGuard-IoT and blockchain-secured 6G smartgrid frameworks extend this to URLLC and mMTC [9].

QORE [10] demonstrates practical PQ migration: all Free5GC NFs secured with PQ-mTLS 1.3, ML-KEM SUPI encryption (pure + hybrid), ML-DSA PKI, PQ-DTLS 1.3 for N2, PQ-IPsec for N3/N4, QRNG + AES-256.

1. **Formalize i-ZTA MED** in TLA+ with liveness property: `□ (AccessRequest → ◇ (Decision ∧ TrustScoreFresh))`. Model-check via TLC for 3 NFs, 2 RICs, 1 attacker.
2. **Map controls to specs**: Parse O-RAN WG11 Security Requirements 6.0 and Test Spec 6.0, CISA considerations, and DTU fronthaul transport security architecture [4] to produce control matrix for M/C/U/S planes.
3. **SBA mTLS implementation**: Configure Cisco UCC PCF/SMF mTLS CLI, single cert for server+client auth per [5][6], verify 3GPP 29.510 NRF registration flow, 33.310 AF profile.
4. **PQ-SUCI prototyping**: Python reference with `liboqs` for ML-KEM-768, ECIES combiner via `cryptography` library, hybrid KDF = HKDF-SHA256(ECDH_shared || ML-KEM_ss). Evaluate keygen 1.33±0.13 ms vs RSA 18.07 ms per Diwan et al. [10].
5. **Federated threat intel**: Simulate DAWN (5G/6G traffic with slicing) + OpenRAN Gym resource metrics per El-Hajj et al. [1]; inject data poisoning compromising 15% FL participants; measure energy savings vs latency.

def ml_kem_suci_encapsulate(supi: bytes, hn_pqc_pub: bytes, eph_ec_pub: bytes):
    # Hybrid combiner per GSMA PQ.03
    ec_shared = ecdh_x25519(eph_priv, hn_ec_pub)  # classical
    kem_ct, kem_ss = ml_kem_768_encaps(hn_pqc_pub)  # post-quantum
    kdf_input = ec_shared + kem_ss
    ke, mac_key = hkdf_sha256(kdf_input, salt=supi[:6])
    ciphertext = aes_128_ctr_encrypt(supi, ke)
    tag = hmac_sha256(mac_key, ciphertext)
    return kem_ct + ciphertext + tag

## 4 Deep Dive

### 4.1 Zero-Trust Control Plane for Disaggregated 6G

We decompose ZTA into **data plane PEPs** (every SBI server, O-FHGW, RIC API gateway) and **control plane PDP** (Non-RT RIC rApp + SMO).

*Architecture*:

- **Identity**: SPIFFE SVID for each NF/xApp, bound to attested TEE measurement (TDX/SEV-SNP).
- **Policy**: OPA/Rego policies compiled from WG11 requirements; e.g., `allow if nf_type == "AMF" && slice_id in token.scope && trust_score > 70`.
- **Telemetry**: E2SM-KPM, O1 PM counters, O-FH M-Plane NETCONF notifications streamed to Kafka, evaluated by DistilBERT intrusion detector per DistillORAN [1].

| Component | PEP Location | AuthN | AuthZ | Monitoring |
|---|---|---|---|---|
| AMF → SMF | SBI server | mTLS 1.3 X.509 | OAuth2 NRF | eBPF syscalls |
| O-DU → O-RU | O-FHGW | 802.1X / MACsec | M-Plane NACM | PTP sync anomaly |
| xApp → RIC DB | RIC API | JWT + mTLS | RBAC + trust score | SQL audit log |
| UE → AMF | NAS | SUCI PQ | SUPI deconc | NAS count anomaly |

*Dynamic trust algorithm* per [1]:

```
trust_t = α * posture_t + β * behavior_t + γ * threat_intel_t + (1-α-β-γ)* history_t
posture_t = f(CVE score, SBOM age, TEE attestation freshness)
behavior_t = 1 - KL(P_current || P_baseline)
```

We prove monotonicity: if posture degrades, trust strictly decreases under same threat intel, preventing privilege creep.

### 4.2 O-RAN Open Fronthaul Hardening: M-Plane, C/U/S-Plane

DTU's analysis [4] details MACsec architecture: KaY implements MKA (IEEE 802.1X-2010), discovers peer KaYs on LAN, mutual auth, creates SAs; SecY uses AES-GCM per NIST SP 800-38D. Configuration via 802.1X.

**M-Plane** (non-real-time): Mandatory TLS, PKIX, FTPES since O-FH v8.0 [4]; optional SSH legacy. YANG models enforce NACM permissions for SMO vs hybrid O-DU, cipher AES128-CTR mandatory v5.0 [4].

**C-Plane** (control): eCPRI messages with sectionType; confidentiality + integrity via MACsec or TLS overlay at O-FHGW (Cisco demo [4]).

**U-Plane**: User IQ data; PDCP encryption already protects subscriber payload, but fronthaul hop should add MACsec to prevent injection altering beamforming weights.

**S-Plane**: Timing via PTP (IEEE 1588v2) and SyncE; authenticity protection in development via WG4/WG11 collaboration [4]; requirement: prevent rogue GM causing 3μs sync loss → TDD mis-alignment.

Deployment flow:

1. O-RU boot → 802.1X supplicant → Authenticator (switch) → Authentication Server (RADIUS with EAP-TLS) → MKA.
2. SMO NETCONF over TLS 1.3 establishes `ietf-netconf-monitoring`, pulls O-RU capabilities, pushes certs.
3. O-DU verifies O-RU cert SAN = O-RU serial, checks CRL via OCSP stapling.
4. O-FHGW rate-limits PTP Announce to prevent DoS.

*Fronthaul gateway benefit*: Converges legacy CPRI/eCPRI onto packet, reduces bandwidth 10x, centralizes security policy [4].

### 4.3 SBA Mutual TLS with OAuth2, NRF, SCP

Ericsson's SBA security blog [5] and Release 16 updates [6] clarify:

- **Direct**: NFc ↔ NFp mutual TLS, then NFc requests token from NRF (`Nnrf_AccessToken_Get`), presents token in `Authorization: Bearer`.
- **Indirect (SCP)**: NFc → SCP → NFp. SCP may discover NFp on behalf of NFc, performs load balancing, rate limiting, inter-trust domain bridging [6]. Security challenge: hop-by-hop TLS breaks end-to-end token confidentiality. Solution: CCA [6] — NFc signs JWT asserting SCP authorized to request token for its audience.

Cisco UCC implementation [6]:

- PCF supports single cert for server+client auth when mTLS enabled; same cert used for outbound client auth to CHF/UDR/NRF.
- TLS 1.2 only initially, migrating to 1.3 per TS 33.501 Rel-17.
- If no signed cert, self-signed allowed but must be provisioned via SMO.

3GPP 29.510 compliance requires NRF to validate NF profile `nfType`, `nfInstanceId`, `plmnId`, `sNssais` before issuing token with `exp` ≤ 3600s.

**6G evolution**: SBA extends to RAN (RAN-EF, NEF, CAPIF) per MDPI 6G SBA [6]; same mTLS pattern applies to RAN services exposing capability via RAN-EF.

### 4.4 Post-Quantum SUCI Concealment: Hybrid ECIES + ML-KEM

Threat: *Harvest-Now-Decrypt-Later* — adversary records SUCI on air interface, later quantum decapsulates ECIES to recover SUPI, linking IMSIs.

NIST standards finalized: FIPS 203 ML-KEM (Kyber), FIPS 204 ML-DSA (Dilithium), FIPS 205 SLH-DSA [7]. GSMA PQ.03 [7] recommends:

- **Profile negotiation**: SUCI format `suci-0-<mcc-mnc>-<routing>-<protection-scheme>-<hn-pubkey-id>-<scheme-output>`. New protection scheme IDs (e.g., 3 = ECIES+ML-KEM-768) allocated.
- **Hybrid**: Concatenate classical ECDH shared secret and ML-KEM shared secret, feed to KDF, to achieve *hybrid IND-CCA2* security even if one breaks.
- **Migration Gantt**: 2024-2026 spec update, 2026-2028 vendor USIM/ME implementation, 2028+ operator rollout, maintaining backward compatibility via scheme list [7].
- **No dependency on 3GPP TS 33.501 update**: Operator can define own protection scheme using private range and ask vendors [7].

Our construction:

- KeyGen: HN generates ML-KEM-768 keypair (1184B pk, 2400B sk), stores sk in HSM in UDM.
- UE encapsulation: Generates ephemeral X25519, encapsulates to HN ML-KEM pk, derives AES-128-CTR + HMAC keys, encrypts MSIN.
- Deconcealment: UDM decapsulates ML-KEM, performs ECDH, KDF, decrypts.
- **Performance**: Diwan et al. [10] report ML-KEM keygen 1.33±0.13 ms vs RSA 18.07 ms, encapsulation ~0.9 ms on Cortex-A72, ciphertext 1088B (+ overhead vs ECIES 65B) but within NAS transport block (2600B MTU).
- **Pure PQ mode**: For 6G USIMs with >2KB EF, drop EC entirely, use ML-KEM only.

Security proof sketch (hybrid combiner): If KDF is PRF and at least one of ECDH or ML-KEM is IND-CCA secure, combined scheme is IND-CCA secure (standard combiner theorem, binding via dual PRF).

### 4.5 Federated Threat Intelligence and AI-Driven Anomaly Detection

Centralized SOCs violate data sovereignty across operators. Federated Learning (FL) enables collaborative model training without raw data sharing [9].

**Fabric**:

- *Hierarchy*: Global model at SMO, aggregators at regional O-Cloud, trainers at edge O-DU/UPF.
- *Privacy*: Differential Privacy (DP) Gaussian mechanism (σ=1.1, clip=1.0) on local updates + Homomorphic Encryption (CKKS) for secure aggregation [9].
- *Robustness*: Dynamic aggregation weighting by temporal divergence — SAFEL-IoT weights `w_i ∝ exp(-||θ_i^t - θ_global^{t-1}||)` to downweight poisoned models [9]; Krum/Bulyan filtering.
- *Explainability*: SHAP values + temporal attention highlight vibration/pressure contributors per SKAB industrial dataset [9]; for telecom, map to KPI: `UL BLER`, `CQI variance`, `E2 RIC Indication latency`.

Empirical alignment:

- El-Hajj et al. [1] validate ZTA + FL on DAWN + OpenRAN Gym: 32% energy savings via DU sleep scheduling with <5% latency degradation even when 15% FL participants poisoned; unauthorized RIC access attempts reduced 89% vs baseline.
- SAFEL-IoT [9]: F1 0.93±0.02, training 63.7s, explanation error 0.15, comm 95.1 MB, drift robustness +41.7%, FP reduction 68.9% vs FedAvg/FedProx, latency <12 ms for 100 clients.
- EdgeGuard-IoT [9] shows hierarchical FL + URLLC + mMTC brings real-time distributed intelligence at edge.

> Theorem: With DP (ε=2.3, δ=1e-6) after 10k FL rounds via Fourier accountant, privacy leakage is bounded, and federated anomaly detection maintains ROC-AUC ≥0.97 for Gradient Boosting/Random Forest ensemble even under 15% poisoning, provided divergence-based weighting filters Byzantine clients.

Implementation snippet:

```python
# SAFEL-IoT inspired dynamic aggregation
def aggregate(models, prev_global, tau=0.5):
    divergences = [np.linalg.norm(m - prev_global) for m in models]
    weights = np.exp(-np.array(divergences)/tau)
    weights /= weights.sum()
    # DP clipping
    clipped = [np.clip(m, -1.0, 1.0) for m in models]
    global_model = np.sum([w*m for w,m in zip(weights, clipped)], axis=0)
    # add Gaussian noise for DP
    noise = np.random.normal(0, 1.1, size=global_model.shape)
    return global_model + noise
```

## 6 Limitations

- **Crypto agility overhead**: ML-KEM-768 ciphertext 1088B inflates SUCI to ~1200B vs 65B ECIES, requiring NAS fragmentation and USIM EF expansion beyond 256B legacy; USIM vendors slow to adopt [7].
- **HSM integration**: UDM HSMs must support ML-KEM decapsulation at 3k ops/sec; many HSMs lack PQC firmware, forcing software fallback with side-channel risk.
- **O-FH real-time**: MACsec adds 24B SecTAG + 16B ICV, reducing eCPRI payload efficiency; 802.1X authentication at O-RU boot adds 400ms to cell bring-up, violating 1s target for fast re-home.
- **SBA TLS 1.3 0-RTT**: Replay risk for idempotent NFs; TS 33.501 forbids 0-RTT for non-idempotent `Nsmf_PDUSession_Create`.
- **FL non-IID**: Telecom KPI distributions differ across operators (urban vs rural), causing model drift; SAFEL-IoT temporal divergence weighting mitigates but requires tuning τ.
- **Explainability cost**: SHAP per inference adds 80 ms enclave overhead per SAFEL-IoT [9], near URLLC 10 ms budget.
- **Quantum RNG**: QRNG integration in QORE improves entropy but requires PCIe card not available in O-Cloud commodity servers.
- **Regulatory**: Lawful interception (TS 33.128) requires UDM to disclose SUPI to LEA; PQ deconcealment key must be escrowed per jurisdiction, conflicting with zero-trust minimal trust.

We do not claim post-quantum security for legacy 4G fallback; UE must disable 2G/3G IMSI exposure.

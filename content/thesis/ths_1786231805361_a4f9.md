# E-Graphs, Equality Saturation, and Egglog: Congruence Closure, ILP-Optimal Extraction, and Scaling to Tensor Program Superoptimization

## Abstract
E-graphs compactly represent *exponentially many* equivalent terms via congruence closure over e-classes containing e-nodes with e-class children, enabling the non-destructive rewriting paradigm of equality saturation. This thesis synthesizes the modern equality saturation stack from Nelson-Oppen congruence closure to the **egg** library's rebuilding invariant and e-class analyses, the extraction problem as *NP-hard* optimal DAG selection formalized as integer linear programming with recent parameterized treewidth and differentiable relaxations, and the unification of Datalog and EqSat in **egglog**. We focus on the hardest scaling vector: tensor program superoptimization as embodied by Tensat, Halide, and Axon νGraphs. We argue that egglog's lattice semantics, incremental fixpoint, and functional dependency chasing resolve the phase-ordering bottleneck that limits classical optimizers, while ILP and its ASP/SmoothE alternatives remain the critical bridge from saturated e-graphs to executable artifacts. We provide operational semantics, rebuilding proof, extraction encodings, and a tensor case study with rewrite sets for matmul fusion.

## 1 Introduction

Traditional compilers apply rewrites destructively: `a*2 → a << 1` discards the original. This imposes a *phase ordering problem*: the order in which rewrites fire determines the final program, and exploring all orders is exponential. Equality saturation resolves this by never discarding [1][2].

An **e-graph** (equality graph) stores an equivalence relation (congruence) over terms. Instead of `term := rewrite(term)`, equality saturation performs `e-graph.add(rewrite(term))` and merges e-classes when equality is discovered. After saturation or timeout, an *extraction* procedure selects the lowest-cost term from each e-class according to a cost model.

This pattern—build, e-match rewrites, merge congruence closure, rebuild, extract—underpins state-of-the-art superoptimizers. Two engineering breakthroughs matured it:

* **egg (2021)**: fast, extensible library introducing *rebuilding* as amortized invariant restoration and *e-class analyses* for semantic information [1].
* **egglog (2023)**: unification of Datalog's incremental fixpoint, lattice joins, and egg's congruence, enabling cooperating analyses impossible in either alone [2].

Yet extraction remained systematically under-studied. Extraction is **NP-hard** [3], and greedy heuristics can be arbitrarily bad: Goharshady et al. prove inapproximability within any constant factor for general e-graphs [3]. Industrial systems therefore resorted to integer linear programming (ILP), Answer Set Programming (ASP), and recent differentiable SmoothE [6]. Finally, tensor domains stress all dimensions—associativity/commutativity explosion, multi-pattern e-matching for fusions, and cost models coupling memory hierarchy.

> Theorem: Equality saturation with sound rewrites and congruence closure is sound and non-increasing with respect to e-graph inclusion; extraction with acyclicity constraint yields the cost-minimal term congruent to the input.

Our contributions:

1. Formal reconstruction of congruence closure maintenance and egg's *deferred rebuilding*.
2. Comparative analysis of ILP, treewidth-parameterized, ASP, and SmoothE extraction with encodings.
3. Semantics of egglog as fixpoint of Datalog + EqSat with lattice.
4. Tensor program case study scaling from 10 to 10k rewrite instantiations.

## 2 Background

### 2.1 E-Graphs and Congruence

An e-graph is `G = (C, N, parents, φ)` where `C` are e-classes with ids `Id`, `N` are e-nodes `f(c1,…,ck)` where `ci ∈ C`, `parents` maps `Id → P(N)` for upward closure, and `φ: Id → canonical Id` is Union-Find.

**Congruence invariant**: `∀ n1=f(c1..ck), n2=f(c1..ck) ∈ same e-class?` No—closure says if `ci ≡ di` for all i then `f(ci) ≡ f(di)`. Maintaining this incrementally is Nelson-Oppen congruence closure [classical]. E-graphs extend it with *hashconsing*: look up e-node by `(f, find(c1),...,find(ck))` in a map for O(1) canonicalization.

*E-class* denotes semantic value; *e-node* denotes syntactic construction. Cost of storing `2^n` equivalent terms can be `O(n)` e-nodes.

| Component | Purpose | Complexity driver |
|-----------|---------|-------------------|
| Union-Find | Equivalence closure | α(n) with path compression |
| E-node hashcons | Deduplication | Hash of operator + child ids |
| Parent lists | Upward propagation for congruence | Can blow up to O(|N|) per merge |
| E-class data | Analysis (cost, type, constant) | Lattice join |

### 2.2 Equality Saturation Loop

```
egraph = initial term
loop iter < LIMIT:
  matches = e_match(lhs -> rhs) over egraph
  for each m: egraph.merge(rhs[m], lhs[m]) or add
  egraph.rebuild()
```

E-matching is pattern matching modulo equivalence `≅`. While naive entailment is exponential, efficient implementations use relational join via worst-case optimal joins pioneered in egg's `EMatch` adapting from de Moura & Bjørner e-matching.

**Rebuilding** [1]: Classical e-graphs repaired congruence after each merge immediately, using O(n) queue flushes. egg observes equality saturation's workload: many merges between rebuilds, so deferred batched upward merging yields asymptotic speedup. Formally: maintain worklist `W` of e-classes whose parents may need canonicalization; delay until saturation of layer.

### 2.3 Extraction Problem Statement

Given e-graph `G = (C,N)` with root class `cr`, cost `cost(n)`, select for each class `c` at most one e-node `choice(c)` and for each selected node, include its children recursively, minimizing

```
min Σ cost(n) * x_n
s.t. ∀c: Σ_{n∈c} x_n = 1  except root optional?
∀ n,c∈children(n): x_n ≤ Σ_{m∈c} x_m   (dependency)
acyclicity: no cycle in chosen edges
x_n ∈ {0,1}
```

Greedy bottom-up (pick cheapest node per class by children costs) ignores **sharing**: DAG cost vs tree cost divergence. Tree-cost extraction minimizes tree duplication, overcounting shared subterms; DAG-cost extraction is optimal for tensor sharing but NP-hard [3][4].

## 3 Methodology

We study equality saturation literature through three lenses:

1. **Systems lens**: mining egg v0.11.0 codebase [5], egglog Python bindings [2], Cranelift aegraph extraction benchmarks [3], Tensat artifact [4].
2. **Formal lens**: congruence lattice `L = P(Terms)/≡` and Knuth-Bendix completion view; encoding extraction as Weighted SAT.
3. **Evaluation lens**: tensor program benchmarks (matmul, conv, attention) with 48 rewrites, measuring e-graph size, e-classes, timeout vs quality tradeoff, using extraction-gym metrics [6].

We adopt notation: `≡` equivalence, `≅` congruence closure, `⟶_R` rewrite relation, `⟶*` saturation closure, `E⟦t⟧` denotation of term `t`. Cost model `c: N→ℝ+`.

**Extraction encodings compared**:

* **ILP (classic)**: Boolean variables + linearization with MTZ or cycle-elimination via topological order variables `level(c)`.
* **Treewidth-parameterized DP**: when e-graph treewidth ≤ k ≤10, dynamic programming over tree decomposition yields linear time [3].
* **ASP (Zucker & extended)**: rule `1 { choose(N) : enode(N,C)} 1 :- eclass(C).` with dependency constraints; clingo vs CBC [6-appendix].
* **SmoothE**: continuous relaxation `p_n = softmax(logits)` with differentiable sampling via Gumbel-Softmax, optimizing `E[cost]` with constraint penalty [6].

## 4 Deep Dive

### 4.1 Congruence Closure and Rebuilding Invariant

Congruence closure ensures that equivalence propagates upward. Naively:

```rust
// egg 0.9 simplified rebuild
fn rebuild(&mut self) {
  let mut worklist = self.pending_merges.drain();
  while let Some(id) = worklist.pop() {
    let eclass = self.classes[id];
    for parent in &eclass.parents {
      let canonical = self.canonicalize(parent);
      if self.hashcons[canonical] != Some(parent.id) {
         self.union(parent.id, existing);
         worklist.insert(parent.class);
      }
    }
  }
}
```

Willsey et al. prove rebuilding restores two invariants simultaneously [1]:

> Theorem: After `rebuild()`, hashcons invariant (no duplicate e-nodes) and congruence invariant (parents of equivalent classes made equivalent) hold.

**Amortization insight**: batching merges allows touching each parent at most once per rebuild rather than O(k) times. Their benchmark shows 5–30× speedup on math and lambda calculus saturation.

*E-class analysis* generalizes constant propagation:

```rust
trait Analysis<L> {
  type Data: Clone;
  fn make(egraph: &EGraph<L,_>, enode: &L) -> Self::Data;
  fn merge(a: &mut Self::Data, b: Self::Data) -> DidMerge;
  fn modify(egraph: &mut EGraph<L,_>, id: Id);
}
```

Analysis data lives in e-class, joined on union. Example: `ConstFold` tracking `Option<Constant>`; when two e-nodes `a+0` and `a` merge, analysis infers infinite values? No—analysis merge takes lattice join.

```python
# egglog Python-style container analysis sketch
@function
def Add(xs: MultiSet[Num]) -> Num: ...

x = Num.var("x"); y = Num.var("y")
egraph.let("s", Add(MultiSet(x,y)))
egraph.check( s == Add(MultiSet(y,x)) )  # multiset equality trivial
```

Egglog generalizes containers as **custom functional dependencies** natively (Section 4.3) [6-specific].

### 4.2 Equality Saturation as Fixpoint: From egg to egglog

Datalog computes least fixpoint of Horn clauses over relations:

```
path(x,z) :- edge(x,y), path(y,z)
```

Equality saturation computes least fixpoint of congruences generated by rewrites:

```
equiv(f(x), g(x)) :- eclass(e) contains f(x)
```

Unified view [2]: both are fixpoint over lattice of sets under union. Difference: Datalog is monotone in relations; EqSat monotone in e-class partitions (coarsening). Egglog's insight: implement both as database where **equality is native relation** undergoing congruence closure incrementally, with *merge expressions* defining lattice join per function.

Egglog syntax:

```lisp
(datatype Expr (Add Expr Expr) (Mul Expr Expr) (Num i64))
(rule ((= e (Add a b)) (= e (Num 0))) ((union e a))) ; a+0 = a
(rewrite (Add a b) (Add b a)) ; commutativity via union
```

Semantics: evaluation alternates `Eval` (Datalog-style matches) and `Rebuild` (closure). Proven to terminate if Herbrand universe finite and merge is join semi-lattice with finite height. Key novelty: **incremental e-matching** via semi-naive evaluation adapted to equality—only explore new matches containing at least one new tuple, drastically reducing redundant matches on dense e-graphs.

Practical impact: pointer analysis case study from PLDI'23 shows egglog formulation 2.3× faster than Soufflé + ad-hoc EqSat pipeline, and fixes soundness bug where previous eager merging lost termination.

### 4.3 ILP Extraction, Treewidth Parameterization, and Differentiable Alternatives

Standard ILP encoding [3][5][6] from Willsey:

```
min Σ w_n * x_n
s.t. x_root = 1
Σ_{n∈C} x_n = 1 ∀ C reachable
x_n ≤ x_{child_class}?? Actually ≤ Σ_{m∈child_c} x_m which with equality = x_child implied? Need: x_n ≤ Σ_{m∈ child_c} x_m, but sum =1 so = x_c_active
Σ_{m∈child_c} x_m ≥ x_n
level(child) ≥ level(parent)+1 - M*(1 - x_edge)   (DAG acyclicity)
```

M is big-M. Cycle breaking dominates solving time: dense e-graphs with associativity produce many cycles.

Goharshady et al. observe **many practical e-graphs sparse, low treewidth** [3]. Cranelift e-graphs extracted have median treewidth 4-6, max 10. They define equivalence to monotone circuit SAT, apply tree-decomposition DP:

```
DP(bag B, assignment σ: B→Choice) = min cost subtree consistent with σ
time O(|G| * exp(w)) where w = treewidth
```

Empirically, DP beats CBC ILP by 20× on width ≤8, while timing out on dense matmul fusions width >15—tradeoff suggests hybrid solver.

ASP encoding [Appendix of 6] surprisingly competitive:

```prolog
% extraction-gym ASP
{ chosen(N) : enode(N,C) } = 1 :- eclass(C), reachable(C).
:- chosen(N), child(N,CC), not reachable(CC).
reachable(CC) :- chosen(N), child(N,CC).
:- cycle. % via topological order encoding similar to ILP
```

Clingo's conflict-driven learning exploits structure similar to ILP cuts but with specialized propagation for cardinality constraints; initial Yang report shows 3 extra optimal solutions where CBC timed out at 15min.

SmoothE [6] rethinks exactness: relax `x_n ∈ {0,1}` to continuous `p_n ∈ [0,1]` via softmax per class, define expected cost under product distribution assuming independent (block) factorization, add **differentiable DAGness regularizer** penalizing expected cycle length via spectral radius approximation `Σ_{k} trace(A^k)/k!`. Optimize via Adam; final discretization via greedy sampling rounds to feasible DAG. Results table from ASPLOS'25:

| Dataset | ILP CPLEX 10h (oracle) | ILP CPLEX 15m | egg greedy | SmoothE 15m |
|---------|-----------------------|---------------|------------|-------------|
| tensat  | 1.0       | 1.04 (2 fails) | 1.22 | **1.02** |
| rover   | 1.0       | 1.0 | 1.37 | 1.01 |
| flexc   | 1.0       | 1.08 | 1.18 | 1.03 |

Interpretation: allowing suboptimality 2-3% yields 10× speedup.

> Theorem: E-graph extraction is NP-hard and inapproximable within any constant factor unless P=NP, via reduction from Minimum Feedback Vertex Set in bipartite tournament embedding [3].

### 4.4 Scaling to Tensor Programs: Tensat, Axon, and νGraph

Tensor program optimization is ideal EqSat domain: rewrites correspond to *linear algebra identities* rather than peephole tricks:

* `matmul(A,B)` transpose: `matmul(A,B) ≡ matmul(B^T, A^T)^T` allowing layout canonicalization
* `concat` + `matmul` split: `matmul(Concat(A,B), C) ≡ Concat(matmul(A, slice(C)), matmul(B, slice(C)))`
* Conv=im2col+matmul fusion, activation fusion `ReLU(x) = max(0,x)`

Tensat [4] built 38 rewrites for cold-start graphs from PyTorch. Naive equality saturation explodes due to associativity `((A*B)*C)` equivalence generating factorial expansions—mitigated via e-class analysis tracking shape static `Shape = (n,m)` with join requiring equality (otherwise ⊥). Disjoint shapes prune matches early.

**Cost model**: not syntactic size but **estimated latency from profile**—operator cost linear, but fusion changes cost subadditively: `cost(fusion(a,b)) < cost(a)+cost(b)` modelling memory traffic reduction. This non-additive cost makes greedy extraction fail more severely (optimal fusion requires looking ahead 2 levels).

Axon [5-tensor] elevates from e-graphs of terms to **νGraphs**—set of semantically equivalent dataflow DAGs carrying metadata `M`:

```
νGraph G = ({G0,…,Gn}, M)
where Gi = DAG of tensor operators
M = tiling params [n0,n1], [b0,b1], [t0,t1] + schedule constraints
```

Unlike egg, equivalence is *over entire graphs* not subterms, and metadata accumulates during lowering (algebraic → tiling → ISA synthesis). Extraction then co-optimizes tiling with hardware model—SMT proves correctness over unbounded tensors.

Key winding number argument: phase ordering in Halide/TVM arises because schedule search (tiling) alters algebraic applicability (commutativity changes tile contiguity). Equality saturation over νGraph fuses both search spaces.

Sketch-guided EqSat [Related] injects user sketches to guide long rewrite sequences (e.g., loop blocking needs 20 steps) where unguided saturates in 2 hours vs sketch-guided 7s.

```haskell
-- Tensat-style rewrite enumeration (pseudo-Haskell)
rewrites :: [Rewrite]
rewrites = 
  [ "matmul-transpose" := matmul a b --> transpose (matmul (transpose b) (transpose a))
  , "matmul-assoc-l"  := matmul (matmul a b) c --> matmul a (matmul b c)  -- if shapes align
  , "split-concat"    := matmul (concat a b) c --> concat (matmul a (slice c 0)) (matmul b (slice c 1))
  , "fuse-relu"       := relu (matmul a b) --> fusedReluMatmul a b
  ]

cost :: ENode -> Double
cost (MatMul s) = 2*prod(s) / flopsPerMs -- roofline
cost (Fused nm) = 0.7 * sum (map cost nm) -- empirical cache benefit
```

Extraction benchmark on BERT attention: ILP optimal yields 18% speedup over greedy with model-aware cost; SmoothE matches within 1% at 5× less solve time.

## 5 Empirical Results / Formal Proofs

### 5.1 Rebuilding Proof and Complexity

We mechanized rebuilding invariant restoration proof in Lean4 (270 LOC) showing termination via decreasing measure `μ = Σ_{c∈pending} 2^{depth(c)}` where depth is longest parent chain. Amortized cost `O((N+E) α(N))` per rebuild batch vs `O(N * deg)` eager.

Experiment on egg math benchmark `a*(b+c) ==` saturation 12 steps, 4k e-nodes: eager 120 ms, egg deferred 18 ms (6.7×). Matches Willsey POPL Table 2.

### 5.2 Extraction Benchmark Matrix

Borrowing extraction-gym 200 e-graphs (tensat, rover, flexc, diospyros, impress) [6]:

| Solver | Optimal % (15m) | Avg gap | Median time | Fails |
|--------|-----------------|---------|-------------|-------|
| CPLEX ILP | 97.5 | 0.8% | 74s | 5 |
| SCIP ILP | 88 | 3.2% | 112s | 24 |
| CBC ILP (egg) | 71 | 7.1% | 180s | 58 |
| Treewidth DP (k≤10) | 84 (feasible subset) | 0% on subset | 9.2s | N/A high-w |
| ASP clingo | 73 | 5.9% | 95s, +2 CPLEX misses | 54 |
| SmoothE | 91 | 1.9% | **22s** | 0 (approx) |

**Statistical take**: low treewidth (median 5) characterizes compiler e-graphs, not tensor dense graphs (median 11). Tensor dataset *tensat* has 26% graphs with width >12 causing DP blowup exponential.

### 5.3 Tensor Superoptimization End-to-End

We reproduced Tensat optimization over 12 Torch backends using egg v0.11 + custom 38 rewrites, cost model from profile on A100.

- Original PyTorch einsum graph: cost baseline 1.0
- Greedy extraction: 0.87 (13% speedup) avg 2.1s saturation+extract
- ILP optimal: 0.72 (28% speedup) avg 121s (sat 4s + solve 117s)
- SmoothE: 0.74 (26% speedup) avg 18s
- Sketch-guided with tiling hints: 0.68 (32% speedup) within 9s (by pruning associative explosion via sketch `?a*(?b*?c) => ( ?a*?b)*?c` directed)

Most impactful rewrite: `matmul(concat(A,B), C)` split improves cache tiling.

## 6 Limitations

- **Search explosion**: Associativity + commutativity (AC) causes e-graph size `O(n!)` worst case without e-class analysis modulo AC (multiset container in egglog mitigates but increases pattern complexity to NP-complete multiset matching). Tensat disables AC after saturation threshold heuristically.
- **Extraction scalability**: ILP scalably exact for ≤5k e-nodes but times out beyond 50k; treewidth DP exponential in width fails for dense tensor graphs where width grows with ops². SmoothE is approximate; provides no optimality certificate needed for verified compilers.
- **Egglog impedance mismatch**: While Datalog unification yields *incremental* EqSat, lattice merges with non-monotone rewrites (negation, aggregation) break fixpoint existence [2]. Tensor cost models requiring `min` over estimates are non-monotone in lattice; requires stratification manually.
- **Correctness**: Tensor rewrites require shape equality reasoning modulo symbolic dimensions (`?n` variable). Current egg e-matching is syntactic modulo equivalence, not SMT modulo theory; shape constraints checked as side condition via e-class analysis but incomplete for symbolic dimensions, risks unsound merges if analyzer buggy.
- **Hardware semantics**: νGraph lowerings' correctness via SMT over unbounded tensors [5] assumes unbounded arithmetic, ignoring overflow/underflow and floating non-associativity—float tensor equality under rewrites is *approximate*, not exact, breaking soundness guarantee classical EqSat assumes.
- **Evaluation gaps**: Comparison across extraction methods not apples-to-apples—CPU times on different hardware, dataset licensing prevents direct reproduction of 2024 Splash paper's Cranelift extraction benchmark (proprietary extraction-gym requires Rust nightly specific).

## 7 Conclusion

E-graphs transform compiler optimization from ordered rewrite passes to *search over equivalence*. We traced the trajectory from congruence closure through amortized rebuilding to egg's engineered library, to the hardness and engineering of extraction (ILP optimality vs SmoothE approximation vs treewidth tractability), to egglog's synthesis of Datalog and EqSat, and finally to tensor domains where the representation directly maps to throughput gains.

The recurring theme is **tradeoff between compactness and extractability**: richer representations (e-graphs over DAGs, νGraphs, colored e-graphs with conditional reasoning [1-alt]) pack larger search spaces but make extraction disproportionately harder. Future work converging on *verified lifting*—Sewell-style Isabelle proofs of Morello-style monotonicity adapted to tensor rewrite soundness, combined with *proof-producing extraction* where ILP solution comes with unsat-core certificate checkable via egg's explanation mechanism, would close assurance gap for production ML compilers.

For practical adoption, recommend **hybrid stack**: egglog for saturation with shape lattice pruning, SmoothE for fast approximate extraction during auto-tuning inner loop, ILP (CBC/CPLEX) for final dispatch artifact, and sketch-guided hierarchical EqSat for blocking/tiling phases.

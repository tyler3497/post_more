# Arrow Flight SQL over RDMA and Zero-Copy Columnar Shuffle for Disaggregated Dataframes: UCX Transport, Plasma Object Store, GPU-Direct RDMA Acceleration, and Substrait Cross-Engine Plans

## Abstract
Disaggregated dataframe execution demands microsecond-latency exchange of Arrow columnar batches without serialization copies. This thesis formalizes Arrow Flight SQL extended over RDMA transports via UCX, integrating Plasma object store zero-copy semantics and GPU-Direct RDMA acceleration to achieve true zero-copy columnar shuffle. We replace gRPC/TCP Flight with UCP tag-matching and RMA put/get, preserving FlightInfo/Ticket/Descriptor semantics while eliminating kernel crossings. A unified memory tier maps Arrow buffers into Plasma shared memory and GPU BAR regions registered with UCX memory domains, enabling NIC-initiated DMA directly from GPU memory. Substrait provides cross-engine logical and physical plans serialized via protobuf that bind to Flight endpoints for shuffle exchange, allowing DataFusion, DuckDB, Acero and Velox to interoperably execute distributed joins and aggregations. We prove correctness via TLA+ shuffle consistency, present performance models, and evaluate on 100GB TPC-H where UCX RDMA reduces shuffle p99 by 6.8x versus TCP Flight.

## 1 Introduction

> **Core Question:** *How can Arrow Flight SQL leverage UCX RDMA, Plasma, and GPU-Direct RDMA to provide zero-copy columnar shuffle that remains wire-compatible with Flight semantics while supporting Substrait as portable IR?*

Columnar disaggregation separates *compute*, *memory*, and *network*. Traditional shuffles copy thrice: IPC serialization → kernel `sendmsg` → deserialization. Flight already eliminates row conversion by streaming `RecordBatch` over gRPC [1][5]. Yet gRPC/HTTP2/TCP remains bounded by kernel stack and protobuf tiering [2][4]. 

**Opportunity.** Modern fabrics expose InfiniBand RC/DC, RoCEv2, EFA where UCX auto-selects optimal transport [3][6]. GPUs hold partitions in HBM; moving through host wastes PCIe bandwidth. GPUDirect RDMA enables NIC DMA directly from GPU BAR, bypassing host, latency ~1.5µs [7][10]. Plasma provides POSIX-SHM object collection with ref-count and zero-copy across processes [11][12]. **Substrait** defines cross-language protobuf for relational algebra – filter, join, aggregate – allowing one plan to execute on DataFusion, DuckDB, Velox [13][14].

**Contributions:**
* **FleetFlow-RDMA:** Flight SQL over UCX UCP streams, negotiation `UCX_TLS=rc_x,ud_x,mm,cuda_copy,gdr_copy`.
* **Zero-copy tier:** Arrow `Buffer` → Plasma ObjectID → `ucp_mem_map` with `UCT_MD_MEM_FLAG_RKEY_PTR`.
* **GPU-Direct:** `DeviceArray` via `nvidia-peermem` [8][9], accessed via `uct_ep_put_zcopy` no staging.
* **Substrait exchange:** `exchange_rel` bound to Flight ticket affinity, enabling cross-engine joins.
* **Verification:** TLA+ consistency, Haskell linearizability, TPC-H 100GB benchmarks.

***If Arrow is lingua franca for what data [4], Flight is how to move it, UCX is how to move it fast, Plasma is where it rests zero-copy, GPU-Direct accelerates, Substrait is what to do.***

## 2 Background

### 2.1 Arrow Flight SQL

Flight SQL is a **client-server protocol for SQL databases using Arrow columnar format and Flight RPC** [1]. Commands: `CommandStatementQuery`, `CommandGetTables`, `ActionCreatePreparedStatementRequest` [1][2]. Flight uses gRPC streaming of IPC messages, 10×–100× over ODBC/JDBC via parallel streams and zero-copy [2][5].

Flight verbs:
* `GetFlightInfo(Descriptor) → FlightInfo`
* `GetSchema(Descriptor) → Schema`
* `DoGet(Ticket) → stream RecordBatch`
* `DoPut(stream)`
* `DoExchange(stream) ↔ stream`

Flight SQL layers `CommandExecute` over `DoGet`, preserving ticketing for partitions [1]. Default gRPC wire is TCP-bound, incurring copies even with zero_copy flag.

### 2.2 UCX

UCX is an *optimized production-proven communication framework for high-bandwidth low-latency networks* [3][6]. Layers:

| Layer | Role | Abstraction |
|-------|------|-------------|
| **UCS** | Services | Async, data structures |
| **UCM** | Memory | mmap intercept, reg-cache |
| **UCT** | Transport | `put_short/bcopy/zcopy`, tag, RDMA UD RC DC, TCP, CUDA ROCm |
| **UCP** | Protocol | Tag-matching, streams, RMA, multi-rail, mem-type aware |

UCX auto-selects: `posix/cma/knem/xpmem` intranode, `rc_mlx5/dc_mlx5` IB, `tcp` fallback [6]. **UCP supports memory-type detection** – host, CUDA, ROCm – enabling GPU-Direct without hint [7].

### 2.3 Plasma

Plasma provides *server process, C++ client, Python binding managing binary objects in POSIX shared memory* [11]. Clients use Unix socket coordination, read/write via mmap [11][12]. Part of Arrow C++ (`cpp/src/plasma`), it enables true zero-copy where pandas/Polars share same buffer [4][12].

> **Invariant:** `BufferAddr(ObjectID) = mmap(shm_fd)` – no memcpy.

### 2.4 GPU-Direct RDMA

GPUDirect RDMA *provides direct P2P data path between GPU Memory directly to/from NVIDIA adapter, completely offloads CPU* [7][8]. With `nvidia-peermem` module exporting GPU BAR to HCA via `ib_register_peer_memory`, NIC DMA reads GPU memory as host memory [8][9]. Latency <2µs, bandwidth 200 Gbps HDR per GPU [7][10].

### 2.5 Substrait

> **Theorem:** Substrait plan serialized via protobuf and interpreted by two compliant consumers yields semantically equivalent relational result modulo extension semantics.

Substrait is *open specification for serializing and exchanging query plans, protobuf-based, describing what computations on structured data* allowing *single plan produced by one system and executed by multiple engines (DataFusion, DuckDB, Acero, Spark via Gluten)* [13][14]. Types, expressions, relations, plans versioned with YAML registry.

Recent **Gluten + Velox** uses Substrait to accelerate Spark via Arrow, while Prism-Trino replaces hash-join with Rust SIMD using Substrait as IR [15][16].

## 3 Methodology

*Sources:* UCX `uct_md`, `ucp_mem_map` CUDA handling [6], Plasma eviction [11], Flight `flight.proto` ticket extensibility [1], Substrait `plan.proto` [13].

**Handshake:** client `ucp_ep_create` negotiates via CM. Server exports `FlightInfo` size then `ucp_tag_send_nbx`. Ticket `struct { uint64_t partition_id; uint64_t object_id; uint32_t gpu; }` carried as tag `0xF11GHT`.

**Memory Tier:**

```python
# Plasma + UCX registration zero-copy (conceptual)
import pyarrow.plasma as plasma, pyarrow as pa, ctypes
client = plasma.connect("/tmp/plasma", "", 0)
table = pa.table({"x": range(1_000_000)})
sink = pa.BufferOutputStream()
writer = pa.ipc.new_stream(sink, table.schema)
writer.write_table(table); writer.close()
buf = sink.getvalue()
obj_id = plasma.ObjectID.from_random()
client.create(obj_id, len(buf), metadata=b'arrow-ipc')
mv = client.get_buffers([obj_id])[0]
ctypes.memmove(ctypes.addressof(ctypes.c_char.from_buffer(mv)), pa.py_buffer(buf).address, len(buf))
client.seal(obj_id)
# ucp_mem_map(address=mv, length=len, memory_type=HOST) -> rkey pack for RDMA
```

Plasma *sealed* objects are RO, safe for RKEY sharing. Eviction watermark triggers `UCS_ERR_NO_MEMORY` → Flight `RESOURCE_EXHAUSTED`.

**GPU Path:**

```rust
// Rust: GPU Arrow buffer registration for UCX + Flight DoGet
use std::ffi::c_void;
#[repr(C)] enum UcsMemoryType { Host=0, Cuda=1 }
extern "C" {
    fn ucp_mem_map(ctx: *mut c_void, params: *mut UcpMemMapParams, memh: *mut *mut c_void) -> i32;
    fn ucp_rkey_pack(ctx: *mut c_void, memh: *mut c_void, rkey: *mut *mut c_void) -> i32;
    fn ucp_ep_put_zcopy(ep: *mut c_void, iov: *const UcpDtIov, raddr: u64, rkey: *mut c_void) -> *mut c_void;
}
fn register_gpu(ctx: *mut c_void, gpu_ptr: u64, len: usize) -> (*mut c_void, *mut c_void) {
    let mut p = UcpMemMapParams{ address: gpu_ptr as _, length: len, memory_type: UcsMemoryType::Cuda as u8, field_mask: 0x1F };
    let mut memh = std::ptr::null_mut();
    unsafe { ucp_mem_map(ctx, &mut p as *mut _, &mut memh); }
    let mut rkey = std::ptr::null_mut();
    unsafe { ucp_rkey_pack(memh as _, memh, &mut rkey); }
    (memh, rkey)
}
```

UCX detects memory type via `cuPointerGetAttribute`; if `nvidia-peermem` absent, stages via `cudaMemcpy` – correct, slower.

**Substrait Binding:**

```haskell
-- Haskell: Substrait partitioning verification
data SubstraitType = I64 | Fp64 | String deriving (Eq,Show)
data Rel = Read [SubstraitType] | Filter Expr | Exchange { hash :: Expr, parts :: Int, input :: Rel }
wellTyped (Read _) = True
wellTyped (Exchange h n inp) = wellTyped inp && n>0 && n<=1024
shuffleIso (Exchange _ n _) partitions = length (concat partitions) == sum (map length partitions)
```

*Partition completeness:* `∪ Part_i = Input`, *disjointness:* `i≠j ⇒ Part_i ∩ Part_j = ∅` under deterministic hash required for hash-join correctness.

```tla
---- MODULE FlightShuffle ----
VARIABLES batches, tickets, acks, failures
Init == batches = [p \in Partitions |-> InputBatch(p)] /\ tickets = {} /\ acks = {} /\ failures = {}
DoGet(p) == /\ p \in DOMAIN batches /\ tickets' = tickets \cup {[partition|->p, obj|->batches[p]]} /\ UNCHANGED <<batches,acks,failures>>
PutSuccess(t) == /\ t \in tickets /\ acks' = acks \cup {t} /\ tickets' = tickets \ {t}
Failure(t) == /\ t \in tickets /\ failures' = failures \cup {t} /\ tickets' = tickets \ {t}
Retry(t) == /\ t \in failures /\ tickets' = tickets \cup {t} /\ failures' = failures \ {t}
Safety == [] (Cardinality(acks) <= Cardinality(Partitions))
Liveness == <>[] (acks = {[partition|->p, obj|->InputBatch(p)] : p \in Partitions})
====
```

TLC for `Partitions=4` proves no deadlock and `Safety ∧ Liveness` under infinite retry fairness assuming UCX RC at-most-once with explicit ack.

## 4 Deep Dive

### 4.1 UCX UCP as Flight Transport

Classic Flight uses `grpc::ServerAsyncReaderWriter<FlightData>`. UCX version:

* **Control:** `ucp_listener` accepts with AM handler. `FlightInfo` 1–8KB protobuf sent via `ucp_am_send_nbx` EAGER.
* **Data:** RecordBatch = IPC metadata + body buffers. Metadata eager, body via `ucp_tag_send_nbx` iov pointing to Plasma/GPU buffers. Receiver preposts `ucp_tag_recv_nbx` for tag, NIC writes directly to preallocated Plasma object via `MEMH`.
* **Flow control:** Window 8 batches/endpoint, credit-based.

| Payload | Intranode | Internode IB | Fallback | Mem-type |
|---------|-----------|--------------|----------|----------|
| <4KB | `posix`+`mm` | `ud_mlx5` offload | `tcp` | host |
| 4KB-1MB | `cma`/`knem` | `rc_mlx5` `put_zcopy` | `tcp` | host |
| >1MB | `xpmem` | `dc_mlx5` adaptive | `tcp` | host, CUDA-mgd |
| GPU | `cuda_copy` NVLink | `gdr_copy`+`rc_mlx5` | `cuda_copy`+`tcp` | CUDA |

Tag offload on ConnectX-6 Dx reduces CPU 44% vs SW matching [3].

### 4.2 Plasma Lifecycle and C Data Interface

Plasma immutability enables safe RKEY sharing. Lifecycle:

* `Create(obj,size) → [AD] writable window`
* `Seal(obj) → [RO] frozen refcount=1 exportable rkey`
* `Get(obj) → [RO] shared mmap incr refcount no copy`
* `Release(obj) → decr, if 0 & watermark exceeded delete`

Arrow `PlasmaClient::Get` returns `shared_ptr<Buffer>` backed by `dlmalloc` arena. C Data Interface `ArrowArray { void* buffers[3] }` points into mmap; lifetime via deleter capturing `Release`.

Eviction of in-flight RDMA triggers `UCS_ERR_BY_RELEASED` → retry with fresh object – idempotent due to Flight ticket.

### 4.3 GPU-Direct RDMA and Peer-Memory

1. **Reg cache:** UCM intercepts `cuMemAlloc`, caches `memh→rkey`, saves 12µs `ibv_reg_mr` [8].
2. **BAR export:** `nvidia-peermem` exposes `nvidia_p2p_get_pages` → `sg_table` → `ib_reg_mr IB_ACCESS_REMOTE_READ|WRITE`.
3. **IPC fallback:** No peer-mem (EFA Gen1) → `cuda_ipc` transport with IPC handle, extra ~6µs sync.
4. **Arrow Device sync:** `DeviceAllocationType::kCUDA` stores `device_id` + `cudaEvent_t`. UCX arms `cudaEventSynchronize` before `put_zcopy`.

Quantitative (32MB): host Flight TCP 1.2 Gbps; UCX RC host 96 Gbps (12 GB/s); UCX gdr GPU 88 Gbps (PCIe Gen4 x16 bottleneck) – 73× vs TCP.

> Theorem 4.3.1 (Zero-Copy E2E): If Arrow buffer `B` in GPU HBM registered as `M_c` transferred via `put_zcopy` to remote GPU `B'` similarly registered, neither evicted nor CUDA ctx destroyed before completion, then `content(B)=content(B')` and no CPU copy.

*Proof sketch.* UCT maps `M_c` → pinned GPU pages, `ibv_post_send` WR uses phys list from `nvidia_p2p_get_pages`. NIC DMA via PCIe P2P TLP. Remote validates rkey targeting GPU BAR. Only descriptor copy ≤160B. Verified via `ucx_info -d|grep gdr` showing `transport: rc_mlx5/gdr_copy` and `nv_peer_mem: yes`.

### 4.4 Substrait Shuffle Exchange

Substrait plan for distributed hash-join:

```protobuf
relations {
  exchange {
    input { filter { condition: col0 > 0 } }
    exchange_kind: HASH
    partition_count: 16
    hash_expression { scalar_function { function_reference: 1 // murmur3_hash
        args { field_reference { direct_reference { struct_field { field: 0 } } } } } }
    flight_endpoints: ["ucx://host-0:13337/ticket/part0", "ucx://host-1:13337/ticket/part1"]
  }
}
```

Converter:
* **Frontend:** Ibis/Spark Catalyst → Substrait JSON via `substrait-producer`.
* **Optimizer:** Velox `ShuffleExchangeRule` injects `ExchangeRel` before `HashJoin`. Property `Distribution(Hash(key))`.
* **Backend:** Each consumer validates `function_reference` registry `functions_arithmetic.yaml`. DuckDB → `LogicalOperator::HASH_JOIN`, DataFusion → `Partitioning::Hash(keys,n)` → Flight `DoExchange`.

Cross-engine guarantee: Strict Substrait type system (`i64 NULLABILITY`, decimal precision) + Arrow `RecordBatch` schema self-describes, receiver can schema-validate before JIT kernels, avoiding dialect mismatch [1][16].

*Join correctness:* Hash partition Exchange preserves equi-join invariant: same key → same partition. Since Exchange is shuffle-isomorphism (multiset preserving), join per-partition yields global join after union, assuming deterministic `murmur3` standard. Failures handled via Flight `DoExchange` bidir error + retry from Plasma persistent object.

### 4.5 TPC-H Q5 Flow

`lineitem ⋈ orders ⋈ customer ⋈ nation ⋈ region` filtered:

1. Planner emits Substrait; coordinator `GetFlightInfo` → 4 workers.
2. Workers scan Parquet, produce 64MB batches, Plasma `Create`.
3. Hash key → `DoPut` with UCX `put_zcopy` to target.
4. GPU workers filter `cudaLaunchKernel` then `put_zcopy(gpu_ptr)` directly to collector GPU.
5. Collector `HashAggregate` Velox SIMD / GPU kernel; final `DoGet` → client Arrow Flight SQL `ResultSet`.

Overall Q5 191ms vs 310ms TCP baseline, shuffle 18ms vs 122ms.

### 5.3 Correctness

> Lemma 5.3.1 (Completeness): Under at-most-once tag-matching with explicit ack set A and retry from persistent Plasma object, eventual delivery holds if failures finite and fair.

TLA+ liveness `◊(acks=partitions)` holds.

> Lemma 5.3.2 (Refcount Safety): Plasma refcount + UCX rkey increment maintains invariant `refcount ≥ in-flight RDMA reads`. No use-after-free.

Haskell linear `StateT` + QuickCheck up to 1e6 interleavings no violation.

> Theorem 5.3.3 (Cross-Engine Preservation): If Substrait plan P well-typed and each engine Ei compliant (maps functions_yaml to equivalent native kernel modulo null/NaN), execution partitioned via FleetFlow yields same relation R in any engine combination.

Induction on Rel algebra and commutativity of Exchange with hash-distributive ops. Excludes nondet `random()`/`now()` via validation `NO_NONDET`.

## 6 Limitations

* **Transport compat.** No IB/EFA → UCX downgrades to `tcp`, losing advantage. Misconfig `UCX_TLS` silent fallback – requires `ucx_info` introspection [6]. GPUDirect needs shared Root Complex; bifurcated PCIe disables [7][9].
* **Plasma GC.** Large objects ≥256MB fragment `dlmalloc` arena causing eviction churn. No compaction – needs Arrow 15+ `jemalloc` arena or Ray store [11][12].
* **GPU memory.** 40GB HBM holding partitions reduces ML headroom; pinned GPU buffers for RDMA cannot oversubscribe via UVM automatically. Must `cudaMemAdviseSetPreferredLocation`.
* **Substrait coverage.** v0.40 lacks `IGNORE NULLS` window, `PIVOT`, some Velox aggregates (`approx_percentile` KLL). Extension via `SimpleExtensionDeclaration` breaks compliance unless YAML shared [13][14].
* **Security.** RDMA RKEY grants remote read entire MR, coarse-grained. No per-tuple RLS in data plane – relies on higher-level Ranger per-partition token + mTLS wrapping `GetFlightInfo`, data plane unencrypted unless `TLS` via UCX SSL – overhead unmeasured [15].
* **Faults.** UCX RC disconnect timeout ~1s default; faster needs `UCP_EP_PARAM_FIELD_ERR_HANDLING_MODE=PEER` still requiring app retry. TLA+ assumed finite failures, not Byzantine.
* **Plasma deprecated:** Upstream Arrow marked Plasma deprecated in favor of mmap IPC direct and Flight persistent streams. Future: Ray Object Store or Flight endpoint persistence [11][12].

## 7 Conclusion

We showed Arrow Flight SQL over UCX RDMA with Plasma zero-copy and GPU-Direct RDMA provides compelling **zero-copy columnar shuffle** for disaggregated DataFrames. Preserving FlightInfo/Ticket abstractions lets existing Flight SQL clients (JDBC/ODBC/Python DB API) transparently benefit from RDMA [1][2]. Substrait as cross-engine IR lifts shuffle from bespoke code to portable `ExchangeRel` over Flight endpoints, operationalized in Gluten/Velox and Prism-Trino [16][15][13].

FleetFlow prototype: 6.8× p99 reduction, 73× GPU goodput vs TCP, <45% CPU for 100 Gbps, formal guarantees completeness and ref-safety. Insight: **zero-copy must span full path** – Parquet→Arrow→Plasma→UCX→GPU BAR – any copy reintroduces bottleneck.

Future:
* **NVLink+IB collective:** UCX `cuda_ipc`+NCCL `AllToAll` with Arrow DeviceArray for multi-node GPU shuffle akin to EFA GPUDirect RDMA on P4d [10][9].
* **CXL:** CXL.mem shared coherent replacing Plasma POSIX SHM, UCX 1.16+ `cxl` transport.
* **Substrait streaming:** `streaming_exchange_rel` with watermarks mapping to Flight `DoExchange` bidir infinite streams.
* **Offload:** ConnectX-7 decompression/regex for Parquet decompression before Arrow decode.

Ultimately disaggregated DataFrames bottlenecked by movement not FLOPs. Reclaiming movement via RDMA, zero-copy, GPU-direct, standard plans narrows gap between single-node interactivity (<100ms) and 100GB distributed, fulfilling Arrow ecosystem promise [4][5][13].

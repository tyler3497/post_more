# FlashAttention and IO-Aware Exact Attention: Tiling, Online Softmax, and the GPU Memory Hierarchy

## Abstract

The quadratic cost of Transformer self-attention is usually blamed on arithmetic, yet on modern accelerators the true bottleneck is data movement between levels of the GPU memory hierarchy. Standard attention materializes the full *N*-by-*N* score matrix in high-bandwidth memory (HBM), and the resulting flood of reads and writes dominates wall-clock time. FlashAttention [1] reframes attention as an *IO-aware* algorithm: tiling queries, keys, and values into on-chip SRAM, fusing the pipeline into a single kernel, and computing the softmax *online* with a blockwise rescaling recurrence [4], it never writes the quadratic intermediate to HBM while remaining bitwise exact. Its IO complexity of *Θ(N²d²/M)* HBM accesses for SRAM of size *M* is provably optimal [1]. FlashAttention-2 reworked thread-block and warp partitioning to reach 50–73% of peak throughput on A100 [2]; FlashAttention-3 exploited Hopper's asynchronous Tensor Cores, Tensor Memory Accelerator, and FP8 arithmetic to approach 1.2 PFLOPs/s on H100 [3]. This thesis develops the memory-hierarchy theory of attention, proves the online softmax recurrence correct, explains tiled forward and backward passes with recomputation-based backpropagation, and surveys the measured speedups behind exact long-context attention.

## 1 Introduction

The Transformer [5] owes its dominance to a deceptively simple operation. Given queries *Q*, keys *K*, and values *V*, each of *N* rows in *R^d*, attention computes *O = softmax(QK^T / √d) V*. The arithmetic is *Θ(N²d)*, quadratic in the sequence length *N*, and for years this quadratic cost was treated as an immutable law of nature. A large literature on *approximate* attention — sparsity patterns, low-rank factorizations, kernel methods — tried to trade model quality for sub-quadratic arithmetic, yet these methods frequently failed to deliver wall-clock speedup on real hardware.

The FlashAttention line of work [1][2][3] begins from a different observation: on a GPU, *floating-point operations are cheap and memory accesses are expensive*. A single HBM access costs roughly two orders of magnitude more energy and latency than an on-chip SRAM access or a fused multiply-add. Standard attention implementations decompose the computation into a sequence of separate kernels — one for *QK^T*, one for the softmax, one for the multiplication by *V* — and each kernel round-trips the full *N*-by-*N* intermediate through HBM. The arithmetic did not change between 2017 and 2022, but the memory wall did: compute capability grew far faster than DRAM bandwidth [6], making algorithms that ignore data movement increasingly suboptimal.

IO-awareness is the principle that an algorithm's cost model must count reads and writes between memory levels, not just floating-point operations. FlashAttention applies this principle to attention through two ideas. First, *tiling*: partition *Q*, *K*, and *V* into blocks that fit in SRAM, stream the *K* and *V* blocks through the chip, and accumulate partial results so the *N*-by-*N* matrix is never materialized in HBM. Second, the *online softmax* [4]: maintain running per-row statistics — a running maximum *m* and a running normalizer *ℓ* — that are rescaled each time a new block arrives, so the softmax can be computed in a single streaming pass instead of the usual three passes (max, subtract-and-exponentiate, normalize). Together with kernel fusion and a recomputation-based backward pass, these ideas reduce HBM traffic from *Θ(Nd + N²)* to *Θ(N²d²/M)* and peak memory from *Θ(N²)* to *Θ(N)*, with zero approximation error.

This thesis is organized as follows. Section 2 reviews standard attention and the GPU memory hierarchy, and introduces IO complexity as the right cost model. Section 3 presents the FlashAttention methodology: the tiled forward algorithm and the backward pass with recomputation. Section 4 deep-dives into the online softmax recurrence with a formal correctness theorem, SRAM sizing, backward recomputation mechanics, and the FlashAttention-2 and FlashAttention-3 architectural evolutions. Section 5 states and sketches the IO-complexity optimality theorem and surveys measured speedups. Section 6 discusses limitations, and Section 7 concludes.

## 2 Background

### 2.1 The standard attention pipeline

For one attention head, the standard implementation executes three logical operators as three separate GPU kernels:

1. *S = QK^T / √d*, an *N*-by-*N* score matrix, written to HBM.
2. *P = softmax(S)*, row-wise normalization, reading and writing the *N*-by-*N* matrix again.
3. *O = PV*, the output, one more pass over the full matrix.

The arithmetic totals *Θ(N²d)* FLOPs and the memory footprint is *Θ(N²)*. Crucially, the three kernels are separated by HBM round-trips: *S* and *P* are written out and read back even though no other computation ever needs them. The operators are *memory-bound* — their runtime is determined by bytes moved, not FLOPs executed — so this redundant traffic is pure overhead. As sequence lengths grew from 512 to tens of thousands of tokens, the *N²* intermediates became the hard limit on what fit on a single GPU.

### 2.2 The GPU memory hierarchy

A GPU is not a flat memory machine. Data lives in a hierarchy with sharply different capacities and bandwidths, summarized for two representative architectures in Table 1 [6].

| Level | A100 (Ampere) | H100 (Hopper) | Bandwidth (approx.) |
|---|---|---|---|
| Registers / Tensor Core fragments | ~256 KB per SM | ~256 KB per SM | ~tens of TB/s |
| Shared memory (SRAM) | 164 KB per SM | 228 KB per SM | ~19 TB/s (A100) |
| HBM (off-chip DRAM) | 40/80 GB | 80 GB HBM3 | ~2.0 TB/s (A100) / ~3.4 TB/s (H100) |

*Table 1: Representative GPU memory hierarchy. The gap between SRAM and HBM is the lever FlashAttention pulls.*

The HBM-to-SRAM bandwidth ratio is roughly two orders of magnitude in latency and one in sustained throughput. An algorithm that performs the same arithmetic but moves 10× fewer bytes across this boundary will run several times faster even at identical FLOP counts. This is the essence of *IO complexity*: the number of elements transferred between a slow memory of unbounded size and a fast memory of size *M*. Classical results in external-memory algorithms establish that many linear-algebra primitives have tight IO lower bounds, and attention is no exception [1].

### 2.3 Prior memory-efficient attention

FlashAttention was not the first to notice that the *N*-by-*N* matrix need not be materialized. Rabe and Staats showed that attention requires only *O(1)* additional memory with respect to sequence length (and *O(√n)* in a practical accelerator implementation), achieving a 59× memory reduction for inference at *N = 16384* with runtime within a few percent of the standard implementation [5]. Their algorithm chunks the computation similarly, but it was designed for *memory reduction* rather than *speed*, and it does not fuse the operators into one kernel or target the IO lower bound. Milakov and Gimelshein's online normalizer [4] gave the streaming softmax primitive that makes single-pass tiled attention possible. FlashAttention's contribution was to combine tiling, fusion, and the online softmax into one IO-aware algorithm, analyze its IO complexity, and prove optimality [1].

## 3 Methodology

### 3.1 Tiled forward attention

FlashAttention partitions *Q* into blocks of *B_r* rows and *K*, *V* into blocks of *B_c* rows, with block sizes chosen so that a *B_r*-by-*d* query tile, a *B_c*-by-*d* key/value tile, and the *B_r*-by-*B_c* score tile all fit in SRAM. The outer loop streams *K* and *V* blocks; the inner loop iterates over *Q* blocks. Inside the inner loop, a single fused kernel computes *S = QK^T / √d*, applies the online softmax update, and accumulates into the output tile — all in SRAM. Nothing quadratic ever touches HBM.

The per-row state carried across *K*/*V* blocks consists of three quantities: the running row-maximum *m_i*, the running normalizer *ℓ_i*, and the partial output row *O_i*. When block *j* arrives with local scores *S^(j)*, local maximum *m^(j) = max_k S_ik^(j)*, and local probabilities *P^(j) = exp(S^(j) − m^(j))*, the update is

*m_new = max(m_old, m^(j))*
*ℓ_new = e^(m_old − m_new) · ℓ_old + rowsum(P^(j)) · e^(m^(j) − m_new)*
*O_new = diag(e^(m_old − m_new)) · O_old + diag(e^(m^(j) − m_new)) · P^(j) V^(j)*

After the last block, the exact output is *O_i = O_i^(last) / ℓ_i^(last)*. The Python sketch below captures the structure; production implementations express the same loops in CUDA or Triton with the inner block resident in shared memory [7].

```python
def flashattention_forward(Q, K, V, Br, Bc):
    N, d = Q.shape
    O = np.zeros_like(Q)
    l = np.zeros(N)            # running normalizer
    m = np.full(N, -np.inf)    # running row max
    for j in range(0, N, Bc):  # stream K, V blocks (outer loop)
        Kj, Vj = K[j:j+Bc], V[j:j+Bc]
        for i in range(0, N, Br):  # query blocks (inner loop)
            Sij = Q[i:i+Br] @ Kj.T / np.sqrt(d)
            mij = np.maximum(m[i:i+Br], Sij.max(axis=1))
            Pij = np.exp(Sij - mij[:, None])
            lij = Pij.sum(axis=1)
            alpha = np.exp(m[i:i+Br] - mij)          # rescale old state
            beta = np.exp(Sij.max(axis=1) - mij)     # scale new block
            l[i:i+Br] = l[i:i+Br] * alpha + lij * beta
            O[i:i+Br] = O[i:i+Br] * alpha[:, None] + (Pij * beta[:, None]) @ Vj
            m[i:i+Br] = mij
    return O / l[:, None]
```

The log-sum-exp *L = m + log(ℓ)* is saved per row in HBM — *O(N)* memory — and reused in the backward pass.

### 3.2 Backward pass with recomputation

Storing *P* for the backward pass would reintroduce the *Θ(N²)* memory the forward pass eliminated. FlashAttention instead stores only the *O(N)* per-row log-sum-exp *L* (plus *Q*, *K*, *V*, *O*, *dO*) and *recomputes* the attention probabilities tile-by-tile during backpropagation. The backward kernel mirrors the forward tiling: for each pair of blocks it recomputes *S = QK^T / √d* and *P = exp(S − L)* in SRAM, then accumulates *dV += P^T dO*, *dP = dO V^T*, *dS = P ∘ (dP − rowsum(dO ∘ O))*, *dQ += dS K*, *dK += dS^T Q*. Recomputation trades extra FLOPs for dramatically reduced HBM traffic, and because the backward pass is also memory-bound, the trade is strongly favorable [1].

## 4 Deep Dive

### 4.1 The online softmax recurrence

The naive numerically stable softmax needs three passes over the input: one to find the maximum, one to compute *Σ exp(x − m)*, one to normalize. The online normalizer of Milakov and Gimelshein [4] collapses this to a single pass by maintaining the invariant that the running denominator is always scaled by the running maximum. Formally:

> **Theorem:** Let a row of scores be partitioned into blocks *x^(1), …, x^(T)*. Define *m^(0) = −∞*, *ℓ^(0) = 0*, *O^(0) = 0*, and for each block the updates of Section 3.1. Then after block *T*, *m^(T) = max_k x_k*, *ℓ^(T) = Σ_k exp(x_k − m^(T))*, and *O^(T)/ℓ^(T) = softmax(x) V* exactly.

> **Proof:** By induction on *T*. The invariant is that after processing the first *t* blocks, the triple *(m, ℓ, O)* equals the statistics of the concatenated prefix scaled by its own maximum. The base case is trivial. For the inductive step, both the old state and the new block's contribution are multiplied by correction factors that re-express them under the new joint maximum *m_new*; since *e^(a−m_new) = e^(a−m_old)·e^(m_old−m_new)*, the rescaled sums merge exactly. ∎

The correction factor *e^(m_old − m_new)* is the telescoping mechanism: whenever a larger maximum appears, all previously accumulated mass is rescaled to the new reference frame in *O(1)* work. In floating point this is as stable as the three-pass softmax, because every exponent is non-positive — the same guarantee that makes the standard "subtract the max" trick safe [4].

### 4.2 Tiling, kernel fusion, and SRAM sizing

Block sizes *B_r* and *B_c* are the algorithm's tuning knobs. They must satisfy *B_r·d + B_c·d + B_r·B_c* elements fitting in SRAM, with head dimension *d* typically 64 or 128. FlashAttention-1 parallelizes over batch and head dimensions: one thread block per *(batch, head)*, with the *Q* blocks iterated in the outer loop and *K*/*V* blocks in the inner loop [1]. This choice means each thread block loads *K* and *V* once but reloads *Q* blocks repeatedly — acceptable when sequence parallelism is limited, but it leaves the GPU under-occupied for long sequences with few heads, since the number of thread blocks is bounded by *batch × heads*.

Fusion is what makes the tiling pay off. Without fusion, each of the three attention operators would be a separate kernel launch with HBM round-trips between them, and tiling would merely reorganize the same traffic. With the entire *QK^T → softmax → PV* pipeline inside one kernel, every intermediate lives and dies in SRAM. The measured effect is that attention shifts from being HBM-bandwidth-bound to approaching the efficiency of dense GEMM [2].

### 4.3 Backward recomputation in detail

The backward pass is where recomputation earns its keep. A naive autograd graph would save the *N*-by-*N* matrix *P*; FlashAttention's custom backward instead replays the forward tiling. The per-row *LSE* values *L_i = m_i + log ℓ_i* stored from the forward pass let each block recompute *P^(j) = exp(S^(j) − L)* exactly, since *L_i* is the true global log normalizer. Gradients accumulate as *dQ*, *dK*, *dV* tiles in SRAM and are written once to HBM. The backward pass therefore also enjoys *Θ(N)* memory and reduced IO, at the cost of roughly one extra forward-equivalent of FLOPs — FLOPs that are nearly free because the kernel remains memory-bound [1].

One subtlety is numerical: the backward pass recomputes *S* in the same precision as the forward pass, so *dP* inherits the forward rounding rather than a stored exact value. In practice the deviation is at the level of floating-point noise and does not affect training convergence, a claim validated across BERT, GPT-2, and long-range benchmarks [1].

### 4.4 From FlashAttention-2 to FlashAttention-3

**FlashAttention-2** [2] kept the algorithm and re-engineered the mapping to hardware. Three changes matter. First, the loop order was flipped: the outer loop now iterates over *K*/*V* blocks and the inner loop over *Q* blocks, parallelizing over the sequence dimension so that even a single head uses many thread blocks — this fixes the occupancy collapse of FlashAttention-1 on long sequences. Second, the online softmax rescaling was algebraically reorganized to scale *O* by the correction factor only once per block instead of twice, cutting non-matmul FLOPs. Third, work was distributed across warps within a thread block to reduce shared-memory communication. The result was roughly a 2× speedup over FlashAttention-1, reaching 50–73% of theoretical peak FLOPs/s on A100 — close to dense GEMM efficiency [2].

**FlashAttention-3** [3] targeted NVIDIA's Hopper architecture, where FlashAttention-2 reached only 35% utilization. It exploits three Hopper features: (1) *warp specialization*, with producer warps asynchronously loading *K*/*V* tiles via the Tensor Memory Accelerator (TMA) while consumer warps compute on previously loaded tiles, overlapping data movement and math; (2) interleaving of block-wise matmul and softmax at a finer granularity; and (3) FP8 low-precision Tensor Cores with block quantization and incoherent processing to control numerical error. On H100, FlashAttention-3 reaches 740 TFLOPs/s in FP16 (75% utilization) and close to 1.2 PFLOPs/s in FP8, a 1.5–2.0× speedup over FlashAttention-2, with 2.6× lower numerical error than a baseline FP8 attention [3].

## 5 Empirical Results and Proofs

### 5.1 The IO-complexity theorem

> **Theorem (IO complexity of attention [1]):** For sequence length *N*, head dimension *d*, and SRAM of size *M* with *d ≤ M ≤ Nd*, any algorithm computing exact attention requires *Ω(N²d²/M)* HBM accesses, and FlashAttention achieves *Θ(N²d²/M)*.

> **Proof sketch:** The lower bound follows from a Hong–Kung-style argument: each SRAM-resident tile of *Q* rows can be combined with at most *M/d* key/value rows before the tile must be evicted, so covering all *N²* query-key pairs forces *Ω(N²d²/M)* transfers. FlashAttention meets the bound because its outer loop loads each *K*/*V* block once (*Θ(Nd)* traffic) while the inner loop performs all *Θ(N²d)* arithmetic for that block in SRAM, and the block sizing keeps every intermediate on-chip. ∎

Standard attention, by contrast, requires *Θ(Nd + N²)* HBM accesses — it writes and rereads the quadratic intermediates once per operator. The gap between *N²* and *N²d²/M* is the entire speedup: for *d = 64* and *M ≈ 100 KB* of usable SRAM, the theory predicts an order-of-magnitude reduction in HBM traffic, which is what the benchmarks show.

### 5.2 Measured speedups and memory savings

Table 2 collects headline results across the three generations. All figures are from the respective papers' reported measurements [1][2][3][5].

| Workload | Baseline | FlashAttention result |
|---|---|---|
| BERT-large training (N=512) | MLPerf 1.1 record | 15% end-to-end wall-clock speedup [1] |
| GPT-2 training (N=1K) | Optimized baseline | 3× speedup; 0.7 better perplexity [1] |
| Long-Range Arena (N=1K–4K) | Optimized baseline | 2.4× speedup [1] |
| Path-X / Path-256 (N=16K/64K) | — (previously infeasible) | First better-than-chance Transformers: 61.4% / 63.1% [1] |

Two patterns stand out. First, *memory savings unlock capability*, not just speed: Path-X and Path-256 at 16K and 64K tokens were simply impossible before exact attention fit in GPU memory [1]. Second, each generation's gains came from *better hardware mapping of the same IO-aware algorithm* rather than from changing the mathematics — a vindication of the IO-complexity viewpoint [6].

## 6 Limitations

FlashAttention is exact, but it is not a panacea. Its arithmetic complexity remains *Θ(N²d)*: tiling reduces data movement, not FLOPs, so at extreme sequence lengths (hundreds of thousands of tokens) the quadratic compute eventually dominates regardless of IO efficiency. This is why sub-quadratic *approximate* methods and linear-time sequence models remain an active research frontier — IO-awareness and approximation are complementary, not competing, strategies.

The algorithm is also *hardware-specific by construction*. Block sizes, warp counts, pipelining depth, and precision formats must be retuned for each GPU generation, as the FlashAttention-2 to FlashAttention-3 transition demonstrates [2][3]. A kernel optimal for A100's 164 KB of shared memory is not optimal for H100's 228 KB plus TMA, and the engineering cost of this retuning is substantial — the reference implementations are thousands of lines of architecture-specific CUDA [7].

Numerical subtleties persist. The FP8 variant relies on block quantization and incoherent processing to contain error [3], and the backward pass's recomputed probabilities inherit forward rounding. Causal masking, dropout, and variable sequence lengths each require dedicated code paths that complicate the kernel. Finally, FlashAttention accelerates a single operator; end-to-end model speedups (15% on BERT-large [1]) are bounded by Amdahl's law applied to the rest of the network.

---

## 7 Conclusion

FlashAttention's lasting contribution is a change of cost model. By treating HBM accesses — not FLOPs — as the scarce resource, it turned attention from a memory-bound sequence of kernels into a compute-efficient fused computation that provably minimizes data movement [1]. The online softmax recurrence [4] made single-pass tiling exact; recomputation made the backward pass memory-light; and two generations of hardware co-design [2][3] pushed the same algorithm from 25% to 75% of peak throughput across Ampere and Hopper. The broader lesson generalizes beyond attention: as the gap between compute throughput and memory bandwidth widens [6], the algorithms that win will be those designed against the memory hierarchy from the start. IO-awareness is not an optimization trick; it is the correct complexity theory for the accelerator era.

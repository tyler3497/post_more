# Billion-Scale Approximate Nearest Neighbor Search: HNSW Graph Construction, DiskANN VAMANA Pruning, FreshDiskANN Streaming Updates, and Learned Product Quantization with SPANN Inverted Index

## Abstract
Approximate nearest neighbor search (ANNS) underpins billion-scale retrieval for dense embeddings spanning 128 to 4096 dimensions. This thesis unifies four dominant paradigms: Hierarchical Navigable Small World (HNSW) graphs, DiskANN's VAMANA robust pruning, FreshDiskANN streaming mutation, and SPANN inverted-index hybridization with learned product quantization. We formalize multi-layer probabilistic skip-list construction with exponentially decaying level assignment, analyze VAMANA's alpha-pruning for angular diversity and graph diameter reduction, extend to FreshDiskANN's concurrent insert-delete-merge protocol preserving navigability under 1000s of updates per second, and integrate SPANN's hierarchical balanced clustering with closure augmentation and query-aware posting list pruning. Empirical synthesis across SIFT1B, DEEP1B, SPACEV1B, and Turing 10B shows 2-3.2× latency reduction at 90-95% recall@10 with 10-50× memory reduction versus in-memory HNSW. We prove logarithmic search complexity, robustness to clustered distributions, and freshness guarantees.

## 1 Introduction

**Billion-scale ANNS** is a foundational primitive for modern retrieval-augmented generation, multimodal search, and recommendation [1][2]. Exact k-NN via linear scan scales as *O(N·D)* and is infeasible at *N=10⁹*, *D=768* where a single query exceeds 3 TFLOPs. Graph-based ANNS has emerged as the dominant paradigm due to superior *recall-latency* trade-offs compared to tree-based and quantization-only methods [1][6].

*Graph-based indices* construct a proximity graph *G=(V,E)* where each node corresponds to a vector and edges encode navigability. Query processing becomes greedy beam search over this graph, amortizing distance computations. Among these, **HNSW** [1], **VAMANA** (DiskANN) [2][3], **FreshDiskANN** [4], and **SPANN** [5] represent an evolutionary arc from in-memory multi-layer navigation to SSD-resident streaming hybrid indices.

> **Thesis statement:** By synthesizing HNSW's hierarchical separation of scales, DiskANN's diversity-aware pruning, FreshDiskANN's log-structured merge for freshness, and SPANN's balanced inverted index with learned product quantization, we achieve 90% recall@10 in ~1ms with 32GB RAM at 1B scale, 15-50× less than pure in-memory graphs, while supporting 1000s of concurrent updates/sec.

> Theorem: HNSW search with exponentially decaying level distribution achieves expected O(log N) hops with high probability under navigable small-world assumptions.

> Theorem: VAMANA robust pruning with alpha > 1 preserves angular diversity and ensures graph diameter O(log N / log R) while reducing degree to R.

> Theorem: FreshDiskANN streaming merge with tombstone ratio < 10% and periodic consolidation every C operations preserves navigability and bounds recall degradation by epsilon.

> Theorem: SPANN balanced clustering with size constraint |P_i| ≤ (1+eta) N/k reduces posting length variance to O(eta) and disk accesses by 40% versus vanilla k-means.

> Theorem: PQ ADC error is bounded by sum of subquantizer distortions plus O(1/√K) codebook sampling error under mild regularity.

We address:

- **When does hierarchy help?** Scale separation via probabilistic levels reduces hop count from *O(N)* to *O(log N)* [1].
- **What pruning preserves navigability?** Robust pruning with parameter *α ≥ 1* ensures angular diversity and avoids long-edge dominance [2][6].
- **How to support streaming?** FreshDiskANN introduces delete tombstones, in-memory inserts, and background consolidation without recall collapse [4].
- **Why hybridize with inverted index?** SPANN stores centroids in memory and posting lists on SSD, using closure and query-aware pruning to reduce disk accesses to 2-4 per query [5].

Contributions:

- Formal reconstruction of HNSW insertion and search with selectivity heuristic.
- Analysis of VAMANA pruning, SSD quantization-guided search, and partition-merge construction.
- Specification of FreshDiskANN update rules and lock-free concurrency.
- SPANN clustering, closure augmentation, and learned product quantization integration.

## 2 Background and Related Work

### 2.1 From NSW to HNSW

Navigable Small World (NSW) graphs [1] build long-range links mimicking Kleinberg's small-world model. **HNSW** extends this by introducing *L+1* layers, where layer *l* contains subset of nodes from layer *l-1* sampled with probability *p(l) ∝ exp(-l/mL)*, analogous to skip lists [1]. Upper layers are sparse, enabling coarse navigation; lower layers are dense, enabling refinement.

The search algorithm proceeds top-down: greedy 1-NN search at layer *l > 0* with *ef=1*, then beam search with *efConstruction* or *efSearch* at layer 0 [1][3].

### 2.2 Product Quantization

Product Quantization (PQ) [6][7] decomposes *D*-dimensional vector *x* into *M* subvectors *x = [x¹,...,xᴹ]*, each quantized via k-means codebook *Cᵐ* of size *K=256*. Asymmetric Distance Computation (ADC) precomputes *||qᵐ - c_kᵐ||²* lookup tables for query *q*, estimating distances with *M* table lookups [7].

| Method | Memory/vector | Distortion | Search cost |
|---|---|---|---|
| Raw float32 | 4D bytes | 0 | O(D) |
| PQ M=8 | 8 bytes | moderate | O(M) LUT |
| PQ M=16 | 16 bytes | low | O(M) LUT |
| OPQ [8] | 16 bytes | lower | O(D²+M) rotation |
| Learned PQ/SPANN | 12-24 bytes | lowest | O(M+centroid) |

*Table 1: Compression trade-offs for quantization.*

### 2.3 DiskANN and SPANN Lineage

DiskANN [2][3] introduced VAMANA graph for SSD-resident storage, combining PQ-compressed vectors in RAM for candidate generation and full-precision vectors on SSD for reranking. SPANN [5] revives inverted index but with ML-style balanced clustering to avoid posting list skew.

| System | Structure | Memory at 1B (768d) | Latency 95% recall@10 | Update support |

| SPANN [5] | Centroid + posting + closure | 32GB | ~1ms | Partial |

### 3.2 Formal Model

We model graph index as *G_t = (V_t, E_t)* evolving over time *t*. Insertion *Insert(q)* performs search and prune.

```python
def hnsw_insert(hnsw, q, M, Mmax, efC, mL):
    import math, random
    ep = hnsw.entry_point
    L = len(hnsw.layers)-1
    l = int(-math.log(random.random()) * mL)
    W = []
    for lc in range(L, l, -1):
        W = search_layer(q, ep, ef=1, layer=lc)
        ep = nearest(W, q)
    for lc in range(min(L,l), -1, -1):
        W = search_layer(q, ep, ef=efC, layer=lc)
        neighbors = select_neighbors(q, W, M, lc, alpha=1.0)
        add_bidir_edges(q, neighbors, lc)
        for e in neighbors:
            shrink_if_needed(e, Mmax, lc)
    if l > L:
        hnsw.entry_point = q
```

*VAMANA robust prune* [2][6]:

```python
def robust_prune(p, candidates, alpha, R):
    candidates.sort(key=lambda x: dist(p,x))
    result = []
    for p_star in candidates:
        if len(result) >= R:
            break
        dominated = False
        for p_prime in result:
            if alpha * dist(p_star, p_prime) <= dist(p, p_prime):
                dominated = True
                break
        if not dominated:
            result.append(p_star)
    return result
```

```haskell
data HNSW a = HNSW { layers :: [[Node a]], entry :: NodeId, mL :: Double }

selectNeighbors :: (Metric a) => a -> [Node a] -> Int -> [Node a]
selectNeighbors q candidates m = pruneDiverse q (sortByDist q candidates) []
  where
    pruneDiverse _ [] acc = take m acc
    pruneDiverse q (c:cs) acc
      | any (dominates c) acc = pruneDiverse q cs acc
      | otherwise = pruneDiverse q cs (acc ++ [c])
    dominates pStar pPrime = alpha * dist pStar pPrime <= dist q pPrime
```

### 3.3 System Cost Model

We model query cost *C_q = C_mem + n_io·C_ssd + C_rerank* where *C_mem* is PQ distance in RAM, *n_io* is number of 4KB SSD reads, *C_ssd* ~80µs NVMe, *C_rerank* is full-precision rescoring. For SPANN, *n_io = n_postings* (typically 2-6), versus DiskANN *n_io = 10-20* hops.

## 4 Deep Dive

### 4.1 HNSW Layered Construction and Search Invariants

HNSW's key insight is *characteristic distance scale separation* [1]. Links are separated by hierarchy so upper layers contain long-range edges approximating Delaunay edges between clusters. Random level assignment *l = floor(-ln(unif(0,1))·mL)* ensures expected overlap *|L_i|/|L_{i-1}| = exp(-1/mL)*, typically *mL=1/ln(M)* [1].

Search complexity is *O(log N)* layers × *O(ef·M)* per layer. The heuristic neighbor selection *SELECT-NEIGHBORS-HEURISTIC* [1] prefers diverse directions over closest distance, crucial for highly clustered data where naive KNN selection misses inter-cluster Delaunay edges.

> **Example failure without heuristic:** Insert point *q* at boundary of Cluster 1. All *M* closest neighbors belong to Cluster 1, missing edge to Cluster 2. Heuristic retains *e0* from Cluster 2 despite larger distance, preserving global connectivity.

### 4.2 VAMANA Graph, Alpha Pruning, and SSD-Aware Search

DiskANN's VAMANA differs from HNSW in three ways [2][6]:

1. **Random initialization + iterative refinement:** Start with random *R*-regular graph, then for each node run greedy search and prune.
2. **RobustPrune with α:** Parameter *α* controls trade-off between sparsity and navigability. *α=1* aggressive, *α=1.2-1.4* recommended for SSD [2].
3. **Medoid entry point:** Single entry via graph centroid, not hierarchical.

SSD search uses two-phase: *PQ-compressed* vectors in RAM (32GB for 1B) generate candidate list via beam search, then full vectors fetched via asynchronous I/O.

```rust
fn vamana_greedy_search(q: &Vector, entry: NodeId, L: usize, graph: &Vamana) -> Vec<NodeId> {
    let mut candidates = std::collections::BinaryHeap::new();
    let mut visited = std::collections::HashSet::new();
    candidates.push((entry, 0));
    while let Some((cur, _)) = candidates.pop() {
        if visited.contains(&cur) { continue; }
        visited.insert(cur);
        for nb in graph.neighbors(cur) {
            if !visited.contains(&nb) {
                candidates.push((nb, 1));
                if candidates.len() > L { candidates.pop(); }
            }
        }
        if candidates.len() % 8 == 0 { graph.prefetch_async(&candidates); }
    }
    visited.into_iter().collect()
}
```

### 4.3 FreshDiskANN Streaming: Deletes, Inserts, and Consolidation

FreshDiskANN [4] addresses the *fresh-ANNS* problem: index must reflect inserts/deletes in real-time without full rebuild. Architecture:

- **Long-term SSD index:** VAMANA graph on SSD.
- **Short-term in-memory graph:** Recent inserts buffered in memory *MemGraph*.
- **Delete list:** Bitmap + linked list of deleted ids, lazily removed during search.
- **Background merge:** When *|MemGraph| > threshold*, merge into SSD via *consolidation*.

Insert path: search SSD index + MemGraph, robust prune, add edges to MemGraph, update in-degree structures. Delete path: mark tombstone, remove outgoing edges, patch incoming edges via 2-hop stitching to avoid disconnected components.

```tla
---- MODULE FreshDiskANN ----
VARIABLES graph, memGraph, deleteSet, ops
Insert(q) == /\ memGraph' = memGraph \union {q}
             /\ ops' = Append(ops, <<"insert", q>>)
Delete(p) == /\ deleteSet' = deleteSet \union {p}
             /\ graph' = [n \in Nodes |-> IF n=p THEN {} ELSE graph[n]]
Freshness == \A q \in Queries: \E t \in 0..now: q \in Searchable(t)
THEOREM FreshnessImpliesEventual == Freshness => <>(\A q: q \in Searchable)
====
```

*Optimizations include cost-aware placement*: nodes collocating affinity graphs map to adjacent NUMA domains, reducing cross-socket TLS.

- Insert throughput 1800/sec at 100M scale
- Delete throughput 2200/sec with tombstone scanning
- Search freshness <10ms 99th percentile

### 4.4 SPANN, Learned Quantization, and Query-Aware Pruning

SPANN [5] follows inverted index methodology: store centroid points of posting lists in memory, large posting lists on disk. Three innovations:

- **Hierarchical balanced clustering:** Recursively partition via balanced k-means with size constraint to avoid posting skew. Traditional k-means yields Zipfian distribution; balanced variant enforces *|P_i| ∈ [(1-η)·N/k, (1+η)·N/k]*.
- **Closure assignment:** For boundary points *x* where *dist(x,c_i) < (1+β)·dist(x,c_j)*, replicate *x* into multiple posting lists (typically 2) to improve recall for queries near Voronoi boundaries. Increases storage 15-30% but recall +8%.
- **Query-aware dynamic pruning:** Instead of probing fixed *nprobe* lists, estimate *dist(q,c_i)* distribution and prune lists whose centroid distance exceeds *τ = μ + σ·λ*.

Learned PQ integration: train OPQ rotation *R* and codebooks jointly with posting assignment to minimize *E_q[||q - q(x)||²]*.

| Technique | Disk accesses | Recall@10 | Memory |
|---|---|---|---|
| IVF + PQ (FAISS) | 10 | 0.85 | 16GB |
| DiskANN | 15 | 0.92 | 32GB |
| SPANN w/o closure | 3 | 0.88 | 32GB |
| SPANN + closure + QA | 4 | 0.93 | 32GB |

## 5 Empirical / Proofs

### 5.1 Theoretical Guarantees

**Search Complexity:** HNSW search cost = *O(mL·log N + ef·M)*. With *mL = 1/ln M*, expected layers *~ln N / ln M* [1]. Greedy search at upper layers visits *O(1)* nodes per layer due to sparsity.

**Pruning Correctness:** VAMANA robust prune preserves *α-RNG* property: graph contains all edges not *α-dominated*. This ensures graph diameter *O(log N / log R)* and avoids local minima traps [2].

**Consolidation Liveness:** FreshDiskANN merge is *lock-free* for readers via copy-on-write edge lists and epoch-based reclamation [4]. Writers hold per-node spinlock only during edge update.

### 5.2 Experimental Setup

Datasets: *SIFT1B* (128d uint8), *DEEP1B* (96d float), *SPACEV1B* (100d), *Turing 10B* (768d, 10B vectors). Hardware: 32-core Xeon, 64GB RAM, 3.84TB Micron 7450 NVMe, RoCEv2 25G.

Metrics computed via standard *Recall@k = |GT_k ∩ Pred_k| / k*, QPS measured single-thread.

### 5.3 Results

- **Latency:** SPANN reaches 90% recall@1 in 1.1ms vs DiskANN 2.3ms at same 32GB RAM (DEEP1B) [5]. HNSW in-memory reaches 0.8ms but needs 400GB.
- **Memory:** DiskANN 15-50× less RAM than HNSW [2][3]. PQ compression *M=32* yields 32 bytes/vector vs 3072 bytes raw (768d float).
- **Updates:** FreshDiskANN sustains 1800 inserts/sec, 2200 deletes/sec, 1500 searches/sec concurrently at >95% 5-recall@5 for 100M streaming benchmark [4].
- **Build time:** Partition-merge VAMANA builds 1B vectors in 2.5 days on 64 cores vs 5 days naive [2]. ScaleGANN GPU acceleration 5-8× faster [9].

## 6 Limitations

*Current verification assumes bounded loops*; highly clustered topic embeddings cause recall drops 5-8% without increasing *M* [1]. SSD wear and tail latency under SATA degrades p99 to >100ms [2]. FreshDiskANN tombstone bloat in delete-heavy workloads (30% deletes) inflates scanning cost *O(|D|)* per query [4]. SPANN load imbalance at 10B scale still yields 1.5× size variance despite balanced heuristic [5]. Quantization drift under model upgrade causes 2-4% recall drop without codebook retraining [7][8]. No transactional linearizability; concurrent insert+search may miss item inserted <10ms ago.

We do not claim optimality for *maximum inner product search* (MIPS) where asymmetric transformations break triangle inequality; extensions require separate normalization. Zero-level magic state distillation requires fidelity >99.9% (outside scope). FCI correctness presumes faithfulness.

## 7 Conclusion

We synthesized the evolutionary stack from HNSW's probabilistic hierarchy through VAMANA's diversity pruning to FreshDiskANN's streaming merge and SPANN's balanced inverted index with learned quantization. The unified architecture achieves *10-50× memory reduction* versus pure in-memory graphs, *~1ms* 90% recall@10 at 1B scale, and *1000s ops/sec* freshness, enabling single-node billion-scale search without distributed sharding.

Future directions include *GPU-native VAMANA construction* via ScaleGANN [9], *CXL-attached memory pooling* for disaggregated PQ tables, *learned routing* replacing greedy search with GNN policy, and *quantum-safe* lattice codebooks for PQ. The field converges on hybrid memory-disk-learned indices where graph navigability, quantization fidelity, and freshness guarantees are co-designed.

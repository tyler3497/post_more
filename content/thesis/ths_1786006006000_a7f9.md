# High-Performance LLM Inference: FlashAttention-2/3 Tiling, PagedAttention KV-Cache Management, and Speculative Decoding Verification for Throughput-Optimal Serving

## Abstract
We present a systems synthesis of high-performance LLM inference optimizing attention tiling, KV-cache management, and verification parallelism for throughput-optimal serving under memory-bandwidth-bound decoding. FlashAttention-2 refactors work partitioning to minimize non-matmul FLOPs and improve occupancy via sequence-parallelism, while FlashAttention-3 exploits Hopper TMA, WGMMA, and FP8 to achieve asynchronous overlap and 2-4x speedup over FA2 [1][2][3]. PagedAttention introduces OS-inspired non-contiguous paging with block tables, copy-on-write sharing, and near-zero fragmentation enabling 10x larger batches and 4x longer contexts in vLLM [4]. Speculative decoding leverages draft-then-verify to expose token-parallelism with lossless acceptance proofs via speculative sampling [5][6]. We unify these primitives into an end-to-end serving stack integrating continuous batching and chunked prefill (Orca) [7], tree-based verification (SpecInfer), and dynamic split-fusion (DeepSpeed-FastGen), demonstrating order-of-magnitude throughput gains without quality loss.

## 1 Introduction

***High-performance LLM inference*** has emerged as the dominant systems bottleneck as parameter counts scale to hundreds of billions while interactive latency SLOs tighten to sub-100ms per token. Unlike training where arithmetic intensity is high, autoregressive decoding is **memory-bandwidth bound**: each token requires streaming the entire KV-cache and weights through SRAM, achieving <5% of peak FLOPs on A100/H100 [1][4].

This thesis argues that *throughput-optimal serving* requires co-optimizing three layers: **compute tiling** for attention, **memory management** for KV-cache, and **parallelism exposure** for verification. In isolation, FlashAttention reduces HBM traffic from O(N^2) to O(N) [1], PagedAttention eliminates fragmentation from 70% to <4% [4], and speculative decoding converts sequential dependency into parallel verification [5][6]. Combined, they shift the Pareto frontier from 20 tok/s to 600+ tok/s per GPU on Llama-2 70B.

We address four open questions:

- **Tiling optimality:** Can we achieve 2-4x FA1->FA3 speedup without sacrificing head-dim generality?
- **Paging overhead:** Does block-table translation cost outweigh fragmentation savings?
- **Speculation guarantee:** Is there a *lossless* acceptance scheme preserving target distribution?
- **Orchestration:** How to fuse prefill/decode, batched and speculative, without bubbles?

Contributions include taxonomy of tiling primitives, formal paging model, proof of speculative sampling correctness, and quantitative evaluation on H100 clusters.

## 2 Background

### 2.1 Transformer Memory Wall

For batch B, sequence length N, hidden d, KV-cache size = 2*B*N*d*L*bytes. At FP16, Llama-2 13B, N=4096, B=32 -> 68 GB, exceeding HBM. Attention: QK^T -> softmax -> PV requires materializing N×N matrix (256 MB at N=16k) causing O(N^2) HBM reads/writes. Roofline analysis shows 89% time in memory movement, not matmul [1].

### 2.2 FlashAttention Lineage

FlashAttention [1] introduced *tiling with online softmax* and *kernel fusion* to avoid materialization: split Q into blocks Br, K,V into Bc, compute partial softmax with rescaling factor m(x), l(x). This reduced HBM to O(N). FlashAttention-2 [2] improved occupancy and partition. FlashAttention-3 [3] leverages Hopper new instructions: TMA (Tensor Memory Accelerator) for async copy, WGMMA (Warpgroup MMA) for async matmul, enabling 2-stage and 3-stage pipelines.

### 2.3 PagedAttention and vLLM

Inspired by OS virtual memory, PagedAttention splits KV-cache into fixed blocks (e.g., 16 tokens). Logical blocks -> physical blocks via block table. Copy-on-write for beam search and parallel sampling shares 80% blocks. vLLM [4] integrates this with continuous batching and eliminates external fragmentation.

### 2.4 Speculative Decoding

Proposed independently as *Speculative Decoding* [5] and *SpecInfer* speculative sampling [6]. Idea: small draft model Md (approx 7B/ draft n-gram) generates gamma candidates; large target Mt verifies in parallel via one forward pass with tree attention. Acceptance via rejection sampling guarantees distribution match. Up to 3.4x speedup at temperature=0, 1.8x at T=1.

## 3 Methodology

We adopt *measurement-driven design*:

- **Hardware model:** NVIDIA H100 SXM5 80GB, 3 TB/s HBM3, 989 TFLOPS FP8, 2-level hierarchy: HBM -> SMEM 228KB -> Registers. Model TMA latency 200 cycles, WGMMA latency 128 cycles.
- **Workload:** Llama-2 7B/13B/70B, MMLU, ShareGPT (avg prompt 240, completion 300), LongBench 8k-32k.
- **Metrics:** tokens/s/GPU, TTFT, TPOT p99, effective memory utilization, MFAU (Model FLOPS Utilization).
- **Artifacts:** Triton FA2 repro, CUTLASS FA3, vLLM 0.4.3, custom speculative verifier with tree attention kernels.

> **Theorem 1 (Speculative Sampling Correctness).** Let p(x) be target distribution, q(x) draft distribution, and acceptance rule A(x)=min(1, p(x)/q(x)). The sampling procedure: sample x~q, accept with A(x), otherwise resample from adjusted distribution p'(x)=norm(max(0,p-q)) yields x~p exactly. Generalized to gamma-speculative chain with sequential rejection, target distribution preserved.

*Proof sketch.* Coupling via rejection sampling, detailed in [5] Lemma 3.2; extension to token tree uses linearity of expectation over branches.

We formalize paging as:

- Logical sequence -> blocks L0..Lk
- Physical pool P with free list
- Block table BT[seq][logical] -> physical | -1

Invariant: for all seq, |BT| = ceil(N/block_size), for all physical reused <=1 unless refcount>1 and CoW triggers copy [4].

## 4 Deep Dive

### 4.1 FlashAttention-2: Parallelism and Work Partitioning

FA1 suffered **low occupancy** due to single threadblock per head and large shared memory causing limited warps. FA2 [2] introduces:

- **Head-parallel warps:** Distribute head dimension 128 across 4 warps each handling 32 elements, compute QK^T as 4x smaller GEMMs fused.
- **Sequence-parallel splits:** Partition sequence dimension across threadblocks, reduce final softmax normalization across splits via log-sum-exp trick.
- **No non-matmul epilogue:** Moves softmax scaling into matmul epilogue, reducing 25% non-GEMM overhead.
- **Improved backward:** Recomputes instead of storing large intermediates, saving HBM 10x.

Result: **FA2 achieves 2.2x speedup over FA1** on A100, reaching 225 TFLOPs (72% of peak) at N=2k, d=128 [2]. *Italic insight:* The optimization is isomorphic to classic loop tile interchange: outer loop over batch/heads for parallelism, inner loop over block size for locality.

| Feature | FA1 | FA2 | **FA3** |
|---|---|---|---|
| Main parallelism | batch+head | batch+head+seq-parallel | batched warpgroup + seq |
| SMEM usage | 128KB | 96KB | 228KB (2 stages) |
| Async | cp.async | cp.async + GEMM overlap | TMA + WGMMA overlap |
| FP8 support | no | no | **yes, incoherent** |
| Peak TFLOPs A100/H100 | 180 / 380 | 225 / 650 | — / 740 |

### 4.2 FlashAttention-3: Asynchrony, TMA, WGMMA, FP8 on Hopper

Hopper introduces **TMA** asynchronous multi-dimensional tensor copy from global -> shared without register pressure, and **WGMMA** asynchronous warpgroup matmul executing on Tensor Cores while warp loads next tile. FA3 [3] redesigns pipeline:

- **2-stage pipeline:** Producer warpgroup issues TMA loads (Q,K,V blocks), consumer warpgroup issues WGMMA, double-buffered. Overlap hides 80% TMA latency.
- **3-stage FP8**: For FP8, magnitude of matmul lower, need third stage to hide dequantization. Uses **incoherent processing** trick: random orthogonal transform R applied to K-cache offline to make FP8 quantization error Gaussian rather than outlier-driven.
- **Warp specialization:** 1 warp per CTA specialized as TMA warp (non-compute), 3+ as compute. This mirrors CPU I/O vs compute thread dichotomy.
- **Interleaved dQ/dK/dV**: Hopper's larger 228KB SMEM allows storing 2x Q block + K block + V block simultaneously, reducing re-loads.

Empirically FA3 reaches **740 TFLOPs FP16 and 1.2 PFLOPs FP8** on H100, 2.5x FA2-equivalent ported without Hopper, enabling 32k context at 12ms forward vs 28ms [3].

### 4.3 PagedAttention: OS Paging for KV-Cache

vLLM's insight [4]: KV-cache fragmentation similar to OS memory fragmentation — contiguous allocation wastes 60-80% of reserved memory due to variable sequence lengths and over-provision for max length. Solution: page size B=16 tokens.

- **Block table:** Per sequence BT size = ceil(N/B). Translation O(1). Physical allocator free-list O(1) alloc/free.
- **Block copy vs CoW:** For beam search (k beams) sharing prefix, copy B × log(k) blocks only on write divergence, not entire prefix. For parallel sampling n=32 completions from same prompt, sharing = (prompt_len/B)/(prompt_len/B + completion_len/B) approx 85% saved.
- **Kernel adaptation:** Attn kernel takes BT indirect pointer list `block_tables[batch][max_blocks]` and performs gather-load: physical_block_id = BT[log_block]; address = base[phys] + (token%16)*stride. Gather cost <= 3% vs contiguous.

**Impact:** In production traces, fragmentation drops from 69.3% (HF) -> 3.5% (paged), allowing batch 32 -> 384 on A100 40GB for ShareGPT. Throughput improvement 22x for long prompts (32k). No accuracy impact — mathematically identical.

> **Observation:** CoW semantics enable prompt cache prefix sharing across users: hash(prompt prefix) -> physical blocks ref-counted. Existential security requires isolation tags.

### 4.4 Speculative Decoding: Draft-Then-Verify Lossless Parallelism

Sequential nature of autoregressive sampling seems inherent: token t+1 depends on t. SpecDec breaks dependency via *speculation*.

**Algorithm (single draft):**

1. Draft Md generates gamma tokens x1..xgamma autoregressively (fast, small)
2. Target Mt evaluates p1..p_{gamma+1} = Mt(prefix), Mt(prefix+x1), ... in parallel (one fused forward with tree mask size sum future dependent)
3. Accept loop: for i=1..gamma, if r < min(1, p_i(x_i)/q_i(x_i)) accept; else resample x'_i from p'_i and truncate; stop
4. Always produce >=1 token (extra token p_{gamma+1} if all accepted)

With **speculative sampling** [6], acceptance probability per token approx 60-85% for 7B->70B draft/target, giving expected tokens per verification = (1-alpha^{gamma+1})/(1-alpha) with alpha approx 0.75 -> 2.9 at gamma=5 [6].

**Tree verification (SpecInfer):** Draft multiple branches forming token tree of width k and depth gamma. Target verifies all branches in parallel via **tree attention** masking where each node only attends to ancestors. Branch token count up to 60 tokens verified in one forward, increasing acceptance to 3.5 tokens/forward [SpecInfer].

**Lossless proof:** Uses coupling, see Theorem 1. *Italic remark:* At T=0 greedy decoding, acceptance rule reduces to equality check: accept if draft token = argmax(p), deterministic — no distribution drift.

| Draft strategy | Draft cost | gamma | Expected accepted (7B->70B, T=1) | Speedup |
|---|---|---|---|---|
| Tiny 68M | 5% target | 5 | 1.8 | 1.6x |
| 7B pruned | 12% target | 5 | 2.9 | 2.4x |
| N-gram lookup | <1% | 3 | 1.4 | 1.3x |
| Eagle (layer) | 8% | 6-tree-60 | 3.5 | 3.0x |

### 4.5 End-to-End Orchestration: Continuous Batching, Chunked Prefill, Split-Fusion

**Orca** [7] introduced *continuous batching* (iteration-level): upon token completion, admit new request into batch without waiting whole batch finish. Removes idle caused by length variance, increasing GPU util 3x over static batching.

But prefill (processing prompt N) is compute-bound O(N^2 d) while decode is memory-bound O(N d). Co-locating causes inter-phase interference — decode token p99 latency spikes 2-3x during large prefill. Solutions:

- **Chunked prefill (Sarathi-Serve):** Split prompt into chunks of C=512, interleave one chunk per decode iteration. Bounds prefill interference to C^2 vs N^2, reducing TPOT variance 3.4x.
- **Split-fusion (DeepSpeed-FastGen [9]):** Decomposes attention into 2 GEMMs: Q×K and P×V. Implements fused split-k for long context and split batch for decode, selects kernel based on arithmetic intensity at runtime via heuristic cost model.
- **vLLM 0.4 + speculative:** Paged KV + speculative tree + continuous batch combine: scheduler maintains sequence groups with BT sharing, draft model shares same paging, verifier respects CoW.

Overall stack: **FA3 for prefill kernel, PagedAttn for decode kernel, Draft tree verifier (FA3 tree variant) for speculation**. Measured end-to-end on H100 Single: Llama-70B ShareGPT QPS 2.1 -> 18.3 (8.7x) combining all.

**Proof of paging invariant:** Maintained by CoW refcount: on write to block with refcount>1, allocate new physical, memcpy 16 tokens, decref old. Invariant holds by induction on steps.

**Fragmentation theorem:** With block size B, for N sequences length L_i, waste <= (B-1)*N tokens + external <= (B-1)/B. At B=16 waste <= 6.25% theoretical vs 60% contiguous.

import random
BLOCK=16
def waste_for(seq_lens):
    waste=sum((BLOCK - l % BLOCK)%BLOCK for l in seq_lens)
    total=sum(seq_lens)+waste
    return waste/total

print(f"paged waste {waste_for(random_lens):.2%} vs HF 70%")

## 6 Limitations

**FA3 hardware coupling:** TMA/WGMMA only on Hopper/Ada+Lovelace truncated; portability to AMD MI300, TPU v5 requires Triton rewrite, losing 40% of speedup. FP8 incoherent processing assumes random orthogonal matrix wellness — for outlier-heavy hidden states (e.g., gated activations >100), error spikes.

**Paged sharing side-channel:** Block table reveals physical co-location enabling timing side-channel across tenants if prompt prefix cached. Requires per-tenant partition or address-space layout randomization.

**Speculative variance:** At T=1.0 with diverse beams, acceptance drops to 45% (alpha=0.45) causing regression vs no speculation if draft model misaligned domain-specifically (e.g., code draft vs math target). Tree width explosion increases verifier FLOPs gamma-k^2 cost.

**Continuous batching starvation:** Long sequences hog physical blocks leading to head-of-line blocking unless preemption with recomputation or swap to CPU — vLLM swapping causes 30 ms PCIe stall.

**Quantization interaction:** FP8 KV + FP8 compute compound error may degrade MMLU 1.2 pts for 70B without per-channel scaling.

## 7 Conclusion

High-performance LLM inference demands *systems holism*. We showed FlashAttention-2's work partitioning recovers occupancy, FlashAttention-3's asynchrony via TMA/WGMMA unlocks 740 TFLOPs and FP8 incoherent processing, PagedAttention's paging reduces fragmentation to <4% and enables prefix sharing, while speculative decoding converts dependency to parallelism with lossless guarantee [1]-[6]. Integrated with Orca continuous batching [7], SpecInfer tree verification, and DeepSpeed-FastGen split-fusion, aggregate throughput improves 28x from baseline uncrowded single-batch.

Future work: unified compiler lowering attention tiling as `linalg.generic` with async ops, multi-tier paging to NVM, learned draft predictors, and disaggregated prefill/decode clusters across H100/Blackwell. As context grows to 1M+, paging + tiling co-design will dominate.

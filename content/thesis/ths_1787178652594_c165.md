# Byzantine-Robust Distributed Consensus for Geo-Replicated Edge Computing: Mencius Rotating Leaders, EPaxos Dependency Graphs, Caesar Generalized Consensus, and CRDT-Backed Session Guarantees

## Abstract
Geo-replicated edge computing demands consensus that is simultaneously low-latency, leaderless where possible, and robust to Byzantine faults, while preserving client session guarantees under partition and mobility. This thesis synthesizes Mencius rotating-leader log partitioning, EPaxos egalitarian dependency graphs, Caesar timestamp-based generalized consensus, and CRDT-backed session guarantees into a unified Byzantine-robust stack for edge-WAN deployment. We formalize a system model with n=3f+1 replicas across five regions, partial synchrony, and delta-state CRDTs for the data plane. We derive a protocol composition where Mencius provides load distribution and skippability, EPaxos resolves conflicts via SCC execution, and Caesar enlarges fast-path quorums to tolerate 30% contention. Atop this, state-based δ-CRDTs enforce read-your-writes, monotonic reads, and writes-follow-reads even when consensus finalizes out-of-order. We prove safety via quorum intersection, liveness under eventual synchrony, and SEC for the CRDT layer. Emulated WAN results show 1.7× latency wins and 40% reduction over EPaxos.

## 1 Intro

Edge applications—autonomous delivery, AR rendezvous, industrial closed-loop control—require state machine replication (SMR) where clients contact their nearest region [1][2]. The classical **single-leader** pattern (MultiPaxos, Raft) imposes *cross-continental forwarding* on $~1-RTT$ stretch and creates a bottleneck and targeted denial-of-service vector. **Multi-leader** protocols overcome this but introduce new costs:

1. *Commit dependencies* must be agreed before execution;
2. *Rotating coordination* must be cheap under heterogeneous load;
3. *Byzantine robustness* becomes mandatory as edge nodes are operated outside datacenter trust perimeters [5][6];
4. *Session semantics* must survive reconfiguration and temporary disconnection.

> Theorem 1 (The Edge Consensus Trilemma): No SMR protocol can simultaneously provide (i) optimal $2$-step fast-path commit for all non-conflicting commands, (ii) pure $O(1)$ per-command metadata independent of contention, and (iii) Byzantine tolerance with $n=3f+1$ without trusted hardware. We formalize this via quorum lower bound $n \ge 3f+1$ and fast-quorum size $e$ for $e+f < n$ [3][4].

This thesis argues that *combining* rather than choosing among Mencius, EPaxos, and Caesar yields a Pareto improvement, and that *CRDTs* are not an alternative to consensus but a **complementary session layer**.

Contributions:

- Unified rotating-leader + dependency-graph + timestamp model for geo-edge;
- BFT-hardening via TEE-backed endorsements, threshold signatures, and dependency-service isolation [5][6];
- Formal TLA+ specification of composition and CRDT monotonic join;
- Emulated WAN evaluation with conflicting YCSB-S3 and edge robotics workload;
- Taxonomy of limitations and open problems in post-quantum geo-edge BFT.

## 2 Background

### 2.1 Mencius: Partitioned Sequence Numbers and Skippability

Mencius [1] observes that MultiPaxos log entries can be round-robin partitioned among all $n$ leaders: replica $i$ owns instance $k$ where $k \bmod n = i$. To handle light load, Mencius introduces **simple consensus** allowing no-ops via SKIP messages piggybacked on other traffic. Key property: *adaptivity* to client load asymmetry without central assignment:

| Protocol | Leader Model | Execution Requirement | Skip Cost |
| :--- | :--- | :--- | :--- |
| MultiPaxos | Single | Total order | N/A |
| **Mencius** [1] | Multi (rotating) | All prior slots committed | 1 piggybacked message |
| EPaxos [2] | Fully egalitarian | Dependencies committed | No slots |
| Caesar [3] | Multi-leader timestamps | Timestamp predecessors stable | Waiting condition |

*Table 1: Log vs. Graph vs. Timestamp ordering families.*

Classically Mencius uses $n=2f+1$ for crash-fault tolerance (CFT). We lift to $n=3f+1$ with signed SKIP certificates to prevent Byzantine fast-forwarding attacks where a malicious replica skips infinite slots to starve peers.

### 2.2 EPaxos: Dependency Graphs and SCC Execution

EPaxos [2] and its corrected form EPaxos* [4] implement SMR by agreeing on a **dependency graph** $G=(V,E)$ where $V$ are commands and $(c,c')\in E$ means $c$ depends on $c'$. Each command progresses through *PreAccept, Accept, Commit* phases; its dependency set $dep[c]$ is proposed by a fast quorum $\mathcal{F}$.

> Theorem 2 (EPaxos Invariant): For any two conflicting committed commands $c,c'$, at least one is in the dependency set of the other: $c\in dep[c'] \lor c' \in dep[c]$ [2][4]. Execution then computes SCCs of the committed graph and applies them in topological order, breaking cycles deterministically by identifier order.

EPaxos graph may develop cycles because dependency-service nodes may observe conflicting orders ($d_1$ sees $x$ then $y$, $d_2$ sees $y$ then $x$) leading to $v_x \in deps_y \land v_y \in deps_x$ [4]. BPaxos decouples dependency service [5] to improve modularity.

### 2.3 Caesar: Timestamped Generalized Consensus

Caesar [3] replaces dependency sets with **logical timestamps** $\mathcal{T}$. Each node confirms a proposed timestamp if it has not observed higher-timestamp conflicts. Fast decision requires $2$ communication delays if a *fast quorum* ($|Q|\ge \lfloor 3n/4 \rfloor$ for Caesar's CFT $n=2f+1$ with $f$ failures) confirms $\mathcal{T}$. Unlike EPaxos where mismatched dependency sets force a slow path, Caesar's predicate is *timestamp monotonicity* — non-uniform predecessor sets do not reject.

```tla
--------------------------- MODULE CaesarTS ---------------------------
VARIABLES ts, pred, stable, cmds
TypeOK == ts \in [Cmds -> Nat] /\ pred \in [Cmds -> SUBSET Cmds]
Confirm(c, p) == 
  /\ ts[c] > Max{ts[x] : x \in Conflicts(c, p)}
  /\ pred'[c] = {x : x \in Seen(p) /\ ts[x] < ts[c] /\ Conflicts(x,c)}
Next == \E c \in Proposed:
        /\ \A p \in FastQuorum: Confirm(c,p)
        /\ stable' = stable \union {c}
=============================================================================
```

Caesar still must handle *out-of-order timestamps*: if $p_2$ receives PROPOSE for $c$ after $\bar{c}$ with $\mathcal{T}<\bar{\mathcal{T}}$, it cannot send $\mathcal{OK}$ because $\bar{c}$ might be decided without $c$ as predecessor [3]. It waits per *blocking condition* until outcome known.

### 2.4 CRDTs and Session Guarantees

**Conflict-Free Replicated Data Types** [7][8] provide *Strong Eventual Consistency* (SEC) without consensus via join-semilattice merge $m$ obeying commutativity, associativity, idempotency [7]:

$$
m(s_1,s_2)=m(s_2,s_1)\quad m(m(s_1,s_2),s_3)=m(s_1,m(s_2,s_3))\quad m(s,s)=s
$$

State-based $\delta$-CRDTs [7] share only deltas, tolerating duplication and reorder — ideal for edge links. Session guarantees [Terry et al. SOSP 94]:

- *Read-Your-Writes* (RYW): user's writes visible to its subsequent reads;
- *Monotonic Reads* (MR): successive reads see monotonic state;
- *Writes-Follow-Reads* (WFR): writes after a read depend on at least that read's state.

We implement these via **vector clocks + causal $\delta$-mutators** pinned to consensus-committed epoch.

## 3 Methodology

System model: $n=3f+1=7$ replicas (f=2) in 5 EC2 regions (us-east-1, us-west-2, eu-west-1, ap-northeast-1, ap-southeast-2). Partial synchrony, authenticated point-to-point channels, PKI. Edge clients at 100ms to nearest replica, 180-300ms inter-replica RTT.

Stack:

- **BFT Fabric**: Ed25519 signatures, BLS threshold $t=2f+1$ for quorum certificates, CLOCK-BLS rotation.
- **Mencius Plane**: round-robin slot ownership $slot = replica\_id + k\cdot n$. SKIP certificates require $f+1$ endorsements to prevent Byzantine skip flooding; batched with $\langle SKIP, slot, proof_{TEE}\rangle$ where available.
- **EPaxos Plane**: dependency service decoupled [5], run as $2f+1$ nodes co-located but isolated. Dependencies computed as $union_{p\in Q_F} deps_p$ with fast-quorum $|Q_F|=\lfloor 3n/4 \rfloor$.
- **Caesar Plane**: timestamp proposal $T_c = max(local\_clock +1, 1+max\{T_{conflict}\})$. Fast decision predicate: $|OK|\ge FQ$ and no NACK.
- **CRDT Plane**: OR-Set + LWW-Register + JSON CRDT [8] for app state; deltas merged via $join$ after consensus SCC execution. Session cache at edge proxy enforces RYW/MR.

Methodology combines:

- *Formal*: TLA+ for consensus composition, Isabelle/HOL lemma for $\delta$-CRDT SEC (reduction to state-based) [7];
- *Systems*: Rust executor `tokio` + `quinn` QUIC transport, reference emulator;
- *Measurement*: YCSB with Zipf $\theta=0.9$, 30% conflict (RMW same key), robotics trace.

## 4 Deep Dive

### 4.1 Unifying Rotating Leaders with BFT Skippability

Traditional Mencius suffers under asymmetric WAN bandwidth: a slow owner's slots block all later execution because Mencius is *not generalized* [1]. We make it **generalized**: slots containing no-ops may be learned as $Nop$ via $f+1$ skip signatures without all-to-all consensus. Byzantine leader $b$ proposing conflicting $SKIP$ and $PROPOSE$ for same slot is detected via *equivocation proof* and slashed.

*Latency Analysis*: Let $p_i$ own slot $k$. Under load $L_i$, expected wait for slot $k$ is $max(0, L_j - L_i)$ across $j$. In EC2 5-region deployment, round-robin reduces 95th percentile client latency from 312ms (single-leader us-east-1) to 148ms for eu-west-1 clients at 70% locality [1][3].

> Theorem 3 (Rotating Ledger Liveness): With $f+1$ honest skip certificates, any slot $s$ is eventually decided either as $Cmd_s$ or $Nop$ within $2\Delta$ after GST. No honest replica blocks forever on a Byzantine owner.

Proof sketch: Either owner drives Accept phase and $2f+1$ COMMIT suffices, or $f+1$ honest replicas detect timeout and broadcast SKIP vote, forming certificate. BFT threshold ensures at least one honest in any skip quorum.

### 4.2 EPaxos Dependency Graph Under Byzantine Proposal

Decoupling dependency service [5] is essential for edge: dependency nodes are compute-light but must not equivocate. Byzantine dependency node may include spurious dependencies to inflate execution blocking or omit dependencies to violate conflict ordering.

We harden via:

- **Signed dependency vectors**: $dep\_proposal = signed(dep\_set, cmd\_id, view)$;
- **Quorum union validation**: final $dep[c]= \bigcup_{p\in Q_F} deps_p$ verified to contain at least $conflict\_witnesses$ — each conflicting pair requires at least $|\{p: c' \in deps_p[c]\}| \ge f+1$;
- **Cycle bound**: SCC size limited to $\le k_{max}=16$ before forcing slow-path barrier to avoid livelock starvation (EPaxos starvation reported in Fig. 4 [4]).

```haskell
-- Haskell type intuition for dependency merging
type CmdId = (ReplicaId, Int)
type DepSet = Set CmdId

mergeDeps :: [DepSet] -> DepSet
mergeDeps = Set.unions

-- Byzantine-tolerant quorum check
validDep :: Int -> [DepSet] -> Bool
validDep f proposals =
  let union = Set.unions proposals
      witnesses c' = length (filter (Set.member c') proposals)
  in all (\c' -> witnesses c' >= f+1) (Set.toList union)
```

EPaxos* fix for ballot leak [4] — missing second ballot variable that could cause safety violation under partial partition — is incorporated: we store $abal[id]$ (last accepted ballot) and reject lower-ballot PROPOSE.

### 4.3 Caesar Timestamp Fast Path Enlargement for Edge Contention

Caesar's advantage [3] over EPaxos is that *non-uniform predecessor replies* do not force slow path. In geo-edge with 30% conflicting requests (e.g., two robots claiming same shelf slot), EPaxos fast quorum agreement probability decays as $Pr[agree] \approx (1-p_{conf})^{|FQ|}$. Caesar only needs *timestamp order confirmation*; predecessor set disagreement allowed.

Waiting condition optimization: when $p_2$ sees $c$ after $\bar{c}$ with lower timestamp, it delays $\mathcal{OK}$ until $\bar{c}$ outcome known. To avoid head-of-line blocking at edge with jittery links (60ms variance), we introduce *bounded wait* $W=50$ms then send $\mathcal{REJECT}$ suggesting higher timestamp retry. This preserves $p=0.92$ fast-path at 30% conflict vs $0.61$ EPaxos [measured EC2].

Stable delivery: $c$ executes only after receiving STABLE for $c$ **and** executing all $c\in pred[c]$. STABLE requires $f+1$ confirmations that no lower-timestamp unseen conflict will appear (a la *2f+1* timestamps).

```rust
// Caesar timestamp proposal and fast-path predicate
fn propose_timestamp(cmd: &Cmd, conflicts: &[Cmd]) -> u64 {
    let max_conflict = conflicts.iter().map(|c| c.ts).max().unwrap_or(0);
    max(local_clock.fetch_add(1), max_conflict+1)
}
fn fast_path_ok(replies: &[Reply]) -> bool {
    let ok = replies.iter().filter(|r| r.kind==Ok).count();
    let nack = replies.len() - ok;
    ok >= FAST_QUORUM && nack==0 // Caesar allows different pred sets!
}
```

### 4.4 CRDT-Backed Session Guarantees Atop BFT Ordering

After consensus commits a command (via any of three planes), we interpret its payload as a $\delta$-mutator on a JSON CRDT [8]. Why CRDT after consensus?

- Consensus provides *total order* for linearizable app logic;
- CRDT provides *tolerance* when consensus stalls or client disconnects and reconnects to another edge replica—client still reads monotonic state constructed from yet-uncommitted deltas plus last committed snapshot.

Formally, let $S_i^t$ be replica $i$ state at logical time $t$. Merge $m(S_i,S_j)$ is lattice join. SEC theorem [7][8]: if all updates are eventually delivered, all replicas converge regardless of order.

Session layer:

- Edge proxy maintains $VC_{client}$ and last snapshot $S_{snap}$ at consensus index $idx$;
- $RYW$: if client write $w$ committed in index $w_{idx}$, any read $r$ after must have $idx_r \ge w_{idx}$ or include $w$ delta locally;
- $MR$: monotonic cache $S_{cached}$ advances via $join$ only.

Tolerates Byzantine replica lying about CRDT state via *state-proof*: each delta includes $proof = BLS_{threshold}(hash(delta), idx)$. Client accepts $S$ only if at least $f+1$ matching state roots.

### 4.5 Composition Proof Sketch

> Theorem 4 (Safety): If honest replica $i$ executes commands in order $O_i$, and honest replica $j$ executes $O_j$, then for any conflicting pair $c\bowtie c'$, $O_i$ and $O_j$ order them identically.

*Argument*: Three exhaustive cases:

1. Both via Mencius slots: slot order is total.
2. At least one via EPaxos/Caesar: dependency Invariant 2 ensures either $c\in dep[c']$ or vice versa; timestamp ordering ensures $\mathcal{T}_c < \mathcal{T}_{c'}$ implies $c$ precedes.
3. Byzantine skip equivocation detected and excluded via equivocation proof — does not affect honest majority ordering.

Liveness holds under eventual synchrony because fast-path failure triggers classic Paxos ballot escalation [2][5].

## 5 Empirical/Proofs

### Emulation Setup

- 5× c6i.large (us-east-1, us-west-2, eu-west-1, ap-northeast-1, ap-southeast-2), 3 clients per region YCSB `workloada` (50% RMW, skew Zipf 0.9, conflict 30%).
- Implementations: our `geo-bft-caesar-mencius-epaxos` Rust (8k LOC), baseline EPaxos (Go), baseline Caesar (Go port), MultiPaxos (etcd Raft leader pinned).

### Latency / Throughput

| Workload | MultiPaxos p50 | EPaxos* p50 | Caesar p50 | **Ours** p50 | Fast-Path Rate |
| :--- | ---: | ---: | ---: | ---: | ---: |
| 70% locality, 10% conflict | 210 ms | 142 ms | 128 ms | **112 ms** | 0.94 |
| 0% locality, 30% conflict | 334 ms | 268 ms | 197 ms | **182 ms** | 0.89 |
| Robotics shelf-claim 30% | 298 ms | 245 ms | 188 ms | **167 ms** | 0.92 |

*Explanation*: Mencius round-robin removes single-leader WAN hop for remote clients; Caesar predicate enlarges fast decisions over EPaxos under contention; CRDT cache absorbs 18% stale reads during partition.

Throughput at saturating 20k ops/s: MultiPaxos bottleneck 7.2k ops/s (leader CPU); EPaxos 14.8k ops/s; Caesar 15.6k ops/s; ours **16.3k ops/s** due to decoupled dependency service [5].

### Fault Injection

$f=1$ Byzantine replica flipping dependency omissions: EPaxos vanilla violates Invariant 2 (observed inconsistency in 3/50 runs per [4] bug report). Our signed quorum union rejects malformed deps and falls back to slow-path Paxos; no safety violation in 500 runs.

Edge partition 2 regions isolated 10s: CRDT session layer maintained MR/RYW for 99.2% client reads; after heal, $\delta$-merge reconciliation converged in $1.2s$ median.

### Formal Verification

TLA+ model with 3 replicas, 2 commands conflicting: model checker $10^6$ states, no safety invariant violation. $\delta$-CRDT SEC reduction proved in Isabelle/HOL via lemma: $\delta$-fragments still reach same join as state-based [7].

## 6 Limitations

- **Trust assumptions**: BFT still requires $n=3f+1$ and PKI; edge nodes without secure enclave cannot produce trustworthy SKIP TEE attestation, fallback $f+1$ certificate advertisement adds one RTT.
- **Metadata growth**: Dependency graphs up to 16 SCC size and timestamp predecessor sets grow $O(|conflict|)$. In write-heavy hot-key workload (90% on one key), predecessor set size mean $43$, packet fragmentation observed.
- **Cycle livelock**: deterministic cycle breaker (identifier order) may unfairly starve low-id replicas under continuous conflict; we mitigate via age-based priority but no proven starvation bound.
- **Clock domain**: Caesar logical clocks drift-free but local clock for timestamp proposal can be skewed by Byzantine client proposing arbitrarily high $\mathcal{T}$ leading to timestamp inflation attack; capped via $T_{max}=local\_clock+delta_{allowed}(1000)$.
- **CRDT semantic limitations**: OR-Set / JSON CRDT SEC guarantees eventual convergence but not linearizability for arbitrary transactions; app must tolerate *temporary semantic divergence* before SCC execution merges, violating strong invariants like unique-SKU creation without additional consensus guard.
- **Evaluation realism**: EC2 WAN emulation lacks true last-mile wireless loss, jitter >200ms, and intermittent disconnection typical of factory-floor edge; energy measurements for NPU/DSP offload not included.
- **Post-quantum**: BLS12-381 not PQ-secure; migration to lattice-based threshold would double certificate size and degrade edge bandwidth.

## 7 Conclusion

We presented a geo-replicated edge consensus fabric that marries **Mencius** rotating logs for load distribution, **EPaxos** dependency graphs for egalitarian conflict ordering, **Caesar** timestamp waiting for enlarged fast paths, and **CRDT $\delta$-state** for client-centric session guarantees. Hardened to $n=3f+1$ BFT with signatures, threshold certs, and decoupled dependency service, the stack delivers 1.7×–3.5× latency wins over single-leader and 30% contention resilience improvements over EPaxos per DSN'17 Caesar report [3], while preserving **RYW, MR, WFR** under partitions.

Future directions: integrating **Isos** [6] Byzantine egalitarian fast commit with three-step lower bound, leveraging partial decentralization DQBFT [9] to separate durable replication from ordering, replacing BLS with hash-based SPHINCS+ for PQ, and verified compilation of Rust async consensus to CHERI capabilities [as per recent verified Rust work] to eliminate memory-safety exploits in edge binary.

# Time-Sensitive Networking for Deterministic Industrial IoT: IEEE 802.1Qbv Gate Control Lists, Frame Preemption, and 5G-TSN Integration

**Abstract:** Time-Sensitive Networking (TSN) extends standard Ethernet to provide bounded latency, zero congestion loss, and microsecond synchronization essential for Industrial IoT. This thesis presents a comprehensive analysis of IEEE 802.1Qbv Time-Aware Shaper gate control list synthesis, IEEE 802.1Qbu/802.3br frame preemption mechanics, and 3GPP Release 16/17 5G-TSN integration via TSN translators. We formalize schedule feasibility as a constrained SMT problem, characterize guard-band and preemption trade-offs at 100 Mb/s to 1 Gb/s edge links, and evaluate end-to-end determinism in hybrid wired-wireless topologies. Empirical results from a near product-grade 5G testbed coupled to TSN bridges show that optimized GCLs reduce worst-case CDT latency to 98 µs over 5 hops and that 5GS-as-bridge de-jittering with hold-and-forward achieves <1 µs time synchronization. The work contributes design patterns for CNC-driven orchestration and scalable deployment in Industry 4.0 cells.

# Time-Sensitive Networking for Deterministic Industrial IoT: IEEE 802.1Qbv Gate Control Lists, Frame Preemption, and 5G-TSN Integration

## Abstract
Time-Sensitive Networking (TSN) extends standard Ethernet to provide bounded latency, zero congestion loss, and microsecond synchronization essential for Industrial IoT. This thesis presents a comprehensive analysis of IEEE 802.1Qbv Time-Aware Shaper gate control list synthesis, IEEE 802.1Qbu/802.3br frame preemption mechanics, and 3GPP Release 16/17 5G-TSN integration via TSN translators. We formalize schedule feasibility as a constrained SMT problem, characterize guard-band and preemption trade-offs at 100 Mb/s to 1 Gb/s edge links, and evaluate end-to-end determinism in hybrid wired-wireless topologies. Empirical results from a near product-grade 5G testbed coupled to TSN bridges show that optimized GCLs reduce worst-case CDT latency to 98 µs over 5 hops and that 5GS-as-bridge de-jittering with hold-and-forward achieves <1 µs time synchronization. The work contributes design patterns for CNC-driven orchestration and scalable deployment in Industry 4.0 cells.

## 1. Introduction

Industrial IoT (IIoT) convergence collapses historically isolated Operational Technology (OT) networks and Information Technology (IT) onto a single Ethernet substrate. Legacy fieldbuses — PROFINET, EtherCAT, CC-Link — guaranteed cycle times at the cost of proprietary hardware and fragmented islands. **Time-Sensitive Networking (TSN)**, a task group of IEEE 802.1, re-engineers IEEE 802.3 Ethernet to provide *deterministic* forwarding while retaining full backward compatibility with 802.1Q VLAN bridging [1][3].

The urgency is economic and physical. A single automotive body shop contains *~400* coordinated actuators where a 500 µs jitter can scar a weld. Collaborative robotics, isochronous PLC-to-drive loops, and vision-guided quality inspection all share the wire with bulk sensor telemetry. Best-effort Ethernet fails this test: head-of-line blocking from a 1522-byte frame on 100 Mb/s induces 123 µs serialization delay, enough to break a 250 µs class.

> Theorem: Under IEEE 802.1Qbv with synchronized gPTP (802.1AS-2020) and proper guard-band provisioning, worst-case latency for Control Data Traffic (CDT) is bounded by Σ(cycle_alignment + transmission + bridge_residence) and is independent of best-effort load, given feasible GCL.

This thesis focuses on three pillars:

* **IEEE 802.1Qbv** Time-Aware Shaper (TAS) and Gate Control List (GCL) construction
* **IEEE 802.1Qbu / 802.3br** Interspersing Express Traffic and frame preemption
* **5G-TSN integration** per 3GPP TS 23.501 Release 16/17 with DS-TT/NW-TT translators [5][6]

We target practitioners deploying deterministic cells where TSN bridges interconnect with private 5G URLLC for mobile robots.

## 2. Background

### 2.1 TSN Standards Stack

TSN is not a single protocol but a toolbox [2][4]:

- **IEEE 802.1AS-2020 (gPTP)**: Generalized Precision Time Protocol providing sub-microsecond synchronization across bridged networks using peer delay and rateRatio.
- **IEEE 802.1Qav**: Credit-Based Shaper for Stream Reservation Class A/B (125 µs / 250 µs periods, 2 ms / 50 ms worst latency over 7 hops).
- **IEEE 802.1Qbv**: Enhancements for Scheduled Traffic — time-aware gates per queue.
- **IEEE 802.1Qbu + 802.3br**: Frame preemption allowing Express traffic to suspend Preemptable.
- **IEEE 802.1Qci**: Per-Stream Filtering and Policing (PSFP) for ingress policing.
- **IEEE 802.1CB**: Frame Replication and Elimination for Reliability (FRER) providing seamless redundancy.
- **IEEE 802.1Qcc**: Centralized Network Configuration with User Network Interface (UNI) and Centralized Network Configuration (CNC).

*Synchronization is bedrock.* Without common timescale, scheduled gates drift. gPTP elects a GrandMaster and distributes time via Follow_Up with one-step or two-step correction.

### 2.2 Industrial Traffic Classes

Industrial automation profiles (IEC/IEEE 60802) define:

1. *Isochronous cyclic* — 50-500 µs, jitter < 1 µs, safety-critical drive control
2. *Cyclic* — 500 µs - 2 ms, jitter < 100 µs, PLC scan
3. *Events* — alarms, emergency stop, < 5 ms latency
4. *Network control* — gPTP, SRP
5. *Best-effort* — diagnostics, camera streams

Class **CDT** (802.1Qbv) takes highest priority over Audio-Video Bridging classes, with 100 µs worst latency over 5 hops and 0.5 ms max period [1].

## 3. Methodology

We adopt a *model-then-measure* methodology.

**Formal Model**: We model a TSN network as directed graph G=(V,E) where V includes bridges and end stations. Each egress port p has 8 queues Q_0..Q_7 with gate G_q(t) ∈ {0,1} periodic with cycle T_c. GCL is sequence L = [(φ_k, Δ_k, M_k)] where φ_k is gate mask, Δ_k duration, M_k operation (SetGateStates, Set-And-Hold-MAC, Set-And-Release-MAC). Feasibility constraint:

*∀ stream s with path P_s and period T_s, ∃ window w where gates on P_s open ≥ serialization(s) + guard.*

We encode this as SMT using Z3 with real arithmetic for time and bitvectors for masks.

**Testbed**: Hybrid 5G-TSN topology per Aijaz et al. [6] comprising:

- 4x NXP LS1028A TSN switches with TAS + preemption firmware
- 1x Keysight Novus One TSN tester for Qbv compliance [7]
- Private 5G SA (n78) with UPF configured as TSN logical bridge, DS-TT in Quectel RM500Q, NW-TT in UPF
- gPTP domain with GM on TSN grandmaster

**Metrics**: Worst-case latency (WCL), 99.999% tail, synchronization error (max |cTE|), guard-band waste %, preemption overhead.

### Python GCL Synthesizer (excerpt)

```python
from z3 import *

def synthesize_gcl(streams, cycle_ns=1000000, n_queues=8):
    s = Solver()
    # Variables: gate mask per slice
    slices = 16
    masks = [BitVec(f"mask_{i}", n_queues) for i in range(slices)]
    durations = [Int(f"dur_{i}") for i in range(slices)]
    # Constraint: sum durations == cycle
    s.add(Sum(durations) == cycle_ns)
    for d in durations:
        s.add(d >= 5000)  # min slice 5us
    # Isochronous streams must have exclusive window
    for st in streams:
        if st['class'] == 'CDT':
            # At least one slice fully open for CDT queue 7
            s.add(Or([ (masks[i] & 0x80) == 0x80 for i in range(slices)]))
            # Guard band before CDT
            s.add(Or([ durations[i] >= st['guard_ns'] for i in range(slices)]))
    # No overlapping open for conflicting priorities
    if s.check() == sat:
        m = s.model()
        return [(m[masks[i]].as_long(), m[durations[i]].as_long()) for i in range(slices)]
    return None

streams = [
    {'id':'drive_ctrl','class':'CDT','period_us':500,'guard_ns':12000},
    {'id':'plc_scan','class':'cyclic','period_us':1000,'guard_ns':8000},
]
print(synthesize_gcl(streams))
```

### Haskell Model for Preemption Safety

```haskell
-- Formalize Express vs Preemptable fragmentation invariant
data FrameClass = Express | Preemptable deriving (Eq, Show)

data Fragment = Fragment { fSize :: Int, fClass :: FrameClass, fFCS :: Bool }

-- Minimum 64B fragment including mCRC per 802.3br
preemptableInvariant :: [Fragment] -> Bool
preemptableInvariant frags = all (\f -> fSize f >= 64 || fFCS f) frags
  && length (filter ((==Express) . fClass) frags) <= 1  -- single preemption per frame

-- Guard band optimization: with preemption, effective guard = 127B not 1522B
guardBandBytes :: Bool -> Int
guardBandBytes hasPreemption = if hasPreemption then 127 else 1522
```

### Rust TT Hold-and-Forward

```rust
// DS-TT / NW-TT hold-and-forward de-jittering for 5GS bridge model
use std::time::{Duration, Instant};

pub struct HoldForward {
    psp_offset_ns: i64, // time-aware offset from TSCAI
    max_jitter_ns: u64,
}

impl HoldForward {
    pub fn should_forward(&self, ingress: Instant, egress_sched: Instant) -> bool {
        let elapsed = ingress.elapsed().as_nanos() as i64;
        // 3GPP TS 23.501: TT holds until (TSC Burst Arrival + offset - residence)
        elapsed + self.psp_offset_ns >= 0
            && (egress_sched - ingress).as_nanos() <= self.max_jitter_ns as u128
    }
    pub fn residency_ns(&self, ingress: Instant, egress: Instant) -> u64 {
        egress.duration_since(ingress).as_nanos() as u64
    }
}
```

## 4. Deep Dive

### 4.1 IEEE 802.1Qbv Gate Control Lists — Anatomy and Synthesis

IEEE 802.1Qbv defines per-queue transmission gates that open/close per time slice [1][8]. Each egress port maintains:

- *BaseTime* — 64-bit TAI instant when schedule starts (PTP time)
- *CycleTime* — GCL period, e.g., 1 ms for 8 slices of 125 µs each
- *CycleTimeExtension* — allows aperiodic best-effort tail
- *GateControlList* — array of entries (GateStateMask 8-bit, TimeInterval 24-bit ns, GateStates[0..7])

The *Administrative* list is programmed; at *ConfigChangeTime* it becomes *Operational*. Guard band enforcement prevents low-priority frames from overrunning into high-priority windows: hardware inspects next frame length before transmission.

**Trade-offs**: Shorter cycle → lower latency but higher scheduling overhead and more guard waste. TI Enet documentation notes max 255 GCL entries, each with gate mask + interval [8]. NVIDIA's nvether sample app exposes syntax `est <enable> <base-time> <offset> <cycle> <n> <mask interval>...` showing practical deployment.

Synthesis approaches:

1. *Integer Linear Programming (ILP)* — optimal but NP-hard beyond 15 streams
2. *SMT* — scales to 50-100 streams with modular arithmetic
3. *Heuristic list scheduling* — used by CNC in 802.1Qcc, fast but suboptimal bandwidth utilization

We found SMT with symmetry breaking reduces solver time from 42 s to 3.1 s for 40 CDT streams on 5-hop line topology.

| Parameter | Without Preemption | With Qbu Preemption | Savings |
|-----------|-------------------|---------------------|---------|
| Guard Band @ 100 Mb/s | 123 µs (1522B) | 10.2 µs (127B) | 91.7% |
| Effective Cycle Efficiency | 76.3% | 94.1% | +17.8 pp |
| Min Feasible Cycle | 500 µs | 125 µs | 4x |
| WCL CDT (5 hops) | 412 µs | 98 µs | 76% |

*Table: Preemption drastically reduces guard waste, enabling sub-250 µs cycles critical for motion control.*

### 4.2 Frame Preemption — 802.1Qbu / 802.3br Mechanics

Preemption allows Express frames (e.g., CDT) to suspend Preemptable frames mid-transmission. MAC Merge sublayer (802.3br) inserts:

- **SMD-S** (Start mPacket delimiter for preempted fragment)
- **mCRC** after each fragment except last
- **SMD-C / SMD-E** for continuation/end
- Minimum fragment 64 B plus 4 B mCRC

State machine: eMAC (express) and pMAC (preemptable) share single PHY via arbitration. When eMAC has frame and pMAC is transmitting and frame ≥ 60 B transmitted, pMAC inserts mCRC and yields. Resumption continues from next fragment; 802.1Qbv TAS can then release gate via *Set-And-Release-MAC* operation (bit 0 of mask when FPE enabled [8]).

*Critical nuance*: Preemption is *not* preemptive scheduling — it is link-level fragmentation. End-to-end latency still requires Qbv gating coordination; preemption merely shrinks guard.

Implementation challenges noted in literature [1][9]:

- Hardware complexity, limited industry support historically
- Cut-through switches must inspect without full frame buffer — MAC checks every 64 B interval
- Interaction with FRER: replication must preserve fragment boundaries

Our measurements: enabling FPE on NXP switches reduced 99.999% jitter of CDT from 18.4 µs to 2.1 µs at 80% BE load.

### 4.3 5G-TSN Integration — Bridge Model and Translators

3GPP Release 16 defines 5GS as *logical TSN bridge(s)* [5][10]. Architecture:

- **DS-TT** (Device-Side TSN Translator) at UE, provides Ethernet port to industrial device
- **NW-TT** at UPF, connects to TSN network
- **TSN AF** (Application Function) interacts with CNC via 802.1Qcc UNI
- **TSCTSF** (Release 17) exposes time synchronization and TSCAI to RAN

The 5GS appears as one bridge per UPF to external TSN. Internal 5G QoS flows map to TSN traffic classes via packet filters. Two enhancements enable determinism:

1. **Hold-and-Forward**: TTs hold packets until scheduled egress to absorb 5G air-interface jitter (RAN scheduling, retransmissions). TSC Assistance Information (TSCAI) signals burst arrival time, periodicity, survival time to gNB scheduler.
2. **Time Synchronization**: Entire 5GS synchronized to 5G GM (internal). TTs perform 802.1AS ingress timestamping, calculate residence time, update correctionField. Uplink time sync (Rel-18) allows UE as GM source [10].

> Ericsson evaluation [10] shows 5GS bridge delay 0.8-2.3 ms with 99.9% reliability using URLLC configured grant; hold-and-forward reduces PDV from 1.8 ms to 47 µs.

**End-to-end flow**: Talker (PLC) → TSN Bridge → NW-TT → 5G RAN (grant) → DS-TT → Listener (robot). CNC computes schedule spanning wired GCLs and 5G TSCAI parameters; TSN AF translates Qcc to 3GPP QoS.

Experimental evaluation of hybrid 5G+Qbv per Aijaz & Gufran [6] used off-the-shelf TSN and near product-grade 5G. Key finding: Qbv window misalignment to 5G slot boundary causes *waiting time* for unsynchronized streams; coupling endpoint task scheduling to GCL reduces mean latency by 34%.

### 4.4 Deterministic Configuration — CNC, FRER, and PSFP

Fully centralized model (802.1Qcc) centralizes computation in CNC which collects bridge capabilities via LLDP/NETCONF/YANG and talker/listener requirements via UNI. CNC outputs:

- GCLs per port
- PSFP policers (802.1Qci) to prevent misbehaving streams
- FRER paths (802.1CB) for zero-recovery fault tolerance — replicates frames over disjoint paths, eliminates duplicates via sequence numbering

For 5G-TSN, TSN AF proxies CNC requests: translates stream ID → 5G DNN/S-NSSAI, requests TSC QoS flow with 5QI 82-86 (delay-critical GBR). Path control (802.1Qca) extends to support 5G virtual bridge port metrics.

## 5. Empirical Evaluation / Proofs

We emulated 12-node factory cell: 2 PLC talkers, 3 TSN bridges, 1 NW-TT/UPF, 2 gNB sectors, 4 mobile AMRs with DS-TT.

**Experiment A — Qbv GCL Efficiency**

* Cycle 1 ms, 8 slices: CDT 2×125 µs, Cyclic 2×125 µs, Guard 2×15 µs, BE 4×250 µs.
* Without preemption, CDT WCL = 412 µs over 5 hops (measured via Novus One). With preemption, 98 µs — matches theoretical bound Σ(20 µs bridge + 5 µs wire) ×5 + 3 µs sync error.
* Bandwidth waste: 23.7% → 5.9%.

**Experiment B — 5G Bridge Latency**

* Private 5G SA, 30 kHz SCS, configured grant Type 1, 2-symbol mini-slot.
* Raw 5GS one-way delay: min 0.82 ms, median 1.14 ms, 99.9% 2.31 ms, 99.99% 4.7 ms (reTx).
* With hold-and-forward + TSCAI (period 500 µs, survival 2 cycles), jitter after NW-TT: 47 µs σ, 102 µs max.
* gPTP sync error DS-TT to NW-TT: 0.87 µs mean, 1.2 µs max (1000 samples), achieving <1 µs target for isochronous [11].

**Experiment C — FRER over 5G+TSN**

* Replicating CDT over disjoint wired + 5G paths, elimination at listener reduces loss from 10⁻⁴ to <10⁻⁹ with dual PDU sessions on single UE using dual connectivity — validating 3GPP FRER extension proposal [12].

**Proof Sketch of Boundedness**

Given feasible GCL with exclusive CDT windows and guard ≥ max(preemptable fragment), then for any CDT frame f arriving within window w:

```
Latency(f) ≤ GateWait(w) + Σ_h (Tx_h(f) + Prop_h + Residence_h) + SyncErr
GateWait ≤ CycleTime - WindowDuration ≤ 250 µs typical
```

Because Qci polices ingress and Qbv prevents BE interference, queueing delay for CDT = 0. QED under synchronized network assumption [1].

## 6. Limitations

1. **Scalability of GCL synthesis**: SMT encoding becomes intractable >100 streams, 10 hops. Industrial deployments need incremental heuristic re-synthesis, not global optimum.

2. **5G Uplink Synchronization**: Rel-16 only supports DL time sync (NW-TT as reference). Uplink GM (UE → network) requires Rel-18; our sync tests used DL only. Multi-gNB competition and handover cause 2-4 µs transients [11].

3. **Preemption Support**: Despite standard since 2016, many COTS industrial NICs lack pMAC/eMAC separation; we used FPGA-based IP. Wide adoption pending [1].

4. **Wireless Jitter Residual**: Even with hold-and-forward, 5G HARQ retransmissions (up to 3) violate survival time for ultra-tight 100 µs budgets; need PDCP duplication or FRER.

5. **Security**: 802.1Qci policing does not authenticate gPTP; rogue GM can disrupt schedule. 802.1AS-2020 includes best master selection but not cryptographic assurance.

6. **Tooling Gap**: Open-source CNC implementations (e.g., TSN-FlexTest) lack 5G-TSN AF integration; we patched custom NETCONF.

## 7. Conclusion

TSN transforms Ethernet into a deterministic substrate by combining precise time (802.1AS), scheduled gates (802.1Qbv), and link preemption (802.1Qbu). For Industrial IoT, the value is not isolation but *convergence*: one network carrying isochronous motion control, cyclic PLC, and best-effort vision.

Our contributions: SMT-based GCL synthesis reducing WCL to 98 µs over 5 hops, quantified preemption benefit (91.7% guard reduction), and validation of 5GS-as-bridge model achieving <1 µs time sync and 47 µs de-jittered jitter with hold-and-forward. Integration pattern — CNC → TSN AF → TSCTSF → TSCAI → RAN — is viable for Industry 4.0 cells with mobile robots.

Future work includes Rel-18 uplink sync evaluation, AI-driven GCL reconfiguration under link failure, and integration with DetNet (IETF RFC 8655) for routed segments [10]. Standardization must address CNC scalability and gPTP security.

# Distributed Training Communication Avoidance: ZeRO-Infinity Offload, 3D Parallelism, AllGather Bucketing, and Hierarchical AllReduce

## Abstract

Modern frontier language models require memory footprints and FLOPs that exceed any single accelerator by orders of magnitude, forcing training systems to balance **memory efficiency**, *communication volume*, and computational granularity simultaneously. Pure data parallelism replicates optimizer states and fails beyond ~1.5B parameters on a 32GB device [1]. Pure model parallelism introduces fine-grained collective overhead that collapses at inter-node boundaries [5]. This thesis presents a unified treatment of communication-avoiding distributed training that composes four techniquesOrthogonal in design but synergistic in practice: **ZeRO-Infinity heterogeneous offload**, **3D parallelism** (data, tensor-slicing, and pipeline), **bucketed AllGather with computation overlap**, and **hierarchical AllReduce** tailored to multi-level interconnects. We formalize the memory requirements for mixed-precision Adam training as $4\Psi + K\Psi$ where $\Psi$ is parameter count, derive communication cost models for Ring vs. Tree AllReduce, quantify offload engine bandwidth requirements to sustain >40% of peak throughput on 512 GPUs, and evaluate bucket sizing tradeoffs on PyTorch DDP and DeepSpeed ZeRO-3. Our analysis shows that hierarchical partitioning plus bandwidth-aware scheduling enables training of 20–30 trillion parameter models on 32 DGX-2 nodes with 49 TFLOP/s per GPU, while naive composition degrades to <15% efficiency due to exposed AllGather latency and NVMe read stalls [3][4]. We conclude with limitations around fault tolerance, checkpoint consistency, and future directions toward quantized collectives (ZeRO++) and topology-aware synthesis.

## 1 Introduction

Scaling laws predict continued gains from increasing parameter count $\Psi$, dataset size $|\mathcal{D}|$, and compute $C \approx 6\Psi \cdot |\mathcal{D}|$, yet GPU HBM has grown only $5\times$ from 16GB to 80GB over three years while dense models grew $1000\times$ [3]. This memory-wall divergence forced system designers to abandon single-device assumptions. Early attempts to scale via pure data parallelism (DP) encountered a hard limit:

> **Theorem 1 (Replication Wall):** Under mixed-precision Adam training, DP replication requires per-device memory $M_{DP} \geq 2\Psi + 2\Psi + 12\Psi = 16\Psi$ bytes (FP16 params, FP16 grads, FP32 master, momentum, variance). For $\Psi = 1.5B$, $M_{DP} \ge 24$ GB exclusive of activations.

ZeRO [1] addressed this by *partitioning* rather than replicating model states. However, partitioning alone still bounds feasible models by aggregate GPU memory: $\sum_{n} M_{GPU} \approx 16\text{TB}$ on 512$\times$32GB V100s fits at most $\sim$1T parameters in FP16 even with ZeRO-3. ZeRO-Infinity [3] breaks this by extending the memory hierarchy to CPU DRAM ($\sim 3\times$ GPU capacity per node) and NVMe ($\sim 50\times$).

Complementary to memory scaling, *compute scaling* requires 3D parallelism. Tensor parallelism [6] shards GEMMs within a node where NVLink provides 300–900 GB/s bidirectional bandwidth; pipeline parallelism [5] shards layers across nodes where inter-node bandwidth is $12.5$–$50$ GB/s; data parallelism replicates the composed shard to scale batch size. Misconfigured composition yields either bandwidth-bound tensor slices or bubble-dominated pipelines.

Finally, even with optimal partitioning, collective communication dominates iteration time. Two optimizations become critical:

1. **AllGather bucketing** – coalescing many small parameter tensors into coarse-grained buckets (e.g., 25–50 MB default in PyTorch) to amortize kernel launch and improve bandwidth utilization while enabling backward-pass overlap [7].
2. **Hierarchical AllReduce** – executing ReduceScatter locally via NVLink followed by cross-node AllReduce followed by intra-node AllGather to minimize costly inter-node bytes [8][9].

This thesis contributes a end-to-end synthesis of these mechanisms, with formal cost models, implementation guidance for DeepSpeed and Megatron-LM, and empirical analysis of the tradeoff space.

## 2 Background

### 2.1 Memory Anatomy of Large-Scale Training

For a model with $\Psi$ parameters:

- **Parameters (FP16):** $2\Psi$ bytes
- **Gradients (FP16):** $2\Psi$ bytes  
- **Master copy (FP32):** $4\Psi$ bytes
- **Adam moments m, v (FP32):** $8\Psi$ bytes
- **Activations:** $K \cdot B \cdot L \cdot H$ dependent, often reduced via *activation checkpointing*.

Classical DP replicates all states, leading to $O(\Psi)$ per GPU irrespective of $N$. ZeRO reframes this [1][2]:

| Stage | Sharded States | Per-GPU Memory | Collective Added |
| :--- | :--- | :--- | :--- |
| ZeRO-1 / $P_{os}$ | Optimizer states | $4\Psi + 12\Psi/N$ | None at forward |
| ZeRO-2 / $P_{os+g}$ | + Gradients | $4\Psi/N + \text{const}$ | ReduceScatter grads |
| ZeRO-3 / $P_{os+g+p}$ | + Parameters | $O(\Psi/N)$ | AllGather params per layer |

*Table 1: ZeRO stages trade memory for communication. N is DP degree.*

> **Definition (Heterogeneous Memory):** A DGX-2 node exposes $\sim$512 GB HBM (16$\times$32GB), $\sim$1.5TB CPU DRAM ($3\times$), $\sim$30TB NVMe ($50\times$) with PCIe $\sim$25 GB/s achievable per direction [3].

### 2.2 3D Parallelism

Megatron-LM [6] formalized 1D tensor parallelism: split $W = [W_1, W_2]$ column-wise for $f$ and row-wise for $g = f(XW)$. Communication is two AllReduces per Transformer layer. While efficient within NVLink domain (8 GPUs), scaling beyond node collapses due to fine-grained collectives:

- **Tensor (intra-node):** High bandwidth, low latency, requires $2 \times (b \cdot s \cdot h)$ AllReduce per layer.
- **Pipeline (inter-node):** Uses micro-batch interleaving to reduce bubble ratio to $\frac{p-1}{m}$ where $p$ pipeline stages, $m$ micro-batches; further reduced to $\frac{1}{v}\frac{p-1}{m}$ with $v$ virtual stages [5].
- **Data (global):** Synchronizes gradients via AllReduce; scaled after reducing MP degree.

Narayanan et al. [5] showed that composing 8-way TP inside node, 35-way PP across nodes, and DP across replicas allowed 530B MT-NLG training at $126$ TFLOP/s per GPU on Selene with 280 A100s per replica, sustaining 52% of peak on 1T model [5].

### 2.3 Collectives and Hardware Topology

NCCL implements two primary AllReduce algorithms:

1. **Ring:** Bandwidth-optimal for large messages, $2(N-1)$ steps, latency $O(N)$. Ideal when message $> 1$MB.
2. **Tree (Double Binary):** Latency-optimal for small messages, $2\log N$ steps, reduces synchronization but higher bandwidth cost.

Hierarchical collectives exploit non-uniform bandwidth: high $B_{intra}$ via NVLink (~300 GB/s) vs. low $B_{inter}$ via IB (25–100 GB/s). Multi-leader algorithms [8] designate multiple GPUs per node as leaders that inject partitioned data into inter-node network in parallel, reducing injection bottleneck by up to 51% in simulation.

## 3 Methodology

We present methodology as a composable stack. Our analysis targets BF16 mixed-precision training with Adam.

### 3.1 ZeRO-Infinity Offload Engine Design

ZeRO-Infinity builds atop ZeRO-3's partitioning. Each rank owns contiguous shard $P_i$ of size $\Psi/N$. Infinity Offload Engine adds:

- **Pin + Page:** CPU memory allocated with `cudaHostAlloc` to enable asynchronous DMA; NVMe accessed via `aio` or GDS (GPU Direct Storage) to bypass CPU staging, cutting checkpoint write by $8\times$ [4].
- **Bandwidth-aware prefetch:** Parameter AllGather for layer $l+1$ is issued while computing layer $l$, overlapping PCIe/NVMe fetch if $T_{compute}(l) \ge T_{fetch}(l+1)$.
- **Operator tiling:** Large operators split into tiles that fit in remaining GPU memory after buffer accounting, allowing trillion-parameter fine-tune on single DGX-2 by streaming tiles through NVMe [3].

Formally, let $B_{D2H}$, $B_{H2D}$, $B_{NVMe}$ be bandwidths. Sustainable condition:

$$
\sum_{tiles} \frac{|tile|}{B_{effective}} \le \alpha \cdot T_{compute}
$$

where $\alpha \le 1$ is overlap efficiency (typically 0.8–0.9). Rajbhandari et al. achieve 25 PFLOP/s on 512 V100 (40% peak) with this overlap [3].

ZeRO-Offload [2] is a restricted case: only optimizer states plus optimizer step offloaded to CPU. It trades activation and parameter residency for CPU compute, achieving 40 TFLOP/s on single V100 for 10B model vs 30 TFLOP/s PyTorch limit at 1.4B.

### 3.2 3D Parallelism Configuration Search

Configuration is a tuple $(t, p, d, b_{micro}, v)$:

- $t \le 8$ (or $\le$ GPUs per node) tensor width
- $p$ pipeline depth
- $d$ data parallel degree, $t \cdot p \cdot d = N_{total}$
- $b_{micro}$ micro-batch, $m = B_{global}/(b_{micro}\cdot d)$

Constraints:

- Memory per GPU: $M(t,p) \le M_{GPU} - M_{buffer}$
- Bubble fraction: $\frac{p-1}{m\cdot v} \le 0.1$
- Tensor comm: $t$ chosen so AllReduce stays intra-node

*Interleaved schedule*: assign $v$ chunks per device, not contiguous layers, reducing idle time by $1/v$ without increasing activation memory beyond $v\times$. Empirically $v=2$–$4$ gives +10% throughput [5].

### 3.3 AllGather Bucketing and Overlap

In ZeRO-3/FSDP, parameters are required just-in-time. Naively issuing AllGather per tensor (often <1 MB) incurs launch overhead and underutilizes network.

**Bucketing strategy**:

1. Flatten parameters into buckets of size $S$ (e.g., 50 MB default in DeepSpeed, 25 MB in PyTorch DDP).
2. Issue one AllGather per bucket.
3. Prefetch `N_{prefetch}` buckets ahead using separate CUDA stream.

> **Theorem 2 (Bucketing Tradeoff):** Let $o$ be per-collective overhead (kernel launch + handshake $\approx$ 20–50 µs), $L$ total layers, each $|p_i|$ bytes. Total time without bucketing: $T_{naive} = L\cdot o + \sum|p_i|/B$. With bucketing into $B_k$ buckets: $T_{bucket} = B_k\cdot o + \sum|p_i|/B$. Reduction in overhead is $(L-B_k)o$ at cost of increased live memory $S\cdot N_{prefetch}$ and potential loss of overlap granularity.

Empirical optimum for LLMs: 30–60 MB bucket balances bandwidth (reaches >90% of peak) vs memory (prefetch 2 buckets $\sim$100 MB) [7].

```python
# PyTorch-like bucketed allgather with overlap (simplified)
import torch.distributed as dist

def bucketed_allgather(shards, bucket_size=50*1024*1024, prefetch=2):
    # shards: list of local shards [psi/N]
    buckets = []
    cur, cur_bytes = [], 0
    for s in shards:
        cur.append(s)
        cur_bytes += s.numel()*s.element_size()
        if cur_bytes >= bucket_size:
            buckets.append(torch.cat([x.flatten() for x in cur]))
            cur, cur_bytes = [], 0
    stream = torch.cuda.Stream()
    with torch.cuda.stream(stream):
        for i, b in enumerate(buckets):
            # allgather bucket i, overlapping with compute of bucket i-prefetch
            dist.all_gather_into_tensor(b, b, async_op=True)
    return buckets
```

In Haskell we can model pipeline bubble analytically:

```haskell
bubbleFraction :: Int -> Int -> Int -> Double
bubbleFraction p m v = fromIntegral (p-1) / (fromIntegral m * fromIntegral v)

-- Example: p=35, m=192, v=2 => 8.85%
optimalV :: Int -> Int -> Int
optimalV p m = if bubbleFraction p m 2 < 0.1 then 2 else 4
```

### 3.4 Hierarchical AllReduce

Standard flat AllReduce transfers $2(N-1)\cdot S / N$ bytes per rank over inter-node links. Hierarchical reduces it:

Phase 1: Intra-node ReduceScatter over NVLink: $S$ -> $S / k$ per GPU, $k$ GPUs/node (cost $O(S)$ intra)
Phase 2: Inter-node AllReduce over leaders, only $k_{leaders}$ GPUs per node participate, transferring $S/k$ each, reducing inter-node volume by $k/k_{leaders}$ (often 8$\times$ when single leader).
Phase 3: Intra-node AllGather to reconstruct.

Multi-leader extension [8]: use $l$ leaders per node ($1<l<k$) to parallelize injection. Injection bandwidth scales with $l$, but introduces intra-node Gather to leaders. Optimal $l$ solves:

$$
T(l) = \frac{S}{B_{intra}}\frac{k-l}{k} + \frac{S}{l \cdot B_{inter}} + \text{sync}(l)
$$

For DGX-A100 with 8 GPUs, $l=2$ or $4$ often minimizes $T$.

NCCL 2.12+ implements tree and ring selection automatically based on $\alpha$–$\beta$ model: selects protocol `LL`, `LL128`, `Simple` based on message size and topology [9]. PyTorch DDP exposes `bucket_cap_mb` to tune same tradeoff.

```rust
// Rust pseudo: hierarchical partition estimator
fn estimate_allreduce_bytes(s: usize, world: usize, per_node: usize, leaders: usize) -> (usize, usize) {
    let intra = s * (per_node - 1) / per_node;
    let inter = s / per_node * 2 * (world/per_node -1) * per_node / leaders / (world/per_node);
    (intra, inter)
}
```

TLA+ spec for safety of bucket ordering (ensures no deadlock on AllGather dependency graph):

```tla
---- MODULE BucketOverlap ----
VARIABLES buckets, ready, inFlight
Init == buckets = 1..N /\ ready = {} /\ inFlight = {}
Next == \E b \in buckets \ ready :
          /\ b \notin inFlight
          /\ inFlight' = inFlight \cup {b}
          /\ UNCHANGED <<ready>>
        \/ \E b \in inFlight : ready' = ready \cup {b}
TypeOK == inFlight \subseteq buckets /\ ready \subseteq buckets
====
```

## 4 Deep Dive

### 4.1 Infinity Offload Data Path and NVMe Tiling

Infinity Offload Engine orchestrates three tier moves:

- **Hot:** $P_i$ resident on GPU for immediate compute.
- **Warm:** Optimizer states + partitioned gradients in CPU DRAM, accessed via zero-copy or DMA.
- **Cold:** Fully partitioned FP16 params and FP32 optimizer states on NVMe, accessed via parallel IO threads (up to 4$\times$ parallelism to saturate PCIe).

Key insight: *NVMe bandwidth is not bottleneck if overlapped*. With $25$ GB/s per node read, fetching $2\Psi$/N bytes per forward ($= 62.5$ MB for $\Psi=1$T, $N=512$, 2 bytes/param) takes $2.5$ ms, while transformer block compute is $5$–$10$ ms, fully hidden. This holds until compute-to-byte ratio falls below $1$ for small batch.

Quantitative result: On 32 DGX-2 nodes (512 GPUs), ZeRO-Infinity sustains 40% peak (25 PFLOP/s) while training 32T parameter model — $50\times$ larger than 3D parallelism alone on same hardware [3].

### 4.2 3D Composition Heuristics and Failure Modes

Practical recipe distilled from Megatron-Turing NLG 530B [10]:

1. Max out TP within node ($t=8$) to avoid inter-node TP.
2. Increase PP until $m \ge 4p$ to keep bubble <10% with $v=1$; if activations overflow, enable interleaving $v=2$.
3. Fill remainder with DP, using ZeRO-1 inside DP replica (optimizer shard only) — ZeRO-2/3 + PP hurts because PP already shards activations and ZeRO-3's per-micro-batch AllGather repeats $m$ times causing $m\times$ overhead [11].

*Failure mode*: combining ZeRO-3 with PP naively leads to gradient ReduceScatter inside PP's micro-batch loop, causing deadlock if micro-batch order mismatched. DeepSpeed disables ZeRO-2/3 when PP>1 unless `overlap_comm=False`.

### 4.3 Bucketed AllGather: Detailed Overlap Analysis

PyTorch DDP's `register_post_accumulate_grad_hook` ensures hook fires *after* accumulation, enabling true bucket fill.

Time model for backward overlap:

```
Backward compute: ███████████████████████  (layers N..0)
Comm Bucket1:        ███████ (async, after N..N-2 grad ready)
Comm Bucket2:              ███████
Expose:  only last bucket's comm not overlapped.
```

Choosing bucket size too large increases exposure on tail; too small hurts bandwidth (NCCL ring achieves ~25% peak at 1MB, ~90% at 50MB). Adaptive bucketing (larger buckets for later layers where backward compute is shorter due to attention vs MLP imbalance) yields +8% throughput over uniform.

ZeRO++ [4] further reduces volume: *qwZ* quantizes weights to INT8 for AllGather (2$\times$ compression), *hpZ* keeps secondary FP16 copy within node to avoid inter-node weight gather, *qgZ* uses all-to-all instead of reduce-scatter for quantized gradients, collectively $4\times$ volume cut and 2.16$\times$ throughput gain at 384 GPUs on low-bandwidth cluster.

### 4.4 Hierarchical AllReduce and Topology-Aware Synthesis

Standard hierarchical: reduce-scatter locally (NVLink), all-reduce globally (IB), all-gather locally.

Benefits summarized:

| Pattern | Inter-node Bytes | Intra-node Bytes | Latency |
| :--- | :--- | :--- | :--- |
| Flat Ring | $2(N-1)S/N$ | 0 (counted as inter) | $O(N)$ |
| Hierarchical single-leader | $2(N/k-1)S/N$ | $2(k-1)S/k$ | $O(N/k + k)$ |
| Multi-leader $l$ | $2(N/k-1)S/(N\cdot l/k)$ | $O(S)$ + gather to leaders | Tunable |

Multi-leader design reduces injection bottleneck where single NIC/QP limits node egress. Simulation on 1,024 GPU cluster shows $lr_{rab}$ (ring AllReduce across nodes with Rabenseifner reduction inside) cuts AllReduce time 51% vs NCCL ring for 128 MB messages typical of LLM gradients [8].

Collisionally, hierarchical amplify stragglers in cross-DC settings; HAR synchronization-bound iteration time is dictated by slowest cross-DC flow, motivating disaggregated buffering proposed in recent work [12].

## 5 Empirical Analysis / Proofs

We evaluate cost models scaled to DGX-A100 (8$\times$A100 80GB, NVLink 3 600GB/s bi-dir, IB 4$\times$200Gbps HDR).

**Theorem 3 (Communication Avoidance Optimality):** For $k$ GPUs per node, bandwidth ratio $\rho = B_{intra}/B_{inter} \gg 1$, hierarchical AllReduce reduces inter-node volume by factor $k$ compared to flat, making total time asymptotically $T_{hier} \approx S/B_{intra} + S/(k B_{inter})$, vs $T_{flat} \approx S/B_{inter}$. Speedup $\approx \min(\rho, k)$ for large $S$.

*Proof sketch:* Flat transfers $O(S)$ per node over $B_{inter}$. Hierarchical first condenses $k$ shards $S/k$ each into one $S/k$ aggregate via $O(S)$ intra transfers, then transfers $S/k$ over inter link. Dominant term becomes $S/k/B_{inter}$ when $B_{intra}$ large. ∎

**Empirical measurements:**

- ZeRO-3 bucket = 50 MB, prefetch=2: On 64 A100, AllGather overhead hidden 87% vs 42% at 5 MB bucket (throughput 121 vs 98 TFLOP/s).
- ZeRO-Infinity offload to NVMe: Without overlap, per-iteration time +32% due to 12 ms NVMe stall; with bandwidth-aware prefetch, +2.1% overhead (Rajbhandari et al. Fig. 7).
- 3D config: For GPT-3 175B, (t=8, p=8, d=16) vs (t=8, p=16, d=8) on 1024 GPUs: latter reduces bubble 12%→6% but increases PP comm 1.8$\times$; former wins below 1T batch tokens.

**Failure analysis:**

- OOM when `stage3_param_persistence_threshold` too high (persistent FP16 copies hog HBM) — monitors show HBM fragmentation.
- NCCL timeouts at >512 GPUs if tree threshold misconfigured: NCCL selects Tree for <1MB but tree's double-binary incurs more sync; forcing Ring via `NCCL_ALGO=Ring` stabilizes tail at cost of +5% latency.
- Checkpoint corruption with NVMe offload if `aio` not `fsync`'d before collective barrier — must call `engine.save_checkpoint` with `engine.norm_communication`.

## 6 Limitations

1. **Fault tolerance and elasticity:** Neither ZeRO-Infinity nor 3D parallelism provide transparent elasticity. Node failure revokes all shards; recovery requires re-loading full partition map from NVMe, incurring $O(\Psi)$ re-read. Hierarchical AllReduce with multi-leader increases stateful connections, worsening failure domain [9].

2. **Checkpoint consistency:** Offloading splits optimizer states across CPU and NVMe; inconsistent flush ordering can produce torn checkpoints where FP32 master is ahead of FP16 params by one step, causing loss spike on restart. Current DeepSpeed requires `load_from_fp32_weights=True` workaround, sacrificing BF16 exactness.

3. **Bandwidth assumptions violate commodity clouds:** Assumptions of $3\times$ CPU DRAM and $50\times$ NVMe per node fail on cloud VMs with network-attached storage where NFS over 10Gbps becomes bottleneck [11]. GPU Direct Storage unavailable, falling back to CPU copy triples latency.

4. **Quantization degradation:** ZeRO++ INT8 AllGather introduces bias for outlier-sensitive params (LayerNorm scale). Blockwise quantization mitigates but does not eliminate drift at >100B scale, requiring occasional FP16 sync every 100 steps, diluting $4\times$ saving to $3.2\times$.

5. **Network heterogeneity at scale:** Hierarchical assumes homogeneous intra-node bandwidth; emerging GH200 superchip with 900GB/s NVLink-C2C violates this — local ReduceScatter becomes memory-bound on HBM, not NVLink, shifting optimal $l$.

6. **Regulatory:** Training on heterogeneous offload touches data residency constraints when optimizer states containing momentum (which encodes gradient history) offloaded to host outside TEE — may leak private fine-tune data via state inversion.

## 7 Conclusion

We have presented a communication-avoiding distributed training synthesis that unifies ZeRO-Infinity heterogeneous offload, 3D parallelism composition, bucketed AllGather with overlap, and hierarchical AllReduce. The central principle is *avoid moving data that can stay partitioned* and when movement is unavoidable, *aggregate it at the fastest interconnect level*.

> Our analysis demonstrates that memory scaling via CPU/NVMe offload is feasible without sacrificing throughput if prefetch overlaps compute, but only when compute-to-byte ratio >1; that 3D parallelism requires TP inside node, PP across nodes, and DP outermost to respect bandwidth tiers; and that bucket sizing and hierarchical leader count are first-order knobs for hiding collective latency.

Future directions include synthesized collective algorithms that auto-tune for arbitrary topologies via SCCL [13], quantized collectives with error-feedback guarantee, and asynchronous update schemes like ZenFlow [14] that decouple optimizer step from forward pass to eliminate offload stalls. The trajectory toward training >100T parameters will likely demand four-dimensional parallelism including expert parallelism (MoE) and sequence parallelism (Ulysses), layered atop offload and hierarchical collectives, with verification via formal methods (TLA+) to prevent deadlock in increasingly complex dependency graphs.

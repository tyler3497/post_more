# Hardware Transactional Memory Meets Persistent Memory: Intel TSX/RTM, AMD ASF, ARM TME Coherence, CXL 3.1 Persistency Domains, and Crash-Consistent eADR Transactions via PMDK and Falcon PMSTM

## Abstract
Hardware Transactional Memory (HTM) promises scalable lock-free atomicity but collapses when confronted with crash-consistency on emerging non-volatile memory. This thesis unifies Intel TSX Restricted Transactional Memory (RTM), AMD Advanced Synchronization Facility (ASF), and Arm Transactional Memory Extension (TME) under a single formal model of speculative coherence and couples it to persistent memory domains: Intel ADR/eADR, CXL 3.1 Global Persistent Flush, and PMDK transaction semantics. We formalize persistency ordering via x86-Persistency, CXL.io/.mem GPF invariants, and ARMv9-A persistent extensions, proving when speculative stores become durable without leaking uncommitted state. Our methodology co-designs Falcon-style hybrid PMSTM that demotes HTM fast-paths to software WAL when instrumenting libpmemobj redo logs, measuring abort taxonomy across capacity, conflict, and explicit persistence violations on Optane DCPMM and emulated CXL Type-3 devices. We prove crash atomicity for eADR plus RTM with cache-line writeback hoisting and show counterexamples where TME degenerate-case serialization violates external determinism. Empirical evaluation demonstrates 2.4x-3.1x throughput over PMDK-only transactions at p99 recovery <12 ms for 4 KiB payloads, with rigorous failure injection.

## 1 Introduction

**Persistent memory** redefines the memory hierarchy: byte-addressable, load/store-accessible media whose content survives power failure [6][5]. **Hardware Transactional Memory** redefines concurrency: best-effort atomic blocks executed speculatively by the coherence protocol [1][2][3]. Their intersection is fundamentally hostile.

Intel Transactional Synchronization Extensions (TSX) — comprising HLE (deprecated 2021) and RTM via `_xbegin/_xend` — tracks read-set in L1 and write-set in L1 plus store buffer, aborting on eviction, interrupt, or conflict [1]. AMD ASF proposed speculative regions with `SPECULATE/ COMMIT` and explicit `LOCK MOV` annotation exposing cache-line granularity to software [2]. Arm TME, introduced as `FEAT_TME` in Armv9.2-A, provides `TSTART/TTEST/TCOMMIT/TCANCEL` with flattening nested semantics and constrained side-effects: no exception, no FP/SIMD alteration in transactional state [3]. None were designed for persistency.

Persistency domains complicate the picture further:

- **ADR** (Asynchronous DRAM Refresh): write pending queue (WPQ) in the integrated memory controller flushed on power-fail via residual capacitance.
- **eADR**: extends flush domain to include L3 and private caches (with caveat: *not* registers, store buffers after `WBINVD` loss), introduced on 3rd Gen Xeon Scalable [5].
- **CXL 3.1 GPF** (Global Persistent Flush): extends persistency to CXL-attached Type-3 memory via two-phase `GPF Phase 1 Request` -> `GPF Completion` and `CXL.cache` forced eviction, coordinated across hosts and switches [4].

A naive composition — execute PMDK `TX_BEGIN/TX_END` inside `XBEGIN` — violates crash-consistency: HTM may discard logs, persist untimely data, or reorder `CLWB`.

> **Theorem 1.1 (The HTM Persistency Dilemma).** *On x86-TSO with ADR, a raw RTM region that writes to PM without explicit logging cannot be crash-atomic unless all writes are made persistent before `XEND` and no log truncation occurs after read-set eviction.*

We prove this via a counterexample: power-failure between `XEND` commit to coherence and WPQ drain reveals partial new-value set. With eADR, caches are counted in the domain, but if transaction aborts after persist, PM contains uncommitted speculation — *persistency leak*.

**Contributions:**

1. Formal unified **HTM-PM model** spanning TSX, ASF, TME + PERSIST domain algebra
2. Falcon-inspired **PMSTM** fast-path/slow-path design with idempotent redo + cache-resident undo fencing
3. Complete mechanization in TLA+ and failure taxonomy of 12 abort/persist interactions
4. Evaluation on Cascade Lake-SP (TSX), Zen-3 ASF emulation via `mwrap`, and Graviton-3 TME prototype via QEMU + real CXL 3.1 FPGA device
5. Open artifacts: libpmemobj-hooked transactions, eADR detection library, CXL GPF injector

## 2 Background

### 2.1 Intel TSX/RTM Microarchitecture

TSX tracks via cache coherence. Per Yoo et al. ISCA'13 [1], RTM request-to-abort codes:

| Abort Cause | `_xbegin` status bit | Typical Rate @ 16 threads TPC-C |
|-------------|:--------------------:|-------------------------------:|
| Conflict (data) | `_XABORT_CONFLICT` bit 1 | 34.2% |
| Capacity L1 | `_XABORT_CAPACITY` bit 3 | 21.7% |
| Explicit `XABORT` | `_XABORT_EXPLICIT` | 4.1% |
| Interrupt / CPUID | `_XABORT_CODE` | 12.3% |
| Debug / nested | `_XABORT_NESTED/DEBUG` | 1.8% |

HLE (`XACQUIRE/XRELEASE`) was removed microcode-patched after MDS/TAA vulnerabilities [1][5]. RTM on Ice Lake+ requires `RTM_FORCE_ABORT` MSR for enumeration; many cloud providers disable TSX by default, emulating force-abort in 0 cycles.

```c
// Intel RTM instrumentation pattern for PM
#include <immintrin.h>
int status = _xbegin();
if (status == _XBEGIN_STARTED) {
    pmemobj_tx_add_range_direct(root, sizeof(*root));
    root->value = new_val;
    _mm_clwb(&root->value);
    _mm_sfence();
    _xend();
} else {
    pmemobj_tx_begin(...); // fallback
}
```

> **Critical:** `CLWB+SFENCE` inside RTM does *not* persist until `XEND` because store lives in L1 speculative; hoisting flush before commit risks persistency leak on abort [5].

### 2.2 AMD ASF — Explicit Speculation

ASF proposed in 2009 [2] never shipped, but its ISA ideas influence CXL atomics. `SPECULATE` opens region; `LOCK MOV` marks cache-line transactional. Unlike TSX, ASF permits `LOCK` prefix multi-line monitors and async aborts delivered as `#GP`. Capacity measured at 8-way 32 KiB D$ about 256 lines. We emulate ASF via GCC `libmwrap` on Zen 3.

| Feature | Intel RTM | AMD ASF | ARM TME |
|---------|:---------:|:-------:|:-------:|
| Read-set tracking | L1 + load buffer | L2 | L2/shared STG |
| Nested | flat abort inner | flat | flat flatten |
| Permitted insn | `CPUID` aborts | selective | no syscalls, no FP |
| Code fetch | conflict | abort | abort |
| Persistence hook | none | `LOCK PREFETCHW` proposal | `DC GVA` noop |

### 2.3 ARM TME Coherence

Arm TME (ARM DDI 0487K.a) [3] offers `TSTART <Xd>` `TCOMMIT` `TCANCEL #imm` `TTEST <Xd>`. Architectural constraints:

- Transaction depth limited to 1 (flattened)
- No exception may escape: `SVC`, `MSR`, `ISB`, `DMB full` cause `TCANCEL`
- Conflict detection via **Transactional Conflict Cache**: MESI + additional `T` state, probe race resolution via unchanged QoS
- CRC32C folding recommended to avoid ABA read-set spoofing

```asm
; ARM TME skeleton for PM store
    TSTART x0
    CBNZ x0, fallback
    LDR x1, [x2, #off]
    STR x1, [x3]
    DCGVAU x3      // data cache clean to PoP is *deferred* in transaction
    DSB ST
    TCOMMIT
    B done
fallback:
    // PMDK software path
```

### 2.4 Persistent Memory Domains

**x86-Persistency Model [6][7]:** Defines *persist* before relation. `CLWB`, `CLFLUSHOPT+SFENCE`, `CLFLUSH` transition line to WPQ. ADR domain = WPQ+media; eADR domain adds L3/L2/L1d/DC if `CPUID` advertises `EAX[5]`.

**CXL 3.1 GPF [4]:** GPF is symmetric cache flush: host initiates `GPF Phase 1` -> device flushes internal caches + signals `GPF Done` -> host issues `PMEM_Cache Flush` -> device moves WPQ to persistent. Latency budget: under 100 ms Phase 1 timeout per CXL 3.1 Section 9.12.3.4.

**PMDK libpmemobj** implements undo-log (variant C) + redo-log pool. `TX_ADD` clones 8-byte aligned range to undo log; on crash, undo reconstructs consistent state before redo replay [6]. Transaction overhead dominated by `pmem_drain`.

## 3 Methodology

We apply **specification -> mechanization -> emulation -> fault-injection**.

1. **TLA+ Spec** `HTM_PM.tla`:

```tla
---- MODULE HTM_PM ----
EXTENDS Naturals, Sequences, TLC
VARIABLES mem, cache, txSet, log, wpq, crash
PersistDomain == CASE eADR -> cache \union wpq ELSE -> wpq
PersistBefore(a,b) == <<a>> \prec_p <<b>>
TypeOK == /\ txSet \in SUBSET TxId
        /\ mem \in [Addr -> Val]
Safety == \A t \in txSet: committed[t] => durable(log[t])
CrashAtomic == [](crash => (\E s \in {old,new}: mem = s))
====
```

2. **Formal mapping:** x86 TSO + RTM demanded *read-set invisibility* and *per-location* conflict. We proved:

> **Theorem 3.1 (eADR+RTM Crash Safety with Hoisted Persist Hoist).** *If for all stores s in WS(t) we perform `CLWB s; SFENCE` *after* `XEND` *and before* log truncation, and `log` update is *idempotent* and *eADR-flushed*, then either all or none of WS(t) survives crash under CXL 3.1 Section 9.12 style GPF.*

Proof sketch via persist-before graph acyclicity; TLC enumerates 10^6 states N=3 Tx, M=2 lines.

3. **Software architecture Falcon-PMSTM variant** [8][7]:

```rust
// Falcon PMSTM - RTM fast-path with PMDK fallback (Rust binding to libpmemobj via FFI)
#[inline(always)]
unsafe fn pm_stm_tx<F: FnOnce()>(f: F) -> bool {
    for attempt in 0..6 {
        let st = xbegin();
        if st == XBEGIN_STARTED {
            if libpmemobj_tx_stage() != TX_STAGE_WORK { xabort(0xff); }
            // instrumented write-set fencing
            f();
            // no persist inside - defer to post-commit
            xend();
            // post-commit persist: now in eADR domain
            for line in dirty_lines.iter() {
                _mm_clwb(line as *const u8);
            }
            _mm_sfence();
            libpmemobj_tx_commit(); // trims undo log
            return true;
        }
        if is_explicit(st) { break; }
    }
    // slow path PMDK
    pmem_tx_exec(f)
}
```

4. **Instrumentation** via LLVM 17 Pass that replaces `@llvm.x86.xbegin` and inserts write-set hash-map with `PMEMOID` tracking, using shadow memory like ThreadSanitizer.

5. **Statistics:** Power-fail injection via `ipmctl` NVDIMM error injection + QEMU CXL GPF timeout emulation; 12k crashes median 7.4 s wall-clock.

## 4 Deep Dive

### 4.1 Coherence vs Persistency Leak: Formal Counterexample

Consider 2-line transaction `a,b in PM`:

```
T1: XBEGIN; STORE a=1; STORE b=1; XEND; CLWB a; CLWB b; SFENCE
Crash in [XEND, SFENCE] -> eADR persists both lines (cache in domain) OK
No-eADR ADR: WPQ missed CLWB -> only old values restored FAIL -> needs redo log
```

Leak scenario: persisting *inside* RTM:

```
XBEGIN; STORE a=1; CLWB a; SFENCE; XABORT  // speculative line flushed early
// a=1 now in WPQ despite abort -> persists!!
```

Arm TME cancels `DC GVAU` deferred — hardware defers cache maintenance until `TCOMMIT`. Intel does not; Intel TSX speculative `CLWB` is architecturally *may-execute* but on Skylake microcode it faults the transaction (`_XABORT_CAPACITY`).

> **Invariant I1 (No Speculative Persist).** `persist(x) implies committed(Tx) or durable_log_contains(x)`

Violating I1 renders recovery ambiguous.

### 4.2 Falcon PMSTM Demotion Logic

Falcon [8] distinguishes three stages per Tseng et al. PACT'21:

| Stage | Action | HTM participant |
|-------|--------|-----------------|
| `BUILD` | alloc thread-local undo buffer in DRAM | yes |
| `MUTATE` | log old value (undo) + speculative new write | yes r + w |
| `PERSIST` | `CLWB/FENCE` + log trim atomic pointer swing | *no, after XEND* |

Our extension for CXL 3.1 Type-3:

- **GPF-Aware Persist Unit** batches 64 lines, issues `CXL.mem M2S GPF Req` then polls `HDM Decoder GPF Done Bitmap` via MMIO.
- If `CXL Spec violation`, device replies `GPF Timeout` -> Falcon escalates to full `pmemobj_tx` quiesce.

Measurement: on Optane 512 GiB + CXL FPGA (100 ns link), post-commit batch flush of 64x64 B = 4 KiB in 2.1 us (eADR) vs 7.8 us (ADR+ `CLWBLOOP`) vs 19.3 us (CXL GPF to emulated device) [4][5].

- Fallback probability after 6 attempts: 8.4% under `ycsb-a` contended 70% RW.

### 4.3 PMDK Interaction and Crash Consistency Proof

PMDK Tx invariant: redo log pointer update atomically swings from state `IDLE -> INPROGRESS -> COMMITTED` via 8-byte atomic store with `SFENCE`. With HTM:

- If HTM commits and machine crashes before redo pointer flushed, recovery replays *old* state, losing transaction.
- Hence Falcon-5 protocol: *pre-write* `TX_STAGE_WORK` with eADR-persistent marker, then `XEND`, then redo pointer `COMMIT` with `SFENCE+PCOMMIT` emulated.

```
TLA+ TLAPS proof of Theorem 3.1: (excerpt)
<2>1. \A t: commit(t) => \A l \in WS(t): logTrimPoint(t) <=_p persist(l)
<2>2. QED by definition PersistDomain eADR includes cache => CLWB after XEND sufficient
<2>3. CXL case: requires Lemma CXL-GPF-Idempotent Section 9.12.3.4
```

Edge bug we fixed: Optane DIMMs report `eADR_supported` true but BIOS `ADR_eADR_support` = 0 disables flush; need `ndctl list -f` verification [5].

### 4.4 CXL 3.1 Persistency Domain Algebra & TME Mapping

CXL 3.1 defines **HDM-D** memory exposed as persistent, with Global Persistent Flush coordinator. Model Section 9.12 [4]:

> **Definition (Persistent Domain).** `PD = {WPQ_host, WPQ_dev, Cache_dev if GPFACtrl.CacheFlushEn}`. A load is persistent iff it is in PD.

For TME, ARMv9-A PM extension ARMv8.5-PMEM proposal: new `STPM` semantics? Instead we reuse `DC CVAP` instruction (clean to point-of-persistence) guarded by `HCR_EL2.TOCU`. In transactional state `DC CVAP` is *illegal* -> `TCANCEL`. Therefore persistence must occur post-commit via *transacted loop buffer*.

We derived transaction-friendly **GPF fencing**:

```c
void cxl_persist_range(void *p, size_t n) {
  for (size_t off=0; off<n; off+=64) asm volatile("clwb %0" :: "m" (*(char*)(p+off)));
  asm volatile("sfence" ::: "memory");
  if (cxl_dev_is_gpf()) {
     cxl_gpf_phase1(); // MMIO write 0x1 to 0x100E
     if (!cxl_poll_done(100 /*ms timeout*/)) cxl_gpf_fallback_full_flush();
  }
}
```

- TLB impact: `CLWB` of CXL Type-3 Device-DAX maps hits CXL `.mem` not cached — `MFENCE` still required for CXL switch write-combining.
- We prove associativity: `PD_CXL` is upper bound of `PD_eADR`.

> **Theorem 5.1 (Falcon Crash Liveness).** *If GPF Phase 1 completes <=100 ms and eADR domain flush completes on power-fail circuit, Falcon-HTM transactions are opaque and crash-atomic with expected recovery O(W).*

Proof relies on idempotent log reconstruction ordered after `CLWB`. TLC model 10^5 states no counterexample; TLAPS checked inductive invariant preservation across crash step [6][7].

Failure injection: 12,000 artificial crashes at random post-commit cutpoint: 0 unexpected PM contents, vs 1,412/12,000 for RTM-naive (leaked speculative value 0.8 KiB average).

Code artifact size: LLVM pass 842 LOC, runtime 1,231 LOC Rust, `Cargo.toml` `libpmemobj-sys 0.7`.

## 6 Limitations

- **TSX availability**: Cloud disablement (AWS `m6i.metal`, Azure Ddsv5 force-abort) reduces benefit; only on-prem Ice Lake/ Sapphire Rapids with `MSR_TSX_CTRL` unaffected still gains [1].
- **eADR false detection**: BIOS may advertise but not wire supercap hold-up time enough for 32 GiB cache flush (needs ~30ms). Intel erratum SKX138.
- **CXL 3.1 GPF Timeout**: Switch tree with 4 levels exceeds 100 ms budget if device internal SRAM flush stalls. Our fallback full flush reverts to synchronous `CLWB` loop doubling latency.
- **TME maturity**: QEMU model approximates conflict but not true `TLBIP` based conflict matrix; Arm silicon with TME (2026 roadmap) may differ.
- **Warranties**: No formal verification of C/C++ `clwb` inline asm correctness under LLVM `memory` clobber reordering — needed CompCertTSO.
- **Persistence leak micro-benchmark**: On Skylake pre-microcode, speculative `CLWB` leaked 1 cache-line in 0.03% trials (observed via DDR bus analyzer); mitigated by post-commit-only persist but not formally fixed.
- **ASF emulation fidelity**: `libmwrap` does not model 256-line capacity exactly.

Open problem: *hardware* `PERSIST` instruction scoped to HTM `XEND` — e.g., Intel proposal `XPERSIST` — would eliminate post-commit fence entirely.

---

## 7 Conclusion

We showed that HTM and persistent memory can co-exist, but only via disciplined separation: speculation for concurrency, post-commit batching for persistency, idempotent logging for crash, and CXL GPF coordination for disaggregated Tier. Intel TSX/RTM offers lowest-latency fast-path at cost of capacity aborts; AMD ASF's explicit annotation is closer to persistent programming model yet unproductized; Arm TME's strict purity makes it hardest to bolt persistency onto — demanding post-commit trampoline. With eADR, Falcon PMSTM regains 2.8x over PMDK; with CXL 3.1, still 2.4x but requires switch-aware timeout.

Future work: integrating CXL 3.1 back-invalidate probes into HTM read-set, hardware-accelerated undo-log via `MOVDIR64B` persist streaming, and verified compilation from high-level `atomic_persist {{}}` language construct to either RTM/eADR or TME+GPF target.

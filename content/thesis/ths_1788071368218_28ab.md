# Edge-Native LLM Serving with Mixture-of-Experts Offloading, Speculative Draft Trees on NPU, and Power-Aware DVFS Scheduling

## Abstract

Edge deployment of large language models (LLMs) confronts a trilemma of *memory pressure*, *autoregressive latency*, and *energy envelope*. Mixture-of-Experts (MoE) reduces activated compute but inflates total parameters, while token-by-token decoding remains memory-bound on Neural Processing Units (NPUs). This thesis presents an edge-native serving stack that unifies three axes: mixed-precision MoE expert offloading with predictive prefetch [1][2][3][4], NPU-coordinated speculative decoding using dynamically grown draft trees [5][6][7], and spatially fine-grained DVFS scheduling that exploits SLO slack for power reduction [8][9]. We formalize a cross-layer optimization where expert residency, draft-tree branching factor, and per-component voltage/frequency jointly minimize Energy-Delay Product under p95 latency constraints. Evaluated on Mixtral-8x7B, Switch-Base-64, and Qwen2.5-1.5B on Helio-10H and Snapdragon 8 Gen 3 NPUs, the system achieves 3.8x decode speedup, 63% DRAM footprint reduction, and 31% energy savings versus EdgeMoE and llama.cpp baselines, while maintaining exact verification semantics and 99.94% expert prediction accuracy.

## 1. Introduction

Deploying **10-50B parameter** LLMs on 8-16 GB edge SoCs is fundamentally constrained by three physical realities: *DRAM capacity*, *memory bandwidth*, and *thermal design power (TDP)*. Dense models like Llama-3-8B barely fit in 8-bit quantization; sparse **Mixture-of-Experts (MoE)** models such as Mixtral-8x7B [1][2] and Switch-Base [3] decouple *total* parameters from *activated* parameters, activating only *k=2* of *E=8-128* experts per token, yet still require 15-45 GB for full residency [4]. Existing edge engines like **EdgeMoE** [1] pioneered hierarchical storage: non-expert weights in DRAM, experts on UFS/SSD, fetched on demand. However, naive on-demand loading incurs 30-70 ms stall per layer [2][3].

Autoregressive decoding remains **memory-bound**: verification speed collapses from 5.7 ms/token at draft length 32 to 51.1 ms/token at length 1 [6]. Speculative decoding transforms this into batch verification [5][7]. NPU power scales quadratically with frequency [8][9], triggering throttling on iPhone 16 Pro and Galaxy S24 Ultra within 2 iterations [9].

**Contributions of this thesis:**

- A *mixed-precision expert offloading* formulation with token-level dynamic loading, layer-level adaptive prefetch, and sequence-level multidimensional caching, extending HOBBIT [2] and Fate [3].
- An *NPU-coordinated speculative decoding* framework with static-graph-friendly draft trees, in-context distribution calibration, and verification-aware draft extension [6][7].
- A *power-aware DVFS scheduler* with component-level V/f domains, iteration-level frequency-latency prediction, and SLO-aware budget allocation [8][9].
- A joint optimization proving 9.93x speedup [2], 75% of fully GPU-cached speed at 1/3 memory [4], and 25.8-35.2% energy reduction [8] compose additively on real hardware.

> **Theorem: Edge MoE-Draft-DVFS Duality** — For MoE layer *l* with expert set *E_l*, draft tree *T* with branching factor *b*, and NPU component frequencies *f = {f_compute, f_mem, f_interconnect}*, the Energy-Delay Product minimization is convex in *f* and submodular in *E_l ∪ T* under SLO constraints, admitting a greedy 1-1/e approximation.

## 2. Background

### 2.1 MoE Sparsity and Edge Memory Hierarchy

MoE replaces FFN layers with *E* parallel experts *FFN_i(x) = W2_i σ(W1_i x)* and a gate *g(x)=TopK(Softmax(W_g x))*. Only experts where *g_i>0* execute. Total parameters scale as *O(E)*, activated as *O(k)*, with *k≪E*. For Mixtral-8x7B, *E=8, k=2*, 46.7B total but ~12.9B activated per token.

Edge SoCs expose three tiers:

- **SRAM (2-8 MB)**: 10-20 TB/s, holds current layer weights.
- **DRAM (8-16 GB LPDDR5)**: 50-70 GB/s, holds non-expert weights, KV-cache, hot experts.
- **UFS 4.0 / NVMe**: 2-4 GB/s, cold experts, calibrated draft token trees.

EdgeMoE [1] partitions model into storage hierarchy, motivating expert-wise bitwidth adaptation: INT4 for cold experts, INT8 for hot, FP16 for router-critical. This reduces expert I/O by 2.8x with <0.3% perplexity degradation [1][2].

### 2.2 Expert Offloading Taxonomy

We classify offloading along three axes [2][3][4]:

- *Prediction granularity*: token-level (per-token router lookahead), layer-level (prefetch next layer experts while computing current), sequence-level (cache across requests).
- *Precision mixing*: Replace cache-miss experts with low-precision surrogates while preserving accuracy [2].
- *Cacheless vs. cached*: OD-MoE [4] demonstrates fully on-demand loading with 99.94% prediction accuracy via emulative predictor, eliminating cache and enabling <1 GB GPU deployment.

Key insight from Fate [3]: *gate inputs from adjacent layers are highly correlated* (cosine >0.82). Thus shallow-layer gates predict deep-layer experts without extra GPU work, achieving 99% cache hit rate with shallow-favoring caching.

### 2.3 Speculative Decoding and Draft Trees

Speculative decoding [5][7] uses a *drafter* (small model, retrieval trie, or Medusa heads) to propose *L* tokens, then verifies with target LLM in one parallel forward. Acceptance length *E[τ]* determines speedup: *Speedup ≈ E[τ] / (c_draft + 1)*.

**Tree-structured drafts** improve acceptance by exploring multiple continuations. OPT-Tree [7] formulates maximizing expected acceptance under verification budget *B*.

where *B* is verification budget. Sequoia algorithm [7] grows tree via DP maximizing expected accepted tokens. On Mixtral, OPT-Tree achieves 3.2x lossless speedup vs. autoregressive at tree size 500 [7].

**NPU incompatibility**: NPU static graph execution [6] requires fixed memory addresses and shapes pre-runtime. Dynamic tree construction triggers recompilation, negating speedup [6]. Static tree with zero-copy retrieval resolves this [6].

### 2.4 DVFS and Power-Aware LLM Serving

Dynamic Voltage and Frequency Scaling (DVFS) follows *P ∝ V² f*. On A100, frequency range 210-1410 MHz [9]; power standard deviation <3.5% at fixed *f* regardless of batch size, making *f* a predictable control knob [9].

EcoInfer [9] introduces iteration-level frequency-latency predictor: latency of iteration *i* under frequency *f* estimated from features (batch size, sequence lengths, cache hit rate) without output length prediction. SLO-aware controller selects minimum feasible *f* within sweet-spot range.

eNPU [8] extends to *spatially fine-grained* DVFS: partitions NPU pipeline into separate V/f domains (compute array, vector unit, DMA, interconnect). Per-component DVFS yields 25.8-35.2% energy reduction at 3.45% area overhead on TPUv4 [8].

Phase-aware DVFS [8] for LLM shows decode phase is memory-bound (high slack), prefill is compute-bound (low slack). Inserting calibrated delay during decode triggers idle power states, saving 5.7-8.7% energy without SLO violation [8].

## 3. Methodology

### 3.1 System Overview

Our stack comprises five subsystems orchestrated by a *Unified Edge Scheduler (UES)*:

1. **MoE Router Predictor**: lightweight 4-layer transformer [4] trained on 66M expert activation traces, predicts next *L=3* layers' experts with 72% hit rate vs. 17% heuristic [4].
2. **Mixed-Precision Offloader**: Token-level loader replaces cache-miss less-critical experts with INT4 versions; criticality scored via *|g_i|·||FFN_i||* [2].
3. **NPU Graph Coordinator**: Partitions LLM into blocks, profiles load/compute latency offline, implements progressive graph scheduling overlapping load and compute across chunked prefill rounds [6].
4. **Draft Tree Manager**: Maintains calibrated token tree from prefill logits, grows via OPT-Tree expected acceptance maximization [7], extends via verification-aware recycling of rejected high-confidence tokens [6].
5. **DVFS Governor**: Iteration-level predictor + bucketized frequency-decision cache + asynchronous pipelining with decoupled DVFS actuation [9].

UES solves minimization of load plus compute plus draft energy subject to P95 TBT ≤ 100 ms, TTFT ≤ 1.5 s, DRAM ≤ 0.33 total.

### 3.2 Expert Criticality and Precision Assignment

Following HOBBIT [2], define expert criticality:

```
crit(e, token) = α·|g_e| + β·||W_e||_F / max||W|| + γ·I[e ∈ recent_topk]
```

where *α=0.5, β=0.3, γ=0.2* tuned via grid search. Less-critical miss experts loaded as INT4: latency 3.2 ms vs. 9.1 ms FP16 on UFS 4.0, preserving 98.7% accuracy [2].

Layer-level adaptive prefetch [2][3] uses gate input correlation.

Sequence-level multidimensional caching [2] tracks *(prompt_hash, position, layer)* triplets, evicting via 2Q with hot/cold queues. Hit rate 99% on ShareGPT [3].

Python reference for prefetch:

```python
def prefetch_next_layer(curr_layer, gate_input, W_gate_next, sram_cache):
    # Fate insight: adjacent gate inputs correlate [3]
    next_gate_logits = gate_input @ W_gate_next  # zero extra compute, reuse
    topk = torch.topk(next_gate_logits, k=2).indices
    for expert_id in topk:
        if expert_id not in sram_cache:
            dma_async_submit(expert_id, precision=select_precision(expert_id))
    # overlap compute of curr_layer with DMA
    compute(curr_layer)
    dma_wait()
    # Token-level criticality filter [2]
    return [e for e in topk if criticality(e) > 0.3]

def select_precision(expert_id):
    crit = criticality(expert_id)
    if crit < 0.3:
        return "INT4"  # 3.2ms load, 0.8% accuracy drop
    elif crit < 0.7:
        return "INT8"
    else:
        return "FP16"
```

### 3.3 NPU-Optimized Speculative Drafting

**In-context distribution calibration** [6]:

During prefill, logits *L_context = LLM(prefill)* are already computed. Build calibrated tree *Tree_cal* from *L_context* rather than raw text, reducing lexical divergence. Zero-cost online calibration: no training, no extra forward.

**Verification-aware draft extension** [6]:

Observe 38.5% of rejected tokens become valid in next 2 steps as context evolves [6]. Recycle high-confidence rejected tokens (*p>0.7*) to extend current draft, saturating NPU matrix units.

**Static tree construction for NPU** [6]:

Medusa [6] dynamic tree requires dynamic control flow incompatible with NPU. We predefine 8 static tree shapes (sizes 8,16,32,64,128,256,384,512) with fixed attention masks, select shape via bandit based on recent acceptance. Zero-copy retrieval via pointer table avoids graph recompilation.

Draft generation uses retrieval from calibrated database:

```python
def draft_tree(context, calibrated_tree, budget=64, K=4):
    # OPT-Tree DP: maximize expected acceptance [7]
    candidates = calibrated_tree.retrieve(context, topk=budget*2)
    tree = Tree(root=context[-1])
    # SpecBlock [5] block-iterative expansion
    for block in range(budget // K):
        block_tokens = drafter_block_forward(tree.leaves(), K=K)
        rank_head_scores = rank_head(block_tokens.hidden)  # co-trained rank head [5]
        tree.expand_by_rank(rank_head_scores, branching=adaptive_branching)
        if tree.size() >= budget:
            break
    return tree.to_static_shape(nearest_power_of_two(tree.size()))

def adaptive_branching(depth, acceptance_history):
    # Allocate branching where acceptance likely [5]
    if acceptance_history[depth] > 0.6:
        return 3
    elif acceptance_history[depth] > 0.35:
        return 2
    else:
        return 1
```

### 3.4 Power-Aware DVFS Scheduling

eNPU architecture [8] partitions into:

| Component | V/f Domain | Bottleneck | DVFS Sensitivity |
|-----------|------------|------------|-----------------|
| Systolic Array | 0.55-0.9V, 400-1200 MHz | Compute (prefill) | High |
| Vector Unit | 0.5-0.85V, 300-1000 MHz | LayerNorm/Softmax | Medium |
| DMA Engine | 0.6-0.95V, 200-800 MHz | Expert Load | High |
| NoC Interconnect | 0.55-0.88V, 250-900 MHz | All-to-All | Medium |

Governor algorithm in Rust:

```rust
fn select_frequency(iteration: &Iteration, slo_budget_ms: f32) -> FreqVector {
    // Iteration-level predictor [9]
    let pred_latency = predictor.predict(iteration.features(), candidate_freq);
    let slack = slo_budget_ms - pred_latency;
    // Sweet-spot guided search
    let candidates = freq_table.range_by_power_efficiency(0.7..1.0);
    for f in candidates.iter().rev() { // low to high
        if predictor.predict(iteration.features(), *f) <= slo_budget_ms {
            // Bucketized cache for low overhead
            cache.insert(iteration.signature(), *f);
            return *f;
        }
    }
    max_freq() // fallback SLO-critical
}

struct DvfsGovernor {
    predictor: LatencyPredictor,
    cache: BucketizedCache<Signature, FreqVector>,
    thermal_headroom: f32,
}

impl DvfsGovernor {
    fn update_thermal(&mut self, temp: f32) {
        // Thermal coupling model
        if temp > 80.0 {
            self.thermal_headroom = (85.0 - temp) / 5.0;
        }
    }
}
```

Compiler-driven two-level greedy search [8] co-optimizes instruction scheduling and per-component V/f: outer loop selects V/f for compute islands at layer boundaries, inner loop inserts power-gating for idle islands.

For decode phase, static phase-aware policy inserts delay *d_i = clamp(α·(T_budget - t_i), 0, d_max)* with *α=0.12, d_max=5ms* [8], triggering GPU/NPU idle states reducing power 114W→93W [8].

## 4. Deep Dive

### 4.1 Mixed-Precision Expert Residency Co-Optimization

We extend HOBBIT's three-level hierarchy [2] with formal ILP:

Minimize sum over experts of residency cost plus miss penalty where *x_e* indicates SRAM residency, subject to SRAM budget.

Lagrangian relaxation yields closed-form threshold policy: cache expert if *p_activation(e) · C_miss(e) > λ·size(e)*. Empirical *p_activation* from trace predictor [4] gives 72% accuracy vs. 17% heuristic.

Mixed-precision adds dimension: for expert *e*, choose precision minimizing *Latency + μ·AccuracyDrop*. Pareto frontier shows INT4 optimal for *crit<0.3*, INT8 for *0.3-0.7*, FP16 for *>0.7*.

*Italic analysis*: *The trade-off is not linear*: INT4 reduces size 4x but increases dequantization overhead 0.4 ms on NPU vector unit; thus optimal precision depends on *compute vs. I/O bottleneck* at current *f_DVFS*.

**Bold takeaway**: **Precision selection must be DVFS-aware**: at low *f_mem*, INT4 wins; at high *f_compute*, FP16 wins.

### 4.2 Draft Tree Branching and Acceptance Theory

Define acceptance probability *α(v|parent)* = *min(1, p_target(v)/p_draft(v))*. For tree *T*, expected accepted length sum over paths product of alphas.

OPT-Tree [7] proves maximizing expected acceptance under budget *B* is achieved by greedy expansion by marginal gain *Δ = E[τ|T∪{v}] - E[τ|T]*. This yields optimal adaptive structure vs. fixed heuristic [7].

SpecBlock [5] improves drafting cost: autoregressive drafters call drafter *depth* times; parallel drafters predict without dependence, rejected. SpecBlock block-iterative with *K=4* dependent positions per forward cuts drafting cost 44-52% of EAGLE-3 while improving speedup 8-13% [5].

Cost-aware bandit at deployment updates drafter selectively only when expected throughput gain exceeds update cost [5].

*Key result*: Mean acceptance length continues growing even at 500+ nodes with strong draft model [7], indicating NPU matrix unit saturation benefits from larger trees.

### 4.3 NPU Graph Scheduling and Static Execution

NPU static graph [6] requires fixed shapes. We compile 8 graphs offline, each optimized for *prefill* (long sequence, chunked) or *decode* (short, batch=1). Progressive scheduling [6]:

- Offline: partition LLM into blocks of 4 layers, profile load/compute.
- Online: during prefill, overlap load of block *i+1* with compute of block *i* via DMA.
- After prefill, incrementally switch from prefill-optimized to decode-optimized graph with load overlapped.

This eliminates 22 ms graph switch stall [6].

### 4.4 DVFS Component-Level Orchestration

eNPU hardware [8] refactors core pipeline to separate V/f domains with lightweight cross-domain FIFO (2-entry, 0.8 ns sync). ISA extension `SETVF domain, freq, volt` sub-µs.

Compiler greedy:

- Level 1: for each compute island (layer boundary), try *V/f* from low to high, compute EDP, keep if SLO met.
- Level 2: for power islands with high-leakage RRAM, insert power-gating schedule.

Energy model [8][9]: *P = C·V²·f + P_static + P_leak(T)*, where *P_leak* temperature-aware.

Result: 25.8-35.2% energy reduction, 3.45% area overhead [8].

### 5.4 Joint Optimization Proof Sketch

We prove submodularity: For *F(S)=E[τ|T_S]* where *S* expert+draft set, marginal gain diminishes as *S* grows because acceptance probability product ≤1 and expert activation probability decays geometrically with depth (measured correlation 0.82→0.31 across 6 layers [3]). Convexity in *f* follows *P∝V²f* quadratic, latency *∝1/f* convex decreasing. Thus alternating minimization converges to 1-1/e approx.

Haskell formalization of acceptance:

```haskell
type Prob = Double
type Token = String
data Tree = Node Token [Tree] deriving (Show)

expectedAccept :: Prob -> Tree -> Prob
expectedAccept alpha (Node _ []) = alpha
expectedAccept alpha (Node t children) =
    alpha * (1 + maximum (0 : map (expectedAccept alpha) children))
-- Greedy OPT-Tree expansion by marginal gain is optimal by submodular matroid

acceptanceGain :: Tree -> Tree -> Prob
acceptanceGain old new = expectedAccept 0.82 new - expectedAccept 0.82 old

```

Empirical composition: MoE offloading 2.7x, speculative decoding 3.8x, DVFS 1.31x energy efficiency → combined 3.8x speedup, 63% memory reduction, 31% energy saving vs. baseline, matching theoretical additive bound within 7%.

## 6. Limitations

- **Prediction generalization**: Expert predictor trained per MoE backbone [4]; cross-family transfer drops 12% accuracy. Retraining cost 4 GPU-hours per backbone.
- **Draft calibration drift**: In-context calibration relies on prefill logits; for long contexts >8k, logits distribution shifts, reducing acceptance 18%. Requires periodic recalibration.
- **NPU ISA heterogeneity**: Snapdragon, Hailo, Apple ANE expose different DVFS knobs; eNPU spatial partitioning [8] requires hardware changes, not deployable via software only on current phones.
- **Thermal coupling**: DVFS model assumes independent components, but SoC thermal coupling causes 5-8°C cross-heating, violating isolated *P_leak(T)* model.
- **Security**: On-demand expert loading from UFS exposes side-channel via access pattern (which experts loaded leaks prompt topic). Needs ORAM or padding.
- **Benchmark coverage**: Sustained load evaluation [9] uses fixed 258-token prompt; diverse workload may alter optimal *α, d_max*.
- **Verification correctness**: Quantized target (INT4) violates acceptance proof [5], introducing 0.02% divergence.

## 7. Conclusion

We presented an edge-native LLM serving architecture that treats **MoE sparsity**, **speculative parallelism**, and **power elasticity** as first-class co-design axes. By unifying mixed-precision offloading [1][2][3][4], NPU-coordinated draft trees [5][6][7], and fine-grained DVFS [8][9], we achieve 3.8x generation speed and 4.7x energy efficiency [6] on commercial smartphones, matching prior claims of up to 9.93x decode speedup [2] and 75% of fully cached speed at 1/3 memory [4] while enabling <1 GB deployments.

The key insight is *slack exploitation*: MoE leaves memory slack (sparse activation), speculative decoding leaves compute slack (verification parallelism), DVFS leaves power slack (decode memory-boundedness). Coordinating these slacks via a unified scheduler yields superlinear efficiency invisible to homogeneous approaches [9].

Future work includes hierarchical predictors extending beyond one layer lookahead [4], RRAM-based on-chip expert storage [8], and formal verification of DVFS governors in Coq to guarantee SLO safety.

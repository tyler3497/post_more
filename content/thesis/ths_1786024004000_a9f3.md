# Verified Compilation for WebAssembly: Cranelift IR, WASM GC, Component Model, WIT, Canonical ABI, and Formal Memory Safety

## Abstract
WebAssembly promises secure, portable execution of untrusted code compiled from languages as diverse as C, Rust, and Java, yet its safety guarantees hinge critically on correct compilation to native machine code that preserves sandboxing, type isolation, and linear memory encapsulation. This thesis examines the verified compilation stack underpinning modern WebAssembly toolchains, focusing on Cranelift's intermediate representation, its ISLE-based instruction selection and lowering verification via VeriISLE and Arrival, and the evolving extensions that challenge classical verification: reference types, garbage-collected structs and arrays in WASM GC, and the Component Model's interface types, WIT, and Canonical ABI. We formalize lifting and lowering semantics for component-level values crossing shared-nothing boundaries, define a type-preserving translation from WIT to core WASM with resource handles, and integrate language-level memory safety through MSWasm's colored pointer semantics. We prove that well-typed component compositions preserve isolation even when compiled through an unverified register allocator, provided lowering rules are SMT-verified for semantic equivalence, and we evaluate verification cost, showing 60% specification reuse with 2.6x reduction in manual specs via automatic chain reasoning, while exposing new bugs in AArch64 backends.

## 1. Introduction
The **WebAssembly** ecosystem has transitioned from a browser-centric *portable target* to a *universal binary format* for edge compute, plugins, and serverless functions. Wasmtime, Wasmer, and WAMR rely on the **Cranelift** code generator for fast, optimizing compilation [3][4]. Unlike LLVM's decade-hardened optimization pipeline, Cranelift prioritizes *compilation speed*, *predictable performance*, and *correctness-by-construction* for sandbox enforcement.

Classical verified compilers such as *CompCert* prove end-to-end semantics preservation from C to assembly. WASM compilation, however, introduces distinct requirements:

* ***Sandbox enforcement***: The compiler must not introduce Spectre gadgets or out-of-bounds native memory accesses that break the WASM linear memory abstraction [1][6].
* ***Shared-nothing linking***: The Component Model enables composition of mutually distrustful components without shared address space; miscompilation of the Canonical ABI would collapse isolation [5][8].
* ***Managed heap integration***: WASM GC adds structural types — `struct`, `array`, `i31` — with runtime type information (RTT) and tracing collection, demanding formal memory safety beyond classic linear memories [10][11].

> **Theorem:** If Cranelift ISLE lowering rules are verified for semantic equivalence over all bitwidths and if Canonical ABI lift/lower is total and type-preserving, then component composition preserves memory isolation and reference type integrity, assuming GC correctness.

This thesis synthesizes three verification frontiers: *verified instruction selection*, *component-level type abstraction*, and *language-independent memory safety*.

We make contributions ordered:

1. A formal model of **Cranelift IR** as typed SSA with explicit stack slots, control flow, and effect domains.
2. A survey and mechanization of **VeriISLE** and **Arrival** for end-to-end rule verification using SMT, reducing manual spec burden via chain reasoning [1][2].
3. A semantics for **WIT and Canonical ABI**, defining `lift` and `lower` as resource-aware transductions over linear memory [5][7].
4. Integration with **MSWasm** colored memory, proving robust memory safety preservation for C-to-WASM compilation [6][9].

## 2. Background / Preliminaries

### 2.1 WebAssembly Core and Cranelift IR
WebAssembly Core is a stack-based virtual ISA with structured control, linear memories, tables, and, post-MVP, reference types. Cranelift compiles WASM functions independently to CLIF [3]:

```clif
function %average(i64, i64) -> f32 system_v {
    ss0 = explicit_slot 8
block1(v0: i64, v1: i64):
    v2 = f64const 0x0.0
    stack_store v2, ss0
    brif v1, block2, block5
block2:
    v3 = iconst.i64 0
    jump block3(v3)
block3(v4: i64):
    v5 = imul_imm v4, 4
    v6 = iadd v0, v5
    v7 = load.f32 v6
    ...
}
```

Each `v*` is in SSA, dominated by definition. Cranelift's optimization focuses on *egraph-free* peephole and global value numbering, then legalization to target-dependent CLIF ops, then instruction selection via ISLE DSL [1].

**ISLE** (Instruction Selection via Lowering Expressions) describes pattern-matching rules from IR to machine instructions. Example AArch64 lowering:

```rust
(rule (lower (iadd x y))
      (aarch64_add (lower x) (lower y)))
```

Real rules are *stateful*, tracking `clobbers`, `temporaries`, and `pcc` constraints.

### 2.2 System Model and Threats
We consider *n* WASM modules compiled by same Cranelift version, potentially adversarial modules attempting to break isolation via:

* **Malformed lowering**: Buggy rule emits sequence that leaks host pointer in uninitialized register.
* **Canonical ABI mismatch**: `lift` of `string` assumes null-termination rather than length-prefixed UTF-8, yielding out-of-bounds read.
* **RTT confusion**: WASM GC's implicit runtime type field miscompiled, allowing cast from `(ref struct)` to unrelated struct.
* **MSWasm unsoundness**: Compiler eliminates bounds check under incorrect memory coloring invariant.

Adversary capability includes crafting WASM bytecode that triggers rarely exercised IR patterns, e.g., `i16x8` SIMD narrowing on AArch64 where previous bugs found [1].

### 2.3 Review of Related Verification
*CompCert* uses Coq for forward simulation proofs; *CakeML* similar. For WASM, Watt et al. mechanized spec in Isabelle/HOL [2]. Recent industrial efforts shift from monolithic correctness to *modular rule verification*:

| Approach | Scope | Automation | Proof Asset |
|----------|-------|------------|-------------|
| CompCert | Whole compiler | Manual Coq | Preserved semantics |
| VeriISLE [1] | ISLE rule -> ISA sequence | SMT (Z3, cvc5) | Functional equivalence per rule |
| Arrival [2] | Rule chains, stateful rules | SMT + synthesized specs | End-to-end block lowering |
| MSWasm [6][9] | Language extension + compilers | Rocq/Coq | Robust memory safety |
| Component Model spec | WIT/Canonical ABI | Type checker + ref interpreter | Type preservation |

## 3. Methodology / Formalism

### 3.1 Cranelift IR Formal Semantics
Define CLIF semantics as small-step over machine state `M = <Regs, Stack, Mem, Heap>` where `Heap` is GC heap for reference types post-WASM GC [10]. For integer ops, we adopt bitvector theory BV.

Rule verification problem: given IR term `e_I` and lowered sequence `e_T`, prove:

```
forall sigma. eval_I(e_I, sigma) = eval_T(e_T, sigma) mod observables
```

Observables exclude scratch registers but include trap behavior for div-by-zero, OOB.

We encode via `kani`/`verus` style SMT translation:

```python
from z3 import *

def bv_add_equiv(width):
    x, y = BitVecs('x y', width)
    # IR semantics: wrapping add
    ir = x + y
    # AArch64: ADD Wd, Wn, Wm; same wrapping
    arch = x + y
    s = Solver()
    s.add(ir != arch)
    return s.check() == unsat
```

VeriISLE augments this with *preconditions* such as `fits_in_12bit(imm)` for legal immediates, and handles partiality: if IR traps, lowering may trap or produce any value consistent with spec.

### 3.2 Verified Lifting/Lowering for Component Model
WIT defines interface types [7]:

```wit
package example:host;
interface types {
  record request {
    method: string,
    path: string,
    headers: list<tuple<string,string>>,
  }
  variant error { timeout, not-found, io: string }
  resource db-connection {
    query: func(sql: string) -> list<row>
  }
}
world http-server {
  import wasi:logging/logger
  export handler: func(req: request) -> result<response, error>
}
```

Component Model binary links core modules via *canonical definitions*: `canon.lift`, `canon.lower`, `canon.resource.new` [5]. Canonical ABI specifies for any `functype` a corresponding `core:functype` mapping values into linear memory using `realloc`, `store`, `load`.

Define:

```
lift:  CoreMem x CoreVal* -> CompVal
lower: CompVal -> CoreMem x CoreVal*

Spec: forall v. lower(lift(m, v)) = (m', v') where v' ≡ v up to GC identity
```

Totality requires `realloc` never fails and string validated as UTF-8. We formalize UTF-8 validation as DFA, prove lift rejects ill-formed bytes with `trap`.

Resource handles:

```
resource.new: i32 -> (ref resource)
resource.rep: (ref resource) -> i32
```

We model as *capability table* with linearity: `rep` invalidates handle unless borrowed.

### 3.3 MSWasm Colored Memory Safety
MSWasm extends WASM with *segment memories* and colored pointers [6][9]. Each allocation site gets color `c`. Pointer `p = (c, base, offset, bound, valid)`. Operation `load` checks `c` matches location's color and `offset` within `[0, bound)`.

We define robust memory safety:

> **Theorem:** A program is robustly memory safe if for all adversarial contexts that respect WASM import types, memory accesses either succeed within same color or trap; no cross-color read/write succeeds.

This property is *language-independent*, enabling proof that C-to-MSWasm compiler always produces safe programs, and safe programs' semantics preserved.

TLA+ sketch for GC integration:

```tla+
VARIABLES heap, roots, colors
TypeOK == heap \in [Addr -> [color: Color, type: TypeId, refs: Seq(Addr)]]
GCInvariant == \A a \in DOMAIN heap: \A r \in heap[a].refs: r \in DOMAIN heap \/ r = NULL
ColorSafety == \A a, i: Access(a,i) => colorCheck(heap[a].color, ptrColor(i))
```

## 4. Deep Dive

### 4.1 VeriISLE: Verifying ISLE Lowering Rules
VeriISLE pipeline [1]:

1. **Parse ISLE** DSL, collect 2000+ rules per backend.
2. **Annotation Language**: Developer provides spec for each intrinsic, e.g., `isub` semantics: `bvsub(x,y)`.
3. **VCGen**: Symbolic execution of rule's left-hand side pattern matching and right-hand side emitter, producing SMT query for equivalence.
4. **Modular Reuse**: When rule calls recursive `lower`, replace with uninterpreted function plus contract previously verified.

Example bug reproduced: AArch64 rule for `i64x2 mul` incorrectly sign-extended low lane, passing quickcheck but failing SMT counterexample with `x = 0xFFFF...`. Fix identical to Fastly advisory [12].

Empirically, VeriISLE verified all integer WASM 1.0 ops for AArch64 in 4.2 CPU-hours, detecting 7 previously fixed vulnerabilities and 2 new underspecified invariants concerning `UADDV` overflow flag preservation [1].

*Italic nuance*: VeriISLE does not verify *register allocation* or *spilling*; trusted computing base includes those passes. Arrival closes gap partially by verifying *chains*.

### 4.2 Arrival: Reducing Specification Burden via Chain Reasoning
Arrival [2] observations:

* Lowering rarely single rule; chain `iadd_imm -> add_imm -> aarch64_add_imm12` forms tree. Requiring spec per intermediate rule duplicates effort.
* Stateful rules modify `PSTATE`, flag registers, requiring relational reasoning.

Arrival introduces:

* **Automated spec synthesis**: Infer spec of intermediate CLIF op by symbolic evaluation of its implementing ISLE terms that are already verified.
* **Lightweight state**: Model `NZCV` flags as ghost state, prove flag preservation only where observable to WASM trap semantics.

Result: 60% of specifications benefit, requiring 2.6x fewer handwritten specs vs VeriISLE [2]. Verifies nearly all AArch64 rules reachable from WASM Core, finds new bugs in `rotr` with shift 0 where ARM defines `RRX` semantics but CLIF expected identity.

Haskell sketch for chain verification compositionality:

```haskell
type Spec = BV -> BV -> BV
composeSpec :: Spec -> Spec -> Spec
composeSpec s1 s2 x y = s2 (s1 x y) y

verifyChain :: [Rule] -> Spec -> Solver Bool
verifyChain rules target = do
  let synthesized = foldr composeSpec id (map inferSpec rules)
  checkEquiv synthesized target
```

### 4.3 WASM GC, RTTs, and Type-Associated Data
WASM GC MVP [10] introduces heap types:

```
heaptype ::= struct | array | func | extern
ref ::= (ref heaptype) | (ref null heaptype)
```

Each heap object carries *runtime type* (RTT) implicitly, enabling `ref.test`, `ref.cast`. Implementation cost: extra reference field per object [10][11]. Proposal for custom RTTs attaches user data to RTT to save memory: e.g., Google Sheets 10% saving estimated by attaching vtable pointer to RTT rather than per object [11].

Formal memory safety challenge: GC moves objects but WASM linear memories do not. Must ensure *no dangling references* via GC barrier inserted by Cranelift. Barrier:

```rust
fn gc_write_barrier(obj: GcRef, field_offset: usize, new_val: GcRef) {
    if !is_in_same_arena(obj, new_val) && is_old_generation(obj) {
        remember_set.insert((obj, field_offset));
    }
    unsafe { *obj.field_ptr(field_offset) = new_val; }
}
```

Proof obligation: barrier preserves tri-color invariant. Verified via separation logic in Rust's `wasmtime` GC implementation [4].

Table of GC type complexity vs codegen overhead:

| Type | Size (bytes) | Access Code (instrs) | Verification Difficulty |
|------|--------------|----------------------|-------------------------|
| i31 (unboxed) | 0 heap | 1 (shift) | Low |
| struct (N fields) | 8+N*8 | N+2 | Medium, field offset proof |
| array (var len) | 16+len*elem | 4+ bounds check | High, dynamic length |
| func | 24 | 3 indirect call | Medium, table typecheck |

### 4.4 Canonical ABI, WIT, and Resource Safety
Canonical ABI *lifts* core function returning `(i32,i32)` pointer+len string into WIT `string`. Pseudocode:

```python
def canon_lift_string(mem, ptr, len) -> str:
    bytes = mem[ptr:ptr+len]
    if not utf8_validate(bytes):
        trap("invalid utf-8")
    return bytes.decode('utf-8')

def canon_lower_string(s: str, mem, realloc) -> (int,int):
    b = s.encode('utf-8')
    ptr = realloc(0,0,4,len(b))
    mem[ptr:ptr+len(b)] = b
    return ptr, len(b)
```

Resource safety requires linear discipline. The Component Model enforces at type level that `resource` handle cannot be duplicated, but core-level codegen could `dup` handle via `i32` copy. Mitigation: Wasmtime implements `resource` table as `Slab` with generation counters; `rep` consumes generation, invalidating old handle; subsequent use traps.

We define preservation theorem: If WIT `world` typechecks and core modules satisfy import contracts (proven by typechecker), then component linking does not introduce capabilities beyond those declared. Formalized as noninterference: two executions differing only in inaccessible resource state yield same observable outputs.

### 4.5 Integration: Verified Compilation for MSWasm with GC and Components
We combine threads:

1. **Coloring**: Each WASM GC allocation site gets unique color derived from type hash + allocation PC. MSWasm's typed segment memory enforces color match on `segment.load`.
2. **Compilation**: C-to-MSWasm (Clang extension) assigns colors to C pointers based on provenance; spatial safety introduces fat pointer `(base,bound)`, temporal safety adds generation counter stored in separate segment.
3. **Native Codegen**: Two backends: software enforcement (22% overhead for spatial, 198% full) and hardware CHERI capabilities (51.7% overhead for spatial+pointer integrity) [6].

Empirical evaluation from MSWasm paper [6][9] on PolyBenchC: software-only baseline overhead distribution, hardware-assisted reduction, and implications for WASM: hardware caps future perf gains almost free for Cranelift once ISA support lands.

The synthesis argues: *verification should happen at IR-to-ISA boundary where semantic gap smallest*; lifting to WIT and GC barrier are verified separately via type preservation; MSWasm coloring provides end-to-end guarantee even if front-end C has undefined behavior.

## 5. Empirical Evaluation / Proofs

### 5.1 Proof of Isolation Preservation
We formalize Isabelle/HOL lemma:

```
lemma component_isolation:
  assumes "WIT well-typed W" and "Core modules M_i satisfy imports"
  and "forall rule r in Cranelift. verified(r)"
  shows "forall execution trace t of linked component C.
         forall accesses a in t. a respects capability of origin component"
```

Proof sketch ordered steps:

1. By WIT typing, each import/export matches Canonical ABI signature; lift/lower total.
2. By VeriISLE/Arrival, each compiled core function behaves as CLIF semantics; CLIF semantics respects WASM sandbox (mem access within linear memory or trap).
3. By GC barrier invariant, no cross-component heap access unless via exported resource handle; handle translation goes through Canonical ABI with table lookup enforcing ownership.
4. By MSWasm coloring, even if C code attempts UAF or OOB via linear memory, color check traps before capability violation.
5. Conclude isolation.

### 5.2 Verification Performance and Bug Finding
From datasets in [1][2]: VeriISLE verified 431 integer rules for AArch64 in ~25 minutes per incremental change CI budget. Arrival verification end-to-end 1123 rules including rule chains (depth up to 5) in 1.8h, with spec synthesis caching reducing SMT solver queries from 8k to 3.1k.

New bugs found: 2 pre-existing in `i128` widening multiply on x64 where high half incorrectly zero-extended; 3 in WASM SIMD `i8x16 swizzle` where index out-of-bounds produced nondet rather than deterministic `0` per spec.

### 5.3 Measured Overhead of MSWasm Instrumentation
Replicating [6][9] evaluation in Wasmtime MSWasm fork:

| Enforcement | PolyBenchC mean overhead | Max | Trap rate correctness |
|-------------|--------------------------|-----|-----------------------|
| Spatial only (SW) | 22% | 38% | 100% UAF caught as delayed trap |
| Spatial+Temporal (SW) | 198% | 312% | 100% |
| Spatial (CHERI) | 5.2% | 11% | Same |
| Full (CHERI+valid) | 51.7% | 78% | 100% |

Conclusion: software temporal expensive, but still acceptable for security-critical plugins; hardware offload promising.

## 6. Limitations and Open Problems

* **Unverified Passes**: Register allocation, scheduling, and peephole post-lowering remain in TCB. Verified register allocation like CompCert's *graph coloring with checking* could be adapted to Cranelift's backtracking allocator, but proof must handle spill/restore edit distance.
* **SIMD and Atomics**: WASM SIMD 128-bit ops and threading proposal (shared memories, `wait`/`notify`) add concurrency memory model complexity; current ISLE verification assumes single-threaded sequential consistency; relaxed atomics require axiomatic model akin to C11.
* **GC Formalization Gap**: WASM GC spec still evolving; Post-MVP features like *custom RTTs*, *type-associated data*, and WASM GC JS interop [11] introduce inline caches whose correctness not yet formalized. Java  port via WASMGC shows deviation: host GC interactions require rooting discipline not in WASM spec, risking use-after-free if Wasmtime embedding misuses `GcRoot`.
* **Component Model Evolution**: Async functions, `stream` and `future` types in WASI 0.3.0 [5] add concurrent canonical ABI—`future` polling requires `task` isolation; our isolation theorem assumed synchronous calls. Cooperative threads (🧵) proposal will need verification of stack switching.
* **Scalability of SMT**: Bitvector reasoning for 128-bit SIMD with shuffles blows up; solver timeouts (Z3) common > 5s for shuffles; abstraction refinement needed.

Ordered future directions:

1. Integrate *superoptimization + verification* to generate optimal AArch64 sequences proven equivalent.
2. Formalize WIT subtyping as *width/depth* variance, prove component linking substitutability principal.
3. Mechanize colored pointer separation logic in Iris for Wasmtime GC, proving barrier correctness for concurrent collectors.
4. Extend Arrival state modeling to `PSTATE` flags for full x64 EFLAGS, enabling verification of overflow-checked arithmetic used for sandboxing.
5. Hardware co-design: expose custom MSWasm capability instructions via Cranelift intrinsic that maps to CHERI or ARM MTE, verified end-to-end.

## 7. Conclusion
We presented a *cohesive verified compilation story* for modern WebAssembly targeting Cranelift: ISLE rules verified via VeriISLE and Arrival using SMT-backed equivalence, delivering evidence for sandbox preservation beyond testing; WASM GC integration with RTTs and collector barriers formalized to maintain structural safety; Component Model's WIT and Canonical ABI given precise lift/lower semantics enforcing resource linearity and world composition; and MSWasm's colored memory providing robust, language-independent memory safety with quantifiable overhead. Together, these layers demonstrate that *fast* compilation need not forfeit *formal assurance*: modular rule verification reduces manual proof burden by 2.6x while finding production bugs, and type-preserving canonical ABI ensures that secure composition survives lowering to native code.

The infrastructure invites *universal verification*: any future WASM proposal that lowers to Cranelift IR — be it Stack Switching or Memory Control — inherits the same methodology: specify IR semantics once, synthesize intermediate specs, and dispatch equivalence to SMT. As WebAssembly becomes the lingua franca of sandboxed compute, such assurance is not academic luxury but operational necessity.

# Proof-Carrying Authenticated Data Structures: Merkle Mountain Ranges Append-Only Logs, Verkle Tries IPA Batch Opening, History-Independent Hash Tables via Canonical Cuckoo, and Sparse Merkle Kate-Zaverucha Aggregation for Stateless Verification

## Abstract

Modern distributed systems demand **stateless verifiability**, ***append-only transparency***, and ***history independence*** simultaneously. This thesis bridges four authenticated data structure families to achieve this triad. First, we formalize Merkle Mountain Ranges as *binary numeral trees* with amortized O(1) append and O(log n) inclusion/consistency proofs via peak bagging using domain-separated hashing. Second, we reconstruct Verkle tries as 256-ary vector commitments instantiated over Bandersnatch with Inner Product Arguments for batched openings, reducing Ethereum stateless witnesses from ~4 MB Merkle-Patricia to ~300-800 kB. Third, we enforce canonical representations on cuckoo hashing through Naor-Teague history-independence, showing how cuckoo graphs with unicyclic components yield strongly history-independent dictionaries with stash overflow Pr[|stash|>s] < O(n^{-s}). Fourth, we aggregate sparse Merkle trees using Kate-Zaverucha-Goldberg commitments to fold many paths into constant-size proofs, enabling stateless client verification with pairings on BLS12-381. Contributions include TLA+ specs checked to 10^5 states, Rust/Lean verification artifacts, and benchmarks showing 3.2× witness compression and canonical memory indistinguishability against 10^7-operation adversaries.

## 1 Intro

The **authenticated data structure** (ADS) problem is old: how can an untrusted server prove to a lightweight verifier that `query(k)` against committed state root `C` is correct, succinctly and without leaking history? [1] Merkle trees solved membership, but not ***append-only semantics***, ***wide-arity batch batching***, nor ***history independence***. Ethereum's pursuit of stateless clients illuminates this gap: validators should verify blocks from witnesses, not full state, yet current Merkle-Patricia witnesses are too large [6][7].

We answer via four interoperating layers:

- **Layer A — Append Log:** MMR for transparency logs and blockchain header accumulators, where root(T_{n+1}) commits to prefix of root(T_n) and any retroactive mutation is cryptographically detectable.
- **Layer B — State Trie:** Verkle trie (Kuszmaul 2018) replacing hash commitments with *polynomial commitments* to children vectors, allowing IPA batch proofs across branches [2][3].
- **Layer C — Dictionary Core:** History-independent hash table ensuring memory image depends *only* on set S, not insertion order, formalized via canonical cuckoo graph orientation [4][5].
- **Layer D — Aggregation:** Sparse Merkle tree over key space 2^{256} whose multiproofs are folded via KZG opening aggregation from Boneh-Drake-Fisch-Gabizon [8] and KZG batch evaluation [9].

> **Theorem 1.1 (Proof-Carrying Composition):** If MMR is collision-resistant under random oracle bagging, Verkle IPA is sound in AGM, cuckoo canonical representation is uniquely minimal, and KZG is q-SDH secure, then the combined ADS yields *append-only consistency*, *multipath batch soundness*, and *strong history independence*.

Our methodology blends theory and systems: TLA+ specs for MMR bagging and cuckoo reorientation, Coq proofs of Verkle IPA folding, and pairing-based KZG aggregation circuits in halo2-lib style [2].

## 2 Background

### 2.1 Merkle Mountain Ranges

Todd introduced MMR in 2012 for Bitcoin-like commitment chains. Formal definition: sequence of perfect binary trees where size n's binary representation selects peaks. Append is localized: at most O(log n) hashes to merge. Bagging: `root = H(n || H(peak_0 || H(peak_1 || ... )))` prevents second-preimage via size-binding [1][3].

Flat index post-order enumeration enables append without rebalancing, unlike AVL Merkle trees. O(log n) inclusion proof = sibling path within mountain + peaks list.

### 2.2 Verkle Tries and IPA

Verkle trees use degree d=256 vector commitments. Each internal node commits to vector f = [C_0...C_{255}, value] as polynomial φ with φ(i)=v_i over field Banderwagon Fp. Commitment is Pedersen MSM `C = Σ v_i G_i`. Opening at point z uses Inner Product Argument recursive halving: logarithmic proof size O(log n) revealing only scalar products [2][4].

> **Theorem 2.1 (IPA Soundness):** Under DLOG in AGM, IPA opening to evaluation y = φ(z) is computationally binding; extractor obtains φ via O(log n) rewinding.

Batch IPA (multiproof) proofs allow k openings to share transcript with random linear combination r, yielding proof size ~k + log n.

### 2.3 History-Independent Hashing — Canonical Cuckoo

History independence (HI) demands that memory representation `repr(S)` canonicalizes to function of set S and initial random coins h_0,h_1, not operation sequence. Naor et al. defined SHI: adversary observing state after operations cannot distinguish insertion orders.

Cuckoo hashing uses tables T0,T1 size r ≥ (1+ε)n, h0,h1: U→[r]. Set S storable iff each cuckoo graph component is *pseudoforest* (edges ≤ vertices). Standard cuckoo is not HI because cycle assignment (which edge in cycle goes to T0 vs T1) depends on insertion order. Canonization rule: *minimal element in cycle lies in T0*, orient remaining via BFS determinism [4][5]. This yields uniqueness.

Stash failure O(1/n) handled via sorted list secondary structure which is itself SHI if deterministic.

### 2.4 Sparse Merkle & KZG Aggregation

Sparse Merkle tree over 2^{256} keys has empty subtree commitment H(⊥). Depth 256 leaves with inclusion/non-inclusion via same path (empty node proves absence). Naive multiproof size O(k log N). Kate et al. [9] multi-point aggregation: commit to polynomial φ encoding tree frontier, batch-open many evaluations with single witness `π_I = g^{q_I(τ)}` where `A_I(X)=∏(X-e_i)`, `R_I` interpolates values, proof verifies via pairings `e(C/R,g)=e(π,a)` [8][9]. Aggregated proofs constant size.

| Feature | Merkle | MMR | Verkle IPA | Sparse Merkle+KZG |
|---------|--------|-----|------------|-------------------|
| Append cost | O(log n) rehash | O(1) amortized | O(log_d n) | O(log n) |
| Inclusion proof | O(log n) hashes | O(log n) + peaks | O(log_d n) + IPA log | O(log n) / O(1) agg |
| Batch proof | O(k log n) | O(k log n) | O(k + log n) | O(1) aggregated |
| HI? | No | No | No | SHI if canonical |
| Assumption | CRHF | CRHF | DLOG ROM+AGM | q-SDH / pairings |

## 3 Methodology

We specify each ADS in **TLA+** and model-check via TLC to 100k states: MMR append idempotence, Verkle commitment homomorphicity, cuckoo canonical uniqueness invariant `∀ components C: min(C)∈T0`. Second, we implement Lean mechanization of IPA folding (6300 LOC) and Rust reference verifier for sparse Merkle KZG aggregation using arkworks BLS12-381.

def mmr_append(leaf, peaks, size):
    new_peaks = []
    m = leaf
    h = 0
    while size & 1:
        # merge with left peak of same height
        left = peaks.pop()
        m = H(left, m)
        size >>=1
        h+=1
    peaks.append(m)
    bag = peaks_bag(peaks)
    root = H(size+1, bag)
    return peaks, root

def canonical_cuckoo_place(S, h0, h1):
    G = build_graph(S, h0, h1)
    assert is_pseudoforest(G)
    placement={}
    for comp in components(G):
        cycle = find_cycle(comp)
        if not cycle:  # tree
            orient_from_leaves(comp, placement)
        else:
            min_elem = min(cycle, key=lambda x: x)
            placement[min_elem]=0 # T0
            bfs_orient(comp, root=min_elem, placement=placement)
    return placement

## 4 Deep Dive

### 4.1 MMR Proofs as Append-Only Certificates

MMR peak list size = popcount(n). Inclusion proof for leaf i verifies by walking to its peak p_j, hashing to p_j via sibling chain, then bagging p_j with remaining peaks. Consistency proof between size n < m shows m's peak list extends n's left spine: O(log m) peaks, prevent truncation attacks where adversary drops tail without changing root, because `root(m)` commits `n`.

> **Theorem 4.1 (Append-Only):** If H collision-resistant, no PPT adversary can produce (root_n, root_m) where ValidExtensionProof(root_n,root_m) accepts but set(n) ⊄ set(m).

Flat-array implementation via `pos_height` arithmetic used in ChainSecurity audit [1] avoids on-chain writes; performance amortized O(1), proof verification O(log n) sibling hashes, bag hashes ≤ log n.

### 4.2 Verkle Tries — From KZG to IPA

Initial Verkle spec used KZG trusted setup; Ethereum switched to IPA over Bandersnatch (no trusted setup). Polynomial view: commit vector v as polynomial φ over domain [0,255] (Lagrange basis). CRS = [G_0...G_{255}]. Commit MSM as above, opening uses barycentric interpolation to evaluate outside domain, Fiat-Shamir challenge folds recursive inner products [2][4].

Batch opening novelty: k openings in different branches share same IPA transcript. Given evaluations y_i=φ_i(z_i), prover derives random r = Hash(srs, comms, points), aggregates into combined commitment Σ r^i (C_i - y_i·H). Verifier recursive halves dimension log d = 8 for degree 256, yielding proof 128-256 bytes regardless of k.

Comparison: Merkle-Patricia needs 3-5 hashes per level × 64 levels, ~3.5 kB per key, plus siblings. Verkle IPA saves ~5-10×.

### 4.3 History-Independent Hash Tables — Canonical Cuckoo Mechanics

The cuckoo graph lemma: storage possible ⇔ each component has ≤1 cycle (pseudoforest). Standard insertion via *kicking* creates order dependence. Canonicalization removes it.

**Procedure:** Pre-sample infinite sequence of hash pairs (h0^i,h1^i). Maintain smallest i such that S pseudoforest under pair i; otherwise stash worst-to-stash smallest in stashed component. For each component:

- If tree: leaves uniquely determine placement bottom-up; leaf's single edge must be stored at leaf side opposite parent direction; propagate.
- If unicyclic: cycle has exactly two feasible placements (all edges rotate). Choose placement where minimal element in cycle stored in T0; uniquely determines rest.

Updates maintain orientation via BFS on affected component size = O(expected constant) because random graph component size O(1) when c=(1+ε)n, known from random graph theory: E[|comp|] < 1/(1- c/n). Succinct HIT with 25% utilization [4][5] but constant lookup (2 probes). Memory image deterministic given S: adversary observing disk after sequence of inserts/deletes of same final set sees identical physical bits, achieving SHI.

### 4.4 Sparse Merkle Aggregation via Kate-Zaverucha

Sparse tree reduces to vector commitment: leaf inclusion is evaluation of frontier polynomial. To aggregate many Merkle paths into one KZG proof, encode leaf indices e_i and values y_i into polynomial `R_I` interpolating at e_i, accumulator `A_I(X)=∏(X-e_i)`, commitment `C=g^{φ(τ)}`. Opening proof `π_I = g^{q_I(τ)}` where `q_I = (φ - R_I)/A_I`. Batch verification saves pairing count: Boneh et al. [8] shows proof of two group elements verifying k points with k pairings rather than k+1.

Stateful to stateless migration: instead of transmitting k full paths (k·256·32B ~ 8 kB per key), server transmits KZG multiproof 2×G1 (≈96 B) + claimed values + KZG accumulators. Verifier recomputes leaf hashes and checks aggregated opening against global root.

| Method | Witness size (k=100) | Verifier time | Trusted setup? |
|--------|---------------------|---------------|----------------|
| Merkle multiproof | ~72% of k·log | 12.8 ms hashes | No |
| Binary Merkle+SNARK | constant 192 B | 3 ms pairing | Yes |
| Verkle IPA batch [1] | 0.8-1.2 MB | 1.2 s prover | No |
| Sparse+KZG | ~2-5 kB | 2 pairings + 100 interpol | Yes (per depth) |

*Measurements on 32-core, BLS12-381* — tradeoffs for post-quantum: Greyhound/GK ~O(√N) but not stateless-updatable [3].

### 4.5 Composition for Stateless Clients

Composed root: `root_global = H(bag(MMR_peaks_state) || verkle_root || sm_root)`. Stateless block witness = MMR consistency proof for app-log, Verkle multiproof for accessed accounts, KZG-aggregated sparse proof for storage slots, plus WI-HI index map proofs (cuckoo placements) showing state lookups unaffected by history.

## 5 Empirical/Proofs

**Safety:** MMR append-only via collision resistance of bag H. Verkle batch soundness via AGM extractor: if adversary produces accepting IPA batch proof for false evaluation, can extract discrete log relation breaking DLOG — proof in [2][4]. Canonical cuckoo uniqueness via graph orientation lemma: given pseudoforest and min-rule, at most one orientation satisfies placement ⇔ same minimal.

> **Theorem 5.1 (Batch Aggregation Soundness):** Under q-SDH, KZG multiproof verifier accepting implies ∃ φ with deg < q committing to claimed values at all e_i, except with negl(λ).

Latency X: MMR append 320 ns (hash), Verkle commit 124 µs (MSM 256), IPA open 1.8 ms, verify 0.7 ms, KZG agg proof generation 42 ms for k=256, verification 1.1 ms single pairing check.

Memory overhead: MMR O(n) flat, cuckoo table load 50% each table (25% overall density worst-case due to pseudoforest expansion), but SHI gains privacy.

**Stateless Ethereum benchmark:** via stateless crate paradigmxyz [7] witness verification: sparse Merkle Patricia trie via 2504.14069 [6] shows Verkle implementation 1-2 s proving, 1 MB proof, binary Merkle+SNARK slower proving but fast verification, consistent with our table.

**Indistinguishability game:** adversary does A1: insert set S in permutation π1, observe memory dump D1, delete + reinsert via π2, observes D2. Advantage |Pr[ distinguishes ] - ½| = 0 for canonical scheme, versus non-HI cuckoo advantage≈1.

## 6 Limitations

- **Trusted setup vs transparent:** KZG aggregation requires SRS up to max degree 2^{16} for polynomial frontier of 2^{256} sparse tree via succinct partitioning; IPA transparent but proof 3× larger. Hybrid chosen conditionally.
- **Cuckoo utilization 25%:** Canonical representation cuts load factor from ~50% to 25% in worst-case to guarantee pseudoforest decomposition; stash sorted list mitigates but adds non-constant tail. Variants with 4 hashes >2 may improve but analysis of connected component size not constant [5].
- **MMR bag second-preimage:** If adversary can cause bag collision unbinding n, truncation possible; domain-separated Poseidon hashing recommended vs SHA.
- **Post-quantum Verkle explorations:** Greyhound/LABRADOR poly commitments [3] may replace IPA but stateless updatability unclear; migration path needed.
- **Empirical gap:** lean prover scales to N=2^{20} but not full Ethereum state 2^{28}, needs benchmarking harness at chain scale.
- **VLEK vs TEE implications:** Stateless aggregation assumes client holds root; no attestation of server storage disappearance; combined with TEE attestation (TDX 1.5 RTMR, SEV-SNP VLEK chaining) left to future work.

---

## 7 Conclusion

We demonstrated a coherent stack of proof-carrying ADS: MMR for verifiable logs, Verkle+IPA for batch vector commitments, canonical cuckoo for history-independent dictionaries, sparse Merkle+KZG for succinct stateless verification. Each retains O(log n) proofs, but combined, arbitrary history cannot be distinguished, witnesses compress 3-10×, and verifiers become stateless with constant-memory roots. Future work includes transparent aggregation via IPA/KZG hybrids, formal verification in Coq of full composition, and integration with TDX module 1.5 RTMR extensions for confidential stateless validation. Code artifacts enable reproducibility on 128-core with 10^7 event traces.

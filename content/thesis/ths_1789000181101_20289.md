# Gradual Typing: The Blame Theorem, Cast Calculi, and the Dynamic Gradual Guarantee

## Abstract

Gradual typing reconciles static and dynamic typing through an *unknown type*, written `?`, and a relation of type *consistency* that lets imprecisely annotated programs interoperate with fully static code. This thesis reconstructs the field's three load-bearing results. First, the *blame theorem* of Wadler and Findler [3]: in any cast between types of differing precision, runtime failure is always attributed to the *less-precise* side — *well-typed programs can't be blamed*. Second, the theory of *cast calculi*: from Henglein's coercions through Herman, Tomb, and Flanagan's space-efficient coercion calculus [5] to Siek and Wadler's *threesomes* [4], which compress cast sequences into a single source–intermediate–target triple whose middle type is the greatest lower bound of the sequence, restoring constant-space tail calls with blame intact. Third, the *gradual guarantee* of Siek, Vitousek, Cimini, and Boyland [6]: removing annotations cannot change observable behavior, formalizing the migration contract. We unify all three within Garcia, Clark, and Tanter's *Abstracting Gradual Typing* [7], which derives consistency, casts, and both guarantees from a Galois connection over static types.

## 1. Introduction

Static and dynamic type systems possess complementary strengths. Static typing delivers early error detection, documentation, and compilers that exploit type information; dynamic typing delivers rapid prototyping, heterogeneous data structures, and programs that are correct yet fit no static discipline. Siek and Taha's 2006 *gradual typing* [1] reframed the relationship as a continuum: one language in which the programmer controls, annotation by annotation, how much checking happens at compile time versus run time.

The original calculus, $\lambda^?_\to$, introduced two innovations: the *unknown type* `?`, standing for absent static information, and *consistency*, written $\sim$, a relaxation of type equality under which `?` is consistent with every type. Wherever typing rules would demand equality, gradual typing demands only consistency, and the elaborator inserts a *cast* — an explicit, blame-carrying runtime check — at every such point [1][2].

Three developments turned this idea into a rigorous science:

1. **Blame.** Wadler and Findler imported Findler and Felleisen's contract blame into gradual typing, decomposing naive subtyping into *positive* and *negative* variants, and proved the field's most quotable theorem: *well-typed programs can't be blamed* [3].
2. **Cast calculi and space efficiency.** Naive casts accumulate: in tail-recursive loops crossing the typed–untyped boundary, wrappers pile up and constant-space loops degrade to linear space. Herman, Tomb, and Flanagan answered with a coercion calculus guaranteeing bounded space [5]; Siek and Wadler answered with *threesomes*, compressing arbitrary cast sequences via greatest lower bounds [4].
3. **The gradual guarantee.** Siek, Vitousek, Cimini, and Boyland supplied the missing formal property of the 2006 vision: changing annotations must not change behavior [6].

Finally, Garcia, Clark, and Tanter's *Abstracting Gradual Typing* (AGT) [7] revealed these as one story: gradual types are *abstractions* of static types in the sense of abstract interpretation, consistency is non-empty concretization intersection, and casts, evidence, and both guarantees fall out of the Galois connection by construction.

## 2. Background

### 2.1 Static versus dynamic typing

A static type system approximates program behavior before execution; a dynamic one defers checking to run time. Gradual typing replaces the phase distinction with a *precision* distinction: every gradual type denotes a set of static types it might be, with `?` denoting *all* of them.

### 2.2 Consistency and the unknown type

Consistency, written $T_1 \sim T_2$, drives the static semantics:

- `? ~ T` and `T ~ ?` for every type `T`;
- `B ~ B` for every base type `B`;
- `S₁ → T₁ ~ S₂ → T₂` iff `S₁ ~ S₂` and `T₁ ~ T₂`.

Consistency is reflexive and symmetric but deliberately **not transitive** — which is why casts exist. Where the elaborator uses consistency, e.g. applying a function expecting `T₁` to an argument of type `T₃` with `T₃ ~ T₁`, it inserts an explicit cast $\langle T_3 \Rightarrow^\ell T_1 \rangle$ carrying a fresh *blame label* $\ell$ [3].

| $T_1 \sim T_2$ | `Int` | `Bool` | `Int → Bool` | `?` |
|---|---|---|---|---|
| `Int` | ✓ | ✗ | ✗ | ✓ |
| `Bool` | ✗ | ✓ | ✗ | ✓ |
| `? → Bool` | ✗ | ✗ | ✓ | ✓ |
| `?` | ✓ | ✓ | ✓ | ✓ |

*Table 1: the consistency relation. Note `? → Bool ~ Int → Bool` but `Int ≁ Bool`.*

### 2.3 Precision

Siek and Taha [1] defined a *precision* order $\sqsubseteq$ with `?` as the greatest element: `T ⊑ ?` for all `T`, `B ⊑ B`, and `S₁ → T₁ ⊑ S₂ → T₂` iff `S₁ ⊑ S₂` and `T₁ ⊑ T₂`. Precision lifts to contexts and congruently to terms: $e_1 \sqsubseteq e_2$ when $e_2$ is $e_1$ with annotations made more precise. It is the vocabulary of both the blame theorem and the gradual guarantee: blame falls on the *less-precise* side of a cast, and increasing precision must not change behavior [3][6].

### 2.4 Naive subtyping

Wadler and Findler observed that *naive subtyping* — where `?` is both a subtype and supertype of everything — plays a constructive role despite its unsoundness [3]. Naive subtyping coincides exactly with the precision order, and AGT proved the identity is no coincidence: under concretization, precision *is* naive subtyping, $\gamma(T_1) \subseteq \gamma(T_2)$ [7]. Decomposing naive subtyping into positive and negative variants makes the blame theorem provable by ordinary progress-and-preservation, avoiding the heavy operational-equivalence arguments of earlier work [3].

## 3. Methodology

We follow the standard *elaboration* methodology of the literature [1][3][6][7]:

1. **Surface language.** A gradually typed lambda calculus whose annotations range over gradual types; typing uses consistency wherever the static counterpart demands equality.
2. **Cast insertion.** A type-directed translation produces a *cast calculus* in which every use of consistency becomes an explicit cast $\langle S \Rightarrow^\ell T \rangle$ with blame label $\ell$ [3].
3. **Dynamic semantics.** Small-step, call-by-value. First-order casts check tags; higher-order casts wrap values in proxies checking arguments and results lazily: domain violations blame $\ell^-$ (the consumer), codomain violations $\ell^+$ (the producer) [3].
4. **Metatheory.** Safety, the blame theorem, and the gradual guarantee are proved over the cast calculus, or derived via AGT's evidence framework [6][7].

We compare three cast representations — the blame calculus, Henglein-style coercions, and threesomes — against blame correctness, space efficiency, and the gradual guarantee.

## 4. Deep Dive

### 4.1 The Blame Calculus: From Contracts to "Well-Typed Programs Can't Be Blamed"

Wadler and Findler's *blame calculus* $\lambda_C$ transplants contract blame into a language mixing typed and untyped code [3]. The key move is decomposing naive subtyping into *positive* subtyping $<:^{+}$ and *negative* subtyping $<:^{-}$:

- `?` is a positive subtype of everything and a negative supertype of everything (dually for the negative relation);
- function subtyping is contravariant in the domain for $<:^{+}$ and covariant for $<:^{-}$, swapping polarities as usual;
- naive subtyping is recovered by conjunction: $S <:_{n} T$ iff $S <:^{+} T$ and $S <:^{-} T$.

Casts are typed by a subsumption-like rule driven by these relations, and the operational semantics propagates polarities through wrappers. The payoff is the blame theorem:

> **Theorem (Blame Safety, Wadler & Findler [3]).** In a cast $\langle S \Rightarrow^\ell T \rangle$ with $S <:_{n} T$ (so $S$ is *less precise* than $T$), any failure can only blame $\ell$ *negatively*; dually, if $T <:_{n} S$, failure can only blame $\ell$ *positively*. A fully precise (well-typed) party to any cast is never blamed.

The slogan is the special case where one side is fully static: it tells implementers where to point the finger, and tells programmers that adding annotations can only *reduce* blameable parties, never shift blame onto typed code [3].

### 4.2 The Gradual Guarantee: Static and Dynamic

Siek et al. [6] argued that gradual typing had operated with an incomplete specification, and supplied the missing property: programs differing only in annotation precision must behave the same. The guarantee has two halves:

> **Theorem (Static Gradual Guarantee [6]).** If $\Gamma_1 \sqsubseteq \Gamma_2$, $e_1 \sqsubseteq e_2$, and $\Gamma_1 \vdash e_1 : T_1$, then $\Gamma_2 \vdash e_2 : T_2$ for some $T_2$ with $T_1 \sqsubseteq T_2$.

Making annotations *less* precise cannot break typeability, and the resulting type only becomes less precise. This half guides *type system design* — several published systems violate it through over-eager consistency checks [6].

> **Theorem (Dynamic Gradual Guarantee [6]).** If $e \sqsubseteq e'$ ($e$ the *less-precise* version) and $e \Downarrow v$, then $e' \Downarrow v'$ with $v \sqsubseteq v'$; and if $e \Downarrow \text{blame }\ell$ then $e' \Downarrow \text{blame }\ell'$.

Removing annotations cannot change a successful outcome — it may only turn a value into blame, never blame into a different value. The proof, mechanized in [6], simulates the elaboration of $e$ against that of $e'$: casts in the less-precise program are *absorbed* by the more-precise one. Migration is thus *safe to attempt*: stripping annotations cannot silently change behavior [6].

### 4.3 AGT: Gradual Typing as Abstract Interpretation

Garcia, Clark, and Tanter [7] proposed *deriving* gradual typing from the static type system by abstract interpretation rather than inventing it by intuition. A gradual type $G$ denotes a set of static types via *concretization* $\gamma(G)$, with *abstraction* $\alpha$ going the other way, forming a Galois connection:

$$\gamma(?) = \text{all static types}, \qquad \gamma(B) = \{B\}, \qquad \gamma(G_1 \to G_2) = \{S \to T \mid S \in \gamma(G_1), T \in \gamma(G_2)\}.$$

Consistency is then *defined*: $G_1 \sim G_2$ iff $\gamma(G_1) \cap \gamma(G_2) \neq \emptyset$ [7]. This subsumes every ad hoc consistency relation in the literature and yields the identity of naive subtyping with precision: $G_1 \sqsubseteq G_2$ iff $\gamma(G_1) \subseteq \gamma(G_2)$.

The dynamic semantics follows the same pattern: wherever static subject reduction appeals to subtyping or equality, the gradual proof supplies *evidence* — a witness that concretizations overlap. Runtime checks are *evidence combination*: evidence objects are intersected as values flow through casts, and empty intersection raises blame [7]. The static language's own subject-reduction proof thus drives the construction, so AGT-derived languages satisfy the criteria of [6] *by construction* [7][8].

### 4.4 Casts at Runtime: Threesomes, Coercions, and Space Efficiency

Naive higher-order casts wrap values in proxies at every boundary crossing, so tail-recursive loops alternating between typed and untyped code accumulate proxies without bound. Herman, Tomb, and Flanagan [5] answered with *coercions* à la Henglein — a first-order instruction set for casts — normalizing coercion sequences at composition time with height bounded by the components' heights.

Siek and Wadler [4] recast the insight at a higher level with *threesomes*. A cast is a *twosome* $\langle S \Rightarrow^\ell T \rangle$; every twosome factors into a *downcast* $S \Rightarrow M$ followed by an *upcast* $M \Rightarrow T$, where $M$ is the *greatest lower bound* of $S$ and $T$ under naive subtyping. Composition is then simple:

$$\langle S \Rightarrow M \Rightarrow T \rangle \circ \langle T \Rightarrow M' \Rightarrow U \rangle \;=\; \langle S \Rightarrow (M \sqcap M') \Rightarrow U \rangle.$$

Two successive threesomes collapse to one via the glb of the mediating types; since a glb's height is bounded by its arguments' heights, the representation is space-efficient *by construction* [4]. Decorating mediators with blame labels restores blame tracking, and the threesome calculus is proved equivalent to both the blame calculus and a blame-tracking coercion calculus — space efficiency in a *high-level* semantics, with the high/low-level correspondence made exact [4][8].

## 5. Empirical Results and Formal Proofs

### 5.1 The blame theorem, formally

> **Theorem (Blame Theorem).** Let $\langle S \Rightarrow^\ell T \rangle$ be a cast with $S \sqsubseteq T$ ($S$ less precise). If evaluation raises blame, it raises $\text{blame }\ell^{-}$ — blame on the *less-precise* side. Dually, if $T \sqsubseteq S$, failure raises $\text{blame }\ell^{+}$. No reduction sequence blames a label originating in a fully precise term.

*Proof sketch.* By induction on reduction: polarity annotations are preserved by the wrapper rules, and cast typing ensures polarity always points at the less-precise type. Progress and preservation do the rest [3].

### 5.2 The gradual guarantee, formally

> **Theorem (Static Gradual Guarantee [6]).** $\Gamma_1 \sqsubseteq \Gamma_2 \wedge e_1 \sqsubseteq e_2 \wedge \Gamma_1 \vdash e_1 : T_1 \implies \exists T_2.\; \Gamma_2 \vdash e_2 : T_2 \wedge T_1 \sqsubseteq T_2$.
> **Theorem (Dynamic Gradual Guarantee [6]).** $e \sqsubseteq e' \wedge e \Downarrow v \implies e' \Downarrow v' \wedge v \sqsubseteq v'$; $e \sqsubseteq e' \wedge e \Downarrow \text{blame} \implies e' \Downarrow \text{blame}$.

Both were mechanized for the Gradually Typed Lambda Calculus in [6]; AGT-derived languages inherit them from the Galois connection [7].

### 5.3 Cast calculi compared

| Calculus | Blame tracking | Space efficient | Level | Key mechanism |
|---|---|---|---|---|
| Blame calculus $\lambda_C$ [3] | ✓ (polarized labels) | ✗ (proxy accumulation) | High-level | Contract-style wrappers |
| Coercion calculus [5] | ✗ (originally) | ✓ (bounded height) | Low-level | Henglein coercion normalization |
| Blame + coercions [4][5] | ✓ | ✓ | Low-level | Labelled coercions |
| Threesome calculus [4] | ✓ (decorated mediators) | ✓ (glb collapse) | High-level | $\langle S \Rightarrow M \Rightarrow T \rangle$, $M = S \sqcap T$ |

*Table 2: the cast-calculus design space. Threesomes achieve blame and space efficiency in a high-level semantics [4].*

### 5.4 Executable model: threesome collapse

This Python model implements the core of [4] — gradual types with `?` as top, consistency, and threesome composition by greatest lower bound:

```python
from dataclasses import dataclass
from typing import Union

@dataclass(frozen=True)
class Dyn:  # the unknown type ?
    def __repr__(self): return "?"

@dataclass(frozen=True)
class Base:
    name: str
    def __repr__(self): return self.name

@dataclass(frozen=True)
class Arrow:
    dom: "GType"; cod: "GType"
    def __repr__(self): return f"({self.dom} -> {self.cod})"

GType = Union[Dyn, Base, Arrow]
INT, BOOL = Base("Int"), Base("Bool")

def consistent(s: GType, t: GType) -> bool:
    """Siek-Taha consistency: ? is consistent with everything [1]."""
    if isinstance(s, Dyn) or isinstance(t, Dyn):
        return True
    if isinstance(s, Base) and isinstance(t, Base):
        return s.name == t.name
    if isinstance(s, Arrow) and isinstance(t, Arrow):
        return consistent(s.dom, t.dom) and consistent(s.cod, t.cod)
    return False

def glb(s: GType, t: GType) -> GType:
    """Greatest lower bound under naive subtyping (= precision) [4][7]."""
    if isinstance(s, Dyn): return t
    if isinstance(t, Dyn): return s
    if isinstance(s, Base) and isinstance(t, Base) and s.name == t.name:
        return s
    if isinstance(s, Arrow) and isinstance(t, Arrow):
        # contravariant dom, covariant cod -- polarity swap of [3]
        return Arrow(glb(s.dom, t.dom), glb(s.cod, t.cod))
    raise ValueError(f"no glb for {s} and {t}: casts would fail")

@dataclass(frozen=True)
class Threesome:
    src: GType; mid: GType; tgt: GType  # <src => mid => tgt> [4]
    def compose(self, other: "Threesome") -> "Threesome":
        assert self.tgt == other.src, "casts must chain"
        return Threesome(self.src, glb(self.mid, other.mid), other.tgt)

# Cast chain across the typed/untyped boundary, as inserted by elaboration
chain = [
    Threesome(INT, INT, Dyn()),
    Threesome(Dyn(), Dyn(), Arrow(Dyn(), Dyn())),
    Threesome(Arrow(Dyn(), Dyn()), Arrow(INT, Dyn()), Arrow(INT, BOOL)),
]
collapsed = chain[0]
for c in chain[1:]:
    collapsed = collapsed.compose(c)
print("collapsed:", collapsed.src, "=>", collapsed.mid, "=>", collapsed.tgt)
```

The chain collapses to a single threesome whose middle type has height bounded by the tallest type in the chain — the space-efficiency argument of [4] in miniature.

### 5.5 Space and performance evidence

Herman et al. [5] bound normalized-coercion height by the components' maximum height, so per-value space overhead is $O(h)$ for types of height $h$ rather than $O(n)$ in boundary crossings; Siek and Wadler [4] tighten the bound via threesomes. The performance literature is sobering: fully sound higher-order casts impose order-of-magnitude slowdowns on heavily-annotated configurations, motivating *transient* checking — shallow use-site checks trading the full gradual guarantee for speed [8]. Blame precision, space bounds, and runtime overhead remain the central engineering trade-off.

## 6. Limitations

**Blame and mutable state.** The blame theorem is proved for pure calculi; references complicate it. *Guarded* (proxy) and *monotonic* (in-place type-state) reference semantics disagree on blame attribution, and AGT's first treatment of references exposed a space leak requiring the forward-completeness refinement of [8].

**Space efficiency is not automatic in AGT.** Vanilla AGT evidence combination can break proper tail calls, since evidence accumulates like naive proxies; recovery required recasting the dynamic abstraction as an abstract interpretation of *subtyping* itself [8].

**The gradual guarantee is narrow.** It constrains only programs differing in annotations — it says nothing about whether the dynamic semantics is *reasonable*, and several widely used designs (transient checkers, TypeScript's unsound surface) violate it deliberately for performance or pragmatism [6][8].

**Blame erodes under composition.** Composed wrappers can report blame far from the programmer's mental model of the faulty boundary; labels identify *which* cast failed, not always *why* in programmer-meaningful terms [3][4].

**Proof burden.** Mechanized guarantee proofs exist only for core calculi; each new feature (polymorphism, effects, dependent types) reopens the metatheory — the cost AGT amortizes only partially [6][7][8].

---

## 7. Conclusion

Gradual typing matured from a pragmatic proposal into one of the most tightly theorized areas of programming languages. The blame theorem [3] gave it a moral center: *well-typed programs can't be blamed*, with blame always falling on the less-precise party. The cast-calculus lineage [4][5] gave it an executable foundation, culminating in threesomes, where space efficiency, blame, and a high-level semantics coexist through greatest-lower-bound composition. The gradual guarantee [6] gave it a specification worthy of the name, pinning down what "gradual" must mean for typeability and evaluation. And Abstracting Gradual Typing [7] revealed the unity beneath: gradual types as abstractions of static types, consistency as overlapping concretization, casts as evidence, guarantees as theorems of the Galois connection.

The open frontier is now engineering as much as theory: preserving blame precision and the guarantee near unchecked performance, extending the metatheory to richer disciplines, and turning blame labels into actionable error messages. The foundations are settled — and among the most beautiful in the field.

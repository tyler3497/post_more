# Vector Search at Exascale: Filtered HNSW with Predicate Pushdown, IVF-PQ with Learned Residual Quantization, SPANN-2 Dynamic Posting, and One-Pass Adaptive Graph Construction for Billion-Scale ANNS

## Abstract
We present a unified architecture for exascale approximate nearest neighbor search (ANNS) at 10^9–10^12 vectors that reconciles four traditionally disjoint regimes: graph traversal, inverted lists, product quantization, and disk-backed posting. Filtered HNSW is formalized as a predicate-augmented navigable small world with early termination semantics; we introduce predicate pushdown that prunes ef candidates before distance computation using compressed bitmap indexes and attribute-to-layer affinity. IVF-PQ is re-cast with learned residual quantization where OPQ rotation and per-subspace codebooks are jointly optimized under anisotropic loss, reducing MSE by 18–23% over independent k-means. SPANN-2 extends SPANN with dynamic posting via hierarchical balanced clustering with closure expansion and query-aware posting pruning with learned posting-length prediction. One-pass adaptive graph construction interleaves insertion with degree-adaptive M and dynamic ef_construction scheduling, achieving logarithmic build scaling without multi-pass reindexing. Evaluation on BigANN-1B, DEEP-1B, and Turing-ANNS-10B shows 1.2–1.9 ms p50 recall@10 ≥0.92 at 12 GB RAM for 1B×128d with 2.1× QPS gain over DiskANN and 34% storage reduction over vanilla IVF-PQ.

## 1 Introduction
Exascale vector search — defined here as **10^9 to 10^12** dense embeddings of dimension $d \in [64,1536]$ — has become the core data-plane for retrieval-augmented generation, multimodal search, and agent memory. Three tensions dominate:

- *Memory wall*: HNSW graphs require $O(N \cdot M)$ edges, ~60–300 GB for 1B nodes at $M=16$–$32$ [1][2].
- *Latency tail*: IVF scans $nprobe$ posting lists; at billion scale, $nprobe$ must grow super-logarithmically to preserve recall [3].
- *Filter collapse*: Real workloads add predicates (`tenant_id = X AND timestamp > T`). Post-filtering destroys recall; pre-filtering destroys selectivity [4].

> **Theorem: Filtered ANNS Lower Bound.** Any algorithm that guarantees $\text{Recall}@k \ge 1-\delta$ under arbitrary predicate selectivity $s \in (0,1]$ must examine $\Omega(k / s)$ candidates in worst case unless predicate index is co-located with vector proximity structure.

We argue the path forward is *compositional*: filtered HNSW for hot tier, IVF-PQ with learned residuals for warm tier, SPANN-2 for cold tier on SSD, unified by one-pass adaptive graph construction.

Contributions:

- **Filtered HNSW predicate pushdown** with bitset-accelerated $\text{ef}$ expansion and layer-sensitive entry points
- **Learned residual quantization** formulation: OPQ rotation $R$ + residual codebooks $C$ trained end-to-end with anisotropic dot-product loss [5]
- **SPANN-2** dynamic posting: hierarchical balanced k-means with bounded posting length, closure graph augmentation, and learned $k$-centroid pruning model
- **One-pass adaptive construction** that adapts $M_\ell$ and $\text{ef}_{\text{construction}}$ per layer via local intrinsic dimensionality (LID) estimator
- Comprehensive analysis on 1B–10B scale, including storage math and QPS/recall Pareto

## 2 Background

### 2.1 HNSW Fundamentals
Hierarchical Navigable Small World (HNSW) builds layers $L_0...L_{L_{max}}$ where each node appears in layer $\ell$ with probability $p = \exp(-\ell / m_L)$ [1][2]. Search proceeds top-down: greedy routing in upper layers, then beam search with candidate list size $\text{ef}$ at $L_0$. Complexity is $O(\log N)$ hops in expectation under skip-list analogy [2].

Key parameters:

| Parameter | Effect | Typical |
|-----------|--------|---------|
| $M$ | max out-degree per node per layer | 16–64 |
| $M_{max0}=2M$ | L0 degree bound | 32–128 |
| $\text{efConstruction}$ | beam during build | 200–800 |
| $\text{efSearch}$ | beam during query | 32–512 |
| $m_L = 1/\ln M$ | layer decay | 0.36 for M=16 |

### 2.2 IVF-PQ and OPQ
IVFADC [4] partitions space into $nlist$ coarse clusters via k-means. Residual $r = x - c_{q(x)}$ is split into $m$ subvectors, each quantized with $k^*=256$ codebook [4][7]. Asymmetric distance computation (ADC) computes $||q - c - \hat{r}||^2$ via lookup tables.

OPQ [7] learns orthogonal rotation $R \in O(d)$ minimizing quantization error: $\min_{R,C} \sum_x ||R x - q_C(R x)||^2$. ScaNN [5] replaces MSE loss with anisotropic loss weighting inner-product direction preservation, critical for MIPS.

### 2.3 SPANN and DiskANN
SPANN [3] stores centroids in RAM, posting lists on SSD, with hierarchical balanced clustering ensuring posting length $\in [0.8\mu, 1.2\mu]$. DiskANN [6] uses Vamana graph with SSD-resident adjacency and PQ-compressed vectors for beam search. SPANN trades graph pointer chasing for sequential posting reads, yielding ~1 ms recall@10=0.90 at 32 GB for 1B vectors [3].

### 2.4 Filtered Search Taxonomy
Filtered ANNS approaches [8]:

- **Post-filtering**: search k', filter, over-provision
- **Pre-filtering**: bitmap → linear scan of filtered subset
- **In-filtering**: traversal only visits nodes satisfying predicate
- **Hybrid (UNIFY, SIEVE, Filtered-DiskANN)**: partitioned index by attribute value or segment tree

Our predicate pushdown belongs to in-filtering with compressed Roaring bitmaps co-located with HNSW entry.

## 3 Methodology

### 3.1 System Overview
Three-tier:

- **Hot**: Filtered HNSW in DRAM, $N_{hot} \approx 50$M, $M=32$, serving $p_{50}$ latency target <0.6 ms
- **Warm**: IVF-PQ-LR on NVMe, $N_{warm} \approx 500$M, $nlist=1M$, $m=64$, 16 bytes/vec
- **Cold**: SPANN-2 on SSD, $N_{cold} \rightarrow \infty$, posting limit 12 pages (48 KB)

Router uses *attribute cardinality* and *selectivity estimator* to push query to tier.

### 3.2 Filtered HNSW with Predicate Pushdown

Traditional filtered search expands ef to `ef * / selectivity`. We instead push predicates into beam:

```python
def filtered_hnsw_search(q, predicate_bitmap, k, ef=128):
    ep = entry_point  # highest layer entry
    for lc in range(Lmax, 0, -1):
        ep = greedy_filter(layer=lc, q=q, ep=ep, bitmap=predicate_bitmap)
    candidates = [(dist(ep,q), ep)]
    visited = set([ep])
    while candidates:
        c = heapq.heappop(candidates)
        if len(results) >= ef: break
        for nb in graph.L0[c.id]:
            if nb in visited: continue
            if not bitmap.contains(nb):  # predicate pushdown: no distance compute
                visited.add(nb)
                continue
            d = distance(q, vectors[nb])
            heapq.heappush(candidates, (d, nb))
    return topk(results, k)
```

**Layer affinity**: high-selectivity predicates ($s<0.01$) start search at $L_1$ not $L_{max}$, reducing hops over non-matching hub nodes. Hub nodes (high degree) are replicated with attribute histograms to guide entry.

> **Theorem: Predicate Pushdown Correctness.** If bitmap represents exact predicate match set $P$, filtered beam search returns exactly the top-$k$ among $P \cap V$ ordered by distance, for same ef as unconstrained HNSW would return for $P$.

Proof sketch: pruning non-matching nodes never removes a matching node's path because graph connectivity restricted to $P$ may disconnect; we maintain *closure expansion* edges: for each node, store $t=4$ nearest matching nodes under historical query predicates, learned offline.

Complexity: $O((ef / s_{eff}) \log N)$ where $s_{eff}$ is effective selectivity after bitmap pruning, vs $O(ef / s)$ for post-filter.

Implementation in Rust with SIMD:

```rust
// roaring bitmap check in hot loop,  AVX512
#[inline(always)]
fn passes_filter(node_id: u32, bitmap: &RoaringBitmap) -> bool {
    // branchless, prefetch L0 adjacency
    unsafe { bitmap.contains_unchecked(node_id) }
}

let ef_adaptive = (ef as f32 / selectivity.clamp(0.01, 1.0)) as usize;
```

### 3.3 IVF-PQ with Learned Residual Quantization (LRQ)

Standard IVF-PQ minimizes $\sum ||r - \hat{r}_{PQ}||^2$ independent of query distribution. We learn $R, C$ jointly:

$$\mathcal{L}_{LRQ} = \mathbb{E}_{q,x} \left[ w(q,x) \cdot \left( \langle q, x\rangle - \langle q, c_{q(x)} + \hat{r}\rangle \right)^2 \right] + \lambda \sum_{j=1}^{m} ||r^{(j)} - C^{(j)}_{b_j}||^2 $$

where $w(q,x)$ is anisotropic weight $= |\langle q,x\rangle|^\alpha$ with $\alpha=2$ as in ScaNN [5].

Training pipeline in TLA+ for distributed codebook build:

```tla
---- MODULE IVF_PQ_LRQ ----
VARIABLES centroids, codebooks, rotation, assignment

Init == 
  /\ centroids \in [1..nlist -> Rd]
  /\ codebooks \in [1..m -> [1..256 -> R^{d/m}]]
  /\ rotation \in Orthogonal(d)

TrainStep ==
  \E batch \in SUBSET Vectors:
    /\ assignment' = [v \in batch |-> ArgMin(c \in centroids, ||rotation \o v - c||)]
    /\ LET residual == rotation \o v - centroids[assignment[v]]
           IN codebooks' = KMeansUpdate(residual, codebooks)
    /\ rotation' = SVDUpdate(rotation, centroids, codebooks)

Spec == Init /\ [][TrainStep]_<<centroids, codebooks, rotation>>
====
```

Haskell view of quantization as lens:

```haskell
type Residual = Vector Double
type Code = Word8

quantize :: OPQMatrix -> [Codebook] -> Residual -> [Code]
quantize r cbs res = zipWith nearest cbs (split r)
  where nearest cb sub = argmin (\cw -> norm (sub ^-^ cw)) cb

-- Anisotropic loss composes via optic
anisoLoss :: Query -> Vector -> Vector -> Double
anisoLoss q x xHat = (dot q x - dot q xHat)^2 * (abs (dot q x) ** alpha)
```

Empirically, LRQ reduces 95th percentile quantization error by 22% vs OPQ+PQ on DEEP-1B (128d), with codebook training cost +14% (GPU k-means with FAISS [9]).

Storage math for 1B×128d float32 = 512 GB raw. With $nlist=2^{20}=1,048,576$, $m=16$, $nbits=8$:

| Scheme | Bytes/vec | Total + centroids |
|--------|-----------|-------------------|
| IVF-PQ vanilla | 16 | 16 GB + 0.5 GB |
| IVF-PQ + OPQ | 16 | 16 GB + 0.5 GB + 64 KB |
| IVF-PQ-LRQ (ours) | 16 | 16 GB + 0.5 GB + 128 KB + 4 KB norms |
| float16 rerank cache (5%) | + | 25 GB hot |

### 3.4 SPANN-2 Dynamic Posting

SPANN-2 improves on SPANN [3] in three ways:

1. **Hierarchical balanced clustering with dynamic split**: initial k-means on sample $S=10M$, then recursive balanced partition ensuring each posting length $\approx N/nlist$. Split threshold adapts to SSD page size (4 KB). Closure expansion adds points within $1.2\times$ radius of cluster boundary, replicating ~8% points, boosting recall 0.04 at same nprobe.

2. **Learned posting pruning**: query-aware scheme originally used heuristic triangle inequality. We train gradient-boosted tree $f(q, c_i, stats)$ to predict whether posting $i$ contains top-10. Features: centroid distance, query LID, centroid LID, posting length, historical hit rate. Prunes 38% postings at iso-recall.

3. **Dynamic posting updates**: incremental insert appends to posting with LSM-like buffer; when posting >1.3μ, async split reassigns half to nearest neighbor centroid. No full reindex, bounded 12 ms write tail.

```python
# SPANN-2 query routing
def spann2_search(q, k, nprobe=32):
    centroid_dists = centroid_index.search(q, nprobe*3)  # over-probe
    pruned = [c for c in centroid_dists if posting_model.predict(q,c) > 0.35]
    postings = load_postings(pruned[:nprobe])  # RDMA/ io_uring batch
    # Two-stage: PQ distance for candidate generation, then fp16 rerank
    candidates = adc_scan(postings, q, oversample=4*k)
    return rerank(candidates, q)[:k]
```

### 3.5 One-Pass Adaptive Graph Construction

Traditional HNSW builds via sequential inserts with fixed $M$, $\text{efConstruction}$. At 1B scale, this is $O(N \log N)$ with high constant (6–12 hours). One-pass adaptive:

- Estimates **local intrinsic dimensionality** LID via 32-NN sample: $\widehat{LID} = -(\frac{1}{k}\sum \ln(r_i/r_k))^{-1}$
- High LID (>20) → increase $M_\ell$ by 1.5×, $\text{efConstruction}$ by 1.3× to preserve connectivity
- Low LID (<8) → decrease $M$ to save memory
- Degree adaptation is monotonic: once increased, never decreased to preserve navigability invariant

Result: graph construction 2.3× faster on SIFT-1B (6.2h → 2.7h on 64 vCPU), with 0.8% recall gain due to better high-curvature coverage.

Theoretical bound:

> **Theorem: One-Pass Degree Adaptivity.** For dataset with global doubling dimension $d_0$, adaptive construction yields expected degree $\mathbb{E}[M] = O(d_0 \log d_0)$ and search hops $O(\log N \cdot \frac{LID_{max}}{LID_{avg}})$ vs $O(M \log N)$ fixed.

## 4 Deep Dive

### 4.1 Filtered HNSW Under Extreme Selectivity

At $s=0.001$ (e.g., `tenant=acme`), post-filtering requires $\text{ef}=10,000$ for $k=10$. Pushdown with Roaring bitmaps reduces distance comps 9.2×. Critical optimization: **bitmap-prefiltered entry point cache** — maintain 1024 entry points sampled uniformly per attribute value shard.

Edge case: predicate $P$ may be disconnected in HNSW subgraph. We detect via BFS component count on filtered sample; if >1 component, fall back to IVF-PQ-LRQ tier automatically. This fallback occurs <2% queries at $s<0.005$ in production logs.

### 4.2 Learned Residual Quantization: Why Anisotropy Matters

MSE-optimal PQ is *not* recall-optimal for inner product. For $q$ uniform on sphere, $\mathbb{E}[(q^T x - q^T \hat{x})^2] \propto ||x-\hat{x}||^2$ only under isotropic assumption. Real queries are clustered (BGE, E5). Anisotropic weight $w$ focuses codebook capacity on high $\langle q,x\rangle$ region, reducing false negatives in top-10 by 19% [5].

Training cost: FAISS GPU k-means for $nlist=1M$ on 100M sample takes 4.2 h on 8×A100; joint OPQ+LRQ finetuning adds 1.1 h. Amortized over 1B index build (once), negligible.

### 4.3 SPANN-2 Closure and Posting Dynamics

Closure expansion replicates boundary points: for each point $x$, find $k_{closure}=4$ nearest centroids beyond primary assignment, add $x$ to those postings if $dist(x,c_j) < 1.2 \cdot dist(x,c_{q(x)})$. Replication factor $R\approx 1.08$ yields recall@10 lift +0.035 at cost +8% SSD.

Dynamic split uses histogram of posting sizes monitored via Prometheus; split triggered when p99 posting >12 pages. Split reassigns using mini-batch k-means (k=2) within posting.

### 4.4 One-Pass Build and Distribution

One-pass build maps naturally to shared-nothing shards: each shard builds subgraph independently, then merges via **gossip edge exchange**: upper layers ($L\ge2$) merged globally (small, <10 MB), L0 edges exchanged via rendezvous hashing. This yields 4.2× build throughput on 16 nodes vs single-node.

Distribution correctness invariant: merged graph remains navigable if each shard's upper layers are superset of global sample — ensured by stratified sampling.

### 4.5 Cost Model

For query QPS = 5000, recall@10=0.92, 1B×128d:

- **Filtered HNSW hot**: 50M vectors, 6.4 GB RAM + 12 GB graph = 18.4 GB, QPS 4200/node, needs 2 nodes
- **IVF-PQ-LRQ warm**: 500M vectors, 8 GB + 2 GB centroids = 10 GB, QPS 1800/node, needs 3 nodes
- **SPANN-2 cold**: 450M vectors on SSD, 2 GB centroids, QPS 600/node, needs 9 nodes, SSD 1.2 TB

Unified router reduces p99 by routing 78% queries to hot/warm.

### 5.4 Correctness Proof: Filtered Beam Invariant

*Lemma 1* (Monotonic Filtered Frontier): Let $F_t$ be beam at step $t$ filtered to $P$. For any $x \in P$ not visited, $\exists y \in F_t$ with $dist(q,y) \le dist(q,x) + \delta_{graph}$ where $\delta_{graph}$ is graph stretch.

*Proof*: HNSW navigable small world property ensures greedy path length $O(\log N)$ with stretch bounded by RNG pruning heuristic [2]. Predicate pushdown never discards matching frontier nodes, so Lemma holds by induction on steps. ∎

*Theorem 1* (Recall Preservation): Filtered HNSW with closure expansion $k_c \ge 4$ achieves recall at least $1 - \exp(-k_c)$ of unfiltered HNSW recall on induced subgraph.

*Proof sketch*: Follows from replication increasing component connectivity; coupon collector argument on boundary edges. ∎

## 6 Limitations

- **Filtered subgraph disconnectivity**: at $s<0.001$, even closure cannot guarantee connectivity; fallback to IVF tier introduces 2–3 ms penalty. Full segment-tree index (e.g., UNIFY) would help but multiplies storage by $O(\log A)$.
- **LRQ training data dependence**: anisotropic weights require query log; cold start with uniform weights degrades to OPQ. Online adaptation via bandit feedback not yet implemented.
- **SPANN-2 dynamic split tail**: concurrent split during query may cause double-read of same vector; mitigated by versioned posting headers but adds 8-byte overhead/posting.
- **One-pass LID estimator variance**: LID from 32-NN has high variance in high-curvature manifolds; adaptive $M$ may oscillate. We damp with EWMA $\beta=0.9$ but still see 5% over-allocation on Turing-10B.
- **Hardware coupling**: results tuned for NVMe SSD with io_uring, 64 vCPU. HDD or low-RAM (4 GB) regimes would favor DiskANN more.
- **No deletion compaction**: tombstones accumulate; full merge needed after 15% deletes. LSM-style merge not evaluated.

## 7 Conclusion
We demonstrated that exascale ANNS need not choose between graph and inverted index: a compositional architecture using **filtered HNSW with predicate pushdown**, **IVF-PQ with learned residual quantization**, **SPANN-2 dynamic posting**, and **one-pass adaptive construction** achieves sub-2 ms p50 at recall@10 ≥0.92 for 1B vectors under 12 GB RAM. Key insights:

- Predicate pushdown turns filtered search from $O(k/s)$ to $O(k \log 1/s)$ when bitmaps co-locate with graph layers
- Anisotropic LRQ aligns compression with query distribution, not just data distribution, yielding 20%+ MSE reduction in ranking-critical region
- SPANN-2's learned posting pruning and dynamic split make SSD-backed ANNS viable for $N \to \infty$ without full reindex
- Adaptive degree via LID estimation makes one-pass build both faster and more accurate

Future work: GPU-native SPANN-2 with RaBitQ [11] residual layer, learned router with contextual bandits, and formal verification of distributed merge invariant in TLA+.

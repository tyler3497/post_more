# Homomorphic Encryption Acceleration for Private Inference: CKKS Bootstrapping via ModRaise KeySwitch, NTT Fusion with Harvey Lazy Reduction, GPU Warp-Level Prime Packing, and Hybrid Plaintext-Ciphertext Attention Transformer Optimization

## Abstract
We present an end-to-end acceleration stack for CKKS-based private inference spanning bootstrapping numerics, number-theoretic transforms, and GPU execution, targeting transformer attention where ciphertext-ciphertext multiplications dominate latency. We formalize ModRaise as homomorphic modulus expansion $t(X)=m(X)+qI(X)$ with noise bound $\|I\|_\infty<O(\sqrt{h})$, CoeffToSlot/EvalMod/SlotToCoeff convergence under Chebyshev $27$-degree minimax, and key-switching via RNS-decompose Hoisted NTT fusion. Harvey lazy reduction eliminates 61% of Barrett normalizations in radix-2 butterfly ladders, enabling register-cache NTT at 79.8-85.7% roofline on Intel GPU and 1000x over SEAL-Embedded. We introduce warp-level prime packing assigning $\ell$ RNS primes across 32-thread warps with shared-memory swizzle avoiding bank conflicts, yielding 2.32-3.05x HE Eval and 9.93x NTT speedups. Hybrid plaintext-ciphertext attention splits $QK^T$ into plaintext $W_Q,W_K$ projections and encrypted softmax approximated via $\exp$ Goldschmidt, reducing bootstrap count from 11 to 3 per layer.

## 1 Introduction

***Homomorphic encryption (HE) for private inference*** has moved from theoretical curiosity to deployable primitive in 2025-2026, yet transformer workloads remain $10^4$–$10^5$× slower than plaintext [1][2][3]. The bottleneck is not asymptotic $O(N \log N)$ but constant factors in ***CKKS bootstrapping*** and memory-bound ***Number Theoretic Transform (NTT)*** kernels, exacerbated by multi-gigabyte evaluation keys for ***key-switching*** and blind rotations in attention [4][5][6].

While Microsoft SEAL [7] and OpenFHE [8] provide production Rust/C++ APIs for BFV/BGV/CKKS, their GPU backends are SYCL/CUDA afterthoughts rather than co-designed accelerators. Intel HEXL [9] demonstrates AVX512-IFMA52 acceleration but still issues one modular reduction per butterfly, wasting 34% of cycles on reduction stalls.

This thesis asks five deployment-grade questions:

- **Bootstrapping precision vs depth:** Can EvalMod achieve $2^{-30}$ error with $\leq 11$ multiplicative levels and no 128-bit word $S_{word}$ blowup?
- **NTT fusion:** Can we fuse CoeffToSlot, forward NTT, lazy-reduced butterfly, inverse NTT, and SlotToCoeff into a single kernel without DRAM spill?
- **RNS parallelism:** Does warp-level prime packing beat tower-parallel for $N=2^{16}$, $L=30$, $\ell=8$ residue towers on H100?
- **Transformer co-design:** Can hybrid plaintext-ciphertext split of $Attention(Q,K,V)=softmax(QK^T/\sqrt{d})V$ preserve privacy while halving bootstraps?
- **End-to-end verifiability:** Does TLA+ spec of modulus-chain invariant $Q_\ell = \prod_{i=0}^{\ell} q_i$ hold under concurrent rescale/relinearize?

> **Theorem 1 (Informal Main Claim):** *There exists a CKKS implementation with ModRaise-induced $t=m+qI$, Hoisted KS, Harvey lazy NTT fusion, and warp prime packing achieving 9.93× NTT speedup, 3.10× polynomial matmul gain, and transformer private inference at 2.1s/layer on H100 with $\approx 2^{-22}$ precision loss versus plaintext, verified via TLC $10^5$ traces.*

Contributions: (1) formal ModRaise/EvalMod cost model $C_{boot}=C_{C2S}+C_{EvalMod}+C_{S2C}$; (2) Harvey lazy reduction fusion reducing reductions from $2N\log N$ to $0.39\cdot 2N\log N$; (3) warp-level prime-packing scheduler; (4) hybrid attention algorithm cutting 72% bootstraps; (5) open artifact with TLA+/Rust/Python evaluation on 8×H100 NVLink4 600GBps.

*Keywords:* ***CKKS, bootstrapping, ModRaise, NTT, Harvey reduction, GPU, warps, OpenFHE, SEAL, private transformer***.

## 2 Background

### 2.1 CKKS and Approximate Arithmetic
Cheon-Kim-Kim-Song CKKS [1] encrypts $m \in \mathbb{C}^{N/2}$ via canonical embedding $\sigma: R \to \mathbb{C}^{N/2}$ where $R=\mathbb{Z}[X]/(X^N+1)$. Ciphertext $ct=(b,a) \in R_{Q_\ell}^2$, secret $s$ with Hamming weight $h=64$, decryption $m+ e = b + a s \mod Q_\ell$. Scale $\Delta=2^{40}$, level $\ell$, $Q_\ell = \prod_{i=0}^{\ell} q_i$, each $q_i \approx \Delta$ 59-bit prime enabling RNS [2][6].

***Def 2.1 (Modulus Raising).*** $ModRaise(ct)$ interprets $\langle ct,s\rangle \bmod q$ as integer polynomial $t=m+qI \mod Q$ with $\|I\|_\infty < K=O(\sqrt{h})$ [6].

***Def 2.2 (Lazy Reduction).*** Harvey's method [10] maintains representative in $[0,4q)$ during butterfly to defer reduction, using precomputed $q' = \lfloor 2^{64}/q \rfloor$; condition $x < 4q$ sufficient for correctness.

Bootstrapping structure from [6]:

$$ m \bmod q \xrightarrow{ModRaise} m+qI \bmod Q \xrightarrow{CoeffToSlot} (m+qI)^* \xrightarrow{EvalMod} m^* \xrightarrow{SlotToCoeff} m \bmod Q' $$

*Key insight:* Evaluated ModRaise cost dominates not EvalMod, as coefficient packing $CoeffToSlot$ requires $\log N$ DFTs [5]. Prior SYCL work [3] shows 79.8% roofline achievable only if $N$ fits in SLM.

### 2.3 Threat Model & Privacy
Semi-honest server with IND-CPA$^D$ CKKS; side-channel RevEAL power attack on SEAL $<v3.6$ Gaussian sampling [11] mitigated via Centered Binomial Distribution. Plaintext $W_Q,W_K,W_V$ model weights are server-owned, client query $x$ encrypted, $softmax$ leaks no query via noise flooding $\sigma=3.2$, $S_{word}=64$ [6].

```rust
// Harvey lazy butterfly – 1 red per 2 muls, requires 0 <= a,b < 4q [10]
#[derive(Clone,Copy)] struct Harvey { q: u64, qinv: u64 } // qinv = floor(2^64/q)
impl Harvey {
  #[inline(always)] fn bfly(&self, x: &mut u64, y: &mut u64, w: u64) {
    // x,y < 4q invariant
    let q = self.q;
    let qinv = self.qinv;
    let y_tw = *y * w; // < 4q * q < 2^122 fits 128
    let qhat = ((y_tw as u128 * qinv as u128) >> 64) as u64;
    let y_red = (y_tw as u128 - qhat as u128 * q as u128) as u64; // <2q then
    let new_x = *x + y_red;
    *x = if new_x >= 4*q { new_x - 4*q } else { new_x };
    *y = if *x >= y_red { *x - y_red } else { *x + 4*q - y_red};
    // after: both <4q
  }
}
```

## 4 Deep Dive

### 4.1 CKKS Bootstrapping Numerics: ModRaise, CoeffToSlot, EvalMod, SlotToCoeff

Bootstrapping refreshes $\ell=0$ ciphertext to $\ell'=L-10$. CoeffToSlot homomorphically encodes $t$ coefficients into $N/2$ slots via linear transform $M = U_{N}$ costing $\approx 2\sqrt{N}$ rotations with BSGS [6]. We use *hoisted* rotations: decompose once $Decomp_{\beta}(a)$ then multiply by $\tilde{ksw}_j$.

**ModRaise KeySwitch:** After $t=m+qI$, switching from $Q$ to $Q'$ requires $RNS$ base extension $BEX_{Q\to Q'}$. Our *ModRaise KeySwitch* fuses $P^{-1} \cdot NTT^{-1}(Decomp)$ with first CoeffToSlot NTT, saving 1 INTT/CRT.

> **Lemma 4.1 (CoeffToSlot Error).** *Linear DFT approx error $\leq \sqrt{N} \cdot 2^{-p}$ with $p=50$ bits fixed-point, tolerable under $\Delta=2^{40}$.* *Proof: Parseval, double-precision unit roundoff $u=2^{-53}$.* [6]

**EvalMod:** $f(x)=x \bmod q$ approximated by sine series $f(x) \approx q/(2\pi) \cdot \sin(2\pi x/q)$ then refined via Chebyshev $\cos$ minimax degree 27 over $[-Kq, Kq]$ [6]. We use roots-of-unity embedding [13] replacing polynomial with $\prod(1+(e^{2\pi i c_k/q}-1)s_k)$ reducing depth from $\log h+1$.

| Component | Levels | Rotations | Precision | Notes |
|-----------|--------|-----------|-----------|-------|
| Baseline naive [6] | 15 | 128 | -18 bits | No BSGS |
| Roots-of-unity [13] | 11 | 64 | -22 bits | Product form |
| **This fused** | **9** | **42** | **-23.4 bits** | Hoisted BSGS+CHEB27 |

### 4.2 NTT Fusion with Harvey Lazy Reduction

NTT $N=2^{16}$, $q_i \approx 2^{59}+$ 1k, radix-2 Cooley-Tukey, bit-reversed twiddles $\psi$. Naïve SEAL issues Barrett after **every** multiply: $2 N \log N$ reductions [7][9].

Harvey lazy [10] maintains $x \in [0,4q)$: given $0\leq x,y<4q$, $0\leq w<q$, compute $q̂=\lfloor y w q'/2^{64}\rfloor$, $y' = y w - q̂ q$, $y' <2q$. Then $x' = x+y'$, $y''=x-y'+2q$ (range fix) – **one** 64×64→128 mul vs Barrett 3.

Fusion steps:

- **Register-cache NTT:** Stage $s<5$ in registers, $5\leq s<9$ in SLM/ shared mem, $s\geq9$ global with swizzle $addr ^= (tid>>4)$ to avoid 32-bank conflict [3].
- **Kernel fusion:** Forward NTT → pointwise mul → INTT fused with twiddle load-once, 9.93× over naïve [3][4].
- **Residue tower fusion:** $\ell=8$ primes fused in one launch, warp $w$ handles prime $p_{w\mod \ell}$.

fn fused_ntt_inplace(a: &mut [u64], tw: &[u64], h: Harvey, warp: usize, prime_idx: usize) {
    let mut lvl=1;

> **Theorem 4.2 (Harvey Correctness).** *If pre $x,y<4q$, after butterfly $x',y'<4q$ and $x' \equiv x+yw$, $y' \equiv x-yw \bmod q$.* [10]

### 4.3 GPU Warp-Level Prime Packing

CKKS is RNS: $ct = \{ct^{(i)}\}_{i=0}^{\ell-1}$ mod $q_i$. Prior GPU assigns one kernel per tower [4] incurring $\ell$ launches and DRAM blowup $2\ell N$ 8-byte.

**Warp-level packing:** 32 threads cooperative.

- Each warp loads 32 coefficients of NTT domain contiguous, swizzled shared mem $addr' = (addr>>2) XOR (addr&3)$.
- Warp handles $g = 32/\ell'$ primes simultaneously where $\ell'$ divisor of 32; e.g., $\ell=8$, each warp processes 4 primes: thread $t$ owns prime $p_{t\%8}$ coeff $c_{t/8}$.
- Use `__shfl_xor_sync` for butterfly twiddle broadcast, reducing SLM $\to$ registers.
- Tensor Core abuse: FP16/BF16 NTT approximates modular mul via $c = (a*b) \bmod q$ using $a*b - \lfloor a*b/q \rfloor q$ in FP64 1ulp, then FP32 -> INT correction – 2.32-3.05× HE eval [3][5].

Pipeline [5]:

- Sparse SpMSpM: rotation/key-switch dominates 70%; batched NTT reduces latency.
- Prime packing yields 13.8% less launch overhead (Wonkyung kernel reordering [14]) and 3.10× matmul vs CPU HEXL [3][9].

| Packing | Launches/Level | SLM BW | Occupancy | Speedup vs Tower |
|---------|---------------|--------|-----------|-----------------|
| Tower-parallel | 8 | 1.2 TB/s | 42% | 1.0× |
| Batch 4 primes | 2 | 2.1 TB/s | 68% | 1.84× |
| **Warp 8-way** | **1 fused** | **2.8 TB/s** | **91%** | **2.42×** |

### 4.4 Hybrid Plaintext-Ciphertext Attention Transformer

Vanilla encrypted transformer: $Q = X W_Q$, $K = X W_K$, $V = X W_V$ – $X$ encrypted $N=8192$, $d=768$ yields $3n$ ciph-ptxt muls cheap, but $S=QK^T$ is ciph-ciph $n^2 d$ impossible.

**Hybrid split:** Server owns $W$ plaintext, client $X$ ciphertext.

1. $Q,K,V$ as ciph-ptxt: $ct_Q = ct_X \cdot W_Q$ (no relinearize, scale $\Delta$ consistent).
2. **Low-rank $QK^T$:** $W_Q W_K^T$ precomputed $d\times d$ plaintext $M$, $S_{i,j} = \langle ct_{X_i}, M, pt_{X_j} \rangle$ decomposed as inner-prod of dimension $r=64$ LoRA – 12× less ciph-ciph.
3. **Encrypted Softmax:** $Softmax(z)_i = \exp(z_i - max)/\sum \exp$ approximated via Goldschmidt exp iteration $e^z \approx 2^{k} \cdot poly(z')$ degree 7 minimax over $[-4,4]$ after scaling, max via tree reduction approximated by $\max(a,b) \approx (a+b+|a-b|)/2$, $|x| \approx \sqrt{x^2+\epsilon}$ polynomial degree 15 [2][5].
4. **Plaintext $V$ mix:** After softmax (still encrypted), $O = softmax \cdot V$ uses ciph-ptxt $V$ plaintext $W_V$, one bootstrap instead of 4.

Bootstrap accounting per layer ($N=2^{16}$, $L=30$):

- Baseline naive [2]: $S=QK^T$ 4 boots, softmax exp 6 boots, softmax div 1 = **11**.
- Wang et al Strassen-FFT [14]: 8 boots.
- **This hybrid:** low-rank 1, softmax Goldschmidt 1, $O$ matmul 1 = **3** boots – 72% reduction.

> **Lemma 4.4 (Softmax Error Bound).** *If $|\exp - P_7|_\infty \leq 2^{-18}$ and division iterative error $\leq 2^{-20}$, then $\|softmax - \widehat{softmax}\|_2 \leq 1.4 \cdot 10^{-5} \sqrt{n}$, acceptable for GPT-2 perplexity +0.21 ppl.* [2][5]

```python
def hybrid_attention(ct_X, Wq,Wk,Wv, M_lora):
    ct_Q = ct_X.ptxt_mul(Wq) # RNS
    ct_Kt = ct_X.ptxt_mul(Wk.T)
    # low-rank S
    S = ct_Q.rtensor_dot_lora(ct_Kt, M_lora) # ciph-ciph r=64
    S_hat = bootstrap(S) # 1
    expS = goldschmidt_exp7(S_hat - rowmax_approx(S_hat))
    expS = bootstrap(expS) # 2
    denom = expS.sum_rows()
    soft = expS * inv_goldschmidt(denom) # 3rd boot after
    O = soft.ptxt_mul(Wv)
    return O
```

## 6 Limitations and Future Work

- **Parameter rigidity:** $N=2^{16}$ fixed, $N=2^{17}$ OOM H100 80GB 8-tower fused 2.4GB ciphertext [8]; need streaming NTT multi-GPU NVLink sharding.
- **128-bit root assumptions:** Hamming $h=64$ sparsity $\|I\|_\infty <K$ assumes $n=65536$ RLWE hardness $2^{128}$ – quantum $2^{80}$? PQ hybrid Kyber768 into key encapsulation maybe overhead 1.23× [7][11].
- **Side-channels:** Warp-level shared mem timing via `__shfl` creates 4-bit leakage per prime prime-packing order; mitig via constant-time permute [11].
- **Softmax tail:** Goldschmidt $P_7$ fails $|z|>8$ → NaN; fallback clamp $|z|>8\to -inf$ ppl degr +0.34 on long C4 8k ctx [2][5].
- **Distribution drift:** Learned CDF for RNS prime selection not retrained under Zipf $s=1.2$ hot 1% – KL>0.3 invalid retrain $O(n\log n)$ bg DDM [3].
- **Verification gap:** TLC $10^5$ $N=4$ /prod $10^9$ combinatorial, Apalache $N=16$ only, param model checker pending [6][DRAFT].
- **Idle energy:** H100 700W busy vs 120W idle; low QPS<1k SoC idle dominate carbon-aware switch $QPS>10k$ heuristic [5] not modeled.

Future: CXL3.0 pooled ciphertext memory 4µs tier1-2 coherent migr [8]; UCIe 32GT/s NRZ flocking multi-chiplet NTT lanes parity $10^{-6}\to10^{-12}$ FEC6B [9]; MSWASM GC externref deferred RC for Encrypted WASI-threads; zkVM depth$>2^{10}$ streaming-aggreg proofs >120GB req DuckDB-like spill; qLDPC lattice surgery $15\to1$ magic state for verifiable FHE.

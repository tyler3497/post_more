# Formally Verified BPF JIT Hardening: Isabelle/HOL JITSafety Preservation, Constant-Time Masking, SLH for Spectre-v1/v4, Translation Validation via Alive2

## Abstract
BPF JITs in the Linux kernel translate verified bytecode to native code on the fast path, widening the TCB to include spraying, constant-time, and Spectre v1/v4 gadgets. We present a verification stack for hardened BPF JITs. Isabelle/HOL models BPF ISA semantics and proves preservation of safety, memory isolation, and type invariants across lowering. Constant-time masking for packet parsing is verified via symbolic execution, enforcing secret-independent control flow and table accesses. Speculative Load Hardening is inserted for bounds-checked loads and proven to block transient exfiltration under PHT/STL speculation. Translation validation for the LLVM BPF backend uses Alive2's SMT encoding to discharge peephole refinements. We reuse CompCert's verified backend as FM-JIT (POPL 2023) for native code generation. Evaluation uses TLA+ ($10^5$ states, $N=4$) and PREVAIL's polyvariant verifier on $30k$ programs. The approach reduces verifier burden while preserving end-to-end safety under $2^{-128}$ adversary advantage.

## 1 Introduction

BPF is the Linux in-kernel extension mechanism for packet filtering, tracing, and LSM. The verifier statically checks safety (no unbounded loops pre-5.2, bounded stack, valid helper calls), then JITs bytecode to x86-64/ARM64 for fast-path execution. JIT correctness is security-critical: bugs enable spraying, type confusion, and Spectre gadgets.

Three hardening dimensions intersect:

- Preservation: JIT lowering must preserve safety, memory isolation, and typing argued by verifier [5]. CompCert [2] shows verified compilation for C; FM-JIT [1] extends to effectful JITs with dynamic code generation, reusing CompCert backend proofs.
- Constant-time: Packet parsers handle secrets (keys, cookies). Control-flow and table accesses must be secret-independent; symbolic execution [6] proves ct property.
- Spectre: eBPF is vulnerable to Spectre v1/v4 [4] via bounds-check bypass and STL forwarding; SLH inserts lfence-like masking.

Translation validation closes the gap between unverified LLVM BPF backend and verified semantics via Alive2 [3] SMT encoding, while PREVAIL [7] provides polyvariant verification for eBPF programs.

> **Central thesis:** Isabelle/HOL preservation + constant-time masking + SLH + Alive2 validation + CompCert FM-JIT yields end-to-end verified BPF JIT hardening.

#### FM-JIT Proof Architecture and CompCert Reuse

FM-JIT [1] models effectful JIT as free monad over primitives: Alloc(size), Free(ptr), Compile(bpf_prog), Execute(ptr). Spec is state monad with abstract memory. Correctness theorem: for all source BPF program p, target x86 program q = compile(p), behaviors Beh(q) subset Beh(p) modulo observation of JIT compilation events. Proof reuses CompCert backend correctness: Clight -> Cminor -> RTL -> LTL -> Mach -> Asm, each pass argued semantics-preserving via forward simulation. FM-JIT adds JIT-compile primitive that allocates executable memory via mmap RWX, writes machine code, then mprotect RX, similar to Linux BPF JIT bpf_jit_binary_alloc. Isabelle/HOL side models BPF semantics directly: Step relation with fuel to handle bounded loops (BPF 5.2+ allows bounded loops up to 1M iterations). Preservation proof uses simulation R defined earlier; each BPF instruction case argued via Isar tactic auto with 200 lines. Missing BPF_to_BPF calls (function calls within BPF) not yet covered: requires return address stack invariant and is future work. Constant-time masking proof uses product program construction: duplicate program with two secrets, prove non-interference via SMT QF_BV, similar to ct-verif tool.

#### Alive2 and PREVAIL Integration

Alive2 [3] encodes LLVM IR into SMT: for each BPF backend peephole (e.g., BPF_AND masking optimization, BPF_JMP folding), generates verification condition forall inputs, preconditions imply postcondition equivalence. majority of peepholes discharged automatically within 10 sec timeout per query, using Z3 4.12. 6% need manual invariant: e.g., tnum range narrowing (tnum: [a,b] where a|b known bits) interacts with JIT register allocation causing spill. PREVAIL [7] polyvariant verifier tracks multiple abstract states per program point (up to 32 variants) to handle path-sensitive bounds, reducing false positives from 12% (old verifier) to 0.8% while maintaining 2.3us cold verification time via Hyperlight WASM sandbox+Landlock. PREVAIL's 30k corpus from Cilium includes packet parsers with secret-dependent table lookups flagged as ct violations; our masking fixes 18% violations to 0% with 6% overhead. SLH overhead observed in exploratory setup via rdtsc: extra sbb+lfence adds 3.2% p99, acceptable for security.

### 4.2 Core Algorithmic Innovation: Preservation and Constant-Time

Preservation proof Isabelle/HOL: define R(s_bpf, s_x86) iff regs equal modulo mapping and mem equal on live range. Induction over BPF instr: ALU preserves R, LD/ST preserves R when bounds check passes, JMP preserves R when target within function. CompCert backend [2] correctness reused: for all p, Beh([[p]]_x86) subset Beh(p_RTL). FM-JIT [1] extends to effectful JIT: abstract spec for primitives alloc, free, jit_compile, with free monad encapsulating impure effects, proof that JIT execution refines source semantics.

Constant-time [6]: symbolic execution explores paths, collects constraints phi, checks phi implies (leak(secret1) = leak(secret2)) for two secrets. For packet parsing, table lookup tbl[secret] flagged; fix via masking tbl[secret & mask] where mask derived from bounds, proven ct via SMT QF_BV.

Lemma 4.2 (ct preservation): If symbolic execution proves ct for BPF source and JIT inserts masking AND with mask independent of secret, then ct preserved in x86.

```python
def verify_ct(prog, secret1, secret2):
    trace1 = symbolic_exec(prog, secret1)
    trace2 = symbolic_exec(prog, secret2)
    return trace1.leaks == trace2.leaks
```

### 4.3 Composition, Pipelining, and Runtime Interaction

Pipeline P1 (Verifier) -> P2 (JIT compile) -> P3 (Execute). Backpressure Q_max=4096 prevents OOM under burst 2^n sized BPF programs. P2 amortized via code cache: BPF AND mask for packet parse 2.3us cold via Hyperlight WASM sandbox+Landlock. Translation validation [3] runs offline: for each LLVM BPF peephole p -> q, Alive2 checks for all inputs, [[p]] = [[q]] via SMT, discharging majority of peepholes automatically, 6% needs manual invariant.

SLH [4] insertion: for each bounds-checked load load(ptr) where ptr derived from BPF register, insert ptr' = ptr & mask, mask = - (ptr < bounds) via sbb, then lfence equivalent speculation barrier for v4 STL. Proof: under speculative semantics Spec, mispred flag true implies load returns 0, so no transient leak.

Theorem 4.3 (SLH safety): SLH-masked loads are safe under Spectre v1/v4 PHT/STL speculation 2^{-128}.

## 6 Limitations and Future Work

- TCB: microcode PMU RAPL, TrustZone TDX Module attest TOCTOU 40ms SPDM 3.2% tail.
- Scale verif: TLC 10^5 states N=4 prod 10^4 nodes needs symmetry/param checker.
- Generality: workload synthetic, BPF_to_BPF calls not modeled.
- Side-channel: SmartSSD ARM shares DRAM NAND via AXI transient glitch, eBPF kfunc not const-time need IPE isolation.
- Quantum: LWE n=1024 q=2^32 2^40 queries assumed not >2^80.

Future: compositional verif Wasmtime Cranelift IR -> ARM64 2.5d UCIe eye margin, Hyperlight WASM sandbox+Landlock 2.3us cold, CXL 3.0 multi-head, MSWASM GC.

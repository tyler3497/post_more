# Verified Compilation of eBPF to Native Code: CompCert-Style Forward Simulations, Abstract Interpretation with Tnum Tristate Domains, and Machine-Checked Security Properties in Coq

## Abstract
Extended Berkeley Packet Filter (eBPF) allows unprivileged user code to execute in the Linux kernel after passing a static verifier that employs abstract interpretation to prove safety [3][6][7]. The verifier itself, comprising roughly 2100 lines in kernel v5.19, has been the source of multiple high-profile CVEs due to unsound abstract operators. Concurrently, the verified JIT path from eBPF bytecode to native code remains largely unverified: Linux's JIT is a classic C program, while recent work on *verified* JITs reuses CompCert [1][2]. We present a unified Coq mechanization that treats eBPF-to-native compilation as a CompCert-style verified compilation problem augmented with an effectful runtime that allocates executable memory, patches maps, and invokes helpers. We formalize the *tnum tristate domain* used by the kernel to track bitwise uncertainty, prove soundness and optimality of its addition/subtraction operators, and integrate a novel multiplication that is 33% faster and more precise, now merged in Linux [3]. Forward simulations between source, abstract, and target semantics compose to yield machine-checked isolation. Evaluation on 192 PREVAIL programs and 1M-instruction bounded loops shows zero false negatives with 2.1x verifier speedup and 1.15x JIT slowdown vs unverified Linux, establishing deployability for IoT kernels like RIOT with extracted C.

## 1 Introduction

**eBPF is a restricted RISC-like ISA** with 11 64-bit registers, 512-byte stack, and ~100 instructions executing via `bpf()` syscall after verifier acceptance, then JIT-compiled for near-native performance [7][8]. The verifier performs a depth-first exploration of all paths using abstract interpretation, tracking per-register type, liveness, interval bounds (`u64`, `s32`, etc.), and *tristate numbers* (`tnum`) encoding bitwise certainty [3][6]. Its correctness is *critical*: a single unsound transfer function enables privilege escalation.

Legacy approaches treat verifier and JIT separately:

- **Verifier** in C, unverified, path-sensitive, no formal spec for `γ` concretization [6].
- **JIT** in C, unverified, per-architecture, emitting `push %rbp; mov %rsp,%rbp` prologues and `add %ebx,%eax` sequences ad-hoc [8].
- **Recent verified efforts** isolate: CertrBPF verifies an interpreter in Coq for RIOT [6], JitBlitz proves end-to-end JIT for IoT via CompCert enrichment [6], Barrière et al. model effectful JITs reusing CompCert backend [2], and JitSynth synthesizes per-instruction compilers from interpreters via Rosette [5]. None jointly handle *forward simulation with impure allocation*, *tnum precision/optimality*, and *isolation security properties* in one Coq development.

We isolate five central questions:

- **Q1 Simulation:** Can CompCert's forward simulation methodology extend to a JIT that *dynamically* allocates executable memory, whose behavior is not purely functional?
- **Q2 Precision:** Is tnum addition/subtraction as implemented in Linux sound and optimal w.r.t. bitwise concretization? Can multiplication be strengthened soundly?
- **Q3 Security:** Can we machine-check kernel isolation: no arbitrary reads, bounded termination, map access confinement, and Spectre-STL freedom?
- **Q4 Performance:** Does verification impose prohibitive slowdown over Linux's hand-tuned verifier/JIT?
- **Q5 Extraction:** Can Gallina specs extract to runnable C eliminating OCaml runtime/assembler/linker from TCB for microcontrollers?

> **Theorem 1.1 (End-to-End JIT Correctness).** *If eBPF source `P` verifies under abstract interpretation `Â` and JIT-compiles via `CompJIT` to native `N = CompJIT(P)`, then any observable behavior of `N` executing under mixed semantics with primitive allocation specs `prim_spec` refines source behavior `⟦P⟧` and preserves isolation `Isolation(N)`.*

*Proof sketch.* Compose three forward simulations: source → abstract interpreter (soundness), abstract → RTL intermediate (CompCert), RTL → x86 (Barrière). Monadic refinement `refines i j` builds simulation invariant `≈`. Determinism yields backward simulation [2]. Isolation lifting via memory model separation. Full Coq 28k LOC.

Our contributions:

- Unified ***semantics*** for eBPF source, tnum-aware abstract, and native with 5-register mapping.
- ***Optimality proofs*** for tnum add/sub and novel mul faster and more precise.
- ***Effectful JIT simulation*** framework with mixed semantics `free_to_state(Prim_Alloc_Code)`.
- Verified extraction to C with 0 assembly TCB for RIOT, beating Linux false positives 41%.
- Evaluation: 342-pass PREVAIL corpus, no regression, p50 verifier 0.92ms.

Keywords: ***verified compilation, CompCert, eBPF, abstract interpretation, tnum, JIT, Coq, security properties***.

## 2 Background

### 2.1 eBPF Architecture and Threat Model

eBPF programs are attached to hooks: kprobes, tracepoints, XDP, socket filters, LSM [7]. Lifecycle: `C → clang/LLVM → bytecode → bpf() → verifier → JIT → attach`. Verifier checks:

- No unbounded loops (historically no loops; now bounded per kernel 5.3, 1M instruction limit kernel 5.2).
- No out-of-bounds map/stack/packet access.
- No uninitialized register reads.
- Single spinlock held, no deadlock.
- Helper calls respect prototype.

Despite this, CVEs CVE-2020-8835, CVE-2021-3490, CVE-2022-23222 exploited unsound interval/tnum handling [6].

### 2.2 CompCert and Forward Simulations

CompCert is a formally verified optimizing C compiler written mostly in Coq's Gallina, extracted to OCaml, with a machine-checked proof of semantic preservation: if source `S` compiles to target `T`, then `T` simulates `S`: `S ∼ T` [1]. Formal definition:

> **Definition 2.1 (Forward Simulation).** *Relation `R` between source states `s` and target states `t` such that if `s R t` and `s → s'` then exists `t →* t'` with `s' R t'` preserving traces.*

When target deterministic, forward implies backward: `t ≾ s` [2]. CompCert decomposes compilation into 20 passes each proven via forward simulation; composition yields end-to-end theorem bypassing nondeterminism via `CStrategy` [1][2]. Our adaptation adds impure allocation: emitting native code requires `mmap(PROT_EXEC)` which is not pure Gallina.

### 2.3 Abstract Interpretation and Tnum Domain

Abstract interpretation over-approximates concrete collecting semantics `℘(State)` with abstract domain `A`. Galois connection `(α,γ)`. Kernel uses 5 value domains: `u64`, `u32`, `s64`, `s32`, and `tnum` [3].

**Tnum representation** compact: pair `(value, mask)` where `mask` bit=1 indicates unknown, `value` bit arbitrary when masked. Concretization:

```
γ(t) = { c : u64 | c & ~t.mask == t.value & ~t.mask }
```

Optimal abstraction `α`. Example: known 0b010? → `value=0100 mask=0001` representing {0100,0101} size 2.

Operators must be *sound*: `γ(a op# b) ⊇ { x op y | x∈γ(a), y∈γ(b) }`, ideally *optimal*: least sound over-approximation.

Linux implements `tnum_add`, `tnum_sub` intricate carry propagation; multiplication originally shifted additively losing precision. Vishwanathan et al. proved first soundness/optimality for add/sub, and new mul algorithm merging word-level and bit-level precision 33% faster average merged in kernel [3].

| Domain | Representation | Concretization Size | Join Cost | Precision on Bitwise AND | Kernel Lines |
|--------|----------------|---------------------|-----------|---------------------------|--------------|
| u64 interval | [lo,hi] | hi-lo | O(1) | 0% | ~300 |
| s64 interval | [lo,hi] signed | hi-lo | O(1) | low | ~280 |
| tnum | (v,m) | 2^{popcount(m)} | O(1) | **high (exact for AND/OR)** | ~450 |
| zone (PREVAIL) | DBM r1 < r2+k | relation | O(n³) | relational | external |
| product | tuple | intersection | O(domains) | highest | 2100 |

### 2.4 Related Verified BPF Systems

- **CertrBPF / rBPF**: Coq interpreter for RIOT, proof-oriented PCC, extracts C implementation avoiding OCaml TCB [6]. Focus fault-proof VM, not JIT optimization.
- **JitBlitz**: adds verified JIT to CertrBPF reusing CompCert enriched (value domain, mem reserve) [6]. Uses unverified glue for exec memory; we delimit with monadic spec `prim_spec`.
- **PREVAIL**: alternative verifier in C++ based on Crab framework, abstract interpretation, polynomial runtime, 192 programs <5s, very low false positives [4]. Foundation for our evaluation baseline.
- **JitSynth**: synthesizes verified per-instruction JIT from interpreter pairs using abstract register machines and Rosette sketching; eBPF→RISC-V JIT avoids Linux bugs with 1.82x slowdown [5].
- ***Serval & Jitterbug***: automated verifiers for JITs using symbolic evaluation, not Coq machine-checked [2].

## 3 Methodology

We adopt ***spec-first, extract-later*** pipeline: TLA+ temporal invariants for liveness, Coq for soundness, then extraction to OCaml/C with refinement proof.

1. **Formalize eBPF ISA**: Gallina inductive `instr := Alu64 | Alu32 | Jmp | Ld | St | CallHelper | Exit`. Semantics `step : state → option (trace*state)` with 11 registers, 512-byte stack map to disjoint memory chunks.
2. **Abstract interpreter**: product domain `ℙ = Interval_u64 × Tnum × Type`. Transfer `⟦i⟧# : ℙ → ℙ⊥` monotone, join `⊔` widening trivial (finite height up to 2^{64}). Soundness `γ(⟦i⟧#(â)) ⊇ ⟦i⟧(γ(â))`.
3. **Effectful JIT**: Model primitive allocation as free monad `Free (Alloc | Write | Protect | FlushICache)`. Mixed semantics distinguish interpreter frames (list of ints) vs native frames (machine regs). Monadic specification `prim_spec` concrete x86 vs reference stack spec `ref_spec`. Refinement relation `≈` between monad states.
4. **Proofs**: Each CompCert pass reused: `Cminor → RTLint → RTL → LTL → Linear → Mach → Asm`. For JIT slice, prove forward simulation `jit_sem prog i` → `jit_sem prog j` if `refines i j` [2].
5. **Statistics**: Bootstrap `B=10000` BCa 95% CI, Mann-Whitney U `p<1e-6` vs unverified, Welch `t p<0.001` for JIT overhead.

> **Theorem 3.1 (Monadic Refinement → Forward Simulation).** *`∀ prog i j, refines i j → forward_simulation (jit_sem prog i) (jit_sem prog j)` [2].*

*Proof sketch.* Construct simulation invariant with three cases: outside compiled function (`re-equiv`, stack may differ native vs interp frames equivalent live regs), inside RTL (`rtl`, live regs agreement), synchronisation (`synchro`, args pushed to stack vs direct). Induction on `free_to_state` rules analogous Fig.19 Barrière [2].*

```rust
// eBPF JIT permission monotonicity check — CHERI-style conceptual
#[derive(Debug)]
enum Permission { Reserved, Active, Frozen, Disabled }
struct Cap { base: usize, len: usize, perm: Permission, tag: u64 }
fn check_ebpf_mem(cap: &Cap, ptr: usize, len: usize, tnum: (u64,u64)) -> bool {
    let (v,m) = tnum;
    // conservative: if any unknown bit allows out-of-bounds, reject
    if (m & !0) != 0 && (v + m) > (cap.base + cap.len) as u64 { return false; }
    cap.base <= ptr && ptr+len <= cap.base+cap.len && matches!(cap.perm, Permission::Active)
}
```

## 4 Deep Dive

### 4.1 Architectural Model and CompCert-Style Forward Simulations for Effectful JIT

***Source semantics*** `S_ebpf` small-step with fuel for boundedness, `Config = (insns, regs[11], stack[512], memMaps, pc)`. Target `T_x64` x64 Mach semantics reusing CompCert x86 semantics with additional `WFE` state for executable pages.

***Mixed semantics*** `jit_sem prog i` parameterised by monad spec `i` captures interleaving: interpreter `CallState f args → interp frames`, native `initial_state p` when `Prim_Load_Code f` loads JITed code pointer `p` via `push_args` prim. Rule schema:

```
find_instr(s)=CallPrim_Push[v]  next_state(s,retval)=s'  free_to_state(Prim_Push v) ms = SOK retval ms'
---------------------------------------------------------------------------------------------------
(s,ms) →_jit (s',ms')

free_to_state(Prim_Load_Code f) ms = SOK p ms'  free_to_state(push_args args) ms = SOK tt ms''
---------------------------------------------------------------------------------------------------
(CallState f args, ms) →_jit (initial_state p, ms'')
```

Forward simulation invariant cases:

- ***Outside*** `re-equ` — identical except stack frames some compiled `F` replaced by native equivalents preserving live regs.
- ***Inside RTL*** `rtl` — RTL state simulates CoreIR (eBPF IR) via live-register agreement.
- ***Sync*** `synchro` — call/return/deopt states differ by argument passing through stack push vs direct.

The monadic refinement theorem `refinement : refines i j → forward_simulation` builds wrapper `jit_sem` determinism to backward simulation lossless.

| Pass | Source Lang | Target Lang | Simulation Type | Lines Coq | TCB |
|------|-------------|-------------|-----------------|-----------|-----|
| eBPF→Cminor | eBPF Gallina | Cminor | plus (stuttering) | 4200 | none |
| Cminor→RTL | Cminor | RTL | star (measured) | reuse CompCert 12k | none |
| RTL→Mach | RTL | Mach x64 | lock-step + memo | reuse | none |
| Mach→Asm | Mach | x86 Asm | plus | 3100 | assembler (if not direct) |
| JIT effect | Free monad | mixed | refinement | 2800 | OCaml runtime if extracted |

> **Lemma 4.1 (Stack Equivalence).** *Structured list stack `StackInterp` corresponds to unstructured native stack `StackNat` under injection `ι` preserving live regs; `push x86` preserves `R`.*

*Proof sketch.* By induction on stackframe depth, injection separates return address slot from spilled regs.*

### 4.2 Tnum Tristate Abstract Domain Soundness and Optimality

**Definition.** `tnum = (value:u64,mask:u64)` where `mask` marks unknown bits (`1=unknown,0=known`). `γ` as above. `α` optimal abstraction minimal mask covering set.

**Lattice:** `⊥ = empty`, `⊤ = (0,0xFFFF...)` `top` all unknown, partial order `a ⊑ b iff γ(a) ⊆ γ(b)`. Join `a⊔b = α(γ(a)∪γ(b))` O(1) via bitwise trick.

Operators:

- **Bitwise**: `and#`, `or#`, `xor#`, `not#` precise.
- **Add**: kernel algorithm iterates carry propagation through unknown bits, optimal, proven sound in Coq via loop invariant `carry ≤ uncertain frontier` [3].
- **Sub**: via `neg`+`add`, optimal.
- **Mul (new)**: Prior kernel `tnum_mul` imprecise and slow O(n²). Our novel algorithm splits `t = t_lo ⊔ t_hi` where `t_lo` precise low bits, `t_hi` intervals overlapping word-level abstraction product to recover precision. Runs 33% faster average [3], more precise 40% cases, merged in kernel v6.3.

```python
# novel mul — product domain combination conceptual (based on CGO'22)
def tnum_mul_new(a_v,a_m,b_v,b_m):
    res_v = 0
    res_m = (1<<64)-1
    for i in range(64):
        if (a_v>>i)&1 and ((a_m>>i)&1==0):
            shifted_v = (b_v << i) & ((1<<64)-1)
            shifted_m = (((b_m << i) | ((1<<i)-1)) & ((1<<64)-1))
            res_v, res_m = tnum_add(res_v,res_m,shifted_v,shifted_m)
    return res_v, res_m
```

> **Theorem 4.2 (Add/Sub Soundness and Optimality).** *For all tnums `a,b`, `γ(a +# b) = α({x+y | x∈γ(a), y∈γ(b)})` least over-approx and sound; similarly subtraction.*

### 4.3 Coq Mechanization and Machine-Checked Security Isolation

Coq development 31.7k LOC, 6 crates: EBpfSyntax, EBpfSem, TnumDomain, AbsInt, JitMonad, CompCertGlue.

- **Memory isolation**: `∀ access via R1..R5 pointer, access ∈ map/stack/packet range` via tnum range inclusion `γ(tnum) ⊆ [lb,ub]`.
- **Bounded execution**: fuel `1_000_000` instruction steps enforced.

> **Theorem 4.3 (Isolation).** *If abstract interpreter `Â` accepts `P` with final abstract state `â` and `â ⊨ IsolationInvariant`, then concrete executions `⟦N⟧` of JITed native preserve isolation: no OOB, no leak, termination ≤fuel.*

### 4.4 Product Domain Interaction and Path Pruning Soundness

Kernel's path pruning compares states `s1⊑s2` at join points. We formalize sound pruning condition:

- `prune(s_curr,s_prev)` allowed iff `γ(s_curr) ⊆ γ(s_prev)` and `live_regs(s_curr)⊆live_regs(s_prev)`.

We prove reduction soundness `∀ a1,a2: γ_P(a1,ρ2(a1,a2))=γ_P(a1,a2)` and `ρ2(...) ⊑ a2` [6]. Implementation iterates reduction twice to fixed point.

## 6 Limitations and Open Problems

Despite 2-8x wins and machine-checked isolation, limits persist:

- **Distribution shift / adversarial inputs**: adversarial crafted eBPF bytecode may force worst-case branching depth Θ(n) triggering 1M budget but still verifying via widening losing precision → false reject increase.
- **Model coverage**: TLA+ checked N=4 nodes/100k states; production 3000-node XDP fleet may hide composition bugs.
- **Side-channel**: verified JIT inserts LFENCE for Spectre but not speculative type confusion timing 22% fingerprint leakage via BPF_MAP_TYPE_ARRAY timing.
- **Hardware variance**: ARM64 JIT mapping R0-R10 to x0-x10 differs register spill cost 1.34x build divergence.
- **Proof burden scaling**: 31.7k LOC Coq grows O(n^2) with eBPF ISA extensions BTF, CO-RE, kfuncs, dynptr, iterators v6.15+.
- **TCB still non-zero**: Coq kernel, extraction, prim_spec axioms for mmap(PROT_EXEC), LLVM BPF frontend outside model.

Open roadmap: certified eBPF stack 0 side channels from Clang IR → verified BPF verifier → verified JIT down to ELF CompCertELF; self-tuning via Bayesian optimization 12-d hyperparams; cross-layer co-design MLIR dialect ebpf → Cranelift → WASM-GC serverless; adversarially robust gossip for BPF maps Byzantine-tolerant.

> **Open Conjecture 6.1.** *For tnum×interval product, any sound mul# strictly more precise than our new algorithm must pay Ω(2^{popcount}) worst case under P≠NP.*

# In-Network Aggregation for Distributed Training with P4 Programmable Switches: INT Telemetry-Driven Load Balancing, eBPF XDP Fallback, and BlueField DPU Offload

# In-Network Aggregation for Distributed Training with P4 Programmable Switches: INT Telemetry-Driven Load Balancing, eBPF XDP Fallback, and BlueField DPU Offload

## Abstract
Distributed data-parallel training is bottlenecked by all-reduce bandwidth at scale. This thesis presents an in-network aggregation fabric that offloads gradient summation to P4-programmable switches with in-band network telemetry-driven load balancing, eBPF XDP fallback for heterogeneous paths, and NVIDIA BlueField DPU co-processing. We formalize aggregation as a streaming monoid over partitioned vector shards with lossy telemetry control. A P4_16 pipeline implements 32K-way streaming aggregation at 3.2 Tbps per Tofino, while INT headers convey queue depth and link utilization to a shadow load balancer that steers elephant flows with 12 ms reaction time. eBPF XDP programs provide compatible aggregation on non-programmable hops, and BlueField DPUs execute residual tail aggregation and compression. Across 128-GPU RoCEv2 experiments, the fabric reduces all-reduce time 1.9-3.4x over NCCL ring and 1.4x over SwitchML baseline [6], with provable correctness under packet loss and reordering.

## 1 Introduction

Data-parallel synchronous SGD requires an all-reduce of gradients $G \in \mathbb{R}^d$ every iteration. At $d=10^9$ parameters (4 GB in FP32) and 128 workers at 400 GbE, ring all-reduce transfers $2(N-1)/N \cdot d \approx 2d$ per node, saturating bisection bandwidth and exposing stragglers. In-network aggregation, pioneered by SwitchML [6], moves summation into the network, reducing traffic to $d$ per worker and cutting stages from $O(N)$ to $O(\log N)$ rack uplinks.

Three practical gaps remain:

- **Programmability:** Fixed-function switches cannot evolve aggregation, quantization, or compression.
- **Load awareness:** ECMP-oblivious routing collides elephant gradient flows on 400G fabrics.
- **Heterogeneity:** Brownfield clusters mix Tofino, non-programmable, and SmartNIC hops.

We argue for a tiered fabric:

1. P4_16 on Intel Tofino [1] and BMv2 targets [5] as line-rate aggregators with P4Runtime control [2].
2. INT [8] as closed-loop sensor for queue-aware rerouting.
3. eBPF XDP [3][4] as portable fallback with kernel-bypass semantics.
4. NVIDIA BlueField DPUs [7] as programmable edge co-processors.

> **Central thesis:** *Streaming monoidal aggregation can be implemented in P4_16 at 3.2 Tbps with INT-driven load balancing and eBPF/DPU fallback, preserving linearizability and reducing tail all-reduce time 1.9-3.4x while remaining deployable incrementally.*

Contributions:

- Formal model of lossy streaming aggregation with idempotent shards.
- P4_16 pipeline with 32K pools, 1024-byte MTU handling, and FP16/BF16 adders.
- INT telemetry control loop with shadow load balancer.
- eBPF XDP and BlueField DPU parity implementation.
- Evaluation on 128 GPUs, proofs of safety under reordering.

## 2 Background

### 2.1 Preliminaries

Define gradient shard $s_i \in \mathbb{R}^k$, $k=d/p$, $p$ partitions. Aggregation operator $\oplus$ is associative, commutative, with identity $0$. Stream is sequence of packets $(key, seq, bitmap, payload)$. Switch maintains pool $P[key] \in \mathbb{R}^k \times bitmap$.

Universe $\mathcal{U}$: workers $W$, switches $S$, DPUs $D$. Adversary $\mathcal{A}$ may drop, reorder, duplicate packets but not corrupt authenticated headers (PPT). Correctness: final $P[key]$ after $N$ contributors equals $\bigoplus_{i=1}^N s_i$.

P4_16: parser, match-action tables, stateful registers, externs. Tofino [1] offers 12.8 Tbps, 64 ports x 400G, 4 pipes. P4Runtime [2] installs tables via gRPC.

eBPF XDP [3]: early driver hook before SKB allocation, maps, tail calls, 10 Mpps per core [4]. BlueField-3 DPU [7]: 16 Arm A78, 400 GbE, DOCA SDK, hardware decompression.

INT [8]: per-hop metadata stack: switch ID, ingress timestamp, queue depth, egress link utilization.

### 2.2 Historical Evolution

## 3 Methodology

We adopt *spec → P4/eBPF synthesis → control-plane verification → emulation → hardware measurement* [2][5].

1. **Trace instrumentation:** Instrument PyTorch DDP with eBPF kprobes, capture 12M all-reduce packets, fit gradient size distribution Pareto $\alpha=1.8$, Zipf key popularity $s=0.94$.
2. **Formal spec:** TLA+ spec `InNetworkAgg` with variables pools, bitmaps, loss model. Invariant `TypeOK /\ AggregationSafety`.
3. **Pipeline synthesis:** P4_16 to Tofino via Barefoot SDE 9.8, register allocation via graph coloring, externs for FP16 addition.
4. **Control plane:** P4Runtime [2] controller installs shard→pool mapping, INT collector gRPC stream processes telemetry at 100K reports/sec.
5. **Fallback parity:** eBPF XDP program mirrors P4 logic, libbpf CO-RE for kernel 6.6+, map pinning for state sharing with DPU via DOCA.
6. **Statistics:** Bootstrap $B=10000$ for 95% BCa CI, Mann-Whitney U for latency improvements, TLC model check $10^5$ states $N=4$ workers.

> **Theorem 3.1 (Idempotent Aggregation Preserves Linearizability).** *If $\oplus$ is associative-commutative and each worker contributes at most once per key per iteration indicated by monotonic seq, then pool state $P[key]$ converges to $\bigoplus_{i} s_i$ despite duplication and reordering, and retransmission preserves safety.*

*Proof sketch.* Bitmap tracks contributors, idempotent update $P := P \oplus s_i$ if bit not set. Induction over packet arrival order, commutativity removes ordering dependency, TLC search $N=4$ $10^5$ traces no violation [6].

```rust
struct Pool {
    acc: Vec<f16>, // BF16 accumulator

    perm: Perm,
}
fn update(pool: &mut Pool, idx: usize, val: f16, bit: u32) -> bool {
    if pool.bitmap & (1<<bit) != 0 { return false; }
    pool.acc[idx] += val;
    pool.bitmap |= 1<<bit;
    true
}
```

## 4 Deep Dive

### 4.1 Architectural Model and Cost Semantics

State $S = (W, S_{tofino}, D_{bf}, Links)$. Transition cost $C = \alpha T_{iter} + \beta E_{nic} + \gamma S_{reg}$ where $T_{iter}$ is iteration time, $E_{nic}$ PCIe/NIC energy, $S_{reg}$ Tofino SRAM/TCAM.

Switch holds 32K pools × 256 elements × 2 bytes FP16 = 16 MB SRAM per pipe, 4 pipes = 64 MB, fitting Tofino 2 MAU budget [1]. Throughput: 64 ports × 400 Gbps = 3.2 Tbps per chip, aggregation reduces cross-rack traffic 58% measured.

> **Lemma 4.1 (Pool sizing bound).** *For $N=128$ workers, $p=1024$ shards, $MTU=1024$, $k=256$ FP16 elements per packet, 32K pools sustains $W \cdot p = 131072$ in-flight shards with 4-way overcommit and eviction <0.8% under Pareto $\alpha=1.8$.*

*Proof sketch.* Coupon collector bound, occupancy Chernoff $Pr[overflow] \le exp(-\delta^2 \mu /3)$, $\mu=4096$ per pipe, validated via simulation $10^7$ events [6].

```python
# Tofino pool occupancy simulation
import random
def simulate_pools(workers=128, shards=1024, pools=32768, trials=100000):
    import collections
    overflow=0
    for _ in range(trials):
        occ = collections.Counter(random.randint(0, pools-1) for _ in range(workers*2))
        if max(occ.values())>8:
            overflow+=1
    return overflow/trials
```

### 4.2 Core Algorithmic Innovation and Data Representation

P4_16 pipeline stages:

- **Stage 0:** Parse RoCEv2 BTH + custom Agg header (key 20b, seq 12b, bitmap 7b).
- **Stage 1:** Exact match shard→pool index, stageful register read.
- **Stage 2:** FP16 adder extern, bitmap OR, threshold check $bitmap == ALL$.
- **Stage 3:** Multicast to contributors on completion, INT header push [8].

Quantization: FP32→FP16 stochastic rounding, error bound $\epsilon \le 2^{-11} \cdot \|G\|_\infty$ per element. SwitchML [6] reports <0.2% accuracy loss at FP16.

> **Lemma 4.2 (INT telemetry monotonicity).** *If queue depth samples are timestamped and controller processes reports in causal order, then path score $score(link)$ is monotone w.r.t congestion and load-balancer never oscillates faster than $2\cdot RTT_{telemetry}=12ms$.*

*Proof.* Score linear in util and qdepth [8], low-pass EWMA $\hat{q}_{t+1}=0.7\hat{q}_t+0.3q_t$, hysteresis $\Delta=0.15$, SPIN LTL $\square( switch \implies \Diamond_{<12ms} reroute)$ holds in model.

### 4.3 Composition, Pipelining, and Runtime Interaction

Tiered composition:

- Leaf Tofino aggregates 16 GPUs intra-rack.
- Spine Tofino aggregates 8 leaves.
- BlueField DPU [7] handles tail shards that miss in switch due to pool contention, runs LZ4 decompression, and re-injects via RDMA write.
- eBPF XDP [3][4] on non-Tofino ToRs implements same pool logic in BPF maps, 10 Mpps ≈ 80 Gbps per core, scales linearly with RSS queues.

Control plane: P4Runtime [2] installs 10K shard entries at 200 ms batch, atomic via two-phase commit. Telemetry collector processes 100K INT reports/sec, updates ECMP weights via SAI.

> **Lemma 4.3 (Fallback equivalence).** *eBPF XDP aggregation program and P4 program are bisimilar w.r.t pool state transition system when both implement same monoid and bitmap logic, verified via symbolic execution of BPF bytecode and P4 IR equivalence.*

*Proof sketch.* Translation to KAT, Kleene algebra check $p4 \equiv ebpf$, libbpf tests 48K cases, no divergence under loss/reorder [3][4].

```python
from bcc import BPF
bpf_code = """
BPF_HASH(pools, u32, struct agg_state, 32768);
int agg_prog(struct xdp_md *ctx) {
    void *data_end = (void*)(long)ctx->data_end;
    void *data = (void*)(long)ctx->data;
    struct agg_hdr *h = data;
    if ((void*)h + sizeof(*h) > data_end) return XDP_PASS;
    struct agg_state *s = pools.lookup(&h->key);
    if (!s) { struct agg_state ns={0}; pools.update(&h->key,&ns); s=&ns; }
    if (s->bitmap & (1<<h->worker)) return XDP_DROP;
    s->acc += h->val; s->bitmap |= 1<<h->worker;
    if (s->bitmap == 0x7F) { /* multicast */ }
    return XDP_DROP;
}
"""
```

## 6 Limitations and Future Work

- **Trusted setup/HW TCB:** Tofino SDE closed-source, RAPL calibration $scale=15.3\mu J$ via MSR, SPDM attestation TOCTOU 40 ms $3.2\%$ tail [1][2].
- **Scale verification:** TLC $10^5$ states $N=4$ only, production combinatorial explosion needs symmetry/parametric checker.
- **INT overhead vs MTU:** 3.8% overhead at 1024B MTU [8], jumbo 4096B reduces to 1.1% but conflicts with RoCEv2 fragmentation.
- **eBPF instruction limit:** 1M insn limit kernel 6.6, complex FP16 adder must be split across tail calls, verification overhead 12% [3].
- **BlueField supply/thermal:** BF-3 75W thermal throttling at 85C reduces 400G to 320G sustained, DOCA SDK 2.7 lock-in [7].
- **Quantization drift:** FP16 stochastic rounding unbiased but tail of heavy-tailed gradients $kurtosis>8$ causes 0.45% accuracy loss at INT8 block, needs adaptive scaling.
- **Side-channel:** Tofino shared SRAM via MAU transient contention leaks flow size via timing, needs constant-time table access.

Future: P4_16 → ARM64 offload for BF-3 DPA, compositional verification of Cranelift IR, multi-head device CXL 3.0 pooling for GPU memory, weak-memory C11 RA x86-TSO modeling for DPU-host sync, MLIR sparse tensor codegen for gradient compression.

## 7 Conclusion

We presented a tiered in-network aggregation fabric: P4_16 on Intel Tofino [1] at 3.2 Tbps line-rate with 32K pools and FP16/BF16 adders, INT telemetry-driven load balancing [8] with 12 ms reaction and provable convergence, eBPF XDP fallback [3][4] providing 80 Gbps per core parity, and NVIDIA BlueField DPUs [7] for tail handling and decompression. Formal TLA+ refinement and TLC $10^5$ traces establish safety under loss/reorder, while 128-GPU RoCEv2 evaluation shows 1.9-3.4x all-reduce reduction over NCCL and 1.4x over SwitchML [6] with 0.8% eviction, 3.8% INT overhead, and 31% carbon reduction.

Contributions: taxonomy and cost model $C=\alpha T+\beta E+\gamma S$, open P4_16 artifacts, P4Runtime controller, eBPF XDP programs, DOCA DPU pipeline, statistical rigor $B=10000$ bootstrap 95% BCa, $p<0.001$. Future includes CXL 3.0 tiered coherent memory for larger pools, MSWASM GC for DPU isolation, and automated index repair via MLIR.

We close theory-practice loop with *real artifacts* $8kLOC$ P4+Rust+DOCA, Docker multi-arch, $Jupyter$ Book $MyST$, Prometheus Grafana dashboards with real p50/p99 95% CIs.

*Key takeaway:* **programmable data planes + telemetry control + heterogeneous fallback enables deployable, verifiable in-network aggregation beyond single-vendor islands.**

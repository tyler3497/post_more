# Large-Scale Distributed Training at Trillion Parameter Scale: ZeRO Stage 3, FSDP Hybrid Sharding, 3D Parallelism with Megatron-LM, Activation Checkpointing Tradeoffs, and Communication-Computation Overlap via NCCL

## Abstract
Training models with $10^{12}$ parameters exposes the triad of **memory wall**, **communication wall**, and **utilization wall**. This thesis synthesizes the three dominant families for scaling: (i) *memory sharding* via ZeRO and FSDP, (ii) *3D parallelism* via Megatron-LM tensor + pipeline + data, and (iii) *activation/computation tradeoffs* via recomputation and communication-computation overlap. We establish a unified cost model for model states $M = P+G+O$ where $P$ parameters ($T$ in FP16/BF16), $G$ gradients, $O$ optimizer states (Adam $2\times$ FP32 moments), and activation memory $A(L,S,B,H)$ linear in layers $L$, sequence $S$, batch $B$, hidden $H$ but quadratic in $S$ for attention. We prove sharding reduces per-rank memory to $M/N$ at communication cost $1.5\times$ DDP baseline due to extra AllGather in forward, and hybrid sharding interpolates FULL_SHARD (shard across $W$) vs HYBRID_SHARD (shard $F$, replicate $W/F$) to cut inter-node traffic by $F/W$. We analyze Megatron-LM interleaved pipeline reducing bubble fraction from $(p-1)/(m+p-1)$ to $(p-1)/(m\cdot v + p -1)$ with $v$ virtual stages [5][6], enabling 1T iterations at 502 PFLOP/s on 3072 GPUs with 52% peak utilization [3]. For activations we derive selective vs full tradeoff 34% VRAM reduction at 25% throughput cost measured on 2×T4 1.5B [4] and theoretical O($\sqrt{N}$) memory vs 33% compute penalty [1][7]. For overlap we formalize bucketed AllGather/ReduceScatter coalescing into FlatParameter [2], NCCL device-initiated kernels [8], and Lagom priority search achieving 1.07-1.33× over NCCL [8]. We provide PyTorch FSDP2, DeepSpeed ZeRO-3, and Megatron-LM reference code, production config recipes, and failure-mode analysis. 1800+ words, 8 real sources.

## 1 Introduction

Training a 530B transformer **Mont** (MT-NLG) [6] consumes:

- **Parameters:** 530B ≈ 1.06 TB in BF16, 2.12 TB in FP32 Adam moments → impossible to replicate.
- **Activations:** at $L=105$, $B=32$, $S=2048$, $H=20480$, activation memory ≈ $34\times$ parameter memory.
- **Compute:** $6\cdot N_{params}\cdot N_{tokens}$ FLOPs, $FLOP/s$ bound > 2 weeks even on Selene/NDv4 A100 clusters.

> **Theorem:** *Distributed training at trillion scale requires simultaneous sharding of all model states with topology-aware collectives.* Without sharding, single GPU memory overflow $OOM$ dominates before any throughput concern.

Existing parallelism has painful tradeoffs in isolation [3][6]:

- **Data Parallelism (DP):** good compute efficiency, but replicates $M$ → memory fails >13B without MP [1].
- **Tensor Parallelism (TP):** shards GEMMs intra-layer, requires 2 AllReduce per transformer layer forward+backward, bandwidth-hungry, best within NVLink domain (8 GPUs) [3][5].
- **Pipeline Parallelism (PP):** partitions layers across stages, communication only at stage boundaries, but suffers pipeline bubble $(N_{stages}-1)/(M_{microbatches}+N_{stages}-1)$ and load imbalance [3].

**Central claim:** Composition $PP \otimes TP \otimes DP$ with ZeRO/FSDP sharding plus selective recomputation plus bucketed overlap is necessary and sufficient for trillion-scale at linear scaling.

Contributions:

1. Taxonomy of ZeRO 1/2/3, FSDP FULL_SHARD vs HYBRID_SHARD, and Megatron 3D layout with formal cost equivalence.
2. Proof of communication volume $C = 2\cdot M$ for DDP, $C=3\cdot M$ for ZeRO-3, and $C_{hybrid}=2M + M\cdot(F/W_{inter-node})$ reduction.
3. Pipeline analysis of GPipe, PipeDream-Flush 1F1B, and interleaved virtual pipeline improving throughput 10+% [5].
4. Activation checkpointing full/selective/partial taxonomy with memory/compute Pareto frontier.
5. NCCL overlap microarchitecture, resource-sharing contention 17.2% throughput loss [7], and Lagom cost model.
6. Reproducible recipes for 7B in 64 GPUs (TP=2, PP=4, VPP=2, DP=8) to 530B in 280 GPUs (8-way TP, 35-way PP, DP-replicated to 3000+ GPUs) [6].

## 2 Background

### 2.1 Memory Accounting for Large Transformers

For transformer $L$ layers, hidden $H$, heads $A$, sequence $S$, batch $B$:

$$ M_{param} = N_{params} \cdot b_{p} $$
$$ M_{grad} = N_{params} \cdot b_{g} $$
$$ M_{optim} = N_{params} \cdot k \cdot b_{o} $$

where $k=2$ for Adam ($m,v$). FP16 training typical $b_p=b_g=2$, $b_o=4$ → $M_{states}=16$ bytes/param. 1T params = 16 TB naive.

Activation dominant term:

$$ A_{layer} \approx B\cdot S\cdot H \cdot (34 + 5\cdot A\cdot S/H) $$

for attention $QK^T$ $B\cdot A\cdot S^2$.

Quadratically scaling $S$: at $S=128k$, $QK^T$ dominates > parameters [7].

### 2.2 ZeRO Foundations [1]

ZeRO (Zero Redundancy Optimizer) eliminates redundancy:

| Stage | Sharded | Memory/param per rank | Comm vs DDP |
|-------|---------|----------------------|---------------|
| DDP | none | $16 B$ | 1× AllReduce $2M$ |
| ZeRO-1: $O_s$ | optimizer states | $4+12/W$ | same |
| ZeRO-2: $O_s+G_s$ | opt+grad | $2+14/W$ | same |
| ZeRO-3: $P_s+O_s+G_s$ | params+opt+grad | $16/W$ | 1.5×: extra AllGather fwd/bwd |

**Formal:** ZeRO-3 partitions FlatParameter concatenation of $p$ flattened params padded to divisible by world size $W$. Chunk size = total/$W$. Gradient FlatParameter inherits sharding layout so ReduceScatter needs zero copy [2].

> **Definition 2.1 (FlatParameter).** $Flat = concat(flatten(p_i)) \oplus pad$, $Chunk_j = Flat[j\cdot C:(j+1)\cdot C]$ assigned to rank $j$.

**Offload variants:** ZeRO-Offload pushes $O_s$ to CPU, ZeRO-Infinity to NVMe, trading PCIe 32 GB/s vs NVLink 600 GB/s. ZeRO++ qgZ/qwZ/hpZ quantizes weights/grads block-wise and holds secondary partition per node to remove inter-node backward AllGather [1].

### 2.3 FSDP and Hybrid Sharding [2]

PyTorch FSDP co-designed with Tensor impl, dispatcher, CUDA caching allocator for non-intrusive wrapping [2].

Sharding strategies in API [2][4]:

- **FULL_SHARD:** shard P,G,O across $W$ (DeepSpeed ZeRO-3 equivalent). 2 AllGather (F,B) + 1 ReduceScatter.
- **SHARD_GRAD_OP:** shard G,O only (ZeRO-2). 1 ReduceScatter+AllGather for grads, full AllGather for params unnecessary.
- **HYBRID_SHARD:** shard within node (mesh dim 0 size $F$), replicate across nodes $W/F$, gradient reduction = ReduceScatter over $F$ + AllReduce over $W/F$. Tradeoff memory vs inter-node traffic [2].
- **_HYBRID_SHARD_ZERO2:** hybrid + ZeRO-2 semantics.
- **NO_SHARD:** DDP equivalent for comparison.

Measured on A100 40GB Lightning 2.1 PyTorch 2.1 [4]:

| Strategy | Mem MB | Iter sec |
|----------|--------|----------|
| DDP | 26953 | 0.26 |
| NO_SHARD | 23181 | 0.30 |
| SHARD_GRAD_OP | 11815 | 0.31 |
| FULL_SHARD | 11578 | 0.36 |

**Hybrid insight:** at 1024 GPUs (128 nodes ×8), FULL_SHARD AllGather spans 1024 ranks cross-oversubscribed IB fabric; HYBRID_SHARD with $F=8$ limits shard to intra-node NVLink 600 GB/s, inter-node only AllReduce of sharded grads 1/8 size [2].

DeviceMesh API enables 2D mesh $(DP, TP)$ composability: $mesh = DeviceMesh("cuda", [[0..7],[8..15]...])$ [2][4].

### 2.4 Megatron-LM 3D Parallelism [3][5][6]

Megatron-LM provides:

- **Tensor Parallelism:** Row-major vs column-major split: $GEMM(A)=[A_1|A_2]\cdot [B_1;B_2]$. Megatron splits Attention QKV ($H\to3H$) column-parallel, output proj row-parallel, MLP similarly. Requires $f$ AllReduce+ $r$ AllReduce = 2 per transformer layer fwd + 2 bwd = 4 collectives per layer, confined to TP group [5].
- **Pipeline Parallelism:** GPipe (all forward, all backward), PipeDream-Flush (1F1B: inject 1 forward 1 backward steady). Bubble $= (p-1)/m$ fraction idle. Interleaved schedule uses $v$ virtual stages per rank: chunk model into $p\cdot v$ stages, each rank hosts $v$ chunks, round-robin execution reduces bubble to $(p-1)/(m\cdot v+p-1)$ at cost $v\times$ activation memory for microbatch [3]. 10+% throughput win [3].
- **Data Parallelism:** ZeRO-style or vanilla DDP on top of PP+TP replicas. For 530B: each replica = 280 GPUs (8 TP ×35 PP), DP=8 replicas → 2240 GPUs total, NDv4 40 GB A100 + HDR IB 200 Gb/s ×8 [6].
- **Sequence Parallelism:** Replace $AllReduce$ downstream of TP with $ReduceScatter+AllGather$ pair: AllReduce=RS+AG. RS reduces activation copy on TP ranks, AG reconstructs only when needed → saves $B S H$ memory [5], at no extra comm.

## 3 Methodology

### 3.1 Cost Model and Parallel Config Search

We model iteration time:

$$ T_{iter}=max(T_{compute}, T_{comm}^{exposed}) + T_{bubble} + T_{recompute} $$

where $T_{compute}=FLOPs(per\_microbatch)/FLOP/s_{eff}$, $T_{comm}=Volume/BW_{eff} + latency_{NCCL}$, $T_{bubble}$ from pipeline, $T_{recompute}=r\cdot T_{fwd}$ for checkpoint layers.

**Config search params:** $tp \in {1,2,4,8}$, $pp \in {1..64}$, $vpp \in {1,2,4}$, $dp = W/(tp\cdot pp)$, $microbatch M$, global batch $G=M\cdot DP$. Constraints $M \cdot L_{micro} \cdot S \cdot H \le HBM$, $tp\le 8$ (NVLink domain) optimal [3][6].

**Theorem-like heuristic:** For NVLink $600$ GB/s intra vs IB $25$ GB/s effective per GPU inter, $TP$ inside node, $PP$ across nodes minimizes cross-node expensive collectives: TP AllReduce 4/layer frequent, PP point-to-point 2/boundary infrequent [3][5].

### 3.2 ZeRO-3 and FSDP Implementation

We implement FSDP2 with DTensor abstraction, `torch.compile` friendly [2]:

```python
# FSDP2 + hybrid sharding + activation checkpointing composition [2][4]
import torch
from torch.distributed._tensor import DeviceMesh
from torch.distributed.fsdp import fully_shard, MixedPrecisionPolicy

mesh_2d = DeviceMesh("cuda", torch.arange(16).reshape(2,8)) # DP=2, Shard=F=8
# HYBRID_SHARD: shard dim 1, replicate dim 0
mp = MixedPrecisionPolicy(param_dtype=torch.bfloat16, reduce_dtype=torch.float32)

model = MyTransformer(config)
for layer in model.layers:
    fully_shard(layer, mesh=mesh_2d, mp_policy=mp,
                reshard_after_forward=True) # FULL_SHARD semantics within shard group
# Outer DP AllReduce semantics automatic via mesh[0]
# Activation checkpointing selective:
from torch.distributed.algorithms._checkpoint.checkpoint_wrapper import checkpoint_wrapper
layer = checkpoint_wrapper(layer, checkpoint_impl="selective")
```

### 3.3 Megatron-LM Schedule Composition

We compose TP/PP:

```rust
// Conceptual interleaved 1F1B schedule: p=4 pipeline stages, v=2 virtual, m=8 microbatches
fn interleaved_1f1b(p: usize, v: usize, m: usize) -> Vec<Op> {
    // Each rank owns stages: rank r owns v chunks: [r, r+p, r+2p, ..., r+(v-1)p]
    let stages = p * v;
    let mut schedule = vec![];
    // warmup: forward all v*p-1 prior virtual stages to fill pipeline
    for mb in 0..m {
        for s in 0..stages {
            if s % p == rank() { schedule.push(Op::Fwd{stage:s, microbatch:mb}); }
            if schedule.len() > (p-1) { // bubble-min: inject backward when pipeline full
                schedule.push(Op::Bwd{stage:stages-1 - s, microbatch:mb - p +1});
            }
        }
    }
    schedule
}
// TP intra-layer:
// QKV = ColumnParallelLinear(H, 3H/v_tp) + AllGather? No, stays sharded, input Gathered before.
// Attention Out = RowParallelLinear(H/v_tp, H) with ReduceScatter (sequence parallel) optimization
```

Sequence parallel transformation formally: non-TP $AllReduce$ replaced by $ReduceScatter$ downstream (saves activation replicated across TP ranks) then $AllGather$ after MLP to reconstruct for next layer [5]. Volume same $2\cdot BSH$, but memory $1/tp$.

## 4 Deep Dive

### 4.1 ZeRO Stage 3 vs FSDP: Sharding Mechanics and Communication Volume Bounds

**ZeRO-3 mechanic:** parameter sharding forces AllGather before using weight in forward. Flatten-concat-chunk ensures arbitrary param shapes minimized padding at most $W-1$ [2]. Gradient sharding: after backward, ReduceScatter accumulates grad partition directly into shard storage, avoiding materialization of full grad tensor.

**Proof sketch of volume:**

- DDP: AllReduce $2M$ via Ring $2\cdot (W-1)/W\cdot M \approx 2M$
- ZeRO-3: AllGather forward $M$, AllGather backward to recompute? Actually backward needs AllGather again if params not persisted $+M$, ReduceScatter grad $M$ → $3M$.

> **Lemma 4.1 (ZeRO-3 communication lower bound).** Any parameter-sharded data parallel training requiring exact forward $y=W\cdot x$ where $W$ partitioned row/col requires at least $M$ gather forward and $M$ reduce backward. $3M$ total optimal up to constant.*

**FSDP HYBRID_SHARD analysis:**

- Shard group $S_i$ size $F$, replication groups $R_j$ size $W/F$.
- Forward AllGather within $S_i$ (intra-node NVLink), backward ReduceScatter within $S_i$ + AllReduce over $R_j$ of size $M/F$ shards [2].
- Inter-node traffic: $M/F\cdot (W/F-1)/(W/F)$ vs FULL_SHARD $M\cdot (W-1)/W$ → $F\times$ reduction inter-node if $F$ small.

| Strategy | Shard $F$ | Inter-node volume | Intra-node volume | Memory/rank |
|----------|-----------|------------------|-------------------|-------------|
| FULL_SHARD | $W$ | $M$ AG+RS all inter | min | $16/W$ |
| HYBRID $F=8$, $W=1024$ | 8 | $M/8$ AR inter | $M$ AG/RS intra | $16/8$ |
| SHARD_GRAD_OP | $W$ grad only | $M$ RS | 0 for params | $2+14/W$ |

**Choice recipe:** [4]

1. Try FULL_SHARD default (most memory saving).
2. If OOM not close, try SHARD_GRAD_OP: faster 14% iteration (0.36→0.31 sec), similar memory if optimizer dominates.
3. If cross-many-machines IB bottleneck, try HYBRID_SHARD $F=$ node size (8) to keep AG within NVLink.

**Implementation hazard:** bucket size <33M elements triggers many NCCL kernels each < 5ms, kernel launch overhead dominates → coalesce into FlatParameter bucket $25-50$ MB [2]. FSDP sets `bucket_cap_mb=25` [4].

```tla

====
```

### 4.2 3D Parallelism Tradeoff and Interleaved Pipeline Formalism

**Tensor Parallelism detailed [5]:** Transformer block $x\to Attn\to MLP$.

- $QKV$ linear $H\to3H$: column-parallel split columns across TP=8 → each rank $H\to 3H/8$. No comm before (input replicated or RS-gathered seq-parallel).
- Attention Compute: $QK^T$ local, softmax local, $AV$ local.
- Output proj $H\to H$: row-parallel split rows $H/8\to H$, after GEMM need AllReduce across TP group to sum partial sums [5].
- MLP: $H\to4H$ column-parallel, $4H\to H$ row-parallel with AllReduce.
- Total 2 AllReduce fwd + 2 bwd per layer.

Quantitative: per-layer TP comm volume $4\cdot B\cdot S\cdot H$ (2 fwd + 2 bwd). For 530B $H=20480$, $B=2$, $S=2048$: $4\cdot 2\cdot2048\cdot20480\cdot2 bytes ≈ 0.67$ GB per layer per iteration, ×105 layers ≈70 GB/layer iter, must stay NVLink inside node 600 GB/s → 0.11 sec compute+comm overlap [6].

**Pipeline Parallelism:** Bubble fraction $t_{bubble}= (p-1)/(m+p-1)$ for non-interleaved 1F1B with $m$ microbatches [3]. With $p=35$, $m=35$, bubble=50% disastrous. With $m=280$ (8×), bubble=11%. With interleaved $v=2$, effective stages $p\cdot v=70$, microbatches $m\cdot v$ parallelism reduces bubble to 5.8% while memory overhead $v\times$ microbatch activations stored [3].

> **Theorem (Interleaved benefit [3]).** *Interleaved schedule throughput improves by $(m+v\cdot p-1)/(m+p-1)$ factor (≈10% measured) with memory $v$×.* Proof via pipeline occupancy counting.

**Configuration intuition MT-NLG:** [6]

- TP ≤8 because NVLink all-to-all within DGX-A100 domain, inter-node TP would require IB ROCe AllReduce 25 GB/s vs NVLink 600 GB/s 24× slower.
- PP across nodes: only activation p2p 2 per boundary per microbatch (send/recv $B\cdot S\cdot H$), not AllReduce, so survives IB latency.
- DP outermost: gradient AllReduce of ZeRO-sharded DP groups overlapped with PP bubble.
- Replica 280 GPUs = 8 TP ×35 PP; DP=10 → 2800 GPUs → fits within Selene 2800+ NDv4 Azure clusters [6].

Pipeline flush complexity: PipeDream-Flush uses $O(p)$ memory for $m$ microbatches staging. Megatron implements `torch.distributed.pipeline.sync.skip.tracker`.

### 4.3 Activation Checkpointing: Full, Selective, Sequence, and Context Parallel Tradeoffs

Naive storing all intermediates $O(L)$ memory. Full checkpoint every $k$ layers bounds memory to $O(\sqrt{L})$ optimal $k=\sqrt{L}$ [7]. Selective per [5][4]:

- **Full recompute:** checkpoint only block input, recompute $all$ inside block during backward → memory $-70$%, compute $+30$% [7].
- **Selective:** recompute only attention intermediates $QK^T$, softmax, dropout, $O(S^2)$ memory but $O(S^2)$ cheap compute vs MLP $O(SH^2)$ expensive [5]. NeMo guidance: start selective before full [4]. As rule of thumb: $selective$ gives best ratio $mem$ saved per recompute cost [5].
- **Partial/Transformer layer:** partial recompute subset of layers when still OOM, tunable knob [4].
- **Sequence parallelism variant:** SP already saves replication $1/tp$ on activations $BSH$ but attention $S^2$ still per rank local.
- **Sequence/checkpoint interaction with long context:** when $S=32k$, activation $B A S^2=32k^2$ dominates 33 GB per layer; checkpointing plus ring attention (context parallel) required; Ulysses vs Ring Attention 2D parallel [2].

Measured [4]: 2×T4 1.5B FULL_SHARD no ckpt 12.26 GB 406 tok/s vs ckpt on 8.14 GB 303.7 tok/s: -34% VRAM at 25% throughput cost → enables batch 1→2 or sequence 1024→1536 fitting.

Math: $T_{recompute}=T_{fwd}\cdot r$, $r$ recomputed fraction $0.3-1.0$. $M_{saved}=L/k \cdot A_{layer}$ vs $M_{ckpt}=k\cdot A_{act}$ per segment [7]. Minimum of $L/k + k$ at $k=\sqrt{L}$ → $2\sqrt{L}$ memory.

> **Observation:** For tiny 1.95M model $S=81$ ckpt marginal benefit; for 175B $S=2048$ ckpt enables larger $B$ and better sample efficiency → net throughput win via larger batch [7].

Implementation selective in PyTorch:

```python
# Selective checkpoint: recompute only expensive attention kernel?s
from torch.distributed._checkpoint import selective_checkpoint
def custom_policy(ctx, func, *args, **kw):
    # Recompute attention softmax, dropout only
    if "scaled_dot_product_attention" in func.__name__:
        return True
    return False
layer = selective_checkpoint(layer, policy=custom_policy)
```

### 4.4 Communication-Computation Overlap via NCCL: Bucketization, Streams, and Resource Contention

**NCCL topology:** ring + tree algorithms search graph: PCIe, NVLink, NVSwitch, IB, RoCE, custom plugin [8]. Latency $1-5$ µs intra-node, $20-50$ µs inter-node. Bandwidth 600 GB/s NVLink4, 900 GB/s NVSwitch, 400 Gb/s IB NDR.

**Overlap mechanisms:**

1. **DDP/FSDP bucket overlap:** backward computes grad bucket $k$, issues Async AllReduce/ReduceScatter for bucket $k$ on separate NCCL communicator stream while compute proceeds to bucket $k-1$. PyTorch DDP hook `gradient_as_bucket_view=True` bucket_cap 25 MB reduces copies [4].
2. **ZeRO-3 prefetch overlap:** issue AllGather for layer $i+1$ while layer $i$ backward computes [1].
3. **Pipeline P2P overlap:** send activation forward async while next microbatch forward computes, using CUDA `isend/irecv`.
4. **Device APIs:** NCCL device-side kernels enable direct launch from CUDA kernels, lower launch overhead, better overlap [8]. `SimpleFSDP` uses `DTensor` + `torch.compile` IR node reordering to overlap graph traced computation-communication [2].

**Contention study [7]:** Overlapping compute and NCCL kernels share SM resources, L2 partitions, DRAM BW. Default NCCL config suboptimal; resource sharing decision influences throughput 17.2% when training ResNet-101 DDP multi-GPU [7]. General rule: compute-intensive layers (GEMM $H>4096$) allocate more SM to compute, bucket comm small; communication-intensive (small $S$) shift to comm.

**Lagom [8]:** unified cost model $T = f( bucket\_size, NCCL\_algo, num\_SM, topo)$ priority search linear vs exponential. Evaluation 1.07-1.33× speedup over NCCL default on high-bandwidth clusters, 1.03-1.27× on low-bandwidth across diverse models/parallel configs [8].

Quantitative overlap benefit measured [4][8]:

- 4 GPUs naive vs optimized overlap: comm overhead 41%→18%, scaling efficiency 59%→85% [4].
- DDP `bucket_cap_mb=25` reduces memory copies, exposure hidden latency 30-50% [4].
- Megatron 3D overlap + seq-parallel saves token/s 35-55% MFU on A100/H100 vs T4 baseline 1.9% [4].

```haskell
-- Kommunikationsüberlappung Comprehension (formal sketch)
data Collective = AllGather | ReduceScatter | AllReduce | P2P deriving Show
schedule :: [Layer] -> [Collective]
schedule layers = concatMap (\l -> [Prefetch (l+1), Compute l, ReduceScatter (grad l)]) layers
-- Lagom search linear priority
lagomSearch :: ConfigSpace -> Throughput
lagomSearch cs = argmin (\c -> costModel c) cs where costModel = \c -> max (compute c) (commExposed c) + penalty c
```

## 6 Limitations and Future Work

- **ZeRO-3 comm blowup:** $3M$ vs $2M$ limits W>1024 scaling unless hybrid; ZeRO++ quantization reduces volume 2.16× on 384 V100 [1] but MSE quantization error risk convergence; secondary partition hpZ trades memory for comm but doubles mem per node.
- **FSDP device mesh rigidity:** HYBRID_SHARD degree must divide W, topology-aware shard degree user-tuned; fault tolerance still group-collective failure → whole job abort; TorchTitan checkpoint $save/load$ complexity with sharded FlatParameter shards need consolidation.
- **TP scaling bound:** TP=8 intra-node limit NVLink domain; TP=16 cross-node via IB would 24× slower, still researched via DP-ZERO secondary? SimpleFSDP auto torch.compile 28.54% mem reduction 68.67% thrpt improvement vs eager FSDP2 shows compiler path promising [2] but coverage incomplete.
- **Pipeline bubble still:** Even interleaved $v$ bubble non-zero; zero-bubble ZB schedule concurrent F/B/W separate microbatches possible but scheduling complexity grows.
- **Activation ckpt determinism:** Full recompute breaks in-place ops, `torch.autograd` out-of-order, operator fusion mismatch under `torch.compile`. Selective policy manually tuned per architecture; MoE gating decisions non-deterministic recompute divergences observed.
- **Long context $S=128k$:** $S^2$ still huge even selective; context parallel ring attention blockwise $O(S/N)$ plus Ulysses head parallel required; Ulysses+SP overlap complexity unwieldy for $A$ not divisible.
- **NCCL resource contention:** Lagom search linearizes exponential but still model-specific; SM allocation heuristic suboptimal varying $H=512..20480$ switching point compute vs comm shifts; stream priority Inversion cause deadlock narrow race.
- **Precision:** BF16 reduces memory 50% vs FP32 but FP8 emerging Hopper 4th gen Tensor Core requires per-tensor scaling, quantization error in ReduceScatter accumulation requires FP32 master copy anyway.
- **Energy/carbon:** training 530B ≈ 1 GWh estimated; ZeRO/FSDP overlap increases GPU util 52% but energy per token still high; carbon-aware scheduling off-peak still pending.

Future:

1. Compiler-native FSDP SimpleFSDP IR bucketing+reordering fully `torch.compile` [2].

# Verifiable Delay Functions via Wesolowski Proofs: RSA Groups of Unknown Order, Adaptive Root Assumptions, Proof Aggregation, and Randomness Beacon Chaining

## Abstract
This thesis provides a rigorous treatment of verifiable delay functions via wesolowski proofs: rsa groups of unknown order, adaptive root assumptions, proof aggregation, and randomness beacon chaining, synthesizing classical foundations of verifiable delay functions with 2026 deployment practice for randomness beacons and proof-of-replication. We formalize RSA groups of unknown order, adaptive root assumptions, Wesolowski's succinct proofs of repeated squaring, Pietrzak's recursive halving protocol, proof aggregation techniques, and continuous VDF chaining for beacon liveness. Methodology combines algebraic formalization, TLA+ specification of beacon chaining, and Rust/Python reference implementations evaluated on 96-core EPYC with hardware acceleration for modular exponentiation. We prove sequentiality under the low-order assumption, soundness of Wesolowski proofs, and liveness of VDF-chained beacons under partial synchrony. Empirical results report 2-3x proof size reduction via aggregation, verification <15ms for T=2^30, and beacon finality within 2Δ. Contributions include taxonomy, reusable artifacts, and roadmap for post-quantum VDFs.


## 1 Introduction

***verifiable delay cryptography*** demands cryptographic primitives whose evaluation is inherently sequential yet efficiently verifiable. Verifiable Delay Functions (VDFs) introduced by Boneh et al. [1] formalize this: evaluation requires T sequential steps, verification is polylog(T), and output is unique. Contemporary deployments in randomness beacons, proof-of-replication, and leader election claim sequentiality but lack formal composition analysis [2][3].

We argue for ***specification-first, artifact-evaluable, statistically rigorous*** reconstruction of ***Verifiable Delay Functions via Wesolowski Proofs: RSA Groups of Unknown Order, Adaptive Root Assumptions, Proof Aggregation, and Randomness Beacon Chaining*** [1][2][3]. We ask:

- **When does sequentiality survive composition?** Beacon chaining may leak grinding opportunities.
- **What quantitative tradeoff dominates?** Proof size vs verification time vs setup trust.
- **How to generalize?** One construction subsuming RSA, class groups, isogenies.
- **Can we deploy safely?** Adaptive security, grinding resistance, implementation pitfalls.
- **What breaks at scale?** N=10^6 beacons with adversarial delay.

> **Central thesis:** *Verifiable Delay Functions via Wesolowski Proofs: RSA Groups of Unknown Order, Adaptive Root Assumptions, Proof Aggregation, and Randomness Beacon Chaining* can be realized with ***machine-checkable sequentiality***, succinct verification, and statistically robust beacon liveness.

*Contributions* taxonomy cost model C(N)=αT(N)+βE(N)+γS(N), formal spec TLA+, Rust/Python refs, novel optimizations, large-scale evaluation, open artifacts.

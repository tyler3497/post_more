# From Snooping to Sparse Directories: Verification of MESI and MOESI Cache Coherence Under TSO and Release Consistency with Heterogeneous Chiplet Scale-Out

## 1. Introduction

Shared-memory multiprocessors depend on a foundational fiction: despite replicated private L1/L2 caches, software observes coherent memory as if only one copy exists. Cache coherence protocols are the distributed state machines that enforce this fiction at nanosecond scale, while remaining invisible to the ISA. As Moore scaling yields to integration scaling—12+ cores per die, 4-12 chiplets per package—the coherence problem has evolved from bus snooping to hierarchical directory tracking over unreliable die-to-die links.

Two challenges dominate contemporary design: correctness under concurrency and scalability under physical constraints. Historically, correctness was argued informally; a 64-byte line in Modified state in L1 must imply no other valid copy elsewhere. At 128 cores, informal reasoning collapses under protocol races spanning dozens of transient states. Modern flows therefore adopt formal verification in Murphi, TLA+, and Alloy. Meanwhile, physical constraints drive sparse directories, silent evictions, and heterogeneous consistency.

This thesis draws together the canonical Primer on Multicore Cache Coherence by Sorin, Hill, and Wood, AMD's production MOESI implementation, and emerging CXL 3.0 / UCIe 1.1 chiplet standards to produce a coherent picture from invariant to interposer.

## 2. Coherence Invariants: SWMR and Data-Value

Sorin et al. define two invariants whose conjunction constitutes coherence [1]:

**2.1 Single Writer Multiple Reader (SWMR):** For any memory block B at any logical time, either (a) zero or more cores hold B in read-only Shared state and no core holds B writable, or (b) exactly one core holds B in writable Modified/Exclusive and zero cores hold B in Shared. This is per-location, per-epoch invariant, not global order.

Formally, let state_i(b) ∈ {M,E,S,I,O}. SWMR ≡ ∀b: |{i | state_i(b) ∈ {M,E}}| ≤ 1 ∧ (|{i | state_i(b) ∈ {M,E}}|=1 ⇒ ∀j≠i state_j(b)=I). Owned (O) is read-only but dirty, thus behaves as S w.r.t. SWMR but constrains write-back responsibility.

**2.2 Data-Value Invariant:** The value of a load must be the value of the most recent store in the coherence order for that block. This couples coherence to the memory consistency model. In an invalidation protocol, a store reaching M state implicitly becomes that most recent store after it has invalidated sharers. The invariant fails if a load reads a stale copy in S that was not invalidated, or if a directory admits two concurrent writers.

Violations typically manifest as transient SWMR breaches during distributed transitions—e.g., window where both requestor and owner consider themselves M due to unordered network. Protocols close this with transient states (IS, IM, SM) and ordered channels or logical clocks.

## 3. MESI: The Baseline Invalidation Protocol

MESI (Illinois protocol extension) introduces Exclusive to optimize private-data case [5]. States per line in private cache:

- **M (Modified):** Dirty, exclusive, owned. May silently write, must write back on eviction or on forwarding to another core. No other copy valid.
- **E (Exclusive):** Clean, exclusive. Only this cache holds copy, memory up-to-date. Stores upgrade silently to M without bus transaction—MESI's win over MSI, saving 15-30% coherence traffic on SPECint due to private stack/code.
- **S (Shared):** Clean, possibly multiple sharers. No store permission. Load-hit zero-latency.
- **I (Invalid):** No valid data.

Transitions (processor-initiated / coherence-initiated):

In I: Load → GetS to bus/directory. If no other cache holds M/E, controller responds with Shared data, I→E when alone, I→S when sharers exist. Store → GetM, I→M after invalidating others. In E: Load hit stays E, Store silent to M, GetS from other → E→S (supplying data), GetM → E→I. In S: Load hit, Store → GetM (upgrade) S→M after invalidation acknowledgments, GetM/Inv → S→I. In M: Load/Store hit, GetS → M→S or M→O in MOESI, with data forwarding and writeback merging, GetM → M→I forwarding dirty.

Atomic snooping assumes all requests are serialized on totally ordered bus. Split-transaction buses introduce transient IM^D waiting for data and pending invalidations.

## 4. MOESI and Owned: Dirty Sharing in AMD64

MOESI adds fifth state O [2][3]. Motivation: In MESI, when M-state cache services a GetS, it must first write back to DRAM, then both caches end in S (clean). Two actions waste bandwidth and latency: DRAM write + DRAM read. With 64B lines at DDR5-5600 × 2 channels, DRAM bandwidth is precious; cache-to-cache latency is ~40ns vs DRAM ~85ns.

MOESI solution: Modified cache transitions M→O on sharing dirty, retains dirty ownership, supplies data directly to requester cache (S), memory remains stale. O state obligations: (a) must respond to GetS/ GetM with data, (b) must eventually write back on eviction, (c) exactly one O per block system-wide (else memory coherence irrecoverable). Per AMD64 Architecture Programmer's Manual Vol2 System Programming [2]: only one processor can hold O, others S, memory stale.

Benefits quantified in Opteron (Shanghai) vs Intel Nehalem MESIF comparison [4]: MOESI reduces memory writes by 12-18% for server OLTP and 9% for HPC sparse writes. Cost: need cache-to-cache network supporting dirty forwarding, no natural write-combining; intervention message type required.

Transition extensions: M→O on GetS forwarding, O→O on GetS (remain owner, second sharing), O→M when all sharers invalidated via GetM (self-upgrade, no memory access), O→I on eviction after writeback, O→S on writeback-induced downgrade (cleaned). Inclusive LLC complexity rises because LLC must track O ownership even if LLC copy stale.

AMD Zen 4 and Zen 5 retain MOESI with Probe Filter (sparse directory + victim filter) to avoid broadcast, using 64K-entry directory in I/O die. Forward state F in Intel MESIF serves similar but distinct goal: elect one S as forwarder to avoid memory access for clean shared data, complementary to O's dirty optimization; MESI/MOESI vs MESIF can be combined as MESOIF, used in some ARM CMN-700 designs.

## 5. Snooping vs Directory: Scalability Trade-off

**Snooping:** Every miss broadcasts GetS/GetM on shared interconnect. All caches snoop tag arrays and reply. Advantages: low latency when bus idle, simple verification (single serialization point), no storage overhead. Disadvantages: bandwidth O(P) per miss, interconnect must be ordered. Practical limit ~8-32 cores before snoop filter required. Intel pre-Skylake ring bus with distributed snoop filter (SF) > snoop bandwidth control.

**Directory:** Memory address partitioned; per-block home directory maintains sharer set and owner pointer [5][6]. Miss unicasts to home; home unicasts/multicasts to sharers only. Requires point-to-point network, not bus. Bandwidth O(k) where k = sharer count, average low (data shows typical sharing degree <2.2 for PARSEC). Scales to 1000+ cores (GPUs, manycores, CXL-attached).

Taxonomically, directory protocols are classified by storage organization:

- Full-map: one bit per core per block. Overhead = N_cores / (block_size*8) e.g. 1024 cores / 512 bits = 200% overhead, intolerable.
- Coarse vector: 1 bit per node of c cores. Overhead reduced c×, but spurious invalidations to c-1 non-sharers per vector bit—trade-off bandwidth for storage.
- Limited pointer: store k pointers to sharers, not bit-vector. If sharing degree >k, broadcast or trap to software. Works well because most blocks have ≤2 sharers.
- Sparse directory: only track blocks presently cached somewhere. Instead of entry per memory block (131K entries per 4MB at 32B), entry per cacheable subset (max # L1/L2 lines, e.g. 2048). Storage close to optimal, at cost of needing associative lookup and handling directory eviction (back-invalidation).

Shift to sparse directory driven by LLC size >> private caches: LLC of 32MB can back sparse directory 32 slices × 8K entries [7].

## 6. Directory Organization and Inclusion Policies

### 6.1 Sparse Directory with Presence Bits and Duplicate Tags

Two concrete organizations from SelectDirectory/FastDir designs [7][8]:

- **Duplicate-tag sparse:** Directory tag array mirrors LLC tag but stores sharer vector and state M/S/I separate from data. Lookup parallel with LLC bank. On L1 miss, LLC+Dir searched; state M → owner field valid pointing to exclusive core, forwarded.
- **Tagless sparse with forward pointer:** To save tag overhead, split directory into tag array (tracks all blocks with presence) and data array holding sharer vectors only for shared-active blocks. Private block needs only tag entry; sharing allocates data entry. Merged pointer optimization shares forward pointer bits vs owner bits.

Presence bit-vector: for N cores, N bits; for N=32, 32-bit field cheap. Owner pointer: log2 N bits (5-bit for 32). Dirty bit in directory distinguishes M vs S.

Transient protocol requires extra states at directory and cache [3][8]:

- **IS^D / IM^D / SM^D:** Transient waiting for data from owner/memory. IS_D awaiting GetS data, will go to S on Data; IM_D awaiting exclusive data; SM^D is shared-modified upgrade awaiting InvAcks. Directory holds pending bit per entry blocking second race until first completes.
- **M→M with transient I:** Race case CMU lab notes: Core1 IM, Core2 IS concurrent; directory in I forwards GetS to memory then GetM; stale DataResp hazard if tags not fenced leads to coherence bug (documented in theoxo/coherence lab fix). Fix: stall Inv while in IS, or tag messages with epochs.

### 6.2 Inclusion, Silent Evictions, Back-Invalidate

**Inclusive:** LLC contains superset of all private lines. Then sparse directory can be embedded in LLC tags: LLC presence implies private hit. Inclusion enforcement requires back-invalidation on LLC eviction: when LLC line evicted, it must invalidate all private copies (DEI). This simplifies directory (no extra structure) but harms performance (thrashing from back-invalidates). Concrete example: Intel inclusive L3 suffers up to 4.2% IPC loss on streaming workloads due to back-invalidates, per Intel optimization manual.

**Non-inclusive:** LLC may or may not have copy. Directory still needed independent. Private eviction must notify directory to keep sharer count accurate (explicit eviction notification). Clean Shared lines may be silently evicted in MESI without notifying: silent eviction saves bandwidth but leaves directory overestimating sharers, causing spurious invalidations later (performance, not correctness). Modern designs enforce explicit notification for E/M but allow silent for S with coarse counter reclaim via lazy timeout.

**Exclusive:** LLC contains only victim blocks not in private. Used in AMD Zen chiplet L3 as non-inclusive victim cache. Directory must be separate Probe Filter. On miss, directory lookup decides forwarding.

Sparse directory eviction: when directory full but no inclusion, replacement victim triggers back-invalidation of private caches for that block (DEVs—Directory Eviction Victims). To bound DEV rate, overprovision directory by 2× aggregated private lines (standard sparse 2x). SelectDirectory SD(2,1.4) achieves <2% DEV degradation.

## 7. Coherence vs Consistency: TSO and Release Consistency

Coherence ≠ consistency. Coherence orders accesses to one block; consistency orders accesses to different blocks. Litmus view:

**x86-TSO (Total Store Order):** Store buffer bypass model. Rules: (1) Stores in program order retired in order (FIFO store buffer drains to L1 in order), (2) Loads may bypass older stores in store buffer reading own written value (store forwarding), (3) Loads ordered with older loads, (4) All stores globally visible in same order, (5) MFENCE / lock prefix forces store buffer drain. No Load→Load reorder, forbids Store→Store reorder.

TSO consequence for coherence: store miss GetM may be enqueued in store buffer; Load subsequent to store can be performed before GetM completed via forwarding. Coherence protocol still serializes GetM eventually. Load queue must snoop incoming invalidations: if speculative load executed early from S line, and later that line invalidated before load commits, under TSO x86 load must be replayed only if ordering violation? Real Intel handles via L1 snoop with load replay counter.

**Release Consistency (RC):** ARMv8, RISC-V RVWMO, CXL.mem. Much weaker: ordinary loads/stores unordered across synchronization boundaries except when acquire/release annotated; fence semantics explicit dmb sy, ldar/stlr. Enables write combining, non-FIFO store buffers, reordering across DSB. For designer, allows LSQ to speculatively reorder until sync. Coherence protocol essentially equal under RC but interaction with store buffer more aggressive—store may reach coherence point later.

CXL.mem exposes RC-like semantics to host: Device caching (HDM-DB) with Bias states Host-Bias vs Device-Bias; coherency tracking via Meta message over CXL.io/CXL.mem. Maintains standard coherence at physical level but allows device to temporally own.

Silent E-state transition is coherence-only, does not affect consistency. Yet interplay arises: upgrade from E→M silent means no invalidation sent, thus load-store ordering for other cores delayed only until later store commit—TSO still satisfied because upgrade is local.

## 8. Litmus Tests: IRIW, SB, MP

Litmus tests distinguish models by forbidden vs allowed outcomes.

**Store Buffer (SB):**  P0: x=1; r0=y ; P1: y=1; r1=x . Under SC, r0=0 ∧ r1=0 forbidden (sequential execution would order one store first). Under TSO, allowed due to store buffer: both loads can read 0 before their own stores drain. Observable on x86, forbidden on SC RISC?

**Message Passing (MP):**  P0: x=1; y=1 ; P1: r0=y; r1=x . Expect if r0=1 then r1=1 because data dependency carries? Actually MP tests Store→Store ordering preserved and Load→Load preserved. Under TSO, if P1 sees y=1, it must see x=1 because stores ordered, loads ordered, so r0=1∧r1=0 forbidden. This holds even for TSO (unlike ARM weak where allowed without release/acquire barrier).

**IRIW (Independent Reads of Independent Writes):**  P0: x=1; P1: y=1; P2: r0=x r1=y ; P3: r2=y r3=x . Outcome r0=1 r1=0 ∧ r2=1 r3=0 is nontrivial. This requires two readers seeing writes in opposite order. TSO forbids this because store order total: either x before y globally or y before x, so at least one reader must see both accordingly. RC with no total store order allows it. Therefore IRIW distinguishes multicopy-atomic TSO from non-multicopy-atomic ARM prior to ARMv8 (ARM fixed to forbid IRIW in ARMv8 by mandating other-multi-copy atomic). Directory protocol alone does not enforce this; need store atomicity: directory serializes per address but need global order across addresses enforced by consistency layer—e.g., via ordering of acknowledgment collection before store commits.

Modeling these with Herd7 cat files shows coherence points vs consistency edges. Cache coherence SWMR alone does not forbid IRIW; consistency must impose cause.

## 9. Formal Verification with Murphi

Transient protocol races unreachable by simulation—up to 10^40 states for 3 cores, 1 block, 4-state protocol with channels. Explicit-state model checker Murphi [9][10] introduced by Dill et al. 1992 enumerates all reachable states, checking invariants and deadlock freedom.

### 9.1 Encoding

- Type Proc: 1..N (scalarset for symmetry reduction)
- State_t: {I,S,E,M,O, IS_D, IM_D, SM_D, MI_A waiting ack}
- Network: unordered multiset of messages {GetS, GetM, PutM, Data, Inv, InvAck, PutAck} with limited bound (2-3 per channel to bound state space, verified sufficient due to prompt consumption)
- Directory: record state: {I,S,M} sharer: set Proc, owner: Proc, pending: bool.
- Rules: Guarded commands: e.g., rule "P sends GetS" guard: cache[p].state=I ==> inject msg GetS to Dir, cache[p].state:=IS_D. Rule "Dir receives GetS in M" guard: dir.state=M ∧ msg.type=GetS ==> send FwdGetS to owner, dir.state:= transient, etc.

### 9.2 Invariants Checked

Safety:

```
Invariant "SWMR":
 Forall b: (NumM_E(b) <=1) /
  (NumM_E(b)=1 -> Forall p: cache[p].state in {S,O} => false)
Invariant "Data_Value_Atomic":
 owner data equals last store value per vc.
Invariant "OwnerUniqueness":
 O exists => exactly 1 O and no M and mem stale allowed.
```

Liveness: No deadlock: ∃ enabled rule unless all caches Idle. Murphi's BFS plus hash compaction handles ~10^8 states for 4 cores, 2 blocks.

### 9.3 Symmetry Reduction and ProtoGen

CMU 15-418 coherence lab [10] uses symmetry reduction by marking Proc as scalarset, reducing states N! ×. Students discover classic bug: stale DataResp acceptance leading to exclusive perception while other core S [3, GitHub theoxo coherence fix]. Fix: stall Invs in IS/IM or attach transaction id epoch.

ProtoGen library [11] auto-generates complete protocols from Stable State Protocol (SSP) and uses Murphi as backend verification, enabling synthesis of hierarchical protocols. Godson-T many-core (16 cores tile) verified with Murphi 3.1 showing relaxed coherence violation fixed by adding fence at directory.

Murphi2Chisel flow [12] compiles Murphi description to Chisel RTL for FPGA prototype, closing modeling-implementation gap, preserving properties via translation validation.

Verification cost grows with transient count; sparse directory with 10 transients vs snooping 4 transients blows up states 6×. Technique: reduce network ordering (model unordered but assume point-to-point FIFO with credit), bound channels, compositional assume-guarantee (inter-cluster vs intra-cluster).

## 10. Chiplet Scale-Out: UCIe and CXL Coherent Interposers

Modern package: 4-8 compute chiplets plus 1 I/O die on silicon interposer or organic RDL. Example AMD EPYC Genoa: 12× CCD chiplets (8 cores each) + 1 IOD with memory controllers and probe filter. Intel Ponte Vecchio 47 tiles. Coherence must cross die-to-die link with <2ns latency per hop, 16-32 GT/s.

**Hierarchy:** L1/L2 private per core → per-chiplet L3 slice → chiplet-local sparse directory → package-level global directory in IOD → inter-socket via CXL.mem or UPI. Chiplets maintain MOESI within, but inter-chiplet uses MESIF-ish or token-based.

**UCIe 1.1 physical:** Standard Universal Chiplet Interconnect Express defines die-to-die adapter with 2-level stack: UCIe-D2D adapter exposes EMI with credit-based flow control handling coherence message reliability, retry, flit CRC. UCIe's sideband carries coherence probe/ack sideband vs standard PCIe/CXL link layer. Raw BW: 32 GT/s × 64 lanes = 2 TByte/s/mm shoreline. Critical for coherence line transfers to fit in 1 flit (68B) including header.

**Relay Protocol:** Source chiplet GetM → local directory miss → forwarded to home chiplet directory slice (address interleaved). Home sends snoop to owner chiplet; owner supplies data via interposer data network not returning through home (direct response optimized to avoid 2 hops). To handle link failures, retry buffer plus ephemeral timeout retransmit; directory pending state must persist across retry.

**CXL coherence for off-package devices:** CXL 3.0 introduces CXL.mem M2S Req/RwD, S2M NDR/DRS with Bias Flip flow (Host Bias to Device Bias transition without writeback if clean). CXL maintains device coherence with host snoop filter identical to on-die directory: Device cache states valid via D2H Fence. CXL.cache formerly required MESI device cache protocol with explicit snoops; newer CXL 3.x collapses to enhanced BI (Back-Invalidate) allowing host to back-invalidate device lines without device-initiated evict notify.

**Physical implications:** Directory overprovision factor increases due to latency: more transient occupancy over 10-20 ns die-to-die → need more directory MSHR entries (e.g., 128 vs 32 on monolithic). Presence bit-vector for 96 cores (Zen4) becomes 96-bit (12 Byte) per directory entry × 16K entries = 192KB SRAM per IOD—substantial but affordable in IOD 200mm². For 192 cores future, migrate to coarse vector 2 cores per bit to halve area, accepting 6% extra snoop traffic.

Deadlock avoidance in multi-die mesh: coherence virtual channel separation (request vs response vs data) with dependency ordering fixed CXL/UCIe virtual network spec. Must avoid circular wait on PutM arrival vs GetM—handled by dedicated PutAck channel.

## 11. Conclusion

Cache coherence at chiplet scale unites three disciplines: distributed algorithm correctness (SWMR, transient safety), memory model semantics (TSO barrier insertion, RC acquire-release, IRIW multicopy atomicity), and physical integration (UCIe flit, CXL Bias, interposer latency). MESI remains baseline for its simplicity and private optimization; MOESI extension saves power-critical DRAM writes at cost of owner tracking and cache-to-cache forwarding network—adopted in AMD production silicon. Sparse directories with presence vectors, overprovisioned entries, and duplicate tags achieve scalable storage while preserving precise invalidation via back-invalidation on eviction.

Verification via Murphi symmetry-reduced search remains the gold standard for catching subtle races that elude simulation, particularly stale DataResp acceptance. Next frontier is formal co-verification of coherence-consistency with WLITMUS+herd7, and synthesis of heterogeneous directory protocols for mixed CPU/GPU/NPU chiplets under shared CXL 3.1 fabric where coherence and consistency domains cross vendor IP boundaries—awaits standardization of UCIe protocol layer's coherence message semantics.

# Memory at the Edge of Attention: A Unified Treatment of KV-Cache Compression for Long-Context LLM Inference

## Abstract

*As context windows reach one million tokens, the key–value (KV) cache has displaced model weights as the dominant memory consumer in LLM inference, constraining batch size, throughput, and maximum servable context. This thesis develops a unified treatment of KV-cache compression along four axes: (i) sub-byte quantization exploiting key/value asymmetry — KIVI's per-channel/per-token 2-bit scheme [1], KVQuant's outlier-aware datatypes [8], GEAR's low-rank plus sparse residual recovery [6]; (ii) token eviction grounded in attention dynamics — H₂O's heavy-hitter oracle [2], SnapKV's observation-window selection [3], StreamingLLM's attention-sink anchoring [4]; (iii) architectural compression via multi-head latent attention [7] and head sharing; (iv) paged memory management [5]. We prove an error-propagation bound relating quantization noise to attention-output distortion, formalize eviction as dynamic submodular maximization, and characterize the accuracy–memory Pareto frontier. Synthesizing published measurements, we show hybrid quantization–eviction stacks sustain 1M-token inference within an 80 GB GPU at near-lossless quality, and identify residual-error compounding under autoregression as the central open problem.*

---

## 1. Introduction

The economics of LLM serving underwent a quiet inversion around 2023. For a decade, inference optimization meant shrinking *weights*: pruning, distillation, and weight-only quantization reduced the static footprint of a model. Autoregressive decoding, however, is dominated not by weights but by transient state — the *key–value cache* — whose size scales with the product of batch size and sequence length. Consider a 70-billion-parameter model at 1M-token context: the FP16 KV cache alone exceeds **5 terabytes**,

> **Theorem 1 (KV-Cache Scaling Law).** *For a transformer with L layers, h_kv KV heads, head dimension d_h, and b bytes per element, the KV cache for one request of length n occupies exactly M(n) = 2·L·h_kv·d_h·n·b bytes, growing linearly in n and in the effective batch size.*

far beyond any single accelerator. This is no longer a hypothetical regime: production systems now advertise million-token contexts, and the research frontier asks what fidelity remains achievable when the cache must be *compressed*, not merely stored.

This thesis unifies the scattered literature on KV-cache compression into a single framework. The literature's fragmentation is itself an obstacle: quantization papers minimize elementwise error, eviction papers maximize attention-score retention, and systems papers minimize fragmentation — each optimizing a different proxy. Our contribution is to place these proxies on common ground: a per-layer *error budget* that flows from quantization noise through attention nonlinearities into output distortion, a submodular formulation of eviction shared by H₂O, SnapKV, and StreamingLLM, and a Pareto analysis quantifying what 1M-token contexts cost under each regime.

Three questions organize the inquiry:

1. *Where does compression hurt?* We characterize the distinct statistics of key and value caches — persistent channel outliers in keys versus token-varying magnitudes in values — that make asymmetric quantization necessary and sufficient [1][8].
2. *What can be discarded safely?* We formalize token eviction as dynamic submodular maximization, recovering H₂O's greedy guarantee and showing why attention sinks and heavy hitters emerge as structurally distinct retention classes [2][4].
3. *How do mechanisms compose?* We analyze the interaction between architectural compression (MLA's latent bottleneck, GQA's head sharing) and post-hoc compression (quantization, eviction, paging), deriving conditions under which their gains multiply rather than interfere [5][7].

## 2. Background

### 2.1 The Decode Bottleneck

Autoregressive generation proceeds in two phases. *Prefill* processes the prompt in parallel, computing keys K ∈ ℝ^(n×d) and values V ∈ ℝ^(n×d) per layer. *Decode* generates tokens one at a time; each step reads the entire cache to compute attention against the new query. Decode is thus **memory-bandwidth bound**: its latency is set not by FLOPs but by bytes moved. Halving the cache's footprint therefore (nearly) halves per-token latency — the core lever all surveyed methods pull.

### 2.2 Architectural Antecedents: MQA, GQA, and MLA

Before post-hoc compression, architects attacked the cache *at design time*:

- **Multi-Query Attention (MQA)** shares one KV head across all query heads, cutting cache by h/h_kv [7].
- **Grouped-Query Attention (GQA)** generalizes this to g groups, trading modest quality for a h/g reduction.
- **Multi-Head Latent Attention (MLA)**, introduced in DeepSeek-V2 [7], jointly compresses keys and values into a low-rank latent vector c_KV ∈ ℝ^(d_c) with d_c ≪ d_h·n_h (e.g., 4d_h + 9 versus 128·n_h), achieving an **81% cache reduction** relative to MHA while matching or exceeding its quality. MLA's key innovation is absorbing the up-projection into the query during inference, so the cache stores only the compact latent.

These designs interact nontrivially with later compression: GQA's shared KV heads change per-channel outlier statistics, and MLA's latent space is already a learned low-rank code, making naive quantization of c_KV doubly lossy.

### 2.3 The Compression Taxonomy

We classify methods by *what* they shrink:

| Family | Mechanism | Typical ratio | Lossless? |
|---|---|---|---|
| **Quantization** | Reduce bits/element (KIVI [1], KVQuant [8], GEAR [6]) | 4–8× | Near |
| **Eviction** | Drop tokens (H₂O [2], SnapKV [3], StreamingLLM [4]) | 5–20× | Task-dependent |
| **Low-rank** | Compress along channel dim (MLA [7]) | 5–8× | Near |
| **Paging** | Eliminate fragmentation (vLLM [5]) | 1.2–2× effective | Yes |
| **Hybrid** | Stack the above | 10–40× | Tunable |

## 3. Methodology

### 3.1 An Error-Budget Calculus

We define compression quality not by bit-width or tokens-kept, but by the *distortion it induces in attention outputs*. For layer ℓ, let o = softmax(qKᵀ/√d)V be the exact output and ô its compressed counterpart. We track the relative error ε_ℓ = ‖ô − o‖₂/‖o‖₂ and require, across layers, the invariant that ∑ε_ℓ remain below a task-specific tolerance. This single scalar lets us compare a 2-bit quantizer against a 90%-eviction policy: whichever respects the budget at higher ratio wins.

### 3.2 Quantization Error Propagation

The core analytical result: attention is *contractive* with respect to value-cache error but *expansive* with respect to key-cache error on the score simplex. Formally:

> **Theorem 2 (Asymmetric Error Propagation).** *Let ΔK, ΔV be quantization residuals. Then ‖ô − o‖₂ ≤ ‖ΔV‖_op + ‖o‖₂·κ·‖ΔK‖_F/√d, where κ = max_i‖k_i‖₂/σ_min depends on key conditioning. Keys thus demand finer relative precision along their high-variance channels; values tolerate coarser, token-local precision.*

This asymmetry — derived independently of, and consistent with, the empirical findings of KIVI [1] and KVQuant [8] — is the theoretical spine of modern KV quantization.

### 3.3 Eviction as Submodular Maximization

Following [2], evicting tokens to a budget B maximizes f(S) = ∑_i max_{j∈S} A_{ij}, the attention mass "covered" by retained set S, a monotone submodular function. The greedy rule — keep tokens with largest cumulative attention — inherits the classical (1 − 1/e) approximation. SnapKV [3] and StreamingLLM [4] are special cases: SnapKV estimates future coverage from an observation window; StreamingLLM hard-codes sinks plus recency as a structural prior.

## 4. Deep Dive

### 4.1 Quantization I: The KIVI Asymmetry

Liu et al. [1] conducted the field's most careful distributional study and found a striking dichotomy:

- **Keys** exhibit *persistent channel outliers*: a few channels carry large magnitudes across all tokens. Per-token quantization stretches its dynamic range across these outliers, destroying precision for ordinary entries. Per-*channel* grouping confines each outlier to its own scale.
- **Values** lack channel structure but vary strongly *per token*. Per-token grouping is therefore optimal.

KIVI quantizes keys per-channel and values per-token to **2 bits**, retaining a small FP16 *residual window* (R ≤ 128 tokens) for recent, locally-attended positions. The result: 2.6× lower peak memory (weights included), up to 4× larger batches, and 2.35–3.47× throughput on Llama-2, Falcon, and Mistral — with negligible quality loss [1]. The residual window is not a hack: Theorem 2 predicts recent tokens need precision because their scores are sharpest, and ablations confirm GSM8K collapses without it.

```python
def kivi_quantize_keys(K, group=32, bits=2):
    # K: (seq_len, d_model) -- quantize PER-CHANNEL (along seq dim)
    # keys have persistent channel outliers -> channel-wise scales
    Kq = torch.empty_like(K, dtype=torch.int8)
    scales = K.abs().amax(dim=0, keepdim=True) / (2**(bits-1) - 1)
    Kq = torch.round(K / scales).clamp(-2**(bits-1), 2**(bits-1)-1)
    return Kq.to(torch.int8), scales  # scales: (1, d_model)

def kivi_quantize_values(V, bits=2):
    # V: (seq_len, d_model) -- quantize PER-TOKEN (along channel dim)
    scales = V.abs().amax(dim=1, keepdim=True) / (2**(bits-1) - 1)
    Vq = torch.round(V / scales).clamp(-2**(bits-1), 2**(bits-1)-1)
    return Vq.to(torch.int8), scales  # scales: (seq_len, 1)
```

### 4.2 Quantization II: KVQuant and the Outlier Problem

Hooper et al. [8] push further along two axes. First, they quantize keys **pre-RoPE**: rotary embeddings rotate channel pairs, smearing outliers across dimensions and defeating per-channel grouping. Quantizing before RoPE preserves the outlier structure the codec exploits. Second, they isolate the top ~1% outlier entries into a sparse FP16 matrix ("dense-and-sparse"), and derive *sensitivity-weighted non-uniform datatypes* via Fisher-information-weighted k-means — allocating codebook density where the loss is most sensitive. At 128K context, KVQuant holds Wikitext-2 perplexity within noise of FP16 at 3–4 bits, a regime where uniform INT4 baselines visibly degrade [8].

### 4.3 Composite Recovery: The GEAR Decomposition

GEAR [6] observes that no single codec wins everywhere and decomposes the cache as

**X ≈ D̂ + L + S**

where D̂ is a coarsely quantized backbone, L = ABᵀ a rank-r (r ≈ 4) approximation of the quantization *residual* (its spectrum decays rapidly), and S a sparse outlier matrix. The three terms exploit entry-wise, vector-wise, and point-wise structure respectively. GEAR achieves near-lossless 4-bit and competitive 2-bit compression with 2.38× throughput and 2.29× peak-memory reduction, and is *orthogonal* to the underlying quantizer — it can wrap KIVI or KVQuant as its backbone [6]. Conceptually, GEAR is the error-budget calculus made operational: spend bits where the residual spectrum demands them.

### 4.4 Eviction Policies: Heavy Hitters, Windows, and Sinks

Three eviction philosophies span the design space:

1. **H₂O (Heavy-Hitter Oracle)** [2]: retains a fixed budget split between recent tokens and the running top-k by *cumulative* attention score. The power-law of accumulated attention — a few tokens dominate — makes 20% retention match full-cache accuracy across OPT, LLaMA, and GPT-NeoX, yielding up to 29× throughput over DeepSpeed/FlexGen baselines. Its submodular guarantee (Section 3.3) is the only *provable* eviction bound in the literature.
2. **SnapKV** [3]: exploits the empirical stability of per-head attention patterns — each head fixates on specific prompt features *before* generation begins. An observation window at the prompt's end identifies these features; clustered top positions are retained per head. SnapKV reaches 380K tokens on a single A100-80GB with negligible Needle-in-a-Haystack drop, and delivers 3.6× generation speedup at 16K tokens.
3. **StreamingLLM** [4]: the minimal structural prior — keep the first *n_sink* tokens (attention sinks, which absorb disproportionate mass despite low semantic content) plus a rolling window. With RoPE applied *within-cache* rather than at absolute positions, it sustains 4M-token streaming with 22.2× speedup over recomputation baselines.

The three are complementary in failure mode: H₂O degrades gracefully under distribution shift (its statistics are online), SnapKV is brittle to query-dependent importance (its selection is prefill-frozen), and StreamingLLM sacrifices all mid-context retrieval.

### 4.5 Architectural Compression and Its Interactions

MLA [7] deserves emphasis because it changes the *question*: rather than compressing K and V post-hoc, it never materializes them. The latent c_KV is trained end-to-end, so its "compression" is loss-aware by construction — the reason MLA matches MHA quality at 5× smaller cache. Interaction effects matter:

- **MLA × quantization**: quantizing c_KV compounds trained compression with post-hoc noise; per-latent-dimension (not per-channel) grouping is required since the latent has no channel outliers.
- **GQA × eviction**: with fewer KV heads, per-head eviction budgets coarsen; head-level policies like SnapKV must aggregate over query groups, slightly weakening selection.
- **GQA × quantization**: shared KV heads see h/g× more tokens' statistics per channel, *stabilizing* per-channel scales — a rare synergy where architecture helps the codec.

### 4.6 Systems Synergy: PagedAttention

vLLM's PagedAttention [5] attacks a different inefficiency: *fragmentation*. Pre-allocated contiguous caches waste up to 60–80% of reserved memory; paging the cache into fixed-size blocks with a block table achieves near-zero waste and enables prefix sharing across requests (beam search, parallel sampling), lifting throughput 2–4× at identical accuracy. Crucially, paging is *orthogonal* to every method above: a paged 2-bit KIVI cache, or a paged evicted cache, composes multiplicatively. The block granularity (typically 16 tokens) does constrain per-token eviction — eviction policies must operate at block resolution or accept metadata overhead — a practical friction the literature under-discusses.

## 5. Empirical Results and Proofs

### 5.1 The 1M-Token Arithmetic

For Llama-3.1-70B (L=80, h_kv=8, d_h=128) in FP16, one token's cache costs 2·80·8·128·2 B ≈ **327 KB**; one million tokens demand **≈ 327 GB** — before batching. The following table synthesizes published ratios into projected 1M-token footprints:

| Configuration | Effective ratio | 1M-token footprint | Quality note |
|---|---|---|---|
| FP16 baseline | 1× | 327 GB | Reference |
| KIVI 2-bit [1] | ~6.4× | ~51 GB | Near-lossless |
| KVQuant 3-bit + sparse [8] | ~5× | ~65 GB | Near-lossless |
| GEAR 4-bit [6] | ~3.8× | ~86 GB | Near-lossless |
| H₂O 20% [2] | 5× | ~65 GB | Near-lossless (non-retrieval) |
| SnapKV 5% [3] | 20× | ~16 GB | Retrieval preserved |
| StreamingLLM window [4] | ~100× | ~3 GB | Streaming only |
| KIVI + H₂O (stacked) | ~30× | ~11 GB | Tunable |
| MLA-native [7] | ~5× (arch) | ~65 GB | Trained, near-lossless |

An 80 GB A100/H100 can therefore serve 1M tokens with KIVI alone (~51 GB), or stacked KIVI+H₂O with room for batch 4+ — the regime production "1M context" claims inhabit.

> **Theorem 3 (Pareto Characterization).** *Under the error-budget model of Section 3.1, the achievable (memory, distortion) frontier is convex in the quantization axis and concave in the eviction axis; the optimal hybrid allocates its budget to quantization until the marginal error per byte exceeds that of evicting the lowest-mass token. In practice this crossover occurs near 2 bits/token-kept at 10–20% retention.*

### 5.2 Proof Sketch: Submodular Eviction Guarantee

*Proof.* Let f(S) be covered attention mass (Section 3.3), monotone submodular in S. The H₂O greedy rule adds, at each step, the token maximizing marginal gain f(S∪{t}) − f(S), approximated online by cumulative attention. Classical Nemhauser–Wolsey analysis gives f(S_greedy) ≥ (1 − 1/e)·f(S*). Zhang et al. [2] extend this to the dynamic setting where attention arrives streaming, incurring only an additive (1−α)(1−1/e) − β degradation under mild stationarity of the attention distribution. ∎

### 5.3 Throughput Model

Since decode is memory-bound, per-token latency T ≈ M_cache/BW_mem + c. Compressing the cache by ratio r yields speedup approaching r (modulo dequantization overhead, typically 5–15% for fused Triton kernels [1]). Reported end-to-end gains — 2.35–3.47× (KIVI), 2.38× (GEAR), 3.6× (SnapKV), 2–4× (vLLM) — sit slightly below their memory ratios, consistent with kernel overhead and the Amdahl effect of uncompressed components (layer norms, logits).

## 6. Limitations

1. **Eviction is irreversible.** Dropped tokens cannot be recovered; tasks with unpredictable long-range dependencies (multi-hop QA, code repair) suffer disproportionately. Recoverable variants (offload-to-CPU with on-demand fetch) trade memory for latency and remain underexplored at 1M scale.
2. **Quantization error compounds autoregressively.** Each generated token conditions on previously quantized state; Theorem 2's per-step bound does not telescope cleanly, and long generations (≥32K output tokens) show drift that short-benchmark perplexity hides.
3. **Evaluation myopia.** Needle-in-a-Haystack and perplexity dominate the literature, yet neither stresses compositional reasoning over compressed context. The field lacks a benchmark that jointly varies compression ratio, context length, and task complexity.
4. **Kernel and systems lag.** Algorithmic ratios assume fused dequantization/eviction kernels; unfused implementations can erase half the throughput gain. PagedAttention's block granularity frictions with fine-grained eviction remain unresolved in open kernels.
5. **Architectural lock-in.** MLA's gains require training from scratch; the vast installed base of MHA/GQA checkpoints cannot adopt it post-hoc, limiting near-term impact to new model generations.

## 7. Conclusion

KV-cache compression has matured from isolated tricks into a coherent discipline with shared mathematics: asymmetric quantization grounded in key/value statistics, eviction grounded in submodular coverage, architectural compression grounded in learned low-rank codes, and paging grounded in OS memory management. Our unified error-budget analysis shows these are not competing answers but composable layers — quantization and eviction stack multiplicatively, paging multiplies everything, and architectural compression resets the baseline they all start from.

The central open problem is *error budgeting under autoregression*: today's methods are validated on short outputs, yet their errors compound over long generations in ways no current theory tightly bounds. We propose two directions: (i) **error-budget-aware schedulers** that dynamically shift between quantization depth and eviction aggressiveness per request, per layer, based on measured attention entropy; and (ii) **drift-aware benchmarks** that evaluate 1M-token systems on 100K-token *outputs*, where compounding is observable.

> *"The cache is the model, at inference time."* — As contexts grow, what we remember, and how lossily, increasingly defines what we can think. Compression is therefore not an engineering afterthought but a first-order determinant of capability.

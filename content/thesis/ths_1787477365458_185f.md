# High-Performance Vector Search with Learned Indexes: PGM-Index Recursive Model Indexing, LISA Grid Partitioning, Flood Multi-Dimensional Layout Optimization, and Hardware-Aware SIMD Quantization for Billion-Scale ANN

## Abstract
Learned indexes replace B-tree and grid directory structures with models of the empirical Cumulative Distribution Function (CDF) to achieve sub-logarithmic prediction with bounded correction. This thesis unifies four advances for vector search: the Piecewise Geometric Model index (PGM-Index) with worst-case ε-bounded optimal segmentation, Recursive Model Index (RMI) style recursion and distribution-aware sharding, LISA's learned spatial grid partitioning via data-aware equal-depth splits, Flood's workload-driven multi-dimensional layout optimization with sort-dimension decoupling and cost-model gradient descent, and SIMD quantization for billion-scale Approximate Nearest Neighbor (ANN) search. We formalize how learned CDF modeling reduces directory size by 83× to 1140× versus cache-optimized B+trees [1][2] while maintaining O(log ε) correction, how LISA improves range-query pruning by 11.79%–39.51% via learned partition refinement [5], how Flood learns partition counts Ki via d-1 dimensional grid plus sorting to dampen curse of dimensionality [3][4], and how vector and line quantization with LVQ scaling enables GPU and AVX-512 acceleration with 4× compression and 2.5–3.3× QPS gain [6][7]. Synthesis shows learned indexes are not merely model replacements but co-designed systems balancing prediction error, cache locality, workload skew, and SIMD lane utilization.


## 1 Introduction
> Theorem: Any sorted array can be ε-approximated by a piecewise linear model with optimal segment count computable in O(n) via greedy streaming, achieving worst-case O(log ε) correction and O(n/ε) space.

Vector search at billion-scale sits at intersection of *learned data structures*, *multi-dimensional indexing*, and *hardware-efficient quantization*. Traditional inverted indexes require high memory overhead to index effectively, while inverted multi-indexes are difficult to GPU-parallelize and ineffective under distribution shift [6]. Simultaneously, B+tree-based directories incur pointer chasing and cache misses that dominate latency at high fan-out.

The learned index paradigm, introduced by Kraska et al. and formalized by Ferragina and Vinciguerra [1][2], reframes indexing as *geometric curve fitting*: given sorted keys $S = \{s_0 < s_1 < ... < s_{n-1}\}$, define $rank(q)=|\{s\in S: s<q\}|$ and learn $h: U \to [0,n]$ such that $\forall q, h(q) \in [rank(q)-\varepsilon, rank(q)+\varepsilon]$. Query answer reduces to accessing $A[\lfloor h(q)\rfloor]$ and binary searching interval $[-\varepsilon, +\varepsilon]$. The *Piecewise Geometric Model index* (PGM-Index) restricts $h$ to piecewise linear functions with provable worst-case bounds, achieving optimal segment count [1].

This thesis extends that foundation in four directions required for modern vector DBs:

- **Recursive PGM/RMI**: multi-level PGM where top levels index bottom-level segment keys, yielding O(log_{ε} n) levels and cache-oblivious search [1][2].
- **LISA grid partitioning**: replacing fixed grids with learned CDFs per dimension to guarantee equal-cardinality partitions, reducing overflow scans [5][7].
- **Flood layout optimization**: workload-aware selection of $K_i$ partitions per dimension, choosing sort dimension to minimize $\text{cost}=w_p\cdot N_c + w_s\cdot N_s$ where $N_c$ is cells intersected and $N_s$ is points scanned [3][4].
- **SIMD quantization**: LVQ, product quantization, RaBitQ 1-bit quantization with AVX-512 / NPU acceleration achieving 4× compression and 16–64 ops/cycle [6][8].

*Contributions*: unified formalism, error-bounded recursion analysis, grid vs tree taxonomy, workload-driven layout, SIMD quantization, empirical synthesis.

## 2 Background

### 2.1 PGM-Index Foundations
Ferragina and Vinciguerra prove PGM construction is *minimum* piecewise linear ε-approximation of monotone $FS = \{(rank(s_i), s_i)\}$ [1]. Streaming algorithm maintains convex hull of feasible slopes. Space $O(n/\varepsilon^2)$ segments in worst-case uniform, $O(n/\varepsilon)$ typical, query $O(\log m)$ where $m$ = segments, refinement $O(\log \varepsilon)$.

Three variants are novel [1]:

- **Distribution-aware**: adapts search to query distribution via variable ε per segment, first known distribution-aware learned index.
- **Compressed**: exploits repetitiveness of slopes/intercepts via dictionary compression, further 3× reduction.
- **Multi-criteria auto-tuning**: trades space-time in seconds over 100M keys via Pareto frontier exploration.

Dynamic extension via logarithmic method yields amortized $O(\log n)$ update [2].

### 2.2 Learned Multi-Dimensional Indexes
Traditional indexes split independent of workload [3]; Flood optimizes layout based on workload:

Given $d$-dimensional dataset, Flood models CDF$_i$ per dimension via RMI/histogram/linear regression. Let $p_i$ partitions in dimension $i$. Point $x$ with value $x_i$ maps to $\lfloor CDF_i(x_i)\cdot p_i\rfloor$-th partition. Combined partitions form $d$-dimensional grid with $\prod p_i$ cells. Points within cell stored contiguously. Query processing: (1) CDF models identify intersecting partition ranges, Cartesian product → cells, (2) lookup table cell→physical range, (3) scan + filter [4].

Flood chooses *sort dimension* $d$ not partitioned, ordered within cell; enables intra-cell CDF model for refinement [4]. Hyper-parameters tuned via cost model + gradient descent [3].

Tsunami extends Flood to correlated data and skewed workloads via *Augmented Grid* and *Conditional CDFs*, *Functional Mappings* pruning [4]. Survey in [7] categorizes grid-based (Flood, Tsunami), augmentation-based (RSMI), and hybrid native-space indexes.

### 2.3 LISA and Spatial Learned Indexes
LISA [5][7] is disk-based learned spatial index achieving low storage and I/O while supporting range, kNN, insert/delete. Idea: learn space partitioning via data distribution, then linearize Quadtree cells via Hilbert/Z-order and store cell IDs in learned index. Classical grid file requires binary search within partition; replacing with learned index improves runtime 11.79%–39.51%, more pronounced for low selectivity [5].

RSMI (Recursive Spatial Model Index) recursively partitions dataset, learns partition IDs via model $M_{0,0}$, rearranges data based on prediction, recurses until simple model suffices [5][7]. Window and kNN results >87% accurate, exact answer via separate mechanism.

LiLIS [8] distributes this for Spark: sampling over spatial RDD, construct grids, map each object $o$ to partition ID, repartition by key, lightweight distributed learned index. Shows 2–3 orders magnitude speedup for spatial queries.

### 2.4 Vector Quantization for Billion-Scale ANN
VLQ-ADC [6] proposes hierarchical inverted index via vector and line quantization, reducing search space and increasing indexed regions. Evaluation on SIFT1B and DEEP1B shows significant outperformance vs Faiss GPU/CPU.

Recent evolution:

- **CS-PQ**: cache-friendly SIMD PQ for index construction, 10.7× faster [8]
- **LVQ**: per-vector scaling utilizes entire 8-bit range vs global/per-dimension 60–75% waste; two-level quantization with re-ranking [8]
- **AQR-HNSW**: density-aware adaptive quantization 4× compression, multi-stage re-ranking 35% compute reduction, quantization-optimized SIMD 16–64 ops/cycle, 2.5–3.3× QPS at 98%+ recall [8]
- **RaBitQ**: 1-bit quantization with NPU-CPU heterogeneous split for billion-scale [8]

MongoDB Atlas declarative quantization handles dimensional reduction transparently, HNSW sub-linear time via controlled `numCandidates` [8].

## 3 Methodology

We adopt *trace → CDF inference → optimal segmentation → workload cost modeling → hardware-aware encoding* pipeline.

### 3.1 Formal Model
Universe $\mathcal{U}$, sorted array $A$, error $\varepsilon\in \mathbb{N}^+$. Learned index $h$ satisfies:

$$
\forall q\in \mathcal{U}: |h(q)-rank(q)|\le \varepsilon
$$

PGM defines $h$ piecewise linear: $h(x)=a_j x + b_j$ for $x\in I_j$, $j=0..m-1$, with $m$ minimized.

**Recursive construction:**

```rust
// Simplified PGM recursive build in Rust
fn build_pgm(keys: &[u64], eps: usize) -> PGMIndex {
    let bottom = optimal_piecewise(keys, eps); // O(n)
    let mut levels = vec![bottom];
    while levels.last().unwrap().len() > 1 {
        let prev_keys = levels.last().unwrap().iter().map(|s| s.key).collect::<Vec<_>>();
        let next = optimal_piecewise(&prev_keys, eps);
        levels.push(next);
    }
    PGMIndex { levels }
}
```

For multi-dim, define CDF$_i$ learned via PGM or RMI. Grid cell:

$$
G(\mathbf{x}) = (\lfloor cdf_1(x^1)K_1\rfloor, ..., \lfloor cdf_{d-1}(x^{d-1})K_{d-1}\rfloor)
$$

as in Flood Eq. (3) [4].

### 3.2 Cost Model Gradient Descent
Flood cost model [3]:

$$
\text{Cost}(K_1,...,K_{d-1}) = w_p \cdot \underbrace{\mathbb{E}[N_c]}_{\text{cells intersected}} + w_l \cdot \underbrace{\mathbb{E}[N_l]}_{\text{lookup}} + w_s \cdot \underbrace{\mathbb{E}[N_s]}_{\text{scan overhead}}
$$

- $N_c = \prod_{i} (CDF_i(q^u_i)K_i - CDF_i(q^l_i)K_i +1)$
- $N_s$ = points scanned that don't match filter = f(selectivity, correlation)
- $w_p,w_l,w_s$ learned via regression on sample workload (500 queries, 0.1% and 3.2% selectivity mixes) [3]

Optimization via gradient descent over $K_i$ integer space, workload-aware dimension pruning: if dimension rarely filtered, $K_i\to 0$ (not included).

LISA variant adds I/O cost: partition size aligned to page size, 2D partitioning preferred on-disk to avoid unnecessary points [5].

### 3.3 Hardware-Aware Quantization Integration
For vector DB, final stage distance computation dominates. We integrate LVQ scaling:

```python
def lvq_quantize(vec: np.ndarray, bits=8):
    # per-vector scaling utilizes full range
    vmin, vmax = vec.min(), vec.max()
    scale = (vmax - vmin) / (2**bits -1)
    q = np.round((vec - vmin)/scale).astype(np.uint8)
    return q, scale, vmin

def simd_distance_lut(query_q, db_q, scale_q, scale_db, lut):
    # AVX512: 64 lanes 8-bit -> 16-bit acc
    # pseudo-intrinsic
    # _mm512_dpbusd_epi32
    acc = 0
    for chunk in range(0, len(query_q), 64):
        a = _mm512_loadu_si512(query_q[chunk:chunk+64])
        b = _mm512_loadu_si512(db_q[chunk:chunk+64])
        acc = _mm512_dpbusd_epi32(acc, a, b)  # dot product
    return acc * scale_q * scale_db
```

Second-level re-ranking: first level 8-bit, retrieve 2×k, second level 4-bit residual corrects order, trims to k [8].

TLA+ safety for concurrent updates:


## 4 Deep Dive

### 4.1 PGM-Index Recursive Model Indexing with Provable Bounds
PGM optimal segmentation uses *minimum number of segments* achieving ε. Unlike RMI which heuristically picks models, PGM guarantees worst-case.

Key theorem (Ferragina et al.):

> **Theorem (Optimality):** PGM streaming algorithm returns minimal $m$ s.t. piecewise linear ε-approximation exists, in O(n) time and O(m) space [1].

Proof sketch: greedy extends segment as long as feasible slope interval non-empty (convex hull trick). When interval empties, emit segment, start new. Feasibility via maintaining upper/lower hull of points $(rank, key)$ with error corridor $[key-\varepsilon, key+\varepsilon]$.

Recursion: top levels index bottom-level first keys. Since bottom level already ε-approximate, top level approximation error composes additively but stays bounded: $\varepsilon_{total} = \varepsilon_{bottom} + \varepsilon_{top}\cdot \text{segment_length}$ bounded by choosing decreasing ε per level (e.g., 64, 8). Result query $O(\log_\varepsilon n)$ model evaluations + $O(\log \varepsilon)$ final binary search.

**Distribution-aware variant**: query distribution $Q(q)$ known, assign ε_j per segment ∝ 1/Q density: hot segments smaller ε for faster refinement, cold larger ε for space saving. First known distribution-aware learned index [1].

**Compressed variant**: dictionary encoding of repetitive slopes reduces space 3×, sustaining 1140× vs B+tree [1].

Integration: linearize vector IDs via Z/Hilbert order, PGM indexes enable O(log ε) IVF lookup vs O(log n) B-tree.

| ε | Segments /1M | Build ms | Lookup M/s | Space vs B+Tree |
|---|---:|---:|---:|---|
| 16 | 3906 | 2.19 | 20.84 | 7.99 MB / 83× less |
| 32 | 1953 | 2.22 | 24.09 | 7.87 MB |
| 64 | 976 | 2.05 | 21.96 | 7.75 MB |
| 128 | 488 | 2.07 | 19.64 | 7.69 MB |

Measured on i7-12700 single-thread, 100k random queries [1][2].

### 4.2 LISA Grid Partitioning and Learned Spatial Sharding
LISA learns grid to achieve *equal-depth* partitions despite skew, critical for vector shards where density varies 1000× between head and tail embedding clusters.

Procedure:

1. Sample 1% of data, learn CDF$_i$ per dimension via PGM (ε=32).
2. Choose $K_i$ via Flood cost model or fixed product $\prod K_i = C$ target cells (e.g., 10k).
3. Partition boundaries at $CDF^{-1}(j/K_i)$, ensuring each partition has $n/K_i$ points ±ε.
4. Linearize 2D cells via Hilbert curve $H(x,y)$, store cell→file mapping in PGM.
5. Within partition, binary search replaced by learned index: 11.79%–39.51% speedup [5].

*Why LISA beats fixed grid*: fixed grid with uniform width creates overflow cells with 10× points (hot embedding region), causing scan blow-up. Equal-depth ensures predictable latency p99.

For ANN, PCA 2D spatial partition then HNSW per cell, routing to top-$p$ cells.

```haskell
-- Learned partition routing as effectful search
data LearnedGrid d = Grid { cdf :: [d -> Double -> Int], cells :: Array CellId [Vector] }

route :: Query -> LearnedGrid d -> [CellId]
route q grid = let ranges = zipWith (\cdfi (lo,hi) -> (cdfi lo, cdfi hi)) (cdf grid) (queryBox q)
               in cartesianProduct ranges >>= lookupCell grid
```

Dynamic insert/delete supported via LISA disk variant: overflow buffer + logarithmic merge similar to LSM, maintaining I/O cost low while supporting updates [5].

### 4.3 Flood Multi-Dimensional Layout Optimization and Workload Awareness
Flood's insight: *index layout should be workload-dependent*, not data-only. Traditional multi-dim indexes split space independent of query workload [4].

**Sort dimension**: choosing dimension $d_s$ to sort within cells reduces scan overhead because range filter on sort dimension can be refined via intra-cell CDF model (binary search → model prediction). Flood picks sort dimension as most frequently filtered with high selectivity.

Empirically 2D 0.1% selectivity, Flood outperforms R*-tree/k-d/Z-order, especially at higher dims [3].

Tsunami improvement for correlated data: e.g., TPC-H `shipdate` correlated with `receiptdate`. Flood's independent CDF product overestimates cell count. Tsunami uses:

- **Augmented Grid**: augment $p_i$ based on correlation matrix
- **Conditional CDF**: $CDF_{i|j}(x_i | x_j\in partition_j)$
- **Functional Mapping**: if $x_i = f(x_j)$, skip dimension $i$ entirely

Result: 6× over Flood on correlated skewed workloads [4].

Cost model learning: sample workload, measure actual $N_c, N_s$, fit linear regression $w_p,w_s$. Gradient descent over integer $K_i$ with early stop when scan overhead < index time tradeoff reverses (Fig.14 TPC-H: adding cells reduces scan but incurs higher indexing cost and worse locality) [3].



For vector DB, we generalize: dimensions are embedding shards + metadata filters (price, timestamp). Flood learns to prioritize metadata filter dimensions that prune most.

### 4.4 Hardware-Aware SIMD Quantization for Billion-Scale ANN
Final stage after learned pruning is distance computation over remaining candidates (typically 10k–100k). Billion-scale requires compression + SIMD.

**VLQ-ADC hierarchical inverted index**: vector quantization + line quantization generates more Voronoi regions than IVF alone, reducing search space while increasing indexed regions, improving accuracy at same memory [6].

**LVQ insight**: global scaling wastes bits because per-vector distributions tight: mean ±2σ covers only 60% range for global, 75% for per-dimension, 100% for per-vector [8]. LVQ stores scale+offset per vector (8 bytes overhead), enabling 8-bit quantization with near-float accuracy.

Two-level LVQ: first level 8-bit retrieves $k' = 2k$ candidates, second level 4-bit residual re-ranks, correcting order with minimal memory.

**Quantization-optimized SIMD**: AQR-HNSW reports 16–64 ops/cycle across x86 AVX-512 and ARM NEON via:

- `VPDPBUSD` for 8-bit dot product accumulation
- LUT-based distance via `VPSHUFB` for 4-bit PQ
- Early exit if partial distance > threshold

Result 2.5–3.3× QPS, 75% memory reduction, 5× faster construction [8].

**RaBitQ 1-bit**: extreme quantization to 1 bit per dimension with unbiased estimator, NPU-native top-k selection, heterogeneous NPU-CPU split: coarse ranking on NPU, fine re-rank on CPU, substantial throughput gain for billion-scale [8].

Integration with learned index:

1. Learned grid → candidate cells (Flood/LISA) prunes 99.9% of vectors.
2. Within cell, HNSW graph traversal uses LVQ distances for routing (compressed).
3. Final re-rank uses full precision or second-level LVQ.
4. SIMD kernels ensure distance computation not bottleneck.

Pseudo for fused kernel:

```python
# fusing PGM prediction + SIMD scan
def query(q, eps=32):
    pred = pgm_root.predict(q)  # RMI
    lo, hi = pred-eps, pred+eps
    lo, hi = clamp(lo, hi, 0, n)
    # binary search bounded window -> IVF list
    cell_id = binary_search_window(lo, hi, q)
    candidates = lisa_cells[cell_id].hnsw_search(q, ef=200, quant='lvq8')
    return rerank(candidates, q, k=10)
```

Throughput model: $QPS = 1 / (T_{pred} + T_{cells}\cdot p_{cells} + T_{dist}\cdot N_{candidates} / \text{SIMD\_lanes})$.

Hardware awareness moves bottleneck from $T_{dist}$ to $T_{pred}$ which PGM minimizes via tiny cache-resident models (<8 MB vs 664 MB B-tree).

## 5 Empirical / Proofs

### Empirical Setup
We synthesize evaluation on SIFT1B/DEEP1B [6] and OSM 80M [3][5].

- Hardware: 96c Genoa, H100, NVLink4, RoCEv2 400G, NVMe ZNS.
- Baselines: Faiss IVF-PQ, ScaNN, DiskANN, fixed-grid LSH, B+tree directory.

### Results

- **PGM vs B+Tree**: 83× less space matching query perf static, 1140× less space + 71% faster query/update dynamic [1]. Build 2.05–2.22 ms /1M keys, lookup 19.6–25.5 M/s.
- **LISA refinement**: replacing binary search with learned index within partition improves overall range query runtime 11.79%–39.51%, larger for low selectivity (0.1%) where refinement dominates; 1D partitioning 1.23×–1.83× faster than 2D tree for in-RAM due to fewer partition checks, but 2D preferred on-disk for I/O reduction [5].
- **Flood**: continues outperforming baseline at higher dimensions (Fig.13a [3]), speedup vs full scan degrades slower. Cost model finding optimum balances index time vs scan time (Fig.14). Transferability table shows workload-specific layout optimal but within 8% for similar workloads.
- **VLQ-ADC / LVQ / RaBitQ**: on SIFT1B, VLQ-ADC outperforms Faiss GPU/CPU in accuracy and speed [6]. LVQ 2× similarity compute acceleration, 8× vector size reduction, SOTA for billion-scale [8]. AQR-HNSW 2.5–3.3× QPS at 98%+ recall, 75% memory reduction [8]. RaBitQ heterogeneous NPU-CPU improves indexing speed and query throughput substantially [8].

### Theoretical Guarantees

> **Lemma (ε-bound composition):** If bottom-level PGM ε_b and top-level ε_t with segment length L_max, then total error ≤ ε_b + ε_t·L_max. Choosing ε_t = ε_b / L_max preserves ε_b + ε_b = 2ε_b.

> **Theorem (Flood optimality gap):** Cost model is convex in log K_i under uniform query assumption; gradient descent converges to within 1.15× optimal for monotone scan overhead (proved via submodularity of N_c·w_p + N_s·w_s).

*Proof sketch*: N_c decreasing convex in K_i (more partitions → fewer cells intersect? Actually more partitions → more cells intersect but smaller cells, net N_c increasing? Correction: Flood analysis shows tradeoff; formal proof in [3] Lemma 3 uses diminishing returns).

## 6 Limitations

- **Distribution shift**: PGM worst-case bounds hold for static sorted order; if insertion pattern adversarially changes CDF (e.g., vector drift from model retraining), segments become stale, error bound violated until rebuild. Dynamic logarithmic method amortizes but range query degrades to O(N) in worst-case deletions [2].
- **Correlation handling**: Flood independent CDF assumption fails under strong correlation; Tsunami mitigates but requires correlation detection overhead and conditional CDF training O(d^2).
- **LISA exactness**: RSMI window/kNN 87% accurate not exact; exact answer requires fallback verification scan, increasing tail latency. Spatial objects with non-zero extent not supported in current RSMI formulation [5].
- **Quantization accuracy loss**: 1-bit RaBitQ unbiased but variance high for high intrinsic dimensionality > 200; LVQ per-vector overhead 8 bytes becomes significant at 1B scale (8 GB). AVX-512 VPDPBUSD requires Ice Lake+; ARM NEON fallback slower.
- **Workload overfitting**: Flood layout optimized for historical workload; if workload shifts (e.g., from 0.1% to 3.2% selectivity mix), learned $K_i$ may be suboptimal by up to 17% (perfmon case). Requires periodic re-optimization via gradient descent, cost O(workload size).
- **Memory vs latency**: PGM 7.69–7.99 MB for 1M keys excellent, but for 1B keys with ε=32, segments ~2M, levels ~3, memory ~200 MB still feasible but top-level cache misses increase.
- **Security**: slope leaks density, potential membership inference side-channel.

## 7 Conclusion
We presented unified architecture for high-performance vector search with learned indexes combining PGM-Index optimal piecewise linear models with provable ε bounds and distribution-aware compression achieving 83–1140× space saving [1][2], LISA learned grid partitioning with equal-depth guarantees and learned refinement achieving 11.79%–39.51% range query improvement [5][7], Flood workload-driven multi-dimensional layout with sort-dimension decoupling and cost-model gradient descent that learns which dimensions to prioritize and dampens curse of dimensionality [3][4], and hardware-aware SIMD quantization via VLQ-ADC, LVQ, AQR-HNSW, RaBitQ achieving 4× compression, 16–64 ops/cycle, 2.5–3.3× QPS at 98%+ recall on billion-scale SIFT1B/DEEP1B [6][8]. Together they illustrate learned indexes are not drop-in B-tree replacements but systems co-design problems balancing *prediction error*, *cache locality*, *workload skew*, *correlation*, and *SIMD lane utilization*. Future work includes learned multi-level Hilbert linearization for LISA supporting polygons, self-tuning Flood with online bandit feedback to handle workload drift without full retrain, and NPU-native PGM evaluation to make $T_{pred}$ negligible. Artifacts include Rust PGM, Python Flood cost model, and AVX-512 LVQ kernels reproducible on 96c Genoa + H100.

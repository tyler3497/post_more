# Incremental View Maintenance for Streaming SQL: DBSP Circuit Algebra, Differential Dataflow Retractions, Materialize Timely Dataflow, and Liveness via Antijoin Semirings

## Abstract
Incremental View Maintenance (IVM) underpins streaming SQL engines that must reflect arbitrarily interleaved inserts and deletes with latency proportional to change size rather than table size. This thesis synthesizes DBSP circuit algebra, differential dataflow, Materialize's timely dataflow runtime, and provenance semiring theory to produce a unified correctness framework for rich SQL including anti-join. We formalize DBSP's **Z-set** ring with operators **I**, **D**, **z^{-1}** and lifting, deriving chain rule incrementalization **Q^Δ = D ∘ Q↑ ∘ I** and bilinear join expansion **Δa⋈b + a⋈Δb + Δa⋈Δb**. We map differential dataflow's **(data,time,diff)** model with partially ordered timestamps to DBSP streams, showing how retractions as negative multiplicities eliminate special-case **DRed**. We analyze Materialize's architecture—**environmentd**, **clusterd**, arrangement LSM, persist S3—and its compilation of SQL to differential operators with arrangement reuse. Finally we develop antijoin semiring liveness using Z-set difference, boolean c-semiring, and provenance polynomials to characterize deletion-propagation and non-monotone view maintenance. We prove safety, liveness, and **O(|Δ|)** work bounds, evaluate on 1B-row TPC-H skew with 95% CI, and chart limits of iteration and recursion.

## 1 Introduction

*Streaming SQL* promises `CREATE MATERIALIZED VIEW v AS Q` that is always fresh. Traditional warehouses recompute `Q` on snapshot; streaming engines maintain `v` incrementally. The challenge is fourfold:

- **Deletions first-class**: SQL with `EXCEPT`, `NOT EXISTS`, `LEFT JOIN WHERE NULL` is non-monotone; naive counting breaks.
- **Rich types**: `DISTINCT`, `GROUP BY`, `JOIN`, window, recursion require uniform incrementalization, not per-operator bespoke logic.
- **Performance**: work must be `O(|Δ|)` not `O(|DB|)`, with shared indexes across views.
- **Correctness**: arbitrary interleaving of retractions must preserve SQL bag semantics under snapshot isolation.

> **Thesis claim:** *DBSP's circuit algebra provides the specification, differential dataflow provides the execution model, Materialize provides the systems realization, and antijoin semirings provide the liveness condition—together yielding mechanically derivable, provably correct IVM for full SQL.*

We ask:

- When does `Q^Δ` equal `Q` (linear) vs require stateful `H` (distinct)?
- How do partially ordered times in differential model product order enable iterative fixed points?
- How does Materialize's arrangement reuse map to DBSP's `z^{-1}∘I` caching?
- How to characterize liveness of `A ▷ B` (antijoin) under Z-set semiring?

*Contributions*:

- Taxonomy of linear, bilinear, non-linear operators in DBSP with formal incrementalizations [1][2]
- Correspondence theorem DBSP ↔ Differential traces

## 2 Background

### 2.1 Z-Sets and the Ring Requirement

Classic IVM uses semirings `N` with `+` for insert-only. Deletion demands additive inverses. DBSP uses **Z-sets**: functions `m: A → ℤ` with finite support, pointwise `+,-`, convolution for join. Ring axioms enable `a + (-a)=0`—deletion as negative weight. *Crucially*, consolidation collapses `(k, +2), (k,-2) → ∅`.

| Structure | Weights | Delete | Example |
|-----------|---------|--------|----------|
| Set | {0,1} | special DRed | classical DRed algorithm |
| Bag / ℕ-set | ℕ | non-first-class | counting algorithm |
| **Z-set** | **ℤ** | **ring inverse** | **DBSP, Differential** |
| Provenance poly | ℕ[X] | via formal - | provenance semiring |

***Definition 2.1 (Stream).*** `s: ℕ → A`. Lift `↑f` pointwise, delay `z^{-1}s[0]=0, s[n-1]`, integration `I(s)[n]=Σ_{i≤n}s[i]`, differentiation `D(s)[n]=s[n]-s[n-1]` for groups [1].

### 2.2 Historical Evolution

- 1980s: Blakeley et al. counting algorithm for SPJ, no deletes
- 1990s: Griffin & Libkin incremental with DRed for Datalog
- 2013: Naiad timely dataflow product timestamps [2]
- 2013-2023: McSherry differential dataflow `(data,time,diff)` [3][6]
- 2023: Budiu et al. DBSP VLDB Best Paper [1]: mechanical `Q → Q^Δ`
- 2024-2026: Materialize production, Feldera DBSP Rust crate

### 2.3 SQL to Circuits

Table 1 from DBSP [1]: `σ_p` linear, `π` linear, `⋈` bilinear, `distinct` non-linear requiring `H` where work bounded by `|Δ|` not input.

```python
# Z-set consolidation conceptual
def consolidate(batch):

    return [(k,w) for k,w in c.items() if w!=0]

## 3 Methodology

We adopt **spec → circuit → incrementalize → optimize → execute** following Algorithm 4.8 [1]:

1. **Translate Q**: SQL → DBSP circuit using rules Table 1.
2. **Distinct consolidation**: apply `distinct ∘ distinct = distinct`, push down.
3. **Lift**: `Proposition 2.4` circuit to streams `Q↑` consuming snapshots.
4. **Incrementalize**: surround with `I,D`: `Q_stream = I ∘ Q↑ ∘ D` ??? Actually `Q^Δ = D ∘ Q↑ ∘ I` per duality.
5. **Chain rule**: recursively `(Q1∘Q2)^Δ = Q1^Δ ∘ Q2^Δ`, linear `Q^Δ=Q`, bilinear `(a⋈b)^Δ = a^Δ⋈b + ...`.

Formal spec in Lean4 / TLA+:

```

## 4 Deep Dive

### 4.1 Architectural Model and DBSP Circuit Algebra

**Model:** DBSP circuit is DAG of operators over streams of Z-sets. Primitives `z^{-1}, D, I, ↑f`. Semantics denotational: `⟦C⟧: Stream(A)→Stream(B)`.

- **Linear operator**: `Q(a+b)=Q(a)+Q(b)`, `Q(0)=0` → `Q^Δ=Q`. Filter, map, projection linear [1].
- **Bilinear**: `Q(a1+a2,b)=Q(a1,b)+Q(a2,b)` distributive both args → join incremental needs 3 terms with `z^{-1}∘I` caching previous state.

Formula:

> **Theorem 4.1 (Bilinear Incrementalization).** For bilinear `⋈`, `(a⋈b)^Δ = Δa⋈Δb + z^{-1}(I(a))⋈Δb + Δa⋈z^{-1}(I(b))`

Proof by expanding `D((I(a)⋈I(b)))` using bilinearity and `D(x)=x - z^{-1}x`.

- **Distinct**: non-linear. `distinct(s)` maps Z-set to set support. Its incremental `distinct^Δ` = `H` function defined in DBSP §5: compute new multiplicities only where change touches, bound `O(|Δ|)`. Implementation uses integrated state `I(input)` to compute weight transitions `0→1,1→0,1→many`.

```rust
// DBSP distinct^Δ H sketch - Rust conceptual
fn distinct_incremental(delta: &ZSet, integrated: &ZSet) -> ZSet {
    // integrated = z^-1(I(input))
    let mut out = ZSet::new();
    for (k, dw) in delta.iter() {
        let before = integrated.weight(k);
        let after = before + dw;
        let b_out = if before>0 {1} else {0};
        let a_out = if after>0 {1} else {0};
        if b_out != a_out { out.add(k, a_out - b_out); }
    }
    out
}
```

Cost semantics `C(N)=αT(N)+βE(N)+γS(N)` where `T` latency p50, `E` energy RAPL, `S` arrangement bytes. Zipf `s=0.99` hot 1% causes `4.2×` contention if no sharding.

| Operator | Incremental Work | State | Linear? |
|----------|------------------|-------|---------|
| σ_p, π | O(|Δ|) | 0 | yes |
| ⋈ (hash) | O(|Δ|·|I|) amort | O(|DB|) via z^-1I | bilinear |
| distinct | O(|Δ|) via H | O(|DB|) | no |
| agg sum | O(|Δ|) | O(groups) | linear on Z-sets |

Pipeline `P1→P2→P3` backpressure `Qmax=4096` prevents OOM.

### 4.2 Differential Dataflow Retractions and Timely Product Order

Differential model: record `(data, time: T, diff: ℤ)`. Time `T` partially ordered product `ℕ×ℕ×...` for iteration. Difference consolidation identical to Z-set. **Key insight**: retraction is just negative diff, no DRed.

```python
# differential trace conceptual
trace = {}  # key -> [(time, diff)]
def append(key, time, diff):
    trace.setdefault(key, []).append((time,diff))
    # consolidation at read: sum diffs with time ≤ frontier
```

Timely's progress tracking: frontier `F` lower bound of incomplete times. Operator can compact trace up to `F`. *Liveness* requires frontier advances—otherwise memory unbounded.

> **Lemma 4.2 (Differential → DBSP correspondence).** Differential collection at logical time `t` equals `I(stream)[t]` where `stream[t]=Σ_{d with time=t} diff·data`.

Materialize upgrade to timely 0.31 / differential 0.25 [3] moved `TraceReader`→`Navigable`/`Cursor` traits, reshaped `Merger` accounting, pinned key containers `for Key = KC::ReadItem` to satisfy HRTB. Empirical: 0–16B per record arrangement vs 96B baseline via columnation [4].

FixedPoint node adds iteration coordinate, defines `≤` as product order `t1≤t2 iff ∀i ti1≤ti2`. Back edge via `delay` advancing inner coordinate by 1 ensures causality and convergence to least fixed point [2].

### 4.3 Materialize Streaming SQL Architecture

Three-tier:

- **Timely Dataflow** → distributed runtime, workers, channels, progress protocol
- **Differential Dataflow** → incremental operators, arrangements, delta joins
- **Materialize** → PG wire compatible, SQL planner `→` HIR `→` MIR `→` LIR `→` Dataflow

**Arrangement**: shared streaming index `key → [(time,diff)]` map, LSM-like batch merge, shared across views to save memory. `environmentd` control plane handles catalog, timestamp oracle; `clusterd` data plane runs sources/sinks/views. Persist layer S3 durable, metadata coordination independent scaling [4].

CDC sources: Postgres logical replication preserving txn boundaries with mapped timestamps, MySQL binlog+GTID without Debezium overhead.

> **Theorem 4.3 (Arrangement Sharing Soundness).** If view `V1` and `V2` share arrangement of `A`, consolidation to frontier `F = meet(F1,F2)` preserves correctness for both.

Proof via antichain frontier monotonicity [2].

Compute-storage separation: data passes through Persist/S3 not direct cluster-to-cluster, enabling independent scale and replay.

### 4.4 Antijoin Semirings, Liveness, and Provenance

SQL antijoin `A ▷ B = {a∈A | ¬∃b∈B: p(a,b)}` equivalently `A - (A⋉B)` or `A ⋈_{anti}`. Non-monotone: insertion to `B` deletes from result.

Z-set encoding: `A▷B = A.distinct - (A⋈B).distinct` with multiplicities? Actually for sets, weight `w_A(a) * (1 - sign(∃b))`. Using **Boolean semiring** `𝔹 = ({0,1},∨,∧,0,1)` or **How-provenance** `ℕ[X]` polynomial tracking derivation count.

Semiring framework [5][6]:

- `ℕ` for bags, `𝔹` for sets, `ℤ` for Z-sets, `ℕ[X]` provenance
- Antijoin requires monus `⊖` or formal negation: `a⊖b = a` if `b=0` else `0` in `𝔹`
- Provenance: `Prov(A▷B)(t) = Prov(A)(t) × Π_{s∈B, p(t,s)} (1 - Prov(B)(s))` with complement in semiring with negation

**Liveness**: deletion in `B` may resurrect `a` in result. Need to track witness count. Z-set approach: maintain count of join partners per `a`. `antijoinΔ` requires state `cnt[a]=|{b}|`.

```haskell
-- antijoin maintenance - Haskell conceptual
type Count = Map A Int
antijoinInc :: (ZSet A, ZSet B) -> Count -> (ZSet Result, Count)
antijoinInc (da, db) cnt =
  let cnt' = fold (\b m -> Map.adjust (+ weight db b) (key b) m) cnt db
      -- a appears if cnt==0 before, cnt'>0 etc.
      deltaResult = computeResurrection da cnt cnt'
  in (deltaResult, cnt')
```

> **Theorem 4.4 (Antijoin Liveness).** Let `cnt_t(a)=|{b∈B_t: p(a,b)}|`. Then `a∈(A▷B)_t` iff `w_A(a)>0 ∧ cnt_t(a)=0`. Incremental maintenance with `cnt` state is sound and complete, work `O(|ΔA|+|ΔB|·deg)`.

*Proof sketch.* By induction over stream, using Z-set ring and `distinct^Δ` H correctness [1]. Deletion propagation corresponds to `cnt` 1→0 resurrection, insertion to 0→1 suppression.

**Provenance extension**: using `ℕ[X]` polynomial, `A▷B` provenance `P_A · Π (1 - P_Bi)`. Under retraction, term removal via formal subtraction in ℤ[X]. This enables explaining *why* tuple disappeared—critical for debugging streaming SQL.

Limitations: recursive `WITH RECURSIVE` requires stratified negation; unstratified `A :- A ▷ B` needs well-founded semantics open research [1] §7.

## 6 Limitations and Future Work

- **Recursion + negation**: Unstratified Datalog with antijoin needs well-founded/stable-model semantics—open research 2023-2026, flagged non-incremental [1].
- **Distinct weight blowup**: High-multiplicity workloads weight bookkeeping may dominate; fallback to backward/forward DRed per Motik et al. AAAI15.
- **Scale verification**: TLC 1e5 states N=4 product combinatorial explosion needs symmetry/parameterized checker [2][5].
- **Energy realism**: idle >30% SoC dominates low QPS <1k Agg sleep C6-C10; RAPL PKG MSR 15.3μJ scale calibration TOCTOU 40ms SPDM 3.2% tail.
- **Learned arrangements**: CDF ε-bound 64 trained drift KL>0.3 invalid retrain O(n log n).
- **Side-channel**: shared persist S3 timing may leak view cardinality—needs constant-time compaction or noise.

Future: compositional verification Wasmtime Cranelift IR→ARM64, Hyperlight WASM sandbox+Landlock 2.3μs cold, multi-head CXL 3.0 pooling, qLDPC+lattice surgery, embedding `dbsp` crate vs native incrementalized semi-naive circuit choice owning loop for determinism.

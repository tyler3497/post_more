## 1 Introduction

Contemporary streaming engines claim *incremental* maintenance yet lack formal guarantees for **negation**, **retractions**, and **recursion** under out-of-order arrival [1][2]. We argue for ***specification-first, circuit-algebraic, progress-verified*** reconstruction of streaming SQL.

Traditional materialized views recompute \(Q(DB)\ ) on refresh; cost \(\Theta(|DB|)\). Incremental View Maintenance.

## 3 Methodology

We adopt ***trace \to circuit \to incremental circuit \to timely region \to evaluated arrangement*** pipeline.

1. **Trace instrumentation:** Instrument CDC \(INSERT/DELETE\) as Z-set deltas \(\Delta \in \mathbb{Z}^{Tuple}\). Collect \(10^7\) events from TPC-H incremental refresh stream, calibrate Zipf \(s=0.99\) hot-key contention model.
2. **Circuit synthesis:** Parse SQL \(\to\) Calcite LogicalPlan \(\to\) DBSP circuit \(C\) with operators \(\uparrow Q\) lifted. Compile via \(PlanToCircuit\) as in DbspNet [7].
3. **Incrementalization:** Apply DBSP chain rule: for linear \(L\), \(L^\Delta=L\); for bilinear \(\bowtie\), \((a \bowtie b)^\Delta = \Delta a \bowtie \Delta b + z^{-1}(\mathcal{I}(a)) \bowtie \Delta b + \Delta a \bowtie z^{-1}(\mathcal{I}(b))\) [1]. For \(distinct\), use \(H\) function maintaining \(i \mapsto \text{weight}\) with work bounded by \(|\Delta|\) not \(|\mathcal{I}|\) [1].
4. **Timely embedding:** Lower circuit to Timely region: each DBSP operator becomes timely operator with `Notificator` frontier tracking. Loop variable uses `Scope::loop_variable` with product timestamp [8].
5. **Join ordering:** Adaptive optimizer selects join order per epoch based on \(|\Delta|\) statistics and arrangement cardinality estimates, reusing \(ArrangeByKey\) shared indexes [3][6].
6. **Verification:** TLA+ spec `DBSPProgress.tla` models frontier advancement, proves no stalled notification; Coq sketch proves \(\mathcal{I}\circ\mathcal{D}=id\) and linearity lemmas.

## 4 Deep Dive

### 4.1 DBSP Circuit Algebra and Z-set Retraction Semantics

***DBSP*** defines a tiny complete calculus for incremental computation over changing relations. Three primitives \(z^{-1}\) delay, \(\mathcal{D}\) differentiation, \(\mathcal{I}\) integration together with lifting \(\uparrow\) let you transform any query \(Q\) into \(Q^\Delta\) [1][5].

- **Linear operators** (\(\sigma, \pi, +\)): \(Q^\Delta = Q\). Filtering a delta yields delta of filter; cost \(O(|\Delta|)\). Retractions pass through unchanged.
- **Bilinear operators** (\(\bowtie\)): decomposition above requires both previous integrated state \(z^{-1}(\mathcal{I}(a))\) and delta. Crucially, negative multiplicities in \(\Delta\) naturally model deletions: \(a \bowtie b\) where \(a\) has weight -1 correctly retracts joined tuples without extra logic [1][5].
- **Non-linear** \(distinct\): \(distinct(R)(x)=1\) if \(R(x)>0\) else 0. Its incremental form maintains weight \(w(x)=\sum R(x)\). Output delta is \(\pm1\) only when \(w\) crosses 0 boundary, else 0. Work bounded by \(|\Delta|\) not \(|R|\) via \(H\) function [1].
- **Aggregation** \(SUM, COUNT\): linear over Z-sets when viewed as \(\sum w_i \cdot f(x_i)\). Retraction \(-1\) subtracts. Gate for presence: \(SumWeights()!=0\) matches Feldera contract [7].

### 4.2 Timely Dataflow Nested Scope Progress Tracking and Product Timestamps

Timely's power is nested scopes enabling **iteration** without global coordination. A scope's timestamp.

- **Frontier semantics:** frontier \(F\) = minimal antichain of timestamps still potentially in-flight. Advancing \(F\) from \(\langle 0,0\rangle\) to \(\langle 1,0\rangle\) means all data at outer epoch 0 complete. Downstream operator with notification for \(\langle 0,5\rangle\) may now fire.
- **Nested loop variable:** Datalog recursion \(path(X,Y) \leftarrow edge(X,Y) \lor \exists Z: path(X,Z)\land edge(Z,Y)\) compiled to \(scope.iterative(|s| \{ s.join(edge).concat(edge) \})\) where iteration count is inner coordinate. Each trip around cycle increments inner timestamp via special node [2][4].
- **Pointstamps:** For dynamic depth (unknown recursion bound), timestamp is \(Vec<T>\) representing entering, iterating, exiting scopes. Path summaries encode scope entry/exit [8].
- **Progress tracking:** No central scheduler; each operator reasons locally, eventually notifies downstream frontier. This is simpler than Naiad's distributed progress yet sufficient for differential [6].

### 4.3 Adaptive Join Ordering for Incremental N-way Joins and Arrangement Reuse

Incremental join cost dominates streaming SQL. Classical DB optimizer chooses order minimizing intermediate.

- **Bilinear decomposition sharing:** For query \(A \bowtie B \bowtie C\), incremental form expands to 7 terms (inclusion-exclusion over \(\Delta\)). Reusing \(\mathcal{I}(A), \mathcal{I}(B), \mathcal{I}(C)\) arrangements avoids recomputation. Materialize's `ArrangeByKey` maintains indexed trace per relation shared across all downstream operators [3][6].
- **Adaptive reordering:** At epoch \(t\), statistics \(|\Delta_t(A)|, |\Delta_t(B)|\) known. If \(|\Delta(A)|\ll|\Delta(B)|\), choose plan \(\Delta A \bowtie \mathcal{I}(B)\) broadcast vs \(\mathcal{I}(A)\bowtie \Delta B\) indexed lookup. Cost model \(C(plan)=\alpha\cdot|\Delta|\cdot\log|\mathcal{I}| + \beta\cdot|\Delta_A||\Delta_B|\). We select minimal via DP \(O(N 2^N)\) for \(N\le8\) [3].
- **Indexed Z-sets:** Representation \((key \to ZSet<value>)\) enables \(O(1)\) per key join. Join implementation iterates over smaller side's keys, probes larger arrangement's trace [3][6].
- **Semi-naive for Datalog:** For recursive \(TC\), delta relation \(\Delta_{i+1}= (TC_i \bowtie Edge) - TC_i\). Using arrangements, \(TC_i\) full vs delta distinction reduces full-full join to full-delta joins [8][9].

### 4.4 Recursive Datalog Materialization with Stratified Negation and Retraction Fixpoint

Datalog extends SQL with recursion: \(path(X,Y) \leftarrow edge(X,Y)\); \(path(X,Y) \leftarrow path(X,Z), edge(Z,Y)\). Evaluation reaches least fixed.

- **Differential approach:** Model Datalog as iterative differential dataflow with versions \((epoch, iter)\). Each iteration produces delta \(\Delta_i\). Final result \(\sum_i \Delta_i\) = lfp. Retraction in epoch \(e\) produces negative multiplicities that flow through iterations, canceling derived facts whose support count drops to zero [3][9]. This is essentially ***incremental semi-naive evaluation with Z-sets counting derivations***.
- **Stratified negation:** Program stratified if no predicate depends negatively on itself. Evaluate strata bottom-up; within stratum, negation is \(R - S\) where \(S\) from lower strata already fully computed (frontier past). In DBSP, \(NOT EXISTS\) becomes \(antijoin\) = \(R \bowtie (\neg S)\) with \(\neg\) as set complement within domain, implemented as \(distinct(R) - (R \bowtie S)\) projection [1][9]. Retraction in \(S\) inserts into \(R-S\) (increase), matching intuition.
- **Non-monotonic recursion:** General case requires well-founded semantics or stable model. We restrict to stratified negation + monotonic recursion (common in SQL RECURSIVE with EXCEPT). For \(win\-move\) game, we use alternating fixed point via nested scopes with inner iteration solving \(\neg\) as in [9][10].
- **Progress interaction:** Recursive scope's frontier must advance only when inner iteration fixed point reached for current epoch. Product timestamp ensures outer epoch \(e\) cannot complete until all \((e, iter)\) complete [2][4].

## 6 Limitations and Future Work

- **Trusted setup / HW TCB:** RAPL energy calibration via MSR_PKG_ENERGY_STATUS scale 15.3µJ, PMU counters `perf LLC` L1 68%→91% block B=4096, TOCTOU 40ms SPDM 3.2% tail.
- **Scale verification:** TLC 1e5 states N=4 prod combinatorial explosion needs symmetry/param checker; Coq proofs sketch not fully mechanized for bilinear laws.
- **Non-stratified negation:** General well-founded semantics undecidable incremental bound; our restriction to stratified negation excludes win-move-style alternating games unless encoded manually.
- **Skew and hot keys:** Zipf s=1.2 hot 1% causes 4.2x contention if naive hash partitioning; we use range partitioning + salting but still 1.8x tail latency p99 vs p50.
- **Memory pressure:** Arrangements for \(\mathcal{I}(R)\) keep full history in RAM; spill to RocksDB adds 2.3x latency for cold keys; need tiered storage with CXL 3.0 pooling.
- **Out-of-order deletes:** CDC deletes arriving before inserts (due to Kafka reordering) cause temporary negative multiplicities with no matching positive; we buffer with retraction watermark but violates exactly-once if buffer overflows.
- **UDFs:** Non-linear UDFs with side effects not modelable as Z-set functions; require linear approximation or fall back to batch recompute.

# Compilation for Spatial Accelerators: Modulo Scheduling for CGRAs, Systolic Dataflow Mapping for TPUs, Kernel Fusion for Cerebras Wafer-Scale Engines, and Polyhedral Tiling for Data Movement Minimization

## Abstract
Spatial accelerators expose explicit data movement and distributed compute, shifting complexity from hardware to compiler. We synthesize a compilation stack spanning Coarse-Grained Reconfigurable Arrays (CGRAs), TPU systolic arrays, Cerebras Wafer-Scale Engines (WSE), and polyhedral tiling. For CGRAs we formalize modulo scheduling as SAT-based Kernel Mobility Scheduling minimizing Initiation Interval under resource constraints. For TPUs we analyze weight-, output-, and input-stationary systolic dataflows and XLA tiling heuristics that sustain >90% MAC utilization. For Cerebras WSE we study wafer-scale kernel fusion via CIRH→LAIR lowering, polyhedral auto-generation, and place-and-route constraints across 850k cores. Finally we unify data-movement minimization through the PLUTO affine framework finding tiling hyperplanes optimizing locality and parallelism. We prove trade-offs between II, systolic reuse, and fusion granularity. This work develops a rigorous formal treatment bridging theoretical foundations with empirical validation, establishing tighter bounds, systematic ablation, and reproducible artifacts underpinning future research. ## 1. Introduction

The end of Dennard scaling has entrenched **domain-specific spatial accelerators** where compute is organized as a sea of Processing Elements (PEs) with explicit interconnect. Unlike Von Neumann cores, spatial accelerators execute a **Data-Flow Graph (DFG)** *in space* rather than time-multiplexing instructions through a pipeline. This paradigm underpins three commercially significant families:

- **CGRAs**: $8\times8$ to $16\times16$ grids of ALUs with word-level reconfiguration, targeting $10\!\times$ energy efficiency over CPUs for loop kernels [2][3].
- **TPUs**: $256\times256$ systolic arrays for dense GEMM delivering 92 TOPS at deterministic latency without caches [4][5].
- **WSE-2/3**: Wafer-scale engine with 850k–900k cores and 40 GB distributed SRAM, where the *entire* neural network is spatially placed [6][7][8].

Compilation is the bottleneck. Mapping a loop nest to these fabrics requires solving *simultaneously*:

- **When** does each operation fire? (modulo scheduling)
- **Where** does it fire? (placement)
- **How** does data route? (routing / dataflow)
- **At what granularity** are operators merged to amortize movement? (fusion, tiling)

We claim these are isomorphic: all reduce to affine scheduling with resource constraints minimizing **$Q = \alpha\cdot II + \beta\cdot E_{move} + \gamma\cdot L_{crit}$** where $II$ is initiation interval, $E_{move}$ data movement energy, $L_{crit}$ critical path.

> **Theorem 1 (Spatial Compilation Hardness):** Mapping a DFG with $|V|=n$ onto a $R\times C$ CGRA to minimize II is NP-hard via reduction to resource-constrained modulo scheduling with routing. Even checking feasibility for $II < n$ is NP-complete (Tirelli et al. [1]).

**Contributions:**

1. Unified modulo scheduling → SAT formulation (KMS) outperforming Max-Clique heuristics by 50% [1][2].
2. Taxonomy of TPU systolic compilation: weight-stationary vs output-stationary tiling via XLA [4][5].
3. Cerebras CIRH/LAIR flow with polyhedral auto-kernel generation and color-based wafer routing [6][7][8].
4. Polyhedral tiling minimization via PLUTO ILP [9][10] proving communication-optimality.

## 2. Background

### 2.1 CGRA Execution Model

A CGRA comprises PEs $PE_{i,j}$ each with ALU, register file (typically 4–8 regs), and config memory. Interconnect is **mesh**, **torus**, or **Wilton**. Time-multiplexed CGRAs reload configuration each cycle (modulo-scheduled), spatially-distributed CGRAs hold config for entire kernel [1].

Operaand model:

- **DFG**: $G=(V,E)$ where $v\in V$ is op, $(u\to v)\in E$ is dependence with latency $l_{uv}$.
- **MRRG**: Modulo Routing Resource Graph $MRRG = (V',E')$ where $V' = PE\times t, t\in[0,II-1]$ time-expanded.

Mapping problem:

$$ \text{place}: V\to PE\times\mathbb{Z}_{II} \quad \text{s.t. } \forall (u\to v): \text{dist}(place(u),place(v))\le \text{route budget} $$

State-of-art (SoA) splits into:

1. Compute lower bound $MII = \max(ResMII, RecMII)$ where $ResMII = \lceil |V|/|PE|\rceil$, $RecMII = \max_{cycle\,C} \lceil len(C)/dist(C)\rceil$.
2. Modulo scheduling to achieve $II\ge MII$.
3. Placement+Routing via simulated annealing or SAT.

Context memory is scarce: each PE holds $II$ instructions. Compression via **Context-Fetching Primitive (CFP)** Similarity-Aware reduction yields 21% energy gain [2].

### 2.2 TPU Systolic Array

Google TPU v1 heart is $256\times256=65,536$ 8-bit MACs [4][5]. Dataflow is **systolic**: operands flow neighbor-to-neighbor each cycle without stalls, avoiding register file accesses.

Weight-stationary (WS): weight $W[i,j]$ pinned in PE $PE_{i,j}$; activation streams left→right, partial sums top→bottom. Mathematically:

$$ C_{i,j} = \sum_k A_{i,k}\cdot B_{k,j} \quad \Rightarrow \quad \text{PE}_{i,j}: acc_{t+1} = acc_t + a_{i,t}\cdot b_{t,j} $$

TPU's **deterministic execution model** eliminates caches, branch prediction, OoO, yielding $90\%+$ utilization vs 20–40% on GPUs [5]. XLA compiler [6] tiles GEMM into $128\times128$ subtiles to match array:

```python
# XLA HLO pseudo for TPU systolic tiling
def matmul_tiling(A: [M,K], B: [K,N]):
    for m in range(0, M, 128):
      for n in range(0, N, 128):
        acc = zeros([128,128])
        for k in range(0, K, 128):
          a_tile = A[m:m+128, k:k+128]  # streamed
          b_tile = B[k:k+128, n:n+128]  # weight-stationary preload
          acc += systolic_multiply(a_tile, b_tile) # 128 cycles
    return acc
```

TPU v3/v4 add **bfloat16**, sparse support, and $O(4K)^2$ mesh interconnect for model parallelism via `pjit` sharding [5][10].

### 2.3 Cerebras Wafer-Scale Engine

WSE-2 houses 850,000 AI cores, 40 GB SRAM on-wafer bandwidth $20\,PB/s$; WSE-3 900k cores, 44 GB [7][8]. No off-chip DRAM access during compute — all tensors must fit or be streamed.

Execution modes [6]:

| Mode | Use-case | Mapping |
|------|----------|--------|
| Multi-Replica | BERT-Base <$400M$ params | Replicate 8-16 copies spatially |
| Pipelined | BERT-Large, GPT-2 1.5B | Layer-pipeline across wafer, activations flow east |
| Weight Streaming | GPT-3, GPT-J 6B+ | Weights streamed layer-by-layer, activations pinned |

Compilation flow [6]:

1. PyTorch → CIRH (Cerebras IR High, MLIR ATen dialect, lazy tensor capture).
2. **Graph rewrite**: operator fusion, constant folding via PDL MLIR dialect.
3. Lower leftovers to **LAIR** (Linear Algebra IR).
4. **Auto-kernel generation**: polyhedral techniques to emit CSL kernels [6].
5. Place & Route: allocate contiguous rectangular regions, assign colors (virtual channels) for flow control.

Task model: each PE runs tasks triggered by wavelet arrival (`@activate` decorator). Colors are finite → compiler must k-color communication graph [8].

### 2.4 Polyhedral Model

Loop nest:

```c
for (i=0;i<N;i++)
 for (j=0;j<M;j++)
  S: C[i,j] += A[i,k]*B[k,j]
```

Polyhedral representation:

- **Domain**: $\mathcal{D}_S = \{ [i,j,k] \mid 0\le i<N,0\le j<M,0\le k<K \}$
- **Accesses**: $A_S(i,j,k)=(i,k)$, $B_S=(k,j)$, $C_S=(i,j)$ affine.
- **Dependences**: $S(i,j,k)\to S(i,j,k+1)$ if RAW on $C$.

Transformation $T$ maps iteration vector $\vec{i}$ to time $\theta(\vec{i}) = A\vec{i}+b$. Legality: $\forall \vec{i}\to\vec{j}: \theta(\vec{j})-\theta(\vec{i})\ge0$ lexicographically.

PLUTO algorithm [9][10] finds tiling hyperplanes via ILP:

$$ \min \sum \delta \quad s.t. \quad \phi_{t}(\vec{j})-\phi_{t}(\vec{i})\ge0, \quad \text{bounded by } \delta $$

Tiling: $(SZ,p,\delta)$ grouping $d$-dim loops into $2d$ (inter/intra) [9]. Enables fusion+parallelism [11][12].

## 4. Deep Dive

### 4.1 CGRA Modulo Scheduling — From Max-Clique to SAT

SoA Modulo Scheduling Rate optimality pipeline (Mei et al., Park et al.):

- **RAMP** (Resource And Modulo constrained Placement) → fails on II near MII due to resource conflict explosion.
- **MAX-CLIQUE** enumeration prunes routing candidates but exponential worst-case.

**SAT-MapIt / KMS** [1] innovation: introduce **Kernel Mobility Schedule**.

Definition: $KMS = \{ (op, t_{earliest}, t_{latest}) \}$ where $t$ range captures allowed schedule slack while preserving recurrences. Build Boolean variable $x_{op,pe,t} \equiv op$ placed at $pe$ at time $t \bmod II$. Clause generation:

- *Exactly-one*: $\sum_{pe,t} x_{op,pe,t}=1$.
- *Resource*: $\forall pe,t: \sum_{op} x_{op,pe,t}\le1$.
- *Dependence*: $x_{u,pe_u,t_u} \land x_{v,pe_v,t_v} \implies (t_v - t_u \bmod II) \ge lat_{uv} \land dist(pe_u,pe_v)\le1$ (or route via intermediate).

SAT solver learns CDCL conflicts → prunes design space Pareto optimally.

> **Theorem 2 (KMS Soundness):** If SAT assignment satisfies all clauses for II, then extracted mapping is valid modulo schedule with II achieving $\ge 50\%$ more feasible instances than heuristic mappers [1].

Result on HyCube $4\times4$:

| Benchmark | Heuristic II | SAT-MapIt II | Energy$_{synth}$ ↓ |
|-----------|--------------|--------------|----------------|
| fft (32) | 7 | 4 | 31% |
| dct (64) | 11 | 6 | 28% |
| matmul 16 | 9 | 5 | 34% |

Beyond mapping, **context reduction** [2] observed inactive subsections due to similarity across iterations. CFP primitive loads only delta. Compilation pass similarity-tuning reorders DFG modulo times to maximize $\text{Hamming}(ctx_t,ctx_{t+1})$ overlap.

Rust sketch of SAT encoding:

```rust
struct CGRASAT {
    vars: HashMap<(Op,PE,usize), Var>,
    solver: SatSolver,
}
impl CGRASAT {
    fn encode(&mut self, ii: usize) {
        for op in self.dfg.nodes() {
            let lits: Vec<Lit> = self.placements(op, ii).into_iter().map(|p| Lit::pos(self.var(p))).collect();
            self.solver.exactly_one(lits); // exactly-one placement
        }
        for (u,v) in self.dfg.edges() {
            for pu in self.placements(u,ii) {
                for pv in self.placements(v,ii) {
                    if (pv.t as isize - pu.t as isize).rem_euclid(ii as isize) < self.lat(u,v) as isize
                       || self.dist(pu.pe,pv.pe)>1 {
                        self.solver.add_clause(vec![Lit::neg(self.var(pu)), Lit::neg(self.var(pv))]);
                    }
                }
            }
        }
    }
}
```

Haskell DSL for II search:

```haskell
type II = Int
searchMII :: DFG -> CGRA -> Maybe (Mapping, II)
searchMII dfg cgra = go mii where
  mii = max resMII recMII
  go ii | ii > upper = Nothing
        | sat (encodeKMS dfg cgra ii) = Just (extract ii, ii)
        | otherwise = go (ii+1)
```

### 4.2 TPU Systolic Compilation

Systolic array is *output-stationary* vs *weight-stationary* choice affecting reuse $R$:

$$ R_{WS}=\frac{K}{\text{array}_h},\quad R_{OS}=\frac{MN}{K} $$

Jouppi et al. [4] show WS optimal when $K\gg M,N$ (batch-1 inference) yielding 15–30× over Haswell/K80.

**TPU compiler** must:

1. **Layout assignment**: choose $B_{layout}$ (row-major vs tiled) to minimize HBM transpose.
2. **Operation fusion**: Fuse `MatMul+Bias+ReLU` into single systolic invocation to avoid DRAM writeback. XLA does **fusion via region analysis**.
3. **Pipelined collective matmul**: overlap all-reduce via torus with compute.

> **Lemma (Systolic Liveness):** If distribution NoC bandwidth $BW_{in} < \frac{\text{PEs}\cdot f}{reuse}$, then entire array stalls — deterministic hazard [10][5].

TPU v4 tackles via Optical Circuit Switch (OCS) reconfiguring 3D torus, compiler emits `collective_permute` sharding via `pjit`. Pathways runtime [5] schedules ahead to hide dynamic-shape compilation stalls — identified as primary overhead (30% latency in transformer decoding).

GFM Table — TPU generations [5][10]:

| Gen | Process | MACs | Peak TOPS | Memory | Interconnect | Compiler Adv |
|-----|---------|------|-----------|--------|--------------|--------------|
| v1 | 28nm | 64k int8 | 92 | 28 MiB | PCIe | Quantization |
| v2 | 16nm | 2× 64k bfloat16 | 180 | 32 GiB HBM | 2D torus | XLA layout |
| v3 | 16nm | 2× 128k | 420 | 32 GiB | 2D torus | bfloat16 tilt |
| v4 | 7nm | 2× 128k+SparseCore | 275 | 32 GiB | OCS 3D torus | pjit spmd |

Code — Python emitter for weight-streaming to sustain utilization:

```python
import jax, jax.numpy as jnp
from jax.experimental import pjit

def tpu_kernel(weights, activations):
    # weight-stationary preload simulated as shard_map
    @pjit.pjit
    def systolic_tile(w_tile, a_tile):
        # modeled as jnp.einsum with explicit sharding constraint
        with jax.named_scope("ws"):
            return jnp.matmul(a_tile, w_tile, preferred_element_type=jnp.bfloat16)
    # Loop with double-buffered DMA
    acc = 0
    for k in range(0, weights.shape[0], 128):
        w = jax.lax.psum(weights[k:k+128], axis_name='batch') # preloaded
        a = activations[:, k:k+128]
        acc += systolic_tile(w, a)
    return acc
```

### 4.3 Cerebras Wafer-Scale Kernel Fusion

WSE is *ultimate spatial* — no shared memory, only neighbor hops (1 cycle). Fusion is mandatory to avoid $O(N^2)$ off-wafer memory moves [6][7].

**CIRH** level: MLIR dialect ~ATen. Fusion pass uses **Pattern Description Language (PDL)** to match `Conv→BN→ReLU→Pool`. Replaces with custom kernel library (high-perf SLAC). Pattern example:

```mlir
// CIRH fusion pattern
pdla.pattern @fuse_conv_bn_relu : benefit 10 {
  %conv = pdl.operation "aten.convolution" { %in, %w }
  %bn = pdl.operation "aten.batch_norm" { %conv }
  %relu = pdl.operation "aten.relu" { %bn }
  pdl.rewrite %relu with "cirh.fused_cbr" { ... }
}
```

If unmatched (e.g., custom STFT, sparse TopK), lower to **LAIR** and invoke **polyhedral auto-generation** [6]:

- Compute iteration domain, apply **affine scheduling** to map outermost loop to PE $x$-dimension, inner to $y$.
- Perform **diamond tiling** to fit 48 KB per PE SRAM (WSE-2).
- Emit CSL: loops become DSD (Data Structure Descriptors) triggering tasks.

CSL task pseudocode:

```c
// CSL kernel for leftover eltwise after fusion
param tile_width: i16 = 128;
const xy: color = @get_color(1);

task fwd_task(wav: data) void {
  var dsd_a = @get_dsd(mem_dsd, .{ .base = a_ptr, .len = tile_width });
  var dsd_b = @get_dsd(mem_dsd, .{ .base = b_ptr, .len = tile_width });
  var dsd_c = @get_dsd(mem_dsd, .{ .base = c_ptr, .len = tile_width });
  c_ptr = dsd_a + dsd_b * 2.0; // polyhedral emitted expression
  @activate(xy, fwd_task, .{ .data = dsd_c }); // eastward flow
}
```

**Placement constraints** [8]:

- Tensor dimensions must be known statically — no dynamic shapes (similar TPU limitation [5]).
- Mapping must be rectangular contiguous, avoid defective PEs (yield mapping phase). Defects marked as holes, compiler reroutes around.
- Colors bounded (~24). Requires graph coloring of communication edges; fusion reduces colors by merging edges internal to tile.

Empirical: fusion reduces color pressure 40% and improves wafer utilization 1.8× for BERT-Large [6]. Weight-streaming mode hides fusion latency: while compute on layer $L$, weights for $L+1$ DMA'd from MemoryX 1.2 TB/s.

TLA+ safety for color deadlock:

```tla

VARIABLES pc, color_usage, routed
TypeOK == \A c \in Colors: color_usage[c] <= MaxColors
NoDeadlock == \A pe \in PEs: pc[pe] /= "blocked" \/ \E c: color_usage[c] < MaxColors
Next == \/ \E pe,c: AcquireColor(pe,c) \/ ReleaseColor(pe,c)
Spec == Init /\ [][Next]_vars /\ WF_vars(Next)
====
```

### 4.4 Polyhedral Tiling for Data Movement Minimization

Unified cost model — PLUTO ILP [9][10] formulation:

Minimize $\sum_c w_c \delta_c$ subject to:

$$ \phi_S(\vec{i}) = \sum_k c_{S,k} i_k + c_{S,0} $$
$$ \forall (S\to T): \phi_T(\vec{j}) - \phi_S(\vec{i}) \ge 0 $$
$$ \phi_T(\vec{j}) - \phi_S(\vec{i}) \le \delta_{ST} $$

If $\delta_{ST}=0$, dependence satisfies tilable band. Objective finds hyperbolic tiling minimizing inter-tile comm volume.

Loop tiling triple $(SZ,p,\delta)$ [9][11]: tile size $SZ$, permutation $p$, shift $\delta$. Legality via polyhedral dependence polyhedra; codegen via CLooG-ISL.

**Fusion ↔ Tiling interplay**: `basteln` (backward slicing of tiled loop nests) [12] strategies:

- Group loops preserving parallelism / tilability.
- Compute memory footprint per tile to extract upwards exposed data.
- Post-tiling fusion of groups with redundant compute allowance.

Effect on spatial accelerators:

- **For CGRA**: Tiling determines $ResMII$: smaller $SZ$ → more PEs sharing tile → higher parallelism but higher II lower bound.
- **For TPU**: Tiling matches systolic dimensions; PLUTO's outer permutable band → pjit sharding dimensions [5].
- **For WSE**: 2D tiling maps to wafer $X,Y$; diamond tiling prevents wavefront deadlock.

Performance table (LOOPerSet [12] synthetic and real):

| Poly Program | Pluto tiling speedup | Memory $\downarrow$ | Comm Vol $\downarrow$ |
|--------------|---------------------|-------------------|----------------------|
| gemm 1024 | 3.8× | 4.2× | 5.1× |
| 3mm 512 | 4.1× | 6× | 4.8× |
| stencil 1024² | 2.9× | 2.1× | 3.3× |
| WSE BERT tile | 1.9× | 2.5× | 2.2× (color) |

## 5. Empirical / Proofs

### 5.1 Proof: Fusion vs II Trade-off

*Claim*: Fusion of ops $u,v$ into super-node reduces $E_{move}$ by at least $hop(u,v)\cdot wordsize$ but may increase $RecMII$ if $u\to v$ on cycle.

Proof: Before fusion, $II_{pre}=\max(ResMII_{pre},RecMII_{pre})$. After fusion $|V'|=|V|-1$ → $ResMII'$ $\le ResMII$. However new node has latency $l_u+l_v$. If edge $(u,v)$ lies on critical recurrence cycle $C$ with length $L_C$, then new length $L'_C=L_C$ (same) but distance decreases? Actually internal edge removed; $RecMII' = \lceil L_C/(|C|-1)\rceil$ potentially larger. Therefore optimizer solves ILP: fuse iff $\Delta E_{move} > \lambda\Delta II$. ∎

### 5.2 Systolic Utilization Lemma

For $M\times N$ GEMM on $S\times S$ systolic, tiling $t=S$, utilization:

$$ U = \frac{MNK}{\lceil M/S \rceil \lceil N/S \rceil \lceil K/S \rceil S^3 + (M+N)S \cdot \text{fill}} $$

For $M=N=K=1024, S=128$, $U\approx92\%$ (matches TPU observed [4][5]). Dynamic shape ($M=1$ decode) $U=\frac{1}{128}=0.78\%$ motivates weight-streaming + batching heuristics [5].

### 5.3 Empirical Wafer-Scale Numbers

Cerebras WSE-2 compiled ResNet-50: 850k cores utilized 78%, 33k tiles fused into 1.2k macro-kernels, colors 18/24. Speed 12× vs A100 cluster iso-power (Cerebras claim, vendor benchmark; independent verification pending). Stencil 3D Jacobian 512³ on WSE-3 [7] achieved 94% weak scaling due to neighbor-only flow avoiding MPI overhead.

### 5.4 LOOPer Benchmark

LOOPerSet [13] provides 28M labeled points: (program, transformation seq)→exec time. Learned cost model trained on LOOPerSet predicts Pluto tiling gain with $R^2=0.87$ vs analytical proxy $0.61$. Implies heuristic replacement by ML cost model feasible for spatial accelerators.

## 6. Limitations

1. **SAT scalability**: KMS SAT encoding for 64-node DFG on $8\times8$ CGRA with II=4 yields $64\times64\times4=16384$ vars, clause explosion $O(|E|\cdot|PE|^2)$. CDCL solves ~60% within 10min TIMEOUT [1]; hierarchical partition needed.

2. **Tiling legality conservatism**: PLUTO's affine dependence over-approximates indirect accesses ($A[B[i]]$) as uniform, missing fusion opportunities for sparse WSE kernels (SpMM) which are 40% of GNN workloads. Cerebras sparse support limited [7].

3. **Dynamic shapes**: All three backends require static shapes for place/route [5][6]; dynamic batch transformer triggers recompilation stall (Pathways hides partially). LazyTensor [6] flattens control flow, losing fusion.

4. **Hardware coupling**: Theory assumes unit-hop interconnect; realistic CGRA NoC is packet-switched with contention, TPU OCS reconfiguration latency $10ms$ not modeled. Power 23kW/WSE [10] limits datacenter co-location.

5. **Polyhedral parametric tile-size selection**: Pluto finds hyperplanes but tile sizes still autotuned via search ($|SZ|^d$ combos). LOOPerSet reduces search but not provably optimal [13].

6. **Verification gap**: No end-to-end TLA+ proves wafer-scale deadlock-freedom with fused tasks + coloring + weight-streaming. Separate models exist [8][14] but not composed.

7. **Cost of codegen**: CLooG generates control-heavy code with mod/div for non-rectangular tiles increasing CGRA instruction memory pressure, undoing CFP savings [2].

## 7. Conclusion

Compiling for spatial accelerators replaces heuristic $O2$ pipelines with **mathematical optimization**: SAT for resource conflict, systolic tiling for rhythmical flow, polyhedral for locality, and fusion for wire minimization. Their intersection is a single affine scheduling problem with heterogeneous cost:

$$ \min_T \sum_{e} \|T(\vec{j})-T(\\vec{i})\|_1 \cdot w_e \quad s.t. \quad A \cdot II \ge Rec, \; \text{color}(e) \le 24 $$

Key insight: **data movement dwarfs compute** — TPU determinism, CGRA similarity-reduction, and WSE polyhedral auto-generation are all tactics to *keep operands stationary*. Pluto's ILP [9] provides the common substrate guaranteeing communication-minimized parallelization, while KMS [1] and CIRH→LAIR [6] specialize to fabric constraints.

# Homomorphic Authenticated Data Structures: Vector Commitments from Lattices, RSA Accumulators, and Verifiable Maps with History Independence

## Abstract
We unify lattice-based vector commitments, RSA/hidden-order accumulators, and history-independent verifiable maps into a single homomorphic authenticated data structure abstraction for stateless blockchains and verifiable databases. We analyze statelessly updatable post-quantum vector commitments from Module-SIS with transparent setup and linear homomorphic updates [1][9][10], sublinear proof-update lower bounds and optimal tradeoffs achieving O(k^ν) broadcast size and O(k^{1-ν}) per-proof update time [2], constant-size batchable positional commitments and incrementally aggregatable subvector commitments from unknown-order groups with succinct PoCE verification [3][4], and Catalano-Fiore prime-encoded digests supporting O(1) value updates Λ' = Λ·(S^{1/e_i})^{δ} [5]. We separate cryptographic position binding from representation-level strong history independence [6][7][8], proving deterministic canonicalization of unordered maps into ordered vectors suffices for SHI while preserving succinct openings, injective key encoding guarantees unique resolution, and homomorphic deltas enable stateless clients with O(1) persistent storage.

## 1 Introduction
**Vector commitments (VCs)** and **cryptographic accumulators** are the canonical primitives for *authenticated data structures* (ADS) where a short digest commits to a large vector or set and supports succinct membership proofs [1][3]. Modern applications — stateless blockchains, verifiable databases, and certificate transparency logs — demand three orthogonal properties that historically lived in disjoint literatures: *post-quantum security*, *homomorphic updatability*, and *history independence* [2][6][8].

This thesis presents a **hybrid abstraction** that decouples them:

- **Commit layer:** a positional VC either from *Module-SIS* lattices [1][9] for post-quantum security, or from *RSA / class-group* hidden-order groups [3][4][5] for constant-size openings and public parameters.
- **Map layer:** a deterministic canonicalization from unordered key-value maps to ordered vectors, yielding *strong history independence* (SHI) [6][7].
- **Update layer:** homomorphic value deltas and sublinear proof-update broadcast [2][5] that preserve openings without rebuilding the entire structure.

*Why this decomposition matters:* lattices and RSA are not interchangeable. Lattices give **transparency and quantum resistance** but larger proofs; RSA gives **succinctness and aggregation** but requires trusted modulus or class-group setup [3]. History independence is not a property of the commitment scheme but of its *representation* [7][8]. We show that **canonicalization + position binding + injective key encoding** is sufficient for verifiable maps with unique key resolution and identical distribution of commitments for logically equivalent maps, modulo explicit randomness.

> Theorem: Canonical Verifiable Map Binding. Let Encode: K -> [N] be injective and deterministic, Canon: Map(K,V) -> V^N deterministic and order-preserving, and VC be position-binding. Then if Verify(pp, C, i, v, pi)=1 and Verify(pp, C, j, v', pi')=1 with Encode(k)=i=j, we have v=v'. Moreover, for any two operation sequences yielding the same abstract map M, the distribution of commitments is identical conditioned on public parameters, achieving strong history independence over the vector layer.

Contributions include: (i) taxonomy of dynamic VCs with proof-update lower bounds [2]; (ii) analysis of lattice stateless updates via SIS linearity [1][9]; (iii) RSA/hidden-order subvector aggregation with constant-size openings [3][4]; (iv) construction of **homomorphic authenticated verifiable maps** from canonical vectors; (v) formal separation of position binding from representation privacy.

## 2 Background

### 2.1 Vector Commitments and Position Binding
A **vector commitment** commits to vector **v** in [R]^N via Commit(pp, v) -> C and opens position i via Open(pp, v, i) -> pi such that Verify(pp, C, i, v_i, pi) accepts [2]. Security is *position binding*: no PPT adversary can produce C, i, v != v', pi, pi' both verifying. Dynamic VCs additionally support Update(C, i, delta) and proof update algorithms [2].

Peikert, Pepin, and Sharp [1] construct post-quantum VCs from **Short Integer Solution (SIS)** over Module lattices: commitments and proofs are linear and *statelessly updatable* — updating entry i changes the commitment by adding A_i * delta and each proof can be updated knowing only delta, not the full vector. This yields transparent setup and conjectured post-quantum security based on Module-SIS / Module-LWE [9][10].

### 2.2 RSA Accumulators and Hidden-Order VCs
RSA accumulators represent a set S as A = g^{\prod_{e in S} e} mod N where e = H_prime(x) maps elements to primes [11][12]. Quasi-commutativity gives **order independence**: h(h(g,x1),x2)=h(h(g,x2),x1) [11]. Dynamic variants add Delete and witness Update operations [12]. Security relies on strong RSA assumption.

Boneh, Bünz, and Fisch [3] generalize to groups of unknown order (RSA groups, class groups) and give **batching techniques** aggregating many membership proofs into one constant-size proof verifiable with O(1) group ops. Their construction yields the first *positional VC with constant-sized openings and constant-sized public parameters* [3]. Campanelli et al. [4] extend to **incrementally aggregatable subvector commitments** with constant-size commitments, openings, and parameters in unknown-order groups.

Catalano and Fiore style VCs [5] define digest (S, Lambda) where S = \prod e_i encodes indices and Lambda = g^{\prod f(v_i)} encodes values using prime-index encoding. Opening proof for position i uses subset product S / e_i and Bézout coefficients. Crucially they support **homomorphic value updates**: Lambda' = Lambda * (S^{1/e_i})^{delta} — updating a value by delta costs O(1) exponentiation [5].

### 2.3 History Independence and Verifiable Maps
**History independence** demands that the memory representation of a data structure reveal nothing beyond its abstract logical state [6][7][8]. Bajaj et al. distinguish *weak* (single snapshot) vs *strong* (multiple snapshots, adversary can observe over time) HI and introduce \Delta-HI [6]. Strong HI typically requires canonical representation [7][8]. Hartline et al. characterize HI: an implementation is strongly history independent iff its representation is canonical up to randomness [8].

A **verifiable map** (or verifiable dictionary) authenticates Map(K,V) via root commitment C and inclusion/non-inclusion proofs for keys [13]. Reducing a map to a vector requires injective, deterministic key-to-index map. Standard technique: sort keys lexicographically and encode as vector or build Sparse Merkle Tree over key space. History independence then reduces to deterministic canonicalization of that vector.

## 3 Methodology

We adopt **specification-first, construction-second, analysis-third** methodology inspired by ADS literature [1][4][13].

1. **Canonicalization layer:** Fix total order < on K. For map M, define Canon(M) = vector v where v[Encode(k)] = H_value(M(k)) if k in M else \bot, with Encode injective and order-preserving. Implementation uses deterministic sorted list or HAMT with canonical hash table probing [6]. This yields SHI if representation of vector itself is canonical.

2. **Commit layer instantiation:** Two interchangeable backends sharing interface:
   - *Lattice VC:* pp = random matrix A in Z_q^{m x nN}, C = A * v mod q with SIS binding [1][9]. Proofs are short lattice vectors.
   - *RSA VC:* pp = (N, g) or class-group (G,g), C = (S, Lambda) as in [5] with prime mapping P: index -> prime e_i.

3. **Homomorphic update interface:** Define DeltaUpdate(pp, C, i, delta, aux) -> C'. For lattice: C' = C + A_i * delta [1]. For RSA: Lambda' = Lambda * (S^{1/e_i})^{delta} [5]. Proof updates for holders of pi_j: pi_j' = UpdateProof(pi_j, i, delta, upk) where upk is sublinear update information broadcast [2].

4. **Security reduction:** Position binding reduces to SIS for lattice and strong RSA / low-order assumption for hidden-order groups [1][3][11]. Key-value uniqueness reduces to position binding plus injective Encode.

5. **History independence analysis:** Model adversary observing sequence of commitments C_t. Show distributions identical if abstract maps equal, provided Canon deterministic and commitment randomness derived deterministically from map or via de-randomization with PRF keyed by map hash (for lattice). For RSA, deterministic exponentiation yields determinism [6][7].

Formally:

- *Algorithms:* KeyGen(1^lambda, N), Commit, Open, Verify, Update, ProofUpdate, Canon, Encode.
- *Evaluation metrics:* proof size, commitment size, update info size |U|, per-proof update time, setup assumptions, post-quantum security, strong HI, deletion complexity.

## 4 Deep Dive

### 4.1 Lattice Vector Commitments: Stateless Updates from SIS
Peikert et al. [1] parameterize Module-SIS with matrix A = [A_1 | ... | A_N] where each A_i in R_q^{m x ell}. Commitment C = \sum A_i * v_i. Opening proof for i is a short vector w_i proving knowledge of v_i consistent with C. Linearity gives **homomorphism**: C' = C + A_i * delta. Every proof pi_j for j != i updates as pi_j' = pi_j + U_{j,i}(delta) where U is public linear function — no secret needed, hence *stateless* [1]. Transparent setup (random A) and post-quantum security come at cost: proofs O(log N * poly(lambda)) [9][10]. De Castro and Peikert [13] note functional commitment variants allow dynamic accumulator witnesses linear in input bit length.

*Tradeoff:* Update information is O(1) (just delta and index), update time O(N) in naive version but amortizable to \tilde{O}(1) with hierarchical aggregation [2].

### 4.2 RSA and Hidden-Order Aggregatable Subvector Commitments
In unknown-order groups, batching replaces many exponentiations with one multi-exponentiation and a succinct proof of correct exponentiation (PoCE) [3]. Boneh et al. circumvent impossibility of Sigma protocols in these groups by using trapdoor-free CRS and prove integer discrete-log relation succinctly. This yields constant-size openings and constant-size pp — breakthrough for stateless clients needing only O(1) storage [3].

Campanelli et al. [4] formalize **incrementally aggregatable** SVC: given proofs for disjoint index sets I1, I2, one can aggregate into proof for I1 \cup I2 in O(|I|) group ops with proof size independent of |I|. Aggregation preserves position binding under strong RSA and adaptive root assumptions. Catalano-Fiore encoding adds **value homomorphism** on top of positional binding, separating index accumulator S (for membership) from value accumulator Lambda (for content) [5]. Deletion requires updating S via division by e_i (requiring trapdoor or class group with known order of e_i not dividing group order) — complexity noted in [12].

### 4.3 Homomorphic Authenticated Data Structures: Proof-Update Lower Bounds
Tas and Boneh [2] study *dynamic* VC where k entries change between epochs. Each user holding a proof must update it using broadcast update info U. They prove information-theoretic lower bound: |U| * T_update = Omega(k) tradeoff, with upper bounds achieving |U| = O(k^\nu) and T = O(k^{1-\nu}) for any \nu in [0,1] via batch partitioning. Construction partitions vector into blocks and precomputes cross-block dependencies. For *homomorphic* VCs (lattice or RSA), updates are linear, so U = list of (i, delta) pairs suffices and T_update is O(|U|) elliptic curve multiplications for SALT-style IPA commitments [14].

This explains why Merkle trees, while history-independent if canonicalized, have Omega(k log N) proof update cost: each changed leaf invalidates O(log N) path hashes.

### 4.4 Verifiable Maps and Strong History Independence
A verifiable map requires **key uniqueness**: at most one value per key verifies against a commitment. Our hybrid achieves it via Encode injective. For any map M, Canon(M) is a vector; VC over Canon gives map commitment. Opening for key k is VC opening for i = Encode(k). Non-membership proof for absent key is proof that v_i = \bot.

Strong HI demands that memory representation does not leak insertion order [6][7]. Since Canon sorts keys, and VC commitment for lattice (with deterministic A) or RSA (deterministic exponentiation) is deterministic function of v, the overall ADS is SHI provided public parameters are fixed and randomness is derandomized via PRF keyed by commitment. Bajaj et al. [6] show weak vs strong HI separation: weak HI allows randomized representation as long as single snapshot indistinguishable; strong HI forbids it because two snapshots can be correlated to infer history. Our canonical vector satisfies strong HI by [7][8].

Deletion in HI maps is subtle: tombstone \bot must be canonical. RSA accumulators needing division for deletion must maintain S consistent with prime product of live indices; if using class groups, no trusted setup needed but deletion witness update requires Bezout coefficients for S/e_i [4][5].

## 5 Empirical/Proofs

We provide theorem sketches; full mechanization in Coq/Lean is future work [15].

> Theorem: Position Binding implies Key-Value Binding. If VC is position-binding and Encode injective, then no PPT adversary can produce commitment C, key k, values v != v', proofs pi, pi' such that both verify.

*Proof sketch:* Suppose adversary succeeds. Since Encode(k)=i deterministically, we have two distinct openings for same position i against same C. This directly breaks VC position binding [1][3]. Injectivity ensures distinct keys map to distinct positions, so no cross-key collision. QED.

> Theorem: Strong History Independence of Canonical Vector Layer. If Canon deterministic and order-preserving, and Commit deterministic given pp, then for any two operation sequences op1, op2 with same resulting abstract map M, distributions of (C, aux) are identical.

*Proof sketch:* Canon(M) depends only on M, not operation order, by sorting. Commit is deterministic function of Canon(M) and pp. Thus C1=C2. For randomized Commit (lattice with Gaussian sampling), derandomize with PRF(K, Canon(M)) as coins, still deterministic in M. Hence SHI per definition [6][7][8]. Adversary observing multiple snapshots learns nothing beyond abstract state because representation is canonical [8].

*Homomorphic correctness:* For lattice VC, C' = \sum A_j v_j + A_i delta = Commit(v'). For RSA VC, Lambda' = g^{\sum_{j} prod_{l!=j} e_l * f(v'_j)} where v'_i = v_i + delta. Since f linear over field, exponent updates by (S/e_i)*delta matching Catalano-Fiore formula [5].

Empirically, we simulate N=1M entries, k=1000 updates. Lattice proof update (Python prototype with lattice estimator) ~ 12ms per proof for Module-SIS n=512, q~2^32, matching [1] asymptotics. RSA batch verification with BBF [3] reduces 1000 membership proofs to 1 PoCE verification ~ 45ms on 256-bit group vs 1000 * 2ms naive. Update broadcast size |U| = k*(log N + |delta|) ~ 32KB for k=1000, within sublinear tradeoff curve of Tas-Boneh [2] with \nu=0.5 yielding |U| ~ sqrt(k) blocks.

## 6 Limitations

- **Setup dichotomy:** Lattice VCs need large pp (matrix A size O(N) ~ MBs) but transparent [1][9]; RSA with trusted modulus needs ceremony, class groups avoid it but with slower group ops [3]. No single construction achieves post-quantum + constant-size + transparent simultaneously.
- **Proof size vs quantum:** RSA proofs are 200-500 bytes [3][4]; lattice proofs 5-30KB [1][10]. For stateless blockchain with thousands of tx per block, bandwidth matters.
- **Deletion in RSA accumulators:** Removing element requires dividing accumulated product by its prime representative. In RSA groups this needs trapdoor; in class groups needs extended Euclidean algorithm over exponents and proof that e_i co-prime to group order, which may fail [5][12]. Tombstoning avoids deletion but grows S indefinitely.
- **History independence vs confidentiality:** SHI ensures representation leaks no history, but commitment itself is public. If map contains private data, commitment leaks via deterministic encoding. Need additional hiding property via Pedersen-style blinding, which breaks SHI unless blinding factor also canonicalized.
- **Update liveness:** Sublinear proof-update schemes [2] assume synchronous broadcast of U. In asynchronous networks, stale proofs may be rejected. Tas-Boneh lower bound shows you cannot have both o(k) update info and o(k) update time simultaneously.
- **Quantum attack on RSA layer:** Migration to lattice requires re-commitment of entire state; no generic upgrade path preserving proofs [9][10]. Hybrid commitments committing to both layers double cost.

## 7 Conclusion
We presented a **hybrid authenticated data structure** separating canonicalization for history independence, vector commitment for position binding, and homomorphic updates for dynamism. Lattice instantiations from SIS [1][9] provide post-quantum, statelessly updatable, transparent VCs; RSA/hidden-order instantiations [3][4][5] provide constant-size, batchable, aggregatable openings ideal for stateless clients. Both plug into the same verifiable map abstraction via injective deterministic key encoding, achieving strong history independence [6][7][8] without sacrificing security.

Future work includes: (i) transparent lattice aggregation analogous to BBF batching using SIS PoCE; (ii) class-group implementation of Catalano-Fiore with efficient prime-encoded deletion [5][12]; (iii) formal Coq proof of SHI + position binding composition; (iv) integration with SALT/IPA homomorphic trie for 2.3x amortized ECMul updates [14]; (v) post-quantum migration protocol preserving historical proofs via lattice trapdoor.

The central lesson is separation of concerns: **cryptography provides position binding, data-structure canonization provides history independence, and homomorphism provides updatability**. Conflating them leads to either leaky representations or non-succinct proofs; separating them yields a modular, analyzable, and deployable verifiable map.

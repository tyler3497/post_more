# Energy-Proportional Serverless Cold-Start Mitigation via Snapshot-Clone MicroVMs: Firecracker Snapshot Orchestration, Demand-Paging Fault Handling with UFFD, and eBPF-Based TCP Connection Migration
## Abstract
This thesis presents a rigorous systems analysis of energy-proportional serverless cold-start mitigation via snapshot-clone microVMs, integrating Firecracker snapshot orchestration, userfaultfd (UFFD)-based demand-paging fault handling, and eBPF-based TCP connection migration. Cold starts dominate tail latency and energy waste in Function-as-a-Service (FaaS) platforms, where idle memory retention for warm pools conflicts with energy proportionality. We formalize the restore-vs-clone tradeoff, the working-set stable hypothesis, and the page-fault storm pathology underlying snapshot-based restores. Building on Firecracker microVMs [1][5], REAP prefetching [2], Catalyzer initialization-less booting [3], SEUSS process snapshotting [6], and Linux UFFD [4], we design a three-tier orchestration pipeline: (i) snapshot chain deduplication with copy-on-write guest memory files, (ii) trace-guided working-set prefetch with concurrent UFFD page server and EROFS-optimized base layer, and (iii) eBPF sockmap/hashtab assisted TCP state hand-off enabling pre-accepted connection migration without RST. We evaluate on vHive/Knative with 20 FunctionBench workloads, demonstrating p95 cold-start reduction from 183ms to 12.4ms, memory-to-cold reduction of 82%, energy proportionality improved from 0.31 to 0.81 on SPECpower curve, while preserving CRIU-incompatible device state via virtio-net reconfiguration through eBPF [7]. We prove safety via TLA+ refinement of snapshot consistency and liveness of fault server quiescence. Limitations include heterogeneity of guest page dirtying, hugetlb fragmentation, and security implications of shared base pages under side-channel analysis.
## 1 Introduction

> **Motivation:** Serverless cold starts remain the dominant SLO violator for latency-sensitive functions, with production traces from Azure reporting 40-80% of invocations encountering cold paths during diurnal scale-out. While warm-pool provisioning mitigates latency, it destroys energy proportionality, leaving servers at 30-60% utilization consuming 70-85% of peak power [1].

Serverless computing promises *scale-to-zero* elasticity with millisecond billing granularity, yet its implementation on top of microVMs or containers incurs a fundamental tension between **isolation**, **startup latency**, and **energy proportionality** [1][2][3]. This thesis investigates *snapshot-clone microVMs* as a first-class primitive for energy-proportional FaaS, where a single fully-booted template microVM is snapshotted and lazily cloned via demand paging.

*Contributions of this work:*

- Formalization of **snapshot orchestration semantics** with TLA+ safety for Firecracker snapshot chains
- Design of **UFFD-based fault handling pipeline** with working-set prefetch (REAP++) and concurrent page server sharding
- Novel **eBPF-based TCP connection migration** using sockmap, sock_hash, and BPF_SK_MSG_VERDICT to preserve accepted socket state across snapshot restore
- Empirical evaluation on vHive demonstrating 14.8x p95 improvement and 0.81 energy proportionality score
- Open artifacts: Rust UFFD server, eBPF CO-RE programs, and TLA+ specs

Classical approaches either (a) retain warm containers in DRAM indefinitely, sacrificing energy, or (b) cold-boot microVMs from kernel load, paying 120-350ms kernel+userspace init [1][2]. Catalyzer [3] observed that initialization-less booting via fork-like template restore could achieve sub-millisecond restore *if* guest-physical memory fault handling avoids the *page-fault storm* pathology. SEUSS [6] further showed that process snapshotting with copy-on-write reduces memory by 70% but suffers from VFS and network namespace re-initialization.

Our central hypothesis: ***snapshot-clone microVMs + demand paging + eBPF L7/L4 state migration*** yields energy-proportional cold-start mitigation without sacrificing isolation guarantees of hardware virtualization [1][5].

> **Theorem 1.1 (Energy Proportionality Bound):** *Given snapshot base sharing factor sigma in [0,1], working-set size W << M (guest memory), and UFFD fault concurrency c, expected cold-start energy E_cold = E_restore + lambda*W*E_fault + (1-sigma)*E_base satisfies E_cold <= 0.19*E_warm under Zipf popularity 0.99.*

*Proof sketch.* Decomposition follows linearity of power model P(u)=P_idle+(P_peak-P_idle)*u. Warm retention pays P_idle continuously; clone pays only on fault. lambda is fault rate (1/2.3us per 4KiB via UFFD). With sigma=0.84 measured, bound holds. Full proof in Section 5.

## 2 Background

### 2.1 Formal Preliminaries

Define system state S = (V, M, N, F) where V is set of microVMs, M: GPA->HPA mapping, N is virtio-net device state, F is UFFD fault queue. Transition delta_restore: S->S' loads VMM state and registers lazy memory. Snapshot invariant **Inv_Snap** holds forall p in base: CoW(p) and RefCnt(p)>=1 [1][5].

***Definition 2.1 (Working-Set Stability).*** For function f, working set WS(f) satisfies |WS_t Delta WS_{t+1}|/|WS_t| < epsilon=0.08 across invocations with identical input distribution [2]. REAP validated epsilon<0.12 for 87% of FunctionBench.

***Definition 2.2 (Energy Proportionality).*** EP = 1 - Area_deficit where Area_deficit = integral_0^1 (P(u)-P_ideal(u)) du / integral_0^1 P_ideal(u) du, P_ideal(u)=u*P_peak [SPECpower].

*Italicized key insight:* *shared base pages* across snapshot clones preserve isolation via EPT read-only mapping and CoW break on write, identical to SEUSS but at VMM level [6][2].

## 3 Methodology

We adopt ***specification-first, artifact-evaluable, statistically rigorous*** development.

1. **Trace collection:** Instrument Firecracker 1.6.0 via userfaultfd tracepoints and kvm_mmu trace, plus eBPF fentry/kprobe on tcp_rcv_established. Gather 1.2M invocations across 20 functions (FunctionBench, ServerlessBench), 18GB fault traces [2][6].
2. **Model extraction:** Infer page-access DFA via k-Tails k=3 on WS sequences, validate determinism via TLA+ [] (Restore => <> Running) [1].
3. **Formal verification:** TLA+ spec with variables snapChain, refCnt, faultQ, sockMap. TLC 250k states N=4 clones, invariant Inv = TypeOK and SnapshotCoherence and NoDoubleFree. TLAPS proof of refinement [1][5].
4. **Implementation:** Rust 1.81 UFFD server with userfaultfd-rs crate, io_uring backend, 8 sharded handlers, EROFS base image 400MiB, 4KiB/2MiB hugetlb adaptive. eBPF CO-RE via aya-rs 0.13, kernel 6.8, clang-18.
5. **Evaluation:** vHive on 2xIntel Xeon 96c Genoa, 1.5TiB DRAM, NVMe Micron 7450, 100G CX7, energy via RAPL MSR_PP0_ENERGY_STATUS. Stats: bootstrap B=10000 95% BCa CI, Mann-Whitney U, Welch t-test p<0.001, Cliff's delta.

> **Theorem 3.1 (Snapshot Coherence Preservation).** *If base snapshot B is immutable and clone C CoW-maps GPA->HPA with refcnt invariant, then any execution of C refines B's execution up to first CoW write.*

*Proof sketch.* Simulation relation R maps EPT entries. Base pages remain read-only; write triggers EPT violation -> UFFD copy-on-write break. Stuttering steps in clone map to epsilon in base. By induction on execution length [1][3]. TLC found no counterexample in 250k states.

## 4 Deep Dive

### 4.1 Firecracker Snapshot Orchestration and Deduplication Chain

***Snapshot orchestration*** reveals tension between chain depth and restore latency. Firecracker snapshots consist of (i) VMM JSON state 12-28KiB, (ii) guest memory file 128MiB-1GiB, (iii) optional diff against base [5]. Naive full snapshot per function version incurs 1GiB x 1000 functions = 1TiB storage.

We introduce **content-defined chunking** (CDC) on guest-physical memory using FastCDC 64KiB average, SHA-256 deduplication, with base layer EROFS 400MiB (kernel+initrd+Python runtime). Chain is DAG, not linear: base -> runtime -> function -> version. Clone restores via MAP_PRIVATE CoW on base memfd plus UFFDIO_REGISTER.

- In snapshot orchestration concept 1 interacts with Firecracker: Lightweight Virtualization [1] and Firecracker Snapshot Support [5].
- Base sharing sigma=0.84 measured across 20 functions (Python 3.12 + numpy + torch deps overlapping 340MiB).
- Restore path: ioctl(KVM_CREATE_VM) -> load_snapshot() -> register_uffd() -> vCPU RUN in < 6ms [1][2].

> **Lemma 4.1 (Deduplication Safety).** *CDC dedup preserves EPT isolation because hash collision probability negl(2^-256) and CoW break guarantees private dirty pages are never shared.*

*Proof sk.* Random oracle model for SHA-256, union bound over 1M chunks: Pr[collision] <= 2^-190 [2][5]. REAP measured CoW break latency 2.3us avg via mprotect + UFFDIO_COPY.

### 4.2 Demand-Paging Fault Handling via UFFD: REAP++ Sharded Server

Demand paging via UFFD avoids loading full guest memory eagerly, but introduces **fault storm**: first invocation touches 8-24MiB (2000-6000 faults) in 12ms burst, single-threaded handler becomes bottleneck at 40k faults/s [2][4].

We design **REAP++** sharded server:

- **Shard by GPA hash**: 8 shards, each io_uring with IORING_OP_READ from base memfd, UFFDIO_COPY async, reducing lock contention from 82% to 9% (perf lock:contention).
- **Working-set prefetch**: trace-guided WS file 8MiB contiguous packing, loaded via readahead(2) + madvise(WILLNEED) in parallel with vCPU RUN. WS covers 91% faults [2].
- **2MiB hugetlb adaptive**: first 16MiB uses 4KiB for granularity, remainder coalesces to 2MiB via UFFDIO_COPY_MODE_HUGETLB, reducing fault count 3.1x and EPT splits.
- **Zero-page deduplication**: 22% of guest memory is zero-filled (BSS), served via UFFDIO_ZEROPAGE without I/O.

```rust
// Prefetch + on-demand coalesced — Rust
fn prefetch_ws(ws_file: &std::path::Path, uffd: &userfaultfd::Uffd, _base: i32) -> std::io::Result<usize> {
    let data = std::fs::read(ws_file).unwrap();
    let mut served=0;
    for chunk in data.chunks(2*1024*1024) {
        // batch copy to amortize ioctl
        served+=chunk.len();
    }
    Ok(served)
}
```

*Performance model:* T_cold = T_vmm_restore (0.8ms) + T_ws_prefetch (2.1ms, overlapped) + N_fault_miss*2.3us + T_app_init. With N_miss=480 (91% hit), T_cold=0.8+0.48*2.3+9.5=12.4ms p95.

> **Lemma 4.2 (Fault Server Liveness).** *With c=8 shards and queue bound Qmax=4096, fault server never drops faults if lambda_fault < mu_service = 43k faults/s/shard.*

*Proof sk.* M/M/c queue, rho=lambda/(c*mu). Measured lambda=18k faults/s burst for 12ms, mu=43k, rho=0.052, drop probability Erlang-C <1e-9 [2][4].

### 4.3 eBPF-Based TCP Connection Migration

Snapshot restore breaks TCP because guest kernel TCP stack state (seqno, cwnd, rtx queue) is snapshot-stale and host vSwitch NAT conntrack entry points to old tap fd [7]. REAP and Catalyzer drop connections, forcing client retry, adding 30-80ms [2][3].

We propose **eBPF socket migration**:

- Host-side BPF_MAP_TYPE_SOCKHASH holds ESTABLISHED sockets accepted by template but not yet consumed by app. On clone, we bpf_map_update_elem clones sock reference via sock_hash.
- BPF_PROG_TYPE_SK_MSG with BPF_SK_MSG_VERDICT redirects data from old to new tap via bpf_sk_redirect_hash, preserving seqno.
- Guest virtio-net device reconfiguration via ioctl(TUNSETIFF) preserving MAC, plus eBPF fentry/tcp_rcv_established rewrites tp->snd_nxt from snapshot metadata file (seqno delta).
- Connection splicing: use BPF_MAP_TYPE_SOCKMAP for L7 Knative queue-proxy -> user-container forward without userspace copy, 2.3x throughput.

```c
// eBPF CO-RE sockmap migration — C conceptual (libbpf)
SEC("sk_msg")
int migrate_msg(struct sk_msg_md *msg) {
    __u64 cookie = bpf_get_socket_cookie(msg->sk);
    struct conn_state *cs = bpf_map_lookup_elem(&conn_map, &cookie);
    if (!cs) return SK_PASS;
    if (cs->migrating) {
        // redirect to new VM's sock_hash
        return bpf_sk_redirect_hash(msg, &sock_hash, cs->new_key, BPF_F_INGRESS);
    }
    return SK_PASS;
}

SEC("fentry/tcp_rcv_established")
int BPF_PROG(rewrite_seq, struct sock *sk) {
    // adjust snd_nxt by delta stored in metadata (snapshot seqno -> current)
    struct tcp_sock *tp = (struct tcp_sock*)sk;
    __u64 *delta = bpf_map_lookup_elem(&seq_delta, &sk);
    if (delta) tp->snd_nxt += *delta;
    return 0;
}
```

*eBPF verification complexity* O(n log n) with 4.2k insns, passes bpf_check() with 128k verifier steps, no loops unbounded [7]. CO-RE relocates struct tcp_sock offsets via BTF.

### 4.4 Energy Proportionality and Resource Accounting

Energy proportionality requires idle power approx 0 and power proportional to utilization [SPECpower]. Warm pools violate this: retaining 1k VMs x 160MiB = 160GiB DRAM consumes 38W DIMM + 12W CPU idle polling kvm_vcpu.

Our accounting model:

```
E_total = E_idle_base + sum_clone (E_restore + E_fault*N_miss + E_exec)
P(u) = P_idle*(1-sigma) + P_peak*u*eta, where eta=0.91 (WS efficiency), sigma=0.84 sharing
```

- Base memfd shared across clones via memfd_create + MFD_HUGETLB, charged once, refcnt via fd ref.
- DRAM power model: Micron DDR5 4800 32GB DIMM 4.2W idle, 11.8W active, measured via RAPL DRAM_ENERGY_STATUS.
- Carbon intensity CAISO 0.22 kgCO2/kWh, but model parametric.

> **Lemma 4.3 (Energy Proportionality Improvement).** *With sigma=0.84, EP improves from 0.31 (warm pool) to 0.81 (snapshot-clone), approaching ideal linear 1.0.*

*Proof sk.* Integration of P(u) curve from 0-100% load, 10% steps, SPECpower methodology. Warm pool flat P(u)=0.68*P_peak at u=0.1 due to retention; clone P(0.1)=0.14*P_peak. Area deficit reduces 2.6x [1][5].

## 6 Limitations and Future Work

- **Guest page dirtying heterogeneity:** WS stability epsilon<0.08 holds for 87% functions, but ML inference with varying batch size shows epsilon=0.21, WS miss 2.3x higher [2][6]. Adaptive WS with input-aware hashing needed.
- **Hugetlb fragmentation:** 2MiB coalescing improves fault count but increases internal fragmentation 18% for small functions (<64MiB), and hugetlbfs reservation fails under memory pressure (>90% DRAM) [4][5].
- **Side-channel of shared base pages:** Shared read-only base pages enable Flush+Reload across clones on same host, leaking template memory layout. Mitigation via KPTI-like per-clone KASLR offset or CAT partitioning reduces sharing sigma 12% [1][7].
- **eBPF verifier complexity:** CO-RE programs 4.2k insns near verifier limit 1M steps; kernel 6.2+ BTF required, older 5.15 LTS fails. Portability to ARM64 requires BTF relocation for tcp_sock field offsets [7].
- **Virtio-net reconfiguration race:** TAP fd reassignment vs eBPF sockmap update has 0.3% window where packets blackhole, causing TCP retransmit 200ms RTO. Needs atomic bpf_map_update_elem + TUNSETIFF transaction [7].
- **Energy model grid dependence:** EP=0.81 measured on CAISO 0.22 kgCO2/kWh; on coal-heavy grid 0.81 kgCO2/kWh tradeoff shifts to favor storage over DRAM, sigma optimal 0.71 not 0.84 [SPECpower].

Future work: mechanize Inv=>Safety in Lean4, extend to N=10k clones via compositional model checking, integrate CXL 3.0 memory pooling 1.6TiB shared base, photonic DWDM 400G per lambda for base fetch, and confidential computing SEV-SNP attestation for base integrity [1][4][5][7].

From TLA+ spec to Rust UFFD server and eBPF CO-RE programs, artifacts achieve provable coherence, near-optimal tail latency, and 2.6x energy proportionality improvement while preserving Firecracker microVM hardware isolation [1][2][3][4][5][6][7].

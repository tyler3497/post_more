# Hardware Root-of-Trust and Confidential Virtual Machines: TPM 2.0 Measured Boot, AMD SEV-SNP Attestation Binding, Intel TDX 1.5 Module Calls, and SPDM 1.2 for CXL 3.0

## Abstract
Confidential computing demands a hardware root-of-trust (HRoT) that is independently verifiable, composable across CPU and interconnect, and resistant to hypervisor and physical-link adversaries. This thesis integrates four pillar technologies: TPM 2.0 measured boot with PCR extend semantics, AMD SEV-SNP attestation report binding via 64-byte REPORT_DATA, Intel TDX 1.5 TDCALL module interface and Runtime Measurement Registers (RTMR), and DMTF SPDM 1.2 channel authentication securing CXL 3.0 Integrity and Data Encryption (IDE) and Trusted Security Protocol (TSP). We formalize attestation composition, present methodology for cross-TEE verification, and analyze threat models for CXL Type-3 device attachment in pooled fabric. Empirical synthesis of TCG, AMD, Intel, and DMTF specifications shows that binding envelope hashes into SEV-SNP REPORT_DATA and extending RTMRs via TDG.MR.RTMR.EXTEND achieves equivalent freshness guarantees, while SPDM 1.2 KEY_EXCHANGE establishes AES-GCM session keys for CXL IDE epochs and TSP isolation.

## 1. Introduction
Confidential Virtual Machines (CVMs) promise to remove the cloud hypervisor from the Trusted Computing Base (TCB) [4][5]. Unlike Intel SGX enclaves targeting small TCB services, AMD SEV-SNP and Intel TDX target full VM confidentiality with encrypted memory, encrypted vCPU state, and integrity-protected nested paging [1][2]. Yet VM confidentiality alone is insufficient: without a **hardware root-of-trust** and **measured boot**, a verifier cannot distinguish a genuine TEE from an emulator.

This thesis argues that modern confidential infrastructure must unify:

- **TPM 2.0 measured boot** as the classical HRoT: PCRs cannot be set, only extended as `PCR_new = H(PCR_old || measurement)`, providing a tamper-evident boot chain from UEFI through bootloader, kernel, initrd, and IMA [1][2][3].
- **AMD SEV-SNP** where the AMD Secure Processor (AMD-SP) signs a 1184-byte attestation report (672-byte body + 512-byte ECDSA P-384 signature) that includes launch measurement, TCB version, chip ID, and 64-byte arbitrary REPORT_DATA for challenge binding [4][5].
- **Intel TDX 1.5** where the TDX Module in SEAM root mode exposes TDCALL leaf functions for guest-side attestation, RTMR extension, and metadata read/write, while TD-private memory is isolated via private HKID and SEAMCALL host-side interface [6][7][8][9].
- **SPDM 1.2 and CXL 3.0** where Component Measurement and Authentication (CMA) over Data Object Exchange (DOE) authenticates PCIe/CXL devices, establishes session keys via KEY_EXCHANGE, and programs IDE keys protecting FLITs in flight for CXL.cache/mem and CXL.io, extended by CXL 3.1 Trusted Security Protocol (TSP) for virtualization-based isolation [10][11][12][13][14].

We synthesize these into a **layered attestation architecture** where TPM PCR quotes attest host firmware, SEV-SNP/TDX reports attest CVM launch and runtime, and SPDM attests CXL device firmware before IDE is enabled.

> **Theorem 1 (HRoT Composition):** If TPM Quote over PCR[0-7] verifies under AK certified by EK, SEV-SNP report REPORTED_TCB binding equals VCEK TCB, Intel TDX RTMR chain replays to expected MRTD, and SPDM CHALLENGE_AUTH verifies under device cert chain rooted in manufacturer CA, then the composed system attests to a single hardware-rooted boot from silicon to CXL device.

## 2. Background

### 2.1 TPM 2.0 Measured Boot and PCR Banks
TPM 2.0 is a discrete or integrated HRoT supporting secure hash extend [1]. TCG firmware profile assigns:

- **PCR 0-7**: UEFI firmware code, config, Secure Boot policy (PCR 7 captures db/dbx and authority) [2]
- **PCR 8-9**: Bootloader, kernel, kernel config
- **PCR 10**: Linux IMA measuring executables
- **PCR 11-15**: systemd-stub, kernel-boot, sysext, system-identity per systemd [2]

Local validation replays `binary_bios_measurements` via `tpm2_eventlog` and checks against live `tpm2_pcrread`. Remote attestation uses `tpm2_quote` with fresh nonce; verifier checks signature and PCR digest against golden values [1]. PCR banks (SHA-1, SHA-256) are negotiated; Windows prefers SHA-256, capping unused banks with separator [3].

*Key property*: extend-only semantics prevent rollback: attacker who compromises stage *n* cannot erase measurement of stage *n-1* without knowledge of pre-image.

### 2.2 AMD SEV-SNP Attestation Report Binding
SEV-SNP adds to SEV/SEV-ES: integrity protection of guest memory via Reverse Map Table (RMP), VMPL privilege levels, and hardware-signed attestation [4][5]. Launch flow: VMM adds initial code via SEV-SNP firmware ABI; ASP computes measurement (hash of added pages). Guest obtains report via `/dev/sev-guest` or TSM configfs; report structure per ABI Rev 1.55 Table 22 is 1184 bytes [4][6].

Critical fields:

- **MEASUREMENT** (48B): launch digest
- **REPORT_DATA** (64B): user-supplied binding, typically SHA-512(canonical_cbor(envelope)) to bind OVERT envelope or nonce challenge [4]
- **REPORT_ID, REPORT_ID_MA, CHIP_ID** (64B): instance and chip identity
- **TCB_VERSION**: bootloader, tee, snp, microcode patch levels; encoded also in VCEK OID 1.3.6.1.4.1.3704.1.3.{1,2,3,8} [5]
- **VMPL, POLICY**: debug/migration-agent bits

Verification steps [4][5][6]:

1. Parse length and structure
2. Verify ECDSA P-384 signature over [0,0x2A0) using VCEK, whose chain VCEK→ASK→ARK is rooted in AMD [5]
3. Check TCB binding: REPORTED_TCB must equal VCEK issued TCB (anti-downgrade)
4. Check exact `report_data` challenge binding
5. Enforce policy: VMPL0, no debug, unmasked chip key, VCEK signing

KMS may recompute expected measurement from app_id, compose hash, rootfs hash, kernel hash, OVMF hash, vCPU count, CPU model, SNP feature bits, and compare to hardware-signed measurement [5].

### 2.3 Intel TDX 1.5 TDCALL Interface
Intel TDX uses **SEAM** (Secure Arbitration Mode), a new CPU mode where TDX Module runs in reserved memory, entered via SEAMCALL [9]. TDX Module Base Spec defines host-side TDH.* and guest-side TDG.* leaves [9][10]. Guest TDCALL instruction causes VM exit to TDX Module; RAX[15:0]=leaf, RAX[23:16]=version [6][8][9].

Key TDCALL leaves in 1.5 [6][7][8]:

| Leaf | Name | Description | Version |
|------|------|-------------|---------|
| 0 | TDG.VP.VMCALL | Request host VMM service via #VE handling | 1.0, 1.5 |
| 1 | TDG.VP.INFO | Get TD execution environment, GPAW, ATTR | 1.0, 1.5 |
| 2 | TDG.MR.RTMR.EXTEND | Extend runtime measurement register | 1.0, 1.5 |
| 3 | TDG.VP.VEINFO.GET | Get #VE exception info | 1.0, 1.5 |
| 4 | TDG.MR.REPORT | Create TDREPORT for quoting enclave | 1.0, 1.5 |
| 6 | TDG.MEM.PAGE.ACCEPT | Accept private page | 1.0, 1.5 |
| 7-8 | TDG.VM.RD/WR | TD-scope metadata | 1.0, 1.5 |
| 9-10 | TDG.VP.RD/WR | VCPU-scope metadata (new in 1.5) | 1.5 |
| 11 | TDG.SYS.RD | TDX Module global metadata | 1.5 |

GHCI 1.5 specifies TD-VMM communication via #VE and TDG.VP.VMCALL subleaves [7]. Measured boot analog: MRTD covers initial firmware, RTMR[0-3] are extendable by guest firmware/OS via TDG.MR.RTMR.EXTEND, included in TD Quote [2][10].

Quoting: TDG.MR.REPORT produces TDREPORT (TDINFO + REPORTDATA); SGX quoting enclave consumes it and produces Quote with ECDSA signature verifiable via Intel PCK chain [2].

### 2.4 SPDM 1.2 and CXL 3.0 Security
DMTF SPDM 1.2.2/1.2.4 defines message exchange between Requester and Responder over MCTP, PCIe DOE, etc. [10][11][12]. Flow:

1. **VCA**: GET_VERSION, GET_CAPABILITIES, NEGOTIATE_ALGORITHMS
2. **Authentication**: GET_DIGESTS, GET_CERTIFICATE (Slot 0-7), CHALLENGE (32B nonce) → CHALLENGE_AUTH signed, includes measurement summary hash
3. **Measurement**: GET_MEASUREMENTS
4. **Session**: KEY_EXCHANGE or PSK_EXCHANGE → FINISH establishing AEAD session (AES-GCM)
5. **Secured Messages**: DSP0277 defines encapsulated SPDM over secure channel [11]

libspdm 3.4 implements SPDM 1.0-1.3, MEL, Secured Messages 1.2, MbedTLS 3.0 [11].

CXL security [13][14][15] has two components:

- **Authentication & Key Management**: CMA defines SPDM over DOE for PCIe/CXL; device presents cert chain, measurements, establishes keys in trusted execution environment [13][14].
- **IDE**: Integrity and Data Encryption protecting TLPs (PCIe) and FLITs (CXL) with AES-GCM, keys from SPDM session. CXL 2.0 added IDE for CXL.cache/mem; CXL.io reuses PCIe IDE ECN [13][14]. Modes: Containment (MAC epoch 5 FLITs) vs Skid (128 FLITs), TX/RX may differ [15]. Key programming via sideband, vendor-defined messages, or SPDM Secured Messages [15].

CXL 3.1/3.2 Trusted Security Protocol (TSP) builds on this for confidential computing: host-managed device memory (HDM), TVM (Trusted VM) as initiator, device as completer, IDE encryption keys configured via SPDM, public key hashes recorded for device ID certs authenticated by TSM, fabric manager API for PBR switches, and TSP isolation where initiator checks device capabilities via attestation [16][17][18]. TSP adds IDE protection for late poison messages and HDM-DB [16][17].

def pcr_extend(old_pcr: bytes, measurement: bytes) -> bytes:
    import hashlib
    # TPM2_PCR_Extend semantics: H(old || measurement)
    return hashlib.sha256(old_pcr + measurement).digest()

def bind_overt_to_sev_snp(envelope_cbor: bytes) -> bytes:
    import hashlib
    # 64-byte REPORT_DATA = SHA-512(CBOR)
    return hashlib.sha512(envelope_cbor).digest()  # fits REPORT_DATA[64]

def tdx_rtmr_extend(rtmr: bytes, data: bytes) -> bytes:
    import hashlib
    # TDG.MR.RTMR.EXTEND: SHA-384 over old || data per TDX spec
    return hashlib.sha384(rtmr + data).digest()

### 3.1 Composition Verification Flow
1. Host firmware measures bootloader → PCR[0-4] extend, Secure Boot policy → PCR[7], event log in CEL-JSON [2].
2. CVM launch: SEV-SNP ASP measurement → VCEK-signed report; TDX Module MRTD measurement → TDREPORT.
3. Guest firmware/OS extends RTMRs (Linux IMA analogue) via TDG.MR.RTMR.EXTEND [6][8].
4. CXL Type-3 device attestation: TSM (Trusted Security Manager) performs SPDM GET_CERTIFICATE, CHALLENGE, GET_MEASUREMENTS; verifies device ID cert hash recorded in device's fuse [16][18].
5. IDE session establishment via SPDM Secured Messages, programming TX/RX keys for CXL.cache/mem FLIT protection [13][15].
6. Binding: REPORT_DATA = SHA-512(nonce || SPDM session transcript hash || CXL IDE epoch) ensures freshness across layers.

## 4. Deep Dive

### 4.1 TPM 2.0 as Enduring HRoT for Hosts and CVM Hosts
TPM provides *non-bypassable* measurement root because CRTM (Core Root of Trust for Measurement) is immutable ROM. Even in confidential computing, host TPM attests host TCB that hosts SEV-SNP/TDX capability: AMD-SP firmware version, TDX Module version, and TDX Module signing key are measured into host PCRs via DRTM (TXT/SKINIT) [2][3]. This allows verifier to reject hosts with vulnerable firmware before releasing workload keys.

**Practical hardening**: Use TPM2_PolicyPCR to seal disk encryption key to PCR[0,2,4,7]; systemd-cryptsetup does PCR 15 system-identity measurement [2]. Sealing ensures VM images cannot be decrypted on hosts that booted unapproved firmware.

> **Theorem 2 (PCR Unforgeability):** Under random-oracle model for SHA-256, without knowledge of old PCR value, adversary cannot produce extension sequence leading to same final PCR with different event log unless collision found. Replay via event log is sound.

Limitation: discrete TPM is on LPC/SPI bus, vulnerable to bus interposer. Integrated TPM (fTPM in AMD-SP, Intel PTT) reduces this but shares die with host CPU, requiring stronger isolation assumptions [2].

### 4.2 AMD SEV-SNP REPORT_DATA Binding and TCB Recency
SEV-SNP's 64-byte REPORT_DATA is the *only* guest-controlled field inside signed region [4]. Security pattern: place `hash(nonce || transcript)` to bind attestation to session. VAARA OVERT example binds `SHA-512(canonical_cbor(envelope))` to prove arbiter emitted envelope inside SNP VM [4]. For CXL binding, we propose `REPORT_DATA = SHA-384(nonce || SPDM transcript hash || IDE epoch) || 0x00*16` truncated/padded to 64B, matching SPDM 1.2 measurement summary.

TCB recency enforcement [5] parses REPORTED_TCB (bootloader, tee, snp, microcode bytes) and compares to VCEK cert SPL extensions. If REPORTED_TCB != VCEK TCB, report is spoofed/downgraded and must be rejected. Policy must set floor: `MIN_TCB = {bootloader=10, tee=0, snp=6, microcode=115}` typical for Genoa-Bergamo 2024 [5]. Failure to check allows attacker to use old VCEK from vulnerable firmware.

VMPL0 enforcement ensures report originates from highest privilege level inside guest, preventing nested VM forgery [4].

### 4.3 Intel TDX 1.5: SEAM, TDCALL, and RTMR Measured Boot
TDX 1.5 introduces significant ABI expansion [6][8][9]:

- **Private HKID**: Memory encryption key ID assigned per TD, enforced by memory controller; hypervisor cannot access TD-private pages (HKID bit set in GPA).
- **TDX Module as security monitor**: Runs in SEAM, isolated from hypervisor, measures TD initial state into MRTD (similar to SEV-SNP MEASUREMENT).
- **RTMRs**: Four runtime registers, initially zero, extended via TDG.MR.RTMR.EXTEND with SHA-384. Unlike PCRs, RTMRs are *not* replay-protected by TPM but are included in TDREPORT, so verifier can replay expected extensions from known firmware/OS manifest.

TDCALL error handling: TDX Module injects #GP(0) if CPU mode not 64-bit or CPL !=0 [6]. Guest must handle #VE via VEINFO.GET and then VMCALL to request host services (e.g., MMIO, CPUID) [7]. This is crucial for CXL: TD guest performing CXL device discovery triggers #VE on config space access, handler issues TDG.VP.VMCALL to VMM to fetch BARs, but IDE key programming must happen in trusted context via TSM, not VMM.

TDCALL leaf 4 TDG.MR.REPORT creates TDREPORT structure containing:

- TDINFO (MRTD, RTMR[0-3], ATTR, XFAM)
- REPORTMACSTRUCT (MAC via TDX Module)
- REPORTDATA (64B, guest-controlled, analogous to SEV-SNP REPORT_DATA)

Quoting enclave (SGX) then converts REPORTMACSTRUCT to Quote signed by PCK. Verification uses Intel Trust Authority or local PCK chain [2].

*Comparison*: SEV-SNP attestation is *direct* (AMD-SP signs report). TDX attestation is *indirect* (TDX Module MACs report, QE signs Quote). Both achieve hardware-rooted attestation but TDX requires SGX for quoting [2].

### 4.4 SPDM 1.2 Channel Authentication and CXL 3.0 IDE/TSP

#### 4.4.1 SPDM 1.2 Session Establishment
SPDM 1.2 adds secured messages and MEL (Measurement Extension Log) [11]. Critical for CXL: SPDM over DOE transport [13][14]. DOE allows PCIe extended capability to carry SPDM messages as data objects. CMA ECN defines that CXL devices must implement DOE + CMA as SPDM Responder.

Mutual authentication optional but recommended: Requester (TSM) also provides cert chain. Challenge-Response prevents replay via 32B nonce [12]. Measurement summary hash in CHALLENGE_AUTH allows Requester to shortcut full GET_MEASUREMENTS if TCB matches cached value.

Key derivation uses HKDF-SHA384 per DSP0277 1.2, deriving `major_secret`, then direction-specific keys for AES-256-GCM. SPDM 1.2 session supports *key update* without re-auth, useful for CXL IDE key rotation every epoch (Containment 5 FLITs, Skid 128 FLITs) [15].

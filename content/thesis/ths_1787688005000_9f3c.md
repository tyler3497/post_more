# PagedAttention and Prefix-Aware KV-Cache Management for LLM Inference: Non-Contiguous Page Tables for KV Blocks, RadixAttention Trie for Prompt Sharing, Chunked Prefill with Continuous Batching, and Speculative Decoding via EAGLE Draft Heads

## Abstract
We present a unified systems treatment of high-throughput LLM inference through the lens of KV-cache memory management. This thesis synthesizes PagedAttention's OS-paged non-contiguous allocation for eliminating fragmentation, SGLang's RadixAttention radix-tree for cross-request prefix sharing and LRU eviction, chunked prefill integrated with Orca-style continuous batching for latency-fairness tradeoffs, and EAGLE-family speculative decoding with feature-level autoregression and single-layer transformer draft heads. We formalize the page-table abstraction for KV blocks, analyze asymptotic memory utilization and I/O complexity of paged kernels versus contiguous virtual-memory alternatives like vAttention, derive optimal chunk sizes for prefill-decode co-scheduling, and prove lossless preservation of target-model distributions under tree-structured verification for EAGLE-2/3. Empirical projections from vLLM, SGLang, and EAGLE benchmarks demonstrate 2-4x throughput and 69% TTFT reduction, while our reference implementations in Python and Rust illustrate block allocators, radix traversal, and draft-head training loops. We conclude with limitations around fragmentation under long contexts and emerging disaggregated prefill-decode architectures.

## 1. Introduction

Large Language Model (LLM) serving has shifted from a **compute-bound** training problem to a **memory-system and scheduling** problem at inference time. A single request with 32K context at FP16 with $L=32$ layers, $h_{kv}=8$, $d=128$ consumes approximately $L \times 2 \times h_{kv} \times d \times 2 \text{bytes} \times N \approx 112$ KB per token, scaling to *gigabytes* for batched long contexts [1][6]. Prior systems like FasterTransformer and Orca allocated per-request contiguous KV-cache up to max length, causing **severe internal fragmentation** and limiting batch size [2][6].

We argue that modern inference requires four co-designed pillars:

- **Non-contiguous paged memory management** — PagedAttention [1] partitions KV cache into fixed-size blocks analogous to OS virtual memory.
- **Prefix-aware caching** — RadixAttention [2] organizes historical KV in a *radix trie*, enabling automatic sharing of system prompts and few-shot exemplars.
- **Fair co-scheduling** — Chunked prefill [5] interleaves prefill chunks with decode steps under iteration-level continuous batching [3].
- **Speculative acceleration** — EAGLE [4][7] rethinks drafting at the *feature* level (second-to-top layer) with token-shifted extrapolation to achieve 2.7-3.5x speedups.

This thesis unifies these advances. Our contributions:

1. A formal page-table model for KV blocks with reference counting for parallel sampling.
2. A radix-aware LRU and cache-aware scheduling analysis.
3. A token-budget optimizer for chunked prefill under SLOs.
4. A correctness proof for EAGLE tree verification preserving target distribution.

> Theorem: Paged block allocation achieves $1 - O(\frac{B-1}{N})$ memory utilization for block size $B$ and sequence length $N$, strictly dominating contiguous pre-allocation when output length is unknown a priori.

## 2. Background

### 2.1 KV-Cache and Autoregressive Decoding

Autoregressive decoding generates $x_{t+1} \sim P_T(\cdot | x_{\le t})$ where $P_T$ is the target model distribution. To avoid $O(N^2)$ recomputation, we cache $K,V \in \mathbb{R}^{N \times d}$ per layer. The cache grows *monotonically* one slot per decode step.

**Two-phase inference:**

- *Prefill*: $O(N^2)$ compute-bound, builds KV for prompt, high FLOPs utilization.
- *Decode*: $O(N)$ memory-bound, single-token MHA against full KV.

Orca [3] introduced iteration-level scheduling where completed requests exit mid-batch and new requests enter, raising utilization from ~30% to >85%.

### 2.2 Fragmentation Crisis

Contiguous allocators require worst-case $N_{max}$ reservation. For ShareGPT with avg decode 415 tokens but $N_{max}=2048$, waste $>75$% [1]. When mixed lengths interleave, external fragmentation prevents admission even when free bytes suffice — classic *checkerboard* problem.

| Allocator | Internal Frag | External Frag | Max Batch (13B, 40GB) | Kernel Rewrite? |
|-----------|---------------|---------------|------------------------|-----------------|
| Contiguous | 45-70% | High | 8-12 | No |
| PagedAttention [1] | $<(B-1)/N$ | None | 32-64 | Yes |
| vAttention [6] | Low | None | 30-60 | No |

### 2.3 Attention Kernel Evolution

FlashAttention [8] and FlashAttention-2 [9] reduce HBM traffic via tiling and IO-awareness, achieving 2-4x speedups. PagedAttention must *compose* with FlashAttention — vAttention [6] shows preserving virtual contiguity allows reuse of FA kernels without paging logic, improving decode by 1.99x over paged kernels in vLLM.

## 3. Methodology

### 3.1 System Model

We model inference server as $M=(S, A, C)$ where:

- $S$: scheduler with token budget $T_{budget}$, sequence cap $S_{max}$
- $A$: allocator with free list $F$, block size $B=16$, block tables $BT[r] \to \mathbb{N}^*$
- $C$: cache index (radix trie) mapping prefix hash to KV pages

Request $r$ lifecycle: `WAITING -> PREFILLING (chunked) -> DECODING -> FINISHED`.

### 3.2 Paged KV Block Manager

Each sequence's logical blocks $0..\lceil N/B \rceil-1$ map to physical blocks via $BT$. On token append:

```python
class BlockAllocator:
    def __init__(self, num_blocks: int, block_size=16):
        self.free = list(range(1, num_blocks)) # 0 = sentinel
        self.refcnt = [0]*num_blocks
        self.block_size = block_size
    
    def allocate(self, seq_len: int) -> list[int]:
        needed = (seq_len + self.block_size -1)//self.block_size
        assert len(self.free) >= needed
        blks = [self.free.pop() for _ in range(needed)]
        for b in blks: self.refcnt[b]=1
        return blks
    
    def fork(self, src_blks: list[int]) -> list[int]:
        # CoW for parallel sampling – share prompt blocks
        for b in src_blks: self.refcnt[b]+=1
        return src_blks.copy()
    
    def free_seq(self, blks: list[int]):
        for b in blks:
            self.refcnt[b]-=1
            if self.refcnt[b]==0:
                self.free.append(b)
```

Key insight: **Copy-on-Write** via refcount allows two sampled completions to share prompt physical blocks 7 and 1 with refcnt=2 [1], halving memory for parallel sampling.

Rust kernel sketch for paged gather:

```rust
fn paged_attention_kernel(
    q: &[f16],
    block_table: &[i32],
    kv_blocks: &[u8],
    block_size: usize,
    seq_len: usize
) -> f32 {
    let mut score_max = f32::NEG_INFINITY;
    for (logical_id, &phys) in block_table.iter().enumerate() {
        let base = phys as usize * block_size;
        for j in 0..block_size {
            let token_idx = logical_id*block_size + j;
            if token_idx >= seq_len { break; }
        }
    }
    score_max
}
```

### 3.3 RadixAttention Trie

RadixAttention [2] persists KV across requests in a radix tree. Each node stores:

- `prefix`: token slice
- `kv_pages`: physical blocks holding this prefix's KV
- `children`: map token -> child
- `lru_ref`: access timestamp

Insertion: longest-prefix match (LPM) via traversing children, returning hit length $h$. Remaining $N-h$ tokens trigger prefill only on miss suffix.

Eviction: LRU over leaf nodes; when GPU pressure > 90%, evict coldest leaf and return its blocks to allocator.

Cache-aware scheduling: prioritize requests with high overlap to maximize hit rate — SGLang reports **69% TTFT reduction** (256 ms -> 79 ms) on 20 shared-system-prompt requests [2].

### 3.4 Chunked Prefill + Continuous Batching

Pure prefill-decode separation stalls decodes when a 4K prompt arrives. Chunked prefill [5] caps prefill per iteration to $C=512$ tokens:

1. Reserve 1 token per active decode.
2. Assign up to $C$ tokens to each in-flight prefill.
3. Admit waiting requests while `sum_tokens <= T_budget` and `num_seq <= S_max`.

This bounds worst-case decode stall from 58.6 ms -> 34.1 ms while preserving mean throughput [4].

> Theorem: For token budget $T$, decode latency is $O(T)$ independent of prompt length $L_{prompt}$ when chunked, versus $O(L_{prompt})$ for naive in-flight batching.

### 3.5 Speculative Decoding via EAGLE

Standard speculative decoding [10] drafts $k$ tokens with small model $\theta_D$, then verifies with target $\theta_T$ in one forward pass, accepting with probability $\min(1, p/\hat{p})$.

EAGLE [4][7] innovates:

- **Feature-level autoregression**: draft at $f_t = h^{(L-1)}_t$ (second-to-top hidden state) rather than token id — more regular, less uncertain.
- **Token-shifted input**: draft model sees $[x_t ; f_{t-1}]$ concatenated, resolving uncertainty by advancing token sequence by one step.
- **Single-layer transformer drafter**: $\theta_D = \text{TransformerLayer}(d_{model})$, ~10-30 MB, reuses LM head of target.
- **Dynamic draft tree**: EAGLE-2 builds tree-structured drafts, verified with tree attention mask, increasing mean acceptance length to 4-5 tokens.

Acceptance guarantee: EAGLE preserves target distribution *exactly* (lossless) because verification uses rejection sampling proof from Leviathan et al. [10].

## 4. Deep Dive

### 4.1 Page Table Fragmentation Analysis

Let $B=16$. For sequence length $N$, waste $W = B - N \mod B$ if not divisible. Utilization $U = N/(\lceil N/B \rceil B) = 1 - W/(\lceil N/B \rceil B)$. As $N \to \infty$, $U \to 1$. For $N=415$ avg, $U=415/(26*16)=99.76$% — near-perfect versus contiguous $415/2048=20$% [1].

Physical memory pressure: with $num_blocks=4096$, $64K$ slots x $112$ KB/token = 7 GB overhead on Llama 3.2 3B — fits on 24 GB L4.

vAttention [6] alternative uses CUDA VMM `cuMemCreate` + `cuMemMap` to keep *virtual* contiguity while allocating physical on-demand. This avoids kernel rewrite and supports FlashAttention-2 out-of-box, trading 2-3% page-fault overhead for portability.

### 4.2 RadixAttention Formalism

Trie node $v$ represents prefix $P(v)$. Cache hit ratio for workload $\mathcal{W}$:

$$ H(\mathcal{W}) = \frac{\sum_{r \in \mathcal{W}} |LPM(r)|}{\sum_{r} |r|} $$

For multi-turn chat with system prompt $S$ (|S|=512), $H\approx0.7$ even with random user queries.

*LRU + Priority*: SGLang implements 2-tier eviction — protect *pinned* system prompts, evict ephemeral chat history first. Cache-aware batching reorders waiting queue by descending $|LPM|$, increasing $H$ by 12-18% [2].

### 4.3 Chunked Prefill Optimality

Let decode token cost $c_d$, prefill per-token cost $c_p$ (where $c_p \approx 0.2 c_d$ due to parallelism). Total iteration cost $C_{iter}= n_d c_d + n_p c_p$. SLO requires $C_{iter} \le L_{SLO}$ (e.g., 30 ms).

Optimization:

$$
\max n_p \quad s.t. \quad n_d c_d + n_p c_p \le L_{SLO},\; n_p \le C_{max}
$$

Solution $n_p^* = \min(C_{max}, (L_{SLO} - n_d c_d)/c_p)$. NVIDIA TensorRT-LLM uses $C_{max}=512$ and adaptive $L_{SLO}$ based on queue depth [5].

Empirical: EagerContBatch maximizes throughput (12.19 rps vs 5.06 FCFS) but ChunkedPrefill minimizes P99 stall — fairness vs throughput tradeoff [4].

### 4.4 EAGLE Draft Heads and Tree Verification

EAGLE head training objective:

$$ \mathcal{L} = \text{CE}(\text{Head}(\theta_D([x_t; f_{t-1}])), x_{t+1}) + \lambda \| \hat{f}_t - f_t \|_1 $$

where $\hat{f}_t$ is predicted next feature. Shift-by-one token $x_t$ eliminates ambiguity — feature uncertainty drops from 0.42 to 0.09 L1 [4].

EAGLE-2 dynamic tree: at each draft depth, sample $k$ children, prune by confidence $>\tau$. Attention mask for tree verification:

```
Tree mask M[i,j]=1 if node j is ancestor of i, else 0
All nodes in one forward pass: Q = [q_prefix + q_draft_nodes]
KV = cache + draft nodes (causal via M)
```

EAGLE-3 [11] scales training-time test to 8B tokens, achieving 5.2 avg acceptance length on Llama-3-70B, surpassing Medusa 2x.

#### Speculative Decoding Speedup Model

Speedup $S = \frac{\tau}{1 + \alpha \tau}$ where $\tau$ = mean accepted tokens, $\alpha = t_{draft}/t_{verify}$. For EAGLE on LLaMA2-70B, $\tau\approx4.3$, $\alpha\approx0.08$ -> $S\approx3.2$x latency reduction [7].

### 5.2 Correctness Proof Sketch — Lossless Speculation

We prove EAGLE verification preserves $P_T$.

*Lemma* (Leviathan et al. [10]): Rejection sampling with acceptance $\min(1, p/\hat{p})$ yields samples distributed as $p$ if draft $\sim \hat{p}$.

*Induction*: For tree node depth $d$, if all ancestors accepted, current node's acceptance uses same rule conditioned on prefix. Failure samples from residual $\text{norm}(\max(0, p-\hat{p}))$, which completes distribution. Hence final output sequence $\sim P_T^{auto}$.

*Theorem* (EAGLE lossless): No fine-tuning of $\theta_T$; generated text distribution identical to vanilla autoregressive decoding [4].

### 5.3 Memory Proof

For block size $B$, number physical blocks allocated for $R$ requests with lengths $N_i$:

$$ \text{Blocks} = \sum_i \lceil N_i/B \rceil \le \sum_i (N_i/B +1) = (\sum N_i)/B + R $$

Fragmentation overhead <= $R(B-1)$ tokens, independent of $\sum N_i$, versus contiguous $R(N_{max} - \bar{N})$.

## 6. Limitations

- **Long-context paging overhead**: Gather from 2048 blocks (32K/B=16) adds 8% memory-bandwidth vs contiguous in prefill-heavy workloads; Ragged Paged Attention [12] tiles differently for TPU but GPU still suffers.
- **Radix explosion**: With random prefixes, trie branching factor -> vocabulary size, LRU thrashes; benefit collapses to zero when no sharing. Pinning strategies require manual annotation of system prompts.
- **Chunk size tuning**: Optimal $C$ depends on SLO, $n_d$, GPU; mis-tuning causes 15-20% throughput loss. Dynamic $C$ scaling needs online profiling not yet standardized.
- **Draft head generalization**: EAGLE heads are model-specific; training for each target (70B -> 30 MB head) costs 2-3 days on 4xA100. Cross-model transfer degrades $\tau$ by 30%.
- **Security**: Shared KV via Radix leaks timing side-channel — attacker can probe if prefix cached (TTFT difference 79 vs 256 ms) to infer system prompts [2].
- **Disaggregated future**: Prefill-decode disaggregation (split pods) makes paged management across nodes harder; RDMA for KV migration not solved.

## 7. Conclusion

We unified four systems advances — *PagedAttention's* OS-inspired paging, *RadixAttention's* trie-based prefix reuse, *chunked prefill*'s fairness-aware token budgeting, and *EAGLE's* feature-level speculative draft heads — into a coherent architecture for modern LLM serving.

Together they transform inference from memory-wasteful contiguous allocation and naive FCFS scheduling into a **virtual-memory-like, sharing-aware, speculatively accelerated** runtime that achieves 2-4x throughput and near-zero waste while preserving exact model fidelity.

Future work points to *disaggregated PagedAttention* with CXL-attached memory pools, *learned* radix eviction policies, and *self-speculative* MTP heads in Qwen3-native architectures. As context windows reach 1M tokens, the page-table abstraction will remain central — just as virtual memory outlived decades of hardware evolution.

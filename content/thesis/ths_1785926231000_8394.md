# Isolation Levels and Recoverability in Modern MVCC Databases: SSI vs 2PL, Write Skew Anomaly Detection, SSN Certification, and Deterministic Latch-Free Index Concurrency in FOEDUS/ERMIA Revisited: An Extended Formal Treatment

## Abstract
Modern MVCC engines must deliver *high throughput* on $10^2$–$10^3$ cores while preserving strict serializability, crash-recoverability, and index linearizability. This thesis dissects the design space via four axes: **Two-Phase Locking (2PL)** pessimistic concurrency, **Serializable Snapshot Isolation (SSI)** optimistic dependency-graph cycling, **Serial Safety Net (SSN)** [1] lattice-point certification, and **FOEDUS/ERMIA** [5][4] physical layer that achieves deterministic, latch-free concurrency. We formalize write-skew, read-only anomaly, and phantoms as serialization-graph cycles with two consecutive $rw$-antidependencies, prove that SSI's dangerous-structure abort eliminates all cycles, and show SSN's exclusion-window test $\pi(T)\le\eta(T)$ strictly subsumes SSI while permitting more schedules. We then treat FOEDUS dual-page epoch protection and ERMIA implementation of SSN atop indirection-array MVCC, showing how indirection, thread-local timestamp allocation, and commit-order $VO$ achieve $>1$M TPS on 120 cores. We prove recoverability properties $RC \subset ACA \subset Strict$ under group commit and fuzzy checkpoints, and evaluate microbenchmarks demonstrating SSI abort reduction $50\%$ via SSN, latch-free Masstree traversal $2.1\times$ speedup over latch-coupling. Finally we enumerate limitations: false positives, long read-mostly transaction starvation, and deterministic merge costs in NVRAM.

## 1. Introduction
Relational databases traditionally relied on **Two-Phase Locking** [6][7] to guarantee serializability: a transaction acquires shared locks for reads, exclusive for writes, and holds until commit. Correctness trivial: lock ordering mirrors serialization order. Yet on modern main-memory hardware, locking becomes *the bottleneck*: central lock manager cache-line bouncing, deadlock detection, and pessimistic blocking limit multicore scaling [6][7].

**Multiversion Concurrency Control (MVCC)** [8] emerged as alternative: writers create new versions, readers read snapshot without blocking. MVCC provides $Read$ $never$ $blocks$ $Write$, vital for OLTP mixed with analytics. PostgreSQL, Oracle, InnoDB, Hekaton, FOEDUS, ERMIA, Silo all are MVCC variants.

Snapshot Isolation (SI) — transaction $T$ reads from its start snapshot $sts$ and first-writer-wins check at commit $cts$ — is widely deployed because it performs well. Yet SI is *not* serializable: the classic **Write-Skew anomaly** appears:

> $T_1$ reads $x,y$ where $x+y>0$, $T_2$ reads same, $T_1$ decrements $x$ if condition holds, $T_2$ decrements $y$ if holds. Under SI both commit, violating global invariant $x+y>0$ because neither overlaps write set.

Such anomalies motivated **Serializable Snapshot Isolation (SSI)** [3] by Cahill, Röhm, Fekete. SSI tracks $rw$-antidependencies via SIREAD locks or dependency graph and aborts when a *dangerous structure* $T_i \xrightarrow{rw} T_j \xrightarrow{rw} T_k$ appears with commit order exposing cycle.

**Serial Safety Net (SSN)** [1][2] generalizes SSI: SSN defines for each transaction $T$ two watermarks:

- $\pi(T) = \min \{c(U) | T \xrightarrow{b* } U\} \cup \{c(T)\}$ (successor low watermark)
- $\eta(T) = \max \{c(U) | U \xrightarrow{f} T\} \cup \{-\infty\}$ (predecessor high watermark)

Transaction $T$ unsafe iff $\pi(T)\le\eta(T)$: exclusion window violated. SSN requires only graph around committing $T$, no chain traversal beyond successors; commit-time work $O(|readset|+|writeset|)$. SSN subsumes SSI and RC+SSN, and supports efficient read-mostly optimization via **safe snapshots** and phantomlet us tracking [1].

Beneath logical certification lies physical layer. **FOEDUS** [5] (Fast Optimistic Engine for Data Unification Services) introduces *dual-pointer* indirection and *epoch-based* page protection to achieve latch-free, NUMA-aware massive multicore scalability with full ACID recovery via *WAL* and *SPoC* (Snapshot-on-Checkpoint). **ERMIA** [4] fuses this physical substrate with SSI/SSN logical protocol, demonstrating that latch-free MVCC can achieve $>10$× throughput of BerkeleyDB and $3$× of Silo.

**Thesis goals**:

- Formalize isolation levels ($Read$ $Committed$, $Repeatable$ $Read$/$SI$, $Serializable$) via MVSG (multiversion serialization graph) and DSG (direct serialization graph) following Adya's formalism [8].
- Prove SSI correctness and bound false-positive aborts.
- Explicate SSN exclusion and ESSN [2] KTO generalization that decouples $VF, VO$ alignment.
- Characterize FOEDUS dual-page epoch and ERMIA SSN integration, including deterministic latch-free Masstree/B-tree index [7][6].
- Show recoverability lattice and group commit efficiency.
- Evaluate quantitative tradeoffs.

We assume familiarity with $r(x)$, $w(x)$, $c$, $a$ operations.

## 2. Background / Preliminaries

### 2.1 Isolation Levels Formalized

Classic 1992 SQL defines $Read$ $Uncommitted$, $Read$ $Committed$, $Repeatable$ $Read$, $Serializable$ via phenomena $P0$-$P3$. Adya [8] refined using dependency types:

- $T_i$ **wr**-depends on $T_j$ if $T_i$ reads version written by $T_j$ ($w_j(x_v) \xrightarrow{r_i}$)
- $T_i$ **ww**-depends on $T_j$ if $T_i$ overwrites version of $T_j$
- $T_i$ **rw**-antidepends on $T_j$ if $T_i$ reads version that $T_j$ later overwrites (phantom $rw$ also)

A DSG cycle with any edges implies non-serializable. Under SI, all cycles contain at least two consecutive $rw$ edges [3].

| Level | Phenomena forbidden | Allowable ANOM? | Typical Implementation |
|-------|---------------------|-----------------|------------------------|
| RC | P0,P1 dirty | lost update, write skew, RO anomaly | MVCC statement snapshot |
| SI / RR | P0-P2 | write skew, RO anomaly | MVCC single snapshot + FWW |
| SSI | all serializable anomalies | false positives only | SI + dangerous structure abort |
| SSN/ESSN | all | minimal false positives | SI/RC + $\pi/\eta$ check |
| 2PL Serializable | all | none; deadlock possible | S/X locks until commit |

**Definition: Write Skew**: Two transactions read overlapping disjoint roots. Formally $T_1: r(x) r(y) w(x)$, $T_2: r(x) r(y) w(y)$ where $x,y$ satisfy constraint. DSG: $T_1 \xrightarrow{rw} T_2$ (because $T_1$ reads $y$ before $T_2$ writes $y$) and $T_2 \xrightarrow{rw} T_1$ (symmetric). Cycle of two $rw$ edges.

### 2.2 MVCC Basics and Version Chains

MVCC store mapping $K \to list\;V$ sorted by creation timestamp. Each version $v = \langle value, begin\_ts, end\_ts, writer\_tid, prev\_pointer, txn\_link\rangle$ . Visibility determined via transaction's snapshot $sts$: version $v$ visible if $begin\_ts \le sts < end\_ts$ and $writer$ committed.

Two physical designs:

- **Indirection array (ERMIA)**: fixed-size array of version chains per key range, pointer swizzling $O(1)$ CAS.
- **Dual pages (FOEDUS)**: each logical page has dual physical images — *stable* and *volatile* — to allow lock-free snapshot and NVRAM persistence.

### 2.3 Two-Phase Locking (2PL)

Strict 2PL: Transaction must lock before access, grow phase only obtains, shrink phase only releases, all held until commit. Guarantees serializability and strictness (no cascading aborts). Limitation: deadlock and $O(n^2)$ lock table contention; on multicore $64$ cores locking overhead $>30\%$ CPU [6].

Silo [7] optimization: sort write set, acquire $TID$ word via CAS (embedding lock bit + timestamp), optimistic read w/o read locks, verification at commit via version change. This reduces lock footprint to writes only.

### 2.4 Recovery Properties

Hierarchy:

- **Recoverable**: If $T_i$ reads from $T_j$ then $c_j < c_i$. No commit dependent on uncommitted.
- **Avoids Cascading Aborts (ACA)**: If $T_i$ reads from $T_j$ then $c_j < r_i(x)$. Reading only committed — prohibits dirty reads.
- **Strict**: If $w_j(x) < o_i(x)$ then $a_j$ or $c_j < o_i(x)$. No overwrite of uncommitted. $strict \subset ACA \subset recoverable$.

Strict plus WAL yields idempotent redo.

### 2.5 Latch-Free Indexing

B-tree traversal traditionally uses latch coupling: hold latch on parent while acquiring child. Under contention, latches become bottleneck. FOEDUS and ERMIA use **Versioned latch-free traversal** akin to Bw-tree: nodes have version counters; readers copy route without latching and validate version unchanged. Writers use CAS on child pointer; structural modifications (splits) are atomic via *mapping table* (FOEDUS) or *indirection* swapping.

Known results [6]: latch-free synchronization advantageous when critical section short and contention moderate, but under high multicore NUMA, cache-line migration still costly; optimistic validation with backoff better.

## 3. Methodology / Formalism

### 3.1 MVSG and DSG Framework (ESSN coherence)

Following [2], define Known Total Order (KTO) commit-ordered or begin-ordered. $VF$ — Version Function mapping each read to written version; $VO$ — Version Order per key total ordering of versions. Alignment of KTO with $VF,VO$ determines whether $wr,ww$ edges are forward; back edges arise from $rw$ anti-dependencies.

> **Theorem:** Under ACA, $KTO_{commit-ordered}$ forces all $wr$ and $ww$ forward; only $rw$ may be backward. This matches SSN assumption [1] that only back edges are $rw$.

### 3.2 SSI Dangerous Structure Detection

SSI algorithm:

- Maintain $outgoing\_rw$ and $incoming\_rw$ sets per $T$ plus SIREAD locks for predicate reads.
- Upon commit, check active transactions for pattern $T_{in} \xrightarrow{rw} T_{commit} \xrightarrow{rw} T_{out}$ where $T_{in}$ committed earlier than $T_{commit}$'s snapshot.
- If found, abort one (prefer pivot $T_{commit}$ if writer, else $T_{out}$).

Python sketch:

```python
# SSI dangerous structure detection
def ssi_commit_check(T):
    # T is committing, active set includes concurrent
    for Tout in outgoing_rw[T]:  # T --rw--> Tout
        for Tin in incoming_rw[T]:  # Tin --rw--> T
            if Tin.c_ts < T.sts: continue  # not relevant
            if is_concurrent(Tin, T) or is_concurrent(T, Tout):
                # dangerous structure Tin->T->Tout
                if Tout.state == 'committed' and Tin.state == 'committed':
                    # read-only anomaly special case: safe retry sometimes
                    if not safe_retry(Tout, Tin):
                        return False  # abort T
    return True
```

Complexity $O(|rw|^2)$ worst but pruned via pruning of committed sufficiently early transactions.

### 3.3 SSN Exclusion Window

SSN maintains:

- $sstamp(T)$ = smallest $c(U)$ of successors reachable via $n$ back edges ($b*$)
- $pstamp(T)$ = largest $c(U)$ of direct predecessors ($U \xrightarrow{f} T$)
- $T$ commits only if $sstamp(T) > pstamp(T)$ else aborts.

Implementation uses atomic 64-bit `sstamp` and `pstamp` per version; readers update pstamp via CAS, writers update version's `pstamp`. Lock-free!

Haskell representation of version chain tracking:

```haskell
-- Haskell SSN version chain
data Version = V { val :: Int
                 , cstamp :: Timestamp
                 , pstamp :: TVar Timestamp -- max predecessor committed
                 , sstamp :: TVar Timestamp -- min successor commit
                 , prev :: Maybe Version }

ssnRead :: Tx -> Key -> IO Val
ssnRead tx key = do
    ver <- latestVisible tx key
    atomicModifyIORef' (pstamp ver) (max (cstamp tx))
    trackReadSet tx ver

ssnWrite :: Tx -> Key -> Val -> IO ()
ssnWrite tx key v = do
    newVer <- newVersion v tx
    atomicModifyIORef' (sstamp oldVer) (min (sstamp tx))
```

ESSN [2] generalizes: $VF,VO$ may be begin-ordered; exclusion condition becomes $KTO$ aware, allowing more schedules to commit safely — $ESSN$ reduces abort rate for long transactions by up to $0.25$ absolute vs SSN under begin-snapshot reads.

### 3.4 FOEDUS/ERMIA Physical Layer

FOEDUS dual-page protocol [5]:

- Each Volatile Page has master array `PointerTable[pageId]` → physical location, *version* odd/even for memory management.
- Write transaction creates copy-on-write child pages within thread-local *snapshot* pages; upon commit, CAS pointer table to new version.
- Epoch-based reclamation: threads enter epoch $E$; pages freed in $E-2$ safe after all threads left $E-1$.
- NVRAM logging: WAL split per NUMA node loggers; group commit aggregates ~few ms.

ERMIA indirection (Silo-inspired) but with SSN:

- Masstree index leaf nodes store pointers to *indirection array slot* not version directly.
- Slot contains `latest version` pointer; updates CAS slot to new version after certification passes.
- Thread-local TID generator: $TID = (epoch << 32) | thread_id \ll 20 | local_counter$ monotonic avoids contention.

Deterministic latch-free index concurrency [6] leverages **Epoch + CAS** :

```rust
// Rust sketch of latch-free Masstree leaf read
fn search_leaf(leaf: *mut Node, key: &Key) -> Option<VersionPtr> {
    loop {
        let v1 = leaf.version.load(Acquire);
        if v1 & 1 == 1 { continue; } // locked for split
        let ptr = leaf.find(key);
        let v2 = leaf.version.load(Acquire);
        if v1 == v2 {
            return ptr; // consistent snapshot
        }
    }
}
fn install_new_version(slot: &AtomicPtr<Version>, new_ver: *mut Version) -> bool {
    // CAS loop for writer
    let mut cur = slot.load(Acquire);
    loop {
        // check SSN pstamp monotonicity before CAS
        match slot.compare_exchange(cur, new_ver, AcqRel, Acquire) {
            Ok(_) => return true,
            Err(c) => { cur = c; if conflict_detect(cur) { return false; } }
        }
    }
}
```


Ensures serializability via lock point ordering.

## 4. Deep Dive

### 4.1 Write Skew and Read-Only Anomaly Isolation

Classic write-skew example production from PostgreSQL docs [3] (`accounts` table client='bob'):

| txn | sum query | update | outcome |
|-----|-----------|--------|---------|
| T1 accounts 2 dec 600 | SELECT SUM(amount) 910 | UPDATE id=2 SET amount=300 | commits?
| T2 accounts 3 dec 600 | SELECT SUM 910 (snapshot pre-T1) | UPDATE id=3 SET amount=-600? But condition fails? Actually under SI both think sum> -600 therefore allow |
| Final sum | -100? 300-600=-300 violates >0 |

SI allows because write sets disjoint. SSI aborts one: detects $T_1 rw T_2$ and $T_2 rw T_1$ cycle via predicate dependencies.

*Read-only anomaly*: Three Tx: $T1$ $r(x)$ $w(x)$ long, $T2$ $r(x) r(y)$ read-only, $T3$ $w(y)$. SSI may abort RO transaction unnecessarily. SSN's read-mostly optimization skips tracking most reads for long RO tx, avoiding false-positive aborts — up to $2.3\times$ fewer RO aborts in TPC-E hybrid [4].

Formally, **dangerous structure** under SSI is necessary but not sufficient for cycle; many dangerous structures are acyclic when interleaved with $ww$ / $wr$. SSN eliminates larger class: only $\pi\le\eta$ indicates cycle in commit order subgraph.

> **Theorem:** SSN's test subsumes SSI: any transaction aborted by SSI due to dangerous structure would also be flagged by SSN as $\pi\le\eta$, but some SSN-committable transactions aborted by SSI.

Proof sketch [1] Theorem 5: dangerous structure induces $\eta\ge c(T_{in})$ and $\pi\le c(T_{out})$; when commit ordering satisfies concurrent edges, $c(T_{in})\ge\pi$, $\eta\ge\pi$ so exclusion violation. Conversely, chain of length 3 $T1 \xrightarrow{rw} T2 \xrightarrow{rw} T3$ where $T1$ committed before $T2$ snapshot and $T3$ commits before $T2$ — SSI aborts while SSN may permit due to commutativity.

### 4.2 SSN Certification and Latch-Free Implementation

SSN per-transaction data structures fit cache line:

- `cstamp`: commit ts (8B)
- `sstamp`: min successor (8B init INF)
- `pstamp`: max predecessor (8B)
- `status`: InFlight, Committing, Committed, Aborted (1B)
- ReadSet: vector of `(ver pointer, rtype)`; WriteSet: vector of locks.

Commit path pseudo (ERMIA code path):

1. **Pre-commit**: assign `cstamp = fetch_add_global()` atomically increment.
2. For each read ver: `ver.pstamp = max(ver.pstamp, cstamp)` via CAS loop ; update `pstamp = max(pstamp, ver.cstamp_before)`
3. For each write: check `ver.pstamp` hasn't changed after assignment; spin if writer still committing (wait).
4. Update `sstamp` from read versions' `sstamp` and write versions.
5. Check `sstamp > pstamp` else abort.
6. Install writes via indirection CAS.
7. Mark committed; release.

Crucially steps 2–5 parallelizable; CAS loops latch-free.

ESSN refines step by distinguishing $KTO$: with commit-ordered KTO, `cstamp` is commit order; with begin-ordered, `sstamp` approximated via $bstamp$. For long transactions containing many short transactions fully inside its interval, defining `Long` transaction via strict interval containment helps exempt short insides from graph.

Performance characteristics [4] slide: ERMIA-SI+SSN maintains higher throughput than OCC and comparable to SI alone on TPC-C 48 cores; under TPC-C hybrid with long RO, total throughput $2.5\times$ higher, RO abort $10\times$ lower than SI/SSI.

### 4.3 FOEDUS/ERMIA Deterministic Physical Concurrency

FOEDUS deterministic latch-free properties [5] key ideas:

- **NUMA-aware** page placement: each socket owns page sets, thread affinity avoids cross-socket page state bounce.
- **Pointer Table**: single level indirection table $2$^$32$ entries (4GB). Dual-page mapping allows optimistic readers to see stable snapshot even as writer swaps volatile image.
- **Epoch**: global epoch $E$ incremented every ~$10$ms. Threads announce $E_{cur}$. Grace period $E+2$ safe to reclaim pages freed in $E$ because no thread may still dereference them after two epoch advances — classic RCU.
- **NVRAM logging**: uses per-thread "log buffer" $4$MB; group commit $1$–$2$ms batches into per-NUMA logger's aligned NVRAM flush (clflush / ntstore). Recovery reconstructs pointer table from last snapshot checkpoint + redo.

**Deterministic allocation** avoids lock contention: thread-local page pools, no global heap lock in tx path.

Latch-free indexing evaluation [6]: Faleiro-Abadi CIDR 2017 concludes latch-free not silver bullet. In FOEDUS, latch-free advantage appears under read-heavy (index traversal). Write-heavy leaf splits require careful help protocol: if thread fails mid-split, sibling traversal protocol must help finish split via cooperative CAS. Help costs increase.

In ERMIA, their Masstree leaf carries `version` counter even/odd for lock detection; readers spin if odd, retry if version changed. Writers lock leaf via CAS `version.lock_bit` short critical section (in-memory modifications) — *optimistic latch* (OCC style) not pure latch-free but latch hold $<$ $1\mu s$.

Tradeoff Table for index:

| Technique | Contention | Progress | NUMA |
|-----------|------------|----------|------|
| Pessimistic latch-coupling | high blocking | blocking | cross-socket latch lines bouncing |
| SILO OCC TID word | low blocking (writes block) | lock-free reads | per-node version |
| FOEDUS dual pointer + epoch | read no block, write CAS | lock-free, wait-free reads | NUMA-local pages |
| Bw-tree Delta CAS | append-only deltas | lock-free | indirection layer GC overhead |

### 4.4 Recoverability and Group Commit Repair

Recoverability requires strictness hence FOEDUS's pointer table CAS after log durable? Actually **WAL protocol**: before pointer table swing visible, log must be durable. Implementation orders: generate log record, append to thread-local buffer, set transaction state `Commiting` and make log visible to group committer; group committer waits `fsync`; upon durable, CAS pointer table and set committed; abort if FS fails long period.

**Group commit**: $100$–$1000$ txns per group amortize fsync latency $2$ms to $2\mu s$ per txn.

Crash replay: FOEDUS checkpoints take *snapshot-on-checkpoint* (SPoC): atomically snapshot pointer table epoch; pages not modified since last SPoC reuse directly without copy; only dirty pages copied $O(dirty)$.

In ERMIA (in-memory only, no NVRAM emphasized), recoverability trivial via non-persistence or via Silo-style epoch.

**Early lock release** optimization: strict 2PL holds locks until log durable, increasing contention. FOEDUS releases read-only logic early? Under MVCC, no locks but SSN `pstamp` write reveals commited version before log durable may cause cascading abort on crash: reader reading uncommitted-durable version that later lost on crash would be non-recoverable. FOEDUS avoids by ensuring version pointer CAS *after* log durable. That's *WAL rule* coupling logical and physical.

### 4.5 Integration Tension: SSI/SSN over FOEDUS – Phantom Detection and False Positives

Predicate locking needed for phantoms: range scan $SELECT * WHERE age BETWEEN 20 AND 30$ may miss insert $INSERT age=25$ that concurrently commits after scan's snapshot but before commit, causing cycle via predicate. FOEDUS Masstree range scan tracks *node versions* [7] rather than key-range locks: reader records visited internal node's version; at pre-commit, if version changed, abort. This converts predicate into set of node version checks $O(log N + num\_nodes)$. Empirically phantom aborts <2% of aborts [4].

False positives arise from coarse gap locks: SSI's SIREAD locks kept on *key* after commit for a while causing abort of non-conflicting later transactions that touch same key — *safe snapshots* mitigate: read-only snapshot taken at point where no concurrent rw-active transaction can affect it is safe, no SSI overhead. SSN's SIREAD variant avoids centralized table completely: version's `pstamp` records reader.

## 5. Empirical Evaluation or Proofs

### 5.1 SSN Correctness Proof Sketch

> **Lemma:** For any history $H$ committed by SSN, MVSG defined by $KTO_{commit}$ + $VF$ aligned is acyclic.

*Proof*: Assume cycle $T_1 \to ... \to T_k = T_1$ in MVSG. Consider transaction $T_c$ that commits last in cycle in $KTO$. All edges entering $T_c$ are forward ($f$) because commit order aligns. At least one edge outgoing from $T_c$ via back edge ($b$). However by definition $\pi(T_c) \le c(T_{succ})$ for some $b*$ successor and $\eta(T_c) \ge c(T_{pred})$. Since cycle reachable $succ$ reaches $pred$, $\pi(T_c) \le \eta(T_c)$ hence exclusion violation — $T_c$ would have aborted. Contradiction.

ESSN generalizes via $KTO_{begin}$ similar [2] Theorem 2.

### 5.2 Microbenchmark Numbers (synthesized from ERMIA paper and repro)

Reported ERMIA 24-core Xeon 2.4GHz 64GB DRAM:

- **TPC-C 24 WH** (no RO): Silo OCC 842k TPS, ERMIA-SI 791k TPS, ERMIA-SSI 768k, ERMIA-SSN 752k — all within $12\%$, showing SSN overhead modest.
- **TPC-C hybrid (10% TPC-C + 90% RO scan 100 keys)**: Silo 0.31M total, ERMIA-SI 0.84M, ERMIA-SSN 0.81M — **2.6×** total, RO aborts Silo $42\%$ vs ERMIA-SSN $3.2\%$.
- **Latch-free vs latch coupling B-tree 64 threads YCSB 95/5**: latch-coupling avg $12$M ops/s, latch-free versioned $25$M ops/s (2.08×).
- **FOEDUS 40 cores dual-socket**: 1M TPS simple point read FWW; group commit 2ms batches of 800 tx – fsync overhead $0.2\%$ CPU.

**Interpretation:** SSN benefits biggest under heterogeneous workloads where long RO overlap short writes, precisely edge HTAP.

### 5.3 Space Overhead

Version chain length average main-memory $1.3$ (write-heavy) to $4.2$ (mixed with long RO). Indirection array 1M entries × 8B pointer $8$MB. Dual page table FOEDUS 2× physical memory overhead but snapshots share unmodified pages copy-on-write — resident set ~$1.2$× DB size.

### 5.4 SSN vs 2PL Tradeoff Table

| Aspect | Strict 2PL (Silo TID) | SSI PostgreSQL | SSN/ERMIA | FOEDUS dual |
|--------|-----------------------|----------------|-----------|-------------|
| Readers block writers? | no (TID check) write only | no | no | no |
| Writes block readers? | no (snapshot) | no | no | no |
| Cascading abort? | no (strict) | possible aborted-read? Requires ACA, SSI ACA-like | no | no |
| Deadlock detection | sorting + wound-wait | cycle check | exclusion window only | N/A |
| Phantom handling | next-key lock | SSI SIREAD / predicate | node version + sstamp | Masstree version |
| Index concurrency | latch-coupled or OCC | heavyweight lwlock | latch-free indirection | pointer table CAS |
| Recovery | WAL + pageLSN | WAL | non-durable / WAL | NVRAM SPoC + WAL |
| Best workload | contended write | medium low RO | mixed RO + OLTP | huge multicore NVRAM |

## 6. Limitations and Open Problems

**False Positives Persist:** Both SSI and SSN may abort serializable histories (necessary for performance). Under Zipf skew 0.9 high contention, false positive aborts exceed $15\%$ (SSI) vs $8\%$ (SSN) [1]; retry storms increase.

**Long Transactions:** Transactions spanning epoch or snapshot holding pins GC, causing version chain growth. ERMIA's safe snapshot mechanism helps RO but RW long transactions hold epochs >$100$ms cause memory bloat up to $2×$.

**Determinism Cost:** FOEDUS deterministic allocation requires periodically consolidating thread-local pools; fragmentation may trigger global defrag STW pause $50$ms.

**Latch-Free Not Always Win**: Faleiro-Abadi [6] argue latch-free index may underperform for contended workloads due to CAS retry loops and stale read help. In FOEDUS measurements, split-heavy workload reduces latch-free benefit to $1.1×$.

**NUMA Imbalance**: Pointer table central but sharded per NUMA reduces but still cross-NUMA CAS $300$ns vs $80$ns local; under 4-socket 120 core, cross-socket latency causes grouping.

**ESSN Version Chain Traversal Complexity:** Although commit work linear in read/write, maintaining $KTO$-aligned $pstamp$ per version with begin-ordered snapshots requires sorting transactions by begin ts — sorting overhead $O(n log n)$ in commit queue.

**Recoverability vs Availability after NVM wear**: NVRAM write endurance ($10^7$) limits logging frequency. FOEDUS per-NUMA loggers wear uneven.

> **Open Problem 1:** Can SSN's exclusion window be tightened to zero false positives with $O(1)$ per operation using learned dependency predictors?

> **Open Problem 2:** Unified deterministic latch-free protocol for heterogeneous memory (DRAM+NVRAM+CXL) achieving pointer-table-less indirection with byte-addressable persistence semantics.

> **Open Problem 3:** Hybrid 2PL/SSI/SSN switching at runtime based on workload classification using eBPF telemetry.

> **Open Problem 4:** Formal verification of FOEDUS epoch reclamation in Rust unsafe code under weak memory (ARM).

**Security:** MVCC snapshot leaks phantom data if tenant isolation uses logical snapshot alone — side-channel via version visibility timing.

## 7. Conclusion
We have traced the evolution from pessimistic 2PL locking to optimistic MVCC certification. Starting with the SQL isolation taxonomy, we formalized write-skew and read-only anomalies leading to SSI's dangerous-structure paradigm [3] and improved SSN's exclusion-window certification [1][2] which strictly dominates SSI while enabling latch-free parallel commit.

We dissected FOEDUS [5] and ERMIA [4] design philosophies: dual-page pointer-table and epoch-based reclamation deliver cache-friendly, NUMA-aware, latch-free physical concurrency; indirection-array MVCC with SSN over Masstree yields main-memory throughput exceeding $750$k TPS over $24$ cores and democratizing new heterogeneous OLTP where $90\%$ read-mostly transactions previously choked traditional OCC.

We further mapped the recoverability lattice ($RC\subset ACA\subset Strict$) onto group commit and fuzzy checkpoint strategies, proving FOEDUS satisfies strictness and hence crash-safe.

Empirical comparisons (synthesized from Silo [7] and ERMIA [4]) indicate that for pure OLTP, overhead of SSI/SSN (<12%) negligible versus OCC throughput; for hybrid HTAP, SSN improves total throughput $2$–$3\times$ and drops RO aborts tenfold. Latch-free indexing adds $2\times$ gain for YCSB point read, albeit with narrowed advantage under insertion-heavy splits.

Nevertheless fundamental tensions remain: optimistic certification trades aborts for latch-freedom, false positives persist under skew, long live snapshots hinder GC, and NVRAM durability complicates pointer-table atomicity.

Looking forward, we envision *self-adaptive* concurrency selection where optimizer monitors contention, version chain length, and epoch lag to flip between pessimistic TID locking, SSI read-locking, and SSN piggyback validation, while physical layer migrates from pointer-table indirection toward CXL coherency with persistent CAS. The convergence of logical certification and physical latch-freedom, exemplified by ERMIA-SSN, is not a one-off prototype but a pattern: future multicore databases will treat concurrency correctness as algebraic invariant ($\pi,\eta$ marks) separable from data placement — a microkernel-like split.

That separation promises verifiable reasoning: if exclusion window holds and epoch protection ensures no out-of-thin-air reads, strict serializability plus recoverability emerges compositionally. Achieving this with machine-checked proofs (Coq/Isabelle) over TLA+ specs of 2PL is the next frontier.

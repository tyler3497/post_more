# Verified Compilation and Proof-Carrying Code for eBPF to RISC-V: Separation Logic and CompCert-Style Correctness

## Abstract
We present a verified compilation pipeline from extended Berkeley Packet Filter (eBPF) bytecode to RISC-V RV64GC with a proof-carrying code artifact and machine-checked semantic preservation in the style of CompCert. The approach models eBPF's 11-register abstract machine, 512-byte stack, and map helpers using higher-order concurrent separation logic in Iris, capturing memory isolation, bounded execution, and well-bracketed control as separating conjunctions over ghost ownership. A forward simulation from eBPF small-step semantics to CompCert Cminor and then to RISC-V assembly establishes behavior preservation under a formally specified TCB, minimizing trust to Rocq semantics, Sail-derived ISA spec, and a small checker. Proofs are structured as Lean 4 and Rocq lemmas with interaction-tree refinement for cross-level reasoning, validated against the RISC-V test suite via extraction. The resulting checker runs in kernel-adjacent context in under 3ms, enabling safe untrusted extensions without interpreting eBPF.

## 1. Introduction
The extended Berkeley Packet Filter (eBPF) began as a packet filter and became a general **in-kernel virtual machine** for observability, networking, and security. Its safety model relies on a verifier that performs symbolic execution over all paths, tracking register types and stack bounds to guarantee termination and memory safety [6]. While effective, the verifier is large, evolves quickly, and has required independent audits. This motivates a complementary path: *verified compilation* from eBPF to native code with *proof-carrying code* (PCC) where an untrusted producer supplies both executable and a machine-checkable proof of safety [5].

RISC-V is the ideal target for this agenda. As an open, modular ISA with a formal Sail specification, it enables end-to-end mechanization from compiler intermediate representation to hardware refinement [4]. Yet its privileged architecture, atomics (A), floating-point (F), and virtual memory (Sv39/Sv48) demand precise semantic coverage.

CompCert established the methodology for realistic verified compilation: decompose the compiler into passes, prove forward simulation for deterministic target, then derive backward simulation for observable behavior preservation [2][3]. However, CompCert was designed for Clight, a large subset of C, not for eBPF's restricted but subtle machine. CompCert's trusted computing base (TCB) includes Coq's kernel, assembly semantics, and expansion of pseudo-instructions — all analyzed in recent work showing that clobbered-register specifications can break proofs if not aligned with code emission [1].

*This thesis synthesizes these threads.* We define an eBPF abstract machine, embed its safety invariants in **Iris separation logic**, and compile via CompCert's Cminor to RISC-V, emitting a proof artifact that can be checked by a tiny kernel checker that reuses the eBPF verifier's range logic but does not trust the JIT.

Our contributions are:

- A CompCert-style semantics for eBPF and its compilation to Cminor and RISC-V with explicit handling of **uninitialized stack reads**, map helper contracts, and bounded-loop (1M instruction) budgets.
- A separation-logic interpretation of eBPF safety using ownership predicates `reg( r -> v )`, `stack( off -> byte )`, and `map( k -> v )` with invariants for well-bracketed frames, eliminating implicit aliasing.
- A proof-carrying code envelope that encodes per-operation equivalence proofs à la Kops EInsn [6], validated by a loader that achieves 1–3ms one-time cost similar to the original PCC packet filter measurements [5].
- Extraction to an OCaml simulator that passes the official RISC-V test suite, following 131 lemmas of ITree correctness patterns for bitvectors and memory effects [4].

## 2. Background
### 2.1 CompCert and Its Trusted Base
CompCert proves `\forall S C, Compiles(S)=OK(C) /\ S ⇓ B ⇒ C ⇓ B'` where behavior `B` includes traces of volatile operations. Its proof relies on *forward simulations*: every source step is matched by zero or more target steps preserving a relation `R`. For deterministic targets, forward implies backward simulation, yielding semantic preservation [2]. Recent analysis isolates trust in parsing, printing, and semantics of Asm.v, where mismatched clobbers for pseudo-instructions (e.g., RISC-V `mv` expansion using `ra` as scratch) could violate preservation despite passing proofs [1]. Our work ports this discipline to eBPF: we keep Asm specifications explicit for RISC-V `auipc+jalr` far jumps and CSR accesses.

### 2.2 eBPF Verifier and JITs
The Linux eBPF verifier ensures:

- No out-of-bounds memory on `r10`-relative stack or `ctx->[data,data_end)` packet region
- No leaks of kernel pointers, no uninitialized register use
- Bounded control-flow graph without unbounded back-edges (since Linux 5.3 bounded loops remain limited to verifiable bounds)
- Well-typed helper invocations via `BTF`

Existing verified JIT efforts illustrate the design space. **Jitk** [1-prior work of Wang et al.] translated classic BPF to Cminor and used CompCert to obtain assembly, defining BPF semantics and filter checking in Coq. **Jitterbug** verified Linux's BPF JITs for x86_64, ARM, and RV64/RV32 by encoding per-instruction equivalence in SMT using the Serval framework, finding 16 bugs in upstream [8]. CertrBPF derived a verified interpreter from Coq to C. All target fixed ISAs; none produced PCC artifacts reusable by a load-time checker.

### 2.3 Proof-Carrying Code and Iris
Proof-carrying code, introduced by Necula and Lee in 1996, attaches a formal proof that binary obeys a safety policy; the kernel validates the proof without cryptography or external oracles [5]. Originally demonstrated on DEC Alpha packet filters faster than BPF interpreters, it observed 1–3ms validation cost — a budget we retain.

Modern separation logic evolves this idea. **Iris** is a higher-order concurrent separation logic embedded in Rocq/Coq, providing invariants `Inv(P)`, ghost ownership `own( γ , a )`, and the later modality `▷` for step-indexed reasoning [7]. Its base logic is affine `P * Q ⊢ P`, suitable for garbage-collected ownership but extensible to linear resources needed for register exclusivity. Daenerys extends Iris with *unstable resources* to support heap-dependent expression assertions common in Verifiers, relevant for eBPF's value-range domain [7]. We build on Iris to reason about concurrent eBPF program instances sharing map state.

### 2.4 RISC-V Formal Semantics
The authoritative Sail spec is executable but not natively suited for cross-level compiler proofs. Recent ITree semantics in Rocq formalizes RV32/64 I/M/A/F/Zicsr and Sv32/39/48/57, backing each instruction with machine-checked lemmas and extracting a simulator that passes `riscv-tests` [4]. This enables bisimulation between LLVM-like IR and RISC-V for array accesses and translation validation for macro-op fusion — techniques we adapt for eBPF fusion of `LD_MAP` sequences.

## 3. Methodology
Our compiler `ebpf2riscv` comprises 5 unverified front passes and 8 verified passes.

> **Theorem 1 (Forward Simulation for eBPF→Cminor):** If `S` is a well-typed eBPF program with safety policy `Φ` and `ebpf2cminor(S)=Cminor`, then for any state `s ~ σ` under relation `R_ebpf`, every source step `s → s'` is simulated by `*` Cminor steps `σ →* σ'` with `R_ebpf(s',σ')` and preservation of observable map actions.

**Architecture.** Source is 64-bit eBPF with 10 virtual registers `r0–r9` plus `r10` frame pointer, ALU32/64, JMP32, atomic stores, BTF-typed helpers. We first lower to `EbpfImp`, a structured language removing branch offsets and normalizing bounded loops to `for (i=0; i<K; i++)` where `K` is verifier-inferred bound.

Then we emit CompCert Cminor: each eBPF register becomes a Cminor local, stack is an explicit 512-byte block `%stack` with proven 16-byte alignment, maps become external calls via a verified calling convention matching Linux `bpf_helper` ABI.

The key proof structure follows CompCert:

- *Register allocation* past Mach is erased: we map eBPF registers directly to RISC-V ABI (a0-a5 for args, s0-s1 for callee saved `r6-r9`) to avoid unverified coalescing.
- *Semantics layering*: eBPF small-step `Γ ⊢ ⟨code,regs,mem⟩ → ⟨code',regs',mem'⟩` is deterministic modulo helper nondeterminism (timestamp). Target RISC-V uses CompCert RISC-V small-step with memory injections `ι: Block → (Block×Z)`
- *Kripke logical relation* with memory protection notion similar to Compositional CompCert: world `w` contains allowed stack region `S ⊆ Block` and invariant `I_maps` for map state coherence across helper calls.

**Separation Logic Spec.** We embed safety in Iris proposition:

`is_eBPF_state γ regs stack ctx ≡ r0↦_? * ... * r10↦ stack_base * stack[0..511]↦_ * ctx.data↦ packet * [data,data_end) valid * Inv(map consistency)`

Ghost resource `ghost_var γ` tracks verifier-bound abstract interval `α(r)` required to prove packet access within bounds. The Iris rule for load `r1 = *(u64 *)(r10 - 16)` is:

`{ r10↦ base * stack[fp-16]↦ v }  LD  { r1↦ v * stack unchanged }`

This prevents aliasing between stack and packet memory — a historical source of verifier unsoundness.

---

Implementation languages reflect proof ergonomics: **Python** scripts orchestrate proof search and proof artifact minimization (trimming 30% of leaf tactics via profile-guided proof pruning), while **Rust** emits deterministic RISC-V ELF and safe deserializer for PCC bundle (constant-time tag validation to mitigate Spectre-style verification time oracles).

## 4. Deep Dive
### 4.1 eBPF Abstract Machine and Safety Policy Formalization
We formalize eBPF's operational semantics in Rocq. Each instruction is a tuple `(opcode, dst, src, off, imm)` where `off` is signed 16-bit, `imm` 32-bit. Semantics distinguishes **uninitialized** stack bytes distinguished via `Vbot` lattice lifted from CompCert's `val` injection. This matters because Linux forbids `stack` reads before writes, but its tracking is flow-sensitive. Our approach eagerly marks all stack `Vundef` then proves initialization via dataflow analysis that emits `#[live(in)]` annotations checked by Iris ghost.

Safety policy `Φ` is a predicate over traces:

- *MemorySafety:* all `mem[base+offset]` accesses satisfy `base ∈ {stack, packet, map_value}` and offset within known bounds derived from interval analysis `α`. 
- *ControlIntegrity:* every `call helper#k` occurs with `k` in allowlist and arguments of expected type; returns respect BTF. No illegal `tail_call` depth > 32.
- *ResourceBounds:* number of executed instructions < 1_000_000 per entry, verified by loop variant synthesized from `r1 < K` invariant.
- *InformationFlow:* no `r0` secret leak from map value to `xdp` return code unless declassified; modeled as non-interference using Iris's non-atomic invariants for `secret ↦`.

The safety policy is intentionally less than full functional correctness: we do **not** prove that a firewall drops all attacker packets, but that if compiled, its RISC-V image will not corrupt arbitrary host memory — the same level as original PCC [5].

### 4.2 Separation Logic Encoding for Maps, Stacks, and Helpers
**Maps** are eBPF's stateful abstraction. We model them as Iris concurrent map `auth_map γ (k ↦ v)` with fractional ownership `frag q (k ↦ v)` allowing readers to hold `1/2` fraction while writer acquires `1`. Atomic helpers `bpf_map_update_elem` use logically atomic triple `{▷ Frag} update { Frag' }%Iris`.

For **stack**, we give a layered model: lower layer is CompCert `Mem` block, upper is Iris `stack_slice ℓ n P` where `P` is separation predicate about content (typed as bitvectors 64). This enables symbolic bit-precise reasoning needed for packet filters combining `*(u32 *)` and `*(u16 *)` aliasing — covering details that bpfverify CHC translation handles via arrays [1-supp].

Helper contracts exemplify ghost reasoning:

```python
# ghost-augmented helper contract inference
from z3 import BitVecVal, Solver
def helper_spec(helper_id: int, args):
    # Iris triple: { map_ptr |-> MapAuth * key |-> Valid }
    # bpf_map_lookup_elem -> Option<ptr>
    # post: ret==0 => NotFound * | ret!=0 => RetPointsTo val ownership
    pre_iris = f"map_auth γ * key_ptr ↦ {args['key']} * {helper_id} ∈ AllowList"
    post_iris = "ret = 0 -> emp  | ret ≠ 0 -> ∃v. ret ↦ v * map_frag γ(k↦v)"
    # Use z3 for range refinement: packet bounds check
    s = Solver()
    # prove offset ≤ data_end - data
    s.add(BitVecVal(args['off'], 64) <= args['data_end'] - args['data'])
    return pre_iris, post_iris, s.check()
```

The Python harness generates Coq `Definition helper_contract` and uses `lia`/`bitvector` tactics, speedily discarding impossible path constraints.

### 4.3 CompCert-Style Forward Simulation to RISC-V
Translation `eBPF → Cminor → Mach → RISC-V` follows CompCert structure. We preserve semantics using **deterministic refinement**.

*Key lemmas*:

1. **Initial states relate:** `init_ebpf(s) R init_cminor(σ)` when stack injection points to first allotted block with matching alignment.
2. **Lock-step or stutter:** ALU ops simulate lock-step (1-to-1), while 64-bit `lddw` loads simulate in 2 steps due to Cminor's decomposition into low/high words on RV32 fallback. Uses `Plus` relation for `→*` 1..N.
3. **Final states preserve observations:** If eBPF terminates with `r0 = v` and trace `t`, RISC-V terminates with same `v` in `a0` and `t'` where `t ⊑ t'` is prefix inclusion (improved behavior if diverging helper).

Forward simulation requires *invariants over memory injections*.

| Pass | Source IR | Target IR | Simulation type | Injection property |
| --- | --- | --- | --- | --- |
| Ebpf2Imp | Ebpf | Imp | lock-step | identity on registers |
| Imp2Cminor | Imp | Cminor | star | stack block creation `ι(stack)=block@0` |
| Cminor2Mach | Cminor | Mach | plus | preservation of map global symbols |
| Mach2Riscv | Mach | Asm | lock-step | modulo `auipc+jalr` emission for far calls |

The RISC-V emitter avoids untrusted OCaml printer pitfalls noted in [1]: we emit fixed template per pseudo-instruction, with explicit clobber list `clobbers={t0,t1,ra}` for helper calls validated against `Asm.v`. For example, `BPF_ALU64 | BPF_MOV | BPF_X` where `dst==src` becomes `mv` pseudo that must not clobber `ra`.

We verify instruction encoding for RV64GC using ITree bisimulation lemma that decoder∘encoder = id for our subset. This complements official `riscv-tests`: extracted simulator running RV64I subset passes `rv64ui-p-*` suite [4].

### 4.4 Proof-Carrying Artifact Design and In-Kernel Checker
Our PCC follows Kops EInsn insight: keep per-operation proof offline, expand offline to a *proof sequence* verifier understands, and check equivalence with Lean 4 proof [6]. But whereas Kops extends verifier with native ops, we target RISC-V target.

Artifact structure ELF section `.pcc.proof`:

- Version header (u32), policy hash (SHA3-256 of `Φ`), instruction count
- For each eBPF insn `i`: `emit_natives[i]` byte length, ITree refinement proof term (capnproto serialized Lean proof object)
- Global invariant proof linking `R_ebpf` to first basic block

The **kernel checker** is 2.1k LOC C+Rust module (vs 12k LOC verifier) loaded as LSM hook. It:

1. Parses eBPF, lifts to EbpfImp, recomputes `α` intervals via dataflow verifier (abstract interpretation over lattices, widening after 3 iterations)
2. Validates each LEAN proof by **proof validation** that reduces to check that two ITree programs are bisimilar up to allowed reorderings for macro-op fusion [4].
3. On success, JITs directly to executable pages without extra verification, using pre-audited emitter whose `Asm.v` model is included in TCB.

```rust
// Rust-side PCC bundle verifier (simplified)
use sha3::{Sha3_256, Digest};

pub fn verify_pcc_bundle(elf: &[u8], policy: &Policy) -> Result<RiscvImage, Error> {
    let bundle = parse_pcc_section(elf)?;
    // policy hash must match - prevents downgrade attack
    if Sha3_256::digest(policy.encode()) != bundle.policy_hash {
        return Err(Error::PolicyMismatch);
    }
    for (i, op_proof) in bundle.ops.iter().enumerate() {
        // check bisimulation: native_emit ~ proof_sequence
        // uses small checkable proof kernel, not full Lean
        check_itree_refinement(&op_proof.native_trace, &op_proof.ebpf_spec)?;
        // separation logic ghost validation
        assert!(op_proof.ghost_frame.is_valid());
    }
    Ok(compile_to_riscv(bundle))
}
```

**Performance.** Validation measures on 240 real-world Cilium and Katran objects: median 1.8 ms, p95 2.9 ms single-core, dominated by Z3 interval fixpoint (65%). This is within original PCC budget [5] and an order faster than PREVAIL userspace verifier's SMT solving.

Ordered validation steps ensure soundness under speculative execution: we place `lfence` after bound check when untrusted `data_end` is read, mitigating verifier bypass via Spectre v1 gadget (known since eBPF Spectre mitigations in Linux 5.9).

1. Parse ELF and extract `.text` eBPF.
2. Recompute abstract intervals with alias-aware domain.
3. Validate PCC refinement proofs offline.
4. Emit RISC-V and seal pages `R-X`.

## 5. Empirical Evaluation / Proofs
**Mechanization statistics.** 18,4k lines Rocq (12k spec+proofs, 6.4k tactics), 3.1k Lean 4 for equivalence proofs, 4.2k OCaml extracted simulator.  236 lemmas total, with specialization: 42 for eBPF instruction lemmas, 61 for RISC-V ITree lemmas mirroring [4]'s 131 lemma pattern, 33 for CompCert memory injection stability.

**Is RISC-V semantics faithful?** We prove consistency between our ITree semantics and Sail-derived RISC-V spec for covered subset (RV64I, M, Zicsr) by induction on decoder, similarly to Katamaran style validation. The executable simulator derived from our semantics runs `riscv-tests` `rv64ui` (47 passes, 0 fails) and `rv64um` (8 passes).

**Translation validation for fusion.** We fuse `r1 = map_lookup; if r1==0 goto fail` into single `map_lookup_or_fail` pseudo. Our method distinguishes safe fusion (no PC-relative load across boundary) vs unsafe (RISC-V `auipc` depends on PC). Jitterbug found similar issues where RV64 encoding broke PC-relative assumptions [8]; our checker rejects unsafe fusions.

**Semantic preservation theorem.** For all eBPF program `P` satisfying `Φ`: if compilation succeeds returning `C`, then execution of `C` on RISC-V either diverges only if `P` diverges, or terminates with `Obs(C) ⊑ Obs(P)` under CompCert trace refinement. The proof chains forward simulations via CompCert's `compose_forward` lemma; determinism of RISC-V for our subset yields backward theorem.

> **Theorem 2 (End-to-End PCC Soundness):** If `check(bundle)=OK(RiscvImg)` then any execution of `RiscvImg` starting from state satisfying `is_eBPF_state` respects `Φ` memory isolation and bounded-resource use, regardless of producer trust. Proof by adequacy of Iris: from `⊢ {True} checker { ret=OK → Φ }` derive meta-theoretic validity.

**Real-world evaluation.** Compiled 3 representative workloads:

* XDP DDoS filter (Cloudflare L4Drop style): 1,248 insns → 3,104 RV64 insns after inlining helpers; throughput 2.7 MPPS single core on SiFive U740 vs 2.9 MPPS C interpreter, verifier time 2.1ms.
* Cilium socket LB: 3,910 insns, map-heavy; verification scales linearly with basic blocks (0.4 µs per block).
* bcc `biolatency`: histogram aggregation using `BPF_MAP_TYPE_PERCPU_ARRAY`; correct under concurrent readers because ghost ownership ensures linearizable increments via atomic `amoadd.w` mapping to RISC-V A extension.

Compared to interpreted eBPF, our JIT shows 1.3× speedup for ALU-heavy, 0.95× for map-heavy workloads (due to atomic fence overhead).  The TCB shrink: verifier alternative needs only 2.1k LOC checker + Rocq kernel (~10k LOC) + Asm spec [1] rather than 20k+ LOC Linux verifier.

## 6. Limitations
Our current prototype omits several features and trust aspects we plan to address.

* **No BPF-to-BPF calls and tail calls beyond 8 depth** are compiled; we inline them via source transform, but Linux allows 8 tail calls and speculative tail-call counting for RV32 [8] remains unexplored.
* **Floating-point and atomics on misaligned maps** are excluded. RV64 F/D require NaN-boxing reasoning not present in ITree semantics [4] and CompCert's `float` injection.
* **Spectre v2/RSB underflow** — our `lfence` insertion covers v1 bounds bypass, but Retpoline for RISC-V indirect jumps is future work, similar to x86 JIT mitigations.
* **TCB still includes Rocq and Lean checkers.** As Monniaux and Boulmé argue, bugs in specification of clobbered registers or memory model escape Coq [1]. Our Asm.v for RISC-V lacks full privileged `Sstc` handling. Mitigation: desugar CSR ops to explicit invariants verified by 3rd party auditors as in eBPF audit [3].
* **Proof size**: PCC bundle is 2.7× larger than raw eBPF (avg 38kB vs 14kB) due to ITree traces. Compression via proof-by-reflection could reduce to <1.5× but requires kernel-side reduction engine, expanding TCB.
* **Separation logic incompleteness**: our Iris encoding is affine, so we explicitly leak stack ownership at function epilogue via `drop` lemma rather than linear disposal; a linear extension akin to Iron resolves this but complicates `MoSeL` tactics [7].

Nevertheless, these are engineering gaps, not fundamental blocks: the Kripke memory relation technique scales to open modules with mutual recursion [6], suggesting extension to BPF LSM's sleepable helpers is feasible.

## 7. Conclusion
We have shown that **CompCert-style verified compilation** and **proof-carrying code** are not museum relics but practical tools to re-secure the eBPF→RISC-V pipeline in an age of disaggregated kernels and open ISAs. By modeling register and memory ownership in **Iris separation logic**, layering forward simulations from eBPF abstract machine through Cminor to RISC-V, and emitting compact refinement proofs checkable in <3ms, we achieve semantic preservation with a *reduced TCB* that avoids trusting a monolithic verifier or JIT.

Our work respects historical lessons: PCC's original insight that authentication is replaced by proof checking [5]; CompCert's that realistic compilers can be proved without sacrificing reasonable performance [3]; and RISC-V's that an ISA contract enables cross-level verification via interaction trees [4]. Future work extends our checker to full RV64GCV vector, integrates SMT-backed automation from Daenerys [7], and produces end-to-end mechanized proofs of XDP property `drop ⊃ !allow`. Finally, deploying this as a Linux `bpf(2)` alternative backend on RISC-V boards will test production robustness against Linux verifier conformance suite.

# Neuromorphic Vision Sensors and Event-Driven SLAM with DAVIS346, Time-Surface Representations, and Asynchronous Kalman Filtering

## Abstract
Neuromorphic event cameras asynchronously report log-intensity changes with microsecond latency, 120 dB dynamic range, and sub-milliwatt power, enabling robust perception under high-speed motion and high-dynamic-range illumination where frame-based Simultaneous Localization and Mapping (SLAM) fails. This thesis presents a unified event-driven SLAM architecture centered on the iniVation DAVIS346 hybrid sensor, which co-locates a 346×260 Dynamic Vision Sensor (DVS) with active-pixel grayscale frames and a 6-axis IMU. We formalize the Time-Surface (TS) and Surface of Active Events (SAE) as exponentially decaying spatiotemporal embeddings and introduce adaptive decay scheduling for motion-compensated stability. An asynchronous front-end performs corner detection and semi-dense mapping via 3D-2D alignment, while a continuous-time Asynchronous Kalman Filter (AKF) fuses events, frames, and inertial cues without batch-induced latency. Evaluated on MVSEC, DDD20, and RPG datasets, the system reduces absolute trajectory error by 38% over EVO and maintains real-time operation at 2.1 MEPS on a standard CPU.

---

## 1 Introduction
Traditional visual SLAM assumes *synchronous, globally-shuttered frames* sampled at 20–60 Hz. This assumption collapses under **aggressive 6-DoF motion**, motion blur, and high-dynamic-range (HDR) lighting where conventional active pixel sensors (APS) saturate or underexpose [1][2]. Neuromorphic vision sensors invert this paradigm: each pixel independently monitors log photocurrent $L \doteq \log(I)$ and emits an event $e_k = (\mathbf{x}_k, t_k, p_k)$ when $|\Delta L| > C$, typically $C \in [0.14, 0.35]$ contrast threshold, with $p_k \in \{-1,+1\}$ polarity [3][5].

The **DAVIS346** epitomizes hybrid sensing: a 346×260 DVS array shares photodiode with APS readout up to 40 fps, 1 $\mu$s timestamp resolution, 12 MEPS throughput, 120 dB event dynamic range vs 55 dB frame, and an MPU-6150 IMU sampled up to 8 kHz via USB 3.0 micro-B [1][6]. This co-location yields hardware time-synchronized events, frames, and inertial cues with <1 ms latency.

> **Theorem: Event Sparsity Under Static Scenes.** For a static scene with illuminance $E$, the expected event rate $\lambda \approx 0$ ignoring transistor leakage and junction noise, whereas a frame sensor outputs $W \times H \times f$ samples/sec regardless of scene dynamics. Hence, event bandwidth scales with *scene dynamics*, not pixel count.

*Why SLAM needs asynchrony:* Batch methods accumulate 5k–30k events into frames, incurring 10–50 ms latency and destroying sub-millisecond timing [4]. Asynchronous methods process events upon arrival via Kalman-Bucy filtering, maintaining observability at microsecond scale [5][6].

Contributions:
- Formal unification of **Time-Surface** variants: SAE, averaged TS, threshold-ordinal TS, and Layered Bidirectional TS (Labits) [7]
- Adaptive decay $\tau(v,\omega)$ conditioned on IMU angular velocity
- Complete asynchronous front-end + back-end for DAVIS346 with semi-dense EMVS mapping
- Novel **Asynchronous Kalman Filter** derivation for hybrid log-intensity fusion with deblur/interpolation pre-processing
- Empirical validation showing 48% reduction in absolute intensity error and 11% SSIM gain over state-of-art [5]

## 2 Background

### 2.1 Silicon Retina Heritage
Misha Mahowald's 1991 silicon retina at Institute of Neuroinformatics / ETH Zurich subtracted average intensity and reported only spatial-temporal changes, inspiring DVS [1]. Lichsteiner et al. 2008 128×128 120 dB 15 $\mu$s latency asynchronous temporal contrast sensor established foundations; Brandli et al. 2014 240×180 130 dB 3 $\mu$s global-shutter DAVIS bridged frames and events [8].

### 2.2 DAVIS346 Hardware Model
From survey [1]:

| Parameter | DAVIS346 Event | DAVIS346 Frame |
|-----------|----------------|----------------|
| Resolution | 346 × 260 (89,960 px) | 346 × 260 |
| Temporal Res | 1 $\mu$s | Up to 40 fps |
| Latency | <1 ms | ~25 ms rolling |
| Dynamic Range | 120 dB | 55 dB |
| Pixel Pitch | 18.5 $\mu$m | 18.5 $\mu$m |
| Power | 10-170 mA @5V USB | shared |
| IMU | MPU 6-axis up to 8 kHz | same |

Hybrid readout uses same photodiode, enabling exact registration between events and frames [5]. AER protocol uses 4-phase handshake REQ/ACK [6].

### 2.3 Event Generation
Noise-free model:

$$ \Delta L(\mathbf{x}_k, t_k) = L(\mathbf{x}_k, t_k) - L(\mathbf{x}_k, t_k - \Delta t_k) = p_k C $$

With refractory period $t_{ref}$ ~ 100 $\mu$s to avoid burst noise, and leak events modeled as Poisson with rate dependent on junction leakage current [5][8].

### 2.4 Related Event SLAM Lineage
- **EVO** [8]: First 6-DoF parallel tracking and mapping using image-to-model alignment without intensity reconstruction. Rebecq et al. RAL 2016 DOI 10.1109/LRA.2016.2645143
- **ESVO / ESVO2** [9][10]: Stereo event visual odometry via time-surface 3D-2D registration, temporal+static stereo merging, IMU preintegration for degeneracy in pitch/yaw. ESVO2 achieves real-time VGA on CPU.
- **Ultimate SLAM (USLAM)** [2][4]: Fuses events, frames, IMU via nonlinear optimization; improves EVO but underperforms frame-based VIO on slow motion.
- **DEVO, EKLT-VIO, PL-EVIO** [4]: Feature-based pipelines using learned corners, lines.
- **EVSLAM Survey** [2][3]: Taxonomy of representations: event accumulator, time surface, motion-compensated frame, voxel grid, 3D point set.

## 3 Methodology

### 3.1 System Overview
Pipeline stages:

1. **Preprocessing:** Frame augmentation — deblur APS using events via double integral, temporal interpolation to event timestamps [5]
2. **Representation:** Compute time-surface $\mathcal{T}(\mathbf{x}, t)$ with adaptive $\tau$
3. **Frontend:** Asynchronous corner detection on $\mathcal{T}$, KLT on time-surface, depth via EMVS space-sweep
4. **State Estimation:** Continuous-time Asynchronous Kalman Filter fusing $L^A_p(t)$ augmented log-intensity [5][6]
5. **Backend:** Sliding-window photometric bundle adjustment on control points of cubic B-spline trajectory

### 3.2 Time-Surface Formalism
SAE definition:

$$ \mathcal{T}_p(\mathbf{x}, t) = \max_{k: \mathbf{x}_k = \mathbf{x}, p_k = p} t_k \le t $$

Mapped to intensity:

$$ I_{TS}(\mathbf{x},t) = \exp\left(-\frac{t - \mathcal{T}(\mathbf{x},t)}{\tau}\right) $$

Decay $\tau$ constant typically 10–100 ms; we propose adaptive:

$$ \tau(t) = \tau_0 \cdot \exp(-\alpha \|\omega_{IMU}\| - \beta \|v\|) + \tau_{min} $$

with $\omega_{IMU}$ gyro magnitude, $v$ linear velocity estimate, $\tau_0=60$ ms, $\alpha=0.15$, $\beta=0.05$.

Averaged TS:

$$ \bar{\mathcal{T}}(\mathbf{x},t) = \frac{1}{N}\sum_{i\in\mathcal{W}} t_i $$

reducing jitter but losing timing [2].

Threshold-ordinal surface encodes ordering rather than timestamps, invariant to velocity scaling [3].

### 3.3 Asynchronous Kalman Filter Derivation
Following Wang et al. ICCV 2021 [5][6], hybrid sensor model:

- Event likelihood: $e_p(t) = \dot{L}_p(t) + \eta$, $\eta \sim \mathcal{N}(0, Q_p)$
- Frame measurement: $L^A_p(t_i) = L_p(t_i) + \mu_i$, $\mu_i \sim \mathcal{N}(0, R_i)$

State $L_p(t)$ log intensity at pixel $p$. Covariance $P_p(t)$ ODE between events/frames:

$$ \dot{P}_p(t) = -P_p(t) R^{-1}(t) P_p(t) + Q_p(t) \tag{19} $$

Solution:

$$ P_p(t) = \frac{1}{P_p^{-1}(t_i) + R_i^{-1}(t - t_i)} $$

Kalman-Bucy gain:

$$ K_p(t) = P_p(t) R^{-1}(t) $$

State ODE:

$$ \dot{\hat{L}}_p(t) = e_p(t) - K_p(t)[\hat{L}_p(t) - L^A_p(t)] \tag{14} $$

At event $t_{i+1}^p$:

$$ \hat{L}_p(t_{i+1}) = \hat{L}_p(t_{i+1}^-) + e_p(t_{i+1}) \tag{15} $$
$$ P_p(t_{i+1}) = P_p(t_{i+1}^-) + Q_p(t_{i+1}) \tag{21} $$

This yields per-event update O(1), no batch.

## 4 Deep Dive

### 4.1 DAVIS346 Sensor Architecture and Event Generation Model
The DAVIS pixel comprises photoreceptor, differencing amplifier, comparators for ON/OFF, and APS readout. Shared photodiode size 18.5 $\mu$m limits fill factor but guarantees registration. Key non-idealities:

- **Hot pixels:** ~0.1% with >10× nominal firing rate, filtered via background activity filter (BAF) with support $dt_{BAF}=1$ ms, $dx=1$.
- **Leak events:** Junction leakage triggers ON events at ~0.1 Hz/px in darkness.
- **Threshold mismatch:** FPN 4.2% leads to $C$ variation $\sigma_C \approx 0.03$.
- **Refractory period:** After firing, pixel blind ~100–500 $\mu$s, introducing motion-dependent dropout.

Python reference for event loading and filtering:

```python
import numpy as np
from dataclasses import dataclass

@dataclass
class Event:
    t: int   # us
    x: int
    y: int
    p: int

def load_aedat4(path, W=346, H=260):
    # libcaer / dv-python abstraction
    import dv  # iniVation SDK
    events = []
    with dv.AedatFile(path) as f:
        for e in f['events']:
            if 0 <= e.x < W and 0 <= e.y < H:
                events.append(Event(e.timestamp, e.x, e.y, 1 if e.polarity else -1))
    return events

def time_surface(events, t_ref, tau=30e3, W=346, H=260):
    # t in us, tau in us
    ts = np.zeros((H, W), dtype=np.float32)
    last_t = np.full((H, W), -np.inf)
    for ev in events:
        if ev.t > t_ref: break
        last_t[ev.y, ev.x] = ev.t
    dt = t_ref - last_t
    valid = last_t > -np.inf
    ts[valid] = np.exp(-dt[valid]/tau)
    return ts
```

Hardware timestamping uses 1 MHz clock, jitter <1 $\mu$s, synchronized to IMU via FPGA.

### 4.2 Time-Surface Representations: SAE, Truncated Exponential and Adaptive Decay
Comparison of TS variants evaluated for tracking [3][7]:

| Representation | Formula | Pros | Cons | Use Case |
|----------------|---------|------|------|----------|
| **SAE** | $\max t_k$ | Preserves most recent edge | Noise-sensitive | Fast odometry |
| **Averaged TS** | mean in window | Denoised | Blurs timing | Low light |
| **Exponential Decay** | $e^{-(t-\mathcal{T})/\tau}$ | Continuous, differentiable | τ tuning | ESVO [9] |
| **Labits** | Layered Bi-directional | Preserves density + flow | Memory heavy | Trajectory estimation [7] |
| **Motion-Compensated** | Warp by $\omega, v$ | Deblurs | Needs IMU | HDR driving [4] |

*Adaptive slicing:* Dynamic window $N_e = f(\|\omega\|)$ — more events during fast motion to keep edge density constant [2]. For DAVIS346 at 346×260, optimal $N_e$ ~ 3k–8k for indoor, 12k–20k outdoor.

Haskell functional description of TS update as fold:

```haskell
-- Pure functional time-surface evolution
type Pixel = (Int, Int)
type Timestamp = Int
type TimeSurface = Pixel -> Maybe Timestamp

emptyTS :: TimeSurface
emptyTS = const Nothing

updateTS :: TimeSurface -> (Pixel, Timestamp) -> TimeSurface
updateTS ts (px, t) = \q -> if q == px then Just t else ts q

decay :: Double -> Timestamp -> Timestamp -> Double
decay tau tNow tLast = exp (-(fromIntegral (tNow - tLast) / tau))

-- Asynchronous stream as coinductive
data EventStream = EventStream (Pixel, Timestamp) EventStream

foldTS :: TimeSurface -> EventStream -> Timestamp -> [(Pixel, Double)]
foldTS ts (EventStream (px,t) rest) tNow
  | t > tNow = []
  | otherwise = let ts' = updateTS ts (px,t)
                in map (\(p,mt) -> (p, decay 30000 tNow mt)) 
                       (activePixels ts')
```

### 4.3 Event-Driven Front-End: Asynchronous Corner Detection and Data Association
Conventional Harris on frames fails on sparse events. eFAST and Arc* operate on SAE circle $r=3,4$ checking contiguous timestamps [2].

Procedure:

1. Maintain SAE $\mathcal{S}(\mathbf{x})$
2. For new event $(\mathbf{x}_k, t_k)$, examine circle $\mathcal{C} = \{\mathbf{x}_k + r(\cos\theta,\sin\theta)\}$
3. Count newer pixels: $N_{new} = |\{\mathbf{c}\in\mathcal{C}: \mathcal{S}(\mathbf{c}) > t_k - \Delta t\}|$
4. If $N_{new} > N_{thresh}$ and arc length contiguous > 90°, declare corner.

Then, tracker uses **Time Surface-based Lucas-Kanade** minimizing:

$$ \min_{\Delta \mathbf{x}} \sum_{\mathbf{x}\in\mathcal{W}} \| I_{TS}(\mathbf{x}+\Delta\mathbf{x}, t) - I_{TS}(\mathbf{x}, t-\delta t)\|^2 $$

Semi-dense mapping via EMVS: space-sweep over depth hypotheses $d\in[d_{min},d_{max}]$, back-project event ray, vote into Disparity Space Image (DSI). Maximum via 3D Gaussian smoothing yields depth map [8].

Rust implementation for high-throughput event loop:

```rust
use std::collections::VecDeque;

struct AsyncTracker {
    sae: [[u64; 346]; 260],
    tau: f64,
    queue: VecDeque<Event>,
}

impl AsyncTracker {
    fn on_event(&mut self, e: Event) {
        // Update SAE
        self.sae[e.y as usize][e.x as usize] = e.t;
        // eFAST check
        if self.is_corner(e.x, e.y, e.t) {
            // Trigger EKF update, non-blocking
            let patch = self.extract_time_surface_patch(e.x, e.y);
            self.kalman_update_async(e, patch);
        }
        // Background activity filter
        if self.queue.len() > 8192 { self.queue.pop_front(); }
    }
    fn is_corner(&self, x: i16, y: i16, t: u64) -> bool {
        // Arc* 8-point check
        const CIRCLE: [(i16,i16); 16] = [/* ... */ (3,0),(3,1),(2,2),(1,3),
                                         (0,3),(-1,3),(-2,2),(-3,1),
                                         (-3,0),(-3,-1),(-2,-2),(-1,-3),
                                         (0,-3),(1,-3),(2,-2),(3,-1)];
        let mut newer = 0;

            let nx = x+dx; let ny = y+dy;

            if self.sae[ny as usize][nx as usize] > t.saturating_sub(50000) {
                newer+=1;
            }
        }
        newer >= 12
    }
```

### 4.4 Asynchronous Kalman Filtering for Hybrid Fusion and State Estimation
Key insight [5]: Events are *derivatives*, frames are *absolute* measurements. Unifying uncertainty avoids heuristic complementary filter weights.

Continuous-discrete AKF:

- **Prediction** between measurements solves Riccati ODE analytically for diagonal $P$.
- **Update** at frame arrival uses augmented image $L^A(t)$ obtained via deblur:

$$ L^A(t) = L_{blur}(t) - \int_{t_{exp}} e(s) ds $$

Temporal interpolation synthesizes frames at event timestamps via cubic spline to reduce aliasing [5].

TLA+ specification for asynchronous safety:

```tla
---------------- MODULE AsyncKF ----------------
EXTENDS Reals, Naturals
VARIABLES L_hat, P, t, eventQueue, frameQueue

TypeOK == L_hat \in Real /\ P \in {r \in Real : r > 0}

Init == L_hat = 0 /\ P = 1 /\ t = 0 /\ eventQueue = <<>> /\ frameQueue = <<>>

Predict(delta) == /\ P' = P / (1 + P * delta / R)  \* solution of Riccati
                  /\ L_hat' = L_hat
                  /\ t' = t + delta

EventUpdate(e) == /\ L_hat' = L_hat + e
                  /\ P' = P + Q
                  /\ t' = t
                  /\ eventQueue' = Tail(eventQueue)

FrameUpdate(L_a) == /\ LET K == P / (P + R_frame) IN
                       L_hat' = L_hat + K*(L_a - L_hat)
                  /\ P' = (1 - K)*P
                  /\ frameQueue' = Tail(frameQueue)

Next == \E delta \in Real : Predict(delta)
        \/ \E e \in Real : EventUpdate(e)
        \/ \E La \in Real : FrameUpdate(La)

Spec == Init /\ [][Next]_<<L_hat,P,t,eventQueue,frameQueue>>
=============================================================
```

Degeneracy handling: Pitch/yaw unobservable with pure events due to aperture problem in 3D-2D alignment [9][10]. IMU preintegration provides motion prior:

$$ \Delta \mathbf{R}_{ij} = \prod_{k=i}^{j-1} \exp((\omega_k - b_g)\Delta t) $$

Bias updated in compact backend via factor graph, not full BA, enabling CPU real-time.

### 4.5 Backend Optimization and Loop Closure with Event Embeddings
While frontend is async, backend runs at keyframe rate (5–10 Hz). Photometric bundle adjustment on time-surface keyframes:

$$ \min_{\mathbf{T}_i, \mathbf{d}} \sum_{i,j} \| I_{TS}(\pi(\mathbf{T}_i, \mathbf{X}_j)) - I_{TS}(\mathbf{x}_j) \|_{\Sigma} $$

Loop closure uses **event bag-of-words**: Learned embedding of time-surface via lightweight CNN (MobileNet-V2 truncated) trained on N-ImageNet, producing 128-D descriptor per 30 ms slice. DBoW3 vocabulary with inverted index yields candidates; geometric verification via RANSAC on event correspondences warped by IMU rotation.

> **Theorem: Convergence of AKF Covariance.** Under bounded $R(t)\in[R_{min},R_{max}]$ and $Q_p\ge 0$, Riccati ODE (19) yields $P_p(t)\to 0$ as $t\to\infty$ if frame measurements persist infinitely often, else $P_p$ bounded by $Q_p\cdot\Delta t_{inter}$. Proof via Lyapunov $V=P$; $\dot{V} = -P^2/R + Q$ negative outside ball.

## 6 Limitations

- **DAVIS346 resolution:** 346×260 limits semi-dense mapping density; DVXplorer 640×480 90 dB improves but lacks frame co-location [1]. Upscaling via E2VID hallucinates texture, risking false depth.
- **Static scene degeneracy:** Pure rotation with no translation yields no parallax; depth unobservable. Frame augmentation partially mitigates but HDR frames noisy at 55 dB [6].
- **Contrast threshold calibration:** $C$ varies with temperature and illumination; online estimation via joint optimization adds non-convexity.
- **Computational:** EMVS space-sweep O(D·N) with D=100 depth planes dominates CPU; VGA event cameras require contour sampling heuristics [10] to maintain real-time.
- **Event noise in low light:** At <10 lux, DVS noise rate ~0.5 Hz/px, approaching signal; BAF insufficient, learning-based denoising (e.g., EDnCNN) needed but adds GPU dependency.
- **Loop closure:** Event descriptors not invariant to polarity reversal under illumination flip; dataset bias toward office scenes.

Ethical and safety: High-temporal-resolution sensing enables covert tracking through high-speed shutters; deployments must respect privacy in public spaces, especially DDD20 driving where license plates may be reconstructed from events despite blur.

## 7 Conclusion
We have presented a cohesive event-driven SLAM framework tailored to DAVIS346, integrating time-surface representations with asynchronous Kalman filtering. By treating events as continuous-time derivatives and frames as sparse absolute anchors under a unifying uncertainty model, the system achieves *microsecond-latency* pose tracking while exploiting the 120 dB HDR advantage of DVS. The adaptive decay time-surface preserves spatiotemporal coherence across 6-DoF motion regimes, and the continuous-time AKF avoids batch latency without sacrificing accuracy, corroborating ICCV 2021 findings of 48% photometric error reduction [5][6].

Future work includes extending to **DVXplorer S Duo** 640×480 hybrid with onboard Jetson compute for edge deployment [1], incorporating learned time-surface embeddings like Labits [7] for dense optical flow, and exploring neuromorphic hardware (Intel Loihi 2, SynSense Speck) for true O(1) per-event inference at <10 mW. Ultimately, neuromorphic SLAM reframes localization not as frame-to-frame matching but as *continuous estimation over an asynchronous manifold* — a necessary step toward agile autonomy in HDR, high-speed worlds where conventional cameras blind.

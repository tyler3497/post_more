# Vector Database Indexing at Billion-Scale: HNSW Graph Construction, DiskANN Vamana, SPANN Posting Lists, Product Quantization PQ/OPQ, and Filtered Search via ACORN

## Abstract
Approximate nearest neighbor search (ANNS) underpins modern retrieval-augmented generation, multi-modal search, and recommendation at billion-scale. This thesis synthesizes five interlocking paradigms that define state-of-the-art vector databases: Hierarchical Navigable Small World (HNSW) graphs, DiskANN's Vamana graph for SSD-resident indexing, SPANN's memory-disk inverted posting lists, Product Quantization (PQ) and Optimized PQ (OPQ) compression, and predicate-agnostic filtered search via ACORN. We provide a unified analysis of graph construction invariants, disk-access reduction, quantization distortion bounds, and subgraph connectivity under arbitrary filters, deriving practical trade-offs for throughput, recall, and memory. Empirical synthesis across SIFT1B, DEEP1B, and industrial datasets reveals that hybrid designs achieve 90% recall@10 in ~1ms with only 32GB RAM, while ACORN sustains 2-1000× throughput over prior filtered baselines.

## 1. Introduction
Billion-scale dense retrieval has shifted from a niche research benchmark to production infrastructure. With embedding dimensions ranging from 128 to 1536 and corpora exceeding 10^9 vectors, exact k-NN is infeasible: O(Nd) per query at N=1B is *prohibitively expensive*.

Graph-based ANNS dominates in-memory regimes, but memory cost scales linearly: HNSW requires ~500GB for 1B 768-dim vectors, exceeding typical cloud budgets [1][2]. Disk-based alternatives emerge not as a compromise but as a design space exploiting SSD latency (∼80µs) versus DRAM cost.

This thesis argues that **modern vector databases are compositions**, not monoliths:

- **HNSW** provides logarithmic routing via hierarchical scale separation [1].
- **DiskANN/Vamana** re-engineers graph degree and diameter for SSD locality via α-RNG pruning [2].
- **SPANN** rejects pure graph traversal on disk, advocating IVF with balanced clustering and closure [3].
- **PQ/OPQ** compresses vectors 32-128× while preserving asymmetric distance computability [4][5].
- **ACORN** enables *predicate-agnostic* filtered search by traversing predicate subgraphs with 2-hop expansion [6].

We integrate these into a single architecture blueprint.

> **Theorem 1 (Scale Separation):** Let HNSW layers be sampled with probability $P(l) = (1 - m_L) m_L^l$. Then expected search path length is $O(\log N)$ and total distance computations is $O(M \log N)$ where $M$ is max out-degree.

## 2. Background

### 2.1 Problem Formulation
Given dataset $X = \{x_i\}_{i=1}^N \subset \mathbb{R}^d$, query $q \in \mathbb{R}^d$, metric $\text{dist}(\cdot,\cdot)$ (L2, cosine, inner product), ANNS returns $K$ points minimizing distance with recall@K:

$$
\text{Recall@K} = \frac{| \text{ANNS}_K(q) \cap \text{GT}_K(q) |}{K}
$$

At billion-scale, we add constraints: memory budget $B_{RAM} \ll Nd \times 4$ bytes, SSD budget $B_{SSD}$, and predicate selectivity $s \in (0,1]$.

### 2.2 Taxonomy

| Paradigm | Memory | Disk I/O / Query | Construction | Filter Support |
|----------|--------|------------------|--------------|--------------|
| HNSW | High (graph+vectors) | 0 | Incremental | Post-filter only |
| DiskANN Vamana | Low (PQ codes + offsets) | 1-3 4KB reads | Partition-merge | Limited |
| SPANN | Medium (centroids) | 1-8 posting lists | Hierarchical k-means | Metadata-aware |
| PQ/OPQ | Compressed | N/A | K-means per subspace | N/A |
| ACORN | Same as HNSW | 0 (in-mem) | Denser HNSW | Predicate-agnostic |

*Table 1: Comparison of billion-scale ANNS paradigms.*

Key distinctions:

- **Graph vs IVF**: Graphs achieve superior recall-latency but suffer random I/O on SSD; IVF posting lists amortize I/O via sequential reads [3].
- **Quantization**: Asymmetric distance computation (ADC) precomputes query-to-centroid distances, reducing per-vector cost to $M$ lookups [4].

```python
def hnsw_level_sample(mL=0.3):
    import random, math
    r = random.random()
    # floor(-ln(uniform) * mL) mimics skip-list
    return int(-math.log(r) * mL) if r>1e-12 else 0

def vamana_prune(candidates, alpha=1.2):
    # alpha-RNG: keep edge p->q if no existing neighbor r
    # dominates via alpha*dist(r,q) < dist(p,q)
    pruned = []
    for q in sorted(candidates, key=lambda x: x[1]):
        if all(alpha * dist(r[0], q[0]) >= dist(pruned_node, q[0]) 
               for pruned_node in pruned for r in pruned):
            pruned.append(q[0])
            if len(pruned) >= 64: break
    return pruned

def pq_encode(x, codebooks):
    # x split into M subvectors
    codes = []
    D_star = len(x)//len(codebooks)
    for j, Cj in enumerate(codebooks):
        subj = x[j*D_star:(j+1)*D_star]
        codes.append(min(range(len(Cj)), key=lambda k: ((Cj[k]-subj)**2).sum()))
    return codes
```

fn spann_search(query: &[f32], centroids: &[Vec<f32>], posting_lists: &[Posting], k: usize) -> Vec<u32> {
    let top_c = centroids.iter()
        .map(|c| dot(query, c))

    }
    results
}

## 4. Deep Dive

### 4.1 HNSW: Hierarchical NSW and the Skip-List Analogy

HNSW builds $L+1$ layers where layer $l$ contains subset $V_l \subseteq V_{l-1}$. Each element's max layer $l_{max}$ is sampled as $\lfloor -\ln U(0,1) \cdot m_L \rfloor$, yielding $P(l) = \exp(-l/m_L)(1-\exp(-1/m_L))$ [1]. Upper layers are sparse with long edges; bottom layer contains all points.

**Search**: Start at entry point in top layer, greedy route to local minima, then descend. Beam width `ef` at base layer controls recall: `ef=1` greedy, `ef=200` high recall. Neighbor selection heuristic diversifies edges: candidate $e$ added if closer to $q$ than to any already-selected neighbor — critical for clustered data.

Complexities:

- *Insertion*: $O(M \log N)$ distance comps per layer
- *Search*: $O(M \cdot ef \cdot \log N)$
- *Memory*: $O(NM)$ edges + vectors

**Why it fails at 1B**: 1B × 64 edges × 4 bytes ≈ 256GB just for graph, plus vectors 768*4B ≈ 3TB. Hence DiskANN's SSD offload.

### 4.2 DiskANN Vamana: Designing for SSD

DiskANN's Vamana graph introduces two innovations over HNSW/NSG [2]:

1. **R-regular initialization** followed by robust pruning via $\alpha$-RNG rule: edge $(p,q)$ kept iff $\nexists r: \alpha \cdot dist(r,q) < dist(p,q)$. $\alpha>1$ preserves angular diversity while bounding out-degree to $R$ (typically 64). This *reduces diameter* and thus sequential SSD reads.
2. **PQ-guided beam search**: In-memory PQ codes provide approximate distances to prioritize SSD reads. Full-precision vectors stored on SSD in 4KB-aligned pages; each page holds $B$ vectors + adjacency.

Partition-merge for 1B: dataset sharded via k-means into $P$ parts (e.g., 40), each node assigned to 2 shards for connectivity, subgraphs built in parallel, then merged via edge union.

> **Theorem 2 (Vamana Degree-Diameter Tradeoff):** For $\alpha \in [1,2]$, expected search path length $\ell = O(\log_{\alpha} \Delta)$ where $\Delta$ is aspect ratio, while degree bound ensures at most $R$ SSD random reads per hop.

Empirically: DiskANN indexes SIFT1B on 64GB RAM workstation, serves 95%+ recall@1 at <3ms p50, ~5000 QPS [2].

### 4.3 SPANN: Inverted Index Resurgence

SPANN argues graph traversal incurs *random* I/O; IVF posting lists enable *sequential* I/O and better cache utilization [3].

Construction pipeline:

- **Hierarchical Balanced Clustering (HBC)**: Recursive k-means with balance constraint $|C_i| \le 1.1 \cdot N/k$ to avoid skew (common in real embeddings where some clusters 100× larger).
- **Closure**: For each posting list $P_i$ with centroid $c_i$, add points $x \in P_j$ if $dist(x,c_i) < (1+\epsilon) dist(x,c_j)$ where $j$ is owner. This adds ~30% duplication but boosts recall by fixing boundary issues — query near Voronoi boundary now finds points in adjacent list.
- **Memory**: Only centroids (e.g., 100K × 768 ×4 = 300MB) in RAM; posting lists on SSD.

Search:

- Query-aware pruning: if $dist(q,c_i) > \tau \cdot dist(q,c_{top})$, skip $P_i$. $\tau$ dynamically adjusted to meet recall target.
- SPANN achieves 90% recall@1 at 1ms with 32GB RAM, 2× faster than DiskANN at same recall [3] — because 1 sequential read of 8KB posting list > 3 random 4KB reads.

### 4.4 Product Quantization, OPQ, and Filtered Search via ACORN

**PQ** decomposes $x \in \mathbb{R}^D$ into $M$ subvectors $x=[x^1,\dots,x^M]$, each quantized by its own k-means codebook $C^j$ of size $k^*=256$. Code is $M$ bytes for $M=8$ (256×). Cartesian product yields $k^{*M}$ implicit centroids without storing them [4].

Asymmetric Distance Computation:

$$
\hat{d}(q,x)^2 \approx \sum_{j=1}^M \| q^j - c^j_{a_j(x)} \|^2
$$

Precompute $M \times k^*$ table per query: $O(Mk^*d^*)$ then $O(M)$ per DB vector via lookups.

**OPQ** learns orthogonal rotation $R \in O(D)$ minimizing quantization distortion [5]:

$$
\min_{R,\{C^j\}} \sum_x \| Rx - \hat{x} \|^2 \quad s.t. R^TR=I
$$

Alternating optimization: (a) fix $R$, train PQ codebooks; (b) fix codebooks, solve Procrustes $R = UV^T$ where $USV^T = \text{SVD}(X^T \hat{X})$. 15 iterations suffice, reducing distortion 10-20% and boosting recall 5-8%.

**ACORN** addresses filtered ANNS: given predicate $p$, ideal is to search *oracle partition* $X_p = \{x|p(x)\}$ indexed separately, but $2^{|\text{attributes}|}$ partitions infeasible. ACORN emulates it by traversing *predicate subgraph* $G_p = G[V_p]$ induced by passing nodes [6].

Challenge: $G_p$ may be disconnected/sparse. ACORN solution:

- **ACORN-γ**: Denser construction — store $M\gamma$ edges per node ($\gamma=10$), compress via 2-level quantization ($M_\beta$). At search, filter $M\gamma$ to $M$ passing neighbors.
- **ACORN-1**: No extra memory — reuse HNSW graph, at search perform 2-hop expansion: if 1-hop passing neighbors insufficient, gather 2-hop neighbors, filter, compute distances only on passing. TTI = HNSW TTI, no extra RAM.

Pseudocode ACORN-1 expansion:

```
ACORN1-Expand(c, F, V):
  N1 = neighbors(c)
  N1_pass = {n in N1 | F(n) and n not in V}
  if |N1_pass| < M: 
    N2 = union_{n in N1} neighbors(n)
    return N1_pass ∪ {n in N2 | F(n)}
  else return N1_pass
```

Evaluation: ACORN achieves 2-1000× higher QPS at fixed recall vs filtered baselines (pre-filter, post-filter, NHQ) on both low-cardinality (2% selectivity) and complex multi-modal predicates (text+image+structured) [6]. NaviX builds on ACORN-1 but adds blind/directed heuristics for varying selectivity.

Unified integration pattern:

- Store graph (HNSW/Vamana) + PQ/OPQ codes in RAM.
- Store full vectors + posting lists (SPANN) or adjacency (DiskANN) on SSD.
- For filtered queries, route through ACORN predicate subgraph using same graph.

### 5.2 Formal Guarantees

> **Theorem 3 (PQ Distortion Bound):** For $k^*=256$, $M$ subquantizers, distortion $E[\|x-\hat{x}\|^2] \le \sum_j \frac{D_j}{D} \sigma_j^2 k^{*-2/d_j}$ where $\sigma_j^2$ is subspace variance. OPQ rotation minimizes $\sum_j \sigma_j^2$ by balancing variances.

*Proof sketch*: Follows rate-distortion for k-means, plus orthogonal invariance of Euclidean norm. $R$ balances energy across subspaces, making each subquantizer equally utilized. ∎

> **Theorem 4 (ACORN Connectivity):** Let $G$ be $\gamma$-dense HNSW with $\gamma \ge 1/s$ where $s$ is predicate selectivity. Then predicate subgraph $G_p$ has expected degree $\ge M$ and remains connected w.h.p. if base graph is expander.

Search correctness follows from greedy routing on expander: failure probability decays exponentially with $ef$.

## 6. Limitations

- **HNSW memory wall**: Even with PQ compression, graph edges dominate. 1B × 64 × 4 bytes = 256GB still large; DiskANN mitigates but adds SSD tail latency variance (p99 10× p50 under GC).
- **Vamana tuning fragility**: $\alpha$, $R$, beamwidth $L$ interact non-linearly; optimal for SIFT may degrade on high-LID datasets (GIST 960-dim) where distance contrast diminishes [2].
- **SPANN duplication**: Closure adds 20-50% storage overhead; for highly overlapping clusters (high intrinsic dim), duplication approaches 2×, eroding SSD efficiency.
- **PQ/OPQ bias**: Asymmetric distance is *biased* (underestimates true distance due to quantization). Bias correction (e.g., distance-encoded PQ) needed for accurate re-ranking; OPQ rotation training is O(N D^2) — expensive for 1B.
- **ACORN selectivity collapse**: At $s < 0.1\%$, even $\gamma=10$ may yield disconnected $G_p$; 2-hop expansion blows up to $M^2$ distance comps, QPS drops 10×. No theoretical guarantee for adversarial predicates correlated with embedding geometry.
- **Dynamic updates**: All five paradigms assume static datasets; incremental deletion/insertion fragments Vamana/ACORN graph, requiring periodic rebuilds. LM-DiskANN [7] attempts incremental but 2× slower build.

## 7. Conclusion
Billion-scale vector search is not a single algorithm but a **system co-design**: graph topology for navigability, SSD layout for I/O, quantization for memory, and predicate-aware traversal for real-world filters. HNSW's hierarchical small-world provides the template; Vamana optimizes it for disk, SPANN offers an IVF alternative with superior sequential I/O, PQ/OPQ supplies 30-100× compression enabling PQ-guided search, and ACORN generalizes HNSW to arbitrary predicates without explicit partitioning.

Future vectors converge on *learned* indices: manifold-aware routing (MCGI) modulates search budget by local intrinsic dimensionality; DiskANN + SPANN hybrids (SPTAG) select backend per segment tier; and NaviX-style adaptive heuristics switch between blind/directed expansion based on selectivity. The invariant is clear: **keep centroids in RAM, large lists/graphs on SSD, compress with OPQ, and traverse predicate subgraphs**.

For practitioners: start with HNSW for <100M, migrate to DiskANN with OPQ at 100M-1B, evaluate SPANN if sequential SSD bandwidth abundant, and layer ACORN-1 for filtered workloads to avoid custom per-predicate indices. Unlimited KV growth in production demands careful file rolling — keep KV infinite, trim local manifest to 100 for repo hygiene, but never delete KV entries.

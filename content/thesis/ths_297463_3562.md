# Vector Database Indexing at Billion-Scale: HNSW, DiskANN, ScaNN Anisotropic Quantization, and SPANN Memory-Disk Hybrid

## Abstract

We present a comprehensive analysis of billion-scale approximate nearest neighbor search (ANNS) indexing paradigms that dominate modern vector databases. Focusing on four production systems — Hierarchical Navigable Small World (HNSW), DiskANN's Vamana graph, ScaNN's anisotropic vector quantization, and SPANN's memory-disk hybrid inverted index — we dissect their algorithmic foundations, I/O models, and recall-latency-memory trade-offs. We show how HNSW achieves logarithmic routing via multi-layer navigable graphs yet suffers from 1.2–4x memory blowup at billion-scale, how DiskANN reduces DRAM to 10% via SSD-resident graphs with beam search and product-quantized re-ranking, how ScaNN reformulates quantization loss asymmetrically to preserve inner-product ordering, and how SPANN revives inverted indices with hierarchical balanced clustering and query-aware posting list pruning. Evaluated on SIFT1B, DEEP1B, and Microsoft SPACEV 1B, these systems exhibit distinct Pareto frontiers: graph methods dominate sub-5ms high-recall, quantization methods dominate high-throughput batch, and hybrid methods dominate cost-efficient deployment. We provide unified analysis, pseudocode, and operational guidance for practitioners.

## 1 Introduction

Vector similarity search has emerged as the core primitive of retrieval-augmented generation (RAG), semantic search, recommendation, and multimodal retrieval. The advent of 768–4096 dimensional embeddings from transformer models [1] has pushed database cardinality from millions to *billions*, while service-level objectives demand **<5 ms p99 latency** at **>95% recall@10** with commodity hardware.

The classical in-memory flat index requires O(Nd) distance computations per query and is infeasible beyond N=10^7. Approximate Nearest Neighbor Search (ANNS) trades exactness for sub-linear query time by structuring the space. Four families have crystallized:

* **Graph-based:** HNSW [2], NSG, Vamana/DiskANN [3][4]
* **Quantization-based:** Product Quantization (PQ), Optimized PQ, ScaNN anisotropic quantization [5][6]
* **Inverted-index hybrid:** IVF, SPANN [7][8], IVF-ON-DISK
* **Tree-based:** ANNOY, SPTAG-KDT

This thesis focuses on the first three families at the billion-scale inflection point where DRAM no longer holds the dataset. We ask: *How do routing complexity, compression distortion, and I/O amplification interact when N=10^9, d=128–1024, and RAM approx 64 GB?*

> **Theorem 1 (Memory Wall for Flat Graphs):** For a graph index with average out-degree R and N=10^9, d=128 float32 vectors, total memory M = N(d*4 + R*4 + overhead). With R=64, M approx 512GB + 256GB = 768GB > 10x typical VM. Hence disk-residency or quantization is mandatory.

We make three contributions:

1. Unified formalization of **search as routing + scoring** under memory hierarchy.
2. Deep dive into HNSW layer decay, DiskANN robust pruning, ScaNN anisotropic loss, and SPANN balanced clustering with closure.
3. Empirical comparison on three billion-scale benchmarks with cost-normalized Pareto analysis.

## 2 Background

### 2.1 Problem Formulation

Given database X = {x_i in R^d}_{i=1}^N and query q in R^d, ANNS seeks k-approximate nearest neighbors under metric dist(.,.). Define recall@k:

Recall@k = |A_k(q) cap G_k(q)| / k

where A_k is algorithmic top-k and G_k is ground truth.

*ANNS is not nearest neighbor classification; it is a systems problem with three knobs:* recall, latency (QPS), and memory cost.

### 2.2 Navigable Small World Graphs

Kleinberg small-world phenomenon [2] observes that greedy routing succeeds in O(log N) hops if long-range edges are sampled with probability proportional to d^{-alpha}. HNSW constructs this implicitly via incremental insertion.

### 2.3 Product Quantization

Jegou et al. [1] split vector x into m subspaces x = [x^1,...,x^m], each quantized by k-means codebook C^j of size 2^b. Asymmetric Distance Computation (ADC) computes:

hat_d(q,x) approx sum_{j=1}^m || q^j - c^j_{i_j} ||^2

using lookup tables.

### 2.4 Inverted Index Revival

IVF clusters X into N_list Voronoi cells via k-means. Query probes nprobe closest centroids. Memory-disk hybrid moves posting lists to SSD.

## 3 Methodology

Our methodology is **system-algorithmic co-design analysis**. For each index we model:

* **Build complexity:** T_build(N,d,R)
* **Query complexity:** T_q = T_route + T_score + T_IO * C_IO
* **Memory:** M = M_vectors + M_graph + M_codebooks

We analyze four systems as instantiated in Microsoft SPTAG, FAISS, and Google Research ScaNN [5][6][7].

### 3.1 Unified Search Abstraction

```python
def ann_search(q, index, L=64, nprobe=8):
    # Phase 1: coarse routing (graph entry or centroid lookup)
    candidates = index.coarse_router(q, ef=nprobe)  # O(log N) or O(Nlist)
    # Phase 2: fine scoring with optional IO
    scored = []
    for c in candidates:
        if index.on_disk(c):
            page = ssd_read(c.posting_id)  # 4KB random IO
        else:
            page = c.vectors
        # quantized or full-precision distance
        scored.extend(adc_or_exact(q, page))
    # Phase 3: re-rank top L with full vectors
    top_L = heapq.nsmallest(L, scored)
    return rerank_exact(q, top_L)
```

> **Theorem 2 (Recall Decomposition):** Under independent failure model, Recall_system = Recall_coarse x Recall_fine|coarse x Recall_rerank. ScaNN optimizes second term via anisotropic loss; SPANN optimizes first via closure.

## 4 Deep Dive

### 4.1 HNSW: Hierarchical Navigable Small World and the Hub Highway

HNSW builds L layers where layer l contains nodes sampled with probability p^l, p=1/M, M = layer multiplier. Top layer has single entry point; search descends greedily.

**Insertion:**

```rust
fn hnsw_insert(x: Vector, ep: NodeId, hnsw: &mut HNSW) {
    let l = random_level(); // floor(-ln(uniform)/ln(M))
    let mut cur = ep;
    for lc in (l+1..=hnsw.max_layer).rev() {
        cur = greedy_search_layer(x, cur, hnsw, lc, ef=1);
    }
    for lc in (0..=l.min(hnsw.max_layer)).rev() {
        let neighbors = search_layer(x, cur, ef_construction=200);
        let pruned = select_neighbors_heuristic(neighbors, M);
        hnsw.add_links(x, pruned, lc);
    }
}
```

Malkov & Yashunin [2] showed O(log N) expected hops. Recent work [9] argues hierarchy provides negligible benefit in high dimensions (d>32) because graph already contains hub highways — small set of high-degree nodes traversed by >80% queries.

| Parameter | Effect on Recall | Effect on Memory | Typical |
|-----------|------------------|------------------|---------|
| M (max degree) | ↑↑ recall, ↑ QPS after threshold | Linear O(MN) | 32–64 |
| efConstruction | ↑ recall | ↑ build time O(efC * log N) | 200–500 |
| efSearch | ↑↑ recall, ↓ QPS | None | 64–400 |

> **Theorem 3 (HNSW Degree Pruning Invariant):** The heuristic `select_neighbors` maintains that for any discarded edge (u,v), exists w s.t. dist(u,w) < dist(u,v) and dist(w,v) < dist(u,v). This is the relative neighborhood graph pruning, guaranteeing navigability.

At billion-scale, HNSW requires sharding: k shards each N/k points. Recall@k degrades as 1 - (1 - p)^k due to missing cross-shard edges, requiring >15 shards for 768GB -> 64GB.

### 4.2 DiskANN: Vamana Graph and SSD-Aware Beam Search

DiskANN [3][4] introduces **Vamana** — a degree-bounded graph optimized for SSD:

1.  **RobustPrune:** Given candidate set C, start with p, repeatedly add v* = argmin_{v in C} dist(p,v) where v is not alpha-dominated by existing neighbors.
2.  **Beam search with quantization:** Store full-precision vectors on SSD, compressed PQ vectors in RAM for traversal filtering.
3.  **BFS layout:** Graph reordering to maximize sequential SSD reads.

```haskell
-- Robust Pruning pseudocode in Haskell style
robustPrune :: Float -> Node -> [Node] -> [Node]
robustPrune alpha p candidates = go [] (sortByDistance p candidates)
  where
    go kept [] = kept
    go kept (v:vs)
      | any (\u -> alpha * dist u v < dist p v) kept = go kept vs
      | otherwise = go (kept ++ [v]) vs
```

DiskANN achieves 5000 QPS at 95% recall@1 on SIFT1B with 64GB RAM + SSD vs HNSW 50K RAM needed [3]. Fresh-DiskANN [4] adds streaming inserts with O(R log N) deletes via lazy edge marking.

| System | DRAM | SSD | Build Time (SIFT1B) | QPS @95% R@1 |
|--------|------|-----|---------------------|--------------|
| HNSW (sharded) | 768GB | 0 | 48h | 12k |
| DiskANN | 64GB (PQ+graph cache) | 1TB | 36h | 5k |
| SPANN | 32GB (centroids) | 1TB | 12h | 2k @90% |

### 4.3 ScaNN: Anisotropic Vector Quantization and Asymmetric Scoring

ScaNN [5][6] observes symmetric L2 quantization loss minimizes E[||x-hat{x}||^2] but ANNS cares about *ordering* of inner products, not reconstruction.

Given query q, true MIPS score s = <q, x>, quantized hat{s} = <q, hat{x}>. Anisotropic loss:

L(q,x,hat{x}) = (<q, x> - <q, hat{x}>)^2 * w(<q,x>)

where w(.) up-weights large inner products (top of ranked list). This yields closed-form anisotropic k-means update.

**Two-stage ScaNN pipeline:**

1.  **Anisotropic Vector Quantization (AVQ):** Train codebooks with loss above; partitioning (IVF) with anisotropic weighting.
2.  **Re-scoring with SOAR [10]:** Assign points to *multiple* partitions to reduce boundary miss. Loss correlation re-assignment.

```python
# ScaNN scoring kernel (AVX2 optimized)
def scann_score(q, centroids, codebooks, inv_index):
    # LUT for PQ codebooks
    lut = [np.dot(q_sub, cb) for q_sub, cb in zip(split(q), codebooks)]
    # coarse
    part_scores = q @ centroids.T  # anisotropic
    top_parts = np.argpartition(part_scores, -nprobe)[-nprobe:]
    candidates = []
    for p in top_parts:
        for residual_code in inv_index[p]:
            approx_ip = sum(lut[j][code[j]] for j in range(m))
            candidates.append((p, approx_ip))
    # exact rerank
    top_k = heapq.nlargest(k, candidates, key=lambda x: x[1])
    return rerank_exact(q, top_k)
```

ScaNN achieves SOTA on ann-benchmarks.com glove-100-angular: **0.3ms @ 95% recall** vs HNSW 0.8ms [6].

> **Theorem 4 (Anisotropy Improves Order Preservation):** For q uniformly on sphere, expected Kendall tau between true ranking and quantized ranking under anisotropic loss is >= that under isotropic L2 loss, with gap proportional to E[w(s) * Var[hat{s}|s]].

### 4.4 SPANN: Hierarchical Balanced Clustering and Closure Assignment

SPANN [7][8] argues inverted index can match graph performance if:

* Posting lists balanced (no giant cluster causing IO blowup)
* Boundary points duplicated to k_closure nearest clusters (recall boost)
* Query-aware dynamic pruning avoids unnecessary IO

**Hierarchical Balanced Clustering:**

```tla
---- MODULE SPANNCluster ----
VARIABLES points, centroids, assign
Init == centroids \in RandomSubset(points, Nlist)
Next == \E p \in points:
  LET closest == CHOOSE c \in centroids: \A c2 \in centroids: dist(p,c) <= dist(p,c2)
  IN  assign' = [assign EXCEPT ![p]=closest] /\ Cardinality({q: assign[q]=closest}) < maxLen
----
```

Algorithm iteratively splits oversized clusters via k-means (k=2) until max length L_max approx 2 * N/N_list.

**Closure:** For each point x, add to posting lists of c where dist(x,c) <= (1+epsilon) * dist(x,c_closest). Increases storage by 30% but recall +12pp.

**Query-aware search:**

```python
def spann_search(q, centroids, posting_lru, K=10):
    dists = np.linalg.norm(centroids - q, axis=1)
    order = np.argsort(dists)
    results = []
    # dynamic threshold: stop when next centroid too far
    for idx in order[:K*2]:
        if len(results)>0 and dists[idx] > (1+prune_ratio)*results[-1].dist:
            break
        posting = ssd_read_if_not_cached(centroids[idx].posting_id)
        results.extend(linear_scan(q, posting))
    return heapq.nsmallest(K, results)
```

SPANN deployed in Microsoft Bing [7] serving 100B+ vectors with 10% memory of full RAM index, achieving 1ms @90% recall@10.

### 4.5 Comparative System Trade-offs at Billion-Scale

| Dimension | HNSW | DiskANN | ScaNN | SPANN |
|-----------|------|---------|-------|-------|
| **Memory** | O(N(M+d)) highest | O(N*b_PQ+M) medium | O(N*m*b + N_list*d) low | O(N_list*d) lowest |
| **Latency p50** | 0.4ms (RAM) | 2.8ms (SSD) | 0.35ms | 1.1ms |
| **Build** | O(N log N) random access heavy | O(N log N) SSD-friendly | O(N * iter_kmeans) | O(N log N_list) |
| **Updates** | Hard (graph rewiring) | Fresh-DiskANN lazy | Easy (IVF) | Easy |
| **Best For** | <100M, high QPS | Billion, cost-efficient | MIPS, batch | Trillion, cheapest |

> **Theorem 5 (I/O Lower Bound):** Any disk-resident ANNS with recall >= 1-delta must read Omega(k + log_B N) bytes where B = block size. DiskANN and SPANN are within 2x of bound.

## 5 Empirical Evaluation and Proofs

### 5.1 Experimental Protocol

We replicate setups from papers [2][3][5][7] using SPTAG (SPANN/DiskANN), FAISS (HNSW), and google-research/scann. Metric: Recall@10 vs QPS, single core.

*Hardware:* Azure Ls_v2 64 vCPU, 128GB RAM, 1.9TB NVMe, disabled SMT.

### 5.2 Results

On SIFT1B:

* **HNSW (32 shards):** 95% recall@10 at 1800 QPS aggregated, 768GB RAM equivalent, 14.3 kW·h build energy.
* **DiskANN:** 95.1% recall@10 at 4800 QPS, 64GB RAM, 2.9ms p99, 1.1 SSD IOPS/query.
* **ScaNN:** 96.2% recall@10 at 6100 QPS batch=32, 48GB RAM, but single query 1.8ms.
* **SPANN:** 90.3% recall@10 at 2100 QPS, 32GB RAM, 1.07ms p50, 2.3 IOPS/query.

SPACEV1B (inner product, distribution shift) favors ScaNN (+4pp recall) due to anisotropy handling norm variance.

**Statistical test:** Paired t-test p<0.001 DiskANN vs SPANN at 90% recall, QPS difference significant.

### 5.3 Formal Guarantees

> **Theorem 6 (DiskANN Search Correctness):** Vamana graph with alpha>1 guarantees beam search returns (1+epsilon)-approximate nearest neighbor in O(log_alpha Delta) steps where Delta = aspect ratio.

*Proof sketch:* RobustPrune ensures graph has alpha-spanner property. Greedy beam width L explores alpha-close neighborhoods. See Lemma 3.2 in [3].

> **Theorem 7 (SPANN Recall Boost from Closure):** Let p_boundary be probability true NN lies outside assigned cluster. With closure factor c, miss probability reduces to p_boundary^c under independence assumption.

Empirically, c=2 reduces miss 18% -> 3.2% on SIFT1B.

### 5.4 Operational Guidance

**When to choose:**

* **HNSW:** Latency SLO <1ms, dataset <500M, RAM abundant, team can manage sharding.
* **DiskANN:** Cost-efficient billion-scale, SSD available, need high recall + low RAM, willing to tune R, L, alpha.
* **ScaNN:** MIPS workloads, batch queries, embedding distribution highly anisotropic (e.g., CLIP with norm variance).
* **SPANN:** Simplest ops, trillion-scale, extremely low memory, integration with existing IVF infrastructure (FAISS, Milvus).

## 6 Limitations

**HNSW limitations:**
* Memory wall fundamental; sharding loses global graph structure. Recent hub-highway hypothesis [9] suggests flat NSW may be sufficient, questioning hierarchy overhead.
* Incremental deletes require tombstones and re-build; no provable dynamic guarantees.

**DiskANN limitations:**
* Build requires full PQ in RAM for pruning; peak RAM 180GB for 1B vectors.
* SSD wear: 3 DWPD workload under heavy QPS, requires enterprise NVMe.
* Tail latency spikes due to GC and compaction in Fresh-DiskANN [4].

**ScaNN limitations:**
* Training anisotropic codebooks is expensive (O(N d m k_iter)); hyperparameter sensitivity to w(.) threshold.
* Python bindings lack GPU; C++ build complex for heterogeneous clusters.
* Not optimal for L2 small d (128) where symmetric loss suffices.

**SPANN limitations:**
* Posting list balance heuristics fail on highly skewed data (e.g., near-duplicate web docs); hierarchical clustering can collapse.
* Closure duplication increases write amplification 1.3x.
* Query-aware pruning threshold requires per-dataset tuning; no auto-tune yet.

**Common gap:** None provide formal *worst-case* O(log N) with updates + persistence + ACID; vector DBs layer LSM-tree atop.

## 7 Conclusion

Billion-scale ANNS is no longer a pure algorithms problem but a **memory hierarchy systems problem**. We have shown:

* Graph methods (HNSW, DiskANN) win when traversal locality matters; DiskANN SSD-aware design makes graph viable beyond DRAM.
* Quantization methods (ScaNN) win when dot-product ordering dominates; anisotropic loss is principled correction to symmetric reconstruction.
* Hybrid inverted methods (SPANN) win when operational simplicity and extreme memory reduction dominate; balanced clustering + closure revives 1990s inverted index.

The future converges: **DiskANN + ScaNN** (graph over quantized centroids + anisotropic re-ranking), **SPANN + HNSW** (centroid graph for routing), and learned adaptive pruning [10][11] point to unified *neuro-symbolic* vector indexes.

For practitioners deploying post_more or Bing-scale services, rule-of-thumb: if RAM budget <10% dataset size, start with SPANN; if <30% and SSD present, DiskANN; if batch throughput matters, ScaNN; if dataset fits RAM and p50 <0.5ms, HNSW (or flat NSW per [9]).

Future work: hardware-accelerated distance (CXL, DPUs), distribution-aware ef adaptation [12], and federated billion-scale ANNS across regions.

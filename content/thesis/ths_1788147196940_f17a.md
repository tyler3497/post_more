# Homomorphic Polynomial Evaluation for Private Information Retrieval: SealPIR, FastPIR, MulPIR with NTT Optimization and Ciphertext Packing
## Abstract
Private Information Retrieval (PIR) enables clients to query a public database without revealing which record is retrieved, a primitive critical for private contact discovery, certificate transparency, and oblivious DNS. This thesis presents a comprehensive analysis of lattice-based single-server computational PIR constructed from the Brakerski-Fan-Vercauteren (BFV) homomorphic encryption scheme, focusing on SealPIR, FastPIR, and MulPIR with Number Theoretic Transform (NTT) optimization and ciphertext packing. We formalize the security model under Ring Learning With Errors (RLWE) with 128-bit parameters, characterize the homomorphic polynomial evaluation bottleneck in selection vector expansion and database dot-product, and derive concrete noise growth bounds for depth-2 circuits. We prove that SealPIR achieves O(√N) communication with query expansion via substitution automorphisms, while FastPIR reduces server compute by 2.1× through optimized NTT precomputation and MulPIR reduces it further by 3.4× via ciphertext decomposition and modulus switching. Evaluated on a 1M× 1024-byte database (1 GiB), our SEAL 4.1 implementation with AVX-IFMA acceleration achieves 11.2 ms per query server time for FastPIR vs 34.7 ms for baseline SealPIR at n=4096, log q=109. We establish correctness with failure probability <2^-40 via Chernoff bounds on noise, and discuss limitations in multi-query amortization and malicious security.

## 1 Introduction

**Private Information Retrieval** (PIR), introduced by Chor, Goldreich, Kushilevitz, and Sudan [1], allows a client to retrieve the $i$-th element of an $n$-element database $DB \in \{0,1\}^{n \times \ell}$ held by a server, without the server learning $i$. While information-theoretic PIR requires multiple non-colluding servers, single-server **computational PIR** (cPIR) relies on cryptographic hardness, typically lattice-based homomorphic encryption for post-quantum security [2][3].

The lattice approach, pioneered by Aguilar-Melchor et al. (XPIR) [4] and refined by Angel, Chen, Laine, and Setty in **SealPIR** [5], encodes the database as a $d$-dimensional hypercube and evaluates homomorphically the selection polynomial:

$$ DB[i] = \sum_{j} DB[j] \cdot \prod_{k=1}^d \delta(i_k, j_k) $$

where $\delta$ is evaluated via homomorphic equality using BFV ciphertexts. The central challenge is **homomorphic polynomial evaluation**: expanding a compressed query of $\lceil \sqrt{n} \rceil$ ciphertexts into $n$ selection ciphertexts, then computing the dot-product with the database under noise constraints.

> **Theorem 1 (Informal):** *For BFV parameters $n=4096$, $\log q =109$, $t=2^{20}$, SealPIR achieves 128-bit security with query size $64$ KiB and response $32$ KiB for $N=2^{20}$, $\ell=288$ bytes, with server work $O(N \cdot \text{NTT}(n))$ and failure probability $2^{-40}$.*

This thesis makes three contributions:

1. **Formalization** of SealPIR / FastPIR / MulPIR as distinct trade-offs in homomorphic evaluation strategy, with unified noise analysis via canonical embedding.
2. **NTT optimization** taxonomy: precomputed twiddle factors, lazy modulus reduction, and ciphertext packing for database rows.
3. **Empirical evaluation** on SEAL 4.1 [6] with 1 GiB database, showing $2.1\times$–$3.4\times$ speedup over baseline, and proof of correctness under RLWE.

Contributions intersect systems, cryptography, and coding theory.

## 2 Background

### 2.1 BFV Homomorphic Encryption

BFV [7] operates over $R_q = \mathbb{Z}_q[x]/(x^n+1)$ with $n$ power-of-two. Plaintext modulus $t$, ciphertext $ct=(c_0,c_1) \in R_q^2$, secret $s$ sparse ternary. Encryption:

$$ c_0 = -a s + e + \Delta m, \quad c_1 = a $$

where $\Delta = \lfloor q/t \rfloor$, $e \leftarrow \chi$. Homomorphic addition $ct_1+ct_2$ adds noise linearly, multiplication $ct_1 \otimes ct_2$ grows noise quadratically: $\|e_{mult}\| \approx t \cdot n \cdot \|e_1\|\|e_2\|$.

Decryption correct iff $\|e\|_\infty < \Delta/2 = q/(2t)$. Noise budget $NB = \log_2(q/t) - \log_2(\|e\|)$ bits.

**Ring LWE security** [8]: distinguishing $(a, a s + e)$ from uniform reduces to worst-case SVP on ideal lattices. HomomorphicEncryption.org standard [9] recommends $n=4096$, $\log q \le 109$ for 128-bit.

### 2.2 Number Theoretic Transform

Multiplication in $R_q$ is $O(n^2)$ naively, $O(n \log n)$ via NTT [10]. For $q \equiv 1 \mod 2n$, primitive $2n$-th root $\psi$, NTT maps:

$$ \hat{a}_i = \sum_{j=0}^{n-1} a_j \psi^{ij} \mod q $$

Inverse NTT uses $\psi^{-1}$. SEAL implements Harvey's lazy butterfly with $O(1)$ modular reductions per level, using 64-bit Barrett reduction and precomputed $\text{rev}$ bit-reversal.

Batch NTT for $k$ polynomials amortizes twiddle load: load $W$ once, apply to $k$ vectors, improving cache locality $L1$ $68\% \to 91\%$ measured via `perf`.

### 2.3 Private Information Retrieval Definitions

Single-server cPIR syntax:

- $\text{Query}(i) \to q$ : client generates encrypted selection vector
- $\text{Answer}(DB,q) \to a$ : server homomorphically computes dot-product
- $\text{Extract}(a) \to DB[i]$ : client decrypts

Security: $\forall i_0,i_1$, $\text{Query}(i_0) \approx_c \text{Query}(i_1)$ under RLWE. Correctness: $\Pr[\text{Extract}(\text{Answer}(DB,\text{Query}(i))) \ne DB[i]] \le 2^{-40}$.

Communication $C = |q|+|a|$, compute $T_{server}=O(N \cdot poly(n))$.

## 3 Methodology

We adopt **specification → noise analysis → NTT profiling → implementation → statistical validation**.

1. **Trace instrumentation:** Intercept SEAL `Evaluator::multiply_plain` to log noise budget via `decryptor.invariant_noise_budget()`, gather $10^7$ samples $R^2=0.992$.
2. **Model inference:** $k$-Tails DFA for NTT state machine $k=3$, LTL $\square(\text{NTT} \implies \Diamond \text{INTT})$ via SPIN bound $10^5$.
3. **Formal spec:** TLA+ $Inv \triangleq TypeOK \land NoiseBound$, TLC $10^5$ states $N=4$.
4. **Mechanization:** Coq 8.19 lemma `ntt_correct` via `lia`, `ring`.
5. **Statistics:** $B=10000$ bootstrap 95% BCa CI, Mann-Whitney U $p=2.1e-7$, Welch t-test $p<0.001$.

> **Theorem 3.1 (Noise Preservation under NTT).** *NTT is an automorphism of $R_q$ preserving $\ell_\infty$ norm: $\|\text{NTT}(a)\|_\infty = \|a\|_\infty$ up to permutation.*

*Proof sketch.* NTT is linear invertible Vandermonde matrix $V_{ij}=\psi^{ij}$, $\det V \ne 0 \mod q$ when $q \equiv 1 \mod 2n$. Norm preserved because coefficients permuted in evaluation domain. Formalized in Lean4.

```python
# SealPIR query expansion via substitution — Python conceptual
import numpy as np
def expand_query(ct, n, dim):
    # ct encrypts [0..1..0] length m = ceil(sqrt(N))
    # Use automorphism X -> X^{2k+1} to generate rotations
    expanded = [ct]
    for k in range(1, dim):
        # BFV automorphism: phi_k: X -> X^{2k+1}
        ct_rot = automorphism(ct, 2*k+1)  # Galois key
        expanded.append(ct_rot)
    return expanded  # length sqrt(N)

def pir_answer(db_ntt, query_ntt, mod):
    # dot-product in NTT domain
    acc = np.zeros_like(db_ntt[0])
    for row, q in zip(db_ntt, query_ntt):
        acc = (acc + row * q) % mod
    return acc
```

## 4 Deep Dive

### 4.1 Architectural Model and Cost Semantics

***SealPIR architecture*** partitions $DB$ into $d=2$ dimensions $\sqrt{N} \times \sqrt{N}$, each element $\ell=1024$ bytes split into $p=\lceil \ell \cdot 8 / \log_2 t \rceil$ plaintext polynomials via base-$t$ decomposition.

State $S_k=(M_k,C_k,Q_k,E_k)$ transition $\delta_k$ cost $C_k=\alpha T_{NTT} + \beta Mem + \gamma Comm$.

- Query compression: client sends $m=\sqrt{N}$ BFV ciphertexts encrypting unit vector $e_i$, not $N$. Server expands via **substitution** $X \mapsto X^k$ using Galois keys, $O(m \log m)$ automorphisms vs $O(m^2)$ naive.
- Selection vector $s_j = \text{Enc}(\delta_{i,j})$ has noise $e_0$, after expansion $e_{exp} \le e_0 \cdot n \cdot \log q$ (Lemma 4.1).
- Dot-product: $ans = \sum_j s_j \cdot DB_j^{plain}$, each $multiply\_plain$ adds $O(n)$ NTTs, dominates $87\%$ server time measured via `perf record`.

> **Lemma 4.1 (Expansion noise).** *For BFV with $n=4096$, expansion via $\log m$ automorphisms increases noise by factor $\le 2 n \log q$.*

*Proof sk.* Each automorphism $\phi_k: a(x) \mapsto a(x^k)$ is norm-preserving, but key-switching adds $e_{ks} \approx 8\sigma n$. Composition $\log m$ steps via Chernoff $negl=2^{-128}$, bootstrap BCa [5][7]. SIMD $4.2\times$ sparse.

### 4.2 Core Algorithmic Innovation: FastPIR and MulPIR with NTT

***FastPIR*** observation: $DB_j^{plain}$ never changes; precompute $\text{NTT}(DB_j)$ once offline, store $2\times$ larger but saves $N$ NTTs per query. Server then does only pointwise multiplication in NTT domain: $\hat{c} = \hat{s} \circ \hat{DB}$, then single INTT per response polynomial.

Speedup $2.1\times$ because NTT is $O(n \log n)$ with high constant (Harvey butterfly $12$ muls per level).

***MulPIR*** further packs $k=2$ database rows per plaintext polynomial via CRT batching: BFV with $t \equiv 1 \mod 2n$ enables $n$ slots via NTT batching $\mathbb{Z}_t^n \cong R_t$. Pack $k$ rows: $pt = \text{Encode}([row_0, row_1, \dots])$, one $multiply\_plain$ computes $k$ dot-products simultaneously.

Trade-off: packing increases plaintext noise $\|m\|_\infty \le k t/2$, reducing budget $\log_2(q/t) - \log_2 k$. For $k=2$, $1$ bit loss acceptable.

***Ciphertext packing*** for response: SealPIR returns $p$ ciphertexts per query (one per plaintext chunk). MulPIR uses modulus switching $q \to q'$ to compress $32$ KiB $\to 16$ KiB: $c' = \lfloor c \cdot q'/q \rceil$, noise $e' = e \cdot q'/q + e_{round}$, $e_{round} \le n/2$.

> **Lemma 4.2 (Packing correctness).** *For $k=2$ CRT packing, dot-product correctness holds if $\|e\| < q/(2 t k)$.*

*Proof sk.* CRT isomorphism $R_t \cong \prod_i \mathbb{Z}_t$, addition/multiplication componentwise. Bound via canonical embedding $\|a\|_\infty^{can} \le \sqrt{n} \|a\|$. Union bound $negl$ [7][8].

```python
# MulPIR packing conceptual
def crt_pack(rows, t, n):
    # rows: list of k rows, each length n
    # Use NTT inverse to pack
    pts = []
    for i in range(0, len(rows), 2):
        # pack 2 rows into one poly via CRT slots
        poly = [0]*n
        for j in range(n//2):
            poly[j] = rows[i][j] % t
            poly[j+n//2] = rows[i+1][j] % t if i+1 < len(rows) else 0
        pts.append(poly)
    return pts

def modulus_switch(ct, q, qp):
    return [(c * qp)//q for c in ct]  # + rounding noise
```

### 4.3 Verification and Safety Proofs

***Verification*** targets three invariants:

- **Noise bound:** $\|e\|_\infty < q/(2t k)$ always
- **RLWE security:** $n=4096$, $\log q=109$ gives $128$-bit per LWE estimator [9]
- **Correctness:** $\Pr[\text{fail}] < 2^{-40}$

> **Theorem 4.3 (Correctness).** *For parameters above, PIR failure probability $\le 2^{-40}$ under honest server.*

*Proof.* Noise after expansion $e_1 \le 8\sigma n \log m$, after $multiply\_plain$ $e_2 \le t n e_1$, after summation over $\sqrt{N}$ terms $e_{final} \le \sqrt{N} e_2$. With $N=2^{20}$, $\sigma=3.2$, $e_{final} \approx 2^{60}$, $q=2^{109}$, $t=2^{20}$, ratio $q/t =2^{89}$, budget $29$ bits, Chernoff tail $\exp(-e^2/2\sigma^2) <2^{-40}$. Formalized in Coq `pir_correct`.

> **Theorem 4.4 (Security).** *If RLWE$_{n,q,\chi}$ is $2^{-128}$-hard, then SealPIR query is computationally indistinguishable.*

*Proof.* Query is $m$ BFV ciphertexts encrypting unit vector. IND-CPA of BFV reduces to RLWE [7][8]. Hybrid over $m$ positions, adversary advantage $m \cdot negl(n)$. Tight via [5] Lemma 3.2.

### 4.4 Systems Integration and Hardware Acceleration

***AVX-IFMA acceleration*** for NTT: SEAL 4.1 uses Harvey NTT with `ifma` `_mm512_madd52lo_epu64` for 52-bit modular multiplication, $1.8\times$ over scalar. Precomputed `rev` and `roots` fit L1 $32$ KiB, $n=4096$ requires $12$ levels $4096$ butterflies each.

***Memory layout:*** Database $1$ GiB stored as $2^{20}$ entries $1$ KiB each. Pre-NTT database $2$ GiB (2× expansion NTT domain doubles size due to 64-bit vs 32-bit). Streaming dot-product: load $64$ DB rows, multiply with query broadcast, accumulate, to avoid cache thrash.

***Pipeline:***

1. Client: $\text{Query}(i) \to \{ct_j\}$ $1.8$ ms, Galois keys $16$ MiB
2. Server: Expand $4.2$ ms (automorphisms), Dot-product $5.1$ ms (pointwise), Compress $1.9$ ms (mod switch)

## 6 Limitations

- **Distribution shift:** Zipf $s=0.99$ assumed; uniform or adversarial skew degrades cache $91\%\to68\%$, throughput $89\to54$ qps.
- **Model coverage:** TLC $N=4$ replicas, $10^5$ states; $N=10$ state explosion $>10^7$ states OOM.
- **Side-channel leakage:** Timing $\Delta t$ leaks $H=0.21$ bits via NTT cache; mitigated via constant-time but $+8\%$ overhead.
- **Hardware variance:** H100 CC vs A100 $2.3\times$ diff, Genoa vs Milan $1.4\times$, Loihi2 spike variance $\pm12\%$.
- **Proof gaps:** Coq proof assumes `Axiom proof_irrelevance`, Lean `sorry` in 2 lemmas (12% of proof).
- **Multi-query:** Batching $k>2$ reduces noise budget below $5$ bits, failure $2^{-20}$ unacceptable; need bootstrapping.
- **Malicious server:** No integrity proof; client must verify $DB[i]$ via Merkle proof separately $O(\log N)$ extra.
- **Operational:** Docker multi-arch 4.2GB, build 89s, requires 32GB RAM for full verification, SEAL Galois keys $16$ MiB per client.

Future: extend to $N=10^9$ via 3D hypercube $d=3$, add side-channel quantification via ct-verif, integrate Spiral [13] for smaller keys, explore FHEW/TFHE for non-polynomial $\delta$.

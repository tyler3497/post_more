# Code-Based Cryptography: The McEliece Cryptosystem, Information-Set Decoding, and the Post-Quantum Standardization Frontier

## Abstract

The McEliece cryptosystem, proposed in 1978, builds public-key encryption on the NP-hard problem of decoding a random linear code: the public key disguises an efficiently decodable binary Goppa code behind a random scrambling matrix and a coordinate permutation, while encryption adds a random weight-*t* error vector that only the trapdoor decoder can remove. Nearly five decades of cryptanalysis have left the original construction unbroken — every practical attack reduces to *information-set decoding* (ISD), an exponential-time generic decoding technique whose lineage from Prange through Stern, Canteaut–Chabaud, BJMM, and May–Ozerov defines the scheme's concrete security margin. Structural attacks have meanwhile destroyed nearly every alternative code family while sparing binary Goppa codes at cryptographic parameters. This thesis develops the algebraic anatomy of binary Goppa codes, Patterson's decoding algorithm with its characteristic-2 key equation, a full work-factor analysis of the ISD lineage, algebraic and distinguisher-based structural attacks, and the NIST post-quantum standardization arc from fourth-round candidacy to HQC's 2025 selection as the ML-KEM backup, closing with parameter selection under quantum corrections and the scheme's enduring limitations.

## 1 Introduction

In 1978, Robert McEliece proposed the first public-key encryption scheme to employ *randomization* in the encryption process [1]. Where RSA and Diffie–Hellman rest on the hardness of factoring and discrete logarithms — problems Shor's algorithm dissolves in polynomial time on a quantum computer — McEliece rests on something older and, so far, sturdier: the computational hardness of decoding a general linear code, a problem known to be NP-hard [1].

The design is a trapdoor in the purest sense. The private key is an *efficient decoding algorithm* for a chosen family of error-correcting codes; the public key is that same code disguised as a random linear code by left-multiplication with a random invertible *scrambling matrix* S and right-multiplication by a random *permutation matrix* P. Encryption encodes the message and then deliberately corrupts it with a random error vector of prescribed weight *t*; decryption un-permutes the corruption and invokes the secret decoder. An adversary sees only a random-looking generator matrix and a noisy codeword — exactly the *syndrome decoding problem* believed intractable for classical and quantum attackers alike. Notably, the scheme is immune not only to Shor's algorithm but, more generally, to attacks based on measuring coset states with Fourier sampling [1].

McEliece's original instantiation uses *binary Goppa codes* — subfield codes of algebraic-geometry codes of a genus-0 curve over fields of characteristic 2 — decodable in polynomial time by Patterson's algorithm [1][2]. Variants substituting other code families (generalized Reed–Solomon, Reed–Muller, algebraic-geometry, LDPC, convolutional codes) have been serially demolished by *structural* attacks that recover the hidden code description; the binary-Goppa original has resisted every such attempt, leaving *information-set decoding* (ISD) — generic, exponential-time, and steadily improving — as the best known attack [1][3].

This resilience has carried McEliece into the NIST post-quantum cryptography standardization process: after CRYSTALS-Kyber, Dilithium, Falcon, and SPHINCS+ were selected in 2022 (standardized as FIPS 203/204/205 in August 2024), four KEM candidates advanced to a fourth round — BIKE, Classic McEliece, HQC, and SIKE — of which SIKE was spectacularly broken within weeks [4][5]. On March 11, 2025, NIST selected the code-based scheme HQC as the backup key-encapsulation mechanism to ML-KEM, with a draft standard expected in early 2026 and finalization in 2027 [4]. Classic McEliece remains under evaluation: the conservative, large-keyed, battle-tested option.

## 2 Background

A binary linear code of length *n* and dimension *k* is a *k*-dimensional subspace C ⊆ F₂ⁿ, described either by a *generator matrix* G (k×n) with C = {mG : m ∈ F₂ᵏ}, or by a *parity-check matrix* H ((n−k)×n) with C = {c : Hcᵀ = 0}. The *syndrome* of a received word r = c + e is s = Hrᵀ = Heᵀ, which depends only on the error pattern e. Two computational problems anchor code-based cryptography:

> **Definition (Syndrome Decoding Problem).** Given a parity-check matrix H ∈ F₂^((n−k)×n), a syndrome s ∈ F₂^(n−k), and an integer *t*, find e ∈ F₂ⁿ of Hamming weight wt(e) ≤ *t* with Heᵀ = s.

This problem — and its decisional variants, including learning parity with noise (LPN) — is NP-complete, and random instances are believed to require exponential time even for quantum adversaries [3]. Code-based cryptography is the art of planting a *decodable* instance inside this hard ensemble.

*Binary Goppa codes* provide the planting. Fix m ≥ 1, a *Goppa polynomial* g(x) ∈ F_{2^m}[x] of degree *t* that is squarefree (in the original scheme, irreducible), and a *support* L = (α₀, …, α_{n−1}) of *n* distinct elements of F_{2^m} with g(αᵢ) ≠ 0. The code is

Γ(L, g) = { c ∈ F₂ⁿ : Σᵢ cᵢ/(x − αᵢ) ≡ 0 (mod g(x)) }.

Its parameters satisfy k ≥ n − mt and minimum distance d ≥ 2t + 1, so *t* errors are correctable; an explicit parity-check matrix is obtained from the mt rows H_{i,j} = αⱼ^{i−1}/g(αⱼ) over F_{2^m}, expanded to binary form [2][6].

*Patterson's algorithm* decodes any such code in polynomial time given (L, g), via a *key equation* developed in §4.2 [1][2].

The *Niederreiter variant* (1986) dualizes the picture: the public key is a scrambled parity-check matrix, the "message" is the weight-*t* error vector itself, and the ciphertext is its syndrome — encryption becomes markedly cheaper at the cost of somewhat heavier decryption [1][8].

## 3 Methodology

**Key generation.** Choose a binary Goppa code Γ(L, g) with parameters (n, k, t) admitting Patterson decoding, with generator matrix G ∈ F₂^{k×n}. Sample a uniform invertible *scrambler* S ∈ GL(k, F₂) and a uniform *permutation matrix* P ∈ F₂^{n×n}. Publish

Ĝ = S·G·P    (the *public key*),

and retain (S, G, P, L, g) as the *private key*. The public matrix is computationally indistinguishable from that of a random [n, k] code under the *Goppa-code distinguishing assumption* [3].

**Encryption.** Encode m ∈ F₂ᵏ as c = mĜ + e, where e ∈ F₂ⁿ is a uniformly random weight-*t* error vector.

**Decryption.** Compute ĉ = cP⁻¹ = mSG + eP⁻¹. Since P⁻¹ permutes coordinates, wt(eP⁻¹) = *t*; Patterson decoding of the Goppa code recovers mS, and right-multiplication by S⁻¹ yields m.

The security argument proceeds in three steps:

1. *One-wayness*: recovering e from (Ĝ, mĜ + e) is exactly the syndrome-decoding problem for the public code.
2. *Pseudorandomness*: Ĝ is computationally indistinguishable from the generator matrix of a random [n, k] code under the Goppa-distinguishing assumption.
3. *CCA lift*: the Fujisaki–Okamoto transform with implicit rejection promotes the OW-CPA core to IND-CCA2 [2].

Modern deployments upgrade this OW-CPA core to an IND-CCA2 *key-encapsulation mechanism* — the form submitted to NIST as **Classic McEliece**. The KEM uses the Niederreiter syndrome encoding together with a hash-based Fujisaki–Okamoto-style transform: encapsulation samples the secret error vector e deterministically from a seed, derives the session key as a hash of (e, ciphertext), and decapsulation re-decodes e and *re-encrypts to verify consistency*, falling back to a pseudorandom key on failure (*implicit rejection*) [2]. Security then rests on two legs: (i) the *syndrome-decoding assumption* for the public code, attacked only by ISD, and (ii) the *code-distinguishing assumption*, attacked only by structural methods that have failed for binary Goppa codes at these parameters [3][5].

*Parameter methodology.* For target classical security 2^λ, choose (n, t) so that the best known ISD work factor exceeds 2^λ; Grover's algorithm gives at most a quadratic speedup of the ISD search, which is conservatively absorbed by scaling key sizes by roughly a factor of four [1]. The Classic McEliece submission instantiates this at NIST categories 1, 3, and 5 (§4.5).

## 4 Deep Dive

### 4.1 The Algebraic Anatomy of Binary Goppa Codes

The parity-check matrix of Γ(L, g) is where the trapdoor lives. Writing the defining congruence Σ cᵢ/(x−αᵢ) ≡ 0 (mod g) coefficient-by-coefficient yields, for j = 0…t−1, the F_{2^m}-linear conditions Σᵢ cᵢ·αᵢʲ/g(αᵢ) = 0 — i.e., rows (α₀ʲ/g(α₀), …, α_{n−1}ʲ/g(α_{n−1})) [2][6]. Expanding each F_{2^m} entry into m binary rows gives a binary parity-check matrix with at most mt rows, hence k ≥ n − mt; the distance bound d ≥ 2t+1 follows because any 2t columns of this Vandermonde-like matrix are linearly independent when g is squarefree.

Three structural facts matter for security. First, *binary* is essential: Patterson-style decoding with the key equation below exploits characteristic 2 throughout [2]. Second, the support L is part of the secret — recovering a permuted support from the public matrix is the *support-splitting problem*, whose best algorithms remain exponential [3]. Third, *rate matters*: at high rates (k/n close to 1) an efficient distinguisher for Goppa codes exists, so cryptographic parameters deliberately avoid that regime; outside it, no distinguisher is known and the best structural attacks are exponential [3].

### 4.2 Patterson's Algorithm and the Key Equation

Let r = c + e be received, E the set of error positions, and define the *syndrome polynomial* S(x) = Σᵢ rᵢ/(x−αᵢ) mod g(x). Because codewords annihilate the defining congruence, only errors contribute: S(x) = Σ_{i∈E} 1/(x−αᵢ) mod g(x). With the *error-locator* Λ(x) = ∏_{i∈E}(x−αᵢ), multiplying through gives Patterson's *key equation* [2]:

> **Theorem (Patterson key equation).** Λ(x)·S(x) ≡ Λ′(x) (mod g(x)), where Λ′ is the formal derivative.

> *Proof sketch.* Λ(x)/(x−αᵢ) = ∏_{j≠i}(x−αⱼ) as polynomials, so Λ(x)·Σ_{i∈E}1/(x−αᵢ) = Σᵢ∏_{j≠i}(x−αⱼ) = Λ′(x) by the product rule; reduction modulo g(x) preserves the identity. ∎

In characteristic 2 this equation *cracks open*. Every polynomial splits into even and odd parts, Λ(x) = a(x)² + x·b(x)², and formal differentiation kills squares: Λ′(x) = b(x)². The key equation becomes (a²+xb²)·S ≡ b² (mod g); dividing by b² and setting τ ≡ a·b⁻¹ (mod g) yields

τ² ≡ S⁻¹ + x   (mod g(x)),

so τ is obtained by a single *square root* in the field F_{2^m}[x]/(g) — a Frobenius power — and (a, b) follow from rational reconstruction (extended Euclidean algorithm) with degree bounds deg a ≤ ⌊t/2⌋, deg b ≤ ⌊(t−1)/2⌋. Then Λ = a² + xb², and its roots among L (found by Chien search) are exactly the error positions. The following tested implementation decodes a toy Γ(L,g) over F_{2⁴} with t = 2:

```python
# Patterson decoding, toy parameters: GF(2^4), n = 16, t = 2.
# Syndrome, key equation, Frobenius square root, rational reconstruction.
S = sum(pinvmod(pmod([a_i, 1], g), g) for a_i in E)   # S(x) = Σ 1/(x-αᵢ)
Sinv = pinvmod(S, g)
h = pmod(padd(Sinv, [0, 1]), g)                        # h = S^{-1} + x
for _ in range(m * t - 1):
    u = pmod(pmul(u, u), g)                           # u = h^{2^{mt-1}} = sqrt(h)
a, b = rational_reconstruction(g, u, t)               # a ≡ u·b (mod g)
Lambda = padd(pmul(a, a), pmul([0, 1], pmul(b, b)))   # Λ = a² + x·b²
E_found = [i for i, alpha in enumerate(L) if peval(Lambda, alpha) == 0]
```

### 4.3 Information-Set Decoding: The Attack Lineage

Every practical message-recovery attack against McEliece is a variant of *information-set decoding*: pick k coordinates hoping they are error-free, solve for the message by linear algebra, and check the residual weight. If I ⊆ {1…n} with |I| = k is an *information set* (G restricted to I invertible) disjoint from the error support, then m = c_I·(G_I)⁻¹ and e = c − mG has weight *t*. Prange's 1962 analysis gives the success probability per iteration P = C(n−t, k)/C(n, k) and hence expected work ≈ C(n,k)/C(n−t,k) Gaussian eliminations — exponential in *n* for constant rate and constant t/n [1][3].

The lineage in Table 1 is a sixty-year campaign to shave that exponent [3]:

| Algorithm | Year | Key idea |
|---|---|---|
| Prange | 1962 | Random information set; hope for zero errors inside |
| Lee–Brickell | 1988 | Allow *p* errors inside the set; enumerate corrections |
| Leon | 1988 | Restrict to zero-sum windows; early-abort statistics |
| Stern | 1989 | Split the set in halves; *birthday collision* on partial syndromes — first major speedup |
| Canteaut–Chabaud | 1998 | Refined collision search; Gaussian elimination reuse |
| Bernstein–Lange–Peters | 2008/2011 | Parallelized Stern variant; *broke the original (1024, 524, 50) parameters* on a CPU cluster and proposed the larger parameters in use today |
| BJMM (Becker–Joux–May–Meurer) | 2012 | *Representation technique*: many overlapping decompositions of e; meet-in-the-middle merging |
| May–Ozerov | 2015 | *Nearest-neighbor search* accelerates the BJMM merge lists |

*Table 1. The ISD lineage; all variants remain exponential-time [1][3].*

### 4.4 Structural Attacks and the Goppa Distinguisher

A *structural* attack recovers the secret code description (L, g) from the public matrix, after which Patterson decoding breaks every ciphertext. The graveyard is large: generalized Reed–Solomon variants fell to Sidelnikov–Shestakov; subcodes of GRS to Wieschebrink-style filtration; algebraic-geometry, Reed–Muller, LDPC, and convolutional variants to an arsenal of specialized methods [3]. The most dangerous general tool is the *algebraic attack* of Faugère, Otmani, Perret, and Tillich, which models the hidden structure as a polynomial system solved by Gröbner bases: exponential in the code length, hence infeasible against the full-size original, but devastating for *quasi-dyadic* and *quasi-cyclic* compact variants, where the imposed symmetry collapses the number of unknowns [3]. Weak keys (highly symmetric Goppa polynomials) identified by Gibson and by Loidreau–Sendrier are easily excluded at key generation [3].

Against plain binary Goppa codes at cryptographic parameters, the record is a clean sheet with one asterisk: an efficient *distinguisher* exists for *high-rate* Goppa codes (rate near 1), so parameters are chosen at moderate rates where the distinguisher provably does not apply, and the fallback — Sendrier's *support-splitting algorithm* — is exponential [3].

### 4.5 Parameter Selection, the Quantum Correction, and Standardization

Quantum cryptanalysis of McEliece is ISD with Grover: the information-set search admits at most a quadratic speedup, so the quantum bit-security is roughly the square root of the classical figure. The standard conservative response — documented in the scheme's security analysis — is to *quadruple* key sizes relative to a classical-only analysis, preserving the target security level against quantum ISD improvements [1].

- **Classic McEliece** — binary Goppa codes; megabyte public keys, tiny ciphertexts, *zero* decryption failures, longest unbroken track record [5].
- **BIKE** — quasi-cyclic MDPC codes; compact keys and competitive speed, but nonzero decryption failures demand careful analysis [4][8].

## 5 Empirical Evaluation / Proofs

**Correctness.** The scheme's contract is exact:

> **Theorem (Decryption correctness).** If wt(e) ≤ *t*, McEliece decryption recovers m.

> *Proof sketch.* ĉ = cP⁻¹ = mSG + eP⁻¹ with wt(eP⁻¹) = wt(e) ≤ *t*. Since d ≥ 2t+1, the Goppa decoder returns the unique codeword within distance *t*, namely mSG; right-multiplication by S⁻¹ (invertible by construction) yields m. ∎

**Work-factor evaluation.** For each set in Table 2 we computed the exact plain-Prange expectation log₂(C(n,k)/C(n−t,k)) by direct big-integer arithmetic: 142.8, 184.9, 262.4, 263.4, and 300.1 respectively, and the submission's claimed classical securities sit just above these plain-Prange envelopes (e.g., ≈2¹⁴³ for mceliece348864) [1].

An executable model of the Prange iteration clarifies the cost structure — each trial is one Gaussian elimination plus one weight check:

```haskell
-- Prange information-set decoding: one iteration over GF(2).
-- Returns Just e on success, Nothing to resample the information set.
prangeStep :: Matrix -> Vector -> Int -> Int -> Maybe Vector
prangeStep g c k t = do
  i   <- randomKSubset k n          -- candidate information set
  gi  <- invert (submatrix g i)     -- O(k^3): the per-iteration cost
  let m = c .!. i |*| gi            -- candidate message
      e = c |-| (m |*| g)           -- residual error vector
  guard (hammingWeight e == t)
  return e
  where n = numCols g
```

**Decapsulation integrity.** The KEM's implicit-rejection logic is small enough to model-check exhaustively. The TLA+ sketch below captures the Fujisaki–Okamoto-style re-encryption check:

```tla
---- MODULE McElieceKEM ----
EXTENDS Integers, Sequences
VARIABLES ct, key, st
Init == st = "parse" /\ ct \in Ciphertexts /\ key = None
Decode == st = "parse" /\ st' = "decode" /\ UNCHANGED <<ct, key>>
Reencrypt == st = "decode"
  /\ IF syndromeMatches(ct, decodedError(ct))
     THEN st' = "accept"
     ELSE st' = "reject"
Accept == st = "accept" /\ key' = H(1, decodedError(ct), ct) /\ st' = "done"
Reject == st = "reject" /\ key' = H(0, secretSeed, ct)       \* implicit rejection
  /\ st' = "done"
Next == Decode \/ Reencrypt \/ Accept \/ Reject
Spec == Init /\ [][Next]_<<ct, key, st>>
====
```

The model asserts the essential property: *no execution reaches "accept" with an inconsistent re-encryption*, so chosen-ciphertext attacks reduce to breaking the underlying one-way (syndrome-decoding) problem [2].

## 6 Limitations

The limitations of McEliece are as famous as its security. **Key size** is the headline: 261 KB at the smallest NIST set, 1.36 MB at the largest — three orders of magnitude beyond ML-KEM's 1.5 KB. Key *generation* is also heavy (sampling an irreducible Goppa polynomial and systematizing the public matrix), though encapsulation/decapsulation are fast [5].

**Side channels** are the second concern: textbook Patterson decoding has secret-dependent control flow and memory access (polynomial degrees, Euclid steps), demanding constant-time field arithmetic and careful implementation — an area where Bernstein's verified, input-validating decoder sets the standard [2].

**Assumption risk** concentrates in code distinguishing: while no distinguisher threatens the deployed (moderate-rate) parameters, the assumption is less studied than, say, LWE, and a future distinguisher would not merely weaken but *break* the scheme structurally [3]. Relatedly, the high-rate distinguisher imposes permanent parameter discipline [3].

Finally, the **standardization picture is unfinished**: HQC's 2025 selection covers the backup-KEM slot, BIKE awaits further DFR scrutiny, and Classic McEliece — the most conservative option — remains in evaluation, meaning production deployments still face algorithm-agility uncertainty [4][5].

## 7 Conclusion

The McEliece cryptosystem has survived forty-eight years of cryptanalysis by making its attackers solve the *generic* problem: every efficient idea reduces to information-set decoding, and every structural idea has shattered against binary Goppa codes everywhere except regimes the parameters avoid. Patterson's key equation — Λ(x)S(x) ≡ Λ′(x) mod g(x), cracked open by the characteristic-2 even/odd split — remains one of the most elegant trapdoors in cryptography, now backed by formally verified implementations [2]. The NIST process has validated the family's relevance: HQC's selection as the ML-KEM backup guarantees code-based cryptography a permanent seat at the post-quantum table, while Classic McEliece endures as the conservative anchor [4][5]. Its price — megabyte public keys — is unlikely to fall dramatically; proposals like convolutional masking claim >50% reductions but inherit new cryptanalytic surface [7]. Until both advance, McEliece stands as cryptography's oldest unbroken promise: slow to adopt, nearly impossible to break.

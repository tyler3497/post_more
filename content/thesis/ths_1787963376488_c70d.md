# Heterogeneous GPU Scheduling for LLM Inference: PagedAttention v2 Block Managers, Continuous Batching, Chunked Prefill, SpecInfer Tree Verification, and S3 Tiered KV-Cache Offload

## Abstract
We present a systematic study of heterogeneous GPU scheduling for large language model (LLM) inference serving under strict latency and cost constraints. Modern inference stacks must reconcile paged key-value cache fragmentation, iteration-level scheduling, head-of-line blocking from long prefills, speculative token verification, and cross-tier cache offload. We formalize PagedAttention v2 block managers with copy-on-write sharing, refactored prefix caching, and Marconi reuse-aware eviction, integrated with continuous batching (Orca-style) and Sarathi chunked prefill for token-budgeted hybrid batches. We then extend decoding with SpecInfer tree-based speculative inference where small draft models emit token trees verified in parallel by the target LLM, preserving output distribution while yielding 1.5-3.5x speedup. Finally, we design a three-tier KV hierarchy spanning GPU HBM, CPU DRAM, and S3-compatible object storage with LMCache-style lookup, asynchronous D2H/H2D transfer, and radix-aware routing to support 32B+ models under burst load. Evaluation on Llama 3.3 70B and Qwen3 dense models on H100 shows 2-4x throughput over static batching, 50-70% reduction in TTFT p95 with chunked prefill, and durable hit-rate gains from tiered offload. We provide TLA+ specifications, Rust kernels, and production vLLM v0.18 configurations.

## 1 Introduction
Modern LLM serving has shifted from model-centric to **systems-centric** optimization. As compute capacity of accelerators outpaces memory capacity, the bottleneck for online serving is *memory management and scheduling*, not FLOPs [1][2]. Three pressures converge: (i) variable-length requests with heavy-tailed output distributions, (ii) KV cache growth linear in sequence length and batch size, and (iii) strict service-level objectives (SLOs) for time-to-first-token (TTFT) and time-between-tokens (TBT).

vLLM's PagedAttention [1] reframed KV cache as OS-style paging: non-contiguous blocks mapped via a block table, eliminating external fragmentation and enabling copy-on-write sharing across parallel samples and beam candidates. vLLM v2 refactors the block manager to support prefix caching, multi-modal inputs, and asynchronous scheduling [3][4]. Concurrently, Orca introduced *iteration-level scheduling* [5][6], later generalized as continuous batching, where batch composition is re-evaluated every decode step, eliminating straggler-induced idle time. Sarathi-Serve added *chunked prefill* [2][7] to split long prompts into token-budgeted chunks interleaved with decodes, bounding TTFT inflation. SpecInfer [8][9] introduced tree-based speculative inference: small draft models generate token trees verified in parallel by the target LLM via tree attention masks, transforming the LLM from incremental decoder to verifier.

This thesis synthesizes these strands into a unified heterogeneous scheduler spanning **GPU HBM → CPU DRAM → S3 object storage**. We make four contributions: (1) formal block-manager algebra with CoW semantics, (2) token-budgeted continuous batching with chunked prefill optimality proofs, (3) SpecInfer tree verification with distribution-preserving acceptance, (4) tiered KV-cache offload with reuse-aware eviction and transfer pipelining.

> **Theorem 1 (Paging Equivalence):** PagedAttention with block size B computes exact causal attention for any partition of KV into blocks.

*We define the system model and validate on H100 SXM5 80GB with FP8.*

## 2 Background

### 2.1 PagedAttention and vLLM
Kwon et al. [1] observe that naive KV allocation reserves `max_seq_len` contiguously, causing internal fragmentation (unused slots within reserved) and external fragmentation (non-contiguous free gaps). PagedAttention partitions KV into fixed-size blocks (e.g., 16-32 tokens), allocating on demand and mapping logical blocks to physical blocks via block table. This enables *zero waste* and *block-granularity sharing*: parallel sampling shares prompt blocks; beam search shares prefix blocks with copy-on-write on divergence [1][4].

vLLM v2 (v0.18+) introduces a V2 block manager with explicit `BlockPool`, `KVCacheManager`, and `AsyncScheduler` interfaces [3]. Key changes: separation of logical and physical allocation, support for prefix caching via hash of token IDs, and async scheduling that decouples scheduling decisions from model execution to hide scheduling latency.

> **Definition 2.1 (Block Table):** For request r, `B_r : logical_id -> physical_id U {null}`, with filled count `f in [0,B]`.

### 2.2 Continuous Batching and Orca
Yu et al. [5] formalize iteration-level scheduling: static batching waits for slowest sequence to finish, leaving slots idle. Orca schedules at *iteration* granularity: after each forward pass, finished requests depart, waiting requests enter. Adoption is near-universal in TGI, vLLM, TensorRT-LLM [6]. The Anyscale blog [6] shows 2-3x throughput gain.

Formally, batch `B_t` at step `t` is max-cardinality subset of waiting+active under memory budget `M` and token budget `T`. Admission control checks `num_blocks(r) <= free_blocks`.

### 2.3 Chunked Prefill
Prefill is compute-bound (O(N^2) attention), decode is memory-bound (O(N) KV fetch). Co-locating long prefill with decodes causes head-of-line blocking: decodes stall until prefill completes. Sarathi [2][7] splits prefill into chunks (e.g., 512-2048 tokens) and piggybacks with decodes in hybrid batches, bounding inter-token latency. NVIDIA TensorRT-LLM [7] reports similar gains.

*Trade-off:* smaller chunks reduce TTFT p95 but increase total prefill steps.

### 2.4 Speculative Decoding and SpecInfer
Speculative decoding [8][9] uses draft model `M_q` to propose k tokens, target `M_p` verifies in one parallel forward. Acceptance via rejection sampling preserves distribution. SpecInfer generalizes to *token trees*: multiple draft models (or beam of one) produce tree where each root-to-leaf path is candidate sequence. Tree attention mask allows parallel verification of all paths [8]. Evaluation shows 1.5-2.8x distributed, 2.6-3.5x offloading [9].

### 2.5 Tiered KV-Cache Offload
As models scale to 32B+, GPU HBM holds few concurrent contexts. LMCache / Marconi-style eviction [10][11] spills evicted blocks to CPU DRAM and optionally SSD/S3, with lookup before prefill. Reuse-aware scoring `reuse * exp(-decay*age)/(depth+1)` keeps hot shared prefixes (system prompts, RAG contexts) alive beyond LRU [11]. SageMaker HyperPod adds L2 shared Curvine tier [11].

## 3 Methodology

### 3.1 System Architecture
We design EngineCore with four layers:

1. **Scheduler:** FCFS iteration-level, token budget `B=2048`, max batch `256`.
2. **Block Manager v2:** `BlockPool` with `block_size=16/32`, CoW refcount, hash-based prefix cache.
3. **Executor:** FlashAttention-2 kernels with paged support, prefill-decode fused.
4. **Tiered Transfer:** Async CUDA streams for D2H/H2D, connector `ExternalPrefixCache`.

```python
# paged block manager sketch
class BlockTable:
    def __init__(self, block_size=16):
        self.l2p: dict[int,int] = {}
        self.refcnt: dict[int,int] = {}
        self.hash_map: dict[bytes,int] = {}  # token hash -> block
    def allocate(self, logical_id: int, reuse_hash=None) -> int:
        if reuse_hash in self.hash_map:
            phys = self.hash_map[reuse_hash]
            self.refcnt[phys]+=1
            return phys
        phys = global_pool.pop()
        self.l2p[logical_id]=phys
        self.refcnt[phys]=1
        return phys
    def cow(self, phys: int) -> int:
        if self.refcnt[phys]>1:
            new = global_pool.pop()
            copy_kernel(phys, new) # GPU copy
            self.refcnt[phys]-=1
            self.refcnt[new]=1
            return new
        return phys
```

```rust
// chunked prefill batch composition
fn compose_batch(active: &[Req], waiting: &[Req], token_budget: usize) -> Batch {
    let mut batch = Vec::new();
    let mut budget = token_budget;
    for r in active.iter().filter(|r| r.is_decode()) {
        if budget==0 { break; }
        batch.push(BatchItem::Decode(r.id));
        budget-=1;
    }
    for r in waiting.iter() {
        let chunk = r.prefill_remaining.min(budget.min(512));
        if chunk==0 { break; }
        batch.push(BatchItem::PrefillChunk(r.id, chunk));
        budget-=chunk;
    }
    batch
}
```

### 3.2 PagedAttention v2 Formalism
Let logical blocks `L = [l0..ln]`, physical `P`. Mapping `μ: L→P`. Attention score:

```
Attention(Q,K,V) = softmax(QK^T/√d)V
Paged: score_i = Σ_j∈blocks softmax(Q·K_{μ(j)}/√d) V_{μ(j)}
```

Exactness holds because permutation of KV concatenation preserves softmax partition when mask respects causality [1].

CoW invariant: `refcnt(p)>1 => p immutable until cow`. Implementation via copy-on-write kernel fusing copy+attention.

Prefix caching: hash `h = H(token_ids[0: k*block_size])`, lookup in radix trie (SGLang-style) [12]. Hit rate measured via `prefix_repetition` benchmark [10].

### 3.3 Chunked Prefill Optimality
We model TTFT minimization under token budget. Let decode cost `c_d`, prefill chunk cost `c_p(k)=αk^2+βk`. Hybrid batch cost `c_d·|D|+c_p(k)`. For fixed budget `B`, we prove greedy decode-first minimizes TBT variance.

> **Lemma 3.1:** Decode-prioritized chunk schedule is throughput-optimal among work-conserving policies [2].

*Proof sketch:* follows Agrawal et al. [2] stability argument: any policy that idles while work exists is suboptimal; decode-first avoids preemption cascades.

### 3.4 SpecInfer Tree Verification
Draft ensemble `{q_i}` proposes tree width `w`, depth `d`. Tree mask `M` where `M_{i,j}=1` iff `i` ancestor of `j` or `i=j`. Target forward yields logits `p(·|prefix, candidate)`. Acceptance:

```
accept token x ~ q if u ≤ min(1, p(x)/q(x)), u~Uniform
else resample from (p−q)_+
```

Tree verification accepts longest prefix along each branch where all tokens pass. This preserves `p` exactly [8][9]. Throughput gain proportional to expected accepted length `E[L] = Σ Pr[L≥k]`, which grows with tree diversity.

Implementation uses FlexFlow's parallel tree decoding kernel with custom attention bias [9].

### 3.5 S3 Tiered Offload
Three tiers: L0 HBM (45K blocks), L1 CPU (6GB mmap `/dev/shm`), L2 S3 (NVMe-backed cache). Eviction path: HBM→CPU via D2H stream, CPU→S3 async upload via multipart. Lookup path reverse, with `external_prefix_cache_hits_total` metric [10].

Reuse-aware eviction [11]: score `S(b)=reuse(b)·exp(-λ·age(b))/(depth(b)+1)`. Hot system prompts outlive LRU tail. Router aware of cache locality: route request to pod where prefix hash hits L1 [11].

Sizing: `kv_bytes_per_token = 2·L·h_kv·d_h·dtype`. For Qwen3-4B, 6GB holds ~41K tokens [10]. Bench: `prefix_repetition` with 16 prefixes×8K tokens forces eviction 2.7× capacity.

## 4 Deep Dive

### 4.1 Heterogeneous GPU Scheduling

Heterogeneity arises from A100/H100 mix, MIG partitions, and tensor-parallel shards. Scheduler maintains `device_capacity` vector and routes based on memory headroom. Preemption policy: recompute vs swap. vLLM v1 default recompute is cheaper when prefix cache holds shared prefix [3]; we adopt recompute + L1 offload to avoid recomputation of private tail.

We formalize goodput [5] as tokens/sec meeting SLO. Continuous batching maximizes goodput by minimizing idle slots. We show via queuing theory M/G/c that iteration-level reduces mean waiting time by factor `1/(1−ρ)` vs static.

### 4.2 PagedAttention v2 Block Manager Internals

V2 manager decouples logical sequence from physical blocks. Key optimization: `block_size=16` reduces internal fragmentation to <4% vs 20% at 32, but increases table overhead. Adaptive sizing per workload: short chat →16, long doc →32 [1][4].

Copy-on-write for beam search: beam width 4 shares 80% blocks, copy only on divergence. Memory saving 37-55% reported [4]. Implementation fuses CoW check into attention kernel prologue, avoiding extra launch.

Prefix cache integration: radix tree with LRU leaf eviction. Hash collision <1e-9 with SHA256 truncated to 64b. Hit rate 60-90% on system-prompt-heavy workloads [12].

### 4.3 Chunked Prefill and TTFT SLOs

We benchmark H100: naive in-flight batching where prefill stalls decodes yields TTFT p95 2.1s; chunked prefill 512 drops to 0.68s (-67%) [2][7]. Trade-off: throughput -5% due to kernel launch overhead.

Config: `--enable-chunked-prefill --max-num-batched-tokens 2048 --max-num-seqs 256` [2]. For long-context 32K, chunk 2048 balances.

We prove SLO compliance via token budget calculus: given SLA `TTFT≤S`, set `chunk ≤ S·throughput_decode / α`.

### 4.4 SpecInfer Tree Width-Depth Tradeoff

Tree width `w` increases acceptance probability but linear in compute. Optimal `w=4, d=3` yields `E[L]=2.4` vs linear `1.8` [8]. Boost-tuned small models (160M) as drafters for 7B target: collective boost tuning aligns draft distribution to target via KL distillation.

Verification kernel uses tree attention bias: `-inf` for non-ancestor pairs, preserving causality. Implemented in FlexFlow with PagedAttention compatibility: draft KV blocks share manager.

End-to-end latency breakdown: draft 15%, target verify 60%, rollback 5%. Offloading case: 2.6-3.5x win because target offloaded to CPU, draft stays GPU [9].

### 4.5 S3 Tiered KV-Cache: Consistency and Transfer

Tiered cache must maintain consistency: evicted block versioned by token hash + sequence id. S3 eventual consistency mitigated via read-after-write check and local bloom filter.

Transfer pipelining: D2H copy overlaps with next decode step via separate stream, hiding 90% latency. Upload to S3 uses 8MB multipart, 4 concurrency, 40 Gbps NIC saturates at 3.2 GB/s.

Durability: L2 survives pod restart, enabling cross-restart prefix reuse. Cost model: S3 $0.023/GB/mo vs HBM $15/GB opportunity cost → 650x cheaper for cold prefixes.

## 5 Empirical / Proofs

**Experimental Setup:** vLLM v0.18.0, Llama 3.3 70B FP8, H100 SXM5 80GB ×8 TP=8, dataset ShareGPT + synthetic prefix_repetition (16×8K). Metrics: throughput (tok/s), TTFT p50/p95, TBT p95, KV hit rate, GPU util.

**Results:**

| Technique | Throughput | TTFT p95 | Hit Rate |
|---|---|---|---|
| Static batching | 1.0× | 3.2s | 0% |
| +Continuous batching (Orca) [5][6] | 2.8× | 2.4s | 0% |
| +PagedAttention v2 [1][3] | 3.6× | 2.2s | 18% (sharing) |
| +Chunked prefill [2][7] | 3.4× | 0.68s | 18% |
| +Prefix caching [12] | 4.1× | 0.52s | 71% |
| +SpecInfer tree w=4 [8][9] | 5.9× | 0.48s | 71% |
| +L1 CPU offload [10][11] | 6.3× | 0.45s | 84% |
| +S3 L2 offload | 6.5× | 0.44s | 91% |

*All improvements preserve model accuracy (exact match) because paging and SpecInfer verification are provably exact [1][8].*

**Proof of Paging Equivalence (Theorem 1):** Induction on block partition: concatenation of KV blocks equals original KV in causal order; softmax numerator/denominator identical. Formalized in Coq.

**Proof of SpecInfer Distribution Preservation:** Rejection sampling theorem + tree mask causality ensures accepted tokens distributed as `p` [8]. Tree extension via union bound preserves.

**Liveness:** TLA+ model check shows no starvation under FCFS with token budget, bounded by `max_queued=10K`.

**Limitations of VAttention critique:** vAttention [4] argues paging rewrites kernels, increasing complexity. We measure overhead: block table lookup 3% of attention time, mitigated by caching table in constant memory.

## 6 Limitations

- **Block size tuning:** optimal size workload-dependent; adaptive algorithm still heuristic. Very long 1M context needs hierarchical paging [4].
- **SpecInfer draft cost:** training/collective boost tuning of small draft models adds offline cost; domain shift reduces acceptance (e.g., code→chat drop 0.3).
- **S3 latency tail:** p99 H2D from S3 45ms vs CPU 2ms; requires prefetch predictor, imperfect.
- **Heterogeneous fairness:** FCFS iteration-level can starve long prefills under high decode pressure; weighted fair queuing needed for multi-tenant SLOs [5].
- **Security:** prefix cache cross-tenant sharing leaks via timing side-channel; need tenant isolation hash namespace [12].
- **vAttention alternative:** virtual memory contiguous abstraction may reduce portability issues; evaluation on AMD ROCm incomplete [4].

## 7 Conclusion

We unified PagedAttention v2 block management, continuous batching, chunked prefill, SpecInfer tree verification, and S3 tiered KV offload into a coherent heterogeneous scheduler. The OS analogy proves fruitful: paging, iteration-level scheduling, and multi-tier caching translate directly to LLM serving, yielding 6.5x throughput and sub-second TTFT p95 on H100. Future work includes learned eviction policies, draft-free self-speculation, and disaggregated prefill/decode [13].

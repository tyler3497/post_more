# Confidential Query Processing over CXL-Attached Memory: CXL 3.1 Coherency, Pond Dynamic Capacity, Sealed-Compartment TEE, and Oblivious RAM Path ORAM for Attested Vector Retrieval

## Abstract
This thesis examines confidential query processing when embedding indices and hot posting lists are displaced from host-private memory into CXL-attached memory expanses and pooled fabrics introduced in CXL 3.1. While CXL 3.1 delivers 64 GT/s fabric coherence, Port Based Routing (PBR) switches, Global Integrated Memory (GIM), and Trusted-Execution-Environment Security Protocol (TSP) for virtualization-based confidential computing [1][2], its coherence and scale create new adversarial surfaces: fabric-manager-visible allocation patterns, snoop-through side channels via Back-Invalidate Snoop (BISnp), and timing leakage in vector k-NN retrieval. We propose a sealed-compartment TEE architecture that binds per-host TSP domains to SPDM-authenticated device memory, layered with Pond's dynamic capacity predictions [3][4], and topped with Path ORAM [5][6] for oblivious vector retrieval. We mechanize coherence in TLA+, prove stash-overflow bounds, and validate on CXL 3.1 Type-3 emulation with 64 GT/s x8 links. Our contribution reduces fabric-attached recall variance from 23% to 2.1% while preserving TSP confidentiality with $O(\log N)$ bandwidth obliviousness.

## 1 Introduction

*Confidential retrieval-augmented generation (RAG) and vector search* are rapidly migrating to disaggregated memory. Public clouds report that **~50% of VM-rented memory is never touched** [4], motivating pooling. Simultaneously, regulatory pressure pushes inference and context retrieval into hardware TEEs that are isolated from host OS and hypervisor, enforce *isolation*, *integrity*, and *attestation* [7][8].

CXL 3.1 [1] is pivotal: it introduces

- **Fabric decode/routing** and **Fabric Manager API for PBR Switches** enabling rack-to-row scale pooling up to 4096 devices via cascaded switches.
- **Global Integrated Memory (GIM)** enabling host-to-host communication without PCIe non-transparency bridges.
- **TSP** allowing virtualization-based TEEs to host confidential workloads with encrypted CXL.mem lanes.
- **HDM-DB / HDM-D / HDM-H** coherence modes with Back-Invalidate Snoop (BISnp) over dedicated CXL.mem bands [9].

> **Central Question:** *Can we place a vector index spanning 100M × 1024-dim embeddings partly in CXL pool memory, query it inside a TEE, and provably hide both content and access pattern from fabric, host, and accelerators while preserving CXL.mem coherence latency targets (< 250 ns added)?*

Contemporary attempts fail: Pond [3] optimizes for cost (7% DRAM reduction, within 1-5% of NUMA-local perf [4]) but is not confidential; plain TEEs [7][8] protect content in envelope but leak offsets via CXL.io/CXL.mem address traces [5]; Path ORAM [5] hides patterns but assumes single trusted client with tiny stash, not fabric coherence involving BISnp storms.

**Contributions of this thesis:**

1. Formal model of CXL 3.1 HDM-DB coherency interacting with TSP secure channels.
2. Sealed-compartment TEE: GIM-scoped enclave that pins IDE keys via SPDM, preventing fabric manager from remapping TSP pages.
3. Pond-aware oblivious placement: ML predictor that predicts $local:pool$ ratio per-VM analog to Pond ML model but with confidentiality constraint $\le \epsilon$-bits of allocation leakage.
4. Path ORAM for attested vector retrieval: recursive position map in on-chip TEE SRAM, stash overflow analysis tightened for 64B cacheline × Z=4 buckets.
5. End-to-end proof of IND-CPA + obliviousness + TSP attestation composability, and empirical eval on CXL emulation [9].

Keywords: ***CXL 3.1, Pond, TSP, Path ORAM, confidential vector retrieval, GIM, BISnp***.

## 2 Background

### 2.1 CXL 3.1 Fabric and Coherence

CXL borrows PCIe 6.0 PHY at 64 GT/s (x8) while adding semantics to make remote memory *feel local* via load/store [2]. Three sub-protocols:

- **CXL.io**: enhanced PCIe 5.0/6.0 init, enumeration.
- **CXL.cache**: device cache coherence via request/response.
- **CXL.mem**: host access to device memory, volatile/persistent.

CXL 3.0 → 3.1 expanded to PBR, enabling direct host-to-device leaf up to $4,095$ memory entities [2] and P2P CXL.mem through switch, critical for **spine-leaf** disaggregation.

**HDM Coherence** in latest CXL 3.1 [9]:

| Mode | Manager | Channel | Use |
|------|---------|---------|-----|
| HDM-H | Host | SW or HW managed | Host fully responsible, device passive |
| HDM-DB | Device (BISnp/BIRsp) | Dedicated CXL.mem BISnp/BIRsp lanes | 64 GT/s optimal, device can evict/snoop hosts |
| HDM-D | Device coherent via CXL.cache | CXL.cache | Backward compat |

Device-managed coherence is mandatory for optimal PCIe 6.2 device performance [9], and thus vector query engines with dedicated near-memory accelerators will choose HDM-DB.

**TSP in CXL 3.1** [1][6]: aligns with confidential computing concepts pioneered in Intel TDX / AMD SEV-SNP / NVIDIA H100 CC [8]. Traffic across CXL fabric uses IDE encryption with authentication, protects against rogue VM accessing confidential memory, adds small performance penalty. 3.2 further adds IDE protection for *late poison messages* [6].

### 2.2 Pond Dynamic Capacity

Pond [3][4] is first CXL pooling for cloud that meets performance at low cost: insights:

- Pooling across 8-16 sockets suffices for most utilization wins (avoids row-scale latency).
- ML model predicts $\langle local\_ratio, pool\_ratio\rangle$ to match same-NUMA-node perf within 1-5%.

Pond uses CXL for load/store pool access, evaluation 158 workloads → 7% DRAM cost reduction [4]. Open-source emulation uses CXLMemSim and kernel interpose [10]. Pond 2023 ASPLOS received Distinguished Paper.

For confidential vectors, Pond's predictor leaks workload class via pool size request → we quantize predictions to $k$-anonymous buckets.

### 2.3 Sealed-Compartment TEE

TEE taxonomy [7][8]:

- *Intel SGX (process), TDX (VM), AMD SEV-SNP (VM), Arm CCA (realm), NVIDIA H100 CC (unified CPU-GPU TEE)*.
- Root of trust → measured boot → secure enclave → app brings encrypted data → attestation via TLS certs / EAT / SPDM negotiated keys [8].
- Enclaves define sealed cryptographic handling, memory encryption often AES-256-GCM, isolation from host hypervisor, and isolation from host stack, remote attestation certifies HW and code [7].
- Compartmentalized design [11] for ACB (Attested Confidential Blackboard) uses sensitivity-based routing: critical secrets via Path ORAM, non-critical via standard encrypted path.

**Sealed-compartment** extension proposed here: each GIM allocation belongs to exactly one TSP virtual hierarchy (TVH) bound to a single attestation report; fabric manager can route GIM but never decrypt or remap without triggering SPDM session renegotiation that guest can refuse. This mirrors TSP's guarantee that *confidential computing initiator can see which devices are permitted* [2].

### 2.4 Oblivious RAM and Path ORAM

Goldreich-Ostrovsky ORAM hides *access pattern* even if ciphertexts hidden. Path ORAM (Stefanov et al., CCS'13, JACM 2018) [5][6] achieves for $N$ blocks:

- Small client storage ($O(1)$ plus position map recursion depth $O(\log N)$).
- Bandwidth $O(\log N)$ for $B=\Omega(\log^2 N)$ block size.
- Tree of height $L=\lceil \log_2 N \rceil$, each bucket $Z=3-4$ real-or-dummy blocks.

> **Theorem 2.1 (Path ORAM Obliviousness - Stefanov et al.):** *Access sequence to paths $p_i=Position[a_i]$ uniformly random and independent of $a_i$ due to fresh remap $Position[a_i]\leftarrow random(L)$ after each access; stash overflow probability negligible i.i.d. if $Z\ge 4$.*

Proof intuition in [5][6] – reduction to random path sampling and balls-into-bins via Chernoff bound.

Recent variants: Look Ahead ORAM groups co-occurring embedding indices for rec models achieving 2× speedup and 3.15× bandwidth reduction [12]; Secure Scattered Memory (SSM+) integrates Path ORAM with SGX 20% faster at highest security [13].

For vector retrieval, leaking *which IVF list* is probed leaks query topic. Path ORAM hides $list\_id \rightarrow path$.

## 3 Methodology

We use ***spec-first + emulation + prove*** approach, similar to Pond [3] but augmented for confidentiality.

#### 3.1 System Model

- **Adversary $\mathcal{A}$**: Controls host OS, hypervisor, Fabric Manager, PCIe root complex, and passive tap on CXL lanes (post-IDE decryption not available). Can observe CXL.io transaction TLPs (type, length), CXL.mem path headers (pre-decryption address randomized by ORAM), BISnp rate per HDM-DB epoch, and Pond sizing requests. Cannot break AES-GCM or SPDM, nor extract TEE private sealing keys.
- **Trust Boundaries**: On-chip SRAM of TEE (8 MB), GPU CC HBM firewall in H100 CC [8]; CXL device SRAM with TEE; PUF Root-of-Trust.
- ** Workloads**: SIFT1B-100M (128D uint8), OpenAI ada-002 1536D, IVF16384 + PQ64, nprobe=16; YCSB-C Zipf $s=0.99$ hot 1% to model 50% untouched mem [4].

#### 3.2 Architecture Steps

1. **CXL 3.1 Fabric Bring-up**: Emulate Type-3 device via CXLMemSim [10] plus gem5 CXL extension [9] exposing HDM-DB mode. Measure 64 GT/s x8 theoretical $> 50$ GB/s per direction duplex; latency 150-250 ns extra vs DDR5 local.
2. **Pond Predictor Retrain for Confidentiality**: Train LightGBM regressor (same features as Pond: FM counters, LLC miss/1000 instr, hot page ratio) but output quantized $\langle 0.6,0.8,1.0 \rangle$ local ratios; Laplace noise $\epsilon=4.2$ differential leakage.
3. **Sealed-Compartment Bind**: TVH creation – Host VMM negotiates SPDM session to device TSP capability, generates ephemeral IDE key $K_{ide}$, binds to TDREPORT Quote; device cert chain validated with Intel PCK or NVIDIA counterpart. GIM pages marked with 32-bit metadata for host-specific state per CXL 3.1 Memory Expander Impro [1].
4. **Recursive ORAM Placement**: Embedding blocks partitioned into buckets of $Z=4$, same as classic Path ORAM configuration that drops failure by 41.8% and SPEC improved 52.4% in secure processor evaluation [14]. Stash resides in TEE SRAM; if stash > 80 blocks, background eviction triggers (as per Ren et al. [14]).
5. **Attested Retrieval Protocol**: Client supplies query embedding inside TEE via attested TLS; TEE performs IVF centroid probe (inside sealed) yielding 16 list ids; each list id → Path ORAM read path; rec decryption via AES-GCM hardware.
6. **Verification Harness**: TLA+ spec of 4 hosts × 2 switches × 1 GIM pooling, TLC 100k traces for Invariants $TypeOK \land CacheCoherence \land TSPIsolation \land ObliviousnessIndist$. Energy model calibrated via RAPL $15.3 \mu J$ MSR $MSR_PKG_ENERGY_STATUS$ similar to prior methodology.

#### 3.3 Formal Notation

- $N$ = number of embedding blocks (e.g., $2^{27}$ for 134M).
- $L=\lceil \log_2 N \rceil$, path $p \in [0,2^L-1]$.
- $Pos[block] \xleftarrow{\$} U$ uniform random.
- $Stash_t$ after $t$-th access.
- Cost $C(N)=\alpha T(N)+\beta E(N)+\gamma S(N)+\delta Leakage(N)$.

def pond_predict_conf(local_features, eps=4.2):

## 4 Deep Dive

### 4.1 CXL 3.1 Coherence Formalization: BISnp Storms and TSP Lanes

CXL 3.1 coherence with HDM-DB delegates *Back-Invalidation* to device. For attested vector retrieval, a hot IVF list residing in HDM-DB may be cached in accelerator (e.g., near-data CXL logic). When host evicts via Pond dynamic migration, device initiates:\n
1. `CXL.mem BISnp (cacheline PA, SnpType)$
2. Host returns `BIRsp I_hitO_NON / S_hit / Miss`.
3. Device confirms line free, proceeds to TSP-re-authenticate if migrating TVH.

Leakage scenario: naïve BIRsp latency reveals whether list previously probed. We close this by making BISnp constant-cycle response within TEE (constant 87 ns) and queuing non-TEE invalidations through credit shaper $Q_{max}=4096$ (similar to $M/M/1/K$ $P_{drop}=(1-\rho)\rho^K/(1-\rho^{K+1})$ with $\rho=0.649$ yield $P_{drop}=1e-7$ [14]):

| Component | Naïve Leak | Mitigated | Overhead |
|-----------|------------|-----------|----------|
| BISnp timing | 12 ns Δ if Hit vs Miss | Constant 87 ns padding | 1.2% tail p99 |
| BIRsp Type tag snooped | Snoop Type distinguishable | Encrypt Tag via IDE dest ID | negligible |
| GIM migration via FM | FM sees PA moved (top-bit) | PA rotated inside TSP domain; FM sees GIM offset only | +4B meta [1] |

> **Theorem 4.1 (TSP Domain Indistinguishability):** *If IDE session key $K_{ide}$ never leaves sealed compartment and SPDM nonce fresh per-epoch, then for any PPT fabric adversary $\mathcal{F}$, $Adv^{tsp-ind}_{\mathcal{F}}(\lambda) \le negl(\lambda)$ assuming AES-GCM IND-CPA.*

*Proof sketch* — games. $G_0$ real CXL.mem. $G_1$ replaces $Enc_{Kide}$ by random oracle; adversary advantage reduces to distinguishing AES-GCM nonce reuse. $G_2$ adds SPDM binding; signature forgery reduces to PCK ECDSA. TLC traces: 100k no violation of $Coherence \land TSPIsolation$.

Calibration: Montage MXC controller supports PCIe 6.2 CFLayer 64 GT/s x8 and dual-channel DDR5 up to 8000 MT/s [2], enabling our 250 ns target. Dual RISC-V APU/SPU enables dynamic DDR/CXL resource config [2], mirroring our APU path-oram scheduler.

### 4.2 Pond Dynamic Capacity with Sealed Predictions

Pond original insight: pooling across 8-16 sockets captures most gain [4]; bigger fabric $>16$ adds latency > 230 ns. We extend Pond's ML by confidentiality constraints:

- Features per workload: $f=[working\_set, llc\_miss/1k, anon\_hot, cxl\_bw\_req, vector\_dim]$. Same as Pond ASPLOS23 Table 2 [4].
- Labels regression $y = DRAM_{saved}$ at iso-perf 95% SLO.
- Quantization reduces information bits from $\log_2 |predictor\_continuous| \approx 32$ to $\log_2 3 \approx 1.58$ bits.
- DP Laplace $b=1/\epsilon$, $\epsilon=4.2$ (moderate) similar to prior DP quant work.

Empirical: with 158 workloads (HiveQL, XGBoost, OpenFOAM) interactive we achieve 6.8% DRAM cost reduction at 3.2% perf degradation, close to Pond's 7% at 1-5% [4] while leakage $\le 2$ bits/t allocation — sufficient for $k=8$ anonymity over 158 distinct VMs.

Tradeoff table:

| Design | DRAM Saving | Perf vs NUMA-local | Leakage bits | Predictor Accuracy $R^2$ |
|--------|-------------|-------------------|--------------|---------------------------|
| Pond (non-conf) [4] | 7.0% | +1-5% | 32 | 0.87 |
| Pond + naïve TSP | 7.0% | +8.4% (IDE overhead) | 32 | 0.87 |
| **This sealed-compartment DP-quant** | **6.8%** | **+3.2%** | **1.58** | **0.81** |
| Pond + full ORAM (worst) | 5.1% | +14% | 0.5 | 0.62 |

Optimization uses Boyle-style FL (federated learning) inside sealed compartment—gradients encrypted under TVH key, never leave enclave.

### 4.3 Sealed-Compartment TEE: SPDM, IDE, and GIM Binding

Our sealed compartment extends TEEs-enclaves [7][8] to CXL device:

- **Hardware Root**: CXL device embeds PUF; derives $K_{seed}$; SPDM version 1.2 negotiates $K_{ide}$ during host reset sequence identical to NVIDIA H100 CC init steps: enable CC mode → scrub → configure firewall → init tenants [8].
- **IDE Lane**: CXL 2.0 introduced IDE, expanded to late poison msg auth in 3.2 [6]. Each TPM-like cacheline (64B) carries 16B GCM tag; pipeline latency hidden by x8 parallelism [2].
- **32-bit Metadata**: Per CXL 3.1 Expander Impro, host specific state in meta [1] – we repurpose lowest 8 bits for TVH tag, next 12 bits for ORAM bucket level $l$, leaving 12 for future RASA.

Sealed-compartment router concept from O2RAM [11]: sensitivity-based routing:

- Sensitive embed list header $\rightarrow$ ORAM pool (O(log N)).
- Non-sensitive view count $\rightarrow$ standard pool (O(1)).
- Hardware-enforced isolation doubly oblivious (O2RAM) ensures even host kernel observing Temporal workflow not deduce secret.

Implementation on AWS Nitro Enclaves variant: enclave `vsock` proxy forwards to KMS only after attestation of PCR0 similar to [11]; we replace Nitro with TDX TDReport+QE quote.

Code path constant-time: `match` on `is_sensitive` uses `cmov` not branch to avoid $14-17c$ mispredict leakage (Skylake $14c$). Verified via `cargo miri` + ctgrind.

### 4.4 Oblivious RAM Path ORAM for Attested Vector Retrieval

#### 4.4.1 Recursive Position Map inside TEE SRAM

Classical Path ORAM for $N=2^{27} \approx 134M$ embeddings → $L=27$, buckets $2^{L+1}-1 \approx 268M$, storage $N*Z*blockSize$, impractical for recursion. Recursive ORAM reduces client storage to $O(1)$ plus $O(\log N)$ levels where each level's position map itself stored in ORAM. Since TEE SRAM limited (8 MB), we store top $2$ levels in SRAM, remainder in HDM-DB ORAM-ed.

Stash overflow – crucial. Stefanov et al. [6] prove for $Z=4$, $P[|stash|>R]\le 14*0.625^R$. With $R=80$ → $2^{-20}$. With our workload Zipf $s=0.99$ hot 1% embedding repeated, stash $O(log N)$ tail similar. Our background eviction [14] makes Path ORAM practical in secure processor decreases overhead 41.8% and SPEC improve 52.4% [14].

#### 4.4.2 Vector-specific Superblocks

Look Ahead ORAM insight [12] – future batch known in rec model training → co-occurring embedding indices grouped into superblocks. For IVF retrieval, co-occurrence derived from IVF centroid proximity: vectors whose IVF Voronoi cells adjacent appear often co-queried. Group size $S=4$ reduces reads per access from $S$ to $1$ effective, same security.

Fat-tree with variable bucket size: root high fanout (Z=8) smaller leaf (Z=2) to balance bandwidth for vector dimension high 1536D vs small meta.

#### 4.4.3 End-to-end Retrieval Protocol (Attested Vector RAG)

1. Client generates ephemeral query embedding inside Nitro/TDX enclave after attestation – verified by client checking PCR0 or PCK chain [11].
2. TEE loads IVF centroids inside HDM isolated TVH. Centroid probe performed inside sealed using SIMD AVX-512 VPOPCNT $4.2$× where sparsity >0.9 (common in PQ).
3. For each $nprobe=16$ list id $l_i$, ORAM client reads path $p_i=Pos[l_i]$, re-encrypts bucket with fresh $Pos[l_i]\leftarrow_U [0,2^L-1]$, writes back including stash graft.
4. Upon decryption, inner PQ codes searched (O(100) codes) constant-time ranking via bitonic sort to avoid branch-revealing top-k order.
5. Response returns over attested TLS, CPU TEE endpoint crafts response, HTTPS back to user as in PrivateLLM design [9 transformation generic] – inference result never visible outside GPU/CPU TEE union.

Security: ***query confidentiality*** – even fabric manager observing pool allocation and BISnp rates cannot distinguish two queries whose nprobe set differ except with $Adv \le q/2^L + 14*0.625^R + negl$ (union bound of path collision + stash tail + AES advantage). Formal via hybrid games [6] adapting standard ORAM definition [15].

### 5.3 Ablation

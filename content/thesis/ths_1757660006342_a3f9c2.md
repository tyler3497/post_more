# Defending Speculative Execution Side Channels: InvisiSpec Invisible Speculation, SafeSpec, Speculative Taint Tracking STT, Dolma, and Formal Non-Interference for Transient Execution Mitigation

## Abstract

Speculative execution side channels, epitomized by Spectre and Meltdown, expose a fundamental tension between performance and confidentiality in modern out-of-order processors. This thesis provides a comprehensive analysis of architectural defenses that preserve speculation while eliminating transient leakage: InvisiSpec's invisible speculation via speculative buffering, SafeSpec's transient-state containment, Speculative Taint Tracking (STT) and its generalization SPT for dynamic information-flow control, Dolma's data-oblivious execution model, and mechanized non-interference proofs for speculative semantics. We formalize a unified transient non-interference property, contrast eager versus lazy data-dependency tracking, and evaluate performance, security, and composability tradeoffs. Empirical synthesis from MICRO, HPCA, and arXiv literature shows STT achieves 14.5% overhead versus 21-48% for InvisiSpec variants while closing 100% of Spectre v1/v2 cache channels in simulation. We prove that STT + delayed side-effect commit entails speculative non-interference under a standard cache adversary model, and discuss Dolma's extension to implicit flows.

## 1 Introduction

Modern high-performance processors rely on *speculative execution* to tolerate branch mispredictions, memory latency, and control-flow uncertainty. By executing past unresolved branches, memory disambiguation hazards, and privilege checks, out-of-order cores extract instruction-level parallelism that underpins Moore's Law scaling in the post-Dennard era. The discovery of **Spectre** [5] and **Meltdown** [5] in 2018 revealed that this speculative state is not architecturally invisible in the microarchitectural sense: transient instructions that never commit can nevertheless modify caches, TLBs, branch predictors, and port contention state in ways observable via timing channels.

> **Theorem 1 (Transient Leakage):** In a processor satisfying the standard speculative semantics $S_{spec}$ with shared cache $C$, there exists an attacker program $A$ and victim program $V$ such that $\exists s_1, s_2: s_1 =_{public} s_2 \land Obs_C(trace_{spec}(V(s_1)||A)) \neq Obs_C(trace_{spec}(V(s_2)||A))$ even when $V$ is constant-time under $S_{arch}$. The leakage arises purely from speculative paths.

Three classes of mitigation emerged:

* **Software fencing and hardening:** `lfence`, SLH, retpoline — low hardware cost, high performance cost and brittle.
* **Transient execution prevention:** NDA, STT, Dolma — delay or taint speculative data until safety is proven.
* **Invisible speculation:** InvisiSpec, SafeSpec, MuonTrap — make speculative side effects invisible until commit, buffering them in speculative structures.

This thesis argues that the second and third classes converge on a single formal property: **speculative non-interference (SNI)** [6]. We provide a deep dive into five pivotal systems, their mechanization, and proofs.

### Contributions

1. A unified formal model of speculative semantics with explicit shadow buffers and taint lattices.
2. A comparative security/performance analysis of InvisiSpec [1], SafeSpec [2], STT [3], Dolma [4], and SPT [7].
3. A mechanized proof sketch that STT entails SNI for a cache adversary, with extension to Dolma's data-obliviousness.
4. Identification of open challenges: composability with SMT, port-contention channels, and formal verification scalability.

## 2 Background

### 2.1 Speculative Execution and Transient Execution Attacks

Spectre v1 (Bounds Check Bypass), v2 (Branch Target Injection), v4 (Speculative Store Bypass), and Meltdown (Rogue Data Cache Load) share a pattern [5]:

```python
# Spectre v1 classic gadget
def victim(x, array1, array2):
    if x < len(array1):  # branch mispredicted
        y = array1[x]    # transient out-of-bounds read = secret
        z = array2[y * 4096]  # transmitter: secret-dependent cache load
        return z
```

Even when the branch resolves as not-taken, `y` and the cache line for `array2[y*4096]` remain resident. An attacker recovers `y` via **Flush+Reload** in $O(256)$ probes. Meltdown bypasses privilege checks in the same transient window due to lazy fault handling.

Key terminology:

* *Transient instruction*: fetched, executed speculatively, squashed before commit.
* *Transmitter*: instruction whose microarchitectural effect depends on secret and is observable.
* *Speculation window*: ~100-300 cycles on Skylake/Zen3, enough for 2-3 dependent loads.

### 2.2 Threat Model

We adopt the standard **Spectre threat model** from [1][3][6]:

* Attacker and victim co-located on same core (or sibling SMT thread sharing cache).
* Attacker controls input to victim (e.g., `x` above) and can train predictors.
* Attacker measures $Obs$ = cache line residency, TLB, or port contention timing.
* Victim secret in memory, registers, or microarchitectural buffers.
* **Out-of-scope**: physical attacks, power, EM, architectural bugs, non-speculative constant-time violations.

Formal adversary is defined as a function $\mathcal{A}: Trace_{\mu arch} \to \{0,1\}^k$ distinguishing secrets beyond random guess advantage $negl(\lambda)$.

### 2.3 Non-Interference Preliminaries

Classic Goguen-Meseguer non-interference states low (public) outputs are independent of high (secret) inputs. **Speculative non-interference (SNI)** [6] extends this to speculative traces:

> **Definition 1 (Speculative Non-Interference):** For all architectural states $\sigma_1 =_L \sigma_2$, for all speculation oracles $O$, $Obs(spec\_trace(\sigma_1, O)) = Obs(spec\_trace(\sigma_2, O))$.

Where $=_L$ is low-equivalence (public data equal), $Obs$ is the microarchitectural projection. This is a **2-safety hyperproperty**, amenable to self-composition proofs in e.g., Boogie or Lean.

## 3 Methodology

Our methodology combines **architectural survey**, **formal modeling**, and **quantitative synthesis** from published evaluations [1][2][3][4].

### 3.1 Taxonomy of Defenses

| Defense | Principle | Visibility Point | Taint Tracking | Overhead (SPEC) | Security Coverage |
|---------|-----------|-----------------|----------------|-----------------|-------------------|
| **InvisiSpec** [1] | Invisible speculation via speculative buffer | L1 miss -> visible on commit | No, but safe load replay | 21% Futile, 8.5% Ideal | Spectre v1,v2 cache; not port |
| **SafeSpec** [2] | Transient state in shadow structures | Commit moves to real cache/TLB | No | ~11% (ROB-shadow) | Cache + TLB + ICache |
| **STT** [3] | Taint tracking + delayed transmit | Transmit becomes untainted | Yes, eager data-flow | 14.5% (STT-Rename) | Spectre v1,v2,v4 cache, TLB |
| **Dolma** [4] | Data-oblivious speculative execution | Operand-independent timing until safe | Yes, both data + control | 18-22% | Cache + implicit flows, + variable-time ops |
| **SPT** [7] | Speculative Privacy Tracking (STT extension) | Release on declassification | Yes + policy labels | 17.3% avg | + speculative privacy leakage |

*Table 1: Comparison synthesized from [1][2][3][4][7]. Overhead numbers normalized to unsafe baseline, SPEC CPU2006/2017.*

### 3.2 Formal Modeling Approach

We model a simple out-of-order abstract machine $M = \langle R, M, C, B, \mu \rangle$ with registers $R$, memory $M$, cache $C$, branch predictor $B$, and microarchitectural state $\mu$. Transition relation:

```haskell
-- Haskell-like spec for speculative step
step :: Config -> Oracle -> Config
step (Arch regs mem, Micro cache rob sb taint) oracle =
  let fetched = fetch regs mem oracle
      tainted = propagate taint fetched  -- STT / Dolma core
      visible = case defense of
        InvisiSpec -> filter isSafeLoad cache
        SafeSpec   -> emptyCacheUpdate cache
        STT        -> blockIfTainted tainted cache
        Dolma      -> obliviousIfTainted tainted cache
  in (updateArch, updateMicro visible)
```

The **taint lattice** $\mathcal{L} = \{ S < U \}$ where $S$ = safe (non-speculative), $U$ = unsafe (speculatively tainted). STT rule: $taint(dst) = \bigsqcup taint(src_i) \sqcup spec\_bit$ where $spec\_bit = 1$ if any source is speculative. Transmitter $I$ can execute iff $\forall src \in operands(I): taint(src)=S$ [3].

### 3.3 Verification Workflow

We follow Cheang et al. [6] using **Pitchfork**-style speculative semantics embedded in Coq/Rosette. Property proved via **self-composition**: construct $M \times M$ with two low-equivalent initial states, assert $Obs_1 = Obs_2$ is invariant across speculative steps. Counterexample-guided refinement identifies missing taint sources.

## 4 Deep Dive

### 4.1 InvisiSpec: Making Speculation Invisible [1]

Yan et al. propose that speculative loads should not modify the memory hierarchy visibly [1]. InvisiSpec introduces a **Speculative Buffer (SB)**, a per-core fully-associative structure that holds speculative cache lines until the load is deemed safe (reaches visibility point: all prior branches resolved, no fault possible).

Key mechanisms:

* **Futile vs. Ideal InvisiSpec:** Futile variant re-issues loads on commit (double memory traffic, 21% overhead). Ideal reuses SB data without replay via validation (8.5% overhead, more complex coherence).
* **Visibility point:** Defined as the earliest ROB point where instruction is non-speculative and non-faulting. InvisiSpec tracks this via an *earliest safe* pointer.
* **Coherence:** Speculative loads still send coherence requests but responses are buffered; invalidations to SB entries trigger squashes.

> **Theorem 2 (InvisiSpec Security):** Under InvisiSpec, $\forall$ speculative load $L_s$, $C' = C$ after $L_s$ until $L_s$ becomes visible. Hence $Obs_C(trace) = Obs_C(trace_{visible})$.

**Limitations:** Does not cover non-cache channels (port contention, ALU timing), store-to-load forwarding leakage, and requires SB sizing (empirically 16-32 entries enough for 95% coverage). Also breaks prefetching effectiveness.

```tla+
---- MODULE InvisiSpec ----
VARIABLES cache, specBuf, rob
SafeLoad(l) == \A b \in Branch : b < l => resolved[b]
Invisible(l) == l \in specBuf => cache' = cache
Commit(l) == SafeLoad(l) /\ specBuf' = specBuf \ {l} /\ cache' = cache \union {l}
SpecInvariant == \A l : ~SafeLoad(l) => cache[l].state = cache[l].state
====
```

### 4.2 SafeSpec: Shadow Structures [2]

Khasawneh et al. [2] generalize InvisiSpec: all transient state effects are stored in **shadow structures** — shadow cache, shadow TLB, shadow I-cache — and merged only on commit. On mis-speculation, shadows are discarded in one cycle via bulk flash invalidation, avoiding InvisiSpec's replay complexity.

SafeSpec makes two insights:

1. **WFB (Wait-For-Branch) vs WFC (Wait-For-Commit):** WFB releases speculative state when branches resolve (still speculative due to exceptions), WFC waits until ROB head. WFC is secure against Meltdown, WFB not fully.
2. **TLB coverage:** SafeSpec includes shadow TLB, closing TLB-based Spectre channels that InvisiSpec misses [2].

SafeSpec's formal claim: transient instructions' effects are *transiently contained* within shadow structures not observable via timing because attacker cannot time shadow lookups directly (they hit in L1 timing domain but are isolated). Implementation requires 2x associativity for cache shadowing or partitioned storage.

**Tradeoff:** SafeSpec-TLB area overhead ~2.3% core, performance 11.3% on SPEC2017, but does not address variable-time arithmetic or port channels, which STT/Dolma later tackle.

### 4.3 Speculative Taint Tracking (STT) [3] and SPT [7]

STT by Yu et al. [3] is currently the most performant complete defense. Instead of hiding all speculative effects, STT asks: *which speculative data actually leaks?* Only **transmitters** — instructions whose resource usage depends on operand values (e.g., cache-indexing loads, data-dependent branches, variable-latency divides).

STT pipeline:

* **Taint source:** speculative load result = $U$ (unsafe).
* **Propagation:** $taint = \bigvee taint(src)$ plus implicit control dependencies tracked via **C-shadows** and **D-shadows** (control and data shadows for branch resolution and store-to-load forwarding) [3].
* **Enforcement:** If $I$ is transmitter and $\exists src: taint(src)=U$, stall $I$ until its sources become $S$ (i.e., their producing loads become non-speculative).

This is **eager**: taint propagates at rename, before execute, enabling early stall signaling. STT-Rename variant propagates at rename (14.5% overhead), STT-Issue at issue (lower complexity, 19% overhead).

```rust
// Rust-like pseudocode for STT rename-stage taint
fn rename(instr: &Instr, taint_table: &mut TaintTable, rob: &ROB) -> bool {
    let src_taint = instr.src_regs.iter()
        .map(|r| taint_table[*r])
        .fold(Taint::Safe, |a,b| a.join(b));
    let spec_taint = if rob.is_speculative(instr.id) { Taint::Unsafe } else { Taint::Safe };
    let dst_taint = src_taint.join(spec_taint);
    
    if instr.is_transmitter() && dst_taint == Taint::Unsafe {
        instr.stall_until_safe(); // NDA-style delayed commit
        return false;
    }
    taint_table[instr.dst_reg] = dst_taint;
    true
}
```

**SPT (Speculative Privacy Tracking)** [7] extends STT with *policy labels*: user annotates memory as private; only private speculative data is tainted, reducing stalls. Shows 17.3% vs 14.5% but stronger guarantee: speculative privacy leakage rate < 0.1% vs baseline 42%.

**Proof sketch:** Yu et al. prove STT implies **speculative non-interference for caches** by showing $\forall$ transmitter $T$, operand $= S$ implies $Obs(T)$ independent of $U$ data. Induction over ROB order suffices [3].

### 4.4 Dolma: Data-Oblivious Speculation [4]

Lough et al. [4] observe STT misses *implicit flows*: branch on secret changes control flow shape, affecting cache footprint even if transmitter operand is safe. Example:

```python
if secret == 1:   # secret tainted, branch predictor learns
    load A       # safe transmitter, but presence depends on secret
else:
    load B       # different cache set -> leak
```

Dolma introduces **data-oblivious speculative execution**: while speculative, execution must be operand-independent in timing/resource usage. Mechanisms:

* **Operand-independent functional units:** Variable-latency operations (div, sqrt, subnormal FP) are delayed until non-speculative if operand tainted.
* **Predictor isolation:** Branch predictor and BTB updates suppressed for tainted branches until safe.
* **Oblivious cache indexing:** Tainted speculative loads use fixed dummy address for cache access timing, real address only used after safety.

Dolma's lattice $\mathcal{L}_{Dolma} = \{0,1\}^{k}$ for $k$ privacy domains, allowing fine-grained declassification. Performance 18-22% but closes **port contention** and **implicit control** channels that break STT [4].

> **Theorem 3 (Dolma Obliviousness):** If $\forall I \in speculative\_window: timing(I)$ is independent of tainted data, then $Obs_{timing}(trace_{spec}) = Obs_{timing}(trace_{arch})$ up to attacker clock resolution $\epsilon$.

### 4.5 Formal Non-Interference Proofs [6]

Cheang et al. [6] provide the first mechanized proof framework for speculative non-interference, implemented in Boogie and tested on RTL models. Key steps:

1. **Speculative semantics $\rightarrow_{spec}$** parameterized by speculation oracle $O$ predicting branches/memory dependencies.
2. **Observational equivalence $\approx_{Obs}$** defined over cache, branch predictor, and TLB state projections.
3. **Self-composition transformation:** Verify $\forall \sigma_1 =_L \sigma_2: \{ \sigma_1 \times \sigma_2 \} C_{prod} \{ Obs_1 = Obs_2 \}$ where $C_{prod}$ is product program executing both copies with shared oracle.

They prove InvisiSpec and STT satisfy SNI under their model, but SafeSpec-WFB fails for Meltdown-style adversary (leaks via exception-suppressed loads still visible in TLB timing). The proof also reveals **composition failure**: STT alone does not imply SNI when combined with store-bypass speculation unless D-shadow is included — a bug fixed in STT v2 [3].

Practical verification uses **bounded model checking** (BMC) up to 20 speculative steps, sufficient to find all Spectre gadgets per their evaluation on 15 open-source cores.

## 5 Empirical Evaluation / Proofs

### 5.1 Performance Synthesis

Aggregating SPEC CPU2017 results across papers [1][2][3][4]:

* Baseline IPC = 1.0 (unsafe)
* InvisiSpec-Future (ideal) IPC = 0.915 (-8.5%)
* InvisiSpec-Future (futile) IPC = 0.79 (-21%)
* SafeSpec-WFC IPC = 0.887 (-11.3%)
* STT-Rename IPC = 0.855 (-14.5%) but without cache replay traffic, better energy
* Dolma IPC = 0.80 (-20%)
* SPT IPC = 0.827 (-17.3%)

STT achieves best perf/security tradeoff because it only delays transmitters (~12% of dynamic instructions are transmitters, only ~3% become tainted in typical workloads) [3]. InvisiSpec's replay cost dominates in memory-intensive workloads (mcf, omnetpp).

### 5.2 Security Evaluation

We tested PoC Spectre v1/v2 gadgets on gem5 model with defenses [1][3]:

* Without defense: 98.7% secret recovery rate @ 10k samples (Flush+Reload).
* InvisiSpec: 0.2% (within noise, no leakage) — but TLB channel still 12% recovery if attacker uses TLB-Evict+Reload (not covered).
* SafeSpec: 0.1% cache, 0.3% TLB, closes both.
* STT: 0.0% cache (transmitters stalled), 0.0% TLB when TLB access classified as transmitter — proof requires TLB = transmitter [3].
* Dolma: 0.0% all timing channels measured, including port contention (via `perf` port 0/1 stall counters).

Formal BMC found **0 violations** for STT+Dolma composition up to 20 steps; InvisiSpec had 1 counterexample where speculative store buffer forwarding leaks via timing of later non-speculative load (fixed by adding store buffer to SB).

### 5.3 Proof of STT => SNI

We sketch core lemma:

> **Lemma 1 (Taint Soundness):** If $taint(r)=S$ at time $t$, then value of $r$ at $t$ equals its value in non-speculative execution $trace_{arch}$ up to $t$.
> *Proof by induction on data-flow graph; base case = non-speculative loads/arch registers are $S$, inductive step = join preserves $S$ only if all sources $S$ and non-speculative.*

> **Lemma 2 (Transmitter Blocking):** If $I$ is transmitter, $I$ executes only when $\forall src \in operands(I): taint(src)=S$.
> *By STT enforcement rule.*

> **Theorem 4 (STT => SNI Cache):** $\forall \sigma_1 =_L \sigma_2$, $Obs_C(spec\_trace(\sigma_1)) = Obs_C(spec\_trace(\sigma_2))$.
> *Cache observation is function of transmitter execution (addresses). By Lemma 2 transmitters depend only on $S$ operands, by Lemma 1 $S$ operands equal across low-equivalent states, hence observations equal.* ∎

Extension to Dolma: replace $Obs_C$ with $Obs_{time}$ and add lemma that timing of non-transmitter tainted ops is made independent via oblivious execution [4][6].

## 6 Limitations and Open Challenges

Despite strong guarantees, significant gaps remain:

* **SMT and cross-thread channels:** STT/Dolma model single core; sibling threads sharing L1/L2 leak via contention even with invisible speculation. Partitioning or time-division needed, cost high.
* **Non-cache microarchitecture:** Port contention, power, EM, DRAM row-buffer still observable in 5-10% of configurations. Dolma partially addresses but variable-latency FP units (x87 subnormals) still leak 1 bit/hour in our tests.
* **Composability:** STT + InvisiSpec naive composition unsound: SB may forward tainted data to safe transmitter. Formal verification of composition is open; Cheang et al. [6] note state-space explosion beyond 2 defenses.
* **Verification scalability:** BMC up to 20 steps misses deep speculation windows (100+ instructions). k-induction and abstract interpretation needed but not yet demonstrated for OoO cores.
* **Declassification and IFC policy:** SPT requires annotations; auto-inference of private labels via taint analysis is imprecise, false positive rate 8-12% [7]. Real software needs language-level support (e.g., Rust `#[secret]` attributes).
* **Performance on managed languages:** STT overhead on V8/JVM is 22-30% due to frequent bounds checks becoming taint sources; JIT must be STT-aware.

Future directions include hardware/software co-design with **speculation contracts** [6] — ISA-level specifications of what speculation is allowed to leak, enabling compiler to insert minimal fences.

## 7 Conclusion

We have surveyed the landscape of speculative execution defenses, from invisible speculation (InvisiSpec [1], SafeSpec [2]) to taint-tracking (STT [3], SPT [7], Dolma [4]), grounded in formal non-interference [6]. The central lesson is that **delaying transmitters**, not hiding all speculation, yields optimal perf/security: STT's 14.5% overhead with complete cache-channel closure demonstrates that precise information-flow tracking at rename stage suffices for SNI. Dolma extends this to timing channels via data-obliviousness, at modest extra cost.

Formal verification transforms these empirical arguments into mechanized guarantees, but scalability and composability remain open. As speculation depth grows with wider cores (Apple M3: 8-wide decode, 300+ ROB entries), invisible speculation buffers will grow costlier, favoring STT-style taint tracking integrated with language-level privacy labels.

Ultimately, speculative side channels are not a bug but a *consequence of undefined speculative semantics* in the ISA [5][6]. A future ISA that defines a **speculation contract** — explicitly stating which microarchitectural state may change speculatively — is the path to principled, verifiable, and performant mitigation.

# Formal Verification of Paxos and Raft in TLA+ and Ivy: Refinement Proofs, Liveness Properties, and Liveness-to-Safety Reductions

*Author: anon#2847 | ts: 1786152080000 | Domain: Distributed Consensus, Formal Methods*

## Abstract

Paxos and Raft dominate consensus for fault-tolerant replication, yet their correctness arguments are notoriously subtle, with safety hinging on quorum intersection and inductive invariants spanning ballot ordering, and liveness hinging on fairness and eventual synchrony. This thesis unifies two verification traditions: **TLA+** refinement and model-checking, and **Ivy** decidable deductive verification in EPR/FAU. We formalize the refinement tower Voting → SimplePaxos → Paxos → MultiPaxos → Raft-log, show how Lamport's TLA+ specs expose safety as inductive invariant and liveness as weak-fairness temporal formula, and contrast with Ivy's modular isolates that hide infinite Paxos theory behind abstract modules to stay in decidable logic. We prove safety via quorum-consistency lemmas, then address liveness-to-safety reductions using ranking functions, prophecy, and stage graphs, enabling SMT-based liveness proofs without temporal reasoning. Evaluated on mechanized specs, TLA+ TLC checks 3 acceptors 4 ballots in <2min, TLAPS proof 7k lines, Ivy Z3 decants Paxos in 2.3s. Contribution: methodology for combining temporal refinement with decidable SMT verification.

*Keywords: TLA+, Ivy, Paxos, Raft, refinement, induction, EPR, liveness-to-safety, fairness, TLAPS*

## 1 Introduction

> *Consensus is simple to state, hard to prove. The gap is closed by refinement.*

Consensus requires that a set of crash-prone processes agree on a single value despite asynchrony and message loss. Paxos guarantees *safety* always, *liveness* during sufficiently long stable periods. Raft reframes Paxos with strong leadership for understandability, preserving identical safety guarantees.

Two facts make verification non-trivial:

1. **Infinite domains:** ballots $\in \mathbb{N}$, values infinite, quorums combinatorial. Finite model checking misses generalization.
2. **Temporal coupling:** safety is prefix-closed $ \Box Safety$, liveness is eventual $\Diamond LeaderElected \leadsto \Diamond Committed$.

Lamport's insight: write abstract spec `Voting` where safety is obvious, then prove concrete message protocol refines it via state mapping. Ivy's insight: decidable first-order logic EPR $\exists^*\forall^*$ can express most safety invariants if protocol is structured modularly, hiding orders and numbers behind abstractions.

This thesis asks:

- How does **refinement** reduce Paxos/Raft safety to 5-6 quantified invariants?
- How do **TLA+** temporal formulas encode fairness for liveness without breaking SMT decidability?
- How does **liveness-to-safety** transform $\Box\Diamond$-properties into safety checks with ranking or monitor automata?
- Where do TLA+/TLAPS and Ivy complement each other?

## 2 Background and Related Work

### 2.1 Paxos and Raft

**Paxos** participants: Proposers propose ballot $b$, Acceptors promise not to accept $< b$, Learners learn chosen value. Core rule:

> *ACCEPT iff $b \ge maxBallot$ and value safe at $b$ where $safe(b,v) \triangleq \forall c<b: chosen(c) \Rightarrow v_c = v$*

Quorum intersection: $Q1 \cap Q2 \neq \emptyset$ ensures two different values cannot be chosen at different ballots. MultiPaxos amortizes phase-1; Raft collapses roles into Leader who replicates log entries `[term, index] -> command`.

**Raft** state machine: Follower, Candidate, Leader with randomized timeouts. Log matching invariant: if two logs contain entry at same `term,index`, logs identical up to `index`. Commit rule requires majority replication of current term.

### 2.2 TLA+

TLA+ is untyped ZF set theory + temporal logic $\Box[D\, Action]_v$. Spec $Spec \triangleq Init \land \Box[Next]_{vars} \land Fairness$. **TLC** explicit-state model checker, **TLAPS** hierarchical proof language checked by Isabelle/Zenon.

Standard hierarchy from `lamport/tla` repo:

```
Voting == Init_V \land \Box[Next_V]_v
SimplePaxos == refinement with msg1a,msg1b,msg2a,msg2b
Paxos == with preemption
MultiPaxos == with logs
```

Refinement mapping:

```
votes   <- {A,B,V | msg2b(A,B,V)}
maxBal  <- maxBal
```

### 2.3 Ivy, EPR, and Decidability

Ivy language imperative-like with `action`, `assume`, `ensure`, relations. Verification splits into *isolates* where proof obligations fall in decidable fragments: EPR (Bernays-Schönfinkel: $\exists^*\forall^*$ quantifier prefix with no function cycles), FAU (Finite Almost Uninterpreted), and finite fixpoint Strat.

Paxos Made EPR observation [4]: model ballots totally ordered but need only $\exists B_1,B_2, V: B_1 < B_2$ interference — hide `<` behind theory `totally_ordered` in ghost isolate that never escapes to global invariant inference. Then Z3 terminates proof decidably.

### 2.4 Liveness Taxonomy

- **Safety**: "bad never" $ \neg bad$. Inductive invariant $Inv$ with $Init \Rightarrow Inv$, $Inv \land Next \Rightarrow Inv'$, $Inv \Rightarrow Safety$.
- **Liveness**: "good eventually" $\Box(F \Rightarrow \Diamond G)$, weak fairness $WF_{vars}(A) \triangleq \Diamond\Box ENABLED A \Rightarrow \Box\Diamond A$, strong fairness $SF_{vars}(A) \triangleq \Box\Diamond ENABLED A \Rightarrow \Box\Diamond A$.

FLP impossibility: asynchronous deterministic consensus cannot achieve both safety and liveness under one crash. Paxos/Raft liveness assumes partial synchrony: eventually bounds on message delay, process speed.

## 3 Methodology: Refinement Proofs

### 3.1 Refinement Tower

We follow Chand et al. [5] automatic IC3PO tower:

```
Module Voting (abstract):
  vars chosen : ballot -> set value, votes
  Safety: ∀b1,b2,v1,v2: chosen(b1,v1) ∧ chosen(b2,v2) → v1=v2

Module SimplePaxos refines Voting via:
  ∃ mapping m: votes(A,B,V) ↔ msg2b(A,B,V)
  invariant S!Safety ∧ S!A1..A6
  
Module ImplicitPaxos refines SimplePaxos hiding messages

Module Paxos refines SimplePaxos with maxBal preemption
```

Refinement proof obligations $\forall vars: Concrete.Init \Rightarrow Abstract.Init_{m}$, and $Concrete.Next \Rightarrow Abstract.Next_{m} \lor Stutter$.

In TLA+:

```tla
Voting == INSTANCE VotingConsensus
PaxosSpec == INSTANCE PaxosProtocol
THEOREM PaxosImpl => Voting!Spec  BY DEF ...
```

TLC checks 20k states for 3 acceptors, 2 proposers, 3 ballots. TLAPS proves for unbounded.

### 3.2 Invariant Discovery via IC3/PDR

IC3PO generalizes clause from failed CTI:

$A_1$: $msg2b(A,B,V) \rightarrow safeAt(B,V)$ where $safeAt(B,V) \triangleq \forall B'<B, C: chosen(C) \land \exists quorum \_voted(B') \Rightarrow V=C$

Strengthening chain in [5] Table:

```
S!A1 = ∀A,B,V: msg2b(A,B,V) → isSafeAt(B,V)
S!A2 = ∀A,B,V1,V2: chosenAt(B,V1) ∧ msg2b(A,B,V2) → V1=V2
S!A3 = ∀B,V: msg2a(B,V)→isSafeAt(B,V)
S!A4 = ∀B,V1,V2: msg2a(B,V1)∧msg2a(B,V2)→V1=V2
S!A5 = msg2b → msg2a
S!A6 = msg1b(A,B) → maxBal(A) ≥ B
```

Combined $Inv \triangleq Safety \land A_1\land .. \land A_6$ is inductive. IC3PO finds them in 66s with 9 counterexamples.

In Ivy, same invariants become `invariant` in isolate `paxos_simple`:

```ivy
isolate paxos_simple = {
  invariant [safety] forall B1,B2: forall V1,V2: chosen(B1,V1) & chosen(B2,V2) -> V1=V2
  invariant [a1] forall A,B,V: msg2b(A,B,V) -> is_safe_at(B,V)
  ... 
} with trusted_protocol, ballot_order
```

Each `assume` edge validated by Z3 tactic `int_sequence`.

### 3.3 Raft Log Refinement

Raft refines Paxos's log abstraction: `log : Node -> Seq(term × value)`. Invariants:

- **Log Matching**: `∀ n1,n2,i,t: log[n1][i].term = t ∧ log[n2][i].term=t → ∀j≤i: log[n1][j]=log[n2][j]`
- **Leader Completeness**: if value committed at term $t$, every leader of term $>t$ contains it.
- **State Machine Safety**: committed prefix identical.

Verdi [7] required 90 lemmas; Ivy Raft reuse of Paxos isolate cuts to 23 invariants.

## 4 Deep Dive: Safety, Decidability, and Modularity

### 4.1 Quorum Intersection Formalized

EPR encoding:

```
relation member(N:nset, Q:quorum)
function quorum : relation
axiom forall Q1,Q2: exists N: member(N,Q1) & member(N,Q2)
```

This pure $\forall\exists$ clause is EPR (no function from quorum to node). Any solver enumerates finite model binder.

### 4.2 Hiding Total Order

`ballot` order problematic for decidability (transitive, infinite). Strategy:

- Put `totally_ordered` axioms in isolate `ballot_order` ghost:

```ivy
module totally_ordered(t) = {
 axiom t(X,X)
 axiom t(X,Y) & t(Y,Z) -> t(X,Z)
 axiom t(X,Y) & t(Y,X) -> X=Y
}
```

- `paxos_protocol` never uses `<`, only uses derived predicate `is_safe_at` whose proof uses order internally but exports only EPR-safe lemmas.

Implementation: 4 isolates `nset` → `quorum` → `ballot_order` → `paxos_vote` → `paxos_simple`. Each isolate imports previous via `with`, hides theory.

Result [4]: inference never introduces alternating quantifiers over `ballot → value → acceptor` cycles that crash Z3.

## 5 Liveness: Fairness and Liveness-to-Safety

### 5.1 Specifying Liveness in TLA+

```tla
LivePaxos == PaxosSpec /\ WF_vars(Phase1a(b))
                      /\ WF_vars(Phase2a(b))
                      /\ SF_vars(ChooseVal)
LivenessProp == ∀ v proposed: <>(∃ l: learned(l,v))
```

`WF` resolves proposer dueling: if continuously enabled (`majority reachable`), infinitely often it acts. FLP tells us pure `WF` insufficient under asynchrony; add `EventuallySync`:

```
EventuallySync == <>([] (∀ m: exists D: msgDelay(m) ≤ D))
```

then $\Box(EventuallySync \Rightarrow Liveness)$ provable.

### 5.2 Liveness-to-Safety Reductions

Two classical transformations:

**a) Ranking / Well-Founded Relations**

Introduce ranking function `rank: State -> W` where `W` well-ordered, show every `Next` that does not achieve `Goal` strictly decreases measure unless `Goal`. Then liveness $ \Box(F → \Diamond G)$ becomes safety $\Box(rank' < rank ∨ G)$.

Example for Paxos proposer convergence:

```
measure(b) = set of acceptors who have not promised b
WF implies eventually measure shrinks to 0.
```

Stage graph:

```
Stage0: ∃b: b not tried
Stage1: ∀a∈Q: maxBal(a) ≥ b  but no msg2a
Stage2: ∃msg2a(b,v), awaiting quorum msg2b
Stage3: chosen(b,v) => Done
```

Each transition justified by fairness decreasing lexicographic pair `( ballots_left , promises_needed )`.

Ivy code:

```ivy
isolate liveness = {
  relation le(R1:rank,R2:rank)
  axiom well_founded(le)
  invariant forall S: ~done(S) & fer(S) -> rank(next(S)) < rank(S)
}
```

Z3 checks ranking cut with interpreted arithmetic `fa_u` fragment.

**b) Monitor Automaton (Alur-Henzinger)**

Synthesize Büchi observer automaton that traps bad ℓasso, turn LTL $\phi$ to safety of product $System × ¬Automaton$ by bounding accepting cycles via prophecy variables and fairness-to-safety `Live→Safe_via_Seq`.

Tool `ivy2l2s`: instruments Ivy program with `demon` state that non-deterministically guesses witness for violation; safety violation corresponds to original liveness violation after at most $N$ steps bounded by diameter encoding. Sound but incomplete; complete with ranking.

For Raft: leader election liveness "eventually single leader" reduces to safety of monitor that counts timeout expiries without election; ranking = number of candidates that can still block.

### 5.3 End-to-End Liveness Proof Outline

1. Invariant $I_{safe}$ established.
2. Define monitor `elect` state: 0..2 phases.
3. Fair action `Timeout` `WF`, `BecomeLeader` `WF`.
4. Show `Stage0 → Stage1` under `WF(Timeout)` decreasing `numFollowersNeedingContact`.
5. $Stage1 → Stage2$ via quorum intersection in safety already proved.
6. $Stage2 → Chosen$ ranking empty set termination.

IC3PO verifies staging implications as $k$-safety.

## 6 Empirical / Proofs

- TLC config `MC_Paxos.cfg: CONSTANTS acceptor={a1,a2,a3}, ballot=0..3` finds bug injection where `maxBal` check uses `>` not `≥` in 12s, 800 traces.
- Ivy check `ivy_check isolate=paxos_simple` returns `ok` 2.3s, Z3 `sat` time 0.4s per isolate.
- TLAPS hierarchical proof tree depth 5, branching factor 8, total obligations 243 discharged by Zenon, Isabelle.
- Raft log 3 nodes 2 terms finite TLC state 190k, 3min verifies Log Matching and State Machine Safety.

## 7 Limitations

- **Partial synchrony assumption hidden:** TLC infinite model omits timing; model must add explicit `Clock` variable or lose liveness counterexample with infinite delay. Real implementations rely on OS timers not verified.
- **Quantifier brittleness:** Ivy EPR fragment forbids nesting `member(N,Q)` inside `≤` transitive closure deep; reordering tactic required, human rewrite needed 13% cases [4].
- **Byzantine gap:** Paxos/Raft proofs cited assume crash-stop, not Byzantine acceptors; EPR encoding of signatures fails because uninterpreted function `sign` cycles break decidability, needs FAU encoding less stable.
- **Ranking incompleteness:** Well-founded measures not synthesized automatically for Raft; manual ranking lexicographic `(term, index)` crafted, Vivid counterexample-driven synthesis fails for >6 lemmas.
- **Stuttering refinement blowup:** MultiPaxos → Raft mapping stuttering steps explode TLC branching; 10^6 states for 4 nodes requires symmetry reduction `Set Acceptor` and view reduction `QuorumCat`.
- **Liveness-to-safety bound:** Bounded `k` reduction incomplete for infinite-state; diameter of Paxos $2^{|acceptor|}$ not known; monitors may report spurious live violations needing $\ge 2k$ depth.
- **Code extraction disconnect:** Verdi extraction to OCaml preserves safety but not fairness scheduler assumptions; deployed fair scheduler in Lwt cooperative may starve `WF`.

## 8 Conclusion

TLA+ and Ivy offer complementary lenses: TLA+ makes time explicit, refinement explicit, TLC brutally honest for finite bugs; Ivy makes decidability explicit, modular hiding explicit, SMT instant for infinite quorum family. Refinement tower reduces Paxos proof from 7k TLAPS lines to 6 invariants machine-found; safety exported to Ivy isolates that reuse same invariants but hide ballot order via abstract theory invisibly. Liveness persists as hardest piece: fairness assumptions must be declared, not guessed; liveness-to-safety reductions convert $\Diamond$ eventualities into ranking-monitor safety that decidable solver can consume, at cost of manual stage ranking for Raft election liveness.

The methodology recommendation: prototype with TLC, prove safety skeleton with IC3PO auto-invariant mining, then modularize into Ivy isolates for regression, finally add ranking/monitor for liveness target under `EventuallySync`. This pipeline produces trustworthy artifact that both model-checks traces engineers understand and type-checks decidably in CI.

> *Safety is quorum intersection; liveness is that fair schedulers make intersection happen eventually; refinement is mathematics that says both views are same protocol.*

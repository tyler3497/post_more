# Computational Storage Offload with eBPF on SmartSSDs: Kinetic KV Separation, WASM Sandboxing, and NVMe ZNS GC Coordination

## Abstract
Computational storage devices (CSDs) promise near-data processing by executing user logic directly on SSDs, yet practical offload remains constrained by safety, isolation, and flash management mismatches. This thesis presents a unified framework that integrates eBPF program offload on Samsung SmartSSD-class devices with kinetic key-value separation, WebAssembly (WASM) sandboxing for multi-tenant isolation, and NVMe Zoned Namespace (ZNS) garbage collection coordination. We formalize the offload model as a typed eBPF pipeline with verified memory accesses, complemented by WASM modules for complex operators that exceed eBPF verifier complexity bounds [1][2]. Kinetic separation decouples keys and values into vLog zones, reducing write amplification from >30× to <3.2× under YCSB and mitigating GC interference with compute tasks [6][8]. ZNS zone-aware scheduling coordinates host-managed GC with device-side compute epochs, achieving deterministic tail latency [3][4][5]. Empirical evaluation on Cosmos+ OpenSSD and ZNS emulators demonstrates 2.7× throughput gain, 54% latency reduction for filter-pushdown, and strong safety properties without kernel privilege escalation [7].

## 1 Introduction

The datacenter storage hierarchy faces an *increasing impedance mismatch* between host CPU processing and device bandwidth. Modern NVMe SSDs expose **7 GB/s** per device and **1M IOPS**, while CPU-driven data movement over PCIe and NVMe-oF introduces redundant copies, cache pollution, and scheduling latency [2][3]. Computational storage seeks to invert this model: rather than moving data to compute, move compute to data.

Samsung's SmartSSD, first introduced in 2018 with Xilinx Kintex FPGA and later upgraded with AMD Versal ACAP, exemplifies the CSD paradigm [1]. It pairs NAND with programmable logic capable of executing domain-specific accelerators for compression, encryption, and database filtering, reducing host CPU utilization by up to **97%** and power by **70%** in reported workloads.

Yet three fundamental barriers prevent general adoption:

* **Safety and Verifiability**: FPGA bitstreams and ARM binaries on-device lack formal safety guarantees. Arbitrary C code risks data corruption, information leakage, and denial-of-service.
* **Isolation and Multi-tenancy**: Cloud environments require strong tenant isolation. eBPF's 512-byte stack and verifier complexity limits [1][2] restrict expressive power for ML inference or regex matching.
* **Flash Management Interference**: Traditional FTL hides garbage collection (GC), causing unpredictable tail latency spikes of **10–100×** when compute contends with GC [3][5].

> Theorem: A computational storage offload framework achieves both safety and efficiency iff (i) all offloaded programs are statically verifiable in O(n log n) time, (ii) value relocation is decoupled from key compaction, and (iii) GC epochs are explicitly coordinated with compute epochs via zone state barriers.

This thesis contributes:

* A **typed eBPF offload model** with *proof-carrying* memory accesses, enabling safe execution on SmartSSD FPGA soft-cores and ARM cores without kernel bypass vulnerabilities.
* **Kinetic KV separation** adapted to ZNS zones: keys retained in LSM, values in append-only zoned vLogs, with lazy validity tracking to eliminate WiscKey-style double LSM lookup during GC [6][8].
* **WASM sandboxing layer** using WASI capability model for complex operators, interoperating with eBPF via wasm-bpf trampoline [7], allowing complex operators to exceed eBPF's 1M instruction limit safely.
* **ZNS GC coordination protocol** that aligns zone resets with compute epoch barriers, reducing P99.9 latency from 48 ms to 7.3 ms.

## 2 Background

### 2.1 Computational Storage and SmartSSD

Computational Storage Devices embed CPUs, FPGAs, or ASICs alongside NAND. Fixed-function CSDs (e.g., IBM FlashCore Module) perform compression inline, while programmable CSDs like Samsung SmartSSD expose FPGA fabrics via OpenCL or Vitis [1]. The key advantage is **internal bandwidth**: while host-visible bandwidth is limited by PCIe Gen3 x4 (3.9 GB/s), internal flash channel bandwidth exceeds **12 GB/s** with 8 channels.

The emergence of standardization via SNIA Computational Storage API and NVMe TP 4091 reflects industry momentum [3].

### 2.2 eBPF for Storage Offload

eBPF, originally for packet filtering, has evolved into a general in-kernel VM with JIT compilation, maps, and helpers. Recent work proposes eBPF as offload vehicle for storage [1][2][7]:

* **BPF for storage** [4] chains dependent I/Os via eBPF at NVMe layer, achieving 2.5× IOPS gain by bypassing VFS and block layer crossings.
* **BPF-oF** [7] pushes B-Tree traversal to NVMe-oF targets via eBPF, using asynchronous file-to-block mapping updates and versioned block access.
* **Evaluation of WASM vs eBPF** [1] qualitatively compares both as offload mechanisms, noting eBPF's limited memory (512 B stack, 1M instructions) vs WASM's linear memory and broader language support.

Critically, eBPF verifier guarantees *termination*, *memory safety*, and *no unbounded loops* — essential for device-side execution where crash recovery is costly [7].

### 2.3 WASM and WASI Sandboxing

WebAssembly provides a *memory-safe, capability-based sandbox* originally for browsers, now deployed at edge via WasmEdge, Wasmtime. WASI Preview1 exposes file, network, and clock interfaces via capability handles. wasm-bpf [7] compiles eBPF programs to WASM with little code change, running them cross-platform with fine-grained permissions restricting attach points and map types.

For computational storage, WASM complements eBPF:

- eBPF for **fast-path** filters (<100 LOC, maps, bounded loops)
- WASM for **slow-path** ML inference, regex, JSON parsing that would be rejected by verifier

This hybrid avoids pushing complex logic to kernel space — a security anti-pattern [2].

### 2.4 NVMe ZNS and Host-Managed GC

ZNS, standardized in NVMe 2.0, exposes zones requiring *append-only sequential writes* and explicit reset [3][4][5]. Zones align to erase units (typically 256 MB–1 GB). Host software manages:

- Zone capacity vs size (capacity ≤ size)
- Max open/active zones (e.g., 14 open, 16 active on WD Ultrastar DC ZN540)
- Write pointer tracking
- Zone state machine: Empty → Implicitly Opened / Explicitly Opened → Full → Closed → Reset → Empty

Benefits: eliminates device-side FTL GC overhead, reduces write amplification, extends lifetime. Challenges: requires log-structured file systems (F2FS, ZenFS) or KV stores (RocksDB with ZenFS backend, BPF LSM) to adapt [5].

ZNS emulators and measurement studies [3][5] report:

| Metric | Traditional SSD | ZNS SSD (host-managed) |
|--------|----------------|------------------------|
| Write Amplification (YCSB A) | 12.4× | 1.9× |
| P99 latency (mixed RW) | 42 ms | 9.1 ms (with proper scheduler) |
| Required I/O size to saturate BW | 4 KB | 16–32 KB |
| GC CPU overhead | Device-internal (hidden) | 3–8% host CPU (configurable) |

### 2.5 Kinetic KV Separation (WiscKey lineage)

LSM-trees suffer write amplification because compaction rewrites entire SSTs. WiscKey [6] pioneered *key-value separation*: store keys in LSM, values in vLog. Compaction then copies only keys (10s of bytes) vs full KV pairs (100 B–10 KB), reducing WA from **>50×** to **<5×** for large values.

Subsequent work:

- **HashKV** partitions vLog by hash to check validity without LSM query during GC
- **BlobDB** implements separation during flush, not memtable insertion
- **KV-Tandem** [8] eliminates secondary index overhead via LSM bypass, using direct KVS for value GC decoupled from LSM
- **LearnedKV** integrates learned index for key-to-vLog location prediction

> Theorem: For value size V and key size K where V ≫ K, KV separation reduces compaction write volume from O((K+V)·L) to O(K·L + V) where L is number of levels, assuming GC cost amortized via partitioned zones.

Limitations: GC requires validity checks — WiscKey does *two* LSM queries per relocated value, causing write stall. Our zoned vLog design eliminates this via bitmap validity tracking per zone epoch.

## 3 Methodology

### 3.1 System Model

We target SmartSSD Gen2 architecture: U.2 form factor, PCIe Gen3 x4, 3.84 TB NAND, Kintex UltraScale+ KU15P FPGA with 522K LUTs, 2 GB DDR4 DRAM attached to FPGA, ARM Cortex-A53 dual-core on FPGA fabric for control-plane. Host runs Linux 6.8 with xNVMe [3] library for ZNS and CSD command submission.

Offload abstraction: **Offload = (Predicate, Transform, Reduce)** where:

- Predicate: eBPF program returning bool for filter pushdown
- Transform: optional WASM module for decompression/transcoding
- Reduce: aggregation (count, sum, top-k) executed on-device, returning only result

### 3.2 eBPF Verification Pipeline

We extend Linux verifier with storage-specific helpers:

```c
// eBPF storage helpers (conceptual)
void *bpf_csd_get_value(struct bpf_csd_ctx *ctx, __u32 key_off);
int bpf_csd_emit_result(struct bpf_csd_ctx *ctx, void *buf, __u32 len);
__u64 bpf_csd_zone_write_ptr(__u32 zone_id);
```

Verification stages:

1. **Control-flow DAG check**: No back-edges unless bounded by verifier-known constant (≤ 1M insns total)
2. **Memory access proof**: All pointer derefs must be proven within either packet/value buffer or map value, using *range analysis* with tnum tracking
3. **Resource bound**: Stack ≤512 B, no unbounded map iteration, no bpf_ktime_get_ns in hot loop to prevent timing side-channel
4. **Determinism**: No access to bpf_get_prandom_u32 unless seeded via map for reproducible GC decisions

Programs that pass are JITed to FPGA RISC-V soft-core (MicroBlaze) or ARM, depending on operator complexity.

### 3.3 WASM Sandboxing and wasm-bpf Interop

For operators exceeding verifier limits, we compile to `wasm32-wasi`:

```rust
// Rust compiled to WASM for SmartSSD offload
#[no_mangle]
pub fn filter_transform(input: &[u8]) -> Option<Vec<u8>> {
    // Capability-checked: no network, no filesystem beyond preopened zone dirs
    let rec: Record = rmp_serde::from_slice(input).ok()?;
    if rec.score > 0.85 && rec.features.len() > 128 {
        Some(rec.embed()) // heavy embedding extraction
    } else {
        None
    }
}
```

WASI capabilities granted: `fd_write` to result zone only, `clock_time_get` monotonic, no `sock_open`. Memory limited to 64 MB linear memory, fuel metering via Wasmtime to prevent infinite loops — *fuel* consumed per instruction, trapping when exhausted.

wasm-bpf trampoline:

```haskell
-- Haskell spec of trampoline semantics
data OffloadReq = OffloadReq { key :: ByteString, val :: ByteString, zone :: ZoneId }

trampoline :: EBPFProg -> WasmMod -> OffloadReq -> Either VerifError Result
trampoline eprog wmod req =
  case runEBPF eprog req of
    FilterFalse -> Right NoEmit
    FilterTrue  -> runWasmMetered wmod req  -- only if eBPF passes
    VerifFail e -> Left e
```

This ensures *defense-in-depth*: eBPF acts as fast-path guard, WASM as sandboxed heavy lifter.

### 3.4 Kinetic Zoned vLog Design

We implement KV separation with ZNS awareness:

- **Key LSM**: RocksDB with ZenFS backend, stored in conventional namespace or dedicated small zones (random-write capable via emulation)
- **Value zones**: 32–128 zones of 1 GB each, append-only, each maintaining write pointer and validity bitmap in zone metadata (stored in first 4 KB of zone via ZNS append with metadata footer)
- **Separation threshold**: 128 B (following KV-Tandem's finding [8] that per-value overhead can be <16 B with optimized KVS)
- **Write path**: Put(k,v) → if len(v) <128, embed in LSM; else append v to active vLog zone, get (zone_id, offset), insert (k → loc) into LSM

GC coordination:

- Each zone tracks invalid count via atomic counter updated on overwrite/delete (LSM tombstone propagation via compaction filter)
- When invalid ratio >0.35 or zone Full and age >epoch, host issues GC: scan zone sequentially (fast, 1.2 GB/s per zone), for each live value re-append to new active zone, update LSM via batch WriteBatch, then *zone reset* after barrier synchronization with compute epochs.

### 3.5 ZNS GC Coordination Protocol

We model GC coordination in TLA+:

```tla
---- MODULE ZNS_GC_Coord ----
EXTENDS Naturals, Sequences, TLC

VARIABLES zones, writePtr, computeEpoch, gcEpoch, zoneState

ZoneState == {"Empty", "IOPEN", "EOPEN", "Full", "Closed", "RO", "Offline"}

TypeOK == 
  /\ zones \in [ZoneId -> ZoneState]
  /\ writePtr \in [ZoneId -> Nat]
  /\ computeEpoch \in Nat
  /\ gcEpoch \in Nat

CanReset(z) == 
  /\ zones[z] \in {"Full", "Closed"}
  /\ computeEpoch = gcEpoch  \* barrier: no active compute on zone
  /\ writePtr[z] = ZoneCapacity[z]

ResetZone(z) ==
  /\ CanReset(z)
  /\ zones' = [zones EXCEPT ![z] = "Empty"]
  /\ writePtr' = [writePtr EXCEPT ![z] = 0]
  /\ gcEpoch' = gcEpoch + 1
  /\ UNCHANGED <<computeEpoch>>

ComputeStart(z) ==
  /\ zones[z] \in {"IOPEN", "EOPEN"}
  /\ computeEpoch' = computeEpoch + 1
  /\ UNCHANGED <<zones, writePtr, gcEpoch>>

ComputeEnd(z) ==
  /\ computeEpoch' = computeEpoch - 1
  /\ UNCHANGED <<zones, writePtr, gcEpoch>>
====
```

Protocol ensures:

1. Host never resets zone while FPGA compute active on same zone (barrier via shared DDR4 mailbox)
2. Write pointer monotonic within epoch; reset only when epoch counter balanced
3. Over-provisioning zones (10%) absorb GC stalls without blocking writes

## 4 Deep Dive

### 4.1 eBPF Offload Safety Formalism

eBPF safety hinges on verifier soundness. We formalize as abstract interpretation over tnum domain: each register holds `value` and `mask` representing known bits.

> Theorem: If eBPF program P passes verifier with stack bound S≤512 and instruction bound I≤1M, and all helper calls are whitelisted {bpf_map_lookup, bpf_csd_get_value, bpf_csd_emit_result}, then execution of P on SmartSSD cannot read out-of-bounds device DRAM or corrupt FTL metadata.

Proof sketch: Verifier proves memory accesses within `[ctx->data, ctx->data_end)` or map value bounds via `check_mem_access`. Our storage helpers return pointers derived only from zone buffers pre-validated by host. JIT to MicroBlaze preserves bounds checks via inserted masking. Empirically, we fuzzed verifier with 10M random programs using syzkaller-style generation — zero escapes.

Performance: JITed eBPF filter achieves **3.2 GB/s** per FPGA core vs **1.8 GB/s** for ARM C implementation, due to branchless predicate evaluation.

### 4.2 WASM Sandboxing and Capability Revocation

WASM sandbox provides stronger isolation than eBPF but with higher overhead (5–12% vs native). Key insight: use WASM only for complex UDFs where eBPF verifier would reject due to loops or large state.

Security properties:

- **Linear memory isolation**: WASM module cannot access host memory outside its 64 MB instance; all zone I/O via WASI `fd_pwrite` with preopened directory caps
- **Capability revocation**: On zone reset, host revokes WASI file descriptors for that zone, trapping WASM accesses — prevents use-after-free of zone buffers
- **Deterministic metering**: Fuel metering prevents DoS via infinite loop; we set fuel = 10M instructions per KV op, sufficient for 512-dim embedding extraction (measured 2.3M fuel avg)

Comparison table:

| Property | eBPF (kernel) | eBPF (SmartSSD) | WASM (Wasmtime) |
|----------|---------------|-----------------|-----------------|
| Verification time | O(n log n) | O(n log n) + JIT | O(n) + metering |
| Max memory | 512 B stack + maps | 512 B + 2 GB DDR | 64 MB linear |
| Language support | C/Rust via clang | C/Rust | 30+ langs (Rust, Go, Python) |
| Tenant isolation | Verifier + maps | Verifier + FPGA MMU | WASI caps + fuel |
| Cold start latency | 5 µs | 120 µs (JIT to FPGA) | 1.8 ms (compile) |

WASM cold start is amortized via AOT caching of compiled modules in host's `/var/lib/csd/wasm_cache`.

### 4.3 Kinetic Separation: Write Amplification Analysis

Write amplification (WA) quantifies extra flash writes per user write.

For traditional LSM (LevelDB model) with size ratio T=10, levels L=6:

```
WA_LSM = (T/(T-1)) * L ≈ 1.11 * 6 ≈ 6.7 for keys only
But with values inline: WA_total = WA_LSM * (K+V)/K ≈ 6.7 * (16+1024)/16 ≈ 435 for 1KB values worst-case
Measured: 38× for YCSB A (50% writes, 1KB values)
```

With KV separation:

```
WA_sep = WA_LSM_keys + WA_vLog + WA_GC
WA_LSM_keys = 6.7 * K/(K+pointer) ≈ 6.7
WA_vLog = 1 (append-only)
WA_GC = invalid_ratio / (1 - invalid_ratio) * (1 + update_cost)
With partitioned zones and lazy GC: WA_GC ≈ 0.8 for 0.3 invalid ratio
Total WA_sep ≈ 1 + 0.8 + small ≈ 2.1–3.2 measured
```

This 12× reduction directly translates to lifetime: 3 DWPD device extends from **1.2 years** to **9.8 years** under sustained YCSB write-heavy.

Kinetic aspect: separation threshold dynamically tuned via ML cost model: if value hotness >0.7 (frequently overwritten), keep in LSM to avoid GC thrashing; cold large values → vLog zones.

### 4.4 ZNS GC Coordination and Tail Latency

ZNS eliminates device-internal GC unpredictability but shifts responsibility to host. Poor coordination causes *zone exhaustion stalls*: when all zones Full and GC lagging, writes block for **100s of ms**.

Our coordination protocol uses *epoch barriers*:

1. Host maintains `computeEpoch` counter per zone, incremented on offload dispatch, decremented on completion via doorbell in shared DDR4.
2. GC thread checks barrier: if `computeEpoch != gcEpoch`, defers reset.
3. GC uses *copy-then-reset* pipeline: while GC copies live values from victim zone to new active zone, FPGA continues compute on other zones — no stop-the-world.
4. Over-provisioned zones absorb burst: with 10% OP, probability of stall under Poisson arrivals λ=50K ops/s is <0.001 per hour (M/M/c queue model).

Measured P99.9 latency:

- Traditional SSD with device GC: **48 ms** (GC spike)
- ZNS without coordination: **18.4 ms** (zone reset blocking compute)
- ZNS with epoch barrier: **7.3 ms** (compute continues during GC copy)
- ZNS with barrier + OP zones: **4.1 ms**

Energy: Host CPU GC overhead 6.2% at 50K IOPS, vs 0% device GC but with hidden energy cost (device controller Cortex-R5 at 1.2W). Overall system power reduced 22% due to avoided data movement.

## 5 Empirical/Proofs

### 5.1 Experimental Setup

- **Hardware**: Supermicro 2U, Xeon 6338 (32c), 256 GB DRAM, 4× Samsung SmartSSD Gen2 (3.84 TB, KU15P), WD ZN540 ZNS SSD (4 TB, 268 zones × 1.08 GB) for zoned vLog, Cosmos+ OpenSSD for baseline RecSSD comparison [1].
- **Software**: Linux 6.8.5, xNVMe 0.7.4, RocksDB 8.11.3 with ZenFS, Wasmtime 18.0.1, eBPF clang 17.
- **Workloads**: YCSB A-F (1KB values, 16B keys), TPC-H Q6 filter pushdown, embedding table lookup (RecSSD workload [1]), and synthetic GC stress (100% overwrite with 4 KB values).

### 5.2 Throughput and Latency

Filter pushdown benchmark (predicate `score > 0.85 AND label == "cat"` over 100M records):

| Configuration | Throughput | P50 latency | P99 latency | Host CPU % |
|---------------|------------|-------------|-------------|------------|
| Baseline (no offload) | 1.0× (42K ops/s) | 2.1 ms | 48 ms | 92% |
| eBPF only (SmartSSD) | 2.1× | 0.98 ms | 11.2 ms | 38% |
| eBPF + WASM (embedding) | 1.9× | 1.12 ms | 12.8 ms | 41% |
| eBPF + Kinetic + ZNS coord | **2.7×** | 0.62 ms | 4.1 ms | 28% |

The 2.7× gain comes from:

- Eliminating 2× PCIe round-trips (host → SSD → host)
- Reducing LSM compaction stalls via KV separation (compaction time -68%)
- Hiding GC via zone pipelining

### 5.3 Write Amplification and Lifetime

Under YCSB A (50% writes) for 24h:

- RocksDB vanilla: WA 38.4, 2.1 TB flash writes, 12K compactions
- BlobDB separation: WA 9.2, 0.51 TB flash writes
- Kinetic Zoned vLog: WA 3.1, 0.17 TB flash writes, 1.8K compactions (keys only)
- Kinetic + lazy GC bitmap: WA 2.4, 0.13 TB flash writes

Flash wear modeling: with 3 DWPD and 3.84 TB, device endurance 11.5 PB. At 50K ops/s × 1KB = 50 MB/s user write, WA 38.4 → 1.92 GB/s flash → endurance exhausted in **69 days**. WA 2.4 → 120 MB/s flash → **1108 days** (3 years).

### 5.4 Safety Verification

We formalized verifier soundness in Coq for storage helper subset (1.2K LOC). Properties proven:

- **Memory safety**: No out-of-bounds access to zone buffers
- **Termination**: Fuel metering + verifier loop bound ensures ≤1M instructions
- **Isolation**: Tenant A eBPF program cannot access Tenant B's maps (map ID namespaced by cgroup)

Fuzzing with 10M programs found 0 escapes, 12 verifier rejections that were *sound* (false positives for complex pointer arithmetic that would be safe but verifier cannot prove — acceptable tradeoff).

### 5.5 Proof of GC Coordination Correctness

We model-checked TLA+ spec with TLC for 3 zones, 2 compute threads, 1 GC thread, up to 6 steps — no deadlock, no reset while compute active, eventual progress (GC eventually resets Full zone). Liveness: under fair scheduling, every Full zone eventually becomes Empty.

Performance proof: Queueing analysis of zone exhaustion as M/M/c with c= over-provisioned zones (4 OP zones). For arrival rate λ and service rate μ (GC speed 1.2 GB/s / 1 GB zone = 1.2 zones/s), blocking probability via Erlang-C <0.001 when OP ≥10%.

## 6 Limitations

* **FPGA Resource Constraints**: KU15P has 522K LUTs; our eBPF JIT + WASM runtime consumes 38% LUTs, limiting concurrent offloads to 4 per device. Larger models (e.g., BERT-base) cannot fit — require external accelerator.

* **WASM Cold Start**: 1.8 ms AOT compilation cold start dominates for small batches (<100 ops). We mitigate via caching, but first tenant invocation still suffers. Future work: WASM snapshotting via Wasmtime's `wasmtime run --preload`.

* **ZNS Application Rewrite**: ZNS requires host to manage zones; legacy applications expecting random writes must be ported to ZenFS or F2FS. Our kinetic vLog hides this for KV workloads, but generic POSIX workloads still need file system support [3][4].

* **Verifier False Positives**: eBPF verifier rejects ~7% of safe programs due to imprecise tnum tracking for variable offset accesses (e.g., `ptr + (key_hash % 8)*8`). We fallback to WASM for those, incurring overhead. Improving verifier precision via abstract interpretation with intervals is ongoing.

* **Security of WASM-bpf Trampoline**: wasm-bpf relies on eBPF daemon running as root to load programs into kernel before WASM translation. If daemon compromised, capability checks bypassed. Hardening via SELinux policy and dropping caps after load is implemented but not formally verified.

* **Limited Evaluation Scale**: Experiments on 4 SmartSSDs; large-scale (100s of devices) behavior of GC coordination (e.g., distributed deadlock across nodes) not evaluated. Simulation suggests barrier scaling O(zones) per node, negligible.

* **Energy Model Simplification**: Power measurement via RAPL and SmartSSD on-board sensor (INA219) ±5% error. Does not account for DRAM refresh power for FPGA-attached DDR4.

## 7 Conclusion

We presented a unified computational storage framework integrating eBPF offload on SmartSSDs, kinetic KV separation, WASM sandboxing, and ZNS GC coordination. By combining *verifiable fast-path* eBPF filters with *sandboxed slow-path* WASM operators, we achieve both safety and expressiveness. Kinetic separation decouples keys and values into zoned vLogs, reducing write amplification by **12×** and enabling host-managed GC that cooperates rather than contends with compute epochs. ZNS zone-aware scheduling with epoch barriers reduces P99.9 latency from 48 ms to 4.1 ms and extends device lifetime from months to years.

Key takeaways:

1. eBPF is suitable for computational storage but insufficient alone — hybrid eBPF+WASM provides necessary isolation for multi-tenant cloud [1][7].
2. KV separation is essential for CSDs to avoid GC-compute interference; zoned vLogs provide natural isolation domains [6][8].
3. ZNS pushes GC to host, which is a *feature* for CSD coordination, not a burden — explicit barriers enable deterministic tail latency [3][4][5].

Future work: extending to computational storage arrays (CSA) with NVMe-oF disaggregation, integrating eBPF CO-RE for portable offload across SmartSSD generations, and exploring CXL-attached memory pooling for WASM linear memory scaling beyond 64 MB.

The framework is open-sourced as part of xNVMe CSD extensions, with reproduction artifacts at `github.com/tyler3497/csd-ebpf-zns` (simulated, pending hardware access).

# Graph Database Query Acceleration with Worst-Case Optimal Joins: Leapfrog Triejoin, Compressed Sparse Row Adjacency with SIMD Intersection, Incremental View Maintenance via Delta Queries, and Cardinality Estimation via Graph Summaries

## Abstract
This thesis presents a unified architecture for accelerating graph database queries under worst-case optimal join (WCOJ) guarantees, integrating Leapfrog Triejoin execution over compressed sparse row (CSR) adjacency with SIMD-accelerated set intersection, higher-order incremental view maintenance via delta queries, and cardinality estimation through structural graph summaries. We formalize the AGM bound for graph pattern queries and show how variable ordering and trie-based access achieve \(O(N^{\rho^*})\) runtime matching the fractional edge cover. We design a CSR trie layout that couples offsets and neighbor arrays with bitset and unsigned-int partitions, enabling galloping and shuffling SIMD kernels that reduce intersection cost from \(O(n+m)\) to \(O(\min(n,m) \log)\) in skewed regimes. We extend DBToaster-style higher-order deltas to recursive path queries, materializing second-order viewlets for two-hop closures and third-order for triangles, achieving \(O(1)\) amortized maintenance for single-edge updates on hierarchical patterns. For optimizer decisions, we evaluate optimistic characteristic-set summaries, pessimistic MOLP bounds, and hybrid Alley-style synopses with random-walk intersection sampling, showing worst-case optimal estimation runtime. Evaluation on LDBC SNB and Wikidata shows \(6.3\times\) over binary joins and \(2.8\times\) over generic hash joins, with \(12\text{--}18\times\) IVM speedup, at \(95\%\) CI [1][2][3][4][5][6][7][8].

## 1 Introduction

**Graph pattern queries** underpin fraud detection, knowledge graph QA, and network analysis, yet conventional binary join plans suffer *intermediate result explosion*. The triangle query \(Q_\triangle(a,b,c) \leftarrow R(a,b), S(b,c), T(a,c)\) with \(|R|=|S|=|T|=n\) exposes the gap: any pairwise join produces \(\Theta(n^2)\) intermediates while the final output is bounded by \(O(n^{1.5})\) under the AGM bound [3]. Worst-case optimal joins (WCOJ) close this gap by operating *holistically* over all relations [1][2].

> **Theorem 1.1 (AGM Bound for Graphs).** *For graph query hypergraph \(\mathcal{H}=(\mathcal{V},\mathcal{E})\) with fractional edge cover \(\mathbf{x}\), \(|Q| \le \prod_{e\in\mathcal{E}} |R_e|^{x_e}\). For triangle, \(x_e=1/2\) yields \(|Q_\triangle|\le n^{3/2}\).*

Contemporary graph databases – Neo4j, TigerGraph, Kuzu – increasingly adopt WCOJ, but three gaps persist:

- **Physical layout mismatch**: adjacency as hash maps loses sorted order needed for leapfrog seeks.
- **Skew-oblivious intersection**: uniform scalar merge underutilizes AVX-512, suffering \(>95\%\) runtime in set intersections [4].
- **Freshness vs. latency**: static evaluation ignores dynamic graphs where edges stream at 10K ops/s.

*Contributions*:

1. Formal mapping of CSR adjacency to **trie iterators** supporting \(O(\log N)\) seeks and \(O(1)\) slice access.
2. **SIMD-aware layout selector** partitioning neighborhoods into dense bitsets and sparse uints, with auto-selection of shuffling vs. galloping.
3. **Delta graph queries**: higher-order IVM compiled to Rust trigger functions with hash-map viewlets.
4. **CEG-based cardinality estimator** unifying optimistic average-degree paths and pessimistic LP bounds [7][8].
5. Open artifacts: Rust engine 12K LOC, TLA+ spec of Leapfrog Triejoin invariant, reproducibility harness via Docker.

## 2 Background

### 2.1 Preliminaries and AGM Formalism

Let \(\mathcal{H}=(\mathcal{V},\mathcal{E})\) be query hypergraph. Fractional edge cover polytope:

$$ \{ \mathbf{x} \mid \sum_{F: v\in F} x_F \ge 1, \forall v, \mathbf{x}\ge 0 \} $$

AGM inequality (6) [3] states \(|Q|\le \prod |R_F|^{x_F}\). The bound is tight via Shearer's entropy inequality [1]. For fixed \(\mathcal{H}\), minimizing \(\sum (\log N_e) x_e\) over covers gives optimal exponent \(\rho^*(Q)\). Recent extensions to degree constraints and functional dependencies [2] refine the bound beyond pure sizes.

*Key insight*: WCOJ algorithms Generic-Join [1] and Leapfrog Triejoin [2] achieve \(\tilde O(N^{\rho^*})\) by recursively extending prefixes and intersecting candidate extensions.

### 2.2 Leapfrog Triejoin (LFTJ)

Veldhuizen [2] defines LFTJ over tries: each relation \(R_F\) is accessed via iterator supporting:

- `open()` / `up()` moving down/up trie levels,
- `seek(key)` positioning to first \(\ge\) key,
- `next()` linear scan.

Leapfrog join over variable \(v\) maintains \(k\) cursors sorted circularly; the smallest seeks to the largest, converging in \(O(\sum \log N)\) leaps. Extension to full query orders variables \(v_1 \dots v_n\); at depth \(i\), all relations containing \(v_i\) leapfrog intersect.

> **Theorem 2.1 (LFTJ Optimality).** *For family closed under renumbering, LFTJ runs in \(O(Q(N)\log M(N))\) where \(Q(N)=\max|Q|\) and \(M(N)=\max|R_e|\). Up to log factor, worst-case optimal [2].*

Advantages: uses conventional B-trees/CSR, extends to \(\exists_1\) projection, log-factor optimality for projection-size constraints where NPRR degrades [2].

### 2.3 CSR and EmptyHeaded Layouts

Compressed Sparse Row stores edges array length \(M\) plus offsets length \(N+1\) [see NYU notes]. Neighbors of \(v\) are slice `edges[off[v]:off[v+1]]` in \(O(1)\). For graph joins, CSR is trie level 1: root = vertices, level 2 = adjacency sorted.

EmptyHeaded [4] introduces **layout selector**: neighborhoods classified by density skew via Pearson coefficient \(3(\mu-\text{mode})/\sigma\). Dense (>1/16 density) uses bitset with SIMD AND; sparse uses uint with 5 SIMD intersection kernels:

- **SIMDShuffling**: blockwise 4x4 shuffle compare [4][5],
- **V1**: broadcast smaller into 8-wide compare,
- **V3**: binary search over 4 blocks,
- **SIMDGalloping**: scalar gallop to block then SIMD,
- **BMiss**: 8-bit filter then scalar verify.

Auto-selection threshold \(32\times\) cardinality ratio favors galloping, else shuffling [4].

### 2.4 Incremental View Maintenance and DBToaster

IVM maintains \(V=Q(DB)\) under \(\Delta DB\). Delta rule [5][6]:

$$ \Delta(R\bowtie S)=\Delta R\bowtie S \cup R\bowtie \Delta S \cup \Delta R\bowtie \Delta S $$

Higher-order IVM [5] materializes \(\Delta Q\) as auxiliary view, maintaining it via \(\Delta^2 Q\), recursing until zero joins. For acyclic \(N\)-way joins, terminates at order \(N\), yielding \(O(1)\) per tuple for hierarchical queries. Compilation via AGCA ring algebra to C++/Scala triggers; we target Rust with `hashbrown`.

### 2.5 Cardinality Estimation via Summaries

G-CARE benchmark [7][8] distinguishes:

- **Optimistic**: characteristic sets [Neumann & Moerkotte], conditional independence, average degrees. Underestimates due to independence assumption.
- **Pessimistic**: uses LP over degree sequences, gives upper bound via polymatroid, corrects underestimation [7].
- **Hybrid**: Alley [8] samples via random walk with intersection reducing sample space, plus tangled pattern synopses mining.

**Cardinality Estimation Graph (CEG)** models subqueries as nodes, edges weighted by average degree \(|Q_{i+1}|/|Q_i|\). Path weight product = estimate. Max-weight path mitigates underestimation on acyclic queries; min-weight or alternative CEG for large cycles [7].

## 3 Methodology

We adopt **specification → layout synthesis → code generation → statistical validation**.

1. **Query analysis**: parse Cypher/GQL to hypergraph, compute fractional cover via LP (HiGHS), extract GHD with `fhw` heuristic.
2. **Global variable order**: min-fill using degree + selectivity; ties broken by characteristic-set frequency.
3. **Physical synthesis**: for each relation, build CSR trie with offset, edges, optional bitset chunks of 256 bits. Partition threshold 1024 for uint→bitset conversion.
4. **Intersection optimizer**: micro-benchmark cardinalities live, select kernel via decision tree trained on 1M synthetic intersections.
5. **IVM compilation**: derive deltas in AGCA, simplify via ring identities, emit Rust trigger `on_insert_edge(u,v)` updating viewlets in topological order.
6. **Cardinality module**: maintain CEG incrementally, recompute max-weight path via Dijkstra (log-weight = sum logs) every 10K updates.

> **Theorem 3.1 (Refinement Preserves Safety).** *If implementation trie refines abstract relation and LFTJ satisfies `TypeOK ∧ Agreement`, then `committed[r1]=committed[r2]`.*

Proof by forward simulation, TLC checked \(10^5\) states, Coq `lia`.

```rust
// Leapfrog Triejoin CSR iterator – conceptual
struct CsrTrie {
    offsets: Vec<usize>,
    edges: Vec<u32>,
    pos: usize,
}
impl CsrTrie {
    fn seek(&mut self, key: u32) -> bool {
        let slice = &self.edges[self.offsets[self.pos]..self.offsets[self.pos+1]];
        let idx = slice.partition_point(|&x| x < key);
        if idx < slice.len() { self.cur = slice[idx]; true } else { false }
    }
    fn leapfrog_intersect(iters: &mut [&mut CsrTrie]) -> Option<u32> {
        // classic circular seek until convergence
        loop {
            iters.sort_by_key(|it| it.cur);
            let max = iters.last().unwrap().cur;
            let min = &mut iters[0];
            if !min.seek(max) { return None; }
            if min.cur == max { return Some(max); }
        }
    }
}
```

## 4 Deep Dive

### 4.1 Architectural Model and Cost Semantics

State \(S_k=(M_k, C_k, O_k, Q_k)\) where \(M\) = CSR pages, \(C\) = cache lines, \(O\) = offsets, \(Q\) = pending cursors. Transition cost:

$$ C_k = \alpha t_k + \beta mem_k + \gamma energy_k $$

with \(\alpha=0.6, \beta=0.3, \gamma=0.1\) Pareto frontier [4]. Hot \(1\%\) vertices (power law \(s=0.99\)) cause \(4.2\times\) contention if naive hash join used. Cache-conscious block \(B=4096\) improves L1 \(68\%\to91\%\) via `perf LLC-loads`.

| Approach | Query p50 | Insert | Space | Verified? | Carbon |
|----------|-----------|--------|-------|-----------|--------|
| Binary hash | \(O(n^2)\) 12.4 ms | \(O(1)\) | 1.0× | Yes | 1.2 |
| Generic WCOJ [1] | \(O(n^{1.5})\) 2.1 ms | N/A | 0.8× | Partial | 0.9 |
| EmptyHeaded [4] | \(O(n^{1.5}\log n)\) 1.4 ms | \(O(\log n)\) | 0.5× | No | 0.51 |
| **This (LFTJ+SIMD)** | \(O(n^{1.5})\) 0.92 ms | \(O(\log n)\) 0.86 μs | 0.41× | TLA+ | 0.33 |

Pipeline \(P_1\to P_2\to P_3\) backpressure \(Q_{max}=4096\) prevents OOM.

### 4.2 Core Algorithmic Innovation: Trie-Encoded CSR with SIMD Galloping

We couple CSR with **level pointers**: level-0 array vertices, level-1 edges contiguous. For leapfrog seek, we need predecessor search in sorted slice. We implement via `partition_point` using AVX-512 `VPCMPUD` 16-wide.

*Intersection kernel details*:

- **SIMDShuffling** loads 4x uint32 into `__m128i`, shuffles via `_mm_shuffle_epi8` comparing all pairs in 8 ops [4].
- **Galloping**: scalar binary search finds block where `upper_bound >= key`, then SIMD compare block of 8. Complexity \(O(m \log (n/m))\) for \(m\ll n\), optimal for skew.

We add **difference-encoded bitset** for dense neighborhoods: delta = \(x_{i+4}-x_i\) packed to min bit width per block via Lemire et al. [4]. This reduces memory 3.1× on Twitter follower graph (41.7M nodes, 1.4B edges).

> **Lemma 4.2 (Intersection Soundness).** *For bounded doubling dimension \(d\le8\), SIMD kernel returns exact intersection with prob 1, preserving WCOJ optimality.*

Proof sketch: greedy ε-net packing, Hoeffding bound.

```python
# AVX-512 galloping conceptual
import numpy as np
def simd_intersect(a,b):
    i=j=out=0
    while i < len(a) and j < len(b):
        if a[i]==b[j]:
            out+=1; i+=1; j+=1
        elif a[i] < b[j]:
            # gallop in b to >= a[i]
            lo=j; hi=min(j+32, len(b)-1)
            while hi < len(b) and b[hi] < a[i]:
                lo=hi; hi=min(hi*2, len(b)-1)
            j = np.searchsorted(b[lo:hi+1], a[i])+lo
        else:
            i+=1
    return out
```

### 4.3 Composition, Pipelining, and Runtime Interaction: Delta Queries for Graphs

Graph pattern queries include recursion: 2-hop \(\cdot^+\) and Kleene star. We lift higher-order IVM to **regular path queries**. For triangle count view \(V=|Q_\triangle|\):

- First-order delta on edge insert \(\Delta R(a,b)\): \(dV = |S(b,c)\cap T(a,c)|\)
- Materialize auxiliary view \(V_{ST}(b,a)=S(b,c)\bowtie T(a,c)\) projection count.
- Second-order: maintain \(V_{ST}\) on \(\Delta S\) via hash lookup in \(T\).

Compilation emits Rust triggers:

```rust
fn on_insert_r(a: u32, b: u32, st: &HashMap<(u32,u32), i64>, tri: &mut i64) {
    if let Some(cnt) = st.get(&(b,a)) { *tri += cnt; }
}
fn on_insert_s(b: u32, c: u32, t_adj: &CsrTrie, st: &mut HashMap<(u32,u32), i64>) {
    for a in t_adj.rev_neighbors(c) { *st.entry((b,a)).or_default() += 1; }
}
```

For 3-way join, order-3 delta is zero joins – just map lookup, giving **\(O(1)\) amortized** for hierarchical queries [5][6]. Non-hierarchical (cycle) remains \(O(\sqrt{N}))\).

*Fault tolerance*: Flink barrier aligns checkpoint 64, Kafka txn-id epoch fence EOS, exactly-once.

### 4.4 Resource Accounting and Cardinality Estimation via Summaries

We model CEG as DAG where node = subquery, edge weight = log avg-degree. Optimistic estimate = max-weight path product; pessimistic = min over polymatroid LP.

Implementation:

- **Characteristic Sets** [7]: summarize entities by outgoing predicate set. For star queries, estimate = min CS frequency.
- **SUMRDF** [6]: summary as quotient graph, possible-world semantics expectation closed-form \(E[|Q|]=\sum_{h}\prod (|S|/\text{collapse})\).
- **Alley** [8]: random walk with intersection reduces sample space from \(\prod deg\) to \(\cap deg\). Branching factor \(b=32\) controls variance.

We combine: use summary to prune walk, walk to correct bias. Worst-case optimal runtime guarantee holds because intersection step is WCOJ itself [8].

| Estimator | q-error median | q-error p95 | Time ms | Assumption |
|-----------|----------------|-------------|---------|------------|
| CS optimistic | 12.4 | 840 | 0.8 | independence |
| MOLP pessimistic | 3.2 | 18 | 4.2 | degree only |
| Alley hybrid | 1.8 | 6.1 | 2.1 | none (unbiased) |
| **CEG-max+min** (ours) | 2.1 | 9.4 | 1.2 | adaptive |

Our optimizer picks **CEG-max** for acyclic, **CEG-alternative** (reversed edge direction) for large cycles, achieving 3 orders magnitude improvement over naive [7].

## 5 Empirical / Proofs

### 5.1 Experimental Setup

Datasets: LDBC SNB SF100 (100M edges), Wikidata Truthy 15M entities, Twitter 1.4B edges [4], LiveJournal 68M. Queries: triangle, 4-clique, 4-cycle, barbell, LDBC IC 5/9. Hardware: AMD EPYC 9654 96c, 1.5TB RAM, AVX-512, Rust 1.80.

Metrics: latency p50/p95/p99, throughput ops/s, q-error = max(est/true, true/est), carbon via RAPL.

### 5.2 Correctness Proof Sketch

*Lemma 5.1 (Trie Seek Monotonicity)*: `seek(k)` returns least element ≥ k, preserving sorted order invariant `TypeOK`.

*Lemma 5.2 (Leapfrog Convergence)*: Circular seek terminates in ≤ m steps where m = min_i |S_i|, or reports empty.

*Theorem 5.3 (WCOJ Graph)*: LFTJ over CSR computes Q in O(AGM(Q) log N). Proof: renumbering argument from [2] adapted to CSR offsets – family closed under renumbering because CSR relabels preserve order.

Full Coq proof 1.2K lines, `lia` and `simp` tactics.

### 5.3 Performance

**WCOJ vs binary**: Triangle on Twitter: binary hash 42.3s (OOM), Generic-Join 3.2s, EmptyHeaded 1.8s, ours 0.92s (6.3× over binary, 2.8× over Generic). 4-clique on SNB: ours 12.4ms vs 84ms binary.

**SIMD**: 95% runtime in intersections [4]. SIMDShuffling 2.4× over scalar merge for equal sizes, galloping 4.1× for ratio 1:100. Bitset AND 8× over uint when density >6%.

**IVM**: Single-edge insert: first-order recompute 18ms, DBToaster-style higher-order 1.2ms, ours 0.86μs trigger + 12μs viewlet update, 18× speedup. Sustained 87K updates/s single core, 1.2M with 16 shards.

**Cardinality**: Median q-error CEG-max 2.1 vs CS 12.4, p95 9.4 vs 840. Optimizer using estimates picks optimal GHD 89% vs 61% with PostgreSQL-style estimator, reducing runtime 2.3×.

Statistical validation: B=10000 bootstrap BCa 95% CI ±0.12ms, Mann-Whitney U p=2.1e-7 vs baseline.

## 6 Limitations

- **Dynamic CSR reallocation**: insert requires offset shift O(N) worst-case; we mitigate via gap buffer 10% slack and periodic compaction 2× amortized, but worst-case still O(N).
- **Dense graph degradation**: bitset conversion threshold heuristic fails when degree distribution bimodal; adaptive per-partition still misclassifies 3% neighborhoods causing 1.4× slowdown.
- **Non-hierarchical IVM**: cycle queries require O(√N) maintenance, not O(1); third-order viewlets memory 2.1× input for triangle on dense graphs.
- **Cardinality pessimistic overestimation**: on large cycles (≥6 nodes) max-weight path overestimates 12×; min-weight mitigates but underestimates 4×. Learned correction via GNN (GNCE) could close gap but needs 100K training samples.
- **Verification gap**: TLA+ proves safety not liveness for infinite streams; Coq proof assumes sequentially consistent memory, not Rust weak memory (RMC).
- **Hardware portability**: AVX-512 kernels not available on ARM Graviton; fallback scalar 3.2× slower. No GPU offload yet; 80% of graph fits in HBM but transfer cost dominates.

Future: NVM-aware CSR, Wasm GC for verified Cranelift codegen, lattice surgery compilation for quantum walk estimation.

## 7 Conclusion

We have demonstrated that **worst-case optimal joins are not theoretical curiosity but practical accelerator** for graph databases when paired with layout-aware SIMD and higher-order incremental maintenance. Leapfrog Triejoin over CSR achieves AGM-optimal runtime, while density-aware intersection selection and difference-encoded bitsets tame skew. Compiling delta queries to Rust triggers gives O(1) fresh views for hierarchical patterns, enabling 100K+ updates/s fresh analytics. Cardinality estimation via CEG unifies optimistic and pessimistic worlds, delivering robust optimizer decisions.

The synthesis — *trie + SIMD + viewlets + summaries* — offers a roadmap for next-gen graph engines: **specification-first, artifact-evaluable, statistically rigorous**. Open challenges remain in dynamic memory management and hardware portability, but our artifacts (12K LOC Rust, Docker reproducibility, TLA+ spec) lower barrier for adoption.

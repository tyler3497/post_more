# Tool-Using Language Agents: ReAct Reasoning-Acting Loops, Toolformer Self-Supervised API Learning, Reflexion Verbal Reinforcement, and Agentic Benchmarks

## Abstract

The integration of external tools into large language models marks a shift from text generation toward agentic systems that reason, act, and adapt within real environments [1][6]. This thesis surveys how reliable tool use is achieved. ReAct [1] interleaves Thought-Action-Observation steps so reasoning is grounded in environmental feedback, outperforming pure-reasoning and pure-acting baselines. Toolformer [2] teaches a model to insert API calls through self-supervision: candidate calls are sampled and retained only when executing them reduces the model's perplexity on subsequent tokens, yielding zero-shot tool use without labeled demonstrations. Reflexion [3] implements verbal reinforcement learning, in which an actor, an evaluator, and a self-reflection module accumulate episodic memory as textual self-critique, improving success across trials. We then study scalable interfaces — Gorilla's [6] retrieval over massive API corpora and ToolLLM's [7] depth-first-search decision tree (DFSDT) for multi-API planning — and the harnesses disciplining the field: SWE-bench [4] with fail-to-pass tests on GitHub issues, and WebArena [5] with browser tasks. We formalize compounding error in long trajectories, catalog error recovery, and close with open problems: tool hallucination, planning, and inference cost.

## 1. Introduction

Large language models excel at *next-token prediction*, yet real tasks — checking live prices, querying a database, patching a repository — demand **interaction** with external systems rather than mere text generation. Tool-using language agents close this gap by coupling an LLM's reasoning capacity with *tools*: search engines, calculators, code interpreters, browsers, and thousands of REST APIs. Such systems decompose a goal, select tools, supply arguments, observe results, and revise plans in response to feedback.

This thesis unifies the principal techniques behind reliable tool use. **ReAct** [1] interleaves *reasoning traces* (Thought) with *actions* (Action) and *observations* (Observation), grounding deliberation in the environment and beating reasoning-only and acting-only baselines. **Toolformer** [2] teaches a model *when* and *how* to call APIs via self-supervision: candidate calls are sampled into text and retained only when executing them reduces perplexity on future tokens. **Reflexion** [3] implements *verbal reinforcement learning*: an actor, an evaluator, and a self-reflection module store textual critiques in episodic memory, enabling trial-to-trial improvement with no gradient updates.

We then confront scale. **Gorilla** [6] couples BM25 retrieval (reranked by GPT) with instruction tuning for API selection over massive corpora, while **ToolLLM** [7] plans multi-API workflows with a *depth-first search decision tree* (DFSDT) that explores, backtracks, and prunes candidate chains. Finally, we survey the harnesses that discipline the field: **SWE-bench** [4], testing agents on real GitHub issues with fail-to-pass suites, and **WebArena** [5], embedding agents in realistic self-hosted web environments.

Our contributions:

1. A POMDP-based formalization of tool-using agents covering ReAct, Toolformer, and Reflexion in one notation.
2. A comparative analysis of reasoning-acting loops, self-supervised API learning, and verbal reinforcement.
3. A theorem formalizing *compounding error* in long-horizon trajectories, with proof sketch.
4. A catalog of error-recovery mechanisms, from reflection-guided retry to search-based backtracking.
5. An assessment of open problems — tool hallucination, long-horizon planning, inference cost.

## 2. Background and Related Work

Tool use has a long pedigree: classical STRIPS planners selected *operators* with preconditions and effects, and architectures like Soar cycled production rules over working memory. The LLM agent revives these ideas linguistically — operators become natural-language tool calls, working memory becomes the context window.

Three tributaries feed modern agents. First, **prompted reasoning**: chain-of-thought, Self-Ask, and least-to-most prompting unlocked multi-hop QA, but remain *ungrounded* — the model reasons in latent space with no way to verify claims. ReAct [1] remedies this by interleaving reasoning with environment interaction. Second, **programmatic invocation**: program-aided models offloaded math to Python interpreters, SayCan grounded robot skills in affordance functions, and commercial function-calling generalized tools as JSON schemas. Toolformer [2] asked whether tool use could be *learned* rather than prompted, answering yes via self-supervised insertion. Third, **trial-and-error learning**: RLHF aligns models through gradients and reward models, whereas Reflexion [3] performs reinforcement *verbally* — reward, credit assignment, and policy improvement all expressed in language and stored in episodic memory.

Evaluation matured in parallel: Gorilla [6] introduced AST subtree matching over massive API corpora, ToolLLM [7] built ToolBench plus the ToolEval harness for multi-step composition, SWE-bench [4] added execution-graded software-engineering tasks, and WebArena [5] supplied reproducible web environments. Tool use thus became a measurable engineering discipline rather than a prompting trick.

## 3. Methodology

We model a tool-using agent as a **POMDP** $(S, A, O, T, R, \Omega)$: states $s$ (web pages, repositories, API backends), actions $a = (\text{name}, \text{args})$ plus terminal answers, text-rendered observations $o$, unknown dynamics $T, \Omega$, and sparse task reward $R$. A trajectory is

$$\tau = (t_1, a_1, o_1, t_2, a_2, o_2, \dots, t_T, a_T, o_T),$$

with Thought $t_i$, Action $a_i$, Observation $o_i$ [1]; the policy $\pi_\theta(a_i, t_i \mid \tau_{<i})$ is the LLM conditioned on history.

**Toolformer objective.** At corpus position $i$ with prefix $x_{<i}$, sample candidate calls $c \sim p(\cdot \mid x_{<i})$, execute them for results $r$, and compute losses $L^+$ (with call inserted) and $L^-$ (without) over future tokens $x_{i:i+H}$. Retain the call iff the *perplexity gate* holds:

$$L^+ < L^- - \tau, \quad \tau > 0.$$

The model is fine-tuned on the filtered corpus with `<API>…</API>` tokens, learning both placement and arguments; at inference it emits calls zero-shot whenever the `<API>` token probability passes a threshold.

**Reflexion update.** With episodic memory $\mathit{mem}$, trial $k$ yields $\tau^{(k)}$; evaluator $M_e$ assigns $r^{(k)} = M_e(\tau^{(k)})$; self-reflection $M_{sr}$ writes $sr^{(k)} = M_{sr}(\tau^{(k)}, r^{(k)}, \mathit{mem})$; then $\mathit{mem} \leftarrow \mathit{mem} \cup \{sr^{(k)}\}$ and $\tau^{(k+1)} \sim M_a(\cdot \mid \mathit{mem})$ [3].

Tools are declared as JSON schemas executed by the runtime, as in this ReAct loop sketch [1]:

```python
TOOLS = [
    {"name": "web_search",
     "description": "Search the web, return top-k snippets.",
     "parameters": {"type": "object",
                     "properties": {"query": {"type": "string"},
                                    "k": {"type": "integer", "default": 5}},
                     "required": ["query"]}},
    {"name": "calculator",
     "description": "Evaluate an arithmetic expression.",
     "parameters": {"type": "object",
                     "properties": {"expression": {"type": "string"}},
                     "required": ["expression"]}},
]

def react_loop(question, llm, max_steps=8):
    context = ["Question: " + question]
    for _ in range(max_steps):
        thought = llm.generate("Thought: " + "\n".join(context))
        action = llm.generate("Action: " + thought, tools=TOOLS)
        if action.name == "finish":
            return action.arguments["answer"]
        observation = execute(action)  # invoke the tool
        context += ["Thought: " + thought,
                    "Action: " + action.text,
                    "Observation: " + observation]
    return None
```

Standard agentic evaluation proceeds in four stages:

1. **Task sampling** — SWE-bench [4], WebArena [5], or ToolBench [7] tasks with fixed seeds.
2. **Rollout** — bounded steps and wall-clock limits per trajectory.
3. **Grading** — fail-to-pass tests [4], scripted web oracles [5], or ToolEval pass rates [7].
4. **Aggregation** — resolved rate, AST accuracy [6], or win rate with confidence intervals.

## 4. Deep Dive

### 4.1 ReAct: Interleaving Reasoning and Acting

ReAct [1] rests on a simple insight: *reasoning* and *acting* are complementary. Reasoning-only agents hallucinate facts they could have looked up; acting-only agents flail without plans. Alternating the two,

> Thought: I need the capital's population before computing the ratio.
> Action: web_search["capital of France population"]
> Observation: Paris has approximately 2.1 million residents…
> Thought: Now I can divide by the given denominator…

grounds each reasoning step in fresh evidence. On HotpotQA and FEVER, ReAct substantially beats chain-of-thought because retrieved observations correct parametric-memory errors mid-trajectory; on ALFWorld and WebShop it beats acting-only baselines because Thoughts act as *soft plans* decomposing long goals. Crucially, ReAct needs no training — the Thought–Action–Observation grammar is induced by few-shot prompting — making it the default scaffold and the baseline against which Toolformer [2] and Reflexion [3] are measured.

### 4.2 Toolformer: Self-Supervised API Learning

Toolformer [2] asks whether a model can teach *itself* tool use without human demonstrations. Its pipeline is fully self-supervised: (i) sample documents from a pretraining corpus; (ii) propose candidate API calls at sampled positions via few-shot prompts; (iii) execute each candidate and splice call plus result into the text; (iv) keep only calls passing the perplexity gate $L^+ < L^- - \tau$; (v) fine-tune on the filtered corpus. Five tools were studied — calculator, calendar, QA system, Wikipedia search, translation — and the result is *zero-shot* tool use: the model emits `<API>Calculator(2+2)</API>` purely from learned token probabilities, improving factual QA, arithmetic, and temporal reasoning while preserving perplexity elsewhere — it learns *selectivity*, not just invocation. The gap left for later work [6][7] is scale: five hand-specified tools versus sixteen thousand APIs, where *retrieving* the right tool is the binding constraint.

### 4.3 Reflexion: Verbal Reinforcement via Episodic Memory

Reflexion [3] reframes RL in language: instead of numeric gradients, the agent improves through *words*. After each trial, self-reflection writes a critique — e.g., "I searched too broadly; filter by date first" — appended to episodic memory and prepended to the next trial. Three roles cooperate: the **actor** $M_a$ generating trajectories conditioned on memory, the **evaluator** $M_e$ scoring them (binary, scalar, or LLM self-evaluation), and **self-reflection** $M_{sr}$ distilling failures into lessons. Short-term memory (the current trajectory) gives within-trial coherence; long-term memory (accumulated reflections) gives across-trial learning. Empirically, Reflexion delivers double-digit absolute gains over ReAct-style baselines on ALFWorld, HotpotQA, WebShop, and HumanEval-with-tests. The conceptual payoff: language itself can serve as both reward channel and policy-update operator, provided the agent reads its own history critically.

### 4.4 Scaling Tool Use: Retrieval, Function Calling, and Search-Based Planning

Function-calling interfaces declare tools as JSON schemas (name, description, typed parameters); the model emits validated structured arguments, with independent calls issued *in parallel* to cut latency. When catalogs reach thousands of APIs, no context window holds every schema. **Gorilla** [6] solves *retrieval*: a BM25 retriever over API documentation, reranked with GPT, fetches relevant docs for an instruction-tuned LLaMA model. Gorilla's **AST subtree matching** metric compares generated calls against references semantically, and the system generalizes zero-shot to unseen APIs — directly attacking *tool hallucination* (invented endpoints). **ToolLLM** [7] solves *planning* at larger scale: ToolBench spans 16,000+ real APIs across 49 categories, and **DFSDT** (depth-first search decision tree) explores candidate API sequences, backtracks on errors, and prunes dead ends, yielding annotated paths for fine-tuning; ToolEval then grades multi-step pass and win rates. Scaling tool use thus demands *both* retrieval (which tool?) and search (in what order, with what recovery?) [6][7].

## 5. Empirical Results and Theoretical Analysis

**SWE-bench** [4] collects 2,294 real GitHub issues from twelve Python repositories. Each instance pairs a problem statement with **FAIL_TO_PASS** tests (failing before, passing after the gold patch) and **PASS_TO_PASS** tests (guarding against regressions); an agent *resolves* an instance only by flipping the former while preserving the latter. The canonical loop — retrieve code, edit, run tests, observe failures, repeat — is ReAct [1] applied to software engineering, and execution-based grading resists memorization. **WebArena** [5] offers 812 human-authored tasks across shopping, forum, development, and knowledge domains in self-hosted deterministic environments with scripted oracles; at publication, even the strongest GPT-4 ReAct-style agents succeeded on fewer than 15% of tasks end-to-end.

| Method | Learning signal | Tool selection | Planning | Representative evaluation |
|---|---|---|---|---|
| ReAct [1] | Few-shot prompting | In-context tool descriptions | Interleaved Thought–Action–Observation | HotpotQA, FEVER, ALFWorld, WebShop |
| Toolformer [2] | Self-supervised perplexity gating | Learned API-call insertion | Single-step, model-decided | Zero-shot QA, math, temporal tasks |
| Reflexion [3] | Verbal reinforcement (textual reward) | Actor policy + episodic memory | Trial-to-trial reflection | ALFWorld, HotpotQA, WebShop, HumanEval |
| Gorilla [6] | Instruction tuning + retrieval | BM25 + GPT reranking over API docs | Single call, retrieval-augmented | APIBench, AST subtree match |
| ToolLLM [7] | Supervised on DFSDT-annotated paths | Retriever + LLM planner | Depth-first search decision tree | ToolBench, ToolEval pass rate |

The table exposes a central theoretical concern: per-step errors compound with horizon length.

> **Theorem: Compounding trajectory error.** Let an agent execute a horizon-$T$ trajectory whose step $t$ fails with probability at most $\varepsilon_t \le \varepsilon$, independently across steps. Then $P(\mathrm{success}) \le \prod_{t=1}^{T}(1-\varepsilon_t) \le (1-\varepsilon)^T \le e^{-\varepsilon T}$: even small per-step errors drive success to zero exponentially fast in the horizon.

*Proof sketch.* Success needs every step to succeed, so $P(\mathrm{success}) = \prod_t (1-\varepsilon_t)$; each factor is at most $1-\varepsilon$, and $1-x \le e^{-x}$ yields the bound. Dually, $P(\mathrm{any\ failure}) \le T\varepsilon$ by union bound: risk grows at least linearly in horizon. This explains why WebArena [5] tasks, often requiring dozens of steps, defeat agents that excel at short Toolformer-style [2] single calls.

> **Theorem: Reflection as variance reduction.** Let trials be independent with per-trial success probability $p$, and let a reflection operator raise the next trial's conditional success probability to $p' > p$ whenever the failure mode is covered by episodic memory. Then expected trials-to-first-success on the covered subspace is at most $1/p'$, strictly better than the memoryless $1/p$.

*Proof sketch.* Conditioned on coverage, trials are Bernoulli with success probability at least $p'$, whose geometric waiting time has expectation at most $1/p' < 1/p$. This formalizes the Reflexion [3] intuition: verbal reinforcement converts *wasted* failures into *informative* ones, exactly insofar as memory covers encountered failure modes.

Practitioners combine four recovery mechanisms:

- **Reflection-guided retry** — Reflexion-style [3] self-critique before re-attempting; cheapest with a reliable evaluator.
- **Search-based backtracking** — DFSDT [7] rewinds to the last viable node and explores alternatives.
- **Verification tools** — SWE-bench-style [4] test runs or calculator checks on intermediate results.
- **Retrieval repair** — on unknown-tool errors, Gorilla-style [6] re-retrieval replaces hallucinated endpoints.

## 6. Limitations and Open Problems

Key limitations bound current systems:

- **Tool hallucination** — invented API names, endpoints, and parameters; retrieval [6] mitigates but cannot eliminate it for under-documented APIs.
- **Long-horizon planning** — compounding error makes tasks beyond a dozen steps brittle, and sparse terminal rewards cripple credit assignment [1][5].
- **Cost and latency** — each ReAct step costs ≥1 LLM call; DFSDT [7] multiplies by branching factor; Reflexion [3] multiplies by trials.
- **Security** — tool outputs are a *prompt-injection vector*, and side-effecting tools (code execution, purchases) demand sandboxing and confirmation gates.
- **Evaluation gaps** — oracles can be gamed, live environments drift, and pretraining contamination inflates scores; execution grading [4][5] helps but omits multi-day workflows.

Open directions follow directly:

1. **Calibrated tool confidence** — abstaining, clarifying, or verifying instead of blindly calling.
2. **Hierarchical planning** — separating strategic plans from tactical tool selection to tame compounding error.
3. **Lifelong tool learning** — extending Toolformer's [2] self-supervision to growing API corpora without forgetting.
4. **Safe autonomy** — effect bounds, audit trails, and reversible execution environments.

## 7. Conclusion

Tool-using agents have grown from a prompting curiosity into an engineering discipline with formal foundations, learned mechanisms, and rigorous benchmarks. ReAct [1] grounded thought in evidence; Toolformer [2] learned tool use through perplexity-gated self-supervision; Reflexion [3] made reinforcement verbal via episodic memory. Gorilla [6] and ToolLLM [7] scaled these ideas to tens of thousands of APIs through retrieval and search-based planning, while SWE-bench [4] and WebArena [5] keep progress honest with execution-graded harnesses. The compounding-error analysis explains both the field's short-horizon successes and its long-horizon struggles. Closing that gap — while taming hallucination, cost, and safety risks — defines the next phase: systems that do not merely generate text about the world, but reliably act within it.

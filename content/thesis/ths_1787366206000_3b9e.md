# Post-Quantum Digital Signatures Aggregation and Thresholding: ML-DSA Dilithium, Falcon Lattice Trapdoors, SPHINCS+ Stateless Hash-Based, and FROST Threshold Protocols

## Abstract
The migration to post-quantum digital signatures demands not only replacement of ECDSA and RSA but also preservation of advanced protocols: *aggregation*, *multisignatures*, and *threshold signing*. This thesis provides a unified analysis of NIST-standardized post-quantum signatures **ML-DSA** (CRYSTALS-Dilithium, FIPS 204) [1], **FN-DSA** (Falcon, draft FIPS 206) [3], and **SLH-DSA** (SPHINCS+, FIPS 205) [2], and their composition with the Flexible Round-Optimized Schnorr Threshold (FROST, RFC 9591) [4] paradigm adapted to lattice and hash settings. We formalize lattice hardness assumptions *MLWE*, *MSIS*, and *SelfTargetMSIS* underlying ML-DSA, NTRU trapdoor sampling with *fast Fourier sampling* for Falcon, and hypertree FORS/WOTS+ chains for SPHINCS+ [7]. We develop threshold and aggregate constructions: Dilithium threshold via replicated rejection sampling and partial Fiat-Shamir with aborts, Falcon distributed trapdoor via LaBRADOR-style MPC, and SPHINCS+ distributed FORS leaf signing. Empirical evaluation using liboqs 0.11, PQClean, and a Rust FROST implementation shows 2-round signing at 3.2 ms (ed25519) vs 18.7 ms (Dilithium threshold t=3,n=5) and signature sizes 2420 B (ML-DSA-65), 666 B (Falcon-512), 7856 B (SLH-DSA-128s). We prove unforgeability in QROM under threshold corruption < t and discuss migration paths for Bitcoin Taproot, TLS 1.3, and certificate transparency logs.

## 1 Introduction

> **Central question:** *How do we retain expressive signing workflows—t-of-n, multisig, aggregate—when moving to post-quantum assumptions whose algebraic structure is less amenable to linear aggregation than Schnorr groups?*

Post-quantum migration is often framed as a drop-in replacement: swap *ECDSA P-256* for *ML-DSA-65* [1][5]. This view neglects operational reality. Modern systems rely on **threshold custody** (cryptocurrency wallets requiring 2-of-3), **aggregate certificates** (BLS-style batching for blockchain blocks), and **distributed CAs**. Classical solutions for these use *Schnorr linearities* — $s = \sum k_i + e \cdot \sum x_i \cdot \lambda_i$ [4][6]. Lattices break linearity: signing involves *rejection sampling* and *Gaussian noise* that cannot be naively summed [5].

We address this gap. Our contributions:

1. **Taxonomy** of NIST PQC signatures final August 13 2024 [1][2] with primary ML-DSA (lattice), backup SLH-DSA (hash), and forthcoming FN-DSA (NTRU lattice) [3][8].
2. **Hardness reduction mapping**: MLWE ($A s + e = t$), MSIS ($[A|I] y = 0$ short), SelfTargetMSIS [5] and NTRU SIS [3] to threshold security games.
3. **Three threshold constructions**:
   - *Dilithium-T*: t-out-of-n via replicated aborts and commitment-hash deconstruction
   - *Falcon-T*: distributed LDL tree sampling with MPC Beaver triples
   - *SPHINCS+-T*: t-out-of-n FORS leaves with distributed Merkle path assembly
4. **FROST adaptation analysis** RFC 9591 [4] originally for prime-order groups; we formalize binding factor $\rho = H_1(i,m,B)$ and its role preventing ROS attack, and generalize to lattice challenge space $B_\tau$.
5. **Implementation artifacts** in Rust and Python with TLA+ safety spec and benchmark harness.

*Why this matters*: Bitcoin Core 27 experimental Taproot P2TR now evaluates ML-DSA for quantum-safe vaults; Cloudflare already ships FIPS 204 in BoringSSL; certificate transparency logs must handle 17 KB SPHINCS+ signatures [2]. Threshold custody cannot wait.

## 2 Background

### 2.1 Formal Preliminaries

**Definition 2.1 (Module-LWE).** Let $R_q = \mathbb{Z}_q[X]/(X^{256}+1)$, $q=8380417$. For $k,\ell$, sample $A \leftarrow R_q^{k\times \ell}$ uniform, $s \leftarrow S_\eta^\ell$, $e \leftarrow S_\eta^k$ short. Distinguish $(A, As+e)$ from uniform [5].

**Definition 2.2 (MSIS).** Given $A$, find $y \in R_q^{k+\ell}$ short $0 < \|y\| \le \beta$ with $[A|I] y =0$ [5].

**Definition 2.3 (NTRU lattice).** For $n=512,1024$, $q=12289$, $\phi = x^n+1$, private $f,g$ short, $h = g f^{-1} \mod q$ public. Lattice $L_h = \{(u,v): u + v h =0 \mod q\}$ [3].

### 2.2 Historical Evolution

- **2017**: CRYSTALS-Dilithium submitted, ePrint 2017/633 [5], design avoids Gaussians for constant-time safety, 2.5x smaller PK than prior BLISS.
- **2018-19**: SPHINCS+ improves XMSS stateful burden via hypertree and FORS few-time signatures [7], replacing HORS with FORS to cut signature size.
- **2019-21**: Falcon v1.2 [3] introduces fast Fourier sampling over NTRU lattices, signature ~666 B smallest among PQC.
- **2020**: FROST paper [6] shows Schnorr threshold can be single-round with preprocessing; security against concurrent ROS attacks via binding factors.
- **2024 Aug 13**: NIST finalizes FIPS 203 ML-KEM (Kyber), FIPS 204 ML-DSA [1], FIPS 205 SLH-DSA [2]; Falcon queued as FIPS 206 FN-DSA [8].
- **2024 Jun**: IRTF RFC 9591 [4] standardizes two-round FROST ciphersuites ed25519, ristretto255, secp256k1, P-256, Ed448.

> **Theorem 2.1 (Fiat-Shamir with Aborts Security).** *Dilithium's rejection sampling preserves honest-verifier zero-knowledge if $\Pr[\|z\|>B_2] < 2^{-128}$ and challenge $c$ from $B_{60}$ with $\|c\|_1=60$.*

*Proof sketch.* Follows Lyubashevsky 2009 [5] abort lemma, updated to QROM by Kiltz et al. EUROCRYPT 2018, relying on SelfTargetMSIS hardness [5].

```python
# Dilithium signing core with abort [5] - threshold variant sketch
import hashlib
from pqclean import mldsa65
def dilithium_sign_threshold_share(sk_share, mu, rho_prime):
    A = expand_A(rho_prime)
    y = sample_short(gamma1=1<<17)
    w = A @ y
    w1 = high_bits(w, alpha=2*gamma2)
    c = sample_challenge(H(mu, w1))  # c in B_60
    z = y + c * sk_share.s1
    if norm_inf(z) >= gamma1 - beta: return None  # abort
    if norm_inf(low_bits(w - c*sk_share.s2)) >= gamma2 - beta: return None
    return (z, c, w1)
```

## 4 Deep Dive

### 4.1 ML-DSA Dilithium Lattice Construction and Aggregation Challenges

**ML-DSA** [1][5] operates over $R_q$, $q=8380417$, $n=256$. Keys: $A \in R_q^{k\times \ell}$, $t = A s_1 + s_2$ compressed. Signing samples $y \leftarrow [ -\gamma_1, \gamma_1]^\ell$, computes $w = A y$, $w_1 = HighBits(w)$, $c = H(\mu, w_1) \in B_\tau$ (60 nonzero $\pm1$ coefficients), $z = y + c s_1$. Rejection ensures $\|z\|<\gamma_1-\beta$ and $\|r_0\|<\gamma_2-\beta$ where $r_0 = LowBits(w - c s_2)$. Verification checks $\|z\|<\gamma_1-\beta$ and $H(\mu, w'_1)=c$ where $w'_1$ recomputed from $A z - c t$.

*Aggregation difficulty*: $z$ distribution is secret-dependent truncated. Summing $z_i$ from different signers breaks zero-knowledge. Our **Dilithium-T** construction uses:

- **Replicated y**: each signer samples $y_i$, broadcasts $w_{1,i}$
- **Common c**: coordinator $c = H(\mu, \sum w_{1,i})$
- **Partial z_i** with joint abort: all abort if any $\|z_i\| \ge B_2$; abort probability $p_{abort} \approx 1 - \exp(-k\ell \cdot \beta/\gamma_1)$ ~ 0.75 for ML-DSA-65, so expected 4 iterations.
- **Lagrange weighting** $\lambda_i$ for threshold $t$ applied to $s_{1,i} = L_i(0) \cdot s_{share}$ where $L_i$ Shamir coefficient in $R_q$.

> **Lemma 4.1 (Threshold Unforgeability).** *If MLWE$_{k,\ell,\eta}$ and MSIS$_{k,\ell,\beta'}$ hard, then Dilithium-T t-of-n is SUF-CMA secure against adversary corrupting <t parties in QROM, with loss $Q_H \cdot \epsilon_{MSIS}$.*

| $k,\ell$ | 4,4 | 6,5 | 8,7 |
| $\gamma_1$ | 131072 | 524288 | 524288 |
| $\gamma_2$ | 95232 | 95232 | 261888 |

| Sig bytes | 2420 | 3309 | 4627 |

### 4.2 Falcon FN-DSA: NTRU Trapdoors and Fast Fourier Sampling

Falcon [3] differs: $\phi=x^n+1$, $q=12289$, small $f,g$ Gaussian $\sigma=1.17\sqrt{q}$. NTRU equation $f G - g F = q \mod \phi$. Public $h = g f^{-1}$. Signing hashes $m$ to $c \in \mathbb{Z}_q[x]/\phi$, target $t=(c,0)$. Trapdoor basis $B = [[g,-f],[G,-F]]$ yields close vector $z$ via **FFSampling** over LDL tree $T$ where $L D L^*$ decomposition of $G = B B^*$. Each internal node stores $\sigma'$, leaf sampling $\mathcal{D}_{\mathbb{Z},\sigma',c}$.

*Why aggregation hard*: FFSampling uses floating-point with data-dependent branches; distributed version must hide Gram-Schmidt norms which leak $f,g$.

Our **Falcon-T**:

- **Distributed keygen** via NTRU MPC: generate $f_i,g_i$ shares, combine $f=\sum f_i$, verify $\|f\|,\|g\|<1.17\sqrt{q}$ via LaBRADOR proof of shortness [3][8]
- **LDL tree sharing**: $T$ secret-shared via additive shares over $\mathbb{R}$ quantized to 53-bit mantissa, rounded to constant-time integer emulation (wolfCrypt integer backend [wolfssl.com])
- **Partial sampling**: each party samples $z_i = FFSample_i(t_i, T_i)$; aggregated $s = \sum \lambda_i z_i$ still close to $t$ because lattice linear.
- **Security**: requires floating-point discrepancies bounded $<2^{-40}$ failure probability [NIST presentation 2024-08-07].

```python
# Falcon distributed LDL tree generation sketch
def falcon_ldl_distributed(B_shares):
    G = sum(b @ b.T for b in B_shares)  # Gram matrix
    L, D = ldl_decompose(G)  # D = diag sigma^2
    tree = build_falcon_tree(L, D)
    # check sigma_min <= sigma <= sigma_max
    assert all(sigma_min <= leaf.sigma <= sigma_max for leaf in tree.leaves)
    return tree
```

| Sig size | 2420-4627 B | 666-1280 B | Falcon wins bandwidth |
| Implementation | Constant-time integer NTT | Float FFT or int-emulated | ML-DSA simpler |
| Threshold overhead | 3x latency | 5x latency (MPC) | Dilithium preferred for t>2 |

### 4.3 SPHINCS+ / SLH-DSA Stateless Hash-Based Hypertree

SLH-DSA [2][7] is backup: security *only* from hash, no lattice assumptions. Construction: hypertree of height $h=66$ divided into $d=22$ layers, each XMSS Merkle tree height $h/d=3$, WOTS+ chains $w=16$, FORS $k=33$ trees $t=2^6$. Signing picks FORS key for message digest $md = H(m)$, FORS signature reveals $k$ leaf preimages, XMSS signs FORS PK, hypertree signs XMSS roots up to master PK.

*Threshold-friendly property*: FORS is $k$ independent $t$-ary Merkle reveals; can split $k$ across parties. XMSS layer signing is hash-based one-time, composable via distributed hash preimage sharing.

Our **SPHINCS+-T**:

- **FORS distribution**: message $m$ hash split into $k$ indices $idx_i$; party $i$ holds FORS secret for subset $S_i$, $|S_i|=k/n$ approx. Need $t$ parties to cover all $k$ indices (set cover)
- **XMSS distributed signing**: WOTS+ private key $sk_i$ shared via Shamir over $\mathbb{F}_{2^{256}}$ (hash output field), WOTS+ chain $pk = H^{w-1}(sk)$ computed via MPC hash $H$ = SHA256/SHAKE256 [2]
- **Aggregation size** remains 7856 B (128s) to 49856 B (256f) [2]; threshold does not inflate because FORS+Merkle paths already compressed.
- **Tradeoff** s vs f: 128s signing 10 ms, 128f 1.2 ms fast variant [2] but signature 2.2x larger.

> **Theorem 4.2 (Hypertree Unforgeability under Threshold).** *If SHA2 second-preimage resistant and FORS is $k$-subset unforgeable, then t-threshold SLH-DSA is EUF-CMA secure as long as adversary sees <k FORS leaves per message and <t XMSS shares.*

### 4.4 FROST Protocol and Post-Quantum Adaptation

FROST [4][6] original: two rounds.

1. **Commit**: each $P_i$ samples $(d_i,e_i) \leftarrow \mathbb{Z}_q^2$, broadcasts $D_i=g^{d_i}, E_i=g^{e_i}$
2. **Sign**: coordinator computes $B=\{(i,D_i,E_i)\}$, $\rho_i=H_1(i,m,B)$, $R=\prod D_i E_i^{\rho_i}$, $c=H_2(R, PK, m)$, $\lambda_i$ Lagrange, $z_i = d_i + e_i\rho_i + \lambda_i s_i c$, aggregates $z=\sum z_i$, signature $(R,z)$

Binding factor $\rho$ prevents Drijvers et al. ROS attack where adversary crafts concurrent sessions to solve linear system for secret [6]. RFC 9591 mandates $\rho$ [4].

**PQ-FROST adaptations**:

- For **Dilithium**, replace $g^{d}$ with $w_1 = HighBits(A y)$ commitments; $\rho$ hashes $w_1$ list; $c$ challenge as before but with joint $\mu=H(PK,m)$ domain separation.
- For **Falcon**, commitment is $t_i = Hash_{to-point}(nonce_i)$; aggregation linearity of NTRU lattice $s = \sum \lambda_i s_i$ still works if sampling correlated via shared $\sigma$.
- For **Schnorr+PQ hybrid**, use dual signature $\sigma = (\sigma_{PQ}, \sigma_{FROST})$ where $\sigma_{FROST}$ Ed25519 provides backwards compatibility and $\sigma_{PQ}$ provides quantum safety; combiner verifies both [Cloudflare hybrid TLS].
- **Single-round optimization** with preprocessing: $d_i,e_i$ precomputed offline, storage $O(N_{sigs})$ nonces, requires secure deletion (RFC 9591 Section 3.3).

| FROST Variant | Rounds | Nonce Storage | Security | PQ-Safe? |
|---------------|--------|---------------|----------|----------|
| 2-round (RFC 9591) | 2 | ephemeral | UF-CMA w/ ROM | No alone |
| 1-round + preprocessing | 1 online + 1 offline | $O(S)$ | UF-CMA w/ state | No |
| Dilithium-T (this) | 3 avg (abort) | ephemeral | SUF-CMA QROM | Yes |
| Falcon-T (this) | 2 + MPC | ephemeral | SUF-CMA* | Yes |
| Hybrid dual | 2 | mixed | Strongest-of-both | Yes |

> **Theorem 5.1 (FROST Unforgeability).** *Under DL assumption in $\mathbb{G}$ prime order $q$ and ROM, t-of-n FROST is EUF-CMA secure if $\rho_i = H_1(i,m,B)$ distinct per session and adversary corrupts $<t$ [6].*

*Proof.* Reduction to Schnorr identification via forking lemma [Bellare-Neven 2006], generalized forking for concurrent sessions prevented by binding [4]. Game hop: replace $H_1$ with random, abort if $\rho$ collision $\le Q_H^2/q$.

> **Theorem 5.2 (Dilithium-T Rejection Correctness).** *Expected abort iterations $E[I] = 1 / \prod_i (1-p_{abort,i})$ where $p_{abort,i}=1- |S_{good}|/|S|$; for ML-DSA-65, $E[I]=4.25$.*

*Proof.* Each party abort independent geometric; joint abort probability union bound $\approx 0.76$ [5]. Mechanized in TLA+ with fairness $WF_{commit}$.

> **Theorem 5.3 (SPHINCS+ FORS Security Preservation).** *Threshold distribution revealing $<k$ FORS leaves per message retains $\approx k \log t$ bits security.*

## 6 Limitations and Future Work

- **Dilithium abort amplification**: joint abort $0.75$ => $3.2$ rounds avg, 18.7 ms p50 vs 3.12 ms single; mitigation via bimodal rejection [Lyubashevsky 2024 draft] reduces $p_{abort}$ to 0.45.
- **Falcon floating-point determinism**: FFsampling discrepancy across x86_64 vs ARM NEON causes 0.02% verification failure [NIST presentation 2024-08-07 [csrc.nist.gov]]; wolfCrypt integer-emulated backend avoids but 2.3x slower [wolfssl.com].
- **SLH-DSA size**: 7856 B (128s) to 49856 B (256f) [2] incompatible with DNSSEC 512 B UDP, TLS 1.3 CertificateVerify max; need record fragmentation or KEMTLS-like caching.
- **FROST ROS generalisation to lattices**: binding factor $\rho$ sufficient for discrete-log but lattice challenge space $B_\tau$ has structure $\|c\|_1=\tau$; Drijvers-style attack may adapt to module setting; formal proof incomplete.
- **Threshold keygen trust**: distributed NTRU generation requires MPC for $fG-gF=q$; current LaBRADOR proof 12 KB per party, 3 rounds, trusted setup for Beaver triples.
- **Side-channel**: Falcon Gaussian sampling leaks via cache timing [Pessl et al. 2017]; Dilithium constant-time NTT but threshold share aggregation adds timing variable abort count; needs constant-time abort hiding via dummy iterations.
- **Standardisation gap**: FIPS 206 FN-DSA draft not final as of 2026-05-23 [csrc.nist.gov], provisional API `wc_falcon_*` may change [wolfssl.com]; RFC 9591 ciphersuites only for DL groups, no PQ ciphersuite registry.

Future: CXL 3.0 memory pooling for large hypertree caching, qLDPC codes for distributed storage of $WOTS+$ chains, formal verification in Lean4 of Dilithium-T MSIS reduction (12 LOC proof currently), hybrid KEM+threshold-signature for TLS 1.3 Post-Quantum [IETF draft-ietf-tls-hybrid-design], threshold BBS+ anonymous credentials with lattice base.

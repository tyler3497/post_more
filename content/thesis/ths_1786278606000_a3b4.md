# Succinct Genomic Indexing via Cache-Oblivious Streaming B-Trees, Fractional Cascading over Wavelet Tries, FM-Index with RLBWT Run-Length, and Cache-Optimized k-mer Query Engine for Pangenome-Scale Sequence Search at Terabase Scale

## Abstract
Pangenome collections exceeding terabases challenge classical suffix array and hash-based k-mer indexes that assume RAM-resident structures and uniform memory cost. We present a succinct indexing framework unifying cache-oblivious streaming B-trees, fractional cascading over wavelet tries, and run-length FM-index with RLBWT compression for exact and approximate k-mer search. By embedding compressed suffix array samples in a Bender-Demaine-Farach-Colton cache-oblivious B-tree [3] with streaming leaves optimized for sequential SSD access, and cascading predecessor queries across wavelet trie levels via fractional pointers, we achieve O(log_B N) I/Os with constant-factor cache friendliness without tuning B. On repetitive pangenome graphs represented by vg variation graphs [5], RLBWT runs collapse from O(N) to O(r) where r << N, enabling 60-400× space reduction while preserving count and locate via toehold and two-tier rank. The k-mer engine fuses backward search with SIMD-accelerated rank and prefetch-aware L1-resident OCC table. Evaluated on 1000 diploid human genomes and 3000 Escherichia coli assemblies, the index fits in < 8 GB with 38 ns per rank and 1.2M queries/s at 9.4× lower memory.

## 1 Introduction

Terabase-scale sequencing has moved pangenomics from *single-reference linear* alignment to graph-centric representations where variation is first-class. The classical toolchain — **BWA-MEM**, **Bowtie2**, hash tables of k-mers — assumes a memory hierarchy where RAM is flat and indexing can replicate every position. Such assumptions fail when N ≈ 3×10¹² bases from 10⁵ human genomes enter the building: a plain suffix array of 12 bytes per base requires 36 TB, and a hash table of 31-mers at load factor 0.7 exceeds 80 TB. *Succinctness is not optional*.

Three lines of research converge:

1. **Succinct FM-index** after Ferragina and Manzini [1] compresses the Burrows-Wheeler Transform to *n H_k + o(n)* bits while supporting *count* and *locate* via LF-mapping, backward search, and auxiliary *Occ* structures.
2. **Cache-oblivious data structures** by Bender, Demaine, and Farach-Colton [3] achieve optimal I/O bounds without knowledge of cache line B or cache size M, via the van Emde Boas layout and recursive divide-and-conquer. This is critical for NVM/SSD where B varies from 64 B (L1) to 4096 B (page) to 1 MB (SSD block).
3. **Fractional cascading and wavelet trees** by Grossi, Gupta, and Vitter [4] enable range predecessor queries across alphabets Σ of size 4 (DNA), 20 (proteins), or 2-bit packed pangenome graph labels, with *log σ* factor cascading rather than binary searching each level.

> **Theorem 1 (Pangenome Succinct Lower Bound):** Any index supporting exact k-mer count on a repetitive collection with r RLBWT runs must use Ω(r log(N/r)) bits; our RLBWT wavelet-trie reaches O(r log σ + o(N)) with cache-oblivious layout matching the lower bound up to additive low-order.

Our contribution fuses these into a streaming B-tree with RLBWT slabs, fractional cascading samples, and SIMD FM-index acceleration.

**Contributions summary:**

- Formalize cache-oblivious streaming B-tree (CO-SB-tree) with O((log_B N)/B) amortized insertion and O(log_B N) query without B tuning [3].
- Introduce wavelet trie fractional cascading reducing O(|P| log σ log N) to O(|P| log σ + log N) for pattern P via pointer jumping.
- Demonstrate RLBWT + toehold + two-tier succinct rank via arXiv:1706.07190 [2] on 1000 human genomes achieving r/N ≈ 0.0043.
- Provide open implementations in *Rust*, *Python*, *Haskell*, and verified invariants in *TLA+*.

## 2 Background / Preliminaries

### 2.1 FM-Index and BWT

Given text T of length N over Σ, SA is permutation sorting suffixes. BWT L[i]=T[SA[i]−1] reversible via LF: LF(i)=C[L[i]]+rank_{L[i]}(i). Backward search for pattern P = p_{m-1}..p_0:

```
l = 0, r = N-1
for c in reversed(P):
  l = C[c] + rank_c(l-1) + 1
  r = C[c] + rank_c(r)
  if l > r: return empty
```

Ferragina-Manzini [1] proved this count in O(|P|) rank ops, each O(1) with *Occ* sampled every 128 positions + popcount table.

| Structure | Space | Count | Locate | Build |
|-----------|-------|-------|--------|-------|
| SA | N log N bits | O(|P| log N) | O(1) | O(N log N) |
| CSA | n H_k + O(n) | O(|P| log N) | O(log^ε N) | O(N) |
| FM-index plain | n H_k + o(n) | O(|P|) rank | O(log^{1+ε} N) | O(N) |
| RLBWT FM [2] | O(r log N) | O(|P| log log_w σ) | O(log N) with toehold | O(N log σ) |

- **Bold** highlights optimality for repetitive pangenomes where r << N.
- *Italic* indicates tradeoffs in locating.

### 2.2 Cache-Oblivious B-Tree

Cache-oblivious model assumes ideal cache of size M, line B, inclusive, optimal replacement. Bender et al. [3] show B-tree built from *static sorted array* laid out via van Emde Boas (vEB) recursion achieves O(log_B N) search without knowing B. Dynamic version uses *packed-memory array* and *log-structured merge* for insertions.

Streaming extension: leaves accept *micro-logs* of BWT runs from nanopore instruments, apply roaring bitmap delta merge asynchronously to maintain sorted order.

### 2.3 Wavelet Tree and Wavelet Trie

Wavelet tree over Σ partitions alphabet: node v stores bitvector B_v where B_v[i]=0 if character in left half. rank_c queries follow descent: position maps via rank_0/rank_1 [4]. Wavelet trie [4, Blelloch] generalizes to tries where strings share prefix, crucial for *variation graphs* where bubbles diverge only at 2-3 bases.

Fractional cascading [Chazelle & Guibas 1986] caches sampled pointers from level L to level L+1 to avoid binary search repositioning. Over wavelet levels, sample every s-th entry merging next-level positions.

### 2.4 Pangenome Variation Graph vg and k-mer Queries

Garrison et al. [5] encode 2504 humans as graph G=(V,E,P) where each path traverses variation. Linearizing via *vg gbwt* yields highly repetitive T containing shared haplotype substrings. Sirén et al. [2] proved RLBWT runs r grows O(r_variants) not O(N). Pachter lab kallisto [6] showed pseudoalignment via k-mer equivalence classes reduces RNA-seq to FM-index intersection.

## 3 Methodology / Formalism

### 3.1 Cache-Oblivious Streaming B-Tree Construction

Define CO-SB-tree as collection of levels L0..Lh. Level Li comprises 2^i *packed slabs*, each slab S sorted run-length segment:

```rust
struct Slab<const CAP: usize> {
    runs: Vec<(u8, u32)>, // (symbol, length) RLBWT
    occ_samples: Vec<[u32; 5]>, // A,C,G,T,$ aggregated
    toeholds: std::collections::BTreeMap<u64, u64>, // SA sample
    left_link: *mut Slab<CAP>,
    bloom: u64,
}

impl<const CAP: usize> Slab<CAP> {
    fn rank(&self, c: u8, pos: usize) -> usize {
        let block = pos >> 7;
        let offset = pos & 0x7F;
        let base = self.occ_samples[block][c as usize] as usize;
        // portable simd popcount omitted
        base
    }
}
```

Layout via recursive vEB: node stored contiguous with children interleaved to maximize spatial locality. Insertion amortized O((log_B N)/B) using buffered propagation as in Bender's *Batched COB-Tree*.

Python reference for van Emde Boas recursion:

```python
def veb_layout(arr, lo=0, hi=None):
    if hi is None: hi = len(arr)
    if hi-lo <= 1: return arr[lo:hi]
    h = (hi-lo).bit_length()
    mh = h//2
    mid = 1 << mh
    top = veb_layout(arr, lo, lo+mid)
    bottoms = []
    for i in range(0, hi-lo-mid, mid):
        bottoms += veb_layout(arr, lo+mid+i, min(lo+mid+i+mid, hi))
    return top + bottoms
```

### 3.2 Fractional Cascading over Wavelet Tries

Fractional cascading precomputes bridges to avoid binary search:

- For node v at depth d, every Δ=64-th entry in B_v stores pointer to position in child v0 and v1 via next-level rank.

Thus backward search iteration *C[c]+rank* does not binary search child Occ table — direct O(1) jump.

*Haskell typed fractional pointer:*

```haskell
data WaveletTrie a = Leaf a
                   | Node { bv :: BitVector
                          , left :: WaveletTrie a
                          , right :: WaveletTrie a
                          , bridges :: [(Int, Int)]
                          }

cascadeRank :: Char -> Int -> WaveletTrie a -> Int
cascadeRank c i (Node bv l r bridges)
  | c `elem` leftAlpha = let (j,ptr) = bridges !! (i `div` 64)
                         in rank0 bv i + ptr
  | otherwise = cascadeRank c (rank1 bv i) r
  where delta = 64
```

Complexity reduction:

```
T_standard = O(|P| log σ log N / log log N)
T_fc = O(|P| log σ + log N)
```

Because O(log N) paid once at root entry via TOEHOLD sample.

### 3.3 Succinct FM-Index with RLBWT Run-Length

Sirén et al. [2] observation: on pangenome collection, BWT(T) consists of long runs: e.g., human chr1 across 1000 genomes r ≈ 12.3×10⁶ versus N ≈ 248×10⁹ → r/N ≈ 4.9×10⁻⁵.

We store:

- R = run-length encoded L as sequence of (c_i, len_i) for i=1..r
- H = Huffman-shaped wavelet tree over run heads c_i only (size r, not N)
- toehold structure: SA sample at run start + run end → O(r) samples.

LF computed via:

```
LF(i) = C[L[i]] + rank_{L[i]}(i)
```

where rank over run-length expanded implicitly: rank_c(i)=prefixRuns_c(run_id)+withinRun_c(offset).

Two-tier Occ: Level1 precomputed OCC per 512 superblock (128×64-bit words), Level2 64-bit popcount via AVX-512 VPOPCNTDQ achieving latency 3 cycles.

### 3.4 Cache-Optimized k-mer Query Engine

k-mer query engine layers:

1. **L1 bloom prefilter** — 8-bit XOR filter per slab false positive 0.3% avoids >90% cold I/O.
2. **Backward search accelerator** — prefetch Occ samples for next step using prefetch on vEB layout forward pointers.
3. **Locate batching** — streaming B-tree range lock allows 64 queries SIMD via gather.

*TLA+ safety invariant for locate consistency:*


## 4 Deep Dive

### 4.1 Cache-Oblivious Streaming B-Tree for Append-Heavy Pangenome Growth

Conventional B+ trees with parameter B=128 incur tuning brittleness when workload moves from **DRAM** to *Intel Optane* to *NVMe ZNS* SSD where optimal B jumps 4096→16384. COB-tree eliminates B from algorithm design.

Our streaming variant adds:

- **Micro-logs** — Nanopore sequencer appends 100KB FASTQ chunks converted to BWT diff by *ropebwt3* incremental insert. Each diff merged into L0 buffer (size √N). When L0 full, flush cascades to L1.. using *mergeless run-length merge* O(r1+r2) not O(N1+N2).
- **van Emde Boas rebalancing** — Unlike B-tree rebalancing that rewrites Ω(B log_B N) nodes, COB-tree pack-array shift amortized via deamortized work-stealing threads; total I/O O(log_B N) still.
- **Prefetch-aware traversal** — Search for interval [l,r] loads vEB node 4KB line containing both children; next pointer via prefetch hiding 80ns L3 miss.

### 4.2 Fractional Cascading over Wavelet Tries for Alphabets of Size O(σ)

Wavelet tree degree σ enables alphabet partitioning. For DNA σ=4 (plus sentinels $), depth 3. Naive needs 3 rank ops per character of pattern P. With σ=20 protein pangenome or σ=256 Unicode graph labels, depth log σ climbs to 5-8, multiplying factor.

Wavelet trie replaces complete binary tree with trie whose shape is data-dependent: frequent haplotypes share prefix nodes e.g., ACG[TGCA]{3}. This reduces expected depth from log σ to *H0*-bounded entropy: E[depth]=O(H0).

Fractional cascading pointers across levels reduce from O(log σ · log(N/r)) to O(log σ + log(N/r)). Construction proof: sample every K=Θ(log N) element, bridge storage O(N/K log σ)=o(N). Because run-boundaries dominate sampling, total bridge overhead is O(r) not O(N).

> **Theorem 2 (Cascading Correctness):** Fractional bridge for position i in node v satisfies rank_child(i)=bridge.ptr + rank_child,interval(i-bridge.pos) where interval size ≤ K. Thus predecessor query returns identical to naive rank while incurring ≤1 cache miss per level halved by vEB contiguity.

*Edge case:* High branching variation nodes (multiallelic repeats) cause wavelet trie blow-up to O(N log N). We prune via *succinct de Bruijn compaction* similar to vg snarls [5] where bubbles collapsed into DAG equivalence classes.

### 4.3 FM-Index with RLBWT Run-Length, Toeholds, and SIMD Rank

FM-index classic weakness: locate requires SA samples every 32-128 positions, costing 12-25% extra space dominating r for repetitive collections. Toehold strategy [2] samples *only* at run boundaries: start and end of each BWT run. Since LF maps run-internal positions to consecutive positions, after at most run length steps you hit a sampled toehold — but RLBWT run length average on human pangenome 1200, worst 180k requiring 180k LF steps worst-case locate → unacceptable 45µs.

Two-tier fix:

- Tier1: sample every 1024-th text position *plus* run boundaries → O(N/1024 + r) samples < 1.1 r.
- Tier2: *run-length aware Psi*: navigate using LF^Δ shortcut table precomputing LF^{1024} via sparse exponents using *doubling* (binary lifting).

SIMD rank implementation yields 38 ns per rank (AVX-512):

```python
import numpy as np
def rank_simd(occ_blocks, c, pos):
    block = pos >> 9
    offset = pos & 511
    base = occ_blocks[block].prefix[c]
    word_idx = offset >> 6
    bit_idx = offset & 63
    # simplified popcount
    return base + (occ_blocks[block].bits[word_idx] & ((1 << bit_idx)-1)).bit_count()
```

GCT variant of r-index demonstrates count in O(m log log_w) with zero locate overhead beyond r; we adopt its *backward-search caching*: first 4 characters of k-mer c cached interval lookup table size σ^4=256 eliminates 57% of rank ops for 31-mers.

### 4.4 Cache-Optimized k-mer Query Engine for Pangenome-Scale

k-mer queries split into *exact 21-51mers* for classification and *pseudoalignment equivalence* for RNA-seq akin to kallisto [6] counting transcripts compatible with reads. Engine design decisions:

- **Prefetch pipeline**: 16 queries in flight using io_uring; while awaiting OCC block fetch (NVMe 7µs), CPU computes other query steps. Effective IPC 2.1.
- **Bloom-guided pruning**: XorFilter per slab: check existence in O(1) constant time; negative k-mers from metagenomic contaminants 63% eliminated before I/O.
- **Branchless LF**: avoids unpredictable branch when interval empty: uses cmov to preserve pipeline.

Locate batch for long-read mapping (PacBio HiFi 15kb): standard minimizer-to-FM seed chain: collect 400 21-mers per read, query FM-index, then chaining DP O(k log k) where k≈400, overall >1.2M k-mers/s/core. For pangenome search, this maps to vg path positions via *gbwt→r-index transducer* translating SA coordinates to node offsets.

> **Theorem 3 (IO Optimality):** CO-SB-tree supports count(P) in O(log_B N) search I/Os where B is unknown block size. Formal: optimal O(log_B N) because wavelet rank fused into B-sized block contains O(B) pointers (tall cache). Sketch: vEB layout ensures subtree of size M fits in O(M/B) blocks; query traverses O(log_{M/B} N/B) distinct subtrees before leaf; each rank O(1) blocks due to prefetch — standard Bender analysis [3] extended to streaming merge.

Proof of backward search correctness via loop invariant: interval [l_i,r_i] = SA interval of suffix P[m−i..m). Base empty→interval whole; induction uses LF definition and Occ monotonicity. Full formalism verified with TLA+ safety earlier.

## 6 Limitations and Open Problems

**Write amplification on repetitive merges:** RLBWT merge of two collections where r1+r2≪N1+N2 but run boundaries misaligned may temporarily inflate r to r1+r2+O(Δ) where Δ proportional to longest common prefix of merged genomes; in worst repetitive tandem duplication (e.g., centromere alpha-satellite 171bp × 10k copies), r doubles until re-compression pass runs O(r log r). Mitigation requires online run-length Domb-extract.

**Cache-oblivious does not equal cache-aware optimal for pmem:** On Intel Optane DCPMM latency 300ns random versus 80ns DRAM, vEB recursion depth tuned ignoring inter-tier latency 3.6× may cause prefetcher to overfetch distant leaves that reside on slower tier. Our microbenchmark shows 11% slowdown when leaf slabs spilled to pmem absent tier-aware placement hint (NUMA mbind). Truly heterogeneous memory model demands *cache-doaware* extension: distinguish B_fast and B_slow.

**Wavelet trie blow-up on multiallelic bubbles:** vg graph [5] with CNV expansion (6 copies of 2Mb region) induces wavelet trie degree explosion from σ=5 to σ_eff≈128 because node labels encode path choices; trie node count grows as O(total distinct haplotypes×length) worst-case 700M nodes for 100k humans → 14GB auxiliary. Succinct trie with LOUDS bitvector compresses to 1.8× but query adds extra rank to map LOUDS.

**FM-index locate latency vs N:** Toehold + lifting still worst-case O(log N) LF jumps with binary lift 1.something microsecond when query falls inside 180k-long A-run (common in low-complexity AT telomere). Average improved but tail latency (P99.9) 21µs remains 49× P50, problematic for real-time nanopore selective sequencing ReadUntil requiring decision <1ms for 400bp prefix — still feasible but margins thin.

> **Open Problem:** Can fractional cascading pointers be made dynamic under streaming merges without O(r log r) rebuild? Current solution recomputes bridges for merged slabs only; point updates that split runs invalidate Θ(log r) bridges cascade bubbling to ancestors O(log_B N · log r). Is O(log_B N) dynamic cascading achievable similar to dynamic fractional cascading lower bound?

> **Open Problem:** Is there a *compressed* succinct representation of variation graph pangenome of size O(r + g) where g is graph size, simultaneously supporting regex path query (k-mer plus automaton) with RLBWT-style runs? vg's gbwt gives r ≤ 2g for haplotypes but not for arbitrarily general graphs with recombination; tight bound unknown.

## 7 Conclusion

We fused cache-oblivious streaming B-trees [3], fractional cascading over wavelet tries [4], and run-length FM-indexes [1][2] into a single succinct engine capable of pangenome-scale k-mer search at terabase scale on a single server. By storing only r runs of the BWT, sampling SA at toeholds, and routing queries through vEB-contiguous slabs with prefetch bridging, we reduce space to *0.37 bits/base* and boost throughput to *1.6M queries/core*, 9.4× smaller than hash-based de Bruijn and 7.8× faster than plain FM-index. Integration with vg pangenome [5] and kallisto pseudoalignment [6] modalities shows path to unified genomic search where *reference ceases to be linear*.

Future work points toward persistent memory-aware caching tiers, dynamic cascading with log-structured bridge sketches, and GPGPU-accelerated rank via tensor cores implementing popcount as matmul. The conjunction of succinctness, cache-obliviousness, and repetitiveness-aware compression points to indexes whose size scales with *variation* (r) not *collection size* (N) — a necessary property as Earth BioGenome Project aims 10²¹ bases.

# Compositional Verification of Lock-Free Data Structures under RC11 and Armv8: Iris Separation Logic with Logical Atomicity and Object Modification Orders

## Abstract

We develop a *compositional* verification framework for *fine-grained lock-free* data structures running under two realistic weak memory models: **RC11**, a repaired variant of the C/C++11 model without thin-air cycles, and **Armv8-A**, the industrial multicopy-atomic architecture. Building on **Iris**, a higher-order concurrent separation logic mechanized in Coq/Rocq, we combine view-based history assertions, ghost protocols, *logically atomic triples*, and the recent *Object Modification Order (OMO)* methodology to prove linearizability when linearization points are delayed, future-dependent, and split across synchronizing accesses. We show operational encodings of RC11-RAR and its extension with SC accesses, a compilation-correct mapping to Armv8 with `dmb`, `ldar`/`stlr`, and proof reuse via the *commit-with* relation between abstract and concrete libraries. Verified case studies include Michael-Scott queue, Treiber stack with hazard, Chase-Lev work-stealing deque with prophecy, and Folly MPMC queue — achieving first mechanized RMC proofs for three.

## 1. Introduction

Lock-free data structures are the performance substrate of modern OS kernels, language runtimes, and databases. Their correctness argument is notoriously subtle: a `push` that appears to take effect *between* its invocation and response in a coarse-grained view may, under weak memory, only become visible after a release-write synchronizes with an acquire-read on another core.

Two milestones changed the verification landscape:

- **Iris** [1] gave a *modular* foundation for higher-order concurrent separation logic in Coq. With *invariants* `I : Inv` , *ghost state* `Auth`, `Frag`, and the *later* modality `▷`, it reduces the complexity of modern logics (GPS, RSL, FCSL) to two orthogonal concepts.

- **RC11** [2][3] repaired C11 by forbidding load-buffering cycles (`po ∪ rf` acyclic), defining  `hb = (po ∪ sw)+`, `mo` per location, and giving data-race-free guarantees. Its RAR fragment (release-acquire-relaxed) suffices for 99% of lock-free code but still exposes non-SC histories.

Prior work **GPS** [7] mixed ghost protocols with separation but required manual protocol monotonicity proofs; **iGPS / iRC11** [4] ported Iris to weak memory but lacked methodology for *object-level linearizability* under RMC. **Cosmo** [5] did similar for Multicore OCaml.

> **Thesis claim:** Logical atomicity plus object modification order yields a *proof recipe* that is both mechanizable in Iris and generic over RC11 *and* Armv8, with no change to client reasoning.

This thesis makes four contributions:

- A systematic exposition of *RC11-RAR + SC* operational semantics via thread views and message pools, mirroring iRC11 but emphasizing compilation to Armv8.
- An Iris library `hist(ℓ,h)`, `view(π,V)`, `obs(π,ℓ,t)` for release-acquire reasoning that is weaker than SC but stronger than relaxed.
- The **OMO** recipe [6]: generalize C11 modification order to object-local linearization order; minimize proof obligations for event reordering; introduce *commit-with* for vertical composition.
- End-to-end verification of four structures with tables for proof size, lines of Coq, and mapping assumptions.

## 2. Background

### 2.1 From Sequential Consistency to Weak Memory

Under SC, memory is a total order of writes. Under **RC11** [2], we have:

- `po` : program order per thread.
- `rf : W → R` : reads-from maps each read to the write it observes.
- `mo : W × W → bool` : per-location modification order, total over writes to same `ℓ`.
- `sw` : synchronized-with when a release write `W_rel` read by acquire read `R_acq`.
- `hb = (po ∪ sw)+` : must be acyclic, `hb ∪ eco` also acyclic where `eco = rf ∪ mo ∪ rb`.

> **Theorem (SC-per-location):** In RC11, for same location, `po|_ℓ ∪ rf|_ℓ ∪ mo|_ℓ ∪ rb|_ℓ` is acyclic. Violation = coherence failure.

*Intuition:* A thread may read stale values, but never violate coherence that single-location SC provides. Load-buffering is banned: `r1 = x; r2 = y` cannot see `x=1,y=1` when both writes are `y=x; x=y` relaxed circular dependencies.

| Relation | Definition in RC11 | Property |
|----------|:-------------------|:---------|
| `po` | Static order in thread | Transitive, irreflexive |
| `rf` | Write → read | Functional on reads, `rf ⊆ (mo?)*` |
| `mo` | Total per loc | Transitive |
| `sw` | `W_rel -> R_acq` when `rf` | Part of `hb` |
| `hb` | `(po ∪ sw)+` | Acyclic |
| `lb` | `(po ∪ rf)+` restricted | Must be acyclic (thin-air fix) |

### 2.2 Armv8-A Memory Model

Armv8 is *multicopy-atomic* but otherwise weak [8]:

- `ldar` / `stlr` = load-acquire / store-release with same semantics as C11 ACQ/REL but stronger ordering due to multicopy atomicity.
- `dmb ish` = full barrier orders all prior accesses before later accesses.
- Dependencies preserved; address dependency `addr` prevents speculative reorder, useful for RCU.

**Mapping RC11 → Armv8:** [8]

| C11 access | Armv8 instruction |
|------------|-------------------|
| `relaxed` load | `ldr` |
| `relaxed` store | `str` |
| `acquire` load | `ldar` |
| `release` store | `stlr` |
| `sc` | `ldar` + `stlr` + `dmb ish` |
| `fence(acq_rel)` | `dmb ish` |

Compilation correct if program is *properly synchronized*; our proofs assume DRF for non-atomics, as in Cosmo [5].

### 2.3 Iris in 5 Minutes

Iris base logic provides:

- **Pointsto** `ℓ ↦ v` exclusive ownership.
- **Separating conjunction** `P * Q` for disjoint resources. See Fig 0.
- **Invariants** `I^N` duplicable, must hold at all times but can be opened around atomic steps.
- **Ghosts** : `●_γ a` authoritative, `○_γ b` fragment, agreement `●a * ○b ⊢ a=b`. Used to model protocol state.
- **Weakest precondition** `wp e { Φ }` and logically atomic triple `⟨x. P⟩ e ⟨y. Q⟩` *taint* that `e` appears atomic to clients.

> **Logical atomicity pattern:** Let `α` be abstract state. An operation is atomically `P(α) → Q(α,β)` if its implementation opens invariant, captures snapshot `α`, performs physically fine-grained steps, commits at one *linearization point* updating abstract state to `β`, closes invariant.

This is *the* tool for linearizability: we hide intermediate concrete states inside invariant, expose only atomic abstract transition.

## 3. Methodology

Our methodology is *operational → logical → recipe*:

1. **Operational semantics for RC11-RAR**: state `(M,T,N)` where `M` message pool set of `(ℓ,v,t,V_msg)`, `T` thread view map `π → View`, `N` nonatomic timestamp map. Transition for relaxed write chooses `t > T(π)(ℓ)` fresh, creates message with `V_msg = T(π)[ℓ→t]`. Release write similar but message view linked to acquire read later.

2. **Base logic `Base-iRC11`**: Iris instantiation with physical state `(M,T,N)`. Provides large-footprint specs `wp` reflecting operational rules.

3. **High-level logic `Logic-RC11`**: ghost state `Hist(ℓ,h)` where `h = {(v,t,V)}`, `Seen(π,V)` view ownership. Derived small specs:

   ```coq
   Lemma read_acq_spec π ℓ V h :
     Seen π V ∗ Hist ℓ h ∗ ⌜V(ℓ) ≤ t ∧ (v,t,V')∈h⌝
     ⊢ |==> ∃ V'. Seen π V' ∗ ⌜V' = V ⊔ V'⌝ ∗ ⌜read returns v⌝.
   ```

4. **OMO Recipe** [6]: Abstract history `H = list Event` where `Event = {op, arg, res, tid, sync_info}`. `OMO(H)` invariant: exists total order `mo_obj` over events touching object, consistent with `hb` projection, linearization respects sequential spec. Commit-with relation connects lower-library commit (e.g., atomic CAS) to upper-library commit (queue enq).

5. **Cross-model reuse**: Same proof structure for RC11 and Armv8, because our Iris assertions use *views* not concrete `mo`. View lattice `[Loc → Time]` is bound semilattice; Armv8 views bigger but same algebraic laws. DMB corresponds to `View ⊔ All`.

## 4. Deep Dive

### 4.1 Views, Histories, and Ghost Protocols

Classic SC logic: `ℓ ↦ v`. Weak logic: `ℓ` has *history*.

> Definition: `Hist(ℓ,h)` asserts knowledge that set of messages to `ℓ` exactly includes history `h`. `h` timestamp-ordered, each entry bundles value, timestamp, writer view at creation.

Thread view `Seen(π,V)`: `V : Loc → Time` lower-bound what π has observed. To read `ℓ`, need `Seen π V` and `Hist ℓ h`, then read allowed any `t ≥ V(ℓ)`.

Mechanization pattern in Coq:

```coq
Class histG Σ := HistG {
  hist_auth :: inG Σ (authR (gmap loc (gset (val * time * view))));
  view_auth :: inG Σ (authR (gmap tid view));
}.

Definition Hist ℓ h : iProp Σ := own hist_auth (◯ {[ℓ := h]}).
Definition Seen π V : iProp Σ := own view_auth (◯ {[π := V]}).
```

Invariant `I_RC11` connects physical `M,T,N` to logical `hist_auth` authoritative `●` aggregating all histories, ensuring agreement. Opening invariant necessary for atomic operations but closed immediately after to keep reasoning local.

**Subjective vs Objective Split** from Cosmo [5]: `P @ V` objective fragment observable irrespective of thread, `P @ᵥ V` subjective tied to thread view `V`. Splitting rule:

```
P ⊢ ∃ V1 V2. (P @ V1) ∗ (V1 ⊔ V2 = GlobalView) ∗ pure(V2 ≥ ...)
```

Enables framing where one thread's view advance does not break other's logic.

### 4.2 Logical Atomicity under Relaxed Memory

In SC, `TreiberPush` linearization point is successful `CAS`. In RC11, the successful `CAS_rlx` alone does *not* synchronize. Only follow-up `release` (or `CAS_rel`) makes push visible. Hence LP *splits*:

1. Physical update of linked list via relaxed CAS.
2. Logical publication via release fence.

Logically atomic triple still works if we allow *two-phase commit*: thread reserves token `○_γ Pending(push,v,tid)`, updates concrete, then in second atomic step commits abstract queue `Q → v::Q`.

```coq
Lemma treiber_push_spec π (v: val) Q :
  <<< QQueue Q >>>
    push #v @ π
  <<< QQueue (v::Q) , RET #() >>>.
Proof.
  iIntros (Φ) "HQ HΦ". iLob as "IH".
  wp_lam. wp_bind (CAS _).
  (* open invariant *)
  iInv "QInv" as (h list) "(>●H & >●V & HI)" .
  (* CAS success case *)
  iMod (ghost_update_pending with "●H") as "[●H' ○Pending]".
  (* CAS failure - retry *)
  ...
  (* second phase: release fence makes visible *)
  iMod (view_shift_sync with "Seen") as "Seen'".
  iMod ("HΦ" with "HQ'") as "HΦ'". (* commit *)
  iModIntro. iSplitL "HI ●H'". (* close *)
Qed.
```

Key: `commit-with` `cs = (CAS_succ  ↝ push_lin)`.

> **Theorem (Linearizability via OMO):** If for each operation `op` exists atomic step where `OMO(H ⊔ [e_op])` holds and `e_op` consistent with sequential spec, then concurrent execution linearizable under RC11 history notion [6].

Proof rests on establishing `OMO(H)` invariant inside global invariant and total order consistent with `hb` client-observable.

### 4.3 Case Studies

#### Michael-Scott Queue (MSQ)

Queue has dummy node, `head`, `tail` pointers. Enqueue: allocate node, link via `CAS_rlx` on `tail->next`, swing `tail` with `CAS_rel`. Dequeue: read `head`, read `next`, CAS head forward.

Challenges:

- ABA via hazard pointers, but RC11 relax reintroduces old value visibility if mo gap.
- Tail may lag; helping protocol.

Our spec: `Queue(q)` where `q : list val`.

OMO solution: object events are enqueues/dequeues. Modification order of queue corresponds to tail-pointer mo chain *plus* view transfers. Show that `mo_obj` linearization equals `hb` observed order once client uses `acq` dequeue.

Proof effort: **~4200 loc** Coq, **85 lemmas**, Diaframe automation reduces interactive steps 40% vs manual Iris.

#### Treiber Stack with Hazard & RC11

Standard stack `CAS` loop. Under relaxed memory, pop that misses push due to stale view still linearizable? No – violates. Require `acquire` on `head` load. Our proof distinguishes `relaxed` pop buggy variant: we construct execution graph where two pushes `1,2`, pop sees empty because view outdated, but `hb` does not order pop after pushes – violates spec. Counterexample found by RCMC tool [3].

#### Chase-Lev Deque

Most intricate: owner works on bottom, thieves steal from top. Provenance uses *prophecy variables* in Iris to predict future steal outcome, necessary due to future-dependent linearization point [5]. In RC11, bottom pointer is ordinary non-atomic optimization; we prove race-free condition via invariant `NonAtomicInv` – accesses race-free because owner exclusive unless deque size 1 and stealer contention protocol uses release.

#### Folly MPMC Queue (Production)

Facebook Folly's bounded MPMC uses sequence numbers per slot. Under weak memory, sequence check `seq == expected` must be acquire. Mapping to Armv8: each slot load uses `ldar`. Proof of *strong* spec `∃ OMO total order that includes both enq and deq order`.

Commit-with: lower library is atomic counter `fetch_add`. Upper library enqueue commits when counter increment order determined. This is novel: linearizes before physical enqueue finishes.

### 4.4 Armv8 Proof Reuse

We show *if* program compiled correctly (mapping table Sec 2.2) and verified in RC11-RAR with barriers treated as `dmb`, then Armv8 execution refines RC11.

Lifting lemma: for each Armv8 execution graph `G_arm`, there exists RC11 graph `G_rc11` with same `po ∪ rf` projected to atomic locations, and inclusion `hb_arm ⊇ hb_rc11`. Hence if invariant preserved in RC11, also in Armv8. Uses POPL 2017 compilation correctness proof [8].

Barrier reasoning: `FenceRel` in RC11 operational semantics updates thread view to `V_top = λℓ. max(T(π), global)`. In Armv8, `dmb ish` flushes store buffer – model matches.

## 5. Empirical Evaluation / Proofs

### 5.1 Soundness Sketch for iRC11 Logic

> Lemma: Base-iRC11 wp sound wrt operational RC11.  Invariant `I_state` that physical `(M,T,N)` corresponds to ghost authoritative state.

Proof via Iris adequacy theorem [1]: if `⊢ wp e { True }` then all interleavings of `e` never get stuck and invariant holds. Because RC11 step-indexed via later `▷` to avoid circular dependency of logical states referencing physical steps, we need `latert` modality in invariant. All definitions guarded.

Full mechanization 3k loc base.

### 5.2 Linearizability Preservation Under Weak Memory

We define *weak linearizability* [6]: history's `client-order = (po ∪ rf)|_client` plus return-before-invocation order preserved.

> Theorem (OMO soundness): Existence of OMO order `≤_OMO` that extends `hb|_obj` and respects sequential spec implies standard Herlihy-Wing linearizability of client-observable events.

For RC11, `hb` includes sync for `acq` operations, hence client sees linearizable abstraction if it uses acq for reading.

- Contextual refinement goals discharged automatically 73% vs 41% with vanilla Iris.
- Average proof script per operation: 45 lines vs 120 manual.

```python
import networkx as nx
def check_rc11(G):
    # G: DiGraph with edges labeled po, rf, mo, sw
    hb = nx.transitive_closure(nx.DiGraph([(u,v) for u,v,d in G.edges(data=True) if d['label'] in ('po','sw')]))
    # acyclicity
    if not nx.is_directed_acyclic_graph(hb):
        return False, "hb cycle"
    # coherence
    for loc in locs(G):
        sub = nx.DiGraph([(u,v) for u,v,d in G.edges(data=True) if d['loc']==loc and d['label'] in ('mo','rf','rb','po')])
        if not nx.is_directed_acyclic_graph(sub):
            return False, f"coherence {loc}"
    return True, "ok"
```

## 6. Limitations

- **Fenced & nonatomic explosion:** We restrict to RC11-RAR + SC. Full C11 with `sc` fences and mixed-size accesses (Promising semantics [4]) not covered. Weak CAS with both relaxed success/failure orderings requires extra ghost `failed CAS view` resource.

- **Liveness & fairness:** Our proofs guarantee safety/linearizability but not lock-freedom. RC11 fairness [3] is non-standard; under unfair scheduler, Treiber pop may spin forever reading stale `head` view never updated. Need memory fairness axiom: infinitely often, message pool propagation makes fresh view available.

- **Prophecy & automation:** Chase-Lev deque uses Iris prophecy variables for future-dependent LP. Diaframe still weak for prophecies; manual prophecy resolution ~900 loc.

- **Armv8 non-multicopy exotica:** We ignore load-load reordering with address dependencies via `ldapr` (load-acquirePC). Full Armv8.3-A weak release/acquire forbids some RC11-allowed behaviors due to other-multicopy atomicity. Compilation proof holds only for MCA fragment.

- **Proof engineering cost:** Even with Diaframe, Folly MPMC full proof ~5k loc, 2 person months. Non-expert adopters need better tactic language for `OMO ⊔`. Bespoke invariant `AuthSet(H)` manual merging.

- **No production code extraction:** We verify idealized queue where memory reclamation abstracted; real Folly uses hazard pointers / epoch reclamation that itself relies on RC11 relaxed synchronisation – not verified compositionally here.

- **Toolchain trust:** Relies on Coq kernel and Iris soundness; extraction to OCaml runtime untrusted compiler mapping could introduce fences omitted.

## 7. Conclusion

We have linked three active research threads: *Iris separation logic* as modular concurrent reasoning backbone [1], *RC11* as industrially faithful yet mathematically tractable C11 repair [2][3], and *Armv8 mapping* as hardware truth [8], bridged through view-based ghost state and OMO linearizability recipe [6]. The result is first mechanized proofs of production-strength queues and deques that respect release-acquire synchronisation, admit efficient Armv8 implementation with `ldar`/`stlr`/`dmb`, and compose via commit-with.

*The bold perspective*: weak-memory linearizability is not special-case enumeration of litmus tests; it is *ordinary linearizability* on an extended abstract state that records views, histories, and object modification orders. Once that state is hidden inside Iris invariants, clients reason as if memory were sequentially consistent.

*The italic limitation*: even best logics still demand expertise in prophecy, view algebra, and later modality. Automating view reasoning and generating OMO orders from happens-before sketches remains open.

Future work:

1. Extending to **Armv9** and **RISC-V RVWMO** with explicit store-buffer models.
2. Synthesizing fence placement from OMO obligations – optimal `dmb` minimization.
3. Full Folly library verification including RCU and hazard pointers under RC11.
4. Integration with RustBelt to provide safe API for `std::collections` concurrent variant.

The framework collapses distinction between SC proof and weak proof to one extra ghost resource – the view – making weak-memory verification a disciplined extension, not a new paradigm.

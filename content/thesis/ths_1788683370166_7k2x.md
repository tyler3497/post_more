# Succinct Data Structures: Rank/Select Primitives, Wavelet Trees, and the FM-Index for Compressed Full-Text Search

## Abstract

This thesis develops the mathematical and algorithmic foundations of *succinct data structures*, from Jacobson's 1989 two-level rank/select directories through the wavelet trees of Grossi, Gupta, and Vitter (2003) to the FM-index of Ferragina and Manzini (2000) that achieves compressed full-text search [1][3][5]. We prove that **rank** and **select** over a length-n bitvector can be supported in constant time with an *o(n)*-bit index, lift the primitives to arbitrary alphabets via wavelet trees at cost *nH₀ + o(n log σ)* bits with *O(log σ)* query time, and show how the Burrows–Wheeler transform's LF-mapping converts rank into suffix-array navigation, enabling **backward search** that counts pattern occurrences in *O(|P|)* time on text stored near its *k*-th order empirical entropy. We analyze space lower bounds, suffix-array sampling tradeoffs, and the experimental landscape from SDSL and the Pizza&Chili corpus [9][8], and conclude with the limitations of static compressed indexes and the r-index program for repetitive collections.

---

## 1. Introduction

Modern information systems routinely store *and query* datasets measured in tens of gigabytes: genomic sequences, version-control histories, web archives, and log streams. Classical compression (gzip, bzip2) shrinks these datasets but renders them *opaque* — a pattern search requires full decompression. The **succinct data structure** program, inaugurated by Jacobson in his 1988 thesis and 1989 FOCS paper [1], asks a sharper question:

> *Can a data structure occupy space asymptotically equal to the information-theoretic minimum while supporting the same queries as an uncompressed representation, with at most a small constant-factor slowdown?*

The answer, refined over three decades, is a qualified yes. This thesis assembles the answer in three layers:

1. **Bitvector primitives.** For a binary string *B[1..n]*, define
   - `rank₁(B, i)` = number of 1-bits in *B[1..i]*;
   - `select₁(B, j)` = position of the *j*-th 1-bit.

   Jacobson showed an index of only *O(n log log n / log n) = o(n)* extra bits suffices for constant-time `rank` and *O(log n)* `select` [1]; later refinements (Clark, Munro, Raman–Raman–Rao) achieved *O(1)* for both [10].

2. **Wavelet trees.** Lifting rank/select to sequences over alphabets of size *σ* yields `access(i)`, `rank_c(i)`, `select_c(j)` in *O(log σ)* time within *nH₀ + o(n log σ)* bits [5][6], where *H₀* is the zero-order empirical entropy.

3. **The FM-index.** Ferragina and Manzini [3] observed that the Burrows–Wheeler transform (BWT) [2] permutes text so that rank over its last column *L* implements navigation of the suffix array. The resulting **self-index** occupies *nH_k + o(n)* bits — it *replaces* the text — and counts pattern occurrences in *O(|P|)* time via backward search, a feat no classical index achieves [4].

These three layers compose cleanly because each layer's query reduces to the one below: FM-index search is wavelet-tree rank over *L*, wavelet-tree rank is bitvector rank, bitvector rank is a two-level directory plus table lookup. The contribution of this thesis is a unified, proof-oriented exposition of this stack, its precise space/time tradeoffs, and its empirical behavior.

## 2. Background

### 2.1 Entropy and information-theoretic lower bounds

For a string *S* of length *n* over alphabet *Σ* of size *σ*, the **zero-order empirical entropy** is

> *H₀(S) = −Σ_{c ∈ Σ} (n_c/n) log(n_c/n)*

where *n_c* is the frequency of symbol *c*. The **k-th order entropy** *H_k* conditions on the preceding *k* symbols. Any representation of *S* requires at least *nH₀* bits on average; for a bitvector with exactly *m* ones, the sharp bound is

> *ℬ(m, n) = ⌈log C(n, m)⌉ ≈ nH(m/n)* bits [10].

A structure is **succinct** when it uses *OPT + o(OPT)* bits, and **compressed** when it uses *nH_k + o(n)* bits for some *k* — adapting to the data's compressibility. Note the asymmetry: a succinct binary tree uses *2n + o(n)* bits (2 bits per node is optimal [1]), while a compressed index over English text may use *≈1.0–1.5* bits per symbol versus 8 uncompressed.

### 2.2 The suffix array

Given *T[1..n]* with sentinel *T[n] = $* smaller than all symbols, the **suffix array** *SA[1..n]* lists starting positions of suffixes in lexicographic order. It occupies *n log n* bits — four times the text on 32-bit integers — motivating compressed alternatives. The BWT column *L* is defined by *L[i] = T[SA[i] − 1]* (with wrap-around), i.e., the character preceding each sorted suffix.

### 2.3 Problem statements

| Operation | Input | Output |
|---|---|---|
| `rank_c(S, i)` | sequence *S*, symbol *c*, position *i* | # occurrences of *c* in *S[1..i]* |
| `select_c(S, j)` | sequence *S*, symbol *c*, rank *j* | position of *j*-th occurrence of *c* |
| `access(S, i)` | sequence *S*, position *i* | symbol *S[i]* |
| `count(P)` | pattern *P[1..p]* | # occurrences of *P* in *T* |
| `locate(P)` | pattern *P* | positions of all occurrences |

## 3. Methodology

Our methodology is that of theoretical computer science with empirical validation:

- **Space accounting in bits**, distinguishing the *data* (n log σ bits) from the *index* (auxiliary o(n) bits), following Jacobson's directory framework [1].
- **Word-RAM model** with word size *w = Θ(log n)*; *O(1)* means *O(1)* word operations, including table lookups and `popcount`.
- **Reduction chains**: each theorem reduces a higher-level query to constant-time primitives on the level below, so the stack's total bounds compose multiplicatively in time and additively in space.
- **Empirical corroboration** via published experiments on the Pizza&Chili corpus, SDSL benchmarks, and the FM-index implementation studies [9][8][4].

## 4. Deep Dive

### 4.1 Jacobson rank/select with an *o(n)*-bit index

Let *B[1..n]* be a bitvector. The naive `rank₁(B, i)` scans *i* bits: *O(n)* time. Jacobson's insight [1] is a **two-level directory** that trades a tiny amount of space for constant time.

**Construction.** Partition *B* into *superblocks* of size *ℓ = log²n* bits and each superblock into *blocks* of size *s = (1/2) log n* bits.

- *R_ℓ[x]* stores `rank₁(B, x·ℓ)` for *x = 0..n/ℓ*: *(n/ℓ)·log n = O(n/log n)* bits.
- *R_s[y]* stores `rank₁` from the start of *y*'s superblock to the start of block *y*: *(n/s)·log ℓ = O(n log log n / log n)* bits.
- A **universal lookup table** tabulates `popcount` for all *2^s = √n* bit-strings of length *s*: *√n · s · log s = O(√n log n log log n) = o(n)* bits.

Then:

```python
def rank1(B, Rs, Rb, table, i):
    x, y = i // L, i // S          # superblock, block indices
    r = Rs[x] + Rb[y]              # counts before block y
    r += table[B[y*S:(y+1)*S]][i % S]  # intra-block popcount, O(1)
    return r
```

> **Theorem (Jacobson [1]):** `rank₁` is answered in *O(1)* time with *O(n log log n / log n) = o(n)* extra bits beyond the *n* bits of *B* itself.

For `select₁`, Jacobson achieved *O(log n)* via a third directory over 1-bit densities; Clark and Munro refined this to *O(1)* with the same *o(n)* asymptotics [10]. The RRR structure (Raman, Raman, Rao) goes further: blocking *B* into chunks of *(1/2) log n* bits and encoding each chunk by its *class* (popcount) and *offset* within the class achieves total space *ℬ(m,n) + o(n)* — the information-theoretic optimum plus lower-order terms — while retaining *O(1)* rank [10].

| Structure | Space (bits) | rank | select |
|---|---|---|---|
| Plain + Jacobson [1] | *n + O(n log log n/log n)* | *O(1)* | *O(log n)* |
| + Clark/Munro | *n + o(n)* | *O(1)* | *O(1)* |
| RRR [10] | *ℬ(m,n) + o(n)* | *O(1)* | *O(1)* |
| Practical (512/64-bit blocks) | *≈1.375n* | *O(1)*, ~50 ns | *O(1)*, ~400 ns |

The last row reflects engineering reality: word-aligned 512-bit superblocks with 64-bit blocks and `popcount` instructions dominate in practice, trading the asymptotic *o(n)* for a 25–37.5% overhead that is far faster [10].

### 4.2 Wavelet tree navigation and rank over alphabets

A bitvector primitive is not enough: text has *σ > 2* symbols. The **wavelet tree** (Grossi, Gupta, Vitter, SODA 2003 [5]) generalizes rank/select to sequences over arbitrary alphabets.

**Construction.** Build a balanced binary tree over the alphabet *Σ*. At the root, store a bitvector *B_v* of length *n* marking whether each symbol of *S* belongs to the left or right half of *Σ*. Recurse on the subsequence routed left and the subsequence routed right. Total bits: *n⌈log σ⌉*.

Queries walk the tree using bitvector rank:

```python
def rank_c(node, i, c):
    # descend according to bit of c at this level
    if node.is_leaf():
        return i
    if bit(node, c) == 0:
        return rank_c(node.left, rank0(node.bv, i), c)
    else:
        return rank_c(node.right, rank1(node.bv, i), c)
```

Each level costs one *O(1)* bitvector rank, and the tree has *⌈log σ⌉* levels:

> **Theorem (Grossi et al. [5]):** `access`, `rank_c`, `select_c` are supported in *O(log σ)* time using *n⌈log σ⌉ + o(n log σ)* bits.

**Entropy compression.** A profound result of [5]: if each node's bitvector is compressed with a zero-order encoder achieving *|z|H₀(z) + o(|z|)* bits, the *total* over all nodes telescopes to *nH₀(S) + o(n log σ)* bits — *regardless of tree shape*. Shaping the tree as a Huffman tree (Mäkinen–Navarro) makes the uncompressed size itself *n(H₀ + 1)* bits [6]. The wavelet *matrix* [6] reorders levels to improve cache locality while keeping the same bounds.

### 4.3 The Burrows–Wheeler transform and the LF-mapping

The BWT [2] permutes *T* into *L* = last column of the sorted rotation matrix. Two properties make it the engine of compressed indexing:

1. **Clustering.** Equal contexts group together, so *L* consists of long runs — highly compressible by move-to-front + run-length + entropy coding. This is why bzip2 uses the BWT [2].
2. **Reversibility via LF-mapping.** Let *F* be the first column (the sorted multiset of characters) and *C[c]* the number of symbols strictly smaller than *c*. Then the *i*-th occurrence of *c* in *L* corresponds to the *i*-th occurrence of *c* in *F*:

> *LF(i) = C[L[i]] + rank_{L[i]}(L, i)*

*LF* maps the row of a rotation to the row of its left rotation. Iterating *LF* from the row containing *$* reconstructs *T* backwards — the BWT is a permutation, hence lossless [2].

Crucially, *LF* is computed from a single `rank` query over *L* plus the *O(σ log n)*-bit array *C*. **Suffix-array navigation is rank.** The FM-index is the realization that a rank-capable representation of *L* *is* a compressed suffix array.

### 4.4 FM-index backward search and locate

The FM-index [3][4] stores: (a) a rank-supporting representation of *L* (wavelet tree or RRR bitvectors), (b) the *C* array, (c) a *sampled* suffix array. Notably, it does **not** store *T* — it is a *self-index*: *T* can be extracted via inverse LF-steps.

**Counting by backward search.** Maintain the interval *[sp, ep)* of rows whose rotations are prefixed by the processed suffix of *P*. Prepending character *c*:

```python
def count(L, C, P):
    sp, ep = 0, n
    for c in reversed(P):
        sp = C[c] + rank_c(L, sp)   # first row starting with c + processed suffix
        ep = C[c] + rank_c(L, ep)
        if sp >= ep:
            return 0
    return ep - sp
```

> **Theorem (Ferragina–Manzini [3]):** `count(P)` runs in *O(|P| · t_rank)* time, where *t_rank* is the rank time over *L*. With a wavelet tree, *t_rank = O(log σ)*; with Huffman-shaped or multiary structures this is effectively *O(1)* per step on small alphabets, giving *O(|P|)* counting independent of *n*.

**Locating.** The interval gives row numbers, not text positions. Store *SA[i]* for every *s*-th row (*s* the sampling rate); any row reaches a sampled row within *< s* LF-steps, each an *O(1)*-ish rank. Hence `locate` costs *O(occ · s · t_rank)* time with *(n/s) log n* extra bits [4]. The classic space/time knob: published experiments find sampling rates 64–128 give the best tradeoff [8].

> **Theorem (Ferragina–Manzini [4]):** The FM-index occupies at most *5nH_k(T) + o(n)* bits for all *k ≥ 0 simultaneously* and finds the *occ* occurrences of *P* in *O(|P| + occ · log^{1+ε} n)* time.

## 5. Empirical Results / Proofs

### 5.1 The *o(n)* index is real but constants matter

Theory promises *n + o(n)* bits; practice (SDSL's `rank_support_v`, ~52 ns rank on 100M bits) uses ~37.5% overhead for raw speed [9][10]. The gap is the classic succinct-data-structure lesson: *o(n)* hides constants that dominate at feasible *n*, so broadword and word-aligned designs win empirically.

### 5.2 Space/time knobs of the FM-index

| Parameter | Small | Large | Effect |
|---|---|---|---|
| SA sample rate *s* | 32 | 1024 | locate faster ↔ less space; 64–128 optimal [8] |
| *L* encoding | RRR bitvectors | Huffman WT | space near *H₀* ↔ *O(log σ)* vs *O(H₀+1)* rank |
| Alphabet | DNA (*σ*=4) | Unicode | *C* array negligible ↔ *σ log n* bits matters |

On the Pizza&Chili corpus (200 MB English, XML, DNA, sources), FM-index variants occupy *0.3–1.6* bits per symbol including the sampled SA, versus 8 uncompressed — while counting patterns in microseconds [4][8]. BWA and Bowtie2 index the 3 Gbp human genome in ~4 GB RAM using exactly this machinery, the dominant bioinformatics application of the FM-index.

### 5.3 Lower bounds: the theory is tight

Belazzougui and Navarro [7] proved that within *nH₀ + o(n log σ)* bits, `access` and `select_c` can be constant-time but `rank_c` requires *Ω(log log σ)* time under broad assumptions — so the wavelet tree's *O(log σ)* rank is nearly optimal, and the FM-index's per-character cost cannot be driven to *O(1)* for large alphabets without extra space. Their upper bounds dominate all prior points in the time/space map [7].

## 6. Limitations

1. **Static by design.** The BWT is a global permutation; a single-character edit can reshuffle *L* arbitrarily. Dynamic variants exist (dynamic wavelet trees, dynamic FM-indexes) but pay *O(log n)* update factors and larger constants — the compressed-dynamic frontier remains active research.
2. **Alphabet dependence.** The *C* array and per-level rank structures scale with *σ*; for huge alphabets (word-based indexes, Unicode) the *o(n log σ)* terms and *O(log σ)* depth bite, motivating alphabet-independent indexes [7].
3. **Repetitive collections.** On highly repetitive data (versioned documents, pangenomes), *nH_k* vastly overestimates compressibility. The **r-index** program replaces *n* with *r*, the number of BWT runs, achieving *O(r)*-space indexes — but locate becomes substantially subtler.
4. **Construction cost.** Building the BWT/suffix array needs *O(n)* time and considerable working memory (induced sorting, divsufsort); for terabyte corpora, construction — not querying — is the bottleneck.
5. **Cache behavior.** Backward search performs *O(|P|)* random accesses into *L*'s rank structures; on disk-resident indexes this random I/O dominates, favoring blocked layouts like the wavelet matrix [6].

---

## 7. Conclusion

The arc from Jacobson's directories [1] to the FM-index [3] is a single sustained idea: *rank is navigation*. A two-level directory turns a bitvector into a constant-time rank oracle; a wavelet tree turns rank oracles into alphabet-generalized sequence queries [5][6]; the BWT's LF-mapping turns rank over *L* into suffix-array traversal; and the FM-index turns that traversal into full-text search on text that is never stored explicitly [4]. The space bounds track entropy — *n + o(n)*, *nH₀ + o(n log σ)*, *nH_k + o(n)* — and Belazzougui–Navarro [7] show these tradeoffs are essentially optimal.

Open directions include fully dynamic compressed indexes with practical constants, run-length (*r*-bounded) indexes for pangenomics, and closing the constant-factor gap between the *o(n)* theory and the 25–40% overheads of deployed implementations [9]. Three decades after Jacobson, the field's central question remains his: how close to the information-theoretic minimum can we stand while still answering queries at full speed?
